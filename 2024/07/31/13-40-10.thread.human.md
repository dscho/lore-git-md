The promisor-remote/LOP patch series from Christian Couder, Patrick Steinhardt, and Junio Hamano has reached a key milestone with v5 being accepted for inclusion. The series introduces protocol v2 capability for promisor remote advertisement, with server-client negotiation mechanics and granular acceptance controls ("KnownName" and "KnownUrl" options). After addressing concerns about patch organization and cross-topic dependencies by removing problematic foundational patches from v4 and rebasing onto a more recent base, Junio has now acknowledged the improvements and indicated the series is ready to be queued.

Key technical aspects include server-side advertisement via `promisor.advertise` config, case-sensitive URL comparison, and new negotiation functions in promisor-remote.[ch]. The security model ensures servers can only advertise remotes while clients maintain full control over acceptance. The accompanying LOP design documentation has been expanded with concrete storage examples and clearer separation of design vs implementation concerns.

With Junio's acceptance, the core protocol implementation and design documentation are now considered complete. Remaining items like MIDX interaction and some security hardening will be handled separately. This marks successful convergence after multiple iterations, with the v5 restructuring having addressed the maintainer's key concerns about patch organization and documentation clarity.
