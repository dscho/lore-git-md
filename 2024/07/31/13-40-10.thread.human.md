Christian Couder's Large Object Promisor (LOP) series, now at v4, introduces protocol v2 support for promisor remotes with fine-grained client control over which servers to accept large objects from (via new "KnownName" and "KnownUrl" matching modes). The implementation spans server capability handling, client-side processing, and comprehensive test coverage, building on prior standardization work around string handling and memory management. A 640-line design document details the system's architecture, security considerations, and integration with services like S3/GCP.

Junio Hamano has raised concerns about the design's technical specifics, particularly around blob storage implementation details and versioned object handling. While Couder has addressed some points about existing storage services, Junio maintains that the documentation still lacks concrete explanations of optimization strategies and policies for offloading older versions of large objects. These open questions continue the thread's pattern of Junio pushing for more implementation clarity in the LOP system design. The series remains under active discussion, with core functionality stabilized but key details around blob management still being refined.
