Christian Couder's Large Object Promisor (LOP) series continues to take shape with the addition of comprehensive design documentation in v4. The thread began with technical implementations for protocol v2 support, introducing server-side advertisement and fine-grained client-side acceptance controls for promisor remotes. The new 640-line design document serves as the architectural foundation, clearly outlining the motivation, scope, and technical details of this Git-LFS alternative.

The system enables efficient large-object handling through server-side blob offloading to dedicated promisor remotes, with careful attention to security models and real-world deployment scenarios. Key participants including Junio Hamano have reviewed earlier code iterations, leading to refinements in string handling, memory management, and test isolation. The current state shows stable core functionality with thorough test coverage across all acceptance modes (None/All/KnownName/KnownUrl), though some follow-up work remains on lazy fetch security and client-side behavior specifics.

This documentation patch completes the picture by providing maintainers and reviewers with the design rationale behind the code changes, positioning LOPs as a thoughtfully-architected solution that builds on Git's existing partial clone infrastructure while adding new protocol extensions. The level of detail suggests the series is nearing readiness for integration, pending resolution of the remaining open items.
