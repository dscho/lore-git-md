This thread investigates intermittent test failures in t1016-compatObjectFormat.sh related to GPG signature verification across different hash algorithms. The issue has evolved from initial environment setup problems to a confirmed instability in GPG's SHA-1 signature generation.

Eric W. Biederman and Junio C Hamano have been the key participants. After addressing test environment issues (including Todd Zullinger's GNUPGHOME preparation and Biederman's gpg wrapper with `--faked-system-time`), the core problem remains: GPG produces inconsistent signatures for identical SHA-1 inputs, even with fixed timestamps. Biederman's latest tests show SHA-256 signatures remain stable while SHA-1 signatures vary between runs, with different PGP signature blocks (ending in `=7Jpz` vs `=G+Gp`) leading to different object IDs (`de9cabc2419f` vs `c87cd5157461`).

Junio has marked the test as FLAKEY while the investigation continues. The focus has now shifted from test infrastructure to understanding why GPG behaves differently for SHA-1 versus SHA-256 signatures. This appears to be a genuine GPG behavior issue that the test is correctly detecting, though the exact cause remains unclear. The discussion continues to seek either a solution to stabilize SHA-1 signatures or a way to modify the test to account for this GPG behavior.
