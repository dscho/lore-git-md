This thread investigated intermittent test failures in t1016-compatObjectFormat.sh, where GPG signatures for SHA-1 objects were producing inconsistent hashes despite identical inputs. Eric W. Biederman and Junio C Hamano determined this was a real GPG behavior - while SHA-256 signatures remained stable across runs, SHA-1 signatures varied even with timestamp fixing. The root cause was traced to insufficient timestamp freezing in the test's GPG wrapper during heavy system loads.

The solution came in the latest patch, which modifies the wrapper to properly freeze timestamps by adding an exclamation mark to the `--faked-system-time` parameter. This change eliminates the flakiness while maintaining the test's ability to verify identical content across hash algorithms. The patch includes both the code fix and documentation explaining the requirement for deterministic behavior.

While this resolves the immediate test instability, the thread leaves open the deeper question of why GPG's SHA-1 implementation exhibits this timestamp sensitivity while SHA-256 does not. The discussion confirms the test was correctly detecting a real behavioral difference in GPG's signature generation between the two algorithms. Junio has acknowledged these findings as potentially indicating a GPG-level issue with SHA-1 signing stability.
