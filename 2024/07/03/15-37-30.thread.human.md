This thread investigates why GPG produces inconsistent SHA-1 signatures while SHA-256 signatures remain stable when verifying commits across different hash algorithms. What began as suspected test flakiness has been narrowed down to a genuine GPG behavior difference, with Eric W. Biederman demonstrating that identical inputs produce varying SHA-1 signatures but consistent SHA-256 results.

The core issue manifests in t1016-compatObjectFormat.sh tests, where SHA-1 signed commits show hash mismatches (de9cabc2419f vs c87cd5157461) across runs despite using a timestamp-fixing wrapper. Junio C Hamano has marked the test as FLAKEY as an immediate mitigation, but the deeper question remains why GPG's SHA-1 signing behaves this way when its SHA-256 signing is stable.

Current understanding shows the problem is reproducible across environments and GPG versions (2.4.7 and 2.4.8), with signature blocks showing different values (=7Jpz vs =G+Gp) for the same content. While the test infrastructure works correctly in detecting this anomaly, the root cause appears to lie in GPG's SHA-1 implementation. The thread is now focused on determining whether this represents a GPG bug or expected (if surprising) behavior, and how to either fix or work around it in Git's test suite.
