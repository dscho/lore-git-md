This thread investigated intermittent test failures in t1016-compatObjectFormat.sh that involved GPG signature verification across SHA-1 and SHA-256 object formats. Eric W. Biederman discovered the root cause: GPG's SHA-1 signature generation was unstable under load, producing different signatures for identical content when timestamps varied slightly, while SHA-256 signatures remained consistent. The issue was particularly frustrating because GPG's documentation didn't clearly explain that adding an exclamation mark to the `--faked-system-time` parameter (`--faked-system-time=...!`) was necessary to fully freeze timestamps.

Junio C Hamano initially considered disabling the flaky tests but ultimately accepted Biederman's solution, which modified both the test script and GPG wrapper to use the exclamation mark syntax. This fix ensures deterministic signature generation while maintaining the test's original purpose of comparing behavior across hash algorithms. The thread revealed an interesting quirk in GPG's implementation - its SHA-1 signatures are more sensitive to timing variations than SHA-256 signatures - though the exact reason for this difference remains unclear. With the fix in place, the test now reliably passes even under stress conditions, and the thread has effectively concluded.
