This is a bug report about `git subtree` failing to properly handle merges and hitting recursion limits when splitting subtrees. Ian Jackson reports that when trying to extract a subtree (`maint/rust-maint-common`) from the arti.git repository, the command either fails with a recursion depth error (in Git 2.45.2) or takes an excessively long time while producing incorrect history (in Git 2.20.1).

The issue appears when the subtree has a complex merge history - in this case, the subtree was originally added via `git subtree add` and then modified through merge requests. The bug makes it impossible to properly split the subtree to create a branch suitable for merging back to its upstream repository. A partial workaround exists (checking out a specific parent commit), but this won't scale as the history grows more complex.

The report provides clear reproduction steps and context about the repository's history, making it easy for maintainers to investigate. Given that `git subtree` is a contrib script rather than core Git functionality, this might explain why such bugs persist across versions. The report would benefit from being turned into a proper bug report with test cases, but it clearly identifies a real usability problem for users of the subtree feature.
