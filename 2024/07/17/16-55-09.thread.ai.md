Thread identity: Bug report about `git subtree split` failing to handle merge-heavy ancestry properly, reported by Ian Jackson against Git 2.45.2 and 2.20.1, with follow-up analysis from Colin Stagner.

Core problem: `git subtree split` command fails in two distinct ways when processing repositories where the subtree was added via merge commits: (1) in Git 2.45.2 it hits a Debian-specific POSIX shell recursion limit (1000 calls), (2) in Git 2.20.1 it produces incorrect history including parent repository commits rather than just the subtree, even after fixes.

Current status: Colin Stagner has identified that the 2.45.2 recursion issue is Debian-specific and has proposed a patch series to work around the shell limitation. The 2.20.1 history inclusion problem persists and appears related to commit e7b07376e5 ("Merge branch 'rs-subtree-fixes'") which changed merge base handling. The latter may represent a fundamental limitation rather than a straightforward bug.

Key technical details: Issue reproduces with Tor Project's arti.git. The recursion depth problem is specific to Debian's shell implementation. The history inclusion problem yields ~12,000 commits instead of expected dozens, tracing to changes in how subtree handles merge bases. Determining "important" history becomes ambiguous with merges.

Open questions: How to properly handle subtree splits across merge commits given the inherent ambiguity? Is the history inclusion issue fixable or does it require rethinking subtree's merge handling? Will Colin's recursion patch be accepted given its Debian-specific nature?

Participant positions: Ian Jackson provided initial detailed reproduction case. Colin Stagner analyzed both failure modes, proposing a fix for the recursion issue while characterizing the history problem as potentially fundamental. No maintainer response yet.

Related work: `git subtree` in contrib/ has long-standing edge cases. Colin references his own patch series addressing shell recursion limit. Commit e7b07376e5 identified as changing merge base behavior.
