Thread identity: Bug report and technical discussion about `git subtree split` failing to handle merge-heavy ancestry properly, reported by Ian Jackson against Git 2.45.2 and 2.20.1, with analysis from Colin Stagner and algorithmic proposal from Ian.

Core problem: `git subtree split` fails in two ways with merge-heavy subtrees: (1) in Git 2.45.2 it exceeds Debian's POSIX shell recursion limit (1000 calls), (2) in Git 2.20.1 it incorrectly includes parent repository commits (producing ~12,000 commits vs expected dozens). The latter issue stems from merge base handling changes in commit e7b07376e5 ("Merge branch 'rs-subtree-fixes'") and represents a more fundamental challenge in determining subtree history across merges.

Current status: Colin Stagner has a patch series addressing the Debian-specific recursion issue. Ian Jackson has now proposed a refined algorithm for merge handling that would make splits deterministic by: treating them as pure functions of downstream commits, avoiding duplicate work, and carefully handling merge parents. The proposal covers four cases (single-parent changes, no-changes, multi-parent merges, explicit subtree merges) and could potentially resolve the history inclusion problem.

Key technical details: Issue reproduces with Tor Project's arti.git. Recursion depth problem is Debian-shell-specific. History problem involves ambiguous merge base selection. Ian's algorithm would track split state through merge commits to maintain correct ancestry. Implementation would need changes to how subtree processes commit graphs during splits.

Open questions: Whether to prototype Ian's algorithm given its complexity. If implemented, whether it would correctly handle all merge cases while reducing commit counts. Maintainer position on accepting Colin's Debian-specific recursion patch. Whether subtree's fundamental design can properly handle complex merge histories or needs architectural changes.

Participant positions: Ian Jackson provided initial report and now a solution proposal. Colin Stagner analyzed both issues and proposed recursion fix. No maintainer response yet to either proposal. Discussion has moved from problem diagnosis to solution design phase.

Related work: Colin's recursion-limit patch series. Commit e7b07376e5 identified as changing merge behavior. `git subtree` in contrib/ has long-standing edge cases with merges. Tor Project's arti.git serves as test case.
