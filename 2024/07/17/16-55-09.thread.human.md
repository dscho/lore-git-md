This thread examines a complex issue with `git subtree split` failing to properly handle repositories where the subtree was added via merge commits. Ian Jackson originally reported two distinct failures: a Debian-specific shell recursion limit in Git 2.45.2 and incorrect history inclusion in Git 2.20.1 that persists even after fixes. Colin Stagner analyzed both issues, proposing a workaround for the recursion problem while characterizing the history issue as potentially fundamental.

In the latest development, Ian has built on Colin's analysis with a detailed proposal for a new algorithm to handle merge-heavy histories more deterministically. His approach would make splits depend purely on downstream commits, avoid duplicate work, and carefully handle merge parents. While this represents significant progress in understanding the problem, the complexity of merge handling in subtree operations means any implementation would need thorough testing. The thread remains open with key questions about whether the history issue can be fixed within the current framework or requires rethinking subtree's merge handling altogether. No maintainer has weighed in yet on either the recursion workaround or this new algorithmic approach.
