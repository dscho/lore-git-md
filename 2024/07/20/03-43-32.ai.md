This is a refactoring patch that generalizes capability writing in the fetch-pack protocol handling. It's the first in a series implementing remote object info support for `git cat-file --batch-command`.

The patch renames `write_fetch_command_and_capabilities()` to the more generic `write_command_and_capabilities()` and makes it accept a command name parameter. This prepares for reuse by other protocol operations beyond just "fetch", specifically for the upcoming "object-info" capability. The change is mechanical but important infrastructure work - it maintains all existing behavior while making the function more flexible.

Key technical points:
- Function moved from fetch-specific to protocol-generic
- Takes new `command` parameter (e.g. "fetch" or future "object-info")
- Still enforces protocol v2 requirement via `ensure_server_supports_v2()`
- All callers updated to pass "fetch" explicitly
- No behavior change for existing fetch operations

The patch comes with sign-offs from Calvin Wan (original author) and Eric Ju (current series author), plus help acknowledgments from Jonathan Tan and Christian Couder. The change is straightforward and well-contained, touching only fetch-pack.c with minimal diff churn (6 lines changed). This appears to be solid foundational work for the larger feature being introduced in subsequent patches.
