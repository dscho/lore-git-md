Security-hardened remote object info feature for `git cat-file`. This is the second version of a 6-patch series that adds a `remote-object-info` command to `git cat-file --batch-command`, allowing clients to query object metadata from protocol v2 servers without full downloads. The implementation builds on Calvin Wan's earlier work and server-side support merged in 2021.

The series refactors fetch-pack packet writing, moves fetch initialization, advertises the object-info capability, adds transport layer support, and implements the new command. Key security measures from the server-side implementation remain enforced, including format string validation and request limits. The client requires protocol v2 and falls back to full fetches when the capability isn't available.

Two design questions remain open for discussion: whether to die or warn+continue on protocol v1 attempts, and how to handle objecttype requests (currently dies but breaks default format). The implementation appears thorough with expanded test coverage in t1017, addressing all major review concerns from the first version. Notable changes since v1 include improved memory management, additional fallback tests, and a heap-buffer-overflow fix.

The series has received extensive review input from multiple contributors including Jeff King, Junio Hamano, and Jonathan Tan. With the security constraints and test coverage now comprehensive, this appears ready for final consideration as a robust addition to Git's remote query capabilities.
