This is a feature patch series adding remote object info support to `git cat-file --batch-command`, building on Calvin Wan's earlier work. The series implements client-side support for querying object information from protocol v2 servers without full downloads, with security hardening from prior iterations now complete.

The 6-patch series refactors fetch-pack packet writing, moves fetch initialization, advertises the object-info capability, adds transport layer support, and finally implements the `remote-object-info` command for `cat-file`. Key technical points include server-side security measures (format string validation, request limits), simplified client-side parsing while maintaining safety, and protocol v2 requirement (v1 attempts error out).

The implementation currently only supports object size queries, with objecttype handling being a point of discussion. The cover letter raises two open questions about behavior: whether to die or warn+continue on protocol v1 attempts, and how to handle objecttype requests (currently dies but breaks default format).

Changes since v1 include renaming of parse_remote_info() to parse_cmd_remote_object_info(), added test coverage for fallback behavior when servers don't support the capability, and various code quality improvements. The series appears well-structured with thorough test coverage in t1017, building on established security foundations from the server-side implementation. The remaining questions seem focused on finalizing user-facing behavior rather than technical implementation concerns.
