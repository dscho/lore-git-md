This is a feature patch adding client-side transport support for remote object info queries, part of a series implementing `git cat-file --batch-command` integration for querying object metadata from remotes. The patch builds on Calvin Wan's earlier work and is now submitted by Eric Ju.

The implementation enables requesting object sizes from protocol v2 servers without full downloads, with fallback to full fetch when the server doesn't support the feature. Key technical aspects include:

- New `fetch_object_info()` function in transport.c handling the protocol v2 negotiation and response parsing
- Integration with the existing fetch-pack state machine via new `object_info` flag and related fields
- Strict protocol v2 requirement (v1 attempts error out)
- Memory management for object info responses
- Support for size queries (with allocation of size storage for each requested object)

The patch modifies several key files:
- `transport.c` gets the core implementation
- `fetch-pack.[ch]` see protocol and state machine changes
- `transport-helper.c` enforces protocol v2 requirement
- `transport.h` gains new fields for object info configuration

Review feedback from Jonathan Tan and Christian Couder has been incorporated, and the implementation appears solid with proper error handling. This is a foundational piece enabling the final `cat-file` integration in later patches of the series. The transport layer changes maintain backward compatibility while adding the new capability in a way that's consistent with Git's existing protocol architecture.
