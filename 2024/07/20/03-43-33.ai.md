This is a refactoring patch in the remote object info feature effort, specifically moving initialization code in `fetch-pack.c` to prepare for supporting multiple initial states. The patch relocates three variable initializations from inside the `FETCH_CHECK_LOCAL` state to before the state machine begins, ensuring they run regardless of which state starts the machine.

The changes are mechanical and behavior-preserving, with the key variables being `allow_unadvertised_object_request`, `use_sideband`, and `args->deepen`. The motivation is to support a new initial state for remote object info queries while maintaining these common initializations. The patch carries sign-offs from both Calvin Wan (original author) and Eric Ju (series submitter), plus help acknowledgments from Jonathan Tan and Christian Couder for review input.

This is patch 2/6 in the series, building infrastructure for the remote object info capability by generalizing the fetch-pack state machine initialization. The change is straightforward with no apparent controversy, serving as groundwork for the subsequent protocol capability additions.
