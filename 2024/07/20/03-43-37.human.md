This is the final patch in a series adding remote object info support to `git cat-file --batch-command`. The feature allows querying object metadata from remote repositories without full downloads, with security hardening from prior iterations now complete.

The patch implements the `remote-object-info` command for `git cat-file`, which can take multiple object IDs at once to reduce network overhead. It currently only supports size queries (not object types) and requires protocol v2. The implementation includes thorough test coverage across git://, file:// and http:// transports, with fallback behavior when servers don't support the capability.

Key technical points:
- New `remote-object-info` command in `git cat-file --batch-command`
- Server advertisement via `transfer.advertiseobjectinfo` config
- Client-side transport support across protocols via new `fetch_object_info()`
- Security measures like format string validation and request limits
- Comprehensive tests covering success cases, fallbacks, and error conditions

The patch appears well-structured with careful attention to edge cases and security. It builds on established protocol foundations and has undergone multiple rounds of review from domain experts like Jeff King, Jonathan Tan, and Christian Couder. The remaining open questions about behavior (like protocol v1 handling) seem minor compared to the technical implementation, which looks solid.
