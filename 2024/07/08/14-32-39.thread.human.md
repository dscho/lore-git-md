This thread addressed a network connectivity issue where users experienced HTTP/2 errors ("RPC failed; curl 92 HTTP/2 stream 5 was not closed cleanly") and fetch-pack disconnections when cloning large repositories from GitHub. The original reporter, Ellie, led the investigation, which explored potential causes including ISP problems, HTTP/2 protocol issues, and misconfigured firewalls or proxies. Workarounds like forcing HTTP/1.1 via `git -c http.version=HTTP/1.1 clone` were attempted but only produced slightly different error behavior.

GitHub has since resolved the issue through server-side configuration changes, as confirmed by Ellie. While the immediate problem is fixed, the discussion highlighted the broader need for resumable transfers in Git to better handle unreliable network conditions—a feature that remains desirable for future development. The technical exploration touched on HTTP protocol differences, fetch-pack behavior, and GitHub-specific server interactions, providing useful context for similar issues that may arise elsewhere. The thread serves as a documented case study in troubleshooting Git-over-HTTP problems, even though the root cause was ultimately external to Git itself.
