Resolved HTTP/2 connectivity issue with GitHub repositories. Original reporter Ellie described clone failures with "RPC failed; curl 92 HTTP/2 stream 5 was not closed cleanly" errors during large repository clones. Investigation revealed the problem stemmed from GitHub server configurations rather than Git client issues. Workarounds like forcing HTTP/1.1 via `git -c http.version=HTTP/1.1 clone` produced different but similarly unhelpful errors. Participants identified firewall/proxy interference as the likely root cause. GitHub has since resolved the issue through server-side changes. While the immediate problem is fixed, Ellie highlighted the ongoing need for resumable transfer support in Git to handle unreliable network conditions. Technical discussion covered HTTP/2 vs HTTP/1.1 protocol differences, fetch-pack sideband handling, and the http.version configuration option. The thread serves as a reference case for HTTP/2-related clone failures and the limitations of client-side workarounds when server configurations are the root cause.
