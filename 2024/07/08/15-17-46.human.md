This is a refactoring patch in the ongoing remote object-info functionality series, responding to Karthik Nayak's architectural feedback. The patch generalizes the packet-writing function in `fetch-pack.c` to support both "fetch" and the new "object-info" command, rather than creating a custom function in `connect.c`.

Eric Ju (replying on behalf of Calvin Wan) acknowledges Karthik's concern about whether this is the right layer for abstraction, but defends the approach by pointing to Taylor Blau's prior approval of this refactoring direction from two years ago. The response maintains that generalizing the function promotes code reuse while still supporting the security-hardened remote object-info feature.

The exchange highlights an architectural tension in the series: whether to follow the pattern of protocol commands like `get_remote_bundle_uri()` (custom functions in `connect.c`) or to generalize existing fetch machinery. The patch sticks with the generalized approach while documenting the rationale more clearly in the commit message. This comes as the series nears completion, with the `git cat-file --batch-command` integration being the final piece.
