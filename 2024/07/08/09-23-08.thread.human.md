This thread examines whether to promote the experimental `RemoveBracesLLVM` clang-format rule—which removes braces from single-statement conditional bodies—from CI-only testing to Git's main `.clang-format` configuration. The rule was introduced in Karthik Nayak's v6 patch as a CI experiment, with concerns about clang-format's limited semantic analysis causing incorrect changes.

Karthik has now reported that the experiment revealed at least one concrete issue: the rule incorrectly removed braces from a `for` loop in `builtin/receive-pack.c` where they improved readability. This validates earlier concerns about the formatter's analysis limitations. Additionally, Karthik notes that contributors rarely use `git clang-format` before submission due to false positives, meaning the rule has seen little real-world testing outside CI.

The discussion suggests the rule may not yet be ready for the main configuration, as the experimental period has exposed both technical limitations and adoption challenges. The rule continues to be applied via a temporary `/tmp/clang-format-rules` file in CI, unchanged from the original implementation. Junio Hamano's original questions about testing adequacy appear answered—the experiment has successfully identified the rule's boundaries, though not in a way that supports immediate promotion.
