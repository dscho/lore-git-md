Thread identity: Discussion about whether to promote the experimental `RemoveBracesLLVM` clang-format brace-removal rule from CI-only testing to Git's main `.clang-format` configuration.

Core problem: Evaluating whether the clang-format rule that removes braces from single-statement conditional bodies should become part of Git's standard formatting rules, after CI testing revealed edge cases where the rule produces undesirable output.

Current status: The rule was introduced in v6 of Karthik Nayak's patch as a CI-only experiment. Testing has shown problematic cases in `builtin/receive-pack.c` where the rule removes braces from a multi-line `for` loop that should retain them for clarity. Junio Hamano's response indicates the rule provides minimal benefit while risking undesirable formatting changes, particularly in existing code.

Key technical details:
- Rule affects formatting of single-statement conditional bodies (if/else/for/while)
- Currently implemented through `/tmp/clang-format-rules` in CI
- Demonstrated to incorrectly format multi-line `for` loops in `builtin/receive-pack.c`
- Lacks semantic analysis to distinguish simple one-liners from complex cases
- Maintainer's original concerns about semantic analysis appear validated
- Contributors rarely use `git clang-format` before submission due to false positives

Open questions:
- Should the rule be abandoned given its demonstrated limitations?
- Is there value in keeping it as a non-blocking CI suggestion?
- Would improving clang-format's semantic analysis be feasible before reconsidering?

Participant positions:
- Karthik Nayak identified problematic cases in real code
- Christian Couder collaborated in testing the rule
- Junio Hamano maintains pragmatic concerns - sees minimal benefit in existing code while acknowledging potential for new code
- Consensus appears to be forming against promoting the rule to main configuration

Related work: Continuation of discussion from Karthik Nayak's v6 patch that introduced the experimental CI testing mechanism. The findings suggest the rule may not be ready for main configuration inclusion despite the experimental period, with the maintainer's position leaning against adoption.
