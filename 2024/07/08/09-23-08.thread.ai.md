Thread identity: Discussion about whether to promote the experimental `RemoveBracesLLVM` clang-format brace-removal rule from CI-only testing to Git's main `.clang-format` configuration.

Core problem: Determining whether the clang-format rule that removes braces from single-statement conditional bodies (if/else/for/while) should become part of Git's standard formatting rules, after being tested in CI via temporary configuration.

Current status: The rule was introduced in v6 of Karthik Nayak's patch as a CI-only experiment. New findings from Karthik and Christian Couder show the rule produces undesirable formatting in `builtin/receive-pack.c`, removing braces from a `for` loop that should keep them for clarity. The rule continues to use the temporary `/tmp/clang-format-rules` file mechanism from the original patch.

Key technical details:
- Rule affects formatting of single-statement conditional bodies
- Currently implemented through `/tmp/clang-format-rules` in CI
- Concrete problematic case found in `builtin/receive-pack.c`
- Maintainer's original concerns about semantic analysis limitations appear validated
- Contributors rarely use `git clang-format` before submission due to false positives

Open questions:
- Should the rule be abandoned given the demonstrated formatting issues?
- Is there value in keeping it as a CI-only check despite low contributor usage?
- Would improving clang-format's semantic analysis be feasible before reconsidering?

Participant positions:
- Karthik Nayak reports the rule produces undesirable formatting in real code
- Christian Couder collaborated in identifying problematic cases
- Junio Hamano's original concerns about semantic analysis appear validated
