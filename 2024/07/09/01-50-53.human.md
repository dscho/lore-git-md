This is the final patch in a series adding remote object metadata query support to `git cat-file --batch-command`. The patch implements a new `remote-object-info` command that allows efficiently querying object sizes and names from remote repositories without downloading the full objects.

The implementation builds on the series' earlier transport layer work, maintaining its strict security hardening (format string validation, request limits) while optimizing for performance. The command accepts multiple object IDs in a single request to minimize round trips, handling both buffered and non-buffered modes. The patch includes comprehensive tests covering security edge cases and protocol requirements.

Justin Tobler's review feedback focuses on code style (suggesting omitting braces for single-line if statements) and implementation details around command parsing. He notes some potential confusion in the interface between `parse_remote_info()` and its callers, suggesting passing just the command function rather than the full parse/queued command structures.

The patch appears production-ready, completing the series' goal of providing secure remote object metadata queries. While some open questions remain about protocol v1 fallback behavior and object type support (as noted in earlier summaries), this final piece delivers the promised `cat-file` integration with thorough test coverage.
