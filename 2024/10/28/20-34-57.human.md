This is the final patch in a feature series adding remote object info support to `git cat-file --batch-command`. The patch implements the new `remote-object-info` command that allows querying object metadata from remote repositories without downloading the full objects.

The command works with multiple transports (git://, file://, http://) and handles both single and multiple OIDs per request. When the remote supports the object-info capability (via transfer.advertiseobjectinfo), it retrieves just the metadata. Otherwise, it falls back to fetching the objects. The implementation includes comprehensive tests covering all these scenarios.

Key technical details:
- The command format is `remote-object-info <remote> <oid> [<oid>...]`
- Currently only supports `%(objectname)` and `%(objectsize)` format specifiers
- Enforces protocol v2 requirement (dies on v1 attempts)
- Includes buffer mode support (-Z/--buffer)
- Adds new test infrastructure in t/lib-cat-file.sh

The patch builds on earlier infrastructure work in the series and has received thorough review from multiple contributors. It appears well-structured with careful attention to edge cases and security considerations. The only remaining open question is about unifying the default format with local object queries once `%(objecttype)` support is added.

This completes the client-side implementation of remote object metadata queries, providing a useful performance optimization for scripts that need to inspect remote objects without downloading them.
