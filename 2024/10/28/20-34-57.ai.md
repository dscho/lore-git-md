This is the final patch in a feature series adding remote object info support to `git cat-file --batch-command`. The patch implements the `remote-object-info` command, which allows querying object metadata from remote repositories without downloading the full objects.

The command supports multiple OIDs per request to reduce network overhead, and falls back to full fetches when the server doesn't support the object-info capability. The implementation enforces protocol v2 and includes comprehensive tests covering various transports (git://, file://, http://) and edge cases.

Key technical details:
- The command uses a default format of `%(objectname) %(objectsize)` since objecttype support isn't implemented yet (a warning notes this will change)
- New `fetch-object-info.[ch]` module handles the protocol v2 exchange
- Transport layer enforces v2 requirement and implements fallback
- Tests verify behavior with/without server capability support
- Variable scoping was tightened in `builtin/cat-file.c` per review feedback

The patch appears well-structured with thorough test coverage, completing the series' goal of enabling efficient remote object metadata queries. All major technical concerns from earlier reviews have been addressed, leaving only minor documentation and format unification questions open for future work.
