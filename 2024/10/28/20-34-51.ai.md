This is a feature patch series adding remote object info support to `git cat-file --batch-command`, building on Calvin Wan's earlier work. The series implements client-side support for querying object metadata from protocol v2 servers without full downloads, with security hardening from prior iterations now complete.

The 6-patch series refactors fetch-pack packet writing, moves fetch initialization, advertises the object-info capability, adds transport layer support, and finally implements the `remote-object-info` command for `cat-file`. Key changes in v5 include moving packet writing code to connect.c, isolating object-info logic in a new fetch-object-info.c file, and adding more comments about fallback behavior.

The implementation enforces protocol v2 and includes comprehensive tests covering security edge cases. Two open questions remain about user-facing behavior: whether to die or warn on protocol v1 attempts, and how to handle objecttype requests (currently dies but breaks default format). The series appears well-structured with thorough test coverage, building on established security foundations from the server-side implementation.

Key files touched:
- New fetch-object-info.c/h for isolated object-info logic
- connect.c gains packet writing utilities
- transport.c implements the protocol v2 exchange
- builtin/cat-file.c adds the new command
- Extensive tests in t1017-cat-file-remote-object-info.sh

The series has received thorough review from Christian Couder, Jonathan Tan, and Karthik Nayak, with all major technical concerns addressed. The remaining discussion focuses on documentation and style refinements before potential merging.
