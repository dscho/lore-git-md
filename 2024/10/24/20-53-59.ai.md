This is the final patch in a 6-part series implementing `git cat-file --batch-command` support for querying remote object metadata without full downloads. The patch adds a `remote-object-info` command that uses protocol v2 to efficiently retrieve object information from remote servers that support the capability.

Key technical points:
- The command takes a remote name and one or more object IDs, retrieving their sizes without downloading full objects when possible
- Default format is `%(objectname) %(objectsize)` since object type` is not yet supported (documented with a warning about future format unification)
- Implements fallback to full fetches when server lacks object-info capability
- Includes comprehensive tests across git://, file:// and http:// transports
- Handles edge cases like malformed OIDs, missing objects, and unsupported format options
- Maintains security hardening from earlier patches (protocol v2 requirement, format validation)

The implementation shows careful attention to:
- Code organization (factoring test helpers into lib-cat-file.sh)
- Documentation clarity (explicit warnings about future format changes)
- Test coverage (exercising all major code paths and error conditions)
- Review feedback (incorporating suggestions from Jonathan Tan and Christian Couder)

This completes the client-side plumbing for remote object queries, building on Calvin Wan's earlier work. The series appears ready for maintainer consideration with all major feedback addressed.
