This is a refactoring patch in the security-hardened remote object info series, specifically preparing the fetch-pack.c infrastructure for future protocol v2 extensions. The patch moves initialization of several protocol-related settings (allow_unadvertised_object_request, use_sideband, args->deepen) from inside the FETCH_CHECK_LOCAL state to just before the state machine begins. This ensures the variables are set regardless of which state the machine starts in, which will be needed when a subsequent patch introduces an alternative initial state for object info queries.

The change is purely mechanical with no behavior difference in the current code - it just relocates the initialization to a more logical place given the planned extension. The patch carries sign-offs from both Calvin Wan (original author) and Eric Ju (current submitter), along with help acknowledgments from Jonathan Tan and Christian Couder. This appears to be a straightforward preparatory change that has already been reviewed and incorporated into the larger series.
