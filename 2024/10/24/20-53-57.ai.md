This is the transport layer implementation for the remote object info feature, part of a 6-patch series adding `git cat-file --batch-command` support for querying remote object metadata without full downloads. Patch 4/6 introduces the core client-side transport logic that communicates with servers supporting the object-info capability.

The patch adds a new `fetch_object_info()` function in transport.c that handles the protocol v2 exchange for requesting object metadata. Key technical aspects include:

- Server capability checking - verifies the remote supports "object-info" and requested features (currently just "size")
- Protocol v2 enforcement - fails explicitly if server doesn't support v2
- Request formatting - uses the refactored `send_object_info_request()` from fetch-pack.c
- Response parsing - handles the server's packetized response format
- Fallback behavior - will perform full fetches when server lacks capability
- Memory management - properly allocates and frees response data structures

The implementation integrates with the existing fetch-pack machinery while adding the object-info specific logic. It maintains all the security hardening from earlier iterations, including format string validation and request limits. The transport layer changes are complemented by updates to fetch-pack.h to expose the needed infrastructure.

Review feedback from Jonathan Tan and Christian Couder has been incorporated, and the patch carries both their sign-offs along with the original author Calvin Wan's. This appears to be a robust implementation that completes the client-side plumbing for the remote object info feature while maintaining compatibility with existing fetch behavior.
