This is the final patch in a 6-part series adding remote object info querying to `git cat-file --batch-command`. The feature allows efficiently retrieving object metadata from remote repositories without downloading full objects.

The patch introduces a new `remote-object-info` command that takes a remote name and one or more object IDs, then prints their metadata (currently just OID and size) by leveraging protocol v2's object-info capability. When the server support is unavailable, it falls back to fetching the objects normally. The implementation handles both buffered and non-buffered modes, with comprehensive tests covering git://, file://, and http:// transports.

Key technical points:
- Default format is `%(objectname) %(objectsize)` since object type support isn't implemented yet
- Warns that the default format will change when object type support is added
- Rejects unsupported format specifiers like `%(objecttype)` and `%(deltabase)`
- Requires protocol v2 and fails gracefully on legacy protocol
- Includes extensive test coverage with various transport protocols and edge cases

The patch appears well-polished, with thorough documentation and test coverage. It builds on prior review feedback from Christian Couder and Jonathan Tan, and seems ready for maintainer consideration. The series as a whole provides a useful optimization for tools that need to query remote object metadata without downloading full objects.
