This is a discussion about the final patch in a series implementing remote object metadata queries via `git cat-file --batch-command`. Christian Couder responds to Karthik Nayak's review feedback regarding the default output format for the new `remote-object-info` command.

The key point of contention is whether to implement `%(objecttype)` support immediately or defer it. Karthik had expressed concern that the current temporary default format (`%(objectname) %(objectsize)`) would need to change later when object type support is added, potentially breaking scripts. Christian argues this isn't "planned breakage" but rather an informational improvement, and suggests the warning in the documentation sufficiently alerts users to specify explicit formats if they need stability.

Christian defends the incremental approach of implementing `%(objectsize)` first in a smaller series, with `%(objecttype)` to follow later, as being more reviewable than one large patch series. He agrees with Karthik's other review comments while maintaining this position on the phased implementation.
