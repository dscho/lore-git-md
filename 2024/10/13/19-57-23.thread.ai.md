Thread identity: Discussion about symbolic reference (symref) usage patterns and practical experiences in Git workflows, originating from Kristoffer Haugsbakk's email sharing real-world usage.

Core problem: Exploring safe and effective patterns for using symrefs in daily Git workflows, particularly addressing pitfalls when symrefs interact with remote-tracking branches and multiple worktrees. The thread focuses on practical solutions that maintain stability across different Git operations.

Current status: Kristoffer reports stable usage for six months with their current approach of using `refs/H` for local branches and `refs/O` for remote branches, avoiding earlier issues with both `refs/heads/` placement and root-level symrefs.

Key technical details:
- Symrefs under `refs/heads/` can cause remote-tracking branch movement during commits
- Root-level symrefs (e.g., `H`) are worktree-specific and don't share well
- `refs/`-prefixed symrefs (e.g., `refs/H`, `refs/O`) work across worktrees
- Specific command usage: `git symbolic-ref` for management
- Use case: Rebasing on remote branches via symrefs while maintaining stability

Participant positions:
- Kristoffer Haugsbakk has validated the `refs/`-prefixed approach through extended real-world use, confirming it avoids the pitfalls of other symref placement strategies
