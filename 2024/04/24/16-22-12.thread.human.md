This thread reports and addresses a Windows-specific bug in `git add --patch` where the keyboard becomes unresponsive after using the "e" edit option. The issue was reported by Dan Demp, who consistently reproduced it on Windows 10 with Git version 2.42.0.windows.2. Johannes Schindelin (Git for Windows maintainer) has identified this as likely related to a known issue (#4776) in Git for Windows, though the original report didn't specify whether an editor override was involved, the fix is already prepared. The fix will be included in Git for Windows v2.49.0, with the release delayed from Friday to Monday following the project's standard no-Friday-release policy. The bug manifests as complete keyboard unresponsiveness requiring termination of the Git Bash process, specifically during the patch editing workflow.
