Thread summary:

Git for Windows bug report regarding keyboard unresponsiveness during `git add --patch` interactive editing (specifically when using the "e" edit option), with complete keyboard lockup requiring process termination on Windows 10 with Git 2.42.0.windows.2. Johannes Schindelen (Git for Windows maintainer) identified this as related to known issue #4776 in the Git for Windows tracker, with a solution prepared for the upcoming v2.49.0 release (delayed from Friday to Monday per project policy). The discussion has branched into release coordination between Git core and Git for Windows projects, with Junio Hamano (Git maintainer) inquiring about aligning release days of the week - noting recent Git core releases have been on Fridays while Git for Windows v2.49.0 is scheduled for Monday, with established release time of 1700 UTC (2600 Tokyo time) but variable days (Git 2.47 was Monday). This represents a meta-discussion about project process coordination between the separate but related projects, with no technical changes to the original Windows-specific terminal/editor interaction issue that remains resolved in the upcoming Git for Windows release.
