Thread summary:

Git for Windows bug report regarding keyboard unresponsiveness during `git add --patch` interactive editing (specifically when using the "e" edit option), with complete keyboard lockup requiring process termination on Windows 10 with Git 2.42.0.windows.2. Johannes Schindelen (Git for Windows maintainer) identified this as related to known issue #4776 in the Git for Windows tracker, with a solution prepared for the upcoming v2.49.0 release (delayed from Friday to Monday per project policy). The discussion has evolved into a broader examination of release scheduling coordination between Git core and Git for Windows projects.

Johannes Schindelin provided extensive external references advocating against Friday releases (curl, Firefox, Microsoft Patch Tuesday, industry research) supporting Git for Windows' Monday release schedule (1700 UTC). Junio Hamano (Git maintainer) has now responded by requesting a direct statement of preference rather than indirect arguments, maintaining a light tone but pressing for concrete proposals about aligning the projects' release cycles. While both acknowledge Friday releases may be suboptimal, no specific alignment plan has been proposed yet. The technical resolution for the original Windows-specific terminal/editor interaction issue remains unchanged (fixed in upcoming Git for Windows v2.49.0). The thread now focuses on maintainer coordination challenges between the separate but related projects, with Junio signaling openness to discussion but seeking more direct input on potential schedule adjustments.
