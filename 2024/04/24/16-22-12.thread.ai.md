Thread summary:

Git for Windows bug report regarding keyboard unresponsiveness during `git add --patch` interactive editing (specifically when using the "e" edit option). The issue causes complete keyboard lockup requiring process termination, reproduced on Windows 10 with Git 2.42.0.windows.2. Johannes Schindelen (Git for Windows maintainer) identifies this as likely related to known issue #4776 in the Git for Windows tracker, though the original report didn't specify editor configuration details. A fix has been prepared and will be included in the upcoming Git for Windows v2.49.0 release, delayed from Friday to Monday per project policy. The problem appears specific to the Windows platform's interaction between the patch editing workflow and terminal/editor processes. No core Git changes are indicated as the fix is being handled within the Git for Windows fork.
