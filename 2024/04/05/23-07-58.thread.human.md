Aleks Todorov has proposed adding commit message formatting capabilities to `git blame`, similar to what `git log` offers. The initial prototype demonstrates how `git blame` could accept a `-F/--format` option to customize how commit metadata appears in blame output, reusing much of the existing formatting infrastructure from `git log`. 

The working implementation shows this with example format strings that can include commit hashes, author names, dates and filenames. The core of the change is relatively small - about 20 lines modifying `builtin/blame.c` to handle the new option and integrate with Git's formatting system.

The main architectural question is whether to fully reuse `git log`'s formatting code (which brings some complexity around input sanitization and alignment) or to implement a more limited, blame-specific version. The prototype takes the first approach as a starting point, but the author explicitly acknowledges this may not be the final direction.

Key points for reviewers to consider include whether the proposed `- F/--format` option name makes sense, how to handle output alignment differences from `git log`, whether certain format specifiers should be restricted for blame output, and whether the feature's utility justifies the added code complexity. The author is looking for feedback on these design questions before proceeding further with the implementation.
