**Thread identity:** New `git url-parse` builtin command series (13 patches) by Matheus Afonso Martins Moreira, now at version 3, providing plumbing to expose Git's internal URL parsing logic. Thread type: patch series.

**Core problem/goal:** Git supports multiple URL formats (SCP-style, IPv6, various file URL forms) that standard URI parsers cannot handle. This series adds a `git url-parse` builtin command to let external tools and scripts decompose URLs exactly as Git does internally.

**Current status:** Junio C Hamano confirmed that deferring the remaining Windows path-handling edge case (`file://server/share/repo` on Windows, where UNC path reconstruction happens downstream in `connect.c` rather than in the URL parser) to follow-up work is acceptable. Junio noted there is no urgency for the new command, so shipping it half-baked is not forced.

**Key technical details:**
- Complete refactoring moving URL parsing helpers from `connect.c` to new `url.[ch]` files (patches 2-4/13), including URL scheme detection (`enum url_scheme` and `url_get_scheme()`) with new `URL_SCHEME_UNKNOWN` return value.
- `url_parse()` implementation in `urlmatch.[ch]` with full SCP-style and IPv6 support, featuring a shared interface with `url_normalize()` but extended format support and NULL return on failure.
- `git url-parse` command interface with `-c/--component` option to extract specific URL parts (scheme, user, password, host, port, path) and cross-platform path handling.
- `Documentation/git-url-parse.txt` man page in standard AsciiDoc format.
- Test suite: 53 tests validating all URL schemes and edge cases across platforms, with Windows-specific fixes for DOS drive prefixes and path assertions (319 lines of test code total, 98 tests in the full series).
- MSYS path rewriting handled through test adjustments; `has_dos_drive_prefix()` used for Windows path recognition.
- UNC path reconstruction confirmed to happen downstream in `connect.c` rather than in the URL layer -- this is the deferred item.
