This is a cover letter for a 13-patch series introducing a new `git url-parse` builtin command. The series aims to expose Git's internal URL parsing logic as a plumbing command, allowing scripts and other programs to reliably parse Git's various URL formats (including non-standard ones like SCP-style URLs).

The motivation is that Git supports multiple URL formats that standard parsers can't handle, making it difficult for external tools to reliably extract components like hostnames. The new command would let scripts parse URLs the same way Git does internally.

Key technical points:
- Moves URL parsing helpers from connect.c to new url.[ch] files
- Introduces url_parse() function in urlmatch.[ch]
- Adds new builtin/url-parse.c implementing the command-line interface
- Allows extracting specific URL components (protocol, host, path etc.)
- Includes comprehensive documentation and tests

The series appears well-structured with logical progression from internal refactoring to the new command implementation. The test coverage (194 lines) suggests thorough validation of the parsing behavior. This could be useful plumbing for tooling that needs to interact with Git repositories programmatically.

As a new feature, it may need discussion about:
- Whether this belongs in core Git vs. a separate tool
- The exact component extraction interface
- Potential performance impact of the new builtin

The implementation looks clean and the use case is clearly motivated. The series seems ready for review, particularly from contributors familiar with Git's URL handling code.
