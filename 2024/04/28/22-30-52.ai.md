This is patch 4/13 in the `git url-parse` series, adding a core URL validation helper function to the new builtin. The patch introduces `parse_or_die()`, which wraps the existing `url_parse()` function from urlmatch.[ch] with error handling that's appropriate for a plumbing command (untranslated error messages, immediate termination on failure).

The implementation is straightforward - it checks the return value of `url_parse()` and either returns successfully or dies with an error message that includes both the invalid URL and the specific parsing failure reason from the url_info struct. This follows the common Git plumbing pattern of failing hard on invalid input rather than trying to recover.

As part of the larger effort to expose Git's URL parsing logic, this helper will likely be used by subsequent patches that implement the actual command-line interface for extracting URL components. The error handling approach here is consistent with other plumbing commands, though reviewers may want to verify that including the raw error string from url_info->err is appropriate (as opposed to a more standardized message).

The patch is small and focused, building on the infrastructure established in earlier patches. It doesn't yet add any user-facing functionality - that appears to be coming in later patches in the series.
