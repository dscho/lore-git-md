This is patch 10/13 in the series introducing a new `git url-parse` builtin command. The patch implements URL validation for all command-line arguments passed to the new command.

The change is straightforward - it adds a loop that processes each input URL by:
1. Parsing it using the `parse_or_die()` helper (introduced in patch 4)
2. Freeing the allocated URL info structure
3. Exiting with an error if any URL fails to parse

This builds on the infrastructure established in previous patches:
- The `url_info` struct and `parse_or_die()` function from earlier in the series
- The option parsing setup completed in patch 9
- The component extraction helpers that will be used in subsequent patches

The implementation follows Git's typical plumbing command pattern where invalid input causes the command to die rather than continue. This matches the behavior of other low-level commands and is appropriate for scripting use cases where malformed input should fail fast.

As this is part of a larger series, the real functionality (extracting and outputting specific URL components) will come in later patches. This patch focuses solely on the validation step, keeping the change small and focused. The series continues to demonstrate careful, incremental development with each patch adding one well-defined piece of functionality.
