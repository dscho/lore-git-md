Feature: New URL parsing helper for `git url-parse` plumbing command.

This is the fourth patch in a 13-part series introducing a new `git url-parse` builtin that exposes Git's internal URL parsing logic. The patch adds a simple helper function `parse_or_die()` to the command implementation, which either successfully parses a URL or dies with an error message.

The function wraps the existing `url_parse()` from urlmatch.h, providing plumbing-appropriate error handling (non-translated error messages, immediate termination on failure). This follows the pattern established in earlier patches of the series, where plumbing commands use direct error reporting rather than the friendlier porcelain-style messages.

The implementation is straightforward - just 10 lines that check the parse result and either return or die. The error message includes both the invalid URL and the specific parsing failure from the url_info struct. This matches the series' goal of giving tooling reliable access to Git's URL parsing behavior, including its handling of non-standard formats like SCP-style URLs.

As with previous patches, this appears to be a clean, incremental addition to the growing `url-parse` command. The series continues to build logically, with each patch adding small, focused pieces of functionality. Reviewers familiar with Git's URL handling (particularly Jeff King, who has worked extensively in this area) would be well-positioned to evaluate whether this error handling approach is appropriate for a plumbing command.
