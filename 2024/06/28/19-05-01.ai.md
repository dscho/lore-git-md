This is part 4 of a 6-patch series implementing remote object-info functionality, focusing on adding client-side transport support. The patch builds on previous security-hardened server-side work to enable querying object metadata without full downloads.

The key technical additions in this patch:
- Implements `fetch_object_info()` in transport.c to handle protocol v2 object-info requests
- Adds `send_object_info_request()` to fetch-pack.c for constructing the request
- Extends transport.h with new fields for object-info options and OIDs
- Enforces protocol v2 requirement (dies on v1/v0 attempts)
- Supports requesting object sizes via the "size" feature
- Includes comprehensive error handling and validation

The implementation maintains the series' strict security posture while integrating with existing transport infrastructure. Notable behaviors:
- Server capability checks before making requests
- Strict parsing of server responses
- Fallback to full fetch when object-info isn't supported
- Clean separation between object-info and regular fetch paths

The patch appears well-structured with clear separation of concerns between transport, fetch-pack, and protocol layers. It builds logically on the prior refactoring work while setting up for the final `cat-file` integration in later patches. The implementation maintains the series' focus on security while providing the necessary transport plumbing.
