This is part 4 of a 6-patch series implementing remote object-info functionality, focusing on adding client-side support for querying object metadata from protocol v2 servers. The patch builds on previous security hardening work and introduces transport layer integration.

The key addition is client-side functions to request object information (size/type) from remote servers without full downloads. The implementation:
- Adds `send_object_info_request()` to construct and send object-info requests
- Extends the fetch-pack state machine to handle object-info operations
- Implements protocol v2 support while explicitly rejecting v0/v1
- Includes comprehensive error handling and validation

The patch maintains the series' security posture with strict protocol version requirements and server capability checks. It enables the client to request object sizes (with type support still under discussion) while falling back to full fetches when the server lacks support.

This appears to be a well-structured addition to the series, with clear separation of concerns between the new object-info functionality and existing fetch operations. The implementation follows the established pattern from prior patches while completing the client-server interaction flow.
