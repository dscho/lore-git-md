This thread is about the final stages of the `git cat-file --batch-command` remote-object-info series, now at **v20** and queued for `next`. The series enables Git clients to query object metadata (currently size, with type support designed for future expansion) from remote repositories without downloading the objects themselves, using the new `object-info` protocol v2 capability.

The implementation is technically complete, with all design and security issues resolved across 20 iterations. Key features include dynamic capability negotiation (clients adapt to server-advertised metadata fields), robust edge-case handling (missing objects, unsupported protocols, malformed inputs), and strict memory safety (bounds-checked inputs, leak fixes). The series has passed CI and is cleared for graduation to `master`, pending minor cosmetic nits.

In this latest exchange, Pablo Sabater and Karthik Nayak resolved two surface-level issues through discussion rather than a reroll:
1. **Documentation caveats**: An unintentional restoration of `CAVEATS` references in `git-cat-file.adoc` was deemed unnecessary and won’t be reverted.
2. **Macro formatting**: Karthik proposed an improved style for the `EXPAND_DATA_INIT` macro (trailing commas, field alignment), which Pablo accepted but noted would only be applied if a reroll becomes necessary for other reasons.

The series remains on track for integration into `master` without further changes, with these cosmetic issues likely to be addressed in a future cleanup. Junio’s prior confirmation that no unresolved concerns remain stands validated.
