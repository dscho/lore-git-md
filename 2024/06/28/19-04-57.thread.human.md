This thread is about a security-hardened implementation of `git cat-file --batch-command` that allows querying object metadata from remotes without downloading full objects. The series has reached its 13th version and is now ready for merging, with all technical issues resolved.

The core feature enables dynamic capability-based validation of format placeholders (like `%(objectsize)`) against what the server actually supports, preventing potential information leaks. The latest patch (8/12) adds server-side capability advertisement for the object-info feature, currently supporting only "size" metadata. This respects the `transfer.advertiseobjectinfo` configuration (disabled by default) and enables the client to make informed decisions about metadata queries.

Key participants include Pablo Sabater (series author), Junio Hamano (maintainer), Patrick Steinhardt, Jonathan Tan, Christian Couder, and Taylor Blau, all of whom have reviewed and approved the approach. Recent changes include memory leak fixes, improved error handling, protocol layer refactoring, and test infrastructure improvements. The series is fully rebased on current master and includes 12 patches covering everything from utility functions (`strtoul_ul()`) to protocol v2 command refactoring and state machine preparation.

The only remaining open question is how to distinguish "unsupported" vs "no data" responses for future placeholders, but this doesn't block the current implementation. The series demonstrates careful attention to security, cross-platform correctness, and maintainability, with all review feedback addressed in the final version.
