This thread is about a security-hardened patch series that adds `git cat-file --batch-command` support for querying object metadata from remotes without full downloads. The series, now at version 18, is functionally complete and queued for Junio’s `next` branch after resolving all technical, security, and design issues. Pablo Sabater is the primary author, with Junio confirming no unresolved concerns remain.

The implementation introduces a new `remote-object-info` command that lets clients query object metadata (currently size, with type support designed for future expansion) from remote repositories via the `object-info` protocol v2 capability. Key features include strict input validation, a 10,000-object batch limit, dynamic allow-lists for metadata fields, and robust edge-case handling—such as omitting unsupported format placeholders (e.g., `%(objectcolor)`) and validating object existence even for `%(objectname)`-only requests. The series also refactors `fetch-pack.c` to remove a problematic static variable, enabling code reuse.

Karthik Nayak’s recent review focuses on minor documentation and code organization nits in patch 11/13: removing `CAVEATS` references (though the underlying warnings still apply), improving translator context for an error message, and restoring alphabetical ordering in a `commands[]` array. These are surface-level issues that don’t affect functionality, and the series remains on track for integration. CI runs are green, and the dynamic allow-list system ensures future extensibility.
