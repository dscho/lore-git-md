This thread is about a security-hardened feature series that adds `git cat-file --batch-command` support for querying object metadata from remotes without full downloads. The series has reached its 15th version and is now considered ready for merging, with all technical, security, and design issues resolved—including recent refinements like platform-independent numeric conversion, memory leak fixes, and static variable elimination.

The core feature allows clients to request object metadata (like size) from servers via a new `object-info` capability in Git’s protocol v2. The design now formally documents how future metadata attributes (e.g., `objecttype`) will be appended to the capability string, resolving earlier concerns about extensibility. A key unresolved debate remains: whether the client should fail explicitly or continue silently when requested metadata is missing (Pablo Sabater prefers silent continuation, while Karthik Nayak advocates for explicit failure).

Recent updates in v15 include critical refactoring to improve memory safety and code hygiene. Notably, a patch moved `write_fetch_command_and_capabilities()` from `fetch-pack.c` to `connect.c` to enable reuse by other commands (like the new `remote-object-info` subcommand), while preserving its existing behavior—including its use of `the_repository`, which will be addressed later. Other improvements include a new `strtoumax_szt()` helper for platform-independent numeric conversion, loop counter scoping fixes, and shared test infrastructure. All outstanding review feedback from Junio Hamano, Karthik Nayak, and others has been incorporated.

The series is now fully documented, with 680 lines of new tests and verified memory safety. While the error-handling debate persists, the implementation is otherwise complete, balancing security, compatibility, and maintainability. The next steps are Junio’s final review and integration.
