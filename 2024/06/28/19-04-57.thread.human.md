This thread implements a security-hardened `git cat-file --batch-command` feature for querying object metadata from remotes without full downloads. The series has evolved through 13 versions, addressing all technical, security, and design feedback, and is now in its final stages before merging.

The core functionality allows Git to request object metadata (like size and type) from remote repositories through a new `remote-object-info` command, with strict protocol validation and capability-based format enforcement. Key decisions include using protocol v1's fail-fast behavior, requiring server support for the object-info capability, and rejecting short OIDs for safety. The implementation includes dynamic capability validation, input size limits, and comprehensive error handling.

All maintainers (Junio Hamano, Patrick Steinhardt, Jonathan Tan, Christian Couder, Taylor Blau) have approved the approach. The only remaining issues are a memory management concern in patch 10/12—where Junio endorsed Chandra Pratap's observation about unnecessary `static` declarations—and a minor documentation nit about backward iteration safety. Pablo Sabater has addressed all other feedback, including implementing clean failure for unsupported features and adding strict format placeholder validation. The series demonstrates strong attention to security, edge cases, and cross-platform correctness.
