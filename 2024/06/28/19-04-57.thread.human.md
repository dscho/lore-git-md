This thread implements a security-hardened `remote-object-info` command for `git cat-file --batch-command`, allowing users to query object metadata (currently just size) from remote repositories without downloading full objects. The series has reached its 16th version after extensive review and refinement, with all technical and security issues now resolved.

The feature is complete, including server capability advertisement, client-side logic, dynamic capability-based format placeholder validation, and comprehensive test coverage. Key improvements in the latest version include fixing a critical refactoring flaw identified by Junio Hamano (removing a problematic static variable entirely), addressing memory leaks in the transport helper subsystem, and implementing runtime validation of format placeholders to prevent crashes. The implementation now safely handles unsupported placeholders by returning empty strings rather than failing, matching established Git patterns like `for-each-ref`.

Pablo Sabater has led the implementation, addressing all review feedback from Junio Hamano, Karthik Nayak, Chandra Pratap, Jonathan Tan, and Christian Couder. The series includes 699 lines of new tests and maintains strict protocol v2 compliance with capability checks. One open question remains about error handling philosophy (whether to fail explicitly or continue silently when metadata is missing), but this is documented and doesn't block merging.

The code is ready for integration, with all security considerations addressed: dynamic capability-based validation, buffer overflow protection, strict input validation, and memory safety verified through multiple fixes. The feature is disabled by default on the server side (`transfer.advertiseobjectinfo`), and includes sensible limits to prevent abuse (10,000 objects max per batch, 8KB URL length limit).
