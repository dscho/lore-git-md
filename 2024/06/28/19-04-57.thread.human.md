This thread documents the 12-iteration development of a secure remote object-info feature, allowing clients to query object sizes from Git servers without full objects. The implementation spans protocol negotiation, transport layer support, and both client/server security hardening. After extensive review, the series has reached production-ready status with all identified vulnerabilities addressed.

The core functionality enables servers to advertise object-info capability (via transfer.advertiseobjectinfo) and clients to request sizes using a restricted format string syntax. Security was a primary focus throughout, with server-side protections including input validation, request size limits, and strict format string whitelisting. The final iteration simplified client-side parsing while maintaining safety, recognizing its trusted execution context.

Recent discussion centers on refinements to format string validation after discovering a segfault vulnerability with unsupported placeholders. Jeff King suggests alternative validation approaches and raises design questions about handling unsupported placeholders - whether to error strictly or return empty values, particularly when mixing remote and local requests. This builds on earlier security hardening from Jeff, Junio Hamano, and others across the series' twelve versions.

The implementation now includes comprehensive test coverage, supports multiple transports (git://, file://, http://), and integrates with git-cat-file. All technical issues have been resolved through collaborative review, with particular security scrutiny from Jeff King. The series represents a complete solution for secure remote object size queries.
