This thread implements a security-hardened `remote-object-info` command for `git cat-file --batch-command`, allowing users to query object metadata (currently just size) from remote repositories without downloading full objects. The feature has progressed through 15 versions and is now ready for merging, with all technical and design issues resolved.

The implementation adds a new `remote-object-info` command that accepts multiple object IDs in a single request, minimizing remote communication overhead. It supports only `%(objectname)` and `%(objectsize)` placeholders for now, with strict input validation including checks for malformed OIDs and a 10,000-object batch limit. The patch includes 680 lines of comprehensive tests covering edge cases and all three transport protocols.

One remaining open question is whether the client should fail explicitly or continue silently when metadata is missing - Pablo prefers silent continuation while Karthik favors explicit failure, but this doesn't block merging.
