This thread is about a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`, allowing Git clients to query object metadata (like size) from remote repositories without downloading the full objects. The series is now in its 18th version and is queued for merging into the `next` branch, meaning it’s considered technically complete and ready for integration testing.

The latest update, patch 12/13 in this iteration, fixes a critical robustness issue in how format placeholders are validated for remote queries. Previously, the code used a simple `strstr()` check, which could cause segfaults or fatal errors if unsupported atoms were used or if the server didn’t provide expected data. The fix introduces a dynamic allow-list of supported atoms (`objectname` and `objectsize`) and changes the behavior to return empty strings for unsupported placeholders, similar to how `for-each-ref` handles such cases. This makes the feature more resilient and prevents format strings from breaking local operations if reused.

The series has been through extensive review and testing, with all known technical, security, and design issues resolved. It includes strict input validation, memory safety measures, and comprehensive test coverage. The implementation is now functionally complete for its initial scope (size-only queries), with future expansions (like object type support) designed to be backward-compatible. The maintainer has queued it for merging, so unless new issues arise, it should graduate to the `master` branch in the near future.
