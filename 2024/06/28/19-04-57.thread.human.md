This thread tracks Pablo Sabater's 16-part GSoC series implementing `git cat-file --batch-command remote-object-info`, which lets users query object metadata (like size) from remote repositories without downloading full objects. The series is now complete and ready for merging, with all technical and security issues resolved.

The final version adds dynamic capability-based filtering of format placeholders, replacing the static allow-list with a system that checks what metadata the server actually supports before making requests. This future-proofs the design for additional metadata like object types while maintaining strict validation. The implementation includes proper memory management, comprehensive error handling, and backward compatibility with existing Git patterns.

Key improvements in this version include fixing a critical refactoring flaw identified by Junio Hamano (removing a problematic static variable entirely), addressing a memory leak in the transport helper subsystem, and adding 699 lines of new tests covering all transport types and edge cases. The series also includes preparatory work like moving and generalizing the `write_fetch_command_and_capabilities()` function, refactoring the state machine in `do_fetch_pack_v2()`, and adding server capability advertisement for the `object-info` feature.

Reviewers Junio Hamano, Chandra Pratap, Karthik Nayak, Jonathan Tan, and Christian Couder have all weighed in, with all substantive feedback addressed. The only remaining open question is whether the client should fail explicitly or continue silently when metadata is missing - no consensus was reached, but the behavior is now clearly documented. The series balances security, compatibility, and maintainability, with strict protocol enforcement, input validation, and memory safety verified throughout.
