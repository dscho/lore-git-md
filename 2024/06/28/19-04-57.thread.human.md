This thread tracks a security-hardened patch series that adds a `remote-object-info` command to `git cat-file --batch-command`, allowing users to query object metadata (currently just size) from remote repositories without downloading full objects. The series, now at **version 17**, has resolved all technical and design issues, including a critical refactoring flaw identified by Junio Hamano in v15, memory leaks in the transport helper subsystem, type mismatches, and unsafe format placeholder handling that previously caused segfaults and crashes.

The implementation is complete, with the final patch in v17 introducing **dynamic capability-based placeholder validation**. This system maps server-advertised capabilities (e.g., "size") to format atoms (e.g., "objectsize") at runtime, ensuring clients only request metadata the server can provide. The approach replaces an earlier static allow-list with a flexible, forward-compatible design that gracefully handles unsupported placeholders by returning empty strings—matching Git’s established patterns in `for-each-ref` and local `git cat-file` behavior. The series also includes **699 lines of new tests** covering all transport types, edge cases, and error conditions, along with comprehensive memory safety improvements, strict input validation, and protocol v2 enforcement.
