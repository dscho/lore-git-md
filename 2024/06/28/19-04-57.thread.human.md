This thread is about the final polish of the GSoC `remote-object-info` series, now at version 18 and queued for `next`. The series lets Git clients query object metadata (like size) from remotes without downloading the full object, using a new `remote-object-info` command and the `object-info` protocol v2 capability.

Junio and Pablo are ironing out the last behavioral edge cases. They’ve clarified how unsupported placeholders (like `%(objectcolor)`) are handled—they’re omitted entirely, producing output like `42 ` instead of `42 %(objectcolor)`. Pablo will add a concrete example to the commit message to make this clearer. The bigger open question is whether `%(objectname)`-only requests should skip the remote query entirely (Pablo’s preference) or fetch cheap metadata (like size) to validate the object’s existence (Junio’s suggestion). This is a trade-off between efficiency and robustness, and no resolution has been reached yet.

The series is technically complete, with all prior feedback incorporated, CI passing, and no remaining design or implementation concerns. These final discussions are about usability and documentation, not blocking issues. The dynamic allow-list for metadata fields and placeholder handling are now well-documented, so the series is ready to graduate unless Junio’s preference for existence checks leads to a follow-up patch.
