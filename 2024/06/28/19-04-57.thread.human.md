This thread is about a long-running security-hardened feature series that adds `git cat-file --batch-command` support for querying object metadata from remotes without full downloads. The series, now at **v20**, has been queued for `next` and is effectively complete, with all technical, security, and design issues resolved. Pablo Sabater is the primary author, with contributions from Calvin Wan, Eric Ju, and others.

The feature allows Git clients to fetch object metadata (currently size, with type support designed for future expansion) via the `object-info` protocol v2 capability. Key components include a new `remote-object-info` command in `git cat-file --batch-command`, dynamic adaptation to server-advertised capabilities, and robust handling of edge cases like missing objects or unsupported attributes. The implementation is memory-safe, with strict input validation, bounds-checking, and a 10,000-object batch limit to prevent abuse. The client batches multiple OIDs into a single request to minimize overhead, and the server enforces unconditional existence checks for bare OID requests to avoid lazy-fetching in partial clones.

The latest update (v20) introduces dynamic capability negotiation, replacing the hardcoded allow-list with a runtime-negotiated one. This ensures forward compatibility as the protocol evolves, with unsupported placeholders (e.g., `%(objecttype)`) silently omitted to match `for-each-ref` behavior. Other recent fixes include a build fix for a signed/unsigned comparison warning, a memory leak fix in `transport-helper.c`, and documentation tweaks. The series has passed CI and is ready for final polish before merging to `master`. Minor unresolved nits (e.g., translation context, alphabetical ordering) are cosmetic and won’t block graduation. Junio has confirmed no remaining design or implementation concerns.
