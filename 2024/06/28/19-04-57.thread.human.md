This thread implements full `git cat-file --batch-command` support for querying remote object metadata (initially size only, with type support designed for future expansion). The series, now at **v21**, has been **queued for `next`** after clearing all technical and design reviews. Junio has just confirmed the merge, marking the final procedural step before graduation to `master`.

The implementation enables Git clients to request object metadata from remotes via the `object-info` protocol v2 capability, with dynamic negotiation of supported attributes (e.g., `size`). Key features include strict input validation (10,000-object batch limit, 8KB URL cap), memory safety (leak fixes, bounds checks), and robust edge-case handling (missing objects, unsupported protocols). The client-side `remote-object-info` command batches requests, adapts to server capabilities, and outputs results in a configurable format (default: `%(objectname) %(objectsize)`). Server-side changes enforce consistent object-existence checks and advertise supported attributes when `transfer.advertiseobjectinfo` is enabled.

All prior concerns—including dynamic capability negotiation, `%(objectname)`-only request handling, memory leaks, and test infrastructure reuse—have been resolved. The series is technically complete for its initial scope, with 747 lines of new tests covering smart transports, `--buffer` mode, and edge cases. Cosmetic nits (documentation typos, macro formatting) addressed in v21 were non-blocking.
