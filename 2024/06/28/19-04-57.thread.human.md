This thread is about a security-hardened implementation of `git cat-file --batch-command` for querying object metadata from remotes without full downloads. The series, now at version 13, has undergone exhaustive refinement and is nearly ready for merging, with all major technical, security, and design issues resolved except two: a memory management issue in the client implementation and a protocol compatibility regression risk in a refactoring step.

The series introduces dynamic capability-based format placeholder validation, strict protocol v2 enforcement, and complete client-server protocol integration. Key maintainers—Junio Hamano, Patrick Steinhardt, Jonathan Tan, Christian Couder, and Taylor Blau—have reviewed and approved the approach. The implementation includes multi-object batching (10,000 objects/request), input size limits to prevent denial-of-service, and strict validation to reject short OIDs for safety. Two confirmed issues remain: unnecessary `static` declarations in `parse_cmd_remote_object_info()` (patch 10/12), which could introduce thread-safety concerns, and an unintentional substitution of `GIT_HASH_SHA1_LEGACY` with `GIT_HASH_SHA1` in `connect.c` (patch 6/12), which breaks backward compatibility with pre-v2 servers. Pablo Sabater has confirmed both issues and will address them in version 14.
