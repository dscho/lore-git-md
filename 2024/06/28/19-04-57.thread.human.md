This thread is about a long-running security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`, now at its 19th version and queued for the `next` branch. The series allows Git clients to query object metadata (like size) from remote repositories without downloading the full objects, using the `object-info` protocol v2 capability.

The latest update is a small but important patch that lets servers advertise which object-info attributes they support—currently just `size`—when the `transfer.advertiseobjectinfo` configuration is enabled. This is a direct response to earlier feedback, ensuring clients don’t waste time requesting unsupported attributes. The feature is opt-in and disabled by default, reflecting the series’ conservative approach. The patch itself is minimal, touching only a few lines in `serve.c`, and doesn’t change behavior beyond the advertisement.

The series has resolved all major technical and design issues, including handling of `%(objectname)`-only requests, memory leaks, and edge cases like missing objects or unsupported placeholders.
