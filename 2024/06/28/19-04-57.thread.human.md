This thread is about a security-hardened series implementing `git cat-file --batch-command` support for querying object metadata from remotes without full downloads. The series, now at **v21**, is technically complete and queued for `next`, with all prior technical, security, and design issues resolved. The author, Pablo Sabater, has driven the effort through 21 iterations, addressing dynamic capability negotiation, memory leaks, edge-case robustness, and test infrastructure reuse.

The implementation enables Git clients to query object metadata (currently size, with type support designed for future expansion) from remote repositories via the `object-info` protocol v2 capability. Key features include full object ID support, numeric `obj-size` values, strict handling of unsupported OIDs, and dynamic adaptation to server-advertised capabilities. The client-side `remote-object-info` command batches multiple OIDs into a single request, enforces strict input validation (8KB URL limit, 10,000-object cap), and handles edge cases like missing objects or unsupported protocols. The server side advertises supported attributes (e.g., `size`, `type`) when `transfer.advertiseobjectinfo` is enabled, and the latest patch (9/13) ensures consistent object-existence checks regardless of requested attributes.

Recent changes in v21 include documentation cleanups, macro formatting fixes, memory leak fixes (including a newly identified leak in `transport-helper.c`), static variable removal, type consistency fixes, and mechanical refactoring for function relocation and generalization. The series is now cleared for graduation to `master`, with no further changes expected. Three minor cosmetic issues remain unresolved (translation context, alphabetical ordering in `cat-file.c` and `Makefile`), but these are non-blocking. The GitHub CI run shows no failures, and Junio’s prior confirmation of no unresolved concerns stands validated. The series is ready for final integration.
