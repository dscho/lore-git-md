This thread implements a security-hardened feature allowing `git cat-file --batch-command` to query object metadata from remote repositories without downloading full objects. The series, now at its 17th version, is complete and ready for merging after addressing all technical and design issues raised during review.

The key development in this patch is server-side capability advertisement for the `object-info` feature, controlled by the `transfer.advertiseobjectinfo` configuration (disabled by default). This patch updates protocol documentation to clarify requirements—full object IDs only, numeric `obj-size` fields, and clear behavior for unrecognized objects—and implements the server-side logic in `serve.c`. The changes are purely preparatory, enabling the client-side functionality that follows in later patches while maintaining the series' security focus through strict protocol enforcement and conservative defaults.

All critical issues from earlier versions have been resolved, including a refactoring flaw in v15, memory leaks in transport helpers, type mismatches, and state machine improvements. The series now includes comprehensive test coverage (699 lines of new tests), dynamic capability-based placeholder validation, and verified memory safety. Reviewers Junio Hamano, Chandra Pratap, Karthik Nayak, Jonathan Tan, and Christian Couder have all contributed substantive feedback, with Chandra Pratap's final review confirmation marking the series as ready for Junio's merge to `next`. The only remaining open question—whether clients should fail explicitly or continue silently when metadata is missing—has been documented but does not block merging.
