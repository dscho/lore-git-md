This thread implements a security-hardened feature allowing `git cat-file --batch-command` to query object metadata from remote repositories without downloading full objects. The series, now at version 17, is complete and has addressed all prior technical and design feedback, including critical refactoring flaws, memory leaks, type mismatches, and security issues in format placeholder handling.

The latest review from Junio Hamano raises two points on the final patch. The first is a minor style suggestion about breaking up a long line in a `for` loop. The second is a substantive security concern: the response parsing logic accesses `object_info_values.items[1 + size_index]` without first verifying the `string_list` contains enough elements. This could lead to an out-of-bounds read if a server returns fewer values than expected, either due to a bug or malice. While the current implementation is safe for the immediate use case, this could become problematic if the protocol is extended to support additional metadata attributes.

All other issues have been resolved. The series includes 699 lines of new tests, verified memory safety, dynamic capability-based placeholder validation, and comprehensive input validation. The implementation is ready for merging once this final bounds-checking issue is addressed. Pablo Sabater will likely send a v18 with the fix, after which the series should be merged to `next`.
