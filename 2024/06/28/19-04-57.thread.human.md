This thread implements a security-hardened `git cat-file --batch-command` feature for querying object metadata from remotes without full downloads. The series, now at version 13, has addressed nearly all technical and design concerns but still has three open issues—two of which were just clarified in this exchange.

Pablo Sabater, the author, responded to Karthik Nayak’s review of patch 6/12, confirming that a key protocol compatibility regression was unintentional. The change from `GIT_HASH_SHA1_LEGACY` to `GIT_HASH_SHA1` in the hash algorithm check (which could break backward compatibility with pre-v2 servers) will be reverted in the next version. Pablo also agreed to move a function comment from the header to the implementation file, though he’ll keep the forward declaration to avoid circular dependencies, as previously advised by Patrick Steinhardt.

The only remaining unresolved issue is a memory management concern in patch 10/12, where unnecessary `static` declarations in `parse_cmd_remote_object_info()` could introduce thread-safety risks. With these fixes in place, the series should be ready for merging, as all core maintainers have already approved the approach. The next version (v14) will address the two newly confirmed issues, bringing the series closer to completion.
