This thread implements a security-hardened feature allowing Git clients to query object metadata (currently just size, with type support planned) from remote repositories without downloading full objects, using `git cat-file --batch-command` with the new `remote-object-info` subcommand. The series, now at **v19**, is technically complete and queued for Junio’s `next` branch, with all substantive design and security concerns resolved after 18 prior iterations.

The core implementation enables the `object-info` protocol v2 capability, letting clients request metadata via `remote-object-info <remote> <oid>...` across all smart transports. Key details include strict input validation (10,000-object batch limit, 8KB URL length cap), dynamic allow-lists for metadata fields, and robust handling of edge cases like missing objects or unsupported placeholders. The latest update (v19) adds a new commit ensuring bare OID requests trigger server-side existence checks, fixes response grammar in the protocol documentation, and tightens input validation in `fetch-object-info.c`. It also squashes two v18 commits into one and resolves a session-state bug where format settings could leak between commands.

Pablo Sabater is the primary author (7/13 patches), with contributions from Eric Ju and Calvin Wan. Junio’s earlier concerns—particularly around robustness for `%(objectname)`-only requests—have been addressed, and the series now includes 747 lines of new tests covering edge cases. Minor cosmetic nits (alphabetical ordering in code and build files) remain but are unlikely to block graduation. The series is ready for `master` after final polish, with its initial scope (size-only queries) now stable and extensible for future metadata fields.
