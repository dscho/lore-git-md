This thread implements a security-hardened feature allowing `git cat-file --batch-command` to query object metadata (like size) from remote repositories without downloading full objects. The series, now at **v18**, is complete and queued for merging into `next` after resolving all technical and security concerns.

The work is led by Pablo Sabater, who took over as primary author after earlier iterations by Eric Ju and Calvin Wan. The final version includes **10 patches**, with the latest addressing bounds-checking, memory leaks, type mismatches, and a critical refactoring flaw in `fetch-pack.c` where a static variable was left uninitialized. The series also introduces **699 lines of new tests** and refactors test infrastructure to avoid duplication.

Key improvements in v18 include:
- **Bounds-checking** in the final patch to prevent out-of-bounds reads when parsing server responses.
- **Dynamic placeholder validation**, replacing a static allow-list with runtime filtering based on server-advertised capabilities.
- **Memory safety fixes**, including a leak in the transport helper subsystem and loop counter hygiene refactoring.
- **Protocol extensibility**, with the `object-info` capability documented for future metadata features (e.g., `objecttype`).

The series has received **substantive reviews** from Junio Hamano (who identified critical flaws in earlier versions), Karthik Nayak, Jonathan Tan, and Christian Couder. Junio confirmed the series is ready for `next` in the v18 cover letter, and Chandra Pratap marked it as ready for merging. Pablo plans a follow-up to add `objecttype` support once this lands.
