This thread is about a long-running security-hardened series that adds `git cat-file --batch-command` support for querying object metadata from remotes without full downloads. The series is now at **v21** and has been queued for `next`, meaning it’s on track for the next Git release.

The core feature lets Git clients request object metadata (currently just size, with type support designed for future expansion) from remote repositories using the `object-info` protocol v2 capability. The client batches multiple object IDs into a single request, validates inputs strictly, and dynamically adapts to server-advertised capabilities. Security measures include a 10,000-object batch limit, 8KB URL length cap, and strict memory management to prevent leaks.

The latest update, from Pablo Sabater, makes the client’s atom allow-list dynamic. Instead of hardcoding support for only `objectname` and `objectsize`, the client now queries the server for each requested placeholder (e.g., `%(objectsize)`) and filters out unsupported options. This ensures compatibility with servers that may support additional attributes in the future, like `objecttype`. Unsupported atoms expand to empty strings, matching `for-each-ref` behavior, while unknown atoms still trigger errors.

All technical and design concerns from prior versions have been resolved, including memory leaks, edge-case robustness, and test infrastructure reuse. The series is technically complete for its initial scope and has no outstanding blockers. Junio’s "What’s cooking" report and Pablo’s confirmation validate its readiness for graduation to `master`. The only remaining items are minor cosmetic nits (translation context, alphabetical ordering in code), which won’t delay integration. The series is authored primarily by Eric Ju, with significant contributions from Pablo Sabater and Calvin Wan.
