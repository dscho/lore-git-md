This thread is about a security-hardened feature that lets Git clients query object metadata (like file size) from remote repositories without downloading the full objects. The series, now at version 18, is complete and queued for merging into Git's `next` branch.

The core feature is a new `remote-object-info` command, part of `git cat-file --batch-command`, which lets users request metadata for one or more objects from a remote repository. The implementation is robust: it enforces strict input validation, limits batch sizes, and dynamically adapts to what the server supports to avoid crashes or errors. For example, if you ask for metadata the server doesn’t provide (like object type), the command now returns an empty string instead of failing, matching how `for-each-ref` handles unsupported fields.

The latest update, from Pablo Sabater, replaces a hardcoded list of allowed metadata fields with a dynamic system that only permits what the server advertises. This paves the way for future expansions (like adding object type support) while keeping the current version stable and secure.
