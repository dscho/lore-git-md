This thread implements a security-hardened `git cat-file --batch-command` extension to query object metadata from remotes without full downloads. The series, now at version 15, is nearly complete, with all technical and design issues resolved except for one critical refactoring flaw in patch 5/13.

The main development is the final integration of the `remote-object-info` command, which supports batching multiple object queries, dynamic capability-based placeholder validation, and strict protocol v2 enforcement. The protocol's extensibility has been formally documented, with future metadata attributes (like `objecttype`) to be appended to the same space-separated capability list. The series also includes platform-independent numeric conversion, shared test infrastructure, and preparatory refactoring for protocol command reuse.

The only remaining blocker is a refactoring issue in patch 5/13, where Junio Hamano identified an uninitialized local variable and a lingering global variable. The fix is straightforward—initialize the local variable to `0` and split the unrelated `hash_algo` type change into a separate patch. Additionally, Junio and Pablo Sabater resolved a minor input validation concern in the new `strtoumax_szt()` helper, ensuring it rejects non-digit characters like `+` and `-` for consistency with Git’s other numeric parsers. This adjustment is now ready for merging.

The series has seen substantive reviews from Junio Hamano, Karthik Nayak, Chandra Pratap, Jonathan Tan, and Christian Couder, with all actionable feedback addressed. The only unresolved discussion is whether the client should fail explicitly or continue silently when metadata is missing, but this is documented and does not block merging. The implementation includes 680 lines of new tests and verified memory safety improvements, making it ready for integration once the patch 5/13 flaw is fixed.
