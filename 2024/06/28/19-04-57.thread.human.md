This thread is about a security-hardened series that adds `git cat-file --batch-command` support for querying object metadata from remotes without full downloads. The series, now at its 19th version, is technically complete and queued for Junio’s `next` branch, meaning it’s under final integration testing before graduating to the main codebase.

The core feature lets Git clients fetch object metadata (currently just size, with type support designed for later) from remote repositories using the `object-info` protocol v2 capability. The implementation is transport-agnostic, enforces strict security limits (10,000-object batches, 8KB URL length), and handles edge cases like missing objects or unsupported format placeholders gracefully. A key design decision—validating object existence even for bare OID requests—was resolved in favor of robustness over efficiency, with Junio explicitly endorsing this approach.

The latest email covers a mechanical refactoring patch (5/13) that moves a helper function from `fetch-pack.c` to `connect.c` to enable broader reuse. Authored by Calvin Wan but carried by Pablo Sabater, the patch is purely preparatory and introduces no functional changes. The series has addressed all prior feedback, including memory leaks, type inconsistencies, and test infrastructure reuse, and is now focused on minor polish (e.g., documentation tweaks) before merging to `master`. CI runs confirm readiness, and the only remaining work is cosmetic.
