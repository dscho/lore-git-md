This is the final patch in a series adding remote object info support to `git cat-file --batch-command`. The patch implements the `remote-object-info` command that allows querying object metadata from remote servers without full downloads, building on the transport layer support added in previous patches.

Key technical details:
- The command takes a remote URL followed by one or more object IDs
- Currently only supports `%(objectname)` and `%(objectsize)` format specifiers (other specifiers like `%(objecttype)` error out)
- Works across git://, http:// and file:// transports (protocol v2 required)
- Implements both buffered and non-buffered modes with different request batching behavior
- Includes comprehensive tests covering security edge cases and protocol requirements

The implementation builds on the series' security hardening (format string validation, request limits) while optimizing for remote performance by allowing multiple object queries per request. The patch maintains the series' strict protocol v2 requirement and input validation.

Open questions from earlier in the series remain about protocol v1 fallback behavior and object type support, but the core functionality appears complete and well-tested. The implementation looks production-ready with thorough test coverage across transport methods and edge cases.
