This is a refactoring patch that prepares for remote object-info functionality by generalizing fetch-pack's packet writing code. It's the first in a 6-patch series implementing `git cat-file --batch-command` integration for remote object queries.

The patch renames `write_fetch_command_and_capabilities()` to the more generic `write_command_and_capabilities()` and makes the command name parameterizable. This allows the same function to be reused for both fetch operations and the new remote object-info command being added in later patches. The changes are mechanical - the core capability writing logic remains the same, just made more flexible.

Key technical details:
- The modified function now takes a `command` parameter instead of hardcoding "fetch"
- All call sites are updated to pass "fetch" to maintain current behavior
- The `ensure_server_supports_v2()` check now validates support for the specific command
- Function signature change is straightforward with no behavior modifications

The patch has been reviewed by Calvin Wan (original author of the remote object-info work) and includes Helped-by tags from Jonathan Tan and Christian Couder, indicating prior discussion. This appears to be a clean, focused refactoring that enables the subsequent patches while maintaining existing functionality. The changes are well-contained to fetch-pack.c with minimal diff noise.
