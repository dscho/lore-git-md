This is a feature patch series adding remote object information queries to `git cat-file --batch-command`. The series builds on Calvin Wan's earlier work to implement server-side object info support, now completing the client-side functionality.

The key addition is a new `remote-object-info` command for `cat-file --batch-command` that lets clients query object metadata (currently just size) from protocol v2 servers without downloading full objects. The implementation handles capability negotiation, falls back to full fetches when needed, and includes comprehensive tests.

The series has gone through multiple iterations (this is a continuation of Calvin's v5) with security hardening and behavior refinements. It touches several subsystems - transport layer, fetch-pack, and cat-file - with changes to packet writing, capability advertisement, and command-line interface.

Two open questions remain about behavior:
1. Whether to die or just warn when encountering protocol v1 (current implementation dies)
2. How to handle format strings requesting unsupported fields like objecttype (currently dies but breaks default format)

The patch set appears well-structured with clean commit separation and thorough test coverage. Given the extensive prior discussion and security hardening, this looks ready for final review, with the open questions being the last design decisions needed before merging.
