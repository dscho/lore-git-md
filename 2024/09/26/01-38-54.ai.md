This is a feature patch adding client-side transport support for remote object info queries, part of a 6-patch series implementing `git cat-file --batch-command` integration for querying object metadata from remotes without full downloads.

The patch implements the core transport layer plumbing to request object information from protocol v2 servers, building on the server-side capability added in a2ba162cda. Key technical aspects:

- Adds `fetch_object_info()` in transport.c to handle protocol negotiation and response parsing
- Implements fallback to full fetch when server lacks object-info capability
- Enforces protocol v2 requirement (v1 attempts die with error)
- Supports multiple-OID batching to reduce network overhead
- Currently limited to size queries (objecttype handling is planned future work)
- Includes security hardening from prior iterations (format string validation, request limits)

The implementation integrates with fetch-pack.c's state machine and adds new fields to transport.h's git_transport_options struct to pass object info requests through the stack. The transport-helper.c changes explicitly fail protocol v1 attempts rather than silently falling back.

This appears to be the main client-side implementation patch in the series, with thorough test coverage already established in t1017. The changes are well-contained to the transport layer while maintaining existing fetch behavior. Review feedback from Jonathan Tan and Christian Couder has been incorporated, addressing style and documentation concerns from earlier versions.

The patch keeps the security measures from the server implementation while adapting them for the client context. It positions the feature for future extension (like objecttype support) through the transport options struct while keeping the initial scope focused on size queries. The series as a whole looks ready for integration with all major technical concerns addressed.
