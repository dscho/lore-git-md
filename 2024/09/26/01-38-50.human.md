This is a feature patch series adding remote object info support to `git cat-file --batch-command`, building on prior work by Calvin Wan. The series implements client-side support for querying object information from protocol v2 servers without full downloads, with security hardening from previous iterations now complete.

The 6-patch series refactors fetch-pack packet writing, moves fetch initialization, advertises the object-info capability, adds transport layer support, and finally implements the `remote-object-info` command for `cat-file`. The implementation includes comprehensive tests in t1017 covering security edge cases and multiple transport protocols (git://, file://, http://).

Key technical points:
- Server-side security measures remain enforced (format string validation, request limits)
- Client-side parsing is simplified while maintaining safety
- Behavior aligns with ref-filter conventions for unsupported fields
- Protocol v2 is required - v1 attempts error out
- Currently only supports object size queries, with objecttype handling being a point of discussion

The cover letter raises two open questions about behavior:
1. Whether to die or warn+continue on protocol v1 attempts
2. How to handle objecttype requests (currently dies but breaks default format)

The series appears well-structured with thorough test coverage, building on established security foundations from the server-side implementation. The remaining questions seem focused on finalizing user-facing behavior rather than technical implementation concerns. The patches have undergone multiple iterations with feedback from reviewers like Christian Couder and Toon Claes, addressing style and documentation issues.
