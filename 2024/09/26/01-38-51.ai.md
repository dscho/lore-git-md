This is a refactoring patch that generalizes fetch-pack's packet writing functionality to support additional protocol v2 commands beyond just "fetch". It's the first in a 6-part series adding remote object info support to `git cat-file --batch-command`.

The patch renames `write_fetch_command_and_capabilities()` to the more generic `write_command_and_capabilities()` and makes it take the command name as a parameter. This allows the same function to be used for both fetch operations and the new "object-info" command being introduced in later patches. The change is mechanical but important infrastructure work - it doesn't change behavior for existing fetch operations.

Key technical details:
- The refactored function now takes a `command` parameter instead of hardcoding "fetch"
- A new `send_object_info_request()` helper is introduced that uses this to write "object-info" commands (used in later patches)
- All existing fetch call sites are updated to pass "fetch" explicitly
- The change maintains all existing protocol v2 capability negotiation behavior

The patch has already received positive review feedback from Jonathan Tan and Christian Couder, who are both familiar with the protocol v2 internals. The changes are straightforward and well-contained to fetch-pack.c, with no user-visible effects yet (those come in later patches). This appears to be solid foundational work for the remote object info feature.
