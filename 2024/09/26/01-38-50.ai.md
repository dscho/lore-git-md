This is a feature patch series adding remote object info support to `git cat-file --batch-command`, building on prior work by Calvin Wan. The series implements client-side support for querying object information from protocol v2 servers without full downloads, with security hardening from previous iterations now complete.

The 6-patch series refactors fetch-pack packet writing, moves fetch initialization, advertises the object-info capability, adds transport layer support, and finally implements the `remote-object-info` command for `cat-file`. Key technical points include:

- Server-side security measures remain enforced (format string validation, request limits)
- Client-side parsing is simplified for trusted contexts while maintaining safety
- Behavior aligns with ref-filter conventions for unsupported fields
- Protocol v2 is required - v1 will error out
- Currently only supports object size queries, with objecttype handling being a point of discussion

The implementation includes comprehensive tests in t1017 covering security edge cases and multiple transport protocols (git://, file://, http://). The series appears well-structured with thorough test coverage, building on established security foundations from the server-side implementation.

Two open questions remain about user-facing behavior:
1. Whether to die or warn+continue on protocol v1 attempts
2. How to handle objecttype requests (currently dies but breaks default format)

The changes since v2 focus on documentation improvements, commit message enhancements, and confirming test coverage of the new transport.c, fetch-pack.c and transport-helper.c logic. The series has received positive feedback from multiple reviewers (Christian Couder, Toon Claes, Jonathan Tan) and appears ready for maintainer consideration.
