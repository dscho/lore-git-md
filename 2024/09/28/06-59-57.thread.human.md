This thread documents a growing concern about Git's `--committer-date-is-author-date` option, which can create commit histories that violate Git's timestamp ordering assumptions. The discussion began with a documentation patch adding warnings to the `git-am` and `git-rebase` man pages about how this option (originally added in 2009 for consistent commit IDs when emailing patches) might cause problems during revision walking.

Phillip Wood has led the technical analysis, distinguishing between valid use cases in `git-am` (where preserving original timestamps when reapplying patches makes sense) versus questionable usage in `git-rebase` (which typically moves commits forward in time). Kristoffer Haugsbakk, responding to Phillip's review, has agreed to several documentation refinements: removing an unclear reference to `git-rev-list` clock skew, softening the wording from "lie" to "override," and making the rebase-specific warnings more precise.

The conversation is now converging on the idea that this option may not belong in `git-rebase` at all, with Kristoffer indicating willingness to mark it as deprecated for rebase in the next version of the patch. While the immediate focus remains on improving the warning text, this could lead to future behavioral changes. Phillip Wood will be unavailable for 10 days but plans to review any revisions when he returns. The discussion highlights both technical concerns about timestamp ordering and user-facing issues around how Git metadata is displayed in popular interfaces like GitHub.
