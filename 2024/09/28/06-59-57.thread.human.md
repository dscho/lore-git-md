This thread discusses the `--committer-date-is-author-date` option in `git-am` and `git-rebase`, which can create commit histories that violate Git's timestamp ordering assumptions. The original patch from Kristoffer Haugsbakk proposed adding warnings to the documentation about this potentially problematic behavior.

The discussion has evolved to distinguish between valid uses in `git-am` (where it helps maintain consistent commit IDs when reapplying patches) versus questionable uses in `git-rebase` (where it can create misleading commit histories). Phillip Wood provided key technical analysis supporting this distinction and suggested deprecating the option for `git-rebase` while keeping it for `git-am`.

In the latest email, Kristoffer agrees with the deprecation approach and offers to mark the option as deprecated in the next patch version. He also raises a new idea: adding a stderr warning when the option is used with `git-rebase`, which would make the issue more visible than just documentation changes. This suggests the discussion is moving beyond documentation toward potential implementation changes, though still focused on user awareness rather than immediate behavior modification. Kristoffer wonders why this approach hasn't been used before, speculating it might relate to concerns about breaking scripts that parse stderr output.
