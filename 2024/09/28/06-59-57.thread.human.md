This thread has reached a clear resolution regarding the problematic `--committer-date-is-author-date` option in `git-am` and `git-rebase`. The discussion, initiated by Kristoffer Haugsbakk, examined how this option violates Git's fundamental assumption that commit timestamps should be non-decreasing in the history. Through technical analysis from Johannes Sixt, Phillip Wood, and Junio Hamano, the community concluded that the original 2009 use case (creating consistent commit IDs when emailing patches) was fundamentally flawed.

The final outcome is a v2 documentation patch from Kristoffer that implements strong warnings about the option's dangers while keeping it available - following Junio's "long rope" philosophy. The warnings now clearly state that using this option violates Git's DAG assumptions, with upgraded WARNING callouts replacing the previous NOTE boxes. All misleading suggestions of "legitimate uses" have been removed, and the terminology has been made more precise. Both Johannes Sixt (who originally argued for outright removal) and Phillip Wood have given their approval to this approach, confirming the technical consensus.

This thread serves as a good example of how the project handles cases where historical features no longer align with current technical understanding - through careful documentation rather than immediate removal, while making the technical realities clear to users. The discussion also clarified that the original use case of pseudo-importing via `git-am` was never valid given Git's timestamp requirements. With these changes merged, users will be properly warned about the implications of using this option.
