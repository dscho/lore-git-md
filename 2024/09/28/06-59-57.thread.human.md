This thread examines the `--committer-date-is-author-date` option in `git-am` and `git-rebase`, originally added in 2009 to maintain consistent commit IDs when emailing patches. The initial documentation update warns that this option can violate Git's assumption of strictly increasing timestamps during revision walking, particularly problematic in rebase operations. 

SZEDER Gábor and Kristoffer Haugsbakk's follow-up discussion reveals why users persist with this option despite the risks: many are unaware of the committer/author date distinction because platforms like GitHub only display committer dates by default, while others actively preserve author dates to make this metadata visible. This highlights a tension between Git's internal requirements and real-world usage patterns shaped by popular interfaces. The thread currently focuses on concrete changes to address these issues, instead surfacing important context about why users might disregard the documented warnings.
