This thread documents the deprecation process for Git's `--committer-date-is-author-date` option in `git-rebase` while maintaining it for `git-am`. The option, originally added to preserve commit IDs when emailing patches, can create timestamp ordering violations when used during rebase operations. Kristoffer Haugsbakk's documentation patch has evolved through review, with consensus now solid around distinguishing the valid `git-am` use case (applying patches) from problematic `git-rebase` usage.

The latest discussion focuses on implementation details of warning users about the deprecation. Kristoffer suggests adding stderr warnings for better visibility, but Junio Hamano notes practical limitations - these messages could get buried in normal rebase output or be completely hidden during interactive sessions where users first see an editor interface. This highlights the need to handle non-interactive and interactive cases differently, possibly combining documentation changes with context-appropriate warnings.

All participants agree on the core direction: keep the option for `git-am` where it serves a legitimate purpose, but discourage it for `git-rebase` due to timestamp ordering issues. The remaining work involves finalizing the warning mechanism, with Kristoffer preparing a v2 patch that will incorporate Junio's feedback about the "lie" terminology and interactive rebase coverage. The discussion remains focused and productive, with no new objections to the established technical rationale.
