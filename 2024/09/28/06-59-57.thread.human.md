This thread has reached consensus that the `--committer-date-is-author-date` option in `git-am` and `git-rebase` is fundamentally flawed, violating Git's timestamp ordering assumptions. The original 2009 use case - using `git-am` to reconstruct commit histories from emailed patches - has been conclusively rejected by Johannes Sixt and others as invalid.

The discussion has shifted from technical debate to documentation strategy. Johannes Sixt advocates for direct "Do not use" language, while Junio Hamano suggests a more nuanced approach. Junio proposes either officially deprecating the option (if the community agrees it's harmful enough to remove) or simply documenting its pitfalls while leaving it available - giving users "a long rope" to potentially misuse. 

Kristoffer Haugsbakk is preparing the final documentation revision, which will need to clearly explain why the original use case was flawed. The exact phrasing remains to be determined, balancing between Johannes' direct warning and Junio's more descriptive approach. While the technical conclusion is settled, the documentation will need to guide users away from this option while possibly stopping short of outright deprecation unless there's consensus for removal.
