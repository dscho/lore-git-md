The thread discusses deprecating the `--committer-date-is-author-date` option in Git's rebase` and `am` commands due to timestamp ordering issues. While the option makes sense for `git-am` (where it helps preserve commit IDs when reapplying patches), it creates problems in `git-rebase` by violating Git's assumption that commits appear in chronological order.

Kristoffer Haugsbakk is leading the documentation effort, with input from maintainers and contributors. The current consensus is to:
1) Keep the option for `git-am` but add strong warnings
2) Deprecate it for `git-rebase` due to timestamp ordering violations

The latest discussion focuses on refining the warning messages in the documentation. Johannes Sixt has suggested making the warnings more prominent by:
- Using "WARNING" instead of "NOTE" in the man pages
- Restructuring the text to place the warning either before the technical description (preferred) or within the warning section
- Improving overall readability of the documentation

Junio Hamano has noted technical challenges around warning visibility, particularly during interactive rebases where stderr output might be hidden. The group is considering embedding warnings in the interactive rebase instruction list as an alternative.

Kristoffer is preparing a v2 patch that will incorporate this feedback while maintaining the core technical direction agreed upon earlier in the thread. The discussion remains focused on implementation details rather than reopening the fundamental decisions about the option's future.
