This thread documents a careful examination of the `--committer-date-is-author-date` option in Git's `am` and `rebase` commands. The discussion began with Kristoffer Haugsbakk proposing documentation improvements to clarify when this timestamp-manipulating option is appropriate. Through review from Phillip Wood, SZEDER Gábor, and Junio C Hamano, consensus emerged that while the option serves a valid purpose in `git-am` (preserving commit IDs when reapplying patches), its use in `git-rebase` can create commit histories that violate Git's timestamp ordering assumptions.

The current focus is on implementation details for warning users about the problematic rebase case. Junio pointed out technical limitations - stderr warnings would be ineffective during interactive rebase sessions and might get lost in normal operation output. Kristoffer is now preparing a v2 documentation patch that will incorporate this feedback, likely including warnings in the interactive rebase instruction list while maintaining clear documentation about the differing appropriateness between `am` and `rebase` use cases. The discussion remains technically focused on finding the most effective way to guide users away from creating problematic commit histories while preserving legitimate uses of the option.
