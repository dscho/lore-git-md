This thread documents the deprecation of the `--committer-date-is-author-date` option in `git-am` and `git-rebase`, originally added in 2009 to enable consistent commit hashes when reapplying patches via email. The discussion has reached a decisive technical conclusion: Johannes Sixt firmly rejected the original premise that mailboxes could serve as commit storage, as the option violates Git's fundamental timestamp ordering assumptions in the commit DAG.

Kristoffer Haugsbakk, who initiated the documentation update, now acknowledges this stronger position and is preparing to revise the docs accordingly. The debate has shifted from whether to deprecate (now settled) to how best to communicate this in the documentation. Johannes prefers a direct "Do not use" warning, while Kristoffer is considering alternative phrasings. The next patch version will need to clearly state that the option should not be used and remove any examples suggesting valid use cases, marking a clear shift from the original documentation's more permissive stance.

The technical questions are resolved, with all participants agreeing the option's original purpose was flawed. What remains is finalizing the documentation language to properly warn users against this now-deprecated functionality, with Kristoffer incorporating Johannes' input into the next revision. The discussion serves as a case study in how to handle documentation updates when long-standing features are recognized as violating core system assumptions.
