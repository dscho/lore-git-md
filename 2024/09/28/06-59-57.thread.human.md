This thread documents a subtle pitfall with the `--committer-date-is-author-date` option in both `git-am` and `git-rebase`. The original patch explains that while this option was introduced in 2009 to help maintain consistent commit IDs when importing patches via email, it can create commit histories that violate Git's assumption of strictly increasing timestamps. 

The documentation updates warn users that this option should only be used when applying commits to a base older than the patches themselves, noting Git's revision walking machinery expects timestamps to increase. The author provides historical context about the option's origins in email patch workflows, while questioning its usefulness in rebasing scenarios where commit IDs change regardless. 

The changes are purely on the documentation side, adding clear warnings without modifying command behavior. The patch appears well-grounded in Git's internals and prior discussions, serving as a helpful caution for users who might otherwise unknowingly create problematic commit histories.
