This thread has reached consensus on how to document the problematic `--committer-date-is-author-date` option in `git-am` and `git-rebase`. The original use case - attempting to use `git-am` as a deterministic importer by matching committer and author dates - has been firmly rejected as violating Git's timestamp ordering assumptions. 

Kristoffer Haugsbakk has submitted a v2 documentation patch implementing strong warnings while keeping the option available, following Junio C Hamano's guidance. The new version improves upon v1 by using more prominent `WARNING` callouts instead of `NOTE` boxes, with clearer language about the risks to history traversal. It removes any suggestion of legitimate uses and replaces potentially judgmental terms like "lie" with neutral alternatives. The warnings now explicitly state that Git expects non-decreasing commit timestamps and prompt users to reconsider whether they truly need this option.

The documentation changes affect both `git-am` and `git-rebase`, with slightly adjusted wording for each command's context. While Johannes Sixt had argued for outright removal, the project has settled on Junio's approach of warning users while still providing the rope to hang themselves if they insist. No further technical debate is expected unless new objections emerge during final review.
