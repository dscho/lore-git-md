Thread identity: Documentation patch about `--committer-date-is-author-date` option in `git-am` and `git-rebase`, warning about timestamp ordering violations, with follow-up discussion about user motivations.

Core problem: The option, originally added in 2009 for consistent commit IDs when emailing patches, can create commit histories that violate Git's assumption of strictly increasing timestamps during revision walking. While useful for `git-am` when applying patches to older bases, its use in `git-rebase` is more questionable. The discussion now includes user-facing considerations - many users are unaware of the committer/author date distinction because popular interfaces (GitHub etc.) only show committer dates by default, while some actively preserve author dates to make them visible.

Current status: Documentation-only patch adding explicit warnings to man pages, not changing command behavior. No version iteration mentioned (appears to be initial submission). Follow-up reveals real-world usage patterns that may conflict with technical best practices.

Key technical details: Updates `Documentation/git-am.txt` and `Documentation/git-rebase.txt` to warn that the option should only be used when applying commits to older bases. Notes Git's revision walker expects increasing timestamps and mentions clock skew tolerance. No code changes proposed.
