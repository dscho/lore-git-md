This thread documents an effort by Jean-Noël Avila to update Git's manual pages to follow new formatting guidelines, specifically addressing synopsis formatting. The initial patch series encountered an issue reported by SZEDER Gábor where `{empty}` strings appeared in rendered output when building with Asciidoctor 2.0.16, particularly affecting `git-diff` and related pages. The problem was traced to how Asciidoctor processes certain syntax elements.

A follow-up patch has now been submitted to address the formatting issue with triple-dot syntax in command synopses. The fix modifies the Asciidoctor extension processing to properly handle dot sequences, adding specific handling for cases like `git-mv <source>... <dest>` where dots were being misinterpreted. The changes focus on the `asciidoctor-extensions.rb.in` file, adding context-aware regex patterns to prevent the unwanted `{empty}` strings while maintaining correct formatting in other cases. While this appears to resolve the immediate issue, it remains to be confirmed whether it fully addresses all instances of the problem across different documentation builds. The core content improvements to the manual pages' structure and synopses remain valid and are not affected by this formatting fix.
