This thread addresses a bug in gitk's handling of renamed files when using external diff tools. The issue occurs when users try to diff files that were renamed between commits - gitk would fail to locate the correct file versions regardless of whether the original or renamed file was selected in the interface.

The solution, now in its third iteration, introduces logic to properly detect renames by parsing "rename from"/"rename to" markers in the diff output. The implementation handles both forward and backward rename detection while maintaining the existing external diff interface. Earlier versions included an experimental GUI toggle that has since been removed based on feedback, resulting in a cleaner solution focused specifically on the core rename detection problem.

The patch appears ready for merging, having evolved through three versions with improvements to variable naming and handling of file selection cases. Johannes Schindelin, as gitk's maintainer, will likely be the one to pick this up for inclusion.
