This thread addresses a bug in gitk where the external diff feature fails to properly handle renamed files. The issue stems from gitk not correctly identifying file paths when files are renamed between commits. Tobias Boesch has submitted a patch series (now at v4) that introduces a new procedure to parse Git's rename markers from diff output, ensuring the correct paths are passed to the external diff tool.

The solution has evolved through several iterations based on feedback from gitk maintainer Johannes Sixt. Early versions included an experimental GUI toggle that was later dropped, while subsequent versions refined the implementation and addressed style concerns. The latest version responds to Sixt's review by replacing regex parsing with direct Git commands for path detection, adopting Tcl style conventions, and simplifying variable names. Boesch has declined to add support for file copies, explaining this would require different handling than renames in Git's current architecture.

The interaction between Boesch and Sixt demonstrates effective maintainer-contributor collaboration, with the contributor being responsive to both technical and stylistic feedback while providing reasoned pushback where appropriate. The patch remains focused on the core issue (43 lines changed) without broader architectural impact. With all major review concerns addressed, this appears ready for final approval pending any minor style refinements Sixt may request.
