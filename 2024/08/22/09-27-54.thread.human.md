This thread addresses a bug in gitk's external diff functionality when dealing with renamed files, now in its eighth iteration. The core issue was that gitk couldn't properly locate files for external diff viewing when they were renamed between commits. 

The solution has evolved through multiple versions under guidance from gitk maintainer Johannes Sixt. The current approach, refined in v8, parses rename information directly from gitk's diff display rather than using an external Git command. Tobias Boesch has implemented Johannes' suggestions from v7, fixing the remaining issues: rename detection now works regardless of whether the original or renamed file is selected, string matching is more precise, and the code uses more idiomatic Tcl comparisons. 

The patch remains focused on gitk's Tcl implementation, adding 40 lines while maintaining robust error handling. The only outstanding item is non-ASCII filename support, which has been deferred as non-blocking. After eight thorough iterations addressing all technical feedback, this appears ready for merging, demonstrating effective collaboration between contributor and maintainer.
