This thread addresses a bug in Git's shell completion where Zsh support broke due to Bash-specific variable expansion syntax introduced in commit 1e0ee4087e. Philippe Blain provided a fix (v1) that replaces the problematic Bash `${!var}` syntax with a portable `__git_indirect` helper function, confirmed working across both Bash 3.2.57 and Zsh 5.0.8. The technical solution appears solid, with no outstanding objections raised.

The discussion has now turned to preventing similar issues in the future. While Philippe suggested adding Zsh testing to CI, D. Ben Knoble pointed out that the existing completion test suite (t9902-completion.sh) is fundamentally Bash-specific as it explicitly executes tests in Bash. This raises broader questions about how to maintain compatibility between the two, given that Zsh relies on ksh emulation mode to use git-completion.bash. Options like splitting the completion scripts or documenting non-portable constructs were mentioned, though neither provides an immediate automated solution. The thread remains open for further discussion about long-term testing strategies, but the immediate technical fix for the Zsh completion breakage appears ready for merging.
