This thread addresses a regression in Zsh shell support for Git's tab completion, broken by a Bash-specific change in commit 1e0ee4087e. The issue caused incorrect completion suggestions (showing internal function names rather than actual config options) when working with Git configuration variables in Zsh's ksh emulation mode.

Philippe Blain has proposed a fix that replaces the problematic Bash indirect variable expansion (`${!var}`) with a new portable `__git_indirect` helper function. The solution uses `printf` and careful `eval` to safely expand variables across different shells while avoiding word splitting or globbing issues. The patch modifies several completion functions in git-completion.bash that handle config variable expansion, particularly for branch.*, remote.* and submodule.* sections.

Testing confirms the fix works correctly on both Bash 3.2.57 and Zsh 5.0.8. Philippe notes that while the current solution resolves the immediate issue, adding Zsh-specific testing to CI could help prevent similar shell compatibility problems in the future, though the existing completion test suite is currently Bash-only. The patch appears ready for merging with no outstanding objections.
