This thread addresses a bug where Zsh shell completion for Git config variables (branch.*, remote.*, etc.) broke due to Bash-specific syntax introduced in commit 1e0ee4087e. The original reporter Philippe Blain identified the issue, and D. Ben Knoble has led the technical solution through three patch versions.

The fix introduces a portable `__git_indirect` helper function that safely handles variable expansion across shells using `eval`, replacing the problematic Bash-specific `${!var}` syntax. The solution maintains proper completion behavior while preventing word splitting issues. Version 3 of the patch has now been formally approved by both Knoble and Blain, with Junio C Hamano indicating he will queue it for merging.

While the immediate technical solution is settled, broader questions remain about improving cross-shell testing infrastructure - the current test suite remains Bash-specific. However, this particular fix appears complete and ready for inclusion in the next release. The patch demonstrates working behavior across both Bash 3.2.57 and Zsh 5.0.8, including proper handling of variables containing spaces.
