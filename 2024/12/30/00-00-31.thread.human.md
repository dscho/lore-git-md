This thread addresses a bug in Git's shell completion where Zsh users saw incorrect completions for config variables (like branch.* or remote.*) due to Bash-specific syntax introduced in commit 1e0ee4087e. The issue stems from Zsh's ksh emulation mode not supporting Bash's `${!var}` indirect expansion, causing raw variable names to appear instead of proper completions.

D. Ben Knoble has taken the lead on the technical solution, now at version 3 of the patch. The fix introduces a portable `__git_indirect` helper function that uses `eval printf` to safely expand variables across shells while preventing word splitting and globbing. The implementation replaces six instances of the problematic Bash syntax and includes a demonstration program showing correct handling of variables containing spaces. Philippe Blain, who originally reported the issue, has reviewed and acked the latest version, confirming it works on both Bash 3.2.57 and Zsh 5.0.8.

While the immediate technical solution appears solid, the broader question of how to test shell completion portability remains open. The existing test suite is Bash-specific, making automated Zsh testing difficult. This infrastructure question may need separate attention, but doesn't block the current fix which cleanly solves the Zsh completion issue while maintaining existing Bash behavior.
