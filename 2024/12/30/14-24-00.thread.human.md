This thread addresses a segfault in `git fast-import` related to hash algorithm handling, particularly when using unsafe SHA-1 implementations. The issue stems from incorrect initialization of hash contexts in `stream_blob()`.

Taylor Blau and Patrick Steinhardt, two key maintainers working on Git's object storage layer, have been discussing solutions. They considered but rejected an approach that would make the `git_hash_ctx` structure self-aware of its algorithm type, as this wouldn't fully address the initialization problem. Instead, they've converged on using Taylor's existing `unsafe_hash_algo()` infrastructure from his recent 10-part series, which provides a cleaner way to handle hash algorithm selection.

The fix specifically targets cases where `hashfile_context` gets initialized with the wrong hash function, which can cause crashes. Patrick has reviewed and agreed with Taylor's proposed solution, indicating the technical approach is now settled. This work connects to broader efforts to improve hash algorithm safety throughout Git, particularly around SHA-1/SHA-256 interoperability that brian m. carlson originally spearheaded.
