This thread addresses a segfault in `git fast-import` caused by incorrect hash function initialization. The immediate fix, changing `stream_blob()` to use `unsafe_init_fn`, was implemented by Patrick Steinhardt and Taylor Blau as a stopgap measure. The discussion has evolved into a broader architectural proposal to make hash handling more robust by storing the hash function type within `struct git_hash_ctx` itself, with initialization functions like `git_hash_sha1_init()` setting this state automatically.

Junio Hamano has now weighed in, agreeing with this approach as a cleaner long-term solution that would eliminate the current brittle system where callers must track initialization variants. The proposed design would not only fix the immediate fast-import issue but could benefit other subsystems by preventing similar bugs. While the architectural direction is now agreed upon, implementation details remain to be worked out, particularly around maintaining synchronization between hash implementations and coordinating with ongoing Meson build system changes. The thread shows consensus forming around encapsulating hash state management as a general improvement to the codebase's handling of hash functions.
