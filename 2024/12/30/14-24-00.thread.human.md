This thread addresses a segfault in `git fast-import` related to hash function initialization, with Patrick Steinhardt and Taylor Blau leading the discussion. The immediate fix changes `init_fn` to `unsafe_init_fn` in `stream_blob()` to match the hashfile API, preventing the crash. While this works, both contributors recognize it as a temporary solution since it requires manual synchronization between components.

The conversation has evolved to propose a more robust architectural change: storing the hash function type directly in `struct git_hash_ctx` with new initialization APIs like `git_hash_sha1_init()`. This would eliminate the need for callers to track which variant to use. The discussion connects to broader hash function safety work in the codebase and may coordinate with ongoing Meson build system changes. The patch touches `builtin/fast-import.c` specifically, but the proposed solution would affect hash API usage across the project. While the immediate segfault is resolved, the thread remains open as participants work toward a more maintainable long-term approach.
