This is a discussion about protocol v2's `remote-object-info` format string design in the final stages of the `git cat-file --batch-command` security feature series. Christian Couder pushes back against Patrick Steinhardt's concern that changing the format string later would break backwards compatibility.

Christian argues that since the documentation explicitly marks the format as experimental and likely to change, users should not rely on it. He suggests that preventing all backwards-incompatible changes, even for clearly labeled experimental features, would make development more difficult by requiring perfection upfront. The alternative, he implies, is worse: either never improving interfaces or accumulating more deprecated cruft over time.

The exchange represents one of the last design-level discussions before this security feature can be merged. While the technical implementation is complete and approved, this touches on the project's broader philosophy about interface stability versus iterative development. Christian's position suggests a more pragmatic approach to experimental features, while Patrick's original concern reflects Git's typical conservatism about protocol changes.
