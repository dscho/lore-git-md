Thread identity: Bug report investigating GPG key selection behavior during tag signing (`git tag -s`), originating from a user experiencing unexpected smartcard key selection.

Core problem: When signing tags with a specified `user.signingkey`, Git correctly passes the key to GPG but GPG appears to override this selection in favor of a smartcard key, even when the smartcard isn't connected. The issue manifests in the interaction between Git's signing interface and GPG's key selection behavior.

Current status: Initial diagnostic information shared showing Git properly forwarding the signing key via `gpg --status-fd=2 -bsau <keyid>`, but GPG's `KEY_CONSIDERED` message indicates a different key is being selected. The thread is in early investigation phase with no proposed Git changes yet.

Key technical details: 
- Reproduction involves `git tag -s` with `user.signingkey` configured
- GPG trace shows correct key passed but different key considered
- GPG prompts for smartcard passphrase despite key specification
- Ends with "Operation cancelled" error when passphrase prompt aborted

Open questions: Whether this is purely a GPG configuration issue or if Git could implement workarounds. The reporter plans further GPG-side investigation.

Participant positions: Initial report suggests this is likely a GPG behavior quirk rather than Git bug, as Git's key forwarding appears correct. No other participants have weighed in yet.
