This thread continues the discussion around the `git-diff-pairs(1)` plumbing command, now in its third iteration. The series aims to modernize Git's diff queue internals while carefully preserving backward compatibility with existing callback contracts.

The latest exchange between Justin Tobler and Patrick Steinhardt confirms an important architectural constraint: the original `diff_addremove()` and `diff_change()` callback signatures must remain unchanged because they're used in `diff_options` with fixed function pointer types. Some callers (like pruning operations) don't actually queue filepairs, making any return value meaningless in those contexts. The solution is to introduce new functions (`diff_filepair_addremove()` and `diff_filepair_change()`) that return pointers while keeping the original callbacks intact.

Patrick agrees with this approach but suggests documenting the rationale in the commit message. This highlights the careful balance being struck between modernization and stability - the changes enable new batched processing functionality without breaking existing contracts. The discussion also surfaces the need to address Junio Hamano's outstanding questions about input format restrictions, documentation needs, and tree expansion handling before the v3 submission. The series is progressing methodically through architectural considerations while maintaining compatibility with Git's diff subsystem.
