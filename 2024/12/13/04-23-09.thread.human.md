This thread introduces `git-diff-pairs(1)`, a new plumbing command for batch blob diff generation, building on prior work by Jeff King. The 3-patch series addresses server-side needs for parallelized diff processing of large change sets.

The first patch refactors diff queue internals to expose `diff_filepair` access, splitting functions into wrapper+core variants. Justin Tobler suggested replacing the original functions entirely rather than maintaining both variants. The second patch implements the core command with comprehensive test coverage, while the third adds explicit queue control via NUL byte flush triggers for server-side operations.

Patrick Steinhardt has now weighed in on the API design questions from patch 1/3, building on Tobler's earlier feedback. He suggests two potential enhancements: either modifying the original functions rather than maintaining parallel versions, or taking the opportunity to make them accept an explicit `diff_queue` parameter instead of using the global queue - which would align with Git's ongoing libification efforts.

While the series remains functionally complete, this late review discussion presents an important design decision point. The core functionality isn't blocked, but the team must now decide between:
1) The current minimal approach (keeping both variants)
2) Removing the original functions (Tobler's suggestion)
3) A more significant API modernization (Steinhardt's suggestion)

The changes would primarily affect diff.c/diff.h internals, with limited impact on existing callers. The thread shows active engagement from key contributors (Tobler, Steinhardt) on refining the API design before finalization.
