Here's a human-readable summary of the thread:

The thread discusses a bug in `git tag -s` where Git silently falls back to using a different GPG key when the configured signing key (stored on a smartcard) is unavailable, rather than failing or warning as expected. Carlos Maiolino reported this discrepancy between documented and actual behavior, noting it undermines the reliability of signed tags when using hardware-backed keys.

Jeff King helped investigate by suggesting debugging steps, which revealed that while Git properly passes CLI-specified keys to GPG, it behaves differently when the config-specified key (`user.signingKey`) can't be accessed (like when a smartcard is disconnected). The core issue appears to be in Git's key availability handling, where it silently falls back instead of maintaining the documented behavior of strictly using the configured key or failing. This affects users relying on hardware security modules for signing operations.
