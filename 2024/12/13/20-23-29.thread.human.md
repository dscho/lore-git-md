Diagnostics show Git is doing its part correctly: the trace logs confirm the right key is being passed to GPG via the command line (`gpg --status-fd=2 -bsau` with the correct key ID). The discussion suggests this is likely a GPG configuration or behavior issue rather than a Git bug, since Git properly forwards the signing key specification. The reporter is continuing to investigate on the GPG side to understand why it's overriding the explicitly requested key. No changes to Git's code are being proposed at this stage - the thread serves to document this interaction quirk between Git's signing interface and GPG's key selection behavior.
