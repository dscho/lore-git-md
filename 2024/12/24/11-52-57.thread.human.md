This thread introduces a new `--expire-to` option for `git gc`, building on existing `git repack` functionality to specify where expired cruft packs should be stored. The first patch in this 2-part series adds the option by:

1. Updating documentation in git-gc.txt
2. Extending the `gc_config` struct with a `repack_expire_to` field
3. Passing the option through to `git repack` in `add_repack_all_option()`
4. Adding test coverage in t6500-gc.sh

The change provides a quality-of-life improvement by eliminating the need to manually chain `git repack --cruft --expire-to` with `git prune`. The implementation is clean and focused, with proper test coverage. The patch appears ready for review, though we'll need to see the second patch in the series to evaluate the complete picture.
