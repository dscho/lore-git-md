This thread discusses adding a new `prune-remote-refs` maintenance task that would run `git remote prune` on all remotes. The original proposal from Shubham Kanodia carefully documents this as an opt-in feature due to its potentially destructive nature, with use cases including selective fetching scenarios and third-party tool integration.

Junio Hamano and Patrick Steinhardt have provided feedback on the implementation, particularly around documentation style (whether to use linkgit:self-references) and error handling semantics in the remote iteration logic. The current version shares error handling behavior with the existing prefetch task, but there's discussion about making it more per-remote rather than all-or-nothing.
