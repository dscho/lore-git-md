This is the final patch in a feature series adding remote object metadata queries to `git cat-file --batch-command`. The patch implements the `remote-object-info` command which allows querying object sizes from remote servers without downloading full objects, building on Calvin Wan's earlier protocol v2 work.

The implementation handles multiple object IDs per command to minimize roundtrips, supports buffered mode, and works across git://, file:// and http:// transports. It requires servers to advertise the object-info capability (enabled via transfer.advertiseobjectinfo). The command currently only supports size queries, with type information deferred to future work.

Key technical details:
- New `remote-object-info` command takes a remote URL followed by object IDs
- Uses protocol v2's object-info capability (fails on v1)
- Default format is `%(objectname) %(objectsize)` (different from local `info`)
- Comprehensive test coverage across transports and edge cases
- Rejects unsupported format specifiers (objecttype, objectsize:disk, deltabase)
- Includes helper functions in new t/lib-cat-file.sh test library

The patch appears well-polished after 8 iterations, with thorough documentation and test coverage. It completes the security-conscious implementation that allows verifying object sizes before download while minimizing attack surface. The remaining discussion about format string stability for experimental features doesn't block merging.
