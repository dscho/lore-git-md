Security discussion thread about encrypting `.git` metadata files (logs, commits etc.), distinct from repository data encryption. Originated by Krishnamurthy Ganesh B advocating for optional symmetric encryption of `.git` contents using user-provided keys/salts, arguing disk encryption doesn't address local user access or code injection threats. References CVEs CVE-2024-32002 and CVE-2024-32004 as motivation. Current debate polarized between Git-native implementation (proposed by Krishnamurthy) versus system-level encryption (advocated by Randall S. Becker). Krishnamurthy reports pursuing bug bounties with GitHub/GitLab/Atlassian to drive adoption. Technical concerns about performance met with caching suggestions, but no concrete implementation or benchmarks provided yet. Core disagreement centers on whether encryption belongs in Git (addressing specific metadata threats) or at filesystem level (as general solution). Thread appears stalled without new technical arguments; future movement may require threat model refinement, performance data, or implementation prototypes.
