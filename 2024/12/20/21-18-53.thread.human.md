This thread addresses a bug in the credential-cache helper's handling of authentication type (authtype) capabilities. The patch series, now at v5, modifies when the helper includes authtype and credential information in responses - changing from unconditional inclusion to capability-gated behavior. The core change makes credential-cache properly respect capability negotiation by only sending this data when explicitly requested via CREDENTIAL_OP_RESPONSE capability.

The technical changes are focused in builtin/credential-cache--daemon.c, with two condition checks updated, and a new test case in t/lib-credential.sh to verify the capability-aware behavior. Junio Hamano reviewed an earlier version (v4) and suggested improvements to the commit message, which have now been incorporated in v5 to better explain the change's rationale, impact, and the distinction between OP_HELPER and OP_RESPONSE capabilities. The test demonstrates how without this fix, "credential fill" could print incomplete credentials due to unexpected authtype attributes being discarded. The change aligns the credential-cache helper with documented behavior in git-credential.txt.
