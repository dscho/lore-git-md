This thread addresses a bug in the credential-cache helper's handling of authentication type (authtype) capabilities, with the fix now in its fifth iteration. The core change modifies how the helper includes authtype and credential information in responses, switching from unconditional inclusion to capability-gated behavior as specified in the git-credential documentation. The technical changes are in builtin/credential-cache--daemon.c, with a new test case verifying the corrected behavior.

The v5 patch incorporated feedback from both Junio Hamano and brian m. carlson, expanding the commit message to better explain how the change aligns with documented behavior and includes regression protection. The fix ensures authtype attributes are only sent when explicitly requested via CREDENTIAL_OP_RESPONSE capability, addressing cases where they were previously being discarded. Brian has now given his approval, confirming the patch looks good after these refinements. With this final ack from a key maintainer and no outstanding concerns, the series appears ready for merging, closing PR #1842. The test case in t/lib-credential.sh will help prevent future regressions in credential attribute transmission behavior.
