This thread has been working through the systematic deprecation and removal of legacy features for Git 3.0, covering reference naming conventions, command removal, and remote configuration changes. The core technical work is complete, with build system preparation, warning infrastructure, and CI validation all in place across multiple iterations (v4 for references, final patch for remote configuration).

The latest discussion focuses on refining the messaging around the "branches/" and "remotes/" directory deprecation. Jakub Wilk pointed out that while these directories were included in the default template until recently (meaning they may exist in many repositories), they are likely unused in modern workflows. Junio Hamano agreed this was an important distinction to clarify in the documentation. The wording has been adjusted from claiming these directories "are not to be found" to more accurately reflect that they may exist but are probably inactive.

Key participants have been Patrick Steinhardt (leading implementation), Junio Hamano (providing historical context and UX suggestions), Jakub Wilk (documentation accuracy), and others contributing to build system integration and testing. The thread demonstrates Git's careful approach to breaking changes - maintaining backward compatibility while clearly communicating modernization paths, now with even more precise documentation about the transition.
