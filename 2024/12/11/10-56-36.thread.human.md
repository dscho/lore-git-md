This thread has systematically worked through the deprecation and removal of legacy Git features in preparation for Git 3.0, with a focus on maintaining backward compatibility through a `WITH_BREAKING_CHANGES` build flag. The discussion has covered both reference naming conventions (branches/ and remotes/ directories) and command removal (git-pack-redundant), establishing a consistent pattern for handling breaking changes.

Patrick Steinhardt has been the primary driver of this effort, with Junio Hamano providing historical context and others like Randall Becker and D. Ben Knoble contributing reviews focused on user experience and build system impacts. The latest patch finalizes the removal of directory-based remote configuration methods that were superseded by config-based remotes two decades ago. It adds warning messages, conditional compilation, and updates documentation and tests to handle both legacy and new behavior.

The series demonstrates Git's careful approach to breaking changes - the infrastructure is now complete with comprehensive test coverage across CI jobs, and documentation that explains both the technical changes and migration paths. While the core work appears finished, some open questions remain about final wiring of deprecations, cross-platform verification, and potential additional commands that might follow this deprecation pattern. The thread shows how Git balances modernization with stability, providing a clear transition path for users while cleaning up long-obsolete code paths.
