This thread documents the deprecation and removal of legacy "branches/" and "remotes/" reference naming conventions in preparation for Git 3.0. What began as a discussion about warning messages has evolved into a comprehensive 5-patch series demonstrating Git's approach to breaking changes.

The series shows a clear progression: first establishing infrastructure (including repurposing a CI job to test breaking changes), then implementing concrete removals (like the `git-pack-redundant` subcommand), and finally addressing the core reference naming changes. The latest patch completes this work by updating documentation in BreakingChanges.txt, adding warning messages in remote.c, and adjusting tests to handle the conditional compilation via the WITH_BREAKING_CHANGES flag.

Key participants have shaped the discussion - Patrick Steinhardt driving implementation while incorporating feedback, Junio Hamano providing historical context, and Randall Becker ensuring user experience considerations aren't overlooked. The technical work spans build system changes, CI configuration updates, and careful documentation of the 20-year deprecation timeline for these features.

The series exemplifies Git's collaborative approach to backward-incompatible changes, balancing clear communication (through warnings and documentation) with practical implementation (via build flags and CI testing). With this final patch, the transition from deprecated feature to removal is now fully documented and implemented, ready for Git 3.0.
