This thread has documented the systematic removal of legacy features in preparation for Git 3.0, focusing on deprecating the old "branches/" and "remotes/" directory structures. What began as a technical implementation has evolved through multiple iterations, with the latest being a precise documentation refinement from Junio Hamano that incorporates Jakub Wilk's observation about the distinction between these directories merely existing (from old templates) versus being actively used.

The implementation, led by Patrick Steinhardt with reviews from D. Ben Knoble and others, established a comprehensive framework for handling breaking changes - including build system flags, warning infrastructure, and CI validation. The documentation has gone through several rounds of refinement, with the final version now accurately describing that while these directories might exist in some repositories, they are typically unused in modern workflows. This represents the last outstanding issue being resolved, with the change carrying both Jakub's Reported-by and Patrick's Acked-by tags, signaling consensus. The thread demonstrates Git's careful approach to backward-incompatible changes, ensuring clear communication paths for users while modernizing the codebase.
