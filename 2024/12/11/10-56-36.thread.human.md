This thread has finalized the removal of Git's legacy "branches/" and "remotes/" reference naming conventions as part of the Git 3.0 release. The 5-patch series, now at version 3, has progressed from initial implementation debates through careful deprecation warnings to final removal, demonstrating Git's methodical approach to breaking changes.

Patrick Steinhardt has driven the implementation, which includes CI infrastructure changes (renaming the "linux-gcc" job to "linux-breaking-changes"), removal of git-pack-redundant as an example of the deprecation process, and now the core reference path changes. The final patch adds warning messages when accessing legacy paths and updates documentation to mark them as deprecated. Junio Hamano, while approving the removal overall, suggested improving the warning messages to include specific migration instructions (either `git remote mv` or `git remote rm`) and emphasized that feedback should focus on why users can't migrate rather than just notification of usage.

The implementation spans remote handling code, Makefile modifications for conditional compilation, CI configurations, and comprehensive documentation updates. The changes maintain backward compatibility through WITH_BREAKING_CHANGES compilation while preparing for final removal in Git 3.0. This concludes a systematic deprecation process that began with infrastructure preparation and example removal, showing how Git approaches breaking changes with careful user notification and modernization.
