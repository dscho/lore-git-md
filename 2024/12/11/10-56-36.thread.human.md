This thread continues the coordinated effort to prepare Git 3.0 for breaking changes, now focusing on the removal of the deprecated `git-pack-redundant` subcommand. Patrick Steinhardt remains the primary implementer, building on the infrastructure established in earlier patches (now at v4) that introduced the `WITH_BREAKING_CHANGES` build option.

The latest patch cleanly removes `git-pack-redundant` when the breaking changes flag is set, following the pattern established for other deprecations. The changes are minimal but thorough - the command is excluded from the build system, unregistered from git.c, and the test suite is adapted to skip related tests when the command isn't available. This maintains backward compatibility by default while allowing early adopters to test the breaking changes path.
