This thread discusses Git's planned deprecation of legacy "branches/" and "remotes/" reference naming conventions, currently in its second patch series iteration (v2). The core debate centers on how to implement these deprecation warnings without disrupting user workflows. Patrick Steinhardt has been driving the technical implementation, proposing an environment variable (GIT_ALLOW_DEPRECATED_REMOTES) to let users temporarily suppress warnings after acknowledging them. This follows earlier feedback from Junio Hamano, who suggested making warnings appear only when deprecated references are actually used.

Junio has now pushed back against the suppression mechanism, arguing that warnings should remain persistently visible until users migrate away from the deprecated features, seeing them as an important nudge toward modernization. Randall Becker had previously raised user experience concerns that led to Patrick's environment variable proposal, creating a three-way tension between technical implementation (Patrick), user control (Randall), and maintainer philosophy (Junio).

The discussion has evolved from purely technical changes in remote.c and reference handling to broader questions about how Git should communicate breaking changes. While the implementation details appear settled - warnings will trigger only on actual use of deprecated references - the thread remains open on whether users should have any control over warning visibility. This represents a key decision point in Git's ongoing reference namespace cleanup effort, with Junio's latest comments suggesting he may prefer keeping the warnings mandatory until the features are fully removed.
