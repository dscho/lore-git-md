This thread has been working through Git 3.0's systematic removal of legacy features, including the deprecation of "branches/" and "remotes/" directory structures. The implementation is now quite mature, with build system support, warning infrastructure, and CI validation all in place. Junio Hamano recently helped refine the user-facing warning messages to be more actionable, changing them from passive notifications to actively soliciting useful feedback about why users might still need these legacy features.

A new contribution from Jakub Wilk provides an important clarification about the documentation's claims. While the deprecation effort is sound, the original assertion that these directories don't exist in modern repositories was overstated - the "branches/" directory was actually part of Git's default template until recently. This doesn't change the technical implementation, but does mean the documentation should more accurately reflect that while these directories are common in existing repositories, they're no longer recommended for modern workflows.

The thread shows a well-coordinated effort between Patrick Steinhardt (leading the implementation), Junio (providing historical context and UX guidance), and various contributors catching important details like Jakub's documentation correction. All core technical components - the warning system, build flags, and test coverage - remain solid as the team now focuses on final documentation accuracy before this change ships in Git 3.0.
