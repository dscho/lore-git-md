This thread has documented the systematic removal of Git's legacy "branches/" and "remotes/" reference paths in preparation for Git 3.0. What began as an implementation discussion has now reached its final stages, with the technical work completed and the focus shifting to polishing user-facing messaging.

Patrick Steinhardt has led the implementation, which included infrastructure changes like CI job reorganization, the removal of git-pack-redundant as a test case, and finally the core reference path removal. The changes maintain backward compatibility through conditional compilation while clearly marking these paths as deprecated. Junio Hamano has provided key review input, particularly around ensuring the warnings give users actionable migration instructions - specifically suggesting the `git remote mv` and `git remote rm` commands be highlighted.

The most recent exchange confirms the warnings already distinguish between "branches/" and "remotes/" access paths, and Patrick has agreed to incorporate Junio's suggested command examples into the messaging. With test coverage in place (particularly t5505 verifying the migration behavior) and all technical concerns addressed, this change appears ready for merging. The thread demonstrates Git's careful approach to breaking changes - methodical infrastructure preparation, clear deprecation warnings, and attention to user experience even when removing 20-year-old legacy features.
