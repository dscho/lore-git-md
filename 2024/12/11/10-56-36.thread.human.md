This thread has been systematically preparing Git 3.0's breaking changes infrastructure, covering reference handling, command removal, and remote configuration deprecation. The core implementation is now complete, with the latest discussion focusing on refining user-facing warnings about legacy "branches/" and "remotes/" directory structures.

Patrick Steinhardt has been the primary driver of this effort, with Junio Hamano providing key input on user experience. The infrastructure includes build system changes (controlled by WITH_BREAKING_CHANGES), CI validation, and comprehensive documentation. The most recent patch tweaks warning messages in builtin/remote.c to be more actionable - changing from simply notifying users about legacy usage to asking why they still need the old format. This small but meaningful change was suggested by Junio to gather better feedback during the deprecation period.

The thread shows a mature framework for managing breaking changes, with all major technical components settled. What remains are final cross-platform verifications and monitoring user experience during the transition. The approach maintains backward compatibility while providing clear modernization paths, demonstrating Git's careful handling of major version changes.
