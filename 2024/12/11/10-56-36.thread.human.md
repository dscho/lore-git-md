This thread documents the careful removal of long-deprecated Git features in preparation for Git 3.0 release, establishing infrastructure for handling breaking changes through a new compile-time flag. The series removes three major legacy components: the `.git/branches/` directory (deprecated since 2005), `.git/remotes/` directory (deprecated since 2011), and the `pack-redundant` command (deprecated since 2011).

Junio Hamano and Christian Couder have been the key participants, with Junio providing important historical context about why these features were originally useful (particularly the directory-based approaches for users managing frequently-changing remotes). Christian has focused on practical implementation details, including CI system integration and suggesting improvements to the deprecation warning strategy.

The latest discussion centers on making the transition smoother for users. Christian noted that the `pack-redundant` removal used an aggressive warning strategy requiring explicit opt-in, and proposed applying similar visibility to the directory-based configuration methods. Junio strongly endorsed this approach, calling it prudent despite the features' long deprecation period. The implementation will need to modify remote.c to add these warnings, though the exact mechanism remains to be specified.

The thread shows consensus on both the technical approach and the importance of clear user communication during this transition. All patches demonstrate consistent patterns for feature removal while maintaining robust testing coverage through conditional compilation. With the CI configuration now finalized and the warning strategy agreed upon, the series appears ready for merging once these final user-facing improvements are implemented.
