This is the final review feedback from Junio Hamano on the `git cat-file --batch-command` remote object info feature, now in its 6th iteration. The series is functionally complete with all technical issues resolved, but Junio raises two important design questions before merging.

First, regarding protocol v1 behavior, Junio suggests that dying (rather than warning and continuing) is likely the right approach when `remote-object-info` is used with protocol v1, since programs driving batch commands probably can't meaningfully recover from this case anyway.

Second, Junio questions the current limitation of not supporting object type queries, suggesting that either the implementation should be extended to support this (if possible) or fall back to a full fetch when object type is requested, similar to how it already falls back when the server lacks object-info capability. He also raises a related point about whether fetched objects should use quarantine to avoid polluting the local object store.

These are the last open questions before this series can be merged. The implementation itself is sound and well-tested, with all prior review feedback addressed across six iterations. Junio's comments focus on edge case behaviors that don't block merging but would improve the feature's robustness. The series represents a significant addition to Git's remote query capabilities, building on Calvin Wan's earlier protocol v2 object info work.
