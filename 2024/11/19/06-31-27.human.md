This is a design discussion about the `git cat-file --batch-command` remote object info feature, now in its 6 iteration. Patrick Steinhardt weighs in on Junio C Hamano's concerns about protocol version handling and quarantine behavior.

Patrick agrees with Junio that not implementing quarantine leads to inconsistent behavior between protocol v1 (leaves cruft objects) and v2 (doesn't). He argues this subtle difference could confuse developers who might not test against both protocol versions. While acknowledging quarantine would help, Patrick suggests the performance impact of fallback fetches might make it better to drop the fallback entirely and revisit it later if users demonstrate a need.

The exchange shows the maintainers converging on a position: either fully commit to the no-fallback design (which avoids both quarantine complexity and inconsistent behavior) or properly implement quarantine. The series remains technically sound, but this final design clarification appears necessary before merging. Patrick's input carries weight as the original reviewer of the protocol v2 integration this feature builds upon.
