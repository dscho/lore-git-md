This is a feature patch series adding remote object information querying to `git cat-file --batch-command`, building on prior protocol v2 security work. The series is now in its 6th iteration with all technical issues resolved and only minor style refinements remaining before merging.

The key addition is a new `remote-object-info` command that lets clients query object metadata from protocol v2 servers without full downloads, falling back to full fetches if needed. The implementation:
- Refactors fetch-pack packet writing into a more general `write_command_and_capabilities()` in connect.c
- Moves fetch initialization code for better organization
- Advertises the object-info capability from servers
- Implements transport layer support in new fetch-object-info.[ch] files
- Adds the user-facing `remote-object-info` command with comprehensive tests

The series has been thoroughly reviewed by multiple contributors (Christian Couder, Jonathan Tan, Taylor Blau) with Junio Hamano indicating readiness for merging pending final style polish. The v6 changes focus on:
- Moving small changes to the first commit for better organization
- Adding detailed descriptions of the connect.c refactoring
- Fixing indentation issues flagged in review

Two open design questions remain about protocol v1 behavior and objecttype handling, but these don't block merging as they concern edge case behaviors rather than core functionality. The implementation includes extensive test coverage in t1017 for security and edge cases.

This represents the culmination of work originally started by Calvin Wan, now shepherded by Eric Ju through multiple iterations to reach production-ready quality. The architectural restructuring in v5 and final polish in v6 position this as a robust addition to Git's remote query capabilities.
