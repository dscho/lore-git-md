Atomic push exit code propagation fix series by Jiang Xin and Patrick Steinhardt, now maintained by Patrick. Addresses silent failure case where git-receive-pack errors during atomic pushes weren't properly reported back to pusher. Core issue: when ref updates succeed but receive-pack fails with non-zero exit, client incorrectly treats as success. Technical solution introduces ERROR_SEND_PACK_BAD_REF_STATUS (value 1) to distinguish ref status errors, modifies transport.c for consistent protocol behavior while detecting ref push failures, ensures graceful connection closure on atomic push failures.

Series progressed through v4 with comprehensive test modernization and infrastructure improvements before implementing core fix. Current state includes:
1. Test modernization in t5504-fetch-receive-strict.sh (relocated heredocs), t5548-push-porcelain.sh (refactored setup, added dry-run tests), and t5543-atomic-push.sh (new failure cases).
2. Protocol changes introducing ERROR_SEND_PACK_BAD_REF_STATUS in send-pack.c, with transport.c modifications to maintain consistency across protocols.
3. Final patch implements core fix by adding packet_flush(out) in send-pack.c during atomic push failures and simplifying transport.c cleanup logic. Test cases upgraded from test_expect_failure to test_expect_success, verifying proper error reporting in both regular and porcelain output formats.
