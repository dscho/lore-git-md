Atomic push exit code propagation fix series by Jiang Xin and Patrick Steinhardt, now maintained by Patrick. Addresses silent failure case where git-receive-pack errors during atomic pushes weren't properly reported back to pusher. Core issue: when ref updates succeed but receive-pack fails with non-zero exit, client incorrectly treats as success. Series implements comprehensive solution through protocol changes, transport layer fixes, and test modernization.

Current state (final version) includes:
1. Protocol-level fix introducing ERROR_SEND_PACK_BAD_REF_STATUS (value 1) in send-pack.h to distinguish ref status errors
2. send-pack.c modifications to:
   - Return new error code instead of -1 for bad ref statuses
   - Add flush packet on atomic push failures (new in final patch)
3. transport.c changes to:
   - Remove workaround ignoring finish_connect() errors (reverted in final patch)
   - Simplify connection cleanup logic
4. Extensive test infrastructure improvements across:
   - t5504-fetch-receive-strict.sh (modernized heredoc placement with `\EOF` syntax)
   - t5543-atomic-push.sh (now with all test_expect_failure cases converted to test_expect_success, including new receive-pack failure scenarios)
   - t5548-push-porcelain.sh (protocol-agnostic setup via create_upstream_template()/setup_upstream(), test isolation improvements, dry-run porcelain verification)

Key technical details:
- Final patch ensures graceful connection closure via flush packet when atomic push fails
- Preserved backward compatibility from commit 7dcbeaa0df
- Complete test coverage of atomic push error propagation including receive-pack failure edge cases
- Protocol-agnostic test infrastructure handles both local and HTTP configurations
- Modern test patterns with test_when_finished cleanup
- Verified porcelain output behavior for both regular and dry-run operations
