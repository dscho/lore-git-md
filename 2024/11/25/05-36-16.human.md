This is the final patch in a feature series adding remote object info support to `git cat-file --batch-command`. The patch implements the `remote-object-info` command, which allows querying object metadata from remote repositories without downloading the objects themselves.

The implementation supports multiple object IDs per command to reduce round-trips, works with git://, file:// and http:// transports, and includes thorough test coverage. The command requires protocol v2 and server support for the object-info capability (enabled via transfer.advertiseobjectinfo). 

Key technical details:
- Default output format is `%(objectname) %(objectsize)` (object type support is planned for future work)
- Fails cleanly when unsupported format specifiers like `%(objecttype)` are requested
- Includes buffer mode support for batching commands
- Verifies objects remain missing locally after remote queries
- Comprehensive tests cover error cases (malformed OIDs, missing objects, unsupported protocols)

The patch appears well-polished after 7 iterations, with sign-offs from Jonathan Tan and Christian Couder. It completes the remote object info functionality started in earlier patches, with all design questions now resolved per maintainer consensus. The implementation is security-conscious, requiring explicit server capability advertisement rather than falling back to object downloads.
