This thread documents the development of a new `--revision` option for `git clone`, allowing users to clone a repository at a specific ref or commit hash while avoiding the creation of remote-tracking branches and detaching HEAD at the requested revision. The series has progressed through five versions, with significant preparatory refactoring to modernize the clone internals before implementing the feature.

Key contributors include the original author (whose preparatory work eliminated global variables from clone.c and restructured tag handling), Patrick Steinhardt (who provided structural feedback), and Jean-Noël Avila (who improved documentation). Junio C. Hamano specifically requested separating a new option validation helper into its own preparatory patch, which was done in v5.

The final implementation adds comprehensive support for cloning at arbitrary revisions while maintaining compatibility with existing options like `--depth`. The test suite verifies behavior with various reference types and edge cases. All feedback has been addressed, and the series appears ready for integration, representing a useful addition for workflows like CI systems that need to check out specific commits without the overhead of remote-tracking branches.
