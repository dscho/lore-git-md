This thread has finalized the implementation of a new `--revision` option for `git clone`, which allows cloning a specific commit or ref without creating remote-tracking branches, instead detaching HEAD at the requested revision. The feature is particularly useful for CI systems and other workflows that need precise repository states without the overhead of full branch tracking.

The series went through six versions with extensive review from Patrick Steinhardt, Toon Claes, and others, addressing all technical concerns. Key improvements included refactoring the clone internals to use a new `struct clone_opts`, standardizing option parsing with a new `die_for_incompatible_opt2()` helper, and hardening the revision lookup with `lookup_commit_or_die()`. Documentation was carefully polished with input from Jean-Noël Avila to ensure clarity about the feature's behavior and its interactions with other clone options like `--tags`.

The implementation is complete with comprehensive test coverage and has been verified to work correctly with related features like shallow clones (`--depth`). Junio Hamano has queued the series for integration, marking the successful conclusion of this effort to provide more flexible repository cloning options.
