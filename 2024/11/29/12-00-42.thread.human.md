This thread has been discussing a 7-patch series that adds a `--revision` option to `git clone`, allowing users to clone a specific commit or ref without creating remote-tracking branches. The series has gone through five iterations with extensive refactoring and review feedback incorporated, including significant input from Patrick Steinhardt and Jean-Noël Avila.

The latest development is a minor code style observation from Patrick Steinhardt about a helper function (`die_for_incompatible_opt2()`) that was introduced in the series. He notes that a condition check before calling this function in `builtin/replay.c` is redundant since the helper already handles that internally. However, this appears to be a tangential comment about another part of the codebase rather than the clone series itself, as the helper function is being used elsewhere.

The core functionality of the same - cloning specific revisions with detached HEAD - remains complete and well-tested. The only substantive open question is about ensuring robust error handling in the `update_head()` function, where Patrick had previously raised a question about whether a change from `lookup_commit_reference()` to `lookup_commit_or_die()` addresses a real crash risk. That verification remains the final item before this series can be considered ready for integration.
