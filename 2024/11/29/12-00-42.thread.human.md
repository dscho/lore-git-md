This thread introduces a new `--revision` option for `git clone` that allows cloning a specific ref or commit hash directly, without creating remote-tracking branches. The 6-patch series, currently at v4, has undergone significant preparatory refactoring to clean up clone internals before implementing the feature. The preparatory work restructured global variables, simplified tag handling, and introduced a `struct clone_opts` to manage configuration.

The core feature lets users clone a single revision (either a ref name like `refs/pull/123` or a raw commit hash), detaching HEAD at that point without creating any tracking branches. It's designed to work with `--depth` for minimal clones, particularly useful in CI environments. The implementation includes comprehensive test coverage in a new test file.

Junio Hamano, the Git maintainer, has now reviewed the final patch. He raises several technical points about implementation details: questioning the string parsing of the revision, noting a style issue with a TODO comment, and examining the handling of incompatible options (particularly why `option_branch` gets special clearing treatment compared to other incompatible flags like `--mirror`). His feedback focuses on code cleanliness and consistency rather than challenging the overall approach, leaving the door open for the author, Toon Claes, to either adjust the implementation or justify the current design. The series appears technically sound but needs to address these final review comments before being ready for merging.
