This thread introduces a new `--revision` option for `git clone` that allows cloning a repository at a specific commit or ref without creating any remote-tracking branches. The feature is particularly aimed at CI systems that need minimal clones of specific versions. The series started with the core functionality but has evolved through four versions to include significant preparatory refactoring of `builtin/clone.c` to improve code structure before adding the new option.

The implementation handles both refs (branches/tags) and raw commit hashes, detaches HEAD when cloning non-branch refs, and maintains compatibility with shallow clones via `--depth`. The option conflicts with `--branch` and `--mirror` since they serve different purposes. The series includes comprehensive tests in a new test file and updates to documentation.

The preparatory work in v4 includes reducing global variables, refactoring the `wanted_peer_refs()` function, and introducing a `struct clone_opts` to better organize the growing set of clone options. The implementation appears thorough with good test coverage, though no reviews have been posted yet to the v4 version of the series.
