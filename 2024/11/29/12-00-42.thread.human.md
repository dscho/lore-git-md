This thread introduces a new `--revision` option for `git clone` that allows cloning a specific commit or ref without creating remote-tracking branches, instead detaching HEAD at the requested revision. The feature is particularly useful for CI workflows and other cases where only a specific point in history is needed.

The implementation has gone through six iterations of review and refinement, with the final patch now queued for integration by Junio Hamano. Key contributors include Patrick Steinhardt, who verified the technical implementation, and Jean-Noël Avila, who polished the documentation. The feature works with `--depth` for shallow clones but is incompatible with `--branch` and `--mirror` options.

The series also included broader improvements to the clone infrastructure, such as refactoring option parsing and tag handling, with a new test file (`t5621-clone-revision.sh`) providing comprehensive coverage. The changes maintain backward compatibility while adding this new capability, which should prove valuable for automated workflows that don't need full repository history or branch tracking.
