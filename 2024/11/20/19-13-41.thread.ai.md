This 8-part series by Taylor Blau (building on brian m. carlson's earlier work) refactors Git's hash algorithm handling to eliminate separate "unsafe" variants of hash operations through a unified `unsafe_hash_algo()` mechanism. The series has undergone extensive review from Jeff King, Patrick Steinhardt, and Junio C Hamano, with all identified edge cases addressed in this final version.

Core architectural changes:
- New `unsafe_hash_algo()` function providing wrapped algorithm access
- `struct git_hash_algo` contains single `unsafe` pointer to alternate implementation
- Complete removal of all `unsafe_` prefixed function variants (init, update, final) and declarations
- `struct hashfile` stores its own `algop` rather than using `the_hash_algo`
- Checkpoint API with `hashfile_checkpoint_init()` ensures algorithm consistency
- `hash_algo_by_ptr()` now returns `GIT_HASH_UNKNOWN` for both NULL and unsafe algorithm pointers
- Test infrastructure includes `sha1-unsafe` helper verifying identical output between variants
- csum-file.c fully converted to use unsafe variants through unified `algop` pointer
- Test helper `cmd_hash_impl()` simplified to single code path with algorithm conversion
- All `unsafe_*_fn` function pointer declarations removed from `hash.h`
- Unsafe variant initializations deleted from `hash_algos[]` array

Safety improvements in final version:
- `hash_algo_by_ptr()` behavior hardened to return UNKNOWN for NULL inputs
- Prevents silent mixing of safe/unsafe variants while maintaining safety
- Jeff King's analysis confirmed this approach addresses pre-existing NULL handling issues
- Forces incorrect usage to fail visibly rather than continuing with corrupt state
- Checkpoint API prevents crashes from algorithm mismatches (fixes 106140a99f, 9218c0bfe1)
