This thread documents brian m. carlson's series refactoring Git's hash algorithm handling to eliminate separate "unsafe" variants, introducing a unified `unsafe_hash_algo()` mechanism. The work builds on brian m. carlson's long-term hash abstraction efforts, with substantial review from Jeff King, Taylor Blau, and Patrick Steinhardt.

The series introduces core infrastructure changes including a new `unsafe_hash_algo()` function, removes all `unsafe_` prefixed variants, and modifies several subsystems to use the new approach. Key technical details involve `struct git_hash_algo` modifications, hashfile algorithm handling, and a new checkpoint API. The changes affect low-level oid manipulation while maintaining backward compatibility.

Recent discussion focused on edge cases in `hash_algo_by_ptr()`, where Jeff King identified that unsafe variants could silently convert back to safe ones. The consensus, now confirmed by Junio, is to have the function return `GIT_HASH_UNKNOWN` for unsafe pointers - making such cases fail visibly rather than silently. While this discussion revealed a pre-existing NULL pointer handling issue (where NULL inputs produce garbage data), the group agreed to address that separately from the current series.

With Junio's approval of the pointer-to-ID conversion approach, the series appears ready for integration. It represents the final step in eliminating unsafe variant scaffolding while preventing operation mixing. Outstanding items like NULL pointer handling and future `bulk-checkin.c` cleanups have been noted for follow-up work.
