Thread summary:

Technical discussion about progress reporting during bundle-URI HTTPS downloads while maintaining clean error handling. Originated from Toon Claes' patch series attempting to show download progress by letting git-remote-https write to stderr, which caused test failures when fatal errors appeared in output (identified by Jeff King). Current focus is on protocol changes between parent/child processes to enable progress reporting without breaking error handling.

Key technical points:
- Problem: Child process (git-remote-https) needs to communicate progress while parent must still suppress/handle fatal errors cleanly
- Rejected approaches: Filtering stderr (hacky), overriding die() in child (impractical)
- Proposed solution direction: Machine-readable progress over stdout with parent handling formatting
- Two format options from Toon:
  1. Structured "progress <size> <total> <throughput>"
  2. "log"-prefixed text for parent to format

Open questions:
- Implementation details of stdout-based progress protocol
- Examples of similar solutions in other parts of Git
- Preferred format for machine-readable progress data

Participants:
- Toon Claes (primary author) - proposing solutions
- Jeff King (Peff) - identified original issue, suggested stdout approach

Related work:
- Original bundle-URI HTTPS implementation
- Git's existing progress reporting mechanisms
- Inter-process communication patterns in Git plumbing
