This is the first patch in Pablo Sabater's GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. It adds the server-side capability to advertise and transmit object type metadata when requested by the client.

The patch teaches the server's object-info handler (in `protocol-caps.c`) to accept "type" as a requested field, extending the existing `requested_info` struct with a new `type` bit field. When the client includes "type" in its request, the server now returns the object type alongside any other requested metadata. The implementation follows the established pattern from the recently merged remote-object-info series (Eric's v21), with the server parsing the "type" capability, calling `get_object_info()` to retrieve the type, and formatting the response using `type_name()`.

The test coverage in `t/t5701-git-serve.sh` is expanded to verify the new capability, sending a request for both size and type metadata and confirming the server responds with the expected format (OID, size, and type name). The patch also includes a minor style fix to the `requested_info->size` bit field for consistency.

This is a clean, mechanical extension of the existing remote-object-info infrastructure. The commit message is clear, the code follows Git's conventions, and the test coverage is thorough. No substantive issues are apparent, though the series has not yet received review. The patch touches only the server-side protocol layer and test suite, leaving client-side integration for later patches in the series.
