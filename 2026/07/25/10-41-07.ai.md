This is a targeted bugfix and usability improvement for the branch subsystem, specifically addressing error message clarity when `git branch -d` refuses to delete a branch that is actively being used for `git bisect`. The v2 patch narrows scope to bisect-only scenarios, leaving rebase and other internal operations for future work, and introduces a new internal data structure (`checked_out_branch` array) to track checkout reasons. It touches `branch.c`, `branch.h`, `builtin/branch.c`, and the test suite (`t/t3200-branch.sh`), adding a helper function `branch_bisecting()` and updating error messages to specify "for bisect" when applicable.

The patch directly responds to Junio’s feedback from v1 by adopting `enum branch_checkout_kind` for debuggability and simplifying the initial implementation to focus on bisect. It leaves the `BRANCH_CHECKOUT_KIND_UPDATE_REF` case (used during rebase with merges) unaddressed, citing difficulty in crafting clear messages for those scenarios. Test coverage is extended to verify the new bisect-specific error message, but coverage for other checkout kinds (`WORKTREE` and `UPDATE_REF`) remains missing, as noted in the thread context.

Phillip Wood’s usability concern about potential confusion when `git status` shows a different branch than the error message is not addressed in this version, nor is Junio’s preference for changing the `BRANCH_CHECKOUT_KIND_CHECKOUT` message to "checked out at '%s'". The patch is well-motivated by stsp’s original report and appears technically sound, but the unresolved design questions around error message wording and test coverage suggest follow-up work is likely before this lands. The new `checked_out_branches` array could serve as a foundation for broader branch-safety checks across other commands (e.g., `git history`), aligning with Junio’s vision for a unified API.
