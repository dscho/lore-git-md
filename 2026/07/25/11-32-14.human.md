This is the core patch in Harald Nordgren’s **`git branch --delete-merged`** series, now in its **23rd iteration** and ready for merging. The patch adds the new `--delete-merged` subcommand, which safely deletes local branches whose work has already landed on their upstream, while preserving branches that are checked out, missing their upstream, or used as upstreams for unmerged work.

The command supports **repeatable `--delete-merged` arguments** (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the upstream match, and **optional positional patterns** (e.g., `topic-*`) to limit deletion scope. A branch is skipped if it is checked out in any worktree, its upstream no longer exists, or pushing it by name would update its upstream (e.g., `main` tracking `origin/main`). Unmerged branches are silently skipped, and **order-independent stacked-branch protection** ensures no branch is deleted out from under dependent work—even in chains like `b1→b2→b3` or self-referential upstreams like `b3→b3`.

The implementation is **well-motivated** (addressing a real workflow pain point) and **thoroughly tested**, with 200+ lines of new tests covering edge cases like missing upstreams, push divergence, stacked dependencies, and ref iteration order independence. The patch touches `builtin/branch.c` (adding the core logic and flags integration), `Documentation/git-branch.adoc` (documenting the new option), and `t/t3200-branch.sh` (expanding the test suite). Earlier versions addressed all substantive review feedback, including Junio C Hamano’s concerns about order dependency and Phillip Wood’s API consistency suggestions.

This is **not a refactoring or cleanup**—it’s a **new feature** that fills a gap in Git’s branch management tooling. The series is **unblocked**, with only mechanical fixes in patch 1/7 remaining before merging. If you care about safe, automated branch cleanup, this is worth watching.
