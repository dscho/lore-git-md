This is a bugfix patch targeting the worktree subsystem. It is the first of two patches in a series that addresses an out-of-bounds memory read in `worktree_basename()` in `builtin/worktree.c`. The bug can cause `git worktree add ""` to recursively delete the current working directory, including `.git`, when an empty string is passed as the worktree path.

The patch prevents the out-of-bounds read by ensuring the function does not access memory before the start of the input path string. This change stops the data loss scenario but still leaves the command exiting with a BUG message (`How come '' becomes empty after sanitization?`), which the second patch in the series will address. The fix is narrowly scoped to the problematic function and does not introduce new symbols, CLI options, or on-disk format changes.
