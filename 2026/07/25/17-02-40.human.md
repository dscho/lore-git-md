This is Junio’s reply to Tian Yuchen’s three-patch series that migrates four more global configuration variables (`minimum_abbrev`, `default_abbrev`, `pack_size_limit_cfg`, `assume_unchanged`) into `repo_config_values` as part of the `the_repository` removal effort.

Junio questions the design choice in patch 1/3: instead of adding explicit `(repo != the_repository)` checks that silently redirect to `the_repository`, he suggests the code should **BUG()** when a non-`the_repository` repo is passed, because the underlying APIs (notably the abbreviation machinery) are not yet ready to handle arbitrary repositories. His concern is that silently redirecting to `the_repository` papers over the unfinished state of those APIs and creates a false sense of progress—it looks like the code now accepts any `repo`, but in reality it still only works with `the_repository`. He sees this as piling on unfinished work rather than actually extending the APIs to support arbitrary repositories.
