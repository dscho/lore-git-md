This is a two-patch series refining the behavior of `git checkout -m` when autostash is involved. The author, Harald Nordgren, addresses two "leftover bits" from a previous discussion: avoiding unnecessary autostash retries when no local changes exist, and improving the clarity of conflict advice messages.

The first patch teaches the sequencer's autostash apply logic to explicitly report conflicts, which helps distinguish between stash application failures and other issues. The second patch adjusts `git checkout -m` to skip autostash retries if there are no tracked local changes, and visually separates autostash conflict advice from the subsequent branch-switch message. The changes touch `builtin/checkout.c`, `sequencer.c`, and related files, with new tests added in `t/t7201-co.sh`.

The motivation is clear: reducing noise in the user experience by avoiding redundant operations and making error messages more readable. The commit messages are concise but sufficient, and the test coverage looks appropriate. This appears to be a well-scoped, user-facing improvement rather than a deep refactoring. If you care about checkout ergonomics or have encountered confusing autostash behavior, this series is worth a look.
