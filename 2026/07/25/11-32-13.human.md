This is part four of Harald Nordgren’s seven-patch series introducing `git branch --delete-merged`, a new command for safe automated cleanup of local branches. The series is now in its 23rd iteration and is ready for merging; this patch is unchanged from v22, which Junio C Hamano confirmed has no outstanding issues.

The patch prepares the existing `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`. When this flag is set, the function will not fall back to `HEAD` if a branch has no upstream, ensuring that `--delete-merged` only deletes branches that are explicitly merged into one of the specified upstreams. Existing callers (like `git branch -d`) retain their current behavior, which considers `HEAD` as a fallback.

The change is minimal and targeted: it modifies `branch_merged()` to suppress the "gentle reminder" message when `head_rev` is `NULL` (indicating the caller has opted out of the `HEAD` fallback) and updates `delete_branches()` to skip the `HEAD` lookup when the new flag is set. The flag is plumbed through the function signature but is only exercised by the `--delete-merged` subcommand in patch 5/7. The patch introduces no behavioral changes for existing callers and is well-tested as part of the broader series.

This is a refactoring patch that enables the core functionality of the series. The flags-based API (introduced in earlier patches) ensures consistency and eliminates local boolean caching, addressing a maintenance risk identified in earlier reviews. The patch touches only `builtin/branch.c` and is low-risk, with no functional impact outside the new `--delete-merged` subcommand. The series as a whole is unblocked and should appear in an upcoming "What's cooking" report.
