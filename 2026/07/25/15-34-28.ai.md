This is the first patch in Harald Nordgren’s two-patch series refining `git checkout -m` autostash conflict handling. It teaches the sequencer’s autostash plumbing to explicitly report whether applying the stash resulted in conflicts by adding a `conflicted` output parameter to `apply_save_autostash_oid()` and `apply_save_autostash_ref()`. The patch threads this parameter through the call chain, updating all existing callers (`builtin/checkout.c`, `builtin/commit.c`, and `builtin/merge.c`) to pass `NULL` so they remain behaviorally unchanged. The core logic in `sequencer.c` now sets `*conflicted = true` when the stash apply fails and prints the existing conflict advice message. No new tests are introduced in this patch; the follow-up patch will exercise the new parameter. The change is mechanical and backward-compatible, laying the groundwork for the checkout retry logic in patch 2.
