This is the third patch in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. It updates the client-side request logic in `fetch-object-info.c` to dynamically send all supported object-info options (currently "size" and "type") instead of hardcoding "size" alone.

The change is a straightforward refactoring: `send_object_info_request()` now iterates over the `object_info_options` string list and transmits every option it contains. The commit message notes that this is safe because the list has already been filtered in `fetch_object_info()` to include only capabilities the server advertises. The patch touches only one file and is mechanical, replacing a conditional with a loop.

This patch prepares the client to parse the "type" field from the server response, though the server-side capability advertisement (added in patch 1) is required for the full end-to-end flow. The implementation follows the established pattern from Eric Sunshine’s predecessor series and maintains backward compatibility by continuing to request "size" when it is the only supported option. No new symbols are introduced, and the behavior change is minimal—only the request format is generalized.
