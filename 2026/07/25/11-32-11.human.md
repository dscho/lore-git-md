This is the second patch in Harald Nordgren’s seven-part `git branch --delete-merged` series, which is now ready for merging. The patch refactors `delete_branches()` and `check_branch_commit()` to replace the existing `force` and `quiet` boolean parameters with a single `unsigned int flags` argument and an enum (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is purely mechanical—no behavior is altered—and is a prerequisite for the subsequent patches that introduce additional flags (`DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`, and `DELETE_BRANCH_DRY_RUN`).

The motivation is straightforward: the current API uses separate booleans for each option, which becomes unwieldy as more options are added. The flags-based approach is cleaner, more extensible, and avoids the risk of stale cached values (e.g., local `int force` variables that might not reflect the caller’s intent). The patch tests the flags directly at each use site, ensuring consistency. This refactoring is low-risk, well-tested, and touches only `builtin/branch.c`.

The series as a whole is unblocked and addresses a real workflow pain point: safe, automated local branch cleanup with comprehensive safety controls (per-branch opt-out, stacked-branch protection, `--dry-run` preview, and repeatable upstream selectors). This patch is a small but necessary step toward that goal, and the implementation looks solid. The only changes since v22 are mechanical fixes to patch 1/7, which have no bearing on this patch.
