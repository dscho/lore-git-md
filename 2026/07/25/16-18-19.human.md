This is a review reply from Jeff King (Peff) to Junio C Hamano’s v2 patch plugging memory leaks in `rewrites_release()` in `remote.c`.

Peff confirms the v2 approach is correct. He explains that the initial assumption in v1—that strings borrowed from the configset subsystem would persist—was unsafe. While he couldn’t construct a concrete failure case, he notes that the configset can be discarded (e.g., during repository discovery or config updates), making any reliance on its persistence fragile. The v2 patch abandons this assumption, copying strings explicitly instead, which Peff endorses as the safer choice even if slightly less efficient. The review is substantive and tested: Peff dug into the code paths and ownership semantics before concluding.
