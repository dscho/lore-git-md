This thread is a three-patch series from Tian Yuchen that migrates four global Git configuration variables (`minimum_abbrev`, `default_abbrev`, `pack_size_limit_cfg`, and `assume_unchanged`) into the `repo_config_values` struct. The goal is to eliminate implicit reliance on the global `the_repository` variable, a key step in the ongoing effort to make Git’s codebase more modular and library-friendly.

The series is part of René Scharfe’s broader `the_repository` removal initiative and builds directly on prior work to scope configuration values to individual repositories. The first patch, which handles `minimum_abbrev` and `default_abbrev`, introduces repository-aware getters and updates callers in several subsystems, including `merge-ort.c` (which explicitly avoids `the_repository`), `object-file.c`, and the sequencer. The changes are mechanical but require careful handling of repository parameters, particularly in code paths that forbid direct use of `the_repository`.

No review feedback has been recorded yet, but the series is positioned as uncontroversial infrastructure work. Existing tests should cover the changes, as no behavior change is intended. The remaining two patches will address `pack_size_limit_cfg` and `assume_unchanged`. If you’re following the `the_repository` removal effort, this is a straightforward but important step forward.
