This thread is about the second iteration of a patch series by Tian Yuchen that migrates two global configuration variables—`pack_size_limit_cfg` and `assume_unchanged`—into the repository-scoped `repo_config_values` struct. The goal is to eliminate process-global state as part of the broader effort to remove implicit reliance on `the_repository`, a key step toward libifying Git’s internals. The first patch in the series, which moved `pack_size_limit_cfg`, has already been reviewed and accepted without objection, while this second patch addresses `assume_unchanged`.

The changes are mechanical and infrastructure-focused, updating direct references to the global variable in `builtin/update-index.c`, `read-cache.c`, and `environment.c` to use the repository-specific instance instead. No getter function is introduced due to the limited number of call sites, and backward compatibility is preserved by falling back to `the_repository` where necessary. The patch touches the index update logic (where `CE_VALID` is managed) and configuration handling, ensuring that `core.ignorestat` updates the repository-scoped value directly. Like the first patch, this one introduces no behavior changes and is intended as a stepping stone for future work.

The series has so far been uncontested, with no review feedback yet on this second patch. Junio Hamano’s earlier objection to the v1 design—specifically, the use of silent fallbacks to `the_repository`—was addressed by narrowing the scope and avoiding such fallbacks in v2. The remaining open question is how to extend APIs like `merge-ort.c` to handle repository-scoped configuration without relying on `the_repository`, but that is left for follow-up work. For now, the series is on track, with only this patch left to review.
