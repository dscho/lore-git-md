This is a two-patch bugfix series targeting `git worktree add`. The patches address an out-of-bounds memory read in `worktree_basename()` that can lead to data loss—specifically, the unintended recursive deletion of the current working directory (including `.git`) when an empty string is passed as the worktree path. The issue manifests inconsistently, sometimes triggering a BUG message (`How come '' becomes empty after sanitization?`) but also allowing silent corruption.

The first patch prevents the out-of-bounds read by ensuring the function does not access memory before the start of the input path string. The second patch adds explicit validation to reject empty strings outright, closing the edge case where malformed input could bypass safety checks. Both changes are confined to `builtin/worktree.c` and are motivated by real-world scenarios involving unset environment variables (e.g., `git worktree add "$UNSET_VAR" -b tb origin/main`).
