This is the sixth patch in Harald Nordgren’s seven-part series introducing `git branch --delete-merged`, a new command for safe automated local branch cleanup. This patch adds the `branch.<name>.deleteMerged` configuration key, which lets users exempt specific branches from automated deletion while still allowing explicit removal via `git branch -d`.

The implementation is straightforward: during candidate filtering in `delete_merged_branches()`, the code checks for `branch.<name>.deleteMerged=false` using `repo_config_get_bool()`. If set, the branch is skipped and a non-quiet message explains the opt-out. The config key is documented in both `branch.adoc` and `git-branch.adoc`, and the test suite verifies that the opt-out works as expected and does not interfere with explicit deletion.

Phillip Wood’s earlier review suggested a mechanical test improvement—using `git for-each-ref` instead of `rev-parse` to verify branch state—which this version incorporates via the `check_branches` helper. The patch is clean, well-tested, and aligns with the series’ overall safety-focused design. There are no open issues; this is a final, merge-ready feature.
