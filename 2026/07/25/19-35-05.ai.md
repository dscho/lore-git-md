This is a reply in the RFC thread introducing `git repack --drop-filtered` for partial clones. The patch under discussion (7/7) implements the drop log (`$GIT_DIR/objects/info/promisor-dropped`) to record objects removed by `--drop-filtered`. The author, Siddharth Shrimali, acknowledges reviewer Siddharth Asthana’s suggestion to document the log path in `gitrepository-layout` and add a test verifying that real drops append entries. Shrimali agrees to include this documentation when the log is finalized, whether in the current minimal version or alongside future error-path improvements.

The drop log remains a deferred feature in the planned v2 series, with its remote-object attribution and error-message integration dependent on the `remote-object-info` protocol command. The current implementation records all configured promisor remotes for each dropped object (a NEEDSWORK limitation), but this is not considered a blocker for v2. The focus for v2 remains on fixing the `--drop-filtered` vs `--write-bitmap-index` validation flaw, implementing safety guards (merge/rebase/cherry-pick checks and index validation), and reorganizing internal APIs. The log’s documentation and test coverage will be addressed as part of finalizing this patch, but are not critical path for the series’ core functionality.
