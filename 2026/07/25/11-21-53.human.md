This is a **bug report and regression analysis** from Erik Cervin-Edin about the `git rebase --update-refs` series under review. Erik describes a minor regression he encountered in v2 of Son Luong Ngoc’s patch series, where the rebase todo file incorrectly included a comment for the branch being rebased (e.g., `# Ref refs/heads/main checked out at '/private/tmp/gittest'`), even though that branch is updated by the rebase itself and should not appear in the `--update-refs` list. This issue was fixed in v3, but Erik shares his findings to clarify the root cause and help prevent similar issues in future iterations.

The regression in v2 occurred because the logic for skipping the current branch relied on `!path` (checking if the branch was not checked out anywhere), but `branch_checked_out()` cannot distinguish between "checked out in the current worktree" and "checked out in another worktree." As a result, the current branch was incorrectly included in the todo list. In v3, the check was simplified to unconditionally skip the current branch (by comparing `head_ref` directly), which resolved the issue.

Erik also hypothesizes that the same symptom (unwanted todo comments) could occur on the `master` branch due to a separate issue: `head_ref` is obtained using `refs_resolve_ref_unsafe()`, whose buffer is overwritten inside `branch_checked_out()`. This could cause the comparison for other branches (e.g., `topic2`) to fail if `head_ref` is clobbered by an earlier lookup. He notes that he hasn’t tested this scenario but suggests it as a possible explanation for similar behavior observed elsewhere.

The email is a helpful contribution to the ongoing review, providing concrete evidence of a regression and its resolution, as well as a plausible theory for a related edge case. It reinforces the importance of the changes in v3 and highlights a potential pitfall in the interaction between `refs_resolve_ref_unsafe()` and `branch_checked_out()`. The next iteration of the series (v4) will likely need to address Phillip Wood’s latest feedback, and Erik’s observations may inform those refinements. The patch remains under active review with no merge status reported.
