This is the third patch in Harald Nordgren’s seven-part series introducing `git branch --delete-merged`. The series as a whole is now unblocked and ready for merging after addressing all prior feedback, including mechanical fixes in patch 1/7 (v23).

This patch adds a `DELETE_BRANCH_SKIP_UNMERGED` flag to the branch-deletion API, allowing bulk callers (specifically the new `--delete-merged` subcommand) to silently skip unmerged branches instead of failing with the usual “not fully merged” error and advice to use `-D`. The change is minimal and targeted: it modifies `check_branch_commit()` and `delete_branches()` to suppress the error and advice when the flag is set, and ensures the deletion loop continues without setting a failure return code. Existing callers—such as `git branch -d`—are unaffected because they do not pass the new flag.

The patch is purely mechanical and introduces no behavioral changes for current users. It is low-risk, well-tested, and touches only `builtin/branch.c`. The flag is exercised only by the `--delete-merged` subcommand (patch 5/7), which needs this behavior to avoid aborting the entire operation when it encounters an unmerged branch. The implementation is consistent with the flags-based API refactoring established in patches 2–4/7, which eliminates local boolean caching to ensure flags remain the single source of truth.
