This is the sixth patch in the RFC series introducing `git repack --drop-filtered` for partial clones, now updated in response to reviewer feedback. The author acknowledges Siddharth Asthana’s observation that a real `--drop-filtered` run should imply `-d` (removing old promisor packs containing the dropped blobs) and commits to documenting this behavior explicitly in the upcoming v2 man page. This clarification will help users understand that the feature not only rebuilds promisor packs without the dropped blobs but also cleans up redundant packs, ensuring disk space is actually reclaimed. The change is straightforward and aligns with the repack machinery’s existing behavior, so it should not introduce new technical risks. The v2 series will address this along with the previously identified blocking issues: the bitmap validation flaw, safety guards for merges/rebases, and index validation.
