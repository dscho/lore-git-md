This is the fourth patch in Pablo Sabater’s five-part GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote-object-info queries. The patch is a small but essential piece of the puzzle: it makes the Git server advertise the new “type” capability so that clients know they can request object type metadata.

The change itself is mechanical and minimal. In `serve.c`, the server’s capability advertisement string is updated from `"size"` to `"size type"`, reflecting the two object-info options now supported. The accompanying test in `t/t1017` is adjusted to verify that the server actually provides type data when requested, replacing an older test that expected an empty string for unsupported placeholders. The commit message is clear and to the point, explaining why the advertisement is necessary and how it fits into the larger series.

This patch looks like a clean, well-scoped extension of the existing remote-object-info infrastructure. It follows the established pattern from Eric Sunshine’s recently merged v21 series and keeps the scope narrow—only object type, as the commit message reiterates. No controversy or open questions are evident; it simply plugs a gap in the protocol handshake. If the rest of the series holds up, this piece should be uncontroversial.
