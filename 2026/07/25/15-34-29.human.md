This is the second patch in a two-patch series refining how `git checkout -m` handles autostash conflicts. The series addresses a long-standing edge case where autostash retries could loop unnecessarily or produce confusing advice messages.

This patch makes two concrete improvements. First, it skips the autostash retry loop entirely when there are no tracked local changes, since retrying cannot resolve the conflict. The patch checks for unstaged or uncommitted changes early and only proceeds with autostash if they exist. Second, it improves the user interface by printing a blank line after the autostash conflict advice, visually separating it from the subsequent "Switched to branch" confirmation message. The change is small but noticeable in the test output, where the advice and branch-switch messages are now clearly delineated.

The implementation touches `builtin/checkout.c`, adjusting the `merge_working_tree` function to conditionally enable autostash based on whether tracked changes exist, and the `switch_branches` function to emit the blank line when conflicts occur. The test suite (`t/t7201-co.sh`) gains a new test case that verifies both the fast-path behavior (no retry when no changes exist) and the improved advice formatting.
