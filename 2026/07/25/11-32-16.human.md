This is the final patch in Harald Nordgren’s `git branch --delete-merged` series, adding `--dry-run` support to the new subcommand. The patch is small, focused, and ready for merging.

The implementation adds a `DELETE_BRANCH_DRY_RUN` flag to the deletion API. When set, `delete_branches()` prints "Would delete branch <name>" or "Would skip branch <name>" for each affected branch without modifying refs or config. The flag is plumbed through the command-line interface via `--dry-run`, which is only accepted when `--delete-merged` is specified. The nonsensical `--dry-run --quiet` combination is rejected as an error, avoiding confusing output.

The patch updates the documentation to describe `--dry-run` as a sanity-check mechanism for wide patterns like `origin/*` and adds three new tests in `t/t3200-branch.sh`. The tests verify that `--dry-run` produces the expected output, preserves refs and config, and is rejected without `--delete-merged`. The implementation is minimal and targeted, suppressing ref and config modifications while printing output that exactly matches the real deletion/protection messages.

This patch completes the series, which is now unblocked and ready for merging. The only changes since v22 are mechanical fixes to patch 1/7, and Junio C Hamano has confirmed there are no outstanding issues. The `--dry-run` feature is a natural complement to the safety-focused design of `--delete-merged`, giving users confidence before committing to deletions.
