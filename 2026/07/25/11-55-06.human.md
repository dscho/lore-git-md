This is the final patch in a five-part GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series builds on Eric Sunshine’s recently merged work to add remote-object-info support, completing the feature by enabling object type metadata — the last piece of metadata guaranteed to match between client and server after a fetch.

This patch unifies the default format string used by `git cat-file` for both local and remote object queries. Previously, the remote-object-info command used a temporary default (`%(objectname) %(objectsize)`) because `%(objecttype)` wasn’t supported; now that it is, the patch switches to the standard default (`%(objectname) %(objecttype) %(objectsize)`), removing the special case in the code and updating the documentation to reflect the change. The patch also removes the warning about the temporary format and updates the CAVEATS section to list `%(objecttype)` as a supported placeholder.

The test suite is updated to expect object type in the output, and a now-redundant test (which verified the old temporary format) is removed. The protocol documentation is also updated to document the "type" attribute in the `object-info` command.

This is a clean, mechanical patch that ties off the series. It’s well-scoped, with clear motivation and thorough test coverage. The change is backward-compatible: clients that don’t request type will continue to work, and the server only transmits type data when explicitly requested. The patch is under review and part of a v1 series; no substantive feedback has been posted yet.
