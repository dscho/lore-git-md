This is the second patch in Pablo Sabater’s five-part GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. It prepares the client to parse object type data from the server response, even though the server does not yet advertise the "type" capability (that comes in patch 1).

The patch is a straightforward mechanical change to `fetch-object-info.c`. It adds a `type_index` variable to track the position of the "type" field in the server’s response, allocates memory for the type data (`object_info_data[j].typep`), and updates the parsing loop to extract and convert the type string into an enum value using `type_from_string()`. The BUG message is also updated to reflect the new supported field. The change is narrowly scoped to the parsing logic and does not alter any existing behavior—it simply lays the groundwork for the full end-to-end support introduced in later patches.

The commit message is clear and concise, explaining the purpose and the incremental nature of the work. The patch itself is well-structured and follows the established pattern from the predecessor series (Eric Sunshine’s v21). No test failures or CI issues are mentioned, and the change looks like a clean, low-risk extension of the existing remote-object-info infrastructure. For anyone following the series, this patch is a predictable and necessary step toward enabling object type queries.
