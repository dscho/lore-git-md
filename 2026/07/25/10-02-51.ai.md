This is a **substantive review follow-up** from Jeff King (Peff) in the ongoing packfile URI race-condition fix series. Peff now believes the intermittent `--stress` test failure in `t5550-http-fetch-dumb.sh` (test 34) is a **false positive** caused by a race in the test’s synchronization logic, not a bug in the core download logic or the custom Perl server.

The issue centers on the `test -s` check that verifies the first downloader has written data to disk before the second downloader starts. Peff’s strace analysis shows the server’s `write()` call does not guarantee the client has received or flushed the data, so the test can spuriously fail even when the download logic is correct. He proposes **dropping the `test -s` check entirely**, arguing the two downloaders are symmetric: if the second downloader writes first, the first downloader’s later write will simply overwrite identical bytes, which the patch’s deterministic staging path design explicitly allows. This change would eliminate the flakiness without affecting the test’s ability to catch real corruption.

The series remains **blocked** until this test synchronization issue is resolved, but Peff’s latest email shifts the focus from infrastructure (Apache rewrite) to test design, suggesting a simpler fix. No code changes are proposed yet; the discussion is still at the design level. Key technical detail: the test’s FIFO-based synchronization is sound for process coordination, but the `test -s` check introduces a data-race that is unrelated to the patch’s core correctness.
