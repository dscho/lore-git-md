Subject: [PATCH v2] remote.c: plug memory leaks in `rewrites_release()`
Series version: standalone patch (v2)
Originating author: Junio C Hamano
Thread type: bugfix

Core problem or goal
Plug memory leaks in the `rewrites_release()` function in `remote.c`, which frees memory associated with URL alias settings (`url.<real>.insteadOf` and `url.<real>.pushInsteadOf`). The function previously failed to free nested allocations within `struct rewrites`, including the `.instead_of` string array and its contents, and made unsafe assumptions about string ownership from the configset.

Current status
Under review; CI confirmation received for both iterations. The patch is a minimal, focused fix (9 insertions, 2 deletions) confined to `remote.c`. All CI jobs passed on the `seen` integration branch for v1 ([30137079882](https://github.com/git/git/actions/runs/30137079882/)) and v2 ([30138777784](https://github.com/git/git/actions/runs/30138777784/)). No integration branch updates have been reported; the patch remains in `seen`.

Key technical details
- Files touched: `remote.c`
- Functions: `rewrites_release()`
- Data structures: `struct rewrites` (tracks URL alias settings), `struct rewrite` (individual alias rule), `struct counted_string` (alias target strings)
- Symbols: `url.<real>.insteadOf`, `url.<real>.pushInsteadOf` (configuration keys)
- Leak sources: nested allocations within `struct rewrites` (`.instead_of` string array and its contents), unsafe reliance on configset string persistence
- String ownership: v1 incorrectly assumed configset strings would persist; v2 explicitly copies and frees strings for robustness, aligning with established patterns elsewhere in the codebase
- Test exposure: leaks were exposed by Emily Shaffer's `en/submodule-insteadof-remote-match` series
- CI confirmation: GitHub Actions runs [30137079882](https://github.com/git/git/actions/runs/30137079882/) (v1, passing) and [30138777784](https://github.com/git/git/actions/runs/30138777784/) (v2, passing)

Open questions and loose ends
None identified. The patch is described as straightforward with no unresolved concerns. The v2 iteration addresses feedback about string ownership assumptions and includes a clearer commit message explaining the data structure hierarchy and the rationale for explicit copying.
