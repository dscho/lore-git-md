This is the third patch in Harald Nordgren’s **v23 `git branch --delete-merged` series**, which is now **ready for merging** after addressing all prior feedback. This patch introduces a **substantive API refactoring** to support bulk branch deletion operations by adding the `DELETE_BRANCH_SKIP_UNMERGED` flag to `delete_branches()` and `check_branch_commit()`.

The change enables callers like the upcoming `--delete-merged` subcommand to **silently skip unmerged branches** instead of failing with the "not fully merged" error and advice that `git branch -d` emits. This is critical for bulk operations where the caller wants to delete only merged branches and ignore unmerged ones without triggering a hard error. The patch is **minimal and targeted**, modifying only the error-handling paths in `check_branch_commit()` and `delete_branches()` to suppress the error and advice when the new flag is set. Existing callers (e.g., `git branch -d`) are unaffected, as the flag is only exercised by the `--delete-merged` subcommand in patch 5/7.

The implementation is **low-risk** and **well-motivated**: it preserves the existing behavior for all current callers while enabling the new bulk-deletion use case. The flag is checked at both the commit-checking (`check_branch_commit()`) and deletion (`delete_branches()`) stages, ensuring unmerged branches are skipped without triggering a failure. This aligns with the series’ goal of providing safe, automated branch cleanup with precise control over deletion behavior.

The patch touches only `builtin/branch.c` and is part of the **flags-based API refactoring** (patches 2-4/7) that replaces boolean arguments with `unsigned int flags` to eliminate local caching and ensure flags remain the single source of truth. Earlier reviews identified the maintenance risk of caching flags locally (e.g., `int force = 1`), and this patch avoids that pitfall by testing the flag directly at each use site. The refactoring is **purely mechanical** and introduces no behavioral changes for existing callers.
