This is patch 6/7 of Harald Nordgren’s `git branch --delete-merged` series, now in its 23rd iteration and ready for merging. The patch adds a per-branch opt-out mechanism via the `branch.<name>.deleteMerged` configuration key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The implementation is straightforward and well-scoped. It introduces a new config key (`branch.<name>.deleteMerged`, defaulting to `true`) that, when set to `false`, prevents the branch from being deleted by `git branch --delete-merged`. The opt-out is checked during candidate filtering in `delete_merged_branches()` using `repo_config_get_bool()`, and a non-quiet skip message is printed to inform the user. The patch updates both `Documentation/config/branch.adoc` and `git-branch.adoc` to document the new key and its behavior, and adds two new tests in `t/t3200-branch.sh` to verify the opt-out mechanism and its interaction with explicit deletion.

The code is clean and follows Git’s conventions. The config key name (`deleteMerged`) is clear and consistent with existing branch config keys (e.g., `merge`, `rebase`). The implementation avoids modifying behavior for existing callers of `delete_branches()` and does not interfere with the normal merge check used by `git branch -d`. The tests are thorough, covering both the opt-out behavior and the ability to override it with explicit deletion, and use the `check_branches` helper (introduced in an earlier patch) to verify branch state via `git for-each-ref`.

This patch is part of a larger, well-motivated effort to provide safe automated branch cleanup. The opt-out mechanism addresses a real workflow need—iterative topic branches that are partially merged upstream—without compromising safety. The implementation is minimal, focused, and aligns with the series’ overall design. Phillip Wood’s earlier review suggested only a mechanical test improvement (using `for-each-ref` for branch state verification), which has been applied. There are no outstanding issues, and the patch is ready for merging alongside the rest of the series.
