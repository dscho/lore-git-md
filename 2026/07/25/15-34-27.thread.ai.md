Subject: [PATCH 0/2] checkout -m: refine autostash conflict handling
Series version: v3 (pending, after enum API change)
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Refine `git checkout -m` behavior when autostash is involved by visually separating autostash conflict advice from the branch-switch confirmation message, eliminating visual clutter without altering the underlying conflict resolution logic.

Current status
Under review; v2 posted as a single patch, now awaiting v3 to adopt an `enum` return type for `apply_save_autostash_oid()` and `apply_save_autostash_ref()`. Junio C Hamano’s prior conditional acceptance of the uncontroversial advice-formatting portion is satisfied. The fast-path optimization has been dropped, addressing Phillip Wood’s performance concern. Phillip Wood has now explicitly endorsed an `enum` API to encode the three states (success, conflict, error), resolving the last design objection. The patch remains a pure UX change with no API or performance disputes.

Key technical details
- Files touched: `sequencer.c` (return-value semantics), `builtin/checkout.c` (advice formatting), `t/t7201-co.sh` (test validation).
- New behavior: `apply_save_autostash_oid()` and `apply_save_autostash_ref()` will return an `enum` (proposed: `AUTOSTASH_APPLY_SUCCESS`, `AUTOSTASH_APPLY_CONFLICT`, `AUTOSTASH_APPLY_ERROR`) instead of an `int`. Callers in `checkout.c` print a blank line to stderr when the return value is `AUTOSTASH_APPLY_CONFLICT`, visually separating conflict advice from the branch-switch confirmation.
- Symbols: `apply_save_autostash_oid()`, `apply_save_autostash_ref()` (return type will change to `enum autostash_apply_result`).
- Test coverage: updated test in `t/t7201-co.sh` uses `test_cmp` to validate the full screen output.
- Base commit: `c73e85354c275c9d409b26445089bc16940fc527` on `master`.

Open questions and loose ends
None. The API design concern is resolved by adopting an `enum`; the patch is now uncontested and ready for v3.
