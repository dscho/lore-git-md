Subject: [PATCH 0/2] checkout -m: refine autostash conflict handling
Series version: v3 (posted, implements enum API and correctness fix)
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Refine `git checkout -m` behavior when autostash is involved by visually separating autostash conflict advice from the branch-switch confirmation message, eliminating visual clutter without altering the underlying conflict resolution logic. The patch must also correctly distinguish between true conflicts and other failures during stash application, and align exit codes with Git’s established conventions.

Current status
v3 posted, implementing the `enum` return type for `apply_save_autostash_oid()` and `apply_save_autostash_ref()` and fixing the correctness issue in conflict detection logic via Phillip Wood’s proposal. The patch now classifies `ret == 1` as a conflict (`STASH_APPLY_CONFLICT`), `ret > 1` or negative as an error (`STASH_APPLY_ERROR`), and `ret == 0` as success (`STASH_APPLY_CLEAN`). The caller in `checkout.c` prints a blank line for conflicts and a new error message for non-conflict failures. All prior review feedback is addressed except for Phillip Wood’s new **major design concern** about exit code conventions: the patch currently uses exit code 2 for conflicts, but Phillip argues that Git’s established convention (used by `merge-tree`, `grep`, and `diff`) is to use exit code 1 for conflicts and other non-zero values for errors. The author must decide whether to adopt this suggestion or defend the current approach. The series remains ready for final review but is not yet uncontroversial.

Key technical details
- Files touched: `sequencer.c`/`sequencer.h` (return-value semantics and conflict detection logic), `builtin/checkout.c` (advice formatting and new error message), `builtin/stash.c` (exit code handling), `stash.h` (new `enum stash_apply_result` definition: `STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`), `Documentation/git-stash.adoc` (exit code documentation), and tests (`t/t3903-stash.sh`, `t/t7201-co.sh`).
- New behavior: `apply_save_autostash_oid()` and `apply_save_autostash_ref()` return `enum stash_apply_result` instead of `int`. Callers in `checkout.c` print a blank line to stderr when the return value is `STASH_APPLY_CONFLICT`, and a new error message (e.g., "could not apply autostash") for `STASH_APPLY_ERROR`. The conflict detection logic now distinguishes between `ret == 1` (conflict), `ret > 1` or negative (error), and `ret == 0` (success).
- Symbols: `apply_save_autostash_oid()`, `apply_save_autostash_ref()` (return type changed to `enum stash_apply_result`), `run_command()` (return value handling adjusted), `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`).
- Test coverage: updated tests in `t/t3903-stash.sh` and `t/t7201-co.sh` use `test_cmp` to validate the full screen output, including the new blank line for conflicts and the new error message for non-conflict failures. Tests cover all three return states but lack coverage for `stash branch` (suggested by Phillip Wood).
- Exit code documentation: `git-stash.adoc` now documents that `apply`, `pop`, and `branch` exit with status 2 on conflicts (stash entry preserved) and 1 on other failures. Phillip Wood argues this should be reversed (status 1 for conflicts, other non-zero for errors) to align with Git’s established convention.
- Code clarity issues: Phillip Wood flags a nested ternary operator in `do_apply_stash()` as unreadable and notes odd indentation in the function signature. The `STASH_APPLY_ERROR` assignment in one error path is redundant since other error paths still return `-1` implicitly.
- Base commit: `c73e85354c275c9d409b26445089bc16940fc527` on `master`.

Open questions and loose ends
1. **Exit code convention**: Should the patch use exit code 1 for conflicts (aligning with Git’s established convention) or continue using exit code 2 (current approach)? Phillip Wood strongly advocates for exit code 1, arguing it simplifies the code and improves consistency. The author must decide whether to adopt this change or defend the current design.
2. **Code clarity**: The nested ternary operator in `do_apply_stash()` and odd indentation in the function signature should be addressed. The redundant `STASH_APPLY_ERROR` assignment in one error path can be removed.
3. **Test coverage**: The `t3903-stash.sh` test includes an unnecessary commit (the reset to `initial` should already provide a clean state). Coverage for `stash branch` should be added to match the exit code documentation.
