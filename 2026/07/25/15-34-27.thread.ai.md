Subject: [PATCH 0/2] checkout -m: refine autostash conflict handling
Series version: v3 (pending, after correctness fix and enum API change)
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Refine `git checkout -m` behavior when autostash is involved by visually separating autostash conflict advice from the branch-switch confirmation message, eliminating visual clutter without altering the underlying conflict resolution logic. The patch must also correctly distinguish between true conflicts and other failures during stash application.

Current status
Under review; v2 posted as a single patch, now awaiting v3 to adopt an `enum` return type for `apply_save_autostash_oid()` and `apply_save_autostash_ref()` **and** to fix the correctness issue in conflict detection logic. Junio C Hamano’s prior conditional acceptance of the uncontroversial advice-formatting portion is satisfied. The fast-path optimization has been dropped, addressing Phillip Wood’s performance concern. Phillip Wood has explicitly endorsed an `enum` API to encode the three states (success, conflict, error). Junio’s new review identifies a correctness gap: the patch currently treats any non-zero return from `run_command()` as a conflict, but `git stash apply` can fail for reasons other than conflicts (e.g., command not found, crash, permission error). The correct signal for a conflict is a specific positive exit code from `git stash apply`, which the patch does not currently distinguish. Junio outlines a three-step plan to fix this: audit all `git stash` subcommands’ return conventions, adjust the exit code handling in `cmd_stash()` to preserve the conflict signal, and document the exit status semantics. For expediency, the patch could initially assume all failures are conflicts, but this must be documented as a known limitation. The patch remains a pure UX change with no API or performance disputes, but now has a correctness blocker.

Key technical details
- Files touched: `sequencer.c` (return-value semantics and conflict detection logic), `builtin/checkout.c` (advice formatting), `t/t7201-co.sh` (test validation), and potentially `builtin/stash.c` (exit code handling).
- New behavior: `apply_save_autostash_oid()` and `apply_save_autostash_ref()` will return an `enum` (proposed: `AUTOSTASH_APPLY_SUCCESS`, `AUTOSTASH_APPLY_CONFLICT`, `AUTOSTASH_APPLY_ERROR`) instead of an `int`. Callers in `checkout.c` print a blank line to stderr when the return value is `AUTOSTASH_APPLY_CONFLICT`, visually separating conflict advice from the branch-switch confirmation. The conflict detection logic must now distinguish between true conflicts and other failures, likely by inspecting the exit code of `git stash apply`.
- Symbols: `apply_save_autostash_oid()`, `apply_save_autostash_ref()` (return type will change to `enum autostash_apply_result`), `cmd_stash()` (may need adjustment to preserve conflict signal).
- Test coverage: updated test in `t/t7201-co.sh` uses `test_cmp` to validate the full screen output, including the new blank line for conflicts. Tests must now also cover non-conflict failures to ensure they are not misclassified.
- Base commit: `c73e85354c275c9d409b26445089bc16940fc527` on `master`.

Open questions and loose ends
1. **Conflict detection correctness**: The patch must distinguish between true conflicts and other failures during stash application. Junio’s review proposes a three-step plan (audit `git stash` subcommands, adjust `cmd_stash()` exit code handling, document semantics), but notes that for expediency the patch could initially assume all failures are conflicts (with documentation). This is a known limitation that must be resolved or documented in v3.
2. **Exit code semantics**: The specific exit code(s) used by `git stash apply` to signal conflicts must be audited and documented. This may require changes to `builtin/stash.c` to ensure the conflict signal is preserved.
3. **Enum API adoption**: The `enum` return type for `apply_save_autostash_oid()` and `apply_save_autostash_ref()` is still pending implementation in v3.
