Thread identity
Subject: [PATCH 0/2] checkout -m: refine autostash conflict handling
Series version: v1 (initial)
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Refine `git checkout -m` behavior when autostash is involved by (1) making the sequencer’s autostash apply logic explicitly report conflicts instead of silently failing, and (2) skipping the autostash retry loop when no tracked local changes exist, while also improving the visual separation of autostash conflict advice from the branch-switch confirmation message.

Current status
Under review; v1 posted. Junio C Hamano has accepted patch 2/2 as-is and signaled intent to queue it for integration (branch not yet specified). Patch 1/2 remains under active review following Phillip Wood’s design objection to its API approach. The fast-path optimization (skipping autostash retry when no tracked changes exist) is now contested on performance grounds: Phillip Wood argues the cost of the pre-check outweighs the benefit of avoiding an occasional redundant stash/unstash cycle, and suggests a deeper refactoring of `unpack_trees()` would be needed to make the optimization truly effective.

Key technical details
- Files touched: `sequencer.c`/`sequencer.h` (autostash plumbing), `builtin/checkout.c` (retry logic and advice formatting), `builtin/commit.c`, `builtin/merge.c` (return-code adjustments).
- New behavior: `apply_save_autostash_oid()` and `apply_save_autostash_ref()` now accept a `conflicted` output parameter that is set to `true` when stash apply fails; existing callers pass `NULL` to preserve current behavior.
- Fast-path: `merge_working_tree()` now checks `has_unstaged_changes()` or `has_uncommitted_changes()` before invoking `unpack_trees()`; if no tracked changes exist, the autostash retry loop is skipped entirely. The new `allow_autostash` parameter (passed from `switch_branches()`) controls this check.
- Advice output: autostash conflict message is visually separated from the branch-switch confirmation by a blank line printed to stderr when `conflicted` is set. This change is uncontroversial and endorsed by Phillip Wood as "very welcome."
- Test coverage: new test in `t/t7201-co.sh` verifies both the no-tracked-changes fast-path and the improved advice layout. Phillip Wood proposes replacing the multi-grep validation with a single `test_cmp` against the full screen output.
- Base commit: `9a0c4701dcd5` on `master`.
- Symbols: `apply_save_autostash_oid()`, `apply_save_autostash_ref()`, `conflicted` parameter, `allow_autostash` parameter.

Open questions and loose ends
Patch 1/2’s API design remains contested: Phillip Wood objects to the use of an output parameter (`conflicted`) to report stash-apply conflicts, arguing the return value should be repurposed instead. No alternative implementation has been proposed yet. The fast-path optimization is now also contested on performance grounds, with Phillip suggesting it may need to be dropped or replaced with a deeper refactoring of `unpack_trees()`. Junio’s acceptance of patch 2/2 (which depends on patch 1/2) is conditional on resolving these objections, likely requiring a v2 of the series.

Participant positions
Junio C Hamano: accepted patch 2/2 as-is; intent to queue for integration, but conditional on patch 1/2 resolving Phillip’s design concern and now also the fast-path performance concern.
Phillip Wood: reviewed both patches substantively. Objects to patch 1/2’s `conflicted` output-parameter design and now also to the fast-path optimization’s performance trade-off, advocating for either dropping the fast-path or refactoring `unpack_trees()` to buffer error messages and return structured error flags. Endorses the advice-layout improvement in patch 2/2 as "very welcome" and suggests it could be squashed into patch 1/2 as motivation for the API changes.
