Subject: [PATCH 0/2] checkout -m: refine autostash conflict handling
Series version: v3 (posted, implements enum API and correctness fix; exit code convention now resolved)
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Refine `git checkout -m` behavior when autostash is involved by visually separating autostash conflict advice from the branch-switch confirmation message, eliminating visual clutter without altering the underlying conflict resolution logic. The patch must also correctly distinguish between true conflicts and other failures during stash application, and align exit codes with Git’s established conventions.

Current status
v3 posted, implementing the `enum` return type for `apply_save_autostash_oid()` and `apply_save_autostash_ref()` and fixing the correctness issue in conflict detection logic via Phillip Wood’s proposal. Junio C Hamano has now explicitly endorsed Phillip Wood’s exit code convention (exit code 1 for conflicts, other non-zero values for errors), resolving the last design obstacle. The series is ready for final mechanical changes: adjusting exit codes to match the established convention, addressing code clarity issues (nested ternary, indentation, redundant assignment), and improving test coverage (removing unnecessary commit, adding `stash branch` coverage). All prior review feedback is addressed; the patch is now uncontroversial and awaits a v4 incorporating these adjustments.

Key technical details
- Files touched: `sequencer.c`/`sequencer.h` (return-value semantics and conflict detection logic, including Junio’s accepted adjustment for `run_command()` return values), `builtin/checkout.c` (advice formatting and new error message), `builtin/stash.c` (exit code handling), `stash.h` (new `enum stash_apply_result` definition: `STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`), `Documentation/git-stash.adoc` (exit code documentation), and tests (`t/t3903-stash.sh`, `t/t7201-co.sh`).
- New behavior: `apply_save_autostash_oid()` and `apply_save_autostash_ref()` return `enum stash_apply_result` instead of `int`. Callers in `checkout.c` print a blank line to stderr when the return value is `STASH_APPLY_CONFLICT`, and a new error message (e.g., "could not apply autostash") for `STASH_APPLY_ERROR`. The conflict detection logic now distinguishes between `ret == 1` (conflict, exit code 1), `ret > 1` or negative (error, exit code 128 or other non-zero), and `ret == 0` (success, exit code 0). Exit code documentation in `git-stash.adoc` will be updated to reflect this convention.
- Symbols: `apply_save_autostash_oid()`, `apply_save_autostash_ref()` (return type changed to `enum stash_apply_result`), `run_command()` (return value handling adjusted per Junio’s accepted suggestion), `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`).
- Test coverage: updated tests in `t/t3903-stash.sh` and `t/t7201-co.sh` use `test_cmp` to validate the full screen output, including the new blank line for conflicts and the new error message for non-conflict failures. Tests cover all three return states but lack coverage for `stash branch` (suggested by Phillip Wood). The unnecessary commit in `t3903-stash.sh` will be removed.
- Code clarity issues: the nested ternary operator in `do_apply_stash()` and odd indentation in the function signature will be addressed. The redundant `STASH_APPLY_ERROR` assignment in one error path will be removed.

Open questions and loose ends
1. **Mechanical changes**: The author must adjust exit codes to use 1 for conflicts (aligning with Git’s established convention), address code clarity issues (nested ternary, indentation, redundant assignment), and improve test coverage (remove unnecessary commit, add `stash branch` coverage). These are uncontroversial and await implementation in v4.
