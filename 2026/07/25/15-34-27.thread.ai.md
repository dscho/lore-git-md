Subject: [PATCH 0/2] checkout -m: refine autostash conflict handling
Series version: v4 (posted, final mechanical adjustments; all design issues resolved)
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Refine `git checkout -m` behavior when autostash is involved by visually separating autostash conflict advice from the branch-switch confirmation message, eliminating visual clutter without altering the underlying conflict resolution logic. The series also correctly distinguishes between true conflicts and other failures during stash application, and aligns exit codes with Git’s established conventions (exit code 1 for conflicts, other non-zero values for errors).

Current status
v4 posted, incorporating all final mechanical adjustments. The series is split into two patches: (1) exit code convention alignment for `git stash apply`/`pop`/`branch` via a new `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`), and (2) advice formatting in `git checkout -m` that adds a blank line to stderr when autostash conflicts occur (`STASH_APPLY_CONFLICT`). All prior review feedback is addressed, including exit code conventions (1 for conflicts, 128 or other non-zero for errors), conflict detection correctness, API design, and test coverage. Junio C Hamano and Phillip Wood have explicitly resolved all design questions. The series is uncontroversial and ready for merging.

Key technical details
- Files touched: `sequencer.c`/`sequencer.h` (return-value semantics and conflict detection logic), `builtin/checkout.c` (advice formatting and error messages), `builtin/stash.c` (exit code handling), `stash.h` (new `enum stash_apply_result` definition: `STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`), `Documentation/git-stash.adoc` (exit code documentation), and tests (`t/t3903-stash.sh`, `t/t7201-co.sh`).
- New behavior: `apply_save_autostash_oid()` and `apply_save_autostash_ref()` return `enum stash_apply_result` instead of `int`. Callers in `checkout.c` print a blank line to stderr when the return value is `STASH_APPLY_CONFLICT`, and a new error message (e.g., "could not apply autostash") for `STASH_APPLY_ERROR`. The conflict detection logic distinguishes between `ret == 1` (conflict, exit code 1), `ret > 1` or negative (error, exit code 128 or other non-zero), and `ret == 0` (success, exit code 0). Exit code documentation in `git-stash.adoc` is updated to reflect this convention.
- Symbols: `apply_save_autostash_oid()`, `apply_save_autostash_ref()` (return type changed to `enum stash_apply_result`), `run_command()` (return value handling adjusted per Junio’s accepted suggestion), `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`).
- Test coverage: updated tests in `t/t3903-stash.sh` and `t/t7201-co.sh` use `test_cmp` to validate the full screen output, including the new blank line for conflicts and the new error message for non-conflict failures. Tests cover all three return states and now include `stash branch` coverage. The unnecessary commit in `t3903-stash.sh` has been removed.
- Code clarity: the nested ternary operator in `do_apply_stash()` and odd indentation in function signatures have been addressed. The redundant `STASH_APPLY_ERROR` assignment in one error path has been removed.

Open questions and loose ends
None. All design and mechanical issues are resolved. The series is ready for merging.
