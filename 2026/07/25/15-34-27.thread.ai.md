Subject: [PATCH 0/2] checkout -m: refine autostash conflict handling
Series version: v2 (consolidated single patch)
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Refine `git checkout -m` behavior when autostash is involved by visually separating autostash conflict advice from the branch-switch confirmation message, eliminating visual clutter without altering the underlying conflict resolution logic.

Current status
Under review; v2 posted as a single patch. Junio C Hamano’s prior conditional acceptance of the uncontroversial advice-formatting portion is now satisfied: the v2 patch repurposes the return value of `apply_save_autostash_oid()` and `apply_save_autostash_ref()` to encode three states (success 0, error -1, conflict 1), removing the contested `conflicted` output parameter. The fast-path optimization (skipping autostash retry when no tracked changes exist) has been dropped entirely, addressing Phillip Wood’s performance concern. Phillip Wood’s endorsement of the advice-formatting improvement ("a good idea") and his suggestion to use `test_cmp` for output validation have both been incorporated. No new objections have been raised; the patch is now a pure UX change with no API or performance disputes.

Key technical details
- Files touched: `sequencer.c` (return-value semantics), `builtin/checkout.c` (advice formatting), `t/t7201-co.sh` (test validation).
- New behavior: `apply_save_autostash_oid()` and `apply_save_autostash_ref()` return 1 on conflict, 0 on success, -1 on error. Callers in `checkout.c` print a blank line to stderr when the return value is 1, visually separating conflict advice from the branch-switch confirmation.
- Symbols: `apply_save_autostash_oid()`, `apply_save_autostash_ref()` (return value now encodes three states).
- Test coverage: updated test in `t/t7201-co.sh` uses `test_cmp` to validate the full screen output, replacing the prior multi-grep approach.
- Base commit: `c73e85354c275c9d409b26445089bc16940fc527` on `master`.

Open questions and loose ends
None. The API design and performance concerns from v1 have been resolved by dropping the fast-path optimization and repurposing the return value. The patch is now uncontested and ready for integration.
