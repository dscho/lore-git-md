This thread is about Pablo Sabater’s Google Summer of Code project to extend `git cat-file --batch-command` with support for the `%(objecttype)` placeholder in remote-object-info queries. The series, now at version 2, is a follow-up to Eric Sunshine’s recently merged work and aims to provide the last piece of metadata guaranteed to match between client and server after a fetch.

The v2 series consists of six patches and addresses all review feedback from the first iteration. The key changes include reordering the patches for better clarity, fixing test portability issues, and unifying the default format string for both local and remote queries to `%(objectname) %(objecttype) %(objectsize)`. The patches touch the server’s capability advertisement, client request logic, protocol extension, and client-side parsing, ensuring end-to-end support for object type metadata. Junio C Hamano’s recent review of the first patch confirmed its correctness, tracing the data flow to validate that the dynamic request logic safely handles only server-supported options. All prior feedback from Chandra Pratap, Karthik Nayak, and others has been incorporated, and the series is now complete and ready for maintainer consideration.

The work is narrowly scoped to object type, with other metadata like disk size or delta base explicitly excluded as unreliable. The implementation is backward-compatible, dynamically including all supported options in client requests, and the server transmits type data as a string (e.g., `"blob"`, `"tree"`), which the client maps to an internal enum. Tests in `t5701` and `t1017` verify the server’s handling of type requests and the client’s parsing of the response, including edge cases like unsupported placeholders. No open questions remain, and the optional robustness test for malformed server responses has been deferred. The series is now awaiting Junio’s merge decision.
