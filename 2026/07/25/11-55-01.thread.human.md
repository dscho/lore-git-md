This GSoC feature series, now at version 3, extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote-object-info queries. The work is led by Pablo Sabater and builds directly on Eric Sunshine's recently merged batch-command infrastructure. The goal is to provide object type metadata—the last piece of metadata guaranteed identical between client and server after a fetch—while explicitly excluding unreliable fields like disk size or delta base.

The series has undergone significant refactoring since its first iteration. After Junio and Peff proposed a hybrid design to avoid sentinel values and boolean flags, Pablo implemented a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests. This replaces the earlier `struct object_info` approach and aligns with the protocol's transmission of raw strings. The current version (v3) addresses all prior review feedback, including a robustness fix in patch 2 that prevents uninitialized data from being used if the server sends fewer object-info lines than requested. The latest patch (3/8) is a mechanical cleanup that removes an intermediate struct, making the API surface clearer ahead of the full architectural shift in patch 4.

Key participants—Junio, Peff, and Chandra Pratap—have provided substantive feedback, with Junio and Peff refining the design and Chandra contributing test improvements. The series is under active review, with no merge status reported yet. The GSoC deadline is approaching, adding urgency to the finalization process. Testing has been expanded in `t5701` and `t1017`, covering both server-side capability advertisement and client-side parsing. The only remaining loose end is architectural finalization, though the current design is now implemented and no further changes are expected unless new feedback emerges.
