This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder when querying remote repositories, completing the last piece of metadata guaranteed to be identical between client and server after a fetch. The series is now at v2, with all review feedback addressed, and consists of six patches that implement server capability advertisement, client request logic, protocol extension, and client-side parsing.

The key change in this final patch unifies the default output format for both local and remote queries to `%(objectname) %(objecttype) %(objectsize)`, removing a temporary workaround from Eric Sunshine’s earlier series. The update touches documentation, the protocol specification, and test cases to reflect this consistency. Earlier patches in the series reordered the patch flow for clarity, fixed test portability issues, and taught both client and server to handle the "type" capability dynamically. Reviewers Junio C Hamano, Chandra Pratap, and Karthik Nayak provided feedback on style, test design, and scope, all of which has been incorporated.

The series is now complete and ready for maintainer consideration, with no open questions or loose ends. It builds directly on the recently merged remote-object-info functionality and is narrowly scoped to object type metadata, avoiding less reliable fields like disk size or delta base.
