This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to be identical on client and server after a fetch. The series is now at v2, with six patches addressing all prior review feedback, and is ready for maintainer consideration.

Junio C Hamano has reviewed the first four patches, confirming their correctness and removing any doubt about their safety. The series is complete, with key changes in v2 including reordered patches for clarity, a test portability fix, server-side type handling, client-side type parsing, server capability advertisement, and a unified default format string. The only remaining feedback is advisory: Junio suggests improving the commit message for the test portability fix (patch 2) and proposes a design cleanup for patch 4’s memory allocation strategy, replacing pointer indirection with bitfields to eliminate heap allocation overhead. Pablo has addressed all other review comments, including Chandra Pratap’s shell quoting nit and Karthik Nayak’s style adjustments.

The series touches `protocol-caps.c`, `fetch-object-info.c`, `serve.c`, and related documentation and test files, adding the "type" capability to the protocol and unifying the default format string for local and remote queries. No on-disk format changes are involved. The implementation is narrowly scoped to object type metadata, with other metadata (disk size, delta base, object mode) explicitly ruled out as unreliable or context-dependent. The series is based directly on Eric Sunshine’s recently merged v21 series and has no external dependencies. All substantive review feedback has been incorporated, and the series awaits Junio’s merge decision.
