This GSoC feature patch series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to match between client and server after a fetch. The series is now at version 4 with nine patches, addressing all prior review feedback and incorporating robustness fixes.

The architectural refactoring replaces the older `struct object_info` with a dedicated `struct fetch_object_info_results` that holds only the requested fields (size and type), avoiding sentinel values and boolean flags. This design aligns with the protocol’s transmission of raw strings like `"blob"` or `"1234"`. Key improvements in v4 include moving the `ask_type` flag to the client-side parsing patch to avoid premature capability handling, adding checks for both under-length and over-length server responses, and explicitly noting the robustness benefits of test cleanups.

Junio and Peff had previously refined the design to use a single array of lightweight structs where the caller controls which fields are populated. All substantive review feedback—including protocol hygiene, error handling, and commit message clarity—has been addressed. The series is feature-complete, merge-ready, and rebased onto `master` following the merge of its predecessor (Eric Sunshine’s `ps/cat-file-remote-object-info`). Tests in `t5701` and `t1017` verify the new functionality, including edge cases like duplicate OIDs and unsupported placeholders. No open technical questions remain.
