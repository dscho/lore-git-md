This GSoC feature series extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the metadata picture after Eric Sunshine's recently merged v21 series. The work is now at v2, with all prior review feedback addressed and only a minor memory-allocation suggestion from Junio remaining.

The series teaches both client and server to handle object type metadata, which is the last piece of metadata guaranteed identical on both sides after a fetch. Pablo Sabater's implementation covers capability advertisement, protocol extension, client request logic, and parsing, while keeping the scope strictly to object type (other metadata like disk size or delta base is explicitly excluded as unreliable). Junio has already reviewed the first three patches, confirming their correctness, and the remaining three are uncontroversial. The only open item is Junio's suggestion to simplify memory allocation in patch 4 by using a single contiguous block for `typep` pointers instead of per-object `xcalloc` calls—an internal cleanup that doesn't affect functionality.

The series is complete and ready for maintainer consideration, with tests expanded in `t5701` and `t1017` to verify the new placeholder works across all transport protocols. Pablo has addressed every piece of feedback from v1, including patch reordering for clarity and test portability fixes, and the code now matches the established patterns from Sunshine's merged work. Once the memory-allocation tweak is made, there are no remaining technical objections.
