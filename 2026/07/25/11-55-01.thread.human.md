This thread is about Pablo Sabater’s Google Summer of Code project to extend `git cat-file --batch-command` with the `%(objecttype)` placeholder, allowing clients to request object type metadata from a server via the remote-object-info protocol. The series is now at version 2, with six patches that address all prior review feedback, but the architectural core is still under discussion.

The key debate centers on how to store batch results in `fetch-object-info.c`. Junio C Hamano and Jeff King (Peff) have converged on a hybrid design: a single array of lightweight structs where the caller decides which fields to populate, avoiding sentinels entirely. This approach bypasses the older `struct object_info` and aligns with the protocol’s transmission of raw strings like `"blob"` or `"1234"`. Junio’s latest email confirms that while sentinel values like `OBJ_NONE` work for object types, they don’t extend cleanly to other fields such as size, reinforcing the hybrid design as the way forward. Pablo has not yet responded to this refinement, but the GSoC deadline is approaching, and the refactoring is expected in the next revision.

Other participants have weighed in with mostly surface-level feedback—Chandra Pratap’s shell quoting nit in patch 5 is the only remaining loose end, and Pablo has already agreed to fix it. The series touches `protocol-caps.c`, `fetch-object-info.c`, `serve.c`, and `builtin/cat-file.c`, adding the "type" capability to the protocol and the `%(objecttype)` placeholder to the client’s batch-command format. No merge decision has been made, and the code is still under review.
