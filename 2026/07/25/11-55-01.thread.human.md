This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder when querying object metadata from a remote server. The series, now complete at five patches, builds directly on Eric Sunshine's recently merged remote-object-info work, adding the last piece of metadata guaranteed to match between client and server after a fetch.

The core change is straightforward: the server now advertises a "type" capability, the client dynamically requests it alongside "size" (the only previously supported option), and the protocol transmits the object type when requested. The final patch unifies the default format string so that both local and remote queries display object name, type, and size, removing a temporary workaround that excluded type from remote queries. Tests and documentation have been updated throughout to reflect the new behavior.

No substantive reviews have appeared yet, but the implementation follows the established pattern from the predecessor series and appears mechanical. The series is narrowly scoped to object type, with other metadata (disk size, delta base, object mode) explicitly ruled out as unreliable or context-dependent. CI passed on GitHub, and the patches touch the expected files—protocol handling, client logic, documentation, and tests—without introducing new loose ends.
