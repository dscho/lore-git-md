This GSoC feature series from Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to match between client and server after a fetch. The nine-patch v4 series is now feature-complete and under final review, with all architectural decisions settled and prior feedback incorporated.

The core change replaces Git’s object-info handling with a cleaner design: a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests (currently size and type), avoiding sentinel values and boolean flags. This refactoring, endorsed by Junio and Peff, replaces the older `struct object_info` approach and aligns with the protocol’s transmission of raw strings like `"blob"` or `"1234"`. The series also adds robustness checks to fail fast if servers violate protocol invariants (e.g., sending too few or too many responses) and unifies the default format across all batch commands.

Junio’s latest feedback on the fourth patch was purely advisory, noting the removal of redundant code (like `remote_atom_map[]`) and questioning why "type" appeared in an allow-list before its implementation. Pablo’s response clarified this was harmless forward-compatibility, and the patch remains uncontroversial. The remaining patches (5–9/9) implement the server-side capability advertisement, client parsing, and test updates, with no open technical questions. The series is now merge-ready, pending Junio’s final review of the later patches.
