This GSoC patch series extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote-object-info queries, completing the metadata picture after Eric Sunshine's recently merged v21 series. The work is now at v1, with all review feedback addressed and a v2 planned to reorder patches for better narrative flow.

The series adds end-to-end support for object type metadata, which is the last piece guaranteed identical between client and server after a fetch. Key changes include server capability advertisement, dynamic client request logic, protocol extension, and client-side parsing/display. The default format string in `cat-file` is now unified to `%(objectname) %(objecttype) %(objectsize)` for both local and remote queries. Tests have been expanded to cover the new functionality, with portability improvements like replacing `wc -c` with Git's `test_file_size` helper.

The only remaining discussion centers on a safety concern in patch 2, where Chandra Pratap raised a potential out-of-bounds array access during server response parsing. Pablo Sabater clarified that the existing code is safe due to built-in constraints, but agreed to add a test simulating a malicious server response for robustness. Junio has weighed in on minor style and test portability issues, while Chandra's review has been thorough but constructive, focusing on code quality and test coverage rather than core functionality. The series appears ready for maintainer consideration once the v2 reordering is posted.
