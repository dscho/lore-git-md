This ten-patch GSoC series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to be identical on client and server after a fetch. The series is now at version 6, addressing a static-analysis warning from CI, and all review feedback has been incorporated. Junio has explicitly endorsed all ten patches as ready to merge, and the series is poised for integration.

The implementation adds end-to-end support for object type metadata: the server advertises the "type" capability, parses client requests for it, and transmits type data as a string (e.g., `"blob"`). The client maps this string to an internal enum and displays it in batch-command output. The default format for all queries is now unified as `%(objectname) %(objecttype) %(objectsize)`, ensuring consistent output across all transport protocols. The series touches a handful of files—primarily `fetch-object-info.c`, `builtin/cat-file.c`, and protocol documentation—and expands test coverage in `t5701` and `t1017` to verify the new functionality.

Key participants include Junio, who refined the design with Jeff King (Peff) into a hybrid approach using a single array of lightweight structs where the caller controls which fields are populated, and Peff, who contributed a mechanical refactoring (patch 6/10) to improve the transport layer’s object-info handling. Chandra Pratap and Karthik Nayak provided surface-level feedback that was addressed in earlier versions. Pablo has implemented all review feedback, including robustness fixes for under-length and over-length server responses, and deferred Peff’s suggestion for a stateful protocol optimization to a follow-up series. The series is feature-complete, with no open questions or loose ends.
