This GSoC thread is extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote-object-info queries, completing the metadata picture after Eric Sunshine’s recently merged series. Pablo Sabater’s v2 patch series—now six patches strong—has addressed all prior review feedback, including Junio’s and Chandra Pratap’s latest nits, and is ready for maintainer consideration. The goal is narrowly scoped: add end-to-end support for object type metadata, which is the last piece guaranteed identical on client and server after a fetch.

The series is under active review, with no merge decision yet. Junio has confirmed the correctness of the first four patches (dynamic request logic, test portability fix, server-side type handling, and client-side parsing), removing any doubt about their safety. However, Jeff King (Peff) has raised a clear architectural concern: the remote-object-info path should bypass `struct object_info` entirely and define its own lightweight query structure, using simple boolean flags to declare what metadata it needs, then parse the server’s response directly into `expand_data`, the cat-file-specific struct. Junio’s latest email reinforces this recommendation, clarifying that `object_info` was never designed for batch queries and that reusing it for remote-object-info is a conceptual mismatch. Pablo has not yet responded to this feedback, and the series may require significant adjustments to the client-side parsing logic in `fetch-object-info.c` and `builtin/cat-file.c`.

The remaining loose end is the architectural refactor to avoid `object_info` for the remote path. Once that is addressed, the series should be ready for maintainer pickup. All other feedback—including Chandra Pratap’s shell quoting nit and Junio’s advisory suggestions—has been incorporated or acknowledged. The test suite has been expanded to cover the new functionality, and the default format string is now unified for both local and remote queries. Key participants include Junio, Peff, Chandra Pratap, and Karthik Nayak, with no objections to the core functionality.
