This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to be identical on client and server after a fetch. The series is now fully implemented in its fifth iteration (ten patches) and has been declared merge-ready by Junio Hamano after addressing all review feedback.

The core change enables end-to-end object type metadata support: the server advertises the "type" capability, parses client requests for it, and transmits type data as a string (e.g., `"blob"`), while the client maps this to an internal `enum object_type` and displays it in batch-command output. The implementation avoids sentinel values and boolean flags by using a hybrid design—a single array of lightweight structs where the caller controls which fields are populated. Key architectural improvements include Jeff King’s refactoring to clarify ownership semantics in the transport layer and Pablo’s robustness fixes to validate server response lengths and fail fast on protocol violations.

The final patch (10/10) unifies the default format for all queries to `%(objectname) %(objecttype) %(objectsize)`, removing a temporary workaround and ensuring consistent output across local and remote queries. Documentation and tests have been updated to reflect the new functionality, with expanded coverage in `t1017` verifying the placeholder works as expected. All prior concerns—from protocol hygiene to premature flag introduction—have been resolved, and the series has received explicit endorsements for integration from Junio. The feature is narrowly scoped to object type, with other metadata (disk size, delta base) explicitly ruled out as unreliable.
