This GSoC feature series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries is now complete and ready for integration. The series, authored by Pablo Sabater, has reached version 6 with all ten patches explicitly endorsed by Junio C Hamano as ready to merge. The final iteration addressed a static-analysis warning identified in CI for v5, incorporating forward declarations and a minor whitespace fix.

The feature enables clients to request and display object type metadata from servers via the remote-object-info protocol, matching the behavior of local queries. The implementation is narrowly scoped to object type, with other metadata (disk size, delta base, object mode) explicitly excluded as unreliable or context-dependent. Key changes include server capability advertisement, client request logic, protocol extension, and client-side parsing/display. The series also unifies the default format for all `cat-file` batch commands, removing a temporary workaround and ensuring consistent output across all transport protocols.

All review feedback has been addressed, including robustness fixes for protocol hygiene (validating under-length and over-length responses), mechanical refactorings to clarify ownership semantics in the transport layer, and design refinements to avoid sentinel values and boolean flags. Participants including Junio, Jeff King (Peff), Chandra Pratap, and Karthik Nayak have reviewed the series, with Chandra’s latest reply serving as a procedural endorsement of the series’ readiness. The series is based on Eric Sunshine’s recently merged "cat-file: add remote-object-info to batch-command" work and touches files in the protocol, transport, and builtin subsystems, with expanded test coverage in `t5701` and `t1017`. No open questions or loose ends remain.
