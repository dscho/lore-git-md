This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to match between client and server after a fetch. The series is now at version 2, with all review feedback from the initial submission addressed, and is ready for maintainer consideration.

The key change in this update is a refactoring of the client request logic to dynamically include all supported options (currently "size" and "type") rather than hardcoding "size" alone. This prepares the codebase for the new "type" capability while maintaining backward compatibility, as the list of options is already filtered to only those advertised by the server. The series also improves test portability, unifies the default format string for local and remote queries, and clarifies documentation to reflect the new functionality.

Reviewers—Junio C Hamano, Chandra Pratap, and Karthik Nayak—raised only advisory feedback in the first version, focusing on style, test design, and documentation wording. All points were incorporated in this revision, including patch reordering for better narrative flow and a fix for a test portability issue. The series is now complete, with no open questions or loose ends, and touches files in the protocol, fetch-object-info, and cat-file subsystems. The only deferred item is an optional robustness test for malformed server responses, which is not considered a blocker.
