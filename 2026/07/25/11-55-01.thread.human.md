This GSoC feature patch series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder, allowing clients to request object type metadata from servers via the remote-object-info protocol. The series builds directly on Eric Sunshine's recently merged v21 work, which introduced remote-object-info but omitted object type—the last piece of metadata guaranteed to match between client and server after a fetch.

The five-patch v1 series is currently under review, with no substantive feedback yet. The second patch (this update) prepares the client to parse the "type" field from server responses by adding storage and tracking logic in `fetch-object-info.c`, though the server won't advertise the capability until patch 1 lands. The changes are mechanical, following the established pattern from Sunshine's series, and include test coverage in `t1017` and `t5701`. No open questions or design objections have surfaced so far, and CI passed on GitHub. The series touches protocol capabilities, client request logic, and documentation, but leaves on-disk formats unchanged.
