This GSoC patch series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the metadata picture after Eric Sunshine’s recently merged v21 series. The goal is narrow: add object type metadata (the last piece guaranteed identical on client and server after a fetch) while explicitly excluding unreliable or context-dependent fields like disk size or delta base.

The series is now complete at v1, with five patches addressing all prior review feedback. Key changes include adding the "type" capability, extending the protocol to transmit type data, unifying the default format string for local and remote queries, and updating test coverage. Chandra Pratap’s review has been constructive, focusing on code quality, test design, and documentation clarity—no objections block progress. Pablo has accepted all minor improvements, including restructuring the `t1017` test in patch 4 to better separate concerns (verifying supported vs. unsupported placeholders). One open question remains: whether to add a test simulating a malicious server response to validate robustness against malformed input, though the current code is technically safe. The series is under review, with no maintainer decision yet.
