This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote object queries, completing the last piece of metadata guaranteed to match between client and server after a fetch. The v2 series is now complete, addressing all review feedback from Junio C Hamano, Chandra Pratap, and Karthik Nayak. The six patches cover server capability advertisement, client request logic, protocol extension, and client-side parsing, with test coverage expanded in both server-side (`t5701`) and client-side (`t1017`) test scripts.

Junio has reviewed the first four patches, confirming their correctness and removing safety concerns about the dynamic request logic. The only remaining technical feedback involves a preparatory patch to simplify memory allocation for `object_info_data[j].typep` by using a single contiguous block, which Pablo plans to implement. Chandra’s latest nit—a shell quoting best practice in the test suite—has been acknowledged and will be incorporated. The series is now ready for Junio’s merge decision, with no open objections or unresolved technical concerns. The default format string for `cat-file` queries has been unified to include object type for both local and remote queries, removing a temporary workaround from the predecessor series.
