This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to match between client and server after a fetch. The five-patch v1 series is now complete and under review, with all patches posted.

The implementation adds server capability advertisement, client request logic, protocol extension, and client-side parsing/display for object type metadata. Key changes include unifying the default format string for local and remote queries (now `%(objectname) %(objecttype) %(objectsize)`), generalizing client request logic to dynamically include all supported options, and updating test coverage in `t1017` and `t5701`. The series builds directly on Eric Sunshine’s recently merged v21 remote-object-info work, maintaining its narrow scope by excluding unreliable metadata like disk size or delta base.

Chandra Pratap’s review has raised two technical points so far. The first, on patch 1, noted a minor style nit in an error message and a test portability issue (using `wc -c` instead of Git’s `test_file_size` helper). The second, on patch 2, identified a potential out-of-bounds array access in the parsing logic that could cause a segmentation fault if the server sends malformed data. This latter concern is substantive but narrowly scoped to robustness, and the reviewer suggested adding a bounds check and a test for graceful failure. No fundamental objections have been raised, and the series remains under review with these improvements likely to be addressed in a future revision.
