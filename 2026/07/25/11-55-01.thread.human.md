This thread is the fourth iteration of Pablo Sabater’s GSoC patch series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The goal is to let clients request and display object type metadata from the server, completing the last piece of metadata guaranteed to match between client and server after a fetch. The series is now feature-complete and under review, with all prior feedback addressed.

The key architectural change in v4 replaces the old `struct object_info` with a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests (currently size and type). This avoids sentinel values and boolean flags, using a single array of lightweight structs where the caller controls which fields are populated. Junio and Peff refined this design, confirming that sentinel values like `OBJ_NONE` don’t work cleanly for fields like `size` and that a separate bit is better for signaling unknown objects. Pablo implemented this in v4, along with robustness fixes: the client now `die()`s if the server sends fewer or more object-info lines than requested OIDs, or an invalid type string, addressing Junio’s protocol hygiene concerns.

The series touches `fetch-object-info.c`, `builtin/cat-file.c`, and related files, introducing the "type" capability in the protocol and the `%(objecttype)` placeholder. Tests in `t5701` and `t1017` verify the new functionality, including consistent output across all transport protocols.
