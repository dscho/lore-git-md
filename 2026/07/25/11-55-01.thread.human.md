This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to be identical on client and server after a fetch. The series is now at version 6 (ten patches) and is ready for integration, with all review feedback addressed and Junio having explicitly endorsed all patches as ready to merge.

The implementation adds end-to-end support for object type metadata: the server advertises the "type" capability, parses client requests, transmits type data as a string (e.g., `"blob"`), and the client maps this to an internal enum. The default format for all `cat-file` batch commands has been unified to `%(objectname) %(objecttype) %(objectsize)`, ensuring consistent output across all transport protocols. Key technical changes include a hybrid design using lightweight structs with caller-controlled field population, robustness fixes for protocol hygiene (validating under-length and over-length responses), and a mechanical refactoring by Jeff King (Peff) to clarify ownership semantics in the transport layer.

The series touches a focused set of files (`serve.c`, `protocol-caps.c`, `fetch-object-info.c`, `builtin/cat-file.c`, and test files) and introduces new symbols like the "type" capability and `%(objecttype)` placeholder. Test coverage has been expanded to verify the new functionality, including edge cases like duplicate OIDs and unsupported placeholders. A potential optimization to make the protocol stateful for connection reuse was discussed but deferred to a follow-up series. The work builds directly on Eric Sunshine’s recently merged `remote-object-info` series and is now feature-complete.
