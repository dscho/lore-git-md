This GSoC feature series, now at version 6, extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to be identical on client and server after a fetch. The series is feature-complete and ready for integration, with all ten patches explicitly endorsed by Junio as ready to merge. Pablo Sabater has addressed all review feedback, including a static-analysis warning in v5 that prompted the v6 update, and the series now includes Jeff King’s (Peff) refactoring to improve the transport layer’s object-info handling by clarifying ownership semantics and eliminating a latent bug.

The implementation adds end-to-end support for object type metadata: the server advertises the "type" capability, parses client requests for it, and transmits type data as a string (e.g., `"blob"`), while the client maps this to an internal enum and displays it via the `%(objecttype)` placeholder. The default format for all `cat-file` batch commands is now unified as `%(objectname) %(objecttype) %(objectsize)`, ensuring consistent output across all transport protocols. The series touches a handful of files—primarily `fetch-object-info.c`, `builtin/cat-file.c`, and protocol documentation—and expands test coverage to verify the new functionality. Junio’s latest email confirms the series is ready for integration, marking the final procedural step before it is queued. The only deferred work is Peff’s suggestion to make the `remote-object-info` protocol stateful for connection reuse, which would be a future optimization.
