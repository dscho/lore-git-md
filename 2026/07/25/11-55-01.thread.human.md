This GSoC feature series by Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to be identical on client and server after a fetch. The series is now at version 4, feature-complete, and under active review.

The core work replaces the previous `struct object_info` with a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests, avoiding sentinel values and boolean flags. This design, refined by Junio and Peff, uses a single array of lightweight structs where the caller controls which fields are populated. All prior review feedback has been addressed, including architectural refactoring, protocol robustness fixes, and test updates. The series now includes end-to-end support for object type metadata: server capability advertisement, client request logic, protocol extension, and client-side parsing/display.

Junio’s latest review endorses a robustness patch that tightens protocol hygiene by ensuring the server sends exactly the expected number of object-info lines. This prevents both under-length and over-length responses, aligning with Git’s defensive programming practices. The series is now merge-ready, with all tests passing and no open technical concerns. The only remaining loose ends are minor—commit message clarifications and advisory feedback—none of which block integration. Key participants (Junio, Peff, Chandra Pratap, and Karthik Nayak) have all weighed in, with their feedback fully incorporated.
