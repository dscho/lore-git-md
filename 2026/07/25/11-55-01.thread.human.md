This nine-patch GSoC series from Pablo Sabater extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries, completing the last piece of metadata guaranteed to be identical on client and server after a fetch. The series is now at v4, feature-complete, and ready for integration.

The core change replaces the temporary workaround that used a different default format for remote queries with a unified default—`%(objectname) %(objecttype) %(objectsize)`—across all `cat-file` batch commands. This final patch updates documentation and tests to reflect the new behavior, ensuring consistent output regardless of transport protocol. Earlier patches in the series refactored the underlying architecture, replacing `struct object_info` with a dedicated `struct fetch_object_info_results` that avoids sentinel values and boolean flags, and added robustness checks to fail fast if the server violates protocol invariants. Junio and Peff’s design feedback has been fully incorporated, and all prior review comments—including surface-level nits from Karthik Nayak and Chandra Pratap—have been addressed.

The series is uncontroversial and merge-ready, with no open technical questions. It builds directly on Eric Sunshine’s recently merged `remote-object-info` work and touches `protocol-caps.c`, `fetch-object-info.c`, `serve.c`, and `builtin/cat-file.c`, along with test updates in `t5701` and `t1017`. The new functionality is backward-compatible and enables clients to request and display object type metadata from the server, matching local queries.
