This is the first patch in Tian Yuchen’s three-part series migrating four global configuration variables into `repo_config_values` as part of the ongoing `the_repository` removal effort. It handles `minimum_abbrev` and `default_abbrev`, the two variables that control how Git abbreviates object IDs.

The patch introduces repository-aware getters (`repo_minimum_abbrev()` and `repo_default_abbrev()`) and moves the variables into the `repo_config_values` struct. The existing `MINIMUM_ABBREV` and `DEFAULT_ABBREV` macros are redefined to call these getters, ensuring backward compatibility while allowing code paths that explicitly avoid `the_repository` (such as `merge-ort`) to access the values safely. The getters include explicit checks for `repo != the_repository`, redirecting to `the_repository` when necessary.

Files touched include `environment.c`/`environment.h` (the central location for these variables), `merge-ort.c`, `object-name.h`, `replay.c`, and `sequencer.c`. The changes are mechanical but require careful attention to repository parameter passing, particularly in `merge-ort.c`, which forbids direct use of `the_repository`. No behavior change is intended, and the patch is positioned as infrastructure for future libification.

The patch is well-structured and aligns with the broader `the_repository` removal effort. It builds directly on prior `repo_config_values` work and is likely uncontroversial, though reviewers may scrutinize the repository parameter handling in edge cases. Existing tests should suffice for coverage, given the mechanical nature of the changes.
