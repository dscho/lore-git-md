This is a bugfix patch from Junio C Hamano that plugs memory leaks in Git's URL alias handling. It is a revised version of an earlier patch, now addressing feedback about safety and consistency with the rest of the codebase.

The patch fixes the `rewrites_release()` function in `remote.c` to properly free all memory associated with the `struct rewrites` data structure, which tracks URL alias settings like `url.<real>.insteadOf` and `url.<real>.pushInsteadOf`. The previous implementation missed freeing several nested allocations: the contiguous array storing `.instead_of` entries, the string pointers within each `.instead_of` element, and the individual `struct rewrite` instances. The new version iterates through each rewrite rule, frees all nested allocations, and then frees the rewrite instance itself.

Junio initially attempted to avoid copying configuration strings (the alias URLs) by relying on the configset subsystem to keep them alive, but discovered this assumption was not safe—most existing code makes copies instead. The revised patch follows this safer pattern, freeing all string copies rather than assuming borrowed strings remain valid. This change makes the code slightly less efficient but more robust.

The patch is minimal (9 insertions, 2 deletions) and focused solely on `remote.c`. It does not change behavior beyond plugging the leaks, which were exposed by recent tests in Emily Shaffer's `en/submodule-insteadof-remote-match` series. CI results for the first version were clean, and a follow-up run with an unrelated topic re-merged is pending.
