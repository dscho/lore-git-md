Core problem or goal: Extend the recently merged `git cat-file --batch-command` remote-object-info functionality to include object type metadata, the last piece of metadata guaranteed to be identical on client and server after a fetch. Series is at v3, feature-complete, with all prior review feedback addressed and the architectural refactoring finalized. The refactoring replaces `struct object_info` with a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests (currently size and type), avoiding sentinel values and boolean flags. The design uses a single array of lightweight structs where the caller controls which fields are populated, aligning with the remote-object-info protocol’s transmission of raw strings (e.g., `"blob"`, `"1234"`).
