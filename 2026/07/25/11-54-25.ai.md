This is part of the ongoing `the_repository` removal effort. The series migrates three more global configuration variables (`minimum_abbrev`, `default_abbrev`, `pack_size_limit_cfg`, and `assume_unchanged`) into `repo_config_values`, making them repository-scoped rather than process-global. The patches touch `environment.c`/`environment.h` as the central location for these variables, with callers in `builtin/pack-objects.c`, `builtin/update-index.c`, `merge-ort.c`, `object-file.c`, `read-cache.c`, `replay.c`, and `sequencer.c` updated to use the new repository-aware getters.

The cover letter highlights a key constraint: some subsystems (notably `merge-ort`) explicitly forbid use of `the_repository` and only accept an explicit `repo` parameter, so the new getters must handle the case where `repo != the_repository`. This is implemented via explicit checks in the getters. The series is a direct continuation of prior work on `repo_config_values` and is motivated by the broader goal of eliminating implicit reliance on the global `the_repository`.

Patch 1/3 handles the two abbreviation-related variables, patch 2/3 moves `pack_size_limit_cfg`, and patch 3/3 migrates `assume_unchanged`. The changes are mechanical but require careful attention to the repository parameter passing, especially in code paths that previously assumed `the_repository`. No behavior change is intended, and the series is positioned as infrastructure for future libification.
