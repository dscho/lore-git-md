This is a follow-up in the ongoing discussion about Ted Nyman’s v4 patch series fixing race conditions in Git’s HTTP transport for packfile URI downloads. Jeff King (Peff) continues diagnosing the intermittent `--stress` test failure in `t5550-http-fetch-dumb.sh` (test 34), which has blocked the series from progressing.

Peff now identifies the root cause of the flakiness: the test’s synchronization logic is flawed. The test relies on `test -s` to check whether the first 1MB of data has been written to the temporary file by the client, but this check is racy—there’s no guarantee the data has actually been flushed to disk by the time the server signals it has sent the bytes. The server’s `write()` call doesn’t ensure the client has received or persisted the data, making the test’s timing assumptions unreliable. Peff suggests dropping the `test -s` check entirely, arguing that the test’s symmetry (two concurrent downloads writing identical bytes) means the order in which the data arrives doesn’t matter. This would simplify the test and eliminate the race without affecting its correctness.

The email doesn’t propose a concrete fix yet, but it shifts focus from the earlier suspicion of socket-level issues (now deemed a red herring) to the test’s synchronization logic. The series remains blocked until this is resolved, but Peff’s analysis narrows the problem to a test design issue rather than a flaw in the core download logic. If the `test -s` check is removed, the test should become more robust under `--stress` without sacrificing coverage.
