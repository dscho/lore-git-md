This is a **substantive review follow-up** from Jeff King (Peff) on Ted Nyman’s v4 series fixing packfile URI download race conditions. Peff digs deeper into the intermittent `--stress` test failure in `t5550-http-fetch-dumb.sh` (test 34) and uncovers a puzzling early EOF on the HTTP connection.

The core observation: curl’s client-side strace shows an unexpected EOF (`recvfrom` returns 0) while the server process remains alive and has not closed its socket. This suggests the connection is being dropped somewhere in the network stack, not by either endpoint. Peff speculates that the custom Perl server’s socket handling might be the culprit and floats the idea of rewriting the test to use Apache, like the rest of Git’s HTTP tests, to eliminate this class of bugs.

The series remains **blocked** on this test flakiness; no code changes are proposed here, only diagnostic findings. The next step is likely either a deeper dive into the Perl server’s socket behavior or a rewrite of the test to use Apache. Until this is resolved, the topic will not progress to `next`.
