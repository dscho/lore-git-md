This is a **substantive review** from Jeff King (Peff) on Ted Nyman’s v4 packfile URI race-condition series, focusing on a **remaining race condition** in the test suite that causes intermittent failures under `--stress` testing.

Peff reports that roughly half of the `--stress` runs of `t5550-http-fetch-dumb.sh` fail immediately, even with the v4 series applied. The failure occurs in test 34, specifically at the `test -s $tmpfile` check, indicating that the test expects a file to exist but it does not. The pack appears to have been indexed by the time the failure is observed, suggesting the issue is not with the core download logic but with the test’s synchronization or timing.

The root cause appears to be a premature hangup on the first HTTP connection: curl reports “end of response with 1048917 bytes missing” and closes the connection before the server has finished sending data. The server process, however, behaves identically in both success and failure cases (writing “ready” to the FIFO, then waiting in `accept()`), and its strace shows no anomalies. The second connection never arrives in the failing case, likely because the test has already bailed. Peff notes that the test is designed to be deterministic using FIFOs, but the extra load from `--stress` seems to expose a latent race.

No fix is proposed in this email, but the observation narrows the problem to the interaction between the test’s custom Perl server and curl’s connection handling. The series remains **blocked** until this test flakiness is resolved, as Junio previously indicated the topic would not progress to `next` with a hanging test. The v4 changes (60-second timeout, FIFO waiter notification, reliable server cleanup) were intended to address the v3 hang, but this new failure suggests a deeper timing issue remains.
