Thread identity: `[PATCH 0/3] v2` series migrating global configuration variables (`pack_size_limit_cfg` and `assume_unchanged`) into `repo_config_values` as part of the ongoing `the_repository` removal effort. Originating author: Tian Yuchen. Thread type: patch series (infrastructure refactoring).

Core problem or goal: Eliminate process-global configuration variables by making them repository-scoped, enabling code paths that explicitly avoid `the_repository` (e.g., future libification efforts) to access them safely. The series is a continuation of prior `repo_config_values` work, motivated by the broader goal of removing implicit reliance on the global `the_repository`. The v2 scope is narrowed to two variables after Junio’s objection to the v1 design for `minimum_abbrev` and `default_abbrev`.

Current status: Under review (v2 posted). Series scope reduced to two patches, both now reviewed in principle:
- **Patch 1/2**: Migrates `pack_size_limit_cfg` from a standalone global in `environment.c` into the `repo_config_values` struct. The global variable is removed, and all direct references are updated to use the repository-specific instance. No getter function is introduced due to limited call sites (only two). Backward compatibility is maintained by accessing the value via `the_repository` in `object-file.c` (ODB transaction logic). Files touched: `builtin/pack-objects.c`, `environment.c`, `environment.h`, and `object-file.c`. The ODB transaction logic in `object-file.c` checks whether the pack size limit would be exceeded during object streaming and flushes the packfile if needed.
- **Patch 2/2**: Migrates `assume_unchanged` from `environment.h` into the `repo_config_values` struct. The global variable is removed, and all direct references are updated to use the repository-specific instance. No getter function introduced due to limited call sites and no hardcoded fallback values. Backward compatibility maintained by accessing the value via `the_repository`’s config in affected code paths. Files touched: `builtin/update-index.c`, `environment.c`, `environment.h`, and `read-cache.c`. The `core.ignorestat` configuration now directly updates `cfg->assume_unchanged`, and the `CE_VALID` flag logic in `read-cache.c` is updated to use the repository-scoped value.

Key technical details:
- Files touched: `environment.c`/`environment.h` (central location for the variables), with callers updated in `builtin/pack-objects.c`, `builtin/update-index.c`, `object-file.c`, `read-cache.c`, `replay.c`, and `sequencer.c`.
- New or renamed symbols: `repo_config_values.pack_size_limit_cfg`, `repo_config_values.assume_unchanged`. No repository-aware getters introduced for these variables.
- Subsystems affected: Configuration handling, pack-objects, index updates, replay, sequencer, and ODB transaction logic.

No new tests were proposed in the series.
