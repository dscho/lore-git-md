Thread identity: `[PATCH 0/3] v1` series migrating global configuration variables (`pack_size_limit_cfg`, `assume_unchanged`, and originally `minimum_abbrev`, `default_abbrev`) into `repo_config_values` as part of the ongoing `the_repository` removal effort. Originating author: Tian Yuchen. Thread type: patch series (infrastructure refactoring).

Core problem or goal: Eliminate process-global configuration variables by making them repository-scoped, enabling code paths that explicitly avoid `the_repository` (e.g., `merge-ort`) to access them safely. The series is a continuation of prior `repo_config_values` work, motivated by the broader goal of removing implicit reliance on the global `the_repository`.

Current status: Under review (v1 posted, v2 planned). Series scope reduced to two patches after Junio’s objection to patch 1/3’s design:
- Patch 1/3 (original): Migrated `minimum_abbrev` and `default_abbrev` into `repo_config_values` with repository-aware getters (`repo_minimum_abbrev()`, `repo_default_abbrev()`). Junio objected to the unconditional fallback to `the_repository` when `repo != the_repository`, arguing it obscured API limitations. Tian conceded and will drop these variables from the series.
- Patch 2/3: Migrates `pack_size_limit_cfg` from a standalone global in `environment.c` into the `repo_config_values` struct. All direct references updated to use the repository-specific instance. No getter function introduced due to limited call sites (only two). In `object-file.c`, a local `cfg` pointer ensures backward compatibility via `the_repository`.
- Patch 3/3: Migrates `assume_unchanged` from `environment.h` into the `repo_config_values` struct. The global variable is removed, and all direct references are updated to use the repository-specific instance. No getter function introduced due to limited call sites and no hardcoded fallback values. Backward compatibility maintained by accessing the value via `the_repository`’s config in affected code paths.

Key technical details:
- Files touched: `environment.c`/`environment.h` (central location for the variables), with callers updated in `builtin/pack-objects.c`, `builtin/update-index.c`, `object-file.c`, `read-cache.c`, `replay.c`, and `sequencer.c`. `merge-ort.c` and `object-name.h` are no longer affected after the scope reduction.
- New or renamed symbols: No repository-aware getters for `pack_size_limit_cfg` or `assume_unchanged` due to limited call sites. Implementation avoids fallbacks to `the_repository` for these variables.
- Subsystems affected: Configuration handling, pack-objects, index updates, replay, sequencer, and ODB transaction logic. Object abbreviation (`minimum_abbrev`, `default_abbrev`) is no longer part of the series.
- No behavior change intended; the series remains purely infrastructure for future libification.
- Test coverage: Not explicitly mentioned, but the mechanical nature of the changes suggests existing tests should suffice. The ODB transaction logic in `object-file.c` (touched in patch 2/3) and `core.ignorestat` behavior in `read-cache.c` (touched in patch 3/3) are noted as potential edge cases for testing.
