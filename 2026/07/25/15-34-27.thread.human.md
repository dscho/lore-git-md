This thread is about a small but long-standing usability improvement to `git checkout -m` when autostash is involved. Harald Nordgren’s two-patch series, now at version 5, refines how Git presents conflict advice during a branch switch. The core issue is that when autostash application hits a conflict, the advice message ("Your local changes are stashed...") and the branch-switch confirmation ("Switched to branch...") currently run together, making them hard to distinguish at a glance.

The first patch (already reviewed and accepted) overhauled the underlying logic: it introduced an `enum stash_apply_result` to clearly distinguish between clean stash application, conflicts, and outright errors, and aligned exit codes with Git’s established conventions (exit code 1 for conflicts, other non-zero values for errors). The second patch, which this email covers, is purely presentational—it simply adds a blank line between the conflict advice and the branch-switch message when a conflict occurs. The change is minimal (a single `fputc` call in `builtin/checkout.c`) and uncontroversial, relying on the infrastructure introduced in the first patch.

The series has been reviewed by Junio Hamano and Phillip Wood, both of whom have signed off on the design and implementation. Junio explicitly called the iteration "ready for merging" after the last minor mechanical refinements were addressed, and Phillip confirmed that all prior feedback—including his own concerns about exit code conventions—has been resolved. The patches are now queued for merging to `next`, with no further changes expected. The test suite has been updated to validate the exact screen output, ensuring the blank line is preserved in future iterations.
