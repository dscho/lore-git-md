This thread is about refining `git checkout -m` behavior when autostash conflicts occur, specifically to clean up the output by separating autostash conflict advice from the branch-switch confirmation message. The series, now at version 5, was posted by Harald Nordgren and has been reviewed and accepted by Junio Hamano and Phillip Wood. Junio has queued it for merging to `next`, meaning no further changes are expected.

The patches adjust return-value semantics and conflict detection logic in `sequencer.c`, reformat advice messages in `builtin/checkout.c`, and update exit code documentation in `git-stash.adoc`. The key technical change is introducing an `enum stash_apply_result` to distinguish between clean stash applications, conflicts, and errors, ensuring exit codes align with Git’s conventions (exit code 1 for conflicts, other non-zero values for errors). Tests in `t/t3903-stash.sh` and `t/t7201-co.sh` were updated to validate the new output and behavior.

All substantive feedback has been addressed, and the series is uncontroversial.
