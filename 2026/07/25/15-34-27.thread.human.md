The conversation has since shifted to a spin-off discussion about Git’s style enforcement in CI. The project currently runs `git clang-format` in an advisory capacity, as the tool’s `RemoveBracesLLVM: true` setting removes excess braces from single-statement `if/else` bodies but cannot enforce consistent brace usage across `if/else if/else` cascades. Harald now argues for adopting stricter, auto-fixable style rules to eliminate recurring review debates, even if it means a disruptive one-time reformat. Phillip acknowledges the trade-off but notes that `clang-format`’s output varies across versions and doesn’t perfectly match Git’s style guide. For now, the project remains in its advisory stance, with no immediate policy or code changes on the horizon.
