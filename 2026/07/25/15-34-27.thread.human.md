This thread is about a small but useful refinement to `git checkout -m` when autostash is involved. Harald Nordgren posted a two-patch series (v4) that visually separates autostash conflict advice from the branch-switch confirmation message, making the output cleaner without changing the underlying conflict resolution logic. The series also fixes a correctness issue by properly distinguishing between true conflicts and other failures during stash application, and aligns exit codes with Git’s established conventions (exit code 1 for conflicts, other non-zero values for errors).

The patches have been thoroughly reviewed and are now uncontroversial. Junio C Hamano accepted the series and queued it for merging to `next`; Phillip Wood, who raised the key design concerns about exit code conventions and API design, has acknowledged that all feedback has been addressed. The changes touch `sequencer.c`, `builtin/checkout.c`, `builtin/stash.c`, and related headers, introducing a new `enum stash_apply_result` to make the three possible outcomes (clean, conflict, error) explicit in the code. Tests in `t/t3903-stash.sh` and `t/t7201-co.sh` have been updated to validate the new exit codes and output formatting, including coverage for `stash branch`.

No further iterations are expected. The series is ready for merging and should land in `next` shortly.
