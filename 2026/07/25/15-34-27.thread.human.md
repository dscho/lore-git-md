This thread is about a two-patch series by Harald Nordgren that refines how `git checkout -m` handles autostash conflicts. The goal is to clean up the output by separating autostash conflict advice from the branch-switch confirmation message, while also fixing exit code conventions and conflict detection logic. The series has been reviewed and accepted, with Junio C Hamano confirming he will queue it for merging into `next`.

Key participants are Junio, Phillip Wood, and Harald Nordgren. Junio initially raised concerns about the conflict detection logic in early versions, which Harald addressed by properly distinguishing between true conflicts (exit code 1) and other errors (exit code 128 or other non-zero values). Phillip Wood advocated for using an `enum` to encode these states and pushed for exit code 1 to signal conflicts, aligning with Git’s established conventions. Both reviewers have since endorsed the series, and all technical and design issues are resolved.

The patches touch `sequencer.c`, `builtin/checkout.c`, `builtin/stash.c`, and related headers, introducing a new helper function (`do_stash_apply`) and updating tests to validate the new behavior. The series is now in its final form (v5), with only minor cosmetic improvements since the last review. No further changes are expected, and the series is ready for integration. The only remaining discussion is about style enforcement tooling, which doesn’t affect the patches themselves.
