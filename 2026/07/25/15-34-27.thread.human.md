This thread is about refining how `git checkout -m` handles conflicts when autostash is enabled. Harald Nordgren’s two-patch series (v1) aims to make autostash conflicts visible rather than silent and to skip unnecessary stash operations when no local changes exist. Junio has accepted the second patch in principle, but Phillip Wood raised two key objections: the API design of the first patch (using an output parameter to report conflicts) and the performance trade-off of its fast-path optimization.

The discussion is now focused on a narrow but critical point: whether the existing `int` return value of `apply_save_autostash_*()` can be repurposed to distinguish conflicts from other errors, or if an `enum` should be introduced instead. Harald’s latest email seeks clarity on this before revising the patch. Phillip’s earlier feedback suggests he favors a return-value-based approach, but no concrete alternative has been proposed yet. The uncontroversial advice-formatting improvement in patch 2 could be merged into patch 1 to justify the API changes, but the series still hinges on resolving this design question. No other reviewers have weighed in, and Junio’s conditional acceptance means a v2 is likely needed.
