This thread is about a critical memory-safety bug in `git worktree add` that can cause silent data corruption—specifically, recursive deletion of the working directory, including `.git`—when given an empty string or a string consisting solely of directory separators (e.g., `""` or `"//"`). The issue was discovered in the wild via Git for Windows issue #6346, likely triggered by unset environment variables in scripts.

Matthias Aßhauer submitted a two-patch series to fix the bug, but Junio C Hamano’s review identified a flaw in the first patch: while it attempts to prevent the out-of-bounds read, it introduces a new risk of pointer underflow when handling strings like `"///"`, which could lead to `strbuf_add()` allocating an enormous buffer. Junio suggested a safer approach, such as avoiding pointer arithmetic entirely or using an integer index loop. The second patch, which adds explicit validation to reject empty strings, remains unaddressed in the review but may need adjustment depending on how the first patch evolves.

René Scharfe’s recent review deepens the discussion by highlighting a broader design issue in `worktree_basename()`: its interface is error-prone because it returns a pointer to the basename while relying on callers to compute the correct length via fragile pointer arithmetic. This design is the root cause of the bug, and René suggests refactoring the function to return the basename length directly, making it harder to misuse. His feedback implies that the current patch is a temporary fix and that a more thorough redesign may be needed in the next version. The series is still under active review, with no prior versions or test coverage included, and reviewers may request reproduction steps or test cases to verify the fix. Matthias is expected to post a v2 addressing the feedback.
