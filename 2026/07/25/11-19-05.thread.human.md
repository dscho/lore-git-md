This thread fixes a critical memory-safety bug in `git worktree add` that could silently delete your working directory or trigger a BUG message when given an empty string with an explicit branch or commit (e.g., `git worktree add "" HEAD`). The root cause was a design flaw in `worktree_basename()` that caused pointer underflow when computing string lengths.

The first patch—a minimal, targeted rewrite of the problematic function—has been merged to Junio’s `next` branch (2025-06-10) and is now finalized with René Scharfe as the sole author, resolving the authorship question raised in the latest exchange. The second patch, which explicitly rejects empty strings in the `"" HEAD` case, is still pending revision; reviewers have asked for adjustments to its placement and commit message to better reflect the edge case it addresses. No test coverage has been added yet, and reproduction steps for the bug remain undocumented.

Key participants: Junio merged the first patch after endorsing René’s fix as "obvious and clear." René provided the technical rewrite and clarified that the second patch’s validation is necessary despite initial doubts. Matthias Aßhauer, who originally reported and patched the bug, has not yet responded to feedback on the second patch. The thread is now waiting on a v2 from Matthias to finalize the series.
