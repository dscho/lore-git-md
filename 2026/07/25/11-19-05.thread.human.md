This thread is about a critical memory-safety bug in `git worktree add` that can lead to data loss or corruption when an empty string is provided with an explicit branch or commit reference (e.g., `git worktree add "" HEAD`). The bug was discovered in the wild via Git for Windows issue #6346 and stems from a design flaw in `worktree_basename()` in `builtin/worktree.c`, which relies on fragile pointer arithmetic to compute the basename length.

Matthias Aßhauer initially proposed a two-patch series to fix the issue. The first patch attempted to prevent the out-of-bounds read by tracking the original string length but introduced a new risk of pointer underflow. Junio C Hamano and René Scharfe both identified flaws in this approach, with Junio suggesting safer alternatives and René proposing a broader refactoring to eliminate the root cause. The second patch added validation to reject empty strings, but its necessity and placement were initially questioned. René later clarified that this validation is required for the `"" HEAD` case, though its implementation may need adjustment.

René Scharfe has now submitted a minimal, targeted rewrite of `worktree_basename()` that directly addresses the memory-safety flaw by replacing the unsafe pointer arithmetic with a safer integer index loop. This patch is a drop-in replacement for the first patch in Matthias’s series and resolves the technical objections raised earlier. The second patch, which rejects empty strings, remains necessary but may need to be moved to an earlier point in the call chain. No test cases have been provided yet, but reviewers have requested them to verify the fix and prevent regressions. Matthias is expected to post a v2 incorporating the feedback.
