This thread is about a critical bug in `git worktree add` that can cause data loss by recursively deleting the working directory when given malformed input (e.g., an empty string or a string of directory separators). The issue stems from an out-of-bounds memory read in `worktree_basename()`, which Matthias Aßhauer attempted to fix in a two-patch series. The first patch, however, contains a logical flaw that Junio C Hamano identified: while it prevents the immediate out-of-bounds read, it could still trigger pointer underflow and cause `strbuf_add()` to allocate an excessively large buffer, leading to crashes or other undefined behavior.

Junio’s review is thorough and technical, focusing on the correctness of the fix rather than surface-level issues. He proposes a simpler and safer approach—using direct pointer assignment or an integer index loop—to avoid pointer arithmetic entirely when the input string is empty or consists solely of separators. The review also notes minor style issues but prioritizes the memory-safety concerns. No tests or reproduction steps have been provided yet, which may delay acceptance of the series. The thread is still in the early review phase, and a revised version (v2) is likely forthcoming to address Junio’s feedback. Key participants so far are Matthias (the author) and Junio (the maintainer), with no other reviews or positions recorded yet.
