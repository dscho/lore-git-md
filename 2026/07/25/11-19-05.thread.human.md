This thread is fixing a critical memory-safety bug in `git worktree add` that can silently delete the working directory (including `.git`) or trigger a BUG message when given an empty string or a string of only directory separators (e.g., `""` or `"//"`). The bug was discovered in the wild via Git for Windows issue #6346, likely triggered by unset environment variables in scripts.

The series, authored by Matthias Aßhauer, consists of two patches. The first patch attempts to prevent the out-of-bounds read in `worktree_basename()` but has been critiqued by Junio C Hamano and René Scharfe for introducing new risks, such as pointer underflow when handling strings like `"///"`. Junio suggests safer alternatives, while René proposes a broader refactoring to make the function less error-prone. The second patch, which adds validation to reject empty strings, was initially thought to be redundant but is now confirmed as necessary for a specific edge case: when `git worktree add` is called with an empty string *and* an explicit branch or commit reference (e.g., `git worktree add "" HEAD`). René’s latest review clarifies that this case bypasses earlier branch-name validation and directly exposes the memory-safety flaw. However, the patch’s placement and commit message may need adjustment to better reflect this nuance.

The series is under active review, with both patches requiring rework. Key open questions include how to safely fix the pointer arithmetic in the first patch, where to place the validation in the second patch, and whether to include test cases to verify the fix. René’s feedback has advanced the discussion by pinpointing the bug’s exact scope, but the design direction for the first patch remains unresolved. No prior versions of the series exist, and the author has yet to respond to the review feedback.
