This thread is about a critical memory-safety bug in `git worktree add` that can cause data loss—specifically, recursive deletion of the working directory—when given an empty string with an explicit branch or commit reference (e.g., `git worktree add "" HEAD`). The issue was discovered via Git for Windows and stems from a design flaw in `worktree_basename()` in `builtin/worktree.c`, where pointer arithmetic underflows when the input string is empty.

The fix is now finalized: René Scharfe has posted a minimal, targeted patch that replaces the original pointer-decrement loop with an integer-index loop, eliminating the underflow risk while preserving the function’s interface. Junio C Hamano endorsed the approach as "obvious and clear" and suggested it’s ready for integration into `next`. This patch is the first of the original two-patch series, now with René as the sole author, and directly addresses the root cause. The second patch—rejecting empty strings when a reference is provided—remains under discussion, with reviewers suggesting adjustments to its placement and commit message.

Key participants include Junio, who provided substantive technical feedback and endorsed the fix, and René, who identified the broader design flaw and authored the final patch. Matthias Aßhauer, the original series author, has not yet responded to review feedback. The fix is uncontroversial and confined to `builtin/worktree.c`, with no new symbols or on-disk format changes. Reviewers have requested reproduction steps or test cases for the `"" HEAD` case to verify the fix and prevent regressions, but the core memory-safety issue is now resolved.
