This thread is about a critical bug in `git worktree add` that can cause data loss by recursively deleting the current working directory (including `.git`). The issue occurs when an empty string or a string consisting solely of directory separators is passed as the worktree path, triggering an out-of-bounds memory read in `worktree_basename()`.

Matthias Aßhauer submitted a two-patch series to fix the problem. The first patch prevents the out-of-bounds read, while the second adds explicit validation to reject empty strings outright. The bug was discovered in the wild (Git for Windows #6346) and can manifest inconsistently—sometimes showing a BUG message, other times silently corrupting the working directory. The patches are narrowly scoped, touching only `builtin/worktree.c`, and do not introduce new CLI options or on-disk format changes.

The series is under review, with no prior versions or existing feedback. While the patches address the immediate issue, reviewers may request additional test coverage or validation for other edge cases (e.g., strings with only separators). The fix is urgent, as the bug poses a real risk of data corruption, but it currently lacks reproduction steps or test cases. No maintainer decisions have been made yet.
