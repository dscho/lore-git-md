This thread is fixing a critical memory-safety bug in `git worktree add` that can lead to silent data corruption—specifically, recursive deletion of the working directory including `.git`—when an empty string is passed with an explicit branch or commit reference (e.g., `git worktree add "" HEAD`). The bug was discovered in the wild via Git for Windows issue #6346, likely triggered by unset environment variables.

Matthias Aßhauer initially proposed a two-patch series to address the issue, but the first patch had a flaw: it could still underflow a pointer when the input was a string like `"///"`, risking enormous buffer allocations. René Scharfe identified the root cause—a design flaw in `worktree_basename()` that relies on fragile pointer arithmetic—and proposed a safer alternative. Junio C Hamano has now endorsed René’s approach, which replaces the original loop with an integer-index loop that stops at the string boundary, eliminating the underflow risk entirely. This patch is ready for integration and will likely replace the first patch in the next revision of the series.

The second patch, which explicitly rejects empty strings, remains under discussion. René clarified that this validation is necessary for the `"" HEAD` case, but its placement may need adjustment to fail faster (e.g., in `add()` or `dwim_branch()`). The commit message should also be updated to reflect this nuance. No test cases have been provided yet, and reviewers may request them to verify the fix and prevent regressions. Matthias has not yet responded to the feedback, so a v2 incorporating these changes is expected soon. The series is under active review, with no prior versions or related in-flight topics.
