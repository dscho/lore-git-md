This is a targeted usability improvement for the branch subsystem. René Scharfe’s v2 patch refines the error message when `git branch -d` refuses to delete a branch that is actively being used for `git bisect`. Instead of the generic "used by worktree at ..." message, users now see "used by worktree at ... for bisect", making it immediately clear why the branch is locked. The change is narrow—it only addresses bisect scenarios for now, leaving rebase and other internal operations for potential follow-up work.

The implementation introduces a new `enum branch_checkout_kind` to track why a branch is checked out (regular worktree, bisect, rebase, or update-ref), and a parallel array of `struct checked_out_branch` to store the refname, worktree path, and reason. This data structure is populated during the existing `prepare_checked_out_branches()` call and queried by the new `branch_bisecting()` helper. The patch touches `branch.c`, `branch.h`, `builtin/branch.c`, and the test suite (`t/t3200-branch.sh`), where the expected error message is updated to match the new wording.

Junio’s feedback on v1 expanded the scope, framing this as the first step toward a consistent API for branch-safety checks across all commands that repoint branch tips (e.g., `git history`). The v2 patch deliberately avoids that broader goal, focusing instead on the immediate usability win for bisect users. The `enum` vs. `int` debate is resolved in favor of `enum` for better debuggability, and the test coverage now verifies the bisect-specific message. However, the `BRANCH_CHECKOUT_KIND_UPDATE_REF` case (used during rebase with merges) remains unaddressed, and Phillip Wood’s recent usability concern—about confusion when `git status` shows a different branch than the error message—has not yet been incorporated.

The patch is well-crafted and addresses a real pain point, but the discussion is still active. If you care about branch-safety checks or error-message clarity, this thread is worth following—it may evolve into a broader effort to unify how Git reports branch usage across commands. For now, the v2 patch is a modest but meaningful improvement for bisect users.
