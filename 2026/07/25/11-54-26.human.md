This is part 1 of a three-patch series in the ongoing `the_repository` removal effort. It migrates the global configuration variables `minimum_abbrev` and `default_abbrev` into the repository-scoped `repo_config_values` struct, replacing them with getter functions (`repo_minimum_abbrev()` and `repo_default_abbrev()`). The changes are mechanical but carefully handle code paths that explicitly avoid `the_repository` (such as `merge-ort`), ensuring the getters work correctly when passed a non-global repository.

The patch touches six files: `environment.c` and `environment.h` (where the variables are defined), plus callers in `merge-ort.c`, `object-name.h`, `replay.c`, and `sequencer.c`. The existing `MINIMUM_ABBREV` and `DEFAULT_ABBREV` macros are redefined to use the new getters, preserving backward compatibility. No behavior change is intended—this is pure infrastructure work to support future libification.

The implementation includes explicit checks for `repo != the_repository` in the getters, a key constraint for subsystems like `merge-ort` that forbid direct use of the global repository. The patch looks well-structured and aligns with the project’s established patterns for this type of refactoring. If the rest of the series maintains this quality, it should be uncontroversial.
