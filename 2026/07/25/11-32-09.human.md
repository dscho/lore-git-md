This is the **v23 submission of Harald Nordgren’s `git branch --delete-merged` series**, now **ready for merging** after addressing the last mechanical correctness issues in patch 1/7. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including **order-independent stacked-branch protection**, per-branch opt-out, `--dry-run` preview, and repeatable upstream selectors.

The **only changes in v23** are mechanical fixes to patch 1/7 (`branch: add --forked filter for --list mode`): the loop variable `i` is now declared as `size_t` to match `filter->forked.nr`, and the `short_upstream_name()` helper uses a clearer sequence of `if (!skip_prefix(...)) skip_prefix(...)` statements instead of the previous `(void)(... || ...)` pattern. These changes address Junio C Hamano’s review feedback and have **no functional impact**—the behavior and design remain identical to v22, which was already unblocked and ready for merging.

The core command, `--delete-merged`, deletes local branches merged into their upstream (matching one or more `--delete-merged` arguments) while preserving branches used as upstreams for unmerged branches. It supports **repeatable upstream selectors** (e.g., `--delete-merged origin/main --delete-merged origin/next`) and **optional positional patterns** (e.g., `topic-*`) to limit deletion scope. Safety mechanisms include skipping checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`. The `--dry-run` flag prints "Would delete" or "Would skip" messages without modifying refs or config, and rejects the nonsensical `--dry-run --quiet` combination.

The series is **well-motivated** (addressing a real workflow pain point for iterative topic-branch workflows) and **thoroughly tested**, with comprehensive integration tests covering all safety checks, edge cases (e.g., stacked-branch protection, per-branch opt-out, `--dry-run`), and the `--forked` filter’s behavior. The implementation aligns with Git’s API consistency expectations, including a flags-based refactoring of `delete_branches()` (patches 2-4/7) and clear documentation updates. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.

Key technical details include:
- **Order-independent stacked-branch protection**: A single-pass graph traversal (`collect_stacked_branch_bases()`) ensures consistent results regardless of ref iteration order. The command fails to delete a branch if it is used as an upstream for an unmerged branch but clears the upstream config for kept (merged) branches whose own upstream is being deleted.
- **Per-branch opt-out**: The `branch.<name>.deleteMerged=false` config key exempts specific branches from automated cleanup while allowing explicit deletion via `git branch -d`.
- **`--forked` filter**: The foundation for `--delete-merged`, supporting exact refnames, remote shorthand, and shell-style globs. Branches are protected if pushing them by name would update their upstream, regardless of `remote.pushDefault` configuration.
- **Flags-based API**: Patches 2-4/7 refactor `delete_branches()` to use `unsigned int flags` (e.g., `DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`) instead of boolean arguments, eliminating local caching to ensure flags remain the single source of truth. The `DELETE_BRANCH_DRY_RUN` flag (patch 7/7) enables `--dry-run` support.
