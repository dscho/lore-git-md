This is the **v23 update of patch 1/7** in Harald Nordgren’s `git branch --delete-merged` series, which is now **ready for merging**. The patch introduces the `--forked` filter for `git branch --list`, a foundational building block for the `--delete-merged` subcommand. The filter lists only branches whose configured upstream matches a given ref, remote name, or shell-style glob (e.g., `--forked origin/main`, `--forked origin`, `--forked 'origin/*'`), and can be repeated to widen the match.

The **only changes in v23** are mechanical fixes to address Junio C Hamano’s final review comments:
- The loop variable `i` in `filter_forked_match()` is now declared as `size_t` to match `filter->forked.nr`, resolving a type mismatch that could trigger compiler warnings or undefined behavior.
- The `short_upstream_name()` helper was rewritten to use explicit `if (!skip_prefix(...)) skip_prefix(...)` statements instead of the `(void)(skip_prefix(...) || ...)` pattern, improving readability.

These changes are **isolated to patch 1/7** and have no functional impact. The rest of the series remains unchanged from v22, which Junio confirmed has no outstanding issues. The `--forked` filter is **well-tested**, with new integration tests covering exact refnames, remote shorthand, shell globs, composition with other filters (`--merged`, `--no-merged`), and edge cases like unknown branches or missing values. The implementation is **low-risk**, touching only `ref-filter.c` and `builtin/branch.c` with no behavioral changes to existing functionality.

The filter’s design is **sound and composable**: it resolves ref arguments to full refnames (e.g., `origin/main` → `refs/remotes/origin/main`) or accepts globs, and matches branches by comparing their upstream against the registered patterns. Exact matches are compared against full upstream refnames for unambiguity, while globs are matched against abbreviated upstream names (e.g., `origin/main`). The filter also handles remote shorthand (e.g., `origin` for `origin/HEAD`) and integrates cleanly with Git’s existing list-filtering machinery.

This patch is **unblocked** and the series as a whole is **ready for merging**. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands. The series addresses a real workflow pain point (safe automated branch cleanup) with thorough safety checks, a flags-based API, and comprehensive test coverage.
