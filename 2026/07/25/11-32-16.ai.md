This is the final patch in Harald Nordgren’s `git branch --delete-merged` series, adding `--dry-run` support to the new subcommand. The patch is purely mechanical and completes the feature set for safe, automated local branch cleanup.

The implementation adds a `DELETE_BRANCH_DRY_RUN` flag to the deletion API, which suppresses ref and config modifications while printing "Would delete" or "Would skip" messages for each affected branch. The flag is plumbed through `delete_branches()` and `delete_merged_branches()`, and the stacked-branch protection helper (`spare_stacked_bases()`) skips config updates during dry runs to avoid side effects. The output matches the real deletion/protection output exactly, making it a reliable preview mechanism.

The patch updates `Documentation/git-branch.adoc` to document the new option and adds three new tests in `t/t3200-branch.sh` to verify `--dry-run` functionality, including edge cases like stacked-branch protection and the rejection of `--dry-run` without `--delete-merged`. The nonsensical `--dry-run --quiet` combination is rejected as part of the existing quiet-flag handling in `delete_branches()`.

This patch is the last piece of the v23 series, which is now unblocked and ready for merging after addressing all mechanical correctness issues in earlier patches. The series as a whole introduces a well-motivated, thoroughly tested feature with comprehensive safety checks, including per-branch opt-out, order-independent stacked-branch protection, and repeatable upstream selectors. The `--dry-run` implementation is minimal, focused, and aligns with Git’s conventions for preview functionality.
