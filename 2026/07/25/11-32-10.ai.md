The patch introduces the `--forked` filter for `git branch --list`, a foundational building block for the `--delete-merged` subcommand that enables safe, automated local-branch cleanup.

The `--forked` filter allows users to list branches whose configured upstream matches a given ref (e.g., `origin/main`), remote name (e.g., `origin`), or shell-style glob (e.g., `origin/*`). It is composable with existing filters like `--merged` and `--no-merged`, and supports repeated arguments to widen the filter (e.g., `--forked origin/main --forked origin/next`). The implementation resolves ref arguments to full refnames (e.g., `origin/main` → `refs/remotes/origin/main`) and matches globs against abbreviated upstream names (e.g., `origin/main`).

Key technical details include:
- **Edge case handling**: Branches are protected if pushing them by name would update their upstream (e.g., `main` tracking `origin/main`), regardless of `remote.pushDefault` configuration. This ensures the filter correctly distinguishes true forks from long-lived branches.
- **Glob support**: Shell-style globs (e.g., `origin/*`) are matched against abbreviated upstream names using `wildmatch()` with `WM_PATHNAME` flags.
- **Remote shorthand**: A remote name like `origin` resolves to the branch its `origin/HEAD` points at (e.g., `origin/main`).
- **Composition**: The filter works seamlessly with `--merged`, `--no-merged`, and other list filters, as demonstrated in the test suite.

The patch touches `builtin/branch.c`, `ref-filter.c`, `ref-filter.h`, `Documentation/git-branch.adoc`, and `t/t3200-branch.sh`.
