This is the **v23 submission of Harald Nordgren’s `git branch --delete-merged` series**, now **ready for merging** after addressing the last mechanical correctness issues in patch 1/7. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including **order-independent stacked-branch protection**, per-branch opt-out, `--dry-run` preview, and repeatable upstream selectors.

The **only changes in v23** are mechanical fixes to patch 1/7 (`branch: add --forked filter for --list mode`):
- The loop variable `i` is now declared as `size_t` to match `filter->forked.nr`, resolving a type mismatch that could trigger compiler warnings or undefined behavior.
- The `short_upstream_name()` helper was rewritten to use explicit `if (!skip_prefix(...)) skip_prefix(...)` statements instead of the `(void)(skip_prefix(...) || ...)` pattern, improving readability and addressing Junio C Hamano’s style concern.

These changes are **isolated to patch 1/7** and have no functional impact. The rest of the series remains **identical to v22**, which Junio C Hamano confirmed has no outstanding issues and is ready for merging. The core command, `--delete-merged`, deletes local branches merged into their upstream (matching one or more `--delete-merged` arguments) while preserving branches used as upstreams for unmerged branches, checked-out branches, branches with missing upstreams, and branches opted out via `branch.<name>.deleteMerged=false`. The `--dry-run` flag provides a safe preview without modifying refs or config.

Key technical details include:
- **Order-independent stacked-branch protection**: A single-pass graph traversal (`collect_stacked_branch_bases()`) ensures consistent results regardless of ref iteration order. The command fails to delete a branch if it is used as an upstream for an unmerged branch but clears the upstream config for kept (merged) branches whose own upstream is being deleted.
- **Per-branch opt-out**: The `branch.<name>.deleteMerged=false` config key exempts specific branches from automated cleanup while allowing explicit deletion via `git branch -d`.
- **Flags-based API**: Patches 2-4/7 refactor `delete_branches()` to use `unsigned int flags` (e.g., `DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`) instead of boolean arguments, eliminating local caching to ensure flags remain the single source of truth.
- **`--forked` filter**: The foundation for `--delete-merged`, supporting exact refnames, remote shorthand, and shell-style globs. Branches are protected if pushing them by name would update their upstream, regardless of `remote.pushDefault` configuration.

The series touches `builtin/branch.c`, `ref-filter.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.txt`, and `t/t3200-branch.sh`. The implementation is **well-motivated** (addressing a real workflow pain point), **thoroughly tested** (with comprehensive integration tests covering all safety checks and edge cases), and **aligned with Git’s API consistency expectations**. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.
