This is part 2 of a 3-patch series refactoring global configuration variables as part of the `the_repository` removal effort. The patch migrates the `pack_size_limit_cfg` variable into the repository-scoped `repo_config_values` struct, eliminating another process-global configuration state.

The change is mechanical: `pack_size_limit_cfg` moves from a standalone global in `environment.c` into the `repo_config_values` struct, with all direct references updated to use the repository-specific instance. The patch touches four files: `builtin/pack-objects.c` (one caller), `environment.c` (removes the global, updates the config parser), `environment.h` (moves the variable into the struct), and `object-file.c` (updates the ODB transaction logic to access the value via `the_repository`'s config). No getter function is introduced because the variable has no hardcoded fallback and only two call sites.

The implementation is straightforward but requires careful attention to the repository context. In `object-file.c`, the patch adds a local `cfg` pointer initialized to `repo_config_values(the_repository)`, ensuring the value is accessed through the correct repository instance. This aligns with the series' goal of making configuration repository-scoped while maintaining backward compatibility.

No behavior change is intended, and the patch is positioned as infrastructure for future libification. The mechanical nature of the change suggests existing tests should suffice, though the ODB transaction logic in `object-file.c` is a potential edge case for testing. The patch is uncontroversial in isolation but contributes to the broader `the_repository` removal effort, which has been a long-running and widely supported project goal.
