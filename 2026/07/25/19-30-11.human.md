This is the sixth patch in the RFC series introducing `git repack --drop-filtered` for partial clones, now updated in response to review feedback. The author acknowledges that a real (non-dry-run) `--drop-filtered` run should imply `-d` to remove old promisor packs containing the dropped blobs, ensuring disk space is actually reclaimed. This clarification will be documented in the `--drop-filtered` option description in the v2 patch series.

The patch itself implements the core object-dropping logic, transitioning the feature from dry-run enumeration to real disk-space reclamation. It modifies `builtin/repack.c` to pass the computed drop set to `repack_promisor_objects()`, which rebuilds promisor packs while excluding the dropped blobs. The repack machinery’s existing crash-safety guarantees remain intact. While the series still faces blocking issues—such as the bitmap validation flaw and missing safety guards—this patch completes the RFC’s technical foundation. The v2 update will address these concerns and include the promised documentation.
