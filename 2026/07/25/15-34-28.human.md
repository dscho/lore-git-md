This is the first patch in a two-part series refining how `git checkout -m` handles autostash conflicts. It teaches the sequencer’s autostash plumbing to explicitly report when applying a stash results in conflicts, rather than silently failing. The change adds a `conflicted` output parameter to `apply_save_autostash_oid()` and `apply_save_autostash_ref()`, threads it through `apply_autostash_ref()`, and updates existing callers in `builtin/checkout.c`, `builtin/commit.c`, and `builtin/merge.c` to pass `NULL` since they don’t yet need the new information.

The patch is clean and mechanical: it adds the plumbing without changing behavior for current callers, setting the stage for the second patch to actually use the conflict signal. The commit message is clear, and the diff is straightforward. No test failures or edge cases are introduced here; the real test coverage comes in the next patch. If you care about autostash behavior, this is a foundational change worth noting.
