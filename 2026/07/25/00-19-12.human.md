This is Junio’s latest "What’s cooking" report for July 2026, summarizing the state of Git’s integration branches. It’s the project’s heartbeat, listing every in-flight topic, its merge status, and Junio’s current disposition.

The report covers 45 topics, with seven already merged to `master` in the most recent batch. Key themes include pluggable object database (ODB) work, the ongoing `the_repository` removal, sparse-index optimizations, and a steady stream of small fixes and documentation updates.

Notable new topics:
- **af/clone-revision-v0-segfault-fix** fixes a segfault when `git clone --revision` falls back to protocol v0.
- **ps/odb-make-creation-pluggable** makes the creation of on-disk ODB structures pluggable, a step toward alternative backends.
- **lo/mv-missing-dest-dir-check** improves `git mv` error reporting by checking for missing destination directories early.

Stalled topics include **tb/repack-geometric-cruft** (combining geometric repacking with cruft packs), **hn/checkout-track-fetch** (fetching during checkout), and **kh/doc-trailers** (documentation cleanup for `git interpret-trailers`).

Cooking in `next` (ready for the next release unless issues surface):
- **jt/config-lock-timeout** adds a short retry for config file locking.
- **tn/stash-avoid-sparse-index-expansion** optimizes `git stash push` for sparse-checkout.
- **ps/refs-wo-the-repository** and **rs/tempfile-wo-the-repository** continue the `the_repository` removal effort.
- **hn/history-squash** adds a `git history squash` subcommand to fold a range of commits.
- **ps/cat-file-remote-object-info** adds a `remote-object-info` batch-command to fetch object metadata without downloading the object.

The report also highlights several topics needing review, including **ps/odb-pluggable-housekeeping** (pluggable ODB maintenance), **js/pack-objects-delta-size-t** (size_t conversions in pack-objects), and **mm/diff-process-hunks** (external diff drivers).

For a busy reader, the ODB pluggability work, `the_repository` removal, and the new `git history squash` command are the most consequential ongoing efforts. The stalled topics are worth watching if you care about repacking, checkout behavior, or documentation quality.
