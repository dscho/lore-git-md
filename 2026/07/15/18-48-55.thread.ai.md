Subject: regression in `git rev-list --no-walk` path filtering (Git 2.55.0)
Series version: standalone bug report (no patch series)
Originating author: Peter Colberg
Thread type: bug report

Core problem or goal
`git rev-list --no-walk` in Git 2.55.0 no longer applies path-filtering arguments (e.g., `-- ':!drivers/gpu/drm/'`) because commit `dd4bc01c0a8f` ("revision: use priority queue for non-limited streaming walks") refactored the commit-processing logic in `get_revision_1()` and inadvertently omitted the `process_parents()` call that enforces path filters. The regression breaks workflows that rely on `--no-walk` for path-based filtering (e.g., bisect or commit analysis).

Current status
A fix has been proposed by the original author of the problematic commit (Kristofer Karlsson). The regression is confirmed, the root cause is identified, and a minimal reproduction case is provided. The proposed fix restores the `try_to_simplify_commit()` call in the `REV_WALK_NO_WALK` case of `get_revision_1()`, which internally invokes `process_parents()` and should restore path filtering. No formal patch has been posted yet, but the technical direction is settled.

Key technical details
- File touched: `revision.c` (function `get_revision_1()`)
- Subsystem: revision-walking
- Symbols: `REV_WALK_NO_WALK`, `try_to_simplify_commit()`, `process_parents()`
- Old behavior: `--no-walk` respected path filters
- New behavior: `--no-walk` ignores path filters
- On-disk format: unchanged
- Test coverage: minimal reproduction case provided; no formal test yet

Open questions and loose ends
