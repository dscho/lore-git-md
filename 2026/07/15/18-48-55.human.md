This is a **bug report** about a regression in `git rev-list --no-walk` introduced in Git 2.55.0.

Peter Colberg reports that since commit `dd4bc01c0a8f` ("revision: use priority queue for non-limited streaming walks"), the `--no-walk` option no longer respects path filtering arguments. The example demonstrates a workflow that worked in Git 2.54.0 but now fails: when piping commits through `git rev-list --stdin --no-walk=unsorted -- ':!drivers/gpu/drm/'`, the path exclusion is ignored, and all commits are passed through instead of only those modifying paths outside the specified directory.

The commit message does not state whether this change was intentional, and Peter explicitly asks whether the new behavior is deliberate or a regression. He provides a minimal diff that reverts the problematic hunk, showing that the removal of `process_parents()` in the `REV_WALK_NO_WALK` case is the likely cause. The report is clear, includes reproduction steps, and cites the exact commit that introduced the issue. This looks like a well-documented regression that deserves prompt attention.
