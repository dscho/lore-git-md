Subject: [PATCH 0/2] gitweb: fix object ID rendering in commitdiff index lines
Series version: v1 (initial submission)
Originating author: Travor Liu
Thread type: bugfix patch series

Core problem or goal
Gitweb’s commitdiff view incorrectly renders index lines (e.g., `index <old>..<new> 100644`) by showing full, unlinked object IDs instead of the usual shortened, clickable hashes. The bug occurs because the regex that matches object IDs runs before the mode-handling code, causing the mode string to be treated as part of the ID range.

Current status
Under review; no prior versions. Patch 1 reorders the logic in `gitweb/gitweb.perl` to strip the mode first, allowing the object-ID matcher to shorten and hyperlink the hashes. Patch 2 adds a regression test in `t9502-gitweb-standalone-parse-output.sh` that verifies the fix for the `100644` mode case. Junio C Hamano has suggested procedural improvements: squashing the test into the first patch to keep fix and validation together, and using `test_grep`/`test_grep !` instead of raw `grep` to align with an in-flight test-script hygiene topic.

Key technical details
