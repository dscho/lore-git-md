This is the first patch in Patrick Steinhardt’s v2 series removing `the_repository` from the refs subsystem. It fixes a latent bug in the packed-refs backend: the `core.packedRefsTimeout` configuration was previously stored in function-static variables, causing only the first repository’s setting to be used. The patch moves the timeout state into `struct packed_ref_store`, making it per-repository. The change is minimal (13 lines added, 6 removed in `refs/packed-backend.c`) and uncontroversial; Junio’s earlier review identified the behavioral regression (zero-initialized `timeout_value` instead of the 1000 ms default), which is now fixed in this version. The patch is part of the ongoing `the_repository` removal effort and is currently in `seen` and `jch`, expected to graduate to `master` in the next cycle.

The key technical detail is the introduction of two new fields in `struct packed_ref_store`: `timeout_configured` (bool) and `timeout_value` (int). The patch updates `packed_refs_lock()` to read the configuration per store and fall back to the 1000 ms default when the key is unset. No other files are touched, and the on-disk format remains unchanged. The commit message clearly explains the problem and the fix, and the code change is straightforward. This is a well-scoped, mechanical refactoring that addresses a real (if theoretical) correctness issue.
