This is a bugfix for `git mv`. The patch addresses a long-standing usability issue where `git mv` misleadingly reports a missing *source* file when the real problem is a missing *destination* directory. For example, running `git mv a/file b/does-not-exist/file` currently fails with "renaming 'a/file' failed: No such file or directory", even though `a/file` exists and the issue is that `b/does-not-exist/` doesn’t.

The fix moves the missing-directory check earlier in the process, during the validation phase rather than waiting for the `rename(2)` syscall to fail. It also ensures `git mv -n` (dry run) correctly detects the problem, which it previously didn’t. The implementation is careful to avoid false positives for directory moves, sparse checkouts, or out-of-cone destinations. The patch includes new tests in `t/t7001-mv.sh` to verify both the error message and dry-run behavior.

The commit message is clear and thorough, explaining the problem, the solution, and the edge cases considered. The code itself is straightforward and well-scoped, touching only `builtin/mv.c` and the test suite. This looks like a well-crafted fix for a real papercut, and the change is small enough to be uncontroversial. Worth a look if you’ve ever been confused by `git mv`’s error messages.
