This is a gitweb bugfix patch from Travor Liu, the first of a two-part series. It fixes a long-standing rendering issue in gitweb’s commitdiff view where index lines (e.g., `index <old>..<new> 100644`) show full, unlinked object IDs instead of the usual shortened, clickable hashes. The problem stems from the order of operations in `gitweb/gitweb.perl`: the code that appends the file mode annotation runs before the regex that shortens and links object IDs, causing the mode string to be treated as part of the ID range.

The patch reorders the logic to strip the trailing mode (e.g., `100644`) before matching the object IDs, then reattaches it after the IDs have been shortened and hyperlinked. The change is minimal—just 13 lines added and 5 removed—and preserves the existing mode display while restoring consistent hash formatting. The commit message clearly explains the issue and the fix, referencing the original commit that introduced the mode annotation (ec1fcc16af from 2005).

This is a straightforward, well-motivated fix with no apparent risk of breaking other gitweb features. The second patch in the series adds a regression test, which will confirm the fix works for the common `100644` mode case. If you use gitweb, this patch is worth reviewing to ensure the change doesn’t introduce any unintended side effects in edge cases.
