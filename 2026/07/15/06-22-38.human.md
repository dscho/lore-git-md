This is the eighth patch in Patrick Steinhardt’s nine-patch series (v4) introducing object filters to `odb_for_each_object()`. It is a refactoring and extension of the object database (ODB) subsystem, part of the ongoing ODB abstraction effort to support pluggable backends.

The patch adds a new `filter` field to the `odb_for_each_object_options` struct, allowing callers to pass object filters to backends. This enables backends to optionally skip objects excluded by the filter as an optimization, though they are free to ignore it if they cannot meaningfully optimize for the given filter. Callers must still re-apply the filter on yielded objects to ensure strict filtering semantics, as the ODB infrastructure supports filters that cannot be answered by the object database alone.

The implementation focuses on the "packed" backend, introducing a new `bitmapped_for_each_object()` callback that uses the previously added `prepare_bitmap_git_for_source()` function to open bitmaps specific to the source being enumerated. This prevents misattribution of objects and redundant enumeration when multiple sources have bitmaps. The patch also exposes the previously static `can_filter_bitmap()` function for backend use and modifies `odb_source_packed_for_each_object()` to skip packs already covered by a bitmap, avoiding duplicates.

The changes are well-motivated and align with the series’ goal of making `git cat-file --batch-all-objects` work with pluggable ODBs. The commit message clearly explains the design trade-offs, particularly the decision to allow backends to ignore filters they cannot optimize for, and the rationale for using source-specific bitmaps. The patch is cleanly structured, with no behavioral changes for end users. All prior review feedback has been addressed, and the series is now ready for integration, pending Junio’s final review. This patch is a key enabler for the final conversion of `git cat-file` to use ODB-mediated filtering in patch 9/9.
