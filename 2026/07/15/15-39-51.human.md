This is a **refactoring patch** in the `remote-curl` transport code, part of René Scharfe’s ongoing effort to simplify Git’s internals by removing redundant state. The patch eliminates the explicit `nr_spec` count passed to the `push_dav` and `push_git` handlers, relying instead on the NULL-termination guarantee of `strvec` arrays. The discussion here centers on whether to go further and pass the entire `strvec` struct to these functions, making the interface more self-documenting and potentially enabling future optimizations.

René’s original patch is a clean, low-risk change that removes an unnecessary parameter and the error-prone conversions between `size_t` and `int` it required. The code is already correct—`strvec` arrays are always NULL-terminated—but the current interface obscures this fact, forcing callers to track and pass an explicit count. The patch replaces the manual loop over `nr_spec` with a call to `strvec_pushv()`, which iterates until it hits a NULL terminator. No behavior changes, no new tests, and no impact on other subsystems.

Patrick Steinhardt’s review suggests refining the interface further by passing a `const struct strvec *` instead of a raw `const char **`. This would make the NULL-termination guarantee explicit and align with the fact that all callers already have a `strvec` in hand. He also notes the absence of a `strvec_pushvec()` function, which could optimize bulk appends by avoiding repeated reallocations, though he acknowledges this is speculative and not a blocker. René agrees the idea has merit but points out that `strvec_pushv()`’s simplicity was part of what made the NULL-terminated approach appealing in the first place.

The discussion is constructive and forward-looking, but it doesn’t block the current patch. René’s change is uncontroversial and could land as-is, while Patrick’s suggestion could be pursued in a follow-up if the project decides the interface clarity is worth the extra churn. Neither side has raised correctness concerns, performance regressions, or edge cases, and the patch remains a straightforward cleanup.
