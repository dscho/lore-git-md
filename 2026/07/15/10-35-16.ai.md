This is the second patch in the v5 series introducing configurable submodule fetch error handling, targeting the fetch and submodule subsystems. It adds the user-facing controls (`fetch.submoduleErrors` config key and `--submodule-errors` CLI option) and wires them through the fetch machinery, completing the feature introduced in the series.

The patch implements the new `fetch.submoduleErrors` configuration (values: `fail` or `warn`) and the corresponding `--submodule-errors=(fail|warn)` command-line option. The default remains `fail` for backwards compatibility. When set to `warn`, submodule fetch errors are reported to stderr but do not affect the exit status of `git fetch` or `git pull`. This addresses the workflow pain point where upstream topic branches reference submodule commits that are not yet available on the submodule remote, allowing the parent fetch to proceed without disruption.

Key implementation details include centralized parsing and formatting logic (using a shared `submodule_error_names` array to eliminate redundant conditional branches), case-sensitive config value matching (using `strcmp` instead of `strcasecmp`), and forwarding the resolved setting to child fetches (`--all`, `--multiple`, nested recursion) when explicitly set. The patch also ensures that the setting is propagated correctly to per-remote child processes, which re-read the repository configuration, so a command-line override (e.g., `--submodule-errors=fail`) is explicitly forwarded to override any `fetch.submoduleErrors=warn` config.

Test coverage is thorough, verifying the new behavior in various scenarios: warn mode (both config and CLI), CLI override of config, forwarding with `--all`, and edge cases like inaccessible submodules. The tests also confirm that the setting does not suppress error reporting for successful fetches. The implementation touches `submodule.c`, `builtin/fetch.c`, documentation files, and adds new tests to `t/t5526-fetch-submodules.sh`.

This patch is technically complete, addresses all prior review feedback, and is uncontroversial. It builds on the logic flaw fix in Patch 1/2 and is ready for `next` once Junio queues the series.
