This is a refactoring patch targeting `builtin/show-branch.c`. Gatla Vishweshwar Reddy’s v3 patch fully addresses the conceptual feedback from Junio C Hamano and Jeff King (Peff) on v2: it keeps the `UNINTERESTING` bit in `object.flags` (where it belongs for revision walking) and moves only the per-branch reachability bits into a dedicated commit-slab (`commit_rev_flags`) that now uses a configurable stride of `uint64_t` words. The slab is initialized with a stride of 1, giving 64 bits and lifting the previous 27-branch limit to 64 branches; the commit message notes that a dynamic stride for even more branches can be added later. All bit operations now use `UINT64_C(1)` for correct 64-bit shifts, and the patch adds clean helper functions (`get_rev_flags_ptr`, `or_rev_flag_bit`, `test_rev_flag_bit`, `has_all_rev_flags`, etc.) to encapsulate slab access. The indentation nit in `show_merge_base` and the type mismatch in `omit_in_dense` are both fixed. The patch touches only `builtin/show-branch.c`, preserves existing behavior, and passes all tests. It is part of the ongoing effort to eliminate misuse of `object.flags` across Git’s codebase and directly reuses the `init_commit_rev_flags_with_stride` infrastructure introduced in the 2025 variable-length bitset slab series. No other in-flight topics conflict with this change.
