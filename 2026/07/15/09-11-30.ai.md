This is the second patch in a two-patch bugfix series for gitweb. It adds a regression test in `t9502-gitweb-standalone-parse-output.sh` to verify that gitweb correctly shortens and hyperlinks object IDs in commitdiff index lines even when Git includes a trailing file mode (e.g., `index <old>..<new> 100644`). The test creates a regular file modification, renders the commitdiff view, and checks that the output contains the expected linked short blob IDs followed by the mode and file-type annotation, while ensuring the full unlinked form is not emitted.

The test is narrowly scoped to the `100644` mode case, which is the most common scenario and the one fixed by the first patch in the series. It complements the code change in `gitweb/gitweb.perl` by providing minimal but sufficient coverage for the regression. The test setup is straightforward: it modifies a file, commits the change, and uses `gitweb_run` to generate the commitdiff output, then greps for the expected pattern. No new test infrastructure or symbols are introduced.

This patch is uncontroversial and directly addresses the issue described in the series cover letter. The test is well-motivated and aligns with the fix in the first patch, which reorders the regex logic in `gitweb.perl` to strip the mode before matching object IDs. The series as a whole is self-contained, with no dependencies on other subsystems or ongoing efforts. The test’s inclusion of both positive and negative checks (presence of the linked short form and absence of the unlinked full form) strengthens confidence in the fix.
