This is the second patch in the nine-patch `diff.<driver>.process` RFC series (v5), which introduces a long-running subprocess protocol for external tools to inject diff hunks into Git's diff and blame pipelines. This patch adds the core xdiff plumbing that lets callers supply pre-computed hunks via two new `xpparam_t` fields (`external_hunks` and `external_hunks_nr`). When these fields are set, `xdl_diff()` populates its internal `changed[]` arrays from the supplied hunks instead of running the builtin diff algorithm, then continues through compaction and emission as usual.

The patch implements careful validation of the supplied hunks: it checks for out-of-bounds line numbers, overlapping or out-of-order hunks, and misaligned unchanged runs between hunks (the unchanged run between two hunks must be the same length on both sides, since `xdl_build_script()` walks the two files in lockstep). If validation fails, the code warns, returns -1, and falls back to the builtin diff algorithm for that file. The patch also skips `trim_common_tail()` when external hunks are present, since those hunks reference line numbers in the original content and trimming would invalidate them.

The implementation is robust and well-explained: it distinguishes between caller preconditions (non-negative counts and 1-based starts, checked with `BUG()`) and tool-response validation (in-bounds ranges, checked silently so the caller can fall back). The new `xdl_clear_changed()` helper ensures the `changed[]` arrays are clean before marking external hunks, and the patch maintains the existing error-handling paths. This is a foundational piece of the series, enabling the later patches that integrate the process driver with `--stat`, `git log -L`, and blame. The code looks solid and addresses all the technical concerns raised in previous review rounds.
