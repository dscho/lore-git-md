This is the final patch (4/4) in Tian Yuchen's v5 series migrating `has_symlinks` into `struct repo_config_values` as part of the `the_repository` removal effort. It completes the work begun in the now-merged v4 series by reintroducing the previously deferred `has_symlinks` migration, establishing a unified getter pattern alongside the already-migrated `trust_executable_bit`.

The patch moves the global `has_symlinks` flag into repository-scoped storage while preserving eager parsing for performance. A new getter function `repo_has_symlinks()` is introduced, and all call sites (in `apply.c`, `combine-diff.c`, `entry.c`, and `read-cache.c`) are updated to use repository-scoped access, falling back to `the_repository` where necessary. The mingw compatibility layer (`compat/mingw.c`) is adjusted to use a new global fallback variable `default_has_symlinks`, which the author notes is a pragmatic but potentially suboptimal solution for early platform-specific overrides before repository initialization.

Key technical details include the addition of `has_symlinks` to `struct repo_config_values`, initialization in `repo_config_values_init()`, and updates to `git_default_core_config()` to store the value in the repository's config rather than a global variable. The mingw-specific `setup_windows_environment()` function now writes to `default_has_symlinks` instead of the old global, and the getter function validates the repository pointer before accessing the config value.

This patch is a well-scoped mechanical migration with no behavioral changes, but the mingw compatibility question may attract further discussion. The author's use of a global fallback variable suggests a tension between the ideal of full repository-scoped configuration and the practical need to support early platform-specific overrides. The series as a whole demonstrates incremental progress in eliminating global state while establishing patterns for future configuration migrations.
