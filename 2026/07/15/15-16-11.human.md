This is the core implementation patch of Harald Nordgren’s `git history squash` feature, the third of five patches in the now-final v9 series. The command folds a commit range into its oldest commit while preserving descendant history, offering a faster alternative to interactive rebase for collapsing linear or merge-containing ranges.

The patch adds the `squash` subcommand to `git history`, complete with range parsing, merge handling, fixup/squash/amend validation, and ref safety checks. Key behaviors: the range is read like `git rev-list` arguments (supporting exclusions and multiple revisions), interior merges are allowed as long as the range has a single base, and refs pointing into the range are rejected by default with advice to use `--update-refs=head`. The command also sanitizes `rev-list` options that would alter walk order, warning if they are overridden.

The implementation is thorough: it reuses sequencer logic for fixup validation, centralizes tree resolution with a helper extracted in patch 1, and shares plumbing with the rest of the `git history` suite. Test coverage is extensive, verifying range parsing, merge handling, descendant replay, authorship preservation, ref safety, and edge cases like below-range fixups and nested merges. The test suite now includes helpers (`stage_file`, `commit_with_message`, `check_commit_count`, etc.) for readability, following the pattern established in earlier topics.

This patch is ready for integration. All prior feedback has been addressed, including the critical `rev-list` option validation gap and the `amend!` message handling edge case.
