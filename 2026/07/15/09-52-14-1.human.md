This is a refactoring patch that moves the `write_fetch_command_and_capabilities()` function from `fetch-pack.c` to `connect.c` as part of the ongoing `remote-object-info` feature series (now at v18). The patch is the sixth in a ten-patch series that implements client-side support for querying object metadata from remotes without downloading full objects.

The move is preparatory: the function will be generalized in the next patch to support arbitrary protocol commands, not just "fetch". This refactoring makes it available to other commands (like the new `object-info` command) without duplicating code. The change is mechanical—cutting the function from `fetch-pack.c` and pasting it into `connect.c`—with no behavior change. The commit message notes that a forward declaration is used in `connect.h` because `string_list` is only referenced as a pointer.

This patch is part of a security-hardened series that has been through 18 iterations and is now queued for merging to `next`. The thread context confirms all technical issues have been resolved, including a critical bounds-checking fix in the final patch. The move itself is uncontroversial and aligns with Git’s practice of consolidating protocol-related helpers in `connect.c`.
