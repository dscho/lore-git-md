This is the second patch in the nine-patch `diff.<driver>.process` RFC series (v5), introducing the core xdiff plumbing that lets external tools inject hunks into Git's diff pipeline. The patch adds two new fields (`external_hunks` and `external_hunks_nr`) to the `xpparam_t` struct, allowing callers to supply pre-computed hunks that `xdl_diff()` will use instead of running the builtin diff algorithm. The implementation carefully validates the supplied hunks: it checks for out-of-bounds line numbers, overlapping or out-of-order hunks, and misaligned unchanged runs between hunks (which must be the same length on both sides to maintain lockstep processing). When validation fails, the code warns and falls back to the builtin diff algorithm for that file.

The patch demonstrates thoughtful attention to edge cases and safety. It skips `trim_common_tail()` when external hunks are present, since those hunks reference line numbers in the original content. The validation logic distinguishes between caller bugs (checked with `BUG()`) and malformed tool responses (handled gracefully with warnings and fallbacks). The new `xdl_clear_changed()` helper ensures the changed arrays are properly reset before marking external hunks, preventing contamination from earlier diff passes. The implementation maintains xdiff's existing compaction and emission paths, so downstream features like word diff and color-moved continue working unchanged.

This is a well-crafted refactoring that integrates cleanly with the existing xdiff machinery while adding the necessary hooks for external diff tools. The validation logic is thorough, the error handling is robust, and the patch preserves all existing behavior when no external hunks are supplied. The only technical constraint is that external hunks must use 1-based line numbers and non-negative counts, which the caller (introduced in later patches) is responsible for enforcing. The patch is ready for merging once the maintainer signs off on the overall justification for the series.
