This thread is about a patch from Tian Yuchen that moves the global `fetch_if_missing` variable into `struct repository`, making it a per-repository flag that controls whether missing objects trigger lazy fetches from promisor remotes. This is part of the ongoing effort to eliminate global state in Git’s codebase, specifically the `the_repository` removal initiative.

The patch has evolved through feedback from Junio C Hamano and Patrick Steinhardt. Junio identified a critical correctness issue in `setup.c` where the patch incorrectly hardcoded `the_repository->fetch_if_missing` instead of using the passed `repo` parameter, which would break per-repository behavior. Patrick raised concerns about potential unintended behavior changes in `builtin/index-pack.c` and `revision.c` when repositories other than `the_repository` are used. The author addressed these by retaining `the_repository` in those subsystems to preserve existing behavior, a pragmatic compromise to avoid regressions. The `setup.c` fix was straightforward (`repo->fetch_if_missing = 0`), and the author has confirmed no other changes are needed beyond these adjustments.

The patch touches 15 files, including `odb.c`, `repository.c`, `fetch-pack.c`, `fsck.c`, `index-pack.c`, `revision.c`, and `setup.c`. It introduces `struct repository->fetch_if_missing` to replace the global variable, initializes it in `initialize_repository()`, and updates call sites to use the repository-specific flag. Special handling in `fsck.c` and `index-pack.c` avoids null pointer dereferences during early option parsing, and a `BUG()` check in `revision.c` ensures `--exclude-promisor-objects` is only used when `fetch_if_missing` is disabled. The default value remains `1` (enabled), preserving existing behavior, and the partial clone documentation is updated to reflect the new per-repository nature of the flag.

The patch is now ready for v2, with all substantive feedback addressed. While no new test coverage is introduced, the changes are expected to preserve existing behavior, and the fixes for `setup.c` and the retention of `the_repository` in specific subsystems should prevent regressions. The patch aligns with the broader libification and `the_repository` removal efforts, making it a logical step forward in eliminating global state.
