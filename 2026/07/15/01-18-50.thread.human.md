This thread is about a patch by Tian Yuchen that moves the global `fetch_if_missing` variable into `struct repository` as part of Git’s ongoing libification and `the_repository` removal efforts. The goal is to make the flag per-repository, preserving existing behavior (defaulting to enabled) while eliminating global state.

The patch is now at v2, which addressed earlier feedback from Junio C Hamano (a critical correctness fix in `setup.c`) and Patrick Steinhardt (concerns about unintended behavior changes in `index-pack.c` and `revision.c`). However, Junio recently identified a new edge case: in repository-less invocations (e.g., `git index-pack` outside a repository), the patch could inadvertently enable lazy fetches where they were previously suppressed, altering behavior. Tian acknowledged this and plans a v3 to fix it. Patrick’s latest review surfaces another correctness issue in `index-pack.c`—a potential null pointer dereference if `repo` is NULL—suggesting the conditional check be removed entirely. The patch is not yet ready for pickup, as both issues must be resolved.

Key participants include Tian (author), Junio (maintainer), and Patrick (reviewer). Junio and Patrick have both flagged correctness issues that require fixes, while Tian has been responsive to feedback. The patch touches 15 files, including `odb.c`, `fetch-pack.c`, and `fsck.c`, and introduces no on-disk format changes. Testing remains a gap, with no explicit verification of multi-repository or repository-less scenarios. The broader context is the libification effort and `the_repository` removal, with this patch following established patterns.
