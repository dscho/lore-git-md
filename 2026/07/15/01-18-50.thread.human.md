This thread is about a patch series by Tian Yuchen that moves the global `fetch_if_missing` variable into `struct repository`, making it a per-repository flag controlling lazy fetches from promisor remotes. This is part of the ongoing libification and `the_repository` removal efforts. The fourth version (v4) of the patch addresses feedback from Junio C Hamano and Patrick Steinhardt, resolving key issues from the previous iteration.

The patch touches 15 files, replacing the global variable with `repo->fetch_if_missing` while preserving the default behavior (enabled). It handles edge cases in `fsck.c` and `index-pack.c` to avoid null pointer dereferences and ensures consistency in `revision.c` by using `revs->repo` instead of `the_repository`. The v4 patch also resolves a conflict with `cf1687a41c` (a recent change in `seen` that split `setup_git_env_internal()`), which was a blocker in v3. The author has coordinated with other topics to avoid further conflicts, and the patch now appears technically sound.

Junio’s feedback in earlier versions surfaced broader architectural questions—whether `fetch_if_missing` belongs in `struct repository` at all—but the v4 patch focuses on resolving immediate correctness issues. Patrick Steinhardt’s concerns about behavior changes and null pointer risks have been addressed, and no new objections have been raised. The patch is now ready for further review, though the long-term design direction remains open. No new test coverage was added, but the changes are expected to preserve existing behavior. The author has indicated the patch is part of the broader effort to eliminate global state, making it a logical step forward.
