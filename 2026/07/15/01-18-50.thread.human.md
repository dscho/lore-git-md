This thread is about a patch (v2) by Tian Yuchen that moves the global `fetch_if_missing` variable into `struct repository` as part of Git’s ongoing libification and `the_repository` removal efforts. The goal is to make the flag per-repository rather than global, preserving existing behavior (defaulting to enabled) while eliminating global state.

The patch is under active review, with two key issues blocking progress. First, Junio C Hamano raised a fundamental design concern: `fetch_if_missing` may not belong in `struct repository` at all, since commands like `git index-pack` can run outside a repository. He outlined three possible approaches to resolve this, none of which have been adopted yet. Second, Patrick Steinhardt identified a null pointer dereference risk in `builtin/index-pack.c`, where the code checks for `repo` but then unconditionally sets `the_repository->fetch_if_missing`, which could crash if `repo` is NULL. Tian has acknowledged both issues and plans a v3 to address them, including a range-diff for easier review.

The patch touches 15 files, including `odb.c`, `fetch-pack.c`, and `index-pack.c`, and introduces `struct repository->fetch_if_missing` while retaining `the_repository` in some subsystems to avoid regressions. No new tests have been added, and the absence of explicit multi-repository or repository-less testing leaves potential edge cases unconfirmed. The thread remains open, with the next version expected to tackle the architectural and correctness issues before the patch can move forward.
