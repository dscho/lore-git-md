This thread is about a patch from Tian Yuchen that moves the global `fetch_if_missing` variable into `struct repository` as part of Git’s ongoing effort to eliminate global state. The patch is part of the broader `the_repository` removal initiative, which aims to make Git’s internals more modular and reusable.

The patch is currently under review and has not yet been revised. Junio C Hamano identified a critical correctness issue in `setup.c`, where the patch incorrectly hardcodes `the_repository->fetch_if_missing` instead of using the passed `repo` parameter. This oversight would break per-repository behavior, undermining the patch’s core goal. Tian has acknowledged the issue and is preparing a v2 to fix it by replacing the hardcoded reference with `repo->fetch_if_missing = 0`. The fix is expected to be straightforward and uncontroversial.

The patch touches 15 files across subsystems like the object database, fetch, fsck, index-pack, and revision handling, but the correctness issue is isolated to a single line in `setup.c`. Once addressed, the patch will preserve the existing behavior (default `fetch_if_missing = 1`) while enabling per-repository control, aligning with the libification effort’s goals. No other open questions or objections have been raised, and the thread is now waiting for the revised version.
