This thread is about a patch by Tian Yuchen that moves the global `fetch_if_missing` variable into `struct repository` as part of Git’s ongoing libification and `the_repository` removal efforts. The goal is to make the flag per-repository, preserving existing behavior (defaulting to enabled) while eliminating global state.

The patch is under review, with Junio C Hamano having already identified a critical correctness issue in `setup.c` where the patch hardcoded `the_repository->fetch_if_missing` instead of using the passed `repo` parameter. Tian acknowledged the issue and confirmed the fix will be mechanical (`repo->fetch_if_missing = 0`). Patrick Steinhardt’s recent review raises two additional concerns about potential behavior changes in `index-pack.c` and `revision.c`, questioning whether the patch correctly handles repositories other than `the_repository`. While Patrick prefers moving the flag into the object database, he acknowledges the current approach aligns with the libification effort. No other objections or requests for changes have been raised, and Tian is expected to submit a v2 addressing these points.

The patch touches 15 files, including `odb.c`, `repository.c`, `fetch-pack.c`, and `fsck.c`, and introduces no on-disk format changes. The default value of `fetch_if_missing` remains `1` (enabled), and initialization occurs in `initialize_repository()`. Special handling in `fsck` and `index-pack` avoids null pointer dereferences during early option parsing, and `revision.c` adds a `BUG()` check to enforce that `--exclude-promisor-objects` can only be used when `fetch_if_missing` is disabled. No new tests have been added, and the correctness issue in `setup.c` suggests multi-repository scenarios may not have been thoroughly tested. The author has not yet addressed this explicitly, but the fix is straightforward. The patch is part of broader efforts to eliminate `the_repository` and improve Git’s modularity.
