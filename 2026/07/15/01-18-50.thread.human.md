This thread is about a refactoring series that moves the global `fetch_if_missing` variable into `struct repository`, making it a per-repository flag that controls whether missing objects trigger lazy fetches from promisor remotes. The series, now at v6, is part of the broader `the_repository` removal and libification efforts led by Tian Yuchen.

The latest version addresses all prior feedback, including Junio’s suggestion to streamline the `option_parse_missing_action()` callback by using the `value` field in `OPT_CALLBACK_F()` to pass the repository address directly. This change eliminates an intermediate variable and a deferred side effect, improving code clarity. The series touches 15 files, including key built-ins like `fetch-pack`, `fsck`, `index-pack`, and `pack-objects`, and preserves existing behavior—the default value remains enabled (`1`), and initialization occurs in `initialize_repository()`. Special handling for repository-less invocations (e.g., the ternary fallback in `index-pack.c`) and edge cases in `fsck.c` remain unchanged.

Junio’s latest review confirmed the series is mechanically complete ("Much better") but left the broader architectural question unresolved: whether `fetch_if_missing` belongs in `struct repository` or should instead use a global "basic settings" structure for repository-less cases. Tian has deferred this discussion, focusing for now on the immediate goal of eliminating `the_repository` references. The series is ready for maintainer decision, though Junio may still request further clarification before queuing. Patrick Steinhardt’s earlier concerns about behavior changes and null pointer risks have been addressed, and no new test coverage was added, though the changes are expected to preserve existing behavior. The patch coordinates with other topics to avoid conflicts and aligns with the project’s libification goals.
