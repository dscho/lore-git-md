This is a refactoring patch that moves the global `fetch_if_missing` variable into `struct repository` as part of the ongoing libification effort. The change is mechanical but touches many subsystems (fetch-pack, fsck, index-pack, pack-objects, prune, rev-list, midx, and the object database) because the flag controls whether missing objects trigger a lazy fetch from promisor remotes.

The patch initializes the new per-repository field to 1 (the previous default) and updates all call sites to read the flag from the repository instance they already have, falling back to `the_repository` where no explicit pointer is passed. Two edge cases in `fsck` and `index-pack` are handled by deferring repository access until after argument parsing to avoid null-pointer dereferences. Documentation is updated to reflect that the setting is now per-repository rather than global.

The commit message is clear and the diff is clean; the patch looks like a well-executed step toward removing globals. No controversy is evident, and the change should be uncontroversial for anyone following the libification roadmap.
