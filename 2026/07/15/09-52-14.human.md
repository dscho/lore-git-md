This is a review comment on the first patch in René Scharfe’s 5-patch series introducing repository-aware tempfile APIs as part of the `the_repository` removal effort. The series is already queued in Junio’s `seen` branch, but Patrick Steinhardt raises a design question about whether passing a full `struct repository *` is overkill when all the function needs is the `core.sharedRepository` setting.

Patrick’s feedback is substantive but forward-looking: he acknowledges the current patch is a reasonable first step, but suggests a future API could accept just the configuration value instead of the entire repository object. This would avoid requiring callers to have a repository available, though it might lead to code duplication. He also notes a minor nit about the implementation (the wrapper could be an inline function in the header), but dismisses it as unimportant since the wrapper will likely be removed in later patches.

The review does not request changes to the current patch, nor does it identify any functional issues. It is a design observation that could inform future work, but for now the series remains on track as-is.
