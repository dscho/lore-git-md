This is the first patch in Harald Nordgren’s **v9 series** introducing the `git history squash` subcommand. It is a **pure refactoring** that extracts a helper function, `first_parent_tree_oid()`, to centralize the logic for resolving a commit’s first-parent tree (or the empty tree for a root commit). The helper replaces three nearly identical code blocks in `builtin/history.c` that previously repeated the same parse-and-copy dance.

The patch touches only `builtin/history.c`, moving 32 lines of duplicated logic into a single 25-line helper. There is **no behavior change**; the goal is to improve maintainability and reduce duplication ahead of the feature implementation in later patches. The helper is already used by the three call sites it replaces: `commit_tree_with_edited_message()`, `commit_became_empty()`, and `split_commit()`.

This patch is **uncontroversial** and ready to merge. It is a textbook example of a preparatory refactoring that makes the subsequent feature patches cleaner and easier to review.
