This is the core implementation patch (3/5) of Harald Nordgren’s `git history squash` feature, now in its ninth and final iteration. The patch adds a new subcommand that folds a commit range into its oldest commit while preserving descendant history, addressing all prior feedback and resolving the last open technical concern (`amend!` message handling).

The command resolves a revision range using `git rev-list` machinery, rejecting single-commit ranges, empty ranges, and ranges with multiple bases. It allows interior merges as long as all parents are reachable from the base but rejects merges whose other parent lies outside the range. By default, the command refuses if any ref points to a commit inside the squashed range, with an advice message suggesting `--update-refs=head` to explicitly retarget the current branch. The range is parsed like `git rev-list` arguments, supporting compound ranges such as `HEAD~3..HEAD ^topic`, and sanitizes all `rev-list` options (including those after `--`) by forcing `--reverse --topo-order` and warning if the user’s options would alter the walk order.

Key internal helpers introduced in this patch:
- `resolve_squash_range()`: Parses and validates the range, ensuring it meets structural requirements and sanitizing `rev-list` options.
- `reject_dangling_fixups()`: Blocks ranges where any `fixup!`/`squash!`/`amend!` marker’s target lies outside the range, while allowing multiple markers for the same in-range commit to fold together. As an exception, a range made entirely of markers for one target is combined into a single commit, taking its message from the last `amend!` if present.
- `find_interior_ref()`: Detects refs pointing to commits inside the squashed range.

The main `cmd_history_squash()` function performs a single three-way merge of the entire range against the oldest commit’s parent, then replays descendants on top. The default squashed commit message now incorporates the body of the last `amend!` commit targeting the oldest folded commit, resolving the internal inconsistency raised by Matt Hunter. The `--reedit-message` option lets users interactively combine commit messages from the entire squashed range using a template that matches `git rebase -i --autosquash`.
