This is the eighteenth and final version of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. The series is now ready for merging to `next` and introduces the ability to query object metadata (currently just size) from remote repositories without downloading full objects.

The implementation completes Eric Ju and Calvin Wan’s earlier work by adding dynamic capability-based validation, strict protocol enforcement, and comprehensive test coverage. The key improvement in v18 is a bounds-checking fix in patch 10/10 that prevents out-of-bounds reads when parsing server responses, addressing the last substantive security concern raised in v17. The series also corrects the cover letter attribution to Pablo Sabater as the primary author, resolving the procedural issue that led Junio Hamano to revert v16.

The feature works with protocol v2 servers advertising the `object-info` capability and supports batching up to 10,000 objects per request. The default format is `"%(objectname) %(objectsize)"`, with empty strings returned for unsupported fields like `%(objecttype)` or `%(deltabase)`. The implementation includes 699 lines of new tests in `t/t1017-cat-file-remote-object-info.sh`, covering edge cases like malformed OIDs, missing objects, and unsupported capabilities.

The series demonstrates careful attention to memory safety, with fixes for a transport helper leak, loop counter scoping improvements, and static variable elimination. It also refactors test infrastructure by moving shared utilities to `t/lib-cat-file.sh` and generalizes protocol command handling to support future extensions. Pablo Sabater plans a follow-up series to add `%(objecttype)` support once this lands in `next`.

All technical feedback from previous versions has been addressed, including Junio’s critical refactoring flaw in v15 and the bounds-checking issue in v17. The series is well-motivated, thoroughly tested, and aligns with Git’s established patterns for security and compatibility. It looks like a solid addition to the codebase.
