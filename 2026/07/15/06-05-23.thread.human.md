This thread began with a bugfix for a long-standing segfault in `git diff --relative --cached` when operating on unmerged paths outside the current directory. Jeff King (Peff) identified the root cause—a NULL pointer dereference in `do_oneway_diff()`—and submitted a minimal fix, followed by a two-patch refactoring series to clean up the same code path. The entire three-patch set has been reviewed and approved by Junio C Hamano and is now queued for integration in `next`.

The original bug, which dates back to 2011, is now resolved: the fix adds a NULL check before `fill_filespec()`, ensuring that `--relative --cached` safely ignores unmerged paths outside the prefix instead of crashing. The refactorings are uncontroversial and improve code clarity without changing behavior. The second patch, which moves the `--relative` prefix check earlier in `oneway_diff()`, triggered a Coverity static-analysis warning about a potential NULL dereference. Peff clarified that the warning is a false positive, as the code only dereferences `tree` when `idx` is NULL, and in that case `tree` cannot be NULL. The discussion has since shifted to whether to add a `BUG()` assertion to document this invariant for static analyzers, with Junio playfully suggesting a message explicitly targeting Coverity. No substantive changes are expected, and the series remains ready for integration.
