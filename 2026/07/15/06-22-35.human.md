This is the fifth patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch restructures how Git opens pack bitmaps by iterating over object sources first, then attempting to load a bitmap for each source. This refactoring is a prerequisite for a later patch (7/9) that will allow opening bitmaps for a specific object source, a key step in enabling `git cat-file --batch-all-objects` to work with pluggable backends.

The change is mechanical but introduces a subtle behavioral difference: when multiple object sources have bitmaps, the new logic prefers the first source’s packfile bitmap over a later source’s multi-pack index (MIDX) bitmap. Previously, any MIDX bitmap would take precedence over all packfile bitmaps. The commit message argues this is an improvement because it prioritizes local bitmaps over those in alternates, and the scenario is already flagged as problematic by existing warnings about duplicate bitmaps.

The diff is clean and focused, touching only `pack-bitmap.c`. It replaces two functions (`open_pack_bitmap` and `open_midx_bitmap`) with a single `open_bitmap_for_source` helper, then updates `open_bitmap` to loop over sources first. The new logic is simpler and more consistent with the ODB abstraction’s design goals. No new test failures are expected, and the change is well-motivated in the context of the series.

This patch looks ready for integration. It addresses a specific technical need (supporting per-source bitmap opening) without introducing user-visible behavior changes, and the trade-off in bitmap precedence is justified. The restructuring is a natural step in the ODB abstraction effort and aligns with the series’ overall direction.
