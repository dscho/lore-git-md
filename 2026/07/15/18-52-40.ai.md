This is the final patch in the GSoC v18 series implementing `git cat-file --batch-command`'s `remote-object-info` feature, now with a dynamic allow-list for server-advertised metadata fields. The patch addresses Junio’s review feedback from the parent email, closing the last open robustness and clarity issues before the series graduates to `next`.

Pablo Sabater clarifies and fixes three points raised in Junio’s review. First, he confirms that unsupported format placeholders (e.g., `%(objectcolor)`) are omitted entirely from the output, producing `42 ` rather than `42 %(objectcolor)` when only `%(objectsize)` is supported. This aligns with `for-each-ref` behavior and will be documented with a concrete example in the updated commit message. Second, he reformats the `EXPAND_DATA_INIT` macro to use one line per item, anticipating future expansion of the `remote_allowed_atoms` list. Third, he resolves the silent failure mode in `parse_cmd_remote_object_info()` by adding an early return when only `%(objectname)` is requested, avoiding unnecessary connection overhead while still returning the expected OID. This sidesteps the current server limitation (no bare-OID existence checks) but leaves the door open for future protocol extensions.

The patch also fixes the edge case where no object-info options are requested: instead of silently skipping the remote query, the client now explicitly returns the OID without contacting the server, preventing misleading output. This change, combined with the dynamic allow-list, ensures the client only queries for metadata the server actually supports, eliminating segfault risks from unsupported placeholders. The series is now technically complete, with all prior feedback addressed and CI confirming readiness for integration. Pablo’s follow-up patches (12/13 and this one) were critical in resolving the last usability and robustness concerns, particularly around silent failures and placeholder handling.
