This is the first patch in a two-part gitweb bugfix series. It addresses a rendering issue in gitweb’s commitdiff view where index lines containing file modes (e.g., `index <old>..<new> 100644`) show full, unlinked object IDs instead of the usual shortened, clickable hashes. The root cause is that gitweb’s regex for matching object IDs runs before the mode-handling code, causing the mode string to be treated as part of the ID range.

The patch reorders the logic in `gitweb/gitweb.perl` to temporarily strip the trailing mode before matching the object IDs, then reappends it after the IDs have been shortened and hyperlinked. This change is minimal and surgical, touching only the `format_extended_diff_header_line` function. The diff shows a clear before-and-after: the mode extraction is moved earlier in the function, and the mode is reattached only after the object-ID formatting is complete.

The commit message is well-explained, citing the original commit that introduced the trailing mode (ec1fcc16af, 2005) and noting the inconsistency with other hash displays in gitweb. It also mentions recent mobile-overflow fixes in other views, framing this as a logical continuation of that effort. No new symbols or on-disk format changes are introduced.

This patch is part of a self-contained series with no external dependencies or related work. The second patch in the series adds a regression test for the `100644` mode case, which will be summarized separately. The fix appears low-risk, as it only affects the rendering of index lines in gitweb’s commitdiff view and does not alter any core Git functionality.
