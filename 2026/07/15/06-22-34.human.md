This is the fourth patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch enables early termination of bitmapped object iteration by propagating non-zero return values from the `show_reach` callback through `for_each_bitmapped_object()` and `show_objects_for_type()`.

The change is a prerequisite for lifting bitmapped object iteration into the packed backend and exposing it via `odb_for_each_object()`, which expects callbacks to support early abortion. Currently, `for_each_bitmapped_object()` ignores callback return values, but once the logic moves into the generic ODB infrastructure, this would become a latent bug. The patch refactors `show_objects_for_type()` to return an `int` and checks the callback’s return value, aborting iteration if non-zero. Two callers in `builtin/pack-objects.c` and `builtin/rev-list.c` are updated to return `0` instead of `1` to preserve existing behavior.

The patch is well-motivated and addresses a clear technical need. The commit message explains the rationale and the mechanical nature of the changes, and the diff is clean and focused. The only caveat is the unresolved design question about consistency between `traverse_bitmap_commit_list()` and `traverse_commit_list()`, but Taylor Blau’s proposed follow-up (splitting the callback type) is already planned to resolve this. No new issues are introduced here, and the patch is ready for integration.
