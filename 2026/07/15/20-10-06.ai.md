This is a small bugfix patch addressing a coding style violation in the submodule helper code. Junio C Hamano (the maintainer) fixes a recently introduced use of `%zu` in `builtin/submodule--helper.c`, which violates Git's CodingGuidelines that explicitly forbid C99's `%z`/`%zu` format specifiers despite their technical availability. The patch replaces the specifier with the project's established workaround: casting the value to `(uintmax_t)` and using `PRIuMAX`.

The violation was introduced six months ago in commit `82c36fa0a9` (submodule: hash the submodule name for the gitdir path, 2026-01-12) but went unnoticed until now. Junio acknowledges the possibility of treating this as a "weather balloon" to test whether `%zu` is now safe to use across all supported platforms, but opts for caution, noting that distributions often lag behind Git releases and that failures in this code path might not trigger visible breakage. The fix follows the existing pattern recommended in the CodingGuidelines, leaving any future bulk conversion to `%z`/`%zu` (via Coccinelle or similar) as a separate effort.

The change is minimal—just two lines in one file—and does not alter behavior. It targets the `submodule--helper` subsystem, specifically the function that generates a hashed gitdir path for submodules when other methods fail. The patch is self-contained and unlikely to be controversial, as it aligns with long-standing project conventions. No tests are included, as this is purely a style compliance fix. The commit message is clear and provides context about the trade-offs considered, making it easy for reviewers to assess the rationale.
