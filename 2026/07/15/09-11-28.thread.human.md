This thread is a small bugfix series from Travor Liu that fixes how Gitweb renders object IDs in commitdiff index lines. The issue is that full, unlinked hashes appear instead of the usual shortened, clickable ones because the regex matching object IDs runs before the mode-handling code, causing the mode string to be treated as part of the ID range. The fix, in the first patch, reorders the logic in `gitweb/gitweb.perl` to strip the mode first, allowing the object-ID matcher to work correctly. The second patch adds a regression test to verify the fix for the `100644` mode case.

Junio C Hamano has reviewed the series and suggested two procedural improvements to the test in the second patch. He recommends squashing the test into the first patch so the fix and its validation appear together, making review easier. He also asks that the test use `test_grep` and `test_grep !` instead of raw `grep` to align with an in-flight topic that will enforce stricter test-script hygiene. These suggestions are surface-level and focus on test mechanics rather than the substance of the fix itself. The series is under review, and no substantive objections or open questions remain.
