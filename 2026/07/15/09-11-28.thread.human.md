This thread is about a small but visible bug in Gitweb’s commitdiff view: index lines like `index <old>..<new> 100644` were showing full, unlinked object IDs instead of the usual shortened, clickable hashes. Travor Liu identified the root cause—a regex that matches object IDs before stripping the trailing mode—and submitted a two-patch series to fix it.

The first version of the series was reviewed by Junio C Hamano, who requested procedural improvements: squash the test into the first patch and use `test_grep` instead of raw `grep` to align with ongoing test-script hygiene work. Travor has now sent v2, which incorporates both changes. The fix itself is minimal: it reorders the logic in `gitweb/gitweb.perl` to strip the mode first, then shorten and hyperlink the object IDs, and finally reappend the mode. The test in `t/t9502` verifies that the index line now shows linked short blob IDs followed by the mode and file-type annotation, with no trace of the unlinked full form.

The patch is ready for integration. It’s a narrow, well-motivated change with clear commit messages and sufficient test coverage, and all review feedback has been addressed. No open questions or objections remain.
