This thread is a small, focused bugfix for gitweb’s commitdiff view. Travor Liu sent a two-patch series that fixes a rendering glitch: index lines like `index <old>..<new> 100644` were showing full, unlinked object IDs instead of the usual shortened, clickable hashes. The root cause was a regex ordering issue—mode handling ran after the object-ID matcher, so the mode string was mistakenly treated as part of the ID range.

The first patch reorders the logic in `gitweb/gitweb.perl` to strip the mode first, letting the object-ID matcher do its job. The second patch, just summarized, adds a minimal regression test in `t9502-gitweb-standalone-parse-output.sh` to verify the fix for the common `100644` mode case. The test is straightforward: it creates a file modification, renders the commitdiff view, and checks that the output contains the expected linked short blob IDs followed by the mode and file-type annotation, while ensuring the full unlinked form is absent.

No objections or open questions have surfaced. The series is under review and appears uncontroversial, with no dependencies on other work. If the patches hold up to scrutiny, they should resolve the issue cleanly.
