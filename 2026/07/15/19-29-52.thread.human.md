This thread is about a bugfix refactoring in Git’s revision-walking machinery, specifically cleaning up the `get_commit_action()` function in `revision.c`. The patch, authored by Michael Montalbo, addresses a latent impurity where the function—nominally a predicate—mutates tracked line ranges when used with `git log -L` (line-level log) without parent rewriting. This side effect violates the function’s intended purity and could cause issues for future callers, such as the in-flight commit graph feature.

The refactoring moves the mutation logic to `simplify_commit()`, ensuring `get_commit_action()` becomes a pure function. Junio C Hamano has reviewed the patch in detail, confirmed its correctness, and accepted the defensive programming rationale. The patch is now queued for integration, though its future may still depend on broader consensus about whether its size (~100 lines) and risk are justified for a preemptive fix. Key changes include a new helper function, `commit_early_ignore()`, which preserves the original behavior while avoiding unnecessary work. Test coverage verifies that `get_commit_action()` no longer mutates commit flags when called out-of-order, using a new `line-log-peek` subcommand. The patch touches `revision.c`, `test-revision-walking.c`, and `t4211-line-log.sh`, but introduces no user-visible changes—it’s purely an internal cleanup to make the code safer for future extensions.
