This thread is about a refactoring patch by Michael Montalbo that cleans up a long-standing impurity in Git's revision-walking machinery. The focus is on `get_commit_action()` in `revision.c`, which historically acted as a predicate to decide whether a commit should be shown but also had a hidden side effect: it mutated tracked line ranges when used with `git log -L` (line-level log) without parent rewriting. This made the function unsafe for out-of-order evaluation, such as in lookahead scenarios.

Montalbo's patch moves the line-range mutation logic out of `get_commit_action()` and into `simplify_commit()`, where it runs before the predicate check. A new helper, `commit_early_ignore()`, factors out cheap checks (like whether a commit is already shown or uninteresting) to avoid unnecessary processing. The result is that `get_commit_action()` is now a pure predicate, which is its intended role and a requirement for callers like the commit graph renderer. The patch includes a new test subcommand, `line-log-peek`, to verify that `get_commit_action()` no longer mutates commit flags when called out of order, along with a corresponding test in `t4211-line-log.sh`.

The change is well-motivated and clearly explained, with a commit message that provides historical context and justifies the implementation trade-offs. It’s a mechanical, localized refactoring that doesn’t change user-visible behavior but makes the code safer for future extensions, such as lookahead optimizations. The patch is part of a broader effort to clean up the revision-walking internals but stands alone as a self-contained improvement. No reviews or objections have been posted yet, so the discussion is still open.
