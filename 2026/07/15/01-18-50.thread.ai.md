Subject: [PATCH] repository: move `fetch_if_missing` into `struct repository`
Series version: standalone patch (part of libification and `the_repository` removal efforts)
Originating author: Tian Yuchen <cat@malon.dev>
Thread type: patch submission

Core problem or goal
Move the global `fetch_if_missing` variable into `struct repository` to make it a per-repository flag controlling whether missing objects should trigger lazy fetches from promisor remotes. This continues the project-wide effort to eliminate global state in favor of repository-specific configuration, preserving existing behavior (default value remains `1`, enabled).

Current status
Under review; awaiting v2. Junio C Hamano identified a critical correctness issue in `setup.c` where the patch hardcodes `the_repository->fetch_if_missing` instead of using the passed `repo` parameter, breaking per-repository behavior. The author has acknowledged the issue and confirmed the fix will be mechanical (`repo->fetch_if_missing = 0`). No other changes are planned.

Key technical details
- **Files touched**: 15 files, including `odb.c`, `repository.c`, `fetch-pack.c`, `fsck.c`, `index-pack.c`, `revision.c`, `setup.c`, and partial clone documentation.
- **New symbols**: `struct repository->fetch_if_missing` (replaces global `fetch_if_missing`).
- **Behavior**: Default value remains `1` (enabled); initialization occurs in `initialize_repository()`. Special handling in `fsck` and `index-pack` avoids null pointer dereferences during early option parsing. `revision.c` adds a `BUG()` check to enforce that `--exclude-promisor-objects` can only be used when `fetch_if_missing` is disabled.
- **On-disk format**: No changes.
- **Test coverage**: No new tests; existing behavior is preserved, but the correctness issue in `setup.c` suggests multi-repository scenarios may not have been tested. Future revisions should verify per-repository behavior.

Open questions and loose ends
