Thread identity
Subject: [PATCH] repository: move `fetch_if_missing` into `struct repository`
Series version: standalone patch (part of libification and `the_repository` removal efforts)
Originating author: Tian Yuchen <cat@malon.dev>
Thread type: patch submission

Core problem or goal
Move the global `fetch_if_missing` variable into `struct repository` to make it a per-repository flag controlling whether missing objects should trigger lazy fetches from promisor remotes. This continues the project-wide effort to eliminate global state in favor of repository-specific configuration, preserving existing behavior (default value remains `1`, enabled).

Current status
Under review; awaiting v2. Junio C Hamano identified a critical correctness issue in `setup.c` where the patch hardcodes `the_repository->fetch_if_missing` instead of using the passed `repo` parameter, breaking per-repository behavior. Patrick Steinhardt raised additional concerns about potential behavior changes in `builtin/index-pack.c` and `revision.c` when repositories other than `the_repository` are used. The author has acknowledged the `setup.c` issue and confirmed the fix will be mechanical (`repo->fetch_if_missing = 0`), but has not yet addressed Patrick's concerns. No other changes are planned.

Key technical details
- **Files touched**: 15 files, including `odb.c`, `repository.c`, `fetch-pack.c`, `fsck.c`, `index-pack.c`, `revision.c`, `setup.c`, and partial clone documentation.
- **New symbols**: `struct repository->fetch_if_missing` (replaces global `fetch_if_missing`).
- **Behavior**: Default value remains `1` (enabled); initialization occurs in `initialize_repository()`. Special handling in `fsck` and `index-pack` avoids null pointer dereferences during early option parsing. `revision.c` adds a `BUG()` check to enforce that `--exclude-promisor-objects` can only be used when `fetch_if_missing` is disabled.
- **Edge cases**: Patrick Steinhardt highlighted two potential behavior changes:
  1. In `index-pack.c`, the new logic (`repo->fetch_if_missing = 0`) might alter behavior when the command runs without a repository (falling back to `the_repository`).
  2. In `revision.c`, the patch assumes the repository passed to `revs->repo` controls `fetch_if_missing`, but the codebase still uses `the_repository` in many places, creating unpredictable interactions.
- **On-disk format**: No changes.
- **Test coverage**: No new tests; existing behavior is preserved, but the correctness issues in `setup.c` and Patrick's concerns suggest multi-repository scenarios may not have been tested. Future revisions should verify per-repository behavior, especially in `index-pack` and `revision`.

Open questions and loose ends
- **Critical correctness issue in `setup.c`**: Resolved in principle; the fix is mechanical and uncontroversial (`repo->fetch_if_missing = 0`).
- **Behavior changes in `index-pack.c` and `revision.c`**: Patrick Steinhardt's concerns remain unresolved. The author has not yet addressed whether the patch could introduce regressions in these subsystems.
- **Testing**: The oversight in `setup.c` and Patrick's questions raise doubts about whether the patch was tested with repositories other than `the_repository`. The author has not explicitly addressed this, but the fixes are expected to be straightforward.
