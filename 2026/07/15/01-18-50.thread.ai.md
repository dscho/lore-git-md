Subject: [PATCH] repository: move `fetch_if_missing` into `struct repository`
Series version: standalone patch (part of libification and `the_repository` removal efforts)
Originating author: Tian Yuchen <cat@malon.dev>
Thread type: patch submission

Core problem or goal
Move the global `fetch_if_missing` variable into `struct repository` to make it a per-repository flag controlling whether missing objects should trigger lazy fetches from promisor remotes. This continues the project-wide effort to eliminate global state in favor of repository-specific configuration, preserving existing behavior (default value remains `1`, enabled).

Current status
Under review; no prior versions of this specific patch have been posted. The change is part of the broader `the_repository` removal initiative and libification effort, both of which are ongoing and have seen multiple related patches in recent months.

Key technical details
- **Files touched**: 15 files, including `odb.c`, `repository.c`, `fetch-pack.c`, `fsck.c`, `index-pack.c`, `revision.c`, and partial clone documentation.
- **New symbols**: `struct repository->fetch_if_missing` (replaces global `fetch_if_missing`).
- **Behavior**: Default value remains `1` (enabled); initialization occurs in `initialize_repository()`.
- **Edge cases**: Special handling in `fsck` and `index-pack` to avoid null pointer dereferences during early option parsing; `revision.c` adds a `BUG()` check to enforce that `--exclude-promisor-objects` can only be used when `fetch_if_missing` is disabled.
- **On-disk format**: No changes.
- **Test coverage**: No new tests; existing behavior is preserved, so no test failures are expected.

Open questions and loose ends
None identified in the patch or summary. The patch is purely a refactoring with preserved semantics, and no design objections or requests for changes have been raised yet.
