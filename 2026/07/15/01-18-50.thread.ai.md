Subject: [PATCH v2] repository: move `fetch_if_missing` into `struct repository`
Series version: v2 (standalone patch, part of libification and `the_repository` removal efforts)
Originating author: Tian Yuchen <cat@malon.dev>
Thread type: patch submission

Core problem or goal
Move the global `fetch_if_missing` variable into `struct repository` to make it a per-repository flag controlling whether missing objects should trigger lazy fetches from promisor remotes. This continues the project-wide effort to eliminate global state in favor of repository-specific configuration, preserving existing behavior (default value remains `1`, enabled).

Current status
Under review; v2 posted addressing all prior feedback. Junio C Hamano identified a critical correctness issue in `setup.c` in v1 (hardcoded `the_repository->fetch_if_missing` instead of using the passed `repo` parameter); this is now fixed with `repo->fetch_if_missing = 0`. Patrick Steinhardt raised concerns about potential behavior changes in `builtin/index-pack.c` and `revision.c` when repositories other than `the_repository` are used; the author has retained `the_repository` in both subsystems to avoid unintended interactions. No further objections or requests for changes have been raised; the patch is now awaiting maintainer pickup.

Key technical details
- **Files touched**: 15 files, including `odb.c`, `repository.c`, `fetch-pack.c`, `fsck.c`, `index-pack.c`, `revision.c`, `setup.c`, and partial clone documentation.
- **New symbols**: `struct repository->fetch_if_missing` (replaces global `fetch_if_missing`).
- **Behavior**: Default value remains `1` (enabled); initialization occurs in `initialize_repository()`. Special handling in `fsck.c` and `index-pack.c` avoids null pointer dereferences during early option parsing. `revision.c` adds a `BUG()` check to enforce that `--exclude-promisor-objects` can only be used when `fetch_if_missing` is disabled. The patch retains `the_repository` in `builtin/index-pack.c` and `revision.c` to preserve existing behavior when these commands run without an explicit repository or when the passed repository differs from `the_repository`.
- **Edge cases**: The `setup.c` fix (`repo->fetch_if_missing = 0`) is mechanical and uncontroversial. The decision to retain `the_repository` in specific subsystems is a pragmatic compromise to avoid regressions.
- **On-disk format**: No changes.
- **Test coverage**: No new tests; existing behavior is preserved. The correctness issues in `setup.c` and Patrick's concerns about multi-repository scenarios have been addressed, but explicit testing of per-repository behavior (especially in `index-pack` and `revision`) remains unconfirmed.

Open questions and loose ends
- **Testing**: The author has not provided explicit confirmation that the patch was tested with repositories other than `the_repository`. While the fixes address the raised concerns, the absence of new test coverage or multi-repository verification leaves a minor risk of undetected regressions.
- **Design preference**: Patrick Steinhardt previously suggested moving the flag into the object database rather than `struct repository`, but acknowledged the current approach aligns with libification goals. This remains a point of discussion but is not blocking.
