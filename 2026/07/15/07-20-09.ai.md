This is a refactoring patch in the ongoing effort to eliminate misuse of `object.flags` in Git. Junio C Hamano reviews Gatla Vishweshwar Reddy’s v3 patch, which converts `builtin/show-branch.c` to use a commit-slab (`commit_rev_flags`) with a configurable stride of `uint64_t` words, lifting the previous 27-branch limit to 64 branches.

Junio’s feedback is narrow and actionable: the patch should retain the existing TODO comment (which references his earlier suggestion to eventually store ref names directly in the slab) until that follow-up work is done, but it should immediately remove the local `#define UNINTERESTING` and instead use the common definition from `<revision.h>`. This change is purely mechanical and does not affect the patch’s core logic or behavior. The patch remains uncontested on its technical merits; the only remaining work is to address this small cleanup before it is ready for maintainer sign-off.
