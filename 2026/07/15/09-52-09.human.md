This is the first patch in the eighteenth and final iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. The series is now queued for merging to `next` after resolving all technical and administrative issues from earlier versions.

This specific patch fixes a memory leak in the transport helper subsystem. The `disconnect_helper()` function in `transport-helper.c` only freed the `data->name` field if the helper had fully started (`data->helper` was non-NULL). When a transport is disconnected before the helper is fully initialized, `data->name`—allocated in `transport_helper_init()`—was never freed. The fix moves `FREE_AND_NULL(data->name)` outside the conditional block so it executes unconditionally during disconnect. The change is minimal (one line moved) and clearly correct, addressing a leak that could accumulate over repeated transport operations.

The patch is part of a larger effort to ensure memory safety across the new `remote-object-info` feature, which allows querying object metadata from remotes without downloading full objects. While this leak is not directly tied to the new functionality, fixing it aligns with the series' focus on robustness and security. The fix has been stable since its introduction in v16 and carries `Mentored-by` trailers from Karthik Nayak and Chandra Pratap, indicating oversight from experienced contributors.

This is a straightforward bugfix with no behavioral impact—users won’t notice the change, but it prevents gradual memory growth in long-running Git processes. The patch is uncontroversial and ready for integration.
