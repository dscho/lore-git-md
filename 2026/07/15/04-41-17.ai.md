This is a refactoring patch from René Scharfe targeting the `remote-curl` transport code.

The patch simplifies how push specifications are passed to the HTTP transport handlers (`push_dav` and `push_git`). Currently, the code tracks both the array of push specs and its item count (`nr_spec`), converting between `size_t` and `int` as needed. René observes that the array is already NULL-terminated (as all `strvec` arrays are), so the count is redundant. The patch removes the `nr_spec` parameter entirely and updates the callers to pass only the array, letting the callee iterate until it hits the NULL terminator.

The change touches three functions: `push_dav`, `push_git`, and `push`. In `push_dav`, the loop over `nr_spec` is replaced with `strvec_pushv`, which copies the entire NULL-terminated array. In `push_git`, the loop is rewritten to iterate until `*specs` is NULL. The top-level `push` function drops the count argument and passes only the array to the protocol-specific handlers.

The diff is small (9 insertions, 11 deletions) and confined to `remote-curl.c`. No behavior change is claimed or apparent; this is purely a code hygiene improvement. René’s patches are typically clean and mechanical, and this one fits that pattern.
