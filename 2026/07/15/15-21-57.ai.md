This is patch 3/9 in Phillip Wood’s **approved, ready-for-`next`** 9-patch series fixing the sequencer’s handling of dropped commits during rebase. It is a **bugfix** targeting the sequencer subsystem.

The patch addresses a specific edge case: when `git commit` fails to execute (e.g., due to a missing executable or permission error), `run_git_commit()` returns `-1`, which the sequencer incorrectly interprets as a signal to reschedule the current command. This is wrong because the commit pick itself succeeded—only the final `git commit` invocation failed. The fix converts `-1` to `1` (matching `do_merge()`’s behavior), ensuring the sequencer does not reschedule the command unnecessarily.

The change is minimal—six lines added to `sequencer.c`—and aligns with the series’ broader goal of ensuring the sequencer accurately tracks the outcome of each pick operation. The commit message clearly explains the rationale and the connection to `do_merge()`. Oswald Buddenhagen’s **surface-level review** of this patch focused on phrasing ("different to" vs. "different from"), which Phillip acknowledged and incorporated as a typofix.

This patch is part of the systemic overhaul’s error-handling improvements, complementing patch 2/9 (external merge strategy failures) and patch 9/9 (core dropped-commit fix). No further changes are expected before the series advances to `next`. The fix is well-motivated, narrowly scoped, and directly addresses a real (if rare) failure mode in the rebase machinery.
