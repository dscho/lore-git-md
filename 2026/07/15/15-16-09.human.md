This is the first patch in Harald Nordgren’s **v9 series** introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. This patch is a **pure refactoring** with no behavior change: it extracts the repeated logic for resolving a commit’s first-parent tree (or the empty tree for a root commit) into a new helper, `first_parent_tree_oid()`.

The helper consolidates three nearly identical code blocks in `builtin/history.c` that parse a commit’s first parent, handle parse errors, and copy the parent’s tree OID. The new function is straightforward—taking a `struct repository *`, a `struct commit *`, and an output `struct object_id *`—and returns an error if the parent cannot be parsed. This cleanup reduces duplication and makes the code easier to maintain, particularly as the `squash` subcommand evolves.

The patch is **uncontroversial** and ready to merge. It touches only `builtin/history.c` (26 insertions, 32 deletions) and is a mechanical extraction with no functional impact. The helper will be used in later patches to support the `--reedit-message` feature and other squash-related logic. This is a typical first step in a larger series, ensuring the foundation is clean before adding new functionality.
