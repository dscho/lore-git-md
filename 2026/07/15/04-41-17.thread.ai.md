Thread identity: Refactoring of `remote-curl` transport code to simplify push specification handling. Series version: standalone patch (potential v2 pending). Originating author: René Scharfe.

Core problem or goal: Eliminate redundant tracking of the push specification array count (`nr_spec`) in the HTTP transport handlers (`push_dav` and `push_git`). The array is already NULL-terminated (as all `strvec` arrays are), so the count is unnecessary and requires error-prone conversions between `size_t` and `int`. Patrick Steinhardt additionally suggests refining the interface to pass a `const struct strvec *` instead of a raw `const char **` to make the NULL-termination guarantee explicit and align with caller context.

Current status: Under review. No prior versions. The patch is a standalone refactoring with no behavior change, but Patrick’s feedback may prompt a v2 if René adopts the `strvec *` interface.

Key technical details:
- Files touched: `remote-curl.c` only.
- Functions modified: `push_dav`, `push_git`, and `push`.
- New behavior: Callers now pass only the NULL-terminated `strvec` array to protocol handlers; handlers iterate until NULL terminator instead of relying on a count. Patrick proposes passing the entire `strvec` struct to make the interface more self-documenting.
- Old behavior: Handlers received both the array and its item count (`nr_spec`), requiring conversions between `size_t` and `int`.
- No new symbols, CLI options, config keys, or on-disk format changes.
- Test coverage: None added; the change is internal to the transport layer and does not affect observable behavior. No test failures or performance regressions reported.

Open questions and loose ends: Whether to adopt Patrick’s suggestion to pass a `const struct strvec *` instead of a raw `const char **`. This is a design-level question about interface clarity and future extensibility (e.g., for a hypothetical `strvec_pushvec()` optimization), not a correctness issue. No other open questions or edge cases identified.

Participant positions:
