Thread identity: Refactoring of `remote-curl` transport code to simplify push specification handling. Series version: standalone patch. Originating author: René Scharfe.

Core problem or goal: Eliminate redundant tracking of the push specification array count (`nr_spec`) in the HTTP transport handlers (`push_dav` and `push_git`). The array is already NULL-terminated (as all `strvec` arrays are), so the count is unnecessary and requires error-prone conversions between `size_t` and `int`.

Current status: Under review. No prior versions. The patch is a standalone refactoring with no behavior change.

Key technical details:
- Files touched: `remote-curl.c` only.
- Functions modified: `push_dav`, `push_git`, and `push`.
- New behavior: Callers now pass only the NULL-terminated `strvec` array to protocol handlers; handlers iterate until NULL terminator instead of relying on a count.
- Old behavior: Handlers received both the array and its item count (`nr_spec`), requiring conversions between `size_t` and `int`.
- No new symbols, CLI options, config keys, or on-disk format changes.
- Test coverage: None added; the change is internal to the transport layer and does not affect observable behavior.

Open questions and loose ends: None identified. The patch is purely mechanical and does not introduce new design questions or edge cases.

Participant positions: None yet recorded. René’s patches are typically uncontroversial and focus on code hygiene, so substantive objections are unlikely.

Related work: Part of the broader ongoing effort to clean up redundant or error-prone patterns in Git’s codebase (e.g., `the_repository` removal, test modernization). This patch aligns with René’s recurring focus on eliminating unnecessary complexity.
