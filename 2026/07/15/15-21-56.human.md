This is a **bugfix patch** in Phillip Wood’s 9-patch series (v3, 2/9) that tightens error handling in the sequencer when an external merge strategy fails. The patch addresses a specific edge case: if an external merge tool exits with a non-zero code other than 1 (e.g., because it would overwrite an untracked file or crash), Git currently treats it the same as a conflict (exit code 1). This is wrong—such failures should cause the rebase to reschedule the pick rather than proceeding as if the merge succeeded with conflicts.

The fix is surgical: it adds a guard to bail out early if the commit message cannot be written, and it distinguishes between exit code 1 (conflicts) and other non-zero codes (unrecoverable failures). The patch also adds a test in `t3404-rebase-interactive.sh` that verifies the rescheduling behavior by injecting a merge tool that exits with code 2.

This is a **well-motivated, narrowly scoped change** that plugs a real hole in the rebase machinery. The test coverage is solid, and the commit message clearly explains the rationale. It is part of a larger, already-approved series that Junio has marked ready for `next` after minor typofixes are squashed. No controversy or open questions remain for this patch.
