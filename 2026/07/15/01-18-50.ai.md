This patch is part of the ongoing libification effort and the broader `the_repository` removal initiative. It moves the global `fetch_if_missing` variable into `struct repository`, making it a per-repository flag that controls whether missing objects should trigger lazy fetches from promisor remotes. The default value remains `1` (enabled), preserving existing behavior.

The change touches 15 files, primarily updating call sites to use the repository-specific flag instead of the global variable. Most updates are mechanical, but two built-ins (`fsck` and `index-pack`) require special handling to avoid null pointer dereferences when the repository pointer isn't available during early option parsing. The patch also updates the partial clone documentation to reflect the new per-repository nature of the flag.

Key technical details include:
- The flag is initialized in `initialize_repository()` and defaults to `1`.
- The `odb.c` logic for promisor remote fetches now checks `odb->repo->fetch_if_missing`.
- The `revision.c` code includes a `BUG()` check to enforce that `--exclude-promisor-objects` can only be used when `fetch_if_missing` is disabled.
- Files modified span core plumbing (`odb.c`, `repository.c`), built-ins (`fetch-pack`, `fsck`, `index-pack`, etc.), and documentation.

The patch appears well-structured for its scope, with clear commit message rationale and attention to edge cases like early option parsing. It continues the established pattern of eliminating globals in favor of repository-specific state, which is a recurring theme in recent Git development. No test failures or behavioral changes are expected, as this is purely a refactoring with preserved semantics.
