This is the seventh patch in Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. The patch adds a missing error check for `dup(helper->in)` in `get_exporter()` in `transport-helper.c`. Previously, a failed `dup()` (returning `-1`) would silently miswire the `fast-export` child process’s output, breaking data flow between the helper and the exporter. The fix propagates the error upward with `error_errno()`, aligning with the series’ goal of hardening code paths against silent failures.

Patrick Steinhardt’s review confirms the patch is correct and notes that the only caller (`push_refs_with_export()`) already handles non-zero return values by dying, so the new error check integrates cleanly with the existing control flow. This is a mechanical, uncontroversial fix with no new symbols or behavior changes; it only adds a guard against an edge case that could otherwise lead to data loss or corruption in transport operations. The transport-helper subsystem is involved in remote operations, so this fix is relevant to users of `git push` or `git fetch` with custom helpers.

The patch is part of a broader effort to address Coverity-flagged unchecked return values across multiple subsystems. Junio C Hamano has raised substantive correctness concerns in two other patches in the series (fifth and ninth), but this patch has no open questions or loose ends. The review depth here is surface-level but sufficient, as the change is straightforward and the existing caller’s error handling already covers the new failure mode.
