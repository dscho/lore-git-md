This is a mature, well-tested feature addition to the submodule and fetch subsystems. The v5 iteration of Paulius Zaleckas’s two-patch series makes submodule fetch errors configurable, allowing users to choose between the current hard failure (`fail`) or a warning-only mode (`warn`) when `git fetch --recurse-submodules` encounters a submodule whose gitlink points to an unreachable OID.

The series directly addresses a real workflow pain point: upstream topic branches that are still in flux can disrupt fetches even when the local branch doesn’t depend on the missing commits. Patch 1 fixes a pre-existing logic flaw in `submodule.c` where phase-1 fetch failures were recorded prematurely, before phase-2 OID-based retries could run. This refactoring ensures errors are only recorded after all retry attempts fail, preserving the current fatal behavior while enabling the configurable policy introduced in Patch 2. The fix is technically sound and necessary for the feature to work correctly.

Patch 2 introduces `fetch.submoduleErrors` (config) and `--submodule-errors=(fail|warn)` (CLI), defaulting to `fail` for backwards compatibility. The implementation routes all submodule fetch errors through `record_fetch_error()`, forwards the setting to child fetches (including `--all`/`--multiple` and nested recursion), and includes thorough test coverage in `t/t5526-fetch-submodules.sh`. v5 incorporates Junio C Hamano’s feedback by using `test_grep` instead of raw `grep` in tests, parsing and formatting the `fail`/`warn` values through a single shared name array (ensuring case-sensitive matching), and properly crediting Jean-Noël Avila for earlier documentation fixes.

The series touches `submodule.c`, `builtin/fetch.c`, documentation files, and the test suite. The commit messages are clear, the rationale is well-explained, and the implementation appears robust. No open technical questions remain, and the changes are narrowly scoped to the submodule fetch error-handling path. This looks like a polished, uncontroversial contribution that addresses a genuine user need without introducing broader risks. The series is under active review and appears ready for merging.
