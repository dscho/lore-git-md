This is the sixth patch in the nine-patch `diff.<driver>.process` RFC series (v5). It ensures the new process-based diff driver respects existing Git conventions for disabling external tools.

The patch makes `--no-ext-diff` disable both the traditional `diff.<driver>.command` and the new `diff.<driver>.process`. Although the two mechanisms work differently (command replaces Git's output entirely, while process feeds hunks back into the pipeline), the patch treats them as equivalent from the user's perspective: both invoke external tools, and `--no-ext-diff` means "no external tools." The implementation replaces the simple OPT_BOOL for `--ext-diff` with an OPT_CALLBACK that sets both `allow_external` and `no_diff_process`, so a single option controls both. This also ensures that `--ext-diff` can override an earlier `--no-ext-diff`.

The patch also disables the diff process unconditionally in `format-patch`, so generated patches are always based on the builtin diff algorithm and can be applied reliably by recipients who do not have the external tool. The documentation is updated to reflect that `--diff-algorithm` and `--no-ext-diff` both bypass the process, and that whitespace-ignoring options do the same. The test coverage is expanded with two new cases: one verifying that `--no-ext-diff` bypasses the process, and another confirming that `format-patch` does not use it.

This is a straightforward housekeeping patch that aligns the new feature with Git's existing behavior. The changes are small (16 lines of C, 16 lines of test) and well-motivated. The patch addresses a minor but important edge case: users who rely on `--no-ext-diff` to avoid external tools should not be surprised by the new process driver. The implementation is clean and the documentation is clear. No controversy is expected.
