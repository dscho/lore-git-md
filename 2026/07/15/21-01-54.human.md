This is the first patch in the nine-part `diff.<driver>.process` RFC series, now in its fifth revision. It is a documentation patch that clarifies the limitations of the existing `diff.<driver>.command` mechanism. The commit adds a new section to `gitattributes(5)` explaining that an external diff driver replaces only the textual patch Git would produce, and that downstream features like word diff, function context (`-W`), `--color-moved`, and syntax coloring do not apply to the driver’s output. It also notes that summary formats (`--stat`, `--numstat`, `--shortstat`, `--dirstat`), `git blame`, and `git log -L` do not consult the external driver at all and continue to use Git’s builtin diff.

The patch is straightforward and well-motivated: it sets the stage for the rest of the series by making the current behavior explicit, so readers can understand why the new `diff.<driver>.process` mechanism (introduced in later patches) is needed. The prose is clear and the scope is narrowly focused on the existing `command` driver, avoiding any forward references to the process driver. This is a sensible preparatory step that should help reviewers and users alike.
