This is the first patch in the v5 series introducing `diff.<driver>.process`, a new mechanism for external tools to inject diff hunks into Git's diff and blame pipelines. This specific patch is a documentation update to `gitattributes(5)` that clarifies the limitations and scope of the existing `diff.<driver>.command` feature, which this series will soon complement.

The patch adds a new explanatory paragraph to the "Defining an external diff driver" section, explicitly stating that an external diff driver configured via `diff.<driver>.command` *replaces* Git's textual patch output but does not integrate with downstream features like word diff, function context (`-W`), `--color-moved`, or coloring. It also notes that summary formats (`--stat`, `--numstat`, `--shortstat`, `--dirstat`), `git blame`, and `git log -L` do not consult the external driver at all and continue to use Git's builtin diff. This documentation is preparatory: it sets the stage for the subsequent patches, which will introduce the `diff.<driver>.process` driver that *does* integrate with these features.

The change is small (10 lines) and purely additive, addressing a long-standing gap in the documentation. The commit message is clear and to the point, and the patch itself is uncontroversial. This is not the main event of the series -- the real action starts in patch 2 -- but it is a necessary foundation for the later patches that contrast the new process driver with the existing command driver. The patch is well-motivated and should be non-controversial.
