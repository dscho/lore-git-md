This is patch 2/9 in Phillip Wood’s approved nine-patch series fixing how the sequencer handles dropped commits during rebase. It is a **bugfix** that tightens error handling for external merge strategies.

The patch addresses a long-standing edge case: when an external merge tool exits with a non-zero code other than 1 (for example, because it would overwrite an untracked file or crash), the sequencer currently treats it the same as a conflict (exit code 1). This is wrong—an unrecoverable failure should reschedule the pick, not leave the rebase in a conflicted state. The patch also adds a guard to reschedule the pick if the commit message cannot be written, since that prevents the commit from being created.

The change is minimal: in `sequencer.c`, `do_pick_commit()` now checks the exit code of `try_merge_command()`. If it is neither 0 (success) nor 1 (conflict), the function returns -1, which tells the caller to reschedule the pick. The test in `t3404-rebase-interactive.sh` verifies that a merge tool exiting with code 2 (simulated by a script) leaves the todo list unchanged, proving the pick was rescheduled.

This patch is part of the systemic audit of rebase-dropped-commit handling; it plugs a specific leak where external merge failures could corrupt the rebase state. The fix is narrow, well-tested, and uncontroversial. Oswald Buddenhagen’s review was surface-level (grammar and punctuation), and those suggestions have been queued as typofixes. No substantive objections remain. The series is approved and ready for `next`.
