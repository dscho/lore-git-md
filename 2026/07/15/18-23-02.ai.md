This is Junio C Hamano's review of the final patch (4/4) in Tian Yuchen's v5 series migrating `has_symlinks` into `struct repo_config_values`. The review is substantive, focusing on the mingw compatibility layer's design.

Junio identifies a potential design issue: the introduction of a global fallback variable (`default_has_symlinks`) could encourage misuse by other parts of the codebase. Instead, he proposes a cleaner pattern modeled after `is_dir_sep()` and similar platform-specific macros. His alternative uses a compile-time macro (`platform_has_symlinks()`) that defaults to `1` but can be overridden by platform-specific headers (e.g., `compat/mingw.h`). The mingw implementation would then define its own function (`mingw_platform_has_symlinks()`) to encapsulate the logic for detecting native symlink support via environment variables.

The suggestion preserves the patch's goal of eliminating global state while avoiding the pitfalls of a mutable global variable. It also aligns with Git's existing conventions for platform-specific overrides. This feedback does not block the series but addresses a technical debt concern that could affect future maintainability. The author will likely need to revise the mingw compatibility layer to adopt this pattern before the patch can advance.
