This is the final review exchange in the long-running GSoC series that implements `git cat-file --batch-command`'s `remote-object-info` feature. The series is at v18, functionally complete, and queued for merging to `next`, with only minor robustness issues left to resolve.

Junio’s review here focuses on the last patch (13/13), which replaces the hard-coded allow-list for format placeholders (`%(objectname)`, `%(objectsize)`) with a dynamic system that adapts to what the server actually advertises. The change is well-motivated: it future-proofs the client for servers that may support only a subset of metadata fields (e.g., `size` but not `type`), and it prevents segfaults by ensuring clients never request unsupported fields. The implementation is clean, with runtime population of `remote_allowed_atoms` based on the server’s advertised capabilities, and it aligns with `for-each-ref`’s behavior of returning empty strings for unsupported atoms rather than raising errors.

Junio raises two technical points. First, he asks for a concrete example in the commit message to clarify how unsupported placeholders are handled. The current text implies that if a client requests `%(objectsize) %(objectcolor)` but the server only supports `size`, the output would be `42 %(objectcolor)`—a behavior that might surprise users. Pablo should clarify whether this is intentional or if unsupported placeholders should be omitted entirely. Second, Junio notes a pre-existing inefficiency: if the caller requests only `%(objectname)` (which requires no remote query), `get_remote_info()` still establishes a connection but skips the actual fetch, leaving the client unaware of whether the objects exist on the remote. This is a minor optimization opportunity but not a blocker for merging.

The patch itself is technically sound and addresses the last major design limitation in the series. The dynamic allow-list system is a necessary foundation for extensibility, and the changes are self-contained and memory-safe. Junio’s feedback is surface-level (clarity and edge-case behavior) rather than substantive, and the series remains on track for integration once these points are addressed. For a busy reader, this is a low-risk, high-value feature that’s nearly ready to ship.
