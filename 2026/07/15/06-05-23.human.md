This is a bugfix patch from Jeff King (Peff) that prevents a segfault in `git diff` when using `--relative` and `--cached` together on unmerged paths outside the current directory.

The bug occurs because `diff_unmerge()` returns NULL for paths outside the prefix, but the caller in `do_oneway_diff()` tries to use that NULL value without checking. Peff traces the regression back to 2011 (commit 76399c0195) and notes that a similar issue was fixed for non-cached diffs in 2021, but the `--cached` case was missed. The fix is minimal: just check for NULL before calling `fill_filespec()`.

The patch includes a test that piggybacks on existing coverage for the non-cached case, verifying that `--relative --cached` now works when there are unmerged changes in a subdirectory. Peff also muses about a possible larger refactoring to check paths earlier in `oneway_diff()`, but opts for the smallest fix here to avoid regressions.

This looks like a clean, well-motivated fix for a real crash. The commit message is thorough, the test is clear, and the change is minimal. Worth attention if you use `git diff --relative --cached` in repositories with unmerged paths.
