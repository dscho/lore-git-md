This is the fifth revision of the `diff.<driver>.process` RFC series, now expanded to nine patches. The series introduces a long-running subprocess protocol that lets external tools inject diff hunks into Git's diff and blame pipelines while preserving downstream features like word diff, function context, and color-moved. This version adds three major new capabilities: `--stat`/`--numstat`/`--shortstat` now consult the process (patch 8), `git log -L` range tracking does too (patch 9), and the protocol now carries the old and new blob object names (old-oid/new-oid) so tools can cache their analysis keyed on the blob pair.

The preparatory documentation patch (patch 1) now explicitly contrasts the new process driver with the existing `diff.<driver>.command`, clarifying that the command driver replaces Git's output entirely while the process driver feeds results back into the standard pipeline. The series also adds a "Which features consult the diff process" section in `gitattributes(5)` that lays out which features use the tool's hunks, which compute independently, and why. This version addresses all remaining technical concerns from previous rounds: the hunk validation now checks per-gap alignment (not just total unchanged line counts), the protocol accepts start=0 with count=0 for empty file sides, and the test backend has been rewritten in C per project norms.

The blame integration (patch 7) demonstrates the key use case: a tool can declare commits as having no semantic changes, causing blame to skip them and attribute lines to earlier commits. The series maintains robust error handling: malformed tool responses trigger warnings and fallbacks to the builtin diff algorithm, and the subprocess API has been refactored to separate process lifecycle from hashmap management (patch 4). The test coverage is comprehensive (950+ lines in `t/t4080-diff-process.sh`), exercising success paths, error conditions, and edge cases like trailing-newline-only changes and whitespace-ignoring flags that bypass the process.

All substantive review feedback from v4 has been addressed, including Windows compatibility and the transition to a C-based test helper. The series is now technically complete and ready for final maintainer sign-off. The only remaining work is documentation refinements around flag behavior interactions, which should not block merging. The implementation demonstrates careful attention to backward compatibility, performance considerations (noting the ~17% overhead in blame operations), and protocol forward-compatibility (ignoring unknown trailing fields in hunk lines).
