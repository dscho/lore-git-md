This is a refactoring patch in the ongoing effort to eliminate misuse of `object.flags` in Git. Junio C Hamano reviews Gatla Vishweshwar Reddy’s v3 patch, which converts `builtin/show-branch.c` to use a commit-slab for per-commit state instead of the shared `object.flags` field. The patch is nearly ready but has two small issues: it prematurely removes a TODO comment that should remain until the slab is extended to store ref names directly, and it keeps a redundant local `#define UNINTERESTING` instead of using the common definition from `revision.h`. These are straightforward fixes that do not affect the core logic. The patch otherwise lifts the 27-branch limit to 64 branches by using a configurable `uint64_t` stride, aligns with Git’s canonical pattern for per-commit data storage, and preserves existing behavior. Gatla’s next revision should address these nits and is likely to receive maintainer sign-off once done.
