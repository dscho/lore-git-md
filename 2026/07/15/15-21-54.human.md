This is a **bugfix series** targeting the sequencer subsystem, part of Phillip Wood’s systemic overhaul to prevent `git rebase` from incorrectly copying notes from dropped commits. This v3 iteration is the final version before the topic is marked ready for `next`.

The series consists of nine patches that methodically refactor the sequencer’s control flow before introducing the core behavioral change in the last patch. Patch 1 restores test coverage for the "apply" backend, which was lost when the default backend switched to "merge". Patches 2 and 3 fix edge cases in external merge strategy handling and command execution failures, ensuring the sequencer correctly reschedules picks when merges fail due to untracked file conflicts or permission errors. Patches 4–7 simplify the logic in `pick_one_commit()`, removing redundant conditions and early returns to make the codebase more maintainable. Patch 8 replaces the integer return value of `do_pick_commit()` with an enum, and patch 9 adds a new `PICK_RESULT_DROPPED` member to prevent dropped commits from being recorded as rewritten.

The key behavioral change is that notes and post-rewrite hooks no longer receive misleading information about commits dropped due to empty changes, fixup sequences, or merge failures. The series also documents a known limitation: the "edit" command still erroneously records dropped commits as rewritten when `rebase --continue` is run, but this is flagged for a separate fix. Test coverage has been expanded in `t3400-rebase.sh`, `t3404-rebase-interactive.sh`, and `t5407-post-rewrite-hook.sh` to catch regressions in both backends and edge cases like external merge failures.
