This is a refactoring patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`. It removes an unused `int` return value from `add_object_entry()` in `builtin/pack-objects.c`, originally authored by Jeff King and lightly edited by Patrick for commit message clarity.

The function historically returned 0 or 1 to indicate whether a new object entry was added, but this behavior has been dead code since 2006 (commit `5379a5c5ee`). The change aligns `add_object_entry()` with its sister function `add_object_entry_from_bitmap()`, which is about to switch to a `void` return type to conform to a callback interface. By removing the unused return value now, the patch clarifies that the two functions have diverged in semantics and avoids future confusion.

The diff is minimal: four lines changed in `builtin/pack-objects.c`, converting the function to `void` and removing redundant `return` statements. No behavior change is expected, and the patch is purely mechanical. Junio C Hamano previously endorsed this cleanup, suggesting it could be squashed into the series or queued independently. It is now integrated as patch 3/9 in v4 of the series, which is otherwise ready for final review and integration.
