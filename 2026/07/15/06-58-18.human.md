This is the second patch in Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. The patch fixes a silent failure in `git config edit` and `git config --edit` by propagating the return value of `launch_editor()` in `show_editor()`. Previously, these commands would exit successfully even if the editor failed to launch; now they return an error, matching the behavior of other Git commands like `git commit`.

Patrick Steinhardt’s review is brief but substantive: he confirms that `launch_editor()` already emits its own error messages, so the patch’s minimal error propagation is correct. The change is uncontroversial, touches only the error path, and requires no new tests or documentation. The fix is a straightforward hardening measure with no behavioral or on-disk format changes.

This patch is ready for integration and does not share the correctness concerns Junio C Hamano raised about the fifth and ninth patches in the series. It is a clean, well-motivated bugfix that aligns with Git’s existing error-handling patterns.
