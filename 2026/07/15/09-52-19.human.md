This is the final patch in the long-running `remote-object-info` feature series, now at v18 and queued for `next`. It adds the `remote-object-info` command to `` `git cat-file --batch-command` ``, allowing users to query object metadata (currently only size) from remote repositories without downloading the full objects.

The patch implements the client-side logic for the new command, which batches multiple object IDs into a single request to avoid remote communication overhead. It supports all three major transport protocols (`git://`, `file://`, and `http://`) and works with both buffered and unbuffered modes. The implementation includes strict input validation (10,000-object batch limit, 8KB URL length limit), protocol v2 enforcement, and dynamic capability-based validation of format placeholders. Currently only `%(objectname)` and `%(objectsize)` are supported, with a warning that the default format may change when `%(objecttype)` support is added.

The 680-line test file (`t/t1017-cat-file-remote-object-info.sh`) exercises every combination of transport, batching mode, and edge case, confirming the command works as intended and does not download objects from the remote. The patch also adds a helper function `free_object_info_contents()` to clean up object info structures and updates the documentation to reflect the new command's behavior and limitations.

This is a well-tested, security-conscious feature that fits cleanly into Git's existing batch-command infrastructure. The series as a whole has addressed all substantive review feedback and is ready for integration.
