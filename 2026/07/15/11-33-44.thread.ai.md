Subject: [PATCH] t7614: avoid suppressing git's exit code in test scripts

Core problem or goal
Fix a latent bug in `t/t7614-merge-signoff.sh` where the exit code of `git cat-file` is lost in a pipe to `sed`, potentially masking crashes or failures. The goal is to ensure the test harness checks the exit codes of both commands by replacing the pipe with an intermediate file and an `&&`-chain.

Current status
Under review. Junio C Hamano reviewed the patch and confirmed the fix is correct. He suggested two follow-up cleanups (removing unnecessary backslash-escaping in `sed` and introducing a helper function for the "cat-file + strip header" pattern) but explicitly stated these are outside the scope of this patch. No objections or requests for changes to the submitted patch have been raised. The patch remains narrowly scoped to the test script and does not affect Git's core functionality.

Key technical details
- File modified: `t/t7614-merge-signoff.sh`
- Commands involved: `git cat-file commit HEAD` and `sed -e "1,/^$/d"`
- Pattern replaced: `git cmd | sed` → `git cmd >file && sed file`
- Test cases affected: three test cases testing `--signoff`, no `--signoff`, and `--signoff --no-signoff` behavior
- New symbols or files: none (intermediate file `commit` is local to the test script)
- Old vs. new behavior: exit codes are now properly checked; no change to test logic or output
- Test coverage: no new tests added; existing test cases now reliably fail if `git cat-file` crashes
- Follow-up opportunities: helper function for "cat-file + strip header" and removing backslash-escaping in `sed` commands
- Related prior work: commit `c6f44e1da5` (t9813: avoid using pipes)
