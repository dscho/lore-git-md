Thread identity: Refactoring of `get_commit_action()` in `revision.c` to eliminate side effects, making it a pure predicate for revision-walking machinery. Series version: standalone patch (no version trailer). Originating author: Michael Montalbo.

Core problem or goal: Remove a long-standing impurity in `get_commit_action()` where the function, while nominally a predicate deciding whether a commit should be shown or ignored, also mutates tracked line ranges when used with line-level log (`git log -L`) without parent rewriting. This side effect makes the function unsafe for out-of-order evaluation (e.g., lookahead scenarios). The goal is to refactor the code so that `get_commit_action()` becomes a pure predicate, moving the mutation logic to `simplify_commit()` where it runs before the predicate check.

Current status: Under review. The patch is a standalone refactoring with no prior versions. It introduces a new helper, `commit_early_ignore()`, to factor out cheap checks (already shown, uninteresting, pack membership) that gate both the mutation and the predicate, ensuring ignored commits are not processed unnecessarily. The patch includes a new test subcommand, `line-log-peek`, added to `test-revision-walking`, and a corresponding test in `t4211-line-log.sh` to verify the function remains side-effect-free.
