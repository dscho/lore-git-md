This is a refactoring patch in the `cat-file` security-hardened series, now at its eighteenth iteration and queued for merging to `next`. The patch moves loop counter declarations inside their `for()` statements for better readability and hygiene, and changes the counter type from `int` to `size_t` where appropriate to avoid signed/unsigned comparison warnings.

Eric Ju originally authored this cleanup, which touches two files: `builtin/cat-file.c` and `fetch-pack.c`. The changes are mechanical and localized—no behavior is altered. In `cat-file.c`, the patch updates three loops: one that dispatches queued commands, one that frees them, and one that parses input commands. In `fetch-pack.c`, it updates the loop that writes server options to the request buffer. The `size_t` type is used where the loop bound is already a `size_t` (e.g., `ARRAY_SIZE()` or `server_options->nr`), eliminating compiler warnings.

This patch is part of the broader effort to integrate `remote-object-info` support into `git cat-file --batch-command`, allowing clients to query object metadata from remotes without downloading full objects. While small, the change contributes to the series' overall goal of clean, maintainable code. The patch has been carried forward unchanged since v16, indicating prior review and validation. Christian Couder is credited with design input.
