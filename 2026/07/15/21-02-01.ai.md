This is the eighth patch in the nine-patch `diff.<driver>.process` RFC series (v5). It wires the external diff process into the `--stat`, `--numstat`, and `--shortstat` summary formats, ensuring these commands now reflect the tool’s view of which lines changed rather than Git’s builtin line diff. The patch also updates the documentation to move these summary formats out of the “not yet wired” group and into the list of features that consult the tool’s hunks, while noting the asymmetry with patch output: unlike `git diff`, the summary formats do not apply textconv, so the tool receives the raw blob content even when a textconv is configured.

The implementation is straightforward: `builtin_diffstat()` now calls `diff_process_fill_hunks()` before running xdiff, just as `builtin_diff()` already does. If the tool reports the files as equivalent (`DIFF_PROCESS_EQUIVALENT`), the xdiff is skipped entirely, leaving the inserted and deleted counts at zero so the file is pruned from the stat output, matching the empty patch that `git diff` would produce. Otherwise, the tool’s hunks (or the builtin fallback) feed the counts through the shared `xpparam_t`. The patch also sends the blob object names (`old-oid`/`new-oid`) to the tool for any stored blob, enabling future blob-based caching optimizations.

Test coverage is thorough: 130 new lines in `t/t4080-diff-process.sh` exercise counts from the tool’s hunks (`--numstat`, `--shortstat`), an equivalent file producing no stat line, `--stat --exit-code`, the raw non-textconv content the tool receives, a multi-file mix of equivalent and changed files, and a mode-only change that keeps the file in the stat output even when the tool reports the content as equivalent. The documentation update clarifies that the line-counting `--dirstat=lines` follows these same counts, while the default `--dirstat` (which weighs byte changes) still computes independently and does not consult the tool.
