This is the first patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`. It targets the packed object database backend and addresses an inefficiency in how objects are looked up during enumeration.

When iterating over objects with a specific prefix, the code currently uses the multi-pack index or individual packfiles to enumerate objects but then ignores the index-provided data for the actual object lookup. Instead, it calls the generic `odb_source_read_object_info()`, which re-traverses the indices to find the object’s location. This is redundant and risks selecting the wrong pack if an object exists in multiple packs. The patch fixes this by using `packed_object_info()` directly, which takes the already-known pack and offset as arguments.

The change also renames the `store` variable to `source` for clarity, though this is a minor stylistic touch mixed into the functional change. The diff is small (15 lines) and focused on `odb/source-packed.c`. Reviewers have already confirmed the core logic is sound, though one surface-level nit about mixing unrelated changes remains open. No behavioral changes are expected for users.
