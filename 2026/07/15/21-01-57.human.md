This is a refactoring patch in the `diff.<driver>.process` RFC series, now at version 5. The patch separates the child-process lifecycle management (setup, handshake, teardown) from the hashmap that indexes running processes by command string. The change introduces two new functions, `subprocess_start_command()` and `subprocess_stop_command()`, which handle the process machinery without touching the hashmap, while the existing `subprocess_start()` and `subprocess_stop()` become thin wrappers that add hashmap operations on top.

The motivation is clear: the current API couples two concerns that not all callers need. Callers like `convert.c` benefit from the hashmap because they manage many files sharing a single filter process, but other callers (such as the upcoming diff-process driver) manage process lifetime through their own data structures and don’t need the hashmap overhead. The patch is small (31 lines added, 6 removed) and mechanical, with no behavior change for existing callers.

The implementation is straightforward. The new functions encapsulate the child-process setup and handshake logic, and the wrappers delegate to them while adding the hashmap operations. The patch also improves error handling: if the handshake fails, the process is cleaned up immediately rather than being left in the hashmap. This is part of a larger effort to make the subprocess API more flexible for the diff-process driver, which needs fine-grained control over process lifecycle.

The patch is well-motivated and addresses a real design tension in the subprocess API. It’s a clean refactoring that doesn’t introduce new complexity, and it’s clearly necessary for the diff-process driver to work efficiently.
