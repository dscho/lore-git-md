This is patch 7/9 in Patrick Steinhardt’s v4 series introducing object filters to `odb_for_each_object()`. It adds a new function `prepare_bitmap_git_for_source()` that opens a bitmap only for a specific packed object source, addressing a correctness issue in the upcoming conversion of the packed backend to use bitmaps for object enumeration.

The patch is a targeted refactoring in the pack-bitmap subsystem, adding 14 lines to `pack-bitmap.c` and 2 lines to `pack-bitmap.h`. The new function `prepare_bitmap_git_for_source()` takes a `struct odb_source_packed *` and returns a `struct bitmap_index *` if a bitmap exists for that source, or `NULL` otherwise. It delegates the actual bitmap opening to the existing `open_bitmap_for_source()` (introduced in patch 5/9) and calls `load_bitmap()` to populate the index. If either step fails, it cleans up and returns `NULL`.

This change is a prerequisite for patch 9/9, which will use the new function to ensure `git cat-file --batch-all-objects` only enumerates objects from the intended source when using bitmaps. The commit message clearly explains the three correctness issues that arise when a bitmap from one source is used to enumerate objects from another: misattribution of objects, incorrect source info, and redundant enumeration.

The patch is mechanical and well-scoped, with no behavioral changes in this commit. It follows the restructuring in patch 5/9 (which reversed the loop order in `open_bitmap()`) and the mechanical rename in patch 6/9 (dropping `_1` suffixes). The function name and signature are consistent with the series’ naming conventions, and the commit message typo noted in Toon Claes’s review (`prepare_source_bitmap_git()` vs. `prepare_bitmap_git_for_source()`) has been corrected in v4.

No open questions or loose ends remain for this patch. It is ready for integration and has no dependencies beyond the earlier patches in the series. The only follow-up work relevant to this patch is Taylor Blau’s proposed callback-type split for bitmapped object iteration, which is planned as a separate series on top of v4.
