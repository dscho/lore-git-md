This is a substantive review comment from Junio C Hamano on Gatla Vishweshwar Reddy’s v3 patch converting `git show-branch` to use a commit-slab for per-commit state. Junio identifies a behavioral regression in the `show_independent()` function: the original code checks that a commit’s flags contain *only* the bit for the current branch (i.e., the commit is reachable from exactly one tip), whereas the new slab-based version merely checks whether the current branch’s bit is set (i.e., the commit is reachable from at least one tip). This weakens the independence check and would cause `git show-branch --independent` to list commits that are reachable from multiple branches, breaking a long-standing invariant. The patch touches only `builtin/show-branch.c` and reuses the `init_commit_rev_flags_with_stride` infrastructure from the 2025 variable-length bitset slab series, but this logic error undermines the refactoring’s claim of preserving existing behavior. Gatla will need to restore the exact-bit-set check in the slab-based implementation before the patch can proceed.
