This is a small bugfix series for `gitweb`, the web-based Git repository browser. The issue is cosmetic but noticeable: when viewing a commit diff, the "index" lines (which show the old and new object IDs) are displayed in full rather than being shortened and hyperlinked, because the code that processes these lines expects the object IDs to be at the end of the line, but they are followed by a file mode like `100644`.

The series consists of two patches. The first patch reorders the processing in `gitweb.perl` so that the object IDs are shortened and linked even when a file mode is present. The second patch adds a regression test to `t9502-gitweb-standalone-parse-output.sh` to ensure this case is covered. The commit message and test are clear and focused, and the change itself is straightforward -- a typical small fix for a long-standing papercut.

The author has tested the series with the Git test suite, specifically the gitweb tests, and reports no issues. There is no indication of prior discussion or controversy; this appears to be a first submission. If you use `gitweb` and have noticed unlinked hashes in diff views, this series will tidy that up. The patches are small, well-explained, and unlikely to cause regressions elsewhere.
