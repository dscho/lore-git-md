This patch updates the Git protocol v2 documentation and the server-side code to advertise the `object-info` capability. The key change is that servers now explicitly declare which object metadata fields they support (currently only `size`) via the capability string. This allows clients to know upfront whether a server can provide the requested information, avoiding unnecessary round-trips or fallback to full fetches.

The documentation update clarifies several protocol details: full object IDs are now required (not abbreviated), the `obj-size` field is explicitly defined as optional, and servers must respond with just the object ID and a space if they do not recognize the object. The server-side code in `serve.c` is updated to append `"size"` to the capability string when `transfer.advertiseObjectInfo` is enabled.

This is a small but essential piece of the larger series, ensuring protocol-level compatibility and preventing clients from requesting unsupported metadata. The changes are straightforward and align with Git’s established patterns for capability advertisement. No controversy or open questions remain for this patch.
