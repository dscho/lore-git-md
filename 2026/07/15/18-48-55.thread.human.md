This thread reports a regression in Git 2.55.0 where `git rev-list --no-walk` no longer respects path filtering arguments like `-- ':!drivers/gpu/drm/'`. The issue was introduced by commit `dd4bc01c0a8f`, which refactored how commits are processed in non-walking modes but accidentally skipped the `process_parents()` call that applies path filters. Peter Colberg, the author, demonstrates the problem with a real-world Linux kernel example and confirms that reverting the problematic hunk restores the expected behavior.

The regression affects workflows that rely on `--no-walk` for path-based filtering, such as bisecting or analyzing commits modifying specific paths. The patch touches `revision.c` in the `get_revision_1()` function, and the issue stems from the interaction between `REV_WALK_NO_WALK` and the path-filtering logic. No test coverage or proposed fix is included yet, but the reproduction steps are clear. This is likely to draw attention from maintainers of the revision-walking code, and the discussion may focus on whether to revert the change, adjust the path-filtering logic, or document it as a breaking behavior.
