This is a refactoring patch from René Scharfe that simplifies how push specifications are passed in `remote-curl.c`.

The patch removes the redundant `nr_spec` (item count) parameter from the `push_dav`, `push_git`, and `push` functions. Since the push specs are stored in a `strvec` — which is already NULL-terminated — the code can rely on that termination instead of tracking the count separately. This eliminates unnecessary conversions between `size_t` and `int` and makes the code slightly cleaner.

The changes are mechanical: replacing loop-based `strvec_push` calls with a single `strvec_pushv` in `push_dav`, and adjusting the loop in `push_git` to iterate until a NULL pointer is encountered. The patch touches only one file and has no behavior change — it’s purely about code hygiene.

Given René’s track record of sending small, well-scoped cleanups, this looks like a solid, uncontroversial improvement. It’s the kind of patch that fits well into the ongoing effort to tidy up Git’s internals without risking regressions.
