This is a bugfix patch for `git mv`. It addresses a long-standing usability issue where `git mv` reports a misleading error when the destination's parent directory does not exist. Currently, the error message incorrectly blames the *source* file (e.g., "renaming 'src' failed: No such file or directory"), even though the source exists and the problem is the missing destination directory. The patch moves the detection of this condition into the checking phase, ensuring the error message clearly identifies the missing directory and that `git mv --dry-run` also catches the problem.

The fix is narrowly scoped to the `builtin/mv.c` file, where it adds a new check during the entry-processing loop. The logic statically verifies the existence of the destination's leading directory only when the move will actually be performed on disk (i.e., not for directory moves, sparse entries, or out-of-cone destinations). The error message reuses the existing "destination directory does not exist" string, maintaining consistency with other cases where this condition is already caught.

The patch includes two new tests in `t/t7001-mv.sh`: one for the basic failure case and another to verify that `--dry-run` now detects the problem. The tests are minimal but sufficient to cover the new behavior. The commit message is clear and well-structured, explaining both the problem and the solution in detail, including the rationale for the specific conditions under which the check is applied.

This is a straightforward, well-motivated fix that addresses a real user pain point. The implementation is careful to avoid false positives (e.g., for directory moves or sparse entries), and the test coverage is appropriate.
