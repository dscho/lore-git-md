This is the eighth patch in Phillip Wood’s nine-patch series fixing how `git rebase` handles dropped commits. The patch converts the integer return value of `do_pick_commit()` to an enum (`pick_result`), making the code clearer and preparing for the addition of `PICK_RESULT_DROPPED` in the next patch.

The change is mechanical: `do_pick_commit()` now returns one of three enum values (`PICK_RESULT_ERROR`, `PICK_RESULT_OK`, or `PICK_RESULT_CONFLICTS`) instead of integers (-1, 0, or 1). The patch updates all callers (`pick_one_commit()` and `single_pick()`) to handle the enum, replacing integer checks with explicit enum comparisons. The diff is confined to `sequencer.c` and is straightforward, with no behavior change.

This is a well-justified refactoring that directly supports the series’ core goal (preventing notes from being copied from dropped commits). The enum makes the code more readable and reduces the risk of mixing up return values. Oswald Buddenhagen previously suggested widening the enum’s scope further, but Phillip rejected this to avoid unnecessary churn, keeping the change minimal and focused.

No substantive issues remain, and the series is expected to land in the next Git release. If you care about rebase correctness or sequencer internals, this patch is worth a quick skim to see how the enum is used; otherwise, the series’ final patch (9/9) is where the real behavior change happens.
