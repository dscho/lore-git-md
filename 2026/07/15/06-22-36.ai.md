This is a refactoring patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`. It is patch 6/9 in v4, a cosmetic-only update that drops the `_1` suffix from the bitmap-opening functions `open_pack_bitmap_1()` and `open_midx_bitmap_1()`, renaming them to `open_pack_bitmap()` and `open_midx_bitmap()` respectively.

The patch is purely mechanical: it updates the function declarations, definitions, and all call sites in `pack-bitmap.c` to reflect the new names. The change follows the preceding patch (5/9), which consolidated the logic for opening bitmaps into a single function, `open_bitmap_for_source()`, making the `_1` suffix redundant. No behavior or logic is altered; the patch simply cleans up the naming to match the refactored structure.

This is part of the ongoing ODB abstraction effort, which aims to restructure Git’s object storage layer to support pluggable backends. The series as a whole is under review and ready for integration, with all prior feedback incorporated. Taylor Blau and Jeff King have both acknowledged the series as ready, and Junio C Hamano previously praised the final patch (9/9) for its clean diffstat. The v4 update addressed only trivial commit message typos in patches 7/9 and 8/9, leaving this patch unchanged from v3.

The patch touches only `pack-bitmap.c` and affects no other subsystems or files. It introduces no new symbols or behavioral changes, and the renaming is consistent with the series’ broader goal of clarifying the codebase. The change is uncontroversial and aligns with the project’s preference for small, self-contained refactorings. No further review is expected to be needed for this patch.
