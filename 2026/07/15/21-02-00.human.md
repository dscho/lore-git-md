This is the blame integration patch for the `diff.<driver>.process` RFC series. It teaches `git blame` to consult an external diff tool when one is configured, allowing the tool to declare commits as having no semantic changes (e.g., reformatting-only commits), which causes blame to skip those commits and attribute lines to earlier commits.

The patch introduces `xdi_diff_process()`, a shared helper that consults the diff process, runs xdiff on the tool's hunks (or falls back to the builtin diff if the process doesn't apply), and returns `DIFF_PROCESS_EQUIVALENT` when the tool reports no changes. This helper is used by blame's `pass_blame_to_parent()` and will later be reused by `git log -L`. The subprocess is long-running, amortizing startup costs across the blame traversal, though each commit still incurs a round-trip to the tool.

The implementation handles edge cases like whitespace-ignoring options (`-w`), which the process cannot honor, forcing a fallback to the builtin diff. The test coverage (60+ lines) verifies that blame respects the tool's hunks (e.g., attributing lines to earlier commits when the tool reports only a subset of changes), skips commits marked as equivalent, and correctly bypasses the process when `--no-ext-diff` or `-w` is used.

This patch demonstrates the key use case for the series: enabling tools to influence blame attribution without breaking downstream features. The overhead (~17% in blame operations) is noted, with OID-based caching identified as future work. The integration is clean, with minimal changes to blame.c (24 lines added) and robust error handling. All substantive review feedback from earlier versions has been addressed.
