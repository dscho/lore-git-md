This is the fifth patch in the eighteenth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. The series is now complete and queued for merging to `next`.

This patch eliminates a problematic static variable (`advertise_sid`) in `fetch-pack.c` that was identified as a critical refactoring flaw in v15. The static variable was used in two places: once in `do_fetch_pack()` (where it was conditionally set based on server capabilities) and once in `fetch_pack_config()` (where it was set via configuration). The inconsistency created a risk of uninitialized use if the configuration was unset, and the static variable's scope made it difficult to reuse the function in other contexts (such as the new `remote-object-info` command).

The fix moves the `advertise_sid` logic into the two functions where it is actually used: `find_common()` and `write_fetch_command_and_capabilities()`. In both places, the variable is now initialized to `0` (matching its default) and set via `repo_config_get_bool()`. The conditional check for server support (`!server_supports("session-id")`) is moved into `find_common()`, ensuring it only applies to the v0/v1 protocol paths where it is relevant. The changes are mechanical and localized, with no behavior modification—only the variable's scope and initialization are altered.

The patch carries `Helped-by` trailers for Jonathan Tan and Christian Couder, indicating their involvement in the design. It is a prerequisite for later patches in the series (notably patch 6/10, which relocates `write_fetch_command_and_capabilities()` to `connect.c` for reuse by the `remote-object-info` command). The fix addresses the last major refactoring issue that led Junio Hamano to revert v16 from `next`, and it has been stable since v16. No further changes were needed in v18.
