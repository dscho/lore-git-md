This is the sixth patch in the nine-patch `diff.<driver>.process` RFC series (v5). It extends the `--no-ext-diff` option to disable the new process-based diff driver alongside the existing command-based driver, ensuring a single option controls all external diff tool usage. The patch also unconditionally disables the diff process in `git format-patch` so generated patches are always based on Git's builtin diff algorithm, guaranteeing they can be applied reliably by recipients without the external tool.

The implementation replaces the boolean `--ext-diff` option with a callback that sets both `allow_external` and `no_diff_process`, allowing `--ext-diff` to override an earlier `--no-ext-diff`. The documentation is updated to reflect that `--no-ext-diff` now covers both driver types, and to note that `--diff-algorithm` also bypasses the process driver. The test suite adds coverage for the new bypass behaviors, including a check that `format-patch` does not invoke the external tool.

This patch addresses a key usability concern: users expect `--no-ext-diff` to disable all external diff mechanisms, not just the legacy command driver. The change is minimal and focused, touching only the option parsing, documentation, and test files. The unconditional disable in `format-patch` is a conservative choice that prioritizes patch reliability over feature consistency, which aligns with the project's historical emphasis on interoperability. The patch is well-motivated and technically sound, with clear documentation updates and thorough test coverage.
