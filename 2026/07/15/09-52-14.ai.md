This is a **substantive review** of the first patch in René Scharfe’s 5-patch series introducing repository-aware tempfile APIs for the `the_repository` removal effort. Patrick Steinhardt raises a design question about whether passing a full `struct repository *` is overkill when only the `core.sharedRepository` setting is needed. He suggests an alternative: letting callers pass the configuration value directly, but acknowledges this could lead to code duplication. He also notes that the thin wrapper in `tempfile.c` could have been an inline function in the header, but dismisses it as a minor nit since the wrapper will likely be removed in later patches.

The review does not request changes or identify bugs, but it surfaces a potential future refactoring direction if callers without a repository emerge. The feedback is technical and forward-looking, not a blocker for the current series. No other participants have weighed in on this specific point.
