This is the seventh patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch is a targeted refactoring that prepares the pack-bitmap subsystem for per-source bitmap handling.

The patch introduces `prepare_bitmap_git_for_source()`, a new function that opens a bitmap *only* for a specified object source (e.g., a single packfile or multi-pack index). This is a necessary step for the packed ODB backend to use bitmaps when answering object filters: without it, the backend might incorrectly use a bitmap from a different source, leading to misattributed objects or redundant enumeration. The function is straightforward—it allocates a `bitmap_index` struct, attempts to open and load the bitmap for the given source, and returns the struct on success or cleans up and returns `NULL` on failure.

The change is small (14 lines) and mechanical, touching only `pack-bitmap.c` and `pack-bitmap.h`. It follows the restructuring in patch 5/9, which reversed the loop order in `open_bitmap()` to prioritize local packfile bitmaps, and the mechanical rename in patch 6/9, which dropped the `_1` suffix from bitmap-opening functions. The commit message clearly explains the motivation and the risks of not making this change, and the implementation is clean and well-scoped.

This patch is uncontroversial and ready for integration. It addresses a specific technical need for the ODB abstraction and has no known downsides or open questions. The only prior feedback was a trivial commit message typo (function name mismatch) in v3, which is now resolved in v4. The series as a whole is under final review by Junio C Hamano, and this patch is a necessary building block for the final conversion of `git cat-file` to use ODB-mediated filtering in patch 9/9.
