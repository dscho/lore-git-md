This is the first patch in Phillip Wood’s **9-patch v3 series** fixing how `git rebase` handles dropped commits. This specific patch is a **test maintenance update** for the "apply" backend in `t3400-rebase.sh`.

Since Git now defaults to the merge backend, the existing test that used `-m` (merge backend) no longer exercises the apply backend’s note-copying behavior. The patch restores coverage by replacing `-m` with `--apply`, ensuring the test explicitly checks the apply backend. This is a **pure refactoring of the test suite** with no behavior change—it simply preserves test coverage for a backend that is still supported but no longer the default.

The change is minimal (two lines in one file) and uncontroversial. It serves as a prerequisite for later patches in the series, which rely on this test to verify that notes from dropped commits are *not* copied. Oswald Buddenhagen’s earlier **surface-level review** suggested adding commas to the test title, but those are being handled separately as typofixes and do not affect this patch’s substance.

This patch is **well-motivated and low-risk**, addressing a gap in test coverage without altering Git’s behavior. It’s a necessary step in the larger effort to audit and repair how the rebase machinery handles dropped commits.
