This is a gitweb-focused bugfix series from Travor Liu. It addresses a rendering issue in gitweb’s commitdiff view where index lines containing file modes (e.g., `index <old>..<new> 100644`) show full, unlinked object IDs instead of the usual shortened, clickable hashes. The root cause is that gitweb’s regex for matching object IDs runs *before* the mode-handling code, so the mode string is treated as part of the ID range.

Patch 1 reorders the logic in `gitweb/gitweb.perl` so the mode is stripped first, allowing the object-ID matcher to shorten and hyperlink the hashes as intended. Patch 2 adds a regression test in `t9502-gitweb-standalone-parse-output.sh` that verifies the fix for the common `100644` mode case. The series touches only `gitweb.perl` and the test script; no other Git subsystems are involved.

The commit message is clear and the test coverage is minimal but sufficient for the narrow scope. The change itself is a straightforward regex reordering with no apparent risk of breaking other gitweb features. No prior discussion or controversy is evident from the email.
