This is the final patch in Harald Nordgren’s `git history squash` series, implementing the `--reedit-message` feature that lets users interactively combine commit messages from the entire squashed range. The patch completes the series by reusing sequencer helpers (`add_squash_combination_header`, `add_squash_message_header`, `squash_subject_comment_len`) and the `TODO_REPLACE_FIXUP_MSG` flag—extracted in an earlier patch—to produce a template that exactly matches `git rebase -i --autosquash`. This ensures visual and behavioral consistency: `fixup!` messages are fully commented out, `squash!` bodies are preserved with only the marker subject commented, and `amend!` replaces its target’s message unless a `squash!` already folded into that target.

The implementation walks the range in reverse topo-order, gathers each commit’s message, and constructs the template using `todo_list_rearrange_squash()` to group `fixup!`/`squash!`/`amend!` commits under their targets. This matches the autosquash arrangement and resolves the last open technical concern from earlier iterations: the command now processes `amend!` messages consistently for both validation and message construction. The patch also adds thorough test coverage for template construction, autosquash grouping, and edge cases like empty messages.

With this patch, the series is functionally complete and ready for integration. Junio’s "Will replace" sign-off on v7 and the resolution of all prior feedback in v9 indicate the series will likely be queued for the next release. The only remaining discussion point—whether `--reedit-message` should be the default—is a minor usability tweak that does not block merging. The architectural vision of using `git history squash` and `git replay` as a faster, non-interactive backend for `git rebase --autosquash` is now a project-level aspiration, with this series as a foundational piece.
