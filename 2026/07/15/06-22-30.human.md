This is the cover letter for the fourth iteration of a nine-patch series introducing object filters to `odb_for_each_object()`. The goal is to enable `git cat-file --batch-all-objects` to work with pluggable object databases by removing its dependency on internal details of the "packed" backend, particularly for efficient handling of bitmapped objects. This is part of Patrick Steinhardt’s ongoing ODB abstraction effort to restructure Git’s object storage layer.

The series is now ready for integration, with all prior review feedback incorporated. This version (v4) is a cosmetic-only update addressing trivial commit message typos in patches 7/9 and 8/9 (function name mismatches: `prepare_source_bitmap_git()` vs. `prepare_bitmap_git_for_source()`). No technical changes were made. The series builds on Git 2.56 with Patrick’s `ps/odb-drop-whence` topic merged.

Key changes include improving object lookup during enumeration, making object filters `const`, allowing early abortion of bitmapped object iteration, and introducing new functions to open bitmaps for a single source. The final patch (9/9) converts `git cat-file` to use ODB-mediated filtering, replacing backend-specific logic with a clean 7-insertion/69-deletion diff. Junio C Hamano reviewed this patch in an earlier version and called it "very nice," praising the implementation.

Reviewers (Jeff King, Taylor Blau, Justin Tobler, and Toon Claes) have all signaled readiness for integration, with no remaining technical objections. Taylor Blau proposed a follow-up series to split the callback type used by `for_each_bitmapped_object()` from `show_reachable_fn`, which Jeff King endorsed as a "nice cleanup." This follow-up is planned but does not block the current series. The only open question—a minor nit about mixing unrelated changes in patch 1/9—is not a blocker.

The series touches the ODB, packed backend, and pack-bitmap subsystems, with changes to `builtin/cat-file.c`, `pack-bitmap.c`, `odb/source-packed.c`, and related headers. It introduces new symbols like `prepare_bitmap_git_for_source()` and `can_filter_bitmap()`, while removing backend-specific functions like `batch_one_object_packed`. No on-disk format changes or end-user behavioral changes are expected.

This is a well-crafted, thoroughly reviewed series that addresses a real architectural need. It looks ready for Junio’s final review and integration into `next`. Contributors working on ODB backends or performance optimizations should take note.
