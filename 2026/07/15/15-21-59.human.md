This is the fifth patch in Phillip Wood’s 9-patch v3 series fixing how the sequencer handles dropped commits during rebase. The series as a whole is a well-tested, maintainer-approved bugfix targeting the rebase machinery, and this patch is a small refactoring step that simplifies control flow for fixup commits that result in conflicts.

The patch removes a redundant conditional in `pick_one_commit()`. Commit e032abd5a0 (2023-09-06) already ensures that when the code enters the fixup-with-conflict block, `res` is positive, and earlier patches in this series have narrowed the possible positive value to 1. Instead of checking `if (res == 1)` to call `intend_to_amend()`, the patch moves that responsibility into `error_with_patch()` by passing an extra flag. The change is purely mechanical: one line is added in `error_failed_squash()` and two lines are removed from `pick_one_commit()`. No behavior changes; the patch is preparation for the core fix in patch 9/9.

Oswald Buddenhagen’s review of this patch was surface-level, focusing on commit message phrasing rather than technical correctness. Phillip acknowledged the feedback but did not alter the code. The patch is part of a series that Junio has already marked ready for `next` once minor typofixes are squashed. If you are following the rebase-dropped-commit audit, this is a safe, uncontroversial step that cleans up the code before the behavioral change lands.
