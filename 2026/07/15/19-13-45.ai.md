This is a review comment on the second patch of Paulius Zaleckas’s v5 series introducing configurable submodule fetch error handling. Junio critiques the use of `size_t` for array indexing in the helper functions that parse and format the new `fetch.submoduleErrors` configuration values (`fail`/`warn`).

The feedback focuses on code readability and adherence to Git’s coding guidelines. Junio argues that `size_t` is unnecessarily verbose for indexing a small, fixed-size array (`submodule_errors_names`), and that using `unsigned` (or even plain `int`) would be more idiomatic and readable. He also points out that the array name should be singular (`submodule_error_name[]`) to reflect that it holds individual strings, not a collection of arrays. The critique includes a link to an external blog post reinforcing the argument against `-Wsign-compare` as a misguided compiler warning.

This is a surface-level review: the comments address mechanical style issues (type choice, naming) rather than the patch’s functionality or design. The feedback is actionable but does not raise new technical concerns or block the series. The patch remains technically complete and uncontroversial; the requested changes are minor and unlikely to affect behavior.
