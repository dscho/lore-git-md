This thread is about a two-patch bugfix series for `git mv` that fixes a misleading error message when the destination directory doesn’t exist. The series, authored by Lucas Zamboni Orioli, is now at v2 and under active review.

The first patch—improving the error message to include both source and destination paths—has been approved by Junio Hamano. The second patch adds an early directory existence check to enable `--dry-run` detection, but Junio has now raised new concerns about edge cases: when the destination path exists but isn’t a directory (e.g., a symlink or file) or when an intermediate path component isn’t a directory. These cases currently pass the check but will fail later during the `rename(2)` syscall, potentially with confusing errors. The TOCTOU race mentioned in earlier reviews remains acknowledged but unresolved.

The author hasn’t yet posted a v3 to address the indentation style fix Junio requested in the previous round or these new edge cases. Ben Knoble’s earlier feedback about the TOCTOU race and error message clarity has already been incorporated. The series is close to being ready for `next` but needs another revision to handle the new technical concerns.
