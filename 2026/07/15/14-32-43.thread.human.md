This thread is about a two-patch bugfix series for `git mv` that improves error messages and adds an early check for missing or problematic destination directories. The series, authored by Lucas Zamboni Orioli, is now in its final version (v5) and has been explicitly approved by Junio Hamano, the project maintainer.

The core issue was that `git mv` emitted misleading error messages when the destination's parent directory didn't exist or contained problematic components, incorrectly blaming the source file. The fix addresses this by including both source and destination paths in error messages and rejecting three problematic cases: missing directories, non-directory components, and any tracked symlink in the destination path. The symlink rejection prevents an index/worktree inconsistency bug where following a symlink would leave the index recording the literal symlink path while the file was moved to the resolved target.

Junio approved the series after the author implemented a minor refactoring he requested, extracting shared logic into a `needs_worktree_rename()` helper function. The series is now ready for integration into the `next` branch. The only remaining loose ends are an acknowledged but unresolved TOCTOU race (where the destination directory could disappear between the check and the actual rename operation) and potential bikeshedding on the helper function's name. The patches touch `builtin/mv.c` and add 146 new test lines to `t/t7001-mv.sh`, covering symlinks, missing directories, and other edge cases. Two new translatable strings were introduced for improved error messages.
