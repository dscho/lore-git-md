This thread is about a small but user-visible bug in `git mv`: when you try to move a file to a destination whose parent directory doesn’t exist, Git currently blames the *source* file (“No such file or directory”) instead of the missing directory. Lucas Zamboni Orioli’s patch fixes the error message and makes `--dry-run` catch the problem too. The change is confined to `builtin/mv.c` and adds two new tests in `t/t7001-mv.sh`.

The patch itself is under review and hasn’t seen any prior versions. So far, Ben Knoble has raised two substantive points: first, that the new `lstat` check introduces a TOCTOU race (the directory could vanish between the check and the actual `rename` syscall), and second, that the error message should name both source and destination paths to make the failure unambiguous. Neither point has been addressed yet, so the discussion is still open. No other reviewers have weighed in.
