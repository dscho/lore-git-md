This thread is about a two-patch bugfix series for `git mv` that fixes a misleading error message when the destination directory doesn’t exist and prevents an index corruption bug caused by symlinks in the destination path. The series, authored by Lucas Zamboni Orioli, is now in its final version (v4) and ready for integration.

The first patch improves the error message to include both source and destination paths, while the second adds an early check for the destination directory’s existence, explicitly rejecting missing directories, non-directory components, and—critically—any tracked symlink in the destination path. This last change resolves a long-standing dispute by aligning `git mv` with `git apply`’s precedent of avoiding symlink traversal, which prevents the index from recording the literal symlink path while the file is moved to the resolved target.

Junio Hamano, the maintainer, has approved the series, calling the approach “sounds good” and confirming that the symlink-handling logic is correct. The only remaining loose end is a TOCTOU race (the destination directory could disappear between the check and the actual move), which Junio and the author have acknowledged as unavoidable for now. The test coverage is thorough, with 83 new lines in `t/t7001-mv.sh` covering symlinks, missing directories, and other edge cases. No further changes are expected, and the series is now technically complete.
