This thread is about a two-patch series (now at v5) that fixes misleading error messages in `git mv`. The series addresses a long-standing usability issue where `git mv` incorrectly blames the source file when the real problem is a missing or problematic destination directory. The first patch, which has been stable since v2 and explicitly approved by Junio, simply improves the error message to include both source and destination paths. The second patch adds an early check for the destination directory's existence, enabling `--dry-run` detection and explicitly rejecting problematic cases like missing directories, non-directory components, and any tracked symlink in the destination path—regardless of whether the symlink points to a directory or not.

The series is now ready for integration. Junio has approved the overall approach ("sounds good") and confirmed the symlink-handling strategy is correct, aligning with `git apply`'s precedent. The author, Lucas Zamboni Orioli, implemented a minor refactoring requested by Junio in v5 to deduplicate a small logic fragment, and the series now includes comprehensive test coverage (146 new test lines) and two new translatable error messages. The only remaining loose end is a known TOCTOU race, which Junio acknowledged as "the best we can do" without a proposed fix. No other objections or requests for changes are outstanding.

Key participants include Junio, who fully resolved the symlink-handling dispute by insisting on rejecting all tracked symlinks in the destination path, and Ben Knoble, who identified the TOCTOU race and suggested the improved error message format. Pablo Sabater provided only surface-level feedback on style, while the author addressed all substantive concerns in the final version. The series touches `builtin/mv.c` and `t/t7001-mv.sh`, with no changes to on-disk format or existing behavior beyond the error message wording.
