This thread is about a two-patch series from Lucas Zamboni Orioli that fixes a misleading error in `git mv` when the destination directory doesn’t exist. The first patch improves the error message to include both source and destination paths, and the second adds an early check for the destination directory’s existence to enable `--dry-run` detection. The series is now at v3 and under review.

The first patch is uncontroversial and approved by Junio C Hamano. The second patch, however, is stuck on a disagreement about how to handle symlinks in the destination path. Junio insists that *any* tracked symlink in the destination path should block the move—regardless of whether it points to a directory or file—using `lstat()` to avoid unsafe traversal. The current implementation (v3) uses `stat()`, which follows symlinks and accepts those pointing to directories while rejecting those pointing to files. This difference is the main blocker, though a TOCTOU race (where the directory could disappear between the check and the actual move) was also noted but deemed unavoidable for now.

Pablo Sabater’s recent email is a minor style review of the second patch, pointing out indentation and brace consistency issues. This feedback is purely cosmetic and doesn’t engage with the symlink debate or other technical concerns. The thread remains focused on resolving the symlink-handling strategy before the series can move forward. No merge status has been reported, and the series is not yet ready for integration.
