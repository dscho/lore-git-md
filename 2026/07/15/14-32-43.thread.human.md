This thread is about a bugfix for `git mv` that addresses a misleading error message when the destination directory doesn’t exist. The series, now at v3, consists of two patches: the first improves the error message to include both source and destination paths, and the second adds an early check for the destination directory’s existence to enable `--dry-run` detection.

The key dispute has been how `git mv` should handle symlinks in the destination path. Junio C Hamano argued that *any* tracked symlink in the path—regardless of whether it points to a directory or file—should block the move, citing safety concerns and precedent from `git apply`. The author, Lucas Zamboni Orioli, initially used `stat()` (which follows symlinks) in v3, but in this latest update, he acknowledges a concrete bug: when `git mv` follows a tracked symlink, it leaves the index inconsistent with the worktree, causing confusing `git status` output. To fix this, Lucas now proposes using `has_symlink_leading_path()`, the same function `git apply` uses to avoid symlink traversal, which will reject all symlinks in the destination path. This aligns the behavior with Junio’s feedback and resolves the last technical blocker.

The series touches `builtin/mv.c` and adds tests in `t/t7001-mv.sh`, covering missing directories, non-directory components, symlinks (now rejected in all cases), and `--dry-run` detection. The TOCTOU race—where the destination directory could disappear between the check and the actual move—remains acknowledged but unresolved. The two-patch structure is preserved, and the series is now ready for integration once the symlink-handling fix is finalized. Pablo Sabater’s earlier review was purely stylistic, while Ben Knoble’s feedback on the TOCTOU race and error message clarity has been addressed.
