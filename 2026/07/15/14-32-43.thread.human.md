This thread is about a two-patch series from Lucas Zamboni Orioli that fixes a bug in `git mv` where it emits misleading errors when the destination directory doesn’t exist. The first patch improves the error message to include both source and destination paths, while the second adds an early check for the destination directory’s existence, enabling `--dry-run` to catch these failures before the actual `rename(2)` syscall.

The series is now in its third version (v3) and addresses all substantive feedback. Junio C Hamano approved the first patch outright, and the second patch now fully resolves his concerns by using `stat()` instead of `lstat()` to align with `rename(2)`’s behavior, explicitly checking for non-directory destinations, and validating intermediate path components. The only acknowledged limitation is a TOCTOU race—where the directory could disappear between the check and the syscall—which is considered unavoidable for now.

Lucas has added thorough test coverage in `t/t7001-mv.sh`, including cases for missing directories, non-directory path components, symlinks (accepting symlinks to directories but rejecting symlinks to files), and `--dry-run` detection. The series introduces one new translatable string ("destination is not a directory") but reuses existing messages where possible to minimize l10n impact.

The thread appears uncontroversial and ready for final review, with no remaining technical objections. Key participants—Junio, Ben Knoble, and Lucas—have all weighed in, and the implementation is now complete. The series touches `builtin/mv.c` and the test suite, with no changes to on-disk formats or new public symbols.
