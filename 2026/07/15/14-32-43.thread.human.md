This thread is about a two-patch bugfix series for `git mv` that fixes a misleading error message when the destination's parent directory doesn't exist. The series is now at version 3, posted by Lucas Zamboni Orioli.

The first patch, which has already been approved by Junio Hamano, improves the error message to include both the source and destination paths, making it clear what actually failed. The second patch adds an early check for the destination directory's existence, enabling `--dry-run` to detect missing directories and handling edge cases like non-directory destinations or invalid intermediate path components. All substantive feedback from Junio and Ben Knoble has been addressed in this version.

The series is effectively ready for final review. The only open points are minor: a known TOCTOU race (acknowledged as unavoidable for now), a small l10n consideration about string reuse, and whether the two commits should remain separate. No one has objected to the split structure, and the changes appear uncontroversial. The patches touch `builtin/mv.c` and add tests in `t/t7001-mv.sh`, with no on-disk format changes.
