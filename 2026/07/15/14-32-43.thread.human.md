The `git mv` thread is fixing a misleading error message when the destination directory doesn’t exist—currently, Git blames the source file instead of the missing directory. The series, now at v3, splits the fix into two patches: the first improves the error message to include both source and destination paths (approved by Junio), while the second adds an early check for the destination directory’s existence to enable `--dry-run` detection.

The second patch is now contested. Junio rejects the `stat()`-based approach in v3, arguing that following symlinks in the destination path is unsafe—it could allow `git mv` to move files outside the working tree if a tracked symlink points elsewhere. He insists on `lstat()` (which doesn’t follow symlinks) and cites `git apply` as precedent. Lucas’s v3 used `stat()` to align with `rename()`’s behavior, but Junio’s feedback reopens the debate. The TOCTOU race (where the directory could vanish between the check and the actual move) remains acknowledged but unresolved.

The series isn’t ready for merging. The first patch is approved, but the second hinges on resolving the symlink-handling strategy. No other objections or new edge cases have surfaced, though sparse-checkout and worktree interactions were flagged for future discussion. Tests cover missing directories, symlinks, and `--dry-run`, but expectations may need revision depending on the final symlink resolution.
