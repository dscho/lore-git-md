This thread is about a two-patch bugfix series for `git mv` that fixes misleading error messages when moving files to a non-existent destination directory. The series is now in its final version (v4) and ready for integration.

The first patch, which this email covers, is a simple but effective improvement: it makes `git mv` include both the source and destination paths in error messages when a `rename()` syscall fails. For example, instead of blaming the source file ("renaming 'a/file' failed: No such file or directory"), it now clearly indicates the missing directory in the destination ("renaming 'a/file' -> 'b/no-such-dir/file' failed: No such file or directory"). This change is uncontroversial, approved by Junio, and requires no new tests since it only affects error message output.

The second patch, which builds on this clarity, adds an early existence check for the destination directory (and its intermediate components) to enable `--dry-run` detection and explicitly reject problematic cases like missing directories, non-directory components, and tracked symlinks in the destination path. The symlink handling was a point of contention in earlier versions, but v4 fully resolves it by rejecting all tracked symlinks in the destination path, aligning with `git apply` precedent and Junio's requirements. The series includes comprehensive test coverage for these edge cases.

The only remaining loose end is a TOCTOU race (the destination directory could disappear between the check and the actual `rename()`), which Junio acknowledged as "the best we can do" without a proposed fix. The series has no reported merge status yet but is under final review. Key participants include Junio (approving the first patch and resolving the symlink dispute), Ben Knoble (substantive review identifying the TOCTOU race), and the author, Lucas Zamboni Orioli, who implemented the fixes and test coverage. Pablo Sabater provided only surface-level feedback on style.
