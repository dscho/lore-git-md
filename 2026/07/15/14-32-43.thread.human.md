This thread is about a two-patch bugfix series for `git mv` that improves error messages and adds an early check for problematic destination paths. The series, now at its fifth iteration (v5), is authored by Lucas Zamboni Orioli and addresses a long-standing issue where `git mv` would emit misleading errors (e.g., blaming the source file) when the destination's parent directory doesn't exist or contains problematic components like symlinks.

The first patch improves error messages to include both source and destination paths, while the second adds an early existence check for the destination directory and its intermediate components. This check explicitly rejects three cases: missing directories, non-directory components, and *any* tracked symlink in the destination path (regardless of target type). The symlink rejection uses `has_symlink_leading_path()` (borrowed from `git apply`) to avoid unsafe traversal and align with Git's policy. The series also introduces a helper function, `needs_worktree_rename()`, to deduplicate logic and optimize memory allocation, though its name may still be tweaked during integration.

Junio has explicitly approved the series ("sounds good") and confirmed the symlink-handling approach is correct. The only unresolved issue is a TOCTOU race (the destination could disappear between the check and the `rename()` syscall), which is acknowledged as "the best we can do" for now. Test coverage is comprehensive, with 146 new lines in `t/t7001-mv.sh` covering symlinks, missing directories, `--dry-run` detection, and other edge cases. The series is technically complete and ready for integration into `next`.
