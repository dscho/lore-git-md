This thread is about a two-patch series from Lucas Zamboni Orioli that fixes a misleading error in `git mv` when the destination's parent directory doesn't exist. The first patch improves the error message to include both source and destination paths, while the second adds an early check for the destination directory's existence, including handling for symlinks in the path.

The series is now in its fourth version and is ready for integration. Junio Hamano has approved the first patch, and the second patch—originally contentious over how to handle symlinks—now fully aligns with Junio's requirement to reject *any* tracked symlink in the destination path, using `has_symlink_leading_path()` to avoid unsafe traversal. This approach mirrors `git apply`'s behavior and resolves the last technical dispute. The patch also adds comprehensive test coverage, including regression tests for the index corruption scenario that could occur when moving through a symlink.

The only remaining loose end is a TOCTOU race (where the destination directory could disappear between the check and the actual move), which Junio acknowledged as "the best we can do" for now. The series has seen substantive review from Ben Knoble (who identified the TOCTOU issue and suggested the improved error message format) and surface-level feedback from Pablo Sabater, but no further objections. The patches touch `builtin/mv.c` and `t/t7001-mv.sh`, with no changes to on-disk formats or new symbols introduced. The series is under final review, with no merge status reported yet.
