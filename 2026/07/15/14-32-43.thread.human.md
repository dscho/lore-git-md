This thread is a two-patch bugfix series for `git mv` that fixes a misleading error message when the destination's parent directory doesn't exist. The series, authored by Lucas Zamboni Orioli, is now at v2 and under active review.

The first patch (previously summarized) improved the error message to include both source and destination paths, addressing a long-standing usability issue where users were incorrectly told the *source* file didn't exist. The second patch, just posted, adds an early existence check for the destination directory during `git mv`'s checking phase. This enables `--dry-run` to detect the problem before attempting the actual rename, which was the core goal of the series. The implementation handles edge cases like directory moves, sparse entries, and out-of-cone destinations, but acknowledges a TOCTOU race: the directory could still disappear between the check and the `rename(2)` syscall.

Ben Knoble provided substantive review, identifying the TOCTOU issue and suggesting the improved error message format that was adopted in the first patch. The author split the work into two commits as requested, keeping the race-free error message change separate from the early directory check. The series touches only `builtin/mv.c` and adds tests to `t/t7001-mv.sh`. Open questions remain about the TOCTOU race and whether to use `lstat` or `stat` for the directory check, but the patches themselves are narrowly scoped and unlikely to be controversial. The l10n team has been flagged for the new translatable string in the first patch.
