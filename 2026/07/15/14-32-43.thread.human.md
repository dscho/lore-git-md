This thread is about a two-patch series by Lucas Zamboni Orioli that fixes a misleading error in `git mv` when the destination's parent directory doesn't exist. The series is now in its fourth version and is effectively complete, with Junio C Hamano having explicitly approved the core logic and approach.

The first patch improves the error message to include both source and destination paths, while the second adds an early check for the destination directory's existence, enabling `--dry-run` detection and explicitly rejecting problematic cases like missing directories, non-directory components, and—critically—any tracked symlink in the destination path. This last point resolves a long-standing index/worktree inconsistency bug where following a symlink could leave the index recording the wrong path. The fix aligns `git mv` with `git apply`'s precedent of avoiding symlink traversal using `has_symlink_leading_path()`.

Junio has approved the series ("sounds good") and confirmed the symlink-handling approach is correct, though he recently requested a minor refactoring to deduplicate a small piece of logic for code hygiene. This is the only remaining action before integration, and it doesn't affect the behavior or test coverage. The TOCTOU race (where the destination directory could disappear between the check and the actual move) remains acknowledged but unresolved, as it's considered "the best we can do" for now. The series has no other open questions or objections, and all substantive feedback—including Ben Knoble's suggestions on error messages and the TOCTOU issue—has been addressed. The only surface-level review came from Pablo Sabater, who focused on style nits without engaging with the technical concerns.
