This thread fixes a misleading error in `git mv` when the destination’s parent directory doesn’t exist—currently, it blames the source file instead of the missing directory. The patch, originally sent by Lucas Zamboni Orioli, adds an early check during the entry-processing loop to catch this case, ensuring `--dry-run` also detects the problem. The change is confined to `builtin/mv.c` and includes new tests in `t/t7001-mv.sh`.

After Ben Knoble’s review flagged a TOCTOU race (the directory could vanish between the check and the actual `rename(2)` call) and suggested a clearer error message, Lucas revised the approach. The fix will now be split into two commits: the first will improve the error message to explicitly name both source and destination paths (e.g., `renaming 'source/file' to 'destination/file' failed: No such file or directory`), avoiding the race entirely, while the second will retain the early directory check. The l10n team has been notified about the new translatable string. The TOCTOU issue remains unresolved for the second commit, but the first is now race-free and ready for review. No other objections or feedback have been raised.
