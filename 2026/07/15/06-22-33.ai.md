This is patch 3/9 in the v4 series introducing object filters to `odb_for_each_object()`, a refactoring patch that removes an unused `int` return value from `add_object_entry()` in `builtin/pack-objects.c`.

The patch is a cleanup originally authored by Jeff King (Peff) and lightly edited by Patrick Steinhardt for commit message clarity. It addresses dead code that has existed since 2006: `add_object_entry()` returns 0 or 1 to indicate whether it added a new object entry, but no caller has used this return value since commit `5379a5c5ee`. The sister function `add_object_entry_from_bitmap()` will soon change to always return 0 (to conform to a callback interface), which would create inconsistent semantics between the two functions. By converting `add_object_entry()` to return `void`, the patch clarifies that the two functions have diverged and eliminates the confusion.

The change is mechanical: the function signature is updated, `return 0` statements are replaced with `return`, and the final `return 1` is removed. The diff is small (4 insertions, 5 deletions) and touches only one file. The commit message explains the historical context, the motivation for the change, and the relationship to the upcoming change in `add_object_entry_from_bitmap()`.

This patch is part of the ODB abstraction effort and was integrated into the series at Junio C Hamano’s suggestion after Peff submitted it as a follow-up to v2. It has no behavior impact and is uncontroversial. The patch is ready for integration and has no open questions or review feedback.
