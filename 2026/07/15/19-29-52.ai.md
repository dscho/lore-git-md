This is a refactoring patch targeting the revision-walking machinery, specifically the `get_commit_action()` function in `revision.c`. The patch addresses a long-standing impurity in the function: while it reads like a predicate deciding whether a commit should be shown or ignored, it also mutates tracked line ranges when used with line-level log (`git log -L`) without parent rewriting. This side effect makes it unsafe for out-of-order evaluation, such as in a lookahead scenario.

The core change moves the line-range mutation logic from `get_commit_action()` to `simplify_commit()`, where it runs before the predicate check. The patch introduces a new helper, `commit_early_ignore()`, to factor out the cheap checks (already shown, uninteresting, pack membership) that gate both the mutation and the predicate. This ensures that commits ignored by those checks are not processed unnecessarily, preserving the original behavior. The refactoring leaves `get_commit_action()` as a pure predicate, which is its intended role and a requirement for callers like the commit graph renderer.

The patch includes a new test subcommand, `line-log-peek`, added to the `test-revision-walking` helper. This subcommand evaluates `get_commit_action()` on a commit the revision walk has not yet reached, verifying that the call does not mutate the commit's flags. A corresponding test in `t4211-line-log.sh` confirms this behavior, ensuring the function remains side-effect-free. The commit message provides thorough historical context, tracing the function's origins and the introduction of the side effect, and explains why the current approach is safe despite the duplicated `commit_early_ignore()` call.

The test coverage is appropriate, targeting the specific impurity the patch addresses. The refactoring is mechanical and localized, touching only the revision-walking logic and its test infrastructure. It does not change user-visible behavior but makes the code safer for future extensions, such as lookahead optimizations. The patch is part of a larger effort to clean up the revision-walking internals, though it stands alone as a self-contained improvement.
