This is the core implementation patch (5/9) of the `diff.<driver>.process` RFC series, introducing the long-running subprocess protocol that lets external tools inject diff hunks into Git's diff and blame pipelines. The patch adds the protocol handler (`diff-process.c`), its public interface (`diff-process.h`), and a comprehensive test backend (`t/helper/test-diff-process-backend.c`) with 645 lines of test coverage (`t/t4080-diff-process.sh`).

The implementation centers on `diff_process_fill_hunks()`, which manages driver lookup, subprocess lifecycle, and error handling. It negotiates a pkt-line protocol (version=1, capability=hunks) with the external tool, sending per-file requests that include the pathname, optional blob object names (old-oid/new-oid), and both file contents. The tool responds with hunk lines (`hunk <old_start> <old_count> <new_start> <new_count>`) that Git validates for bounds, ordering, and alignment before feeding them into xdiff. The protocol is forward-compatible: tools ignore unknown request keys, and Git ignores unknown trailing fields on hunk lines.

Key technical details include:
- **Subprocess management**: The tool runs as a long-lived process stored on the `userdiff_driver` struct, launched on first use and torn down on communication failure.
- **Validation**: Hunks are checked for bounds, overlap, and per-gap alignment (not just total unchanged line counts) to ensure xdiff's lockstep traversal remains synchronized.
- **Error handling**: Malformed responses trigger warnings and fallbacks to the builtin diff algorithm; tools can signal transient errors (`status=error`) or permanent withdrawal (`status=abort`).
- **Bypass mechanisms**: The process is skipped for binary files, unmatched drivers, and options the tool cannot honor (whitespace-ignoring flags, `--diff-algorithm`, etc.).
- **OID handling**: The old-oid/new-oid fields are sent only when the content is the raw blob (omitted under textconv or for working-tree sides without stored objects), enabling tools to cache analysis keyed on the blob pair.
- **Edge cases**: The implementation handles empty file sides (start=0, count=0), trailing-newline-only changes (fallback to builtin diff), and mid-file pure insertions/deletions.

The test backend exercises every protocol mode (success, error, abort, crash) and edge case (malformed hunks, overlapping regions, flood attacks), while the integration tests verify downstream features (word diff, `--exit-code`, log) and bypass behaviors. The patch is technically complete, with all substantive review feedback from earlier iterations addressed. The remaining work is documentation refinements around flag interactions, which should not block merging.
