This thread is about a small but thoughtful refactoring in `remote-curl.c` that removes redundant tracking of the push specification array count. René Scharfe proposed the change to simplify the HTTP transport handlers by relying on the NULL-termination of `strvec` arrays instead of passing an explicit count. The discussion has since expanded into a design-level conversation about whether to pass a `const struct strvec *` to the handlers for better interface clarity and future-proofing, with Patrick Steinhardt advocating for this approach and René preferring the current simplicity.

Junio C Hamano has now weighed in, endorsing Patrick’s suggestion that a `strvec_pushvec()` helper could be a valuable independent effort. He sees this as a way to encourage safer usage patterns—length-limited vectors over NULL-terminated arrays—and notes that identifying conversion candidates would be straightforward. However, Junio’s input doesn’t change the immediate direction of the patch; it’s more of a forward-looking observation about API design. René remains the decision-maker on whether to reroll the patch with the `strvec *` interface, and Patrick has already stated he won’t insist on it.

The patch itself is a standalone refactoring with no behavior changes, confined to `remote-curl.c`, and is still under review. No merge status has been reported, and the only unresolved question is whether René will adopt the `strvec *` interface in a future version. The discussion reflects the project’s ongoing attention to interface design and code hygiene, even in small, internal changes.
