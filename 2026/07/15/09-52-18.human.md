This is the core patch of the now-complete `git cat-file --batch-command` remote object-info series, implementing client-side support for querying object sizes from protocol v2 servers without downloading full objects. The patch adds a new `fetch-object-info.c` file (121 lines) and integrates it into the transport layer, enabling Git to request object metadata via the `object-info` capability when servers advertise it.

The implementation follows Git’s established patterns: it writes the entire request into a buffer before sending (matching `send_fetch_request()` in `fetch-pack.c`), enforces protocol v2, and validates server responses against a dynamic allow-list of supported metadata fields. When servers don’t recognize an object ID, the code sets the corresponding size pointer to NULL, allowing callers to handle missing objects gracefully. The patch includes strict input validation (10,000-object batch limit, 8KB URL length limit) and a bounds-checking fix in `parse_object_size()` to prevent out-of-bounds reads from malformed server responses.

This is the final piece of the 18-patch series, which has been cooking for over two years and is now queued for merging to `next`. The series is well-motivated (avoiding unnecessary object downloads), thoroughly tested (699 lines of new tests in `t/t1017-cat-file-remote-object-info.sh`), and has addressed all prior security concerns. The implementation is conservative—it only supports object sizes for now, with object types planned as a follow-up—and aligns with Git’s existing capability advertisement patterns. The patch looks production-ready and should interest anyone working with large repositories or performance-sensitive workflows.
