This is a **bugfix** targeting the trace2 subsystem. Derrick Stolee addresses a real-world issue where Git crashes with a "recursion detected in die handler" error when timestamp formatting fails in trace2 telemetry. The root cause appears to be `xsnprintf()` calls in `tr2_tbuf.c` that trigger `die()` if the formatted timestamp overflows the buffer, which can happen if system calls like `gettimeofday()` or `gmtime_r()` fail or return unexpected values.

The patch replaces `xsnprintf()` with `snprintf()` and adds defensive initialization of `timeval` and `tm` structs to zero. If formatting fails, it falls back to a hardcoded "blank" timestamp (e.g., `1900-00-00T00:00:00.000000Z`) instead of crashing. This change is motivated by user reports of the issue occurring in client-side telemetry (using the 'event' trace2 format), where the failure during `atexit` events created infinite recursion.

The commit message is thorough, explaining the observed symptoms, the code path involved, and the rationale for the fix. It acknowledges uncertainty about the exact cause of the system call failures but justifies the defense-in-depth approach. The patch touches only `trace2/tr2_tbuf.c` and removes all `xsnprintf()` uses from the trace2 directory, leaving two `xstrdup()` calls (which only fail on OOM) untouched.

No test accompanies the change, as the issue depends on system call failures that are hard to reproduce. The patch is well-scoped and addresses a clear stability problem in a subsystem (trace2) that is increasingly used for telemetry. The fallback timestamps are designed to be obviously invalid, signaling the error to trace consumers without masking it. This looks like a solid fix for a real, if rare, crash.
