This is a refactoring patch series (v5) that migrates two long-standing global configuration flags—`trust_executable_bit` and `has_symlinks`—into `struct repo_config_values`, tying them to specific repository instances. The series is part of the ongoing `the_repository` removal effort and builds directly on the recently merged v4, which handled only `trust_executable_bit`. Tian Yuchen has now reintroduced the `has_symlinks` migration (as patch 4/4) after deferring it in earlier iterations due to implementation complexity.

The work touches core index and configuration plumbing, updating `read-cache.c`, `environment.c/h`, `apply.c`, and `compat/mingw.c`. The migration is mechanical and behavior-preserving, maintaining eager parsing for performance in hot paths. New getter functions (`repo_trust_executable_bit()` and `repo_has_symlinks()`) are introduced, and all call sites are updated to use repository-scoped access. The series also cleans up redundant extern declarations and relocates `ce_mode_from_stat()` for better code organization.

Notable changes since v4 include dropping a comment for `repo_executable_bit()`, preferring the `repo` parameter over `the_repository` where possible, and addressing `compat/mingw.c` with a fallback variable (though the author questions whether a cleaner solution exists). The series now spans four patches, with the final one tackling `has_symlinks`—a more complex migration due to its deeper integration.
