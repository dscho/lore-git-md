This is a refactoring patch targeting the `show-branch` command. The sixth iteration of a standalone patch by Gatla Vishweshwar Reddy, it completes the conversion of `git show-branch` from using the shared `object.flags` field for per-commit state to a dedicated commit-slab (`commit_rev_flags`) with configurable stride. The patch is now technically ready for maintainer sign-off, having addressed all feedback from Junio C Hamano on v5.

The core change lifts the previous 27-branch limit to 64 branches by using a `uint64_t`-based slab, with infrastructure in place for dynamic stride to support even more branches in the future. The `UNINTERESTING` bit remains in `object.flags` for revision-walking compatibility, while all per-branch reachability bits move to the slab. Key helper functions (`get_rev_flags_ptr`, `or_rev_flag_bit`, `test_rev_flag_bit`, `has_only_rev_flag_bit`, etc.) encapsulate slab access, and `has_only_rev_flag_bit` preserves the original semantics in `show_independent`: a commit is independent only if reachable from exactly one tip.

The v6 delta from v5 restores two critical behaviors in `join_revs`: propagation of the `UNINTERESTING` bit to parents (without smudging the current commit) and the original logic that avoids redundant traversal. It also updates documentation and error messages to reflect the new 64-branch limit and replaces the non-portable `%zu` format specifier with `%lu` and an explicit `(unsigned long)` cast. Three new tests in `t3202-show-branch.sh` verify that `show-branch` works correctly with 30+ branches, including `--independent` and `--merge-base` modes.

Files touched: `builtin/show-branch.c` (primary refactoring), `Documentation/git-show-branch.adoc` (limit update), and `t/t3202-show-branch.sh` (new tests). The patch reuses the `init_commit_rev_flags_with_stride` infrastructure from the 2025 variable-length bitset slab series and is part of the ongoing effort to eliminate misuse of `object.flags` across Git’s codebase. No open questions remain; the patch is uncontested and ready for integration.
