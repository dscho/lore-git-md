This is patch 4/9 in v4 of Patrick Steinhardt’s ODB abstraction series. It makes the iteration of bitmapped objects abortable by propagating non-zero return values from the `show_reach` callback through `show_objects_for_type()` and `for_each_bitmapped_object()`. The patch updates two callers (`builtin/pack-objects.c` and `builtin/rev-list.c`) to return `0` instead of `1` to preserve existing behavior, as their callbacks previously returned `1` but the return value was ignored.

The change is a prerequisite for lifting bitmapped object iteration into the packed backend’s `odb_for_each_object()` callback, which expects early termination on non-zero returns. The patch addresses a latent bug: once bitmapped iteration becomes accessible via the generic ODB interface, callers could accidentally trigger infinite loops or incorrect behavior by returning non-zero values. The fix is mechanical and aligns the bitmap traversal path with the non-bitmap path’s calling convention, though a follow-up series (Taylor Blau’s two-patch proposal) will further refine the callback type split to avoid a "foot-gun" where `traverse_commit_list()` ignores callback returns while `for_each_bitmapped_object()` respects them.

Files touched: `builtin/pack-objects.c`, `builtin/rev-list.c`, `pack-bitmap.c`, and `pack-bitmap.h`. Key symbols: `show_objects_for_type()` (now returns `int`), `for_each_bitmapped_object()` (now propagates callback return values), and the callbacks `add_object_entry_from_bitmap()` and `show_object_fast()` (updated to return `0`). The patch is a refactoring with no user-visible behavior change, but it enables future ODB-mediated filtering in `git cat-file --batch-all-objects`. Review feedback from Taylor Blau and Jeff King (v2/v3) has been fully addressed, and the patch is ready for integration.
