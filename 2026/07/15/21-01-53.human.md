This is the fifth revision of Michael Montalbo's RFC series introducing `diff.<driver>.process`, a long-running subprocess protocol that lets external tools inject diff hunks into Git's diff and blame pipelines while preserving Git's display features (word diff, function context, color-moved). The series is now technically complete, with all substantive review feedback addressed, and is approaching readiness for merging.

The key advance in v5 is the addition of three new patches that extend the process's reach beyond patch output and blame to the summary formats (`--stat`, `--numstat`, `--shortstat`) and `git log -L` range tracking. These features now consult the tool's hunks, so a file the tool reports as equivalent contributes no stat line and a reformat-only commit is dropped from the line-log rather than shown with an empty diff. The series also adds preparatory documentation (patch 1) that contrasts the new process driver with the existing `diff.<driver>.command`, making the trade-offs explicit.

The protocol now carries the old and new blob object names (`old-oid`/`new-oid`) so tools can cache their analysis keyed on the blob pair. A side's oid is sent only when the content the tool receives is the raw blob (omitted under textconv or for a working-tree side with no stored object), so any oid that is sent always names the bytes the tool sees. The hunk validation is stricter: it now checks per-gap alignment (not just the total unchanged-line count) and caps hunk accumulation to the combined line count of the two files, so a misbehaving tool cannot drive unbounded memory growth before validation. The hunk parser ignores unknown trailing fields for forward-compatibility.

The series is well-motivated: structural/AST-based diff tools like Difftastic can produce better line matching than Git's builtin algorithm, but the existing `diff.<driver>.command` replaces Git's output entirely, losing display features and never benefiting blame or `git log -L`. The process protocol solves both problems by letting the tool control which lines Git considers changed while Git handles all output formatting. The blame integration demonstrates a key use case: skipping reformat-only commits in history analysis while preserving semantic change attribution.

The implementation is thorough: 9 patches, 2500+ lines, 950-line test script covering success and error paths, and a C-based test helper (replacing the Python one from v3). The subprocess management is refactored to store the process on the `userdiff_driver` struct rather than in a hashmap, and the protocol follows `filter.<driver>.process` with capability negotiation and pkt-line framing. Error handling is robust: SIGPIPE protection, input validation, and graceful fallback to the builtin diff on tool failure.

The series has addressed all blocking concerns: Windows compatibility (path handling with spaces), scripting language dependency (C test helper), and the maintainer's stylistic guidance. Junio Hamano has explicitly endorsed the C-based test helper approach, and the last substantive review feedback (from Johannes Schindelin) is now implemented. The remaining work is documentation refinements around flag behavior interactions and final maintainer sign-off on the overall justification.
