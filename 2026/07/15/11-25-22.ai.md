This is a **design discussion reply** in René Scharfe’s 5-patch series introducing repository-aware tempfile APIs for the `the_repository` removal effort. René responds to Patrick Steinhardt’s substantive review of patch 1/5, where Patrick questioned whether passing a full `struct repository *` is overkill when only the `core.sharedRepository` setting is needed.

René acknowledges the conceptual tension: `create_tempfile()` sounds generic but is actually repository-specific because it respects shared permissions. He agrees that a repository-less variant *could* be cleaner in theory, but in practice, every caller already has access to at least `the_repository`, so the current design is sufficient. The exchange leaves the door open for future refactoring if a genuine need for a repository-less API emerges, but neither party sees an immediate use case. This reply does not alter the series’ trajectory—no v2 is expected for this point—but it clarifies the rationale behind the chosen approach and reinforces that the current implementation is pragmatic rather than over-engineered.

The discussion remains confined to plumbing-level design; no user-visible behavior or broader architectural concerns are at stake. The series is still queued in Junio’s `seen` branch, and this reply does not introduce new technical debt or unresolved questions.
