This thread is about a bugfix for a crash in Git’s trace2 telemetry subsystem. Derrick Stolee identified that Git can crash with a "recursion detected in die handler" error when timestamp formatting fails in trace2, particularly during `atexit` events. The issue stems from `xsnprintf()` calls in `tr2_tbuf.c` that trigger `die()` if system calls like `gettimeofday()` or `gmtime_r()` fail or return unexpected values, leading to infinite recursion.

The fix replaces `xsnprintf()` with `snprintf()` and adds defensive initialization of `timeval` and `tm` structs to zero. If formatting fails, it falls back to a hardcoded "blank" timestamp (e.g., `1900-00-00T00:00:00.000000Z`) instead of crashing. The patch is narrowly scoped to `trace2/tr2_tbuf.c` and removes all `xsnprintf()` uses from the trace2 directory, leaving only two `xstrdup()` calls (which fail only on OOM) untouched. No test accompanies the change, as the issue depends on rare system call failures that are difficult to reproduce. The fallback timestamps are designed to be obviously invalid, ensuring the error is visible to trace consumers without masking it.

This is a straightforward stability fix for a real-world issue in a subsystem increasingly used for telemetry. The patch has not yet received any reviews or discussion, so its status remains "under review."
