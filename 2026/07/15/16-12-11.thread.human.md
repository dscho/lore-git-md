This thread is about a bugfix for a Git crash on Windows caused by a recursion in the die handler when timestamp formatting fails in the trace2 telemetry subsystem. The crash occurs during `atexit` events when `xsnprintf()` calls in `tr2_tbuf.c` trigger `die()` due to system call failures in `gettimeofday()` or `gmtime_r()`, or more specifically, due to Git for Windows’s redirection of `vsnprintf()` to `libintl_vsnprintf()`, which allocates memory for format strings with more than six placeholders (trace2 uses seven).

Derrick Stolee proposed a patch that replaces `xsnprintf()` with `snprintf()` in trace2, initializes time-related structs defensively, and falls back to a hardcoded timestamp on failure. Taylor Blau suggested an alternative fix targeting the `xsnprintf()`/`libintl` boundary in a MinGW-specific way, which Junio Hamano refined to avoid cluttering shared code. The discussion has converged on a two-part solution: Derrick’s patch for hardening trace2 and Taylor’s platform-isolated fix. No new patch versions have been posted yet, but the next step is likely a revised patch implementing Taylor’s fix in a MinGW-specific file.

The key participants—Derrick, Taylor, and Junio—agree on the root cause and the complementary nature of the fixes. Derrick’s patch is seen as a necessary hardening measure, while Taylor’s alternative addresses the broader issue in a platform-specific way. Junio also raised a broader question about whether trace2’s error handling needs a more comprehensive audit, but this is not a blocker for the current fixes. The lack of test coverage is acknowledged, as the issue depends on transient system call or allocation failures that are hard to reproduce. The thread remains under review, with no outstanding objections.
