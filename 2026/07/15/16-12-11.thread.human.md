The goal is to ensure Git never crashes during telemetry operations, even under extreme conditions, by replacing banned functions with defensive fallbacks that degrade gracefully (e.g., hardcoded timestamps, `NULL` returns, or a static fallback context).

The series is now complete with v3, which addresses all prior feedback. Key changes include:
- A new `banned-die.h` header to enforce compile-time bans on `die()`-prone functions in trace2 (and potentially other subsystems in the future).
- Replacements for banned helpers with manual error handling (e.g., `calloc()` instead of `xcalloc()`, `strdup()` instead of `xstrdup()`).
- A statically allocated fallback context for thread-local storage (TLS) when dynamic allocation fails, ensuring trace2 can continue operating with degraded telemetry (e.g., `"unknown"` thread names, dropped events).
- Test updates to verify the `:<REDACTED>` string format in redacted URLs and other edge cases.
