This thread is about a seven-part patch series from Derrick Stolee that hardens Git’s trace2 telemetry subsystem to prevent crashes caused by memory allocation or system call failures. The original issue—a "recursion detected in die handler" error on Git for Windows—was traced to `xsnprintf()` failing in trace2’s timestamp formatting, but the series now aims to eliminate *all* `die()`-triggering helpers (like `xstrdup()`, `ALLOC_ARRAY()`, and `xstrfmt()`) from trace2. The goal is to ensure Git never crashes during telemetry operations, even under stress, by replacing these functions with defensive fallbacks that degrade gracefully (e.g., returning `NULL`, using hardcoded timestamps, or skipping events).

The series introduces `banned-die.h`, a new header that enforces compile-time bans on `die()`-prone functions in trace2, and has evolved through three versions to address feedback. Key changes include fixing an off-by-one error in redaction logic, improving error handling in config parsing, and adding tests to verify the `:<REDACTED>` format in URLs. Junio Hamano (the maintainer) has endorsed the approach, while Jeff King (Peff) has raised broader concerns: the compile-time bans don’t address indirect `die()` calls via helpers like `strbuf` or `json-writer.c`, leaving the door open for crashes. Derrick acknowledges this limitation but argues the series is a pragmatic first step, and Patrick Steinhardt has suggested the `banned-die.h` pattern could be reused for other architectural constraints (e.g., banning `the_repository` in specific subsystems).

The latest version (v3) is under review, with all prior feedback addressed. The series is self-contained to trace2 but could set a precedent for future hardening efforts. Open questions include whether a ground-up rewrite of trace2 is needed to fully eliminate `die()` dependencies, how to test failure cases, and the long-term impact on trace consumers (who may see degraded data under failure conditions). The MinGW-specific fix proposed by Taylor Blau remains a planned follow-up. For now, the focus is on merging the current series as incremental progress.
