This thread is about a critical bugfix and hardening effort for Git’s trace2 subsystem, led by Derrick Stolee. The goal is to prevent Git crashes caused by `die()`-triggering helpers (like `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, and now `xcalloc()`) under memory pressure or system call failures. The original crash—a "recursion detected in die handler" error—was traced to `xsnprintf()` failures in trace2 timestamp formatting, particularly on Git for Windows due to `libintl_vsnprintf()` memory allocations. The solution has evolved into a seven-patch series that systematically replaces these helpers with defensive fallbacks, prioritizing process stability over telemetry completeness.

Derrick’s series is now complete, with the final patch replacing `xcalloc()` in `tr2tls_create_self()` with a statically allocated fallback context that uses the thread name `"unknown"` to signal allocation failure. This ensures the process degrades gracefully rather than crashing, even if telemetry data is lost. The series touches 16 files within the trace2 subsystem and introduces `banned-die.h` as a new enforcement mechanism to block `die()`-triggering helpers. Key changes include hardcoded timestamps, `NULL` returns, and counters for unrecorded regions, all designed to keep Git running under failure conditions. The patches are self-contained and do not alter on-disk formats or user-visible behavior, though telemetry consumers may see malformed or missing data.

The thread has seen no objections or technical concerns, and the approach aligns with prior feedback from Junio Hamano and Taylor Blau. The only remaining loose end is a planned MinGW-specific follow-up (Taylor’s alternative to disable `libintl_vsnprintf()` redirection for `xsnprintf()`), which will be implemented separately. The series is under review, and the introduction of `banned-die.h` could serve as a template for hardening other low-level subsystems in the future. Testing remains a challenge due to the transient nature of allocation failures, but the hardening is well-motivated and addresses a real-world stability issue.
