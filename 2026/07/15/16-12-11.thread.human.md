This thread is about fixing a Git crash in the trace2 subsystem, where a "recursion detected in die handler" error occurs when timestamp formatting fails during `atexit` events. The crash is specific to Git for Windows and stems from `xsnprintf()` calls in `tr2_tbuf.c` triggering `die()` due to memory allocation failures in `libintl_vsnprintf()` (which Git for Windows redirects `vsnprintf()` to). Derrick Stolee originally proposed a patch to replace `xsnprintf()` with `snprintf()` in trace2 and add defensive initialization, while Taylor Blau suggested an alternative fix targeting the `xsnprintf()`/`libintl` boundary in a MinGW-specific way.

The discussion has converged on a two-part solution: Derrick’s patch (hardening trace2) and Taylor’s alternative (disabling `libintl_vsnprintf()` redirection for `xsnprintf()` in a platform-isolated file). Junio Hamano, the maintainer, endorsed both approaches but recommended implementing Taylor’s fix in a MinGW-specific file (e.g., `compat/mingw/`) to avoid cluttering shared code. In his latest update, Derrick confirmed that allocation failures are the likely root cause and plans to revise his patch to reflect this, while also replacing `xstrdup()` in trace2 to further harden against allocation-related crashes. He will also explore implementing Taylor’s fix in the suggested MinGW-specific manner. No revised patches have been posted yet, but the plan is clear, and all participants remain aligned. Open questions include how to validate the fix without reproducible test cases and whether trace2’s error handling needs a broader audit, though neither is a blocker for the current fixes.
