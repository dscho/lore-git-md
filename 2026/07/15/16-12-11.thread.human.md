This thread is about fixing a Git crash in the trace2 telemetry subsystem, where a "recursion detected in die handler" error occurs when timestamp formatting fails. The crash happens during `atexit` events, creating infinite recursion in the die handler. Derrick Stolee initially proposed a patch replacing `xsnprintf()` with `snprintf()` in `tr2_tbuf.c` and adding defensive initialization to avoid crashes, falling back to a hardcoded timestamp on failure.

Taylor Blau’s review identified a deeper root cause: Git for Windows’s redirection of `vsnprintf()` to `libintl_vsnprintf()`, which allocates memory for format strings with more than six placeholders (trace2 uses seven). This allocation failure triggers `xsnprintf()`’s `die()`, causing the recursion. Taylor suggested an alternative fix targeting `wrapper.c` to disable `libintl_vsnprintf()` redirection for `xsnprintf()`, addressing the broader issue rather than the trace2-specific symptom.

Derrick has now acknowledged Taylor’s analysis and agreed that the alternative is architecturally cleaner. However, he still defends his original patch, arguing that trace2 should avoid `die()` entirely where possible. The thread seems to be converging on a two-part fix: Taylor’s approach to resolve the `xsnprintf()`/`libintl` boundary and Derrick’s patch to harden trace2 against reentrancy. The discussion remains collaborative, with both contributors agreeing on the broader issue while leaving room for further testing. No test coverage is proposed, as the issue depends on transient system call or allocation failures, which are difficult to reproduce. The platform focus remains Git for Windows, where `libintl_vsnprintf()`’s behavior differs from POSIX.
