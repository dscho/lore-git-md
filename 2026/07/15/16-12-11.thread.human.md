This thread is about a bugfix for a Git crash in the trace2 telemetry subsystem, where a "recursion detected in die handler" error occurs when timestamp formatting fails during `atexit` events. The crash stems from `xsnprintf()` calls in `tr2_tbuf.c` triggering `die()` due to memory allocation failures in Git for Windows’s `libintl_vsnprintf()` redirection, which allocates memory for format strings with more than 6 placeholders (trace2 uses 7). Derrick Stolee proposed a patch to replace `xsnprintf()` with `snprintf()` in trace2, add defensive initialization, and fall back to a hardcoded timestamp on failure, while Taylor Blau suggested a MinGW-specific fix to disable `libintl_vsnprintf()` redirection for `xsnprintf()`.

The discussion has converged on a two-part solution: Derrick’s patch to harden trace2 (including replacing `xstrdup()`) and Taylor’s platform-isolated fix. Junio Hamano, the maintainer, has endorsed both approaches and suggested implementing Taylor’s fix in a MinGW-specific file to avoid cluttering shared code. No new objections or technical concerns have been raised, and the thread remains under review while Derrick works on revised patches. The fix targets `trace2/tr2_tbuf.c` and a future MinGW-specific file, with no changes to on-disk format or test coverage (due to the difficulty of reproducing allocation failures). Open questions include the specifics of the allocation failures and whether a broader audit of trace2’s error handling is needed, though neither is a blocker. The thread is collaborative, with all participants aligned on the path forward.
