This is the core implementation patch in the `diff.<driver>.process` RFC series, now at version 5 (patch 5/9). It introduces the long-running subprocess protocol that lets external tools inject custom diff hunks into Git's diff and blame pipelines while preserving downstream features like word diff, function context, and color-moved.

The patch adds `diff-process.c` and `diff-process.h`, which implement the pkt-line protocol handshake and per-file request/response loop. The tool receives file pairs and returns hunks that reference line numbers in the content; Git uses these instead of its builtin diff algorithm but still controls all output formatting. The protocol negotiates version 1 and capability "hunks", with per-file requests sending command=hunks, pathname, optional old-oid/new-oid (for blob-based caching), and both file contents. The tool responds with zero or more hunk lines and a status packet (success, error, or abort). On error or abort, Git falls back to the builtin diff for that file or the entire session, respectively.

Key technical details include robust error handling (malformed hunks trigger warnings and fallbacks), hunk validation (checking for out-of-bounds line numbers, overlapping hunks, and misaligned unchanged runs), and subprocess lifecycle management (the process is stored on the `userdiff_driver` struct and launched on first use). The implementation also handles edge cases like empty file sides, trailing-newline-only changes, and whitespace-ignoring flags that bypass the process entirely. The test coverage is comprehensive, with 645 lines of shell tests exercising success paths, error conditions, and edge cases like overlapping hunks and tool crashes.
