This is the first patch in Patrick Steinhardt’s nine-patch v4 series introducing object filters to `odb_for_each_object()`. It targets the packed object database backend and addresses an inefficiency in object lookups during enumeration.

The patch fixes a redundant lookup problem: when iterating through objects in a packed source (either via a multi-pack index or individual packfiles), the code uses the index to enumerate objects but then ignores the index-provided data for the actual object lookup, instead calling the generic `odb_source_read_object_info()`. This forces a second index traversal to locate the object, which is inefficient and subtly incorrect—it risks selecting the wrong pack if the object exists in multiple packs.

The fix replaces the generic lookup with direct calls to `packed_object_info()`, using the pack and offset data already available from the index. The patch also renames the `store` variable to `source` for clarity, though this rename is mixed into the same patch as the lookup logic change, which some reviewers have noted as a minor stylistic nit.

No behavior changes are expected for end users, and the on-disk format is unaffected. The change is purely internal to the ODB subsystem, specifically `odb/source-packed.c`. Review feedback on earlier versions identified the inefficiency and confirmed the fix’s correctness; the only remaining discussion is the surface-level nit about mixing unrelated changes in the same patch, which does not block integration.
