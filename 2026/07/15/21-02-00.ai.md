This is the blame integration patch for the `diff.<driver>.process` series, the seventh of nine patches in v5. It teaches `git blame` to consult an external diff process when one is configured, allowing the tool to declare commits as having no semantic changes (returning zero hunks) so blame can skip them and attribute lines to earlier commits.

The patch introduces `xdi_diff_process()`, a shared helper in `diff-process.c` that consults the diff process, runs xdiff on the tool’s hunks (or falls back to the builtin algorithm if the process doesn’t apply), and returns `DIFF_PROCESS_EQUIVALENT` when the tool reports no changes. Blame’s `pass_blame_to_parent()` uses this helper to decide whether to skip a commit: if the process returns no hunks, blame treats the commit as a no-op and continues traversing the file’s history. The subprocess remains long-running across the entire blame operation, amortizing startup costs, but each commit still incurs a round-trip to the tool.

Key technical details: the patch handles blame’s whitespace-ignoring options (`-w`, `-b`, etc.) by bypassing the process entirely when they’re active (since the tool can’t honor them), and it omits blob object names in the protocol because blame diffs each blob pair only once, making a per-invocation cache key unnecessary. The test coverage (60+ lines in `t/t4080-diff-process.sh`) exercises the core functionality—skipping reformat-only commits, respecting tool-provided hunks, and correctly bypassing the process for `--no-ext-diff` and `-w`.

This patch demonstrates the series’ design goal: tight integration with Git’s existing pipelines while preserving all downstream features. The implementation is careful about error handling (falling back to the builtin diff on process errors) and performance (noting the ~17% overhead in blame operations, with OID-based caching identified as future work). The shared `xdi_diff_process()` helper will be reused by `git log -L` in a later patch, showing the infrastructure’s reusability. All substantive review feedback from earlier rounds has been addressed, and the patch is ready for final sign-off.
