Subject: [PATCH v2 0/2] mv: fix misleading error for missing destination directory
Series version: v3 (two-patch series)
Originating author: Lucas Zamboni Orioli (via GitGitGadget)
Thread type: bugfix patch series

Core problem or goal
`git mv` emits a misleading error when the destination's parent directory does not exist, incorrectly blaming the source file (e.g., "renaming 'src' failed: No such file or directory"). The series fixes this in two commits: the first improves the error message by naming both source and destination paths, and the second adds an early existence check for the destination directory (and its intermediate components) to enable `--dry-run` detection.

Current status
Under review; v3 posted, addressing all substantive feedback. The first patch (error message clarity) remains approved by Junio C Hamano ("Makes sense"). The second patch (early directory existence check) now **fully resolves Junio's feedback**: it uses `stat()` instead of `lstat()` to align with `rename()`'s behavior, explicitly checks for non-directory destinations (reporting "destination is not a directory"), and validates intermediate path components (reporting "destination directory does not exist"). The TOCTOU race remains acknowledged but unresolved, as it is considered "the best we can do" for now. The series is ready for final review and appears uncontroversial.

Key technical details
- Files touched: `builtin/mv.c`, `t/t7001-mv.sh`
- New behavior: error message now includes both source and destination paths (e.g., "renaming A -> B failed: no such file or directory"); early `stat()` check for destination directory existence enables `--dry-run` detection and explicitly handles non-directory destinations, invalid intermediate components, and symlinks (accepts symlinks to directories, rejects symlinks to files)
- Old behavior: misleading error blaming source file; `--dry-run` could not detect missing destination directories
- New symbols: none (internal logic changes only)
- Test coverage: new tests in `t/t7001-mv.sh` covering missing directories, non-directory path components, symlinks (both to files and directories), and `--dry-run` detection
- Edge cases handled: directory moves, sparse entries, out-of-cone destinations, trailing slashes in destination path, symlinks, regular files, and non-directory intermediate components in destination path
- On-disk format: unchanged
- l10n impact: new translatable string for the improved error message (`"renaming '%s' to '%s' failed"` in the first patch); minor consideration for the non-directory case (whether to reuse the existing "does not exist" message or introduce a new string)

Open questions and loose ends
- TOCTOU race: the destination directory could disappear between the `stat()` check and the `rename(2)` syscall (raised by Ben Knoble; acknowledged as "the best we can do" by Junio; no proposed fix yet)
- l10n string reuse: whether to introduce a new translatable string for the non-directory case or reuse the existing "does not exist" message (minor consideration flagged by the author)
- Interaction with sparse-checkout and worktree modes (mentioned as areas for follow-up discussion)
- Whether the two commits should remain separate or be squashed (author's v3 proposal keeps them split; no new feedback on this point)
