Subject: [PATCH v2 0/2] mv: fix misleading error for missing destination directory
Series version: v3 (two-patch series)
Originating author: Lucas Zamboni Orioli (via GitGitGadget)
Thread type: bugfix patch series

Core problem or goal
`git mv` emits a misleading error when the destination's parent directory does not exist, incorrectly blaming the source file (e.g., "renaming 'src' failed: No such file or directory"). The series fixes this in two commits: the first improves the error message by naming both source and destination paths, and the second adds an early existence check for the destination directory (and its intermediate components) to enable `--dry-run` detection.

Current status
Under review; v3 posted. The first patch (error message clarity) remains approved ("Makes sense"). The second patch (early directory existence check) is **contested on symlink-handling strategy**: Junio C Hamano **rejects the `stat()`-based approach** adopted in v3, arguing that **any tracked symlink in the destination path should block the move**, regardless of whether it points to a directory or file. He insists on `lstat()` (which does not follow symlinks) to avoid unsafe traversal and align with `git apply` precedent. The TOCTOU race remains acknowledged but unresolved ("the best we can do"). The two-patch structure is unchanged. Pablo Sabater’s **surface-level review** of the second patch addressed only cosmetic style nits (indentation, brace placement) and did not engage with the symlink-handling dispute or other technical concerns. No merge status; the series is not yet ready for integration.

Key technical details
- Files touched: `builtin/mv.c`, `t/t7001-mv.sh`
- New behavior: error message now includes both source and destination paths (e.g., "renaming A -> B failed: no such file or directory"); early existence check for destination directory enables `--dry-run` detection and explicitly handles non-directory destinations, invalid intermediate components, and symlinks (behavior now **contested**: v3 accepted symlinks to directories and rejected symlinks to files; Junio's feedback implies rejecting **all** symlinks in destination path).
- Old behavior: misleading error blaming source file; `--dry-run` could not detect missing destination directories.
- New symbols: none (internal logic changes only).
- Test coverage: new tests in `t/t7001-mv.sh` covering missing directories, non-directory path components, symlinks (both to files and directories), `--dry-run` detection, directory moves, sparse entries, out-of-cone destinations, trailing slashes in destination path, and non-directory intermediate components in destination path. **Test expectations may need revision** to reject all symlinks in destination path (not just symlinks to files).
- Edge cases handled: symlinks (behavior now **explicitly contested**: Junio requires rejection of any tracked symlink in destination path, even if it points to a directory), regular files, non-directory intermediate components, trailing slashes.
- On-disk format: unchanged.
- l10n impact: new translatable string for the improved error message (`"renaming '%s' to '%s' failed"` in the first patch) and one new string for non-directory destinations (`"destination is not a directory"` in the second patch); reuses existing "destination directory does not exist" message for ENOENT/ENOTDIR errors.

Open questions and loose ends
- **Symlink-handling strategy**: whether to use `stat()` (follows symlinks, aligns with `rename()` behavior) or `lstat()` (does not follow symlinks, rejects **all** symlinks in destination path). Junio insists on `lstat()`; Lucas's v3 used `stat()`.
- **TOCTOU race**: the destination directory could disappear between the existence check and the `rename(2)` syscall (raised by Ben Knoble; acknowledged as "the best we can do" by Junio; no proposed fix yet).
- **Interaction with sparse-checkout and worktree modes** (mentioned as areas for follow-up discussion; no actionable feedback yet).
- **Commit structure**: whether the two commits should remain separate or be squashed (author's v3 proposal keeps them split; no new feedback on this point).
