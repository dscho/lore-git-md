Core problem or goal
`git mv` emits misleading error messages when the destination's parent directory does not exist or contains problematic components, incorrectly blaming the source file (e.g., "renaming 'src' failed: No such file or directory"). The series fixes this in two commits: the first improves error messages to include both source and destination paths, and the second adds an early existence check for the destination directory (and its intermediate components) to enable `--dry-run` detection and explicitly reject three problematic cases: missing directories, non-directory components, and **any tracked symlink in the destination path** (regardless of target type). The symlink rejection addresses an index/worktree inconsistency bug where following a symlink leaves the index recording the literal symlink path while the file is moved to the resolved target.

Key technical details
- Files touched: `builtin/mv.c`, `t/t7001-mv.sh`
- New behavior: error message now includes both source and destination paths (e.g., "renaming A -> B failed: no such file or directory"); early existence check for destination directory enables `--dry-run` detection and explicitly rejects missing directories, non-directory components, and **any tracked symlink** (final or intermediate) in the destination path. The check uses `has_symlink_leading_path()` to avoid following symlinks.
- Old behavior: misleading error blaming source file; `--dry-run` could not detect missing destination directories; symlinks in destination path could cause index/worktree inconsistency.
- New symbols: `needs_worktree_rename()` (helper function for deduplicated logic; internal use only).
- Test coverage: updated tests in `t/t7001-mv.sh` cover symlinks as both final and intermediate components (146 new test lines), alongside existing cases for missing directories, non-directory path components, `--dry-run` detection, directory moves, sparse entries, out-of-cone destinations, trailing slashes, non-directory intermediate components, moving into existing directories, and bare filenames in the current working directory. Includes a regression test for the index corruption scenario.
- Edge cases handled: symlinks (now rejected regardless of target type), regular files, non-directory intermediate components, trailing slashes, bare filenames, normalized destinations (e.g., `dir/file`).
- On-disk format: unchanged.
- l10n impact: two new translatable strings (improved error message and "destination is beyond a symbolic link"); no changes to existing strings.

Open questions and loose ends
