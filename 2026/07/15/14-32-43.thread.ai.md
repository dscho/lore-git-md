Subject: [PATCH] mv: fix misleading error for missing destination directory
Series version: standalone patch (no series)
Originating author: Lucas Zamboni Orioli (via GitGitGadget)
Thread type: bugfix patch

Core problem or goal
`git mv` currently emits a misleading error message when the destination's parent directory does not exist. The error incorrectly blames the source file (e.g., "renaming 'src' failed: No such file or directory") even though the source exists and the problem is the missing destination directory. The patch moves the detection of this condition into the checking phase so the error message clearly identifies the missing directory and `--dry-run` also catches the problem.

Current status
Under review; no prior versions. The patch is narrowly scoped to `builtin/mv.c`, adding a new check during the entry-processing loop that statically verifies the existence of the destination's leading directory only when the move will actually be performed on disk (excluding directory moves, sparse entries, or out-of-cone destinations). The error message reuses the existing "destination directory does not exist" string.

Key technical details
- Files touched: `builtin/mv.c`, `t/t7001-mv.sh`
- New behavior: error message now correctly identifies missing destination directory; `--dry-run` detects the problem
- Old behavior: misleading error blaming source file
- New symbols: none (internal logic change only)
- Test coverage: two new tests in `t/t7001-mv.sh` covering basic failure case and `--dry-run` detection
- Edge cases handled: directory moves, sparse entries, out-of-cone destinations, trailing slashes in destination path
- On-disk format: unchanged
