Subject: [PATCH v2 0/2] mv: fix misleading error for missing destination directory
Series version: v2 (two-patch series)
Originating author: Lucas Zamboni Orioli (via GitGitGadget)
Thread type: bugfix patch series

Core problem or goal
`git mv` emits a misleading error when the destination's parent directory does not exist, incorrectly blaming the source file (e.g., "renaming 'src' failed: No such file or directory"). The series fixes this in two commits: the first improves the error message by naming both source and destination paths, and the second adds an early existence check for the destination directory to enable `--dry-run` detection.

Current status
Under review; v2 posted. The first patch (error message clarity) remains approved by Junio C Hamano ("Makes sense"). The second patch (early directory existence check) now has **new substantive feedback** from Junio identifying edge cases in the `lstat`-based check: (1) paths that exist but are not directories (e.g., symlinks or regular files), and (2) intermediate path components that are not directories (e.g., `a/b/c` where `a/b` is a file). The current implementation treats these as success, but they will cause `rename(2)` to fail later. The TOCTOU race remains acknowledged but unresolved. The author has not yet posted a v3 addressing either the indentation style fix or the new edge-case feedback.

Key technical details
- Files touched: `builtin/mv.c`, `t/t7001-mv.sh`
- New behavior: error message now includes both source and destination paths (e.g., "renaming A -> B failed: no such file or directory"); early `lstat` check for destination directory existence enables `--dry-run` detection
- Old behavior: misleading error blaming source file; `--dry-run` could not detect missing destination directories
- New symbols: none (internal logic changes only)

- l10n impact: new translatable string for the improved error message (`"renaming '%s' to '%s' failed"` in the first patch)
