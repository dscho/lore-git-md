Subject: [PATCH v2 0/2] mv: fix misleading error for missing destination directory
Series version: v3 (two-patch series, v4 expected)
Originating author: Lucas Zamboni Orioli (via GitGitGadget)
Thread type: bugfix patch series

Core problem or goal
`git mv` emits a misleading error when the destination's parent directory does not exist, incorrectly blaming the source file (e.g., "renaming 'src' failed: No such file or directory"). The series fixes this in two commits: the first improves the error message by naming both source and destination paths, and the second adds an early existence check for the destination directory (and its intermediate components) to enable `--dry-run` detection. The second patch now also **blocks moves through any tracked symlink in the destination path**, addressing an index/worktree inconsistency bug where following a symlink leaves the index recording the literal symlink path while the file is moved to the resolved target.

Current status
Under review; v3 posted, v4 expected. The first patch (error message clarity) remains approved ("Makes sense"). The second patch (early directory existence check) is **no longer contested on symlink-handling strategy**: Lucas has accepted Junio’s position that **any tracked symlink in the destination path should block the move**, regardless of whether it points to a directory or file. The fix will use `has_symlink_leading_path()` (from `symlinks.c`), aligning with `git apply` precedent and avoiding unsafe traversal. The TOCTOU race remains acknowledged but unresolved ("the best we can do"). The two-patch structure is unchanged. No merge status; the series is now ready for integration pending v4.

Key technical details
- Files touched: `builtin/mv.c`, `t/t7001-mv.sh`
- New behavior: error message now includes both source and destination paths (e.g., "renaming A -> B failed: no such file or directory"); early existence check for destination directory enables `--dry-run` detection and explicitly rejects missing directories, non-directory components, and **any tracked symlink** in the destination path (final or intermediate). The check will use `has_symlink_leading_path()` to avoid following symlinks.
- Old behavior: misleading error blaming source file; `--dry-run` could not detect missing destination directories; symlinks in destination path could cause index/worktree inconsistency.
- New symbols: none (internal logic changes only).
- Test coverage: updated tests in `t/t7001-mv.sh` will cover symlinks as both final and intermediate components, alongside existing cases for missing directories, non-directory path components, `--dry-run` detection, directory moves, sparse entries, out-of-cone destinations, trailing slashes, and non-directory intermediate components.
- Edge cases handled: symlinks (now rejected regardless of target type), regular files, non-directory intermediate components, trailing slashes.
- On-disk format: unchanged.
- l10n impact: two new translatable strings (improved error message and non-directory destination error); no changes to existing strings.
