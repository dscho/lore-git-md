Subject: [PATCH] mv: fix misleading error for missing destination directory
Series version: standalone patch (no series)
Originating author: Lucas Zamboni Orioli (via GitGitGadget)
Thread type: bugfix patch

Core problem or goal
`git mv` emits a misleading error when the destination's parent directory does not exist, incorrectly blaming the source file (e.g., "renaming 'src' failed: No such file or directory"). The patch moves the detection of this condition into the checking phase so the error message clearly identifies the missing directory and `--dry-run` also catches the problem.

Current status
Under review; no prior versions. The patch is narrowly scoped to `builtin/mv.c`, adding a static check during the entry-processing loop that verifies the existence of the destination's leading directory only when the move will actually be performed on disk (excluding directory moves, sparse entries, or out-of-cone destinations). The error message reuses the existing "destination directory does not exist" string.

Key technical details
- Files touched: `builtin/mv.c`, `t/t7001-mv.sh`
- New behavior: error message now correctly identifies missing destination directory; `--dry-run` detects the problem
- Old behavior: misleading error blaming source file
- New symbols: none (internal logic change only)
- Test coverage: two new tests in `t/t701-mv.sh` covering basic failure case and `--dry-run` detection
- Edge cases handled: directory moves, sparse entries, out-of-cone destinations, trailing slashes in destination path; TOCTOU race noted but not addressed in this patch
- On-disk format: unchanged

Open questions and loose ends
- Use of `lstat` (not `stat`) for directory existence check (still unresolved)
- Interaction with sparse-checkout and worktree modes (mentioned as areas for follow-up discussion)
- TOCTOU race: the destination directory could disappear between the new `lstat` check and the eventual `rename(2)` syscall (raised by Ben Knoble; no proposed fix yet)
- Error message clarity: suggestion to name both source and destination paths in the error message (e.g., "renaming A -> B failed: no such file or directory") for unambiguous diagnosis (raised by Ben Knoble)

Participant positions
- **Ben Knoble**: Substantive review identifying a TOCTOU race and suggesting an improved error message format that includes both source and destination paths. No testing or benchmarking reported. Position remains open pending author response or patch revision.
