This is the eighth patch in Patrick Steinhardt’s nine-patch series (v4) introducing object filters to `odb_for_each_object()`. It extends the ODB abstraction by allowing callers to pass object filters to backends, enabling optimizations like bitmap-based filtering. The patch implements this for the packed backend, exposing `can_filter_bitmap()` and introducing a new `bitmapped_for_each_object` callback to mediate between bitmap iteration and the ODB interface.

The core change adds a `filter` field to `struct odb_for_each_object_options`, letting backends optionally skip objects excluded by the filter. The packed backend now checks if the filter can be handled via bitmaps (using `can_filter_bitmap()`) and, if so, delegates iteration to `for_each_bitmapped_object()`. The new `bitmapped_for_each_object()` callback ensures objects are only yielded if they belong to the current source, preventing misattribution or duplicates. The patch also skips packs already covered by bitmaps during non-bitmap iteration to avoid redundant work.

Key symbols introduced or modified include the `filter` field in `odb_for_each_object_options`, the `bitmapped_for_each_object_data` struct, the `bitmapped_for_each_object()` callback, and the now-public `can_filter_bitmap()`. The packed backend’s `odb_source_packed_for_each_object()` is updated to use `prepare_bitmap_git_for_source()` (introduced in patch 7/9) and to skip packs already processed by bitmaps. The patch touches `odb.h`, `odb/source-packed.c`, `pack-bitmap.c`, and `pack-bitmap.h`, with no on-disk format changes.

Review feedback from earlier versions has been addressed: the `filter` field is now `const`, `can_filter_bitmap()` is exposed for backend use, and the bitmap iteration logic is source-aware. The patch is part of the ODB abstraction effort and depends on prior patches in the series, particularly patch 7/9’s `prepare_bitmap_git_for_source()`. It enables the final patch (9/9) to refactor `git cat-file` to use ODB-mediated filtering. No new review feedback is present in this version, and the patch appears ready for integration.
