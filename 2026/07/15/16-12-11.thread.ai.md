Thread identity: Bugfix patch targeting the trace2 subsystem to prevent a "recursion detected in die handler" crash when timestamp formatting fails in trace2 telemetry. Originating author: Derrick Stolee. Thread type: standalone patch (bugfix).

Core problem or goal: Fix a Git crash caused by `xsnprintf()` calls in `tr2_tbuf.c` that trigger `die()` if timestamp formatting fails (e.g., due to system call failures in `gettimeofday()` or `gmtime_r()`). The crash occurs during `atexit` events, creating infinite recursion in the die handler. The root cause is now understood to be Git for Windows’s redirection of `vsnprintf()` to `libintl_vsnprintf()`, which allocates memory for format strings with >6 placeholders (trace2 uses 7), causing `xsnprintf()` to `die()` and trigger recursion. The goal is to eliminate the crash by either (a) replacing `xsnprintf()` with `snprintf()` in trace2 and adding defensive initialization (Derrick’s patch), or (b) disabling `libintl_vsnprintf()` redirection for `xsnprintf()` in `wrapper.c` (Taylor Blau’s alternative), or both.

Current status: Under review. This is the first version of the patch, but the discussion has evolved to consider two complementary fixes. No prior iterations exist. The patch touches `trace2/tr2_tbuf.c` (Derrick’s patch) and may extend to `wrapper.c` (Taylor’s alternative). No test accompanies the change due to the difficulty of reproducing system call or allocation failures. Both contributors agree on the root cause and are exploring a two-part solution: Taylor’s alternative to address the `xsnprintf()`/`libintl` boundary, and Derrick’s patch to harden trace2 against reentrancy.
