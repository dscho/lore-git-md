Thread identity: Bugfix and hardening patch series targeting the trace2 subsystem to prevent crashes caused by `die()`-triggering helpers (e.g., `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, `xcalloc()`) under memory pressure or system call failures. Originating author: Derrick Stolee. Thread type: patch series (bugfix/hardening).

Core problem or goal: Eliminate all `die()`-triggering helpers from the trace2 API to prevent Git crashes during telemetry operations. The original crash (a "recursion detected in die handler" error) was caused by `xsnprintf()` failures in trace2 timestamp formatting, specifically due to `libintl_vsnprintf()` memory allocations on Git for Windows. The expanded goal is to harden trace2 against all allocation or system call failures by replacing banned functions with defensive fallbacks that prioritize process stability over telemetry completeness. The series introduces `banned-die.h` to systematically enforce this constraint across the trace2 subsystem and potentially other low-level subsystems in the future.

Current status: Under review. The first four patches have been posted: the first introduces `banned-die.h` as the enforcement mechanism, the second replaces `xsnprintf()` in timestamp formatting with `snprintf()` and defensive fallbacks, the third replaces `xstrdup()` in `tr2_sysenv.c` with `strdup()` and defensive fallbacks (returning `NULL` or halting config parsing on failure), and the fourth replaces `ALLOC_ARRAY()` in `trace2.c` with `calloc()` and defensive fallbacks (returning `NULL` to calling functions, which now check for failure). Junio’s feedback from the prior thread remains aligned with this approach, and no new objections or technical concerns have been raised. Key technical details:
- **Files touched**: `banned-die.h` (new), all trace2 `.c` files, and `trace2/tr2_tls.h`. The changes are self-contained to the trace2 subsystem, though the header’s placement at the root of the tree signals intent for future reuse in other subsystems.
- **Subsystem**: trace2 (telemetry), memory allocation, MinGW compatibility.
- **Behavior change**:
  - The first patch introduces no behavior changes; it only sets up the enforcement mechanism. The second patch replaces `xsnprintf()` in timestamp formatting with `snprintf()` and adds defensive fallbacks (e.g., hardcoded timestamps like `"1900-00-00T00:00:00.000000Z"`) to prevent `die()` calls under failure conditions. The third patch replaces `xstrdup()` in `tr2_sysenv.c` with `strdup()` and defensive fallbacks: `tr2_sysenv_cb()` halts config parsing on failure (returning a negative value), and `tr2_sysenv_get()` returns `NULL` (indistinguishable from an unset environment variable). The fourth patch replaces `ALLOC_ARRAY()` in `redact_argv()` with `calloc()` and defensive fallbacks: calling functions (`trace2_cmd_start_fl()`, `trace2_child_start_fl()`, and `trace2_exec_fl()`) now check for `NULL` and degrade gracefully by dropping telemetry rather than crashing. Subsequent patches will replace other `die()`-triggering helpers (e.g., `xstrfmt()`, `ALLOC_GROW()`, `xcalloc()`) with similar defensive alternatives.
  - Trace2 will tolerate allocation or system call failures by falling back to degraded operation (e.g., truncated messages, hardcoded timestamps, dropped events, or `NULL` returns) instead of crashing. This is a breaking change for trace consumers, who may see malformed or missing data under failure conditions, but the trade-off is intentional and documented. The series prioritizes process stability over telemetry completeness.
  - The new `banned-die.h` header centralizes the enforcement of "no `die()` in trace2" and is updated to block `ALLOC_ARRAY()`. Its structure is designed to be extensible for other banned functions and could serve as a template for hardening other low-level subsystems.
  - The fourth patch handles a subtle edge case in `redact_arg()`: it may return a `const char *` pointing to either the original argument (no allocation) or a newly allocated string (requiring freeing). The patch casts to `(char *)` when freeing to avoid deeper refactoring, a pragmatic trade-off.
- **On-disk format**: No changes.
- **Test coverage**: None, as the issue depends on transient allocation or system call failures that are hard to reproduce. The series acknowledges this limitation.
- **Platform focus**: Primarily Git for Windows, where `libintl_vsnprintf()`’s allocation behavior differs from POSIX, but the hardening applies to all platforms.
