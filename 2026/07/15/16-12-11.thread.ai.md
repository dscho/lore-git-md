Thread identity: Bugfix and hardening patch series targeting the trace2 subsystem to prevent crashes caused by `die()`-triggering helpers (e.g., `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, `xcalloc()`) under memory pressure or system call failures. Originating author: Derrick Stolee. Thread type: patch series (bugfix/hardening).

Core problem or goal: Eliminate all `die()`-triggering helpers from the trace2 API to prevent Git crashes during telemetry operations. The original crash (a "recursion detected in die handler" error) was caused by `xsnprintf()` failures in trace2 timestamp formatting, specifically due to `libintl_vsnprintf()` memory allocations on Git for Windows. The expanded goal is to harden trace2 against all allocation or system call failures by replacing banned functions with defensive fallbacks that prioritize process stability over telemetry completeness. The series introduces `banned-die.h` to systematically enforce this constraint across the trace2 subsystem and potentially other low-level subsystems in the future.

Key technical details:
- **Files touched**: `banned-die.h` (updated to block `xcalloc()`), all trace2 `.c` files (`trace2/tr2_ctr.c`, `trace2/tr2_tls.c`, `trace2/tr2_tmr.c`), and `trace2/tr2_tls.h`. The changes are self-contained to the trace2 subsystem, though the header’s placement at the root of the tree signals intent for future reuse in other subsystems.
- **Subsystem**: trace2 (telemetry), memory allocation, MinGW compatibility.
- **Behavior change**:
  - The first patch introduces no behavior changes; it only sets up the enforcement mechanism. The second patch replaces `xsnprintf()` in timestamp formatting with `snprintf()` and adds defensive fallbacks (e.g., hardcoded timestamps like `"1900-00-00T00:00:00.000000Z"`) to prevent `die()` calls under failure conditions. The third patch replaces `xstrdup()` in `tr2_sysenv.c` with `strdup()` and defensive fallbacks: `tr2_sysenv_cb()` halts config parsing on failure (returning a negative value), and `tr2_sysenv_get()` returns `NULL` (indistinguishable from an unset environment variable). The fourth patch replaces `ALLOC_ARRAY()` in `redact_argv()` with `calloc()` and defensive fallbacks: calling functions (`trace2_cmd_start_fl()`, `trace2_child_start_fl()`, and `trace2_exec_fl()`) now check for `NULL` and degrade gracefully by dropping telemetry rather than crashing. The fifth patch replaces `xstrfmt()` in `redact_arg()` with manual string concatenation using `memcpy()`, overflow checks (`unsigned_add_overflows()`), and defensive fallbacks: if allocation or formatting fails, the function returns `NULL`, and callers (`redact_argv()`) propagate the failure by freeing partially allocated memory and returning `NULL`. The sixth patch replaces `ALLOC_GROW()` in `tr2_tls.c` with a manual reallocation strategy and a `nr_skipped_regions` counter: when reallocation fails, the code increments the counter and skips further stack growth, allowing the process to continue with degraded telemetry (e.g., missing timing data for deeply nested regions) rather than crashing. The counter is decremented as regions are exited, ensuring graceful degradation without memory leaks. The seventh patch replaces `xcalloc()` in `tr2tls_create_self()` with `calloc()` and introduces a **statically allocated fallback context** (`tr2tls_thread_fallback`) that uses the thread name `"unknown"` to signal allocation failure. When allocation fails, the code returns this fallback context instead of crashing. The new `tr2tls_is_fallback()` helper allows callers to detect and handle the fallback state, ensuring no modifications are attempted on the read-only fallback context. The patch also updates all trace2 counter and timer functions (`tr2_ctr.c`, `tr2_tmr.c`) to short-circuit when operating on a fallback context, preserving process stability at the cost of degraded telemetry (e.g., dropped counter/timer events).
  - Trace2 will tolerate allocation or system call failures by falling back to degraded operation (e.g., truncated messages, hardcoded timestamps, dropped events, `NULL` returns, unrecorded regions, or a static fallback context) instead of crashing. This is a breaking change for trace consumers, who may see malformed or missing data under failure conditions, but the trade-off is intentional and documented. The series prioritizes process stability over telemetry completeness.
  - The new `banned-die.h` header centralizes the enforcement of "no `die()` in trace2" and is updated to block `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, and `xcalloc()`. Its structure is designed to be extensible for other banned functions and could serve as a template for hardening other low-level subsystems.
  - The seventh patch handles a subtle edge case in thread-local storage: the fallback context is statically allocated and read-only, requiring callers to detect and handle it gracefully. This avoids complex error propagation while ensuring the process remains alive.

- **Platform focus**: Primarily Git for Windows, where `libintl_vsnprintf()`’s allocation behavior differs from POSIX, but the hardening applies to all platforms.
