Thread identity: Bugfix and hardening patch series targeting the trace2 subsystem to prevent crashes caused by `die()`-triggering helpers (e.g., `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, `xcalloc()`) under memory pressure or system call failures. Originating author: Derrick Stolee. Thread type: patch series (bugfix/hardening).

Core problem or goal: Eliminate all `die()`-triggering helpers from the trace2 API to prevent Git crashes during telemetry operations. The original crash (a "recursion detected in die handler" error) was caused by `xsnprintf()` failures in trace2 timestamp formatting, specifically due to `libintl_vsnprintf()` memory allocations on Git for Windows. The expanded goal is to harden trace2 against all allocation or system call failures by replacing banned functions with defensive fallbacks that prioritize process stability over telemetry completeness. The series introduces `banned-die.h` as a general-purpose enforcement mechanism to systematically block `die()`-prone functions in trace2 and potentially other low-level subsystems, with Junio C Hamano clarifying that the banned functions are prohibited due to their potential to trigger `die()` in unsafe contexts (e.g., `atexit()` handlers).

Key technical details:
- **Files touched**: `banned-die.h` (new header to block `die()`-triggering functions), all trace2 `.c` files (`trace2/tr2_ctr.c`, `trace2/tr2_tls.c`, `trace2/tr2_tmr.c`), and `trace2/tr2_tls.h`. The changes are self-contained to the trace2 subsystem, though the header’s placement at the root of the tree signals intent for future reuse in other subsystems.
- **Subsystem**: trace2 (telemetry), memory allocation, MinGW compatibility, and architectural enforcement mechanisms.
- **Behavior change**:
  - The first patch introduces `banned-die.h` to enforce the prohibition of `die()`-triggering functions (e.g., `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, `xcalloc()`) in trace2. The header is designed to be extensible for other banned functions or traits (e.g., `the_repository`, `the_hash_algo`) in future hardening efforts.
  - Subsequent patches replace banned functions with defensive fallbacks:
    - `xsnprintf()` in timestamp formatting is replaced with `snprintf()` and hardcoded fallbacks (e.g., `"1900-00-00T00:00:00.000000Z"`).
    - `xstrdup()` in `tr2_sysenv.c` is replaced with `strdup()`, with `tr2_sysenv_cb()` halting config parsing on failure and `tr2_sysenv_get()` returning `NULL`.
    - `ALLOC_ARRAY()` in `redact_argv()` is replaced with `calloc()`, with callers degrading gracefully by dropping telemetry on `NULL`.
    - `xstrfmt()` in `redact_arg()` is replaced with manual string concatenation and overflow checks, returning `NULL` on failure.
    - `ALLOC_GROW()` in `tr2_tls.c` is replaced with manual reallocation and a `nr_skipped_regions` counter to skip stack growth on failure.
    - `xcalloc()` in `tr2tls_create_self()` is replaced with `calloc()` and a **statically allocated fallback context** (`tr2tls_thread_fallback`) that uses the thread name `"unknown"` to signal failure. The new `tr2tls_is_fallback()` helper allows callers to detect and handle the fallback state, and trace2 counter/timer functions short-circuit when operating on a fallback context.
  - Trace2 will tolerate allocation or system call failures by falling back to degraded operation (e.g., truncated messages, hardcoded timestamps, dropped events, `NULL` returns, unrecorded regions, or a static fallback context) instead of crashing. This is a breaking change for trace consumers, who may see malformed or missing data under failure conditions, but the trade-off is intentional and documented.
- **On-disk format**: No changes.
- **Test coverage**: None, as the issue depends on transient allocation or system call failures that are hard to reproduce. The series acknowledges this limitation.
- **Platform focus**: Primarily Git for Windows, where `libintl_vsnprintf()`’s allocation behavior differs from POSIX, but the hardening applies to all platforms.
