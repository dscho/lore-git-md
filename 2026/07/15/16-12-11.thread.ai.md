Thread identity: Bugfix patch targeting the trace2 subsystem to prevent a "recursion detected in die handler" crash when timestamp formatting fails in trace2 telemetry. Originating author: Derrick Stolee. Thread type: standalone patch (bugfix).

Core problem or goal: Fix a Git crash caused by `xsnprintf()` calls in `tr2_tbuf.c` that trigger `die()` if timestamp formatting fails (e.g., due to system call failures in `gettimeofday()` or `gmtime_r()`). The crash occurs during `atexit` events, creating infinite recursion in the die handler. The goal is to replace `xsnprintf()` with `snprintf()` and add defensive initialization to avoid crashes, falling back to a hardcoded "blank" timestamp on failure.

Current status: Under review. This is the first version of the patch (no prior iterations). The patch is well-scoped, touching only `trace2/tr2_tbuf.c`, and removes all `xsnprintf()` uses from the trace2 directory while preserving two `xstrdup()` calls (which only fail on OOM). No test accompanies the change due to the difficulty of reproducing system call failures.

Key technical details:
- **Files touched**: `trace2/tr2_tbuf.c`.
- **Subsystem**: trace2 (telemetry).
- **Behavior change**: Replaces `xsnprintf()` with `snprintf()` and initializes `timeval` and `tm` structs to zero. Falls back to a hardcoded timestamp (e.g., `1900-00-00T00:00:00.000000Z`) on formatting failure.
- **On-disk format**: No changes.
- **Test coverage**: None (issue depends on system call failures, which are hard to reproduce).

Open questions and loose ends: None identified. The patch is self-contained and addresses the crash without introducing new dependencies or follow-ups. The fallback timestamp is designed to be obviously invalid, ensuring the error is visible to trace consumers.
