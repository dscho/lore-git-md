Thread identity: Bugfix and hardening patch series targeting the trace2 subsystem to prevent crashes caused by `die()`-triggering helpers (e.g., `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, `xcalloc()`) under memory pressure or system call failures. Originating author: Derrick Stolee. Thread type: patch series (bugfix/hardening).

Core problem or goal: Eliminate all `die()`-triggering helpers from the trace2 API to prevent Git crashes during telemetry operations. The original crash (a "recursion detected in die handler" error) was caused by `xsnprintf()` failures in trace2 timestamp formatting, specifically due to `libintl_vsnprintf()` memory allocations on Git for Windows. The expanded goal is to harden trace2 against all allocation or system call failures by replacing banned functions with defensive fallbacks that prioritize process stability over telemetry completeness. The series introduces `banned-die.h` as a general-purpose enforcement mechanism to systematically block `die()`-prone functions in trace2 and potentially other low-level subsystems. The architectural debate now centers on whether compile-time bans (as implemented) are sufficient or if a broader rewrite of trace2’s dependencies is needed to address indirect `die()` calls via helpers like `strbuf` or `json-writer.c`. Derrick Stolee defends the current approach as a pragmatic first step, while Jeff King argues it is incomplete and may require a ground-up rewrite.

- **Behavior change**:
  - The first patch introduces `banned-die.h` to enforce the prohibition of `die()`-triggering functions (e.g., `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, `xcalloc()`) in trace2. The naming inconsistency (`BANNED(die)`) and include-ordering risk are now fixed, with a local comment in `trace2.c` documenting the requirement that `banned-die.h` must be included last.
  - Subsequent patches replace banned functions with defensive fallbacks:
    - `xsnprintf()` in timestamp formatting is replaced with `snprintf()` and hardcoded fallbacks (e.g., `"1900-00-00T00:00:00.000000Z"`).
    - `xstrdup()` in `tr2_sysenv.c` is replaced with `strdup()`, with `tr2_sysenv_cb()` now returning `0` (instead of `-1`) on failure to terminate the config parsing loop early without signaling a fatal error. This prevents the config system from interpreting an allocation failure as a malformed config value, ensuring graceful degradation under memory pressure. However, Elijah Newren’s review reveals that the error path still triggered a `die()` in `git_parse_source()` via `xstrfmt()` in the original version; Derrick’s latest reply addresses this by changing the return value to `0`.
    - `ALLOC_ARRAY()` in `redact_argv()` is replaced with `calloc()`, with callers degrading gracefully by dropping telemetry on `NULL`.
    - `xstrfmt()` in `redact_arg()` (fifth patch) is replaced with manual string concatenation and overflow checks, returning `NULL` on failure. Elijah Newren’s review identifies a one-byte off-by-one error in the manual string construction: the patch copies `redact_len - 1` bytes of the `:<REDACTED>` placeholder, omitting the trailing `>` and producing `:<REDACTED` instead of `:<REDACTED>`. Junio’s latest reply confirms this error and clarifies that the fix requires copying `redact_len` bytes to include the trailing `>`.
    - `ALLOC_GROW()` in `tr2_tls.c` (sixth patch) is replaced with manual reallocation and a `nr_skipped_regions` counter to skip stack growth on failure. However, when applied in isolation, this patch breaks the invariant that the region stack cannot underflow, triggering a `BUG()` in `tr2tls_pop_unwind_self()` with the message `"no open regions in thread 'main'"`. The regression is resolved by the seventh patch, which replaces `xcalloc()` and ensures the fallback context is properly initialized.
    - `xcalloc()` in `tr2tls_create_self()` (seventh patch) is replaced with `calloc()` and a **statically allocated fallback context** (`tr2tls_thread_fallback`) that uses the thread name `"unknown"` to signal failure. The new `tr2tls_is_fallback()` helper allows callers to detect and handle the fallback state, and trace2 counter/timer functions short-circuit when operating on a fallback context.
  - Trace2 will tolerate allocation or system call failures by falling back to degraded operation (e.g., truncated messages, hardcoded timestamps, dropped events, `NULL` returns, unrecorded regions, or a static fallback context) instead of crashing. This is a breaking change for trace consumers, who may see malformed or missing data under failure conditions, but the trade-off is intentional and documented. Jeff King’s review implies that this degradation may still be insufficient if trace2 remains dependent on helpers like `strbuf` that could crash Git despite the hardening.
