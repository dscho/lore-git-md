Thread identity: Bugfix patch targeting the trace2 subsystem to prevent a "recursion detected in die handler" crash when timestamp formatting fails in trace2 telemetry. Originating author: Derrick Stolee. Thread type: standalone patch (bugfix).

Core problem or goal: Fix a Git crash caused by `xsnprintf()` calls in `tr2_tbuf.c` that trigger `die()` if timestamp formatting fails due to system call failures (e.g., `gettimeofday()` or `gmtime_r()`) or memory allocation failures in `libintl_vsnprintf()`. The crash occurs during `atexit` events, creating infinite recursion in the die handler. The root cause is Git for Windows’s redirection of `vsnprintf()` to `libintl_vsnprintf()`, which allocates memory for format strings with >6 placeholders (trace2 uses 7), causing `xsnprintf()` to `die()` and trigger recursion. The goal is to eliminate the crash via a two-part solution: (1) Derrick’s patch, which replaces `xsnprintf()` with `snprintf()` in trace2, adds defensive initialization, and falls back to a hardcoded timestamp on failure, and (2) a MinGW-specific fix (Taylor Blau’s alternative, as refined by Junio) to disable `libintl_vsnprintf()` redirection for `xsnprintf()` in a platform-isolated file (e.g., `compat/mingw/`). Derrick also plans to replace `xstrdup()` in trace2 to further harden against allocation-related crashes.
