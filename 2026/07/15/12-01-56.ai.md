This is a refactoring patch in the ongoing effort to eliminate misuse of `object.flags` in Git. Gatla Vishweshwar Reddy’s v5 patch converts `builtin/show-branch.c` to use a commit-slab (`commit_rev_flags`) for per-commit branch-tracking state, replacing the previous direct use of `commit->object.flags`. The patch lifts the 27-branch limit to 64 branches by using a configurable stride of `uint64_t` words, and preserves the `UNINTERESTING` bit in `object.flags` for revision-walking compatibility. The regression in `show_independent()` (where the slab-based version weakened the independence check from *exactly* the current branch’s bit to *at least* that bit) is now fixed via the `has_only_rev_flag_bit()` helper, restoring the original semantics.

The patch addresses Junio C Hamano’s feedback from v4 by retaining the TODO comment about eventually storing ref names directly in the slab and removing the local `#define UNINTERESTING` in favor of the common definition from `<revision.h>`. The changes are mechanical and do not affect the patch’s core logic. The patch touches only `builtin/show-branch.c`, introducing new slab infrastructure (`commit_rev_flags`, `flags_stride`, and helper functions like `get_rev_flags_ptr()` and `or_rev_flag_bit()`) and updating all bit operations to use `UINT64_C(1)` for correct 64-bit shifts. Existing tests continue to pass, and the patch is uncontested on its technical merits.

This is the fifth iteration of the patch, superseding Gatla’s v3 and v4, Meet Soni’s earlier RFC, and an earlier version by Gatla. The patch reuses the `init_commit_rev_flags_with_stride` infrastructure from the 2025 variable-length bitset slab series (commit 20250225011757.GA752084) and is part of the broader effort to eliminate `object.flags` misuse. The author has acknowledged Patrick Steinhardt’s meta-level reminder about replying inline to review comments, and the patch is now ready for maintainer sign-off pending Junio’s final approval of the mechanical cleanups.

Key symbols introduced or modified include `commit_rev_flags` (the slab), `flags_stride` (configurable stride for the slab), and helper functions like `has_only_rev_flag_bit()` (critical for restoring the independence check). The patch does not change user-visible behavior but removes a long-standing limitation and aligns the code with Git’s canonical pattern for per-commit data storage.
