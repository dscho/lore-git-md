This is the final patch in Harald Nordgren’s `git branch --delete-merged` series, now ready for merging. It adds `--dry-run` support to the new `--delete-merged` subcommand, allowing users to preview which branches would be deleted without modifying refs or configuration. The implementation is clean and well-tested, with no functional changes since the last iteration—only the mechanical loop variable fix from v21 applies here.

The patch updates `builtin/branch.c` to introduce the `DELETE_BRANCH_DRY_RUN` flag, which suppresses ref/config deletion and prints "Would delete branch <name>" messages instead. The flag is passed through the existing `delete_branches()` API, ensuring consistent behavior with the real deletion path. Documentation in `git-branch.adoc` clearly explains the feature’s purpose (sanity-checking wide patterns like `origin/*` before committing to deletions), and the patch rejects the nonsensical `--dry-run --quiet` combination upfront.

Test coverage is thorough, verifying that `--dry-run` output matches the real deletion messages exactly, respects stacked-branch protection, and preserves configuration. The tests also confirm the command rejects `--dry-run` without `--delete-merged`.
