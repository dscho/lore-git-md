This is the third patch in Harald Nordgren’s seven-patch `git branch --delete-merged` series, which is now implementation-complete and ready for merging. This patch adds a `DELETE_BRANCH_SKIP_UNMERGED` flag to the branch-deletion API, allowing bulk callers (like the upcoming `--delete-merged` subcommand) to silently skip unmerged branches instead of aborting with an error.

The change is minimal and targeted: it modifies `check_branch_commit()` and `delete_branches()` to suppress the "not fully merged" error and advice when the new flag is set, while preserving the existing behavior for all current callers. The flag is checked at both the commit-checking and deletion stages, ensuring unmerged branches are skipped without triggering a failure. This is critical for the `--delete-merged` subcommand, which needs to handle unmerged branches gracefully as part of its bulk operation.

The patch is purely mechanical and introduces no behavioral changes for existing users. It touches only `builtin/branch.c` and is well-tested in later patches that exercise the `--delete-merged` subcommand. Phillip Wood’s earlier review identified a maintenance risk in the flags-based API (local boolean caching), but this was resolved in a prior patch by eliminating such caching entirely, ensuring the flags remain the single source of truth. The patch is low-risk and directly supports the series’ goal of safe, automated branch cleanup.
