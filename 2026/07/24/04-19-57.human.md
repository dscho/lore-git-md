This is a **platform compatibility bugfix** for macOS, addressing a severe memory leak in Git’s use of the system regex engine (TRE) when processing invalid UTF-8 sequences. The patch is under review, with Junio C Hamano raising two main questions: whether Git should carry a workaround for a macOS bug at all, and how long the workaround might need to persist.

The issue is real and impactful—Chungmin Lee reports that a single `git grep` over binary files (like PDFs) can leak gigabytes of memory, triggering kernel watchdog panics on macOS. The proposed fix is narrowly scoped: it splits input buffers at invalid multibyte sequences using `mbrtowc()`, ensuring the leaking code path in TRE is never reached while preserving all genuine matches. The implementation is clean, with detailed comments explaining the constraints (e.g., anchoring `^`/`$` at true buffer boundaries) and regression tests in `t7810-grep.sh` to verify correctness.

Junio’s questions are procedural rather than technical. He asks whether Git should take on the burden of working around a platform bug, and whether the patch’s structure (a new `compat/regexec.c` file and conditional compilation) is future-proof if other platforms need similar overrides. The patch itself is well-crafted, with a clear commit message, thorough test coverage, and no behavioral regressions for valid UTF-8 input. If the project decides to accept platform-specific workarounds for such severe issues, this patch is ready. **Worth attention from macOS users and reviewers familiar with regex internals.**
