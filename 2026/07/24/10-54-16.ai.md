This is a small refactoring patch in the security-hardened `git cat-file --batch-command` remote-object-info series, now at v21 and queued for `next`. The patch fixes a signed/unsigned type mismatch in `fetch-pack.c`: `hash_algo_by_name()` returns an `unsigned int`, but the local `hash_algo` variable was declared as `int`. The mismatch is currently masked by `DISABLE_SIGN_COMPARE_WARNINGS`, but the function will soon be moved to `connect.c` (in a later patch in the same series), where the warning would become visible.

The change is mechanical: the variable is updated to `const unsigned int` to match the return type of `hash_algo_by_name()`, and marked `const` because it is never modified. The patch touches a single line in `fetch-pack.c` and has no behavioral impact. It is a prerequisite for the upcoming function relocation and ensures type consistency across the codebase. The fix is uncontroversial and aligns with the series' broader focus on robustness and maintainability.
