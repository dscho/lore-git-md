This is the final patch in Harald Nordgren’s **`git branch --delete-merged`** series, adding `--dry-run` support to the new subcommand. The patch is **ready for merging** and completes the feature set promised in the cover letter.

The implementation adds a `DELETE_BRANCH_DRY_RUN` flag to the deletion API, which suppresses ref and config modifications while printing "Would delete" or "Would skip" messages for each affected branch. The flag is only accepted when `--delete-merged` is specified, and the nonsensical `--dry-run --quiet` combination is rejected. The output matches the real deletion/protection output exactly, making it a reliable preview mechanism. The patch updates `Documentation/git-branch.adoc` and adds three new tests in `t/t3200-branch.sh` to verify `--dry-run` functionality, including edge cases like stacked-branch protection and the rejection of `--dry-run` without `--delete-merged`.

The changes are minimal and targeted: the flag is plumbed through `delete_branches()` and `delete_merged_branches()`, and `spare_stacked_bases()` skips config updates during dry runs to avoid side effects. The implementation is **well-tested** and **consistent with Git’s existing dry-run patterns** (e.g., `git clean --dry-run`). Phillip Wood’s review of this patch suggested only minor commit message wording improvements and noted the `--dry-run --quiet` combination as a potential UX quirk, which Harald Nordgren addressed by rejecting it as nonsensical. The patch is **uncontroversial** and **aligns with the series’ safety-focused design**.
