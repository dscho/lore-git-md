This is a bugfix patch for `git clone` that prevents a segmentation fault when using `--revision` with protocol v0 against servers that advertise more refs than requested. The patch is now in its second version and includes both the fix and a regression test.

The issue occurs in `update_remote_refs()` when `guess_remote_head()` returns a non-NULL `remote_head_points_at` whose `peer_ref` field is NULL. The original code unconditionally dereferenced `remote_head_points_at->peer_ref->name`, causing a crash. The fix adds a NULL check for `remote_head_points_at->peer_ref` before proceeding. The test case enforces protocol v0 and verifies that cloning with `--revision` works as expected.

The commit message has been expanded to clearly explain the protocol v0 vs. v2 behavior difference and the code path leading to the crash. The test file `t/t5621-clone-revision.sh` now includes a new test case that reproduces the issue and confirms the fix. This addresses the last remaining action item from the maintainer's feedback on the initial submission.

The patch touches only `builtin/clone.c` and the test file, making it a minimal, targeted fix. The regression test ensures the bug cannot reappear unnoticed. All technical discussion appears resolved, and the patch is ready for merging.
