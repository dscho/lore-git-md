Subject: [PATCH 0/3] config --url: add scp-style URL support
Series version: v1
Originating author: Fabian Pottbäcker
Thread type: patch series

Core problem or goal
Add scp-style SSH URL support (e.g., `host:path`) to `git config --url`, bringing it into consistency with nearly every other Git command that already accepts this syntax. The change is motivated by scripting convenience: tools that extract or manipulate remote URLs from Git configuration (e.g., from user-facing "clone" buttons) often encounter scp-style URLs and need to parse them.

Current status
Under review. Three-patch series posted as v1. No prior versions.

Key technical details
- Files touched: `builtin/config.c`, `urlmatch.c`, `t/t1300-config.sh` (tests extended in patch 2), `t/unit-tests/u-urlmatch-normalization.c` (new unit tests in patch 1).
- New or renamed symbols: none.
- Behavior change: `git config --url` now parses scp-style SSH URLs (`host:path`) in addition to explicit schemes (`ssh://`, `ftp://`, etc.).
- On-disk format: unchanged.
- Test coverage: patch 1 adds unit tests for URL normalization (default port stripping for SSH/FTP); patch 2 extends `t1300-config.sh` with 14 lines of test cases mirroring existing `--get-urlmatch` coverage; patch 3 switches to the shared `url_parse` function (already used elsewhere in Git) and updates documentation to clarify that `--url` supports all URL formats (including scp-style), unlike the config-file URL syntax used in `http.<url>.*` options.
- Dependencies: none.

Open questions and loose ends
- **Comment nit (patch 1)**: Ben Knoble identified a copy-paste error in the comments for FTP and SSH default-port normalization: the comments incorrectly read "Skip http :21" and "Skip http :22" instead of "Skip ftp :21" and "Skip ssh :22". The code logic is correct, but the comments are misleading. This is a low-weight but actionable request for a fix before the patch lands.
