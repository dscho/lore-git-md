This is a small feature series that adds scp-style URL support to `git config --url`. Currently, almost all Git commands accept scp-style URLs (e.g., `user@host:path`), but `git config --url` is a notable exception, which limits its usefulness in scripting scenarios where users want to extract or manipulate remote URLs programmatically.

The series consists of three patches. The first normalizes default ports for SSH and FTP URLs to ensure consistent parsing. The second adds missing tests for `git config --url`, mirroring existing coverage for `--get-urlmatch`. The third patch updates `git config --url` to use the `url_parse` function, enabling it to handle scp-style URLs just like other Git commands.

The motivation is practical: many Git hosting services default to scp-style URLs in their clone instructions, and scripting tools that rely on `git config --url` (e.g., for setting up author identities based on remote URLs) currently fail with this format. The author notes that while this change could be extended further (e.g., integrating with `fmt_ident` for automatic identity management), those enhancements are out of scope for now.

The patches touch `urlmatch.c`, `builtin/config.c`, and the test suite, with a net addition of 85 lines. The changes are narrowly focused and appear well-scoped for the stated goal. No prior discussion or controversy is evident from the cover letter. If you work with Git scripting or remote URL handling, this series might be worth a closer look.
