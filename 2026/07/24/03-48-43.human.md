This is the fourth patch in Patrick Steinhardt’s five-part series making Git’s on-disk object database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort, which aims to allow alternative backends beyond the traditional loose-object and packfile storage.

This patch introduces a small but useful helper function, `odb_source_type_to_name()`, that maps an ODB source type (e.g., `ODB_SOURCE_LOOSE`, `ODB_SOURCE_PACKED`) to a human-readable string like `"loose"` or `"packed"`. The function is immediately used to improve the error messages in the downcasting macros across all ODB source backends. Instead of printing raw enum values (`BUG("trying to downcast source of type '3' to loose")`), the messages now show the actual type names (`BUG("trying to downcast source of type 'packed' to 'loose'")`), making debugging easier.

The change is mechanical and touches only the ODB source headers and implementation files. It’s a clean, low-risk improvement that doesn’t alter behavior but makes future debugging and error reporting clearer. The patch is well-explained and fits neatly into the larger series, which is already under review and targeting the current development cycle. If the series lands, this helper will be a small but welcome usability win for anyone working on ODB internals.
