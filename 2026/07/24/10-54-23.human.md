This is the core feature patch in the long-running `git cat-file --batch-command` remote-object-info series, now at version 21 and cooking in `next`. It adds the `remote-object-info` command to `` `git cat-file --batch-command` ``, allowing users to query object metadata (currently just size, with type support planned) from a remote repository without downloading the full objects.

The patch implements the command with careful attention to performance and robustness. Instead of making one request per object, it batches multiple OIDs into a single query to minimize overhead. Input validation is strict: URLs are capped at 8KB, batches at 10,000 objects, and OIDs must be full-length (no short OIDs). The command dynamically adapts to server-advertised capabilities, skipping unsupported placeholders like `%(objecttype)` to avoid crashes. Memory safety is ensured with `xcalloc` and a new `free_object_info_contents()` helper. The implementation also handles edge cases like missing objects, unsupported protocols, and malformed inputs gracefully.

Test coverage is thorough: 719 lines of new tests in `t/t1017-cat-file-remote-object-info.sh` exercise all three smart transports (`git://`, `file://`, `http://`), `--buffer` mode, `-Z` output, and edge cases like short OIDs and malformed inputs. The tests confirm that objects are *not* downloaded from the remote, a key security and performance guarantee.
