This thread is about a five-patch series from Taylor Blau that hardens Git’s packfile subsystem against packs containing duplicate object entries. The series aims to ensure that components like reverse indexes, delta resolution, MIDX verification, and bitmap generation handle such packs correctly without breaking existing functionality. While duplicate entries in packs are technically invalid, Git currently tolerates them until operations like `git fsck` or `git repack` encounter them—this series shifts toward early detection to prevent downstream issues.

Junio C Hamano, the maintainer, has weighed in to clarify that packs with duplicates are not just unusual but invalid, and he supports the series’ goal of catching these issues sooner. His reply serves as an implicit acknowledgment of the direction, though no formal Reviewed-by or Acked-by has been recorded yet. The series remains under initial review, with no prior versions or merge status reported.

Key technical changes include adjustments to delta resolution logic to handle cycles involving duplicates, MIDX verification updates to accept any duplicate copy of an object, and safeguards in bitmap generation and multi-pack reuse to prevent crashes or incorrect object emission. Tests have been added or extended to cover these scenarios. Open questions include the performance impact of the delta cycle fallback and whether the MIDX-related changes fully address all edge cases. So far, no substantive reviews have been posted, but the series appears technically sound and unlikely to face major objections.
