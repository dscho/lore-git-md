This thread is a five-part bugfix series from Taylor Blau aimed at hardening Git’s packfile subsystem to handle duplicate object entries consistently. The series addresses a gap where components like reverse indexes, delta resolution, MIDX verification, and bitmap generation either mishandle or reject packs containing duplicates, despite Git’s general tolerance for them outside strict indexing. The goal is to ensure these packs remain readable, verifiable, and safe for operations like bitmap-assisted fetches, while preserving `index-pack`’s existing duplicate policy.

The first patch, just posted, focuses on test coverage. It adds a new test in `t/t5308-pack-detect-duplicates.sh` to verify that per-pack reverse indexes correctly retain and map duplicate entries back to their physical order in the pack. The test constructs a pack with objects in the sequence A, B, A, C and confirms that the reverse index preserves both copies of A, checking both on-disk and in-memory implementations. This sets the stage for the rest of the series, which will adjust the internal logic to handle duplicates properly. No review feedback has arrived yet, and the series remains under initial review with no merge status reported. The key technical areas touched include `packfile.c`, `pack-bitmap.c`, and `midx.c`, with no on-disk format changes. Open questions include the performance impact of delta cycle fallbacks and whether the MIDX verification changes fully address all edge cases.
