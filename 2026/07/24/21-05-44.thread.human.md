Taylor Blau’s five-part bugfix series to harden Git’s packfile subsystem against duplicate object entries is now complete with the posting of v1. The series ensures that components like reverse indexes, delta resolution, MIDX verification, and bitmap generation handle packs containing duplicate entries without breaking existing functionality. The final patch, just sent, addresses a subtle but critical issue in multi-pack index (MIDX) bitmap reuse: when a preferred pack contains duplicates, the MIDX’s one-bit-per-OID mapping no longer aligns with the physical pack’s entry order, risking incorrect object emission or duplication. The fix disables verbatim reuse and whole-word selection when the bitmap and physical counts differ, falling back to the ordinary packing path when necessary. This conservative approach prioritizes correctness over performance and should be uncontroversial, though no reviews have yet been posted.

The series touches several subsystems, including `packfile.c` (delta resolution), `pack-bitmap.c`, `midx.c`, and test files like `t5308-pack-detect-duplicates.sh` and `t5332-multi-pack-reuse.sh`. Key changes include adjusting reverse indexes to retain duplicates, implementing a depth-first search fallback for delta resolution cycles, and ensuring MIDX verification accepts any duplicate copy of an object. The final patch also adds a guard in the bitmap test helper to reject packs with duplicates, preventing crashes. While the series is under initial review, the narrow scope of each patch—directly addressing invariants without altering on-disk formats—suggests high likelihood of acceptance once feedback is received. Open questions remain about the performance impact of delta cycle fallback and whether MIDX verification fully covers all duplicate-related edge cases.
