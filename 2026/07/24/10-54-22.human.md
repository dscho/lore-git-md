This is the eleventh patch in the twenty-first iteration of the `git cat-file --batch-command` remote-object-info series, now cooking in `next`. The patch adds client-side support for the `object-info` protocol v2 capability, allowing Git to query object metadata (currently only size) from a remote repository without downloading the full object.

The implementation introduces a new `fetch_object_info()` function in `fetch-object-info.c` that sends an `object-info` command to the server, parses the response, and populates an array of `struct object_info` with the results. The function is protocol-v2-only and returns an error if the server does not advertise the `object-info` capability. A new `unrecognized` field in `struct object_info` tracks whether the server did not recognize a requested object, and the response parsing strictly validates the format (e.g., checking for empty strings to detect unrecognized objects).

The transport layer is extended with a `fetch_object_info` vtable entry, implemented for both smart transports (`fetch_object_info_via_pack`) and transport helpers (`fetch_object_info_helper`). The smart transport implementation buffers the entire request in memory (following the pattern in `fetch-pack.c`) and handles the protocol negotiation, while the helper implementation delegates to the transport helper process. The patch also updates the transport vtable structures (`taken_over_vtable` and `builtin_smart_vtable`) to expose the new functionality.

The code is well-structured and includes input validation (e.g., checking for malformed size values with `parse_object_size()`), bounds checking, and error handling. The commit message clearly documents the design choices, such as the decision to buffer the request rather than stream it, and the rationale for the new `unrecognized` field. This patch is a critical piece of the series, enabling the `remote-object-info` command in `git cat-file --batch-command` (introduced in patch 12/13) to function.
