This is patch 11/13 in the GSoC v21 `git cat-file --batch-command` remote-object-info series, which is now queued for `next`. It implements the **client-side transport layer** for the `object-info` protocol v2 capability, enabling Git to query object metadata (currently size only) from remote repositories without downloading the full objects.

The patch adds a new file, `fetch-object-info.c`, which contains the core logic for sending `object-info` requests and parsing responses. Key details:
- **Protocol handling**: The client sends a request with the `object-info` command, supported attributes (currently only `size`), and a list of OIDs. The request is buffered in memory (following the pattern in `fetch-pack.c`) and sent in one go.
- **Response parsing**: The server’s response is parsed line-by-line, with strict validation of OIDs and attribute counts. A new `unrecognized` field in `struct object_info` is set when the server does not recognize an OID, and the `size` attribute is parsed into a `size_t` with overflow protection.
- **Transport integration**: The patch extends the transport vtable with a `fetch_object_info` method, implemented for both smart transports (`fetch_object_info_via_pack`) and transport helpers (`fetch_object_info_helper`). The smart transport implementation handles protocol version discovery, stateless RPC, and connection cleanup.
- **Error handling**: The client dies if the server does not advertise the `object-info` capability, if the protocol version is not v2, or if the response format is malformed. Input validation includes bounds-checking for OIDs and attribute counts.

The patch is **mechanical and well-scoped**, with clear separation of concerns: `fetch-object-info.c` handles the protocol logic, while `transport.c` and `transport-helper.c` wire it into the existing transport infrastructure. The commit message is thorough, documenting design choices (e.g., buffering the request, the `unrecognized` field) and limitations (e.g., no streaming support). The code is type-safe (using `size_t` for object counts, `xcalloc` for allocations) and includes bounds-checking to prevent integer overflows.

This is the **last major functional patch** in the series before the `git cat-file --batch-command` integration (patch 12/13).
