This is a **substantive architectural proposal** in the ongoing ODB performance regression thread, authored by Patrick Steinhardt (the original ODB rework author). Patrick responds to Peff’s observation that the regression is fundamentally an **alternates performance issue**—not just a quarantine-specific problem—by outlining a **course correction** for the ODB abstraction: moving alternates handling from the ODB layer into the "files" backend itself. This would treat alternates as an implementation detail of the files backend rather than a cross-backend concern, enabling optimizations like pack-first-loose-second lookups across all alternates while simplifying other subsystems (commit-graph, bitmap, maintenance).

The proposal directly addresses the root cause of the regression (the ODB rework’s shift to "pack-loose, pack-loose" lookups across backends) and would eliminate redundant loose object checks in alternates-heavy scenarios (e.g., `clone -s`, `--reference`, large-scale hosting deployments). It also resolves several secondary issues: dropping the `OBJECT_INFO_SECOND_READ` flag, unifying commit-graph/bitmap loading, and cleaning up the object storage extension design. Patrick acknowledges that the change is feasible because submodules still require the `struct odb_source` list, and alternates aren’t strictly needed for write isolation (e.g., quarantine directories could use separate mechanisms).

Patrick plans to implement this in stages, starting with a patch series to remove `odb_prepare_alternates()` calls (already drafted but delayed until late July). The proposal is **highly credible**—it comes from the ODB rework’s original author, addresses Peff’s cross-process concerns, and aligns with Junio’s earlier suggestion to optimize alternates handling. However, the timeline (two weeks for initial patches) means a near-term fix for the regression may still be needed separately. The email advances the thread by shifting focus from a targeted lookup-order fix to a broader architectural cleanup, though it remains to be seen how this interacts with Peff’s critique of transaction-aware ODB writes. Key technical details: alternates, `struct odb_source`, `OBJECT_INFO_SECOND_READ`, commit-graph/bitmap loading, and the "files" backend.
