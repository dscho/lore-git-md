This is the second patch in Ted Nyman’s three-patch bugfix series (v4) targeting race conditions in Git’s HTTP transport. It directly addresses the core issue: concurrent appends to partial packfiles corrupting downloads when multiple Git processes fetch the same packfile URI or dumb HTTP pack into a single object database.

The patch replaces the previous append-mode (`O_APPEND`) file handling with a read-write (`O_RDWR`) approach that seeks to the current end of the file once, then retains the offset matching the requested HTTP `Range`. Because the staging path uniquely identifies immutable pack contents, overlapping responses write identical bytes at identical offsets, preventing corruption while preserving resumable downloads. On MinGW, the patch works around Windows sharing behavior by creating a missing partial pack exclusively, closing it, and reopening it without `O_CREAT` so every retained descriptor permits another downloader to unlink the staging path.

Test coverage is thorough: new regression tests in `t/t5550-http-fetch-dumb.sh` exercise resumed transfers, EOF ranges, overlapping 200/206 responses, and unlinking the staging path while `index-pack` holds its descriptor. A particularly robust overlapping-download test uses a custom Perl server with a 60-second timeout, FIFO waiter notification, and reliable server process cleanup to deterministically verify that concurrent downloads cannot corrupt the pack.

The patch touches `http.c`, `http-fetch.c`, `http-push.c`, `http-walker.c`, and `Documentation/git-http-fetch.adoc`, with no new symbols introduced. The implementation is narrowly scoped to the packfile URI and dumb HTTP download paths, leaving other HTTP fetch behaviors and on-disk formats unchanged. The series is uncontroversial, well-motivated, and ready for progression to `next` if the test suite passes cleanly.
