This is the first patch in Patrick Steinhardt’s five-part series making on-disk ODB structures pluggable, part of the ongoing ODB abstraction effort. It fixes a bug in the loose-object map loading logic: the function `load_one_loose_object_map()` was ignoring the passed-in ODB source and always loading the map from the common `objects/` directory instead of the source-specific path. The patch corrects this by using the loose source’s path to construct the map file location, ensuring each source loads its own map.

The change is confined to `loose.c` and is mechanical: it removes the redundant `repo` parameter from `load_one_loose_object_map()`, retrieves the repository from the source’s ODB, and replaces the `strbuf`-based path construction with a simpler `xstrfmt()` call. The fix is preparatory for the rest of the series, which will defer ODB directory creation until after the backend is known, removing hardcoded assumptions about directory layouts. No user-visible behavior changes or test updates are included in this patch.
