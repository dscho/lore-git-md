This is patch 9/13 of the GSoC v21 `git cat-file --batch-command` remote-object-info series, now technically complete and queued for `next`. The patch enforces consistent object-existence checks on the server side, regardless of whether attributes (like `size`) are requested.

The change extracts the existence check from `send_info()` into a new helper, `get_object_info()`, which wraps `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK` flags. This ensures a partial-clone server won’t fetch missing objects during an `object-info` request, and avoids unnecessary pack rescans. The patch also tightens the unrecognized-object check from `< 0` to `<= OBJ_NONE` to cover both `OBJ_BAD` and `OBJ_NONE` cases.

Behaviorally, bare OID requests now return `<OID>` for recognized objects and `<OID> SP` for unrecognized ones, regardless of requested attributes. The documentation in `gitprotocol-v2.adoc` is updated to reflect this: full OIDs are now required, `obj-size` is explicitly defined as numeric, and the response format for unrecognized OIDs is clarified. The test suite adds three new cases covering bare OID requests, unrecognized OIDs, and size requests for unrecognized OIDs, bringing the total coverage to 63 new lines in `t/t5701-git-serve.sh`.

This is a targeted protocol-level fix that resolves a prior inconsistency in how the server handled bare OID requests. The change is mechanical and well-tested, with no known regressions or open questions. It’s a prerequisite for the later `remote-object-info` command implementation (patch 12/13) and aligns with the series’ goal of robust, dynamic capability negotiation.
