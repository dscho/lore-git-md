This is the fourth patch in Harald Nordgren’s **v21 `git branch --delete-merged` series**, which is now implementation-complete and ready for merging. This patch prepares the `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that prevents falling back to `HEAD` when checking whether a branch is merged into its upstream.

The change is minimal and targeted: it modifies `delete_branches()` and `branch_merged()` to respect the new flag, ensuring that `--delete-merged` only deletes branches that are merged into their upstream (and not `HEAD` as a fallback). The flag is checked in two places: (1) to skip the `HEAD` fallback in `delete_branches()`, and (2) to suppress the "gentle reminder" about `HEAD` fallback in `branch_merged()` when the caller explicitly opts out. Existing callers (e.g., `git branch -d`) retain their current behavior, as the flag is only set by the new `--delete-merged` subcommand.

This patch is part of the **flags-based API refactoring** introduced in earlier patches (2-3/7) to replace boolean arguments with an `unsigned int flags` parameter. The refactoring is now complete, with all local boolean caching eliminated to ensure flags remain the single source of truth. The patch is **well-tested** in later patches that exercise the `--delete-merged` subcommand, and it introduces no behavioral changes for existing callers. The motivation is clear: the `--delete-merged` subcommand needs to enforce stricter merge checks than `git branch -d`, and this flag provides the necessary control.

The patch touches only `builtin/branch.c` and is a straightforward, low-risk change that aligns with the series’ goal of enabling safe automated branch cleanup. The series as a whole is **unblocked for merging**, with this patch addressing a key design requirement for the `--delete-merged` subcommand.
