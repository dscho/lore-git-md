This patch introduces the `--forked` filter for `git branch --list`, the foundational building block for the `--delete-merged` subcommand.

The `--forked` option lists only branches whose configured upstream matches a given ref, remote name, or shell-style glob. For example, `git branch --forked origin/main` shows branches tracking `origin/main`, while `git branch --forked 'origin/*'` matches all branches tracking any `origin/` branch. The filter is repeatable (e.g., `--forked origin/main --forked origin/next`) to widen the match, and composable with existing filters like `--merged` and `--no-merged`. The implementation resolves ref arguments to full refnames (e.g., `origin/main` → `refs/remotes/origin/main`) and supports remote shorthand (e.g., `origin` for `origin/HEAD`). A key edge case—branches that push to their upstream (e.g., `main` tracking `origin/main`)—is handled by protecting them from deletion, ensuring the filter correctly distinguishes true forks from long-lived branches.
