This is the fourth patch in Taylor Blau’s five-part bugfix series hardening Git’s packfile subsystem against duplicate object entries. The series aims to ensure that components like reverse indexes, delta resolution, and multi-pack indexes (MIDX) handle such packs correctly without breaking existing functionality.

This patch specifically addresses the bitmap writer, which currently assumes each object ID appears only once in a pack. When fed a pack containing duplicates, the internal `packlist_alloc()` function triggers a BUG() because its hash table permits only one entry per OID. The patch modifies the test helper (`test-bitmap.c`) to detect duplicate OIDs during pack ingestion and die gracefully with a clear error message instead of crashing. The change preserves the internal uniqueness check for other callers while making the test helper’s limitations explicit.

The patch also extends the existing test script `t5308-pack-detect-duplicates.sh` to verify that the bitmap writer rejects packs with duplicates, using the same test pack created earlier in the series. The test confirms the expected fatal diagnostic is produced.

This is a narrowly scoped, defensive change that aligns the bitmap test helper with the rest of the series’ goal of making duplicate-handling consistent and safe. It looks well-motivated and unlikely to be controversial. The patch is part of the broader effort to harden Git’s packfile internals without changing on-disk formats or promoting duplicates as a preferred storage mechanism.
