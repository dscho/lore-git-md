This is the second patch in Harald Nordgren’s **v22 `git branch --delete-merged` series**, which is now **unblocked and ready for merging**. This patch refactors `delete_branches()` and `check_branch_commit()` to replace separate `force` and `quiet` boolean parameters with a single `unsigned int flags` argument and an enum (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is purely mechanical and introduces no behavioral differences—flags are tested directly at each use site to prevent stale cached values, addressing a maintenance risk identified in earlier reviews.

The patch touches only `builtin/branch.c` and is part of a broader effort to modernize the branch-deletion API for the new `--delete-merged` subcommand. By eliminating local boolean caching (e.g., `int force = 1`), it ensures the flags remain the single source of truth throughout the call chain. This refactoring is a prerequisite for later patches (3/7 and 4/7) that add new flags (`DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`) to support `--delete-merged`’s requirements, such as suppressing the `HEAD` fallback and skipping unmerged branches silently.

The implementation is straightforward: the enum values are tested via bitwise operations (e.g., `flags & DELETE_BRANCH_FORCE`), and the existing logic is preserved verbatim. The patch is **low-risk** and **well-tested**, with no changes to the test suite—existing tests continue to pass, confirming the refactoring does not alter behavior. This aligns with the series’ goal of enabling safe, automated branch cleanup while maintaining backward compatibility for all current callers (e.g., `git branch -d/-D`).
