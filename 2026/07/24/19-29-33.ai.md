This is the **core implementation patch** of Harald Nordgren’s `git branch --delete-merged` series, now in its **final v22** and **ready for merging**. The patch adds the `--delete-merged` subcommand to `git branch`, enabling safe, automated cleanup of local branches whose work has already landed on their upstream. It is the **fifth of seven patches** in a series that has been **unblocked** after resolving all correctness and design concerns, including the **order dependency issue in stacked-branch protection** via a single-pass graph traversal.

The command deletes local branches merged into their upstream (matching one or more `--delete-merged` arguments) while preserving branches used as upstreams for unmerged work. It supports **repeatable upstream selectors** (e.g., `--delete-merged origin/main --delete-merged origin/next`) and **optional positional patterns** (e.g., `topic-*`) to limit deletion scope. Safety mechanisms include skipping checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`. The implementation is **order-independent**, ensuring consistent results regardless of ref iteration order, and **thoroughly tested** with comprehensive integration tests covering all edge cases.

Key technical details:
- **Stacked-branch protection**: The command fails to delete a branch if it is used as an upstream for an unmerged branch but clears the upstream config for kept (merged) branches whose own upstream is being deleted. This is implemented via `collect_stacked_branch_bases()`, a new helper that traverses upstream chains from each branch, marking all transitively required branches as "protected" before any deletions occur. The `visited_branch_names` strset avoids infinite loops in self-referential chains (e.g., `b3→b3`), and the `protected_branch_names` strset is indexed by **branch names** (e.g., `main`) rather than full refnames, aligning with `branch_get()` and `branch_get_upstream()` behavior.
- **Push divergence check**: The `branch_pushes_to_upstream()` helper determines whether pushing a branch by name would update its upstream, protecting branches like `main` tracking `origin/main` even when `remote.pushDefault` names a fork.
- **Candidate filtering**: The `--forked` filter machinery (introduced in patch 1/7) resolves upstream arguments to full refnames or shell-style globs, and `delete_merged_branches()` applies all safety checks (checked-out branches, missing upstreams, push divergence, merge status) before populating the `deletable_branch_names` strset.
- **Flags-based API**: The command uses the flags-based `delete_branches()` API (refactored in patches 2-4/7) with `DELETE_BRANCH_SKIP_UNMERGED` (to silently skip unmerged branches) and `DELETE_BRANCH_NO_HEAD_FALLBACK` (to avoid considering `HEAD` as a fallback).

The patch touches `builtin/branch.c` (adding ~150 lines for the core logic and helpers), `Documentation/git-branch.adoc` (documenting the new subcommand and its safety checks), and `t/t3200-branch.sh` (adding ~200 lines of integration tests). The tests verify:
- Order-independent stacked-branch protection (e.g., chains like `b1→b2→b3` and self-referential upstreams like `b3→b3`).
- Push divergence handling (e.g., `main` tracking `origin/main` is preserved).
- Missing upstream and checked-out branch protection.
- Repeatable `--delete-merged` arguments and positional patterns.
- Config cleanup for kept branches (e.g., clearing upstreams for branches whose own upstream is deleted).

The implementation is **well-motivated** (addressing a real workflow pain point for stacked-branch users), **API-consistent** (using the flags-based `delete_branches()` interface), and **low-risk** (no behavioral changes to existing `git branch` subcommands). The only follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which Harald Nordgren has agreed to implement after the series lands.
