This is a small but important refactoring patch in the ongoing `git cat-file --batch-command` remote-object-info series (now at v21). The patch fixes a signed/unsigned type mismatch in `fetch-pack.c`: `hash_algo_by_name()` returns an `unsigned int`, but the variable storing its result was declared as `int`. While this mismatch is currently masked by a `DISABLE_SIGN_COMPARE_WARNINGS` pragma, the function will soon be moved to `connect.c` (in a later patch in the same series), where the warning would become visible.

The change is mechanical and safe: the variable is updated to `const unsigned int` to match the return type of `hash_algo_by_name()`, and marked `const` because it is never modified. The patch touches only one line in `fetch-pack.c` and has no behavioral impact. It is a prerequisite for the upcoming function relocation and helps keep the codebase warning-free as the series progresses toward integration.

This is a well-motivated, low-risk cleanup that aligns with the series' broader goal of robust, maintainable remote object metadata queries. The fix is uncontroversial and unlikely to draw further discussion.
