This is a refactoring patch series that advances the **ODB (object database) abstraction** effort. Patrick Steinhardt is making the creation of on-disk data structures pluggable so that alternative backends can define their own directory layouts instead of being forced into Git’s traditional `objects/info` and `objects/pack` structure.

The series consists of five patches. The first two are preparatory: they fix a loose-object map loading issue and untangle the initialization sequence so that the ODB itself can be created later. The third patch defers ODB creation until after the backend is known. The fourth adds a helper to map ODB source types to human-readable names, and the fifth finally moves the on-disk directory creation into the backend’s hands. Thirteen files are touched, mostly in the `odb/` and `setup.c` areas.

This is clearly part of the long-running ODB abstraction work that Patrick has been driving. The commit messages are detailed and the code changes look mechanical but deliberate. No new user-visible behavior is introduced; the goal is infrastructure for future backends. If you care about pluggable storage or are reviewing the ODB series, this is worth following.
