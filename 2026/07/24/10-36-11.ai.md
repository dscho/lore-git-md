This is the first patch in Harald Nordgren’s **final, unblocked v21 series** introducing `git branch --delete-merged`, which adds the foundational `--forked` filter for `--list` mode. The patch implements a composable branch-listing filter that identifies branches whose upstream matches a given ref, remote shorthand, or shell glob (e.g., `--forked origin/main`, `--forked origin`, or `--forked 'origin/*'`). The filter can be repeated to widen the match and combines with existing filters like `--merged` and `--no-merged`.

The implementation touches `ref-filter.c` and `builtin/branch.c`, adding a new `ref_filter_forked_add()` API to register patterns, a `filter_forked_match()` helper to check each branch’s upstream against those patterns, and a `short_upstream_name()` utility to abbreviate refs for glob matching. The filter resolves remote shorthand (e.g., `origin`) to the branch pointed to by `origin/HEAD` and supports exact ref matching (full refname) or glob matching (abbreviated upstream name). Documentation updates to `git-branch.adoc` and a comprehensive test suite in `t/t3200-branch.sh` verify exact ref matching, glob expansion, remote shorthand resolution, composition with other filters, and error handling for invalid patterns.

This patch is **well-crafted and thoroughly tested**, with no known issues. It establishes the core filtering logic that the `--delete-merged` subcommand (patch 5/7) will use to identify deletable branches. The only prior feedback on this patch (from Phillip Wood) was surface-level and has been addressed: tests now avoid a detached HEAD edge case and are reordered for clarity. The `--forked` filter’s edge case—protecting branches if pushing them by name would update their upstream—was fixed in v19 and is now covered by tests. The patch is **ready for merging** as part of the series.
