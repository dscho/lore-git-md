This is the third and final patch in Ted Nyman’s v4 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI downloads. The patch addresses a subtle but important edge case: when `index-pack` encounters an existing `.keep` file, it reports `"pack<TAB><hash>"` instead of `"keep<TAB><hash>"`, causing `fetch-pack` to fail if it only expects the latter.

The fix is straightforward and well-motivated. `fetch-pack` now accepts both `"pack"` and `"keep"` prefixes from `http-fetch`, validates the reported pack hash against the advertised hash, and only registers a `.keep` lockfile if the current fetch created it (tracked via a new `created_keep` flag). The patch adopts Jeff King’s suggested `strbuf` refactor for clarity, replacing the fixed-size `packname` buffer with a more robust approach. A new regression test in `t/t5702-protocol-v2.sh` exercises the scenario by pre-creating a `.keep` file and verifying that the fetch succeeds without corrupting it.

The change is narrowly scoped to the packfile URI code path and has no impact on other fetch behaviors or on-disk formats. The commit message clearly explains the motivation and the test coverage is thorough. This patch, combined with the earlier ones in the series, completes a clean, minimal solution to a real-world race condition. If the test suite passes, the series is ready to progress to `next`.
