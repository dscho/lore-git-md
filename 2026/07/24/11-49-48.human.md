This is a CI/build system patch discussion, specifically a review of a fix for a Coccinelle static-analysis performance issue.

Jeff King (Peff) reviews the patch that avoids a pathological slowdown in Coccinelle 1.1.1 by moving loop index declarations into their respective `for` loops. He acknowledges the problem but questions whether the fix is the right approach. Peff notes that the slowdown is a known Coccinelle issue, already fixed in version 1.3.0, and suggests upgrading the CI job's Coccinelle version instead of working around the problem in the codebase. The CI job currently uses Ubuntu 22.04, which ships with an older Coccinelle version; upgrading to Ubuntu 25.10 would provide the fixed version.

Peff also observes that the patch itself improves code hygiene by avoiding reuse of the same loop index variable across unrelated loops, which could otherwise lead to shadowed variables. However, he points out a minor type inconsistency in the second loop: the patch declares `i` as `size_t` but the loop bounds (`candidates.nr`) are `int`, requiring an awkward cast. He suggests using `int` for consistency and to eliminate the cast.

The review is substantive, engaging with both the immediate fix and the broader CI infrastructure. It raises a valid question about whether the project should address the root cause (outdated tooling) rather than applying a workaround. The patch itself is narrowly scoped and well-motivated, but Peff's feedback suggests the discussion may shift toward CI tooling updates.
