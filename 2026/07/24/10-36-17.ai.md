This is the final patch in Harald Nordgren’s `git branch --delete-merged` series, adding `--dry-run` support to the new subcommand. The patch is **implementation-complete and ready for merging**, with no functional changes since v20.

The `--dry-run` flag prints one line per branch that would be deleted (e.g., "Would delete branch merged (was abc1234)") without modifying refs or branch configuration. It is only valid when used with `--delete-merged` and is rejected otherwise. The implementation reuses the existing `delete_branches()` infrastructure, adding a `DELETE_BRANCH_DRY_RUN` flag that suppresses ref/config deletion and prints "Would delete" messages instead. The output matches the real deletion output exactly, including the "was <commit>" suffix. The patch also rejects the nonsensical `--dry-run --quiet` combination, as agreed in prior discussion.

The patch updates `Documentation/git-branch.adoc` to document the new flag and adds three new tests in `t/t3200-branch.sh`: one verifies the output matches the real deletion message, another confirms stacked-branch protection is respected during dry runs, and the last rejects `--dry-run` without `--delete-merged`. The tests use the `check_branches` helper (introduced in patch 6/7) to verify branch state via `git for-each-ref`, ensuring the dry run does not modify the repository.

This patch is **low-risk and well-tested**, touching only `builtin/branch.c`, `Documentation/git-branch.adoc`, and the test suite. The implementation is consistent with Git’s existing `--dry-run` patterns (e.g., `git clean --dry-run`) and addresses the v18 issue where dry runs incorrectly modified config. The series is now **unblocked for merging**, with the only agreed follow-up work being the extension of stacked-branch protection to `git branch -d` for consistency. Key files: `builtin/branch.c` (adds `DELETE_BRANCH_DRY_RUN` flag), `Documentation/git-branch.adoc`, and `t/t3200-branch.sh`.
