This is the second patch in Taylor Blau’s five-part bugfix series hardening Git’s packfile subsystem against duplicate object entries. It specifically addresses delta cycle resolution: when a REF_DELTA chain forms a cycle, the code now searches duplicate representations of the same OID to find an acyclic path to a full object.

The implementation adds a depth-first search that treats each OID as a node and tries every entry in its .idx run. A bitmap prevents revisiting the same OID group, and OFS_DELTA bases are translated back to OIDs so the search can continue across duplicate copies. The recovery logic is confined to proven cycles; ordinary lookups continue to use the existing single-entry lookup for performance.

The patch extends t5309 with three new test cases: a root-level full duplicate, a mixed REF/OFS cycle, and a three-object cycle that requires backtracking before taking an alternate path to a full base. The fixtures are hash-independent, so the same tests run under both SHA-1 and SHA-256.

Code changes are localized to packfile.c (199 lines added) and t5309 (148 lines added). No new symbols are introduced; the delta-path machinery is internal to the unpack_entry and packed_to_object_type functions. The on-disk format remains unchanged.
