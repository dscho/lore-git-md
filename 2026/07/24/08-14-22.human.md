This is the v4 reroll of Ted Nyman's bugfix series addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The series is now three patches, with the first still a preliminary cleanup (documentation and error-message typo fixes) and the latter two implementing the core fix.

The v4 iteration makes no changes to the production code but tightens the test suite: it now matches HTTP 416 responses in trace output for both older and current libcurl versions, adds a timeout to the overlapping-download test server to prevent hangs, notifies FIFO waiters on server failures, and ensures the test server process is tracked for cleanup. The test order is also adjusted so an early downloader failure cannot leave the server waiting indefinitely. These adjustments address the test hang in `t5550-http-fetch-dumb.sh` that blocked v3 from progressing to `next`.

The core design remains unchanged: deterministic staging paths opened in read-write mode (not append) ensure overlapping responses write identical bytes at identical offsets, preserving resumable downloads for both packfile URIs and dumb HTTP without cross-process coordination. The MinGW-specific sharing behavior is still handled by creating missing staging files exclusively, closing them, and reopening without `O_CREAT` to allow unlinking. The `.keep` file race is resolved by having `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, validating the pack hash against the advertised hash, and only removing `.keep` files created by the current process.

The series is well-motivated, the implementation is clean, and the test coverage is thorough. The changes are narrowly scoped to the packfile URI download path and should be uncontroversial. With the test hang resolved, this version looks ready for `next`.
