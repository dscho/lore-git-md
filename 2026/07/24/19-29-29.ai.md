This is the first patch in Harald Nordgren’s **v22 `git branch --delete-merged` series**, which is now **implementation-complete, unblocked, and ready for merging**. This patch introduces the `--forked` filter for `git branch --list`, the foundational building block for the `--delete-merged` subcommand. The filter lists only branches whose configured upstream matches a given ref, remote name, or shell-style glob (e.g., `origin/main`, `origin`, `origin/*`), and can be repeated to widen the match (e.g., `--forked origin/main --forked origin/next`).

The implementation is **well-crafted and thoroughly tested**, with no known issues. It adds a new `ref_filter_forked_add()` function to resolve and register patterns, and a `filter_forked_match()` helper to check each branch’s upstream against the registered patterns. The filter supports exact ref matching (compared against full upstream refnames) and glob matching (compared against abbreviated upstream names), ensuring unambiguous results. It composes cleanly with existing filters (`--merged`, `--no-merged`) and handles edge cases like remote shorthand resolution (e.g., `origin` for `origin/HEAD`) and local branches tracking other local branches. The test suite covers exact ref matching, glob expansion, remote shorthand, composition with other filters, and error handling for invalid patterns.

This patch is **low-risk and self-contained**, touching only `ref-filter.c`, `builtin/branch.c`, and the test suite. It establishes the core filtering logic that the `--delete-merged` subcommand (patch 5/7) will use to identify deletable branches. The only follow-up work related to this patch is a **non-blocking future improvement** (simulating push/fetch refspecs to better distinguish true forks from long-lived branches), which Phillip Wood has confirmed is not required for merging. The series as a whole is ready for integration, with Junio C Hamano explicitly stating there are no outstanding issues.
