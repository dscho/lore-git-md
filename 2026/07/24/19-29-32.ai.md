This is the fourth patch in Harald Nordgren’s **v22 `git branch --delete-merged` series**, which is now **unblocked and ready for merging**. The patch prepares the `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that prevents falling back to `HEAD` when checking whether a branch is merged into its upstream.

The change is **minimal and targeted**: it modifies `delete_branches()` and its helper `branch_merged()` to respect the new flag, ensuring that `--delete-merged` (which will use this flag) only deletes branches merged into their upstream, without considering `HEAD` as a fallback. The flag is checked at both the commit-checking (`branch_merged()`) and deletion (`delete_branches()`) stages, suppressing the `HEAD` fallback and the "gentle reminder" message when the caller explicitly opts out. Existing callers (e.g., `git branch -d`) retain their current behavior, as the flag is only set by the new `--delete-merged` subcommand.

The patch is **well-motivated** and **low-risk**: it introduces no behavioral changes for current callers, and the new flag is only exercised by later patches in the series (specifically patch 5/7, which implements the `--delete-merged` subcommand). The commit message clearly explains the purpose of the flag and its interaction with the existing code. The change aligns with the series’ broader goal of providing safe, automated branch cleanup with precise control over deletion criteria.

This patch is part of the **flags-based API refactoring** (patches 2-4/7) that replaces boolean arguments with an `unsigned int flags` parameter, eliminating local boolean caching to ensure flags remain the single source of truth. The refactoring is **mechanical and well-tested**, with no known issues. The series as a whole is **implementation-complete**, with all safety mechanisms (per-branch opt-out, order-independent stacked-branch protection, `--dry-run` preview) and filtering capabilities (repeatable `--delete-merged` arguments, positional branch patterns) now in place.
