This is the core implementation patch of Harald Nordgren’s `git branch --delete-merged` series, now in its 21st iteration and ready for merging. The patch adds the `--delete-merged` subcommand to `git branch`, which safely deletes local branches whose work has already landed on their upstream, while preserving branches that are still needed (checked out, used as upstreams for unmerged work, or configured to opt out).

The command supports repeatable `--delete-merged` arguments to widen the upstream match (e.g., `--delete-merged origin/main --delete-merged origin/next`) and optional positional patterns (e.g., `topic-*`) to limit deletion scope. Safety checks include skipping checked-out branches, branches with missing upstreams, and branches that push to their upstream (e.g., `main` tracking `origin/main`). The stacked-branch protection logic—now order-independent via a single-pass graph traversal—ensures no branch is deleted out from under unmerged work, even in chains of dependencies (e.g., `b1→b2→b3`). The implementation is well-tested, with 200+ lines of new tests covering edge cases like self-referential upstreams, missing upstreams, and ref iteration order independence.

Key files touched: `builtin/branch.c` (core logic), `Documentation/git-branch.adoc` (user-facing docs), and `t/t3200-branch.sh` (integration tests). The patch builds on the flags-based API introduced in earlier patches (e.g., `DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`) and integrates with the `--forked` filter machinery from patch 1/7. The stacked-branch protection refactor (v20) resolved Junio C Hamano’s blocking correctness concern, and the series is now unblocked for merging. The only follow-up work is extending this protection to `git branch -d` for consistency, which will be implemented post-merge.
