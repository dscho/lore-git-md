This is the **v21 submission** of Harald Nordgren’s `git branch --delete-merged` series, which is now **implementation-complete and ready for merging**. The series introduces a safe, automated way to clean up local branches that have been merged upstream, with robust filtering and safety controls.

The only change in v21 is a **mechanical tweak to loop variables** to prevent CI timeouts, addressing a build issue without altering functionality. The core logic remains unchanged from v20, which resolved the last correctness issue (order dependency in stacked-branch protection) via a **single-pass graph traversal** that ensures consistent results regardless of ref iteration order. Junio C Hamano’s blocking concern is now fully addressed, and the series is unblocked.

Key features include:
- **`--delete-merged`**: Deletes local branches merged into their upstream (specified via repeatable arguments like `--delete-merged origin/main --delete-merged origin/next`), with optional positional patterns (e.g., `topic-*`) to limit scope.
- **Safety mechanisms**: Skips checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`.
- **Order-independent stacked-branch protection**: Fails to delete a branch if it’s used as an upstream for an unmerged branch, but clears stale upstream configs for kept (merged) branches. The v20 refactor ensures this logic is deterministic.
- **`--dry-run`**: Previews deletions without modifying refs or config, matching real output exactly.
- **Per-branch opt-out**: `branch.<name>.deleteMerged=false` exempts specific branches from automated cleanup while allowing explicit deletion via `git branch -d`.

The series is **well-tested**, with comprehensive integration tests covering edge cases (e.g., self-referential upstreams, missing upstreams) and all safety checks. The API is designed for extensibility, using a flags-based approach for `delete_branches()` to avoid boolean parameter proliferation. Documentation updates clarify the new options and config keys.
