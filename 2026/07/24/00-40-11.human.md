This is the final patch in a small feature series that adds scp-style URL support to `git config --url`. The series as a whole is a well-scoped scripting convenience: it brings `git config --url` into consistency with nearly every other Git command by teaching it to parse scp-style SSH URLs (e.g., `host:path`) alongside the existing explicit schemes (`ssh://`, `ftp://`, etc.).

This patch does the core work by switching `git config --url` to use Git’s shared `url_parse` function, which already handles scp-style syntax elsewhere in the codebase. The change is minimal—just one line in `builtin/config.c`—and the commit message explains the reasoning clearly: URL matching was previously used mostly for HTTP(S) transports, so this change has little internal effect beyond aligning behavior with other commands. The patch also updates the documentation to clarify that `--url` now supports all URL formats, including scp-style syntax, unlike the config-file URL syntax used in `http.<url>.*` options.

The test coverage added in this patch is thorough, with 44 new lines in `t/t1300-config.sh` that mirror the existing `--get-urlmatch` tests. These verify that scp-style URLs work correctly for both `--get-urlmatch` and the deprecated `--url` option, and that edge cases (like missing sections or malformed URLs) produce the expected errors. The patch looks clean, the rationale is sound, and the implementation is straightforward—this should be uncontroversial and ready for merging once the series has been reviewed.
