This is the **v22 submission of Harald Nordgren’s `git branch --delete-merged` series**, now **implementation-complete, unblocked, and ready for merging**. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including **order-independent stacked-branch protection**, per-branch opt-out, `--dry-run` preview, and repeatable upstream selectors.

The **only change in v22** is a mechanical adjustment to loop variables (`int i` instead of `size_t i` or `size_t i = 0`) to avoid typecasts and prevent CI timeouts, with **no functional impact**. This version is **identical to v21 in behavior and design**, which resolved the last correctness issue (order dependency in stacked-branch protection) via a **single-pass graph traversal** that collects all protected branches before mutating the deletion set. Junio C Hamano has explicitly confirmed there are no outstanding issues, signaling the series is ready for merging.

The core command, `--delete-merged`, deletes local branches merged into their upstream (matching one or more `--delete-merged` arguments) while preserving branches used as upstreams for unmerged branches. It supports **repeatable upstream selectors** (e.g., `--delete-merged origin/main --delete-merged origin/next`) and **optional positional patterns** (e.g., `topic-*`) to limit deletion scope. Safety mechanisms include skipping checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`. The `--dry-run` flag prints "Would delete" or "Would skip" messages without modifying refs or config, and rejects the nonsensical `--dry-run --quiet` combination.

The series touches `builtin/branch.c`, `ref-filter.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.txt`, and `t/t3200-branch.sh`. Patches 2-4/7 introduce a flags-based API for `delete_branches()` (e.g., `DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`), while patches 5-7/7 implement the core command, per-branch opt-out, and `--dry-run` support. The implementation is **well-motivated** (addressing a real workflow pain point), **thoroughly tested** (with comprehensive integration tests covering all safety checks and edge cases), and **aligned with Git’s API consistency expectations**. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.

Key technical details include:
- **Order-independent stacked-branch protection**: A single-pass graph traversal (`collect_stacked_branch_bases()`) ensures consistent results regardless of ref iteration order. The command fails to delete a branch if it is used as an upstream for an unmerged branch but clears the upstream config for kept (merged) branches whose own upstream is being deleted.
- **Per-branch opt-out**: The `branch.<name>.deleteMerged=false` config key exempts specific branches from automated cleanup while allowing explicit deletion via `git branch -d`.
- **`--forked` filter**: The foundation for `--delete-merged`, supporting exact refnames, remote shorthand, and shell-style globs. Branches are protected if pushing them by name would update their upstream, regardless of `remote.pushDefault` configuration.
- **Flags-based API**: Patches 2-4/7 refactor `delete_branches()` to use `unsigned int flags` instead of boolean arguments, eliminating local caching to ensure flags remain the single source of truth. The `DELETE_BRANCH_NO_HEAD_FALLBACK` flag ensures `--delete-merged` only deletes branches merged into their upstream, without considering `HEAD` as a fallback.
