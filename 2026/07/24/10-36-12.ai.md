This is the second patch in Harald Nordgren’s **`git branch --delete-merged`** series (7/7 total). It refactors the `delete_branches()` and `check_branch_commit()` functions in `builtin/branch.c` to replace separate boolean parameters (`force`, `quiet`) with a unified `unsigned int flags` argument and an enum (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is purely mechanical and introduces no behavioral differences—all flag tests are performed directly at use sites to prevent stale cached values, addressing a maintenance risk identified in earlier reviews.

The patch is part of the series’ broader effort to modernize the branch-deletion API ahead of adding new features (e.g., `DELETE_BRANCH_SKIP_UNMERGED` in patch 3/7). The flags-based approach is well-aligned with Git’s existing patterns (e.g., `REF_*` flags) and prepares the codebase for the `--delete-merged` subcommand’s more complex requirements. Phillip Wood’s earlier review confirmed this refactoring resolves the "two sources of truth" issue (local boolean caching vs. flags), and the implementation now ensures flags remain the single source of truth throughout the call chain.

Key changes are confined to `builtin/branch.c` and include:
- Replacing `force`/`quiet` parameters with `flags` in both functions.
- Testing `DELETE_BRANCH_FORCE` and `DELETE_BRANCH_QUIET` directly from `flags` at each use site (e.g., `if (!(flags & DELETE_BRANCH_FORCE))`).
- Updating the `cmd_branch()` caller to pass flags via bitwise OR (e.g., `(delete > 1 ? DELETE_BRANCH_FORCE : 0) | (quiet ? DELETE_BRANCH_QUIET : 0)`).

The patch is **low-risk** and **well-tested**—it introduces no new functionality but lays critical groundwork for the series’ later patches.
