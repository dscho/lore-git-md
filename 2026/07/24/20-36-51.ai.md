This is a bugfix patch for submodule handling, now queued for merging. Junio C Hamano has queued the v2 patch that fixes a regression in `git submodule update --remote` when URL aliases (`url.<base>.insteadOf`) are used. The regression, introduced in commit ca62f524c1 (2025), caused submodules with aliased URLs to fail to match their remotes because `.gitmodules` stores the unexpanded alias (e.g., `local:path`) while the submodule’s remotes report the resolved URL (e.g., `/full/path`).

The v2 patch addresses Junio’s feedback on the initial version by improving the commit message clarity, removing a redundant variable (`url_to_match`), and streamlining the test. The core logic in `repo_remote_from_url()` (in `remote.c`) now resolves aliases via `alias_url()` before comparing URLs, ensuring the correct remote is selected. The test in `t/t7406-submodule-update.sh` verifies the fix with a global `insteadOf` alias, submodule setup, and remote renaming.
