This is the sixth patch in Harald Nordgren’s **final, ready-to-merge v21 series** for `git branch --delete-merged`. It adds a per-branch opt-out mechanism via the `branch.<name>.deleteMerged=false` config key, allowing users to exempt specific topic branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The implementation is straightforward and well-tested. The config key is checked during candidate filtering in `delete_merged_branches()`; if set to `false`, the branch is skipped with a non-quiet message explaining the opt-out. The opt-out is ignored by traditional `git branch -d`, which continues to use the normal merge check. Documentation is added to both `branch.adoc` and `git-branch.adoc`, and the test suite verifies opt-out behavior, skip messages, and explicit deletion. Phillip Wood’s earlier review suggested a mechanical test improvement (using `git for-each-ref` via the `check_branches` helper), which has been applied.

This patch is a **clean, low-risk addition** that addresses a real workflow need: iterative topic branches that receive early upstream merges but remain active. The design is consistent with Git’s existing config patterns, and the implementation avoids touching any core deletion logic beyond the opt-out check. The series as a whole is now **unblocked for merging**, with this patch completing the safety architecture alongside stacked-branch protection and `--dry-run` preview. The only agreed follow-up is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.
