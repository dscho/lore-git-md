This is the first patch in Harald Nordgren’s v21 `git branch --delete-merged` series, which is now implementation-complete and ready for merging. This patch introduces the `--forked` filter for `git branch --list`, a foundational building block for the series’ core functionality.

The `--forked` option filters the branch list to show only branches whose configured upstream matches a given pattern. The argument can be a full refname (e.g., `origin/main`), a remote shorthand (e.g., `origin` for `origin/HEAD`), or a shell-style glob (e.g., `origin/*`). Multiple `--forked` arguments can be combined to widen the filter, and the option composes naturally with existing filters like `--merged` and `--no-merged`. For example, `git branch --merged origin/main --forked 'origin/*'` lists branches forked from `origin` that are already merged into `origin/main`.

The implementation adds a new `forked` field to the `ref_filter` struct and introduces two key functions: `ref_filter_forked_add()` resolves ref arguments to full refnames or accepts globs, and `filter_forked_match()` checks each branch’s upstream against the registered patterns. The patch includes thorough test coverage, verifying exact ref matching, glob expansion, remote shorthand resolution, composition with other filters, and error handling for invalid patterns. The tests also cover edge cases like local branches tracking other local branches.

This patch is well-motivated and clearly documented, with updates to `git-branch.adoc` explaining the new option’s behavior and examples. The implementation is clean and aligns with Git’s existing filter infrastructure.
