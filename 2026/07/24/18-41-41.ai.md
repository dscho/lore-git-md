This is a substantive review by Junio C Hamano of the second patch in Patrick Steinhardt’s ODB abstraction series. The patch refactors loose object map loading to remove hard-coded assumptions about the ODB backend, and Junio’s feedback focuses on two technical points.

First, he asks for clarification on the phrase “extract its loose backend,” suggesting it could be reworded for precision—likely meaning whether the code is extracting the object map from the loose backend or something else. This is a surface-level nit, but it affects the commit message’s clarity.

Second, and more substantively, he questions the safety of the downcast in the loop that iterates over ODB sources. The current code assumes every source is a `files` backend and downcasts unconditionally; Junio asks whether the downcast macro would return `NULL` for non-files sources, allowing the loop to skip them safely. He then floats a more forward-looking design: defining a generic `load object map` method in the `odb_source` interface, which would eliminate the need for downcasting entirely and make the loop backend-agnostic. This is a deeper architectural suggestion that aligns with the series’ goal of pluggable ODB backends but would require additional refactoring beyond this patch.

The review is concise and technical, engaging directly with the code’s design rather than its surface details. It does not raise correctness concerns but does identify a potential robustness issue (the unconditional downcast) and suggests a cleaner long-term direction. No test results or build feedback are reported; this is purely a design-level review.
