Thread identity: patch series titled "harden packfile subsystem against duplicate object entries", v1, authored by Taylor Blau. Thread type: bugfix series.

Core problem or goal: make Git's packfile subsystem consistently handle packs containing duplicate object entries (which Junio C Hamano clarifies are **invalid**, not merely unusual) by ensuring early detection and rejection before such packs can propagate or cause downstream issues. The series ensures that components like reverse indexes, delta resolution, MIDX verification, bitmap generation, and multi-pack reuse correctly process or reject duplicate-containing packs while preserving `index-pack`'s duplicate policy and existing functionality for valid packs.

Current status: series under initial review (v1 posted). Junio C Hamano has acknowledged the direction with an implicit Ack for the overall goal, emphasizing the importance of early detection of invalid packs. No merge status reported; series remains under review.

Key technical details:
- Files/subsystems: `packfile.c` (delta resolution logic), `pack-bitmap.c`, `midx.c` (MIDX verification logic adjusted in patch 3), `builtin/pack-objects.c` (MIDX reuse logic in patch 5), `t/helper/test-bitmap.c` (new guard added in patch 4), test files `t5308-pack-detect-duplicates.sh` (new test added in patch 1, extended in patches 3 and 4), `t5332-multi-pack-reuse.sh` (extended in patch 5), `t5309-pack-delta-cycles.sh` (extended in patch 2).
- New/renamed symbols: new helper `pack_index_has_oid_at_offset()` in `midx.c` (patch 3) scans duplicate OID blocks in pack indexes to validate MIDX-recorded offsets.
- Behavior changes:
  - Reverse indexes now correctly retain duplicates (validated in patch 1).
  - Delta resolution falls back to duplicate entries to break cycles (patch 2 implements depth-first search across duplicate OID entries, using a bitmap to prevent revisiting the same OID group; OFS_DELTA bases are translated back to OIDs to continue the search).
  - MIDX verification (patch 3) now accepts any duplicate copy of an object by scanning the contiguous block of duplicate OIDs in the source pack index, rather than comparing against the single offset returned by `find_pack_entry_one()`. This matches reader behavior where `midx_to_pack_pos()` reconstructs the RIDX position from the recorded (pack, offset) pair and falls back to normal packing if the offset differs from the MIDX writer's selection.
  - Bitmap test helper (patch 4) explicitly rejects packs with duplicates via a three-line guard in `t/helper/test-bitmap.c` that checks for duplicate OIDs before calling `packlist_alloc()`, preventing a BUG() crash in the bitmap writer’s internal hash table. The existing `t5308-pack-detect-duplicates.sh` test is extended with a single new case verifying the fatal diagnostic.
  - Multi-pack reuse (patch 5) disables verbatim reuse and whole-word selection when the MIDX pseudo-pack’s one-bit-per-OID mapping misaligns with the physical pack’s entry order (e.g., pack ordered [A, B, A, C] has four physical positions but only three MIDX positions). The patch reads the selected count from the MIDX’s BTMP chunk (if present) rather than the pack’s `num_objects`, and skips preferred-pack reuse entirely when BTMP is absent, falling back to the ordinary packing path. This prevents overcounting and incorrect object emission.
- On-disk format: no changes; the series addresses in-memory handling and verification logic.
- Test coverage:
  - Patch 1 adds `t5308-pack-detect-duplicates.sh` to verify reverse-index behavior with duplicates (objects A, B, A, C sequence), covering both on-disk and in-memory reverse-index backends.
  - Patch 2 extends `t5309-pack-delta-cycles.sh` with three new test cases: a root-level full duplicate, a mixed REF/OFS cycle, and a three-object cycle requiring backtracking to find an alternate path to a full base. Fixtures are hash-independent (SHA-1 and SHA-256 compatible).
  - Patch 3 extends `t5308-pack-detect-duplicates.sh` to test MIDX verification over duplicate packs, confirming the MIDX-selected offset differs from `find_pack_entry_one()`'s choice and verifying `git fsck` acceptance. The `test-find-pack` helper is extended with a `--show-offset` flag to expose the offset chosen by `find_pack_entry_one()` for testing.
  - Patch 4 extends `t5308-pack-detect-duplicates.sh` with a new test case verifying the bitmap helper’s fatal diagnostic on duplicate packs.
  - Patch 5 extends `t5332-multi-pack-reuse.sh` with two new test cases: one verifying reuse works correctly with intra-pack duplicates when BTMP is present and is skipped when BTMP is absent, and another ensuring deltas whose bases are omitted from the MIDX-selected range are handled by normal packing rather than being incorrectly reused.

Open questions and loose ends:
- Performance impact of delta cycle fallback (patch 2) remains a potential discussion point, particularly the overhead of depth-first search in large packs with many duplicates.
- Whether MIDX verification changes (patch 3) and MIDX bitmap reuse changes (patch 5) sufficiently address all duplicate-related edge cases (e.g., cross-pack duplicates, interactions with other MIDX features like bitmaps).
