This is the third patch in Harald Nordgren’s seven-part `git branch --delete-merged` series, which is now implementation-complete and ready for merging. The patch introduces a new flag, `DELETE_BRANCH_SKIP_UNMERGED`, to the branch deletion API, enabling bulk callers (like the upcoming `--delete-merged` subcommand) to silently skip unmerged branches instead of aborting with an error. This is a purely mechanical refactoring that preserves existing behavior for all current callers while preparing the API for the new `--delete-merged` functionality.

The change modifies `check_branch_commit()` and `delete_branches()` in `builtin/branch.c` to check the new flag. When `DELETE_BRANCH_SKIP_UNMERGED` is set, the functions suppress the "not fully merged" error and advice, returning success for unmerged branches instead of failing. This allows the `--delete-merged` subcommand (introduced in patch 5/7) to process only merged branches without aborting on unmerged ones. The patch is low-risk: it adds a single flag and a conditional check, with no behavioral changes for existing callers.

The motivation is clear: the `--delete-merged` subcommand needs to handle unmerged branches gracefully, and the existing API’s error-on-unmerged behavior is inappropriate for bulk operations. The implementation is straightforward and aligns with the series’ broader goal of providing safe, automated branch cleanup. The patch is well-tested as part of the series’ comprehensive integration tests, which verify that the new flag works as intended in the context of the `--delete-merged` subcommand.
