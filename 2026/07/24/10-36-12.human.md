This is the second patch in Harald Nordgren’s seven-part series introducing `git branch --delete-merged`. It refactors the existing `delete_branches()` function to use a flags-based API instead of separate boolean arguments (`force` and `quiet`). The change is purely mechanical and introduces no behavior differences, but it lays the groundwork for the new flags (`DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`, and `DELETE_BRANCH_DRY_RUN`) that later patches will add.

The patch replaces the `force` and `quiet` parameters with an `unsigned int flags` argument and defines two enum values (`DELETE_BRANCH_FORCE` and `DELETE_BRANCH_QUIET`). At each use site, the code now tests the flags directly rather than relying on cached boolean values, eliminating a potential maintenance risk where forwarded or mutated flags could become stale. The conversion is straightforward and well-explained in the commit message, and the diff is clean, touching only `builtin/branch.c`.

This is a refactoring patch that is clearly motivated by the needs of the larger series. The flags-based API will make it easier to add new deletion behaviors (like skipping unmerged branches or supporting `--dry-run`) without cluttering the function signature. The patch is uncontroversial and appears ready for merging as part of the series.
