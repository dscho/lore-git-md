This is the third patch in Patrick Steinhardt’s five-part series making Git’s on-disk object database (ODB) structures pluggable. It is pure refactoring that prepares the repository-initialization code for the upcoming backend-specific directory creation.

The patch defers the creation of the object database until after the ref database is set up. Today, `apply_repository_format()` immediately calls `odb_new()`, which in turn creates the `objects/pack/` and `objects/info/` directories. In the next patch these directories will be created by the backend itself, so the ODB must not be instantiated until the backend is known. To achieve this, the patch splits the work into two steps: `apply_repository_format()` now skips ODB creation when the new `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag is passed, and the actual ODB creation is moved into a new helper, `create_object_database()`, which is called later in `init_db()`. The patch also extracts a small helper, `get_object_directories()`, to avoid duplicating the environment-variable lookup.

The diff touches only `setup.c` and `setup.h`; it adds the new flag and shuffles about 30 lines of code. There are no user-visible changes, no new tests, and no on-disk format modifications. The change is mechanical and looks well-contained, but it is a prerequisite for the next patch, which will introduce the pluggable directory-creation mechanism.
