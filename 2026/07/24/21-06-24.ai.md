This is the fifth and final patch in Taylor Blau’s five-part bugfix series hardening Git’s packfile subsystem against duplicate object entries. The patch addresses a subtle but critical issue in multi-pack index (MIDX) bitmap reuse: when a preferred pack contains duplicate objects, the MIDX pseudo-pack’s one-bit-per-OID mapping no longer aligns with the physical pack’s entry order, breaking both verbatim reuse and delta base validation.

The core problem is that a pack ordered [A, B, A, C] assigns four physical positions but only three MIDX positions (since the MIDX retains only one copy of A). This mismatch causes two distinct failures: (1) the bitmap count (`bitmap_nr`) overcounts by including both copies of A, and (2) MIDX positions no longer correspond to physical pack positions, so verbatim reuse or whole-word selection can emit the wrong objects or duplicate entries. The patch resolves these by reading the selected count from the MIDX’s BTMP chunk (if present) rather than the pack’s `num_objects`, and by disabling verbatim reuse and whole-word selection whenever the bitmap and physical counts differ. When BTMP is absent, the patch skips preferred-pack reuse entirely, falling back to the ordinary packing path rather than scanning the entire pseudo-pack for an optional optimization.

The implementation touches three files: `builtin/pack-objects.c` (disabling verbatim reuse and translating MIDX positions to physical pack positions), `pack-bitmap.c` (reading the selected count from BTMP and skipping reuse when BTMP is missing), and `t/t5332-multi-pack-reuse.sh` (adding two new test cases). The first test verifies that reuse works correctly with intra-pack duplicates when BTMP is present and is skipped when BTMP is absent; the second ensures that a delta whose base is omitted from the MIDX-selected range is handled by normal packing rather than being incorrectly reused. The changes are narrowly scoped to the MIDX reuse path and leave classic single-pack bitmap handling unchanged, as those bitmaps are only created for packs with one entry per OID.

This patch directly addresses the last open edge case in the series: MIDX bitmap interactions with duplicate objects. The solution is conservative, prioritizing correctness over performance by disabling reuse when BTMP is missing, and the test coverage appears thorough, exercising both the happy path and the fallback behavior. The patch is likely to be uncontroversial once reviewed, as it preserves existing invariants and only disables an optional optimization when necessary.
