Subject: [PATCH 0/5] odb: make on-disk ODB structures pluggable
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (infrastructure, part of ODB abstraction effort)

Core problem or goal
Decouple the creation of backend-specific on-disk object database (ODB) structures (e.g., `objects/info`, `objects/pack`) from the generic repository setup code. The top-level `objects/` directory remains mandatory for repository recognition, but individual backends now handle their own subdirectory creation via a new `create_on_disk` callback in the ODB source interface. This enables future ODB backends to implement custom on-disk layouts without modifying core setup logic. The first two patches fix latent bugs in loose-object map loading: the first ensures the map is loaded from the correct ODB source path (not always the common `objects/` directory), and the second removes hard-coded assumptions that the primary ODB is always the "files" backend and that the ODB must be initialized before the repository’s compatibility hash algorithm is set.

Key technical details
- Files touched: `loose.c`, `loose.h`, `odb/source-loose.c`, `odb/source-files.c`, `odb/source*.h`, `setup.c`, `setup.h`, `repository.c`.
- New or renamed symbols: `loose_object_map_load()` (public function), backend-specific directory creation helpers, ODB source type mapping functions (`odb_source_type_to_name()`), `get_object_directories()`, `create_object_database()` (renamed from `create_object_directory()`), `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag, `create_on_disk` callback in the ODB source interface.
- Behavior change: ODB creation is deferred until after the ref database is set up; hardcoded assumptions about directory layouts and initialization order are removed. Loose-object maps are now loaded from source-specific paths, and initialization steps in `apply_repository_format()` are reordered. The repository can now be left in a partially-initialized state (ref database created, ODB not yet created) via the new flag. The fourth patch adds a helper function to map ODB source types to human-readable strings for improved error messages in downcasting macros. The final patch moves the creation of backend-specific directories (`objects/pack`, `objects/info`) from the generic `create_object_database()` function into the "files" backend’s `create_on_disk` callback.
- On-disk format: no changes to existing repositories; this is purely internal refactoring.
