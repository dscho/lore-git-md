This is the v21 submission of Harald Nordgren’s `git branch --delete-merged` series, now **implementation-complete and ready for merging**. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including per-branch opt-out, `--dry-run` preview, and **order-independent stacked-branch protection**.

The only change in v21 is a mechanical adjustment to loop variables (`size_t i` instead of `size_t i = 0`) to prevent a CI timeout, with no functional impact. The v20 refactor resolved the last correctness issue (order dependency in stacked-branch protection) via a **single-pass graph traversal** that collects all protected branches before mutating the deletion set, addressing Junio C Hamano’s blocking concern. The series is now **unblocked for merging** with no known issues.

Key technical details remain unchanged from v20:
- **Core behavior**: Deletes local branches merged into their upstream (matching `--delete-merged` arguments) while preserving branches used as upstreams for unmerged branches. Supports glob patterns for both upstreams and local branches.
- **Safety mechanisms**: Skips checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`.
- **Stacked-branch protection**: Fails to delete a branch if it is used as an upstream for an unmerged branch, but clears the upstream config for kept (merged) branches whose own upstream is being deleted. The new implementation ensures this logic is **order-independent** by collecting all protected branches before mutating the deletion set.
- **`--dry-run`**: Prints "Would delete branch <name>" for each affected branch without modifying refs or config. Rejects the nonsensical `--dry-run --quiet` combination.
- **Test coverage**: Comprehensive integration tests verify all safety checks, edge cases (e.g., self-referential upstreams, missing upstreams), and the new order-independent stacked-branch protection behavior.

The series touches `builtin/branch.c`, `ref-filter.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.txt`, and `t/t3200-branch.sh`. Patches 2-4/7 introduce a flags-based API for `delete_branches()` (e.g., `DELETE_BRANCH_SKIP_UNMERGED`), while patches 5-7/7 implement the core `--delete-merged` command, per-branch opt-out, and `--dry-run` support. The implementation is **well-motivated** (addressing a real workflow pain point) and **thoroughly tested**, with clear documentation and a design aligned with Git’s API consistency expectations. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.
