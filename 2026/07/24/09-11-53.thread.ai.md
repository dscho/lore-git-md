Thread identity: patch series (single patch), originating author tnyman@openai.com, thread type: build system / CI fix addressing a Coccinelle 1.1.1 performance regression in `builtin/branch.c` caused by the `separate_loop_index` rule in `tools/coccinelle/strvec.cocci`.

Core problem or goal: resolve a pathological performance regression in Coccinelle 1.1.1 static analysis triggered by reusing a single loop index variable declared at function scope across two separate loops in `delete_merged_branches()`. The regression causes the static-analysis job on the `seen` integration branch to hit its six-hour timeout. The patch provides a narrowly scoped, mechanical workaround: declare each loop index in its respective `for` loop instead of sharing one declared at function scope, avoiding the expensive Coccinelle rule while preserving the function's behavior. The discussion has fully resolved into a two-phase plan: (1) apply the immediate, low-risk fix for the loop index type mismatch (`size_t` → `int` to match `candidates.nr`), and (2) defer the broader question of standardizing all ref-counting types to `size_t` (or a custom signed equivalent) for a future, quieter discussion. The root-cause question (upgrading the CI toolchain to Coccinelle 1.3.0+) remains unresolved but is now orthogonal to the immediate action.

Current status: **merged to `master`** as a pragmatic workaround for the Coccinelle 1.1.1 performance regression.
