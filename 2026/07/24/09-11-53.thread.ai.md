Thread identity: patch series (single patch), originating author tnyman@openai.com, thread type: build system / CI fix addressing a Coccinelle 1.1.1 performance regression in `builtin/branch.c` caused by the `separate_loop_index` rule in `tools/coccinelle/strvec.cocci`.

Core problem or goal: resolve a pathological performance regression in Coccinelle 1.1.1 static analysis triggered by reusing a single loop index variable declared at function scope across two separate loops in `delete_merged_branches()`. The regression causes the static-analysis job on the `seen` integration branch to hit its six-hour timeout. The patch provides a narrowly scoped, mechanical workaround: declare each loop index in its respective `for` loop instead of sharing one declared at function scope, avoiding the expensive Coccinelle rule while preserving the function's behavior. The broader discussion now centers on whether to address the root cause (upgrading the CI toolchain to Coccinelle 1.3.0+) or continue working around toolchain limitations in the codebase. A secondary question about type consistency in ref-counting loops has been resolved in favor of an immediate, low-risk fix for the loop index type mismatch, with broader ref-counting standardization deferred.

Current status: **merged to `master`** as a pragmatic workaround for the Coccinelle 1.1.1 performance regression. Junio C Hamano incorporated the patch into Harald Nordgren's `hn/branch-delete-merged` topic, confirming it as a stylistic improvement that reduces the Coccinelle check from a six-hour timeout to 0.06 seconds, with the full `coccicheck` run completing in 47 seconds. All 190 tests in `t3200-branch.sh` pass. The discussion remains open on the CI toolchain upgrade question, but the type consistency issue has been resolved: a follow-up patch correcting the second loop index type (`size_t` → `int` to match `candidates.nr`) is now the immediate next step, while the broader question of standardizing all ref-counting to `size_t` by updating `struct ref_array` in `ref-filter.h` is deferred for future discussion.
