Thread identity: patch series (single patch), originating author tnyman@openai.com, thread type: build system / CI fix addressing a Coccinelle 1.1.1 performance regression in `builtin/branch.c` caused by the `separate_loop_index` rule in `tools/coccinelle/strvec.cocci`.

Core problem or goal: resolve a pathological performance regression in Coccinelle 1.1.1 static analysis triggered by reusing a single loop index variable declared at function scope across two separate loops in `delete_merged_branches()`. The regression causes the static-analysis job on the `seen` integration branch to hit its six-hour timeout. The patch provides a narrowly scoped, mechanical workaround: declare each loop index in its respective `for` loop instead of sharing one declared at function scope, avoiding the expensive Coccinelle rule while preserving the function's behavior.

Current status: **merged to `master`**. Junio C Hamano accepted the patch as a pragmatic workaround for the Coccinelle 1.1.1 performance regression, incorporating it into Harald Nordgren's `hn/branch-delete-merged` topic. The patch is a stylistic improvement that reduces the Coccinelle check from a six-hour timeout to 0.06 seconds, with the full `coccicheck` run completing in 47 seconds. All 190 tests in `t3200-branch.sh` pass. The discussion remains open on whether the project should upgrade the CI toolchain to Coccinelle 1.3.0+ (which includes a fix for the exponential slowdown) or continue working around such issues in the codebase, but no further changes are required for this patch.
