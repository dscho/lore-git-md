This thread is about Patrick Steinhardt’s five-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of a larger effort to abstract the ODB layer. The goal is to decouple backend-specific directory creation (like `objects/pack` or `objects/info`) from the core repository setup code, allowing future ODB backends to define their own layouts without modifying Git’s internals. The series also fixes two latent bugs in loose-object map loading, ensuring maps are read from the correct ODB source path and removing hardcoded assumptions about the "files" backend.

The patches are under active review, with Junio C Hamano and Justin Tobler providing feedback. Junio’s review was thorough, approving some patches outright (with minor nits) but raising substantive design concerns on others. The second patch, which refactors loose-object map loading, drew particular scrutiny: Junio questioned the robustness of its unconditional downcasting and suggested a more backend-agnostic approach, while Justin Tobler probed whether the lazy-loading design could lead to inconsistencies in multi-backend setups. The fifth patch also sparked discussion about the `create_on_disk` callback’s naming and extensibility for non-filesystem backends. No merge decisions have been made yet, and the series remains in the review phase.

Key technical changes include deferring ODB creation until after the ref database is set up, introducing a `create_on_disk` callback for backend-specific directory creation, and fixing a bug where loose-object maps were loaded from the wrong path in repositories with alternates and compatibility hash algorithms. The series touches core files like `loose.c`, `setup.c`, and `repository.c`, and introduces new symbols like `loose_object_map_load()` and `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION`. While the patches don’t change the on-disk format, they lay groundwork for future ODB backends. Open questions center on design robustness, callback naming, and commit message clarity—issues that may require a v2 to address.
