This thread is about Patrick Steinhardt’s six-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of the broader ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack/`) from core repository setup, enabling future backends with custom layouts. The first patch—a correctness fix for loose-object map loading in multi-backend setups—is slated to merge to `next` soon, thanks to a dedicated test case from Toon Claes. The rest of the series is uncontroversial but blocked on a revised fourth patch, where Patrick has conceded to Toon’s alternative design: removing a flag-based initialization refactor in favor of explicit ODB creation at every call site.

The latest update is a minor cleanup to the third patch, where Patrick acknowledges a redundant `xstrdup_or_null()` call for `o->alternate_db` (spotted by Toon) and will remove it in the next version. This doesn’t affect functionality but tidies up the code. The series remains split: the first patch is a standalone fix, while the others await the revised initialization logic. Key participants—Junio, Justin Tobler, and Toon Claes—have all weighed in, with Toon’s design input now shaping the final approach. The only open questions are forward-looking (e.g., callback naming for non-filesystem backends), but none block progress.
