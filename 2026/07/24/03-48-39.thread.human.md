This thread is about Patrick Steinhardt’s five-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of a larger effort to abstract the ODB layer. The series decouples backend-specific directory creation (like `objects/pack`) from core repository setup, allowing future ODB backends to define their own layouts. The first two patches fix latent bugs in loose-object map loading, including a correctness issue where maps were loaded from the wrong path in repositories with compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility) and alternates. Patrick incorporated a test case from Toon Claes to verify the fix, elevating the first patch’s importance to a regression fix.

The series is under active review, with substantive feedback from Junio C Hamano, Justin Tobler, and Toon Claes. Key discussions revolve around the robustness of downcasting in multi-backend setups (Junio and Justin), the naming of the `create_on_disk` callback (Junio), and the initialization sequence (Justin). Patrick has addressed some concerns—rewriting commit messages to clarify latent bugs and retaining the callback name for consistency with the ref subsystem—but others remain open, such as whether to add a generic `load object map` method to the ODB interface. The latest exchange with Justin clarifies that the `should_use_loose_object_map()` check is now per-source, but Patrick sees no practical risk of inconsistency, and eager loading of compatibility maps is retained for caution. No merge status has been reported, and the series is still in review.
