This thread is about Patrick Steinhardt’s six-patch series (v3) to make Git’s on-disk object database (ODB) structures pluggable, part of the broader ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/info` or `objects/pack`) from the core repository setup, allowing future ODB backends to define their own on-disk layouts without modifying Git’s core logic.

The series is under active review, with the first patch—a correctness fix for loose-object map loading—already marked by Junio Hamano as "will merge to 'next'" in his 2025-06-10 "What's cooking" report. The remaining patches, including this fourth one, are uncontroversial and ready for merging. This fourth patch refactors the repository initialization sequence to defer ODB creation until after the reference database is set up, a mechanical change that paves the way for the pluggable ODB directory creation introduced in the sixth patch. The only functional adjustment since v2 is to account for the new third patch, which moved environment variable handling into `odb_new()`.

Key participants include Junio (who reviewed the series and split the status of the patches), Justin Tobler (who approved v2 with "looks good to me"), and Toon Claes (who contributed a test case for the first patch, elevating it to a correctness fix). The series is a prerequisite for future ODB backends, such as the planned `objectStorage` extension, and ties into related work on moving environment variable handling into the ODB backend. No open questions remain for this fourth patch, and the series as a whole is progressing smoothly toward integration.
