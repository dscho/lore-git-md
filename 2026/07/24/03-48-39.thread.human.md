This thread is about Patrick Steinhardt’s five-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack`) from core repository setup, enabling future ODB backends with custom layouts. The first patch fixes a latent correctness bug in loose-object map loading, now verified by a test case from Toon Claes, making it a strong candidate for early merging. The series is at v2 and under active review, with Justin Tobler approving the latest changes.

The main discussion now centers on the third patch, which defers ODB creation. Toon Claes proposed an alternative implementation to simplify environment variable handling, but Patrick countered with a narrower refinement: moving environment variable logic directly into `odb_new()`. This aligns with a planned follow-up to consolidate ODB-related environment variables into the "files" backend, reducing coupling. The change is uncontroversial and doesn’t alter the series’ core design, though it leaves open whether Toon will accept the adjustment. Other patches are ready for merging, with only minor design questions remaining (e.g., callback naming for non-filesystem backends).

Key participants include Junio (who raised architectural questions about downcast safety and callback extensibility), Justin Tobler (who approved v2 after substantive review of v1), and Toon Claes (who provided the test case and proposed the alternative implementation). The series remains under review, with no merge status reported. The first patch’s correctness fix and the fifth patch’s callback design are uncontroversial, while the third patch’s initialization sequence is still being refined.
