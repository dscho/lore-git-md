This thread is about Patrick Steinhardt’s six-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack/`) from core repository setup, enabling future ODB backends with custom layouts. The first patch, a correctness fix for loose-object map loading in multi-backend setups (e.g., SHA-256 with SHA-1 compatibility), is already slated for early graduation to Junio’s `next` branch, while the rest of the series is uncontroversial and ready for merging.

The latest update, Toon Claes’s review of the third patch, is a mechanical but important refactor: it moves environment variable handling (`GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`) from `apply_repository_format()` into `odb_new()`, making the function self-contained. This eliminates redundant logic and prepares for future work, like deferring ODB construction. Toon noted a minor cleanup opportunity (removing redundant string duplication) but confirmed the patch is functionally sound. The series as a whole has no outstanding technical objections, though some architectural questions—like Junio’s suggestion for a generic `load object map` method—remain unresolved but aren’t blockers.

Key participants include Patrick (author), Junio (maintainer, who reviewed the series and marked the first patch for `next`), Justin Tobler (substantive reviewer who approved the changes), and Toon (who provided test cases and feedback). The series touches ODB initialization plumbing and is a prerequisite for non-filesystem backends, tying into Patrick’s broader `objectStorage` extension plans.
