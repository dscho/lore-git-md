This thread is about Patrick Steinhardt’s six-patch series making Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack/`) from core repository setup, enabling future ODB backends with custom layouts. The first patch fixed a latent correctness bug where Git ignored loose-object maps in alternates when using compatibility hash algorithms (e.g., SHA-256 with SHA-1), and it’s now approved for merging to `next`. The rest of the series has also gained approval from Justin Tobler and Toon Claes, with the latest revision adopting Toon’s alternative design for the initialization sequence.

The series is now in its final stages. Junio Hamano’s recent reply confirms the fourth patch—a mechanical refactoring that makes ODB creation explicit at every call site—is nearly ready, pending a small reroll to address two minor issues: a misleading docstring and a formatting inconsistency. These are cosmetic and don’t affect functionality. The entire series is uncontroversial, with the first patch already slated for `next` and the rest expected to follow once the reroll lands. Key changes include new callbacks for backend-specific directory creation, fixes for latent bugs in loose-object map handling, and a cleaner initialization sequence that paves the way for non-filesystem backends. The series touches core files like `odb.c`, `setup.c`, and `repository.c`, and introduces symbols like `create_on_disk` and `ODB_NEW_HONOR_ENV`.
