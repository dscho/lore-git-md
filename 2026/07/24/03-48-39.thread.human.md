This thread is about Patrick Steinhardt’s five-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack` or `objects/info`) from the core repository setup code, allowing future ODB backends to define their own layouts without modifying Git’s internals. The series also fixes two latent bugs in loose-object map loading, one of which—affecting repositories with alternates and compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility)—was confirmed by Toon Claes with a test case showing real-world impact.

The series is under active review, with Junio C Hamano, Justin Tobler, and Toon Claes providing substantive feedback. The first patch, which fixes the loose-object map path bug, is now recognized as a correctness fix, while the second patch’s refactor of loose-object map loading has drawn questions about multi-backend consistency and downcast safety. Junio suggested a more forward-looking design (adding a generic `load object map` method to the ODB source interface) to eliminate downcasting entirely, and Justin questioned whether the `should_use_loose_object_map()` guard might behave inconsistently across backends. Toon’s recent reply clarifies that the guard was moved to accommodate a new call site (`odb_source_loose_new()`), ensuring it’s enforced even when the loose backend is initialized directly, but the broader architectural questions remain open.

Other open issues include the naming of the `create_on_disk` callback (Junio suggested a more generic term like `initialize` for non-filesystem backends), the design of the initialization sequence (Justin prefers an explicit `odb_new()` call over a flag-based approach), and commit message clarity. The series touches several files, including `loose.c`, `odb/source-loose.c`, and `setup.c`, and introduces new symbols like `loose_object_map_load()` and the `create_on_disk` callback. No merge status has been reported, and the series is still in the review phase.
