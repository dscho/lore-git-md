This thread is Patrick Steinhardt’s five-part patch series decoupling Git’s on-disk object database (ODB) structures from the core repository setup code. The goal is to make the `objects/` directory layout pluggable, so future ODB backends can define their own subdirectory structures without modifying the generic setup logic. The series fixes two latent bugs in loose-object map loading—ensuring maps are loaded from the correct ODB source path and removing hardcoded assumptions about the "files" backend—and reorders initialization steps to defer ODB creation until after the ref database is set up.

The first four patches lay the groundwork by refactoring path handling, introducing new helper functions, and removing hardcoded assumptions. The just-posted fifth patch completes the series by adding a `create_on_disk` callback to the ODB source interface, moving backend-specific directory creation (e.g., `objects/pack`, `objects/info`) into the "files" backend’s implementation. This is purely internal refactoring with no user-visible changes, but it’s a critical step for the broader ODB abstraction effort. The series is under initial review, with no feedback yet from other contributors. No open questions or objections have been raised so far.
