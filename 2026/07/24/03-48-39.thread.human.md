This thread is about Patrick Steinhardt’s six-patch series **v5** to make Git’s on-disk object database (ODB) structures pluggable, part of the broader ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack/`) from core repository setup, enabling future ODB backends with custom layouts.

The first patch, which fixed a latent correctness bug in loose-object map loading, has already been merged to Junio’s `next` branch. The remaining five patches are fully approved and ready for merging. The series addresses all prior feedback, including a design change in this fourth patch: instead of deferring ODB creation via a flag, it now makes ODB initialization an explicit step at every call site, simplifying the path for the final patch’s `create_on_disk` callback. Key reviewers—Justin Tobler and Toon Claes—have given their "looks good to me" (LGTM), and Patrick has addressed the last minor docstring and formatting nits in this reroll.

The technical changes touch `repository.c`, `setup.c`, and `setup.h`, with the core logic now ensuring ODB initialization and on-disk creation are handled together. The series is uncontroversial, with Junio’s "What’s cooking" report (June 10) listing the remaining patches as "will merge to 'next'." The only open questions are forward-looking (e.g., callback naming for non-filesystem backends), but these don’t block the current work. The series is now in its final form, targeting the current development cycle.
