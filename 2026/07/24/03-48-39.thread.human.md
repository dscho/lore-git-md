This thread is about Patrick Steinhardt’s five-patch series making Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack`) from the core repository setup, allowing future ODB backends to define their own layouts without modifying Git’s internals. The series is now at v2, with key improvements: a new test case (provided by Toon Claes) that confirms the first patch fixes a latent bug affecting repositories with SHA-256 compatibility and alternates, and clearer commit messages, particularly for the second patch, which now explicitly describes a correctness issue where the code would BUG if a non-"files" backend were used with a compatibility hash algorithm.

The series touches 14 files, introducing new functions and a `create_on_disk` callback for ODB sources, while removing hardcoded assumptions about directory layouts. The third patch defers ODB creation until after the ref database is set up, a prerequisite for the planned `objectStorage` extension, which will enable non-filesystem backends. Feedback from Junio C Hamano, Justin Tobler, and Toon Claes has been largely addressed, though some architectural questions remain open, such as whether to eliminate downcasting in the ODB source loop (Junio’s suggestion) or rename the `create_on_disk` callback to something more generic. The added test case and clarified commit messages strengthen the case for merging, especially for the first two patches, which now address confirmed correctness issues. The rest of the series is infrastructure work with no immediate user impact but is critical for future ODB backends. The series remains under review, with no merge status reported.
