This thread is Patrick Steinhardt’s five-patch series refactoring Git’s object database (ODB) setup to make on-disk structures pluggable. The goal is to decouple backend-specific directory creation (like `objects/pack`) from the core repository setup, enabling future ODB backends to define their own layouts without modifying Git’s core logic. The series is part of the broader ODB abstraction effort led by Steinhardt, which aims to make Git’s storage layer more flexible.

The first two patches fixed latent bugs in loose-object map loading, ensuring maps are loaded from the correct ODB source and removing hardcoded assumptions about initialization order. The third patch, just posted, refactors the repository initialization sequence to defer ODB creation until after the ref database is set up. This is a mechanical change—splitting `create_object_directory()` into two steps and adding a flag to skip ODB creation during repository format application—but it’s a critical enabler for the next patch, which will introduce backend-specific directory creation. No reviews have been posted yet, and the series remains under initial review with no open questions or objections raised so far. The work targets the current development cycle and is based on the "7th batch" integration.
