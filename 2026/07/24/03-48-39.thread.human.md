This six-patch series from Patrick Steinhardt completes a key step in Git’s object database (ODB) abstraction effort, making on-disk ODB structure creation pluggable. The final patch, now posted, implements the `create_on_disk` callback in the "files" backend, allowing backends to manage their own subdirectory layouts (e.g., `objects/pack/`, `objects/info/`) while keeping the top-level `objects/` directory mandatory for repository discovery. This refactoring enables future ODB backends—such as those for non-filesystem storage—to define custom layouts without modifying core setup logic.

The series began with a critical correctness fix: a latent bug in loose-object map loading that caused alternates’ maps to be silently ignored when using compatibility hash algorithms (e.g., SHA-256 with SHA-1). That patch, now merged to `next`, included a regression test verifying `git rev-parse` resolves objects borrowed from alternates. The remaining patches disentangle ODB initialization from repository setup, moving environment variable handling into `odb_new()`, eliminating redundant checks, and introducing the `create_on_disk` callback. Junio’s "What’s cooking" report (June 10) lists the first patch as merged and the rest as ready for `next`, with all substantive feedback addressed in the final v5 reroll.

Key participants—Justin Tobler and Toon Claes—have given their "looks good to me" (LGTM) for the entire series, and Patrick incorporated the last minor docstring and formatting nits raised by Toon. The architectural discussion about initialization sequence design is resolved in favor of Toon’s alternative, which abandons a temporary flag in favor of explicit ODB creation at every call site. While a few forward-looking questions remain (e.g., downcast safety for multi-backend setups, callback naming for non-filesystem backends), they’re not blockers. The series is now fully approved and poised for integration.
