This patch series from Patrick Steinhardt continues its march toward making Git’s on-disk object database (ODB) structures pluggable, a key piece of the larger ODB abstraction effort. The latest update, v4, is now fully uncontroversial and ready for merging. The first patch—a correctness fix that ensures alternates’ loose-object maps are properly loaded—has already been slated for early graduation to Junio’s `next` branch, thanks to its dedicated regression test and clear safety benefits. The rest of the series, including this third patch, is also in the clear.

The third patch itself is a clean refactoring that moves ODB-related environment variable handling into `odb_new()`, where it logically belongs. By introducing a simple `ODB_NEW_HONOR_ENV` flag, Patrick eliminates awkward string duplication and simplifies the call site in `apply_repository_format()`. This change is purely preparatory, setting the stage for the revised fourth patch (which now makes ODB creation explicit at every call site) and aligning with the longer-term goal of pushing environment variable logic into the backends themselves. Justin Tobler’s prior approval and the lack of new feedback in v4 confirm its readiness.

With the architectural debate over initialization sequence resolved in favor of Toon Claes’s simpler alternative, the series is now a straightforward progression of small, well-tested steps. The remaining patches—including the sixth, which implements the `create_on_disk` callback in the "files" backend—are all uncontroversial and await Junio’s final sign-off. The only lingering questions are forward-looking (e.g., whether the `create_on_disk` callback should be renamed for non-filesystem backends) and won’t block this iteration. For now, the focus is on landing these foundational changes so future ODB backends can implement custom on-disk layouts without touching core setup logic.
