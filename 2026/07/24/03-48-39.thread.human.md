This thread is about Patrick Steinhardt’s five-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack` or `objects/info`) from the core repository setup code, allowing future ODB backends to define their own on-disk layouts without modifying Git’s internals. The series also fixes two latent bugs in loose-object map loading, including one where repositories using compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility) and alternates would fail to load objects correctly.

The series is under active review, with Junio C Hamano and Justin Tobler providing substantive feedback on multiple patches. Junio raised concerns about the robustness of downcasting in the ODB source loop and suggested a more forward-looking design—adding a generic `load object map` method to the ODB interface to avoid backend-specific assumptions. Justin questioned the initialization sequence design, particularly the use of a flag to defer ODB creation, and asked whether an explicit `odb_new()` call might be cleaner. Toon Claes recently weighed in on the first patch, elevating its importance by demonstrating that the bug it fixes is not just theoretical: it breaks real-world setups with alternates and compatibility hash algorithms. Toon’s review included a concrete test case to verify the fix, making the issue immediately actionable.

The series touches several core files (`loose.c`, `setup.c`, `repository.c`, and ODB source files) and introduces new symbols like the `create_on_disk` callback and `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag. While the fifth patch received surface-level approval from Justin, the second and third patches remain open for discussion due to design questions about initialization order and multi-backend safety. No merge status has been reported, and the series is still in the review phase for the current development cycle. The next steps will likely involve addressing Junio’s and Justin’s feedback, particularly around the downcasting issue and initialization sequence, as well as incorporating Toon’s test case to ensure the fix is robust.
