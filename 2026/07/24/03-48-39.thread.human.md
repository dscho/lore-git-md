This thread is about Patrick Steinhardt’s six-patch series making Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack/` and `objects/info/`) from the core repository setup, allowing future ODB backends to define their own on-disk layouts without modifying Git’s core logic. The first patch in the series fixes a latent correctness bug in loose-object map loading, which is now confirmed as a regression fix with test coverage, making it a candidate for early graduation.

The series is now complete with v3, which includes a new patch (the fifth) improving error message clarity in downcasting macros and another (the fourth) refactoring the initialization sequence to defer ODB creation until after the reference database is set up. The sixth and final patch, just posted, implements the core mechanism by adding a `create_on_disk` callback to the ODB source interface, used by the "files" backend to create its subdirectories. This patch is uncontroversial and aligns with the series’ refactoring goals.

Key participants include Junio C Hamano, who reviewed the series and signaled intent to merge the first patch to `next` while keeping the rest under review; Justin Tobler, who reviewed the series in v2 and gave a "looks good to me"; and Toon Claes, who provided a test case for the first patch’s correctness fix. Open questions remain about downcast safety, callback naming, and the future of loose-object map loading, but these are not blockers for the current series. The first patch is set to graduate independently, while the remaining five are ready for merging.
