This thread is about Patrick Steinhardt’s five-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The goal is to decouple backend-specific directory creation (like `objects/pack` or `objects/info`) from the core repository setup code, allowing future ODB backends to define their own layouts without modifying Git’s internals. The series also fixes latent bugs in loose-object map loading and removes hardcoded assumptions about initialization order.

Junio C Hamano has reviewed all five patches. The first four received a mix of surface-level and substantive feedback: the second patch’s design (unconditional downcasting) was flagged as potentially fragile, with Junio suggesting a more backend-agnostic approach, while the fourth was approved with a minor spelling fix. The fifth patch, which introduces the `create_on_disk` callback and moves backend-specific directory creation into the "files" backend, was just reviewed. Junio acknowledged its correctness but questioned whether the callback’s name and scope are future-proof for non-filesystem backends (e.g., cloud object stores), suggesting a more generic name like `initialize`. This isn’t a blocker for the current series but hints at interface refinements for later work. The series remains under review, with no merge status reported.

Key technical changes include deferring ODB creation until after the ref database is set up, loading loose-object maps from source-specific paths, and adding a flag to leave the repository partially initialized. The patches touch core setup code (`setup.c`, `repository.c`) and ODB source files, introducing new symbols like `create_on_disk` and renaming `create_object_directory()` to `create_object_database()`. There are no on-disk format changes, and the series is based on the "7th batch" integration for the current development cycle. The only open questions are Junio’s design feedback on the second and fifth patches, which may require follow-up but don’t currently block progress.
