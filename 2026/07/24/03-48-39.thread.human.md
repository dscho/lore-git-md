This thread is about Patrick Steinhardt’s five-patch series to make Git’s on-disk object database (ODB) structures pluggable, part of the larger ODB abstraction effort. The series decouples backend-specific directory creation from core repository setup, enabling future ODB backends with custom layouts. The first patch fixes a latent correctness bug in loose-object map loading, now verified by a test case from Toon Claes, making it a strong candidate for early graduation. The rest of the series refactors initialization logic to defer ODB creation and moves backend-specific directory setup into a new callback.

The series is under review, with v2 incorporating feedback from Justin Tobler (who approved the entire series) and Junio C Hamano (who raised design questions about the second and fifth patches). The third patch, which defers ODB creation, has drawn an alternative implementation from Toon Claes. His version consolidates environment variable handling into a single helper, eliminating awkward double-pointer passing and making the control flow more linear. This refactoring is narrow and improves readability without changing behavior, aligning with the series’ goals. No new technical questions have emerged, and the patch is ready for merging if Patrick accepts it.

Key open questions remain about the long-term design: whether to add a generic `load object map` method to the ODB source interface (Junio’s suggestion), how to handle initialization sequence cleanliness (Justin’s concern), and the naming of the `create_on_disk` callback for non-filesystem backends. The series is uncontroversial in its current form, with the first, fourth, and fifth patches effectively ready for merging. The third patch’s alternative implementation from Toon offers a cleaner path forward, and the second patch’s latent BUG fix is now well-justified. The only remaining direct caller of `repo_read_loose_object_map()` could eventually be replaced by a `FLUSH_CACHES` operation, but this is forward-looking.
