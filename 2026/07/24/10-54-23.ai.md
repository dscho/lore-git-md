This is the core feature patch in the GSoC `git cat-file --batch-command` remote-object-info series, now at v21 and queued for `next`. It introduces the `remote-object-info` command to `git cat-file --batch-command`, allowing users to query object metadata (currently size only) from remote repositories without downloading the full objects.

The patch implements the command with strict input validation: 8KB URL length limit, 10,000-object batch cap, and full OID format enforcement (no short OIDs). It dynamically validates format placeholders against server-advertised capabilities, supporting only `%(objectname)` and `%(objectsize)` for now. The execution model batches multiple OIDs into a single request to minimize overhead, with special handling for `--buffer` mode to avoid remote communication overhead. Memory safety is enforced via `xcalloc`, bounds-checking, and `free_object_info_contents()` to prevent leaks.

Key technical details include the `is_remote` flag in `struct expand_data`, initialization of `data->type = OBJ_BAD` to prevent crashes when `type_name()` returns NULL, and strict handling of unsupported atoms (returning empty strings, matching `for-each-ref` behavior). The command integrates with the transport layer via the `fetch_object_info` vtable method and requires protocol v2. Test coverage spans all three smart transports (`git://`, `file://`, `http://`), `--buffer` mode, `-Z` output, and edge cases like missing objects, unsupported protocols, and malformed inputs.

The implementation is robust and well-tested, with 719 lines of new tests in `t/t1017-cat-file-remote-object-info.sh` covering the full matrix of scenarios. The patch is authored by Eric Ju with significant contributions from Pablo Sabater (who added the atom allow-list validation) and Calvin Wan, and carries sign-offs from Jonathan Tan and Christian Couder. The series is technically complete for its initial scope (size-only queries) and cleared for graduation to `master`.
