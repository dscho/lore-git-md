This is the fourth patch in Harald Nordgren’s **v22 `git branch --delete-merged` series**, which is now **unblocked and ready for merging**. This patch prepares the `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that prevents falling back to `HEAD` when checking whether a branch is merged into its upstream.

The change is **minimal and targeted**: it modifies `branch_merged()` and `delete_branches()` to skip the `HEAD` fallback when the new flag is set, ensuring `--delete-merged` only deletes branches merged into their upstream (not `HEAD`). The patch preserves existing behavior for all current callers, as the flag is not yet used. The commit message clearly explains the motivation—avoiding a "gentle reminder" message and irrelevant `HEAD` checks for bulk callers that have already established the branch has an upstream.

This is a **low-risk refactoring** that aligns with the series’ broader goal of introducing a safe, automated branch cleanup command. The patch touches only `builtin/branch.c` and is part of a **well-tested, API-consistent** effort to modernize the branch deletion logic. The series as a whole is **implementation-complete**, with all safety mechanisms (per-branch opt-out, order-independent stacked-branch protection, `--dry-run` preview) and edge cases (missing upstreams, push divergence, self-referential upstreams) now addressed.
