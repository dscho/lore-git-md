This is the **core implementation patch** of Harald Nordgren’s `git branch --delete-merged` series, now in its **final v22** and **ready for merging**. The patch adds the `--delete-merged <branch>` subcommand, which safely deletes local branches whose work has already landed on their upstream, while preserving branches that are still needed (checked out, missing upstreams, push to their upstream, or used as upstreams for unmerged work).

The command supports **repeatable upstream selectors** (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the upstream match, and **optional positional patterns** (e.g., `topic-*`) to limit deletion scope. Safety mechanisms include **order-independent stacked-branch protection** (ensuring no branch is deleted out from under stacked work), per-branch opt-out via `branch.<name>.deleteMerged=false`, and `--dry-run` preview (implemented in patch 7/7). The implementation is **well-motivated** (addressing a real workflow pain point), **thoroughly tested** (with comprehensive integration tests covering all safety checks and edge cases), and **aligned with Git’s API consistency expectations**.

Key technical details:
- **Order-independent stacked-branch protection**: A single-pass graph traversal (`collect_stacked_branch_bases()`) ensures consistent results regardless of ref iteration order. The command fails to delete a branch if it is used as an upstream for an unmerged branch but clears the upstream config for kept (merged) branches whose own upstream is being deleted.
- **Safety checks**: Skips checked-out branches, branches with missing upstreams, and branches that push to their upstream (e.g., `main` tracking `origin/main`). Unmerged branches are silently skipped.
- **Integration with existing machinery**: Uses the `--forked` filter (introduced in patch 1/7) to resolve upstream arguments and the flags-based API (patches 2-4/7) for deletion behavior (`DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`).
- **Test coverage**: The expanded test suite verifies merged branches are deleted, unmerged/checked-out/protected/opt-out branches are spared, stacked-branch protection works regardless of branch name order, and edge cases (missing upstreams, self-referential upstreams) are handled correctly.

The patch touches `builtin/branch.c` (adding the core command and helpers), `Documentation/git-branch.adoc` (documenting the new option), and `t/t3200-branch.sh` (adding 200+ lines of integration tests). Junio C Hamano has confirmed there are no outstanding issues, and the series is **unblocked and ready for merging**. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.
