This is the second patch in Patrick Steinhardt’s five-part series making Git’s on-disk object database (ODB) structures pluggable. It refactors how loose-object maps are loaded so that the logic lives in the loose backend instead of the repository setup code.

The patch addresses two problems in the current initialization sequence: it assumes the primary ODB is the “files” backend, and it forces repository configuration and ODB initialization to be interleaved. By moving the map-loading call into `odb_source_loose_new()`, the loose backend now owns the process, removing the hard-coded dependency on the files backend and allowing the ODB to be fully initialized before any compatibility hash algorithm is set.

Code changes are confined to five files: `loose.c`/`loose.h` (expose `loose_object_map_load()`), `odb/source-loose.c` (call the new function at backend creation time), `repository.c` (remove the now-redundant call from `repo_set_compat_hash_algo()`), and `setup.c` (reorder ODB creation to happen after repository configuration). The diff is small and mechanical, with no new behavior visible to users.
