This is a bugfix patch for `git clone` that prevents a segmentation fault when using `--revision` with servers that advertise more refs than requested (notably Azure DevOps). The issue surfaces specifically with protocol v0, where `guess_remote_head()` returns a non-NULL `remote_head_points_at` whose `peer_ref` field is NULL, leading to a crash when the code dereferences `remote_head_points_at->peer_ref->name` without a NULL check.

The fix is minimal: a single additional NULL check in `update_remote_refs()` in `builtin/clone.c`. This version (v2) also includes the regression test Junio requested, which enforces protocol v0 and verifies the clone succeeds without segfaulting. The commit message now clearly explains the protocol-level difference between v0 and v2 that triggers the bug, and the test ensures the fix works in the problematic scenario.
