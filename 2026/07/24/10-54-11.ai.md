This is the twenty-first iteration of the `git cat-file --batch-command` remote-object-info series, now **technically complete** and **queued for `next`**. The series enables Git clients to query object metadata (currently size, with type support designed for future expansion) from remote repositories without downloading full objects, using the `object-info` protocol v2 capability.

This revision (v21) makes three targeted cosmetic changes since v20: (1) **drops the unnecessary documentation change** in `git-cat-file.adoc` that restored `CAVEATS` section references for `objectsize:disk` and `deltabase` atoms (resolving the prior disagreement between Pablo Sabater and Karthik Nayak); (2) **fixes the `EXPAND_DATA_INIT` macro formatting** to use Karthik’s preferred style (trailing commas and field alignment) for cleaner future expansion; and (3) **corrects a typo and adds a blank line before the `WARNING`** in the documentation. These changes address the last remaining surface-level nits and do not affect functionality or behavior.

The series remains structurally unchanged: 13 patches authored by Pablo Sabater (7), Eric Ju (3), and Calvin Wan (3). Key components include the `remote-object-info` command in `git cat-file --batch-command` (patch 12/13), dynamic adaptation to server-advertised capabilities via the `remote_allowed_atoms` string list (patch 13/13), and robust input validation (10,000-object batch limit, 8KB URL length cap, strict OID format checks). The implementation handles edge cases like missing objects, unsupported protocols, and malformed responses, and includes 747 lines of new tests in `t/t1017-cat-file-remote-object-info.sh` covering all three smart transports (`git://`, `file://`, `http://`), `--buffer` mode, and `-Z` output.

The build fix for `hash_algo` (patch 5/13) remains incorporated, and the series is cleared for graduation to `master`. The GitHub CI run shows no failures, and the unresolved cosmetic nits from v20 have now been addressed. The series is ready for final integration.
