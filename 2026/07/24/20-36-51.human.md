This is a bugfix patch for submodule handling, now queued for merging. Junio C Hamano has picked up the v2 iteration of Éric NICOLAS’s patch that fixes a regression in `git submodule update --remote` when URL aliases (`url.<base>.insteadOf`) are used. The regression, introduced in commit ca62f524c1 (2025), caused submodules with aliased URLs to fail to match their remotes, falling back to the default remote logic instead.

The patch modifies `repo_remote_from_url()` in `remote.c` to resolve URL aliases via `alias_url()` before comparing URLs, ensuring the correct remote is selected. The test in `t/t7406-submodule-update.sh` verifies the fix with a global `insteadOf` alias, submodule setup, and remote renaming. This version addresses all feedback from Junio’s review of the initial patch, improving commit message clarity and simplifying the implementation by reusing the `url` variable instead of introducing a redundant one.

The fix is narrowly scoped, well-tested, and ready for merging. Junio’s "Queued" note signals it will likely appear in `next` soon, with no remaining objections or open questions. If you work with submodules and URL aliases, this patch resolves a real-world annoyance without changing on-disk formats or introducing new complexity.
