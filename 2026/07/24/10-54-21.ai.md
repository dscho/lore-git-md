This is part 10 of the 13-patch `git cat-file --batch-command` remote-object-info series (v21), now queued for `next`. The patch enables servers to advertise which object-info attributes they support (currently only `size`) when the `transfer.advertiseobjectinfo` configuration is enabled. This allows clients to dynamically tailor their queries to the server's capabilities, avoiding unnecessary requests for unsupported attributes.

The change is minimal: it modifies the `object_info_advertise()` function in `serve.c` to append `"size"` to the `value` strbuf when advertising is enabled. The function previously ignored the `value` parameter entirely. The patch is authored by Calvin Wan but carries sign-offs from Eric Ju and Pablo Sabater, reflecting the collaborative nature of the series.

This is a foundational piece of the protocol v2 `object-info` capability, complementing earlier patches that implement the client-side command (`remote-object-info` in `git cat-file --batch-command`) and server-side request handling. The advertisement mechanism is designed for extensibility: when additional attributes (e.g., `type`) are added in the future, the server can advertise them by extending the `value` string.

The patch is uncontroversial and aligns with the series' goal of dynamic capability negotiation. It has no test coverage of its own but is exercised by the broader test suite in `t/t1017-cat-file-remote-object-info.sh`, which verifies that clients correctly adapt to server-advertised capabilities. The series as a whole is technically complete and cleared for graduation to `master`.
