This is a **platform compatibility bugfix** for macOS, addressing a memory leak in the system regex engine (TRE) when processing invalid UTF-8 sequences. Junio C Hamano’s reply to Chungmin Lee’s patch raises two main points for discussion: the long-term maintainability of the workaround and the organization of platform-specific overrides in the codebase.

The patch itself remains a well-motivated, self-contained fix for a real-world problem—`git grep` over binary files (e.g., PDFs) can leak gigabytes of memory on macOS, risking kernel watchdog panics. The implementation splits input buffers at invalid multibyte sequences using `mbrtowc()`, ensuring consistency with TRE’s decoder while avoiding the leaking path. Junio’s questions do not challenge the correctness or necessity of the fix but focus on structural concerns: whether the workaround should live in Git indefinitely (given it targets a macOS bug) and whether the current conditional compilation approach scales cleanly if other platforms need similar overrides in the future.

On the first point, Junio asks how long the workaround will need to be maintained, implicitly questioning whether this is a temporary band-aid or a permanent fixture. The patch’s commit message does not speculate on upstream macOS fixes, so the answer remains open. On the second point, Junio suggests a more modular approach for future platform-specific overrides: define each override in its own platform header, then conditionally include it in `git-compat-util.h` with a fallback inline definition. This would avoid cluttering the main header with nested `#ifdef` chains as more platforms require workarounds.

The test coverage (`t7810-grep.sh`) verifies matches around invalid UTF-8 and correct anchoring of `^`/`$`, but Junio questions whether the test should be macOS-specific or allowed to run (and possibly fail) on other platforms. The current patch restricts the test to macOS builds using multibyte regex, which is technically correct but may limit broader regression detection.

No technical flaws in the patch itself are identified in Junio’s reply—only structural and long-term maintenance considerations. The fix is narrowly scoped, thoroughly tested, and integrates cleanly across all build systems (Makefile, Meson, CMake). Reviewers familiar with regex internals or macOS-specific issues may want to weigh in on the maintainability questions, but the patch is otherwise ready for deeper technical review.
