This is the core patch in Harald Nordgren’s **final v21 series** for `git branch --delete-merged`, now **implementation-complete and unblocked for merging**. The patch adds the new subcommand that safely deletes local branches whose work has already landed on their upstream, with comprehensive safety checks and **order-independent stacked-branch protection**.

The command deletes local branches matching optional patterns when their configured upstream matches one of the `--delete-merged` arguments and their tip is reachable from that upstream. The `--delete-merged` option can be repeated to widen the upstream match (e.g., `--delete-merged origin/main --delete-merged origin/next`), while positional patterns (e.g., `topic-*`) limit which local branches are considered. This design keeps upstream selection and local branch filtering orthogonal, giving users precise control over the cleanup scope.

Safety is the central concern. The command skips branches that are checked out in any worktree, have missing upstreams, or would update their upstream when pushed by name (e.g., `main` tracking `origin/main`). It also **silently skips unmerged branches**, so one unmerged topic does not abort the entire sweep. The most intricate safety mechanism is **order-independent stacked-branch protection**: a branch is kept if it is used as an upstream for an unmerged branch, even transitively (e.g., `b1→b2→b3`). The implementation collects all protected branches in a single pass before mutating the deletion set, ensuring consistent results regardless of ref iteration order. This addresses Junio C Hamano’s blocking correctness concern from earlier versions.

The patch touches `builtin/branch.c`, adding the new `delete_merged_branches()` function and helpers like `collect_stacked_branch_bases()` and `protect_stacked_branch_bases()`. The test suite in `t/t3200-branch.sh` is expanded with **200+ lines of integration tests** covering all safety checks, edge cases (self-referential upstreams, missing upstreams), and the order-independent protection logic. The implementation is **well-motivated** (addressing a real workflow pain point), **thoroughly tested**, and **aligned with Git’s API consistency expectations**. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.
