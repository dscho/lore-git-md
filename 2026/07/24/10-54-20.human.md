This is the ninth patch in the v21 series implementing `git cat-file --batch-command` remote object metadata queries. The patch tightens the server-side object existence check so that **bare OID requests** (those without any attributes like `size`) now trigger an unconditional lookup, ensuring consistent behavior regardless of what metadata the client asks for.

The change extracts the existence check into a new helper, `get_object_info()`, which wraps `odb_read_object_info_extended()` with two key flags: `OBJECT_INFO_SKIP_FETCH_OBJECT` (to prevent partial-clone servers from fetching missing objects) and `OBJECT_INFO_QUICK` (to avoid unnecessary pack rescans). The helper returns `OBJ_BAD` for unknown objects, and the patch updates the condition from `< 0` to `<= OBJ_NONE` to catch both `OBJ_BAD` and `OBJ_NONE` as unrecognized.

With this patch, bare OID requests now have two possible responses: `<OID>` if the object exists, or `<OID> SP` if it doesn’t. The documentation in `gitprotocol-v2.adoc` is updated to reflect this behavior, explicitly requiring full OIDs, defining `obj-size` as numeric, and clarifying that the `attr` header is optional (zero or more pkt-lines). The patch also adds 63 lines of new tests in `t/t5701-git-serve.sh` covering bare OID requests, unrecognized OIDs, and size queries for missing objects.

This is a well-motivated robustness improvement that closes a gap in the protocol’s edge-case handling. The commit message clearly explains the change, the new helper is cleanly designed, and the tests cover the key scenarios. The patch is part of a series that is now technically complete and queued for `next`, so this is a final polish rather than a course correction.
