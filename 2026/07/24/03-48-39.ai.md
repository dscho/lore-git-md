This is the cover letter for a five-patch series from Patrick Steinhardt that makes the creation of on-disk object database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort, which aims to allow alternative backends beyond the traditional loose-object and packfile storage.

The goal is to decouple the creation of backend-specific directories (like `objects/info` and `objects/pack`) from the generic repository setup. While the top-level `objects/` directory remains mandatory for repository recognition, individual backends now handle their own subdirectory creation. This change enables future backends to implement custom on-disk layouts without modifying core setup logic.

The series starts with a preparatory fix in the loose-object map handling to ensure correct source loading, then detangles the loading of loose object maps from repository setup. The key change is deferring ODB creation until after the backend is known, followed by introducing a helper function to map ODB source types to their names. The final patch implements the pluggable directory creation mechanism.

Files touched span the loose-object handling (`loose.c`, `loose.h`), ODB source management (`odb/source*.c`, `odb/source*.h`), and repository setup (`setup.c`, `repository.c`). The changes are mechanical but foundational, introducing new functions and structures while removing hardcoded assumptions about directory layouts.

This is infrastructure work with no immediate user-visible impact, but it’s a prerequisite for any future ODB backend that doesn’t follow the traditional loose/pack layout. The series is based on the recent "7th batch" integration (commit `9a0c4701dc`), indicating it’s targeting the current development cycle.
