This is the third patch in Patrick Steinhardt’s five-patch series refactoring Git’s object database (ODB) setup to support pluggable backends. The patch defers ODB creation until after the ref database is initialized, introducing a new flag (`APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION`) to leave the repository in a partially-initialized state. This is pure infrastructure work—no user-visible changes or on-disk format modifications—but it’s a critical step toward allowing backends to handle their own directory layouts (e.g., `objects/pack`, `objects/info`) in later patches.

Junio’s review here is light but approving. He walks through the diff to confirm the logic: environment variables for object directories are still read early (via the new `get_object_directories()` helper), but ODB creation is now conditional on the new flag. The deferred creation happens in `create_object_database()` (renamed from `create_object_directory()`), which is called after ref setup and configuration. Junio’s only substantive note is a rhetorical question about whether this deferral is preparing for a future where the backend type is specified in global config—a reasonable inference, though the patch itself doesn’t implement that.

The patch is well-scoped and clearly motivated by the series’ goal. It’s a mechanical refactor that moves code around without changing behavior, and the commit message does a good job explaining the "why" (enabling pluggable backends) alongside the "what." If you’re following the ODB abstraction effort, this is worth noting as a foundational change; otherwise, it’s safe to skip unless you’re debugging repository initialization. No controversy or open questions here—just a straightforward step in a larger refactor.
