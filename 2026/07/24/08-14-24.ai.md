This is the second patch in Ted Nyman’s three-patch v4 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI and dumb HTTP downloads. The patch targets the core issue: when multiple Git processes fetch the same packfile into a single object database, they can corrupt the temporary pack file by appending duplicate data.

The solution is straightforward: instead of opening the partial pack file in append mode (which forces each write to the current end of the file), the patch opens it in read-write mode without O_APPEND and seeks to the current end once. Each downloader then retains the offset matching the Range it requested. Because the staging key uniquely identifies immutable pack contents, overlapping responses write identical bytes at identical offsets, preventing corruption while preserving resumable downloads. The patch also handles MinGW’s non-append O_RDWR open behavior, which grants FILE_SHARE_DELETE only for existing files, by creating a missing partial pack exclusively, closing it, and reopening it without O_CREAT so every retained descriptor permits another downloader to unlink the staging path.

The implementation touches `http.c` (the core change), `http-fetch.c`, `http-push.c`, and `http-walker.c` (all accepting HTTP 416 when a partial pack is already complete), and updates the `git-http-fetch` documentation to clarify that the staging key need not be the pack hash but must uniquely identify the pack contents for resumption. The patch adds extensive test coverage in `t/t5550-http-fetch-dumb.sh`, exercising resumed transfers, EOF ranges, overlapping 200 and 206 responses, unlinking the staging path while `index-pack` holds its descriptor, and a deterministic overlapping-download test using a custom Perl server with a 60-second timeout, FIFO waiter notification, and reliable server process cleanup.

No new symbols are introduced, and the on-disk format remains unchanged. The patch is narrowly scoped to the packfile URI and dumb HTTP download paths, with no impact on other HTTP fetch behaviors. The v4 reroll includes only test robustness improvements since v3, addressing the test hang reported by Junio C Hamano. The series is rebased onto current `master` and ready for review; if the test suite passes cleanly, this patch is likely to progress to `next` soon.
