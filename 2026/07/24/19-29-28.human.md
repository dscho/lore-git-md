This is the final v22 of Harald Nordgren’s `git branch --delete-merged` series, now **implementation-complete and ready for merging**. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including per-branch opt-out, `--dry-run` preview, and **order-independent stacked-branch protection**.

The only change in v22 is a mechanical adjustment to loop variables (using `int i` instead of `size_t i` where appropriate) to avoid unnecessary typecasts. This has no functional impact and is purely a code hygiene improvement. The series remains **unblocked for merging** with no known issues, and Junio C Hamano has explicitly signaled it is ready for inclusion.

The core functionality is unchanged from v21: `--delete-merged` deletes local branches merged into their upstream (matching one or more `--delete-merged` arguments) while preserving branches used as upstreams for unmerged branches. The command supports glob patterns for both upstreams and local branches, and includes multiple safety mechanisms: it skips checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`. The **order-independent stacked-branch protection** ensures consistent results regardless of ref iteration order by collecting all protected branches before mutating the deletion set.

The series is **well-motivated** (addressing a real workflow pain point for users with many merged topic branches) and **thoroughly tested**, with integration tests covering all safety checks, edge cases (e.g., self-referential upstreams, missing upstreams), and the new order-independent protection logic. The implementation is **low-risk**: patches 2-4/7 refactor the deletion API to use flags instead of booleans, while patches 5-7/7 introduce the new `--delete-merged` command, per-branch opt-out, and `--dry-run` support. The design aligns with Git’s API consistency expectations, and the documentation is clear and complete.

The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which Harald Nordgren has committed to implementing after the series lands. This is not a blocker for merging. The series touches `builtin/branch.c`, `ref-filter.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.txt`, and `t/t3200-branch.sh`, and is **ready for inclusion in `next`**.
