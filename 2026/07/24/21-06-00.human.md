This is the second patch in Taylor Blau’s five-part bugfix series hardening Git’s packfile subsystem against duplicate object entries. It tackles delta cycles—situations where a chain of delta objects loops back on itself—by teaching Git to recover through alternate representations of the same object when the primary lookup hits a cycle.

The patch adds a depth-first search that treats each object ID as a node and tries every physical entry in the pack’s `.idx` run for that OID. A bitmap prevents revisiting the same OID group, and OFS_DELTA bases are translated back to OIDs so the search can continue across duplicate copies. Once a full object is found, the exact offsets along the acyclic path are recorded so `unpack_entry()` can replay them. Ordinary lookups remain unchanged; the recovery machinery activates only after a proven cycle is detected.

Test coverage is thorough: the updated `t5309-pack-delta-cycles.sh` now verifies both type and content after indexing, covering a root-level full duplicate, a mixed REF/OFS cycle, and a three-object cycle that requires backtracking before taking an alternate path. The fixtures are hash-independent, so the same tests run under SHA-1 and SHA-256.

The implementation is careful to confine the duplicate-run scans and visited bitmap to the recovery phase, minimizing performance impact on normal operations. The commit message and code comments clearly explain the algorithm and edge cases, making the patch easy to follow despite its complexity. No new user-facing behavior is introduced; this is purely an internal robustness fix.
