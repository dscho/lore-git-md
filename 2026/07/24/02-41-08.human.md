This is a macOS-specific bugfix for the fsmonitor daemon, addressing a performance regression that caused excessive timeouts and lstat() calls during `git status` on loaded systems. The patch has received its first review from Koji Nakamaru, who calls it "carefully designed" and notes that it should be sufficient to mitigate the issue. Nakamaru suggests the commit message would be even stronger with additional benchmark results showing timeout reduction, but does not identify any technical flaws or request changes to the implementation.

The patch itself remains unchanged from the original submission. It adds an asynchronous flush of pending FSEvents notifications on macOS immediately after cookie creation, while leaving Linux and Windows backends unaffected. The locking considerations (avoiding blocking while holding `main_lock`) are preserved, and the one-second timeout behavior is unchanged. No new test files were added, but the original commit message included concrete performance data from an M4 Max Mac with a 1M-entry index.
