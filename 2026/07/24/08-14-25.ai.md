This is the third and final patch in Ted Nyman’s v4 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI downloads. It makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, ensuring robust handling when a `.keep` file already exists.

The patch addresses a subtle edge case: when `index-pack` encounters a pre-existing `.keep` file, it reports `"pack<TAB><hash>"` instead of `"keep<TAB><hash>"`. The current code only accepts `"keep"`, causing the fetch to fail. Ted’s change validates the reported pack hash against the advertised hash and only registers a new `.keep` lockfile if the current process created it (tracked via a `created_keep` flag). The implementation adopts Jeff King’s suggested `strbuf` refactor for clarity, replacing the fixed-size `packname` buffer with a more flexible `packhash` array.

Test coverage is thorough: a new regression test in `t/t5702-protocol-v2.sh` exercises a packfile URI fetch with a pre-existing `.keep` file, verifying that the pack and index files are created, the `.keep` file is preserved unchanged, and the excluded blob is correctly fetched. The test is deterministic and integrates cleanly with the existing protocol-v2 test suite.

The patch is narrowly scoped to the packfile URI code path in `fetch-pack.c` and introduces no new symbols or on-disk format changes. It complements the earlier patches in the series by ensuring that concurrent downloads and pre-existing `.keep` files do not disrupt the fetch process. With this change, the series is now complete and ready for integration, assuming the test suite passes cleanly.
