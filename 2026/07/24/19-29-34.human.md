This is the sixth patch in Harald Nordgren’s **v22 `git branch --delete-merged` series**, which is now **implementation-complete, unblocked, and ready for merging**. This patch adds the **`branch.<name>.deleteMerged` config key**, allowing users to opt specific branches out of automated cleanup while still permitting explicit deletion via `git branch -d`.

The feature addresses a real workflow pain point: topic branches that are actively developed after an early round has been merged upstream. The opt-out is checked during candidate filtering in `delete_merged_branches()`, and unless `--quiet` is given, the command prints a skip message (e.g., "Skipping 'kept' (branch.kept.deleteMerged is false)") so users understand why their branch was preserved. The implementation is **minimal and targeted**, touching only `builtin/branch.c`, `Documentation/config/branch.adoc`, `Documentation/git-branch.adoc`, and `t/t3200-branch.sh`. The test suite verifies opt-out behavior, skip messages, and explicit deletion via `git branch -d`, using `git for-each-ref` for branch state verification via the `check_branches` helper.

This patch is **well-crafted and uncontroversial**, with no known issues. Phillip Wood’s **surface-level review** suggested only a mechanical test improvement (using `for-each-ref` instead of `rev-parse` for branch state verification), which has been applied. The feature complements the series’ other safety mechanisms (checked-out branches, missing upstreams, push divergence, order-independent stacked-branch protection) and is **ready for merging** alongside the rest of the series.
