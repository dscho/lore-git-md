This is patch 4/7 of Harald Nordgren’s `git branch --delete-merged` series, now in its 21st iteration and ready for merging. The patch prepares the `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, which prevents the function from falling back to `HEAD` when checking whether a branch is merged into its upstream.

The change is minimal and targeted: it modifies `delete_branches()` to skip the `HEAD` fallback when the new flag is set, and updates `branch_merged()` to suppress the "gentle reminder" about `HEAD` fallback when the caller explicitly opts out. This ensures that `--delete-merged` only deletes branches that are merged into their upstream, without considering `HEAD` as a fallback. The patch is purely mechanical and introduces no behavioral changes for existing callers, as the new flag is not used outside of the `--delete-merged` subcommand (which is introduced in a later patch).

The implementation is low-risk and well-tested, with the flag being checked at both the commit-checking and deletion stages. The patch touches only `builtin/branch.c` and is part of the broader flags-based API refactoring (patches 2-4/7) that replaces boolean arguments with an `unsigned int flags` parameter. This refactoring has been reviewed and is now complete, with all local boolean caching eliminated to ensure flags remain the single source of truth.

The patch is a necessary prerequisite for the `--delete-merged` subcommand, which relies on the new flag to avoid deleting branches that are not merged into their upstream, even if they are merged into `HEAD`. The series as a whole is unblocked and ready for merging, with this patch addressing a key design requirement for the new subcommand.
