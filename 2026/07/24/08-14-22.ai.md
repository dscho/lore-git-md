This is the cover letter for the v4 reroll of Ted Nyman’s bugfix series addressing race conditions in Git’s HTTP transport during concurrent packfile URI and dumb HTTP downloads. The series remains a three-patch set, with no changes to the production code since v3—only test robustness improvements.

The core issue is unchanged: when multiple Git processes fetch the same packfile into a single object database, they can corrupt the temporary pack file or cause resume requests to fail at EOF. The v4 series continues to use deterministic staging paths opened in read-write mode (without append), ensuring overlapping responses write identical bytes at identical offsets. This preserves resumable downloads for both packfile URIs and dumb HTTP while avoiding cross-process coordination.

The key updates in v4 are test-focused. The overlapping-download test server now includes a 60-second timeout to prevent hangs, notifies FIFO waiters on failure, and tracks the server process for reliable cleanup. The test also waits for the second downloader first, ensuring an early failure cannot leave the server waiting indefinitely. Additionally, the HTTP 416 trace matching now accounts for both older and current libcurl output formats, avoiding false failures.

The series is well-motivated, with thorough test coverage for resumption, EOF ranges, overlapping responses, unlinking the staging path while `index-pack` holds its descriptor, and pre-existing `.keep` files. The MinGW-specific sharing behavior is documented and handled robustly. No open technical questions remain from prior reviews, and the test hang reported in v3 appears to be resolved by these changes.

The patches touch `http.c`, `fetch-pack.c`, and their documentation, with new regression tests in `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`. The implementation is narrowly scoped to the packfile URI and dumb HTTP download paths, with no impact on other HTTP fetch behaviors or on-disk formats. The series is rebased onto current `master` and ready for review.

If the test suite now passes cleanly, this series is likely to progress to `next` soon. The changes are uncontroversial and address a real-world race condition with a clean, minimal solution.
