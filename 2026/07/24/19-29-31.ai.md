This is the third patch in Harald Nordgren’s **v22 `git branch --delete-merged` series**, which is now **unblocked and ready for merging**. This patch is a **refactoring** that adds a new flag, `DELETE_BRANCH_SKIP_UNMERGED`, to enable bulk callers (like the upcoming `--delete-merged` subcommand) to silently skip unmerged branches instead of failing with the "use `git branch -D`" advice. The change is **minimal and targeted**, touching only `builtin/branch.c` to modify `check_branch_commit()` and `delete_branches()` so they suppress the error and advice when the flag is set. Existing callers (e.g., `git branch -d`) are unaffected, as the flag is not set by default.

The patch is part of the **flags-based API refactoring** introduced in patches 2-4/7 to replace boolean arguments with an `unsigned int flags` parameter. Here, `DELETE_BRANCH_SKIP_UNMERGED` (bit `1 << 2`) is added to the `enum delete_branch_flags`, and the flag is checked at both the commit-checking (`check_branch_commit()`) and deletion (`delete_branches()`) stages. When set, the functions skip unmerged branches without triggering a failure, which is critical for the `--delete-merged` subcommand’s bulk operation. The implementation is **low-risk**: it introduces no behavioral changes for existing callers, and the flag is only used by the new `--delete-merged` logic in later patches.
