This is the third patch in Patrick Steinhardt’s five-patch series making on-disk object database (ODB) structures pluggable. It refactors the repository initialization sequence to defer ODB creation until after the ref database is set up, preparing for the next patch where backend-specific directory creation will be introduced.

The patch splits the current `create_object_directory()` function into two steps: a new `get_object_directories()` helper that captures the environment variables for the object and alternate directories, and a renamed `create_object_database()` that now both instantiates the ODB (`odb_new()`) and creates the on-disk directories. The key change is that `apply_repository_format()` now accepts a new flag `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION`; when set, it skips ODB creation entirely, leaving the repository in a partially-initialized state. The caller (`init_db()`) is updated to pass this flag and then call `create_object_database()` later, after the ref database is created.

Files touched are `setup.c` and `setup.h`. The diff is mechanical: it moves code around, adds the new flag, and renames one function, but does not change any on-disk formats or user-visible behavior. This is pure infrastructure work, enabling the next patch to inject backend-specific directory creation logic. The patch is well-scoped and clearly motivated by the series’ overall goal of making ODB backends pluggable.
