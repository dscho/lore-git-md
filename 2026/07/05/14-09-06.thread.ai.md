Thread identity: patch series introducing a `-x` flag to `git rebase -i`'s `pick`, `reword`, and `edit` commands to append "(cherry picked from commit ...)" lines, mirroring `git cherry-pick -x` behavior. Series version: v1. Originating author: Trevor Gross.
Core problem or goal: users performing cherry-picks during interactive rebases lack a native way to record commit origin, forcing them to use `exec git cherry-pick -x` which disrupts the rebase flow. The patch integrates this functionality directly into rebase todo commands, reusing existing `TODO_RECORD_ORIGIN` logic from `git cherry-pick`. Junio C Hamano has raised a fundamental design objection: `git rebase` and `git cherry-pick` serve different workflows (moving vs. duplicating history), and the `-x` flag’s purpose (recording origin) is undermined when the original commits are discarded, making the appended line potentially misleading.
Current status: v1 posted; under review with substantive feedback from Junio C Hamano. No merge status recorded. The thread’s future depends on whether the author can reconcile the feature with rebase’s core semantics or propose an alternative design.
