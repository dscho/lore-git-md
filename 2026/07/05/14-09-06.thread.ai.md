Thread identity: patch series introducing a `-x` flag to `git rebase -i`'s `pick`, `reword`, and `edit` commands to append "(cherry picked from commit ...)" lines, mirroring `git cherry-pick -x` behavior. Series version: v1. Originating author: Trevor Gross.
Core problem or goal: users performing cherry-picks during interactive rebases lack a native way to record commit origin, forcing them to use `exec git cherry-pick -x` which disrupts the rebase flow. The patch integrates this functionality directly into rebase todo commands, reusing existing `TODO_RECORD_ORIGIN` logic from `git cherry-pick`.
Current status: v1 posted; under review with substantive feedback from Junio C Hamano. No merge status recorded.
Key technical details:
- Files touched: `rebase-interactive.c`, `sequencer.c`, `t/t3404-rebase-interactive.sh`.
- New flag: `-x` for `pick`, `reword`, and `edit` commands in rebase todo list, parsed as an argument to the command (e.g., `pick 123456 -x`).
- Behavior: appends "(cherry picked from commit ...)" to commit messages, reusing `TODO_RECORD_ORIGIN` logic. Fast-forwards skip the message (documented difference from `git cherry-pick -x`).
- Edge cases: struct initialization (`struct todo_item item = { 0 }`), error handling for malformed todo lines (e.g., `pick -xabcdef 123456`), and parsing ambiguity between `-x` as a flag vs. argument.
- Test coverage: verifies flag works with all three commands and checks output format.
