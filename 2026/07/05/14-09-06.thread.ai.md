Trevor Gross’s `git rebase -i -x` patch series (v1) introduces a `-x` flag for `pick`, `reword`, and `edit` commands to append "(cherry picked from commit ...)" lines, mirroring `git cherry-pick -x`. The series remains under active review, with **high-weight substantive objections** from Junio C Hamano, Jeff King (Peff), and Phillip Wood challenging the feature’s conceptual alignment with `git rebase` (moving vs. duplicating history). No merge status recorded; the thread’s future depends on resolving these design concerns or pivoting to an alternative approach.

**Core problem or goal**: Users performing cherry-picks during interactive rebases lack a native way to record commit origin, forcing them to use `exec git cherry-pick -x`, which disrupts the rebase flow. The patch integrates this functionality directly into rebase todo commands, reusing `TODO_RECORD_ORIGIN` logic from `git cherry-pick`. However, the fundamental tension between `rebase` (moving history) and `cherry-pick` (duplicating history) remains unresolved, with Peff and Phillip proposing an interactive `cherry-pick -i` mode as a more semantically coherent solution. Phillip’s review frames this as a *requirements* problem, asking Trevor to justify why `rebase` is the right tool for this workflow rather than extending `cherry-pick`.

**Current status**: v1 posted; under review. The series faces three major design objections:
1. **Junio’s objection**: The `-x` flag’s purpose is undermined in a rebase workflow where original commits are discarded, making the annotation’s utility questionable.
2. **Peff’s objection**: The feature misaligns with `rebase`’s core semantics and could be better addressed by extending `cherry-pick` with an interactive mode (`-i`), leveraging its existing sequencer backend. Peff’s experiment confirms that `cherry-pick` already generates a todo file (`.git/sequencer/todo`), suggesting minimal work to add interactivity.
3. **Phillip’s objection**: Endorses Peff’s critique and presses Trevor to justify the rebase-centric approach, noting that `cherry-pick -i` would avoid inconsistencies between per-commit `-x` flags (Trevor’s patch) and the global `record-origin` option (used by `cherry-pick -x`). Phillip also highlights edge cases (e.g., `edit -x` followed by `fixup`) where the "cherry picked from" trailer’s meaning becomes ambiguous.

**Key technical details**:
- Files touched: `rebase-interactive.c`, `sequencer.c`, `t/t3404-rebase-interactive.sh`.
- New flag: `-x` for `pick`, `reword`, and `edit` commands in rebase todo list, parsed as an argument (e.g., `pick 123456 -x`).
- Behavior: Appends "(cherry picked from commit ...)" to commit messages, reusing `TODO_RECORD_ORIGIN` logic. Fast-forwards skip the message (documented difference from `git cherry-pick -x`).
- Edge cases: Struct initialization (`struct todo_item item = { 0 }`) fixes a latent bug in `do_pick_commit()`; error handling for malformed todo lines (e.g., `pick -xabcdef 123456`) remains unresolved; parsing ambiguity between `-x` as a flag vs. argument persists. Phillip notes that the per-commit `-x` flag approach would require awkward conditional logic (`if (opt->record_origin || (item->flags & TODO_RECORD_ORIGIN))`) to check for trailers.
- Test coverage: Verifies flag works with all three commands and checks output format.
- **New insight**: Peff’s review reveals that `cherry-pick` already uses the sequencer backend and generates a todo file, implying an interactive mode could be implemented with minimal changes. Phillip confirms this and suggests harmonizing the global `record-origin` option with per-commit `-x` flags by having `cherry-pick -x` automatically add `-x` to each todo line. Behavioral inconsistency noted: `cherry-pick -x` applies globally via `record-origin = true`, while Trevor’s patch allows per-command `-x` flags.

**Open questions and loose ends**:
