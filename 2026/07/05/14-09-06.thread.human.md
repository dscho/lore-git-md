This thread introduces a new `-x` flag for `git rebase -i`'s `pick`, `reword`, and `edit` commands, bringing them in line with `git cherry-pick -x` by appending a "(cherry picked from commit ...)" trailer to commit messages. The feature is motivated by a common workflow pain point: users often cherry-pick commits during interactive rebases but previously had to resort to `exec git cherry-pick -x`, which breaks the rebase flow. The implementation is clean, reusing existing cherry-pick logic and adding thorough test coverage in `t/t3404-rebase-interactive.sh`.

The patch touches `rebase-interactive.c` and `sequencer.c` and includes documentation updates. It handles edge cases like fast-forwards (where no rewrite occurs, so no trailer is added) and maintains consistency with `git cherry-pick -x` while avoiding unnecessary divergence.
