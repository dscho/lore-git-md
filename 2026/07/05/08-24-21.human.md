This is the fourth patch in Johannes Schindelin’s 12-patch v2 series that plugs resource leaks and error-path bugs flagged by Coverity. The series as a whole is already slated for merging by Junio, and this patch is a straightforward fix to the `start_command()` function in `run-command.c`.

The bug: when `start_command()` fails to set up a pipe partway through, it tries to roll back by closing any file descriptors it has already opened. The code tested `if (cmd->in)` or `if (cmd->out)` before calling `close()`, but the `CHILD_PROCESS_INIT` default of -1 (meaning “no descriptor”) is non-zero, so the test passed and `close(-1)` was called on error paths. This is undefined behavior and triggers sanitizer warnings.

The fix: replace the three `if (cmd->in)` / `if (cmd->out)` tests with `if (cmd->in > 0)` / `if (cmd->out > 0)`, which rejects both the -1 sentinel and 0 (the parent’s own standard streams). The idiom is already used correctly on the stdin-pipe failure branch a few lines above. The change is mechanical, touches only three lines, and carries no risk of regression. Coverity flagged this as CID 1049722.
