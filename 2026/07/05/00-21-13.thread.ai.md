Thread identity: build system regression report; thread type: bug report; originating author: Kurt Mielke.

Core problem or goal: Git 2.55.0 fails to build from source on AlmaLinux 10 due to an unconditional requirement for `cargo` (Rust toolchain), introduced in this release. The failure occurs at `CARGO target/release/libgitcore.a` (Makefile line 3021, error code 127) and is bypassed by setting `NO_RUST=1`. The central question is whether this Rust requirement is intentional for 2.55.0 or an accidental build system regression.

Current status: under investigation; no maintainer response yet. Git 2.55.0 is the first release to default to building with Rust enabled, but Rust components remain optional via `NO_RUST=1`. Rust is planned to become a *requirement* for Git 3.0, though the timeline may be adjusted for platforms lacking Rust support. AlmaLinux does provide Rust packages, but the build system does not auto-detect their availability.

Key technical details: build system (Makefile), Rust toolchain (`cargo`), `NO_RUST=1` as a supported workaround, no new symbols or on-disk format changes, no test coverage implications reported. The failure is linked to the ongoing Rustification effort (Ezekiel Newren).

Open questions and loose ends: whether the default change to enable Rust by default was intentional, whether the build system should auto-detect Rust toolchain availability (e.g., via `which cargo` or similar), whether `NO_RUST=1` is a supported long-term configuration or merely a temporary escape hatch, and what platforms are expected to provide Rust tooling by default. The discussion remains unresolved, with no maintainer input on the regression or the intended build system behavior.
