Git 2.55.0 introduced a build system regression that breaks source builds on AlmaLinux 10 (and likely other platforms) by unconditionally requiring the Rust toolchain (`cargo`), which was not needed in Git 2.54.0. The build fails at `CARGO target/release/libgitcore.a` with error code 127, though users can bypass it by setting `NO_RUST=1` during compilation. The issue stems from the ongoing Rustification effort, but it’s unclear whether the Rust requirement was intended to become mandatory in this release or if this is an accidental regression.

D. Ben Knoble, a build system contributor, clarified that Git 2.55.0 is the first release to *default* to building with Rust enabled, though the components remain optional (the `NO_RUST=1` workaround is valid). He noted that Rust will become a *requirement* for Git 3.0, but the timeline may shift to accommodate platforms without Rust support. While AlmaLinux does provide Rust packages, the default change still breaks builds for users who haven’t installed them. The thread remains unresolved: no maintainer has weighed in on whether the default change was premature, whether the build system should auto-detect Rust toolchain availability, or whether `NO_RUST=1` is a supported long-term configuration. The report’s author, Kurt Mielke, has not yet responded to Ben’s clarification.
