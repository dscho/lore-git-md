This thread reports a build regression in Git 2.55.0: the build process now fails on systems without Rust tooling (`cargo`), whereas Git 2.54.0 built successfully without it. Kurt Mielke, the reporter, encountered the failure on AlmaLinux 10 and worked around it by setting `NO_RUST=1` during the build. The failure occurs at the `CARGO target/release/libgitcore.a` step, suggesting the build system now assumes Rust is available by default—likely tied to the ongoing Rustification effort, though the email doesn’t confirm whether this is intentional.

The report is light on details: no bisect was performed, no specific commit is identified, and the motivation for the Rust requirement isn’t discussed. The error (exit code 127, "command not found") and the absence of any `rus*` commands on the system confirm the root cause. While the workaround (`NO_RUST=1`) restores functionality, the thread raises a broader question: should Rust be a *default* dependency for building Git, or should the build system gracefully handle its absence? This touches on the long-standing debate about Rustification, particularly concerns from contributors like Randall S. Becker about platform support (e.g., NonStop). No responses or maintainer input have appeared yet, so the thread’s outcome remains open.
