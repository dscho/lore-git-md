This thread began when Kurt Mielke reported that Git 2.55.0 fails to build from source on AlmaLinux 10 due to an unconditional requirement for `cargo` (the Rust toolchain), which was introduced in this release. The build breaks at `CARGO target/release/libgitcore.a` unless `NO_RUST=1` is set, raising questions about whether this change was intentional or a regression. D. Ben Knoble clarified that Git 2.55.0 is the first release to default to building with Rust enabled, though Rust remains optional via `NO_RUST=1`, and that Rust will become a *requirement* for Git 3.0—though the timeline may shift for platforms lacking Rust support.

The maintainer, Junio C Hamano, has now posted a documentation patch to correct the Git 2.55.0 release notes, which had previously described the Rust requirement as a future change rather than one already in effect. The patch clarifies that Rust components are now enabled by default in 2.55.0 (with `NO_RUST=1` as an opt-out) and will become mandatory in a later version. This confirms that the default change was intentional, though the broader questions about build system behavior—such as whether it should auto-detect Rust toolchain availability or whether `NO_RUST=1` is a supported long-term configuration—remain unresolved. The thread has yet to receive input from the Rustification effort’s primary driver, Ezekiel Newren, or from platform maintainers like Randall S. Becker, who have raised concerns about Rust support on niche platforms. For now, the workaround (`NO_RUST=1`) remains the only confirmed solution for affected users.
