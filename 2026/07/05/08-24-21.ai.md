This is the fourth patch in Johannes Schindelin’s v2 series of Coverity-driven leak and error-path fixes. It targets `run-command.c` and plugs a latent bug in `start_command()` where the error-path rollback could call `close(-1)` if the caller set `cmd->no_stdin` or `cmd->no_stdout` without supplying a real file descriptor.

The fix is mechanical: replace the three `if (cmd->in)` / `if (cmd->out)` guards with `if (cmd->in > 0)` / `if (cmd->out > 0)` so that the -1 sentinel (CHILD_PROCESS_INIT) and 0 (the parent’s own standard streams) are both rejected. The change is confined to the error-path rollback logic and does not affect the normal code flow. Coverity flagged this as CID 1049722; the patch carries no new tests because the bug is latent and the fix is covered by existing test coverage of `start_command()`.
