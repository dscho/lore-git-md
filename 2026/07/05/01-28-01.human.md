This is the maintainer's merge signal for Patrick Steinhardt's six-patch ODB refactoring series. Junio C Hamano has queued the v2 series—renamed to avoid ambiguity (`struct object_info_source` → `struct odb_source_info`, `sourcep` → `source_infop`)—after its conceptual approval and resolution of all review feedback. The series is now in `next` and on track for the next release.

The patches replace `struct object_info`'s `whence` field with an opt-in `source_infop` pointer, enabling future multi-source object resolution and pluggable ODB backends. No behavior changes were introduced, and the documentation patch (6/6) clarifies the purpose and ownership of the new fields. The only lingering concern—a readability trade-off in an implicit pointer upcast—was acknowledged but not deemed blocking.

If you're following the ODB abstraction effort, this is a foundational change that paves the way for pluggable backends. The series is self-contained and ready to merge.
