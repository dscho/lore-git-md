This is the ninth patch in the v2 series of Coverity-driven leak fixes, targeting the `imap-send` subsystem. The patch plugs a memory leak in `curl_append_msgs_to_imap()` where the `msgbuf.buf` strbuf—used to accumulate message data across loop iterations—was never released before the function returned. The fix adds a single line (`strbuf_release(&msgbuf.buf)`) alongside the existing libcurl cleanup calls, ensuring the buffer is freed unconditionally. Coverity flagged this as CID 1671507 ("Resource leak").

The change is mechanical and well-scoped, touching only `imap-send.c` with no user-visible behavior impact. The leak was straightforward: the strbuf was allocated and grown during the upload loop but lacked a corresponding release on function exit. The fix aligns with the series' broader goal of addressing Coverity-identified resource leaks without altering functionality. Like the other patches in this series, it carries minimal regression risk and is suitable for early-cycle merging. The patch has not yet received explicit review feedback in the thread, but its simplicity and consistency with the series' other fixes suggest it will likely be uncontroversial.
