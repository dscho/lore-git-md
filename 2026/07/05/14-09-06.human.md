This is a feature patch for `git rebase -i`. Trevor Gross proposes adding a `-x` flag to the `pick`, `reword`, and `edit` commands in interactive rebase, mirroring the behavior of `git cherry-pick -x`. When used, it appends a "(cherry picked from commit ...)" line to the commit message, making it easier to track the origin of rebased commits without breaking the rebase flow.

The patch touches the sequencer (`sequencer.c`), interactive rebase logic (`rebase-interactive.c`), and documentation (`git-rebase.adoc`). It also adds a thorough test case in `t3404-rebase-interactive.sh` that verifies the new flag works with all three supported commands and handles fast-forwards correctly (where the message is *not* added, unlike `cherry-pick -x`).

The implementation is clean: it reuses the existing `TODO_RECORD_ORIGIN` flag and the commit-message-amending logic from `cherry-pick`, so there’s no new code path for writing the trailer. The help text is updated to document the new option, and the diff shows the flag is parsed and persisted in the todo list.

This is a well-motivated, small feature that fills a clear gap in the interactive rebase workflow. The commit message explains the use case, the code is straightforward, and the test coverage looks solid. It’s the kind of patch that could land quickly if reviewers agree the behavior is desirable.
