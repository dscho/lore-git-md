This is the eleventh patch in Johannes Schindelin’s twelve-patch v2 series that plugs resource leaks and error-path bugs flagged by Coverity in Git’s codebase. The series as a whole has strong maintainer approval and is slated for merging.

This specific patch fixes a memory leak in the `git fsmonitor--daemon` startup sequence. The daemon allocates a `current_token_data` structure before any of the subordinate setup steps (alias resolution, listener/health-thread constructors, or asynchronous IPC server initialization). If any of those steps fail, the code jumps straight to the `done:` cleanup block without freeing the token data, leaking the allocation. On the successful path the listener thread takes ownership and clears the pointer, so the leak only occurs on early failures.

The fix is a two-line addition at the top of the `done:` block: it calls `fsmonitor_free_token_data()` and then sets the pointer to NULL. The helper is NULL-safe and asserts that the client reference count is zero, which holds trivially because the IPC server has not yet begun accepting clients when these failures occur. The change is mechanical, well-scoped, and covered by existing tests. No user-visible behavior changes.
