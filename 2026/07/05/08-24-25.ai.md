This is the eighth patch in Johannes Schindelin’s v2 series of Coverity-driven leak fixes. It plugs four memory leaks in the `git worktree add` subcommand that occur when `run_command()` fails while creating a new branch.

The patch touches `builtin/worktree.c` and redirects the early error return through the existing `cleanup:` label so that four allocations—`path`, `opt_track`, `branch_to_free`, and `new_branch_to_free`—are freed before the function exits. The change is mechanical: the `return -1` is replaced with `ret = -1; goto cleanup`, and the `cleanup:` block is moved to cover the entire function. No new symbols are introduced, and the on-disk format is unaffected.

The fix is well-scoped and addresses a real leak identified by Coverity. It carries no user-visible behavior change and is covered by existing tests. The patch is part of a series that Junio has already stated he will queue for merging, and it carries Reviewed-by tags from Patrick Steinhardt and Eric Sunshine on earlier versions. The v2 revision consolidates cleanup into a single exit path, eliminating a fragility risk noted in review.
