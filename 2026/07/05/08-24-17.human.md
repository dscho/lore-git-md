This is a cleanup series from Johannes Schindelin addressing resource leaks and error-path bugs identified by Coverity in Git's codebase. The series is now at **v2** (12 patches, down from 13 in v1) and targets memory, file descriptor, and process handle leaks, as well as improper cleanup on error paths. No user-visible behavior changes are introduced—this is purely about internal correctness.

The patches touch a broad range of subsystems: loose-object handling (`loose.c`), the run-command API (`run-command.c`), diff machinery (`line-log.c`), directory traversal (`dir.c`), submodules (`submodule.c`), worktree creation (`builtin/worktree.c`), IMAP sending (`imap-send.c`), reftable (`reftable/table.c`), fsmonitor daemon (`builtin/fsmonitor--daemon.c`), and Windows-specific code (`compat/mingw.c`). Each patch is small and focused, typically adding a single `free`, `close`, or `release` call on an error path or restructuring control flow to ensure resources are properly owned and released.

Key improvements since v1 include:
- **Patch 1/12**: Replaced unsafe `errno`-based error detection in `load_one_loose_object_map()` with an explicit `ferror(fp)` check, addressing a correctness concern raised by Junio C Hamano.
- **Patch 7/12**: Consolidated cleanup in `get_superproject_working_tree()` into a single exit path, eliminating a fragility risk (two separate `free(cwd)` calls) and plugging a latent leak of `one_up`’s backing buffer.
- **Patch 5/13 (v1)**: Withdrawn, as the issue was already fixed by an earlier commit.
- **Commit messages**: Improved clarity by using backticks for function names and reflowing text.

The series has strong maintainer approval: Junio C Hamano stated he will queue it for merging ("looking good"), and several patches carry `Reviewed-by` tags from Patrick Steinhardt and Jeff King (Peff). Peff independently reproduced the leak fixed in patch 5/12 under `GIT_TEST_COMMIT_GRAPH_CHANGED_PATHS=1`, confirming its real-world impact. The fixes are mechanical and unlikely to introduce regressions, making this a low-risk, high-value cleanup effort.

One orthogonal issue remains: an uninitialized-slot bug in `read_one_dir()` that could cause `free_untracked()` to dereference garbage pointers. Johannes plans to address this separately, keeping the current series focused on Coverity’s leak reports. This is a well-scoped, uncontroversial series that looks ready for merging.
