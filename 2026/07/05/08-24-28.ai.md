This is the eleventh patch in Johannes Schindelin’s v2 twelve-patch series that plugs resource leaks and error-path bugs identified by Coverity in Git’s codebase. The patch targets the fsmonitor daemon (`builtin/fsmonitor--daemon.c`) and fixes a memory leak of `state.current_token_data` on early daemon-startup failures.

The leak occurs in `fsmonitor_run_daemon()`: the function allocates `state.current_token_data` before any subordinate setup step (alias resolution, listener/health constructors, asynchronous IPC server initialization) that may fail. On the successful path, the listener thread takes ownership and clears the field during teardown, so the `done:` cleanup block sees a NULL pointer. On early-error paths, however, control jumps straight to `done:` with the freshly allocated token data still referenced, and it is never freed. The fix adds two lines at the top of the `done:` block: `fsmonitor_free_token_data(state.current_token_data)` and `state.current_token_data = NULL`. The success path remains a no-op (the pointer is already NULL there); the error paths now drop the otherwise-leaked allocation. `fsmonitor_free_token_data()` is NULL-safe and asserts `client_ref_count == 0`, which holds trivially because the IPC server has not yet begun accepting clients when these failures occur.

The patch is mechanical, well-scoped, and carries no user-visible behavior changes. It is part of a series that Junio C Hamano has stated he will queue for merging, indicating strong maintainer approval. The fix is covered by existing tests and does not introduce new test coverage. No open questions or loose ends remain for this patch.
