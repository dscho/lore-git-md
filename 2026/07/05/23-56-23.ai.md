This is a build system discussion following up on a reported regression in Git 2.55.0. D. Ben Knoble, a build system contributor, replies to Kurt Mielke’s report that Git 2.55.0 now unconditionally requires `cargo` (Rust toolchain) to build, breaking the build on AlmaLinux 10 where Rust is not installed by default.

Ben clarifies that Git 2.55.0 is the first release to default to building with Rust enabled, but the Rust components remain optional (the `NO_RUST=1` workaround is valid). He notes that Rust is planned to become a *requirement* for Git 3.0, though the timeline may be adjusted for platforms lacking Rust support. He also points out that AlmaLinux does provide Rust packages, implying the user could install them if they want to build with Rust support.

The email does not resolve whether the default change was intentional or whether the build system should auto-detect Rust toolchain availability. It also does not address whether `NO_RUST=1` is a supported long-term configuration or merely a temporary escape hatch. The tone is factual and neutral, offering no opinion on whether the default change was premature.

Key technical details carried forward: the Makefile now defaults to building Rust components, the failure occurs at `CARGO target/release/libgitcore.a`, and `NO_RUST=1` bypasses the Rust build step. The discussion remains open, with no maintainer response yet.
