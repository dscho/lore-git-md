This is a **substantive review** from Junio C Hamano on Trevor Gross’s patch introducing a `-x` flag to `git rebase -i`’s `pick`, `reword`, and `edit` commands. Junio raises a fundamental design concern about the conceptual mismatch between `rebase` and `cherry-pick -x`.

The core issue is philosophical: `rebase` is designed to *replace* the original history (including copying notes), while `cherry-pick -x` is meant to *duplicate* history in a new context, preserving the original commit for reference. Junio argues that appending "(cherry picked from commit ...)" during a rebase is inherently contradictory, because the rebase’s purpose is to *erase* the original commit—making the cherry-pick reference meaningless. He questions whether `exec git cherry-pick -x` even works as claimed, hinting at deeper behavioral differences between rebase’s `pick` and standalone cherry-picks.

This isn’t a nitpick about code style or edge cases; it’s a challenge to the patch’s premise. Junio’s feedback suggests the feature may need rethinking or at least a much clearer justification for why the conceptual tension is acceptable. The review is likely to spark further discussion about whether the feature belongs in `rebase` at all, or if users should continue using `exec` workarounds despite their clunkiness. Trevor will need to address this head-on in the next revision.
