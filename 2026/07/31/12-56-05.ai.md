This is the final patch in Junio C Hamano’s `git add --resolved` series (v3 4/4), introducing the user-facing command-line option. The patch completes the feature by implementing the core logic in `builtin/add.c`, adding a new helper `has_conflict_markers()` in `merge-ll.c`, and including a comprehensive test script (`t/t2207-add-resolved.sh`).

The `--resolved` option stages only unmerged paths where conflict markers have been removed, addressing a workflow pain point for maintainers who resolve conflicts while carrying unrelated local changes. The implementation scans the index for unmerged paths, checks each for remaining conflict markers (with an early exit for binary files), and stages resolved paths or aborts with an error listing unresolved ones. The patch also updates the documentation (`git-add.adoc`) to describe the new option and its incompatibility with `-u` and `-A`.

The series is technically complete and addresses all prior review feedback, including a portability fix in v3 (replacing `git checkout master` with `git checkout @{-1}`). The remaining open question is purely conceptual: whether `--resolved` should remain a monolithic, workflow-oriented operation (Junio’s position) or be split into a more general `--unmerged` selector with explicit policy flags (Michael Montalbo’s proposal). This patch does not resolve that debate but provides the implementation under the current design.

Key technical details for follow-up discussion include the `has_conflict_markers()` helper, the stricter conflict-marker rule (requiring a space after `<<<<<<<` and `>>>>>>>`), and the test script’s coverage of edge cases (partially resolved conflicts, pathspecs, deletions, and option incompatibility). The patch is well-tested and ready for review on its technical merits, though the final command-line syntax may still evolve based on the ongoing design discussion.
