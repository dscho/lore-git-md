This is a CI/build system patch. Harald Nordgren proposes a change to Git's GitHub Actions workflow to reduce CI resource usage for pull requests.

The patch modifies `.github/workflows/main.yml` to group CI workflow runs by pull request number rather than commit hash. When a new push is made to a pull request, any in-progress CI runs for that same PR are canceled, ensuring only the latest revision consumes runner capacity. Push events (not associated with pull requests) continue to be grouped by commit hash, preserving the existing "skip-if-redundant" optimization.

The motivation is straightforward: GitHub's CI groups runs by commit hash by default, so each push to a PR starts a new workflow run without canceling the previous one. This wastes resources when contributors push multiple revisions in quick succession. The change is small (11 insertions, 9 deletions) and targets only the concurrency logic in the workflow file.

No prior discussion or cover letter is referenced, so this appears to be a standalone patch rather than part of a larger series. The change looks well-scoped and uncontroversial, addressing a practical pain point for contributors who iterate on PRs.
