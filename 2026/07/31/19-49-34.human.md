This is the first patch in Pablo Sabater’s GSoC v2 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now complete, addressing all review feedback from v1, and ready for maintainer consideration.

This patch generalizes the client’s request logic to dynamically include all supported options (currently "size" and "type") rather than hardcoding "size". The change is mechanical: it replaces a conditional that only checked for "size" with a loop that iterates over the `object_info_options` list, which has already been filtered to contain only options the server supports. The commit message explains that this is safe because the list is pre-trimmed in `fetch_object_info()`, and the patch itself adds a comment clarifying this invariant.

The patch touches only `fetch-object-info.c` and is a straightforward refactoring with no behavior change in this iteration. It sets the stage for the subsequent patches that introduce the "type" capability and `%(objecttype)` placeholder. The change is well-motivated and aligns with the series’ goal of making the client’s request logic extensible for future metadata options.
