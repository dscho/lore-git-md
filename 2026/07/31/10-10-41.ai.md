This is a CI/build system patch. It modifies GitHub Actions workflow configuration to reduce wasted CI runner capacity by canceling stale workflow runs for pull requests.

The patch updates the `concurrency` group in `.github/workflows/main.yml` to distinguish between pull request and push events. For pull requests, it groups runs by pull request number and cancels any in-progress runs when a new push occurs. For regular pushes, it retains the existing behavior of grouping by commit hash to enable the `skip-if-redundant` optimization.

The change is motivated by the observation that GitHub Actions currently groups workflow runs by commit hash, which means every push to a pull request starts a new run without canceling the previous one. This wastes CI resources since only the latest push matters for pull request testing. The patch addresses this by making the concurrency group pull-request-aware.

The implementation is straightforward: it modifies the `concurrency.group` expression to include the pull request number when available, and sets `cancel-in-progress` to true only for pull request events. The commit message and code comment clearly explain the rationale and behavior change.

This appears to be a well-targeted improvement to Git's CI infrastructure, addressing a real inefficiency without changing core Git functionality. The patch is self-contained and unlikely to be controversial.
