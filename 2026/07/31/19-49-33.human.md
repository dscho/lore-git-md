This is a Google Summer of Code feature patch series (v2) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now complete at six patches, incorporating all review feedback from v1 and reordering the patches for better narrative flow.

The goal remains narrowly scoped: object type is the last piece of metadata guaranteed to match between client and server after a fetch, so this series adds end-to-end support for it. The implementation is mechanical and follows the established pattern from Eric Sunshine’s recently merged predecessor series. Key changes in v2 include moving the "request all supported options dynamically" patch to the front (now patch 1), replacing a manual loop with `for_each_string_list_item()`, adopting Git’s `test_file_size` helper for test portability, and restoring the test that mixes `info` and `remote-object-info` commands with the unified default format.

The series touches `protocol-caps.c`, `fetch-object-info.c`, `serve.c`, and the `git-cat-file` man page, updating both the client request logic and server capability advertisement. The final patch unifies the default format string to `%(objectname) %(objecttype) %(objectsize)` for all queries, removing the temporary workaround that excluded type from remote queries. Test coverage in `t1017` and `t5701` is expanded to verify the new capability, including edge cases like unsupported placeholders returning empty strings.

The v2 iteration addresses all review feedback: Junio’s test portability improvement is incorporated, Karthik Nayak’s style suggestions are adopted where they align with project conventions, and Chandra Pratap’s proposed patch reordering and test restructuring are implemented. The series appears ready for maintainer consideration; the changes are incremental, well-explained, and backed by passing CI. If you care about remote object metadata or the `cat-file` plumbing, this is worth a look.
