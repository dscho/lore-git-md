This is a **bug report follow-up** in the ongoing `git config --global` documentation vs. behavior discrepancy thread. Nils Fahldieck responds to Ben Knoble’s review, reinforcing his argument for aligning the code with the documentation (Option A) while conceding the pedantic nature of his initial wording critique.

Nils acknowledges Ben’s point about the irrelevance of the "doesn’t exist" vs. "not readable" distinction, but doubles down on the core inconsistency: `git config --get` reads *both* `~/.gitconfig` and the XDG config file, while `git config --global` reads only one. This behavioral mismatch—where some commands read both files and others don’t—is now the central user-facing issue. He ties this back to his real-world use case (a PR for the `git-get` helper tool, which relies on `--global` and thus fails to read settings from the XDG file), grounding the discussion in practical impact.

The email also reveals Nils’s willingness to contribute a documentation patch but expresses uncertainty about the process for updating both the Git man pages and the git-scm.com website (including translations). This suggests the thread may soon shift from discussion to implementation, though the unresolved question of *which* fix to pursue (Option A or B) remains. The maintainer’s preference for Option B (documenting the single-file behavior) is still unchallenged, but Nils’s framing—emphasizing the inconsistency between `--get` and `--global`—strengthens the case for Option A (making `--global` read both files). No new technical details emerge, but the focus on user expectations and cross-command consistency sharpens the debate.
