This is the fourth patch in Pablo Sabater’s six-patch GSoC series (v2) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series builds directly on Eric Sunshine’s recently merged v21 work and is now complete, addressing all review feedback from v1.

This patch prepares the client to parse the object type from the server’s response, even though the server does not yet advertise the "type" capability (that comes in patch 5). The change is mechanical: it adds a `type_index` variable to track the position of the "type" field in the server’s response, allocates storage for the parsed type in the `object_info_data` array, and maps the server’s string response (e.g., `"blob"`) to Git’s internal enum using `type_from_string()`. The `BUG()` assertion is updated to reflect the new supported option, replacing the hardcoded "only size is supported" message.

The patch touches only `fetch-object-info.c` and is narrowly scoped to parsing logic. It does not change behavior on its own -- the client will ignore the type field until the server advertises the capability in the next patch. The implementation is straightforward and well-aligned with the existing pattern for handling the "size" field, suggesting it is unlikely to introduce regressions. The series as a whole is ready for maintainer consideration.
