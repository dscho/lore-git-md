This is Junio C Hamano’s follow-up in the ongoing RFC thread about restricting hex object IDs to lowercase in Git 3.0. He expands on his earlier invocation of the Robustness Principle with a concrete hypothetical: Git’s dumb HTTP transport encountering a loose object directory named in uppercase (e.g., `objects/AB/`). Junio argues that a truly robust implementation would accept such directories and files as valid, normalize them to lowercase internally, and avoid storing duplicates—rather than rejecting them outright, as brian m. carlson’s series proposes.

The email does not engage with the patch’s code or tests but instead reaffirms Junio’s philosophical objection to tightening the rule after twenty years. He acknowledges that rejecting uppercase is *a* solution but suggests that a more liberal approach—accepting but normalizing—would better honor the Robustness Principle without sacrificing compatibility. The tone remains open-ended ("I dunno"), leaving the door ajar for further discussion or a compromise that preserves case-insensitive parsing for external inputs while enforcing lowercase internally. No technical review or maintainer decision is implied; the thread remains in RFC limbo.
