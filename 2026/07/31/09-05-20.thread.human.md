This thread is about a regression in `git rebase` that causes fatal errors when commit graphs are enabled and submodules are involved. The issue was introduced in Git v2.54 by commit `bb5da75d61` and affects users who update submodule pointers during a rebase. Reporter Florian Schmidt provided a bisect result and a workaround (disabling commit graphs), but the root cause remains unclear—specifically, why `lookup_commit_reference_gently()` resolves a submodule OID against the main repository’s commit graph.

Patrick Steinhardt has joined the discussion, asking whether the issue persists on the `master` branch (where recent commit-graph fixes might already address it) and requesting a minimal reproducer to help diagnose the problem. No patches or technical analysis have been posted yet, so the thread is still in the investigation phase. The key open question is whether the commit graph is being queried without respecting submodule boundaries, or if the function should avoid the commit graph entirely for submodule OIDs.
