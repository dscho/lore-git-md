Thread identity: feature request for a configuration option to suppress warnings about trailing blank lines at the end of files. Originating author: Thomas Nemeth. Thread type: user request (not a patch series or RFC).

Core problem or goal: Thomas Nemeth requests a Git configuration option to suppress warnings about trailing blank lines (specifically, trailing newlines) in diff output, motivated by Vim workflow ergonomics. The goal is a quality-of-life improvement for users who intentionally keep a trailing blank line, without affecting Git's handling of other trailing whitespace. Junio C Hamano later clarified that the request could be interpreted in two ways: (1) suppressing warnings for *any* trailing blank line (including zero), or (2) enforcing *exactly one* trailing blank line (flagging zero or multiple as problematic). The existing `core.whitespace=-blank-at-eof` setting addresses the first interpretation but not the second.

Current status: request raised; no patch or technical proposal submitted. Junio has acknowledged the request, corrected a misunderstanding about the scope of `blank-at-eof`, and clarified that Git currently lacks a dedicated mechanism to suppress trailing blank-line warnings without also disabling other whitespace checks. No maintainer intention to implement or merge has been expressed. The thread remains dormant, with the existing `core.whitespace=-blank-at-eof` workaround (suggested by Johannes Sixt) as the only available suppression method, though it disables the `blank-at-eof` check globally and does not address the stricter interpretation of enforcing exactly one trailing line.

Key technical details: none proposed yet. Junio’s response highlights that any implementation would need to resolve:

- What mechanism the feature should modify (e.g., diff output, `git apply`, `git diff --check`).
- What the configuration option should be named.
- Whether the feature should support only one trailing blank line or multiple.
A potential implementation would likely involve:
- A new configuration knob (e.g., `core.ignoreTrailingBlankLine` or similar).
- Adjustments to Git's whitespace-checking logic in `diff.c`, `apply.c`, and possibly other commands (e.g., `git add -p`, `git diff --check`).
- No changes to on-disk format or test coverage implied yet.
Hannes’s suggestion to use `core.whitespace=-blank-at-eof` demonstrates that partial suppression is already possible, but this affects all whitespace checks, not just trailing blank lines, and does not support the stricter interpretation of enforcing exactly one trailing line.
