Thread identity: feature request for a configuration option to suppress warnings about trailing blank lines at the end of files. Originating author: Thomas Nemeth. Thread type: user request (not a patch series or RFC).

Core problem or goal: Thomas Nemeth requests a new Git configuration option to disable warnings about trailing blank lines (specifically, a single trailing newline) in diff output, motivated by ergonomic preferences for Vim workflows. The goal is a quality-of-life improvement for users who intentionally keep a trailing blank line, without affecting Git's handling of other trailing whitespace.

Current status: request raised; no patch or technical proposal submitted. Junio C Hamano has responded, acknowledging the request and clarifying that Git currently lacks a dedicated mechanism to suppress trailing blank-line warnings without also disabling other whitespace checks (e.g., via `core.whitespace=-blank-at-eof`). He frames the feature as contingent on thoughtful design but does not endorse or reject it, leaving the thread dormant. No maintainer intention to implement or merge has been expressed. The existing `core.whitespace=-blank-at-eof` workaround (suggested by Johannes Sixt) remains the only available suppression method, though it disables the `blank-at-eof` check globally.

Key technical details: none proposed yet. Junio’s response highlights three design questions that would need resolution for any implementation:
- What mechanism the feature should modify (e.g., diff output, `git apply`, `git diff --check`).
- What the configuration option should be named.
- Whether the feature should support only one trailing blank line or multiple.
A potential implementation would likely involve:
- A new configuration knob (e.g., `core.ignoreTrailingBlankLine` or similar).
- Adjustments to Git's whitespace-checking logic in `diff.c`, `apply.c`, and possibly other commands (e.g., `git add -p`, `git diff --check`).
- No changes to on-disk format or test coverage implied yet.
Hannes’s earlier suggestion to use `core.whitespace=-blank-at-eof` demonstrates that partial suppression is already possible, but this affects all whitespace checks, not just trailing blank lines.

Open questions and loose ends:
- Whether the project considers this a worthwhile addition (scope and demand).
- Naming and placement of the configuration option, if implemented.
- Whether the option should suppress warnings in all contexts (e.g., `git diff --check`, `git apply`) or only in diff output.
- Backwards compatibility: whether existing `core.whitespace` settings should interact with the new option.
- Whether the existing `core.whitespace=-blank-at-eof` workaround is sufficient for users with this preference, reducing the urgency of a dedicated option.
- Junio’s three design questions (mechanism, naming, single vs. multiple trailing lines) remain unanswered.
- No design or implementation proposal yet.
