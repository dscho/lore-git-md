Core problem or goal
Reduce wasted GitHub Actions CI runner capacity by ensuring only the latest workflow run for a pull request remains active, canceling any stale in-progress runs when a new push occurs. The current configuration groups workflow runs by commit hash, which prevents cancellation of stale runs for pull requests.

Current status
Under review; no prior versions. Patch modifies `.github/workflows/main.yml` to make the `concurrency.group` expression pull-request-aware, grouping by pull request number for pull request events and by commit hash for regular pushes. Sets `cancel-in-progress: true` for pull request events only. No evidence of integration into Junio’s branches; remains in review state.

- File touched: `.github/workflows/main.yml`

- Old behavior: all workflow runs for a commit hash run to completion, regardless of pull request state
