This is the third patch in Pablo Sabater’s six-patch GSoC series (v2) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series builds directly on Eric Sunshine’s recently merged v21 work and is now complete, addressing all review feedback from v1.

This patch teaches the server-side object-info handler in `protocol-caps.c` to accept and return the object type when requested. The implementation is straightforward: it adds a `type` bit field to the `requested_info` struct, parses the "type" capability in the incoming request, and appends the type name (e.g., "blob", "tree") to the server’s response. The patch also wraps an over-long line in `send_info()` and fixes the bit-field style for `requested_info.size`, both minor cleanups noted in v1 review.

Test coverage is expanded in `t5701-git-serve.sh` with a new test that verifies the server correctly handles a request for both size and type, returning the expected format. The test is clear and portable, using `test_file_size` as endorsed by Junio in the v1 discussion.

The patch is narrowly scoped and well-executed, touching only the server-side logic and its tests. It follows the established pattern from the predecessor series and integrates cleanly with the rest of the codebase. No open questions or controversies remain; this is a ready-to-merge feature addition.
