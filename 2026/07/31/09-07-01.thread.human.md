This thread is a small but useful documentation improvement from Kristoffer Haugsbakk. The `git-refs(1)` man page currently buries an important warning about ref migration limitations deep in a "KNOWN LIMITATIONS" section, making it easy for users to miss. The series reorganizes this warning into a prominent admonition block directly under the `migrate` subcommand description, ensuring users see it when they need it most. The first of two patches does exactly that—relocating the warning without changing its text—and is uncontroversial. The second patch will add a missing cross-reference to `git-maintenance(1)`.

The change is purely presentational, touching only the AsciiDoc source for `git-refs(1)`, and no code or behavior is altered. Kristoffer’s commit message explains the rationale well: when the warning was originally added, the man page was short and the limitations were visible from the command description, but now that the page has grown to describe nine subcommands, the warning is effectively hidden. The patch is part of his ongoing documentation cleanup efforts, which have consistently improved man page clarity and organization. No objections or open questions have been raised so far, and the series is under review.
