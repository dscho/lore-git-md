This is the fourth patch in Pablo Sabater’s GSoC v2 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the client to parse the "type" field from the server’s response, preparing it for when the server advertises the capability (which happens in patch 5).

The change is confined to `fetch-object-info.c` and is mechanical: it adds a `type_index` variable to track the position of the "type" field in the server’s response, allocates storage for the parsed type in the `object_info_data` array, and uses `type_from_string()` to convert the server’s string (e.g., `"blob"`) into Git’s internal enum. The `BUG()` assertion is updated to reflect the new supported option. The patch does not alter behavior yet — the server still does not advertise "type" — but it ensures the client can handle the response format once the server does.

This is a straightforward plumbing change with no user-visible impact at this stage. The commit message clearly states the patch’s preparatory role, and the implementation follows the established pattern for parsing the "size" field. No test coverage is added here; testing is deferred to later patches that exercise the full end-to-end flow. The patch is uncontroversial and appears ready for integration.
