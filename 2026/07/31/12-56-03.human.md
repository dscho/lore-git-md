This is the second patch in Junio C Hamano’s four-part `git add --resolved` series, a refactoring that consolidates duplicate conflict-marker detection logic. The patch replaces two near-identical functions—`is_conflict_marker()` in `diff.c` and `is_cmarker()` in `rerere.c`—with a single, stricter helper, `is_conflict_marker_line()`, in the new `merge-ll.c` file. The unified helper enforces a space after `<<<<<<<` and `>>>>>>>` markers, aligning with Git’s conflict-generation behavior and eliminating a subtle inconsistency between the two existing implementations.

The change is purely internal and does not alter user-visible behavior. It touches four files (`diff.c`, `merge-ll.c`, `merge-ll.h`, and `rerere.c`) and reduces the total line count by 17, replacing 56 lines of duplicate logic with 31 lines of shared code. The stricter rule—requiring a space after `<<<<<<<` and `>>>>>>>`—is intentional and matches the format Git itself produces, so it should not break existing workflows. The helper also returns the marker character (`<`, `=`, `>`, or `|`) instead of a boolean, allowing callers to distinguish between different marker types without rescanning the line.

This refactoring is a prerequisite for the `--resolved` feature in patch 3/4, which uses the new helper to scan files for remaining conflict markers. The consolidation is well-motivated and technically sound; the only potential concern is whether the stricter rule might reject valid conflict markers from other tools, but the commit message explicitly addresses this by noting that Git’s own conflicts always include the space.
