This is the first patch in a two-patch documentation series from Kristoffer Haugsbakk improving the `git-refs(1)` man page. It moves a warning about ref migration limitations—currently buried in a "KNOWN LIMITATIONS" section at the end of the page—into a prominent admonition block directly under the `migrate` subcommand description. The motivation is clear: the warning is critical for users considering a ref storage migration (it notes that concurrent writes can lead to an inconsistent state), but it is currently easy to overlook because it appears far from the command synopsis. The patch is purely presentational, touching only the AsciiDoc source for `git-refs(1)`, and the commit message explains the rationale well—when the warning was originally added, the man page was short and the limitations were visible from the command description, but now that the page has grown to describe nine subcommands, the warning is effectively hidden.

The change is uncontroversial and addresses a real usability issue. The admonition block is appropriately marked as a "CAUTION" and the text is unchanged, only relocated. No code or behavior is altered, and the patch is part of Kristoffer’s ongoing documentation cleanup efforts. The second patch in the series will add a missing cross-reference to `git-maintenance(1)` in the same warning text. This patch stands on its own and could be merged independently if needed. The diff is clean and the reorganization is logical—users reading about the `migrate` command will now see the warning immediately, rather than having to scroll past unrelated subcommands.
