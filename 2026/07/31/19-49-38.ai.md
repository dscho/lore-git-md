This is the fifth patch in Pablo Sabater’s GSoC v2 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the server to advertise the "type" capability, completing the end-to-end chain: the server can now both handle type requests (added in patch 3) and signal to the client that it is safe to ask for them.

The change is minimal and mechanical: in `serve.c`, the `object_info_advertise()` function appends " type" to the advertised capabilities string, which already included "size". The test suite in `t1017-cat-file-remote-object-info.sh` is updated to reflect the new behavior: the test that previously verified `%(objecttype)` returned an empty string is flipped to expect the actual type ("blob"), and a new test checks that truly unsupported placeholders (`%(objectmode)`, `%(objectsize:disk)`, etc.) still return empty strings. The patch also adds helper variables (`hello_type`, `tree_type`, `commit_type`, `tag_type`) to the test preamble, making the expected output more readable and maintainable.

This patch is the last piece needed before the client can actually request and display object types from the server. The series is now feature-complete: patches 1–4 prepare the client and server to handle type requests, patch 5 enables the capability advertisement, and patch 6 (the next one) will unify the default format string to include `%(objecttype)`. The implementation remains narrowly scoped to object type, with no changes to on-disk format or protocol version. All review feedback from v1 has been addressed, and the series is ready for maintainer consideration.
