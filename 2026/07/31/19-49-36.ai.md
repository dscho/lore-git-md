This is the third patch in Pablo Sabater’s GSoC v2 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the server-side object-info handler in `protocol-caps.c` to accept and return the "type" field when requested by the client.

The implementation is straightforward: it adds a `type` bit field to the `requested_info` struct, parses the "type" keyword in the client request, and appends the object type (e.g., `"blob"`, `"tree"`) to the server’s response using `type_name()`. The patch also includes a test in `t5701-git-serve.sh` that verifies the server correctly handles a request for both "size" and "type" and returns the expected output format.

Two minor cleanups are included: wrapping an over-long line in the error message and fixing the bit field style for `requested_info.size` to match the new `type` field. The changes are mechanical and align with the established pattern from Eric Sunshine’s recently merged v21 series. No behavioral regressions or edge cases are introduced; the patch is narrowly scoped to adding type support on the server side.
