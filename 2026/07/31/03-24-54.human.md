This is Junio C Hamano’s review of the fourth patch in brian m. carlson’s RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. The series aims to make Git’s hex parsing consistent (emitting and accepting only lowercase) to address security and compatibility issues, but remains in the RFC stage awaiting feedback on whether the project wants this change at all.

Junio’s review is substantive but narrowly focused. He approves the mechanical change in this patch—replacing `HEX_KIND_MIXED` with `HEX_KIND_OID` in object ID parsing code—but raises a precise technical question: whether the new `HEX_KIND_OID` label should also apply to "derived" hashes like packfile names and rerere database keys, which are not object IDs themselves but are computed from the same hash function. This is not a rejection or a request for rework, but a clarification request about the intended scope of the stricter parsing. The question is forward-looking: if the project eventually adopts the breaking change, should these derived hashes also be subject to the same lowercase-only enforcement?

The patch itself remains uncontroversial and preparatory. It introduces no functional change and is part of the infrastructure needed for the eventual breaking change. Junio’s question does not challenge the patch’s correctness or the series’ overall goal, but it signals that the scope of the stricter parsing may need to be defined more precisely before the change is finalized. This is a typical maintainer concern: ensuring that a breaking change is applied consistently and predictably across all relevant code paths.

For a busy reader, this review is a signal that the series is being taken seriously at the maintainer level, but that the discussion is still in the design phase. The question about derived hashes is a detail, but it is the kind of detail that could affect the change’s impact on users and tools. If you are following the Git 3.0 breaking changes discussion, this is a thread to watch, but there is no immediate action or decision here. The ball is back in brian’s court to clarify the intended scope of `HEX_KIND_OID`.
