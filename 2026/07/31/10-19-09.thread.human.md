This thread began when Thomas Nemeth requested a Git configuration option to suppress warnings about trailing blank lines at the end of files, motivated by his Vim workflow. He wanted to preserve a trailing blank line for ergonomic reasons when moving C functions around in a file, but Git’s diff output would flag it as problematic. Junio C Hamano clarified that Git already supports suppressing these warnings via `core.whitespace=-blank-at-eof`, which Thomas acknowledged as a sufficient workaround for his needs. The stricter interpretation—enforcing *exactly one* trailing blank line—remains unaddressed, though no one has actively pushed for it.

The discussion has since shifted to workflow-level solutions. Johannes Sixt suggested a Vim-specific workaround: using line-wise visual mode (`V`) instead of character-wise mode (`v`) to avoid the trailing blank line issue entirely. This sidesteps the need for Git configuration changes but doesn’t engage with whether Git should accommodate such preferences more broadly. The thread is now dormant, with no patches proposed or maintainer interest expressed in implementing a dedicated option. The existing `core.whitespace` setting appears to cover the original use case, leaving the stricter interpretation as an open question without active demand.
