This thread is a feature request from Thomas Nemeth for a Git configuration option to suppress warnings about trailing blank lines at the end of files, motivated by Vim workflow preferences. The discussion has so far focused on clarifying the request's scope and practicality rather than proposing a technical solution.

Junio C Hamano, the maintainer, noted that the request could be interpreted in two ways: either suppressing warnings for *any* trailing blank line (already possible via `core.whitespace=-blank-at-eof`, though this disables other whitespace checks) or enforcing *exactly one* trailing line (not currently supported). Johannes Sixt suggested the existing workaround might suffice, while Ben Knoble recently asked Thomas for concrete examples of how trailing blank lines improve workflows, aiming to better understand the use case. No patch or implementation proposal has been submitted, and the thread remains dormant with no maintainer indication of intent to implement. The open questions revolve around whether the feature is worthwhile, how it should interact with existing settings, and whether the stricter interpretation (enforcing exactly one line) is justified. For now, users seeking to suppress these warnings can use the `core.whitespace` workaround, though it’s a blunt tool.
