This thread is a feature request from Thomas Nemeth for a Git configuration option to suppress warnings about trailing blank lines at the end of files, motivated by Vim workflow preferences. The discussion has clarified what Git can already do—namely, disable *all* trailing blank-line warnings via `core.whitespace=-blank-at-eof`—but has not advanced toward a dedicated option for this specific case.

Junio C Hamano initially misread the request as wanting Git to enforce *exactly one* trailing blank line, but later corrected this, noting that the existing `core.whitespace` setting suffices for simply suppressing warnings about *any* trailing blank line. However, no one has proposed a design for a more targeted option, and Junio has not signaled whether such a feature would be accepted. The thread remains open-ended, with key questions unanswered: whether the project sees value in this addition, how it should be named, and where it should apply (e.g., diff output, `git apply`, or other commands). For now, users who want to suppress these warnings can use the existing `core.whitespace` workaround, though it disables other whitespace checks as well.
