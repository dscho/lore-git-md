This is a follow-up in the ongoing discussion about the discrepancy between the documented and actual behavior of `git config --global`. Nils Fahldieck acknowledges Ben Knoble’s reference to a related thread about unintuitive behavior with `--global` and `--no-includes`, which helped clarify the historical context of the `--global` flag. He now better understands why `git config --global` reads only one file (prioritizing `~/.gitconfig` over the XDG config file), but he still sees a user-facing inconsistency: `git config --get` reads both files, while `git config --global` does not.

Nils explains that this discrepancy affects third-party tools like `git-get`, which relies on `git config --global` for configuration and thus misses settings in the XDG file. He reiterates that the documentation should be updated to reflect the actual behavior, though he remains open to either aligning the code with the docs (reading both files) or the docs with the code (documenting single-file behavior). He expresses willingness to contribute a patch but seeks guidance on the contribution process, particularly for updating the documentation on git-scm.com and its internationalized versions.

The thread remains unresolved on the fix direction, but Nils’s message reinforces the user impact of the issue and keeps the focus on the need for clarity in the documentation. His mention of `git-get` adds a real-world example of how the discrepancy can cause confusion, which may help sway the discussion toward a resolution.
