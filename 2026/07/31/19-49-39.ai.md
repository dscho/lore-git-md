This is the final patch in Pablo Sabater’s GSoC v2 series extending `` `git cat-file --batch-command` `` to support the `%(objecttype)` placeholder in remote-object-info queries. It unifies the default format string for both local and remote queries to `%(objectname) %(objecttype) %(objectsize)`, removing the temporary workaround that excluded `%(objecttype)` from remote queries in the predecessor series.

The patch touches four files: it updates the `git-cat-file` man page to reflect the new default format and remove the warning about future unification, extends the protocol-v2 documentation to include the `type` attribute in the `object-info` command, removes the hard-coded fallback format in `builtin/cat-file.c`, and updates the test suite in `t1017` to expect the new three-field output (`<oid> <type> <size>`) for all transport protocols (git://, file://, http://). The test that previously verified mixing `info` and `remote-object-info` commands now confirms they share the same unified format.

This patch completes the end-to-end chain: the server advertises the "type" capability, the client requests and parses it, and the output format is now consistent regardless of whether the query is local or remote. The series is ready for maintainer consideration.
