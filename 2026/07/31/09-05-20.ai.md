This is a **bug report** about a regression in `git rebase` when commit graphs are enabled, specifically affecting repositories with submodules. The issue surfaced between Git v2.53 and v2.54 and was bisected to commit `bb5da75d61` ("commit: use commit graph in `lookup_commit_reference_gently()`").

The reporter, Florian Schmidt, describes a scenario where rebasing a branch with submodule pointer changes fails with the error `error: Could not read 157b7492624beac3ac667dd3a84de9969377866b` and `fatal: invalid commit position. commit-graph is likely corrupt`. Disabling commit graphs (`core.commitGraph=false`) allows the rebase to proceed, though it still results in submodule conflicts as expected. The problematic commit OID (`157b7492624beac3ac667dd3a84de9969377866b`) is not found in the main repository but *is* recognized as a commit in one of the submodules (`rpmsrc/qemu-kvm`), suggesting Git may be incorrectly resolving object references across repository boundaries.

The commit message provides a clear reproduction case: a single-commit branch updating two submodule pointers, followed by a `git rebase` that fails only when commit graphs are enabled. The bisect result points directly to the commit that introduced commit-graph usage in `lookup_commit_reference_gently()`, which is a strong indicator of the root cause. The reporter also notes that Git v2.53 emits similar errors but continues the rebase, while v2.54 fails fatally.

Key technical details for follow-up discussion:
- **Subsystems touched**: commit graph, submodule handling, rebase machinery.
- **Error message**: `invalid commit position. commit-graph is likely corrupt`.
- **Regression commit**: `bb5da75d61` ("commit: use commit graph in `lookup_commit_reference_gently()`").
- **Workaround**: Disable commit graphs (`core.commitGraph=false`).
- **Object OID**: `157b7492624beac3ac667dd3a84de9969377866b` (exists in submodule, not in main repo).
- **Test case**: Rebase a branch with submodule pointer changes.

The report is well-structured, includes a bisect, and provides enough context to investigate the issue without requiring additional information. The apparent confusion between main repository and submodule object resolution is likely the core problem. This looks like a genuine regression that could affect users with submodules, and the bisect result gives reviewers a clear starting point.
