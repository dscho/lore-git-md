This thread is about a small but practical improvement to Git's GitHub Actions CI setup. Harald Nordgren proposed a change to cancel stale workflow runs for pull requests, ensuring only the latest push to a PR consumes CI runner capacity. The patch has evolved through three versions, with the latest (v3) making only a minor stylistic tweak to the commit message.

The core idea is simple: modify `.github/workflows/main.yml` so that workflow runs for the same pull request are grouped together and canceled if a new push arrives, while preserving the existing behavior for regular pushes. Junio C Hamano, the maintainer, reviewed the change and accepted a minor trade-off—duplicate workflow runs could theoretically occur for the same commit if it’s pushed directly and later submitted as a PR—but deemed this edge case rare and unavoidable under GitHub Actions' design.

All feedback has been addressed, and the patch is now ready for merge. The change is self-contained, touching only the CI workflow file, and introduces no new symbols or on-disk changes. No further revisions are expected.
