This thread is about a CI improvement to cancel stale GitHub Actions workflow runs for pull requests, reducing wasted runner capacity. Harald Nordgren posted a v2 patch that modifies `.github/workflows/main.yml` to group workflow runs by pull request number (for PR events) and commit hash (for regular pushes), ensuring only the latest run for a PR remains active. Junio C Hamano reviewed the patch, confirmed the intended behavior, and later tested v2, identifying a potential edge case: the same commit pushed directly to a repository and later submitted as a PR could trigger duplicate workflow runs due to separate concurrency groups for `push` and `pull_request` events.

Harald responded that this scenario is unavoidable under GitHub Actions’ design, as concurrency groups are scoped to individual repositories. The thread now centers on whether the project accepts this low-probability inefficiency. Junio’s review framed it as a rare edge case, and no other participants have weighed in. The patch itself is well-scoped and addresses prior feedback, but this unresolved detail may delay merging until maintainers assess the trade-off. No further changes are proposed, leaving the decision to Junio or other maintainers.
