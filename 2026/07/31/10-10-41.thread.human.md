This thread is about a small but practical improvement to Git's GitHub Actions CI setup. Harald Nordgren proposed a patch (now at v2) that cancels stale workflow runs for pull requests, freeing up CI runner capacity. The change modifies `.github/workflows/main.yml` to group workflows by pull request number for PR events, ensuring only the latest run stays active, while keeping the existing commit-based grouping for regular pushes.

Junio C Hamano reviewed the patch, raised an edge case about potential duplicate workflow runs for the same commit (if pushed directly and later submitted as a PR), and confirmed with Harald that this is an inherent limitation of GitHub Actions—rare in practice and not worth working around. After testing v2, Junio accepted the trade-off, clearing the way for the patch to be merged. The thread is now effectively closed, with no further changes expected. The patch is ready for Junio to pick up into his integration branches.
