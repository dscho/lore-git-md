This thread is about a small but practical improvement to Git's GitHub Actions CI setup. Harald Nordgren submitted a patch that makes the CI system cancel stale workflow runs for pull requests—currently, every push to a PR starts a new run without stopping the old one, wasting runner time and capacity. The fix is simple: it tweaks the workflow configuration to group runs by pull request number instead of commit hash, so only the latest run stays active.

The patch is self-contained, touches only the CI workflow file, and comes with a clear explanation of why it’s needed. No one has reviewed it yet, and it hasn’t been picked up in Junio’s integration branches. Harald’s follow-up is just a polite nudge for review, emphasizing the real-world benefit of reducing CI costs. Given the low-risk nature of the change and its practical upside, it’s likely to attract attention from CI-focused contributors like Johannes Schindelin or D. Ben Knoble. Nothing is contested or unresolved—just waiting for eyes on the patch.
