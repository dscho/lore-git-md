This thread is about a small but practical improvement to Git's GitHub Actions CI setup. Harald Nordgren proposed a patch to cancel stale workflow runs for pull requests, freeing up CI runner capacity. The first version grouped workflows by commit hash or pull request number, which Junio C Hamano reviewed and found acceptable in principle but raised a concern: if multiple workflows run simultaneously for the same commit, they might interfere and some could be skipped entirely.

Harald has now sent a second version that addresses this edge case. The new patch makes the concurrency group include the workflow name, so each workflow gets its own group per commit or pull request. This keeps the original benefit—canceling stale pull request runs—while ensuring simultaneous workflows don’t step on each other. The commit message is now more detailed, explaining both the old and new behavior and how the edge case is handled. Junio’s feedback has been fully incorporated, and the patch remains a clean CI-only change with no impact on Git’s core code. It’s ready for another look and, if no further issues arise, should be a straightforward merge.
