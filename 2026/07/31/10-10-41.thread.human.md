This thread is about a small but practical CI improvement: automatically canceling stale GitHub Actions workflow runs for pull requests to save runner capacity. Harald Nordgren posted a patch that modifies the workflow configuration to group runs by pull request number rather than commit hash, ensuring only the latest run stays active. Junio reviewed the first version, raised an edge case about simultaneous workflows, and Harald quickly addressed it in v2.

The patch is now under final review. Junio tested the edge case he’d previously flagged—whether a commit pushed to a repository and then submitted as a pull request would trigger duplicate workflows—and confirmed the v2 patch avoids this by splitting concurrency groups by workflow name and event type. While he notes the scenario is rare (most contributors push to forks without CI), he’s satisfied the change doesn’t regress the existing optimization for non-PR pushes. No objections remain, and the patch is ready for merging unless new concerns surface. The change is confined to the GitHub Actions configuration and doesn’t touch core Git code or tests.
