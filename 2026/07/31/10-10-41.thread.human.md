This thread is about a small but practical improvement to Git's GitHub Actions CI setup. Harald Nordgren proposed a patch to reduce wasted CI runner capacity by canceling stale workflow runs when a new push occurs on a pull request. Currently, workflows are grouped by commit hash, so multiple runs for the same pull request can pile up if pushes happen in quick succession.

Junio C Hamano recently reviewed the patch after it sat unreviewed for a while. He walked through the change carefully and endorsed the core idea—canceling stale runs for pull requests is a clear win—but raised a potential edge case: if multiple workflows in the same concurrency group are triggered simultaneously for the same commit, the new grouping logic might cause some workflows to be skipped entirely. He asked Harald to either verify this isn’t a problem or document the behavior in the commit message. No code changes were requested yet, so the patch is still under review and not queued for integration.

So far, only Junio has weighed in, and the discussion is focused on this one edge case. If Harald addresses it, the patch will likely move forward without further controversy.
