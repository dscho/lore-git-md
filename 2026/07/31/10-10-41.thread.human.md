This thread is about a small but practical improvement to Git's GitHub Actions CI workflow. Harald Nordgren submitted a patch that reduces wasted CI runner capacity by making the workflow cancel stale in-progress runs when a new push is made to a pull request.

The change is simple: it modifies the `concurrency` group configuration in `.github/workflows/main.yml` to distinguish between pull request and push events. For pull requests, runs are now grouped by pull request number (rather than commit hash), and any in-progress run is canceled when a new push occurs. This ensures only the latest push is tested, saving resources. For regular pushes, the existing behavior—grouping by commit hash to enable the `skip-if-redundant` optimization—is preserved.

The patch is self-contained, well-explained, and addresses a real inefficiency in Git's CI setup. Since it only affects workflow configuration and doesn’t touch core Git functionality, it’s unlikely to be controversial. No reviews or objections have appeared yet, but given the straightforward nature of the change, it may be merged without much discussion.
