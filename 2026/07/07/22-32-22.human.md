This is a bug report from SZEDER Gábor about a puzzling `git fetch` behavior. He observes that a routine daily fetch from GitHub’s Git mirror unexpectedly downloaded over 400,000 objects (nearly 300 MiB) despite the vast majority of those objects already being present locally. The fetch included forced updates to the `jch`, `next`, and `seen` branches, which suggests that the remote rewound or rebased those branches, but Gábor’s analysis shows that most of the downloaded objects were duplicates of what he already had.

The report is thorough: he provides exact command output, object counts, and a diff showing the overlap between existing and received objects. He also notes that this might be a recurring issue (he remembers a similar event weeks earlier) but was unable to reproduce it in a fresh clone. His local Git version is based on `next` with some long-standing personal patches, none of which touch object transfer, and he has no unusual fetch or transfer configuration.

This looks like a real, if intermittent, bug in Git’s object negotiation logic. The fact that it involves forced updates to integration branches (`next`, `seen`) suggests it could be triggered by Junio’s integration workflow, but the root cause is not yet clear. The report is credible and well-documented, making it worth attention from anyone working on fetch, pack negotiation, or the integration branches.
