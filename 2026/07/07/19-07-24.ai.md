This is the v7 iteration of the feature addition that teaches `git replay` a `--linearize` option to flatten merge commits into a linear history. The series is now **technically complete** and addresses all prior feedback, including the most significant change in this version: **removing the mutual exclusivity between `--linearize` and `--revert`**, allowing them to be used together. This resolves the last substantive interface design question raised by Junio C Hamano in v6.

The series consists of three patches, with the core implementation in patch 3/3. The first two patches are refactoring: patch 1/3 introduces a helper function (`put_mapped_commit`) to simplify the logic for tracking replayed commits, and patch 2/3 moves the logic for resolving the replay base outside `pick_regular_commit()`, improving clarity and reducing the function's parameter count. The refactoring is purely internal and introduces no behavior changes.

The core patch (3/3) implements `--linearize` by skipping merge commits and reparenting subsequent commits onto the previous non-merge commit, ensuring a single linear history even when multiple branches are involved. The commit message and documentation have been extended to explain the behavior, edge cases, and differences from `git rebase --no-rebase-merges`. Test coverage is thorough, including scenarios for replaying multiple divergent branches, handling merge commits, and verifying the new `--revert`/`--linearize` compatibility. The regression fix from v6 (restoring the `replayed_base` parameter) remains in place, ensuring correct behavior when replaying a single branch containing merge commits.

Key changes in v7:
- **Removed the mutual exclusivity between `--linearize` and `--revert`**, allowing them to be used together. This resolves Junio's v6 feedback about the need to either justify the incompatibility or move it to a BUGS/LIMITATIONS section. The new behavior is tested and documented.
- **Changed authorship of the core patch (3/3) from Johannes Schindelin to Toon Claes**, reflecting the extensive changes since the original patch. Johannes explicitly disclaimed authorship, and the change addresses Junio's procedural nit about attribution.
- **Added a new test** verifying that `--revert` and `--linearize` can be used together to revert a range containing a merge commit.

The interface design debate (whether to mirror `git rebase`'s `--rebase-merges=<mode>` syntax) is no longer blocking. The series continues to use `--linearize` as a standalone flag, with the commit message justifying the divergence on the grounds that it better describes the predictable, all-or-nothing flattening behavior. The behavioral difference from `git rebase --no-rebase-merges` is documented and tested.
