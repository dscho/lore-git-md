Thread identity: patch series titled "Make ODB optimizations pluggable", v1, 11 patches, authored by Patrick Steinhardt. Thread type: patch series introducing modular ODB optimization logic as part of the ongoing ODB abstraction effort.

Core problem or goal: restructure Git's object database (ODB) to allow different backends to implement their own optimization strategies (repacking, geometric repacking, auto-gc) without hardcoding them in `builtin/gc.c`. The series prepares the codebase by extracting existing optimization logic into a modular system, enabling future backends (e.g., reftable, custom storage) to define their own housekeeping tasks. The first five patches addressed a long-standing inconsistency in the "pre-auto-gc" hook, reordered maintenance tasks to group ODB-related optimizations, refactored `cmd_gc()` to isolate repack and prune logic into `maintenance_task_odb()`, eliminated global state in repack argument assembly, and relocated backend-specific configuration reads to call sites. Patch 6 introduces `struct odb_optimize_options` to encapsulate all ODB optimization settings, decoupling them from `struct gc_config` and preparing for backend-specific logic.

Current status: series v1 posted; under initial review. No prior versions or merge status recorded. Changes remain preparatory, with no new backends or user-visible behavior changes beyond the expanded scope of the "pre-auto-gc" hook, the reordering of maintenance tasks, and the extraction of repack/prune logic into a self-contained `maintenance_task_odb()` helper. Patches 1-6 are mechanical refactorings that preserve all existing logic while preparing for pluggable optimizations.
