Thread identity: patch series titled "Make ODB optimizations pluggable", v2, 12 patches, authored by Patrick Steinhardt. Thread type: patch series introducing modular ODB optimization logic as part of the ongoing ODB abstraction effort.

Core problem or goal: restructure Git's object database (ODB) to allow different backends to implement their own optimization strategies (repacking, geometric repacking, auto-gc) without hardcoding them in `builtin/gc.c`. The series prepares the codebase by extracting existing optimization logic into a modular system, enabling future backends (e.g., reftable, custom storage) to define their own housekeeping tasks. The first eight patches (v1 patches 1-7 plus the new v2 patch 1) address a long-standing inconsistency in the "pre-auto-gc" hook, reorder maintenance tasks to group ODB-related optimizations, refactor `cmd_gc()` to isolate repack and prune logic into `maintenance_task_odb()`, eliminate global state in repack argument assembly, relocate backend-specific configuration reads to call sites, introduce `struct odb_optimize_options` to encapsulate all ODB optimization settings, unify the incremental and geometric repacking strategies under the new `odb_optimize()` entry point, and improve test robustness by replacing brittle `GIT_TRACE2_EVENT`-based checks with a new `test_maintenance_tasks` helper that verifies task execution via trace2 output. Patch 9 (v1 patch 8) extracted the auto-condition checks from `need_to_gc()` and `geometric_repack_auto_condition()` into a single, strategy-aware helper, `odb_optimize_required()`, centralizing the logic that determines whether an ODB optimization should run under `--auto`. Patch 10 (v1 patch 9) mechanically refactored ODB optimization helpers (`too_many_loose_objects()`, `find_base_packs()`, `too_many_packs()`, `estimate_repack_memory()`) to operate on a `struct odb_source_files` parameter instead of the global `the_repository`, preparing for the relocation of the entire "files" source optimization logic into `odb/source-files.c` in patch 11 (v1 patch 10). Patch 11 fixed signedness issues in `too_many_loose_objects()`, `find_base_packs()`, and `odb_optimize()` to prevent compiler warnings when the code was moved to `odb/source-files.c` in patch 12 (v1 patch 11), ensuring clean compilation in the new context. Patch 12 completes the series by relocating the `odb_optimize()` and `odb_optimize_required()` functions into the "files" ODB source backend, exposing them through vtable pointers in the ODB source interface, and removing the now-redundant code from `builtin/gc.c`.
