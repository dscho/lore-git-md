Thread identity: patch series titled "Make ODB optimizations pluggable", v2, 12 patches, authored by Patrick Steinhardt. Thread type: patch series introducing modular ODB optimization logic as part of the ongoing ODB abstraction effort.

Core problem or goal: restructure Git's object database (ODB) to allow different backends to implement their own optimization strategies (repacking, geometric repacking, auto-gc) without hardcoding them in `builtin/gc.c`. The series prepares the codebase by extracting existing optimization logic into a modular system, enabling future backends (e.g., reftable, custom storage) to define their own housekeeping tasks. The first eight patches (v1 patches 1-7 plus the new v2 patch 1) address a long-standing inconsistency in the "pre-auto-gc" hook, reorder maintenance tasks to group ODB-related optimizations, refactor `cmd_gc()` to isolate repack and prune logic into `maintenance_task_odb()`, eliminate global state in repack argument assembly, relocate backend-specific configuration reads to call sites, introduce `struct odb_optimize_options` to encapsulate all ODB optimization settings, unify the incremental and geometric repacking strategies under the new `odb_optimize()` entry point, and improve test robustness by replacing brittle `GIT_TRACE2_EVENT`-based checks with a new `test_maintenance_tasks` helper that verifies task execution via trace2 output. Patch 2 (v2) expands the "pre-auto-gc" hook to intercept all auto-maintenance tasks, not just `gc`, ensuring it can inhibit tasks like `reflog-expire`, `geometric-repack`, and `rerere-gc`. The patch lifts the `run_hooks()` call out of `need_to_gc()` and into `maybe_run_task()`, using a new `enum auto_gc_hook_result` to track whether the hook has run and whether it succeeded. Patch 3 (v2) reorders maintenance tasks in `builtin/gc.c` to group all ODB-related optimizations (repack, prune) together, moving worktree pruning and rerere garbage collection before them. This is a mechanical refactoring with no behavioral changes, explicitly dismissing the theoretical edge case where pruning worktrees before ODB optimizations could make objects unreachable as negligible in practice. Patch 4 (v2) extracts the repack and prune logic from `cmd_gc()` into a new helper function, `maintenance_task_odb()`, as a pure refactoring with no intended behavioral changes. The patch moves the repack and prune logic—previously inlined in `cmd_gc()`—into `maintenance_task_odb()`, along with the warning about too many loose objects. The warning’s timing may shift slightly, but the commit message explicitly dismisses this as having no practical impact. The new helper takes the existing `maintenance_run_opts`, `gc_config`, and `repack_args` parameters, preserving all existing logic (e.g., precious objects check, promisor object exclusions, cruft pack handling). Patch 5 (v2) eliminates global state in repack argument assembly by moving the `strvec` of repack arguments from global scope into `maintenance_task_odb()`, where it is now constructed locally. This requires passing two additional parameters (`keep_largest_pack` and `aggressive`) to the function, removing the interdependence on the global `repack_args` vector. The `need_to_gc()` helper is simplified to drop its `repack_args` parameter, as the argument assembly is now deferred to `maintenance_task_odb()`. Patch 6 (v2) inlines eight backend-specific configuration values (`gc_auto_threshold`, `gc_auto_pack_limit`, `repack_filter`, `repack_filter_to`, `big_pack_threshold`, `max_delta_cache_size`, `delta_base_cache_limit`) into their call sites in `builtin/gc.c`, removing them from the generic `gc_config` struct. This ensures future ODB backends do not need to handle "files"-specific settings, keeping the generic configuration backend-agnostic. The patch is a mechanical refactoring with no intended behavioral changes, preserving all existing logic (auto-condition checks, pack selection, memory estimation, repack argument assembly) while shifting the location of configuration reads. Patch 7 (v2) introduces `struct odb_optimize_options` to encapsulate all ODB optimization settings, consolidating 11 fields previously scattered across `gc_config` or passed as loose parameters: flags for verbosity, auto-maintenance, and delta reuse; prune expiration and cruft pack settings; repack depth and window; and backend-specific options like `keep_largest_pack` and `max_cruft_size`. The patch updates `add_repack_all_option()` and `maintenance_task_odb()` to use the new structure, introduces the `odb_optimize()` helper (which will eventually move into the ODB layer), and updates the geometric repack task to use `odb_optimize_options` when falling back to a full repack. Patch 8 (v2) unifies the incremental and geometric repacking strategies under the new `odb_optimize()` entry point by introducing `enum odb_optimize_strategy` (`ODB_OPTIMIZE_INCREMENTAL`, `ODB_OPTIMIZE_GEOMETRIC`) and moving the geometric repack logic into `odb_optimize()`. The patch replaces `maintenance_task_geometric_repack()` with a call to `odb_optimize(ODB_OPTIMIZE_GEOMETRIC)`, skips pruning for geometric repacks (since they use cruft packs), and updates `maintenance_task_odb()` to pass `ODB_OPTIMIZE_INCREMENTAL` as the default strategy. Tests are updated to expect `-q` instead of `--quiet` in `git repack` invocations. Patch 9 (v2) introduces `odb_optimize_required()`, a new helper that centralizes the auto-condition checks for both incremental and geometric repacking strategies. Previously, this logic was duplicated in `need_to_gc()` (for incremental repacks) and `geometric_repack_auto_condition()` (for geometric repacks); now both callers delegate to the new function, which dispatches based on the requested `enum odb_optimize_strategy`. The patch moves the auto-condition logic—loose-object thresholds, pack counts, geometric split factors, and configuration reads—into a single function, parameterized by a `struct odb_optimize_options` that specifies the strategy. The `gc_condition()` and `geometric_repack_auto_condition()` helpers are updated to construct the appropriate options struct and call `odb_optimize_required()`, while `need_to_gc()` is inlined into the new function. The patch preserves all existing logic, including the handling of negative auto-threshold values (which force a repack) and the geometric split-factor calculation. Patch 10 (v2) mechanically refactors ODB optimization helpers (`too_many_loose_objects()`, `find_base_packs()`, `too_many_packs()`, `estimate_repack_memory()`) to operate on a `struct odb_source_files *` parameter instead of the global `the_repository`, preparing for the relocation of the entire "files" source optimization logic into `odb/source-files.c` in patch 12. The patch updates the function signatures to accept the explicit parameter, replacing direct accesses to `the_repository->objects->sources` and `the_repository` with dereferences of the passed-in pointer. The `find_base_packs()` helper is updated to iterate over `files->packed` (via `packfile_store_get_packs()`) instead of using `repo_for_each_pack(the_repository)`, and `estimate_repack_memory()` now calls `odb_source_count_objects(&files->base, ...)` instead of `odb_count_objects(the_repository->objects, ...)`. All callers in `builtin/gc.c` are updated to pass the downcast `files` pointer, preserving the existing logic for loose-object thresholds, pack selection, memory estimation, and geometric repacking. Patch 11 (v2) fixes signedness issues in `too_many_loose_objects()`, `find_base_packs()`, and `odb_optimize()` to prevent compiler warnings when the code is relocated to `odb/source-files.c` in patch 12. The changes ensure clean compilation in the new context: `too_many_loose_objects()` now bails early if the input `limit` is non-positive, avoiding a comparison between a signed limit and an unsigned object count; `find_base_packs()` casts the pack size to `uintmax_t` when comparing against the (unsigned) limit; and `odb_optimize()` casts `gc_auto_pack_limit` to `unsigned long` when comparing against `keep_pack.nr`. The commit message confirms the changes are safe (e.g., `gc_auto_pack_limit` is guaranteed positive in the relevant code path) and preserves all existing logic, including the quirky 256-multiple rounding of the loose-object threshold. Patch 12 (v1 patch 11) completes the series by relocating the `odb_optimize()` and `odb_optimize_required()` functions into the "files" ODB source backend, exposing them through vtable pointers in the ODB source interface, and removing the now-redundant code from `builtin/gc.c`.
