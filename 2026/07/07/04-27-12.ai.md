This is a **substantive follow-up review** in the ongoing `git rebase -i -x` thread, where Jeff King (Peff) responds to Phillip Wood’s technical and design concerns about extending `git cherry-pick` with an interactive mode (`-i`). Peff largely agrees with Phillip’s assessment but tempers expectations about user behavior and edge cases, while reinforcing the practicality of the `cherry-pick -i` approach.

Peff acknowledges Phillip’s point about generalizing the rebase todo-list editor for `cherry-pick -i` but notes that the `rebase.missingCommitsCheck` logic is the primary rebase-specific hurdle—one that could be abstracted without excessive effort. On the question of whether all rebase commands (e.g., `edit`, `fixup`) should be supported in `cherry-pick -i`, Peff adopts a permissive stance: he assumes users will document edits in commit messages rather than enforcing strict semantic rules for trailers like "(cherry picked from commit ...)". This reflects a preference for flexibility over rigid validation, though it leaves open the ambiguity Phillip raised about how such trailers should be interpreted when commits are modified.

The review also touches on the `--exec` tangent, where Peff observes that most post-pick operations (e.g., `make test`) can already be achieved by cherry-picking first and then rebasing with `-x`. The `-x` flag for recording origin stands out as an exception because it inherently references the *original* commit, not the rebased version. Peff’s example—`git cherry-pick -x` followed by `git rebase -i`—suggests a pragmatic workaround but underscores why an interactive `cherry-pick` mode would still be valuable for streamlining workflows.

Key technical details remain unresolved:
- The `rebase.missingCommitsCheck` logic would need to be generalized or bypassed for `cherry-pick -i`.
- Edge cases like `edit -x` or `pick -x` followed by `fixup` are left to user discretion, with no explicit validation proposed.
- The `--exec` idea is acknowledged but not prioritized, as existing workflows already cover most use cases.

Peff’s tone is collaborative and low-stakes, framing the discussion as exploratory rather than prescriptive. The thread’s direction now hinges on whether Trevor Gross (the original author) will pivot to the `cherry-pick -i` approach or attempt to justify the rebase-centric design. Junio C Hamano’s earlier endorsement of the `cherry-pick -i` alternative adds weight to this path forward.
