This is the second patch in the reftable backend performance regression fix series, now updated in response to Patrick Steinhardt’s review. The patch removes the `suppress_deletions` flag from the reftable merged iterator to fix quadratic behavior when re-creating deleted refs, but the author (Kristofer Karlsson) has revised the approach to preserve downstream compatibility with libgit2.

The key change is that the flag will now be kept in the reftable library API but no longer set from `stack.c`, allowing libgit2 to continue using it while Git’s internal call sites bypass it. This shrinks the patch to a single line removal in `stack.c` and avoids breaking external consumers. The core logic remains: tombstones are now handled explicitly at each call site after bounds checks, enabling early termination when tombstones exceed the relevant bound. The performance improvement (from ~14s to ~0.2s in 8000-ref scenarios) is preserved, and the patch still touches `refs/reftable-backend.c` and `reftable/merged.{c,h}`.

Kristofer confirms that all iteration sites for ref and log records have been adapted to handle deletions, and Patrick’s review identified the libgit2 compatibility issue that prompted this adjustment. The revised patch is narrower in scope but maintains the original goal of fixing the quadratic regression without disrupting downstream users. No new symbols or on-disk format changes are introduced. The thread’s next step is likely a v2 incorporating this compatibility-preserving tweak.
