This is a **build system** and **platform compatibility** follow-up in the ongoing `USE_NSEC` discussion. Jeff King (Peff) responds to Patrick Steinhardt’s proposal to make nanosecond timestamp support runtime-configurable, endorsing the incremental approach while clarifying the long-term fate of the `USE_NSEC` build knob.

Peff agrees with Patrick’s plan to **always compile nanosecond support into Git** (when the platform allows it) and expose it via a runtime config knob (e.g., `core.useNsec`), while retaining the current build-time default (`USE_NSEC` disabled). This sidesteps the auto-detection challenges raised earlier and makes the feature more accessible without requiring users to rebuild Git. He suggests this as the **first step**, with the possibility of later auto-detection or other refinements. Importantly, Peff **advocates for eventually removing the `USE_NSEC` build knob entirely** once the runtime config is available, arguing that retaining it to tweak the unconfigured default would add unnecessary complexity. This aligns with his earlier skepticism about the knob’s value but contrasts with D. Ben Knoble’s defense of build-time parity for power users (e.g., Gentoo distributors).

The email does not address the default value for `core.useNsec` (Peff’s earlier suggestion of a conservative `false` remains unresolved) or the interoperability risks of mixing `USE_NSEC` and non-`USE_NSEC` implementations (e.g., Git and JGit). However, his endorsement of Patrick’s proposal as a pragmatic first step suggests these concerns are not blockers. The next likely action is a patch implementing `core.useNsec` and updating the build system to always compile in nanosecond support, followed by deprecation of the `USE_NSEC` knob in both Meson and Makefile. No concrete implementation details or test plans are proposed yet, but Peff’s focus on incremental progress implies the runtime config could land without resolving every edge case upfront.
