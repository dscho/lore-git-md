This is patch 6/11 in Patrick Steinhardt's "Make ODB optimizations pluggable" series, part of the ongoing ODB abstraction effort. It introduces `struct odb_optimize_options` to encapsulate all settings related to object database optimization, decoupling them from the monolithic `struct gc_config`.

The patch is a mechanical refactoring that moves repack and prune logic into a new structure while preserving all existing behavior. It defines an `enum odb_optimize_flags` for boolean options (verbose, auto-maintenance, delta reuse) and populates the new structure with values from `gc_config` and runtime flags. The `maintenance_task_odb()` helper is rewritten to construct an `odb_optimize_options` instance and delegate to a new `odb_optimize()` function, which now takes an explicit `struct object_database *` parameter instead of relying on `the_repository`.

Key technical details: the patch adds 120 lines to `builtin/gc.c`, mostly in the new `odb_optimize()` function and the revised `maintenance_task_odb()` wrapper. It introduces four new symbols (`enum odb_optimize_flags`, `struct odb_optimize_options`, `ODB_OPTIMIZE_FIELDS_FROM_GC_CONFIG` macro, and `odb_optimize()`) and removes none. The `maintenance_task_geometric_repack()` helper is updated to use the new structure for its repack-all path. No on-disk format changes or user-visible behavior changes occur; the patch is purely preparatory for future backend-specific optimization logic.

The commit message notes that the new structure retains some backend-specific fields (e.g., `keep_largest_pack`, `cruft_packs`) as a pragmatic concession to retrofitting the abstraction onto existing code. This is unlikely to be controversial given the series' overall goal of making optimizations pluggable. The patch looks well-structured and maintains the same error handling and configuration semantics as the original code.
