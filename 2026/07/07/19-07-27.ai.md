This is the third and final patch in the v7 series introducing a `--linearize` option to `git replay`. It implements the core feature: flattening merge commits into a linear history by dropping merges and replaying all commits into a single topology. The patch is technically complete, addressing all prior feedback, and is ready for review.

The implementation adds the `--linearize` flag to the command-line interface and modifies the replay machinery in `replay.c` to skip merge commits while reparenting subsequent commits onto the last replayed non-merge commit. This ensures all replayed commits form a single linear chain, even when multiple revision ranges are provided. The behavior is documented in `git-replay.adoc`, with clear explanations of how it differs from `git rebase --no-rebase-merges` and how multiple branches are handled.

Key changes in this patch include the logic in `replay_revisions()` that checks for merge commits and either skips them (when `--linearize` is active) or errors out (when it is not). The patch also restores the `last_commit` handling to ensure correct parentage for commits following a merge, fixing the regression identified in earlier versions. The mutual exclusivity between `--linearize` and `--revert` has been removed, allowing them to be used together; this change is tested and documented.

Test coverage is thorough, including scenarios for replaying to the root commit, handling merge commits, linearizing multiple divergent branches, and verifying compatibility with `--revert`. The tests explicitly check that the behavioral difference from `git rebase --no-rebase-merges` is preserved and that refs pointing to merge commits are updated to their last replayed ancestor. The patch touches `replay.c`, `replay.h`, `builtin/replay.c`, `Documentation/git-replay.adoc`, and `t/t3650-replay-basics.sh`.

The interface design debate (whether to mirror `git rebase`'s `--rebase-merges=<mode>` syntax) is resolved in favor of `--linearize` as a standalone flag, with the commit message justifying the divergence on the grounds that it better describes the predictable, all-or-nothing flattening behavior.
