This is a substantive review comment in the `git history` feedback discussion, specifically addressing the user experience of silent success in `git history reword` and `git history fixup`. Dominique Martinet reports hands-on testing of the experimental commands and identifies concrete usability problems when operating on commits that are not ancestors of HEAD.

Martinet demonstrates that both `fixup` and `reword` can silently succeed (exit 0) while producing no visible effect: `fixup` leaves staged changes untouched without explanation, and `reword` creates an unreachable commit without updating any ref. The transcript shows that without feedback, users cannot distinguish between a successful rewrite and a no-op. This directly contradicts the earlier assumption that silence would be unambiguous when an editor opens.

The review endorses Pablo Sabater’s proposal to print the old and new commit hashes on success, but adds a new technical consideration: the commands should verify that the rewritten commit is reachable from some ref (either via `--update-refs` or as an ancestor of HEAD) before proceeding. This would prevent the creation of unreachable commits and make the feedback meaningful.

Martinet’s contribution shifts the discussion from abstract consistency principles to concrete failure modes, providing a clear rationale for feedback output and introducing a new requirement (ref reachability) that the implementation must address.
