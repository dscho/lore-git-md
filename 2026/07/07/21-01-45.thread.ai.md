Subject: [PATCH v2] unpack-trees: fix quadratic-time index scan in `next_cache_entry()`
Series version: standalone patch, v2
Originating author: Henrique Ferreiro (via GitGitGadget)
Thread type: performance bugfix

Core problem or goal
Eliminate a quadratic-time index scan in `next_cache_entry()` triggered when `git diff` is run with a pathspec matching a subtree whose entries appear early in the index. The fix introduces a `cache_bottom` field in `o->internal` to track forward-scan progress, allowing subsequent calls to skip already-unpacked entries.

Current status
**Merged to 'master' on 2024-07-10** (date inferred from Junio's merge confirmation). The patch is now part of the upcoming Git release. No further review or iteration is expected unless edge cases emerge during integration testing.

Key technical details
- **File modified**: `unpack-trees.c`
- **Function modified**: `next_cache_entry()`
- **New field**: `o->internal.cache_bottom` (tracks forward-scan progress)
- **Existing field**: `o->cache_bottom` (handles backward scans and ordering mismatches)
- **Test added**: `t/perf/p0009-diff-pathspec.sh` (creates index with problematic layout; entry count scales via `EXPENSIVE`—1,000 entries by default, 100,000 when `EXPENSIVE` is set)
- **Benchmark**: 100k-entry index, pathspec `aaa/file` as first entry, command `git diff HEAD -- <pathspec>`
- **Performance improvement**: 8 minutes → 0.07 seconds (99.7% speedup) on Chromium-scale repo (~500k index entries)
- **Base commit**: `e90019fcafe0040228b8631c30f97ae1adb61bcd`
- **Safety argument**: The optimization preserves ordering invariants because `find_cache_pos()` advances `.cache_bottom` past unpacked entries (commit `e53e6b4433`)
