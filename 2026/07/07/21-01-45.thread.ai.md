Originating author: Henrique Ferreiro (via GitGitGadget)
Thread type: performance bugfix

Core problem or goal
Eliminate a quadratic-time index scan in `next_cache_entry()` that occurs when `git diff` is run with a pathspec matching a subtree whose entries appear early in the index. The fix introduces a `cache_bottom` field to track scan progress, allowing subsequent calls to skip already-unpacked entries.

Current status
Under review; no prior versions. Patch is self-contained, well-motivated, and includes both a minimal code change (4 lines in `unpack-trees.c`) and a thorough perf regression test (`t/perf/p0009-diff-pathspec.sh`). Junio’s review raises a **critical correctness concern**: the new `cache_bottom` optimization may break when a path’s sorting order differs between the index and tree objects, as the existing `.cache_bottom` field was designed to handle such mismatches. The perf test is otherwise praised but suggested to scale entry count via the `EXPENSIVE` prerequisite.

Key technical details
- **File modified**: `unpack-trees.c`
- **Function modified**: `next_cache_entry()`
- **New field**: `o->internal.cache_bottom` (tracks forward-scan progress)
- **Existing field**: `o->cache_bottom` (handles backward scans and ordering mismatches)
- **Test added**: `t/perf/p0009-diff-pathspec.sh` (creates 100k-entry index with problematic layout; suggested to make entry count configurable via `EXPENSIVE`)
- **Benchmark**: 100k-entry index, pathspec `aaa/file` as first entry, command `git diff HEAD -- <pathspec>`
- **Performance improvement**: 8 minutes → 0.07 seconds (99.7% speedup) on Chromium-scale repo (~500k index entries)
- **Base commit**: `e90019fcafe0040228b8631c30f97ae1adb61bcd`
- **Core concern**: interaction between forward-scan optimization (`cache_bottom`) and existing backward-scan logic (`.cache_bottom`), which may break when index/tree ordering differs
