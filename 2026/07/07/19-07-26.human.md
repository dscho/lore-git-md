This is the second patch in the v7 series that introduces `--linearize` to `git replay`. It is a refactoring patch that moves the logic for resolving the replay base from `pick_regular_commit()` to its caller, `replay_revisions()`.

The patch addresses a readability issue: previously, the base for a replayed commit was determined partly inside `pick_regular_commit()` (by checking the `replayed_commits` map) and partly by its caller (by passing either `onto` or `last_commit` as a fallback). This split logic made the code harder to follow. The refactoring consolidates all base-selection logic into `replay_revisions()`, where it is now clearly documented with a comment explaining the fallback behavior for both regular replay and revert operations.

The change reduces `pick_regular_commit()`'s parameter count from five to four, simplifying its interface. The refactoring is purely internal and introduces no behavior changes -- the commit message explicitly states this, and the diff confirms it. The patch is a preparatory step for the `--linearize` feature in patch 3/3, which will rely on the cleaner base-resolution logic.

This patch has been stable since v5 and has received no substantive feedback in the last two iterations. It is well-motivated, clearly explained, and ready for review. The only prior concern (raised by Patrick Steinhardt in v4) was about the enum-to-bool refactoring in patch 1/3, but that was reverted in v5, leaving this patch unaffected. The series as a whole is technically complete and addresses all prior feedback, so this refactoring should be uncontroversial.
