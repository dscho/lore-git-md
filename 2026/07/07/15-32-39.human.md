This is the seventh patch in Patrick Steinhardt’s 11-patch series making Git’s object database (ODB) optimizations pluggable. It unifies the two existing repacking strategies—traditional incremental repacking and geometric repacking—under a single `odb_optimize()` function, preparing the codebase for future backend-specific implementations.

The patch moves the geometric repacking logic (previously a standalone function `maintenance_task_geometric_repack()`) into `odb_optimize()`, introducing a new `enum odb_optimize_strategy` to distinguish between `ODB_OPTIMIZE_INCREMENTAL` and `ODB_OPTIMIZE_GEOMETRIC`. The `struct odb_optimize_options` gains a `strategy` field to control which repacking method is used. This refactoring eliminates code duplication: the geometric logic now reuses the same `repack_cmd` setup, error handling, and pruning logic as the incremental path, while preserving all existing behavior (including cruft pack handling and multi-pack-index writes).

Tests in `t/t7900-maintenance.sh` are updated to reflect a minor output change: `--quiet` is replaced with `-q` in `git repack` invocations, which is functionally equivalent but aligns with the unified code path. The patch is a clean mechanical refactoring with no user-visible changes, and the commit message clearly explains the motivation—preparing for pluggable optimizations—without overselling the immediate impact. The series remains on track as part of the broader ODB abstraction effort.
