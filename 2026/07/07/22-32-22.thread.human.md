This thread is a bug report from SZEDER Gábor about a severe performance regression in `git fetch`: when fetching incrementally from GitHub’s `git/git` mirror, Git downloads hundreds of thousands of objects (around 300 MiB) even though almost all of them are already present locally. The issue appears to depend on repository state, as it couldn’t be reproduced in a fresh clone, suggesting a bug in object negotiation or packfile generation triggered by specific conditions—possibly related to forced updates on integration branches like `jch`, `next`, and `seen`.

Junio C Hamano has weighed in, noting that while `next` has been rewound recently, `seen` and `jch` are frequently rewound as part of normal workflow, so forced updates alone shouldn’t explain the massive transfer. He suggests ruling out GitHub’s server-side behavior as a first step, implying the issue might lie in how GitHub constructs packfiles rather than in Git’s client-side logic. No root cause has been identified yet, and the thread remains open. The next steps will likely involve deeper debugging of the fetch/pack negotiation process, possibly by contributors like Patrick Steinhardt or Jeff King, who have expertise in this area. For now, the bug is confirmed but unresolved, with no clear path to a fix.
