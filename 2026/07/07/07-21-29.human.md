This is the tenth patch in Patrick Steinhardt’s 13-patch refactoring series to separate repository discovery from setup in Git’s core code. The patch extracts the discovery phase into a new function, `repo_discover()`, making the two-phase structure (discovery vs. configuration) explicit and self-contained.

The change is mechanical: it moves the discovery logic (previously inline in `setup_git_directory_gently()`) into a static helper, `repo_discover()`, which populates a `struct repo_discovery` without touching the repository object. The caller (`setup_git_directory_gently()`) then applies the discovered configuration to the repository. This aligns with the series’ architectural goal of consolidating setup logic into `repo_init()` and reduces scattered state in `setup.c`.

The patch touches only `setup.c` (43 lines changed) and preserves all existing behavior, including error handling for `nongit_ok` and `chdir` failures. It builds on earlier patches that introduced `struct repo_discovery` (patch 5/13) and embedded the repository format into it (patch 6/13). No new symbols are introduced, but the separation sets the stage for future patches (e.g., 11–13/13) to further consolidate setup logic.

This is a well-structured refactoring step with a clear purpose and no apparent downsides. The patch is uncontroversial and likely to be merged as part of the series. Watch for follow-up discussion on whether the new function boundaries handle edge cases (e.g., environment variable overrides, worktree path computation) correctly in later patches.
