This is the first patch in a two-patch bugfix series targeting a performance regression in the commit-graph subsystem. The patch adds trace2 instrumentation to `compute_reachable_generation_numbers()` to expose the cost of the generation-number DFS (depth-first search). This diagnostic tool reveals a regression introduced in commit 199d452758 (April 2025), where incremental commit-graph writes re-walk the entire commit ancestry instead of reading topological levels from lower layers of a split commit-graph chain.

The instrumentation consists of a step counter and a `trace2_data_intmax` call that logs the number of DFS steps taken. The accompanying test in `t/t5324-split-commit-graph.sh` demonstrates the bug: when writing an incremental layer for a commit whose parent exists in the base layer, the DFS walks all the way down to the root (7 steps for 5 base commits) rather than reading the existing topological level and stopping immediately (1 step). This test will later verify the fix in patch 2/2.

The patch touches `commit-graph.c` and the test script, adding 33 lines. The instrumentation is narrowly scoped and does not change behavior—it only makes the existing inefficiency observable. The commit message clearly explains the purpose of the instrumentation and the regression it exposes, providing a concrete reproduction scenario. This is a well-motivated diagnostic patch that sets up the actual fix in the next patch. No controversy or alternative approaches are evident; the patch appears uncontroversial and ready for review.
