This thread is about a performance bugfix for `git diff` that eliminates a quadratic-time index scan in `next_cache_entry()` when using pathspecs matching early index entries. Henrique Ferreiro proposed a minimal 4-line patch introducing a `cache_bottom` field to track scan progress, achieving a 99.7% speedup (from 8 minutes to 0.07 seconds) on large repositories like Chromium.

Junio C Hamano has raised a critical correctness concern: the new optimization might break when the index and tree objects sort paths differently, as the existing `.cache_bottom` logic was designed to handle such mismatches. The patch currently leaves this backward-scan logic unchanged, and Junio questions whether the forward-scan optimization interacts safely with it. This is now the key blocker for the patch, which otherwise appears ready for review. Junio also suggested a minor improvement to the perf test (`t/perf/p0009-diff-pathspec.sh`) to make its entry count configurable via the `EXPENSIVE` prerequisite, following the pattern in `t/perf/p4209-pickaxe.sh`. The patch remains under active review with no prior versions or other participant feedback recorded yet.
