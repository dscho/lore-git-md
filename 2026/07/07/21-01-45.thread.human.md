This thread is about a performance bugfix for `git diff` that eliminates a quadratic-time index scan in `unpack-trees.c`. The issue surfaces when running `git diff` with a pathspec matching a subtree whose entries appear early in the index, causing severe slowdowns in large repositories. Henrique Ferreiro proposed a minimal fix (4 lines in `unpack-trees.c`) that introduces a `cache_bottom` field to track forward-scan progress, skipping already-unpacked entries. The patch includes a perf test and delivers a dramatic speedup—from 8 minutes to 0.07 seconds on a Chromium-scale repository.

Junio Hamano initially raised a critical correctness concern about whether the new optimization would interact safely with the existing `.cache_bottom` logic, which handles index/tree ordering mismatches. Henrique addressed this by arguing that `find_cache_pos()` already advances `.cache_bottom` past unpacked entries, a point Junio now finds "sensible." The only remaining action is to scale the perf test’s entry count via the `EXPENSIVE` prerequisite, as Junio suggested. With the core correctness question resolved, the patch appears ready to land once this minor test improvement is made.
