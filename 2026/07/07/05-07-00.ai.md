This is the fourth patch in Jeff King's seven-patch series refactoring the `git_hash_*()` API to make it more robust. This patch specifically makes `git_hash_discard()` idempotent by adding an `active` flag to the `git_hash_ctx` struct.

The change addresses a long-standing pain point: callers must remember whether they have already finalized or discarded a hash context to avoid double-freeing resources. With this patch, `git_hash_discard()` becomes a no-op if called on an inactive context, allowing cleanup code to safely discard without tracking state. The patch updates all relevant wrapper functions (`git_hash_init()`, `git_hash_final()`, `git_hash_final_oid()`, and `git_hash_discard()`) to set or check the `active` flag, ensuring consistent behavior across the API.

The implementation is minimal and focused: seven lines added across two files (`hash.c` and `hash.h`). The `active` flag is set to `true` during initialization and `false` after finalization or discard. This change is backward-compatible for well-behaved callers but catches misuse (like double-discard) that previously went unnoticed. The patch paves the way for simplifying existing callers in later patches (5–6) and enforcing the invariant via Coccinelle in patch 7.

No behavior changes are expected for end users, and the patch does not touch on-disk formats or user-facing features. The primary impact is internal: reducing the cognitive load for developers working with hash contexts and preventing subtle bugs in error paths. The commit message clearly explains the motivation and the specific pattern this enables (e.g., unconditional cleanup in error paths).
