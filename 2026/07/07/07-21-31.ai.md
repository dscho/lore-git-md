This is the **twelfth patch (12/13)** in Patrick Steinhardt’s **v2 refactoring series** to separate repository discovery from setup in Git’s core code. The patch **passes the worktree path as an explicit parameter to `init_db()`** instead of configuring it indirectly via `set_git_work_tree()`, completing the series’ goal of consolidating repository configuration into a single location.

The change is mechanical but architecturally significant: it eliminates the last remaining case where repository setup (`init_db()`) relied on scattered state rather than explicit parameters. The patch updates `builtin/clone.c` and `builtin/init-db.c` to compute the worktree path upfront and pass it directly to `init_db()`, removing all calls to `set_git_work_tree()` in those files. In `setup.c`, `init_db()` now accepts a `worktree` parameter and applies it immediately after setting the gitdir, ensuring the repository is fully configured in one place. The `setup.h` header is updated to reflect the new signature.

Key details:
- **Files touched**: `builtin/clone.c`, `builtin/init-db.c`, `setup.c`, `setup.h`.
- **New parameter**: `worktree` in `init_db()` (replaces indirect `set_git_work_tree()` calls).
- **Behavioral invariants**: No user-visible changes. The patch preserves existing logic for computing the worktree path (e.g., relative paths in non-bare repos, `xgetcwd()` fallback) and error handling (e.g., `access()` checks).
- **Edge cases**: The patch handles bare repositories (`--bare`) and `--separate-git-dir` correctly, maintaining the existing incompatibility between the two flags.
- **Integration**: This is a direct follow-up to earlier patches (e.g., 7/13, which moved the prefix to `struct repository`) and aligns with the series’ broader goal of eliminating global state.

The patch is uncontroversial in isolation but is critical for the series’ cohesion. It removes the last vestige of the "partially-configured repository" antipattern that the series targets, ensuring all repository configuration happens in `init_db()` or `apply_repository_format()`. No review feedback has been posted yet, but the change is likely to be well-received as it simplifies the call sites in `clone` and `init-db` and makes the setup flow more predictable. Watch for follow-up discussion on whether the new parameter order in `init_db()` is intuitive or if additional callers (e.g., `git submodule`) need similar updates.
