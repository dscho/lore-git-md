This is the second half of a two-patch bugfix series targeting a quadratic performance regression in Git’s reftable backend. The thread’s first patch added test coverage; this reply is Patrick Steinhardt’s self-review of those tests, posted the day after the series was sent.

Patrick identifies two potential issues in the new performance test. First, the test measures both ref creation and deletion, which could skew results—he suggests using `test_when_finished` to move cleanup outside the timed section. Second, the asymmetric test (deleting old refs and creating new ones) runs in the same repository as the symmetric test, so leftover tombstones from the first test could affect the second; he recommends separate repositories to isolate each scenario. Neither issue is critical, but both are worth fixing before the tests land.

The correctness test (`t0610-reftable-basics.sh`) draws a mild question: Patrick wonders whether it adds value, since Git already has many ref creation/deletion tests. The test is small and narrowly scoped to tombstone behavior, so it is unlikely to be controversial, but his comment flags it as potentially redundant.

This self-review is substantive but not deep—it focuses on test mechanics rather than the underlying performance pathology. The tone is constructive and matter-of-fact, treating the issues as minor polish rather than blockers. If the author addresses the points, the test patch should be ready to merge alongside the performance fix in the next iteration.
