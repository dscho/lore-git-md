This is **patch 6/13** in Patrick Steinhardt’s **refactoring series** to separate repository discovery from setup in Git’s core code. The patch embeds `struct repository_format` directly into `struct repo_discovery`, eliminating the need to pass both structures separately to discovery functions. This is a mechanical but foundational change that aligns with the series’ goal of making the discovery phase self-contained.

The patch modifies `setup.c` to store the repository format inside `struct repo_discovery` and updates all discovery functions (`repo_discover_explicit_gitdir`, `repo_discover_implicit_gitdir`, `repo_discover_bare_gitdir`) to use the embedded format instead of a separate parameter. The `REPO_DISCOVERY_INIT` macro is updated to initialize the embedded format, and `repo_discovery_release` now clears it. The change reduces boilerplate in `setup_git_directory_gently`, where the separate `repo_fmt` variable is removed in favor of `discovery.format`.

No behavior changes are intended, and the patch preserves all existing logic for handling misconfigurations (e.g., `core.worktree` + `core.bare`), environment variable overrides, and worktree path resolution. The embedded format is applied to the repository in the same place as before (`apply_repository_format`), and the ref-storage format parsing (e.g., `ref_backend_uri`) remains unchanged. The patch is well-scoped and appears to be a clean step toward consolidating discovery state.

Key symbols introduced/modified:
- `struct repo_discovery` now embeds `struct repository_format format`.
- `REPO_DISCOVERY_INIT` initializes the embedded format.
- `repo_discovery_release` clears the embedded format.
- Discovery functions no longer take a separate `struct repository_format *` parameter.

This patch is part of the series’ broader effort to prepare for consolidating repository setup into `repo_init()`. It touches only `setup.c` and is a prerequisite for later patches (e.g., patch 7/13, which moves the prefix to `struct repository`). The change is low-risk but critical for the series’ architecture.
