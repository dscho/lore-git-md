This is the fourth patch in Patrick Steinhardt’s 11-patch series making object database (ODB) optimizations pluggable. It refactors how `git gc` assembles the arguments it passes to `git repack`, moving the logic from global scope into the `maintenance_task_odb()` helper.

The patch is a pure refactoring: it shuffles roughly 150 lines of code inside `builtin/gc.c` so that the repack argument vector is built inside the helper instead of being passed in from the caller. Two new parameters (`keep_largest_pack` and `aggressive`) are added to the helper to keep the logic self-contained. The commit message is clear and the diff is mechanical, with no intended behavior change.

This is a preparatory step for the broader ODB abstraction effort. By making the repack arguments self-contained, future ODB backends can call `maintenance_task_odb()` without having to duplicate the argument-building logic. The patch looks clean and well-motivated; it should be uncontroversial.
