This is a reply from Patrick Steinhardt to Justin Tobler’s **substantive review** of the second patch in his 13-patch refactoring series. The series aims to separate repository discovery from setup in Git’s core code, and this patch moves "bogus worktree" detection logic into `apply_repository_format()`.

Patrick clarifies two key points raised by Justin. First, he confirms that the patch does not introduce new silent behavior: Git already ignored misconfigurations (both `core.worktree` and `core.bare` set) when `GIT_WORK_TREE` was present, so the change preserves existing behavior. Second, he explains that `apply_repository_format()` is always called eventually, ensuring the validation happens regardless of the call order. The patch’s deferral of the check has no user-visible impact.

The response is concise and directly addresses Justin’s questions, but it leaves the broader architectural questions unanswered—particularly whether the silent override is desirable or if the ordering assumption should be documented. The series remains under active review, and this exchange may prompt further discussion about edge cases in repository initialization. For now, the patch appears technically sound but could benefit from clearer commit message notes about these nuances.
