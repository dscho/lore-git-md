This is the fourth patch in Patrick Steinhardt’s 13-patch refactoring series to separate repository discovery from setup in Git’s core code. The patch splits `setup_git_env_internal()` into two distinct functions: one that configures the repository’s gitdir and propagates environment variables (`apply_gitdir_and_environment()`), and another that sets up global parameters like replace refs and lazy fetching (`setup_environment()`). The latter is moved into `init_git()`, as it only needs to run once during initialization, while the former remains in `setup.c` and is called whenever the gitdir changes (e.g., during `chdir` notifications).

The change is a clean refactoring with no intended behavior changes. It touches `common-init.c` and `setup.c`, renaming and splitting functions to better align with the series’ goal of making repository setup more modular. The patch is well-motivated: the original function’s dual responsibilities made it harder to reason about, and this split paves the way for later patches that consolidate repository configuration into `repo_init()`. No new tests are added, but existing tests (e.g., `t1510-repo-setup.sh`) should verify the refactoring doesn’t break anything.

This patch is uncontroversial and looks ready for merging, assuming the rest of the series holds up. It’s a small but necessary step toward the larger architectural cleanup.
