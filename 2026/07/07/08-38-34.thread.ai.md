Thread identity: security inquiry regarding Git for Windows and libssh2 CVE-2026-55200. Originating author: Martin Berner. Thread type: vulnerability report / security question, not a patch series or design discussion.

Core problem or goal: determine whether Git for Windows (the Windows-specific fork maintained by Johannes Schindelin) is affected by CVE-2026-55200 due to bundling libssh2 1.11.1, and if so, when a patched build will be released. The inquiry has been resolved: Git for Windows is not exposed to the vulnerability in practice, and no remediation is required.

Current status: resolved. Johannes Schindelin confirmed that Git for Windows bundles libssh2 1.11.1 but does not use it in a way that exposes the vulnerability. Martin Berner has acknowledged the explanation, apologized for the tone of his initial inquiry, and closed the loop. No patched release is planned; future updates will follow MSYS2 and upstream libssh2 releases. Todd Zullinger provided additional context that the libssh2 project has not yet released a version incorporating the fix for CVE-2026-55200, but this does not alter the conclusion for Git for Windows.

Key technical details: Git for Windows bundles libssh2 1.11.1 via MSYS2, but the library is only used indirectly through libcurl, and there is no code path in Git’s usage that would trigger the vulnerability described in CVE-2026-55200. The bundled version is the latest upstream release, and no newer version is available from MSYS2. No files, symbols, or subsystems in the upstream Git codebase are implicated. Todd Zullinger linked to an open GitHub issue in the libssh2 repository tracking the request for a new release to distribute recent security fixes, including CVE-2026-55200.

Open questions and loose ends: none. The inquiry is closed. Future updates to libssh2 in Git for Windows will depend on upstream releases and MSYS2 packaging, but no timeline or action is required at this time. The libssh2 GitHub issue remains open as a reference for monitoring upstream progress.
