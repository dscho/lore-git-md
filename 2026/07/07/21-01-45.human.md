This is a **performance bugfix** for `git diff` with pathspecs. The patch eliminates a quadratic-time scan in `next_cache_entry()` that occurs when the pathspec matches a subtree whose entries appear early in the index. On a Chromium-scale repository (500k index entries), the fix reduces runtime from 8 minutes to 0.07 seconds for a command like `git diff HEAD -- .agents/OWNERS`. The regression is guarded by a new perf test (`p0009-diff-pathspec.sh`) that builds a 100k-entry index to verify the fix.

The change itself is minimal: it records the scan position in `o->internal.cache_bottom` so subsequent calls to `next_cache_entry()` skip already-unpacked entries. The commit message is exemplary—it clearly states the problem, the fix, and provides before/after measurements. The test is well-designed, isolating the pathological case without requiring a full Chromium checkout.
