This is the sixth patch in Patrick Steinhardt’s 11-patch series making Git’s object database (ODB) optimizations pluggable. It introduces `struct odb_optimize_options` to isolate the configuration and flags needed for ODB housekeeping (repacking, pruning, etc.) from the generic `gc_config` struct. The patch is a refactoring step: it moves existing logic into the new structure without changing behavior, but the new structure is explicitly designed to be backend-agnostic so that future ODB backends (e.g., reftable or custom storage) can implement their own optimization strategies.

The patch touches only `builtin/gc.c`, adding 120 lines and removing 61. It defines the new `odb_optimize_options` struct with fields for flags (verbose, auto-maintenance, delta reuse), pruning/expiry settings, and backend-specific options like `keep_largest_pack` and `cruft_packs`. The existing `maintenance_task_odb()` helper is split: its core logic moves to a new `odb_optimize()` function that takes the new options struct, while the old helper becomes a thin wrapper that translates `gc_config` and command-line flags into the new format. The patch also updates `maintenance_task_geometric_repack()` to use the new options struct when constructing its repack command.

The commit message notes that some backend-specific options remain in the new struct as a pragmatic concession, since the ODB abstraction is being introduced retroactively. The patch preserves all existing logic, including default values, error handling, and the read-once semantics for configuration values. No new tests are added, as the patch is purely preparatory for future backend work. This is a well-structured refactoring that clearly advances the series’ goal of modular ODB optimizations.
