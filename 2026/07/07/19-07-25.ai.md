This is the first patch in the v7 series introducing `--linearize` to `git replay`. It refactors the replay machinery by extracting a helper function, `put_mapped_commit()`, to encapsulate the logic for storing rewritten commits in the `replayed_commits` map. The existing `mapped_commit()` function is renamed to `get_mapped_commit()` for symmetry.

The change is purely internal and preparatory: it reduces code duplication in `replay_revisions()` and makes the commit-mapping logic clearer. The diff touches only `replay.c`, moving 11 lines of map-handling code into a new static function and updating the single call site. No behavior changes are introduced; this is a mechanical refactoring to simplify the next patch.

The patch is well-motivated and uncontroversial. Prior feedback on earlier versions (notably from Justin Tobler and Patrick Steinhardt) questioned a different refactoring (converting an enum to a boolean), but that concern was resolved by reverting the change in v5. This patch sidesteps that debate entirely and focuses on a straightforward extraction that improves readability without altering semantics. The commit message is concise and accurately describes the change.
