This is Junio’s "What’s cooking in git.git" report for July 2026 (#03), summarising the state of the integration branches.

The report lists 14 topics that have just graduated to the `master` branch, 5 new topics that are ready for review, 2 stalled topics, and 30+ topics still cooking in `next` or `seen`.

Graduated highlights
- **cc/promisor-auto-config-url-more**: promisor-remote now auto-configures unknown remotes and trusts known ones via `promisor.acceptFromServerUrl`.
- **en/ort-harden-against-corrupt-trees**: the ort merge backend now aborts on duplicate tree entries and non-adjacent D/F conflicts.
- **hn/status-pull-advice-qualified**: `git status` now suggests `git pull <remote> <branch>` when the local branch is behind its push branch.
- **jk/repo-info-path-keys**: `git repo info` now outputs both absolute and relative paths for `gitdir` and `commondir`.
- **mv/log-follow-mergy**: `git log --follow` now handles renames in non-linear history more accurately.
- **po/hash-object-size-t**: `git hash-object` now works correctly with objects >4 GB on Windows and other LLP64 platforms.
- **ps/connected-generic-promisor-checks**: connectivity checks now search promisor objects generically, allowing them to work in repositories without packfiles.
- **ps/refs-onbranch-fixes**: reference backend configuration now loads lazily, avoiding chicken-and-egg recursion during repository setup.
- **ps/setup-drop-global-state**: the setup code has dropped remaining global state (`git_work_tree_cfg`, `is_bare_repository_cfg`).
- **tb/pack-path-walk-bitmap-delta-islands**: `git pack-objects --path-walk` now supports reachability bitmaps and delta islands concurrently.

New topics ready for review
- **ds/sparse-index-ita-crash**: fixes a crash in the sparse-index code when encountering an intent-to-add entry outside the cone.
- **ij/subtree-reject-v2-config**: the shell `git subtree` now bails out if it detects the new Rust implementation’s configuration, preventing accidental use of the old script on repositories already managed by the new tool.
- **kk/reftable-tombstone-quadratic-fix**: reftable performance with many deletion tombstones has been optimised by skipping tombstones at higher-level call sites.
- **rs/blame-abbrev-marks**: `git blame` now reserves a column for marks (^, ?, *) only when such marks are actually shown, saving screen space.
- **jm/t0213-skip-emulated-ancestry-tests**: the `TRACE2_ANCESTRY` prerequisite in `t0213` has been refined to avoid failures under user-mode emulation.

Stalled topics
- **ap/http-redirect-wwwauth-fix**: waiting for a response to review comments on preserving `WWW-Authenticate` headers across redirects.
- **jt/config-lock-timeout**: waiting for a response to review comments on retrying configuration file locking.

Cooking highlights
- **bc/parse-options-exit-0-on-help**: `git rev-parse --parseopt` and most subcommands now exit with 0 (not 129) when `-h` or `--help` is given.
- **jk/hash-algo-leak-fixes**: various cryptographic hash contexts that were not finalised are now discarded, plugging memory leaks with non-default backends.
- **ps/t-fixes-for-git-test-long**: expensive tests have been disabled on platforms that lack sufficient resources, and the long test suite is now enabled in GitLab CI.
- **ps/setup-split-discovery-and-setup**: repository discovery and configuration have been split into two phases, paving the way for clean unification of repository setup.
- **pw/rebase-drop-notes-with-commit**: rebase no longer copies notes from commits that are dropped (e.g., because their changes are already upstream).
- **tb/repack-geometric-cruft**: `git repack --geometric --cruft` now works correctly, rolling up non-cruft packs while writing a separate cruft pack.
- **ps/history-drop**: the experimental `git history` command has gained a `drop` subcommand to remove a commit and replay its descendants.
- **ps/refs-writing-subcommands**: `git refs` has been extended with `create`, `delete`, `update`, and `rename` subcommands.
- **ps/cat-file-remote-object-info**: `git cat-file --batch-command` now supports `remote-object-info`, allowing clients to request object metadata from a remote server without downloading the object.
