This is a **build system** and **platform compatibility** follow-up in the ongoing discussion about `USE_NSEC`, the build-time knob that enables sub-second file timestamp tracking in Git. Jeff King (Peff) responds to Patrick Steinhardt’s proposal to make nanosecond timestamp support runtime-configurable, offering a pragmatic path forward.

Peff agrees with Patrick’s incremental approach: first add a runtime config knob (e.g., `core.useNsec`) to let users opt into nanosecond timestamps, then later decide whether to auto-detect or deprecate the build-time option. He is **agnostic about whether the original Meson patch should proceed**—it adds parity with Autotools but may become redundant if `USE_NSEC` is removed entirely. His preference is to **eventually remove `USE_NSEC`** once the runtime config is available, rather than retaining it to tweak the default behavior.

The email does not address the default value for `core.useNsec` (Peff previously suggested a conservative `false` to avoid interoperability risks) or how the config would interact with existing repositories. It also sidesteps the broader debate about whether nanosecond timestamps are still necessary on modern filesystems, where Peff’s own testing showed they work reliably. The focus here is purely on implementation sequencing: runtime config first, then deprecation of the build-time knob.

This reply keeps the discussion moving toward a concrete solution but leaves key questions unresolved—most notably, whether the original patch should merge now or wait for the runtime-configurable alternative. The tone is collaborative, with Peff deferring to the group’s eventual consensus on auto-detection and defaults.
