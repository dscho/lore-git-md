This is the fifth patch in Patrick Steinhardt’s 11-patch series making Git’s object database (ODB) optimizations pluggable. It’s a refactoring patch that moves configuration values specific to the traditional "files" backend out of the generic `struct gc_config` and into the call sites that actually use them.

The patch removes six fields from `gc_config`—`gc_auto_threshold`, `gc_auto_pack_limit`, `repack_filter`, `repack_filter_to`, `big_pack_threshold`, and `delta_base_cache_limit`—and replaces them with local variables in the functions that need them. The config-reading calls (`repo_config_get_int`, `repo_config_get_ulong`, `repo_config_get_string`) are now done directly in the helper functions (`too_many_packs`, `estimate_repack_memory`, `add_repack_all_option`, `need_to_gc`, and `maintenance_task_odb`) rather than once at startup. The patch is purely mechanical and preserves all existing behavior; it just stops forcing every future ODB backend to carry around settings that only the files backend cares about.

The change is clearly motivated by the larger goal of the series: once optimizations are pluggable, each backend should manage its own configuration, not inherit fields from a struct that was designed for a single backend. The patch is small (115 lines changed, all in `builtin/gc.c`) and self-contained; it builds on the earlier patches in the series but doesn’t introduce any new dependencies. Test coverage isn’t touched, which makes sense because the patch doesn’t change what the code does, only where the configuration values live.

This looks like a well-crafted, incremental step toward pluggable ODB optimizations. It’s not flashy, but it’s the kind of cleanup that makes the later patches in the series cleaner and more maintainable. If you care about the ODB abstraction effort, this patch is worth a quick skim to see how the configuration plumbing is being restructured. If you’re just following Git development casually, you can safely skip it—nothing here changes user-visible behavior.
