This is the second patch in the **v7 Rustification build system series**, focusing on **macOS Universal Binary support** for Rust components. It introduces the `RUST_TARGETS` environment variable, allowing users to specify multiple target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`) to compile separate static libraries per architecture and combine them into a single Universal Binary using `lipo`. This aligns Rust’s build process with macOS’s standard distribution practices, ensuring Git can be built as a single artifact that runs natively on both Intel and Apple Silicon Macs without Rosetta.

The patch modifies the `Makefile` to add declarative pattern rules for compiling each target-specific library slice via Cargo, then combines them into `target/release/libgitcore.a` (or `target/debug/`) using `lipo` when multiple targets are specified. The build system now uses `RUST_BUILD_CONFIG` (either `release` or `debug`) to unify the target directory structure, replacing the previous `RUST_TARGET_DIR` variable. Key new symbols include `RUST_TARGETS` (user-facing), `RUST_MEMBER_LIBS` (internal build variable for per-architecture libraries), and `RUST_LIB_NAME` (platform-specific library name, e.g., `libgitcore.a` or `gitcore.lib`). The patch also introduces `mkdir_p_parent_template` to ensure the target directory exists before running `lipo`.

Behavior is cleanly conditional: the feature is a no-op unless `RUST_TARGETS` is set, and it errors out if used on non-macOS platforms (where `lipo` is unavailable). The patch preserves backward compatibility and integrates seamlessly with the rest of the build system, including the parallel build race condition fix from Patch 1. No on-disk format changes or new tests are introduced, though the existing build infrastructure implicitly covers the changes. The implementation assumes `lipo` is available (part of Xcode Command Line Tools), with Xcode 12 (2020) likely required for Apple Silicon support.

This patch directly addresses the **macOS Universal Binary requirement** for Rust components, a practical necessity for CI and distribution workflows. The design is well-scoped and aligns with Cargo’s conventions while meeting macOS’s distribution needs. The unresolved artifact layout question (Patrick Steinhardt’s concern about `target/` directory structure) does not affect functionality, and the current implementation is production-ready.
