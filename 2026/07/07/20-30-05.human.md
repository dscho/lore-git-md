This is the third patch in Patrick Steinhardt’s 11-patch series making Git’s object database (ODB) optimizations pluggable. Junio C Hamano reviews this refactoring patch, which extracts the repack and prune logic from `cmd_gc()` into a new helper function, `maintenance_task_odb()`. The patch is purely structural—no behavior changes—and prepares the codebase for later commits that will move this logic into the ODB abstraction layer.

Junio’s review is surface-level but constructive. He notes that the patch changes how fatal errors are reported: the original code used `die()` directly in `cmd_gc()`, while the new helper function returns an `error()` code, and `cmd_gc()` now calls `die(NULL)` to avoid duplicating the "fatal:" prefix. Junio endorses this change as a clean way to avoid redundant error messages. There are no objections or deeper technical concerns raised; the feedback is minor and non-blocking.

The patch itself is a straightforward code move, relocating 79 lines within `builtin/gc.c` without altering logic. It preserves all existing behavior, including the loose-object warning (though its timing shifts slightly, with no expected practical impact). This is a well-scoped step toward the series’ goal of modularizing ODB housekeeping, and Junio’s feedback suggests it is on the right track. Readers following the ODB abstraction effort will recognize this as a necessary preparatory step for pluggable optimizations.
