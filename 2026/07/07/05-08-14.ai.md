This is the sixth patch in Jeff King’s seven-patch series refactoring the `git_hash_*()` API. It removes the `hash_ctx_valid` flag from the `http_object_request` struct in `http.c` and `http.h`, relying instead on the newly idempotent `git_hash_discard()` introduced in patch 4.

The change is mechanical: the flag was added in a recent commit (a2d8ea5a76) to prevent double-discard of the hash context, but now that `git_hash_discard()` safely handles multiple calls, the flag is redundant. The patch deletes the flag and all its conditional logic, simplifying the cleanup path in `release_http_object_request()`. No behavior change is expected, and the diff is minimal (5 lines removed, 1 line added).

This patch is a straightforward application of the idempotency guarantee established earlier in the series. It touches only the HTTP transport layer and does not interact with other subsystems. The removal of the flag is a clean follow-through on the series’ goal of standardizing hash API usage.
