This is the final patch in Jeff King's seven-patch series refactoring the `git_hash_*()` API to make it more robust. The patch adds defensive checks to all wrapper functions (`git_hash_clone`, `git_hash_update`, `git_hash_final`, and `git_hash_final_oid`) to ensure they are only called on an active hash context. If the `active` flag (introduced in patch 4) is not set, the functions trigger a `BUG()` to catch misuse early.

The change targets a subtle but important correctness issue: while some hash backends (like sha1dc) might tolerate operations on an inactive context, others (like OpenSSL) could exhibit undefined behavior. By enforcing the invariant at the wrapper level, the patch ensures consistent behavior across all backends and prevents latent bugs from surfacing unpredictably. The Coccinelle semantic patch introduced earlier in the series (patch 1) already enforces this pattern, but these explicit checks provide runtime protection and clearer failure modes.

The patch touches only `hash.c`, adding 10 lines of straightforward guard clauses. It does not modify behavior for well-behaved callers but will now loudly fail if a caller attempts to use a context after it has been finalized or discarded. This aligns with the series' goal of standardizing and hardening the hash API, though the commit message notes that `git_hash_init` is intentionally excluded from these checks—calling it twice would leak resources, but the function's contract allows the struct to be in an undefined state beforehand.

No new symbols are introduced; the patch relies on the `active` flag added to `struct git_hash_ctx` in patch 4. The change is purely defensive and has no user-visible impact, but it completes the series' safety improvements by catching misuse at runtime rather than relying solely on compile-time enforcement. The patch is mechanical and well-scoped, fitting neatly into the broader effort to make the hash API more resilient.
