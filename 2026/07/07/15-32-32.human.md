This is the cover letter for an 11-patch series from Patrick Steinhardt that makes Git’s object database (ODB) optimizations pluggable. The goal is to refactor the maintenance machinery so that different ODB backends (e.g., the traditional “files” backend, future reftable-backed storage, or third-party implementations) can each provide their own optimization logic instead of hard-coding everything in `builtin/gc.c`.

The series starts with small preparatory steps: running the “pre-auto-gc” hook for all maintenance tasks, reordering worktree and rerere tasks, and extracting the ODB-specific code into a helper function. It then moves on to make the repack arguments self-contained, inline backend-specific config values, and introduce a new `odb_optimize()` API that takes a set of optimization options. Geometric repacking is moved into this new function, and a predicate `odb_optimize_required()` is added to decide whether optimization is needed. The final patches refactor the existing “files” backend to implement the new interface, fix some signedness issues, and wire up the pluggable infrastructure in `odb.c`.

The diffstat shows a net reduction of almost 450 lines in `builtin/gc.c`, offset by new files in the `odb/` directory that encapsulate the “files” backend’s optimization logic. The test suite (`t7900-maintenance.sh`) gains new coverage for the pluggable hooks.

This is a refactoring patch series that lays the groundwork for future ODB backends; it does not change user-visible behavior. The commit messages are terse but the code changes look mechanical and well-scoped. If you care about the ODB abstraction effort or plan to work on alternative storage backends, this series is worth following.
