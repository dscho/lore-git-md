This is a follow-up in the ongoing bug report about an incremental `git fetch` unexpectedly downloading hundreds of thousands of objects. Junio C Hamano, the Git maintainer, replies to SZEDER Gábor’s detailed report but offers no clear explanation.

Junio notes that while the `next` branch was recently rewound, the `seen` and `jch` branches are *constantly* rewound, so the forced updates alone shouldn’t explain the massive download. He suggests eliminating GitHub’s server-side behavior as a first step in debugging, implying the issue might lie in how GitHub’s mirror generates packfiles rather than in Git’s client-side negotiation logic. However, he doesn’t propose a specific cause or next step.

The thread remains unresolved, with the core mystery intact: why did the fetch transfer ~300 MiB of objects when only ~1,400 were new? Junio’s response doesn’t challenge Gábor’s analysis but doesn’t advance it either. The focus now shifts to whether the problem is reproducible outside GitHub’s infrastructure or if it’s tied to server-side packfile generation. Contributors working on object negotiation (e.g., Patrick Steinhardt or Jeff King) may need to weigh in to determine if this is a client-side regression or a server-side quirk. For now, the report stands as a credible, well-documented performance issue with no clear resolution.
