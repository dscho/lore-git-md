This is a small but important refactoring in Patrick Steinhardt’s 11-patch series making Git’s object database (ODB) optimizations pluggable. The patch reorders two maintenance tasks—worktree pruning and rerere garbage collection—so they run *before* ODB optimizations (repacking, auto-gc) rather than after. This grouping is preparatory work for later patches that will extract all ODB-related logic into a modular, backend-agnostic layer.

Junio C Hamano’s reply endorses the broader direction, noting that Git’s `gc` and `maintenance` commands have evolved beyond pure ODB optimization to include general housekeeping (reflog, packed-refs, reftable compaction, etc.). He sees this reordering as a logical step toward making those tasks pluggable, aligning with the series’ goal of modularizing ODB optimizations.

The patch itself is mechanical—moving 14 lines of code within `cmd_gc()`—and preserves existing behavior. Patrick acknowledges a theoretical edge case where pruning worktrees earlier might make objects unreachable that would otherwise have been kept alive, but dismisses it as negligible in practice. No test changes are needed here; the expanded test suite in patch 1 already validates the reordering’s correctness.

This is a well-motivated, low-risk change that sets the stage for the series’ later refactorings. The discussion so far is constructive, with no objections raised. If you’re tracking the ODB abstraction effort, this patch is worth noting as a foundational step, but it’s unlikely to spark controversy on its own.
