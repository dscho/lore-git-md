This is the second patch in the **v7 Rustification build system series**, focusing on **macOS Universal Binary support** for Rust components. It introduces the `RUST_TARGETS` environment variable, allowing users to specify multiple target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`) to produce a single Universal Binary static library (`libgitcore.a`) via `lipo`. This matches macOS distribution standards and enables native execution on both Intel and Apple Silicon Macs without Rosetta.

The patch is **well-motivated and technically sound**. The commit message clearly explains the gap between Cargo’s single-target model and macOS’s Universal Binary expectations, and the implementation is clean: it adds declarative pattern rules to compile each target slice separately, then combines them with `lipo` if multiple targets are specified. The build remains a no-op when `NO_RUST=1` is set, and the patch errors out gracefully on non-macOS platforms if `RUST_TARGETS` is misused. The use of `mkdir_p_parent_template` ensures directories exist before `lipo` runs, avoiding race conditions.

This is a **build-system-only change** with no on-disk format or runtime behavior implications. It touches only the `Makefile` and is implicitly covered by existing build tests. The unresolved artifact layout question (Patrick Steinhardt’s concern about `target/` directory structure) does not affect functionality, and the current design aligns with practical macOS distribution needs. The patch is **ready for integration** and complements the series’ other fixes (parallel build race condition and CI verification). If you care about Rust support on macOS, this is worth reviewing.
