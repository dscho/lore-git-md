This is the second patch in Patrick Steinhardt’s 11-patch series making Git’s object database (ODB) optimizations pluggable. It is a small, focused refactoring that reorders two maintenance tasks—worktree pruning and rerere garbage collection—so they run *before* object database optimizations (repacking, auto-gc) rather than after.

The change is preparatory: later patches in the series will move all ODB-related optimization logic out of `builtin/gc.c` and into a new backend-agnostic layer. By grouping these tasks first, the code becomes easier to extract. The commit message acknowledges a theoretical edge case—pruning worktrees before object optimizations could make objects unreachable that would otherwise have been kept alive—but dismisses it as negligible in practice. The patch itself is mechanical: it moves 14 lines of code (7 added, 7 removed) within the same function, with no new behavior or API changes. Test coverage is not touched here; the validation for this reordering is handled by the expanded test suite in patch 1.
