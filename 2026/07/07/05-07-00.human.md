This is the fourth patch in Jeff King’s seven-patch series refactoring the `git_hash_*()` API. It makes `git_hash_discard()` idempotent by adding an `active` flag to the `git_hash_ctx` struct. When `git_hash_init()` is called, the flag is set to `true`; when either `git_hash_final()` or `git_hash_discard()` is called, it is set to `false`. Subsequent calls to `git_hash_discard()` on an inactive context become no-ops.

The change is a straightforward internal refactoring with no user-visible behavior change. It simplifies error-handling paths for callers, allowing them to unconditionally call `git_hash_discard()` in cleanup code without worrying about whether the context has already been finalized. The patch itself is small (seven lines added) and mechanical, adding the flag and updating the three functions that transition the context out of the active state.

This patch is the technical centerpiece of the series: the remaining patches (5–7) will rely on this idempotence to clean up existing callers and enforce the invariant via Coccinelle. The commit message clearly explains the motivation and the intended usage pattern, making it easy for reviewers to assess the change in isolation.
