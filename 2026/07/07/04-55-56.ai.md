This is a refactoring and cleanup series from Jeff King (Peff) targeting the `git_hash_*()` API. The series makes `git_hash_discard()` idempotent (safe to call multiple times) and cleans up inconsistent usage of the hash API across the codebase. It builds on Peff’s earlier `jk/hash-algo-leak-fixes` branch and touches 24 files, including core object-writing code (`csum-file.c`, `http.c`), built-ins (`fast-import`, `index-pack`, `receive-pack`), and test helpers.

The motivation stems from a recent subthread where Peff identified that `git_hash_discard()` could leave the hash context in an inconsistent state if called twice. The series first standardizes all callers to use the `git_hash_*()` wrapper functions (patches 1–3), then makes `git_hash_discard()` idempotent (patch 4), and finally updates callers to rely on the new behavior (patches 5–7). A Coccinelle semantic patch (patch 7) enforces that all wrapper functions check the `ctx->active` flag, preventing future regressions.

Key technical details: the `git_hash_ctx` struct now tracks an `active` flag; `git_hash_discard()` sets it to zero, and all wrapper functions (`git_hash_update()`, `git_hash_final()`, etc.) return early if the context is inactive. This change is backward-compatible for well-behaved callers but catches double-discard bugs that previously went unnoticed. The series also removes a redundant `http.h` declaration and documents the function-pointer nature of the hash-algo vtable.

The patches are mechanical and focused, with clear commit messages explaining each step. The Coccinelle rule is a strong signal that Peff intends this to be a one-time cleanup rather than an ongoing maintenance burden. No behavior changes are expected for end users, but the series should make the code more robust against future misuse of the hash API.
