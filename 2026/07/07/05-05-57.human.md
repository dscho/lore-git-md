This is the third patch in Jeff King’s seven-patch series refactoring the `git_hash_*()` API. It is a documentation update to `hash.h` that shifts the focus from the raw function pointers in the `git_hash_algo` struct to the wrapper functions (`git_hash_init()`, `git_hash_clone()`, etc.) that the rest of the series is standardizing on.

The patch adds clear, actionable comments for each wrapper: when to call it, what state the context must be in, and what cleanup is required. It also documents two subtle requirements that surfaced during the series: the destination of `git_hash_clone()` must already be initialized, and every hash context must eventually be either finalized or discarded to avoid resource leaks. Finally, it adds a prominent warning that the low-level function pointers are implementation details and should not be called directly—Coccinelle will enforce this in a later patch.

The change is small (32 insertions, 11 deletions) and purely additive; no code behavior is altered. It is a natural follow-up to the mechanical conversions in patches 1 and 2, giving future readers a clear roadmap before the semantic-patch enforcement lands in patch 7. The patch looks well-motivated and uncontroversial.
