This is the **v2 cover letter** for Patrick Steinhardt’s 13-patch **refactoring series** that splits repository discovery from setup in Git’s core code. The series is part of the ongoing effort to clean up `setup.c` and consolidate repository configuration into `repo_init()`.

The v2 update addresses feedback from the initial submission:
- Expanded the commit message for patch 3/13 to clarify the precedence order between the `GIT_SHALLOW_FILE` environment variable and the `--shallow-file` command-line switch (command-line takes precedence, matching existing behavior).
- Removed an unused parameter in `set_alternate_shallow_file()`.
- Fixed a typo in patch 2/13 ("exlicitly" → "explicitly").

The series remains focused on separating the two phases of repository setup:
1. **Discovery**: Populates a new `struct repo_discovery` with the repository’s location and format, without touching any repository state.
2. **Setup**: Uses the discovery results to configure the repository object, making the process more modular and self-contained.

Key changes in v2 are minor but important for clarity and correctness. The series is well-motivated, with clear commit messages and a logical progression of patches. It builds on recent work like `ps/setup-drop-global-state` and `jk/repo-info-path-keys`, and aligns with broader goals like `the_repository` removal and ODB abstraction. No behavior changes are intended, but the refactoring could expose edge cases in repository initialization.

The series has already received **substantive reviews** from Justin Tobler on patches 1–3, 5, and 7/13, with Patrick addressing most feedback. Junio C Hamano queued patch 2/13 after fixing the typo. The remaining patches are likely to generate discussion about the new `repo_discovery` API and its implications for future setup logic. This is a foundational refactor worth watching for anyone interested in Git’s internals.
