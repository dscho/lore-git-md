This is the fourth patch in Patrick Steinhardt’s 11-patch series making object database (ODB) optimizations pluggable, part of the ongoing ODB abstraction effort. It refactors `builtin/gc.c` to eliminate global state in the repack argument assembly, moving the logic into the `maintenance_task_odb()` helper introduced in patch 3.

The patch is a pure refactoring: it removes the global `strvec repack_args` and instead builds the repack command-line inside `maintenance_task_odb()`, which now takes two additional parameters (`keep_largest_pack` and `aggressive`). The `need_to_gc()` helper is simplified to drop its `repack_args` parameter, since the decision whether to repack is now decoupled from the argument construction. The diff is large (156 lines changed) but mechanical, with no intended behavior change.

Key technical details: the patch touches only `builtin/gc.c`, removing the global `repack_args` vector and replacing it with local construction inside `maintenance_task_odb()`. The function signature changes from `(struct maintenance_run_opts *, struct gc_config *, struct strvec *)` to `(struct maintenance_run_opts *, struct gc_config *, int, int)`, reflecting the new self-contained design. The logic for incremental vs full repack, aggressive repack flags, and memory estimation remains identical; it is merely relocated.

This refactoring is a prerequisite for the pluggable ODB optimization system: by making the repack logic self-contained, future backends can call `maintenance_task_odb()` without worrying about global state or interdependencies. The patch is well-motivated in the context of the series and appears clean, though the diff is dense enough that reviewers may want to verify edge cases (e.g., memory estimation logic, pack selection) remain intact. No new tests are added, as the patch is behavior-preserving.
