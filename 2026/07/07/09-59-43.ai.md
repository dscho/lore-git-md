This is the second patch in a two-patch bugfix series targeting a performance regression in the commit-graph subsystem. The regression was introduced in commit 199d452758 (April 2025) as part of the `ps/commit-graph-via-source` series and affects split commit-graph chains. The issue causes the `topo_levels` slab to be incorrectly propagated only to the topmost layer of the chain, forcing `compute_reachable_generation_numbers()` to re-walk the entire ancestry of commits parsed from lower layers during incremental writes.

The fix is a one-line change in `commit-graph.c`: replacing `g->topo_levels` with `chain->topo_levels` in the loop that propagates the slab across all layers of the commit-graph chain. This aligns the loop variable with the other loops in the same refactoring and ensures the `topo_levels` pointer is set for every layer, not just the topmost. The commit message provides clear technical context, quantifies the performance impact (a 3.7-second slowdown on a large repository), and explains the root cause: commits parsed from lower layers had their topological levels left at zero in the slab, triggering unnecessary DFS re-walks.

The patch also updates the test in `t/t5324-split-commit-graph.sh` to reflect the corrected behavior. The test now expects only 1 DFS step (down from 7) when writing an incremental commit-graph, verifying that the fix works as intended. The test file change removes the BUG comment and updates the expected trace2 output to match the new behavior.

This is a narrowly scoped, well-motivated fix for a real performance regression. The commit message is thorough, citing the exact commit that introduced the bug, explaining the mechanism, and providing reproduction context. The patch touches only the affected code path and includes test coverage to prevent regression. The series appears uncontroversial and ready for review, with no open questions or alternative approaches mentioned. Users with `fetch.writeCommitGraph` enabled or those running `git maintenance` after fetch are the primary beneficiaries.
