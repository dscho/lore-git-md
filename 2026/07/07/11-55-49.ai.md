This is a security inquiry response about Git for Windows and its bundled libssh2 dependency, specifically addressing CVE-2026-55200. Johannes Schindelin, the Git for Windows maintainer, replies to Martin Berner’s question.

The response clarifies that while Git for Windows does bundle libssh2 1.11.1, the library is only used indirectly through libcurl, and there is no code path in Git’s usage that would expose libssh2 functionality. Schindelin therefore considers the vulnerability non-critical for Git for Windows and does not plan to rush a patched release. He also explains that Git for Windows relies on MSYS2 for its dependencies, and MSYS2 currently only provides libssh2 1.11.1, which is the latest upstream release according to libssh2’s official sources.

The tone of the reply is direct, particularly in addressing the phrasing of Berner’s original question ("when can a patched build be expected"), which Schindelin describes as potentially entitled. He emphasizes that the inquiry demands work from an open-source project without offering assistance, a dynamic he cautions against. The response also includes links to MSYS2’s package repository and libssh2’s official release page to support the explanation.

No patch, code change, or technical discussion about the CVE itself is provided. The thread remains a security inquiry rather than a vulnerability remediation effort. The key takeaway is that Git for Windows is not exposed to CVE-2026-55200 in practice, and no immediate action is planned. Future updates to libssh2 in Git for Windows will depend on upstream releases and MSYS2 packaging.
