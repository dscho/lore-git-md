This is the **final patch (13/13)** in Patrick Steinhardt’s 13-patch refactoring series to separate repository discovery from setup in Git’s core code. The patch **removes `set_git_work_tree()` from the public API** by marking it as `static` in `setup.c` and deleting its declaration from `setup.h`. This is a mechanical cleanup following patch 12/13, which eliminated the last external callers of the function by consolidating worktree configuration into `init_db()`.

The change is straightforward: the function is now file-local, reflecting its reduced scope after the series’ architectural changes. No behavior changes are introduced, and the patch preserves the existing logic for validating and setting the worktree path (e.g., realpath resolution, `repo->worktree_initialized` checks). The removal of the public declaration signals that `set_git_work_tree()` is no longer part of Git’s stable internal API, aligning with the series’ goal of consolidating repository setup into `repo_init()` and related functions.

This patch completes the series’ primary objective: **decoupling discovery (finding the repository) from setup (configuring it)**. The new `struct repo_discovery` and its associated functions (`repo_discover()`, `apply_repository_format()`) now handle discovery results without partially configuring the repository, while `init_db()` and `apply_repository_format()` manage setup. The removal of `set_git_work_tree()` from the public API is a symbolic milestone, reinforcing that worktree configuration is now an internal implementation detail of `setup.c`.

For future discussion, watch for:
- **API stability**: Whether other subsystems (e.g., `git submodule`) might still rely on indirect worktree configuration patterns that could break in edge cases.
- **Integration with ongoing efforts**: How this refactoring interacts with `the_repository` removal (e.g., ensuring `the_repository` is fully configured before use) and ODB abstraction (e.g., repository initialization order).
- **Edge cases**: Handling of environment variable overrides (e.g., `GIT_WORK_TREE`) or symlinks in worktree paths, though these are preserved by the series’ invariants.

The patch is uncontroversial and likely to be merged as-is, but its significance lies in what it represents: the culmination of a carefully structured refactoring that paves the way for further cleanup in `setup.c`.
