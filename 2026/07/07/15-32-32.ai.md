This is the cover letter for an 11-patch series from Patrick Steinhardt that makes object database (ODB) optimizations pluggable. The series is part of the ongoing ODB abstraction effort, restructuring how Git manages object storage to allow alternative backends beyond the traditional loose-object and packfile storage.

The goal here is to extract the logic for object housekeeping—tasks like repacking, geometric repacking, and auto-gc—into a modular system where different ODB backends can implement their own optimization strategies. The series touches `builtin/gc.c` heavily, moving most of the existing optimization logic into a new `odb/source-files.c` file (470 lines added) while shrinking `builtin/gc.c` by 466 lines. It also introduces new ODB-related headers (`odb.h`, `odb/source.h`, `odb/source-files.h`) and a small API in `odb.c` to support the pluggable design.

Key technical details: the series introduces an `odb_optimize()` function to encapsulate optimization tasks, an `odb_optimize_required()` helper to determine when optimizations are needed, and a new `struct odb_source_files` to hold backend-specific configuration. The commit messages note that the changes are preparatory for future backends (like reftable or custom storage systems) but do not themselves introduce any new backends. The series also fixes signedness issues in ODB-related code and refactors the "pre-auto-gc" hook to run for all maintenance tasks, not just gc.

The patch set is self-contained and builds on the start of the Git 2.56 cycle (commit `f85a7e6620`). No prior cover letter or thread context was provided, so the full scope of the ODB abstraction effort isn’t visible here, but this series is clearly a major step toward making optimizations backend-agnostic. The changes are mechanical and focused on refactoring rather than new behavior, though the test file `t/t7900-maintenance.sh` sees significant expansion (143 lines added), suggesting thorough validation of the new structure.
