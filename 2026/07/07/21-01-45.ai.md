This is a **performance bugfix** targeting the `unpack-trees` subsystem, specifically the `next_cache_entry()` function. The patch eliminates a quadratic-time index scan that occurs when running `git diff` with a pathspec matching a subtree whose entries appear early in the index. The fix is simple: track how far the scan has progressed (`cache_bottom`) so subsequent calls skip already-unpacked entries.

The commit message provides a clear, quantified motivation: on a Chromium-scale repository (~500k index entries), `git diff HEAD -- .agents/OWNERS` improved from **8 minutes to 0.07 seconds**. The regression test (`p0009-diff-pathspec.sh`) creates a 100,000-entry index with the problematic layout and confirms the fix, showing a **99.7% speedup** in the perf test.

The change itself is minimal—just **4 lines added** in `unpack-trees.c`—and the test coverage is thorough. The patch is well-motivated, self-contained, and addresses a real-world performance cliff. It looks ready for serious review and likely to land quickly.
