This is a **test-focused follow-up** in the reftable backend performance regression thread. Kristofer Karlsson, the patch author, responds to Patrick Steinhardt’s review of the test suite in the first patch of the two-patch series.

Kristofer acknowledges the review’s points about test isolation and measurement clarity. He agrees to split the performance test (`p1401-ref-store-tombstones.sh`) into more granular benchmarks, separating ref creation from deletion to avoid conflating their timings, and to use fresh repositories for each scenario to prevent tombstone carry-over from skewing results. These changes will sharpen the performance data, making it easier to pinpoint the regression’s impact.

On the correctness test (`t0610-reftable-basics.sh`), Kristofer pushes back slightly: he couldn’t find existing tests that cover the specific *delete-then-recreate* flow where tombstones are present during recreation. While Git has many tests for ref creation and deletion in isolation, none appear to target the tombstone interaction edge case this patch addresses. The test’s necessity hinges on whether this gap is real or just overlooked.

The response keeps the thread moving toward resolution, with Kristofer signaling willingness to revise the tests while defending their core purpose. No new technical concerns about the fix itself are raised.
