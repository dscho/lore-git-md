This thread is a cleanup and hardening series from Jeff King (Peff) that refactors Git’s `git_hash_*()` API to make it more robust and consistent. The series addresses a long-standing issue where `git_hash_discard()` was not idempotent—calling it multiple times could leave the hash context in an inconsistent state. Peff’s patches standardize the API’s behavior, improve its documentation, and add defensive runtime checks to catch misuse early. The series is now in its final stages, with all substantive feedback addressed.

Junio C Hamano, the maintainer, reviewed the patches and raised a design question about the asymmetry in patch 7/7: why `git_hash_discard()` is allowed after `git_hash_final()` but `git_hash_final()` cannot be called twice. Peff clarified that this asymmetry is intentional, reflecting the different purposes of the two functions—`git_hash_final()` produces a meaningful result (a hash), while `git_hash_discard()` is purely for cleanup. Calling `git_hash_final()` on a discarded context is treated as a programming error and triggers a `BUG()`, whereas `git_hash_discard()` is safe to call repeatedly. This explanation resolved Junio’s question, and no further changes are expected unless new concerns arise.

The series touches 33 files across Git’s core object-writing code, built-ins, and test infrastructure. It introduces no user-visible behavior changes but makes the API more resilient against misuse.
