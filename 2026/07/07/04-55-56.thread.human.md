This thread is a seven-patch series from Jeff King (Peff) that refactors Git’s `git_hash_*()` API to make it safer and more consistent. The series addresses a long-standing issue where `git_hash_discard()` was not idempotent—calling it twice could leave the hash context in an inconsistent state, risking undefined behavior in some backends (like OpenSSL). The goal is to standardize usage of the API, make `git_hash_discard()` idempotent, and add runtime checks to catch misuse early.

The series is now complete and under review. The first three patches lay the groundwork by converting callers to use wrapper functions and improving documentation in `hash.h` to guide developers toward safe usage. Patch 4 introduces an `active` flag to `git_hash_ctx` to make `git_hash_discard()` idempotent, while patches 5 and 6 apply this change to simplify cleanup logic in `csum-file.c` and remove a redundant `hash_ctx_valid` flag from the HTTP transport layer. The final patch, just posted, adds defensive checks to all wrapper functions to ensure they are only called on an active context, triggering a `BUG()` if not. This provides runtime protection against misuse, complementing the Coccinelle semantic patch introduced earlier in the series.

The changes touch 29 files across core object-writing code, built-ins, test helpers, and Coccinelle tooling. No user-visible behavior changes are expected, and there are no on-disk format changes. The series is mechanical and focused, with clear commit messages and no open questions or loose ends identified so far. Peff’s motivation stems from a prior subthread highlighting the non-idempotent behavior of `git_hash_discard()`, and the series is designed to be a one-time cleanup with no ongoing maintenance burden.
