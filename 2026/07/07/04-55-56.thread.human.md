This thread is a cleanup and refactoring series from Jeff King (Peff) that makes the `git_hash_*()` API safer and more consistent. The series began after Peff noticed that `git_hash_discard()` wasn’t idempotent—calling it twice could leave the hash context in a broken state. The seven-patch series, now at its second version, fixes this by adding an `active` flag to the `git_hash_ctx` struct, standardizes usage by replacing direct calls to low-level hooks with public wrapper functions, and adds defensive runtime checks to catch misuse early.

The changes touch 26 files, including core object-writing code, built-in commands, and test helpers. No user-visible behavior changes are expected, and the series is ready for integration after addressing all review feedback in v2. Junio C Hamano, Patrick Steinhardt, and Brian M. Carlson reviewed the patches; while some feedback was cosmetic (typos, unnecessary braces), Brian provided useful historical context about why direct `init_fn()` calls were used in Rust bindings. That constraint is now resolved, clearing the way for the cleanup. The series is a one-time effort with no ongoing maintenance burden.
