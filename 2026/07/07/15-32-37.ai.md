This is the fifth patch in Patrick Steinhardt’s 11-patch series making object database (ODB) optimizations pluggable. It is a refactoring patch that moves configuration values specific to the "files" ODB backend out of the generic `gc_config` struct and into the call sites that actually use them.

The patch removes eight fields from `struct gc_config`: `gc_auto_threshold`, `gc_auto_pack_limit`, `repack_filter`, `repack_filter_to`, `big_pack_threshold`, `max_delta_cache_size`, and `delta_base_cache_limit`. These values are now read directly from the repository configuration at the point of use in functions like `too_many_packs()`, `estimate_repack_memory()`, `need_to_gc()`, and `maintenance_task_odb()`. The changes are mechanical and preserve all existing logic, including default values and error handling.

The motivation is clean separation of concerns: the generic `gc_config` struct should not carry backend-specific knobs. This prepares the codebase for future ODB backends (e.g., reftable or custom storage) that will not need or want these "files"-specific settings. The patch is a prerequisite for the pluggable optimization logic introduced later in the series.

No new behavior or user-visible changes are introduced. The patch touches only `builtin/gc.c` (115 lines changed) and is behavior-preserving by design. Reviewers may wish to verify that the relocated config reads do not introduce subtle edge cases (e.g., config values changing mid-run), though the patch maintains the same read-once semantics as the original code.
