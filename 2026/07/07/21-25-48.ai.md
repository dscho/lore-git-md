This is a brief reply in the `git_hash_*()` API refactoring thread, clarifying the historical reason for the direct `init_fn()` calls that the series is now eliminating.

Brian m. carlson explains that the Rust bindings (used in Git’s Rustification effort) treat `const struct git_hash_algo *` as an opaque `const void *`, preventing access to the `init_fn` field. This forced Rust code to call `algop->init_fn()` directly rather than using the `git_hash_init()` wrapper. While this technical constraint could be resolved with `cbindgen` or `bindgen`, it has not yet been addressed, which is why direct `init_fn()` calls have persisted. Brian endorses the series’ goal of standardizing on `git_hash_init()` as the public interface going forward.

The comment provides useful context for the series’ motivation but does not raise any technical objections or suggest changes. It is a surface-level clarification rather than a substantive review.
