This is the third patch in Jeff King's seven-patch series refactoring the `git_hash_*()` API. It focuses on improving the documentation in `hash.h` to guide developers toward using the wrapper functions (`git_hash_init()`, `git_hash_clone()`, etc.) instead of directly invoking the function pointers in the `git_hash_algo` struct. The patch also adds practical usage notes, such as the requirement to initialize the destination context before calling `git_hash_clone()` and the obligation to finalize or discard a hash context to avoid resource leaks.

The changes are purely documentary—no code behavior is altered. The patch replaces terse, pointer-centric comments with clear, actionable guidance for callers, explicitly warning against direct use of the low-level hooks. This aligns with the series' broader goal of standardizing and hardening the hash API, and it sets the stage for the Coccinelle semantic patch (introduced in patch 7) that will enforce wrapper usage. The updated documentation also reflects insights Peff gained while working on the series, such as the need to initialize clone destinations and the resource-management implications of hash contexts.
