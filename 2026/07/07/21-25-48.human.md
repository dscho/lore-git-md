This is a small but meaningful refactoring patch in Jeff King’s ongoing series to clean up and harden Git’s `git_hash_*()` API. The patch mechanically converts all direct calls to `algop->init_fn()` into the wrapper function `git_hash_init()`, using a new Coccinelle semantic patch to enforce consistency. This is the first step in a seven-patch series that will eventually make `git_hash_discard()` idempotent and add defensive runtime checks to the hash API.

The motivation here is practical: the Rust bindings for Git currently treat `const struct git_hash_algo *` as an opaque `const void *`, which means they can’t access the `init_fn` field directly. The `git_hash_init()` wrapper was created to work around this limitation, but many callers still bypass it and call `init_fn` directly. This patch standardizes the codebase on the wrapper, preparing the ground for future logic (like an `active` flag) that will be added to `git_hash_init()` in later patches. Brian M.
