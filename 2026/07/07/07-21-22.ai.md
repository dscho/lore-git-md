This is **patch 3/13 in Patrick Steinhardt’s v2 refactoring series** to separate repository discovery from setup. The patch unifies shallow-file configuration by moving it entirely into `apply_repository_format()`, eliminating the redundant handling in `handle_options()` and `setup_git_env_internal()`.

The change is mechanical: the `--shallow-file` command-line option now sets the `GIT_SHALLOW_FILE` environment variable instead of calling `set_alternate_shallow_file()` directly, and `apply_repository_format()` reads that variable. The patch also removes the `override` parameter from `set_alternate_shallow_file()` since it is no longer needed (the environment variable is always set with overwrite semantics). The commit message clarifies that the precedence order—command-line options overriding environment variables—is preserved, despite appearances.

This is a **refactoring patch** with no intended behavior change. It touches `git.c`, `setup.c`, `shallow.c`, and `shallow.h`, and is part of the series’ broader goal of ensuring `the_repository` contains no relevant state before `apply_repository_format()` is called. Justin Tobler’s substantive review of v1 raised questions about environment-variable design and shallow-file precedence; Patrick’s reply addressed the precedence concern but left the design question unresolved. The patch itself is uncontroversial, but the unresolved design discussion may resurface in later iterations.
