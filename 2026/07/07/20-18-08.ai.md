This is Jeff King's reply to Junio C Hamano's review of the fourth patch in his seven-patch series refactoring the `git_hash_*()` API. The patch makes `git_hash_discard()` idempotent by adding an `active` flag to the `git_hash_ctx` struct, allowing cleanup code to safely discard a hash context without tracking whether it was already finalized.

Jeff clarifies the design intent behind the patch, confirming that the goal is indeed to allow `git_hash_discard()` to be called even after `git_hash_final()`. He acknowledges that the example in the commit message could have been clearer and provides a more realistic scenario where the cleanup is split across multiple functions, making it difficult for `foo_release()` to know whether the hash was already finalized. This reinforces the need for idempotent behavior in `git_hash_discard()`.

Jeff also addresses Junio's question about the asymmetry between `git_hash_discard()` and `git_hash_final()`, explaining that while `git_hash_discard()` is now protected from multiple calls, `git_hash_final()` remains unprotected because calling it multiple times is a bug. This aligns with the patch's goal of catching misuse early rather than silently allowing it. The response references a separate part of the thread where this behavior is discussed in more detail, indicating that the design is intentional and well-considered.

The email does not introduce any new changes to the patch but provides important context for understanding its motivation and design.
