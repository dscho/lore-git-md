This is the first patch in Patrick Steinhardt’s 11-patch series making ODB optimizations pluggable. It fixes a long-standing inconsistency in how the "pre-auto-gc" hook is invoked: currently the hook only runs for `git gc` and the "gc" maintenance task, but the hook’s intent is to block *any* automated housekeeping. The patch extends the hook to run once, before the first auto-maintenance task that would actually execute, regardless of whether that task is reflog expiry, geometric repack, or rerere gc.

The change is mechanical: `need_to_gc()` no longer calls `run_hooks()`; instead the hook is invoked inside `maybe_run_task()` when the auto-flag is set and the task’s auto-condition is satisfied. A new `enum auto_gc_hook_result` tracks whether the hook has already run (or decided to skip everything), ensuring it fires exactly once per `git maintenance run --auto`. The test file `t/t7900-maintenance.sh` gains 121 lines covering all combinations: hook succeeds, hook fails, no maintenance needed, and explicit `--auto` vs non-auto runs.

This patch is a small but necessary step toward the series’ larger goal: once optimizations are pluggable, the hook must guard every backend’s housekeeping, not just the files backend’s gc. The change is backward-compatible and does not alter on-disk format or user-visible behavior beyond the hook’s expanded scope.
