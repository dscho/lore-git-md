This thread is a 12-patch series from Patrick Steinhardt titled "Make ODB optimizations pluggable," which restructures Git's object database (ODB) to allow different backends to implement their own optimization strategies. The series is part of the ongoing ODB abstraction effort and aims to extract existing optimization logic (repacking, geometric repacking, auto-gc) into a modular system, enabling future backends like reftable or custom storage to define their own housekeeping tasks.

The first version of the series received feedback from Junio C Hamano on the first three patches, particularly noting test brittleness due to reliance on `GIT_TRACE2_EVENT` checks. This has been addressed in the v2 series by introducing a new `test_maintenance_tasks` helper in the first patch, which directly verifies task execution via trace2 output, making the test suite more robust. The rest of the series remains focused on mechanical correctness and test reliability, with no design-level objections raised. The patches progressively refactor `builtin/gc.c` to isolate repack and prune logic, eliminate global state, relocate backend-specific configuration reads, introduce a unified `odb_optimize()` entry point, and finally relocate the optimization logic into the "files" ODB source backend.

The series is currently under review, with no prior versions merged. It is a prerequisite for pluggable ODB backends and preserves all existing logic, including geometric split factors, cruft pack handling, and auto-condition checks. The only remaining open point from v1 was the test brittleness, which has been resolved in v2. Reviewers may still wish to verify the parameterized ODB optimization helpers and the final relocation of logic, though the patches maintain identical behavior to the original code paths. Patrick Steinhardt is the sole author and has addressed all feedback from Junio so far.
