This is the final patch in Jeff King’s seven-part series refactoring the `git_hash_*()` API. It adds defensive checks to all wrapper functions (`git_hash_clone`, `git_hash_update`, `git_hash_final`, and `git_hash_final_oid`) to ensure they are only called on an active hash context. If the `ctx->active` flag is not set, the code triggers a `BUG()` to catch misuse early.

The patch is small (10 lines added to `hash.c`) and mechanical, following the pattern established in earlier patches. It complements the Coccinelle semantic patch introduced in patch 1, which enforces the same invariant at the call-site level. The checks are especially valuable because different hash backends (e.g., OpenSSL vs. sha1dc) behave differently when misused—some silently corrupt data, while others crash. This change standardizes the failure mode to a loud, consistent `BUG()` on every build.

The commit message explains why `git_hash_init` is exempt: its purpose is to initialize an undefined struct, so calling it twice is both unlikely and less harmful (it would leak memory, but not corrupt state). The rest of the series has already made `git_hash_discard` idempotent, so the only remaining risk is calling the other wrappers on an inactive context.
