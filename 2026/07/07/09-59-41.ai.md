This is a two-patch bugfix series targeting the commit-graph subsystem. The cover letter identifies a regression introduced in commit 199d452758 (April 2025) as part of the `ps/commit-graph-via-source` series. The bug causes the `topo_levels` slab to be incorrectly propagated only to the topmost layer of a split commit-graph chain, rather than to all layers. This forces `compute_reachable_generation_numbers()` to re-walk the entire ancestry of commits parsed from lower layers, resulting in a measurable performance degradation—from 4133ms to 233ms for an incremental commit-graph write on a large repository with a 4-layer split graph.

The fix itself is in the second patch: it corrects the loop variable in the propagation logic to use `chain` instead of `g`, aligning it with the other loops in the same refactoring. The first patch adds trace2 instrumentation to help diagnose similar issues in the future. The series touches `commit-graph.c` and adds a new test in `t/t5324-split-commit-graph.sh` to verify the fix.

The regression affects users with `fetch.writeCommitGraph` enabled or those running `git maintenance` after fetch, as both trigger incremental commit-graph writes. The commit message provides clear reproduction context, cites the exact commit that introduced the bug, and includes a link to the original series for reference. The performance impact is quantified, and the fix is narrowly scoped to the identified issue. No controversy or alternative approaches are mentioned, suggesting this is a straightforward correction. The series is well-motivated and appears ready for review.
