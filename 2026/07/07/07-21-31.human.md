This is the **twelfth patch in Patrick Steinhardt’s v2 refactoring series** to separate repository discovery from setup in Git’s core code. The patch makes `init_db()` accept an explicit `worktree` parameter instead of relying on `set_git_work_tree()` to propagate the worktree path after the fact. This aligns with the series’ goal of consolidating repository configuration into a single phase, mirroring the earlier refactoring of discovery logic.

The change is mechanical but consequential: it removes scattered calls to `set_git_work_tree()` in `builtin/clone.c` and `builtin/init-db.c` and centralizes worktree assignment inside `init_db()`. The patch also simplifies `cmd_init_db()` by computing the worktree path earlier and passing it directly to `init_db()`, eliminating redundant path resolution and freeing logic. The `--separate-git-dir` check for bare repositories is now handled inline rather than in a separate branch.

No behavior changes are intended, and the patch preserves all existing invariants (e.g., worktree accessibility checks, bare repository constraints). The diff is clean, touching only the four files shown, and the commit message clearly explains the motivation: eliminating the "antipattern" of partial configuration. This is a logical follow-up to earlier patches (notably 5–11/13) that introduced `struct repo_discovery` and consolidated gitdir/worktree setup.

The patch looks well-crafted and uncontroversial, but watch for follow-up discussion about whether the new `worktree` parameter should be made mandatory (currently it’s optional, matching the existing `set_git_work_tree()` behavior). The series’ final patch (13/13) will remove `set_git_work_tree()` entirely, so this patch is a necessary stepping stone.
