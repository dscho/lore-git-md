Thread identity: bugfix series for commit-graph regression in split commit-graph chains; 2 patches; originating author Kristofer Karlsson; thread type: patch series.

Core problem or goal: fix a performance regression in the commit-graph subsystem introduced by commit `199d452758` (September 2025) in the `ps/commit-graph-via-source` series. The bug causes the `topo_levels` slab to be incorrectly propagated only to the topmost layer of a split commit-graph chain, forcing `compute_reachable_generation_numbers()` to re-walk the entire ancestry of commits parsed from lower layers. This degrades performance from 233ms to 4133ms for an incremental commit-graph write on a large repository with a 4-layer split graph.

Current status: ready for merge; series at v1, awaiting v2 with corrected commit message (date misstatement: April 2025 → September 2025). Junio C Hamano’s clarification request has been resolved; he marked the topic as "Expecting a reroll" and is ready to merge once v2 is posted. Patch 1/2 adds trace2 instrumentation for diagnostics; Patch 2/2 fixes the loop variable in the propagation logic to use `chain` instead of `g`, ensuring the `topo_levels` slab is propagated to all layers of the split commit-graph chain. The test in `t/t5324-split-commit-graph.sh` is restructured to use `test_expect_failure` in patch 1/2 and flip to `test_expect_success` in patch 2/2, demonstrating the fix. Taylor Blau and Patrick Steinhardt reviewed both patches: Taylor approved Patch 2/2 as "obviously good" and suggested an exploratory architectural change (moving `topo_levels` from `commit_graph` to `write_commit_graph_ctx`) to prevent similar bugs, which Kristofer Karlsson deferred as a non-blocking follow-up; Patrick Steinhardt confirmed the fix as correct and the test change as sensible, calling the bug "embarrassing" and endorsing the series. Kristofer later analyzed three refactoring paths for Taylor’s suggestion—threading the slab through the call chain, attaching it to `struct object_database`, or introducing a dedicated chain-wide struct—but concluded the current one-line fix remains the best near-term solution. The series is uncontested and ready for merge once the commit-message correction is implemented.

Key technical details:
