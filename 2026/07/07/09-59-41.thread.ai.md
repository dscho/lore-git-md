Thread identity: bugfix series for commit-graph regression in split commit-graph chains; 2 patches; originating author Kristofer Karlsson; thread type: patch series (post-merge discussion on patch presentation style and review ergonomics).

Core problem or goal: fix a performance regression in the commit-graph subsystem introduced by commit `199d452758` (September 2025) in the `ps/commit-graph-via-source` series, where the `topo_levels` slab was incorrectly propagated only to the topmost layer of a split commit-graph chain, degrading incremental commit-graph write performance from 233ms to 4133ms on large repositories with deep split graphs.

Current status: merged to `master` as of the v2 series. Post-merge discussion has shifted to review ergonomics: Taylor Blau advocates for splitting a failing test and its fix into separate commits when either the test setup or the bugfix is non-trivial, while Junio C Hamano highlights a trade-off in the initial review experience on the mailing list. When a patch email shows limited context, a reviewer seeing a multi-line test body with `test_expect_failure` in the first patch and a flip to `test_expect_success` in the second may struggle to understand the behavioral change, especially if the test setup is complex. Junio frames this as a tension between author convenience and reviewer clarity given the project’s imbalance between patch volume and reviewer capacity. The discussion remains stylistic and non-blocking; no further code changes are required or proposed.

Key technical details:
- Files touched: `commit-graph.c`, `t/t5324-split-commit-graph.sh`.
- Subsystem: commit-graph (split commit-graph chains).
- New symbols: trace2 instrumentation in `compute_reachable_generation_numbers()` (step counter, `trace2_data_intmax` call).
- Old behavior: `topo_levels` slab propagated only to topmost layer of split commit-graph chain; incremental writes re-walk entire commit ancestry via DFS.
- New behavior (after patch 2/2): `topo_levels` slab correctly propagated to all layers; DFS stops early when topological levels are available, restoring original performance.
- On-disk format: no changes.
- Test coverage: updated test in `t/t5324-split-commit-graph.sh` uses `test_expect_failure` in patch 1/2 and flips to `test_expect_success` in patch 2/2 to verify the fix (1 DFS step expected after patch 2/2). The stylistic debate centers on whether to restructure the test to assert expected behavior in Patch 1/2, reducing Patch 2/2 to a minimal flip, versus preserving the current structure for diff readability.
- Affected workflows: users with `fetch.writeCommitGraph` enabled or running `git maintenance` after fetch.

Open questions and loose ends: none for the immediate fix. The architectural follow-up discussion continues: Taylor Blau endorsed Kristofer Karlsson’s exploration of moving the `topo_levels` slab from `struct commit_graph` to `struct object_database` (option b) as the most promising of the three refactoring paths, but noted that the commit-slab API’s current global treatment may not yet align with the ODB abstraction effort. This refactoring is deferred as a follow-up. The post-merge discussion now includes a debate on whether to formalize guidance about splitting failing tests and fixes into separate commits in `Documentation/SubmittingPatches` or `Documentation/CodingGuidelines`; no consensus has been reached, and no action is required.
