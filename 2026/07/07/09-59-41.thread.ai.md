Thread identity: bugfix series for commit-graph regression in split commit-graph chains; 2 patches; originating author Kristofer Karlsson; thread type: patch series.

Core problem or goal: fix a performance regression in the commit-graph subsystem introduced by commit `199d452758` (September 2025) in the `ps/commit-graph-via-source` series. The bug causes the `topo_levels` slab to be incorrectly propagated only to the topmost layer of a split commit-graph chain, forcing `compute_reachable_generation_numbers()` to re-walk the entire ancestry of commits parsed from lower layers. This degrades performance from 233ms to 4133ms for an incremental commit-graph write on a large repository with a 4-layer split graph.

Current status: merged to `master` as of the v2 series posted by Kristofer Karlsson via GitGitGadget. The v2 reroll addressed Junio C Hamano’s clarification request by correcting the commit-message metadata (date misstatement: April 2025 → September 2025). Patch 1/2 adds trace2 instrumentation for diagnostics; Patch 2/2 fixes the loop variable in the propagation logic to use `chain->topo_levels` instead of `g->topo_levels`, ensuring the `topo_levels` slab is propagated to all layers of the split commit-graph chain. The test in `t/t5324-split-commit-graph.sh` is restructured to use `test_expect_failure` in patch 1/2 and flip to `test_expect_success` in patch 2/2, demonstrating the fix.

Key technical details:
- Files touched: `commit-graph.c`, `t/t5324-split-commit-graph.sh`.
- Subsystem: commit-graph (split commit-graph chains).
- New symbols: trace2 instrumentation in `compute_reachable_generation_numbers()` (step counter, `trace2_data_intmax` call).
- Old behavior: `topo_levels` slab propagated only to topmost layer of split commit-graph chain; incremental writes re-walk entire commit ancestry via DFS.
- New behavior (after patch 2/2): `topo_levels` slab correctly propagated to all layers; DFS stops early when topological levels are available, restoring original performance.
- On-disk format: no changes.
- Test coverage: updated test in `t/t5324-split-commit-graph.sh` uses `test_expect_failure` in patch 1/2 and flips to `test_expect_success` in patch 2/2 to verify the fix (1 DFS step expected after patch 2/2).
- Affected workflows: users with `fetch.writeCommitGraph` enabled or running `git maintenance` after fetch.

Open questions and loose ends: none. The architectural proposal by Taylor Blau (moving the `topo_levels` field from `commit_graph` to `write_commit_graph_ctx`) was explored by Kristofer Karlsson but deferred as a follow-up; the exploration confirmed the current approach is sufficient for now.
