Thread identity: bugfix series for commit-graph regression in split commit-graph chains; 2 patches; originating author Kristofer Karlsson; thread type: patch series (post-merge discussion on patch presentation style, review ergonomics, and architectural follow-ups).

Core problem or goal: fix a performance regression in the commit-graph subsystem introduced by commit `199d452758` (September 2025) in the `ps/commit-graph-via-source` series, where the `topo_levels` slab was incorrectly propagated only to the topmost layer of a split commit-graph chain, degrading incremental commit-graph write performance from 233ms to 4133ms on large repositories with deep split graphs. Post-merge discussion has expanded to include review ergonomics (splitting failing tests and fixes into separate commits) and architectural follow-ups (refactoring the `topo_levels` slab to align with the ODB abstraction effort).

Current status: merged to `master` as of the v2 series. The immediate bugfix is complete, but post-merge discussion continues on two fronts: (1) stylistic debate about whether to formalize guidance on splitting failing tests and fixes into separate commits, with Taylor Blau advocating for the practice and Junio C Hamano highlighting trade-offs in reviewer clarity given the project’s patch volume; (2) architectural exploration of moving the `topo_levels` slab from `struct commit_graph` to `struct object_database` or a chain-wide struct, with Patrick Steinhardt raising deeper questions about whether commit graphs are a property of the ODB or a specific backend. No further code changes are required or proposed at this time.

Key technical details:
- Files touched: `commit-graph.c`, `t/t5324-split-commit-graph.sh`.
- Subsystem: commit-graph (split commit-graph chains).
- New symbols: trace2 instrumentation in `compute_reachable_generation_numbers()` (step counter, `trace2_data_intmax` call).
- Old behavior: `topo_levels` slab propagated only to topmost layer of split commit-graph chain; incremental writes re-walk entire commit ancestry via DFS.
- New behavior (after patch 2/2): `topo_levels` slab correctly propagated to all layers; DFS stops early when topological levels are available, restoring original performance.
- On-disk format: no changes.
- Test coverage: updated test in `t/t5324-split-commit-graph.sh` uses `test_expect_failure` in patch 1/2 and flips to `test_expect_success` in patch 2/2 to verify the fix (1 DFS step expected after patch 2/2). The stylistic debate centers on whether to restructure the test to assert expected behavior in Patch 1/2, reducing Patch 2/2 to a minimal flip, versus preserving the current structure for diff readability.
- Architectural context for follow-ups: the ODB abstraction effort, the commit-slab API’s global treatment, and the potential need to detangle commit-graph internals to support pluggable backends (e.g., distributed or alternative storage systems).
- Affected workflows: users with `fetch.writeCommitGraph` enabled or running `git maintenance` after fetch.

Open questions and loose ends:
- Stylistic: whether to formalize guidance in `Documentation/SubmittingPatches` or `Documentation/CodingGuidelines` about splitting failing tests and fixes into separate commits. No consensus has been reached; no action is required.
- Architectural: whether commit graphs are inherently a property of the object database or of a specific backend. Patrick Steinhardt outlines two long-term paths—making commit graphs pluggable as a standalone mechanism or treating them as a backend property—but does not commit to either. The discussion remains exploratory and non-blocking; the merged bugfix stands.
