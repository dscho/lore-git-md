Thread identity: bugfix series for commit-graph regression in split commit-graph chains; 2 patches; originating author Kristofer Karlsson; thread type: patch series (post-merge discussion on patch presentation style, review ergonomics, tooling improvements, and architectural follow-ups).

Core problem or goal: fix a performance regression in the commit-graph subsystem introduced by commit `199d452758` (September 2025) in the `ps/commit-graph-via-source` series, where the `topo_levels` slab was incorrectly propagated only to the topmost layer of a split commit-graph chain, degrading incremental commit-graph write performance from 233ms to 4133ms on large repositories with deep split graphs. Post-merge discussion has expanded to include review ergonomics (splitting failing tests and fixes into separate commits), tooling improvements (context expansion in patch emails), and architectural follow-ups (refactoring the `topo_levels` slab to align with the ODB abstraction effort).

Current status: merged to `master` as of the v2 series. The immediate bugfix is complete. Post-merge discussion is now resolved on all fronts: (1) the stylistic debate about splitting failing tests and fixes is settled in favor of preserving atomic commits, with Junio C Hamano’s demonstration of reviewer-side tooling (`git show ':!t/' | git apply -R && make test`) accepted as sufficient; (2) the tooling exploration for selective context expansion is dropped after Kristofer Karlsson acknowledged the existing workflow meets the need; (3) architectural exploration of moving the `topo_levels` slab remains open but non-blocking, with no immediate action required.
