Thread identity: bugfix series for commit-graph regression in split commit-graph chains; 2 patches; originating author Kristofer Karlsson; thread type: patch series.

Core problem or goal: fix a performance regression in the commit-graph subsystem introduced by commit 199d452758 (April 2025, `ps/commit-graph-via-source`). The bug causes the `topo_levels` slab to be incorrectly propagated only to the topmost layer of a split commit-graph chain, forcing `compute_reachable_generation_numbers()` to re-walk the entire ancestry of commits parsed from lower layers. This degrades performance from 233ms to 4133ms for an incremental commit-graph write on a large repository with a 4-layer split graph.

Current status: under review; series at v1. Patch 1/2 adds trace2 instrumentation for diagnostics; Patch 2/2 fixes the loop variable in the propagation logic to use `chain` instead of `g`, ensuring the `topo_levels` slab is propagated to all layers of the split commit-graph chain. Taylor Blau reviewed both patches: approved Patch 2/2 as "obviously good" and suggested an exploratory architectural change (moving `topo_levels` from `commit_graph` to `write_commit_graph_ctx`) to prevent similar bugs, which Kristofer Karlsson deferred as a non-blocking follow-up. The series remains uncontested. Open questions about trace2 instrumentation type (`intmax_t` vs `uintmax_t`) and test structure (`test_expect_failure`) are now resolved: Kristofer Karlsson confirmed the current `intmax_t` implementation is sufficient for diagnostic purposes and agreed to restructure the test using `test_expect_failure` to assert the expected behavior (1 DFS step) rather than documenting the incorrect behavior (7 steps) as a comment.

Key technical details:
- Files touched: `commit-graph.c`, `t/t5324-split-commit-graph.sh`.
