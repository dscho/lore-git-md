Thread identity: bugfix series for commit-graph regression in split commit-graph chains; 2 patches; originating author Kristofer Karlsson; thread type: patch series.

Core problem or goal: fix a performance regression in the commit-graph subsystem introduced by commit 199d452758 (April 2025, `ps/commit-graph-via-source`). The bug causes the `topo_levels` slab to be incorrectly propagated only to the topmost layer of a split commit-graph chain, forcing `compute_reachable_generation_numbers()` to re-walk the entire ancestry of commits parsed from lower layers. This degrades performance from 233ms to 4133ms for an incremental commit-graph write on a large repository with a 4-layer split graph.

Current status: under review; series at v1. Patch 1/2 adds trace2 instrumentation for diagnostics; Patch 2/2 fixes the loop variable in the propagation logic to use `chain` instead of `g`, ensuring the `topo_levels` slab is propagated to all layers of the split commit-graph chain. Taylor Blau reviewed both patches: approved Patch 2/2 as "obviously good" but suggested an exploratory architectural change (moving `topo_levels` from `commit_graph` to `write_commit_graph_ctx`) to prevent similar bugs. Kristofer Karlsson acknowledged the suggestion but deferred it as a non-blocking follow-up, prioritizing the immediate fix. The series remains uncontested. Trace2 instrumentation refinements (use of `uintmax_t` instead of `intmax_t`) and test structure (restructure as `test_expect_failure`) remain open for Patch 1/2.

Key technical details:
- Files touched: `commit-graph.c`, `t/t5324-split-commit-graph.sh`.
- Subsystem: commit-graph (split commit-graph chains).
- New symbols: trace2 instrumentation in `compute_reachable_generation_numbers()` (step counter, `trace2_data_intmax` call).
- Old behavior: `topo_levels` slab propagated only to topmost layer of split commit-graph chain; incremental writes re-walk entire commit ancestry via DFS.
- New behavior (after patch 2/2): `topo_levels` slab correctly propagated to all layers; DFS stops early when topological levels are available, restoring original performance.
- On-disk format: no changes.
- Test coverage: updated test in `t/t5324-split-commit-graph.sh` demonstrates the regression (7 DFS steps for 5 base commits) and verifies the fix (1 step expected after patch 2/2). Taylor proposes restructuring the test to use `test_expect_failure` for clarity.
- Affected workflows: users with `fetch.writeCommitGraph` enabled or running `git maintenance` after fetch.
