Core problem or goal: fix a performance regression in the commit-graph subsystem introduced by commit `199d452758` (September 2025) in the `ps/commit-graph-via-source` series, where the `topo_levels` slab was incorrectly propagated only to the topmost layer of a split commit-graph chain, degrading incremental commit-graph write performance from 233ms to 4133ms on large repositories with deep split graphs. Post-merge discussion has resolved review ergonomics and tooling questions but remains open on architectural alignment: whether commit-graph optimizations (row-oriented layout, `topo_levels` slab) are tied to specific object-store backends or whether fundamental commit attributes (generation numbers) should be exposed as a standalone API decoupled from the commit-graph format.

Current status: merged to `master` as of the v2 series. The immediate bugfix is complete. Post-merge discussion is now resolved on stylistic and tooling fronts but continues on architectural conceptual boundaries. Taylor Blau’s follow-up clarifies that generation numbers are a fundamental commit attribute independent of storage format, while optimizations like MIDX or reachability bitmaps are backend-specific. No immediate code changes are proposed; the discussion remains exploratory and non-blocking.
