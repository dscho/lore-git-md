This thread is about a two-patch bugfix series from Kristofer Karlsson that addresses a performance regression in Git's commit-graph subsystem. The regression, introduced by commit `199d452758` in September 2025, causes the `topo_levels` slab to be incorrectly propagated only to the topmost layer of a split commit-graph chain, forcing unnecessary re-walks of commit ancestry and degrading incremental commit-graph write performance from 233ms to 4133ms on large repositories.

The series is now uncontested and ready for merge. Patch 1/2 adds trace2 instrumentation for diagnostics, while Patch 2/2 fixes the loop variable in the propagation logic to ensure the `topo_levels` slab is correctly propagated to all layers of the split commit-graph chain. The test in `t/t5324-split-commit-graph.sh` was updated to demonstrate the fix, flipping from `test_expect_failure` to `test_expect_success` after the fix is applied. Taylor Blau reviewed both patches, approving Patch 2/2 as "obviously good" and suggesting an architectural refactor (moving `topo_levels` to `write_commit_graph_ctx`) as a non-blocking follow-up, which Kristofer deferred. Junio C Hamano requested a minor correction to the commit message (fixing the date from April to September 2025) and is now awaiting a rerolled v2. Once posted, the series is expected to merge without further delay. No on-disk format changes are involved, and the fix restores the original performance behavior.
