This thread is a two-patch bugfix series from Kristofer Karlsson that addresses a performance regression in Git’s commit-graph subsystem, specifically in split commit-graph chains. The regression was introduced by commit `199d452758` (September 2025) in the `ps/commit-graph-via-source` series and caused a dramatic slowdown—from 233ms to 4133ms—for incremental commit-graph writes in large repositories with multi-layer split graphs. The root cause was a mispropagation of the `topo_levels` slab, which forced unnecessary re-walking of commit ancestry.

The fix itself is a one-line change in `commit-graph.c`, replacing a loop variable to ensure the `topo_levels` slab is correctly propagated to all layers of the split chain. The accompanying test in `t/t5324-split-commit-graph.sh` demonstrates the fix by flipping from `test_expect_failure` to `test_expect_success`. Taylor Blau reviewed the patch as "obviously good," and Junio C Hamano raised no technical objections after a minor clarification about the commit OID in the commit message was resolved. Kristofer plans to post a v2 with the corrected commit message, after which the series is ready for merge.

The only loose end was an architectural suggestion from Taylor Blau to move the `topo_levels` field from `commit_graph` to `write_commit_graph_ctx` to reduce future mispropagation risk. Kristofer explored three refactoring paths but deferred them as follow-ups, concluding the current fix is the best near-term solution. The series is uncontested, touches only `commit-graph.c` and its test file, and has no on-disk format changes. It affects users with `fetch.writeCommitGraph` enabled or those running `git maintenance` after fetch.
