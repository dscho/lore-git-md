This thread began as a bugfix series addressing a performance regression in Git's commit-graph subsystem, where a mispropagated `topo_levels` slab in split commit-graph chains caused incremental writes to slow from 233ms to over 4 seconds in large repositories. The two-patch series, authored by Kristofer Karlsson, was merged to `master` after a quick v2 update to correct a commit message error. The fix itself—a one-line change to propagate the slab correctly—was uncontroversial and endorsed by reviewers Taylor Blau and Patrick Steinhardt.

Since merging, the discussion has shifted to broader questions of patch presentation and review ergonomics. Kristofer proposed tooling improvements to selectively expand context in patch emails, aiming to balance atomic commits with reviewer clarity. Junio C Hamano has consistently pushed back, arguing that the existing workflow already supports the desired outcome: reviewers can isolate tests and observe pre-fix behavior by temporarily reverting code changes while keeping the test intact. He demonstrated this with a concrete command (`git show ':!t/' | git apply -R && make test`) and cautioned that artificially expanding context or splitting commits risks merge conflicts without adding value. Taylor Blau has advocated for formalizing the practice of splitting failing tests and fixes into separate commits, while Patrick Steinhardt raised deeper architectural questions about whether commit graphs should be tied to the object database or treated as a backend property—though these remain exploratory and non-blocking.

The thread is now purely discussion-driven, with no further code changes planned. The core tension—whether to prioritize atomic commits or reviewer clarity—remains unresolved, but Junio’s latest response reinforces his view that the project’s existing tooling is sufficient and that the burden should lie with reviewers to adapt their workflows rather than authors to restructure patches. The conversation may inform future updates to `Documentation/SubmittingPatches`, but no immediate guidance is expected.
