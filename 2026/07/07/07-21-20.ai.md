This is a refactoring patch, part 1 of a 13-patch series by Patrick Steinhardt. It renames `check_repository_format_gently()` to `read_and_verify_repository_format()` to better reflect the function’s dual purpose: reading the repository format from disk and then verifying its consistency. The patch also reorders the parameters so the `struct repository_format *` comes first, aligning with other functions that pass this structure around.

The change is mechanical and confined to `setup.c`, touching only the function definition and its seven call sites. The commit message explains the motivation clearly: the old name could mislead readers into thinking the function only validates an already-populated format, whereas it actually populates the structure from the repository’s config file before checking it.

No behavior change is introduced; this is purely a readability and API-clarity improvement. The patch is well-contained and unlikely to be controversial. It sets the stage for the rest of the series, which appears to be splitting repository discovery and setup logic.
