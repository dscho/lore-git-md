This is a refactoring and cleanup series from Jeff King (Peff) that improves the `git_hash_*()` API. The series makes `git_hash_discard()` idempotent (safe to call multiple times) and cleans up inconsistent usage of the hash API across the codebase.

The motivation stems from a recent discussion about fixing hash-algorithm leaks, and this series builds on those fixes. Patch 1-3 standardize how the hash API is initialized and called, patch 4 implements the idempotent behavior for `git_hash_discard()`, and patches 5-7 update callers to rely on this new safety. The final patch adds a defensive check to all wrapper functions to catch misuse early.

The series touches 24 files, including core object-writing code (`csum-file.c`, `http.c`), built-ins (`fast-import`, `index-pack`, `receive-pack`), and test helpers. A new Coccinelle semantic patch (`tools/coccinelle/hash.cocci`) is included to help enforce consistent usage going forward.

This looks like a well-crafted, focused cleanup. The commit messages are detailed, the changes are mechanical but non-trivial, and the series addresses a real technical debt issue rather than inventing new functionality. Peff is a long-time contributor with deep knowledge of Git's internals, so the patches are likely to be solid. The only potential friction might be if other ongoing work conflicts with these API changes, but the series is small enough that such conflicts should be easy to resolve.
