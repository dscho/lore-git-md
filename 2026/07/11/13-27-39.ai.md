This is the fourth patch in the **ready-to-merge v6 series** optimizing `paint_down_to_common()` for one-sided histories. It adds **regression tests** for the side-exhaustion optimization, ensuring the function correctly handles cases where one merge-base candidate is an ancestor of another and that the optimization does not regress when the commit-graph is disabled.

The patch introduces a new test script, `t6099-merge-base-side-exhaustion.sh`, which verifies two key behaviors:
1. **Ancestor exclusion**: When multiple merge-base candidates exist (e.g., `B` and `C` in the test graph), and one is an ancestor of another, `git merge-base --all` correctly excludes the ancestor (`C`) from the output, returning only the shallowest candidate (`B`). This exercises the interaction between the side-exhaustion optimization and the `remove_redundant` safety net in `get_merge_bases_many_0`.
2. **Commit-graph dependency**: The side-exhaustion optimization relies on generation numbers, so it is disabled when the commit-graph is absent (generation numbers default to `INFINITY`). The test confirms that `git merge-base --all` still produces correct results in this case, though without the performance benefit.

The test graph is carefully constructed to trigger the optimization: `A` and `X` are the tips, with `B` and `C` as merge-base candidates. `B` reaches `C` via `d1`, so `B` should be the sole output. The test runs in three modes:
- With the commit-graph (optimization enabled).
- Without the commit-graph (optimization disabled, fallback to correct but slower behavior).
- Single-result mode (`git merge-base` without `--all`), which should return the shallowest candidate (`B`).

The patch also updates `t/meson.build` to include the new test script in the build system. There are no code changes to Git’s core logic—this is purely test coverage. The tests are **deterministic** and **self-verifying**, using `test_cmp` to compare expected and actual outputs.

This patch complements the edge-case tests added in patch 3/10 (already summarized) and the performance-focused tests in `t6600` (updated in this series). It is a **low-risk, high-value addition**, addressing a specific regression scenario identified during the series’ development.
