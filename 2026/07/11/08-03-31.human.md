This is a design discussion about Git's default behavior. Jeff King (Peff) replies to Omri Sarig's question about why Git porcelain commands like `git log` default to showing the *author date* rather than the *committer date*.

Peff explains that in a mailing-list-based workflow (the original and still dominant contribution model for Git itself), the committer date is less meaningful because it reflects when the maintainer applied the patch, not when the author wrote it. By analogy, Git also shows the author's name by default, not the committer's. This suggests the current default is a deliberate choice aligned with the project's own workflow, not a historical accident.

The reply is brief but authoritative, coming from a long-time contributor with deep knowledge of Git's history and design principles. It does not propose a change or explore alternative workflows, but it provides a clear rationale for the status quo. The thread remains open for further discussion about whether this default still makes sense for other workflows (e.g., rebase-heavy teams).
