This is the fifth patch in the **ready-to-merge v6 series** optimizing `paint_down_to_common()` in Git’s commit-reach subsystem. The patch adds **Trace2 instrumentation** to measure the number of commits visited during the paint walk, enabling deterministic performance analysis without relying on wall-clock benchmarks.

The change is minimal and surgical: it introduces a `steps` counter in `paint_down_to_common()` (incremented for each commit processed) and emits the total via `trace2_data_intmax()`. The accompanying test updates (`t/t6600-test-reach.sh`) extend the existing `run_all_modes` helper to capture Trace2 output for each commit-graph mode (`none`, `full`, `half`, `no-gdat`) and add a new `test_paint_down_steps` helper to assert step counts deterministically. Two existing tests (`in_merge_bases_many:self` and a new `merge-base --all` test) now verify step counts, ensuring the instrumentation works across all commit-graph configurations.

This patch is **purely additive**—it neither changes the algorithm’s behavior nor introduces new dependencies. The instrumentation is lightweight (a single counter and Trace2 call) and serves as a foundation for future optimizations, including the side-exhaustion early termination added later in the series. The test coverage is thorough, validating step counts in both symmetric and asymmetric merge-base queries.

The patch is **fully reviewed and uncontroversial**, with no open feedback. It complements the series’ broader goal of making `paint_down_to_common()` more observable and maintainable. The only minor note is that the test helper (`test_paint_down_steps`) was introduced in an earlier patch (v6 02/10), so this patch’s test changes depend on that infrastructure. The series remains **regression-free** and **ready to merge**.
