This is the third patch in the **ready-to-merge v6 series** optimizing `paint_down_to_common()` for one-sided histories. It adds **edge-case test coverage** to `t6600-test-reach.sh` for the side-exhaustion logic introduced earlier in the series.

The patch exercises four specific scenarios:
- **Self-reference**: A commit is both the query target and one of the inputs (e.g., `in_merge_bases_many(A, X)` where `A` is also in `X`).
- **Duplicate inputs**: The `X` list contains repeated commits, testing deduplication and queue stability.
- **Pending-stale transition**: A diamond topology (`ps-*`) where a commit transitions from `(PARENT1|PARENT2)` to `(PARENT1|PARENT2|STALE)` during the walk, ensuring the STALE propagation does not corrupt the queue.
- **Infinity-gate fallback**: A topology (`pi-*`) where both query tips are outside the commit-graph, forcing a fallback to non-monotonic commit-date ordering. This verifies the algorithm handles `GENERATION_NUMBER_INFINITY` correctly.

The tests are **deterministic** (hardcoded OIDs and expected outputs) and run in all commit-graph modes (`--full`, `--no-commit-graph`, and split-index). They complement the existing `t6099-merge-base-side-exhaustion.sh` regression tests by focusing on **queue state transitions** rather than performance.

No new infrastructure is introduced; the patch reuses the `test_all_modes` helper and adds ~110 lines of setup/test code. The commit message clearly links each test to the specific code path it exercises, making it easy to diagnose failures. This is a **low-risk, high-value** addition that hardens the series against regressions in edge-case topologies.
