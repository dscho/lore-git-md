This is the **final implementation update** for patch 5/7 in Harald Nordgren’s `git branch --delete-merged` series, now incorporating Phillip Wood’s review feedback. The patch is **feature-complete and ready for merging** once the remaining mechanical test improvements are applied.

Key changes in this update:
1. **Added `<branch>` argument support** to `--delete-merged`, mirroring the `--forked` filter’s design. Users can now limit deletion candidates by specifying one or more branch patterns (e.g., `git branch --delete-merged origin/next topic/*`). This addresses Phillip’s usability concern about the lack of filtering flexibility in the original design, which required per-branch opt-out via config. The implementation reuses the `--forked` machinery for consistency.

2. **Test suite refinements**:
   - **Helper functions**: Renamed `merged_branch` to `create_branch_with_upstream` and added explanatory comments to clarify its purpose (creates a branch with a specified upstream and pushes it to the remote).
   - **Simplified branch creation**: Replaced manual `git branch --set-upstream-to` calls with `git checkout -b --track`, reducing test verbosity.
   - **Removed redundant commands**: Eliminated unnecessary `git fetch` calls (after pushes) and `test_when_finished` blocks that duplicated `setup_repo_for_delete_merged`’s cleanup.
   - **New helper function**: Added `check_branches` to standardize `for-each-ref` comparisons, improving test readability and maintainability.
   - **Config checks**: Replaced manual `rev-parse --abbrev-ref` checks with `git config --get-regexp` for upstream/remote settings, making the intent clearer.
   - **Test cleanup**: Removed the redundant "keeps a chain of upstreams" test (overlapping with the "clears the upstream of a kept base" test) and renamed `on-local` to `local-to-delete` to avoid needing explanatory comments.

3. **Implementation notes**:
   - The `<branch>` argument support integrates seamlessly with the existing `--forked` filter logic, ensuring consistent behavior for exact refnames, remote shorthand, and shell-style globs.
   - The test suite now better reflects the expected outcomes, with clearer branch naming and helper functions that document their purpose.
