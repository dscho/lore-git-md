This is a **bugfix** for the object-file subsystem, addressing a double-free regression in object stream handling. The patch itself is already well-explained and looks solid, but this reply from Jeff King (Peff) adds a nuanced security consideration.

Peff acknowledges the patch and test are good but questions whether the issue should be treated as a security concern after all. He points out that while the affected code paths don’t operate on the transport layer, they *could* be reached via `upload-pack` or `pack-objects` when cloning from a local untrusted `.git` repository. This would violate Git’s stated (though not guaranteed) goal of safely cloning from untrusted local repos. Peff clarifies that Git’s `SECURITY` man page already acknowledges this risk, framing it as a known trade-off rather than a strict promise.

The exchange doesn’t change the patch—it’s still a clean, targeted fix—but it does raise the stakes slightly. If the project later decides to harden this scenario, the fix here might be revisited or supplemented. For now, the patch remains under review with no action required, but the thread is worth watching if security boundaries are a concern for your workflow.
