This is a cleanup patch for the `pack-objects` subsystem, specifically addressing dead code in `add_object_entry()`. Jeff King (Peff) follows up on his earlier review comment in Patrick Steinhardt’s ODB abstraction series (v2 3/8) where he noted that the return value of `add_object_entry()` has been unused since 2006 (commit `5379a5c5ee`). The patch removes the unused `int` return, converting the function to `void` to align with its sister function `add_object_entry_from_bitmap()`, which was recently changed to always return 0 to conform to a callback interface.

The change is minimal: four lines removed, five lines adjusted in `builtin/pack-objects.c`. It eliminates a long-standing inconsistency where two related functions returned `int` with different semantics, reducing potential confusion for future maintainers. The patch is well-motivated by the historical context and does not affect behavior, as the return value was never used. It is a natural follow-up to Patrick’s series, though not part of it, and could be queued independently once Junio picks up the v2 ODB patches.

This is a low-risk, high-clarity cleanup that fits the project’s preference for small, self-contained patches. The diff is straightforward and the commit message clearly explains the rationale. No test coverage is needed, as the change is purely internal and behavior-preserving. The patch is ready to proceed as-is.
