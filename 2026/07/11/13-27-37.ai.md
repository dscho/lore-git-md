This is a **test infrastructure patch** that improves diagnostic output for Trace2 data assertions. It is the second patch in the **v6 series optimizing `paint_down_to_common()`** (a performance-critical commit-reach function), which is now **fully reviewed and ready to merge**.

The patch introduces `test_trace2_data_singular()`, a new helper in `t/test-lib-functions.sh` that verifies a Trace2 event appears exactly once with the expected value. Unlike the existing `test_trace2_data` (a bare `grep` that fails silently), this helper provides detailed diagnostics on failure: whether the key was missing, appeared multiple times, or had the wrong value. Output goes to FD 4 (the test framework’s diagnostic channel), matching the behavior of `test_grep`.

The implementation is straightforward: it extracts the value from the Trace2 JSON event, checks for uniqueness, and compares it to the expected value. The helper is already used in later patches of the series (e.g., to assert step counts in `paint_down_to_common()`), where deterministic performance instrumentation is a key feature.

This is a **non-blocking polishing item**—the series is merge-ready without it—but the author values the improved debugging experience. The patch itself is **low-risk** (no behavior changes, only test diagnostics) and **self-contained** (touches only `t/test-lib-functions.sh`). Review feedback on the helper’s design is still welcome, but it does not delay the series.
