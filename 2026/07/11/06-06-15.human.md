This is a refactoring patch targeting the `git add -e` (interactive edit) command. The author, Gatla Vishweshwar Reddy, posts v4 of a standalone patch that replaces the subprocess call to `git apply` with a direct invocation of Git’s internal `apply_all_patches()` API. The goal is to eliminate fork overhead, keep the operation in-process, and improve code clarity.

The patch touches only `builtin/add.c`, removing unused includes (`run-command.h`, `strvec.h`) and adding `apply.h`. The implementation now initializes an `apply_state` struct with `cached` and `recount` options, then calls `apply_all_patches()` directly. The author addresses Junio’s concern about `repo_git_path()` potentially returning a relative path by passing `NULL` as the prefix to `init_apply_state()`, which ensures the path is used unchanged regardless of whether it is absolute or relative.

A new test in `t3702-add-edit.sh` verifies that `git add -e` works correctly when run from a subdirectory, complementing the existing 4 tests in that file. All tests pass, including the new one. The commit message is clear and well-structured, explaining the motivation, the change, and the reasoning behind the prefix-handling adjustment.
