This is the third patch in Pablo Sabater’s **v9 series** implementing cascading indentation for visual roots in `git log --graph`. The series is now technically complete and addresses all known edge cases, including the `--author`/`-grep` filter issue fixed in patch 4/4.

This patch adds a **two-slot lookahead buffer** to `struct git_graph`, populated by `get_revision()` via the unified `next_commit_to_show()` helper introduced in patch 2/4. The buffer ensures the graph renderer can safely peek two commits ahead—critical for determining whether the next commit is a visual root (and thus needs indentation). The design replaces the fragile peek-based approach from earlier versions, which risked accessing unsimplified or rewritten commits. The buffer is deterministic: commits are only added after full simplification, and timestamps are tweaked to ensure stable ordering.

The implementation is minimal and focused. `graph_is_interesting()` is updated to treat lookahead commits as "interesting" parents, preserving graph topology. Three new functions (`graph_pop_lookahead()`, `graph_get_lookahead_room()`, and `graph_push_lookahead()`) manage the buffer, with assertions to catch misuse. The buffer is populated in `get_revision()` only when a graph is active, avoiding overhead for non-graph operations. Compatibility with Jeff King’s planned `revs->commits` removal and Kristofer Haugsbakk’s `kk/prio-queue-get-put-fusion` topic is maintained.

The patch is **ready for final review**. It introduces no behavioral changes—its sole purpose is to provide the infrastructure for patch 4/4’s visualization logic. The lookahead buffer is a clean, robust solution to the architectural crossroads identified in v6/v7, and Junio Hamano has already approved the approach.
