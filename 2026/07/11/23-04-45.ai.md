This is a **contributor housekeeping** patch series follow-up from Junio C Hamano, the maintainer, addressing the last open review point on Ian Jackson’s `git-subtree` safeguard series. The series adds a runtime check in `contrib/subtree/git-subtree.sh` to prevent mixing the existing shell implementation with a forthcoming Rust rewrite, which will use a config key (`subtree.rust-rewrite`) to store metadata and will not be backward-compatible.

Junio’s email confirms that the only remaining item from the review discussion is the test style suggestion: whether to use `test_commit` and orphan branches instead of manually creating commits and repositories. He notes that the earlier debate about shell portability (`local`) is resolved—the project’s coding guidelines explicitly permit `local` in the test suite, and the scripted Porcelains (like `git-subtree`) are not required to avoid it. The email serves as a gentle nudge for Ian to post a v2 incorporating the agreed-upon test improvements, as the series is otherwise ready and marked "Expecting a reroll" in Junio’s draft "What’s cooking" report.

The patch touches `contrib/subtree/git-subtree.sh` and `t/t7900-subtree.sh`, introducing a new config key (`subtree.rust-rewrite`) and a helper function (`reject_if_v2_config`) that checks the top-level repository config for it. The safeguard’s design—checking only the downstream repository’s config, not subtree-internal metadata—has been clarified and accepted in prior discussion. The forthcoming Rust rewrite will not support manual `-X subtree` merges, but this limitation will be documented rather than enforced at runtime. The series is conceptually complete, with no substantive changes remaining open.
