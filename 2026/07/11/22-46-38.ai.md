This is a **build system** and **platform compatibility** follow-up in the `USE_NSEC` discussion. Junio C Hamano, the maintainer, responds to Patrick Steinhardt’s proposal to make nanosecond timestamp support runtime-configurable via a new `core.useNsec` knob. Junio concludes that the original patch (adding a `nanosec` Meson option to mirror the Autotools `USE_NSEC` knob) is now overshadowed by the broader design discussion and withdraws it from his integration tree.

The email signals a clear shift in focus: the original patch, which aimed to ensure build system parity, is no longer the priority. Instead, the discussion has evolved into a larger effort to rethink how Git handles sub-second timestamps—whether to deprecate the `USE_NSEC` build knob entirely, make the feature runtime-configurable, or flip its default. Junio’s decision to discard the topic from his tree reflects this shift and invites a new patch series that implements the runtime-configurable approach (e.g., `core.useNsec`) and deprecates the build-time knob.

Key technical details to track for future patches: the proposed **runtime config knob** (`core.useNsec`), the **build-time default** (disabled, matching current behavior), and the **compilation strategy** (always include nanosecond support if the platform allows it). Junio’s response does not address the default value for `core.useNsec` or interoperability risks, but it confirms that the original patch is no longer the path forward. The next step would likely be a patch series implementing the runtime-configurable approach, with clear documentation of the trade-offs and backward-compatibility considerations. The discussion’s convergence on deprecating the build-time knob suggests that such a series would have a strong chance of acceptance if it addresses the open questions.
