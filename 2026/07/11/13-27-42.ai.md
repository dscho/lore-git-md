This is patch 7/10 in the **ready-to-merge v6 series** optimizing `paint_down_to_common()` for one-sided histories. The patch introduces `struct paint_state`, a refactoring that replaces the old `nonstale_queue` wrapper with **per-side counters** (`parent1_count`, `parent2_count`, `mb_candidate_count`) to track commits by their paint flags (PARENT1-only, PARENT2-only, or both). This enables the early-termination logic in later patches while maintaining equivalent behavior—both implementations detect when no non-stale entries remain, but the new version uses counters instead of a `max_nonstale` pointer.

Key changes:
- **New struct**: `paint_state` wraps a `prio_queue` and adds counters for each commit type. The `paint_count_update()` helper adjusts these counters based on paint flags, with an exhaustive switch documenting all valid flag combinations.
- **Queue management**: `paint_queue_put()` and `paint_queue_get()` replace the old `nonstale_queue_*_dedup()` functions. The "pop first" design of `paint_queue_get()` (dequeue, then check counters) causes minor step-count reductions in some topologies (e.g., `t6600` tests drop by 1 step) but is functionally equivalent.
- **Dead code removal**: The unused `nonstale_queue_put_dedup()` and `nonstale_queue_get_dedup()` are deleted, though the `nonstale_queue` struct itself remains for `ahead_behind()`.
- **Documentation update**: The technical doc (`paint-down-to-common.adoc`) is revised to reflect the new termination condition ("queue contains only stale entries" instead of `max_nonstale` checks).

The patch is **mechanical and low-risk**, touching only `commit-reach.c` and test expectations. It lays the groundwork for the early-termination optimization in patch 8/10 by making commit counts explicit.
