This thread is about a small but important test fix for the recently introduced `fetch.submoduleErrors` configuration option. The original feature, authored by Patrick Ziegler, added a way to control how Git handles submodule errors during fetch operations. However, it introduced a test regression in `t/t5526-fetch-submodules.sh`, where several tests used raw `grep` commands instead of the Git test helper `test_grep`, risking false negatives when patterns weren’t found.

Ramsay Jones caught this and sent a fixup patch that mechanically replaces all `grep` calls with `test_grep` and adjusts negated cases (`! grep`) to the idiomatic `test_grep !`. The change is confined to the test file and doesn’t affect the feature’s runtime behavior. Junio has acknowledged the fix and plans to pick it up in the next integration cycle unless the original author sends a replacement first. The topic is still under review in Junio’s `seen` branch and hasn’t been merged yet, but there are no open questions or loose ends—just a straightforward correction to keep the test suite robust.
