This is the seventh patch in the **ready-to-merge v6 series** optimizing `paint_down_to_common()` for one-sided commit histories. The patch introduces a `paint_state` struct to track per-side commit counters (PARENT1-only, PARENT2-only, and merge-base candidates) during the walk, replacing the old `max_nonstale` pointer-based termination logic.

The change is **mechanical and low-risk**: the new counters (`parent1_count`, `parent2_count`, `mb_candidate_count`) mirror the existing flag-based logic but make the termination condition (`!parent1_count && !parent2_count && !mb_candidate_count`) explicit and easier to reason about. The `paint_queue_get()` helper now returns `NULL` when all counters reach zero, which is functionally equivalent to the old `max_nonstale` check but avoids processing the final stale commit. This explains the minor step-count reductions in `t6600-test-reach.sh` (e.g., `6 -> 5` for pending-stale tests).

The patch also **removes unused functions** (`nonstale_queue_put_dedup()`, `nonstale_queue_get_dedup()`) that became redundant after the refactor. The `paint_count_update()` helper centralizes counter adjustments in a single `switch` statement, documenting all valid flag combinations (e.g., `PARENT1 | STALE` is explicitly ignored).

**Context for reviewers**: This is a **refactoring prerequisite** for the early-termination optimization in later patches. The counters enable deterministic detection of side exhaustion (e.g., when one side’s queue drains), which is critical for the 100-1000x speedups in asymmetric queries.
