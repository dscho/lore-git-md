This is the fourth and final patch in Pablo Sabater’s **v9** series implementing **cascading indentation for visual roots in `git log --graph`**. The patch introduces the actual visualization logic, building on the lookahead buffer infrastructure added in patch 3/4.

The core change adds a new `GRAPH_PRE_ROOT` state to the graph renderer, which prints an extra row connecting an indented visual root to its child. The indentation itself is controlled by two new counters in `struct git_graph`: `visual_root_depth` (how many adjacent visual roots precede the current commit) and `visual_root_cascade` (whether the current commit is part of a cascade and should skip its own indentation). A commit is identified as a visual root if it has no interesting parents (determined by `graph_is_interesting()`) and is not a non-first parent of a merge. The lookahead buffer (introduced in patch 3/4) is used to peek at the next commit and decide whether to cascade or terminate indentation.

The patch also fixes the `--author`/`-grep` edge case identified in v8: `graph_is_visual_root_candidate()` now iterates over each parent and calls `graph_is_interesting()` to detect if the parent is excluded by filters, ensuring visual roots are correctly identified even when parent pointers remain intact. Two new test cases in `t4218-log-graph-indentation.sh` verify this fix.

Test coverage is comprehensive, with 473 lines of new tests in `t4218-log-graph-indentation.sh` covering `--max-count`, `--max-count-oldest`, `--first-parent`, filtered parents, boundary commits, and octopus merges. The series is now **technically complete** and addresses all known edge cases.
