This is the third patch in Pablo Sabater’s **v9 series** implementing cascading indentation for visual roots in `git log --graph`. It introduces a **two-slot lookahead buffer** inside `struct git_graph` to safely peek ahead two commits without relying on fragile peeks into `rev_info` internals. The buffer is populated by `get_revision()` via the unified `next_commit_to_show()` helper (introduced in patch 2/4), ensuring commits are fully simplified before inspection.

The patch adds three new functions to `graph.h`/`graph.c`:
- `graph_pop_lookahead()` – retrieves the next commit from the buffer.
- `graph_get_lookahead_room()` – checks remaining buffer capacity.
- `graph_push_lookahead()` – adds a commit to the buffer, with a BUG() if overfilled.

The buffer is integrated into `get_revision()`: if the graph is active, the function first tries to pop from the buffer before falling back to `next_commit_to_show()`. After retrieving a commit, it fills the buffer with up to two additional commits. The patch also updates `graph_is_interesting()` to treat buffered commits as "interesting" parents, preserving graph topology even when commits are pre-fetched.

This is a **refactoring patch** with no user-visible behavior change. It is **well-motivated** by the architectural crossroads resolved in earlier iterations: the lookahead buffer eliminates the need for peek functions (`revision_peek_next_commit()`, `revision_has_commits_after()`) that Junio Hamano rejected as unsafe. The implementation is **clean and defensive**, using `ARRAY_SIZE()` and BUG() assertions to catch misuse. It is **compatible** with Jeff King’s planned removal of `revs->commits` and Kristofer Haugsbakk’s `kk/prio-queue-get-put-fusion` topic.

The patch is **ready for final review**. Junio Hamano and Phillip Wood have not yet signed off, but the design is **finalized** and the implementation addresses all known edge cases (deterministic behavior, buffer safety, and integration with `graph_is_interesting()`). The only remaining work is reconciliation with `kk/prio-queue-get-put-fusion`, which is non-blocking. This patch is **critical infrastructure** for the visualization logic in patch 4/4.
