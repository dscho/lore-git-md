This is the second patch in Pablo Sabater’s v9 series implementing cascading indentation for visual roots in `git log --graph`. The series is now technically complete, addressing all known edge cases, and this patch is a refactoring step toward the lookahead buffer introduced in patch 3/4.

The patch extracts the logic for retrieving the next commit into a new helper function, `next_commit_to_show()`. Currently, `get_revision()` fetches commits from two different sources depending on whether `--max-count-oldest` is active: either directly from the revision walk (via `get_revision_internal()`) or from a saved list (`revs->commits`) populated by `--max-count-oldest`. The new helper unifies this logic, returning the next commit regardless of its source. This refactoring is purely mechanical—there is no behavior change—and is necessary for the subsequent lookahead buffer implementation, which needs to pre-fetch commits from the same source consistently.

The patch is small (24 insertions, 12 deletions) and focused. It preserves the existing behavior for `--reverse`, which retains its own commit-popping loop to avoid unintended side effects (specifically, setting `SHOWN` and `CHILD_SHOWN` flags). The helper is well-named and clearly documented, making the intent obvious. This is a clean preparatory step for the lookahead buffer, which is the architectural foundation for the series’ core functionality.
