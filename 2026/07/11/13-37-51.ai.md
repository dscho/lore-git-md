This is the second patch in Pablo Sabater’s four-part v9 series implementing cascading indentation for visual roots in `git log --graph`. It introduces `next_commit_to_show()`, a helper function that abstracts the logic for retrieving the next commit to display, whether it comes from the normal revision walk (`get_revision_internal()`) or from the saved list used by `--max-count-oldest`.

The patch is purely preparatory and makes no behavioral changes. Its purpose is to unify the commit retrieval logic so that a subsequent patch (3/4) can pre-fetch two commits into a lookahead buffer without duplicating the source-selection logic. The helper is intentionally not used for `--reverse` mode, as that would incorrectly set `SHOWN` and `CHILD_SHOWN` flags, which are not desired in that context.

The implementation is straightforward: `next_commit_to_show()` checks `revs->max_count_stage` to decide whether to pop from the saved list (`revs->commits`) or call `get_revision_internal()`. The flags `SHOWN` and `CHILD_SHOWN` are set only when popping from the saved list, preserving existing behavior. The patch touches only `revision.c` and is well-scoped, with no external dependencies or edge cases introduced at this stage.

This patch is a prerequisite for the lookahead buffer introduced in patch 3/4, which resolves the architectural fragility of peeking at unsimplified commits. Junio Hamano has already approved the lookahead buffer approach in principle, and this helper is the first step toward that design. The patch is ready for final review, with no known issues or open questions. Phillip Wood’s review is still pending, but the patch is unlikely to require further revisions.
