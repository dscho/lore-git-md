This is the **core implementation patch** (5/7) of Harald Nordgren’s long-running `git branch --delete-merged` series, now in its final v18 form. The patch adds the `--delete-merged` subcommand, which safely deletes local branches merged into their upstream while preserving branches used as upstreams for unmerged branches. Harald has incorporated Phillip Wood’s latest review feedback, addressing test clarity, conciseness, and a minor design enhancement—**no functional flaws remain**.

Key updates in this revision:
- **Added a `<branch>` argument** to `--delete-merged`, mirroring `--forked`’s behavior. This allows users to limit deletion candidates (e.g., `git branch --delete-merged origin/main`) without relying solely on the `branch.<name>.deleteMerged` config opt-out. The change is backward-compatible and improves usability.
- **Overhauled test suite** for clarity and maintainability:
  - Renamed helper functions (e.g., `merged_branch` → `create_branch_with_upstream`) and added comments where needed.
  - Simplified test patterns using `git checkout -b --track` to avoid manual `git branch --set-upstream-to` calls.
  - Removed redundant commands (e.g., `git fetch` after a push, `test_when_finished` alongside `setup_repo_for_delete_merged`).
  - Introduced a `check_branches` helper to standardize `for-each-ref` comparisons.
  - Replaced manual config checks with `git config --get-regexp` for upstream/remote settings.
  - Moved the premature `--dry-run` test case to patch 7/7 (where it belongs).
- **Improved test readability** by renaming branches (e.g., `on-local` → `local-to-delete`) and removing unnecessary subshells.
- **Fixed edge cases** like the reverse-numbered branch chain (`b3→b2→b1`), which is now deleted in favor of a clearer `lower→mid→tip` progression.

The patch retains all safety mechanisms from earlier versions:
- **Stacked-branch protection (abort-and-clear)**: Fails to delete a branch if it’s an upstream for an unmerged branch, but clears stale upstream configs for kept branches.
- **Per-branch opt-out**: Respects `branch.<name>.deleteMerged=false` (implemented in patch 6/7).
- **Push divergence checks**: Preserves branches where `push == upstream`.
- **No deletion of checked-out branches** (any worktree).
