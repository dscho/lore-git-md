This is the second patch in Harald Nordgren’s **seven-part series** introducing `git branch --delete-merged`, now in its **twentieth revision** and ready for merging. The series as a whole adds safe, automated local-branch cleanup with comprehensive filtering and safety controls, including per-branch opt-out, `--dry-run` preview, and order-independent stacked-branch protection.

This specific patch **refactors the branch-deletion API** to replace separate `force` and `quiet` boolean parameters with a single `unsigned int flags` argument and an enum (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is purely mechanical and introduces no behavior differences, but it is a prerequisite for later patches that add new flags (`DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`, and `DELETE_BRANCH_DRY_RUN`). The implementation tests the flags directly at each use site to prevent stale cached values, addressing a maintenance risk identified in earlier reviews.

The patch touches only `builtin/branch.c` and is **well-explained** in the commit message. It is part of a **mature, unblocked series** that has resolved all correctness and design concerns, including the order-dependency issue in stacked-branch protection that previously blocked merging. The flags-based API is a clean foundation for the new `--delete-merged` command and its safety features. If you care about branch management or Git’s internal APIs, this patch is worth a quick skim; otherwise, it is safe to treat as a routine refactoring.
