This is the final patch in Harald Nordgren’s seven-part series introducing `git branch --delete-merged`, adding the `--dry-run` option. The patch is small, focused, and well-executed, completing a feature that has been thoroughly reviewed and is now unblocked for merging.

The `--dry-run` option lets users preview which branches would be deleted by `git branch --delete-merged` without actually touching any refs or configuration. It prints one line per affected branch (e.g., "Would delete branch merged (was abc1234).") and exits cleanly. The implementation is careful to avoid side effects: it skips all ref and config modifications, including the stacked-branch protection’s upstream-clearing logic, so the repository state remains unchanged. The option is rejected unless `--delete-merged` is also specified, and the nonsensical `--dry-run --quiet` combination is explicitly forbidden.

The patch touches three files. In `builtin/branch.c`, it adds the `DELETE_BRANCH_DRY_RUN` flag to the existing deletion API, modifies `delete_branches()` to skip ref/config updates when the flag is set, and extends the command-line parser to accept `--dry-run` only alongside `--delete-merged`. The documentation in `git-branch.adoc` is updated to describe the new option, and the test suite in `t/t3200-branch.sh` is expanded with three new tests: one verifies the output matches the real deletion output exactly, another confirms stacked-branch protection is respected during dry runs, and a third ensures `--dry-run` is rejected without `--delete-merged`.

This patch is the capstone of a long-running effort that has addressed all design and correctness concerns raised during review. The `--dry-run` implementation is minimal, safe, and exactly what users would expect: a true preview that leaves no trace. The series as a whole is now ready for merging, with only a follow-up planned to extend stacked-branch protection to `git branch -d` for consistency.
