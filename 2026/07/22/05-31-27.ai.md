This is a **platform compatibility bugfix** targeting macOS, specifically addressing a memory leak in the system regex engine (TRE) that occurs when `regexec()` encounters invalid UTF-8 sequences. The patch introduces a Darwin-specific workaround in `compat/regexec.c` to prevent the leak by splitting input buffers at invalid multibyte sequences and searching each valid segment separately.

The issue is severe: a single `git grep` command over files containing binary data (e.g., PDFs) can leak gigabytes of memory, potentially triggering kernel watchdog panics. The fix is narrowly scoped to macOS builds using the system regex engine (skipped when `NO_REGEX` is set, such as in ASAN builds). It preserves all genuine matches while avoiding the leaking path entirely, making it safe to drop once macOS fixes the underlying bug.

The implementation uses `mbrtowc()` to split buffers at the exact bytes the platform’s decoder rejects, ensuring consistency with TRE’s behavior. The patch integrates cleanly across all build systems (Makefile, Meson, CMake) and includes regression tests in `t7810-grep.sh` to verify matches around invalid bytes and correct anchoring of `^`/`$`.

This is a well-motivated, thoroughly tested fix for a real-world problem, with clear reproduction steps and a conservative approach that avoids behavioral regressions.
