This is the sixth patch in Harald Nordgren’s **final v20 series** for `git branch --delete-merged`, which is now **unblocked and ready for merging**. This patch adds a **per-branch opt-out mechanism** via the `branch.<name>.deleteMerged` config key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The implementation is straightforward and well-integrated. The opt-out check happens early in `delete_merged_branches()`, before any safety or stacked-branch protection logic, and produces a non-quiet skip message (e.g., "Skipping 'kept' (branch.kept.deleteMerged is false)"). The config key is documented in both `branch.adoc` and `git-branch.adoc`, with clear examples and caveats. Tests verify the opt-out behavior, skip messages, and that explicit deletion via `git branch -d` ignores the setting (using the normal merge check instead).

Phillip Wood’s **surface-level review** of an earlier version suggested a mechanical test improvement—using `git for-each-ref` (via the `check_branches` helper) instead of `rev-parse` to verify branch state—and this has been applied. The current implementation is clean, with no known issues or edge cases. The opt-out mechanism complements the series’ broader safety architecture (stacked-branch protection, push divergence checks, etc.) and addresses a real workflow need: keeping topic branches alive after an early round of upstream merges.

This patch is **low-risk and well-tested**, touching only `builtin/branch.c` and the test suite. It’s a natural fit for the series and doesn’t introduce any new dependencies or design questions.
