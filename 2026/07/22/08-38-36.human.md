This is a small bugfix patch for the `git-p4` tool in `contrib/`. The patch corrects the `extractLogMessageFromGitCommit` function so that it returns only the commit message body, rather than the entire raw commit object (which includes metadata like author, tree, and parent SHAs).

The change is straightforward: the function now scans for the first blank line in the commit object (the standard separator between headers and message body) and discards everything before it. The old behavior was clearly wrong—including commit metadata in the message body would produce malformed or confusing commit messages in Perforce-to-Git imports—but the commit message doesn’t provide a concrete example of where this caused problems in practice.

The patch touches only `git-p4.py` and is self-contained. It looks technically sound, though the lack of test coverage or a specific reproduction case might leave reviewers wanting a bit more context. Unless someone identifies a downstream consumer that actually relies on the metadata being present, this is likely to be uncontroversial.
