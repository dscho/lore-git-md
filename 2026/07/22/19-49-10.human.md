This is a bugfix patch for submodule handling, now under review by Junio. The patch addresses a regression (introduced in 2025) where `git submodule update --remote` fails to match the submodule’s configured remote when URL aliases (`url.<base>.insteadOf`) are used. The issue arises because `.gitmodules` stores the unexpanded alias (e.g., `local:path`), while the submodule’s remotes report the resolved URL (e.g., `/full/path`), causing the lookup to fail and fall back to the default remote.

Junio’s feedback focuses on two areas: the commit message and the implementation. He suggests clarifying the security implications of the failure (e.g., whether it could be exploited by malicious `.gitmodules` files) and improving the commit reference format. On the code side, he proposes a minor stylistic tweak to avoid introducing a new variable (`url_to_match`) and notes that the patch preserves the existing "first match wins" behavior without warning about ambiguous configurations—a potential future concern but outside this patch’s scope.

The patch itself remains narrowly scoped and well-tested, with a new test case in `t/t7406-submodule-update.sh` covering the regression. Junio’s comments are constructive but not blocking; the fix looks likely to proceed once the commit message is updated. No substantive objections or alternative approaches have been raised yet.
