This is Patrick Steinhardt’s response to the ODB performance regression discussion, engaging directly with Junio’s proposal to distinguish "fast" and "slow" lookups within ODB backends. Patrick acknowledges the regression but pivots to a broader architectural goal: eliminating the need to modify the list of ODB sources during transactions (e.g., for quarantine directories like `tmp_objdir`). His proposed solution is to bypass the source list entirely for writes during active transactions, routing them directly to the transaction object instead of the primary ODB source. This would prevent the problematic loose-object checks in the quarantine directory during connectivity traversals, as objects written to the transaction wouldn’t be visible to the ODB layer until the transaction commits.

The email is substantive and forward-looking, tying the regression fix to a larger refactoring effort (transaction-aware ODB writes) that Patrick and Justin Tobler have planned. While he doesn’t address Junio’s "fast/slow" lookup idea directly, his proposal would incidentally resolve the performance issue by avoiding the quarantine directory’s loose objects during connectivity checks. He notes that this change shouldn’t break existing behavior, as transactions aren’t typically read from immediately.
