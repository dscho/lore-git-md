This thread is a user request from Kyle Marek to add a configuration option that would allow symlinks in submodule paths, reversing a security restriction introduced in May 2024. The restriction, which outright rejects symlinks in submodule paths, broke workflows where multiple worktrees share a single copy of their submodules via symlinks. Marek acknowledges the security rationale but argues the blanket prohibition is overly restrictive and points to an existing TODO comment in the codebase that explicitly proposes a `safe.submodule.path` configuration variable to let users opt out.

So far, the thread is just the initial request—no patches have been posted, and no maintainers or reviewers have weighed in yet. The ball is in the project’s court to decide whether such a configuration knob would be acceptable, balancing security concerns against user flexibility. If the project agrees, the next step would likely be a patch implementing the proposed variable.
