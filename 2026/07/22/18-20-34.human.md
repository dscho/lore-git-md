This is a user request for a configuration knob to re-enable symlinks in submodule paths, reversing a two-year-old security-motivated restriction.

Kyle Marek reports that Git commit e8d06089 (2024-05-15) broke a long-standing workflow: multiple worktrees sharing a single copy of their submodules via symlinks. The commit message cites security concerns, but Kyle argues the change was overly paternalistic and left no escape hatch. A TODO comment in the code already acknowledges the need for a user-configurable override (e.g., `safe.submodule.path`).

The email is not a patch—it asks whether the project would accept one. No technical details are given yet, so the discussion is still at the design stage. If the maintainers are receptive, this could become a small feature addition; if not, it may turn into a policy debate about how much Git should protect users from themselves.
