Subject: [PATCH] compat/regex: work around macOS TRE regexec() memory leak
Series version: standalone patch (no series)
Originating author: Chungmin Lee
Thread type: platform-specific bugfix

Core problem or goal
Fix a memory leak in Git’s macOS builds when the system regex engine (TRE) processes invalid UTF-8 sequences. A single `git grep` over binary files (e.g., PDFs) can leak gigabytes, risking kernel watchdog panics. The patch adds a Darwin-specific workaround in `compat/regexec.c` that splits input buffers at invalid multibyte boundaries and searches each valid segment separately, avoiding the leaking code path while preserving all genuine matches.

Current status
Under review; no prior versions. Junio C Hamano has raised structural and long-term maintainability questions but has not identified technical flaws in the patch itself. The fix remains narrowly scoped to macOS builds using the system regex engine (skipped when `NO_REGEX` is set, e.g., ASAN builds). All build systems (Makefile, Meson, CMake) are updated, and regression tests in `t7810-grep.sh` verify matches around invalid bytes and correct anchoring of `^`/`$`.

Key technical details
Files touched: `compat/regexec.c`, `t7810-grep.sh`
New symbols: none (internal-only logic)
Behavior change: none for valid UTF-8; invalid sequences are now split at the exact bytes rejected by `mbrtowc()`, ensuring consistency with TRE’s decoder
On-disk format: unchanged
Test coverage: new tests in `t7810-grep.sh` for invalid UTF-8 handling and `^`/`$` anchoring. Junio has questioned whether the test should be macOS-specific or allowed to run on other platforms for broader regression detection.

Open questions and loose ends
1. Long-term maintainability: How long will the workaround need to be maintained? The commit message does not speculate on upstream macOS fixes, leaving this open.
2. Platform-specific override organization: Junio suggests a more modular approach for future overrides—define each in its own platform header, then conditionally include it in `git-compat-util.h` with a fallback inline definition to avoid cluttering the main header with nested `#ifdef` chains.
3. Test scope: Should the new tests in `t7810-grep.sh` be macOS-specific or allowed to run on other platforms? The current patch restricts them to macOS builds using multibyte regex, which is technically correct but may limit broader regression detection.
