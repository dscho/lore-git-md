This thread is about a small but important bugfix for `git-p4`, the Perforce interoperability tool in Git's `contrib/` directory. The issue is that `extractLogMessageFromGitCommit` in `git-p4.py` currently returns the entire raw Git commit object—including metadata like author, tree, and parent SHAs—when it should return only the commit message body. This causes Perforce-to-Git imports to include unwanted metadata in the imported commit messages.

The patch, posted by a new contributor (hardikxk), surgically fixes the problem by modifying the function to skip the metadata headers and return only the message body. The change is minimal, touching just one file and introducing no new symbols or on-disk format changes. While the patch doesn’t include a reproduction case or test coverage, the fix is straightforward and unlikely to be controversial unless someone identifies a downstream consumer that relies on the metadata being present. So far, there are no reviews, but the patch looks technically sound and ready for feedback.
