This is the fourth patch in Harald Nordgren’s **v20 `git branch --delete-merged` series**, which is now unblocked and ready for merging. This patch prepares the `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that prevents falling back to `HEAD` when no upstream is configured. This ensures the `--delete-merged` command only deletes branches that are explicitly merged into their upstream, without silently defaulting to `HEAD` as a reference point.

The change is small and focused: it modifies `delete_branches()` to skip the `HEAD` fallback when the new flag is set, and updates the `branch_merged()` helper to avoid printing a "gentle reminder" about `HEAD` fallback for callers that explicitly opt out. The patch preserves existing behavior for all current callers (e.g., `git branch -d`), which continue to use the `HEAD` fallback as before.

This is a **refactoring patch** that enables the core `--delete-merged` logic (introduced in patch 5/7) to work correctly. The new flag is part of the series’ broader effort to unify branch deletion behavior under a flags-based API, which was previously reviewed and approved by Phillip Wood. The patch is **well-motivated**—the `HEAD` fallback is inappropriate for `--delete-merged` because it would allow deleting branches that aren’t merged into any of the specified upstreams—and the implementation is straightforward.

No test coverage is added here, as the patch only introduces a flag and does not change observable behavior. The flag’s effect will be tested in later patches that exercise the `--delete-merged` subcommand. The patch is **ready for merging** as part of the series.
