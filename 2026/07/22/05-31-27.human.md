This is a platform-compatibility bugfix targeting macOS. The patch works around a memory leak in macOS's system regex engine (TRE) that occurs when `regexec()` encounters invalid UTF-8 sequences in a multibyte locale. The leak is severe enough to exhaust system memory and trigger kernel watchdog panics during operations like `git grep` on files containing binary data.

The fix adds a Darwin-specific `regexec_buf()` implementation in `compat/regexec.c` that splits the input buffer at invalid UTF-8 sequences and searches each valid segment separately, avoiding the leaking path entirely. The workaround is compiled in only when using the platform regex engine (not the bundled one) and preserves all genuine matches while preventing spurious ones. Build system integration is provided for Makefile, Meson, and CMake.

The commit message is exceptionally thorough, documenting the root cause, the constraints on the solution, the behavior change envelope, and a real-world reproduction case. Test coverage in `t7810-grep.sh` verifies that matches around invalid bytes are preserved and that `^`/`$` anchors behave correctly at true line boundaries. This looks like a well-crafted, motivated fix for a real problem.
