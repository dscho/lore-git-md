This is a two-patch bugfix series targeting `git rebase --update-refs` behavior with symbolic references (symrefs). The series addresses edge cases where branch symrefs—such as `main` pointing to `master` during a branch rename migration—cause rebase failures after the primary branch has already been successfully rewritten. The v3 revision incorporates feedback from Phillip Wood’s substantive review, splitting the fix into two focused patches: one for skipping branch-to-branch symrefs and another for safeguarding non-branch symref targets.

The first patch resolves the core issue by skipping symrefs that point to other branches (under `refs/heads/`), preventing duplicate updates while preserving the existing handling for checked-out branches. It uses `refs_resolve_refdup()` to safely resolve symrefs and maintains an owned copy of the resolved HEAD name to avoid interference from later ref resolution. The second patch adds protections for non-branch symrefs, ensuring their resolved targets are not updated if they are checked out in another worktree or if the symref itself is already being handled. This prevents cross-worktree conflicts and duplicate updates.

The series includes thorough test coverage in `t3404-rebase-interactive.sh`, verifying behavior for both HEAD aliases (e.g., `no-conflict-branch-alias`) and secondary branch aliases (e.g., `second-alias`), as well as symref chain resolution. The tests confirm that symrefs remain intact after rebase and that the correct refs are updated or skipped. The implementation is backend-agnostic, passing tests with both files and reftable backends.

This revision directly addresses Phillip Wood’s feedback from v2, including restoring the unconditional skip for the current branch, improving symref resolution logic, and splitting the changes into logically distinct patches. The series is now well-scoped and appears ready for inclusion, with clear commit messages and test coverage that demonstrate the fixes for the identified edge cases. The changes are minimal and focused, avoiding unnecessary restructuring of unrelated code.
