**Technical details**:
- **Core behavior**: Deletes local branches whose tip is reachable from their upstream (matching one of the `--delete-merged` arguments) and whose push destination differs from their upstream. Supports glob patterns for both upstreams and local branches.
- **Safety mechanisms**: Skips checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`.
- **Stacked-branch protection**: Fails to delete a branch if it is used as an upstream for an unmerged branch, but clears the upstream config for kept (merged) branches whose own upstream is being deleted. The new implementation ensures this logic is **order-independent** by collecting all protected branches before mutating the deletion set.
- **`--dry-run`**: Prints "Would delete branch <name>" for each affected branch without modifying refs or config. Rejects the nonsensical `--dry-run --quiet` combination.
- **Test coverage**: Comprehensive integration tests verify all safety checks, edge cases (e.g., self-referential upstreams, missing upstreams), and the new order-independent stacked-branch protection behavior.
