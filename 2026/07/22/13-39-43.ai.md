The key change in v20 is a **structural refactor** of `spare_stacked_bases()` and its helper function to eliminate an **order dependency** in stacked-branch protection. The new implementation (`protect_stacked_branch_bases()`) collects all protected branches in a single pass before mutating the deletion set, ensuring consistent results regardless of ref iteration order. This addresses Junio C Hamano’s blocking correctness concern from earlier versions.

**What changed in the logic**:
1. **Single-pass collection**: The new `collect_stacked_branch_bases()` function traverses upstream chains from each branch, marking all transitively required branches as "protected" before any deletions occur. This replaces the previous two-phase approach (marking spared branches during iteration, then clearing their upstreams afterward).
2. **Transitive protection**: The refactor explicitly handles chains of dependencies (e.g., `b1→b2→b3`) by walking the entire upstream chain for each branch and protecting all branches in the chain.
3. **Variable naming**: The patch clarifies the distinction between branch names (e.g., `main`) and full refnames (e.g., `refs/heads/main`) by renaming struct members (e.g., `deletable_branch_names` instead of `deletable`).

**Why the previous approach was insufficient**:
The v19 implementation removed spared branches from the deletion set *during* ref iteration, which could produce inconsistent results depending on the order in which branches were processed. For example, if `b1` was processed before `b2` (where `b2→b1`), `b1` would be spared, but if `b2` was processed first, `b1` might be incorrectly deleted. The new implementation avoids this by deferring all mutations until after the full set of protected branches is collected.

**Technical details**:
- The refactor introduces a `visited_branch_names` strset to avoid infinite loops in self-referential upstream chains (e.g., `b3→b3`).
- The `protected_branch_names` strset replaces the previous `spared` set, with clearer semantics.
- The `refs_for_each_ref_ext()` call now uses a `prefix` option to limit iteration to local branches, avoiding unnecessary work.
