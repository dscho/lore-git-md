This is the v20 submission of Harald Nordgren’s `git branch --delete-merged` series, now **implementation-complete and addressing the last major correctness blocker** that has held up merging since v19. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including per-branch opt-out, `--dry-run` preview, and **stacked-branch protection that is now order-independent**.

The key change in v20 is a **structural refactor of the stacked-branch protection logic** to eliminate the order dependency that Junio C Hamano flagged as a correctness issue in v19. Instead of mutating the deletion set during ref iteration (which produced inconsistent results depending on iteration order), the new implementation **first collects all protected branches in a single pass**, then removes them from the deletion set in a separate step. This ensures the result is deterministic and independent of ref iteration order, addressing Junio’s concern without requiring a full multi-pass algorithm. The commit message and variable names have also been clarified to reduce confusion around branch names versus full refnames.

The series is now **ready for merging** with no known issues. All design questions (stacked-branch protection, per-branch opt-out, `--forked` filter edge cases) have been resolved, and the implementation aligns with Git’s API consistency expectations. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, as requested by Junio, but this is **not a blocker** for v20.

For users, the new `--delete-merged` command provides a safe way to clean up local branches that have been merged into their upstream (e.g., `git branch --delete-merged origin/main`), with multiple safety mechanisms:
- Skips checked-out branches, branches with missing upstreams, and branches that push to their upstream (e.g., `main` tracking `origin/main`).
- Respects per-branch opt-out via `branch.<name>.deleteMerged=false`.
- **Protects branches transitively required by surviving local upstreams** (e.g., if `topic` tracks `main` and `main` is unmerged, neither is deleted).
- Supports `--dry-run` to preview deletions without modifying refs or config.
- Accepts multiple `--delete-merged` arguments (e.g., `--delete-merged origin/main --delete-merged origin/next`) and optional positional patterns (e.g., `topic-*`) to limit deletion scope.

The series is **well-motivated** (addressing a real workflow pain point) and **thoroughly tested**, with clear documentation and a flags-based API designed for future extensibility.
