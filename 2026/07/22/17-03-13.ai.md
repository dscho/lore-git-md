This is a bugfix targeting the revision-walking machinery. Junio C Hamano identifies and fixes a logic error in `process_parents()` where the `--exclude-first-parent-only` option was not being honored when the first parent of a merge commit had already been marked `SEEN`. The patch ensures that, under that option, the revision walker stops processing parents after the first one, even if it was previously seen, preventing incorrect propagation of the `UNINTERESTING` flag to subsequent parents.

The change is small and surgical: two `break` statements are added inside the parent-processing loop in `revision.c`, guarded by the `exclude_first_parent_only` flag. The accompanying test in `t/t6012-rev-list-simplify.sh` exercises the edge case by explicitly including the first parent on the command line (which marks it `SEEN`) and verifying that later parents are not incorrectly excluded.

Jerry Zhang’s `Reviewed-by` trailer is present, but the review itself is not included in the input. The commit message is clear and self-contained, explaining both the symptom (“we end up marking the second parent as UNINTERESTING”) and the cure (“break out of the loop instead of continuing”). The test coverage is minimal but sufficient for the specific regression.

This patch is a standalone fix, not part of a larger series. It touches only the revision-walking subsystem and the corresponding test script, so downstream consumers can expect no side effects outside `git rev-list` and related commands.
