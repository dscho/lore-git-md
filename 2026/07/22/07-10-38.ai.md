This is the final patch in Harald Nordgren’s `git branch --delete-merged` series, adding `--dry-run` support to the new subcommand. The patch is **implementation-complete and unblocked**, closing the last functional gap in the series.

The `--dry-run` flag prints one line per branch that would be deleted (e.g., "Would delete branch merged (was abc1234)") without modifying refs or config. It is rejected unless paired with `--delete-merged`, and the nonsensical `--dry-run --quiet` combination is explicitly forbidden. The implementation hooks into the existing `delete_branches()` API via the new `DELETE_BRANCH_DRY_RUN` flag, ensuring all safety checks (stacked-branch protection, per-branch opt-out, push divergence) are respected during the preview. During dry runs, `spare_stacked_bases()` skips config updates (e.g., clearing upstreams) to avoid side effects.

The patch updates `Documentation/git-branch.adoc` to document the new option and adds three new tests in `t/t3200-branch.sh`: one verifies the output matches the real deletion message exactly, another confirms stacked-branch protection is respected during dry runs, and the last rejects `--dry-run` without `--delete-merged`. The tests use the `check_branches` helper introduced in patch 6/7 to verify branch state via `git for-each-ref`.
