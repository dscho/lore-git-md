This is patch 6/7 of Harald Nordgren’s `git branch --delete-merged` series, now in its 20th iteration and unblocked for merging. The patch adds a per-branch opt-out mechanism via the `branch.<name>.deleteMerged` config key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The implementation is straightforward: during candidate filtering in `delete_merged_branches()`, the code checks for `branch.<name>.deleteMerged=false` and skips the branch with a non-quiet message. The opt-out is ignored by traditional `git branch -d`, which continues to use the normal merge check. Documentation is added to `branch.adoc` and `git-branch.adoc`, and the test suite verifies both the opt-out behavior and explicit deletion.

Phillip Wood’s earlier surface-level review suggested a mechanical test improvement (using `git for-each-ref` via the `check_branches` helper instead of `rev-parse` for branch state verification), which has been applied. The tests now cover opt-out behavior, skip messages, explicit deletion, and branch state verification. The implementation is clean, well-tested, and aligns with the series’ safety-focused design. No substantive issues remain.
