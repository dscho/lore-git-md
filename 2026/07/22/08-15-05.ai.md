This is the first patch in a two-patch bugfix series (v3) addressing edge cases in `git rebase --update-refs` when dealing with symbolic references (symrefs) to branches. The patch prevents rebase failures caused by duplicate updates to symrefs that point to other branches (e.g., `main` symlinked to `master` during a branch rename migration).

The core change is in `sequencer.c`, where the `add_decorations_to_list` function now resolves local branch decorations before queuing them for update. It skips symrefs whose targets are under `refs/heads/` to avoid duplicate updates, while preserving the symref itself. The patch also maintains an owned copy of the resolved HEAD to prevent interference from later ref resolution, and restores the unconditional skip for the current branch to avoid duplicate updates.

Test coverage in `t/t3404-rebase-interactive.sh` verifies the fix for both HEAD aliases (e.g., `no-conflict-branch-alias`) and secondary branch aliases (e.g., `second-alias`), confirming that symrefs remain intact after rebase and that only the concrete branch is updated. The changes are minimal and focused, addressing the specific issue without restructuring unrelated code.
