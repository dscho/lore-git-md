This is a bugfix for the revision walker. Junio C Hamano identifies a subtle logic error in how `--exclude-first-parent-only` interacts with commits that have already been marked `SEEN`. The current code skips the first parent when it is `SEEN` but then continues to process the second parent, incorrectly marking it as `UNINTERESTING`. The patch changes the `continue` to a `break` in two places, ensuring that once the first parent is handled (or skipped), no further parents are processed.

The fix is small and targeted: two new conditionals in `revision.c` and a new test case in `t/t6012-rev-list-simplify.sh` that verifies the behavior when the first parent is already `SEEN`. The commit message is clear and the test coverage looks sufficient. Jerry Zhang’s `Reviewed-by` suggests the patch has already received a second look. Given that this is a correctness issue in a core Git command, it is likely to be merged soon.
