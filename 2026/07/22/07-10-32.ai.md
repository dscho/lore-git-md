This is the first patch in Harald Nordgren’s **v20 `git branch --delete-merged` series**, which is now unblocked and ready for merging. This patch introduces the `--forked` filter for `git branch --list`, the foundational building block for the series’ core functionality.

The `--forked` filter lists only local branches whose configured upstream matches a given pattern. The argument can be a full refname (e.g., `refs/remotes/origin/main`), a remote shorthand (e.g., `origin`), or a shell-style glob (e.g., `origin/*`). The filter is repeatable, allowing users to widen the selection (e.g., `--forked origin/main --forked origin/next`). It is designed to compose with existing filters like `--merged` and `--no-merged`, enabling precise branch selection for cleanup workflows.

The implementation adds a new `ref_filter_forked_add()` function to register patterns and a `filter_forked_match()` helper to check each branch’s upstream against those patterns. Exact matches are compared against the full upstream refname, while glob patterns are matched against the abbreviated upstream name (e.g., `origin/main`). The filter also handles remote shorthand (e.g., `origin` for `origin/HEAD`) and integrates cleanly with the existing ref-filter machinery.

The test suite covers all key behaviors: exact ref matching, glob expansion, remote shorthand resolution, composition with other filters, and error handling for invalid patterns. The tests also verify that the filter works with local branches that track other local branches (e.g., `local-onbase` tracking `local-base`).

This patch is **well-tested and uncontroversial**, with no known issues. It establishes the filtering foundation for the `--delete-merged` subcommand introduced in patch 5/7.
