This is a bugfix patch targeting the `git-p4` Perforce interoperability tool in `contrib/`. The patch refines the `extractLogMessageFromGitCommit` helper in `git-p4.py` to return only the commit message body, stripping out metadata headers (author, tree, parent SHAs) that were previously included in the output. The change is minimal and surgical: it replaces the original logic that waited for the first blank line to mark the start of the message with a two-phase scan that first skips everything until the blank line, then collects the rest.

The patch is a direct response to the issue identified in the thread summary: the function was returning the entire raw commit object, which would cause Perforce-to-Git imports to include unwanted metadata in the imported commit messages. The fix is contained to a single file and introduces no new symbols or on-disk format changes. While the commit message does not provide a concrete user-facing scenario or reproduction case, the intent is clear and the implementation is straightforward.

This is a standalone patch, not part of any larger series or ongoing effort. The lack of test coverage is the most obvious gap, but the change is small enough that reviewers may not consider it a blocker.
