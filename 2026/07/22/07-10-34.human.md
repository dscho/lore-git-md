This is the third patch in Harald Nordgren’s **v20 `git branch --delete-merged` series**, which is now unblocked and ready for merging. This patch adds a `DELETE_BRANCH_SKIP_UNMERGED` flag to the branch-deletion API, allowing bulk callers (like the upcoming `--delete-merged` command) to silently skip unmerged branches instead of failing with an error message.

The change is straightforward: when the new flag is set, `check_branch_commit()` and `delete_branches()` suppress the "not fully merged" error and advice, returning success for unmerged branches instead of propagating an error. This enables the `--delete-merged` command to process many branches in one pass while preserving the safety of the traditional `git branch -d` behavior for existing callers.

The patch is **well-motivated**—it prepares the API for the bulk-deletion use case without altering the behavior of any current Git commands. The implementation is clean, with the flag tested directly at each use site to avoid stale cached values. This aligns with the series’ broader goal of introducing a flags-based API for branch deletion, which was previously reviewed and approved by Phillip Wood.

It is a mechanical refactoring that introduces no behavioral changes for existing callers and is a prerequisite for the core `--delete-merged` functionality in patch 5/7.
