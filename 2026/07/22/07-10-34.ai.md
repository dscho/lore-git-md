This is the third patch in Harald Nordgren’s **`git branch --delete-merged`** series (v20, 3/7). It introduces a new flag, `DELETE_BRANCH_SKIP_UNMERGED`, to the existing `delete_branches()` API, allowing bulk callers (like the upcoming `--delete-merged` subcommand) to silently skip unmerged branches instead of failing with an error. The change is mechanical and preserves the behavior of all existing callers.

The patch modifies `check_branch_commit()` and `delete_branches()` to check the new flag before emitting errors or setting a failure return code. When `DELETE_BRANCH_SKIP_UNMERGED` is set, unmerged branches are skipped without error messages, enabling the caller to continue processing the remaining branches. This is critical for the `--delete-merged` subcommand, which needs to handle unmerged branches gracefully rather than aborting the entire operation.

The implementation is straightforward: the new flag is added to the `enum delete_branch_flags`, and the error-handling paths in both functions are gated by a conditional check. The patch does not alter the core merge-check logic or introduce new edge cases. All existing callers (e.g., `git branch -d`) remain unaffected, as they do not set the new flag.

This is a **refactoring patch** that prepares the codebase for the `--delete-merged` subcommand (introduced in patch 5/7). The change is uncontroversial and aligns with the series’ goal of providing a safe, automated branch-cleanup mechanism. The patch is **ready for merging** as part of the larger series, which is now unblocked after resolving the order-dependency issue in stacked-branch protection.

Key files touched: `builtin/branch.c`. No new tests are added here, as the behavior change is tested in later patches that exercise the new flag.
