This is the first patch in a two-part bugfix series for `git rebase --update-refs` when dealing with symbolic references (symrefs) to branches. The patch prevents rebase failures that occur when a symref (like `main` pointing to `master`) causes duplicate ref updates after the primary branch has already been successfully rewritten.

The core issue is that `git rebase --update-refs` processes branch decorations, including symrefs, which can lead to redundant updates when the symref's target is also a branch under `refs/heads/`. This patch resolves the problem by skipping symrefs that point to other branches, ensuring only the concrete branch is updated. It also maintains an owned copy of the resolved HEAD to prevent later ref resolution from interfering with the current branch check.

The implementation in `sequencer.c` uses `refs_resolve_refdup()` for safe symref resolution and adds logic to skip symrefs whose targets are under `refs/heads/`. The patch restores the unconditional skip for the current branch (previously removed in v2) and includes test updates to verify the behavior. Tests in `t3404-rebase-interactive.sh` confirm that symrefs like `no-conflict-branch-alias` and `second-alias` remain intact after rebase, with their targets correctly updated.
