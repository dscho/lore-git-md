This thread is about a memory leak in Git’s macOS builds when the system regex engine (TRE) processes invalid UTF-8 sequences. The issue can cause `git grep` over binary files to leak gigabytes of memory, risking kernel watchdog panics. Chungmin Lee posted a fix in v2, which adds a Darwin-specific workaround in dedicated platform files (`compat/darwin.h` and `compat/darwin/regexec.c`). The patch splits input buffers at invalid multibyte boundaries, avoiding the leaking code path while preserving all genuine matches.

Junio C Hamano reviewed the v2 patch and found it structurally sound, addressing his earlier concerns about maintainability and organization. He suggested a minor addition: a comment in the `Makefile` to document when users should define the `DARWIN_REGEXEC` symbol, similar to other platform-specific flags. He even provided a ready-to-squash patch for this change. The patch is now effectively ready for merging, pending this trivial update. The fix is narrowly scoped to macOS builds using the system regex engine, with no behavioral changes for valid UTF-8, and includes thorough test coverage for edge cases.
