This thread is about a critical macOS-specific memory leak in Git’s regex handling. Chungmin Lee reports that when `git grep` processes files with invalid UTF-8 sequences (like PDFs), the system regex engine (TRE) on macOS leaks memory—sometimes gigabytes per command—risking kernel watchdog panics. The fix, implemented in `compat/regexec.c`, works around the bug by splitting input buffers at invalid multibyte sequences and searching each valid segment separately, avoiding the leaking path entirely.

The patch is narrowly targeted: it only affects macOS builds using the system regex engine (skipping ASAN builds via `NO_REGEX`) and preserves all genuine matches. It includes regression tests in `t7810-grep.sh` to verify behavior around invalid bytes and anchoring. The solution is conservative, with detailed commit messages explaining both the problem and the constraints of the workaround. While the fix is safe to drop once Apple patches the underlying bug, it’s a pressing issue for macOS users today.
