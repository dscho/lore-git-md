This is the final patch in Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. It targets the bisect subsystem (`builtin/bisect.c`), where `bisect_run()` temporarily redirects stdout to capture command output but fails to check whether `dup(1)` succeeded. Without this check, a failed `dup()` leaves `saved_stdout` as `-1`, which later causes `close(-1)` (triggering Coverity’s warning) and prevents stdout from being restored, leaving the process’s output misdirected for the remainder of the bisect run.

The fix is minimal and mechanical: after calling `dup(1)`, the code now checks if the returned descriptor is negative. If so, it closes the temporary file descriptor, emits an `error_errno()` message, and breaks out of the loop, letting the existing cleanup path handle the rest. This matches the error-handling pattern already used elsewhere in the function and ensures the bisect operation fails cleanly rather than silently proceeding with broken output redirection.

Like the rest of the series, this patch is uncontroversial and well-motivated. It touches only one file, introduces no new behavior, and addresses a clear correctness issue. The commit message is concise but complete, naming the Coverity CID and explaining both the problem and the fix. The series as a whole is now fully reviewed and ready for integration; this patch is the last piece of the hardening effort.
