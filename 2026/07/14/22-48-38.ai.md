This is the fifth patch in Johannes Schindelin’s 11-patch series fixing unchecked return values reported by Coverity. It targets the `git last-modified` command (`builtin/last-modified.c`), where three calls to `repo_parse_commit()` previously ignored failures, leading to silent misbehavior when commits are corrupt or unavailable (e.g., in shallow or partial clones).

The patch adds explicit error checks at all three sites. When parsing fails, the code now skips the problematic commit (or parent) rather than proceeding with uninitialized data. This matches the defensive pattern used elsewhere in Git’s revision walkers and ensures that "last modified" results are not silently incorrect. The fix is mechanical and uncontroversial, with no new behavior or on-disk format changes. The commit message clearly explains the consequences of the unchecked return values and how the patch addresses them.
