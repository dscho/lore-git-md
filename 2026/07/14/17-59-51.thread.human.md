This thread is about René Scharfe’s 5-patch series introducing repository-aware variants of Git’s tempfile and lockfile APIs, part of the broader effort to remove the global `the_repository` variable. The series is mechanical, touching 38 files across core subsystems like ref backends, commit-graph, and ODB, with no user-visible changes. The goal is to push repository parameters outward through the plumbing layer, eliminating implicit reliance on `the_repository`.

The series has been queued in Junio’s `seen` branch since July 10, with no major objections. Junio’s cursory review found nothing glaring, and Patrick Steinhardt, while raising substantive design questions—such as whether passing a full `struct repository *` is overkill when only `core.sharedRepository` is needed—ultimately welcomed the change as a practical step forward. His feedback on patch 5/5 included a request for a compile-time guard (`USE_THE_REPOSITORY_VARIABLE`) to prevent new callers from reintroducing `the_repository` dependencies, but René pushed back, arguing this should be addressed in a separate series. Junio’s latest reply clarifies that while the guard is a medium-term goal, it doesn’t need to block this series. The thread leaves the guard’s implementation as a loose end for future work.

The series is incremental, converting only callers that already hold a `struct repository *` reference, and René has documented this rationale in the thread. No v2 is expected, and the patches are aligned with the ongoing `the_repository` removal effort. The only unresolved question is whether the compile-time guard will be added later, but this doesn’t affect the current series’ trajectory.
