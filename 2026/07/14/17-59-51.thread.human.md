This thread is about René Scharfe’s five-patch series that adds repository-aware variants of Git’s tempfile and lockfile APIs (`repo_create_tempfile`, `repo_hold_lock_file_for_update`, etc.). The goal is to eliminate implicit reliance on the global `the_repository` variable, part of the long-running effort to remove this global. The series is mechanical and touches plumbing code across apply, builtins, ref backends, commit-graph, midx, ODB, and config subsystems—no user-visible changes are expected.

So far, the first two patches have laid the groundwork: patch 1 introduced the new tempfile functions, and patch 2 converted the first caller (`refs/packed-backend.c`). The latest email covers patch 3, which adds the corresponding lockfile functions (`repo_hold_lock_file_for_update`, etc.) and wires them into the internals. These new functions delegate to the existing `lock_file_timeout` machinery, now modified to accept a `struct repository *` parameter. The old non-repo entry points remain as thin wrappers around the new ones, ensuring backward compatibility. No callers are converted yet; that happens in patch 5.

The series is still under review (v1 posted), with no substantive feedback or objections recorded. It’s a clean, incremental step in the `the_repository` removal effort, and the changes are confined to plumbing. If the pattern holds, the remaining patches will convert additional callers and extend the API further. No merge status has been reported yet.
