This is patch 5/13 in the seventeenth iteration of a security-focused feature series implementing `git cat-file --batch-command`'s `remote-object-info` functionality. The patch eliminates the static `advertise_sid` variable in `fetch-pack.c` to prepare for the upcoming relocation of `write_fetch_command_and_capabilities()` to `connect.c`.

The change addresses the critical refactoring flaw Junio Hamano identified in v15, where a local `advertise_sid` variable was introduced without removing the file-scope global, leaving the code in an inconsistent state. This version resolves that by:
- Removing the static variable entirely
- Moving the `!server_supports("session-id")` check from `do_fetch_pack()` to `find_common()` where it logically belongs (since it only affects v0/v1 protocol)
- Initializing local variables via `repo_config_get_bool()` in both `find_common()` and `write_fetch_command_and_capabilities()`
- Explicitly setting the default value to 0 to match the original behavior

The patch is purely mechanical and preparatory, with no behavior changes. It enables the subsequent function relocation while maintaining the existing session-id advertisement logic. The `Helped-by` trailers credit Jonathan Tan and Christian Couder for design input, indicating this was a collaboratively reviewed solution to the earlier refactoring issue. This is a key cleanup that removes a potential source of undefined behavior while keeping the codebase consistent.
