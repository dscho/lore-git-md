This is the sixth patch in Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. It targets the `git_pread()` compatibility shim in `compat/pread.c`, which is used on platforms lacking a native `pread()` system call.

The bug is straightforward: `git_pread()` saves the current file offset with `lseek(fd, 0, SEEK_CUR)` but does not check the return value. If the descriptor is non-seekable (e.g., a pipe), `lseek()` returns `-1`, leaving `current_offset` set to `-1`. Later, the code attempts to restore the original position with `lseek(fd, -1, SEEK_SET)`, which either fails with `EINVAL` or silently sets the file position to an unintended location, corrupting subsequent reads.

The fix is minimal: add a check immediately after the first `lseek()` and return `-1` if it fails, matching the existing error handling for the second `lseek()` call. The patch is purely defensive, introducing no new behavior or dependencies. It is uncontroversial and mechanically sound, fitting the series’ overall goal of hardening error paths without changing functionality.
