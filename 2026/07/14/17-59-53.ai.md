This is the second patch in René Scharfe’s five-patch series converting the tempfile and lockfile APIs to be repository-aware as part of the `the_repository` removal effort.

The patch itself is tiny: a single-line change in `refs/packed-backend.c` that replaces the call to the global `create_tempfile()` with the new `repo_create_tempfile()`, passing the ref store’s base repository (`refs->base.repo`) instead of implicitly using `the_repository`. The commit message explains that this ensures the `core.sharedRepository` setting is read from the correct repository rather than the global one. No other files are touched, and the change is purely mechanical.

Because the new API was introduced in patch 1/5, this patch is the first actual conversion of a caller. The refs subsystem is a natural early adopter because it already works with non-default repositories. The diff is minimal, the motivation is clear, and the change aligns perfectly with the series’ goal of eliminating implicit reliance on `the_repository`. No controversy or open questions are evident; this looks like a straightforward, well-targeted step in the ongoing refactoring.
