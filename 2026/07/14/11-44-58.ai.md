This is a refactoring patch that improves code hygiene by moving loop counter declarations inside their `for()` statements. Part of the long-running `remote-object-info` series (v17, patch 2/10), it addresses a minor but persistent readability issue that was noted during review of earlier versions.

The patch changes four loops—three in `builtin/cat-file.c` (`dispatch_calls()`, `free_cmds()`, and `batch_objects_command()`) and one in `fetch-pack.c` (`write_fetch_command_and_capabilities()`)—to declare their counters (`i`) inside the `for()` statement rather than at function scope. Where the loop bound is a `size_t` (e.g., `nr`, `ARRAY_SIZE()`), the counter is also changed from `int` to `size_t` to eliminate signed/unsigned comparison warnings. The changes are purely mechanical and have no behavior impact; they simply keep declarations close to use, following Git’s coding style.

This is preparatory cleanup for the larger series, which adds the `remote-object-info` command to `git cat-file --batch-command`. The patch was originally authored by Eric Ju and carries a Helped-by trailer from Christian Couder, indicating it benefited from design-level input. It has been incorporated into Pablo Sabater’s v17 resend, which is now ready for merging to `next`. The change is uncontroversial and aligns with established Git practice.
