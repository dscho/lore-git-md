This is the ninth patch in the seventeenth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. This specific patch enables servers to advertise their support for the `object-info` capability, controlled by the `transfer.advertiseobjectinfo` configuration (disabled by default).

The patch updates both the protocol documentation and the server implementation. In `gitprotocol-v2.adoc`, it clarifies several protocol requirements: full object IDs must be used (no short OIDs), fixes a parenthesis mismatch, explicitly defines `obj-size` as a numeric field, and documents that servers return only the object ID (with no metadata) for unrecognized objects. The server-side change in `serve.c` populates the capability value with "size" when the feature is enabled, following the documented space-separated attribute list format.

This is a well-crafted, uncontroversial patch that directly enables the client-side functionality implemented in later patches. The documentation updates are thorough and address edge cases, while the server implementation is minimal and secure (disabled by default). The patch maintains the series' focus on security by keeping the feature opt-in and documenting behavior for unrecognized objects. All review feedback from earlier versions appears to be addressed, and the patch is ready for integration.
