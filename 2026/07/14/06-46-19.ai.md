This is a substantive review in the ongoing packfile URI download race condition bugfix series. Jeff King (Peff) engages deeply with the design and implementation of Patch 1/2, which uses unique tempfiles for packfile URI downloads to prevent corruption from concurrent append operations.

Peff proposes an alternative approach: instead of using unique tempfiles, keep the deterministic path but open the file in write-only mode (without O_APPEND) using low-level file descriptors, avoiding the corruption caused by concurrent appends. He provides a minimal diff demonstrating this approach and confirms it passes the existing test. However, he acknowledges this is more of a discussion point than a counter-proposal, noting potential portability concerns and the risk of silent corruption if conflicting data is written.

He also questions the trade-off of abandoning resumable downloads for packfile URI fetches, arguing this is a regression that could matter to users, especially given packfile URIs are marketed as resumable. He suggests two potential improvements if resumption is abandoned: allowing users to opt into resumable behavior via configuration, and piping the download directly to `index-pack --stdin` to reduce disk I/O and enable pipelining. The latter would also inherently fix the concurrency issue by leveraging `index-pack`'s own tempfile handling.

Peff’s review is thorough and constructive, covering both high-level design trade-offs (correctness vs. efficiency, resumption vs. simplicity) and low-level implementation details (file handling, error paths, naming clarity). He raises no blocking objections but clearly signals that the current design’s loss of resumption is a meaningful drawback worth reconsidering. The review advances the thread by surfacing alternative approaches and clarifying the stakes of the design choices.
