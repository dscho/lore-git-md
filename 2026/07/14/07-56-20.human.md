This is a bug report about `git log --cherry-mark`.

Uwe Kleine-König reports that `git log --cherry-mark --right-only` fails to mark a commit as equivalent (`=`) when the range includes a merge commit, even though the same commit *is* correctly marked when the merge commit is excluded from the range. He demonstrates the issue with a real-world example from the Linux kernel tree, using Git 2.55.0 plus Phillip Wood’s recent series that addressed a previous bug in the same area.

The discrepancy appears when comparing `next/master...a54cadc575df` (which includes a merge) versus `next/master...a54cadc575df^2` (which excludes it): in the former, the commit `ca270a534d0f` is shown without the `=` marker, while in the latter it is correctly marked as equivalent. Uwe asks whether his expectation is wrong or whether this is a genuine bug.

No patch is attached; the author offers to provide a bundle of the relevant commits privately if needed. The report is clear and includes exact command lines and output, making it easy for a reviewer to reproduce.
