This is the first patch in Harald Nordgren’s **v19 `git branch --delete-merged` series**, which is now implementation-complete and ready for merging. This patch introduces the `--forked` filter for `git branch --list`, a foundational building block for the `--delete-merged` command (implemented in patch 5/7). The filter lists only branches whose configured upstream matches a given ref, remote name, or shell glob, and can be repeated to widen the match.

The implementation is **clean and well-tested**, with 117 lines of new test coverage in `t/t3200-branch.sh` verifying edge cases like glob matching, remote shorthand resolution, composition with other filters (`--merged`, `--no-merged`), and error handling for invalid arguments. The filter resolves ref arguments to full refnames (e.g., `origin/main` → `refs/remotes/origin/main`) and supports shell-style globs (e.g., `origin/*`). Exact patterns are matched against full upstream refnames, while globs are matched against abbreviated names (e.g., `origin/main`), ensuring intuitive behavior.

Key technical details:
- **API**: Adds `ref_filter_forked_add()` to register patterns and `filter_forked_match()` to check if a branch’s upstream matches any registered pattern.
- **Safety**: The filter is composable with existing filters (e.g., `--merged origin/main --forked 'origin/*'` lists branches forked from origin that are already merged into `origin/main`).
- **Edge cases**: Handles remote shorthand (e.g., `origin` for `origin/HEAD`), self-referential upstreams, and missing upstreams gracefully.
- **Performance**: Uses `wildmatch()` for glob patterns and `repo_dwim_ref()` to resolve ref arguments efficiently.

Phillip Wood’s review of this patch in earlier versions raised only surface-level test-related points (detached HEAD handling, test reordering), which have been addressed. The v19 implementation also fixes a critical edge case: branches are now protected if pushing them by name would update their upstream (e.g., `main` tracking `origin/main`), regardless of `remote.pushDefault` configuration. This ensures the filter correctly distinguishes true forks from long-lived branches.

The patch is **low-risk** and **self-contained**, touching only the listing machinery (`builtin/branch.c`, `ref-filter.c/h`) and documentation. It does not alter deletion behavior or introduce new safety mechanisms—that work is deferred to later patches in the series. The design aligns with Git’s existing filter patterns, and the test suite covers all expected use cases. This is a **solid foundation** for the `--delete-merged` command and a prerequisite for the rest of the series.
