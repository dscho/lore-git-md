This is a performance inquiry about the `git last-modified` command, authored by Toon Claes and now being evaluated by a Forgejo contributor.

Gusted reports that `git last-modified -z -t --max-depth=0` is consistently about 2.5× slower than a hand-rolled `git log --name-status -c --format=... --parents --no-renames -t -z` pipeline when run against the ziglang/zig repository. Both commands are given the same commit and path filter (`doc/langref/`), and the repository has a commit-graph with changed-path Bloom filters precomputed. The benchmark shows 66 ms for `last-modified` versus 26 ms for the `log` pipeline.

The email is not a patch or a review; it is a request for insight. Gusted is asking whether the performance gap is expected, whether there is a more efficient invocation of `git last-modified`, or whether the command itself could be optimized. The thread context shows this is the first message in the thread, so no prior discussion exists yet.
