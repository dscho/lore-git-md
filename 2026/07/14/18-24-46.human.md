This is the **final v19** of Harald Nordgren’s `git branch --delete-merged` series, now **implementation-complete and ready for merging**. The series adds a safe, automated local-branch cleanup command that deletes branches whose work has already landed on their upstream, while preserving branches that are checked out, missing their upstream, pushing back to their upstream (like `main` tracking `origin/main`), or opted out via `branch.<name>.deleteMerged` config.

The key changes in v19 address the last remaining mechanical issues from v18:
- **Fixed a bug where `--dry-run` would still remove config** (now properly skips all modifications).
- **Redesigned `--delete-merged` as a repeatable upstream selector** with optional positional patterns to limit deletion scope (e.g., `git branch --delete-merged origin/main 'feature*'`).
- **Simplified flags handling** by testing `DELETE_BRANCH_*` bits directly at each use site, eliminating the maintenance risk of cached boolean locals.
- **Clarified assertions in tests** and improved branch naming (e.g., `local-to-delete` instead of `on-local`).

The series is structured as seven patches:
1. Adds the `--forked` filter for `--list` mode (unchanged from v18).
2. Converts `delete_branches()` to use an `unsigned int flags` argument (now tests flags directly).
3. Adds `DELETE_BRANCH_SKIP_UNMERGED` to skip unmerged branches silently (unchanged).
4. Prepares `delete_branches()` for bulk callers with `DELETE_BRANCH_NO_HEAD_FALLBACK` (unchanged).
5. Implements `--delete-merged` with all safety checks, including **refined stacked-branch protection** (abort-and-clear) and support for positional patterns.
6. Adds the `branch.<name>.deleteMerged` opt-out mechanism (unchanged).
7. Adds `--dry-run` support for `--delete-merged` (now properly skips config modifications).

### Core behavior

- **Safety checks**: Branches are spared if they are checked out, missing their upstream, pushing to the same ref as their upstream, or opted out via `branch.<name>.deleteMerged=false`.
- **Stacked-branch protection**: The command **fails to delete a branch if it is used as an upstream for an unmerged branch**, but **clears the upstream config for kept (merged) branches whose own upstream is being deleted**. This avoids breaking dependency chains while cleaning up stale configs.
- **`--dry-run`**: Prints "Would delete branch <name>" or "Would skip branch <name> (used as upstream)" for each affected branch, matching the real deletion/protection output exactly.
- **Positional patterns**: Optional `<pattern>` arguments limit which local branches are considered (e.g., `git branch --delete-merged origin/main 'topic-*'`).

**Test coverage** is comprehensive, verifying:
- Merged branches are deleted while unmerged/checked-out/protected/opt-out branches are spared.
- Stacked-branch protection (abort-and-clear) handles chains of dependencies (e.g., `b1→b2→b3`) and self-referential upstreams.
- `--dry-run` output matches real deletion/protection output.
- Per-branch opt-out via `branch.<name>.deleteMerged=false` works as expected.
- Positional patterns limit deletion scope correctly.
