This is the first patch in Harald Nordgren’s **v19 `git branch --delete-merged` series**, which is now implementation-complete and ready for merging. This patch introduces the `--forked` filter for `git branch --list`, a foundational building block for the upcoming `--delete-merged` command.

The `--forked` option lets users list only branches whose upstream matches a given ref, remote name, or shell glob. For example, `git branch --forked origin/main` lists branches tracking `origin/main`, while `git branch --forked 'origin/*'` matches all branches tracking any `origin/` branch. The filter is repeatable (e.g., `--forked origin/main --forked origin/next`) and composable with existing filters like `--merged` or `--no-merged`. The implementation resolves ref arguments to full refnames (e.g., `origin/main` → `refs/remotes/origin/main`) and supports glob patterns for flexible matching.

The patch is **well-tested**, with comprehensive coverage for exact refnames, remote shorthand (e.g., `origin`), glob patterns, and edge cases like unknown branches or missing values. The commit message clearly explains the motivation: this filter is the selection mechanism for `--delete-merged`, which will delete branches once they’ve landed upstream.
