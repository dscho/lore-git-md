This is a refactoring patch that converts `show-branch.c` to use a commit-slab instead of the shared `object.flags` field for storing per-commit state. The patch replaces direct access to `commit->object.flags` with a dedicated `commit_rev_flags` slab and helper functions (`get_rev_flags`, `or_rev_flags`). The change eliminates a fragility where `show-branch` was using bits in a globally shared field (risking conflicts with other subsystems) and aligns the code with Git’s canonical pattern for per-commit data.

The patch touches only `builtin/show-branch.c`, adding 39 lines and removing 23. It defines the new slab, initializes and clears it in `cmd_show_branch`, and updates all flag accesses to use the slab helpers. The commit message clearly explains the motivation (avoiding `object.flags` conflicts) and the implementation (commit-slab as the standard alternative). No behavior change is intended, and the patch appears to be a clean, mechanical conversion.

This is part of the broader effort to eliminate misuse of `object.flags`, a recurring theme in Git refactoring. The patch is well-scoped, well-explained, and unlikely to be controversial. It looks like a solid contribution from a new contributor.
