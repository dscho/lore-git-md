This is a substantive review comment on the first patch of Ted Nyman’s packfile URI race-condition series. Junio C Hamano raises a design-level concern: while the patch’s use of unique tempfiles is correct and safe, it may be inefficient by forcing redundant downloads when multiple processes fetch the same packfile concurrently. Instead of each process starting its own download, Junio suggests a coordination mechanism where the second process detects an in-progress download (via `O_CREAT | O_EXCL` on a predictable tempfile) and waits for the first process to finish rather than initiating a separate network request.

The review touches the core trade-off between correctness and performance in concurrent HTTP fetches. Junio’s proposal would preserve the resumable behavior for packfile URI downloads while avoiding redundant work, but it introduces complexity (polling, cleanup on process death) that the current patch avoids. The discussion is now open on whether the simplicity of unique tempfiles is preferable to the efficiency of coordinated downloads, and how much additional machinery is justified for this edge case. No implementation or code-level feedback is provided yet; this is purely a design question.
