This is the first patch in Paulius Zaleckas’s v4 series introducing configurable submodule fetch errors. It fixes a long-standing logic flaw in `submodule.c` where phase-1 fetch failures were recorded prematurely, before phase-2 OID-based retries could run. The patch restructures `fetch_finish()` to defer error recording until all retry attempts are exhausted, ensuring the overall fetch succeeds if the missing commits are retrieved by phase 2. The fix also extracts a helper `record_fetch_error()` for consistent error handling and updates error reporting to include the submodule name in the final summary.

The patch touches `submodule.c` and adds a new test in `t/t5526-fetch-submodules.sh` that verifies a failed submodule fetch is still reported even when the gitlinked commits are present locally. The test sets up an isolated environment with a superproject and submodule, creates an unreachable commit, and breaks the submodule’s remote to force a fetch failure, ensuring the error is surfaced despite the commits being locally available. The commit message clearly explains the problem, the solution, and the edge cases addressed, making the rationale easy to follow.

This is a refactoring patch that is technically necessary for the feature introduced in the second patch. It preserves the current fatal behavior while enabling the configurable policy, and the changes are narrowly scoped to the submodule fetch error-handling path. The test coverage is thorough, and the implementation appears robust. No open questions remain, and the patch is uncontroversial. It should be uncontroversial to merge once the series is reviewed.
