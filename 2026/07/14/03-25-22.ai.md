This is part 7 of a 10-patch refactoring series that migrates global configuration variables into `struct repo_config_values` as part of the ongoing `the_repository` removal effort. This patch moves the `push_default` enum (which controls the default behavior of `git push` when no refspec is provided) into the repository-specific configuration structure.

The patch resolves a circular header dependency by keeping the `enum push_default_type` definition in `environment.h` rather than moving it to `remote.h`, where it logically belongs. A `NEEDSWORK` comment is added to flag this as a future cleanup opportunity. The configuration parser in `environment.c` is updated to write to the per-repository structure, and all callers in `builtin/push.c` and `remote.c` are modified to read the value via `repo_config_values(the_repository)->push_default`. The global variable `push_default` is removed.

The change is mechanical and well-contained, touching only four files. The commit message clearly explains the circular dependency issue and the rationale for the temporary placement of the enum. No user-visible behavior changes are introduced, and the patch maintains backward compatibility. This is a solid step in the libification effort, though the `NEEDSWORK` comment indicates follow-up work is needed to relocate the enum definition. The patch is ready for integration and has no open technical concerns.
