This is the penultimate patch in the v17 series implementing the `remote-object-info` command for `git cat-file --batch-command`. The patch adds the user-facing command that allows querying object metadata (currently just size) from remote repositories without downloading the full objects.

The implementation introduces a new `remote-object-info` command that accepts a remote URL followed by one or more object IDs. Unlike the existing `info` command, which processes objects one at a time, `remote-object-info` batches multiple object requests into a single network call to minimize overhead. The command works in both regular and `--buffer` modes, with special handling to ensure batched requests are sent together rather than individually.

Key aspects of the implementation:
- Input validation enforces strict limits (10,000 objects max, 8KB URL length) to prevent abuse
- The command supports all three transport protocols (`git://`, `file://`, `http://`)
- Only `%(objectname)` and `%(objectsize)` placeholders are currently supported, with clear documentation about future extensibility
- Comprehensive error handling covers unsupported capabilities, malformed OIDs, missing objects, and protocol version requirements
- The patch includes 680 lines of new tests in `t/t1017-cat-file-remote-object-info.sh` covering all transport types, edge cases, and error conditions

The implementation maintains compatibility with existing batch-command workflows while adding the new functionality. The documentation clearly warns users not to rely on the current default format (`%(objectname) %(objectsize)`) remaining unchanged when additional metadata like object types become supported.

This patch completes the series by providing the actual user-facing functionality that was prepared in earlier patches, including the core client-side implementation, server capability advertisement, and dynamic placeholder validation. The implementation demonstrates careful attention to security through strict input validation, protocol enforcement, and memory safety.
