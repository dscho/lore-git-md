Subject: [PATCH v2] show-branch: use commit-slab for per-commit state instead of object.flags
Series version: v6 (standalone patch, supersedes v5 by Gatla Vishweshwar Reddy, v4, v3, and v2 by the same author, and an earlier RFC by Meet Soni)
Originating author: Gatla Vishweshwar Reddy
Thread type: refactoring patch

Core problem or goal
Refactor `builtin/show-branch.c` to eliminate its reliance on the shared `object.flags` field for per-commit state, replacing it with a dedicated commit-slab (`commit_rev_flags`) that uses a configurable stride of `uint64_t` words. This removes the risk of flag-bit collisions with other subsystems, aligns the code with Git’s canonical pattern for per-commit data storage, and lifts the previous 27-branch limit to 64 branches (with a path forward for dynamic stride to support even more branches). The `UNINTERESTING` bit remains in `object.flags` for revision-walking compatibility.

Current status
Under review. This is the sixth iteration of the patch, addressing Junio C Hamano’s feedback on v5: (1) restored the propagation of the `UNINTERESTING` bit to parents in `join_revs()`, (2) reinstated the original logic in `join_revs()` that avoids redundant traversal, (3) updated documentation and error messages to reflect the new 64-branch limit, and (4) replaced the non-portable `%zu` format specifier with a portable alternative. The v6 delta also adds three new tests in `t3202-show-branch.sh` to verify correct operation with 30+ branches, including `--independent` and `--merge-base` modes. The patch is now technically ready for maintainer sign-off; no further feedback has been received since v6 was posted.

Key technical details
- Files touched: `builtin/show-branch.c` (primary refactoring), `Documentation/git-show-branch.adoc` (limit update), `t/t3202-show-branch.sh` (new tests)
- New symbols: `commit_rev_flags` slab (configurable stride of `uint64_t` words), `flags_stride`, `get_rev_flags_ptr()`, `or_rev_flag_bit()`, `test_rev_flag_bit()`, `has_all_rev_flags()`, `has_only_rev_flag_bit()` helpers
- Old behavior: direct access to `commit->object.flags` for per-commit state, limited to 27 branches due to 32-bit storage; `show_independent()` checks for *exactly* the current branch’s bit set; `join_revs()` propagates `UNINTERESTING` to parents and avoids redundant traversal
- New behavior: slab-based storage with configurable stride (64 bits by default), lifting the branch limit to 64, with infrastructure for dynamic stride to support more branches. The `UNINTERESTING` bit remains in `object.flags` for revision-walking compatibility. The regression in `show_independent()` was fixed in v4 via `has_only_rev_flag_bit()`, and the regressions in `join_revs()` (propagation of `UNINTERESTING` and redundant traversal avoidance) were fixed in v6. Documentation and error messages now reflect the 64-branch limit, and the `%zu` format specifier has been replaced with `%lu` and an explicit `(unsigned long)` cast. Three new tests in `t3202-show-branch.sh` verify correct operation with 30+ branches, including `--independent` and `--merge-base` modes.
- Test coverage: existing tests continue to pass; new tests in `t3202-show-branch.sh` cover 30+ branches, `--independent`, and `--merge-base` modes
- Delta from v5: (1) restored propagation of `UNINTERESTING` to parents in `join_revs()`, (2) reinstated the original logic in `join_revs()` that avoids redundant traversal, (3) updated documentation and error messages to reflect the new 64-branch limit, (4) replaced the non-portable `%zu` format specifier with `%lu` and an explicit `(unsigned long)` cast, and (5) added three new tests in `t3202-show-branch.sh` to verify correct operation with 30+ branches, including `--independent` and `--merge-base` modes
- Prior art: reuses `init_commit_rev_flags_with_stride` infrastructure from the 2025 variable-length bitset slab series (commit 20250225011757.GA752084)
