Subject: [PATCH v2] show-branch: use commit-slab for per-commit state instead of object.flags
Series version: v4 (standalone patch, supersedes v3 by Gatla Vishweshwar Reddy, v2 by the same author, and an earlier RFC by Meet Soni)
Originating author: Gatla Vishweshwar Reddy
Thread type: refactoring patch

Core problem or goal
Refactor `builtin/show-branch.c` to eliminate its reliance on the shared `object.flags` field for per-commit state, replacing it with a dedicated commit-slab (`commit_rev_flags`) that uses a configurable stride of `uint64_t` words. This removes the risk of flag-bit collisions with other subsystems, aligns the code with Git’s canonical pattern for per-commit data storage, and lifts the previous 27-branch limit to 64 branches (with a path forward for dynamic stride to support even more branches). The `UNINTERESTING` bit remains in `object.flags` for revision-walking compatibility.

Current status
Under review. This is the fourth iteration of the patch, addressing Junio C Hamano’s feedback on v3: the behavioral regression in `show_independent()` has been fixed by introducing the `has_only_rev_flag_bit()` helper, which restores the exact-bit-set check (a commit is independent only if it is reachable from exactly one tip, not merely if the i-th bit is set). The patch preserves existing behavior except for the now-resolved regression. No merge status reported; awaiting maintainer sign-off once reviewers confirm the fix. Patrick Steinhardt’s recent email was a meta-level reminder about mailing-list etiquette (replying to review comments) and does not affect the technical status.

Key technical details
- Files touched: `builtin/show-branch.c` only
- New symbols: `commit_rev_flags` slab (configurable stride of `uint64_t` words), `get_rev_flags_ptr()`, `or_rev_flag_bit()`, `test_rev_flag_bit()`, `has_all_rev_flags()`, `has_only_rev_flag_bit()` helpers
- Old behavior: direct access to `commit->object.flags` for per-commit state, limited to 27 branches due to 32-bit storage; `show_independent()` checks for *exactly* the current branch’s bit set
- New behavior: slab-based storage with configurable stride (64 bits by default), lifting the branch limit to 64, with infrastructure for dynamic stride to support more branches. The `UNINTERESTING` bit remains in `object.flags` for revision-walking compatibility. The regression in `show_independent()` is now fixed: the exact-bit-set check is restored via `has_only_rev_flag_bit()`.
- Test coverage: unchanged (existing tests continue to pass, and the regression is now caught by the logic)
- Delta from v3: (1) introduced `has_only_rev_flag_bit()` helper to restore the exact-bit-set check in `show_independent()`, (2) updated commit message to document the fix
- Prior art: reuses `init_commit_rev_flags_with_stride` infrastructure from the 2025 variable-length bitset slab series (commit 20250225011757.GA752084)
