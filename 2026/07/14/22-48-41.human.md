This is the eighth patch in Johannes Schindelin’s 11-patch series fixing unchecked return values flagged by Coverity. It targets the transport-helper subsystem, specifically the `push_refs_with_export()` function in `transport-helper.c`.

The patch addresses a silent failure in the fast-export marks file finalization. After a successful push, the code writes the marks to a `.tmp` file and renames it into place, but previously ignored the return value of `rename()`. If the rename fails (due to permissions, disk full, or antivirus interference on Windows), the `.tmp` file is left behind, and the existing `export_marks` file remains stale. The next fast-export operation then resumes from inconsistent bookkeeping, risking silent corruption.

The fix is minimal: it checks the return value of `rename()` and emits a `warning_errno()` if it fails, naming both the source and destination paths so the user can recover manually. The push itself is not failed—this is a warning, not a fatal error, since the push already succeeded. The change is uncontroversial and aligns with the series’ goal of hardening code paths without altering behavior. No new config keys, options, or on-disk formats are introduced.
