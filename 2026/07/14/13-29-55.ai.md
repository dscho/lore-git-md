This is a two-patch series targeting the submodule and fetch subsystems, now at v4. The goal is to make submodule fetch errors configurable, allowing users to choose between the current hard failure (`fail`) or a warning-only mode (`warn`) when `git fetch --recurse-submodules` encounters a submodule whose gitlink points to an unreachable OID.

The series is well-structured and addresses a real workflow pain point: upstream topic branches that are still in flux can disrupt fetches even when the local branch doesn’t depend on the missing commits. Patch 1 fixes a pre-existing logic flaw in `submodule.c` where phase-1 fetch failures were recorded prematurely, before phase-2 OID-based retries could run. This refactoring ensures errors are only recorded after all retry attempts fail, preserving the current fatal behavior while enabling the configurable policy introduced in Patch 2. The fix is technically sound and necessary for the feature to work correctly.

Patch 2 introduces `fetch.submoduleErrors` (config) and `--submodule-errors=(fail|warn)` (CLI), defaulting to `fail` for backwards compatibility. The implementation routes all submodule fetch errors through `record_fetch_error()`, forwards the setting to child fetches (including `--all`/`--multiple` and nested recursion), and includes thorough test coverage in `t/t5526-fetch-submodules.sh`. v4 specifically addresses Junio C Hamano’s concern about CLI override propagation, ensuring an explicit `--submodule-errors=fail` is always forwarded to child fetches and not silently reverted to the config default.

The series touches `submodule.c`, `builtin/fetch.c`, documentation files, and the test suite. The commit messages are clear, the rationale is well-explained, and the implementation appears robust. No open questions remain, and the changes are narrowly scoped to the submodule fetch error-handling path. This looks like a mature, well-tested contribution that addresses a genuine user need without introducing broader risks. The series remains under review but is likely to be uncontroversial.
