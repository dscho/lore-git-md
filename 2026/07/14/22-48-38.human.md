This is the fifth patch in Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. It targets the `git last-modified` command (`builtin/last-modified.c`), where three calls to `repo_parse_commit()` previously ignored failures.

The bug is straightforward: when `repo_parse_commit()` fails (e.g., due to a corrupt or missing commit object), the commit’s internal fields (parents, tree, date) remain uninitialized. The command then proceeds with NULL or garbage values, leading to silent misattribution of file modifications. For example, paths changed in ancestors beyond the corrupt commit might be credited to the wrong commit or omitted entirely. The fix adds explicit error checks at all three call sites, skipping unparsable commits to prevent incorrect output.

The patch is mechanical and uncontroversial, following the same pattern as other revision walkers in Git. It introduces no new behavior or on-disk format changes, only hardening the code against silent failures. The commit message clearly explains the consequences of the bug and the rationale for the fix, making it easy to assess. This looks like a solid, low-risk improvement that addresses a real correctness issue.
