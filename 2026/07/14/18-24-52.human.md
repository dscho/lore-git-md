This is the sixth patch in Harald Nordgren’s **v19 `git branch --delete-merged` series**, now implementation-complete and ready for merging. This patch adds a **per-branch opt-out mechanism** via the `branch.<name>.deleteMerged=false` config key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The feature is **well-motivated** for iterative topic-branch workflows: a developer can mark a branch as "keep developing" after an early round is merged upstream, avoiding accidental deletion by `--delete-merged` while retaining the ability to manually prune it later. The implementation is **clean and minimal**, adding only 14 lines of C code and 36 lines of tests. The opt-out check is integrated into the existing `delete_merged_branches()` candidate filtering logic, and the config key is documented in both `branch.adoc` and `git-branch.adoc`.

### Key details

- **Behavior**: When `branch.<name>.deleteMerged=false` is set, `--delete-merged` skips the branch and prints a non-quiet message (e.g., "Skipping 'kept' (branch.kept.deleteMerged is false)"). Explicit deletion via `git branch -d` ignores the opt-out and uses the normal merge check.
- **Safety**: The opt-out is checked *after* other safety mechanisms (e.g., checked-out branches, missing upstreams, push divergence), ensuring it doesn’t override critical protections.
- **Tests**: The patch adds two new tests in `t3200-branch.sh`:
  1. Verifies `--delete-merged` skips a branch with `deleteMerged=false` and prints the skip message.
  2. Confirms `git branch -d` ignores the opt-out and deletes the branch normally.
  Both tests use the `check_branches` helper (introduced in an earlier patch) to verify branch state via `git for-each-ref`, avoiding fragile `rev-parse` checks.
