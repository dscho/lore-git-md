This is patch 2/10 in the v12 series migrating global configuration variables into `struct repo_config_values`. It moves the `excludes_file` global (used for the global ignore file path) into the repository-specific configuration struct and introduces a proper getter, `repo_excludes_file()`, to encapsulate the lazy-loading fallback logic that assigns the XDG default path when the variable is NULL.

The patch is a clean, well-motivated refactoring that preserves existing behavior while centralizing memory management. It updates `git_default_core_config()` to store the configured path in `cfg->excludes_file` instead of the global, extends the `repo_config_values_clear()` destructor to free the field, and replaces direct global access in `setup_standard_excludes()` with the new getter. The getter caches the result of `repo_config_values()` and handles the XDG default path assignment internally, ensuring backward compatibility.

Files touched are `dir.c`, `environment.c`, and `environment.h`. The patch is memory-safe (properly frees the heap-allocated string via `FREE_AND_NULL()`) and CI-clean. It builds directly on the infrastructure introduced in patch 1/10 (`repo_config_values_clear()`) and follows the established pattern from the merged `excludes_file` migration. No user-visible behavior changes are introduced.

This is a solid step in the libification effort, addressing a global variable with clear per-repository semantics. The getter design is sensible, and the patch is ready for integration. Reviewers should note the cached getter call and the destructor’s role in memory management, though these are already settled in the series.
