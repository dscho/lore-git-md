This is the first patch in an 11-patch series addressing unchecked return values flagged by Coverity. It targets the HTTP transport layer in `http.c`, specifically the `get_active_slot()` function, which is a critical entry point for all HTTP-based operations (clone, fetch, push, bundle-uri downloads).

The patch adds a NULL check for the return value of `curl_easy_duphandle()`, which can fail when memory allocation fails internally. Without this check, a NULL `slot->curl` would lead to undefined behavior when passed to `curl_easy_setopt()`, typically resulting in a crash. The fix is minimal and uncontroversial: it simply calls `die()` with a clear error message when the duplication fails, as there is no reasonable recovery path from an out-of-memory condition during HTTP session setup.

The commit message is thorough, explaining the context (Coverity report), the risk (undefined behavior leading to crashes), and the scope (all HTTP operations). The change itself is mechanical and aligns with the series' goal of hardening error paths without introducing new behavior. No test coverage is added, but the existing HTTP test suite should implicitly exercise this code path.

Key technical details for follow-up: the function `get_active_slot()` in `http.c`, the libcurl API `curl_easy_duphandle()`, and the crash risk from passing NULL to `curl_easy_setopt()`. This patch is a clear bugfix with no downsides, and the series as a whole remains uncontroversial.
