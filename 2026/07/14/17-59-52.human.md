This is the first patch in René Scharfe’s five-part series introducing repository-aware variants of the tempfile and lockfile APIs as part of the `the_repository` removal effort. It adds `repo_create_tempfile_mode()` and its convenience wrapper `repo_create_tempfile()`, which take an explicit `struct repository *` parameter instead of implicitly using the global `the_repository`. The implementation is a thin wrapper around the existing `create_tempfile_mode()`; the only functional change is passing the repository parameter through to `adjust_shared_perm()`. The patch is mechanical, well-scoped, and aligns with the ongoing project goal of eliminating global state. No user-visible behavior changes are expected, and the commit message is concise but sufficient. This is a solid, uncontroversial refactoring step that sets the stage for the rest of the series.
