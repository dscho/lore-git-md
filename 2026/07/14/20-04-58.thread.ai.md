Thread identity: RFC proposal for workflow optimizations in large repositories with long-running branches and merge-heavy histories. Originating author: Richard Fine. Thread type: design discussion / feature request.

Core problem or goal: Address two pain points in large repositories with long-running branches and frequent merges: (1) accidental deep fetches when pulling merge commits with ancient second-parent histories, and (2) repository bloat from retaining full branch history when only a linear mainline is typically needed. Proposes two Git enhancements: persistent shallow fetch options (config-driven `--shallow-since` enforcement) and a "fake-linear mainline" mechanism to mask merge commit second parents until explicitly expanded.

Current status: Initial proposal; no prior versions. No decisions or agreements yet. Key technical details:
- **Persistent shallow fetch**: Config key `remote.<name>.shallowsince` to enforce `--shallow-since` for all fetches from a remote, regardless of trigger (CLI, GUI, automation). Subsystems: shallow clones, fetch, config.
- **Fake-linear mainline**: Mechanism to treat merge commits as linear (ignoring second parent) until explicitly expanded, using `.git/shallow` or replace refs. Challenges: `git gc` respecting masked state, incremental fetches, reachability (e.g., `git log --follow`, `git bisect`).
- Files/subsystems: shallow machinery, fetch logic, config, replace refs, partial clones.
- Related efforts: partial clones (`--filter=tree:0`), replace refs, `--filter` options.

Open questions and loose ends:
- Whether the problems are widespread enough to justify new features.
- Alternative approaches (e.g., extending `git clone --filter`, using existing replace refs or partial clone tools).
- Edge cases: interaction with `git fetch --unshallow`, reachability guarantees for `git blame`/`git bisect`, `git gc` behavior, incremental fetch safety.
- Performance vs. correctness tradeoffs, especially for the fake-linear proposal.
- Adoption barriers: user confusion, tooling support, documentation needs.
