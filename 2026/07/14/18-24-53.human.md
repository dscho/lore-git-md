This is the final patch in Harald Nordgren’s seven-part series implementing `git branch --delete-merged`, adding the `--dry-run` option. The patch is small, focused, and directly addresses a usability concern: letting users preview which branches would be deleted before committing to the operation.

The implementation is straightforward. When `--dry-run` is combined with `--delete-merged`, the command prints "Would delete branch <name>" for each branch that meets the deletion criteria, but skips all ref and config modifications. The output matches the real deletion output exactly, so users can trust what they see. The patch also sensibly rejects `--dry-run` unless `--delete-merged` is also specified, and it rejects the nonsensical `--dry-run --quiet` combination.

The code changes are minimal and well-contained: a new `DELETE_BRANCH_DRY_RUN` flag, a conditional block in `delete_branches()` to skip the actual deletion, and a small update to `spare_stacked_bases()` to avoid clearing upstream configs during dry runs. The documentation and tests are clear and cover the expected behavior, including edge cases like stacked branches and the rejection of invalid flag combinations.

This patch is a clean, low-risk addition that rounds out the series. It addresses the last piece of feedback from Phillip Wood (who noted the `--dry-run --quiet` quirk) and fixes a bug in v18 where dry runs incorrectly modified config. The series as a whole is now implementation-complete, thoroughly tested, and ready for merging.
