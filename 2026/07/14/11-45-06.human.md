This is the core implementation patch of a security-hardened feature series that adds `git cat-file --batch-command` support for querying object metadata from remote repositories. This specific patch (10/10 in v17) introduces the client-side logic for the `object-info` capability, completing the series' primary functionality.

The patch implements `fetch_object_info()` in new files `fetch-object-info.c` and `fetch-object-info.h`, providing a dedicated function for querying object metadata (currently just size) from v2 servers without downloading full objects. The implementation follows Git's established patterns: it verifies server support for the `object-info` capability, constructs and sends the request using the same buffer-based approach as `fetch-pack.c`, and parses responses with careful memory management. When servers don't recognize an object, the function sets size pointers to NULL rather than failing, matching the documented v2 protocol behavior.

Key aspects include strict protocol v2 enforcement, capability checks, and integration with the transport layer via a new vtable entry (`fetch_object_info`). The function is implemented for both smart transport and transport-helper backends, ensuring compatibility with all three protocols (`git://`, `file://`, `http://`). Memory safety is addressed through proper cleanup for stateless RPC and the use of `parse_object_size()` for safe size conversion.

This patch directly enables the user-facing `remote-object-info` command introduced elsewhere in the series, which allows batch queries of object metadata from remotes. The implementation is well-structured and maintains separation from existing fetch infrastructure while following Git's extensibility patterns. All technical issues from previous versions have been resolved, and the series appears ready for merging to `next`.
