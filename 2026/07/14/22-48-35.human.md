This is a bugfix patch, the second in an 11-patch series addressing unchecked return values flagged by Coverity. It targets the configuration editor logic in `builtin/config.c`.

The patch fixes a silent failure in `show_editor()`: the function calls `launch_editor()` but ignores its return value, always returning success even when the editor fails to launch. This affects `git config edit` and `git config --edit`, which would previously report success even if the editor could not be started. The fix adds a check and propagates the failure by returning `-1`, which the callers already handle correctly.

The change is minimal and mechanical: a single conditional around `launch_editor()` and a `return -1` on failure. The commit message clearly explains the problem, the affected commands, and the propagation path. This aligns with the rest of Git’s editor-launching code (e.g., `git commit`), which already treats editor failures as errors.

No new behavior or edge cases are introduced; the patch only hardens an existing code path against silent failures. The fix is uncontroversial and well-motivated by the Coverity report. If the series lands, this patch will eliminate a minor but confusing inconsistency in Git’s error handling.
