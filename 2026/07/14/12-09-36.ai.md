This is the **four-level wrapping implementation** in Pablo Sabater’s `git log --graph` indentation series, now at **v12**. The patch modifies the cascading behavior introduced in patch 4/7 to reset indentation after four levels, preventing visual ambiguity in sequences of orphaned roots.

The change is **small and focused**: it adds 22 lines to `graph.c` and 29 lines to the new test file (`t4218-log-graph-indentation.sh`). The core logic is in `graph_update()`, where a new condition checks if the current visual root depth is a multiple of four and the next commit is *not* a visual root. If so, it resets `visual_root_cascade` to force the next commit to indent normally. The indentation calculation in `graph_output_commit_line()` is updated to use modulo arithmetic (`(depth - cascade) % 4 * 2`), ensuring consistent wrapping.

The test covers the edge case where a non-root commit would otherwise align vertically with a wrapped root, verifying that the forced indentation resolves the ambiguity. The commit message explains the rationale for choosing four levels: it balances clarity (avoiding "pyramid" effects) with compactness. This design was finalized after discussion in earlier iterations, where Mirko Faina endorsed the four-level wrap as superior to the original two-level proposal.

The patch is **stable and uncontroversial**; it has not changed since v7 and addresses all prior feedback about symmetry-induced ambiguity. It relies on the lookahead buffer (patch 3/7) and visual root detection logic (patch 4/7) but does not introduce new dependencies. The implementation is **low-risk**, with clear invariants enforced by the modulo operation and explicit checks for non-root commits. The test coverage is thorough, including a ten-commit sequence of orphaned roots to verify the wrap behavior.
