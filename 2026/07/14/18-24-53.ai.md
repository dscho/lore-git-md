This is the final patch in Harald Nordgren’s `git branch --delete-merged` series, adding `--dry-run` support to the new command. The patch introduces a `DELETE_BRANCH_DRY_RUN` flag to the deletion API, ensuring the command prints which branches would be deleted without modifying refs or config. The implementation is careful to avoid side effects during dry runs, including skipping config updates (e.g., clearing upstreams for spared branches) and ref deletions. The flag is rejected unless combined with `--delete-merged`, and the nonsensical `--dry-run --quiet` combination is implicitly prevented by the existing quiet-handling logic.

The patch updates `builtin/branch.c` to pass the `DELETE_BRANCH_DRY_RUN` flag through the call chain, modifies `spare_stacked_bases()` to skip config updates during dry runs, and extends `delete_branches()` to print "Would delete" messages instead of performing deletions. Documentation in `git-branch.adoc` explains the new option, and the test suite (`t/t3200-branch.sh`) verifies dry-run output matches real deletion output, including stacked-branch protection behavior and edge cases like missing `--delete-merged`.
