This is the final patch in the v17 series, completing the dynamic capability-based placeholder validation system for the `remote-object-info` command in `git cat-file --batch-command`. The patch replaces the static allow-list (which only permitted "objectname" and "objectsize") with a fully dynamic system that maps server-advertised capabilities to format atoms at runtime.

The implementation introduces a `remote_atom_map` that connects protocol options (e.g., "size") to format atoms (e.g., "objectsize"), and populates `remote_allowed_atoms` based on what the server actually supports. This ensures clients only request metadata the server can provide, addressing the segfault and `die()` issues identified in earlier versions while maintaining forward compatibility. The patch also moves `object_info_options` out of `get_remote_info()` so callers can specify which metadata they want, and ensures empty output lines when all placeholders are unsupported (matching `for-each-ref` behavior).

Key changes include:
- A new `remote_atom_map` struct mapping protocol options to format atoms
- Backward iteration when filtering capabilities to avoid element-skipping
- Support for "type" in `object_info_options` (preparing for future server support)
- Proper cleanup of `remote_allowed_atoms` in `batch_objects()`
- Empty-string behavior for unsupported placeholders (consistent with Git patterns)

The patch is purely mechanical and preparatory for future extensibility, with no behavior changes for the current "size" capability. It directly addresses the critical safety issues raised in the thread while maintaining the series' security-focused design.
