This is a well-crafted feature series that makes submodule fetch errors configurable. The author, Paulius Zaleckas, has addressed feedback from Junio C Hamano and others across four iterations, refining both the technical implementation and the user-facing controls.

The core problem is familiar to anyone working with submodules: when `git fetch --recurse-submodules` encounters a submodule whose gitlink points to an unreachable OID, Git currently fails hard. This is disruptive in workflows where upstream topic branches are still in flux—even if the local branch doesn’t depend on the missing commit, the entire fetch aborts. The series introduces `fetch.submoduleErrors` (config) and `--submodule-errors=(fail|warn)` (CLI) to let users opt into non-fatal behavior, with the default remaining `fail` for full backwards compatibility.

Patch 1 fixes a pre-existing logic flaw in `submodule.c` where phase-1 fetch failures were recorded immediately, before the phase-2 OID-based retry could run. This was marked as NEEDSWORK in the code, and the fix ensures errors are only recorded if the phase-2 retry also fails or if no retry is scheduled. The change is surgical and preserves the existing fatal behavior while making the code ready for the configurable error policy in Patch 2.

Patch 2 adds the user-facing controls and wiring. It routes all submodule fetch errors through `record_fetch_error()` so they honor the new warn mode, forwards the setting to child fetches (so it works with `--all`/`--multiple` and nested recursion), and adds comprehensive tests covering the new modes, error reporting, and edge cases. The v4 update specifically addresses Junio’s concern about CLI override propagation: an explicit `--submodule-errors=fail` is now always forwarded to child fetches, preventing silent reversion to the config default.

The series touches `submodule.c`, `builtin/fetch.c`, the fetch config and options documentation, and the test suite (`t/t5526-fetch-submodules.sh`). The commit messages are clear and the test coverage looks thorough. No major objections remain, and the implementation appears solid. This is a practical improvement for users who work with submodules in active upstream repositories.
