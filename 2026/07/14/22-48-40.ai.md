This is the seventh patch in Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. It targets the transport-helper subsystem, specifically the `get_exporter()` function in `transport-helper.c`.

The patch adds a check for the return value of `dup(helper->in)`, which duplicates the helper’s input file descriptor for use by the `fast-export` child process. Previously, if `dup()` failed (e.g., due to file descriptor exhaustion), it would return `-1`, which the `child_process` machinery interprets as a request to create a new pipe for stdout. This would silently redirect the `fast-export` output to an unread pipe, breaking the data flow between the helper and the exporter. The fix propagates the error upward with `error_errno()` if `dup()` fails, preventing the silent miswiring.

The change is mechanical and uncontroversial, aligning with the series’ goal of hardening code paths against silent failures. The commit message clearly explains the risk (silent redirection of output) and the fix (explicit error handling). No new symbols or behavior changes are introduced; the patch only adds a guard against an edge case that could otherwise lead to data loss or corruption in transport operations. The transport-helper subsystem is involved in remote operations, so this fix is relevant to users of `git push` or `git fetch` with custom helpers.
