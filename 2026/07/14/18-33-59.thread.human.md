The thread is about optimizing the performance of `git last-modified`, a command Toon Claes introduced to show when files were last modified. The command was found to be 2.5× slower than a hand-rolled `git log` pipeline when querying a single directory in the ziglang/zig repository, despite both using commit-graph and changed-path Bloom filters. Jeff King (Peff) identified the bottleneck: `last-modified` was checking every path in the target directory against every commit’s Bloom filter, while `git log` used a single Bloom filter key derived from the pathspec. Peff posted a proof-of-concept patch that reused Bloom filter logic from `revision.c`, cutting runtime from 64 ms to 16 ms.

Toon has now confirmed the performance gap and expanded benchmarking to GitLab’s repositories. On `gitlab-org/gitlab`, the patch speeds up queries for the `app/` directory by 1.56×, and on `gitlab-org/gitaly`, it improves performance for `internal/` by 1.33×, with no regressions observed. He agrees with Peff’s analysis and plans to adopt the cleaner refactoring, committing to coordinate on a unified patch series. The only remaining open questions are whether the patch handles non-literal pathspecs (deferred as out of scope) and whether GitHub’s internal `blame-tree` implementation already solved this problem. The patch is not yet queued but is likely to land smoothly, given the demonstrated speedups and coordination between Toon and Peff.
