This thread is a performance inquiry about the `git last-modified` command, introduced by Toon Claes. Gusted, a Forgejo contributor, reports that `git last-modified -z -t --max-depth=0` is consistently about 2.5 times slower (66 ms vs. 26 ms) than a hand-rolled `git log` pipeline when run against the ziglang/zig repository, even with a precomputed commit-graph and changed-path Bloom filters. The test filters commits by a specific path (`doc/langref/`), and both commands are given the same inputs.

At this stage, the thread is just getting started—no responses or optimizations have been proposed yet. The question is whether the performance gap is expected, if there’s a more efficient way to invoke `git last-modified`, or if the command itself could be improved. Key participants so far are Gusted (the reporter) and Toon Claes (the command’s author), though no replies have been posted yet. The discussion may reveal whether this is a known limitation or an opportunity for optimization.
