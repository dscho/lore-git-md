This is the core patch in Harald Nordgren’s **`git branch --delete-merged`** series, now in its final v19 iteration and ready for merging. The patch adds the new `--delete-merged <branch>` subcommand to `git branch`, enabling safe, automated cleanup of local branches whose work has already landed upstream.

The command deletes local branches whose tip is reachable from their upstream (matching one of the `--delete-merged` arguments) and whose push destination differs from their upstream. It supports **repeatable upstream arguments** (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the match, and **optional positional patterns** (e.g., `topic-*`) to limit deletion scope. Safety is enforced through multiple checks: skipped branches include those checked out in any worktree, those with missing upstreams, those that push to their upstream (e.g., `main` tracking `origin/main`), and those opted out via `branch.<name>.deleteMerged=false`.

The most technically interesting part is the **refined stacked-branch protection** (abort-and-clear): if a branch is used as an upstream for an unmerged branch, it is spared, but if that spared branch’s own upstream is being deleted, its now-stale upstream config is cleared. This avoids breaking dependency chains while cleaning up stale configs. The implementation uses `strset` to track deletable and spared branches, and `refs_for_each_branch_ref()` to traverse the ref graph.

The patch is **well-tested**, with comprehensive integration tests covering all safety checks, edge cases (self-referential upstreams, missing upstreams), and the new repeatable upstream selector behavior. The documentation is clear and complete, explaining both the command’s purpose and its safety guarantees.

This is a **feature patch** that addresses a real workflow pain point (safe branch cleanup) with a thoughtful design and thorough implementation. The series has been reviewed by Phillip Wood and Junio C Hamano, with all design questions resolved and mechanical issues fixed in v19. The only follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which Harald has agreed to implement after the series lands.
