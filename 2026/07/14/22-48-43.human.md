This is a bugfix patch, part of Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. It is the tenth patch in the series (10/11).

The patch plugs a silent failure path in the bisect subsystem. Six call sites of `get_terms()` in `builtin/bisect.c` previously ignored its return value; when the `BISECT_TERMS` file is missing or truncated, `get_terms()` fails but the bisect commands (`next`, `skip`, `visualize`, `run`, and the legacy `bad`/`good` paths) would proceed with NULL or empty term strings. This produces confusing downstream behavior: commands try to use refs like `refs/bisect/` with no suffix, leading to misleading error messages. The fix adds a simple check at each call site: if either `term_bad` or `term_good` is still NULL after `get_terms()`, the command exits with a clear “no terms defined” error, matching the existing pattern in `bisect_terms()`.

The change is mechanical and uncontroversial. It touches only `builtin/bisect.c`, adding 12 lines of error-checking code. No new behavior is introduced; the patch merely surfaces an existing failure condition that was previously masked. The commit message is concise and explains both the problem and the rationale for checking the term pointers rather than the return value (some callers set default terms before calling `get_terms()`, so the pointers may be non-NULL even if `get_terms()` fails). The patch is well-motivated and looks ready for review.
