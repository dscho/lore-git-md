This is a performance inquiry about the `git last-modified` command, authored by Toon Claes and now being evaluated by a Forgejo contributor.

Gusted reports that `git last-modified` (a relatively new built-in command) is about 2.5× slower than a hand-rolled `git log --name-status` pipeline when retrieving the last commit that touched each file in a subdirectory. The test repository is the Zig project (≈ 100 k commits, 15 k files), and both commands are run with commit-graph bloom filters enabled. The benchmark shows 66 ms for `last-modified` vs 26 ms for the `log`-based approach.

The email is not a patch or a bug report; it is a request for insight. Gusted is asking whether the performance gap is expected, whether there is a more efficient invocation they are missing, or whether the command itself could be optimized. No code changes are proposed yet, so there is nothing to review or merge. The thread is open-ended and may lead to either documentation updates, command-line guidance, or future performance patches.
