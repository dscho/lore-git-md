This is the second patch in Paulius Zaleckas’s v4 series introducing configurable submodule fetch errors. It adds the user-facing controls (`fetch.submoduleErrors` config and `--submodule-errors` CLI option) and wires them into the fetch machinery so that submodule fetch failures can be reported as warnings instead of hard errors.

The patch is narrowly scoped to the submodule fetch error-handling path. It preserves backwards compatibility by defaulting to `fail`, but users can now set `fetch.submoduleErrors=warn` or pass `--submodule-errors=warn` to allow fetches to complete even when a submodule’s gitlink points to an unreachable commit. The resolved value is always forwarded to child fetches (`--all`, `--multiple`, nested recursion) whenever it was set explicitly, ensuring the user’s intent is preserved across process boundaries.

The implementation touches `builtin/fetch.c` (config parsing, CLI option, forwarding logic), `submodule.c` (error routing and propagation), documentation, and adds thorough test coverage in `t/t5526-fetch-submodules.sh`.
