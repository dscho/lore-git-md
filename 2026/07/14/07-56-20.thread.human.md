This thread is a bug report from Uwe Kleine-König about a regression in `git log --cherry-mark --right-only`. When a merge commit is included in the revision range, Git fails to mark a commit as equivalent (`=`) even though the same commit is correctly identified when the range excludes the merge. The example uses a Linux kernel tree and shows that commit `ca270a534d0f` appears unmarked (`*`) in the broader log but marked as equivalent (`=`) in the narrower one, suggesting the merge commit disrupts the cherry-mark logic.

Uwe provides clear reproduction steps using Git 2.55.0 with Phillip Wood’s recent series that fixed a prior bug in the same area. The report is well-documented and appears to isolate a real issue in the revision-walking logic that compares commits across branches. No patch is attached—this is purely a bug report—but Uwe has offered to share a bundle of the relevant commits privately if needed. So far, there are no replies or proposed fixes from other contributors.
