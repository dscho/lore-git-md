This is the second patch in Pablo Sabater’s **v12 series** implementing visual root indentation for `git log --graph`. It introduces a **helper function `next_commit_to_show()`** in `revision.c` to unify how `get_revision()` retrieves commits, whether from the normal revision walk or from the saved list used by `--max-count-oldest`.

The patch is **purely preparatory** and makes no behavior changes. It extracts the existing logic for choosing the commit source into a standalone function, which the next patch (3/7) will use to populate the lookahead buffer. The `--reverse` branch is explicitly excluded to avoid unintended side effects (setting `SHOWN`/`CHILD_SHOWN` flags). The implementation is **mechanically straightforward**, moving 12 lines of code into a new helper and replacing the original logic with a single call to it.

This patch has been **stable since v7** and is **ready for final review**. It is a **prerequisite for the lookahead buffer** (patch 3/7), which Junio Hamano has already approved in principle. The only interaction with other subsystems is the coupling to `get_revision_internal()` and the `--max-count-oldest` logic, both of which remain unchanged. No new edge cases or dependencies are introduced.

The commit message clearly explains the motivation (pre-fetching commits for lookahead) and the exclusion of `--reverse`. The diff is minimal and focused, touching only `revision.c`. This patch is **low-risk** and **uncontroversial**, serving solely as infrastructure for the core feature.
