This is a documentation cleanup patch for `git fast-export`. The patch aligns the command’s help text (`git fast-export -h`) with its man-page synopsis and with Git’s standard convention for describing revision arguments. Previously, the help text used `[<rev-list-opts>]` while the man page showed an unusual format with a pipe (`| 'git fast-import'`). Both now use `[<options>] [<revision-range>] [[--] <path>...]`, matching the pattern used by commands like `git log` and `git rev-list`.

The change is purely textual and does not affect the command’s behavior. It touches the man page (`Documentation/git-fast-export.adoc`), the usage string in `builtin/fast-export.c`, and removes `fast-export` from the list of commands that trigger a test failure in `t/t0450/adoc-help-mismatches`. The patch was already queued in Junio’s `seen` branch on June 12, 2025, and this email is a review acknowledgment from Patrick Steinhardt, who agrees the change improves consistency.

This is a small but well-motivated cleanup that resolves a long-standing inconsistency. The patch is uncontroversial and ready for merging. If you care about command-line help consistency, this is worth noting but not urgent.
