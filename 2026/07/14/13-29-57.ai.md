This is the second patch in a two-patch series (v4) introducing configurable submodule fetch error handling. It adds the user-facing controls—`fetch.submoduleErrors` (config) and `--submodule-errors=(fail|warn)` (CLI)—that let users choose whether submodule fetch errors should abort the parent fetch (`fail`, the default) or merely warn (`warn`). The patch also ensures the resolved setting (whether from CLI or config) is forwarded to all child fetches (`--all`, `--multiple`, nested recursion) so that the user’s intent is preserved across per-remote processes.

The implementation touches `builtin/fetch.c` (config parsing, CLI option, forwarding logic), `submodule.c`/`submodule.h` (passing the setting to the submodule fetch machinery), and documentation. Test coverage in `t/t5526-fetch-submodules.sh` verifies the new behavior, CLI override propagation, and edge cases like inaccessible submodules. The commit message and code are clear, and the patch addresses Junio C Hamano’s earlier concern about CLI override propagation by ensuring explicit `--submodule-errors=fail` is always forwarded, even when the config default is `warn`. This is a mature, well-tested feature addition with no open questions.
