This is the second patch in Pablo Sabater’s **v12 series** introducing visual root indentation for `git log --graph`. The patch is a **refactoring** that extracts the logic for determining the next commit to show into a new helper function, `next_commit_to_show()`, in `revision.c`. This change is **purely preparatory** and has no user-visible behavior change.

The helper unifies two existing code paths: the normal revision walk (via `get_revision_internal()`) and the staged output mode introduced by `--max-count-oldest` (which pops commits from `revs->commits`). The motivation is to enable the **lookahead buffer** in patch 3/7, which needs to pre-fetch commits from the same source as `get_revision()`. The `--reverse` branch is explicitly excluded to avoid unintended side effects, preserving its existing behavior.

The patch is **mechanically straightforward**, moving 12 lines of logic into a new 24-line helper and replacing the original code with a single call to `next_commit_to_show()`. It has been **stable since v7** and is **ready for final review**. Junio Hamano and Kristofer Karlsson have already approved the architectural approach, and the implementation faithfully mirrors the design discussed in earlier iterations. No further changes are expected.
