This is a security-focused patch from the final iteration (v17) of Pablo Sabater's GSoC series adding `remote-object-info` support to `git cat-file --batch-command`. This specific patch implements critical safety improvements by replacing the previous `strstr()`-based placeholder validation with a strict allow-list mechanism for remote object queries.

The patch addresses two serious issues in the existing code: first, it prevents segfaults when `data->type` contains garbage for atoms recognized by `expand_atom()` but not supported by the remote; second, it stops the command from dying when encountering unknown placeholders, which would block local queries sharing the same format. The solution adds an explicit list of supported remote atoms (`objectname` and `objectsize`) and modifies `expand_atom()` to return empty strings for unsupported placeholders in remote mode, matching how `for-each-ref` handles inapplicable atoms.

Key safety improvements include initializing `data->type` to `OBJ_BAD` and adding a NULL check for `type_name()` to prevent segfaults from uninitialized data. The patch also updates documentation to clarify that unsupported placeholders now return empty strings rather than raising errors, and modifies tests to expect this new behavior. The implementation is careful to maintain backward compatibility while closing security gaps - particularly important since this feature allows querying remote repositories where malicious servers could potentially exploit validation weaknesses.
