This is patch 3/10 in the v12 series migrating global configuration variables into `struct repo_config_values`. It moves the `editor_program` global into the repository-scoped configuration structure as part of the ongoing libification effort.

The patch is a straightforward refactoring: it removes the global `char *editor_program` declaration, adds the field to `struct repo_config_values`, updates the initializer and destructor to manage the new field, and adjusts the single caller (`git_editor()` in `editor.c`) to access the value via `repo_config_values(the_repository)->editor_program`. Memory management is handled via `FREE_AND_NULL()` in both the config parser and the destructor, ensuring no leaks.

The commit message explains the rationale for migrating program paths: while per-repo editor configuration may seem unnecessary for short-lived processes, it becomes important in long-running processes managing multiple repositories, and it eliminates mutable global state. No getter function is introduced; callers access the field directly through `repo_config_values()`, which is consistent with the pattern established in earlier patches.

This patch is technically complete, addresses all prior feedback, and is ready for integration. It touches only three files (`editor.c`, `environment.c`, `environment.h`) and makes no user-visible behavior changes. The series as a whole is now CI-clean and memory-leak-free, with this patch representing one of the simpler migrations in the set. Reviewers should note the direct field access pattern and the destructor’s role in memory cleanup.
