This is the first patch in a refactoring series (v12, 10 patches) that continues the ongoing `the_repository` removal effort. It introduces `repo_config_values_clear()`, a destructor for `struct repo_config_values`, to centralize memory management for heap-allocated configuration variables. The function is called from `repo_clear()` and currently handles freeing the `attributes_file` field.

The patch is small and focused, adding the destructor declaration in `environment.h`, its implementation in `environment.c`, and the call site in `repository.c`. The commit message explains the motivation clearly: preventing memory leaks as global configuration variables are migrated into `struct repo_config_values`. The design choice to pass a `struct repo_config_values*` (rather than operating on `the_repository`) is deliberate, enabling future submodule support and avoiding initialization-order crashes.

This is a foundational change for the rest of the series, which migrates eleven more variables into `repo_config_values`. The patch itself is uncontroversial and well-motivated, with no behavioral changes or user-visible impact. Reviewers should note the destructor’s signature and its placement in the repository teardown sequence, as these details were previously debated in the thread. The series as a whole is ready for `next`, and this patch sets the stage for the memory management patterns used in the subsequent migrations.
