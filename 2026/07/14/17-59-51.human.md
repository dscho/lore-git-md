This is a refactoring series from René Scharfe, part of the ongoing `the_repository` removal effort. The goal is to stop having the tempfile and lockfile APIs implicitly use the global `the_repository` variable, making them work explicitly with any `struct repository *` instead.

The series starts by introducing new repository-aware versions of the tempfile creation functions (`repo_create_tempfile` and `repo_create_tempfile_mode`), then migrates the packed-refs backend to use them. It follows up by adding similar repository-aware variants for the lockfile API (`repo_hold_lock_file_for_update` and friends), then removes the implicit `the_repository` dependency from the original tempfile functions. The final patch is a cleanup that converts existing lockfile users that already work with non-default repositories to the new explicit API.

The patch touches 21 files across multiple subsystems (refs, midx, commit-graph, apply, etc.), but the changes are mechanical and localized. Each patch is small and focused, making the series easy to review incrementally. The commit messages are clear and the rationale is well-explained: this is a necessary step toward eliminating the global repository variable, which has been a long-standing goal.

Given René’s track record with this kind of cleanup work, the series looks solid and uncontroversial. It’s the kind of incremental improvement that the project routinely accepts once it passes review.
