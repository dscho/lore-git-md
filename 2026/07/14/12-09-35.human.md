This is the **core visualization patch** in Pablo Sabater’s **v12 series** implementing **visual root indentation for `git log --graph`**. It is the fourth of seven patches and introduces the actual indentation logic that makes the feature work.

The patch addresses a long-standing readability issue in `git log --graph`: when commits have excluded parents (due to filtering, `--first-parent`, or being actual roots), they can appear vertically adjacent to unrelated commits, creating false visual connections. The solution is to **indent visual roots** (except the first in a sequence) while preserving parent-child relationships. This is done by adding a new `is_visual_root` flag to `struct git_graph`, a `GRAPH_PRE_ROOT` state to connect indented roots to their children, and logic to **cascade indentation** for adjacent visual roots (with the last root in a sequence left unindented to avoid ambiguity).

Key implementation details:
- **Visual root detection** happens in `graph_is_visual_root()`, which checks if the current commit is a candidate (no visible parents, not a boundary) and not a non-first merge parent (to avoid double-connecting edges).
- **Indentation depth** is tracked in `visual_root_depth` and applied in `graph_output_commit_line()` using `(depth - cascade) * 2`, where `cascade` omits indentation for the first root in a sequence.
- **Merge parents** are explicitly excluded from indentation via a new `is_merge_parent` flag in `struct column`, ensuring they remain visually connected to the merge commit.
- The **`GRAPH_PRE_ROOT` state** prints an extra row to connect indented roots to their children, similar to `GRAPH_PRE_COMMIT` for octopus merges.
- **Test coverage** is extensive: the new `t4218-log-graph-indentation.sh` file (514 lines) verifies edge cases like single roots, cascading roots, merge parents, boundary commits, and filtering options (`--first-parent`, `--left-right`, `--max-count`, `--grep`/`--author`).

The patch is **well-crafted and thoroughly tested**, with clear commit message explanations and no functional changes from v11. It depends on the **lookahead buffer** (patch 3/7) and **unified helper function** (patch 2/7), both of which are stable and uncontroversial. The only remaining open question is Junio’s concern about **test brittleness** (exact output matching), but this is a general issue with graph tests and not specific to this patch.

This is a **user-visible feature** that directly improves `git log --graph` usability, and the implementation is ready for final review. If you care about graph readability, this patch is worth your attention.
