This is a user feedback email on the `git history squash` feature, now in its eighth iteration. Matt Hunter raises a usability edge case: when `--reedit-message` is omitted, the command ignores any `amend!` message in the range that targets the first folded commit, even though the command is already aware of `fixup!`, `squash!`, and `amend!` semantics (e.g., it rejects ranges with dangling fixup targets). He suggests it would feel more consistent if the default behavior incorporated such an `amend!` message into the squashed commit’s message, rather than strictly preserving the first commit’s message.

The observation is thoughtful but narrow: it targets only the default message-handling behavior, not the core functionality. Matt acknowledges the trade-off and does not insist on a change, framing it as a question of consistency rather than a bug. His praise for the “fixup consolidation” feature (how the command folds multiple fixups for the same commit) suggests he finds the overall design useful and well-executed. The email is unlikely to derail the series, but it may prompt a brief discussion about whether the default should be tweaked before the feature lands.
