This thread is a patch series from Johannes Schindelin addressing 11 instances where Git code ignores return values from functions that can fail, as flagged by Coverity static analysis. The goal is to harden these code paths against silent failures without changing behavior or on-disk formats. The series is currently under review, with no prior versions or maintainer decision yet.

Junio C Hamano has raised two substantive correctness concerns that must be addressed before the series can proceed: one in the fifth patch (`builtin/last-modified.c`) regarding resource cleanup in `last_modified_run()`, and another in the ninth patch (`bisect.c`) about a resource leak in `get_terms()`. Patrick Steinhardt has reviewed several patches, confirming the correctness of the second (`builtin/config.c`) and seventh (`transport-helper.c`) patches, and raising a design question about the tenth patch (`builtin/bisect.c`)—whether `get_terms()` should itself return an error if either term is `NULL` to centralize error handling. In the latest email, Steinhardt suggests a minor extension to the eleventh patch (`bisect.c`) to also check the return value of `dup2()`, which would further tighten error handling in the same code path. This suggestion is a reasonable nit and is likely to be incorporated in a future revision.

The series touches multiple files, including `http.c`, `builtin/config.c`, `reftable/block.c`, `transport-helper.c`, and `bisect.c`, adding error checks to functions like `curl_easy_duphandle`, `deflateInit`, `repo_parse_commit`, and `dup`. No new symbols or on-disk format changes are introduced, and test coverage remains unchanged. The open questions revolve around the two correctness issues raised by Junio and the design question from Patrick, with the latter depending on whether any callers legitimately accept `NULL` terms. The author has not yet responded to these points.
