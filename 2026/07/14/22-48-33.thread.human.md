This thread is a patch series from Johannes Schindelin addressing 11 instances where Git code ignores return values from functions that can fail, as flagged by Coverity static analysis. The goal is to harden these code paths against silent failures without changing behavior or on-disk formats. The series is currently under review, with no prior versions or maintainer decision yet.

Junio C Hamano has raised substantive correctness concerns in two patches: the fifth (resource cleanup in `builtin/last-modified.c`) and the ninth (a resource leak in `bisect.c`). Patrick Steinhardt has reviewed the second patch (`builtin/config.c`) and confirmed its approach, and now also reviewed the seventh patch (`transport-helper.c`), confirming its correctness. This seventh patch adds a missing error check for `dup(helper->in)` in `get_exporter()`, ensuring that a failed `dup()` propagates an error rather than silently breaking data flow between the helper and exporter. The fix is uncontroversial and integrates cleanly with existing error handling.

The series touches multiple subsystems, including HTTP, config, reftable, transport helpers, and bisect, with no new symbols or behavior changes—only fatal error paths or propagation to callers. While the broader series still has open questions (the two correctness issues Junio raised), this seventh patch is ready for integration. The thread remains focused on addressing Coverity findings, with no design objections or alternative proposals so far.
