This thread is a straightforward patch series from Johannes Schindelin addressing 11 instances where Git code ignores return values from functions that can fail, as flagged by Coverity static analysis. The goal is to harden these code paths against silent failures without changing behavior or on-disk formats.

So far, the series has seen no substantive review, but the patches are mechanical and uncontroversial. The latest email covers the seventh patch, which fixes an unchecked `dup()` call in the transport-helper subsystem. Without the fix, a `dup()` failure (e.g., due to file descriptor exhaustion) could silently redirect `fast-export` output to an unread pipe, breaking data flow between the helper and exporter. The fix propagates the error upward, preventing silent miswiring during remote operations like `git push` or `git fetch`.

The series touches several files, including `http.c`, `builtin/config.c`, `reftable/block.c`, and `transport-helper.c`, adding error checks to functions like `curl_easy_duphandle()`, `deflateInit()`, `repo_parse_commit()`, and `lseek()`. No new symbols or behavior changes are introduced—just fatal error paths or propagation to callers. The patches are exercised by existing test suites, and the reftable-related changes include unit tests. No open questions or objections have been raised yet.
