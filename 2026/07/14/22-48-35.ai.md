This is the second patch in Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. It targets the `show_editor()` function in `builtin/config.c`, which previously ignored the return value of `launch_editor()` and always returned success. The fix propagates the failure upward by returning `-1` when the editor fails to launch, ensuring that `git config edit` and `git config --edit` now exit with an error rather than silently succeeding. The change is minimal and mechanical, touching only the error-handling path without altering any existing behavior or on-disk formats. The patch is uncontroversial and aligns with how other Git commands (e.g., `git commit`, `git rebase --edit-todo`) already handle editor failures. No new symbols or test coverage are introduced, but the existing config test suite will implicitly exercise the new error path. The commit message clearly identifies the issue, the affected callers, and the Coverity origin.
