Ben Knoble has now reproduced a plausible cause: when `git merge --autostash` (or the `merge.autostash` config) is used, staged changes can be silently unstaged during the merge, leaving the working tree intact but the index cleared. His test script confirms this behavior across Git versions 2.53.0 and 2.55.0-rc0. The reproduction is narrow—it only covers staged changes on an existing file, not new files or untracked content—but it suggests that Kishore’s issue may stem from an autostash-enabled merge rather than repository corruption or a more destructive operation like `git reset --hard`. The thread is still waiting for Kishore to confirm whether this matches their scenario or if other factors (e.g., new files, branch deletion) were involved. No patches or maintainer decisions have been made; the focus remains on diagnosing the root cause.
