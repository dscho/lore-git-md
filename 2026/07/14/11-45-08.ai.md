This is a security-focused refactoring patch in the `remote-object-info` series (GSoC v17, 12/13). The patch addresses critical safety issues in format placeholder handling for remote object queries by replacing the previous `strstr()`-based validation with a strict allow-list approach.

The patch fixes two concrete problems: (1) uninitialized `data->type` values causing segfaults when remote servers return incomplete metadata, and (2) the `strbuf_expand_bad_format()` die() behavior blocking local queries when shared formats contain unsupported placeholders. The solution introduces a static `remote_object_info_atoms[]` array listing only "objectname" and "objectsize" as supported placeholders, with remote mode now returning empty strings for unsupported atoms (matching `for-each-ref`'s behavior for inapplicable atoms).

Key changes include:
- Initializing `data->type` to `OBJ_BAD` and adding NULL checks for `type_name()`
- Adding an `is_remote` flag to `struct expand_data` to distinguish remote vs local queries
- Implementing allow-list validation in `expand_atom()` that skips unsupported atoms in remote mode
- Updating documentation to clarify that unsupported placeholders return empty strings rather than errors
- Modifying tests to expect empty strings instead of die() behavior for unsupported placeholders

The patch maintains backward compatibility while significantly improving safety - remote queries now gracefully handle unsupported placeholders rather than crashing or blocking local operations. This is a substantive security improvement that directly addresses the segfault and die() issues identified in the thread context.
