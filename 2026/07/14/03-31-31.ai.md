This is a **substantive architectural follow-up** to the recently merged commit-graph regression fix. Taylor Blau responds to Patrick Steinhardt’s exploration of whether commit graphs belong at the object database (ODB) level or as a backend-specific property. Taylor agrees with Patrick’s skepticism about treating commit graphs as a universal ODB property—particularly for distributed or alternative backends—but carves out an exception for generation numbers, which he argues are a fundamental commit attribute independent of storage format. He suggests that while optimizations like MIDX or reachability bitmaps are tied to specific object-store representations, generation numbers (and by extension, the commit-graph’s topological levels) have value even in non-filesystem backends. The discussion remains exploratory and non-blocking; no immediate code changes are proposed, but it clarifies the conceptual boundary between commit-graph internals and the ODB abstraction effort.

Key technical details for future reference:
- **Subsystems**: commit-graph, ODB abstraction.
- **Symbols**: `topo_levels` slab, `struct object_database`, generation numbers.
- **Architectural context**: the distinction between commit-graph optimizations (row-oriented layout) and fundamental commit attributes (generation numbers).
- **Related efforts**: pluggable ODB refactoring, MIDX, reachability bitmaps.
- **Open question**: whether generation numbers should be exposed as a standalone API or remain coupled to the commit-graph format. Taylor’s framing implies the former, but no concrete design is proposed.
