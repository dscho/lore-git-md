Subject: [PATCH 0/11] Coverity: unchecked return values
Series version: v1 (initial posting, now with five fixups: fifth patch for `last_modified_run()` cleanup, ninth patch for `get_terms()` resource leak, a second fixup for the fifth patch, the fourth fixup for the ninth patch’s leak, and this fifth fixup for the tenth patch’s error handling centralization)
Originating author: Johannes Schindelin via GitGitGadget
Thread type: patch series

Core problem or goal
Coverity static analysis identified 11 instances where Git code ignores return values from functions that can fail (e.g., `curl_easy_duphandle`, `deflateInit`, `repo_parse_commit`, `lseek`, `dup`, `strbuf_getline_lf`, `launch_editor`, `reftable_table_init_ref_iterator`, and `rename`). The series adds missing error checks to harden these code paths against silent failures, without introducing new behavior or changing on-disk formats.

Current status
Under review; no prior versions. No maintainer decision yet; no integration branch assigned. Junio C Hamano has raised and now resolved four substantive correctness concerns via fixup patches:
- Fifth patch (`builtin/last-modified.c`): ensures proper cleanup of the `active_paths` slab when skipping unparsable commits in the `--not` queue. The original patch used `continue`, which bypassed cleanup; the first fixup replaced it with `goto cleanup`, and the second fixup further refines the error path to ensure the slab is released even when the commit is unparsable.
- Ninth patch (`bisect.c`): fixes a resource leak in `get_terms()` where `terms->term_bad` was not freed if the second `strbuf_getline_lf()` fails. The first fixup for this patch (the fourth overall) adds `FREE_AND_NULL(terms->term_bad)` before the `goto finish` in the error path, ensuring proper cleanup.
- Tenth patch (`builtin/bisect.c`): centralizes error handling in `get_terms()` itself, so that the function now returns an error if either `term_bad` or `term_good` is `NULL`, deduplicating error messages at the call sites and simplifying the callers. This change aligns with the existing pattern in `bisect_terms()` and uses the same translated error message. The fifth fixup patch implements this approach, resolving Patrick Steinhardt’s design question.
Patrick Steinhardt has reviewed the second (`builtin/config.c`) and seventh (`transport-helper.c`) patches and confirmed their correctness. The eleventh patch’s design question (whether to also check the return value of `dup2(temporary_stdout_fd, 1)`) remains open, but Johannes Schindelin has not yet responded.

Key technical details
Files touched: `http.c`, `builtin/config.c`, `reftable/block.c`, `t/unit-tests/t-reftable-block.c`, `builtin/last-modified.c`, `compat/pread.c`, `transport-helper.c`, `bisect.c`, `builtin/bisect.c`, `t/unit-tests/u-reftable-table.c`.
New symbols: none.
Behavior changes: none; only fatal error paths (`die()`) or propagation to caller added, except in `transport-helper.c` where a non-fatal `warning_errno()` is now emitted for a failed `rename()`. Specific fixes:
- `http.c`: `get_active_slot()` now checks `curl_easy_duphandle()` return value for NULL, calling `die()` on failure to prevent undefined behavior in `curl_easy_setopt()`.
- `builtin/config.c`: `show_editor()` now propagates `launch_editor()` failure upward by returning `-1`, ensuring `git config edit` and `git config --edit` exit with an error rather than silently succeeding. Patrick Steinhardt reviewed this patch and confirmed the approach is correct, as `launch_editor()` already emits its own error messages.
- `reftable/block.c`: `block_writer_init()` now checks `deflateInit()` return value and propagates failures via `REFTABLE_ZLIB_ERROR`, preventing silent data corruption or crashes when `deflate()` is later called with an uninitialized `z_stream`.
- `compat/pread.c`: `git_pread()` now checks the return value of the first `lseek(fd, 0, SEEK_CUR)` call; if it fails (e.g., on a non-seekable descriptor like a pipe), the function returns `-1` immediately, preventing a subsequent `lseek(fd, -1, SEEK_SET)` call that would either fail with `EINVAL` or silently corrupt the file position. The indentation inconsistency noted by Patrick Steinhardt (tabs in new code vs. spaces in the rest of the file) does not affect the patch’s technical correctness.
- `transport-helper.c`: `get_exporter()` now checks the return value of `dup(helper->in)`. If `dup()` fails (e.g., due to file descriptor exhaustion), the error is propagated upward with `error_errno()`, preventing the `child_process` machinery from silently redirecting `fast-export` output to an unread pipe, which would break data flow between the helper and the exporter. Additionally, `push_refs_with_export()` now checks the return value of `rename()` when finalizing the fast-export marks file; if the rename fails, a `warning_errno()` message is emitted naming both the source and destination paths, allowing manual recovery without aborting the push operation. Patrick Steinhardt reviewed this patch and confirmed its correctness, noting that the only caller (`push_refs_with_export()`) already handles non-zero return values by dying.
- `builtin/last-modified.c`: three calls to `repo_parse_commit()` now check return values; on failure, the commit (or parent) is skipped rather than proceeding with uninitialized data, ensuring "last modified" results are not silently incorrect. The original fifth patch used `continue` in the `--not` queue error path, bypassing cleanup of the `active_paths` slab; the first fixup replaced `continue` with `goto cleanup`, and the second fixup further refines the error path to ensure the slab is released even when the commit is unparsable.
- `bisect.c` and `builtin/bisect.c`: `get_terms()` and `read_bisect_terms()` now check the return value of `strbuf_getline_lf()`. In `get_terms()`, a truncated `BISECT_TERMS` file returns `-1`, matching the existing behavior for a missing file. In `read_bisect_terms()`, a truncated file now calls `die()` with a descriptive message, ensuring the user is alerted rather than proceeding with empty or invalid term names. The ninth patch adds error checks at all six call sites of `get_terms()` in `builtin/bisect.c`; previously, a failed `get_terms()` would leave `term_bad` and `term_good` as `NULL` or empty, leading to confusing downstream behavior (e.g., nonsensical ref names like `refs/bisect/` with no suffix). The new checks ensure a clear "no terms defined" error is returned, matching the existing pattern in `bisect_terms()`. The fourth fixup patch adds `FREE_AND_NULL(terms->term_bad)` before the `goto finish` in the second error path of `get_terms()`, ensuring proper cleanup if the second `strbuf_getline_lf()` fails. The fifth fixup patch centralizes error handling in `get_terms()` itself, so that the function now returns an error if either `term_bad` or `term_good` is `NULL`, deduplicating error messages at the call sites and simplifying the callers.
- Eleventh patch (`bisect.c`): `bisect_run()` now checks the return value of `dup(1)`; if `dup()` fails (returning -1), the function closes the temporary file descriptor, emits an `error_errno()` message, and breaks out of the loop to ensure proper cleanup. This prevents two silent failures: passing -1 to `close()` (Coverity CID 1508242) and leaving stdout redirected to the temporary file for the remainder of the bisect run.
On-disk format changes: none.
Test coverage: unchanged; unit tests in `t-reftable-block.c` and `t-reftable-table.c`, and the existing config, last-modified, transport-helper, and bisect test suites implicitly exercise the new error paths.

Open questions and loose ends
The eleventh patch’s design question remains open: whether to extend the patch to also check the return value of `dup2(temporary_stdout_fd, 1)`, which follows the newly checked `dup(1)` call. Patrick Steinhardt’s suggestion is purely about completeness and does not alter the series’ overall goal or behavior. Johannes Schindelin has not yet responded.
