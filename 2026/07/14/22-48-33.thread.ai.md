Core problem or goal
Coverity static analysis identified 11 instances where Git code ignores return values from functions that can fail (e.g., `curl_easy_duphandle`, `deflateInit`, `repo_parse_commit`, `lseek`, `dup`, `strbuf_getline_lf`, `launch_editor`, `reftable_table_init_ref_iterator`, and `rename`). The series adds missing error checks to harden these code paths against silent failures, without introducing new behavior or changing on-disk formats.

Key technical details
Files touched: `http.c`, `builtin/config.c`, `reftable/block.c`, `reftable/writer.c`, `t/unit-tests/u-reftable-table.c`, `builtin/last-modified.c`, `compat/pread.c`, `transport-helper.c`, `bisect.c`, `builtin/bisect.c`.
New symbols: none.
Behavior changes: none; only fatal error paths (`die()`) or propagation to caller added, except in `transport-helper.c` where a non-fatal `warning_errno()` is emitted for a failed `rename()`. Specific fixes:
- `http.c`: `get_active_slot()` checks `curl_easy_duphandle()` return value for NULL, calling `die()` on failure. This prevents undefined behavior when subsequent libcurl operations are attempted with a NULL handle, addressing a latent crash vector in the HTTP subsystem.
- `builtin/config.c`: `show_editor()` propagates `launch_editor()` failure upward by returning `-1` (patch 2 in v3). This aligns `git config --edit` with other editor-launching commands (`git commit`, `git rebase --edit-todo`), ensuring consistent failure visibility.
- `reftable/block.c` and `reftable/writer.c`: `block_writer_init()` errors are now propagated to `reftable_writer_new()`, which deinitializes `bw->zstream` if initialization fails and releases `wp->block` and `wp` itself, preventing memory leaks and inconsistent `block_writer` states. The commit message for patch 3 clarifies that silent corruption from an uninitialized `z_stream` is not possible with current zlib versions. Patch 4 adds an explicit check for `deflateInit()` return value (`Z_OK`) in `block_writer_init()`, freeing the `z_stream` on failure and returning `REFTABLE_ZLIB_ERROR` to maintain consistency with existing `deflate()` error handling.
- `t/unit-tests/u-reftable-table.c`: `reftable_table_init_ref_iterator()` return value is now checked in `test_reftable_table__seek_once` and `test_reftable_table__reseek` via `cl_assert_equal_i(ret, 0)`, ensuring iterator initialization failures (e.g., due to memory allocation errors) are caught immediately rather than causing undefined behavior or misleading test results (patch 5).
- `compat/pread.c`: `git_pread()` checks the return value of the first `lseek(fd, 0, SEEK_CUR)` call; if it fails, the function returns `-1` immediately. This prevents a latent bug where a non-seekable descriptor (e.g., a pipe) would cause `lseek()` to return `-1`, leaving `current_offset` set to an invalid value and later passed to `lseek(fd, -1, SEEK_SET)`, which could either set the file position to an unintended location or fail with `EINVAL` on some platforms.
- `transport-helper.c`: `get_exporter()` checks `dup(helper->in)` return value; if `dup()` fails, the error is propagated upward with `error_errno()`. `push_refs_with_export()` checks `rename()` return value and emits a `warning_errno()` message if it fails. The `dup()` check in `get_exporter()` prevents silent miswiring of the fast-export process’s output to an unread pipe, which would break the transport-helper’s data flow. The `rename()` check in `push_refs_with_export()` addresses a silent inconsistency where a failed rename leaves the `.tmp` marks file behind, causing the next fast-export operation to resume from stale bookkeeping; the warning names both paths to help users recover manually. Patrick Steinhardt’s review of patch 9 raises a design question about whether the code should attempt to `unlink()` the `.tmp` file if `rename()` fails, but acknowledges the trade-off: leaving the `.tmp` file gives the user a chance to recover manually. The current patch is a clear improvement over the silent failure, enabling users to act on the warning rather than discovering the issue only when stale bookkeeping causes later errors.
- `builtin/last-modified.c`: three calls to `repo_parse_commit()` now check return values; on failure, the commit (or parent) is skipped. In `process_parent()`, a failed parse causes an early return, skipping the parent entirely. In the main walk loop (`last_modified_run()`), an unparsable commit triggers a jump to the cleanup block, while in the `--not` exclusion walk, the commit is simply skipped. This matches the defensive pattern used elsewhere in Git’s revision walkers and ensures that corrupt commits do not produce incorrect "last modified" results or prematurely terminate exclusion walks.
- `bisect.c` and `builtin/bisect.c`: `get_terms()` and `read_bisect_terms()` check `strbuf_getline_lf()` return values. `get_terms()` now accepts a `file_missing_is_ok` flag to centralize error handling. Patch 10 (v3) extends `get_terms()` to accept a `file_missing_is_ok` flag, allowing `bisect_terms()` to treat a missing `BISECT_TERMS` file as an error while letting the other five callers (`process_replay_line`, `cmd_bisect__next`, `cmd_bisect__skip`, `cmd_bisect__visualize`, and `cmd_bisect__run`) proceed gracefully. All call sites now check the return value and propagate the same error message (`"no terms defined"`) already used by `bisect_terms()`. Patch 11 adds explicit checks for `dup()` and `dup2()` return values in `bisect.c`, closing `saved_stdout` if `dup2()` fails to prevent resource leaks. The fix in `bisect_run()` ensures that if either `dup(1)` or `dup2(temporary_stdout_fd, 1)` fails, `saved_stdout` (if valid) and `temporary_stdout_fd` are closed, the error is reported via `error_errno()`, and the loop is exited to allow the existing cleanup path to handle the rest.
On-disk format changes: none.
Test coverage: unchanged; unit tests in `t-reftable-block.c` and `t-reftable-table.c`, and the existing config, last-modified, transport-helper, and bisect test suites implicitly exercise the new error paths.
