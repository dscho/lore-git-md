Thread identity
Subject: [PATCH 0/11] Coverity: unchecked return values
Series version: v1 (initial posting)
Originating author: Johannes Schindelin via GitGitGadget
Thread type: patch series

Core problem or goal
Coverity static analysis identified 11 instances where Git code ignores return values from functions that can fail (e.g., `curl_easy_duphandle`, `deflateInit`, `repo_parse_commit`, `lseek`, `dup`, `strbuf_getline_lf`, `launch_editor`, `reftable_table_init_ref_iterator`, and `rename`). The series adds missing error checks to harden these code paths against silent failures, without introducing new behavior or changing on-disk formats.

Current status
Under review; no prior versions. No maintainer decision yet; no integration branch assigned. Junio C Hamano has raised substantive correctness concerns in the fifth and ninth patches: (1) resource cleanup in `last_modified_run()` in `builtin/last-modified.c` (fifth patch) and (2) a resource leak in `get_terms()` in `bisect.c` (ninth patch) where `terms->term_bad` is not freed if the second `strbuf_getline_lf()` fails. Patrick Steinhardt has reviewed the second patch (`builtin/config.c`) and confirmed its approach is correct, noting that `launch_editor()` already emits its own error messages, so the caller only needs to propagate the failure upward. Patrick Steinhardt has also reviewed the seventh patch (`transport-helper.c`) and confirmed its correctness, noting that the only caller (`push_refs_with_export()`) already handles non-zero return values by dying, so the new error check integrates cleanly with the existing control flow. Additionally, Patrick Steinhardt has suggested extending the eleventh patch (`bisect.c`) to also check the return value of `dup2(temporary_stdout_fd, 1)`, which currently follows the newly checked `dup(1)` call; if `dup2()` fails, the bisect run would proceed with stdout still pointing to the original destination, potentially corrupting output or masking errors.

Key technical details
Files touched: `http.c`, `builtin/config.c`, `reftable/block.c`, `t/unit-tests/t-reftable-block.c`, `builtin/last-modified.c`, `compat/pread.c`, `transport-helper.c`, `bisect.c`, `builtin/bisect.c`, `t/unit-tests/u-reftable-table.c`.
New symbols: none.
Behavior changes: none; only fatal error paths (`die()`) or propagation to caller added, except in `transport-helper.c` where a non-fatal `warning_errno()` is now emitted for a failed `rename()`. Specific fixes:
- `http.c`: `get_active_slot()` now checks `curl_easy_duphandle()` return value for NULL, calling `die()` on failure to prevent undefined behavior in `curl_easy_setopt()`.
- `builtin/config.c`: `show_editor()` now propagates `launch_editor()` failure upward by returning `-1`, ensuring `git config edit` and `git config --edit` exit with an error rather than silently succeeding. Patrick Steinhardt reviewed this patch and confirmed the approach is correct, as `launch_editor()` already emits its own error messages.
- `reftable/block.c`: `block_writer_init()` now checks `deflateInit()` return value and propagates failures via `REFTABLE_ZLIB_ERROR`, preventing silent data corruption or crashes when `deflate()` is later called with an uninitialized `z_stream`.
- `compat/pread.c`: `git_pread()` now checks the return value of the first `lseek(fd, 0, SEEK_CUR)` call; if it fails (e.g., on a non-seekable descriptor like a pipe), the function returns `-1` immediately, preventing a subsequent `lseek(fd, -1, SEEK_SET)` call that would either fail with `EINVAL` or silently corrupt the file position. Patrick Steinhardt noted in a surface-level review that while the new code is correctly indented with tabs, the rest of the file uses spaces for indentation, but this observation does not affect the patch’s technical correctness.
- `transport-helper.c`: `get_exporter()` now checks the return value of `dup(helper->in)`. If `dup()` fails (e.g., due to file descriptor exhaustion), the error is propagated upward with `error_errno()`, preventing the `child_process` machinery from silently redirecting `fast-export` output to an unread pipe, which would break data flow between the helper and the exporter. Additionally, `push_refs_with_export()` now checks the return value of `rename()` when finalizing the fast-export marks file; if the rename fails, a `warning_errno()` message is emitted naming both the source and destination paths, allowing manual recovery without aborting the push operation. Patrick Steinhardt reviewed this patch and confirmed its correctness, noting that the only caller (`push_refs_with_export()`) already handles non-zero return values by dying.
- `builtin/last-modified.c`: three calls to `repo_parse_commit()` now check return values; on failure, the commit (or parent) is skipped rather than proceeding with uninitialized data, ensuring "last modified" results are not silently incorrect. Junio C Hamano has identified a correctness issue in the error-handling logic for `last_modified_run()`: the current patch skips unparsable commits in the `--not` queue with a `continue`, bypassing cleanup of the `active_paths` slab associated with the commit being processed (`c`). This could lead to memory leaks or inconsistent slab state. The fix requires replacing the `continue` with a `goto cleanup` to ensure proper resource cleanup.
- `bisect.c` and `builtin/bisect.c`: `get_terms()` and `read_bisect_terms()` now check the return value of `strbuf_getline_lf()`. In `get_terms()`, a truncated `BISECT_TERMS` file returns `-1`, matching the existing behavior for a missing file. In `read_bisect_terms()`, a truncated file now calls `die()` with a descriptive message, ensuring the user is alerted rather than proceeding with empty or invalid term names. The ninth patch adds error checks at all six call sites of `get_terms()` in `builtin/bisect.c`; previously, a failed `get_terms()` would leave `term_bad` and `term_good` as `NULL` or empty, leading to confusing downstream behavior (e.g., nonsensical ref names like `refs/bisect/` with no suffix). The new checks ensure a clear "no terms defined" error is returned, matching the existing pattern in `bisect_terms()`. Junio C Hamano has identified a resource leak in `get_terms()`: if the first line is read successfully but the second fails (returning `EOF`), the patch currently jumps to `finish` without freeing `terms->term_bad`, which was allocated by `strbuf_detach()`. This would leave the struct in a partially initialized state with a dangling pointer, risking a leak if the caller does not handle the `-1` return value by calling `free_terms()`. The fix requires adding a `free(terms->term_bad)` before the `goto finish` in the second error path. The tenth patch addresses the six call sites of `get_terms()` in `builtin/bisect.c`, ensuring consistent error handling. Patrick Steinhardt has raised a design question about this patch: instead of checking the term pointers (`term->bad` and `term->good`) at each call site, should `get_terms()` itself return an error if either term is `NULL`? This could centralize error handling and deduplicate error messages, simplifying the callers. The question is whether any callers legitimately accept `NULL` terms, which would determine whether such a change is feasible. The eleventh patch addresses `bisect_run()` in `builtin/bisect.c`, where a failed `dup(1)` call was previously ignored. The fix adds an error check: if `dup()` fails (returning -1), the function now closes the temporary file descriptor, emits an `error_errno()` message, and breaks out of the loop to ensure proper cleanup. This prevents two silent failures: passing -1 to `close()` (Coverity CID 1508242) and leaving stdout redirected to the temporary file for the remainder of the bisect run. Patrick Steinhardt has suggested extending this patch to also check the return value of `dup2(temporary_stdout_fd, 1)`, which follows the `dup(1)` call; if `dup2()` fails, the bisect run would proceed with stdout still pointing to the original destination, potentially corrupting output or masking errors. The fix would follow the same pattern: check the return value, emit an `error_errno()` message, close the temporary file descriptor, and break out of the loop.
On-disk format changes: none.
Test coverage: unchanged; unit tests in `t-reftable-block.c` and `t-reftable-table.c`, and the existing config, last-modified, transport-helper, and bisect test suites implicitly exercise the new error paths.

Open questions and loose ends
Junio C Hamano has raised two correctness concerns that must be addressed before the series can be considered ready for integration:
1. Fifth patch (`builtin/last-modified.c`): the error-handling logic in `last_modified_run()` must ensure proper cleanup of the `active_paths` slab when skipping unparsable commits in the `--not` queue. The current `continue` bypasses cleanup, risking memory leaks or inconsistent slab state.
2. Ninth patch (`bisect.c`): the error-handling logic in `get_terms()` must free `terms->term_bad` if the second `strbuf_getline_lf()` fails, preventing a resource leak.

Additionally, Patrick Steinhardt has raised two design questions:
1. Tenth patch (`builtin/bisect.c`): whether `get_terms()` should itself return an error if either term is `NULL`, centralizing error handling and deduplicating error messages at the call sites. This question remains open and depends on whether any callers legitimately accept `NULL` terms.
2. Eleventh patch (`bisect.c`): whether to extend the patch to also check the return value of `dup2(temporary_stdout_fd, 1)`, which currently follows the newly checked `dup(1)` call. The suggestion is purely about completeness and does not alter the series’ overall goal or behavior.
