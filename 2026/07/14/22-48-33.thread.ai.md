Subject: [PATCH 0/11] Coverity: unchecked return values
Series version: v1 (initial posting)
Originating author: Johannes Schindelin via GitGitGadget
Thread type: patch series

Core problem or goal
Coverity static analysis identified 11 instances where Git code ignores return values from functions that can fail (e.g., `curl_easy_duphandle`, `deflateInit`, `repo_parse_commit`, `lseek`, `dup`, `strbuf_getline_lf`, `launch_editor`, `reftable_table_init_ref_iterator`). The series adds missing error checks to harden these code paths against silent failures, without introducing new behavior or changing on-disk formats.

Current status
Under review; no prior versions. No maintainer decision yet; no integration branch assigned.

Key technical details
Files touched: `http.c`, `builtin/config.c`, `reftable/block.c`, `t/unit-tests/t-reftable-block.c`, `builtin/last-modified.c`, `compat/pread.c`, `transport-helper.c`, `bisect.c`, `builtin/bisect.c`, `t/unit-tests/u-reftable-table.c`.
New symbols: none.
Behavior changes: none; only fatal error paths (`die()`) or propagation to caller added. Specific fixes:
- `http.c`: `get_active_slot()` now checks `curl_easy_duphandle()` return value for NULL, calling `die()` on failure to prevent undefined behavior in `curl_easy_setopt()`.
- `builtin/config.c`: `show_editor()` now propagates `launch_editor()` failure upward by returning `-1`, ensuring `git config edit` and `git config --edit` exit with an error rather than silently succeeding.
- `reftable/block.c`: `block_writer_init()` now checks `deflateInit()` return value and propagates failures via `REFTABLE_ZLIB_ERROR`, preventing silent data corruption or crashes when `deflate()` is later called with an uninitialized `z_stream`.
- `compat/pread.c`: `git_pread()` now checks the return value of the first `lseek(fd, 0, SEEK_CUR)` call; if it fails (e.g., on a non-seekable descriptor like a pipe), the function returns `-1` immediately, preventing a subsequent `lseek(fd, -1, SEEK_SET)` call that would either fail with `EINVAL` or silently corrupt the file position.
- `transport-helper.c`: `get_exporter()` now checks the return value of `dup(helper->in)`. If `dup()` fails (e.g., due to file descriptor exhaustion), the error is propagated upward with `error_errno()`, preventing the `child_process` machinery from silently redirecting `fast-export` output to an unread pipe, which would break data flow between the helper and the exporter.
- `builtin/last-modified.c`: three calls to `repo_parse_commit()` now check return values; on failure, the commit (or parent) is skipped rather than proceeding with uninitialized data, ensuring "last modified" results are not silently incorrect.
- `t/unit-tests/u-reftable-table.c`: `test_reftable_table__seek_once` and `test_reftable_table__reseek` now check the return value of `reftable_table_init_ref_iterator()` using `cl_assert_equal_i(ret, 0)`, ensuring the test fails clearly if iterator initialization fails (e.g., due to memory allocation errors) rather than proceeding with an uninitialized iterator.
- Other patches (per prior summary) add similar checks for `strbuf_getline_lf` and remaining instances in `bisect.c`/`builtin/bisect.c`.
On-disk format changes: none.
Test coverage: unchanged; unit tests in `t-reftable-block.c` and `t-reftable-table.c`, and the existing config, last-modified, and transport-helper test suites implicitly exercise the new error paths.

Open questions and loose ends
