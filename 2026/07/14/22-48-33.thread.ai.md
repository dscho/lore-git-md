Core problem or goal
Coverity static analysis identified 11 instances where Git code ignores return values from functions that can fail (e.g., `curl_easy_duphandle`, `deflateInit`, `repo_parse_commit`, `lseek`, `dup`, `strbuf_getline_lf`, `launch_editor`, `reftable_table_init_ref_iterator`, and `rename`). The series adds missing error checks to harden these code paths against silent failures, without introducing new behavior or changing on-disk formats.

Current status
Under review; v2 posted incorporating all substantive review feedback. No maintainer decision yet; no integration branch assigned. Junio C Hamano’s four correctness concerns (fifth and ninth patches, plus a second fixup for the fifth patch and the fourth fixup for the ninth patch) are fully resolved by the corresponding fixup patches in v2. Patrick Steinhardt’s two design questions (tenth patch’s error-handling centralization and eleventh patch’s `dup2()` completeness) are also resolved by the fifth and sixth fixup patches, respectively. All patches are now technically complete and uncontroversial. The sixth patch (`compat/pread.c`), seventh patch (`transport-helper.c`), and eighth patch (`transport-helper.c`) are explicitly confirmed as ready for integration in the latest email.

Key technical details
Files touched: `http.c`, `builtin/config.c`, `reftable/block.c`, `t/unit-tests/t-reftable-block.c`, `builtin/last-modified.c`, `compat/pread.c`, `transport-helper.c`, `bisect.c`, `builtin/bisect.c`, `t/unit-tests/u-reftable-table.c`.
New symbols: none.
Behavior changes: none; only fatal error paths (`die()`) or propagation to caller added, except in `transport-helper.c` where a non-fatal `warning_errno()` is now emitted for a failed `rename()`. Specific fixes:
- `http.c`: `get_active_slot()` now checks `curl_easy_duphandle()` return value for NULL, calling `die()` on failure to prevent undefined behavior in `curl_easy_setopt()`. This patch (first in v2) is uncontroversial and ready for integration.
- `builtin/config.c`: `show_editor()` now propagates `launch_editor()` failure upward by returning `-1`, ensuring `git config edit` and `git config --edit` exit with an error rather than silently succeeding. Patrick Steinhardt reviewed this patch and confirmed the approach is correct, as `launch_editor()` already emits its own error messages. The change aligns `git config`’s editor-launching behavior with other Git commands like `git commit` and `git rebase --edit-todo`.
- `reftable/block.c`: `block_writer_init()` now checks `deflateInit()` return value and propagates failures via `REFTABLE_ZLIB_ERROR`, preventing silent data corruption or crashes when `deflate()` is later called with an uninitialized `z_stream`. The fix is minimal (two lines added, one removed) and matches the existing error-handling pattern for `deflate()` failures elsewhere in the function.
- `compat/pread.c`: `git_pread()` now checks the return value of the first `lseek(fd, 0, SEEK_CUR)` call; if it fails (e.g., on a non-seekable descriptor like a pipe), the function returns `-1` immediately, preventing a subsequent `lseek(fd, -1, SEEK_SET)` call that would either fail with `EINVAL` or silently corrupt the file position. The indentation inconsistency noted by Patrick Steinhardt (tabs in new code vs. spaces in the rest of the file) does not affect the patch’s technical correctness. The patch is explicitly confirmed as ready for integration in the latest email.
- `transport-helper.c`: `get_exporter()` now checks the return value of `dup(helper->in)`. If `dup()` fails (e.g., due to file descriptor exhaustion), the error is propagated upward with `error_errno()`, preventing the `child_process` machinery from silently redirecting `fast-export` output to an unread pipe, which would break data flow between the helper and the exporter. Additionally, `push_refs_with_export()` now checks the return value of `rename()` when finalizing the fast-export marks file; if the rename fails, a `warning_errno()` message is emitted naming both the source and destination paths, allowing manual recovery without aborting the push operation. The eighth patch specifically addresses the `rename()` check, which is minimal (three lines added, one removed) and uncontroversial. Patrick Steinhardt reviewed the seventh patch and confirmed its correctness, noting that the only caller (`push_refs_with_export()`) already handles non-zero return values by dying.
- `builtin/last-modified.c`: three calls to `repo_parse_commit()` now check return values; on failure, the commit (or parent) is skipped rather than proceeding with uninitialized data, ensuring "last modified" results are not silently incorrect. The error path now uses `goto cleanup` to ensure the `active_paths` slab is released even when the commit is unparsable. The patch directly addresses Junio’s v1 review concern about proceeding with uninitialized commit data and follows the defensive pattern used in other revision walkers like `limit_list()` and `get_revision_internal()`.
- `t/unit-tests/u-reftable-table.c`: `test_reftable_table__seek_once()` and `test_reftable_table__reseek()` now check the return value of `reftable_table_init_ref_iterator()`; if initialization fails, the test fails with an assertion error rather than proceeding with an uninitialized iterator. The change is minimal (two lines added) and matches the error-checking pattern used elsewhere in the same test file.
- `bisect.c` and `builtin/bisect.c`: `get_terms()` and `read_bisect_terms()` now check the return value of `strbuf_getline_lf()`. In `get_terms()`, a truncated `BISECT_TERMS` file returns `-1`, matching the existing behavior for a missing file. In `read_bisect_terms()`, a truncated file now calls `die()` with a descriptive message, ensuring the user is alerted rather than proceeding with empty or invalid term names. The ninth patch adds error checks at all six call sites of `get_terms()` in `builtin/bisect.c`; previously, a failed `get_terms()` would leave `term_bad` and `term_good` as `NULL` or empty, leading to confusing downstream behavior (e.g., nonsensical ref names like `refs/bisect/` with no suffix). The new checks ensure a clear "no terms defined" error is returned, matching the existing pattern in `bisect_terms()`. The tenth patch centralizes error handling in `get_terms()` itself by extending its signature to accept a `file_missing_is_ok` flag, so that the function now returns an error if either `term_bad` or `term_good` is `NULL`, deduplicating error messages at the call sites and simplifying the callers. The eleventh patch (`bisect.c`) now checks the return values of both `dup(1)` and `dup2(temporary_stdout_fd, 1)`; if either call fails, the code emits an `error_errno()` message, closes the temporary file descriptor, and breaks out of the bisect-run loop, ensuring proper cleanup and preventing silent failures.
On-disk format changes: none.
Test coverage: unchanged; unit tests in `t-reftable-block.c` and `t-reftable-table.c`, and the existing config, last-modified, transport-helper, and bisect test suites implicitly exercise the new error paths.
