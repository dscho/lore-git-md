Core problem or goal
Coverity static analysis identified 11 instances where Git code ignores return values from functions that can fail (e.g., `curl_easy_duphandle`, `deflateInit`, `repo_parse_commit`, `lseek`, `dup`, `strbuf_getline_lf`, `launch_editor`). The series adds missing error checks to harden these code paths against silent failures, without introducing new behavior or changing on-disk formats.

Current status
Under review; no prior versions. No maintainer decision yet; no integration branch assigned.

Key technical details
Files touched: `http.c`, `builtin/config.c`, `reftable/block.c`, `t/unit-tests/t-reftable-block.c`, `builtin/last-modified.c`, `compat/pread.c`, `transport-helper.c`, `bisect.c`, `builtin/bisect.c`.
New symbols: none.
Behavior changes: none; only fatal error paths (`die()`) or propagation to caller added. Specific fixes:
- `http.c`: `get_active_slot()` now checks `curl_easy_duphandle()` return value for NULL, calling `die()` on failure to prevent undefined behavior in `curl_easy_setopt()`.
- `builtin/config.c`: `show_editor()` now propagates `launch_editor()` failure upward by returning `-1`, ensuring `git config edit` and `git config --edit` exit with an error rather than silently succeeding.
- Other patches (per prior summary) add similar checks for `deflateInit`, `repo_parse_commit`, `lseek`, `dup`, and `strbuf_getline_lf`.
On-disk format changes: none.
Test coverage: unchanged; unit tests in `t-reftable-block.c` and the existing config test suite implicitly exercise the new error paths.
