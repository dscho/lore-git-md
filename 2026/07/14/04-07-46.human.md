This is a brief follow-up in the ongoing packfile URI race-condition bugfix series. Taylor Blau chimes in to endorse Ted Nyman’s argument against Junio C Hamano’s suggestion of using `O_CREAT | O_EXCL` with the existing `.pack.temp` filename. Taylor agrees that Git cannot reliably tell whether a `.pack.temp` file is from an in-progress download or a leftover from a crashed process, since those files are not pruned by Git’s temporary-file cleanup. The note reinforces the design choice in Patch 1—unique tempfiles for each download—as the simplest and most robust way to fix the race without introducing coordination complexity. No new code or tests are proposed; the email simply signals alignment on the current approach.
