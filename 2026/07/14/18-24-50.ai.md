This is the fourth patch in Harald Nordgren’s **v19 `git branch --delete-merged` series**, now implementation-complete and ready for merging. The patch prepares the existing `delete_branches()` API for the upcoming `--delete-merged` bulk caller by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, which prevents falling back to `HEAD` when a branch has no upstream. This change is mechanical and does not alter behavior for existing callers, but it is critical for the safety guarantees of the new `--delete-merged` command.

The patch modifies `delete_branches()` to conditionally skip the `HEAD` fallback when the new flag is set, ensuring that `--delete-merged` only deletes branches that are explicitly merged into their upstream (and not into `HEAD`). The commit message clarifies that this is a transitional step: the existing behavior (falling back to `HEAD`) is preserved for all current callers, while the new flag enables the stricter semantics required by `--delete-merged`. The change is well-scoped, touching only the `head_rev` lookup logic and leaving the rest of the function unchanged.

This patch is part of the **flags-based API refactoring** (patches 2–4/7) that replaces boolean arguments with an `unsigned int flags` parameter. The refactoring eliminates local boolean caching, ensuring flags remain the single source of truth and resolving a maintenance risk noted in earlier iterations. The new flag (`DELETE_BRANCH_NO_HEAD_FALLBACK`) complements the existing `DELETE_BRANCH_SKIP_UNMERGED` (added in patch 3/7) and will be joined by `DELETE_BRANCH_DRY_RUN` in patch 7/7.
