This is the sixth patch in Harald Nordgren’s **v19 `git branch --delete-merged` series**, now implementation-complete and ready for merging. The patch adds a **per-branch opt-out mechanism** via the `branch.<name>.deleteMerged=false` config key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The implementation is straightforward and well-scoped: the opt-out is checked during candidate filtering in `delete_merged_branches()`, and a non-quiet skip message is printed for each exempted branch. The config key is documented in both `branch.adoc` and `git-branch.adoc`, and the test suite verifies the opt-out behavior, skip messages, and explicit deletion via `git branch -d`. Phillip Wood’s surface-level review suggested a mechanical test improvement (using `git for-each-ref` via the `check_branches` helper), which has been applied.

The patch is **low-risk and well-motivated**, addressing a real workflow need (iterative topic branches) without altering the core deletion logic. The opt-out mechanism complements the series’ existing safety checks (stacked-branch protection, push divergence, etc.) and is consistent with Git’s config-based customization patterns.
