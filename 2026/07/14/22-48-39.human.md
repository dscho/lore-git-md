This is a bugfix patch, part of Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. It targets the `git_pread()` compatibility wrapper in `compat/pread.c`.

The issue is straightforward: `git_pread()` saves the current file offset with `lseek(fd, 0, SEEK_CUR)` and later restores it. If the initial `lseek()` fails (e.g., because the file descriptor is a pipe or non-seekable), the saved offset is `-1`, which is then passed to `lseek(fd, -1, SEEK_SET)`. This can either set the file position to an unintended location or fail outright with `EINVAL` on some platforms. The fix adds a check for the initial `lseek()` return value and returns `-1` immediately if it fails, matching the error handling already present for the other `lseek()` calls in the function.

The patch is minimal (two lines added) and uncontroversial. It follows the same pattern as the rest of the series: a mechanical addition of error checking to prevent silent failures. The commit message clearly explains the problem and the fix, and the change is consistent with the existing error-handling style in the file. No new behavior is introduced, and the fix is exercised by any code path that calls `git_pread()` on a non-seekable file descriptor.
