This is a bug report about `git log --cherry-mark`.

Uwe Kleine-König reports that `git log --cherry-mark --right-only` fails to mark a commit as equivalent (`=`) when the range includes a merge commit, even though the same commit is correctly marked when the range excludes the merge. The example uses a Linux kernel tree where a series of patches was applied, and demonstrates that `ca270a534d0f` appears as unmarked (`*`) in the first log but as equivalent (`=`) in the second, narrower log. The discrepancy suggests the merge commit interferes with the cherry-mark logic.

The report includes reproduction steps using Git 2.55.0 plus Phillip Wood’s recent series addressing a previous bug in the same area. Uwe offers to provide a bundle of the relevant commits privately if needed. No patch is attached; this is a pure bug report rather than a fix. The issue looks real and well-isolated, targeting the revision-walking logic that compares commits across branches.
