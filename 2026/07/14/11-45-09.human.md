This is the final patch in the seventeenth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. The patch replaces the static allow-list for format placeholders with dynamic capability-based validation, directly addressing a critical limitation identified during review: the original hardcoded list ("objectname", "objectsize") would break as servers evolve to support additional metadata like object types.

The implementation maps server-advertised capabilities (e.g., "size") to format atoms (e.g., "objectsize") at runtime, filtering unsupported options before sending requests. This two-stage approach—first introduced in v16 to fix segfaults and `die()` calls—now fully generalizes to future protocol extensions. The patch also moves `object_info_options` out of `get_remote_info()` to let callers specify requested metadata, and ensures empty output lines when all placeholders are unsupported (matching Git’s established patterns).

Key changes include:
- A `remote_atom_map` connecting protocol options to format atoms
- Backward iteration during capability filtering to avoid element-skipping
- Explicit cleanup of `remote_allowed_atoms` in `batch_objects()`
- Support for "type" in preparation for future server-side additions

The patch is well-motivated and technically sound, completing the series’ security-focused design. All prior feedback—including Junio’s critical refactoring flaw in v15 and the segfault issues in format handling—has been addressed. The series is now ready for merging to `next`.
