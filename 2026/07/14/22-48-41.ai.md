This is the eighth patch in Johannes Schindelin’s 11-patch series fixing unchecked return values flagged by Coverity. It targets the transport-helper subsystem, specifically the `push_refs_with_export()` function in `transport-helper.c`.

The patch addresses a silent failure in the export-marks bookkeeping: after a successful push, the code writes the fast-export marks to a `.tmp` file and then `rename()`s it into place, but the return value of `rename()` is ignored. If the rename fails (due to permissions, disk full, or antivirus interference on Windows), the `.tmp` file is left behind and the existing `export_marks` file remains stale. The next fast-export operation that resumes from this file then operates on inconsistent state, potentially corrupting the exported history.

The fix is minimal and pragmatic: instead of promoting the failure to a fatal error (which would be inappropriate since the push itself succeeded), the patch emits a `warning_errno()` message naming both the source and destination paths, allowing the user to recover manually. The function continues to return 0, preserving the existing behavior for the push operation itself. The change is purely defensive and introduces no new behavior or on-disk format changes. Coverity flagged this as CID 1427723 ("Unchecked return value").
