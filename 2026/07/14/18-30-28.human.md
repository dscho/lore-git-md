This is a refactoring patch that converts the `show-branch` command from using the shared `object.flags` field to a dedicated commit-slab for storing per-commit state. The patch comes from Gatla Vishweshwar Reddy, a first-time contributor to the Git project.

The motivation is clear: `show-branch` currently uses `commit->object.flags` to track two kinds of data (the `UNINTERESTING` bit and per-branch reachability bits), but this field is shared across the entire Git codebase. Storing command-specific data there risks conflicts with other subsystems. The patch replaces this usage with a new `commit_rev_flags` slab, which is the established pattern for associating per-commit data without polluting shared fields.

The conversion is mechanical and thorough. The patch introduces helper functions (`get_rev_flags` and `or_rev_flags`) to encapsulate slab access, initializes and clears the slab in `cmd_show_branch` to prevent memory leaks, and updates all references to `commit->object.flags` in the file. The diff is clean and focused, touching only `builtin/show-branch.c`.

This is a well-motivated, low-risk refactoring that aligns with Git’s ongoing efforts to eliminate fragile patterns (like shared `object.flags` usage) in favor of more robust abstractions. The commit message is clear, and the implementation follows established conventions. It looks like a solid contribution that should attract little controversy.
