This thread is about a refactoring patch to `git show-branch` that replaces its use of the shared `object.flags` field with a dedicated commit-slab for per-commit state. The patch, now in its fourth iteration (v4) by Gatla Vishweshwar Reddy, addresses feedback from Junio C Hamano and Jeff King on earlier versions. The key improvement is lifting the previous 27-branch limit to 64 branches by using a configurable `uint64_t`-based slab, while keeping the `UNINTERESTING` bit in `object.flags` for compatibility with revision walking.

The main blocker in v3 was a behavioral regression in `show_independent()`: the slab-based version weakened the independence check from requiring *exactly* the current branch’s bit to *at least* that bit. Gatla’s v4 fixes this by introducing `has_only_rev_flag_bit()`, restoring the exact-bit-set logic. The patch is now ready for maintainer sign-off, pending confirmation from reviewers that the fix is correct. No other objections or open questions remain, and the design direction is uncontested. Junio and Peff provided substantive feedback on earlier versions, but neither has reviewed v4 yet. The patch touches only `builtin/show-branch.c` and reuses infrastructure from the 2025 variable-length bitset slab series.
