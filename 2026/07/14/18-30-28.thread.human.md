This thread is about a refactoring patch that replaces `git show-branch`'s use of the shared `object.flags` field with a dedicated commit-slab, lifting a long-standing 27-branch limit. The patch, now in its second version by Gatla Vishweshwar Reddy, directly addresses feedback from Junio C Hamano on an earlier RFC by Meet Soni, widening the slab storage to 64 bits to allow up to 62 branches.

Junio’s latest review raises substantive concerns: he argues the patch doesn’t fully exploit the slab’s flexibility, suggesting a variable-length array would better handle hundreds of branches, and notes the UNINTERESTING bit (used for revision walking) should stay in `object.flags` rather than moving to the slab. He also flags a type mismatch in `omit_in_dense()` that could break 32-bit platforms. While the patch is mechanically clean and well-motivated, these issues will need to be resolved before it can move forward. No other reviewers have weighed in yet.
