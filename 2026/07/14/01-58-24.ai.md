This is a follow-up in the packfile URI race-condition bugfix series, specifically addressing Junio C Hamano’s design-level concern about Patch 1. Ted Nyman acknowledges the inefficiency of redundant downloads when multiple processes fetch the same packfile concurrently but argues for keeping the current approach in this series. The unique tempfile design preserves the existing "download, index, then install" workflow for each process, fixing both the concurrent-append and EOF-resume race conditions without introducing cross-process coordination complexity.

Ted points out that using `O_CREAT | O_EXCL` with the existing `.pack.temp` filename would not reliably distinguish between an in-progress download and a leftover file from a crashed process, since those files are not pruned by Git’s temporary-file cleanup. Implementing a coordination mechanism would require additional logic to handle handoffs (e.g., detecting when the first process finishes or fails) and a timeout policy, which he considers out of scope for this correctness-focused series. He suggests deferring the efficiency improvement to a follow-up unless Junio insists it is necessary for the fix.

The discussion remains open on whether the simplicity of unique tempfiles is preferable to the performance benefits of coordinated downloads, but Ted’s response clarifies the trade-offs and keeps the focus on the immediate bugfix. No code changes are proposed in this email; it is purely a design rationale. The thread is now awaiting Junio’s reaction to the argument for deferring the coordination logic.
