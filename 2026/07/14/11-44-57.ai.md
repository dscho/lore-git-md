This is the first patch in the seventeenth iteration of a security-focused feature series adding `remote-object-info` support to `git cat-file --batch-command`. The patch fixes a memory leak in the transport helper subsystem where `data->name` (allocated during `transport_helper_init()`) was not being freed when disconnecting a transport whose helper had not fully started.

The fix is minimal and targeted: it moves `FREE_AND_NULL(data->name)` outside the conditional block in `disconnect_helper()` so the allocation is always freed on disconnect, regardless of the helper's state. This matches Git's established pattern for resource cleanup and addresses a subtle edge case that could affect long-running processes. The change is purely mechanical with no behavior modification beyond plugging the leak.

This patch demonstrates the series' attention to memory safety, which has been a recurring theme across iterations. The leak would most likely manifest in edge cases where transport initialization fails or is interrupted, making the fix a real (if narrow) improvement. The fix was previously identified and confirmed in review, and this version implements it cleanly.
