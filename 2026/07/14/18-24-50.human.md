This is the fourth patch in Harald Nordgren’s **v19 `git branch --delete-merged` series**, which is now implementation-complete and ready for merging. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including per-branch opt-out, `--dry-run` preview, and refined stacked-branch protection.

This specific patch prepares the `delete_branches()` function for the upcoming `--delete-merged` bulk caller by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`. The flag prevents the function from falling back to `HEAD` when checking whether a branch is merged into its upstream, which is necessary for the `--delete-merged` command to avoid false positives. Existing callers retain their current behavior, ensuring no regressions.

The change is small but critical for the series’ safety guarantees. The `--delete-merged` command relies on precise upstream reachability checks, and falling back to `HEAD` would undermine its ability to distinguish truly merged branches from those that merely share a common ancestor with the current branch. The patch also updates the `branch_merged()` helper to skip the "gentle reminder" about `HEAD` fallback when the caller explicitly opts out, avoiding unnecessary noise in the `--delete-merged` workflow.

This patch is part of the **flags-based API refactoring** (patches 2-4/7) that replaces boolean arguments with an `unsigned int flags` parameter. The refactoring eliminates local boolean caching, ensuring flags remain the single source of truth and resolving a maintenance risk noted in earlier versions. The new flag is well-documented in the enum and integrates cleanly with the existing `DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`, and `DELETE_BRANCH_SKIP_UNMERGED` flags.

The patch is **well-motivated** and **minimal**, touching only the necessary code to support the `--delete-merged` command. It includes a clear commit message and maintains backward compatibility for all existing callers.
