This is the core patch in Harald Nordgren’s **`git branch --delete-merged`** series, now in its final v19 form and ready for merging. The patch implements the actual `--delete-merged` subcommand, which safely deletes local branches whose work has already landed on their upstream, while preserving branches that are still needed (e.g., checked-out, used as upstreams for unmerged branches, or opted out via config).

The command supports **repeatable upstream arguments** (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the upstream match, and **optional positional patterns** (e.g., `topic-*`) to limit deletion scope. Safety checks include:
- Skipping checked-out branches (any worktree).
- Preserving branches with missing upstreams or those that push to their upstream (e.g., `main` tracking `origin/main`).
- **Refined stacked-branch protection (abort-and-clear)**: If a branch is used as an upstream for an unmerged branch, it is spared, and its own stale upstream config is cleared if the upstream is being deleted. This avoids breaking dependency chains while cleaning up stale configs.
- Silently skipping unmerged branches (one unmerged topic does not abort the entire sweep).

The implementation is **thoroughly tested**, with integration tests covering edge cases like self-referential upstreams, missing upstreams, and the interaction between stacked branches. The patch also includes clear documentation in `git-branch.adoc`, explaining the command’s behavior and safety guarantees.

This is a **well-crafted feature** that addresses a real workflow pain point (safe automated branch cleanup) with careful attention to safety and edge cases. The series has converged on a design that aligns with Git’s API consistency expectations, and all remaining issues (e.g., `--dry-run` config modification, flags handling) have been resolved in v19.
