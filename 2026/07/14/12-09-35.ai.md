This is the **core visualization patch** (4/7) in Pablo Sabater’s **`git log --graph` visual root indentation** series, now at **v12**. The patch implements the actual indentation logic that clarifies ancestry relationships by progressively indenting commits with excluded parents (visual roots), while preserving parent-child connections.

The patch introduces a new `is_visual_root` flag in `struct git_graph` and a `GRAPH_PRE_ROOT` state to print an extra row connecting indented roots to their children. Key behaviors:
- **Cascading indentation**: adjacent visual roots increase indentation depth, but the last root in a sequence is not indented to avoid ambiguity.
- **Merge parents**: explicitly excluded from indentation via a new `is_merge_parent` flag in `struct column`, ensuring they remain visually connected to the merge commit.
- **Indentation calculation**: applied in `graph_output_commit_line()` using `(depth - cascade) * 2`, where `cascade` omits indentation for the first root in a sequence.

The implementation relies on the **lookahead buffer** (introduced in patch 3/7) to determine visual root status before rendering, and the **unified `next_commit_to_show()` helper** (patch 2/7) to ensure commits are fully simplified before inspection. The patch adds **244 lines** to `graph.c`, including new helper functions (`graph_is_visual_root_candidate`, `graph_peek_next_visible`, `graph_needs_pre_root_line`) and BUG assertions to enforce invariants.

**Test coverage** is extensive: the new `t4218-log-graph-indentation.sh` (514 lines) verifies edge cases for single roots, cascading roots, merge parents, boundary commits, and filtering options (`--first-parent`, `--left-right`, `--max-count`, `--grep`/`--author`). Existing tests (`t4215`, `t6016`) were updated to reflect the new indentation rules.

The patch is **mechanically stable** (no changes since v7) and **architecturally approved** by Junio Hamano and Kristofer Karlsson. The only remaining work is final review of the series; this patch itself has no known issues. The **four-level wrap** (patch 5/7) and **opt-out mechanism** (patch 7/7) build on this foundation, but this patch is self-contained and ready for integration.
