This is the tenth patch in Johannes Schindelin’s 11-patch series addressing unchecked return values identified by Coverity. It targets the bisect subsystem, specifically the `get_terms()` function in `builtin/bisect.c`.

The patch adds error checks at all six call sites of `get_terms()`. Previously, if `get_terms()` failed (e.g., due to a missing or truncated `BISECT_TERMS` file), the term strings (`term_bad` and `term_good`) would remain `NULL` or empty, leading to confusing downstream behavior such as nonsensical ref names (e.g., `refs/bisect/` with no suffix) and misleading error messages. The new checks ensure that a failed `get_terms()` results in a clear "no terms defined" error, matching the existing pattern in `bisect_terms()`.

The fix is mechanical and uncontroversial: each call site now verifies that `terms->term_bad` and `terms->term_good` are non-NULL before proceeding. The check is performed on the term pointers rather than the return value of `get_terms()` because some callers (e.g., `bisect skip`, legacy `bad/good`) call `set_terms()` before `get_terms()`, and the `set_terms()` values should survive a `get_terms()` failure. The patch touches only `builtin/bisect.c` and introduces no new symbols or behavior changes beyond the added error handling.

This aligns with the series’ overall goal of hardening Git against silent failures by ensuring critical return values are checked. The bisect subsystem is now more robust, and users will receive clear error messages instead of confusing or misleading output when the `BISECT_TERMS` file is corrupted or missing. The patch is well-motivated and fits cleanly into the broader Coverity-driven effort.
