This is the final patch in Johannes Schindelin’s 11-patch series addressing unchecked return values flagged by Coverity. It targets the bisect subsystem’s `bisect_run()` function in `builtin/bisect.c`, where a failed `dup(1)` call was previously ignored. The fix adds an error check: if `dup()` fails (returning -1), the function now closes the temporary file descriptor, emits an `error_errno()` message, and breaks out of the loop to ensure proper cleanup. This prevents two silent failures: passing -1 to `close()` (Coverity CID 1508242) and leaving stdout redirected to the temporary file for the remainder of the bisect run.

The patch is mechanical and aligns with the series’ goal of hardening error paths without changing behavior. It touches only `builtin/bisect.c` and introduces no new symbols or on-disk format changes. The error handling follows the pattern established in earlier patches: propagate failures upward with a descriptive message. The bisect test suite will implicitly exercise this path, though no new tests are added. This is a straightforward fix for a latent bug that could corrupt output redirection under resource constraints (e.g., file descriptor exhaustion).
