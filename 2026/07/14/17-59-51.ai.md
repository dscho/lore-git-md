This is a refactoring series targeting the `the_repository` removal effort. René Scharfe introduces new repository-aware variants of the tempfile and lockfile APIs (`repo_create_tempfile`, `repo_hold_lock_file_for_update`, etc.) and migrates existing callers to use them instead of the global `the_repository`. The series touches 21 files across multiple subsystems: apply, builtins, ref backends, commit-graph, midx, ODB, and config.

The motivation is clear: eliminating implicit reliance on `the_repository` is a long-standing project goal, and the tempfile/lockfile layer is a natural place to push the repository parameter outward. Patch 1 introduces the new APIs; patches 2–4 migrate the tempfile and lockfile internals; patch 5 converts a handful of lockfile users that already work with non-default repositories. The diffstat shows a net increase of 58 lines, mostly due to the new API declarations in `lockfile.h` and `tempfile.h`.

René is the primary driver of the `the_repository` removal effort, so this series is well-aligned with ongoing work. The changes are mechanical and confined to plumbing; no user-visible behavior changes are expected. The commit messages are concise but sufficient, and the patch boundaries are logical.

Key technical details for follow-up discussion: the new functions are named `repo_create_tempfile_mode`, `repo_hold_lock_file_for_update_timeout_mode`, etc., mirroring the existing non-repo variants. Callers in `refs/packed-backend.c`, `commit-graph.c`, and `midx-write.c` are among the first to adopt the new APIs. The series does not yet convert all lockfile users—only those that already accept a `struct repository *` parameter—so future patches will likely extend this pattern.
