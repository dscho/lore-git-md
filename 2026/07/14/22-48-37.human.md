This is a test patch, part of Johannes Schindelin’s 11-patch series fixing unchecked return values flagged by Coverity. It is the fourth patch in the series (4/11).

The patch plugs a small but real gap in the reftable unit tests: two test functions (`test_reftable_table__seek_once` and `test_reftable_table__reseek`) call `reftable_table_init_ref_iterator` without checking its return code. Every other reftable function call in the same file already checks its return value, so this omission is inconsistent and could mask initialization failures. The fix is mechanical—wrap the call in `cl_assert_equal_i(ret, 0)`—and matches the surrounding style.

The change is uncontroversial and clearly motivated. It does not alter any production code, only the test suite, so there is no risk of regressing user-facing behavior. The commit message is concise and names the specific function and test file, making it easy for reviewers to verify the context. If the series as a whole lands, this patch will quietly improve test robustness without drawing further attention.
