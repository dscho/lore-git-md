This is the v19 submission of Harald Nordgren’s `git branch --delete-merged` series, now **implementation-complete** and addressing all remaining mechanical issues identified in v18. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including per-branch opt-out, `--dry-run` preview, and refined stacked-branch protection (abort-and-clear). This version resolves the last pre-merge blockers: a bug where `--dry-run` incorrectly removed config, redundant flags handling, and test assertions.

Key changes in v19:
1. **Fixed `--dry-run` bug**: The command no longer modifies config during dry runs (e.g., clearing upstreams for spared branches). Added test coverage to verify this.
2. **Redesigned `--delete-merged` as a repeatable upstream selector**: The option can now be specified multiple times (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the upstream match, while optional positional patterns (e.g., `topic-*`) limit deletion scope. This addresses usability feedback from Phillip Wood.
3. **Simplified flags handling**: Eliminated local boolean caching in `delete_branches()` to ensure flags remain the single source of truth, resolving the maintenance risk noted in v18.
4. **Improved safety checks**: Branches are now protected if pushing them by name would update their upstream (e.g., `main` tracking `origin/main`), regardless of `remote.pushDefault` configuration. This fixes an edge case where branches without explicit `branch.<name>.pushRemote` could be misclassified as forked.
5. **Test refinements**: Clarified assertions, renamed helpers for readability (e.g., `create_merged_branch`), and added explicit `branch.main.pushRemote` configuration to prevent false positives in `--forked` filtering.

The series is now **ready for merging** with no known issues. All design questions (stacked-branch protection, per-branch opt-out, `--forked` filter edge cases) have been resolved, and the implementation aligns with Git’s API consistency expectations. The only follow-up work agreed upon is extending stacked-branch protection to `git branch -d` for consistency, as requested by Junio C Hamano.

**Technical details**:
- **Core behavior**: Deletes local branches whose tip is reachable from their upstream (matching one of the `--delete-merged` arguments) and whose push destination differs from their upstream. Supports glob patterns for both upstreams and local branches.
- **Safety mechanisms**: Skips checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`.
- **Stacked-branch protection**: Fails to delete a branch if it is used as an upstream for an unmerged branch, but clears the upstream config for kept (merged) branches whose own upstream is being deleted. This avoids broken dependency chains while cleaning up stale configs.
- **`--dry-run`**: Prints "Would delete branch <name>" for each affected branch without modifying refs or config. Rejects the nonsensical `--dry-run --quiet` combination.
- **Test coverage**: Comprehensive integration tests verify all safety checks, edge cases (e.g., self-referential upstreams, missing upstreams), and the new repeatable upstream selector behavior.

The series is **well-motivated** (addressing a real workflow pain point) and **thoroughly tested**, with clear documentation and a flags-based API designed for future extensibility. The v19 changes are mechanical and do not alter the core logic or safety guarantees.
