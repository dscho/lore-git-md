This is the final patch in the v7 series refining Rust build integration for the macOS credential helper (`git-credential-osxkeychain`). The patch wires up the helper in `contrib/Makefile` so it is built and tested in CI when `TEST_CONTRIB_TOO=yes` is set on macOS. This completes the series by ensuring the helper is included in standard CI runs, addressing a gap in verification for Rust-dependent contrib utilities.

The change is small and targeted: it adds `git-credential-osxkeychain` to the `OS_CONTRIB` variable in `contrib/Makefile`, which controls which contrib utilities are built on macOS. The patch also fixes a build system correctness issue Junio identified in the v6 iteration—missing the `config.mak.uname` include, which defines `uname_S` and ensures the `ifeq ($(uname_S),Darwin)` conditional works as intended. Without this include, the helper would not be built on macOS even when Rust is enabled. The fix aligns the include order with the top-level `Makefile`, following the same sequence (`config.mak.uname`, `config.mak.autogen`, `config.mak`).

This patch is part of a three-patch series that has already resolved its blocking issues (parallel build race condition, Universal Binary support, and CI verification). The v6 series is queued in Junio’s integration branches and is effectively under review, with graduation to `next` likely in the current cycle. The v7 series is functionally identical to v6 and exists only to address Junio’s feedback on the include order; no further changes are expected.

The patch is well-motivated and uncontroversial. It touches only `contrib/Makefile` and introduces no new behavior beyond ensuring the macOS credential helper is tested in CI. The fix is platform-specific (macOS-only) and has no impact when `NO_RUST=1` is set or on non-macOS platforms. No new tests are introduced, but the change is implicitly covered by existing build tests and CI runs. The patch is ready for integration and should proceed without further discussion.
