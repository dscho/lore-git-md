This is a **performance bugfix** for `unpack-trees.c` that addresses a quadratic-time index scan in `next_cache_entry()`. The patch is now in its second iteration, responding to Junio’s **substantive review** that raised a critical correctness concern about the interaction between the new forward-scan optimization (`cache_bottom`) and the existing backward-scan logic (`.cache_bottom`), which was designed to handle index/tree ordering mismatches.

Henrique’s reply argues that the optimization is safe because `.cache_bottom` already tracks the first entry needing processing, and `find_cache_pos()` advances it past unpacked entries (citing commit `e53e6b4433`). This directly addresses Junio’s concern, though the thread remains open pending further review or testing to confirm the fix doesn’t break ordering invariants. The patch itself is minimal (4 lines) and includes a thorough perf test (`t/perf/p0009-diff-pathspec.sh`), which Junio suggested improving by making the entry count (`100000`) configurable via the `EXPENSIVE` prerequisite—a surface-level tweak Henrique has not yet incorporated.
