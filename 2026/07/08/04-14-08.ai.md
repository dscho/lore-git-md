This is patch 7/11 in the v2 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch makes a targeted mechanical change: it modifies `odb_transaction_commit()` and its backend callback to return an `int` error code instead of `void`, so backends can signal commit failures (e.g., when the "files" backend cannot migrate its temporary object directory into the permanent ODB). The change is purely about error propagation—no behavior is altered, and the function still treats a `NULL` transaction as a no-op.

The patch touches only two files: `odb/transaction.c` (13 lines) and `odb/transaction.h` (7 lines). The diff is straightforward: the commit callback now returns an `int`, and `odb_transaction_commit()` forwards that value to its caller. This is part of the series' broader effort to surface previously ignored errors (patches 5–6/11 address similar gaps in `prepare`/`begin`/`commit` and backend initialization).

The motivation is clear: `git-receive-pack` (converted in a later patch) needs to handle commit failures gracefully, and the current `void` return type makes that impossible. The change is uncontroversial and aligns with the series' goal of robust error handling. No test coverage is added here, but the existing test suite will exercise the updated interface once the full series lands. This patch is a prerequisite for the behavioral changes in patches 8–11/11.
