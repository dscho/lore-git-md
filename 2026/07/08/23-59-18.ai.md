This is patch 4/11 in the v3 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch removes redundant validation from the "files" backend (`odb_transaction_files_begin()`) that duplicated the same check already performed by the generic `odb_transaction_begin()` layer.

The change is a mechanical simplification: the generic ODB layer already enforces the "only one transaction per ODB" rule, so the "files" backend no longer needs to repeat it. The commit message is clear and the diff is minimal (4 lines removed, 1 line updated in the header comment). Patrick Steinhardt, the ODB subsystem owner, explicitly endorsed this change in earlier review as fixing a layering violation. No behavioral change is introduced; the patch is purely about code organization.

This is part of the larger ODB abstraction effort led by Patrick Steinhardt. The series as a whole is functionally complete, with all feedback from v1 and v2 addressed, and is queued for `next` pending integration. The only remaining open items are deferred to follow-up work (a latent transaction-leak in `odb_transaction_commit()` and a header dependency concern). This patch itself has no unresolved feedback.
