This is a **performance bugfix** for the `unpack-trees` subsystem, specifically addressing a quadratic-time index scan in `next_cache_entry()`. The patch is now **technically complete and ready for merge** after incorporating all review feedback from Junio.

The core issue occurs when running `git diff` with a pathspec matching a subtree whose entries appear early in the index. The fix introduces a `cache_bottom` field in `o->internal` to track forward-scan progress, allowing subsequent calls to skip already-unpacked entries. The optimization is minimal (4 lines in `unpack-trees.c`) and preserves existing ordering invariants, as confirmed by Junio's review.

Performance impact is dramatic: on a Chromium-scale repository (~500k index entries), `git diff HEAD -- .agents/OWNERS` improves from **8 minutes to 0.07 seconds**. The regression test (`t/perf/p0009-diff-pathspec.sh`) now scales entry count via the `EXPENSIVE` prerequisite (10,000 entries by default, 100,000 when enabled), showing a **99.7% speedup** in the perf test.
