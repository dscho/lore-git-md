Subject: [PATCH] submodule--helper: restore `-i` shorthand for `--init` in `git submodule update`
Series version: standalone patch
Originating author: Dominique Martinet
Thread type: bugfix patch

Core problem or goal
Restore support for the `-i` shorthand flag in `git submodule update`, which regressed in Git v2.49 due to commit 3ad0ba722744 ("git-submodule.sh: improve variables readability"). The shell script still passes `-i` to `submodule--helper`, but the helper no longer recognizes it, breaking the command-line interface.

Current status
**Accepted for application.** Junio C Hamano has endorsed the patch and will apply it. The fix is a minimal, targeted one-line addition to the `module_update_options` array in `builtin/submodule--helper.c` to alias `'i'` to `--init`. The regression is confirmed, and the approach is uncontroversial.

Key technical details
- Files touched: `builtin/submodule--helper.c`
- Symbols: `module_update_options` array (adds `'i'` as an alias for `--init`)
- Behavior: Restores pre-v2.49 CLI behavior for `git submodule update -i`
- Test coverage: None added; relies on existing tests for `submodule update`
- On-disk format: No changes

Open questions and loose ends
None. The patch is complete, self-contained, and accepted.

Participant positions
- Dominique Martinet (author): Proposed the fix, arguing it is justified for consistency even though the option is undocumented, as it previously worked. Included a `Fixes:` trailer for the regressing commit.
- Junio C Hamano (maintainer): **Endorsed the patch** after briefly considering an alternative (modifying the shell script to pass `--init` instead of `-i`). Concluded that teaching `submodule--helper` to recognize the short option is cleaner, as users should not invoke the helper directly. The thread is now closed.

Related work
None. This is a standalone regression fix.
