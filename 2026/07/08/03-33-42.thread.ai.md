Subject: [PATCH] submodule--helper: restore `-i` shorthand for `--init` in `git submodule update`
Series version: standalone patch
Originating author: Dominique Martinet
Thread type: bugfix patch

Core problem or goal
Restore support for the `-i` shorthand flag in `git submodule update`, which regressed in Git v2.49 due to commit 3ad0ba722744 ("git-submodule.sh: improve variables readability"). The shell script still passes `-i` to `submodule--helper`, but the helper no longer recognizes it, breaking the command-line interface.

Current status
Under review. The patch is a minimal, targeted fix: a one-line addition to the `module_update_options` array in `builtin/submodule--helper.c` to alias `'i'` to `--init`. The change is uncontroversial and addresses a clear regression, though the practical impact is limited because the `-i` option is undocumented.

Key technical details
- Files touched: `builtin/submodule--helper.c`
- Symbols: `module_update_options` array (adds `'i'` as an alias for `--init`)
- Behavior: Restores pre-v2.49 CLI behavior for `git submodule update -i`
- Test coverage: None added; the patch relies on existing tests for `submodule update`
- On-disk format: No changes

Open questions and loose ends
None identified. The patch is complete and self-contained.

Participant positions
- Dominique Martinet (author): Argues the fix is justified for consistency, even though the option is undocumented, because it previously worked. Includes a `Fixes:` trailer for the regressing commit.
