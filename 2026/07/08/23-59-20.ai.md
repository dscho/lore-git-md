This is patch 6/11 in the v3 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch refactors `odb_transaction_begin()` to return an error code and write the transaction into an out-parameter, replacing the old behavior of returning the transaction pointer directly. A convenience wrapper `odb_transaction_begin_or_die()` is added for call sites that don’t need explicit error handling.

The change is a mechanical error-propagation improvement with no behavioral impact. The patch updates all call sites (in `builtin/add.c`, `builtin/unpack-objects.c`, `builtin/update-index.c`, `cache-tree.c`, `object-file.c`, and `read-cache.c`) to use the new interface. Notably, `cache_tree_update()` and `add_files_to_cache()` now check for an existing inflight transaction before starting a new one, avoiding redundant transactions. Patrick Steinhardt, the ODB subsystem owner, previously called this change "very much welcome" and noted it results in "much saner behaviour with less surprises."

The diff shows the new interface in action: `odb_transaction_begin()` now returns an `int` and takes a double pointer for the transaction, while the wrapper `odb_transaction_begin_or_die()` handles fatal errors. The patch also removes an unnecessary inclusion of `git-compat-util.h` from `odb/transaction.h` (a style nit resolved from v2 feedback). No open questions remain for this patch; it is ready for integration.
