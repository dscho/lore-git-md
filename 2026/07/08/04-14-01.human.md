This is the v2 submission of a refactoring series that replaces `tmp_objdir` usage in `git-receive-pack` with the newer `odb_transaction` subsystem. The goal is to make `receive-pack` ODB-backend-agnostic, though the actual object writes remain tied to the "files" backend for now (handled by child processes like `git-index-pack` and `git-unpack-objects`). This is part of the broader ODB abstraction effort led by Patrick Steinhardt.

The series has grown from 6 to 11 patches, reflecting feedback from the v1 review. Key changes include:
- Renaming and consolidating transaction-related functions for consistency (e.g., `flush_loose_object_transaction` → `odb_transaction_files_flush`).
- Propagating error codes through the transaction lifecycle, ensuring failures in `begin`, `commit`, and environment setup are surfaced rather than silently ignored.
- Introducing `ODB_TRANSACTION_RECEIVE` flags to handle `receive-pack`'s specific needs (eager directory creation, "incoming" prefix naming).
- Splitting the final patch into smaller, more focused commits (e.g., flag introduction vs. application in `receive-pack`).
- Using a file-local global variable in `builtin/receive-pack.c` to pass the transaction parameter consistently, avoiding churn.

The series touches 14 files, with the heaviest changes in `object-file.c` (159 lines) and `builtin/receive-pack.c` (69 lines). New interfaces like `odb_transaction_env()` (now using `struct strvec`) and `odb_transaction_begin_or_die()` improve ergonomics and error handling. The commit messages are clear, and the changes appear mechanical but well-motivated, with no user-facing behavior changes.

This looks like a solid, uncontroversial refactoring. The v1 feedback was substantive but constructive, and the v2 addresses all blocking issues while deferring follow-up work (e.g., error-handling improvements, lazy directory creation) to future series. The series is queued for `next` and should merge smoothly. If you care about ODB abstraction or `receive-pack` internals, this is worth a closer look.
