This is the second patch in a three-patch bugfix series targeting race conditions in Git's HTTP daemon test helpers. The series addresses a latent concurrency issue in the test infrastructure (`t/lib-httpd/`) where two CGI scripts—`apply-one-time-script.sh` (fixed in patch 1) and `http-429.sh` (this patch)—use non-atomic shell operations (`test -f` followed by `touch` or `rm`) to manage shared state in `HTTPD_ROOT_PATH`. Because Apache serves requests concurrently, and a single Git operation can open multiple requests to the same endpoint (e.g., a partial fetch that lazily retrieves a promisor object), these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, causing an HTTP 500 error.

Patch 2 replaces the non-atomic check in `http-429.sh` with an atomic `mkdir` operation, which fails if the directory already exists. This ensures that exactly one of any concurrent requests is rate-limited (returning HTTP 429), while the rest are forwarded to `git-http-backend`. The change is minimal and targeted, touching only the state-management logic in `http-429.sh` without altering its behavior under sequential execution. Unlike patch 1, which included a new test to deterministically reproduce the race, this patch does not add a regression test. The commit message explains that the race cannot be forced deterministically because the check and set are adjacent commands with no external synchronization point, making the fix preventive rather than curative.

The patch is well-motivated and clearly explained. The atomic `mkdir` idiom is a standard shell pattern for this kind of concurrency problem, and the commit message links it to the broader fix in patch 1. The changes are confined to the test infrastructure and do not affect user-visible behavior or on-disk formats. The series as a whole (including this patch) looks like a clean, uncontroversial fix for a real, if narrow, problem in the test suite. The absence of a regression test for this specific script is understandable given the difficulty of forcing the race, though the new test in patch 1 already covers the general pattern. The patch is unlikely to draw significant discussion, as the fix is mechanical and the motivation is concrete.
