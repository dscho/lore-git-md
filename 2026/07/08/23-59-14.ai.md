This is the v3 submission of a refactoring series that replaces `tmp_objdir` usage in `git-receive-pack` with the ODB transaction subsystem, advancing the ODB abstraction effort led by Patrick Steinhardt. The series is functionally complete: all 11 patches are reviewed, integrated, and ready for `next`. This version picks up Reviewed-by trailers and minor wording tweaks; there are no code changes from v2.

The goal is to make `git-receive-pack` ODB-backend-agnostic by staging incoming objects via transactions rather than temporary object directories. The series preserves existing behavior (objects staged in an "incoming" directory, migrated to the main object store after pre-receive hooks and connectivity checks) while replacing the underlying mechanism. Key interfaces (`odb_transaction_begin`, `odb_transaction_commit`, `odb_transaction_env`) now return `int` for error propagation, and a new `ODB_TRANSACTION_RECEIVE` flag maintains `receive-pack`'s eager directory creation and naming conventions during the transition.

Two deferred issues remain: a latent transaction-leak in `odb_transaction_commit` (freed before returning backend errors) and a header dependency concern (`odb/transaction.h` vs `odb/source.h`). Both are acknowledged and slated for follow-up work. The series touches 14 files, with the heaviest changes in `object-file.c` (159 lines) and `builtin/receive-pack.c` (69 lines). Test coverage relies on the existing test suite, which exercises `receive-pack` and its child processes (`git-index-pack`, `git-unpack-objects`).

The author, Justin Tobler, has addressed all feedback from v1 and v2, including mechanical cleanups (indirection reduction, redundant validation removal), error propagation improvements, and plumbing for environment-variable inheritance. Patrick Steinhardt, the ODB subsystem owner, signaled strong approval in his v2 reply: "I've got a couple smaller nits, but overall I'm quite happy with the shape of this series now." The series is queued for `next` pending integration.
