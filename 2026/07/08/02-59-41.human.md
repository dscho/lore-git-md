This is the first patch in a three-part bugfix series targeting race conditions in Git’s HTTP daemon test helpers. It fixes a concurrency issue in `t/lib-httpd/apply-one-time-script.sh`, where non-atomic shell operations (`test -f` followed by `rm`) could cause Apache to serve an HTTP 500 error when handling concurrent requests. The problem was observed as a flaky failure in `t5616.47` on macOS CI runners, where a partial fetch would lazily retrieve a promisor object while the first response was still in flight, triggering the race.

The fix replaces the non-atomic check-and-remove sequence with an atomic `mv` operation to claim the "one-time-script" marker. This ensures that only one request can successfully claim the marker, while others fall back to serving the unmodified response. The patch also introduces per-request scratch files (named with `$$`) to prevent concurrent requests from clobbering each other’s output. The changes are minimal and preserve the script’s behavior under sequential execution.

A new test, `t5567-one-time-script.sh`, is added to lock down the fix. Unlike the flaky `t5616.47`, this test directly exercises the helper without a web server, using FIFOs to force the race deterministically. The test verifies that neither request emits an empty body (which would trigger HTTP 500) and that each request plays its intended role: one rewrites its response, and the other passes through unchanged. The test is well-structured and provides a clear reproduction of the bug.

The patch is narrowly scoped, addressing only the concurrency issue in the test helper. The commit message is detailed, explaining the problem, the fix, and the reproduction case. The changes are mechanical and unlikely to be controversial, as they target a real, observed flake in the test suite. The new test is a strong addition, as it provides a deterministic way to verify the fix. This patch is well-crafted and ready for review.
