This is the first patch in a four-part bugfix series that has already been merged, now addressing a follow-up issue in test prerequisites. The patch ensures the `t1517-outside-repo.sh` test script correctly skips Subversion-related tests when the SVN Perl modules are not installed, rather than failing them.

The change adds a new `SVN` test prerequisite that checks for the presence of `SVN::Core` and `SVN::Repos` Perl modules, mirroring the approach used in `t/lib-git-svn.sh`. This is necessary because the upcoming exit-code standardization for `--help` flags (implemented in later patches) will cause `git-svn` to exit 0 when given `--help`, whereas the tests currently expect it to fail. Without this prerequisite, tests would incorrectly pass or fail depending on whether SVN modules are available, rather than reflecting the intended behavior.

The patch is minimal and targeted: it modifies only `t/t1517-outside-repo.sh`, adding the prerequisite check and updating the command loop to use it for `svn` commands. This resolves the shell-quoting and version-checking issues identified in earlier iterations of the series, simplifying the prerequisite logic to focus solely on module availability. The fix is uncontroversial and aligns with the project's test infrastructure conventions.
