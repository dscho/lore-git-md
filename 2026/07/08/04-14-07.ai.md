This is the sixth patch in Justin Tobler’s v2 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch refactors `odb_transaction_begin()` to return an error code and write the transaction into an out-parameter, replacing the old behavior of returning the transaction pointer directly. A convenience wrapper, `odb_transaction_begin_or_die()`, is added for call sites that don’t need to handle errors explicitly.

The change is mechanical but important: it propagates errors from the backend (e.g., failure to create a temporary object directory) to callers, which is critical for `git-receive-pack` in a later patch. The patch updates all existing call sites to handle the new return value, either by using the `_or_die` wrapper or by explicitly checking for an inflight transaction (a new error case). Files touched include `builtin/add.c`, `builtin/unpack-objects.c`, `builtin/update-index.c`, `cache-tree.c`, `object-file.c`, `odb/transaction.c`, `odb/transaction.h`, and `read-cache.c`.

No behavioral changes are introduced—this is purely an error-handling improvement. The patch is part of the ODB abstraction effort and depends on earlier patches in the series. All feedback from v1 has been addressed, and the series is queued for `next`. The change is uncontroversial and aligns with the goal of making the ODB transaction layer more robust.
