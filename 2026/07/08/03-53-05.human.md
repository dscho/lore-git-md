This is the final patch in Jeff King’s seven-part series refactoring the `git_hash_*()` API. It adds defensive runtime checks to all wrapper functions to catch misuse early, ensuring consistent behavior across all hash backends. The patch targets the core hash subsystem, specifically `hash.c`, and introduces no user-visible changes—its purpose is purely internal robustness.

The patch enforces that `git_hash_update()`, `git_hash_clone()`, `git_hash_final()`, and `git_hash_final_oid()` can only be called on an active (initialized but not yet finalized or discarded) hash context. Violations trigger a `BUG()`, replacing the previous behavior where some backends (like sha1dc) would silently produce nonsense output while others (like OpenSSL) would invoke undefined behavior. This aligns with the series’ goal of standardizing the API and eliminating subtle footguns.

Notably, `git_hash_init()` and `git_hash_discard()` are exempted from these checks. The former cannot be validated because the context’s contents are undefined before initialization, and the latter is intentionally idempotent (a key improvement introduced earlier in the series). The commit message also explains why `git_hash_final()` is not made idempotent: double-calling it is likely a bug, and the current design (triggering a `BUG()`) is preferable to silently producing incorrect hashes.

The patch is small (10 lines added) and mechanical, adding guard clauses to each wrapper function. It complements the earlier patches by providing runtime enforcement of the invariants established in the series, while the Coccinelle semantic patch (introduced in patch 1) ensures compile-time consistency. All review feedback has been addressed, and the series is now ready for integration. This patch is a fitting capstone—it doesn’t change behavior but hardens the API against misuse, a hallmark of Peff’s meticulous approach.
