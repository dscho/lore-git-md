This is the first patch in Jeff King’s v2 seven-patch series refactoring the `git_hash_*()` API. It establishes the foundation for the rest of the series by enforcing consistent use of the `git_hash_init()` wrapper instead of direct calls to `algop->init_fn()`.

The patch is purely mechanical: it replaces every direct call to `the_hash_algo->init_fn(&ctx)` with `git_hash_init(&ctx, the_hash_algo)` across 21 files. The changes touch core object-writing code (`csum-file.c`, `object-file.c`, `hash.c`), built-ins (`fast-import`, `index-pack`, `receive-pack`, `submodule--helper`), test helpers, and even the Coccinelle tooling itself. A new semantic patch (`tools/coccinelle/hash.cocci`) is added to prevent regressions by catching any future direct `init_fn()` calls at compile time.

No behavior changes are introduced; this is a refactoring step that prepares the codebase for the more substantive changes in later patches (notably making `git_hash_discard()` idempotent). The patch is well-motivated, with a clear commit message explaining the goal of standardizing the API usage. The Coccinelle rule ensures the change is both thorough and maintainable. No objections remain after v1 feedback was addressed.
