This is part 8 of the v8 series migrating global configuration variables into `struct repo_config_values`. The patch moves the `autorebase` enum (which controls whether newly created branches automatically rebase by default) from a global variable into the per-repository configuration structure.

The change is mechanical and follows the established pattern: the `enum rebase_setup_type` definition is relocated in `environment.h` to make it visible to `struct repo_config_values`, the global `autorebase` variable is removed, and all accesses are updated to use `repo_config_values(the_repository)->autorebase`. The default value `AUTOREBASE_NEVER` is initialized in `repo_config_values_init()`. The only caller affected is `should_setup_rebase()` in `branch.c`, which now reads the value from the repository-specific structure instead of the global.

No memory management concerns apply here (unlike the string-valued fields in earlier patches), and the patch is CI-clean. The relocation of the enum is necessary to avoid circular dependencies and aligns with the series' goal of eliminating globals. This is a straightforward refactoring step in the ongoing libification effort, with no user-visible behavior changes. The patch is ready for integration once the series as a whole lands.
