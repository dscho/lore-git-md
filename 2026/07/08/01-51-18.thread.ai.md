Subject: [PATCH] merge --abort: preserve autostash on reset failure
Series version: standalone patch (no series)
Originating author: Kris Point
Thread type: bug report / bugfix patch

Core problem or goal
When `git merge --abort` fails (e.g., due to a locked index), the autostash created by `merge --autostash` is permanently lost because the `MERGE_AUTOSTASH` ref is deleted before `git reset --merge` is attempted. The goal is to prevent this data loss by deferring deletion of the autostash until after the reset succeeds.

Current status
Under review. The patch is a single, narrowly scoped bugfix with no prior versions. The author (Kris Point) considers it ready, but Phillip Wood has identified a design flaw in the proposed solution and proposed an alternative approach involving decoupling reset logic and introducing a new flag (`RESET_WORKING_TREE_MERGE`) to `reset_working_tree()` or `reset_head()`. No maintainer decision or merge status has been recorded yet.

Key technical details
- File touched: `builtin/merge.c`
- New behavior (proposed in patch): `MERGE_AUTOSTASH` ref is read without being deleted upfront; `cmd_reset()` is responsible for merge state cleanup (including persisting the autostash); the autostash is only applied if the reset succeeds.
- Flaw in proposed behavior: The patch would unconditionally save the autostash even if it applies cleanly (which should not happen), and if the reset fails, the autostash would still be saved rather than preserved in the merge state.
- Correct behavior (per Phillip Wood): The autostash should only be saved if conflicts arise during application, and merge state should persist if the reset fails.
- Alternative approach: Decouple reset logic from `cmd_reset()` and introduce a new flag (`RESET_WORKING_TREE_MERGE`) to `reset_working_tree()` or `reset_head()` (target branch: `ps/history-drop` in `seen`).
- No new symbols, CLI options, or on-disk format changes introduced by the patch.
- Test coverage: Implied manual testing by the author; no new test file mentioned. The reviewer’s alternative approach may require additional test coverage for edge cases.
