Subject: [PATCH] merge --abort: preserve autostash on reset failure
Series version: standalone patch (no series)
Originating author: Kris Point
Thread type: bug report / bugfix patch

Core problem or goal
When `git merge --abort` fails (e.g., due to a locked index), the autostash created by `merge --autostash` is permanently lost because the `MERGE_AUTOSTASH` ref is deleted before `git reset --merge` is attempted. The goal is to prevent this data loss by deferring deletion of the autostash until after the reset succeeds.

Current status
Under review. The patch is a single, narrowly scoped bugfix with no prior versions. No maintainer decision or merge status has been recorded yet.

Key technical details
- File touched: `builtin/merge.c`
- New behavior: `MERGE_AUTOSTASH` ref is read without being deleted upfront; `cmd_reset()` is responsible for merge state cleanup (including persisting the autostash); the autostash is only applied if the reset succeeds.
- Old behavior: `MERGE_AUTOSTASH` ref was deleted before `cmd_reset()` was called, risking permanent loss if the reset failed.
