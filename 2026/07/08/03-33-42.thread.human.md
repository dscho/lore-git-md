This thread is about a small but clear regression fix in Git's submodule handling. The `-i` shorthand for `git submodule update --init` stopped working in Git v2.49 due to a cleanup commit that improved variable readability in the shell script but didn't account for the short option in the helper. Dominique Martinet sent a one-line patch to restore the alias in `submodule--helper.c`, and Junio Hamano, the maintainer, has now accepted it.

The fix is uncontroversial and targeted: it simply adds `'i'` as an alias for `--init` in the `module_update_options` array. While the `-i` option is undocumented, it previously worked, and the patch restores that behavior without any side effects. Junio briefly considered an alternative—modifying the shell script to pass `--init` instead—but decided the current approach was cleaner, since users shouldn't be calling `submodule--helper` directly anyway.

The patch will be applied shortly, and no further discussion or changes are needed. The thread is now closed.
