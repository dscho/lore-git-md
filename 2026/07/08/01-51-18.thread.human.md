This thread is about a small but important bugfix to `git merge --abort`. Kris Point identified a data-loss edge case: when `merge --autostash` is used, the autostash is deleted before `git reset --merge` runs, so if the reset fails (for example, because the index is locked), the stash is lost permanently. The patch modifies `builtin/merge.c` to read the `MERGE_AUTOSTASH` ref without deleting it upfront, lets `cmd_reset()` handle the merge state cleanup (which includes persisting the autostash), and only applies the autostash if the reset succeeds.

The fix is narrowly scoped—just five insertions and six deletions—and follows Git's coding conventions. The commit message clearly explains the problem, the solution, and the reasoning. Kris reports having tested the change, and the submission itself shows no signs of controversy. This looks like a straightforward, well-motivated bugfix that should be uncontroversial. No reviews or maintainer decisions have appeared yet, so the patch is still under initial consideration.
