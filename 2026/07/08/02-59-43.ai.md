This is the third and final patch in a three-patch series fixing race conditions in Git’s HTTP daemon test helpers. The series targets a real, observed flake in the test suite (`t5616.47`) where concurrent HTTP requests to the same CGI script caused HTTP 500 errors due to non-atomic file operations.

This patch adds a new section to `t/README` titled "Writing concurrency-safe helpers," documenting the atomic idioms introduced in the earlier patches. It explains the problem (concurrent processes cannot assume exclusive file access), the anti-pattern (`test -f` followed by `rm` or `touch`), and the two safe operations: `mkdir` for electing a single "winner" among concurrent requests, and `mv` (rename) for consuming a one-shot marker. The section also notes the use of `$$` suffixes to prevent clobbering of scratch files and links the idioms to Git’s own lockfile machinery (`O_CREAT|O_EXCL`) and `make_symlink()` in `t/test-lib.sh` as precedents. A brief pointer is added to `t/lib-httpd.sh` to direct readers to the new documentation.

The patch is purely documentation and does not change any code behavior. It is a natural follow-up to the earlier fixes, generalizing the pattern for future test helpers and making the rationale explicit. The addition is well-placed in `t/README`, which already serves as the primary guide for test authors, and the cross-reference in `t/lib-httpd.sh` ensures visibility for HTTP-specific helpers. The documentation is clear, concise, and grounded in real examples from the series, making it immediately useful for contributors writing concurrent test code. No controversy or open questions are apparent; this is a straightforward, well-motivated addition.
