This is patch 5/11 in the v2 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch makes the "files" transaction backend propagate errors from its internal operations (`prepare`, `begin`, `commit`) rather than silently ignoring them.

The changes are mechanical but important for robustness: the three core transaction interfaces (`odb_transaction_files_prepare`, `odb_transaction_files_begin`, `odb_transaction_files_commit`) are converted from `void` to `int` return types, and callers are updated to check for failures. The patch touches four files: `object-file.c` (26 lines, the bulk of the work), `object-file.h` (3 lines), `odb/source-files.c` (6 lines), and `odb/transaction.h` (7 lines). No behavior changes are introduced—this is purely about surfacing errors that were previously swallowed.

The patch is well-scoped and clearly motivated: it addresses a latent issue (silent failures in transaction setup) that was noted in the v1 review but deferred to keep the series focused. The commit message is concise and accurate, and the code changes are straightforward. This is a solid, uncontroversial step in the ODB abstraction effort.
