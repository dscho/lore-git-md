This is a refactoring patch in the ongoing ODB abstraction effort, specifically part of Justin Tobler’s series to replace `tmp_objdir` usage in `git-receive-pack` with ODB transactions. This is patch 3 of 11 in v2, which has already addressed all feedback from v1 and is queued for `next`.

The patch eliminates the standalone `flush_loose_object_transaction()` helper by embedding its logic directly into `odb_transaction_files_commit()`. The change is purely mechanical: the same hardware-flush barrier and temporary-directory migration that were previously in a separate function are now inlined at the end of the commit function. The commit message explains the motivation clearly—consolidating related logic rather than maintaining a separate helper—and the diff confirms that behavior is unchanged. The patch touches only `object-file.c` and removes 36 lines while adding 28, a net reduction that reflects the cleanup.

This is a small but sensible step in the larger transaction refactoring. The inlining makes the control flow easier to follow, and the commit message’s explanation of the hardware-flush barrier is a nice touch for future readers. No new edge cases or error paths are introduced, and the patch preserves the existing durability guarantees.
