Subject: [PATCH 0/3] Fix race conditions in HTTP daemon test helpers
Series version: v1
Originating author: Michael Montalbo (via GitGitGadget)
Thread type: patch series (bugfix)

Core problem or goal
Two CGI scripts in `t/lib-httpd/` (`apply-one-time-script.sh` and `http-429.sh`) use non-atomic shell operations (`test -f` followed by `rm` or `touch`) to manage shared state in `HTTPD_ROOT_PATH`. Because Apache serves requests concurrently and a single Git operation can open multiple requests to the same endpoint (e.g., a partial fetch that lazily retrieves a promisor object while the first response is still being served), these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, causing an HTTP 500 error. The series replaces the non-atomic checks with atomic operations (`mv` for the one-shot marker in `apply-one-time-script.sh`, `mkdir` for the first-request election in `http-429.sh`) to eliminate the race.

Current status
Under review; no prior versions. The series is self-contained and targets only the test infrastructure (`t/` directory). The motivation is a real, observed flake in `t5616.47` on macOS CI runners, where the race caused a fetch to fail with an HTTP 500 error. All three patches have now been posted; no responses or reviews have been recorded yet.

Key technical details
- Files touched: `t/lib-httpd/apply-one-time-script.sh`, `t/lib-httpd/http-429.sh`, `t/t5567-one-time-script.sh` (new), `t/README`.
- New test: `t5567-one-time-script.sh` exercises the `apply-one-time-script.sh` helper without a web server, using FIFOs to force the race deterministically. The test confirms that neither request emits an empty body (which would trigger HTTP 500) and that each behaves as expected: the modifying request rewrites its response, while the passthrough request remains unchanged.
- Atomic idioms: `mv` for one-shot markers (patch 1), `mkdir` for first-request election (patch 2). Patch 3 documents these idioms in `t/README`, explaining the problem, the anti-pattern, and the safe alternatives, with cross-references to Git’s lockfile machinery (`O_CREAT|O_EXCL`) and `make_symlink()` in `t/test-lib.sh` as precedents. Per-request scratch files use `$$` suffixes to prevent clobbering.
- No changes to on-disk formats, CLI options, or user-visible behavior; the fixes are purely internal to the test helpers.
- Patch 2 does not include a regression test for `http-429.sh` because the race cannot be forced deterministically (the check and set are adjacent commands with no external synchronization point), making the fix preventive rather than curative.
