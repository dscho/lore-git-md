Core problem or goal
Two CGI scripts in `t/lib-httpd/` (`apply-one-time-script.sh` and `http-429.sh`) use non-atomic shell operations (`test -f` followed by `rm` or `touch`) to manage shared state in `HTTPD_ROOT_PATH`. Because Apache serves requests concurrently and a single Git operation can open multiple requests to the same endpoint (e.g., a partial fetch that lazily retrieves a promisor object while the first response is still being served), these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, causing an HTTP 500 error. The series replaces the non-atomic checks with atomic operations (`mv` for the one-shot marker in `apply-one-time-script.sh`, `mkdir` for the first-request election in `http-429.sh`) to eliminate the race. The goal is to make the test helpers robust against concurrent execution, not to prevent the scripts from running multiple times (which is safe).

Key technical details
- Files touched: `t/lib-httpd/apply-one-time-script.sh`, `t/lib-httpd/http-429.sh`, `t/t5567-one-time-script.sh` (new), `t/README`, `t/lib-httpd.sh` (brief pointer).
- New test: `t5567-one-time-script.sh` exercises `apply-one-time-script.sh` without a web server, using FIFOs to force the race deterministically. Confirms neither request emits an empty body (which would trigger HTTP 500) and each behaves as expected: the modifying request rewrites its response, while the passthrough request remains unchanged.
- Atomic idioms: `mv` for one-shot markers (patch 1), `mkdir` for first-request election (patch 2), and `rm` (without `-f`) as an atomic alternative to `mv` for consuming one-shot markers (patch 3). Patch 3 documents these idioms in `t/README`, explaining the problem, the anti-pattern, and the safe alternatives, with cross-references to Git’s lockfile machinery (`O_CREAT|O_EXCL`) and `make_symlink()` in `t/test-lib.sh` as precedents. Per-request scratch files use `$$` suffixes (process IDs) to prevent clobbering.
- Error handling change: patch 1’s v2 redirects `stderr` of `./one-time-script` to `/dev/null` to suppress an expected error when the script is removed by a concurrent request. This is now documented in the thread and will be documented in the code with a comment. The change does not mask legitimate errors from the script itself.
- Documentation updates: patch 3’s v2 incorporates Patrick Steinhardt’s editorial suggestions: the section header now reads "Writing concurrency-safe helpers for `lib-httpd`" (with a note that the advice applies broadly), the note about `rm` (without `-f`) as an atomic alternative to `mv` for consuming one-shot markers is included, and the shell variable `$$` is explicitly described as the process ID (PID).
- No changes to on-disk formats, CLI options, or user-visible behavior; the fixes are purely internal to the test helpers.
- Patch 2 does not include a regression test for `http-429.sh` because the race cannot be forced deterministically (the check and set are adjacent commands with no external synchronization point), making the fix preventive rather than curative.
