Core problem or goal
Two CGI scripts in `t/lib-httpd/` (`apply-one-time-script.sh` and `http-429.sh`) use non-atomic shell operations (`test -f` followed by `rm` or `touch`) to manage shared state in `HTTPD_ROOT_PATH`. Because Apache serves requests concurrently and a single Git operation can open multiple requests to the same endpoint (e.g., a partial fetch that lazily retrieves a promisor object while the first response is still being served), these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, causing an HTTP 500 error. The series replaces the non-atomic checks with atomic operations (`rm` without `-f` for the one-shot marker in `apply-one-time-script.sh`, `mkdir` for the first-request election in `http-429.sh`) to eliminate the race. The goal is to make the test helpers robust against concurrent execution, not to prevent the scripts from running multiple times (which is safe).

Key technical details
- Files touched: `t/lib-httpd/apply-one-time-script.sh`, `t/lib-httpd/http-429.sh`, `t/t5567-one-time-script.sh` (new), `t/lib-httpd.sh` (documentation update).
- New test: `t5567-one-time-script.sh` exercises `apply-one-time-script.sh` without a web server, using FIFOs to force the race deterministically. Confirms neither request emits an empty body (which would trigger HTTP 500) and each behaves as expected: the modifying request rewrites its response, while the passthrough request remains unchanged.
- Atomic idioms: `rm` (without `-f`) for one-shot markers (patch 1), `mkdir` for first-request election (patch 2), and `rm` (without `-f`) as an atomic alternative to `mv` for consuming one-shot markers (patch 3). Patch 3 documents these idioms in `t/lib-httpd.sh`, explaining the problem, the anti-pattern, and the safe alternatives, with cross-references to Git’s lockfile machinery (`O_CREAT|O_EXCL`) and `make_symlink()` in `t/test-lib.sh` as precedents. Per-request scratch files use `$$` suffixes (process IDs) to prevent clobbering.
- Error handling change: patch 1 redirects `stderr` of `./one-time-script` to `/dev/null` to suppress an expected error when the script is removed by a concurrent request. This is now documented in the code with a comment explaining that the error is expected and does not mask legitimate failures from the script itself.
- Documentation updates: patch 3’s v3 is located in `t/lib-httpd.sh` (instead of `t/README`) and is specific to the HTTP daemon helpers, addressing Patrick Steinhardt’s preference for contextual placement. The documentation mentions `rm` (without `-f`) as an atomic alternative to `mv` for consuming one-shot markers, reflecting the change in patch 1, clarifies the use of `$$` as process IDs (PIDs), and now states that scratch file names *should* include the process ID (`$$`) rather than merely describing existing practice, incorporating Patrick Steinhardt’s editorial suggestion.
- Patch 2 details: replaces the non-atomic "check-and-set" (`test -f` followed by `touch`) in `http-429.sh` with a single atomic `mkdir` operation, preventing concurrent requests from both incorrectly returning 429 (Too Many Requests) instead of forwarding one to `git-http-backend`. Fixes a correctness issue in the "permanent" mode (which returns 429 to every request) by skipping the `mkdir` entirely, ensuring no state marker is left behind. The original implementation used a racy "create-then-remove" pattern, which could leave a marker visible to a concurrent request, causing it to be wrongly forwarded. The commit message explains the problem, the atomic idiom (`mkdir`), and the reasoning behind the "permanent" mode fix in detail. The diff touches only `t/lib-httpd/http-429.sh`, replacing the state file logic with a state directory and adding explanatory comments. No regression test is included because the race cannot be forced deterministically (the check and set are adjacent commands with no external synchronization point).
- No changes to on-disk formats, CLI options, or user-visible behavior; the fixes are purely internal to the test helpers.
