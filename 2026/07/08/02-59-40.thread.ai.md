Subject: [PATCH 0/3] Fix race conditions in HTTP daemon test helpers
Series version: v2 (addresses Junio’s feedback on patches 1 and 2: commit-message clarifications, explicit rationale for the `"permanent"` case in patch 2, and retention of existing locale behavior)
Originating author: Michael Montalbo (via GitGitGadget)
Thread type: patch series (bugfix)

Core problem or goal
Two CGI scripts in `t/lib-httpd/` (`apply-one-time-script.sh` and `http-429.sh`) use non-atomic shell operations (`test -f` followed by `rm` or `touch`) to manage shared state in `HTTPD_ROOT_PATH`. Because Apache serves requests concurrently and a single Git operation can open multiple requests to the same endpoint (e.g., a partial fetch that lazily retrieves a promisor object while the first response is still being served), these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, causing an HTTP 500 error. The series replaces the non-atomic checks with atomic operations (`mv` for the one-shot marker in `apply-one-time-script.sh`, `mkdir` for the first-request election in `http-429.sh`) to eliminate the race. The goal is to make the test helpers robust against concurrent execution, not to prevent the scripts from running multiple times (which is safe).

Current status
Under review; v2 posted. The series is self-contained and targets only the test infrastructure (`t/` directory). The motivation is a real, observed flake in `t5616.47` on macOS CI runners, where the race caused a fetch to fail with an HTTP 500 error. Junio C Hamano reviewed v1 and provided substantive feedback on patches 1 and 2. In v2, Michael Montalbo addressed all feedback: for patch 1, the commit message and helper comment now explicitly state that the atomic `mv` operation shrinks but does not eliminate the race window for concurrent script execution, and that the goal is not to prevent the script from running multiple times (which is safe) but to ensure only one request’s modified output is served; for patch 2, the commit message and code comment now explicitly state that the atomic `mkdir` check is required for correctness in all cases, including when `retry_after` is set to `"permanent"`, and that the original implementation’s create-then-remove pattern left a race window where a concurrent `"permanent"` request could see the marker and be forwarded, defeating the requirement that every such request rate-limits; the v2 also retains the existing locale behavior in `apply-one-time-script.sh` (forcing C locale only when modifying output) as a deliberate choice. Patch 3 (the documentation patch) was unchanged in v2, as Junio called it a "nice finishing touch" and did not request any changes. No other reviews or objections have been recorded.

Key technical details
- Files touched: `t/lib-httpd/apply-one-time-script.sh`, `t/lib-httpd/http-429.sh`, `t/t5567-one-time-script.sh` (new), `t/README`, `t/lib-httpd.sh` (brief pointer).
- New test: `t5567-one-time-script.sh` exercises the `apply-one-time-script.sh` helper without a web server, using FIFOs to force the race deterministically. The test confirms that neither request emits an empty body (which would trigger HTTP 500) and that each behaves as expected: the modifying request rewrites its response, while the passthrough request remains unchanged.
- Atomic idioms: `mv` for one-shot markers (patch 1), `mkdir` for first-request election (patch 2). Patch 3 documents these idioms in `t/README`, explaining the problem, the anti-pattern, and the safe alternatives, with cross-references to Git’s lockfile machinery (`O_CREAT|O_EXCL`) and `make_symlink()` in `t/test-lib.sh` as precedents. Per-request scratch files use `$$` suffixes to prevent clobbering.
- No changes to on-disk formats, CLI options, or user-visible behavior; the fixes are purely internal to the test helpers.
- Patch 2 does not include a regression test for `http-429.sh` because the race cannot be forced deterministically (the check and set are adjacent commands with no external synchronization point), making the fix preventive rather than curative.
