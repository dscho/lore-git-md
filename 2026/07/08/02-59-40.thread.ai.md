Subject: [PATCH 0/3] Fix race conditions in HTTP daemon test helpers
Series version: v4 (final; no further changes after manual commit-message rewrite and minor documentation wording tweak)
Originating author: Michael Montalbo (via GitGitGadget)
Thread type: patch series (bugfix)

Core problem or goal
Two CGI scripts in `t/lib-httpd/` (`apply-one-time-script.sh` and `http-429.sh`) use non-atomic shell operations (`test -f` followed by `rm` or `touch`) to manage shared state in `HTTPD_ROOT_PATH`. Because Apache serves requests concurrently and a single Git operation can open multiple requests to the same endpoint (e.g., a partial fetch that lazily retrieves a promisor object while the first response is still being served), these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, causing an HTTP 500 error. The series replaces the non-atomic checks with atomic operations (`rm` without `-f` for the one-shot marker in `apply-one-time-script.sh`, `mkdir` for the first-request election in `http-429.sh`) to eliminate the race. The goal is to make the test helpers robust against concurrent execution, not to prevent the scripts from running multiple times (which is safe).

Current status
Ready for integration into `next`. All substantive and editorial feedback from v1–v4 has been addressed: patch 1 uses `rm` (without `-f`) instead of `mv` to consume the one-shot marker, simplifying the logic while maintaining atomicity, and includes a comment explaining the redirection of `stderr` to `/dev/null` to suppress expected errors when the script is removed by a concurrent request; patch 2 replaces the non-atomic "check-and-set" in `http-429.sh` with a single atomic `mkdir` operation, eliminating a latent race condition where concurrent requests could both incorrectly return 429 (Too Many Requests) instead of forwarding one to `git-http-backend`, and fixes a correctness issue in the "permanent" mode by skipping the `mkdir` entirely to ensure no state marker is left behind; patch 3 relocates the documentation update from `t/README` to `t/lib-httpd.sh` and makes it specific to the HTTP daemon helpers, addressing Patrick Steinhardt’s preference for contextual placement, and now also mentions `rm` (without `-f`) as an atomic alternative to `mv` for consuming one-shot markers, reflecting the change in patch 1, and incorporates Patrick Steinhardt’s editorial suggestions in v3 and v4 to clarify that scratch file names *should* include the process ID (`$$`) and to adjust the wording describing the relationship between the marker file and the guarded logic ("guarded by the marker" instead of "claims the marker"). The v4 revision rewrites all commit messages manually to address verbosity concerns raised by Junio C Hamano and Patrick Steinhardt in v3, with no technical changes. Junio previously marked the series as ready for integration in v2, and Patrick Steinhardt endorsed it as "good enough" in v3 and "a lot better now" in v4. Michael Montalbo’s latest replies confirm the series is complete and awaits integration, and link to recent CI failures (GitGitGadget and GitHub’s Git mirror) that appear to be caused by the same race, reinforcing the urgency of the fix.
