This is patch 7/11 in Justin Tobler’s ODB transaction series, now updated in response to Patrick Steinhardt’s review. The patch originally converted `odb_transaction_commit()` to return an error code, but Patrick spotted a latent bug: if the backend’s commit callback fails, the transaction is leaked because it is freed *before* the error is returned. The leak existed in the old `void` version but became more visible with the error-return change.

Justin acknowledges the issue and plans to fix it in the next revision by clearing the transaction even on failure. Patrick compares this to Git’s reference-transaction lifetime bugs, where automatic cleanup on commit caused similar problems, and suggests introducing an explicit `odb_transaction_release()` function to avoid ambiguity. Justin agrees and notes this could be added alongside `odb_transaction_abort()` in a follow-up series he is already working on.

The fix itself is straightforward (move the `free()` after the error check), but the discussion surfaces a broader design question about transaction lifetime management. The series remains on track for `next`; this is a mechanical correction rather than a design blocker.
