This is a follow-up in the RFC thread proposing `--only`/`--except` options for `git clone` to specify sparse-checkout paths. The author, Pushkar Singh, responds to Jeff King’s feedback, clarifying the motivation and design intent.

Pushkar acknowledges Peff’s suggestion of allowing a patterns file (e.g., `.git/info/sparse-checkout`) to be provided at clone time but explains that his proposal was shaped by the existing `git sparse-checkout set` workflow, which he uses regularly. He sees the feature as a convenience layer over that workflow rather than a direct interface to the patterns file. This distinction is important: the proposal targets users who prefer CLI commands over manual file editing, and it would not replace or modify the underlying sparse-checkout machinery.

On performance, Pushkar confirms that his primary goal is ergonomic—simplifying the workflow by eliminating the need for a separate `git sparse-checkout set` step after clone. He has not explored whether the selected paths could be used earlier in the clone process (e.g., to optimize object fetching), and he defers to domain experts like Derrick Stolee on whether that would be practical. This keeps the scope of the feature narrow and focused on user experience rather than performance.

The email adds little new technical detail but reinforces the proposal’s intent and constraints. The key takeaway is that the feature is meant to be a thin convenience layer, not a fundamental change to sparse-checkout or clone behavior. The thread’s next steps hinge on whether sparse-checkout experts (now cc’d) see value in this approach or prefer Peff’s file-based alternative. No implementation exists yet, and the discussion remains at the design stage.
