This is the first patch in a nine-patch refactoring series (v8) that continues the libification effort by migrating global configuration variables into `struct repo_config_values`. The patch introduces `repo_config_values_clear()`, a destructor function that frees heap-allocated strings in `repo_config_values` when a repository is torn down. As a starting point, it handles cleanup for `attributes_file`, with future patches extending it to other variables.

The implementation is straightforward: the new function checks if the repository is `the_repository` (to avoid crashing on submodules, which are not yet supported by `repo_config_values()`), retrieves the config values struct, and frees `attributes_file`. The function is called from `repo_clear()`, ensuring proper cleanup during repository teardown. A `NEEDSWORK` comment notes the submodule limitation, but this is not a blocker for the series.

This patch overlaps with the recently merged `excludes_file` migration but is re-split for clarity in this series. The memory leak fix for heap-allocated strings (addressed in v8) is not visible here but will be handled in later patches. The patch is well-motivated and aligns with the project’s goals for explicit memory management. No user-visible behavior changes are introduced.
