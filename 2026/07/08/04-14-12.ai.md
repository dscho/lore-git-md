This is the final patch in Justin Tobler’s v2 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It applies the infrastructure built in the previous ten patches by replacing the direct `tmp_objdir` calls in `builtin/receive-pack.c` with the new `odb_transaction` interfaces.

The patch removes the global `tmp_objdir` variable and introduces a local `struct odb_transaction *` that is created at the start of the unpack phase (`odb_transaction_begin` with the `ODB_TRANSACTION_RECEIVE` flag) and committed just before reference updates (`odb_transaction_commit`). Every place that previously called `tmp_objdir_env` now calls `odb_transaction_env` to populate the environment for child processes (`git-index-pack`, `git-unpack-objects`, and hooks). The temporary directory is no longer added as an alternate; instead, the transaction’s object directory becomes the primary ODB in the main process, which is functionally equivalent for `receive-pack`’s needs.

The diff touches only `builtin/receive-pack.c` (68 lines changed: 35 insertions, 33 deletions) and removes the `#include "tmp-objdir.h"` line. No new symbols are introduced; the patch simply wires up the transaction interfaces that were already added in earlier patches. The change is mechanical and preserves the existing quarantine semantics: objects are staged in an "incoming" directory and migrated to the main object store only after the pre-receive hook and connectivity checks pass. Error handling is consistent with the rest of the series: failures during transaction begin or commit are surfaced as command errors.
