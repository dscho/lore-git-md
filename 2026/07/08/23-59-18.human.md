This is a refactoring patch that removes redundant validation from the "files" ODB backend. It is the fourth patch in Justin Tobler’s v3 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`.

The change is straightforward: the "files" backend (`odb_transaction_files_begin()`) currently checks whether a transaction is already in progress on the ODB, but this check is redundant because the generic `odb_transaction_begin()` layer already enforces the same rule. The patch removes the duplicate check, simplifying the code and fixing a layering violation where the backend was duplicating ODB-layer state management.

The diff is small (4 lines removed, 1 line modified) and touches only `object-file.c` and `object-file.h`. The commit message clearly explains the motivation and the change. Patrick Steinhardt, the ODB subsystem owner, explicitly endorsed this change in his review of v2, calling it a fix for a layering violation. No behavioral change is introduced; this is purely a mechanical cleanup.

The patch is part of the larger ODB abstraction effort and is already reviewed and integrated into the series. It is queued for `next` alongside the rest of the series.
