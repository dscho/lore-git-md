This is the second patch in Kristofer Karlsson’s two-part performance optimization series for Git’s priority queue implementation. It introduces the cascade-down optimization for `prio_queue_get()` calls that are not immediately followed by a `prio_queue_put()` (the "unfused" case).

The patch replaces the standard sift-down algorithm in `flush_get()` with a cascade-then-sift-up strategy. Instead of placing the last element at the root and sifting it down (requiring two comparisons per level), the vacancy is cascaded down to a leaf by promoting the smaller child at each level (one comparison per level), then the last element is placed at the leaf and sifted up. This is the well-documented "bottom-up heapsort" variant, and René Scharfe’s exhaustive testing confirms it never requires more comparisons than sift-down for extract-min operations.

The implementation is minimal: 20 lines added, 2 removed in `prio-queue.c`, with no changes outside that file. The new `cascade_down()` helper is cleanly separated from the existing `sift_down_root()` logic, which remains in place for the fused replace path (handled by the already-merged `kk/prio-queue-get-put-fusion` series). The patch preserves API compatibility and is covered by existing tests.

Benchmark results show a ~2% end-to-end improvement on large repositories with thousands of active branches, with no regressions in any scenario. The optimization is particularly effective for wide commit graphs where priority queues grow deeper, as the per-level savings compound. René’s empirical analysis of all heap permutations up to 12 items provides definitive evidence that cascade-down is strictly faster for `prio_queue_get()` operations.

The series has reached technical consensus, with both Kristofer and René endorsing the hybrid approach. The only remaining question is whether the modest 1-2% performance improvement justifies the code change, given that the lazy-fold optimization already handles most get+put pairs. Kristofer notes in the cover letter that both the value gain and code cost appear small, leaving the decision to Junio. The patch is ready to merge if the maintainer approves.
