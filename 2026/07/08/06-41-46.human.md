This is a review comment on patch 7/11 in Justin Tobler’s v2 series converting `git-receive-pack` to use ODB transactions. The patch itself is a mechanical change: it makes `odb_transaction_commit()` return an `int` so backends can signal commit failures, which is a prerequisite for the later behavioral changes in the series.

Patrick Steinhardt’s feedback is brief but substantive. He spots a potential memory leak in the updated code: if the backend’s `commit()` callback fails, the function returns early without freeing the transaction object. This mirrors a historical design flaw in Git’s reference transactions, where automatic cleanup on commit led to lifetime issues. Patrick explicitly notes this is not a regression introduced by this series, so he does not block the patch—but the observation is a clear signal that the transaction API’s lifetime management may need revisiting in a future effort.

The review is narrowly scoped to this patch’s error-handling logic, not the broader series goals. No code changes are requested here, but the comment flags a latent issue that could become more pressing if the ODB transaction system sees wider use. For now, the patch remains uncontroversial and ready for integration.
