This is a performance optimization patch series (v3) targeting Git's priority queue implementation, specifically the `prio_queue_get()` operation. The series is now split into two commits: the first extracts `sift_up()` from `prio_queue_put()` as a refactoring step, and the second introduces the cascade-down optimization for unfused `prio_queue_get()` calls.

The core change replaces the standard sift-down algorithm with a bottom-up cascade approach when removing the root element without an immediate replacement. This method promotes the smaller child at each level (requiring one comparison per level) until the vacancy reaches a leaf, then places the last element there and sifts it up. The optimization is particularly effective for wide commit graphs where priority queues grow deeper, as the per-level savings compound. Benchmarks show a ~2% end-to-end improvement on large repositories with thousands of active branches, with no regressions in any scenario.

The v3 revision incorporates all prior feedback: it preserves René Scharfe's existing optimizations for `prio_queue_replace()`, extracts the new logic into a separate `cascade_down()` function, and rebases on the recently merged `kk/prio-queue-get-put-fusion` series. The patch is minimal (32 lines added, 11 removed) and well-covered by existing tests. René's exhaustive analysis of all heap permutations up to 12 items confirms the cascade approach never requires more comparisons than standard sift-down for extract-min operations.

The series reflects the technical consensus reached in earlier discussion, with both Kristofer and René endorsing the hybrid approach. The remaining open question is whether the modest 1-2% performance improvement justifies the code change, given that the lazy-fold optimization already handles most get+put pairs. Kristofer notes in the cover letter that both the value gain and code cost appear small, suggesting this may ultimately be closed unless Junio decides the optimization is worth merging.

Key technical details include: the optimization is equivalent to the bottom-up heapsort algorithm, `sift_down_root()` is preserved for the fused replace path, and the implementation handles empty-root cases with a boolean flag. The patch touches only `prio-queue.c` and maintains API compatibility for third-party code using both `prio_queue` and `lazy_queue`.
