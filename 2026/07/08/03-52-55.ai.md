This is the third patch in Jeff King’s v2 series refactoring the `git_hash_*()` API. It is a documentation update to `hash.h` that shifts focus from the low-level function pointers in `struct git_hash_algo` to the public `git_hash_*()` wrapper functions. The patch adds clear usage guidance, warns against direct use of the function pointers, and documents two key constraints: callers must initialize the destination context before calling `git_hash_clone()`, and every initialized hash context must eventually be finalized or discarded to avoid resource leaks. These constraints are not new, but the documentation now makes them explicit. The patch also sets the stage for the Coccinelle semantic patch (introduced in patch 1) that will enforce wrapper usage at compile time. No code behavior changes; this is purely about improving clarity and steering future contributors toward the intended API. The commit message frames the change as a way to "lead readers in the right direction from the start."
