This is a refactoring series from Jeff King (Peff) that improves the robustness of Git’s `git_hash_*()` API. The v2 iteration addresses all review feedback from the first round: cosmetic fixes (unnecessary braces, typos, trailing whitespace), clearer documentation, and expanded rationale for the design choices.

The core change makes `git_hash_discard()` idempotent—safe to call multiple times—while leaving `git_hash_final()` unprotected to catch programming errors. This asymmetry is intentional: `git_hash_final()` attempts to produce a meaningful hash, so calling it on an inactive context triggers a `BUG()` to surface bugs early, whereas `git_hash_discard()` is purely a cleanup operation and can safely be called redundantly. The series also standardizes usage of the hash API by eliminating direct calls to low-level hooks (e.g., `init_fn()`) in favor of the public `git_hash_init()` wrapper, enforced by a new Coccinelle semantic patch.

The patches touch 24 files across core object-writing code (`csum-file.c`, `http.c`), built-ins (`fast-import`, `index-pack`, `receive-pack`), and test helpers. No user-visible behavior changes are expected, but the changes make the code more resilient against misuse. The Coccinelle rule and runtime checks in the wrapper functions ensure the new invariants are maintained going forward.

This is a well-crafted, mechanical cleanup with thorough test coverage and clear commit messages. The v2 is ready for integration, with no substantive objections remaining. If you care about low-level Git internals or API design, this series is worth a quick skim; otherwise, it’s safe to ignore—it’s a quality-of-life improvement for developers, not a feature or bugfix.
