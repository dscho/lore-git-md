This is a test infrastructure bugfix targeting the HTTP daemon test helpers. The series addresses a race condition in two CGI scripts (`apply-one-time-script.sh` and `http-429.sh`) that share state between concurrent requests by writing to the filesystem without atomic operations. The issue manifests as occasional HTTP 500 errors in CI, particularly on macOS runners during partial fetches with promisor objects.

The fix is straightforward: replace non-atomic `test -f`/`rm` sequences with atomic filesystem operations (`rename` for the one-shot script, `mkdir` for the 429 handler). Patch 1 fixes the primary flake (with a new test that reproduces the race deterministically), patch 2 hardens the less-likely-to-fail 429 script, and patch 3 documents the atomic idioms in `t/README` for future test authors.

The commit messages are unusually clear for test infrastructure work, explaining both the symptom (CI flakiness) and the root cause (concurrent requests to the same CGI endpoint). The new test in patch 1 is particularly well-designed—it bypasses the web server entirely to force the race condition deterministically, which should make future debugging easier.

This looks like a solid, well-motivated fix for a real problem. The changes are minimal and focused, and the documentation addition in patch 3 is a nice touch that might prevent similar issues in the future. The series is unlikely to be controversial.
