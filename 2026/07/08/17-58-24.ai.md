This is a follow-up in the feature-request thread about programmatic commit editing during interactive rebase. Johannes Schindelin (Dscho) provides concrete scripting techniques that build on the existing `GIT_SEQUENCE_EDITOR` mechanism already identified as the solution.

Dscho first suggests a simple way to pause the rebase at the start by inserting a `break` command into the todo list, allowing a script to then transform the list before continuing. He then offers a more sophisticated example tailored to Matthias Beyer’s use case: generating a regex from `git rev-list` output to match commits that modified files in a given subdirectory, and using `sed` to rewrite the rebase todo list in-place. The example handles the expanded OIDs in the todo file and demonstrates how to chain Git commands with shell tools to automate the workflow without any new Git features.

The contribution is substantive and practical, addressing both the immediate scripting need and the shell-nesting edge cases previously surfaced by D. Ben Knoble. It does not reopen the design discussion—it accepts the established conclusion that `GIT_SEQUENCE_EDITOR` is the right mechanism—but it adds production-ready patterns that future users can adapt. No new symbols, options, or on-disk formats are introduced; the focus remains on shell scripting and existing Git plumbing.
