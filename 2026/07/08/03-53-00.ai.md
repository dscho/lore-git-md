This is the fifth patch in Jeff King’s seven-patch v2 series refactoring the `git_hash_*()` API. The patch simplifies cleanup logic in `csum-file.c` by leveraging the idempotent behavior of `git_hash_discard()` introduced in patch 4. It removes a redundant helper function (`free_hashfile_memory()`) and eliminates conditional hash-discard logic when `f->skip_hash` is set, relying instead on `free_hashfile()` to handle cleanup uniformly. The changes are mechanical and reduce code duplication without altering behavior.

The patch touches only `csum-file.c`, removing 12 lines and adding 5. It is a direct follow-up to patch 4, which made `git_hash_discard()` safe to call multiple times by adding an `active` flag to `git_hash_ctx`. Here, Peff undoes some of the defensive logic introduced in an earlier commit (64337aecde, "csum-file: always finalize or discard hash"), which had added a separate cleanup path for `finalize_hashfile()`. The simplification is now possible because `git_hash_discard()` no longer requires callers to track whether the hash context has already been finalized.

No new symbols are introduced; the patch merely consolidates existing cleanup paths. The change is internal to the hashfile subsystem and has no user-visible impact. The commit message clearly explains the motivation and the specific lines being removed, making the patch easy to review. Given that the series has already addressed all technical feedback and this patch is a straightforward application of the new idempotency guarantee, it is unlikely to generate further discussion. The patch is ready for integration alongside the rest of the series.
