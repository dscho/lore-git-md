This is a refactoring patch that advances the ODB abstraction effort. It renames `fsync_loose_object_transaction()` to `odb_transaction_files_fsync()` for naming consistency with other "files" ODB transaction helpers. The change is purely mechanical: no behavior is altered, but the conditional logic is reordered slightly to improve clarity. The patch touches only `object-file.c` (10 insertions, 6 deletions).

The motivation is straightforward: as part of the larger ODB abstraction work led by Patrick Steinhardt, transaction-related functions are being renamed to follow a consistent `odb_transaction_<backend>_<action>` pattern. This patch aligns the fsync helper with that convention. The reordered conditional makes it clearer that the hardware flush is skipped only when there is an active transaction, and that a full fsync is performed otherwise.

Patrick Steinhardt, the ODB subsystem owner, has already reviewed this change in a prior iteration and accepted the minor duplication introduced by the conditional reordering. The patch is part of a functionally complete 11-patch series (v3) that replaces `tmp_objdir` usage in `git-receive-pack` with ODB transactions. All feedback from earlier versions has been addressed, and the series is queued for `next` pending integration. This specific patch is uncontroversial and ready to merge.
