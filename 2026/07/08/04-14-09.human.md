This is the eighth patch in Justin Tobler’s v2 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It introduces the `odb_transaction_env()` interface, which lets child processes access the transaction’s staging area by inheriting environment variables.

The patch adds a new `env` callback to the `odb_transaction` struct and implements it for the "files" backend. The callback populates a `strvec` with the environment variables needed for child processes (like `git-index-pack` or `git-unpack-objects`) to write objects into the transaction’s temporary directory. The implementation is straightforward: it calls `tmp_objdir_env()` on the transaction’s `tmp_objdir` and pushes the result into the provided `strvec`.

This is a mechanical but necessary piece of the ODB abstraction effort. The commit message explains the motivation clearly: child processes spawned by Git need access to uncommitted objects in the transaction’s staging area. The patch itself is small (39 lines across three files) and does not change behavior—it just exposes the existing `tmp_objdir` environment variables through the transaction interface.

No controversy here; this is a well-scoped addition that addresses feedback from v1 about making the transaction environment accessible to child processes. The patch is part of a larger refactoring, but it stands on its own as a clean interface improvement. If you care about ODB abstraction or `receive-pack` internals, this is worth noting, but it’s not user-facing.
