This is a review comment on the second patch in Michael Montalbo’s three-patch series fixing race conditions in Git’s HTTP daemon test helpers. Junio C Hamano points out a minor but important ambiguity in the in-code comment and suggests the commit message should clarify whether the `retry_after != permanent` check is a correctness requirement or merely an optimization. The original patch replaced a non-atomic `test -f && touch` sequence with an atomic `mkdir`, but the comment could be read as implying that the `permanent` case never needed atomicity in the first place. Junio’s feedback is substantive but lightweight—it asks for a small documentation improvement rather than a code change, so the fix is likely to be quick and uncontroversial. The patch itself remains a clean, well-motivated bugfix targeting test infrastructure concurrency.
