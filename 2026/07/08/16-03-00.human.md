This is the final patch in Tian Yuchen’s v8 series migrating global configuration variables into `struct repo_config_values`. It moves the `object_creation_mode` enum — which controls whether Git uses hardlinks or renames when creating object files — into the per-repository configuration structure.

The patch relocates the `enum object_creation_mode` definition in `environment.h` so it is visible to `struct repo_config_values`, initializes the field to its default value (`OBJECT_CREATION_MODE`) in `repo_config_values_init()`, and updates `git_default_core_config()` to write directly to the repository-specific structure. The only caller in `object-file.c` is updated to read the value from `repo_config_values(repo)` instead of the global variable.

This is a clean, mechanical refactoring with no user-visible behavior change. The commit message is clear and the patch itself is small and focused. The memory management pattern established in earlier patches (proper cleanup of heap-allocated strings) does not apply here since `object_creation_mode` is an enum, not a string. The series as a whole is now technically complete, CI-clean, and addresses the memory leak Junio C Hamano identified in v7. This patch is ready for integration once the rest of the series is reviewed.
