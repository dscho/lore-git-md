This is patch 3/9 of Tian Yuchen's v8 refactoring series, migrating the `editor_program` global variable into `struct repo_config_values`. The patch is part of the ongoing libification effort to eliminate mutable global state and prepare Git for long-running processes managing multiple repositories.

The change moves the `editor_program` string from a global variable to a heap-allocated field in `repo_config_values`, following the same pattern established for `excludes_file` in the prior merged series. The patch updates `git_default_core_config()` to store the editor path in the repository-specific struct, and `repo_config_values_clear()` to free it during cleanup. Callers in `editor.c` now access the field via `repo_config_values(the_repository)->editor_program` instead of the global variable.

The commit message explicitly addresses the RFC question about migrating program paths: while per-repository editor configuration is rare in practice, it respects developers' workflows with different toolchains and eliminates a source of global state that could cause issues in concurrent repository scenarios. No getter function is introduced; direct field access is used instead.

This patch is technically straightforward and follows the established memory management pattern. The memory leak fix from v8 (proper cleanup during re-assignment) is visible here in the `FREE_AND_NULL(cfg->editor_program)` call in `git_default_core_config()`. The change is confined to three files and maintains backward compatibility.
