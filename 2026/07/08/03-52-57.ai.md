This is the fourth patch in Jeff King’s seven-patch v2 series refactoring the `git_hash_*()` API. The patch makes `git_hash_discard()` idempotent by adding an `active` flag to the `git_hash_ctx` struct. When a hash context is initialized, the flag is set to `true`; when it is finalized or discarded, the flag is set to `false`. A redundant call to `git_hash_discard()` now returns early rather than triggering undefined behavior or a double-free.

The change is a targeted improvement to the hash API’s robustness. It eliminates a subtle footgun: callers no longer need to track whether they have already finalized or discarded a context before cleaning up. The patch itself is small (7 lines added) and touches only `hash.c` and `hash.h`. No behavior changes are visible to users; the patch is purely internal plumbing. The `active` flag will be used in later patches to simplify existing callers and add defensive runtime checks.

Carlson’s technical context on hash-library conventions. No technical objections remain. The patch is ready for integration and should be uncontroversial.
