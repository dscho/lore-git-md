This thread is about clarifying how contributors should explicitly abandon a patch series by notifying the mailing list, rather than leaving the maintainer to track stale topics. Junio C Hamano authored a patch to update `Documentation/SubmittingPatches` with this guidance, incorporating minor wording improvements suggested by Michael Montalbo (including a typo fix).

The patch itself is still under discussion, with no revised version posted yet. A secondary conversation has emerged about whether related documentation, like `MyFirstContribution`, should be kept in sync with such updates. Junio also shared details about his internal workflow for managing stale topics, which could inform future documentation but isn’t part of the current patch.

Alongside the main discussion, Weijie Yuan and Michael Montalbo highlighted a recurring workflow issue: replies sent via Gmail’s web interface using lore.kernel.org’s "mailto:" links lose the `In-Reply-To` header, breaking threading and complicating tooling like `b4`. While this doesn’t affect the patch directly, it’s a known pain point for contributors using webmail. No action has been taken on this yet, but it may influence future contributor guidelines or tooling improvements. The thread remains open, with no decisions made about syncing documentation or codifying Junio’s workflow details.
