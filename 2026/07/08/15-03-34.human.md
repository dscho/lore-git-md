This is the first patch in a two-patch bugfix series addressing a usability issue in Git's bundle-URI protocol implementation. The patch makes the client more resilient when servers advertise invalid bundle-URI data (specifically empty URIs), preventing the confusing "expected 'packfile'" error that previously masked the real problem.

The change modifies `get_remote_bundle_uri()` in `connect.c` to continue reading packets even after encountering invalid bundle-URI lines, effectively draining the protocol stream so no stale data remains to interfere with subsequent protocol exchanges. This allows the clone operation to proceed successfully while still reporting the configuration error to the user. The patch includes comprehensive test coverage that verifies both the error reporting and the absence of the misleading "expected packfile" message.

This is a well-crafted fix that addresses a real user-facing problem without changing fundamental behavior. The commit message clearly explains the issue and solution, and the implementation is clean with good inline comments. The test cases cover both missing and empty URI scenarios, demonstrating thorough consideration of edge cases. This patch should be uncontroversial as it simply makes error handling more robust while maintaining backward compatibility.
