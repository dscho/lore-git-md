This is part of a refactoring series (v8, 9 patches) that continues the libification effort by moving global configuration variables into `struct repo_config_values`. This specific patch (2/9) migrates the `excludes_file` variable, which tracks the path to the global ignore file, into the repository configuration structure.

The patch encapsulates the lazy-loading fallback logic for `excludes_file` (which defaults to the XDG config path if unset) into a new getter function, `repo_excludes_file()`. It also ensures proper memory management by freeing the dynamically allocated string via `repo_config_values_clear()` during repository teardown. The changes are confined to `dir.c`, `environment.c`, and `environment.h`, with no user-visible behavior changes.

This patch overlaps with work already merged in the prior `excludes_file` series but is re-split here for clarity. The memory leak issue Junio C Hamano identified in v7 has been resolved in this version, making the series technically complete and CI-clean. The patch is well-motivated as part of the broader effort to eliminate globals and centralize memory management, though the RFC questions about migrating program paths (like editor/pager) and the relationship to `git_branch_track` remain open.

For reviewers, the key points to check are the correctness of the getter logic and the memory management in `repo_config_values_clear()`. The patch looks solid and aligns with the project’s libification goals. If the rest of the series holds up similarly, this is likely ready for `next`.
