This is the final patch in a now-merged four-patch bugfix series that standardizes help-flag exit codes across Git’s parse-options infrastructure. The patch updates the core `parse-options.c` and `usage.c` logic so that `--help`/`-h` exits with status 0 (Unix convention) instead of 129, and propagates this change to 37 test files and three built-in commands (`git blame`, `git shortlog`, `git update-index`).

The change is mechanical: every test or command that previously expected exit code 129 for help output is updated to expect 0. The patch also distinguishes between `--help` (short help) and `--help-all` (full help) in some commands, adjusting test expectations accordingly. One notable exception is `git diff`, which does its own option parsing and still exits 129; tests for it are updated to accept either exit status.

This patch completes the system-wide fix initiated in earlier patches. The series was accepted as a regular bugfix and is now fully merged, resolving a 17-year-old inconsistency in Git’s help behavior. No further discussion or follow-up is expected.
