This is the first patch in a three-patch bugfix series targeting race conditions in Git’s HTTP daemon test helpers. It fixes a concurrency flaw in `t/lib-httpd/apply-one-time-script.sh`, where non-atomic shell operations (`test -f` followed by `rm`) could cause concurrent requests to race, leading to HTTP 500 errors when a second request tried to execute a marker file that the first had already removed. The fix replaces the non-atomic check with an atomic `mv` operation, ensuring only one request claims the marker, and adds per-request scratch files to prevent clobbering. The patch also introduces `t/t5567-one-time-script.sh`, a new test that directly exercises the helper without a web server, using FIFOs to force the race deterministically. The test confirms that neither request emits an empty body (which would trigger HTTP 500) and that each behaves as expected: the modifying request rewrites its response, while the passthrough request remains unchanged.

The commit message is thorough, explaining the race’s real-world impact (a flaky `t5616.47` failure on macOS CI) and the atomic idiom’s rationale. The implementation is minimal and targeted, touching only the helper script and adding the test. The new test is particularly strong, as it isolates the race without relying on timing-sensitive HTTP server interactions. The patch is part of a well-motivated series addressing a concrete, observed problem in the test infrastructure, and the fix aligns with Git’s existing atomic patterns (e.g., lockfile machinery). No controversy is expected, as the changes are confined to test helpers and do not affect user-visible behavior. The series’ cover letter and this patch’s commit message provide all necessary context for reviewers to assess the fix.
