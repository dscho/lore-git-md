This is the v3 iteration of a four-patch bugfix series that standardizes help-flag exit codes across Git’s parse-options infrastructure. The series is now fully merged, but this revision addresses two post-merge issues identified in the thread: the overly restrictive `SVN` test prerequisite and the incomplete refactoring in `usage_with_options_internal()`.

The core change remains the same: `--help`/`-h` now exits 0 (Unix convention) instead of 129 for all commands using parse-options, including `git rev-parse --parseopt` when invoked via shell eval. The direct invocation mode of `--parseopt` still exits 129 to preserve its debugging utility. This v3 drops the problematic Perl version check (`$SVN::Core::VERSION gt '1.1.0'`) from the `SVN` prerequisite, simplifying it to just test for module availability. It also fixes the inverted condition in `t1517-outside-repo.sh` and updates `usage_with_options_internal()` to consistently return `PARSE_OPT_HELP_ERROR` when `err` is set, closing the refactoring gap Peff identified.

Key technical details for follow-up: the series touches `parse-options.c`, `usage.c`, 37 test files, and three built-ins (`git blame`, `git shortlog`, `git update-index`). The shell-eval mode achieves exit 0 by appending `exit 0` to its heredoc output, a solution Junio accepted despite calling it "yuck." The behavioral trade-offs (wrapped commands and shell-eval edge cases) remain documented and accepted. This revision is a targeted cleanup of the merged series, not a reopening of the core exit-code debate.
