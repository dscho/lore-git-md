This is the sixth patch in Justin Tobler’s v2 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch refactors `odb_transaction_begin()` to return an error code and write the transaction into an out-parameter, rather than returning the transaction directly. This change allows callers to detect and handle failures during transaction setup, which will be necessary when `git-receive-pack` starts using transactions in a later patch.

The patch introduces `odb_transaction_begin_or_die()` as a convenience wrapper for call sites that do not need to handle errors explicitly. It also updates all existing callers of `odb_transaction_begin()` to either use the new error-returning interface or switch to the `_or_die` variant. Notably, `cache-tree.c` and `read-cache.c` now check whether a transaction is already inflight before attempting to start a new one, avoiding the error case entirely.

The changes are mechanical and focused on error propagation. No behavior changes are introduced—this is purely plumbing work to prepare for the later patches in the series. The patch touches eight files, with the most significant changes in `odb/transaction.c` and `odb/transaction.h`. The commit message clearly explains the motivation and the refactoring steps, and the code changes are straightforward. This looks like a well-crafted, uncontroversial step in the ODB abstraction effort.
