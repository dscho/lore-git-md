This is a follow-up in the feature request thread about programmatically editing the rebase todo list. Johannes Schindelin (Dscho) responds to Matthias Beyer’s specific use case—splitting commits that modified files in a given subdirectory—by providing a concrete, working solution using the existing `GIT_SEQUENCE_EDITOR` mechanism.

Dscho’s approach is practical and production-ready. He first suggests a simple way to pause the rebase at the start (inserting a `break` command) so a script can modify the todo list before continuing. He then gives a more targeted solution: construct a regex from the OIDs of commits that touched the subdirectory, then use `sed` to replace `pick` with `edit` for those commits in the rebase todo file. The example is complete, including the shell pipeline to generate the regex and the exact file path to the todo list (`$(git rev-parse --git-path rebase-merge/git-rebase-todo)`).

The contribution is substantive and directly addresses the original request without requiring new Git features. It also surfaces a useful detail: the OIDs in the todo file are expanded, so matching by OID is more reliable than matching by commit message or other metadata. Dscho notes the solution may need adaptation for specific use cases, but the core pattern is sound and portable across platforms (with a small caveat about GNU vs. BSD `sed` syntax).

This email effectively closes the technical gap in the thread. Earlier responses (notably from brian m. carlson and D. Ben Knoble) already established that `GIT_SEQUENCE_EDITOR` exists and can solve the problem, but Dscho’s example is the first to show exactly how to apply it to the subdirectory-based workflow Matthias described. The thread is now a self-contained tutorial on automating rebase edits, and future users searching for similar automation will find a clear, tested pattern here.
