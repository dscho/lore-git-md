This is the second patch in Kristofer Karlsson’s two-part performance optimization series for Git’s priority queue. It introduces the cascade-down strategy for `prio_queue_get()` operations that do not immediately replace the extracted root element.

The patch replaces the standard sift-down algorithm with a bottom-up cascade: instead of placing the last element at the root and sifting it down (requiring two comparisons per level), it moves the vacancy down by promoting the smaller child at each level (one comparison per level), then places the last element at the resulting leaf and sifts it up. This approach is equivalent to the well-known bottom-up heapsort variant and is particularly effective for wide commit graphs where priority queues grow deeper. Benchmarks show a ~2% end-to-end improvement on large repositories with thousands of active branches, with no regressions in any scenario.

The implementation is minimal and focused: it adds a new `cascade_down()` helper function, modifies `flush_get()` to use the cascade-then-sift-up strategy, and preserves the existing `sift_down_root()` logic for the fused replace path (already merged in the `kk/prio-queue-get-put-fusion` series). The patch touches only `prio-queue.c` and maintains full API compatibility. René Scharfe’s exhaustive testing of all heap permutations up to 12 items confirms the cascade approach never requires more comparisons than standard sift-down for extract-min operations.

This patch reflects the technical consensus reached in earlier discussion, with both Kristofer and René endorsing the hybrid approach. The series is now procedurally unblocked following the merge of the API simplification work. The remaining open question is purely about cost/benefit: whether the modest 1–2% performance improvement justifies the additional code complexity, given that the lazy-fold optimization already handles most get+put pairs. Kristofer notes in the cover letter that both the value gain and code cost appear small, leaving the final decision to Junio.
