This is the fourth iteration of a bugfix series that standardizes help-flag exit codes across Git’s parse-options infrastructure. The series is now fully merged, but this v3 addresses two post-merge issues identified in the thread: it removes the problematic Perl version check in the `SVN` test prerequisite (fixing both the overly restrictive guard and the shell-quoting bug) and corrects an inverted condition in `t1517-outside-repo.sh`.

The four patches are unchanged in purpose from v2: the first skips SVN tests when the modules are missing (now simplified to only check availability, not version), the second refactors `parse-options.c` to distinguish help triggered by user request (`-h`) from help triggered by errors, the third ensures `git rev-parse --parseopt` exits 0 on `--help` when invoked via shell eval, and the fourth makes all parse-options users exit 0 on `-h`. The series touches 40 files, including 37 test updates to reflect the new exit-code expectations.

The key improvement in v3 is the removal of the `SVN::Core::VERSION gt '1.1.0'` check, which was confirmed to be broken due to Perl treating dotted version strings as ASCII sequences (e.g., `1.14.5` < `1.2.0`). This resolves the false negatives that caused tests to skip even when SVN was available. The change is minimal but important: it replaces a fragile version check with a simple availability test, ensuring tests run when they should and skip only when SVN is genuinely unavailable.

The series remains a well-motivated bugfix with thorough test coverage. The behavioral trade-offs (e.g., wrapped scripts now exiting 0 on `--help`) are documented and accepted as part of the broader consistency fix. No further changes are expected to the core logic, though Peff’s proposed one-line fix for `usage_with_options_internal()` (to fully align the refactoring) may appear in a future patch. For now, this v3 is the final version of the series.
