This is the final patch in a three-part bugfix series targeting race conditions in Git's HTTP daemon test helpers. The series addresses flaky test failures caused by non-atomic shell operations in CGI scripts (`apply-one-time-script.sh` and `http-429.sh`), which can race when Apache serves concurrent requests to the same endpoint.

This patch adds documentation to `t/README` explaining how to write concurrency-safe test helpers. It describes the anti-pattern (using `test -f` followed by a separate `rm` or `touch`) and introduces two atomic idioms: `mkdir` for electing a single "winner" among concurrent processes, and `mv` (rename) for consuming a one-shot marker. The documentation also notes the use of `$$` suffixes to prevent concurrent invocations from clobbering each other's scratch files. The patch references Git's own lockfile machinery and `make_symlink()` as precedents, grounding the advice in existing patterns.

The change is minimal and targeted, adding only 32 lines to `t/README` and a brief pointer in `t/lib-httpd.sh`. The documentation is clear and practical, offering concrete guidance for future test helpers. This patch doesn't fix a bug directly but prevents future regressions by codifying best practices for concurrency in test scripts. The series as a whole is well-motivated, addressing a real flake observed in CI, and this documentation patch is a thoughtful addition that generalizes the solution for broader use. It looks uncontroversial and ready for review.
