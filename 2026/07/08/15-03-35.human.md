This is the second patch in a two-patch bugfix series for the bundle-URI protocol. It addresses server-side validation to prevent Git servers from advertising invalid bundle-URI configuration (specifically empty URIs) to clients.

The patch modifies `bundle-uri.c` to silently filter out bundle configuration lines with empty values during the conversion from Git config to protocol packet lines. When an empty value is encountered, the server now skips sending that line entirely and logs a warning (visible only server-side) rather than transmitting malformed data. This complements the client-side resilience added in patch 1, which ensures the client can gracefully handle any remaining protocol-level errors without failing with confusing "expected 'packfile'" messages.

The implementation is straightforward: the `config_to_packet_line()` function now checks `value && *value` before writing any bundle-prefixed config line. The test coverage verifies that empty URI values are filtered out while valid configuration is transmitted normally. The patch maintains the existing behavior that bundle-URI information is optional, and the server remains silent about missing configuration rather than erroring out.

This patch is unlikely to be controversial. The silent filtering approach was agreed upon in earlier discussion, with the rationale that client-side warnings provide sufficient visibility for administrators. The commit message clearly acknowledges the limitation that this validation is line-by-line and cannot catch all semantic errors (like missing URIs for declared bundles), positioning this as a pragmatic first step rather than a complete solution. The change is minimal, well-tested, and directly addresses the core problem of preventing servers from propagating misconfigurations.
