This thread is a three-patch series from Michael Montalbo (via GitGitGadget) fixing race conditions in Git’s HTTP daemon test helpers. The issue affects two CGI scripts in `t/lib-httpd/` that manage shared state using non-atomic shell operations (`test -f` followed by `rm` or `touch`). Because Apache serves requests concurrently, and a single Git operation can open multiple requests to the same endpoint (e.g., a partial fetch retrieving a promisor object), these scripts can race, causing HTTP 500 errors. The series replaces the non-atomic checks with atomic operations (`mv` for one-shot markers, `mkdir` for first-request election) to eliminate the race.

The series is under review and targets only the test infrastructure (`t/` directory). Patch 1 fixed `apply-one-time-script.sh` and added a new test (`t5567-one-time-script.sh`) to exercise the helper deterministically using FIFOs. Patch 2 (this email) fixes `http-429.sh` by replacing its non-atomic check with an atomic `mkdir`, ensuring exactly one request is rate-limited (returning HTTP 429) while others are forwarded to `git-http-backend`. The change is minimal and doesn’t alter the script’s behavior under sequential execution. No regression test was added for this patch, as the race cannot be forced deterministically, but the fix is preventive and well-motivated. Patch 3 will document the atomic idioms in `t/README`.

The series is narrowly scoped, addressing a real flake observed in `t5616.47` on macOS CI runners. The fixes are mechanical and don’t introduce new behavior or edge cases. No reviews have been posted yet, but the series is uncontroversial and unlikely to draw significant discussion.
