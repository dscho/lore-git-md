This thread is about a three-patch series from Michael Montalbo that fixes race conditions in Git’s HTTP daemon test helpers. The series targets two CGI scripts in `t/lib-httpd/` that manage shared state using non-atomic shell operations, which can fail when Apache serves concurrent requests—something that happens routinely during partial fetches or promisor object retrievals. The fix replaces the racy `test -f`/`rm`/`touch` sequences with atomic operations (`mv` for one-shot markers, `mkdir` for first-request election), making the test helpers robust against concurrent execution.

Junio C Hamano reviewed the second version of the series and deemed all patches ready for integration. The changes are confined to the test infrastructure and address a real flake observed in `t5616.47` on macOS CI runners. However, a new question from Patrick Steinhardt has stalled progress: patch 1’s v2 now silences `stderr` of `./one-time-script`, and Patrick wants to know why, as this could mask legitimate errors. Until Michael clarifies the intent, the series remains poised for `next` but isn’t yet merged.

The documentation patch (3/3) received a light review from Patrick, who suggested minor wording tweaks to the new “Writing concurrency-safe helpers” section in `t/README`. These are editorial nits—adding “lib-httpd” to the header, noting that `rm` (without `-f`) is a viable alternative to `mv`, and replacing `$$` with “PIDs” for clarity—none of which affect the technical content. The series is otherwise uncontroversial and self-contained.
