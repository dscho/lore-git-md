This thread is about a small but important fix to Git’s test infrastructure. Michael Montalbo sent a three-patch series (now at v2) to eliminate race conditions in two CGI scripts used by the HTTP daemon test helpers. The scripts, `apply-one-time-script.sh` and `http-429.sh`, manage shared state using non-atomic shell operations (`test -f` followed by `rm` or `touch`), which can fail when Apache serves concurrent requests—something that happens routinely during partial fetches or promisor object retrieval. The fix replaces these operations with atomic ones (`mv` and `mkdir`), making the test helpers robust against concurrent execution.

Junio C Hamano reviewed the series and marked it ready for integration after v2 addressed his feedback on commit-message clarity and rationale. The series is self-contained, touching only test files, and fixes a real flake observed in CI. Patrick Steinhardt raised two points in his review: a substantive question about why patch 1 redirected `stderr` to `/dev/null` (which Michael has now clarified as intentional, to suppress an expected error when the script is removed by a concurrent request) and minor editorial suggestions for the documentation in patch 3. With the error-handling rationale now explicit, the series is poised to move into Junio’s `next` branch. No further changes are expected beyond a planned code comment to document the behavior.
