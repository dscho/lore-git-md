This thread is a three-patch series from Michael Montalbo fixing race conditions in Git’s HTTP daemon test helpers, which have caused flaky test failures in CI. The series targets two CGI scripts in `t/lib-httpd/` that manage shared state using non-atomic shell operations, leading to HTTP 500 errors when concurrent requests race. The fixes replace these operations with atomic alternatives: `mv` for a one-shot marker and `mkdir` for a first-request election.

Junio C Hamano has reviewed all three patches. He endorsed the `mkdir` solution in patch 2 as "obvious" but requested clarification in the commit message about whether skipping the atomic check for `"permanent"` responses is a correctness requirement or an optimization. For patch 1, he previously asked for clearer language distinguishing between shrinking the race window and eliminating concurrent execution (the latter isn’t the goal). Patch 3, a documentation update, was praised as a "nice finishing touch" and left unchanged. No other reviews have been posted, and the series remains under review with a v2 likely to address Junio’s feedback.

The fixes are self-contained to the test infrastructure, with no user-visible changes. A new test (`t5567-one-time-script.sh`) exercises the atomic `mv` logic deterministically using FIFOs, while the `mkdir` fix is preventive—its race can’t be forced in tests. The series is motivated by a real flake in `t5616.47` on macOS CI, and the solutions align with Git’s existing lockfile and test-library idioms. Once the commit messages are clarified, the patches are expected to be uncontroversial.
