This thread is a three-patch series from Michael Montalbo that fixes race conditions in Git’s HTTP daemon test helpers, which have caused flaky test failures in CI. The series targets two CGI scripts in `t/lib-httpd/` that manage shared state using non-atomic shell operations (`test -f` followed by `rm` or `touch`). Because Apache serves requests concurrently, these operations can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, triggering an HTTP 500 error. The fixes replace the non-atomic checks with atomic operations—`rm` (without `-f`) for one-shot markers and `mkdir` for first-request election—to eliminate the races.

Junio C Hamano reviewed the series through v1 and v2, providing substantive feedback on the atomicity logic and commit messages. All concerns were addressed in v3: patch 1 now uses `rm` instead of `mv` for simplicity, patch 2 fixes a latent race in `http-429.sh` and corrects a "permanent" mode issue, and patch 3 (the subject of this email) relocates the documentation from `t/README` to `t/lib-httpd.sh` for better context, as suggested by Patrick Steinhardt. The series is self-contained, touches only test infrastructure, and includes a new test (`t5567-one-time-script.sh`) that forces the race deterministically using FIFOs. No open questions remain, and the series is ready for integration into Junio’s `next` branch.

Michael has been responsive to feedback, clarifying error-handling choices (e.g., redirecting `stderr` to `/dev/null` to suppress expected errors) and defending the generic scope of the documentation before ultimately relocating it to address Patrick’s preference. The fixes are purely internal to the test helpers and introduce no user-visible changes. The series addresses a real, observed flake in `t5616.47` on macOS CI runners, making the test suite more reliable.
