This thread is a three-patch series from Michael Montalbo (via GitGitGadget) fixing race conditions in Git’s HTTP daemon test helpers. The issue—a real flake observed in `t5616.47` on macOS CI—occurs when concurrent HTTP requests to the same CGI script (`apply-one-time-script.sh` or `http-429.sh`) race on non-atomic file operations (`test -f` followed by `rm` or `touch`), causing HTTP 500 errors. The series replaces these with atomic operations: `mv` for one-shot markers and `mkdir` for first-request election, along with per-request scratch files to prevent clobbering.

The first two patches implement the fixes and add a new test (`t5567-one-time-script.sh`) to verify the `apply-one-time-script.sh` helper deterministically. The third patch, just posted, adds documentation to `t/README` explaining the problem, the anti-pattern, and the safe idioms, with cross-references to Git’s lockfile machinery and `make_symlink()` as precedents. The series is narrowly scoped to test infrastructure, with no changes to user-facing behavior or on-disk formats, and is under review with no prior versions or recorded feedback yet. The fixes are mechanical and do not alter the scripts’ behavior under sequential execution, making this a straightforward, uncontroversial bugfix.
