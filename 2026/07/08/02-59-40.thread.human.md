This thread is a v2 patch series from Michael Montalbo that fixes race conditions in Git’s HTTP daemon test helpers. The series targets two CGI scripts in `t/lib-httpd/` that manage shared state using non-atomic shell operations, which can cause HTTP 500 errors when Apache serves concurrent requests—an issue observed as a flake in macOS CI runs.

The second patch in the series, just posted, addresses `http-429.sh`, a script that rate-limits requests by returning HTTP 429 to the first request and forwarding subsequent ones. The original implementation used a non-atomic `test -f` followed by `touch`, creating a race where concurrent requests could both bypass rate-limiting. The fix replaces this with an atomic `mkdir`, ensuring exactly one request is elected as the first. Junio C Hamano’s feedback from v1 has been fully addressed: the commit message and code comments now explicitly state that the atomic check is required for correctness in all cases, including the `"permanent"` case (which must return 429 to every request). The patch is minimal, changes only the state management logic, and is uncontroversial.

The series is now complete with v2, which also addressed Junio’s feedback on the first patch (clarifying the rationale for the atomic `mv` operation in `apply-one-time-script.sh`) and left the third patch (documentation) unchanged. No other reviews or objections have been raised, and there are no remaining open questions. The fixes are purely internal to the test infrastructure and do not affect user-visible behavior.
