This thread is about a v2 patch series from Michael Montalbo that fixes race conditions in Git’s HTTP daemon test helpers. The series targets two CGI scripts in `t/lib-httpd/` that manage shared state using non-atomic shell operations, which can race when Apache serves concurrent requests to the same endpoint—something that happens in practice during partial fetches or promisor object retrievals. The races caused HTTP 500 errors and were observed as flakes in `t5616.47` on macOS CI runners.

The fixes replace the problematic `test -f`/`rm` or `test -f`/`touch` sequences with atomic operations: `mv` for one-shot markers in `apply-one-time-script.sh` and `mkdir` for first-request election in `http-429.sh`. The v2 updates fully addressed Junio C Hamano’s feedback from v1, clarifying commit messages and code comments to distinguish between shrinking the race window and preventing concurrent script execution, and explicitly documenting the rationale for the atomic operations, including the `"permanent"` case in patch 2. A new test (`t5567-one-time-script.sh`) exercises the race deterministically using FIFOs, and `t/README` now documents the safe idioms.

Junio’s final review marks the series as ready for integration, calling patch 1 “well thought out and nicely done” and acknowledging the improved explanations in patch 2. The series is now poised to graduate to `next`; no further changes are expected. The fixes are minimal, targeted, and uncontroversial, addressing a concrete test-infrastructure problem without touching user-visible behavior.
