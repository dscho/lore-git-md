This thread is a small but important bugfix series from Michael Montalbo that eliminates race conditions in Git’s HTTP daemon test helpers. The issue affects two CGI scripts in `t/lib-httpd/` that manage shared state using non-atomic shell operations, causing intermittent HTTP 500 errors when Apache serves concurrent requests—something that happens routinely in real Git operations like partial fetches. The fix replaces the racy `test -f`/`rm`/`touch` sequences with atomic operations (`mv` for one-shot markers, `mkdir` for first-request election) and adds a new test to verify the behavior.

Junio C Hamano has reviewed the series (now at v2) and marked it ready for integration. The changes are confined to the test infrastructure and don’t affect user-facing behavior. Michael addressed all feedback from Junio and Patrick Steinhardt, including clarifying the rationale for the atomic checks and documenting the error-handling change in patch 1 (redirecting `stderr` to suppress expected errors when a script is removed by a concurrent request). The only remaining discussion was Patrick’s minor editorial suggestions for the documentation in patch 3, which Michael has now incorporated with slight adjustments to keep the guidance generic rather than HTTP-specific. The series is complete and poised for `next`.
