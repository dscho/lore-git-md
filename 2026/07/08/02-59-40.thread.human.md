This thread fixes race conditions in Git's HTTP daemon test helpers, making them robust against concurrent execution. The series, now at v3, addresses feedback from Junio C Hamano and Patrick Steinhardt on earlier versions.

Michael Montalbo identified two scripts in `t/lib-httpd/` that used non-atomic shell operations to manage shared state, causing HTTP 500 errors when Apache served concurrent requests. The fixes replace these with atomic operations: `rm` (without `-f`) for one-shot markers and `mkdir` for first-request election. Patch 2, which Patrick Steinhardt just reviewed, replaces a racy "check-and-set" in `http-429.sh` with an atomic `mkdir`, also fixing a correctness issue in the "permanent" mode. All substantive feedback has been addressed, and the series includes a new test that forces the race deterministically.

Junio previously marked the series as ready for integration, and Patrick's latest review confirms the changes are sensible without raising new concerns. The series is complete and targets only the test infrastructure, with no open questions remaining.
