This thread is about fixing race conditions in Git’s HTTP daemon test helpers that can cause flaky CI failures. Michael Montalbo sent a three-patch series to address non-atomic shell operations in two CGI scripts (`apply-one-time-script.sh` and `http-429.sh`) used by the test suite. These scripts manage shared state in a way that can race when Apache serves concurrent requests—such as during a partial fetch that lazily retrieves promisor objects—leading to HTTP 500 errors.

Junio C Hamano reviewed all three patches and provided feedback on the first two, focusing on commit-message clarity. For the first patch, he clarified that the atomic `mv` operation shrinks but doesn’t eliminate the race window for concurrent script execution, and Michael agreed to update the commit message to make this distinction explicit. For the second patch, Junio endorsed the `mkdir` solution but asked whether skipping the check for the `"permanent"` case was a correctness requirement or an optimization. Michael has now confirmed it’s a correctness issue: the original code was racy even for `"permanent"`, and the fix is required to prevent HTTP 500 errors. The third patch, which documents the atomic idioms in `t/README`, was praised as a "nice finishing touch" and left unchanged.

The series is self-contained, touching only test infrastructure (`t/` directory), and a second version is likely to address Junio’s feedback. No other reviews or objections have been raised, and the fixes are uncontested. The motivation stems from a real flake observed in `t5616.47` on macOS CI runners, where the race caused fetch failures. The new test in `t5567-one-time-script.sh` exercises the one-shot helper deterministically using FIFOs, confirming that neither request emits an empty body (which would trigger HTTP 500). The series remains under review, with no changes to user-visible behavior or on-disk formats.
