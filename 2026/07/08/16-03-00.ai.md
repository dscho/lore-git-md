This is the final patch in Tian Yuchen's v8 series migrating global configuration variables into `struct repo_config_values`. It moves the `object_creation_mode` enum (which controls whether Git uses hardlinks or renames when creating object files) into the per-repository configuration structure.

The patch relocates the `enum object_creation_mode` definition in `environment.h` to make it visible to `struct repo_config_values`, initializes the per-repository default value in `repo_config_values_init()`, and updates `git_default_core_config()` to write to the repository-specific structure instead of the global variable. The only caller (`finalize_object_file_flags()` in `object-file.c`) is updated to read the value from `repo_config_values(repo)`.

This is a clean refactoring with no user-visible behavior changes. The memory management pattern for enum values is simpler than for heap-allocated strings (no dynamic allocation or cleanup needed), so this patch does not interact with the memory leak fix that was the focus of earlier discussion. The relocation of the enum definition is mechanical and resolves the visibility issue without introducing new dependencies.

The patch completes the series' goal of migrating all targeted variables into `repo_config_values`. The only remaining loose ends are the RFC questions about program path migration and the relationship to `git_branch_track`, neither of which affect this patch. The `NEEDSWORK` comment about enum placement (carried over from patch 7/9) remains, but this patch does not worsen it.
