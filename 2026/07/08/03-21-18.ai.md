This is the second patch in the v8 Rustification build system series, introducing **macOS Universal Binary support** for Rust components via the `RUST_TARGETS` environment variable. It is part of the ongoing Rustification effort and directly addresses the need to distribute Git with native support for both Intel and Apple Silicon Macs in a single build artifact.

The patch modifies the `Makefile` to allow users to specify multiple Rust target triples (e.g., `RUST_TARGETS="aarch64-apple-darwin x86_64-apple-darwin"`). When multiple targets are provided on macOS, the build system compiles each target independently using Cargo, then combines the resulting static libraries into a single Universal Binary using `lipo`. This matches the standard macOS distribution practice and ensures Rust libraries integrate seamlessly with the existing C toolchain, which already supports Universal Binaries via `-arch` flags. The implementation is clean: it introduces `RUST_BUILD_CONFIG` to unify the target directory structure under `target/release/` or `target/debug/`, and `RUST_MEMBER_LIBS` to track per-architecture artifacts. The build remains a no-op when `RUST_TARGETS` is unset or when `NO_RUST=1` is specified, and it errors out if `RUST_TARGETS` is used on non-macOS platforms.

This is a **well-crafted, narrowly scoped feature addition** that solves a real distribution problem for macOS users. The commit message clearly explains the motivation (Universal Binaries are standard practice for macOS distribution and CI), the technical approach (Cargo’s lack of multi-arch support vs. clang’s native support), and the implementation details. The patch is part of a series that has already resolved its blocking issues (parallel build race condition in patch 1, CI verification in patch 3) and is queued in Junio’s integration branches (status: under review, in `next`). The only open question—Patrick Steinhardt’s concern about the `target/` directory structure—is not a blocker and does not affect functionality.

Key technical details for follow-up discussion: the patch introduces `RUST_TARGETS` (user-facing), `RUST_BUILD_CONFIG` (internal, unifies `target/release/` and `target/debug/`), `RUST_MEMBER_LIBS` (internal, tracks per-architecture artifacts), and `mkdir_p_parent_template` (helper for directory creation). The build system now places the universal library in `target/release/libgitcore.a` (or `target/debug/`), while per-architecture artifacts land in `target/<triple>/release/`. This layout is functionally complete and aligns with practical macOS distribution needs, though Patrick’s proposal to unify under `target/$BUILD_CONFIG/<triple>/` remains unresolved. The patch assumes `lipo` is available (part of Xcode Command Line Tools) and enforces macOS-only usage of `RUST_TARGETS`. No on-disk format changes or new tests are introduced.
