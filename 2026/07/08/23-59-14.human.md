This is the v3 submission of a well-scoped infrastructure refactoring series that replaces `tmp_objdir` usage in `git receive-pack` with the newer `odb_transaction` subsystem. The goal is to make `receive-pack` ODB-backend-agnostic, advancing Patrick Steinhardt’s ongoing ODB abstraction effort. This version is a routine respin to pick up Reviewed-by trailers and minor wording tweaks; there are no code changes from v2.

The series is functionally complete, with all 11 patches reviewed and integrated. Two design-level concerns remain deferred to future work: a header dependency question (whether `odb/transaction.h` and `odb/source.h` should be merged) and a latent transaction-leak in `odb_transaction_commit()`. Both are acknowledged by the author and subsystem owner, and neither blocks integration. Patrick Steinhardt’s v2 reply signals strong approval: “I’ve got a couple smaller nits, but overall I’m quite happy with the shape of this series now.”

Key changes since v1 include consistent naming for transaction helpers, proper error-code propagation throughout the transaction lifecycle, and a new `ODB_TRANSACTION_RECEIVE` flag to preserve `receive-pack`’s existing behavior (eager directory creation, “incoming” prefix) during the transition. The final patch (11/11) converts `receive-pack` to use the new interfaces, removing the global `tmp_objdir` variable and replacing it with a local `struct odb_transaction *`. The temporary directory is no longer added as an alternate; instead, the transaction’s object directory becomes the primary ODB in the main process, preserving quarantine semantics.

The patch touches 14 files, with the heaviest changes in `object-file.c` (159 lines) and `builtin/receive-pack.c` (69 lines). New or modified interfaces include `odb_transaction_begin()`, `odb_transaction_commit()`, and `odb_transaction_env()`, all of which now return `int` for error propagation. The series is queued for `next` pending integration; no objections remain to the approach or goals. The changes are mechanical but non-trivial, with thorough error propagation and interface updates. Test coverage remains unchanged, relying on the existing test suite to exercise `receive-pack` and its child processes.
