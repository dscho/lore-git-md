This is patch 7/11 in Justin Tobler’s v2 series converting `git-receive-pack` to use ODB transactions. The patch changes `odb_transaction_commit()` to return an `int` so backends can signal commit failures, but Patrick Steinhardt spots a latent issue: the function now frees the transaction *before* returning any backend error, so a failing commit leaks the transaction object.

The leak is not new—it existed in the old `void` version—but the error-return conversion makes it more visible. Patrick compares it to Git’s reference-transaction lifetime bugs, where automatic cleanup on commit caused similar problems. He explicitly says the issue predates this series and can be deferred, so the patch itself is still acceptable. The observation is a heads-up for future work rather than a blocker.
