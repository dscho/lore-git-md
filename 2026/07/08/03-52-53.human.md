This is the second patch in Jeff King’s seven-part series refactoring the `git_hash_*()` API. The series aims to standardize usage of Git’s hash functions by replacing direct calls to low-level function pointers (like `algo->update_fn()`) with wrapper functions (`git_hash_update()`, etc.). This patch focuses on the remaining wrappers beyond `git_hash_init()`, which was addressed in the first patch.

The patch mechanically converts all direct calls to `update_fn`, `clone_fn`, `final_fn`, `final_oid_fn`, and `discard_fn` across the codebase to their corresponding wrapper functions. The Coccinelle semantic patch (`tools/coccinelle/hash.cocci`) enforces this change, ensuring consistency and preventing regressions. A minor cleanup in `t/helper/test-synthesize.c` removes an unused function parameter, as the wrapper functions no longer require passing the `algo` pointer separately.

The changes are straightforward and risk-free: the wrapper functions delegate to the same underlying implementations, so behavior remains unchanged. The patch reduces boilerplate and makes the code more maintainable by centralizing hash API usage. No user-visible impact is expected, and the patch is ready for integration. The only files touched are `builtin/submodule--helper.c`, `t/helper/test-synthesize.c`, and the Coccinelle rule itself. Review feedback on the first version was minimal and addressed in this update.
