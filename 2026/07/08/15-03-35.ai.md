This is the second patch in the v2 series fixing the bundle-URI protocol implementation. It prevents Git servers from advertising invalid bundle configuration (specifically empty URIs) to clients, complementing the client-side resilience added in patch 1.

The change modifies `bundle-uri.c` to silently filter out bundle configuration lines where the value is empty during the configuration-to-packet conversion. When such invalid configuration is encountered, the server logs a warning (`config '%s' has no value`) but does not transmit it to the client. This matches the technical consensus reached in earlier discussion: silent filtering is preferred over visible error reporting to avoid breaking the protocol stream.

The patch adds a new test case in `t/lib-bundle-uri-protocol.sh` that verifies the server correctly omits empty URI values from its response while preserving valid configuration. The test sets up a repository with both valid and empty bundle URIs, then confirms the server only advertises the valid one.

This is a straightforward, well-scoped fix that addresses the server-side half of the problem. The implementation is clean and aligns with the project's preference for silent filtering in protocol handlers. The only remaining edge case (bundles with missing mandatory fields like `uri`) is explicitly documented as out of scope, with the client already handling such cases appropriately. The patch is unlikely to be controversial as it doesn't change fundamental behavior—just prevents misconfigurations from propagating.
