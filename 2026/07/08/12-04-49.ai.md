This is a follow-up in the `git history reword` feedback discussion, focusing on output format and operational safety. Patrick Steinhardt responds to D. Ben Knoble’s review, agreeing in principle with the need for feedback but expressing reservations about how to represent results consistently across all reference updates (not just HEAD). He remains open to emitting output if a clear, user-friendly format can be designed.

The key technical points are: (1) feedback must cover *all* updated refs, not just HEAD; (2) the command intentionally allows rewriting unreachable commits, so any "strict" mode should be opt-in rather than enforced; (3) if strict mode is introduced, it should default to on but be disableable with a flag. Steinhardt’s position aligns with the thread’s broader consensus on silent success for no-op cases but adds implementation-level nuance: the feedback mechanism must scale to detached HEAD and `--update-refs` scenarios, and safety checks should not break existing workflows. This reply keeps the discussion concrete, moving toward a design where feedback is mandatory but strictness is configurable.
