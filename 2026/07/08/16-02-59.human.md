This is part of a refactoring series (v8, 8/9) that continues the libification effort by moving global configuration variables into `struct repo_config_values`. This specific patch migrates the `autorebase` setting, which controls whether newly created branches default to automatic rebasing, from a global variable into the per-repository configuration structure.

The patch moves the `enum rebase_setup_type` definition higher in `environment.h` to make it visible to `struct repo_config_values`, then updates `repo_config_values_init()` to initialize `autorebase` to `AUTOREBASE_NEVER`. The configuration parsing in `git_default_branch_config()` is adjusted to write directly to the repository's configuration instance rather than the global variable. The only caller (`should_setup_rebase()` in `branch.c`) is updated to read the value from `repo_config_values(the_repository)` instead of the global.

This is a clean, mechanical change that follows the established pattern from earlier patches in the series. The commit message clearly explains the motivation and the specific adjustments made. There are no user-visible behavior changes, and the patch is well-scoped to its single purpose. The memory management concerns raised in earlier iterations of the series do not apply here since `autorebase` is an enum, not a heap-allocated string.

The patch is part of the broader `the_repository` removal effort and builds directly on the recently merged `excludes_file` migration. It looks ready for integration once the series as a whole is reviewed.
