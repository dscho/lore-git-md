This is the third patch in Justin Tobler’s v3 ODB transaction series (11 patches total). It eliminates the standalone `flush_loose_object_transaction()` helper by embedding its logic directly into `odb_transaction_files_commit()`. The change is purely mechanical: the hardware-flush (`fsync`) and directory-migration (`tmp_objdir_migrate`) steps are now performed inline, reducing indirection in the transaction lifecycle.

The motivation is clarity: the old helper name was misleading because it performed both hardware flushing *and* object migration, which conceptually belongs in the commit phase. The commit message now explicitly states this rationale, addressing Patrick Steinhardt’s earlier question about the helper’s purpose. No behavioral changes are introduced; the patch is a refactoring to improve code organization.

The diff touches only `object-file.c`, moving 36 lines of logic (including comments) from the helper into the commit function. The change is uncontroversial and has been reviewed by Patrick, who signaled strong approval for the series in his v2 reply. This patch is part of the larger ODB abstraction effort and is queued for `next` alongside the rest of the series.
