This is the final patch in Justin Tobler’s v3 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch removes the global `tmp_objdir` variable and replaces it with a local `struct odb_transaction *` that is created at the start of the unpack phase (`odb_transaction_begin` with the `ODB_TRANSACTION_RECEIVE` flag) and committed just before reference updates (`odb_transaction_commit`). The temporary directory is no longer added as an alternate; instead, the transaction’s object directory becomes the primary ODB in the main process, preserving quarantine semantics.

The change is non-regressive: objects are staged in an "incoming" directory and migrated to the main object store only after pre-receive hooks and connectivity checks pass, matching the existing behavior. Error handling is consistent with the rest of the series—failures during transaction begin or commit are surfaced as command errors. The patch touches only `builtin/receive-pack.c`, removing the `tmp-objdir.h` include and updating the unpack, hook, and connectivity-check paths to use the new `odb_transaction_env` interface.

This is a clean, well-scoped conversion that completes the series’ goal of making `receive-pack` ODB-backend-agnostic. The author has addressed all prior feedback, and Patrick Steinhardt (the ODB subsystem owner) has signaled strong approval for the series as a whole. The patch is ready for `next` and looks like a straightforward integration.
