This is the second patch in Justin Tobler’s v2 series (11 patches total) converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It is a **purely mechanical refactoring** of the "files" ODB backend: the `fsync_loose_object_transaction()` helper is renamed to `odb_transaction_files_fsync()` to align with the naming scheme established in the first patch (`odb_transaction_files_prepare()`). The conditional guarding the fsync logic is also slightly reordered for clarity, but **behavior is unchanged**—the function still issues a writeout-only fsync during the transaction and a full hardware flush at commit time.

The patch touches only `object-file.c` (16 lines, 10 insertions, 6 deletions) and updates two call sites: the `flush_batch_fsync` helper and the `close_loose_object` function. The commit message explicitly states that no functional change is intended, and the diff confirms this—only symbol names and control-flow structure are altered. This is part of the series’ broader goal of making the ODB transaction API more consistent before deeper behavioral changes (like error propagation) are introduced in later patches.

The patch is **well-scoped and uncontroversial**; it directly addresses feedback from v1 about naming consistency and is queued for `next` alongside the rest of the series. No new technical concerns are raised here, and the change is small enough to be easily verified. Future work (deferred to follow-up series) will tackle error-handling improvements and lazy directory creation, but this patch is purely preparatory.
