This is a follow-up in Justin Tobler’s ODB transaction series, specifically addressing the latent transaction-leak issue Patrick Steinhardt identified in patch 7/11. The exchange confirms the bug: `odb_transaction_commit()` frees the transaction *before* returning any backend error, so a failing commit leaks the transaction object. The leak predates this series (it existed in the old `void` version) but becomes more visible with the error-return conversion.

Justin acknowledges the issue and plans to fix it in the next version by clearing the transaction even on failure. Patrick compares this to Git’s reference-transaction lifetime bugs, where automatic cleanup on commit caused similar problems, and suggests introducing a separate `odb_transaction_release()` function to make the lifecycle explicit. Justin agrees and notes this could be added alongside `odb_transaction_abort()` in a follow-up series he is already working on.

The discussion is purely about cleanup mechanics and does not affect the series’ core goal (converting `receive-pack` to use ODB transactions). The fix is straightforward and uncontroversial, but the observation about transaction lifetime management may influence future ODB abstraction work. No code changes are included in this email; the resolution is deferred to a later iteration.
