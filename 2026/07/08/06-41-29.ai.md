This is a review reply in the ODB transaction refactoring series. Patrick Steinhardt (the ODB subsystem owner) accepts Justin Tobler’s patch 4/11, which removes redundant validation from the "files" backend’s transaction-start logic.

The patch deletes a four-line guard in `odb_transaction_files_begin()` that checked whether a transaction was already in progress. The commit message explains this check is redundant because the generic `odb_transaction_begin()` layer already enforces the same rule. Patrick’s reply explicitly endorses the change as a fix for a layering violation: the "files" backend should not need to know about object-database-level state, which is properly managed by the ODB layer itself. His feedback is substantive but brief, confirming the patch’s technical rationale without raising new concerns.

This patch is part of Justin’s v2 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. Patch 4/11 is a clean, mechanical simplification with no behavioral change, and Patrick’s acceptance removes the last open question on this part of the series. The patch is now effectively ready for integration, pending resolution of the one remaining open question on patch 3/11 (about the motivation for eliminating `flush_loose_object_transaction()`).
