This is the final patch in a three-patch bugfix series targeting race conditions in Git’s HTTP daemon test helpers. The series addresses a real, observed flake in `t5616.47` where concurrent HTTP requests to the same CGI script caused HTTP 500 errors due to non-atomic file operations. Earlier patches in the series replaced the racy `test -f`/`rm` and `test -f`/`touch` sequences with atomic operations (`mv` for one-shot markers, `mkdir` for first-request election), and this patch documents those idioms for future test authors.

The patch adds a new section to `t/README` titled "Writing concurrency-safe helpers," explaining the problem (concurrent processes cannot assume exclusive file access), the anti-pattern (check-then-act sequences), and the two safe operations. It also notes the use of `$$` suffixes to prevent scratch-file clobbering and links the idioms to Git’s own lockfile machinery (`O_CREAT|O_EXCL`) and `make_symlink()` in `t/test-lib.sh` as precedents. A brief pointer in `t/lib-httpd.sh` directs readers to the new documentation. Junio C Hamano’s review is positive, calling it a "nice finishing touch," with no further changes requested. The documentation is clear, concise, and grounded in the real examples from the series, making it immediately useful for contributors writing concurrent test code. This is a straightforward, well-motivated addition with no controversy or open questions.
