This is a refactoring patch in the ODB transaction subsystem, part of Justin Tobler’s ongoing series to replace `tmp_objdir` usage in `git-receive-pack` with ODB transactions. Patch 4/11 removes redundant validation from the "files" backend.

The patch deletes a four-line check in `odb_transaction_files_begin()` that prevented starting a new transaction if one was already in progress. The commit message explains that this check is redundant because the generic `odb_transaction_begin()` layer already enforces the same rule. The change touches only `object-file.c` and `object-file.h`, removing the `if (odb->transaction) return NULL;` guard and updating the function’s header comment to drop the "If a transaction is already pending, NULL is returned" clause.

This is a clean, mechanical simplification with no behavioral change. The generic transaction layer’s validation remains in place, so the safety invariant (only one transaction per ODB) is preserved. The patch is well-motivated and uncontroversial; it directly addresses feedback from the v1 review cycle to eliminate duplication. No test coverage is affected, and the change is queued for `next` alongside the rest of the series.
