This is the fifth patch in Justin Tobler’s v2 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It propagates errors from the "files" transaction backend’s `prepare`, `begin`, and `commit` steps so callers can handle failures explicitly rather than silently ignoring them.

The patch changes three functions in `object-file.c` from `void` to `int`, returning `-1` on failure. `odb_transaction_files_prepare()` now reports `tmp_objdir_create()` failures, and `odb_transaction_files_commit()` reports `tmp_objdir_migrate()` failures. The `odb_transaction_files_begin()` interface is updated to return an error code and populate the output parameter via pointer, matching the pattern used elsewhere in the ODB transaction layer. The changes are mechanical and confined to the transaction lifecycle; no behavior changes beyond error propagation.

This is a well-motivated refactoring that addresses a latent robustness issue. The commit message clearly explains the problem (silently ignored errors) and the solution (propagating errors to callers). The patch is small, focused, and touches only the transaction backend’s internal interfaces. It is part of the ODB abstraction effort and builds on earlier patches in the series that introduced error propagation in the generic transaction layer. No controversy or open questions remain; this looks like a straightforward improvement.
