This is patch 6/9 of Tian Yuchen's v8 series migrating global configuration variables into `struct repo_config_values`. It moves the `apply_default_whitespace` and `apply_default_ignorewhitespace` variables—used by `git apply` to store default whitespace handling settings—into the repository-scoped configuration structure.

The patch updates `git_apply_config()` to accept a `struct repository *` parameter (removing its reliance on `the_repository`), initializes the new fields in `repo_config_values_init()`, and ensures proper cleanup in `repo_config_values_clear()`. Callers in `apply.c` now access these values through `repo_config_values(repo)-><field>` instead of the former globals. The memory leak fix introduced in earlier patches (freeing old values before re-assignment) is extended here to cover these two new string fields.

This is a mechanical but important step in the libification effort. The changes are confined to `apply.c`, `environment.c`, and `environment.h`, with no user-visible behavior changes. The patch follows the established pattern from earlier migrations in the series, reinforcing the memory management discipline that resolved Junio's v7 concern. No new RFC questions or `NEEDSWORK` comments are introduced; this is purely infrastructure work.
