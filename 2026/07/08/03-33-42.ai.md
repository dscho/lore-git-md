This is a bugfix patch for the submodule subsystem.

The patch restores support for the `-i` shorthand flag in `git submodule update`, which has been broken since Git v2.49. The regression was introduced by commit 3ad0ba722744 ("git-submodule.sh: improve variables readability"), which made the shell script pass `-i` directly to `submodule--helper`, but the helper did not recognize the short option. The fix is a one-line change in `builtin/submodule--helper.c`, adding `'i'` as an alias for the `--init` option in the `module_update_options` array.

The commit message notes that this short option is not documented in the help text, but since it previously worked, the author argues it should be fixed for consistency. The patch is minimal and targeted, touching only the option parsing logic in the submodule helper. While the impact is likely limited due to the lack of documentation, it addresses a clear regression and aligns the helper’s behavior with the shell script’s expectations.

This is a standalone patch, not part of a larger series. The change is straightforward and unlikely to be controversial, though its practical value may be modest given the option’s obscurity. The patch includes a `Fixes:` trailer pointing to the regressing commit, which is a good practice for tracking purposes.
