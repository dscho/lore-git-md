This is the final patch in the v7 Rustification build system series, now under review for a minor but important fix. The patch adds CI verification for the macOS credential helper (`git-credential-osxkeychain`) by wiring it into `contrib/Makefile` so it is built and tested during standard CI runs on macOS when `TEST_CONTRIB_TOO=yes` is set. The change is straightforward and uncontroversial, but Junio has raised a technical question about the Makefile inclusion order.

The patch adds `credential/osxkeychain` to the `OS_CONTRIB` variable when running on Darwin, then includes it in the `all`, `test`, and `clean` targets of `contrib/Makefile`. The `osxkeychain/Makefile` itself gains a new `test` target that depends on building the helper, ensuring the build and link steps are exercised. This closes a gap where the helper was previously excluded from automated testing, despite being a critical component for macOS users.

Junio’s feedback points out that the patch only includes `../config.mak.autogen` and `../config.mak`, but not `../config.mak.uname`, which defines `uname_S`. The top-level Makefile includes these in a specific order (`config.mak.uname` first), and Junio suggests the contrib Makefile should follow the same pattern to ensure `uname_S` is defined correctly. This is a surface-level but important correctness issue, as the conditional inclusion of the macOS helper depends on `uname_S` being set.

The rest of the patch is sound: it touches only build infrastructure, introduces no new behavior or on-disk changes, and uses the existing `TEST_CONTRIB_TOO` mechanism for CI coverage. The series as a whole (v6, which is functionally identical to v7) is already queued in Junio’s integration branches and is likely to graduate to `next` once this minor Makefile inclusion issue is resolved. This patch is a small but necessary housekeeping improvement for the Rustification effort, ensuring future regressions in the macOS credential helper are caught early.
