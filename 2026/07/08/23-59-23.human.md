This is the ninth patch in Justin Tobler’s v3 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch introduces `enum odb_transaction_flags` and the `ODB_TRANSACTION_RECEIVE` flag to preserve `receive-pack`’s existing behavior—eager directory creation and the "incoming" prefix—during the transition.

The change is purely plumbing: it adds a flags parameter to the transaction interface (`odb_transaction_begin`, `odb_transaction_begin_or_die`, and backend callbacks) and updates all call sites to pass `0` (no flags). The "files" backend checks for `ODB_TRANSACTION_RECEIVE` and adjusts its temporary directory setup accordingly. No user-facing behavior changes; the patch exists solely to maintain compatibility while the refactoring is in progress.

The patch touches 13 files, mostly mechanical updates to pass the new flags parameter. The only substantive logic is in `odb_transaction_files_begin`, where the "files" backend uses the flag to set the prefix and eagerly create the directory. The commit message documents the flag as a temporary measure and notes that future work could unify the behavior across all transactions.

This patch is part of the ODB abstraction effort led by Patrick Steinhardt. The series is functionally complete and queued for `next`; this patch specifically addresses the deferred header dependency concern by introducing the enum, though the discussion about merging `odb/transaction.h` and `odb/source.h` remains open. The patch is uncontroversial and ready for integration.
