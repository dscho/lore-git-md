This is the second patch in the v8 series adjusting Git's build system to support **macOS Universal Binaries** for Rust components, part of the broader Rustification effort. The patch introduces the `RUST_TARGETS` environment variable, allowing users to specify multiple target triples (e.g., `x86_64-apple-darwin aarch64-apple-darwin`) for cross-compilation. On macOS, the build system compiles separate static libraries for each target and combines them into a single Universal Binary using `lipo`, ensuring compatibility with both Intel and Apple Silicon Macs without Rosetta emulation.

The implementation is clean and well-scoped, touching only the `Makefile` to add declarative pattern rules for per-target compilation and a `lipo`-based merge step. The patch maintains backward compatibility: if `RUST_TARGETS` is unset, the build falls back to the default single-target behavior. It also enforces macOS-only usage of `RUST_TARGETS` with a clear error message for other platforms, avoiding silent failures. The commit message provides a clear rationale and technical context, explaining why this approach is necessary (Cargo's lack of native multi-arch support) and how it integrates with the existing C toolchain.

This is a **practical, user-facing improvement** for macOS users and CI systems that distribute Git packages. The patch is **ready for integration**, with no unresolved technical concerns—Patrick Steinhardt's earlier question about artifact layout (unrelated to this patch) remains open but does not block this change. The series as a whole is already queued in Junio's `next` branch, and this patch is a key enabler for the macOS credential helper's Universal Binary support.
