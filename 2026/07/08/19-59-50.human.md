This is the final patch in a three-part bugfix series that eliminates race conditions in Git’s HTTP daemon test helpers. The series targets a real, observed flake in the test suite (`t5616.47`) where concurrent HTTP requests to the same CGI script caused HTTP 500 errors due to non-atomic file operations.

This patch adds a new section to `t/README` titled "Writing concurrency-safe helpers," documenting the atomic idioms introduced in the earlier patches. The documentation explains the problem (concurrent processes cannot assume exclusive file access), the anti-pattern (`test -f` followed by `rm` or `touch`), and the two safe operations: `mkdir` for electing a single "winner" among concurrent requests, and `mv` (rename) for consuming a one-shot marker. It also notes the use of `$$` suffixes to prevent clobbering of scratch files and links the idioms to Git’s own lockfile machinery (`O_CREAT|O_EXCL`) and `make_symlink()` in `t/test-lib.sh` as precedents. A brief pointer is added to `t/lib-httpd.sh` to direct readers to the new documentation.

The earlier patches in the series received substantive review, with Junio requesting only a minor clarification in the commit message for the first patch. This patch is purely documentation and does not change any code behavior, making it a straightforward and uncontroversial addition.
