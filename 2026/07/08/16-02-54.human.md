This is a refactoring patch (part 3 of 9 in v8) that migrates the global `editor_program` variable into `struct repo_config_values`. It continues the libification effort by eliminating mutable global state, preparing the codebase for long-running processes that manage multiple repositories concurrently.

The patch moves `editor_program` into `repo_config_values` and updates the code to access it via `repo_config_values(the_repository)->editor_program`. Memory management is handled by `repo_config_values_clear()`, which now frees the field during repository teardown. The commit message acknowledges the RFC discussion about whether per-repository editor configuration is worthwhile, arguing that developers often use different toolchains for different projects and that eliminating globals is necessary for modularity.

This is a clean, mechanical change with no user-visible behavior impact. The memory leak fix from v8 (properly freeing old values during re-assignment) is reflected here in the `git_config_string(&cfg->editor_program, ...)` call. The patch touches `editor.c`, `environment.c`, and `environment.h`, and follows the established pattern from the earlier `excludes_file` migration.

The series as a whole looks technically solid and ready for `next`. This specific patch is uncontroversial and aligns with the project's ongoing `the_repository` removal goals.
