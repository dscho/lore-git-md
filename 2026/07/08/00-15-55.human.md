This is the second patch in the now-merged four-patch series that standardizes help-flag exit codes across Git’s parse-options infrastructure. The series as a whole is a well-motivated bugfix addressing a long-standing inconsistency: `--help`/`-h` now exits 0 (Unix convention) instead of 129 for all commands using parse-options, including `git rev-parse --parseopt` in shell-eval mode.

This specific patch introduces a new return code, `PARSE_OPT_HELP_ERROR`, to distinguish between help output triggered by user request (`--help`) and help output triggered by invalid input (e.g., ambiguous options). The change is mechanical but important: it ensures that future patches can safely switch user-requested help to exit 0 without accidentally masking real errors. The patch updates `parse-options.c`, `parse-options.h`, and three built-in commands (`git blame`, `git shortlog`, `git update-index`) to handle the new return code, and it closes the refactoring gap in `usage_with_options_internal()` that Peff identified in review.

The implementation is clean and targeted. The new return code is inserted into the existing enum with minimal disruption (shifting `PARSE_OPT_COMPLETE` from -3 to -4), and the logic in `usage_with_options_internal()` now consistently returns `PARSE_OPT_HELP_ERROR` when `err` is set, ensuring uniform behavior across all help-output contexts. The patch also updates the ambiguous-option case in `parse_long_opt()` to return `PARSE_OPT_HELP_ERROR` instead of `PARSE_OPT_HELP`, which is the correct distinction for error-triggered help.

This patch is part of a fully merged series, and the thread context confirms that all post-merge issues—including the prerequisite logic flaw and shell-quoting bug—have been resolved in this v3 revision. The trade-offs (wrapped commands and shell-eval edge cases) are documented and accepted, and the series has been endorsed by Junio as a regular bugfix. For readers tracking the exit-code standardization effort, this patch is the technical foundation that makes the broader behavioral change safe and maintainable.
