This is the first patch in the v8 series migrating more global configuration variables into `struct repo_config_values`. It introduces `repo_config_values_clear()`, a destructor function to free heap-allocated strings in the struct when a repository is torn down. The immediate focus is `attributes_file`, but the function is designed to scale as more variables are migrated.

The patch adds the new function in `environment.c`, declares it in `environment.h`, and wires it into `repo_clear()` in `repository.c`. A guardrail prevents crashes when `repo_clear()` is called on submodules: since `repo_config_values()` currently BUG()s out for non-`the_repository` instances, the destructor silently returns early. This limitation is marked `NEEDSWORK` but is not a blocker for the series.

The implementation is straightforward and follows the pattern established in the recently merged `excludes_file` migration. The memory leak fix from v8 (proper cleanup of heap-allocated strings during re-assignment) is not yet visible here—it will appear in later patches—but this patch lays the groundwork by ensuring all future migrated strings can be freed. No user-visible behavior changes; this is purely infrastructure for the libification effort.
