This is the final patch in a now-merged four-patch bugfix series that aligns Git’s help-flag exit codes with Unix conventions. The patch changes all commands using the parse-options API to exit 0 (success) when `-h` or `--help` is given, instead of the long-standing 129 (error) exit code. The commit updates 37 test files to expect the new behavior, adjusts three built-in commands (`git blame`, `git shortlog`, `git update-index`) to handle the change, and modifies the core `parse-options.c` and `usage.c` files to implement the fix.

The change is straightforward: when a user requests help, the program should exit successfully, printing the help text to standard output. This matches the Unix philosophy and resolves a 17-year inconsistency in Git’s behavior. The patch also handles edge cases where commands behave differently for `-h` versus `--help-all`, ensuring those cases are tested appropriately.

This is a well-motivated, system-wide bugfix with thorough test coverage. The series was carefully reviewed and is now fully merged, so no further discussion is expected. If you maintain scripts that check Git command exit codes, you may need to update them to expect exit 0 for help requests.
