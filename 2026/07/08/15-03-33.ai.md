This is a two-patch bugfix series targeting the bundle-URI protocol implementation. It addresses a usability issue where Git clients fail with confusing "expected 'packfile'" errors when servers advertise invalid bundle-URI data (empty URIs), while also preventing servers from advertising such invalid data in the first place.

The series combines both client-side resilience and server-side validation, reflecting the technical consensus reached in earlier discussion. Patch 1 (by Toon Claes) modifies `get_remote_bundle_uri()` to drain the protocol stream after encountering invalid bundle-URI lines, ensuring the client can continue with the clone operation while still reporting the configuration error. Patch 2 (by Justin Tobler) adds server-side validation to silently filter out empty URIs during bundle configuration-to-packet conversion.

Key technical details include: the changes touch the bundle-URI protocol implementation in `bundle-uri.c` and `connect.c`, maintain the optional nature of bundle-URIs, and add test coverage for both missing and empty URI cases. The implementation is clean and well-motivated, with expanded inline comments and test cases that verify both the error reporting and the absence of the confusing "expected packfile" message.

The series appears ready for review, with the main open question being whether the server-side validation should silently filter invalid URIs or provide more visible error reporting to administrators. This is a practical implementation detail rather than a fundamental disagreement, as all participants agree on the combined approach. The patches are unlikely to be controversial as they don't change the fundamental behavior - they just make error handling more robust while preventing misconfigurations from propagating.
