This is the final patch in the v7 Rustification build system series, now under review for a minor but important fix. The patch adds CI verification for the macOS credential helper (`git-credential-osxkeychain`) by wiring it into `contrib/Makefile` so it is built and tested during standard CI runs on macOS when `TEST_CONTRIB_TOO=yes` is set. The series as a whole—fixing a parallel build race condition, adding Universal Binary support for Rust components, and now this CI verification—is functionally complete and queued in Junio’s integration branches (v6, which is identical to v7).

Junio’s reply identifies a **build system correctness issue**: the patch includes `config.mak.autogen` and `config.mak` but omits `config.mak.uname`, which defines `uname_S`. Without it, the `ifeq ($(uname_S),Darwin)` conditional will not work, and the macOS credential helper will not be included in the build even on macOS. This is a straightforward oversight—`contrib/Makefile` does not currently include `config.mak.uname`, but the top-level `Makefile` does, and the same order should be followed here. The fix is mechanical and uncontroversial; it does not affect the patch’s core goal of CI verification but ensures the conditional logic works as intended.

The rest of the patch is sound: it adds `credential/osxkeychain` to the `OS_CONTRIB` variable on Darwin, then includes it in the `all`, `test`, and `clean` targets of `contrib/Makefile`. The `osxkeychain/Makefile` gains a new `test` target that depends on building the helper, ensuring the build and link steps are exercised. This closes a gap where the helper was previously excluded from automated testing, despite being a critical component for macOS users.

The series is otherwise ready for integration. The blocking parallel build race condition and Universal Binary support are resolved, and the artifact layout question raised by Patrick Steinhardt remains open but is not a blocker. This patch is a minor but important housekeeping improvement, ensuring future regressions in the macOS credential helper are caught early. The fix for the missing `config.mak.uname` include is trivial and should not delay the series.
