This patch is part of Justin Tobler’s ODB abstraction refactoring series, specifically patch 7/11 in v3. It converts `odb_transaction_commit()` from a `void` function to one that returns an `int` error code, allowing backends to signal commit failures (e.g., when the "files" backend cannot migrate its temporary object directory). The change is mechanical: the backend’s commit callback now returns an error, which `odb_transaction_commit()` forwards to the caller. The transaction is freed unconditionally, even on failure—a latent leak that predates this series but becomes more visible with the error-return conversion. This issue is acknowledged and deferred to follow-up work, where Justin plans to clear the transaction even on failure and Patrick Steinhardt suggests introducing a separate `odb_transaction_release()` function for explicit lifecycle management.

The patch touches only `odb/transaction.c` and `odb/transaction.h`, updating the function signature and adding a trivial NULL check. No behavioral change occurs in this patch alone; the error propagation becomes meaningful only when backends implement failure cases (handled in later patches). The commit message explicitly ties this change to the upcoming `git-receive-pack` conversion, where transaction failures must be surfaced to users. Patrick Steinhardt’s prior review signals strong approval of the series, and this patch is queued for `next` alongside the rest of the functionally complete series.
