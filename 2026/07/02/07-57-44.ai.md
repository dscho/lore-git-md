This is the first patch in Jeff King’s 9-patch **bugfix series** addressing memory leaks in Git’s hash implementations when using non-default backends like OpenSSL SHA-256 or libgcrypt. This specific patch removes the now-unused `discard_hashfile()` function, which was introduced in a prior commit but rendered redundant by a parallel cleanup effort.

The patch is a **refactoring cleanup** that simplifies the `csum-file` API by eliminating a redundant function. The author explains that `discard_hashfile()` and `free_hashfile()` served nearly identical purposes, differing only in whether they closed file descriptors. After analyzing the three existing callers, Peff concludes that `free_hashfile()` is the better choice because it avoids potential double-close bugs (e.g., when descriptors are owned by a `tempfile` struct) and aligns with how callers already manage descriptors. The discarded function’s descriptor-closing behavior was also irrelevant for current use cases, as no callers use the `check_fd` field.

The change is small (10 lines removed) and uncontroversial, but it sets the stage for later patches in the series that will modify `free_hashfile()` to address hash-context leaks. The commit message is thorough, detailing the history of the redundant function and the rationale for preferring `free_hashfile()`. No test changes are needed, as this is purely an internal API adjustment.
