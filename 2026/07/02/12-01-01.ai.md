This is the eighth patch in a nine-patch series that makes `GIT_TEST_LONG` tests reliable and efficient enough to run in CI. This specific patch disables the RAM disk workaround on macOS GitLab CI jobs to prevent out-of-memory errors when running expensive tests that write large amounts of data.

The patch removes the RAM disk setup from `.gitlab-ci.yml`, which was originally added to work around slow macOS disks. The RAM disk was limited to 4 GB, but enabling `GIT_TEST_LONG` (done in the next patch) causes tests to write up to 8 GB of data, leading to `ENOSPC` errors. While the RAM disk could theoretically be expanded (the runners now have 16 GB of RAM), test runs showed this approach remains flaky. Disabling the RAM disk increases job runtime (from 18–21 minutes to 25–33 minutes), but the macOS jobs are not the slowest in the pipeline, so the trade-off is acceptable for stability.

The change is minimal: it removes the `TEST_OUTPUT_DIRECTORY` override and the `before_script` steps that created the RAM disk, defaulting to `/tmp/test-output` instead. The patch is well-justified by the observed flakiness and the need to accommodate larger test data volumes. No objections or alternatives have been raised yet. This is a CI/build system patch with no user-facing impact.
