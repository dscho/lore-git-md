This is the **third and final patch in v6 of the `git replay --linearize` series**, which implements the core functionality and documents the behavior. The patch is now **focused on fixing the critical post-merge issues** from v5: the silent commit-dropping regression, merge commit divergence handling, and CLI design justification.

The patch adds the `--linearize` option to `git replay`, which flattens the commit topology into a single linear history by dropping merge commits and replaying all reachable commits in a first-parent walk. This is **intentionally distinct** from `git rebase --no-rebase-merges`—the design choice is to produce a **single linear sequence** even when replaying multiple revision ranges, which may duplicate shared history. The commit message and documentation now **explicitly justify this behavior** and clarify edge cases, addressing Patrick Steinhardt’s demand for documented rationale.

Key changes in this patch:
- **Core logic**: The `replay_revisions()` function is updated to handle `--linearize` by skipping merge commits (leaving `last_commit` unchanged) and replaying non-merge commits onto `last_commit` (not their original parent). This ensures a single linear history.
- **Documentation**: The `git-replay` man page now explains that `--linearize` stacks all revision ranges into one line, updates refs to their position in that line, and drops merge commits while preserving both sides of divergent merges. The rationale for the `--linearize` naming (vs. `git rebase`'s `--rebase-merges`) is included.
- **Test coverage**: The test suite is **expanded significantly** to verify:
  - Linearization of merge commits (e.g., `topic-with-merge`).
  - Handling of root commits (replaying down to an unrelated root).
  - Multiple divergent branches (ensuring all commits are replayed, not just tips).
  - Divergent merges (verifying both sides are preserved).
  - `--contained` with `--linearize` (updating contained refs correctly).
  - Patch equivalence (using `range-diff` to confirm replayed commits produce identical patches).

**Technical details**:
- **Functions**: `replay_revisions()` now checks `opts->linearize` to determine base selection (`last_commit` for linearized commits, original parent otherwise).
- **Data structures**: `struct replay_revisions_options` gains a `linearize` field.
- **CLI**: `--linearize` is incompatible with `--revert` (enforced in `cmd_replay()`).
- **Files**: `replay.c`, `replay.h`, `builtin/replay.c`, `Documentation/git-replay.adoc`, and `t/t3650-replay-basics.sh`.

**Status**: This patch **resolves all three critical post-merge issues** from v5:
