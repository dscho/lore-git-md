This is the fourth patch in Toon Claes’s nine-patch series making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets `t5608-clone-2gb.sh`, a test that exercises Git’s ability to handle large repositories by creating clones with multi-gigabyte packfiles.

The patch reduces peak disk usage from 16 GB to 8 GB by pruning repositories as soon as they are no longer needed. The key change is the addition of `test_when_finished rm -rf` calls after each clone operation, ensuring that intermediate repositories are deleted immediately rather than lingering until the end of the test. The setup repository (`2gb-repo`) is also explicitly removed after its clones are created. The diff is mechanical: the test script is refactored to wrap each clone in a `test_when_finished` block, and the setup repository is moved into a subshell so it can be cleaned up early.

The commit message clearly explains the problem (16 GB peak usage) and the solution (pruning repositories early), and the change is uncontroversial -- it is a straightforward efficiency improvement that does not alter test behavior or skip any cases. This patch, like the others in the series, is motivated by the goal of making `GIT_TEST_LONG` tests runnable in CI without consuming excessive resources. No new prerequisites or environment variables are introduced.
