This is the first patch in Patrick Steinhardt’s six-part series refactoring `struct object_info` to replace the `whence` field with a more flexible `source_infop` pointer. The series is part of the ongoing ODB abstraction effort and is conceptually approved by Junio C Hamano, with all feedback from v1 addressed in this iteration.

This patch threads an optional `struct odb_source_packed *source` parameter through `packed_object_info()` and `packed_object_info_with_index_pos()`. The parameter is unused for now but will allow callers to record the source of an object in later patches. Most callers pass `NULL` (since they don’t yet need source information), while the packed ODB backend passes the already-available source. The change is mechanical, touching eight files across the ODB, packfile, and builtin subsystems, and introduces no behavior changes.

The patch is well-structured and clearly motivated: it lays the groundwork for the rest of the series by making the new parameter available where it will be needed. The commit message explains the purpose of the parameter and why most callers pass `NULL`, which helps clarify the incremental approach. No substantive issues were raised in the thread for this patch—it received surface-level approval from Justin Tobler and was part of the broader conceptual approval from Junio.

If you’re following the ODB abstraction work, this patch is a small but necessary step toward multi-source object resolution. It’s unlikely to be controversial on its own, but it sets up the more interesting changes in patches 2 and 3. The series as a whole looks like it’s on track for merging.
