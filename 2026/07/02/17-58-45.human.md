This is the final patch in a well-polished v6 series that adds a `--linearize` option to `git replay`. The feature flattens merge commits, producing a linear history by stacking all replayed commits into a single topology—even when multiple branches are involved. The patch is technically complete, addresses all prior feedback, and includes thorough test coverage and documentation.

The implementation skips merge commits entirely when `--linearize` is active, reparenting subsequent commits onto the last non-merge commit. This ensures a predictable, all-or-nothing flattening that avoids dangling commits. The patch also restores the `replayed_base` parameter (reintroduced in patch 2/3) to fix a regression where replaying a single branch containing merge commits would drop commits after the merge. The fix guarantees all commits are replayed into a single linear history, not just the tip.

The man page and commit message are now extensive, documenting edge cases, behavioral differences from `git rebase --no-rebase-merges`, and the rationale for the interface design. The series diverges from `git rebase`'s `--rebase-merges=<mode>` syntax, using `--linearize` as a standalone flag instead. The commit message justifies this choice, arguing that `--linearize` better describes the predictable flattening behavior and that mirroring `git rebase`'s syntax would repeat past UX mistakes. This justification meets Patrick Steinhardt’s requirement for explicit reasoning.

Test coverage is comprehensive, including scenarios for replaying multiple divergent branches, handling merge commits, and verifying the behavioral difference from `git rebase`. The patch also enforces mutual exclusivity with `--revert` and documents the incompatibility. Files touched include `replay.c`, `replay.h`, `builtin/replay.c`, `Documentation/git-replay.adoc`, and `t3650-replay-basics.sh`.

The series is ready for review, with no unresolved technical objections. The only lingering discussion is the interface design, but this does not block merging the current implementation. The patch is a clean, well-motivated addition to the replay machinery, offering a simpler alternative to Johannes Schindelin’s earlier merge-replay implementation.
