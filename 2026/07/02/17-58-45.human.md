The `--linearize` option flattens merge commits into a single linear history by replaying only first-parent commits, providing server-side functionality equivalent to `git rebase --no-rebase-merges`. The key design choice—producing a **single linear sequence regardless of input branches**—is now explicitly documented, even if it duplicates shared history. This resolves the **silent commit-dropping regression** (fixed in patch 2/3) and clarifies how `--linearize` handles **divergent merges** (both sides are preserved, but the merge commit itself is dropped).

The test suite is significantly expanded to cover edge cases: multiple divergent branches, divergent merges, `--contained` with `--linearize`, and root commit handling.
