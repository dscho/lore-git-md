Core problem or goal
The thread investigates whether `git rm -n *.json`’s recursive behavior is a bug or correct but under-documented behavior. The command’s pathspec logic treats `*` as matching directory separators, so `*.json` matches JSON files in any subdirectory. The original report framed this as a violation of `git rm`’s documented non-recursive contract; Patrick Steinhardt reclassified it as expected pathspec behavior described in `gitglossary(7)`.

Current status
The issue is recharacterized as a potential documentation gap rather than an implementation bug. No patches have been proposed. The discussion now centers on whether `git-rm(1)` sufficiently clarifies pathspec semantics or needs amendment.

Key technical details
- Command: `git rm -n *.json`
- Subsystem: pathspec handling (`pathspec.c`, shared across Git; `builtin/rm.c` for the command)
- Behavior: `*` in pathspecs matches `/` by default, so `*.json` recurses into subdirectories. This is documented in `gitglossary(7)` but not prominently in `git-rm(1)`.
- No new symbols, no on-disk format changes, no test coverage yet.
- Platform: originally reported on Git for Windows 2.55.0.windows.1; core Git behavior, not platform-specific.
