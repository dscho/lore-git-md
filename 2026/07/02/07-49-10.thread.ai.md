Subject: `git rm -n *.json` unexpectedly recurses into subdirectories

Core problem or goal
The thread investigates whether `git rm -n *.json`’s recursive behavior is a bug or correct but under-documented. The command’s pathspec logic treats `*` as matching directory separators, so `*.json` matches JSON files in any subdirectory. The original report framed this as a violation of `git rm`’s non-recursive contract; Patrick Steinhardt reclassified it as expected pathspec behavior documented in `gitglossary(7)`. Phillip Wood further clarified that the behavior depends on shell globbing: if no `.json` files exist in the current directory, the shell passes the literal `*.json` to Git, which then treats it as a recursive pathspec; if `.json` files exist, the shell expands the glob, and Git receives explicit non-recursive paths.

Current status
The issue is recharacterized as a documentation gap rather than an implementation bug. The discussion now centers on whether `git-rm(1)` sufficiently clarifies pathspec semantics and their interaction with shell globbing, or needs amendment to address the edge case Phillip Wood identified (empty vs. non-empty directory).
