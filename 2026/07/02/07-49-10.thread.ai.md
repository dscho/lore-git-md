Subject: `git rm -n *.json` unexpectedly recurses into subdirectories

Core problem or goal
The thread investigates why `git rm -n *.json` recursively matches JSON files in subdirectories, contrary to user expectations. The behavior is rooted in Git’s pathspec logic: `*` matches directory separators by default (documented in `gitglossary(7)`), and the interaction with shell globbing creates an edge case where no `.json` files in the current directory cause the shell to pass `*.json` literally to Git, triggering recursive matching. The discussion has firmly shifted from treating this as a bug to addressing a documentation gap: whether `git-rm(1)` should clarify pathspec semantics, cross-reference `gitglossary(7)`, or explicitly mention the `:(glob)` modifier to prevent confusion.

Current status
The behavior is confirmed as expected, not a code defect. The pathspec machinery already supports non-recursive matching via the `:(glob)` modifier (e.g., `git rm -n ':(glob)*.json'`), but this is not prominently documented in `git-rm(1)`. The thread now centers on whether the man page should improve its explanation of pathspec behavior, particularly the interaction between shell globbing and Git’s recursive matching rules. Phillip Wood’s clarification—highlighting the dependency on shell globbing (empty vs. non-empty directory)—and Mikael Magnusson’s review—quoting `gitglossary(7)` and noting the man page makes no promise of non-recursive behavior—have sharpened the focus on user expectations and discoverability.

Key technical details
- Command: `git rm -n *.json`
- Subsystem: pathspec handling (`pathspec.c`, shared across Git; `builtin/rm.c` for the command)
- Behavior: `*` in pathspecs matches `/` by default (documented in `gitglossary(7)`). Recursion depends on shell globbing:
  - If no `.json` files exist in the current directory, the shell passes `*.json` literally to Git, which treats it as a recursive pathspec.
  - If `.json` files exist, the shell expands the glob, and Git receives explicit non-recursive paths.
  - The `:(glob)` pathspec modifier restricts matching to the current directory (e.g., `git rm -n ':(glob)*.json'`), overriding the default recursive behavior.

- Platform: originally reported on Git for Windows 2.55.0.windows.1; core Git behavior, not platform-specific.
