Subject: `git rm -n *.json` unexpectedly recurses into subdirectories
Series version: none (standalone bug report)
Originating author: Евгений Плискин
Thread type: bug report

Core problem or goal
The `git rm` command, when invoked with the `-n` (dry-run) flag and a glob pattern (`*.json`), recursively removes JSON files from subdirectories. The documentation states that `git rm` should not recurse without an explicit directory specification, so this behavior contradicts the documented contract.

Current status
Reported; no patches, no prior discussion, no merge status. The issue is observed on Git for Windows 2.55.0.windows.1 but is likely a core Git issue rather than a platform-specific regression.

Key technical details
- Command: `git rm -n *.json`
- Expected behavior: only files matching `*.json` in the current directory are listed for removal.
- Actual behavior: all JSON files in subdirectories are also listed for removal.
- Subsystem: worktree / index manipulation (`builtin/rm.c`).
- No new symbols, no on-disk format changes, no test coverage yet.

Open questions and loose ends
- Is the recursion caused by shell glob expansion (Windows vs. POSIX shell differences) or by Git’s internal path matching logic?
- Does the same behavior occur on non-Windows platforms?
- Is the documentation out of sync with the implementation, or is this a genuine bug?
