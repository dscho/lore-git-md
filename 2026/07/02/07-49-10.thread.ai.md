Core problem or goal
The `git rm` command, when invoked with the `-n` (dry-run) flag and a glob pattern (`*.json`), recursively removes JSON files from subdirectories. The documentation states that `git rm` should not recurse without an explicit directory specification, so this behavior contradicts the documented contract.

Current status
Reported; no patches or prior discussion. The issue is observed on Git for Windows 2.55.0.windows.1 but is suspected to be a core Git issue rather than platform-specific. Matt Hunter attempted to reproduce the issue but could not, and has requested a reproduction script to clarify whether the recursion stems from shell glob expansion (Windows vs. POSIX differences) or Git’s internal path matching logic.

Key technical details
- Command: `git rm -n *.json`
- Expected behavior: only files matching `*.json` in the current directory are listed for removal.
- Actual behavior: all JSON files in subdirectories are also listed for removal (reported by Евгений Плискин; not reproduced by Matt Hunter).
- Subsystem: worktree / index manipulation (`builtin/rm.c`).
- No new symbols, no on-disk format changes, no test coverage yet.
