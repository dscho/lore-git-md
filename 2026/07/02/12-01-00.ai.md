This is the seventh patch in a nine-patch series improving the reliability and efficiency of `GIT_TEST_LONG` tests in Git's CI and test suite. The patch standardizes how the `GIT_TEST_LONG` environment variable is parsed by switching to the `test_bool_env` helper function, which was introduced earlier in the series (patch 5). This change ensures that `GIT_TEST_LONG` can be explicitly disabled by setting it to `false` or similar values, rather than only being enabled by non-empty strings.

The patch touches two files: `ci/lib.sh` and `t/test-lib.sh`. In `ci/lib.sh`, it updates the CI script to export `GIT_TEST_LONG=true` instead of `YesPlease`, aligning with the boolean parsing logic. In `t/test-lib.sh`, it modifies the command-line option parser to set `GIT_TEST_LONG=true` when the `--long-tests` flag is used, and updates the `EXPENSIVE` prerequisite to use `test_bool_env GIT_TEST_LONG false` instead of checking for a non-empty string. These are mechanical changes that do not alter test behavior but make the parsing more consistent and predictable.

The patch is well-motivated and uncontroversial. It addresses a minor but real usability issue where users or CI scripts could not reliably disable `GIT_TEST_LONG` once it was set. The change is backward-compatible for all practical purposes, as `test_bool_env` treats `YesPlease` (the old value) as `true`. No new edge cases or regressions are introduced, and the patch fits cleanly into the series' broader goal of making `GIT_TEST_LONG` tests more robust and CI-friendly.
