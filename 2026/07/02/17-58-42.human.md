This is a feature patch series introducing the `--linearize` option to `git replay`. The v6 iteration is a substantial rework of the previous version, addressing post-merge regressions and design concerns identified in the thread. The series is now three patches: two refactoring steps and the main implementation.

The core change teaches `git replay` to flatten merge commits into a linear history by walking only first parents, mimicking `git rebase --no-rebase-merges`. The most significant update in v6 is the **complete redesign of the base-selection logic**: instead of embedding it inside `pick_regular_commit()`, the logic is now resolved outside the function, making the flow clearer and fixing the silent commit-dropping regression that plagued v5. The commit message for the main patch has been drastically expanded to explain the behavior, particularly how multiple revision ranges are stacked into a single linear history (a key difference from `git rebase`).

The documentation now explicitly warns that `--linearize` flattens all input ranges into one sequence, updating all refs to point to their position in that sequence. This is intentional but may surprise users expecting independent linearization of each branch. The series also adds extensive test coverage for edge cases: multiple divergent branches, merge commits, `--contained` interactions, and root-commit handling. A new test verifies that replaying a merge commit preserves both sides of the divergence (though the merge itself is dropped).

The CLI design debate with Patrick Steinhardt is not resolved in this version, but the commit message now provides the explicit justification he demanded for diverging from `git rebase`'s `--rebase-merges` syntax. The series carries Johannes Schindelin’s Signed-off-by, indicating his continued support despite the earlier regression. This version looks like a serious, well-tested effort to address the post-merge issues while maintaining the original design intent. The expanded documentation and test coverage suggest the author is treating the feedback as constructive rather than adversarial.
