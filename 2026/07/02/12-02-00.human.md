This is the second patch in Patrick Steinhardt’s six-part ODB refactoring series, now in its second iteration. It splits the backend-specific details out of `struct object_info` into a new, opt-in `struct object_info_source` (renamed to `struct odb_source_info` in later patches). The change is mechanical: callers that need provenance information now allocate a `struct object_info_source` on the stack and point `sourcep` at it; those that don’t simply pass `NULL`. The patch touches seven files—`builtin/cat-file.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `odb.c`, `odb.h`, `packfile.c`, and `reachable.c`—and is a straightforward refactoring with no behavior change.

The motivation is clear: the existing `struct object_info` unconditionally populates a union with backend-specific data (e.g., packfile, offset, object type) even when callers don’t care about it. This patch makes that information opt-in, which is a prerequisite for the ODB abstraction effort and future multi-source object resolution. The commit message explains the rationale well, and the code changes are clean—mostly moving the union into a separate struct and updating callers to use `oi->sourcep->u.packed` instead of `oi->u.packed`.

This patch received substantive review in v1, with Justin Tobler questioning the architectural rationale and Junio C Hamano flagging a readability concern about the implicit upcast in a later patch (3/6). Those issues are now settled: the opt-in design is accepted, and the naming ambiguity (`sourcep` vs. `source_infop`) is resolved in v2. The series is conceptually approved and on track for merging, so this patch is worth attention if you’re following the ODB refactoring work. It’s a foundational change, but the implementation is solid and the tests (existing ODB/packfile coverage) should catch any regressions.
