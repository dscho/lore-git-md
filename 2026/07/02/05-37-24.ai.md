This is a **substantive review comment** on the first patch of the recently merged four-part series standardizing help-flag exit codes in the parse-options infrastructure. Jeff King (Peff) identifies a **bug in the `SVN` test prerequisite logic** introduced in `t/t1517-outside-repo.sh`.

The issue is a shell-quoting error: the single quotes around `'1.1.0'` in the Perl one-liner are interpreted as ending and restarting the `test_lazy_prereq` snippet, leaving the version comparison (`$SVN::Core::VERSION gt 1.1.0`) without quotes around the version string. This causes Perl to compare the version number as a string rather than a version object, leading to incorrect results (e.g., "1.14.5" is not greater than "1.2.0" lexicographically). Peff notes this bug is inherited from `t/lib-git-svn.sh` but is newly exposed by the prerequisite's inline Perl code.

The review is **technically precise** and **actionable**: it pinpoints the exact line, explains the shell-parsing behavior, and demonstrates the incorrect comparison with a concrete example (SVN::Core 1.14.5 vs. "1.2.0"). Peff also observes that the existing safety checks for `test_expect_success` do not apply to `test_lazy_prereq`, making this a silent failure. The fix will require escaping or restructuring the quotes in the Perl snippet.

This comment is part of the ongoing discussion about the `SVN` prerequisite logic raised by Junio in the thread summary. While the series itself is merged, this review suggests a follow-up patch is needed to correct the prerequisite's behavior, ensuring `git-svn` tests are skipped only when Subversion is genuinely unavailable. The impact is limited to test reliability but could cause false negatives in environments where SVN is usable.
