This is the v2 cover letter for Patrick Steinhardt’s six-patch series refactoring `struct object_info` in Git’s ODB subsystem. The series replaces the coarse `whence` field with a new `struct odb_source_info` that carries both source type and backend-specific data, enabling future multi-source object resolution and pluggable ODB backends. This iteration addresses feedback from v1: the struct and pointer names are renamed (`struct object_info_source` → `struct odb_source_info`, `sourcep` → `source_infop`) to avoid ambiguity with the actual ODB source.

The series is now conceptually approved by Junio C Hamano ("everything makes sense") and all patches have been reviewed. Patches 1-3/6 (struct refactoring and backend integration) received substantive architectural feedback from Junio and Justin Tobler; patches 4-6/6 (caller conversion, field removal, and documentation) received surface-level approval. The changes are mechanical but foundational, touching 14 files across the ODB, packfile, and builtin subsystems. No behavior changes are introduced—callers can now opt out of source population, and the new `source_infop` field is populated only when requested.

Key technical details: the series threads the new `source_infop` pointer through `packed_object_info()`, converts all `whence` users to `source_infop->source->type`, and removes the `whence` field entirely. Patch 3/6 includes a BUG check to prevent callers from requesting source information without providing a valid `source_infop` parameter. The pointer assignment `oi->source_infop->source = &source->base` (using an implicit upcast) remains unchanged despite Junio’s readability concerns, as it is technically safe. The series is based on `ps/odb-source-packed` and targets `master`.

If you’re tracking the ODB abstraction effort or multi-source object resolution, this series is a critical intermediate step. The naming changes in v2 resolve the ambiguity flagged in v1, and the conceptual approval suggests it’s on track for merging. No open questions remain—only surface-level follow-ups (e.g., the implicit upcast) were noted in the thread.
