This is the second patch in a two-part series adjusting Git’s build system for Rust components, specifically targeting macOS Universal Binary support for the `git-credential-osxkeychain` credential helper. The patch introduces the `RUST_TARGETS` environment variable, allowing users to specify multiple Rust target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`). The build system then compiles each target separately and combines the resulting static libraries into a single Universal Binary using `lipo`, a tool bundled with Xcode Command Line Tools.

The commit message now clearly explains the motivation: Universal Binaries bundle native code for multiple architectures into a single file, which is standard practice for macOS distribution and CI packaging. This avoids the need for Rosetta emulation or maintaining separate packages for different architectures. The implementation uses Make pattern rules to handle per-target compilation and preemptively creates target directories to avoid race conditions, addressing feedback from earlier iterations.

However, Patrick Steinhardt’s substantive review concerns remain unresolved. The patch only handles Rust libraries, not the final binaries. While the commit message notes that the Apple toolchain (clang) natively supports Universal Binaries via `-arch` flags for C code, the patch does not modify the C build rules to use them. This means the Rust library’s multi-architecture support may not deliver the intended benefit unless the rest of Git is also built as a Universal Binary. Additionally, the patch assumes `lipo` is universally available on macOS, which Patrick questioned.

The patch is well-structured and maintains backward compatibility for single-target builds. It introduces no on-disk format changes and is implicitly covered by existing build tests. While the first patch in the series (fixing a parallel build race condition) is uncontroversial, this patch’s practical value remains unclear without corresponding changes to the C build. The series is not yet ready to proceed without further discussion or revision.
