This thread is a nine-patch series from Jeff King (Peff) fixing memory leaks in Git’s non-default hash implementations (OpenSSL SHA-256 and libgcrypt). The leaks occur because Git’s hash context (`git_hash_ctx`) requires explicit cleanup via `git_hash_final()` in error paths, but the codebase fails to call this for non-default backends, causing leaks detectable under `SANITIZE=leak`. The series introduces `git_hash_discard()` as a new primitive and systematically applies it across subsystems like `csum-file`, `patch-id`, stream OID checking, HTTP object requests, and libgcrypt-specific handle copying.

The series is currently at its initial version (v1), with all patches posted but unreviewed. Patches 1–6 address leaks in `csum-file`, `patch-id`, and stream OID checking, while patch 7 (new) adds a `hash_ctx_valid` flag to HTTP object requests to avoid double-free errors. The latest patch (8/9) fixes a libgcrypt-specific leak when cloning SHA-256 contexts, where `gcry_md_copy()` leaks the destination context’s prior allocation. The fix closes the destination context before copying, prioritizing API consistency over optimization. No objections or requests for changes have been raised yet, though CI gaps remain: the linux-sha256 job lacks leak checking, and libgcrypt isn’t tested in CI. The series is purely a correctness fix with no user-visible changes or on-disk format modifications.
