Jeff King’s nine-patch series to plug memory leaks in Git’s non-default hash implementations (OpenSSL SHA-256, libgcrypt) is now partially reviewed. The first patch, which removes a redundant `discard_hashfile()` function in favor of `free_hashfile()`, has been approved by Junio C Hamano, who called the reasoning “sounds good” and playfully deferred to Eric Sunshine for any naming objections. Peff has since replied, proposing a follow-up cleanup to rename `free_hashfile()` to `hashfile_free()` or `hashfile_discard()` for consistency with Git’s naming conventions, but this would come later to avoid disrupting the current series. The remaining eight patches—introducing a new `git_hash_discard()` primitive and systematically applying it to leaky subsystems like `csum-file`, `patch-id`, stream OID checking, HTTP object requests, and libgcrypt-specific leaks—remain unreviewed. The series is well-scoped, with no user-visible changes; it fixes a correctness issue (memory leaks) that only surfaces under `SANITIZE=leak` with non-default hash backends. No objections have been raised, and the only open question is whether Eric Sunshine will weigh in on naming. The series is not yet queued for merging.
