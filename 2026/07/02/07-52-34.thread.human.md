This thread is a bugfix series from Jeff King (Peff) that plugs memory leaks in Git’s non-default hash implementations (OpenSSL SHA-256 and libgcrypt). The leaks occur when `git_hash_final()` isn’t called in error paths, and the series introduces `git_hash_discard()` (proposed to be renamed to `git_hash_release()`) to systematically clean up hash contexts. Junio Hamano approved the first patch, which removes a redundant function and simplifies the `csum-file` API, but naming and design discussions are ongoing for the rest of the series.

The key debate centers on whether `git_hash_discard()` should be idempotent—Patrick Steinhardt and Brian m. carlson argue it should, citing historical pain with non-idempotent APIs and the practical benefits for Rust integration. Peff’s current implementation uses a flag-based approach to avoid double-discarding, but the reviewers’ consensus suggests this may need revisiting in a future revision. The series touches multiple subsystems (`csum-file`, `patch-id`, HTTP object requests, and libgcrypt-specific code) and fixes leaks in 68 test scripts when run with non-default hash backends. No merge decisions have been made yet, and the remaining patches await further review.
