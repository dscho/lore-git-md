This is the final patch in Jeff King’s 9-patch **bugfix series** plugging memory leaks in Git’s hash implementations when using non-default backends like OpenSSL or libgcrypt. The series has already introduced `git_hash_discard()` and applied it across several subsystems; this patch replaces the temporary "hacky" implementation (which called `git_hash_final()` into a dummy buffer) with **platform-specific discard functions** for OpenSSL and libgcrypt.

The patch adds explicit `discard_fn` callbacks to Git’s hash algorithm vtable, then implements them for each backend: OpenSSL’s SHA-1 and SHA-256 (which free the `EVP_MD_CTX` via `EVP_MD_CTX_free()`), and libgcrypt’s SHA-256 (which calls `gcry_md_close()`). For backends that don’t need special cleanup (like Git’s built-in implementations), it provides no-op fallback functions. The change touches `hash.h`, `hash.c`, and three platform-specific headers (`sha1/openssl.h`, `sha256/gcrypt.h`, `sha256/openssl.h`), adding about 60 lines of boilerplate to ensure every hash context can be discarded cleanly.

Jeff tested the patch with all five supported configurations (`OPENSSL_SHA1`, `OPENSSL_SHA1_UNSAFE`, `OPENSSL_SHA256`, `GCRYPT_SHA256`, and the default built-in implementations) and confirmed the leaks remain plugged. The commit message acknowledges the boilerplate is annoying but argues it’s worth it for correctness and efficiency—especially since `git_hash_discard()` is typically called on error paths where performance isn’t critical. The patch is uncontroversial and completes the series’ goal of eliminating leaks in non-default hash backends.
