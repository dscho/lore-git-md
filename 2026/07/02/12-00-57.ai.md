This is the fourth patch in Toon Claes’s nine-patch series making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets `t5608-clone-2gb.sh`, a test that verifies Git’s ability to handle large repositories by creating clones with multi-gigabyte packfiles. The patch reduces peak disk usage from 16 GB to 8 GB by deleting repositories as soon as they are no longer needed, using `test_when_finished` and explicit `rm -rf` calls.

The change is purely mechanical: the test script is refactored to wrap each clone operation in `test_when_finished rm -rf` and to remove the 2 GB setup repository (`2gb-repo`) immediately after the last clone that uses it. The 4 GB repository (`4gb-repo`) and its clones are similarly cleaned up as soon as their respective test cases complete. No test logic or assertions are altered; the patch only adds cleanup hooks.

This is a straightforward efficiency improvement that directly addresses the series’ goal of making `GIT_TEST_LONG` tests CI-friendly. The commit message clearly explains the motivation and the mechanical nature of the change. No new CLI options, config keys, or on-disk formats are introduced. The patch is uncontroversial and well-scoped.
