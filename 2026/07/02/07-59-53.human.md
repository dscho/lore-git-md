This is the second patch in Jeff King’s nine-patch **bugfix series** plugging memory leaks in Git’s non-default hash implementations (OpenSSL SHA-256, libgcrypt). It introduces the new `git_hash_discard()` primitive, which provides a clean way to free resources held by a `git_hash_ctx` when an operation is aborted before calling `git_hash_final()`.

The patch is straightforward: it adds the function to `hash.h` and implements it in `hash.c` by calling `git_hash_final()` into a dummy buffer, relying on the side effect of freeing the underlying resources. The commit message acknowledges this is slightly inefficient but notes it’s only used on error paths, and the abstraction allows for a more efficient implementation later (which arrives in patch 9). The change is minimal—just 13 lines added across two files—and doesn’t alter behavior, only correctness.

This is a foundational patch for the series, enabling the subsequent fixes in `csum-file`, `patch-id`, and other subsystems. The implementation is conservative and uncontroversial, deferring platform-specific optimizations to later patches. If the series lands, this function will become a standard part of Git’s hash API.
