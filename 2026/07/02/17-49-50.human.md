This is a review comment on patch 3/9 of Toon Claes’s series to make `GIT_TEST_LONG` tests reliable and efficient in CI. The patch, originally authored by Patrick Steinhardt, refactors `t4141-apply-too-large.sh` to eliminate a performance bottleneck caused by a byte-by-byte `dd` copy, reducing runtime from minutes to under a second.

SZEDER Gábor’s review points out that while the patch dramatically improves execution time, it does not address the high memory usage of `git apply` itself, which exceeds 1 GB of resident set size (RSS). The `EXPENSIVE` prerequisite, he argues, is not solely about runtime but also about resource consumption, and should therefore be retained. His observation is precise and grounded in the test’s actual behavior: the test still exercises a memory-intensive code path, even if it now runs faster.

The review is substantive but narrow, focusing on a single technical point without questioning the broader approach or suggesting alternative solutions. It does not engage with the patch’s correctness or the series’ overall goal, but it does identify a legitimate concern about resource usage that could affect CI stability. The author’s claim that the test is now efficient enough to drop `EXPENSIVE` is not fully supported by the evidence, and the review’s objection is likely to be taken seriously. This is a clear case where the patch’s performance improvement is real but incomplete, and the feedback suggests a straightforward adjustment: keep the `EXPENSIVE` prerequisite.
