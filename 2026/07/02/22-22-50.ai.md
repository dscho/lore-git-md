This is the first patch in a two-part build system update for the Rustification effort, specifically targeting the macOS credential helper (`git-credential-osxkeychain`). It ensures the helper correctly links against Rust libraries when Rust support is enabled.

The patch addresses a parallel build race condition: when running `make -j` from a clean working tree, Make might attempt to link `git-credential-osxkeychain` before Cargo has built the required Rust library (`libgitcore.a`). By adding `$(RUST_LIB)` as a prerequisite to the credential helper's build rule, the build system now guarantees Cargo runs first. The change is wrapped in `ifndef NO_RUST` blocks to ensure it remains a no-op when Rust is disabled, maintaining backward compatibility.

The commit message is clear and well-motivated, explaining both the problem (parallel build failures) and the solution (prerequisite addition). The change itself is minimal and focused, touching only the `Makefile` and introducing no new symbols or behavior changes beyond fixing the build race. This is a straightforward, uncontroversial fix that should work as intended. No new test coverage is introduced, but the change is implicitly covered by existing build tests.

This patch stands alone as a logical unit, but it also sets the stage for the second patch in the series, which introduces macOS Universal Binary support for Rust components. The two patches are cleanly split: this one ensures correct linking, while the next one enables multi-architecture builds. Patrick Steinhardt’s earlier concerns about Universal Binary completeness do not affect this patch, which is purely about build correctness.
