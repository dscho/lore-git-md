This is the fourth patch in Jeff King’s nine-patch **bugfix series** plugging memory leaks in Git’s hash implementations when non-default backends (OpenSSL, libgcrypt) are used. The series was discovered via `SANITIZE=leak` and targets low-level plumbing code.

This patch introduces `hashfile_checkpoint_release()`, a function that cleans up the `git_hash_ctx` stored inside a `hashfile_checkpoint` struct. The checkpoint is essentially a snapshot of the hash state at a given point in a file, and its context may need explicit cleanup depending on the hash backend. The new function is called in two places: `builtin/fast-import.c` (streaming blobs) and `object-file.c` (ODB transaction writes). With this change, two more test scripts (`t1050` and `t9300`) become leak-free when run with `OPENSSL_SHA1_UNSAFE=1`.

The patch is a straightforward plumbing fix—no user-visible behavior changes, just resource cleanup. It touches four files and adds nine lines of code. The naming choice ("release" instead of "discard") is deliberate: the function is meant to be called unconditionally for every checkpoint, whereas `git_hash_discard()` is only needed if `git_hash_final()` wasn’t called.
