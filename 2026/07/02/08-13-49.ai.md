This is the **ninth and final patch** in Jeff King’s 9-patch bugfix series addressing memory leaks in Git’s hash implementations when using non-default backends like OpenSSL or libgcrypt. The series as a whole plugs leaks by introducing a `git_hash_discard()` primitive and systematically applying it across subsystems (`csum-file`, `patch-id`, HTTP object requests, etc.).

Patch 9 replaces the "hacky" `git_hash_discard()` implementation (which called `git_hash_final()` into a dummy buffer to trigger resource cleanup) with **platform-specific discard functions**. This eliminates the inefficiency of computing a final hash just to free resources, though the author notes the original approach was "probably not too terrible" given that `discard()` is mostly called on error paths. The patch adds explicit `discard_fn` callbacks to Git’s hash algorithm vtable (`struct git_hash_algo`), requiring boilerplate wrappers for each algorithm (SHA-1, SHA-256, and their unsafe variants) and platform (OpenSSL, libgcrypt). Fallback no-op functions are provided for platforms that don’t need special cleanup.

The changes touch `hash.c`, `hash.h`, and platform-specific headers (`sha1/openssl.h`, `sha256/gcrypt.h`, `sha256/openssl.h`). Testing covered all backends the author could build (`OPENSSL_SHA1`, `OPENSSL_SHA256`, `GCRYPT_SHA256`, etc.), with no regressions reported. The patch is narrowly scoped to correctness and performance, with no user-visible behavior changes. While the boilerplate is verbose, the approach is pragmatic: it reuses the existing `CLONE_HELPER` flag to determine whether a platform needs smart copying/discarding, avoiding a separate flag for discard.

This patch completes the series, which appears well-motivated and uncontroversial. The leaks only affect non-default hash backends, so the impact is limited, but the fixes are thorough and the commit messages clearly explain each change. The series is likely to be merged as-is, though future API discussions might revisit naming (e.g., `free_hashfile()` vs. `discard_hashfile()`) or further optimize the discard paths. Key symbols for follow-up: `git_hash_discard_fn`, `platform_SHA1_Discard`, `platform_SHA256_Discard`, `CLONE_HELPER`.
