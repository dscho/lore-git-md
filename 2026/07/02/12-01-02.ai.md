This is the final patch in Toon Claes’s nine-patch series that makes `GIT_TEST_LONG` tests reliable and efficient enough to run in CI. It plugs the last gap by enabling the long-running tests in GitLab CI, matching the behavior already implemented for GitHub Actions in 7a094d68a2 (ci: run expensive tests on push builds to integration branches, 2026-05-08). The patch also disables `GIT_TEST_LONG` on Windows runners, which only have 7.5 GB of RAM—insufficient for some of the expensive tests.

The change touches two files: `.gitlab-ci.yml` and `ci/lib.sh`. In `.gitlab-ci.yml`, it adds `GIT_TEST_LONG: false` to the Windows jobs (`test:mingw64` and `test:msvc-meson`) to prevent out-of-memory failures. In `ci/lib.sh`, it extends the existing logic that enables `GIT_TEST_LONG` for GitHub pull requests and pushes to integration branches (`next`, `master`, `main`, `maint`) to also cover GitLab’s equivalent events. The patch maps GitLab’s `CI_PIPELINE_SOURCE` to the GitHub-style `CI_EVENT` variable and uses `GIT_TEST_LONG=${GIT_TEST_LONG:-true}` to allow explicit override while defaulting to `true` for qualifying events.

This is a straightforward CI configuration patch with no user-facing behavior changes. It completes the series’ goal of making `GIT_TEST_LONG` tests visible and reliable in GitLab CI, complementing the earlier fixes that addressed broken tests and resource inefficiencies. The Windows exclusion is a pragmatic workaround for hardware limitations. The patch is well-motivated and uncontroversial, fitting cleanly into the broader effort to improve test coverage in CI.
