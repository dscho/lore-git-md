This is the third patch in Patrick Steinhardt’s six-part series refactoring `struct object_info` to support pluggable ODB backends. The series is conceptually approved and on track for merging, with only surface-level follow-ups remaining.

This patch adds a `source` field to the new `struct odb_source_info` (introduced in patch 2/6) and populates it in each ODB backend’s lookup path. The field records which backend an object was retrieved from, replacing the old `whence` enum’s role in identifying the source. The `whence` field is still set for now but will be removed in a later patch. The change is mechanical: every backend (`inmemory`, `loose`, `packed`) now assigns its `struct odb_source` to the new field during object lookup.

The patch touches nine files, mostly updating callers to use the new `source_infop` pointer (renamed from `sourcep` in v2 to avoid ambiguity). A BUG check in `packfile.c` ensures callers don’t request source information without providing a valid `source_infop` parameter. The pointer assignment `oi->source_infop->source = &source->base` uses an implicit upcast, which Junio C Hamano flagged as potentially confusing but accepted as technically safe.

This is a foundational step toward multi-source object resolution and pluggable ODB backends. If you’re following Patrick’s ODB abstraction work, this patch is critical—it enables future callers to distinguish between objects from different backends without relying on the coarse `whence` enum. The changes are well-contained and don’t alter behavior, but the new `source` field will be key for later work.
