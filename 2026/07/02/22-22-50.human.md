This is the first patch in a two-part build system update for the Rustification effort, specifically targeting the macOS credential helper (`git-credential-osxkeychain`). The patch ensures that when Rust is enabled, the credential helper correctly links against the Rust-compiled library (`libgitcore.a`) by adding it as a prerequisite to the build target.

The change is straightforward and well-motivated: without this prerequisite, parallel builds (`make -j`) from a clean working tree can fail because Make doesn’t know it needs to invoke Cargo to build the Rust library before linking the credential helper. The patch also wraps the Rust-related build definitions in `ifndef NO_RUST` blocks, making the dependency a clean no-op when Rust is disabled. This aligns with the project’s preference for conditional compilation over intermediate variables.

The commit message is clear and explains the problem, the fix, and the rationale for the conditional blocks. The patch itself is minimal—just six lines added to the `Makefile`—and maintains backward compatibility. It’s a small but necessary step for the broader Rustification effort, particularly for macOS users. The only potential concern is whether the parallel build issue was reproducible in practice, but the fix is low-risk and addresses a real edge case.

This patch looks ready to proceed, assuming no objections to the conditional compilation approach. The second patch in the series (Universal Binary support) is where the more substantive discussion is likely to continue.
