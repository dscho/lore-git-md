This is a **build system** patch for the **Rustification effort**, specifically refining macOS Universal Binary support for Rust components in Git. The email is a reply from the author, Shardul Natu, addressing feedback on the v2 patch and explaining the design choices behind the v3 revision.

The key update is that the series is now split into three logical commits: (1) a fix for a parallel build race condition (new in v3), (2) Universal Binary support for Rust libraries, and (3) a minor cleanup. The first patch ensures `git-credential-osxkeychain` links against Rust libraries when Rust is enabled, resolving a race where `make -j` might try to link the helper before Cargo builds the required `libgitcore.a`. This change is uncontroversial and ready to proceed.

The Universal Binary implementation (second patch) allows users to specify multiple Rust target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`) to compile separate static libraries and combine them into a single Universal Binary using `lipo`. The commit message now clarifies that Universal Binaries bundle native code for multiple architectures (e.g., x86_64 and arm64) into one file, which is standard practice for macOS distribution and CI packaging. The author argues that `lipo` is a safe dependency, as it is part of Xcode Command Line Tools, a hard prerequisite for building Git on macOS. They also explain why only Rust libraries need special treatment: Apple’s C toolchain natively supports Universal Binaries via `-arch` flags, while Cargo requires separate invocations per target.

However, Patrick Steinhardt’s substantive concerns remain unresolved. The patch only handles Rust libraries, not the final binaries. If the rest of Git (written in C) is not also built as a Universal Binary, the Rust library’s multi-architecture support may not deliver the intended benefit. The author acknowledges this but notes that the C toolchain’s native support means no additional Makefile changes are needed for C code. This leaves the practical utility of the feature somewhat limited—it will only be useful in scenarios where the C build is manually configured for Universal Binaries, which is not addressed here.

The third patch (cleanup) is non-controversial. No new test coverage was introduced, but the changes are implicitly covered by existing build tests. The series is well-structured, with clear commit messages and thorough explanations of the macOS-specific toolchain behavior. The unresolved architectural question—whether Universal Binary support is meaningful without corresponding C build changes—is the main hurdle before this can land.
