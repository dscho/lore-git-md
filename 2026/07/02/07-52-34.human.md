This is a **bugfix series** from Jeff King targeting memory leaks in Git’s hash algorithm handling. The leaks only surface when Git is built with OpenSSL’s SHA-256 (or SHA-1) implementation, which allocates resources that must be explicitly freed. The default hash backends don’t require this cleanup, so the leaks have gone unnoticed in regular CI runs.

The core issue is that Git’s hash API (`git_hash_ctx`) expects callers to invoke `git_hash_final()` to release resources, but error paths or early returns can skip this step. Peff introduces a new `git_hash_discard()` primitive (patch 2) and retrofits it across the codebase (patches 3–9) to ensure cleanup happens even when operations fail. The series also tidies up related subsystems like `csum-file` (patches 1, 3–4) and fixes a libgcrypt-specific leak (patch 8) that CI doesn’t catch.

The patches are narrowly scoped and mechanical: each one plugs a single leak by adding a discard call or adjusting error handling. The commit messages are clear and reference the specific functions or structs involved, making it easy to verify the fixes. This is classic Peff—small, precise changes with thorough explanations.

If you care about memory safety or use OpenSSL-backed hashes, this series is worth attention. The changes are unlikely to be controversial, but the new `discard` API might draw scrutiny from maintainers who prefer minimal additions to the public interface. The series is self-contained and doesn’t depend on other ongoing efforts.
