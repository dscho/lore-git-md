This is the final patch in a nine-part series that makes Git’s `GIT_TEST_LONG` tests reliable and efficient enough to run in CI. This specific patch enables `GIT_TEST_LONG` in GitLab CI, closing a coverage gap where expensive tests were previously only run in GitHub Actions.

The change is straightforward: it updates `.gitlab-ci.yml` and `ci/lib.sh` to export `GIT_TEST_LONG` (defaulting to `true`) for merge requests and pushes to integration branches (`next`, `master`, `main`, `maint`). On Windows runners, which only have 7.5 GB of RAM, the variable is explicitly set to `false` to avoid out-of-memory failures. The patch also maps GitLab’s `CI_PIPELINE_SOURCE` to the GitHub-style `CI_EVENT` variable so the existing logic in `ci/lib.sh` can handle both CI systems uniformly.

This is a well-motivated, mechanical change that aligns GitLab CI with GitHub CI’s behavior. The earlier patches in the series fixed broken tests, improved efficiency, and standardized boolean parsing, so enabling `GIT_TEST_LONG` in GitLab CI is now safe and practical. The patch is uncontroversial and looks ready to merge.
