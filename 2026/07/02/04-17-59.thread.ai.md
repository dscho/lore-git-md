Core problem or goal
Fix a memory leak and state corruption bug in `git apply`'s `find_header()` function. When Git-style diff headers (e.g., "diff --git a/foo b/bar") are scanned but ultimately rejected, partially parsed state is left in the `struct patch`, which can then corrupt subsequent parsing of traditional "---/+++" headers. The bug manifests as impossible patch states (e.g., a patch marked as creating a new file but still carrying an old filename from the abandoned header). The fix also rejects empty default names from "diff --git" lines, which are invalid pathnames.

- File touched: `apply.c` (core logic), `t/t4100-apply-stat.sh` (regression tests)
- New behavior: Git-style diff headers are parsed into a temporary `struct patch`; state is only committed to the real patch if the header is accepted. Empty default names from "diff --git" lines are explicitly rejected.
- Old behavior: Partially parsed state from abandoned Git-style headers could corrupt the real patch's state.
- Test coverage: Two new regression tests added to `t/t4100-apply-stat.sh`, covering the empty default-name case and the abandoned-header case.
