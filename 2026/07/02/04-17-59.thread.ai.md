Core problem or goal
Fix a memory leak and state corruption bug in `git apply`'s `find_header()` function. When Git-style diff headers (e.g., "diff --git a/foo b/bar") are scanned but ultimately rejected, partially parsed state is left in the `struct patch`, corrupting subsequent parsing of traditional "---/+++" headers. The bug manifests as impossible patch states (e.g., a patch marked as creating a new file but still carrying an old filename from the abandoned header). The proposed fix also rejects empty default names from "diff --git" lines, which are invalid pathnames.

Current status
Maintainer **Junio C Hamano** has **rejected the patch** on conceptual grounds. The current behavior—where abandoned Git-style headers corrupt the real patch—is **deliberate**, serving as a "sanity check" to force users to inspect and fix malformed patches. No alternative solutions or follow-up actions were proposed. The patch is effectively closed unless the author provides a rebuttal or revised approach that preserves the intended design.

- Subsystem: `apply` (patch application)

- Proposed behavior: Git-style diff headers parsed into a temporary `struct patch`; state only committed if the header is accepted. Empty default names from "diff --git" lines explicitly rejected.
