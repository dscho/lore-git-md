This is the fifth patch in Patrick Steinhardt’s six-patch ODB refactoring series, now targeting the removal of the `whence` field from `struct object_info`. The patch is mechanical: it deletes the `whence` enum and all assignments to it across `odb.c`, `odb.h`, `odb/source-inmemory.c`, `odb/source-loose.c`, and `packfile.c`. No behavior changes are introduced—all callers have already been converted to use the new `source_infop->source->type` pattern in the preceding patches.

The patch touches five files and removes 14 lines, completing the migration from the coarse `whence` field to the more flexible `struct odb_source_info`. The `oid_object_info_convert()` helper in `odb.c` no longer copies the `whence` field, and the backend-specific `populate_object_info()` functions (`odb/source-inmemory.c`, `odb/source-loose.c`, `packfile.c`) drop their `oi->whence` assignments. The BUG check in `packfile.c` (added in patch 3/6) remains unchanged, ensuring callers cannot request source information without a valid `source_infop` parameter.

This patch is uncontroversial and received surface-level approval from Justin Tobler in the v1 thread. The series as a whole is conceptually approved by Junio C Hamano, and this patch is a straightforward cleanup step. If you’re tracking the ODB abstraction effort, this is the penultimate patch in the series—patch 6/6 adds documentation for the new `source_infop` field.
