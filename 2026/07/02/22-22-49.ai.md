This is a build system patch for the Rustification effort, specifically the macOS credential helper (`git-credential-osxkeychain`). The v3 series splits the previous monolithic patch into two logical commits: the first ensures the credential helper links against Rust libraries when Rust is enabled, and the second introduces support for macOS Universal Binaries via the `RUST_TARGETS` environment variable.

The Universal Binary support is now better motivated in the commit message. It explains that Universal Binaries bundle native code for multiple architectures (e.g., x86_64 and arm64) into a single file, which is standard practice for macOS distribution and CI packaging. The implementation uses Make pattern rules to compile each target-specific Rust library slice, then combines them with `lipo` (part of the mandatory Xcode Command Line Tools) into a single static library. The build system now preemptively creates the target directory structure to avoid race conditions, addressing Junio Hamano’s earlier concern.

Patrick Steinhardt’s substantive review concerns from v2 remain unresolved in this iteration. The patch still assumes `lipo` is universally available on macOS, and it only handles Rust libraries, not the final binaries. If the rest of Git (written in C) is not also built as a Universal Binary, the Rust library’s multi-architecture support may not deliver the intended benefit. The commit message now clarifies that the C toolchain natively supports Universal Binaries via `-arch` flags, but the patch does not modify the C build rules to use them. This leaves the practical value of the feature unclear: without corresponding changes to the C build, the Rust library’s Universal Binary may not be usable in a multi-architecture Git executable.

The patch touches only the `Makefile` and maintains backward compatibility for single-target builds. New symbols introduced include `RUST_TARGETS` (user-facing) and `$(RUST_MEMBER_LIBS)` (internal). The split into two commits improves clarity, but the architectural questions Patrick raised—whether the two changes should be separate, and whether Universal Binary support is complete—remain open. The series is not yet ready to proceed without further discussion or revision.

Key technical details:
- **Files touched**: `Makefile` (build system integration).
- **New symbols**: `RUST_TARGETS` (environment variable), `$(RUST_MEMBER_LIBS)` (internal build variable).
- **Behavior changes**: Universal Binary support for Rust libraries on macOS, explicit linking of `git-credential-osxkeychain` with Rust libraries.
- **Open questions**: Availability of `lipo` on macOS, completeness of Universal Binary support (Rust libraries only, not binaries), practical use case without corresponding C build changes.
- **Test coverage**: Implicitly covered by existing build tests; no new test files introduced.
