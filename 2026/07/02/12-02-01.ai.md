This is the third patch in Patrick Steinhardt’s six-patch ODB refactoring series, targeting the `struct object_info` redesign. The patch adds a `source` field to the new `struct odb_source_info` (introduced in patch 2/6) and populates it in each ODB backend’s lookup path. This enables callers to identify which backend an object was retrieved from, a prerequisite for multi-source object resolution and pluggable ODB backends.

The patch touches nine files, primarily updating backend implementations (`odb/source-inmemory.c`, `odb/source-loose.c`, `packfile.c`) to set the `source` field during object lookup. It also updates caller sites in `builtin/cat-file.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `odb.c`, and `reachable.c` to use the renamed `source_infop` pointer (resolving the naming ambiguity flagged in v1). The `whence` enum remains in place for now but is redundant; it will be removed in patch 5/6.

Key technical details: the patch introduces a BUG check in `packfile.c` to prevent callers from requesting source information without providing a valid `source_infop` parameter. The pointer assignment `oi->source_infop->source = &source->base` uses an implicit upcast, which Junio C Hamano previously flagged as potentially confusing but technically safe. No behavior changes are introduced—this is purely a refactoring step to prepare for future multi-source resolution.

The patch is part of Patrick Steinhardt’s ongoing ODB abstraction effort and depends on `ps/odb-source-packed`. It has received substantive architectural review from Junio and Justin Tobler, with no open questions remaining. The series is conceptually approved and on track for merging. If you’re following the ODB refactoring work, this patch is a critical intermediate step toward eliminating direct `packed_object_info()` usage in favor of `odb_read_object_info()`.
