This is a **follow-up feature patch series (v6)** for the `--linearize` option in `git replay`, addressing the **critical post-merge issues** identified in v5. The series is now **urgently focused on fixing the silent commit-dropping regression** while also **clarifying the design intent** and **expanding test coverage** for edge cases.

The v6 series **reworks the base-selection logic** to restore the `replayed_base` mechanism that was inadvertently broken in v5. The key change is **moving base resolution entirely outside `pick_regular_commit()`**, which both fixes the regression and improves code clarity. The commit message for the main patch (3/3) is now **dramatically expanded** to document the behavior of `--linearize` in detail, including how it handles multiple revision ranges and merge commits. This addresses the **documentation gap** that contributed to the post-merge confusion.

**Critical fixes and improvements in v6:**
1. **Regression fix**: The silent commit-dropping in single-branch replay is resolved by properly restoring the `replayed_base` logic. The new test `"replay with --linearize rebase multiple divergent branches into a single line"` verifies this behavior across multiple branches.
2. **Merge commit divergence handling**: The series **explicitly documents** that `--linearize` drops merge commits but preserves both sides of divergent merges (e.g., when replaying a merge of X and Y, both X and Y are replayed into the linear history). A new test (`"replay with --linearize of a divergent merge keeps both sides"`) validates this.
3. **CLI design clarification**: The commit message and documentation now **justify the `--linearize` naming** and explain why it differs from `git rebase --no-rebase-merges`. This responds to Patrick Steinhardt’s demand for **explicit rationale** in commit messages.
4. **Test coverage**: The test suite is **significantly expanded** to cover:
   - Multiple divergent branches (ensuring all commits are replayed, not just tips).
   - Divergent merges (verifying both sides are preserved).
   - `--contained` with `--linearize` (updating contained refs correctly).
   - Root commit handling and `--advance` combinations.

**Technical details:**
- **Patch 1/3** (unchanged from v5): Adds `put_mapped_commit()` helper for the `replayed_commits` khash map.
- **Patch 2/3** (new): Moves base resolution outside `pick_regular_commit()`, fixing the regression and improving readability. This replaces the v5 patch that added explanatory comments.
- **Patch 3/3**: The main `--linearize` implementation, now with **detailed documentation** and **test coverage** for the edge cases identified post-merge. The commit message explicitly states that `--linearize` produces a **single linear sequence** regardless of input branches, even if this duplicates shared history.
