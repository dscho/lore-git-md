This is a **bugfix series** targeting memory leaks in Git's hash algorithm handling, specifically when using non-default hash implementations like OpenSSL's SHA-256 or libgcrypt. The series is authored by Jeff King and consists of 9 patches.

The core issue is that Git's hash context (`git_hash_ctx`) sometimes requires explicit cleanup via `git_hash_final()`, but the codebase doesn't always call this function—especially when returning early due to errors. These leaks are invisible with Git's default hash implementations (which treat the context as a simple byte array) but become apparent when using OpenSSL or libgcrypt, which allocate resources during initialization. The leaks were discovered by running the test suite with `SANITIZE=leak` and `OPENSSL_SHA256=1`.

The series introduces a new `git_hash_discard()` primitive (patch 2) to explicitly free hash contexts, then systematically applies it across subsystems where leaks occur: `csum-file` (patches 1, 3, 4), `patch-id` (patch 5), stream OID checking (patch 6), HTTP object requests (patch 7), and a libgcrypt-specific leak in SHA-256 handle copying (patch 8). Patch 9 adds platform-specific discard functions for OpenSSL and libgcrypt. The changes touch 13 files, primarily in low-level plumbing (`hash.c`, `csum-file.c`, `http.c`).

The patches are narrowly scoped and appear well-motivated, with clear commit messages explaining each leak's cause and fix. The series is likely uncontroversial, as it addresses a correctness issue (memory leaks) without changing behavior. However, the leaks only manifest with non-default hash backends, so the impact is limited to users who explicitly configure Git to use OpenSSL or libgcrypt.

Key technical details for follow-up discussion:
- New functions: `git_hash_discard()`, `hashfile_release_checkpoint()`
- Modified subsystems: `csum-file`, `patch-id`, `http`, `object-file`
- Test flags: `SANITIZE=leak`, `OPENSSL_SHA256=1`, `GIT_TEST_DEFAULT_HASH=sha256`
- Related CI gaps: linux-sha256 job lacks leak checking; libgcrypt not tested in CI
- Files touched: `hash.h`, `csum-file.h`, platform-specific headers (`sha1/openssl.h`, `sha256/gcrypt.h`, etc.)
