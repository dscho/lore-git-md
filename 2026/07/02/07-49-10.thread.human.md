This thread began when Евгений Плискин reported that `git rm -n *.json` unexpectedly recurses into subdirectories, contrary to the documentation’s claim that `git rm` does not recurse without an explicit directory. Matt Hunter attempted to reproduce the issue but couldn’t, asking for a clearer reproduction script to determine whether the recursion stems from shell glob expansion differences (Windows vs. POSIX) or Git’s internal path matching.

Patrick Steinhardt then clarified that the behavior is not a bug but a documented feature of Git’s *pathspec* system: the `*` wildcard in a pathspec matches directory separators by default, so `*.json` naturally includes JSON files in subdirectories. This is explicitly described in `gitglossary(7)`. The thread has now shifted from a bug report to a discussion about whether the `git-rm(1)` documentation sufficiently explains this behavior or if it needs improvement to avoid misleading users. No patches have been proposed yet, and the focus remains on aligning user expectations with the documented pathspec rules.
