The thread started when Евгений Плискин reported that `git rm -n *.json` unexpectedly recurses into subdirectories, framing it as a violation of `git rm`’s documented non-recursive behavior. Patrick Steinhardt reclassified the issue as correct but under-documented pathspec behavior, noting that `*` in pathspecs matches directory separators by default—a rule documented in `gitglossary(7)` but not prominently in `git-rm(1)`. The discussion then turned to whether the man page needs clarification.

Phillip Wood’s recent email adds a critical layer: the behavior depends on shell globbing. If no `.json` files exist in the current directory, the shell passes `*.json` literally to Git, which treats it as a recursive pathspec. If `.json` files *do* exist, the shell expands the glob, and Git receives explicit paths that don’t recurse. This explains why earlier attempts to reproduce the issue failed—users with `.json` files in their working directory wouldn’t see the recursion. The focus has now shifted to documenting this shell-Git interaction, not just Git’s pathspec rules. No patches have been proposed yet, but the thread is converging on a documentation fix to address the edge case Phillip identified. Key participants include Евгений (original reporter), Patrick (reclassifying the issue), and Phillip (clarifying the shell interaction).
