This thread is about a reported bug in `git rm`: when run with the `-n` (dry-run) flag and a glob pattern like `*.json`, it unexpectedly recurses into subdirectories, listing JSON files there for removal. The documentation says `git rm` should not recurse without an explicit directory, so this behavior appears to violate the contract.

Евгений Плискин originally reported the issue, noting it on Git for Windows 2.55.0.windows.1 but suspecting it’s a core Git problem. So far, no patches or deeper analysis have been posted. Matt Hunter followed up, saying he couldn’t reproduce the behavior and asking for a minimal reproduction script to help pinpoint whether the recursion stems from shell glob expansion (Windows vs. POSIX differences) or Git’s own path-matching logic. The thread is still in the early diagnostic phase, with no decisions or resolutions yet.
