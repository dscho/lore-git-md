This is a bugfix patch targeting the `apply` subsystem, specifically the parsing of patch headers in `git apply`.

The patch addresses a memory leak and state corruption issue in `find_header()` where abandoned Git-style diff headers (those that are scanned but not ultimately used) could leave behind partially parsed state in the `struct patch`. This leftover state could then interfere with subsequent traditional "---/+++" header parsing, leading to impossible patch states (e.g., a patch marked as creating a new file but still carrying an old filename from the abandoned header). The fix introduces a temporary `struct patch` to parse Git headers into, only committing the parsed state to the real patch if the Git header is accepted. It also explicitly rejects empty default names from "diff --git" lines, which are invalid pathnames.

The commit message is clear and well-motivated, explaining both the problem and the solution. The regression tests cover both the empty default-name case and the abandoned-header case, demonstrating the issue and verifying the fix. The code changes are localized to `apply.c` and the test additions are in `t/t4100-apply-stat.sh`.

The patch appears to be a clean, well-scoped fix for a real bug with no obvious downsides. It touches a core part of Git's patch application logic, so the added test coverage is particularly valuable.
