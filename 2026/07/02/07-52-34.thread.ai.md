Thread identity
Subject: [PATCH 0/9] hash: plug memory leaks in non-default hash implementations
Series version: v1 (initial submission)
Originating author: Jeff King
Thread type: bugfix series

Core problem or goal
Git's hash context (`git_hash_ctx`) requires explicit cleanup via `git_hash_final()` when using non-default hash implementations (OpenSSL SHA-256, libgcrypt), but the codebase fails to call this function in error paths, causing memory leaks. These leaks are invisible with Git's default hash backends (which treat the context as a simple byte array) but become apparent under `SANITIZE=leak` with `OPENSSL_SHA256=1`. The series introduces a new `git_hash_discard()` primitive and systematically applies it to leaky subsystems: `csum-file`, `patch-id`, stream OID checking, HTTP object requests, and a libgcrypt-specific leak in SHA-256 handle copying. Patch 1 additionally removes a redundant `discard_hashfile()` function introduced in a prior commit, simplifying the `csum-file` API.

Current status
Initial submission (v1). No prior versions. Patch 3 (this email) applies the `git_hash_discard()` primitive to the `csum-file` subsystem, fixing leaks in error paths and `skip_hash` cases. Patches 4-9 remain unreviewed. No merge status (not queued in `seen`, `next`, or `master`).

Key technical details
- New symbols: `git_hash_discard()`, `hashfile_release_checkpoint()`, `free_hashfile_memory()`
- Modified subsystems: `csum-file` (patches 1, 3, 4), `patch-id` (patch 5), stream OID checking (patch 6), HTTP object requests (patch 7), libgcrypt SHA-256 handle copying (patch 8), platform-specific discard functions (patch 9)
- Files touched: `hash.h`, `hash.c`, `csum-file.h`, `csum-file.c`, `patch-id.c`, `http.c`, `object-file.c`, `sha1/openssl.h`, `sha256/gcrypt.h`, `sha256/openssl.h`
- Functions removed: `discard_hashfile()` (patch 1)
- Related symbols: `free_hashfile()`, `finalize_hashfile()`, `hashfd_check()`, `git_hash_final()`, `skip_hash`
- Implementation detail: `git_hash_discard()` calls `git_hash_final()` into a dummy buffer (inefficient but pragmatic); platform-specific optimizations deferred to patch 9. Patch 3 splits `free_hashfile()` into a public wrapper (calling `git_hash_discard()`) and an internal `free_hashfile_memory()` (used by `finalize_hashfile()` to avoid double-discarding).
- Test coverage: Leaks discovered via `SANITIZE=leak` and `OPENSSL_SHA256=1`; patch 3 eliminates leaks in six test scripts (`t1600`, `t1601`, `t2107`, `t7008`, `t9210`, `t9211`) when run with `OPENSSL_SHA1_UNSAFE=1`. CI gaps noted: linux-sha256 job lacks leak checking, libgcrypt not tested in CI.
- On-disk format: No changes
- Behavior: No user-visible changes; fixes correctness issue (memory leaks) in non-default configurations. Patch 1 is a refactoring cleanup with no functional impact.
