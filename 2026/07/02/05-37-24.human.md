This is a **substantive review comment** on the first patch of the recently merged four-part series that standardizes help-flag exit codes across Git's parse-options infrastructure. Jeff King (Peff) identifies a **bug in the `SVN` test prerequisite logic** introduced in the patch.

The issue is a shell-quoting error in the `test_lazy_prereq SVN` definition: single quotes inside the Perl one-liner prematurely terminate the shell snippet, causing the version comparison `$SVN::Core::VERSION gt '1.1.0'` to be parsed incorrectly. The Perl `gt` operator is then comparing a version string against an unquoted numeric literal, which can produce wrong results (Peff notes that 1.14.5 is correctly greater than 1.1.0 but incorrectly not greater than 1.2.0 under this bug). The error is inherited from `t/lib-git-svn.sh`, but the single-quote problem is new to this patch.

This is a **clear technical flaw** that could cause the `SVN` prerequisite to misbehave, potentially skipping tests when Subversion is actually available or vice versa. The fix is straightforward (escape or avoid single quotes in the Perl snippet), but the observation is sharp and worth addressing promptly given the series has already been merged. Peff's review is substantive and tested: he checked the actual behavior with his installed `SVN::Core` version and traced the quoting issue. The author, brian m. carlson, is expected to respond with a follow-up patch.
