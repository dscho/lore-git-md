This is a nine-patch series from Patrick Steinhardt targeting the test suite and CI infrastructure, specifically around the `GIT_TEST_LONG` environment variable. The series starts with a simple goal—adding a GitLab CI badge to the README and enabling `GIT_TEST_LONG` in GitLab CI—but expands to fix several broken or inefficient tests that surface when `GIT_TEST_LONG` is enabled.

The first patch adds a GitLab CI badge to the README for better visibility. The next six patches address test failures and inefficiencies that become apparent when `GIT_TEST_LONG` is active: skipping broken expensive tests on 32-bit systems, fixing inefficient `dd` usage, reducing disk usage in a clone test, cleaning up large repositories, and using a more robust helper (`test_bool_env`) to parse `GIT_TEST_LONG`. The final two patches adjust GitLab CI settings—disabling the RAM disk on macOS jobs (which was causing issues) and enabling `GIT_TEST_LONG` to ensure these tests run in CI.

The series is well-motivated: it fixes real problems that only appear under `GIT_TEST_LONG`, making the test suite more reliable and CI more useful. The changes are mostly small and focused, though some test adjustments (like the 2GB clone test) are more involved. If you care about test robustness or GitLab CI, this series is worth a look.
