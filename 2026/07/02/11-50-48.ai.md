This is a **build system** patch for the **Rustification effort**, specifically addressing macOS Universal Binary support for Rust components. Patrick Steinhardt's review of the v2 patch raises substantive technical concerns and suggests structural improvements.

The email questions whether the two changes—linking the macOS credential helper with Rust libraries and adding Universal Binary support—should be split into separate commits, as they address unrelated problems. Patrick also requests clearer motivation for Universal Binaries: what they are, why Git needs to support them, and what practical benefit they provide to users or developers on macOS. This is a notable gap in the current commit message.

On the implementation, Patrick identifies two key issues. First, he asks whether `lipo` (the macOS tool used to combine architecture-specific binaries) can be assumed to be universally available on macOS. Second, and more critically, he points out that the patch only handles Rust libraries, not the final binaries. If the rest of Git (written in C) is not also built as a Universal Binary, the Rust library's multi-architecture support may be ineffective or even counterproductive. This suggests the current approach may be incomplete or misaligned with how Universal Binaries are typically used in macOS development.

The review is substantive and tested: Patrick has clearly engaged with the code, identified a potential platform-compatibility issue, and raised a fundamental architectural question about how Universal Binaries should work in a mixed C/Rust codebase. His feedback implies that the patch, while technically functional for Rust libraries, may not deliver the intended user benefit without further work.

Key technical details for follow-up discussion:
- **Files touched**: `Makefile` (build system integration).
- **New symbols**: `RUST_TARGETS` (user-facing environment variable), `RUST_MEMBER_LIBS` (internal build variable).
- **Behavior change**: Multi-architecture Rust library builds on macOS via `lipo`.
