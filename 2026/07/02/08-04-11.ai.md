This is the fifth patch in Jeff King’s nine-patch **bugfix series** addressing memory leaks in Git’s hash algorithm handling when using non-default hash implementations (OpenSSL, libgcrypt). The series was previously summarized in the thread context.

This patch fixes a leak in the patch-id computation code (`builtin/patch-id.c` and `diff.c`). The `flush_one_hunk()` helper calls `git_hash_final()` on the running hash context and reinitializes it for the next hunk, but when the function returns after the last hunk, the hash context is discarded without cleanup. This leaks memory if the hash backend (e.g., OpenSSL SHA-256) allocated resources during initialization. The fix adds a single call to `git_hash_discard()` in both `get_one_patchid()` and `diff_get_patch_id()` to explicitly free the context.

The leak is reproducible with `SANITIZE=leak OPENSSL_SHA256=1 GIT_TEST_DEFAULT_HASH=sha256`, which triggers failures in 60 test scripts (57 fixed by this patch). The change is minimal—two lines added—and targets a correctness issue without altering behavior. The patch is uncontroversial and aligns with the series’ goal of systematically plugging leaks in error paths. No prior discussion or review feedback exists yet for this specific patch. Key symbols: `git_hash_discard()`, `flush_one_hunk()`, `get_one_patchid()`, `diff_get_patch_id()`.
