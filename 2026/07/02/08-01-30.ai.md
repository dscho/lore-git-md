This is the third patch in Jeff King’s nine-patch **bugfix series** plugging memory leaks in Git’s hash implementations when non-default backends (OpenSSL, libgcrypt) are used. The series was introduced in patch 2 with the new `git_hash_discard()` primitive; this patch applies it to the `csum-file` subsystem.

The patch ensures that every `hashfile` struct—created with an initialized `git_hash_ctx`—either calls `git_hash_final()` (via `finalize_hashfile()`) or explicitly discards the hash context with `git_hash_discard()`. Two leaky code paths are fixed: (1) direct calls to `free_hashfile()` that abort without finalizing, and (2) `finalize_hashfile()` skipping `git_hash_final()` when the `skip_hash` flag is set. The latter is particularly subtle because `skip_hash` is set *after* the hashfile is initialized, so the context is always allocated even when unused.

The fix splits `free_hashfile()` into two functions: the public `free_hashfile()` (now calling `git_hash_discard()`) and a new internal `free_hashfile_memory()` (used by `finalize_hashfile()` to avoid double-discarding). This preserves the existing API while ensuring cleanup. The patch eliminates leaks in six test scripts (`t1600`, `t1601`, `t2107`, `t7008`, `t9210`, `t9211`) when run with `SANITIZE=leak OPENSSL_SHA1_UNSAFE=1`.

Key technical details for follow-up:
- Modified file: `csum-file.c`
- New internal function: `free_hashfile_memory()`
- Public API unchanged: `free_hashfile()` now discards the hash context
- Behavior: No user-visible changes; fixes leaks in error paths and `skip_hash` cases
- Test coverage: Leaks confirmed via `SANITIZE=leak` with OpenSSL ≥ 3.0 (allocating backend)
- Related symbols: `hashfile_finalize()`, `git_hash_discard()`, `skip_hash`

The patch is narrowly scoped and well-motivated, addressing a correctness issue without altering functionality. It builds directly on patch 2’s `git_hash_discard()` and sets the stage for later patches (4–9) to apply the same fix to other leak sites. No reviews or objections have surfaced yet.
