This is a build system patch for the Rustification effort, specifically enabling macOS Universal Binary support for Rust components in Git. The v3 series splits the previous monolithic patch into two focused commits: the first ensures the macOS credential helper (`git-credential-osxkeychain`) links against Rust libraries when Rust is enabled, while the second introduces the `RUST_TARGETS` environment variable to compile and combine multiple architecture-specific Rust static libraries into a single Universal Binary using `lipo`.

The motivation is now clearly stated: Universal Binaries are standard practice for macOS distribution, allowing a single build artifact to run natively on both Intel and Apple Silicon Macs without Rosetta emulation. The commit message explains how this integrates with the existing C build system (which already supports Universal Binaries via clang flags) and why Rust requires a different approach (Cargo must be invoked separately for each target triple). The implementation uses declarative Make pattern rules to compile each target-specific library slice, then combines them with `lipo`—a tool the authors assert is part of the mandatory Xcode Command Line Tools on macOS.

This version addresses all prior feedback: it splits the unrelated changes into separate commits, adds a `mkdir_p_parent_template` call to preemptively create the target directory, and expands the commit message to justify Universal Binaries and document the new `RUST_TARGETS` variable. The patch appears well-crafted and ready for final review, though Patrick Steinhardt’s earlier concerns about `lipo` availability and whether the C code also needs Universal Binary treatment remain unresolved. If those are addressed, this looks like a clean, maintainable solution to a real packaging problem.
