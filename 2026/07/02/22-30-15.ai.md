This is a **build system** patch for the **Rustification effort**, specifically addressing macOS Universal Binary support and a parallel build race condition. The email is a reply from Shardul Natu to Patrick Steinhardt’s substantive review of the v2 patch, clarifying technical details and announcing a v3 split.

The response confirms that the v3 series will separate the two unrelated changes: (1) fixing a parallel build race by ensuring `git-credential-osxkeychain` links against Rust libraries when Rust is enabled, and (2) introducing Universal Binary support via the `RUST_TARGETS` environment variable. The first change is uncontroversial and ready to proceed; the second remains under discussion due to Patrick’s architectural concerns.

Shardul addresses Patrick’s questions about `lipo` availability (it is part of Xcode Command Line Tools, a hard prerequisite for macOS builds) and explains why only Rust libraries need explicit Universal Binary treatment: Apple’s C toolchain natively supports multi-architecture builds via `-arch` flags, while Cargo requires separate invocations per target triple. The patch bridges this gap by using `lipo` to combine target-specific Rust static libraries into a single universal archive, which the C linker then incorporates into the final universal Git executables. This explanation clarifies the practical benefit of Universal Binaries for macOS distribution and CI packaging, though Patrick’s concern about whether the C build also needs Universal Binary treatment remains unresolved.
