This is the fifth patch in Toon Claes’s nine-patch series making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets the test suite’s `t7508-status.sh` script, specifically an expensive test that creates and adds files larger than 4 GiB. The test is currently gated by the `EXPENSIVE` prerequisite but fails (and hangs) on 32-bit systems because Git tracks object sizes using `size_t`, which cannot represent files larger than 4 GiB on those platforms. The patch adds the `SIZE_T_IS_64BIT` prerequisite to the test, skipping it on 32-bit systems where it is known to be broken.

The change is a single-line modification to `t7508-status.sh`, replacing `EXPENSIVE` with `EXPENSIVE,SIZE_T_IS_64BIT` in the test’s prerequisite list. This is a targeted fix for a known issue that has been causing CI hangs in GitHub’s `linux32` job since `7a094d68a2` (2026-05-08), which enabled expensive tests on integration branch pushes. The commit message clearly explains the technical limitation (Git’s use of `size_t` for object sizes) and the pragmatic rationale for skipping the test rather than attempting a deeper fix.

This patch is part of the series’ broader goal of making `GIT_TEST_LONG` tests reliable enough to run in CI without hanging or consuming excessive resources. It complements earlier patches that skip broken tests in `t0021-conversion.sh` (patch 2) and later patches that improve test efficiency (e.g., patch 3’s refactor of `t4141-apply-too-large.sh`). The change is uncontroversial and aligns with the series’ focus on pragmatic fixes for CI stability. No new behavior or user-facing features are introduced; the patch simply prevents a known-broken test from running on incompatible platforms.
