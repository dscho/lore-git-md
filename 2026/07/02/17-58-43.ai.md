This is the first patch in the v6 series introducing `--linearize` to `git replay`. It refactors internal replay machinery by extracting a helper function `put_mapped_commit()` to encapsulate the logic for storing rewritten commits in the `replayed_commits` map. The existing `mapped_commit()` function is renamed to `get_mapped_commit()` for symmetry.

The patch touches only `replay.c` and is purely a refactoring with no behavior change. It prepares the codebase for the `--linearize` feature by making the commit-mapping logic more modular and readable. The new `put_mapped_commit()` helper will be used in patch 3/3 to record linearized commits. This refactoring was uncontested in prior rounds and is now stable.

For the summarizer: the key names introduced are `put_mapped_commit()` and `get_mapped_commit()` (replacing `mapped_commit()`). The patch is mechanical and does not affect user-facing behavior or command-line options. It is a prerequisite for the `--linearize` implementation in patch 3.
