This thread is about a bug in `git rev-list --exclude-first-parent-only` where the option incorrectly excludes commits when additional commits are explicitly specified on the command line, even if those commits are not part of the first-parent ancestry path being excluded. The issue was reported by Michael Hore, who provided a clear reproduction case and diagnosis.

Junio C Hamano proposed a fix targeting the `process_parents()` function in `revision.c`, which ensures that explicitly specified commits are correctly handled. The fix includes a new test case in `t/t6012-rev-list-simplify.sh` to verify the correction. Jerry Zhang, the original author of the `--exclude-first-parent-only` option, has reviewed the patch and confirmed that it aligns with the intended behavior. His review, which includes a **Reviewed-by** trailer, clarifies that the option is designed to exclude only the first-parent ancestry path while still including commits reachable from explicitly specified commits. This review significantly strengthens the case for merging the patch, as it comes from the feature’s original author and addresses concerns about the fix’s correctness.

The patch is now effectively ready for integration unless other reviewers raise additional concerns. Open questions remain about whether the fix might break other use cases or if further test coverage is needed for edge cases like octopus merges, but no substantive objections have been raised so far. The fix is isolated to the revision traversal subsystem and does not depend on other in-flight topics.
