This thread is about a bug in `git rev-list --exclude-first-parent-only` where the option incorrectly excludes commits when additional commits are explicitly specified on the command line. Michael Hore reported the issue with a clear reproduction case, pointing to `process_parents()` in `revision.c` as the likely source.

Junio C Hamano has now proposed a fix that modifies `process_parents()` to break out of the parent-processing loop early when `--exclude-first-parent-only` is active and certain conditions are met. This prevents the exclusion logic from incorrectly marking commits as uninteresting. The patch includes a new test case to verify the fix, though Junio notes some uncertainty about whether the change might break other intended use cases, as the original author of the feature is no longer active.

The fix is straightforward and well-motivated, targeting a clear edge case in the revision-walking machinery. No other participants have weighed in yet, but the patch is likely to be merged if no regressions are found. The thread is now focused on whether this change aligns with the intended behavior of `--exclude-first-parent-only` and whether it introduces any unintended side effects.
