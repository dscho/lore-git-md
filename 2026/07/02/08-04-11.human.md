This is the fifth patch in Jeff King’s nine-patch **bugfix series** plugging memory leaks in Git’s hash implementations when using non-default backends like OpenSSL or libgcrypt. The patch targets the `patch-id` subsystem, where the `git_hash_ctx` used to compute patch IDs was never explicitly discarded after use, leaking memory if the hash backend allocated resources during initialization.

The fix is minimal: a single call to `git_hash_discard()` is added in both `builtin/patch-id.c` and `diff.c` after the final `flush_one_hunk()` call, ensuring the hash context is properly cleaned up. The leak is particularly noticeable with OpenSSL’s SHA-256 implementation, where running the test suite with `SANITIZE=leak` and `OPENSSL_SHA256=1` previously triggered failures in 57 test scripts—mostly those involving `git rebase`, which internally uses patch IDs.

The patch is straightforward and well-motivated, addressing a clear correctness issue without changing behavior. It follows the pattern established in earlier patches (e.g., patch 3’s `csum-file` fixes) and is unlikely to be controversial. The only potential discussion point might be whether the leak’s impact—limited to non-default hash backends—justifies the added cleanup code, but given the series’ goal of eliminating all such leaks, this patch fits neatly into the broader effort.
