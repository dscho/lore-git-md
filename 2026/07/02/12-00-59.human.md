This is the sixth patch in a nine-patch series that makes `GIT_TEST_LONG` tests more reliable and efficient in CI. The series as a whole is well-motivated: it fixes broken tests, reduces resource usage, and enables GitLab CI to run expensive tests that were previously skipped.

This specific patch targets `t7900-maintenance.sh`, one of the tests gated by `GIT_TEST_LONG` because it creates a 2 GB repository. The problem is that the test never cleans up the repository, so the 2 GB of data persists until the entire test suite finishes. This not only wastes disk space but also forces subsequent tests to potentially repack the same data multiple times, slowing everything down.

Patrick Steinhardt’s fix is straightforward and mechanical: he moves the test into a separate repository that is cleaned up immediately after the test completes. He also disables auto-maintenance to prevent races with the manual maintenance commands the test runs. The change is purely about efficiency and resource management—no behavior is altered, and the test still verifies the same functionality. The patch looks clean and uncontroversial; it should reduce CI resource usage without introducing new risks.
