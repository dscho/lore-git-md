Subject: [PATCH 0/9] ci & test: make GIT_TEST_LONG tests reliable and efficient
Series version: v1 (initial submission)
Originating author: Toon Claes
Thread type: patch series

Core problem or goal
The series addresses two related problems in Git’s test suite and CI infrastructure: (1) several tests gated by the `GIT_TEST_LONG` environment variable are broken or hang in GitHub CI and GitLab CI, and (2) the GitLab CI pipeline does not run these expensive tests at all, leaving long-running test coverage invisible. The goal is to make `GIT_TEST_LONG` tests reliable and efficient enough to run in CI without consuming excessive resources or hanging pipelines.

Current status
The series is at v1, submitted by Toon Claes. No prior versions exist. No patches have been merged or queued. The changes are split into three categories: CI visibility/configuration (patches 1, 8, 9), test correctness fixes (patches 2, 5, 7), and test efficiency improvements (patches 3, 4, 6). Patch 1 (README badge) is uncontroversial and purely additive. Patch 2 (this update) addresses a broken test in `t0021-conversion.sh` that hangs on 64-bit systems by skipping it when `SIZE_T_IS_64BIT` is set. Patch 3 (new email) refactors `t4141-apply-too-large.sh` to replace a byte-by-byte `dd` copy with direct `genzeros` generation, reducing runtime from minutes to under a second and removing the `EXPENSIVE` prerequisite. Patch 4 (new email) reduces peak disk usage in `t5608-clone-2gb.sh` from 16 GB to 8 GB by deleting repositories as soon as they are no longer needed, using `test_when_finished` and explicit `rm -rf` calls.

Key technical details
- Files touched: test scripts (`t0021-conversion.sh`, `t4141-apply-too-large.sh`, `t5608-clone-2gb.sh`, `t7508-status.sh`, `t7900-maintenance.sh`), CI configuration (`.gitlab-ci.yml`, `ci/lib.sh`), `README.md`, and a new helper function `test_bool_env` for consistent boolean parsing of `GIT_TEST_LONG`.
- Test behavior changes: two tests (`t0021`, `t7508`) are now skipped on 64-bit systems (where `SIZE_T_IS_32BIT` is not set) due to being broken; three tests (`t4141`, `t5608`, `t7900`) are refactored to use less disk space or CPU time (e.g., `fallocate` instead of `dd`, reduced file size from 2 GiB to 1 GiB, and immediate repository cleanup). Patch 2 specifically skips `t0021` on 64-bit platforms to avoid hangs. Patch 3 replaces the `test_copy_bytes` pipeline (`dd ibs=1`) with direct `genzeros` generation in `t4141`, eliminating a 6-minute bottleneck and removing the `EXPENSIVE` prerequisite, making the test runnable in standard CI. Patch 4 reduces peak disk usage in `t5608` by deleting repositories immediately after use, cutting the footprint from 16 GB to 8 GB.
- CI changes: GitLab CI now enables `GIT_TEST_LONG`, and the macOS RAM disk is disabled to prevent out-of-memory issues.
- No new CLI options, config keys, or on-disk format changes.
