Core problem or goal
The series addresses two related problems in Git’s test suite and CI infrastructure: (1) several tests gated by the `GIT_TEST_LONG` environment variable are broken or hang in GitHub CI and GitLab CI, and (2) the GitLab CI pipeline does not run these expensive tests at all, leaving long-running test coverage invisible. The goal is to make `GIT_TEST_LONG` tests reliable and efficient enough to run in CI without consuming excessive resources or hanging pipelines.

Current status
The series is at v1, submitted by Toon Claes. No prior versions exist. No patches have been merged or queued. The changes are split into three categories: CI visibility/configuration (patches 1, 7, 8, 9), test correctness fixes (patches 2, 5), and test efficiency improvements (patches 3, 4, 6). Patch 1 (README badge) is uncontroversial and purely additive. Patch 2 addresses a broken test in `t0021-conversion.sh` that hangs on 64-bit systems by skipping it when `SIZE_T_IS_64BIT` is set. Patch 3 refactors `t4141-apply-too-large.sh` to replace a byte-by-byte `dd` copy with direct `genzeros` generation, reducing runtime from minutes to under a second and removing the `EXPENSIVE` prerequisite. Patch 4 reduces peak disk usage in `t5608-clone-2gb.sh` from 16 GB to 8 GB by deleting repositories as soon as they are no longer needed. Patch 5 adds the `SIZE_T_IS_64BIT` prerequisite to `t7508-status.sh`, skipping a test that creates and adds files larger than 4 GiB on 32-bit systems where `size_t` cannot represent such sizes. Patch 6 refactors `t7900-maintenance.sh` to clean up the 2 GB repository immediately after the test finishes, reducing peak disk usage and preventing the data from being repacked by later tests. Patch 7 standardizes the parsing of the `GIT_TEST_LONG` environment variable across the test suite and CI scripts by switching to the `test_bool_env` helper, ensuring consistent boolean interpretation (e.g., `false` or `0` disables the variable). Patch 8 (GitLab CI macOS RAM disk) disables the RAM disk workaround on macOS GitLab CI jobs to prevent out-of-memory errors when running `GIT_TEST_LONG` tests, which write up to 8 GB of data. The RAM disk was originally added to work around slow macOS disks but was limited to 4 GB, causing `ENOSPC` errors. Disabling it increases job runtime (from 18–21 minutes to 25–33 minutes) but is justified for stability. Patch 9 (GitLab CI configuration) enables `GIT_TEST_LONG` in the GitLab pipeline and disables it on Windows runners due to insufficient RAM (7.5 GB).

Key technical details
- Files touched: test scripts (`t0021-conversion.sh`, `t4141-apply-too-large.sh`, `t5608-clone-2gb.sh`, `t7508-status.sh`, `t7900-maintenance.sh`), CI configuration (`.gitlab-ci.yml`, `ci/lib.sh`), `README.md`, and `t/test-lib.sh`.
- Test behavior changes: three tests (`t0021`, `t7508`, `t7900`) are now skipped on platforms where they are known to be broken due to `size_t` limitations (64-bit for `t0021`, 32-bit for `t7508`); three tests (`t4141`, `t5608`, `t7900`) are refactored to use less disk space or CPU time (e.g., `fallocate` instead of `dd`, reduced file size from 2 GiB to 1 GiB, and immediate repository cleanup). Patch 2 skips `t0021` on 64-bit platforms to avoid hangs. Patch 3 replaces the `test_copy_bytes` pipeline (`dd ibs=1`) with direct `genzeros` generation in `t4141`, eliminating a 6-minute bottleneck and removing the `EXPENSIVE` prerequisite. Patch 4 reduces peak disk usage in `t5608` by deleting repositories immediately after use, cutting the footprint from 16 GB to 8 GB. Patch 5 adds `SIZE_T_IS_64BIT` to `t7508`’s prerequisites, skipping the test on 32-bit systems where Git cannot track object sizes larger than 4 GiB. Patch 6 isolates the 2 GB repository in `t7900` into a dedicated sub-repository that is deleted immediately after the test, reducing peak disk usage and preventing repacking by later tests. Patch 7 introduces consistent boolean parsing for `GIT_TEST_LONG` via `test_bool_env`, ensuring that the variable can be explicitly disabled (e.g., `GIT_TEST_LONG=false`). Patch 8 disables the macOS RAM disk in `.gitlab-ci.yml` by removing the `TEST_OUTPUT_DIRECTORY` override and the `before_script` steps that created the RAM disk, defaulting to `/tmp/test-output` instead. Patch 9 enables `GIT_TEST_LONG` in GitLab CI for qualifying events (pushes to integration branches) and disables it on Windows runners (`test:mingw64` and `test:msvc-meson`) due to insufficient RAM (7.5 GB). The patch maps GitLab’s `CI_PIPELINE_SOURCE` to the GitHub-style `CI_EVENT` variable and uses `GIT_TEST_LONG=${GIT_TEST_LONG:-true}` to allow explicit override while defaulting to `true` for qualifying events.
- CI changes: GitLab CI now enables `GIT_TEST_LONG` for pushes to integration branches (`next`, `master`, `main`, `maint`), matching GitHub Actions behavior. The macOS RAM disk is disabled (patch 8) to prevent out-of-memory issues, and Windows runners are excluded (patch 9) due to hardware limitations.
- No new CLI options, config keys, or on-disk format changes. The `test_bool_env` helper is internal to the test suite and does not affect user-facing behavior.
