Core problem or goal
The series addresses two related problems in Git’s test suite and CI infrastructure: (1) several tests gated by the `GIT_TEST_LONG` environment variable are broken or hang in GitHub CI and GitLab CI, and (2) the GitLab CI pipeline does not run these expensive tests at all, leaving long-running test coverage invisible. The goal is to make `GIT_TEST_LONG` tests reliable and efficient enough to run in CI without consuming excessive resources or hanging pipelines, while ensuring that resource-intensive tests remain appropriately labeled.

Current status
The series is at v1, submitted by Toon Claes. No prior versions exist. No patches have been merged or queued. The changes are split into three categories: CI visibility/configuration (patches 1, 7, 8, 9), test correctness fixes (patches 2, 5), and test efficiency improvements (patches 3, 4, 6). All patches except patches 3 and 5 are uncontroversial. Patch 6 (refactoring `t7900-maintenance.sh`) has received substantive review from Jeff King (Peff), who endorses it as an "obvious improvement" for reducing peak disk usage, despite noting that runtime remains unchanged. Patch 3 (refactoring `t4141-apply-too-large.sh`) continues to draw substantive reviews from SZEDER Gábor and Peff, with Gábor arguing for retaining the `EXPENSIVE` prerequisite due to high memory usage, and Peff raising broader questions about the `test_copy_bytes` helper's design. Patch 5 (skipping `t7508-status.sh` on 32-bit systems) is now uncontested after Peff retracted his earlier confusion, confirming the patch’s motivation and the necessity of the `SIZE_T_IS_64BIT` prerequisite.

Key technical details
- Files touched: test scripts (`t0021-conversion.sh`, `t4141-apply-too-large.sh`, `t5608-clone-2gb.sh`, `t7508-status.sh`, `t7900-maintenance.sh`), CI configuration (`.gitlab-ci.yml`, `ci/lib.sh`), `README.md`, and `t/test-lib.sh`.
- Test behavior changes: three tests (`t0021`, `t7508`, `t7900`) are now skipped on platforms where they are known to be broken due to `size_t` limitations (64-bit for `t0021`, 32-bit for `t7508`); three tests (`t4141`, `t5608`, `t7900`) are refactored to use less disk space or CPU time (e.g., `fallocate` instead of `dd`, reduced file size from 2 GiB to 1 GiB, and immediate repository cleanup). Patch 2 skips `t0021` on 64-bit platforms to avoid hangs. Patch 3 replaces the `test_copy_bytes` pipeline (`dd ibs=1`) with direct `genzeros` generation in `t4141`, eliminating a 6-minute bottleneck but leaving memory usage unchanged (RSS > 1 GiB). The `EXPENSIVE` prerequisite was removed in this patch, which Gábor argues is premature. Peff’s review notes that `test_copy_bytes` was originally introduced due to portability concerns with `head -c` but questions whether those concerns still apply. Patch 4 reduces peak disk usage in `t5608` by deleting repositories immediately after use, cutting the footprint from 16 GB to 8 GB. Patch 5 adds `SIZE_T_IS_64BIT` to `t7508`’s prerequisites, skipping the test on 32-bit systems where Git cannot track object sizes larger than 4 GiB. Peff’s follow-up confirms the issue is real and the prerequisite is necessary. Patch 6 isolates the 2 GB repository in `t7900` into a dedicated sub-repository (`expensive-repo`) that is deleted immediately after the test via `test_when_finished`, reducing peak disk usage and preventing repacking by later tests. The sub-repository also disables auto-maintenance to avoid races. Peff tested the patch and confirmed it does not reduce runtime (~1m40s with `--long`) but endorsed it for its disk usage improvements. Patch 7 introduces consistent boolean parsing for `GIT_TEST_LONG` via `test_bool_env`, ensuring the variable can be explicitly disabled (e.g., `GIT_TEST_LONG=false`). Patch 8 disables the macOS RAM disk in `.gitlab-ci.yml` by removing the `TEST_OUTPUT_DIRECTORY` override and the `before_script` steps that created the RAM disk, defaulting to `/tmp/test-output` instead. Patch 9 enables `GIT_TEST_LONG` in GitLab CI for qualifying events (pushes to integration branches) and disables it on Windows runners (`test:mingw64` and `test:msvc-meson`) due to insufficient RAM (7.5 GB).
- CI changes: GitLab CI now enables `GIT_TEST_LONG` for pushes to integration branches (`next`, `master`, `main`, `maint`), matching GitHub Actions behavior. The macOS RAM disk is disabled (patch 8) to prevent out-of-memory issues, and Windows runners are excluded (patch 9) due to hardware limitations.
- No new CLI options, config keys, or on-disk format changes. The `test_bool_env` helper is internal to the test suite and does not affect user-facing behavior.
