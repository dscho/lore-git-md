Toon Claes’s patch series aims to make Git’s long-running tests (`GIT_TEST_LONG`) both reliable and efficient enough to run in CI. The series is at its first version, with no prior iterations, and addresses broken or hanging tests in GitHub and GitLab CI while also enabling these tests in GitLab’s pipeline for the first time. Most of the changes are uncontroversial—fixing flaky tests, reducing disk usage, and standardizing environment variable handling—but one patch has drawn scrutiny.

Patch 3, originally written by Patrick Steinhardt, refactors `t4141-apply-too-large.sh` to replace a slow byte-by-byte `dd` copy with direct `genzeros` generation, cutting runtime from minutes to under a second. This change also removed the `EXPENSIVE` prerequisite, as the test no longer took long to run. However, SZEDER Gábor pointed out that while the test is now fast, `git apply` still consumes over 1 GiB of memory when processing the 1 GiB patch, which he argues is itself an "expensive" resource cost. The `EXPENSIVE` label, he suggests, should be retained to reflect this, even if the test runs quickly. The review doesn’t dispute the technical correctness of the patch but raises a policy question about how Git defines "expensive" tests—whether the label should apply to runtime, memory usage, or both.

The rest of the series remains unchallenged. Patches 1 (README badge), 2 (skipping a broken test on 64-bit systems), 4 (reducing disk usage in `t5608`), 5 (skipping a 32-bit-incompatible test), 6 (cleaning up test repositories sooner), 7 (standardizing `GIT_TEST_LONG` parsing), 8 (disabling the macOS RAM disk to prevent out-of-memory errors), and 9 (enabling `GIT_TEST_LONG` in GitLab CI while excluding Windows runners) all address specific, well-defined problems without introducing new concerns. The series as a whole is a pragmatic effort to improve CI coverage and test reliability, and aside from the `EXPENSIVE` debate in patch 3, there’s no indication of deeper disagreements or unresolved technical issues. The next step will likely be a response from Toon or Patrick on whether to restore the `EXPENSIVE` label or adjust the patch’s rationale.
