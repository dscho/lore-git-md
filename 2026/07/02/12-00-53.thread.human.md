This thread is a nine-patch series aimed at making Git’s `GIT_TEST_LONG` tests more reliable and efficient in CI. Originally submitted by Toon Claes as v1, the series was revised by Patrick Steinhardt as v2 to address feedback, particularly around test correctness and resource usage. The goal is to fix broken or hanging tests, reduce their resource consumption, and ensure they run in GitLab CI (matching GitHub Actions coverage) without overloading runners.

All patches are now uncontroversial and ready for integration, with one minor exception: patch 2/9, which skips an expensive test on 64-bit platforms, needs a trivial commit message update to correct a phrasing error about the `SIZE_T_IS_64BIT` prerequisite. Junio C Hamano pointed out the inaccuracy, and Patrick agreed to fix it. The rest of the series—covering CI configuration, test efficiency improvements, and platform-specific skips—has no open technical issues. Key changes include replacing a slow `dd`-based pipeline with a faster `genzeros` helper (while retaining the `EXPENSIVE` label due to high memory usage), reducing disk footprint in several tests, and enabling `GIT_TEST_LONG` for GitLab CI pushes to integration branches (excluding Windows due to hardware limits).

The series has received substantive reviews from Jeff King (Peff) and SZEDER Gábor, with all objections resolved. No maintainer has yet weighed in on the broader policy question of how Git defines "expensive" tests (runtime vs. resource usage), but this doesn’t block integration. The patches touch test scripts, CI configuration, and internal helpers, with no user-facing changes. Once the commit message nit is addressed, the series should be ready for Junio’s queue.
