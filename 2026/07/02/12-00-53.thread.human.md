This thread is about a nine-patch series from Toon Claes that aims to make Git’s `GIT_TEST_LONG` tests both reliable and efficient enough to run in CI. The series addresses two key problems: broken or hanging tests in GitHub and GitLab CI, and the fact that GitLab CI doesn’t run these expensive tests at all. So far, the series has introduced fixes for specific test hangs (like skipping a broken test on 64-bit systems), performance improvements (such as replacing a slow `dd` copy with direct generation of test data), and CI configuration changes to enable `GIT_TEST_LONG` in GitLab.

The latest patch, the fourth in the series, focuses on `t5608-clone-2gb.sh`, a test that verifies Git’s handling of large repositories by creating clones with multi-gigabyte packfiles. The patch reduces peak disk usage from 16 GB to 8 GB by cleaning up repositories as soon as they’re no longer needed, using `test_when_finished` and explicit `rm -rf` calls. This is a purely mechanical change—no test logic is altered, just cleanup hooks are added—and it directly supports the series’ goal of making these tests more CI-friendly. No reviews or objections have been recorded yet, and the series remains uncontroversial so far. The next patches are likely to continue this pattern of targeted fixes and efficiency improvements.
