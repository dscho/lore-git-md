This thread is a nine-patch series aimed at making Git’s `GIT_TEST_LONG` tests more reliable and efficient for CI, now in its second version submitted by Patrick Steinhardt. The series addresses two key problems: broken or hanging `GIT_TEST_LONG` tests in GitHub and GitLab CI, and the lack of coverage for these tests in GitLab CI. The v2 revision incorporates all feedback from the initial submission by Toon Claes, including a notable concession to retain the `EXPENSIVE` prerequisite in one test due to high memory usage, despite runtime improvements.

The series is split into three categories: CI visibility and configuration (patches 1, 8, and 9), test correctness fixes (patches 2, 5, and 7), and efficiency improvements (patches 3, 4, and 6). The latest patch, the sixth in the series, focuses on `t7900-maintenance.sh`, an expensive test that creates a 2 GB repository. It isolates this repository into a dedicated sub-repository that is deleted immediately after the test, reducing peak disk usage and preventing state pollution for subsequent tests. This change, like others in the series, is uncontroversial and follows established patterns for managing expensive test data.

Key participants include Patrick Steinhardt, who authored the v2 series and addressed feedback, and SZEDER Gábor, whose objection about memory usage led to restoring the `EXPENSIVE` prerequisite in one test. Jeff King (Peff) has also reviewed several patches, endorsing the efficiency improvements while raising broader questions about test design that were ultimately resolved. The series is now ready for integration, with no outstanding technical objections or open questions. It aligns GitLab CI behavior with GitHub Actions and introduces internal improvements, like the `test_bool_env` helper, that may serve as models for future test suite cleanup.
