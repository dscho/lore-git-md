This thread is a nine-patch series aimed at making Git’s `GIT_TEST_LONG` tests reliable and efficient enough to run in CI without hanging or consuming excessive resources. Originally identified by Toon Claes, the series was refined and resubmitted as v2 and v3 by Patrick Steinhardt, addressing feedback from reviewers like SZEDER Gábor and Jeff King.

The series fixes broken or hanging tests, improves their efficiency, and ensures they run in both GitHub Actions and GitLab CI. Key changes include skipping tests on platforms where they’re known to fail due to `size_t` limitations, reducing disk and CPU usage in resource-intensive tests, and introducing a consistent way to parse the `GIT_TEST_LONG` environment variable. The final patch (v3’s patch 9) enables `GIT_TEST_LONG` for GitLab CI pushes to integration branches, matching GitHub Actions’ behavior, while pragmatically excluding Windows runners due to hardware constraints.

All patches are uncontroversial and ready for integration. The series has resolved all prior feedback, including a substantive objection about retaining the `EXPENSIVE` prerequisite for a memory-heavy test and a surface-level nit about commit subject accuracy. The changes are split into three categories: CI visibility/configuration, test correctness fixes, and efficiency improvements. No further changes are expected, and the series is now complete.
