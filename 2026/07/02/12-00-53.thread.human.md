This thread is about a nine-patch series aimed at making Git’s long-running tests (`GIT_TEST_LONG`) more reliable and efficient in CI. The series, now in its second version, was originally proposed by Toon Claes and has been revised by Patrick Steinhardt to address feedback.

The goal is to fix broken or hanging tests in GitHub and GitLab CI while ensuring that resource-intensive tests remain appropriately labeled. The series also enables `GIT_TEST_LONG` tests in GitLab CI for the first time, aligning its behavior with GitHub Actions. Key changes include skipping tests on platforms where they’re known to fail, reducing disk and CPU usage in others, and improving CI configuration to avoid out-of-memory issues.

The first patch in this version simply adds a GitLab CI status badge to the project’s README, making the pipeline more visible alongside the existing GitHub badge. This is a minor but useful documentation tweak that sets the stage for the rest of the series. The rest of the patches address test correctness, efficiency, and CI configuration—all uncontroversial at this point. The only substantive feedback from the first version (about retaining the `EXPENSIVE` label for a memory-heavy test) has been resolved, and the series appears ready for integration. No maintainer has weighed in yet, but the changes have been endorsed by Jeff King (Peff) and SZEDER Gábor’s concerns have been addressed.
