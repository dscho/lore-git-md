This thread is about a nine-patch series that makes Git’s long-running tests (`GIT_TEST_LONG`) reliable and efficient enough to run in CI. Originally submitted by Toon Claes (v1) and later revised by Patrick Steinhardt (v2, v3), the series fixes broken or hanging tests in GitHub CI and enables these tests in GitLab CI for the first time. The v3 revision, just approved by Junio C Hamano, corrects only the commit subjects for two patches to clarify prerequisite logic—no technical changes were needed.

The series is now ready for integration. All substantive feedback from earlier versions has been addressed, including restoring the `EXPENSIVE` label for a memory-intensive test after SZEDER Gábor objected. The patches fall into three categories: CI configuration (enabling `GIT_TEST_LONG` in GitLab CI and improving pipeline visibility), test correctness fixes (skipping tests on platforms where they’re known to fail), and efficiency improvements (reducing disk and CPU usage). Windows runners are excluded due to hardware limitations, and a macOS RAM-disk workaround was removed to prevent out-of-memory issues.

Key participants include Patrick Steinhardt (who drove the revisions), SZEDER Gábor (who raised a memory-usage concern), Jeff King (who reviewed several patches), and Junio (who approved the final version). The series is uncontroversial and introduces no user-facing changes—just internal test and CI improvements. It’s now queued for `next`.
