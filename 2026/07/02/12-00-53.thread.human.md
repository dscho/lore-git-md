Toon Claes’s nine-patch series to make Git’s `GIT_TEST_LONG` tests reliable and efficient in CI is nearing consensus. The series tackles two main issues: broken or hanging tests in GitHub and GitLab CI, and the lack of coverage for long-running tests in GitLab’s pipeline. Most patches are uncontroversial, focusing on CI configuration, test correctness, and efficiency improvements.

The key technical changes include skipping tests on platforms where they’re known to fail due to `size_t` limitations, refactoring tests to use less disk space or CPU time, and ensuring expensive test data is cleaned up immediately. Patch 6, which refactors `t7900-maintenance.sh` to isolate and delete a 2 GiB repository right after the test, has drawn praise from Jeff King (Peff) and Patrick Steinhardt. While it doesn’t reduce runtime, it’s seen as an "obvious improvement" for disk usage and test isolation. Patch 3, which originally aimed to remove the `EXPENSIVE` prerequisite from `t4141-apply-too-large.sh`, will retain the label after SZEDER Gábor’s review highlighted its high memory usage—over 1 GiB—despite the runtime fix.

The series also aligns GitLab CI with GitHub Actions by enabling `GIT_TEST_LONG` for pushes to integration branches, while disabling it on Windows runners due to hardware constraints. The only remaining open question is a policy-level discussion about how Git defines "expensive" tests—whether by runtime or resource usage—but this doesn’t block the current patches. With no maintainer feedback yet, the series is ready for a v2 addressing the minor adjustments agreed upon during review.
