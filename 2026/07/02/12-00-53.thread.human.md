This thread is about a patch series from Toon Claes aimed at making Git’s long-running tests (`GIT_TEST_LONG`) reliable and efficient enough to run in CI. The series tackles two main issues: broken or hanging tests in GitHub and GitLab CI, and the fact that GitLab CI doesn’t run these expensive tests at all. The patches are split into three groups—CI configuration, test correctness fixes, and efficiency improvements—and most are uncontroversial.

The key sticking points have been around two patches. Patch 3, which refactors `t4141-apply-too-large.sh`, drew substantive reviews from SZEDER Gábor and Jeff King (Peff). Gábor argued the `EXPENSIVE` prerequisite should stay due to high memory usage, while Peff questioned the design of the `test_copy_bytes` helper. Patch 5, which skips `t7508-status.sh` on 32-bit systems, was initially questioned by Peff, who thought the test passed in his CI setup. However, in this latest email, Peff clarified that his setup wasn’t actually running the expensive tests, confirming the patch’s fix is correct. Patch 6, which refactors `t7900-maintenance.sh` to reduce disk usage, has been endorsed by Peff as an "obvious improvement."

The series is now largely uncontested, with the only remaining open question being whether the `EXPENSIVE` prerequisite should be retained for patch 3. Toon Claes and Patrick Steinhardt (the original author of patches 3, 5, and 6) haven’t yet responded to the reviews, but the path forward seems clear: patch 5 is now confirmed as correct, and the discussion around patch 3 is more about policy than code. The CI changes in the series will enable `GIT_TEST_LONG` tests in GitLab CI for integration branches, aligning it with GitHub Actions.
