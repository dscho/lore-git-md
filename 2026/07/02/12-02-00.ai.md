This is the second patch in Patrick Steinhardt’s six-patch ODB refactoring series, targeting the `struct object_info` redesign. It splits the backend-specific union (`u`) out of `struct object_info` into a new opt-in `struct object_info_source`, making provenance information optional rather than unconditionally populated. The patch is mechanical: it moves the `u` union into the new struct, adds a `sourcep` pointer to `struct object_info`, and updates all callers to either pass a stack-allocated `struct object_info_source` (if they need provenance) or `NULL` (if they don’t). No behavior changes are introduced—existing callers that previously accessed `oi->u.packed` now access `oi->sourcep->u.packed` instead.

The patch touches seven files (`builtin/cat-file.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `odb.c`, `odb.h`, `packfile.c`, `reachable.c`), primarily updating object lookup and traversal logic. The most invasive changes are in `odb.h`, where the new `struct object_info_source` is defined and the `u` union is removed from `struct object_info`. The `packfile.c` changes are notable for guarding all `sourcep` population behind a `NULL` check, ensuring callers that don’t request provenance aren’t penalized. The commit message explicitly notes that the `whence` field remains untouched for now, as it will be replaced by a `struct odb_source` pointer in a later patch.

This patch is a prerequisite for the series’ goal of enabling multi-source object resolution and pluggable ODB backends. The opt-in design aligns with the broader ODB abstraction effort, where callers should only pay for what they use. The changes are low-risk: the new `sourcep` field defaults to `NULL`, and the patch preserves the existing `whence`-based logic until later patches remove it. The thread context confirms this patch received substantive architectural review in v1 and is now conceptually approved, with only surface-level follow-ups remaining (e.g., the implicit upcast in patch 3/6).

Key symbols introduced: `struct object_info_source`, `oi->sourcep`. Key files modified: `odb.h` (struct definitions), `packfile.c` (guarded population). If you’re tracking the ODB abstraction effort, this patch is a critical intermediate step—it decouples object metadata from provenance data, enabling future backend-specific extensions. The changes are localized to object lookup paths, with no impact on on-disk formats or user-visible behavior.
