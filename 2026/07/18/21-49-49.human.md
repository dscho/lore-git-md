This is the twentieth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`, enabling clients to query object metadata (currently size, with type support planned) from remote repositories without downloading full objects. The series is now in its final polish phase, with all substantive technical and design issues resolved in prior versions, and is queued for `next`.

This revision (v20) makes four targeted changes to address minor nits and build hygiene: (1) **moves the `hash_algo` type fix** (changing `int` to `unsigned int`) to precede the function’s relocation to `connect.c`, ensuring the build remains warning-free; (2) **reverts documentation caveats** about `objectsize:disk` and `deltabase` in `git-cat-file.adoc` to their original form, preserving the `CAVEATS` section; (3) **reformats the `EXPAND_DATA_INIT` macro** to use one line per item for clarity and future expansion; and (4) **adds more context** to the `die()` message in `parse_cmd_remote_object_info()` to improve error reporting. The series remains functionally identical to v19, with no changes to the core protocol, security, or edge-case handling.

The implementation introduces a new `remote-object-info` command in `git cat-file --batch-command`, allowing clients to query object metadata from remotes via the `object-info` protocol v2 capability. Key features include dynamic adaptation to server-advertised capabilities (e.g., silently omitting unsupported placeholders like `%(objecttype)`), strict input validation (10,000-object batch limit, 8KB URL length cap), and robust error handling for missing objects or unsupported protocols. The default format is `%(objectname) %(objectsize)`, with a warning that this may change once type support is added. Tests cover all three smart transports (`git://`, `file://`, `http://`), `--buffer` mode, `-Z` output, and edge cases like malformed OIDs.

The series is authored by Pablo Sabater (7/13 patches), with contributions from Eric Ju (3/13) and Calvin Wan (3/13). Junio Hamano’s prior concerns about robustness (e.g., `%(objectname)`-only requests) and security (bounds-checking) have been addressed, and the GitHub CI run shows no failures. The series is technically complete for its initial scope (size-only queries) and is ready for graduation to `master` after these final cosmetic adjustments.
