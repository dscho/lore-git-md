This is the tenth patch in the twentieth iteration of the security-hardened `git cat-file --batch-command` remote-object-info series, which is now queued for `next`. The patch enables servers to advertise which object-info attributes they support (currently only `size`) when the `transfer.advertiseobjectinfo` configuration is enabled.

The change is small and mechanical: it modifies the `object_info_advertise` function in `serve.c` to append `"size"` to the `value` strbuf if the feature is advertised. This allows clients to dynamically tailor their queries to avoid unsupported attributes, ensuring forward compatibility as the protocol gains new capabilities. The feature remains disabled by default (`advertise_object_info = 0`) and requires explicit opt-in via configuration.

This patch is part of the series' broader effort to implement the `object-info` protocol v2 capability, which lets clients query object metadata (e.g., size) from remotes without downloading full objects. The advertisement mechanism is a key enabler for the client-side dynamic placeholder handling introduced in later patches. The change is uncontroversial and aligns with the series' design goals of robustness and extensibility. No behavioral changes or edge cases are introduced here—this is purely preparatory plumbing.
