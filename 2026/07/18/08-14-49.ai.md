This is the v3 iteration of a performance-minded refactoring patch in the `wt-status` subsystem, targeting a theoretical quadratic-time inefficiency in `wt_status_collect_untracked()`. The patch replaces repeated `string_list_insert()` calls with a single `string_list_append()` pass followed by one `string_list_sort_u()` operation per list (`s->untracked` and `s->ignored`). This change preserves the existing sorted, duplicate-free output while making the collection strategy more explicit and maintainable.

The patch is now fully aligned with prior feedback from Patrick Steinhardt and Jeff King. The commit message has been refined to clarify that the quadratic-time behavior is likely theoretical (due to pre-sorted input from `fill_directory()`) and to emphasize code clarity over performance gains. The implementation uses `string_list_sort_u()` as suggested by Patrick, and the base commit is updated to `41365c2a9ba`.

Key technical details remain unchanged: the patch touches only `wt-status.c`, modifies `wt_status_collect_untracked()`, and relies on existing `string_list` helpers. The unresolved question about whether `dir.entries` and `dir.ignored` can contain duplicates is no longer central to the patch’s justification, though it may still surface in discussion. The patch is small (6 insertions, 2 deletions) and appears ready for integration, with no new tests or benchmarks added as the performance impact was deemed negligible.
