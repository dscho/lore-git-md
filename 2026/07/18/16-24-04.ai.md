This is a substantive review comment on the first patch of the `--auto-reset` series. Johannes Sixt (Hannes) raises a platform-compatibility concern about the refactoring in `print_fd_to_stdout()`: the commit message claims the change avoids needing the file to be "reachable by name," which implies the file might be deleted while still open. On Windows, deleting an open file is normally impossible, so this scenario should not occur in Git's codebase. Hannes asks whether the Windows port has progressed to the point where deleting open files is now possible, or if the commit message is overstating the risk. The question is technical and specific, targeting the rationale for the refactoring rather than its implementation. No alternative approach is suggested, but the concern could prompt the author to clarify the motivation or adjust the commit message to avoid implying a cross-platform issue where none exists.
