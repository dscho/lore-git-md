This is a **bugfix follow-up** in the sequencer series, specifically addressing the regression Uwe Kleine-König reported: the fix for dropped-commit notes works in non-interactive rebase but fails in interactive mode (`-i`). Phillip Wood clarifies the root cause and scope of the issue.

The problem stems from Git’s inconsistent handling of empty commits. By default, `git rebase -i` uses `--empty=ask`, which prompts the user to decide whether to keep or drop empty commits. Phillip’s series only prevents notes from being copied for commits dropped by `--empty=drop` (the default for non-interactive rebase). When Uwe manually skipped empty commits during an interactive rebase (`git rebase --skip`), the sequencer still recorded those commits as "rewritten," causing their notes to be incorrectly copied to the next commit.

Phillip acknowledges the gap: the series does not yet handle user-initiated drops (e.g., via `git rebase --skip` or `git rebase --continue` without committing). He also notes a historical quirk—`--empty=ask` drops commits on `--continue` but keeps them on `--skip`—which complicates the fix. The commit message in the original series (patch 9/9) already documented this limitation for the "edit" command, but the issue extends to interactive rebase more broadly.

**Key details for follow-up discussion:**
- **Files/subsystems:** `sequencer.c` (core logic), interactive rebase backend.
- **Behavior change needed:** Extend the `PICK_RESULT_DROPPED` logic to cover user-initiated drops (e.g., `--skip`).
- **Test gap:** The interactive rebase backend (`t3404-rebase-interactive.sh`) lacks coverage for this edge case.
- **Design question:** Should `--empty=ask` be revised to keep empty commits on `--continue` and drop them on `--skip`? Phillip expresses a preference for this, but it would be a breaking change.

This is a **high-priority regression** for the series, but the fix is likely localized to how `record_in_rewritten()` is called in interactive rebase. No patches have been proposed yet; Phillip is still designing the solution. The thread remains open pending further updates.
