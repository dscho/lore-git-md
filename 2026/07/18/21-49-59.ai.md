This is the tenth patch in the GSoC v20 series implementing `git cat-file --batch-command` remote object metadata queries. The patch enables servers to advertise the `object-info` protocol v2 capability when `transfer.advertiseobjectinfo` is enabled, allowing clients to dynamically determine which metadata attributes (currently only `size`) are supported.

The change is minimal and mechanical: it modifies the `object_info_advertise` function in `serve.c` to append `"size"` to the `value` strbuf when the feature is advertised, while preserving the existing configuration logic (`advertise_object_info = 0` by default). The patch is authored by Calvin Wan but carries Signed-off-by trailers from Eric Ju and Pablo Sabater, reflecting their involvement in the series.

This patch directly supports the series' goal of dynamic client-server negotiation: clients can now inspect the server's advertised capabilities and tailor their `remote-object-info` queries to avoid unsupported attributes, ensuring forward compatibility as the protocol expands. The implementation is conservative, advertising only `size` (with `type` support designed but not yet exposed), and maintains the existing opt-in configuration requirement.

No behavioral changes or edge cases are introduced; the patch is purely preparatory for the client-side logic in later patches. The commit message clearly states the motivation (client awareness of server capabilities) and the current limitation (size-only support). This is a well-scoped, uncontroversial step in the larger series.
