This is a small but essential build fix for the ongoing `git cat-file --batch-command` remote-object-info series, now at v20 and queued for `next`. The patch corrects a signed/unsigned type mismatch in `write_fetch_command_and_capabilities()` by changing the `hash_algo` variable from `int` to `const unsigned int` to match the return type of `hash_algo_by_name()`. The mismatch is currently masked by a `DISABLE_SIGN_COMPARE_WARNINGS` pragma in `fetch-pack.c`, but the function is slated to move to `connect.c` in a later patch (5/13 in the series), where the warning would break the build.

The change is purely mechanical and has no behavioral impact. It is a prerequisite for the function relocation and must be incorporated before the series graduates to `master`. The patch is uncontroversial and aligns with the series' broader focus on memory safety and type consistency. Junio has already confirmed the series is technically complete, and this fix resolves the last build obstacle.
