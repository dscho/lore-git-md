This thread is about a small but user-visible improvement to Git's branch deletion error messages. René Scharfe's patch makes `git branch -d` more informative when it refuses to delete a branch that's currently checked out—not just in a regular worktree, but also during operations like `git bisect` or `git rebase`. Instead of a generic "used by worktree" message, the error now specifies the context (e.g., "for bisect" or "for rebase"), helping users understand why the branch is locked.

The change is straightforward: it adds a `strintmap` to track the checkout reason in `branch.c` and `branch.h`, updates the error messages in `builtin/branch.c`, and adds tests in `t/t3200-branch.sh`. The patch addresses a specific usability issue raised by stsp and has no known objections or open questions. It’s a self-contained fix with no dependencies or follow-ups expected.
