This thread began with René Scharfe’s patch to improve the error message when trying to delete the currently checked-out branch, replacing a generic "used by worktree at..." with specific reasons like "for bisect" or "for rebase". Junio expanded the scope, seeing this as a step toward a unified API for branch-safety checks across Git commands, and suggested refinements to error messages and test coverage.

The discussion has now settled on using an `enum` for internal debuggability, but the design of the `UPDATE_REF` error message—used during rebase with merges—remains contested. René favors merging it into the simpler "rebase" category, while Junio prefers a more descriptive message. Phillip Wood’s recent review adds a usability angle: if the error says the branch is "being rebased" but `git status` shows a different branch, users may be confused. He suggests either enhancing `git status` to show all rewritten branches or crafting a distinct message for `UPDATE_REF` that clarifies multiple branches are involved (e.g., "because it is being updated by a rebase running in '../feature' which is updating multiple branches"). Phillip also endorses Junio’s earlier tweak to the "checkout" message ("checked out" instead of "used by worktree").

The patch is still under review, with test coverage for `WORKTREE` and `UPDATE_REF` cases still missing. No consensus has emerged on the `UPDATE_REF` message, but the thread has broadened to include usability considerations alongside technical design. Follow-up work to unify branch-safety checks across commands (e.g., `git history`) remains a possibility but hasn’t materialized yet.
