This thread is about improving the error message when you try to delete the branch you’re currently on with `git branch -d`. Right now, Git just says the branch is “used by worktree at...”, which doesn’t tell you whether you’re in the middle of a `bisect`, a `rebase`, or just a regular checkout. René Scharfe’s patch makes the message specific: if you’re bisecting, it now says “for bisect”.

Junio reviewed the first version and suggested a bigger cleanup—using an enum instead of an integer for the checkout reason, adding tests for every possible scenario, and eventually building a common API so commands like `git history` don’t miss the same safety check. René’s v2 patch takes the first step: it adopts the enum and focuses only on bisect, leaving rebase and other cases for later. The tests now cover bisect, but the worktree and rebase-with-merges cases are still untested, and the wording of the error messages is still under discussion. Phillip Wood pointed out that users might be confused if `git status` shows a different branch than the error message, so there’s a small usability question left to settle.

The patch itself is ready for the bisect case, but the thread has grown into a blueprint for a more consistent branch-safety layer across Git. No follow-up patches have landed yet, but the new internal tracking array René added could be the foundation for that broader effort.
