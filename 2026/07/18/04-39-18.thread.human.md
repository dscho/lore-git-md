This thread began with René Scharfe’s patch to improve the error message when trying to delete the currently checked-out branch with `git branch -d`. The original message was generic ("used by worktree at ..."), leaving users unsure whether the branch was locked by a regular worktree, a `git bisect`, `git rebase`, or another operation. René’s patch replaces it with specific messages naming the actual reason (e.g., "for bisect" or "for rebase").

Junio’s feedback expands the scope slightly, seeing this as a stepping stone toward a consistent API for checking branch usage across all commands that repoint branch tips—like `git history`, which recently missed this safety check. The discussion now focuses on refining the error messages, particularly for the `BRANCH_CHECKOUT_KIND_UPDATE_REF` case (used during rebase with merges), where Junio suggests making the wording more explicit. The test suite currently covers only two of the four defined checkout kinds, so ensuring full coverage is the next step.

The patch itself remains small and self-contained, addressing a clear usability issue raised by stsp. While the immediate goal is polishing the error messages, Junio’s comments hint at broader potential: unifying branch-safety checks across Git commands. For now, the patch is under review, with no major objections or open questions—just a request for clearer messaging and better test coverage.
