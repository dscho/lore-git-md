This thread is about improving the error message when users try to delete the branch they currently have checked out. René Scharfe’s patch replaces the generic "used by worktree at ..." message with a specific one that names the actual reason—like "for bisect" or "for rebase"—making it clearer why the operation is blocked. Junio’s feedback expanded the scope, suggesting this could be the start of a broader effort to standardize branch-safety checks across Git commands, like the recently introduced `git history`, which missed this check.

The patch is still under review, with two key questions unresolved: how to word the error message for the `BRANCH_CHECKOUT_KIND_UPDATE_REF` case (used during rebase with merges), and whether to simplify the logic by treating it as just "for rebase." Tests currently cover only two of the four checkout kinds, leaving `worktree` and `update-ref` untested—a gap Junio wants addressed. René is open to refining the implementation but is cautious about overcomplicating the messages.

The changes are confined to `branch.c`, `branch.h`, `builtin/branch.c`, and the test file `t/t3200-branch.sh`, introducing an internal `strintmap` to map checkout reasons to descriptive strings. No new symbols are exposed, and the on-disk format is unchanged. While the patch itself is a straightforward usability fix, Junio’s vision for a unified API could lead to follow-up work, making this a foundational change for future improvements. For now, the focus is on finalizing the error messages and test coverage before the patch can be merged.
