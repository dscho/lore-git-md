This thread is about improving the error message when trying to delete a branch that’s currently in use by `git bisect`. René Scharfe’s v2 patch narrows the fix to just the bisect case, replacing the generic "used by worktree" message with a clearer "for bisect" one. The patch is now cooking in Junio’s `next` branch, meaning it’s under integration testing for the next release.

The discussion has revealed broader design questions. Junio and Phillip Wood both prefer more descriptive messages—for example, changing "used by worktree at '%s'" to "checked out at '%s'"—and Junio wants to extend this clarity to other cases, like rebases with merges. Phillip also raised a usability concern: if `git status` shows a different branch than the error message, users might get confused. He suggested either improving `git status` to show all branches being rewritten or crafting a more detailed error message for the rebase case. These issues remain open, and test coverage for the remaining checkout kinds (worktree and rebase) is still missing.

René’s patch is seen as a foundation for a future unified API to check branch safety across Git commands, a goal Junio and Toon Claes both support. For now, though, the focus stays on the bisect case, with follow-up work expected to address the rest.
