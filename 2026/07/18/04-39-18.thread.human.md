This thread is about improving the error message when users try to delete their current branch with `git branch -d`. The current message is vague ("used by worktree at ..."), and René Scharfe’s patch makes it specific—telling users whether the branch is in use by a regular worktree, `git bisect`, `git rebase`, or other operations. Junio Hamano reviewed the patch and expanded its scope, suggesting this could be the start of a broader, consistent API for branch-safety checks across Git commands, especially after `git history` recently missed this check.

The patch is still under review, with no prior versions. The latest discussion between Junio and René has focused on two technical details: whether to use `int` or `enum` for the checkout kind variable (now resolved in favor of `enum` for better debuggability), and whether to simplify error messages by merging the `BRANCH_CHECKOUT_KIND_UPDATE_REF` case (used during rebase with merges) into the "rebase" category. René prefers simplicity, while Junio leans toward more descriptive messages like "for rebase with merges". Test coverage is also incomplete—only two of the four checkout kinds are currently tested.

The patch touches `branch.c`, `branch.h`, `builtin/branch.c`, and `t/t3200-branch.sh`, but doesn’t change any on-disk formats or user-facing symbols. The unresolved questions are whether to keep the `UPDATE_REF` message distinct, how to fully test all checkout kinds, and whether this work will lead to a unified branch-safety API. René is the author, and Junio is the primary reviewer, with no other participants weighing in yet.
