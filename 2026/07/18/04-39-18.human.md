This is a small but user-facing improvement to the `git branch` command. René Scharfe’s patch makes Git’s error message more informative when you try to delete a branch that is currently checked out—not just in a regular worktree, but also during internal operations like `git bisect` or `git rebase`.

The change is straightforward: instead of a generic “used by worktree at /path” message, Git now tells you *why* the branch is checked out (“for rebase”, “for bisect”, or “for update-ref”). The implementation adds a new `strintmap` to track the checkout reason alongside the existing worktree path map, and the error message in `builtin/branch.c` is updated to include that context.

The patch is well-motivated (the original suggestion came from stsp), the commit message is clear, and the code is clean. It touches only the branch-checkout tracking machinery and the error-reporting path, so the risk of regressions is low. The test updates are minimal but sufficient to verify the new wording. This looks like a solid, uncontroversial usability fix that should be easy to merge.
