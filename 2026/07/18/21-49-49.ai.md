This is the twentieth iteration of the `git cat-file --batch-command` remote-object-info series, now **technically complete** and **queued for `next`**. The series enables Git clients to query object metadata (currently size, with type support designed for future expansion) from remote repositories without downloading full objects, using the `object-info` protocol v2 capability.

This revision (v20) makes four targeted changes since v19: (1) **moves the `hash_algo` type fix** (changing `int` to `unsigned int`) to patch 5/13, ensuring it precedes the relocation of `write_fetch_command_and_capabilities()` to `connect.c` and resolves the signed/unsigned comparison warning that would otherwise break the build; (2) **reverts documentation caveats** for `objectsize:disk` and `deltabase` atoms in `git-cat-file.adoc`, restoring the `CAVEATS` section references that were removed in v19; (3) **reformats the `EXPAND_DATA_INIT` macro** to use one line per item for clarity and future expansion; and (4) **adds more context to the `die()` message** in `parse_cmd_remote_object_info()` when command-line parsing fails, improving error reporting.

The series remains structurally unchanged: 13 patches authored by Pablo Sabater (7), Eric Ju (3), and Calvin Wan (3). Key components include the `remote-object-info` command in `git cat-file --batch-command` (patch 12/13), dynamic adaptation to server-advertised capabilities via the `remote_allowed_atoms` string list (patch 13/13), and robust input validation (10,000-object batch limit, 8KB URL length cap, strict OID format checks). The implementation handles edge cases like missing objects, unsupported protocols, and malformed responses, and includes 747 lines of new tests in `t/t1017-cat-file-remote-object-info.sh` covering all three smart transports (`git://`, `file://`, `http://`), `--buffer` mode, and `-Z` output.

The build fix for `hash_algo` (patch 5/13) is mechanical and must be incorporated before the series graduates to `master`. The remaining changes are cosmetic (documentation, macro formatting, error messages) and do not affect functionality. Junio’s prior confirmation that no unresolved design or implementation concerns remain still holds, and the series is cleared for integration.
