This is a substantive review from Jeff King (Peff) on the first patch in Toon Claes’s four-patch series optimizing `git last-modified` by reusing Bloom filters. Peff acknowledges the refactoring’s intent—moving the `bloom_keyvecs_nr` precondition check into `check_maybe_different_in_bloom_filter`—but raises a design concern about the function’s return semantics. The function currently returns a tristate (`0`, `1`, or `-1`), where `-1` signals an uncheckable filter (e.g., no key vectors or missing commit-graph data). While the existing code correctly treats `-1` and `1` identically (both indicate "maybe changed"), Peff argues this is subtle and error-prone, especially as the function is about to become public in `revision.h`. He suggests simplifying the interface to a boolean (`false` = definitely unchanged, `true` = possibly changed) to make the contract clearer. The review is narrowly scoped to this patch but has implications for the series’ later patches, which expose the new helper function. No other technical issues are raised.
