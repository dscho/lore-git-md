This is the core implementation patch (12/13) of the `git cat-file --batch-command` remote-object-info series, now at v20 and queued for `next`. The patch adds the `remote-object-info` command to `git cat-file --batch-command`, enabling clients to query object metadata (currently size only) from remote repositories without downloading the objects themselves. This is the centerpiece of the series, integrating the protocol-level `object-info` capability (introduced in earlier patches) with the user-facing command-line interface.

The implementation follows a distinct execution model to minimize remote communication overhead: unlike other `--batch-command` commands, which process objects one at a time, `remote-object-info` batches multiple object IDs into a single request to the server. The command accepts a remote URL followed by one or more full object IDs (40-character SHA-1/256), validates them strictly (rejecting short OIDs or malformed input), and enforces hard limits (8KB URL length, 10,000 objects per request). Input parsing and memory management are robust, using `xcalloc` for allocations, bounds-checking, and a new `free_object_info_contents()` helper (added in this series) to prevent leaks.

Security and edge-case handling are thorough. The command dynamically validates format placeholders against the server's advertised capabilities, silently omitting unsupported atoms (e.g., `%(objecttype)`) to match `for-each-ref` behavior. This prevents crashes when the server only supports a subset of metadata (currently `size` only). The patch also initializes `expand_data->type` to `OBJ_BAD` and handles `type_name()` returning `NULL`, adding defense-in-depth against uninitialized memory access. For `%(objectname)`-only requests, the client queries the server for the object's size (discarding the result) to validate the object's existence, per Junio's insistence on correctness over efficiency.

The test coverage is extensive: 719 lines of new tests in `t/t1017-cat-file-remote-object-info.sh` verify all three smart transports (`git://`, `file://`, `http://`), `--buffer` mode, `-Z` (null-delimited) output, and edge cases like malformed OIDs, legacy protocols, and unsupported placeholders. The tests confirm that objects are not downloaded from the remote (validating the core efficiency claim) and that the command integrates cleanly with existing `--batch-command` functionality.

The patch is technically complete for its initial scope (size-only queries) and addresses all prior review feedback, including the dynamic allow-list for placeholders, memory safety fixes, and robustness improvements. The only remaining unresolved nits are cosmetic (translation context, alphabetical ordering in code and build files), which do not affect functionality.
