This is the second patch in the v7 series refactoring `trust_executable_bit` and `has_symlinks` as part of the ongoing `the_repository` removal effort. The patch updates the performance-critical `ce_mode_from_stat()` helper to accept a `struct repository *` parameter, preparing it for repository-scoped configuration access. However, the new parameter is not yet used in this patch, which SZEDER Gábor points out causes compilation errors under `DEVELOPER=1` due to the unused parameter warning being treated as an error.

The issue is straightforward: the patch adds the `repo` parameter to the function signature but does not yet use it, which violates Git’s coding guidelines when warnings are treated as errors. SZEDER suggests marking the parameter as `UNUSED` in this patch and removing the annotation in the next patch (3/4), where the parameter will actually be used. This is a minor but necessary fix to ensure the series builds cleanly at every step.

The rest of the patch remains uncontroversial. It preserves `ce_mode_from_stat()` as a `static inline` function in `read-cache.h` (addressing Junio’s earlier design concern) and reorders the boolean expressions to optimize for the common case where global variable accesses will be replaced with getter functions. The added comment clarifying the function’s role in handling filesystem limitations is also a positive addition.

This is a small, mechanical refactoring with no behavioral changes, but it is a critical plumbing step for the broader series. The fix SZEDER proposes is low-risk and aligns with Git’s incremental development practices. The series as a whole is otherwise ready for inclusion, with all prior feedback addressed. This issue does not challenge the design or correctness of the patch—just its build hygiene.
