This is the fourth patch in the GSoC v20 series implementing `git cat-file --batch-command` remote object metadata queries. It prepares for moving `write_fetch_command_and_capabilities()` to `connect.c` by eliminating the static `advertise_sid` variable in `fetch-pack.c`.

The patch replaces the global `advertise_sid` (set in `fetch_pack_config()` via `transfer.advertisesid`) with local initializations in both `find_common()` and `write_fetch_command_and_capabilities()`. The `do_fetch_pack()` check for `session-id` support is folded into the condition in `find_common()` to match the v2 protocol's inline check pattern. The default value (0) matches the original static initialization, so behavior is unchanged.

This is a mechanical refactoring with no functional impact. The change is necessary because the static variable would not be accessible after the function moves to `connect.c` in patch 5/13. Karthik Nayak's earlier review confirmed the commit message accurately describes the protocol scope and variable usage. The patch is well-motivated and uncontroversial.
