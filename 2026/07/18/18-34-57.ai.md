This is a **build fix** for the `remote-object-info` series (v19, patch 5/13). SZEDER Gábor reports a signed/unsigned comparison warning that breaks the build when `write_fetch_command_and_capabilities()` is moved from `fetch-pack.c` (which suppresses sign-compare warnings) to `connect.c` (which does not). The issue arises because `hash_algo_by_ptr()` returns an `unsigned int`, while the local `hash_algo` variable is declared as `int`.

The fix is straightforward: change `hash_algo` to `unsigned int` in the function. SZEDER suggests doing this as a preparatory step *before* the move to `connect.c` to avoid the build failure. The patch is a mechanical type adjustment with no behavior change, but it is critical for the series to compile cleanly. Given the series is already queued for `next`, this fix should be incorporated before the topic graduates to `master`.
