This is the core patch in the twentieth iteration of the `git cat-file --batch-command` remote-object-info series, now queued for `next`. It adds the `remote-object-info` command to `` `git cat-file --batch-command` ``, allowing users to query object metadata (currently size only) from a remote repository without downloading the full objects.

The implementation batches multiple object IDs into a single request to minimize round trips, enforcing strict limits (10,000 objects, 8KB URL length) and validating input format (full OIDs only, no short hashes). The command dynamically adapts to the server’s advertised capabilities, silently omitting unsupported placeholders like `%(objecttype)` to match `for-each-ref` behavior. Memory safety is enforced via `xcalloc` allocations, bounds-checking, and a new `free_object_info_contents()` helper to prevent leaks. The patch includes 719 lines of new tests covering all three smart transports (`git://`, `file://`, `http://`), `--buffer` mode, `-Z` output, and edge cases like malformed OIDs or legacy protocols.

The command integrates with the `object-info` protocol v2 capability, which servers advertise when `transfer.advertiseobjectinfo` is enabled. The implementation is robust: it handles missing objects gracefully, rejects unsupported protocols, and ensures bare OID requests trigger an unconditional existence check on the server. The default output format (`%(objectname) %(objectsize)`) omits `%(objecttype)` until type support is added, with a warning in the documentation that the format may change in the future.

This patch is the centerpiece of the series, tying together the protocol extensions, transport layer changes, and client-side logic introduced in earlier patches. The test coverage is thorough, and the implementation addresses all prior feedback, including dynamic placeholder handling and memory safety.
