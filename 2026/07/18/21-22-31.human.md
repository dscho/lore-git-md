Taylor agrees with Peff’s assessment that removing uncovered ancestor trees (like `d/` when the pathspec is `d/a`) is a reasonable trade-off for an experimental command, as it preserves the performance benefit while avoiding misleading results. He provides a **tested patch** implementing this approach, which modifies `add_path_from_diff()` to skip paths that don’t match the pathspec. The patch is straightforward and aligns with the likely intent of most callers, who care about files rather than trees.

For completeness, Taylor also explores an alternative design that retains uncovered paths in the output while still using Bloom filters for optimization. This approach tracks uncovered paths separately and checks them individually against the Bloom filter, reducing the number of lookups compared to the original code. While this preserves output fidelity, it offers diminishing returns as the number of uncovered paths grows, and Taylor’s benchmarks show it is slower than simply omitting uncovered paths (227 ms vs. 190 ms in a synthetic test). He ultimately recommends the simpler solution of omitting uncovered paths, leveraging the command’s experimental status.
