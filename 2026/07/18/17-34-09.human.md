This is a user-facing error message improvement for the branch subsystem. Junio C Hamano reviews René Scharfe’s patch that makes `git branch -d` report *why* a branch cannot be deleted—whether it is checked out in a regular worktree, or locked by an internal operation like `git bisect` or `git rebase`. The patch is small, well-motivated, and already has test coverage for the two most common cases (`bisect` and regular checkout).

Junio’s feedback is substantive but constructive. He notes that the new `branch_checkout_kind()` API could serve as the foundation for a broader safety check that all branch-modifying commands should use, plugging a gap recently exposed by `git history`. On the patch itself, he asks for two clarifications: (1) why the `kind` variable is declared as `int` instead of the enum type, and (2) whether the generic “used by worktree” message is still needed as a catch-all. He also suggests more user-friendly wording for the `BRANCH_CHECKOUT_KIND_UPDATE_REF` case, which currently reads “for update-ref” and is not self-explanatory.

The patch is not yet merged; it is under active review and likely to evolve slightly in response to Junio’s comments. If you care about branch safety or clearer error messages, this is a low-risk, high-value change worth following.
