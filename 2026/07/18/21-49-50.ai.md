This is a bugfix patch from the GSoC `git cat-file --batch-command` remote-object-info series, now at v20. It plugs a memory leak in `transport-helper.c` that occurs when a transport is disconnected before its helper process is fully started. The leak was introduced in an earlier version of the series and fixed in v19; this patch carries the fix forward unchanged into v20.

The issue is straightforward: `disconnect_helper()` frees `data->name` only inside the `if (data->helper)` block, but `data->name` is allocated unconditionally in `transport_helper_init()`. If the transport is disconnected before the helper is started, `data->name` is never freed. The fix moves `FREE_AND_NULL(data->name)` outside the conditional block so it runs on every disconnect.

This is a targeted, mechanical change with no behavior impact beyond fixing the leak. It is a prerequisite for the series' graduation to `master` and has already been reviewed and accepted in earlier iterations. The patch is uncontroversial and ready to merge.
