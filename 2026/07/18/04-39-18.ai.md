This is a user-facing error message improvement for the branch subsystem. René Scharfe’s patch makes `git branch -d` more helpful when it refuses to delete a branch that is currently checked out—not just in a regular worktree, but also during internal operations like `git bisect` or `git rebase`. Instead of a generic "used by worktree at ..." message, the error now specifies the kind of checkout (e.g., "for bisect" or "for rebase"), so users immediately see why the branch is locked. The change touches `branch.c`, `branch.h`, `builtin/branch.c`, and the test suite (`t/t3200-branch.sh`), adding a new `strintmap` to track the checkout reason and updating the error messages accordingly. The patch is small, self-contained, and motivated by a concrete usability pain point raised by stsp.
