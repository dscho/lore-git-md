This is a bugfix patch from the GSoC `git cat-file --batch-command` remote-object-info series, now at v20. It plugs a memory leak in `transport-helper.c` that occurs when a transport is disconnected before its helper process is fully started. The leak was introduced in an earlier version of the series and only affects the in-flight topic, not any released version of Git.

The fix is minimal and mechanical: the `FREE_AND_NULL(data->name)` call is moved outside the `if(data->helper)` block so that the `data->name` string allocated in `transport_helper_init()` is always freed on disconnect, regardless of whether the helper process was started. The change is a single line, and the commit message clearly explains the scenario (disconnecting a transport that never fully initialized its helper) and cites the relevant prior discussion.

This patch is the first in the 13-patch series and is a prerequisite for the rest; it was already incorporated in v19 and remains unchanged in v20. The leak was caught during review and does not affect the core functionality of the series, but it is a correctness fix that should be included before the topic graduates to `master`. The patch is uncontroversial and ready to merge.
