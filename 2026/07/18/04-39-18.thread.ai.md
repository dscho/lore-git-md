Subject: [PATCH] branch: clarify error message when deleting the current branch
Series version: standalone patch (potential follow-up work anticipated)
Originating author: René Scharfe
Thread type: user-facing error message improvement with emerging design implications for a broader branch-safety API

Core problem or goal
The error message from `git branch -d` when attempting to delete the currently checked-out branch is generic ("used by worktree at ..."), obscuring the actual reason (regular worktree, `git bisect`, `git rebase`, or other internal operations). The patch replaces the generic message with a specific one that names the reason (e.g., "for bisect" or "for rebase"). Junio’s feedback expands the scope, framing this as a foundation for a broader, consistent API to check branch usage across all commands that repoint branch tips (e.g., `git history`, which recently missed this safety check).

Current status
Under review; no prior versions. Junio’s feedback suggests refining error messages and test coverage, with potential follow-up work to unify branch-safety checks across Git commands. The latest email from René proposes simplifying the error message logic by merging the `BRANCH_CHECKOUT_KIND_UPDATE_REF` case into the "rebase" category for clarity, pending Junio’s agreement.

Key technical details
- Files touched: `branch.c`, `branch.h`, `builtin/branch.c`, `t/t3200-branch.sh`
- New data structure: a `strintmap` in `branch.c` mapping checkout reasons (`BRANCH_CHECKOUT_KIND_*`) to descriptive strings
- New symbols: none (internal-only change)
- On-disk format: unchanged
- Test coverage: extended in `t/t3200-branch.sh` to verify error messages during `bisect` and `rebase`; Junio notes coverage is incomplete (only 2 of 4 checkout kinds tested). The remaining untested kinds are `BRANCH_CHECKOUT_KIND_WORKTREE` and `BRANCH_CHECKOUT_KIND_UPDATE_REF`.
- Error message refinement: Junio requested clearer wording for `BRANCH_CHECKOUT_KIND_UPDATE_REF` (used during rebase with merges). René now proposes merging this case into the "rebase" category to simplify the user-facing message.

Open questions and loose ends

2. **Test coverage**: Need to extend tests to cover the remaining checkout kinds (`BRANCH_CHECKOUT_KIND_WORKTREE` and `BRANCH_CHECKOUT_KIND_UPDATE_REF`).
3. **Broader API design**: Junio’s feedback hints at unifying branch-safety checks across commands (e.g., `git history`). This may require follow-up patches to standardize the API and error messages. No concrete patches yet, but this thread could seed the effort.
