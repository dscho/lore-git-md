This is a build-fix review in the `remote-object-info` series (v19, patch 5/13). SZEDER Gábor identifies a signedness mismatch in the moved `write_fetch_command_and_capabilities()` function: `hash_algo_by_ptr()` returns an unsigned integer, but the local `hash_algo` variable is signed, triggering a compiler warning (treated as an error) when the function is relocated from `fetch-pack.c` (which suppresses sign-compare warnings) to `connect.c` (which does not).

The issue is straightforward and the fix is mechanical: change `hash_algo` from `int` to `unsigned int` while the function still resides in `fetch-pack.c`, avoiding a build break in the next patch. This is a surface-level correction that does not alter behavior, but it is necessary for the series to compile cleanly. The review is substantive only in that it catches a latent build issue; the underlying logic of the function remains unchanged. The series as a whole remains technically complete and queued for `next`.
