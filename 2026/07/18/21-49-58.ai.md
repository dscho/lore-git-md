This is patch 9/13 in the twentieth iteration of the `git cat-file --batch-command` remote-object-info series, now queued for `next`. The patch ensures that bare object ID requests (without any attributes) trigger an unconditional existence check on the server, closing a gap where such requests could silently succeed without validating the object.

The change introduces a new `get_object_info()` wrapper around `odb_read_object_info_extended()` that sets `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK` flags to prevent partial-clone servers from fetching missing objects or rescanning packs unnecessarily. The wrapper returns `OBJ_BAD` for unknown objects, and the patch tightens the existence check from `< 0` to `<= OBJ_NONE` to catch both `OBJ_BAD` and `OBJ_NONE` as unrecognized cases. This ensures bare OID requests for valid objects return just the OID, while unrecognized OIDs (including those with `size` requested) append a space, matching the documented behavior in `gitprotocol-v2.adoc`.

The patch also updates the protocol documentation to explicitly require full OIDs, clarify the optional nature of `obj-size`, and describe the response format for unrecognized OIDs. Three new tests in `t/t5701-git-serve.sh` verify the behavior: bare OID requests for valid objects, bare OID requests for unrecognized objects, and size requests for unrecognized objects. The implementation is robust and aligns with Junio’s insistence on prioritizing correctness over efficiency for existence checks.
