This is a review comment on the first patch in Toon Claes’s four-patch series optimizing `git last-modified` by reusing Bloom filters. Jeff King (Peff) raises a subtle but important interface design question about the `check_maybe_different_in_bloom_filter` function, which this patch refactors. The function currently returns a tristate (`0`, `1`, or `-1`), but only the distinction between "definitely not in the filter" (`0`) and "possibly in the filter" (`1` or `-1`) is meaningful to callers. Peff suggests simplifying the return type to a boolean (`false` for "definitely not", `true` for "possibly") to make the interface more intuitive and less error-prone, especially as the function is about to be exposed publicly in a later patch. His comment is substantive, focusing on API clarity and long-term maintainability, and is worth addressing before the series graduates. The patch itself is otherwise uncontroversial and well-motivated.
