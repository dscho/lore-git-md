This is the core client-side implementation patch for the `object-info` protocol capability in the `git cat-file --batch-command` remote-object-info series (patch 11/13 of v20). The patch introduces the `fetch_object_info()` function and integrates it into Git’s transport layer, enabling clients to query object metadata (currently only size) from remote repositories without downloading full objects.

The implementation adds a new `fetch-object-info.c` file with 138 lines of code, defining the `fetch_object_info()` function that sends an `object-info` command to a v2 server, parses the response, and populates an `object_info` struct array with the results. Key technical details include:
- **Protocol handling**: The function validates server support for `object-info`, sends a request with OIDs and requested attributes (currently only `size`), and processes the response line-by-line. Each response line must start with the requested OID, followed by attribute values in the order specified in the request.
- **Edge case handling**: The implementation detects unrecognized objects (marked via a new `unrecognized` field in `struct object_info`) and validates response format, including strict checks for OID matches and attribute count. Unrecognized objects are flagged by an empty string in the response, while malformed responses trigger fatal errors.
- **Transport integration**: The patch extends the transport vtable with a new `fetch_object_info` entry, implemented for both smart transports (`fetch_object_info_via_pack`) and transport helpers (`fetch_object_info_helper`). The smart transport implementation reuses the existing connection setup logic from `fetch_refs_via_pack` but skips object negotiation, focusing solely on metadata retrieval.
- **Memory safety**: Allocations for size pointers in `object_info_data` use `xcalloc`, and the response parsing cleans up temporary string lists with `string_list_clear`. The new `unrecognized` field in `struct object_info` is a single bit, minimizing memory overhead.

The patch is mechanical and focused, with no behavior changes outside the new functionality. It depends on earlier patches in the series (e.g., the `write_command_and_capabilities` generalization in patch 7/13) and prepares for the `git cat-file --batch-command` integration in patch 12/13. The implementation is designed for extensibility: the `object_info_options` string list and `object_info` struct can accommodate future attributes (e.g., `type`) without breaking changes. Tests for this functionality are introduced in patch 13/13 (`t/t1017-cat-file-remote-object-info.sh`).
