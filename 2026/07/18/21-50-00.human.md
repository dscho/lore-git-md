This is the core transport-layer patch in the long-running `git cat-file --batch-command` remote-object-info series, now at v20 and queued for `next`. Patch 11/13 adds the client-side plumbing that lets Git query object metadata (currently just size) from a remote repository without downloading the full object.

The patch introduces a new `fetch_object_info()` function that speaks the `object-info` protocol v2 capability. It sends a request listing the desired OIDs and the `size` attribute, parses the server’s response, and populates an array of `struct object_info` with the results. A new `unrecognized` flag in `struct object_info` marks OIDs the server doesn’t know about. The transport layer is extended with a `fetch_object_info` vtable entry, implemented for both smart transports (`fetch_object_info_via_pack`) and transport helpers (`fetch_object_info_helper`). Input is buffered in memory (not streamed), and the implementation is strict about protocol version (v2 only) and server capabilities.

The patch is cleanly structured: `fetch-object-info.c` contains the request/response logic, `fetch-object-info.h` the public interface, and the transport layer changes hook everything together. The code is well-tested (747 lines of new tests in the series) and handles edge cases like malformed responses, missing objects, and unsupported protocols. It’s the linchpin that enables the user-facing `remote-object-info` command in patch 12/13. No unresolved technical concerns remain, and the series is cleared for integration.
