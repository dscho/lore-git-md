This is a refactoring patch targeting the UTF-8 string width calculation functions in Git.

The patch changes the return type of `utf8_strwidth()` and `utf8_strnwidth()` from `int` to `size_t`, addressing a long-standing `//TODO` comment in the code. The functions calculate the display width of UTF-8 strings, which can never be negative, so `size_t` is a more appropriate type than `int`. The change removes an unnecessary cast (`cast_size_t_to_int`) and simplifies the return logic.

The patch touches only `utf8.c` and `utf8.h`, with no behavior changes—just type modernization. The commit message is minimal but sufficient for this kind of mechanical cleanup. There are no tests or documentation updates, which is typical for this type of refactoring.
