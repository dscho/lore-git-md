This thread began as a refactoring effort by Hardik Kumar to change the return type of Git’s UTF-8 string-width functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t`, addressing a type-system mismatch for inherently non-negative display widths. After three iterations (v1–v3), the series was withdrawn following sustained opposition from key reviewers—Junio C Hamano, Pablo Sabater, and Phillip Wood—who concluded the practical benefits were outweighed by risks like regressions, pervasive explicit casts, and incomplete conversions. The debate is now resolved in favor of the status quo, with a documentation patch that replaces the existing TODO comment in `utf8.c` with a clear rationale for the current design.

The documentation patch, just posted by Hardik, implements the consensus: it explains why the functions return `int` (to align with APIs like `printf()` that require signed values for padding calculations) and why the `cast_size_t_to_int()` helper remains necessary to prevent overflows. The patch is minimal and purely explanatory, closing the thread by codifying the reasoning behind the existing design. No further technical changes are planned, and the discussion is effectively concluded. The only remaining action was deciding where to place the documentation—Junio’s directive to embed it directly in `utf8.c` (rather than a separate file) has been followed.
