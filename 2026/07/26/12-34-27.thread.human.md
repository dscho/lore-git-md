This thread is about a refactoring patch by Hardik Kumar that changes the return type of Git’s UTF-8 string-width functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t`, aiming to eliminate a type mismatch where functions computing inherently non-negative display widths return a signed type. The patch is now in its second iteration (v2), which updated all callers to use `size_t` explicitly but introduced multiple regressions—unsigned integer underflow, mixed-sign comparisons, and incomplete conditional compilation updates—across several subsystems (`diff.c`, `pretty.c`, `blame.c`, `gettext.h`, `column.c`, and `wt-status.c`).

Junio C Hamano has expressed strong skepticism about whether the patch is worth pursuing at all, arguing that the practical benefit is minimal (the functions measure display widths of strings that fit on a single line) and that the risk of regressions outweighs the theoretical type-safety improvement. Hardik remains committed to the effort, defending the use of `size_t` as more appropriate for non-negative values, but his latest email does not address Junio’s broader concerns or outline specific fixes for the unresolved regressions. Pablo Sabater’s high-weight review from v2 also remains unaddressed, particularly the removal of an overflow check in the now-deleted `cast_size_t_to_int()` helper, which previously protected against undefined behavior.

The patch is not ready for integration and faces two possible outcomes: a v3 with substantial fixes to address the regressions without reintroducing implicit conversions, or withdrawal if Junio’s skepticism prevails. Key technical sticking points include underflow risks in `diff.c`, mixed-sign comparisons in `pretty.c` and `blame.c`, and incomplete updates in `gettext.h`’s conditional compilation paths. Hardik’s proposed fixes (e.g., casting back to `int` in some callers) are pragmatic but undermine the patch’s original goal of eliminating implicit conversions. The thread’s future hinges on whether Hardik can resolve these issues convincingly or whether the project decides the effort is not worth the cost.
