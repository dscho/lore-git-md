This thread is about a refactoring patch by Hardik Kumar that changes the return type of two UTF-8 string-width calculation functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t` in `utf8.c` and `utf8.h`. The goal is to eliminate a type mismatch where functions computing inherently non-negative display widths return a signed type, addressing a long-standing `//TODO` comment and removing a helper function used for type conversion.

The patch itself is a clean, mechanical cleanup that updates the internal caller (`strbuf_utf8_align()`) without changing behavior. However, René Scharfe raised a substantive review concern: the patch changes the function signatures in the header file, so any caller outside the provided diff could now receive a `size_t` where it previously expected an `int`. This could introduce subtle bugs or warnings if those callers perform arithmetic or comparisons assuming a signed type. While the patch addresses the `//TODO` and removes redundant type conversion, its impact is broader than the diff suggests, making it potentially riskier than it first appears.

The thread is now waiting for Hardik to either audit all callers or explain why the change is safe as-is. Until that happens, the patch remains under review with an open technical question about compatibility. No other reviews or decisions have been posted yet.
