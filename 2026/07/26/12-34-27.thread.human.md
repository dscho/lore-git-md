This thread is about a refactoring patch by Hardik Kumar that changes the return type of two UTF-8 string-width calculation functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t` to better match their inherently non-negative output. The patch removes a helper function (`cast_size_t_to_int`) and updates one internal caller (`strbuf_utf8_align()`), but the header change affects all callers, raising concerns about compatibility.

Reviewers René Scharfe and Pablo Sabater have raised significant questions about whether the patch is safe as-is. Pablo’s audit found callers in `builtin/repo.c` and elsewhere that might not handle the new `size_t` return type correctly, and he argues the patch should either update all callers or explain why implicit conversion is safe. The removal of the overflow check in the now-deleted helper function is another open question—no one has confirmed whether any callers relied on it. Hardik acknowledges the feedback and plans to revise the patch, but the core issue of how to handle the type change remains unresolved.

The only concrete change so far is a minor style fix (removing unnecessary parentheses), and Hardik has yet to address Pablo’s suggestion to rewrite the commit message for clarity. The patch is still under active discussion, with no consensus on the best path forward.
