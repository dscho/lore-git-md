This thread is about a refactoring patch by Hardik Kumar that changes the return type of Git’s UTF-8 string-width functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t` to better match the inherently non-negative nature of string widths. The patch is now in its second iteration (v2), which updates all callers to use `size_t` for local variables holding the return value, addressing compatibility concerns raised in the first version.

Despite these improvements, the v2 patch has introduced significant regressions. Junio C Hamano and Pablo Sabater have both identified blocking issues: unsigned integer underflow in `diff.c`, incorrect mixed-sign comparisons in `pretty.c` and `builtin/blame.c`, and build breaks in `gettext.h` when `NO_GETTEXT` is defined. Pablo’s review also highlights unnecessary type changes in `column.c` and suggests further adjustments in `wt-status.c` to avoid narrowing conversions. The patch is not ready for Junio’s `next` branch and will require a v3 to fix these problems.

The unresolved question from v1—whether any callers relied on the overflow check in the now-removed `cast_size_t_to_int()` helper—remains open, but the immediate focus is on addressing the new type-safety bugs. Hardik has not yet responded to the feedback, so the next steps will depend on how he incorporates these suggestions into a revised version. The discussion has been substantive, with reviewers providing specific code snippets to guide the fixes.
