This is the v5 reroll of Ted Nyman’s bugfix series addressing race conditions in Git’s HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The series is now ready for final review after addressing the last test flakiness concerns raised in v4.

The core issue remains unchanged: concurrent downloads into the same object database can corrupt temporary pack files or cause resume requests to fail at EOF. The solution—using deterministic staging paths opened in read-write mode without append—ensures overlapping responses write identical bytes at identical offsets, preserving resumable downloads for both packfile URIs and dumb HTTP while avoiding cross-process coordination. The MinGW-specific sharing behavior is documented and handled, and the `.keep` file race is resolved by accepting both `"keep"` and `"pack"` output from `index-pack`.

The v5 changes are minimal and test-focused. The `--index-pack-arg` documentation now clarifies that the first instance specifies the command and subsequent instances specify its arguments, addressing Taylor Blau’s feedback. The overlapping-download test drops assumptions about write order, making the test more robust without changing production code. Ted reports the test now passes 240 runs with 12 parallel stress jobs, confirming the fix for the v4 flakiness.

The series is well-scoped, touching only `http.c`, `fetch-pack.c`, and their documentation, with new regression tests in `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`. The implementation is uncontroversial, addresses a real-world race condition, and has no impact on other HTTP fetch behaviors or on-disk formats. All prior review feedback has been incorporated, and the series is rebased onto current `master`. If no new issues surface, this is likely to graduate to `next` soon.
