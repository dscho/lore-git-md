This is the fourth patch in a seven-part feature series adding new path-related keys to the `git repo info` command. The patch introduces `path.hooks.absolute` and `path.hooks.relative`, which expose the repository’s hooks directory location in a scriptable format, respecting `core.hooksPath` configuration.

The implementation is straightforward: it uses `repo_git_path_replace()` to resolve the hooks path (accounting for `core.hooksPath` overrides) and `format_path()` to produce absolute or relative output. The patch touches `builtin/repo.c` for the logic, `Documentation/git-repo.adoc` for the man page update, and `t/t1900-repo-info.sh` for tests covering both the default `.git/hooks` location and a custom `core.hooksPath` override.

The design aligns with the series’ established pattern: keys return paths unconditionally, even if the directory does not exist, mirroring `git rev-parse --git-path` behavior. This allows scripts to know where to *create* hooks, not just where to read them. The patch is mechanically clean, with clear commit messages and test coverage, and fits neatly into the broader goal of making repository component paths discoverable without requiring direct access to Git’s internals.

No substantive review has landed yet, but the patch is unlikely to be controversial. The only open question is stylistic—whether `path.hookdir` would be a more consistent name than `path.hooks`—but this is a minor nit. The series as a whole is well-crafted and addresses a real need for external tooling. If you care about scriptable Git introspection, this patch (and the series) is worth a look.
