This is the sixth patch in a nine-patch series introducing `diff.<driver>.process`, a long-running subprocess protocol that lets external tools inject diff hunks into Git’s diff and blame pipelines. This patch unifies the bypass mechanism for both the new process driver and the existing `diff.<driver>.command` under the single `--no-ext-diff` option, and disables the process driver entirely in `git format-patch` to ensure generated patches use Git’s builtin diff algorithm.

The change replaces the boolean `--ext-diff` option with a callback that sets both `allow_external` and `no_diff_process`, so `--no-ext-diff` now disables both external diff mechanisms. The documentation is updated to reflect this unification, and to note that `--diff-algorithm` also bypasses the process driver. In `git format-patch`, the process driver is unconditionally disabled via the `no_diff_process` flag, guaranteeing that patches can be applied reliably by recipients without the external tool. The test suite adds coverage for these new behaviors, including verifying that `format-patch` does not invoke the external tool.

This is a well-motivated and cleanly implemented piece of plumbing that addresses a real usability concern: users expect `--no-ext-diff` to mean “no external tools,” and `format-patch` must produce patches that work everywhere. The patch is small, focused, and thoroughly tested, and it fits neatly into the larger series. It looks ready for merging once the rest of the series is approved.
