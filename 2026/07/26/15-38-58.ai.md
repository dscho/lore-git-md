This is a v2 bugfix series from Phillip Wood addressing two edge cases in the interactive rebase (`rebase -i`) subsystem. The series fixes (1) an incorrect commit count in the squash/fixup template message when a preceding fixup/squash command is skipped, and (2) the editor not opening after a `fixup -c` command if a preceding fixup/squash was skipped.

The only change from v1 is a small but critical robustness fix in the first patch: the condition `p[1] != '\n'` is now `p[1] && p[1] != '\n'` to guard against trailing NUL bytes in legacy command-list files, addressing Junio C Hamano’s review concern. The second patch is unchanged. Both patches touch `sequencer.c` and add substantial test coverage (36 and 47 lines respectively) to `t/t3418-rebase-continue.sh` and `t/t3437-rebase-fixup-options.sh`.

The series is narrowly scoped, well-tested, and responds directly to maintainer feedback. Phillip Wood is a domain expert in the sequencer code, and the fixes are surgical—removing an orphaned newline when skipping a command and introducing a helper function `seen_fixup_edit_msg()` to track `fixup -c` commands consistently.
