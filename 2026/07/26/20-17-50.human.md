This is the first patch in a two-part bugfix series for `git mv`. It addresses a long-standing usability issue where the error message for a failed rename operation misleadingly blames the source file, even when the real problem is a missing directory in the destination path.

The change is simple and surgical: when `rename(2)` fails, the error message now includes both the source and destination paths instead of just the source. For example, instead of "renaming 'src' failed: No such file or directory", the user now sees "renaming 'a/file' to 'b/no-such-dir/file' failed: No such file or directory". This makes it immediately clear which part of the operation is problematic.

The patch touches only one line in `builtin/mv.c` and has no behavioral impact beyond the improved error message. The commit message explains the rationale well: `rename(2)` returns `ENOENT` for both missing source files and missing destination directories, and there's no reliable way to distinguish them after the fact without introducing a race condition. The solution is to let the user see both paths and decide for themselves.

This patch has been stable since v2 and carries Junio's "Makes sense" approval. It's a clear improvement with no downsides, and the change is small enough that it could plausibly be merged on its own if the second patch were delayed. The only thing missing is an update to the test suite to verify the new error message format, but that's handled in the second patch of the series.
