This is the second patch in a two-patch test infrastructure series introducing the `commit_body()` helper. The series aims to eliminate an exit-code masking bug in the Git test suite by replacing ~60 duplicated instances of the pattern `git cat-file commit <rev> | sed -e '1,/^$/d'` with a reusable shell function.

This patch performs the mechanical conversion across 11 test scripts (`t3405`, `t3408`, `t3434`, `t3900`, `t4150`, `t7500`, `t7501`, `t7502`, `t7600`, `t7604`, `t7614`). The author notes that the idiom appears in four equivalent spellings (piped or written to a file first, with or without `-e`, using `\$` or `$` in the sed address), all producing byte-identical output, so they collapse cleanly into a single `commit_body` call. Two sites required special handling: `t7600` greps the raw commit object for a phrase that is actually part of the body, so the grep can now run against the stripped body instead, and `t3900` pipes the stripped body into `iconv`, so the output is written to a file first to avoid reintroducing an exit-code hole.

The patch is well-scoped and thoroughly verified: all converted test scripts pass in full, and a deliberate `git cat-file` failure now properly fails tests that previously masked the error. Key names introduced include the `commit_body()` helper function and the temporary file `.commit`. The changes are purely internal to the test suite and have no user-visible impact. The series is under review and not yet in any integration branch.
