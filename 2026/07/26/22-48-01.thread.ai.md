Subject: [PATCH 0/2] test: introduce commit_body() helper
Series version: v1 (initial submission, v2 forthcoming)
Originating author: Shlok Kulshreshtha
Thread type: patch series (test infrastructure)

Core problem or goal
Introduce a reusable shell helper `commit_body()` in the Git test suite to extract the message body from a commit object, replacing ~60 duplicated instances of the pattern `git cat-file commit <rev> | sed -e '1,/^$/d'` that currently mask exit codes. The change is motivated by a recently merged bugfix in `t7614` (commit `b6b276974e`) where Junio Hamano noted the exit-code hole in the existing idiom.

Current status
Under review (no evidence of merge to any integration branch). Series is at v1; v2 is forthcoming to address two missed call sites (`t7509-commit.sh` and `t3404-rebase-interactive.sh`). No prior versions exist.

Key technical details
- New helper function: `commit_body()` (added to `t/test-lib-functions.sh`)
- Documentation: added to `t/README` with usage example (`commit_body HEAD >actual`)
- Files touched: `t/test-lib-functions.sh`, `t/README`, 13 test scripts (`t3404`, `t3405`, `t3408`, `t3434`, `t3900`, `t4150`, `t7500`, `t7501`, `t7502`, `t7509`, `t7600`, `t7604`, `t7614`)
- Behavior: writes commit object to temporary file `.commit`, strips header with `sed -e "1,/^$/d"`, cleans up; propagates exit codes correctly by avoiding pipeline masking. The idiom appears in four equivalent spellings (piped or written to a file first, with or without `-e`, using `\$` or `$` in the sed address), all producing byte-identical output, so they collapse cleanly into a single `commit_body` call.
- Special cases: `t7600` greps the stripped body instead of the raw commit object for a phrase that is actually part of the body; `t3900` writes the stripped body to a file first to avoid reintroducing an exit-code hole when piping into `iconv`; `t7509` contains a separate helper `message_body()` that follows the same exit-code-masking pattern and was identified as a missed conversion in v1; `t3404` contains an inline pipe that was also missed in v1.
- Test coverage: all touched scripts pass in full; deliberate `git cat-file` failure now properly fails tests
- No user-visible impact; purely internal to the test suite

Open questions and loose ends
- The `message_body()` helper in `t7509-commit.sh` and the inline pipe in `t3404-rebase-interactive.sh` were not updated in v1 and still use the exit-code-masking pattern. Both will be converted to `commit_body()` in v2, requiring updates to patch 2/2. No other open questions remain.
