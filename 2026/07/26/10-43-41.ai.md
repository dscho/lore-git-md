This is the fifth patch in the v3 series adding path-related keys to `` `git repo info` ``. It introduces ``path.index.absolute`` and ``path.index.relative``, exposing the location of the repository’s index file in a scriptable way. The implementation uses ``repo_get_index_file()`` and ``format_path()``, respects the ``GIT_INDEX_FILE`` environment override, and returns the path unconditionally—even in bare repositories or when the file does not exist—matching the precedent set by ``git rev-parse --git-path``. The patch touches ``builtin/repo.c``, ``Documentation/git-repo.adoc``, and ``t/t1900-repo-info.sh``, where it adds tests for both standard and bare-repository scenarios. The documentation explicitly clarifies that the returned path reflects the configured location regardless of whether the file exists or the repository is bare, closing the design question raised in earlier iterations. This patch is mechanically clean, well-tested, and ready for review; the only remaining discussion points are likely to be stylistic (e.g., whether ``path.index-file`` would be a more consistent name).
