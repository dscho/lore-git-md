This is a refactoring patch that splits the subprocess API into two layers. The existing `subprocess_start()` and `subprocess_stop()` functions manage both a child process and a hashmap that indexes running processes by command string. This patch extracts `subprocess_start_command()` and `subprocess_stop_command()` so that callers who manage process lifetime through their own data structures (like the upcoming `diff.<driver>.process` feature) can reuse the child process setup and handshake machinery without the hashmap overhead.

The change is mechanical: the new functions handle process lifecycle (setup, handshake, teardown), while the original functions become thin wrappers that add hashmap operations on top. The patch is part of the `diff.<driver>.process` RFC series (v6, 4/9) and directly addresses a review request to decouple these concerns. It is well-motivated, with clear commit message and code comments explaining the split. No behavior changes are introduced; this is purely preparatory work for the diff-process driver.
