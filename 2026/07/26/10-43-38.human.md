This is the second patch in K Jayatheerth’s seven-part GSoC series adding path-related keys to `` `git repo info` ``. It introduces ``path.superproject-working-tree.absolute`` and ``path.superproject-working-tree.relative``, which expose the superproject’s working-tree root when the current repository is an initialized submodule, and return an empty string otherwise.

The implementation is straightforward: it calls ``get_superproject_working_tree()``, formats the result with ``format_path()`` using either ``PATH_FORMAT_CANONICAL`` or ``PATH_FORMAT_RELATIVE``, and registers the two new keys in the ``repo_info_field[]`` table. Documentation and tests are included, covering both submodule and non-submodule cases. The patch is mechanically clean and follows the established pattern from the first patch. No substantive review feedback has surfaced yet, so the design—empty string when not in a submodule—remains uncontested.
