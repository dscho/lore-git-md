This thread is about a small but consequential change to Git’s CI setup: bumping the Ubuntu image used for static-analysis jobs from `ubuntu-22.04` to `ubuntu-latest` (currently `ubuntu-24.04`) to pick up a newer Coccinelle version. The goal was to improve performance, but SZEDER Gábor’s recent benchmarks have thrown that rationale into question—Coccinelle 1.3.1 is 4.5× slower than the older version, directly contradicting the expected benefit.

The series itself is straightforward: a preparatory cleanup in `bloom.c` to silence a Coccinelle false positive, followed by updates to GitHub and GitLab CI configs to use the newer image. Junio C Hamano and Patrick Steinhardt initially approved the change in principle, while Elijah Newren endorsed it. However, the performance regression has shifted the conversation. Patrick’s latest reply digs deeper, questioning whether Coccinelle rules are even useful for the project. He notes that Git’s build system runs all `.cocci` files indiscriminately (except for `.pending` files), and suggests that many rules—especially those meant to ease API migrations—may not be worth maintaining. This isn’t a call for immediate action but a fundamental critique of the tooling’s value.

The thread is still under review, with no merge status reported. The next steps will likely hinge on whether the performance regression is reproducible and whether the project is willing to accept slower static-analysis runs in exchange for other benefits (like newer Coccinelle features). Meanwhile, Patrick’s broader skepticism about Coccinelle rules could spark a separate discussion about whether the project should continue writing them for API changes. For now, the series is paused while the community weighs the trade-offs.
