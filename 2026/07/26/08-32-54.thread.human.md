This thread is about updating Git’s static-analysis CI jobs to use a newer Ubuntu image (24.04 instead of 22.04) to gain a newer Coccinelle version, along with a small cleanup in `bloom.c` to silence a false positive. The series was initially posted by Jeff King (Peff) and received approval in principle from Junio C Hamano and Patrick Steinhardt, with Elijah Newren also endorsing the change. However, the performance rationale for the image bump has since been called into question: SZEDER Gábor’s benchmarks showed Coccinelle 1.3.1 is 4.5× slower than 1.1.1, directly contradicting the expected improvement.

The discussion has since shifted to broader questions about Coccinelle’s role in the project. Patrick Steinhardt, who earlier questioned the value of Coccinelle rules, has refined his position, distinguishing between temporary rules for API migrations (which he sees as less valuable) and permanent rules that enforce consistent coding antipatterns (e.g., `if (a == NULL)`), which he still supports. Junio C Hamano has also weighed in, defending Coccinelle’s utility for enforcing coding conventions. Meanwhile, SZEDER Gábor identified an inefficiency in the CI setup—static-analysis and documentation jobs install unnecessary build dependencies—and suggested a follow-up cleanup.

The series remains under review, with no merge status reported. Open questions include whether to proceed with the image bump despite the performance regression, how to address the CI inefficiency, and whether to audit or prune Coccinelle rules. The thread is now less about the specific patch and more about the project’s long-term approach to static analysis tooling.
