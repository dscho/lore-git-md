This is the fifth patch in a seven-patch series adding new path-related keys to the `git repo info` command. It introduces `path.index.absolute` and `path.index.relative`, which expose the location of Git’s index file in a scriptable format, respecting the `GIT_INDEX_FILE` environment override.

The implementation is straightforward: it uses `repo_get_index_file()` to retrieve the index path and formats it as either an absolute or relative path, mirroring the behavior of earlier patches in the series. The documentation explicitly clarifies that the returned path reflects the configured or default location *regardless* of whether the repository is bare or the file exists, aligning with the precedent set by `git rev-parse --git-path`. This design allows scripts to know where to create or modify the index file, not just where to read it.

Tests cover the standard case, environment overrides, and bare repositories, ensuring the key behaves consistently across contexts. The patch is mechanically clean, with clear commit messages and no unresolved edge cases. The only potential discussion point is stylistic—whether the key name (`path.index`) should use a hyphen (`path.index-file`) for consistency with other Git terminology—but this is minor and unlikely to block progress.

This patch is part of a well-structured GSoC series that has already settled its core design questions. It’s ready for review and looks like a sensible addition to `git repo info`.
