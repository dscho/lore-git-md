This is a documentation patch, the first in a nine-part RFC series introducing `diff.<driver>.process`, a new mechanism for external tools to inject diff hunks into Git’s diff and blame pipelines. The patch adds a clear explanation to `gitattributes(5)` of what the existing `diff.<driver>.command` *cannot* do: it only replaces the textual patch output, not the underlying diff computation, so features like word diff, function context (`-W`), `--color-moved`, and coloring operate on Git’s builtin diff, not the driver’s output. The summary formats (`--stat`, `--numstat`, `--shortstat`, `--dirstat`), `git blame`, and `git log -L` do not consult the command driver at all. This sets the stage for the later patches, which introduce the process driver to address these limitations.

The commit message is concise and the diff is minimal (ten lines), but the addition is important: it establishes the baseline expectations for external diff drivers, making it clear why the process driver is needed. The prose is direct and avoids overselling; it simply states the current behavior so readers can understand the scope of the problem the series aims to solve. This patch is unlikely to be controversial, but it is essential context for the rest of the series.
