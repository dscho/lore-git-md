This is the v4 submission of a two-patch bugfix series for `git mv`, addressing misleading error messages and unsafe behavior when the destination path contains missing directories or tracked symlinks. The series is now complete and ready for integration.

The first patch improves error messages by including both source and destination paths when `rename()` fails, making it clear which part of the operation caused the problem. The second patch adds an early check for three problematic destination path cases: missing leading directories, non-directory components, and **any tracked symlink** in the path. This prevents both misleading error messages and a subtle index corruption bug where moving through a symlink would leave the index recording the literal symlink path while the file was moved to the resolved target.

Key changes in v4: the implementation now uses `has_symlink_leading_path()` (from `symlinks.c`) to reject all tracked symlinks in the destination path, regardless of their target type, aligning with `git apply` precedent and Junio's requirement that Git must not follow tracked symlinks. This replaces the v3 approach that used `stat()` and accepted symlinks to directories. The patch also adds a new translatable error message ("destination is beyond a symbolic link") and comprehensive test coverage for symlinks as both final and intermediate components, including a regression test for the index corruption scenario.

Files touched: `builtin/mv.c` (logic changes) and `t/t7001-mv.sh` (83 new test lines covering missing directories, non-directory components, symlinks, `--dry-run` detection, and force-flag behavior). The series introduces no new symbols but adds two new translatable strings. The TOCTOU race (where the destination could disappear between check and `rename()`) remains acknowledged but unresolved, as it's considered "the best we can do" for now.

This is a well-motivated, user-facing fix with thorough test coverage and clear commit messages. The symlink-handling dispute that dominated earlier iterations is now resolved, and the series appears ready for final review. The only remaining technical loose end is the TOCTOU race, which is explicitly acknowledged in the commit message.
