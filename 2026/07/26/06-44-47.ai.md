This is the second patch in Ted Nyman’s v5 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI and dumb HTTP downloads. It is a **bugfix** targeting the HTTP transport subsystem, specifically the packfile URI and dumb HTTP download paths.

The patch prevents corruption when multiple Git processes concurrently fetch the same packfile by switching from append mode to read-write mode without O_APPEND. Each downloader retains the offset matching its requested Range, ensuring overlapping responses write identical bytes at identical offsets instead of appending duplicate data. This preserves resumable downloads while avoiding cross-process coordination.

Key changes are in `http.c`, where the staging file is now opened read-write and seeked to its current end. The patch handles MinGW’s non-append O_RDWR open behavior by creating a missing partial pack exclusively, closing it, and reopening it without O_CREAT so every retained descriptor permits another downloader to unlink the staging path. The `http-fetch.c`, `http-push.c`, and `http-walker.c` callers now accept HTTP 416 when a partial pack is already complete, letting index-pack validate its contents.

Test coverage in `t/t5550-http-fetch-dumb.sh` exercises resumed transfers, EOF ranges, overlapping 200/206 responses, unlinking the staging path while indexing, and a deterministic overlapping-download test using a custom Perl server with a 60-second timeout, FIFO waiter notification, and reliable server process cleanup. The test suite now passes 240 runs with 12 parallel `--stress` jobs, confirming the fix for the intermittent failure in test 34.

The patch is narrowly scoped to the packfile URI and dumb HTTP download paths, with no impact on other HTTP fetch behaviors or on-disk formats. It is rebased onto current `master` and ready for `next`. The design has been stable since v3, with v5 only improving documentation and test robustness. No open technical questions remain.
