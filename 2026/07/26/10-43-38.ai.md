This is the second patch in the v3 series adding path-related keys to `git repo info`. It introduces `path.superproject-working-tree.absolute` and `path.superproject-working-tree.relative` to expose the superproject’s working tree path when the current repository is a submodule. The implementation uses `get_superproject_working_tree()` and `format_path()` with `PATH_FORMAT_CANONICAL` or `PATH_FORMAT_RELATIVE`, returning an empty string when not inside a submodule.

The patch touches `builtin/repo.c` (adding two new getter functions and registering the keys), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding tests for both absolute and relative paths, including edge cases). The test coverage is thorough, verifying behavior both inside and outside a submodule.

This patch is mechanically clean and aligns with the series’ design principles: it mirrors existing internal Git APIs (`get_superproject_working_tree()`) and follows the established suffix-based formatting pattern. The only potential point of discussion is the key naming (`superproject-working-tree` vs. alternatives like `superproject.root`), but the current choice is consistent with `git rev-parse --show-superproject-working-tree`. The patch is ready for substantive review, though no major technical concerns are expected. For future reference, note the new keys (`path.superproject-working-tree.absolute`, `path.superproject-working-tree.relative`) and their reliance on `get_superproject_working_tree()`.
