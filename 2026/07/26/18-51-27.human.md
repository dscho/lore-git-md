This is the eighth patch in the v6 series implementing `diff.<driver>.process`, a long-running subprocess protocol that lets external tools inject diff hunks into Git’s diff and blame pipelines. This patch wires the `--stat`, `--numstat`, and `--shortstat` summary formats to consult the external diff process, ensuring their counts reflect the tool’s view of which lines changed rather than Git’s builtin line diff.

The patch modifies `builtin_diffstat()` to call `diff_process_fill_hunks()` before running xdiff. If the tool reports the files as equivalent (`DIFF_PROCESS_EQUIVALENT`), the xdiff is skipped, leaving the inserted and deleted counts at zero so the file is pruned from the stat output—matching the empty patch that `git diff` produces for equivalent files. Otherwise, the tool’s hunks (or the builtin fallback) feed the counts through the shared `xpparam_t`. Under `-L`, the surviving hunks are routed through the same line-range filter that `builtin_diffstat()` already uses, so a process-provided diff is scoped to the tracked range: `git log -L<range> --stat` counts only the tool’s changed lines within the range.

The patch documents an important asymmetry: unlike patch output, summary formats do not apply textconv, so the tool is consulted on the raw blob content even when a `textconv` is configured. This keeps `git diff --stat` counting raw lines as it does today, and the documentation now clarifies that the line-counting `--dirstat=lines` follows these counts while the default `--dirstat` (byte-based) computes independently. The patch also preserves mode-only changes in stat output: if the tool reports the content equivalent but the mode changed, the file still appears in the stat.

Test coverage is thorough, exercising counts from the tool’s hunks (`--numstat`, `--shortstat`), equivalent files producing no stat line, `--stat --exit-code`, raw non-textconv content sent to the tool, multi-file mixes of equivalent and changed files, mode-only changes, and range-scoped `--stat` under `git log -L`. The tests confirm that the integration preserves all existing behaviors while making the summary formats consistent with the tool’s view. This patch completes the series’ goal of making every “which lines changed” operation consult the external tool, with only combined diffs (`--cc`) remaining as future work.
