This is the third and final patch in Ted Nyman’s v5 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI and dumb HTTP downloads. The patch addresses a subtle edge case in `fetch-pack`: when `index-pack` encounters an existing `.keep` file, it reports `"pack<TAB><hash>"` instead of `"keep<TAB><hash>"`, causing `fetch-pack` to reject the output and fail. The fix makes `fetch-pack` accept both formats, validates the reported pack hash against the advertised hash, and only registers a `.keep` lockfile when the current fetch created it.

The change is narrowly scoped to `fetch-pack.c` and adds a new regression test in `t/t5702-protocol-v2.sh` that exercises a packfile URI fetch with a pre-existing `.keep` file. The implementation adopts Jeff King’s suggested `strbuf` refactor for clarity (though the diff here shows the final state rather than the refactor itself) and handles the output parsing without consuming subsequent fsck messages. The test confirms the `.keep` file is preserved, the pack and index are correctly installed, and the excluded blob is accessible.

This patch completes the series, which has already seen its preliminary cleanup (patch 1) merged to `next` and its core HTTP transport fix (patch 2) thoroughly reviewed and stress-tested. The production code here is unchanged since v4, and the series is rebased onto current `master` with no open technical questions. The fix is uncontroversial and ready for integration.
