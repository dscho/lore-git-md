This is the sixth patch in a seven-patch series adding new path-related keys to the `git repo info` command. It introduces `path.grafts.absolute` and `path.grafts.relative`, which expose the location of the repository’s grafts file in a scriptable format, respecting the `GIT_GRAFT_FILE` environment override.

The patch is clean and well-scoped, touching only `builtin/repo.c`, `Documentation/git-repo.adoc`, and the test suite (`t/t1900-repo-info.sh`). The implementation follows the established pattern of the series: it uses `repo_get_graft_file()` to fetch the path and `format_path()` to handle absolute/relative formatting. The documentation explicitly clarifies that the path is returned unconditionally, even if the file does not exist, aligning with `git rev-parse --git-path` precedent. Tests cover both the default case and an environment override.

This patch is part of a settled design discussion. Earlier feedback questioned whether the path should be returned when the file does not exist, but the current behavior (unconditional return) was confirmed as intentional and useful for scripts that need to *create* the file. The v3 iteration adds no functional changes—only documentation clarifications—but the series as a whole is now mechanically solid and ready for deeper technical review.

The only remaining open question is stylistic: whether the key name (`path.grafts`) should align more closely with existing Git terminology (e.g., `path.graft-file`). The patch itself is uncontroversial and likely to be accepted as-is. If you care about scriptable access to repository paths, this series is worth tracking.
