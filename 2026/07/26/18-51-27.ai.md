This is the eighth patch in the v6 series implementing `diff.<driver>.process`, a long-running subprocess protocol that lets external tools inject diff hunks into Git's diff and blame pipelines. This patch wires the `--stat`, `--numstat`, and `--shortstat` summary formats to consult the external diff process, ensuring their counts reflect the tool's view of which lines changed rather than Git's builtin line diff.

The patch modifies `builtin_diffstat()` to call `diff_process_fill_hunks()` before running xdiff. If the tool reports the files as equivalent (`DIFF_PROCESS_EQUIVALENT`), the xdiff is skipped, leaving the counts at zero so the file is pruned from the stat output—matching the empty patch that `git diff` already produces for equivalent files. Otherwise, the tool's hunks (or the builtin fallback) feed the counts through the shared `xpparam_t`. Under `-L`, the surviving hunks are routed through the same line-range filter used by the builtin stat, so a process-provided diff is scoped to the tracked range: `git log -L<range> --stat` counts only the tool's changed lines within the range, not the builtin diff's.

The stat path does not apply textconv, so the tool is consulted on the raw blob content even when a `textconv` is configured for patch output. This keeps `git diff --stat` counting raw lines as it does today, preserving the existing asymmetry between patch output and summary counts under textconv. Because the content is the raw blob, the stat path sends the blob object names (`old-oid`/`new-oid`) to the tool for any stored blob, where the patch path omits the OID under textconv.

The documentation updates move the summary formats out of the "not yet wired" group and into the list of features that use the tool's hunks, noting the raw, non-textconv content they receive. It also clarifies that the line-counting `--dirstat=lines` follows these counts, while the default `--dirstat` (byte-based) computes independently and does not consult the tool. The patch adds 130 lines of test coverage in `t/t4080-diff-process.sh`, exercising counts from the tool's hunks, equivalent files producing no stat line, `--stat --exit-code`, raw non-textconv content, multi-file mixes, mode-only changes, and range-scoped `--stat` under `git log -L`.

The change is well-motivated and technically sound, addressing a prior inconsistency where `git diff --stat` and `git diff` could disagree on whether a file had changed. The integration is tight but unobtrusive, preserving all existing behaviors (mode-only changes, textconv asymmetry, range filtering) while ensuring the stat counts align with the tool's hunks. The rebase onto `mm/line-log-limited-ops` resolves the merge conflict in `line-log.c` by adjusting how `builtin_diffstat()` routes the tool's hunks through the line-range filter, ensuring range-filtering semantics are preserved without altering core functionality.
