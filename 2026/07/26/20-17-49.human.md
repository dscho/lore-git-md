This is a bugfix series for `git mv`, now in its fourth iteration. The goal is to fix a misleading error message and prevent index corruption when moving files through symlinked paths.

The series now consists of two patches. The first improves the error message to include both source and destination paths when a rename fails. The second adds an early check that rejects any destination path containing a tracked symlink—regardless of whether the symlink points to a file or directory—using `has_symlink_leading_path()` from `symlinks.c`. This aligns `git mv` with `git apply`'s behavior and prevents the index from recording a literal symlink path while the file is moved to the resolved location, which previously corrupted the repository state.

The v4 update addresses Junio’s feedback by switching from `stat()` back to `lstat()` and introducing `has_symlink_leading_path()` to reject all symlinks in the destination path. The series also adds a new error message ("destination is beyond a symbolic link") and expands test coverage to include symlinks as both intermediate and final path components, as well as regression tests for the index corruption bug.

Files touched are `builtin/mv.c` and `t/t7001-mv.sh`. The changes are well-scoped, with clear commit messages and thorough test coverage. The only acknowledged limitation is a TOCTOU race (the destination directory could disappear between the check and the `rename(2)` syscall), which is considered "the best we can do" for now. The series is ready for integration and unlikely to be controversial.
