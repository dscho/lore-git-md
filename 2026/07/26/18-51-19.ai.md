This is the sixth revision of the `diff.<driver>.process` RFC series, now rebased onto the in-flight `mm/line-log-limited-ops` topic to resolve the merge conflict in `line-log.c`. The series introduces a long-running subprocess protocol that lets external tools inject diff hunks into Git's diff and blame pipelines while preserving all downstream features (word diff, function context, color-moved, `--stat`, `git blame`, and `git log -L`).

The rebase adjusts how `builtin_diffstat()` routes the tool's hunks through the line-range filter when `-L` is active (patch 8), ensuring that "git log -L --stat" counts only the tool's changed lines within the tracked range rather than the builtin diff's. This is the only functional change from v5; the core protocol, validation logic, and integration points remain unchanged. The series is now technically complete, with all major diff and blame features wired to consult the external tool, robust error handling, and comprehensive test coverage (1113+ lines in `t/t4080-diff-process.sh`).

The documentation (patch 1) clearly contrasts the new process driver with the existing `diff.<driver>.command`, explaining why the command driver cannot integrate with Git's full diff pipeline. The "Which features consult the diff process" section in `gitattributes(5)` now includes `git log -L` and the stat formats, and notes that combined diffs (`--cc`) remain on the builtin algorithm as future work. The subprocess API has been refactored to separate process lifecycle from hashmap management (patch 4), and the protocol carries blob object names (old-oid/new-oid) for future caching optimizations.

All substantive review feedback from previous rounds has been addressed, including Windows compatibility and the transition to a C-based test helper. The maintainer has endorsed the technical direction, and the only remaining work is minor documentation refinements around flag behavior interactions. The series is ready for final sign-off and merging.
