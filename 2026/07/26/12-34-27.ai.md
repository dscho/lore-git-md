This is a refactoring patch targeting the UTF-8 string-width calculation functions in Git.

The patch changes the return type of `utf8_strwidth()` and `utf8_strnwidth()` from `int` to `size_t`, addressing a long-standing `//TODO` comment in the code. The functions compute the display width of UTF-8 strings, which is inherently a non-negative quantity, so `size_t` is a more appropriate type than `int`. The change removes a helper function (`cast_size_t_to_int`) that was previously used to convert the result, and updates the function signatures in both the implementation (`utf8.c`) and header (`utf8.h`).

The patch touches only these two functions and their callers within `utf8.c` (specifically, `strbuf_utf8_align()`). No behavior change is introduced—this is purely a type-system cleanup. The commit message is minimal but sufficient for the scope of the change.

This appears to be a well-scoped, mechanical refactoring with no obvious downsides. The functions are used in formatting contexts (e.g., column alignment in `git column`), so the change is unlikely to introduce regressions. The patch is standalone and not part of a larger series.
