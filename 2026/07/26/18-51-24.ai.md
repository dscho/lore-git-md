This is the core implementation patch in the `diff.<driver>.process` series (5/9 in v6). It introduces the long-running subprocess protocol that lets external tools inject diff hunks into Git’s diff and blame pipelines while preserving all downstream features (word diff, function context, color-moved, `--stat`, `git blame`, and `git log -L`).

The patch adds `diff-process.c` and `diff-process.h`, which implement the pkt-line protocol over stdin/stdout. The handshake negotiates version=1 and capability=hunks, then per-file requests send the pathname, optional blob object names (old-oid/new-oid), and both file contents. The tool responds with hunk lines (`hunk <old_start> <old_count> <new_start> <new_count>`) and a status packet (success, error, or abort). Git validates the hunks for bounds, overlap, and per-gap alignment before feeding them into xdiff, which continues through compaction and emission for downstream features. On error or abort, Git falls back to the builtin diff for that file or the entire session, respectively.

Key technical details:
- The subprocess is stored on the `userdiff_driver` struct and launched on first use; failures are cached to avoid retrying.
- The protocol carries blob object names (old-oid/new-oid) only when the content is the raw blob (omitted under textconv or for working-tree sides without stored objects).
- Hunks must be ordered, non-overlapping, and keep unchanged runs aligned on both sides; misaligned gaps trigger fallback.
- The tool can report files as equivalent (no hunks + status=success), causing `git diff` to produce no output and `git blame` to skip the commit.
- Bypass mechanisms include `--no-ext-diff`, `--diff-algorithm`, whitespace-ignoring flags, and `format-patch`.
- The test backend (`test-diff-process-backend.c`) exercises all response modes (success, error, abort, crash, malformed hunks) and edge cases (empty file sides, mid-file insertions, overlapping hunks).

The patch is well-tested (645 lines of new tests in `t/t4080-diff-process.sh`) and integrates cleanly with the rest of the series. It addresses all prior review feedback, including Windows compatibility and the transition to a C-based test helper. The only remaining work is minor documentation refinements.
