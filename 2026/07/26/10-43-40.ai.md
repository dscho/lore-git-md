This is the fourth patch in the v3 series adding path-related keys to `` `git repo info` ``. It introduces ``path.hooks.absolute`` and ``path.hooks.relative``, which expose the repository’s hooks directory in both absolute and relative forms, respecting any ``core.hooksPath`` override. The implementation is straightforward: it uses ``repo_git_path_replace()`` to resolve the hooks path and ``format_path()`` to produce the requested format. Tests verify both the standard ``.git/hooks`` fallback and a custom ``core.hooksPath`` setting. The patch is mechanically clean, well-documented, and ready for review; the only likely discussion point is whether the key name ``path.hooks`` (rather than ``path.hookdir``) aligns with existing Git terminology.
