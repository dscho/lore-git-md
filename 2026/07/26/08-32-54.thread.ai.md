Thread identity
Subject: [PATCH 0/2] ci: bump Ubuntu image for static-analysis job
Series version: v1 (initial)
Originating author: Jeff King (peff@peff.net)
Thread type: patch series (CI/build system)

Core problem or goal
Bump the Ubuntu image version used in Git’s static-analysis CI jobs from `ubuntu-22.04` to `ubuntu-latest` (resolving to `ubuntu-24.04` at time of posting) to pick up a newer Coccinelle version (1.3.0+), with the expectation of improved performance. The series also includes a preparatory cleanup in `bloom.c` to silence a Coccinelle false positive (`CHECK_ASSERTION_SIDE_EFFECTS`) triggered by an assertion macro when compiled with GCC 15 under `-O2`.

Current status
Under review; v1 posted. Junio C Hamano and Patrick Steinhardt have signaled approval in principle, while Elijah Newren has endorsed the change. SZEDER Gábor’s recent review introduces a **major caveat**: Coccinelle 1.3.1 benchmarks as **4.5× slower** than 1.1.1 on the same Git revision, directly contradicting the patch’s performance rationale. No merge status reported; next step is likely re-evaluation of the image bump in light of the new data.

Key technical details
- Files touched: `bloom.c` (preparatory cleanup: assertion macro replaced with explicit `if/else if/else` cascade ending in `BUG()`), `.github/workflows/main.yml`, `.gitlab-ci.yml` (CI config updates: `ubuntu-22.04` → `ubuntu-latest`).
- Subsystems: CI/build system (static-analysis job only), bloom filter code.
- New/renamed symbols: none.
- Old-vs-new behavior: no functional change to Git; CI toolchain version updated and Coccinelle false positive silenced. Performance impact of the image bump is now **contested** (expected improvement vs. measured 4.5× regression).
- On-disk format: unchanged.
- Test coverage: none added; CI job itself is the verification. SZEDER Gábor’s benchmarks provide empirical data on Coccinelle performance.
- CI inefficiency identified: static-analysis and documentation jobs install unnecessary build dependencies (compiler, Apache, p4, jgit, etc.) due to a 2021 pattern-matching change in the CI scripts.

Open questions and loose ends
- **Performance regression**: Is the 4.5× slowdown in Coccinelle 1.3.1 reproducible across environments, and is it specific to Git’s `.cocci` rules or a general regression? Does the newer version offer other benefits (e.g., correctness, feature support) that outweigh the performance cost?
- **CI image choice**: Should the image bump proceed despite the performance regression, or should the series be revised to target a different Ubuntu version (e.g., one with Coccinelle 1.1.1)?
- **CI inefficiency**: Should the unnecessary build dependencies in static-analysis and documentation jobs be addressed as part of this series or as a separate follow-up?
- **Coccinelle rule audit**: Patrick Steinhardt’s earlier suggestion to audit and prune obsolete `.cocci` files remains open, as does Junio C Hamano’s proposal to add exit criteria to Coccinelle rules and update `tools/coccinelle/README`.
