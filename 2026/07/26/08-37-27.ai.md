This is the first patch in a two-patch CI/build system series from Jeff King. It refactors a small section of `bloom.c` to silence a false positive from Coccinelle’s `CHECK_ASSERTION_SIDE_EFFECTS` rule, which incorrectly flags the assertion `assert(version == 1 || version == 2)` as having side effects when compiled with GCC 15 under `-O2`. The false positive is specific to newer GCC versions and does not affect the correctness of the code, but it would block upgrading the Ubuntu image in the static-analysis CI job (which the second patch does).

The change replaces the assertion with an explicit `if/else if/else` cascade that directly checks the version, ending with a `BUG()` call for unexpected values. This both silences the Coccinelle warning and makes the control flow slightly clearer by removing redundant logic. The patch touches only `bloom.c` and introduces no functional changes to Git’s behavior. Jeff cc’d Elijah Newren, the original author of the bloom filter code, but no review feedback has been recorded yet.

The motivation is pragmatic: the current assertion triggers a false positive in newer toolchains, and the series aims to upgrade the CI image to `ubuntu-24.04` (which ships GCC 15). While the false positive could also be avoided by tweaking compiler flags (e.g., using Clang or `-flto`), Jeff argues that the refactoring improves readability and is a cleaner solution. The patch is narrowly scoped to the specific assertion and does not attempt to address broader issues with Coccinelle’s side-effect detection.

Key technical details: the function `test_bloom_murmur3_seeded()` in `bloom.c` is modified; the assertion macro `assert()` is replaced with direct conditional checks; the `BUG()` macro is introduced for the unexpected case. No new symbols are added, and the on-disk format remains unchanged. The patch is self-contained and does not depend on the second patch in the series, though it is motivated by the same CI toolchain upgrade.
