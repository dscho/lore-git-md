This is a refactoring patch that changes the return type of UTF-8 string-width functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t`. The patch itself is clean and addresses a long-standing type mismatch, but the review by Pablo Sabater raises important concerns about its broader impact.

Sabater’s feedback is substantive. He points out that the patch removes `cast_size_t_to_int()`, which previously included an overflow check, and that the header change affects *all* callers of these functions—not just the one updated in the patch (`strbuf_utf8_align()`). While he notes that no callers appear to break with the new type, he argues the patch should update them all for consistency. He also suggests improvements to the commit message, including moving the TODO reference to the trailer and rewording the description to better explain the rationale.

The patch is well-scoped but incomplete as written. The type change is justified (display width is inherently non-negative), but the lack of caller updates risks introducing subtle bugs or compiler warnings. Sabater’s review is thorough and constructive, making it clear this patch will need a v2 to address the compatibility and consistency issues. Worth watching for follow-up.
