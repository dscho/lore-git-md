This is Junio's final review note on the two-patch `git mv` bugfix series. He confirms that the use of `has_symlink_leading_path()`—borrowed from `git apply`—correctly addresses the core issue: Git must not follow tracked symlinks when resolving the destination path, regardless of their target. The series now rejects any tracked symlink in the destination path, preventing both misleading error messages and the index corruption bug where moving through a symlink would leave the index recording the literal symlink path while the file was moved to the resolved target.

Junio’s tone is approving; he calls the approach “sounds good” and agrees that allowing symlink traversal would be more confusing than rejecting it outright. The series is now technically complete: the symlink-handling dispute that dominated earlier iterations is resolved, the error messages are clear, and the test coverage is thorough (83 new lines in `t/t7001-mv.sh`, including a regression test for the index corruption scenario). The only acknowledged loose end is the TOCTOU race, which Junio and the author have agreed is “the best we can do” for now.

This email signals that the series is ready for integration; no further changes are expected. The patches touch `builtin/mv.c` and `t/t7001-mv.sh`, add two new translatable strings, and introduce no new symbols. The split structure (first patch improves error messages, second adds the early existence check) remains unchanged and is now uncontroversial.
