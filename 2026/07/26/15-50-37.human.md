This is a refactoring patch that changes the return type of UTF-8 string-width calculation functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t`. The patch addresses a long-standing `//TODO` comment and removes a helper function (`cast_size_t_to_int`) used for type conversion. While the change is mechanically clean, it has sparked a substantive review discussion about compatibility risks.

The patch itself is straightforward: it updates the function signatures in both the implementation (`utf8.c`) and header (`utf8.h`), and adjusts the internal caller (`strbuf_utf8_align()`) to use the new return type. The author argues that implicit type conversion should handle any mismatches at call sites, but this claim is contested. The review highlights that the header change affects *all* callers, not just the ones shown in the diff, which could introduce subtle bugs if callers assume a signed return type.

René Scharfe raised the critical question of whether all callers are safe with the new `size_t` return type, given that `cast_size_t_to_int()` (which included an overflow check) has been removed. Hardik Kumar responded by suggesting that implicit conversions would suffice, but this does not address the broader compatibility concern. René also noted a minor style nit (unnecessary parentheses around `string` in a ternary), which the author agreed to fix in a follow-up version.

The patch is under review, and the key open question is whether the change is safe for all callers. Until this is resolved—either by auditing all callers or providing a clear rationale for the current scope—the patch remains in limbo. The discussion underscores the importance of considering the full impact of header-level changes, even in seemingly simple refactorings.
