This is the final patch in the `diff.<driver>.process` RFC series, now at version 6. It wires `git log -L` range tracking to consult the external diff process, ensuring that commit selection matches the diff output. Previously, `git log -L` used Git's builtin diff for tracking while the displayed diff consulted the external tool, causing reformat-only commits to be selected but then rendered with an empty diff. Now, when the tool reports the files as equivalent, the commit is dropped from the log entirely, matching what the user sees.

The patch modifies `collect_diff()` in `line-log.c` to call `xdi_diff_process()` before falling back to the builtin diff. The driver is selected by the old (parent) path, mirroring how `builtin_diff()` resolves it, so renamed files use the same driver for both tracking and display. Blob object names are omitted in this path (though the infrastructure exists for future optimization). The documentation in `gitattributes.adoc` is updated to reflect that `git log -L` now consults the external tool for both range tracking and display.

Test coverage (33 lines in `t/t4080-diff-process.sh`) verifies that equivalent commits are dropped from the log while preserving the creating commit, ensuring the change is selectively skipped rather than the entire log going empty. The patch completes the series' goal of making every "which lines changed" operation consult the external tool, with the only remaining cases using the builtin algorithm being combined diffs (`--cc` and merge diffs), whose protocol would need extension for multiple parent comparisons.

This patch is part of a well-structured, thoroughly reviewed series that has addressed all substantive feedback, including a rebase onto `mm/line-log-limited-ops` to resolve a merge conflict. The series is now technically complete and ready for final sign-off.
