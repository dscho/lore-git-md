This is Junio’s final sign-off on the two-patch bugfix series for `git mv`.  The series is now **ready for integration** into `next`.

The core issue—a misleading error message that blamed the source file when the destination’s parent directory was missing—is fixed in two steps: the first patch improves the error message to show both source and destination paths, and the second adds an early check that explicitly rejects three problematic cases: missing directories, non-directory components, and **any tracked symlink** in the destination path.  The symlink-handling dispute that ran through earlier iterations is now resolved by using `has_symlink_leading_path()`, which aligns `git mv` with the precedent set by `git apply` and Junio’s requirement that Git must never follow tracked symlinks.

The series touches only `builtin/mv.c` and `t/t7001-mv.sh`; the test suite has grown by 83 lines to cover symlinks as both final and intermediate components, missing directories, `--dry-run` detection, and a regression test for the index-corruption scenario.  Two new translatable strings were added, but the on-disk format is unchanged.  The only acknowledged loose end is a TOCTOU race (the destination could disappear between the check and the actual `rename()`), which Junio accepts as “the best we can do” for now.

No new objections or requests for changes have surfaced since v4 was posted, and Junio’s review here is purely confirmatory.  The series looks clean, well-tested, and uncontroversial.
