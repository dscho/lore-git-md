This is a test infrastructure patch, part of a two-patch series introducing a new helper function for the Git test suite. The patch adds `commit_body()`, a shell function that extracts the message body from a commit object, to `t/test-lib-functions.sh` and documents it in `t/README`.

The helper addresses a long-standing issue where the test suite repeatedly uses `git cat-file commit <rev> | sed -e '1,/^$/d'` to strip commit headers, a pattern that masks exit codes if `git cat-file` fails. By writing the commit object to a temporary file instead of piping it directly to `sed`, the helper ensures that failures propagate correctly. The implementation is straightforward and follows Junio Hamano’s suggested approach from a recent bugfix in `t7614` (commit `b6b276974e`), which motivated this series.

The patch is well-crafted: the commit message clearly explains the problem, the solution, and the rationale for avoiding pipes. The helper itself is simple and self-contained, and the documentation in `t/README` includes a usage example. This is the first of two patches; the second will convert existing call sites to use the new helper. No user-visible changes are introduced—this is purely internal test suite cleanup.

The series looks like a solid improvement. The motivation is concrete (fixing a real exit-code hole), the implementation is clean, and the scope is well-defined. If the second patch delivers on the promise of converting the ~60 duplicated instances, this will be a worthwhile cleanup that makes the test suite more robust. No controversy or open questions are apparent in this patch.
