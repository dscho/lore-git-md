This is the final review exchange in Patrick Steinhardt’s five-patch series refactoring Git’s object database (ODB) setup to support pluggable backends. Junio C Hamano’s reply to the fifth patch is brief but substantive, focusing on the long-term design of the new `create_on_disk` callback.

The patch itself moves the creation of backend-specific directories (`objects/pack`, `objects/info`) from the generic repository setup code into the "files" backend’s implementation, completing the series’ goal of decoupling ODB layout from core initialization. Junio’s feedback is forward-looking: he questions whether the callback’s name (`create_on_disk`) is too narrow, given that future backends (e.g., cloud-based ODBs) might need initialization steps that don’t involve disk operations. His suggestion to rename the callback to something more generic (e.g., `initialize`) reflects a concern that the current naming could constrain future use cases.

The exchange is constructive and low-stakes. Junio explicitly acknowledges the note in Patrick’s commit message about the mandatory `objects/` directory (a key constraint for repository discovery) and even jokes about Git 4.0, signaling that the feedback is about future-proofing rather than blocking the current patch. The review is substantive but not urgent—this is a design question for later, not a correctness issue for now. The series as a whole remains under review, with the first four patches already receiving Junio’s feedback in earlier rounds.
