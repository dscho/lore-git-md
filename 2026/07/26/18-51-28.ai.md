This is the final patch in the `diff.<driver>.process` RFC series (v6, 9/9). It wires `git log -L` range tracking to consult the external diff process, completing the series' goal of making every "which lines changed" operation in Git's diff and blame pipelines consult the external tool.

The patch modifies `line-log.c` to call `xdi_diff_process()` in `collect_diff()`, the function that determines which commits affect the tracked line range. When the tool reports the files as equivalent, no ranges are collected, causing the tracked range to map across the commit unchanged and the commit to drop out of the log. This matches the behavior already implemented for `git blame` and summary formats, ensuring consistency between what the log selects and what the diff displays. The driver is selected by the old (parent) path, matching how `builtin_diff()` resolves the driver, so renamed files use the same driver for both range tracking and display.

The documentation update removes `git log -L` from the "not yet wired" list and clarifies that both the line-range display and the underlying range tracking now consult the tool. The test coverage (33 lines) verifies that a reformat-only commit is dropped from the log while preserving the creating commit, confirming the change is selectively skipped rather than the entire log going empty.

This patch resolves the last major integration point identified in the series' documentation. The only remaining cases using the builtin algorithm are combined diffs (`--cc` and merge diffs), whose protocol would need extension for multiple parent comparisons. The series is now technically complete, with all substantive review feedback addressed and the merge conflict with `mm/line-log-limited-ops` resolved via rebase.
