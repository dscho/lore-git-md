This is the core implementation patch of the `diff.<driver>.process` feature, the fifth in a nine-patch series now at v6. The patch adds a long-running subprocess protocol that lets external tools inject diff hunks into Git’s diff and blame pipelines while preserving all downstream features (word diff, function context, color-moved, `--stat`, `git blame`, and `git log -L`).

The key mechanism is a pkt-line protocol over stdin/stdout: Git sends file pairs (pathname, optional blob object names, and content) and the tool responds with hunk lines that mark changed line ranges. The patch includes robust validation (bounds, overlap, per-gap alignment) and graceful fallbacks to the builtin diff on tool errors, crashes, or malformed responses. The subprocess is stored on the `userdiff_driver` struct and launched on first use, with failures cached to avoid repeated warnings. The protocol is forward-compatible: tools ignore unknown request keys, and Git ignores unknown trailing fields on hunk lines.

The patch also introduces `diff_process_fill_hunks()`, the public entry point that handles driver lookup, flag checks (e.g., `--no-ext-diff`, `--diff-algorithm`), and subprocess management. It returns an enum to distinguish "hunks populated" from "files equivalent" from "tool failure," letting callers decide whether to skip the diff or fall back. The implementation is careful about edge cases: it bypasses the process for whitespace-ignoring flags (which the tool cannot honor), handles empty file sides, and preserves the trailing-newline-only change marker rather than treating such files as equivalent.

Test coverage is thorough: the patch adds a C-based test helper (`test-diff-process-backend.c`) with 16 response modes (success, error, abort, crash, malformed hunks, etc.) and a 645-line test script (`t/t4080-diff-process.sh`) exercising core behavior, downstream features, bypass mechanisms, and error handling. The tests confirm that the tool controls which lines are marked as changed, that word diff and log work normally, and that fallbacks preserve correctness.

The patch is well-structured and addresses all prior review feedback, including subprocess API refactoring and Windows compatibility. It is now technically complete and ready for final review, with only minor documentation refinements remaining. The series as a whole is unblocked after rebasing onto `mm/line-log-limited-ops` to resolve the merge conflict in `line-log.c`.
