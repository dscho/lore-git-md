This is the first patch in a two-part test infrastructure series. It introduces the `commit_body()` helper function to `t/test-lib-functions.sh` and documents it in `t/README`.

The patch follows the design sketched in the cover letter: the helper writes the commit object to a temporary file (`.commit`), strips the header with `sed -e "1,/^$/d"`, and cleans up. This ensures that any failure in `git cat-file` propagates to the test script rather than being masked by a pipeline. The implementation is minimal and exactly matches Junio Hamano’s suggested approach from the earlier bugfix (`b6b276974e`).

The documentation in `t/README` is clear and includes a usage example (`commit_body HEAD >actual`), making the helper immediately usable for future test scripts. No edge cases or error conditions are handled beyond the core functionality, which is appropriate for a test helper.

Key technical details for follow-up discussion: the helper is named `commit_body`, takes a single revision argument (`<rev>`), and operates on a temporary file named `.commit`. The `sed` invocation is hard-coded to strip everything up to and including the first blank line, which matches the existing idiom being replaced. The patch touches only `t/README` and `t/test-lib-functions.sh`.
