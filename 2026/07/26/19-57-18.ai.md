This is a refactoring patch (v2) that changes the return type of UTF-8 string-width calculation functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t` in `utf8.h` and `utf8.c`. The patch also updates all callers to use `size_t` for local variables holding the return value, addressing the compatibility concerns raised in the v1 review.

The core change is a type-system cleanup: the functions compute inherently non-negative display widths, so returning `size_t` is more appropriate than `int`. The v2 patch is more comprehensive than v1, updating all callers (11 files) to avoid implicit conversions and potential undefined behavior. Some callers still cast the result back to `int` where necessary (e.g., for padding calculations or test compatibility), but these are now explicit via `cast_size_t_to_int()`.

The patch removes the `//TODO` comment in `utf8.c` and drops the redundant parentheses around `string` in a ternary, as requested in the v1 review. The commit message is clearer, explaining the rationale and scope of the change. The overflow check in the removed `cast_size_t_to_int()` helper is not reintroduced, but the patch does not address whether any callers relied on it—this remains an open question.

- Files: `utf8.c`, `utf8.h`, and 9 caller files (`builtin/blame.c`, `builtin/branch.c`, `builtin/repo.c`, `column.c`, `diff.c`, `gettext.c`, `gettext.h`, `pretty.c`, `wt-status.c`).
