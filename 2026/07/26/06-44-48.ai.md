This is the third and final patch in Ted Nyman’s v5 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI downloads. The patch makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, ensuring robust handling when a `.keep` file already exists.

The change is narrowly scoped to `fetch-pack.c` and adds a new regression test in `t/t5702-protocol-v2.sh`. The core logic now reads the prefix (`keep` or `pack`) and hash from `index-pack`’s output without consuming subsequent fsck messages, validates the reported pack hash against the advertised hash, and only registers a `.keep` lockfile if the current fetch created it (`created_keep` flag). This prevents race conditions where multiple processes might otherwise contend over the same `.keep` file.

The patch adopts Jeff King’s suggested `strbuf` refactor for clarity (though the diff here uses a simpler `char[]` approach) and includes a test exercising a packfile URI fetch with a pre-existing `.keep` file. The test confirms the `.keep` file is preserved, the pack and index are correctly written, and the expected object is retrievable.

No substantive concerns remain; the patch is rebased onto current `master` and ready for `next`. The series as a whole (patches 1 and 2 already in `next`) addresses a real bug with thorough test coverage and minimal risk to unrelated code paths. The changes are well-motivated and align with prior feedback from Junio C Hamano, Taylor Blau, and Jeff King.
