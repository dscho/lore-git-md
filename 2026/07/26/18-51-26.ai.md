This is the seventh patch in the `diff.<driver>.process` RFC series (v6, 9 patches total). It wires `git blame` to consult the external diff process when configured, enabling blame to skip commits that the tool reports as having no semantic changes (e.g., reformatting-only commits). The patch introduces `xdi_diff_process()`, a shared helper in `diff-process.c` that consults the process, runs xdiff on the tool’s hunks (or falls back to the builtin diff), and returns `DIFF_PROCESS_EQUIVALENT` for zero-hunk responses. This helper is reused by `git log -L` in a later patch.

The integration is tight: blame’s `pass_blame_to_parent()` calls `xdi_diff_process()` with the parent path (matching `builtin_diff()`’s driver resolution), and skips the commit when the tool reports equivalence. The subprocess is long-running (amortizing startup cost across the blame traversal), but each commit incurs a round-trip. Whitespace-ignoring options (`-w`, `-b`) bypass the process entirely, as the tool cannot honor them. Blob object names are omitted in the protocol for blame, since each blob pair is diffed only once.

Test coverage (60+ lines in `t/t4080-diff-process.sh`) exercises skipping reformat-only commits, respecting tool-provided hunks, and bypassing the process for `--no-ext-diff` and `-w`. The patch is a key step toward the series’ goal of making every "which lines changed" operation consult the external tool, and it demonstrates the protocol’s flexibility by reusing the same helper for both blame and line-log operations.
