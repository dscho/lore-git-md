This is a **brief follow-up in a substantive review thread** about the first patch in Son Luong Ngoc’s v3 series fixing `git rebase --update-refs` edge cases with symbolic references. Junio C Hamano weighs in on Phillip Wood’s latest refinement, focusing on the HEAD comparison logic.

Junio agrees with Phillip’s suggestion to use `resolved_ref` (the resolved target of the symref) instead of `decoration->name` (the symref name itself) when checking if a decoration matches the current HEAD. This would handle cases where HEAD points outside `refs/heads/` (e.g., to a tag) and a symref under `refs/heads/` points to the same target, ensuring consistent skipping behavior. However, Junio questions whether a HEAD that is a symref pointing outside `refs/heads/` is a valid or intended configuration, asking why the code should cater to it at all. This introduces a broader design question: should the rebase logic assume HEAD always points to a branch, or should it robustly handle edge cases like symrefs to tags or other namespaces?
