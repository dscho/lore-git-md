This is the second patch in the v6 series introducing `diff.<driver>.process`, a long-running subprocess protocol that lets external tools inject diff hunks into Git's diff and blame pipelines. This patch adds support for external hunks to the xdiff layer by extending `xpparam_t` with two new fields: `external_hunks` (an array of `xdl_hunk` structs) and `external_hunks_nr` (the array length). When these fields are set, `xdl_diff()` populates the `changed[]` arrays from the supplied hunks instead of running the builtin diff algorithm, then continues through compaction and emission as usual.

The implementation includes thorough validation of the supplied hunks: it checks for out-of-bounds line numbers, overlapping or out-of-order hunks, and misaligned unchanged runs between hunks. If validation fails, the function warns and falls back to the builtin diff algorithm for that file. The unchanged runs between hunks (and before the first and after the last) must be the same length on both sides, as `xdl_build_script()` walks the two files in lockstep over unchanged lines. The patch also skips `trim_common_tail()` when external hunks are present, since they reference line numbers in the original content.

The patch is well-structured and clearly motivated, with detailed comments explaining the validation logic and the rationale for skipping `trim_common_tail()`. The use of `BUG()` for caller preconditions (non-negative counts and 1-based starts) is appropriate, as these are normalized by the caller before reaching xdiff. The fallback to the builtin diff on validation failure is a sensible design choice, ensuring robustness even if the external tool misbehaves. This patch is a critical enabler for the rest of the series, as it allows the diff-process driver to bypass the builtin diff algorithm while still leveraging xdiff's compaction and emission paths for downstream features like word diff, color-moved, and function context.
