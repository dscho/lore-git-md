This is the second patch in Ted Nyman’s three-part bugfix series (v5) addressing race conditions in Git’s HTTP transport during concurrent packfile URI and dumb HTTP downloads. The patch is a **substantive bugfix** targeting the core issue: when multiple Git processes fetch the same packfile into a single object database, they can corrupt the temporary pack file by appending duplicate data.

The solution switches the staging file from append mode (`O_APPEND`) to read-write mode (`O_RDWR`) without append, using deterministic staging paths and per-descriptor offsets. This ensures overlapping responses write identical bytes at identical offsets, preserving resumable downloads while preventing corruption. The patch handles edge cases like MinGW’s non-append `O_RDWR` open behavior (which grants `FILE_SHARE_DELETE` only for existing files) and concurrent unlink scenarios, including Windows sharing semantics. It also updates error handling to accept HTTP 416 ("Requested Range Not Satisfiable") when a partial pack is already complete, letting `index-pack` validate the contents.

The implementation touches `http.c`, `http-fetch.c`, `http-push.c`, and `http-walker.c`, with no new symbols introduced. The most significant changes are in `http.c`, where the staging file logic is refactored to use `lseek()` and `pwrite()`-style semantics. The patch includes extensive test coverage in `t/t5550-http-fetch-dumb.sh`, exercising resumed transfers, EOF ranges, overlapping 200/206 responses, unlinking the staging path while indexing, and a deterministic overlapping-download test using a custom Perl server with a 60-second timeout and FIFO waiter notification. The tests now pass 240 runs with 12 parallel `--stress` jobs, confirming the fix for the intermittent failure in test 34 that blocked earlier versions.

The series has been through multiple iterations, with this patch unchanged since v3. Earlier versions faced skepticism from Junio C Hamano about abandoning resumable downloads for packfile URIs and a test hang in `t5550-http-fetch-dumb.sh`, both resolved in v4. Jeff King (Peff) initially reported a false positive in `--stress` testing, which was addressed by dropping the `test -s` check and HTTP 200/206 trace greps. The patch is now rebased onto current `master` and ready for `next`. The changes are narrowly scoped to the packfile URI and dumb HTTP download paths, with no impact on other HTTP fetch behaviors or on-disk formats. The fix is well-motivated, thoroughly tested, and addresses a real-world race condition that could corrupt repositories during concurrent fetches.
