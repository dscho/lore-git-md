This patch adds Trace2 instrumentation to the packfile URI download process in `git fetch-pack`. When a protocol v2 fetch includes packfile URIs, the client downloads each advertised pack via a separate `http-fetch` process. The patch wraps this download loop in a Trace2 region, records the number of URIs advertised, and extends an existing test to verify the new telemetry.

The change touches `fetch-pack.c` and `t/t5702-protocol-v2.sh`. In `fetch-pack.c`, it adds a `trace2_region_enter`/`trace2_region_leave` pair around the URI download loop and emits a `trace2_data_intmax` event with the URI count. The test extension checks for the new region events and the URI count in the Trace2 output.

This is a small but useful observability improvement for protocol v2 fetches. It makes the cost of downloading external packs visible in Trace2 telemetry without spamming the logs with per-pack events. The patch is narrowly scoped, well-tested, and unlikely to be controversial. The commit message clearly explains the motivation and implementation.
