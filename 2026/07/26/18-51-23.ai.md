This is a refactoring patch in the `diff.<driver>.process` RFC series (v6, 4/9). It separates the subprocess lifecycle management (starting, handshaking, stopping) from the hashmap operations that index running processes by command string. The change is purely internal: `subprocess_start_command()` and `subprocess_stop_command()` are extracted so that callers like the diff-process driver can manage their own process lifetime via their data structures (e.g., `userdiff_driver`) without redundant hashmap lookups. The original `subprocess_start()` and `subprocess_stop()` remain as thin wrappers for backward compatibility.

The patch touches only `sub-process.c` and `sub-process.h`, adding 23 lines and removing 6. The new functions are straightforward: `subprocess_start_command()` handles process setup and handshake, while `subprocess_stop_command()` handles teardown. The hashmap-specific logic stays in the original wrappers. This refactoring was requested in earlier review rounds to avoid forcing the diff-process driver to maintain a parallel hashmap when it already tracks its subprocess via the `userdiff_driver` struct.

The change is well-motivated and cleanly executed. It introduces no behavior changes and is a prerequisite for the diff-process driver's subprocess integration in later patches. The commit message clearly explains the motivation and the split. This patch is uncontroversial and ready for merging as part of the series.
