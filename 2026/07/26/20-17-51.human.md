This is the second patch in a two-patch bugfix series for `git mv`, now at its fourth iteration (v4). The patch addresses a long-standing issue where `git mv` either misreports errors or silently corrupts the repository when the destination path contains missing directories, non-directory components, or tracked symlinks. This version resolves the last technical dispute by rejecting *all* tracked symlinks in the destination path, regardless of their target, using `has_symlink_leading_path()`—a change Junio explicitly required to align with `git apply`’s behavior.

The patch adds an early check in `builtin/mv.c` that catches three problematic cases before `rename(2)` is called: missing leading directories (ENOENT/ENOTDIR), non-directory components, and any tracked symlink in the path. The symlink check is the most consequential change—it prevents a subtle index corruption bug where moving a file through a symlink would leave the index recording the literal symlink path while the file was moved to the resolved target. The new logic also enables `--dry-run` to detect missing directories, which was previously impossible.

Test coverage is thorough: 83 new lines in `t/t7001-mv.sh` cover symlinks as both final and intermediate components, missing directories, non-directory path components, `--dry-run` detection, and force-flag behavior. The tests include a regression check for the index corruption scenario, ensuring the fix is robust. Two new translatable error messages are introduced: one for missing directories and another for symlink-related rejections.

The only acknowledged loose end is a TOCTOU race (the destination could disappear between the check and `rename(2)`), but the commit message notes this is "the best we can do" for now. The patch is well-motivated, clearly explained, and addresses all prior review feedback. With Junio’s approval of the first patch and the symlink-handling dispute resolved, this series looks ready for integration. If you care about `git mv`’s reliability or have encountered confusing error messages, this fix is worth reviewing.
