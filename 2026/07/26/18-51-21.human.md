This is the second patch in the nine-part `diff.<driver>.process` RFC series (v6), which introduces a long-running subprocess protocol for external tools to inject diff hunks into Git's diff and blame pipelines. This patch specifically adds support in the xdiff layer for accepting pre-computed hunks via new `xpparam_t` fields (`external_hunks` and `external_hunks_nr`). When these fields are set, `xdl_diff()` populates the changed arrays from the supplied hunks instead of running the builtin diff algorithm, then continues through compaction and emission as usual.

The implementation includes thorough validation of the supplied hunks: it checks for out-of-bounds line numbers, overlapping or out-of-order hunks, and misaligned unchanged runs between hunks (which must match lengths on both sides to maintain lockstep alignment during `xdl_build_script()`). On validation failure, it warns and falls back to the builtin diff algorithm for that file. The patch also skips `trim_common_tail()` when external hunks are present, since those hunks reference line numbers in the original content. Non-negative counts and 1-based starts are treated as caller preconditions (enforced with `BUG()`), as the caller is expected to normalize hunks before this point.

The changes are minimal and focused: 115 lines across five files, introducing the `xdl_hunk` struct, the new `xpparam_t` fields, and the `xdl_populate_hunks_from_external()` helper. The patch is well-motivated by the series' goal of enabling structural/AST-based diffs while preserving downstream features like word-diff, color-moved, and function context. The validation logic is particularly robust, ensuring that malformed tool responses degrade gracefully rather than causing crashes or incorrect diffs. This patch is a critical enabler for the rest of the series, which wires up the protocol and integrates it with Git's diff, blame, and range-tracking operations.
