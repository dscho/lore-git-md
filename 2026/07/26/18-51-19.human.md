This is the sixth revision of the `diff.<driver>.process` RFC series, a feature that lets external tools inject diff hunks into Git’s diff and blame pipelines while preserving all downstream formatting (word diff, function context, color-moved, etc.). The series is now rebased onto the in-flight `mm/line-log-limited-ops` topic to resolve a merge conflict in `line-log.c`.

The core idea remains unchanged: a long-running subprocess protocol (pkt-line over stdin/stdout) that sends both file versions and receives changed line ranges. Git validates the hunks, feeds them into xdiff, and treats zero-hunk responses as “no changes,” which propagates through patch output, `--stat`, blame, and `git log -L`. The protocol now carries blob object names (old-oid/new-oid) so tools can cache their analysis by blob pair.

This revision makes one functional change: `builtin_diffstat()` now routes the tool’s hunks through the same line-range filter that the builtin stat uses when `-L` is active. This ensures “`git log -L<range> --stat`” counts only the tool’s changed lines within the tracked range, matching the behavior of the builtin diff. The test suite adds a 30-line case that verifies this scoping: a tool that reports only one of two changed regions produces a stat count of 2/2 instead of the builtin’s 4/4.

All other patches are unchanged from v5 except for the rebase adjustments in patch 9 (`line-log.c`). The series is now technically complete, with no open objections from Junio or other reviewers. The only remaining work is final documentation polish, which should not block merging. The implementation demonstrates robust error handling, graceful fallbacks, and careful attention to backward compatibility.
