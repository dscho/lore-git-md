This is a CI/build system patch, the first in a two-patch series from Jeff King. It refactors a small section of `bloom.c` to silence a false positive from Coccinelle’s `CHECK_ASSERTION_SIDE_EFFECTS` rule when compiled with GCC 15.

The change replaces an `assert(version == 1 || version == 2)` with an explicit `if/else` cascade that ends in a `BUG()` call. The new version is functionally identical but avoids the assertion macro’s side-effect detection logic, which GCC 15 misinterprets as having side effects in the comparison. Jeff notes that the false positive only appears under `-O2` with GCC 15; clang and `-flto` builds do not trigger it. The patch also improves readability by removing the redundant version check and making the control flow more linear.

The motivation is twofold: to prevent confusion for developers running Coccinelle locally with newer compilers, and to enable the upcoming CI image upgrade (patch 2/2) that will use Ubuntu 24.04 and its newer toolchain. No behavior change to Git itself is introduced, and the patch is self-contained to `bloom.c`. Elijah Newren, the original author of the bloom filter code, is cc’d but has not yet responded.
