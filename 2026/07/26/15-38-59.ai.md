This is the first patch in Phillip Wood’s v2 bugfix series for interactive rebase edge cases. It fixes an incorrect commit count in the squash/fixup template message when a preceding fixup or squash command is skipped during `rebase --skip`.

The patch addresses a subtle bug in how the sequencer tracks executed commands. The command list file uses a newline-before-each-command convention (except the first), and skipping a command previously left an orphaned newline, causing the count to be off by one. The fix removes the newline when popping a skipped command and makes the reading logic skip blank lines for version compatibility. The v2 tightens the reading logic further by guarding against trailing NUL bytes (`p[1] && p[1] != '\n'`), addressing Junio’s review concern from v1.

The patch touches `sequencer.c` and extends `t/t3418-rebase-continue.sh` with 36 lines of new test coverage, including scenarios with multiple skipped commands. The changes are backward-compatible with existing rebase state files and ensure correct behavior when users switch Git versions mid-rebase (e.g., between CLI and IDE). The consequence of the bug is minor—only an incorrect count in the commit message template—but the fix is surgical and well-motivated.
