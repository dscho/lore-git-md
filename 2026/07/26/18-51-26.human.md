This is the seventh patch in the nine-patch `diff.<driver>.process` RFC series (v6), which enables external tools to inject diff hunks into Git's diff and blame pipelines. This patch wires `git blame` to consult the external diff process when configured, allowing blame to skip commits where the tool reports no semantic changes (e.g., reformatting-only commits).

The patch introduces `xdi_diff_process()`, a shared helper in `diff-process.c` that consults the external tool, runs xdiff on the tool's hunks (or falls back to the builtin diff if the tool doesn't apply), and returns `DIFF_PROCESS_EQUIVALENT` when the tool reports no changes. This helper is reused by both `git blame` (here) and `git log -L` (in a later patch). The blame integration modifies `pass_blame_to_parent()` to call this helper, skipping commits when the tool reports equivalence. The subprocess is long-running (amortizing startup cost across the blame traversal), but each commit incurs a round-trip to the tool.

Key details:
- **Bypass mechanisms**: Blame's `-w` (ignore whitespace) option bypasses the process entirely, as the tool cannot honor it. The bypass keys off `xpp.flags` (the flags the diff actually runs with), covering blame without a separate guard.
- **Driver resolution**: The driver is looked up by the parent (old) path, matching `builtin_diff()`'s behavior, ensuring consistent driver selection across diff, blame, and line-log.
- **Blob object names**: Omitted in the protocol for blame (each blob pair is diffed only once, so the tool gains nothing from a per-invocation cache key).
- **Test coverage**: Adds 126 lines to `t/t4080-diff-process.sh`, exercising tool-provided hunks, commit skipping, and bypass behaviors (`--no-ext-diff`, `-w`).

The patch is well-motivated and technically sound, addressing a core goal of the series: making every "which lines changed" operation consult the external tool. The shared `xdi_diff_process()` helper avoids code duplication, and the test coverage is thorough. The only limitation is the ~17% performance overhead in blame operations, which the author notes could be optimized with OID-based caching in the future. This is a substantive, ready-to-merge patch that completes the blame integration for the series.
