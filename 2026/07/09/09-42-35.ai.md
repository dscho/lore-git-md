This is the eighth patch in Johannes Schindelin’s eleven-patch bugfix series (`js/coverity-fixes-v2`) addressing NULL-dereference issues identified by Coverity. It targets the `add_parents_only()` function in `revision.c`, which resolves revision suffixes like `commit^@` (all parents) and `commit^!` (commit minus parents).

The patch fixes a subtle edge case where `get_reference()` can return NULL for reasons other than `ignore_missing`—specifically when `exclude_promisor_objects` or `do_not_die_on_missing_objects` is set. Previously, the code only checked for `ignore_missing`, leaving the other two cases to dereference NULL. The fix adds explicit handling for all three NULL-return scenarios: returning `0` for `ignore_missing` and `do_not_die_on_missing_objects` (consistent with existing patterns in `handle_revision_arg()` and `process_parents()`), and `-1` for the `exclude_promisor_objects` case.

The change is narrow and defensive, with no new behavior introduced beyond preventing crashes. The commit message explains the rationale clearly, including the pre-existing limitation in the caller’s return-value handling (where `-1` is treated as success for `commit^@`/`commit^!` pseudo-options). This aligns with the series’ goal of eliminating NULL-dereference vulnerabilities without altering normal operation. Like the rest of the series, this patch is uncontroversial and well-motivated, with no new tests added (existing coverage suffices). The function is part of Git’s revision-walking plumbing, so the fix affects a core subsystem.
