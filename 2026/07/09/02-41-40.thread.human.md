This thread is about a patch series (v7) by Chen Linxuan that adds `includeIf worktree:<pattern>` support to Git’s config system, allowing conditional config inclusion based on the working tree’s path. The feature is designed for multi-worktree setups where the `.git` directory’s location isn’t intuitive, and it reuses existing path-matching logic while preserving symlinks.

The series is under active review, with no prior versions merged or cooking in integration branches. The current version (v7) addresses earlier feedback from Patrick Steinhardt and Junio C Hamano on symlink handling and test coverage. It consists of three patches: a preparatory refactoring, the core implementation, and tests/documentation.

Patrick Steinhardt’s latest review raises two design concerns about the second patch. First, he questions the need for an accessor function (`repo_get_worktree_original()`), suggesting direct field access would be simpler. More critically, he flags the complexity of the symlink-preserving path reconstruction logic (`logical_path_from_cwd()`), calling it "awkward" and noting it conflicts with his in-flight `ps/setup-split-discovery-and-setup` series. He proposes either removing the `chdir()` call during repository discovery (a larger change) or documenting the limitation for now. The review doesn’t reject the feature but highlights a tension between correctness and maintainability. The author will need to decide how to address this—whether to refactor the logic, document the limitation, or coordinate with Patrick’s series.

No other reviews or objections have been recorded, and the series is otherwise considered technically complete. The open question is how to resolve the symlink-handling complexity without disrupting Patrick’s upcoming work.
