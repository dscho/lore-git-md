This thread is about a patch series by Chen Linxuan that adds `includeIf worktree:<pattern>` and `worktree/i:<pattern>` conditions to Git’s configuration system, allowing users to include config files based on the working tree’s path. This is particularly useful in multi-worktree setups where the `.git` directory’s location isn’t intuitive.

The series is now at version 8, which simplifies the implementation by removing the symlink-preserving worktree path logic. This change addresses feedback from Patrick Steinhardt, who raised concerns about the complexity and potential conflicts with his in-flight `ps/setup-split-discovery-and-setup` series. The current version also resolves a test failure (`t1305`) that appeared when the series was merged into Junio’s `seen` integration branch. The core functionality remains intact: users can still conditionally include config files using glob patterns, `~` expansion, and case-insensitive matching via `worktree/i:`. The documentation now notes that symlink spellings may not match, as the condition resolves to the real path.

The series consists of two patches: one refactoring the existing `include_by_gitdir()` helper into `include_by_path()`, and the other implementing the new `worktree:` and `worktree/i:` keywords. It includes thorough test coverage for bare repositories, early config reading, and non-repository scenarios. The author has been responsive to feedback, and the series appears ready for integration, assuming no new objections arise. The trade-off of documenting the symlink limitation is a pragmatic compromise to avoid blocking on Patrick’s larger refactoring effort.
