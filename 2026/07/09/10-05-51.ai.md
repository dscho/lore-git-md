This is a **surface-level usability discussion** about the `--no-deref` option in the now-merged `git refs create` subcommand. Toon Claes revisits his earlier feedback, proposing to **eliminate `--no-deref` entirely** and instead direct users to `git ref` (for dereferenced operations) or `git symbolic-ref` (for symref-specific operations). His suggestion stems from frustration with the option’s obscurity and the cognitive overhead of remembering its behavior: `--no-deref` does not enable symref creation but instead fails if the target exists as a symref, a distinction he argues is unintuitive and poorly documented.

The proposal is framed as a **simplification** rather than a technical fix, with Toon explicitly acknowledging uncertainty about how to improve the current design. His alternative—splitting functionality between `git ref` (for dereferenced operations) and `git symbolic-ref` (for symref manipulation)—would avoid the need for a `--no-deref` flag altogether, but it would also fragment the unified `git refs` interface introduced by the series. No code changes are proposed or expected, as the series is already merged, but the feedback underscores lingering usability concerns that could inform future documentation or CLI refinements. Key files/subsystems: `builtin/refs.c` and `Documentation/git-refs.adoc`.
