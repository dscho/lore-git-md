Thread identity: twelve-patch bugfix series (`js/coverity-fixes-v2`) by Johannes Schindelin (Dscho) via GitGitGadget, targeting NULL-dereference issues identified by Coverity. Thread type: patch series (bugfix).

Core problem or goal: eliminate NULL-dereference vulnerabilities in eleven files across diff, remote, reftable, mailsplit, bisect, replay, revision, pack-bitmap, and shallow subsystems, plus address a latent bug in `write_one_shallow()` related to `oid_to_hex()`'s rotating static buffer. Each patch adds a guard or early check to prevent dereferencing NULL pointers or using invalid file descriptors, addressing edge cases such as commits with unset `maybe_tree`, non-obvious NULL `remote` in `remote_tracking()`, partial initialization failures in reftable stack creation, `fopen()` failures in `mailsplit`, NULL commits in bisect functions due to concurrent gc or repository corruption, NULL returns from `peel_committish()` in `git replay --onto`, NULL returns from `get_reference()` in `revision.c`, missing base MIDX bitmaps in incremental MIDX chains, shallow graft entries referencing missing commit objects, and the latent `oid_to_hex()` bug. The final patch (12/12) fixes the latent `oid_to_hex()` bug by replacing the static buffer with a stack-allocated buffer and `oid_to_hex_r()`.

- Symbols: guards added in functions already named in commit messages; no new public symbols. Specific guards:
  - In `diffcore_merge_broken()` (`diffcore-break.c`), `if (!pp) continue` mirrors existing pattern in outer loop, preventing dereference of NULL `pp->one` or `pp->two` in the inner loop.
  - In `cmd_diff()` (`diff.c`), `repo_get_commit_tree()` return value checked for NULL before dereferencing; if NULL, `die()` is called with a descriptive error message.
  - In `stack_destroy()` (`reftable/stack.c`), NULL check (`if (st->list_file)`) added before calling `read_lines()` to prevent passing NULL filename to `open()`.
  - In `remote_tracking()` (`remote.c`), `BUG()` is now called if `remote` is NULL, treating it as a contract violation.
  - In `split_mbox()` (`mailsplit.c`), NULL check for file handle `f` moved before the `fileno(f)` call to prevent undefined behavior.
  - In `bisect_successful()` (`bisect.c`), NULL check added for the commit returned by `lookup_commit_reference_by_name()`; if NULL, returns `BISECT_FAILED`.
  - In `bisect_start()` (`bisect.c`), uses `"HEAD"` as a fallback for the `head` variable after the `if (!head)` check.
  - In `cmd_replay()` (`replay.c`), NULL check added after `peel_committish()` call in the `--onto` code path; if the object does not peel to a commit, `die()` is called.
  - In `add_parents_only()` (`revision.c`), explicit handling added for all three NULL-return scenarios from `get_reference()`: `ignore_missing`, `do_not_die_on_missing_objects`, and `exclude_promisor_objects`. Includes a regression test (`t/t0410-partial-clone.sh`).
  - In `load_midx_bitmap()` (`pack-bitmap.c`), NULL check added after `prepare_midx_bitmap_git()` call when loading the base MIDX bitmap in an incremental MIDX chain.
  - In `write_one_shallow()` (`shallow.c`), two latent bugs addressed: (1) uses a stack-allocated buffer (`hex[GIT_MAX_HEXSZ + 1]`) and `oid_to_hex_r()` to avoid clobbering the `hex` variable, and (2) uses the graft entry’s OID (`graft->oid`) instead of the commit object’s OID when `lookup_commit()` returns NULL.
- Behavior: purely defensive; no new user-visible behavior beyond error messages for edge cases.
- On-disk format: unchanged.
- Test coverage: the eighth patch (revision.c) includes a regression test (`t/t0410-partial-clone.sh`). Existing tests verify guards do not break normal operation.
