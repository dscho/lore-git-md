Thread identity: twelve-patch bugfix series (`js/coverity-fixes-v2`) by Johannes Schindelin (Dscho) via GitGitGadget, targeting NULL-dereference issues identified by Coverity. Thread type: patch series (bugfix).

Core problem or goal: eliminate NULL-dereference vulnerabilities in eleven files across diff, remote, reftable, mailsplit, bisect, replay, revision, pack-bitmap, and shallow subsystems, plus address a latent bug in `write_one_shallow()` related to `oid_to_hex()`'s rotating static buffer. Each patch adds a guard or early check to prevent dereferencing NULL pointers or using invalid file descriptors, addressing edge cases such as commits with unset `maybe_tree`, non-obvious NULL `remote` in `remote_tracking()`, partial initialization failures in reftable stack creation, `fopen()` failures in `mailsplit`, NULL commits in bisect functions due to concurrent gc or repository corruption, NULL returns from `peel_committish()` in `git replay --onto`, NULL returns from `get_reference()` in `revision.c`, missing base MIDX bitmaps in incremental MIDX chains, shallow graft entries referencing missing commit objects, and the latent `oid_to_hex()` bug. The final patch (12/12) fixes the latent `oid_to_hex()` bug by replacing the static buffer with a stack-allocated buffer and `oid_to_hex_r()`.

The tenth patch (replay.c) adds a NULL check after `peel_committish()` in the `--onto` code path; if the object does not peel to a commit, `die()` is called with a descriptive error message. The eleventh patch (bisect.c, `bisect_start()`) assigns the literal string `"HEAD"` as a safe fallback for the `head` variable after the `if (!head)` check, satisfying Coverity’s static analysis without altering behavior in any reachable code path. The twelfth patch (shallow.c) now also addresses a latent crash in `write_one_shallow()` when a shallow graft entry references a missing commit object by using the graft entry’s OID (`graft->oid`) instead of the commit object’s OID for the log message, preventing a dereference of NULL `c->object.oid`.

Key technical details:
- Files touched: diffcore-break.c, diff.c, remote.c, reftable/merged.c, reftable/stack.c, mailsplit.c, bisect.c (two patches), replay.c, revision.c, pack-bitmap.c, shallow.c.
- Symbols: guards added in functions already named in commit messages; no new public symbols. Specific guards:
  - In `diffcore_merge_broken()` (`diffcore-break.c`), `if (!pp) continue` mirrors existing pattern in outer loop, preventing dereference of NULL `pp->one` or `pp->two` in the inner loop. The edge case requires at least two broken pairs whose peers survive rename/copy detection and appear later in the queue.
  - In `cmd_diff()` (`diff.c`), `repo_get_commit_tree()` return value checked for NULL before dereferencing; if NULL, `die()` is called with a descriptive error message ("unable to read tree object for commit '%s'"). This addresses the edge case where a commit was parsed but its `maybe_tree` field is unset (e.g., not in the commit-graph).
  - In `stack_destroy()` (`reftable/stack.c`), NULL check (`if (st->list_file)`) added before calling `read_lines()` to prevent passing NULL filename to `open()` when `reftable_new_stack()` fails partway through initialization (e.g., due to OOM).
  - In `remote_tracking()` (`remote.c`), `BUG()` is now called if `remote` is NULL, treating it as a contract violation. The commit message explains that while the only caller (`apply_cas()`) already guards against this edge case, the reasoning is non-obvious and fragile; the fix makes the contract explicit.
  - In `split_mbox()` (`mailsplit.c`), NULL check for file handle `f` (returned by `fopen()`) moved before the `fileno(f)` call to prevent undefined behavior when the file cannot be opened.
  - In `bisect_successful()` (`bisect.c`), NULL check added for the commit returned by `lookup_commit_reference_by_name()`; if NULL, the function returns `BISECT_FAILED` (the symbolic constant) instead of propagating the error code `-1` from `error()`. This addresses Junio’s maintainability feedback from the v1 review.
  - In `bisect_start()` (`bisect.c`), the leftover use of `head` after `if (!head)` is addressed by using `"HEAD"` as a fallback, satisfying Coverity without changing behavior in reachable code paths.
  - In `cmd_replay()` (`replay.c`), NULL check added after `peel_committish()` call in the `--onto` code path; if the object does not peel to a commit, `die()` is called with a descriptive error message ("object %s is not a commit").
  - In `add_parents_only()` (`revision.c`), explicit handling added for all three NULL-return scenarios from `get_reference()`: `ignore_missing`, `do_not_die_on_missing_objects`, and `exclude_promisor_objects`. The first two cases return 0 (consistent with existing patterns in `handle_revision_arg()` and `process_parents()`), while the third returns -1, matching the caller’s expectation that any nonzero return is treated as “handled.” The patch also adds a regression test (`t/t0410-partial-clone.sh`) that verifies graceful handling of `commit^@` when the underlying commits are missing promisor objects.
  - In `load_midx_bitmap()` (`pack-bitmap.c`), NULL check added after `prepare_midx_bitmap_git()` call when loading the base MIDX bitmap in an incremental MIDX chain, falling back to non-bitmap object enumeration if the base bitmap is missing. The edge case is realistic—base MIDX bitmaps can be missing due to pruning or being written without `--write-bitmap-index`—and the fix is defensive without altering normal operation.
  - In `write_one_shallow()` (`shallow.c`), two latent bugs are addressed: (1) the verbose logging code now uses a stack-allocated buffer (`hex[GIT_MAX_HEXSZ + 1]`) and `oid_to_hex_r()` to avoid clobbering the `hex` variable due to `oid_to_hex()`'s rotating static buffer, and (2) the log message now uses the graft entry’s OID (`graft->oid`) instead of the commit object’s OID when `lookup_commit()` returns NULL, preventing a dereference of NULL `c->object.oid`.
- Behavior: purely defensive; no new user-visible behavior beyond error messages for edge cases; rare edge cases addressed without altering normal operation.
- On-disk format: unchanged.
- Test coverage: the eighth patch (revision.c) includes a regression test (`t/t0410-partial-clone.sh`). Existing tests expected to verify guards do not break normal operation.
