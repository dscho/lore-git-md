This thread is a bugfix series from Johannes Schindelin (Dscho) addressing NULL-dereference vulnerabilities identified by Coverity across eleven Git subsystems. The series, now at its tenth patch, remains under review with no maintainer decision yet.

The latest patch fixes a crash in the bisect subsystem when `refs_resolve_ref_unsafe()` returns NULL (e.g., in a detached bare-OID state with the reftable backend) but `repo_get_oid("HEAD")` succeeds. The fix ensures `head` is never NULL by falling back to the string literal `"HEAD"` after confirming the OID is valid, preventing a dereference in later code paths. Like the rest of the series, this is a minimal, defensive change with no new user-visible behavior or test coverage—just a guard against a rare but plausible edge case.

The series as a whole touches diff, remote, reftable, mailsplit, bisect, replay, revision, pack-bitmap, shallow, and diffcore-break subsystems, adding early checks or guards to prevent crashes. No objections or open questions have been raised so far, and the patches are uncontroversial, focusing solely on hardening Git against NULL-dereference risks. The prior version (`js/coverity-fixes`) was merged, and this iteration continues that work.
