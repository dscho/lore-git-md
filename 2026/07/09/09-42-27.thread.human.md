This thread is a twelve-patch bugfix series (`js/coverity-fixes-v2`) by Johannes Schindelin (Dscho) addressing NULL-dereference vulnerabilities identified by Coverity across eleven files in Git’s codebase. The series targets edge cases in diff, remote, reftable, mailsplit, bisect, replay, revision, pack-bitmap, and shallow subsystems, plus a latent bug in `oid_to_hex()`’s static buffer handling. All patches add defensive guards or early checks to prevent crashes or undefined behavior.

The series is now in its second iteration (`v2`), incorporating all feedback from Junio C Hamano’s reviews of `v1`. The first seven patches (covering diffcore-break.c, diff.c, reftable/stack.c, remote.c, mailsplit.c, bisect.c’s `bisect_successful()`, and pack-bitmap.c) were previously approved by Junio. Key changes in `v2` include: using `BUG()` for NULL `remote` in `remote_tracking()` (addressing Junio’s feedback that this is a contract violation), returning `BISECT_FAILED` instead of `-1` in `bisect_successful()` for maintainability, adding a regression test for `revision.c` (`t/t0410-partial-clone.sh`), and fixing the latent `oid_to_hex()` bug with a stack-allocated buffer. The ninth patch (pack-bitmap.c), just summarized, adds a NULL check in `load_midx_bitmap()` for missing base MIDX bitmaps, following the established error-handling pattern in the bitmap code.

The series is uncontroversial and ready for integration. No open questions remain, and all feedback has been addressed. Junio’s reviews have been thorough but surface-level for some patches (e.g., "obviously correct"), while others (like the `remote.c` and `bisect.c` changes) prompted deeper discussion. Taylor Blau was CC’d for incremental MIDX expertise but has not reviewed the series. The fixes are purely defensive, with no user-visible behavior changes beyond clearer error messages for edge cases. The on-disk format remains unchanged, and existing tests should verify the guards don’t break normal operation.
