This is the first patch in a refactoring series targeting the ongoing `the_repository` removal effort. It addresses a subtle but real bug in the packed-refs backend: the `core.packedRefsTimeout` configuration is currently stored in function-static variables, meaning only the first repository's setting is ever used. The patch moves these variables into `struct packed_ref_store`, allowing per-repository timeout values.

The change is small (17 lines, 1 file) but technically sound. It fixes a latent issue where multiple repositories with different timeout settings would incorrectly share the same value. The commit message clearly explains the problem and solution, and the implementation is straightforward: the static variables become struct fields, and the config lookup now uses the repository pointer from the ref store.

This patch is a good example of the incremental progress in the `the_repository` removal effort. It doesn't yet eliminate `the_repository` from this code path (that happens in later patches), but it prepares the ground by making the configuration repository-specific. The fix is well-motivated and unlikely to be controversial.

Key technical details for follow-up discussion:
- File: `refs/packed-backend.c`
- New struct fields: `timeout_configured` (bool), `timeout_value` (int)
- Modified function: `packed_refs_lock()`
- Config key: `core.packedRefsTimeout`
- The patch maintains the existing default timeout (1000ms) when the config is unset.
