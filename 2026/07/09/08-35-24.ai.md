This is the fourth patch in Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch restructures how Git opens bitmaps by iterating over object sources first, then attempting to load a bitmap for each source. This refactoring enables future work where bitmaps for specific sources can be opened individually, a requirement for later patches in the series.

The change modifies `pack-bitmap.c` to reverse the loop order: previously, Git first searched all sources for a multi-pack index bitmap, then all sources for a packfile bitmap. Now, it iterates over each source and tries both bitmap types for that source before moving to the next. This alters bitmap precedence in edge cases where multiple sources have bitmaps—now, local bitmaps (from earlier sources) take precedence over multi-pack index bitmaps in alternates, which the commit message argues is an improvement.

The patch is a refactoring with no user-visible behavior change, but it lays groundwork for the next patch in the series. The code is clean and the commit message clearly explains the motivation and edge-case implications. Reviewers focused on ODB backends or bitmap performance may want to verify the new precedence logic, but the change itself looks uncontroversial and well-justified.
