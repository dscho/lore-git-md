This is the fifth patch in Johannes Schindelin’s eleven-patch bugfix series (`js/coverity-fixes-v2`) addressing NULL-dereference issues identified by Coverity. This patch targets `builtin/mailsplit.c`, a utility used to split mailbox files into individual messages for `git am`.

The issue is straightforward: `split_mbox()` calls `fileno(f)` to check if the input is a terminal, but the NULL check for `f` (returned by `fopen()`) happens *after* this call. If `fopen()` fails and returns NULL, `fileno(NULL)` invokes undefined behavior—typically a segmentation fault. The fix moves the NULL check before the first use of `f`, ensuring the error path is taken safely.

The change is minimal—just three lines reordered—and preserves all existing behavior. No new tests are added, but the fix is narrow enough that existing test coverage should suffice to verify it doesn’t break normal operation. Given the series’ focus on defensive programming and Dscho’s track record, this patch looks like a clear, uncontroversial fix.
