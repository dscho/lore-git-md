This is the first patch in the v2 series fixing the reftable backend's quadratic performance regression with tombstones. It introduces a new perf test (`t/perf/p1401-ref-store-tombstones.sh`) that measures two pathological scenarios: recreating the same refs after deletion (quadratic behavior) and creating new, differently-named refs after deletion (worst-case tombstone sorting). The test uses fresh repositories for each scenario to ensure clean tombstone state, addressing prior feedback about measurement isolation.

The test exercises the regression by creating 8,000 refs, deleting them (leaving tombstones), and then either recreating the same refs or creating new ones with names that sort after the tombstones. The second scenario is particularly severe because the merged iterator must scan all tombstones before reaching the new refs. The test is narrowly scoped to the reftable backend and does not touch other ref backends.

This patch is purely infrastructure for the series; the actual fix is in the second patch. The test is well-structured, with clear setup and teardown, and directly targets the performance issue described in the cover letter. No new symbols or APIs are introduced. The test's design reflects the author's response to reviewer feedback, particularly Patrick Steinhardt's concern about test isolation.
