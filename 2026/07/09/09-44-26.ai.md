This is a **surface-level review** of the `git refs delete` subcommand in Patrick Steinhardt’s merged `git refs` series. Toon Claes questions the behavior of `--no-deref` when deleting symbolic references (symrefs), specifically whether it should verify the symref’s *target reference name* (e.g., `refs/heads/foo`) rather than its *target OID* (e.g., `$A`).

The review highlights a potential usability issue: the current implementation checks the OID of the symref’s target (dereferenced value), while Toon’s proposed alternative would check the *name* of the target reference. For example, if `refs/heads/symref` points to `refs/heads/foo`, the current code verifies the OID of `refs/heads/foo`, whereas Toon’s suggestion would verify that the symref points to `refs/heads/foo` (regardless of its OID). The proposed test case demonstrates this difference by using `refs/heads/bar` (a nonexistent reference) as the expected target.

This feedback is **not a technical flaw**—the current behavior is consistent with `git update-ref -d` and the rest of the `git refs` subcommands—but it does raise a question about whether the semantics are intuitive for users. The series is already merged, so this is unlikely to result in code changes, but it may inform future documentation or usability improvements. The discussion is narrowly scoped to this edge case and does not challenge the broader design of the series.
