This thread is a bug report from Ondřej Medek about confusing and inconsistent behavior in `git fetch`'s automatic tag fetching. The core issue is that `git fetch` only fetches tags pointing to fetched histories when at least one refspec in the command includes a destination (`:dst`) part—even if that refspec is unrelated to the branch being fetched. For example, `git fetch origin master` skips tags, but `git fetch origin refs/heads/master:refs/remotes/origin/master` or even `git fetch origin master refs/none/*:refs/none/*` will fetch them. This behavior contradicts the documentation, which states that tags are fetched "by default," and has left users puzzled.

The report is thorough, with clear reproduction steps and a focus on the technical detail that the `:dst` part acts as a global toggle for tag fetching across all refspecs in the command. Ondřej suggests either documenting this quirk (if it’s intentional) or fixing it (if it’s a bug). So far, there are no replies from maintainers or other contributors, so the thread is still open and awaiting input on whether this is a documentation gap or a genuine bug in need of a patch.
