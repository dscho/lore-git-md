This is the third patch in Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch enables early abortion of bitmapped object iteration by propagating non-zero return values from the `show_reach` callback through `for_each_bitmapped_object()` and its helper `show_objects_for_type()`.

The change is motivated by a latent bug: once bitmapped object iteration is lifted into the generic ODB infrastructure (in a later patch), callers of `odb_for_each_object()` will expect to be able to abort iteration by returning non-zero from their callback. Currently, `for_each_bitmapped_object()` ignores the callback’s return value and always iterates to completion. This patch fixes that by making `show_objects_for_type()` return an `int` and propagating any non-zero value up the call stack.

Two existing callbacks (`add_object_entry_from_bitmap` in `builtin/pack-objects.c` and `show_object_fast` in `builtin/rev-list.c`) were modified to always return `0` because they were only ever invoked via `traverse_bitmap_commit_list()`, which also ignored their return values. The patch also tidies up the iteration loop in `for_each_bitmapped_object()` by replacing four repetitive calls to `show_objects_for_type()` with a single loop over an array of object types.

The patch is clean, well-explained, and clearly a prerequisite for the later ODB integration. It touches only the bitmap subsystem and does not change on-disk formats or user-visible behavior. No test failures or edge cases are mentioned in the commit message, suggesting the change is mechanical and low-risk. This is a solid, uncontroversial step in the ODB abstraction series.
