This is the third patch in Johannes Schindelin’s eleven-patch bugfix series (`js/coverity-fixes-v2`) addressing NULL-dereference issues identified by Coverity. The series as a whole targets defensive programming gaps across multiple subsystems; this specific patch adds a NULL guard in `remote_tracking()` in `remote.c`.

The function `remote_tracking()` currently dereferences `remote->fetch` without checking whether `remote` itself is NULL. While the only caller (`apply_cas()`) already guards its calls behind `use_tracking` and `use_tracking_for_rest` checks, the reasoning required to confirm that `remote` is never NULL is non-obvious and fragile. The patch adds a simple early return (`return -1`) when `remote` is NULL, treating it as "no tracking ref available" rather than risking a crash.

The change is minimal—two lines added—and purely defensive. It does not alter any user-visible behavior or on-disk format, and the commit message clearly explains both the problem and the chosen fix. Given that the series is a follow-up to a previously merged set of Coverity fixes and that Dscho is the author, this patch looks uncontroversial and well-motivated. No new tests are included, but the existing test suite should suffice to verify that the guard does not break normal operation.
