This is the first patch in a refactoring series targeting the ongoing `the_repository` removal effort. It addresses a subtle but real bug in the packed-refs backend: the `core.packedRefsTimeout` configuration is currently stored in function-static variables, meaning only the first repository's setting is ever used. If Git were to handle multiple packed-refs stores (even theoretically), all would incorrectly share the same timeout value.

The fix moves the timeout configuration into `struct packed_ref_store`, making it per-store rather than global. The change is minimal—just 11 lines added to the struct and a few lines of logic to read the config per-store instead of once globally. The patch is well-motivated and clearly explained in the commit message, which explicitly calls out the "code smell" and the (admittedly unlikely) scenario where the bug could manifest.

This is a clean, mechanical refactoring that fits neatly into the larger `the_repository` removal effort. The patch itself is small and focused, touching only `refs/packed-backend.c`, and the rationale is sound. No new tests are needed since the change is purely internal and the existing test suite should catch any regressions. The patch looks ready for review and unlikely to be controversial.
