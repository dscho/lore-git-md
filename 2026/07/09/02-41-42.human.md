This is a refactoring patch that prepares the ground for a feature in the `includeIf` conditional configuration mechanism. It is the second patch in Chen Linxuan’s three-patch series (`[PATCH v7 2/3]`).

The patch adds a new field `worktree_original` to the `struct repository` and a corresponding accessor `repo_get_work_tree_original()`. While `repo->worktree` continues to hold the realpath-resolved (canonical) worktree path, `worktree_original` stores the original, symlink-preserving spelling that the user actually typed or followed. The motivation is that a follow-up patch will use this field to make `includeIf`’s `worktree:` condition match both the real and the symlinked spelling, just as the existing `gitdir:` condition already does.

The implementation is careful: `repo_set_worktree()` now derives both the canonical and the symlink-preserving path from the input, and for the “discovered repository” case (where the setup code has already `chdir()`’d to the worktree root) a helper function `logical_path_from_cwd()` recovers the original spelling from `$PWD` instead of falling back to the physical path. The patch also adds a small utility `same_entry()` that compares two paths by device and inode to ensure `$PWD` is still trustworthy.

No callers of the new accessor exist yet; they will appear in the next patch. The commit message is clear and the code is well-explained, with good test coverage implied by the edge-case handling. This looks like a solid, uncontroversial preparatory step.
