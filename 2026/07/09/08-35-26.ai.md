This is the sixth patch in Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. It adds a new `filter` field to the `odb_for_each_object_options` struct, allowing callers to pass an object filter that backends may use to optimize enumeration. The packed backend is updated to leverage this filter when a bitmap is available, using the previously introduced `prepare_bitmap_git_for_source()` to ensure bitmaps are only opened for the correct source.

The patch touches `odb.h`, `odb/source-packed.c`, `pack-bitmap.c`, and `pack-bitmap.h`. Key changes include making `can_filter_bitmap()` public, introducing a new callback (`bitmapped_for_each_object`) to handle filtered iteration, and modifying `odb_source_packed_for_each_object()` to skip packs already covered by a bitmap. The logic ensures objects are only yielded once and that filters are applied consistently, though callers must still re-apply the filter to returned objects for strict correctness.

This is a well-motivated refactoring that addresses a real inefficiency: without this change, `odb_for_each_object()` would redundantly traverse indices during enumeration, risking incorrect pack selection and degraded performance. The implementation is careful to avoid duplicates and misattribution, and the commit message clearly explains the trade-offs (e.g., backends may ignore the filter). The patch looks technically sound and aligns with the series’ goal of making `git cat-file --batch-all-objects` work with pluggable ODBs. No obvious loose ends or controversies are apparent.
