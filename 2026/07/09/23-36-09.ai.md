This is a feature patch introducing a new `post-worktree-add` hook. It is the first patch in a three-patch series (v1) by Domen Kožar, co-authored with an AI assistant.

The patch addresses a gap in Git's hook system: tools that manage per-worktree state (IDEs, development environment managers) currently have no reliable way to detect when a new worktree is created. The existing `post-checkout` hook is skipped when `--no-checkout` or `--orphan` is used, and cannot distinguish between a worktree addition and a regular checkout. The new hook runs unconditionally after `git worktree add` completes, regardless of checkout status, and receives the new worktree's absolute path and identifier as arguments.

Implementation is straightforward: the hook is invoked in the new worktree's directory with `GIT_DIR` and `GIT_WORK_TREE` cleared, matching the environment of `post-checkout`. It runs after `post-checkout` and is skipped if that hook fails. A failing `post-worktree-add` hook does not delete the worktree but propagates its exit status to the `git worktree add` command. The patch updates `builtin/worktree.c`, documents the hook in `githooks(5)`, and adds comprehensive tests in `t/t2400-worktree-add.sh` covering normal cases, `--no-checkout`, `--orphan`, bare repositories, relative paths, and hook failure scenarios.

The motivation is clear and the implementation appears thorough: the commit message explains the problem, the code is clean, and the test coverage is extensive. The hook's design mirrors existing hooks, so it should feel familiar to users. No controversy is evident from the patch itself.
