Subject: [PATCH 0/8] refs: remove more uses of `the_repository`
Series version: v2 (timeout fix applied; integration conflicts resolved)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Eliminate implicit uses of the global `the_repository` variable in the refs subsystem and worktree code, continuing the long-running effort to make repository handling explicit throughout Git. The series systematically replaces `the_repository` with explicit `struct repository *` parameters in function signatures and call sites across 25 files. A latent bug in the packed-refs backend is fixed en passant: the `core.packedRefsTimeout` configuration was previously stored in function-static variables, causing only the first repository's setting to be used; this is now per-repository via `struct packed_ref_store` fields.

Current status
Series is now in the `seen` and `jch` integration branches and expected to graduate to `master` in the next cycle. v2 posted 2026-05-22, rebased on the start of the Git 2.56 cycle (f85a7e6620) with `ps/refs-writing-subcommands` already merged. The behavioral regression in the packed-refs timeout initialization (zero-initialized `timeout_value` instead of the old 1000 ms default) is fixed: `timeout_value` is explicitly set to 1000 in `packed_ref_store_init()` when the config key is unset. Integration conflicts with the `seen` branch (two hunks: one in `lib/setup.c`, one in `lib/refs/files-backend.c`) were minimal and are documented in the cover letter; Junio has already resolved them. The final patch (8/8) completes the conversion by targeting the last remaining callsites in built-in commands and `refs.c`, updating `copy_branchname()` and `check_branch_ref()` function signatures to accept a repository parameter, adjusting all their callers (29 lines changed across 8 files), and removing the `USE_THE_REPOSITORY_VARIABLE` macro from `refs.c`. The worktree-related helper `has_worktrees()` is also updated to take a repository parameter, fixing a TODO comment that noted the previous inconsistency.

Open questions and loose ends
None. The behavioral regression in the packed-refs timeout initialization is fixed in v2, and the series is now mechanically complete.
