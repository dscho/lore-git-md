Thread identity
Subject: [PATCH 0/8] refs: remove more uses of `the_repository`
Series version: v2 (timeout fix applied; integration conflicts resolved)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Eliminate implicit uses of the global `the_repository` variable in the refs subsystem and worktree code, continuing the long-running effort to make repository handling explicit throughout Git. The series systematically replaces `the_repository` with explicit `struct repository *` parameters in function signatures and call sites across 25 files. A latent bug in the packed-refs backend is fixed en passant: the `core.packedRefsTimeout` configuration was previously stored in function-static variables, causing only the first repository's setting to be used; this is now per-repository via `struct packed_ref_store` fields.

Current status
Series is now in the `seen` and `jch` integration branches and expected to graduate to `master` in the next cycle. v2 posted 2026-05-22, rebased on the start of the Git 2.56 cycle (f85a7e6620) with `ps/refs-writing-subcommands` already merged. The behavioral regression in the packed-refs timeout initialization (zero-initialized `timeout_value` instead of the old 1000 ms default) is now fixed: `timeout_value` is explicitly set to 1000 in `packed_ref_store_init()` when the config key is unset. Integration conflicts with the `seen` branch (two hunks: one in `lib/setup.c`, one in `lib/refs/files-backend.c`) were minimal and are documented in the cover letter; Junio has already resolved them.

Key technical details
- Files touched: 25, spanning `refs/` (packed and files backends), `worktree.c`, `worktree.h`, built-in commands (`branch.c`, `builtin/branch.c`, `builtin/check-ref-format.c`, `builtin/checkout.c`, `builtin/merge.c`, `builtin/worktree.c`), and core library code (`refs.c`, `reachable.c`, `revision.c`, `setup.c`). The first patch (1/8) fixes the packed-refs timeout bug by moving the timeout state into `struct packed_ref_store`, adding two new fields (`timeout_configured` and `timeout_value`) and updating `packed_refs_lock()` to read the configuration per store. The second patch (2/8) removes the `USE_THE_REPOSITORY_VARIABLE` macro from `refs/packed-backend.c` after the backend’s single use of `the_repository` was converted in patch 1/8. The sixth patch (6/8) specifically updated 19 files to refactor the public worktree API to accept an explicit `struct repository *` parameter. The seventh patch (7/8) completes the conversion by targeting the last remaining callsites in built-in commands and `refs.c`, updating `copy_branchname()` and `check_branch_ref()` function signatures to accept a repository parameter, adjusting all their callers (29 lines changed across 8 files), and removing the `USE_THE_REPOSITORY_VARIABLE` macro from `refs.c`. The worktree-related helper `has_worktrees()` is also updated to take a repository parameter, fixing a TODO comment that noted the previous inconsistency.
- Symbols modified: core ref-handling functions (`lock_raw_ref()`, `init_db()`), public worktree APIs (`get_worktrees(struct repository *)`, `get_worktrees_without_reading_head(struct repository *)`, `get_linked_worktree(struct repository *, const char *)`, `repair_worktrees(struct repository *, worktree_repair_fn, void *, int)`, `other_head_refs(struct repository *, refs_for_each_cb, void *)`, `write_worktree_linking_files(struct repository *, const char *, const char *, int)`), internal worktree management routines (`should_prune_worktree(struct repository *, const char *)`, `submodule_uses_worktrees(struct repository *, const char *)`), and refs-related helpers (`copy_branchname(struct repository *, ...)`, `check_branch_ref(struct repository *, ...)`, `has_worktrees(struct repository *)`). The fourth patch replaced all `the_repository` calls in `worktree.c` with the already-available `wt->repo` pointer, touching seven call sites in five functions (`validate_worktree`, `update_worktree_location`, `repair_gitfile`, `repair_worktree_after_gitdir_move`, and `init_worktree_config`). The fifth patch updated four file-local functions in `worktree.c` (`get_main_worktree`, `get_worktrees_internal`, `infer_backlink`, and `move_config_setting`) to take an explicit `struct repository *` parameter, adjusting 26 lines and removing 21, while preserving backward compatibility in the public APIs, which continue to default to `the_repository`. The sixth patch removed the `USE_THE_REPOSITORY_VARIABLE` macro from `worktree.c` and updated all public functions to take a repository parameter, with backward compatibility preserved via wrappers. The seventh patch removed the `USE_THE_REPOSITORY_VARIABLE` macro from `refs.c` and completed the conversion of the remaining callsites.
- New struct fields: `timeout_configured` (bool) and `timeout_value` (int) in `struct packed_ref_store`.
- On-disk format: unchanged.
- Test coverage: no new tests; existing test suite validates refactoring correctness and the timeout fix.
- New/renamed symbols: none beyond the new struct fields in `packed_ref_store` and updated function signatures.

Open questions and loose ends
None. The behavioral regression in the packed-refs timeout initialization is now fixed in v2.
