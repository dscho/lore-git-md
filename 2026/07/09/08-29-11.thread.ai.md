Subject: [PATCH 0/8] refs: remove more uses of `the_repository`
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Eliminate implicit uses of the global `the_repository` variable in the refs subsystem and worktree code, continuing the long-running effort to make repository handling explicit throughout Git. The series systematically replaces `the_repository` with explicit `struct repository *` parameters in function signatures and call sites across 25 files. A latent bug in the packed-refs backend is fixed en passant: the `core.packedRefsTimeout` configuration was previously stored in function-static variables, causing only the first repository's setting to be used; this is now per-repository via `struct packed_ref_store` fields.

Current status
Blocked on integration conflicts; v1 posted 2026-05-15. The series passes all tests when run standalone but causes widespread test failures when merged into either the `jch` or `seen` integration branches. No technical objections to the refactoring itself have been raised in the thread, but the conflicts with other in-flight topics now take priority. The root cause of the failures remains unclear; the next step is for Patrick to rebase the series on current `seen` and diagnose interactions with conflicting topics.

The worktree-related helper `has_worktrees()` is also updated to take a repository parameter, fixing a TODO comment that noted the previous inconsistency.

Open questions and loose ends
- Junio C Hamano identified a behavioral regression in the first patch: the new per-repository `timeout_value` field is zero-initialized by `xcalloc()`, whereas the old static variable defaulted to 1000 ms. When `core.packedRefsTimeout` is unset, the new code will use 0 ms, which is almost certainly not the intended behavior. The fix is to explicitly initialize `timeout_value` to 1000 in `packed_ref_store_init()`.
- Integration conflicts with other in-flight topics in `jch` and `seen` are now the primary blocker. The nature of the failures (crashes, wrong behavior, test assertion mismatches) and the specific conflicting topics are unknown.
