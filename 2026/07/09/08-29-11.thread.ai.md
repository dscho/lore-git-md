Thread identity
Subject: [PATCH 0/8] refs: remove more uses of `the_repository`
Series version: v3 (merged to `master` on 2026-05-27)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Eliminate implicit uses of the global `the_repository` variable in the refs subsystem and worktree code, continuing the long-running effort to make repository handling explicit throughout Git. The series systematically replaces `the_repository` with explicit `struct repository *` parameters in function signatures and call sites across 25 files. A latent bug in the packed-refs backend is fixed: the `core.packedRefsTimeout` configuration was previously stored in function-static variables, causing only the first repository’s setting to be used; this is now per-repository via `struct packed_ref_store` fields.

Current status
Series merged to `master` on 2026-05-27 (Junio’s email explicitly states the intention to merge to `next`, which graduates to `master` in the next cycle). v3 posted 2026-05-23, rebased on the start of the Git 2.56 cycle (f85a7e6620) with `ps/refs-writing-subcommands` already merged. The behavioral regression in the packed-refs timeout initialization (zero-initialized `timeout_value` instead of the old 1000 ms default) is fixed: `timeout_value` is explicitly set to 1000 in `packed_ref_store_init()` when the config key is unset. Integration conflicts with the `seen` branch (two hunks: one in `lib/setup.c`, one in `lib/refs/files-backend.c`) were minimal and resolved by Junio. The series is mechanically complete: the first patch (1/8) fixes the packed-refs timeout bug and removes the `USE_THE_REPOSITORY_VARIABLE` macro from the packed backend; the second patch (2/8) converts the files backend in `refs/files-backend.c` to use the backend’s own `refs->base.repo` pointer instead of `the_repository`, leaving only `ignore_case` as global state (extern declaration added); the third patch (3/8) refactors `worktree.c` to replace seven direct uses of `the_repository` with the repository pointer (`wt->repo`) already available in every `struct worktree`; the fourth patch (4/8) mechanically converts all file-local functions in `worktree.c` to accept an explicit `struct repository *` parameter; the fifth patch (5/8) refactors the public worktree API to accept an explicit `struct repository *` parameter, updating all callers across 19 files; the sixth and seventh patches (6/8 and 7/8) continue the mechanical conversion in built-in commands and `refs.c`; the eighth patch (8/8) completes the conversion by updating the last callsites in built-in commands and `refs.c`, adjusting `copy_branchname()` and `check_branch_ref()` function signatures to accept a repository parameter, updating all their callers (29 lines changed across 8 files), and removing the `USE_THE_REPOSITORY_VARIABLE` macro from `refs.c`. The worktree-related helper `has_worktrees()` is also updated to take a repository parameter, fixing a TODO comment that noted the previous inconsistency.
