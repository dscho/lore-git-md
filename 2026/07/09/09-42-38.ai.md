This is the final patch in Johannes Schindelin’s eleven-patch bugfix series (`js/coverity-fixes-v2`) addressing NULL-dereference issues identified by Coverity. It targets the shallow subsystem, specifically the `write_one_shallow()` function in `shallow.c`.

The bug occurs when a shallow graft entry references a commit object that is not present in the object store (e.g., due to a partial fetch or repository corruption). In such cases, `lookup_commit()` returns NULL, but the verbose logging code still attempts to dereference `c->object.oid`, causing a crash. The fix replaces `c->object.oid` with `graft->oid` in the verbose message, since the graft entry’s OID is always available and matches the lookup key.

The change is minimal (one line) and purely defensive, ensuring the verbose output does not crash when the commit object is missing. This aligns with the rest of the series, which adds similar NULL guards in other subsystems without altering normal behavior. The patch is uncontroversial and well-motivated, completing the series with a fix for a subtle but real edge case in shallow repository handling. No new tests are included, but the change is narrow enough that existing test coverage should suffice.
