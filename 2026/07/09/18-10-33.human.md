This is a brief follow-up in Michael Montalbo’s three-patch series fixing race conditions in Git’s HTTP daemon test helpers. The series targets a real, observed flake in `t5616.47` on macOS CI runners, where concurrent HTTP requests to the same CGI script caused HTTP 500 errors due to non-atomic state checks.

This email responds to Junio C Hamano’s review of the second patch, which replaces a non-atomic `test -f` check in `http-429.sh` with an atomic `mkdir` operation. Junio’s feedback focused on whether skipping the `mkdir` check when `retry_after` is set to `"permanent"` was a correctness requirement or an optimization. Michael clarifies that it is indeed a correctness requirement: the original code was wrong even for `"permanent"` because it still performed the racy `test -f` check, which could cause concurrent requests to clobber each other’s state. He will update the commit message and code comment in the next version to make this explicit.

The patch itself remains uncontroversial; the fix is a standard atomic idiom (`mkdir`) and Junio had already called it “an obvious solution for such a situation.” The only remaining work is to document the rationale more clearly. A v2 addressing this and Junio’s earlier feedback on the first patch (commit-message clarity and a minor locale fix) is likely. No other reviews or objections have surfaced.
