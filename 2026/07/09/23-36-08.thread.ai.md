Core problem or goal: add reliable automation triggers for worktree lifecycle events (creation, removal, and movement) to support high-velocity tooling, particularly AI-driven development environments that create and destroy worktrees frequently. The series aims to provide a standardized, Git-native mechanism for running custom logic after these events, eliminating the need for external wrappers or filesystem polling.

Key technical details: new hooks `post-worktree-add`, `post-worktree-remove`, and `post-worktree-move`; fired after worktree addition/removal/movement, including pruned worktrees. Implemented in `builtin/worktree.c` (modified `prune_worktree`, `prune_dups`, `prune_worktrees`, and `move_worktree` to return exit status and invoke hooks), `worktree.c` (ensured `should_prune_worktree` always returns worktree path), and `worktree.h`. Test coverage in `t/t2400-worktree-add.sh`, `t/t2401-worktree-prune.sh` (extended for prune coverage), and `t/t2403-worktree-move.sh` (new for move hook). Documented in `Documentation/githooks.adoc` (updated to clarify prune behavior and move hook) and registered in `hook-list.h` via `Documentation/config/hook.adoc`. Hook signatures: `post-worktree-add` (no arguments, runs in new worktree directory with `GIT_DIR` and `GIT_WORK_TREE` cleared), `post-worktree-remove` (worktree directory and ID as arguments; receives empty string for path if gitdir file is missing/corrupt), `post-worktree-move` (old absolute path as argument, runs in new worktree directory with `GIT_DIR` and `GIT_WORK_TREE` cleared). Hook exit status propagates to `git worktree add`/`remove`/`move`/`prune` but does not affect the operation's outcome (e.g., cannot prevent worktree deletion). Changes from v1: (1) `post-worktree-add` runs unconditionally after `post-checkout` (even if `post-checkout` fails); (2) `post-worktree-add` no longer takes arguments (working directory is the new worktree); (3) added `post-worktree-move` hook, which runs in the new location and receives the old absolute path as its sole argument; (4) `post-worktree-remove` extended to run during `git worktree prune`, ensuring the hook is invoked for all worktree removal paths (including manual deletion), with documented edge-case behavior for missing/corrupt gitdir files.
