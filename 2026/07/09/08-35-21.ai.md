This is the first patch in Patrick Steinhardt’s seven-part series introducing object filters to `odb_for_each_object()`. It targets the packed object database backend, specifically improving object lookup efficiency during enumeration.

The patch addresses an inefficiency in `odb_for_each_object()` where, despite using multi-pack or pack indices to enumerate objects, the code still relies on the generic `odb_source_read_object_info()` function for object lookups. This forces a redundant index traversal and risks incorrect pack selection if an object exists in multiple packs. The fix replaces the generic lookup with direct calls to `packed_object_info()`, using the already-available index data to avoid the second traversal. The change also renames the `store` variable to `source` for clarity, aligning with the ODB abstraction’s terminology.

The diff touches only `odb/source-packed.c`, modifying two helper functions: `for_each_prefixed_object_in_midx()` and `for_each_prefixed_object_in_pack()`. Both now use the pack and offset information directly from the index rather than re-resolving it. The patch is mechanical and focused, with no behavior change beyond the performance improvement and correctness fix.

This is a foundational change for the series, preparing the packed backend to support the object filters introduced in later patches. The commit message clearly explains the problem, the solution, and the rationale, making it easy to assess the patch’s purpose and impact. No test failures or edge cases are mentioned, suggesting the change is straightforward and well-contained.
