This is the tenth patch in Johannes Schindelin’s 12-patch series widening size fields in Git’s delta and pack machinery to `size_t` for 64-bit Windows correctness. It fixes a latent type mismatch in `http-push.c`: the local variable `size` in `start_put()` is changed from `ssize_t` to `size_t` because it holds the unsigned result of `git_deflate_bound()` and is only used in unsigned contexts (`strbuf_grow()` and `stream.avail_out`, both already `size_t`). The original `ssize_t` was technically wrong—values above `SSIZE_MAX` would wrap negative and then be implicitly sign-extended to a huge `size_t` when passed to `strbuf_grow()`—but this was not a practical issue for the object sizes pushed today. The patch is a single-line mechanical change that prepares the code for the upcoming widening of `git_deflate_bound()` itself. No behavior change or new tests; the fix is purely about type hygiene.
