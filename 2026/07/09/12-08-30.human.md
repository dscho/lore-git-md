This is the first patch in a two-patch bugfix series targeting a quadratic performance regression in Git’s reftable backend. It adds a new performance test (`t/perf/p1401-ref-store-tombstones.sh`) that measures the time taken to recreate refs after mass deletion in two scenarios: re-creating the same refs (quadratic behavior) and creating new, differently-named refs (worst-case tombstone sorting).

The test is well-designed and directly exercises the regression described in the cover letter. It uses 8,000 refs to make the quadratic behavior obvious, and the two scenarios isolate the two pathological cases: tombstones that sort before the new refs (asymmetric variant) and tombstones that sort after (recreate variant). Each scenario runs in a fresh repository to prevent tombstone carryover, addressing prior feedback about test isolation. The setup is straightforward and the test script is cleanly written.

This patch is purely additive and does not change any production code. It is a prerequisite for the second patch, which implements the actual fix. The test will help verify that the fix works and prevent future regressions. There is nothing controversial here; it is a clear, focused addition that serves a specific purpose in the series. If the second patch lands, this test will be a valuable part of the regression suite.
