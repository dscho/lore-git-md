This thread is about a patch from Gatla Vishweshwar Reddy, a first-time contributor, that refactors `git add -e` (interactive edit) to use Git’s internal `apply_all_patches()` API instead of forking a `git apply` subprocess. The goal is to improve efficiency and code clarity by keeping the operation in-process.

Junio C Hamano has reviewed the patch and raised a significant correctness concern: the proposed change omits a call to `check_apply_state()`, which is required to properly configure the `apply_state` struct for index updates. Without this, the `update_index` field might not be set, causing the internal API to silently skip writing the edited patch back to the index—directly breaking the command’s intended behavior. Junio’s feedback is substantive, explaining the role of `state->check_index` and `state->update_index` and asking the author to verify testing coverage. The patch is still under review, and no updated version has been posted yet. The thread is currently focused on this correctness issue, with no other participants weighing in.
