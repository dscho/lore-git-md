This thread is about a small but well-targeted refactoring of `git add -e` (interactive edit). First-time contributor Gatla Vishweshwar Reddy has submitted a patch that replaces an external `git apply` subprocess call with a direct invocation of Git's internal `apply_all_patches()` API. The change is confined to `builtin/add.c` and is purely mechanical—it removes the overhead of forking a child process while preserving identical behavior, using the same `--cached` and `--recount` options that were previously passed to the subprocess.

The patch itself is clean and self-contained: nine lines added, seven removed, with no test failures or edge cases reported. It follows Git's ongoing pattern of eliminating subprocess calls where internal APIs are available, and the commit message clearly explains the motivation. So far, there’s been no review feedback on the list, so the patch remains under initial consideration. If it holds up to scrutiny, it’s a straightforward improvement that should integrate smoothly.
