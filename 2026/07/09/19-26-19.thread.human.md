This thread is about a refactoring patch to `git add -e` (interactive edit) that replaces a subprocess call to `git apply` with Git’s internal `apply_all_patches()` API. The goal is to eliminate the overhead of forking a child process while keeping the operation in-process. The original patch (v1) was posted by first-time contributor Gatla Vishweshwar Reddy and drew a substantive review from Junio C Hamano, who identified a correctness issue: the patch omitted a required `check_apply_state()` call, which could cause the internal apply API to silently skip updating the index.

The author has now posted v2, which addresses Junio’s feedback by adding the missing `check_apply_state()` call after configuring the `apply_state` struct. The updated patch also cleans up includes, adopts present-tense commit message style, and confirms that all 58 tests in `t3700-add.sh` pass. The change is narrowly scoped to `builtin/add.c` and aligns with Git’s ongoing effort to reduce subprocess usage. With the correctness issue resolved and tests passing, the patch is now a strong candidate for merging, pending a final review from Junio or another maintainer.
