This thread is about a refactoring patch by Gatla Vishweshwar Reddy that replaces the external `git apply` subprocess call in `git add -e` (interactive edit) with Git’s internal `apply_all_patches()` API. The goal is to eliminate fork overhead and improve code clarity while maintaining identical behavior.

The patch is now at v3, addressing Junio Hamano’s feedback on v2. The new version fixes the declaration-after-statement style violation and confirms that `repo_git_path()` returns an absolute path, ensuring correct subdirectory operation. All 58 tests in `t3700-add.sh` pass, but the author notes there’s no existing test coverage for `git add -e` in subdirectories and asks whether a new test is needed. Junio hasn’t yet weighed in on this final point, so the patch remains under review until that’s resolved.

The change is confined to `builtin/add.c`, removes unused includes, and adds `apply.h`. No new symbols are introduced, and the behavior is unchanged in intent. The author’s responsiveness—addressing both mechanical and behavioral concerns—has been strong, but the lack of test coverage for subdirectory use leaves a small open question before merging. This aligns with Git’s broader effort to reduce subprocess usage where internal APIs are available.
