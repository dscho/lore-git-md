This thread is about a small but meaningful refactoring to `git add -e` (interactive edit). The patch, authored by first-time contributor Gatla Vishwahwar Reddy, replaces an external `git apply` subprocess call with Git’s internal `apply_all_patches()` API, eliminating fork overhead and keeping the operation in-process. After four iterations—each addressing subtle correctness concerns raised by Junio C Hamano—the patch is now approved and has been marked for inclusion in the `next` branch.

The key technical change is in `builtin/add.c`, where the patch removes the subprocess call and instead initializes the apply state with a `NULL` prefix, ensuring the path from `repo_git_path()` is passed unchanged to the apply machinery. A new test in `t/t3702-add-edit.sh` verifies that the feature still works correctly when run from a subdirectory. All existing tests pass, and no new symbols or on-disk changes are introduced.

Junio’s final email frames the merge as a low-risk experiment: the patch is small and correct, but since there’s been no feedback from actual users of `git add -e`, he’s leaving the door open for late-discovered regressions. If any issues surface during integration testing, the patch can be easily reverted. The thread is effectively closed—no open questions remain—but the patch’s journey into `master` will depend on whether any problems emerge in `next`.
