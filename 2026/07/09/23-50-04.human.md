This is a gentle reminder for a bugfix patch that relaxes Git’s SSH signature inspection behavior.

The patch, originally sent on July 9, removes the hard requirement that `gpg.ssh.allowedSignersFile` must be configured before Git will display any SSH signature details. Without the patch, users who only want to see the key fingerprint or signature status (e.g., via `git show --show-signature`) are blocked by an error and forced to create the file even if they don’t need automated principal validation. The change lets Git fall back to a “novalidate” mode, showing basic signature information while printing a hint that the file can be configured for full validation.

The implementation is minimal: it touches only `gpg-interface.c`, adds an include for `advice.h` to emit the hint, and leaves the on-disk format untouched. The commit message includes clear before-and-after examples, but the patch itself does not add tests or update documentation. No objections or requests for changes have surfaced yet, and the patch remains under review with no maintainer decision.
