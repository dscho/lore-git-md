This is a **surface-level usability discussion** about the `--no-deref` option in the newly merged `git refs create` subcommand. Toon Claes suggests dropping `--no-deref` entirely, arguing that users who want to modify a regular reference should use `git refs` (which dereferences symrefs by default), while those needing to manipulate symbolic references should use `git symbolic-ref`. This would simplify the interface by removing an obscure option whose behavior—failing if the target exists as a symref—is not intuitive for most users.

The proposal is brief and does not engage with the atomicity guarantees that `--no-deref` provides (e.g., preventing accidental overwrites of symrefs). It also does not address whether this change would break existing scripts or workflows that rely on the option. Since the series is already merged, this is likely a **post-hoc observation** rather than a call for immediate action, but it may inform future refinements to the `git refs` interface. The discussion remains at the level of CLI ergonomics, not technical correctness.
