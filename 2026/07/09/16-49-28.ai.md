This is the first patch in a 12-part platform-compatibility series widening size fields in Git’s delta and pack machinery from `unsigned long` to `size_t` to prevent truncation on 64-bit Windows. The series is part of the broader effort to eliminate incorrect `unsigned long` usage in favor of `size_t`.

This patch widens the `src_size` and `memsize` fields in the private `struct delta_index` (defined in `diff-delta.c`) from `unsigned long` to `size_t`. The change is purely internal: the struct is not exposed outside `diff-delta.c`, so the widening has no runtime effect yet. The commit message explains this is preparatory work for the subsequent API-wide changes, allowing later patches to focus on caller updates without mixing internal and external changes.

The patch itself is mechanical: three lines changed in `diff-delta.c`, replacing `unsigned long` with `size_t` in the struct definition and a local variable. No logic or behavior changes are introduced. The commit message is clear and ties the change to the broader series goal, referencing the earlier commit `606c192380` that introduced `cast_size_t_to_ulong()` shims in the pack-objects code.

This is a low-risk, well-scoped change that sets the stage for the rest of the series. It is uncontroversial and should be of interest primarily to Windows users and maintainers of the delta/pack subsystems. The patch is authored by Johannes Schindelin, the Git for Windows maintainer, and is motivated by real-world truncation issues observed on that platform.
