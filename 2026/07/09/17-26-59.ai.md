This is a **bugfix follow-up** to the first patch in Michael Montalbo’s three-patch series fixing race conditions in Git’s HTTP daemon test helpers. The patch targets `t/lib-httpd/apply-one-time-script.sh` and replaces a non-atomic `test -f`/`rm` sequence with an atomic `mv` to prevent concurrent requests from both modifying the response and emitting an empty body (which triggers HTTP 500 errors).

The email is a **reply to Junio C Hamano’s substantive review**, which identified a subtle but important distinction: the atomic `mv` shrinks the race window but does not prevent the one-time script from running multiple times, and the goal is not to prevent concurrent execution (which is safe) but to ensure only one request’s modified output is served. Michael agrees with Junio’s clarification and will update the commit message and helper comment to make this nuance explicit. He also notes that the locale handling in the original script was inconsistent (forcing C locale only when modifying output) and offers to either fix it in this series or defer it to a future cleanup.

No new technical concerns are raised, and the discussion remains narrowly focused on commit-message clarity and a minor locale inconsistency. The series continues to look like a well-motivated, self-contained bugfix for test infrastructure, with no user-visible changes or controversy. A v2 is likely to address Junio’s feedback, but the core fix is already endorsed as correct.
