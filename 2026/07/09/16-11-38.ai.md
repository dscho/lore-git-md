This is patch 2/9 of Tian Yuchen's v9 series migrating global configuration variables into `struct repo_config_values`, part of the ongoing `the_repository` removal effort. This patch moves the `excludes_file` global (the path to the global ignore file) into the repository-specific configuration structure and introduces `repo_excludes_file()`, a getter that implements the lazy-loading fallback to the XDG default path previously handled in `setup_standard_excludes()`.

The change is mechanical and follows the established pattern from the merged `excludes_file` series: the global variable is removed, the field is added to `struct repo_config_values`, and callers in `dir.c` are updated to use the new getter. Memory management is handled by `repo_config_values_clear()`, which now frees the heap-allocated `excludes_file` string during repository teardown. The patch is CI-clean and does not alter user-visible behavior.

This is a re-split of work already merged in the prior series, included here for clarity and to establish the memory-management pattern for the rest of the series. The only functional difference from the merged version is the explicit use of `repo_config_values_clear()` to free the field, which was added in patch 1/9 of this series. The patch touches `dir.c`, `environment.c`, and `environment.h`, and introduces the `repo_excludes_file()` getter.

The patch is technically sound and ready for integration. It carries no unresolved `NEEDSWORK` items and does not introduce new open questions. The submodule limitation in `repo_config_values_clear()` (silently returning for non-`the_repository` instances) is inherited from the prior series and remains marked as `NEEDSWORK`, but is not a blocker.
