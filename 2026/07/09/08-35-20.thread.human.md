This thread is about Patrick Steinhardt’s eight-patch v2 series introducing object filters to `odb_for_each_object()`, a key step in Git’s ongoing ODB abstraction effort. The goal is to let `git cat-file --batch-all-objects` work with pluggable object databases by removing its tight coupling to the "packed" backend’s internals, while also fixing inefficiencies in object lookups during enumeration.

The series is under active review, with all feedback from v1 incorporated into v2. Junio Hamano praised the final patch’s diffstat (7 insertions, 69 deletions) and requested a clearer commit message, which Patrick added. Justin Tobler and Taylor Blau reviewed multiple patches, raising questions about object lookup behavior, style, and design choices—all resolved in v2. Taylor also identified a performance inefficiency in patch 1/8 (unnecessary MIDX traversals) and an incomplete refactoring in patch 3/8 (missing error propagation in `traverse_bitmap_commit_list()`), the latter of which Jeff King (Peff) expanded into a broader design question: whether Git’s object traversal APIs should consistently support early termination via callback return values. Peff noted that the non-bitmap `traverse_commit_list()` ignores callback returns entirely, suggesting the two APIs should align. This adds a new layer to the discussion but doesn’t block progress. Peff also submitted a follow-up cleanup patch to remove a long-dead `int` return from `add_object_entry()`, which could be queued alongside the series.

The series touches the ODB, packed backend, pack-bitmap, and `git cat-file` subsystems, introducing new functions like `open_bitmap_for_source()` and exposing `can_filter_bitmap()` for backend use. No on-disk format changes are made, and end-user behavior is unchanged. The main open question is how to handle the traversal API consistency Peff raised; Patrick hasn’t responded yet. Otherwise, the series appears technically sound and ready for integration once the design question is resolved.
