This thread is about Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, a key step in Git’s ongoing ODB abstraction effort. The goal is to let `git cat-file --batch-all-objects` work with pluggable object databases by removing its tight coupling to the packed backend’s internals—specifically, its manual bitmap handling. The series also fixes an inefficiency in `odb_for_each_object()` where object lookups during enumeration redundantly traverse indices, risking incorrect pack selection and degrading performance.

The series is now effectively ready for acceptance. Junio C Hamano reviewed the final patch (7/7), calling the implementation "very nice" and praising its 7-insertion/69-deletion diffstat, which replaces backend-specific logic with ODB-mediated filtering. His only request was a clearer commit message upfront, explicitly stating the problem: the current `cat-file` implementation reaches into ODB internals and manually manages bitmaps, creating tight coupling. Patrick has agreed to this tweak, and no other changes are needed. Justin Tobler’s earlier reviews of patches 1/7, 3/7, 4/7, and 6/7 raised technical questions about object lookup behavior, return-value changes, style, and interface design, but all were resolved without requiring code changes. The series is built on Git 2.56 with Patrick’s `ps/odb-drop-whence` topic merged, and a v2 reroll is expected soon.

Key technical changes include making object filters `const`, renaming variables for clarity, introducing new functions to open bitmaps for specific sources, reversing loop order in `open_pack_bitmap_1()` to prioritize local bitmaps, and enabling early termination of bitmapped object iteration. The series touches the ODB, packed backend, and pack-bitmap subsystems, with no expected end-user behavioral changes or on-disk format modifications. Once Patrick posts v2 with the improved commit message, the series is likely to be merged.
