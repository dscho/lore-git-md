This thread is about Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, a key step in Git’s ongoing ODB abstraction effort. The goal is to let `git cat-file --batch-all-objects` work with pluggable object databases without relying on internal details of the packed backend, while also fixing inefficiencies in object lookups during enumeration.

The series is under active review, with v1 posted and no prior versions. Junio C Hamano praised the final patch (7/7) for its clean diffstat and requested only a minor commit message tweak to better motivate the change. Justin Tobler has reviewed patches 1, 3, 4, and now 6, raising technical questions but no outright objections. His latest review questions the design of the `filter` field in `odb_for_each_object_options`, suggesting it would be awkward for callers if backends can ignore filters and force re-application. This is a design-level concern about API ergonomics, not a blocker, and Patrick’s response will likely clarify whether the current approach is intentional or if the interface will be adjusted.

The series touches the ODB, packed backend, and pack-bitmap subsystems, with changes spanning `builtin/cat-file.c`, `pack-bitmap.c`, and ODB interface headers. Key technical changes include making object filters `const`, introducing new functions to open bitmaps per source, and altering bitmap precedence to prioritize local bitmaps over multi-pack index bitmaps. No on-disk format changes are involved, and no end-user behavioral changes are expected. The series is built on Patrick’s `ps/odb-drop-whence` topic and is likely to be accepted once the remaining review comments—Junio’s commit message tweak, Justin’s questions on patch 1, and the new design question on patch 6—are addressed.
