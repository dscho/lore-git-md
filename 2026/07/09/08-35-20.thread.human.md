This thread is Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, a key step in the ongoing ODB abstraction effort to restructure Git’s object storage layer for pluggable backends. The series aims to enable `git cat-file --batch-all-objects` to work efficiently with alternative object databases by removing its dependency on internal details of the packed backend, while also fixing inefficiencies in object lookups during enumeration.

The first six patches lay the groundwork: they make object filters `const`, rename variables for clarity, introduce source-specific bitmap handling, reverse loop order to prioritize local bitmaps, and add a `filter` field to `odb_for_each_object_options` to allow callers to pass filters directly to backends. The just-posted final patch (7/7) demonstrates the payoff by refactoring `git cat-file --batch-all-objects` to use the new ODB-mediated filtering, removing 69 lines of backend-specific code and eliminating the dependency on `pack-bitmap.h`. The series is built on Git 2.56 with Patrick’s `ps/odb-drop-whence` topic merged and is currently under review with no prior versions or feedback yet.

Key technical changes include new functions like `open_bitmap_for_source()` and `prepare_bitmap_git_for_source()`, improved object lookup during enumeration, and early termination of bitmapped object iteration. The series touches the ODB, packed backend, and pack-bitmap subsystems, with changes spanning `builtin/cat-file.c`, `pack-bitmap.c`, `odb/source-packed.c`, and related headers. While the changes are internal and don’t alter end-user behavior, they simplify the codebase and future-proof it for pluggable backends. Reviewers—particularly those focused on ODB abstraction or `cat-file` internals—will want to verify edge cases around bitmap interaction and alternate object databases. No open questions or objections have been raised yet, but the series is newly posted and awaiting feedback.
