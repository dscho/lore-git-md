This is the first patch in Patrick Steinhardt’s seven-part series introducing object filters to `odb_for_each_object()`. It targets the packed object database backend and fixes an inefficiency in how objects are looked up during enumeration.

When iterating through packed objects—either via a multi-pack index or individual packfiles—Git currently uses the index only to enumerate objects but then falls back to the generic `odb_source_read_object_info()` function for the actual lookup. This forces a second, redundant index traversal and can even return the wrong pack if an object exists in multiple packs. The patch replaces the generic lookup with a direct call to `packed_object_info()`, passing the already-known offset from the index. It also renames the `store` variable to `source` for clarity.

The change is confined to `odb/source-packed.c` and is purely internal plumbing: no user-visible behavior changes, no new APIs, and no on-disk format impact. The commit message is clear and the diff is small, making the fix easy to verify. This is a solid, low-risk first step toward the series’ larger goal of enabling pluggable ODB backends.
