This is the sixth patch in Johannes Schindelin’s 12-patch series widening size fields in Git’s delta and pack machinery from `unsigned long` to `size_t` for 64-bit Windows correctness. The patch updates the `create_delta()` and `diff_delta()` functions in `delta.h` and their callers to use `size_t` for all size parameters and output variables, ensuring no truncation occurs when handling objects larger than 4 GiB on platforms where `unsigned long` is 32-bit.

The changes are mechanical and confined to type widening. The patch updates the function signatures in `delta.h` and `diff-delta.c`, then adjusts each caller to match. Most callers still use `unsigned long` for downstream compatibility (e.g., zlib’s `avail_in` or test helpers), so the patch introduces temporary `size_t` variables and `cast_size_t_to_ulong()` shims to bridge the gap. These shims are noted as temporary and will be removed in later topics that widen the downstream consumers. The only caller widened outright is `t/helper/test-delta.c`, which has no downstream constraints.

Files touched: `delta.h`, `diff-delta.c`, `builtin/fast-import.c`, `builtin/pack-objects.c`, `diff.c`, `t/helper/test-delta.c`, and `t/helper/test-pack-deltas.c`. The patch is low-risk, with no behavior or on-disk format changes, and is part of the broader `unsigned long` → `size_t` conversion effort. The commit message is clear and explains the reasoning for each caller’s approach, making the patch easy to review. This is a well-scoped, platform-specific fix that should be uncontroversial.
