This is a feature patch series introducing two new Git hooks: `post-worktree-add` and `post-worktree-remove`. The series consists of three patches, authored by Domen Kožar, targeting the worktree subsystem. The motivation is clear: automated workflows (particularly AI-driven development environments) create and destroy worktrees at high velocity, and there is currently no reliable way to trigger setup or cleanup actions for these worktrees. The patches address this by adding hooks that fire after a worktree is added or removed, including cases where worktrees are pruned after manual deletion.

The implementation touches `builtin/worktree.c`, `worktree.c`, and `worktree.h`, and adds comprehensive test coverage in `t/t2400-worktree-add.sh`, `t/t2401-worktree-prune.sh`, and `t/t2403-worktree-move.sh`. The hooks are documented in `Documentation/githooks.adoc`. The series is well-motivated and addresses a real gap in Git's automation story, particularly for tooling that manages ephemeral worktrees. The commit messages and cover letter are clear and explain the design choices, including edge cases like hook ordering and path resolution during pruning.

Two design points are flagged for discussion: whether `post-worktree-add` should run even if `post-checkout` fails, and how to handle path resolution for pruned worktrees when the gitdir file is missing or corrupt. These are reasonable questions that will likely draw feedback from reviewers familiar with hook semantics and worktree internals. The series looks technically sound and is likely to be of interest to anyone building tooling around Git worktrees.
