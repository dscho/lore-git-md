This is the third patch in Johannes Schindelin’s eleven-patch bugfix series (`js/coverity-fixes-v2`) addressing NULL-dereference issues flagged by Coverity. This installment adds a defensive check in `remote.c` to guard the `remote_tracking()` helper against a NULL `remote` pointer.

The fix is minimal: a two-line guard at the start of `remote_tracking()` that returns -1 (the same sentinel value already used when no tracking ref exists) if `remote` is NULL. The commit message explains that the only caller (`apply_cas()`) already ensures the pointer is non-NULL, but the reasoning is subtle and the guard makes the code more robust. No behavior change is visible to users, and the patch does not touch any other part of the codebase.
