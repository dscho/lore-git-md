This is the third and final patch in a feature series introducing `includeIf worktree:<pattern>` and `worktree/i:<pattern>` conditions to Git’s config system. It wires the new keywords into the config machinery, adds comprehensive test coverage, and documents the feature.

The patch completes the implementation by hooking the new conditions into `config.c`’s `include_condition_is_true()` function. It reuses the `include_by_path()` helper (refactored in patch 1) and passes the symlink-preserving worktree path (stored by patch 2) as the path to match against. The conditions never match in bare repositories or during early config reading, where no worktree is available.

Test coverage is thorough: it verifies behavior in bare repositories, multiple worktrees, symlinked paths (including symlinked worktrees), case-sensitive and case-insensitive matching, early config reading, and non-repository scenarios. The documentation explains the distinction between `worktree:` and `gitdir:`, provides usage examples, and compares the feature with `extensions.worktreeConfig`.

This patch is well-prepared for review. The implementation is clean, the tests cover edge cases, and the documentation is clear. The series as a whole addresses a real gap in multi-worktree workflows and integrates smoothly with Git’s existing config system. No unresolved technical issues are apparent.
