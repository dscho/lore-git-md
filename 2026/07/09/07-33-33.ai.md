This is a bug report (or documentation request) about confusing behavior in `git fetch`'s automatic tag fetching. The author, Ondřej Medek, observes that `git fetch` sometimes fetches tags pointing to fetched histories and sometimes does not, despite the documentation claiming it does so "by default." The inconsistency hinges on whether the refspec includes a destination (`:dst`) part: commands like `git fetch origin master` do *not* fetch tags, while `git fetch origin refs/heads/master:refs/remotes/origin/master` *does*. Even more puzzlingly, adding a dummy refspec with a `:dst` (e.g., `refs/none/*:refs/none/*`) causes tags to be fetched for unrelated refspecs like `master`.

The report includes clear reproduction steps: creating a test tag, pushing it, and deleting it locally before each test. The author suggests either documenting this behavior (if intentional) or fixing it (if a bug). The key technical detail is the role of the `:dst` part in refspecs, which appears to act as a global toggle for automatic tag fetching across all refspecs in the command, not just the ones containing it. This behavior is not currently explained in the documentation, making it a likely source of user confusion. The report is well-structured and provides enough detail for someone to investigate or test the claim.
