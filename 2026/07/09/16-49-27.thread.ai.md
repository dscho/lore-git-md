Subject: [PATCH 0/13] Widen size fields in delta/pack machinery for 64-bit Windows
Series version: v3 (final; fully type-consistent, addresses all prior review feedback)
Originating author: Johannes Schindelin (via GitGitGadget)
Thread type: patch series (platform-compatibility fix)

Core problem or goal
Widen size-related fields, parameters, and local variables in Git’s delta-compression and pack-objects code from `unsigned long` or `int` to `size_t` to prevent integer truncation on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` does not match the pointer width. This completes the ongoing effort to eliminate incorrect `unsigned long` usage in favor of `size_t` in the delta/pack subsystems.

Current status
Queued in `next` for integration testing. The series is now fully type-consistent across all affected code paths, addressing all prior review feedback, including the final two truncation risks in the delta-window memory accounting chain (`mem_usage` in `find_deltas()` and the corresponding output parameter in `try_delta()`), the delta-encoding API (`create_delta()`, `diff_delta()`, and their `delta_size` output parameters), the zlib stream interfaces (`avail_in`, `avail_out`, and `use_pack()`'s `left` output parameter), the `maxsize` local variable in `archive-zip.c` (Patch 8/13), and the narrowing bug in `diff.c`’s `deflate_it()` function (Patch 9/13). The 13-patch split is final; no further changes are expected unless new issues emerge during integration.

Internal preparatory work in Patch 1 widens `struct delta_index` fields (`memsize`, `src_size`) and the return type of `sizeof_delta_index()` to `size_t`; these are private to `diff-delta.c` and have no runtime effect until later patches widen the public API. Patch 4 widens the return type of `free_unpacked()` from `unsigned long` to `size_t` to match the widened `SIZE(n->entry)`. All other prior widenings remain unchanged: delta-cache accounting variables (`delta_cache_size`, `max_delta_cache_size`), zlib stream fields, and local variables in `archive-zip.c`, `http-push.c`, and test helpers.
- Internal preparatory work: Patch 7 widens the `use_pack()` function’s `left` output parameter and the `avail_in`/`avail_out` fields in the `git_zstream` struct to `size_t`, resolving truncation risks in the zlib stream interfaces. Patch 6 widens the delta-encoding API (`create_delta()`, `diff_delta()`, and their `delta_size` output parameters) to `size_t`, ensuring consistency across all callers. Some callers retain `unsigned long` locals (e.g., `deltalen` in `fast-import.c`) due to downstream dependencies on still-unsigned interfaces (like zlib’s `avail_in`), bridged via temporary `size_t` variables and `cast_size_t_to_ulong()` shims. Patch 5 widens the `mem_usage` counter in `find_deltas()` and its output parameter in `try_delta()` to `size_t`, resolving the last truncation risk in the delta-window memory accounting chain. Patch 8 widens the `maxsize` local variable in `archive-zip.c`’s `zlib_deflate_raw()` to `size_t` in preparation for the upcoming widening of `git_deflate_bound()`’s return type (Patch 12). Patch 9 widens the `bound` local variable in `diff.c`’s `deflate_it()` to `size_t`, fixing a silent narrowing bug where `git_deflate_bound()`’s `unsigned long` return value was assigned to an `int` local, risking truncation on platforms where `unsigned long` exceeds `INT_MAX` (e.g., 64-bit Windows). The fallback formula for inputs exceeding zlib’s `uLong` range (>4 GiB on 64-bit Windows) remains unchanged, mirroring zlib’s stored-block logic plus worst-case wrapper overhead. The code is guarded by `#if SIZE_MAX > ULONG_MAX` to avoid overhead on platforms where `unsigned long` is already 64-bit.
