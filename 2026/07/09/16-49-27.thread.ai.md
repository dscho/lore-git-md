Subject: [PATCH 0/12] Widen size fields in delta/pack machinery for 64-bit Windows
Series version: v2 (addresses all review feedback from v1; ready for integration)
Originating author: Johannes Schindelin (via GitGitGadget)
Thread type: patch series (platform-compatibility fix)

Core problem or goal
Widen size-related fields, parameters, and local variables in Git’s delta-compression and pack-objects code from `unsigned long` or `int` to `size_t` to prevent integer truncation on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` does not match the pointer width. This is part of the ongoing effort to eliminate incorrect `unsigned long` usage in favor of `size_t`.

Current status
Under review; v2 posted. All review feedback from Patrick Steinhardt on v1 has been addressed: (1) `sizeof_delta_index()` return type and callers widened to `size_t` (Patch 1); (2) `max_delta_cache_size` configuration parsing now uses `git_config_size_t()` to reject negative values (Patch 3); (3) `free_unpacked()` return type widened to `size_t` (Patch 4); (4) `bufsize` parameter of `create_delta_index()` widened to `size_t` (Patch 2); (5) `mem_usage` counter in `find_deltas()` and corresponding output parameter in `try_delta()` widened to `size_t` (Patch 5); (6) all size parameters in `create_delta()` and `diff_delta()` widened to `size_t` (Patch 6); (7) `*left` output parameter of `use_pack()` and `avail_in`/`avail_out` fields in `struct git_zstream` widened to `size_t` (Patch 7); (8) `maxsize` local variable in `zlib_deflate_raw()` (in `archive-zip.c`) widened to `size_t` (Patch 8); (9) `bound` local variable in `deflate_it()` (in `diff.c`) widened from `int` to `size_t` (Patch 9); (10) `size` local variable in `start_put()` (in `http-push.c`) widened from `ssize_t` to `size_t` (Patch 10); (11) `maxsize` local variable in `do_compress()` (in `t/helper/test-pack-deltas.c`) widened from `unsigned long` to `size_t` (Patch 11). The series remains mechanical, with no behavior or on-disk format changes. The twelve-patch split is unchanged despite earlier discussion about squashing. The series is uncontroversial and ready for integration once any remaining feedback is addressed.

Key technical details

Local variables in `builtin/pack-objects.c` (`avail`, `remaining`) and `pack-check.c` (`remaining`) widened to `size_t` for consistency (Patch 7).
- Internal preparatory work: Patch 1 widened `src_size` and `memsize` in `struct delta_index` and the return type of `sizeof_delta_index()` to `size_t`, ensuring internal consistency before updating callers. Patch 2 widened the `bufsize` parameter of `create_delta_index()` to `size_t`. Patch 3 introduced `git_config_size_t()` and `git_parse_size_t()` to parse `max_delta_cache_size` (now `size_t`) and reject negative values, addressing a latent bug where `git_config_int()` would silently accept negative values. Patch 4 widened the return type of `free_unpacked()` to `size_t` to prevent truncation when summing two `size_t` values (`sizeof_delta_index()` and `SIZE(n->entry)`), though the sole caller (`find_deltas()`) still used `unsigned long` for its `mem_usage` counter, leaving a residual truncation risk. Patch 5 widened the `mem_usage` counter in `find_deltas()` and the corresponding output parameter in `try_delta()` to `size_t`, eliminating the last 32-bit truncation risk in the delta-window memory accounting chain on 64-bit Windows. Patch 6 widened all size parameters in `create_delta()` and `diff_delta()` to `size_t` and updated callers, using temporary `cast_size_t_to_ulong()` shims where downstream consumers remain `unsigned long`. Patch 7 widened the `*left` output parameter of `use_pack()` and the `avail_in`/`avail_out` fields in `struct git_zstream` to `size_t`, enabling the next patch (08/12) to remove the last `cast_size_t_to_ulong()` shim in `write_no_reuse_object()`. Patch 8 widened the `maxsize` local variable in `zlib_deflate_raw()` (in `archive-zip.c`) to `size_t` to prepare for the upcoming widening of `git_deflate_bound()`’s return type. Patch 9 widened the `bound` local variable in `deflate_it()` (in `diff.c`) from `int` to `size_t` to fix a latent narrowing bug where the `unsigned long` return value of `git_deflate_bound()` was silently truncated to `int`, risking negative values for inputs above 2 GiB. Patch 10 widened the `size` local variable in `start_put()` (in `http-push.c`) from `ssize_t` to `size_t` to align with `git_deflate_bound()`’s unsigned return type and avoid potential negative wraparound for large inputs. Patch 11 widened the `maxsize` local variable in `do_compress()` (in `t/helper/test-pack-deltas.c`) from `unsigned long` to `size_t` to maintain consistency with the upcoming widening of `git_deflate_bound()`’s return type (Patch 12). The fallback formula in Patch 12 for inputs above zlib’s `uLong` range (>4 GiB on 64-bit Windows) remains unchanged, with added references to zlib’s stored-block logic for clarity.
