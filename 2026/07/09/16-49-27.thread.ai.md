Subject: [PATCH 0/13] Widen size fields in delta/pack machinery for 64-bit Windows
Series version: v3 (final; fully type-consistent, addresses all prior review feedback)
Originating author: Johannes Schindelin (via GitGitGadget)
Thread type: patch series (platform-compatibility fix)

Core problem or goal
Widen size-related fields, parameters, and local variables in Git’s delta-compression and pack-objects code from `unsigned long` or `int` to `size_t` to prevent integer truncation on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` does not match the pointer width. This completes the ongoing effort to eliminate incorrect `unsigned long` usage in favor of `size_t` in the delta/pack subsystems.

Current status
Queued in `next` for integration testing. The series is now fully type-consistent across all affected code paths, addressing the two truncation risks Junio C Hamano identified in v2 (resolved in v3). All prior review feedback has been incorporated, and the series remains uncontroversial and mechanically correct. The 13-patch split is final; no further changes are expected unless new issues emerge during integration.

Key technical details
- Files touched: 21, spanning `diff-delta.c`, `pack-objects.c`, `git-zlib.c`, `http-push.c`, `archive-zip.c`, `remote-curl.c`, `builtin/fast-import.c`, `builtin/pack-objects.c`, `config.c`, `config.h`, `parse.c`, `parse.h`, and test helpers.
- New/renamed symbols: `git_deflate_bound()` parameter and return type widened to `size_t` (Patch 12), `zlib_buf_cap()` widened to `size_t` (Patch 13), `unpack_object_header_buffer()` length parameter widened to `size_t` (Patch 13), `create_delta_index()` parameter `bufsize` widened to `size_t` (Patch 2), and `git_config_size_t()`/`git_parse_size_t()` helpers (Patch 3) for handling the `max_delta_cache_size` configuration variable. Internal preparatory work in Patch 1 widens `struct delta_index` fields (`memsize`, `src_size`) and the return type of `sizeof_delta_index()` to `size_t`; these are private to `diff-delta.c` and have no runtime effect until later patches widen the public API. Patch 4 widens the return type of `free_unpacked()` from `unsigned long` to `size_t` to match the widened `SIZE(n->entry)`, though the caller `find_deltas()` still uses an `unsigned long` for its `mem_usage` counter, leaving truncation there until later patches address it. All other prior widenings remain unchanged: delta-cache accounting variables (`delta_cache_size`, `max_delta_cache_size`), zlib stream fields (`avail_in`, `avail_out`), `*left` output parameter of `use_pack()`, `mem_usage` counter in `find_deltas()` and `try_delta()`, and local variables in `archive-zip.c`, `diff.c`, `http-push.c`, and test helpers.
- Internal preparatory work: Patch 13 finalizes the type chain by widening the last two `unsigned long` interfaces (`zlib_buf_cap()` and `unpack_object_header_buffer()`), eliminating all truncation risks in the delta/pack code paths. The fallback formula for inputs exceeding zlib’s `uLong` range (>4 GiB on 64-bit Windows) remains unchanged, mirroring zlib’s stored-block logic plus worst-case wrapper overhead. The code is guarded by `#if SIZE_MAX > ULONG_MAX` to avoid overhead on platforms where `unsigned long` is already 64-bit.
