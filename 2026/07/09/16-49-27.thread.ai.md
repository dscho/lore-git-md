Thread type: patch series (platform-compatibility fix)

Core problem or goal
Widen size-related fields, parameters, and local variables in Git’s delta-compression and pack-objects code from `unsigned long` or `int` to `size_t` to prevent integer truncation on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` does not match the pointer width. This is part of the ongoing effort to eliminate incorrect `unsigned long` usage in favor of `size_t`.

Current status
Ready for integration; v2 posted and all review feedback incorporated. Patrick Steinhardt’s substantive review of v2 confirms that all requested changes from his v1 feedback are now addressed: the `sizeof_delta_index()` return type is widened, the new `git_parse_size_t()` and `git_config_size_t()` helpers correctly handle the now-wider `max_delta_cache_size`, and the commit message for the `git_deflate_bound()` patch (12/12) includes references to zlib’s stored-block logic. No further revisions are expected; the series is uncontroversial, mechanically correct, and awaits Junio’s merge to `next` in the next "What's cooking" cycle. The twelve-patch split remains unchanged, reflecting the breadth of the delta/pack code rather than complexity.
