Thread identity
Subject: [PATCH 0/12] Widen size fields in delta/pack machinery for 64-bit Windows
Series version: v1
Originating author: Johannes Schindelin (via GitGitGadget)
Thread type: patch series (platform-compatibility fix)

Core problem or goal
Widen size-related fields, parameters, and local variables in Git’s delta-compression and pack-objects code from `unsigned long` or `int` to `size_t` to prevent integer truncation on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` does not match the pointer width. This is part of the ongoing effort to eliminate incorrect `unsigned long` usage in favor of `size_t`.

Current status
Under review; v1 posted. No prior versions. The series is mechanical and confined to type widening; no behavior or on-disk format changes.

Key technical details
- Files touched: 17, primarily in the delta (`diff-delta.c`, `delta.h`), pack-objects (`pack-objects.c`, `pack-objects.h`), and zlib (`git-zlib.c`) subsystems; also `http-push.c`, `archive-zip.c`, `builtin/fast-import.c`, `builtin/pack-objects.c`, `diff.c`, and test helpers (`t/helper/test-delta.c`, `t/helper/test-pack-deltas.c`).
- New/renamed symbols: `struct delta_index` size fields (`src_size`, `trg_size`, `max_size`), `create_delta_index()` and `create_delta()` parameters (including `bufsize` in `create_delta_index()` and all size parameters in `create_delta()` and `diff_delta()`), delta-cache accounting variables (`delta_cache_size`, `max_delta_cache_size`, `delta_cacheable()`) in `pack-objects.c`, zlib stream fields in `git-zlib.c`, the return type of `free_unpacked()` in `builtin/pack-objects.c`, and the `mem_usage` counter in `find_deltas()` and corresponding output parameter in `try_delta()` (widened from `unsigned long` to `size_t`).
- Internal preparatory work: Patch 1 widened `src_size` and `memsize` in the private `struct delta_index` (defined in `diff-delta.c`) from `unsigned long` to `size_t`; Patch 2 widens the `bufsize` parameter of `create_delta_index()` from `unsigned long` to `size_t` in both declaration (`delta.h`) and definition (`diff-delta.c`). Patch 3 widens the global counters `delta_cache_size` and `max_delta_cache_size`, and the helper function `delta_cacheable()` in `builtin/pack-objects.c` from `unsigned long` to `size_t`, matching the `size_t` return type of `DELTA_SIZE()` that feeds into these counters. The sole caller (`try_delta()`) still passes `unsigned long` parameters, which safely promote to `size_t`. Patch 4 widens the return type of `free_unpacked()` from `unsigned long` to `size_t` to prevent truncation when summing `sizeof_delta_index()` (already `size_t`) and `SIZE(n->entry)` (widened to `size_t` in an earlier topic). Patch 5 widens the `mem_usage` counter in `find_deltas()` and the corresponding output parameter in `try_delta()` from `unsigned long` to `size_t`, ensuring type consistency in the delta-window memory accounting chain. The `window_memory_limit` configuration value remains `unsigned long` but safely promotes when compared against `mem_usage`. Patch 6 widens all size parameters and output variables in `create_delta()` and `diff_delta()` from `unsigned long` to `size_t` in both declaration (`delta.h`) and definition (`diff-delta.c`), then updates callers. Most callers still use `unsigned long` downstream (e.g., zlib’s `avail_in` or test helpers), so the patch introduces temporary `size_t` variables and `cast_size_t_to_ulong()` shims to bridge the gap; these shims are noted as temporary and will be removed in later topics that widen the downstream consumers. The only caller widened outright is `t/helper/test-delta.c`, which has no downstream constraints.
- Behavior change: none; this is a pure type-widening correctness fix.
- On-disk format change: none.
- Test coverage: unchanged; no new tests added.
