Core problem or goal
Widen size-related fields, parameters, and local variables in Git’s delta-compression and pack-objects code from `unsigned long` or `int` to `size_t` to prevent integer truncation on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` does not match the pointer width. This is part of the ongoing effort to eliminate incorrect `unsigned long` usage in favor of `size_t`.

Current status
Under review; v2 posted and all review feedback incorporated. The series is uncontroversial, mechanically correct, and ready for integration. No further changes are expected. The twelve-patch split remains unchanged. The final patch (12/12) widens `git_deflate_bound()`—both its parameter and return type—from `unsigned long` to `size_t`, completing the type-consistency chain across all callers (archive-zip, diff, http-push, test helpers, remote-curl, and fast-import). The fallback formula for inputs exceeding zlib’s `uLong` range (>4 GiB on 64-bit Windows) mirrors zlib’s stored-block logic plus worst-case wrapper overhead, ensuring correctness without behavior change for inputs within `uLong`. The code is guarded by `#if SIZE_MAX > ULONG_MAX` to avoid overhead on platforms where `unsigned long` is already 64-bit.
