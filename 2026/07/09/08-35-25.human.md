This is the fifth patch in Patrick Steinhardt’s seven-part series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch adds a new function, `prepare_bitmap_git_for_source()`, which opens a bitmap belonging to a specific object source rather than the first available bitmap across all sources.

The motivation is clear: the packed ODB backend (which will soon use bitmaps for object filtering) operates on a single source, so using a bitmap from a different source would misattribute objects, duplicate enumeration, and potentially cause correctness issues. The new function ensures bitmaps are scoped to the correct source, addressing these risks. The implementation is straightforward—allocating a `bitmap_index` struct, attempting to open and load the bitmap for the given source, and cleaning up on failure.

This change is a necessary plumbing step for the series’ broader goal of enabling `git cat-file --batch-all-objects` to work with pluggable ODB backends. It’s a small but critical refactoring, with no behavior changes in this patch itself. The commit message and code are well-explained, and the patch looks technically sound. Reviewers focused on ODB internals or bitmap handling will likely want to pay attention to this one.
