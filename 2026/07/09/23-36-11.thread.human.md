This thread is about a small but useful extension to Git’s hook system. Domen Kožar has proposed a patch that runs the existing `post-worktree-remove` hook not only when worktrees are explicitly removed (`git worktree remove`) but also when they are pruned (`git worktree prune`). The hook now fires once per pruned worktree, including duplicates, and receives the worktree path when it can be determined. If the path is unavailable, the hook gets an empty string instead.

The implementation touches the worktree internals in `worktree.c` and the built-in command in `builtin/worktree.c`, updates the hook documentation, and adds thorough tests covering dry runs, missing paths, and hook failures. Domen’s patch is the third in a v1 series; the earlier patches and cover letter weren’t included, so we don’t know if there are other changes in the series, but this one stands on its own as a clean, well-tested feature.

So far there’s no review traffic on the list, so the patch is still in its initial “under review” state. If it follows the usual pattern, we’ll see feedback in the next few days; given the narrow scope and good test coverage, it’s likely to be uncontroversial and could land in `next` soon.
