This is the fourth patch in Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch restructures how Git opens bitmaps by iterating over object sources first, rather than iterating over multi-pack indices and packfiles separately. This refactoring prepares the ground for a later patch that will allow opening bitmaps for a single object source, a requirement for making `git cat-file --batch-all-objects` work with pluggable backends.

The change touches only `pack-bitmap.c` and is purely internal: it reverses the loop order so that the outer loop iterates over object sources, while the inner loop tries to load either a multi-pack index bitmap or a packfile bitmap for that source. The commit message notes a subtle edge case where this alters bitmap precedence—local packfile bitmaps now take priority over multi-pack index bitmaps in alternates—but argues this is an improvement and that repositories with multiple bitmaps are already broken.

The patch is clean and well-motivated, with a clear explanation of why the refactoring is needed. It looks like a necessary step toward the series’ goal, and the code changes are straightforward. Reviewers focused on the ODB abstraction or bitmap handling will likely want to pay attention.
