This is the eighth patch in Johannes Schindelin’s 12-patch series widening size fields in Git’s delta and pack machinery for 64-bit Windows compatibility. The series is part of the broader effort to replace `unsigned long` with `size_t` where appropriate, preventing integer truncation on platforms where `unsigned long` is 32-bit.

This patch widens a single local variable, `maxsize`, in `archive-zip.c` from `unsigned long` to `size_t`. The variable holds the return value of `git_deflate_bound()`, which will be widened to `size_t` in a later patch. Without this change, the upcoming widening would silently truncate the value on 64-bit Windows, where `size_t` is 64-bit but `unsigned long` remains 32-bit. The patch is purely preparatory; it has no effect on current behavior since `size_t` and `unsigned long` are the same width on all platforms where this code runs today.

The change is mechanical and confined to one line in `archive-zip.c`. The commit message clearly explains the motivation and the preparatory nature of the work. This is a low-risk, uncontroversial patch that fits neatly into the larger series. Readers interested in Windows compatibility or the ongoing `unsigned long` cleanup effort will find it relevant, but it is unlikely to attract significant discussion on its own.
