This is the tenth patch in Johannes Schindelin’s 12-patch series widening size-related fields in Git’s delta and pack machinery to `size_t` for 64-bit Windows correctness. It fixes a latent type mismatch in `http-push.c`: the local `size` in `start_put()` is changed from `ssize_t` to `size_t` because it is initialized from `git_deflate_bound()` (an unsigned upper bound) and passed only to `strbuf_grow()` and `stream.avail_out`, both of which already expect `size_t`. The original `ssize_t` was technically wrong—values above `SSIZE_MAX` would wrap negative on assignment and then implicitly re-extend to a huge `size_t` at the call sites, risking absurd allocation requests. While this is not a practical issue for today’s object sizes, the change is necessary before `git_deflate_bound()` itself is widened in a later patch. The fix is a one-line type substitution in `http-push.c` with no behavior change.
