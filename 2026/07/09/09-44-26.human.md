This is a surface-level review of the `git refs delete` subcommand in Patrick Steinhardt’s merged series. Toon Claes questions the behavior of `--no-deref` when deleting symbolic references (symrefs). The current implementation checks the *target OID* of the symref (e.g., the OID of `refs/heads/foo` if `symref` points to it), but Toon expected it to check the *target ref name* (e.g., `refs/heads/foo` itself) instead. His proposed test case would make the command fail if the provided ref name (`refs/heads/bar`) doesn’t match the symref’s target (`refs/heads/foo`), even if their OIDs are identical.

The distinction is subtle but important for atomicity: Toon’s version would enforce that the symref’s target *name* matches the expected value, while the current version only checks the target’s OID. Neither approach is inherently wrong, but the difference highlights a potential usability gap—users might assume `--no-deref` behaves like a string comparison rather than an OID check. The series is already merged, so this feedback is unlikely to trigger changes unless others weigh in on the design.
