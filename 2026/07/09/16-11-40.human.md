This is the fourth patch in Tian Yuchen’s v9 series migrating global configuration variables into `struct repo_config_values`. It moves the `pager_program` variable out of a file-scoped static in `pager.c` and into the repository-specific structure, mirroring the pattern already established for `editor_program` and `excludes_file`.

The patch is a clean refactoring: the configuration parsing stays in `pager.c`, but read/write operations now go through `repo_config_values(the_repository)->pager_program`. Memory management is handled by `repo_config_values_clear()`, which frees the heap-allocated string during repository teardown. The only functional change is the fix for a memory leak in `core_pager_config()`—the old value is now freed before re-assignment, resolving the regression Junio flagged in v8.

No user-visible behavior changes; this is foundational work for the ongoing `the_repository` removal effort. The patch is CI-clean, well-explained, and ready for `next`. The remaining open question—whether migrating program paths like the pager is worthwhile—is explicitly addressed in the commit message but does not block this change.
