This is patch 6/9 of Tian Yuchen's v9 series migrating global configuration variables into `struct repo_config_values`. It moves the `apply_default_whitespace` and `apply_default_ignorewhitespace` strings from globals into the repository-specific structure, continuing the libification effort.

The patch updates `git_apply_config()` to accept a `struct repository *` parameter instead of relying on `the_repository`, and modifies all callers to pass the repository instance. The strings are now heap-allocated via `repo_config_get_string()` and freed in `repo_config_values_clear()`, matching the memory management pattern established in earlier patches. No getters are introduced; callers access the fields directly through `repo_config_values(repo)-><field>`.

Files touched are `apply.c`, `environment.c`, and `environment.h`. The changes are mechanical and follow the same pattern as the prior string migrations in this series (editor, pager, askpass). The patch is CI-clean and resolves the memory leak concerns Junio raised in v8 by ensuring proper cleanup during re-assignment.

This is a foundational refactoring with no user-visible behavior changes. It prepares the `git apply` subsystem for further modularization and eliminates two more globals. The series remains on track for `next` once the remaining patches are reviewed.
