This is the eighth patch in Tian Yuchen's v9 series migrating global configuration variables into `struct repo_config_values` as part of the ongoing `the_repository` removal effort. This patch moves the `autorebase` enum (which controls whether newly created branches default to rebasing) into the repository-specific configuration structure.

The patch relocates the `enum rebase_setup_type` definition higher in `environment.h` to make it visible to `struct repo_config_values`, then adds an `autorebase` field to the structure. The default value `AUTOREBASE_NEVER` is initialized in `repo_config_values_init()`, and configuration parsing in `git_default_branch_config()` is updated to write directly to the repository's configuration instance. The only caller (`should_setup_rebase()` in `branch.c`) is updated to read from `repo_config_values(the_repository)->autorebase` instead of the global variable.

This is a clean, mechanical migration with no user-visible behavior changes. The patch follows the established pattern from earlier patches in the series, and the enum relocation is necessary to avoid visibility issues. No memory management concerns apply (enums are not heap-allocated). The patch is technically sound and ready for integration, though the series as a whole still has open RFC questions about the broader design.
