This thread is a 12-patch series from Johannes Schindelin, posted via GitGitGadget, that widens size-related fields in Git’s delta and pack-objects code from `unsigned long` to `size_t`. The goal is to prevent integer truncation on 64-bit Windows, where `unsigned long` is 32-bit, and other platforms where the type’s width doesn’t match pointer size. This is part of a broader effort to replace incorrect `unsigned long` usage with `size_t` across the codebase.

The series is currently under review, with no prior versions. The first patch, which just landed, is purely preparatory: it widens two fields (`src_size` and `memsize`) in the private `struct delta_index` in `diff-delta.c` from `unsigned long` to `size_t`. Since the struct isn’t exposed outside the file, this change has no runtime effect yet—it’s setting the stage for later patches that will update the public APIs. The patch is mechanical, with no logic or behavior changes, and is uncontroversial.

Johannes, the Git for Windows maintainer, is the sole participant so far. The series touches 14 files, primarily in the delta, pack-objects, and zlib subsystems, and doesn’t alter on-disk formats or add new tests. No open questions or objections have been raised yet, but the thread is just getting started. If you’re working on Windows compatibility or the delta/pack code, this is worth following.
