This thread is a twelve-patch series from Johannes Schindelin, posted via GitGitGadget, that widens size-related fields in Git’s delta-compression and pack-objects code from `unsigned long` or `int` to `size_t` to prevent integer truncation on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` doesn’t match the pointer width. The series is part of the ongoing effort to replace incorrect `unsigned long` usage with `size_t` for better type safety.

The patches are mechanical and confined to type widening, touching around 20 files across subsystems like delta handling, pack-objects, zlib wrappers, and diff code. The final patch, just posted, updates `git_deflate_bound()`—the last `unsigned long` holdout in the zlib wrapper—to use `size_t` for both its parameter and return type. This change includes a compile-time guard to handle platforms where zlib’s `uLong` type is narrower than `size_t`, ensuring correctness for large inputs without altering behavior for smaller ones. All callers were already updated in earlier patches, so no narrowing conversions remain.

The series is under review and remains uncontroversial, with no prior versions or open questions. It’s a preparatory step for the broader `unsigned long` to `size_t` conversion effort, motivated by real-world truncation issues on 64-bit Windows. No behavior or on-disk format changes are introduced, and test coverage is unchanged.
