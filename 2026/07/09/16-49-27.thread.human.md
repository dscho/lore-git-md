This thread is about a twelve-patch series from Johannes Schindelin that widens size-related fields in Git’s delta-compression and pack-objects code from `unsigned long` or `int` to `size_t`. The goal is to prevent integer truncation on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` doesn’t match the pointer width. This is part of a broader effort to replace incorrect `unsigned long` usage with `size_t` throughout Git.

The series is now at version 2, addressing all feedback from Patrick Steinhardt’s review of v1. The changes are mechanical and uncontroversial, with no behavior or on-disk format changes. The latest email covers the eleventh patch, which widens the `maxsize` local variable in a test helper (`t/helper/test-pack-deltas.c`) from `unsigned long` to `size_t`. This is purely preparatory for the next patch, which will widen `git_deflate_bound()`’s return type. The entire series is ready for integration, with no open questions or loose ends remaining. Key participants are Johannes Schindelin (author) and Patrick Steinhardt (reviewer), both of whom have signed off on the current state.
