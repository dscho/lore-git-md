This thread is about a 12-patch series from Johannes Schindelin that fixes integer truncation risks in Git’s delta-compression and pack-objects code on 64-bit Windows, where `unsigned long` is only 32 bits. The series widens size-related fields, parameters, and variables to `size_t` to match the pointer width, addressing a real-world compatibility issue while preparing for broader `unsigned long` cleanup across the codebase.

The second version of the series, now under review, has incorporated all feedback from Patrick Steinhardt on the initial posting. Key changes include widening the return types of `sizeof_delta_index()` and `free_unpacked()`, introducing `git_config_size_t()` to correctly parse configuration values, and ensuring the delta-window memory accounting chain is fully 64-bit safe. The series remains mechanical—no behavior or on-disk format changes—and is split into twelve patches for clarity, though earlier discussion suggested squashing.

Johannes has addressed every technical concern raised in the first round, and the series is now uncontroversial and ready for integration. The patches touch 21 files across the delta, pack-objects, zlib, and diff subsystems, with no new tests added since the changes are purely type-related. The work is part of a larger effort to eliminate incorrect `unsigned long` usage, and while it’s motivated by Windows compatibility, it benefits other platforms where `unsigned long` doesn’t match the pointer width.
