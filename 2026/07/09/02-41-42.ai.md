This is a refactoring patch that prepares the ground for an upcoming feature in the `includeIf` conditional configuration mechanism. It is the second patch in Chen Linxuan’s v7 series (3/3 total).

The patch adds a new field `worktree_original` to the `repository` struct and a corresponding accessor `repo_get_work_tree_original()`. This field stores the user-facing, symlink-preserving spelling of the worktree path—absolute and normalized, but not realpath-resolved—so that a future patch can match it against `includeIf.worktree:` patterns the same way `gitdir:` already matches both real and symlinked spellings. The commit message is clear: the motivation is to preserve the original path that the user actually typed (or that the shell’s `$PWD` recorded) rather than the canonicalized realpath that Git has historically stored.

The implementation is careful: `repo_set_worktree()` now computes both the realpath (unchanged) and the symlink-preserving copy, falling back to the realpath if normalization fails. In the discovered-repository case—where Git has already `chdir()`’d to the worktree root—`logical_path_from_cwd()` recovers the original spelling from `$PWD` by verifying that it still refers to the same filesystem entry (same device and inode) and that the below-root suffix matches the physical path exactly. The patch also wires up the new field in `repo_clear()` to avoid leaks.

No callers use the new accessor yet; that is left for the next patch in the series. The code is clean, well-commented, and touches only the repository and setup subsystems. It looks like a solid, uncontroversial plumbing change that enables the feature without changing any observable behavior.
