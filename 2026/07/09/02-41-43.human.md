This is the final patch in a well-crafted three-part feature series introducing `includeIf worktree:<pattern>` and `worktree/i:<pattern>` to Git’s config system. The patch adds the new condition keywords, wires them into the config machinery, and provides thorough test coverage.

The implementation reuses the `include_by_path()` helper (refactored in patch 1) and passes it the symlink-preserving worktree path stored by the preparatory commit. This ensures consistent behavior with the existing `gitdir:` condition: both the logical and physical paths are matched, so users can write patterns using either spelling. The condition never matches in bare repositories or during early config reading, where no worktree exists.

Documentation is clear and practical, showing real-world examples (e.g., different `user.name`/`user.email` for personal vs. work directories) and contrasting the feature with `extensions.worktreeConfig`. Tests cover symlinked worktrees, case sensitivity, bare repositories, early config, and non-repository scenarios.

This is a clean, user-facing feature with no on-disk format changes or new CLI options. The v7 iteration addresses all prior feedback from Patrick Steinhardt and Junio C Hamano, and the series looks ready for serious review. If you work with multiple worktrees, this patch is worth your attention.
