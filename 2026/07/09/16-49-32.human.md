This is the fifth patch in Johannes Schindelin’s 12-patch series widening size-related fields in Git’s delta and pack machinery to `size_t` for 64-bit Windows compatibility. The patch targets `builtin/pack-objects.c`, widening the `mem_usage` counter and the corresponding output parameter in `try_delta()` from `unsigned long` to `size_t`.

The change is mechanical and necessary: `mem_usage` accumulates byte counts (via `SIZE()` and `sizeof_delta_index()`) that are already `size_t`, and on 64-bit Windows, `unsigned long` is 32-bit, risking truncation. The patch ensures type consistency in the delta-window memory accounting chain, leaving only `sizeof_delta_index()`’s return type (bounded by design) as the remaining narrow point. The config-driven `window_memory_limit` remains `unsigned long` but safely promotes when compared to `mem_usage`.

This is a straightforward, low-risk fix addressing a real platform-specific issue. The patch is uncontroversial and aligns with the broader effort to eliminate incorrect `unsigned long` usage in favor of `size_t`. No behavior or on-disk format changes are introduced. For readers tracking the series, this patch resolves the last 32-bit narrowing point in the delta-window memory accounting path.
