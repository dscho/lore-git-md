This is a substantive review comment on patch 6/11 of Justin Tobler’s v3 series converting `git-receive-pack` to use ODB transactions. Junio C Hamano raises a safety concern about the error-handling flow in the newly refactored `odb_transaction_begin()`: if `odb_source_begin_transaction()` fails, the caller’s `*out` pointer might be left in an undefined state, potentially leading to a dangling reference or double-free if the caller proceeds under the assumption that `*out` is valid.

The question is whether `odb_source_begin_transaction()` guarantees that `*out` remains untouched on failure, or whether the caller must defensively guard against a partially written output parameter. Junio suggests a conditional assignment pattern (`if (!(ret = ...)) odb->transaction = *out;`) to ensure the ODB’s internal state (`odb->transaction`) is updated only when the backend call succeeds.

This is a classic low-level C safety issue: output parameters in error paths are a common source of subtle bugs, and the review is probing whether the patch’s error-handling logic is robust against backend failures. The answer will determine whether the patch needs a follow-up fix or whether the current implementation is already safe. No other aspects of the patch are under discussion here.
