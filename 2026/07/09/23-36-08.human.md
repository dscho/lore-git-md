This is a feature patch series introducing new Git hooks for worktree events. Domen Kožar, maintainer of devenv, proposes adding `post-worktree-add` and `post-worktree-remove` hooks to address a gap in automation for worktree lifecycle management, particularly in AI-driven development workflows where worktrees are created and destroyed rapidly.

The series consists of three patches: the first adds the `post-worktree-add` hook, which runs after a worktree is fully set up (and after `post-checkout` if it exists); the second adds `post-worktree-remove` for `git worktree remove`; and the third extends the remove hook to also fire during `git worktree prune`, covering manually deleted worktrees. The implementation handles edge cases like missing or corrupt gitdir files by passing an empty string to the hook when the path cannot be determined.

The motivation is clear and practical: current hooks like `post-checkout` don’t fire for `--no-checkout` or `--orphan` worktrees, and there’s no way to clean up external resources (like databases or services) when a worktree is removed. The patches include thorough test coverage in `t2400-worktree-add.sh`, `t2401-worktree-prune.sh`, and `t2403-worktree-move.sh`, suggesting the implementation is well-tested. The commit messages and documentation updates are detailed, making the changes easy to understand.

Two design questions are explicitly flagged for feedback: whether `post-worktree-add` should run even if `post-checkout` fails (currently it doesn’t), and how to handle path resolution for pruned worktrees with missing or corrupt gitdir files. These are reasonable points of discussion and don’t detract from the overall quality of the series. The patches look like a clean, well-scoped addition that addresses a real need without overcomplicating the codebase. For anyone managing worktrees at scale, this is likely worth paying attention to.
