This is a review of the fourth patch in Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch refactors how Git opens bitmaps by iterating over object sources first, then attempting to load a bitmap for each source, rather than searching all sources for a multi-pack index bitmap and then all sources for a packfile bitmap. This change is a prerequisite for later patches in the series and improves clarity while altering bitmap precedence in edge cases (now preferring local bitmaps over those in alternates).

Justin Tobler’s review is substantive but narrowly focused. He confirms the refactoring’s direction is sound and easier to follow, and agrees the bitmap precedence change is acceptable given that multiple bitmaps in a repository are already warned against. His feedback is minor: he suggests a slightly more readable style for a conditional in `open_bitmap_for_source()` (using an explicit `if` rather than a negated return value) and notes that the logic for skipping further searches once a bitmap is found is clear. No technical objections are raised, and the review does not identify any bugs or edge cases that would block the patch. The discussion remains constructive and focused on code clarity rather than correctness.

The patch itself is a clean refactoring with no user-visible behavior change, and the commit message clearly explains the motivation and edge-case implications. Reviewers focused on ODB backends or bitmap performance may want to verify the new precedence logic, but the change looks uncontroversial and well-justified. This patch is likely to be accepted as-is or with minor stylistic tweaks.
