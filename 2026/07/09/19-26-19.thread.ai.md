Subject: [PATCH] builtin/add.c: refactor `git add -e` to use internal apply API
Series version: standalone patch (v4 posted, now approved)

Thread type: patch submission (refactoring)

Core problem or goal
Replace the subprocess call to `git apply` in the `git add -e` (interactive edit) command with a direct invocation of Git’s internal `apply_all_patches()` API to eliminate fork overhead, keep the operation in-process, and improve code clarity.

Current status
Approved by Junio C Hamano in v4. The patch is ready for merging to `next`; no further technical issues are known. The v4 update resolved the subdirectory correctness risk by passing `NULL` as the prefix argument to `init_apply_state()`, ensuring the path from `repo_git_path()` is passed unchanged to the apply machinery. A new test in `t/t3702-add-edit.sh` explicitly verifies subdirectory operation. All 58 tests in `t3700-add.sh` and the expanded `t3702` (now 5 tests) pass.

Key technical details
- Files touched: `builtin/add.c`, `t/t3702-add-edit.sh`
- New symbols: none (uses existing `apply_all_patches()` and `apply_state` struct)
- Removed includes: `run-command.h`, `strvec.h`
- Added include: `apply.h`
- Behavior: unchanged in intent; the internal apply path now correctly handles subdirectory operation by passing `NULL` as the prefix to `init_apply_state()`, ensuring `repo_git_path()`’s output (absolute or relative) is used as-is.
- Test coverage: existing `t3700-add.sh` (58 tests) and `t3702-add-edit.sh` (5 tests, including the new subdirectory test) pass.
