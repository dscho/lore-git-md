Core problem or goal
Replace the subprocess call to `git apply` in the `git add -e` (interactive edit) command with a direct invocation of Git’s internal `apply_all_patches()` API. The goal is to eliminate the overhead of forking a child process, keep the operation in-process, and improve code clarity.

Current status
Under review (v1 posted). Junio C Hamano has raised a correctness concern: the patch omits a required `check_apply_state()` call, which may cause the internal apply API to silently skip writing the edited patch back to the index. No updated version has been posted.

Key technical details
- Files touched: `builtin/add.c` only
- New symbols: none (uses existing `apply_all_patches()` and `apply_state` struct)
- Removed includes: `run-command.h`, `strvec.h`

- Behavior: intended to be unchanged, but Junio’s review indicates the current patch may not update the index as expected due to missing state initialization
