This is the ninth patch in Johannes Schindelin’s eleven-patch bugfix series (`js/coverity-fixes-v2`) that plugs NULL-dereference holes found by Coverity. It targets the MIDX bitmap subsystem in `pack-bitmap.c`.

The issue is straightforward: when `prepare_midx_bitmap_git()` is called to load the bitmap for a chained MIDX’s base layer, it can return NULL if the base MIDX lacks a bitmap (e.g., it was written without `--write-bitmap-index` or the bitmap was pruned by `gc`). The code immediately dereferences that NULL pointer on the next line. The fix adds a NULL check and, if the base bitmap is missing, jumps to the existing cleanup label that unmaps the current bitmap and returns -1, forcing the caller to fall back to non-bitmap object enumeration.

The change is minimal—four lines added—and matches the error-handling pattern already used elsewhere in the same function for other bitmap-loading failures. No new behavior is introduced; the patch simply prevents a crash in an edge case that can occur in real-world incremental MIDX chains.
