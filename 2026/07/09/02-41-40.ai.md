This is a feature patch series (v7) adding a new `includeIf` condition to Git’s config system. The series introduces `worktree:<pattern>` and `worktree/i:<pattern>` keywords, allowing users to conditionally include configuration files based on the working tree’s path, which is particularly useful in multi-worktree setups where the `.git` directory’s location is not intuitive.

The implementation reuses the existing `include_by_path()` helper, now extended to support symlink-preserving path matching (consistent with the existing `gitdir:` behavior). The preparatory commit stores a symlink-preserving copy of the worktree path, and the final commit wires this into the `includeIf` mechanism. The series includes thorough test coverage for symlinked paths, case sensitivity, bare repositories, and early config reading scenarios.

This is a well-motivated feature with clear use cases for multi-worktree workflows. The v7 iteration addresses feedback from Patrick Steinhardt and Junio C Hamano, including better symlink handling and improved test coverage. The series is split into logical commits, and the documentation includes a comparison with `extensions.worktreeConfig`. The changes are confined to `config.c`, `repository.c`, and `setup.c`, with no behavior changes outside the new feature. The patch looks ready for serious review.
