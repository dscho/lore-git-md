This is the seventh patch in Johannes Schindelin’s 12-patch series widening size-related fields in Git’s delta and pack machinery from `unsigned long` to `size_t` for 64-bit Windows compatibility. The patch targets two tightly coupled changes: widening the `avail_in`/`avail_out` fields in `struct git_zstream` and the `*left` output parameter of `use_pack()` from `unsigned long` to `size_t`.

The rationale is mechanical consistency: four call sites in `builtin/pack-objects.c` and `pack-check.c` pass `&stream.avail_in` directly to `use_pack()`, so widening either side alone would require temporary bridge variables at each call. By widening both together, the patch avoids that clutter and prepares the ground for the next commit (patch 8/12), which will widen `do_compress()` and eliminate the last `cast_size_t_to_ulong()` shim in `write_no_reuse_object()`.

Files touched are `builtin/pack-objects.c`, `git-zlib.h`, `pack-check.c`, `packfile.c`, and `packfile.h`. The changes are purely type substitutions; no logic or behavior is altered. The commit message notes that the widened locals (`avail`, `remaining`, `left`) are bounded by `core.packedGitWindowSize`, so the patch is about type consistency rather than enabling >4GB windows. Similarly, `git_zstream.avail_in`/`avail_out` are already capped by `zlib_buf_cap()` at 1 GiB, so the wrapper effectively already accepted `size_t`-shaped inputs.
