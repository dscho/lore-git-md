This is a review comment from Junio C Hamano on patch 4/9 of Tian Yuchen’s v8 series, which migrates the `pager_program` global variable into `struct repo_config_values`. The series is part of the ongoing libification effort to eliminate globals and centralize memory management.

Junio’s concern is straightforward: the patch fixes a memory leak in `check_pager_config()` by freeing the old `pager_program` value before re-assignment, but it does *not* apply the same fix to `core_pager_config()`. Both functions call `git_config_string()`, which overwrites the target pointer without freeing the previous value, so `core_pager_config()` still leaks memory when the same configuration key is set multiple times (e.g., during repeated `git_config()` calls or in long-running processes). The fix in `check_pager_config()` is correct but incomplete.

The review is substantive: it identifies a real bug (a memory leak) and pinpoints the exact location where the fix is missing. The observation is precise, referencing the function name and the problematic line, and the suggested remedy (applying the same `free()` pattern as in `check_pager_config()`) is clear. No new tests or behavioral changes are implied; this is purely a correctness fix for the refactoring.
