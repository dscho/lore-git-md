This is the fifth patch in Johannes Schindelin’s 12-patch series widening size-related fields in Git’s delta and pack machinery from `unsigned long` to `size_t` for 64-bit Windows compatibility. The patch widens the `mem_usage` counter in `find_deltas()` and the corresponding output parameter in `try_delta()` from `unsigned long` to `size_t`, ensuring type consistency in the delta-window memory accounting chain.

The change is mechanical and confined to `builtin/pack-objects.c`, adjusting only the two variables that must move together to maintain type safety. The commit message explains that `mem_usage` accumulates byte counts already computed as `size_t` (via `SIZE()` and `sizeof_delta_index()`), making this the last narrowing point in the chain on platforms where `unsigned long` is 32-bit. The `window_memory_limit` configuration value remains `unsigned long` but safely promotes when compared against `mem_usage`.

This patch is a straightforward correctness fix with no behavior or on-disk format changes, continuing the series’ focus on eliminating integer truncation risks in large-object handling. The adjustment is uncontroversial and aligns with the broader effort to replace `unsigned long` with `size_t` where appropriate. No new test coverage is added, as the change is purely internal. The patch builds on earlier work in the series, particularly the widening of `free_unpacked()`’s return type in patch 4.
