This is the first patch in Kristofer Karlsson’s two-patch bugfix series targeting a performance regression in split commit-graph chains. It adds trace2 instrumentation to `compute_reachable_generation_numbers()` in `commit-graph.c`, exposing the number of DFS steps taken during topological-level computation. The instrumentation is diagnostic: it lets users observe when the code falls back to a full ancestry walk instead of reading existing topological levels from lower graph layers. The test in `t/t5324-split-commit-graph.sh` is updated to expect exactly one DFS step after the fix lands; for now it is marked `test_expect_failure` to demonstrate the bug. No behavior change is introduced—this patch only surfaces the regression so the fix in patch 2/2 can be verified. The commit message cites the regressing commit (`199d452758`, September 2025) and quantifies the performance impact (233 ms → 4133 ms). The patch is uncontested and part of a series already merged to `master`.
