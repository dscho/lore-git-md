This is the eighth patch in Johannes Schindelin’s eleven-patch bugfix series (`js/coverity-fixes-v2`) addressing NULL-dereference issues identified by Coverity. This installment targets the `add_parents_only()` function in `revision.c`, which resolves revision suffixes like `commit^@` (all parents) and `commit^!` (commit minus parents).

The function calls `get_reference()` in a loop to peel through tag objects until it reaches a commit. The existing NULL check after `get_reference()` only handled the `ignore_missing` case, but `get_reference()` can return NULL through three distinct paths: `ignore_missing`, `exclude_promisor_objects`, and `do_not_die_on_missing_objects`. The latter two cases previously fell through to dereference the NULL pointer, risking a crash.

The patch adds explicit handling for all three cases. For `ignore_missing` and `do_not_die_on_missing_objects`, it returns 0, matching the existing behavior and the pattern in `handle_revision_arg()`. For the `exclude_promisor_objects` case, it returns -1, consistent with how `handle_revision_arg()` treats promisor objects. The commit message notes that callers in `handle_revision_pseudo_opt()` treat any nonzero return as "handled," so the -1 for promisor objects is effectively indistinguishable from success—meaning a promisor-excluded tag target referenced via `commit^@` would be silently skipped rather than producing an error. This is a pre-existing limitation, and the patch’s defensive programming is strictly an improvement over the previous NULL-dereference risk.

The change is narrow and well-motivated, touching only the control flow in `add_parents_only()` without altering its core logic or introducing new behavior. Like the rest of the series, it is uncontroversial and ready for review. The patch is part of a broader effort to harden Git’s revision-parsing code against edge cases, and its inclusion in the series reinforces the value of static analysis tools like Coverity in catching subtle bugs.
