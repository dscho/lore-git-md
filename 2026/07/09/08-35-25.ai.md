This is the fifth patch in Patrick Steinhardt’s seven-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. It adds a new function, `prepare_bitmap_git_for_source()`, to open bitmaps exclusively for a single object source.

The patch addresses a correctness issue in the upcoming use of bitmaps by the "packed" ODB backend: `prepare_bitmap_git()` currently opens the first available bitmap from any connected source, which could lead to misattribution of objects, redundant enumeration, and incorrect source info when multiple sources exist. The new function ensures bitmaps are only opened for the specified source, avoiding these problems.

The change is minimal and focused: it adds the new function in `pack-bitmap.c` and declares it in `pack-bitmap.h`. The implementation reuses existing helpers (`open_bitmap_for_source()` and `load_bitmap()`) and follows the same error-handling pattern as `prepare_midx_bitmap_git()`. The commit message clearly explains the motivation and edge cases, making the rationale easy to follow.

This patch is a prerequisite for the next one, which will teach the "packed" backend to use bitmaps for object filtering. It looks well-crafted and uncontroversial, with no obvious loose ends or open questions. The series as a whole is shaping up as a clean step toward pluggable ODB backends.
