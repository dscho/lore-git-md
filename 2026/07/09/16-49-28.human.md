This is the first patch in a 12-part platform-compatibility series targeting 64-bit Windows. It widens the size fields in `struct delta_index` (used internally by the delta-compression code) from `unsigned long` to `size_t`. The change is preparatory: the struct is private to `diff-delta.c`, so widening its fields now allows later patches to update the public API without mixing type changes with logic changes.

The patch itself is mechanical—three field declarations in one file—and introduces no runtime behavior change. On Windows, where `unsigned long` is 32-bit, the values still fit because the surrounding API still truncates them. The commit message explains the rationale clearly: this split keeps the API-change commit (coming later) focused on caller updates rather than internal plumbing.

This is a clean, low-risk refactoring that aligns with the broader effort to replace `unsigned long` with `size_t` for size-related fields. No controversy is expected; the patch is straightforward and well-motivated by the Windows platform’s constraints.
