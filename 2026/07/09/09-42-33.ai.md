This is the sixth patch in Johannes Schindelin’s eleven-patch bugfix series (`js/coverity-fixes-v2`) addressing NULL-dereference issues identified by Coverity. The series as a whole targets defensive programming gaps across multiple subsystems; this patch specifically guards against a NULL commit in `bisect_successful()` in `builtin/bisect.c`.

The fix adds a NULL check for the commit returned by `lookup_commit_reference_by_name()`. If the commit is NULL (a rare but possible edge case due to concurrent gc or repository corruption), the function now returns an error rather than dereferencing the pointer in `repo_format_commit_message()`. The change is minimal: five lines added immediately after the lookup, preserving the existing control flow and error handling.

No new behavior is introduced; the patch is purely defensive. The commit message explains the edge case clearly and cites Coverity as the source of the report. Given that `bisect_successful()` is only called after a successful bisect run, the NULL case is unlikely in practice, but the guard is a reasonable safeguard against undefined behavior.

The patch is uncontroversial and fits the pattern established by the rest of the series: small, focused, and well-motivated. No tests are added, but the change is narrow enough that existing test coverage should suffice to verify it does not break normal operation.
