Subject: [PATCH 0/7] Introduce object filters to odb_for_each_object()
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Enable `git cat-file --batch-all-objects` to work with pluggable object databases by removing its dependency on internal details of the "packed" backend, specifically for efficient handling of bitmapped objects. This is a step in the ongoing ODB abstraction effort to restructure Git’s object storage layer to support alternative backends. The series also addresses an inefficiency in `odb_for_each_object()` where object lookups during enumeration redundantly traverse indices, risking incorrect pack selection and degrading performance.

He requested a small improvement to the commit message: adding a clear problem statement upfront to motivate the patch, specifically noting that the current `git cat-file --batch-all-objects` implementation reaches into ODB internals and manually manages bitmaps, creating tight coupling between the command and backend details. Key technical details
- Subsystems: object database (ODB), packed backend, pack-bitmap
- Files: `builtin/cat-file.c`, `pack-bitmap.c`, `pack-bitmap.h`, `odb/source-packed.c`, ODB interface headers, `builtin/pack-objects.c`, `builtin/rev-list.c`, `odb.h`
- New/renamed symbols: object filters made `const` in `for_each_bitmapped_object()` and related functions; `store` variable renamed to `source` in `odb/source-packed.c` for clarity; new functions `open_bitmap_for_source()` (patch 4) and `prepare_bitmap_git_for_source()` (patch 5) to open bitmaps for a single source; reversed loop order in `open_pack_bitmap_1()` to iterate over sources first, then attempt to load a bitmap for each source (previously: search all sources for a multi-pack index bitmap, then all sources for a packfile bitmap); altered bitmap precedence—local bitmaps now take precedence over multi-pack index bitmaps in alternates; improved object lookup during enumeration; early abortion of bitmapped object iteration via non-zero return value propagation in `for_each_bitmapped_object()` and `show_objects_for_type()` (patch 3); callers in `builtin/pack-objects.c` and `builtin/rev-list.c` updated to return 0 instead of 1 to preserve existing behavior (patch 3); new `filter` field in `odb_for_each_object_options` struct (patch 6); public `can_filter_bitmap()` function (patch 6); new `bitmapped_for_each_object` callback (patch 6); modified `odb_source_packed_for_each_object()` to skip packs already covered by a bitmap (patch 6) and to use index-provided pack and offset data for object lookups, replacing the generic `odb_source_read_object_info()` with direct calls to `packed_object_info()` (patch 1); the condition `if (opts->flags || data->request)` in `odb_source_packed_for_each_object()` now includes `data->request` where it previously did not
- Behavior: replaces direct backend-specific logic in `cat-file` with ODB-mediated filtering; eliminates redundant index traversals in `odb_for_each_object()` by using already-available index data for object lookups; enables early termination of bitmapped object iteration; ensures bitmaps are opened only for the specified source, preventing misattribution of objects and redundant enumeration; allows callers to pass object filters to backends for optimization; no end-user behavioral changes expected
- On-disk format: no changes
- Test coverage: not yet detailed in the summary
