Core problem or goal
Enable `git cat-file --batch-all-objects` to work with pluggable object databases by removing its dependency on internal details of the "packed" backend, specifically for efficient handling of bitmapped objects. This is a step in the ongoing ODB abstraction effort to restructure Git’s object storage layer to support alternative backends. The series also addresses an inefficiency in `odb_for_each_object()` where object lookups during enumeration redundantly traverse indices, risking incorrect pack selection and degrading performance.

Key technical details
- Subsystems: object database (ODB), packed backend, pack-bitmap, `git cat-file`, `git pack-objects`, `git rev-list`
- Files: `builtin/cat-file.c`, `builtin/pack-objects.c`, `builtin/rev-list.c`, `list-objects.c`, `list-objects.h`, `odb.h`, `odb/source-packed.c`, `pack-bitmap.c`, `pack-bitmap.h`
- New/renamed symbols: object filters made `const` in `for_each_bitmapped_object()`, `filter_bitmap()`, and `can_filter_bitmap()` (patch 2/9); `store` variable renamed to `source` in `odb/source-packed.c` for clarity (patch 1/9); new functions `open_bitmap_for_source()` (patch 5/9), `prepare_bitmap_git_for_source()` (patch 7/9), and `can_filter_bitmap()` (previously static, now exposed in patch 8/9); dropped `_1` suffixes from `open_pack_bitmap_1()` and `open_midx_bitmap_1()` (patch 6/9), renaming them to `open_pack_bitmap()` and `open_midx_bitmap()` respectively; reversed loop order in `open_bitmap()` to iterate over sources first, then attempt to load a bitmap for each source (patch 5/9); altered bitmap precedence—local packfile bitmaps now take precedence over multi-pack index bitmaps in alternates (patch 5/9); improved object lookup during enumeration by using index-provided pack and offset data for object lookups, replacing the generic `odb_source_read_object_info()` with direct calls to `packed_object_info()` (patch 1/9); early abortion of bitmapped object iteration via non-zero return value propagation in `for_each_bitmapped_object()` and `show_objects_for_type()` (patch 4/9); callers in `builtin/pack-objects.c` and `builtin/rev-list.c` updated to return `0` instead of `1` to preserve existing behavior (patch 4/9); new `filter` field in `odb_for_each_object_options` struct (patch 8/9); new `bitmapped_for_each_object` callback (patch 8/9); modified `odb_source_packed_for_each_object()` to skip packs already covered by a bitmap (patch 8/9) and to use index-provided pack and offset data for object lookups; the condition `if (opts->flags || data->request)` in `odb_source_packed_for_each_object()` now includes `data->request` to ensure the pack is populated for `packed_object_info()`; refactored `builtin/cat-file.c` to use the new filtering mechanism (patch 9/9); exposed `can_filter_bitmap()` for backend use (patch 8/9); removed functions `batch_one_object_packed` and `batch_one_object_bitmapped` (patch 9/9); removed `pack-bitmap.h` include from `builtin/cat-file.c` (patch 9/9); removed unused `int` return from `add_object_entry()` in `builtin/pack-objects.c` (patch 3/9, Jeff King’s cleanup); **proposed follow-up change**: split the callback type used by `for_each_bitmapped_object()` from `show_reachable_fn`, introducing a new abortable callback type for bitmapped object iteration (e.g., `bitmap_show_reachable_fn`) while making `show_reachable_fn` return `void` to align with `traverse_commit_list()`. This affects `for_each_bitmapped_object()` (in `pack-bitmap.c`), `show_reachable_fn` (used by `traverse_commit_list()` in `list-objects.c`), and their callers in `builtin/pack-objects.c` and `builtin/rev-list.c`. Jeff King endorses this as a "nice cleanup" but notes that its safety can only be confirmed by implementation. **Clarified performance detail**: the optimization leveraging the OID fanout chunk to narrow iteration range for single-byte prefixes is not applicable because the shortest prefix used in practice is at least 2 bytes (4 hex characters), so redundant `match_hash()` calls do not occur.
- Behavior: replaces direct backend-specific logic in `cat-file` with ODB-mediated filtering; eliminates redundant index traversals in `odb_for_each_object()` by using already-available index data for object lookups; enables early termination of bitmapped object iteration; ensures bitmaps are opened only for the specified source, preventing misattribution of objects and redundant enumeration; allows callers to pass object filters to backends for optimization; no end-user behavioral changes expected
