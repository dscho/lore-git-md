Subject: [PATCH 0/8] Introduce object filters to odb_for_each_object()
Series version: v2 (v1 was 7 patches; v2 adds one patch, drops `_1` suffixes, improves commit messages, and incorporates review feedback)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Enable `git cat-file --batch-all-objects` to work with pluggable object databases by removing its dependency on internal details of the "packed" backend, specifically for efficient handling of bitmapped objects. This is a step in the ongoing ODB abstraction effort to restructure Git’s object storage layer to support alternative backends. The series also addresses an inefficiency in `odb_for_each_object()` where object lookups during enumeration redundantly traverse indices, risking incorrect pack selection and degrading performance.

Current status
Under review; v2 posted. Built on Git 2.56 with Patrick’s `ps/odb-drop-whence` topic merged. Junio C Hamano reviewed the final patch (7/7 in v1, now 8/8 in v2) and called it "very nice," praising the 7-insertion/69-deletion diffstat that replaces backend-specific logic with ODB-mediated filtering. He requested a small improvement to the commit message: adding a clear problem statement upfront to motivate the patch, specifically noting that the current `git cat-file --batch-all-objects` implementation reaches into ODB internals and manually manages bitmaps, creating tight coupling between the command and backend details. Patrick has incorporated this change in v2. Justin Tobler reviewed patches 1/7, 3/7, 4/7, and 6/7 in v1, raising questions about technical details and design choices but no objections. All review feedback from v1 has been resolved: (1) Patch 1/8’s two open questions about object lookup behavior and the `if (opts->flags || data->request)` condition were clarified, confirming that reading from a different packfile is semantically incorrect but not harmful, and that `data->request` ensures the pack is populated for `packed_object_info()`. (2) Patch 3/8’s return-value changes were confirmed as safe due to dead code elimination. (3) Patch 4/8’s style suggestions were incorporated. (4) Patch 6/8’s design question—whether backends should be required to support a subset of object filters—was resolved in favor of the current design, which allows backends to ignore filters, consistent with Git’s existing patterns (e.g., reference backend exclude patterns). The v2 update adds one new patch (5/8) to drop unnecessary `_1()` suffixes from bitmap-opening functions, simplifies the logic in `open_bitmap_for_source()` by using a boolean instead of an integer, and improves commit message explanations. Patch 2/8 (the new email) marks the `filter` parameter in `for_each_bitmapped_object()` and its internal helpers as `const` to reflect immutability; this is a purely mechanical change with no behavior or interface impact. Patch 3/8 (this email) enables early termination of bitmapped object iteration by propagating non-zero return values from the `show_reach` callback through `for_each_bitmapped_object()` and `show_objects_for_type()`, addressing a latent bug where the callback’s return value was previously ignored. The change is mechanical and aligns the bitmap iteration API with Git’s broader object enumeration patterns. The series is likely to be accepted once any remaining minor adjustments are finalized.

Key technical details
- Subsystems: object database (ODB), packed backend, pack-bitmap
- Files: `builtin/cat-file.c`, `builtin/pack-objects.c`, `builtin/rev-list.c`, `odb.h`, `odb/source-packed.c`, `pack-bitmap.c`, `pack-bitmap.h`
- New/renamed symbols: object filters made `const` in `for_each_bitmapped_object()` and related functions (patch 2/8); `store` variable renamed to `source` in `odb/source-packed.c` for clarity (patch 1/8); new functions `open_bitmap_for_source()` (patch 4/8) and `prepare_bitmap_git_for_source()` (patch 6/8) to open bitmaps for a single source; dropped `_1` suffixes from `open_pack_bitmap_1()` and `open_bitmap_1()` (patch 5/8); reversed loop order in `open_pack_bitmap()` (formerly `open_pack_bitmap_1()`) to iterate over sources first, then attempt to load a bitmap for each source (previously: search all sources for a multi-pack index bitmap, then all sources for a packfile bitmap); altered bitmap precedence—local bitmaps now take precedence over multi-pack index bitmaps in alternates; improved object lookup during enumeration by using index-provided pack and offset data for object lookups, replacing the generic `odb_source_read_object_info()` with direct calls to `packed_object_info()` (patch 1/8); early abortion of bitmapped object iteration via non-zero return value propagation in `for_each_bitmapped_object()` and `show_objects_for_type()` (patch 3/8); callers in `builtin/pack-objects.c` and `builtin/rev-list.c` updated to return 0 instead of 1 to preserve existing behavior (patch 3/8); new `filter` field in `odb_for_each_object_options` struct (patch 8/8); public `can_filter_bitmap()` function (patch 8/8); new `bitmapped_for_each_object` callback (patch 8/8); modified `odb_source_packed_for_each_object()` to skip packs already covered by a bitmap (patch 8/8) and to use index-provided pack and offset data for object lookups; the condition `if (opts->flags || data->request)` in `odb_source_packed_for_each_object()` now includes `data->request` to ensure the pack is populated for `packed_object_info()`; refactored `builtin/cat-file.c` to use the new filtering mechanism (patch 8/8)
- Behavior: replaces direct backend-specific logic in `cat-file` with ODB-mediated filtering; eliminates redundant index traversals in `odb_for_each_object()` by using already-available index data for object lookups; enables early termination of bitmapped object iteration; ensures bitmaps are opened only for the specified source, preventing misattribution of objects and redundant enumeration; allows callers to pass object filters to backends for optimization; no end-user behavioral changes expected
