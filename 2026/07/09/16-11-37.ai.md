This is the first patch in a refactoring series (v9, 9/9) that continues the libification effort by migrating global configuration variables into `struct repo_config_values`. Specifically, this patch introduces `repo_config_values_clear()`, a destructor function to free heap-allocated strings in `struct repo_config_values` when a repository instance is torn down. The immediate focus is on `attributes_file`, with a note that future patches will extend this to other variables.

The patch adds the new function in `environment.c`, declares it in `environment.h`, and invokes it from `repo_clear()` in `repository.c`. A key limitation is noted: submodules are not supported by `repo_config_values()` (which BUG()s out for non-`the_repository` instances), so the destructor silently returns for submodules to avoid crashes. This is marked as `NEEDSWORK` but is not a blocker for the series.

The implementation is straightforward and follows the pattern established in the recently merged `excludes_file` series. The patch is technically sound, with no user-visible behavior changes, and is part of a broader effort to eliminate globals and centralize memory management. The submodule limitation is a known constraint, but the patch is ready for review as part of the series. No memory leaks or regressions are introduced here.
