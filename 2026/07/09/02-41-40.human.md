This is a feature patch series introducing a new `includeIf` condition for Git's configuration system. The series, now in its seventh iteration, adds `worktree:<pattern>` and `worktree/i:<pattern>` to allow conditional config inclusion based on the working tree's path, addressing a gap in multi-worktree setups where `gitdir` patterns are cumbersome.

The implementation is split into three patches: a preparatory refactor of `include_by_gitdir()`, a new helper to store a symlink-preserving worktree path, and the actual condition wiring. The key improvement in v7 is preserving symlinked paths for matching, making the behavior consistent with `gitdir:` and resolving a long-standing usability issue. The series includes thorough test coverage for symlinks, case sensitivity, bare repositories, and early config reading.

The motivation is clear and practical: users with multiple worktrees can now write config rules that match the working tree's checkout path directly, rather than navigating the `.git/worktrees/` directory structure. The documentation includes a helpful comparison with `extensions.worktreeConfig`, and the implementation reuses existing pattern-matching logic for consistency.

This looks like a well-crafted, mature contribution that addresses a real user pain point. The iterative improvements based on reviewer feedback (notably from Patrick Steinhardt and Junio Hamano) suggest it's ready for serious consideration. The only potential sticking point might be the symlink-handling edge cases, but the expanded test coverage in v7 should mitigate that concern.
