This thread is about Patrick Steinhardt’s patch series to remove remaining uses of the global `the_repository` variable from Git’s refs subsystem and worktree code. The series is now in its third iteration (v3), posted on 2026-05-22, and is part of the long-running effort to make repository handling explicit throughout Git. The v3 iteration collapses two patches from v2, merging a redundant macro removal into the first patch, which also fixes a latent bug in the packed-refs backend where `core.packedRefsTimeout` was incorrectly stored in function-static variables, causing only the first repository’s setting to be respected. This bug was fixed in v2, and the series is now mechanically complete, touching 25 files across core Git functionality.

The series systematically replaces implicit uses of `the_repository` with explicit `struct repository *` parameters in function signatures and call sites. Key changes include updating the packed and files ref backends, refactoring worktree internals to use available repositories, and removing remaining `the_repository` uses in built-in commands and `refs.c`. The worktree subsystem was included because it complicated an earlier attempt to make refdb initialization eager, and the author refactored it while working in the area. The final patch updates `copy_branchname()` and `check_branch_ref()` function signatures to accept a repository parameter, adjusting all their callers. The series is built on the start of the Git 2.56 cycle with `ps/refs-writing-subcommands` already merged, and Patrick provides clear conflict resolution guidance for the `seen` branch, indicating tested integration with current development.

Junio C Hamano, the maintainer, reviewed the first patch in v1 and caught a behavioral regression in the timeout initialization, which would have introduced a functional change (0 ms timeout instead of 1000 ms) when the config key was unset. This oversight was fixed in v2, and Junio has since resolved integration conflicts caused by a mismerge in `setup.c`. The series is now in the `seen` and `jch` integration branches and is expected to graduate to `master` in the next cycle. Toon Claes provided a surface-level review of patch 2/8 in v2, noting the redundancy of the macro removal, which Patrick has since addressed in v3. The series is uncontroversial, with no open questions or loose ends, and is ready for merging. It fits cleanly into the larger `the_repository` removal effort driven by René Scharfe.
