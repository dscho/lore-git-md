This thread is about Patrick Steinhardt’s eight-patch series to remove more uses of the global `the_repository` variable from Git’s refs subsystem and worktree code. The goal is to make repository handling explicit by passing `struct repository *` parameters instead of relying on the global state. The series is now in its third version, posted on 2026-05-23, and is queued in Junio’s `seen` and `jch` integration branches, with graduation to `master` expected in the next cycle.

The work is incremental and mechanical, touching 25 files across the refs backends, worktree internals, built-in commands, and core refs API. A latent bug in the packed-refs backend was fixed: the `core.packedRefsTimeout` configuration was previously stored in function-static variables, causing only the first repository’s setting to be used; this is now per-repository via `struct packed_ref_store` fields. The series also resolves a behavioral regression in the timeout initialization (zero-initialized `timeout_value` instead of the old 1000 ms default) and addresses minor integration conflicts with the `seen` branch. The public worktree API has been updated to accept explicit repository parameters, and all callers—including built-in commands and test helpers—have been adjusted accordingly.

Junio Hamano’s review was substantive, catching the timeout initialization regression, while Toon Claes’s review was surface-level but confirmed the series is clear to proceed. The series is uncontroversial and fits into the broader `the_repository` removal effort led by René Scharfe. No open questions remain, and the changes are expected to merge without further discussion.
