This thread is about Patrick Steinhardt’s eight-patch series to remove more uses of the global `the_repository` variable in Git’s refs subsystem and worktree code. The goal is to make repository handling explicit by replacing implicit uses of `the_repository` with `struct repository *` parameters across 25 files. Along the way, the series fixes a latent bug in the packed-refs backend where the `core.packedRefsTimeout` configuration was incorrectly shared across repositories.

The series was initially under review after being posted on May 15, 2026, with Junio C Hamano catching a behavioral regression in the first patch: the new per-repository timeout field was zero-initialized, which would have changed the default timeout from 1000 ms to 0 ms when the config key was unset. That issue was acknowledged but not yet fixed when Junio’s latest email arrived. The bigger problem now is that the series causes widespread test failures when merged into the `jch` or `seen` integration branches, blocking its progress. The exact cause of the conflicts isn’t clear, but they’re severe enough to prevent the series from moving forward until Patrick rebases it and diagnoses the interactions with other in-flight topics. No new technical objections to the refactoring itself have been raised, but the integration conflicts take priority for now.
