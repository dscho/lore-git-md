This thread is about Patrick Steinhardt’s eight-patch series to remove more uses of the global `the_repository` variable in Git’s refs subsystem and worktree code. The goal is to make repository handling explicit throughout Git, a long-running effort led by René Scharfe. The series also fixes a latent bug in the packed-refs backend where the `core.packedRefsTimeout` configuration was incorrectly shared across repositories.

The series is now in its second version, posted on May 22, 2026, and has been integrated into Junio Hamano’s `seen` and `jch` branches, with graduation to `master` expected in the next cycle. The first version had a behavioral regression in the packed-refs timeout initialization, which is now fixed in this update. Junio’s review caught the issue early, and the conflicts with the `seen` branch—caused by a mismerge in `setup.c`—have been resolved.

The technical work spans 25 files, including the refs backends, worktree management, and built-in commands like `branch` and `checkout`. Key changes include moving the packed-refs timeout state into `struct packed_ref_store`, refactoring the public worktree API to accept explicit `struct repository *` parameters, and updating built-in commands to pass the repository parameter through their call chains. No new tests were added, as the existing test suite validates the refactoring and bug fix.

The series is uncontroversial, with no open questions remaining. Junio’s review was substantive, focusing on the timeout regression, while the rest of the patches are mechanical cleanups. The work builds on the already-merged `ps/refs-writing-subcommands` series and is part of the broader effort to eliminate `the_repository`.
