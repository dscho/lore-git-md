This is a feature patch extending Git's hook system to run the `post-worktree-remove` hook when worktrees are pruned (not just when explicitly removed). Domen Kožar adds support for running the hook once per pruned worktree, including duplicates, and ensures the hook receives the worktree path when available. The patch updates `should_prune_worktree()` to return the `.git` file path even for pruned entries, modifies `prune_worktree()` and `prune_dups()` to propagate hook exit status, and adds comprehensive tests covering edge cases like dry runs, missing paths, and hook failures.

The change is motivated by tooling that needs to observe worktree deletions regardless of how they occur (explicit removal or pruning after manual deletion). The implementation is careful to handle cases where the worktree path cannot be determined, passing an empty string to the hook in those scenarios. The patch touches `builtin/worktree.c`, `worktree.c`, `worktree.h`, `Documentation/githooks.adoc`, and adds new tests in `t/t2401-worktree-prune.sh`.
