This thread is about Domen Kožar’s patch series adding `post-worktree-add`, `post-worktree-remove`, and `post-worktree-move` hooks to Git, now in its second version. The goal is to provide reliable automation triggers for worktree lifecycle events—creation, removal, and movement—so tools (especially AI-driven development environments) can react predictably when worktrees are added, deleted, or moved.

The series is under active review, with Domen having addressed most of the initial feedback in v2. Key changes included simplifying the `post-worktree-add` hook to run unconditionally after `post-checkout` (even if the latter fails) and removing its arguments, as well as adding the new `post-worktree-move` hook. Phillip Wood, the primary reviewer, has generally been supportive, though one request—documenting the relative order of `post-worktree-add` and `post-checkout`—remains unaddressed.

This latest patch (the third in the v2 series) extends the `post-worktree-remove` hook to run during `git worktree prune`, ensuring tooling can observe worktree deletions even when the worktree is removed manually rather than via `git worktree remove`. The hook is invoked for each pruned entry, including duplicates, and receives the worktree’s absolute path and identifier (or an empty string if the path can’t be determined). The implementation is thorough, with updates to `builtin/worktree.c`, `worktree.c`, and test coverage in `t/t2401-worktree-prune.sh`. The patch explicitly documents edge cases, like missing gitdir files, and aligns with the series’ broader goal of consistent automation triggers. So far, there’s no indication of controversy, and the changes appear ready for integration once the remaining loose end (documenting hook execution order) is resolved.
