This thread is about Domen Kožar’s patch series introducing three new Git hooks—`post-worktree-add`, `post-worktree-remove`, and `post-worktree-move`—to reliably trigger automation for worktree lifecycle events. The series is now at version 2 and targets tooling like AI-driven development environments that frequently create and destroy worktrees.

The latest update adds the `post-worktree-move` hook, completing the series. This hook runs in the new worktree location after a move, receiving the old absolute path as its sole argument. Like the other hooks, its exit status is propagated but doesn’t affect the operation’s outcome. The design ensures consistency: all three hooks share a minimal signature (`post-worktree-add` takes no arguments, `post-worktree-move` takes one, and `post-worktree-remove` takes two), making them easy to configure together. The implementation is clean, with updates to `builtin/worktree.c`, documentation, and test coverage in `t/t2403-worktree-move.sh`.

Key changes from version 1 include simplifying `post-worktree-add` to run unconditionally after `post-checkout` (even if `post-checkout` fails) and removing its arguments. The `post-worktree-remove` hook now also runs during `git worktree prune`, ensuring coverage for all removal paths. Phillip Wood’s review shaped these decisions, though one loose end remains: the relative order of `post-worktree-add` and `post-checkout` is still undocumented. Domen has addressed all other feedback, and the series is now technically complete and ready for final review.
