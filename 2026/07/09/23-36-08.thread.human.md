This thread is about Domen Kožar’s patch series adding `post-worktree-add`, `post-worktree-remove`, and `post-worktree-move` hooks to Git, aimed at supporting high-velocity tooling like AI-driven development environments. The series is now at version 2, with all three hooks implemented and key changes from v1: `post-worktree-add` runs unconditionally after `post-checkout` (even if the latter fails), no longer takes arguments, and a new `post-worktree-move` hook was added. Domen also extended `post-worktree-remove` to cover `git worktree prune` and documented edge cases for missing or corrupt gitdir files.

The main participants are Domen, who authored the series and refined it based on feedback, and Phillip Wood, who provided substantive review. Phillip initially questioned whether `post-worktree-add` should run if `post-checkout` fails but now agrees with unconditional execution. He also requested documentation of the hook execution order, which remains unaddressed in v2. The hooks are designed to be non-blocking—exit status propagates but doesn’t affect the operation’s outcome—and are documented in `githooks.adoc` with clear signatures.

The only open question is the undocumented relative order of `post-worktree-add` and `post-checkout`. Caleb White’s recent email is a friendly but low-weight note expressing enthusiasm for the feature and suggesting the `b4` tool for patch management, without engaging with the technical details. The series is still under review, with no merge status reported.
