This thread introduces a new feature: two Git hooks, `post-worktree-add` and `post-worktree-remove`, designed to support automated workflows that create and destroy worktrees rapidly. Domen Kožar is the author, and the series consists of three patches targeting the worktree subsystem. The motivation is clear—there’s currently no reliable way to trigger setup or cleanup actions when worktrees are added or removed, which is a gap for tooling, especially AI-driven development environments.

The implementation touches core worktree code (`builtin/worktree.c`, `worktree.c`, and `worktree.h`) and includes thorough test coverage across three test scripts. The hooks are documented in `githooks.adoc`, and the series is well-explained, including edge cases like hook ordering and path resolution during pruning. Two design questions are flagged for discussion: whether `post-worktree-add` should run if `post-checkout` fails, and how to handle path resolution when the gitdir file is missing or corrupt. These are reasonable points that may draw feedback from reviewers familiar with hook semantics.

The series appears technically sound and addresses a real need, particularly for tooling that manages ephemeral worktrees. No reviews or maintainer decisions have been posted yet, so the discussion is still open. If you’re building automation around Git worktrees, this is worth watching.
