This thread introduces `post-worktree-add` and `post-worktree-remove` hooks to support automation in environments that frequently create and destroy worktrees, such as AI-driven development tools. Domen Kožar posted the first version of the series, which is now under review.

The key design points have evolved through discussion with Phillip Wood. Initially, there was uncertainty about whether `post-worktree-add` should run if `post-checkout` fails—Phillip had suggested skipping it, but both authors now agree it should run unconditionally since the worktree still exists and tooling needs to track it. Another point of debate was whether the hook should receive the worktree’s absolute directory and ID as arguments. While Phillip questioned their utility (since the hook runs inside the worktree), Domen argued for consistency with `post-worktree-remove` and the practical benefit of shared hook scripts. Phillip also floated the idea of a future `post-worktree-rename` hook, but this remains unresolved.

The series touches `builtin/worktree.c`, `worktree.c`, and `worktree.h`, with test coverage in `t/t2400-worktree-add.sh`, `t/t2401-worktree-prune.sh`, and `t/t2403-worktree-move.sh`. The hooks are documented in `Documentation/githooks.adoc`. Open questions include how to handle path resolution for pruned worktrees with missing or corrupt gitdir files and whether the relative order of `post-worktree-add` and `post-checkout` should be documented. The series is still under review, with no merge decisions yet.
