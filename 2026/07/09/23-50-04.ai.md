This is a gentle follow-up to a bugfix patch targeting Git's SSH signature verification.

The patch, originally sent on July 9, relaxes the requirement that `gpg.ssh.allowedSignersFile` must be configured before Git will display SSH signature details. Currently, users who only want to inspect a signature (key, fingerprint, validity) are blocked by an error and forced to create the file even if they don’t need automated principal validation. The patch introduces a "novalidate" fallback mode that shows basic signature information while advising the user to configure the file for full validation.

The change is minimal—touching only `gpg-interface.c` and adding a hint via `advice.h`—and the commit message clearly demonstrates the improved output. The thread summary confirms no objections or requests for changes have been raised yet, but the patch still lacks test coverage for the new fallback path and a documentation update. The author’s follow-up here is a routine ping to keep the patch visible while it awaits review or maintainer attention. No new technical details or revisions are introduced in this email.
