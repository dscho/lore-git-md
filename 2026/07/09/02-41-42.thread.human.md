This thread is about a refactoring patch by Chen Linxuan that prepares for an upcoming enhancement to Git's `includeIf` conditional configuration mechanism. The patch, part of a three-patch series (v7), introduces a new field `worktree_original` to the `repository` struct and an accessor function `repo_get_work_tree_original()`. This field stores the user-facing, symlink-preserving path of the worktree—normalized but not resolved via realpath—so that future patches can match it against `includeIf.worktree:` patterns consistently, similar to how `gitdir:` already handles symlinked paths.

The implementation is careful and well-documented, ensuring that `repo_set_worktree()` computes both the realpath (unchanged) and the symlink-preserving copy, with a fallback to the realpath if normalization fails. For discovered repositories (where Git has already `chdir`'d to the worktree root), the patch uses `logical_path_from_cwd()` to recover the original path from `$PWD`, verifying it matches the physical path. The patch also ensures proper cleanup in `repo_clear()` to avoid memory leaks. While the new accessor isn't used yet—its purpose is reserved for the next patch in the series—the change is uncontroversial and strictly preparatory, touching only the repository and setup subsystems without altering observable behavior. So far, there are no reviews or objections on the list.
