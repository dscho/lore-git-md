This is part of a refactoring series (v9, patch 3/9) that continues the libification effort by moving global configuration variables into `struct repo_config_values`. This specific patch migrates the `editor_program` global variable into the repository-specific configuration structure.

The patch updates `environment.c` to store the editor path in `repo_config_values` instead of a global variable, modifies `git_default_core_config()` to use the new location, and ensures proper memory management via `repo_config_values_clear()`. The only caller (`git_editor()` in `editor.c`) is updated to access the value through `repo_config_values(the_repository)`.

The commit message explains the rationale: while per-repository editor configuration is rarely needed in practice, moving this string into `repo_config_values` eliminates mutable global state and respects developers who use different toolchains for different projects. This aligns with the broader goal of making Git safe for long-running processes managing multiple repositories.

The patch is clean and mechanical, with no user-visible behavior changes. It follows the established pattern from earlier patches in the series (and the merged `excludes_file` work). The memory management looks correct, and the change is well-motivated. This is a solid step in the ongoing `the_repository` removal effort.
