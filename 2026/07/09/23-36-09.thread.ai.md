Core problem or goal
Git lacks a reliable way for tools that manage per-worktree state (IDEs, development environment managers) to detect when a new worktree is created. The existing `post-checkout` hook is skipped when `--no-checkout` or `--orphan` is used and cannot distinguish between a worktree addition and a regular checkout.

Current status
Under review; v1 posted. No prior versions.

Key technical details
- New hook: `post-worktree-add`
- Files touched: `builtin/worktree.c`, `Documentation/githooks.txt` (man page `githooks(5)`), `t/t2400-worktree-add.sh` (tests)
- Hook runs unconditionally after `git worktree add` completes, regardless of checkout status
- Invoked in the new worktree’s directory with `GIT_DIR` and `GIT_WORK_TREE` cleared, matching `post-checkout` environment
- Arguments: absolute path and identifier of the new worktree
- Runs after `post-checkout`; skipped if `post-checkout` fails
- Failure propagates exit status to `git worktree add` but does not delete the worktree
- Test coverage: normal cases, `--no-checkout`, `--orphan`, bare repositories, relative paths, hook failure scenarios
