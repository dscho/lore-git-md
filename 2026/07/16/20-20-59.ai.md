This is a **substantive review** of the second patch in Tian Yuchen’s v6 series migrating `trust_executable_bit` and `has_symlinks` configuration flags as part of the `the_repository` removal effort. Junio C Hamano questions the decision to move `ce_mode_from_stat()` from a header-declared `static inline` function to `read-cache.c`, suggesting instead that it could remain inline while being modified to accept a `struct repository *` parameter.

The review challenges the patch’s mechanical approach (relocating the function to the `.c` file) and proposes an alternative design: keep the function inline in the header but refactor it to take a repository pointer, allowing it to access repository-scoped configuration without sacrificing performance. Junio’s concern centers on whether `ce_mode_from_stat()` is called in hot paths where inlining might matter, though he does not assert that it is—only that the current patch’s justification ("to cleanly encapsulate dependencies") may not outweigh the cost of losing inlining.

This feedback is **design-level** and could require reworking the patch if adopted. It does not dispute the series’ overall goal (migrating the flags to `struct repo_config_values`) but suggests a different implementation path for this specific helper. The thread context confirms that earlier iterations of this patch (v4/v5) received no objections, so this is a new consideration introduced in v6. The review is narrowly scoped to the function’s placement and does not address the broader series’ readiness or the mingw compatibility changes in patch 4/4, which were previously resolved.

If Tian incorporates this feedback, the patch would likely need to:
1. Keep `ce_mode_from_stat()` in `read-cache.h` as a `static inline`.
2. Add a `struct repository *` parameter to the function.
3. Update all call sites to pass the repository pointer (or `the_repository` as a fallback).
4. Ensure the function can access repository-scoped configuration without violating header dependencies.

This would preserve performance while still enabling the configuration migration. The review is a reminder that even preparatory patches in large refactoring efforts may need to balance encapsulation with performance considerations. No other reviewers have weighed in on this point yet, so the discussion is currently between Tian and Junio.
