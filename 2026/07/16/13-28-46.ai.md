This is the test patch (5/7) for the RFC series introducing `git repack --drop-filtered` for partial clones. It adds comprehensive validation and enumeration tests for the new option, covering CLI argument safety, promisor blob filtering, and non-destructive dry-run behavior.

The patch creates a new test script (`t/t7706-repack-drop-filtered.sh`) and updates `t/meson.build` to include it. The tests verify that `--drop-filtered` enforces its preconditions: it requires `--filter` and `-a`, rejects `--filter-to` and `--write-bitmap-index`, demands a promisor remote, and only works with `--dry-run` in this RFC version. The enumeration tests confirm that only promisor blobs exceeding the filter threshold (e.g., `blob:limit=1k`) are listed as drop candidates, while smaller promisor blobs and locally created objects are excluded. The dry-run tests ensure no objects are actually removed.

The test design follows established patterns from `t0410` (partial clone tests), using helper functions like `promisor_blob()` to create synthetic promisor objects. The safety test for locally created blobs is particularly important—it validates the core guarantee that only recoverable (promisor) objects are ever considered for dropping.
