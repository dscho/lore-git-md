This is the second patch in a seven-part GSoC series that extends the `git repo info` command with new path-related keys. This patch adds `path.superproject-working-tree.absolute` and `path.superproject-working-tree.relative`, exposing the superproject’s working tree location when the current repository is a submodule. The implementation is clean: it reuses the existing `get_superproject_working_tree()` helper and the `format_path()` utility, following the same pattern established in the first patch for `path.toplevel`. Documentation and tests are included, covering both the happy path (inside a submodule) and the edge case (not in a submodule, where the keys return an empty string).

The motivation is straightforward: scripts that operate in multi-repository setups currently have to shell out to `git rev-parse --show-superproject-working-tree`; this patch gives them a native, scriptable alternative. The patch is unlikely to be controversial—it mirrors the behavior of an existing plumbing command and fits neatly into the series’ overall goal of making repository metadata more accessible. Reviewers may quibble over the key name (`superproject-working-tree` vs. something shorter), but the functionality itself looks solid.
