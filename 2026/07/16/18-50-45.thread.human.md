This thread is about a performance patch from first-time contributor Sahitya Chandra that addresses a quadratic-time inefficiency in Git’s `wt-status` subsystem. The patch targets how untracked and ignored paths are collected, replacing repeated sorted insertions with a single append pass followed by a sort and deduplication. The change reduces complexity from O(n²) to O(n log n) while preserving the existing behavior of producing sorted, duplicate-free lists.

The patch is narrowly scoped to `wt-status.c` and is small (6 insertions, 2 deletions), making it easy to review. Sahitya’s commit message explains the trade-offs, including rejecting a more aggressive optimization that would rely on `fill_directory()`’s pre-sorted output in favor of a safer approach. The patch modifies `wt_status_collect_untracked()` and affects the `s->untracked` and `s->ignored` string lists, using existing helpers like `string_list_sort()` and `string_list_remove_duplicates()`.

Key open questions include whether duplicate removal is strictly necessary (the commit message notes uncertainty about whether `dir.entries` and `dir.ignored` can contain duplicates) and whether the performance improvement is measurable in real-world scenarios. Given this is Sahitya’s first contribution, the patch may attract extra scrutiny, but the problem and solution are well-motivated and the implementation appears clean.
