This thread is about a small but well-reviewed performance refactoring in Git’s `wt-status` subsystem. Sahitya Chandra, a first-time contributor, posted a patch that replaces a quadratic-time pattern in `wt_status_collect_untracked()` with a more efficient linear-time append followed by a single sort-and-deduplicate pass. The patch is now at version 2, having incorporated feedback from Patrick Steinhardt and Jeff King.

The change is purely internal to `wt-status.c` and preserves the existing behavior—sorted, duplicate-free lists of untracked and ignored files—while improving code clarity. Both reviewers agreed the performance impact is likely negligible in practice, so the patch is now framed as a maintainability win. No benchmarks were added, and no new tests were needed since the existing `wt-status` test suite covers the functionality.

The patch is ready for further review or integration. The only lingering question—whether the input lists can ever contain duplicates—has been set aside as non-blocking. Sahitya’s v2 submission confirms the patch addresses all prior feedback and is ready to move forward.
