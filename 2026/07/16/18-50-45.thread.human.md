This thread is about a first-time contribution from Sahitya Chandra that aims to fix a quadratic-time performance issue in Git’s `wt-status` subsystem. The patch replaces repeated `string_list_insert()` calls—each of which triggers an O(n) array shift—with a single `string_list_append()` pass followed by a sort and deduplicate step, reducing the overall complexity to O(n log n). The change is small (just 6 insertions and 2 deletions in `wt-status.c`) and preserves the existing behavior of producing sorted, duplicate-free lists of untracked and ignored paths.

Patrick Steinhardt reviewed the patch and endorsed the approach while suggesting two improvements: using the existing `string_list_sort_u()` helper to simplify the code, and adding benchmark results to the commit message to demonstrate the real-world impact. The patch’s commit message already acknowledges a trade-off between safety (explicit deduplication) and a more aggressive optimization that would rely on `fill_directory()`’s pre-sorted output, setting the stage for further discussion.

The patch is still under initial review, with no prior versions or additional feedback yet. The next steps are likely a v2 incorporating Patrick’s suggestions, particularly the helper function and benchmarks. The thread is focused and uncontroversial so far, with no open objections or design disagreements.
