This is the sixth iteration of a refactoring series that migrates the `trust_executable_bit` and `has_symlinks` configuration flags into `struct repo_config_values`, completing the work begun in the now-merged v4 and v5 series. The series is part of the ongoing `the_repository` removal effort and targets core index handling and configuration plumbing.

The key change since v5 is the elimination of the contested global fallback variable (`default_has_symlinks`) in the mingw compatibility layer, replacing it with a compile-time macro (`platform_has_symlinks()`) and a platform-specific function (`mingw_platform_has_symlinks()`), as proposed by Junio C Hamano. This design change removes mutable global state while preserving the ability to detect native symlink support via environment variables. The author has adopted Junio’s proposal, addressing the primary open question from the previous iteration.

The series moves both flags into repository-scoped storage, establishes a unified getter pattern (`repo_trust_executable_bit()` and `repo_has_symlinks()`), and updates all call sites to use repository-scoped access. Eager parsing is maintained for performance in hot paths, and the getters include repository pointer validation. The mingw compatibility layer is now adjusted to use the new macro/function pattern, which should resolve the design concerns raised in v5. The author notes that `repo_config_values()` still does not support non-`the_repository` instances due to deep integration of these flags, but this work lays groundwork for future elimination of the global.

Files touched include `read-cache.c`, `environment.c/h`, `apply.c`, `compat/mingw.c`, and related headers. The series removes redundant extern declarations, relocates `ce_mode_from_stat()` implementation, and migrates both flags into `repo_config_values` with proper initialization and safety checks. The mingw adjustments are now cleaner and more maintainable, avoiding the global variable that was previously a point of contention.

This is a well-crafted refactoring that addresses prior review feedback and resolves the design issue raised by Junio. The series preserves existing behavior while eliminating global state, and the new mingw compatibility pattern is a clear improvement. The migration pattern established here could serve as a template for future configuration refactoring efforts. The series appears ready for final review and likely inclusion in `next`.
