Core problem or goal
Introduce a `--auto-reset=<where>` option to `git bisect` that automatically returns the working tree to a user-specified commit after the bisect identifies the first bad commit. The parameter `<where>` accepts `original` (reset to the pre-bisect commit, the default) or `found` (leave the working tree on the first bad commit). The feature targets both automated workflows (scripts, CI pipelines) and interactive debugging by eliminating the need for an explicit `git bisect reset`.

Current status
Design settled; v2 patch series in preparation. The author has accepted Junio C Hamano’s proposal to convert the original boolean `--auto-reset` flag into a parameterized option (`--auto-reset=<where>`). The preparatory refactoring (patch 1) and quiet-checkout addition (patch 2) remain uncontroversial and unchanged. The next iteration will focus on implementing the parameterized behavior, updating the `BISECT_AUTO_RESET` state file to store the target commit, and revising documentation and tests to cover both `original` and `found` use cases.

Key technical details
- Files touched: `bisect.c`, `builtin/bisect.c`, `Documentation/git-bisect.adoc`, `t/t6030-bisect-porcelain.sh`.
- New CLI option: `--auto-reset=<where>` (parameterized; values `original` or `found`; default `original`). The boolean form (`--auto-reset`) is deprecated.
- Behavior: After `git bisect` identifies the first bad commit, the working tree is automatically reset to the commit specified by `<where>`. The default (`original`) preserves the original pre-bisect state; `found` leaves the working tree on the first bad commit (the culprit).
- Internal changes: `print_file_to_stdout()` -> `print_fd_to_stdout()` (opened with `O_RDWR`, seek to start before copying to stdout); `bisect_reset()` now accepts a `quiet` parameter to suppress checkout output. The `BISECT_AUTO_RESET` state file will store the target commit (`original` or `found`) rather than a boolean flag. If `<where>` is `found`, the reset step is omitted entirely.
- Test coverage: Four new tests in `t/t6030-bisect-porcelain.sh` will validate auto-reset behavior for both `original` and `found`, state cleanup, and non-persistence across sessions. Edge cases (interrupted bisects, descriptor errors, seek failures, quiet parameter handling in error paths) will also be covered.
- No on-disk format changes or new symbols introduced beyond the state file updates.

Open questions and loose ends
- **State file format**: The `BISECT_AUTO_RESET` state file must be updated to store the target commit (`original` or `found`) rather than a boolean flag. The exact format and persistence logic are still to be determined.
- **Edge case handling**: Reviewers may scrutinize behavior if the bisect is interrupted, fails, or encounters errors (e.g., `bisect run` exits non-zero, descriptor errors, seek failures, or quiet parameter handling in error paths).
- **Documentation and tests**: Both will need updates to reflect the parameterized behavior, including examples for `original` and `found` use cases.
- No other review comments have been received; the design discussion is now resolved.
