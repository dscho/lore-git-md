This is an RFC patch series introducing a new `git repack --drop-filtered` option for partial clones. The feature aims to reclaim disk space by safely removing locally cached promisor blobs that can be re-fetched from the promisor remote. The series is authored by Siddharth Shrimali, a first-time contributor to this subsystem.

The core idea is to extend `git repack` with a `--drop-filtered` flag that, when combined with a filter specification (e.g., `--filter=blob:limit=10M`), identifies and removes large promisor blobs exceeding the threshold. The implementation guarantees safety by only targeting objects marked as promisor (ensuring they are recoverable) and avoids touching locally created objects. A key innovation is the introduction of a drop log (`$GIT_DIR/objects/info/promisor-dropped`) to record removed objects, enabling better error messages when lazy fetches fail due to prior drops.

The series touches several subsystems: it adds new options to `builtin/repack.c`, extends the `list-objects-filter` API with `list_objects_filter__filter_oidset()`, and introduces a new `repack-filtered.c` file for the core logic. The promisor pack rebuilding logic in `repack-promisor.c` is modified to support excluding objects, and a new test script (`t/t7706-repack-drop-filtered.sh`) validates the behavior. The commit messages note that the series is still in flux—function signatures and test placement will be reorganized in v2.

Two significant follow-ups are planned: adding safety guards to prevent drops during merges/rebase operations or when blobs are referenced by the current index, and enhancing the drop log to record the exact promisor remote for each object (pending a new `remote-object-info` protocol command). The author explicitly calls out the lack of client-side remote object availability queries as a current limitation.

The series is well-motivated for partial clone users, addressing a long-standing pain point (accumulated promisor blobs consuming disk space). The design appears sound, leveraging existing repack machinery for crash safety and introducing the drop log as a forward-compatible improvement. However, the RFC status and noted churn in function signatures suggest the implementation is not yet final. The planned safety guards and remote verification will be critical for production use.
