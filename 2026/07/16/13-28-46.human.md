This is the fifth patch in an RFC series introducing `git repack --drop-filtered` for partial clones. It adds the test suite (`t/t7706-repack-drop-filtered.sh`) that validates the new option’s behavior.

The tests cover four areas: CLI validation (ensuring `--drop-filtered` requires `--filter` and `-a`, rejects `--filter-to` and `--write-bitmap-index`, and mandates `--dry-run` in this RFC version), enumeration correctness (verifying that only promisor blobs above the filter threshold are listed as drop candidates), safety (confirming locally created blobs are never listed), and non-destructiveness (`--dry-run` leaves objects intact). The helper functions (`promisor_blob`, `pack_as_from_promisor`) follow the established pattern from `t0410` to create synthetic promisor objects.

The test script is thorough and well-structured, exercising the preconditions and edge cases the author has identified as critical for safety. It does not yet cover the planned safety guards (e.g., preventing drops during merges or when blobs are referenced by the index) or the drop log, which are deferred to later patches. The series remains in RFC status, so the tests are expected to evolve alongside the implementation. For anyone following the partial-clone disk-space reclamation effort, this patch provides a clear picture of what the final behavior should look like.
