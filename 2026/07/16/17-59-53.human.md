This is a bugfix for the revision-walking subsystem, already under review and now queued by Junio. The patch restores path filtering in `git rev-list --no-walk <commit> -- <path>`, which was broken by a regression introduced in May 2026 (commit `dd4bc01c0a`). Without the fix, the command outputs all commits regardless of whether they touch the specified paths; with it, only commits that modified those paths are shown.

The fix itself is minimal—just two lines in `revision.c`—and folds the `REV_WALK_NO_WALK` case into existing logic that already handles path filtering correctly. The commit message is clear and includes a concrete reproduction example using `linux.git`, showing the before-and-after difference: 2026 unfiltered commits versus 146 correctly filtered ones. Three new tests in `t/t6017-rev-list-stdin.sh` verify the fix, two of which fail without it.

The regression was reported by Peter Colberg, and the fix has been verified against the exact scenario from the report. Junio’s reply confirms the fix works as expected and indicates he will queue it, so this patch is effectively ready for the next integration cycle. It’s a well-scoped, uncontroversial fix with no dependencies or follow-ups.
