This is an RFC patch series introducing a new `git repack --drop-filtered` option for partial clones. The feature aims to reclaim disk space by safely removing locally cached promisor blobs that can be re-fetched from the promisor remote later.

The series adds a `--drop-filtered` flag to `git repack` that, when combined with a filter spec (e.g., `--filter=blob:limit=10M`), identifies and removes large promisor blobs exceeding the threshold. The implementation enumerates promisor objects, rebuilds the promisor pack without the selected blobs, and logs dropped objects in a new `promisor-dropped` file for better error reporting. A `--dry-run` mode lists candidates without making changes.

The author acknowledges several missing pieces, including safety guards to prevent drops during merges or when blobs are referenced by the index, and plans to improve remote verification once a `remote-object-info` command is available. The current version also has some churn in function signatures and test organization, which will be cleaned up in v2.

This is a well-motivated feature for partial clone users dealing with disk space bloat, and the design appears sound, though the RFC status suggests it’s still seeking feedback on approach. The implementation touches core repack machinery and promisor object handling, so review from Patrick Steinhardt, Taylor Blau, or others familiar with the ODB and repack subsystems would be valuable. The series looks promising but isn’t ready for merging yet.
