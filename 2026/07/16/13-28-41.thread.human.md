This thread introduces a new `git repack --drop-filtered` option to help partial clones reclaim disk space by safely removing locally cached promisor blobs exceeding a size threshold. The feature, proposed by first-time contributor Siddharth Shrimali, has reached its third iteration (v3) with all seven patches now posted. The core functionality is complete: promisor objects are enumerated, filtered by size, and dropped by rebuilding the promisor pack while excluding them, with crash safety guaranteed by Git’s existing repack machinery.

The series addresses all feedback from earlier versions, including a subtle bitmap validation fix (explicit `-b` is now always rejected, even when `repack.writeBitmaps` is set), softer documentation language acknowledging remote availability risks, and a reframing of the safety guards—merge/rebase/cherry-pick checks and index validation—as UX optimizations rather than correctness measures. Junio Hamano, the maintainer, has proposed replacing these guards with a time-based heuristic (avoiding culling recently fetched objects) to reduce redundant network operations, but this remains deferred to a follow-up. The current implementation is finalized, though its integration status is still unknown.

Key technical details include new CLI options (`--drop-filtered` and `--dry-run`), a new helper function (`list_objects_filter__filter_oidset()`) to apply filters without object traversal, and modifications to `repack_promisor_objects()` to support object exclusion. The feature is currently limited to `blob:limit` filters, with future extensions possible. Open questions include the reliability of promisor-object enumeration in practice and the design trade-off between the current safety guards and Junio’s proposed time-based heuristic. The series builds on existing partial clone and repack infrastructure, with deferred work including a drop log and remote verification pending the `remote-object-info` protocol command.
