This thread is an RFC patch series from first-time contributor Siddharth Shrimali proposing `git repack --drop-filtered`, a new option to safely reclaim disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold. The series is now complete at 7 patches, implementing the core functionality and a drop log (`$GIT_DIR/objects/info/promisor-dropped`) to record removed objects for better error messages during future lazy-fetch failures.

Junio Hamano, the maintainer, identified a critical flaw in the first patch: the validation for `--drop-filtered`'s incompatibility with `--write-bitmap-index` (`-b`) occurs too late in the control flow, after configuration may have already set `write_bitmaps`. This makes it impossible to distinguish between user-requested bitmaps (which should trigger an error) and config-driven bitmaps (which should be silently disabled), rendering the safety mechanism ineffective. Siddharth has acknowledged the issue and plans to restructure the validation in v2 to explicitly track command-line vs. configuration sources, which is now a blocking prerequisite for the series to proceed. No other substantive reviews have been recorded yet, and the series remains in RFC status with no integration branch assignment. The implementation is expected to undergo API reorganization and add deferred safety checks (e.g., preventing drops during merges or rebases) in future versions.
