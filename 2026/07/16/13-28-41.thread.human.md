This thread is an RFC patch series from first-time contributor Siddharth Shrimali, introducing `git repack --drop-filtered` to safely reclaim disk space in partial clones by removing locally cached promisor blobs above a user-specified size threshold. The series is now complete at RFC v1 (7/7 patches), with a v2 planned to address key blocking issues.

The core idea is to extend `git repack` with a `--drop-filtered` option that targets only promisor objects (ensuring they remain recoverable from the promisor remote) while avoiding locally created objects. The feature includes a drop log (`$GIT_DIR/objects/info/promisor-dropped`) to record removed objects for better error messages during future lazy-fetch failures. The latest patch (6/7) implements the actual object-dropping logic, transitioning from dry-run enumeration to real disk-space reclamation by passing the computed drop set to `repack_promisor_objects()` and implying `-d` to remove old promisor packs containing the dropped blobs. The repack machinery’s existing crash-safety guarantees are preserved.

Key participants include Junio C Hamano (maintainer), who identified a blocking logical flaw in the `--drop-filtered` vs `--write-bitmap-index` validation that must be fixed in v2, and Siddharth Asthana (reviewer), who raised critical safety concerns about preventing drops during merges, rebases, or cherry-picks and validating the index to avoid immediate re-fetching of just-dropped blobs. Christian Couder provided surface-level feedback on the CLI design, endorsing the current `--drop-filtered` + `--dry-run` separation. The series remains under active design iteration with no integration branch assignment, and v2 will focus on fixing the bitmap validation flaw, adding safety guards, reorganizing internal APIs, and documenting the drop log. Remote verification logic and client-side object availability checks are deferred pending the `remote-object-info` protocol command.
