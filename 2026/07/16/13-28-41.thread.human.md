This thread introduces a new `git repack --drop-filtered` option for partial clones, allowing users to safely reclaim disk space by removing locally cached promisor blobs exceeding a specified size threshold. The feature is designed with safety in mind, targeting only objects marked as promisor (ensuring they remain recoverable from the remote) and avoiding locally created objects. The v5 series, posted by first-time contributor Siddharth Shrimali, is now complete with six patches and addresses all prior feedback, including a critical type-mismatch bug and documentation improvements.

The implementation adds two key safety optimizations: checks to prevent drops during ongoing operations (merge, rebase, am, cherry-pick, revert, or bisect) and validation to avoid dropping blobs referenced by the current index. These are skipped for bare repositories, and error messages now explicitly list all blocked operations. The series also enforces preconditions like requiring `--filter=blob:limit` and a promisor remote, while rejecting incompatible options such as `--filter-to` or explicit bitmaps. Tests cover validation, enumeration, and safety guards, confirming the feature works as intended without triggering lazy fetches.

Reviewers Siddharth Asthana and Christian Couder have endorsed the approach, with Christian’s feedback on documentation and error messages fully addressed in v5. Junio C Hamano, the maintainer, previously raised technical questions about promisor-object enumeration and repack machinery behavior, but no new feedback has emerged since v5’s posting. The series is technically ready for maintainer review, though its integration status remains pending. Deferred follow-up work includes remote verification, a time-based culling heuristic, and a drop log for error recovery.
