This thread is an RFC patch series from first-time contributor Siddharth Shrimali, proposing `git repack --drop-filtered` to safely reclaim disk space in partial clones by removing locally cached promisor blobs above a size threshold. The series is now fully posted as RFC v1 (7 patches), with the latest addition—patch 3/7—extending the promisor pack rebuilding logic to exclude objects marked for removal.

The feature’s core goal is to let users specify a size limit (e.g., `--filter=blob:limit=10M`) and drop only those promisor blobs that exceed it, while ensuring safety through three guarantees: objects must be marked as promisor (recoverable from the remote), locally created objects are untouched, and a drop log records removed objects for better error messages during future lazy-fetch failures. The current implementation is still evolving—function signatures, test placement, and internal APIs are expected to change in v2, and key safety checks (like preventing drops during merges or when blobs are referenced by the index) are planned but not yet implemented.

Patch 3/7 is a mechanical but necessary piece of the puzzle: it modifies `repack_promisor_objects()` to accept an optional `oidset` of objects to exclude when rebuilding the promisor pack. This plumbing enables the actual object-dropping logic in patch 7/7, though for now, all existing callers pass `NULL`, so behavior remains unchanged. The patch is uncontroversial but depends entirely on the rest of the series landing. No maintainer feedback has arrived yet, and the series is not yet assigned to an integration branch. The next steps will likely focus on addressing the open questions around safety guards, remote verification, and API cleanup before a v2 is posted.
