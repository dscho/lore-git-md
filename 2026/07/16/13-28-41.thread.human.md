This thread is about Siddharth Shrimali’s patch series introducing `git repack --drop-filtered`, a new option for partial clones that safely reclaims disk space by removing locally cached promisor blobs exceeding a user-specified size threshold. The series is now in its third iteration (v3), with all seven patches posted and all prior feedback addressed—including a subtle bitmap validation fix, softer documentation language, and a reframing of the safety guards as UX optimizations rather than correctness measures.

The core functionality is finalized: promisor objects are enumerated, filtered by size, and dropped by rebuilding the promisor pack while excluding them, with crash safety guaranteed by Git’s existing repack machinery. The series adds two new CLI options (`--drop-filtered` and `--dry-run`), a new helper function (`list_objects_filter__filter_oidset()`) to apply filters to existing OID sets without object traversal, and a new test script (`t/t7706-repack-drop-filtered.sh`). Junio has proposed replacing the current merge/rebase/cherry-pick checks and index validation with a time-based heuristic to reduce redundant network operations, but this remains deferred to a follow-up.

No maintainer decision has been made yet, and the series is not yet in any integration branch. Open questions include the reliability of promisor-object enumeration in practice, the scope of supported filters (currently limited to `blob:limit`), and the deferred drop log and remote verification features. The author and reviewers (Siddharth Asthana, Christian Couder) have endorsed the approach, while Junio’s feedback has focused on technical robustness and UX trade-offs. The series builds on existing partial clone and repack infrastructure, with the drop log introducing a new mechanism analogous to Git’s promisor object log.
