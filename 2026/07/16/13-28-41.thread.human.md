The thread is about a new `git repack --drop-filtered` option for partial clones, allowing users to reclaim disk space by removing large promisor blobs that can be re-fetched from a remote. The feature is now complete in its fourth iteration (v4), with all seven patches posted by first-time contributor Siddharth Shrimali.

The implementation safely drops only objects marked as promisor, avoiding locally created ones, and includes optimizations to prevent immediate re-fetching—like blocking drops during merges or rebases and refusing to remove blobs referenced by the current index. These are framed as UX improvements rather than correctness measures, since lazy-fetching would restore dropped objects transparently. Junio has suggested replacing these checks with a time-based heuristic (e.g., avoiding recently fetched objects) but this remains deferred.

Key technical details include new CLI options (`--drop-filtered` and `--dry-run`), a new helper function to filter objects by size, and modifications to the repack machinery to exclude dropped objects while rebuilding promisor packs. The series also fixes a subtle bitmap validation bug and adds thorough documentation. All mechanical feedback from Junio has been addressed in v4, and the author has confirmed plans to run the full test suite and trial merges before the next revision.

The series is functionally complete and production-ready, but no maintainer decision has been made yet. Open questions include whether to adopt the time-based heuristic, the reliability of promisor-object enumeration, and the deferred drop log for tracking removed objects. Reviews from Siddharth Asthana and Christian Couder have been supportive, while Junio’s feedback remains focused on due diligence and integration readiness.
