This thread is about a bugfix for a regression in Git’s revision-walking subsystem. In May 2026, commit `dd4bc01c0a` introduced a bug where `git rev-list --no-walk <commit> -- <path>` ignored path arguments and returned all commits instead of filtering by the specified paths. Kristofer Karlsson’s patch corrects this by ensuring the `REV_WALK_NO_WALK` case calls `try_to_simplify_commit()`, which evaluates path relevance. The fix is minimal—just two lines in `revision.c`—and includes three new tests in `t/t6017-rev-list-stdin.sh` to verify the behavior.

The regression was reported by Peter Colberg, and the patch provides a clear reproduction case using `linux.git`, showing the fix reduces output from 2026 unfiltered commits to 146 correctly filtered ones. The change is well-scoped, touching only the revision-walking logic without affecting other subsystems. Given the recent introduction of the bug and the targeted fix, this should be uncontroversial and ready for merging. No objections or further discussion have appeared yet.
