This is the second patch in Paulius Zaleckas's v6 series introducing configurable submodule fetch error handling. It adds the user-facing controls (`fetch.submoduleErrors` config key and `--submodule-errors` CLI option) that let users choose whether `git fetch --recurse-submodules` should fail hard or merely warn when a submodule’s gitlink points to an unreachable OID. The default remains `fail` for backwards compatibility, preserving existing behavior.

The patch wires up the new setting throughout the fetch machinery: the config key is parsed in `git_fetch_config()`, the CLI option is added to `cmd_fetch()`’s option table, and the resolved value is forwarded to child fetches (including `--all`/`--multiple` and nested recursion) via `add_options_to_argv()`. This ensures the setting propagates to per-remote child processes, overriding any repository config when explicitly set. The implementation is clean, using a centralized name array (`submodule_error_name[]`) for both parsing and formatting, and the array indexing type is now `unsigned` (not `size_t`) per Junio’s feedback.

Test coverage is thorough, verifying the new behavior in both config and CLI modes, including edge cases like CLI overrides, `--all` forwarding, and inaccessible submodules. The tests also confirm that successful fetches do not trigger error summaries when `warn` is set. The patch touches `builtin/fetch.c`, `submodule.c`, `submodule.h`, and documentation files, and builds directly on the refactoring in Patch 1/2 (which fixed a pre-existing logic flaw in error recording).

This patch is technically complete, addresses all prior review feedback, and appears ready for `next`. The changes are narrowly scoped to the submodule fetch error-handling path, the rationale is well-explained, and the implementation is robust. The new controls solve a real workflow pain point—upstream topic branches that are still in flux—without introducing broader risks. Key files modified include `builtin/fetch.c`, `submodule.c`, `submodule.h`, `Documentation/config/fetch.adoc`, `Documentation/fetch-options.adoc`, and `t/t5526-fetch-submodules.sh`. The new config key (`fetch.submoduleErrors`) and CLI option (`--submodule-errors`) are case-sensitive and parsed via a shared name array.
