This is the first patch in a three-part **feature** series adding a `--auto-reset` option to `git bisect`. The patch refactors how `git bisect run` handles its output, replacing a file-based approach with direct descriptor manipulation.

The change is small and mechanical: instead of reopening the `BISECT_RUN` output file by name after each bisect step, the code now reads from the already-open file descriptor. This eliminates a redundant `open()` call and removes the assumption that the file remains accessible by path. The patch touches only `builtin/bisect.c` and makes no behavior changes—it is purely preparatory for the `--auto-reset` feature introduced in patch 3.

The refactoring looks clean and well-scoped. The commit message clearly explains the motivation and the implementation, and the diff is straightforward. There are no obvious edge cases or risks introduced here; this is a tidy internal improvement that sets the stage for the actual feature. Reviewers are unlikely to object to this part of the series.
