This is a **feature** patch series introducing a `--auto-reset` option to `git bisect`. The series consists of three patches that collectively allow users to automatically return to the original commit after `git bisect` identifies the first bad commit, rather than leaving the bisect session active until manually reset.

The cover letter explains the motivation: the new option streamlines the bisect workflow by eliminating the need for an explicit `git bisect reset` after the bisect completes. This is particularly useful in automated scripts or CI pipelines where manual intervention is impractical. The implementation touches `bisect.c`, `builtin/bisect.c`, and the documentation (`Documentation/git-bisect.adoc`), with new tests added in `t/t6030-bisect-porcelain.sh`.

Patch 1 ("bisect: read run output from the open descriptor") appears to be a preparatory refactoring to ensure the bisect process can reliably capture output from `git bisect run`. Patch 2 ("bisect: let bisect_reset() optionally check out quietly") adds flexibility to the reset mechanism, likely to avoid noisy output during the auto-reset. Patch 3 ("bisect: add --auto-reset to leave when done") introduces the user-facing option and wires it into both `git bisect start` and `git bisect run`.

The series is well-scoped and includes test coverage, which suggests it addresses a real workflow pain point. The changes are confined to the bisect subsystem, so the risk of unintended side effects elsewhere in Git is low. The option name (`--auto-reset`) is clear and consistent with Git’s naming conventions. No prior discussion or RFC is mentioned, so this appears to be the first public proposal of the feature. The implementation is likely to be uncontroversial, though reviewers may scrutinize the edge cases (e.g., what happens if the bisect is interrupted or fails).
