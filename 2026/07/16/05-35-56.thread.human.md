This thread is about a small but useful quality-of-life improvement for `git bisect`: a new `--auto-reset=<where>` option that automatically returns the working tree to either the original pre-bisect commit (`original`, the default) or the first bad commit (`found`) after the bisect completes. The feature is aimed at both scripted workflows and interactive debugging, eliminating the need for an explicit `git bisect reset`.

The v2 patch series, posted by Harald Nordgren, is now under review and effectively complete. The design settled early on Junio C Hamano’s suggestion to make the option parameterized (`--auto-reset=<where>`) rather than a simple boolean flag, accommodating both use cases in a single interface. The series consists of three patches: the first refactors a helper function to avoid file reopens (just reviewed and uncontroversial), the second extends the `bisect_reset()` plumbing to support quiet checkouts (also uncontroversial), and the third implements the core `--auto-reset` logic with thorough test coverage. The only constraint is that `--auto-reset` cannot be used with `--no-checkout`, as that mode prevents checking out either target.

All three patches are now ready for integration. Junio has already reviewed the preparatory refactoring and found it clean and safe, and the rest of the series has no open questions or unresolved feedback. The feature is self-contained, touches only the bisect subsystem, and introduces no on-disk format changes. Once merged, it will be a welcome convenience for anyone who regularly uses `git bisect`.
