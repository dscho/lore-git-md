This thread introduces a new `--reset-when-found[=<where>]` option for `git bisect`, designed to automate the reset step after identifying the first bad commit. The feature is aimed at scripted and CI workflows, eliminating the need for an explicit `git bisect reset`. The default behavior resets the working tree to the pre-bisect state (`original`), while the `found` option leaves it on the first bad commit for debugging.
