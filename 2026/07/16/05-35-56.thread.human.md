This thread introduces a `--reset-when-found[=<where>]` option to `git bisect`, allowing automatic reset of the working tree after identifying the first bad commit. The feature, now in its sixth iteration (v6), is designed for automated workflows and interactive debugging, eliminating the need for an explicit `git bisect reset`.

The series is technically complete and has addressed all maintainer feedback, including Junio C Hamano’s final review comments. It consists of two patches: a preparatory plumbing change and the core implementation, which refactors the bisect state machine to centralize auto-reset logic. The option supports two modes—`original` (default, resets to the pre-bisect commit) and `found` (leaves the working tree on the first bad commit)—and is wired into both `git bisect start` and `git bisect run`. Junio’s latest review confirms the patch is ready for integration into `next`, with no further changes required or expected.

Johannes Sixt contributed surface-level feedback in earlier versions, all of which has been addressed. The most recent exchange between Harald and Junio reaffirmed the value of the current design as a foundation for future extensibility but did not introduce new action items or objections. The series remains ready for integration.
