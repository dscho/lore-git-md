This thread introduces a new `--reset-when-found[=<where>]` option for `git bisect`, allowing users to automatically reset the working tree after identifying the first bad commit. The feature is now complete and ready for integration, with the v6 series addressing all maintainer feedback.

Harald Nordgren authored the two-patch series, which adds the option with two possible reset targets: `original` (the default, resetting to the pre-bisect commit) or `found` (leaving the first bad commit checked out). The implementation centralizes the auto-reset logic in `cmd_bisect()`, avoids file-scope static variables, and includes thorough test coverage for edge cases. Junio C Hamano, the maintainer, proposed and reviewed the internal clean-ups, which have all been implemented. Johannes Sixt provided surface-level feedback on earlier versions, also fully addressed.

The series touches `bisect.c`, `builtin/bisect.c`, the documentation, and the test suite, with no on-disk format changes or new dependencies. The option is incompatible with `--no-checkout`, and this constraint is enforced with a clear error message. The feature is uncontroversial and now awaits integration into Junio’s `next` branch.
