This thread introduces a `--auto-reset` option for `git bisect` to automatically return the working tree to the original commit after identifying the first bad commit, targeting automated workflows. The v1 patch series by Harald Nordgren (three patches) is under review, with no prior feedback.

Junio C Hamano, the maintainer, has raised a key design question: he expects `--auto-reset` to leave the working tree on the *first bad commit* (the culprit) rather than the original pre-bisect commit. This challenges the current implementation's behavior and suggests a potential mismatch with user expectations. The series includes preparatory refactoring (e.g., replacing `print_file_to_stdout()` with `print_fd_to_stdout()`), a quiet-checkout capability for `bisect_reset()`, and test coverage for the new option. No other technical issues have been flagged yet, but this design question will need resolution before the series can advance.
