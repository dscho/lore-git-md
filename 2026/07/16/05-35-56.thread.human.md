This thread introduces a new `--reset-when-found[=<where>]` option for `git bisect`, allowing users to automatically reset the working tree after identifying the first bad commit. The feature is designed for automated workflows and interactive debugging, eliminating the need for an explicit `git bisect reset`.

The series, now at version 5, has been fully refactored to incorporate Junio C Hamano’s proposed internal simplification. The auto-reset logic is now centralized in the top-level `cmd_bisect()` function, eliminating the `defer_reset` parameter and decoupling `bisect_clean_state()` from `bisect_reset()`. The first bad commit OID is propagated via a file-scope static variable (`first_bad_oid`). The user-facing behavior remains unchanged: the option accepts `original` (reset to the pre-bisect commit, the default) or `found` (leave the working tree on the first bad commit). The series is technically complete, with all substantive and surface-level feedback addressed, including Johannes Sixt’s suggestions on error message boilerplate and test safety.

The implementation touches `bisect.c`, `builtin/bisect.c`, `bisect.h`, and the documentation, with four new tests in `t/t6030-bisect-porcelain.sh` validating auto-reset behavior, state cleanup, and edge cases. The series is marked for integration into `next` and has no remaining open questions or dependencies on other in-flight topics. Harald Nordgren is the author, with Junio and Johannes Sixt as key reviewers.
