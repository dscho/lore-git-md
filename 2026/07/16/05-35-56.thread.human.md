This thread introduces a new `--reset-when-found[=<where>]` option for `git bisect`, allowing users to automatically reset the working tree after identifying the first bad commit. The feature is designed for automated workflows and interactive debugging, eliminating the need for an explicit `git bisect reset`. The default behavior resets to the pre-bisect commit (`original`), but users can also opt to leave the working tree on the first bad commit (`found`).
