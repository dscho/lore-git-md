The `git bisect` command is gaining a new `--reset-when-found[=<where>]` option, designed to streamline automated workflows and interactive debugging. When the bisect identifies the first bad commit, the working tree automatically resets to either the original pre-bisect state (the default, `original`) or the first bad commit itself (`found`). This eliminates the need for an explicit `git bisect reset` afterward.

The feature is implemented in a two-patch series, now at version 4, with the maintainer Junio C Hamano marking it ready for integration into the `next` branch. The design settled on a parameterized option after earlier discussion, replacing the simpler `--auto-reset` with a more explicit name that clarifies when the reset occurs. The only practical limitation is that users cannot conditionally choose the reset target based on the bisect outcome—it must be specified upfront.

All feedback from reviewer Johannes Sixt has been addressed, including error message consistency, shell safety in tests, and translation simplification. The series touches the bisect plumbing and porcelain, updates the man page, and adds thorough test coverage. With no open questions or loose ends, the feature is uncontroversial and expected to graduate to the main branch in the current cycle.
