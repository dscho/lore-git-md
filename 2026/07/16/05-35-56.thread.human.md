The `git bisect --reset-when-found` feature is nearly ready to land. Harald Nordgren’s latest update addresses the last bits of feedback from Johannes Sixt on the v3 patch series, which adds an option to automatically reset the working tree after a bisect completes. The option takes an optional parameter—`original` (the default) to return to the pre-bisect state, or `found` to leave the working tree on the first bad commit—making it useful for both automated scripts and interactive debugging.

The series itself is uncontroversial and has been marked for Junio’s `next` branch. The only remaining work was mechanical: tweaking an error message to use Git’s standard template and fixing a couple of shell-safety issues in the test helpers. Harald has agreed to both changes, so the implementation is now polished and ready for integration. No design questions remain, and the feature doesn’t touch any other in-flight work. If you’ve been waiting to use this in CI or scripts, it should appear in the next release cycle.
