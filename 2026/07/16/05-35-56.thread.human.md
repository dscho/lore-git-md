This thread introduces a new `--reset-when-found[=<where>]` option for `git bisect`, allowing the working tree to automatically reset to either the original pre-bisect commit (`original`, the default) or the first bad commit (`found`) once the bisect completes. The feature is designed for automated workflows and interactive debugging, eliminating the need for an explicit `git bisect reset`.

The v6 patch series, now a clean two-patch set, has addressed all maintainer feedback, including Junio C Hamano’s final review comments. The preparatory patch refactors `bisect_reset()` to accept a `quiet` parameter, while the second patch implements the core feature, centralizing the auto-reset logic in `cmd_bisect()` and removing file-scope static variables. Junio’s feedback was focused on minor stylistic polish—such as reflowing function signatures and a debatable `else` clause—but these were non-blocking, and the author has removed the distracting clean-up hunks. The series is technically complete and ready for integration into `next`.
