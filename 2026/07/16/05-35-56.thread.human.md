This thread introduces a new `--reset-when-found[=<where>]` option for `git bisect`, allowing users to automatically reset the working tree after identifying the first bad commit. The feature is designed for automated workflows and interactive debugging, eliminating the need for an explicit `git bisect reset`. The default behavior resets to the pre-bisect commit (`original`), but users can also choose to leave the working tree on the first bad commit (`found`).

The v3 patch series, authored by Harald Nordgren, has been marked for integration into Junio C Hamano’s `next` branch. The series is uncontroversial, with all substantive feedback addressed. Johannes Sixt’s recent review flagged minor surface-level issues—such as error message boilerplate, shell safety in tests, and test cleanup chaining—but these are mechanical and don’t affect the feature’s core logic. Junio’s latest reply explores a potential future refactoring to improve error-handling consistency but doesn’t block the series’ progress.

The implementation touches `bisect.c`, `builtin/bisect.c`, and related documentation and tests. The option is parameterized, with `<where>` accepting `original` or `found`, and includes plumbing changes like a `quiet` parameter for `bisect_reset()`. The series is self-contained, with no dependencies on other in-flight work. Once the minor fixes from Sixt’s review are addressed, the feature is ready for integration.
