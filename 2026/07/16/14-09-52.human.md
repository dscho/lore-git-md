This is the sixth iteration of a two-patch series that makes submodule fetch errors configurable, targeting the fetch and submodule subsystems. The series introduces `fetch.submoduleErrors` (config) and `--submodule-errors=(fail|warn)` (CLI) to let users choose whether `git fetch --recurse-submodules` should fail hard or merely warn when a submodule’s gitlink points to an unreachable OID. The default remains `fail` for backwards compatibility, preserving existing behavior.

The motivation is clear: upstream topic branches that are still in flux can cause submodule fetches to fail unnecessarily, disrupting workflows. This series addresses that pain point without introducing broader risks. Patch 1 fixes a pre-existing logic flaw in `submodule.c` where phase-1 fetch failures were recorded prematurely, before phase-2 OID-based retries could run. This refactoring ensures errors are only recorded after all retry attempts fail, which is necessary for the configurable policy in Patch 2 to work correctly. The fix also ensures phase-1 failures are reported even when the gitlinked commits are already present locally, and routes all submodule fetch errors through `record_fetch_error()` for consistent reporting.

Patch 2 adds the user-facing controls, including forwarding the resolved setting (whether from CLI or config) to child fetches (`--all`, `--multiple`, nested recursion) when explicitly set. The implementation touches `submodule.c`, `builtin/fetch.c`, documentation files, and adds comprehensive test coverage in `t/t5526-fetch-submodules.sh`. The commit messages are well-explained, and the changes are narrowly scoped to the submodule fetch error-handling path. v6 incorporates Junio’s latest mechanical feedback: the fail/warn helpers now use a singular array name (`submodule_error_name`) and plain `unsigned` instead of `size_t` casts, aligning with Git’s idiomatic style.

The series is technically complete and addresses all prior review feedback. The implementation appears robust, the test coverage is thorough, and the changes are uncontroversial.
