This is a performance patch targeting the `wt-status` subsystem. It addresses a quadratic-time inefficiency in how untracked and ignored file paths are collected during `git status`.

The patch replaces repeated `string_list_insert()` calls—which maintain sorted order but can trigger O(n) array shifts on each insertion—with a single `string_list_append()` pass followed by a final sort and deduplication. The change reduces the overall complexity from O(n²) to O(n log n) while preserving the existing behavior of producing sorted, duplicate-free lists.

The commit message is clear and includes a thoughtful note about a potential alternative (relying on `fill_directory()`'s pre-sorted output) that the author chose not to pursue due to unverified assumptions about duplicate entries. This suggests careful consideration of the trade-offs.

The patch itself is small and focused, touching only `wt-status.c` and making minimal changes to the logic. It looks like a clean, well-motivated optimization that should be uncontroversial. If you care about `git status` performance in repositories with many untracked files, this is worth watching.
