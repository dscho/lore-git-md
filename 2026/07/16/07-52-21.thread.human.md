This thread is about a 5-patch series from Patrick Steinhardt that reintroduces `writev(3p)` support in Git’s wrapper subsystem, with this specific patch addressing a platform compatibility bug on systems like NonStop where small `MAX_IO_SIZE` values cause `writev()` to fail with `EINVAL`. The fix introduces `xwritev()`, a new wrapper function that splits large iovec requests into chunks, handles syscall restarts, and falls back to `xwrite()` when necessary, ensuring consistency with existing error-handling patterns.

The patch targets `wrapper.c` and `wrapper.h`, updating `writev_in_full()` to use the new wrapper. The motivation is clear: Git currently fails on platforms with restrictive `MAX_IO_SIZE` limits, and the fix is straightforward, following established conventions. Randall Becker, the NonStop port maintainer, reported the issue, lending credibility to the need for this change. So far, there’s no review feedback, but the patch appears uncontroversial and well-motivated, focusing on a narrow, technical fix rather than a broader design change. The series is still under review, with no indication of merge status yet.
