This is a review comment on the second patch in Souma’s three-part series teaching `git history` to sign rewritten commits. The series aims to make `fixup`, `reword`, and `split` respect the same GPG-signing configuration (`commit.gpgsign`) and command-line flags (`-S/--gpg-sign`, `--no-gpg-sign`) already supported by `git commit`.

Patrick Steinhardt suggests merging this documentation patch and the next (test) patch into the first (implementation) patch. His rationale is twofold: the changes are tightly coupled, and the documentation synopsis update should not be separated from the code that implements the new flags. He also notes that the test script (`t0450`) would likely fail if the first patch were applied alone, since the synopsis in the manual and the command itself would be out of sync.

The feedback is brief and technical, focusing on patch organization rather than the substance of the feature. No objections to the feature itself are raised, and the suggestion is framed as a practical improvement to the series structure.
