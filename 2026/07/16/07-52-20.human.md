This is a refactoring patch from Patrick Steinhardt, part of a five-patch series. It introduces `writev(3p)` wrappers (`writev_in_full` and `writev_or_die`) to Git’s wrapper layer, mirroring the existing pattern for `write(2)` and `read(2)` calls.

The patch adds a robust `writev_in_full` function in `wrapper.c` that handles partial writes, `EINTR`/`EAGAIN` retries, and updates the `iovec` array in-place to reflect consumed data. It also provides a `writev_or_die` helper in `write-or-die.c` that aborts the process on failure, following Git’s established error-handling convention. The commit message references the preceding patch in the series, which presumably added the low-level `writev` compatibility wrapper.

The implementation is clean and idiomatic: it reuses the same retry logic and error codes (`ENOSPC` for zero-byte writes) as the existing `write_in_full`. No tests or documentation are included, which is typical for plumbing-layer wrappers. The patch is clearly preparatory work for a larger effort, though the series’ overall goal is not stated here.
