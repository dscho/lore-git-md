Thread identity: Patch series to backport `wincred` credential helper bugfixes from Git for Windows to upstream Git. Two-patch series, v1, authored by Johannes Schindelin (Dscho).

Core problem or goal: Fix two critical bugs in the `wincred` credential helper on Windows: (1) memory corruption during credential erasure, causing process termination (status 0xC0000374) and silent credential retention; (2) silent loss of OAuth tokens during storage due to heap corruption when writing both a password and an `oauth_refresh_token` into a single `CredentialBlob`. Both issues were discovered and fixed in Git for Windows v2.55.0(3) and are now upstreamed to Git.

Current status: **Merged to `master`** (Junio C Hamano, 2024-08-15). The series is now part of the mainline codebase and will be included in the next Git release. No prior versions; this was the initial submission.

Key technical details:
- Files touched: `contrib/credential/wincred/git-credential-wincred.c` (10 lines changed across both patches).
- Functions modified: `erase_credential` (patch 1/2) and `store_credential` (patch 2/2).
- Root causes:
  - Patch 1/2: Miscalculation in buffer allocation and `wcsncpy_s` usage, where `CredentialBlobSize` (byte count) was treated as a WCHAR count, leading to a one-WCHAR overrun when appending a terminating NUL.
  - Patch 2/2: Allocation did not account for the terminating NUL when formatting both a password and an `oauth_refresh_token` into a single `CredentialBlob`, and `_snwprintf_s()` received a byte count where it expected a WCHAR count.
- Subsystem: `contrib/credential/wincred` (Windows-specific credential helper).
- No new symbols, CLI options, or on-disk format changes.
- No test coverage included (typical for `contrib/` code).
- Platform-specific: Windows only; no cross-platform impact.
- References prior fix d22a488482 for a similar bug in `get_credential`.
