This is the first patch in an RFC series introducing `git repack --drop-filtered` for partial clones. It adds the command-line options `--drop-filtered` and `--dry-run` to `git repack`, but only implements validation logic—no objects are actually dropped yet.

The patch wires up the new flags in `builtin/repack.c`, enforcing several safety constraints: `--drop-filtered` requires `--filter` (specifically `blob:limit=<n>` for now) and `-a`, is incompatible with `--filter-to` and bitmap writing, and demands a promisor remote to avoid permanent data loss. The `--dry-run` flag is mandatory in this iteration, reflecting the RFC status and the author’s intent to add real deletion logic in later patches.

The constraints are clearly motivated and align with the series’ goal of safe disk-space reclamation in partial clones. The patch is small, focused, and well-explained; the commit message and code comments make the current limitations explicit.
