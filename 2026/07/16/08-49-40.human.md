This is the third patch in a four-patch series (v6) that refactors Git’s core configuration plumbing as part of the ongoing `the_repository` removal effort. The patch moves the global `trust_executable_bit` flag into the repository-scoped `repo_config_values` struct and introduces a new getter function, `repo_trust_executable_bit()`, to access it. Call sites are updated to use the new getter, falling back to `the_repository` where necessary.

The change is mechanical and well-scoped, touching only `apply.c`, `environment.c/h`, and `read-cache.c`. The getter validates the repository pointer and defaults to `1` if none is provided, preserving existing behavior. The patch also initializes the new field in `repo_config_values_init()` and updates `git_default_core_config()` to store the value in the repository struct instead of the global variable.

This patch is uncontroversial and aligns with the established pattern from earlier iterations (v4, now merged). The author has incorporated prior feedback, including dropping redundant comments and ensuring the getter follows the same style as the forthcoming `has_symlinks` migration in patch 4/4. The series as a whole is under active review, with this patch serving as a straightforward intermediate step toward eliminating global state. No behavioral changes are introduced, and the patch is likely to proceed to `next` once the series concludes review.
