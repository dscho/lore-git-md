Thread identity: Bug report / RFC about `git submodule` behavior with sparse-checkout. Originating author: Brad Larson. Thread type: feature request / design discussion.

Core problem or goal: When using `git sparse-checkout` to limit the working tree to a subset of files (e.g., only `src/doc`), `git submodule update --init` initializes *all* submodules, not just those within the sparse-checkout cone. This undermines the purpose of sparse-checkout for repositories with many submodules, as users end up with unnecessary submodule checkouts. The goal is to explore whether the maintainers would accept a patch to make `git submodule` respect sparse-checkout configuration, so it only interacts with submodules whose paths are within the cone.

Current status: Under discussion. No prior versions or patches exist; this is the initial inquiry. No maintainer decision or merge status has been recorded.

Key technical details:
- Subsystems touched: `git submodule`, `git sparse-checkout`.
- Current behavior: `git submodule update --init` initializes all submodules regardless of sparse-checkout cone.
- Proposed behavior: Only initialize submodules whose paths fall within the sparse-checkout cone.
- Reproduction: Clone a large repository (e.g., Rust) with `--filter=blob:none --no-checkout`, set a sparse-checkout pattern, check out the branch, and run `git submodule update --init`. Submodules outside the cone are still initialized.
- No new symbols, CLI options, or on-disk format changes are proposed yet.

Open questions and loose ends:
- Whether the maintainers consider this a desirable change in principle.
- How to handle edge cases (e.g., submodules partially within the cone, nested submodules, or submodules referenced by paths outside the cone).
- Whether this should be opt-in (e.g., via a new flag) or the default behavior.
- Backwards compatibility concerns: existing workflows relying on the current behavior might break.

Participant positions:
- Brad Larson (author): Argues the current behavior is counterintuitive and proposes a patch to make `git submodule` respect sparse-checkout. Position is constructive and open to feedback.

Related work:
- Sparse-checkout / sparse-index efforts (Derrick Stolee, Elijah Newren, and others) aim to improve performance in monorepos by limiting the working tree to a subset of files. This thread intersects with those efforts by addressing submodule behavior within sparse-checkout cones. No direct dependency on other in-flight topics.
