Christian Couder’s 12-patch series to refactor `git fast-import`’s command-line parsing and lay groundwork for libification is now complete with the v2 update. The series standardizes the usage string, eliminates reliance on global variables, and fully integrates the parse-options API, replacing a hand-written command-line parser with a single `parse_options()` call. The most notable user-facing change is the removal of support for five undocumented options (`--alias`, `--get-mark`, `--ls`, `--notes`, and `--cat-blob`) on the command line, as these are only valid within the input stream; a new test verifies they now fail when used incorrectly. Other improvements include support for abbreviated options (e.g., `--dep=5` for `--depth=5`) and more specific error messages for numeric argument parsing failures.

The series has been under review since v1, with Junio C Hamano’s feedback addressed in v2 by eliminating placeholder local variables and completing the parse-options integration. The final patch (12/12) is a mechanical cleanup, removing a redundant `from_stream` argument after earlier changes made it unnecessary. While the code is now functionally complete and CI tests pass (except for a likely unrelated Windows+Meson failure), the series has yet to receive broader technical review beyond Junio’s initial feedback. The libification effort remains unfinished, with many globals still present for future work, and the behavior change in patch 11/12 may need documentation updates. Christian has positioned the series as a step toward full libification, though no further progress is expected until the current changes are reviewed and merged.
