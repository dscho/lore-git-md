This thread is a 12-patch series from Christian Couder refactoring `git fast-import` to standardize its usage string and modernize its command-line parsing infrastructure. The goal is to reduce reliance on global variables and prepare the command for eventual libification. The series is now at v2, posted after Junio C Hamano’s feedback on v1 resolved concerns about placeholder variables by fully integrating the parse-options API.

The most recent update (patch 9/12) replaces the hand-written usage string with a structured `struct option` array, grouping options into logical sections and aligning the help output with the SYNOPSIS documentation. Hidden options are now properly organized under an `OPT_HIDDEN_GROUP` macro introduced earlier in the series, ensuring they appear only with `--help-all`. While this patch is purely presentational—it changes only the help text, not the parsing logic—it sets the stage for later patches that will complete the parse-options integration and encapsulate remaining globals in a new `struct fast_import_state`.

The series has passed CI tests (except for a likely unrelated Windows+Meson failure) and awaits broader review. No maintainer decisions have been made yet, and the libification effort remains incomplete. The only behavior change introduced so far is in patch 12/12, which rejects undocumented options on the command line—this may need further documentation or release note updates. Christian has addressed all feedback from Junio, but no other contributors have weighed in with substantive technical review.
