This thread is a patch series from Christian Couder refactoring `git fast-import` to standardize its usage string, reduce reliance on global variables, and modernize its command-line parsing. The series, now at version 3 with 12 patches, aims to fully integrate the parse-options API and enable future libification. The latest update is a small, mechanical refactoring that localizes loop counters in `cmd_fast_import()` to their respective loops, using the most appropriate type for each. This change is purely preparatory and doesn’t alter behavior.

Key participants include Christian (the author), Junio C Hamano (the maintainer), and Elijah Newren, who provided substantive feedback on earlier versions. Elijah’s review identified three behavioral changes in the series—most notably an inconsistency with the `--allow-unsafe-features` option—but the author has documented these as known limitations and deferred a general fix. Junio’s feedback on earlier versions has been addressed, and the series is now under broader review. The only remaining open question is whether to address the `--allow-unsafe-features` inconsistency in a future update.

The series touches `parse-options.h`, `parse-options.c`, `builtin/fast-import.c`, and related documentation and tests. No on-disk format changes are introduced, but the command-line behavior now rejects undocumented options (e.g., `--alias`, `--get-mark`) and supports abbreviated options (e.g., `--dep=5` for `--depth=5`). The work aligns with Git’s broader parse-options modernization and libification efforts.
