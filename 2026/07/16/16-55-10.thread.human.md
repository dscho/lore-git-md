Christian Couder’s twelve-patch series to refactor `git fast-import`’s usage string and modernize its command-line parsing with the parse-options API is now in its second revision and under active review. The series aims to standardize help text, reduce reliance on global variables, and pave the way for libification by fully integrating the parse-options API. Junio’s feedback from the first version—concerning awkward placeholder variables—has been addressed, and the series now completes the parse-options integration, eliminating redundant code and shrinking the codebase by 38 lines overall.

The most significant user-visible change comes in patch 11, which switches the command-line parser from a hand-written loop to `parse_options()`. This removes support for five undocumented options (`--alias`, `--get-mark`, `--ls`, `--notes`, and `--cat-blob`) on the command line, as these are only meaningful inside the input stream, and adds support for abbreviated options (e.g., `--dep=5` for `--depth=5`) and space-separated values (e.g., `--depth 5`). A new test verifies that the removed options now fail when given on the command line. Elijah Newren’s review of this patch identified a subtle inconsistency: the early scan for `--allow-unsafe-features` (needed to process in-stream "feature" lines) is stricter than `parse_options()` itself, potentially causing the in-stream feature to be rejected even when the command-line option is accepted. He suggests either documenting this as a known limitation or adjusting the early scan to match `parse_options()`’s flexibility. His follow-up confirms that beyond this and two minor editorial issues—rewording the `PARSE_OPT_LASTARG_DEFAULT` documentation and reformatting overly long function signatures—he has no further objections, signaling the series is otherwise ready for broader review.

The series touches `parse-options.h`, `parse-options.c`, `builtin/fast-import.c`, and related documentation, introducing the `OPT_HIDDEN_GROUP` macro and a new `struct fast_import_state` to encapsulate globals. CI tests pass except for a likely unrelated Windows+Meson failure. No merge status has been reported, and the series remains under review with no substantive technical concerns beyond the three open nits. The libification effort is incomplete, but this series represents a significant step toward that goal.
