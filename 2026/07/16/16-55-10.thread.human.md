This patch series from Christian Couder continues its march toward modernizing `git fast-import` by standardizing its usage string and paving the way for libification. The latest update, patch 9/12 in the v3 series, replaces the old hand-written usage string with a structured `struct option` array, grouping options into logical sections (Common, Marks, Submodule rewrite, Signing, and Advanced) and marking hidden options appropriately. The SYNOPSIS in the man page has been updated to match, and the command is now removed from the list of help-text mismatches, signaling that the documentation is finally in sync.

The series has seen steady progress since v1, with all feedback from Junio C Hamano and Elijah Newren addressed. Elijah’s review of patch 11/12 identified three behavioral changes introduced by the switch to `parse_options()`—space-separated values, bare `--` support, and the `--allow-unsafe-features` inconsistency—and the author has now documented these thoroughly in the cover letter, commit message, and man page. The inconsistency, where the early scan for `--allow-unsafe-features` is stricter than `parse_options()`, is flagged as a known limitation with a `NEEDSWORK` comment, but the author proposes deferring a general fix for now. The rest of the series is largely mechanical, refactoring globals into a `struct fast_import_state` and preparing the codebase for the final parse-options integration.

The only unresolved loose end is the Windows+Meson CI failure, which appears unrelated, and the broader question of whether the behavioral changes in patch 11/12 will require release notes. The series is otherwise ready for broader review, with no substantive objections remaining. If you’ve been following the libification effort, this is a key step forward—Christian’s work here lays the groundwork for cleaner, more maintainable code while keeping the existing functionality intact.
