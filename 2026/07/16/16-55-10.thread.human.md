This thread is about a 12-patch series from Christian Couder that refactors `git fast-import` to standardize its usage string, reduce reliance on global variables, and modernize its command-line parsing using Git’s `parse-options` API. The ultimate goal is to enable libification by eliminating globals and improving code structure. The series is now complete with the posting of v3, which addresses all feedback from Junio C Hamano and Elijah Newren.

The key changes include introducing a new `OPT_HIDDEN_GROUP` macro for organizing hidden options, documenting existing `parse-options` flags and macros, encapsulating global state in a `struct fast_import_state`, and switching the command-line parser from a hand-written loop to `parse_options()`. The most significant behavioral change comes in patch 11/12, which rejects five undocumented options (`--alias`, `--get-mark`, `--ls`, `--notes`, and `--cat-blob`) on the command line (they are only meaningful inside the input stream), enables abbreviated options and space-separated values, and accepts bare `--` as an end-of-options marker. This patch also introduces a known inconsistency with `--allow-unsafe-features`: the early scan for this option (needed to process in-stream "feature" lines) is stricter than `parse_options()`, rejecting abbreviations and space-separated values. This limitation is documented in the man page, cover letter, and commit message, and flagged with a `NEEDSWORK` comment in the code, but the author proposes deferring a general fix.

The series has passed CI except for a likely unrelated Windows+Meson failure. No merge status has been reported, and the series remains under review. Elijah Newren’s review identified the three behavioral changes in patch 11/12, with the `--allow-unsafe-features` inconsistency being the most significant open point. His feedback on documentation wording and stylistic issues has been incorporated. Junio’s feedback on earlier versions has also been addressed. The final patch (12/12) is a mechanical cleanup that removes a redundant argument from `parse_one_feature()` and its callers, simplifying the code after the parse-options integration. The series is now ready for broader review or integration.
