This is the first patch in a seven-part feature series adding new path-related keys to the `git repo info` command. It introduces `path.toplevel.absolute` and `path.toplevel.relative`, which expose the repository’s top-level working tree directory in a script-friendly format. The implementation is clean: it adds two new getter functions in `builtin/repo.c`, updates the documentation, and includes thorough tests covering both normal and bare repositories.

The motivation is straightforward: scripts currently rely on `git rev-parse --show-toplevel` or manual path inference, which is less robust than a dedicated, strictly formatted key. The patch handles edge cases (bare repositories return an empty string) and follows the established pattern of suffix-based formatting (absolute vs. relative paths). The commit message is clear, and the code aligns with Git’s conventions.

This is a well-scoped, uncontroversial addition. It doesn’t touch core Git internals or depend on other in-flight work, making it a safe candidate for merging once the full series is reviewed. Reviewers may suggest minor adjustments to naming or documentation wording, but the substance looks solid. The patch is part of a GSoC project mentored by Justin Tobler and Lucas Seiki Oshiro.
