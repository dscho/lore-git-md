Subject: [PATCH 0/7] fast-import: refactor usage string and libify
Series version: v3 (12 patches)
Originating author: Christian Couder <christian.couder@gmail.com>
Thread type: patch series

Core problem or goal
Refactor `git fast-import` to standardize its usage string with its SYNOPSIS documentation, reduce reliance on global variables, and modernize the parse-options API. The series introduces infrastructure (a new `OPT_HIDDEN_GROUP` macro and a `struct fast_import_state`) and documents existing parse-options flags to support future libification work. The ultimate goal is to fully parse command-line arguments via the parse-options API, eliminating remaining global variables and enabling libification.

Current status
Under review; v3 is complete with all 12 patches posted and all feedback from Junio C Hamano and Elijah Newren addressed. The cover letter and commit messages explicitly document the three behavioral changes introduced by patch 11/12 (space-separated values, bare `--`, and the `--allow-unsafe-features` inconsistency). The `--allow-unsafe-features` inconsistency is flagged in the code with a `NEEDSWORK` comment and in the man page with concrete examples; the author proposes to defer a general fix in favor of documenting the limitation. CI tests pass except for a likely unrelated Windows+Meson failure. No merge status reported; series remains under review.

Elijah Newren's review of patch 11/12 identified three behavioral changes introduced by the switch to `parse_options()`:
1. A bare `--` (or trailing `--`) is now accepted as the end-of-options marker, aligning with conventional `parse_options()` behavior.
2. Value-taking options now accept space-separated arguments in addition to the `--opt=value` form.
3. The early scan for `--allow-unsafe-features` (which predates `parse_options()` and is needed to process in-stream "feature" lines) is stricter than `parse_options()` itself: it only matches the exact spelling and stops at the first non-option token, while `parse_options()` accepts abbreviations (e.g., `--allow-unsafe`) and space-separated values. This can cause the in-stream feature to be rejected even though the command-line option is accepted, creating a subtle inconsistency. The v3 cover letter, commit message, and man page now explicitly document this as a known limitation, and a `NEEDSWORK` comment in the code proposes teaching the early scan about value-taking options. No code changes were made to address the inconsistency in this version.

Key technical details
- New `OPT_HIDDEN_GROUP` macro (patch 1/12) for organizing hidden options in parse-options, added to `parse-options.h`, with usage formatter updates in `parse-options.c` to skip hidden groups unless `--help-all` is requested. Test coverage added in `test-parse-options.c` and `t/t0040-parse-options.sh` verifies that hidden groups and options appear only in `--help-all` output, not in the default `-h` help. The macro is purely additive and enables later patches to group `git fast-import`'s hidden options logically.
- Patch 2/12 adds a "Option flags" subsection to `Documentation/technical/api-parse-options.adoc` documenting per-option flags (`PARSE_OPT_HIDDEN`, `PARSE_OPT_OPTARG`, `PARSE_OPT_LASTARG_DEFAULT`, etc.), their purpose, and typical use cases, distinguishing them from global `parse_options()` flags. The documentation clarifies the `-h` versus `--help-all` behavior for hidden options and incorporates Elijah Newren's feedback on the `PARSE_OPT_LASTARG_DEFAULT` description: the rewording clarifies that the no-argument form is only accepted when the option is the last token on the command line, and that it should not be combined with `PARSE_OPT_OPTARG`.
- Patch 3/12 adds documentation for `OPT_*_F()` macro variants (which accept a trailing `flags` argument) and the `OPT_HIDDEN_GROUP()` and `OPT_HIDDEN_BOOL()` convenience macros to `Documentation/technical/api-parse-options.adoc`, explaining the `_F` suffix convention and placing the new macros adjacent to their non-hidden counterparts (`OPT_GROUP()` and `OPT_BOOL()`). The patch is purely additive, inserting 18 lines of explanatory text without altering existing behavior.
- Patch 4/12 localizes loop counters in `cmd_fast_import()` to their respective `for` loops, using the most appropriate type (`int`, `unsigned int`, or `size_t`) for each loop's bounds. The change is purely mechanical, touching only `builtin/fast-import.c` and reducing its line count by two while preserving behavior. No new symbols or on-disk/CLI behavior changes.
- Patch 5/12 changes the type of `show_stats` and `quiet` from `unsigned int` to `int` in `builtin/fast-import.c` to match `OPT_BOOL`'s expected target type. No behavior change; purely mechanical. The patch ensures type consistency ahead of the parse-options integration in patch 11/12, where these flags will be parsed via `OPT_BOOL` callbacks. The variables remain globals for now but will be encapsulated in `struct fast_import_state` in later patches.
- Patch 6/12 factors out `option_max_pack_size()`, `option_big_file_threshold()`, `option_signed_commits()`, `option_signed_tags()`, and `option_quiet()` to encapsulate the parsing logic for their respective options. These helpers replace generic "unknown option" failures with specific `die()` messages when `git_parse_ulong()` fails to parse numeric arguments. The refactoring is mechanical and preparatory, touching only `builtin/fast-import.c`. The commit message explicitly notes the improved error messages as a minor user-visible change.
- Patch 7/12 introduces `struct fast_import_state` to encapsulate `global_argc`, `global_argv`, and `global_prefix`, passing the struct as the first argument to nearly every function in `builtin/fast-import.c`. Many functions receive the new parameter only to forward it or for future use, so they are marked `UNUSED` to silence compiler warnings. Elijah Newren's feedback on overly long function signatures has been addressed in v3 by reformatting all modified lines to Git's 80-character line limit, using multi-line style (e.g., `note_change_n` split across four lines). The feedback was purely stylistic; the reviewer explicitly stated the "substance of the patch looks good." The patch touches only `builtin/fast-import.c` and is a preparatory step toward eliminating globals.
- Patch 8/12 moves the global variables `seen_data_command` and `allow_unsafe_features` into `struct fast_import_state` and reorders `fast_import_state_init()` to avoid clobbering the early `--allow-unsafe-features` command-line scan. The `UNUSED` marker is removed from `check_unsafe_feature()` because its `state` parameter is now used. The patch is purely mechanical, touching only `builtin/fast-import.c` and preserving behavior. No new symbols are introduced beyond the struct members themselves.
- Patch 9/12 replaces the hand-written, single-line usage string with a `struct option` array, grouping options into logical sections (Common, Marks, Submodule rewrite, Signing, and Advanced), marking hidden options with `PARSE_OPT_HIDDEN`, and using the `OPT_HIDDEN_GROUP` macro. The SYNOPSIS line in `Documentation/git-fast-import.adoc` is updated to match, and the command is removed from `t0450/adoc-help-mismatches`. The change is purely presentational and preparatory: the new `fast_import_options` array is passed to `show_usage_with_options_if_asked()` to render `-h` and `--help-all` output, but the actual parsing is still handled by the existing hand-written loop in `parse_argv()`. The patch touches only `builtin/fast-import.c`, `Documentation/git-fast-import.adoc`, and the test file `t/t0450/adoc-help-mismatches`, with no behavior changes beyond improved help output.
- Patch 10/12 converts a dozen command-line options from direct string/unsigned assignments to `OPT_CALLBACK` entries in the `fast_import_options` array, introducing dedicated callback functions (e.g., `option_parse_date_format`, `option_parse_max_pack_size`) that delegate to the existing helpers (e.g., `option_date_format`, `option_max_pack_size`). The callbacks are not yet invoked by `parse_options()`, so behavior remains unchanged. Each callback follows the same pattern: it checks for the `unset` flag (using `BUG_ON_OPT_NEG`), delegates to the existing helper, and returns 0. The `fast_import_options` array is updated to use `OPT_CALLBACK_F` for each converted option, passing the appropriate callback and adjusting the `opt->value` field where needed (e.g., for options that store their result in `struct fast_import_state`). The patch touches only `builtin/fast-import.c`, adding 168 lines and removing 40, and is purely preparatory for the parse-options integration in patch 11/12.
- Patch 11/12 (the behavior-changing patch) switches the command-line parser from a hand-written loop to `parse_options()`, completing the parse-options integration. It removes support for five undocumented options (`--alias`, `--get-mark`, `--ls`, `--notes`, and `--cat-blob`) on the command line, as these are only meaningful inside the input stream. A new test (`t9300-fast-import.sh`) verifies that each of these options now fails when given on the command line. The patch also enables abbreviated options (e.g., `--dep=5` for `--depth=5`), space-separated values for value-taking options (e.g., `--depth 5`), and accepts bare `--` as an end-of-options marker. The man page (`Documentation/git-fast-import.adoc`) is updated to document the known inconsistency with `--allow-unsafe-features`: the early scan for this option (needed to process in-stream "feature" lines) is stricter than `parse_options()`, rejecting abbreviations and space-separated values. This is flagged as a `NEEDSWORK` in the code and documented as a limitation in the man page, with concrete examples showing which command-line forms are accepted or rejected. The patch touches `builtin/fast-import.c`, `Documentation/git-fast-import.adoc`, and `t/t9300-fast-import.sh`, with no new symbols introduced beyond the existing `parse_options()` integration. The changes are well-motivated and align with the series’ goal of standardizing the usage string and enabling libification.
- Patch 12/12 removes the redundant `from_stream` argument from `parse_one_feature()` and its callers, simplifying the code after patch 11/12 eliminated the only non-stream call site. The change is purely mechanical: every invocation previously passed `1` as the `from_stream` argument, so the parameter is dropped and the value hard-coded. The `check_unsafe_feature()` helper is updated to match, removing its own `from_stream` parameter since it is now always called in a stream context. The patch touches only `builtin/fast-import.c`, reducing its line count by 9 while preserving behavior. No new symbols are introduced.
- Files touched: `parse-options.h`, `parse-options.c`, `builtin/fast-import.c`, `Documentation/technical/api-parse-options.adoc`, `Documentation/git-fast-import.adoc`, and the test suite (`t0040`, `t0450`, `t9300`).
- No on-disk format changes; CLI behavior changes include:
  - Rejection of undocumented options (`--alias`, `--get-mark`, `--ls`, `--notes`, `--cat-blob`) on the command line (patch 11/12).
  - Improved error messages for numeric argument parsing failures (patch 6/12).
  - Support for abbreviated options (e.g., `--dep=5` for `--depth=5`) and space-separated values (e.g., `--depth 5`) (patch 11/12).
  - Acceptance of bare `--` as an end-of-options marker (patch 11/12).
  - Stricter early scan for `--allow-unsafe-features` compared to `parse_options()`, creating a potential inconsistency where the command-line option is accepted but the in-stream feature is rejected (patch 11/12). This is now documented as a known limitation in the man page, cover letter, and commit message, with a `NEEDSWORK` comment in the code.
- New symbols: `OPT_HIDDEN_GROUP`, `struct fast_import_state`, `fast_import_state_init()`, `seen_data_command`, `allow_unsafe_features` (now members of `struct fast_import_state`), `parse_allow_unsafe_features()`, `option_max_pack_size()`, `option_big_file_threshold()`, `option_signed_commits()`, `option_signed_tags()`, `option_quiet()`, `option_parse_date_format()`, `option_parse_max_pack_size()`, and other `option_parse_*()` callbacks for the dozen options converted in patch 10/12.
