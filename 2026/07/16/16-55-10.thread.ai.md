Subject: [PATCH 0/7] fast-import: refactor usage string and libify
Series version: v2 (12 patches)
Originating author: Christian Couder <christian.couder@gmail.com>
Thread type: patch series

Core problem or goal
Refactor `git fast-import` to standardize its usage string with its SYNOPSIS documentation, reduce reliance on global variables, and modernize the parse-options API. The series introduces infrastructure (a new `OPT_HIDDEN_GROUP` macro and a `struct fast_import_state`) and documents existing parse-options flags to support future libification work. The ultimate goal is to fully parse command-line arguments via the parse-options API, eliminating remaining global variables and enabling libification.

Current status
Under review; v2 posted addressing Junio C Hamano's feedback on v1. The v2 series eliminates placeholder local variables in the `struct option` array by fully integrating the parse-options API, completing the libification step for command-line parsing. Patch 6/12 (new in v2) factors out five option-handling code paths (`--max-pack-size`, `--big-file-threshold`, `--signed-commits`, `--signed-tags`, and `--quiet`) into dedicated `option_*()` helper functions to enable their reuse as `OPT_CALLBACK` targets, improving error reporting by replacing generic "unknown option" failures with specific `die()` messages when `git_parse_ulong()` fails to parse numeric arguments. Patch 7/12 (new in v2) introduces `struct fast_import_state` to encapsulate `global_argc`, `global_argv`, and `global_prefix`, passing the struct as the first argument to most functions in `builtin/fast-import.c`; the change is purely mechanical, with no behavior change intended. Patch 8/12 (new in v2) moves the global variables `seen_data_command` and `allow_unsafe_features` into `struct fast_import_state` and adjusts initialization order to avoid a memset clobber during the early `--allow-unsafe-features` command-line scan; the `UNUSED` marker is removed from `check_unsafe_feature()` because its `state` parameter is now used. Patch 9/12 (new in this update) replaces the hand-written, single-line usage string with a `struct option` array, grouping options into logical sections (Common, Marks, Submodule rewrite, Signing, and Advanced), marking hidden options with `PARSE_OPT_HIDDEN`, and using the `OPT_HIDDEN_GROUP` macro. The SYNOPSIS line in `Documentation/git-fast-import.adoc` is updated to match, and the command is removed from `t0450/adoc-help-mismatches`. The change is purely presentational: the parse-options API is used only to render the help text, not to parse arguments. CI tests pass except for a likely unrelated Windows+Meson failure. No merge status reported; series remains under review.

Key technical details
- New `OPT_HIDDEN_GROUP` macro (patch 1/12) for organizing hidden options in parse-options, added to `parse-options.h`, with usage formatter updates in `parse-options.c` to skip hidden groups unless `--help-all` is requested. Test coverage added in `test-parse-options.c` and `t/t0040-parse-options.sh`.
- Added "Option flags" subsection to `Documentation/technical/api-parse-options.adoc` (patch 2/12) documenting per-option flags (`PARSE_OPT_HIDDEN`, `PARSE_OPT_OPTARG`, etc.), their purpose, and typical use cases, distinguishing them from global `parse_options()` flags. The documentation clarifies the `-h` versus `--help-all` behavior for hidden options.
- Patch 3/12 adds documentation for `OPT_*_F()` macro variants (which accept a trailing `flags` argument) and the `OPT_HIDDEN_GROUP()` and `OPT_HIDDEN_BOOL()` convenience macros to `Documentation/technical/api-parse-options.adoc`, explaining the `_F` suffix convention and placing the new macros adjacent to their non-hidden counterparts (`OPT_GROUP()` and `OPT_BOOL()`).
- Patch 4/12 localizes loop counters in `cmd_fast_import()` to their respective `for` loops, using the most appropriate type (`int`, `unsigned int`, or `size_t`) for each loop's bounds.
- Patch 5/12 changes the type of `show_stats` and `quiet` from `unsigned int` to `int` in `builtin/fast-import.c` to match `OPT_BOOL`'s expected target type. No behavior change; purely mechanical.
- Patch 6/12 factors out `option_max_pack_size()`, `option_big_file_threshold()`, `option_signed_commits()`, `option_signed_tags()`, and `option_quiet()` to encapsulate the parsing logic for their respective options. These helpers replace generic "unknown option" failures with specific `die()` messages when `git_parse_ulong()` fails to parse numeric arguments. The refactoring is mechanical and preparatory, touching only `builtin/fast-import.c`.
- Patch 7/12 introduces `struct fast_import_state` to encapsulate `global_argc`, `global_argv`, and `global_prefix`, passing the struct as the first argument to nearly every function in `builtin/fast-import.c`. Many functions receive the new parameter only to forward it or for future use, so they are marked `UNUSED` to silence compiler warnings. The change is purely mechanical and preparatory, touching only `builtin/fast-import.c`.
- Patch 8/12 moves the global variables `seen_data_command` and `allow_unsafe_features` into `struct fast_import_state` and reorders `fast_import_state_init()` to avoid clobbering the early `--allow-unsafe-features` command-line scan. The `UNUSED` marker is removed from `check_unsafe_feature()` because its `state` parameter is now used. No behavior change is intended; the patch touches only `builtin/fast-import.c`.
- Patch 9/12 replaces the hand-written, single-line usage string with a `struct option` array, grouping options into logical sections (Common, Marks, Submodule rewrite, Signing, and Advanced), marking hidden options with `PARSE_OPT_HIDDEN`, and using the `OPT_HIDDEN_GROUP` macro. The SYNOPSIS line in `Documentation/git-fast-import.adoc` is updated to match, and the command is removed from `t0450/adoc-help-mismatches`. The change is purely presentational and preparatory, with no behavior change beyond improved help output.
- Patch 10/12 introduces `parse_option_alias_cb()` to handle the `--alias` option, which is now parsed via `OPT_CALLBACK`.
- Patch 11/12 adds `parse_option_date_format_cb()` to handle the `--date-format` option via `OPT_CALLBACK` and `parse_option_pack_size_limit_cb()` to handle the `--max-pack-size` option via `OPT_CALLBACK`. It completes the parse-options integration by rejecting undocumented options (`--alias`, `--get-mark`, `--cat-blob`, `--ls`, and `--notes`) on the command line, as these are intended for use only in the input stream. This is a behavior change.
- Files touched: `parse-options.h`, `parse-options.c`, `builtin/fast-import.c`, `Documentation/technical/api-parse-options.adoc`, `Documentation/git-fast-import.adoc`, and the test suite (`t0040`, `t0450`).
- No on-disk format changes; CLI behavior change limited to rejection of undocumented options and improved error messages for numeric argument parsing failures.
- New symbols: `OPT_HIDDEN_GROUP`, `struct fast_import_state`, `fast_import_state_init()`, `seen_data_command`, `allow_unsafe_features` (now members of `struct fast_import_state`), `parse_allow_unsafe_features()`, `parse_option_alias_cb()`, `parse_option_date_format_cb()`, `parse_option_pack_size_limit_cb()`, `option_max_pack_size()`, `option_big_file_threshold()`, `option_signed_commits()`, `option_signed_tags()`, `option_quiet()`.
