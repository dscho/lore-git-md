Subject: [PATCH 0/7] fast-import: refactor usage string and libify
Series version: v1 (v2 in progress)
Originating author: Christian Couder <christian.couder@gmail.com>
Thread type: patch series

Core problem or goal
Refactor `git fast-import` to standardize its usage string with its SYNOPSIS documentation, reduce reliance on global variables, and modernize the parse-options API. The series introduces infrastructure (a new `OPT_HIDDEN_GROUP` macro and a `struct fast_import_state`) and documents existing parse-options flags to support future libification work. The ultimate goal is to fully parse command-line arguments via the parse-options API, eliminating remaining global variables and enabling libification.

Current status
Under review; v1 posted and feedback received. Junio C Hamano provided initial feedback on the final patch (7/7), expressing discomfort with the intermediate state of the refactor—specifically, the introduction of unused local variables in the `struct option` array as placeholders for future parsing logic. Christian has acknowledged the feedback and is preparing v2 to fully integrate the parse-options API, which will remove the placeholder variables and complete the libification step. The `.mailmap` discussion was resolved in v1 and is unrelated to the technical content. No other reviewers have engaged yet.

Key technical details
- New `OPT_HIDDEN_GROUP` macro (patch 1/7) for organizing hidden options in parse-options.
- Added "Option flags" subsection to `Documentation/technical/api-parse-options.adoc` (patch 2/7) documenting per-option flags (`PARSE_OPT_HIDDEN`, `PARSE_OPT_OPTARG`, etc.), their purpose, and typical use cases, distinguishing them from global `parse_options()` flags.
- Patch 3/7 adds documentation for `OPT_*_F()` macro variants (which accept a trailing `flags` argument) and the `OPT_HIDDEN_GROUP()` and `OPT_HIDDEN_BOOL()` convenience macros to the same document, explaining the `_F` convention and placing the new macros adjacent to their non-hidden counterparts.
- Patch 4/7 localizes loop counters in `cmd_fast_import()` to their respective `for` loops, using the most appropriate type (`int`, `unsigned int`, or `size_t`) for each loop's bounds.
- Patch 5/7 introduces `struct fast_import_state` to encapsulate `global_argc`, `global_argv`, and `global_prefix`, passing the struct as the first argument to most functions in `builtin/fast-import.c`.
- Patch 6/7 moves two more global variables—`seen_data_command` and `allow_unsafe_features`—into `struct fast_import_state` and adjusts initialization order to avoid a memset clobber during the early `--allow-unsafe-features` command-line scan. No behavior change is intended.
- Patch 7/7 (v1) replaced the hand-written, single-line usage string with a `struct option` array, grouping options into logical sections (Common, Marks, Submodule rewrite, Signing, and Advanced), marking hidden options with `PARSE_OPT_HIDDEN`, and using the `OPT_HIDDEN_GROUP` macro. The SYNOPSIS line in `Documentation/git-fast-import.adoc` was updated to match, and the command was removed from `t0450/adoc-help-mismatches`. The patch introduced function-local variables (e.g., `pack_size_limit`, `date_format`) referenced in the `struct option` array but never initialized or used, serving as placeholders for future parsing logic. In v2, these placeholders will be removed as the parse-options API will fully parse command-line arguments, and the parsed values will be stored in `struct fast_import_state`.
- Files touched: `parse-options.h`, `parse-options.c`, `builtin/fast-import.c`, `Documentation/technical/api-parse-options.txt`, `Documentation/git-fast-import.adoc`, and the test suite (`t0450`).
- No on-disk format or CLI behavior changes; CI tests passed.
- New symbols: `OPT_HIDDEN_GROUP`, `struct fast_import_state`, `fast_import_state_init()`, `seen_data_command`, `allow_unsafe_features` (now members of `struct fast_import_state`).
