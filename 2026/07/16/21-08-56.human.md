This is a review comment from Junio C Hamano on the first patch of Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. The series aims to let users reclaim disk space by safely removing locally cached promisor blobs that exceed a size threshold.

Junio’s feedback is narrowly focused on a safety check in the option-parsing logic. The patch currently disables bitmaps (via `write_bitmaps = 0`) only after all options and configuration have been parsed, which Junio points out is too late: if the user explicitly requested bitmaps on the command line (`--write-bitmap-index`), silently overriding that choice could mask a configuration error or user intent. He suggests the check should happen earlier, before the bitmap configuration is finalized, to ensure the user’s explicit request is respected or explicitly rejected.

The rest of the patch’s validation logic—requiring `--filter`, `-a`, a promisor remote, and rejecting `--filter-to`—is not questioned here. Junio’s comment is a surface-level but important correctness fix: it prevents a silent override of an explicit user option, which would otherwise be a subtle and potentially confusing behavior. The fix itself is straightforward and does not affect the series’ core functionality or design.
