Core problem or goal
A regression introduced in commit `dd4bc01c0a` (May 2026) broke path filtering in `git rev-list --no-walk <commit> -- <path>`. The command now outputs all commits regardless of whether they touched the specified paths, instead of filtering to commits that modified those paths.

Current status
Under review. The patch is a minimal two-line fix in `revision.c` that restores the call to `try_to_simplify_commit()` for the `REV_WALK_NO_WALK` case by folding it into the existing `REV_WALK_REFLOG` logic. Three new tests in `t/t6017-rev-list-stdin.sh` verify the fix; two fail without it, one is defensive.
