This is the final patch in Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. It implements the drop log (`$GIT_DIR/objects/info/promisor-dropped`) that records every object removed by `--drop-filtered`, enabling better error messages when lazy fetches fail later.

The log format is simple: each line lists the object ID, a timestamp, the filter spec used, and the promisor remote(s) the object was expected to be recoverable from. The remote field currently lists *all* configured promisor remotes rather than the specific one that actually holds the object, because Git lacks a way to query remote object availability locally. A NEEDSWORK comment flags this as a follow-up once the planned `remote-object-info` protocol command lands. The log is written only on real runs, not dry runs.

The patch adds a new `append_drop_log()` function in `repack-promisor.c` that handles file creation, timestamp generation, and writing each dropped OID to the log. The function is called from `builtin/repack.c` after the repack completes, passing the `drop_oids` set computed earlier in the series. Error handling is thorough: safe creation of leading directories, file open/close checks, and a single warning if any I/O fails.

This completes the core functionality of the series. The drop log is the last missing piece that makes `--drop-filtered` safe for real-world use, and its design is forward-compatible with future improvements like remote-specific object tracking. The implementation is clean and well-motivated, though the deferred remote verification leaves a known limitation. No reviews have appeared yet, but the patch looks ready for feedback.
