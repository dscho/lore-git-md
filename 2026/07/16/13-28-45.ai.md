This is the fourth patch in Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. It adds the core enumeration logic that identifies which promisor blobs exceed the user-specified size threshold and are therefore candidates for removal.

The patch works around a fundamental limitation in the existing repack machinery: promisor objects are handled separately (via `repack_promisor_objects()`) before the main `pack-objects` run, so the filtered pack produced by `write_filtered_pack()` is always empty in partial clones. Instead, the patch introduces `enumerate_promisor_blobs()` in the new `repack-filtered.c` file. This function walks all promisor objects directly using `odb_for_each_object()` with the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag, collects them into an oidset, and then applies the filter (currently only `blob:limit`) via the helper `list_objects_filter__filter_oidset()` added in patch 2/7. In `--dry-run` mode, it prints the OIDs of the blobs that would be dropped.

The implementation is careful to avoid lazy fetches during enumeration by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query. It also relies on the caller (`cmd_repack`) to validate preconditions (e.g., that a promisor remote is configured and the filter is `blob:limit`), so no redundant `is_promisor_object()` checks are needed. The patch does not yet perform the actual deletion or promisor-remote verification—those are deferred to later patches.

Key technical details for follow-up discussion: the new `enumerate_promisor_blobs()` function, the `collect_promisor_blob()` callback, and the conditional branching in `cmd_repack()` that bypasses `write_filtered_pack()` when `--drop-filtered` is active. The patch also introduces the `collect_cb_data` struct and the `all_promisor_blobs`/`to_drop` oidsets as internal data structures. The commit message explicitly notes that the enumeration is safe because every object visited is a promisor object by construction.
