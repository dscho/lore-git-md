This is the third patch in Siddharth Shrimali’s seven-part RFC series introducing `git repack --drop-filtered` for partial clones. The patch extends `repack_promisor_objects()` to accept an optional `oidset` of objects to exclude when rebuilding the promisor pack. The change is mechanical: the new `to_drop` parameter is plumbed through to the internal `write_oid()` callback, which skips any OID found in the set. All existing callers continue to pass `NULL`, so there is no behavior change yet.

The patch is clearly a building block for the `--drop-filtered` feature: it enables the promisor pack to be rebuilt without the objects that will later be dropped. The commit message is concise and the diff is small, touching only three files. No safety checks or error handling are added here—those are deferred to later patches in the series.

This is a well-scoped, uncontroversial refactoring that fits cleanly into the larger design. It does not introduce new user-visible behavior, but it is a necessary step toward the goal of safely reclaiming disk space in partial clones. The patch looks solid and ready for review, though the RFC status means the author expects feedback before finalizing the API.
