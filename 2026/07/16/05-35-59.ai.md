This is the third and final patch in Harald Nordgren’s three-part **feature** series introducing `--auto-reset` to `git bisect`. It implements the user-facing option and wires it into both `git bisect start` and `git bisect run`.

The patch adds the `--auto-reset` flag to the command-line synopsis, updates the documentation to explain that the option automatically resets the bisect session after the first bad commit is found, and persists the flag in a new `BISECT_AUTO_RESET` state file. When the bisect completes successfully, the code now checks for the presence of this file and, if found, calls `bisect_reset(NULL, 1)` to return to the original commit quietly. The implementation is careful to avoid leaking the auto-reset state into subsequent bisect sessions: the state file is unlinked during `bisect_clean_state()` and is not re-created unless the flag is explicitly passed again.

Four new tests in `t/t6030-bisect-porcelain.sh` verify that the auto-reset behavior works as expected, that the bisect state is properly cleaned up, and that the flag does not persist across separate bisect sessions. The patch is narrowly scoped to the bisect subsystem and does not introduce new symbols or on-disk format changes. The preparatory work in patches 1 and 2 (refactoring file descriptor handling and adding quiet-checkout support) is now fully leveraged here.
