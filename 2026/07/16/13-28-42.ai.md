This is the first patch in an RFC series introducing `git repack --drop-filtered` for partial clones. It adds the command-line options `--drop-filtered` and `--dry-run` to `builtin/repack.c`, but only implements validation logic—no objects are actually dropped yet.

The patch enforces strict preconditions: `--drop-filtered` requires `--filter` (currently limited to `blob:limit=<n>`), `-a`, and a configured promisor remote. It is incompatible with `--filter-to` and bitmap writing (which is silently disabled). The `--dry-run` flag is mandatory in this version, reflecting the RFC’s early state; the actual deletion logic will follow in later patches.

The implementation is minimal and focused on safety: it rejects unsupported filter types, ensures a promisor remote exists, and disables bitmaps to avoid breaking pack closure. The commit message and code comments make it clear that this is scaffolding for future work, not a complete feature. No test coverage is included here; that appears in patch 7/7.

This patch is well-structured for an RFC: it establishes the CLI contract and validation rules without committing to internal APIs that may change. The safety checks are appropriate for a feature that deletes data, and the limitations (e.g., only `blob:limit` filters) are explicitly called out. The series’ overall goal—reclaiming disk space in partial clones—is a real pain point, and this patch lays the groundwork for addressing it.
