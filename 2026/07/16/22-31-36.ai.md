This is a **contributor housekeeping** discussion about `.mailmap` update etiquette, specifically a reply from Junio C Hamano clarifying the preferred workflow.

Junio responds to D. Ben Knoble’s question about how to handle a future email address change in Git’s `.mailmap` file. Knoble had proposed three options; Junio endorses the simplest: send the `.mailmap` update as a standalone patch (option b) and have it applied directly to `master`. He explains that adding a new entry does not invalidate the old address—it merely links the new one to the same contributor—so there is no need to coordinate the update with the landing of commits bearing the new address. The response is brief, pragmatic, and closes the procedural question without further discussion. No code or technical changes are involved.
