This is a bugfix patch targeting the wrapper subsystem, part of a 5-patch series reintroducing `writev(3p)` support. It addresses a platform compatibility issue on systems like NonStop where `MAX_IO_SIZE` is small enough to cause `writev(3p)` to fail with `EINVAL` when passed large iovec entries.

The patch introduces `xwritev()`, a new wrapper function that mirrors the behavior of the existing `xwrite()` by handling platform-specific limits. It splits overly large iovec requests into chunks that fit within `MAX_IO_SIZE`, restarts syscalls on `EINTR` and `EAGAIN`, and falls back to `xwrite()` if the first iovec entry itself exceeds the limit. The `writev_in_full()` function is updated to use this wrapper, making its retry logic consistent with `write_in_full()`.

The motivation is clear: without this fix, Git fails on platforms with restrictive `MAX_IO_SIZE` values. The commit message explains the edge cases (short writes, zero-length writes, and syscall restarts) and credits Randall Becker for reporting the issue. The implementation is straightforward and follows established patterns in the codebase.

This patch is the third in the series and appears well-motivated and technically sound. It touches `wrapper.c` and `wrapper.h`, introducing a new public function (`xwritev`) and updating an existing one (`writev_in_full`). The change is unlikely to be controversial, as it aligns with existing error-handling conventions.
