This is the final patch in a 4-patch v6 series refactoring `has_symlinks` configuration as part of the `the_repository` removal effort. It migrates the global `has_symlinks` flag into `struct repo_config_values`, introduces a new getter function `repo_has_symlinks()`, and updates all call sites to use repository-scoped access. The patch also implements Junio C Hamano’s requested design change for the mingw compatibility layer, replacing the previously contested global fallback variable with a compile-time macro (`platform_has_symlinks()`) and a platform-specific function (`mingw_platform_has_symlinks()`).

The patch touches nine files, primarily `environment.c` (where the global is removed and the getter is defined), `compat/mingw.c` (where the new platform-specific logic is implemented), and various callers (`apply.c`, `combine-diff.c`, `entry.c`, `read-cache.c`) that now use `repo_has_symlinks()` with a fallback to `the_repository`. The mingw adjustments ensure that platform-specific overrides (e.g., detecting native symlink support via the `MSYS` environment variable) remain functional before repository initialization, while eliminating mutable global state.

This iteration resolves the last substantive review concern from v5, adopting Junio’s proposed design in full. The migration pattern—moving a global configuration flag into `repo_config_values` with a repository-scoped getter—aligns with the established approach from earlier patches in the series (e.g., `trust_executable_bit` in patch 3/4) and may serve as a template for future configuration refactoring. The mingw changes are now consistent with Git’s existing platform-compatibility conventions (e.g., `is_dir_sep()`).

The patch is uncontroversial in its current form, with no behavioral changes and thorough repository pointer validation in the new getter. The mingw adjustments could attract attention from platform maintainers (e.g., Johannes Schindelin), but the design is now settled. This patch, along with the rest of the series, appears ready for final review and likely inclusion in `next`.
