Key technical details:
- Files touched: `builtin/repo.c` (implementation), `Documentation/git-repo.adoc` (documentation), `t/t1900-repo-info.sh` (tests).
- New symbols: Twenty-one new keys with suffix-based formatting support: `path.toplevel.absolute`, `path.toplevel.relative`, `path.superproject-root.absolute`, `path.superproject-root.relative`, `path.hooks.absolute`, `path.hooks.relative`, `path.index.absolute`, `path.index.relative`, `path.grafts.absolute`, `path.grafts.relative`, `path.git-prefix`, and `path.cdup`. The `path.git-prefix` key returns the relative path from the top-level working tree to the current directory (e.g., `sub/dir/` in a subdirectory, empty string at the root), including a trailing slash. The `path.cdup` key returns the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root).
- Implementation details:
  - Patch 1/7 (v5): `path.toplevel.absolute` and `path.toplevel.relative` use `repo_get_work_tree()` and `format_path()`. In bare repositories, both keys return an empty string.
  - Patch 2/7 (v5): `path.superproject-root.absolute` and `path.superproject-root.relative` use `get_superproject_working_tree()` and `format_path()`. Returns an empty string when not inside a submodule.
  - Patch 3/7 (v5): `path.hooks.absolute` and `path.hooks.relative` use `repo_git_path_replace()` and `format_path()`, respecting `core.hooksPath` and documenting `/dev/null` handling.
  - Patch 4/7 (v5): `path.index.absolute` and `path.index.relative` use `repo_get_index_file()` and `format_path()`, respecting `GIT_INDEX_FILE`.
  - Patch 5/7 (v5): `path.grafts.absolute` and `path.grafts.relative` use `repo_get_graft_file()` and `format_path()`, respecting `GIT_GRAFT_FILE`.
  - Patch 6/7 (v5): `path.git-prefix` uses the repository’s `prefix` field and `format_path()`. Returns the relative path from the top-level working tree to the current directory (e.g., `sub/dir/` in a subdirectory, empty string at the root).
  - Patch 7/7 (v5): `path.cdup` uses a new `get_path_cdup()` function, returning the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root). The implementation counts slashes in the repository’s `prefix` field to generate `../` sequences.
- Behavior: Keys return filesystem paths (absolute or relative) for repository components. In bare repositories or when not inside a submodule, the respective keys return an empty string, except for `path.index`, `path.grafts`, and `path.hooks`, which return paths unconditionally (even when the file or directory does not exist or the repository is bare), aligning with `git rev-parse --git-path` precedent. The `path.hooks` keys explicitly document that they return `/dev/null` verbatim when `core.hooksPath` is set to that value. The test suite includes coverage for `/dev/null` handling, bare-repository edge cases, and the new `path.cdup` and `path.git-prefix` behaviors.
