Originating author: K Jayatheerth (GSoC contributor). Thread type: feature patch series. Current version: 5 (feature-complete, mechanically clean, ready for final technical review).

Core problem or goal: Expose filesystem locations of repository components (e.g., hooks directory, index file, grafts file, superproject root, and the relative path from the top-level working tree to the current directory *and its inverse*) in a user-facing, scriptable format via `git repo info`. The new keys mirror existing internal Git struct fields but avoid requiring direct access to Git’s internals. Each key supports suffix-based formatting (e.g., absolute vs. relative paths). The series includes `path.cdup` (the inverse of `path.git-prefix`) to complete the relative-path key set, as requested by Junio C Hamano and to address prior design objections.

**New in v5 (patches 6/7 and 7/7)**:
- Patch 6/7: Implements `path.git-prefix` using the repository’s `prefix` field and `format_path()`. The key returns the relative path from the top-level working tree to the current directory (e.g., `sub/dir/` in a subdirectory, empty string at the root), matching `git rev-parse --show-prefix` behavior. The implementation reuses existing Git setup code and includes tests for the root and subdirectory cases.
- Patch 7/7: Implements `path.cdup` using a new `get_path_cdup()` function, returning the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root). The implementation counts slashes in the repository’s `prefix` field to generate the correct number of `../` sequences. The patch resolves the last open design question by providing a direct counterpart to `path.git-prefix`, solidifying the series’ design.

  - Patch 7/7 (v5): `path.cdup` uses a new `get_path_cdup()` function, returning the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root). - Behavior: Keys return filesystem paths (absolute or relative) for repository components, matching internal Git struct fields. In bare repositories or when not inside a submodule, the respective keys return an empty string, except for `path.index`, `path.grafts`, and `path.hooks`, which return paths unconditionally (even when the file or directory does not exist or the repository is bare), aligning with `git rev-parse --git-path` precedent. The `path.index`, `path.grafts`, and `path.hooks` keys respect the `GIT_INDEX_FILE`, `GIT_GRAFT_FILE`, and `core.hooksPath` environment/config overrides, respectively. The `path.git-prefix` key returns the relative path from the top-level working tree to the current directory, including a trailing slash (empty string at the root). The `path.cdup` key returns the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root). The `path.hooks` keys explicitly document that they return `/dev/null` verbatim when `core.hooksPath` is set to that value. The test suite includes coverage for `/dev/null` handling (non-Windows platforms only), absolute path resolution without prepending the repository root, bare-repository edge cases for `path.index` and `path.grafts`, and the new `path.cdup` and `path.git-prefix` behaviors at the repository root and in subdirectories.
