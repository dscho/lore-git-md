Originating author: K Jayatheerth (GSoC contributor). Thread type: feature patch series. Current version: 4 (mechanically clean, ready for substantive technical review).

Core problem or goal: Expose filesystem locations of repository components (e.g., hooks directory, index file, grafts file, superproject root, and the relative path from the top-level working tree to the current directory) in a user-facing, scriptable format via `git repo info`. The new keys mirror existing internal Git struct fields but avoid requiring direct access to Git’s internals. Each key supports suffix-based formatting (e.g., absolute vs. relative paths) where applicable. The `path.objects` key was dropped in v4 due to concerns about its long-term viability in light of pluggable ODB backends.

Current status: Fourth submission (version 4) is mechanically clean and addresses all feedback from v3: rebased onto `master` to resolve the forward-compatibility issue with `startup_info->prefix` (now using `repo->prefix`), removed redundant `strbuf_addstr(buf, "")` calls, added missing test coverage for relative paths in bare repositories, renamed `path.superproject-working-tree` to `path.superproject-root` for clarity, and dropped the `path.objects` key entirely. The series also adds a test case for `/dev/null` handling in `path.hooks` (guarded for non-Windows platforms) and refines commit messages to avoid overly specific phrasing. - Behavior: Keys return filesystem paths (absolute or relative) for repository components, matching internal Git struct fields. In bare repositories or when not inside a submodule, the respective keys return an empty string, except for `path.index`, `path.grafts`, and `path.hooks`, which return paths unconditionally (even when the file or directory does not exist or the repository is bare), aligning with `git rev-parse --git-path` precedent. The `path.index`, `path.grafts`, and `path.hooks` keys respect the `GIT_INDEX_FILE`, `GIT_GRAFT_FILE`, and `core.hooksPath` environment/config overrides, respectively. The `path.git-prefix` key returns the relative path from the top-level working tree to the current directory, including a trailing slash (empty string at the root). The `path.hooks` keys explicitly document that they return `/dev/null` verbatim when `core.hooksPath` is set to that value, matching `git rev-parse --git-path hooks` behavior. The test suite now includes coverage for `/dev/null` handling (non-Windows platforms only), absolute path resolution without prepending the repository root, and bare-repository edge cases for `path.index` and `path.grafts`.
