This is the second patch in a three-part **feature** series adding a `--auto-reset` option to `git bisect`. The patch itself is a **refactoring** that prepares the `bisect_reset()` function to optionally perform a quiet checkout, suppressing progress and branch-status output.

The change adds a `quiet` parameter to `bisect_reset()` and passes `--quiet` to the underlying `git checkout` command when the flag is set. No callers enable the flag yet, so the patch is purely preparatory and does not alter existing behavior. The modification is confined to `builtin/bisect.c` and is straightforward: the checkout command’s argument list is restructured to conditionally include `--quiet`, and all existing callers pass `0` (false) for the new parameter.

This patch is clearly motivated by the upcoming `--auto-reset` feature (introduced in patch 3), which will use the quiet checkout to avoid cluttering output in automated workflows. The implementation is clean and backward-compatible, and the change is small enough that it is unlikely to introduce regressions. Reviewers may check that the argument order in the `strvec_pushl()` calls remains correct, but the patch looks technically sound. No test coverage is added here, which is appropriate since the behavior change is deferred to the next patch.
