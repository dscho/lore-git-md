This is the final patch in a four-part refactoring series (v6) that migrates the `has_symlinks` configuration flag into repository-scoped storage as part of the ongoing `the_repository` removal effort. The patch completes the work begun in the now-merged v4 by moving `has_symlinks` into `struct repo_config_values` and introducing a new getter function, `repo_has_symlinks()`, to access it.

The key technical change here is the elimination of the global `has_symlinks` variable in favor of repository-specific storage, with a fallback to a platform-specific macro (`platform_has_symlinks()`) for early initialization (e.g., MinGW). The patch adopts Junio C Hamano’s proposed design from v5, replacing the previously contested global fallback variable with a compile-time macro and a platform-specific function (`mingw_platform_has_symlinks()`). This aligns with Git’s existing platform-compatibility patterns (e.g., `is_dir_sep()`) and removes mutable global state while preserving the ability to detect native symlink support via environment variables.

The patch updates all call sites in `apply.c`, `combine-diff.c`, `entry.c`, and `read-cache.c` to use the new getter, with explicit fallbacks to `the_repository` where no repository pointer is available. The mingw compatibility layer is adjusted to use the new macro/function pattern, and the `setup_windows_environment()` function now relies on `mingw_platform_has_symlinks()` instead of writing to a global. The patch also initializes `repo_config_values->has_symlinks` with the platform-specific default during repository setup.

This iteration appears ready for final review, as it addresses the last substantive concern from v5 (the mingw compatibility design). The migration is mechanical and preserves existing behavior, though the author notes that `repo_config_values()` still does not support non-`the_repository` instances due to deep integration of these flags. The patch is uncontroversial in its current form and likely to proceed to `next` once review concludes. Platform maintainers (e.g., Johannes Schindelin) may weigh in on the mingw adjustments, but the design now follows established Git conventions.
