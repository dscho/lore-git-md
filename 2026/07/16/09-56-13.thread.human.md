This thread is about a small but important refactoring patch from Patrick Steinhardt, part of the ongoing effort to remove Git’s global `the_repository` variable. The patch updates two utility functions in `copy.c`—`copy_file()` and `copy_file_with_time()`—to accept an explicit `struct repository *` parameter instead of relying on the global variable. This touches ten call sites across various subsystems, including a correctness fix in `sequencer.c` where Phillip Wood spotted a latent bug: mixing `the_repository` with a local repository instance could lead to inconsistent path or permission handling.

The patch is now in its second version, which addresses Phillip’s feedback by ensuring all call sites in `sequencer.c` use the local repository context consistently. Phillip has since reviewed and approved v2, calling it technically sound and ready for integration. There are no open questions or objections; this is a mechanical, uncontroversial change with no intended behavior impact. The patch is part of the broader `the_repository` removal effort, which has been underway for months and touches nearly every part of Git’s codebase. While the change itself is small, it’s a necessary step toward making repository-dependent operations explicit and safer.
