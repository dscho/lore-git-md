This is a bugfix patch targeting the revision-walking subsystem. Kristofer Karlsson identifies and fixes a regression introduced in commit `dd4bc01c0a` (May 2026) where `git rev-list --no-walk <commit> -- <path>` incorrectly ignores path arguments and outputs all commits regardless of whether they touch the specified paths.

The regression occurs because the new `REV_WALK_NO_WALK` enum case skips `process_parents()`, which normally calls `try_to_simplify_commit()` to evaluate path filtering. The fix adds a direct call to `try_to_simplify_commit()` for the `REV_WALK_NO_WALK` case, mirroring the existing `REV_WALK_REFLOG` behavior. The patch includes three new tests in `t6017-rev-list-stdin.sh` to verify the fix: one defensive test (passes without the fix) and two that fail without it.

The commit message is clear and well-motivated, citing a real-world example from the Linux kernel repository where the bug caused 2026 unfiltered commits instead of the expected 146. The fix itself is minimal (one line moved) and appears correct. This is a straightforward regression fix with test coverage, making it a strong candidate for merging.
