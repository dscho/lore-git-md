This is the first patch in a two-part bugfix series for the `wincred` credential helper on Windows. It addresses a memory corruption issue that occurs when Git attempts to erase a stored credential using `git credential reject`. The bug, which was partially fixed in an earlier commit for a different code path, causes the helper to overrun a buffer by one WCHAR when copying a credential's password for comparison, leading to silent process termination and leaving the credential stored despite the user's intent to erase it.

The fix is straightforward: the code now correctly calculates the required buffer size in WCHAR units (including space for the terminating NUL) and passes the destination capacity in WCHAR elements rather than bytes, aligning with the `wcsncpy_s` API requirements. The change is minimal—just four lines modified in `contrib/credential/wincred/git-credential-wincred.c`—and is clearly motivated by a real-world issue that was already fixed in Git for Windows.

This is a well-targeted bugfix with no cross-platform impact, and the commit message provides enough context to understand both the symptom and the root cause. The patch looks technically sound and uncontroversial, though as with all `contrib/` code, it lacks test coverage. The series as a whole is a routine backport of fixes that have already been validated downstream.
