This thread is a two-patch series from Johannes Schindelin (Dscho) to backport critical bugfixes from Git for Windows to upstream Git’s `wincred` credential helper. The fixes address two Windows-specific issues: (1) memory corruption during credential erasure (patch 1/2), and (2) silent loss of OAuth tokens during storage (patch 2/2, just summarized). Both bugs were discovered and fixed in Git for Windows v2.55.0(3) and are now being upstreamed.

The technical details are straightforward: the root cause in both patches is a miscalculation in buffer allocation and string-handling functions, where byte counts were treated as WCHAR counts, leading to one-WCHAR overruns and process crashes (status `0xC0000374`). The fixes are minimal—adjusting allocations and buffer sizes—and are confined to `contrib/credential/wincred/git-credential-wincred.c`. There are no new symbols, CLI options, or on-disk format changes, and the changes are Windows-only with no cross-platform impact. As is typical for `contrib/` code, no test coverage is included.

The series is under initial review and appears uncontroversial. No feedback has been received yet, but the patches are well-motivated, with clear commit messages referencing prior fixes and a GitHub advisory. The backport completes the upstreaming of these critical fixes from Git for Windows.
