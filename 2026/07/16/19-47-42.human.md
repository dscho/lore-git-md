This is a **bug report and feature request** about `git submodule` behavior with sparse-checkout.

Brad Larson describes what he sees as a design flaw: when you use `git sparse-checkout` to limit your working tree to a subset of files, `git submodule update --init` still initializes and checks out *all* submodules, not just those inside the sparse-checkout cone. He demonstrates this with a Rust repository, where only `src/doc` is checked out but submodules in `library/` and `src/tools/` are still cloned. He asks whether the project would accept a patch to make `git submodule` respect the sparse-checkout configuration.

The report is clear and includes reproduction steps, Git version, and a concrete example. It does not include a proposed implementation or patch, so this is currently a discussion starter rather than a code contribution. The behavior Brad describes is likely to resonate with users working in large monorepos with many submodules, where sparse-checkout is meant to reduce both disk usage and network traffic. Whether the maintainers will consider this a bug or a deliberate design choice remains to be seen.
