This is the first patch in the v6 series introducing configurable submodule fetch errors. It fixes a long-standing logic flaw in Git’s submodule fetch error handling where phase-1 (ref-based) fetch failures were recorded immediately, even when a subsequent phase-2 (OID-based) retry could still succeed. The patch restructures `fetch_finish()` to defer error recording until all retry attempts are exhausted, ensuring the overall fetch result accurately reflects whether the required commits were ultimately obtained.

The core change extracts error recording into a new helper, `record_fetch_error()`, which is now used consistently across `fetch_start_failure()`, `get_fetch_task_from_index()`, and the deferred logic in `fetch_finish()`. This ensures all submodule fetch errors—whether from transport failures, missing refs, or unreachable commits—are routed through the same path, fixing the premature failure case while preserving error reporting for genuine problems (e.g., transport errors when all commits are already present locally).

The patch touches only `submodule.c` and adds a new test in `t/t5526-fetch-submodules.sh` that verifies a failed submodule fetch is still reported even when the gitlinked commits exist locally. The test sets up an isolated environment with a superproject and submodule, creates an unreachable commit in the submodule, and breaks the submodule’s remote to force a fetch failure. The test confirms the error is surfaced in the final summary, addressing the NEEDSWORK comment added in bd5e567dc7.

This is a refactoring patch that paves the way for the configurable error policy in Patch 2/2. The changes are narrowly scoped to the submodule fetch error-handling path, and the commit message clearly explains the edge cases (e.g., unconditional fetches, locally present commits) and why deferring error recording is correct. The test coverage is thorough and portable, using `test_grep` instead of raw `grep` as previously requested by Ramsay Jones.

It does not introduce new user-facing behavior but is necessary for the configurable policy in the next patch to work correctly.
