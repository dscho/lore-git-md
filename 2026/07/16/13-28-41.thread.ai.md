Thread identity
Subject: [RFC PATCH 0/N] repack: introduce --drop-filtered for partial clones
Series version: RFC v1 (patches 1/7–7/7 complete, v2 planned)
Originating author: Siddharth Shrimali (first-time contributor)
Thread type: RFC patch series

Core problem or goal
Extend `git repack` with a `--drop-filtered` option that safely reclaims disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold (e.g., `--filter=blob:limit=10M`). The feature must guarantee safety by (1) only targeting objects marked as promisor (ensuring they are recoverable from the promisor remote), (2) avoiding locally created objects, and (3) introducing a drop log (`$GIT_DIR/objects/info/promisor-dropped`) to record removed objects for improved error messages during future lazy-fetch failures.

Current status
RFC v1 is now complete (7/7 patches posted). Patch 7/7 implements the drop log (`$GIT_DIR/objects/info/promisor-dropped`) that records every object removed by `--drop-filtered` in the format `<oid> <timestamp> <tz> filter=<spec> remote=<name>`. The remote field currently lists all configured promisor remotes rather than the specific one each object is recoverable from (marked NEEDSWORK pending the `remote-object-info` protocol command). The log is written only on real runs, not dry runs, and is created with `safe_create_leading_directories()`. Error handling is minimal (warnings on I/O failures). The patch wires the log writing into `builtin/repack.c` after the repack completes via `append_drop_log()` in `repack-promisor.c`. **Maintainer feedback on patch 1/7 identifies a blocking logical flaw**: the `--drop-filtered` vs `--write-bitmap-index` (`-b`) validation occurs too late in the control flow—after `write_bitmaps` may have been set by repository configuration—so it cannot distinguish between user-requested bitmaps (which should be rejected) and config-driven bitmaps (which should be silently disabled). The author has acknowledged the flaw and plans to restructure the validation in v2 to explicitly track whether `--write-bitmap-index` was set on the command line (erroring out if so) versus via configuration (silently disabling it). Safety guards (merge/rebase checks, index validation) and remote verification logic remain deferred to follow-ups, but the core functionality promised in the RFC is now implemented. No integration branch assignment yet; implementation remains in flux with expected API reorganization in v2.

Key technical details
- **New CLI options**: `git repack --drop-filtered` (supports real runs) and `--dry-run` (no longer mandatory)
- **New files**: `repack-filtered.c` (core logic), `t/t7706-repack-drop-filtered.sh` (test script)
- **Modified files**: `builtin/repack.c` (option parsing, validation, conditional bypass of `write_filtered_pack()`, drop log wiring), `list-objects-filter.{c,h}` (new `list_objects_filter__filter_oidset()` API), `repack-promisor.c` (promisor pack rebuilding with object exclusion via `to_drop` parameter, `append_drop_log()`), `repack.h` (function signature changes)
- **New data structures**: drop log (`$GIT_DIR/objects/info/promisor-dropped`) recording removed OIDs with timestamp, filter spec, and promisor remote(s); `collect_cb_data` struct; `all_promisor_blobs` and `to_drop` oidsets
- **New helper functions**: `list_objects_filter__filter_oidset()` (applies filter to an existing oidset without object traversal), `enumerate_promisor_blobs()` (walks promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, returns drop set via output parameter), `append_drop_log()` (formats and appends drop entries to the log file)
- **Behavior**: `--drop-filtered` + `--filter=<spec>` (currently limited to `blob:limit=<n>`) removes promisor blobs exceeding the threshold; locally created objects are untouched. Bitmaps are silently disabled to avoid breaking pack closure. The `to_drop` set’s contents are passed to `repack_promisor_objects()` to rebuild promisor packs while excluding the dropped blobs, implying `-d` to remove old promisor packs containing the dropped objects. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. Test coverage validates CLI preconditions (e.g., `--filter` and `-a` are required, `--filter-to` is rejected, promisor remote must be configured), promisor blob filtering (only blobs exceeding the threshold are listed as drop candidates), dry-run safety (no objects are removed), and actual object removal (preserving smaller blobs).
- **Safety**: objects are only enumerated if marked as promisor (via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`); lazy fetches are avoided during enumeration by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query. Preconditions enforced: `--filter` must be `blob:limit`, `-a` is required, a promisor remote must be configured, and `--filter-to` is rejected. **The bitmap validation flaw (lines 245–247 in `builtin/repack.c`) renders the safety mechanism ineffective**: the check for `--drop-filtered` vs `--write-bitmap-index` occurs after `write_bitmaps` may have been set by config, so it cannot distinguish between user-requested and config-driven bitmaps. The drop log enables future error-message improvements but does not yet validate that dropped objects are not referenced by the index or that the promisor remote still has them (deferred to follow-ups).

Open questions and loose ends
1. **Safety guards**: v2 will add checks to prevent drops during merges, rebases, or when blobs are referenced by the current index.
2. **Remote verification**: the drop log currently records all configured promisor remotes rather than the specific one each object is recoverable from; this depends on the `remote-object-info` protocol command (not yet implemented).
3. **Function signature churn**: internal APIs (`list_objects_filter__filter_oidset()`, `repack_promisor_objects()`, `enumerate_promisor_blobs()`) and test placement will be reorganized in v2. The helper’s current implementation duplicates `blob:limit` logic, flagged for refactoring.
4. **Client-side remote object availability**: no way to query whether a promisor remote still has an object; this is a known limitation.
5. **Merge status**: no maintainer decision yet; integration branch unknown.
6. **Filter scope**: currently limited to `blob:limit`; future extensions may include other filter types (e.g., `tree:0`).
7. **Bitmap validation**: the blocking flaw in patch 1/7 must be fixed before the series can proceed.
8. **CLI design**: the author has reaffirmed the separation of `--drop-filtered` and `--dry-run` after considering an alternative syntax (`--drop-filtered[=dry-run]`), but remains open to revisiting the design based on broader feedback. The rationale for the two-option design will be documented in the commit message for v2.
