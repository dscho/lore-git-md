Subject: [PATCH v3 0/N] repack: introduce --drop-filtered for partial clones

Core problem or goal
Extend `git repack` with a `--drop-filtered` option that safely reclaims disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold (e.g., `--filter=blob:limit=10M`). The feature guarantees safety by (1) only targeting objects marked as promisor (ensuring they are recoverable from the promisor remote), (2) avoiding locally created objects, and (3) introducing UX optimizations (merge/rebase/cherry-pick checks and index validation) to prevent immediate re-fetching. Junio previously proposed an alternative, time-based heuristic to reduce redundant network operations, but this and two other items—remote verification (via the pending `remote-object-info` protocol command) and the drop log (with error-path improvements)—are now explicitly deferred to follow-up work, not blocking requirements for this series. The author has reframed the safety guards as optional optimizations rather than correctness measures, since lazy-fetching would transparently restore dropped objects.

Current status
v4 was complete (7/7 patches posted) and production-ready, incorporating Junio’s three mechanical fixes from v3 (SYNOPSIS mismatch, usage string newline, test script style). However, Junio’s latest review identified a **blocking type-mismatch bug** in patch 2/7 (`list_objects_filter__filter_oidset()`): the code passes the address of an `unsigned long` variable to `struct object_info.sizep`, which expects `size_t *`. While this works on most platforms, it violates strict aliasing rules and could cause silent data corruption or crashes on platforms where `size_t` and `unsigned long` differ (e.g., Windows 64-bit). **The author has acknowledged the bug and confirmed the fix (changing `unsigned long` to `size_t`) for v5.** The series remains blocked until v5 is posted. **Integration branch remains unknown; no maintainer decision yet.** The series is otherwise feature-complete for its stated scope, with all deferred items (remote verification, recency-based culling, drop log) confirmed as follow-up work. Christian Couder’s documentation reorganization feedback (squashing most of the `--drop-filtered` description into patch 5/7 and moving only the safety guards paragraph to patch 6/7) has been noted but not yet implemented; the author has not responded to this suggestion.

Key technical details
- **New CLI options**: `git repack --drop-filtered` (real runs) and `--dry-run` (reporting only), documented in `Documentation/git-repack.adoc` with constraints (e.g., `blob:limit` only, `-a` required, promisor remote required), incompatibilities (e.g., `--filter-to`, bitmaps), and safety optimizations (merge/rebase/cherry-pick checks, index validation). The documentation explains the implied `-d`, the rationale for silent bitmap disabling, and the `--dry-run` preview functionality.
- **New files**: `repack-filtered.c` (core logic, including `enumerate_promisor_blobs()`), `t/t7706-repack-drop-filtered.sh` (test script, now with `test_grep` fixes).
- **Modified files**: `builtin/repack.c` (option parsing, validation, conditional bypass of `write_filtered_pack()`, drop log wiring, real object removal via `repack_promisor_objects()` with `to_drop`, and safety guards via `wt_status_get_state()` and `repo_read_index()`), `list-objects-filter.{c,h}` (new `list_objects_filter__filter_oidset()` API), `repack-promisor.c` (promisor pack rebuilding with object exclusion via `to_drop` parameter, `append_drop_log()`), `repack.h` (function signature changes), `Documentation/git-repack.adoc` (man page updates for `--drop-filtered` and `--dry-run`).
- **New data structures**: `all_promisor_blobs` and `to_drop` oidsets; drop log (deferred) recording removed OIDs with timestamp, filter spec, and promisor remote(s).
- **New helper functions**: `list_objects_filter__filter_oidset()` (applies filter to an existing oidset without object traversal, avoids lazy fetches via `OBJECT_INFO_SKIP_FETCH_OBJECT`), `enumerate_promisor_blobs()` (walks promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, returns drop set via output parameter `oidset *to_drop`).
- **Behavior**: `--drop-filtered` + `--filter=<spec>` (currently limited to `blob:limit=<n>`) removes promisor blobs exceeding the threshold; locally created objects are untouched. Bitmaps are silently disabled to avoid breaking pack closure. The `to_drop` set’s contents are passed to `repack_promisor_objects()` to rebuild promisor packs while excluding the dropped blobs, implying `-d` to remove old promisor packs containing the dropped objects. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. **Safety optimizations**: (1) merge/rebase/cherry-pick checks (via `wt_status_get_state()`) prevent drops during ongoing operations, (2) index validation (via `repo_read_index()`) prevents drops of blobs referenced by the current index. Both checks are skipped for bare repositories. Error messages are specific: "Refuse to drop objects while another operation is in progress" and "Bare repository: cannot drop '<path>' (<oid>): it is referenced by the current index". The current implementation performs two separate promisor-object walks (one for enumeration, one for repacking), but this could be optimized in the future.
- **Preconditions enforced**: `--filter` must be `blob:limit`, `-a` is required, a promisor remote must be configured, and `--filter-to` is rejected. Objects are only enumerated if marked as promisor (via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`); lazy fetches are avoided during enumeration by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query.
- **Bitmap validation fix**: Patch 1/7 fixes a subtle validation bug where explicit `-b` usage was incorrectly allowed when `repack.writeBitmaps` was set in the config. The updated patch now correctly rejects explicit `-b` with `--drop-filtered`, while silently disabling config-driven bitmaps for the duration of the command.
- **Blocking bug in Patch 2/7**: `list_objects_filter__filter_oidset()` passes the address of an `unsigned long` variable (`size`) to `struct object_info.sizep`, which expects `size_t *`. This violates strict aliasing rules and could cause silent data corruption or crashes on platforms where `size_t` and `unsigned long` differ (e.g., Windows 64-bit). **The fix is to change `size` to `size_t` and has been confirmed by the author for v5.**

Open questions and loose ends
1. **Merge status**: No maintainer decision yet; integration branch remains unknown. The author must post v5 with the type-mismatch fix before the series can proceed.
2. **Reliability of `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`**: Junio seeks confirmation that promisor-object enumeration is robust in practice. Siddharth Shrimali and Siddharth Asthana trust the mechanism, but real-world validation from other partial-clone users would be valuable.
3. **Repack machinery behavior**: Junio confirms the rebuilt promisor pack must be constructed from locally available data only, without triggering lazy fetches. The current implementation performs two separate promisor-object walks (one for enumeration, one for repacking), but this could be optimized in the future.
4. **Filter scope**: Currently limited to `blob:limit`; future extensions may include other filter types (e.g., `tree:0`), object age, path, or reachability.
5. **Code duplication**: `list_objects_filter__filter_oidset()` duplicates the `blob:limit` size check logic from `list_objects_filter__filter_object()`. This is flagged with a `NEEDSWORK` comment and noted as technical debt.
6. **Timestamp granularity**: Promisor objects are always stored in packs (never loose), so per-object timestamps are not natively available. The current best proxy is the mtime of the promisor pack itself, which loses granularity after repacking consolidates multiple packs. A mechanism similar to cruft pack `.mtimes` files would be necessary for the time-based heuristic (deferred to follow-up).
7. **Implied `-d`**: The `--drop-filtered` option implies `-d` to remove old promisor packs containing dropped blobs. This is documented in the code comment in `builtin/repack.c` but could be made explicit in the user-facing documentation if reviewers prefer.
8. **Follow-up work confirmed**: The three deferred items—remote verification (via the pending `remote-object-info` protocol command), recency-based culling (time-based heuristic), and the drop log (with error-path improvements)—are now explicitly follow-up work, not blocking requirements for this series.
9. **Christian Couder’s feedback on Patch 2/7**: Suggests making the `opts` parameter in `list_objects_filter__filter_oidset()` `const` to improve code hygiene. This is a mechanical improvement that does not affect functionality and is easy to incorporate.
10. **Christian Couder’s feedback on Patch 4/7**: Surface-level review addressing code comment formatting and punctuation in `enumerate_promisor_blobs()` and the test script. Suggested changes include adding missing full stops, fixing inconsistent capitalization, and standardizing comment block style. These are mechanical improvements with no impact on program behavior or logic.
11. **Christian Couder’s documentation reorganization feedback**: Proposes squashing most of the `--drop-filtered` description into patch 5/7 and moving only the safety guards paragraph to patch 6/7. The author has not yet responded to this suggestion.
12. **Error message improvement**: The author has proposed improving the error message in patch 6/7 (for ongoing operations) as a follow-up to declining the `die_if_some_operation_in_progress()` refactoring.
