Thread identity
Subject: [RFC PATCH 0/N] repack: introduce --drop-filtered for partial clones
Series version: RFC v2 (patches 1/7–7/7, now complete)
Originating author: Siddharth Shrimali (first-time contributor)
Thread type: RFC patch series

Core problem or goal
Extend `git repack` with a `--drop-filtered` option that safely reclaims disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold (e.g., `--filter=blob:limit=10M`). The feature must guarantee safety by (1) only targeting objects marked as promisor (ensuring they are recoverable from the promisor remote), (2) avoiding locally created objects, and (3) introducing safety guards to prevent drops during merges, rebases, or cherry-picks, and to avoid dropping blobs referenced by the current index. Junio has proposed an alternative, time-based heuristic to reduce redundant network operations: avoid culling recently fetched objects (e.g., those downloaded within the last 20 minutes) instead of relying on the current merge/rebase/cherry-pick checks and index validation. Siddharth Shrimali now endorses this heuristic as a natural extension of the existing "enumerate-then-filter" framework, noting that promisor objects are always stored in packs (never loose), so per-object timestamps would require extending the promisor object log or introducing a separate timestamp file (precedent: cruft pack `.mtimes` files). The current safety guards (merge/rebase/cherry-pick checks and index validation) are now acknowledged as **optional optimizations** rather than correctness measures, since lazy-fetching would transparently restore dropped objects.

Current status
RFC v2 is now complete (7/7 patches posted, including the documentation patch). The series addresses all blocking issues from v1: (1) the `--drop-filtered` vs `--write-bitmap-index` validation flaw is fixed by restructuring the validation to distinguish command-line vs configuration-driven bitmap settings; (2) **critical safety guards (merge/rebase/cherry-pick checks and index validation) are fully implemented (patch 6/7)**, though their necessity is now contested—Junio proposes replacing them with a time-based heuristic, and Siddharth Shrimali agrees this is feasible and preferable; (3) the core enumeration logic (`enumerate_promisor_blobs()`) is in place (patch 4/7), identifying promisor blobs exceeding the threshold via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` and `OBJECT_INFO_SKIP_FETCH_OBJECT`; (4) real object removal is implemented (patch 5/7), wiring the `drop_oids` set into `repack_promisor_objects()` to rebuild promisor packs while excluding dropped blobs, and setting `delete_redundant = 1` to remove old promisor packs containing the dropped objects, **implying `-d`** and ensuring disk space is reclaimed. The **documentation patch (7/7)** completes the series by adding user-facing descriptions of `--drop-filtered` and `--dry-run`, their constraints, safety mechanisms, and behavior (e.g., implied `-d`, incompatibility with `--filter-to`, and silent bitmap disabling). The drop log (`$GIT_DIR/objects/info/promisor-dropped`) and remote verification remain deferred to follow-ups, but the core functionality and documentation are finalized. Integration branch remains unknown; no maintainer decision yet. The time-based heuristic would require extending the filter logic to incorporate object fetch timestamps, likely via a new metadata field in the promisor object log or a separate timestamp file (analogous to cruft pack `.mtimes`). **Siddharth Asthana’s latest review endorses the promisor-object enumeration mechanism and safety guards, while suggesting softer language in documentation about "guaranteed recoverability" to acknowledge remote availability risks.**

Key technical details
- **New CLI options**: `git repack --drop-filtered` (real runs) and `--dry-run` (reporting only), documented in `Documentation/git-repack.adoc` with constraints (e.g., `blob:limit` only, `-a` required, promisor remote required), incompatibilities (e.g., `--filter-to`, bitmaps), and safety guarantees (merge/rebase/cherry-pick checks, index validation). The documentation explains the implied `-d`, the rationale for silent bitmap disabling, and the `--dry-run` preview functionality. Junio’s time-based heuristic would require extending the filter logic to incorporate object fetch timestamps, tracked via a new metadata field in the promisor object log or a separate timestamp file (precedent: cruft pack `.mtimes` files).
- **New files**: `repack-filtered.c` (core logic, including `enumerate_promisor_blobs()`), `t/t7706-repack-drop-filtered.sh` (test script).
- **Modified files**: `builtin/repack.c` (option parsing, validation, conditional bypass of `write_filtered_pack()`, drop log wiring, real object removal via `repack_promisor_objects()` with `drop_oids`, and **safety guards via `wt_status_get_state()` and `repo_read_index()`**), `list-objects-filter.{c,h}` (new `list_objects_filter__filter_oidset()` API), `repack-promisor.c` (promisor pack rebuilding with object exclusion via `to_drop` parameter, `append_drop_log()`), `repack.h` (function signature changes), `Documentation/git-repack.adoc` (man page updates for `--drop-filtered` and `--dry-run`).
- **New data structures**: `all_promisor_blobs` and `to_drop` oidsets; drop log (deferred) recording removed OIDs with timestamp, filter spec, and promisor remote(s). Junio’s proposal would require additional metadata to track object fetch timestamps, likely via a new metadata field in the promisor object log or a separate timestamp file (precedent: cruft pack `.mtimes` files).
- **New helper functions**: `list_objects_filter__filter_oidset()` (applies filter to an existing oidset without object traversal, avoids lazy fetches via `OBJECT_INFO_SKIP_FETCH_OBJECT`), `enumerate_promisor_blobs()` (walks promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, returns drop set via output parameter `oidset *to_drop`).
- **Behavior**: `--drop-filtered` + `--filter=<spec>` (currently limited to `blob:limit=<n>`) removes promisor blobs exceeding the threshold; locally created objects are untouched. Bitmaps are silently disabled to avoid breaking pack closure. The `to_drop` set’s contents are passed to `repack_promisor_objects()` to rebuild promisor packs while excluding the dropped blobs, **implying `-d`** to remove old promisor packs containing the dropped objects. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. **Safety guards**: (1) **merge/rebase/cherry-pick checks** (via `wt_status_get_state()`) prevent drops during ongoing operations, (2) **index validation** (via `repo_read_index()`) prevents drops of blobs referenced by the current index. Both checks are skipped for bare repositories. Junio’s time-based heuristic would replace these guards by avoiding culls of recently fetched objects (e.g., within the last 20 minutes). The current implementation performs two separate promisor-object walks (one for enumeration, one for repacking), but this could be optimized in the future. Error messages are specific: "cannot be used while another operation is in progress" and "cannot drop '<path>' (<oid>): it is referenced by the current index". **Siddharth Asthana’s review frames the index guard as a UX optimization to avoid immediate re-fetching, rather than a correctness requirement.** These guards are now acknowledged as **optional optimizations** rather than correctness measures, since lazy-fetching would transparently restore dropped objects.
- **Preconditions enforced**: `--filter` must be `blob:limit`, `-a` is required, a promisor remote must be configured, and `--filter-to` is rejected. Objects are only enumerated if marked as promisor (via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`); lazy fetches are avoided during enumeration by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query.
- **Drop log specifics**: The log path (`$GIT_DIR/objects/info/promisor-dropped`) is documented in `gitrepository-layout` and tested to verify that real drops append entries. The current implementation records all configured promisor remotes for each dropped object (a NEEDSWORK limitation), but this is not a blocker for v2. Remote-object attribution and error-message integration remain dependent on the `remote-object-info` protocol command. Junio’s proposal would require extending the log to include fetch timestamps.
- **Bitmap validation fix**: The latest revision (patch 1/7) fixes a subtle validation bug where the original code failed to detect when a user explicitly passed `-b` (or `--write-bitmap-index`) on the command line if `repack.writeBitmaps` was already true in the config. The updated patch now correctly rejects such explicit `-b` usage with `--drop-filtered`, while silently disabling config-driven bitmaps for the duration of the command. This distinction ensures explicit `-b` is treated as a hard conflict, whereas config-driven bitmaps are temporarily overridden.
- **Patch-specific details**:
  - **Patch 1/7**: Adds `--drop-filtered` and `--dry-run` options to `builtin/repack.c`, implements all validation logic (including the bitmap-handling fix distinguishing command-line vs config-driven settings), and wires up the options without performing object enumeration or deletion. The validation layer is complete and tested in `t/t7706-repack-drop-filtered.sh`.
  - **Patch 2/7**: Introduces `list_objects_filter__filter_oidset()` to apply a filter to an existing oidset without an object walk. The helper reimplements the `blob:limit` size check (duplicating logic from `list_objects_filter__filter_object()`) and flags this duplication with a `NEEDSWORK` comment. It avoids lazy fetches via `OBJECT_INFO_SKIP_FETCH_OBJECT` and supports only `blob:limit` filters in this version.
  - **Patch 3/7**: Extends `repack_promisor_objects()` to accept an optional `to_drop` oidset parameter, enabling rebuilt promisor packs to exclude specified objects. The change is backward-compatible: all existing callers pass `NULL`, preserving unchanged behavior.
  - **Patch 4/7**: Implements `enumerate_promisor_blobs()` in `repack-filtered.c`, which walks all promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, collects blobs into an oidset, and applies the filter using `list_objects_filter__filter_oidset()`. Junio’s time-based heuristic would extend this function to incorporate object fetch timestamps, likely via a new metadata field in the promisor object log or a separate timestamp file (precedent: cruft pack `.mtimes`). The enumeration is wired into `cmd_repack()` so that `--dry-run` prints the candidate OIDs.
  - **Patch 5/7**: Implements real object removal by wiring the `drop_oids` set into `repack_promisor_objects()`, which rebuilds promisor packs while excluding the dropped blobs. Sets `delete_redundant = 1` to remove old promisor packs containing the dropped objects, **implying `-d`**.
  - **Patch 6/7**: **Implements the two critical safety guards** (merge/rebase/cherry-pick checks and index validation) via `wt_status_get_state()` and `repo_read_index()`. Both checks are skipped for bare repositories. The test script verifies the guards, though their necessity is now contested. Junio’s proposal would replace these guards with a time-based heuristic. The patch adds 47 lines to `builtin/repack.c` and includes specific, actionable error messages. The test script (`t/t7706-repack-drop-filtered.sh`) verifies both guards: one test creates a conflicting merge and confirms the command fails, while another stages a large blob, marks it as promisor, and verifies the drop is refused.
  - **Patch 7/7**: **Documentation patch** adds 35 lines to `Documentation/git-repack.adoc` describing `--drop-filtered` and `--dry-run`, their behavior, constraints, incompatibilities, and safety mechanisms. If Junio’s proposal is adopted, the documentation would need updates to describe the time-based heuristic and its implications. **Siddharth Asthana suggests softening the "guaranteed recoverable" language to acknowledge remote availability risks.**

Open questions and loose ends
1. **Safety guard design**: Junio proposes replacing the current merge/rebase/cherry-pick checks and index validation with a time-based heuristic (avoid culling recently fetched objects, e.g., within the last 20 minutes). Siddharth Shrimali now endorses this approach as a natural extension of the existing "enumerate-then-filter" framework, noting that promisor objects are always stored in packs (never loose), so per-object timestamps would require extending the promisor object log or introducing a separate timestamp file (precedent: cruft pack `.mtimes` files). The list’s preference on this trade-off (simplicity vs smarter heuristics) will determine the next revision’s design. The current safety guards are now viewed as optional optimizations rather than correctness measures. **Siddharth Asthana’s review frames the index guard as a UX optimization to avoid immediate re-fetching.**
2. **Reliability of `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`**: Junio seeks confirmation that promisor-object enumeration is robust in practice. Siddharth Shrimali trusts the mechanism, and **Siddharth Asthana’s review explicitly endorses it as reliable.** Real-world validation from other partial-clone users would still be valuable.
3. **Repack machinery behavior**: Junio confirms the rebuilt promisor pack must be constructed from locally available data only, without triggering lazy fetches. Siddharth Shrimali clarifies that enumeration uses `OBJECT_INFO_SKIP_FETCH_OBJECT`, and the rebuild step only repacks locally available promisor objects (tested with the promisor remote disabled). The current implementation performs two separate promisor-object walks (one for enumeration, one for repacking), but this could be optimized in the future.
4. **Drop log**: deferred to a follow-up; the log path (`$GIT_DIR/objects/info/promisor-dropped`) is documented and tested for real drops, but remote-object attribution and error-path improvements remain dependent on the `remote-object-info` protocol command. Junio’s proposal would require extending the log to include fetch timestamps.
5. **Remote verification**: client-side remote object availability checks remain deferred pending the `remote-object-info` protocol command.
6. **Merge status**: no maintainer decision yet; integration branch unknown.
7. **Filter scope**: currently limited to `blob:limit`; future extensions may include other filter types (e.g., `tree:0`), object age, path, or reachability. Siddharth Shrimali notes these could plug into the existing "enumerate-then-filter" framework without structural changes. Junio’s time-based heuristic would add object age as a new filter criterion.
8. **Code duplication**: `list_objects_filter__filter_oidset()` duplicates the `blob:limit` size check logic from `list_objects_filter__filter_object()`. This is flagged with a `NEEDSWORK` comment and acknowledged as a pragmatic trade-off for v2.
9. **Timestamp granularity**: promisor objects are always stored in packs (never loose), so per-object timestamps are not natively available. The current best proxy is the mtime of the promisor pack itself, which reflects the fetch time but loses granularity after repacking consolidates multiple packs. Siddharth Shrimali suggests adopting a mechanism similar to cruft pack `.mtimes` files to track per-object timestamps for promisor objects, which would be necessary for the time-based heuristic.
10. **Documentation language**: Siddharth Asthana suggests softening the "guaranteed recoverable" language in the documentation to acknowledge that recoverability depends on remote availability, which is not guaranteed.
11. **Bitmap validation edge case**: The latest revision (patch 1/7) fixes a subtle validation bug where explicit `-b` usage was incorrectly allowed when `repack.writeBitmaps` was set in the config. The fix ensures explicit `-b` is always rejected with `--drop-filtered`, while config-driven bitmaps are silently disabled.
