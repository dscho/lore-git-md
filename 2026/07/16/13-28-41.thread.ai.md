Core problem or goal
Extend `git repack` with a `--drop-filtered` option that safely reclaims disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold (e.g., `--filter=blob:limit=10M`). The feature guarantees safety by (1) only targeting objects marked as promisor (ensuring they are recoverable from the promisor remote), (2) avoiding locally created objects, and (3) introducing UX optimizations (merge/rebase/cherry-pick checks and index validation) to prevent immediate re-fetching. Junio previously proposed an alternative, time-based heuristic to reduce redundant network operations, but this and two other items—remote verification (via the pending `remote-object-info` protocol command) and the drop log (with error-path improvements)—remain explicitly deferred to follow-up work. The author has reframed the safety guards as optional optimizations rather than correctness measures, since lazy-fetching would transparently restore dropped objects.

Key technical details
- **New CLI options**: `git repack --drop-filtered` (real runs) and `--dry-run` (reporting only), documented in `Documentation/git-repack.adoc` with constraints (e.g., `blob:limit` only, `-a` required, promisor remote required), incompatibilities (e.g., `--filter-to`, bitmaps), and safety optimizations (merge/rebase/cherry-pick checks, index validation). The documentation explains the implied `-d`, the rationale for silent bitmap disabling, and the `--dry-run` preview functionality.
- **New files**: `repack-filtered.c` (core logic, including `enumerate_promisor_blobs()`), `t/t7706-repack-drop-filtered.sh` (test script).
- **Modified files**: `builtin/repack.c` (option parsing, validation, conditional bypass of `write_filtered_pack()`, drop log wiring, real object removal via `repack_promisor_objects()` with `to_drop`, and safety guards via `wt_status_get_state()` and `repo_read_index()`), `list-objects-filter.{c,h}` (new `list_objects_filter__filter_oidset()` API), `repack-promisor.c` (promisor pack rebuilding with object exclusion via `to_drop` parameter, `append_drop_log()`), `repack.h` (function signature changes), `Documentation/git-repack.adoc` (man page updates for `--drop-filtered` and `--dry-run`).
- **New data structures**: `all_promisor_blobs` and `to_drop` oidsets, plus a new "skip-set" (`index_referenced_oids`) to track blobs referenced by the index without mutating `drop_oids`.
- **New helper functions**: `list_objects_filter__filter_oidset()` (applies filter to an existing oidset without object traversal, avoids lazy fetches via `OBJECT_INFO_SKIP_FETCH_OBJECT`), `enumerate_promisor_blobs()` (walks promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, returns drop set via output parameter `oidset *to_drop`).
- **Behavior**: `--drop-filtered` + `--filter=<spec>` (currently limited to `blob:limit=<n>`) removes promisor blobs exceeding the threshold; locally created objects are untouched. Bitmaps are silently disabled to avoid breaking pack closure. The `to_drop` set’s contents are passed to `repack_promisor_objects()` to rebuild promisor packs while excluding the dropped blobs, implying `-d` to remove old promisor packs containing the dropped objects. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety.
- **Safety optimizations**: (1) merge/rebase/am/cherry-pick/revert/bisect checks (via `wt_status_get_state()`) prevent drops during ongoing operations, (2) index validation (via `repo_read_index()`) now **skips** blobs referenced by the current index with a warning instead of failing, improving usability. Both checks are skipped for bare repositories. Error messages are specific: "Refuse to drop objects while another operation is in progress" (listing all blocked operations explicitly) and "Skipping '<path>' (<oid>): it is referenced by the current index". The drop log will not record skipped blobs as dropped.
- **Preconditions enforced**: `--filter` must be `blob:limit`, `-a` is required, a promisor remote must be configured, and `--filter-to` is rejected. Objects are only enumerated if marked as promisor (via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`); lazy fetches are avoided during enumeration by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query.
- **Bitmap validation fix**: Patch 1/6 fixes a subtle validation bug where explicit `-b` usage was incorrectly allowed when `repack.writeBitmaps` was set in the config. The updated patch now correctly rejects explicit `-b` with `--drop-filtered`, while silently disabling config-driven bitmaps for the duration of the command.
- **Patch-specific details**:
  - **Patch 1/6**: Adds `--drop-filtered` and `--dry-run` options to `builtin/repack.c`, implements all validation logic (including the bitmap-handling fix distinguishing command-line vs config-driven settings), and wires up the options without performing object enumeration or deletion. Tests cover all validation scenarios, including the bitmap-handling fix.
  - **Patch 2/6**: Introduces `list_objects_filter__filter_oidset()` in `list-objects-filter.{c,h}`, a helper that applies a filter (currently only `blob:limit`) to an existing oidset without performing an object walk. The implementation duplicates the `blob:limit` size check logic from `list_objects_filter__filter_object()`, marked with a `NEEDSWORK` comment for future refactoring. The helper avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info. **Fixed blocking bug**: changed `unsigned long size` to `size_t size` to match `struct object_info.sizep`. **Mechanical improvement**: made the `opts` parameter `const` as suggested by Christian Couder.
  - **Patch 3/6**: Extends `repack_promisor_objects()` to accept an optional `to_drop` oidset; when provided, the function rebuilds the promisor pack while excluding those objects. The change is minimal and backward-compatible: all existing callers pass `NULL`, so behavior is unchanged. The implementation skips objects in the `to_drop` set during promisor object enumeration (via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`), ensuring the rebuilt promisor pack omits the dropped objects while preserving all others.
  - **Patch 4/6**: Implements `enumerate_promisor_blobs()` in `repack-filtered.c`, which walks all promisor objects (using `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`) and collects blobs into an oidset (`all_promisor_blobs`). It then applies the filter (currently only `blob:limit`) to that set using `list_objects_filter__filter_oidset()`, producing the final `to_drop` set. In `--dry-run` mode, the function prints the OIDs of candidate blobs to stdout. The implementation avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query. The test script verifies enumeration, `--dry-run` output, and locally created blob exclusion.
  - **Patch 5/6**: Wires up the `to_drop` oidset—computed by `enumerate_promisor_blobs()`—to `repack_promisor_objects()`, enabling real object removal. On a real run (`--drop-filtered` without `--dry-run`), it sets `delete_redundant = 1` to remove old promisor packs containing the dropped blobs. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. The test script verifies that a large promisor blob is absent after `--drop-filtered` runs, while a smaller one remains. **Documentation**: Squashed most of the `--drop-filtered` description into this patch, covering preconditions, incompatibilities, implied `-d`, and silent bitmap disabling.
  - **Patch 6/6 (updated)**: Adds safety guards to prevent `--drop-filtered` from running during ongoing operations (merge, rebase, am, cherry-pick, revert, bisect) or **skipping** blobs referenced by the current index with a warning. The implementation uses `wt_status_get_state()` to detect ongoing operations and `repo_read_index()` to collect index-referenced OIDs into a "skip-set" (`index_referenced_oids`). The dry-run printer and real drop logic consult this set to avoid mutating `drop_oids`. Error messages now clarify that the operation continues for other blobs. Both checks are skipped for bare repositories. **Documentation**: Squashed the safety guards paragraph into this patch, updated to reflect the warning-based approach. **New behavior**: Skips index-referenced blobs instead of failing, improving usability. Tests will be updated to cover the new behavior.

Open questions and loose ends
1. **Integration branch**: The series is **proposed for `next`** and awaits the final v6 update (patch 6/6) before Junio’s explicit merge annotation.
2. **Test coverage**: The author must update the test script (`t/t7706-repack-drop-filtered.sh`) to cover the new warning-based index validation behavior, including `--dry-run` output for skipped blobs and real runs that skip index-referenced blobs.
3. **Drop log**: The planned drop log must not record skipped blobs as dropped. This is noted as a follow-up consideration but does not block v6.
4. **Filter scope**: Currently limited to `blob:limit`; future extensions may include other filter types (e.g., `tree:0`), object age, path, or reachability. Samuel Bronson’s feedback does not yet address `--filter=blob:none` support, but this may be requested in the future.
5. **Code duplication**: `list_objects_filter__filter_oidset()` duplicates the `blob:limit` size check logic from `list_objects_filter__filter_object()`. This is flagged with a `NEEDSWORK` comment and noted as technical debt.
6. **Timestamp granularity**: Promisor objects are always stored in packs (never loose), so per-object timestamps are not natively available. The current best proxy is the mtime of the promisor pack itself, which loses granularity after repacking consolidates multiple packs. A mechanism similar to cruft pack `.mtimes` files would be necessary for the time-based heuristic (deferred to follow-up).
7. **Implied `-d`**: The `--drop-filtered` option implies `-d` to remove old promisor packs containing dropped blobs. This is documented in the code comment in `builtin/repack.c` but could be made explicit in the user-facing documentation if reviewers prefer.
8. **Follow-up work confirmed**: The three deferred items—remote verification (via the pending `remote-object-info` protocol command), recency-based culling (time-based heuristic), and the drop log (with error-path improvements)—remain explicitly out of scope for this series.
