Thread identity
Subject: [RFC PATCH 0/N] repack: introduce --drop-filtered for partial clones
Series version: RFC v1 (patches 1/7–7/7 posted; patch 3/7 now detailed)
Originating author: Siddharth Shrimali (first-time contributor)
Thread type: RFC patch series

Core problem or goal
Extend `git repack` with a `--drop-filtered` option that safely reclaims disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold (e.g., `--filter=blob:limit=10M`). The feature must guarantee safety by (1) only targeting objects marked as promisor (ensuring they are recoverable from the promisor remote), (2) avoiding locally created objects, and (3) introducing a drop log (`$GIT_DIR/objects/info/promisor-dropped`) to record removed objects for improved error messages during future lazy-fetch failures.

Current status
RFC v1 posted in full (7 patches). Patch 1/7 establishes CLI validation and scaffolding; patch 2/7 adds `list_objects_filter__filter_oidset()` to the `list-objects-filter` API for OID-based filtering without object traversal; patch 3/7 (newly detailed) extends `repack_promisor_objects()` to accept an optional `oidset` of objects to exclude during promisor pack rebuilding. Patches 4–6 build internal APIs and safety checks; patch 7/7 adds the actual object-dropping logic and test coverage. Implementation remains in flux: function signatures, test placement, and internal API boundaries are expected to change in v2. No maintainer decision or integration branch assignment yet.

Key technical details
- **New CLI options**: `git repack --drop-filtered` and `--dry-run` (mandatory in v1)
- **New file**: `repack-filtered.c` (core logic, introduced in patch 2/7)
- **Modified files**: `builtin/repack.c` (option parsing, validation), `list-objects-filter.{c,h}` (new `list_objects_filter__filter_oidset()` API), `repack-promisor.c` (promisor pack rebuilding with object exclusion via `to_drop` parameter), `repack.h` (function signature change for `repack_promisor_objects()`)
- **New data structure**: drop log (`$GIT_DIR/objects/info/promisor-dropped`) to record removed OIDs (patch 7/7)
- **New helper function**: `list_objects_filter__filter_oidset()` (patch 2/7) applies a filter (currently `blob:limit`) to an existing oidset without object traversal, using `OBJECT_INFO_SKIP_FETCH_OBJECT` to avoid lazy fetches. The implementation duplicates the `blob:limit` size check logic (marked `NEEDSWORK` for future refactoring).
- **Behavior**: `--drop-filtered` + `--filter=<spec>` (currently limited to `blob:limit=<n>`) removes promisor blobs exceeding the threshold; locally created objects are untouched. Bitmaps are silently disabled to avoid breaking pack closure. The `to_drop` set’s contents are not validated in patch 3/7—safety checks (e.g., ensuring dropped objects are promisor and not referenced by the index) are deferred to higher layers.
- **Safety**: objects are only dropped if marked as promisor and not referenced by the current index (safety guards planned for v2). Preconditions enforced in patch 1/7: `--filter` must be `blob:limit`, `-a` is required, a promisor remote must be configured, and `--filter-to` is rejected.

Open questions and loose ends
1. **Safety guards**: v2 will add checks to prevent drops during merges, rebases, or when blobs are referenced by the current index.
2. **Remote verification**: the drop log will be enhanced to record the exact promisor remote for each object, but this depends on a new `remote-object-info` protocol command (not yet implemented).
3. **Function signature churn**: the RFC notes that internal APIs (`list_objects_filter__filter_oidset()`, `repack_promisor_objects()`) and test placement will be reorganized in v2. The helper’s current implementation duplicates `blob:limit` logic, which is flagged for refactoring.
4. **Client-side remote object availability**: currently no way to query whether a promisor remote still has an object; this is a known limitation.
5. **Merge status**: no maintainer feedback yet; integration branch unknown.
6. **Dry-run requirement**: `--dry-run` is mandatory in v1, reflecting the RFC’s early state; this may be relaxed in v2.
