Thread identity
Subject: [RFC PATCH 0/N] repack: introduce --drop-filtered for partial clones
Series version: RFC v2 planned (patches 1/7–7/7; v1 was RFC v1)
Originating author: Siddharth Shrimali (first-time contributor)
Thread type: RFC patch series

Core problem or goal
Extend `git repack` with a `--drop-filtered` option that safely reclaims disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold (e.g., `--filter=blob:limit=10M`). The feature must guarantee safety by (1) only targeting objects marked as promisor (ensuring they are recoverable from the promisor remote), (2) avoiding locally created objects, and (3) introducing safety guards to prevent drops during merges, rebases, or cherry-picks, and to avoid dropping blobs referenced by the current index.

Current status
RFC v1 is complete (7/7 patches posted). The series remains in active design iteration with no integration branch assignment. **Blocking issues for v2 are now settled**: (1) the `--drop-filtered` vs `--write-bitmap-index` validation flaw (Junio’s feedback) will be fixed by restructuring the validation to distinguish command-line vs configuration-driven bitmap settings; (2) **safety guards** (merge/rebase/cherry-pick checks and index validation) are now confirmed as non-negotiable for v2 (Siddharth Asthana’s feedback); (3) the drop log (`$GIT_DIR/objects/info/promisor-dropped`) is **deferred to a follow-up**, along with remote-object attribution and `remote-object-info` protocol dependencies. The CLI design (`--drop-filtered` + `--dry-run`) is finalized, with rationale to be documented in the commit message. **Function signature reorganization** (internal APIs such as `enumerate_promisor_blobs()`) remains a v2 priority. **New clarification for v2**: a real `--drop-filtered` run will now **imply `-d`** (removing old promisor packs containing the dropped blobs), ensuring disk space is actually reclaimed. This behavior will be documented in the v2 man page and aligns with the repack machinery’s existing logic.

Key technical details
- **New CLI options**: `git repack --drop-filtered` (real runs) and `--dry-run` (no longer mandatory)
- **New files**: `repack-filtered.c` (core logic), `t/t7706-repack-drop-filtered.sh` (test script)
- **Modified files**: `builtin/repack.c` (option parsing, validation, conditional bypass of `write_filtered_pack()`, drop log wiring, and real object removal via `repack_promisor_objects()` with `drop_oids`), `list-objects-filter.{c,h}` (new `list_objects_filter__filter_oidset()` API), `repack-promisor.c` (promisor pack rebuilding with object exclusion via `to_drop` parameter, `append_drop_log()`), `repack.h` (function signature changes)
- **New data structures**: `all_promisor_blobs` and `to_drop` oidsets; drop log (deferred) recording removed OIDs with timestamp, filter spec, and promisor remote(s)
- **New helper functions**: `list_objects_filter__filter_oidset()` (applies filter to an existing oidset without object traversal), `enumerate_promisor_blobs()` (walks promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, returns drop set via output parameter `oidset *to_drop`)
- **Behavior**: `--drop-filtered` + `--filter=<spec>` (currently limited to `blob:limit=<n>`) removes promisor blobs exceeding the threshold; locally created objects are untouched. Bitmaps are silently disabled to avoid breaking pack closure. The `to_drop` set’s contents are passed to `repack_promisor_objects()` to rebuild promisor packs while excluding the dropped blobs, **now implying `-d`** to remove old promisor packs containing the dropped objects. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. **Safety guards for v2**: merge/rebase/cherry-pick checks and index validation (preventing drops of blobs referenced by the current index) will be implemented to avoid immediate re-fetching of just-dropped blobs.
- **Preconditions enforced**: `--filter` must be `blob:limit`, `-a` is required, a promisor remote must be configured, and `--filter-to` is rejected. Objects are only enumerated if marked as promisor (via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`); lazy fetches are avoided during enumeration by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query.

Open questions and loose ends
1. **Bitmap validation**: the blocking flaw in patch 1/7 must be fixed in v2 by restructuring the validation to explicitly track whether `--write-bitmap-index` was set on the command line (erroring out if so) versus via configuration (silently disabling it).
2. **Safety guards**: merge/rebase/cherry-pick checks and index validation are now confirmed as non-negotiable for v2 (Siddharth Asthana’s feedback) and will be implemented before posting v2.
3. **Function signature churn**: internal APIs (`list_objects_filter__filter_oidset()`, `repack_promisor_objects()`, `enumerate_promisor_blobs()`) and test placement will be reorganized in v2.
4. **Drop log**: deferred to a follow-up; the log path (`$GIT_DIR/objects/info/promisor-dropped`) will not be documented in `gitrepository-layout` or tested for real drops in v2.
5. **Remote verification**: the drop log’s remote-object attribution (recording which promisor remote each object is recoverable from) and client-side remote object availability checks remain deferred pending the `remote-object-info` protocol command.
6. **Merge status**: no maintainer decision yet; integration branch unknown.
7. **Filter scope**: currently limited to `blob:limit`; future extensions may include other filter types (e.g., `tree:0`).

- **Junio C Hamano (maintainer)**: **Substantive review of patch 1/7** identifies and confirms the blocking logical flaw in the `--drop-filtered` vs `--write-bitmap-index` validation. The check occurs too late in the control flow (after `write_bitmaps` may have been set by config), so it cannot distinguish between user-requested bitmaps (which should be rejected) and config-driven bitmaps (which should be silently disabled). This renders the safety mechanism ineffective and must be fixed before the series can proceed.
- **Christian Couder**: **Surface-level review of patch 1/7** focuses on CLI design. Endorses the current separation of `--drop-filtered` and `--dry-run`, noting that `--dry-run` is already a common pattern in other Git commands. Requests only that the commit message explain the rationale for the two-option design.
- **Siddharth Asthana (reviewer)**: **Substantive review** endorses the core approach (using the promisor repack path rather than `write_filtered_pack()`) as the right technical direction. Raises two **critical safety concerns** that are now confirmed as non-negotiable for v2: (1) **safety guards preventing drops during merges, rebases, or cherry-picks**, and (2) **index validation** (preventing drops of blobs referenced by the current index to avoid immediate re-fetching). Aligns with Christian Couder on the CLI design (`--drop-filtered` + `--dry-run`). **Endorses deferring the drop log** to a follow-up but insists the safety guards are blocking for v2.
