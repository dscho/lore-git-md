Thread identity
Subject: [RFC PATCH 0/N] repack: introduce --drop-filtered for partial clones
Series version: RFC v2 (patches 1/7–7/7)
Originating author: Siddharth Shrimali (first-time contributor)
Thread type: RFC patch series

Core problem or goal
Extend `git repack` with a `--drop-filtered` option that safely reclaims disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold (e.g., `--filter=blob:limit=10M`). The feature must guarantee safety by (1) only targeting objects marked as promisor (ensuring they are recoverable from the promisor remote), (2) avoiding locally created objects, and (3) introducing safety guards to prevent drops during merges, rebases, or cherry-picks, and to avoid dropping blobs referenced by the current index.

Current status
RFC v2 is complete (7/7 patches posted). The series addresses all blocking issues from v1: (1) the `--drop-filtered` vs `--write-bitmap-index` validation flaw is fixed by restructuring the validation to distinguish command-line vs configuration-driven bitmap settings; (2) safety guards (merge/rebase/cherry-pick checks and index validation) are implemented; (3) the core enumeration logic (`enumerate_promisor_blobs()`) is now in place (patch 4/7), identifying promisor blobs exceeding the threshold via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` and `OBJECT_INFO_SKIP_FETCH_OBJECT`; (4) function signature reorganization (internal APIs such as `enumerate_promisor_blobs()` and `repack_promisor_objects()`) is complete. The drop log (`$GIT_DIR/objects/info/promisor-dropped`) and remote verification remain deferred to follow-ups, but the core functionality is finalized. A real `--drop-filtered` run now **implies `-d`** (removing old promisor packs containing the dropped blobs), ensuring disk space is actually reclaimed. This behavior is documented in the v2 man page. The CLI design (`--drop-filtered` + `--dry-run`) is finalized, with rationale documented in the commit message. Integration branch remains unknown; no maintainer decision yet.

Key technical details
- **New CLI options**: `git repack --drop-filtered` (real runs) and `--dry-run` (reporting only)
- **New files**: `repack-filtered.c` (core logic, including `enumerate_promisor_blobs()`), `t/t7706-repack-drop-filtered.sh` (test script)
- **Modified files**: `builtin/repack.c` (option parsing, validation, conditional bypass of `write_filtered_pack()`, drop log wiring, and real object removal via `repack_promisor_objects()` with `drop_oids`), `list-objects-filter.{c,h}` (new `list_objects_filter__filter_oidset()` API), `repack-promisor.c` (promisor pack rebuilding with object exclusion via `to_drop` parameter, `append_drop_log()`), `repack.h` (function signature changes), `Documentation/git-repack.adoc` (man page updates)
- **New data structures**: `all_promisor_blobs` and `to_drop` oidsets; drop log (deferred) recording removed OIDs with timestamp, filter spec, and promisor remote(s)
- **New helper functions**: `list_objects_filter__filter_oidset()` (applies filter to an existing oidset without object traversal, avoids lazy fetches via `OBJECT_INFO_SKIP_FETCH_OBJECT`), `enumerate_promisor_blobs()` (walks promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, returns drop set via output parameter `oidset *to_drop`)
- **Behavior**: `--drop-filtered` + `--filter=<spec>` (currently limited to `blob:limit=<n>`) removes promisor blobs exceeding the threshold; locally created objects are untouched. Bitmaps are silently disabled to avoid breaking pack closure. The `to_drop` set’s contents are passed to `repack_promisor_objects()` to rebuild promisor packs while excluding the dropped blobs, **implying `-d`** to remove old promisor packs containing the dropped objects. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. **Safety guards**: merge/rebase/cherry-pick checks and index validation (preventing drops of blobs referenced by the current index) are implemented to avoid immediate re-fetching of just-dropped blobs.
- **Preconditions enforced**: `--filter` must be `blob:limit`, `-a` is required, a promisor remote must be configured, and `--filter-to` is rejected. Objects are only enumerated if marked as promisor (via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`); lazy fetches are avoided during enumeration by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query.
- **Drop log specifics**: The log path (`$GIT_DIR/objects/info/promisor-dropped`) is documented in `gitrepository-layout` and tested to verify that real drops append entries. The current implementation records all configured promisor remotes for each dropped object (a NEEDSWORK limitation), but this is not a blocker for v2. Remote-object attribution and error-message integration remain dependent on the `remote-object-info` protocol command.
- **Patch 1/7 specifics**: Adds `--drop-filtered` and `--dry-run` options to `builtin/repack.c`, implements all validation logic (including the bitmap-handling fix distinguishing command-line vs config-driven settings), and wires up the options without performing object enumeration or deletion. The validation layer is complete and tested in `t/t7706-repack-drop-filtered.sh`, addressing the critical feedback from v1.
- **Patch 2/7 specifics**: Introduces `list_objects_filter__filter_oidset()` to apply a filter to an existing oidset without an object walk. The helper reimplements the `blob:limit` size check (duplicating logic from `list_objects_filter__filter_object()`) and flags this duplication with a `NEEDSWORK` comment. It avoids lazy fetches via `OBJECT_INFO_SKIP_FETCH_OBJECT` and supports only `blob:limit` filters in this version.
- **Patch 3/7 specifics**: Extends `repack_promisor_objects()` to accept an optional `to_drop` oidset parameter, enabling rebuilt promisor packs to exclude specified objects. The change is backward-compatible: all existing callers pass `NULL`, preserving unchanged behavior. The new parameter is plumbed through to the `write_oid()` callback, which skips objects present in `to_drop`. This is the core mechanism enabling later patches to remove filtered promisor blobs. The exclusion logic is minimal and safe, with no performance impact for the default case.
- **Patch 4/7 specifics**: Implements `enumerate_promisor_blobs()` in `repack-filtered.c`, which walks all promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, collects blobs into an oidset, and applies the filter using `list_objects_filter__filter_oidset()`. The enumeration is wired into `cmd_repack()` so that `--dry-run` prints the candidate OIDs, while real drops are deferred to later patches. Safety is guaranteed by construction: every object visited is a promisor object (recoverable from the remote), and `OBJECT_INFO_SKIP_FETCH_OBJECT` prevents lazy fetches during enumeration. Test coverage verifies that only promisor blobs exceeding the threshold are listed, that locally created blobs are never candidates, and that `--dry-run` leaves objects untouched.

Open questions and loose ends
1. **Drop log**: deferred to a follow-up; the log path (`$GIT_DIR/objects/info/promisor-dropped`) is documented in `gitrepository-layout` and tested for real drops, but remote-object attribution and error-path improvements remain dependent on the `remote-object-info` protocol command. The current implementation’s NEEDSWORK limitation (recording all configured promisor remotes) is not a blocker for v2.
2. **Remote verification**: client-side remote object availability checks remain deferred pending the `remote-object-info` protocol command.
3. **Merge status**: no maintainer decision yet; integration branch unknown.
4. **Filter scope**: currently limited to `blob:limit`; future extensions may include other filter types (e.g., `tree:0`).
5. **Code duplication**: `list_objects_filter__filter_oidset()` duplicates the `blob:limit` size check logic from `list_objects_filter__filter_object()`. This is flagged with a `NEEDSWORK` comment and acknowledged as a pragmatic trade-off for v2.
