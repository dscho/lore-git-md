Core problem or goal
Extend `git repack` with a `--drop-filtered` option that safely reclaims disk space in partial clones by removing locally cached promisor blobs exceeding a user-specified size threshold (e.g., `--filter=blob:limit=10M`). The feature guarantees safety by (1) only targeting objects marked as promisor (ensuring they are recoverable from the promisor remote), (2) avoiding locally created objects, and (3) introducing UX optimizations (merge/rebase/cherry-pick checks and index validation) to prevent immediate re-fetching. Junio has proposed an alternative, time-based heuristic to reduce redundant network operations: avoid culling recently fetched objects (e.g., those downloaded within the last 20 minutes) instead of relying on the current guards. Siddharth Shrimali now frames the guards as optional optimizations rather than correctness measures, since lazy-fetching would transparently restore dropped objects. The time-based heuristic would require extending the promisor object log or introducing a separate timestamp file (precedent: cruft pack `.mtimes` files), but remains deferred to a follow-up.

Key technical details
- **New CLI options**: `git repack --drop-filtered` (real runs) and `--dry-run` (reporting only), documented in `Documentation/git-repack.adoc` with constraints (e.g., `blob:limit` only, `-a` required, promisor remote required), incompatibilities (e.g., `--filter-to`, bitmaps), and safety optimizations (merge/rebase/cherry-pick checks, index validation). The documentation explains the implied `-d`, the rationale for silent bitmap disabling, and the `--dry-run` preview functionality.
- **New files**: `repack-filtered.c` (core logic, including `enumerate_promisor_blobs()`), `t/t7706-repack-drop-filtered.sh` (test script, now with `test_grep` fixes).
- **Modified files**: `builtin/repack.c` (option parsing, validation, conditional bypass of `write_filtered_pack()`, drop log wiring, real object removal via `repack_promisor_objects()` with `to_drop`, and safety guards via `wt_status_get_state()` and `repo_read_index()`), `list-objects-filter.{c,h}` (new `list_objects_filter__filter_oidset()` API), `repack-promisor.c` (promisor pack rebuilding with object exclusion via `to_drop` parameter, `append_drop_log()`), `repack.h` (function signature changes), `Documentation/git-repack.adoc` (man page updates for `--drop-filtered` and `--dry-run`).
- **New data structures**: `all_promisor_blobs` and `to_drop` oidsets; drop log (deferred) recording removed OIDs with timestamp, filter spec, and promisor remote(s).
- **New helper functions**: `list_objects_filter__filter_oidset()` (applies filter to an existing oidset without object traversal, avoids lazy fetches via `OBJECT_INFO_SKIP_FETCH_OBJECT`), `enumerate_promisor_blobs()` (walks promisor objects via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, returns drop set via output parameter `oidset *to_drop`).
- **Behavior**: `--drop-filtered` + `--filter=<spec>` (currently limited to `blob:limit=<n>`) removes promisor blobs exceeding the threshold; locally created objects are untouched. Bitmaps are silently disabled to avoid breaking pack closure. The `to_drop` set’s contents are passed to `repack_promisor_objects()` to rebuild promisor packs while excluding the dropped blobs, implying `-d` to remove old promisor packs containing the dropped objects. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. **Safety optimizations**: (1) merge/rebase/cherry-pick checks (via `wt_status_get_state()`) prevent drops during ongoing operations, (2) index validation (via `repo_read_index()`) prevents drops of blobs referenced by the current index. Both checks are skipped for bare repositories. Error messages are specific: "cannot be used while another operation is in progress" and "cannot drop '<path>' (<oid>): it is referenced by the current index". The current implementation performs two separate promisor-object walks (one for enumeration, one for repacking), but this could be optimized in the future.
- **Preconditions enforced**: `--filter` must be `blob:limit`, `-a` is required, a promisor remote must be configured, and `--filter-to` is rejected. Objects are only enumerated if marked as promisor (via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`); lazy fetches are avoided during enumeration by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query.
- **Bitmap validation fix**: Patch 1/7 fixes a subtle validation bug where explicit `-b` usage was incorrectly allowed when `repack.writeBitmaps` was set in the config. The updated patch now correctly rejects explicit `-b` with `--drop-filtered`, while silently disabling config-driven bitmaps for the duration of the command.

Open questions and loose ends
1. **Safety guard design**: Junio proposes replacing the current merge/rebase/cherry-pick checks and index validation with a time-based heuristic (avoid culling recently fetched objects, e.g., within the last 20 minutes). The list’s preference on this trade-off (simplicity vs smarter heuristics) will determine the next revision’s design. The current guards are now viewed as UX optimizations rather than correctness measures.
2. **Reliability of `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`**: Junio seeks confirmation that promisor-object enumeration is robust in practice. Siddharth Shrimali and Siddharth Asthana trust the mechanism, but real-world validation from other partial-clone users would be valuable.
3. **Repack machinery behavior**: Junio confirms the rebuilt promisor pack must be constructed from locally available data only, without triggering lazy fetches. The current implementation performs two separate promisor-object walks (one for enumeration, one for repacking), but this could be optimized in the future.
4. **Drop log**: deferred to a follow-up; the log path (`$GIT_DIR/objects/info/promisor-dropped`) is documented and tested for real drops, but remote-object attribution and error-path improvements remain dependent on the `remote-object-info` protocol command.
5. **Remote verification**: client-side remote object availability checks remain deferred pending the `remote-object-info` protocol command.
6. **Merge status**: no maintainer decision yet; integration branch unknown.
7. **Filter scope**: currently limited to `blob:limit`; future extensions may include other filter types (e.g., `tree:0`), object age, path, or reachability.
8. **Code duplication**: `list_objects_filter__filter_oidset()` duplicates the `blob:limit` size check logic from `list_objects_filter__filter_object()`. This is flagged with a `NEEDSWORK` comment.
9. **Timestamp granularity**: promisor objects are always stored in packs (never loose), so per-object timestamps are not natively available. The current best proxy is the mtime of the promisor pack itself, which loses granularity after repacking consolidates multiple packs. A mechanism similar to cruft pack `.mtimes` files would be necessary for the time-based heuristic.
