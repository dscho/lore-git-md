This is the third patch in Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. It extends the promisor pack rebuilding logic (`repack_promisor_objects()`) to accept an optional `oidset` of objects to exclude from the rebuilt pack. The change is mechanical: the new `to_drop` parameter is plumbed through to the `write_oid()` callback, which skips any OID found in the set. All existing callers continue to pass `NULL`, so behavior is unchanged for now.

The patch is a straightforward plumbing layer that enables the core `--drop-filtered` logic (coming in patch 7/7). It touches three files: `builtin/repack.c` (trivial caller update), `repack-promisor.c` (the exclusion logic), and `repack.h` (function signature change). The implementation is minimal and correct, but the commit message could be clearer about the intended use: the `to_drop` set will contain promisor blobs that exceed the `--filter=blob:limit` threshold, and the exclusion ensures they are not re-added to the promisor pack after being removed.

This is a well-scoped refactoring that fits cleanly into the series’ architecture. The only future-proofing note is that the `to_drop` set’s contents are not validated here—safety checks (e.g., ensuring dropped objects are promisor and not referenced by the index) are deferred to higher layers, which is reasonable for an RFC. The patch is unlikely to be controversial, but its utility depends entirely on the rest of the series landing.
