This is the fourth patch in a seven-part GSoC series adding new path-related keys to the `git repo info` command. The patch introduces `path.hooks.absolute` and `path.hooks.relative`, which expose the repository’s hooks directory location in a scriptable format, respecting `core.hooksPath` configuration.

The implementation is straightforward: it uses `repo_git_path_replace()` to resolve the hooks path (accounting for `core.hooksPath` overrides) and formats it as either an absolute or relative path using the existing `format_path()` helper. The patch touches `builtin/repo.c` (adding the new keys and their formatting logic), `Documentation/git-repo.adoc` (documenting the keys), and `t/t1900-repo-info.sh` (testing the functionality). Tests verify both the standard `.git/hooks` fallback and custom `core.hooksPath` setups.

This patch continues the series’ pattern of exposing internal Git paths in a user-friendly way, mirroring earlier additions like `path.objects` and `path.gitdir`. The commit message clearly explains the motivation—external tools needing a stable way to locate hooks—and the implementation follows the established suffix-based formatting convention. No substantive review feedback has appeared yet, but the patch looks well-crafted and aligns with the series’ goals. Reviewers may focus on whether the key naming (`path.hooks`) is sufficiently intuitive or if it should align more closely with existing Git terminology (e.g., `gitdir`).
