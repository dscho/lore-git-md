This is the v6 iteration of a two-patch series that makes submodule fetch errors configurable, completing the effort Paulius Zaleckas began in v1. The series introduces `fetch.submoduleErrors` (config) and `--submodule-errors=(fail|warn)` (CLI) to let users choose whether `git fetch --recurse-submodules` should fail hard or merely warn when a submodule’s gitlink points to an unreachable OID. The default remains `fail` for backwards compatibility, preserving existing behavior.

Patch 1 fixes a pre-existing logic flaw in `submodule.c` where phase-1 fetch failures were recorded prematurely—before phase-2 OID-based retries could run. This refactoring ensures errors are only recorded after all retry attempts fail, which is necessary for the configurable policy in Patch 2 to work correctly. The fix also ensures phase-1 failures are reported even when the gitlinked commits are already present locally, and routes all submodule fetch errors through `record_fetch_error()` for consistent reporting and policy enforcement.

Patch 2 adds the user-facing controls, including forwarding the resolved setting (whether from CLI or config) to child fetches (`--all`, `--multiple`, nested recursion) when explicitly set. The implementation touches `submodule.c`, `builtin/fetch.c`, documentation files, and adds comprehensive test coverage in `t/t5526-fetch-submodules.sh`. v6 incorporates Junio’s latest mechanical feedback: the fail/warn helpers now use a singular array name (`submodule_error_name[]`) and plain `unsigned` instead of `size_t` for array indexing, aligning with Git’s idiomatic style.

The series is now technically complete, addressing all prior review feedback from Junio, Ramsay Jones, and Jean-Noël Avila. The changes are narrowly scoped to the submodule fetch error-handling path, the rationale is well-explained in the commit messages, and the test coverage is thorough. The implementation appears robust and uncontroversial, solving a real workflow pain point—upstream topic branches that are still in flux—without introducing broader risks. This looks ready for `next` once Junio queues it.

Key files touched include `submodule.c`, `submodule.h`, `builtin/fetch.c`, `Documentation/config/fetch.txt`, `Documentation/fetch-options.txt`, and `t/t5526-fetch-submodules.sh`. The new config key (`fetch.submoduleErrors`) and CLI option (`--submodule-errors`) are case-sensitive and parsed via a centralized name array, eliminating redundant conditional branches. The setting is explicitly forwarded to per-remote child processes to override any repository config, preserving user intent.
