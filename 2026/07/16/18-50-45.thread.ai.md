Core problem or goal: Replace O(n²) `string_list_insert()` calls (which maintain sorted order but trigger O(n) array shifts per insertion) with a single O(n) `string_list_append()` pass followed by one O(n log n) sort and deduplicate operation per list (`s->untracked` and `s->ignored`). The goal is to reduce the theoretical complexity to O(n log n) while preserving the existing behavior of producing sorted, duplicate-free lists. The patch is now framed primarily as an improvement to code clarity and maintainability, as the original quadratic-time behavior is acknowledged to be likely theoretical (due to pre-sorted input from `fill_directory()`) and not a practical bottleneck.
