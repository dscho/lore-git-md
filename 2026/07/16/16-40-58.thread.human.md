This thread is a user support discussion about a platform-specific issue: pressing Ctrl+C in a Vagrant SSH session from Git Bash terminates the entire session instead of just interrupting the current command. The problem appears to be unique to Git Bash (it doesn’t happen in PowerShell) and is suspected to be related to a known Git for Windows bug (GitHub issue #3716).

Johannes Schindelin, the Git for Windows maintainer, has identified the issue as likely matching the known bug and has now confirmed that it persists even with the latest Git for Windows release (2.55.0.windows.3). He suggests a workaround: installing the native Windows OpenSSH client and then reinstalling Git for Windows while opting out of the bundled SSH. This workaround points to the issue being tied to Git Bash’s SSH implementation rather than Git core. The original reporter, Moksh Goyal, hasn’t yet responded to test the workaround or provide additional environment details.

The discussion remains open and diagnostic, with no code changes or patches proposed. If the workaround resolves the issue, the thread may conclude as a Git for Windows support matter rather than requiring upstream Git changes. The next step is for the user to test the workaround and report back.
