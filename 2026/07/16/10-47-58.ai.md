This is a bugfix patch targeting the revision-walking subsystem. It corrects a regression introduced in commit `dd4bc01c0a` (May 2026) where `git rev-list --no-walk <commit> -- <path>` stopped respecting path arguments and instead output all commits regardless of whether they touched the specified paths.

The root cause is straightforward: the original commit added a new `REV_WALK_NO_WALK` enum case to `get_revision_1()` but omitted the call to `try_to_simplify_commit()`, which evaluates whether a commit touches the given paths. The fix folds the `REV_WALK_NO_WALK` case into the existing `REV_WALK_REFLOG` case, which already calls `try_to_simplify_commit()`. The change is minimal—just a two-line diff in `revision.c`—and the commit message provides a clear reproduction example using `linux.git` that shows the before/after behavior: 2026 unfiltered commits versus 146 correctly filtered ones.

The patch includes three new tests in `t/t6017-rev-list-stdin.sh` that verify path filtering with `--no-walk`. Two of these tests fail without the fix, while the third ("single commit, match") is defensive and passes even without it. The regression was reported by Peter Colberg, and the fix has been verified against the exact scenario from the report.

This looks like a well-scoped, well-motivated fix. The commit message is clear, the reproduction case is concrete, and the test coverage is appropriate. The regression is recent (two months old) and the fix is targeted, so it should be uncontroversial. The patch touches only the revision-walking logic and does not interact with other subsystems.
