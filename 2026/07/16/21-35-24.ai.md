This is a review reply from Junio C Hamano to the final patch (7/7) in Christian Couder’s `git fast-import` refactoring series. The review is substantive but cautious, focusing on the awkwardness of introducing a large set of unused local variables in the new `struct option` array while deferring the actual parsing logic to future work.

Junio acknowledges the series’ stated goal—modernizing the usage string—and accepts that full libification (moving parsing into `fast_import_state_init()`) is out of scope. However, he expresses discomfort with the current implementation: the patch defines many function-local variables (e.g., `pack_size_limit`, `date_format`) that are referenced in the `struct option` array but never initialized or used, serving only as placeholders for future parsing. He suggests that referencing the existing global variables (e.g., `max_packsize`) directly in the `struct option` array would be cleaner, even if it slightly bends the series’ scope.

The review does not reject the patch outright but flags the current approach as aesthetically awkward and potentially confusing. No technical flaws are identified; the concern is purely about code clarity and the intermediate state of the refactor. The ball is back in Christian’s court to either adjust the patch or justify the placeholder variables as a necessary transitional step. No other reviewers have weighed in yet.
