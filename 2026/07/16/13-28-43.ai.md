This is the second patch in the RFC series introducing `git repack --drop-filtered` for partial clones. It adds a new helper function, `list_objects_filter__filter_oidset()`, to the `list-objects-filter` API, enabling callers to determine which OIDs in a given set would be filtered out by a specified filter (currently limited to `blob:limit=N`).

The helper is designed for scenarios where the caller already has a set of OIDs and wants to apply a filter without performing an object walk—exactly the use case for `--drop-filtered`, which collects promisor blobs into an oidset and needs to identify which ones exceed the size threshold. The implementation bypasses the existing filter machinery (which is tied to object traversal) and instead reimplements the `blob:limit` size check directly, with a `NEEDSWORK` comment acknowledging the duplication and signaling intent to refactor this in a future version. The helper avoids triggering lazy fetches by using `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info.

The patch touches `list-objects-filter.c` and `list-objects-filter.h`, adding the new function and its documentation. While the current implementation is functional, the duplication of the size check logic is a clear technical debt that will need addressing before the series stabilizes. The helper’s design is pragmatic for the RFC stage, but its long-term maintainability hinges on integrating it with the existing filter machinery. No substantive review feedback has been recorded yet, so the API and implementation remain open to change.
