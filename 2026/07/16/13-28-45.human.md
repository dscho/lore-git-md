This is the fourth patch in Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. It implements the core enumeration logic that identifies which promisor blobs are candidates for removal when `--drop-filtered` is used.

The patch works around a key limitation in the existing repack machinery: promisor objects are handled separately (via `repack_promisor_objects()`) before the main `pack-objects` run, so the filter machinery in `write_filtered_pack()` never sees them. Instead, it directly walks promisor objects using `odb_for_each_object()` with the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag, collecting all promisor blobs into an oidset. The `list_objects_filter__filter_oidset()` helper (introduced in patch 2/7) then applies the filter (e.g., `blob:limit=10M`) to select blobs exceeding the threshold. In `--dry-run` mode, the patch simply prints the OIDs of these blobs; actual deletion is deferred to later patches.

The implementation is careful to avoid lazy fetches during enumeration by using `OBJECT_INFO_SKIP_FETCH_OBJECT`, and it skips an explicit `is_promisor_object()` check because the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag guarantees all enumerated objects are promisor. The patch adds a new `enumerate_promisor_blobs()` function in `repack-filtered.c` and updates `builtin/repack.c` to call it when `--drop-filtered` is specified.

This is a well-scoped, technically sound step toward the series’ goal. The approach—directly enumerating promisor objects rather than relying on the filter machinery—is necessary and correct. The patch is clearly motivated and integrates cleanly with the existing repack infrastructure. As an RFC, it’s expected to evolve (e.g., safety guards and remote verification are still pending), but the core logic appears solid. For partial clone users, this is a promising step toward reclaiming disk space without sacrificing safety.
