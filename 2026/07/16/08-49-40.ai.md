This is the third patch in the v6 series migrating `trust_executable_bit` into `struct repo_config_values` as part of the `the_repository` removal effort. The patch is a mechanical refactoring with no behavioral changes: it moves the global `trust_executable_bit` variable into the repository-scoped `repo_config_values` struct, introduces a new getter function `repo_trust_executable_bit()`, and updates all call sites to use repository-scoped access.

The implementation follows the established pattern from earlier patches in the series. The getter function validates the repository pointer and falls back to `1` (the default value) if none is provided, preserving existing behavior. Call sites in `apply.c`, `environment.c`, and `read-cache.c` are updated to use the new getter, with `the_repository` passed explicitly where no repository pointer is available. The patch also initializes the new field in `repo_config_values_init()` and updates `git_default_core_config()` to store the value in the repository-scoped struct instead of the global variable.

This patch is uncontroversial and aligns with the series' goal of eliminating global state. The changes are straightforward and mirror the approach used for other configuration migrations in the `the_repository` removal effort. The only minor tension is the continued reliance on `the_repository` in some call sites, which the author acknowledges as a limitation of the current `repo_config_values` design. This patch does not address the mingw compatibility layer (handled in patch 4/4) or the `has_symlinks` migration (also in patch 4/4), but it completes the groundwork for both by establishing the repository-scoped storage and getter pattern.

Files touched are `apply.c`, `environment.c/h`, and `read-cache.c`.
