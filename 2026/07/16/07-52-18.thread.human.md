This thread is about reviving a `writev(3p)`-like wrapper to reduce system call overhead in Git’s low-level I/O operations, originally merged in Git 2.54 but reverted due to platform compatibility issues. Patrick Steinhardt posted a v1 patch series reintroducing the wrapper with fixes for NonStop and CMake, targeting pktline transmission and cat-blob responses for performance gains. The series has sparked debate over API design, naming, and maintainer appetite.

The integer-overflow concern raised by Simon Richter has been resolved: Junio C Hamano confirmed the existing bounds-checking logic is safe, and Patrick added an explicit overflow check for clarity. The API naming dispute is now settled in favor of `git_write_gather()` (or similar), endorsed by Junio and suggested by Johannes Sixt to avoid implying POSIX semantics. However, Patrick remains hesitant about the rename without a broader rethink of Git’s I/O abstraction strategy and has not addressed the missing benchmarks or the lack of a range-diff to the reverted version. Junio has not commented on whether the series is welcome or if the performance gains justify the complexity.

Key participants include Patrick (author), Simon Richter (identified the overflow issue), Johannes Sixt (pushed for clearer API naming), and Junio (resolved the naming dispute but left broader questions open). The series is still under technical review, with no immediate reroll expected due to Patrick’s offsite. Open questions include the magnitude of performance gains, maintainer appetite, and whether the effort will proceed.
