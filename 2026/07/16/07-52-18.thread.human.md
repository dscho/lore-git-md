This thread is about Patrick Steinhardt’s patch series to reintroduce a `writev(3p)`-like wrapper for performance gains in low-level I/O operations, specifically in pktline transmission and cat-blob responses. The series, now at v1, revives a feature originally merged in Git 2.54 but reverted due to platform compatibility issues (NonStop, CMake), which have since been addressed.

The key technical change replaces multiple `write()` calls with batched `writev()`-like operations, using new wrappers (`git_writev()` and `git_writev_or_die()`) with explicit bounds-checking to avoid partial writes. The integer-overflow concern raised by Simon Richter has been resolved after Junio C Hamano confirmed the existing logic is safe. However, the API’s naming and self-documentation remain contested. Junio has now endorsed Johannes Sixt’s suggestion to rename the wrapper to `git_write_gather()` (or similar) to avoid implying POSIX semantics, framing this as a long-term architectural improvement that would make the API more portable and self-documenting. This decision resolves the naming dispute but leaves other open questions unaddressed.

The series is still under technical review, with no maintainer decision on whether it will be merged. Patrick has expressed openness to dropping the effort if it’s not desired, and Junio’s latest email does not clarify his appetite for the feature. Other loose ends include the lack of benchmark results demonstrating performance gains and the absence of a range-diff to the reverted version, which complicates review. Key participants include Patrick (author), Simon Richter (correctness review), Johannes Sixt (API design critique), and Junio (maintainer). No new patch version is expected immediately, as Patrick and the GitLab team are at an offsite.
