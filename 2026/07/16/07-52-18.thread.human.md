This thread is about reviving a `writev(3p)`-like wrapper in Git to reduce system call overhead in low-level I/O operations, specifically for pktline transmission and cat-blob responses. The wrapper was originally merged in Git 2.54 but reverted due to platform compatibility issues (NonStop, CMake); the current v1 series by Patrick Steinhardt incorporates fixes for those issues and demonstrates broader applicability.

The key technical questions—API design, naming, and architectural concerns—have now been resolved. Johannes Sixt and Junio C Hamano confirmed that Git’s use cases do not require atomicity, allowing the `git_write_gather()` API to be implemented as a simple loop of `write(2)` calls. Junio also endorsed the API’s design, removing the last technical obstacle. The integer-overflow concern raised by Simon Richter was addressed with an explicit overflow check, and the naming dispute was settled in favor of `git_write_gather()` to avoid implying POSIX semantics.

What remains open is whether the performance gains justify the complexity, a decision Junio has not yet made. Additionally, the absence of a range-diff to the reverted version complicates review, though no immediate reroll is expected while Patrick is at an offsite. The series is still under technical review, with no maintainer decision on merge status. Key participants include Patrick (author), Simon Richter (reviewer), Johannes Sixt (reviewer), and Junio (maintainer).
