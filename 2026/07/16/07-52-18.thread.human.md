This thread is about Patrick Steinhardt’s patch series to reintroduce a `writev(3p)`-like wrapper (`git_writev()`) to reduce system call overhead in Git’s low-level I/O operations, specifically for pktline transmission and cat-blob responses. The series is a revival of code originally merged in Git 2.54 but later reverted due to platform compatibility issues (NonStop, CMake); this version includes fixes for those problems and expands the wrapper’s use cases.

The discussion has so far focused on two key technical concerns. First, Simon Richter identified a potential integer overflow in the wrapper’s bounds-checking logic, which Junio C Hamano has now addressed with a proposed fix that explicitly guards against unsigned wrap-around. Second, Johannes Sixt (Hannes) criticized the wrapper’s name (`git_writev()`) for implying POSIX semantics that the emulation cannot guarantee, suggesting `git_write_gather()` as a more accurate alternative. The series remains under active review, with no maintainer decision on whether it will be merged.

Patrick is open to dropping the effort if the approach isn’t well-received, but the performance motivation remains compelling. The current version is self-contained, with no unresolved external dependencies, though the lack of a range-diff to the reverted version complicates review. No benchmarks have been shared yet, leaving the magnitude of the performance gains unclear. The series touches build system files, wrapper code, and specific call sites in `sideband.c` and `fast-import.c`, but does not change on-disk formats.
