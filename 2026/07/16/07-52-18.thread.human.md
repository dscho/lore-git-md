This thread is about reviving a `writev(3p)`-like wrapper to reduce system call overhead in Git’s low-level I/O operations, specifically for pktline transmission and cat-blob responses. The wrapper was originally merged in Git 2.54 but reverted due to platform compatibility issues (NonStop, CMake); this v1 series from Patrick Steinhardt incorporates fixes for those issues and demonstrates broader applicability.

All technical design and correctness issues have now been resolved. The integer-overflow concern raised by Simon Richter was addressed by Junio C Hamano’s confirmation of existing bounds-checking safety and Patrick’s explicit overflow check. The API name was settled as `git_write_gather()` to avoid implying POSIX semantics, and Johannes Sixt and Junio confirmed that Git’s use cases don’t require atomicity, allowing the wrapper to be implemented as a simple loop of `write(2)` calls. Junio’s latest reply resolves the last design question by treating the naming issue as a documentation problem rather than a technical obstacle.

The series is now technically complete and under review, but two open questions remain: whether the performance gains justify the complexity (maintainer appetite) and the absence of a range-diff to the reverted version, which complicates review. Patrick is at an offsite, so no immediate reroll is expected. No maintainer decision on merge status has been made yet.
