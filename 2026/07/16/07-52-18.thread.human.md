This thread is about reviving a `writev(3p)`-like wrapper in Git to reduce system call overhead in low-level I/O operations, specifically for pktline transmission and cat-blob responses. The series, authored by Patrick Steinhardt, reintroduces the wrapper after it was reverted in Git 2.54 due to platform compatibility issues (NonStop, CMake). Those issues are now fixed, and all technical design questions—including API naming, integer-overflow safety, and atomicity requirements—have been resolved. The wrapper, now named `git_write_gather()`, is implemented as a simple loop of `write(2)` calls, which is sufficient for Git’s single-writer use cases.

The series is technically complete and under review, with no unresolved objections. The latest discussion centers on a minor implementation tweak: Patrick proposes restoring the non-interleaving property of the emulated `writev()` in the compatibility wrapper by writing only the first `iovec` before looping. This would match `write(3p)` behavior and address Johannes Sixt’s concern about future contributors assuming atomicity, while preserving performance gains. Junio C Hamano and Johannes Sixt have already resolved the broader architectural questions, and no new technical objections have been raised. The remaining open questions are whether Junio finds the performance gains justify the complexity and whether Patrick will respin the series to include a range-diff to the reverted version for clarity. Patrick is currently at an offsite, so no immediate reroll is expected.
