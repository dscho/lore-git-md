This thread is about reviving a `writev(3p)`-like wrapper to reduce system call overhead in Git’s low-level I/O operations, specifically for pktline transmission and cat-blob responses. The series, authored by Patrick Steinhardt, reintroduces a wrapper originally merged in Git 2.54 but reverted due to platform compatibility issues (NonStop, CMake). Those issues are now fixed, but the API design, maintainer appetite, and broader I/O abstraction strategy remain under discussion.

The key technical debate has centered on the wrapper’s API and whether it can safely omit POSIX guarantees. Johannes Sixt’s latest review resolves the last major open question: Git’s use cases don’t require atomicity, so the proposed `git_write_gather()` API can be implemented as a simple loop of `write(2)` calls without violating necessary semantics. This aligns with Junio C Hamano’s preference for a Git-specific API that avoids implying POSIX semantics. The integer-overflow concern raised by Simon Richter has also been addressed, with Patrick adding an explicit overflow check for clarity.

The series is still under technical review, with no maintainer decision on merge status. Patrick has conditionally accepted the API rename but remains hesitant about broader I/O abstraction discussions. Junio has redirected architectural questions to Johannes, who has now provided the needed clarity. The next steps are a respin from Patrick (delayed by his offsite) and further discussion on maintainer appetite—whether the performance gains justify the complexity. Benchmark results and a range-diff to the reverted version are still missing, which could help reviewers assess the changes.
