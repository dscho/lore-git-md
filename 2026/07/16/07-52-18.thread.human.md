This thread is about Patrick Steinhardt’s patch series to reintroduce a `writev(3p)`-like wrapper for performance gains in low-level I/O operations, specifically pktline transmission and cat-blob responses. The series, now at v1, revives a feature originally merged in Git 2.54 but reverted due to platform compatibility issues (NonStop, CMake), which have since been addressed.

The core debate has shifted from correctness (an earlier integer-overflow concern was resolved) to API design and maintainer appetite. Junio C Hamano has endorsed Johannes Sixt’s suggestion to rename the wrapper to `git_write_gather()` to avoid implying POSIX semantics, but the broader question of Git’s I/O abstraction strategy remains open. Junio has asked Johannes to clarify which POSIX guarantees the wrapper *doesn’t* need, which would determine whether the API can be implemented as a simple loop of `write(2)` calls or must retain some `writev(2)`-like batching. Patrick Steinhardt has conditionally accepted the rename but remains hesitant to open a larger I/O abstraction discussion at this stage.

The series is still under technical review, with no immediate reroll expected (Patrick is at an offsite). Key open questions include the magnitude of performance gains (benchmarks are still missing), whether the maintainers consider the effort worthwhile, and the lack of a range-diff to the reverted version, which complicates review. No maintainer decision on merge status has been made yet.
