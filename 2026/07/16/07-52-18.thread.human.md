This thread revives a previously reverted performance optimization: a `writev(3p)`-like wrapper to reduce system call overhead in Git’s low-level I/O operations. The series, authored by Patrick Steinhardt, targets pktline transmission and cat-blob responses, aiming to batch multiple `write()` calls into a single system call where possible. After the initial merge in Git 2.54 was reverted due to platform compatibility issues (NonStop, CMake), this version incorporates fixes for those problems and resolves all remaining technical concerns.

Key participants have weighed in with substantive reviews. Simon Richter identified an integer-overflow risk in the wrapper’s bounds-checking logic, which Junio C Hamano later confirmed was already safe due to existing constraints, though Patrick added an explicit overflow check for clarity. Johannes Sixt raised concerns about the API name (`git_writev()`) implying POSIX semantics and the lack of atomicity in the emulation, both of which were addressed by renaming the function to `git_write_gather()` and confirming that Git’s use cases don’t require atomicity. The last technical hurdle—a forward-compatibility worry about future contributors assuming atomicity—was resolved by Junio’s acceptance of Patrick’s proposed tweak: the compatibility wrapper will now write only the first `iovec` in the loop, matching `write(2)`’s non-interleaving behavior and simplifying the code.

With all objections addressed and no open questions remaining, the series is technically complete. Junio’s latest reply describes the implementation tweak as “clever” and notes the code is now both safer and cleaner. The only remaining step is a one-line update to the first patch, after which Junio will decide whether the performance gains justify merging the series. The discussion has been thorough, with no signs of lingering dissent, and the path to integration appears clear.
