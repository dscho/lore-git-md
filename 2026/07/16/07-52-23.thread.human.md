This thread is about a small but targeted performance improvement in `git fast-import`. Patrick Steinhardt sent a 5-patch series to optimize the `cat-blob` response path, which is used by frontends like `git-filter-repo` when they request blob data in bulk. The specific patch in question replaces three separate `write()` calls with a single `writev()` call, cutting syscall overhead. Benchmarks on `linux.git` show a 4% speedup (1.320s → 1.270s) for 100,000 objects, with system time dropping from 0.161s to 0.132s.

The change is confined to `builtin/fast-import.c` and doesn’t affect other Git commands. It uses a helper function (`writev_in_full()`) introduced earlier in the series and includes proper error handling. So far, there’s no review feedback, so the patch is still under initial consideration. If you work with large repositories or use `git-filter-repo`, this is a minor but measurable win once it lands.
