This is the first patch in a two-patch bugfix series for the `wincred` credential helper on Windows. It fixes a memory corruption issue in the `match_cred_password` function that occurs when Git attempts to erase a stored credential via `git credential reject`. The bug causes the helper process to terminate abruptly (status 0xC0000374), masking the failure and leaving the credential stored despite the user's intent to remove it.

The root cause is a miscalculation in buffer allocation and `wcsncpy_s` usage. The `CredentialBlobSize` field is a byte count, but the code incorrectly treated it as a WCHAR count for both allocation and the destination-capacity argument to `wcsncpy_s`. This led to a one-WCHAR overrun when the function appended a terminating NUL. The fix adjusts the allocation to account for the NUL terminator and passes the correct WCHAR-based capacity to `wcsncpy_s`.

The patch touches only six lines in `contrib/credential/wincred/git-credential-wincred.c` and is narrowly scoped to this specific memory safety issue. It references a prior fix (d22a488482) for a similar bug in `get_credential`, indicating this was an overlooked edge case in that earlier work. The commit message provides clear technical context, including the symptom (process termination), the cause (buffer overrun), and the impact (silent credential retention).

This is a well-motivated, low-risk fix for a real bug with no cross-platform implications. The absence of test coverage is typical for `contrib/` code, where testing infrastructure is minimal. The patch is part of a backport from Git for Windows v2.55.0(3), where the issue was originally discovered and fixed. No controversy or open questions are apparent from the submission.
