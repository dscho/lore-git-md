This is the final patch in Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. It implements the drop log (`$GIT_DIR/objects/info/promisor-dropped`) that records every object removed by `--drop-filtered`, enabling better error messages when lazy fetches fail due to prior drops.

The log format is `<oid> <timestamp> <tz> filter=<spec> remote=<name>`, where the remote field currently lists all configured promisor remotes rather than the specific one each object is recoverable from. A NEEDSWORK comment marks this as a temporary limitation pending the `remote-object-info` protocol command (not yet merged). The log is written only on real runs, not dry runs, and the patch adds the necessary plumbing in `repack-promisor.c` (`append_drop_log()`) and wires it into `builtin/repack.c` after the repack completes.

The implementation is straightforward: it walks the `drop_oids` set, formats each entry, and appends it to the log file. Error handling is minimal (warnings on I/O failures), and the log is created with `safe_create_leading_directories()`. The patch does not yet include the safety guards (merge/rebase checks, index validation) or remote verification logic deferred to follow-ups, but it completes the core functionality promised in the RFC. The drop log’s existence is a key enabler for the planned error-message improvements.
