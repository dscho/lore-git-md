This is the sixth patch in a seven-part GSoC feature series adding new path-related keys to the `git repo info` command. The series exposes filesystem locations of repository components (e.g., hooks directory, index file, grafts file) in a scriptable format, avoiding direct access to Git’s internals.

This patch introduces `path.grafts.absolute` and `path.grafts.relative` keys, which return the canonical path to the repository’s grafts file, respecting the `GIT_GRAFT_FILE` environment variable override. The implementation follows the established pattern of the series: it adds two new getter functions (`get_path_grafts_absolute` and `get_path_grafts_relative`) in `builtin/repo.c`, updates the documentation in `Documentation/git-repo.adoc`, and extends the test suite (`t/t1900-repo-info.sh`) to verify both standard behavior and environment variable overrides.

The motivation is clear: external toolchains managing history rewrites or legacy grafts need a clean way to query the grafts file location without resorting to legacy commands like `git rev-parse --git-path info/grafts`. The patch is well-scoped and consistent with the rest of the series, which has already introduced similar keys for other repository components. The commit message and code are straightforward, and the tests cover both the default case and environment variable overrides.

This patch is unlikely to be controversial, though reviewers may check for consistency with existing key naming conventions (e.g., whether `grafts` should be `graft-file` to match `index-file`).
