This is the first patch in Paulius Zaleckas’s v6 series introducing configurable submodule fetch errors. It fixes a long-standing logic flaw in Git’s submodule fetch machinery where phase-1 ref-fetch failures were recorded immediately, even when a subsequent phase-2 OID-based retry could still succeed. The fix ensures errors are only recorded after all retry attempts fail, which is a prerequisite for the configurable policy in the second patch.

The patch restructures `fetch_finish()` to defer error recording: phase-1 failures no longer set the overall result flag if there is a phase-2 retry pending. Instead, the error is recorded only if the phase-2 fetch also fails. The logic also handles edge cases where the submodule was fetched unconditionally (no OID retry) or where all required commits are already present locally (no retry needed). A new helper, `record_fetch_error()`, centralizes error recording and ensures consistent reporting.

The implementation touches only `submodule.c` and adds a comprehensive test in `t/t5526-fetch-submodules.sh`. The test verifies that a failed submodule fetch is still reported even when the gitlinked commits are present locally, covering the pre-existing logic flaw. The commit message is clear and well-structured, explaining the problem, the solution, and the edge cases.

This patch is a clean, narrowly scoped refactoring that addresses a real correctness issue. The test coverage is thorough, and the changes are uncontroversial. It looks ready for `next` once Junio queues the series.
