This is a performance patch targeting the sideband protocol implementation. It is the fourth patch in a five-patch series (subject: "[PATCH 4/5] sideband: use writev(3p) to send pktlines") by Patrick Steinhardt.

The patch replaces two separate `write(3p)` syscalls per pktline (one for the length header, one for the data) with a single `writev(3p)` call that sends both parts in one operation. The motivation is to reduce kernel-level contention under high load, particularly in scenarios where GitLab or other forges serve precomputed packfiles from cache. The commit message includes a synthetic benchmark showing a 1.37× speedup for `git-upload-pack(1)` when the packfile generation overhead is eliminated, and notes that GitLab has observed kernel semaphore saturation in the pipe write path that this change helps mitigate.

The change itself is confined to `sideband.c` and is mechanical: it introduces a two-element `iovec` array, populates it with the header and payload, and calls the newly added `writev_or_die()` helper (presumably introduced in an earlier patch in the series). The patch is well-motivated, includes reproducible benchmarking instructions, and cites real-world production observations, suggesting it addresses a genuine bottleneck. No test failures or edge cases are mentioned, implying the refactoring is straightforward and safe.
