This is a refactoring patch that moves the global `fetch_if_missing` variable into `struct repository`, continuing the ongoing `the_repository` removal effort. The change is part of Git's libification work, making the flag a per-repository setting that controls whether missing objects should trigger lazy fetches from promisor remotes. The default value remains `1` (enabled), preserving existing behavior.

The patch touches 15 files, including core plumbing (`odb.c`, `repository.c`), built-ins (`fetch-pack`, `fsck`, `index-pack`, etc.), and documentation. Most changes are mechanical, replacing the global variable with `the_repository->fetch_if_missing` or `repo->fetch_if_missing`. Special handling is added for `fsck` and `index-pack` to avoid null pointer dereferences during early option parsing, deferring repository operations until after arguments are processed.

Version 2 addresses feedback from Junio C Hamano and Patrick Steinhardt. The critical correctness issue in `setup.c` (hardcoding `the_repository` instead of using the passed `repo` parameter) is fixed, and the patch now retains `the_repository` in `builtin/index-pack.c` and `revision.c` to avoid unintended behavior changes when other repositories are used. The partial clone documentation is updated to reflect the new per-repository nature of the flag.

The patch appears well-structured and aligns with the established pattern of eliminating globals in favor of repository-specific state. While no new tests are added, the changes are straightforward and preserve existing behavior.
