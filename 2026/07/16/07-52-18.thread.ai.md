Subject: [PATCH 0/6] Reintroduce writev(3p) wrapper for performance
Series version: v1 (initial revival)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Reintroduce a `writev(3p)` wrapper to reduce system call overhead in low-level I/O operations, specifically targeting pktline transmission in `sideband.c` and cat-blob responses in `fast-import.c`. The wrapper was originally merged in Git 2.54 but reverted due to platform compatibility issues (NonStop, CMake); this series incorporates fixes for those issues and demonstrates broader applicability.

Current status
Under review; v1 posted. No prior versions in this thread. The series is self-contained, with no unresolved external dependencies.

Key technical details
- Files touched: `Makefile`, `compat/posix.h`, `compat/writev.c`, `wrapper.{c,h}`, `write-or-die.{c,h}`, `sideband.c`, `builtin/fast-import.c`, plus build system files (`config.mak.uname`, `CMakeLists.txt`, `meson.build`).
- New symbols: `git_writev()` and `git_writev_or_die()` wrappers; platform-specific implementations in `compat/writev.c`.
- Behavior change: replaces multiple `write()` calls with batched `writev()` in pktline transmission and cat-blob responses; explicit `MAX_IO_SIZE` handling to avoid partial writes.
- On-disk format: no changes.
- Test coverage: none mentioned; benchmarks referenced but not provided in the email.
- Safety concern: Simon Richter identified a potential integer overflow in the `iov_len` accumulation logic (`iov[i].iov_len + sum > SSIZE_MAX`), which could undermine the wrapper’s bounds-checking.

Open questions and loose ends
- Benchmark results: magnitude of performance gains unspecified.
- Maintainer appetite: Patrick Steinhardt notes openness to dropping the effort if the approach is not desired.
- Platform coverage: NonStop and CMake fixes included; no explicit mention of other niche platforms (e.g., Cygwin, older BSDs).
- Integer overflow fix: the bounds-checking logic in `git_writev()` must be revised to prevent overflow before comparison.
