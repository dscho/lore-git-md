Subject: [PATCH 0/6] Reintroduce writev(3p) wrapper for performance
Series version: v1 (initial revival)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Reintroduce a `writev(3p)`-like wrapper to reduce system call overhead in low-level I/O operations, specifically targeting pktline transmission in `sideband.c` and cat-blob responses in `fast-import.c`. The wrapper was originally merged in Git 2.54 but reverted due to platform compatibility issues (NonStop, CMake); this series incorporates fixes for those issues and demonstrates broader applicability. The goal is performance improvement, but the API design and naming remain points of contention.

Current status
Under review; v1 posted. No prior versions in this thread. The series is self-contained, with no unresolved external dependencies. The integer-overflow concern raised by Simon Richter has been resolved by Junio C Hamano's re-examination of the bounds-checking logic, which confirmed the existing implementation is safe. No maintainer decision on merge status; still in technical review phase, with naming and self-documentation as remaining open questions.

Key technical details
- Files touched: `Makefile`, `compat/posix.h`, `compat/writev.c`, `wrapper.{c,h}`, `write-or-die.{c,h}`, `sideband.c`, `builtin/fast-import.c`, plus build system files (`config.mak.uname`, `CMakeLists.txt`, `meson.build`).
- New symbols: `git_writev()` and `git_writev_or_die()` wrappers; platform-specific implementations in `compat/writev.c`. The naming of these symbols remains contested.
- Behavior change: replaces multiple `write()` calls with batched `writev()`-like operations in pktline transmission and cat-blob responses; explicit `MAX_IO_SIZE` handling to avoid partial writes.
- On-disk format: no changes.
- Test coverage: none mentioned; benchmarks referenced but not provided in the email.
- Safety concerns: The integer-overflow issue in the `iov_len` accumulation logic (`iov[i].iov_len + sum > SSIZE_MAX`) has been resolved. Junio C Hamano confirmed the existing bounds-checking logic is safe because both `sum` and `iov[i].iov_len` are individually constrained to ≤ `SSIZE_MAX`, preventing wrap-around in `size_t`.

Open questions and loose ends
- Benchmark results: magnitude of performance gains unspecified.
- Maintainer appetite: Patrick Steinhardt notes openness to dropping the effort if the approach is not desired.
- Platform coverage: NonStop and CMake fixes included; no explicit mention of other niche platforms (e.g., Cygwin, older BSDs).
- API naming: the proposed `git_writev()` name is contested; `git_write_gather()` is suggested as an alternative to avoid implying POSIX semantics. No resolution yet.
- Patch self-documentation: absence of a range-diff to the reverted version complicates review of changes beyond the NonStop and CMake fixes.
