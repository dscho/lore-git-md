Subject: [PATCH 0/6] Reintroduce writev(3p) wrapper for performance
Series version: v1 (initial revival)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Reintroduce a `writev(3p)`-like wrapper to reduce system call overhead in low-level I/O operations, specifically targeting pktline transmission in `sideband.c` and cat-blob responses in `fast-import.c`. The wrapper was originally merged in Git 2.54 but reverted due to platform compatibility issues (NonStop, CMake); this series incorporates fixes for those issues and demonstrates broader applicability. The goal is performance improvement, with the API design, naming, and broader I/O abstraction strategy now resolved. Maintainer appetite and benchmark results remain open.

Current status
Under review; v1 posted. No prior versions in this thread. The series is self-contained, with no unresolved external dependencies. The integer-overflow concern raised by Simon Richter has been resolved: Junio C Hamano confirmed the existing bounds-checking logic is safe, and Patrick Steinhardt added an explicit overflow check using `unsigned_add_overflows()` for clarity, with negligible performance cost. API naming is resolved in favor of `git_write_gather()` (or similar) to avoid implying POSIX semantics, following Johannes Sixt’s suggestion. The architectural question about I/O abstraction is now resolved: Johannes Sixt confirmed that Git’s pktline and cat-blob use cases do not require atomicity, allowing the `git_write_gather()` API to be implemented as a simple loop of `write(2)` calls without violating necessary semantics. Junio C Hamano has not yet commented on maintainer appetite (whether the series is welcome or the performance gains justify the complexity) or the absence of a range-diff to the reverted version. No maintainer decision on merge status; the series remains in technical review phase pending further input from Junio C Hamano and a respin from Patrick Steinhardt, who is currently at an offsite.

Key technical details
- Files touched: `Makefile`, `compat/posix.h`, `compat/writev.c`, `wrapper.{c,h}`, `write-or-die.{c,h}`, `sideband.c`, `builtin/fast-import.c`, plus build system files (`config.mak.uname`, `CMakeLists.txt`, `meson.build`).
- New symbols: `git_write_gather()` and `git_write_gather_or_die()` wrappers (naming resolved); platform-specific implementations in `compat/writev.c`. The API is a two-level abstraction: a Git-specific API that platforms can implement either via `writev(2)` or as a series of `write(2)` calls, avoiding implied POSIX semantics.
- Behavior change: replaces multiple `write()` calls with batched `writev()`-like operations in pktline transmission and cat-blob responses; explicit `MAX_IO_SIZE` handling to avoid partial writes.
- On-disk format: no changes.
- Test coverage: none mentioned; benchmarks referenced but not provided in the email.
- Safety concerns: The integer-overflow issue in the `iov_len` accumulation logic (`iov[i].iov_len + sum > SSIZE_MAX`) has been resolved. Junio C Hamano confirmed the existing bounds-checking logic is safe because both `sum` and `iov[i].iov_len` are individually constrained to ≤ `SSIZE_MAX`, preventing wrap-around in `size_t`. Patrick Steinhardt added an explicit overflow check using `unsigned_add_overflows()` for clarity, with negligible performance cost.
- Architectural resolution: Johannes Sixt confirmed that Git’s pktline and cat-blob use cases do not require atomicity, allowing the `git_write_gather()` API to be implemented as a simple loop of `write(2)` calls without violating necessary semantics.
