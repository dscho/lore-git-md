This is a platform-compatibility patch, the first in a five-part series from Patrick Steinhardt. It introduces a `writev(3p)` compatibility wrapper for systems that lack the POSIX `writev` syscall—specifically Windows, which is explicitly marked as `NO_WRITEV` in the build system. The wrapper mimics the behavior of `writev` by iterating over the `iovec` array and calling `xwrite` for each segment, while also handling edge cases like integer overflow and partial writes.

The patch touches the build system (Makefile, CMake, Meson) to conditionally compile the wrapper when `NO_WRITEV` is defined, and it adds the necessary headers and type definitions in `compat/posix.h`. The implementation is straightforward and includes safety checks to match the documented behavior of the real `writev` syscall, such as returning `EINVAL` if the total length overflows `ssize_t`.

This is preparatory work for a later patch in the series (not shown here) that will add the first caller to `writev`. The commit message is clear about the motivation, and the patch itself is well-structured, with build-system integration across all supported build tools. No controversy is evident, and the change aligns with Git’s long-standing practice of providing compatibility wrappers for missing POSIX functions. If you care about Windows support or the upcoming feature that will use `writev`, this patch is worth noting.
