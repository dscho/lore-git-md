Core problem or goal
Reintroduce `writev(3p)` support in Git’s wrapper subsystem to fix a platform compatibility issue on systems like NonStop where `MAX_IO_SIZE` is small enough to cause `writev(3p)` to fail with `EINVAL` when passed large iovec entries. The goal is to make Git functional on these platforms by splitting overly large iovec requests into chunks that fit within the platform’s `MAX_IO_SIZE` limit.

Current status
Under review. This is the third patch in a 5-patch series; no prior versions of this series have been recorded in the thread summary. No merge status to any integration branch has been reported.

Key technical details
- Files touched: `wrapper.c`, `wrapper.h`
- New symbols: `xwritev()` (public wrapper function)
- Updated symbols: `writev_in_full()` (now uses `xwritev()`)
- Behavior: `xwritev()` splits large iovec requests into `MAX_IO_SIZE`-compliant chunks, restarts syscalls on `EINTR`/`EAGAIN`, and falls back to `xwrite()` if the first iovec entry itself exceeds the limit
- Edge cases handled: short writes, zero-length writes, syscall restarts
- On-disk format: no changes
- Test coverage: not mentioned in this patch; likely relies on existing test suite
