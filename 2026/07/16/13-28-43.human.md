This is the second patch in Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. It adds a new helper function, `list_objects_filter__filter_oidset()`, to the `list-objects-filter` API.

The helper is designed for callers that already have a set of OIDs and want to know which ones a filter would exclude, without performing a full object walk. This is exactly what `--drop-filtered` needs: it collects promisor blobs into an oidset and then asks which of them exceed the size threshold. Currently, only `blob:limit=N` filters are supported.

The implementation is straightforward but provisional. Instead of reusing the existing filter machinery (which is tied to object traversal), the helper reimplements the blob size check directly. A NEEDSWORK comment marks this duplication, signaling that the helper will be refactored in v2 to reuse the real filter logic. The helper also avoids triggering lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info.

The patch is clean and well-scoped, adding 45 lines to `list-objects-filter.c` and 16 lines to the header. It fits neatly into the series’ goal of building internal APIs before the actual object-dropping logic in patch 7/7. The commit message clearly explains the motivation and the current limitations, making it easy for reviewers to understand why this helper is needed and what work remains.
