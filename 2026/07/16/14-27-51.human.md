This is the second patch in a two-part bugfix series for the `wincred` credential helper on Windows. It addresses a silent credential loss issue when storing OAuth tokens, completing the backport of fixes already validated in Git for Windows v2.55.0(3).

The patch fixes a heap corruption bug in the `store_credential()` function where the code writes one WCHAR past the allocated buffer when formatting OAuth tokens. The root cause mirrors the issue fixed in patch 1/2: the allocation size calculation and `_snwprintf_s()` usage both treat buffer sizes inconsistently (bytes vs WCHAR counts), leading to an out-of-bounds write of the terminating NUL. This triggers heap verification failures on Windows, causing the helper to crash with status `0xC0000374`—though the calling `git credential approve` masks the error, leaving users with the illusion that their credentials were saved when they weren’t.

The fix applies the same pattern used in a prior fix (d22a488482) for a similar bug in `get_credential()`: allocate `(wlen + 1) * sizeof(WCHAR)` bytes and pass `wlen + 1` as the WCHAR count to `_snwprintf_s()`. The change is minimal—just two lines in `contrib/credential/wincred/git-credential-wincred.c`—and carries no risk of cross-platform regressions since the `wincred` helper is Windows-specific.

Like the first patch, this one is well-motivated and clearly explained, though it lacks test coverage (which is typical for `contrib/` code). The commit message effectively describes the symptom (silent credential loss), the mechanism (heap corruption), and the remedy. The series as a whole looks like a straightforward backport of fixes already proven in Git for Windows, and there’s no indication of controversy or open questions. If you care about Windows credential handling, this is worth a quick review; otherwise, it’s safe to assume it will land without drama.
