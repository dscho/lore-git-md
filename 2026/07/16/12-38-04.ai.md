This is the final patch in Patrick Steinhardt’s three-part series removing `the_repository` dependency from `refspec.c`, completing the refactoring begun in patches 1 and 2. The series is part of the ongoing `the_repository` removal effort.

The patch eliminates the last remaining use of `the_hash_algo` in `refspec.c` by modifying the `refspec` struct itself to store the hash algorithm at initialization time. Instead of requiring callers to pass the algorithm each time they append a refspec, the `refspec` struct now holds the algorithm, and `refspec_append()` uses it internally. This change affects 10 files: `builtin/fast-export.c`, `builtin/fetch.c`, `builtin/push.c`, `builtin/send-pack.c`, `builtin/submodule--helper.c`, `http-push.c`, `refspec.c`, `refspec.h`, `remote.c`, and `transport-helper.c`. All callers now initialize their `refspec` structs with `refspec_init_fetch()` or `refspec_init_push()`, passing `the_hash_algo` (or `repo->hash_algo` in `send-pack.c`).

The patch introduces new macros `REFSPEC_INIT_FETCH(algo)` and `REFSPEC_INIT_PUSH(algo)` to replace the old static initializers, and updates the `refspec` struct to include a `hash_algo` field. The `refspec_init_fetch()` and `refspec_init_push()` functions now require an explicit hash algorithm parameter, and `refspec_append()` uses the stored algorithm when parsing new refspec items. The `USE_THE_REPOSITORY_VARIABLE` macro is removed from `refspec.c`, fully decoupling the file from the global repository.

No behavior change is intended, and all callers currently pass `the_hash_algo` (or the equivalent `repo->hash_algo`), so the patch is purely mechanical.
