This is the first patch in a three-patch **feature** series introducing `--auto-reset` to `git bisect`. The patch refactors how `git bisect run` handles its output by reading from an already-open file descriptor instead of reopening the file by name. This is a preparatory change for the `--auto-reset` feature, ensuring the bisect process can reliably capture and replay output without depending on the file's accessibility by path.

The change touches only `builtin/bisect.c`, replacing `print_file_to_stdout()` with `print_fd_to_stdout()`. The new function seeks back to the start of the open descriptor (previously opened with `O_RDWR`) and copies its contents to stdout, avoiding the need to reopen the file. The patch also updates the file open flags to include read access, which is necessary for the new approach.

This refactoring is clean and self-contained, with no behavior change visible to users. The commit message clearly explains the motivation: eliminating the dependency on the file being reachable by name, which is a prerequisite for the later `--auto-reset` functionality. The change is well-scoped and unlikely to introduce regressions, as it only affects the internal mechanics of `bisect run` output handling.

The patch includes no new tests, which is appropriate since it is an internal refactoring with no user-visible impact. Reviewers may focus on whether the new approach handles edge cases (e.g., descriptor errors, seek failures) gracefully, but the implementation appears robust.

This is a solid foundation for the series, setting up the plumbing needed for the `--auto-reset` option in patch 3. The series as a whole targets automated workflows, where eliminating manual cleanup steps is a meaningful improvement.
