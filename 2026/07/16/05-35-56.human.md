This is a feature patch series introducing a `--auto-reset` option for `git bisect`. The three-patch series adds a new flag that automatically resets the bisect state and returns to the original commit once the first bad commit is identified, rather than requiring an explicit `git bisect reset`.

The motivation is straightforward: users often forget to run `git bisect reset` after finishing a bisect session, leaving the repository in a bisect state. This can cause confusion or unintended behavior in subsequent commands. The new option automates this cleanup step, making bisect workflows more convenient and less error-prone.

The implementation touches `bisect.c` and `builtin/bisect.c`, with supporting changes to documentation and tests. The first patch refactors how bisect run output is read to support the new behavior, the second makes `bisect_reset()` optionally quiet, and the third introduces the `--auto-reset` flag itself. The test coverage in `t6030-bisect-porcelain.sh` looks thorough, covering both `git bisect start` and `git bisect run` with the new option.
