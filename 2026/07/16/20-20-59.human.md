This is a refactoring patch in the ongoing `the_repository` removal effort, specifically the second of four in Tian Yuchen’s v6 series migrating `trust_executable_bit` and `has_symlinks` configuration flags to repository-scoped storage. Junio C Hamano raises a performance concern about moving `ce_mode_from_stat()`—currently a `static inline` helper in `read-cache.h`—out of the header and into `read-cache.c`, which would prevent inlining and could impact hot paths.

The patch itself is a mechanical cleanup: relocate the function to the `.c` file to allow future repository-scoped configuration access, remove redundant `extern` declarations, and add a clarifying comment. No behavior changes are introduced, and the commit message explicitly frames it as a prerequisite for later work. Junio’s feedback does not dispute the necessity of the relocation but questions whether the function should remain inline, suggesting it could instead take a `struct repository *` parameter while staying in the header. This is a substantive design point rather than a surface-level nit, as it touches on performance trade-offs in a core index-handling function.

The thread context shows this series is under active review, with v4 already merged to `master` and v6 resolving the last major design objection (the mingw compatibility layer) from v5. This patch has been uncontroversial in prior iterations, but Junio’s comment introduces a new consideration: whether the migration can be achieved without sacrificing inlining. The outcome could set a precedent for how similar helpers are refactored in future `the_repository` work. For now, the patch remains a straightforward cleanup, but the discussion may lead to a v7 iteration if Tian revisits the inlining decision.
