This is the second patch in a two-patch bugfix series for the `wincred` credential helper on Windows, authored by Johannes Schindelin. It addresses a silent credential loss bug when storing OAuth tokens, completing the backport of fixes from Git for Windows v2.55.0(3) to upstream Git.

The patch fixes a heap corruption issue in the `store_credential()` function where the code writes one WCHAR past the allocated buffer when formatting both a password and an `oauth_refresh_token` into a single `CredentialBlob`. The root cause mirrors the bug fixed in patch 1/2: the allocation does not account for the terminating NUL, and `_snwprintf_s()` receives a byte count where it expects a WCHAR count. This causes the helper process to crash with status `0xC0000374`, which `git credential approve` masks, leaving the credential unsaved and the user unexpectedly prompted again.

The fix is minimal and surgical: it adjusts the allocation to `(wlen + 1) * sizeof(WCHAR)` and passes `wlen + 1` as the buffer capacity in WCHARs. The change is confined to four lines in `contrib/credential/wincred/git-credential-wincred.c`, with no new symbols, CLI options, or on-disk format changes. Like the first patch, this is Windows-specific and has no cross-platform impact.

The commit message is clear and technical, referencing the prior fix (d22a488482) for a similar bug in `get_credential()` and linking to the GitHub advisory GHSA-rxqw-wxqg-g7hw. The patch is well-motivated and appears uncontroversial, though as with patch 1/2, there is no test coverage included, which is typical for `contrib/` code.

This patch, together with patch 1/2, closes the two critical bugs identified in the Git for Windows fork. The series is small, focused, and ready for review. No open questions or loose ends are apparent from the submission.
