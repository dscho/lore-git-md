This thread is about a Google Summer of Code contributor’s patch series, now at version 3, that adds seven new path-related keys (`path.toplevel`, `path.superproject-working-tree`, `path.objects`, `path.hooks`, `path.index`, `path.grafts`, and `path.git-prefix`) to the `git repo info` command. The goal is to expose filesystem locations of repository components in a scriptable format, mirroring internal Git struct fields without requiring direct access to Git’s internals.

The series is mechanically clean and free of glaring design issues, with Junio C Hamano explicitly inviting broader technical review. The v3 iteration clarified edge-case behavior for `path.index` and `path.grafts` (both now return paths unconditionally, even in bare repositories or when the file doesn’t exist, aligning with `git rev-parse --git-path` precedent). The design for `path.hooks` follows the same settled approach. However, Junio’s latest review identified a forward-compatibility issue in the first patch: it uses `startup_info->prefix`, a struct member recently removed from `master`. The author will need to rebase the series onto a current `master` and update the implementation to use the replacement mechanism before the series can proceed. No other technical concerns have been raised, and the rest of the series remains unaffected.

Key participants include Junio (who has endorsed the current design for `path.index`, `path.grafts`, and `path.hooks` and encouraged higher-quality review culture) and Lucas Seiki Oshiro (who initially raised edge-case questions but has since provided only surface-level feedback). The series is still under active review, with no merge status reported. The next steps are for the author to address the compatibility issue and for the community to provide substantive technical feedback on the remaining patches.
