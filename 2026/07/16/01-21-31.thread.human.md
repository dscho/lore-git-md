This thread is about a Google Summer of Code contributor’s patch series that adds seven new path-related keys to the `git repo info` command, making it easier for scripts to discover where Git stores its internal files (like the hooks directory, index file, or object database). The series is now in its third version, with all seven patches posted and mechanically clean. The key design question—whether `path.index` and `path.grafts` should return paths even when the files don’t exist or the repository is bare—has been settled: they do, matching the behavior of `git rev-parse --git-path`.

The first patch in this version introduces `path.toplevel.absolute` and `path.toplevel.relative`, which expose the top-level working tree path (the same value as `git rev-parse --show-toplevel`). It’s a straightforward addition, well-tested and documented, and should be uncontroversial. The rest of the series follows the same pattern, exposing other repository paths like the hooks directory, object database, and superproject working tree. Reviewers have raised questions about naming consistency (e.g., `path.objects` vs. `path.objectdir`), but no major technical objections have surfaced yet. The series is still under review, awaiting deeper feedback on its design and implementation.
