This GSoC thread introduces seven new path-related keys to `git repo info`, letting users and scripts query filesystem locations of repository components (e.g., hooks directory, index file, object database, superproject working tree) without poking at Git’s internals. K Jayatheerth’s initial v1 series—all seven patches posted—is under review but hasn’t yet drawn substantive feedback.

Junio C Hamano just chimed in on the final patch, flagging two mechanical nits: an out-of-order `#include` and a misleading commit title that claims “validation” where none exists. Neither touches the patch’s core work—exposing `startup_info->prefix` as `path.git-prefix`—so the fix should be quick. The rest of the series (keys for toplevel, superproject, objects, hooks, index, and grafts) remains uncontroversial and self-contained, with tests covering edge cases like bare repos and environment overrides. No merge status yet; the next step is a v2 addressing Junio’s comments.
