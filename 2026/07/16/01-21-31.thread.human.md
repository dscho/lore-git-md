This thread is about a Google Summer of Code contributor’s patch series, now at version 3, that adds seven new path-related keys (`path.toplevel`, `path.superproject-working-tree`, `path.objects`, `path.hooks`, `path.index`, `path.grafts`, and `path.git-prefix`) to the `git repo info` command. The goal is to expose filesystem locations of repository components in a scriptable format, mirroring internal Git struct fields without requiring direct access to Git’s internals.

The series is mechanically clean and free of glaring design issues, as confirmed by Junio C Hamano, who has explicitly invited substantive technical review from the broader community. The v3 iteration is functionally identical to v2 but includes documentation clarifications for `path.index` and `path.grafts` to explicitly state their behavior in edge cases (e.g., bare repositories or non-existent files). The design for `path.hooks`, `path.index`, and `path.grafts` is settled: all three keys return paths unconditionally, even when the file or directory does not exist or the repository is bare, aligning with `git rev-parse --git-path` precedent. The series remains under review, with no merge status reported.

Key technical details include the implementation of 21 new keys with suffix-based formatting (e.g., `path.toplevel.absolute` and `path.toplevel.relative`), respecting environment/config overrides like `core.hooksPath` and `GIT_OBJECT_DIRECTORY`. The series touches `builtin/repo.c`, `Documentation/git-repo.adoc`, and adds tests in `t/t1900-repo-info.sh`. Open questions remain about key naming consistency (e.g., `path.objectdir` vs. `path.objects`) and whether the broader community will suggest adjustments. The author has shifted focus to another effort while awaiting further feedback, leaving the series in a holding pattern for now.
