This thread is about a Google Summer of Code contributor’s patch series adding seven new path-related keys to `git repo info`, letting users and scripts discover the filesystem locations of Git repository components like the hooks directory, index file, grafts file, and object database. The series is now in its third version, with all seven patches posted and mechanically clean.

The core idea is to expose internal Git paths in a scriptable way, mirroring existing struct fields but avoiding direct access to Git internals. Each key supports absolute and relative path variants, and the design for `path.hooks`, `path.index`, and `path.grafts` has settled on returning paths unconditionally—even in bare repositories or when the file doesn’t exist—so scripts know where to create files, not just read them. This aligns with `git rev-parse --git-path` precedent and is now explicitly documented.

The series awaits substantive technical review of its design and naming choices. Junio Hamano has endorsed the current behavior for `path.grafts` and `path.index`, and the author has addressed all mechanical feedback. Lucas Seiki Oshiro previously suggested returning empty strings in bare repositories for `path.index`, but that position was superseded by the settled design. Open questions remain about key naming consistency (e.g., `path.objectdir` vs. `path.objects`). No merge status has been reported; the series is still under review.
