This thread is about a Google Summer of Code project by K Jayatheerth to add seven new path-discovery keys to the `git repo info` command, exposing filesystem locations of repository components like the hooks directory, index file, and object database in a scriptable format. The series is now in its second version, with all seven patches posted and mechanically clean after Junio C Hamano’s review of the initial submission.

The main design discussion has centered on whether these keys should return empty strings in contexts where the paths don’t apply—like bare repositories—or the actual paths Git would use. This was resolved for `path.grafts` in favor of returning the path unconditionally, matching `git rev-parse --git-path` behavior. The remaining open question was `path.index`: should it return an empty string in bare repositories, where no index file is typically used, or the default `<gitdir>/index` path? Junio has now weighed in decisively, siding with the pragmatic approach of returning the path Git’s internals would use, regardless of repository type. This aligns with the precedent set by `path.grafts` and removes the last behavioral ambiguity before deeper technical review.

The series touches `builtin/repo.c`, adds eighteen new keys with suffix-based formatting (e.g., `path.index.absolute` and `path.index.relative`), and includes tests and documentation. No substantive feedback has yet arrived on the other five patches, but with Junio’s clarification on `path.index`, the design phase appears complete. The next step is likely a v3 patch reflecting this consensus, after which the series will move to broader technical review.
