This thread is about K Jayatheerth’s Google Summer of Code project to add seven new path-related keys (`path.toplevel`, `path.superproject-working-tree`, `path.objects`, `path.hooks`, `path.index`, `path.grafts`, and `path.git-prefix`) to the `git repo info` command. The goal is to expose filesystem locations of repository components in a scriptable format, avoiding direct access to Git’s internals. The series is now in its second version, with all seven patches posted and mechanically clean after addressing Junio’s feedback on patch 7/7.

The main discussion has centered on two behavioral questions. First, whether `path.grafts` should return paths only when the grafts file exists or unconditionally (matching `git rev-parse --git-path`). Junio has now clarified that the current unconditional behavior is intentional and useful, as scripts may need to know where to create the file. Second, whether `path.index` should return an empty string in bare repositories, where no index file is used, rather than a derived path. Lucas Seiki Oshiro suggested this change to avoid misleading scripts, but no decision has been made yet. The rest of the series awaits further technical review.

The implementation touches `builtin/repo.c`, `Documentation/git-repo.adoc`, and adds tests in `t/t1900-repo-info.sh`. The new keys support suffix-based formatting (e.g., `path.toplevel.absolute` vs. `path.toplevel.relative`) and respect environment/config overrides where applicable. The series is under review, with no merge decisions made yet. The author has not yet responded to the substantive feedback on `path.grafts` or `path.index`.
