This thread is about a Google Summer of Code contributor’s patch series adding seven new path-related keys to the `git repo info` command, exposing filesystem locations of repository components (like the hooks directory, index file, or object database) in a scriptable format. The series is now in its second version, with all seven patches posted and mechanically clean after addressing minor feedback on the last patch.

The main discussion has centered on two behavioral design questions. The first—whether `path.grafts` keys should return paths only when the grafts file exists—has been resolved: Junio C Hamano endorsed the current unconditional behavior, aligning it with `git rev-parse --git-path`’s precedent, and the author has agreed. The second question, still open, is whether `path.index` keys should return an empty string in bare repositories (where no index file is used) rather than a derived path, as suggested by reviewer Lucas Seiki Oshiro. The rest of the series awaits further technical review, including feedback on key naming and suffix semantics.

The author has confirmed no changes are needed for the `path.grafts` patch, and the series is otherwise ready for deeper review. No merge decisions have been made yet.
