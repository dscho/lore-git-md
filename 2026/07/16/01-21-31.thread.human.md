This thread is about a Google Summer of Code contributor’s patch series adding seven new path-related keys (`path.toplevel`, `path.superproject-working-tree`, `path.objects`, `path.hooks`, `path.index`, `path.grafts`, and `path.git-prefix`) to the `git repo info` command. The goal is to expose filesystem locations of repository components in a scriptable format, mirroring internal Git struct fields without requiring direct access to Git’s internals. The series is now at version 3, with a fourth iteration in preparation to address mechanical nits and a forward-compatibility issue.

The current version is mechanically clean but blocked on two substantive design questions: whether exposing the object database directory is compatible with pluggable ODB backends (raised by Justin Tobler, with Patrick Steinhardt CC’d for input), and how the `path.hooks` keys should handle the special `/dev/null` value for `core.hooksPath`. The author, K Jayatheerth, has accepted all mechanical feedback from Justin, including removing redundant code and improving test coverage, and has signaled a preference for keeping `/dev/null` handling consistent with `git rev-parse` (returning it verbatim) rather than special-casing it to return an empty string. Junio C Hamano has endorsed the series’ design for `path.index` and `path.grafts`, and the broader community is now invited to weigh in on the remaining open questions.

The series touches `builtin/repo.c`, documentation, and tests, and introduces 21 new keys with suffix-based formatting support (e.g., `path.toplevel.absolute` and `path.toplevel.relative`). The next steps are to resolve the ODB abstraction and `/dev/null` handling questions, rebase onto `master` to address the forward-compatibility issue, and post a v4 update. No merge status has been reported, and the series remains under active review.
