This thread is about a Google Summer of Code contributor’s patch series that adds seven new path-related keys to `git repo info`, exposing filesystem locations of repository components (like the hooks directory, index file, and object database) in a scriptable format. The series is now in its third version, with all seven patches posted and mechanically clean.

The key design decision—returning paths unconditionally, even in bare repositories or when files don’t exist—has been settled for `path.hooks`, `path.index`, and `path.grafts`, aligning with `git rev-parse --git-path` precedent. The latest patch adds `path.git-prefix`, which shows the relative path from the top-level working tree to the current directory, including a trailing slash. The implementation reuses `startup_info->prefix` and is thoroughly tested.

The series is ready for substantive review, with no unresolved technical questions. The remaining discussion is likely to focus on naming consistency (e.g., whether `path.git-prefix` should match `gitdir`/`commondir` terminology). Junio Hamano has endorsed the current design for the three contentious keys, and the author, K Jayatheerth, has addressed all mechanical feedback. The only open question is whether reviewers will suggest stylistic adjustments to key names or suffixes.
