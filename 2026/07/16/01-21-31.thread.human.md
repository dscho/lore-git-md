This thread is about a Google Summer of Code contributor’s patch series adding seven new path-related keys to `git repo info`, exposing filesystem locations of repository components like the hooks directory, index file, and object database. The series is now at version 3, with a fourth iteration in preparation to address a forward-compatibility issue and minor mechanical nits.

The core design is settled for most keys: `path.hooks`, `path.index`, and `path.grafts` return paths unconditionally, even in bare repositories or when the file doesn’t exist, following `git rev-parse --git-path` precedent. Junio Hamano has confirmed the series is mechanically clean and free of glaring design issues, inviting broader technical review. The main blocker is a forward-compatibility issue in the first patch, where the implementation uses `startup_info->prefix`, a struct member recently removed from `master`. The author plans to rebase the series and replace this with the current mechanism.

Justin Tobler’s latest review of the third patch (`path.objects`) raises a substantive question about future compatibility with pluggable ODB backends. He notes that exposing the object directory location may not make sense if the ODB becomes an internal detail of a specific backend, and suggests the keys could return an empty string in such cases. He’s also asked Patrick Steinhardt, the ODB abstraction lead, for input. The series remains under active review, with no merge status reported.
