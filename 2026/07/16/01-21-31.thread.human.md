This thread is about K Jayatheerth’s Google Summer of Code project to add seven new path-related keys (`path.toplevel`, `path.superproject-working-tree`, `path.objects`, `path.hooks`, `path.index`, `path.grafts`, and `path.git-prefix`) to the `git repo info` command. The goal is to expose filesystem locations of repository components in a scriptable format, avoiding direct access to Git’s internals. The series is now at version 2, with all seven patches posted and mechanically clean after addressing Junio C Hamano’s feedback on the initial submission.

The design discussion for `path.grafts` has been resolved—Junio endorsed the current behavior of returning the grafts file path unconditionally, even when the file doesn’t exist, aligning it with `git rev-parse --git-path`. However, the behavior of `path.index` in bare repositories remains unresolved. Lucas Seiki Oshiro suggested returning an empty string in bare repositories (where no index is used) to avoid misleading scripts, while K Jayatheerth is now seeking clarification on whether to follow the series’ existing empty-string convention or make an exception for scripts that might need to know where to *create* an index file. This decision will determine whether patch 5/7 needs adjustment before the series moves forward.

The remaining five patches await substantive technical review, and the outcome of this discussion could influence how other keys handle edge cases. Junio and Lucas are the key participants, with K Jayatheerth actively engaging to resolve the open question.
