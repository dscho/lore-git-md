This thread is about a Google Summer of Code contributor’s patch series adding six new path-related keys to the `git repo info` command, exposing filesystem locations of repository components (e.g., hooks directory, index file, superproject root) in a scriptable format. The series is now in its fourth iteration, with all mechanical issues resolved and the design debate over `path.git-prefix` settled by Junio C Hamano’s intervention. The maintainer rejected objections to `path.git-prefix` and proposed adding `path.cdup` for symmetry; the author has agreed to implement it in the next version.

The current series includes seven patches: six implementing the new keys (`path.toplevel`, `path.superproject-root`, `path.hooks`, `path.index`, `path.grafts`, and `path.git-prefix`) and a seventh refactoring cleanup. The keys support suffix-based formatting (e.g., absolute vs. relative paths) and align with existing Git internals, though `path.objects` was dropped due to concerns about pluggable ODB backends. Junio endorsed the unconditional path-return behavior for `path.index`, `path.grafts`, and `path.hooks`, matching `git rev-parse --git-path` precedent. The series remains under active review, with the next version (v5) expected to add `path.cdup` and expand to eight patches.

Key participants include Junio (maintainer), who confirmed the series is mechanically clean and invited substantive review, and the author, K Jayatheerth, who has addressed all feedback. Reviewers like Lucas Seiki Oshiro and Justin Tobler raised design questions (e.g., `/dev/null` handling, ODB abstraction), most of which are now resolved. The thread’s focus has shifted to implementing `path.cdup`, which will return the relative path from the current directory to the top-level working tree, completing the relative-path key set. No merge status has been reported; the series is still under review.
