The `git repo info` patch series adding seven new path-related keys (`path.toplevel`, `path.superproject-root`, `path.hooks`, `path.index`, `path.grafts`, `path.git-prefix`, and `path.cdup`) is now at version 5, with the author preparing a v6 to address a critical correctness bug. The series aims to expose filesystem locations of repository components in a scriptable format, mirroring internal Git struct fields while avoiding direct access to Git’s internals. Each key supports suffix-based formatting (e.g., absolute vs. relative paths), and the series includes `path.cdup`—the inverse of `path.git-prefix`—to complete the relative-path key set, as requested by Junio C Hamano.

The latest update reveals a correctness bug in the `path.superproject-root` implementation, where `get_superproject_working_tree()` ignores its `repo` parameter and instead uses the process’s current working directory. This breaks behavior when invoked from a submodule’s `.git` directory, causing incorrect results for `path.superproject-root.absolute` and `path.superproject-root.relative`. The author has acknowledged the issue and plans to fix it in v6 by updating the function to respect the `repo` parameter and use the repository’s working directory. The fix is expected to be straightforward, and the test suite already covers the expected behavior. This bug is the primary blocker for the series; once resolved, the series will be ready for further substantive review.

Junio C Hamano has raised an architectural concern about shared logic between `git repo info` and `git rev-parse`, proposing a follow-up refactoring to consolidate this logic into a helper library (`repo-info.c`). The author has countered with a two-phase plan: merge the current series first, then address the refactoring in a separate effort. Junio’s preference for avoiding technical debt may lead to further iteration, but the correctness bug takes precedence. Other open questions include minor adjustments to key naming and suffix semantics, though these are uncontroversial. The series remains under active review, with no merge status reported. Key participants include Junio (maintainer), K Jayatheerth (author), and reviewers like SZEDER Gábor, Lucas Seiki Oshiro, and Justin Tobler, who have contributed to mechanical and design feedback.
