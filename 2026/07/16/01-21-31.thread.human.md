This thread is about a Google Summer of Code project to extend `git repo info` with seven new path-related keys (`path.toplevel`, `path.superproject-root`, `path.hooks`, `path.index`, `path.grafts`, `path.git-prefix`, and `path.cdup`). The series is now in its fifth version, submitted by K Jayatheerth, and is feature-complete and mechanically clean after a rebase resolved an earlier build issue.

The core goal is to expose filesystem locations of repository components in a scriptable format, avoiding direct access to Git’s internals. The new keys support suffix-based formatting (e.g., absolute vs. relative paths) and include `path.cdup`—the inverse of `path.git-prefix`—to address prior design feedback. The series has been well-received for its alignment with `git rev-parse` precedent, but Junio C Hamano recently raised a substantive architectural concern: the new keys duplicate logic already present in `git rev-parse`, risking long-term maintainability issues. He proposed consolidating this shared logic into a new helper library (e.g., `repo-info.c`).

Jayatheerth responded with a pragmatic two-phase plan: queue the current series as-is (since earlier path keys are already merged) and follow up with a dedicated refactoring series to extract the shared logic incrementally. This approach keeps the feature addition separate from the architectural cleanup, though it defers the latter to a later effort. The thread remains under active review, with the architectural concern now the primary focus. No merge status has been reported, and the series is still cooking in Junio’s integration branches. The outcome will likely hinge on whether Junio accepts the two-phase approach or insists on addressing the duplication before merging.
