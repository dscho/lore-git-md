This is a refactoring patch (v3) targeting the UTF-8 string-width calculation functions in `utf8.c`/`utf8.h`. The patch changes the return type of `utf8_strwidth()` and `utf8_strnwidth()` from `int` to `size_t` to better reflect that their results are inherently non-negative, and updates all callers to use `size_t` for local variables. However, **v3 reintroduces explicit casts to `int` at nearly every call site**, preserving the original implicit conversions and undermining the patch’s stated goal of type consistency. This version resolves compilation warnings from v2 but does not address the deeper regressions identified by Junio C Hamano and Pablo Sabater, including mixed-sign comparisons, underflow risks, and struct field mismatches.

The patch touches 11 files: `utf8.c`, `utf8.h`, and nine callers (`builtin/blame.c`, `builtin/fetch.c`, `builtin/repo.c`, `column.c`, `diff.c`, `gettext.c`, `gettext.h`, `pretty.c`, and `wt-status.c`). Key changes include updating function signatures to return `size_t`, removing the `cast_size_t_to_int()` helper, and promoting local variables in callers to `size_t`. However, **the patch immediately casts these results back to `int` when used in arithmetic or comparisons**, reintroducing the very conversions it aims to eliminate. For example, in `diff.c`, `padding = len - cast_size_t_to_int(utf8_strwidth(name))` remains unsafe, and `len -= 3` (now `size_t`) could underflow if `len < 3`.

Hardik’s approach prioritizes minimal disruption over type safety. Instead of refactoring callers to use `size_t` consistently (e.g., promoting struct fields in `builtin/repo.c` or eliminating mixed-sign comparisons), he adds casts to `int` at every call site, preserving the original behavior. This sidesteps immediate regressions but fails to deliver meaningful type-system improvements. The patch also removes the overflow check in `cast_size_t_to_int()` without justification, despite Pablo Sabater’s prior concern that some callers might rely on it.
