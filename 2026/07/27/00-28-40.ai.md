This is the third patch in Ted Nyman’s v6 series fixing race conditions in Git’s HTTP packfile downloads. It specifically addresses HTTP 416 ("Requested Range Not Satisfiable") responses that occur when a resumed pack request is already complete—typically because a previous attempt finished the transfer but failed before indexing it.

The patch modifies three HTTP transport callers (`http-fetch.c`, `http-push.c`, and `http-walker.c`) to treat HTTP 416 as a non-failure status, allowing `index-pack` to validate the already-complete staging file. This is a narrow behavioral change: the code now accepts HTTP 416 alongside the existing `CURLE_OK` success case, deferring to `index-pack` for final validation. The implementation is minimal—just three one-line conditionals—and does not introduce new symbols or alter on-disk formats.

A new regression test in `t/t5550-http-fetch-dumb.sh` verifies the fix by seeding a complete partial pack, confirming the server returns HTTP 416, and checking that `http-fetch` successfully indexes the file. The test uses the existing Perl HTTP server and leaves no temporary files behind, matching the series’ broader test design.

This patch directly addresses one of Peff’s post-acceptance advisory points from v5: HTTP 416 handling for completed partial packs. The change is uncontroversial and aligns with the series’ goal of preserving resumable downloads while preventing corruption. No open questions remain, and the patch is ready for review as part of the broader v6 series.
