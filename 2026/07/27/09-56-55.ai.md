This is the first patch in a **test infrastructure** series (v2, 2/2) that introduces the `commit_body()` helper to the Git test suite. The patch adds the helper function to `t/test-lib-functions.sh` and documents it in `t/README` with a usage example (`commit_body HEAD >actual`). The implementation writes the commit object to a temporary file (`.commit`), strips the header with `sed -e "1,/^$/d"`, and cleans up, ensuring exit codes propagate correctly—unlike the ~60 existing instances of the pattern `git cat-file commit <rev> | sed ...`, which mask failures in the pipeline.

The motivation is clear: eliminating duplicated code while fixing an exit-code hole noted in a prior bugfix (commit `b6b276974e`). The helper is well-scoped, with no user-visible impact—it’s purely internal test suite plumbing. The documentation is concise and includes a practical example, and the implementation avoids common pitfalls (e.g., pipeline masking) by design. This patch sets the stage for the second patch, which converts all existing call sites to use the new helper.

Key technical details for follow-up discussion:
- **Function name**: `commit_body()`
- **Temporary file**: `.commit`
- **Files touched**: `t/test-lib-functions.sh`, `t/README`
- **Related prior work**: commit `b6b276974e` (motivating bugfix)
- **Behavior change**: exit codes now propagate correctly; no output differences.
