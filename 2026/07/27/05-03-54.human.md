This is a feature patch adding a built-in userdiff driver for Swift, now receiving a surface-level review. Michael Montalbo asks whether the patch should include a test in `t/t4034-diff-words.sh`, the test script that verifies word-level diff behavior for built-in language drivers. The question is procedural rather than technical: other language drivers (like C, Java, and Rust) include such tests, so Swift might be expected to follow suit for consistency.

The patch itself is already fully reviewed and technically complete, with Junio C Hamano promoting it to `next` and Johannes Sixt explicitly acking the v2 revision. The author, Shlok Kulshreshtha, has provided thorough test coverage in `t/t4018/` (13 Swift-specific test fixtures) and strong empirical validation of the regex patterns against real-world Swift code. The only remaining step before graduation to `master` is a brief waiting period for feedback from Swift users on the mailing list.

Michael’s suggestion is a minor completeness check rather than a blocker. The patch does not currently include a `t/t4034-diff-words.sh` test, but adding one would be a straightforward follow-up if the author or another contributor chooses to do so. The absence of such a test does not affect the correctness or functionality of the Swift driver, which is already well-tested for hunk header generation and word boundary detection. If the author responds positively, this could become a trivial v3 patch; otherwise, it may remain an optional follow-up. Either way, the patch is on track for integration.
