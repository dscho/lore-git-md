This thread is a straightforward bugfix for the pack-bitmap subsystem, authored by David Lin. The issue is an off-by-one edge case in `find_objects()` where objects at position zero in the base bitmap were incorrectly excluded, leading to redundant work (reloading reachability bitmaps or adding objects to the not-mapped list). The fix is minimal: changing a conditional check from `pos > 0` to `pos >= 0` in `pack-bitmap.c`.

The patch has been through two iterations. The first version (`v1`) included a test for pseudo-merge scenarios, and Taylor Blau’s substantive review confirmed the fix’s correctness while suggesting two improvements: a surface-level commit message tweak and a substantive test addition for non-pseudo-merge cases. Both were addressed in `v2`, which now covers both pseudo-merge and non-pseudo-merge scenarios (e.g., `git rev-list --objects --use-bitmap-index HEAD HEAD`). The patch is ready for integration, with no open questions or loose ends. The regression was introduced in commit 11d45a6e6a, and the fix is uncontroversial.
