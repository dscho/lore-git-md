This thread is a focused bugfix for the pack-bitmap subsystem, submitted by David Lin. The issue is an off-by-one edge case where objects at position zero in the base bitmap were incorrectly excluded from being recognized as already represented, leading to redundant work like bitmap reloads or additions to the not-mapped list. The fix itself is minimal—changing a single conditional check in `find_objects()` from `pos > 0` to `pos >= 0`—and has been confirmed as correct by Taylor Blau, who provided a substantive review.

The patch is now in its second iteration (`v2`), which incorporates Taylor’s feedback. While the core fix remains unchanged, the commit message and code comment have been clarified to better explain the nature of the redundant work avoided. More importantly, `v2` adds a new test case covering non-pseudo-merge scenarios, addressing the only remaining gap identified in the review. The test verifies that objects at position zero are correctly recognized after stored bitmaps, even outside the pseudo-merge context, using `git rev-list --objects --use-bitmap-index HEAD HEAD`.

The patch touches `pack-bitmap.c` and the test file `t/t5333-pseudo-merge-bitmaps.sh`, with no changes to the resulting object set—only the elimination of redundant internal work. There are no unresolved technical concerns, and the patch appears ready for integration. It fixes a regression introduced in commit 11d45a6e6a and has no dependencies on other in-flight topics.
