This is a documentation patch that closes out the UTF-8 string-width refactoring thread. Hardik Kumar replaces the old `//TODO` comment in `utf8.c` with a concise rationale explaining why `utf8_strwidth()` and `utf8_strnwidth()` continue to return `int` instead of `size_t`. The new comment notes that callers expect a signed value for padding and `printf()` compatibility, so the explicit cast to `int` remains necessary. This patch is the final, agreed-upon resolution after three earlier refactoring attempts were withdrawn due to reviewer opposition. It touches only one file (`utf8.c`) and makes no code changes—just documentation. The patch is small, well-explained, and uncontroversial.
