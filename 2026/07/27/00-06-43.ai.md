This is a substantive review of Hardik Kumar's refactoring patch (v2) that changes the return type of UTF-8 string-width functions from `int` to `size_t`. Junio C Hamano identifies multiple bugs introduced by the patch due to unsigned integer underflow and incorrect mixed-sign comparisons, demonstrating that the change is not as straightforward as a simple type-system cleanup.

The review highlights two concrete examples where the patch breaks existing logic. In `diff.c`, the safeguard `if (len < 0)` becomes ineffective because `len` is now `size_t` (unsigned), allowing it to wrap around to a large value when decremented below zero. In `pretty.c`, a negative `padding` value (now possible due to unsigned `occupied`) causes incorrect behavior in later comparisons, preventing the intended "steal spaces" logic from working. Junio notes that these bugs appear in code not directly shown in the patch, making the review process difficult and error-prone.

The patch is part of an ongoing effort to address a `//TODO` comment and improve type safety, but the v2 iteration fails to account for the subtle interactions between signed and unsigned arithmetic in the callers. While the goal is reasonable, the implementation introduces regressions that would likely go unnoticed without careful review. Junio’s feedback suggests the patch needs significant rework before it can be considered for merging.
