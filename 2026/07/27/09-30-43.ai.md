This is a bug report for a crash in `git cat-file --batch-command`. The author, Alan Stokes, reproduces an assertion failure in `print_object_or_die()` at `builtin/cat-file.c:387` when using `--batch-command` with a format string that does not include `%(objecttype)`. The crash occurs specifically when requesting `contents` for an object but omitting the type from the output format.

The reproduction steps are minimal: initialize a repository, create a blob, and then run `echo contents <blob-hash> | git cat-file --batch-command="%(objectsize)"`. The command succeeds if `%(objecttype)` is included in the format string or if `--batch` is used instead of `--batch-command`. The author hypothesizes that `--batch-command` does not fetch the object type metadata unless explicitly requested, leading to a NULL dereference in `print_object_or_die()`.

The report includes system details (Git 2.54.0, Linux, SHA-1 default) and notes the issue has persisted since at least Git 2.43.0. The author suggests two potential fixes: always fetching the type metadata for `--batch-command`, or doing so only when a `contents` command is issued. The crash is deterministic and affects a core plumbing command, making it a serious correctness issue. No prior discussion or patches are referenced in the email.
