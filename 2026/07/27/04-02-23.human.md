This is a refactoring patch that changes the return type of UTF-8 string-width functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t`. The goal is to address a `//TODO` comment and improve type safety by using an unsigned type for inherently non-negative display widths. The patch is now in its second iteration (v2), which updates all callers to use `size_t` explicitly, eliminating implicit conversions.

However, Junio C Hamano’s review identifies significant regressions introduced by this change. The patch breaks existing logic in `diff.c` and `pretty.c` due to unsigned integer underflow and incorrect mixed-sign comparisons. For example, in `diff.c`, the safeguard `if (len < 0)` becomes ineffective because `len` is now `size_t` (unsigned), allowing it to wrap around to a large value when decremented below zero. Similarly, in `pretty.c`, negative `padding` values (now possible due to unsigned `occupied`) cause incorrect behavior in later comparisons, breaking the intended "steal spaces" logic.

The patch’s expected benefit is low in practice, as Junio notes that these functions are only used for measuring display widths of strings that fit on a single line—far below the limits of `int`. The cost, however, is high: the change introduces subtle bugs that require careful coding and review to avoid. Junio suggests that the effort to clear the `//TODO` may not be worth the risk, especially if it means reintroducing the "safe cast" protection that was removed in this patch.

The patch is not ready for `next` and will need a v3 to address the regressions. The thread remains open, with the unresolved question of whether the overflow check should be reintroduced or if the patch should be abandoned altogether. For now, this is a cautionary example of how even well-intentioned refactoring can introduce unexpected issues.
