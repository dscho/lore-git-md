This is the second patch in Jeff King’s two-patch refactoring series that follows up on his recently merged bugfix for the `git diff --relative --cached` segfault. The patch itself is a small, targeted refactoring in `diff-lib.c` that moves the `--relative` prefix check earlier in `oneway_diff()`, eliminating redundant work for paths outside the prefix. The change is uncontroversial and approved by Junio, but this email adds a new detail: Peff notes a Coverity static-analysis warning about a potential NULL dereference in the newly added code.

The warning is a false positive, as Peff explains: the code only dereferences `tree` when `idx` is NULL, and in that case `tree` cannot be NULL because it would imply an impossible state (a deletion with no prior entry). He suggests a `BUG()` assertion to clarify the invariant for static analyzers, but is unsure whether it would help human readers. The discussion is purely about code clarity and tooling, not about correctness or behavior. No action is required from Junio or other reviewers, and the patch remains ready for integration.

Key technical identifiers for follow-up: the warning pertains to the `oneway_diff()` function in `diff-lib.c`, specifically the relationship between the `idx` and `tree` parameters. The proposed `BUG()` assertion would target the same code path, reinforcing the invariant that at least one of `idx` or `tree` must be non-NULL. This detail is unlikely to generate further discussion, but if it does, the focus will be on whether to add the assertion for tooling clarity.
