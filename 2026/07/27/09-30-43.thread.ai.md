Subject: `git cat-file --batch-command` assertion failure when omitting `%(objecttype)`
Series version: none (bug report)

Core problem or goal
`git cat-file --batch-command` crashes with an assertion failure in `print_object_or_die()` when the output format string does not include `%(objecttype)` and the `contents` command is issued. The crash is deterministic, affects a core plumbing command, and has existed since at least Git 2.43.0.

Current status
**Patch submitted and ready for review.** Jeff King (Peff) has submitted the formal patch that implements the targeted fix (save/restore `data->info.typep` around the `contents` command) and adds test coverage in `t1006-cat-file.sh`. The patch is minimal, preserves performance for `info` commands, and aligns with prior feedback from Alan Stokes and Pablo Sabater. No objections or open questions remain; the thread is now in the review phase for inclusion in `next`.

Key technical details
- **File**: `builtin/cat-file.c`, line 387 (`print_object_or_die()`)
- **Subsystem**: `cat-file` plumbing, `--batch-command` mode
- **New/renamed symbols**: none
- **Behavior**: assertion failure (NULL dereference) when `contents` is requested without `%(objecttype)` in the format string
- **Fix**: save/restore `data->info.typep` around the `contents` command to avoid NULL dereference while preserving performance
- **Workaround**: include `%(objecttype)` in the format string or use `--batch` instead of `--batch-command`
- **Test coverage**: new test in `t1006-cat-file.sh` verifies the crash is resolved and output matches `--batch` mode
- **Performance**: the fix avoids over-fetching type metadata for subsequent `info` commands
