Core problem or goal
`git cat-file --batch-command` crashes with an assertion failure in `print_object_or_die()` when the output format string does not include `%(objecttype)` and the `contents` command is issued. The crash is deterministic, affects a core plumbing command, and has existed since at least Git 2.43.0.

Current status
Under review. A tested fix is now available: Pablo Sabater has implemented Jeff King’s suggested targeted fix (save/restore `data->info.typep` around the `contents` command) to avoid performance regressions. The patch is minimal, addresses the performance concern, and has been confirmed to work. No formal patch submission yet; the next step is to add test coverage in `t1006-cat-file.sh`.

Key technical details
- File: `builtin/cat-file.c`, line 387 (`print_object_or_die()`)
- Subsystem: `cat-file` plumbing, `--batch-command` mode
- New/renamed symbols: none
- Behavior: assertion failure (NULL dereference) when `contents` is requested without `%(objecttype)` in the format string
- Workaround: include `%(objecttype)` in the format string or use `--batch` instead of `--batch-command`
- Performance consideration: the targeted fix avoids over-fetching type metadata for subsequent `info` commands, preserving performance for lightweight requests
- Test coverage: none yet; reproduction steps provided in the report; target test file: `t1006-cat-file.sh`
