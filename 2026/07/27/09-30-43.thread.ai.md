Core problem or goal
`git cat-file --batch-command` crashes with an assertion failure in `print_object_or_die()` when the output format string does not include `%(objecttype)` and the `contents` command is issued. The crash is deterministic, affects a core plumbing command, and has existed since at least Git 2.43.0.

Current status
**Queued for `next`.** Junio C Hamano has explicitly marked the topic for `next` in his reply, indicating it is ready for integration testing. The patch, authored by Jeff King (Peff), is uncontroversial, includes test coverage, and resolves the crash without regressing performance. No objections or open questions remain.

Key technical details
- **File**: `builtin/cat-file.c`, line 387 (`print_object_or_die()`)
- **Subsystem**: `cat-file` plumbing, `--batch-command` mode
- **New/renamed symbols**: none
- **Behavior**: assertion failure (NULL dereference) when `contents` is requested without `%(objecttype)` in the format string
- **Fix**: save/restore `data->info.typep` around the `contents` command to avoid NULL dereference while preserving performance for `info` commands
- **Workaround**: no longer necessary; the fix resolves the crash
- **Test coverage**: new test in `t1006-cat-file.sh` verifies the crash is resolved and output matches `--batch` mode
- **Performance**: the fix avoids over-fetching type metadata for subsequent `info` commands
