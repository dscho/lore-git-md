This is the fifth patch in Ted Nyman’s six-part v6 series fixing race conditions in Git’s HTTP transport during concurrent packfile downloads. It addresses a Windows-specific issue: MinGW’s non-append `O_RDWR` open only grants `FILE_SHARE_DELETE` (allowing another process to unlink the file) if the file already exists. When creating a new partial pack, the initial `O_CREAT` open lacks this sharing mode, preventing other downloaders from cleaning up the staging path.

The fix is a retry loop: first try opening the file without `O_CREAT`; if it doesn’t exist, create it exclusively, close it, and retry the open. This ensures every retained descriptor permits unlinking. The patch also adds a new test that verifies a packfile can be unlinked while `index-pack` is running, using a custom `index-pack` wrapper to remove the staging file before indexing. The test is MinGW-compatible and doesn’t rely on FIFOs.

The change is narrowly scoped to `http.c` and the test suite, with no impact on other platforms or subsystems. The implementation is clean and well-motivated, addressing a real portability gap without complicating the core logic. The test coverage is thorough and platform-agnostic. This patch, along with the rest of the series, looks ready for `next`.
