This is a refactoring patch (v3) that changes the return type of UTF-8 string-width calculation functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t` to better reflect that their results are inherently non-negative. The patch updates the function signatures in `utf8.c` and `utf8.h`, removes the now-unnecessary `cast_size_t_to_int()` helper, and adjusts all callers to use `size_t` for local variables holding the return value. However, **v3 reintroduces explicit casts to `int` at nearly every call site** (via `cast_size_t_to_int()`), effectively preserving the original implicit conversions and undermining the patch’s stated goal of type consistency.

The patch touches 11 files: `utf8.c`, `utf8.h`, and nine callers (`builtin/blame.c`, `builtin/fetch.c`, `builtin/repo.c`, `column.c`, `diff.c`, `gettext.c`, `gettext.h`, `pretty.c`, and `wt-status.c`). Key changes include:
- Function signatures: `utf8_strwidth()` and `utf8_strnwidth()` now return `size_t`.
- `gettext_width()` is also updated to return `size_t` (with conditional compilation fixes for `NO_GETTEXT`).
- Caller-side variables (e.g., `len`, `padding`, `num`) are updated to `size_t`, but their results are immediately cast back to `int` when used in arithmetic or comparisons with `int` variables.
- The `maxwidth()` helper in `wt-status.c` is updated to return `size_t`, but its callers still expect `int`-compatible values.

**Regressions and unresolved issues**:
1. **Mixed-sign comparisons**: The patch does not address the core problem of comparing `size_t` results with `int` variables (e.g., `padding = len - cast_size_t_to_int(utf8_strwidth(name))` in `diff.c`). These comparisons remain unsafe and could trigger `-Wsign-compare` warnings or subtle bugs.
2. **Underflow risks**: In `diff.c`, `len -= 3` (now `size_t`) could underflow if `len < 3`, and `padding = len - cast_size_t_to_int(...)` could produce incorrect results if `utf8_strwidth()` returns a value larger than `len`.
3. **Struct field mismatches**: In `builtin/repo.c`, `stats_table` struct fields (`name_col_width`, `value_col_width`) remain `int`, forcing casts that reintroduce implicit conversions.
4. **Conditional compilation**: The `gettext.h` update is correct, but the patch does not address whether `NO_GETTEXT` builds were tested.
5. **Overflow check removal**: The patch removes the overflow check in `cast_size_t_to_int()` without justification, despite prior reviewer concerns that some callers might rely on it.

**Author’s approach**: Hardik’s v3 prioritizes minimal disruption over type safety. Instead of promoting struct fields or refactoring callers to use `size_t` consistently, he adds casts to `int` at every call site, preserving the original behavior but reintroducing the very conversions the patch aims to eliminate. This approach sidesteps regressions but fails to deliver the promised type-system improvements.
