This is the fifth patch in Ted Nyman’s v6 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI downloads. It addresses a Windows-specific file-sharing requirement: open files must explicitly permit `FILE_SHARE_DELETE` before another process can unlink them. The patch ensures that every retained file descriptor allows unlinking by retrying the open call without `O_CREAT` after an exclusive creation attempt, enabling deterministic staging paths to work correctly on Windows.

The change is narrowly scoped to `http.c` and adds a new test in `t/t5550-http-fetch-dumb.sh` that verifies unlinking works while indexing, replacing the FIFO-based test that could not run on MinGW. The implementation loops until it either opens an existing file or successfully creates, closes, and reopens a new one, handling `EEXIST` races from concurrent creators. This preserves the core fix’s resumable-download guarantee while satisfying Windows sharing semantics.

The patch is well-motivated and directly addresses Peff’s advisory feedback about Windows compatibility. The test coverage is thorough, and the code is cleanly separated from the generic concurrent-download logic in patch 4. No new symbols are introduced, and the change is platform-specific, so it should not affect non-Windows systems. The series remains under review but is technically complete and ready for integration.
