This thread is about a bug in `git cat-file --batch-command` that causes an assertion failure when the output format string omits `%(objecttype)` and the `contents` command is issued. The crash has been present since at least Git 2.43.0 and affects a core plumbing command.

The fix is now settled: Pablo Sabater implemented Jeff King’s suggested solution—saving and restoring `data->info.typep` around the `contents` command—to avoid performance regressions while resolving the crash. Alan Stokes confirmed the fix is correct and simple, though he won’t be submitting the formal patch due to time constraints. The next step is for someone (likely Pablo or another volunteer) to submit the patch with test coverage in `t1006-cat-file.sh`. Once that’s done, the fix should be uncontroversial and ready for integration.

No maintainer feedback has arrived yet, and the thread is effectively in a holding pattern until the formal patch is submitted. The workaround remains to include `%(objecttype)` in the format string or use `--batch` instead of `--batch-command`.
