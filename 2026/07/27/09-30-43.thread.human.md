This thread is about a bug in `git cat-file --batch-command` that causes a crash when the `contents` command is used without including `%(objecttype)` in the output format. The issue, present since at least Git 2.43.0, was reported by Alan Stokes and confirmed by Jeff King (Peff), who subsequently submitted a minimal fix.

Peff’s patch, which temporarily saves and restores `data->info.typep` around the `contents` command, has been reviewed and is now ready for integration. The fix avoids a NULL dereference while preserving performance for subsequent `info` commands, and it includes test coverage in `t1006-cat-file.sh` to verify the crash is resolved. Junio C Hamano has queued the patch for the `next` branch, meaning it will undergo integration testing before graduating to `master`. No objections or open questions remain, and the workaround of including `%(objecttype)` or using `--batch` is no longer necessary. The thread is effectively closed, with the fix on track for inclusion in the next Git release.
