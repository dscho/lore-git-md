This thread is a bug report from Alan Stokes about a crash in `git cat-file --batch-command`. The issue is an assertion failure in `print_object_or_die()` when using `--batch-command` with a format string that omits `%(objecttype)` but requests object contents. The crash is reproducible with minimal steps: create a blob and run `echo contents <blob-hash> | git cat-file --batch-command="%(objectsize)"`. The command works fine if `%(objecttype)` is included or if `--batch` is used instead.

Alan hypothesizes that `--batch-command` doesn’t fetch object type metadata unless explicitly requested, leading to a NULL dereference. The bug has existed since at least Git 2.43.0 and affects a core plumbing command, making it a serious correctness issue. No prior discussion or patches are mentioned, and no responses have been posted yet. The thread is currently just the initial report with reproduction details and a suggested fix direction (either always fetching type metadata or doing so conditionally for `contents` commands).
