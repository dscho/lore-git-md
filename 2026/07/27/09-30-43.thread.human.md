This thread is about a bug in `git cat-file --batch-command` that causes an assertion failure when the output format string omits `%(objecttype)` and the `contents` command is issued. The issue, reported by Alan Stokes, affects a core Git plumbing command and has been present since at least Git 2.43.0.

Jeff King (Peff) confirmed the bug and suggested a targeted fix to avoid a performance regression: saving and restoring `data->info.typep` around the `contents` command rather than always fetching type metadata. Pablo Sabater has now provided a tested implementation of this fix, which resolves the crash while preserving performance for `info` requests. The patch is minimal and addresses the core issue without introducing side effects.

The discussion is now focused on finalizing the fix. The next step is to submit a formal patch with test coverage in `t1006-cat-file.sh`. Given the lack of controversy and the clear scope of the fix, this patch is likely to be uncontroversial and ready for Junio’s `next` branch once tests are added. No maintainer feedback has been received yet, but the technical direction is settled.
