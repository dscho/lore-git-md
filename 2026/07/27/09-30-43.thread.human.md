This thread is a bug report about a crash in `git cat-file --batch-command` when the `contents` command is used without `%(objecttype)` in the format string. The issue, confirmed by Jeff King (Peff), is a NULL dereference in `print_object_or_die()` in `builtin/cat-file.c`, affecting Git versions since at least 2.43.0.

Peff has identified the root cause: the `--batch-command` code path fails to fetch object type metadata when `contents` is requested, unlike `--batch`, which always includes it. He provided a minimal fix but noted a performance trade-off—enabling type-checking for all subsequent commands, not just `contents`. The preferred solution, he suggests, is to save and restore `data->info.typep` around the `contents` command to avoid unnecessary fetches. The discussion is now focused on implementing this fix, with Peff encouraging Alan Stokes to submit a patch including test coverage in `t1006-cat-file.sh`.

No maintainer feedback or alternative approaches have been raised yet, and the thread remains in the patch-proposal stage. The workaround for users is to include `%(objecttype)` in the format string or use `--batch` instead of `--batch-command`.
