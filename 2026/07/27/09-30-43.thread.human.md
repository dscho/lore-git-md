This thread began when Alan Stokes reported a deterministic assertion failure in `git cat-file --batch-command` when the output format omits `%(objecttype)` and the `contents` command is issued. The crash, present since at least Git 2.43.0, affects a core plumbing command and was quickly diagnosed as a NULL dereference in `print_object_or_die()`.

The technical solution was settled early: Jeff King (Peff) proposed a targeted fix—saving and restoring `data->info.typep` around the `contents` command—to avoid performance regressions for subsequent `info` calls. Pablo Sabater implemented and tested this approach, confirming it resolved the crash without side effects. Alan Stokes, the original reporter, declined to submit the formal patch, leaving the thread in a holding pattern until someone stepped in.

That step has now been taken. Peff has submitted a formal patch that implements the agreed fix and adds a test in `t1006-cat-file.sh` to verify the crash no longer occurs and that output matches `--batch` mode. The patch is minimal, touching only `builtin/cat-file.c` and the test suite, and preserves the performance characteristics of the original design. With the solution now implemented and tested, the thread is effectively complete and the patch should be ready for `next` once reviewed. No further discussion or objections are expected.
