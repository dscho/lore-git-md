This is the second patch in Ted Nyman’s v6 series fixing packfile URI race conditions in Git’s HTTP transport. It addresses a latent double-close bug in `finish_http_pack_request()` where the staging-file descriptor is redundantly closed after `start_command()` already takes ownership of it. The fix is a one-line change: removing the manual `close(tmpfile_fd)` call, which prevents a potential double-close when `run_command()` fails.

The patch is a targeted bugfix with no behavior change—it only removes a redundant operation that could cause issues if the descriptor were reused or if the close triggered side effects. The commit message is clear and concise, explaining the ownership transfer and the rationale for the change. No new symbols or test coverage are introduced; the fix is purely mechanical and confined to `http.c`.

This is a preparatory commit for the larger concurrent-download fix that follows in patch 4. By splitting out this latent bug, the series improves bisectability and makes the core fix easier to review. The change is uncontroversial and aligns with Git’s coding practices for descriptor ownership. No objections or open questions remain for this patch.
