This is a procedural follow-up to the now-withdrawn refactoring series that attempted to change the return type of `utf8_strwidth()` and `utf8_strnwidth()` from `int` to `size_t`. Junio C Hamano replies to Hardik Kumar’s question about where to place the documentation explaining the existing design’s rationale.

Junio suggests the documentation should **replace the TODO comment in `utf8.c`** rather than live in a separate file in `Documentation/technical/`. The TODO comment originally motivated the refactoring effort, which reviewers later deemed misguided after identifying regressions, mixed-sign comparison risks, and minimal practical benefits. The new documentation will clarify (a) why the functions return `int` (to align with `printf()`-style APIs that require `int` for padding calculations) and (b) why `cast_size_t_to_int()` is necessary (to prevent overflows). This approach avoids introducing a new file and keeps the rationale close to the code it describes.

The thread is now effectively closed. The refactoring patch is abandoned, and the only remaining action is to update the comment in `utf8.c`. No further technical discussion is expected unless Phillip Wood or others weigh in on Junio’s suggestion. The outcome reaffirms the status quo, with improved documentation to prevent similar efforts in the future.
