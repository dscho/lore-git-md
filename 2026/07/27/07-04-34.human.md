This is a refactoring patch (v3) that attempts to change the return type of UTF-8 string-width functions (`utf8_strwidth()` and `utf8_strnwidth()`) from `int` to `size_t`. The patch touches `utf8.c`, `utf8.h`, and nine caller files, updating function signatures and local variables to use `size_t` but reintroducing explicit casts to `int` at nearly every call site. This approach preserves the original behavior while sidestepping the type-system improvements the patch claims to deliver.

The v3 patch addresses compilation warnings from earlier versions but does not resolve the core issues identified in prior reviews. Mixed-sign comparisons (e.g., `padding = len - cast_size_t_to_int(...)` in `diff.c`), underflow risks (`len -= 3` in `diff.c`), and struct field mismatches (`stats_table` fields in `builtin/repo.c` remain `int`) persist. The patch also removes the overflow check in `cast_size_t_to_int()` without justification, despite reviewer concerns that some callers might rely on it.

Hardik’s approach prioritizes minimal disruption over type safety, adding casts to `int` at call sites rather than promoting struct fields or refactoring callers to use `size_t` consistently. This undermines the patch’s stated goal of eliminating implicit conversions and leaves the codebase in a state that is no safer than before. Junio C Hamano’s prior skepticism about the patch’s value remains unresolved, as the practical benefit of enforcing `size_t` consistency is minimal for functions measuring display widths of strings that fit on a single line.
