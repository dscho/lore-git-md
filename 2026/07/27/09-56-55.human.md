This is the first patch in a **test infrastructure** series (v2) that introduces a `commit_body()` helper to the Git test suite. The patch adds the helper function to `t/test-lib-functions.sh` and documents it in `t/README` with a usage example.

The motivation is clear: the test suite currently duplicates the pattern `git cat-file commit <rev> | sed -e '1,/^$/d'` about 60 times, which masks exit codes from `git cat-file`. The new helper avoids this by writing the commit object to a temporary file (`.commit`), stripping the header with `sed`, and cleaning up, ensuring proper exit-code propagation. This is a direct response to a recently merged bugfix (commit `b6b276974e`) where Junio Hamano noted the exit-code hole in the existing idiom.

The implementation is straightforward and well-explained. The helper is documented with a clear example (`commit_body HEAD >actual`), and the commit message explicitly addresses the exit-code issue. No user-visible changes are introduced—this is purely internal test suite cleanup.

The patch is part of a two-patch series; the second patch will convert the ~60 call sites to use the new helper. This first patch lays the groundwork and is uncontroversial. The series as a whole is a clean refactoring with a clear rationale, and this patch is a necessary step toward eliminating the duplicated pattern. No objections or open questions are apparent at this stage.
