This is the sixth and final patch in Ted Nyman’s v6 series fixing race conditions in Git’s HTTP transport for packfile URI downloads. It addresses a `.keep` file handling edge case in `fetch-pack.c`: when `index-pack` encounters an existing `.keep` file, it outputs `"pack<TAB><hash>"` instead of `"keep<TAB><hash>"`, but the code previously only accepted the latter. The patch makes `fetch-pack` accept both formats, validates the downloaded pack’s hash against the expected value, and ensures `.keep` lockfiles are only registered when the current fetch created them.

The change is minimal and surgical: the core logic in `do_fetch_pack_v2()` now checks for either `"keep\t"` or `"pack\t"` at the start of `http-fetch`’s output, reads the hash without consuming subsequent fsck output, and skips registering a `.keep` lockfile if the output was `"pack"`. The test in `t/t5702-protocol-v2.sh` verifies the behavior by pre-creating a `.keep` file, confirming the pack is still downloaded and indexed, and ensuring the existing `.keep` file remains untouched.

This patch completes the series’ goal of robust concurrent packfile URI downloads. It’s a narrow bugfix with no new symbols or on-disk format changes, and the test coverage is thorough. The change is uncontroversial and aligns with the series’ broader design of deterministic, race-free HTTP downloads.
