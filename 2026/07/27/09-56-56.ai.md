This is the **second patch in a v2 test infrastructure series** that replaces ~61 duplicated `git cat-file commit <rev> | sed -e '1,/^$/d'` patterns across 12 test scripts with a new reusable shell helper `commit_body()`. The series is part of a broader effort to eliminate exit-code masking in Git’s test suite, motivated by a prior bugfix in `t7614` (commit `b6b276974e`).

This patch applies the `commit_body()` helper to all remaining call sites, including two edge cases missed in v1: the `message_body()` helper in `t7509-commit-authorship.sh` (now removed) and an inline pipe in `t3404-rebase-interactive.sh`. The conversion is mechanical for most sites, but two scripts required special handling: `t7600-merge.sh` (where a grep for a phrase in the commit body was refactored to use the stripped output) and `t3900-i18n-commit.sh` (where piping into `iconv` was replaced with a file write to avoid reintroducing the exit-code hole). The patch also explicitly excludes three unrelated `sed` patterns in `t9001`, `t1450`, and `t4014` that strip non-commit content.

The changes are confined to the test suite (`t/` directory) and introduce no user-visible behavior. All converted scripts pass tests, including deliberate `git cat-file` failure cases that now correctly fail. The helper itself was introduced in the first patch of the series, which also added documentation to `t/README`. Key names: `commit_body()` (function), `.commit` (temporary file). Files touched: 12 test scripts (`t3404`, `t3405`, `t3408`, `t3434`, `t3900`, `t4150`, `t7500`, `t7501`, `t7502`, `t7509`, `t7600`, `t7604`, `t7614`). The series is under review, with no merge signals yet.
