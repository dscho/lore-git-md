This is a v6 reroll of Ted Nyman’s bugfix series for race conditions in Git’s HTTP transport during concurrent packfile URI and dumb HTTP downloads. The series is now split into six patches, separating the double-close fix, HTTP 416 handling, core concurrent-download logic, and Windows sharing requirements into distinct commits while keeping the final production code identical to v5. The series remains focused on preserving resumable downloads for both packfile URIs and dumb HTTP by using deterministic staging paths and read-write mode without append.

The key changes since v5 are organizational: the core fix (previously Patch 2) is now split into four smaller patches (Patches 2–5), each addressing a specific aspect of the problem. Patch 2 fixes a latent double-close bug in `finish_http_pack_request()`, where the staging-file descriptor was being closed twice—once by `start_command()` and again explicitly. Patch 3 adds HTTP 416 handling for completed partial packs, treating the response as a successful download and letting `index-pack` validate the pack. Patch 4 implements the core concurrent-download fix by removing append mode and using descriptor offsets to ensure overlapping responses write identical bytes at identical offsets. Patch 5 addresses Windows-specific sharing requirements, ensuring the staging file can be unlinked by other processes. The final patch (Patch 6) remains unchanged, handling the `.keep` file race by accepting both `"pack"` and `"keep"` output from `index-pack`.

The test suite has been refined to improve clarity and portability. The HTTP 416 test is now standalone, covering both concurrent and non-concurrent interrupted downloads, while the overlapping-download test retains its FIFO-based design but is skipped on MinGW. The series passes all tests, including 240 runs with 12 parallel `--stress` jobs, confirming the fix’s robustness. The patches touch `http.c`, `fetch-pack.c`, and their documentation, with new regression tests in `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`.

This reroll addresses Peff’s post-acceptance feedback from v5 by splitting the "confusing bits" into separate commits, though the production code remains unchanged. The series is already merged to Junio’s `next` branch and is likely to graduate to `master` soon. The changes are narrowly scoped to the packfile URI and dumb HTTP download paths, with no impact on other HTTP fetch behaviors or on-disk formats. The implementation handles platform-specific quirks (MinGW’s non-append O_RDWR open, Windows sharing semantics) and ensures `.keep` file handling is more robust. No open technical questions remain.
