This is the fourth patch in Ted Nyman’s six-patch v6 series fixing race conditions in Git’s HTTP transport during concurrent packfile downloads. It implements the **core concurrent-download fix** by replacing append-mode writes with read-write mode and a single seek to the current end of the staging file. This ensures that overlapping HTTP responses write identical bytes at identical offsets, preserving resumable downloads while preventing corruption.

The patch touches `http.c` and `Documentation/git-http-fetch.adoc`, updating the staging-key documentation to clarify that the hash need not be the pack hash itself but must uniquely identify the pack contents for resumption. The implementation is minimal: it opens the staging file in `O_RDWR | O_CREAT` (without `O_APPEND`), seeks to the end once, and retains the file descriptor for `index-pack` to avoid reopening a path that another downloader may have unlinked. The change is confined to the packfile URI and dumb HTTP download paths, with no impact on other HTTP fetch behaviors or on-disk formats.

Test coverage is thorough: the patch adds a new test for resuming partial downloads and a **deterministic concurrent-download test** using a custom Perl server that reliably reproduces overlapping 200/206 responses. The Perl server, introduced in an earlier patch, is reused here with a 60-second timeout and robust process cleanup, ensuring the test is both reliable and portable. The test passes 240 runs with 12 parallel stress jobs, confirming the fix’s robustness.

The patch directly addresses Peff’s advisory feedback from v5, splitting the monolithic fix into smaller commits for clarity. It is **ready for review** and likely to progress to `next` soon, given that all prior objections have been resolved and the series is now rebased onto current `master`. No open technical questions remain, and the implementation is platform-compatible, handling MinGW’s non-append `O_RDWR` behavior and Windows sharing semantics (the latter addressed in Patch 5). The `.keep` file handling in `fetch-pack` remains unchanged and robust.
