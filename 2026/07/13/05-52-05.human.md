This is the second patch in Patrick Steinhardt’s 12-patch series **"Make ODB optimizations pluggable"**, which is part of the ongoing ODB abstraction effort. This patch addresses a long-standing inconsistency in the "pre-auto-gc" hook by expanding its scope to cover *all* maintenance tasks, not just garbage collection.

The hook’s original intent was to allow users to intercept automated maintenance (e.g., to prevent parallel operations), but it only ran for the "gc" task, leaving other tasks like reflog expiration or geometric repacking unaffected. This patch fixes that by running the hook once, before the first auto-maintenance task that meets its auto-condition, regardless of whether that task is "gc" or another type. The change is backward-compatible: the hook still runs for `git gc --auto` as before, but now also covers `git maintenance run --auto` when any task would execute.

The implementation lifts the hook invocation out of `need_to_gc()` and into `maybe_run_task()`, using a new `enum auto_gc_hook_result` to ensure the hook runs exactly once per `maintenance run` invocation. The patch includes thorough test coverage in `t/t7900-maintenance.sh`, verifying that the hook runs once (not per task), can inhibit all tasks when it fails, and does not run when no maintenance is needed or when `--auto` is omitted.

This is a well-motivated, uncontroversial change that aligns the hook’s behavior with its intended purpose. The patch is cleanly structured, with no behavioral regressions or edge cases noted in the commit message. Junio’s feedback on the v1 version of this patch (which focused on test brittleness) has been fully addressed in the v2 series by the new `test_maintenance_tasks` helper introduced in patch 1. The patch is ready for review and looks like a straightforward improvement.
