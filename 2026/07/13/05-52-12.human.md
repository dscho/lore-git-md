This is the ninth patch in Patrick Steinhardt’s 12-patch series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. The patch introduces `odb_optimize_required()`, a new helper that centralizes the logic for determining whether an ODB optimization (incremental repack or geometric repack) should run under `--auto`. This refactoring consolidates two previously scattered functions—`need_to_gc()` and `geometric_repack_auto_condition()`—into a single, strategy-aware entry point, preparing the codebase for pluggable ODB backends.

The patch is a mechanical refactoring with no intended behavioral changes. It replaces the hardcoded auto-condition checks in `need_to_gc()` and `geometric_repack_auto_condition()` with a unified `odb_optimize_required()` function that takes an `enum odb_optimize_strategy` (`ODB_OPTIMIZE_INCREMENTAL` or `ODB_OPTIMIZE_GEOMETRIC`) and an `odb_optimize_options` struct. The new helper encapsulates all existing logic: configuration reads (`gc.auto`, `gc.autopacklimit`, `maintenance.geometric-repack.auto`, `maintenance.geometric-repack.splitFactor`), pack geometry analysis, and loose object estimation. The patch updates `cmd_gc()` and the `gc_condition()` and `geometric_repack_auto_condition()` task callbacks to use the new helper, preserving all existing semantics (e.g., negative `gc.auto` values disabling auto-gc, geometric repack split factors, and promisor object exclusions).

The patch touches only `builtin/gc.c` and is uncontroversial, as it merely reorganizes existing logic without altering behavior. The commit message explicitly notes that the change is an implementation detail of the ODB backend, making the logic pluggable for future backends. Reviewers may wish to verify that the new helper correctly handles edge cases (e.g., negative auto-values, zero thresholds) and that the `OPTIMIZE_FIELDS_FROM_GC_CONFIG` macro initializes the `odb_optimize_options` struct correctly, but the patch maintains identical behavior to the original code paths. This is a prerequisite for the final patch in the series, which relocates the optimization logic into the ODB source backend.
