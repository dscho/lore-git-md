This is the fifth patch in Pablo Sabater’s **v10 series** implementing **visual root indentation for `git log --graph`**, now introducing **four-level wrapping** to prevent excessive cascading indentation.

The patch modifies the graph-drawing logic in `graph.c` to **reset indentation after four levels**, avoiding the "pyramid effect" that occurs when a single author contributes many isolated patches (e.g., with `--author` filtering). The implementation adds a modulo-4 check in `graph_update()` to detect when the visual root depth reaches a multiple of four, at which point it **stops cascading** and forces the next commit to indent normally if it is not itself a visual root. This prevents ambiguity where vertically adjacent commits might otherwise appear related. The indentation calculation in `graph_output_commit_line()` is updated to use `(depth - cascade) % 4` instead of the previous linear formula, ensuring the wrap is applied consistently.

The accompanying test in `t/t4218-log-graph-indentation.sh` verifies the behavior with a ten-commit sequence of orphaned roots, confirming that the graph correctly wraps after four levels and handles the ambiguous case (where a non-root commit would otherwise align with the wrapped root) by forcing an extra level of indentation. The test is thorough, covering both the wrap and the edge case that motivated the design.

This patch **resolves the last major usability concern** from earlier revisions, where indefinite cascading made the graph hard to read. The four-level wrap was **agreed in discussion** as the best balance between visual clarity and avoiding symmetry-induced ambiguity, and the implementation matches the design described in the commit message.
