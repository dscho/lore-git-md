This thread is a two-patch bugfix series from Ted Nyman addressing race conditions in Git's packfile URI download mechanism over HTTP. The series targets concurrent downloads to the same repository, which can corrupt temporary packfiles or cause spurious failures. The first patch ensures each direct packfile URI download uses a unique temporary file, while the second patch makes `fetch-pack` accept both `"pack<TAB><hash>"` and `"keep<TAB><hash>"` as valid success messages from `index-pack`, addressing a race around `.keep` file creation.

The changes are narrowly scoped to the HTTP transport (`http.c`, `http.h`), fetch-pack plumbing (`fetch-pack.c`), and documentation (`git-http-fetch.adoc`), with regression tests added to `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`. The series does not affect other fetch mechanisms, and the solution appears technically sound, using unique temporary files to isolate downloads and relaxing message parsing to handle races. No objections or alternative approaches have been raised in the thread so far, and the patches include thorough test coverage. The series is likely to proceed smoothly toward integration.
