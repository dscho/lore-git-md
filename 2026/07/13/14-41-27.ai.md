This is patch 3/9 in Patrick Steinhardt’s v3 series introducing object filters to `odb_for_each_object()`. It is Jeff King’s cleanup patch, now integrated into the series, which removes the unused `int` return value from `add_object_entry()` in `builtin/pack-objects.c`.

The patch is a mechanical cleanup with no behavior change. The function `add_object_entry()` has returned 0 or 1 since 2006 to indicate whether it added a new object entry, but no caller has used this return value since commit `5379a5c5ee` (2006). The sister function `add_object_entry_from_bitmap()` also returns an `int`, but its return value is about to change to conform to a callback interface, creating a divergence in semantics. By converting `add_object_entry()` to `void`, the patch makes it clear that the two functions have different purposes and removes dead code.

The diff touches only `builtin/pack-objects.c`, changing the function signature and removing two `return 0` statements and one `return 1`. The commit message explains the historical context and the motivation for the change, and Patrick Steinhardt has lightly edited it for clarity. Junio C Hamano has already reviewed and endorsed the cleanup, suggesting it could be squashed into the series or queued independently. This version integrates it as patch 3/9, making the series self-contained.

The patch is uncontroversial and ready for integration. It is a small but meaningful step toward API clarity in the pack-objects subsystem.
