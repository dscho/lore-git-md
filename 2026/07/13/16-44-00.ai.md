This is the **lookahead buffer implementation** in Pablo Sabater’s **v11 series** adding visual root indentation to `git log --graph`. The patch introduces a two-slot lookahead buffer (`lookahead[2]`) in `struct git_graph` and wires it into the revision walk via `get_revision()`. The buffer is managed as a FIFO queue, pre-fetching up to two commits ahead when a graph is active, and is populated by the `next_commit_to_show()` helper (introduced in patch 2/7).

The core change is in `revision.c`: `get_revision()` now checks the lookahead buffer first, falling back to `next_commit_to_show()` only if the buffer is empty. When a commit is popped, the function pre-fetches additional commits to keep the buffer full, ensuring the graph renderer always has access to the next two commits. The patch also updates `graph_is_interesting()` to treat buffered commits as "interesting," preserving correct parent-child relationships in the graph output.

This is a **purely internal refactoring** with no user-visible behavior change. The lookahead buffer is a prerequisite for the visual root detection logic in patch 4/7, which needs to peek ahead to determine whether a commit is a visual root before rendering it. The implementation is stable since v7 and has been approved by Junio Hamano and Kristofer Karlsson. The patch adds 84 lines across `graph.c`, `graph.h`, and `revision.c`, including new helper functions (`graph_pop_lookahead`, `graph_get_lookahead_room`, `graph_push_lookahead`) and BUG assertions to enforce buffer invariants.

The only interaction with other subsystems is the coupling to `next_commit_to_show()` (patch 2/7), which ensures the lookahead buffer fetches commits from the correct source (revision walk or saved list for `--max-count-oldest`). The `--reverse` branch is explicitly excluded to avoid side effects. No edge cases or performance regressions are introduced; the buffer is small (two slots) and only active when a graph is being rendered.

This patch is **ready for final review** and has no unresolved technical questions. It is a critical enabler for the visual root indentation feature and is unlikely to see further changes. The next patch in the series (4/7) builds directly on this infrastructure to implement the indentation logic.
