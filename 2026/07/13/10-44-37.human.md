This is the second patch in Pablo Sabater’s **v10 series** implementing visual root indentation for `` `git log --graph` ``. It is a **refactoring patch** that extracts the logic for retrieving the next commit into a new helper function, `next_commit_to_show()`.

The patch addresses a technical requirement for the series: the upcoming lookahead buffer (introduced in patch 3/7) needs to pre-fetch commits from the same source that `get_revision()` uses. Currently, `get_revision()` retrieves commits from two different places depending on whether `--max-count-oldest` is active. This patch unifies that logic into a single helper, making it possible to pre-fetch commits consistently without changing behavior.

The change is **mechanical and preparatory**—there are no user-visible effects, and the commit message explicitly notes that the `--reverse` branch is intentionally left unchanged to avoid altering its behavior. The patch is **well-scoped and clearly motivated**, with a clean diff that moves code into a helper function without introducing complexity. It has already been reviewed in earlier iterations and is unlikely to be controversial.

This patch is **ready for final review** and is a necessary stepping stone for the lookahead buffer implementation in patch 3/7. If the series is accepted, this refactoring will be part of the foundation for the visual indentation feature.
