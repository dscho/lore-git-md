This is the **core visualization patch** in Pablo Sabater’s **v10 series** implementing **visual root indentation for `git log --graph`**. It is **patch 4/7** and introduces the actual indentation logic that was the original goal of the series.

The patch adds indentation to commits that appear as "visual roots" (commits with no visible parents due to filtering, boundary conditions, or being actual roots) to prevent them from being vertically adjacent to unrelated commits, which would falsely imply a relationship. The implementation relies on the **lookahead buffer** (introduced in patch 3/7) to safely inspect future commits and determine whether a commit is a visual root before rendering it.

Key technical details:
- A new `is_visual_root` flag in `struct git_graph` tracks whether the current commit is a visual root.
- A new `GRAPH_PRE_ROOT` state is added to print an extra row connecting an indented visual root to its child (if any).
- The indentation depth increases for each adjacent visual root ("cascading"), but the last visual root in a sequence is not indented to avoid unnecessary whitespace.
- Merge parents (non-first parents of a merge) are explicitly excluded from indentation because they are already visually connected by an edge.
- The indentation is applied in the commit line rendering (`graph_output_commit_line`) by adding spaces proportional to the visual root depth.

The patch includes **extensive test coverage** in the new `t4218-log-graph-indentation.sh` file, covering edge cases such as:
- Single roots (not indented).
- Cascading visual roots (indentation increases for each adjacent root).
- Merge parents (not indented).
- Boundary commits (not indented, as they inherit their child’s column).
- `--first-parent`, `--left-right`, `--max-count`, and `--grep`/`--author` filtering.
- Integration with non-oneline formats (indentation applies to the description as well).
