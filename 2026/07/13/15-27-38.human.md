This is a **surface-level review** of the sixth patch in Harald Nordgren’s `git branch --delete-merged` series (v18). The patch introduces a per-branch opt-out mechanism via `branch.<name>.deleteMerged=false`, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

Phillip Wood’s feedback is minimal and stylistic: he suggests improving the test by checking the output of `git for-each-ref` instead of relying solely on `rev-parse` and `test_grep`. This would make the test more robust by directly verifying the state of the refs rather than inferring it from error messages and existence checks. The change is purely about test clarity and does not affect the patch’s functionality or design.

The patch itself remains **well-motivated and stable**, with no substantive issues raised. It cleanly integrates into the series’ broader goal of safe, automated branch cleanup, complementing existing safety checks (checked-out branches, missing upstreams, push divergence, and stacked-branch protection). The opt-out mechanism is minimal, non-intrusive, and thoroughly tested, addressing iterative topic-branch workflows without complicating the core logic.

This review does not alter the series’ readiness for merging. The only remaining pre-merge action is Harald’s agreed-upon mechanical fix to the flags-based API in patches 2–4, which is unrelated to this patch.
