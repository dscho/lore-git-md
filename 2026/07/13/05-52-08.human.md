This is the fifth patch in Patrick Steinhardt’s 12-patch series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. The patch refactors how `git gc` assembles the arguments for `git repack` by moving the logic from global scope into the `maintenance_task_odb()` helper, making the code self-contained and easier to follow.

The change eliminates the global `repack_args` string vector, which was previously built in `cmd_gc()` and passed around to multiple functions. Instead, the repack arguments are now constructed directly inside `maintenance_task_odb()`, which now takes two additional parameters: `keep_largest_pack` and `aggressive`. The logic for determining whether to perform a full repack, incremental repack, or no repack at all is preserved exactly, including edge cases like memory estimation for large packs and the handling of `--auto` mode. The `need_to_gc()` helper is also simplified, as it no longer needs to populate `repack_args`.

This is a pure refactoring with no intended behavioral changes. The patch is well-motivated: the global `repack_args` was a source of hidden interdependencies, and moving it into the helper function makes the code more modular and easier to relocate in later patches. The commit message clearly explains the rationale, and the diff is mechanical, with no subtle edge cases introduced. The patch is uncontroversial and aligns with the series’ goal of preparing the ODB optimization logic for pluggability.
