This is the fourth patch in Patrick Steinhardt’s 12-patch series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. It extracts the object database (ODB) optimization logic from `cmd_gc()` into a new helper function, `maintenance_task_odb()`, as a pure refactoring with no intended behavior change.

The patch moves the repack and prune logic — previously inlined in `cmd_gc()` — into the new helper, along with the warning about too many loose objects. The warning’s timing may shift slightly, but the commit message explicitly dismisses this as having no practical impact. The change is mechanical: the new function takes the same parameters (`maintenance_run_opts`, `gc_config`, and `repack_args`), performs the same checks (e.g., skipping if `precious_objects` is set), and propagates errors identically. The only difference is that `cmd_gc()` now calls `maintenance_task_odb()` and dies on failure, rather than inlining the logic.

This refactoring is a prerequisite for later patches in the series, which will relocate the ODB optimization logic into the "files" ODB source backend. The patch is well-motivated and uncontroversial; it follows the series’ established pattern of isolating backend-specific logic for eventual pluggability. No objections or design concerns were raised in the v1 review, and the v2 iteration addressed all prior feedback. The code is clean, the commit message is clear, and the test suite (updated in patch 1) remains robust. For anyone following the ODB abstraction effort, this patch is a straightforward but necessary step toward modular housekeeping.
