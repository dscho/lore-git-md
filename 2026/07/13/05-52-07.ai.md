This is the fourth patch in Patrick Steinhardt’s 12-patch v2 series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. The patch extracts the object database (ODB) optimization logic from `cmd_gc()` into a new helper function, `maintenance_task_odb()`, as a pure refactoring with no intended behavioral changes.

The patch moves the repack and prune logic—previously inlined in `cmd_gc()`—into `maintenance_task_odb()`, along with the warning about too many loose objects. The warning’s timing may shift slightly, but the commit message explicitly dismisses this as having no practical impact. The new helper takes the existing `maintenance_run_opts`, `gc_config`, and `repack_args` parameters, preserving all existing logic (e.g., precious objects check, promisor object exclusions, cruft pack handling). The caller (`cmd_gc()`) now invokes the helper and dies on failure, with the error message simplified to avoid redundant prefixes.

Key details:
- **Files touched**: `builtin/gc.c` (79 lines changed: 49 added, 30 removed).
- **New symbol**: `maintenance_task_odb()`.
- **Behavior**: unchanged; the patch is a mechanical refactoring to prepare for later modularization.
- **Subsystems**: ODB housekeeping (repack/prune), maintenance tasks, `the_repository` usage (unchanged for now).

The patch is uncontroversial and aligns with the series’ goal of isolating ODB optimization logic for future pluggability. No review feedback has surfaced yet, but the change is straightforward and maintains identical functionality. This is a prerequisite for later patches that relocate the logic into the ODB source backend.
