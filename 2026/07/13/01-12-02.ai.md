This is the third patch in a four-patch series from Taylor Blau that refines how `git pack-objects` handles delta reuse when `--no-ref-delta` is specified. The series as a whole relaxes an earlier simplification that disabled all delta and bitmap reuse in this mode, which was overly conservative.

The patch teaches `pack-objects` to keep delta reuse enabled when `--delta-base-offset` is also given, even with `--no-ref-delta`. The key insight is that a reused delta whose base appears earlier in the output can be encoded as an `OFS_DELTA` instead of a `REF_DELTA`, so the restriction no longer applies. Preferred bases and external thin-pack bases still require `REF_DELTA` encoding and therefore remain disabled. Bitmap reuse is updated to inspect each candidate object individually, skipping any `REF_DELTA` entries when `--no-ref-delta` is in effect and avoiding the fast-path whole-word copy for the preferred or single pack.

The code changes touch `builtin/pack-objects.c` and `pack-bitmap.c`, adding a new `allow_ref_delta` parameter to the bitmap-reuse entry point and propagating it through the call chain. Tests in `t/t5300-pack-object.sh` and `t/t5332-multi-pack-reuse.sh` verify that reused deltas are correctly rewritten as `OFS_DELTA` and that the bitmap path still produces packs without `REF_DELTA` entries.

The patch is narrowly scoped, well-motivated, and includes thorough test coverage. It looks like a clean, incremental improvement to the pack-reuse machinery.
