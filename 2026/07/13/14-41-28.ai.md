This is patch 4/9 in Patrick Steinhardt’s v3 series introducing object filters to `odb_for_each_object()`. It enables early termination during iteration of bitmapped objects by propagating non-zero return values from the `show_reach` callback through `show_objects_for_type()` and `for_each_bitmapped_object()`. The patch is a prerequisite for lifting bitmap iteration into the "packed" backend (patch 8/9) and exposing it via `odb_for_each_object()`, which expects callbacks to support early termination.

The change modifies `pack-bitmap.c` to make `show_objects_for_type()` return an `int` instead of `void`, checks the return value of `show_reach()`, and aborts iteration if non-zero. The loop in `for_each_bitmapped_object()` is refactored to iterate over an array of object types and propagate any non-zero return values. Two existing callbacks—`add_object_entry_from_bitmap()` in `builtin/pack-objects.c` and `show_object_fast()` in `builtin/rev-list.c`—are updated to return `0` instead of `1` to preserve their current behavior, as their non-zero returns were previously ignored by `traverse_bitmap_commit_list()`.

The patch also documents the new early-termination behavior in the `for_each_bitmapped_object()` function comment. The diffstat shows 25 insertions and 13 deletions across four files, with the bulk of the changes in `pack-bitmap.c`. The commit message explicitly acknowledges the inconsistency with `traverse_bitmap_commit_list()`, which still ignores callback return values, but defers resolving this "foot-gun" to avoid a large-scale refactoring.

This is a well-motivated, mechanical change that aligns the bitmap iteration API with the calling convention expected by `odb_for_each_object()`. The patch is uncontroversial and has no unresolved review feedback. It is part of the ODB abstraction effort and depends on earlier patches in the series. No new technical debt is introduced beyond the acknowledged API inconsistency, which is documented and deferred.
