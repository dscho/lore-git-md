This thread is a two-patch bugfix series from Ted Nyman addressing race conditions in Git’s packfile URI download mechanism over HTTP. The series targets concurrent fetches into a shared object database, where multiple Git processes could corrupt temporary packfiles or trigger spurious failures due to overlapping `.keep` file handling.

The first patch prevents corruption by ensuring each packfile URI download writes to a unique temporary file, rather than a fixed path that could be appended to by concurrent processes. The second patch resolves a race where `index-pack`’s success message could vary depending on whether another process had already created the `.keep` file, causing `fetch-pack` to misinterpret the result. Both patches include regression tests in the relevant test scripts (`t5550` and `t5702`).

The changes are confined to the HTTP transport layer (`http.c`, `fetch-pack.c`) and documentation, with no impact on other fetch modes or the on-disk format. The series appears well-prepared, with clear commit messages and thorough test coverage, and addresses real-world issues observed in the wild. There’s been no review feedback yet, so the patches are still under initial consideration.
