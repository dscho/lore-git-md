This thread is a two-patch bugfix series from Ted Nyman that addresses race conditions in Git’s HTTP transport when multiple processes fetch the same packfile URI, which could corrupt temporary files or cause spurious failures. The series was initially held up by a message threading issue—Mutt rewrote the cover letter’s `Message-ID`, breaking tools like `b4 am`—but Ted has now provided the correct ID, restoring the chain and clearing the procedural hurdle. The patches themselves, which introduce unique temporary files for packfile URI downloads and adjust `fetch-pack` to handle both `pack` and `keep` success lines from `index-pack`, remain unchanged and are still awaiting substantive technical review.

Junio C Hamano flagged the threading problem but hasn’t yet weighed in on the code. The fixes touch `http.c`, `http.h`, `fetch-pack.c`, and the `git-http-fetch` documentation, and include regression tests in `t5550-http-fetch-dumb.sh` and `t5702-protocol-v2.sh`. With the threading issue resolved, the series is now ready for review, but no feedback has been provided so far.
