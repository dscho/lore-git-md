This thread is about a small but welcome cleanup to `git fast-export`. Christian Couder noticed that the command's `-h` help text and its man-page synopsis didn't match each other or Git's usual style for revision arguments. The patch unifies both to the standard form `[<options>] [<revision-range>] [[--] <path>...]`, the same pattern used by `git log` and `git rev-list`. It also removes `fast-export` from a test that was flagging the mismatch as a failure.

Junio reviewed the change and agreed that the original man-page synopsis was oddly specific (it included `| 'git fast-import'` as an example rather than a formal syntax description). He queued the patch for merging, so this inconsistency should be resolved in the next Git release. The patch is purely textual—no code behavior changes—and passed CI on Christian's branch. There's nothing left to discuss; it's ready to go.
