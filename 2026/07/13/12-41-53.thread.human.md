This thread is a small but useful cleanup for `git fast-export`. Christian Couder noticed that the command's help text (`git fast-export -h`) didn't match its man page or follow Git's usual pattern for describing revision arguments. The patch updates both the usage string in the code and the man page to use the standard format `[<options>] [<revision-range>] [[--] <path>...]`, matching what other commands like `git log` use. It also removes `fast-export` from a test that was failing because of this mismatch.

The change is purely about documentation consistency—no behavior is altered. The files touched are the man page, the usage string in `builtin/fast-export.c`, and a test file that checks for help-vs-documentation mismatches. Christian reports that CI passed on his branch, so this should be ready to merge once it gets a quick review. No objections or open questions have been raised yet.
