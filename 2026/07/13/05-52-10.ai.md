This is patch 7/12 in Patrick Steinhardt’s "Make ODB optimizations pluggable" series, part of the ongoing ODB abstraction effort. It introduces `struct odb_optimize_options` to encapsulate all settings related to object database optimization, decoupling them from the monolithic `struct gc_config`. The patch is a mechanical refactoring with no intended behavioral changes, but it is a critical step toward making ODB optimizations pluggable.

The new structure (`odb_optimize_options`) consolidates 11 fields that were previously scattered across `gc_config` or passed as loose parameters: flags for verbosity, auto-maintenance, and delta reuse; prune expiration and cruft pack settings; repack depth and window; and backend-specific options like `keep_largest_pack` and `max_cruft_size`. A convenience macro (`OPTIMIZE_FIELDS_FROM_GC_CONFIG`) simplifies initialization by copying relevant fields from `gc_config`. The patch updates `add_repack_all_option()` and `maintenance_task_odb()` to use the new structure, and introduces a new `odb_optimize()` helper that will eventually move into the ODB layer. The geometric repack task is also updated to use `odb_optimize_options` when falling back to a full repack.

Key symbols introduced: `enum odb_optimize_flags` (with `ODB_OPTIMIZE_VERBOSE`, `ODB_OPTIMIZE_AUTO`, and `ODB_OPTIMIZE_NO_REUSE_DELTAS`), `struct odb_optimize_options`, the `OPTIMIZE_FIELDS_FROM_GC_CONFIG` macro, and the `odb_optimize()` function. The patch touches only `builtin/gc.c` and is a pure refactoring, preserving all existing logic (e.g., precious objects checks, promisor object exclusions, memory estimation, and cruft pack handling). The only observable change is a slight shift in the timing of the "too many loose objects" warning, which the commit message explicitly dismisses as having no practical impact.

This patch is uncontroversial and well-motivated: it isolates ODB-specific settings from generic GC configuration, enabling future backends to define their own optimization strategies. The encapsulation is clean, and the macro-based initialization keeps the code readable. No objections or design concerns are evident, and the patch is a prerequisite for the final relocation of optimization logic into the ODB layer in patch 12. Reviewers may wish to verify that the new structure’s fields are correctly initialized in all code paths, particularly in the geometric repack fallback, but the patch appears mechanically sound.
