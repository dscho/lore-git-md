This is the first patch in Patrick Steinhardt’s nine-patch v3 series introducing object filters to `odb_for_each_object()`. It targets the packed object database backend, specifically improving object lookup efficiency during enumeration.

The patch addresses an inefficiency in `odb_source_packed_for_each_object()`: when iterating through objects in a multi-pack index or individual packfiles, the code uses the index to enumerate objects but then ignores the index-provided pack and offset data for the actual object lookup. Instead, it calls the generic `odb_source_read_object_info()`, which redundantly re-traverses the indices to locate the object. This not only degrades performance but also risks looking up the object in the wrong pack if it exists in multiple packs.

The fix replaces the generic lookup with direct calls to `packed_object_info()`, using the index-provided pack and offset data. The patch also renames the `store` variable to `source` for clarity, though this stylistic change is mixed with the functional improvement. The condition `if (opts->flags || data->request)` now includes `data->request` to ensure the pack is populated before calling `packed_object_info()`.

Review feedback from v2 (Taylor Blau) identified a performance concern: the current implementation aborts iteration on the first non-match, mitigating the inefficiency, but the loop’s scope (full MIDX chain vs. primary MIDX) remains ambiguous. Patrick deferred Taylor’s proposed optimization (using the OID fanout chunk to narrow the iteration range) to a separate series, leaving the current implementation as "not incorrect, merely suboptimal."

The patch is a well-motivated, low-risk improvement that aligns with the series’ broader goal of abstracting object storage. It touches only `odb/source-packed.c` and introduces no behavioral changes. The diffstat (8 insertions, 7 deletions) reflects the targeted nature of the change. While the mixed variable rename is a minor nit, the core logic is sound and ready for integration.
