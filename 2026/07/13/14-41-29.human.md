This is the fifth patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`. It refactors the bitmap-opening logic in `pack-bitmap.c` to iterate over object sources first, then attempt to load a bitmap for each source, rather than searching all sources for a multi-pack index bitmap followed by all sources for a packfile bitmap. The change is a prerequisite for a later patch (8/9) that will open bitmaps exclusively for a specific object source, ensuring objects are correctly attributed to their source and avoiding redundant enumeration.

The patch reverses the loop order in `open_bitmap()`, introducing a new helper function `open_bitmap_for_source()` that encapsulates the logic for opening either a multi-pack index bitmap or a packfile bitmap for a single object source. This refactoring simplifies the code and makes it easier to extend, though it also subtly changes bitmap precedence in one edge case: when an earlier object source has only a packfile bitmap and a later source has a multi-pack index bitmap, the earlier source’s packfile bitmap now takes precedence. Previously, a multi-pack index bitmap from any source would have taken precedence over all packfile bitmaps. The commit message argues this is an improvement, as it prefers local bitmaps over those in alternates, and notes that repositories with multiple bitmaps are already considered broken (and warned about).

The diffstat shows a net reduction of seven lines, reflecting the consolidation of duplicate logic into the new helper function.
