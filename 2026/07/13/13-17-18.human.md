This is the first patch in Phillip Wood’s 10-patch **bugfix and refactoring series** targeting the sequencer subsystem. The series addresses a long-standing issue where `git rebase` incorrectly copies notes from dropped commits to the current HEAD, corrupting note history.

This specific patch restores test coverage for the "apply" backend, which was lost when the default rebase backend switched from "apply" to "merge". The change is minimal: it replaces the `-m` flag (which forces the merge backend) with `--apply` in a test case in `t3400-rebase.sh`. This ensures the test suite continues to verify that `git rebase --apply` correctly copies notes, while the existing test for the default (merge) backend remains unchanged.

The patch is a **pure test maintenance update** with no behavior changes. It is well-motivated and necessary for the broader series, as the later patches (including the core fix in patch 10) rely on this coverage to verify their correctness across both backends. The commit message clearly explains the rationale, and the change itself is straightforward. This is a small but important step in the series, ensuring the fix is thoroughly tested.
