This is the eighth patch in Patrick Steinhardt’s 12-part series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. The patch unifies Git’s two object database optimization strategies—incremental repacking (used by `git gc`) and geometric repacking (used by `git maintenance`)—under a single entry point, `odb_optimize()`. This is a refactoring patch with no intended behavioral changes, but it paves the way for future ODB backends to implement their own optimization logic.

The patch introduces an `enum odb_optimize_strategy` to distinguish between `ODB_OPTIMIZE_INCREMENTAL` and `ODB_OPTIMIZE_GEOMETRIC`, and adds a `strategy` field to the `struct odb_optimize_options` structure. The geometric repacking logic, previously inlined in `maintenance_task_geometric_repack()`, is moved into `odb_optimize()` and guarded by a `switch` statement. The incremental repacking logic is restructured to use the same `switch` block, making the code paths more symmetrical. The patch also updates `maintenance_task_geometric_repack()` to call `odb_optimize()` with the new `ODB_OPTIMIZE_GEOMETRIC` strategy, eliminating the now-redundant geometric repacking code.

Tests in `t/t7900-maintenance.sh` are updated to reflect a minor change in command-line argument formatting: `--quiet` is replaced with `-q` in the expected `git repack` invocations. This is a mechanical change with no functional impact, as the two flags are equivalent. The patch is well-motivated and clearly explained in the commit message, which explicitly notes the equivalence of `--quiet` and `-q` and the goal of unifying the two optimization strategies.

This patch is a prerequisite for the final relocation of ODB optimization logic into the ODB source backend (patch 12). It is uncontroversial and maintains identical behavior to the original code paths, though reviewers may wish to verify that the restructuring does not introduce subtle edge cases in pack selection or memory estimation logic. The patch is part of a series that has already addressed Junio C Hamano’s feedback on earlier iterations, and no objections to the core design have been raised.
