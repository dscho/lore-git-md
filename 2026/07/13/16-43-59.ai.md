This is the second patch in Pablo Sabater’s **v11 series** implementing visual root indentation for `` `git log --graph` ``. It introduces a helper function, `next_commit_to_show()`, that abstracts the logic for retrieving the next commit to display, whether from the revision walk (`get_revision_internal()`) or from the saved list used by `--max-count-oldest`. The change is **purely preparatory** and has no user-visible behavior change.

The helper is needed for the **lookahead buffer** introduced in patch 3/7, which pre-fetches commits to determine visual root status before rendering. By centralizing the commit retrieval logic, the patch ensures the lookahead buffer fetches from the correct source (revision walk or saved list) without duplicating code. The `--reverse` branch is explicitly excluded from using the helper to avoid unintended side effects, as it manages its own commit traversal.

The patch touches only `revision.c`, adding 24 lines and removing 12. The implementation is **mechanical and low-risk**, with no new edge cases or dependencies. It has been **stable since v7** and is **ready for final review**. The series’ architectural decisions (lookahead buffer, four-level wrap, opt-out mechanism) are already settled, and this patch is a straightforward prerequisite for the core visualization logic in patch 4/7. No further changes are expected.
