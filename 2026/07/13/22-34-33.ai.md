This patch is a **bugfix** targeting the HTTP transport layer, specifically the handling of packfile URI downloads. It addresses a race condition where two concurrent `git http-fetch` processes downloading the same packfile into a shared object database can corrupt the temporary file by writing to the same path. The issue stems from the deterministic temporary file naming scheme introduced in 8d5d2a34df (2020), which uses the advertised pack hash to derive the path (`objects/pack/pack-<hash>.pack.temp`).

The fix switches packfile URI downloads to use Git’s tempfile API, generating unique temporary files (e.g., `objects/pack/tmp_pack_XXXXXX`) instead of the deterministic path. This prevents concurrent processes from clashing, but at the cost of losing resumability for packfile URI downloads—retries now start with an empty file rather than appending to a partial download. Ordinary dumb HTTP pack requests retain the old behavior, as they rely on the deterministic path to resume partial downloads.

The patch touches `http.c` and `http.h`, adding a `tempfile` field to `struct http_pack_request` and refactoring the request-creation logic into a new helper, `new_http_pack_request_for_url`, which takes a `resumable` flag to distinguish between the two download modes. The documentation (`git-http-fetch.adoc`) is updated to remove outdated references to the hash’s role in temporary file naming. A new test in `t/t5550-http-fetch-dumb.sh` exercises the race condition by pausing one download mid-flight and starting a second process, verifying that both succeed without corruption or leftover temporary files.

The change is narrowly scoped to packfile URI downloads, which are a relatively recent feature (added in 2020) and less commonly used than dumb HTTP fetches. The trade-off—sacrificing resumability for correctness—is justified, as packfile URI downloads are typically small and fast, while concurrent corruption is a hard failure. The patch is well-motivated, includes a thorough test, and avoids disrupting the more widely used dumb HTTP path. It looks like a clean, targeted fix for a real problem.
