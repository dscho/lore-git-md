This is the **fifth patch in the v11 series** implementing visual root indentation for `git log --graph`. It introduces **four-level wrapping** for cascading visual roots, addressing a usability issue where long sequences of indented roots could create excessive "pyramid" effects or visual ambiguity when filtered (e.g., by `--author`).

The patch modifies `graph.c` to reset indentation after four levels, ensuring commits wrap back to the initial column. To avoid ambiguity when a non-root commit aligns vertically with a wrapped root, the logic forces an extra indentation level in such cases. The implementation is minimal: it adds a modulo operation (`% 4`) to the padding calculation in `graph_output_commit_line()` and updates `graph_update()` to stop cascading when the visual root depth reaches a multiple of four. The test in `t4218-log-graph-indentation.sh` verifies the wrap with a ten-commit sequence of orphaned roots, including the ambiguous case where a non-root commit would otherwise align with the wrapped root.

This is a **usability refinement** that resolves a key objection from earlier revisions (symmetry-induced ambiguity in the two-level wrap design). The choice of four levels balances clarity and compactness, as noted in the commit message. The patch is **ready for final review** and has no unresolved technical concerns. It depends on the lookahead buffer (patch 3/7) and core visualization logic (patch 4/7) but is otherwise self-contained. The test coverage is thorough, including the edge case that motivated the wrapping behavior.
