This is a bugfix series targeting the packfile URI download mechanism in Git's HTTP transport. The author, Ted Nyman, addresses two race conditions that can occur when multiple Git processes concurrently fetch the same packfile into a single object database.

The first patch prevents file corruption by giving each direct packfile URI download its own temporary file, rather than sharing a single `.temp` file. This change is specific to packfile URIs; ordinary dumb HTTP pack requests retain their existing resumable staging behavior. The commit message is clear about the motivation and scope, and the patch includes a regression test.

The second patch handles a related race around `.keep` files. When one process creates the keep file before another finishes, `index-pack` reports a different success message. The patch makes `fetch-pack` accept both forms and ensures only the current process's keep files are removed. This too comes with a regression test.

The series touches `http.c`, `fetch-pack.c`, and adds tests in `t5550-http-fetch-dumb.sh` and `t5702-protocol-v2.sh`. The changes are well-scoped and the commit messages explain both the problem and the fix. The regression tests suggest the issues are real and reproducible.

This looks like a solid, well-motivated fix for a subtle concurrency bug. The patches are small, focused, and come with tests, so they should be easy to review and merge. If you work with large repositories that use packfile URIs, this series is worth paying attention to.
