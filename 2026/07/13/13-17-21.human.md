This is a **bugfix patch** in Phillip Wood’s 10-patch series overhauling how `git rebase` handles dropped commits. It targets a specific edge case in the sequencer: when `git commit` fails to execute (e.g., due to a missing binary or permission error), the rebase machinery incorrectly reschedules the commit for later retry, even though the commit was already successfully picked and all necessary state files were written. The fix ensures such failures are treated as unrecoverable errors rather than transient issues, aligning the behavior with how merge command failures are handled.

The patch is small and surgical, adding a single line to `sequencer.c` that converts a `-1` return value from `run_git_commit()` to `1` (indicating an error but no rescheduling). This matches the behavior of `do_merge()`, which already handles command execution failures this way. The commit message is clear and concise, explaining both the problem and the rationale for the fix. No tests are included here, but the broader series expands test coverage for related edge cases in `t3404-rebase-interactive.sh` and `t5407-post-rewrite-hook.sh`.
