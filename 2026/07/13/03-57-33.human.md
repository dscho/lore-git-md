This is the fifth patch in Tian Yuchen’s v11 series migrating global configuration variables into `struct repo_config_values` as part of the ongoing `the_repository` removal effort. This specific patch moves the `askpass_program` global variable into the repository-scoped structure, eliminating redundant state and enabling proper memory management.

The change is straightforward: the global `askpass_program` (declared in `environment.h` and defined in `environment.c`) is removed, and its storage is relocated to the `askpass_program` field in `struct repo_config_values`. The field is initialized to `NULL` in `repo_config_values_init()`, freed in `repo_config_values_clear()`, and accessed directly via `repo_config_values(the_repository)->askpass_program` in `prompt.c`. The patch also updates the configuration parsing logic in `git_default_core_config()` to use the repository-specific field, ensuring the value is properly managed with `FREE_AND_NULL()` before reassignment.

The motivation is clear: global heap-allocated strings are a blocker for libification, introducing thread-safety issues in multi-repo environments. This patch aligns `askpass_program` with the pattern established for `editor_program` and `pager_program` in earlier patches, centralizing memory management and preparing the codebase for further modularization. The change is minimal and focused, touching only three files (`environment.c`, `environment.h`, and `prompt.c`) and preserving backward compatibility.
