This is a **design discussion reply** in the ongoing `--autosquash` bugfix thread. Phillip Wood responds to Yuxuan Chen’s objection to using an empty marker commit for a proposed `revert!` (or `drop!`) autosquash directive. Phillip now proposes a hybrid approach: a new `git revert --drop` option that creates a commit with the inverse patch *and* a `drop!` message, allowing `git rebase --autosquash` to later convert the target commit to a `drop` instruction and discard the `drop!` commit itself. This would avoid conflicts during the rebase while still reflecting the intended removal in the repository state before the rebase runs.

The discussion remains unresolved but has narrowed to a concrete technical trade-off: Yuxuan prioritizes semantic clarity and consistency with `git revert`, while Phillip prioritizes conflict avoidance and workflow ergonomics. The hybrid proposal attempts to bridge the gap, but no code has been written yet, and the original bugfix patch (handling `--empty` for `fixup!`/`squash!`) is still the immediate focus. The `revert!` directive remains a potential follow-up effort.
