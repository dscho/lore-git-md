This is the eighth patch in Patrick Steinhardt’s nine-patch v3 series introducing object filters to `odb_for_each_object()`. It adds a `filter` field to the `odb_for_each_object_options` struct, allowing callers to pass object filters to backends for optimization. The "packed" backend implementation uses this to skip excluded objects via bitmaps, improving efficiency by avoiding redundant enumeration of packs already covered by a bitmap.

The patch touches `odb.h`, `odb/source-packed.c`, `pack-bitmap.c`, and `pack-bitmap.h`. It introduces a new `bitmapped_for_each_object` callback in the packed backend, which uses the recently added `prepare_bitmap_git_for_source()` function (from patch 7/9) to open bitmaps exclusively for the current object source. This ensures objects are correctly attributed to their source and prevents misattribution or redundant enumeration. The backend skips packs already covered by a bitmap during iteration, and the patch also exposes `can_filter_bitmap()` (previously static) to allow backends to check if a filter can be optimized via bitmaps.

Taylor Blau’s review of this patch in v2 was surface-level, noting it "looks plausibly correct" but not engaging deeply with the technical details. The patch is part of the ODB abstraction effort and builds on earlier patches in the series, particularly the bitmap preparation logic introduced in patch 7/9. No new review feedback has emerged for this patch in v3, and the implementation aligns with the series’ goal of enabling `git cat-file --batch-all-objects` to work with pluggable object databases. The changes are mechanical and well-motivated, with no behavioral changes expected for end users.
