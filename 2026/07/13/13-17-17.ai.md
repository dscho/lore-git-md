This is a **bugfix and refactoring series** targeting the sequencer subsystem, specifically addressing the long-standing issue where `git rebase` incorrectly copies notes from dropped commits to the current HEAD. Phillip Wood’s v2 series, now reduced to 10 patches, is a systemic overhaul that fixes the core bug while simplifying the control flow in `sequencer.c` to prevent similar regressions.

The series is structured as a gradual refactoring followed by the core fix. Patch 1 restores test coverage for the "apply" backend, which was lost when the default rebase backend switched to "merge". Patches 2–8 are preparatory refactorings that simplify `pick_one_commit()` and `do_pick_commit()`, making the codebase more maintainable. Patch 9 introduces an enum to represent the result of picking a commit, replacing a boolean return value with a more expressive type. The final patch (10) adds a new enum member for dropped commits and modifies the sequencer to avoid recording them as rewritten, which prevents notes from being incorrectly copied.

Key technical details include the removal of redundant conditions in `pick_one_commit()`, the introduction of `enum pick_result` to clarify the outcome of commit picking, and the core behavioral change in patch 10, which ensures notes and post-rewrite hooks no longer receive misleading information about dropped commits. The series touches `sequencer.c` extensively, with test additions in `t3400-rebase.sh`, `t3404-rebase-interactive.sh`, and `t5407-post-rewrite-hook.sh`. The on-disk format remains unchanged.
