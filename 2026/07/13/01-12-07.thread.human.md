This thread is about a small but precise extension to Git's wire protocol: a new `no-ref-delta` capability that lets servers tell clients not to send `REF_DELTA` objects (type 7) in pushed packs. Taylor Blau posted the fourth and final patch in the series, which teaches `receive-pack` to advertise the capability and `send-pack` to honor it by passing `--no-ref-delta` to `git pack-objects`. The implementation is clean—just a boolean flag in `struct send_pack_args` and a command-line option—and comes with documentation and a test that verifies the client omits `REF_DELTA` objects when the server requests it.

The patch keeps `no-ref-delta` separate from `ofs-delta`, so servers can reject reference-based deltas without also having to support offset-based ones. The commit message doesn’t explain why a server might want this, but the separation hints at a use case where offset deltas are fine but reference deltas aren’t. So far, there’s no review feedback, so the series is still under initial consideration. If you’re tracking protocol changes, this is one to watch—it’s a narrowly scoped addition that could be useful for servers with specific delta-handling constraints.
