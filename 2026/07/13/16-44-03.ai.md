The change is **purely mechanical** and **internal**: it moves nine lines of code (the `repo_config_get_string()` call and its associated conditional block) into a separate function, reducing `graph_init()`’s complexity and preparing the codebase for future graph-related configuration options. The patch touches only `graph.c` (13 lines total: 9 added, 4 removed) and introduces no new edge cases, dependencies, or behavior changes. The new `graph_read_config()` function is called immediately at the start of `graph_init()`, preserving the existing initialization order.

This patch is **preparatory work** for patch 7/7, which introduces the `log.graphIndent` configuration variable to control the new indentation feature. By isolating configuration reading into its own function, the series maintains a clean separation of concerns and avoids cluttering `graph_init()` with additional config lookups. The commit message explicitly states this intent, and the implementation aligns with the series’ overall goal of modular, maintainable code.
