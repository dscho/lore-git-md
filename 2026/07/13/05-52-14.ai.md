This is the eleventh patch in Patrick Steinhardt’s twelve-patch series **"Make ODB optimizations pluggable"**, which refactors Git’s object database housekeeping to support pluggable backends. This patch fixes signedness issues in three ODB-related functions to prevent compiler warnings when the code is relocated to `odb/source-files.c` in the next (and final) patch.

The changes are mechanical and targeted: `too_many_loose_objects()` now bails early if the input `limit` is non-positive, avoiding a comparison between a signed limit and an unsigned object count; `find_base_packs()` casts the pack size to `uintmax_t` when comparing against the (unsigned) limit; and `odb_optimize()` casts `gc_auto_pack_limit` to `unsigned long` when comparing against `keep_pack.nr`. The commit message explains each fix’s rationale and confirms the changes are safe (e.g., `gc_auto_pack_limit` is guaranteed positive in the relevant code path). No behavioral changes are intended, and the patch preserves all existing logic, including the quirky 256-multiple rounding of the loose-object threshold.

This is a prerequisite for the final patch’s relocation of the ODB optimization logic into the "files" backend, ensuring clean compilation in the new context. The fixes are uncontroversial and align with the series’ focus on mechanical correctness. Reviewers may wish to verify the casts do not introduce edge cases in pack selection or memory estimation, though the commit message explicitly addresses these concerns.
