This is part of Patrick Steinhardt’s 12-patch series **"Make ODB optimizations pluggable"**, specifically patch 7/12. The patch introduces `struct odb_optimize_options` to encapsulate all settings related to object database (ODB) optimization, decoupling them from the monolithic `struct gc_config`. This is a refactoring step toward making ODB housekeeping logic pluggable across different backends.

The patch defines a new structure with fields for repack depth, window size, prune expiration, cruft pack handling, and backend-specific options like `keep_largest_pack`. It also introduces an `enum odb_optimize_flags` for boolean settings (e.g., `ODB_OPTIMIZE_VERBOSE`, `ODB_OPTIMIZE_AUTO`). The existing `maintenance_task_odb()` helper is refactored to construct an `odb_optimize_options` instance and delegate to a new `odb_optimize()` function, which centralizes the repack and prune logic. The `maintenance_task_geometric_repack()` helper is similarly updated to use the new structure.

This is a mechanical refactoring with no intended behavioral changes. The patch preserves all existing logic, including geometric repack split factors, cruft pack handling, multi-pack-index writes, and auto-condition checks. The motivation is to isolate ODB-specific settings from the generic `gc_config` struct, enabling future backends to define their own optimization strategies. The commit message notes that some backend-specific options remain in the structure as a pragmatic concession to retrofitting abstractions onto existing code.

The patch is well-structured and clearly motivated, with thorough test coverage in earlier patches ensuring no regressions. It is uncontroversial and aligns with the series’ goal of modularizing ODB optimizations. Reviewers may focus on verifying that the new structure correctly encapsulates all relevant settings and that the refactored call sites maintain identical behavior.
