This is the first patch in Patrick Steinhardt’s nine-patch v3 series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch improves object lookup efficiency during enumeration in the packed backend by using index-provided pack and offset data directly, replacing redundant calls to the generic `odb_source_read_object_info()` function. It also renames the `store` variable to `source` for clarity.

The change targets `odb/source-packed.c` and modifies two helper functions—`for_each_prefixed_object_in_midx()` and `for_each_prefixed_object_in_pack()`—to call `packed_object_info()` directly instead of delegating to `odb_source_read_object_info()`. This avoids a second index traversal and ensures objects are looked up in the correct pack, even if they exist in multiple packs. The patch also adds a `data->request` check to the `if (opts->flags)` condition to ensure the pack is populated before calling `packed_object_info()`.

Review feedback from v2 identified a performance inefficiency in this patch: the current implementation aborts iteration on the first non-match, mitigating the inefficiency, but the loop’s scope (full MIDX chain vs. primary MIDX) remains ambiguous. Patrick deferred Taylor Blau’s proposed optimization (using the OID fanout chunk to narrow the iteration range) to a separate series, leaving the current implementation as "not incorrect, merely suboptimal." The surface-level nit about mixing the `store` → `source` rename with the object lookup logic remains open but is minor and does not block progress.

The patch is a straightforward refactoring with no behavior changes, but it lays the groundwork for later patches in the series by ensuring object lookups during enumeration are both correct and efficient.
