Core problem or goal
Fix two race conditions in Git’s HTTP transport packfile URI mechanism that can corrupt temporary packfiles or cause spurious failures when multiple Git processes fetch the same packfile URI into a shared object database.

Current status
Under review; no prior versions. Patch 1/2 changes temporary file staging to use unique paths, preventing concurrent corruption. Patch 2/2 updates `fetch-pack` to accept either `pack<TAB><hash>` or `keep<TAB><hash>` from `index-pack` and ensures only process-local `.keep` files are removed.

New behavior: packfile URI downloads now write to unique temporary files; `fetch-pack` accepts both `pack` and `keep` success lines from `index-pack`
On-disk format: unchanged
