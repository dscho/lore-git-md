This is the third patch in Phillip Wood’s 10-patch series fixing how `git rebase` handles dropped commits, with a focus on **external merge strategy failures**. The patch tightens error handling in the sequencer when an external merge tool exits with a non-zero status other than 1 (conflicts). Previously, any non-zero exit code was treated as a conflict, but some codes (e.g., 2) signal unrecoverable failures—like overwriting untracked files—that should abort the current pick and reschedule it. The patch also ensures the sequencer reschedules the pick if the commit message cannot be written, preventing a silent failure.

The change is small but critical: it modifies `do_pick_commit()` in `sequencer.c` to distinguish between merge conflicts (exit code 1) and other failures (exit codes ≠ 0 or 1), returning -1 to trigger rescheduling. A new test in `t3404-rebase-interactive.sh` verifies this behavior by simulating a merge tool that exits with code 2, confirming the pick is rescheduled rather than treated as a conflict.

This patch is part of the series’ broader goal of ensuring the rebase machinery correctly handles all edge cases where commits are dropped—whether due to empty changes, fixups, or now, external merge failures. The fix is well-motivated and tested, addressing a real-world scenario where users might otherwise lose work or see unexpected behavior. The series is queued in Junio’s tree and looks ready to land.
