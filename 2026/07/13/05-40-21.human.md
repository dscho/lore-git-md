This is Junio’s "What’s cooking in git.git" report for July 2026 (#05), summarizing the state of all in-flight topics. It is not a patch itself, but a high-level digest of the project’s integration pipeline.

The report lists 50+ topics currently cooking in Junio’s tree, grouped by their integration status: graduated to `master`, new topics needing review, stalled topics, and actively cooking topics. Key highlights:

- **Graduated to `master`**: A handful of small fixes and cleanups, including a fix for `unpack-trees` quadratic performance, Coverity NULL-safety fixes, and a clarification in the 2.55 release notes about Rust support (enabled by default but still optional).

- **New topics needing review**:
  - `js/pack-objects-delta-size-t` widens object-size fields from `unsigned long` to `size_t` to avoid truncation on 64-bit Windows.
  - `pz/fetch-submodule-errors-config` adds `fetch.submoduleErrors` to make submodule fetch errors non-fatal.
  - `gr/add-e-use-apply-api` refactors `git add -e` to use the internal apply API instead of spawning a subprocess.
  - `fz/rebase-autosquash-empty` teaches `git rebase --autosquash` to respect `--empty` when a fixup/squash empties its target.

- **Stalled topics**: Several long-running efforts (e.g., `kh/doc-trailers`, `sn/rebase-update-refs-symrefs`) are stalled awaiting author response.

- **Actively cooking topics**:
  - `ps/odb-pluggable-housekeeping` refactors `git gc` to make ODB housekeeping pluggable, a key step toward alternative ODB backends.
  - `ps/refs-wo-the-repository` continues the `the_repository` removal effort, this time targeting the ref subsystem.
  - `ps/odb-for-each-object-filter` teaches `odb_for_each_object()` to accept object filters, enabling bitmap optimizations in `git cat-file --batch-all-objects`.
  - `jt/receive-pack-use-odb-transactions` refactors `git receive-pack` to use ODB transactions instead of `tmp_objdir`.
  - `hn/history-squash` adds a `squash` subcommand to the experimental `git history` command.
  - `kk/merge-base-exhaustion` optimizes merge-base computation by terminating early when one side’s commits are exhausted.

The report also notes a few discarded topics (e.g., `kk/prio-queue-cascade-sift`, retracted after performance concerns).

For a busy reader, the most consequential topics are the ODB pluggability work (`ps/odb-pluggable-housekeeping`), the ref subsystem refactoring (`ps/refs-wo-the-repository`), and the submodule fetch error handling (`pz/fetch-submodule-errors-config`). The rest are mostly incremental improvements or fixes.
