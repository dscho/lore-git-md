Thread identity: Bugfix for HTTP packfile URI download race condition (concurrent corruption).
Series version: single patch (no versioning).
Originating author: Ted Nyman.
Thread type: bug report and fix.

Core problem or goal: Fix a race condition in Git’s HTTP transport layer where two concurrent `git http-fetch` processes downloading the same packfile URI can corrupt the temporary file by writing to the same deterministic path (`objects/pack/pack-<hash>.pack.temp`). The fix replaces the deterministic naming scheme with Git’s tempfile API, generating unique temporary files (`objects/pack/tmp_pack_XXXXXX`) for packfile URI downloads, eliminating the race but sacrificing resumability for this download mode.

Current status: Under review. No prior versions or merge status recorded.

Key technical details:
- Files touched: `http.c`, `http.h`, `Documentation/git-http-fetch.adoc`.
- New/renamed symbols: `tempfile` field added to `struct http_pack_request`; new helper function `new_http_pack_request_for_url` with a `resumable` flag to distinguish packfile URI downloads (non-resumable) from dumb HTTP pack requests (resumable).
- Behavior change: Packfile URI downloads now use unique temporary files, preventing concurrent corruption but losing resumability. Dumb HTTP pack requests retain the old deterministic path behavior.
- On-disk format: No changes; temporary files are transient and not part of the repository.
- Test coverage: New test in `t/t5550-http-fetch-dumb.sh` verifies the fix by pausing one download mid-flight and starting a second process, ensuring both succeed without corruption or leftover temporary files.

Open questions and loose ends: None identified. The patch is narrowly scoped, well-motivated, and includes a thorough test. The trade-off (sacrificing resumability for correctness) is justified by the low likelihood of large packfile URI downloads and the severity of concurrent corruption.
