This is a **bugfix series** targeting the sequencer subsystem, part of the broader effort to correct how `git rebase` handles dropped commits. Phillip Wood’s v2 addresses feedback on his earlier 11-patch series, squashing minor fixes, merging two preparatory patches, and adding Uwe Kleine-König’s Tested-by. The series now consists of 10 patches that methodically refactor the sequencer’s control flow before introducing the core fix in the final patch.

The problem is straightforward: when `git rebase` drops a commit (e.g., because its changes are already upstream), the sequencer incorrectly records it as rewritten, causing notes from the dropped commit to be copied to the current HEAD and misleading post-rewrite hooks. The series fixes this by introducing an enum to represent the result of picking a commit, adding a new `PICK_RESULT_DROPPED` member, and modifying `pick_one_commit()` to skip `record_in_rewritten()` for dropped commits.

The refactoring is incremental and well-motivated. Patches 1–8 simplify control flow in `pick_one_commit()` and `do_pick_commit()`, addressing edge cases like external merge failures and failed commits. Patch 9 converts `do_pick_commit()`’s return type to an enum, and patch 10 uses this enum to prevent dropped commits from being recorded as rewritten. The series also restores test coverage lost when the default rebase backend switched from "apply" to "merge" and expands tests to cover fixup sequences, external merge failures, and post-rewrite hook behavior.

Phillip’s response to feedback is pragmatic. He squashed Junio’s typofixes and Oswald Buddenhagen’s suggested patch merge, but declined to widen the enum’s scope further, arguing that the current approach is sufficient and avoids unnecessary churn. The series is now queued in Junio’s tree and looks ready for merging. It directly addresses the technical debt in the rebase machinery and is a clear improvement over Uwe’s original patch, which is now functionally redundant. The only known limitation—a minor issue with the "edit" command—is documented and flagged for a separate fix. This is a **substantive, tested-level contribution** that merits attention.
