This is a feature patch introducing a new `--no-ref-delta` option to `git pack-objects`. It is the second patch in a four-patch series from Taylor Blau.

The patch teaches `git pack-objects` to avoid writing `REF_DELTA` entries in the output pack. `REF_DELTA` entries reference their base object by its full object ID, which can be problematic for consumers that want to avoid building an index of object IDs (e.g., a `receive-pack` implementation that retains the pack without indexing it). The new option disables `REF_DELTA` while preserving `OFS_DELTA` (which references bases by their offset within the same pack). When used without `--delta-base-offset`, no deltas are emitted at all, so delta search is skipped entirely.

The implementation disables delta reuse and bitmap reuse under `--no-ref-delta` to avoid copying existing `REF_DELTA` entries, though the commit message notes this is overly pessimistic and the next patch in the series will re-enable reuse in safe cases. The patch adds the option to the command-line parser, updates the delta search logic to respect the new flag, and includes three new tests in `t/t5300-pack-object.sh` covering: (1) packs with no deltas at all, (2) packs with only `OFS_DELTA`, and (3) thin packs where excluded bases would normally force `REF_DELTA`.

The patch is narrowly scoped, well-tested, and clearly motivated. It touches only the pack-objects subsystem and does not affect other parts of Git. The commit message and code are both precise and self-contained.
