This is the final patch in Phillip Wood’s 10-patch series fixing a long-standing bug in `git rebase` where notes from dropped commits were incorrectly copied to the current HEAD. The patch introduces the core behavioral change: commits dropped during rebase (due to empty changes, fixup sequences, or other reasons) are no longer recorded as rewritten, preventing notes and post-rewrite hooks from receiving misleading information.

The fix adds a new `PICK_RESULT_DROPPED` enum value to `do_pick_commit()` and modifies `pick_one_commit()` to skip `record_in_rewritten()` for dropped commits. A key edge case is handled: if the dropped commit is the final one in a fixup chain, the list of rewritten commits is flushed to avoid leaving stale state. The patch also adjusts the behavior of the "edit" command so that `rebase --continue` no longer amends the previous pick when the commit is dropped, though a known limitation remains where such commits are still erroneously recorded as rewritten—this is flagged in the code comment for a future fix.

Test coverage is expanded in `t3400-rebase.sh` to verify that notes from dropped commits are not copied, and in `t5407-post-rewrite-hook.sh` to confirm the hook receives accurate data for fixup sequences and empty commits. The commit message clearly documents the behavioral change and the known limitation, satisfying Junio’s earlier request for clarity.
