This is the third patch in Phillip Wood’s 10-patch v2 series fixing how `git rebase` handles dropped commits. It targets a specific edge case in the sequencer: **external merge strategies that fail for reasons other than conflicts** (e.g., untracked file overwrites, permission errors, or merge tool crashes).

The patch modifies `do_pick_commit()` in `sequencer.c` to distinguish between three outcomes of `try_merge_command()`:
- Exit code 0: merge succeeded (no action needed).
- Exit code 1: merge had conflicts (handled as before).
- Any other non-zero exit code: merge failed unrecoverably (now treated as an error, returning `-1` to reschedule the pick).

It also adds a guard to reschedule the pick if the commit message cannot be written to `git_path_merge_msg()`, preventing a silent failure. The test in `t3404-rebase-interactive.sh` verifies this behavior by mocking a merge tool that exits with code 2, ensuring the commit is rescheduled rather than dropped.

This is a **substantive bugfix** with clear test coverage, addressing a gap in the sequencer’s error handling. The change is minimal and well-motivated, fitting neatly into the series’ broader goal of ensuring dropped commits are handled consistently across all rebase operations. No controversy or follow-up discussion is evident in this patch alone.
