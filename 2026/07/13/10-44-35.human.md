This is the **v10 revision** of Pablo Sabater’s feature series introducing **visual root indentation** for `git log --graph`. The series is now **complete and ready for final review**, addressing all previously unresolved design and usability concerns.

The core problem remains: when `git log --graph` filters out parents (via `--author`, `--grep`, or other filters), commits can appear vertically adjacent to unrelated commits, creating misleading visual relationships. This series fixes that by **indenting visual roots** (commits that look like roots because their parents are excluded) to clarify their independence. The indentation **cascades** for consecutive visual roots, resetting after four levels to avoid excessive indentation while maintaining clarity.

Key improvements in v10:
- **Four-level wrapping** (new patch 5/7) implements the agreed-upon design, preventing symmetry-induced ambiguity in edge cases (e.g., when the number of visual roots is a multiple of 3 or 4). This was the last major usability decision left unresolved in v9.
- **Opt-out mechanism** (new patch 7/7) adds a `--[no-]graph-indent` flag and a `log.graphIndent` configuration variable, allowing users to disable indentation if desired. This addresses concerns about forced visual changes in non-oneline formats (e.g., `--format=fuller`).
- **Config separation** (new patch 6/7) moves configuration reading into a dedicated `graph_read_config()` function, simplifying `graph_init()` and improving code organization.

The series is now **seven patches long**, with the first four unchanged from v9:
1. Test infrastructure cleanup (moving `check_graph` helper) – already merged.
2. Unified lookahead population via `next_commit_to_show()` in `revision.c`.
3. Lookahead buffer implementation in `graph.c` and `revision.c`.
4. Visualization logic with cascading indentation.
5. **New**: Four-level wrapping for cascading commits.
6. **New**: Separate config reading into `graph_read_config()`.
7. **New**: `--[no-]graph-indent` flag and `log.graphIndent` config.

The **architectural foundation** (a two-slot lookahead buffer populated by `next_commit_to_show()`) remains robust and compatible with ongoing work like Jeff King’s `revs->commits` removal and Kristofer Haugsbakk’s `kk/prio-queue-get-put-fusion`. The series is **technically complete**, with all known edge cases addressed, including the late-stage fix for filters like `--author` and `--grep` that exclude commits after enqueuing.
