This thread is about a bugfix for a race condition in Git’s HTTP transport layer, specifically affecting packfile URI downloads. Ted Nyman identified that concurrent `git http-fetch` processes can corrupt temporary files when downloading the same packfile into a shared object database. The issue arises from a deterministic temporary file naming scheme introduced in 2020, which uses the pack hash to derive the path. The fix replaces this with Git’s tempfile API, generating unique temporary files to prevent clashes, though this sacrifices resumability for packfile URI downloads—a trade-off deemed acceptable given the feature’s limited usage and the severity of the corruption risk.

The patch modifies `http.c` and `http.h`, introducing a `tempfile` field to `struct http_pack_request` and refactoring the request-creation logic into a new helper function. Documentation and a new test in `t/t5550-http-fetch-dumb.sh` verify the fix. The change is narrowly scoped to packfile URI downloads, avoiding disruption to the more widely used dumb HTTP path. So far, the patch appears uncontroversial, with no review feedback yet—it’s a clean, well-motivated fix for a real problem.
