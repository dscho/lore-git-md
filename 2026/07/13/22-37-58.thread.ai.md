Thread identity: Bugfix series for packfile URI download race conditions in Git's HTTP transport. Series version: v3 (reroll). Originating author: Ted Nyman. Thread type: patch series (bugfix).

Core problem or goal: Fix race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack into a single object database. The races can corrupt temporary pack files or cause resume requests to fail at EOF. The series provides a unified solution for both packfile URIs and dumb HTTP, preserving resumable downloads while preventing corruption by using deterministic staging paths opened in read-write mode without append, ensuring overlapping responses write identical bytes at identical offsets.

Current status: Rerolled (v3) under review. The v3 series consists of three patches:
- Patch 1: Preliminary cleanup correcting the `--index-pack-arg` option name in `Documentation/git-http-fetch.adoc` and `http-fetch.c` error messages (plural `args` -> singular `arg`), addressing Junio C Hamano's review feedback. No behavioral changes; purely textual.
- Patch 2: Uses deterministic staging paths for both packfile URIs and dumb HTTP, preserving resumable downloads. Handles concurrent unlink scenarios (including Windows sharing behavior) and fixes the EOF-range/416 case. The core change in `http.c` switches from append mode to read-write mode with per-descriptor offsets, ensuring overlapping responses write identical bytes at identical offsets. Test coverage includes new regression tests in `t/t5550-http-fetch-dumb.sh` and a deterministic overlapping-download test using a custom Perl server.
- Patch 3: Makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, validating the reported pack hash against the advertised hash and only registering a keep lockfile when the current process created it (`created_keep` flag). The patch adopts Peff’s suggested `strbuf` refactor for clarity, replaces the fixed-size `packname` buffer, and adds a regression test in `t/t5702-protocol-v2.sh` exercising packfile URI fetches with pre-existing `.keep` files.

Changes since v2:
- Split the `--index-pack-args` documentation and error-message typo fixes into Patch 1, keeping functional changes in Patches 2–3 clean.
- Patch 2 now clarifies the rationale for per-descriptor offsets and MinGW's sharing behavior, and adds a regression test for unlinking the staging path while `index-pack` holds its descriptor (runnable on MinGW).
- Patch 3 adopts Peff’s `strbuf` refactor, replaces the fixed-size `packname` buffer with a more flexible approach, and adds a regression test for packfile URI fetches with pre-existing `.keep` files, verifying that existing `.keep` files are preserved and the pack hash is validated against the advertised hash.

Junio C Hamano reviewed the v2 series and suggested the preliminary cleanup split, which has been implemented. He expressed unease about the `pwrite(2)` approach but accepted the Windows/MINGW workaround. No technical objections to the core design remain.

A deterministic overlapping-download test uses a custom Perl server to verify pack integrity.

Concurrent processes write identical bytes at identical offsets, preventing corruption while maintaining resumability. The `.keep` file handling is more robust, with `fetch-pack` validating the pack hash and only registering a keep lockfile when the current process created it.
