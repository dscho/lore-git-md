Thread identity: Bugfix series for packfile URI download race conditions in Git's HTTP transport. Series version: v5 (reroll). Originating author: Ted Nyman. Thread type: patch series (bugfix), now in follow-up discussion phase.

Core problem or goal: Fix race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack into a single object database, preventing corruption while preserving resumable downloads. The series provides a unified solution for both packfile URIs and dumb HTTP using deterministic staging paths and read-write mode without append.

Current status: Entire series (three patches) **merged to Junio's `next` branch** (2026-06-10) and ready for graduation to `master`. Production code unchanged since v3; v5 contains only documentation clarifications and test robustness improvements. Patches:
- Patch 1: Merged to `next` – purely textual cleanup correcting `--index-pack-arg` option name in documentation and error messages.
- Patch 2: Merged to `next` – core fix using deterministic staging paths and read-write mode for both packfile URIs and dumb HTTP.
- Patch 3: Merged to `next` – makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, with hash validation and conditional keep lockfile registration.

HTTP 416 handling ensures correctness when a concurrent process completes the download before another issues its Range request.
