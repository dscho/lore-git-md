Thread identity: Bugfix series for packfile URI download race conditions in Git's HTTP transport. Series version: v5 (reroll). Originating author: Ted Nyman. Thread type: patch series (bugfix).

Core problem or goal: Fix race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack into a single object database. The races can corrupt temporary pack files or cause resume requests to fail at EOF. The series provides a unified solution for both packfile URIs and dumb HTTP, preserving resumable downloads while preventing corruption by using deterministic staging paths opened in read-write mode without append, ensuring overlapping responses write identical bytes at identical offsets.

Current status: Entire series (three patches) **merged to Junio's `next` branch** and ready for graduation to `master`. Production code unchanged since v3; v5 contains only documentation clarifications and test robustness improvements. Patches:

- Patch 3: Merged to `next` – makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, with hash validation and conditional keep lockfile registration.

Open questions and loose ends: None. Peff’s review raised three advisory points:
