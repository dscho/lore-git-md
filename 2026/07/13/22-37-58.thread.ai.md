Thread identity: Bugfix series for packfile URI download race conditions in Git's HTTP transport. Series version: v5 (reroll). Originating author: Ted Nyman. Thread type: patch series (bugfix).

Core problem or goal: Fix race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack into a single object database. The races can corrupt temporary pack files or cause resume requests to fail at EOF. The series provides a unified solution for both packfile URIs and dumb HTTP, preserving resumable downloads while preventing corruption by using deterministic staging paths opened in read-write mode without append, ensuring overlapping responses write identical bytes at identical offsets.

Current status: Rerolled (v5) with documentation clarifications and test robustness improvements; production code unchanged since v3. The series consists of three patches:
- Patch 1: **Merged to 'next'** -- Preliminary cleanup correcting the `--index-pack-arg` option name in `Documentation/git-http-fetch.adoc` and `http-fetch.c` error messages (plural `args` -> singular `arg`). The patch is purely textual, uncontroversial, and has been queued in Junio's `next` branch as of 2026-06-10. Documentation now clarifies that the first instance specifies the command and subsequent instances specify its arguments, resolving ambiguity noted in v4 reviews.
- Patch 2: **Merged to 'next'** -- Uses deterministic staging paths for both packfile URIs and dumb HTTP, preserving resumable downloads. The core change in `http.c` switches from append mode to read-write mode with per-descriptor offsets, ensuring overlapping responses write identical bytes at identical offsets. The patch handles concurrent unlink scenarios (including Windows sharing behavior) and updates `http-fetch.c`, `http-push.c`, and `http-walker.c` to accept HTTP 416 when a partial pack is already complete. Test coverage includes new regression tests in `t/t5550-http-fetch-dumb.sh` exercising resumed transfers, EOF ranges, overlapping 200/206 responses, unlinking the staging path while indexing, and a deterministic overlapping-download test using a custom Perl server with a 60-second timeout, FIFO waiter notification, and reliable server process cleanup. The test now passes 240 runs with 12 parallel `--stress` jobs, confirming the fix for the intermittent failure in test 34 (the `test -s` check and HTTP 200/206 trace greps were removed in v4).
- Patch 3: **Merged to 'next'** -- Makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, validating the reported pack hash against the advertised hash and only registering a keep lockfile when the current process created it (`created_keep` flag). The patch adopts Peff’s suggested `strbuf` refactor for clarity and adds a regression test in `t/t5702-protocol-v2.sh` exercising packfile URI fetches with pre-existing `.keep` files.
