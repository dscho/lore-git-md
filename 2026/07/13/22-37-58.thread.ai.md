Thread identity: Bugfix series for packfile URI download race conditions in Git's HTTP transport. Series version: v4 (reroll). Originating author: Ted Nyman. Thread type: patch series (bugfix).

Core problem or goal: Fix race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack into a single object database. The races can corrupt temporary pack files or cause resume requests to fail at EOF. The series provides a unified solution for both packfile URIs and dumb HTTP, preserving resumable downloads while preventing corruption by using deterministic staging paths opened in read-write mode without append, ensuring overlapping responses write identical bytes at identical offsets.

Current status: Rerolled (v4) with test robustness improvements only; production code unchanged since v3. The v4 series consists of three patches:
- Patch 1: **Merged to baseline** -- Preliminary cleanup correcting the `--index-pack-arg` option name in `Documentation/git-http-fetch.adoc` and `http-fetch.c` error messages (plural `args` -> singular `arg`), addressing Junio C Hamano's review feedback. The patch is purely textual, uncontroversial, and has no behavioral changes. It was split out at Junio's request and is now ready for merging as a clean baseline for the subsequent bugfix patches. Taylor Blau's surface-level review confirms the historical context (the plural form dates back to 2021 and was never accurate) and suggests minor documentation improvements: dropping the misleading claim about URL-encoded space-separated arguments and clarifying the distinction between the command name and its arguments. No test changes are needed since the option was never plural in practice.
- Patch 2: Uses deterministic staging paths for both packfile URIs and dumb HTTP, preserving resumable downloads. The core change in `http.c` switches from append mode to read-write mode with per-descriptor offsets, ensuring overlapping responses write identical bytes at identical offsets. The patch handles concurrent unlink scenarios (including Windows sharing behavior) by creating a missing partial pack exclusively, closing it, and reopening it without O_CREAT so every retained descriptor permits another downloader to unlink the staging path. It also updates `http-fetch.c`, `http-push.c`, and `http-walker.c` to accept HTTP 416 when a partial pack is already complete, and clarifies in `git-http-fetch` documentation that the staging key need not be the pack hash but must uniquely identify the pack contents for resumption. Test coverage includes new regression tests in `t/t5550-http-fetch-dumb.sh` exercising resumed transfers, EOF ranges, overlapping 200/206 responses, unlinking the staging path while indexing, and a deterministic overlapping-download test using a custom Perl server with a 60-second timeout, FIFO waiter notification, and reliable server process cleanup. HTTP 416 trace matching accounts for both older and current libcurl output formats.
- Patch 3: Makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, validating the reported pack hash against the advertised hash and only registering a keep lockfile when the current process created it (`created_keep` flag). The patch adopts Peff’s suggested `strbuf` refactor for clarity, replaces the fixed-size `packname` buffer with a more descriptive `packhash` variable, and adds a regression test in `t/t5702-protocol-v2.sh` exercising packfile URI fetches with pre-existing `.keep` files. The test verifies that the pack and index files are created, the `.keep` file is preserved unchanged, and the excluded blob is correctly fetched.

Changes since v3:
- Test robustness improvements only: the overlapping-download test server now includes a 60-second timeout, notifies FIFO waiters on failure, and tracks the server process for reliable cleanup. The test also waits for the second downloader first, ensuring an early failure cannot leave the server waiting indefinitely. HTTP 416 trace matching now accounts for both older and current libcurl output formats, avoiding false failures. No production code changes.

Junio C Hamano reviewed the v2 series and suggested the preliminary cleanup split, which has been implemented.
