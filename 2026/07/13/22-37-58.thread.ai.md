Thread identity: Bugfix series for packfile URI download race conditions in Git's HTTP transport. Series version: v6 (reroll). Originating author: Ted Nyman. Thread type: patch series (bugfix), now in focused follow-up refinement phase.

Core problem or goal: Fix race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack into a single object database, preventing corruption while preserving resumable downloads. The series provides a unified solution for both packfile URIs and dumb HTTP using deterministic staging paths and read-write mode without append, now split into six smaller, more focused commits for clarity and bisectability.

Current status: Series expanded to six patches, rebased onto current `master`, and ready for review. The core fix (v5 patches 2 and 3) is now broken into four commits addressing Peff’s post-acceptance advisory points: **Patch 2**: fixes a latent double-close bug in `finish_http_pack_request()` where `start_command()` already takes ownership of the staging-file descriptor (redundant `close()` removed); **Patch 3**: adds HTTP 416 handling for the case where a previous attempt completes the transfer but fails before indexing it; **Patch 4**: implements the core concurrent-download fix using deterministic staging paths and read-write mode (no append); **Patch 5**: handles Windows/MINGW sharing semantics (`O_EXCL` loop workaround). The final two patches (Windows sharing fix and `.keep` file race handling) remain unchanged from v5. All patches are **under review**; no merge status change since v5 (still not in `next` or `master`). Production code changes are minimal and confined to `http.c` and `fetch-pack.c`; documentation and tests are updated accordingly.
