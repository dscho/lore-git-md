Thread identity: Bugfix series for packfile URI download race conditions in Git's HTTP transport. Series version: v4 (reroll). Originating author: Ted Nyman. Thread type: patch series (bugfix).

Core problem or goal: Fix race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack into a single object database. The races can corrupt temporary pack files or cause resume requests to fail at EOF. The series provides a unified solution for both packfile URIs and dumb HTTP, preserving resumable downloads while preventing corruption by using deterministic staging paths opened in read-write mode without append, ensuring overlapping responses write identical bytes at identical offsets.

Current status: Rerolled (v4) with test robustness improvements; production code unchanged since v3. The v4 series consists of three patches:
- Patch 1: **Merged to baseline** -- Preliminary cleanup correcting the `--index-pack-arg` option name in `Documentation/git-http-fetch.adoc` and `http-fetch.c` error messages (plural `args` -> singular `arg`). The patch is purely textual, uncontroversial, and ready for merging. Taylor Blau's review confirms the historical context and suggests minor documentation improvements (dropping the misleading claim about URL-encoded space-separated arguments and clarifying the distinction between the command name and its arguments).
- Patch 2: Uses deterministic staging paths for both packfile URIs and dumb HTTP, preserving resumable downloads. The core change in `http.c` switches from append mode to read-write mode with per-descriptor offsets, ensuring overlapping responses write identical bytes at identical offsets. The patch handles concurrent unlink scenarios (including Windows sharing behavior) and updates `http-fetch.c`, `http-push.c`, and `http-walker.c` to accept HTTP 416 when a partial pack is already complete. Test coverage includes new regression tests in `t/t5550-http-fetch-dumb.sh` exercising resumed transfers, EOF ranges, overlapping 200/206 responses, unlinking the staging path while indexing, and a deterministic overlapping-download test using a custom Perl server with a 60-second timeout, FIFO waiter notification, and reliable server process cleanup. HTTP 416 trace matching accounts for both older and current libcurl output formats.
- Patch 3: Makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, validating the reported pack hash against the advertised hash and only registering a keep lockfile when the current process created it (`created_keep` flag). The patch adopts Peff’s suggested `strbuf` refactor for clarity and adds a regression test in `t/t5702-protocol-v2.sh` exercising packfile URI fetches with pre-existing `.keep` files.

Changes since v3:
- Test robustness improvements only: the overlapping-download test server now includes a 60-second timeout, notifies FIFO waiters on failure, and tracks the server process for reliable cleanup. The test also waits for the second downloader first, ensuring an early failure cannot leave the server waiting indefinitely. HTTP 416 trace matching now accounts for both older and current libcurl output formats, avoiding false failures. Peff reports that `--stress` testing of `t5550-http-fetch-dumb.sh` fails intermittently in test 34, with curl reporting "end of response with 1048917 bytes missing" and closing the connection prematurely. The server behaves identically in success and failure cases, but the second connection never arrives in the failing case. Peff’s latest analysis concludes this is a **false positive** caused by a race in the `test -s` check that verifies the first downloader has written data to disk before the second downloader starts. The `write()` call on the server side does not guarantee the client has received or flushed the data, so the test can spuriously fail even when the download logic is correct. Peff proposes **dropping the `test -s` check entirely** and removing the trace greps for HTTP 200/206 responses, as the deterministic staging path design makes the order of writes irrelevant. The test’s FIFO-based synchronization remains intact, ensuring the two downloaders run concurrently. No production code changes are involved; the fix is purely about test robustness.

Junio C Hamano reviewed the v2 series and suggested the preliminary cleanup split, which has been implemented. He expressed unease about the `pwrite(2)` approach but accepted the Windows/MINGW workaround. The v3 series was merged to `seen` but blocked by a test hang in `t5550-http-fetch-dumb.sh`; the v4 changes resolved this hang, but the series remains **blocked** until the test flakiness is resolved. No technical objections to the core design remain.
