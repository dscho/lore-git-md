This is the **visualization implementation patch (4/7)** in Pablo Sabater’s **v11 series** introducing **visual root indentation for `git log --graph`**. The patch adds the core logic that indents commits with excluded parents to clarify ancestry relationships in graph output, relying on the **lookahead buffer** (introduced in patch 3/7) to safely determine visual root status during revision traversal.

The implementation introduces a new `is_visual_root` flag in `struct git_graph` and a new graph state, `GRAPH_PRE_ROOT`, which prints an extra row to connect indented roots to their children. The indentation logic handles three key cases:
- **Single visual root with children**: prints a `GRAPH_PRE_ROOT` row to connect the child to the indented root.
- **Child-less visual root**: renders the indented commit directly.
- **Adjacent visual roots**: cascades indentation for each subsequent root, omitting indentation for the last root in a sequence to avoid ambiguity.

The patch also adds a new `is_merge_parent` flag to `struct column` to exclude non-first parents of merges from indentation, ensuring they remain visually connected to the merge commit. The indentation depth is calculated in `graph_output_commit_line()` using `(depth - cascade) * 2`, where `cascade` is a boolean that omits indentation for the first root in a sequence.

The **test coverage** in the new `t4218-log-graph-indentation.sh` file is extensive, verifying edge cases for single roots, cascading roots, merge parents, boundary commits, and filtering options (`--first-parent`, `--left-right`, `--max-count`, `--grep`/`--author`). The tests confirm that indentation is applied consistently to commit messages and descriptions, and that boundary commits (which inherit their child’s column) do not require indentation.

This patch is **ready for final review** and has no unresolved technical or usability questions. The lookahead buffer infrastructure (patch 3/7) and the four-level wrapping mechanism (patch 5/7) are prerequisites for this logic, but this patch itself is self-contained and does not introduce new dependencies. The only follow-up work noted is the **redundant-indentation edge case** (marked NEEDSWORK in v8), which remains documented but unaddressed in this revision.
