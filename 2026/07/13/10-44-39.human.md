This is the **core visualization patch** in Pablo Sabater’s **v10 series** implementing **visual root indentation for `git log --graph`**. It is the fourth of seven patches and introduces the actual indentation logic that makes unrelated commits no longer appear vertically adjacent to visual roots (commits with excluded parents).

The patch adds a new `GRAPH_PRE_ROOT` state to `struct git_graph` and wires it into the graph-rendering state machine. When a commit is identified as a visual root (via the helper `graph_is_visual_root()`), the renderer indents it by two spaces per level of adjacency, creating a cascading effect for consecutive visual roots. A new edge row (`GRAPH_PRE_ROOT`) is printed only when the visual root has children, ensuring the child remains visually connected to its parent. Merge parents (non-first parents of a merge) are explicitly excluded from indentation because they are already connected by an edge.

The test file `t4218-log-graph-indentation.sh` (514 lines) exercises every edge case: single roots, unrelated branches, merges, filtered parents, `--left-right`, `--first-parent`, `--max-count`, `--author`, `--grep`, and boundary commits. The tests confirm that indentation is applied consistently to commit messages, descriptions, and edge rows, and that the last visual root in a cascade is *not* indented to avoid unnecessary whitespace.

This patch is **ready for final review**; it has no unresolved technical questions and is part of a series whose design decisions (lookahead buffer, four-level wrap, opt-out mechanism) are already settled. The only remaining work is Junio Hamano’s and Phillip Wood’s sign-off on the new state and indentation logic.
