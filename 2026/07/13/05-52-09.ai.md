This is a refactoring patch in Patrick Steinhardt’s 12-part series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. It is the sixth patch in the v2 series and focuses on eliminating backend-specific configuration values from the generic `gc_config` struct.

The patch inlines eight configuration values (`gc_auto_threshold`, `gc_auto_pack_limit`, `repack_filter`, `repack_filter_to`, `big_pack_threshold`, `max_delta_cache_size`, `delta_base_cache_limit`) that are inherently tied to the "files" ODB backend. These values are now read directly at their call sites in `builtin/gc.c` rather than being stored in the generic `gc_config` struct. This change ensures that future ODB backends (e.g., reftable) do not need to handle or even be aware of "files"-specific settings, keeping the generic configuration clean and backend-agnostic.

The patch is a mechanical refactoring with no intended behavioral changes. All existing logic—including auto-condition checks, pack selection, memory estimation, and repack argument assembly—remains identical, only the location where configuration values are read has shifted. The diff shows the removal of these fields from `gc_config`, the elimination of their initialization and release logic, and their inlining at the specific call sites where they are used (e.g., `too_many_packs()`, `estimate_repack_memory()`, `add_repack_all_option()`, `need_to_gc()`, `maintenance_task_odb()`). The `gc_condition()` helper is also updated to drop its now-unused `gc_config` parameter.

This patch is a prerequisite for later patches in the series that relocate the entire ODB optimization logic into the "files" backend, ensuring that backend-specific details do not leak into the generic configuration layer. The change is uncontroversial and aligns with the series’ goal of modularizing ODB housekeeping. Reviewers may wish to verify that the inlined configuration reads do not introduce subtle edge cases in memory estimation or pack selection, though the patch maintains identical behavior to the original code paths.
