This is a bugfix patch for the packfile URI feature in Git's fetch-pack mechanism. It addresses a race condition where concurrent fetches can fail unnecessarily when downloading packfiles via URIs.

The issue stems from how `index-pack --keep` reports success: it outputs either `"keep<TAB><hash>"` (if it created the `.keep` file) or `"pack<TAB><hash>"` (if the `.keep` file already existed). Since commit dd4b732df7 (2020), `fetch-pack` has only accepted the `"keep"` form, causing failures when another process has already created the `.keep` file. The patch updates `fetch-pack` to accept both forms, only adding the `.keep` file to the cleanup list if it was created by the current process.

The change is minimal and targeted: it modifies the output parsing logic in `fetch-pack.c` to handle both success cases and adds a regression test in `t/t5702-protocol-v2.sh` that verifies the fix by pre-creating a `.keep` file and ensuring the fetch succeeds without modifying it. The test is well-structured and covers the edge case explicitly.
