This is a bugfix series targeting the packfile URI download mechanism. Two patches address race conditions that can corrupt temporary packfiles or cause fetch failures when multiple Git processes concurrently download the same pack into a single object database.

The first patch changes direct packfile URI downloads to use unique temporary files (named with a process-specific suffix) instead of the shared `pack-<hash>.pack.temp`. This prevents concurrent appends from corrupting the file. Regular dumb HTTP pack requests keep their existing resumable staging behavior, so only packfile URI retries start fresh downloads.

The second patch handles a related race around `.keep` files. When another process has already created the keep file, `index-pack` reports `"pack<TAB><hash>"` instead of `"keep<TAB><hash>"`. The patch makes `fetch-pack` accept both forms as success and only remove keep files it created itself. Both patches include regression tests for their respective races.

The series is narrowly scoped and well-motivated: the commit messages clearly describe the problems and the fixes. The changes are confined to the HTTP and fetch-pack subsystems, with no behavior changes for ordinary fetches. If you work with large repositories that use packfile URIs (common in monorepos), this is worth reviewing.
