This thread is about Taylor Blau’s patch series introducing a `no-ref-delta` capability to Git’s pack protocol, which would let receivers (like a write-through proxy) request packs containing only `OFS_DELTA` entries. The goal is to simplify asynchronous pack processing by avoiding the need for an object ID index upfront, which is critical for the proxy’s design—it spools incoming packs byte-for-byte and replays them upstream before allowing local ref updates. `REF_DELTA` entries complicate this by requiring OID lookups or a second pass, and their worst-case resolution order (a long delta chain depending on a late base) risks pipeline stalls.

The series is under review, with v1 posted but no consensus yet on the design. Jeff King (Peff) raised fundamental concerns about whether `no-ref-delta` is the right solution, suggesting a narrower “bases-before-deltas” capability instead. Taylor’s follow-up clarified the proxy’s reliance on offset-based addressing and the memory overhead of `REF_DELTA` resolution, but the discussion remains open on whether the stricter `no-ref-delta` approach is justified or if a more permissive capability could achieve the same performance goals with broader protocol compatibility. Key technical details include the proxy’s single-pass design, the trade-off between strict enforcement and flexibility, and the lack of on-disk format changes. No code changes or test updates have been introduced in this latest exchange.
