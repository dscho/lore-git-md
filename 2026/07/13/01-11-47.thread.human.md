This thread introduces a new `no-ref-delta` capability for Git's pack protocol, allowing receivers (like `receive-pack`) to request that senders (`send-pack`) avoid including `REF_DELTA` entries in generated packs. The goal is to simplify pack processing for receivers that don’t want to build an object ID index upfront, as `REF_DELTA` bases are harder to locate without one. The series is authored by Taylor Blau, a well-known contributor with deep expertise in Git’s pack subsystem, and consists of four patches.

The first patch adds a test helper (`test-tool pack-deltas`) to inspect delta representations, making it easier to verify the feature’s behavior. The second patch introduces the `--no-ref-delta` option in `pack-objects`, initially disabling delta and bitmap reuse for simplicity. The third patch re-enables safe reuse scenarios, addressing edge cases where delta reuse could inadvertently copy `REF_DELTA` entries. The final patch wires up the capability in the protocol, allowing `send-pack` to honor the receiver’s request.
