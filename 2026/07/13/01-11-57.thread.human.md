This thread is about a new `--no-ref-delta` option for `git pack-objects`, introduced by Taylor Blau in the second patch of a four-part series. The feature lets users generate packs without `REF_DELTA` entries—deltas that reference their base objects by full object ID—which can simplify pack processing for consumers like `receive-pack` that want to avoid building an object ID index. The option preserves `OFS_DELTA` (offset-based deltas) and, when combined with `--no-delta-base-offset`, disables all deltas entirely.

The implementation is conservative: it currently disables both delta reuse and bitmap reuse to prevent accidental inclusion of existing `REF_DELTA` entries, though the commit message acknowledges this is a temporary limitation and hints that the next patch will relax it. The patch adds the option to the command-line parser, updates the delta search logic, and includes three new tests in `t/t5300-pack-object.sh` to verify behavior with no deltas, `OFS_DELTA`-only packs, and thin packs.

So far, the patch is narrowly focused on the pack-objects subsystem, with no impact on other parts of Git. The code and commit message are clear and self-contained, and the motivation is well-justified. No reviews or objections have appeared yet, so the series is still in its initial proposal phase.
