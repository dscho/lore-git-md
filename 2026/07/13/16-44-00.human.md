This is the third patch in Pablo Sabater’s **v11 series** implementing **visual root indentation for `git log --graph`**. The series is now technically complete and awaiting final review.

This patch adds a **two-slot lookahead buffer** to `struct git_graph` so the graph renderer can safely peek ahead two commits during revision traversal. The buffer is managed as a FIFO queue: `get_revision()` pre-fetches up to two commits via `next_commit_to_show()` (introduced in patch 2/7) and stores them in the buffer, while `graph_pop_lookahead()` retrieves them when the graph needs to render the next commit. The patch also updates `graph_is_interesting()` to treat buffered commits as “interesting” so parent-child relationships are preserved.

The implementation is **mechanically clean** and **well-explained**: the buffer is initialized in `graph_init()`, the helper functions (`graph_pop_lookahead`, `graph_get_lookahead_room`, `graph_push_lookahead`) are simple and documented, and the BUG() assertions catch misuse. The only behavioral change is internal: `get_revision()` now pre-fetches commits when a graph is active, but this has no user-visible effect yet.

The lookahead architecture was **approved in principle** by Junio Hamano and Kristofer Karlsson in earlier rounds, and this patch faithfully implements that design. It is **stable since v7** and has not changed in v10 or v11. The next patch (4/7) will use the buffer to determine visual-root status before rendering.
