Subject: [PATCH 0/2] Fix race conditions in packfile URI downloads
Series version: v1 (initial submission)
Originating author: Ted Nyman <tnyman@openai.com>
Thread type: bugfix patch series

Core problem or goal
Fix race conditions in Git’s HTTP transport that can corrupt temporary packfiles or cause spurious failures when multiple Git processes concurrently fetch the same packfile URI into a single object database.

Current status
Under review; no prior versions. Two patches:
1. Use unique temporary files for each direct packfile URI download, preventing concurrent append corruption.
2. Make fetch-pack accept both `"pack<TAB><hash>"` and `"keep<TAB><hash>"` as valid success messages from index-pack and ensure only keep files created by the current process are removed.

Key technical details
Files touched: `http.c`, `http.h`, `fetch-pack.c`, `git-http-fetch.adoc`
New/renamed symbols: none
Behavior change: packfile URI downloads now use unique temporary files; success message parsing relaxed to tolerate concurrent keep-file creation.
On-disk format: unchanged
Test coverage: regression tests added to `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`
