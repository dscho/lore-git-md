This is the fourth patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`. It addresses a latent bug in the bitmap iteration code: `for_each_bitmapped_object()` currently ignores the return value of its callback, making it impossible for callers to abort iteration early. This becomes problematic as the series prepares to lift bitmap iteration into the generic ODB infrastructure, where `odb_for_each_object()` expects callbacks to support early termination via non-zero returns.

The patch refactors `show_objects_for_type()` to propagate non-zero return values from the `show_reach` callback, allowing `for_each_bitmapped_object()` to abort iteration when requested. It also updates the two callbacks that previously returned non-zero—`add_object_entry_from_bitmap()` in `builtin/pack-objects.c` and `show_object_fast()` in `builtin/rev-list.c`—to always return 0, preserving their existing behavior while aligning with the new early-termination capability. The change is mechanical and focused, touching only the bitmap iteration logic in `pack-bitmap.c` and its callers.

This patch is a prerequisite for the later ODB integration (patch 8/9) and the final conversion of `git cat-file` (patch 9/9). The thread context confirms that the design question about callback return-value consistency—raised by Jeff King and Taylor Blau—has been resolved by leaving the existing traversal APIs unchanged, avoiding a large-scale refactoring. The patch itself is uncontroversial and well-motivated, with no unresolved feedback. It looks ready for integration.
