This is a feature patch series introducing a new `no-ref-delta` capability for `git send-pack`. The series, authored by Taylor Blau, teaches Git to avoid writing `REF_DELTA` entries in packfiles when the receiving end requests it, which can simplify processing for certain `receive-pack` implementations that want to retain incoming packs without building an object ID index.

The motivation is clear: some receivers may prefer to handle packs without resolving delta bases by object ID, making `REF_DELTA` entries inconvenient. The new capability is designed to be independent of `ofs-delta`, so disabling `REF_DELTA` doesn’t imply anything about `OFS_DELTA` support. The series carefully handles the complexity of delta reuse—both ordinary reuse (which rewrites headers) and bitmap-based reuse (which copies entries directly)—to ensure `REF_DELTA` entries are omitted when requested.

The patches are well-structured: the first adds a test helper to inspect delta representations, the second introduces the `--no-ref-delta` option in `pack-objects` (initially disabling reuse for simplicity), the third re-enables safe reuse scenarios, and the fourth wires up the capability in `send-pack`. The commit messages and code changes look thorough, with test coverage for both ordinary and multi-pack reuse cases.

This is a targeted, well-explained feature that addresses a specific need without overhauling existing behavior. The series appears ready for review and is likely to be uncontroversial, though the delta reuse logic in patches 2 and 3 may draw scrutiny from reviewers familiar with the pack subsystem.
