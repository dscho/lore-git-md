This is a feature patch introducing a new `--no-ref-delta` option to `git pack-objects`. Part 2 of a 4-patch series.

The patch teaches `git pack-objects` to avoid writing `REF_DELTA` entries in the output pack. `REF_DELTA` entries reference their base object by its full SHA-1, which can be problematic for consumers that want to process the pack without building an index of all object IDs. The new option ensures that any delta base must appear earlier in the same pack, making the pack self-contained without requiring external lookups.

The implementation disables delta reuse and bitmap reuse when `--no-ref-delta` is specified, since either could introduce existing `REF_DELTA` entries. The commit message acknowledges this is overly pessimistic but keeps the change simple; the next patch in the series will re-enable reuse in safe cases. The option is independent of `--delta-base-offset`, so `OFS_DELTA` entries (which reference their base by offset within the pack) remain allowed.

Tests verify that `--no-ref-delta` produces packs with no deltas at all when used without `--delta-base-offset`, and packs with only `OFS_DELTA` entries when both options are given. A third test confirms that `--no-ref-delta` correctly skips deltas whose bases are excluded (and thus would have to be `REF_DELTA`).

The patch is well-motivated and clearly explained. The commit message and tests leave no ambiguity about the intended behavior. It looks like a clean, focused addition that addresses a real need for pack consumers.
