This is the **core `--delete-merged` patch (5/7)** in Harald Nordgren’s long-running series to add safe automated branch cleanup. The email itself is a brief exchange about a **subtle edge case in the `--forked` filter**, but the patch it refers to is now **implementation-complete and ready for merging** after 18 revisions.

The patch adds the `git branch --delete-merged` command, which deletes local branches that are fully merged into their upstream while preserving branches that are still needed (checked-out, used as upstreams for unmerged branches, or explicitly opted out via `branch.<name>.deleteMerged=false`). The **refined stacked-branch protection** (abort-and-clear) ensures that deleting a branch clears its upstream config for any kept branches that depended on it, avoiding broken dependency chains. The command also supports `<branch>` arguments to limit deletion candidates, reusing the `--forked` filter machinery for consistency.

The edge case under discussion here is a **known limitation** in the `--forked` filter: branches without an explicit `branch.<name>.pushRemote` may be misclassified as "forked" when `remote.pushDefault` is set (e.g., in test environments). Phillip Wood proposes a **refined heuristic** that would simulate a push operation (apply push refspec, then fetch refspec) and only treat a branch as forked if the final ref does *not* match its upstream. This would better distinguish true forks from long-lived branches like `main`, `next`, and `seen`. Harald agrees the idea is sound and plans to implement it, but **this is not a blocker for v18**—it’s a forward-looking improvement that could be added later. The series remains **ready for merging** once the agreed mechanical fixes (flags cleanup in patches 2-4/7 and rejecting `--dry-run --quiet`) are applied.

The patch is **well-tested**, with coverage for stacked-branch protection, per-branch opt-out, `--dry-run` functionality, and edge cases like self-referential upstreams. Phillip Wood’s latest review suggested test improvements (comments, helper functions, redundant command removal, branch naming clarity), all of which have been incorporated. The test suite now explicitly configures `branch.main.pushRemote` to prevent `main` from being misclassified as forked, exposing the edge case as a **documented limitation** rather than a bug.

This is a **mature, user-ready feature** that addresses a real pain point (safe local branch cleanup) with careful attention to safety and workflow integration. The only remaining pre-merge tasks are mechanical fixes, not design changes.
