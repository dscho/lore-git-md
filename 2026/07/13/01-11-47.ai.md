This is a feature patch series introducing a `no-ref-delta` capability for Git's pack protocol. The series adds a new option to `git pack-objects` and a corresponding protocol capability that allows the receiver (`receive-pack`) to request that the sender (`send-pack`) avoid writing `REF_DELTA` entries in the generated pack. This is useful for receivers that want to process the pack without first building an object ID index, as it makes delta bases easier to locate.

The series is structured as four patches. The first patch adds a test helper (`test-tool pack-deltas`) to inspect delta representations, which simplifies testing the behavior of the new feature. The second patch introduces the `--no-ref-delta` option in `pack-objects`, initially disabling delta and bitmap reuse for simplicity. The third patch re-enables safe reuse scenarios, and the final patch wires up the new capability in the protocol, allowing `send-pack` to honor the receiver's request.

The commit messages are detailed and explain the technical challenges, particularly around delta reuse. Ordinary delta reuse can rewrite `REF_DELTA` entries as `OFS_DELTA` when the base is already in the output pack, but bitmap pack reuse requires careful inspection to avoid copying `REF_DELTA` entries directly. The series addresses these edge cases explicitly.
