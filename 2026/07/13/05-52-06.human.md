This is the third patch in Patrick Steinhardt’s 12-patch v2 series making Git’s object database (ODB) optimizations pluggable. The patch reorders maintenance tasks in `builtin/gc.c` so that worktree pruning and rerere garbage collection run *before* object optimizations (repacking and pruning), rather than after. The goal is to group all ODB-related tasks together, preparing for later patches that will move this logic into the "files" ODB backend.

The change is mechanical and uncontroversial. The commit message acknowledges a theoretical edge case—pruning worktrees before ODB optimizations could make objects unreachable that would otherwise have been kept alive—but dismisses it as negligible in practice. The reordering has no user-visible impact: all tasks still run, just in a different sequence. The patch is a prerequisite for the ODB abstraction effort, ensuring that backend-specific housekeeping logic can be cleanly relocated in later patches. No new symbols or behaviors are introduced; the diff simply moves two blocks of code upward in `cmd_gc()`.
