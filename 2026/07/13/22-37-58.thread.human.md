This thread is a bugfix series from Ted Nyman addressing race conditions in Git’s HTTP transport when multiple processes concurrently fetch the same packfile URI. The initial version used unique temporary files to prevent corruption but abandoned resumable downloads for packfile URIs, a trade-off that Junio and Peff found problematic. Ted now plans a reroll to preserve predictable partial-pack paths while preventing concurrent corruption, extending the fix to cover dumb HTTP as well.

The series touches `http.c` and `fetch-pack.c`, with new regression tests in `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`. The second patch, which makes `fetch-pack` tolerate concurrent `.keep` file creation, is now set to adopt Peff’s suggested `strbuf` refactor for clarity, though Ted notes a wrinkle with `transfer.fsckObjects` emitting extra lines that must not be consumed prematurely. No objections remain to the mechanical changes, and the reroll will also correct a documentation typo.

The open questions center on how the reroll will handle handoffs between processes, stale-file cleanup, and whether a unified coordination mechanism (e.g., lockfiles or Peff’s write-only file descriptor approach) will cover both packfile URIs and dumb HTTP. Junio has signaled that the current approach may not be acceptable for merging without a better resumability story, while Taylor Blau and Peff have provided targeted feedback on code clarity. The next version will likely be the one to watch for design convergence.
