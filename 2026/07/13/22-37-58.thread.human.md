This thread is about a two-patch bugfix series from Ted Nyman that fixes race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile via packfile URIs. The races could corrupt temporary pack files or cause resume requests to fail at EOF. The fixes introduce unique temporary files for each direct packfile URI download and make `fetch-pack` accept both forms of `.keep` file success messages, ensuring it only removes keep files it created itself.

The changes are narrowly scoped to the packfile URI download path, touching `http.c` and `fetch-pack.c` with new regression tests in `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`. The implementation is pragmatic and unlikely to affect backwards compatibility. The series is well-motivated and addresses edge cases that would primarily impact CI systems or automated tooling with concurrent fetches. No reviews or maintainer decisions have been posted yet, so the series is still under initial review.
