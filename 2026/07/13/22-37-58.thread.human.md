This thread is about a bugfix series (v4) from Ted Nyman that addresses race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The races could corrupt temporary pack files or cause resume requests to fail. The series provides a unified solution for both scenarios by using deterministic staging paths and read-write mode without append, ensuring overlapping responses write identical bytes at identical offsets while preserving resumable downloads.

The series consists of three patches. Patch 1, a preliminary cleanup fixing a documentation typo, is uncontroversial and ready to merge. Patch 2 implements the core fix, switching to deterministic staging paths and handling concurrent unlink scenarios. Patch 3 makes `fetch-pack` more robust in handling `.keep` files. The v4 reroll improved test robustness but revealed an intermittent `--stress` test failure in `t5550-http-fetch-dumb.sh`, initially thought to be a blocking issue. Jeff King (Peff) has since determined this is a false positive caused by a race in the test's synchronization logic, not a bug in the core logic. He proposes removing the problematic `test -s` check, which would unblock the series.

Key participants include Ted Nyman (author), Junio C Hamano (maintainer, initially skeptical but now satisfied with the design), Taylor Blau (reviewed patches, no substantive concerns), and Peff (deeply engaged, proposed test fix). The series is currently blocked pending agreement on Peff's test adjustment, but no technical objections to the core design remain. If the test fix is adopted, the series could proceed to Junio's `next` branch without further delays.
