This thread is a bugfix series from Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The series is now at version 5, with the first two patches already in Junio's `next` branch and this final patch completing the fix.

The core issue involves potential corruption of temporary pack files or failed resume requests during concurrent downloads. The solution uses deterministic staging paths and read-write mode without append to ensure overlapping responses write identical bytes at identical offsets, preserving resumable downloads while preventing corruption. This patch specifically makes `fetch-pack` more robust by accepting both `"keep"` and `"pack"` output from `index-pack`, validating the pack hash, and only registering a `.keep` lockfile when the current process created it.

The series has been thoroughly reviewed by Junio Hamano, Taylor Blau, and Jeff King, with all substantive concerns addressed. The test coverage is comprehensive, including new regression tests for both dumb HTTP and packfile URIs that exercise resumed transfers, EOF ranges, and concurrent download scenarios. The series is now ready for integration, with no open questions remaining.
