This thread is a bugfix series from Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI. The initial version used unique temporary files to prevent corruption but abandoned resumable downloads for packfile URIs—a trade-off that Junio and Peff found unacceptable, as resumability is a key feature goal. Ted now plans a reroll that will preserve predictable partial-pack paths while preventing concurrent corruption, extend the fix to dumb HTTP (which shares the same vulnerability), and address handoff and stale-file cleanup.

The series touches `http.c` and `fetch-pack.c`, with new regression tests covering the tempfile and `.keep` file races. Reviews from Taylor Blau and Peff approved the core logic but raised concerns about the resumability trade-off and suggested mechanical improvements. Peff’s latest follow-up focuses on a `strbuf` refactor for `fetch-pack`’s parsing logic to handle extra lines from `index-pack` when `transfer.fsckObjects` is enabled, though the choice of implementation is left to Ted. The reroll will also correct a documentation typo in `--index-pack-args`. No merge status is indicated; the series remains under review pending the revised design.
