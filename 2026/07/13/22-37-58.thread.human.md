This thread is a bugfix series from Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The v4 series, now under review, aims to fix these races while preserving resumable downloads by using deterministic staging paths and read-write mode without append.

The series consists of three patches. The first, a preliminary cleanup correcting a documentation typo, has been merged as a baseline. The second patch implements the core fix, ensuring overlapping responses write identical bytes at identical offsets, and includes extensive test coverage. The third patch improves `.keep` file handling in `fetch-pack`. While the v3 series was merged to `seen`, it was blocked by a test hang; v4 introduced robustness improvements to address this, but Jeff King (Peff) has now reported a new intermittent failure under `--stress` testing. The failure occurs in test 34, where the test expects a file to exist but it does not, despite the pack being indexed. Peff's analysis suggests the issue lies in premature connection closure by curl, exposing a latent race in the test's synchronization. The series remains blocked until this flakiness is resolved, as Junio Hamano has previously indicated the topic won't progress to `next` with unstable tests.

Key participants include Ted Nyman (author), Junio Hamano (maintainer), Taylor Blau (reviewer), and Peff, who has provided substantive feedback on both the design and test robustness. The series is uncontroversial in its core approach but requires further work to stabilize the test suite before it can advance.
