This thread is a bugfix series by Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The v6 series, now complete at six patches, is a focused refinement of the earlier v5 implementation, incorporating feedback from Jeff King (Peff) to split the core fix into smaller, more bisectable commits.

The series preserves resumable downloads while preventing corruption by using deterministic staging paths and read-write mode without append. Key changes include fixing a latent double-close bug, adding HTTP 416 handling for completed partial packs, implementing the core concurrent-download fix, and addressing Windows/MINGW sharing semantics. The final patch (v6 Patch 6) resolves a `.keep` file handling edge case in `fetch-pack.c`, ensuring it accepts both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack` and only registers `.keep` lockfiles when the current process created them.
