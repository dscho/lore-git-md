This thread is about a bugfix series (v4) by Ted Nyman that addresses race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The races could corrupt temporary pack files or cause resume requests to fail. The series provides a unified solution for both packfile URIs and dumb HTTP, using deterministic staging paths and read-write mode without append to ensure overlapping responses write identical bytes at identical offsets, preserving resumable downloads.

The series consists of three patches. Patch 1, a preliminary cleanup correcting a typo in `--index-pack-arg`, is uncontroversial and ready for merging. Patch 2 implements the core fix, switching to deterministic staging paths and handling concurrent unlink scenarios. Patch 3 makes `fetch-pack` more robust in handling `.keep` files. The v4 reroll improved test robustness, resolving a test hang in `t5550-http-fetch-dumb.sh`, but the series remains blocked by an intermittent `--stress` test failure in test 34. Jeff King (Peff) analyzed this failure and concluded it is a false positive caused by a race in the `test -s` check, not a bug in the core logic. He proposed dropping the `test -s` check and related trace greps, as the deterministic staging path design makes the order of writes irrelevant. Junio C Hamano has now endorsed this solution, agreeing that the check should be removed. No production code changes are needed; the next step is for Ted to reroll the series with the adjusted test. The core design has no remaining technical objections, and the series is otherwise ready to proceed.
