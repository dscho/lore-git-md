This thread is a bugfix series from Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI. The initial submission proposed using unique temporary files for each download to avoid corruption, but deliberately abandoned resumable downloads for packfile URIs—a trade-off that Junio C Hamano and Jeff King (Peff) found unacceptable, as resumability is a core goal of the feature.

Ted has now conceded that the initial approach was premature and plans to revise the design to preserve predictable partial-pack paths while preventing concurrent corruption. The new design will need to handle handoff scenarios (where one process takes over a stalled download) and stale-file cleanup (leftover `.pack.temp` files from crashed processes). Ted also noted that dumb HTTP shares the same concurrency vulnerability, hinting at a unified solution. The thread has shifted from a "fix first, optimize later" mindset to a more nuanced approach that balances correctness, coordination complexity, and user expectations.

Key participants include Junio (maintainer), who emphasized the importance of resumability; Peff, who proposed alternatives like write-only file descriptors or piping to `index-pack --stdin`; and Taylor Blau, who endorsed the initial approach but deferred to Junio’s final verdict. The series is not yet merged, and the next iteration will need to address these design concerns before proceeding. The second patch (tolerating both `"keep"` and `"pack"` output from `index-pack`) remains uncontroversial but may adopt Peff’s suggested `strbuf` refactor for improved readability.
