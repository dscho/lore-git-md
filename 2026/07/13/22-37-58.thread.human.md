This thread is about a bugfix series from Ted Nyman that addresses race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The series, now at version 5, has been fully merged into Junio's `next` branch and is ready for graduation to `master`.

The core issue involves potential corruption of temporary pack files or failed resume requests due to overlapping downloads. The solution uses deterministic staging paths and read-write mode (without append) to ensure concurrent processes write identical bytes at identical offsets, preserving resumable downloads while preventing corruption. The series consists of three patches: a documentation cleanup (merged), the main fix for both packfile URIs and dumb HTTP (merged), and a patch making `fetch-pack` more robust when handling `.keep` files (also merged).

Key participants include Ted Nyman (author), Junio C Hamano (maintainer), Taylor Blau, and Jeff King (Peff). Junio initially expressed skepticism about abandoning resumable downloads but accepted the current design after thorough review. Taylor Blau provided feedback on documentation and mechanical clarity, while Peff engaged deeply with the technical details, confirming the fix resolves earlier test failures. In the latest email, Peff raised no blocking concerns but noted some discomfort with the subtlety of the solution and identified a latent bug fix (a descriptor leak) that could be split into a separate commit for clarity. All feedback has been addressed, and the series is now stable in `next`.
