This thread is fixing race conditions in Git’s HTTP transport when multiple processes concurrently fetch the same packfile URI, which can corrupt temporary files or break resume requests. Ted Nyman’s initial two-patch series avoids cross-process coordination by giving each download its own temporary file, a trade-off that Junio C Hamano initially questioned for its redundancy but which Taylor Blau and Ted now defend as the simplest correct fix.

Jeff King (Peff) has just weighed in, suggesting the `.pack.temp` file could act as a lockfile using Git’s existing logic—auto-removing stale files or checking process liveness via PID. He also flags the inconsistency of abandoning resumable downloads for packfile URIs while preserving them for dumb HTTP, though he accepts the current approach as a short-term fix. The thread now agrees on “fix first, optimize later,” but Junio’s final call is still pending. No code changes have been requested yet; the discussion remains at the design level.
