This thread is about a bugfix series from Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The v3 series, now under review, consists of three patches that together provide a unified solution preserving resumable downloads while preventing corruption.

The core issue involves concurrent processes corrupting temporary pack files or failing resume requests at EOF. The fix uses deterministic staging paths opened in read-write mode without append, ensuring overlapping responses write identical bytes at identical offsets. Patch 1 is a preliminary cleanup fixing documentation and error message typos. Patch 2 implements the core fix with thorough test coverage, including new regression tests for resumed transfers, EOF ranges, and concurrent scenarios. Patch 3, the focus of this latest update, makes `fetch-pack` handle both `"keep"` and `"pack"` output from `index-pack`, adding validation of the pack hash against the advertised hash and only registering a keep lockfile when the current process created it.

Junio C Hamano reviewed earlier versions and suggested the cleanup split, while Jeff King (Peff) provided design feedback and a `strbuf` refactor that was adopted. Taylor Blau also reviewed parts of the series. The v3 series addresses all prior feedback, with no remaining open questions. The implementation is considered ready for serious review, with the latest patch specifically addressing a correctness issue in concurrent fetch scenarios without introducing backwards compatibility concerns.
