This thread is a bugfix series from Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The initial version used unique temporary files to prevent corruption but abandoned resumable downloads for packfile URIs, which drew skepticism from Junio and Peff. This reroll preserves resumability while fixing the races by using deterministic staging paths opened in read-write mode without append, allowing overlapping responses to write identical bytes at identical offsets. The solution now covers both packfile URIs and dumb HTTP, handles handoffs and stale-file cleanup, and includes thorough test coverage.

Ted has addressed all prior feedback: the design no longer sacrifices resumability, the implementation is cleaner (with Peff’s suggested `strbuf` improvements incorporated), and the documentation is corrected. The series touches `http.c` and `fetch-pack.c`, with new regression tests in `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`. Taylor Blau and Peff had previously reviewed the initial version favorably, and this reroll should resolve Junio’s concerns about the loss of resumability. The series appears ready for final review and is likely to be uncontroversial.
