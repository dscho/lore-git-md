This thread is a bugfix series from Ted Nyman addressing race conditions in Git’s HTTP transport when multiple processes concurrently fetch the same packfile URI. The races can corrupt temporary pack files or cause resume requests to fail. The series consists of two patches: the first modifies the HTTP layer to use unique temporary files for each packfile URI download, while the second handles a race condition with `.keep` files in `fetch-pack`.

The initial submission is under review, with key participants including Junio C Hamano, Taylor Blau, and Jeff King. The core design—using unique tempfiles to avoid cross-process coordination—has gained consensus as the correct trade-off for the immediate bugfix, despite Junio’s initial concerns about redundant downloads. Taylor Blau approved the logic, documentation, and test coverage of Patch 1, suggesting only a minor mechanical improvement. Jeff King’s latest review further tightens the cleanup code in `release_http_pack_request()`, clarifying ownership semantics around the `preq->packfile` handle and recommending the removal of a redundant `NULL` assignment. Patch 2, addressing `.keep` file races, has not yet received detailed feedback.

The series is technically sound and nearly ready for merging, pending Junio’s final verdict on the design trade-offs and the minor code cleanup suggested by Peff. Open questions include whether resumable downloads for packfile URIs should be preserved (and how) and whether the inconsistency with dumb HTTP’s resumable behavior introduces new edge cases. The regression tests in `t5550-http-fetch-dumb.sh` and `t5702-protocol-v2.sh` cover the tempfile and `.keep` file races, though the concurrent download test has not been deeply scrutinized.
