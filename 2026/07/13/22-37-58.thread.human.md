This thread is a bugfix series from Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The v4 series, now complete, consists of three patches and is ready for integration.

The core issue involves potential corruption of temporary pack files or failed resume requests due to concurrent downloads. The solution uses deterministic staging paths and read-write mode without append to ensure overlapping responses write identical bytes at identical offsets, preserving resumable downloads while preventing corruption. The first patch—a preliminary cleanup fixing a documentation typo—has already been merged as a baseline. The second patch implements the core fix for both packfile URIs and dumb HTTP, while the third (just summarized) ensures `fetch-pack` robustly handles pre-existing `.keep` files by accepting both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`.

Junio C Hamano reviewed earlier versions and requested the cleanup split, which Ted implemented. While Junio initially expressed unease about the `pwrite(2)` approach, he accepted the Windows/MINGW workaround. Jeff King (Peff) engaged deeply with the design trade-offs, and his suggestion to use `strbuf` for clarity was adopted in the final patch. Taylor Blau provided feedback on the first patch but hasn’t responded to later revisions. The v3 series was merged to `seen` but blocked by a test hang, which the v4 robustness improvements (timeout, FIFO waiter notification, and reliable cleanup) appear to have resolved. No technical objections remain, and the series is rebased onto current `master`. If the test suite passes cleanly, it should progress to `next`.
