This thread is a bugfix series by Ted Nyman addressing race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The series is now in its sixth iteration (v6), expanded to six focused patches after incorporating feedback from Jeff King (Peff) on post-acceptance advisory points.

The core issue is preventing corruption while preserving resumable downloads, and the v6 series now cleanly separates concerns: Patch 3 (the email just received) specifically handles HTTP 416 responses for cases where a resumed download is already complete but not yet indexed. This is a minimal, uncontroversial change that treats HTTP 416 as a non-failure status, deferring validation to `index-pack`. The patch includes a new regression test and touches only the HTTP transport callers without introducing new symbols or on-disk format changes.
