This is the second patch in Patrick Steinhardt’s 12-patch v2 series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. The patch addresses a long-standing inconsistency in the "pre-auto-gc" hook, which currently only intercepts the "gc" maintenance task despite its intended purpose of inhibiting *all* automated repository maintenance.

The change expands the hook’s scope to run exactly once before the first auto-maintenance task (foreground or background) that would execute, as determined by the task’s auto-condition. This ensures the hook can inhibit tasks like `reflog-expire`, `geometric-repack`, and `rerere-gc`, not just `gc`. The implementation lifts the `run_hooks()` call out of `need_to_gc()` and into `maybe_run_task()`, using a new `enum auto_gc_hook_result` to track whether the hook has run and whether it succeeded. The patch preserves the hook’s existing behavior for `git gc` and `git maintenance` without `--auto`, and adds comprehensive test coverage in `t/t7900-maintenance.sh` to verify the hook runs exactly once, can inhibit all tasks, and does not run when no maintenance is needed.

The patch is a targeted behavioral fix with no refactoring or relocation of code. It directly addresses Junio C Hamano’s feedback from v1, which endorsed the design goal of expanding the hook’s scope. The test suite now uses the new `test_maintenance_tasks` helper (introduced in patch 1) to robustly verify task execution via trace2 output, replacing the brittle `GIT_TRACE2_EVENT` checks from v1. No objections to the core change remain, and the patch is uncontroversial. Key symbols introduced: `enum auto_gc_hook_result` (`AUTO_GC_HOOK_UNDECIDED`, `AUTO_GC_HOOK_RUN`, `AUTO_GC_HOOK_SKIP`). Files touched: `builtin/gc.c` (35 lines added, 9 removed) and `t/t7900-maintenance.sh` (126 lines added). The patch is a prerequisite for the series’ broader goal of making ODB optimizations pluggable, as it ensures all backends can rely on a consistent housekeeping guard.
