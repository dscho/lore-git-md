This is a protocol extension patch adding a new `no-ref-delta` capability to the Git wire protocol. It is the fourth and final patch in a series (not seen in full here).

The patch teaches `receive-pack` to advertise the new capability and `send-pack` to honor it by passing `--no-ref-delta` to `git pack-objects` when the server requests it. The capability is kept separate from `ofs-delta`, allowing servers to reject `REF_DELTA` (type 7) objects without also having to support `OFS_DELTA` (type 6). Documentation is updated to describe the new capability, and a test verifies that the client correctly omits `REF_DELTA` objects when the server advertises `no-ref-delta`.

The implementation is straightforward: a new boolean field `no_ref_delta` is added to `struct send_pack_args`, populated when the server advertises the capability, and passed to `pack-objects` as a command-line flag. The test uses `GIT_TRACE2_EVENT` to confirm that the expected `pack-objects` invocation includes `--no-ref-delta`.

No motivation is given in the commit message for why a server might want to reject `REF_DELTA` objects, but the separation from `ofs-delta` suggests a use case where the server can handle offset-based deltas but not reference-based ones. The patch is small, well-contained, and includes both documentation and test coverage.
