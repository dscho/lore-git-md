This is the third patch in Patrick Steinhardt’s nine-patch series introducing object filters to `odb_for_each_object()`. It is a cleanup patch originally authored by Jeff King (Peff) that removes the unused `int` return value from `add_object_entry()` in `builtin/pack-objects.c`.

The patch is small and mechanical: it converts `add_object_entry()` from returning `int` to returning `void`, removing the now-dead code that checked its return value. The function’s return value has not been used since 2006 (commit `5379a5c5ee`), so this change is purely about code hygiene. The commit message explains that the cleanup aligns the function with its sister function, `add_object_entry_from_bitmap()`, which is about to change to always return 0 to conform to a callback interface. By removing the unused return value entirely, the patch makes it clear that the two functions have diverged in their semantics.

This patch was reviewed and endorsed by Junio C Hamano in an earlier iteration, and Patrick Steinhardt has integrated it into the series as patch 3/9. The change is uncontroversial and does not affect behavior or performance. It is a straightforward cleanup that reduces confusion about the function’s interface. The patch touches only one file (`builtin/pack-objects.c`) and is part of the broader ODB abstraction effort, though it stands alone as a self-contained improvement.
