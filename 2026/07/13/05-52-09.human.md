This is a refactoring patch in Patrick Steinhardt’s 12-patch series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. The patch inlines configuration values specific to the "files" ODB backend directly at their call sites in `builtin/gc.c`, removing them from the generic `struct gc_config`. This prepares the codebase for pluggable ODB backends by ensuring backend-specific details do not leak into shared structures.

The patch removes eight fields from `struct gc_config` (`gc_auto_threshold`, `gc_auto_pack_limit`, `repack_filter`, `repack_filter_to`, `big_pack_threshold`, `max_delta_cache_size`, and `delta_base_cache_limit`) and updates all functions that previously relied on these fields to read the configuration directly. The changes are mechanical and preserve existing behavior: the same configuration keys are read, the same default values are used, and the same logic applies. The patch also updates function signatures (e.g., `too_many_packs()` now takes an `int gc_auto_pack_limit` parameter instead of a `struct gc_config *`) and eliminates redundant config reads by consolidating them at the call sites where the values are needed.

This is a well-crafted refactoring with a clear motivation: isolating backend-specific configuration to enable pluggable ODB optimizations. The commit message explains the rationale, and the patch itself is clean and focused. No behavioral changes are intended, and the patch is uncontroversial. It is a prerequisite for later patches in the series that relocate the ODB optimization logic into the "files" backend. Reviewers may wish to verify that the inlined configuration reads do not introduce subtle edge cases in memory estimation or pack selection, but the patch maintains identical logic to the original code paths.
