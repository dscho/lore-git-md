This is the tenth patch in Patrick Steinhardt’s 12-patch series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. The patch refactors four ODB optimization helpers—`too_many_loose_objects()`, `find_base_packs()`, `too_many_packs()`, and `estimate_repack_memory()`—to operate on an explicit `struct odb_source_files *` parameter instead of implicitly using the global `the_repository`. This is a mechanical refactoring with no intended behavioral changes, preparing the code for the final relocation of the entire "files" source optimization logic into `odb/source-files.c` in patch 12.

The patch updates the function signatures to accept a `struct odb_source_files *files` parameter, replacing direct accesses to `the_repository->objects->sources` and `the_repository` with calls to `files->packed` and `odb_source_count_objects(&files->base, ...)`. The `find_base_packs()` helper is also updated to iterate over `packfile_list_entry` objects from `files->packed` instead of using `repo_for_each_pack()`. All existing logic—loose-object thresholds, pack selection, memory estimation, and promisor object handling—is preserved, with the only change being the source of the data (now passed explicitly rather than derived globally).

This patch is uncontroversial and aligns with the series’ goal of eliminating global state to enable pluggable ODB backends. Reviewers may wish to verify that the parameterized helpers do not introduce subtle edge cases in pack selection or memory estimation, though the patch maintains identical behavior to the original code paths. The next patch (11/12) will address signedness issues in these helpers to ensure clean compilation in their new context.
