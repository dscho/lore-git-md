This is a refactoring patch in the ODB abstraction series, specifically patch 5/9 of v3. It restructures how Git opens packfile and multi-pack-index (MIDX) bitmaps by iterating over object sources first, then attempting to load a bitmap for each source. The change is mechanical and preparatory: it enables a subsequent patch (8/9) to open bitmaps for a specific object source, which is necessary for the ODB-mediated filtering mechanism.

The patch reverses the loop order in `open_bitmap()`: previously, Git searched all sources for a MIDX bitmap, then all sources for a packfile bitmap; now, it iterates over each source and tries to load either a MIDX or packfile bitmap for that source. This introduces a subtle change in bitmap precedence: local packfile bitmaps now take precedence over MIDX bitmaps in alternates, which the commit message argues is an improvement since local sources are preferred.

Key symbols modified: `open_bitmap()` (now iterates per-source), `open_bitmap_for_source()` (new helper function), `open_pack_bitmap()` and `open_midx_bitmap()` (both removed in favor of the new helper). The patch also simplifies the logic in `open_bitmap()` by using a boolean (`found`) instead of an integer return value, and it improves trace2 reporting by breaking early when a bitmap is found and tracing is disabled.

The change is well-motivated and clearly explained in the commit message, which notes the edge case about bitmap precedence and justifies the new behavior. No unresolved review feedback targets this patch, and the restructuring is a prerequisite for the ODB filtering mechanism introduced later in the series.
