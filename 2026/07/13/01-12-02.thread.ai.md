Subject: [PATCH 3/4] pack-objects: allow delta reuse with --no-ref-delta when --delta-base-offset is given
Series version: v1 (four-patch series)
Originating author: Taylor Blau
Thread type: patch series

Core problem or goal
Relax an earlier over-conservative restriction that disabled all delta and bitmap reuse when `git pack-objects --no-ref-delta` was specified. The patch enables delta reuse for objects whose base appears earlier in the output pack, allowing them to be encoded as `OFS_DELTA` instead of `REF_DELTA`, while still disabling reuse for preferred bases and external thin-pack bases that require `REF_DELTA` encoding.

Current status
Under review. This is the third patch in a four-patch series; no prior version of this series has been recorded in the thread summary.

Key technical details
- Files touched: `builtin/pack-objects.c`, `pack-bitmap.c`
- New or renamed symbols: `allow_ref_delta` parameter added to the bitmap-reuse entry point and propagated through the call chain
- Behavior change: reused deltas whose base appears earlier in the output pack are now rewritten as `OFS_DELTA` when `--no-ref-delta` and `--delta-base-offset` are both given
- On-disk format: no change; the patch only affects which delta encoding is chosen
- Test coverage: `t/t5300-pack-object.sh` and `t/t5332-multi-pack-reuse.sh` verify that reused deltas are correctly rewritten and that bitmap reuse produces packs without `REF_DELTA` entries
