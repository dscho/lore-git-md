This is the eleventh patch in Patrick Steinhardt’s 12-part series **"Make ODB optimizations pluggable"**, a refactoring effort to modularize Git’s object database housekeeping. The patch fixes signedness issues in three ODB-related functions to prevent compiler warnings when the code is later moved into `odb/source-files.c` in patch 12.

The changes are mechanical and targeted: `too_many_loose_objects()` now bails early if the limit is non-positive (mirroring similar checks elsewhere), `find_base_packs()` casts a pack size to `uintmax_t` before comparing it to a limit, and `odb_optimize()` casts `gc_auto_pack_limit` to `unsigned long` when comparing it to `keep_pack.nr`. The fixes are safe because the problematic comparisons only occur in contexts where the values are known to be positive (e.g., `gc_auto_pack_limit` is only used when `too_many_packs()` returns true, which requires a positive limit).

The patch is uncontroversial and well-motivated: it ensures clean compilation in the new context without altering behavior. The commit message clearly explains each fix and why it is safe. This is a prerequisite for the final patch’s relocation of the optimization logic into the ODB backend, and the changes are narrow enough to avoid introducing subtle edge cases. Reviewers may still wish to verify the casts don’t mask unexpected negative values, but the logic appears sound.
