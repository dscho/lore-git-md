This is patch 10/12 in Patrick Steinhardt’s v2 series **"Make ODB optimizations pluggable"**, part of the ongoing ODB abstraction effort. The patch refactors four ODB optimization helpers—`too_many_loose_objects()`, `find_base_packs()`, `too_many_packs()`, and `estimate_repack_memory()`—to operate on an explicit `struct odb_source_files *` parameter instead of implicitly using the global `the_repository`. This is a mechanical refactoring with no intended behavioral changes, preparing the code for the final relocation of the entire "files" source optimization logic into `odb/source-files.c` in patch 12.

The patch updates the function signatures to accept a `struct odb_source_files *files` parameter, replacing direct accesses to `the_repository->objects->sources` and `the_repository` with dereferences of the passed-in `files` pointer. The `find_base_packs()` helper is updated to iterate over `files->packed` (via `packfile_store_get_packs()`) instead of using `repo_for_each_pack(the_repository)`, and `estimate_repack_memory()` now calls `odb_source_count_objects(&files->base, ...)` instead of `odb_count_objects(the_repository->objects, ...)`. All callers in `builtin/gc.c`—`odb_optimize()` and `odb_optimize_required()`—are updated to pass the downcast `files` pointer, preserving the existing logic for loose-object thresholds, pack selection, memory estimation, and geometric repacking.

The patch is uncontroversial and aligns with the series’ goal of eliminating global state to enable pluggable ODB backends. Reviewers may wish to verify that the parameterized helpers do not introduce subtle edge cases in pack selection or memory estimation, though the logic remains identical to the original code paths. The next patch (11/12) will address signedness issues in these helpers to ensure clean compilation in the new context.
