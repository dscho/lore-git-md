This is the **third patch in the v10 series** implementing visual root indentation for `git log --graph`. It introduces the **lookahead buffer infrastructure** in `struct git_graph` and wires it into the revision walk.

The patch adds a two-slot lookahead buffer (`lookahead[2]`) to `struct git_graph`, along with helper functions to push, pop, and query the buffer (`graph_push_lookahead`, `graph_pop_lookahead`, `graph_get_lookahead_room`). The buffer is populated by `get_revision()` in `revision.c`, which now pre-fetches up to two commits ahead when a graph is active, ensuring that `graph_peek_next_visible()` (used in later patches) can safely inspect future commits without violating the revision walk's invariants. The `graph_is_interesting()` function is updated to treat commits in the lookahead buffer as "interesting," preserving the correct parent-child relationships in the graph layout.

This is a **pure infrastructure patch** with no user-visible behavior change. It is the technical foundation for the visual root detection logic introduced in patch 4/7. The implementation is straightforward: the buffer is managed as a simple FIFO queue, and the pre-fetching logic in `get_revision()` ensures that the buffer is always populated when the graph renderer needs it. The patch is **well-scoped** and **minimally invasive**, touching only `graph.c`, `graph.h`, and `revision.c`.

The lookahead buffer approach was **previously approved** by Junio Hamano and Kristofer Karlsson (who prototyped the design), and this patch faithfully implements their agreed architecture. The only interaction with other subsystems is the integration with `get_revision()`, which now conditionally pre-fetches commits when a graph is active. The patch is **ready for final review** and has no known issues or open questions. It is a critical enabler for the visual root indentation feature and must land before the visualization logic in patch 4/7.
