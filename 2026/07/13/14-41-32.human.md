This is the eighth patch in Patrick Steinhardt’s nine-patch v3 series introducing object filters to `odb_for_each_object()`. It is a core piece of the ODB abstraction effort, enabling backends to optimize object enumeration by skipping excluded objects when possible.

The patch adds a `filter` field to the `odb_for_each_object_options` struct, allowing callers to pass object filters to backends. Backends may use these filters to skip excluded objects (e.g., via bitmaps) but are not required to, so callers must still re-apply the filter to yielded objects if strict filtering is needed. This design avoids artificial limitations on future backends while providing a clear contract: filters are a best-effort hint, not a guarantee.

The "packed" backend implementation introduces a new `bitmapped_for_each_object` callback that uses the recently added `prepare_bitmap_git_for_source()` function (patch 7/9) to open bitmaps exclusively for the current object source. This ensures objects are correctly attributed to their source and avoids redundant enumeration when multiple sources are present. The backend skips packs already covered by a bitmap during iteration, improving efficiency. The patch also exposes `can_filter_bitmap()` (previously static) to allow backends to check if a filter can be optimized via bitmaps.

The changes are confined to `odb.h`, `odb/source-packed.c`, `pack-bitmap.c`, and `pack-bitmap.h`, with no user-visible behavior changes.
