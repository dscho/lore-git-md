This is the first patch in Patrick Steinhardt’s v2 series "Make ODB optimizations pluggable," a refactoring effort that is part of the larger ODB abstraction project. The patch addresses a long-standing test fragility issue in `t/t7900-maintenance.sh` by replacing brittle `GIT_TRACE2_EVENT`-based checks with a more robust helper, `test_maintenance_tasks`.

The problem being solved is clear: the existing tests verify maintenance task execution by parsing spawned Git commands from trace2 logs, which breaks whenever command-line arguments change. This patch introduces a helper that instead checks for trace2 *regions* (e.g., `maintenance:commit-graph`), making the tests resilient to implementation details like argument order or command structure. The change is purely internal to the test suite and does not affect Git’s behavior, but it significantly improves test reliability.

The patch touches only `t/t7900-maintenance.sh`, replacing 92 lines of fragile command-matching logic with 102 lines of cleaner, region-based assertions. The new `test_maintenance_tasks` helper extracts task names from trace2 output, allowing tests to verify *what* ran (e.g., `geometric-repack`) rather than *how* it ran (e.g., `git repack --geometric=2`). This aligns with the series’ broader goal of modularizing ODB optimizations, as future backends will need to define their own tasks without tying tests to specific commands.

The patch is well-motivated and uncontroversial. Junio C Hamano’s feedback on v1 (which flagged the test brittleness) has been fully addressed, and the change is a prerequisite for the rest of the series. The commit message clearly explains the problem, solution, and trade-offs, and the implementation is straightforward. No behavioral changes or edge cases are introduced—this is purely a test infrastructure improvement. If the series lands, this patch will make future maintenance easier by reducing test flakiness.
