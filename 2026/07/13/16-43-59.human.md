This is the second patch in Pablo Sabater’s **v11 series** implementing visual root indentation for `` `git log --graph` ``. The patch extracts the logic for determining the next commit to show into a new helper function, `next_commit_to_show()`, in `revision.c`. This is a **purely preparatory refactoring** with no behavior change; the helper will be used in the next patch to populate the lookahead buffer that enables safe visual root detection.

The patch handles both commit sources that `get_revision()` currently supports: the normal revision walk (via `get_revision_internal()`) and the staged output mode introduced by `--max-count-oldest` (which pops commits from `revs->commits`). The `--reverse` branch is intentionally left unchanged because using the helper there would incorrectly set the `SHOWN` and `CHILD_SHOWN` flags, altering behavior.

The change is **mechanically straightforward** (24 lines added, 12 removed) and touches only `revision.c`. It is **well-motivated** by the upcoming lookahead buffer implementation, which needs to pre-fetch commits from the same source that `get_revision()` uses. The commit message clearly explains the purpose and the edge case (`--reverse`) that is deliberately excluded.

This patch is **ready for final review** and has no known issues. It is part of a **technically complete series** whose design decisions (lookahead buffer, four-level wrap, opt-out mechanism) have already been settled. Once signed off, the series is likely to proceed to `next`.
