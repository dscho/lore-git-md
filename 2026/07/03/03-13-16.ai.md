This is a feature patch series introducing new `includeIf` conditions for Git configuration. The series adds `worktree:<pattern>` and `worktree/i:<pattern>` to allow conditional config inclusion based on the working tree's realpath, addressing a gap in multi-worktree setups where `gitdir` patterns are cumbersome.

The implementation refactors `include_by_gitdir()` into a more generic `include_by_path()` and adds the new conditions with glob pattern matching (including `**/`, `~` expansion, and case-insensitive variants). The series includes thorough test coverage for edge cases like non-repository worktrees, early config reading, and case sensitivity on different filesystems.

This is the sixth iteration of the series, incorporating feedback from Junio C Hamano, Patrick Steinhardt, and Phillip Wood. Key improvements include Windows CI fixes (using `**` instead of `/` in patterns), better documentation cross-referencing, and additional test cases. The series appears well-motivated and technically sound, with clear use cases for multi-worktree workflows.

The patch touches `config.c`, updates `Documentation/config.adoc`, and adds comprehensive tests in `t/t1305-config-include.sh`. The refactoring is minimal and focused, avoiding unnecessary churn while enabling the new functionality.

This feature would be particularly useful for users managing multiple worktrees with different configuration needs, offering a cleaner alternative to `gitdir`-based patterns that currently require knowledge of Git's internal worktree directory structure.
