This is a **surface-level review** of the `git refs create` subcommand, part of Patrick Steinhardt’s now-merged five-patch series consolidating reference manipulation under `git refs`. The series itself is fully integrated into Git’s `next` branch and ready for the next release, but Toon Claes raises usability questions about the `--no-deref` option in the context of symbolic reference creation.

Toon’s review focuses on whether `--no-deref` is the right interface for creating symbolic references with `git refs create`. He points out that the option’s name and documentation (`"Operate on <ref> itself rather than the reference it points to via a symbolic ref"`) are obscure for users who want to create a symref, and he questions whether the symmetry with `git refs update`/`delete` justifies its inclusion. He also notes that the test suite does not cover the case where `git refs create` is called on an existing reference with the same value (which intentionally fails), and he suggests additional tests for symref creation with `--no-deref`.

The review is narrowly scoped to CLI ergonomics and test coverage, not the correctness or design of the subcommand itself. Patrick Steinhardt has already acknowledged similar stylistic feedback in earlier patches (e.g., `--deref`/`--no-deref` symmetry in `git refs delete`), but this series is merged, so any changes would require a follow-up patch. The discussion here is likely to inform future work on reference manipulation commands rather than block this feature.
