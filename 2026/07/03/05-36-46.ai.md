This is a **build system** patch in the ongoing **Rustification** effort, specifically addressing **macOS Universal Binary support** for Rust components. Junio C Hamano reviews the second patch in Shardul Natu and Koji Nakamaru’s v3 series, which introduces the `RUST_TARGETS` environment variable to enable multi-architecture builds on macOS.

The patch itself is now well-motivated and clearly explains the technical rationale: Apple’s C toolchain natively supports Universal Binaries via `-arch` flags, but Cargo requires separate invocations per target triple, necessitating explicit `lipo`-based combining of Rust static libraries. Junio’s feedback is purely surface-level, focusing on minor Makefile style nits (removing a redundant `@` prefix and replacing `if [` with `if test`). These are uncontroversial and will likely be addressed in a trivial reroll.

The patch is part of a converging series. The first patch (parallel build race fix) is already uncontroversial, and this one is now accepted in principle pending the minor style tweaks. Patrick Steinhardt’s earlier substantive concerns about Universal Binary completeness (whether the C build should also be modified to use `-arch` flags) remain unresolved in principle but are no longer blocking—Junio’s review signals that the current design is sufficient for practical use cases like macOS distribution and CI.

No new test coverage was introduced, but the changes are implicitly covered by existing build tests. The patch touches only the `Makefile`, introduces no on-disk format changes, and maintains backward compatibility. Key symbols: `RUST_TARGETS` (user-facing) and `$(RUST_MEMBER_LIBS)` (internal). The series is now effectively ready to proceed once the minor style feedback is incorporated.
