Matthias Beyer has proposed a feature to allow programmatic marking of commits for editing during an interactive rebase, specifically to automate splitting commits that modified files in a given subdirectory. The current manual process requires cross-referencing `git log` output with the rebase todo list, which the proposal aims to streamline with a hypothetical `--edit-commits` option for `git rebase -i`.

So far, the only response has been from Michal Suchánek, who suggests a lightweight workaround: using a custom script as the `EDITOR` environment variable to automate the rebase todo list. While this approach is technically valid and could serve as a temporary solution, it doesn’t address the core request for a built-in Git interface. The suggestion also doesn’t engage with the broader design questions raised in the original proposal, such as how to specify commits (e.g., via rev-list expressions or pathspec filtering), how the feature would interact with other rebase options like `--autosquash`, or whether the complexity of the feature is justified for what may be a niche workflow. The discussion remains open, with no movement toward an implementation or deeper technical review.
