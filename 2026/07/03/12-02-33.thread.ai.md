Core problem or goal
Provide a programmatic way to mark commits for editing during an interactive rebase, specifically to automate the workflow of splitting commits that modified files in a given subdirectory. The current manual process requires cross-referencing `git log` output with the rebase todo list.

Current status
The request has been definitively answered by demonstrating that the existing `GIT_SEQUENCE_EDITOR` mechanism fully addresses the use case. No implementation work is needed; the original workflow can be automated with a one-liner or a more robust script. The thread is now informational, documenting practical patterns and edge cases for future users. A minor correction to the recommended command-line usage was previously noted: `--autosquash` no longer requires `-i` (interactive mode) as of commit f8f87e082798, simplifying the automation pattern.

Key technical details
- Subsystem: sequencer (interactive rebase implementation)
- Existing mechanism: `GIT_SEQUENCE_EDITOR` environment variable, which allows arbitrary modification of the rebase todo list
- Example solutions:
  - Simple pause: `GIT_SEQUENCE_EDITOR='sed -i "1ibreak"' git rebase --autosquash <base>`
  - Subdirectory-based editing: `GIT_SEQUENCE_EDITOR='sed -i "s/^pick \([0-9a-f]\{7,\}\) /edit \1 /" $(git rev-list --reverse <base>..HEAD -- <pathspec> | sed "s/^/\//;s/$/\/p/")' git rebase --autosquash <base>`
- Pattern construction: `git rev-list --reverse <base>..HEAD -- <pathspec>` generates the list of commits touching the subdirectory; the `sed` script then matches these OIDs in the todo file
- Shell-nesting complexity: Git appends `"$@"` to the `GIT_SEQUENCE_EDITOR` command, which can interfere with the last command in a pipeline or with embedded shell variables
- Quoting and escaping pitfalls: variables containing spaces or special characters require careful handling when interpolated into strings that are later evaluated by another shell
- Robust patterns: D. Ben Knoble and Johannes Schindelin provide concrete scripts demonstrating how to handle interpolated arguments, chain commands, and insert breakpoints without breaking the rebase flow
- No new CLI options, symbols, or on-disk format changes required
- Workaround previously suggested (`EDITOR` script) is superseded by `GIT_SEQUENCE_EDITOR`, which is designed for this purpose
- Redundant flags: `-i` is no longer required with `--autosquash`; the correct invocation is now `GIT_SEQUENCE_EDITOR=true git rebase --autosquash`
