This is the third patch in Patrick Steinhardt’s nine-patch v2 series making `GIT_TEST_LONG` tests reliable and efficient in CI. It targets `t4141-apply-too-large.sh`, a test that verifies `git apply` rejects patches exceeding Git’s size limits.

The patch replaces an inefficient pipeline that generated a 1 GiB patch by streaming infinite zeros through `test_copy_bytes` (implemented as `dd ibs=1`, copying one byte at a time). The old approach took 6 minutes on a fast machine and up to 40 minutes in CI. The new version passes the desired size directly to `test-tool genzeros`, which already has an optimized fast-path for generating large zero buffers. Runtime drops to under a second.

Despite the dramatic speed-up, the patch retains the `EXPENSIVE` prerequisite. The commit message explains that `git apply` still allocates 1 GiB of memory to hold the patch, so the test remains resource-intensive. This concession addresses SZEDER Gábor’s v1 feedback that memory usage, not just runtime, should determine whether a test is labeled expensive.

The change is a single-file, three-line diff in `t/t4141-apply-too-large.sh`. No new helpers or user-facing behavior are introduced. The patch is uncontroversial, well-motivated, and ready for integration. It directly advances the series’ goal of making `GIT_TEST_LONG` tests CI-friendly without sacrificing coverage.
