This is a **substantive review** of the sixth patch in Patrick Steinhardt’s 12-patch security-hardening series for Git’s reftable backend. The series as a whole is technically complete and addresses a range of vulnerabilities discovered through fuzzing, but this specific review from Toon Claes focuses on improving the robustness of the unit test for a heap-buffer-overflow fix.

Toon’s feedback is narrowly scoped but meaningful: he suggests making the test case stricter by first verifying the expected block size before corrupting it, and then using a minimally invalid value (5 instead of 1) to reduce the risk of off-by-one errors in the test logic. The change is small but thoughtful, targeting the test’s resilience rather than the fix itself. His rationale is clear: ensuring the test reliably hits the intended code path and avoids false positives. The patch author (Patrick) has not yet responded, but this is a constructive, low-risk suggestion that would strengthen the test without altering the security fix. If adopted, it would likely be uncontroversial.
