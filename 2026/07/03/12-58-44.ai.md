This is the first patch in the v3 series hardening Git’s reftable backend against corrupted files. It introduces Meson build support for libFuzzer, enabling coverage-guided fuzzing of the reftable parser.

The patch adds a new `-Dfuzzers_link_args=` build option to pass linker arguments specifically for fuzzing executables. This plugs a gap in Meson’s existing `-Db_sanitize=` option, which cannot configure per-target link arguments. The documentation now explains how to set up libFuzzer: users must enable both the `address` and `fuzzer-no-link` sanitizers via `-Db_sanitize=`, enable fuzzers with `-Dfuzzers=true`, and pass `-fsanitize=fuzzer` via the new `-Dfuzzers_link_args=` option. The patch wires up the new option in `oss-fuzz/meson.build` so that all fuzzing targets are linked with the specified arguments.

This is a build-system change only, touching `meson.build`, `meson_options.txt`, and `oss-fuzz/meson.build`. No code or public APIs are modified. The patch is part of the series’ fuzzing infrastructure (patches 1–2), which is new to Git and may be reused for other subsystems. The commit message is clear and includes a usage example, making the new functionality immediately actionable for users. The technical quality is high, and the patch is uncontroversial.
