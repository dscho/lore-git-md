This is the first patch in the **test infrastructure** series introducing `greplint.pl`, a linter to standardize test assertions by replacing bare `grep` with `test_grep`. This specific patch documents the existing `test_grep` helper in `t/README`, which was previously undocumented despite being the recommended replacement for bare `grep` in test assertions.

The documentation explains `test_grep`'s purpose: improving debuggability by printing file contents on failure (unlike bare `grep`, which fails silently) and supporting negation with `!` as the first argument (to avoid suppressing diagnostic output). It also clarifies when *not* to use `test_grep`—for data filtering or command substitution—and warns that the helper requires the file to exist (triggering a `BUG` otherwise). Edge cases like backend-specific files or platform-dependent paths (e.g., NTFS 8.3 short names) are explicitly called out as reasons to retain bare `grep`.

This patch is purely additive and uncontroversial, serving as foundational context for the rest of the series. The documentation is clear and aligns with the series' goal of making `test_grep` the default for assertions while preserving flexibility for edge cases. No technical changes are made; the patch simply codifies existing conventions. The commit message is concise and directly addresses the gap in documentation.
