Matthias Beyer asks whether Git has a built-in way to programmatically mark commits for editing during an interactive rebase. His use case: he wants to split every commit that modified files in a specific subdirectory (`subdir/*.rs`) when rebasing a feature branch onto `master`. Currently he does this manually by cross-referencing `git log` output with the interactive rebase todo list.

The email is a straightforward feature request disguised as a question. It proposes a hypothetical `--edit-commits=<commit-list>` option for `git rebase -i` that would automate the manual matching step. Matthias acknowledges the potential UI clutter but still finds the idea convenient. No patch is attached; this is purely a discussion starter.
