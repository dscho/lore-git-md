This is patch 3/12 in the v3 series hardening Git’s reftable backend against corrupted files. It fixes an out-of-bounds read in the `binsearch()` utility function when called with an empty range (`sz == 0`).

The bug is straightforward: `binsearch()` performs a binary search by repeatedly calling a comparison function with indices into the range. When the range is empty, there is no valid index, but the function still calls the comparison function with index 0, causing an out-of-bounds read. The fix adds an early return when `sz == 0`, avoiding the invalid call. The accompanying unit test (`test_reftable_basics__binsearch_empty`) verifies the fix by passing an empty range and a comparison function that fails if called, ensuring the function returns 0 without invoking the comparison.

The patch touches `reftable/basics.c` (the fix) and `t/unit-tests/u-reftable-basics.c` (the test). No new symbols are introduced, and the change is purely defensive: it prevents a crash on malformed input without altering behavior for valid cases. The fix is minimal, well-motivated, and accompanied by a clear test case. This is a typical example of the hardening work in this series, addressing a low-level edge case discovered by fuzzing. No feedback or controversy is associated with this specific patch; it is uncontroversial and ready for merging.
