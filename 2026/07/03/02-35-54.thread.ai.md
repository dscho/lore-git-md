Subject: [PATCH] macOS: fix crash in precompose_utf8 with long UTF-8 filenames
Series version: standalone patch (no series)
Originating author: Ihar Hrachyshka
Thread type: bugfix

Core problem or goal
Fix a crash in `git status` on macOS when reading directory entries containing UTF-8 filenames longer than 255 bytes (NAME_MAX). The crash occurs in Git's `precompose_utf8` compatibility layer due to a fixed-size `d_name` array in `dirent_prec_psx` being too small for the dynamically reallocated buffer in `precompose_utf8_readdir`, triggering fortified libc overflow checks. The patch addresses both the immediate crash and the underlying assumption that filenames cannot exceed `NAME_MAX` on macOS, clarifying that macOS allows filenames up to 1024 bytes (__DARWIN_MAXPATHLEN) and 255 Unicode characters (which can exceed 255 bytes in UTF-8 encoding).

Current status
Patch submitted; no prior versions. Junio C Hamano, Torsten Bögershausen, and Patrick Steinhardt have reviewed. Junio agrees the fix is sound but requests the test be rewritten to avoid Perl. Patrick raised two technical points: (1) macOS's handling of filenames longer than `NAME_MAX` and Unicode byte counting, now addressed by Ihar's explanation that macOS permits filenames up to 1024 bytes and 255 Unicode characters, and (2) memory management, with Ihar acknowledging `FLEX_ALLOC_MEM()` could be used for initial allocation but noting the buffer must remain resizable during `precompose_utf8_readdir()` to handle edge cases. The patch is likely to be accepted once the test is adjusted and any further memory-management refinements are incorporated. No merge decision yet; under review.

Key technical details
- Files touched: `compat/precompose_utf8.c`, `compat/precompose_utf8.h`
- Subsystem: macOS Unicode normalization compatibility layer (`precompose_utf8`)
- New/renamed symbols: none (internal refactoring only)
- Behavior change: eliminates crash on long UTF-8 filenames; no functional change for shorter filenames or other platforms
- On-disk format: unaffected
- Test coverage: regression test in `t/t3910-mac-os-precompose.sh` that creates a 261-byte UTF-8 filename (249 'a' + 3 em-dashes + ".md") and verifies `git status` succeeds with `core.precomposeunicode` enabled. Test currently uses Perl to generate the filename; Junio suggests rewriting it to use shell tools (`printf`) instead.
- Implementation details: converts `d_name` to a flexible array member using `FLEX_ARRAY`, adjusts allocation with `st_add` and `offsetof`, and maintains existing API. The buffer starts with a `NAME_MAX + 1` allocation and reallocates only when encountering longer filenames, avoiding over-allocation for most entries. Patrick Steinhardt suggests using `FLEX_ALLOC_MEM()` for initial allocation, though reallocation during `precompose_utf8_readdir()` would still require a helper function.
