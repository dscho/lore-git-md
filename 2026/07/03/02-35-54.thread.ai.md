Core problem or goal
Fix a crash in `git status` on macOS when reading directory entries containing UTF-8 filenames longer than 255 bytes (NAME_MAX). The crash occurs in Git's `precompose_utf8` compatibility layer due to a mismatch between the fixed-size `d_name` array in `dirent_prec_psx` and the dynamic reallocation logic in `precompose_utf8_readdir`, which triggers fortified libc overflow checks.

Current status
Patch submitted; no prior versions. Torsten Bögershausen provided a **medium-weight review** noting the patch is technically sound but suggesting a minor test prerequisite addition (explicit `PERL` prerequisite for the regression test). No maintainer decisions yet.

- New/renamed symbols: none (internal refactoring only)
- Behavior change: eliminates crash on long UTF-8 filenames; no functional change for shorter filenames or other platforms
