Subject: [PATCH v2] macOS: fix crash in precompose_utf8 with long UTF-8 filenames
Series version: standalone patch, v2
Originating author: Ihar Hrachyshka
Thread type: bugfix

Core problem or goal
Fix a crash in `git status` on macOS when reading directory entries containing UTF-8 filenames longer than 255 bytes (NAME_MAX). The crash occurs in Git's `precompose_utf8` compatibility layer due to a fixed-size `d_name` array in `dirent_prec_psx` being too small for the dynamically reallocated buffer in `precompose_utf8_readdir`, triggering fortified libc overflow checks. The patch addresses both the immediate crash and the underlying assumption that filenames cannot exceed `NAME_MAX` on macOS, clarifying that macOS allows filenames up to 1024 bytes (__DARWIN_MAXPATHLEN) and 255 Unicode characters (which can exceed 255 bytes in UTF-8 encoding).

Key technical details
- Files touched: `compat/precompose_utf8.c`, `compat/precompose_utf8.h`
- Subsystem: macOS Unicode normalization compatibility layer (`precompose_utf8`)
- New/renamed symbols: `dirent_prec_psx_size()` helper function for safe size calculations
- Behavior change: eliminates crash on long UTF-8 filenames; no functional change for shorter filenames or other platforms
- On-disk format: unaffected
- Test coverage: regression test in `t/t3910-mac-os-precompose.sh` that creates a 256-byte UTF-8 filename (253 'a' + 3 em-dashes + ".md") using `printf` and `tr`, and verifies `git status` succeeds with `core.precomposeunicode` enabled. The test is now portable and does not require Perl.
- Implementation details: converts `d_name` to a flexible array member using `FLEX_ARRAY`, adjusts allocation with `st_add` and `offsetof`, and introduces `dirent_prec_psx_size()` for safe size calculations. The buffer starts with a `NAME_MAX + 1` allocation and reallocates only when encountering longer filenames, avoiding over-allocation for most entries.
