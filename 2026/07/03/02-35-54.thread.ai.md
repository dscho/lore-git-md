Subject: [PATCH] macOS: fix crash in precompose_utf8 with long UTF-8 filenames
Series version: standalone patch (no series)
Originating author: Ihar Hrachyshka
Thread type: bugfix

Core problem or goal
Fix a crash in `git status` on macOS when reading directory entries containing UTF-8 filenames longer than 255 bytes (NAME_MAX). The crash occurs in Git's `precompose_utf8` compatibility layer due to a fixed-size `d_name` array in `dirent_prec_psx` being too small for the dynamically reallocated buffer in `precompose_utf8_readdir`, triggering fortified libc overflow checks. The patch addresses both the immediate crash and the underlying assumption that filenames cannot exceed `NAME_MAX` on macOS.

Current status
Patch submitted; no prior versions. Junio C Hamano and Torsten Bögershausen have reviewed. Junio agrees the fix is sound but requests the test be rewritten to avoid Perl. Patrick Steinhardt has now reviewed, raising two technical points: (1) why macOS allows filenames longer than `NAME_MAX` and whether Unicode characters are treated specially in byte counting, and (2) whether the implementation could use `FLEX_ALLOC_MEM()` and avoid over-allocation. The patch is likely to be accepted once the test is adjusted and Patrick's memory-management suggestions are addressed. No merge decision yet.

Key technical details
- Files touched: `compat/precompose_utf8.c`, `compat/precompose_utf8.h`
- Subsystem: macOS Unicode normalization compatibility layer (`precompose_utf8`)
- New/renamed symbols: none (internal refactoring only)
- Behavior change: eliminates crash on long UTF-8 filenames; no functional change for shorter filenames or other platforms
- On-disk format: unaffected
- Test coverage: regression test in `t/t3910-mac-os-precompose.sh` that creates a 261-byte UTF-8 filename (249 'a' + 3 em-dashes + ".md") and verifies `git status` succeeds with `core.precomposeunicode` enabled. Test currently uses Perl to generate the filename; Junio suggests rewriting it to use shell tools (`printf`) instead.
- Implementation details: converts `d_name` to a flexible array member using `FLEX_ARRAY`, adjusts allocation with `st_add` and `offsetof`, and maintains existing API. Patrick Steinhardt suggests using `FLEX_ALLOC_MEM()` for initial allocation and sizing the buffer more precisely to avoid over-allocation for shorter filenames, though reallocation during `precompose_utf8_readdir()` would still require a helper function.
