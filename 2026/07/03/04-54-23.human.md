This is a **test infrastructure bugfix** and part of Michael Montalbo’s 6-patch series introducing `greplint.pl`, the test-suite linter that converts bare `grep` assertions to `test_grep`. This specific patch fixes a latent line-counting bug in the shared shell parser (`lib-shell-parser.pl`) that affects `greplint.pl`’s error reporting.

The bug occurs when a double-quoted string contains a multi-line command substitution (`$()`). The parser’s `scan_dqstring` function was counting newlines twice: once during the recursive parsing of the `$()` body, and again in a catch-all counter at the end of the function. This double-counting would cause incorrect line numbers for any tokens that follow such a string, though the bug was latent because `chainlint.pl` (the other consumer of this parser) uses byte offsets rather than line numbers for its annotations.

The fix is straightforward: remove the post-loop catch-all counter and instead count newlines inline as non-special characters are consumed. This ensures each newline is counted exactly once, whether it appears literally, as a line splice (escaped newline), or inside a `$()` substitution. The change is confined to `t/lib-shell-parser.pl` and does not affect the parser’s output—only the internal line-number tracking used by `greplint.pl` for error messages.

This patch is a prerequisite for the series, as `greplint.pl` relies on accurate line numbers to report conversion issues. While the bug is minor (it only affects reporting, not functionality), fixing it ensures the linter’s diagnostics are reliable. The commit message clearly explains the issue and the fix, and the change itself is minimal and well-scoped. No controversy or open questions remain; this is a clean, uncontroversial bugfix that rounds out the series.
