This is a review of the GSoC feature patch adding category-based prefix querying to `` `git repo info` ``. Junio C Hamano, the maintainer, replies to the initial submission with a substantive critique of the design.

The review questions the choice to limit the feature to simple prefix matching (e.g., `layout`) rather than supporting glob patterns (e.g., `layout.*` or `path.*.absolute`). Junio argues that globs would be more expressive and better match user intent, especially when querying nested namespaces. He notes that the patch already abandons binary search in favor of a linear scan, so the additional complexity of glob matching would be negligible.

Junio suggests a hybrid approach: first attempt an exact match using the existing `bsearch()` code path; if that fails, fall back to the new prefix (or glob) matcher to collect all matching keys. This preserves backward compatibility while enabling the new functionality. The review does not object to the feature itself but calls for a more flexible and future-proof design before the patch is ready for merging. No implementation details are provided; the feedback is purely architectural.
