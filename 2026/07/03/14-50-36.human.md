This is the documentation patch in Souma’s three-part series teaching `git history` to sign rewritten commits. It updates the `git-history` man page to describe the new `--gpg-sign` (`-S`) and `--no-gpg-sign` options for the `fixup`, `reword`, and `split` subcommands.

The change is straightforward: the synopsis lines for all three subcommands now include the signing options, and a short paragraph explains how they work—mirroring the wording already used in `git-commit(1)`. The patch keeps the key-id syntax and configuration override behavior (`commit.gpgsign`) consistent with the rest of Git, so users familiar with `git commit -S` will immediately recognize the pattern.

Nothing here looks controversial or under-explained; it’s a clean, minimal addition that matches the code changes in the other two patches. If the series lands, this documentation will be ready.
