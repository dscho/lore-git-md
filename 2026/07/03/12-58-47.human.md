This is a security-hardening patch for Git’s reftable backend, part of Patrick Steinhardt’s ongoing series to harden the code against maliciously corrupted files. This is the fourth patch in the v3 series (12 patches total).

The patch fixes a crash in `reftable/record.c`: when decoding a ref record with an invalid value type, the code previously called `abort()`, treating it as a programming error. Since the data is untrusted (read from disk), this is now handled as a normal error: the function returns `REFTABLE_FORMAT_ERROR` instead of crashing. The fix also delays setting the value type until after validation to avoid storing an invalid type in the record.

The commit message is clear and well-motivated, and the patch includes a new unit test (`test_reftable_record__ref_record_decode_invalid_value_type`) in `t/unit-tests/u-reftable-record.c`. The test verifies that decoding an invalid value type (one beyond the valid range) returns the expected error code. No public APIs or on-disk formats are changed; the behavior is strictly safer.

This patch is uncontroversial and technically complete. It addresses a real issue (a crash on corrupted input) with a minimal, targeted fix and thorough test coverage. The series as a whole is now fully reviewed and ready for merging.
