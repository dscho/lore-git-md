This is a reply to a feature request about programmatic commit editing during interactive rebase, offering an existing Git mechanism as a solution.

Brian m. carlson responds to Matthias Beyer’s proposal for a `--edit-commits` option by pointing out that Git already provides `GIT_SEQUENCE_EDITOR`, an environment variable analogous to `EDITOR` but specifically for modifying the rebase todo list. He demonstrates how to use it with a Perl one-liner that replaces "pick" with "edit" for commits matching a pathspec, effectively solving the original use case without requiring new Git code. The example uses abbreviated commit hashes (`%h`) and pipes the output of `git log` into `paste` to construct a regex pattern.

The reply also mentions a personal alias (`srebase`) that leverages `GIT_SEQUENCE_EDITOR=true` to suppress the editor entirely when autosquashing, showing how the variable can be used for other automation tasks. No new technical questions are raised; the response is purely informative, redirecting the request to an existing feature rather than engaging with the design or complexity trade-offs of a hypothetical built-in option. The tone is matter-of-fact and assumes the reader is comfortable with shell scripting and Git’s internals.
