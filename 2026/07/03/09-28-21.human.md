Toon Claes reviews the test case for the out-of-bounds read fix in `reftable_block_init()`. The patch itself (a bounds check in `reftable/block.c`) is uncontroversial and already acknowledged as correct. Toon’s feedback focuses narrowly on the test’s robustness: he suggests two improvements to the unit test in `t/unit-tests/u-reftable-block.c`. First, he proposes adding a sanity check to verify the expected block size before corrupting it, ensuring the test reads the correct offset. Second, he recommends using a minimally invalid size (`block_size + 1`) instead of the hardcoded `0xffffff` to reduce the risk of off-by-one errors in the test logic. The changes are small but meaningful for test reliability and maintainability.
