This is a feature patch for the `git repo info` command, part of a Google Summer of Code (GSoC) project. The patch introduces category-based prefix querying, allowing users to request all keys under a given namespace (e.g., `layout` returns both `layout.bare` and `layout.shallow`) instead of requiring exact key names or dumping all metadata with `--all`.

The implementation replaces the previous `bsearch`-based lookup with a linear search to find the first matching prefix, justified by the small size of the `repo_info_field` array. The patch updates the command's documentation (`git-repo.adoc`) to explain the new behavior, including examples and error conditions (e.g., partial prefixes like `lay` are rejected). Tests in `t/t1900-repo-info.sh` verify both successful prefix queries and proper error handling for invalid inputs.

The commit message and code suggest the change is motivated by usability: as the number of supported keys grows, filtering the full output externally (e.g., with `grep`) becomes inefficient. The patch is well-scoped, touching only `builtin/repo.c`, documentation, and tests, and includes a clear rationale for the linear search trade-off. No prior discussion or cover letter is referenced, so this appears to be the initial submission. The feature aligns with Git's plumbing command design, offering a more ergonomic way to query grouped metadata.
