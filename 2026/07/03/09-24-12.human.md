This is the final patch in Patrick Steinhardt’s nine-patch series making `GIT_TEST_LONG` tests reliable and efficient enough to run in CI. It closes the test-coverage gap between GitHub Actions and GitLab CI by enabling the expensive tests on GitLab for pushes to integration branches (`next`, `master`, `main`, `maint`), matching the behavior introduced in GitHub Actions by 7a094d68a2 (2026-05-08). The patch also disables `GIT_TEST_LONG` on Windows runners, which have only 7.5 GB of RAM—insufficient for some of the memory-hungry `EXPENSIVE` tests.

The change is mechanical and uncontroversial: it updates `.gitlab-ci.yml` to set `GIT_TEST_LONG=false` for Windows jobs and extends `ci/lib.sh` to recognize GitLab’s pipeline triggers (`CI_PIPELINE_SOURCE`) and branch names (`CI_BRANCH`), then exports `GIT_TEST_LONG=true` for the same integration-branch events that GitHub Actions already covers. The conditional now uses `${GIT_TEST_LONG:-true}` so that the variable can still be explicitly disabled (e.g., `GIT_TEST_LONG=false`) if needed.

No new prerequisites, test failures, or user-facing behavior changes are introduced. The patch is ready to merge and completes the series’ goal of making `GIT_TEST_LONG` tests visible and reliable in both CI systems.
