This is the first patch in the **test infrastructure** series introducing `greplint.pl`, a linter to standardize test assertions by replacing bare `grep` with `test_grep`. This specific patch documents the existing `test_grep` helper in `t/README`, which has been in use for years but was previously undocumented.

The new documentation explains `test_grep`'s purpose: it wraps `grep` to print file contents on failure (unlike bare `grep`, which fails silently), supports negation with `!` as the first argument (preserving diagnostic output), and enforces file existence with a `BUG` if the file is missing. It also clarifies when *not* to use `test_grep`—for data filtering or command substitution—and notes that bare `grep` should be retained for platform-specific or backend-dependent files (e.g., NTFS 8.3 short names or reftable-specific paths).
