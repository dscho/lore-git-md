This is a **test infrastructure refactoring** patch, part of the `greplint.pl` series (4/6 in v3). It fixes a latent line-counting bug in the shared shell parser (`lib-shell-parser.pl`) used by both `chainlint.pl` and `greplint.pl`.

The bug occurs when a double-quoted string contains a multi-line command substitution (`$()`). The parser’s `scan_dqstring` function counts newlines twice: once during the recursive parsing of the `$()` body (via `scan_token`), and again in a catch-all counter at the end of the function. This causes incorrect line numbers for subsequent tokens, though no current consumer (including `chainlint.pl`) is affected because they use byte offsets rather than line numbers.

The fix is surgical: newlines are now counted inline as non-special characters are consumed, and the redundant post-loop counter is removed. The change is confined to `scan_dqstring` and does not alter the parser’s output or behavior for existing tools. The commit message clearly explains the bug’s scope (latent, no known breakage) and the fix’s mechanics.

This patch is a prerequisite for the `greplint.pl` series because the linter’s error reporting relies on accurate line numbers. The fix itself is uncontroversial—it corrects a clear accounting error without introducing new logic. The broader series has already addressed all substantive feedback (e.g., `# lint-ok` audits, edge cases), and this patch is a final polish step. Expect it to merge alongside the rest of the series.
