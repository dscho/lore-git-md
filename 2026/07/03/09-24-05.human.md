This is the second patch in Patrick Steinhardt’s nine-patch series making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets a specific test in `t0021-conversion.sh` that writes and round-trips a 2 GB file through Git’s clean/smudge filters. On 32-bit platforms, this test is broken: it either fails with `ENOMEM` or hangs indefinitely, and the failures are not reliably detectable. Rather than attempt a complex fix, the patch simply skips the test on 32-bit systems by adding the `SIZE_T_IS_64BIT` prerequisite to the test’s declaration.

The change is minimal — a one-line edit to the test script — and well-motivated. The commit message clearly explains the problem (32-bit platforms cannot handle files larger than `SSIZE_MAX`), the context (the test only started hanging in CI after `GIT_TEST_LONG` tests were enabled), and the rationale for skipping rather than fixing. The patch is uncontroversial and aligns with the series’ overall goal of making expensive tests runnable in CI without breaking pipelines. No user-facing behavior changes are introduced, and the fix is defensive: it prevents a known-broken test from running on platforms where it cannot succeed.
