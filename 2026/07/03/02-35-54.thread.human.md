This thread is about fixing a crash in Git on macOS when handling long UTF-8 filenames in `git status`. The issue occurs in Git's `precompose_utf8` compatibility layer, where a fixed-size buffer in `dirent_prec_psx` overflows when processing filenames longer than 255 bytes (NAME_MAX). The patch, submitted by first-time contributor Ihar Hrachyshka, has been reviewed by Junio C Hamano and Torsten Bögershausen, who agree the fix is sound but Junio requested the test be rewritten to avoid Perl.

The patch touches `compat/precompose_utf8.c` and `.h`, refactoring the internal memory allocation to use a flexible array member (`FLEX_ARRAY`) and avoid the crash. The test currently uses Perl to generate a 261-byte UTF-8 filename, but Junio prefers a shell-based approach (`printf`). Patrick Steinhardt recently raised two technical points: why macOS allows filenames longer than `NAME_MAX` (suggesting platform-specific quirks may be at play) and whether the patch could use Git's `FLEX_ALLOC_MEM()` macro for more precise memory allocation. The patch is likely to be accepted once these adjustments and the test rewrite are addressed. No major objections remain, and the discussion has focused on refining the implementation rather than questioning the fix itself.
