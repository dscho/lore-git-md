This thread is about a bugfix for a crash in `git status` on macOS when handling UTF-8 filenames longer than 255 bytes. The issue occurs in Git's `precompose_utf8` compatibility layer, where a fixed-size buffer in `dirent_prec_psx` was too small for dynamically reallocated filenames, triggering fortified libc overflow checks. The fix, authored by Ihar Hrachyshka, converts the buffer to a flexible array member and adjusts allocation logic to handle macOS's allowance of filenames up to 1024 bytes (though limited to 255 Unicode characters, which can exceed 255 bytes in UTF-8 encoding).

The patch has been reviewed by Junio C Hamano, Torsten Bögershausen, and Patrick Steinhardt. Junio initially requested the test be rewritten to avoid Perl, which Ihar addressed in the v2 patch by using shell tools (`printf` and `tr`) to generate the test filename. Patrick raised technical points about macOS's filename handling and memory management, which Ihar clarified and partially addressed. The current version (v2) is now ready for merging, with all substantive feedback incorporated. The fix is confined to `compat/precompose_utf8.c` and its header, with no impact on other platforms or subsystems. The regression test ensures the crash no longer occurs, and the commit message clearly explains the fortified libc interaction.
