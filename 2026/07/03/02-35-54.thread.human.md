This thread is about fixing a crash in Git on macOS when `git status` encounters UTF-8 filenames longer than 255 bytes. The crash occurs in Git's Unicode normalization layer (`precompose_utf8`) due to a buffer size mismatch. Ihar Hrachyshka submitted a patch that resolves the issue by making the buffer dynamically resizable, and it has drawn reviews from Junio C Hamano, Torsten Bögershausen, and Patrick Steinhardt.

The patch is close to being accepted but needs two adjustments: the test should be rewritten to avoid Perl (per Junio's request), and the memory management could be refined further (per Patrick's suggestion). Ihar has now clarified that macOS allows filenames to exceed `NAME_MAX` bytes because the system uses a larger limit (`__DARWIN_MAXPATHLEN`), and that this behavior is consistent with how other platforms handle Unicode filenames. The current implementation starts with a `NAME_MAX + 1` buffer and only reallocates when necessary, which balances memory efficiency with edge-case handling.

The discussion remains technical and constructive, with no unresolved objections. Once the test is adjusted and any final memory-management tweaks are made, the patch is likely to be merged. The fix is macOS-specific and doesn’t affect other platforms or subsystems.
