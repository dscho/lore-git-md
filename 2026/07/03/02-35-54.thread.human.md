This thread is about a bugfix for a crash in `git status` on macOS when handling long UTF-8 filenames. The issue occurs in Git's `precompose_utf8` compatibility layer, which normalizes Unicode filenames, and triggers a fortified libc overflow check when filenames exceed 255 bytes. The patch, submitted by a first-time contributor, refactors the internal buffer handling to use a flexible array member and adjusts allocation logic, eliminating the crash without changing behavior for shorter filenames or other platforms.

Torsten Bögershausen, a macOS and Unicode expert, reviewed the patch positively but noted a minor test prerequisite issue: the regression test in `t/t3910-mac-os-precompose.sh` uses Perl to generate a 261-byte UTF-8 filename but doesn't declare a `PERL` prerequisite. This could cause false test failures on systems without Perl. The patch itself is well-scoped, touching only `compat/precompose_utf8.c` and its header, and includes a clear commit message explaining the crash scenario. No other reviews or maintainer decisions have been recorded yet, but the fix appears to address a real-world issue with appropriate test coverage. The next step is likely a small adjustment to the test to address Torsten's feedback.
