This is a **platform compatibility** follow-up in the ongoing Rustification build system thread. D. Ben Knoble responds to Patrick Steinhardt’s question about whether `lipo`—the macOS tool used to create Universal Binaries—can be safely assumed to be available on macOS systems.

Knoble’s research confirms that `lipo` has been part of Xcode since at least 2005 (Xcode 2.1), when Apple introduced Universal Binaries for the PowerPC-to-Intel transition. For the modern Universal Binary 2 format (supporting Apple Silicon), Xcode 12 (released in 2020) appears to be the minimum required version, though Apple’s official documentation does not specify a precise version. The tool is included in the Xcode Command Line Tools, which are a standard part of macOS development environments.

The response is factual and well-sourced, providing the historical context and version requirements that Patrick’s review flagged as missing. It effectively answers the immediate question: `lipo` is not a niche tool but a standard component of macOS development toolchains, and its availability is a reasonable assumption for Git’s build system. This removes one of the two substantive concerns Patrick raised in his review of the v2 patch. The remaining architectural question—whether the current approach (Universal Binaries for Rust libraries only) is sufficient or whether the C build should also support them—remains open but is now decoupled from platform compatibility.
