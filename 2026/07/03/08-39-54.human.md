This is a **platform-compatibility bugfix** for macOS, addressing a crash in `git status` when processing long UTF-8 filenames. The patch itself was submitted by a first-time contributor and received a positive review from Torsten Bögershausen, who confirmed the fix is technically sound but raised a minor question about test prerequisites. Junio C Hamano, the maintainer, has now weighed in on the thread, suggesting a small improvement to the test to avoid a `PERL` dependency.

The issue occurs in Git’s `precompose_utf8` compatibility layer, which normalizes Unicode filenames on macOS. When a filename exceeds 255 bytes (the `NAME_MAX` limit), the code attempts to reallocate a buffer but triggers fortified libc overflow checks, causing a crash. The patch fixes this by converting the `d_name` field to a flexible array member (`FLEX_ARRAY`) and adjusting the allocation logic to match the actual memory layout. The fix is well-scoped, touching only `compat/precompose_utf8.c` and its header, with no impact on other platforms or Git’s on-disk format.

The patch includes a regression test in `t/t3910-mac-os-precompose.sh` that creates a 261-byte UTF-8 filename (249 'a' characters + 3 em-dashes + ".md") and verifies `git status` succeeds with `core.precomposeunicode` enabled. Torsten’s review questioned whether the test should explicitly declare a `PERL` prerequisite, since it uses Perl to generate the filename. Junio agrees the prerequisite is needed if the test remains as-is but suggests an alternative: replacing the Perl one-liner with a `printf` command to generate the filename, which would eliminate the dependency entirely. This is a minor but practical improvement—Perl is widely available, but avoiding it makes the test more portable and robust.

The patch appears to be on track for merging, pending this small test adjustment. The fix addresses a real-world crash scenario with clear test coverage, and the discussion has focused on refining the test rather than questioning the core implementation. No other edge cases or concerns have been raised, and the maintainer’s feedback is constructive rather than blocking. If the author updates the test as suggested, this patch is likely to be queued soon.
