This is a security-hardening patch for Git’s reftable backend, part of Patrick Steinhardt’s v3 series addressing vulnerabilities in corrupted reftable files. This specific patch (7/12) fixes an out-of-bounds read that occurs when a maliciously crafted block header claims a size larger than the actual data available. The fix adds a bounds check in `reftable_block_init()` to reject such blocks with a `REFTABLE_FORMAT_ERROR` instead of crashing.

The vulnerability is demonstrated with a clear AddressSanitizer trace showing the heap-buffer-overflow when reading the restart count from an invalid offset. The test case has been strengthened in v3: it now dynamically calculates the corruption value by reading the actual block size (47 bytes), verifying it, and then incrementing it by 1 to ensure the test always targets the minimal invalid size. This addresses feedback from Toon Claes on v2, making the test more robust and self-documenting.

The patch is technically sound, with a minimal fix in `reftable/block.c` and a thorough unit test in `t/unit-tests/u-reftable-block.c`. The commit message is detailed, including the ASan output and a clear explanation of the attack vector. This is part of the broader reftable security effort, which now includes integrated fuzzing infrastructure to prevent regressions. All prior feedback has been addressed, and the series appears ready for merging.
