This is a **refactoring** patch that extracts the shell parser from `chainlint.pl` into a shared module (`lib-shell-parser.pl`) to enable reuse by other test-suite linters. It is the third patch in the six-part `greplint.pl` series (v3), which aims to standardize test assertions by replacing bare `grep` with `test_grep`.

The patch moves the `Lexer`, `ShellParser`, and `ScriptParser` classes—along with their supporting methods—from `chainlint.pl` into the new `lib-shell-parser.pl` file. The changes are purely mechanical: `chainlint.pl` now loads the shared module via `do()` and subclasses `ScriptParser` as `ChainlintParser` to implement its &&-chain checking logic. The commit message confirms no functional change: `chainlint.pl` produces identical output, and its self-tests pass.

Key technical details:
- **Files touched**: `t/chainlint.pl` (reduced from ~520 to ~30 lines) and `t/lib-shell-parser.pl` (new, ~530 lines).
- **New symbols**: `lib-shell-parser.pl` (shared module), `ScriptParser::unwrap()` (extracted helper).
- **Inheritance**: `ChainlintParser` extends `ScriptParser`; `TestParser` (used by `chainlint.pl`) now inherits from `ShellParser`.
- **Motivation**: The shared parser enables `greplint.pl` (introduced in a later patch) to reuse the same shell tokenizer for identifying command boundaries, avoiding code duplication.

This patch is a prerequisite for the `greplint.pl` linter and demonstrates careful design: the shared module is intentionally minimal, with `ScriptParser::check_test()` left as a no-op to be overridden by subclasses. The extraction is clean, with no behavioral changes, and the commit message clearly documents the rationale and impact. The patch is uncontroversial and ready for merging as part of the larger series.
