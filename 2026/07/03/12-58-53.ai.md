This is the tenth patch in Patrick Steinhardt’s v3 series hardening Git’s reftable backend against corrupted files. It fixes an out-of-bounds read when a restart offset points past the end of the records section.

The vulnerability occurs in `restart_needle_less()` (`reftable/block.c`), which is called during binary search over restart points. Restart offsets are stored in a table at the end of each block and must point to records within the block. Without validation, a bogus offset can cause the parser to read past the end of the buffer when decoding the record key, as shown in the ASan backtrace. The fix adds a bounds check: if the offset is beyond the restart table’s start (`block->restart_off`), the function sets `args->error` and returns an error.

The patch includes a new unit test (`test_reftable_block__corrupt_restart_offset`) in `t/unit-tests/u-reftable-block.c`. The test writes a single ref record into a block, corrupts the first restart offset to `0xffffff` (the maximum 24-bit value), and verifies that `block_iter_seek_key()` returns `REFTABLE_FORMAT_ERROR`. The test uses the `cl_reftable_write_block` helper introduced earlier in the series to reduce boilerplate.

This is a targeted security fix with no user-visible behavior change. The commit message is clear, the ASan output is included, and the test is minimal but effective. Like the rest of the series, it replaces a crash with a graceful error return. No prior feedback on this specific patch is recorded in the thread context, but the pattern matches the other fixes in the series, all of which have been approved by Junio C Hamano. The patch touches only `reftable/block.c` and the test file; no public APIs or on-disk formats are modified.
