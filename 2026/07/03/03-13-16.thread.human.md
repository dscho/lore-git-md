This thread is about adding `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` to Git’s config system, allowing conditional config inclusion based on the working tree’s realpath. The feature addresses a usability gap in multi-worktree setups where `gitdir`-based patterns are cumbersome due to Git’s internal directory structure.

The series is now targeting **v7**, with the last remaining issue—a symlink-handling inconsistency—resolved via Chen Linxuan’s proposal to store an additional non-realpath worktree path in `struct repository`. This aligns `worktree` and `gitdir` behavior, ensuring both match symlinked and real paths consistently. Patrick Steinhardt has endorsed the solution, and Junio C Hamano has signaled readiness to merge v7 once the updated patches arrive. The preparatory refactoring and core implementation remain uncontroversial, with no outstanding objections to the design.

Key technical details include new config conditions, glob pattern support (`**/`), case-insensitive matching (`/i`), and symlink-aware path resolution. The changes touch `config.c`, `setup.c`, and possibly `repository.h`, with test coverage expanded to handle symlinked paths, Windows compatibility, and edge cases like nested symlinks. Junio and Phillip Wood have yet to review the plumbing changes, but the path forward is clear.
