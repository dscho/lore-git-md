This thread is about adding `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` to Git’s config system, allowing conditional config inclusion based on the working tree’s realpath. The feature aims to improve usability in multi-worktree setups where `gitdir`-based patterns are cumbersome.

The series is now at v6, with v7 expected to resolve the last remaining blocker: a symlink-handling inconsistency between `worktree` (which resolves symlinks to realpath) and `gitdir` (which matches both symlinked and real paths). Patrick Steinhardt, who identified the issue, has endorsed Chen Linxuan’s proposed solution—storing an additional non-realpath worktree path in `struct repository`—despite its added complexity, prioritizing user-facing consistency over implementation elegance. Junio C Hamano and Phillip Wood have not yet weighed in on this specific proposal, but their earlier reviews raised no objections to the core design. The preparatory refactoring and core implementation remain uncontroversial, and the glob pattern (`**`) for cross-platform compatibility is final.

The next step is for Chen to implement the changes and submit v7. If no new objections arise, the series is likely to proceed with the proposed symlink-handling fix, which will touch `setup.c`, `config.c`, and possibly `repository.h`. Test coverage for edge cases like nested symlinks and Windows junctions may expand in the next iteration.
