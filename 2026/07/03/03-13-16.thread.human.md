This thread is about a patch series (v6) by Toon Claes that adds `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` conditions to Git’s configuration system. The goal is to simplify conditional config inclusion in multi-worktree setups, where the existing `gitdir`-based patterns are cumbersome because they require knowledge of Git’s internal `.git/worktrees/` directory structure.

The series is now at v6, with all prior feedback from Junio C Hamano, Patrick Steinhardt, and Phillip Wood addressed. Key improvements include Windows CI fixes (using `**` instead of `/` in patterns), better documentation cross-references, and expanded test coverage for edge cases like non-repository worktrees and early config reading. The first patch refactored `include_by_gitdir()` into a generic `include_by_path()` helper, paving the way for the new worktree condition without changing existing behavior.

The second patch, just summarized, implements the core functionality. It adds the new condition keywords, reuses the existing pattern-matching logic, and ensures the feature works as documented—matching the worktree’s realpath, handling symlinks, and respecting case sensitivity. The documentation is clear, with practical examples showing how `worktree` patterns differ from `gitdir` ones, and the tests cover all major edge cases. There are no open questions or objections, and the series appears ready for merging. This would be a welcome usability improvement for users managing multiple worktrees with different configuration needs.
