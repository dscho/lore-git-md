This thread is about adding `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` conditions to Git’s config system, allowing conditional config inclusion based on the working tree’s realpath. The feature aims to improve usability in multi-worktree setups, where `gitdir`-based patterns are cumbersome due to Git’s internal directory structure.

The series is now at **v6**, with all prior feedback addressed, but a **behavioral inconsistency** has emerged: the new `worktree` condition resolves symlinks to the real path, while the existing `gitdir` condition matches both symlinked and real paths. This discrepancy risks confusing users who expect consistent behavior. The preparatory refactoring (generalizing `include_by_gitdir()` to `include_by_path()`) and core implementation remain uncontroversial, and Junio has endorsed the documentation and test patterns. However, the symlink issue must be resolved before the series can graduate to `next`.

Chen Linxuan has joined the discussion, analyzing the root cause and proposing a **v7 solution**: store an additional absolute, non-realpath worktree path in the repository struct specifically for `includeIf.worktree` evaluation. This would align the behavior with `gitdir` but adds complexity to the plumbing. The proposal is technically precise and addresses Patrick Steinhardt’s test case, but no decision has been made yet—Chen is seeking feedback on whether this approach is preferable to documenting the divergence as intentional. The discussion remains narrowly focused on symlink handling, with no broader design changes under consideration. Key participants—Junio, Patrick, and Phillip Wood—have all provided substantive reviews, and the outcome of this symlink debate will determine the series’ readiness for merging.
