This is a brief follow-up in the ongoing discussion about whether `git rm -n *.json` unexpectedly recurses into subdirectories. The thread has already established that the behavior is correct—Git’s pathspec logic treats `*` as matching directory separators by default—but the conversation is now focused on whether the documentation should be clearer.

Matt Hunter clarifies why he initially couldn’t reproduce the issue: his shell (on a non-Windows system) expanded `*.json` to match files in the current directory, so Git never saw the literal `*.json` pattern. This highlights a key edge case: when no `.json` files exist in the current directory, the shell passes `*.json` directly to Git, triggering the recursive pathspec behavior. The interaction between shell globbing and Git’s pathspec handling is now a central point of discussion for potential documentation improvements.

He finds the man page clear in hindsight but acknowledges that the tight integration between `git rm` and Unix `rm` can make it easy to overlook Git-specific pathspec nuances.
