The key insight here is that the observed behavior depends on shell globbing: if `.json` files exist in the current directory, the shell expands the glob, passing explicit non-recursive paths to Git; if no such files exist, the shell passes `*.json` literally, and Git’s recursive pathspec matching takes over.

Matt confirms he initially missed this nuance because his test environment had `.json` files in the working directory, causing the shell to expand the glob and mask the recursive behavior. He does not propose any documentation changes or patches, but his observation reinforces the thread’s shift toward clarifying how shell-Git interaction affects pathspec handling.
