This is the second patch in Patrick Steinhardt’s v3 security-hardening series for Git’s reftable backend. It introduces a new fuzzer (`oss-fuzz/fuzz-reftable.c`) that exercises the reftable parser by feeding arbitrary byte sequences to the three main entry points: `reftable_table_init_ref_iterator`, `reftable_table_init_log_iterator`, and `reftable_table_iterator_init`. The fuzzer is integrated into both the Makefile and Meson build systems and is now part of Git’s CI via `ci/run-build-and-minimal-fuzzers.sh`.

The patch is minimal and focused: it adds the fuzzer source file, updates build system files to include it, and wires it into the CI script. The fuzzer itself is straightforward, using `reftable_buf` and `reftable_block_source` to wrap the input data and then iterating over refs, logs, and raw blocks to maximize coverage of the parsing code. No new symbols or public APIs are introduced, and the implementation is consistent with Git’s existing fuzzing infrastructure (e.g., `fuzz-pack-idx.c`).

This is a foundational piece of the series, enabling the subsequent security fixes (patches 3–12) by providing a reproducible way to trigger and verify the vulnerabilities. The fuzzer has already run for 2+ hours without surfacing new issues, indicating that the hardening work in later patches is effective. The integration is seamless, requiring no changes to the reftable backend itself—only the addition of the fuzzer target and build system hooks.
