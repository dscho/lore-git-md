This is a clarification in response to a bug report about `git rm` unexpectedly recursing into subdirectories.

Patrick Steinhardt replies to Евгений Плискин’s report that `git rm -n *.json` recursively removes JSON files from subdirectories, despite the documentation suggesting it should not. Patrick explains that this behavior is *not* a bug—it is the intended design of Git’s pathspec matching. The `*` wildcard in a pathspec matches directory separators by default, meaning `*.json` will match all `.json` files in the current directory *and* its subdirectories. This is documented in `gitglossary(7)` under "pathspec," which explicitly states that patterns like `Documentation/*.jpg` will match files in subdirectories.

The confusion appears to stem from a misinterpretation of `git rm`’s documentation, which does not clearly state that pathspecs inherently support recursive matching. Patrick asks Евгений to clarify which part of `git-rm(1)` led to the expectation of non-recursive behavior, suggesting the documentation might need improvement rather than the code.

No patch is proposed here—this is purely a documentation and user-expectation issue. The thread remains open for Евгений to respond, but the core technical question (whether the behavior is a bug) is now resolved: it is working as designed. If this thread continues, it may shift toward discussing how to make the documentation clearer for users who expect glob patterns to behave like shell globs (which typically do not recurse).
