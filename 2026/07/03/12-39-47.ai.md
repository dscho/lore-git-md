The `:(glob)` prefix prevents `*` from matching directory separators, aligning the command’s behavior with the user’s original expectation of non-recursive matching. This exchange reinforces that the core issue is documentation clarity rather than a code defect, as the pathspec machinery already supports the desired behavior through explicit syntax.

The key technical detail is the `:(glob)` pathspec modifier, which is documented in `gitglossary(7)` but not prominently cross-referenced in `git-rm(1)`. The thread now has a concrete example of how to achieve non-recursive matching, which could inform future documentation improvements. No patch is proposed here, but the discussion provides a clear user-facing workaround and a specific point of confusion (the lack of visibility of `:(glob)` in `git rm`’s man page) for potential follow-up.

The subsystem remains pathspec handling, with no changes to `builtin/rm.c` or new symbols introduced.
