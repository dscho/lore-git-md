Core problem or goal
Add `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` conditions to Git’s config system, allowing conditional config inclusion based on the working tree’s realpath. This closes a usability gap in multi-worktree setups where `gitdir`-based patterns are awkward because they require knowledge of Git’s internal `.git/worktrees/` directory structure.

Current status
Series is at v6. All prior feedback from Junio C Hamano, Patrick Steinhardt, and Phillip Wood has been addressed, but a new **behavioral inconsistency** has been identified: the `worktree` condition resolves symlinks to the real path, while the existing `gitdir` condition matches both symlinked and real paths. This discrepancy could confuse users who expect consistent behavior between the two conditions. The preparatory refactoring in patch 1/6 (generalizing `include_by_gitdir()` to `include_by_path()`) and the core implementation in patch 2/6 (adding the new condition keywords, documentation, and tests) remain uncontroversial. Junio’s latest reply endorses the current documentation structure and test patterns, but the symlink handling issue must be resolved before merging. The updated glob pattern (`**`) for cross-platform compatibility is still considered final.

Key technical details
- Files touched: `config.c`, `Documentation/config.adoc`, `t/t1305-config-include.sh`
- New symbols: `includeIf.worktree:<pattern>`, `includeIf.worktree/i:<pattern>`
- Refactoring: `include_by_gitdir()` generalized to `include_by_path()` (patch 1/6)
- Pattern features: glob support (`**/`, `~` expansion), case-insensitive variant (`/i`), realpath resolution, symlink handling
- Behavior: matches against the working tree’s realpath (via `repo_get_work_tree()`); never matches in bare repositories or during early config reading; respects filesystem case sensitivity. **Symlink handling is now a point of contention**: `gitdir` matches both symlinked and real paths, while `worktree` currently resolves symlinks to the real path only.
- Test coverage: worktree realpath resolution, early config reading, case sensitivity, non-repository worktrees, bare repositories, multiple worktrees, symlinked paths, cross-platform path handling. **Test case demonstrating the symlink inconsistency is now provided by Patrick Steinhardt.**

Open questions and loose ends
