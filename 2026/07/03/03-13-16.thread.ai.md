Core problem or goal
Add `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` conditions to Git’s config system, allowing conditional config inclusion based on the working tree’s realpath. This closes a usability gap in multi-worktree setups where `gitdir`-based patterns are awkward because they require knowledge of Git’s internal `.git/worktrees/` directory structure.

Current status
Series is at v6, with v7 expected to resolve the **symlink-handling inconsistency** identified in review. The preparatory refactoring (patch 1/6) and core implementation (patch 2/6) remain uncontroversial. Junio C Hamano and Phillip Wood have no outstanding objections; Patrick Steinhardt’s feedback on symlink behavior is the sole blocker. The updated glob pattern (`**`) for cross-platform compatibility is final. **New development**: Chen Linxuan has proposed a technical solution for v7 that would align `worktree` and `gitdir` behavior by storing an additional non-realpath worktree path in `struct repository`, but this approach is still under discussion and has not been implemented.

Key technical details
- Files touched: `config.c`, `Documentation/config.adoc`, `t/t1305-config-include.sh` (v6); `setup.c` likely added for v7.
- New symbols: `includeIf.worktree:<pattern>`, `includeIf.worktree/i:<pattern>`
- Refactoring: `include_by_gitdir()` generalized to `include_by_path()` (patch 1/6)
- Pattern features: glob support (`**/`, `~` expansion), case-insensitive variant (`/i`), realpath resolution, symlink handling.
- **Symlink behavior (current)**: `worktree` resolves symlinks to realpath; `gitdir` matches both symlinked and real paths. **Proposed v7 change**: Store a secondary non-realpath worktree path in `struct repository` or `struct config_options` to enable consistent matching with `gitdir`.
- Behavior: Matches against the working tree’s realpath (via `repo_get_work_tree()`); never matches in bare repositories or during early config reading; respects filesystem case sensitivity.
- Test coverage: Worktree realpath resolution, early config reading, case sensitivity, non-repository worktrees, bare repositories, multiple worktrees, symlinked paths, cross-platform path handling. **New test case**: Patrick Steinhardt’s demonstration of the symlink inconsistency, now a focal point for v7.

Open questions and loose ends
- **Symlink handling resolution**: Should `worktree` match symlinked paths (like `gitdir`) or continue resolving to the real path? Chen’s proposal (store a non-realpath worktree path) is the leading candidate but requires feedback from Junio and Patrick. Alternatives (e.g., documenting the divergence as intentional) remain on the table.
- **Implementation complexity**: Chen’s proposal adds state to `struct repository` and requires plumbing changes in `setup_discovered_git_dir()`. Reviewers must weigh this complexity against the benefit of behavioral consistency.
- **Edge cases**: Nested symlinks, Windows junctions, and interactions with `PWD` may require additional test coverage in v7.
- Junio’s documentation consolidation suggestion remains deferred to a follow-up topic.
