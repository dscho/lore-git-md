Originating author: Toon Claes
Thread type: patch series

Core problem or goal
Add `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` conditions to Git’s config system, allowing conditional config inclusion based on the working tree’s realpath. This closes a usability gap in multi-worktree setups where `gitdir`-based patterns are awkward because they require knowledge of Git’s internal `.git/worktrees/` directory structure.

Current status
Series is at v6. Previous iterations addressed feedback from Junio C Hamano, Patrick Steinhardt, and Phillip Wood. Key changes: Windows CI fixes (replacing `/` with `**` in patterns), improved documentation cross-references, and expanded test coverage for edge cases (non-repository worktrees, early config reading, case sensitivity). The first patch in the series refactors `include_by_gitdir()` into a generic `include_by_path()` helper, preparing the codebase for the new worktree condition without altering existing behavior. The second patch implements the core functionality, adding the two new condition keywords, documentation, and comprehensive test coverage.

Key technical details
- Files touched: `config.c`, `Documentation/config.adoc`, `t/t1305-config-include.sh`
- New symbols: `includeIf.worktree:<pattern>`, `includeIf.worktree/i:<pattern>`
- Refactoring: `include_by_gitdir()` generalized to `include_by_path()` (patch 1/6)
- Pattern features: glob support (`**/`, `~` expansion), case-insensitive variant (`/i`)
- Behavior: matches against the working tree’s realpath (obtained via `repo_get_work_tree()`); never matches in bare repositories or during early config reading; resolves symlinks to realpath; respects case sensitivity based on filesystem
- Test coverage: worktree realpath resolution, early config reading, case sensitivity on different filesystems, non-repository worktrees, bare repositories, multiple worktrees, symlinked paths
