Core problem or goal
Add `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` conditions to Git’s config system, allowing conditional config inclusion based on the working tree’s realpath. This closes a usability gap in multi-worktree setups where `gitdir`-based patterns are awkward because they require knowledge of Git’s internal `.git/worktrees/` directory structure.

Current status
Series is now **targeting v7**, with the **symlink-handling inconsistency resolved** via Chen Linxuan’s proposed approach: storing an additional non-realpath worktree path in `struct repository` or `struct config_options` to align `worktree` and `gitdir` behavior. The preparatory refactoring (patch 1/6) and core implementation (patch 2/6) remain uncontroversial. **Patrick Steinhardt has endorsed Chen’s solution**, and **Junio C Hamano has signaled readiness to merge v7** once the updated patches are submitted, expecting no further objections. Phillip Wood has not yet weighed in on the specific proposal, but no objections to the core design persist. The updated glob pattern (`**`) for cross-platform compatibility is final.

Key technical details
- Files touched: `config.c`, `Documentation/config.adoc`, `t/t1305-config-include.sh` (v6); **`setup.c` and `repository.h` added for v7** (to derive and store the non-realpath worktree path).
- New symbols: `includeIf.worktree:<pattern>`, `includeIf.worktree/i:<pattern>`
- Refactoring: `include_by_gitdir()` generalized to `include_by_path()` (patch 1/6)
- Pattern features: glob support (`**/`, `~` expansion), case-insensitive variant (`/i`), **consistent symlink handling** (v7: matches both symlinked and real paths, like `gitdir`).
- **Symlink behavior (v7)**: Stores a secondary non-realpath worktree path in `struct repository` (derived in `setup_discovered_git_dir()` using `cwd`, worktree-root offset, and `$PWD`) to enable matching against both symlinked and real paths. This resolves the v6 inconsistency where `worktree` resolved symlinks to realpath while `gitdir` matched both.
- Behavior: Matches against the working tree’s realpath (via `repo_get_work_tree()`) **and** the non-realpath path (v7); never matches in bare repositories or during early config reading; respects filesystem case sensitivity.
- Test coverage: Worktree realpath resolution, early config reading, case sensitivity, non-repository worktrees, bare repositories, multiple worktrees, **symlinked paths (now passing Patrick’s test case)**, cross-platform path handling. **New edge cases for v7**: nested symlinks, Windows junctions, `$PWD` manipulation.
