Core problem or goal
Extend `git repo info` to support category-based prefix queries (e.g., `git repo info layout` returns all keys under the `layout.*` namespace) to improve usability as the number of supported metadata keys grows. The original proposal has been reconsidered in response to maintainer feedback: the author now argues that such a query system is premature for a plumbing command and proposes abandoning the feature in favor of a different GSoC task.

Current status
Initial submission (v1) under review; design direction has shifted. The patch is effectively shelved unless further discussion revives it. No merge status; still under review, but the focus has moved to a new project direction.

- **Files touched**: `builtin/repo.c`, `Documentation/git-repo.adoc`, `t/t1900-repo-info.sh` (original patch)
- **Behavior change**: original patch replaced `bsearch` with linear search to find first matching prefix in the `repo_info_field` array (justified by small array size)
- **New CLI behavior**: original patch accepted partial namespace prefixes (e.g., `layout`) but rejected ambiguous partial matches (e.g., `lay`)
- **Error handling**: original patch returned non-zero exit code and descriptive message for invalid prefixes
- **Test coverage**: original patch verified successful prefix queries and proper error handling for invalid inputs
- **On-disk format**: no changes; query interface enhancement only
- **Proposed design change**: Junio suggested a hybrid exact-match/glob-matcher design; author now proposes abandoning the feature entirely for this command.
