Core problem or goal
Extend `git repo info` to support category-based prefix queries (e.g., `git repo info layout` returns all keys under the `layout.*` namespace). The change addresses usability friction as the number of supported metadata keys grows, eliminating the need for external filtering (e.g., `grep`) of `--all` output. Junio C Hamano has raised a design question: whether the feature should support glob patterns (e.g., `layout.*`) instead of or in addition to simple prefix matching, arguing that globs would be more expressive and better match user intent.

Current status
Initial submission (v1) under review; no prior discussion. Patch is self-contained but requires design reconsideration before proceeding. No merge status; still under review.

Key technical details
- **Files touched**: `builtin/repo.c`, `Documentation/git-repo.adoc`, `t/t1900-repo-info.sh`
- **Behavior change**: replaces `bsearch` with linear search to find first matching prefix in the `repo_info_field` array (justified by small array size)
- **New CLI behavior**: accepts partial namespace prefixes (e.g., `layout`) but rejects ambiguous partial matches (e.g., `lay`)
- **Error handling**: returns non-zero exit code and descriptive message for invalid prefixes
- **Test coverage**: verifies successful prefix queries and proper error handling for invalid inputs
- **On-disk format**: no changes; this is a query interface enhancement only
- **Proposed design change**: Junio suggests a hybrid approach: first attempt an exact match using the existing `bsearch()` code path; if that fails, fall back to a prefix (or glob) matcher to collect all matching keys. This preserves backward compatibility while enabling the new functionality.

Open questions and loose ends
- **Design direction**: Should the feature support glob patterns (e.g., `layout.*`) in addition to or instead of simple prefix matching? Junio favors globs for expressiveness and future-proofing.
- **Implementation trade-offs**: The patch abandons binary search for linear search; Junio notes that the additional complexity of glob matching would be negligible given this change.
- No conditional approvals or objections raised beyond the design question.
