This is the third patch in Patrick Steinhardt’s nine-patch series making `GIT_TEST_LONG` tests reliable and efficient in CI. It targets `t4141-apply-too-large.sh`, a test that verifies `git apply` rejects patches larger than Git’s internal limits.

The patch replaces an extremely inefficient pipeline: the test previously used `test-tool genzeros` to generate an unbounded stream of zeros, then piped it through `test_copy_bytes` (which copies one byte at a time via `dd ibs=1`) to limit the output to 1 GiB. This approach took up to 40 minutes in CI. The fix removes `test_copy_bytes` entirely and instead passes the desired byte count directly to `genzeros`, which already supports a limit argument and is optimized for fast generation. The change cuts runtime from minutes to under a second.

Despite the dramatic speed-up, the patch retains the `EXPENSIVE` prerequisite. The commit message explains that `git apply` still loads the entire 1 GiB patch into memory, so the test remains resource-intensive. This concession addresses feedback from SZEDER Gábor on the v1 series, where he argued that memory usage—not just runtime—should determine whether a test is labeled expensive.

The patch is a clean, mechanical change to a single test script. It is uncontroversial and appears ready for integration. No user-facing behavior changes are introduced.
