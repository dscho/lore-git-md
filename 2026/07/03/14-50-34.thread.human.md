This thread introduces a small but useful feature: teaching `git history` to sign rewritten commits (`fixup`, `reword`, `split`) using the same GPG-signing controls (`commit.gpgsign`, `-S/--gpg-sign`) already available in `git commit`. The series is at its first version, posted by Souma, and has so far drawn one substantive review from Patrick Steinhardt.

Patrick’s feedback is mostly about code organization and clarity. He asks that the documentation and usage text changes be folded into the main implementation patch to avoid breaking hypothetical tests that check command-line help consistency. He also flags a few mechanical issues—parameter ordering, unused callback data, and config-parsing logic—and suggests splitting the `replay.c` plumbing into a separate preparatory commit. The only conceptual question he raises is whether it’s appropriate to sign *every* rewritten commit, even those whose content wasn’t authored by the person doing the rewriting; this could create misleading signatures if the original author’s work is signed by someone else. No one else has weighed in yet, so the discussion remains open on both the patch structure and the signing policy. A v2 is likely once these points are addressed.
