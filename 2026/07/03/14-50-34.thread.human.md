This thread is about teaching `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`) using the same GPG-signing configuration and command-line options already supported by `git commit`. The series, now at version 2, is authored by Souma and remains under active review.

The key change is that rewritten commits now respect `commit.gpgsign`, `-S/--gpg-sign`, and `--no-gpg-sign`, with command-line options overriding configuration. The implementation touches the replay machinery in `replay.c` and `builtin/history.c`, plumbing a new `sign_commit` field through several functions. The on-disk format remains unchanged—only the commit object’s signature trailer is added when signing is enabled. Tests in `t3451` through `t3454` verify all flag/config combinations, including explicit key selection and the no-new-commit case for `drop`.

Patrick Steinhardt’s feedback from the first version has been fully addressed: the replay API plumbing is now split into a dedicated preparatory patch, and the documentation and tests are folded into the main feature patch. The commit message now discusses the conceptual trade-off of signing commits originally authored by someone else, though this remains unresolved. No new feedback has emerged since the v2 posting, so the series is still awaiting further review.
