This thread is about teaching `git history` to sign rewritten commits (like `drop`, `fixup`, `reword`, and `split`) using the same GPG-signing options already supported by `git commit`. The series is now at version 2, with Souma addressing feedback from Patrick Steinhardt on the first version.

The key change in this update is a cleaner split of the replay API plumbing. The first patch (just summarized) refactors the replay machinery to accept a signing option, while the second patch will introduce the actual signing behavior, documentation, and tests. This separation makes the changes easier to review. The series still hasn’t received a maintainer decision, but it’s under active review and likely to see further tweaks.

The main open question remains whether signing rewritten commits—especially those originally authored by someone else—is a good idea or could be misleading. This is now discussed in the commit message, but no consensus has emerged yet. So far, only Patrick has provided substantive feedback, and all his requests from v1 have been addressed in v2.
