This thread introduces a small but useful feature: teaching `git history` to sign rewritten commits (`fixup`, `reword`, `split`) using the same GPG-signing controls (`commit.gpgsign`, `-S/--gpg-sign`) already available in `git commit`. The series is at its first version, authored by Souma, and touches the core `history` command implementation, replay machinery, and documentation.

Patrick Steinhardt has reviewed the series and raised a structural concern: the documentation and usage text changes should be folded into the first patch (the core implementation) rather than split into separate patches. His reasoning is that the changes are tightly coupled and leaving them separate risks breaking test coverage if only the first patch is applied. This feedback is substantive but focused on patch organization, not the technical content of the feature itself. No other reviews or objections have surfaced yet, and the series remains under initial review.
