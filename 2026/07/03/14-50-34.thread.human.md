This thread introduces a small but useful quality-of-life improvement: teaching `git history` to sign rewritten commits (`fixup`, `reword`, `split`) using the same GPG configuration and command-line options already supported by `git commit`. The series is at its first iteration (v1) and consists of three patches touching the history command implementation, replay machinery, and documentation.

Souma’s implementation plumbs the signing logic through the existing `commit_tree_ext` and `commit_tree_with_edited_message` functions, adding a new `sign_commit` field to the `replay_revisions_options` struct and a `history_config` callback to pick up the `commit.gpgsign` setting. The on-disk format remains unchanged—only the commit object’s signature trailer is added when signing is enabled.

The third patch, just arrived, adds comprehensive test coverage in three new test scripts (`t3451`, `t3452`, `t3453`). Each script verifies that the three subcommands respect both the configuration and the command-line flags (`-S`, `--gpg-sign`, `--no-gpg-sign`), including precedence rules and the replay of descendant commits. The tests are gated on the `GPG` prerequisite and cover every combination of config and flag.

No reviews or objections have appeared yet, so the series is still in its initial state. If the implementation holds up under scrutiny, it should be a straightforward merge, bringing `git history`’s signing behavior in line with the rest of the commit tooling.
