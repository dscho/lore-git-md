This is the twelfth and final patch in Patrick Steinhardt’s v3 series hardening Git’s reftable backend against security vulnerabilities in maliciously corrupted files. It fixes a heap-buffer-overflow in `reftable_table_new()` that occurs when a truncated reftable file is too small to contain both the header and footer, causing an out-of-bounds read of the footer.

The vulnerability arises because the code computes the table’s data section size by subtracting the footer size from the file size without first verifying that the file is large enough to hold both the header and footer. In a truncated file, this subtraction can underflow, leading to an invalid pointer calculation and an out-of-bounds read when the footer is accessed. The fix adds a bounds check to ensure the file size is at least the sum of the header and footer sizes before proceeding; if not, the function returns `REFTABLE_FORMAT_ERROR`.

The patch includes a new unit test (`test_reftable_table__new_with_truncated_table`) that reproduces the issue by writing a valid reftable block and then truncating it to one byte less than the footer size. The test verifies that `reftable_table_new()` correctly returns the expected error code. The test uses the `cl_reftable_write_to_buf` helper introduced earlier in the series to reduce boilerplate.

This fix is part of the series’ third logical group (security fixes) and touches `reftable/table.c` and the corresponding unit test file. Like the rest of the series, it replaces a crash with a safe error return and does not change any public APIs or on-disk formats. The commit message includes ASan output demonstrating the vulnerability, and the fix is straightforward and well-motivated.
