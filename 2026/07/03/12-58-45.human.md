This is the second patch in Patrick Steinhardt’s 12-patch security-hardening series for Git’s reftable backend, now at v3. The patch adds a new fuzzer (`oss-fuzz/fuzz-reftable.c`) that exercises the reftable parser by feeding it arbitrary byte sequences. The fuzzer targets the three main entry points into the reftable code: ref iterators, log iterators, and raw block iterators. This is part of the series’ broader goal of hardening the reftable backend against maliciously corrupted files, which has already uncovered a range of vulnerabilities (out-of-bounds reads/writes, NULL pointer dereferences, etc.).

The fuzzer is minimal but effective: it wraps the input data in a `reftable_block_source`, initializes a `reftable_table`, and iterates over refs, logs, and raw blocks. The implementation is straightforward, with no new public APIs or on-disk format changes. The patch also updates the build system (`Makefile`, `meson.build`) and CI scripts (`ci/run-build-and-minimal-fuzzers.sh`) to include the new fuzzer, ensuring it runs in Git’s oss-fuzz integration. The `.gitignore` entry is added for completeness.

This patch is uncontroversial and technically sound. It builds on the fuzzing infrastructure introduced in patch 1/12 (Meson support for libFuzzer) and is a prerequisite for the subsequent security fixes in the series. The fuzzer has already been used to discover the vulnerabilities addressed in patches 3–12, and its inclusion in CI will help prevent regressions. No feedback or objections have been raised about this patch in prior iterations (v1 or v2), and it aligns with Git’s existing fuzzing practices.

The patch is part of the series’ first logical group (fuzzing infrastructure), which also includes patch 1/12. The rest of the series focuses on a test helper (patch 5/12) and the security fixes themselves (patches 3–4, 6–12). With all feedback addressed in v3 and no open questions, this patch appears ready for merging. The series as a whole is well-motivated, thoroughly tested, and directly addresses a real security concern.
