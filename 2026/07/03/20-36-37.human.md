This is a **brief technical clarification** in the ongoing discussion about the `SVN` test prerequisite logic. Junio C Hamano explains how Perl interprets the malformed version comparison (`$SVN::Core::VERSION gt '1.1.0'`) due to the shell-quoting bug Peff identified.

The key point: Perl treats sequences of digits separated by dots (e.g., `1.1.0`) as strings where each segment maps to an ASCII character when there are more than two segments. For example, `65.66.67` becomes `ABC`. This means the version comparison (`gt`) is performed lexicographically, not numerically, leading to incorrect results (e.g., `1.14.5` is *not* greater than `1.2.0` as strings). Junio confirms Peff’s suspicion that the `gt` operator is ineffective in this context.
