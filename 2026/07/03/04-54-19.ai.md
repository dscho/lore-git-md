This is the v3 submission of a **test infrastructure improvement** series that introduces `greplint.pl`, a linter to convert bare `grep` assertions in Git's test suite to `test_grep`. The series is now in its final form, addressing all prior feedback and resolving edge cases that could mask or introduce test bugs.

The core goal remains unchanged: replacing bare `grep` with `test_grep` to improve debuggability (since `test_grep` prints file contents on failure). However, v3 incorporates critical refinements from the maintainer and reviewers, particularly around cases where bare `grep` was tolerating missing files—something `test_grep` explicitly rejects with a `BUG`. The author has audited all `# lint-ok` annotations to ensure they do not preserve incorrect test logic, and has adjusted two problematic cases:
- In `t1400-update-ref.sh`, the `.git/packed-refs` check is now guarded by a `REFFILES` prerequisite, since the file is absent under the reftable backend.
- In `t7450-bad-git-dotfiles.sh`, the `git~2` check (an NTFS 8.3 short name) remains a bare `grep` with an explanatory comment, as the file’s presence depends on platform-specific settings.

The series also fixes three pre-existing bugs where `grep` was missing file arguments (now reading empty stdin), and extracts `chainlint.pl`'s shell parser into a shared module (`lib-shell-parser.pl`) to avoid code duplication. A latent line-counting bug in the lexer was fixed, though it only affected `greplint.pl`'s reporting.

Key files introduced or modified:
- `greplint.pl`: The new linter, with test fixtures under `t/greplint/`.
- `lib-shell-parser.pl`: Shared shell tokenizer for `chainlint.pl` and `greplint.pl`.
- `t/README`: Documents `test_grep` and its requirements (e.g., file existence).
- `Makefile`: Wires `greplint.pl` into `test-greplint` and `check-greplint` targets.

The conversion itself touches ~340 test files, replacing ~2800 `grep` assertions. The linter intentionally skips `grep` used as data filters (e.g., `grep -vf` or `grep <file`) or with redirects, as these require judgment calls about preserving output behavior. A follow-up series may address these cases once conventions are established.

This version is ready for merging, with no open technical concerns. The author’s audit of `# lint-ok` annotations and the maintainer’s acceptance of the approach (after initial skepticism) signal consensus. The series improves test reliability while avoiding false positives, and the shared parser infrastructure enables future lint rules. Expect this to graduate to `next` shortly.
