This is a feature patch series (3 patches) from Souma that teaches `git history` to sign rewritten commits. The series makes the `fixup`, `reword`, and `split` subcommands respect the `commit.gpgsign` configuration variable and the `-S/--gpg-sign` and `--no-gpg-sign` command-line options. It adds regression tests for configuration-driven signing, command-line overrides, and descendant-commit replay, and updates the `git-history` documentation to reflect the new behavior.

The core change is in `builtin/history.c` and `replay.c`, where the commit-creation logic is extended to pass signing options through to the underlying commit machinery. The test coverage spans all three subcommands (`t3451` for `reword`, `t3452` for `split`, `t3453` for `fixup`) and verifies that signing is triggered by both config and flags, that command-line flags override config, and that descendant commits replayed after a rewrite retain their original signing status. The documentation patch adds a short section on signing options and cross-references the `git-commit` man page for details on `-S`.
