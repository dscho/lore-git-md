This is the sixth patch in Patrick Steinhardt’s nine-patch v2 series making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets `t7900-maintenance.sh`, an expensive test that creates a 2 GB repository to exercise the incremental-repack task.

The patch isolates the 2 GB repository into a dedicated sub-repository (`expensive-repo`) that is deleted immediately after the test via `test_when_finished`. It also disables auto-maintenance in the sub-repository to prevent races with the manual maintenance commands the test runs. The change reduces peak disk usage by 2 GB and prevents the expensive repository from affecting heuristics used by subsequent tests. No behavior changes are introduced; the test remains gated by both `EXPENSIVE` and `GIT_TEST_LONG`.

The diff is mechanical and well-motivated: the commit message clearly explains the disk usage and state pollution problems, and the implementation (wrapping the test in a subshell, using `test_when_finished`, and disabling auto-maintenance) is a standard pattern for isolating expensive test data. The patch is uncontroversial and appears ready for integration. It complements the efficiency improvements in patches 3 and 4, which also reduce disk usage in other `GIT_TEST_LONG` tests.
