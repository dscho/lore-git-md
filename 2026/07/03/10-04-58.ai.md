Phillip Wood adds a key technical clarification: the observed behavior depends on whether the shell expands the `*.json` glob before Git sees it. If no `.json` files exist in the current directory, the shell passes the literal `*.json` to Git, which then treats it as a pathspec that recurses into subdirectories. If `.json` files *do* exist, the shell expands the glob to those filenames, and Git receives explicit paths that do not recurse. This explains why Matt Hunter (in the earlier thread) could not reproduce the behavior—his shell likely expanded the glob.

The observation shifts the discussion toward user expectations: the confusion arises not just from Git’s pathspec rules but from the interaction between shell globbing and Git’s argument parsing. Phillip’s point suggests the documentation gap might be more about this interaction than about pathspecs alone.
