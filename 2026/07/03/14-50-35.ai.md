This is the first patch in Souma's three-patch series teaching `git history` to sign rewritten commits. It extends the `fixup`, `reword`, and `split` subcommands to respect the `commit.gpgsign` configuration variable and the `-S/--gpg-sign` and `--no-gpg-sign` command-line options.

The patch adds a new `history_config` callback that reads `commit.gpgsign` and stores the result in a `sign_commit` string. It introduces a new `OPT_HISTORY_GPG_SIGN` macro to parse the `-S/--gpg-sign` option, which overrides the config setting. The `sign_commit` string is then plumbed through the commit-creation functions (`commit_tree_ext`, `commit_tree_with_edited_message`, `split_commit`) and into the replay machinery (`replay.c`), where it is passed to `commit_tree_extended` to add the GPG signature trailer when signing is enabled.

Key technical details: the patch touches `builtin/history.c` and `replay.c`, adding a new `sign_commit` field to the `replay_revisions_options` struct. The on-disk format is unchanged; only the commit object's signature trailer is added when signing is enabled. The patch updates the usage strings for all three subcommands to document the new `--[no-]gpg-sign` option. The plumbing ensures that descendant commits replayed after a rewrite retain their original signing status unless explicitly overridden.
