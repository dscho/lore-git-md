This is a platform-compatibility bugfix targeting macOS, continuing the discussion of Ihar Hrachyshka's patch to fix a crash in Git's `precompose_utf8` layer when handling long UTF-8 filenames. The patch itself is not being resent here; instead, Patrick Steinhardt raises two technical points about the implementation.

Patrick first questions why macOS allows filenames longer than `NAME_MAX` (255 bytes) in the first place, noting that this seems unusual and asking whether macOS treats Unicode characters specially in its byte counting. This is a substantive inquiry about the platform's behavior rather than a critique of the patch, and it may uncover edge cases or platform-specific quirks that could inform future work.

On the implementation, Patrick suggests using Git's `FLEX_ALLOC_MEM()` macro instead of introducing a new helper function (`dirent_prec_psx_size()`). He also observes that the current patch over-allocates memory for most directory entries, since it always allocates space for `NAME_MAX + 1` bytes upfront even when filenames are shorter. He proposes that the initial allocation should be sized more precisely to match the actual filename length, though he acknowledges that reallocation during `precompose_utf8_readdir()` would still require the helper function for resizing.

The review is substantive, engaging with both the platform-specific behavior and the memory management details of the fix. Patrick's feedback is constructive and signals that the patch is on track for acceptance once these adjustments are made.
