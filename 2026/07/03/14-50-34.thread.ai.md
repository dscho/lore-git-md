Thread identity
Subject: [PATCH 0/3] teach `git history` to sign rewritten commits
Series version: v1 (v2 anticipated)
Originating author: Souma
Thread type: patch series

Core problem or goal
Teach `git history` to sign rewritten commits (`fixup`, `reword`, `split`) using the same configuration (`commit.gpgsign`) and command-line options (`-S/--gpg-sign`, `--no-gpg-sign`) already supported by `git commit`.

Current status
Series is at v1; no maintainer decision yet. Patrick Steinhardt’s substantive review requests mechanical cleanups, a preparatory split of `replay.c` changes, and a discussion of the conceptual trade-off around signing commits authored by others. A v2 is likely.

Key technical details
- Files touched: `builtin/history.c`, `replay.c`, `Documentation/git-history.txt`, `t/t3451-history-reword.sh`, `t/t3452-history-split.sh`, `t/t3453-history-fixup.sh`
- New behavior: `fixup`, `reword`, `split` now respect `commit.gpgsign`, `-S[=<key-id>]`, `--gpg-sign[=<key-id>]`, and `--no-gpg-sign`
- New symbols: `history_config` callback, `OPT_HISTORY_GPG_SIGN` macro, `sign_commit` field in `replay_revisions_options` struct, plumbing through `commit_tree_ext`, `commit_tree_with_edited_message`, `split_commit`, and `replay.c` machinery
- On-disk format: unchanged; only the commit object’s signature trailer is added when signing is enabled
- Test coverage: new tests in `t3451`, `t3452`, `t3453` verify config-driven signing, command-line overrides, and descendant-commit replay for `reword`, `split`, and `fixup`; tests are GPG-gated and cover all flag/config combinations

Open questions and loose ends
- **Patch organization**: Patrick Steinhardt requests that the documentation update (patch 2/3) and usage text change (patch 3/3) be folded into the first patch (the core implementation), arguing that the current split risks breaking `t0450` (a hypothetical test checking command-line help or synopsis consistency) if only the first patch is applied.
- **Parameter ordering**: `commit_tree_with_edited_message` and `split_commit` should keep the `out` parameter last for consistency.
- **Config callback**: `history_config` should pass `NULL` instead of `data` to `git_default_config` since `data` is unused.
- **Conceptual trade-off**: whether signing rewritten commits that were originally authored by someone else is desirable or misleading; this should be discussed in the commit message.
- **Preparatory split**: Patrick recommends splitting the `replay.c` changes into a separate commit before the main feature patch.

Participant positions
