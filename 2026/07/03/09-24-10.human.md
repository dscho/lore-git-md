This is the seventh patch in Patrick Steinhardt’s nine-patch v2 series making `GIT_TEST_LONG` tests reliable and efficient for CI. It introduces consistent boolean parsing for the `GIT_TEST_LONG` environment variable by switching to the `test_bool_env` helper.

The patch touches two files: `ci/lib.sh` and `t/test-lib.sh`. In `ci/lib.sh`, it changes the CI export from `GIT_TEST_LONG=YesPlease` to `GIT_TEST_LONG=true`, aligning with the boolean convention. In `t/test-lib.sh`, it updates the command-line flag (`--long-tests`) to set `GIT_TEST_LONG=true` instead of `GIT_TEST_LONG=t`, and modifies the `EXPENSIVE` prerequisite to use `test_bool_env GIT_TEST_LONG false`, ensuring the variable can be explicitly disabled (e.g., `GIT_TEST_LONG=false`).

The change is mechanical and uncontroversial, addressing a minor but real usability gap: previously, setting `GIT_TEST_LONG=false` had no effect because the test suite only checked for non-empty values. The new behavior is more intuitive and matches Git’s conventions for boolean environment variables. No user-facing behavior changes are introduced, and the patch is ready for integration.
