This is the fourth patch in Patrick Steinhardt’s v2 series making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets `t5608-clone-2gb.sh`, a test that exercises Git’s ability to handle large repositories by creating and cloning repositories with multi-gigabyte packfiles.

The patch reduces the test’s peak disk usage from 16 GB to 8 GB by deleting repositories immediately after they are no longer needed. The key change is wrapping each clone operation in `test_when_finished rm -rf`, which ensures the repository is removed as soon as the test step completes. The setup repository (`2gb-repo`) is also deleted explicitly after the first two clone tests, and the two 4 GB clones (`4gb-clone-unpack` and `4gb-clone-index`) are similarly cleaned up. The refactoring is mechanical: the test logic remains identical, but the repositories are now isolated in dedicated directories and pruned as soon as possible.

No new test prerequisites, environment variables, or user-facing behavior are introduced. The patch is uncontroversial and aligns with the series’ goal of making expensive tests more CI-friendly. Jeff King (Peff) reviewed the patch in v1 and described it as an "obvious improvement" for disk usage and defensive isolation of expensive test data, though he noted the runtime remains unchanged. The change is self-contained and does not interact with other patches in the series beyond the shared goal of reducing resource consumption.
