This is a brief follow-up from Junio C Hamano in the thread about standardizing `--help` exit codes across Git's parse-options API. The series has already been merged, but Jeff King (Peff) previously raised two post-merge concerns about unintended consequences: a theoretical edge case in shell-eval mode scripts and a more concrete regression scenario for scripts that wrap Git commands without parsing their own options.

Junio acknowledges Peff’s second point—the "hacky little scripts" scenario—as a "much more likely breakage scenario" than he initially imagined. He doesn’t propose any changes or suggest reverting the series, but his agreement signals that this behavioral trade-off is now officially documented as a known risk. The tone is matter-of-fact, treating the issue as a minor but real side effect of the fix rather than a flaw requiring action.

No new technical details or patches are introduced here; this is purely a confirmation of Peff’s assessment. For readers tracking the thread, it’s a signal that the discussion about edge cases is now settled, with the project accepting the trade-off as part of the broader effort to standardize help behavior.
