This is a platform-compatibility bugfix targeting macOS. The patch addresses a crash in `` `git status` `` when reading directory entries with UTF-8 filenames longer than `NAME_MAX` bytes (typically 255). The crash occurs because the precompose UTF-8 wrapper reallocates its internal buffer for long names, but the `d_name` field is declared as a fixed-size array, triggering fortified libc checks that reject the copy even though the allocation was grown.

The fix changes `d_name` to a flexible array member and sizes allocations using `offsetof()`, ensuring the fortified copy sees a destination whose size matches the actual allocation. A new regression test creates a 261-byte non-ASCII filename and verifies that `` `git status` `` runs successfully with `core.precomposeunicode` enabled.
