This is the second patch in the v6 series introducing `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` conditions to Git’s config system. The patch implements the core functionality described in the cover letter: it adds the new conditions, documents them, and provides comprehensive test coverage.

The implementation reuses the `include_by_path()` helper introduced in patch 1/6, passing the worktree’s realpath (from `repo_get_work_tree()`) as the match target. The conditions support glob patterns with `**/`, `~/`, and `./` expansion, and the `/i` variant performs case-insensitive matching. The patch explicitly handles edge cases: bare repositories (no worktree, so no match), early config reading (no repository available, so no match), and non-repository contexts (no match).

Documentation is thorough, explaining the difference between `worktree` and `gitdir` patterns, providing practical examples, and contrasting the new feature with `extensions.worktreeConfig`. The tests cover multiple worktrees, symlinked paths, case sensitivity, early config reading, and non-repository scenarios.

This patch is well-crafted and directly addresses the usability gap in multi-worktree setups. The implementation is clean, the tests are exhaustive, and the documentation is clear. If the series lands, this will be a welcome addition for users managing multiple worktrees with different configuration needs.
