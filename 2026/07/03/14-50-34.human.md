This is a feature patch series that extends Git’s commit-signing behavior to cover rewritten commits in `git history`. The series consists of three patches: the core implementation, documentation updates, and regression tests.

The motivation is straightforward: when users run `git history fixup`, `reword`, or `split`, the rewritten commits now respect the `commit.gpgsign` configuration setting, as well as the `-S/--gpg-sign` and `--no-gpg-sign` command-line options. This brings the `history` command in line with how `git commit` and `git rebase` already handle signing.

The implementation touches `builtin/history.c` and the underlying `replay.c` machinery, adding a new `sign_commit` flag to the replay options and plumbing it through the rewrite logic. The tests cover the three main scenarios: configuration-driven signing, command-line overrides, and the handling of descendant commits that are replayed after a rewrite.
