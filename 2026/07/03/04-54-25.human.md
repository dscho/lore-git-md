This is the final patch in a **test infrastructure** series that introduces `greplint.pl`, a linter to enforce the use of `test_grep` over bare `grep` in Git’s test suite. The series is now complete and ready for merging, with all prior feedback addressed.

The patch adds the linter itself, which scans test scripts for bare `grep` assertions (where `test_grep` should be used) and incorrect negations (`! test_grep` instead of `test_grep !`). The tool reuses the shared shell parser from `lib-shell-parser.pl` (introduced earlier in the series) to avoid false positives—it correctly skips `grep` inside heredocs, command substitutions, and quoted strings. The linter also handles edge cases like backslash-continued lines in double-quoted test bodies, ensuring accurate line-number reporting.

Key features of `greplint.pl`:
- Detects bare `grep` used as assertions (not filters) and flags them with clear error messages.
- Catches incorrect negations (`! test_grep`) that suppress diagnostic output.
- Respects `# lint-ok` annotations for intentional exceptions (e.g., platform-specific paths).
- Includes comprehensive test fixtures under `t/greplint/` to verify detection logic and edge cases.
- Integrates into the build system via `test-greplint`, `check-greplint`, and `clean-greplint` targets.

The patch also adds `.gitattributes` entries to ensure consistent line endings for the linter’s test fixtures, matching the existing `chainlint` setup. With this addition, the series achieves its goal: preventing regression of bare `grep` assertions while maintaining flexibility for legitimate uses. The maintainer’s earlier concerns about `# lint-ok` exemptions have been resolved, and the linter’s design—leveraging the shared shell parser—avoids duplication with `chainlint.pl`. This is a well-crafted, thoroughly tested contribution that improves test reliability without disrupting existing workflows.
