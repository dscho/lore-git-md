This is the fifth patch in Patrick Steinhardt’s v2 series making `GIT_TEST_LONG` tests reliable and efficient in CI. It targets a specific test in `t7508-status.sh` that creates and tracks files larger than 4 GiB, which is only possible on systems where `size_t` is 64-bit. The test was already marked `EXPENSIVE` due to its runtime, but it was also silently broken (and hanging) on 32-bit platforms in GitHub’s `linux32` CI job since `GIT_TEST_LONG` was enabled there in May 2026.

The fix is minimal and surgical: the test now gains the `SIZE_T_IS_64BIT` prerequisite, skipping it on 32-bit systems where Git cannot track object sizes beyond 4 GiB. The change is uncontroversial and aligns with the series’ goal of making expensive tests reliable. No behavior changes are introduced for 64-bit platforms, and the test remains gated by both `EXPENSIVE` and `GIT_TEST_LONG`. The patch touches only one line in the test script and carries a clear commit message explaining the platform limitation. It is ready for integration.
