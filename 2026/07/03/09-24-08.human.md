This is the fifth patch in Patrick Steinhardt’s nine-patch v2 series making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets a single test in `t7508-status.sh` that creates files larger than 4 GiB, which Git can only handle when `size_t` is 64-bit. On 32-bit systems the test fails and—worse—hangs in the `linux32` CI job, masking the actual error.

The fix is minimal: add the `SIZE_T_IS_64BIT` prerequisite to the test’s `test_expect_success` line. This skips the test on 32-bit platforms where it cannot succeed, eliminating the hang and making the failure visible. The change is uncontroversial and matches the pattern already used elsewhere in the test suite for similar size-related constraints. No new infrastructure is introduced; the patch simply applies an existing mechanism to a broken test.
