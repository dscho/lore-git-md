This is a build system patch for the ongoing Rustification effort, specifically enabling macOS Universal Binary support for Rust components in Git. Junio C Hamano reviews the second patch in Shardul Natu and Koji Nakamaru’s v3 series, which introduces the `RUST_TARGETS` environment variable to compile separate Rust static libraries for multiple architectures (e.g., x86_64 and arm64) and combine them into a single Universal Binary using `lipo`.

Junio’s feedback is surface-level and focuses on minor style nits in the Makefile. He notes the commit message is now much clearer about the technical rationale—explaining why Cargo requires separate invocations per target triple while the C toolchain handles multi-architecture builds natively via `-arch` flags. The review points out two small issues: an unnecessary `@` prefix in a `mkdir` command (inconsistent with existing patterns) and a shell script `if [ ... ]` construct that should use `test` instead to align with Git’s coding guidelines. No substantive objections remain; the patch is otherwise well-structured and addresses earlier feedback on directory creation and motivation.

The series as a whole is converging, with the first patch (fixing a parallel build race condition) already uncontroversial. The Universal Binary implementation is now accepted in principle, pending these minor adjustments. The changes are build-time only, with no on-disk format or runtime behavior impact, and are implicitly covered by existing build tests. This patch is worth attention from macOS distributors and CI maintainers, as it enables a single Git artifact to run natively across Intel and Apple Silicon Macs without Rosetta.
