This is a **build system** and **platform compatibility** follow-up in the ongoing discussion about the `USE_NSEC` knob, which controls whether Git tracks sub-second file timestamps. D. Ben Knoble chimes in to reinforce the case for his original patch that adds a `nanosec` Meson build option mirroring the existing Autotools and Makefile `USE_NSEC` setting.

Knoble reports that his own testing on **XFS** confirms Jeff King’s findings on ext4 and ext2: nanosecond timestamps survive cache drops, meaning `USE_NSEC` would not trigger spurious "racy Git" mismatches on that filesystem either. This further undermines the historical concern that coarse-grained filesystems would break Git’s stat-based timestamp tracking. Knoble’s message is brief but pointed: the original patch still makes sense for **build system parity**, especially for source-based distributions like Gentoo that want to expose the knob to users who know their filesystem supports nanoseconds. He does not engage with the larger questions about default behavior, runtime configuration, or deprecation—those remain open—but his stance is clear: unless `USE_NSEC` is removed entirely, the Meson option should proceed.
