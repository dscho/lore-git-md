This is the fourth patch in Patrick Steinhardt’s v2 series making `GIT_TEST_LONG` tests more reliable and efficient for CI. It targets `t5608-clone-2gb.sh`, a test that exercises Git’s ability to handle large repositories by creating and cloning repositories with multi-gigabyte packfiles.

The test previously created a sequence of repositories—first a 2 GB setup repo, then a bare clone, a worktree clone, a 4 GB repo, and two more clones—without cleaning up intermediate repositories. This led to peak disk usage of around 16 GB, even though some repositories were hardlinked. The patch refactors the test to delete each repository immediately after it is no longer needed, cutting peak disk usage in half to 8 GB. The changes are mechanical: the test now wraps repository creation in subshells, uses `test_when_finished` to schedule cleanup, and explicitly removes the 2 GB repository before moving on to the 4 GB test cases.

The commit message is clear and detailed, explaining both the problem (excessive disk usage) and the solution (immediate cleanup). The patch itself is straightforward and uncontroversial, touching only the test script with no user-facing behavior changes. It is part of a larger, well-motivated effort to make expensive tests viable in CI, and the series as a whole looks ready for integration. This specific patch is an obvious improvement that reduces resource consumption without affecting test coverage.
