This is the first patch in a three-part feature series that teaches `git history` to sign rewritten commits. It extends the `fixup`, `reword`, and `split` subcommands to respect the `commit.gpgsign` configuration variable and the `-S/--gpg-sign` and `--no-gpg-sign` command-line options, matching the behavior already supported by `git commit`.

The patch touches `builtin/history.c` and `replay.c`, adding a new `sign_commit` parameter that propagates through the commit-creation and replay machinery. It reads the signing configuration early in each subcommand, defines a new `OPT_HISTORY_GPG_SIGN` macro to handle the `-S` flag, and updates all relevant functions to pass the signing key through to `commit_tree_extended`. The changes are mechanical and follow the established pattern used elsewhere in Git.

The implementation looks clean and well-scoped: it does not alter the on-disk format, only adds the signature trailer when signing is enabled, and maintains backward compatibility by defaulting to no signing when neither config nor flags are set. The patch is part of a larger effort to make `git history` behave more like the rest of Git’s commit machinery, and the series as a whole appears to be a sensible, user-facing improvement.
