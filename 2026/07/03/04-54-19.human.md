This is the final version of a well-executed test infrastructure improvement. The series introduces `greplint.pl`, a new linter that converts bare `grep` assertions in Git's test suite to `test_grep`, improving debuggability by showing file contents on failure. The v3 reroll addresses all remaining concerns from the maintainer and reviewers, making this ready for merging.

The key changes since v2 are surgical: the series now properly handles edge cases where files may not exist (e.g., backend-specific files or platform-dependent paths like NTFS 8.3 short names). The most notable fix is in `t1400-update-ref.sh`, where the `.git/packed-refs` check is now guarded by a `REFFILES` prerequisite to avoid `test_grep` BUGing under the reftable backend. Another fix leaves the NTFS short-name check in `t7450-bad-git-dotfiles.sh` as a bare `grep` with a clear `# lint-ok` annotation, since the file's presence is conditional on 8.3 name generation.

The series is thorough: it documents `test_grep` in `t/README`, fixes three pre-existing bugs where `grep` was missing file arguments, extracts chainlint's shell parser into a shared module for reuse, and includes a line-counting fix for multi-line command substitutions. The conversion itself touches ~340 test files, replacing ~2800 `grep` assertions while preserving cases where `grep` is used as a data filter rather than an assertion. The linter is wired into the Makefile as `test-greplint` and `check-greplint`, ensuring new bare `grep` assertions are caught early.

The author has been responsive to feedback, and the maintainer's concerns about latent bugs being preserved by automated conversion have been fully addressed. The remaining limitation (assertions like `grep pattern file >/dev/null` or `grep pattern <file`) is explicitly called out as follow-up work, but this series stands on its own as a clear improvement. The commit messages are detailed and the code is clean, making this a low-risk, high-value addition to Git's test infrastructure.
