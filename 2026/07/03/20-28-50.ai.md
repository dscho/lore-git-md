This is a **bugfix patch** for the `--exclude-first-parent-only` option in `git rev-list`, addressing the misbehavior reported by Michael Hore. The patch is authored by Junio C Hamano and targets the revision traversal subsystem (`revision.c`), specifically the `process_parents()` function.

The fix introduces logic to break out of the parent-processing loop early when `--exclude-first-parent-only` is active and either (1) a parent commit fails to parse or (2) a parent has already been marked as `SEEN`. This prevents the exclusion logic from incorrectly marking commits as uninteresting when additional commits are explicitly specified on the command line. The patch includes a new test case in `t/t6012-rev-list-simplify.sh` that reproduces the reported scenario and verifies the fix.

Junio notes that the original author of `--exclude-first-parent-only` (introduced in 2022) is no longer active, and he expresses uncertainty about whether the fix might break other intended use cases. The patch is straightforward but touches a core part of the revision-walking machinery, so it may attract scrutiny from reviewers familiar with this subsystem. The test coverage is minimal but sufficient to verify the reported issue.

This is a **standalone patch** (not part of a series) and appears to be a direct response to the bug report. The fix is well-motivated and addresses a clear edge case, though the lack of input from the original feature author leaves some room for debate about the intended behavior. The patch is likely to be merged if no regressions are identified.
