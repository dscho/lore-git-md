This is a **maintainer follow-up** in the macOS Unicode filename crash thread. Junio C Hamano responds to Torsten Bögershausen’s review of the patch, agreeing that the test should declare a `PERL` prerequisite if it continues to use Perl—but suggesting an even better approach: rewriting the test to avoid Perl entirely.

The test in question creates a 261-byte UTF-8 filename (249 'a' characters + 3 em-dashes + ".md") to trigger the crash fixed by the patch. Currently, it uses Perl to generate the filename, which is why Torsten raised the `PERL` prerequisite question. Junio points out that Perl isn’t actually necessary: the long string of 'a's can be generated with shell tools, and the 9-byte UTF-8 sequence (the em-dashes) can be written directly using `printf` with backslash notation. This would make the test more portable and eliminate the need for a `PERL` prerequisite.

No other technical concerns are raised; the discussion remains focused on test robustness. The patch itself—fixing the crash in `precompose_utf8` by converting `d_name` to a flexible array member—is not questioned. Junio’s feedback is procedural and constructive, signaling that the fix is likely to be accepted once the test is adjusted. The thread is now waiting on the original author (a first-time contributor) to send a revised version.
