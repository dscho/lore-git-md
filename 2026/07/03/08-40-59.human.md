This is a platform-compatibility bugfix for macOS, addressing a crash in `git status` when encountering UTF-8 filenames longer than `NAME_MAX` (255 bytes). The patch is part of an ongoing discussion about the best way to fix the issue, with Junio C Hamano and Torsten Bögershausen already having reviewed the original submission.

Patrick Steinhardt now joins the review, raising two technical points. First, he questions why macOS allows filenames longer than `NAME_MAX` in the first place, noting that Unicode character counting might play a role. This isn't directly addressed in the patch but could be relevant for understanding edge cases. Second, he suggests using Git's `FLEX_ALLOC_MEM()` macro instead of introducing a new `dirent_prec_psx_size()` helper function, arguing it would be a cleaner fit. He also observes that the current implementation may overallocate memory for most directory entries, though he acknowledges the reallocation logic in `precompose_utf8_readdir()` makes this unavoidable in some cases.

The patch itself remains well-scoped: it fixes a real crash, includes a regression test, and confines changes to the macOS Unicode normalization compatibility layer (`compat/precompose_utf8.c`). The discussion is now focused on implementation details rather than the core problem or solution. The author will need to revise the patch to address Patrick's feedback, particularly around memory allocation. Once that's done, this looks likely to be accepted, as the fix is technically sound and addresses a clear issue.
