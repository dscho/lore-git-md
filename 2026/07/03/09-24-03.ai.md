This is the v2 revision of a nine-patch series targeting Git’s test suite and CI infrastructure, focusing on the `GIT_TEST_LONG` environment variable and the expensive tests it gates. The series is authored by Patrick Steinhardt, building on an earlier v1 submission by Toon Claes that identified broken and inefficient `GIT_TEST_LONG` tests in CI.

The core goal remains unchanged: make `GIT_TEST_LONG` tests reliable and efficient enough to run in CI without hanging or consuming excessive resources. The v2 revision addresses the only substantive feedback from v1 by restoring the `EXPENSIVE` prerequisite in `t4141-apply-too-large.sh` (patch 3). SZEDER Gábor had objected that the test’s memory usage (over 1 GiB) still justified the label, even though the runtime had been reduced from minutes to under a second. Patrick concedes the point in the updated commit message, acknowledging that the test’s memory footprint remains high despite the efficiency improvement.

The series continues to split into three categories: CI visibility (patches 1, 8, 9), test correctness fixes (patches 2, 5, 7), and test efficiency improvements (patches 3, 4, 6). Patch 1 adds a GitLab CI badge to the README, patch 8 disables the macOS RAM disk (which was causing out-of-memory issues), and patch 9 enables `GIT_TEST_LONG` in GitLab CI for integration branch pushes, excluding Windows runners due to hardware limitations. Patches 2 and 5 skip tests (`t0021-conversion.sh` and `t7508-status.sh`) on platforms where they are known to be broken due to `size_t` limitations, while patch 7 introduces `test_bool_env` to consistently parse `GIT_TEST_LONG` as a boolean. Patches 3, 4, and 6 refactor tests to reduce disk or CPU usage: `t4141` replaces a slow `dd` loop with `fallocate`, `t5608` reduces its maximum file size from 2 GiB to 1 GiB, and `t7900` isolates its 2 GiB repository into a dedicated sub-repository that is deleted immediately after the test.

The changes are mechanical and well-motivated, with clear commit messages explaining each fix. No user-facing behavior changes are introduced, and the series is self-contained with no dependencies on other in-flight topics. The unresolved policy question about how Git defines "expensive" tests (runtime vs. resource usage) remains open, but the technical issues around patch 3 are now resolved. The series looks ready for integration, with no remaining substantive objections.
