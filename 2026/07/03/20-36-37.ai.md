This is a **substantive technical clarification** in the ongoing discussion about the `SVN` test prerequisite logic. Junio C Hamano explains the Perl behavior behind the shell-quoting bug identified by Jeff King (Peff) in the `SVN` prerequisite’s version check (`$SVN::Core::VERSION gt '1.1.0'`).

The issue stems from Perl’s interpretation of dotted numbers: when a string like `1.1.0` is parsed as a bare sequence of digits and dots, Perl treats it as a string of ASCII characters (e.g., `65.66.67` becomes `ABC`), not as a version number. This means the `gt` comparison in the prerequisite is effectively comparing strings, not versions, leading to incorrect results (e.g., `1.14.5` is lexicographically *less* than `1.2.0`). Junio’s examples demonstrate this behavior clearly, confirming Peff’s suspicion that the version check is broken.

This clarification reinforces the need for the follow-up patch brian m. carlson has agreed to write, which will remove the version check entirely and simplify the prerequisite to rely only on the presence of the SVN Perl modules. The impact is limited to test reliability, but the fix will ensure `git-svn` tests are skipped only when SVN is genuinely unavailable, avoiding false negatives. No new technical questions are raised; this email simply provides the missing detail to explain *why* the existing logic fails.
