This is a brief follow-up in the feature-request thread about programmatically marking commits for editing during an interactive rebase.

Michal Suchánek suggests a workaround: setting a custom `EDITOR` script that pre-populates the rebase todo list with "edit" commands for the desired commits. This avoids modifying Git itself but requires users to write and maintain a small script for each use case. The suggestion is pragmatic and low-risk, though Michal acknowledges it may not be ideal for one-off workflows.

The reply does not engage with the technical feasibility or design of Matthias Beyer’s proposed `--edit-commits` option, nor does it address the broader questions about complexity or CLI clutter raised in the original request. It simply offers an existing escape hatch that could achieve the same goal with minimal effort. For users who only occasionally need this functionality, this workaround might be sufficient, but it doesn’t resolve the underlying request for a built-in solution.
