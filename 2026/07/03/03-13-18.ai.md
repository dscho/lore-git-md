This is the second patch in the v6 series introducing `includeIf.worktree:<pattern>` and `includeIf.worktree/i:<pattern>` conditions to Git’s config system. It implements the core functionality described in the cover letter, building on the preparatory refactoring in patch 1/6.

The patch adds the two new condition keywords to `config.c`, using the `include_by_path()` helper introduced earlier. The implementation is straightforward: it passes the worktree’s realpath (obtained via `repo_get_work_tree()`) to the existing pattern-matching logic, with the same glob syntax and case-insensitive variant as `gitdir`. The condition is explicitly designed to never match in bare repositories or during early config reading, where no worktree is available.

Documentation in `config.adoc` is thorough, explaining the difference between `worktree` and `gitdir` patterns, providing practical examples (e.g., personal vs. work configurations), and contrasting the new feature with `extensions.worktreeConfig`. The examples clarify that `worktree` patterns match the checkout directory (as returned by `git rev-parse --show-toplevel`), not the `.git` directory, which is the key usability improvement over `gitdir` in multi-worktree setups.

Test coverage in `t/t1305-config-include.sh` is comprehensive, exercising bare repositories, multiple worktrees, symlinked paths, case sensitivity, early config reading, and non-repository scenarios. The tests confirm that the condition behaves as documented: it resolves symlinks to the realpath, respects case sensitivity based on filesystem, and gracefully handles edge cases like missing repositories.

The patch is well-motivated and technically sound. It addresses a clear gap in multi-worktree workflows without altering existing behavior, and the implementation reuses existing infrastructure. The only potential point of contention—Windows path separators—was already resolved in v6 by using `**` instead of `/` in patterns. This patch is ready for integration and would be a useful addition for users managing multiple worktrees with different configuration needs.
