This is a feature request for a programmatic way to edit commits during an interactive rebase.

Matthias Beyer describes a workflow where he wants to split commits that modified files in a specific subdirectory during a rebase. Currently, he manually cross-references the output of `git log` with the interactive rebase todo list to mark commits for editing. He proposes a hypothetical `--edit-commits` option for `git rebase -i` that would accept a list of commit hashes to automatically mark as "edit" in the todo list.

The request is well-motivated with a concrete use case (improving history clarity by splitting commits that touch certain files) and includes a plausible command-line sketch. It touches the sequencer subsystem (where interactive rebase is implemented) and would likely require changes to `git-rebase--interactive.sh` and possibly the C sequencer code. The proposal is narrowly scoped and does not appear to conflict with existing rebase functionality.

No prior art or related Git features are mentioned in the email, and there is no indication this has been discussed before on the list. The request is framed as a convenience feature rather than a correctness fix, so it may face questions about whether the complexity is justified for a niche workflow.
