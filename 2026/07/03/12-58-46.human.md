This is a security-hardening patch for Git’s reftable backend, part of Patrick Steinhardt’s 12-patch v3 series that systematically hardens the code against maliciously corrupted files. This specific patch (3/12) fixes an out-of-bounds read in the `binsearch()` function when searching an empty range.

The bug is straightforward: `binsearch()` performs a binary search over a range of `sz` elements, but when `sz` is zero (an empty range), it still calls the comparison function with an index of 0, triggering an out-of-bounds read. The fix is equally simple—return early when `sz` is zero. The patch includes a new unit test (`test_reftable_basics__binsearch_empty`) that verifies the function returns 0 without calling the comparison function, ensuring the fix works as intended.

This is a clean, well-scoped fix with a clear commit message and accompanying test. The vulnerability is low-risk (exploitation requires local disk access to corrupt a reftable file), but the fix is uncontroversial and aligns with the series’ goal of hardening the reftable backend. The patch touches only `reftable/basics.c` and adds a test to `t/unit-tests/u-reftable-basics.c`, with no changes to public APIs or on-disk formats.
