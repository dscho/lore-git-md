This is the final patch in Patrick Steinhardt’s 12-part security-hardening series for Git’s reftable backend. It fixes a heap-buffer-overflow when opening a truncated reftable file: if the file is too small to contain both the header and footer, subtracting the footer size from the file size underflows, causing `reftable_table_new()` to read the footer out of bounds. The fix adds a bounds check to verify the file is large enough before computing the table size, returning `REFTABLE_FORMAT_ERROR` if not. The new unit test (`test_reftable_table__new_with_truncated_table`) reproduces the issue by truncating a valid table to one byte short of the footer size and verifies the function now fails gracefully.

The patch is technically straightforward and follows the established pattern of the series: replace a crash with an error return, add a unit test, and include ASan output demonstrating the vulnerability. Junio C Hamano has already approved the majority of the series (patches 6–10), and this patch is consistent with those in both style and substance. The fuzzing infrastructure introduced earlier in the series has not surfaced any new issues, and all prior feedback has been addressed.

This is a security fix targeting a local-only attack vector (corrupted reftable files), but the hardening is comprehensive and the series is now complete. The patch itself is small, well-explained, and accompanied by a clear test case. With no open questions or objections, this final piece appears ready to merge alongside the rest of the series.
