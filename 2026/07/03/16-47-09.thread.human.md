This thread introduces a GSoC feature patch to extend `git repo info` with category-based prefix querying (e.g., `git repo info layout` to list all `layout.*` keys). The initial submission, from a contributor not yet established in the project, implements a simple prefix-matching mechanism but has drawn a substantive design critique from Junio C Hamano.

Junio’s review questions the decision to limit the feature to simple prefixes rather than supporting glob patterns (e.g., `layout.*` or `path.*.absolute`). He argues that globs would be more expressive and better align with user expectations, especially for nested namespaces. Since the patch already replaces binary search with a linear scan for prefix matching, he sees the additional complexity of glob support as negligible. Junio proposes a hybrid design: first attempt an exact match using the existing `bsearch()` logic, then fall back to a prefix or glob matcher if no exact match is found. This would preserve backward compatibility while enabling the new functionality. The review does not oppose the feature itself but calls for a more flexible and future-proof design before the patch is ready for merging.

No other reviews or responses have been recorded yet, and the author has not yet addressed Junio’s feedback. The patch remains under review, with the design direction now contested. The implementation touches `builtin/repo.c`, updates documentation, and adds test coverage, but makes no changes to on-disk formats.
