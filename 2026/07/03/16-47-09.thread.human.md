This thread introduces a new feature for `git repo info`, a command from a Google Summer of Code project, allowing users to query repository metadata by category prefixes (e.g., `git repo info layout` returns all keys under `layout.*`). The patch, submitted as an initial implementation, replaces the existing exact-match lookup with a linear search to support prefix-based queries, justified by the small size of the metadata array. It includes updates to the command's documentation and tests, with clear examples and error handling for invalid inputs.

The change is motivated by usability, addressing the inefficiency of filtering full metadata output externally as the number of supported keys grows. The implementation is self-contained, touching only `builtin/repo.c`, documentation, and tests, and the commit message provides a clear rationale for the linear search trade-off. No prior discussion or review feedback is mentioned, so this appears to be the first public submission of the feature. The design aligns with Git's plumbing command conventions, offering a more ergonomic way to query grouped metadata.
