This is the first patch in Patrick Steinhardt’s 12-patch security-hardening series for Git’s reftable backend. It adds Meson build support for libFuzzer, enabling coverage-guided fuzzing of the reftable parser.

The patch introduces a new Meson build option, `-Dfuzzers_link_args=`, which allows users to pass linker arguments specifically for fuzzing executables. This plugs a gap in the existing build system: while sanitizers like AddressSanitizer can already be enabled via `-Db_sanitize=`, there was no way to link libFuzzer itself (`-fsanitize=fuzzer`) without affecting the entire build. The documentation added to `meson.build` provides clear setup instructions, showing users how to combine `-Db_sanitize=address,fuzzer-no-link`, `-Dfuzzers=true`, and the new `-Dfuzzers_link_args=-fsanitize=fuzzer` to build functional fuzzers.

The change is minimal and focused: it modifies only `meson.build`, `meson_options.txt`, and `oss-fuzz/meson.build`, adding the new option and wiring it into the fuzzer build targets. No existing functionality is altered, and the patch is purely infrastructure. The motivation is clear—fuzzing is the primary tool used to discover the vulnerabilities fixed later in the series—and the implementation is straightforward. This is a well-crafted, uncontroversial patch that lays the groundwork for the hardening work that follows.
