This is the second patch in a two-part performance optimization for `git stash push` in sparse-checkout repositories. It applies the same sparse-index-aware logic already used in `git rm` and `git reset` to avoid unnecessary index expansion when the pathspec is entirely within the sparse-checkout cone.

The patch modifies `builtin/stash.c` to call `pathspec_needs_expanded_index()` before expanding the index. If the pathspec cannot match any sparse-directory entry, the index remains sparse, dramatically improving performance for cone-internal paths. The change is minimal: two lines replaced, with no new symbols introduced. Test coverage is thorough, adding compatibility tests for literal, prefixed, wildcard, file-based, multiple, staged, and missing pathspecs to `t1092-sparse-checkout-compatibility.sh`, and a path-limited stash case to the p2000 performance suite.

Performance impact is striking: on a cone-mode repository with 349,525 tracked paths, `git stash push -- deep/a` drops from 18.9 seconds to 0.06 seconds, with zero index expansions. The patch is well-motivated, clearly explained, and includes regression tests for the heap-buffer-overflow bug fixed in patch 1/2. The series as a whole looks ready for review and appears to address a real, measurable performance problem without introducing behavioral regressions.
