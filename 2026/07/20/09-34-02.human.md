This is a bug report about unintuitive behavior in `git config` when using `--global` with included configuration files.

Hendrik Jaeger describes a scenario where `git config --global user.name` fails to find a configuration value that is set in an included file, even though the same command without `--global` succeeds. The behavior contradicts his expectations and the documentation, which states that `--includes` is disabled by default when a "specific file" is given (listing `--global` as an example). Hendrik argues that `--global` restricts the *scope* rather than specifying a file, so the current behavior feels inconsistent.

He provides a detailed, reproducible shell transcript showing the issue: when `user.name` is set in an included file, `git config --global user.name` returns nothing unless `--includes` is explicitly added, while `git config user.name` works without it. The transcript also demonstrates that `--global` takes precedence over included values when both are present, which may not be obvious to users.

The report is well-structured, with clear steps and expected vs. actual outcomes. Hendrik notes that he has already worked around the issue in the `lbmk` project by adding `--includes`, but he wants to understand whether the current behavior is intentional or a bug. No patches are proposed—this is purely a request for clarification.
