This is the eighth iteration of a refactoring series that migrates `trust_executable_bit` and `has_symlinks` into `struct repo_config_values`, completing the `the_repository` removal effort for these core index-related configuration flags. The series is part of the broader project to eliminate global state in Git’s codebase.

The v8 iteration makes two targeted adjustments to address feedback from Junio C Hamano and SZEDER Gábor. First, it marks the `struct repository *` parameter in `ce_mode_from_stat()` as `UNUSED` in patch 2/4, then removes the annotation in patch 3/4 once the parameter is actually used. This resolves the build-breaking `-Werror=unused-parameter` warning identified in v7. Second, it removes defensive NULL checks in the new getter functions (`repo_trust_executable_bit()` and `repo_has_symlinks()`), opting instead to crash loudly if a NULL repository is passed. This aligns with Junio’s preference for exposing bugs early and matches the pattern used elsewhere in the codebase (e.g., `repo_protect_ntfs()`).

The series remains a mechanical migration with no behavioral changes. It moves both flags into repository-scoped storage, establishes new getter functions, and updates all call sites to use repository-scoped access. The mingw compatibility layer is refactored to use a compile-time macro (`platform_has_symlinks()`) and a static function (`mingw_platform_has_symlinks()`), eliminating mutable global state while preserving native symlink detection. This design follows Git’s existing platform-compatibility conventions.

Files touched include `read-cache.c`, `environment.c/h`, `apply.c`, `compat/mingw.c`, and related headers. The changes are incremental and build on prior work, including an earlier attempt to use `struct repo_settings` (which was deemed suboptimal). The author acknowledges that `repo_config_values()` still does not support non-`the_repository` instances due to deep integration of these flags, but the series lays groundwork for future progress.

The series is uncontroversial and appears ready for inclusion. All prior feedback has been addressed, including the build-breaking issue and stylistic adjustments. The migration pattern established here could serve as a template for similar configuration refactoring efforts, and the mingw adjustments may attract attention from platform maintainers (e.g., Johannes Schindelin). The series is likely to proceed to `next` in Junio’s integration branches.
