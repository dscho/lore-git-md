This is the **second patch in the v3 series** introducing the `--reset-when-found[=<where>]` option to `git bisect`. It implements the core feature: after identifying the first bad commit, the working tree is automatically reset to either the pre-bisect commit (`original`, the default) or the first bad commit itself (`found`). The patch wires the option into both `git bisect start` and `git bisect run`, persists the chosen target in a `BISECT_RESET_WHEN_FOUND` state file, and enforces the constraint that `--reset-when-found` cannot be used with `--no-checkout`.

Key technical details include the deferred reset behavior for `git bisect run` (the reset happens after the captured output is printed and the `BISECT_RUN` file is closed, addressing platform-compatibility concerns about unlinking open files) and the quiet reset implementation (using the `quiet` parameter added in patch 1/2). The patch also adds four new tests in `t/t6030-bisect-porcelain.sh` to validate both `original` and `found` targets, state cleanup, and edge cases like invalid targets and `--no-checkout` conflicts.

The implementation is clean and uncontroversial, with no on-disk format changes beyond the new state file. All design decisions from the v2 discussion are settled, and the series is ready for integration. The only practical limitation (users cannot conditionally choose the reset target based on the bisect outcome) is noted but reasonable given the feature's simplicity.
