This is the fourth and final patch in the v8 series that migrates `has_symlinks` into `struct repo_config_values` as part of the `the_repository` removal effort. The patch completes the work begun in earlier iterations by moving the global `has_symlinks` configuration into repository-scoped storage, introducing a new getter function (`repo_has_symlinks()`), and updating all call sites to use repository-scoped access. The mingw compatibility layer is refactored to use a compile-time macro (`platform_has_symlinks()`) and a static function (`mingw_platform_has_symlinks()`), eliminating mutable global state.

The patch touches ten files, including `environment.c/h`, `compat/mingw.c/h`, and several core index-handling files (`read-cache.c`, `entry.c`, `apply.c`). The global `has_symlinks` variable is removed from `environment.h`, and the new getter function (`repo_has_symlinks()`) is added to provide repository-scoped access. The mingw-specific implementation now uses a platform-specific macro and function, aligning with Git’s existing compatibility patterns. The `setup_windows_environment()` function is updated to use the new static function, and the `platform_has_symlinks()` macro is defined in `git-compat-util.h` with a default value of `1` for non-mingw platforms.

This patch is a mechanical refactoring with no behavioral changes. It follows the same pattern established in patch 3/4 for `trust_executable_bit`, ensuring consistency in how repository-scoped configuration is accessed. The mingw adjustments are now settled, and the design has been reviewed and approved by Junio C Hamano in prior iterations. The patch is uncontroversial and appears ready for inclusion, completing the series’ goal of eliminating global state for these core index-related settings. The series as a whole is part of the broader `the_repository` removal effort and may serve as a template for future configuration migrations.
