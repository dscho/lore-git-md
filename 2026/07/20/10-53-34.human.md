This is the third patch in a four-part series (v8) that migrates the `trust_executable_bit` configuration flag from global scope into `struct repo_config_values`, completing the `the_repository` removal effort for this setting. The patch introduces a new getter function, `repo_trust_executable_bit()`, and updates all call sites to use repository-scoped access, falling back to `the_repository` where necessary. The global variable is removed, and the default value is now set in `repo_config_values_init()`.

The changes are mechanical and follow the established pattern from earlier patches in the series. The patch touches `apply.c`, `environment.c/h`, `read-cache.c`, and `read-cache.h`, updating function signatures and call sites to pass the repository pointer. The `ce_mode_from_stat()` helper in `read-cache.h` now uses the new getter, and the `UNUSED` annotation for its `repo` parameter (added in v7 to resolve a build issue) is removed here since the parameter is now actively used.

This patch addresses Junio C Hamano’s stylistic feedback from v7 by reformatting the ternary expression in `repo_trust_executable_bit()` for clarity and removing defensive NULL checks, aligning with his preference for crashing on NULL to expose bugs. The call site in `write_entry()` has been updated to match this stricter pattern. The patch is uncontroversial and part of the broader `the_repository` removal effort, which has seen steady progress with minimal pushback.
