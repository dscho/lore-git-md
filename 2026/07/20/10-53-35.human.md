This is the final patch in a four-part series that completes the migration of `has_symlinks` from a global variable into the repository-scoped `repo_config_values` struct. The series is part of the ongoing `the_repository` removal effort and builds directly on the earlier migration of `trust_executable_bit` (merged in v4).

The patch introduces a new getter function, `repo_has_symlinks()`, that callers use instead of the old global. It also adds a `platform_has_symlinks()` macro that defaults to 1 on Unix but can be overridden by platforms like MinGW. The MinGW compatibility layer is refactored to use a compile-time-determined static variable (`mingw_platform_has_symlinks()`), eliminating the mutable global that Junio objected to in earlier iterations. All call sites are updated to pass a repository pointer where possible, falling back to `the_repository` when necessary.

The diff touches ten files, primarily updating call sites in `apply.c`, `combine-diff.c`, `entry.c`, `read-cache.c`, and the MinGW compatibility layer. The global variable is removed from `environment.h`, and the `git_default_core_config()` function now writes the value into the repository-specific struct. The mingw adjustments are settled and align with Git’s existing platform-compatibility patterns.

This patch is a mechanical refactoring with no behavior change. It addresses all prior feedback, including Junio’s design-level concerns about mingw compatibility and SZEDER Gábor’s build-breaking issue in the earlier `ce_mode_from_stat()` refactoring. The series is uncontroversial and appears ready for inclusion in `next`.
