This is the first patch in Harald Nordgren’s **v10 series** introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit. This patch is a **pure refactoring** that extracts a helper function, `first_parent_tree_oid()`, to centralize the logic for resolving a commit’s first-parent tree (or the empty tree for a root commit). The helper replaces three nearly identical code blocks in `builtin/history.c`, reducing duplication and improving maintainability.

The change is mechanical and introduces no behavior differences. The new helper takes a `struct repository *`, a `struct commit *`, and an output `struct object_id *`, returning 0 on success or -1 on error. It handles the root-commit edge case by copying the repository’s empty tree OID and parses the parent commit only when one exists. The three callers—`commit_tree_with_edited_message()`, `commit_became_empty()`, and `split_commit()`—are updated to use the helper, eliminating redundant parse-and-copy logic.

This patch is **ready to merge** and sets the stage for the core `squash` implementation in patch 3/5. The refactoring is clean and well-scoped, addressing a minor but recurring code smell in the `history` builtin. No controversy or unresolved feedback is attached to this patch.
