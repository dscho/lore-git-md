This is a brief but pointed follow-up from Junio in the ongoing discussion about Harald Nordgren’s patch to add `--abort` hints to `git rebase` failure and status messages. Junio endorses Phillip Wood’s skepticism about the patch’s core use case: using `git rebase` as a control structure to run checks on each commit, where a single exec failure should terminate the process. He frames this workflow as fundamentally misaligned with rebase’s purpose—finding a breakage in history without any intent to fix it—and makes clear his lack of sympathy for the proposed change. The message is short, but it decisively shifts the thread’s tone: what began as a UI consistency patch is now explicitly under scrutiny as a potential misuse of Git’s tooling. Junio’s position is substantive and carries weight; if the author cannot justify the workflow’s validity, the patch’s future looks uncertain.
