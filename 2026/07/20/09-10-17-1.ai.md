This is the **v3 feature patch series** for `git bisect`, introducing the `--reset-when-found[=<where>]` option. The series is now down to two patches after the author dropped the preparatory descriptor-handling refactor from v2, retaining only the quiet-checkout plumbing (patch 1) and the core feature implementation (patch 2).

The new option automates the post-bisect cleanup: once the first bad commit is identified, the working tree is reset to either the pre-bisect commit (`original`, the default) or the first bad commit itself (`found`). This eliminates the manual `git bisect reset` step, benefiting both scripted workflows and interactive debugging. The implementation persists the chosen target in a `BISECT_RESET_WHEN_FOUND` state file and enforces the constraint that `--reset-when-found` cannot be used with `--no-checkout`, as that mode prevents checking out either target.

Key changes in v3 include the rename from `--auto-reset` to `--reset-when-found` (settled in the v2 discussion) and a behavioral tweak for `git bisect run`: the reset is now deferred until after the captured output is printed and the `BISECT_RUN` file is closed, addressing platform-compatibility concerns about unlinking open files. The test suite has been updated to reflect the new option name and the deferred reset behavior, with four new tests validating both `original` and `found` targets, state cleanup, and edge cases like invalid targets and `--no-checkout` conflicts.

The series is technically sound, with no on-disk format changes or new symbols beyond the state file updates. The only unresolved item from v2—Johannes Sixt’s platform-compatibility concern about the dropped descriptor refactor—has been sidestepped by reverting to filename-based output handling, making the series uncontroversial. The implementation is ready for review, with all design decisions settled and thorough test coverage in place. The practical limitation noted in v2 (users cannot conditionally choose the reset target based on the bisect outcome) remains, but this is a reasonable trade-off for the feature’s simplicity.
