This is a brief follow-up in the ongoing `git config --global` and `include.*` discussion. Junio C Hamano, the maintainer, endorses Jeff King’s analysis that the current behavior is intentional and not a bug. He agrees that the `lbmk` project’s use of `--global` is overly restrictive and that `git var GIT_AUTHOR_IDENT` (or `AUTHOR_IDENT`) is the correct way to check whether Git can derive an identity, since it accounts for environment variables, `author.*`/`committer.*` splits, and all config sources.

The thread has now reached consensus on the technical question: the behavior is by design, and the practical issue lies with `lbmk`’s usage rather than Git’s implementation. No patch is proposed here, but the discussion may prompt a follow-up with the `lbmk` maintainers. The tone remains constructive, and the technical details (e.g., `git var`’s handling of environment variables and split identities) are settled. If you’re following this for the design implications, the next step is likely outreach to `lbmk`.
