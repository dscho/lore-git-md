This is a follow-up in the `git config` bug report thread about inconsistent handling of `include.*` directives. Ben Knoble suggests an alternative approach to Hendrik Jaeger's original problem: instead of using `git config --global --includes user.name`, he proposes using `git config user.name` (without `--global`) or `git var GIT_AUTHOR_IDENT` to check the user's configured identity. This sidesteps the inconsistency entirely by avoiding the `--global` flag, which is the root of the reported behavior.

The suggestion is practical and addresses the immediate use case (the `lbmk` project's config check), but it does not resolve the underlying question of whether the current behavior is intentional or a bug. The thread remains open on that point, with no patch proposed yet. Ben's comment is a surface-level workaround rather than a substantive review of the design; it does not engage with the man page's phrasing or the rationale for the inconsistency between `--global` and repository-level `git config`. For a developer following the thread, this reply is a minor detour rather than a step toward resolution.
