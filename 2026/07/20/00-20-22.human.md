This is the sixth patch in K Jayatheerth’s seven-patch GSoC series adding path-related keys to `` `git repo info` ``. The series exposes filesystem locations of repository components (hooks, index, grafts, etc.) in a structured, scriptable format. This specific patch introduces `` `path.grafts.absolute` `` and `` `path.grafts.relative` ``, which report the grafts file location regardless of whether the file exists.

Lucas Seiki Oshiro raises a practical concern: when no grafts file exists, the command still returns the path (e.g., `` `.git/info/grafts` ``), which could mislead scripts into thinking the file is present. This behavior mirrors how `` `git rev-parse --git-path info/grafts` `` works, but the question is whether `` `git repo info` `` should be more opinionated about existence. The patch currently follows the established pattern of the series—reporting the path Git would use, not whether it exists—but this may be worth revisiting if users expect the command to validate file presence.

No design or naming feedback has emerged yet, so the core functionality remains uncontroversial. The patch itself is mechanically clean, with good test coverage for environment overrides and edge cases. If the series receives broader review, this existence-check question could become a point of discussion, but for now it is a single reviewer’s observation rather than a consensus concern. The patch is ready for technical review, and the issue raised is a minor design choice rather than a bug.
