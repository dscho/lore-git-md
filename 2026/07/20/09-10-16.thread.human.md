This thread is about a two-patch series from Harald Nordgren that fixes Git’s push tracking display when a remote is renamed (e.g., from `origin` to `upstream`). Currently, `git status` stops showing the push destination after a rename, even though pushes still work. The series restores the display by resolving the URL of the renamed remote to any remaining remote that shares the same URL. It also extends support to allow URLs (not just remote names) as values for `branch.<name>.pushRemote`, which is useful for workflows involving GitHub’s `gh` CLI, which renames remotes during forking.

The series is under review, with v1 already posted. Junio C Hamano, the maintainer, requested a revised commit message for the first patch to clarify that the URL-based lookup is an *extension* to support renamed-remote workflows, not a fix for an existing capability. Harald has agreed to this change and will post v2 with the updated commit message. No technical objections have been raised, and the core logic (unique URL lookup, handling of duplicate URLs) is considered sound. The series touches `remote.c`, `remote.h`, `transport.c`, and adds a 104-line test script in `t/t5505-remote.sh`.

The only remaining task is the revised commit message, which is expected to address the documentation gap without requiring code changes. Once v2 is posted, the series should be ready for integration.
