This is the first patch in a rerolled bugfix series (v2) targeting race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The patch addresses the core issue by replacing the previous append-mode approach with a deterministic staging path opened in read-write mode, allowing overlapping responses to write identical bytes at identical offsets. This preserves resumable downloads while preventing corruption.

The patch touches `http.c` and related HTTP transport files, along with documentation updates to clarify staging-key semantics and correct a stale `--index-pack-args` spelling. The implementation handles concurrent unlink scenarios (including Windows sharing behavior), fixes the EOF-range/416 case, and ensures proper handoff to `index-pack`. The test coverage is thorough, including new regression tests for resumed transfers, overlapping 200/206 responses, and a deterministic overlapping-download test using a custom Perl server.

This is a well-crafted fix that directly addresses the feedback from v1, particularly the concern about abandoning resumable downloads. The design is clean and avoids cross-process coordination while maintaining correctness. The patch looks ready for serious review and should be uncontroversial. If you care about HTTP transport reliability or work with large repositories, this is worth paying attention to.
