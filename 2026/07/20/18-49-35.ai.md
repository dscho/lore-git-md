This is a substantive review by Junio C Hamano of the second patch in Harald Nordgren’s two-patch series fixing push tracking after remote rename. The review engages deeply with the patch’s design and motivation, raising two key points:

First, Junio questions whether the current system *intends* to accept a URL (rather than a remote name) as the value for `branch.<name>.pushRemote`. He argues that the existing documentation (`git config --help`) implies this is a misconfiguration, not a supported feature, and suggests the commit message should frame the patch as *extending* the system to support URLs, not as fixing an existing capability. This is not a technical objection but a request for clearer documentation of the patch’s scope and intent.

Second, Junio confirms the patch’s core logic—when `branch.<name>.pushRemote` is a URL, Git should look for a uniquely matching configured remote (by URL or pushurl) and, if found, treat that remote’s name as the effective value for `pushRemote`. He agrees with the patch’s handling of the duplicate-URL edge case (no tracking if multiple remotes share the URL) and clarifies that the patch does not need to modify the existing push/fetch refspec resolution logic, only the initial remote lookup.

The review is constructive and forward-looking, signaling interest in the topic once the commit message is clarified. No implementation concerns are raised yet; the focus is entirely on documentation and design intent. The thread remains under review, with the ball in Harald’s court to revise the commit message.
