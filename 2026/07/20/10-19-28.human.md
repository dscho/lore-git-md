This is a minor follow-up in the ongoing RFC thread introducing `git repack --drop-filtered` for partial clones. The author, Siddharth Shrimali, responds to Christian Couder’s surface-level review of the first patch, which focused on the command-line interface design.

Shrimali acknowledges Couder’s suggestion of an alternative syntax (`--drop-filtered[=dry-run]`) but stands by the current separation of `--drop-filtered` and `--dry-run`, citing consistency with other Git commands and future flexibility. He leaves the door open to revisiting the design based on broader feedback, noting this is still an RFC. The only concrete change planned for v2 is adding a rationale to the commit message explaining the CLI choice.

This exchange is purely about interface aesthetics and does not address the blocking logical flaw in the bitmap validation logic (identified by Junio in the thread summary) or any of the deeper architectural questions. For a busy reader, it signals that the CLI surface is uncontroversial but not yet finalized, while the core safety and correctness issues remain unresolved. The thread’s real substance lies elsewhere—specifically in the maintainer’s feedback on patch 1/7 and the author’s acknowledgment of the need to restructure the validation logic.
