This is the first patch in a two-part performance optimization series for `git stash push` in sparse-checkout repositories. It fixes a latent heap-buffer-overflow bug in the pathspec subsystem that AddressSanitizer catches when wildcard pathspecs are passed from a subdirectory.

The issue stems from inconsistent use of `item.match` (which includes any subdirectory prefix) and `item.original` (the unprefixed argument) in `pathspec_needs_expanded_index()`. The helper was introduced in 2021 to avoid unnecessary sparse-index expansion, but it incorrectly used `item.original` for length and string comparisons, potentially reading past the end of the allocation when `item.match` is longer. The patch mechanically replaces all `item.original` references with `item.match` in the helper, ensuring consistent use of the prefixed path.

Test coverage is added for prefixed wildcard pathspecs in `git rm` and `git reset`, confirming both commands now keep the index sparse. The fix is a prerequisite for the second patch, which will apply the same optimization to `git stash push`. No new symbols are introduced, and the on-disk format remains unchanged. The patch touches only `pathspec.c` and the sparse-checkout compatibility test script.
