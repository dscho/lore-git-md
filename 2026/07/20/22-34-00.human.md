This is the second patch in Ted Nyman’s v2 series fixing race conditions in Git’s HTTP transport when multiple processes fetch the same packfile URI. The series as a whole targets a subtle but real bug: concurrent downloads of the same packfile can corrupt temporary files or cause resume requests to fail at EOF.

This patch makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, which happens when a `.keep` file already exists. The change is straightforward: instead of rejecting anything but `"keep"`, the code now reads either prefix, validates the reported pack hash against the advertised hash, and only registers a new `.keep` lockfile if the current fetch created it. The rest of the stream (e.g., fsck output) is left untouched for later parsing.

The test coverage is solid: a new regression test in `t/t5702-protocol-v2.sh` exercises a packfile URI fetch with a pre-existing `.keep` file, verifying that the pack and index are created, the `.keep` file is preserved, and the expected object is retrievable.

The patch is clean, well-motivated, and directly addresses the race condition described in the cover letter. It looks ready for review and should be uncontroversial.
