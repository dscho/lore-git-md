This is the second patch in a two-patch performance optimization series for `git stash push` in sparse-checkout repositories. It applies the sparse-index-aware pathspec logic already used in `git rm` and `git reset` to avoid unnecessary index expansion when stashing paths wholly inside the sparse-checkout cone.

The patch modifies `builtin/stash.c` to call `pathspec_needs_expanded_index()` before expanding the index. If the pathspec is cone-internal, the index remains sparse, eliminating the expensive expansion step. The change is minimal: two lines added, two removed. Test coverage in `t1092-sparse-checkout-compatibility.sh` exercises literal, prefixed, wildcard, file-based, multiple, staged, and missing pathspecs, all confirming the index stays sparse. A new p2000 performance test case (`git stash push -- $SPARSE_CONE/a`) measures the speedup.

Performance impact is dramatic: on a cone-mode repository with 349,525 tracked paths, `git stash push` drops from 18.9 seconds to 0.06 seconds, with zero index expansions. The patch is based on the prerequisite bugfix in 1/2 (heap-buffer-overflow in `pathspec_needs_expanded_index()`) and leverages the same logic as `git rm` (commit bcf96cfca6). No new symbols are introduced; the on-disk format is unchanged.

The series is self-contained, passes all listed test suites (sparse-index, stash, pathspec, rm, reset, SHA-256, unit tests), and includes ASan regression coverage. The author reports no performance regression in full-index mode (1.62s → 1.65s). This patch is the payoff for the refactoring in 1/2 and the clear performance win for sparse-checkout users.
