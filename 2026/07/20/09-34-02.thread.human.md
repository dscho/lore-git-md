This thread is a bug report from Hendrik Jaeger about an unintuitive interaction between `git config --global` and the `include.*` mechanism. Jaeger demonstrates that while `git config` (without `--global`) automatically respects included configuration files, `git config --global` does not—unless the `--includes` flag is explicitly added. This behavior contradicts the man page's implication that `--global` should behave like other "specific file" cases, where includes are respected by default.

The report is clear and reproducible, showing how moving a configuration value into an included file makes it invisible to `git config --global` unless `--includes` is used. Jaeger notes that while adding `--includes` solves their immediate problem (a check in the `lbmk` project), they’re unsure whether the current behavior is intentional or a bug. The thread is currently in the discussion phase, with no responses yet from maintainers or other contributors. If this is indeed a bug, it may require either a documentation update to clarify the behavior or a code change to align `--global` with user expectations.
