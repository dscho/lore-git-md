This thread began when Hendrik Jaeger reported that `git config --global` does not respect `include.*` directives by default, creating an inconsistency with repository-level `git config` (which does respect includes). The discussion quickly clarified that this behavior is intentional: `--global` is treated as `--file=$HOME/.gitconfig`, avoiding includes to prevent surprises for users who explicitly request a specific file. Jeff King (Peff) provided the key technical rationale, and Junio C Hamano has now definitively endorsed this view, closing the "is this a bug?" question.

The thread has shifted toward practical guidance for downstream projects like `lbmk`, which uses `--global` to check for configured Git identities. Both Peff and Junio recommend alternatives that better match Git’s internal resolution logic: omitting the `--global` scope entirely (letting `git config` resolve values as Git would) or using `git var GIT_AUTHOR_IDENT`, which accounts for environment variables, split `author.*`/`committer.*` settings, and all config layers—including includes—without requiring the caller to specify a scope. No code changes to Git are proposed; the focus is now on educating users about these more robust approaches. The man page may eventually be clarified to reflect the actual behavior of `--global`, but that remains an open question.
