This is a two-patch performance optimization for `git stash push` in sparse-checkout repositories. The series targets the sparse-index subsystem and is motivated by a measurable slowdown when stashing paths wholly inside the sparse-checkout cone.

The problem: `git stash push -- <pathspec>` currently expands the sparse index to a full index before checking whether the pathspec matches any tracked path. When the pathspec is entirely within the cone, this expansion is unnecessary and makes the command’s runtime proportional to the total number of tracked paths rather than the number of sparse-directory entries.

Patch 1/2 refactors the pathspec helper (`match_pathspec_item`) to use the parsed, prefixed path consistently. The existing code could read past the end of the unprefixed path for wildcard pathspecs passed from a subdirectory, triggering a heap-buffer-overflow that AddressSanitizer catches. The fix is mechanical and adds no new behavior.

Patch 2/2 applies the same logic used in `git rm` (commit bcf96cfca6) to `git stash push`: it checks whether the pathspec matches any tracked path *before* expanding the index. If the pathspec is wholly inside the cone, the index is left sparse, avoiding the expensive expansion. The patch adds test coverage for the supported pathspec forms and a path-limited stash case to the p2000 performance suite.

Performance impact is dramatic: on a cone-mode repository with 349,525 tracked paths and 49 sparse-index entries, `git stash push` drops from 18.9 s to 0.06 s (best of three runs), with zero index expansions. A full-index control shows no regression (1.62 s → 1.65 s). The series is based on current master (48bbf81c29) and passes focused sparse-index, stash, pathspec, rm, reset, SHA-256, and unit-test coverage, as well as Clang, GCC, and sanitizer builds.
