This is a bug report about `git config` behavior with `--global` and `--includes`. The author, Hendrik Jaeger, describes an unintuitive interaction where `git config --global` does not respect `include.*` directives by default, even though the man page suggests it should when no specific file is given. The report includes a detailed, reproducible shell session demonstrating the issue: when a config value is moved to an included file, `git config --global` fails to find it unless `--includes` is explicitly added, while `git config` (without `--global`) finds it automatically.

The behavior appears inconsistent with user expectations and the man page's phrasing, which lists `--global` as an example of "giving a specific file" (a claim Jaeger disputes). The author notes that adding `--includes` resolves their practical problem (a check in the `lbmk` project) but questions whether the current behavior is intentional and, if so, what the rationale might be. The report is clear, well-structured, and includes all necessary context for others to reproduce the issue. It does not propose a patch but invites discussion about whether this is a bug or a deliberate design choice.
