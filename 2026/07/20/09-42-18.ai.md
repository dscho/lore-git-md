This is a **substantive review reply** in the `git last-modified` Bloom filter optimization thread, focusing on patch 3/4. Jeff King (Peff) responds to Taylor Blau’s proposed fix for the `--show-trees` correctness bug, where ancestor tree entries (e.g., `d/`) appear in the output even when the pathspec targets a subpath (e.g., `d/a`).

Peff agrees with Taylor’s simpler solution—filtering out uncovered paths in `add_path_from_diff()` using `match_pathspec()`—but raises a technical concern: whether `match_pathspec()` is the right tool, given that tree-diffing uses `tree-walk.c:do_match()` instead. He notes the two functions *should* be equivalent to avoid command discrepancies, but this isn’t explicitly documented. The discussion suggests this is a pre-existing oddity rather than a blocker for the patch.

Peff also highlights a minor edge case: when querying a directory (e.g., `Documentation/technical/`), the output includes both the directory itself and its contents. While the proposed fix would remove the parent directory (`Documentation/`), it would retain the queried directory (`Documentation/technical/`), which might still feel redundant to users. He dismisses this as a non-critical quirk, given the command’s experimental status.

The reply reaffirms the consensus that **removing uncovered paths entirely** is the right trade-off—prioritizing performance and clarity over strict output completeness. No new behavioral concerns are introduced, and the path forward for patch 3/4 is now clear: adopt Taylor’s `match_pathspec()`-based filtering. The unresolved question about `match_pathspec()` vs. `do_match()` is noted but unlikely to derail the series.
