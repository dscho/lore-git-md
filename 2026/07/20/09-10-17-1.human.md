This is a **feature** patch series (v3) adding the `--reset-when-found` option to `git bisect`. The series implements the design agreed in earlier rounds, renaming the option from `--auto-reset` to `--reset-when-found` and simplifying the implementation by dropping the preparatory file-descriptor refactoring from v2.

The new option lets users automatically reset the bisect session after the first bad commit is found, with two possible behaviors: `original` (return to the pre-bisect commit, the default) or `found` (leave the working tree on the first bad commit). This eliminates the need for an explicit `git bisect reset`, making the feature useful for both automated workflows (scripts, CI pipelines) and interactive debugging. The option is available in both `git bisect start` and `git bisect run`, and the chosen target is persisted in a `BISECT_RESET_WHEN_FOUND` state file.

Key changes in v3 include the rename to `--reset-when-found`, dropping the `print_fd_to_stdout()` refactoring (reverting to filename-based output handling), and deferring the reset in `git bisect run` until after the captured output is printed and the `BISECT_RUN` file is closed. This avoids platform-specific issues with unlinking open files. The series also enforces that `--reset-when-found` cannot be used with `--no-checkout`, as that mode prevents checking out either target.

The implementation is clean and well-tested, with four new tests in `t/t6030-bisect-porcelain.sh` covering both `original` and `found` behaviors, state cleanup, and edge cases like invalid targets and `--no-checkout` conflicts. The only unresolved concern from v2—Johannes Sixt’s question about the cross-platform implications of the file-descriptor refactoring—is now moot, as that change was dropped.

The series looks ready for integration. It addresses the feedback from earlier rounds, avoids unnecessary complexity, and delivers a practical improvement for bisect workflows. The only minor limitation is that users cannot conditionally choose the reset target based on the bisect outcome, but this is a reasonable trade-off for the feature’s simplicity.
