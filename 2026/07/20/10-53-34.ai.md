This is the third patch in the v8 series migrating `trust_executable_bit` into `struct repo_config_values` as part of the `the_repository` removal effort. The patch introduces the getter function `repo_trust_executable_bit()` and updates all call sites to use repository-scoped access, falling back to `the_repository` where necessary. It also removes the global variable and updates `git_default_core_config()` to write to the repository-specific struct.

The changes are mechanical and follow the established pattern from earlier patches in the series. The patch incorporates Junio C Hamano’s feedback from v7: the ternary expression in `repo_trust_executable_bit()` is reformatted for clarity (adding a space before the `?` operator), and the defensive `repo->gitdir` check is removed to match Junio’s preference for crashing on NULL rather than masking bugs. The call site in `write_entry()` has been updated to match this stricter pattern. The `UNUSED` annotation for the `repo` parameter in `ce_mode_from_stat()` is removed here, as the parameter is now actively used by the getter function.

Files touched include `apply.c`, `environment.c/h`, `read-cache.c`, and `read-cache.h`. The patch is uncontroversial and aligns with the series’ goal of eliminating global state. The migration pattern established here may serve as a template for future configuration refactoring efforts. No behavioral changes are introduced, and the patch is ready for inclusion.
