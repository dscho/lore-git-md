This is a brief but substantive review in support of Patrick Steinhardt’s RFC to reorganize Git’s source tree by moving `libgit.a` components into a new `lib/` directory. Brian m. carlson, a long-time contributor, endorses the change, calling the current root-directory clutter "odd" and arguing that the reorganization will improve discoverability for both new and existing contributors. He also strongly supports the idea of using this mass rename as an incentive to improve Git’s tooling—specifically, better rename tracking in `git log`—which would benefit not just Git but other projects facing similar reorganizations. The tone is constructive and aligns with the pro-reorganization camp, though it doesn’t engage with the practical concerns (e.g., rebasing pain, mental overhead) raised by critics like SZEDER Gábor. Worth noting for readers: this is a clear signal of support from a respected contributor, but the debate remains unresolved.
