This is the second patch in Ted Nyman’s v2 series fixing race conditions in Git’s HTTP transport. It targets the `fetch-pack` side of the packfile URI feature, where a race occurs when multiple processes concurrently fetch the same packfile and `index-pack` finds an existing `.keep` file.

The patch makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `http-fetch`. It reads only the prefix and hash, leaving any subsequent fsck output available to `fetch-pack`, then validates the reported pack hash against the advertised hash. A keep lockfile is registered only when the current process created it (`created_keep` flag). The test coverage adds a regression test that exercises a packfile URI fetch with a pre-existing `.keep` file, verifying the pack and index are correctly installed and the `.keep` file remains untouched.

The implementation is clean and directly addresses the race described in the commit message. It adopts Peff’s suggested `strbuf` refactor (visible in the use of `packhash` and the tighter read loop) and is well-motivated by the v1 discussion. No new symbols are introduced, and the on-disk format is unchanged. The patch looks ready for review and should be uncontroversial.
