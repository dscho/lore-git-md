This thread is about a two-patch series from tnyman@openai.com that optimizes `git stash push` in sparse-checkout repositories. The goal is to avoid unnecessary index expansion when stashing paths that lie entirely within the sparse-checkout cone, which currently causes performance to scale poorly with the total number of tracked paths rather than just the sparse entries.

The first patch fixes a latent heap-buffer-overflow bug in `pathspec_needs_expanded_index()` triggered by wildcard pathspecs from subdirectories, while the second patch applies the sparse-index-aware logic to `git stash push`. The optimization is dramatic: in a cone-mode repository with nearly 350,000 tracked paths, `git stash push` time drops from 18.9 seconds to just 0.06 seconds, with no performance regression in full-index mode. The series is self-contained, passes all relevant test suites (including ASan regression coverage), and leverages existing logic from `git rm`.

The patches touch `pathspec.c` and `builtin/stash.c`, with test coverage in `t7012-skip-worktree.sh` and a new performance test in `p2000-sparse-operations.sh`. No new symbols or on-disk format changes are introduced. The series is currently under review, with no open questions or objections raised so far. The author has provided thorough test coverage and performance measurements, positioning this as a clear win for sparse-checkout users.
