This is the v8 iteration of a refactoring series that migrates `trust_executable_bit` and `has_symlinks` into `struct repo_config_values`, completing the `the_repository` removal effort for these core index-related configuration flags. The series is now in its final form after addressing all prior feedback, including Junio C Hamano’s stylistic and defensive-programming suggestions from v7.

The key change in v8 is the handling of the `repo` parameter in `ce_mode_from_stat()`. In patch 2/4, the parameter is marked as `UNUSED` to avoid compiler warnings, and in patch 3/4, the annotation is removed once the parameter is actually used. This resolves the build-breaking issue raised by SZEDER Gábor in v7 while preserving the function’s `static inline` status in `read-cache.h`. The series also removes defensive NULL checks in the new getter functions (`repo_trust_executable_bit()` and `repo_has_symlinks()`), following Junio’s preference for crashing on NULL to expose bugs rather than masking them. The call site in `write_entry()` has been adjusted accordingly.

The series remains a mechanical migration with no behavioral changes. It moves both flags into repository-scoped storage, establishes new getter functions, and updates all call sites to use repository-scoped access. The mingw compatibility layer continues to use a compile-time macro (`platform_has_symlinks()`) and platform-specific function (`mingw_platform_has_symlinks()`), eliminating mutable global state. The design aligns with Git’s existing platform-compatibility patterns and may serve as a template for future configuration migrations.

Files touched include `read-cache.c`, `environment.c/h`, `apply.c`, `compat/mingw.c`, and related headers. The series removes redundant extern declarations, migrates both flags into `repo_config_values` with proper initialization, and ensures repository pointer validation (or lack thereof, per Junio’s feedback). The mingw adjustments are now settled, and the `ce_mode_from_stat()` refactoring is finalized. The author has incorporated all prior feedback, including dropping redundant comments and preserving performance-critical inlining.

The series builds on prior work and demonstrates incremental progress in eliminating global state. While `repo_config_values()` still does not support non-`the_repository` instances, this series lays the groundwork for eventual elimination of the global. The migration pattern established here could inform similar configuration refactoring efforts, and the mingw adjustments may attract attention from platform maintainers (e.g., Johannes Schindelin). The series is uncontroversial and appears ready for inclusion in `next`.
