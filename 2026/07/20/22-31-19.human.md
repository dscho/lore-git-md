This is a performance-focused bugfix for `git stash` in sparse-checkout repositories. The series targets the sparse-index subsystem and is authored by Ted Nyman, a first-time contributor to the Git mailing list.

The problem: `git stash push -- <pathspec>` currently expands the sparse index to a full index even when the pathspec refers only to files inside the sparse-checkout cone. This expansion makes the command unnecessarily slow in large repositories—demonstrated here with a 300× speedup on a test repository with 350,000 tracked paths. The fix follows the same pattern already used for `git rm` and `git reset`, avoiding expansion when the pathspec cannot match a sparse-directory entry.

Patch 1/2 is a small correctness fix to the pathspec helper: it ensures the helper uses the parsed, prefixed path consistently, preventing a heap-buffer-overflow that AddressSanitizer catches when a wildcard pathspec is passed from a subdirectory. Patch 2/2 then applies this helper in `git stash push`, adding test coverage for the supported pathspec forms and a new path-limited stash case in the p2000 performance suite.

The commit message is thorough, showing clear before/after timings, listing the base commit, and confirming that all relevant test suites (sparse-index, stash, pathspec, rm, reset, SHA-256, unit tests) pass. The code changes are minimal and well-contained, touching only `builtin/stash.c` and `pathspec.c`. This looks like a solid, well-tested contribution that should be uncontroversial.
