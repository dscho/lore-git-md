This is the core implementation patch (3/5) of Harald Nordgren’s `git history squash` series, now in its tenth iteration. The patch adds the `squash` subcommand to the `git history` built-in, allowing users to fold a commit range into its oldest commit while preserving descendant history. This is the most substantial patch in the series, introducing the range resolution logic, merge commit handling, fixup/squash/amend validation, ref-handling behavior, and the core squashing operation.

The implementation resolves all remaining feedback from v9, including **reflog message accuracy** (now recording the full revision expression) and **rev-list option sanitization** (preserving the `boundary` walk invariant while enforcing `--reverse --topo-order`). The patch also tightens the documentation to clarify `amend!` message handling and `--reedit-message` behavior.

Key components introduced in this patch:
- **`resolve_squash_range()`**: Parses and validates the revision range, ensuring it has a single base and rejecting malformed or empty ranges. **Sanitizes all `rev-list` options** by enforcing `--reverse --topo-order` and preserving the `boundary` invariant, while warning if user-provided options would alter the walk order.
- **`reject_dangling_fixups()`**: Blocks ranges where any `fixup!`/`squash!`/`amend!` marker’s target lies outside the range, preventing silent absorption of markers meant for external commits. As an exception, a range made entirely of markers for one target is combined into a single commit, taking its message from the last `amend!` if present.
- **`find_interior_ref()`**: Detects refs pointing to commits inside the squashed range, which would dangle after the operation. By default, the command refuses such operations, with an advice message suggesting `--update-refs=head` to rewrite only the current branch.
- **`cmd_history_squash()`**: The main entry point, which orchestrates range resolution, fixup validation, ref handling, and the squashing operation. It performs a single three-way merge of the entire range against the oldest commit’s parent, then replays descendants on top. The default squashed commit message incorporates the body of the last `amend!` commit targeting the oldest folded commit.

The patch handles edge cases like interior merges (allowed if fully contained), octopus merges, and nested merges, while rejecting ranges with multiple bases or merges whose other parent lies outside the range. The test suite (introduced in this patch) covers these scenarios, along with range parsing, ref handling, `amend!` message selection, and `--dry-run` prediction accuracy.

This patch is **ready to merge**, with all technical feedback addressed and Junio’s "Will replace" sign-off on v7. The only unresolved discussion—whether `--reedit-message` should be the default—is a minor usability tweak and does not block integration. The patch is a foundational piece of the project’s broader vision to use `git history squash` and `git replay` as a faster backend for `git rebase --autosquash`.
