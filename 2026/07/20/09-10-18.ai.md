This is the first patch in the **v3 `--reset-when-found` feature series** for `git bisect`. It introduces a plumbing-level change: a `quiet` parameter to `bisect_reset()` that suppresses checkout progress and branch-status output when the function restores the original HEAD. The patch is purely preparatory—no callers set the flag yet, so behavior remains unchanged. The implementation is straightforward: the `quiet` parameter is passed through to the underlying `git checkout` command as `--quiet`, and all existing callers are updated to pass `0` (false) to preserve current behavior. The change is confined to `builtin/bisect.c` and touches only the `bisect_reset()` function and its call sites.

The patch is well-motivated by the needs of the follow-up feature patch: the `--reset-when-found` option will use this quiet mode to avoid cluttering scripted output with checkout noise. The commit message clearly states the purpose and scope, and the diff is minimal and focused. No test coverage is added here, as the quiet parameter is not yet exposed to users—testing will be handled in the next patch, which exercises the new plumbing. The change is uncontroversial and aligns with the settled design from the v2 discussion.
