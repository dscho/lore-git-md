This is the first patch in a two-part performance optimization series for `git stash push` in sparse-checkout repositories. The patch fixes a latent heap-buffer-overflow bug in the pathspec subsystem that AddressSanitizer catches when wildcard pathspecs are passed from a subdirectory.

The bug stems from inconsistent use of `item.match` (the prefixed path) and `item.original` (the unprefixed argument) in `pathspec_needs_expanded_index()`. The helper was introduced in 2021 to avoid unnecessary sparse-index expansion but incorrectly used `item.original` for length and string comparisons, risking buffer overflows when `item.match` is longer. The patch mechanically replaces all `item.original` references with `item.match`, ensuring consistent use of the prefixed path.

Taylor Blau confirms the bug is reproducible with a simple script and that the patch resolves the issue. The fix is a prerequisite for the second patch, which will apply the same optimization to `git stash push`. Test coverage is added for prefixed wildcard pathspecs in `git rm` and `git reset`, confirming both commands now keep the index sparse. The patch touches only `pathspec.c` and the sparse-checkout compatibility test script, with no new symbols or on-disk format changes. The fix looks well-motivated and thoroughly tested.
