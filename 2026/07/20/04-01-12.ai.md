This is a maintainer's reply in the `git repo info path.grafts` thread, clarifying the design intent behind unconditional path reporting. Junio C Hamano explains that returning the grafts file path even when the file does not exist is intentional and useful: scripts may need to know where to *create* the file, not just where to read it. The response frames the behavior as a feature rather than a bug, aligning it with the existing `git rev-parse --git-path` precedent. No code change is requested or implied; the maintainer's position is that the current implementation is correct as-is. The ball is now back in the author's court to either accept the design or argue for a different approach.
