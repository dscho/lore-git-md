This is the second patch in the v8 series refactoring `trust_executable_bit` and `has_symlinks` as part of the ongoing `the_repository` removal effort. The patch updates the performance-critical `ce_mode_from_stat()` helper to accept a `struct repository *` parameter, preparing it for repository-scoped configuration access in later patches.

The change is mechanical: the function signature is updated to include the repository pointer (marked `UNUSED` for now), and all callers are adjusted to pass either the appropriate repository instance or `the_repository` as a fallback. The boolean expressions in the function are reordered to prioritize the cheap `S_ISREG(mode)` check, minimizing overhead from the upcoming getter function calls. A clarifying comment is added to document the function’s purpose and filesystem limitation handling.

Files touched include `apply.c`, `builtin/update-index.c`, `diff-lib.c`, `read-cache.c`, and `read-cache.h`. The patch preserves the function’s `static inline` status to maintain performance in hot paths. While the `UNUSED` annotation will be removed in patch 3/4 once the parameter is actively used, this preparatory step ensures the codebase remains buildable throughout the series.

The patch is uncontroversial and aligns with the established pattern for migrating global configuration variables into repository-scoped storage. It follows Junio C Hamano’s feedback from earlier iterations and resolves the build-breaking issue raised by SZEDER Gábor in v7. No behavioral changes are introduced; this is purely a refactoring to enable the later migration of `trust_executable_bit` and `has_symlinks`.
