This is a fixup patch addressing Junio C Hamano’s substantive correctness concern in the fifth patch of Johannes Schindelin’s 11-patch series hardening Git against unchecked return values. The issue is in `builtin/last-modified.c`: when a commit in the `--not` queue fails to parse, the current patch skips it with `continue`, bypassing cleanup of the `active_paths` slab associated with that commit. Junio’s fix replaces `continue` with `goto cleanup`, ensuring the slab is properly released even for unparsable commits. This is a narrowly scoped but technically necessary correction; the fix itself is a one-line change that aligns the error path with the function’s existing resource-management pattern. No new tests or documentation are needed, as the change only affects an internal error-handling path that existing tests already exercise indirectly. The patch is presented as a `fixup!` commit, signaling it should be squashed into the original fifth patch before integration.
