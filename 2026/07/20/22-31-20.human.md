This is the first patch in a two-part performance optimization for `git stash push` in sparse-checkout repositories. It fixes a latent heap-buffer-overflow bug in the pathspec helper function `pathspec_needs_expanded_index()` that AddressSanitizer catches when wildcard pathspecs are passed from a subdirectory.

The issue stems from inconsistent use of the pathspec’s `original` (unprefixed) and `match` (prefixed) fields. The function computes lengths and wildcards from `match` but then uses `original` for string comparisons, potentially reading past the end of the allocation. The fix is mechanical: switch all comparisons to use `match` consistently. The patch also adds test coverage for prefixed wildcard pathspecs in `git rm` and `git reset` to ensure the index remains sparse.

This is a bugfix with no behavior change for the end user, but it is a prerequisite for the second patch, which will use the same helper to avoid unnecessary index expansion in `git stash push`. The commit message is clear and the test addition is minimal but sufficient.
