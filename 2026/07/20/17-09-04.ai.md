This is a brief follow-up in the `git config` behavior discussion thread. Junio C Hamano endorses Jeff King’s analysis that the current behavior of `git config --global` (not respecting `include.*` directives by default) is correct and intentional, and that the `lbmk` project’s use of `--global` is overly restrictive. He reinforces Peff’s suggestion that `git var GIT_AUTHOR_IDENT` is the right tool for checking whether Git can derive an author identity, as it accounts for environment variables, split `author.*`/`committer.*` settings, and all config layers—including includes—without requiring the caller to specify a scope. The email does not propose any code changes to Git itself but closes the design question definitively: the behavior is not a bug, and the thread’s focus should now shift to educating downstream projects like `lbmk` about the more appropriate alternatives.
