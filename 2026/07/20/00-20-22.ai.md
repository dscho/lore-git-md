This is a substantive review of the sixth patch in K Jayatheerth’s seven-patch GSoC series adding path-related keys to `git repo info`. The patch implements `path.grafts.absolute` and `path.grafts.relative` to expose the grafts file location, but Lucas Seiki Oshiro identifies a behavioral issue: the keys return the grafts file path even when the file does not exist, which could mislead scripts into assuming the file is present. The reviewer suggests checking for file existence before returning the path, a change that would affect the patch’s current behavior and require updates to both implementation and tests.

The review is tested (Lucas ran the command and observed the behavior) and substantive (it questions the design choice of returning a non-existent path). This feedback is likely to spark discussion about whether `git repo info` should report only existing paths or all possible paths, regardless of their current existence. The patch currently follows the pattern of `git rev-parse --git-path`, which also returns paths without checking for existence, so the resolution may hinge on consistency with existing Git commands. No alternative implementation is proposed yet, but the issue is now clearly on the table for the series as a whole.
