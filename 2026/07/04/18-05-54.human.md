This is the first patch in the finalized v4 series for the Git build system, focusing on Rustification support for macOS. It fixes a parallel build race condition in the `git-credential-osxkeychain` helper by adding `$(RUST_LIB)` as a prerequisite to its build rule. Without this change, running `make -j` from a clean working tree could fail because Make wouldn’t know to build the Rust library (`libgitcore.a`) before linking the credential helper.

The patch also wraps the Rust-related build targets (`$(RUST_LIB)` and the `rust` phony target) in `ifndef NO_RUST` blocks, ensuring backward compatibility when Rust is disabled. This is a clean, minimal fix—just six lines added to the `Makefile`—that directly addresses the race condition without introducing new complexity. The commit message clearly explains the problem and solution, and the change aligns with the series’ goal of robust Rust integration.

This patch is well-motivated and ready for integration. It’s part of a converged series with no outstanding objections, and the fix is straightforward enough that it’s unlikely to introduce regressions. If you care about Rust support or macOS builds, this is worth noting but doesn’t require deep scrutiny.
