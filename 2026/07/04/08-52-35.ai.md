This is the third and final patch in Pablo Sabater’s v7 series implementing **cascading indentation for visual roots in `git log --graph`**. The series is now architecturally resolved—Junio Hamano has approved the lookahead buffer redesign that replaced the earlier peek-based approach—and this patch delivers the actual visualization logic.

The patch teaches `graph.c` to indent visual roots (commits that appear root-like because their parents are filtered out or excluded) by two characters per level, except for the first in a cascade. A new `GRAPH_PRE_ROOT` state prints an extra row to connect an indented root to its child, mirroring the existing `GRAPH_PRE_COMMIT` logic for octopus merges. The indentation depth is tracked in `struct git_graph` via `visual_root_depth` and `visual_root_cascade`; the latter suppresses indentation for the first root in a sequence so that subsequent roots cascade cleanly. Merge parents (non-first parents of a merge) are explicitly excluded from indentation because they are already connected by an edge.

The new test file `t4218-log-graph-indentation.sh` exercises every edge case: single roots, unrelated branches, merges, filtered parents, `--first-parent`, `--left-right`, boundaries, and cascading sequences. All three `test_expect_failure` cases from v6 now pass. One documented edge case remains: redundant indentation when filtered parents are present; this is marked NEEDSWORK but deemed acceptable for now.
