This is the seventh patch in Johannes Schindelin’s 13-patch series fixing resource leaks and error-path bugs flagged by Coverity. The series as a whole is already approved by Junio C Hamano and will be queued for merging; this patch is now clarified and ready to go.

The patch plugs two memory leaks in `read_one_dir()` (dir.c) that occur when parsing the untracked-cache data fails early. Coverity flagged the leaks of `ud.untracked` and `ud.dirs` when `decode_varint()` or `memchr()` return an error. The fix adds `free(ud.untracked)` and `free(ud.dirs)` before the two early returns.

Patrick Steinhardt initially questioned whether the fix was complete, noting two additional early returns later in the function that still appeared to leak. Johannes’s reply clarifies that ownership of `ud.untracked` and `ud.dirs` is transferred to the caller via the `xmalloc`’d struct on the success path, so the later returns are correct as-is. The explanation will be folded into the v2 commit message to avoid future confusion.

The patch is small, mechanical, and well-motivated; it touches only the two error paths and leaves the rest of the function unchanged. No user-visible behavior changes or on-disk format changes are introduced. The fix is covered by existing tests and does not require new ones.
