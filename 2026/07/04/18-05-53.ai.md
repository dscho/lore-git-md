This is the fourth iteration of a two-patch series targeting the Git build system, specifically the Rustification effort on macOS. The series resolves a parallel build race condition in the `git-credential-osxkeychain` helper and adds support for macOS Universal Binaries (multi-architecture builds) when Rust is enabled.

The first patch ensures `git-credential-osxkeychain` links against Rust libraries by adding `$(RUST_LIB)` as a prerequisite to its build rule, wrapped in `ifndef NO_RUST` for backward compatibility. This fixes a race condition where parallel builds (`make -j`) could attempt to link the credential helper before Cargo finishes compiling `libgitcore.a`.

The second patch introduces Universal Binary support via the `RUST_TARGETS` environment variable. Users can specify multiple target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`), and the build system compiles separate static libraries per target, combining them into a single Universal Binary using `lipo`. The commit message clarifies the technical rationale: Apple’s C toolchain natively supports multi-architecture builds via `-arch` flags, but Cargo requires separate invocations per target triple. The patch bridges this gap by combining target-specific Rust static libraries into a universal archive, enabling Universal Binary support for Rust components even if the C build is not explicitly configured for it. Junio’s requested style tweaks (removing `@` from `mkdir` and replacing `[` with `test`) are incorporated.

The series is now converged, with all substantive feedback addressed. Patrick Steinhardt’s earlier concerns about Universal Binary completeness (whether the C build should also support multi-architecture) remain unresolved in principle, but the current design is accepted as sufficient for practical use cases like macOS distribution and CI. The changes touch only the `Makefile`, introduce no on-disk format changes, and maintain backward compatibility. No new tests are added, but the changes are implicitly covered by existing build tests. The series is ready for integration into Junio’s branches.

Key technical details include the new `RUST_TARGETS` environment variable and the internal `$(RUST_MEMBER_LIBS)` build variable. The build system now preemptively creates target directories to avoid race conditions, and the Universal Binary support assumes `lipo` is available (part of Xcode Command Line Tools, widely available on macOS). The split into two logical commits improves clarity and maintainability.
