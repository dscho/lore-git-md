This is the third and final patch in Pablo Sabater’s v7 series implementing **cascading indentation for visual roots in `git log --graph`**. The series is now architecturally complete, with the lookahead buffer (introduced in patch 2/3) providing a robust foundation for this visualization logic.

The patch adds the actual indentation behavior: when a commit appears as a "visual root" (either a true root or a commit whose parents are all filtered out), it is indented by two characters for each level of adjacency with other visual roots. The first visual root in a cascade is not indented, but subsequent ones are, creating a clear visual distinction. A new `GRAPH_PRE_ROOT` state ensures that indented roots with children are properly connected via an edge on a separate row.

The implementation is careful to avoid indenting non-first parents of merges, which are already visually connected to the merge commit. The logic is encapsulated in `graph_is_visual_root()`, which uses the lookahead buffer to peek at the next commit and determine whether indentation is needed. The test suite (`t4218-log-graph-indentation.sh`) is comprehensive, covering single roots, cascading roots, merges, filtered parents, and edge cases like `--first-parent` and `--boundary` flags.

This patch is well-motivated and technically sound. The lookahead buffer (already approved by Junio Hamano) eliminates the fragility of earlier versions, and the test coverage is thorough. The only remaining loose ends are documentation of the visualization rules and a minor edge case (redundant indentation when filtered parents are present), both of which are marked NEEDSWORK but do not block merging. The series is now ready for final review of the visualization logic.
