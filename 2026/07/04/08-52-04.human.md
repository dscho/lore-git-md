This is a CI/build system patch from Johannes Schindelin that fixes a specific problem in GitHub Actions workflows when run in private repositories. The issue causes Dockerized CI jobs to fail consistently with "cannot create async thread: Resource temporarily unavailable" errors, particularly in the t5xxx-t6xxx test range. The fix adds container options (`--pids-limit=16384`, `--ulimit=nproc=16384`, `--ulimit=nofile=32768`) only when the repository is private, based on benchmarking that shows 16k is the optimal balance between stability and performance.

The patch is narrowly targeted and well-motivated. Schindelin uses private repositories to test Microsoft Git changes not yet ready for public release, and this change enables those tests to run successfully without affecting public repository workflows. The commit message provides detailed benchmarking data comparing 64k, 16k, and public-repository runtimes across all 13 Dockerized jobs, demonstrating the trade-offs clearly. This is a practical fix rather than a general CI optimization.

The implementation is minimal, touching only `.github/workflows/main.yml` with a conditional options string. Junio C Hamano's earlier review focused only on commit message wording, and this v2 addresses that feedback by rewording the title to better reflect the intent. No technical objections have been raised, and the approach appears uncontested.

This looks like a straightforward, well-tested fix that solves a real problem for private repository testing. The patch is ready for merging unless someone identifies an unintended consequence of the container options.
