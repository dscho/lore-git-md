This is a CI/build system patch that adjusts GitHub Actions workflows to address a resource limitation specific to private GitHub repositories. Johannes Schindelin reports that Dockerized CI jobs in private repositories consistently fail with "cannot create async thread: Resource temporarily unavailable" errors, particularly in the t5xxx-t6xxx test range. The patch modifies `.github/workflows/main.yml` to conditionally apply container options (`--pids-limit=16384`, `--ulimit=nproc=16384`, `--ulimit=nofile=32768`) only when the repository is private, based on benchmarking that shows 16k is the optimal trade-off between stability and performance (higher limits like 64k caused 2-2.5x longer runtimes).

The change is minimal and targeted: it touches only the container configuration line in the workflow file, leaving public repository workflows unaffected. Schindelin’s motivation is practical—enabling private testing of Microsoft Git changes not yet ready for public consumption—and the commit message provides detailed benchmarking data comparing runtimes across all 13 Dockerized jobs under different PID limits. The v2 update addresses only commit message framing (correcting "reduce" to "raise" in the subject), with no technical changes from v1.

This patch is uncontested so far, with Junio C Hamano’s review focusing solely on the commit message’s accuracy. The technical approach (conditional PID limits) appears sound, and the problem it solves is well-documented. No open questions remain, and the change is unlikely to be controversial given its narrow scope and clear motivation. The key technical detail to track in follow-up discussion is the `github.repository_visibility` conditional, which ensures the fix applies only where needed.
