This is a platform-compatibility bugfix targeting macOS, addressing a crash in `git status` when processing UTF-8 filenames longer than `NAME_MAX` (255 bytes). The v2 patch incorporates feedback from Junio C Hamano and others, replacing the Perl-based test with a shell-only version using `printf` and `tr` to generate a 256-byte filename (253 'a' characters + 3 UTF-8 em-dashes).

The core fix remains unchanged: converting `d_name` in `dirent_prec_psx` to a flexible array member (`FLEX_ARRAY`) and adjusting allocation calculations to match the actual memory layout. This ensures fortified libc functions no longer reject the dynamic buffer expansion during `precompose_utf8_readdir()`. The implementation now includes a helper function `dirent_prec_psx_size()` for safe size calculations using `st_add` and `offsetof`.

The regression test creates a minimal reproducer (256 bytes) and verifies `git status` succeeds with `core.precomposeunicode` enabled. The test is now portable across environments, addressing Junio's procedural concern while maintaining the original test's intent. Memory management refinements suggested by Patrick Steinhardt (e.g., `FLEX_ALLOC_MEM()`) were not adopted, but the current approach remains correct and avoids over-allocation for most filenames.

This version appears ready for merging, with all substantive feedback addressed. The patch is confined to `compat/precompose_utf8.c` and its header, with no impact on other platforms or subsystems. The commit message clearly explains the crash scenario and the fortified libc interaction, making it easy for future maintainers to understand the change.
