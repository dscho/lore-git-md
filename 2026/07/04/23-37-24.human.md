This is a platform-compatibility bugfix targeting macOS, addressing a crash in `git status` when encountering UTF-8 filenames longer than 255 bytes. The patch is a revised version (v2) of an earlier submission that fixes the same issue but now avoids using Perl in the test, as requested by Junio C Hamano.

The core problem remains the same: Git's `precompose_utf8` compatibility layer crashes when processing directory entries with long UTF-8 filenames because the fixed-size `d_name` array in `dirent_prec_psx` is too small for the dynamically reallocated buffer. The fix converts `d_name` to a flexible array member (`FLEX_ARRAY`) and adjusts allocation calculations to match the actual memory layout, preventing fortified libc overflow checks from triggering. The implementation is clean, using `st_add` and `offsetof` for safe size calculations, and maintains the existing API.

The regression test has been rewritten to use shell tools (`printf` and `tr`) instead of Perl, creating a 256-byte filename (253 'a' characters followed by three UTF-8 em-dashes) to verify `git status` works with `core.precomposeunicode` enabled. This addresses Junio's feedback from the first version while keeping the test minimal and focused. The test explicitly checks the byte count of the generated filename to ensure it reproduces the crash scenario.

The patch touches only `compat/precompose_utf8.c` and its header, with no impact on other platforms or subsystems. It’s a well-scoped fix for a real-world macOS issue, with clear motivation and appropriate test coverage.
