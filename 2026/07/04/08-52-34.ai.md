This is the second patch in Pablo Sabater’s v7 series implementing cascading indentation for visual roots in `` `git log --graph` ``. It introduces the **lookahead buffer** that replaces the fragile peek-based abstraction from v6, following Kristofer Karlsson’s redesign which Junio Hamano has already approved in principle.

The patch adds a two-slot lookahead buffer to ``struct git_graph`` and populates it in ``get_revision()``. When the graph layer needs to inspect upcoming commits, it now pulls them from this buffer instead of peeking at the revision walker’s internal queue. This ensures that commits are fully simplified before the graph layer sees them, eliminating the fragility that blocked earlier versions. The buffer is small (only two commits), deterministic (timestamps are tweaked to guarantee stable output), and compatible with Jeff King’s planned removal of ``revs->commits`` and Kristofer Haugsbakk’s ``kk/prio-queue-get-put-fusion`` topic.

Key changes are in ``graph.c``, ``graph.h``, and ``revision.c``. The new symbols are ``struct git_graph.lookahead[2]``, ``graph_pop_lookahead()``, ``graph_get_lookahead_room()``, and ``graph_push_lookahead()``. The patch also updates ``graph_is_interesting()`` to treat lookahead commits as interesting even if their ``SHOWN`` flag is not yet set, which is necessary for the graph to correctly track parent-child relationships.

The implementation is clean and well-motivated: the commit message explains why the lookahead buffer is needed, how it resolves the fragility of peeking at unsimplified commits, and how it fits into the larger series. The code itself is straightforward, with clear comments and no obvious edge cases. This patch is the architectural foundation for the visualization logic in patch 3/3 and is ready for final review.
