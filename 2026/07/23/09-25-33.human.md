This is a feature patch adding a new configuration option to control the connection timeout for Git’s HTTP operations. The patch introduces `http.connectTimeoutMS` (and its environment-variable counterpart `GIT_HTTP_CONNECT_TIMEOUT_MS`) to let users override libcurl’s default 300-second connection-phase timeout with a millisecond-precision value.

The implementation is straightforward: a new static variable `curl_connect_timeout_ms` is added to `http.c`, populated from either the config key or the environment variable, and passed to libcurl via `CURLOPT_CONNECTTIMEOUT_MS`. The documentation update is minimal but clear, and the new test script (`t5585-http-connect-timeout.sh`) exercises both the happy path and error cases (non-numeric values, empty values, zero, etc.).

The patch is well-motivated, self-contained, and includes both documentation and tests. It looks like a clean, uncontroversial addition that should be easy to review and merge.
