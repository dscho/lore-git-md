Subject: [PATCH] clone: fix segfault with --revision on servers advertising more refs than requested

Thread type: bug report / bugfix

Core problem or goal
Fix a segmentation fault in `git clone --revision=<ref>` when the server (e.g., Azure DevOps) advertises more refs than the client requested under protocol v0. The crash occurs in `update_remote_refs()` because `guess_remote_head()` returns a non-NULL `remote_head_points_at` whose `peer_ref` field is NULL; the code then unconditionally dereferences `remote_head_points_at->peer_ref->name`.

The patch is complete: the one-line NULL check in `update_remote_refs()` is conceptually approved, and the requested regression test has been added. Junio has not yet issued a formal Reviewed-by or Acked-by, but all technical discussion is resolved and no further changes are expected. The series is ready for merging.
