Subject: [PATCH] clone: fix segfault with --revision on servers advertising more refs than requested
Series version: standalone patch (initial submission, marked “resend” but no prior version cited)
Originating author: Adrian Friedli
Thread type: bug report / bugfix

Core problem or goal
Fix a segmentation fault in `git clone --revision=<ref>` when the server (e.g., Azure DevOps) advertises more refs than the client requested. The crash occurs in `update_remote_refs()` because `guess_remote_head()` returns a non-NULL `remote_head_points_at` whose `peer_ref` field is NULL; the code then unconditionally dereferences `remote_head_points_at->peer_ref->name`. The root issue is servers violating the expected protocol by ignoring `ref_prefixes`.

Current status
Conceptually approved; the patch (a one-line NULL check in `update_remote_refs()`) is now the agreed fix. Junio confirms that a `struct ref` with a NULL `.peer_ref` is legitimate when the fetch does not store the result in any remote-tracking ref. The only remaining action item is a regression test; no new version of the patch has been posted yet.
