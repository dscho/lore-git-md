This is a bugfix patch targeting the `git clone` command. It addresses a segmentation fault that occurs when using the `--revision` argument with servers that advertise more refs than requested, such as Azure DevOps.

The issue arises in `builtin/clone.c` when `guess_remote_head()` returns a non-NULL `remote_head_points_at` whose `peer_ref` field is NULL. The current code in `update_remote_refs()` dereferences `remote_head_points_at->peer_ref->name` without checking whether `peer_ref` is NULL, leading to a crash. The patch adds a NULL check for `remote_head_points_at->peer_ref` before proceeding.

The reproduction case is straightforward: running `git clone --revision=refs/heads/main` against an Azure DevOps repository triggers the segfault. The commit message clearly explains the two scenarios (good case vs. bad case) and traces the code path that leads to the crash. The fix itself is minimal—just one additional NULL check—and appears correct for the described problem.
