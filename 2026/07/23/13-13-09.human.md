This is the first patch in a two-part bugfix series for `git mv`. It addresses a misleading error message that occurs when `git mv` fails due to a missing destination directory. Currently, the error blames the source file (e.g., "renaming 'src' failed: No such file or directory"), even when the source exists and the problem is the destination's parent directory. This patch makes the error message unambiguous by including both the source and destination paths, so the user can see exactly which part of the operation failed.

The change is minimal and race-free: it modifies a single line in `builtin/mv.c` to expand the error message format from `"renaming '%s' failed"` to `"renaming '%s' to '%s' failed"`. This avoids the need for post-failure path inspection, which could introduce time-of-check-to-time-of-use (TOCTOU) races. The patch is well-motivated and aligns with reviewer feedback from the first iteration of the series.

This is a straightforward, user-facing improvement with no behavioral changes beyond the error message. The commit message clearly explains the problem and the rationale for the fix. Since the error message is now translatable, the l10n team will need to handle the new string, but this is a routine part of the process. The patch is unlikely to be controversial and appears ready for merging.
