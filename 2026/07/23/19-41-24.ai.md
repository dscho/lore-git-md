This is the final patch in Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. It implements the drop log (`$GIT_DIR/objects/info/promisor-dropped`), which records every object removed by `--drop-filtered` to improve error messages when lazy fetches fail due to prior drops. The log format is `<oid> <timestamp> <tz> filter=<spec> remote=<name>`, though the remote field currently lists all configured promisor remotes rather than the specific one each object is recoverable from—a known limitation marked NEEDSWORK and deferred until the `remote-object-info` protocol command is available.

The patch adds the plumbing in `repack-promisor.c` (`append_drop_log()`) and wires it into `builtin/repack.c` after the repack completes. The log is written only on real runs (not dry runs), with minimal error handling (warnings on I/O failures). Reviewer Siddharth Asthana endorses the current approach, noting the NEEDSWORK is acceptable for now, but suggests documenting the log path in `gitrepository-layout` and adding a test to verify real drops append entries. The drop log’s existence is a key enabler for future error-message improvements, though it is not yet used by any code in this series. The patch completes the core functionality promised in the RFC but does not include the safety guards (merge/rebase checks, index validation) or remote verification logic deferred to follow-ups.
