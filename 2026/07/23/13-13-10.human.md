This is the second patch in a two-part bugfix series for `git mv`, addressing a long-standing usability issue where the command fails late and with a misleading error when the destination's parent directory does not exist. The first patch improved the error message to include both source and destination paths; this one moves the directory existence check into the checking phase so that `git mv --dry-run` can detect the problem before attempting the actual rename.

The patch adds a best-effort `lstat` check on the destination's leading directory during the checking phase, guarded by the same conditions that determine whether the entry will be renamed on disk. This avoids false positives for directory moves (where child entries are expanded under a not-yet-created directory) and sparse or out-of-cone destinations (which are not written to the worktree). The check is explicitly acknowledged as racy: the directory could still disappear between the check and the `rename(2)` syscall, but the change fixes the common case and enables `--dry-run` detection.

Two new tests in `t/t7001-mv.sh` cover the error path and the dry-run case. The implementation is narrowly scoped to `builtin/mv.c` and does not introduce new symbols or change the on-disk format. The commit message is thorough, explaining the rationale for the guard conditions and the limitations of the approach.

The patch looks well-crafted and addresses a real user-facing problem. The TOCTOU race is noted but not resolved, and the use of `lstat` (rather than `stat`) remains an open question, but neither issue appears likely to block acceptance. This is a sensible, incremental improvement that should be uncontroversial.
