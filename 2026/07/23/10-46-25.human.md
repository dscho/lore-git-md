This is a **substantive technical reply** from Jeff King (Peff) in the ongoing discussion about the `git receive-pack` performance regression introduced by the ODB abstraction rework. Peff directly engages with Patrick Steinhardt’s proposed architectural solution—routing writes during active transactions directly to the transaction object—and raises **fundamental process-boundary limitations** that complicate the approach.

Peff’s core point is that the quarantine mechanism’s cross-process nature (e.g., `index-pack`, `rev-list`, and user hooks) makes it impossible to fully abstract away the alternates juggling via the ODB API alone. Even if writes are routed to the transaction object in-process, **separate processes** like `index-pack` must still be explicitly told where to write, and hooks must transparently read from both the quarantine area and the original ODB. This means the alternates mechanism (or something functionally equivalent) will likely persist, undermining Patrick’s goal of eliminating source-list modifications during transactions.

The email is **highly technical and narrowly scoped**, focusing on the feasibility of Patrick’s proposal rather than proposing an alternative. Peff’s analysis suggests that while Patrick’s transaction-aware ODB writes might simplify *in-process* behavior, they won’t resolve the cross-process coordination required for quarantine directories. This leaves the regression’s root cause—the redundant loose-object checks across ODB backends—unaddressed by Patrick’s plan, reinforcing the need for a **targeted fix** (e.g., restoring the "pack-first, loose-second" lookup order across backends) as a near-term solution. The discussion remains open, but Peff’s feedback shifts the focus back to pragmatic, incremental fixes rather than waiting for a larger architectural overhaul.
