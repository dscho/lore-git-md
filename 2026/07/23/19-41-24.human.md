This is the final patch in Siddharth Shrimali’s RFC series introducing `git repack --drop-filtered` for partial clones. It adds the drop log (`$GIT_DIR/objects/info/promisor-dropped`) that records every object removed by `--drop-filtered`, enabling better error messages when lazy fetches fail later.

The log format is simple: each line lists the object ID, a timestamp, the filter spec used, and all configured promisor remotes (a temporary limitation marked NEEDSWORK until the `remote-object-info` protocol command lands). The log is written only on real runs, not dry runs, and the patch wires it into `builtin/repack.c` after the repack completes. Error handling is minimal—warnings on I/O failures—but the implementation is otherwise complete.

Siddharth Asthana, a reviewer, endorses the log as a useful development aid but suggests it could be deferred until the error-path improvements that consume it are ready. He also recommends documenting the log path in `gitrepository-layout` and adding a test to verify that real drops append entries. The author (Shrimali) has already marked the remote-field limitation as a follow-up, so this patch is not blocked on it.

The drop log is a small but important piece of the series’ safety story. While it doesn’t yet validate that dropped objects are still available on the promisor remote, it provides the foundation for future error-message improvements. The patch itself is straightforward and uncontroversial, though its long-term utility depends on follow-up work.
