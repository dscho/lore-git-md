This is a bugfix for `git clone` that addresses a segmentation fault when using `--revision` with servers (like Azure DevOps) that advertise more refs than the client requested. Junio has now clarified that the fix belongs in `update_remote_refs()`—the original patch location—rather than in `guess_remote_head()`. His reasoning is that `peer_ref` can legitimately be NULL when the fetch result isn’t stored in a remote-tracking ref, so the issue isn’t with the guessing logic itself but with the downstream code that assumes `peer_ref` is always non-NULL.

The patch remains a minimal one-line NULL check in `builtin/clone.c`, but Junio’s feedback removes the earlier design ambiguity. The only remaining loose end is the lack of a regression test, which Junio still considers important. The fix itself looks uncontroversial and well-placed, but the absence of test coverage means it’s not yet ready to merge. If Adrian provides a test, this should move quickly into `next`.
