This is the v3 iteration of a two-patch bugfix series for `git mv` that fixes misleading error messages when the destination's parent directory does not exist. The series is now complete and addresses all substantive feedback from Junio C Hamano and Ben Knoble.

The first patch improves the error message to include both source and destination paths (e.g., "renaming A -> B failed: no such file or directory"), making it clear which part of the operation failed. The second patch adds an early check for the destination directory's existence during the checking phase, enabling `--dry-run` to detect the problem before the actual rename syscall. This version switches from `lstat()` to `stat()` to match `rename()`'s behavior, explicitly checks for non-directory destinations (reporting "destination is not a directory"), and validates intermediate path components. The TOCTOU race remains acknowledged but unresolved, as it is deemed "the best we can do" for now.

The implementation touches only `builtin/mv.c` and adds comprehensive test coverage in `t/t7001-mv.sh`, including edge cases for symlinks, regular files as path components, and dry-run detection. The commit messages are detailed and explain the rationale for the implementation choices, including why `stat()` is preferred over `lstat()`. The series is well-scoped, user-facing, and unlikely to be controversial. Junio's feedback has been fully addressed, and the author has signaled readiness to move forward. This looks like a solid fix that should proceed to `next`.
