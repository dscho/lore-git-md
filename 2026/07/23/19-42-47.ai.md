This is the sixth patch in the RFC series introducing `git repack --drop-filtered` for partial clones. It implements the actual object-dropping logic, transitioning the feature from dry-run enumeration to real disk-space reclamation.

The patch modifies `builtin/repack.c` to pass the computed drop set (`drop_oids`) to `repack_promisor_objects()`, which rebuilds promisor packs while excluding the dropped blobs. On a real run (not `--dry-run`), it also implies `-d` to remove the old promisor packs that still contain the dropped blobs, ensuring they don’t linger redundantly. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. The `repack-filtered.c` helper is updated to return the drop set via an output parameter (`to_drop`) rather than printing it directly, and the test script (`t/t7706-repack-drop-filtered.sh`) gains a new test validating that `--drop-filtered` actually removes the promisor blob locally while preserving smaller blobs.

Key changes include finalizing the `enumerate_promisor_blobs()` signature (now taking an `oidset *to_drop` instead of a `dry_run` flag), lifting the `--dry-run` restriction (real runs are now supported), and solidifying the conditional bypass of `write_filtered_pack()`. The patch also removes the now-obsolete test that rejected `--drop-filtered` without `--dry-run`. Safety checks (e.g., preventing drops during merges) remain deferred to future patches, but the core drop mechanism is now functional. The series still faces blocking issues in v2, notably the bitmap validation flaw and missing safety guards, but this patch completes the RFC’s technical foundation.
