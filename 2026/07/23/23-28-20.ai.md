This is a substantive review reply in the ongoing `git mv` bugfix series. Junio C Hamano rejects the `stat()`-based approach Lucas Zamboni Orioli proposed in v3 for the second patch, arguing that following symlinks in a Git working tree is unsafe. He cites `git apply` as precedent for avoiding symlink traversal and insists that `lstat()` (which does not follow symlinks) is the correct choice. The core concern is that a tracked symlink in the destination path could point outside the working tree, allowing `git mv` to move files to unintended locations. This reply reopens the technical discussion on the second patch, leaving the symlink-handling strategy unresolved. The first patch (improved error message) remains uncontested and approved. No new edge cases or implementation details are introduced; the focus is solely on the symlink safety trade-off. The series is not yet ready for integration.
