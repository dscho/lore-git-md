This is the second patch in a two-patch bugfix series for `git mv`, targeting a misleading error when the destination directory does not exist. The patch adds an early check during the validation phase to detect missing or invalid destination directories before attempting the `rename(2)` syscall. This ensures `git mv --dry-run` correctly reports failures that would otherwise only surface at runtime, and provides clearer error messages for edge cases like non-directory path components or symlinks.

The implementation uses `stat()` (not `lstat()`) to match `rename()`'s behavior: symlinks to directories are accepted, while symlinks to files are rejected. Missing directories or non-directory path components reuse the existing "destination directory does not exist" message, while other stat errors (e.g., permission issues) fall through to `rename()` for reporting. The patch handles sparse entries, out-of-cone destinations, and trailing slashes correctly, and adds comprehensive test coverage for missing directories, non-directory path components, symlinks, and `--dry-run` detection.

This is a well-crafted fix that addresses all prior feedback from Junio C Hamano and Ben Knoble. The TOCTOU race (where the directory could disappear between the check and the syscall) is acknowledged but left unresolved, as it’s deemed "the best we can do" for now. The patch touches only `builtin/mv.c` and `t/t7001-mv.sh`, with no new symbols or on-disk format changes. The l10n impact is minimal, limited to reusing existing translatable strings.

The series as a whole is uncontroversial and appears ready for final review. The first patch (improving error messages) was already approved by Junio, and this second patch resolves the remaining technical concerns. If you care about `git mv` usability or dry-run accuracy, this is worth a look.
