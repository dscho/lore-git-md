This is Junio C Hamano's follow-up to Lucas Zamboni Orioli's v3 proposal for the second patch in the `git mv` bugfix series. Junio raises a security concern: using `stat()` instead of `lstat()` could allow a malicious or misconfigured working tree to trick `git mv` into moving files outside the working tree if the destination path contains a symlink. He cites `git apply` as precedent for avoiding symlink-following behavior. The message does not address the other edge cases (non-directory paths, intermediate components) or the TOCTOU race, focusing solely on the symlink-handling design choice. This reply reopens the technical discussion on the second patch and may require a v4 to resolve.
