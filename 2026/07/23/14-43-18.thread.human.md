This thread is about a bug fix for a segmentation fault in `git clone --revision=<ref>` when the server advertises more refs than the client requested. The crash occurs because the code dereferences a NULL `peer_ref` field in a `struct ref` returned by `guess_remote_head()`. Adrian Friedli reported the issue and proposed a minimal one-line NULL check in `builtin/clone.c`.

Junio initially questioned whether the fix belonged in `update_remote_refs()` or `guess_remote_head()`, but after further review, he confirmed that a `struct ref` with a NULL `.peer_ref` is legitimate in this context. The fix is now conceptually approved, with the only remaining task being the addition of a regression test to prevent future regressions. No other objections or alternative approaches have been raised, and the discussion has settled on the proposed fix location. The thread is now waiting on Adrian to provide the requested test.
