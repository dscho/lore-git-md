This is the second patch in the two-patch bugfix series for `git mv`, focusing on the early directory existence check to enable `--dry-run` detection. Junio C Hamano replies to Lucas Zamboni Orioli’s v2 patch with a **substantive review** that identifies two edge cases in the new `lstat`-based check: (1) when the path exists but is not a directory (e.g., a symlink or regular file), and (2) when an intermediate path component is not a directory (e.g., `a/b/c` where `a/b` is a file). The current implementation treats these as success, but they will cause the later `rename(2)` syscall to fail, potentially with confusing error messages.

The review suggests these conditions should be detected during the checking phase to provide clearer diagnostics and to ensure `--dry-run` behaves consistently. The patch touches `builtin/mv.c` and is part of a well-motivated series that already has maintainer approval for the first patch (error message clarity). The unresolved TOCTOU race remains acknowledged but is not the focus here. The new feedback does not invalidate the patch but adds technical depth to the discussion, likely requiring a v3 to address the edge cases before the series can graduate to `next`.

Key terms for follow-up: `lstat`, `ENOTDIR`, symlink handling, intermediate path components, `--dry-run`, and the existing `bad` error message flow. Files involved: `builtin/mv.c` (no new symbols introduced). The review is narrowly scoped to the directory existence logic and does not revisit the series’ overall structure or the TOCTOU trade-off.
