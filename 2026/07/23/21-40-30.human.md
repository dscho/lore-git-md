This is the first patch in a two-part bugfix series for `git mv`. It addresses a misleading error message when a rename operation fails due to a missing destination directory. Currently, `git mv` blames the source file even when the real problem is a missing parent directory in the destination path. The patch changes the error message to include both the source and destination paths, making it clear which part of the operation failed. For example, instead of "renaming 'src' failed: No such file or directory", the message now reads "renaming 'a/file' to 'b/no-such-dir/file' failed: No such file or directory".

The change is minimal—just one line in `builtin/mv.c`—and uncontroversial. Junio C Hamano already approved this part of the series in an earlier review, calling it "Makes sense". The commit message explains the rationale well: `rename(2)` returns the same `ENOENT` error for both missing source and missing destination directory components, so the error message should include both paths to avoid misleading the user. There is no race condition here because the message is generated after the syscall fails, and the paths are still valid at that point.

This patch is ready to merge and does not depend on the second patch in the series. It is a straightforward improvement that makes `git mv` more user-friendly without changing any behavior. The only impact is on translators, who will need to update the error message string, but the change is minor and unlikely to cause issues. If you care about clear error messages, this patch is worth a quick look.
