This is the sixth patch in the RFC series introducing `git repack --drop-filtered` for partial clones. It implements the actual object-dropping logic, turning the earlier dry-run enumeration into a real space-reclaiming operation. The patch is well-structured and addresses the core functionality promised by the series: safely removing locally cached promisor blobs that exceed a size threshold while ensuring they remain recoverable from the promisor remote.

The patch modifies `builtin/repack.c` to pass the computed drop set (`drop_oids`) to `repack_promisor_objects()`, which rebuilds the promisor packs while excluding the dropped blobs. On a real run (not `--dry-run`), it implies `-d` to remove the old promisor packs that still contain the dropped blobs, ensuring no redundant copies linger. The repack machinery’s existing write-before-delete and fsync guarantees make the drop crash-safe. The `repack-filtered.c` helper is updated to return the drop set via an output parameter (`to_drop`) rather than printing it directly, and the test script (`t/t7706-repack-drop-filtered.sh`) gains a new test validating that `--drop-filtered` actually removes the promisor blob locally while preserving smaller blobs.

Key changes include finalizing the `enumerate_promisor_blobs()` signature (now takes an `oidset *to_drop` instead of a `dry_run` flag), lifting the `--dry-run` restriction (real runs are now supported), and solidifying the conditional bypass of `write_filtered_pack()`. The patch also removes the now-obsolete test that rejected `--drop-filtered` without `--dry-run`. Safety checks (e.g., preventing drops during merges) are still deferred to future patches, but the core drop mechanism is now functional.

The patch is part of a larger RFC series that remains in active design iteration. The blocking logical flaw in the `--drop-filtered` vs `--write-bitmap-index` validation (identified by Junio) is confirmed and must be fixed in v2, along with safety guards, API reorganization, and drop-log documentation. The series is not yet assigned to an integration branch, and the CLI design (`--drop-filtered` + `--dry-run`) is settled but still needs rationale documentation in the commit message. The patch itself is technically sound and aligns with the series’ goal of safely reclaiming space in partial clones.
