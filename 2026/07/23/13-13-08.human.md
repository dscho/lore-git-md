This is a bugfix patch series for `git mv`, now split into two focused commits. The first commit improves the error message to include both source and destination paths when a rename fails, addressing the misleading output that previously blamed the source file. The second commit adds an early check for the existence of the destination directory during the checking phase, ensuring that `git mv --dry-run` can detect the problem before attempting the actual move.

The series is narrowly scoped to `builtin/mv.c` and the test suite (`t/t7001-mv.sh`), with no changes to on-disk formats or new symbols. The implementation is careful to avoid false positives—for example, it skips the check for directory moves (where child entries are expanded under a not-yet-created directory) and sparse or out-of-cone destinations (which aren’t written to the worktree). The tests cover both the error path and dry-run detection, though the TOCTOU race in the second commit remains unresolved, as noted in the thread.

The changes are well-motivated and address a real usability issue. The split into two commits—first clarifying the error message, then adding the early check—makes the logic easier to review and ensures the first part is race-free. The patch looks ready for further review, though the unresolved TOCTOU race and the choice of `lstat` (vs. `stat`) for the directory check may prompt discussion. Interaction with sparse-checkout and worktree modes is also flagged as a potential follow-up topic.
