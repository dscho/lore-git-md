This is a bugfix patch that prevents a segfault in `git clone` when using the `--revision` argument with servers that ignore the `ref_prefixes` option and return more refs than requested.

The issue occurs when a server (like Azure DevOps) advertises all refs even when Git asks only for a specific revision. In this case, `guess_remote_head()` returns a non-NULL `remote_head_points_at` whose `peer_ref` field is NULL, leading to a NULL dereference when the code later accesses `remote_head_points_at->peer_ref->name`. The fix adds an explicit check for `remote_head_points_at->peer_ref` before proceeding.

The patch is minimal—just one line—and includes a clear reproduction case (cloning from Azure DevOps with `--revision`). The commit message explains the two code paths (good vs. bad) and why the crash happens. This looks like a well-motivated, narrowly scoped fix for a real-world edge case. Worth attention if you use `--revision` or work with servers that don’t respect `ref_prefixes`.
