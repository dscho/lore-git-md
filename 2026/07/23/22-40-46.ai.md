This is Junio C Hamano's follow-up to Lucas Zamboni Orioli's proposal to switch from `lstat()` to `stat()` in the second patch of the `git mv` bugfix series. Junio rejects the `stat()` approach, arguing that following symlinks in a Git working tree is unsafe: it could allow `git mv` to move files outside the working tree if the destination path contains a tracked symlink pointing to an external directory. He cites `git apply` as precedent for avoiding symlink traversal and implies that `lstat()` (which does not follow symlinks) is the correct choice. This reply reopens the technical discussion on the second patch, specifically the symlink-handling strategy, and suggests that the v3 iteration may need further revision. The TOCTOU race and the two-patch structure remain unchanged.
