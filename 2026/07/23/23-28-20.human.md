This is a reply in the ongoing `git mv` bugfix thread. Junio C Hamano rejects the `stat()`-based approach Lucas Zamboni Orioli proposed in v3 of the second patch, arguing that following symlinks in a Git working tree is unsafe. He cites `git apply` as precedent for avoiding symlink traversal and insists that `lstat()` (which does not follow symlinks) is the correct choice. The core concern is that `stat()` could allow `git mv` to move files outside the working tree if the destination path contains a tracked symlink pointing to an external directory. This reply leaves the symlink-handling strategy unresolved and blocks the series from advancing until the disagreement is settled. The first patch (improved error message) remains uncontested and approved.
