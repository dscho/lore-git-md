This is a feature patch adding a new configuration option to control the HTTP connection timeout in Git. The patch introduces `http.connectTimeoutMS` (and its environment variable counterpart `GIT_HTTP_CONNECT_TIMEOUT_MS`) to allow users to specify a millisecond-level timeout for the connection phase (DNS lookup, TCP/TLS/QUIC handshakes), overriding libcurl's default 300-second timeout.

The implementation touches `http.c` to add the new configuration variable, parse it from both config and environment, and pass it to libcurl via `CURLOPT_CONNECTTIMEOUT_MS`. The documentation is updated in `Documentation/config/http.adoc` with a clear description of the new option. A new test script (`t/t5585-http-connect-timeout.sh`) thoroughly exercises the feature, covering positive cases (valid numeric values), edge cases (zero, empty, non-numeric values), and environment variable handling. The test is also added to the Meson build system.

The patch is well-structured and complete: it includes the code change, documentation, and tests, and the commit message clearly states the motivation (libcurl's default timeout being too long for some use cases). The test coverage is particularly strong, verifying both success and error paths for both config and environment variable usage. This looks like a straightforward, user-facing improvement with no obvious downsides or controversy. The implementation follows existing patterns in the codebase (e.g., `http.lowSpeedLimit`/`http.lowSpeedTime`), making it a clean addition.
