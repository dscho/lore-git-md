This is a bugfix patch for submodule handling, addressing a regression introduced in 2025 where `git submodule update --remote` fails when URL aliases (`url.<base>.insteadOf`) are used. The v2 iteration incorporates Junio C Hamano’s feedback from the initial review, refining both the commit message and implementation.

The core issue remains the same: `.gitmodules` stores the unexpanded alias (e.g., `local:path`), while the submodule’s remotes report the resolved URL (e.g., `/full/path`), causing the lookup to fail. The fix modifies `repo_remote_from_url()` in `remote.c` to resolve aliases via `alias_url()` before comparing URLs, ensuring the correct remote is selected. The v2 simplifies the code by reusing the `url` variable instead of introducing a temporary `url_to_match`, and the commit message now more clearly explains the fallback behavior and edge cases.

The test in `t/t7406-submodule-update.sh` verifies the fix by setting up a global `insteadOf` alias, creating a submodule with the aliased URL, and confirming `update --remote` works after renaming the default remote. The test is slightly tidied in v2 (removing an unnecessary file creation and simplifying the update command).
