This thread introduces a new `http.connectTimeoutMS` configuration option, allowing users to set HTTP connection timeouts with millisecond precision, overriding libcurl's default 300-second timeout. The feature is proposed by GalaxySnail (via GitGitGadget) in a single-patch series that touches `http.c`, documentation, and adds a new test script.

Junio C Hamano has reviewed the patch and raised three key points that need resolution. First, he asks for clarification on the real-world use case for millisecond-level timeout control—whether this addresses a practical need (like CI pipelines or flaky networks) or merely exposes an implementation detail. Second, he identifies a behavioral ambiguity: the patch silently ignores a zero value for `http.connectTimeoutMS`, while libcurl treats zero as "use the default timeout." He suggests documenting this behavior and adjusting the code to explicitly restore the default when zero is set. Third, he questions the necessity of a dedicated test script, noting that the current tests only verify parsing rather than real-world timeout behavior and could be merged into an existing HTTP test file.

The patch is otherwise well-structured, but these issues must be addressed before it can proceed. The maintainer’s feedback is focused on usability and resource management, and the author will need to respond with concrete use cases and technical adjustments. No other reviews have been posted yet.
