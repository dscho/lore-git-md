This is the first patch in a two-patch bugfix series for `git mv`. It addresses a misleading error message that occurs when `git mv` fails due to a missing destination directory. Currently, the error blames the source file (e.g., "renaming 'src' failed: No such file or directory"), even when the source exists and the destination's parent directory is missing. This patch updates the error message to include both the source and destination paths, making it clear which part of the operation failed (e.g., "renaming 'a/file' to 'b/no-such-dir/file' failed: No such file or directory").

The change is minimal and focused: it modifies a single line in `builtin/mv.c` to pass both `src` and `dst` to `die_errno()`. The commit message explains the rationale clearly, noting that `rename(2)` returns `ENOENT` for both missing source and missing destination directory components, and that errno does not distinguish between the two. The patch avoids a TOCTOU race by not re-inspecting the paths after the `rename(2)` failure, instead relying on the user to interpret the error message.

This is a straightforward, user-facing improvement with no behavioral changes beyond the error message. The patch is uncontroversial and aligns with reviewer feedback from the previous iteration of the series. The new error message string will require translation updates, but this is a routine part of the l10n process. The patch is ready for review and unlikely to generate significant discussion, though it sets the stage for the second patch in the series, which introduces an early directory existence check. Key files: `builtin/mv.c`.
