This is a v2 bugfix patch for submodule handling, addressing a regression in `git submodule update --remote` when URL aliases (`url.<base>.insteadOf`) are used. The patch resolves feedback from Junio C Hamano on the initial version, improving the commit message clarity and simplifying the implementation by reusing the `url` variable instead of introducing a new one (`url_to_match`).

The core issue remains the same: since ca62f524c1 (2025), submodules with aliased URLs fail to match their remotes because `.gitmodules` stores the unexpanded alias (e.g., `local:path`) while the submodule’s remotes report the resolved URL (e.g., `/full/path`). The fix modifies `repo_remote_from_url()` in `remote.c` to resolve aliases via `alias_url()` before comparing URLs, ensuring the correct remote is selected. The test in `t/t7406-submodule-update.sh` verifies the fix with a global `insteadOf` alias, submodule setup, and remote renaming.

Key changes in v2:
- **Commit message**: Now explicitly references the original commit (ca62f524c1) and clarifies the fallback behavior’s limitations (e.g., failing when no "origin" remote exists).
- **Code**: Removes the redundant `url_to_match` variable, directly reusing `url` after alias resolution. The logic is otherwise unchanged.
- **Test**: Simplified by removing an unnecessary file creation and streamlining the submodule update commands.

The patch is narrowly scoped, well-tested, and addresses Junio’s feedback without introducing new concerns. It should be ready for merging once any final nitpicks are resolved.
