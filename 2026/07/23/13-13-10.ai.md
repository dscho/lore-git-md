This is the second patch in a two-patch bugfix series for `git mv`, addressing a TOCTOU race and improving `--dry-run` behavior when the destination's parent directory does not exist. The patch moves the directory existence check into the checking phase of `builtin/mv.c`, ensuring that `git mv -n` can detect the problem before the actual rename syscall. The implementation is careful to avoid false positives for directory moves, sparse entries, and out-of-cone destinations by guarding the check with the same conditions under which `rename(2)` is invoked.

The patch adds a new `lstat` check for the destination's leading directory during the checking phase, failing with the existing "destination directory does not exist" message if the directory is missing. This is a best-effort diagnostic rather than a guarantee, as the directory could still disappear between the check and the `rename(2)` syscall. The change is narrowly scoped to `builtin/mv.c` and adds two new tests in `t/t7001-mv.sh` covering both the error path and `--dry-run` detection.

Key technical details include the use of `lstat` (not `stat`) for the directory existence check, which remains unresolved in the discussion, and the explicit acknowledgment of the TOCTOU race. The patch does not introduce new symbols but modifies internal logic to handle the edge cases mentioned. The l10n impact is minimal, as it reuses an existing error message.

This patch is part of a well-scoped, user-facing fix with clear test coverage and detailed commit messages. The unresolved TOCTOU race and the choice of `lstat` over `stat` may prompt further discussion, but the patch itself is unlikely to be controversial. It directly addresses the core issue raised in the series: enabling `--dry-run` to detect missing destination directories. Files touched: `builtin/mv.c`, `t/t7001-mv.sh`.
