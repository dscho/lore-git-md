This is the second patch in a two-part bugfix series for `git mv`, addressing a long-standing issue where the command gives misleading errors when the destination directory does not exist. Junio C Hamano’s reply here focuses on a specific code block in the patch: the new directory existence check. He points out two edge cases the current implementation misses—when the parent path exists but is not a directory (e.g., a symlink or regular file), and when an intermediate component in the path is not a directory (ENOTDIR). The patch currently treats any `lstat` success as sufficient, which could lead to false negatives or confusing downstream errors.

The patch itself is already cooking in `next` and has Junio’s conditional approval pending a style fix for indentation. This new feedback adds a technical wrinkle: the current check is too permissive and could mask real problems. The author will need to decide whether to tighten the validation (e.g., by checking `S_ISDIR` or handling ENOTDIR) or document the limitation as a deliberate trade-off. Either way, the fix remains a targeted improvement to error clarity and `--dry-run` behavior, with no on-disk format changes or new user-facing options. Files touched: `builtin/mv.c`; key terms: `lstat`, ENOTDIR, symlink handling.
