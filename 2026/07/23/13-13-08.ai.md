This is a two-patch bugfix series for `git mv`, addressing a misleading error message when the destination's parent directory does not exist. The series splits the work into two logical commits: the first improves the error message to include both source and destination paths, and the second adds an early existence check for the destination directory to enable `--dry-run` detection.

The core issue is that `git mv` currently reports errors like "renaming 'src' failed: No such file or directory" when the *destination's* parent directory is missing, incorrectly blaming the source file. The first patch fixes this by making the error message unambiguous (e.g., "renaming A -> B failed: no such file or directory"). The second patch moves the directory existence check into the checking phase, ensuring `--dry-run` can detect the problem before the actual rename syscall. The implementation is careful to avoid false positives for directory moves, sparse entries, and out-of-cone destinations.

The series touches only `builtin/mv.c` and adds two new tests in `t/t7001-mv.sh`. The TOCTOU race in the second patch (where the directory could disappear between the check and the rename) remains unresolved but is explicitly acknowledged. The author followed reviewer feedback by splitting the work into two commits and improving the error message format. The l10n team will need to handle the new translatable string for the improved error message.

This is a well-scoped, user-facing fix with clear test coverage. The commit messages are detailed and explain the rationale for the implementation choices. The series is unlikely to be controversial and appears ready for further review, though the TOCTOU race and the use of `lstat` (vs `stat`) may prompt additional discussion.
