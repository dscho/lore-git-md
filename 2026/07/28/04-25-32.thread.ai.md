Thread identity: RFC patch introducing `pack.allowDuplicateObjects` configuration and `git index-pack --[no-]allow-duplicate-objects` flag, targeting the packfile handling subsystem. Series version: RFC (single patch). Originating author: friel@openai.com. Thread type: RFC patch series.

Core problem or goal: Allow Git to accept packfiles containing duplicate objects during `git index-pack` when explicitly configured, addressing a performance bottleneck for servers streaming objects from overlapping existing packs. The feature is opt-in (default `false`) and preserves all other validation checks, including strict mode rejection of duplicates. The discussion has evolved to focus on whether Git should ever allow invalid packfiles (even as an opt-in exception) and how to design the feature to minimize risks.

Current status: Under review as an RFC with no prior versions or integration status. The patch has received substantive technical feedback and philosophical pushback. Taylor Blau has advanced the discussion by arguing that Git’s internals are already hardened against duplicates (via `tb/pack-with-duplicates`) and proposing a narrower design where `--allow-duplicate-objects` would only relax the duplicate-OID check in `--strict` mode while preserving all other validation. Junio C Hamano’s objection remains unresolved but is now framed as a design challenge rather than a fundamental veto.
