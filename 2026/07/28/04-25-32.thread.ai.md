Thread identity: RFC patch introducing `pack.allowDuplicateObjects` configuration and `--[no-]allow-duplicate-objects` flag for `git index-pack`, targeting the packfile handling subsystem. Series version: RFC (single patch). Originating author: friel@openai.com. Thread type: RFC patch series.

Core problem or goal: Allow Git to accept packfiles containing duplicate objects during `git index-pack` when explicitly configured to do so, addressing a performance bottleneck for servers that stream objects from overlapping existing packs. The feature is opt-in (default `false`) and preserves all other validation checks, including strict mode rejection of duplicates.

Current status: Under review as an RFC with no prior versions or integration status (not in `pu`, `seen`, `next`, or `master`). The patch has received substantive technical feedback from Taylor Blau and conceptual pushback from Junio C Hamano, who frames the feature as a slippery slope that could complicate Git’s internals and undermine repository integrity. Junio references a past discussion with Shawn Pearce to support his position that Git should prioritize early detection and rejection of malformed or invalid packfiles, rather than allowing them even as an opt-in exception. The author must now address Junio’s philosophical concerns or demonstrate that the trade-offs (performance vs. correctness) are unavoidable and well-contained.

Key technical details:
- **Files touched**: `builtin/index-pack.c`, `Documentation/git-index-pack.txt`, `Documentation/config/pack.txt`, `t/t5308-pack-detect-duplicates.sh` (new test file).
- **New symbols**: Configuration knob `pack.allowDuplicateObjects` (boolean, default `false`), command-line flag `--[no-]allow-duplicate-objects` for `git index-pack`.
- **Behavior**: When enabled, `git index-pack` accepts packs with duplicate objects during validation. The current design makes `--allow-duplicate-objects` incompatible with `--strict`/`--verify` (using a tri-state enum: `DUPLICATE_OBJECTS_REJECT`, `DUPLICATE_OBJECTS_ALLOW_CONFIG`, `DUPLICATE_OBJECTS_ALLOW_OPTION`). Taylor Blau has suggested revisiting this design to allow the flag to selectively disable *only* the duplicate-object check while preserving other strict validation. Junio’s feedback does not engage with this technical detail, focusing instead on the broader principle of rejecting invalid packfiles outright.
- **On-disk format**: No changes; duplicates are only allowed during pack validation and do not affect delta resolution or storage.
- **Test coverage**: Extensive, including configuration overrides, integration with `git clone` (full, shallow, and partial clones), and edge cases like connectivity checks. Taylor Blau suggested streamlining test redundancy, but Junio’s feedback does not address test coverage.
