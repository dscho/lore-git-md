This is a new feature patch series from Junio C Hamano introducing a `git add --resolved` option. The goal is to streamline the maintainer workflow by allowing paths with resolved conflicts to be added to the index without including unrelated local changes.

The series starts with two refactoring patches: the first consolidates conflict marker detection logic (previously duplicated in `diff.c` and `rerere.c`) into a new helper in `merge-ll.c`, while the second adds a helper function to simplify removing files from the index with support for `--dry-run` and `--verbose` flags. The third patch implements the core feature, teaching `git add` to recognize a `--resolved` flag that stages only files with conflict markers removed. The fourth patch is a whitespace-only cleanup of `read-cache.c`.

The motivation is clear and practical: maintainers frequently deal with merge conflicts while also having unrelated local changes in their working tree, making `git add -u` impractical. The new option addresses this by targeting only resolved conflicts. The series includes a new test script (`t/t2207-add-resolved.sh`) with 108 lines of test coverage, suggesting thorough validation. The implementation looks well-structured, with the refactoring patches logically separated from the feature addition. This appears to be a polished, well-motivated contribution that should be uncontroversial.
