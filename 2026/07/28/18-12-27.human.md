This is a **bugfix** for a memory leak in `git merge` when using the `merge.defaultToUpstream` configuration. The patch, originally submitted by Toon Claes, has received a substantive review from Jeff King (Peff), who confirmed the leak and the correctness of the fix. Junio C Hamano has now queued the patch for integration, signaling that it will likely land in `next` soon.

The leak has been present since 2011 but went unnoticed because the test suite lacked coverage for the default-to-upstream path. Toon’s patch adds a test in `t/t7600-merge.sh` to exercise this code path under the leak sanitizer, ensuring the fix is verified. The fix itself is minimal: it introduces an `argv_to_free` variable in `cmd_merge()` to track the allocated argument array from `setup_with_upstream()` and frees it later.

Peff’s review noted the surrounding code’s awkwardness—particularly how `argv` is manipulated after allocation—but deemed a larger refactor unnecessary. Junio’s reply playfully acknowledges this, indicating no further changes are expected. The patch is a straightforward, well-motivated correction with no behavior changes, and the added test coverage strengthens the project’s memory hygiene. If you care about merge internals or leak fixes, this is a small but solid improvement worth noting.
