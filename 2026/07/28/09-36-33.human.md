This is a **substantive review follow-up** in the ongoing thread about Son Luong Ngoc’s patch series fixing `git rebase --update-refs` edge cases with symbolic references. The discussion centers on the first patch, which skips branch symref aliases during rebase.

Phillip Wood responds to Junio C Hamano’s design question about whether the rebase logic should handle HEAD pointing outside `refs/heads/` (e.g., to a tag). Phillip confirms that Git explicitly allows HEAD to point to any ref under `refs/` (not just branches), citing a 2009 commit that formalized this behavior. While he acknowledges that non-branch HEADs might surprise users (noting a recent Discord report), he argues that the current patch’s logic should account for them to maintain consistency. The implication is that the series should use `resolved_ref` (the resolved target of the symref) rather than `decoration->name` (the symref name itself) when comparing against HEAD, as this would correctly handle cases where HEAD and a symref point to the same target, even if that target is outside `refs/heads/`.

The exchange does not resolve the design question but clarifies that the existing Git codebase already supports non-branch HEADs, so the patch should not assume HEAD always points to a branch. No merge status is reported, and the series remains under review. The next iteration (v4) is expected to incorporate this refinement, along with Phillip’s earlier requests for an explanatory comment and minor test organization tweaks. The latent bug in `master` (clobbered `head_ref` buffer) identified by Erik Cervin-Edin remains unaddressed and may become a follow-up topic.
