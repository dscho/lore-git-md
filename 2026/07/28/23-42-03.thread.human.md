This thread is a performance inquiry from Ryszard Knop about the `fetch.bundleURI` feature in Git, which is unexpectedly slow when cloning the Linux kernel repository in a CI environment. Knop describes a setup where pre-generated Git bundles are used to avoid repeated full clones, but the bundle-based approach takes 4–5 minutes—comparable to or even slower than a standard clone (3–4 minutes). Profiling shows that `git index-pack` is the bottleneck, consuming 100% CPU on a single thread for most of the operation.

The inquiry is not a patch or a proposed fix but a request for clarification: is this slowness expected, or is it a potential bug? Knop notes that an alternative approach—using a full bare repository—might be more performant but is less elegant. The discussion may evolve into profiling deeper issues, exploring optimizations, or evaluating alternative solutions for large-repository CI workflows. No responses or reviews have been posted yet.
