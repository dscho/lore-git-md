This is the first patch in the v8 series introducing `--linearize` to `git replay`. It is a **pure refactoring** that extracts the logic for storing rewritten commits into a new helper function, `put_mapped_commit()`, and renames the existing `mapped_commit()` to `get_mapped_commit()` for symmetry.

The change is internal to `replay.c` and prepares the codebase for the `--linearize` feature by encapsulating commit-mapping logic. The diff shows the new helper function and its usage in `replay_revisions()`, replacing manual hashmap operations with a cleaner interface. No behavior changes are introduced; this is purely about code organization and maintainability.

The patch is well-motivated in the commit message, which explains the goal of reducing complexity in `replay_revisions()`. The refactoring was previously debated in earlier versions (v2–v5) over enum-vs-bool tradeoffs, but the current implementation (using a hashmap) has been stable since v5. Feedback from Justin Tobler and Patrick Steinhardt on earlier iterations was addressed by reverting the enum-based approach in favor of this simpler design.

This patch is uncontroversial and serves as a foundation for the subsequent patches in the series. It touches only `replay.c` and is unlikely to conflict with other ongoing work. The new helper functions (`put_mapped_commit` and `get_mapped_commit`) will be used in patch 3/3 to implement `--linearize`.
