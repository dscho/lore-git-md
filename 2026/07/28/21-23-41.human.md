This is the fifth and final patch in Patrick Steinhardt’s five-part series making on-disk object database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort, and this patch completes the decoupling by introducing a `create_on_disk` callback in the ODB source interface. The callback allows each backend to define its own directory layout while keeping the top-level `objects/` directory mandatory for repository discovery.

Justin Tobler’s review is brief but substantive. He confirms the callback’s implementation matches the current set of directories (`objects/pack`, `objects/info`) and approves the unconditional creation of the `objects/` directory, which is necessary for repository recognition. His only question is architectural: whether the callback invocation should be part of `odb_new()` (possibly gated by a flag) rather than a separate explicit step. This is a design preference rather than a correctness issue, and he acknowledges the current approach is reasonable.

The patch itself is clean and well-scoped, touching only three files (`odb/source-files.c`, `odb/source.h`, and `setup.c`). It moves the creation of backend-specific directories from the generic `create_object_database()` function into the "files" backend’s callback, making the codebase ready for future backends with custom layouts. No user-visible behavior changes are introduced, and the implementation includes proper error handling for the callback. This is a foundational step for the ODB abstraction effort, and the review suggests it is on track for eventual integration.
