This is a bugfix for the pack-bitmap subsystem, addressing an off-by-one edge case in `find_objects()` that was introduced in commit 11d45a6e6a.

The patch corrects a logic error where the code checks `pos > 0` to determine if an object is already represented in the base bitmap. This check incorrectly excludes objects at position zero, causing unnecessary work: either reloading the object's individual reachability bitmap or redundantly adding it to the not-mapped list. The fix changes the condition to `pos >= 0`, ensuring position zero is treated as valid. The resulting object set remains unchanged, but redundant work is eliminated.

The commit message is clear and well-motivated, identifying the problematic commit, explaining the edge case, and describing the behavioral impact. The test coverage has been expanded in this version (`v2`) to include both pseudo-merge and non-pseudo-merge scenarios. The non-pseudo-merge test exercises a simple case where `HEAD` is passed twice to `git rev-list --objects --use-bitmap-index`, ensuring the position-zero object is recognized as already present after the first occurrence.
