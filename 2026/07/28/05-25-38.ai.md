This is a **platform compatibility bugfix** for macOS, addressing the same memory leak in the system regex engine (TRE) as the v1 patch but with significant structural improvements. The v2 patch adopts Junio C Hamano’s suggestion to organize the Darwin-specific override in a dedicated platform header (`compat/darwin.h`) and implementation file (`compat/darwin/regexec.c`), making the codebase more modular and maintainable. The fix remains narrowly scoped to macOS builds using the system regex engine (skipped when `NO_REGEX` is set) and preserves all behavioral guarantees of the original implementation.

The core logic is unchanged: the patch splits input buffers at invalid multibyte sequences using `mbrtowc()`, searches each valid segment separately with `REG_STARTEND`, and ensures `^`/`$` anchors only match at true line boundaries. However, v2 adds clearer documentation of `mbrtowc()`’s return values (`-1` for encoding errors, `-2` for incomplete sequences) and treats the workaround as indefinite, acknowledging that Git will need to support affected macOS releases even after upstream fixes. Build system integration is now consistent across Makefile, Meson, and CMake, using a single `DARWIN_REGEXEC` flag.

Test coverage has expanded to verify matches around invalid bytes, correct anchoring, and edge cases like incomplete trailing sequences. The new tests use POSIX regex patterns to avoid the fixed-string optimization, ensuring they exercise the patched code path. While the positive invalid-UTF-8 matching tests remain macOS-specific (due to platform differences in regex behavior), the anchor-related tests run on all `MB_REGEX` platforms, improving broader regression detection.

The patch is well-motivated, thoroughly tested, and addresses Junio’s structural concerns without compromising the fix’s correctness.
