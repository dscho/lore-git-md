This is a documentation patch that wraps up the long-running discussion about the return type of Git’s UTF-8 string-width functions. Junio C Hamano and Phillip Wood are finalizing the wording of a comment in `utf8.c` that will explain why `utf8_strwidth()` and `utf8_strnwidth()` return `int` instead of `size_t`. The patch itself is uncontroversial and ready for a last revision: Hardik Kumar (the author) has already agreed to cite the original commit (937b7c8b) that introduced `cast_size_t_to_int()` to fix a crash caused by implicit `size_t`→`int` conversion. Junio’s suggested comment text now explicitly ties the `int` return type to `printf()`-style padding (`%*s`) and clarifies that the value will never exceed what `int` can represent, making the design choice legitimate. Once Hardik incorporates these tweaks, the patch should be ready to merge.
