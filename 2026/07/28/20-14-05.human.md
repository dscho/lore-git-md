This is a review reply to the first patch in Patrick Steinhardt’s five-part series making on-disk ODB structures pluggable. The patch fixes a bug in loose-object map loading: the function was ignoring the passed-in ODB source and always loading the map from the common `objects/` directory instead of the source-specific path.

Justin Tobler’s review is substantive and tested. He first asks whether the bug means repositories using a compatibility hash and alternates are currently broken, then confirms the fix by tracing how the repository’s hash algorithm is now accessed through the loose source rather than passed redundantly. He explicitly notes that the new path construction (`xstrfmt("%s/loose-object-idx", loose->base.path)`) uses the correct source-specific path. The review is concise but covers both the bug’s implications and the correctness of the fix, and Justin’s sign-off (“Looks good”) carries the weight of someone who has thought through the change. No further action appears needed on this patch.
