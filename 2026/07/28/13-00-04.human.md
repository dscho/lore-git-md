This is a bugfix patch that plugs a memory leak in `git merge` when the `merge.defaultToUpstream` configuration is enabled. The leak occurs because the `setup_with_upstream()` function allocates an argument array that was never freed, and Toon Claes’s patch tracks and releases that memory at the end of the command.

The commit message is clear and thorough: it explains the default behavior, identifies the exact function responsible for the leak, traces the bug back to its introduction in 2011, and notes why the leak sanitizer missed it (no existing test exercised the default-to-upstream code path). A new test in `t7600-merge.sh` now covers this case, so the leak should not reappear. The fix itself is minimal—just two lines of bookkeeping plus the free call—and looks correct.

The patch is well-motivated: Toon ran into the leak while using `yay` (an AUR helper that calls `git merge` without arguments), so this is a real-world issue, not a theoretical one. The change is small, self-contained, and comes with test coverage, so it should be uncontroversial and ready for `next`.
