This is the fifth patch in Patrick Steinhardt’s five-part series making on-disk ODB structures pluggable, part of the ongoing ODB abstraction effort. The patch introduces a `create_on_disk` callback in the ODB source interface, allowing each backend to define its own directory layout while keeping the top-level `objects/` directory mandatory for repository discovery. Justin Tobler’s review is **surface-level**: he confirms the callback’s purpose and implementation match the current files-based layout, approves the unconditional creation of the `objects/` directory, and briefly muses about whether the callback should be invoked inside `odb_new()` rather than as a separate step. His feedback is observational and does not raise technical concerns or suggest changes.

The patch itself is a clean, mechanical refactoring that moves the creation of backend-specific directories (`objects/pack`, `objects/info`) from the generic `create_object_database()` function into the "files" backend’s callback. No user-visible behavior changes are introduced, and the implementation is straightforward, with clear commit messages and no obvious gaps in error handling. This completes the series’ goal of decoupling ODB setup from repository initialization, a foundational step for future backends with custom layouts. The only open question is Justin’s minor design preference about callback invocation timing, which is unlikely to block progress. The series remains under review, with no merge status reported.
