This is the v2 cover letter for a two-patch series that continues the `the_repository` removal effort by migrating two more global configuration variables (`pack_size_limit_cfg` and `assume_unchanged`) into the `repo_config_values` struct. The series is now scoped down from the original three patches after Junio objected to the design of the `minimum_abbrev`/`default_abbrev` migration in v1.

The goal remains the same: eliminate process-global configuration variables so that code paths (like `merge-ort`) that explicitly avoid `the_repository` can access them safely. No getter functions are introduced for these variables due to their limited call sites, and backward compatibility is maintained by accessing the values via `the_repository` where needed.

The v2 series looks clean and uncontroversial. The dropped patch (1/3 from v1) was the only point of contention, and the remaining two patches address Junio’s feedback by avoiding the problematic fallback design. The commit messages and code changes appear straightforward, with no behavior changes intended. This is pure infrastructure work, so existing tests should suffice for coverage.
