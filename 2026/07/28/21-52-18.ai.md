This is the core feature patch in Junio C Hamano’s `git add --resolved` series (3/4). It implements the new `--resolved` option for `git add`, which stages only unmerged paths where conflict markers have been removed, leaving unrelated local changes untouched.

The patch adds the command-line option, updates the man page, and introduces the logic in `builtin/add.c`. The implementation scans the index for unmerged paths, checks each for remaining conflict markers using the `has_conflict_markers()` helper (defined in `merge-ll.c`), and either stages the resolved paths or aborts with an error listing any unresolved ones. Binary files and deletions are staged as resolved without marker checks. The option is incompatible with `-u` and `-A`.

The test script `t/t2207-add-resolved.sh` covers the main scenarios: refusing to stage files with markers, succeeding when all markers are removed, ignoring unconflicted modified files, handling deletions, respecting pathspecs, and enforcing option incompatibility. The implementation is self-contained, touching only `builtin/add.c`, `merge-ll.c`, and the new test file.
