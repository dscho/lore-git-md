This is a bugfix for the pack-bitmap subsystem, now ready for integration. Junio Hamano has queued the patch after all review feedback was addressed in the second iteration (`v2`). The fix targets an off-by-one edge case in `find_objects()` where objects at position zero in the base bitmap were incorrectly excluded, causing redundant work—either reloading reachability bitmaps or adding objects to the not-mapped list unnecessarily.

The patch itself is minimal and well-scoped: it changes a single conditional check from `pos > 0` to `pos >= 0` in `pack-bitmap.c`, ensuring position zero is treated as valid. The commit message clearly explains the regression (introduced in commit 11d45a6e6a), the edge case, and the behavioral impact—no change to the resulting object set, just elimination of redundant work. The test coverage now verifies both pseudo-merge and non-pseudo-merge cases, ensuring the fix works regardless of how the position-zero object is encountered. The patch touches only `pack-bitmap.c` and the test file `t/t5333-pseudo-merge-bitmaps.sh`, and all review feedback has been addressed.
