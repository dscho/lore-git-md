This is a documentation patch that wraps up the UTF-8 string-width refactoring discussion. Phillip Wood reviews Hardik Kumar’s v4 patch, which replaces the old TODO comment in `utf8.c` with a rationale for why `utf8_strwidth()` and `utf8_strnwidth()` still return `int`. The patch itself is uncontroversial—it simply documents the design constraints that led to the withdrawal of the earlier refactoring series—but Phillip suggests a sharper commit message and a more precise explanation in the code comment.

The key point Phillip raises is that the current comment should explicitly cite overflow prevention (not just signature inertia) as the reason for the `cast_size_t_to_int()` helper. The commit that introduced the helper (937b71cc8b) fixed a crash caused by `size_t` overflow when converting to `int`, so the documentation should reflect that history. The patch is otherwise ready; it just needs a clearer message and a tweak to the in-code rationale. Once those are addressed, this will be the final word on the topic.
