This is the second patch in the v8 series introducing `--linearize` to `git replay`. It is a **pure refactoring** that moves the logic for resolving the replay base from `pick_regular_commit()` into its caller, `replay_revisions()`. The change reduces `pick_regular_commit()`'s parameters from five to four and consolidates base-selection logic in one place, improving maintainability and clarity. No behavior changes are introduced.

The patch updates `replay.c` to compute the replay base (`base`) upfront in `replay_revisions()`, using the helper functions `get_mapped_commit()` (introduced in patch 1/3) and `put_mapped_commit()`. The logic distinguishes between regular replay (where the base is either the replayed parent or `onto`) and revert replay (where the base is always `last_commit`). The commit message explains the motivation: bundling base-selection logic in one place reduces confusion about where the replay base is determined and prepares the ground for `--linearize` (implemented in patch 3/3).

Key technical details include the removal of the `onto` parameter from `pick_regular_commit()`, the introduction of a local `base` variable in `replay_revisions()`, and the preservation of the fallback to `last_commit` for revert mode. The patch is a prerequisite for `--linearize` but does not itself alter user-visible behavior. Feedback from earlier iterations (v2–v5) led to the reversion of an enum-based approach in favor of this simpler design, which was reviewed and approved by Justin Tobler and Patrick Steinhardt.
