This is a **substantive review** of the first patch in Patrick Steinhardt’s ODB abstraction series. Justin Tobler identifies a real-world edge case: repositories using a compatibility hash algorithm and alternates are currently broken because the loose-object map loading logic ignores the source-specific path and always falls back to the primary ODB’s `objects/` directory. The bug surfaces when multiple ODB sources exist (e.g., alternates) and the repository uses a non-default hash algorithm (SHA-256 with SHA-1 compatibility). Justin’s review confirms the fix is correct—it now loads the map from the source-specific path (`loose->base.path`)—and notes the mechanical improvement of removing the redundant `repo` parameter in favor of deriving it from the source. The patch touches `loose.c` and introduces no new symbols; the key change is replacing `repo_common_path_replace()` with `xstrfmt()` to construct the correct path. No test updates are included, but the fix is clearly motivated and addresses a latent bug in the ODB initialization sequence. The review depth is substantive: Justin traces the code path, identifies the broken scenario, and verifies the fix resolves it.
