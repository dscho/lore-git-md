This is a **bugfix** patch addressing a memory leak in `git merge` when `merge.defaultToUpstream` is enabled. The leak, present since 2011, occurs when `git merge` is called without arguments, triggering `setup_with_upstream()` to allocate an argument array that is never freed. Toon Claes’s patch fixes this by tracking the allocated array in a new variable (`argv_to_free`) and freeing it at the end of `cmd_merge()`. The fix is minimal, well-motivated, and includes a new test in `t/t7600-merge.sh` to prevent regression.

Jeff King (Peff) reviewed the patch and confirmed its correctness. He noted that the existing code’s argv-handling is "pretty gross" but acknowledged that a more extensive refactor (e.g., using a `strvec`) would be overkill for this isolated issue. His feedback is substantive but focused on the fix’s adequacy rather than suggesting broader changes.

The patch is unlikely to be controversial. It addresses a clear correctness issue without altering behavior, and the added test ensures the leak won’t resurface. The fix is isolated to `builtin/merge.c` and the test suite, making it a low-risk change. If you care about memory hygiene or the merge subsystem, this is worth a quick look—otherwise, it’s safe to skip unless you’re tracking every leak fix.
