This is the first patch in Tian Yuchen’s v2 series refactoring global configuration variables as part of the `the_repository` removal effort. It migrates `pack_size_limit_cfg` from a standalone global in `environment.c` into the repository-scoped `repo_config_values` struct.

The change is mechanical: the global variable is removed, the struct field is added, and the two call sites (`builtin/pack-objects.c` and `object-file.c`) are updated to read from the repository-specific instance. In `object-file.c`, the value is accessed via `the_repository`’s config to maintain backward compatibility, which aligns with the v2 design constraint that no silent fallbacks to `the_repository` should occur when `repo != the_repository`. No getter function is introduced because the call sites are limited and no hardcoded fallback values are needed.

The patch touches core subsystems (pack-objects and ODB transactions) but does not change behavior. It is infrastructure work for future libification, and the mechanical nature suggests existing tests should cover it. No review feedback has been posted yet, so the technical soundness remains unchallenged. If this patch lands cleanly, it sets a precedent for how similar migrations should handle backward compatibility.
