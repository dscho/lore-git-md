This is the core feature patch in Junio C Hamano’s four-part series introducing `git add --resolved`. The patch implements the new `--resolved` option, which stages only unmerged paths where conflict markers have been fully removed, leaving unrelated local changes untouched.

The implementation scans the index for unmerged paths, checks each for remaining conflict markers using the helper introduced in an earlier patch (`has_conflict_markers()`), and either stages the resolved paths or aborts with an error listing any files that still contain markers. The option respects pathspecs and handles edge cases like file deletions and binary files. It explicitly rejects combinations with `-u` or `-A` to avoid ambiguity.

The patch includes a thorough test script (`t/t2207-add-resolved.sh`) covering refusal to stage files with markers, success when all markers are removed, pathspec filtering, handling of deletions, and incompatibility with conflicting options. The commit message and code are clear and well-motivated, addressing a real workflow pain point for maintainers who frequently resolve conflicts while juggling unrelated local changes. This looks like a polished, production-ready feature that should attract attention from reviewers familiar with the merge and add subsystems.
