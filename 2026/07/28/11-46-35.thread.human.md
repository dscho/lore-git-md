This thread is about a security fix for Git for Windows that prevents credential exfiltration via symlink auto-detection. The vulnerability, assigned CVE-2026-32631, allows a malicious repository to leak a user's NTLMv2 hash by triggering an SMB connection to a UNC path or drive-less absolute path (e.g., `\attacker\share`). Johannes Schindelin authored the patch, which modifies `compat/mingw.c` to skip auto-detection for symlink targets starting with a backslash, defaulting to file symlinks and warning users to explicitly set `symlink=dir` in gitattributes for directory symlinks. The fix is already released in Git for Windows v2.53.0(3) and is Windows-specific, with no impact on other platforms.

Junio C Hamano has now queued the patch for upstream Git, though it’s unclear which integration branch (`seen`, `next`, or `master`) it’s in. The fix is uncontroversial and aligns with prior mitigations for similar vulnerabilities. There’s no discussion yet about backporting to older Git for Windows releases or adding automated test coverage, though the patch was validated with a manual proof-of-concept. The thread is effectively resolved from a technical standpoint, pending Junio’s merge.
