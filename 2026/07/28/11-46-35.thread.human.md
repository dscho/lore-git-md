This thread is about a **security bugfix for Git for Windows** that prevents credential exfiltration when cloning crafted repositories with symlinks enabled. Johannes Schindelin (Dscho) posted the patch via GitGitGadget to address a vulnerability (CVE-2026-32631) where Git for Windows could leak a user's NTLMv2 hash to a remote attacker via an SMB connection triggered by symlink auto-detection.

The fix modifies `compat/mingw.c` to skip auto-detection for symlink targets starting with a backslash (UNC paths or drive-less absolute paths), defaulting to file symlinks instead and warning users to set the `symlink` gitattribute to `dir` if needed. This matches the mitigation used for a similar MinTTY vulnerability (CVE-2025-66413). The patch is minimal, conservative, and already released in Git for Windows v2.53.0(3). It’s **Windows-specific** and doesn’t affect other platforms, though it’s high-priority due to its security implications. No test coverage is included, but the commit message details the attack vector and proof-of-concept scenario.
