This is the first patch in the v8 series introducing `--linearize` to `git replay`. It is a pure refactoring that extracts the logic for storing rewritten commits into a new helper function, `put_mapped_commit()`, and renames the existing `mapped_commit()` to `get_mapped_commit()` for symmetry.

The change is small and mechanical: the new `put_mapped_commit()` helper encapsulates the khash map insertion that was previously inlined in `replay_revisions()`, reducing code duplication and improving readability. The rename from `mapped_commit()` to `get_mapped_commit()` makes the pairing with the new function obvious. No behavior changes are introduced; this is preparatory work for the `--linearize` feature in patch 3/3.

The patch touches only `replay.c` and is well-motivated by the need to clean up the growing `replay_revisions()` function. The commit message is clear and the code changes are straightforward. This refactoring has been stable since v5, with no substantive feedback in later iterations. It looks ready to merge as part of the series.
