This thread introduces `git add --resolved`, a new option that stages only files whose conflict markers have been removed, making it easier to resolve merge conflicts without accidentally staging unrelated local changes. The series, now at version 2, is a four-patch effort by Junio C Hamano that consolidates duplicate conflict-marker detection logic, adds helper functions for index manipulation, and includes a performance tweak for binary files.

The core functionality is complete: the `--resolved` option scans the index for unmerged paths, checks each for remaining conflict markers, and stages resolved files while aborting with an error if any unresolved conflicts remain. Binary files and deletions are staged without marker checks. The series also refactors conflict-marker detection into a shared helper (`is_conflict_marker_line()`) and introduces a new index-removal helper (`remove_file_from_index_with_flags()`) that supports `--dry-run` and `--verbose` flags. All four patches have been updated in response to feedback, including a fix for a logic error in option incompatibility handling and the addition of a missing test script entry in `t/meson.build`.

The only remaining loose end was a test portability issue: the final `git checkout master` step in the test script assumed the default branch was named `master`, which isn’t always true. Junio’s self-review caught this, and the fix—using `git checkout @{-1}` to return to the previous branch—has been identified and will likely be incorporated in a future update. The rest of the series is technically sound, with no outstanding objections or open questions about the implementation itself. Michael Montalbo’s review identified and resolved the two substantive issues in the previous version, and the series is now awaiting further review or potential merge.
