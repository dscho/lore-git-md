This thread introduces `git add --resolved`, a new option that stages only files where merge conflicts have been fully resolved (i.e., conflict markers removed). The feature aims to prevent users from accidentally staging unrelated local changes during conflict resolution. Junio C Hamano posted the initial four-patch series (v1), which includes a refactoring of conflict-marker detection logic, a new helper for index removal with flags, the core `--resolved` implementation, and a whitespace-only style fix.

The series is under active review, with all patches fully described and reviewed. Michael Montalbo identified two technical issues in the third patch: a logic error in option incompatibility handling and a missing test script entry in `t/meson.build`. Junio has since addressed both in a follow-up, correcting the incompatibility check to `0 < addremove_explicit` and confirming the test script will be added to the build system. The core functionality remains unchanged, and these fixes are minor but necessary for correctness. No objections or conditional approvals have been recorded, and the series is now ready for a v2 update incorporating these adjustments. Open questions remain about edge cases like partially resolved conflicts and interaction with `--patch` mode, but the implementation is otherwise stable.
