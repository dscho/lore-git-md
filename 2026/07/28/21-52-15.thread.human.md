This thread introduces `git add --resolved`, a new feature by Junio C Hamano that lets users stage only files whose merge conflicts have been fully resolved (i.e., conflict markers removed). The series is now complete in its second version, addressing all prior feedback.

The feature works by scanning the index for unmerged paths matching the given pathspec, checking each file for remaining conflict markers, and staging only those that are clean. Binary files and deletions are staged without marker checks. The implementation is careful to avoid accidental staging of unrelated local changes, a common pain point during merge conflict resolution. Two preparatory patches refactored duplicate conflict-marker detection logic and added helper functions for index manipulation, while the final patch delivers the user-facing option with thorough test coverage.

Michael Montalbo’s review of the first version caught two technical issues—a logic error in option incompatibility handling and a missing test script entry—which Junio fixed in v2. The series is now under review for edge cases like partially resolved conflicts and interaction with `--patch`, but the core functionality is solid and the code is ready for closer scrutiny.
