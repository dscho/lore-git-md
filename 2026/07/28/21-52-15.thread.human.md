This thread is about Junio C Hamano’s patch series introducing `git add --resolved`, a new option to stage only files whose conflict markers have been removed after a merge conflict. The series is now at version 3, with all prior review feedback addressed—including a logic fix for option incompatibility, a portability tweak in the test script, and a performance optimization for binary files. The feature itself is technically complete, but two key discussions remain open.

First, there’s a design debate: Junio’s implementation treats `--resolved` as a monolithic operation, staging files only when *all* conflict markers are gone, while Michael Montalbo argues for incremental staging via a `--skip-conflict-markers` flag, allowing users to stage resolved files one by one. Junio defends the current approach as consistent with Git’s existing workflows (e.g., `git am --resolved`), but Montalbo’s proposal highlights a tension between strictness and flexibility in merge resolution workflows. Second, Jeff King (Peff) raised a usability concern: `--resolved` might create a false sense of completeness by staging only conflict-free files while ignoring related changes (like updates to callers of a modified function). Junio counters that Git’s merge machinery already prevents this by refusing to operate on locally modified paths, but the risk hasn’t been addressed in documentation or command output.

The latest email shifts focus to a broader architectural issue in Git’s option-parsing logic. Junio critiques the current pattern in `git add`, where the presence of flags (e.g., `-A`) is conflated with the behaviors they trigger (e.g., `addremove`), making the code harder to maintain. He suggests a future refactoring to separate these concerns, though this isn’t a blocker for the series. The thread is otherwise ready for integration, pending a minor correctness fix to the binary-file check in `has_conflict_markers()` and final clarity on the incremental staging debate. Key participants include Junio (author), Montalbo (reviewer pushing for incremental staging), and Peff (usability advocate).
