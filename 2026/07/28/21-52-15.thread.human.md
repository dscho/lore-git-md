This thread introduces `git add --resolved`, a new option that stages only files whose conflict markers have been fully removed, helping users avoid accidentally staging unrelated local changes during merge conflict resolution. The series, authored by Junio C Hamano, is now complete with all four patches posted as v1.

The first three patches lay the groundwork: they refactor conflict-marker detection into a shared helper, add a flexible index-removal function with support for dry-run and verbose modes, and implement the core `--resolved` logic. The fourth patch is a minor whitespace cleanup in `read-cache.c` that aligns with the project’s coding style. Tests cover refusal to stage files with remaining markers, success when all markers are removed, and handling of deletions, pathspecs, and option incompatibility.

No substantive reviews have arrived yet, so the series remains under initial review. Key open questions include how the feature handles partially resolved conflicts, its interaction with `--patch` mode, and whether the stricter conflict-marker rule is correct for all existing callers. The implementation touches several core files but makes no on-disk format changes.
