Junio’s `git add --resolved` series, which adds a new option to stage only files whose conflict markers have been removed, is now under review with all four patches described and a follow-up addressing two issues raised by Michael Montalbo. The series consolidates duplicate conflict-marker detection logic, adds a helper for index removal with flags, and introduces the core `--resolved` feature. A recent follow-up patch optimizes the `has_conflict_markers()` helper by adding an early exit for binary files, preventing unnecessary scans of large binaries. This tweak is uncontroversial and ready for integration, as it doesn’t change the core functionality but improves performance in edge cases.

The series is technically sound, with no on-disk format changes or new configuration keys. The new `git add --resolved` option scans the index for unmerged paths, checks for remaining conflict markers, and stages resolved files while aborting with an error for unresolved ones. Binary files and deletions are staged without marker checks. The stricter conflict-marker rule (requiring a space after `<<<<<<<` and `>>>>>>>`) has been consolidated into a single helper, and the `remove_file_from_index_with_flags()` helper supports `--dry-run` and `--verbose` flags. The test script `t/t2207-add-resolved.sh` covers key scenarios, including pathspecs and option incompatibility with `-u` and `-A`.

Michael Montalbo’s review identified two issues—a logic error in option incompatibility handling and a missing test script entry in `t/meson.build`—both of which were fixed in a follow-up. The only remaining open questions involve edge cases like partially resolved conflicts and interaction with `--patch` mode, but these are minor and don’t block integration. Junio has addressed all substantive feedback, and the series is now awaiting further review or maintainer action. The recent performance optimization for binary files further strengthens the case for merging.
