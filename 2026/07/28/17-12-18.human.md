This is the third patch in a seven-part feature series adding path-related keys to `` `git repo info` ``. The patch implements ``path.objects.absolute`` and ``path.objects.relative``, exposing the repository’s object database directory in both absolute and relative forms while respecting the ``GIT_OBJECT_DIRECTORY`` environment override.

Justin Tobler’s review raises two points. First, he suggests rewording the commit message to avoid over-specifying the use case (“Tools and deployment hooks” → “Scripts operating on a repository”) and to clarify what “legacy parsing methods” refers to. These are minor documentation nits and do not affect the code. Second, he questions whether exposing the object directory path is future-proof in light of Patrick Steinhardt’s pluggable ODB effort: if a non-filesystem ODB backend is introduced, the key might return an empty string or become misleading. Justin CC’d Patrick for input, but the patch itself is not blocked—this is a forward-looking design question rather than a mechanical issue.

The implementation is clean and follows the established pattern: two getter functions call ``repo_get_object_directory()`` and pass the result through ``format_path()``. Justin also asks whether the absolute path getter should ignore the prefix (passing an empty string instead of ``startup_info->prefix``), which would make the absolute nature of the path more explicit. This is a small stylistic choice and does not affect functionality.

The patch is ready for review; the only open questions are stylistic (commit message wording, prefix handling) and design-level (ODB compatibility). No substantive technical issues have been identified.
