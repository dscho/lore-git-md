This is a **design discussion follow-up** in the `git rebase --update-refs` symref bugfix thread. Junio C Hamano pushes back on Phillip Wood’s earlier clarification about Git’s permissiveness with HEAD pointing outside `refs/heads/`.

Junio acknowledges that the low-level `symbolic-ref` command (used for repair) allows HEAD to point anywhere under `refs/`, but argues that end-user commands like `git checkout` have long since been tightened to prevent users from creating such states in the first place. His question implies that the rebase logic might not need to handle these edge cases robustly if they’re already considered invalid or broken configurations. This challenges the premise of the current patch series, which assumes such symrefs are valid and must be handled correctly.

The exchange doesn’t block the v3 series (which remains under review), but it introduces a potential shift in direction: if the project agrees these configurations are invalid, future revisions might simplify the code by rejecting them outright rather than accommodating them. For now, the series’ approach—using `resolved_ref` for HEAD comparison—still aligns with Git’s documented behavior, but Junio’s skepticism suggests this could become a point of contention in v4 or later.
