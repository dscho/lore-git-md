Core problem or goal
A credential exfiltration vulnerability in Git for Windows allows a crafted repository with symlinks enabled to leak the user's NTLMv2 hash to a remote attacker. The attack vector involves symlink type auto-detection triggering an SMB connection to a UNC path or drive-less absolute path (e.g., `\attacker\share`), exposing credentials. The fix aims to close this leak while preserving existing functionality for non-malicious symlinks.

Current status
Patch posted as a standalone security fix; already released in Git for Windows v2.53.0(3). **Queued in Junio's integration branches (branch unspecified)**. CVE-2026-32631 assigned. The fix is Windows-specific and does not affect other platforms.

Key technical details
- **Files touched**: `compat/mingw.c` (Windows compatibility layer)
- **Function modified**: `process_phantom_symlink()`
- **New behavior**: Skips auto-detection for symlink targets starting with a backslash (UNC paths or drive-less absolute paths), defaulting to file symlinks and emitting a warning. Users must explicitly set `symlink=dir` in gitattributes for directory symlinks.
- **Edge cases addressed**: Drive-less absolute paths (e.g., `\path\to\dir`) are treated as UNC paths to prevent credential exposure.
- **On-disk format**: No changes; the fix is runtime behavior only.
- **Test coverage**: None included in the patch; commit message references a proof-of-concept scenario.
