Subject: [PATCH 0/4] git add --resolved
Series version: v1 (initial submission)
Originating author: Junio C Hamano
Thread type: patch series (feature addition)

Core problem or goal
Introduce a `git add --resolved` option that stages only paths whose conflict markers have been removed, allowing users to resolve merge conflicts without accidentally staging unrelated local changes. The series consolidates duplicate conflict-marker detection logic and adds a helper for index removal with flags.

Current status
Under review; v1 posted. All four patches are now fully described and reviewed: (1) refactoring of conflict-marker detection logic into `is_conflict_marker_line()` in `merge-ll.c`, (2) introduction of `remove_file_from_index_with_flags()` in `read-cache.c`, (3) the core `--resolved` feature in `builtin/add.c`, and (4) a whitespace-only reindentation of `skip_submodule()` in `read-cache.c` (pure style fix, no behavior change). The first three patches implement the feature and its supporting infrastructure; the fourth is a routine cleanup. Michael Montalbo’s substantive review identified two actionable issues: a logic error in `die_for_incompatible_opt3()` that misclassifies `--no-all` and `--ignore-removal` as incompatible with `--resolved`, and a missing `t/meson.build` entry for the new test script `t/t2207-add-resolved.sh`.

Key technical details
- New command-line option: `git add --resolved`
- New helpers:
  - `is_conflict_marker_line()` in `merge-ll.c` (header `merge-ll.h`), replacing duplicate implementations in `diff.c` and `rerere.c`; stricter rule requires space after `<<<<<<<` and `>>>>>>>` markers
  - `remove_file_from_index_with_flags()` in `read-cache.c` (header `read-cache-ll.h`), supporting `--dry-run` (`ADD_CACHE_PRETEND`) and `--verbose` (`ADD_CACHE_VERBOSE`) flags for index removals
  - `has_conflict_markers()` in `merge-ll.c`, used by `--resolved` to scan file content for remaining conflict markers
- Files touched: `merge-ll.c`, `merge-ll.h`, `read-cache.c`, `read-cache-ll.h`, `builtin/add.c`, `diff.c`, `rerere.c`, `Documentation/git-add.txt`, `t/t2207-add-resolved.sh`, `t/meson.build`
- New test script: `t/t2207-add-resolved.sh` covers refusal to stage files with markers, success when all markers are removed, ignoring unconflicted modified files, handling deletions, pathspecs, and option incompatibility with `-u` and `-A`
- No on-disk format changes; no new config keys or environment variables
- Conflict-marker helper returns marker character (`<`, `=`, `>`, or `|`) to distinguish marker types
- `--resolved` scans the index for unmerged paths, checks each for remaining conflict markers, stages resolved paths, or aborts with an error listing unresolved ones; binary files and deletions are staged as resolved without marker checks
- Whitespace patch reindents `skip_submodule()` in `read-cache.c` to match surrounding style; no logic changes

Open questions and loose ends
- Edge cases: partially resolved conflicts (some markers remain), interaction with `--patch` mode, behavior when no conflicts exist
- Reviewers should verify:
  - Stricter conflict-marker rule is correct for all callers (`diff.c`, `rerere.c`)
  - Consolidation of conflict-marker logic is complete (no remaining duplicates)
  - `remove_file_from_index_with_flags()` behaves correctly with edge-case flag combinations (e.g., both `--dry-run` and `--verbose` set, or path not in index)
  - `--resolved` logic handles partially resolved conflicts and `--patch` interaction as expected
  - The two issues raised by Michael Montalbo: (1) `die_for_incompatible_opt3()` logic in `builtin/add.c` must distinguish `--no-all` and `--ignore-removal` from `--all` (condition should be `0 < addremove_explicit`), and (2) `t/t2207-add-resolved.sh` must be added to `t/meson.build` for test discovery
