Core problem or goal
Introduce a `git add --resolved` option that stages only paths whose conflict markers have been removed, allowing users to resolve merge conflicts without accidentally staging unrelated local changes. The series consolidates duplicate conflict-marker detection logic, adds helpers for index removal with flags, and includes a targeted performance optimization for binary files. The conceptual design of the option is now under discussion: whether `--resolved` should remain a monolithic operation or be split into a more general `--unmerged` selector with explicit policy overrides for conflict markers.

Current status
Under review; v2 posted with all four patches updated. The series is technically complete and addresses all prior review feedback from Michael Montalbo (logic error in option incompatibility handling, missing test script entry in `t/meson.build`, and portability fix for the test script). The v2 update also added a performance optimization for binary files. The current discussion centers on the user-facing interface: Michael Montalbo has proposed an alternative design that decouples the selection of unmerged paths from the conflict-marker safety check, suggesting `--unmerged` as a more general selector with explicit policy flags like `--allow-conflict-markers` or `--skip-conflict-markers`.

Key technical details
- New command-line option: `git add --resolved` (design now under discussion; alternative `--unmerged` proposed)
- New helpers:
  - `is_conflict_marker_line()` in `merge-ll.c` (header `merge-ll.h`), replacing duplicate implementations in `diff.c` and `rerere.c`; stricter rule requires space after `<<<<<<<` and `>>>>>>>` markers; returns marker character (`<`, `=`, `>`, or `|`) to distinguish marker types
  - `remove_file_from_index_with_flags()` in `read-cache.c` (header `read-cache-ll.h`), supporting `--dry-run` (`ADD_CACHE_PRETEND`) and `--verbose` (`ADD_CACHE_VERBOSE`) flags for index removals
  - `has_conflict_markers()` in `merge-ll.c`, used by `--resolved` to scan file content for remaining conflict markers; includes an early-exit check for binary files using `buffer_is_binary()`
- Files touched: `merge-ll.c`, `merge-ll.h`, `read-cache.c`, `read-cache-ll.h`, `builtin/add.c`, `diff.c`, `rerere.c`, `Documentation/git-add.txt`, `t/t2207-add-resolved.sh`, `t/meson.build`
- New test script: `t/t2207-add-resolved.sh` covers refusal to stage files with markers, success when all markers are removed, ignoring unconflicted modified files, handling deletions, pathspecs, and option incompatibility with `-u` and `-A`; updated in v2 to use `git checkout @{-1}` instead of `git checkout master` for portability
- No on-disk format changes; no new config keys or environment variables
- Conflict-marker helper returns marker character to distinguish marker types
- `--resolved` scans the index for unmerged paths, checks each for remaining conflict markers, stages resolved paths, or aborts with an error listing unresolved ones; binary files and deletions are staged as resolved without marker checks
- Whitespace patch reindents `skip_submodule()` in `read-cache.c` to match surrounding style; the misindented block was introduced in commit a16c4a245a (February 2026) when `--force` support for `ignore=all` submodules was added
- Bugfix in v2: `die_for_incompatible_opt3()` in `builtin/add.c` now uses `0 < addremove_explicit` (not `0 <= addremove_explicit`); `t/meson.build` updated to include `t/t2207-add-resolved.sh`
- Performance tweak in v2: `has_conflict_markers()` in `merge-ll.c` exits early if `buffer_is_binary()` detects binary content, avoiding unnecessary I/O and processing

Open questions and loose ends
- Design decision: whether `--resolved` should remain a monolithic operation or be split into a more general `--unmerged` selector with explicit policy flags for conflict markers (e.g., `--allow-conflict-markers` or `--skip-conflict-markers`). Michael Montalbo’s review argues that the current design conflates selection (unmerged paths) with policy (conflict-marker check), and that decoupling them would make the command more flexible and the naming more precise.
- Edge cases: partially resolved conflicts (some markers remain), interaction with `--patch` mode, behavior when no conflicts exist. The implementation handles partially resolved conflicts by aborting with an error listing unresolved paths, and `--patch` mode is explicitly incompatible (enforced by `die_for_incompatible_opt3()`). Behavior when no conflicts exist is to do nothing (no error, no staging), which is documented in `git-add.txt`.
- Reviewers should verify:
  - Stricter conflict-marker rule is correct for all callers (`diff.c`, `rerere.c`)
  - Consolidation of conflict-marker logic is complete (no remaining duplicates)
  - `remove_file_from_index_with_flags()` behaves correctly with edge-case flag combinations (e.g., both `--dry-run` and `--verbose` set, or path not in index)
  - `--resolved` logic handles deletions and binary files as expected (staged without marker checks)
  - The two issues raised by Michael Montalbo in v1 are resolved: (1) option incompatibility logic is fixed, and (2) test script is discoverable via Meson
  - The performance tweak in `has_conflict_markers()` does not alter behavior and correctly identifies binary files
  - The test script portability fix (`git checkout @{-1}`) works in all environments (repositories using `main` or other default branch names)
  - Whether the proposed `--unmerged` design (with policy flags) would better align the interface with the underlying implementation
