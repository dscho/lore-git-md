Core problem or goal
Introduce a `git add --resolved` option that stages only paths whose conflict markers have been removed, allowing users to resolve merge conflicts without accidentally staging unrelated local changes. The series consolidates duplicate conflict-marker detection logic, adds helpers for index removal with flags, and includes a targeted performance optimization for binary files.

Current status
Under review; v2 posted with all four patches updated. The series is technically complete: (1) whitespace-only reindentation of `skip_submodule()` in `read-cache.c` (preparatory cleanup, no logic changes), (2) refactoring of conflict-marker detection into `is_conflict_marker_line()` in `merge-ll.c` (replacing duplicate implementations in `diff.c` and `rerere.c` with a stricter rule requiring space after `<<<<<<<` and `>>>>>>>` markers; returns marker character `<`, `=`, `>`, or `|` to distinguish types), (3) introduction of `remove_file_from_index_with_flags()` in `read-cache.c` (supporting `--dry-run` and `--verbose` flags), and (4) the core `--resolved` feature in `builtin/add.c` (with early exit for binary files, mutual exclusivity with `-u` and `-A`, and comprehensive test coverage in `t/t2207-add-resolved.sh`). The v2 update addresses the two issues raised by Michael Montalbo: a logic error in `die_for_incompatible_opt3()` (fixing the condition from `0 <= addremove_explicit` to `0 < addremove_explicit`) and the missing `t/meson.build` entry for `t/t2207-add-resolved.sh`. It also adds a performance optimization to `has_conflict_markers()` to skip binary files early using `buffer_is_binary()`. Junio’s self-review of the test script in patch 4/4 identified a portability issue: the final `git checkout master` step hardcoded the branch name, which may not exist in all repositories. The fix replaces it with `git checkout @{-1}`, which checks out the previous branch regardless of its name, making the test more robust.

Key technical details
- New command-line option: `git add --resolved`
- New helpers:
  - `is_conflict_marker_line()` in `merge-ll.c` (header `merge-ll.h`), replacing duplicate implementations in `diff.c` and `rerere.c`; stricter rule requires space after `<<<<<<<` and `>>>>>>>` markers; returns marker character (`<`, `=`, `>`, or `|`) to distinguish marker types
  - `remove_file_from_index_with_flags()` in `read-cache.c` (header `read-cache-ll.h`), supporting `--dry-run` (`ADD_CACHE_PRETEND`) and `--verbose` (`ADD_CACHE_VERBOSE`) flags for index removals
  - `has_conflict_markers()` in `merge-ll.c`, used by `--resolved` to scan file content for remaining conflict markers; now includes an early-exit check for binary files using `buffer_is_binary()`
- Files touched: `merge-ll.c`, `merge-ll.h`, `read-cache.c`, `read-cache-ll.h`, `builtin/add.c`, `diff.c`, `rerere.c`, `Documentation/git-add.txt`, `t/t2207-add-resolved.sh`, `t/meson.build`
- New test script: `t/t2207-add-resolved.sh` covers refusal to stage files with markers, success when all markers are removed, ignoring unconflicted modified files, handling deletions, pathspecs, and option incompatibility with `-u` and `-A`; updated in v2 to use `git checkout @{-1}` instead of `git checkout master` for portability
- No on-disk format changes; no new config keys or environment variables
- Conflict-marker helper returns marker character to distinguish marker types
- `--resolved` scans the index for unmerged paths, checks each for remaining conflict markers, stages resolved paths, or aborts with an error listing unresolved ones; binary files and deletions are staged as resolved without marker checks
- Whitespace patch reindents `skip_submodule()` in `read-cache.c` to match surrounding style; the misindented block was introduced in commit a16c4a245a (February 2026) when `--force` support for `ignore=all` submodules was added
- Bugfix in v2: `die_for_incompatible_opt3()` in `builtin/add.c` now uses `0 < addremove_explicit` (not `0 <= addremove_explicit`); `t/meson.build` updated to include `t/t2207-add-resolved.sh`
- Performance tweak in v2: `has_conflict_markers()` in `merge-ll.c` exits early if `buffer_is_binary()` detects binary content, avoiding unnecessary I/O and processing

Open questions and loose ends
- Edge cases: partially resolved conflicts (some markers remain), interaction with `--patch` mode, behavior when no conflicts exist. The implementation handles partially resolved conflicts by aborting with an error listing unresolved paths, and `--patch` mode is explicitly incompatible (enforced by `die_for_incompatible_opt3()`). Behavior when no conflicts exist is to do nothing (no error, no staging), which is documented in `git-add.txt`.
