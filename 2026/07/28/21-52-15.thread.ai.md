Core problem or goal
Introduce a `git add --resolved` option that stages only paths whose conflict markers have been removed, allowing users to resolve merge conflicts without accidentally staging unrelated local changes. The series consolidates duplicate conflict-marker detection logic, adds helpers for index removal with flags, and includes a targeted performance optimization for binary files.

Current status
Under review; v1 posted with two follow-ups: (1) a bugfix addressing option incompatibility logic and missing test script entry (Michael Montalbo), and (2) a performance tweak to `has_conflict_markers()` that exits early for binary files. All four original patches remain unchanged in behavior. The series is now technically complete: (1) refactoring of conflict-marker detection into `is_conflict_marker_line()` in `merge-ll.c`, (2) introduction of `remove_file_from_index_with_flags()` in `read-cache.c`, (3) the core `--resolved` feature in `builtin/add.c`, and (4) a whitespace-only reindentation of `skip_submodule()` in `read-cache.c`. The follow-ups correct a logic error in `die_for_incompatible_opt3()`, add the missing `t/meson.build` entry for `t/t2207-add-resolved.sh`, and optimize `has_conflict_markers()` to avoid scanning binary files.

Key technical details
- New command-line option: `git add --resolved`
- New helpers:
  - `is_conflict_marker_line()` in `merge-ll.c` (header `merge-ll.h`), replacing duplicate implementations in `diff.c` and `rerere.c`; stricter rule requires space after `<<<<<<<` and `>>>>>>>` markers
  - `remove_file_from_index_with_flags()` in `read-cache.c` (header `read-cache-ll.h`), supporting `--dry-run` (`ADD_CACHE_PRETEND`) and `--verbose` (`ADD_CACHE_VERBOSE`) flags for index removals
  - `has_conflict_markers()` in `merge-ll.c`, used by `--resolved` to scan file content for remaining conflict markers; now includes an early-exit check for binary files using `buffer_is_binary()`
- Files touched: `merge-ll.c`, `merge-ll.h`, `read-cache.c`, `read-cache-ll.h`, `builtin/add.c`, `diff.c`, `rerere.c`, `Documentation/git-add.txt`, `t/t2207-add-resolved.sh`, `t/meson.build`
- New test script: `t/t2207-add-resolved.sh` covers refusal to stage files with markers, success when all markers are removed, ignoring unconflicted modified files, handling deletions, pathspecs, and option incompatibility with `-u` and `-A`
- No on-disk format changes; no new config keys or environment variables
- Conflict-marker helper returns marker character (`<`, `=`, `>`, or `|`) to distinguish marker types
- `--resolved` scans the index for unmerged paths, checks each for remaining conflict markers, stages resolved paths, or aborts with an error listing unresolved ones; binary files and deletions are staged as resolved without marker checks
- Whitespace patch reindents `skip_submodule()` in `read-cache.c` to match surrounding style; no logic changes
- Bugfix follow-up: `die_for_incompatible_opt3()` in `builtin/add.c` now uses `0 < addremove_explicit` (not `0 <= addremove_explicit` or `addremove`); `t/meson.build` updated to include `t/t2207-add-resolved.sh`
- Performance follow-up: `has_conflict_markers()` in `merge-ll.c` exits early if `buffer_is_binary()` detects binary content, avoiding unnecessary I/O and processing
