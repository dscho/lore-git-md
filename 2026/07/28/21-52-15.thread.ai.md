Core problem or goal
Introduce a `git add --resolved` option that stages only paths whose conflict markers have been removed, allowing users to resolve merge conflicts without accidentally staging unrelated local changes. The series also consolidates duplicate conflict-marker detection logic and adds a helper for index removal with flags.

Current status
Under review; v1 posted. Four patches: (1) refactoring of conflict-marker detection logic into a shared helper in `merge-ll.c`, (2) introduction of `remove_file_from_index_with_flags()` in `read-cache.c`, (3) the core `--resolved` feature in `builtin/add.c`, and (4) a whitespace cleanup. The first patch has been detailed in the new email; the remaining three await substantive review.

Key technical details
- New command-line option: `git add --resolved`
- New helper: `remove_file_from_index_with_flags()` in `read-cache.c` (supports `--dry-run` and `--verbose`)
- Consolidated conflict-marker detection logic: `is_conflict_marker_line()` in `merge-ll.c` (header `merge-ll.h`), replacing duplicate implementations in `diff.c` and `rerere.c`
- Stricter conflict-marker rule: requires a space after `<<<<<<<` and `>>>>>>>` markers, matching Git’s conflict output format
- Files touched: `merge-ll.c`, `merge-ll.h`, `read-cache.c`, `builtin/add.c`, `diff.c`, `rerere.c`
- New test script: `t/t2207-add-resolved.sh`
- No on-disk format changes; no new config keys or environment variables
- New helper returns marker character (`<`, `=`, `>`, or `|`) to distinguish marker types
