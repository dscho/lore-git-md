This is a review of the fourth patch in K Jayatheerth’s seven-patch series adding path-related keys to `git repo info`. The patch introduces `path.hooks.absolute` and `path.hooks.relative`, which expose the repository’s hooks directory location, respecting `core.hooksPath` overrides. Justin Tobler’s review raises a substantive edge-case question about how to handle the special `/dev/null` value for `core.hooksPath`, which disables hooks entirely.

The current implementation returns `/dev/null` when that is the configured hooks path, matching `git rev-parse --git-path hooks` behavior. Justin questions whether this makes sense for the relative-path variant (`path.hooks.relative`) and suggests special-casing `/dev/null` to return an empty string instead. This is a forward-looking design question: while the current behavior is consistent with existing Git tools, it may not be the most intuitive or useful for scripts that expect a filesystem path. The review is substantive but narrowly scoped to this edge case; the rest of the patch is mechanically clean and well-documented.

The thread context shows this series is otherwise ready for broader review, with only minor mechanical nits and a larger open question about ODB abstraction compatibility remaining. This specific review does not block the series but adds another small design decision to resolve before merging. If the `/dev/null` handling is clarified, the patch will likely proceed without further controversy.
