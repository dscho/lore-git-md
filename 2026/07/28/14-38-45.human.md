This is the second patch in Jeff King’s two-part series fixing test failures in `t0014-alias.sh` when `WITH_BREAKING_CHANGES=1` is enabled. The patch makes the test future-proof by dynamically generating the list of deprecated commands instead of hardcoding `whatchanged` and `pack-redundant`. If no deprecated commands exist (as will be the case after Git 3.0 removes them), the relevant tests are skipped via a new `HAVE_DEPRECATED` prereq.

The change is small and surgical: it replaces the hardcoded variables with a helper that queries Git for its list of deprecated commands, then sets the prereq if at least two are found. This prevents the test from failing when stale build artifacts (like old `git-whatchanged` hardlinks) are present, which was the root cause of the original failures. The patch does not touch the `t1517-outside-repo.sh` failures, which remain unaddressed but are acknowledged as a separate issue.

The approach is pragmatic and low-risk. It avoids the need to manually update the test when deprecated commands are removed, while maintaining coverage for the alias-handling logic that will still exist post-3.0. The prereq ensures the test gracefully degrades rather than failing, which is especially useful for CI environments where clean builds aren’t always guaranteed. The patch looks well-crafted and directly addresses the thread’s core problem.
