This is a build configuration report from brian m. carlson about test failures when `WITH_BREAKING_CHANGES=1` is enabled in `config.mak`.

With `WITH_BREAKING_CHANGES=1` set alongside other common developer options (Rust support, Clang, Asciidoctor), two test scripts fail: `t0014-alias.sh` (tests 4 and 8) and `t1517-outside-repo.sh` (tests 248 and 249). The failures disappear when the breaking-changes flag is removed, so the issue is clearly tied to that option. Brian notes that the project has a CI job for this configuration, yet it apparently does not catch these failures, raising questions about test coverage. The report is a heads-up for anyone working on or reviewing patches that depend on `WITH_BREAKING_CHANGES`; he plans to send a series based on that option and wants the test suite to pass first.
