This thread began when brian m. carlson reported test failures in `t0014-alias.sh` and `t1517-outside-repo.sh` when building Git with `WITH_BREAKING_CHANGES=1`, a configuration flag expected to see more use as the project prepares for Git 3.0. The root cause was quickly identified: stale build artifacts (`git-whatchanged` and `git-pack-redundant` executables) left from prior builds. These executables are no longer built when `WITH_BREAKING_CHANGES=1` is enabled, but if they remain in the build directory, the test suite treats them as external commands, triggering alias-loop detection logic that causes the failures.

Jeff King (Peff) submitted a two-patch series that fully resolves the `t0014-alias.sh` failures. The fix dynamically generates the list of deprecated commands used in the test from `git --list-cmds=deprecated`, rather than hardcoding them, and introduces a `HAVE_DEPRECATED` prereq to skip the tests if fewer than two deprecated commands are available. This makes the test resilient to future changes in the set of deprecated commands and to stale build artifacts. Junio C Hamano reviewed and accepted the series, and Peff confirmed the approach is the correct solution for the transitional period before Git 3.0. The `t1517-outside-repo.sh` failures remain unaddressed but are acknowledged as a separate issue caused by stale build artifacts; a clean build (`make clean` or `git clean -xdf`) is expected to resolve them. The discussion has concluded that no further changes to `t1517` are needed beyond ensuring clean builds in CI and local testing environments.

The thread is now settled. Brian m. carlson acknowledged Peff’s patches as sensible, and no further discussion or changes are expected. The key takeaway for developers is that `WITH_BREAKING_CHANGES=1` may expose stale build artifacts as test failures, and a clean build is the recommended mitigation for `t1517-outside-repo.sh`. The `t0014-alias.sh` fix is already in place and will handle the transitional period leading up to Git 3.0 gracefully.
