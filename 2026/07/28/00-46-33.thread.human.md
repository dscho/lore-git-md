This thread is about test failures that occur when building Git with `WITH_BREAKING_CHANGES=1`, a configuration flag expected to see more use as contributors prepare for Git 3.0. The failures affect two test scripts—`t0014-alias.sh` and `t1517-outside-repo.sh`—and are caused by stale build artifacts (`git-whatchanged` and `git-pack-redundant` executables) left over from prior builds. These executables are no longer built when `WITH_BREAKING_CHANGES=1` is enabled, but if they remain in the build directory, the test suite treats them as external commands, triggering alias-loop detection logic that causes the failures.

The root cause was identified early in the thread, with Jeff King (Peff) providing a detailed explanation of why the failures occur. The discussion has since shifted to how to handle this limbo state before Git 3.0. Peff has now proposed a two-patch series to fix the `t0014-alias.sh` failures by dynamically generating the list of deprecated commands used in the test, rather than hardcoding them. This makes the test more robust as deprecated commands are removed in future Git versions. The patches are confined to the test script and do not touch core Git logic. Peff notes that the `t1517-outside-repo.sh` failures, which are also caused by stale build artifacts, are unrelated and left for future work.

The thread has involved key participants like brian m. carlson (who reported the issue), Junio C Hamano, Phillip Wood, and Peff. The proposed fix is unlikely to be controversial, though it doesn’t address all the test failures—just the ones in `t0014`. The next steps are to review Peff’s patches and decide whether similar improvements are needed for `t1517`. The issue doesn’t block brian’s upcoming patch series, as the failures are build-system artifacts rather than regressions in Git’s logic.
