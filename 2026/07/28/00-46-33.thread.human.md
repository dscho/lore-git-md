This thread began when brian m. carlson reported test failures in `t0014-alias.sh` and `t1517-outside-repo.sh` when building Git with `WITH_BREAKING_CHANGES=1`, a configuration flag expected to see more use as the project prepares for Git 3.0. The root cause turned out to be stale build artifacts—specifically, leftover `git-whatchanged` and `git-pack-redundant` executables from prior builds. These binaries are no longer built when `WITH_BREAKING_CHANGES` is enabled, but if they remain in the build directory, the test suite treats them as external commands, triggering alias-loop detection logic that causes the failures.

Jeff King (Peff) has now submitted a complete two-patch series to fix the `t0014-alias.sh` failures. The first patch refactored the test to use variables for deprecated command names, and the second dynamically generates the list of deprecated commands using `git --list-cmds=deprecated`, skipping the relevant tests if no deprecated commands are available. This makes the test resilient to both future changes in the set of deprecated commands and to stale build artifacts that could otherwise cause false positives in CI or local testing. The `t1517-outside-repo.sh` failures remain unaddressed but are acknowledged as a separate issue caused by the same stale artifacts; Peff has suggested generating that test’s command list from the Makefile as a potential follow-up. For now, the discussion has shifted to ensuring CI and local testing environments use clean builds to avoid such issues. No impact on brian’s upcoming patch series is expected, as the failures are not regressions in Git’s logic but artifacts of the build system.
