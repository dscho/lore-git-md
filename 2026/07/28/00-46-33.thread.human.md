This thread began when brian m. carlson reported test failures under the `WITH_BREAKING_CHANGES=1` build configuration, a flag expected to see increased use as contributors prepare for Git 3.0. The failures were traced to stale build artifacts and a build system issue where `WITH_BREAKING_CHANGES` was read too late to affect the list of binaries to build. Jeff King (Peff) quickly submitted a two-patch series to fix the failing tests by making them resilient to future changes in the set of deprecated commands, and Junio merged this series. Brian then submitted a follow-up patch to address the underlying build system issue by moving the inclusion of `config.mak` earlier in the Makefile, which Junio also merged.

However, Peff has now identified a serious flaw in this approach: moving the `include` directives too early breaks the Makefile’s last-one-wins behavior for variables like `CFLAGS`, potentially masking build misconfigurations. He also points out pre-existing fragility in the Makefile’s handling of Rust-related variables, which cannot be overridden by `config.mak` settings. The thread is now focused on resolving this build system issue, with Peff proposing a more targeted solution—extracting the `git-whatchanged` line from `BUILT_INS` and handling it conditionally later in the Makefile—to avoid disrupting the broader Makefile logic. Brian’s patch will likely need revision, and the discussion has shifted from the resolved test failures to the underlying build system design.
