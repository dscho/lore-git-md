This thread began when brian m. carlson reported test failures in `t0014-alias.sh` and `t1517-outside-repo.sh` when building Git with `WITH_BREAKING_CHANGES=1`, a configuration flag expected to see more use as contributors prepare for Git 3.0. The root cause was stale build artifacts—specifically, leftover `git-whatchanged` and `git-pack-redundant` executables from prior builds—that interfered with test expectations once those commands were no longer built under the breaking-changes flag.

Jeff King (Peff) quickly diagnosed the issue and submitted a two-patch series to fix the `t0014-alias.sh` failures. The first patch refactored the test to use variables for deprecated command names, and the second dynamically generates the list of deprecated commands from `git --list-cmds=deprecated`, introducing a `HAVE_DEPRECATED` prereq to skip the tests if fewer than two deprecated commands are available. Junio C Hamano reviewed and accepted the series, and the final exchange in the thread confirms the fix is complete and unlikely to need further revision. The `t1517-outside-repo.sh` failures, also caused by stale build artifacts, remain unaddressed but are acknowledged as a separate issue; a clean build (`make clean` or `git clean -xdf`) is expected to resolve them. The discussion has shifted to ensuring CI and local testing environments avoid false positives by using clean builds, with no further changes planned for the test suite at this time.
