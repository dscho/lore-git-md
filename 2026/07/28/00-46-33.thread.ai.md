Thread identity: Build configuration report regarding test failures with `WITH_BREAKING_CHANGES=1` in `config.mak`. Originating author: brian m. carlson. Thread type: bug report / regression notice.

Core problem or goal: Identify and document test suite failures that occur when `WITH_BREAKING_CHANGES=1` is enabled, a build configuration flag expected to see increased use as contributors prepare for Git 3.0. The failures affected `t0014-alias.sh` (tests 4 and 8) and `t1517-outside-repo.sh` (tests 248 and 249), and were caused by stale build artifacts (`git-whatchanged` and `git-pack-redundant` executables) left from prior builds. These executables are no longer built when `WITH_BREAKING_CHANGES=1` is enabled, but if they remain in the build directory, the test suite treats them as external commands, triggering alias-loop detection logic that caused the failures. The underlying build system issue—configuration settings like `WITH_BREAKING_CHANGES` being read *after* the list of binaries to build is generated—has been resolved by brian m. carlson's patch, which moves the inclusion of `config.mak` earlier in the Makefile to ensure the flag takes effect at the correct time.

Current status: **Fully resolved and merged to `master`**.
