Thread identity: Build configuration report regarding test failures with `WITH_BREAKING_CHANGES=1` in `config.mak`. Originating author: brian m. carlson. Thread type: bug report / regression notice.

Core problem or goal: Identify and document test suite failures that occur when `WITH_BREAKING_CHANGES=1` is enabled, a build configuration flag expected to see increased use as contributors prepare for Git 3.0. The failures were caused by stale build artifacts (`git-whatchanged` and `git-pack-redundant` executables) left from prior builds, combined with a build system dependency-ordering issue where `WITH_BREAKING_CHANGES=1` was read too late to affect the list of binaries to build. The underlying build system issue—ensuring `WITH_BREAKING_CHANGES` is honored correctly while preserving the Makefile's variable precedence model—remains open and contested.

Current status: **Test failures resolved, but build system fix is flawed and contested**. The thread began with brian m. carlson's report of test failures under `WITH_BREAKING_CHANGES=1`, which were traced to stale build artifacts and a build system dependency-ordering issue. Jeff King (Peff) submitted a two-patch series to fix the `t0014-alias.sh` failures by dynamically generating the list of deprecated commands from `git --list-cmds=deprecated` and introducing the `HAVE_DEPRECATED` prereq, making the test resilient to future changes in the set of deprecated commands. Junio C Hamano merged this series, and the test failures are resolved. The `t1517-outside-repo.sh` failures were confirmed to be caused by stale build artifacts; a clean build resolved them, but the root cause was addressed by brian's follow-up patch, which moved the inclusion of `config.mak` earlier in the Makefile to ensure `WITH_BREAKING_CHANGES=1` is respected during initial build target generation. Junio merged this patch to `master` on 2025-07-10, but Peff has since identified a **serious flaw** in the approach: moving the `include` directives too early breaks the Makefile's last-one-wins behavior for variables like `CFLAGS`, potentially masking build misconfigurations. Peff also highlights pre-existing fragility in the Makefile—specifically, the `RUST_LIB_NAME` and `RUST_BUILD_CONFIG` logic, which appears before the `config.mak` includes and thus cannot be overridden by `config.mak` settings like `NO_RUST`. The thread is now focused on resolving this build system design issue; brian's patch will likely need revision to avoid disrupting the Makefile's variable precedence model.
