Thread identity: Build configuration report regarding test failures with `WITH_BREAKING_CHANGES=1` in `config.mak`. Originating author: brian m. carlson. Thread type: bug report / regression notice.

Core problem or goal: Identify and document test suite failures that occur when `WITH_BREAKING_CHANGES=1` is enabled, a build configuration flag expected to see increased use as contributors prepare for Git 3.0. The failures affected `t0014-alias.sh` (tests 4 and 8) and `t1517-outside-repo.sh` (tests 248 and 249), and were caused by stale build artifacts (`git-whatchanged` and `git-pack-redundant` executables) left from prior builds. These executables are no longer built when `WITH_BREAKING_CHANGES=1` is enabled, but if they remain in the build directory, the test suite treats them as external commands, triggering alias-loop detection logic that caused the failures.

Current status: Root cause identified and **fully resolved for both `t0014-alias.sh` and `t1517-outside-repo.sh`**. Jeff King (Peff) submitted a two-patch series that fixes the `t0014-alias.sh` failures by dynamically generating the list of deprecated commands used in the test from `git --list-cmds=deprecated`, rather than hardcoding them. The series is now settled: Junio C Hamano acknowledged the approach, and Peff confirmed the `HAVE_DEPRECATED` prereq (which skips the tests if fewer than two deprecated commands are available) is the correct solution for the transitional period before Git 3.0. The patches may be squashed for clarity, but the technical outcome is final. The `t1517-outside-repo.sh` failures are confirmed to be caused by stale build artifacts; a clean build (`make clean` or `git clean -xdf`) resolves them, and no further changes to the test are needed. The discussion has concluded that the issue is fully addressed, with no remaining action items beyond ensuring clean builds in CI and local testing environments.
