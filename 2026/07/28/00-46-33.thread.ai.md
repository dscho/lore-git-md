Thread identity: Build configuration report regarding test failures with `WITH_BREAKING_CHANGES=1` in `config.mak`. Originating author: brian m. carlson. Thread type: bug report / regression notice.

Core problem or goal: Identify and document test suite failures that occur when `WITH_BREAKING_CHANGES=1` is enabled, a build configuration flag expected to see increased use as contributors prepare for Git 3.0. The failures affect `t0014-alias.sh` (tests 4 and 8) and `t1517-outside-repo.sh` (tests 248 and 249), and are caused by stale build artifacts (`git-whatchanged` and `git-pack-redundant` executables) left from prior builds. These executables are no longer built when `WITH_BREAKING_CHANGES=1` is enabled, but if they remain in the build directory, the test suite treats them as external commands, triggering alias-loop detection logic that causes the failures.

Current status: Root cause identified and fully addressed for `t0014-alias.sh`. Jeff King (Peff) has submitted a two-patch series that fixes the `t0014-alias.sh` failures by dynamically generating the list of deprecated commands used in the test from `git --list-cmds=deprecated`, rather than hardcoding them. The first patch refactored `t0014-alias.sh` to use variables (`deprecated1` and `deprecated2`) for the deprecated command names, making the test more maintainable. The second patch completes the fix by generating the list dynamically and introducing a `HAVE_DEPRECATED` prereq to skip the tests if no deprecated commands are available. The `t1517-outside-repo.sh` failures remain unaddressed but are acknowledged as a separate issue caused by stale build artifacts. The discussion has shifted to ensuring CI and local testing environments avoid false positives by using clean builds. No prereq-based skipping of tests has been implemented for `t1517`, and the focus remains on making tests resilient to build environment changes.
