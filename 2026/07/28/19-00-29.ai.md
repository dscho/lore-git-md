This is a substantive review of the fourth patch in the `git repo info` path-keys series. Justin Tobler raises a design question about how the new `path.hooks` keys should handle the special `/dev/null` value for `core.hooksPath`. Currently, the patch returns `/dev/null` verbatim (matching `git rev-parse --git-path hooks` behavior), but Justin questions whether this makes sense for the relative-path variant and suggests returning an empty string instead. He notes that `git rev-parse` always returns an absolute path for `/dev/null`, regardless of the `--path-format` flag, and wonders if the series should follow suit or deviate by treating `/dev/null` as a special case. This is a forward-looking edge-case concern that could affect script compatibility if not resolved consistently. The review is substantive but does not block the patch; it invites discussion on the intended behavior rather than identifying a bug.
