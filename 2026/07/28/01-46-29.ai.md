This is the first patch in Tian Yuchen’s v2 series refactoring global configuration variables as part of the `the_repository` removal effort. It migrates `pack_size_limit_cfg` from a standalone global in `environment.c` into the `repo_config_values` struct, making it repository-scoped. The change is mechanical: the global variable is removed, the struct field is initialized to zero in `repo_config_values_init()`, and all direct references are updated to use the repository-specific instance.

The patch touches four files: `builtin/pack-objects.c` (one caller), `environment.c` (variable storage and initialization), `environment.h` (struct definition), and `object-file.c` (ODB transaction logic). No getter function is introduced due to the limited number of call sites (only two), and backward compatibility is maintained by accessing the value via `the_repository` in `object-file.c`. The ODB transaction logic in `object-file.c` is the most subtle part—it checks whether the pack size limit would be exceeded during object streaming and flushes the packfile if needed. The change here is straightforward but worth noting for future edge-case testing.

This patch is uncontested so far and aligns with the v2 design constraint established in the thread: no silent fallbacks to `the_repository` when `repo != the_repository`. The mechanical nature of the changes suggests existing tests should cover the behavior, though the ODB transaction logic in `object-file.c` might benefit from explicit verification. The patch sets the stage for the second patch in the series, which migrates `assume_unchanged` in a similar fashion.
