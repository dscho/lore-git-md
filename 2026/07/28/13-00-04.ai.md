This is a bugfix patch that plugs a memory leak in `git merge` when the `merge.defaultToUpstream` configuration is enabled.

The patch addresses a long-standing leak (present since 2011) in `builtin/merge.c`. When `git merge` is called without arguments and `merge.defaultToUpstream` is true, the function `setup_with_upstream()` allocates an argument array that is never freed. Toon Claes fixes this by tracking the allocated array in a new variable (`argv_to_free`) and freeing it at the end of `cmd_merge()`. The fix is minimal and targeted, touching only the necessary lines in `builtin/merge.c`.

The patch also adds a test in `t/t7600-merge.sh` to exercise the default-to-upstream path, which previously went untested. The test fails under the leak sanitizer without the fix, confirming the leak's presence and the fix's effectiveness. The commit message provides clear context: the leak was discovered when running `yay` (an AUR helper for Arch Linux) with a leak-sanitized Git build, as `yay` calls `git merge` without arguments.

The patch is well-motivated and self-contained, with a clear reproduction case and a straightforward fix. The leak is small but persistent, and the test ensures it won’t regress. The change is unlikely to be controversial, as it only addresses a correctness issue without altering behavior. The code touches the merge subsystem, but the fix is isolated to the leaky allocation path.
