This is a **substantive review follow-up** in the ongoing `git rebase --update-refs` symref bugfix thread. Phillip Wood responds to Junio C Hamano’s design question about whether the rebase logic should assume HEAD always points to a branch or robustly handle edge cases like symrefs to tags.

Phillip clarifies that Git has *always* allowed HEAD to point to any ref under `refs/` (not just branches), citing commit e9cc02f0e4 from 2009. While he hasn’t tested it, he believes the rebase code already handles non-branch HEADs correctly. He acknowledges the tension between robustness and simplicity, noting that some users (like Caleb on Discord) have been surprised by Git’s permissiveness here. The implication is that the current patch’s approach—using `resolved_ref` for HEAD comparison—is the correct one, even if it complicates the code slightly, because it aligns with Git’s long-standing behavior and avoids breaking valid (if unusual) configurations.

This exchange doesn’t block the v3 series but frames a broader design choice for future work. The next revision (v4) will likely adopt Phillip’s suggestion to use `resolved_ref` for HEAD comparison, along with the explanatory comment and test tweaks he requested earlier. The latent `head_ref` buffer clobbering bug (unrelated to this patch) remains unaddressed and may become a separate follow-up.
