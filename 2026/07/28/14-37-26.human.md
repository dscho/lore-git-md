This is the first patch in a two-part **test infrastructure** series from Jeff King (Peff) that addresses test failures in `t0014-alias.sh` when `WITH_BREAKING_CHANGES=1` is enabled. The patch factors out the hardcoded names of deprecated commands ("whatchanged" and "pack-redundant") into variables (`deprecated1` and `deprecated2`) to prepare for a follow-up change that will dynamically generate this list from the Makefile. The refactoring is purely mechanical and does not alter test behavior, but it makes the test more maintainable as deprecated commands are removed in future Git versions (including Git 3.0).

The patch is part of a broader effort to make the test suite resilient to build environment changes, particularly the "limbo state" introduced by `WITH_BREAKING_CHANGES`. The failures it targets occur when stale build artifacts (like `git-whatchanged` and `git-pack-redundant` executables) from prior builds interfere with test expectations. While this patch does not yet solve the dynamic generation problem, it lays the groundwork by eliminating hardcoded assumptions about which commands are deprecated. The commit message is clear, and the diff is straightforward, though Peff notes the change is noisy enough to warrant its own patch.

This is a well-scoped, uncontroversial refactoring that aligns with the thread’s goal of preventing false positives in CI and local testing. The second patch in the series will complete the fix by replacing the hardcoded list with a dynamic one. No objections or alternative approaches are expected, as the change is purely preparatory.
