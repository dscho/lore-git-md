This is the third patch in Patrick Steinhardt’s ODB abstraction series, and Justin Tobler’s reply raises a design question about the initialization sequence.

The patch defers object database (ODB) creation by splitting the current `create_object_directory()` into two steps: `get_object_directories()` to capture environment variables, and `create_object_database()` to instantiate the ODB and create on-disk directories. A new flag, `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION`, allows `apply_repository_format()` to skip ODB creation, leaving the repository in a partially-initialized state until `create_object_database()` is called later.

Justin’s question is whether it would be simpler to make `odb_new()` an explicit step after `apply_repository_format()` in all cases, rather than introducing a flag to conditionally skip ODB creation. He notes there are not many call sites, so the change might not be burdensome. This is a substantive review comment—it challenges the patch’s approach and suggests an alternative design. The question is well-placed, as it touches on the clarity and maintainability of the initialization sequence, which is central to the series’ goal of making ODB backends pluggable. No answer from Patrick yet, so the discussion remains open.
