This thread introduces a new configuration option, `pack.allowDuplicateObjects`, and a corresponding command-line flag for `git index-pack` to allow clients to accept packfiles containing duplicate objects. The feature is motivated by real-world scenarios where servers stream objects from overlapping packs, which can be more efficient than deduplicating at request time but currently triggers Git's strict validation checks.

The patch, posted by friel@openai.com as an RFC, is well-structured and thoroughly tested. It adds the new configuration knob (defaulting to `false`) and a command-line override (`--[no-]allow-duplicate-objects`), while preserving backward compatibility—explicit `--strict` or `--verify` flags still reject duplicates, and the default behavior remains unchanged. The implementation is conservative, opting users in rather than changing default behavior, and includes extensive test coverage for edge cases like configuration overrides, connectivity checks, and integration with `git clone`.

The patch builds on an existing topic (`tb/pack-with-duplicates`) and is unlikely to be controversial, given its narrow scope and opt-in nature. The author is seeking feedback on the approach, particularly around the interaction between the new flag and existing strictness checks, though the current design explicitly forbids combining `--allow-duplicate-objects` with `--strict` or `--verify`. The feature does not affect delta resolution or the on-disk format, focusing solely on pack validation. So far, no reviews or objections have been posted, leaving the design and implementation open for discussion.
