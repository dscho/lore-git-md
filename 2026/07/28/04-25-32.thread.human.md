This thread is an RFC patch introducing `pack.allowDuplicateObjects`, a new configuration and command-line flag for `git index-pack` that allows Git to accept packfiles containing duplicate objects when explicitly enabled. The patch, authored by friel@openai.com, targets servers that stream objects from overlapping packs, aiming to improve performance without sacrificing safety—duplicates are rejected by default and remain so under `--strict` or `--verify`.

Taylor Blau, a key contributor with deep expertise in the pack subsystem, has provided the first substantive review. His feedback centers on a design question: whether the new flag should be a strict override (as currently implemented) or a carve-out from `--strict`. The current design makes `--allow-duplicate-objects` incompatible with `--strict`/`--verify`, but Taylor suggests an alternative where the flag would disable *only* the duplicate-object check while preserving all other strict validation. This would better align with use cases like `git clone`, where users might want to accept duplicates but still enforce other safety checks. He also notes minor documentation and test improvements, such as clarifying the scope of connectivity checks and streamlining the test suite.

The patch itself remains well-motivated and technically sound, with no fundamental objections raised. The discussion is now focused on refining the interface, particularly the interaction with `--strict`, which the author will need to address in a follow-up version. The series is still under initial review, with no prior versions or integration status, and the implementation is self-contained and ready for further feedback.
