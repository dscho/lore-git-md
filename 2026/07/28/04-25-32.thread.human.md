This thread is an RFC patch series proposing `pack.allowDuplicateObjects` and a corresponding `git index-pack --[no-]allow-duplicate-objects` flag to let Git accept packfiles containing duplicate objects when explicitly configured. The author, friel@openai.com, initially framed this as a performance optimization for servers streaming objects from overlapping packs, but the discussion has since shifted toward a more fundamental question: whether Git should ever allow invalid packfiles, even as an opt-in exception.

The thread has attracted substantive feedback from Junio C Hamano and Taylor Blau. Junio objects on principle, arguing that duplicate objects violate Git’s integrity guarantees and should never be stored, while Taylor counters that Git already tolerates duplicates in non-strict `index-pack`, shallow clones, and filtered clones, making this a pragmatic extension rather than a new risk. The author has since agreed with Junio’s suggestion that duplicates should be deduplicated *during* `index-pack` rather than stored, reframing the feature as a way to prevent duplicates from proliferating. Taylor’s latest reply reinforces this direction, proposing that lightweight deduplication during the fetch/clone stream could address Junio’s concerns without requiring a full repack.

The patch touches `builtin/index-pack.c`, adds a new configuration knob (`pack.allowDuplicateObjects`), and introduces a command-line flag for `git index-pack`. The current design uses a tri-state enum to make `--allow-duplicate-objects` incompatible with `--strict`/`--verify`, but Taylor has proposed a narrower override that would only relax the duplicate-OID check in `--strict` mode. The proposed deduplication approach would eliminate the need for an opt-in exception entirely, aligning with Junio’s philosophical objection but requiring significant changes to the patch’s interface and test suite.

Key open questions remain: whether deduplication should be automatic or opt-in, how to handle edge cases like delta resolution and connectivity checks, and whether the feature should remain configurable. The discussion is now centered on refining the implementation to deduplicate during indexing, with Taylor and the author collaborating on the next steps. No consensus has been reached on the broader question of whether Git should eventually reject duplicates in *all* `index-pack` modes, but the tone remains constructive and focused on practical trade-offs.
