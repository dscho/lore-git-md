This thread is an RFC patch proposing `pack.allowDuplicateObjects`, a configuration and command-line flag to allow Git to accept packfiles containing duplicate objects during `git index-pack`. The feature is opt-in (defaulting to `false`) and targets performance bottlenecks for servers streaming objects from overlapping packs. The patch, authored by friel@openai.com, has sparked a philosophical debate about Git’s integrity guarantees.

Taylor Blau has been the most engaged reviewer, providing substantive feedback on the design and implementation. He initially suggested refining the interaction between `--allow-duplicate-objects` and `--strict` mode, proposing that the flag should selectively disable only the duplicate-object check while preserving other validation. In his latest reply, Taylor pushes back against Junio C Hamano’s broader objection, arguing that Git’s internals are already hardened against duplicates (via his earlier `tb/pack-with-duplicates` series) and that the feature can be scoped narrowly to address Junio’s concerns. He frames the feature as a pragmatic trade-off, noting that duplicate objects can sometimes contain the only copy of an object a user needs, and proposes a design where `--allow-duplicate-objects` would relax only the duplicate-OID check in `--strict` mode.

Junio, however, remains skeptical, framing the feature as a slippery slope that could complicate Git’s internals and undermine repository integrity. He references a past discussion with Shawn Pearce to support his position that Git should reject invalid packfiles outright, even as an opt-in exception. The thread is now at a crossroads: Junio’s philosophical objection must be addressed, either by refining the design to satisfy his concerns or by demonstrating that the performance trade-offs are unavoidable and well-contained. The ball is in Junio’s court to respond to Taylor’s arguments or clarify why the hardened internals and narrower scope still violate Git’s principles. The patch itself touches `builtin/index-pack.c`, adds a new test file (`t/t5308-pack-detect-duplicates.sh`), and introduces a configuration knob (`pack.allowDuplicateObjects`) and command-line flag (`--[no-]allow-duplicate-objects`). No prior versions exist, and the series remains under review with no integration status.
