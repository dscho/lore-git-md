This is the maintainer's acknowledgment of the second patch in Jeff King's two-patch series fixing `t0014-alias.sh` test failures under `WITH_BREAKING_CHANGES=1`. Junio C Hamano confirms the logic behind the new `HAVE_DEPRECATED` prereq: it guards tests that require at least two deprecated commands to exercise alias-loop detection between them. With fewer than two deprecated commands available, those tests become meaningless and are now skipped. The patch itself dynamically generates the list of deprecated commands using `git --list-cmds=deprecated`, making the test resilient to future changes in the set of deprecated commands (such as their eventual removal in Git 3.0) and to stale build artifacts that previously caused false positives.

The change is confined to `t/t0014-alias.sh` and introduces no new symbols or on-disk format changes. It directly addresses the root cause identified earlier in the thread: stale `git-whatchanged` and `git-pack-redundant` executables left over from prior builds, which the test suite treated as external commands, triggering alias-loop detection logic. The prereq-based skipping is a pragmatic solution for the transitional state of `WITH_BREAKING_CHANGES`, where deprecated commands are no longer built but may still linger in the build directory. Junio's reply signals acceptance of the approach; the patch is well-scoped, unlikely to be controversial, and completes the fix for the `t0014` failures. The remaining `t1517-outside-repo.sh` failures (also caused by stale build artifacts) are acknowledged as a separate issue not addressed by this series.
