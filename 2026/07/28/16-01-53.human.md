This is the maintainer's ack for the second patch in Jeff King's series fixing `t0014-alias.sh` test failures under `WITH_BREAKING_CHANGES=1`. Junio C Hamano confirms the logic behind the new `HAVE_DEPRECATED` prereq: it ensures the tests that require at least two deprecated commands (to test alias loops between them) are only run when such commands exist. The patch dynamically generates the list of deprecated commands using `git --list-cmds=deprecated`, making the test resilient to future changes in which commands are deprecated.

The patch is straightforward and well-motivated, addressing the root cause of the test failures (stale build artifacts triggering alias-loop detection) while also future-proofing the test for Git 3.0, when the current deprecated commands (`whatchanged` and `pack-redundant`) will be removed. Junio's ack signals this patch is ready for integration; it will likely be queued in `next` soon. The remaining issue with `t1517-outside-repo.sh` (also caused by stale build artifacts) is acknowledged as a separate problem and not addressed here. The series as a whole is a pragmatic solution to prevent false positives in CI and local testing environments where `WITH_BREAKING_CHANGES` is used.
