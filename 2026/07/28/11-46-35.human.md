This is a security-focused platform compatibility patch for Git for Windows. Johannes Schindelin addresses a credential exfiltration vulnerability (CVE-2026-32631) where cloning a malicious repository with symlinks enabled could leak the user's NTLMv2 hash to an attacker-controlled SMB server. The issue stems from Git for Windows' auto-detection of symlink types, which triggers network connections for UNC paths (e.g., `\\attacker\share`).

The fix skips auto-detection for any symlink target starting with a backslash (a reliable indicator of UNC paths or uncommon drive-less absolute paths), defaulting to file symlinks instead. A warning is emitted to guide users who need directory symlinks to set the `symlink` gitattribute explicitly. This follows the same mitigation pattern used for a similar vulnerability (CVE-2025-66413) in Git for Windows.

The patch touches only `compat/mingw.c` and is minimal in scope, adding 23 lines of defensive logic. It was already released in Git for Windows v2.53.0(3), indicating it has undergone testing in that context. The commit message is thorough, explaining the attack vector, the trade-offs (e.g., handling rare drive-less paths), and the relationship to prior work.

This is a targeted fix for a real security issue, not a speculative hardening measure. The change is unlikely to be controversial, though users with unusual symlink setups may need to adjust their workflows. The patch is specific to Windows and does not affect other platforms.
