This is a performance inquiry about `fetch.bundleURI`. Ryszard Knop reports that using Git bundles to seed a clone in a CI pipeline is unexpectedly slow—taking 4–5 minutes, which is comparable to or even slower than a standard full clone of the Linux kernel repository (3–4 minutes). The bottleneck appears to be `git index-pack`, which consumes 100% CPU for most of the operation.

The workflow involves initializing a new repository, configuring `fetch.bundleURI` to point to a pre-generated bundle, and then fetching a specific ref from the remote. While this approach is conceptually elegant for reducing load on the remote server, the observed performance suggests that bundle unpacking may not be optimized for this use case. The email does not include benchmarking details beyond wall-clock times, but the focus on `index-pack` hints at a potential inefficiency in how bundles are processed during fetches.

For readers following Git performance, this is worth noting if they rely on bundles for similar scenarios. The thread invites discussion about whether this slowness is expected or if there might be room for optimization in the bundle-fetch path. No patches or proposed fixes are included—this is purely a question about current behavior.
