This thread is about a small but long-standing memory leak in `git merge` that occurs when the `merge.defaultToUpstream` configuration is enabled. Toon Claes discovered the issue while running a leak-sanitized Git build with `yay` (an Arch Linux AUR helper), which calls `git merge` without arguments. The leak has been present since 2011 and stems from an allocated argument array in `setup_with_upstream()` that was never freed.

Toon’s patch fixes the leak by tracking the allocated array in a new variable (`argv_to_free`) and freeing it at the end of `cmd_merge()`. The fix is minimal, touching only `builtin/merge.c`, and includes a new test in `t/t7600-merge.sh` to ensure the default-to-upstream path is exercised and the leak doesn’t regress. The patch is well-motivated, self-contained, and unlikely to be controversial, as it addresses a correctness issue without altering behavior. No reviews or objections have been posted yet, so the patch is still under initial consideration.
