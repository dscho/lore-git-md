This thread is about a small but long-standing memory leak in `git merge` when the `merge.defaultToUpstream` configuration is enabled and the command is run without arguments. Toon Claes posted a patch that fixes the leak by ensuring the argument array allocated in `setup_with_upstream()` is properly freed. The fix is self-contained, touches only `builtin/merge.c` and adds a test in `t/t7600-merge.sh`, and doesn’t change any behavior—just plugs the leak.

Jeff King (Peff) reviewed the patch and confirmed both the leak and the fix are correct. He noted the surrounding code is a bit awkward—specifically how `argv` is manipulated after allocation—but called a larger refactor "micro-polishing" not worth the effort. His feedback signals the patch is on solid ground, though the code’s messiness might be revisited later. For now, the fix is minimal and well-motivated, with no open objections or requests for changes.
