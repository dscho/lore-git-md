This is a new feature series introducing `git add --resolved`, authored by Junio C Hamano. The goal is to streamline the workflow of resolving merge conflicts by allowing users to stage only conflict-resolved paths while leaving unrelated local changes untouched. The series consists of four patches: two preliminary refactorings, the core feature implementation, and a whitespace-only cleanup.

The first patch consolidates conflict-marker detection logic into a single helper in `merge-ll.c`, replacing duplicate implementations in `diff.c` and `rerere.c`. The second patch adds a new helper function, `remove_file_from_index_with_flags()`, to simplify removing paths from the index with support for `--dry-run` and `--verbose` options. The third patch implements the `--resolved` option for `git add`, which stages only files with resolved conflicts, identified by the absence of conflict markers. The fourth patch is a whitespace-only reindentation in `read-cache.c`.

The feature is motivated by Junio’s observation that maintainers frequently resolve conflicts while also having unrelated local changes in their working tree. The current `git add -u` stages all changes, which is not ideal in this scenario. The new `--resolved` option addresses this by targeting only conflict-resolved paths. The series includes a new test script, `t/t2207-add-resolved.sh`, which validates the feature’s behavior.

The implementation touches several subsystems: `merge-ll.c` (conflict marker logic), `read-cache.c` (index manipulation), `builtin/add.c` (command logic), and `diff.c`/`rerere.c` (cleanup of redundant code).
