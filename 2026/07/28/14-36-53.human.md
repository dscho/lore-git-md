This is a **test infrastructure** patch series from Jeff King (Peff) that addresses the test failures reported in the `WITH_BREAKING_CHANGES=1` thread. The series focuses on `t0014-alias.sh`, which fails when stale build artifacts (like `git-whatchanged` and `git-pack-redundant`) are present in the build directory. These executables are no longer built when `WITH_BREAKING_CHANGES=1` is enabled, but if they linger from prior builds, the test suite treats them as external commands, triggering alias-loop detection logic that causes the failures.

The series consists of two patches. The first refactors `t0014-alias.sh` to factor out the choice of deprecated commands, making the test more maintainable. The second patch goes further by generating the list of deprecated command names dynamically, rather than hardcoding them. This ensures the test stays in sync with the build system and avoids relying on stale artifacts. Peff notes that this approach also prepares the test for future deprecations, as it will automatically adapt to whatever commands are no longer built.

Peff explicitly does not address the `t1517-outside-repo.sh` failures in this series, as those are not directly tied to deprecation but rather to the test's reliance on a static list of commands (`git --list-cmds`). He suggests that test could be improved by generating its command list from the Makefile instead, but that’s left for future work.

The patches look well-crafted and directly target the root cause of the `t0014` failures. They avoid the need for a prereq to skip tests when `WITH_BREAKING_CHANGES=1` is enabled, instead making the test robust against build pollution. This is a cleaner solution for the limbo period before Git 3.0, where contributors are increasingly using this configuration. The series is small, focused, and unlikely to be controversial.
