This is a **bugfix for the pack-bitmap subsystem**, addressing an off-by-one edge case where objects at bitmap position zero were incorrectly excluded from being recognized as already represented in the base bitmap. The patch is now in its second iteration (`v2`), incorporating feedback from Taylor Blau’s **substantive review** of the initial version.

The core fix remains unchanged: adjusting the conditional check in `find_objects()` from `pos > 0` to `pos >= 0` to correctly handle objects at position zero. The commit message and code comment have been reworded to clarify that the redundant work avoided is not necessarily a duplicate disk read (since bitmaps are often already loaded in memory) but rather unnecessary bitmap reloads or additions to the not-mapped list. This aligns with Taylor’s technical explanation of the bitmap traversal logic.

The most significant update in `v2` is the addition of a **new test case** covering the non-pseudo-merge scenario, as requested by Taylor. The test uses `git rev-list --objects --use-bitmap-index HEAD HEAD` to verify that objects at position zero are correctly recognized after stored bitmaps, even outside the pseudo-merge context. This expands test coverage beyond the original pseudo-merge assertion, addressing the sole remaining gap identified in the review.

The patch touches `pack-bitmap.c` (core bitmap traversal logic) and `t/t5333-pseudo-merge-bitmaps.sh` (test file). Key symbols involved include `bitmap_position()`, `find_objects()`, and the `SEEN` flag. The behavior change is internal-only: the resulting object set remains identical, but the fix eliminates redundant work during bitmap traversal.
