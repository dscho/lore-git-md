This is a **bugfix** patch for the `git cat-file --batch-command` assertion failure, now **queued for `next`** by Junio C Hamano. The patch, authored by Jeff King (Peff), resolves a NULL-dereference crash in `print_object_or_die()` when the `contents` command is issued without `%(objecttype)` in the format string. The fix is minimal: it temporarily overrides `data->info.typep` to point to `data->type` during the `contents` command, then restores the original value to avoid unnecessary type metadata lookups for subsequent `info` commands. This preserves performance while fixing the crash.

The patch includes a new test in `t1006-cat-file.sh` that verifies the crash no longer occurs and that the output matches `--batch` mode. Junio’s reply explicitly marks the topic for `next`, indicating it is ready for integration testing. The fix is uncontroversial, aligns with prior feedback from Alan Stokes and Pablo Sabater, and addresses a core plumbing command regression present since Git 2.43.0.

Key technical details: the change is confined to `builtin/cat-file.c` (3 lines added) and the test suite, with no new symbols or behavior changes beyond resolving the crash. The workaround of including `%(objecttype)` in the format string or using `--batch` instead of `--batch-command` is no longer necessary.
