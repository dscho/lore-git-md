Thread type: patch series (Rustification cleanup)

Core problem or goal
Fix memory leaks and uninitialized memory risks in the Rust bindings for Git’s C hash functions. The issues occur when non-default block algorithms (e.g., OpenSSL) are used, leading to crashes or leaks at the Rust/C boundary. The series ensures proper initialization and cleanup of the C hash context.

Current status
Under review; no prior versions. Patch 1/2 fixes uninitialized memory in `CryptoHasher::clone`; patch 2/2 plugs a memory leak in the `Drop` implementation for `CryptoHasher` by calling `git_hash_discard`. Both patches are confined to `src/hash.rs` and introduce no behavior or API changes.

Key technical details
Files touched: `src/hash.rs`
New or renamed symbols: `git_hash_discard` (C function, now declared in Rust FFI)
Behavior changes: none (pure memory hygiene)
On-disk format changes: none
Test coverage: existing Rust unit tests exercise the drop path more thoroughly; no new tests added in this series
Technical specifics: Patch 1/2 ensures `git_hash_init` is called before cloning the C context; patch 2/2 adds `git_hash_discard` to the `Drop` implementation to release crypto library state. Jeff King (Peff) reviewed the approach and rejected an alternative (making `git_hash_clone()` work without prior initialization) as unnecessarily complicating callers and risking new leaks.

Open questions and loose ends
None identified. The series is expected to be uncontroversial and merge-ready after addressing any minor Rust-specific feedback.
