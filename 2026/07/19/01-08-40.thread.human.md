This thread is a two-patch Rust cleanup series from brian m. carlson, fixing memory leaks and uninitialized memory risks in Git’s Rust hash bindings. The issues only surface when non-default block algorithms like OpenSSL are used, causing crashes or leaks at the Rust/C boundary. The first patch (already summarized) addressed uninitialized memory in `CryptoHasher::clone`; this second patch plugs a leak in the same layer by ensuring the crypto library’s internal context is properly released when the Rust `CryptoHasher` is dropped.

The fixes are straightforward and confined to `src/hash.rs`, with no behavior changes or new APIs. The series is a direct follow-up to Jeff King’s recent C-side leak fixes in the same area, and brian describes both patches as uncontroversial and merge-ready. No substantive review has landed yet, but the changes are small, well-scoped, and backed by Rust’s leak sanitizer tests.
