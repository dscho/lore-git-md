This is the second patch in a two-part Rustification cleanup series from brian m. carlson, rounding out the memory-safety fixes for the Rust hash bindings. It plugs a leak that occurs when the Rust `CryptoHasher` is dropped without freeing the underlying C crypto context—something the default block code happens to handle, but OpenSSL and other backends do not.

The fix is a one-line addition to the `Drop` implementation: `git_hash_discard` is called before `git_hash_free` to ensure the crypto library’s internal state is properly released. The patch also adds a small test helper (`h3`) to exercise the clone-and-drop path, verifying that the leak is gone when run under the leak sanitizer.

The change is confined to `src/hash.rs` and is purely about memory hygiene; no new APIs or behavior changes are introduced. Given the author’s track record and the fact that this is a direct follow-up to Jeff King’s recent C-side leak fixes, the patch looks uncontroversial and ready for a quick review.
