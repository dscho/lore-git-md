This is a two-patch Rustification cleanup series from brian m. carlson, targeting the Rust hash code that wraps Git’s C hashing layer. The patches address memory leaks and uninitialized memory risks in the Rust bindings for Git’s hash functions, specifically when non-default block algorithms are in use.

The series is a direct follow-up to Jeff King’s recent C-side leak fixes in the same area. Patch 1 ensures the C hash context is fully initialized before Rust clones it, preventing potential use of uninitialized memory. Patch 2 adds explicit cleanup of the hash context when Rust is done with it, plugging a leak that would otherwise persist until process exit.

The changes are confined to `src/hash.rs` and are small (11 insertions, 2 deletions). No new APIs or behavior changes are introduced; this is purely about correctness and memory hygiene in the Rust/C boundary layer. The commit messages are concise but clear about the problem and the fix.

Given the author and the context (a follow-up to Peff’s leak fixes), this looks like a well-scoped, uncontroversial cleanup. The patches are likely to be merged once they receive a cursory review.
