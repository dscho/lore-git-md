Subject: [PATCH] send-email: add filesystem path completion for patch files
Series version: standalone patch (v1 posted, v2 anticipated)
Originating author: Yury Norov (NVIDIA) <yury.norov@gmail.com>
Thread type: patch series (single-patch)

Core problem or goal
Extend bash completion for `git send-email` to include filesystem paths for patch files when the user’s prefix could match both a revision identifier (commit hash, branch, tag) and a patch file (e.g., `0` in a directory containing `0001-*.patch`). The problem is now framed as a usability trade-off: whether offering both refs and patch files in the same completion list improves or degrades the user experience. The discussion has shifted from the original trigger (a 14-year-old Git tag with a purely hexadecimal name) to broader design principles, with examples like `0-branch`, `0-tag`, and `0001.patch` illustrating the underlying logic.

Current status
Under review; v1 posted, v2 anticipated. The core implementation (`__gitcomp_file_append()` helper) remains uncontested, but the patch’s necessity is now debated on usability grounds. Junio’s feedback resolved the initial stalemate over problem validity by proposing a revised commit message and more realistic test cases, but SZEDER Gábor’s review introduces a counterargument: shorter, focused completion lists (offering only refs) are more usable, and users can still trigger filesystem completion explicitly (e.g., via `./<TAB>`, `<ALT-/>`, or `-- <TAB>`). The test robustness issue (placement of `test_when_finished` block) remains unresolved but is expected to be addressed in v2. The thread awaits Yury’s v2, which will need to reconcile these usability concerns with the original goal.

- Files touched: `contrib/completion/git-completion.bash`, `t/t9902-completion.sh`
- New helper: `__gitcomp_file_append()` appends filesystem candidates to the existing completion list without disrupting revision completion; uses `compgen -f` and follows the established pattern of `__gitcompadd`/`__gitcompappend`
- Behavior change: `git send-email <TAB>` now offers both patch files and refs (branches, tags) when they share a prefix, but this is contested on usability grounds
- Test coverage: regression test in `t/t9902-completion.sh` verifies that both patch files and refs are offered; Junio proposes expanding the test to include more realistic cases (`0001.patch`, `0-tag`, `0-branch`) to address artificial-test-case concerns. The `test_when_finished` block placement issue remains unresolved.
- Implementation details: the Bash 3 file-mode hack (from 2013) remains applicable; the completion script does not expand abbreviated object names to full hashes (contrary to the original commit message’s claim)
- Real-world trigger: a 14-year-old Git tag (`05c69d298c96...`) with a purely hexadecimal name, but the discussion now focuses on broader usability principles
