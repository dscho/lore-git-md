Subject: [PATCH] send-email: add filesystem path completion for patch files

Core problem or goal
The bash completion script for `git send-email` currently only completes revision identifiers (commit hashes, branch names, etc.). When a user types a prefix that matches both a revision and a patch file (e.g., `0` in a directory containing `0001-*.patch`), the script offers only the revision, not the patch file. The goal is to extend the completion to include filesystem paths for patch files alongside existing revision completion.

Current status
Under review; v1 posted. Junio C Hamano provided surface-level feedback on test robustness and naming style but no substantive objections to the core logic. Awaiting input from completion-script experts.

Key technical details
- Files touched: `contrib/completion/git-completion.bash`, `t/t9902-completion.sh`
- New helper: `__gitcomp_file_append()` appends filesystem candidates to the existing completion list without disrupting revision completion
- Behavior change: `git send-email <TAB>` now offers both patch files and 40-hex refs when they share a prefix
- Test coverage: regression test in `t/t9902-completion.sh` verifies that both patch files and 40-hex refs are offered; Junio identified a test-script robustness issue (the `test_when_finished` block should be registered *before* creating the tag and files to ensure cleanup happens even if setup fails)
- Implementation details: `__gitcomp_file_append()` uses `compgen -f` to generate file candidates and follows the established pattern of `__gitcompadd`/`__gitcompappend`; the Bash 3 file-mode hack (from 2013) remains applicable

Open questions and loose ends
- Test robustness: Junio requested the `test_when_finished` block be moved earlier in the test setup.
- Naming style: Junio mildly criticized the use of a purely hexadecimal tag name as unnecessarily ambiguous, though he acknowledged the bug should be fixed regardless.
- Commit message wording: D. Ben Knoble suggests replacing the informal term “hashtag” with “hash” or “object name” for consistency with Git’s documentation.
