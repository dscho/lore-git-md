Subject: [PATCH] send-email: add filesystem path completion for patch files

Thread type: patch series (single-patch)

Core problem or goal
Extend bash completion for `git send-email` to include filesystem paths for patch files when the user’s prefix could match both a revision identifier (commit hash, branch, tag) and a patch file (e.g., `0` in a directory containing `0001-*.patch`). The discussion centers on a usability trade-off: whether offering both refs and patch files in the same completion list improves or degrades the user experience. Examples like `0-branch`, `0-tag`, and `0001.patch` illustrate the underlying logic, with the original trigger (a 14-year-old Git tag with a purely hexadecimal name) now serving as a specific instance of the broader design question.

Current status
Under review; v1 posted, v2 anticipated. The core implementation (`__gitcomp_file_append()` helper) remains uncontested, but the patch’s necessity is debated on usability grounds. Junio’s feedback resolved the initial stalemate over problem validity by proposing a revised commit message and more realistic test cases, which D. Ben Knoble endorsed. SZEDER Gábor’s review introduced a counterargument: shorter, focused completion lists (offering only refs) are more usable, and users can still trigger filesystem completion explicitly (e.g., via `./<TAB>`, `<ALT-/>`, or `-- <TAB>`). Junio’s latest reply acknowledges this principle but notes it would make the feature useless for his workflow, as he never feeds refs to `git send-email`. The thread remains in a holding pattern awaiting Yury’s v2, which must reconcile these competing usability concerns. The test robustness issue (placement of `test_when_finished` block) remains unresolved but is expected to be addressed in v2.

Key technical details
- Files touched: `contrib/completion/git-completion.bash`, `t/t9902-completion.sh`
- New helper: `__gitcomp_file_append()` appends filesystem candidates to the existing completion list without disrupting revision completion; uses `compgen -f` and follows the established pattern of `__gitcompadd`/`__gitcompappend`
- Behavior change: `git send-email <TAB>` now offers both patch files and refs (branches, tags) when they share a prefix, but this is contested on usability grounds
- Test coverage: regression test in `t/t9902-completion.sh` verifies that both patch files and refs are offered; Junio proposes expanding the test to include more realistic cases (`0001.patch`, `0-tag`, `0-branch`) to address artificial-test-case concerns. The `test_when_finished` block placement issue remains unresolved.
- Implementation details: the Bash 3 file-mode hack (from 2013) remains applicable; the completion script does not expand abbreviated object names to full hashes (contrary to the original commit message’s claim)
- Real-world trigger: a 14-year-old Git tag (`05c69d298c96...`) with a purely hexadecimal name, but the discussion now focuses on broader usability principles
