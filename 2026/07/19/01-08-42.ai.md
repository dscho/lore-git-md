This is the second patch in brian m. carlson’s two-patch Rustification cleanup series, completing the memory hygiene fixes in the Rust hash bindings. It plugs a leak in the C hash context that occurs when the Rust `CryptoHasher` is dropped without explicitly discarding the underlying crypto library state. The leak only manifests with non-default block algorithms like OpenSSL, not with Git’s built-in hash implementation.

The fix adds a call to `git_hash_discard` in the `Drop` implementation for `CryptoHasher`, ensuring the crypto library’s internal context is properly released. The patch also declares the new C function in the Rust FFI bindings and updates the test module to exercise the drop path more thoroughly by cloning and explicitly dropping a hasher. The change is confined to `src/hash.rs` and introduces no behavior or API changes—it is purely about correctness at the Rust/C boundary.
