This is the first patch in a two-part Rustification cleanup series targeting memory hygiene in Git’s Rust hash bindings. It fixes a latent bug where the `CryptoHasher`’s `Clone` implementation fails to initialize the C hash context before cloning into it, which can lead to crashes when using non-default backends like OpenSSL. The fix is a four-line addition in `src/hash.rs` that ensures the context is properly initialized via `git_hash_init` before the clone operation. No new symbols or behavior changes are introduced; this is purely a correctness fix for the Rust/C boundary layer. The patch is well-scoped and directly addresses the issue described in the commit message. Given the context (a follow-up to Jeff King’s C-side leak fixes) and the author’s track record, this looks like a straightforward, uncontroversial fix that should merge without issue.
