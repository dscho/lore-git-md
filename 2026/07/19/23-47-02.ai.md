This is a surface-level review comment on the fourth patch in Jean-Noël Avila’s v1 series converting four Git command man pages to the new AsciiDoc synopsis style. The series is part of the ongoing documentation synopsis-style conversion effort and targets `git request-pull`, completing the batch.

Junio C Hamano notes an inconsistency in the number of dashes used to delimit AsciiDoc code blocks in the updated examples: the patch uses five, six, five, and five dashes in different places, while an earlier patch in the same series used nine. He asks whether there is a widely accepted AsciiDoc guideline governing the number of dashes and, if so, what it is. The observation is purely presentational and does not affect the rendered output or functionality of the man pages. No technical concerns are raised, and the question is framed as a stylistic preference rather than a correctness issue.

The files touched remain `Documentation/git-request-pull.adoc` and, by reference, `Documentation/git-imap-send.adoc`. The inconsistency is limited to the example blocks in the DESCRIPTION section, not the SYNOPSIS or OPTIONS sections that were the primary focus of the conversion. No new symbols, behavior changes, or on-disk format changes are introduced. The patch remains documentation-only and part of the larger synopsis-style conversion effort.
