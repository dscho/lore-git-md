This thread is about a proposed patch to improve bash completion for `git send-email` by offering filesystem paths for patch files when the user’s input could match both a revision (like a branch or tag) and a patch file (e.g., typing `0` in a directory with `0001-*.patch`). The patch itself is technically uncontroversial—it introduces a helper function to append filesystem candidates without disrupting existing revision completion—but its necessity is now debated on usability grounds.

Junio Hamano initially questioned whether the patch addressed a real problem but later collaborated with the author, Yury Norov, to refine the commit message and test cases to better reflect real-world scenarios (like `0-branch`, `0-tag`, and `0001.patch`). However, SZEDER Gábor raised a counterargument: shorter completion lists (offering only refs) are more usable, and users can still trigger filesystem completion explicitly (e.g., with `./<TAB>`). This usability trade-off remains unresolved and will need to be addressed in the upcoming v2.

Ben Knoble, who previously reviewed the patch favorably, now acknowledges Junio’s proposed improvements and flags SZEDER’s usability concerns as something Yury will need to consider in the next version. The thread is in a holding pattern awaiting Yury’s v2, which will need to balance the original goal of offering both refs and patch files in the same completion list against the argument for keeping the list shorter and more focused. No major technical objections remain, but the patch’s fate hinges on how well it addresses these usability concerns.
