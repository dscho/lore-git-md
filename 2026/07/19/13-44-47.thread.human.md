This thread introduces a small but long-overlooked quality-of-life fix for `git send-email`: when you type a prefix that matches both a Git revision and a patch file (like `0` in a directory with `0001-*.patch`), the bash completion script currently only offers the revision, not the file. Yury Norov’s patch extends the completion to include filesystem paths for patch files alongside the existing revision completion, using a new helper function to append file candidates without disrupting the existing logic.

Junio C Hamano, the maintainer, has reviewed the patch and calls it a welcome fix for a real annoyance, though he notes he avoids the issue in his own workflow. His feedback is minor and focused on test hygiene: he suggests registering the `test_when_finished` cleanup block earlier to ensure it runs even if setup fails, and mildly criticizes the use of a purely hexadecimal tag name in the test as unnecessarily ambiguous. The core logic of the patch remains uncontested, but the patch is still under review and awaiting input from completion-script experts before moving forward.
