This thread is about a patch from Yury Norov that extends bash completion for `git send-email` to include filesystem paths for patch files when the user’s input could match both a Git ref (like a branch or tag) and a patch file. For example, typing `0` in a directory with both `0-branch` and `0001.patch` would now show both options in the completion list. The patch itself is technically sound—it introduces a helper function (`__gitcomp_file_append()`) that appends filesystem candidates without disrupting existing ref completion—but its necessity is hotly debated.

Junio Hamano initially questioned whether the patch solved a real problem but later shifted to refining the commit message and test cases after recognizing the logic flaw it addressed. The core disagreement now centers on usability: SZEDER Gábor argues that offering both refs and patch files in the same completion list makes the list longer and harder to navigate, while Junio notes that hiding filesystem paths (as other Git commands do) would break his workflow, since he never feeds refs to `git send-email`. D. Ben Knoble reviewed the implementation favorably, but the thread is stuck waiting for Yury to post a v2 that reconciles these competing concerns. The unresolved questions include whether directories should also be included in completion, how to improve test realism, and how to frame the commit message to avoid misleading claims about object name expansion. The patch is still under review, with no clear consensus on the usability trade-off.
