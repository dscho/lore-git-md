This thread introduces a small but practical improvement to Git's bash completion for `git send-email`. Yury Norov (NVIDIA) has submitted a patch that lets users tab-complete patch filenames (like `0001-*.patch`) alongside the existing revision completion. The change fixes a real annoyance: when you type `git send-email 0<Tab>` in a directory with patch files, Git currently suggests unrelated 40-hex commit hashes instead of the patch files you actually want.

The implementation is clean and focused. It adds a new helper function `__gitcomp_file_append()` in `contrib/completion/git-completion.bash` that safely appends filesystem candidates to the existing completion list without breaking the revision logic. A new test in `t/t9902-completion.sh` verifies that both patch files and 40-hex refs appear when they share a prefix. The patch is ready for review and doesn't touch any core Git code—just the completion script and its tests. No objections or review feedback have appeared yet.
