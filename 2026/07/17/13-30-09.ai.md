This is the first patch in the v2 series adding path-related keys to `` `git repo info` ``. It introduces `path.toplevel.absolute` and `path.toplevel.relative`, which expose the top-level working tree directory in absolute and relative forms, respectively. The implementation uses `repo_get_work_tree()` to retrieve the path and `format_path()` with `PATH_FORMAT_CANONICAL` or `PATH_FORMAT_RELATIVE` to format it. In bare repositories, both keys return an empty string.

The patch touches `builtin/repo.c` (adding two new getter functions and registering the keys), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding tests for absolute/relative formatting and bare-repository behavior). The tests verify that the keys return the correct paths in subdirectories and handle bare repositories as expected.

This patch is a straightforward, well-scoped addition that mirrors the existing `path.gitdir` keys in both implementation and documentation style. The commit message clearly explains the motivation (replacing `git rev-parse --show-toplevel` in scripts) and edge-case behavior (bare repositories).
