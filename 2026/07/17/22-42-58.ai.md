This is the first patch in the v2 `--auto-reset` series for `git bisect`. Junio C Hamano reviews the preparatory refactoring that replaces `print_file_to_stdout()` with `print_fd_to_stdout()`, switching from reopening the `BISECT_RUN` file by name to reading from the already open descriptor. The change avoids potential issues with file accessibility and is a necessary foundation for the `--auto-reset` feature.

The patch is uncontroversial and ready for integration. Junio notes the use of `O_RDWR` (instead of `O_WRONLY`) to allow seeking, which is a clean solution, and raises a theoretical edge case about seek failures but concludes it is unlikely to be a practical regression. The refactoring is small, focused, and maintains identical behavior to the original implementation. It touches only `builtin/bisect.c` and includes no user-visible changes or new test coverage.

This patch is part of a three-patch series that is otherwise settled and ready for merging. The series introduces `--auto-reset=<where>` to automatically return the working tree to a user-specified commit after bisect completes, targeting both automated workflows and interactive debugging. The refactoring here is motivated by the need to avoid file reopens in the subsequent `--auto-reset` implementation.
