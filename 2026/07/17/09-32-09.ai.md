This is the first patch in Patrick Steinhardt’s nine-patch refactoring series that moves loose-object writing logic into the ODB abstraction layer. It centralizes the computation of compatibility object IDs (used when a repository has a secondary hash algorithm configured) inside the generic `odb_write_object_ext()` function instead of duplicating the logic in each backend. The change touches seven files: the core ODB interface (`odb.c`, `odb.h`) and all four source backends (`source-files.c`, `source-inmemory.c`, `source-loose.c`, `source-packed.c`). The loose backend sees the biggest delta—about 20 lines of hash-computation code are removed—while the generic layer gains the same logic plus a small wrapper to handle the optional `compat_oid` parameter. No callers need adjustment, and there are no behavior or on-disk format changes. The patch is a clean, mechanical step toward making the loose backend more self-contained.
