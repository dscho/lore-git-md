This is the first patch in Harald Nordgren’s v2 series introducing the `--auto-reset` option for `git bisect`. It is a **refactoring** that prepares the ground for the feature by changing how `git bisect run` handles its output.

The patch replaces `print_file_to_stdout()` with `print_fd_to_stdout()`, which reads the bisect script’s output from an already-open file descriptor instead of reopening the file by name. The change is mechanical: the file (`BISECT_RUN`) is now opened in `O_RDWR` mode, the descriptor is rewound with `lseek()`, and the contents are copied to stdout. The old code opened the file twice (once for writing, once for reading); the new code does it once and keeps the descriptor open. This avoids a potential race and removes the requirement that the file be reachable by name, although in practice the file is still written to the same location.

The commit message is clear and the diff is small. No behavior change is claimed or intended; the patch is purely preparatory for the `--auto-reset` feature that follows. It touches only `builtin/bisect.c` and has no test coverage of its own, which is appropriate for a refactoring that does not alter observable behavior. The patch looks clean and uncontroversial.
