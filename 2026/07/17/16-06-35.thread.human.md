This thread is about a two-patch bugfix series for `git rebase -i` by Phillip Wood, now at version 2. The series fixes two edge cases: an incorrect commit count in squash/fixup template messages when a preceding fixup/squash command is skipped, and a missing editor launch after `fixup -c` when a prior fixup/squash was skipped. The fixes are minimal and surgical, touching only `sequencer.c` and adding a new helper function to track `fixup -c` commands consistently.

Junio C Hamano, the maintainer, has reviewed both patches substantively. His only concern in v1—a robustness issue with trailing NUL bytes in legacy command-list files—was addressed in v2. A minor string-matching nit (whether helpers should require a space after `squash`/`fixup -c`) was resolved in this latest exchange: Junio accepted Phillip’s argument that the file is internally generated and only contains lines starting with those verbs, so no space check is needed. With that, the series is now effectively ready for integration. Junio plans to mark it for `next` after a few more days, and no further changes are expected. The patches include extensive test coverage in `t/t3418-rebase-continue.sh` and `t/t3437-rebase-fixup-options.sh`, verifying both the commit count accuracy and the editor-launch edge case.
