This is a surface-level review reply from Taylor Blau in the thread about Toon Claes's Bloom-filter optimization for `git last-modified`. Taylor agrees with Junio C Hamano's earlier substantive review of patch 2/4, specifically endorsing Junio's observation that the refactoring unintentionally changes Bloom filter statistics reporting. The key point is that the new code increments `count_bloom_filter_not_present` even when no Bloom key vectors exist (`revs->bloom_keyvecs_nr == 0`), whereas the original code returns early without incrementing. Taylor considers this a bug and suggests the guard (`revs->bloom_keyvecs_nr != 0`) should remain before the generation and filter lookups. He also notes the change should be explicitly mentioned in the commit message if it is intended as a fix. The reply is brief and aligns with Junio's technical assessment, adding no new technical details but reinforcing the need to address the behavioral regression.
