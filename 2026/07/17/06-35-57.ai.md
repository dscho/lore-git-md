This is the second patch in the v7 series refactoring `trust_executable_bit` and `has_symlinks` as part of the `the_repository` removal effort. It updates the performance-critical `ce_mode_from_stat()` helper to accept a `struct repository *` parameter, enabling repository-scoped access to these configuration flags.

The patch keeps `ce_mode_from_stat()` as a `static inline` function in `read-cache.h` (addressing Junio’s design concern from v6) while adding the repository parameter. All callers—spread across `apply.c`, `builtin/update-index.c`, `diff-lib.c`, and `read-cache.c`—are updated to pass the appropriate repository instance (or `the_repository` as a fallback). The boolean expressions in the function are reordered to evaluate `S_ISREG(mode)` first, optimizing for the common case where global variable accesses are replaced with getter functions.

No behavioral changes are introduced; this is a mechanical refactoring to support the broader goal of eliminating global state. The patch also adds a clarifying comment for `ce_mode_from_stat()`, documenting its role in handling filesystem limitations (missing symlinks or unreliable executable bits). Mentored-by tags from Christian Couder, Ayush Chandekar, and Olamide Caleb Bello reflect prior review and guidance.

This patch directly resolves Junio’s v6 objection about relocating `ce_mode_from_stat()` to `read-cache.c` by preserving its inlining while still enabling repository-scoped access. The changes are minimal and focused, touching only the function signature and its callers. The series’ readiness hinges on this patch, as it establishes the plumbing needed for the subsequent migration of both flags into `struct repo_config_values`.
