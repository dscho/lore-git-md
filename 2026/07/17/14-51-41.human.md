This is the first patch in Souma’s v2 series teaching `git history` to sign rewritten commits. It refactors the replay machinery (`replay.c` and `replay.h`) so that callers can request signatures on newly created commits. The change is purely plumbing: a new `sign_commit` field is added to the `replay_revisions_options` struct and threaded through the commit-creation functions (`create_commit` and `pick_regular_commit`). Existing callers continue to get unsigned commits because the field is zero-initialized, so there is no behavior change yet. The patch is well-scoped and mechanical, addressing Patrick Steinhardt’s v1 feedback to split the replay API changes into a separate preparatory step.
