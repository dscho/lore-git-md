This is a refactoring patch that completes the long-running effort to eliminate `git show-branch`'s reliance on the shared `object.flags` field for per-commit state. The patch, now in its seventh iteration, converts the code to use a dedicated commit-slab (`commit_rev_flags`) with a configurable stride of `uint64_t` words, lifting the previous 27-branch limit to an effectively unbounded number of branches (limited only by memory and the 64-bit stride).

The key improvements in this version address Junio C Hamano’s feedback on v6. The patch now dynamically grows the `ref_name[]` array and allocates `rev[]` and `reflog_msg[]` at runtime, eliminating the hardcoded `MAX_REVS` limit entirely. The stride is computed as `(ref_name_cnt + 63) / 64`, allowing the slab to support an arbitrary number of branches. Additionally, a new `has_subset_rev_flags()` helper restores the original pruning behavior in `join_revs()`, avoiding redundant queueing and parsing in merge-heavy histories. The `UNINTERESTING` bit remains in `object.flags` for revision-walking compatibility, and the patch includes thorough test coverage for 30+ branches, `--independent`, and `--merge-base` modes.
