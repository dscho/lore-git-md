This is a feature patch (v2 of 2) that teaches `git history` to sign rewritten commits. The series now consists of two patches: the first adds signing plumbing to the replay machinery, and the second implements the feature in `builtin/history.c` and adds comprehensive test coverage.

The v2 addresses all of Patrick Steinhardt’s review feedback from v1: the replay changes are split into a preparatory patch, the documentation and tests are folded into the feature patch so each commit builds and passes `t0450`, the `sign_commit` parameter is moved before the output parameter in `commit_tree_ext()` and its callers, the `history_config` callback now passes `NULL` to `git_default_config()`, and the commit message explains why configuration is read before command-line options. The series also adds signing support and tests for the `history drop` subcommand and coverage for selecting an explicit signing key.

The implementation follows the same precedence rules as `rebase`, `cherry-pick`, and `revert`: `commit.gpgsign` supplies the default, command-line options override it, and the last option wins. Every rewritten commit—including both halves of a split and replayed descendants—is signed, except when dropping the tip (which creates no replacement commit). The signature records the attestation of the current committer while retaining the original author identity. Test coverage spans all four subcommands (`reword`, `split`, `fixup`, and `drop`) and verifies config-driven signing, command-line overrides, last-option-wins precedence, and explicit key selection. The tests are GPG-gated and cover all flag/config combinations.
