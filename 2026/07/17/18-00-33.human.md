This is a reply from the author of the RFC patch series introducing `git repack --drop-filtered`. Siddharth Shrimali acknowledges Junio C Hamano’s **substantive review** of patch 1/7, which identified a **blocking logical flaw** in the option validation logic: the check for `--drop-filtered`’s incompatibility with `--write-bitmap-index` (`-b`) occurs too late in the control flow to distinguish between user-requested bitmaps (which should be rejected) and config-driven bitmaps (which should be silently disabled).

The author confirms the issue and plans to fix it in v2 by restructuring the validation to treat explicit `-b` on the command line as an error while silently disabling bitmaps set by configuration (e.g., `repack.writeBitmaps=true`). This change will address the safety concern that currently renders the feature unsafe. No other technical details or design decisions are discussed in this reply; the focus remains on resolving the maintainer’s feedback before proceeding with the rest of the series. The series remains in RFC status with no integration branch assignment.
