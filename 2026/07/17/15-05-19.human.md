This is a security and robustness patch in the `git cat-file --batch-command` remote object info series, now at v19 and queued for `next`. The patch ensures that bare OID requests (those without any metadata attributes like `size`) still trigger an existence check on the server, closing a gap where such requests would previously echo back the OID without verifying its presence in the repository.

The change introduces a new wrapper function `get_object_info()` that consolidates the existence check and adds two important flags: `OBJECT_INFO_SKIP_FETCH_OBJECT` (to prevent partial-clone servers from fetching missing objects) and `OBJECT_INFO_QUICK` (to avoid unnecessary pack rescans). The condition for recognizing objects is tightened to treat both `OBJ_BAD` and `OBJ_NONE` as unrecognized, ensuring consistent behavior. The protocol documentation is updated to clarify that full OIDs are required, that `obj-size` is optional, and that unrecognized OIDs always return `<OID> SP` regardless of requested attributes.

The patch also adds three new tests in `t/t5701-git-serve.sh` covering bare OID requests, unrecognized OIDs, and size requests for unrecognized OIDs, bringing the test coverage to 65 lines. This addresses Junio Hamano’s earlier insistence on robustness over efficiency for `%(objectname)`-only requests, and the solution is now documented as the correct long-term behavior. The implementation is careful to avoid lazy-fetching while maintaining security, and the commit message clearly explains the trade-offs. This is a well-motivated, thoroughly tested change that resolves the last major technical concern in the series.
