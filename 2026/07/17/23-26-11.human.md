This is a brief but substantive reply in the review thread for patch 2/4 of Toon Claes’s Bloom-filter optimization series for `git last-modified`. Taylor Blau agrees with Junio C Hamano’s observation that the patch unintentionally skews Bloom filter statistics by incrementing `count_bloom_filter_not_present` even when no key vectors exist (`revs->bloom_keyvecs_nr == 0`). He endorses Junio’s suggestion to keep the original guard (`if (!revs->bloom_keyvecs_nr) return -1;`) before generation and filter lookups, calling it a separable fix that should be explicitly mentioned in the commit message if retained. The exchange is narrowly focused on correctness and observability of monitoring data, not style or structure.
