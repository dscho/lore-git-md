This is the final patch in the nineteenth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. The series is now technically complete, queued for `next`, and this patch makes the client's allow-list for object metadata placeholders dynamically adapt to the server's advertised capabilities.

The patch replaces the static allow-list (`objectname`, `objectsize`) with a dynamic system that queries the server for supported object-info attributes (currently `size` and `type`). The client now silently omits unsupported placeholders (e.g., `%(objecttype)` when the server doesn't advertise `type`) rather than failing, matching `for-each-ref`'s behavior for known-but-inapplicable atoms. This ensures forward compatibility as the `object-info` protocol gains new capabilities. The implementation moves `object_info_options` out of `get_remote_info()` so the caller can control which options are requested, and ensures output is always produced—even if no attributes are supported, resulting in a blank line.

Key technical details include a mapping between protocol options (`size`, `type`) and placeholders (`objectsize`, `objecttype`), backward-compatible handling of bare `%(objectname)` requests (which trigger an existence check), and a new `remote_allowed_atoms` string list in `struct expand_data` to track supported placeholders. The patch also removes the pre-sort in `fetch_object_info_via_pack()` since the list is now unsorted, and updates the `EXPAND_DATA_INIT` macro to initialize the new string list. Tests verify that unsupported placeholders expand to empty strings and that `%(objectname)`-only requests work as expected.

The patch is authored by Pablo Sabater and includes 86 lines of changes to `builtin/cat-file.c`, 20 to `fetch-object-info.c`, and 28 new test lines in `t/t1017-cat-file-remote-object-info.sh`. It resolves the last major design issue in the series by enabling dynamic adaptation to server capabilities while maintaining security (bounds-checking, memory safety) and robustness (existence checks for bare OIDs). The series is now ready for graduation to `master` after minor cosmetic nits are addressed.
