This is the fourth and final patch in Toon Claes’s four-part series optimizing the experimental `git last-modified` command by reusing Bloom filters. Taylor Blau’s reply is a **substantive review** focused on test coverage. He points out that the existing test suite (`t8020`) does not actually exercise the Bloom filter code path added in this patch because it never writes a commit-graph with `--changed-paths` (which is required for Bloom filters to exist). The current test cases use unquoted wildcards (e.g., `a/*`), which the shell expands into literal pathspecs before `git last-modified` sees them, bypassing the per-path Bloom filter logic this patch enables. Taylor suggests adding a test that writes a commit-graph with changed-path Bloom filters and uses a genuinely quoted wildcard (e.g., `git last-modified -r "*"`), which would trigger the zero-prefix wildcard case this patch handles. He clarifies that this is not a correctness issue but a gap in test coverage, and his feedback is aimed at ensuring the optimization is properly validated. The review is constructive and specific, providing clear guidance on how to improve the patch.
