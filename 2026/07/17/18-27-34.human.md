This is the final patch in Harald Nordgren’s v2 series adding the `--auto-reset[=<where>]` option to `git bisect`. It implements the core feature: after the first bad commit is identified, the working tree is automatically reset to either the pre-bisect commit (`original`, the default) or the first bad commit (`found`), as specified by the user. The patch wires the option into both `git bisect start` and `git bisect run`, persists the chosen target in a `BISECT_AUTO_RESET` state file, and enforces the constraint that `--auto-reset` cannot be used with `--no-checkout`.

The implementation is clean and well-tested. The new state file is properly cleaned up, the reset is performed quietly (using the `quiet` parameter introduced in patch 2), and the test suite now includes four new tests covering both `original` and `found` behaviors, state cleanup, and edge cases like invalid targets and `--no-checkout` conflicts. The only practical limitation is that users cannot conditionally choose the reset target based on the bisect outcome, as the target must be specified upfront — a reasonable trade-off for the simplicity of the feature.

This patch looks ready for integration. It addresses the feedback from v1, particularly Junio’s suggestion to parameterize the option, and the preparatory refactoring in patches 1 and 2 ensures the changes are minimal and focused. The series as a whole is a well-crafted addition that will benefit both automated workflows and interactive debugging.
