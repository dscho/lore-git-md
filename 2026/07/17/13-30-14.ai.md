This is the sixth patch in K Jayatheerth’s seven-patch GSoC series adding path-related keys to `git repo info`. It introduces the `path.grafts.absolute` and `path.grafts.relative` keys, exposing the location of the repository’s grafts file in both absolute and relative formats. The implementation respects the `GIT_GRAFT_FILE` environment variable override, mirroring the behavior of `git rev-parse --git-path info/grafts` but in a structured, scriptable format.

The patch touches `builtin/repo.c` to add two new getter functions (`get_path_grafts_absolute` and `get_path_grafts_relative`), updates `Documentation/git-repo.adoc` to document the new keys, and extends `t/t1900-repo-info.sh` with tests verifying both the standard grafts file location and the `GIT_GRAFT_FILE` override. The code is clean and follows the established pattern from earlier patches in the series, using `repo_get_graft_file()` and `format_path()` with `PATH_FORMAT_CANONICAL` or `PATH_FORMAT_RELATIVE`. Test coverage includes edge cases for environment variable overrides, ensuring consistency with Git’s existing behavior.

No substantive feedback has been received on this patch yet, but the series as a whole may face naming or suffix-semantic discussions (e.g., whether `grafts` should be `graft-file` for consistency with other keys like `index`). The patch is mechanically sound and ready for technical review, with no unresolved issues from prior iterations. It advances the series’ goal of making repository component paths accessible without requiring direct access to Git’s internals.
