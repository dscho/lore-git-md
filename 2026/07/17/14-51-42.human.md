This is the main feature patch in Souma’s v2 series teaching `git history` to sign rewritten commits. It is the second of two patches (the first was a preparatory refactoring of the replay API) and implements the actual signing logic for the `drop`, `fixup`, `reword`, and `split` subcommands.

The patch reads the `commit.gpgsign` configuration early to establish the default, then lets later `-S`/`--gpg-sign` or `--no-gpg-sign` options override it. Every newly created commit—both halves of a split and replayed descendants—is signed if the effective setting is true; dropping the tip creates no replacement commit, so nothing is signed. The signature records the committer’s attestation while preserving the original author identity, matching the behavior of `git rebase --gpg-sign`.

Documentation is updated to show the new options in the synopsis and add a short section explaining them. GPG-gated tests in `t3451`, `t3452`, `t3453`, and `t3454` verify configuration-driven signing, command-line overrides, last-option-wins precedence, replayed descendants, split commits, explicit key selection, and the no-new-commit case for `drop`. All flag/config combinations are covered, and the tests are careful to check that only the rewritten commits are signed, not the originals.

The patch is well-structured, thoroughly tested, and addresses all of Patrick Steinhardt’s v1 feedback. The only remaining open question is the conceptual trade-off around signing commits originally authored by someone else; this is now discussed in the commit message but has not yet been resolved by the maintainer.
