This is the core implementation patch (12/13) in the v19 series that adds the `remote-object-info` command to `git cat-file --batch-command`. It enables querying object metadata (currently size only) from a remote repository without downloading the full objects, completing the feature's client-side logic.

The patch introduces the command parser (`parse_cmd_remote_object_info`) and supporting infrastructure in `builtin/cat-file.c`. Key technical details include:
- **Input handling**: The command accepts a remote URL followed by one or more object IDs (full 40-character SHA-1/256), with strict validation against malformed OIDs, short OIDs, and excessive input length (capped at 8KB URL + 10,000 objects).
- **Security**: Memory safety is enforced via `xcalloc` for allocations, bounds-checking on all inputs, and a new `free_object_info_contents()` helper (added to `odb.h`) to prevent leaks. The `is_remote` flag in `struct expand_data` and initialization of `data->type` to `OBJ_BAD` prevent uninitialized memory access.
- **Protocol integration**: The command uses the `object-info` protocol v2 capability (advertised by servers with `transfer.advertiseobjectinfo=true`) to fetch metadata. It dynamically validates format placeholders against the server's advertised attributes, silently omitting unsupported atoms (e.g., `%(objecttype)`) to match `for-each-ref` behavior.
- **Edge cases**: Handles missing objects (returns "missing" status), unsupported protocols (fails with clear error), and gracefully skips unsupported format placeholders. The implementation avoids remote communication overhead by batching multiple OIDs into a single request.
- **Test coverage**: The patch adds 719 lines of new tests in `t/t1017-cat-file-remote-object-info.sh`, covering all three smart transports (`git://`, `file://`, `http://`), `--buffer` mode, `-Z` (null-delimited) output, and edge cases like malformed OIDs or legacy protocols.

The command's behavior diverges from `info` in two key ways: (1) it defaults to `%(objectname) %(objectsize)` format (omitting `%(objecttype)` until type support is added), and (2) it processes all OIDs in a single request to minimize round trips. The patch also includes a warning in the documentation that the default format may change once type support is implemented.

This patch is the culmination of the series' client-side work, following the protocol and transport-layer changes in earlier patches. The implementation is now feature-complete for its initial scope (size-only queries) and has passed all CI checks.
