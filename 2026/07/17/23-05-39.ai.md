This is a **substantive review** of patch 3/4 in Toon Claes’s four-patch series optimizing `git last-modified`. Taylor Blau identifies a correctness bug in the Bloom-filter pre-filtering logic when `--show-trees` is used. The issue arises because the original pathspec does not cover all entries in `lm->paths` (which also includes ancestor tree entries added by `populate_paths_from_revs()`), so a Bloom filter that says “no changes” for the pathspec may still miss changes to those ancestor trees. Taylor provides a minimal reproduction case in `t8020` and suggests guarding the pre-filter with a check for `!lm->show_trees`. The review also includes a surface-level nit about style (`if (!foo())` vs `if (foo() == 0)`), but the core feedback is the correctness concern. The cover-letter benchmarks, which use `--show-trees`, may therefore be misleading until this is fixed.
