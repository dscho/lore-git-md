This is a feature patch adding a built-in userdiff driver for the Swift programming language. The patch introduces patterns for recognizing Swift function declarations and word boundaries, enabling proper diff hunk headers and word-level diffs for `.swift` files without manual configuration.

The implementation is thorough: the funcname pattern covers Swift’s declaration grammar, including attributes (`@objc`, `@available`), modifiers (`public`, `static`), and edge cases like failable initializers (`init?`), generics (`init<T>`), and operator functions. The word regex handles Swift identifiers, literals (hexadecimal, octal, binary, floating-point), and operators (`<<=`, `??`, range operators). The patch includes 13 new test fixtures in `t/t4018/` covering all major Swift declaration types (classes, structs, enums, protocols, extensions, actors, etc.) and edge cases like multi-line attributes and generics.

The motivation is clear: without a Swift driver, `git diff` hunk headers default to the generic heuristic, often showing the enclosing type rather than the changed function. The commit message explicitly states this and confirms the author verified the pattern against real Swift code, including complex cases like generic functions with `where` clauses. The patch also updates `Documentation/gitattributes.adoc` to document the new driver.

This is a self-contained, well-tested contribution that addresses a real gap in Git’s built-in language support. The author notes this is part of the "add a userdiff driver for a language" microproject and confirms no prior patch for Swift exists. The implementation appears robust, with no obvious omissions or sloppiness. The patch is likely to be uncontroversial and could be merged as-is if tests pass. Key files touched: `userdiff.c`, `Documentation/gitattributes.adoc`, and `t/t4018/` (new test fixtures).
