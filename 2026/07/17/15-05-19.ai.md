This is a security and robustness patch in the `git cat-file --batch-command` remote object info series (GSoC v19, 9/13). It ensures the server always checks object existence, even when no attributes (like size) are requested, closing a gap where bare OID requests could silently succeed without validating the object.

The patch introduces a new `get_object_info()` wrapper around `odb_read_object_info_extended()` that enforces two key flags: `OBJECT_INFO_SKIP_FETCH_OBJECT` (preventing partial-clone servers from fetching missing objects) and `OBJECT_INFO_QUICK` (avoiding unnecessary pack rescans). The existence check is now unconditional, and the response grammar is tightened—unrecognized OIDs now return `<OID> SP` regardless of requested attributes, while recognized OIDs return just `<OID>` for bare requests. Documentation in `gitprotocol-v2.adoc` is updated to reflect these behaviors, including explicit requirements for full OIDs and optional `obj-size` fields.

Tests in `t/t5701-git-serve.sh` verify the new behavior: bare OID requests for valid objects return the OID alone, while unrecognized OIDs (including those with `size` requested) append a space. The patch also fixes a subtle bug in the original check, replacing `< 0` with `<= OBJ_NONE` to catch both `OBJ_BAD` and `OBJ_NONE` as unrecognized cases.

This is a targeted but critical change—it resolves Junio’s long-standing concern about robustness in `%(objectname)`-only requests by ensuring the server always validates object existence, while avoiding lazy-fetching in partial clones. The implementation is minimal and focused, with no behavior changes for existing attribute requests. The series remains on track for `next`, with this patch addressing the last major technical issue.
