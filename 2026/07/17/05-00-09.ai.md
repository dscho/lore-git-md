This is a **feature addition** to `git bisect` that remains under active design discussion. Junio C Hamano, the maintainer, proposes a revised design for the `--auto-reset` option: instead of a boolean flag, it should accept a parameter (`--auto-reset=<where>`) with values `original` (reset to the pre-bisect commit) or `found` (leave the working tree on the first bad commit). The default, if the parameter is omitted, would be `original`.

This proposal directly addresses the core design disagreement identified in earlier feedback. The maintainer’s rationale is situational: where to reset depends on the user’s immediate needs (automated workflow vs. interactive debugging) rather than a fixed preference. The change would require updates to the implementation, documentation, and tests, but the preparatory refactoring (patch 1) and quiet-checkout addition (patch 2) are unaffected and remain uncontroversial.

The author, Harald Nordgren, has not yet responded to this specific proposal, so the thread is now waiting on his reaction or a revised patch series. No other reviewers have weighed in on the parameterized design. The outcome will determine whether the feature becomes a flexible tool for both automated and interactive use cases or remains narrowly targeted. Key technical details to track in follow-up discussion: the parameter syntax, default behavior, and whether the `BISECT_AUTO_RESET` state file needs to store the target commit or just the flag.
