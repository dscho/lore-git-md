This is the final patch in the v2 series introducing the `--auto-reset[=<where>]` option to `git bisect`. It implements the core functionality: persisting the reset target in a `BISECT_AUTO_RESET` state file, enforcing the `--no-checkout` constraint, and performing the quiet reset when the first bad commit is found. The patch touches `bisect.c`, `builtin/bisect.c`, and `Documentation/git-bisect.adoc`, and adds four new tests to `t/t6030-bisect-porcelain.sh` covering both `original` and `found` behaviors, state cleanup, and edge cases.

The implementation is clean and follows the design agreed in the v1 discussion. The new `enum auto_reset_mode` and helper functions (`parse_auto_reset`, `auto_reset_mode_name`, `bisect_auto_reset`) are straightforward and well-named. The state file handling is consistent with existing bisect state files, and the constraint that `--auto-reset` cannot be used with `--no-checkout` is enforced at both `start` and `run` time. The reset is performed quietly, as intended, and the state file is cleaned up afterward.

The test coverage is thorough, validating both happy paths and error cases (invalid targets, `--no-checkout` conflicts, state cleanup, and descriptor errors). The tests are well-structured and use helper functions to avoid duplication. No gaps in functionality or edge case handling are apparent.

This patch is ready for review. It is the last piece of the series, and the preparatory patches (1 and 2) are already uncontroversial and ready for integration. The series as a whole is a well-motivated feature addition that addresses both automated workflows and interactive debugging, and this patch delivers the promised functionality without introducing unnecessary complexity.
