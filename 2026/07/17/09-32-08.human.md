This is part of the ongoing ODB (object database) abstraction effort, specifically the ninth installment in Patrick Steinhardt’s series to restructure how Git reads and writes objects. The goal here is to move the logic for writing loose objects out of `object-file.c` and into `odb/source-loose.c`, making the loose-object backend more self-contained.

The series starts with small preparatory steps—computing object IDs in the generic write path, lifting existence checks out of the loose backend, and adding mtime support—before tackling the main refactoring. The bulk of the work is in patch 7, which rewrites `force_object_loose()` to use the new generic `odb_source_write_object()` interface instead of calling `write_loose_object()` directly. Patches 8 and 9 then relocate the function and the loose-object writing logic into the loose backend.

The diffstat shows almost perfect code motion: 549 lines removed from `object-file.c` and 402 lines added to `odb/source-loose.c`, with only minor adjustments elsewhere. The series is built on current `master` plus two recent topics (`jt/receive-pack-use-odb-transaction` and `jk/git-hash-cleanups`), and Patrick notes an evil merge is required for the packed backend’s transaction API.

This looks like a well-scoped, mechanical refactoring that continues the ODB abstraction work without changing behavior. The commit messages are clear, the test coverage is maintained, and the series is ready for review. If you care about the ODB layer or are following the abstraction effort, this is worth a look.
