This is the first patch in the v2 series adding `--auto-reset` to `git bisect`. It refactors the bisect run output handling to avoid reopening the `BISECT_RUN` file by name, instead reading from the already open descriptor. The change is a preparatory cleanup motivated by the need to avoid file reopens in the subsequent `--auto-reset` implementation.

The patch replaces `print_file_to_stdout()` with `print_fd_to_stdout()`, which takes an open file descriptor, seeks to the start, and copies its contents to stdout. The descriptor is now opened with `O_RDWR` (instead of `O_WRONLY`) to allow seeking, and the file is no longer reopened by name. The behavior remains identical to the original, but the implementation is more robust and avoids potential issues with file accessibility by name.

This is a small, focused refactoring with no user-visible changes. The commit message clearly explains the motivation, and the code changes are straightforward. The patch is uncontroversial and appears ready for integration. It touches only `builtin/bisect.c` and is a necessary foundation for the `--auto-reset` feature in later patches. No test failures or edge cases are introduced, and the change aligns with Git's general preference for avoiding unnecessary file operations.
