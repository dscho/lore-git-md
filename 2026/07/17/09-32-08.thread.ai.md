Subject: [PATCH 0/9] Refactor loose object backend for ODB abstraction
Series version: v1 (initial)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Move the logic for writing loose objects out of `object-file.c` and into `odb/source-loose.c`, making the loose object backend more self-contained as part of the ongoing ODB abstraction effort. The series refactors `force_object_loose()` to use the generic `odb_source_write_object()` interface instead of directly calling `write_loose_object()`, with preparatory steps including computing object hashes and compatibility IDs in the generic write function, lifting object existence checks out of the loose backend, and adding mtime support during object writes.

Current status
Under review; this is the first iteration of the series. No prior versions exist. The series is built on top of two recent topics: `jt/receive-pack-use-odb-transaction` and `jk/git-hash-cleanups`, and requires an evil merge to resolve a conflict in the packed backend's transaction handling.

Key technical details
- Files touched: 12, primarily `object-file.c` (removing ~400 lines) and `odb/source-loose.c` (adding ~400 lines), plus adjustments to ODB transaction interfaces and loose backend internals. Patch 3/9 centralizes object hash computation in the generic `odb_write_object_ext()` function, removing the redundant `write_object_file_prepare()` helper from `object-file.c` and updating all four ODB source backends (`source-files.c`, `source-inmemory.c`, `source-loose.c`, `source-packed.c`) to expect a precomputed `const struct object_id *` instead of computing the hash themselves. Patch 2/9 introduces a wrapper function `cl_assert_write_object()` in the in-memory unit-test backend (`t/unit-tests/u-odb-inmemory.c`) to encapsulate calls to `odb_source_write_object()`, replacing 25 direct calls. Patch 1/9 additionally touches the core ODB interface (`odb.c`, `odb.h`) and all four source backends to centralize compatibility ID computation. Patch 4/9 lifts the object-existence check out of the loose backend (`odb/source-loose.c`) and into the generic ODB layer (`odb.c`), removing a layering violation and eliminating redundant checks across backends. This change makes it possible to write an object into a specific source even if the same object exists in another source.
- New or renamed symbols: `odb_source_write_object()` (generic write interface), `force_object_loose()` (refactored to use generic interface), `odb_write_object_ext()` (extended with optional `compat_oid` parameter), `cl_assert_write_object()` (test wrapper), ODB transaction flags parameter added.
- Subsystems: ODB (object database), loose object backend, ODB transactions, object hash computation, in-memory test backend.
- No behavior changes or on-disk format changes; this is a pure refactoring.
- Fixes a memory leak in `force_object_loose()`.
- Updates the in-memory test backend to support the new write interface.
- Object hash computation, compatibility ID handling, and object-existence checks moved to the generic write function, eliminating duplication across backends.

Open questions and loose ends
None identified yet; the series is presented as a well-structured refactoring with no expected behavior changes. Reviewers may surface questions about the transaction interface changes, the impact on other ODB backends, the necessity of the new `compat_oid` parameter in the generic interface, the test wrapper's role in future-proofing the interface, whether the new `const` qualifier on the `oid` parameter in `odb_write_object_ext()` is consistently respected across all backends, or the implications of allowing writes to a specific source even when the object exists elsewhere.
