Thread identity
Subject: [PATCH 0/9] Refactor loose object backend for ODB abstraction
Series version: v1 (initial, build-breaking; v2 expected after merge fix)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Move the logic for writing loose objects out of `object-file.c` and into `odb/source-loose.c`, making the loose object backend fully self-contained as part of the ongoing ODB abstraction effort. The series refactors all loose-object writing machinery to use the generic `odb_source_write_object()` interface, eliminating direct calls to `write_loose_object()` and consolidating loose backend internals. Preparatory steps include centralizing object hash computation, compatibility ID handling, object-existence checks, and mtime support in the generic ODB layer, and relocating `force_object_loose()` to its sole caller.

Current status
Under review; this is the first iteration of the series. Junio has stated he will fix the oversight, which will unblock the series and allow substantive review to proceed. No prior versions exist. The series is built on top of `jt/receive-pack-use-odb-transaction` and `jk/git-hash-cleanups`. All nine patches have been posted, completing the refactoring. The final patch (9/9) moves the remaining loose-object writing helpers (`start_loose_object_common`, `write_loose_object_common`, `end_loose_object_common`, `create_tmpfile`, `close_loose_object`) into `odb/source-loose.c`, leaving only `odb_source_loose_write_stream` in `object-file.c` with a TODO comment indicating it should eventually move as well. The series achieves its goal of making the loose backend self-contained, with no behavior changes or on-disk format changes.

Key technical details
- Files touched: 12 in the initial series, plus 11 in patch 5/9, 1 in patch 6/9 (`object-file.c`), 1 in patch 7/9 (`object-file.c`), 2 in patch 8/9 (`object-file.c` and `builtin/pack-objects.c`), and 2 in patch 9/9 (`object-file.c` and `odb/source-loose.c`). The series primarily moves code from `object-file.c` (removing ~823 lines) to `odb/source-loose.c` (adding ~757 lines), with adjustments to ODB transaction interfaces, loose backend internals, and all four ODB source backends (`source-files.c`, `source-inmemory.c`, `source-loose.c`, `source-packed.c`). Patch 3/9 centralizes object hash computation in the generic `odb_write_object_ext()` function, removing the redundant `write_object_file_prepare()` helper from `object-file.c` and updating all backends to expect a precomputed `const struct object_id *` instead of computing the hash themselves. Patch 2/9 introduces a wrapper function `cl_assert_write_object()` in the in-memory unit-test backend (`t/unit-tests/u-odb-inmemory.c`) to encapsulate calls to `odb_source_write_object()`, replacing 25 direct calls. Patch 1/9 additionally touches the core ODB interface (`odb.c`, `odb.h`) and all four source backends to centralize compatibility ID computation. Patch 4/9 lifts the object-existence check out of the loose backend (`odb/source-loose.c`) and into the generic ODB layer (`odb.c`), removing a layering violation and eliminating redundant checks across backends. This change makes it possible to write an object into a specific source even if the same object exists in another source. Patch 5/9 adds a new `mtime` parameter (a `const time_t *`) to `odb_source_write_object()`, `odb_source_freshen_object()`, and all four backends, enabling the loose backend to preserve pack mtimes when loosening objects during repack. Patch 6/9 fixes a memory leak in `force_object_loose()` by adding a `goto`-based cleanup block to free the content buffer on early returns. Patch 7/9 replaces the direct call to `write_loose_object()` in `force_object_loose()` with `odb_source_write_object()`, passing the precomputed compatibility object ID and mtime. Patch 8/9 moves the `force_object_loose()` function to its only caller, `builtin/pack-objects.c`, removing its declaration from `object-file.h`. Patch 9/9 moves the remaining loose-object writing helpers into `odb/source-loose.c` and exposes two transaction-related helper functions (`odb_transaction_files_prepare` and `odb_transaction_files_fsync`) previously static in `object-file.c`.
- New or renamed symbols: `odb_source_write_object()` (generic write interface), `force_object_loose()` (relocated to `pack-objects.c`), `odb_write_object_ext()` (extended with optional `compat_oid` parameter), `cl_assert_write_object()` (test wrapper), `odb_transaction_files_prepare`, `odb_transaction_files_fsync`, ODB transaction flags parameter added, `mtime` parameter in ODB write and freshen interfaces.
- Subsystems: ODB (object database), loose object backend, ODB transactions, object hash computation, in-memory test backend, mtime handling, `pack-objects` builtin, `the_repository` removal.
- No behavior changes or on-disk format changes; this is a pure refactoring.
- Fixes a memory leak in `force_object_loose()`.
- Updates the in-memory test backend to support the new write interface and mtime parameter.
- Object hash computation, compatibility ID handling, object-existence checks, and mtime support moved to the generic write function, eliminating duplication across backends.
- The loose backend is now fully self-contained, with only `odb_source_loose_write_stream` remaining in `object-file.c` (marked with a TODO for future relocation).
- The build-breaking issue is due to a missing evil merge resolution in the packed backend's transaction function (`odb_source_packed_transaction_prepare`), which expects a different parameter type than what is provided by the current base.
