This is the v7 iteration of a refactoring series that migrates `trust_executable_bit` and `has_symlinks` into `struct repo_config_values`, completing the `the_repository` removal effort for these core index-related configuration flags. The series is now uncontested after addressing Junio C Hamano’s design-level feedback from v6.

The key change in v7 is keeping `ce_mode_from_stat()` as a `static inline` function in `read-cache.h` while teaching it to accept a `struct repository *` parameter, as Junio requested. This preserves potential performance benefits in hot paths while enabling repository-scoped configuration access. The commit message for patch 4/4 has also been reworded to emphasize the platform-specific override mechanism, addressing Junio’s editorial feedback.

The series remains a mechanical migration with no behavioral changes. It moves both flags into repository-scoped storage, establishes new getter functions (`repo_trust_executable_bit()` and `repo_has_symlinks()`), and updates all call sites to use repository-scoped access. The mingw compatibility layer now uses a compile-time macro (`platform_has_symlinks()`) and platform-specific function (`mingw_platform_has_symlinks()`), eliminating mutable global state while preserving native symlink detection via environment variables. This design aligns with Git’s existing platform-compatibility patterns (e.g., `is_dir_sep()`).

Files touched include `read-cache.c`, `environment.c/h`, `apply.c`, `compat/mingw.c`, and related headers. The series removes redundant extern declarations, migrates both flags into `repo_config_values` with proper initialization, and ensures repository pointer validation in the new getters. The mingw adjustments are now cleaner and may serve as a template for future platform-specific overrides. The author has also incorporated prior feedback, including dropping redundant comments and preserving `ce_mode_from_stat()`’s inlining.

The series builds on prior work (including an unsuccessful attempt to use `struct repo_settings`) and demonstrates incremental progress in eliminating global state. The inclusion of `has_symlinks`—previously deferred—reflects growing confidence in the approach, though the author notes that `repo_config_values()` still does not support non-`the_repository` instances due to deep integration of these flags. This limitation is acknowledged as a future challenge, but the series lays groundwork for eventual elimination of the global.
