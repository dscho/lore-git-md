This is the main feature patch (2/2 in the v2 series) that teaches `git history` to sign rewritten commits. It extends the `drop`, `fixup`, `reword`, and `split` subcommands to respect the `commit.gpgsign` configuration variable and the `-S/--gpg-sign` and `--no-gpg-sign` command-line options, with command-line options overriding configuration and the last option winning.

The patch touches `builtin/history.c` to add a new `sign_commit` field to the replay machinery, plumbing it through `pick_regular_commit`, `create_commit`, `commit_tree_ext`, `commit_tree_with_edited_message`, and `split_commit`. It reads the signing configuration early (before option parsing) so that later command-line options can override it. The documentation (`git-history.txt`) is updated to document the new options, and GPG-gated tests in `t3451-history-reword.sh`, `t3452-history-split.sh`, `t3453-history-fixup.sh`, and `t3454-history-drop.sh` verify that signing works as expected for all flag/config combinations, including explicit key selection and the no-new-commit case for `drop`.

The commit message explicitly addresses the conceptual trade-off of signing rewritten commits that were originally authored by someone else, noting that the signature records the current committer’s attestation while retaining the original author identity. This discussion is now part of the commit message, though the broader question remains unresolved. The patch is well-tested and addresses all feedback from the v1 review, including splitting the replay API plumbing into a dedicated preparatory patch (1/3) and folding documentation and tests into this patch.
