This is a feature patch (v2 of 2) that teaches `git history` to sign rewritten commits. The series addresses Patrick Steinhardt’s v1 review feedback by splitting the replay API plumbing into a preparatory patch (1/2) and folding the documentation and tests into the main feature patch (2/2). The implementation now respects `commit.gpgsign`, `-S[=<key-id>]`, `--gpg-sign[=<key-id>]`, and `--no-gpg-sign` across all `history` subcommands (`drop`, `fixup`, `reword`, `split`), with command-line options overriding configuration and the last option winning. Every newly created commit—including both halves of a split and replayed descendants—is signed, except when dropping the tip (which creates no replacement commit). The signature records the committer’s attestation while preserving the original author identity.

The patch touches `builtin/history.c`, `replay.c`, `replay.h`, and the test scripts `t3451-history-reword.sh`, `t3452-history-split.sh`, `t3453-history-fixup.sh`, and `t3454-history-drop.sh`. Key symbols introduced include the `sign_commit` field in `replay_revisions_options`, the `OPT_HISTORY_GPG_SIGN` macro, and plumbing through `commit_tree_ext`, `commit_tree_with_edited_message`, and `split_commit`. Test coverage is GPG-gated and verifies configuration-driven signing, command-line overrides, explicit key selection, and the no-new-commit case for `drop`.

The v2 reorganization ensures each commit builds and passes `t0450`, and the commit message now explicitly discusses the conceptual trade-off of signing commits authored by others. The preparatory patch (1/2) is purely mechanical, while the feature patch (2/2) combines the core implementation, documentation, and tests. The series is under active review and likely to see further iteration.
