This is the third patch in Toon Claes’s four-patch series to speed up the experimental `git last-modified` command by reusing Git’s Bloom-filter machinery. The patch makes `git last-modified` behave like `git log` when filtering commits: instead of expanding the pathspec into individual files and checking each one against the Bloom filter, it first checks the entire pathspec against the filter. If the filter says “no,” the commit is skipped entirely; only if it says “maybe” does the command proceed to the per-path checks. The change is a single three-line addition in `builtin/last-modified.c` and reduces the command’s runtime by roughly 3.5× on the ziglang/zig repository (from 52 ms to 14 ms). The patch is clean, well-motivated by the benchmark in the commit message, and directly reuses the helper (`revs_maybe_changed_in_bloom`) that was exposed in patch 2. No new tests or on-disk format changes are involved.
