This is a gitweb bugfix patch, the second iteration of a two-patch series that was previously split. The author has incorporated Junio’s feedback: the regression test is now squashed into the implementation patch, and the test script uses `test_grep`/`test_grep !` instead of raw `grep`.

The patch fixes a rendering glitch in gitweb’s commitdiff view: index lines that include a trailing file mode (e.g., `index <old>..<new> 100644`) were showing full, unlinked object IDs instead of the usual shortened, clickable hashes. The root cause is a simple ordering issue in the regex logic—mode handling ran after the object-ID matcher, so the mode string was treated as part of the ID range. The fix is minimal: temporarily strip the mode, let the existing object-ID shortening and linking code do its work, then re-append the mode. The test verifies that the common `100644` case now shows linked short blob IDs and no longer emits the unlinked full form.

The commit message is clear and the code change is straightforward, touching only `gitweb/gitweb.perl` and the test script. There is no risk of breaking other gitweb features, and the patch aligns with recent mobile-overflow fixes in other views. The series looks ready for `next`.
