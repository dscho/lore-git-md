This is the first patch in Souma’s v2 series teaching `git history` to sign rewritten commits. It refactors the replay machinery (`replay.c` and `replay.h`) to let callers specify whether and how to sign newly created commits.

The patch adds a `sign_commit` field to the `replay_revisions_options` struct and threads it through the commit-creation plumbing: `pick_regular_commit` and `create_commit`. The field is a `const char *`; `NULL` means no signing, an empty string means use the default key, and a non-empty string specifies an explicit key ID. All existing callers zero-initialize the options struct, so their behavior is unchanged.

The diff touches only two files and is purely mechanical: no new behavior is introduced yet, and no tests or documentation are added. This patch exists solely to prepare the replay API for the feature patch that follows.
