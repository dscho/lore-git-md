This is the author's reply to Junio's **substantive review** of the first patch in the RFC series introducing `git repack --drop-filtered`. The author acknowledges the **blocking logical flaw** identified by Junio: the validation for `--drop-filtered`'s incompatibility with `--write-bitmap-index` (`-b`) occurs too late in the control flow to distinguish between user-requested bitmaps (which should trigger an error) and config-driven bitmaps (which should be silently disabled). The current implementation only checks `write_bitmaps > 0`, which conflates the two cases after configuration has already been read.

The author confirms the plan for v2: restructure the validation to explicitly track whether `--write-bitmap-index` was set on the command line (erroring out if so) versus via configuration (silently disabling it). This fix is a prerequisite for the series to proceed, as the safety mechanism designed to prevent bitmap corruption is currently ineffective. No other changes or responses to the review are mentioned, suggesting the focus remains on addressing this single issue before broader API or safety-guard refinements.
