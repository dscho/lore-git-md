This is a bugfix patch in Patrick Steinhardt’s nine-part refactoring series that moves loose-object writing into the ODB abstraction layer. Patch 6/9 plugs a memory leak in `force_object_loose()`: when the function fails to convert the object’s hash to the repository’s compatibility algorithm, it returns early without freeing the buffer allocated by `odb_read_object_info_extended()`. The fix adds a common exit path that ensures the buffer is always freed. The change is small (18 insertions, 8 deletions) and touches only `object-file.c`. It’s a clear, well-motivated cleanup that fits neatly into the larger ODB refactoring effort.
