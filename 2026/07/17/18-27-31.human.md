This is a **feature** patch series introducing the `--auto-reset[=<where>]` option to `git bisect`. The v2 iteration implements the design settled in the previous discussion, replacing the original boolean `--auto-reset` flag with a parameterized option that accepts `original` (reset to the pre-bisect commit, the default) or `found` (leave the working tree on the first bad commit).

The series consists of three patches. Patch 1 refactors how `git bisect run` reads output from the executed command, avoiding redundant file reopens. Patch 2 adds a `quiet` parameter to `bisect_reset()` to suppress checkout noise during auto-reset. Patch 3 introduces the user-facing option, wires it into both `git bisect start` and `git bisect run`, and updates the `BISECT_AUTO_RESET` state file to store the target commit (`original` or `found`) rather than a boolean flag. The implementation rejects `--auto-reset` when used with `--no-checkout`, since that mode cannot check out either target.

The documentation and tests have been updated to cover both `original` and `found` use cases, including edge cases like interrupted bisects, descriptor errors, and state cleanup. The series is well-scoped, touching only the bisect subsystem, and includes thorough test coverage. The design addresses both automated workflows (scripts, CI pipelines) and interactive debugging by eliminating the need for an explicit `git bisect reset`.
