This is a bug report about `git history fixup` interacting badly with worktrees. Toon Claes describes a minimal reproduction: after running `git history fixup HEAD` in one worktree, a second worktree (created earlier) suddenly shows staged changes it never saw. The commit history itself is correct, but the index of the unrelated worktree is corrupted. The report is clear, includes exact commands and output, and demonstrates the problem without extra noise. If this behavior is unintended, it looks like a real bug that could trip up users who rely on multiple worktrees. Worth watching for follow-up discussion or a patch.
