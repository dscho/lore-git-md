This thread is about Patrick Steinhardt’s nine-patch series refactoring Git’s loose object backend to make it fully self-contained as part of the ongoing ODB abstraction effort. The goal is to move loose-object writing logic from `object-file.c` into `odb/source-loose.c`, eliminating direct calls to `write_loose_object()` and consolidating loose backend internals under the generic `odb_source_write_object()` interface. The series also centralizes object hash computation, compatibility ID handling, object-existence checks, and mtime support in the generic ODB layer, and relocates `force_object_loose()` to its sole caller.

The series is currently blocked by a build-breaking issue identified by SZEDER Gábor and confirmed by Junio C Hamano: an evil merge resolving a function signature mismatch in `odb/source-packed.c` was correctly applied when merging an earlier ODB transaction series into Junio’s `jch` branch, but was accidentally omitted when creating the integration base for this series. As a result, none of the nine patches compile. Junio has acknowledged the oversight and will fix it, which should unblock the series for substantive review. No prior versions exist, and the series is built on top of `jt/receive-pack-use-odb-transaction` and `jk/git-hash-cleanups`.

Key participants are Patrick Steinhardt (author) and SZEDER Gábor (reviewer), with Junio stepping in to address the mechanical issue. The refactoring itself is complete, with the loose backend now fully self-contained except for `odb_source_loose_write_stream`, which remains in `object-file.c` with a TODO for future relocation. No behavior or on-disk format changes are introduced, and the series fixes a memory leak in `force_object_loose()`. Open questions may include the impact of transaction interface changes, the necessity of the new `compat_oid` parameter, and the performance implications of the mtime plumbing. Once the build issue is resolved, reviewers can focus on these aspects.
