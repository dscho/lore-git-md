This is a **feature addition** to `git bisect` that advances the design discussion. The author, Harald Nordgren, accepts Junio C Hamano’s proposal to convert `--auto-reset` from a boolean flag into a parameterized option (`--auto-reset=<where>`) with values `original` (reset to the pre-bisect commit) or `found` (leave the working tree on the first bad commit). The default will be `original`.

The thread is now poised for a v2 patch series that implements the parameterized design. The preparatory refactoring (patch 1) and quiet-checkout addition (patch 2) remain unchanged and uncontroversial. The main work in v2 will be updating the implementation, documentation, and tests to support both `original` and `found` behaviors, including revising the `BISECT_AUTO_RESET` state file to store the target commit rather than a boolean flag. The new tests in `t/t6030-bisect-porcelain.sh` will need to cover both reset behaviors and edge cases such as interrupted bisects or descriptor errors. No other reviewers have weighed in on the design, so the next iteration will likely focus on the technical details of the parameterized implementation.
