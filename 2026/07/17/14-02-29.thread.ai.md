Thread type: patch submission (feature addition)

Core problem or goal
Add a built-in userdiff driver for the Swift programming language so that `git diff` and `git log -p` produce meaningful hunk headers and word-level diffs for `.swift` files without requiring manual `.gitattributes` configuration.

Current status
Queued in `seen` (not `next` or `master`). Junio C Hamano has explicitly stated that the patch requires validation from active Swift users on the mailing list before it can progress further. The v2 patch is now technically complete, addressing all substantive review feedback from v1. The author has provided empirical validation of the regex patterns against Swift’s official grammar (26 declaration forms) and real-world Swift codebases (20,454 hunks across seven projects, 99.9 % accuracy in hunk header identification). Formal testing by Swift users on the mailing list remains the sole blocker.

Key technical details
- Files: `userdiff.c` (new patterns), `Documentation/gitattributes.adoc` (documentation), `t/t4018/` (13 Swift test fixtures).
- New symbols: `builtin_swift_patterns` (funcname and word_regex entries).
- Behavior: replaces generic heuristic with Swift-aware patterns for function declarations and word boundaries. The funcname pattern covers all 26 declaration forms in Swift’s official grammar, structured as attributes → modifiers → declaration keyword, with boundary conditions that prevent false matches (e.g., `initialize(`). The word regex handles Swift identifiers, literals (hexadecimal, octal, binary, floating-point), and operators (`<<=`, `??`, range operators).
- On-disk format: none; purely in-memory regex compilation.
- Test coverage: 13 test cases covering classes, structs, enums, protocols, extensions, actors, attributes, modifiers, generics, failable initializers, and operator functions. Changes since v1: duplicate `RIGHT` tokens in `swift-failable-init`, `swift-init`, and `swift-generic-subscript` test files have been fixed; the word regex has been simplified by removing redundant single-character operator handling, relying on Git’s built-in `PATTERNS` behavior. Regex optimizations: separate patterns for hexadecimal, octal, and binary literals retained to maintain correct digit-range validation; floating-point pattern does not handle `.5` literals (Swift requires a leading digit, e.g., `0.5`).
