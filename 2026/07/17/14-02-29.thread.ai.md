Core problem or goal
Add a built-in userdiff driver for the Swift programming language so that `git diff` and `git log -p` produce meaningful hunk headers and word-level diffs for `.swift` files without requiring manual `.gitattributes` configuration.

Current status
Queued in `seen` (not `next` or `master`). Junio C Hamano has explicitly stated that the patch requires validation from active Swift users before it can progress further. The v2 patch is now technically complete, addressing all substantive review feedback from v1. The author has provided empirical validation of the regex patterns against real-world Swift codebases, but formal testing by Swift users on the mailing list remains pending.

Key technical details
- Files: `userdiff.c` (new patterns), `Documentation/gitattributes.adoc` (documentation), `t/t4018/` (13 Swift test fixtures).
- New symbols: `builtin_swift_patterns` (funcname and word_regex entries).
- Behavior: replaces generic heuristic with Swift-aware patterns for function declarations and word boundaries. The funcname pattern covers all 26 declaration forms in Swift's official grammar.
- On-disk format: none; purely in-memory regex compilation.
- Test coverage: 13 test cases covering classes, structs, enums, protocols, extensions, actors, attributes, modifiers, generics, failable initializers, and operator functions. **Resolved issues**: duplicate `RIGHT` tokens in `swift-failable-init`, `swift-init`, and `swift-generic-subscript` test files have been fixed. The word regex has been simplified by removing redundant single-character operator handling, relying on Git's built-in `PATTERNS` behavior.
- Regex optimizations: The author retained separate patterns for hexadecimal, octal, and binary literals to maintain correct digit-range validation. The floating-point pattern does not handle `.5` literals, as Swift requires a leading digit (e.g., `0.5`), making such cases syntax errors. The current regex structure (separating modifiers from declaration keywords) avoids false matches on lines containing only modifiers (e.g., `public var counter = 0`).

Open questions and loose ends
- **Validation pending**: the patch must still be tested by active Swift users on the mailing list to confirm the regexes accurately capture Swift syntax in real-world usage. This remains the sole blocker for progression to `next`.
- **Empirical validation**: The author provided coverage data from seven real-world Swift projects (20,454 hunks reviewed), showing 99.9% accuracy in hunk header identification. While this demonstrates strong real-world applicability, it does not substitute for formal validation by Swift users on the list.
