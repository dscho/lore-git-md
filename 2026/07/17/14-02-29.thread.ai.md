Core problem or goal
Add a built-in userdiff driver for the Swift programming language so that `git diff` and `git log -p` produce meaningful hunk headers and word-level diffs for `.swift` files without requiring manual `.gitattributes` configuration.

Key technical details
- Files: `userdiff.c` (new `builtin_swift_patterns`), `Documentation/gitattributes.adoc` (documentation), `t/t4018/` (13 Swift test fixtures).
- New symbols: `builtin_swift_patterns` (funcname and word_regex entries).
- Behavior: replaces generic heuristic with Swift-aware patterns for function declarations and word boundaries. The funcname pattern covers all 26 Swift declaration forms (attributes → modifiers → declaration keyword) with boundary conditions to prevent false matches (e.g., `initialize(`). The word regex handles Swift identifiers, literals (hexadecimal, octal, binary, floating-point), and operators (`<<=`, `??`, range operators).
- On-disk format: none; purely in-memory regex compilation.
- Test coverage: 13 test cases in `t/t4018/` covering classes, structs, enums, protocols, extensions, actors, attributes, modifiers, generics, failable initializers, and operator functions. Changes since v1: fixed duplicate `RIGHT` tokens in `swift-failable-init`, `swift-init`, and `swift-generic-subscript` test files; simplified word regex by removing redundant single-character operator handling (relying on Git’s built-in `PATTERNS` behavior). Regex optimizations: separate patterns for hexadecimal, octal, and binary literals retained for digit-range validation; floating-point pattern excludes `.5` literals (Swift requires leading digit, e.g., `0.5`).

Open questions and loose ends
The surface-level suggestion to add a word-level diff test in `t/t4034-diff-words.sh` (proposed by Michael Montalbo) has been declined by Johannes Sixt. Hannes cited the complexity of writing accurate test scripts for word diffs and the disproportionate effort relative to the microproject’s scope. He noted that Swift’s word patterns are straightforward and do not warrant the additional testing that more exotic drivers (e.g., Scheme) received. The patch’s test coverage remains aligned with other language drivers, and the omission does not affect correctness or readiness for integration.
