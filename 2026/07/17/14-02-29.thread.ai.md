Subject: [PATCH] userdiff: add built-in Swift language driver
Series version: standalone patch (v1 posted; v2 expected after review feedback)
Originating author: Shlok Kulshreshtha
Thread type: patch submission (feature addition)

Core problem or goal
Add a built-in userdiff driver for the Swift programming language so that `git diff` and `git log -p` produce meaningful hunk headers and word-level diffs for `.swift` files without requiring manual `.gitattributes` configuration.

Current status
Queued in `seen` (not `next` or `master`). Junio C Hamano has explicitly stated that the patch requires validation from active Swift users before it can progress further. The patch is technically complete but has received **substantive review feedback** that may prompt a v2. Junio and Hannes have informally acknowledged that designing accurate regex patterns for a language’s syntax is non-trivial, but this does not alter the procedural status.

Key technical details
- Files: `userdiff.c` (new patterns), `Documentation/gitattributes.adoc` (documentation), `t/t4018/` (13 new Swift test fixtures).
- New symbols: `builtin_swift_patterns` (funcname and word_regex entries).
- Behavior: replaces generic heuristic with Swift-aware patterns for function declarations and word boundaries.
- On-disk format: none; purely in-memory regex compilation.
- Test coverage: 13 test cases covering classes, structs, enums, protocols, extensions, actors, attributes, modifiers, generics, failable initializers, and operator functions. **Issues noted**: two test files (`swift-failable-init` and `swift-init`) contain the placeholder token `RIGHT` twice, creating ambiguity about which instance the pattern matches; a third test (`swift-generic-subscript`) also duplicates `RIGHT` on the same line (harmless but inconsistent).
- Regex optimizations: Hannes initially suggested (1) replacing `[a-z]+` with explicit Swift keywords to reduce backtracking and (2) merging hexadecimal/octal/binary literal patterns, but later retracted the keyword suggestion as speculative and unnecessary. The floating-point pattern’s handling of `.5` literals remains unaddressed (low impact).

Open questions and loose ends
- **Validation pending**: the patch must still be tested against real-world Swift codebases by active Swift users on the list to confirm the regexes accurately capture Swift syntax.
- **Test ambiguities**: the duplicate `RIGHT` tokens in test fixtures should be resolved for clarity.
- **Regex optimizations**: the author may address the remaining minor suggestions (e.g., literal pattern merging) in a follow-up version, though these are not blockers.
