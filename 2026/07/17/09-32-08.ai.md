This is a refactoring patch series (9 patches) from Patrick Steinhardt, part of the ongoing ODB (object database) abstraction effort. The goal is to move the logic for writing loose objects out of `object-file.c` and into `odb/source-loose.c`, making the loose object backend more self-contained.

The series starts by refactoring `force_object_loose()` to use the generic `odb_source_write_object()` interface instead of directly calling `write_loose_object()`. This involves several preparatory steps: computing object hashes and compatibility IDs in the generic write function, lifting object existence checks out of the loose backend, and adding support for setting mtime during object writes. The series also fixes a memory leak in `force_object_loose()` and updates the in-memory test backend to support the new write interface.

Key technical details include changes to the ODB transaction interface (adding a flags parameter), modifications to how object hashes are computed during writes, and adjustments to the loose backend's internal structure. The series touches 12 files, with the bulk of the changes being the movement of ~400 lines out of `object-file.c` and into `odb/source-loose.c`.

This is built on top of two recent topics (jt/receive-pack-use-odb-transaction and jk/git-hash-cleanups) and requires an evil merge to resolve a conflict in the packed backend's transaction handling. The series appears well-structured and motivated, continuing Patrick's long-running work to make Git's object storage layer more modular. No behavior changes are expected from this refactoring.
