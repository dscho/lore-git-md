This is the third patch in the v7 series that migrates `trust_executable_bit` and `has_symlinks` into `struct repo_config_values` as part of the `the_repository` removal effort. The patch moves the `trust_executable_bit` configuration flag from global scope to repository-scoped storage, introducing a new getter function `repo_trust_executable_bit()` and updating all call sites to use repository-scoped access.

The patch touches five files: `apply.c`, `environment.c`, `environment.h`, `read-cache.c`, and `read-cache.h`. It removes the global `trust_executable_bit` variable, adds the flag to `struct repo_config_values`, and implements the getter function in `environment.c`. The getter includes repository pointer validation and falls back to `the_repository` when necessary. Call sites in `apply.c` and `read-cache.c` are updated to use the new getter, and the `git_default_core_config()` function now writes the configuration value to the repository-specific struct instead of the global variable.

This is a mechanical refactoring with no behavioral changes. The patch follows the established pattern from earlier patches in the series and prepares the codebase for the final patch (4/4), which migrates `has_symlinks`. The inclusion of `Mentored-by` tags reflects prior review and guidance from Christian Couder, Ayush Chandekar, and Olamide Caleb Bello. The patch is uncontroversial and aligns with the broader goal of eliminating global state in Git's configuration handling.
