This is the core client-side implementation patch in the nineteenth iteration of the `git cat-file --batch-command` remote object-info series. It adds the plumbing that lets Git clients query object metadata (currently just size) from a remote repository without downloading the full object.

The patch introduces a new `fetch-object-info.c` file that implements the client-side protocol logic. It sends an `object-info` command over protocol v2, parses the server’s response, and populates an `object_info` struct with the results. Key details: the request is buffered in a `strbuf` before being sent (following the pattern in `fetch-pack.c`), the server must advertise the `object-info` capability, and the client enforces strict validation—each response line must echo the requested OID at the expected position, and malformed responses trigger a fatal error. A new `unrecognized` flag in `struct object_info` marks objects the server does not know about, and the client silently omits unsupported metadata fields (like `%(objecttype)`) rather than failing.

The patch also wires up the transport layer: it adds a `fetch_object_info` vtable entry, implements it for both smart transports and transport helpers, and exposes a public `transport_fetch_object_info()` function. The implementation is security-conscious—it bounds-checks numeric fields, limits batch size, and uses `xcalloc` to avoid uninitialized memory.

This is the eleventh patch in a thirteen-patch series that is now technically complete and queued for `next`. All substantive issues from earlier rounds have been resolved, and the series is on track for graduation to `master` after final cosmetic polish.
