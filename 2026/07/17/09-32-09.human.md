This is the first patch in Patrick Steinhardt’s nine-part refactoring series to move loose-object writing logic into the ODB abstraction layer. It centralizes the computation of compatibility object IDs (used when a repository has a secondary hash algorithm) inside the generic `odb_write_object_ext()` function instead of duplicating it across each ODB backend. The change is mechanical: the loose, files, and in-memory backends now receive a pre-computed compatibility hash (or NULL) rather than generating it themselves. No behavior changes are introduced, and the patch is a clean step toward making the loose backend more self-contained.
