This is a gitweb bugfix patch (v2 of a 2-patch series). Travor Liu addresses the rendering issue where commitdiff index lines with trailing file modes (e.g., `index <old>..<new> 100644`) show full, unlinked object IDs instead of the usual shortened, clickable hashes. The fix reorders the logic in `gitweb/gitweb.perl` to strip the mode before matching object IDs, then reappends it after shortening and linking the hashes. This preserves the mode display while ensuring consistent hash formatting.

The patch incorporates Junio C Hamano’s requested changes from v1: the regression test is now squashed into the implementation patch, and raw `grep` invocations are replaced with `test_grep`/`test_grep !` to align with ongoing test-script hygiene improvements. The test in `t/t9502-gitweb-standalone-parse-output.sh` verifies the fix by checking that the index line for a regular file modification shows linked short blob IDs followed by the mode and file-type annotation, and that the full unlinked form is absent.

Files touched are `gitweb/gitweb.perl` (specifically the `format_extended_diff_header_line` function) and the test script. The change is narrow in scope, with no new symbols introduced and no on-disk format modifications. The commit message clearly explains the root cause (regex order vs. mode handling) and frames the fix as a continuation of prior mobile-overflow work in gitweb.

This v2 appears ready for integration; the author has addressed the maintainer’s procedural feedback without altering the substantive fix. The patch is well-motivated, minimally invasive, and includes sufficient test coverage for the regression. No open questions or controversy remain.
