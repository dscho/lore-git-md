This is the final patch in the nineteenth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. The series is now queued for `next` and ready for graduation to `master`.

This patch makes the client's allow-list for `remote-object-info` placeholders dynamic, adapting to the server's advertised capabilities. Previously, the allow-list was hardcoded to support only `%(objectname)` and `%(objectsize)`, which worked because servers either supported both or neither. As the `object-info` protocol gains new capabilities (e.g., `%(objecttype)`), servers with different Git versions will advertise different feature sets, so the client must now query the server's capabilities and adjust its allow-list accordingly.

The implementation works by mapping protocol options (e.g., `"size"`) to their corresponding placeholders (e.g., `"%(objectsize)"`). When the client requests a format like `%(objectsize) %(objecttype)`, it first checks which options the server supports. If the server only supports `"size"`, the client omits `"type"` from the request, and `%(objecttype)` expands to an empty string in the output (e.g., `"42 "` for a 42-byte object). This matches `git for-each-ref`'s behavior for known but inapplicable atoms. Unknown placeholders (e.g., `%(objectcolor)`) still trigger a fatal error.

The patch also moves `object_info_options` out of `get_remote_info()` so the caller can control which options are requested, and ensures `batch_object_write()` is called even when no attributes are supported, producing a blank line. The `type` option is included in `object_info_options` but always filtered out, allowing tests to verify that unsupported placeholders expand to empty strings. The response header lookup in `fetch_object_info()` now uses an unsorted string list, as the allow-list is no longer kept sorted.

Test coverage is expanded with two new cases: one verifying that requesting only `%(objectname)` echoes the OID back, and another confirming that `%(objectname)` still triggers an existence check on the server. The patch is well-motivated and addresses a clear limitation in the original design. The changes are mechanical and focused, with no behavioral regressions. The series as a whole is technically complete and ready for integration.
