This is a bugfix patch (6/9) in Patrick Steinhardt’s ODB abstraction refactoring series. It plugs a memory leak in `force_object_loose()` that occurs when converting an object to a compatibility hash algorithm fails: the function returns early without freeing the content buffer allocated by `odb_read_object_info_extended()`. The fix adds a common exit path that ensures the buffer is always freed, regardless of where the function returns.

The patch touches only `object-file.c`, changing 18 lines to introduce a `goto`-based cleanup block. This is a targeted, low-risk fix that does not alter behavior—only resource management. The leak itself is small (one buffer per failed conversion), but it is in a code path that could be triggered during repack operations, so plugging it is clearly worthwhile.

Because this is part of a larger refactoring, the patch depends on earlier changes in the series that prepare the ODB interfaces. It is not controversial and looks like a routine correctness fix. Readers following the ODB abstraction effort will want to note it, but it does not introduce new concepts or raise design questions.
