This is the fourth patch in K Jayatheerth’s seven-part GSoC series adding path-related keys to `` `git repo info` ``. It introduces ``path.hooks.absolute`` and ``path.hooks.relative``, which expose the repository’s hooks directory in both absolute and relative forms, respecting the ``core.hooksPath`` configuration.

The implementation is straightforward: two new getter functions call ``repo_git_path_replace(repo, &hooks_path, "hooks")`` and then format the result with ``PATH_FORMAT_CANONICAL`` or ``PATH_FORMAT_RELATIVE``. The patch updates the field table in ``builtin/repo.c``, documents the keys in ``git-repo.adoc``, and adds tests that verify both the standard ``.git/hooks`` fallback and a custom ``core.hooksPath`` override.

Mechanically the patch is clean—no include-order issues, no misleading commit titles, and the tests cover the advertised behavior. The design mirrors the earlier ``path.objects`` and ``path.gitdir`` keys, so it feels consistent within the series. Whether reviewers will prefer ``path.hookdir`` over ``path.hooks`` for naming consistency with existing Git terminology remains an open question, but that is a design-level discussion that has not yet begun. For now, this patch is ready for technical review.
