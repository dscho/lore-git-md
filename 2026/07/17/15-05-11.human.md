This is a small but important bugfix that plugs a memory leak in the transport-helper subsystem. The patch is part of the ongoing GSoC effort to add `git cat-file --batch-command` support for remote object metadata queries (the v19 series summarized in the thread context).

The leak occurs when `disconnect_helper()` is called before the helper process is fully started. In that case, `data->helper` is still NULL, so the existing `FREE_AND_NULL(data->name)` call inside the conditional block is skipped, leaving `data->name` (allocated in `transport_helper_init()`) unfreed. The fix is mechanical: move the `FREE_AND_NULL(data->name)` call outside the conditional so it runs unconditionally on disconnect.

The change is minimal (one line moved), well-explained, and clearly correct. It doesn’t touch any behavior other than memory management, and the commit message includes a link to the original discussion that identified the issue. This is the kind of low-risk, high-value cleanup that belongs in `next` alongside the rest of the series.
