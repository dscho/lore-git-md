This thread is about Toon Claes’s patch series (v1) to speed up the experimental `git last-modified` command by reusing Git’s Bloom filters. The goal is to match the speed of `git log` when querying the last commit that modified files matching a pathspec (including wildcards like `*.c`), reducing runtime from 52 ms to 14 ms on the ziglang/zig repository.

The series is under active review, with key feedback from Junio C Hamano, Taylor Blau, and Jeff King (Peff). Junio and Taylor identified unintended behavioral changes in patch 2/4 (Bloom filter statistics reporting) and a correctness bug in patch 3/4 when `--show-trees` is used, which may invalidate the cover-letter benchmarks. Peff’s latest review doubles down on the `--show-trees` issue, proposing to remove ancestor tree entries from the output rather than disabling the Bloom-filter optimization entirely. This would preserve performance while avoiding misleading results, though it’s a trade-off for an experimental command. Peff also notes a documentation inconsistency around `--show-trees` behavior.

Other open questions include Peff’s design concerns about the public API’s tristate return semantics (patch 1/4) and the maintainability of patch 4/4’s approach to managing `bloom_filter_settings`. The author has acknowledged missing trailers for Peff’s earlier contributions and plans to address them in a reroll. No version updates have been posted yet, and the series remains in review with no merge status. The discussion is substantive, focusing on correctness, performance trade-offs, and long-term maintainability.
