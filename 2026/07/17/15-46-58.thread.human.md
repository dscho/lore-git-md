This thread is about a four-patch series from Toon Claes that speeds up the experimental `git last-modified` command by reusing Git’s Bloom filters. The goal is to match the speed of `git log` when querying the last commit that modified files matching a pathspec (including wildcards like `*.c`). On the ziglang/zig repository, the current implementation is about 3.7 times slower (52 ms vs 14 ms).

The series is under review, with the first version posted and no prior iterations. Key discussions have focused on two main issues: a correctness bug in `--show-trees` handling and a maintainability concern about how Bloom filter settings are managed. Jeff King (Peff) and Taylor Blau have both reviewed the series thoroughly, with Peff raising a design concern about the public API’s return semantics in patch 1/4 and Taylor identifying a correctness bug in patch 3/4. Junio C Hamano also reviewed patch 2/4, pointing out unintended behavioral changes in Bloom filter statistics reporting.

The latest email from Peff resolves the stalled discussion: while his suggestion to refactor how `bloom_filter_settings` are managed is cleaner, he no longer considers it a blocker. However, the `--show-trees` correctness issue must be fixed before the series can proceed. The agreed solution is to filter out ancestor tree entries not covered by the original pathspec using `match_pathspec()`, which preserves the performance benefit while avoiding misleading results. Toon is expected to post a reroll incorporating this fix, along with the previously acknowledged `Helped-by` trailers for Peff. The only remaining open question is whether the second unintended behavioral change in patch 2/4 (skipping counter updates on errors) is intentional or needs correction.
