This thread is about a performance optimization for the experimental `git last-modified` command, which now reuses Git’s Bloom filters to achieve near-parity with `git log` when querying the last commit that modified files matching a pathspec (including wildcards like `*.c`). The series, now at version 4, is complete and ready for integration, with all prior technical feedback resolved.

Toon Claes posted the v4 reroll, incorporating Junio C Hamano’s suggested fix for a test environment interaction in `t8020-last-modified.sh`. The test now explicitly controls `GIT_TEST_COMMIT_GRAPH` to ensure consistent behavior, addressing the issue that caused the series to be ejected from Junio’s `seen` branch. The reroll also includes trace2 instrumentation to verify the Bloom filter fast-path is correctly triggered for wildcard pathspecs, and a final patch restores `bloom_filter_settings` after `prepare_revision_walk()` clears it, ensuring the optimization works as intended.

Key participants include Toon Claes (author), Jeff King (Peff), Junio C Hamano (maintainer), and Taylor Blau. Peff and Taylor provided substantive reviews focusing on correctness, maintainability, and test coverage, while Junio’s feedback was pragmatic, ensuring the test suite behaves reliably. The series achieves a 3.7× speedup without `--show-trees` and a 1.95× speedup with it, and now fully supports wildcard pathspecs. The only remaining loose end is a minor question about whether `--show-trees` should also use trace2 counters, but this is unlikely to block integration.
