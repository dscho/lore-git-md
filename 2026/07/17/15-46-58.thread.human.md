This thread is about Toon Claes’s six-patch series (v2) optimizing the experimental `git last-modified` command by reusing Git’s Bloom filters to speed up queries about the last commit that modified files matching a pathspec. The series is now complete and under review, with all prior feedback addressed.

The key goal is to make `git last-modified` nearly as fast as `git log` for these queries, achieving up to a 3.7× speedup (60.7 ms → 16.2 ms) without `--show-trees` and a 1.95× speedup (61.9 ms → 31.8 ms) with `--show-trees` on the ziglang/zig repository. The v2 reroll resolved all technical blockers: the public API was refactored to use clearer boolean returns, unintended behavioral changes in Bloom filter statistics were reverted, and a correctness bug in `--show-trees` was fixed. The series also added two new patches—one introducing helpers for `--show-trees` filtering and another adding a test to verify Bloom filter behavior with `--show-trees`.

The latest patch (6/6) addresses a critical edge case: wildcard pathspecs (e.g., `*.c`) would previously break the Bloom filter optimization because `prepare_revision_walk()` clears the `bloom_filter_settings` field. The fix restores the settings pointer after the revision walk, ensuring the optimization works for all pathspec types. The series touches `revision.c`, `revision.h`, `bloom.c`, `bloom.h`, `builtin/last-modified.c`, and the test suite, introducing new public functions like `revs_maybe_changed_in_bloom()` and `revs_maybe_changed_in_bloom_with_parents()`. Reviews from Jeff King, Junio C Hamano, and Taylor Blau have been substantive, focusing on correctness, maintainability, and performance, and all concerns have been addressed. The series is now ready for final review, with no known technical blockers remaining.
