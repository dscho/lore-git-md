This thread is about optimizing the experimental `git last-modified` command by reusing Git’s Bloom filters to match the speed of `git log` when querying the last commit that modified files matching a pathspec (including wildcards like `*.c`). The series, now at version 3, achieves a 3.7× speedup without `--show-trees` and a 1.95× speedup with it on the ziglang/zig repository, bringing performance nearly to parity with `git log`.

Toon Claes posted the final version of the six-patch series, addressing all prior feedback. The key improvements include fixing a `--show-trees` correctness bug, ensuring wildcard pathspec support, and adding trace2 instrumentation to verify the Bloom filter fast-path is correctly triggered. The latest patch resolves a specific edge case where wildcard pathspecs lost their Bloom filter settings during `prepare_revision_walk()`, forcing expensive diff operations. The fix restores the settings and adds a trace2 counter to confirm the optimization works as intended. All technical concerns from reviewers—including Jeff King, Junio C Hamano, and Taylor Blau—have been resolved, and the series is now ready for integration.

The optimization is complete, with no remaining open questions or loose ends that would block merging. The series touches `revision.c`, `bloom.c`, and `builtin/last-modified.c`, introducing new helpers like `revs_maybe_changed_in_bloom_with_parents()` to handle parent directory checks for `--show-trees`.
