This thread is about a performance optimization for the experimental `git last-modified` command, which now reuses Git’s Bloom filters to achieve near-parity with `git log` when querying the last commit that modified files matching a pathspec (including wildcards like `*.c`). The series, now at v4, is complete and ready for integration, with all prior feedback addressed.

Toon Claes authored the series, which delivers a 3.7× speedup without `--show-trees` and a 1.95× speedup with it on the ziglang/zig repository. The latest patch (5/4) adds a pre-filter in `maybe_changed_path()` that uses the Bloom filter machinery to discard commits early if they definitely didn’t touch any relevant path, reducing expensive tree diffs. For `--show-trees`, it also checks parent directories to avoid false negatives when a commit touches a sibling file. The test suite now verifies the Bloom filter fast-path works correctly with `--show-trees` and matches the commit-graph-disabled baseline.

Key reviewers—Jeff King, Junio C Hamano, and Taylor Blau—have all signed off on the technical approach. Jeff King’s concerns about API design and maintainability were resolved by refactoring the Bloom filter helpers, Junio’s test environment fix was incorporated, and Taylor Blau’s `--show-trees` correctness fix is now implemented. The series is under review and appears ready for merging, with no open technical objections. The only minor loose ends are documentation clarity for `--show-trees` and the naming of a helper function, neither of which are blocking.
