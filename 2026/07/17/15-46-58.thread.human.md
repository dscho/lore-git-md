This thread is about a six-patch series (v3) from Toon Claes that optimizes the experimental `git last-modified` command by reusing Git’s Bloom filters to speed up queries about the last commit modifying files matching a pathspec (including wildcards like `*.c`). The series has now reached its final form, with all technical feedback addressed and performance nearly matching `git log`—a 3.7× speedup without `--show-trees` and a 1.95× speedup with it on the ziglang/zig repository.

The latest email covers the fifth patch, which adds a Bloom-filter pre-filter to avoid unnecessary tree diffs. This patch is purely internal, using helpers introduced earlier in the series to check whether a commit *might* have modified any path matching the user’s query. For `--show-trees`, it also checks parent directories to avoid false negatives. A new test verifies the optimization works correctly with `--show-trees`, and trace2 instrumentation (added in v3) confirms the Bloom filter fast-path is triggered as expected. The series is now complete, with no open questions, and ready for integration.
