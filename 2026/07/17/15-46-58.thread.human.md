The key changes involve refactoring the Bloom filter API in `revision.c` to avoid redundant lookups and support wildcard pathspecs (e.g., `*.c`). Jeff King (Peff) initially raised a design concern about the public API’s tristate return values, but after discussion, Toon agreed to refactor it to use a boolean return (`false` = definitely unchanged, `true` = possibly changed) while keeping the internal tristate logic for statistics. Junio C Hamano and Taylor Blau identified unintended behavioral changes in patch 2/4—one of which (incrementing a counter even when no Bloom key vectors exist) is now agreed to be reverted. Peff confirmed this approach is sound, though a minor edge case with directory queries remains. Patch 4/4’s approach to restoring Bloom filter settings after `prepare_revision_walk()` clears them is acknowledged as fragile but accepted as non-blocking.
