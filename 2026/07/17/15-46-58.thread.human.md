This thread is about Toon Claes’s four-patch series to speed up the experimental `git last-modified` command by reusing Git’s Bloom filters. The goal is to match the speed of `git log` when querying the last commit that modified files matching a pathspec, including wildcards like `*.c`. The current implementation is about 3.7 times slower, and this series aims to close that gap.

The series is under review, with most technical issues resolved. Junio C Hamano and Taylor Blau identified and agreed on fixes for unintended behavioral changes in Bloom filter statistics reporting, and a correctness bug in `--show-trees` was addressed by filtering out ancestor tree entries not covered by the original pathspec. Jeff King (Peff) raised a design concern about the public API’s return semantics in patch 1/4, suggesting a boolean return for clarity, and a maintainability issue in patch 4/4 regarding how `bloom_filter_settings` is managed. The latter is the last open question: whether to keep the current approach of restoring the settings after `prepare_revision_walk()` clears them or adopt Peff’s suggestion to manage the settings pointer in the `last-modified` struct. Junio’s recent email nudges the thread to clarify whether the series is ready as-is or needs further revision. Toon has acknowledged missing trailers for Peff’s contributions and plans to add them in a reroll. No new test files were added, but the cover-letter benchmarks should now reflect the corrected `--show-trees` behavior.
