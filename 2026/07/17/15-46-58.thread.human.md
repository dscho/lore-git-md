This thread is about Toon Claes's patch series to speed up the experimental `git last-modified` command by reusing Git's Bloom filters. The v3 series is complete, achieving a 3.7× speedup for wildcard pathspec queries like `*.c` and fixing correctness issues with the `--show-trees` option. All prior technical feedback has been addressed, including design concerns from Jeff King and test coverage requests from Taylor Blau and Junio C Hamano.

The series was briefly in Junio's `seen` branch but was ejected after CI revealed a test failure in `t8020-last-modified.sh` under standard Git test environment variables. The failure is reproducible locally and stems from an interaction where the test script's global `GIT_TEST_COMMIT_GRAPH=1` setting overrides the `-c core.commitGraph=false` baseline. Junio's latest email provides a straightforward fix: explicitly unset `GIT_TEST_COMMIT_GRAPH` for the baseline case and set it to `1` for the commit-graph-enabled case. This is a minor but necessary correction to ensure the test reliably exercises both code paths.

The series is otherwise ready for integration. The only remaining loose end is this test environment fix; once applied, the series should be clear to merge. Key participants include Toon (author), Jeff King (design review), Taylor Blau (correctness and test coverage), and Junio (maintainer feedback). The optimization is part of Git's ongoing effort to improve performance for experimental commands.
