This thread is about Toon Claes's patch series (`v1`) to speed up the experimental `git last-modified` command by reusing Git's Bloom filters, aiming to match the performance of `git log` (14 ms vs. 52 ms on the ziglang/zig repository). The series touches `revision.c`, `revision.h`, and `builtin/last-modified.c`, introducing new public functions like `revs_maybe_changed_in_bloom` to optimize pathspec queries, including wildcards like `*.c`.

Key progress has been made since the initial posting. The most critical issue—a correctness bug in `--show-trees` where ancestor tree entries (e.g., `d/`) appeared for subpath queries (e.g., `d/a`)—is now resolved in principle. Taylor Blau and Jeff King agreed on a design that filters out uncovered paths in `add_path_from_diff()` using `match_pathspec()`, preserving the performance gains while avoiding misleading results. Jeff King raised a minor concern about whether `match_pathspec()` aligns with `tree-walk.c:do_match()`, but this is a pre-existing oddity and not a blocker. A quirk remains where querying a directory (e.g., `Documentation/technical/`) retains both the directory and its contents, but this is deemed acceptable for an experimental command.

Other open questions remain. Jeff King's review of patch 1/4 still questions the tristate return semantics of `check_maybe_different_in_bloom_filter` (returning `0`, `1`, or `-1`), suggesting a boolean return for clarity. Patch 2/4's unintended behavioral change—skipping counter updates on `bloom_filter_contains_vec()` errors—is unresolved, though Junio C Hamano and Taylor Blau agreed the first unintended change (incrementing `count_bloom_filter_not_present` without key vectors) should be reverted. Jeff King also proposed an alternative design for patch 4/4 to avoid restoring `bloom_filter_settings` after `prepare_revision_walk()` clears it, favoring a more maintainable approach where `last-modified` manages its own settings pointer. The author has yet to address missing trailers for Jeff King's contributions.

Participants include Toon Claes (author), Jeff King (substantive reviews on API design, correctness, and maintainability), Junio C Hamano (maintainer, focused on behavioral regressions), and Taylor Blau (substantive reviews on correctness, test coverage, and performance trade-offs). The series is under active review, with no new version posted yet. The next steps are likely a reroll incorporating the agreed fixes for `--show-trees`, addressing the unresolved behavioral changes, and clarifying the API design questions.
