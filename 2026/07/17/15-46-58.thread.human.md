This thread is about Toon Claes’s patch series to speed up the experimental `git last-modified` command by reusing Git’s Bloom filters. The series is now in its fourth version and is ready for integration. The key improvement is a 3.7× speedup (from 60.7 ms to 16.2 ms) when querying the last commit that modified files matching a pathspec, including wildcards like `*.c`, bringing performance nearly to parity with `git log`.

The latest update, v4, incorporates Junio C Hamano’s fix for a test environment issue that caused CI failures in v3. The test now explicitly controls `GIT_TEST_COMMIT_GRAPH` to ensure consistent behavior, regardless of the broader test environment. All previously identified technical feedback—including the `--show-trees` correctness fix, wildcard pathspec support, and trace2 instrumentation—has been addressed. The series touches `revision.c`, `bloom.c`, and `builtin/last-modified.c`, introducing new helpers like `revs_maybe_changed_in_bloom_with_parents()` to handle directory queries correctly.

The only remaining loose ends are minor: a maintainability concern about how `bloom_filter_settings` is managed (acknowledged but non-blocking), and a follow-up question about whether the `--show-trees` test should use trace2 counters for consistency. Jeff King and Taylor Blau have reviewed the series substantively, focusing on correctness and maintainability, while Junio’s feedback has been pragmatic, ensuring the tests are robust. The series is now complete and awaiting final integration.
