The experimental `git last-modified` command is being optimized to match the speed of `git log` when querying the last commit that modified files matching a pathspec (including wildcards like `*.c`). The current v1 patch series from Toon Claes reuses Git’s Bloom filter machinery to achieve this, reducing runtime from 52 ms to 14 ms on the ziglang/zig repository. The series is under active review, with all major technical issues now resolved.

Key participants—Toon Claes (author), Jeff King (Peff), Junio C Hamano (maintainer), and Taylor Blau—have converged on the remaining fixes needed for a reroll. The most critical issue, a correctness bug in `--show-trees` output when using Bloom filters, will be addressed by filtering ancestor tree entries not covered by the original pathspec using `match_pathspec()`. Jeff King’s design concern about the public API’s tristate return semantics has been resolved: Toon will refactor the interface to use a boolean return (`false` = definitely unchanged, `true` = possibly changed) while preserving the internal logic. Junio’s review also identified two unintended behavioral changes in Bloom filter statistics reporting, one of which (incrementing counters when no key vectors exist) is agreed to be reverted; the other (skipping counter updates on errors) remains unresolved but is not considered a blocker. The series is now waiting for a reroll incorporating these changes, with no further open questions expected to delay progress.
