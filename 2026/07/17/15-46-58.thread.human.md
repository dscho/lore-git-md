The experimental `git last-modified` command is now poised for integration after a fourth iteration that resolves the last technical hurdle. Originally proposed by Toon Claes, the series reuses Git’s Bloom filter machinery to speed up queries about the last commit that modified files matching a pathspec—including wildcards like `*.c`—by up to 3.7×. The latest version, v4, applies a one-line fix suggested by Junio C Hamano to a test environment interaction that had blocked v3, ensuring the test suite behaves consistently regardless of broader CI settings.

The optimization is complete: it fully supports wildcard pathspecs, fixes a correctness bug in `--show-trees` (which now properly filters ancestor tree entries), and includes trace2 instrumentation to verify the Bloom filter fast-path is correctly triggered. Benchmarks on the ziglang/zig repository show the command now performs nearly as well as `git log`, with runtime dropping from 60.7 ms to 16.2 ms for simple queries and from 61.9 ms to 31.8 ms when `--show-trees` is enabled. The changes are confined to the experimental command and its supporting code in `revision.c`, `bloom.c`, and the test suite, with no impact on the on-disk format or other Git commands.

All substantive feedback from earlier iterations has been addressed. Jeff King, Taylor Blau, and Junio reviewed the design and implementation, with Taylor identifying the `--show-trees` correctness bug and Junio providing the test fix that unblocked the series. The only lingering discussion—a maintainability concern about how `bloom_filter_settings` is restored after `prepare_revision_walk()`—was acknowledged as non-blocking, and the current approach was accepted as sufficient. The series is now ready for Junio to pick up, with all tests passing and the public API cleanly exposed.
