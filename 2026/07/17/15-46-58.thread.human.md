This thread is about a patch series from Toon Claes that optimizes the experimental `git last-modified` command by reusing Git’s Bloom filters to speed up queries about the last commit modifying files matching a pathspec (including wildcards). The v2 reroll, posted after addressing all feedback from v1, achieves a 3.7× speedup (60.7 ms → 16.2 ms) without `--show-trees` and a 1.95× speedup (61.9 ms → 31.8 ms) with `--show-trees` on the ziglang/zig repository, bringing performance nearly to parity with `git log`.

The series is now under review and consists of six patches, with all previously identified technical blockers resolved. Key improvements include a refactored public API with clearer boolean returns, a fix for the `--show-trees` correctness bug (filtering ancestor tree entries not covered by the original pathspec), and restored Bloom filter statistics behavior. The latest patch (4/6) introduces `revs_maybe_changed_in_bloom_with_parents()`, a new function that extends Bloom filter checks to include parent directories of queried paths, enabling `git last-modified --show-trees` to correctly report modifications to tree entries containing the pathspec. This patch is well-motivated, minimal, and directly addresses the correctness requirement identified in v1.

The main participants are Toon Claes (author), Jeff King (Peff), Junio C Hamano (maintainer), and Taylor Blau, all of whom have provided substantive reviews focusing on API design, correctness, and maintainability. The series is now complete and ready for further review, with no further rerolls expected unless new substantive feedback emerges. The only remaining loose ends are minor documentation inconsistencies and a maintainability concern about Bloom filter settings management, both of which are acknowledged but non-blocking.
