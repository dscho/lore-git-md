This is the second patch in Phillip Wood’s two-patch bugfix series for interactive rebase (`rebase -i`). It addresses a specific edge case: when a `fixup -c` command is followed by a skipped fixup or squash command, the editor is not opened to allow the user to edit the commit message, breaking the expected workflow.

The patch modifies `sequencer.c` to track whether any `fixup -c` command exists in the current chain of fixup/squash commands, not just whether a squash command was seen. This ensures that the editor is launched when needed, even if the final command in the chain is skipped. The fix is minimal and surgical: it introduces a new helper function `seen_fixup_edit_msg()` to check for `fixup -c` commands and updates `commit_staged_changes()` to use this check alongside the existing squash check.

The test coverage is thorough, adding 47 lines to `t/t3437-rebase-fixup-options.sh` to verify two scenarios: skipping the final fixup command in a chain containing `fixup -c`, and skipping a later fixup command in the same chain. Both tests confirm that the editor is opened and the commit message is correctly updated. The tests are well-structured and clearly demonstrate the regression and the fix.
