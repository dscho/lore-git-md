This is a follow-up in the ongoing discussion about the performance of `git last-modified`. Toon Claes clarifies a mix-up in earlier reports: the current patch from Jeff King (Peff) addresses the slowdown Gusted reported for single-file queries, but does *not* fix a separate, older performance issue Gusted raised about directory-wide queries. That older issue remains unaddressed.

Toon also shares implementation details about Forgejo’s current fallback (a `git log` pipeline that reconstructs last-modified commits for every file in a directory) and suggests that Forgejo could gain efficiency by piping `git last-modified` output into the new `git format-rev` command (introduced in Git 2.55). He hasn’t benchmarked this yet, but the idea is to replace the multi-step `git log` + `git cat-file` dance with a single, optimized pipeline. The email is light on new technical content but keeps the thread moving by separating the two distinct performance problems and offering a potential path forward for Forgejo.
