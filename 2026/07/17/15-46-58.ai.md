This is a performance optimization for the experimental `git last-modified` command, part of a four-patch series from Toon Claes. The goal is to make `git last-modified` as fast as `git log` when querying the last commit that modified files in a directory, by reusing Git’s Bloom filter machinery more effectively.

The series starts with a small refactoring in `revision.c` (patch 1) to deduplicate a Bloom-key precondition check. Patch 2 then exposes a new helper function, `repo_may_have_commit_with_changes`, that lets callers check whether a commit’s Bloom filter might contain changes for a given pathspec without looking up the filter twice. Patch 3 wires this helper into `git last-modified`, cutting its runtime by roughly 3.5× on the ziglang/zig repository (from 52 ms to 14 ms). Patch 4 adds a further optimization for wildcard pathspecs by caching per-path Bloom filters.

The commit message includes concrete benchmarks and reproduces the exact `git log` invocation that was previously faster, making the motivation clear. The changes are confined to `revision.c`, `revision.h`, and `builtin/last-modified.c`; no other subsystems are touched. The series looks well-structured, with each patch building on the previous one, and the code appears to be a straightforward reuse of existing Bloom-filter logic rather than a novel algorithm.
