This is the nineteenth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`, enabling clients to query object metadata (size, and eventually type) from remote repositories without downloading full objects. The series is now technically complete and ready for `next`, with all substantive issues resolved in prior versions.

This revision (v19) introduces three key changes: (1) **a new commit** (`protocol-caps: check object existence regardless of the attributes requested`) that ensures bare OID requests trigger an existence check on the server, avoiding lazy-fetching while maintaining robustness; (2) **corrected response grammar** in `gitprotocol-v2.adoc` to match the implementation’s actual behavior; and (3) **input validation** in `fetch-object-info.c` to ensure each response line echoes the requested OID at its expected position. The series also squashes two v18 commits into a single patch (`cat-file: add remote-object-info to batch-command`) and fixes a session-state bug where the default format for `remote-object-info` could leak into subsequent `info` commands.

The implementation remains focused on its initial scope (size-only queries) but is designed for extensibility. The dynamic allow-list system (`remote_allowed_atoms`) now adapts to the server’s advertised capabilities, and the client silently omits unsupported placeholders (e.g., `%(objecttype)`) rather than failing. Security measures include a 10,000-object batch limit, 8KB URL length cap, and strict bounds-checking in response parsing. Tests cover edge cases like missing objects, unsupported protocols, and malformed OIDs, with 747 lines of new tests in `t/t1017-cat-file-remote-object-info.sh`.

The series is authored by Pablo Sabater (7/13 patches), with contributions from Eric Ju (3/13) and Calvin Wan (3/13). Junio Hamano’s prior concerns about robustness (e.g., `%(objectname)`-only requests) and security (bounds-checking) have been addressed, and the GitHub CI run shows no failures. Minor nits from v18—such as alphabetical ordering in `commands[]` and `Makefile`—remain unresolved but are cosmetic. The series is queued for `next` and appears ready for graduation to `master` after final polish.
