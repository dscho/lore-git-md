This is the tenth patch in the nineteenth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. The series is queued for `next` and targets the smart protocol v2 `object-info` capability.

This patch enables servers to advertise which object-info attributes they support (currently only `size`) when the `transfer.advertiseobjectinfo` configuration is enabled. The change is minimal: the `object_info_advertise` function in `serve.c` now appends `"size"` to the `value` strbuf if the feature is advertised, allowing clients to dynamically determine what metadata they can query. The patch is authored by Calvin Wan but carries sign-offs from Eric Ju and Pablo Sabater, reflecting the collaborative refinement of the series.

The patch is a direct response to earlier review feedback that clients should not blindly request unsupported attributes. By advertising supported features, the server enables clients to tailor their queries, avoiding unnecessary round-trips or fallback to full fetches. The implementation remains conservative: only `size` is advertised, and the feature is disabled by default (`advertise_object_info = 0`), requiring explicit opt-in via configuration.

No behavioral changes are introduced beyond the advertisement itself; the patch is purely preparatory for client-side logic that will use this information. The change is mechanical and aligns with the series' broader design goal of extensibility without modifying core protocol behavior. The commit message succinctly states the purpose and scope, and the patch itself is trivial, touching only five lines in a single function.
