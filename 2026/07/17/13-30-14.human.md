This is the sixth patch in K Jayatheerth’s seven-patch GSoC series adding path-related keys to `git repo info`. It introduces `path.grafts.absolute` and `path.grafts.relative`, exposing the location of the repository’s grafts file in both absolute and relative formats. The implementation respects the `GIT_GRAFT_FILE` environment variable override, mirroring the behavior of `git rev-parse --git-path info/grafts` but in a structured, scriptable way.

The patch is mechanically clean: it adds the two new keys to the `repo_info_field` table in `builtin/repo.c`, implements the corresponding getter functions (`get_path_grafts_absolute` and `get_path_grafts_relative`) using `repo_get_graft_file()` and the existing `format_path()` helper, updates the documentation in `Documentation/git-repo.adoc`, and extends the test suite (`t/t1900-repo-info.sh`) to verify standard behavior and environment-variable overrides. The commit message clearly states the motivation—external toolchains managing legacy history splices need a clean way to query the grafts file location—and the code follows the established pattern from earlier patches in the series.

No substantive feedback has been posted yet, so the design remains unchallenged. Reviewers may still suggest renaming the key (e.g., `path.graft-file` instead of `path.grafts`) for consistency with Git’s existing terminology, but the patch itself is ready for technical review. It is part of a well-structured, self-contained GSoC effort that has already addressed all mechanical issues raised in the first iteration.
