This thread is about adding built-in Swift language support to Git’s userdiff system, so `git diff` and `git log -p` can produce meaningful hunk headers for `.swift` files without manual configuration. The patch, originally submitted by Shlok Kulshreshtha, is currently queued in Junio’s `seen` branch but needs validation from active Swift users before it can move forward.

Shlok has now addressed the substantive review feedback from Johannes Sixt (Hannes). The test cases that previously had ambiguous placeholder tokens now clearly mark which instance the pattern should match. Shlok also explained why the current regex structure—keeping modifiers separate from declaration keywords—is better than enumerating all Swift keywords: it avoids false matches on lines containing only modifiers. The regex for numeric literals remains split to ensure correct digit-range validation, and the floating-point pattern correctly omits `.5` since Swift requires a leading digit. The word regex was simplified by removing redundant single-character operator handling.

To demonstrate real-world accuracy, Shlok manually reviewed over 20,000 hunks from seven popular Swift projects and found that 99.9% of hunk headers correctly identified a declaration. The upcoming v2 will include these fixes, a reworded attribute description, and a changelog. While the patch is technically ready, Junio has made it clear that it still needs testing by Swift users on the mailing list before it can progress.
