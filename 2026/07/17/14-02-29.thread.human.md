This thread is about adding a built-in Swift language driver to Git’s userdiff system, allowing `git diff` and `git log -p` to produce meaningful hunk headers and word-level diffs for `.swift` files without manual configuration. The patch, now in its second version, is fully reviewed and queued in `next` for integration testing, with no outstanding technical concerns.

The patch adds Swift-aware patterns to `userdiff.c`, documents the new driver in `gitattributes.adoc`, and includes 13 test cases covering Swift’s diverse declaration forms. All substantive review feedback from the first version—including test ambiguities and regex optimizations—has been addressed, and the maintainer, Junio C Hamano, has declared it technically complete. Johannes Sixt’s explicit acknowledgment of the second version closes the review loop, leaving only a brief waiting period before graduation to `master`.

Michael Montalbo, a Swift user, recently tested the patch and confirmed it works as intended. His feedback is narrowly focused: while the patch thoroughly tests hunk header generation, it doesn’t include a word-level diff test in `t/t4034-diff-words.sh`, a script used to verify how other language drivers split identifiers and literals. Montalbo suggests adding such a test to align Swift with the testing rigor applied to other drivers. This is a surface-level improvement—constructive but not blocking—and the patch remains ready for integration.
