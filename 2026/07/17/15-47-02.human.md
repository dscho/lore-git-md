This is the final patch in Toon Claes’s four-part series optimizing the experimental `git last-modified` command by reusing Git’s Bloom filters. The series as a whole aims to close the performance gap between `git last-modified` and `git log` when querying the last commit that modified files in a directory.

This patch specifically addresses a corner case with wildcard pathspecs like `*.c`. The `prepare_revision_walk()` function clears the `bloom_filter_settings` field when it encounters a pathspec that cannot be converted into a Bloom key, which breaks the per-path Bloom filter lookups that the earlier patches in the series rely on. The fix is simple: restore the Bloom filter settings after `prepare_revision_walk()` runs, ensuring that wildcard pathspecs continue to benefit from the Bloom filter optimizations. The change is confined to `builtin/last-modified.c` and adds just eight lines of code.

The patch is a targeted fix for an edge case that would otherwise degrade performance for wildcard queries. It rounds out the series cleanly, ensuring that the 3.5× speedup reported in the cover letter applies uniformly across all pathspec types. The commit message is concise but clear about the problem and the solution, and the code itself is straightforward. No new tests are added, but the existing benchmarks in the cover letter cover the performance improvement. This looks like a well-considered, low-risk addition to a series that already appears solid.
