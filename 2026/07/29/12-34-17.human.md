This is the tail end of a GSoC patch series that extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder when querying object metadata from a remote repository. The series is small (five patches) and builds directly on Eric Sunshine’s recently merged remote-object-info infrastructure.

The author, Pablo Sabater, and reviewer, Chandra Pratap, have reached agreement on the only substantive feedback: reordering the patches so the client-side generalization (dynamically requesting all supported options) lands first, making the subsequent type-specific patches easier to follow. Pablo has accepted the suggestion and will send a v2 with the new ordering. All other review points—style nits, test portability, documentation wording, and test restructuring—have already been addressed in the current v1.

The scope is intentionally narrow: only object type is supported, because it is the last piece of metadata guaranteed to match between client and server after a fetch. Other candidates (disk size, delta base, object mode) are explicitly ruled out as unreliable or context-dependent. The series touches protocol capability advertisement, client request logic, server-side transmission, and client-side parsing, plus test and documentation updates. No on-disk format changes are involved.

This looks like a clean, well-scoped increment that should be ready for maintainer consideration once v2 is posted.
