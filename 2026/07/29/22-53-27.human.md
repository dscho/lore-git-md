This is a brief follow-up in the ongoing review of Pablo Sabater’s GSoC series adding `%(objecttype)` support to `git cat-file --batch-command` for remote-object-info queries. Karthik Nayak retracts his earlier design question about whether the server should transmit object type as a string or integer: after re-reading the code, he confirms the server *does* send the type as a string (e.g., `"blob"`, `"tree"`), and the client parses it with `type_from_string()`. The question was based on a misreading of the patch context, not on any actual mismatch or safety issue. No code changes are needed; the implementation is correct as-is. This clears the last open technical point on patch 2, leaving only advisory feedback (commit-message wording and style nits) already addressed in the thread. The series remains on track for v2 with patch reordering and optional robustness tests.
