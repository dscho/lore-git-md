This is the final patch in brian m. carlson’s RFC series proposing a breaking change for Git 3.0: **Git will accept hex object IDs only in lowercase**. The earlier five patches laid the infrastructure; this one flips the switch in “breaking changes mode” (the compile-time flag that will be enabled in Git 3.0).

The patch itself is small: it defines `HEX_KIND_OID` as `HEX_KIND_LOWER` when `WITH_BREAKING_CHANGES` is set, updates `BreakingChanges.adoc` to document the new requirement, and fixes the one existing test (`t5324`) that relied on an uppercase hex character. A new test in `t1503` verifies that `git rev-parse --verify` now rejects uppercase object IDs.

The motivation remains the same as in the cover letter: Git has always emitted lowercase hex, but accepting both cases has led to security assumptions in external tools (e.g., Gitolite, example hooks) that assume hex uniqueness. Only one test in the entire suite fails, suggesting minimal existing reliance on uppercase parsing.

This patch is the payoff of the series—it’s where the actual behavior change happens. The implementation is clean and the test coverage is adequate, but the real question is still open: **does the project want this breaking change at all?** The series is explicitly an RFC, so expect discussion to focus on that question rather than on the code itself.
