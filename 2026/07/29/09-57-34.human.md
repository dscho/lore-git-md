This is a surface-level review of the third patch in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series builds on Eric Sunshine’s recently merged work and is now under active review.

The patch itself is a small, mechanical refactoring in `fetch-object-info.c` that replaces a hardcoded request for the "size" option with a loop that dynamically sends every option in the `object_info_options` list. The change is safe because the list has already been filtered to include only capabilities the server advertises, and it prepares the client to handle the "type" field introduced in earlier patches. The reviewer, Chandra Pratap, suggests two minor style improvements: tightening the comment wording and using the `for_each_string_list_item()` macro instead of an explicit loop. Neither suggestion affects functionality, and both are typical of the project’s preference for idiomatic code.

This patch is part of a well-scoped, five-patch series that adds end-to-end support for object type metadata in remote-object-info queries. The series is narrowly focused on object type (the last piece of metadata guaranteed to match between client and server) and explicitly excludes other fields like disk size or object mode as unreliable or context-dependent. Earlier feedback on the series has been constructive and technical, with no objections to the core functionality. The only substantive issue raised so far is an out-of-bounds array access in patch 2, which the author will likely address in a follow-up.

For a reader following Git development, this patch is a low-risk, incremental step in a larger effort to unify local and remote object queries. The series looks well-crafted, with clear commit messages, thorough test coverage, and a narrow scope that avoids controversy. If the remaining feedback is addressed, it seems likely to be merged.
