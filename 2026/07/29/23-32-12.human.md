This is the third patch in brian m. carlson’s six-part RFC series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The patch extends the infrastructure introduced in the first two patches by modifying `hex_to_bytes()` to accept an `enum hexkind` parameter, allowing callers to specify whether they want to accept mixed-case hex or enforce lowercase-only parsing. For now, all callers continue to use `HEX_KIND_MIXED`, so runtime behavior is unchanged.

The patch touches seven files: `hex-ll.c`/`hex-ll.h` (the core implementation), plus callers in `builtin/index-pack.c`, `diagnose.c`, `http-push.c`, `notes.c`, and `object-file.c`. Each caller is updated to pass `HEX_KIND_MIXED`, preserving the existing behavior. The changes are mechanical and do not introduce test failures, consistent with the series’ strategy of separating infrastructure from enforcement.

This patch is a stepping stone toward the eventual goal of enforcing lowercase-only parsing in Git 3.0. It does not itself change behavior, but it lays the groundwork for later patches that will switch specific contexts (like `object-name.c`) to `HEX_KIND_LOWER`. The series remains in the RFC stage, explicitly seeking feedback on whether the project wants this breaking change at all. So far, no substantive technical review has occurred.
