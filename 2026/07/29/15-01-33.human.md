The patch introduces a small but important optimization to `has_conflict_markers()` in `merge-ll.c`: it now checks for binary content early and aborts the scan if the file is binary, avoiding unnecessary line-by-line processing of large binary files. The change is minimal (three lines added) and self-contained, touching only the helper function that the `--resolved` option uses to detect remaining conflict markers.

The motivation is clear: without this check, `git add --resolved` could waste time scanning binary files that cannot contain conflict markers, degrading performance in repositories with large binaries. The fix is straightforward and aligns with Git’s existing `buffer_is_binary()` helper, which is already used elsewhere to avoid treating binary data as text. No behavior changes are introduced—binary files were already skipped by the original implementation (they are staged as resolved without marker checks), so this is purely a performance tweak.
