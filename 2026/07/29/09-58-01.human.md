This is a review comment on the fourth patch in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series builds on Eric Sunshine’s recently merged work and is narrowly scoped to object type metadata, which is the last piece of metadata guaranteed to be identical on client and server after a fetch.

Chandra Pratap’s feedback is surface-level but constructive. The patch currently updates an existing test to verify that `%(objecttype)` now works, replacing an earlier test that expected an empty string for unsupported placeholders. Chandra suggests splitting this into two tests: one to confirm that "type" is supported, and another to preserve the original behavior for *unsupported* placeholders (e.g., `%(objectsize:disk)` or future extensions). This would make the test suite more robust and easier to extend, as new placeholders could be added without modifying existing tests. The suggestion is a minor improvement to test clarity and maintainability, not a blocker for the patch itself. No technical issues are raised, and the feedback aligns with the series’ goal of clean, forward-compatible design.
