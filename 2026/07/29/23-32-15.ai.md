This is the final patch in brian m. carlson’s RFC series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. It activates the enforcement mechanism introduced in the earlier infrastructure patches by defining `HEX_KIND_OID` as `HEX_KIND_LOWER` when `WITH_BREAKING_CHANGES` is enabled, thereby rejecting uppercase hex in object ID parsing. The patch updates `Documentation/BreakingChanges.adoc` to document the change, adds a new test in `t1503-rev-parse-verify.sh` to verify that uppercase object IDs are rejected, and adjusts an existing test in `t5324-split-commit-graph.sh` to avoid false positives in SHA-256 mode.

The change is minimal and targeted: it flips the switch on the infrastructure already in place, documents the new requirement, and ensures the test suite passes. The test adjustments are careful to avoid relying on the specific hex character used for corruption, ensuring the test remains valid across hash algorithms. This patch is the culmination of the series and the one that actually introduces the breaking behavior, but it remains gated behind the `WITH_BREAKING_CHANGES` flag, meaning it will only take effect in Git 3.0 or when explicitly enabled for testing.

The series as a whole is now complete and ready for substantive review. The implementation is clean and the motivation (consistency, security, and compatibility with external tools) is well-documented. The only open question is whether the project wants this breaking change at all, and if so, whether the approach taken here is the right one. This patch is unlikely to generate new technical objections but will be central to the broader design discussion.
