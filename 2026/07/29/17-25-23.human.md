This is the third patch in Junio C Hamano’s four-part series introducing `git add --resolved`, now in its second iteration (`v2 3/4`). It refactors index-removal logic to support `--dry-run` and `--verbose` flags consistently.

The helper encapsulates the verbose reporting and pretend-mode logic that callers like `update_callback()` previously had to implement manually. The diff is small (18 lines added, 4 removed) and touches only `read-cache-ll.h` and `read-cache.c`.

This is a clean refactoring that addresses the asymmetry noted in the commit message: index additions and removals now share the same flag semantics. The change is motivated by the upcoming `--resolved` feature (patch 4/4), which will use the new helper to report staged removals during conflict resolution. No behavior changes are introduced; the patch is purely preparatory. The implementation looks solid, with clear commit message and test coverage already present in the series’ new test script (`t2207-add-resolved.sh`).
