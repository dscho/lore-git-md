This is the second patch in brian m. carlson’s six-patch RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. The patch extends the `hex2chr()` helper to accept an `enum hexkind` parameter, allowing callers to specify whether they want to accept any hex case (`HEX_KIND_MIXED`) or only lowercase (`HEX_KIND_LOWER`). Every existing call site is updated to pass `HEX_KIND_MIXED`, so the patch is purely preparatory—no runtime behavior changes yet. The files touched (`hex-ll.h`, `hex.c`, `mailinfo.c`, `ref-filter.c`, `strbuf.c`, `url.c`, `urlmatch.c`) span core hex parsing, quoted-printable decoding, percent-encoding, and ref formatting, showing the breadth of places that will eventually need to enforce lowercase-only parsing. The patch is small (9 lines changed), mechanical, and does not introduce test failures, making it a safe stepping stone for the larger change.
