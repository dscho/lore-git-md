This is an RFC series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The author, brian m. carlson, argues that Git has always emitted lowercase hex object IDs, but the parser currently accepts both cases, leading to compatibility and potential security issues in external software that assumes uniqueness of hex representations.

The series introduces new functionality in `hex-ll.c`/`hex-ll.h` to enforce lowercase-only parsing, modifies various subsystems to label their hex parsing usage, and updates `object-name.c` to use the new strict parsing. Only one test fails with this change (fixed in the last patch), suggesting minimal existing reliance on uppercase hex.

Key technical details:
- New `hex_kind` enum and `hexval()` function to enforce lowercase parsing
- Changes touch core object parsing in `object-name.c`, `hex.c`, and multiple builtins
- The breaking change would be gated behind a "breaking changes mode" (likely Git 3.0)
- Files modified include `hex-ll.[ch]`, `object-name.c`, and various consumers like `ref-filter.c`, `pkt-line.c`

The motivation appears sound (consistency, security), but as an RFC, the series is explicitly seeking feedback on whether the project wants this change at all. The implementation looks complete but would need broader review if accepted. This is likely to be controversial given it's a breaking change affecting object ID parsing.
