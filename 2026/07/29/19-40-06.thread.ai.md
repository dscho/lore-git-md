Core problem or goal
The `git maintenance` command, since commit d465be2327 (October 2025), errors out on any unrecognized maintenance strategy instead of defaulting to the documented `"none"` strategy. The parser function `parse_maintenance_strategy()` did not accept `"none"` as valid input, breaking both the documented fallback and explicit use of `git maintenance --strategy=none`.

Current status
Under review; no prior versions. The patch is a minimal two-line code change in `builtin/gc.c` (adding case-insensitive `"none"` to the parser) plus three lines of test coverage in `t/t7900-maintenance.sh` to verify that `none` is accepted with and without a schedule. The fix is now effectively approved by Patrick Steinhardt, who confirmed the regression and the correctness of both the code change and test coverage. The only remaining action is the author identity housekeeping (in-body `From:` line to align with sign-off address) flagged by Junio and echoed by Patrick.

Key technical details
- Files touched: `builtin/gc.c`, `t/t7900-maintenance.sh`
- New behavior: `parse_maintenance_strategy()` now accepts `"none"` (case-insensitive)
- Old behavior: parser rejected `"none"`, causing `git maintenance` to fail
- On-disk format: unchanged
- Test coverage: explicit tests for `--strategy=none` and `--strategy=none --schedule=<any>`
