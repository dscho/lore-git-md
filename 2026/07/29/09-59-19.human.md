This is the final patch in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch removes the temporary workaround that excluded object type from the default format for remote queries, unifying the default format to `%(objectname) %(objecttype) %(objectsize)` for both local and remote object queries.

The change is straightforward: the code in `builtin/cat-file.c` that overrode the default format for remote queries is deleted, the documentation is updated to reflect that `%(objecttype)` is now supported, and the test suite is adjusted to expect object type metadata in the output. The patch also updates the Git protocol v2 documentation to describe the new "type" attribute in the `object-info` command.

Chandra Pratap’s review is surface-level, focusing on wording nits in the commit message and documentation, and on test design. The most substantive point is that the patch deletes a test that validated mixing `info` and `remote-object-info` commands in the same batch session; Chandra suggests updating the test rather than removing it to preserve coverage. This is a reasonable suggestion but does not affect the core functionality. The review does not raise any technical objections to the patch itself.
