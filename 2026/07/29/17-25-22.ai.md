This is the second patch in Junio C Hamano’s `git add --resolved` series (`v2 2/4`), a **refactoring** that consolidates duplicate conflict-marker detection logic. The patch replaces two near-identical functions—`diff.c:is_conflict_marker()` and `rerere.c:is_cmarker()`—with a single helper, `is_conflict_marker_line()`, in `merge-ll.c`. The new helper enforces a stricter rule: conflict markers (`<<<<<<<`, `>>>>>>>`) must be followed by a space, matching Git’s actual conflict output and the behavior previously used only in `rerere.c`.

The patch deletes 56 lines across three files (`diff.c`, `rerere.c`, `merge-ll.c`) and adds 39, resulting in a net reduction. The new helper returns the marker character (`<`, `=`, `>`, or `|`) instead of a boolean, allowing callers in `rerere.c` to distinguish marker types without additional parsing. The stricter space requirement is intentional and documented in the commit message; it aligns with Git’s conflict-generation behavior and avoids false positives from lines that happen to start with repeated `<` or `>` characters.

No behavior changes are expected for `diff --check` or `rerere` users, but the stricter rule could theoretically reject conflict markers that were previously accepted by `diff.c`. The commit message justifies this as correct, given Git’s conflict output format. The patch is a prerequisite for the `--resolved` feature in patch 4/4, which relies on the new helper to scan file content for remaining conflict markers.

The implementation is clean and well-motivated, with clear commit message rationale and no obvious edge cases left unaddressed. The stricter rule is the only potential point of contention, but the justification appears sound. This patch is unlikely to generate significant discussion beyond confirmation that the stricter rule is correct for all callers.
