This is the fourth patch in brian m. carlson’s six-patch RFC series that prepares Git 3.0 to accept only lowercase hex object IDs. The patch itself is purely mechanical: it introduces a new `HEX_KIND_OID` constant (currently an alias for `HEX_KIND_MIXED`) and updates every call site that parses object IDs to use the new label instead of the generic `HEX_KIND_MIXED`. No runtime behavior changes yet; the goal is simply to mark which hex-parsing calls are object-ID specific so that a later patch can flip the switch and enforce lowercase-only parsing. The files touched are all low-level plumbing (`hex.c`, `object-file.c`, `diagnose.c`, `http-push.c`, `notes.c`), so the risk of unintended side effects is minimal. The patch looks clean and well-scoped, and it directly serves the series’ stated goal of making the eventual breaking change safe and predictable.
