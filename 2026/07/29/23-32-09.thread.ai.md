Thread identity: RFC patch series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. Originating author: brian m. carlson. Thread type: design discussion / RFC.

Core problem or goal: Git currently emits lowercase hex object IDs but accepts both uppercase and lowercase in parsing, creating potential compatibility and security issues for external tools that assume hex uniqueness. The series aims to enforce lowercase-only parsing in Git 3.0, making the behavior consistent and predictable. The first five patches introduce infrastructure (new `hex_kind` enum, `hexval_lc_table`, updated `hexval()`, `hex2chr()`, and `hex_to_bytes()` functions, and `HEX_KIND_OID` constant) and refactor existing hex-parsing code to use these helpers without altering runtime behavior yet. The final patch activates enforcement by defining `HEX_KIND_OID` as `HEX_KIND_LOWER` when `WITH_BREAKING_CHANGES` is enabled, documents the change in `Documentation/BreakingChanges.adoc`, and adds test coverage to verify rejection of uppercase object IDs.

Current status: RFC stage; no prior versions. The series is now complete in implementation and explicitly seeks feedback on whether the project wants this breaking change at all. No maintainer decisions or merge status yet; under initial review. The first five patches are preparatory and do not change behavior; the sixth patch introduces the breaking change but remains gated behind `WITH_BREAKING_CHANGES`.

Key technical details:

- Modified subsystems: `hex.c`, `pkt-line.c`, `color.c`, `mailinfo.c`, `ref-filter.c`, `strbuf.c`, `url.c`, `urlmatch.c`, `index-pack.c`, `diagnose.c`, `http-push.c`, `notes.c`, `object-file.c`, `object-name.c` (hex parsing in packet-length parsing, quoted-printable decoding, percent-encoding, ref formatting, URL handling, object ID parsing from disk/network/diagnostics, and object name resolution), plus `Documentation/BreakingChanges.adoc` (documentation).
