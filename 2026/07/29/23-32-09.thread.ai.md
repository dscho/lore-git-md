Thread identity: RFC patch series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. Originating author: brian m. carlson. Thread type: design discussion / RFC.

Core problem or goal: Git currently emits lowercase hex object IDs but accepts both uppercase and lowercase in parsing, creating potential compatibility and security issues for external tools that assume hex uniqueness. The series aims to enforce lowercase-only parsing in Git 3.0 to make the behavior consistent and predictable. The first five patches introduce infrastructure (new `hex_kind` enum, `hexval_lc_table`, updated `hexval()`, `hex2chr()`, and `hex_to_bytes()` functions, and `HEX_KIND_OID` constant) and refactor existing hex-parsing code to use these helpers without altering runtime behavior yet. The final patch activates enforcement by defining `HEX_KIND_OID` as `HEX_KIND_LOWER` when `WITH_BREAKING_CHANGES` is enabled, documents the change in `Documentation/BreakingChanges.adoc`, and adds test coverage to verify rejection of uppercase object IDs.

Current status: RFC stage; no prior versions. The series is complete in implementation but explicitly seeks feedback on whether the project wants this breaking change. Junio C Hamano, the maintainer, has pushed back on the motivation, stating that the justification ("we might be able to do this without harming too many users") is insufficient and that a clearer, long-term benefit is needed to justify the disruption. No maintainer decisions or merge status yet; the discussion is now focused on the rationale rather than the implementation. The first five patches remain preparatory and do not change behavior; the sixth patch introduces the breaking change but remains gated behind `WITH_BREAKING_CHANGES`.

Key technical details:
- New files: `hex-ll.c`/`hex-ll.h` (lower-level hex parsing utilities).
- New symbols: `hex_kind` enum (`HEX_KIND_MIXED`, `HEX_KIND_LOWER`, `HEX_KIND_OID`), `hexval_lc_table`, updated `hexval()`, `hex2chr()`, and `hex_to_bytes()` functions (all take `enum hex_kind` parameter).
- Modified subsystems: `hex.c`, `pkt-line.c`, `color.c`, `mailinfo.c`, `ref-filter.c`, `strbuf.c`, `url.c`, `urlmatch.c`, `index-pack.c`, `diagnose.c`, `http-push.c`, `notes.c`, `object-file.c`, `object-name.c` (hex parsing in packet-length parsing, quoted-printable decoding, percent-encoding, ref formatting, URL handling, object ID parsing from disk/network/diagnostics, and object name resolution), plus `Documentation/BreakingChanges.adoc` (documentation).
- On-disk format: no changes; this is a parser behavior change only.
- Test coverage: new test in `t1503-rev-parse-verify.sh` verifies rejection of uppercase object IDs; existing test in `t5324-split-commit-graph.sh` adjusted to avoid false positives in SHA-256 mode.
- Breaking change gated behind "breaking changes mode" (target: Git 3.0).
- First five patches are mechanical and do not introduce test failures or behavioral changes; the sixth patch introduces the breaking behavior but only when `WITH_BREAKING_CHANGES` is enabled.
