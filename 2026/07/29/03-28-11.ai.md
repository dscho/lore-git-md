This is a **substantive review** of Junio C Hamano’s `git add --resolved` feature patch (3/4 in the series). Michael Montalbo identifies two technical issues in the implementation:

1. **Option incompatibility logic** – The new `die_for_incompatible_opt3()` call incorrectly treats `addremove_explicit == 0` (set by `--no-all` or `--ignore-removal`) as equivalent to `--all` being active. This causes false positives: `git add --resolved --no-all` and `git add -u --ignore-removal` now fail with misleading error messages, even though these combinations were previously valid. The fix would require changing the condition to `0 < addremove_explicit`.

2. **Test infrastructure omission** – The new test script `t/t2207-add-resolved.sh` lacks an entry in `t/meson.build`, which would prevent it from being discovered and run by the test harness. This is a build-system oversight rather than a code bug.

The review is narrowly focused but technically precise, targeting edge cases in option parsing and test integration. Both issues are actionable and likely to be addressed in a v2. The patch remains a well-crafted feature addition, but these corrections are necessary for correctness and testability.
