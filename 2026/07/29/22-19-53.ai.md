This is a review comment on the fourth patch of Junio C Hamano’s `v2` series introducing `git add --resolved`. The reviewer (Junio himself, in a self-review) identifies a subtle but important bug in the test script: the final `git checkout master` step assumes the original branch is named `master`, but this is not guaranteed (the default branch could be `main` or something else). The fix is to use `git checkout @{-1}`, which checks out the previous branch regardless of its name, making the test more robust and portable.

The issue is a classic test portability pitfall: hardcoding branch names that may not exist in all environments. The proposed fix is correct and aligns with Git’s own test suite conventions. This is a surface-level review (a one-line test script correction) but an important one, as it prevents the test from failing in non-`master` repositories. The rest of the patch and series remain unchanged.
