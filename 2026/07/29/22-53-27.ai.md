This is a follow-up in the ongoing review of Pablo Sabater’s GSoC series adding `%(objecttype)` support to `git cat-file --batch-command` for remote-object-info queries. Karthik Nayak retracts his earlier design question about whether the server should transmit object type as a string or integer: after re-reading the patch, he confirms the server *does* send the type as a string (e.g., `"blob"`, `"tree"`), and the client uses `type_from_string()` to map it to the internal enum. The retraction is brief and self-contained; no further discussion or code change is implied. The thread’s open questions remain unchanged: patch reordering, optional robustness tests, and the pending v2 roll-up.
