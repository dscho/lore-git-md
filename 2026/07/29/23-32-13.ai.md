This is the fourth patch in brian m. carlson's RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. The series aims to make Git's hex parsing consistent (emitting and accepting only lowercase) for security and compatibility reasons, but remains in the RFC stage awaiting feedback on whether the project wants this change at all.

This patch is purely preparatory and introduces no functional change. It adds a new `HEX_KIND_OID` constant (currently aliased to `HEX_KIND_MIXED`) and updates several core files (`diagnose.c`, `hex.c`, `http-push.c`, `notes.c`, `object-file.c`) to use this constant instead of the generic `HEX_KIND_MIXED` when parsing object IDs. The change is mechanical and touches low-level object storage and diagnostic code paths, including loose object directory traversal, HTTP push object path parsing, and notes tree loading.

The patch is small (6 files, 8 insertions, 6 deletions) and does not alter runtime behavior. It lays groundwork for later patches in the series that will enforce lowercase-only parsing by replacing `HEX_KIND_OID` with `HEX_KIND_LOWER`. The modified subsystems are all involved in parsing object IDs from disk, network, or diagnostics, making them natural candidates for stricter validation.

No test failures or behavioral changes are introduced here. The patch is uncontroversial in isolation but serves as a marker for future strictness, signaling which code paths are involved in object ID parsing. The real discussion remains whether the project wants this breaking change at all, not the mechanics of this preparatory step.
