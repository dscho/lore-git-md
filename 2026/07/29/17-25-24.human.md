This is the fourth and final patch in Junio C Hamano’s `git add --resolved` series, now in its second version (`v2`). It implements the core user-facing feature: a new `--resolved` option for `git add` that stages only unmerged paths where conflict markers have been removed, while refusing to stage any file that still contains markers.

The patch adds the option to the command-line parser, documents it in `git-add.adoc`, and introduces the main logic in `builtin/add.c`. The implementation scans the index for unmerged paths, checks each regular file for remaining conflict markers using the new `has_conflict_markers()` helper (which itself uses the `is_conflict_marker_line()` helper introduced earlier in the series), and either stages the resolved paths or aborts with an error listing unresolved ones. Binary files and deletions are staged without marker checks. The new test script `t/t2207-add-resolved.sh` covers refusal to stage files with markers, success when all markers are removed, ignoring unconflicted modified files, handling deletions, pathspecs, and option incompatibility with `-u` and `-A`.

This patch is the payoff of the series: a well-motivated workflow improvement for users resolving merge conflicts, with clear documentation and thorough test coverage. The implementation is careful about edge cases (binary files, deletions, pathspecs) and integrates cleanly with the existing `git add` machinery. The only open questions are minor edge behaviors (partially resolved conflicts, `--patch` interaction), which are likely to surface in further review but do not undermine the series’ readiness. The series as a whole looks like a solid, self-contained feature addition that addresses a real pain point.
