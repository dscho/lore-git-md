This is the fourth and final patch in Junio C Hamano’s `v2` series introducing `git add --resolved`, a new feature that stages only unmerged paths whose conflict markers have been removed. The patch implements the core logic, error handling, and documentation for the `--resolved` option, completing the series.

The implementation scans the index for unmerged paths matching the given pathspec, checks each regular file for remaining conflict markers using the `has_conflict_markers()` helper (which now includes an early exit for binary files), and either stages the resolved paths or aborts with an error listing unresolved ones. Deletions and binary files are staged as resolved without marker checks. The patch also updates the option-parsing logic to enforce mutual exclusivity with `-u` and `-A`, and adds comprehensive test coverage in `t/t2207-add-resolved.sh` for edge cases like pathspecs, deletions, and option incompatibility.

The commit message is clear and thorough, explaining the motivation (avoiding accidental staging of unrelated local changes during merge conflict resolution), the behavior (staging only resolved unmerged paths, ignoring non-conflicted modifications), and the technical details (early exit for binary files, error reporting). The test script covers all advertised functionality, including refusal to stage files with markers, success when all markers are removed, handling of deletions, and pathspec filtering.

This patch ties together the refactorings and helpers introduced in the earlier patches (conflict-marker detection, index removal with flags) and delivers the user-facing feature. The implementation appears robust, with sensible error handling and performance optimizations.
