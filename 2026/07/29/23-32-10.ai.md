This is the first patch in brian m. carlson’s RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. The patch introduces the infrastructure needed for the change without altering behavior yet.

It adds a new `hex_kind` enum (`HEX_KIND_MIXED` and `HEX_KIND_LOWER`) and a second lookup table (`hexval_lc_table`) that rejects uppercase hex digits. The existing `hexval()` function is modified to take an additional `enum hexkind` parameter, but all callers are updated to pass `HEX_KIND_MIXED`, so the runtime behavior remains unchanged. New files `hex-ll.c` and `hex-ll.h` centralize the low-level hex-parsing logic.

The patch touches four files: `hex-ll.c` (new table and updated `hex_to_bytes`), `hex-ll.h` (enum and function signature), `color.c` (one call site), and `pkt-line.c` (packet-length parsing). The diff is mechanical and does not introduce any new test failures. This is purely preparatory work for the later patches that will enforce lowercase-only parsing in specific contexts.
