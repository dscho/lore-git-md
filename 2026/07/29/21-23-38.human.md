This is a reply in the ongoing RFC thread about allowing Git to accept packfiles with duplicate objects. Taylor Blau pushes back gently on Junio C Hamano’s characterization of such packs as "broken," arguing that the only issue is client-side support — which his earlier `tb/pack-with-duplicates` series already addresses. He clarifies that shallow clones (when configured with an artificially large depth) already accept duplicate objects today because they run `index-pack` without `--strict`, so the repository state is not novel. The exchange keeps the discussion alive but does not resolve the core philosophical divide: Junio insists that duplicates must be deduplicated during indexing to avoid spreading "broken" packs, while Taylor maintains that the state is safe and that the feature is a pragmatic performance trade-off. The thread remains open, with no new technical proposals or design changes introduced in this message.
