This is the final patch in Pablo Sabater’s five-part GSoC series, completing the work to extend `git cat-file --batch-command` with `%(objecttype)` support for remote-object-info queries. The patch unifies the default format string for local and remote queries, removing the temporary workaround that excluded object type from remote queries and aligning the behavior with the rest of the `cat-file` commands.

The patch is mechanical and uncontroversial: it updates the default format to `%(objectname) %(objecttype) %(objectsize)` for all queries, removes the now-obsolete warning about future unification, and adjusts documentation and tests to reflect the change. The only feedback from Chandra Pratap was surface-level—minor wording fixes in the commit message and documentation, and a suggestion to retain (and update) a test that validates mixing `info` and `remote-object-info` commands in the same session. Pablo has accepted all feedback and will incorporate the changes in the next revision.

The series as a whole is now complete and under review. It builds directly on Eric Sunshine’s recently merged remote-object-info work, adding the last piece of metadata guaranteed to be identical on client and server after a fetch. The implementation is narrowly scoped to object type, with other metadata explicitly ruled out as unreliable or context-dependent. No maintainer decision has been reported, but the series appears well-crafted, thoroughly tested, and aligned with the project’s recent direction. If you care about `cat-file` or remote protocol extensions, this is worth tracking.
