This is the final patch in Pablo Sabater’s five-part GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch unifies the default format string for local and remote queries, removing the temporary workaround that excluded object type from remote queries. The change is mechanical: it updates the default format to `%(objectname) %(objecttype) %(objectsize)` for all queries, removes the now-obsolete warning about future unification, and updates documentation and tests to reflect the new behavior.

The patch touches four files: `Documentation/git-cat-file.adoc` (removes caveats about `%(objecttype)` not being supported in remote queries and updates the default format description), `Documentation/gitprotocol-v2.adoc` (documents the new "type" attribute in the object-info protocol), `builtin/cat-file.c` (removes the temporary format override for remote queries), and `t/t1017-cat-file-remote-object-info.sh` (updates tests to expect the new default format and adds a new test to explicitly validate mixing `info` and `remote-object-info` commands in the same session).

Chandra Pratap’s review feedback on this patch was surface-level, focusing on wording clarity in the commit message and documentation, and on test design. Pablo Sabater accepted all suggestions: he will reword the commit message to clarify that tests are being updated to expect the new default format, fix two minor grammar issues in the documentation, and restore a test that validates mixing `info` and `remote-object-info` commands (rather than deleting it). The restored test will explicitly verify that both commands now output `<OID> <TYPE> <SIZE>`, ensuring the unified format works as intended.

The series as a whole is now complete and addresses all review feedback. The only remaining loose end is a non-blocking suggestion to add a test for robustness against malformed server responses (raised in patch 2), which Pablo Sabater plans to implement as a follow-up. The patch sequence and core functionality are uncontroversial, and the series is ready for maintainer consideration.
