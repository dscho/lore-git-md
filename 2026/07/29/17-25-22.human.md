This is the second patch in Junio C Hamano’s four-part series introducing `git add --resolved`. It consolidates duplicate conflict-marker detection logic from `diff.c` and `rerere.c` into a single helper, `is_conflict_marker_line()`, in `merge-ll.c`.

The patch replaces two nearly identical functions (`diff.c:is_conflict_marker()` and `rerere.c:is_cmarker()`) with a unified implementation that enforces a stricter rule: conflict markers (`<<<<<<<`, `>>>>>>>`) must be followed by a space, not just any whitespace. This matches Git’s own conflict output format and is a deliberate tightening of the rules. The new helper also returns the marker character (`<`, `=`, `>`, or `|`) rather than a boolean, which allows callers to distinguish between different marker types without rescanning the line.

The change is mechanical and well-contained: the new function is added to `merge-ll.c`, declared in `merge-ll.h`, and both `diff.c` and `rerere.c` are updated to use it. The commit message explains the rationale clearly and cites the original commits that introduced the duplicate logic. No behavior changes are intended beyond the stricter space requirement, and the patch includes no new tests because the existing test suites for `diff --check` and `rerere` already cover conflict-marker detection.

This refactoring is a sensible cleanup that reduces code duplication and prepares the ground for the `--resolved` feature in patch 4. The stricter rule is unlikely to cause issues in practice, since Git’s own conflict markers always include the space. The patch looks solid and uncontroversial.
