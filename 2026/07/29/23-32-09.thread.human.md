This thread is about an RFC patch series from brian m. carlson proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The goal is to address security and compatibility issues caused by Git's current case-insensitive parsing, which can confuse external tools that assume hex uniqueness. The series introduces infrastructure changes (new hex-parsing helpers and refactoring) in the first five patches, while the sixth patch activates the enforcement, gated behind Git 3.0's "breaking changes mode."

The discussion has shifted from philosophical debate to technical refinement. Junio C Hamano, the maintainer, has signaled tentative acceptance ("Will queue") but remains ambivalent, suggesting a potential compromise—normalizing mixed-case inputs to lowercase internally while still accepting them externally. Brian has deferred to project consensus, leaving the door open for the series to be dropped if the community disagrees. Key technical issues remain unresolved, including omissions in the fourth patch (two sites should use `HEX_KIND_OID` instead of `HEX_KIND_MIXED`), a behavioral change in the fifth patch (preserving original case where the old code lower-cased it), and a correctness risk flagged by Elijah Newren (storing an `unsigned int` in an `int`). The sixth patch's test adjustments also need clearer documentation, as noted by Junio and Elijah.

The thread's fate hinges on two open questions: whether the project will accept the breaking change at all, and whether Junio's proposed compromise is feasible. Phillip Wood's recent question—why `ABCDEF` is a security risk when `abcdef^0` is not—directly challenges the series' motivation and could sway the outcome. Michael Montalbo's demonstration of mixed-case object IDs creating ambiguity strengthens Brian's argument, but Junio's ambivalence and the unresolved technical issues leave the series in limbo. The latest email from Elijah adds minor clarifications but doesn't move the core debate forward. For now, the series remains an RFC, awaiting broader community feedback or a decisive push from the maintainer.
