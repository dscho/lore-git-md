This thread is an RFC discussion about a proposed breaking change for Git 3.0: restricting hex object IDs to lowercase only. The series, authored by brian m. carlson, aims to address potential compatibility and security issues by enforcing consistent lowercase parsing, though the initial justification was deemed insufficient by Junio C Hamano, the maintainer.

The implementation is complete, with the first five patches introducing infrastructure (new hex-parsing utilities and refactoring) without altering behavior, and the sixth patch activating enforcement—gated behind `WITH_BREAKING_CHANGES`. The discussion has now shifted from theoretical consistency to practical security concerns. brian provides concrete evidence of real-world vulnerabilities caused by Git's current case-insensitive parsing, citing tools that fail to sanitize object IDs properly and ecosystem inconsistencies (e.g., Gitolite and GitHub tools rejecting uppercase hex). The argument now hinges on security risks, ecosystem compatibility, and user expectations set by Git's own documentation.

No new technical feedback or patches have emerged, and the thread remains focused on whether the security benefits justify the disruption of a breaking change. Junio's response to this updated justification will determine whether the series moves forward.
