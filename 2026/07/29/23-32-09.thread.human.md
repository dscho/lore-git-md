This thread is an RFC patch series from **brian m. carlson** proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. Git currently accepts both uppercase and lowercase hex in parsing, despite always emitting lowercase, which can cause compatibility and security issues for external tools. The series aims to enforce lowercase-only parsing in Git 3.0 for consistency and predictability.

So far, the first three patches are preparatory infrastructure changes that don’t alter runtime behavior. The first two introduced a `hex_kind` enum and updated core hex-parsing functions, while this latest patch extends the `hex_to_bytes()` helper to accept the new `hex_kind` parameter, updating all callers to pass `HEX_KIND_MIXED` (no functional change yet). The series is complete in implementation but explicitly seeks feedback on whether the project wants this breaking change at all. No maintainer decisions or merge status have been recorded yet, and no substantive technical reviews have been posted—only the author’s motivation and implementation are on the table.

The key open question remains whether the project is willing to accept this breaking change in Git 3.0. The series touches low-level plumbing (hex parsing, object IDs, network protocols) but makes no on-disk format changes. Later patches will enforce lowercase-only parsing in specific contexts, gated behind the Git-3.0-breaking-changes mode. If the project moves forward, this will be a significant shift in how Git handles object IDs, so expect debate over the trade-offs between consistency and backward compatibility.
