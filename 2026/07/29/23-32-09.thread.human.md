This thread is an RFC patch series by brian m. carlson proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The goal is to address security vulnerabilities and ecosystem inconsistencies caused by Git's current case-insensitive parsing of object IDs, which has led to real-world issues in external tools like Gitolite and GitHub-hosted services.

The series consists of six patches. The first five introduce infrastructure (new hex-parsing utilities and refactoring) without changing runtime behavior, while the sixth patch enforces lowercase-only parsing when `WITH_BREAKING_CHANGES` is enabled. Junio C Hamano, the maintainer, initially pushed back on the motivation, but brian later provided concrete evidence of security vulnerabilities to support the change. The discussion has so far focused on whether the project wants this breaking change at all, rather than the implementation details.

In the latest email, Junio engages with the fourth patch, approving its general direction but raising a technical question about whether the new `HEX_KIND_OID` constant should also apply to derived hashes like packfile names and rerere database keys. This suggests the discussion may be shifting toward implementation specifics, though the broader design question remains unresolved. No maintainer decisions or merge status have been established yet, and the series is still in the RFC stage. The key open question is whether the security benefits justify the ecosystem disruption of this breaking change.
