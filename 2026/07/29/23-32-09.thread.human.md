This thread is about an RFC patch series from brian m. carlson proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The goal is to address security and compatibility issues caused by Git's current acceptance of both uppercase and lowercase hex, which has led to real-world vulnerabilities in external tools that assume hex uniqueness. The series introduces infrastructure for stricter hex parsing (new `hex_kind` enum, updated functions, and constants) and refactors existing code to use these helpers, with the final patch enforcing lowercase-only parsing when `WITH_BREAKING_CHANGES` is enabled.

The series is complete but remains in RFC limbo, with Junio C Hamano signaling tentative acceptance ("Will queue") while expressing ambivalence about the breaking change. Key technical details include new files (`hex-ll.c`/`hex-ll.h`), modified subsystems (hex parsing, packet-length handling, object ID resolution), and test coverage verifying rejection of uppercase object IDs. Open questions include whether the project will accept the change, whether derived hashes (e.g., packfile names) should be covered, and whether Junio’s proposed compromise—normalizing mixed-case inputs to lowercase internally—is viable. Junio’s latest review of the final patch flags a minor documentation gap in the test adjustment for `t5324-split-commit-graph.sh`, but this does not challenge the series’ substance. Phillip Wood’s earlier question about the security rationale remains unanswered and may determine the series’ fate. Brian has deferred to project consensus, leaving the door open for the series to be dropped if the community disagrees.
