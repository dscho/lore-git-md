This thread is an RFC patch series from brian m. carlson proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. Git currently accepts both uppercase and lowercase hex in parsing, even though it emits only lowercase, which can cause compatibility and security issues for external tools that assume hex uniqueness. The series introduces infrastructure to enforce lowercase-only parsing in Git 3.0, making the behavior consistent and predictable.

The first five patches lay the groundwork—new `hex_kind` enum, updated hex-parsing functions, and refactoring existing code to use these helpers—without altering runtime behavior. The final patch, just posted, activates the enforcement mechanism by defining `HEX_KIND_OID` as `HEX_KIND_LOWER` when `WITH_BREAKING_CHANGES` is enabled, rejecting uppercase hex in object ID parsing. It also documents the change in `Documentation/BreakingChanges.adoc` and adds tests to verify the new behavior.

The series is now complete and ready for substantive review. The implementation is clean, and the motivation (consistency, security, and compatibility) is well-documented. The key open question remains whether the project wants this breaking change at all, and if so, whether the approach is the right one. No maintainer decisions have been made yet, and the series is still under initial review. The final patch is unlikely to draw new technical objections but will be central to the broader design discussion.
