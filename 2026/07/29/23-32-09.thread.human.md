This thread is an RFC discussion about a proposed breaking change for Git 3.0: restricting hex object IDs to lowercase only, led by brian m. carlson. The goal is to address security vulnerabilities and ecosystem inconsistencies caused by Git's current case-insensitive parsing of object IDs, which has led external tools to fail when handling uppercase hex. The series introduces infrastructure changes (new hex-parsing utilities and refactoring) in its first five patches, with the sixth patch enforcing lowercase-only parsing when Git is built with `WITH_BREAKING_CHANGES`.

Junio C Hamano, the maintainer, initially questioned the motivation but has since engaged deeply with the proposal, raising philosophical objections based on the Robustness Principle. He argues that Git should remain liberal in what it accepts, even in a breaking-change release, and suggests a compromise: enforcing lowercase internally while continuing to accept uppercase in external inputs (e.g., network protocols). His latest emails expand on this with concrete examples, such as Git's dumb HTTP transport encountering uppercase loose object directories, proposing that Git should normalize rather than reject such inputs.

Jeff King (Peff) has now added a critical new dimension to the discussion: uppercase hex within object *contents* (specifically commits and tags) can create parallel histories of otherwise identical commits. This happens because Git does not normalize case when hashing object contents, meaning a commit with an uppercase parent hash produces a different object ID than the same commit with a lowercase parent hash. While accidental creation of such objects is unlikely, Peff's example shows the problem extends beyond external inputs into the object model itself. This complicates the debate, as the proposed breaking change would not address this case—it only restricts parsing of external inputs.

The thread remains in the RFC stage, with no maintainer decision or merge status. The discussion is now focused on whether the project should proceed with the breaking change, whether a compromise (e.g., internal enforcement with external normalization) is viable, and how Peff's observation about object contents affects the justification. No substantive technical reviews beyond Junio's and Peff's have emerged, and the series' future hinges on whether the security and consistency arguments outweigh the disruption and philosophical objections.
