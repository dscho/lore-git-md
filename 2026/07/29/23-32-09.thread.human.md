This thread is an RFC patch series by brian m. carlson proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The goal is to address security and compatibility issues caused by Git's current case-insensitive parsing, which can confuse external tools that assume hex uniqueness. The series introduces infrastructure changes (new `hex_kind` enum, updated parsing functions) and refactors existing code to use these helpers without altering behavior—until the final patch, which enforces lowercase-only parsing when `WITH_BREAKING_CHANGES` is enabled.

Junio C Hamano has signaled tentative acceptance ("Will queue") but remains ambivalent, suggesting a compromise where Git normalizes mixed-case inputs to lowercase internally while still accepting them from external sources. The thread has been in RFC limbo, with no final decision, though the implementation is complete and well-reviewed. The latest development is a substantive question from Phillip Wood, who asks why uppercase hex object IDs (`ABCDEF`) pose a security risk when their lowercase equivalents (`abcdef^0`) do not. This challenges the core justification for the breaking change, and brian's response will likely determine whether the series advances or stalls. The patch itself is minimal and ready, but the security rationale remains the last open question.
