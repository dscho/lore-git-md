This thread is about an RFC patch series from brian m. carlson proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. Git currently accepts both uppercase and lowercase hex in parsing, which has led to security issues in external tools that assume hex uniqueness. The series introduces infrastructure to enforce lowercase-only parsing, with the final patch activating this enforcement gated behind Git 3.0’s "breaking changes mode."

The discussion is still in the RFC stage, with Junio C Hamano signaling tentative acceptance but no final decision. Key participants include brian (the author), Junio (the maintainer), Jeff King, Phillip Wood, Elijah Newren, and Michael Montalbo. The series has faced questions about its security rationale, technical implementation, and whether the project should accept such a breaking change. Junio has suggested a potential compromise—normalizing mixed-case inputs to lowercase internally while accepting them externally—but this remains unresolved.

The latest email is a minor follow-up addressing a trivial typo in a comment (68-67 → 68-6f) in the first patch’s `hexval_lc_table` definition. This fix is uncontroversial and will be included in the next version (`v2`), but it doesn’t advance the thread’s core questions. The series remains in limbo, awaiting broader community feedback on whether the security justification is sufficient to justify the breaking change.
