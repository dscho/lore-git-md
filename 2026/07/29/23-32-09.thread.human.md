This thread is an RFC patch series from **brian m. carlson** proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. Git currently emits lowercase IDs but accepts both cases during parsing, which can create compatibility and security issues for external tools. The series introduces infrastructure (new `hex_kind` enum, updated parsing functions, and refactoring across subsystems) and gates the breaking change behind `WITH_BREAKING_CHANGES`.

The discussion has now reached a critical juncture. **Junio C Hamano**, the maintainer, has pushed back on the motivation, arguing that the benefit does not yet justify the disruption. While he acknowledges the inconsistency in Git’s behavior, he insists that "we might be able to do this without harming too many users" is not a strong enough case—there must be a clear, long-term advantage to adopting this change. The thread remains in the RFC stage, with no technical review of the patches yet, and Junio’s response suggests the series will not advance without a more compelling argument.

The key question now is whether the project considers this inconsistency severe enough to warrant a breaking change. The implementation is complete and functional, but the discussion has shifted from *how* to *whether* this change should happen at all. If no stronger rationale emerges, the series may stall here.
