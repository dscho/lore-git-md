This is a **build system** patch that addresses a subtle dependency issue in the Git Makefile. Brian m. carlson reports that even after Jeff King’s recent fixes for test failures under `WITH_BREAKING_CHANGES=1`, the `t1517-outside-repo.sh` test still fails in some cases. The root cause is that the Makefile reads `config.mak` (where `WITH_BREAKING_CHANGES` is set) *after* it determines which binaries to build, so the list of deprecated commands like `git-whatchanged` isn’t updated correctly. This leaves stale build artifacts that interfere with test expectations.

The patch moves the inclusion of `config.mak` (and related files) earlier in the Makefile, ensuring that `WITH_BREAKING_CHANGES` is honored when the list of binaries is generated. The change is small—just four lines moved—but it’s a targeted fix for a real problem that affects developers testing Git 3.0 compatibility. The commit message is clear and ties the patch directly to the earlier thread about test failures, making it easy to follow the context.

This isn’t a regression in Git’s logic but a build-system quirk, so the risk is low. The patch looks well-motivated and should resolve the remaining edge case without side effects.
