This is a **feature** series introducing `git add --resolved`, now in its second version (`v2`). The series is authored by Junio C Hamano and consists of four patches: two refactorings, the core feature implementation, and a whitespace cleanup. The goal is to allow users to stage only paths whose conflict markers have been removed, avoiding accidental staging of unrelated local changes during merge conflict resolution.

The series is now technically complete. The first patch reindents `skip_submodule()` in `read-cache.c` (whitespace-only). The second consolidates duplicate conflict-marker detection logic into a new helper, `is_conflict_marker_line()`, in `merge-ll.c`, replacing implementations in `diff.c` and `rerere.c`. The third introduces `remove_file_from_index_with_flags()`, a helper for index removals with `--dry-run` and `--verbose` support. The fourth implements the `--resolved` option, which stages only files without conflict markers, with an early exit for binary files to improve performance.

Relative to `v1`, this version addresses two issues raised by Michael Montalbo: a logic error in `die_for_incompatible_opt3()` (fixing the condition from `0 <= addremove_explicit` to `0 < addremove_explicit`) and the missing `t/meson.build` entry for the new test script `t/t2207-add-resolved.sh`. Additionally, Junio added a performance optimization to `has_conflict_markers()` to skip binary files early using `buffer_is_binary()`.

Key technical details include the new `--resolved` option, the `remove_file_from_index_with_flags()` helper, and the conflict-marker detection logic in `merge-ll.h`. The test script `t2207-add-resolved.sh` covers edge cases like pathspecs, deletions, and option incompatibility with `-u` and `-A`. The series touches `merge-ll.c`, `read-cache.c`, `builtin/add.c`, `diff.c`, `rerere.c`, and documentation. No on-disk format changes or new config keys are introduced.

The implementation appears well-motivated and thorough, with clear commit messages and test coverage. The follow-ups address substantive review feedback, and the performance tweak is a sensible addition. Open questions remain around edge cases like partially resolved conflicts and interaction with `--patch`, but these are likely to surface in further review. The series is self-contained and does not depend on other ongoing efforts.
