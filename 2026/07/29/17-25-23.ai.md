This is the third patch in Junio C Hamano’s `git add --resolved` series (v2, 3/4). It introduces `remove_file_from_index_with_flags()`, a helper function in `read-cache.c` that encapsulates the `--dry-run` (`ADD_CACHE_PRETEND`) and `--verbose` (`ADD_CACHE_VERBOSE`) behaviors for index removals. The patch updates `update_callback()` to use the new helper, replacing manual flag checks with a single call.

The motivation is straightforward: `add_file_to_index()` already supports these flags, but `remove_file_from_index()` does not, forcing callers to handle reporting and dry-run logic themselves. This refactoring aligns the removal path with the addition path, reducing code duplication and making the API more consistent. The implementation is minimal and focused, adding only the necessary plumbing without altering behavior.

The patch touches `read-cache-ll.h` (declaration) and `read-cache.c` (implementation and caller update). The new helper is a thin wrapper around `remove_file_from_index()`, with the same return semantics (0 on success, -1 on failure). The change is mechanical and unlikely to introduce regressions, but reviewers should verify that edge cases—such as flag combinations (e.g., both `ADD_CACHE_PRETEND` and `ADD_CACHE_VERBOSE` set) or paths not in the index—are handled correctly.

This patch is a prerequisite for the `--resolved` feature in the next patch, which will use the new helper to stage resolved conflicted files.
