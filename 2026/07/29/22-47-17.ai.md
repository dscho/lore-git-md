This is a surface-level review of the second patch in Pablo Sabater’s GSoC series extending `` `git cat-file --batch-command` `` to support the `%(objecttype)` placeholder in remote-object-info queries. Karthik Nayak’s feedback focuses on two minor points: a suggested rewording of the commit message to clarify the flow between sentences, and a question about whether the server should transmit object type as a string (to avoid potential mismatches between client and server) rather than as an integer that the client then maps to a string using `type_from_string()`. The question is phrased as a design consideration rather than a blocker, and Pablo has not yet replied. The rest of the patch — the code changes themselves — is not commented on, so the implementation appears uncontroversial. This is the kind of feedback that can be addressed with a small commit-message tweak and, if needed, a follow-up explanation or code adjustment in the next iteration.
