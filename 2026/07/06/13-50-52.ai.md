This is a bugfix targeting the sparse-index subsystem. Derrick Stolee identifies and fixes a segfault that occurs when Git attempts to collapse a full index into a sparse index while an intent-to-add (ITA) entry exists outside the sparse-checkout cone. The crash happens because the cache-tree node's `entry_count` can be negative (indicating invalidation), but the sparse-index collapse logic does not account for this, leading to an out-of-bounds access when iterating over cache entries.

The fix is minimal: the code now checks if `entry_count` is negative before attempting to collapse a cache-tree node, skipping the collapse if so. This prevents the crash but leaves some potential performance optimizations on the table—specifically, the ability to collapse valid child trees even when an ITA entry is present. Stolee notes that a more involved fix could achieve this, but the current change is sufficient to resolve the immediate issue and is unlikely to affect real-world usage, given the bug's obscurity.

The patch includes two new tests: one in `t3705-add-sparse-checkout.sh` to verify `git add` behavior with sparse-checkout, and another in `t1092-sparse-checkout-compatibility.sh` to demonstrate the interaction with the sparse index and compare it to full-index behavior. The latter test also highlights the trade-off in the fix—some sparse directories that *could* be collapsed are left expanded due to the presence of the ITA entry.

Key technical details for follow-up discussion:
- The bug surfaces in `convert_to_sparse_rec()` in `sparse-index.c`, where the loop over cache entries assumes a non-negative `entry_count`.
- The fix moves the `span` assignment earlier in the loop and adds a guard clause to skip invalidated nodes.
- The tests use `git add -N` (intent-to-add) and `git sparse-checkout set` to trigger the scenario, then verify the index state with `git ls-files` and `git status`.
- The patch touches the sparse-index, cache-tree, and intent-to-add subsystems, with implications for how Git handles untracked files in sparse repositories.
