Subject: [PATCH 0/2] git-subtree: safeguard against mixing old and new implementations
Series version: v1 (scoping fix confirmed, error message formatting resolved, test style improvements accepted and now idiomatically refined)
Originating author: Ian Jackson
Thread type: patch series (contributor housekeeping)

Core problem or goal
Add a safeguard to the existing shell-script `git-subtree` (in `contrib/`) to detect and reject repositories that have been modified by a forthcoming Rust rewrite of the same command. The Rust rewrite will use a config key (`subtree.rust-rewrite`) to store downstream project metadata and will not be backward-compatible; mixing the two implementations could create unparseable history.

Current status
Under review; v1 posted. The scoping bug in the detection helper function `reject_if_v2_config` (use of global `rev` instead of positional argument `$1`) is resolved. The error message formatting question is resolved: Junio C Hamano confirmed the current long, single-line `die` message is acceptable. The author has accepted Colin Stagner’s test style suggestions (use `test_create_repo` with orphan branches and the `test_commit` helper) and Phillip Wood’s idiomatic test assertion pattern (`test_must_fail git ... 2>err && test_grep regexp err`). No substantive changes remain open.

Key technical details
- Files touched: `contrib/subtree/git-subtree.sh` (detection logic), `t/t7900-subtree.sh` (test case).
- New config key: `subtree.rust-rewrite` (presence triggers the error).
- New error message: “This repository appears to have been used with the new git-subtree Rust rewrite.”
- Test coverage: one new test case verifies the error is triggered when the config key exists; uses `test_create_repo` and `test_commit --no-tag` for consistency with other subtree tests and to avoid unwanted tag creation. The test now asserts the exact error message using `test_must_fail git subtree ... 2>err && test_grep "expected message" err`.
- Bug fix: `reject_if_v2_config` helper function now uses `$1` to check the intended revision (`HEAD`).
- Shell portability note: the helper uses `local`, which is not POSIX-compliant but is already present elsewhere in the script; the author declines to remove it, citing negligible compatibility risk.
- Detection scope: the logic checks only the top-level repository config, not `.git-subtree/config` inside the subtree being split, because the decision to use the new algorithm depends on the downstream’s adoption of the Rust rewrite, not on upstream metadata.
- Forthcoming Rust rewrite design: will not support unmarked subtree merges (those performed manually with `git merge -X subtree`); this limitation will be documented and tested but not enforced at runtime.

Open questions and loose ends
