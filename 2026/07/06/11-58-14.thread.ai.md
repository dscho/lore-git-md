Subject: [PATCH 0/2] git-subtree: safeguard against mixing old and new implementations
Series version: v1 (scoping fix confirmed, error message formatting resolved, test style suggestions noted)
Originating author: Ian Jackson
Thread type: patch series (contributor housekeeping)

Core problem or goal
Add a safeguard to the existing shell-script `git-subtree` (in `contrib/`) to detect and reject repositories that have been modified by a forthcoming Rust rewrite of the same command. The Rust rewrite will use a config key (`subtree.rust-rewrite`) to store downstream project metadata and will not be backward-compatible; mixing the two implementations could create unparseable history.

Current status
Under review; v1 posted. The scoping bug in the detection helper function `reject_if_v2_config` (use of global `rev` instead of positional argument `$1`) is resolved in principle. The error message formatting question is also resolved: Junio C Hamano confirmed the current long, single-line `die` message is acceptable, given the script’s eventual deprecation. No substantive changes remain open. The next revision is expected to address the scoping fix and may incorporate test style suggestions.

Key technical details
- Files touched: `contrib/subtree/git-subtree.sh` (detection logic), `t/t7900-subtree.sh` (test case).
- New config key: `subtree.rust-rewrite` (presence triggers the error).
- New error message: “This repository appears to have been used with the new git-subtree Rust rewrite.”
- Test coverage: one new test case verifies the error is triggered when the config key exists.
- Bug fix: `reject_if_v2_config` helper function now uses `$1` to check the intended revision (`HEAD`).
- Shell portability note: the helper uses `local`, which is not POSIX-compliant but is already present elsewhere in the script.
- Test style: the current test creates two separate repos and uses manual `echo`/`git add`/`git commit` sequences; Colin Stagner suggests using `test_create_repo` with orphan branches and the `test_commit` helper for consistency with other subtree tests.

Open questions and loose ends
- **Portability**: the use of `local` in shell functions is discouraged by the project’s shell coding guidelines, though it is already used elsewhere in `git-subtree.sh`. No action has been requested or promised.
- **Edge coverage**: whether the detection logic should also check for the config file inside the subtree being split (`.git-subtree/config` in the subtree’s root) rather than only at the top level of the repository. The current implementation checks only the top-level tree; no change has been requested or promised.
- **Test style**: Colin Stagner’s suggestions to use `test_create_repo` and `test_commit` for better alignment with existing test patterns. No response from the author yet; no decision on whether these will be adopted.
