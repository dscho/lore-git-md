This is a test modernization patch. A new contributor, Gatla Vishweshwar Reddy, fixes a long-standing but subtle issue in `t/t1410-reflog.sh`: when Git commands are piped directly to `wc -l`, the exit code of the Git command is lost, which means the test suite can miss failures. The patch replaces every instance of `git reflog | wc -l` with a two-step process: first redirect the output to a temporary file, then count the lines from that file. This preserves the exit code and makes the tests more robust.

The change is mechanical and confined to a single test script. It touches eight locations, all following the same pattern. The commit message is clear and the rationale is sound—this is a well-known shell scripting pitfall, and the fix is idiomatic. No new behavior is introduced; the tests now simply fail when they should instead of silently passing.

This looks like a solid, uncontroversial improvement. It’s the kind of small-but-valuable cleanup that the test suite needs, and it’s a good sign that a new contributor is tackling it. The patch is ready for review and likely to be merged without drama.
