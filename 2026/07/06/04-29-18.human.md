This is a **UX improvement proposal** for `` `git show` ``, inspired by the ongoing debate over Patrick Steinhardt’s source-tree reorganization. Kaartic Sivaraam suggests adding a hint to `` `git show` `` when a requested file does not exist in a given commit but appears to have been renamed. The hint would show the new path and offer a one-click correction (e.g., `` `origin/seen:lib/wt-status.c` ``).

The idea is narrowly scoped: it does not change Git’s core rename-detection logic, only the error message when a user asks for a file that has moved. The proposal is motivated by the real pain that Junio C Hamano and Phillip Wood reported after the ``lib/`` reorganization—users repeatedly forgetting where files now live. Sivaraam’s mock-up is concrete and low-cost: a single-line hint that piggy-backs on existing rename tracking without running a full ``git log --follow``.

No code is attached, so this is an RFC rather than a patch. The tone is exploratory (“I wonder if it would be worth…”), and the suggestion is framed as a potential mitigation for the workflow friction that the ``lib/`` move has introduced. It does not take sides in the larger debate about whether the reorganization was justified, but it does acknowledge that the disruption is real and persistent.
