This is a test performance patch, part 3 of a 9-patch series. It targets `t4141-apply-too-large.sh`, a test that verifies `git apply` correctly rejects patches exceeding Git's size limits.

The current test generates a 1 GB patch by piping an unbounded stream of zeros from `test-tool genzeros` through `test_copy_bytes`, which uses `dd ibs=1` to copy one byte at a time. This results in 1 billion read/write operations, making the test extremely slow—6 minutes on Patrick Steinhardt's machine and up to 40 minutes in CI.

The fix leverages `genzeros`'s built-in limit parameter to generate exactly 1 GB of data directly, eliminating the need for `test_copy_bytes`. This change reduces test execution time to under a second. The patch keeps the `EXPENSIVE` prerequisite because `git apply` still consumes 1 GB of memory, even though the test itself is now fast.

The diff modifies only the test script, replacing the `sz` variable and `test_copy_bytes` call with a direct `genzeros` invocation using the same byte count. The change is mechanical and focused on performance, with no behavior change.
