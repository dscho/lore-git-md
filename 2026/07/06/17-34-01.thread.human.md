This thread is about a small but important test portability fix for Git’s Trace2 ancestry tracking. Jamie Magee identified that the `t0213-trace2-ancestry.sh` test fails in user-mode emulation environments like QEMU, where `/proc/<pid>/stat` reports the emulator’s name ("qemu-riscv64") instead of the guest process ("test-tool" or "git"). The fix updates the test to skip itself when process names are unreliable, ensuring the test doesn’t produce false negatives in these environments.

Junio C Hamano, the maintainer, initially approved the patch in principle, calling its grep pattern "tricky" but acceptable for a controlled test environment. He planned to queue it to `seen` for further exposure but later clarified that this doesn’t imply readiness for `next` and explicitly requested a substantive review from a Trace2 domain expert. The patch remains in the review queue, awaiting that review before it can progress further.

Alongside the technical discussion, Weijie Yuan raised a procedural question about why `Cc:` trailers appear in Git commit messages despite not being documented in Git’s contribution guidelines. Junio explained that the trailer is used by GitGitGadget to automatically copy recipients when emailing patches, reflecting a practical convention rather than a formal policy. He contrasted Git’s use of `Cc:` with the Linux kernel’s more formal approach, noting that Git doesn’t treat it as a way to shift responsibility for bugs. This question is now resolved from the maintainer’s perspective, though it might prompt future documentation updates.

The patch itself is narrowly scoped to the test script and doesn’t affect native platforms or introduce new symbols or on-disk changes. The only remaining hurdle is the requested Trace2-specific review, which is the next step before the fix can move forward.
