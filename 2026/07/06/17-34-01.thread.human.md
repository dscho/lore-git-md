This thread is about a small but important fix to a Git test script (`t0213-trace2-ancestry.sh`) that was failing in user-mode emulation environments like QEMU. The test checks Trace2 ancestry tracking by verifying process names in `/proc/<pid>/stat`, but emulators report the emulator’s name (e.g., "qemu-riscv64") instead of the guest process ("test-tool" or "git"), causing false negatives. Jamie Magee’s patch updates the test to skip itself when process names are unreliable, ensuring the fix doesn’t break native platforms while addressing the emulation edge case.

The patch has been approved in principle by Junio C Hamano, who called its grep pattern "tricky" but acceptable for a controlled test environment. However, Junio later clarified that "Will queue" only means placement in the `seen` branch for further exposure—not readiness for `next`—and explicitly requested a substantive review from a Trace2 domain expert before the fix can progress. That review is still pending, leaving the patch in limbo despite its narrow scope and uncontroversial goal.

The thread took a slight detour when Weijie Yuan asked a procedural question about Git’s commit message conventions, specifically whether `Cc:` trailers (common in the Linux kernel) are encouraged or documented in Git’s contribution guidelines. While this doesn’t affect the patch itself, it highlights a potential documentation gap for newcomers. The patch remains unchanged, and the core issue—waiting for a Trace2 expert’s review—is still unresolved. No other objections or technical concerns have been raised.
