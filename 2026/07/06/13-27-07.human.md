This is the fourth patch in Patrick Steinhardt’s five-part series introducing new reference-writing subcommands to `` `git refs` ``. The series is already merged, and this iteration (v4) makes no functional changes to the `` `create` `` subcommand itself—it remains identical to v3, including the typo fix for "null new object ID" that Junio C Hamano noted in his review.

The patch adds the `` `git refs create` `` subcommand, which provides an explicit, atomic way to create references that must not already exist. Unlike `` `git refs update` `` (which mirrors `` `git update-ref` `` and allows implicit creation), `` `create` `` enforces strict "must not exist" semantics: it rejects the operation if the reference already exists, even if the new value matches the old one. The implementation supports `` `--message=<reason>`` for reflog entries, `` `--no-deref`` to control symbolic-reference handling, and `` `--create-reflog`` to force reflog creation. The test suite (`` `t/t1466-refs-create.sh` ``) covers 151 lines of edge cases: atomicity checks, option handling, symref behavior, and error conditions.

The key usability question—whether `` `--no-deref`` is intuitive for symref handling—remains unresolved but is now explicitly documented in the tests. When the target reference is a symref, `` `create` `` dereferences it by default (creating the target reference), while `` `--no-deref`` makes the command fail with "dangling symref already exists". This behavior is consistent with other `` `git refs` `` subcommands but may surprise users who expect the option to enable symref creation. Patrick’s response to Toon Claes’s review dismissed the idea of a dedicated `` `--symref`` flag, noting that the option’s purpose is to enforce atomicity rather than enable symref creation.

The patch is technically solid and uncontroversial. The commit message is clear, the test coverage is thorough, and the implementation aligns with the project’s ongoing `` `the_repository` `` removal effort (though this patch itself doesn’t touch repository globals). No further changes are expected, as the series is already merged.
