This is a bugfix patch targeting the sparse-index subsystem. Derrick Stolee identifies and fixes a segfault that occurs when Git tries to collapse a full index into a sparse index while an "intent-to-add" entry exists outside the sparse-checkout cone. The crash happens because the cache tree node's `entry_count` can be negative (indicating invalidity), but the sparse-index conversion logic does not account for this.

The fix itself is minimal: the code now checks for a negative `entry_count` and skips collapsing that node, preventing the crash. Stolee acknowledges that a more thorough fix could collapse some directories further, but opts for the simplest solution given that the bug has not been reported by real users. Two new tests in `t1092-sparse-checkout-compatibility.sh` and `t3705-add-sparse-checkout.sh` verify the fix and demonstrate the interaction between intent-to-add entries and sparse-checkout.

The commit message is clear and well-structured, explaining the root cause, the fix, and the trade-offs. The patch is narrowly scoped and unlikely to introduce regressions elsewhere. If you work with sparse-checkout or sparse-index, this is worth reviewing to ensure the fix aligns with your expectations.
