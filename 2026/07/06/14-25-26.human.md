This is a refactoring patch that migrates the `askpass_program` global variable into `struct repo_config_values` as part of the ongoing libification effort. It is the fifth patch in Tian Yuchen’s nine-patch series that continues the work begun with the recently merged `excludes_file` migration.

The patch moves the heap-allocated string that holds the path to the credential-prompting program out of global scope and into the per-repository configuration structure. Memory management is now handled by the existing `repo_config_values_clear()` destructor, which is called during repository teardown. The change is mechanical: the global `askpass_program` is replaced with `cfg->askpass_program` in the config parser, and the single caller in `prompt.c` now reads the value via `repo_config_values(the_repository)->askpass_program`.

No user-visible behavior changes are introduced, and the patch passes CI. The commit message explains the motivation—eliminating a mutable global string to remove a thread-safety hazard and unblock further modularization—while acknowledging that per-repository askpass programs are uncommon in practice. This is one of the variables the author flagged in the cover letter as potentially controversial, so reviewer feedback on the trade-off may shape future work.
