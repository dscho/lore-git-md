This is a **build system** and **platform compatibility** follow-up in the ongoing `USE_NSEC` discussion. Patrick Steinhardt responds to D. Ben Knoble’s openness to converting `USE_NSEC` into a runtime-configurable flag (e.g., `core.useNsec`), proposing a concrete path forward while sidestepping the auto-detection challenges raised earlier.

Patrick’s proposal is incremental: keep the current build-time default (`USE_NSEC` disabled) but **always compile nanosecond timestamp support into Git** when the platform provides the necessary APIs. Users would then opt into the feature via a config knob (e.g., `core.useNsec = true`). This avoids the need for auto-detection during repository initialization—a sticking point in earlier discussion—while making the feature more accessible than the current build-time knob, which most distributors leave disabled. The approach mirrors how Git handles other optional behaviors (e.g., `core.ignoreCase`), though Junio’s earlier response noted that `USE_NSEC` is less critical than case-sensitivity.

The email acknowledges the desirability of automated testing but does not let its absence block progress. Patrick suggests that even without tests, the runtime-configurable approach would improve accessibility, as most users would no longer need to rebuild Git to enable nanosecond timestamps. This pragmatism contrasts with Knoble’s earlier caution about the "surgery" and testing required for runtime configuration, though Patrick does not address how the config knob would interact with existing build-time settings (e.g., would distributors need to update their configurations?).

Key technical details to track: the proposed **runtime config knob** (likely `core.useNsec`), the **build-time default** (disabled, matching current behavior), and the **compilation strategy** (always include nanosecond support if the platform allows it). The proposal does not resolve the default value for the config knob—Peff’s earlier suggestion of a conservative default (`false`) remains unaddressed—but it does offer a middle ground between Knoble’s build-time parity patch and Patrick’s earlier skepticism about the knob’s existence. No patch has been submitted yet, so the next step would likely be a prototype implementing `core.useNsec` and updating the build system to always compile in nanosecond support.
