This is a **build system** and **platform compatibility** follow-up in the ongoing debate about Git’s `USE_NSEC` mechanism. Patrick Steinhardt responds to D. Ben Knoble’s openness to converting `USE_NSEC` from a build-time knob to a runtime-configurable flag (e.g., `core.useNsec`).

Patrick proposes a pragmatic middle ground: keep the default behavior as `USE_NSEC` disabled (matching the current build-time default), but compile nanosecond timestamp support into Git unconditionally if the platform supports it. Users could then opt into the feature via configuration, making it more accessible than the current build-time knob—most distributions don’t enable it at all. This approach avoids the need for auto-detection (which Jeff King’s testing showed isn’t reliably portable) while still addressing Patrick’s earlier concern that a build-time knob is too coarse for filesystem behavior that varies at runtime.

The email doesn’t address the interoperability risks (e.g., mixing `USE_NSEC` and non-`USE_NSEC` implementations like Git and JGit) or the unresolved question of whether `USE_NSEC` should be deprecated entirely. Patrick’s proposal is incremental: it doesn’t flip the default to `true` (as Brian M. Carlson suggested) or remove the knob (as Patrick himself previously argued), but it does make the feature more discoverable and user-configurable. Testing remains a loose end—Patrick acknowledges that automated tests would be ideal but doesn’t propose a concrete plan, leaving the runtime-configuration idea as a plausible direction rather than a ready-to-implement patch.

For a busy reader, this email signals that the discussion is converging on a runtime-configurable `USE_NSEC` as the most likely path forward, though the details (default behavior, testing, interoperability) are still unresolved. The original Meson parity patch remains queued for merging, but its long-term relevance depends on whether the project adopts Patrick’s proposal or pivots to a more ambitious change.
