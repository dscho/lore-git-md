This is patch 8/9 in a refactoring series (v7) that continues the libification effort by migrating global configuration variables into `struct repo_config_values`. Specifically, this patch moves the `autorebase` enum (which controls whether newly created branches automatically rebase by default) from a global variable into the repository-specific configuration structure.

The changes are mechanical and follow the established pattern from earlier patches in the series. The `enum rebase_setup_type` is relocated higher in `environment.h` to make it visible to `struct repo_config_values`, and the global `autorebase` variable is replaced with a field in the repository's configuration instance. The default value `AUTOREBASE_NEVER` is initialized in `repo_config_values_init()`, and configuration parsing in `git_default_branch_config()` now writes directly to the repository's configuration. The only caller (`should_setup_rebase()` in `branch.c`) is updated to read from `repo_config_values(the_repository)->autorebase` instead of the global variable.

This patch is part of the broader `the_repository` removal effort and builds directly on the recently merged `excludes_file` migration. It introduces no user-visible behavior changes and is purely preparatory for further libification. The diff is small (14 lines changed across 3 files) and aligns with the series' goal of centralizing memory management for configuration variables. The `autorebase` enum is now stored alongside other repository-specific settings like `push_default` and `object_creation_mode`, which were migrated in earlier patches of this series.

Key symbols introduced/modified: `repo_config_values->autorebase`, `enum rebase_setup_type` (relocated), and the updated `git_default_branch_config()` logic. The patch touches `branch.c`, `environment.c`, and `environment.h`, and follows the same memory management pattern (heap allocation, cleanup via `repo_config_values_clear()`) as the rest of the series. No new getters are introduced; callers access the field directly via `repo_config_values(the_repository)`.

The patch is technically complete and CI-clean, but the series as a whole still has open RFC questions about the value of migrating program paths (editor/pager/askpass) and the relationship to prior discussions about `git_branch_track`. This patch itself is uncontroversial and focuses on a straightforward enum migration.
