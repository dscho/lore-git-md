This thread is about a bugfix for a segfault in Git’s sparse-index subsystem. The issue occurs when Git tries to collapse a full index into a sparse index while an intent-to-add (ITA) entry exists outside the sparse-checkout cone, triggering an out-of-bounds access in `convert_to_sparse_rec()`. Derrick Stolee authored a minimal fix that checks for invalidated cache-tree nodes (indicated by a negative `entry_count`) and skips them, preventing the crash. The patch includes tests to verify the fix and demonstrate the trade-off: some sparse directories that *could* be collapsed are left expanded due to the ITA entry, but this is deemed acceptable for now.

Junio C Hamano, the maintainer, reviewed and endorsed the patch, calling it "an easy and safe cop-out" and marking it for the `next` integration branch. No objections or additional edge cases were raised, and the discussion was brief. The patch is now poised to move from review to integration testing, with no open questions or follow-up work requested. The fix is self-contained and resolves the immediate issue without promising further optimizations.
