This thread is about a bug fix for a segfault in Git's sparse-index subsystem. The issue occurs when Git tries to collapse a full index into a sparse index while an intent-to-add (ITA) entry exists outside the sparse-checkout cone. Derrick Stolee identified the root cause—an out-of-bounds access in `convert_to_sparse_rec()` when iterating over cache-tree nodes with a negative `entry_count`—and submitted a minimal fix that skips invalidated nodes.

The patch has been unconditionally endorsed by Junio C Hamano, who called it "an easy and safe cop-out" over the crash. It is now queued in the `next` branch for integration testing, with no further changes expected. The fix resolves the immediate crash but leaves some performance optimizations unrealized, as valid child trees are not collapsed when an ITA entry is present. Stolee acknowledges this trade-off as acceptable given the bug's obscurity. Two new tests verify the fix and document the behavior. No open questions or follow-up work have been raised.
