This thread is about a bugfix for a segfault in Git’s sparse-index subsystem. The crash occurs when Git tries to collapse a full index into a sparse index while an intent-to-add (ITA) entry exists outside the sparse-checkout cone. Derrick Stolee identified the root cause—an out-of-bounds access in `convert_to_sparse_rec()`—and submitted a minimal fix that skips invalidated cache-tree nodes. The patch adds two new tests to verify the fix and its interaction with sparse-checkout.

Junio C Hamano, the maintainer, has marked the patch for the `next` branch, where it will undergo integration testing before graduating to `master`. Both Stolee and Junio agree the fix is sufficient for the immediate issue, though Stolee notes that a more involved change could recover some performance optimizations. There are no open questions or follow-up work planned. The patch is now confirmed for the next stage of the integration pipeline.
