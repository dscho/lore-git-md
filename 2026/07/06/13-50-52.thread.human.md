This thread is about a bugfix in Git's sparse-index subsystem. Derrick Stolee identified and fixed a segfault that occurs when Git tries to collapse a full index into a sparse index while an intent-to-add (ITA) entry exists outside the sparse-checkout cone. The crash happens because the code didn't account for negative `entry_count` values in cache-tree nodes (which indicate invalidation), leading to an out-of-bounds access.

The fix is minimal: it checks if `entry_count` is negative before attempting to collapse a cache-tree node, skipping the operation if so. This prevents the crash but leaves some performance optimizations on the table—specifically, the ability to collapse valid child trees even when an ITA entry is present. Stolee notes this trade-off but considers the current fix sufficient for the immediate issue, which is unlikely to affect real-world usage due to its obscurity.

The patch includes two new tests to verify the fix: one in `t3705-add-sparse-checkout.sh` for `git add` behavior with sparse-checkout, and another in `t1092-sparse-checkout-compatibility.sh` to demonstrate the interaction with the sparse index and compare it to full-index behavior. The tests use `git add -N` (intent-to-add) and `git sparse-checkout set` to trigger the scenario, then verify the index state with `git ls-files` and `git status`.

No follow-up discussion or review feedback has appeared yet, so the patch is still under initial consideration. The fix touches the sparse-index, cache-tree, and intent-to-add subsystems, with implications for how Git handles untracked files in sparse repositories.
