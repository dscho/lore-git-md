This is the third patch in Harald Nordgren’s v7 series introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The patch implements the core squash logic, including range resolution, input validation, merge commit handling, ref safety checks, and the replay of descendants.

The squash operation works by performing a single three-way merge of the entire range against the oldest commit’s parent, then replaying any commits above the range on top of the result. The range is parsed like `git rev-list` arguments, supporting compound ranges such as `HEAD~3..HEAD ^topic`. The implementation rejects ranges with multiple bases, merges whose other parents lie outside the range, and ranges whose oldest commit is a `fixup!`, `squash!`, or `amend!` (since the marker’s target cannot be inside the range). By default, it also refuses to proceed if any ref points to a commit inside the squashed range, with an advice message suggesting `--update-refs=head` to rewrite only the current branch.

The patch adds a new test script (`t/t3455-history-squash.sh`) with 632 lines of coverage, including tests for range parsing, merge commit handling (nested, octopus, and external-parent rejection), descendant replay, authorship preservation, ref-handling behavior, and strict input validation. The implementation is well-motivated and addresses all prior feedback from the thread, including Junio’s shape-based validation approach and Phillip Wood’s usability concerns about template formatting and input flexibility.
