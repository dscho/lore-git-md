This is a small bugfix patch targeting error reporting in the `` `git rm` `` command.

The patch changes a single line in `builtin/rm.c` where the code currently calls `die()` after a failed `remove_file_from_index()` system call. The new version uses `die_errno()` instead, which automatically includes the system error message (from `errno`) in the output. This makes the error message more informative for users when the failure is due to a system-level issue like permission problems or missing files.

The change is mechanical and follows Git’s established pattern of using `die_errno()` for system call failures. The commit message is minimal but sufficient for the scope of the change. There is no test coverage included, but the patch is unlikely to introduce regressions since it only improves error reporting without altering control flow.

This is a standalone patch, not part of a larger series. The author is a first-time contributor to the Git project. The patch looks well-targeted and uncontroversial.
