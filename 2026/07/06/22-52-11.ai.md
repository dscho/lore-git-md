This is the first patch in the v6 Rustification build system series, addressing the parallel build race condition in `git-credential-osxkeychain` by explicitly adding `$(RUST_LIB)` as a prerequisite. The patch resolves the blocking duplicate `main()` symbol issue from v5 by avoiding `$(GITLIBS)` (which includes `common-main.o`) and instead depending directly on `$(LIB_FILE)` and `$(RUST_LIB)`. This ensures Rust libraries are built before linking while preventing symbol conflicts, since `git-credential-osxkeychain.c` defines its own `main()` function.

The change is minimal and targeted: it updates the Makefile to add `$(RUST_LIB)` to the osxkeychain target’s prerequisites and wraps Rust-related definitions in `ifndef NO_RUST` to ensure clean no-op behavior when Rust is disabled. The commit message clearly explains the technical rationale, including why `$(GITLIBS)` cannot be used here despite being the standard prerequisite for other Git targets. This patch is a direct response to Junio C Hamano’s blocking feedback on v5 and is now unblocked for integration.

Key technical details include the explicit dependency on `$(RUST_LIB)`, the avoidance of `$(GITLIBS)` to prevent duplicate symbols, and the conditional `NO_RUST` handling. The patch touches only the `Makefile` and introduces no on-disk format changes. It is implicitly covered by existing build tests and maintains backward compatibility. The unresolved artifact layout question from Patrick Steinhardt does not affect this patch, which focuses solely on the race condition fix.
