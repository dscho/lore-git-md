This is the first patch in a two-patch bugfix series targeting a quadratic performance regression in the reftable backend. It adds test coverage for the problem being fixed: tombstone handling in ref operations.

The patch introduces two new tests. The first is a performance test (`t/perf/p1401-ref-store-tombstones.sh`) that measures the time taken to recreate refs after mass deletion, both when recreating the same refs and when creating differently-named refs. These scenarios currently exhibit quadratic behavior due to inefficient tombstone handling in the reftable backend. The test uses 8,000 refs to make the performance pathology obvious.

The second test is a correctness test (`t/t0610-reftable-basics.sh`) that verifies refs deleted and then recreated with the same names remain visible afterward. This ensures the fix does not break basic ref visibility semantics.

The tests are narrowly scoped to the reftable backend and focus on the specific edge case being addressed in the series. The commit message clearly explains the scenarios being tested and why they matter. The performance test in particular provides a clear baseline for measuring the impact of the upcoming optimization in patch 2/2.

This patch is well-motivated and thorough. It provides both correctness and performance coverage for the regression, making it easier to review and validate the actual fix. No controversial design choices are evident here—just solid test infrastructure for a real problem.
