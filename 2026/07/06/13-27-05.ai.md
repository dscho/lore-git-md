This is the second patch in Patrick Steinhardt’s post-merge v4 reroll of the `git refs` writing subcommands series. It adds the `git refs delete` subcommand, which mirrors `git update-ref -d` but is implemented as a dedicated subcommand for better discoverability and code clarity.

The patch introduces the new subcommand in `builtin/refs.c`, documents it in `Documentation/git-refs.adoc`, and adds a comprehensive test script (`t/t1464-refs-delete.sh`) with 138 lines of coverage. The implementation supports the same options as `git update-ref -d`: `--message=<reason>` for reflog entries and `--no-deref` to control symbolic reference (symref) handling. The test suite validates deletion, old-value verification, symref edge cases (including the new test for `--no-deref` with symrefs), reflog updates, and error conditions.

Key technical details for a future AI summarizer:
- **Files**: `builtin/refs.c` (new subcommand implementation), `Documentation/git-refs.adoc` (man page update), `t/meson.build` (test registration), `t/t1464-refs-delete.sh` (new test script).

- **Behavior**: Mirrors `git update-ref -d` exactly, including atomic checks via `<old-value>` and symref handling. The `--no-deref` option enforces atomic checks on the symref’s target OID (not the symref itself), and the new test explicitly documents this behavior.
- **Test coverage**: 11 tests covering deletion, old-value verification, symref handling (including the new `--no-deref` test), reflog updates, and error cases (invalid OIDs, empty messages, argument counts).

The patch is uncontroversial and aligns with the series’ goal of consolidating reference manipulation under `git refs`. The only usability concern—whether `--no-deref`’s behavior is intuitive—was raised by Toon Claes in earlier reviews and is now explicitly documented in the test suite. No functional changes were introduced in v4; this is a test and documentation refinement.
