This is the **fifth patch in the v4 series** that mechanically converts bare `grep` assertions to `test_grep` across Git’s test suite. The patch touches **338 test files**, replacing roughly 2,800 `grep` calls with `test_grep` to improve debuggability—when a `test_grep` fails, it prints the file contents, whereas bare `grep` fails silently.

The conversion is driven by `greplint.pl`, a new linter introduced earlier in the series. The patch’s commit message provides a step-by-step recipe for reproducing the conversion, including manual adjustments for two edge cases: one where `.git/packed-refs` may be absent under the reftable backend (guarded by `test_have_prereq REFFILES`) and another where `git~2` is an NTFS 8.3 short name that exists only when short-name generation is enabled (guarded by `test -f`). The linter skips `grep` calls used as data filters (e.g., `grep | wc -l` or `x=$(grep ...)`), leaving them annotated with `# lint-ok`.

The patch is purely mechanical, with no functional changes to the tests themselves. It is part of a **technically complete and maintainer-approved series** that also fixes three pre-existing test bugs where `grep` was missing file arguments. The series is expected to graduate to `next` shortly.
