This is a **substantive review reply** in Jeff King’s memory-leak bugfix series, focusing on the design of an idempotent `git_hash_discard()`. Patrick Steinhardt responds to Jeff’s exploration of idempotency tradeoffs with a clear preference for **strict enforcement**: he proposes that calling any hash function (`git_hash_update()`, `git_hash_final()`, etc.) on an uninitialized context should trigger a `BUG()` rather than silently reinitializing or ignoring the call. This aligns with his earlier stance on avoiding subtle bugs from non-idempotent APIs (e.g., reference transactions) and prioritizes fail-fast behavior over flexibility.

The discussion centers on three unresolved questions from Jeff’s email:
1. **How to handle calls on inactive contexts** – Patrick rejects both silent no-ops and auto-reinitialization, arguing that `BUG()` is the most sensible solution to catch misuse early.
2. **Whether to check the `active` flag during initialization** – He endorses Jeff’s suggestion to split initialization into a zero-allocation `HASH_CTX_INIT` step and a `git_hash_start()` function that enforces the active flag, preventing leaks from redundant `init_fn()` calls.
3. **Implementation timing** – Both agree that idempotency improvements should land *after* the current series, avoiding disruption to the leak fixes.

### Key implications for the series

- The current patch 7’s `hash_ctx_valid` flag (tracking whether `git_hash_final()` was called) would become redundant if idempotency is implemented, but the patch remains correct as-is.
- No changes are needed to the existing series; Patrick’s feedback is forward-looking for a follow-up patch.
- The `BUG()`-on-misuse approach would require fixing direct backend calls (e.g., in `submodule--helper.c`) to use the public API, as these bypass the `active` flag logic.

**Why this matters**: The exchange clarifies the project’s risk tolerance for hash context management. Patrick’s strict stance suggests future reviewers may favor fail-fast designs, while Jeff’s pragmatic diff keeps the current series focused on correctness.
