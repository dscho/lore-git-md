This is the first patch in a two-patch bugfix series targeting a quadratic performance regression in the reftable backend. It adds test coverage for the regression, which manifests when re-creating refs that were previously deleted (tombstoned).

The patch introduces two new tests: a performance test (`p1401-ref-store-tombstones.sh`) and a correctness test (`t0610-reftable-basics.sh`). The performance test exercises two scenarios: recreating the same refs after deletion (which currently exhibits quadratic behavior) and creating new, differently-named refs after deleting old ones (a worse case where tombstones sort after the new refs, forcing every creation to scan all tombstones). The correctness test verifies that refs deleted and then re-created with the same names remain visible afterward.

The test setup is thorough, using 8,000 refs to clearly demonstrate the performance pathology. The asymmetric scenario is particularly valuable, as it exposes the worst-case behavior where tombstones and new refs sort in opposite order. The correctness test, while simpler, ensures the fix does not break basic ref visibility. Both tests are narrowly scoped to the reftable backend and focus on the specific tombstone-related regression.

This patch is purely additive and does not change any production code. It provides the necessary baseline for evaluating the performance fix in the second patch, which will reduce runtime from ~14s to ~0.2s in these scenarios. The test coverage appears well-designed to catch regressions and validate the fix's correctness. No controversial elements are present; the tests are straightforward and directly address the stated problem.
