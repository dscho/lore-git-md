This is the fourth patch in Patrick Steinhardt’s five-part series adding reference-writing subcommands to `git refs`. The series is already merged (v3 was queued for the next release), and this iteration makes no functional changes—only test additions and minor stylistic tweaks in response to earlier feedback.

Patch 4/5 introduces the `git refs create` subcommand, which provides an explicit, atomic way to create references. Unlike `git refs update` (which mirrors `git update-ref` and allows implicit creation), `create` enforces that the reference must not already exist, even if the new value matches the old one. The implementation supports `--message=<reason>` for reflog entries, `--no-deref` to control symbolic reference (symref) handling, and `--create-reflog` to force reflog creation. The test suite (`t/t1466-refs-create.sh`) covers 151 lines of edge cases, including atomicity checks, symref behavior, reflog handling, and error conditions (invalid OIDs, empty messages, and argument counts).

The key design choice here is the atomic "must not exist" semantics, which contrasts with `update`’s implicit creation. This addresses the asymmetry Patrick noted in the cover letter: while `git refs delete` provides a dedicated shortcut for deletion, there was no equivalent for creation. The subcommand’s behavior is now well-documented in both the man page and tests, though usability questions about `--no-deref` remain unresolved (see thread context). The option’s purpose is to enforce atomicity by failing if the target exists as a symref, but its obscurity and counterintuitive behavior (e.g., requiring prior knowledge of symref existence) were flagged by Toon Claes in earlier reviews.

- **Files**: `builtin/refs.c` (adds the `cmd_refs_create` function and updates the subcommand dispatch table), `Documentation/git-refs.adoc` (adds the `create` subcommand to the synopsis and description), `t/meson.build` (registers the new test script), and `t/t1466-refs-create.sh` (151-line test suite).
- **New symbols**: Subcommand `git refs create`; CLI options `--message`, `--no-deref`, and `--create-reflog`.
- **Behavior**:
  - Rejects creation if the reference exists (even with the same value), enforcing atomic "must not exist" semantics.
  - `--no-deref` controls symref handling: if the target exists as a symref, the command fails with "dangling symref already exists" (tested in `create with symref target and --no-deref refuses to create reference`). The option does not enable symref creation.
  - No reflog is created by default; `--create-reflog` forces reflog creation.
  - Error messages cover invalid OIDs, null OIDs, empty messages, and incorrect argument counts.
- **Test coverage**: Validates atomicity, symref edge cases (including `--no-deref` behavior), reflog handling, and error conditions. The symref test explicitly confirms that `--no-deref` prevents creation when the target exists as a symref.
