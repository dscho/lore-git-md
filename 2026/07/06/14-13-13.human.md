This is a build system documentation patch from Junio C Hamano, the Git maintainer, addressing the Rust-related regression report in Git 2.55.0.

Junio confirms that the build failure reported by Kurt Mielke is expected behavior: Git 2.55.0 is the first release where Rust support is enabled by default, though it remains optional via `NO_RUST=1`. He attaches a small patch to update the 2.55.0 release notes, fixing an incomplete sentence that previously stated Rust support would be enabled by default "in some future version of Git." The corrected wording now clearly states that Rust support *is* enabled by default in 2.55.0 and will become mandatory in a future version.

The patch itself is trivial — a two-line edit to `Documentation/RelNotes/2.55.0.adoc` — but it serves as an official acknowledgment of the change. Junio expresses mild surprise that no one had previously noticed the outdated release note text, but does not comment on whether the default change was premature or whether the build system should auto-detect Rust toolchain availability. The tone is matter-of-fact: the behavior is intentional, the release notes needed updating, and the patch does that.

For readers following the thread, this email resolves the core question: the Rust requirement in 2.55.0 is not a regression, but a deliberate (if under-documented) change. The discussion may now shift to whether the build system should auto-detect Rust toolchains or whether `NO_RUST=1` remains a supported long-term configuration.
