This is the fourth patch in Patrick Steinhardt’s nine-patch v3 series making `GIT_TEST_LONG` tests reliable and efficient for CI. It directly targets `t5608-clone-2gb.sh`, a test that verifies Git’s ability to handle large repositories. The test currently peaks at 16 GB of disk usage, which is excessive even for CI environments. Patrick refactors the test to delete repositories as soon as they are no longer needed, cutting peak disk usage in half to 8 GB.

The change is mechanical and defensive: each repository created (`2gb-repo`, `clone-bare`, `clone-wt`, `4gb-repo`, `4gb-clone-unpack`, `4gb-clone-index`) is now wrapped in `test_when_finished rm -rf` so it is automatically removed when the test block exits. The diff is straightforward, moving the repository setup into a dedicated directory (`2gb-repo`) and adding the cleanup hooks. No behavior changes are introduced; the test still exercises the same edge cases around large objects and clones.

Jeff King (Peff) reviewed the v1 version and called it an “obvious improvement” for disk usage and defensive isolation of expensive test data. There has been no controversy or follow-up discussion on this patch; it is uncontroversial and ready for integration. The reduction in disk usage is measurable and meaningful for CI runners, making the test more practical to run in resource-constrained environments.
