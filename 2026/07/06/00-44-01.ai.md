This is a **brief technical follow-up** in Jeff King’s memory-leak bugfix series, clarifying a detail in the proposed idempotency design for `git_hash_discard()`. The email corrects an earlier claim: while adding an `active` flag to `struct git_hash_ctx` and setting it in `git_hash_init()` would make `git_hash_discard()` safe for most callers, it would **not** protect direct calls to backend-specific `init_fn()` functions (e.g., `algo->init_fn(&ctx)`). These callers bypass the public API and would need to be updated to use `git_hash_init()` instead.

Key technical details for the summarizer:
- **Problem**: Direct calls to `algo->init_fn()` (in `submodule--helper.c` and `test-synthesize.c`) would not set the `active` flag, leaving `git_hash_discard()` unable to track initialization state.
- **Solution**: Jeff proposes converting these callers to use `git_hash_init()`, which would centralize the `active` flag logic.
- **Scope**: Only two files are affected (`submodule--helper.c` and `test-synthesize.c`), and the change is mechanical (replacing `algo->init_fn(&ctx)` with `git_hash_init(&ctx, algo)`).
- **Impact**: This is a prerequisite for the idempotency design but does not block the current series, which remains correct without it. The fix could be applied in a follow-up patch.
- **No new objections**: The email is a factual correction, not a debate. Patrick Steinhardt’s earlier idempotency suggestion remains unchallenged, and Jeff’s proposal addresses the implementation gap.
