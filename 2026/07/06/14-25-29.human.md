This is the eighth patch in a nine-patch refactoring series that continues the libification effort by moving global configuration variables into `struct repo_config_values`. Specifically, this patch migrates the `autorebase` enum, which controls whether newly created branches automatically rebase by default.

The change is mechanical and follows the established pattern: the global `autorebase` variable is removed, the `enum rebase_setup_type` is relocated in `environment.h` to make it visible to `struct repo_config_values`, and the enum is added as a field to that struct. The default value (`AUTOREBASE_NEVER`) is initialized in `repo_config_values_init()`, and configuration parsing in `git_default_branch_config()` is updated to write directly to the repository’s configuration instance. The only caller (`should_setup_rebase()` in `branch.c`) is updated to read from `repo_config_values(the_repository)->autorebase` instead of the global.

The patch is clean and well-contained, touching only three files (`branch.c`, `environment.c`, and `environment.h`). There are no user-visible behavior changes, and the migration aligns with the series’ goal of eliminating globals and centralizing memory management. This is a straightforward continuation of the work begun in the recently merged `excludes_file` series, and it looks ready for review. No controversy or loose ends are apparent in this specific patch.
