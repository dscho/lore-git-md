This is the first patch in the v5 series refining Git's Rust build system integration for macOS. It addresses a parallel build race condition in the `git-credential-osxkeychain` helper by making its build rule consistent with the rest of the codebase.

The patch adds `$(GITLIBS)` as a prerequisite to the `git-credential-osxkeychain` target in the Makefile. `$(GITLIBS)` already bundles `common-main.o`, `$(LIB_FILE)`, and `$(RUST_LIB)` (when Rust is enabled), so this change ensures the helper links against Rust libraries when Rust is enabled, resolving the race condition where Cargo might not build `libgitcore.a` before the helper is linked. The commit message explains this rationale clearly, framing the change as a consistency improvement rather than just a bugfix.

Additionally, the patch wraps the definitions of `$(RUST_LIB)` and the "rust" build target in `ifndef NO_RUST` guards. This ensures that when `NO_RUST=1` is specified, `$(RUST_LIB)` evaluates to empty, making the Rust dependency a clean no-op without needing intermediate variables. The change is minimal, touching only the Makefile, and maintains backward compatibility.

This patch directly resolves Patrick Steinhardt's earlier substantive review concern about build dependency structure. The v5 iteration consolidates the feedback into a single logical change, improving clarity and maintainability. The Universal Binary support (patch 2/2) remains decoupled from this fix. The patch is well-motivated, with a clear commit message explaining the technical rationale, and is ready for integration. No new tests are needed, as the change is implicitly covered by existing build tests.
