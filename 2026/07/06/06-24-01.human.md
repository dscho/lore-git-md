This is the sixth patch in Patrick Steinhardt’s nine-patch v3 series making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets `t7900-maintenance.sh`, an expensive test that creates a 2 GB repository to exercise the `incremental-repack` task. The patch isolates the large repository into a dedicated sub-repository (`expensive-repo`) and deletes it immediately after the test using `test_when_finished`, cutting peak disk usage by 2 GB and preventing the repository from lingering until the end of the test suite. It also disables auto-maintenance to avoid races with the manual maintenance commands.

The change is a straightforward, well-motivated cleanup. The commit message clearly explains the problem (clogging disk and potentially affecting other tests’ heuristics) and the solution (isolation and immediate cleanup). The patch itself is mechanical and focused, touching only the test script and using established patterns (`test_when_finished`, subshell isolation). No new user-facing behavior or on-disk format changes are introduced.

This patch is uncontroversial and ready for integration. It complements the efficiency improvements in patches 3 and 4, which also reduce resource usage in `GIT_TEST_LONG` tests. The series as a whole is now complete and addresses all feedback from earlier revisions.
