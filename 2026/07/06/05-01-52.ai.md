This is the **v4 submission of a test infrastructure series** that introduces `greplint.pl` to convert bare `grep` assertions in Git's test suite to `test_grep`. The series is now **technically complete and approved for merging**, with only minor documentation tweaks since v3. It addresses all prior feedback, including the maintainer’s concerns about edge cases and `# lint-ok` annotations.

The core goal remains unchanged: replacing bare `grep` with `test_grep` to improve debuggability (since `test_grep` prints file contents on failure). However, v4 refines the approach for handling conditionally present files—such as backend-specific paths or platform-dependent short names—by requiring explicit guards (e.g., `test_have_prereq REFFILES` or `test -f <path>`) around `test_grep` calls. This replaces the previous reliance on `# lint-ok` annotations for missing-file cases, which the maintainer found problematic. The only remaining `# lint-ok` annotations now document greps used as data filters (e.g., `grep | wc -l` or `x=$(grep ...)`), where the linter’s pipeline heuristic cannot detect the enclosing redirect.

Key changes since v3:
- **Documentation updates**: `t/README` now encourages explicit guards for conditionally present files, with a worked example for `REFFILES` and `test -f`. The term "plain guarded 'grep'" is replaced with clearer guidance.
- **Edge-case handling**: The last missing-file-tolerant `! grep` (in `t7450-bad-git-dotfiles.sh`, checking NTFS 8.3 short names) is converted to a guarded `test_grep` using `test -f`. This removes the only `# lint-ok` annotation that previously exempted an assertion rather than a data filter.
- **Linter behavior**: `greplint.pl`’s `lint_ok()` comment now strictly documents greps used as data filters, not missing-file cases. The two remaining `# lint-ok` annotations (in `t5326` and `t5702`) are for this purpose.

The series also fixes three pre-existing bugs where `grep` was missing file arguments (now reading empty stdin), extracts `chainlint.pl`’s shell parser into a shared module (`lib-shell-parser.pl`), and corrects a latent line-counting bug in the lexer. The bulk conversion touches ~340 test files, replacing ~2800 `grep` assertions. The linter is wired into the build system with `test-greplint` and `check-greplint` targets.

**Files introduced or modified**:
- `greplint.pl`: The linter, with test fixtures under `t/greplint/`.
- `lib-shell-parser.pl`: Shared shell tokenizer for `chainlint.pl` and `greplint.pl`.
- `t/README`: Documents `test_grep` and its requirements (e.g., file existence).
- `Makefile`: Adds `test-greplint` and `check-greplint` targets.

**Known limitations**: The linter does not flag `grep` with redirects (e.g., `grep pattern file >/dev/null` or `grep pattern <file`), as these require judgment calls about preserving output behavior. A follow-up series may address these once conventions are established.

This version is **ready for integration**, with no open technical concerns. The maintainer’s prior skepticism about `# lint-ok` annotations has been resolved by the shift to explicit guards, and the series is expected to graduate to `next` shortly. The shared parser infrastructure also enables future lint rules.
