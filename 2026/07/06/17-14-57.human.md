This is the second patch in the v5 series refining Git's Rust build system integration for macOS, focusing on Universal Binary support. It introduces the `RUST_TARGETS` environment variable, allowing users to specify multiple target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`) for cross-compilation. The build system compiles each target separately via Cargo, then combines the resulting static libraries into a single Universal Binary using `lipo`—a standard macOS tool for creating multi-architecture binaries.

The patch is well-motivated and addresses a practical need for macOS distribution and CI workflows, where Universal Binaries are the norm. It assumes `lipo` is available (part of Xcode Command Line Tools), a reasonable assumption for Git's build system, as noted by D. Ben Knoble in earlier discussion. The implementation is clean: it adds declarative pattern rules for per-target compilation, uses `mkdir_p_parent_template` to ensure directory creation before `lipo` runs, and maintains backward compatibility by falling back to single-target builds when only one triple is specified.

One open question remains about the artifact layout in the `target/` directory. Patrick Steinhardt pointed out that the current design places the universal library in `target/release/` while per-architecture artifacts land in `target/<triple>/release/`, which deviates from Cargo's conventions. The authors have not addressed this in v5, but the functionality is complete and sufficient for practical use. The patch is ready for integration unless further discussion on the layout question leads to a revision.

The change is narrowly scoped to the `Makefile` and introduces no on-disk format changes. It’s a build-time improvement that complements the first patch in the series (which fixed a parallel build race condition). If you care about macOS packaging or Rust integration, this patch is worth reviewing, but it’s unlikely to be controversial beyond the artifact layout detail.
