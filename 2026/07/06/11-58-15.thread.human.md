This thread is about a safety patch for `contrib/subtree` that prevents the legacy shell-script version of `git subtree` from running on repositories that have already been processed by the new Rust rewrite. The patch adds a check in the shell script to detect the presence of the Rust tool's configuration file (`.git-subtree/config`) and bail out with a clear error message if found, directing users to the new tool instead.

The change is minimal—it touches only `git-subtree.sh`, adding a helper function and calling it in the three main entry points (`add`, `split`, and `merge`). The motivation is to avoid silent data corruption during the transition period, since the Rust rewrite uses a different on-disk format. The patch is forward-compatible but not backward-compatible: once a repository adopts the Rust tool, the shell script will refuse to run, ensuring users don’t mix the two implementations.

This is the first of a two-patch series, and while the second patch isn’t included here, the goal is clear: to prevent mixed-tool usage during the migration. The patch itself is straightforward, with no behavior change for repositories that haven’t used the Rust tool yet. No tests are included, but the logic is simple and self-contained. So far, there’s been no review feedback, so the patch’s fate remains open.
