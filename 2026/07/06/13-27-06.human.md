This is the third patch in Patrick Steinhardt’s five-part series adding reference-writing subcommands to `git refs`. The series is already merged, and this reroll (v4) makes no functional changes to this patch—it only adds tests and stylistic tweaks elsewhere in the series.

The patch introduces the `git refs update` subcommand, which mirrors `git update-ref`’s behavior. It allows updating a reference to a new object ID, optionally verifying the old value for atomicity. Special cases include:
- An all-zero `<new-value>` deletes the reference.
- An all-zero `<old-value>` ensures the reference does not exist (enabling atomic creation).
- The command supports `--message` for reflog entries, `--no-deref` to avoid dereferencing symbolic refs, and `--create-reflog` to force reflog creation.

The implementation is straightforward: it parses arguments, validates object IDs, and delegates to `refs_update_ref()`. The test suite (`t/t1465-refs-update.sh`) is thorough, covering 268 lines of edge cases—creation, modification, deletion, symref handling, reflog behavior, and error conditions. No new usability concerns were raised in this patch; the focus was on ensuring parity with `git update-ref`.

This patch is uncontroversial and well-tested. The only open questions about the series (e.g., symref handling in `delete`/`rename`) are addressed in other patches. If you’re tracking the `git refs` consolidation effort, this is a stable, incremental addition.
