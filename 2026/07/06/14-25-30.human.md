This is the final patch in Tian Yuchen’s nine-part refactoring series that moves more global configuration variables into `struct repo_config_values`. This specific patch migrates `object_creation_mode`, an enum that controls whether Git creates object files using hardlinks or renames.

The change is mechanical and follows the established pattern: the enum definition is moved higher in `environment.h` so it’s visible to `struct repo_config_values`, the global variable is removed, and the per-repository default is set in `repo_config_values_init()`. The configuration parser in `git_default_core_config()` now writes directly to the repository-specific structure, and the sole caller in `object-file.c` is updated to read from `repo_config_values(repo)->object_creation_mode` instead of the global.

This is a clean, well-contained step in the ongoing libification effort. The patch is small, touches only three files, and introduces no user-visible behavior changes. It looks ready to merge once the rest of the series settles, assuming the RFC questions about program-path migration and the relationship to `git_branch_track` don’t surface unexpected concerns.
