This is the seventh iteration of Harald Nordgren’s `git history squash` feature, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now functionally complete and addresses all prior feedback, including a major design change in v7 to align the `--reedit-message` template with `git rebase -i`’s squash behavior.

The headline change in v7 is the adoption of `git rebase -i`’s squash-message template. The `--reedit-message` flag now builds the same editor template that `git rebase -i` shows for a squash: a combination of an "N commits" banner with each folded message under its own header, following autosquash rules for markers. Specifically, a `fixup!` message is fully commented out under a "will be skipped" header, while a `squash!` or `amend!` keeps its body with only the marker subject commented so its remark can be reworded. This required extracting helper functions from the sequencer (`add_squash_combination_header`, `add_squash_message_header`, and `squash_subject_comment_len`) to ensure both commands build the identical template from one source. The commit message and documentation have been expanded to clarify this behavior and scope the merge limitation more precisely.

Other changes in v7 include:
- Refusing a range whose oldest commit is a `fixup!`, `squash!`, or `amend!`, since the marker’s target cannot be inside the range.
- Reordering the squash usage so dashed options come before `<revision-range>`, and spelling out `HEAD` instead of `@` in the documentation and examples.
- Expanding the squash commit message and documentation with an overview of the feature and clarifying the merge limitation to avoid contradicting the ability to fold a single-base interior merge.

The implementation remains a single three-way merge of the entire range against the oldest commit’s parent, followed by replaying descendants. The range is read like the arguments to `git rev-list`, supporting compound ranges such as `HEAD~3..HEAD ^topic`. The ref-handling logic rejects operations where any ref points to a commit inside the squashed range by default, with an advice message suggesting `--update-refs=head` to retarget only the current branch.

Files touched include `builtin/history.c` (390 insertions, 108 deletions across the series), `sequencer.c`/`sequencer.h` (extracted helpers), `advice.c`/`advice.h`, `Documentation/git-history.adoc`, and a new test script `t/t3455-history-squash.sh` (632 lines). The series is ready for Junio’s final assessment; no further design changes are expected. The only open question from prior discussion is whether `--reedit-message` should be the default, but this is a minor usability tweak that does not block merging.
