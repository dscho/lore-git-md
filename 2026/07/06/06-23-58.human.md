This is a test performance fix, part 3 of a 9-patch series. Patrick Steinhardt addresses an inefficient test in `t4141-apply-too-large.sh` that was generating a 1GB patch to verify `git apply` rejects overly large patches. The old implementation used `test_copy_bytes` (which copies one byte at a time via `dd ibs=1`) on top of `test-tool genzeros`, resulting in 1 billion read/write operations and taking up to 40 minutes in CI.

The patch removes the redundant `test_copy_bytes` call and instead passes the size limit directly to `genzeros`, which is already optimized for fast data generation. This change reduces test execution time from minutes to under a second on Patrick’s system. The EXPENSIVE prerequisite is retained because `git apply` still consumes 1GB of memory, but the test is now far less burdensome to run. The fix is straightforward and well-motivated, targeting a clear pain point in the test suite.
