This is the seventh patch in the v3 series making `GIT_TEST_LONG` tests reliable and efficient for CI. It introduces consistent boolean parsing for the `GIT_TEST_LONG` environment variable by switching to the `test_bool_env` helper, which allows the variable to be explicitly disabled (e.g., `GIT_TEST_LONG=false`).

The change is mechanical and touches only two files: `ci/lib.sh` and `t/test-lib.sh`. In `ci/lib.sh`, the patch updates the CI script to set `GIT_TEST_LONG=true` (instead of `YesPlease`) when enabling long tests for integration branches, aligning with the boolean convention. In `t/test-lib.sh`, it replaces the direct `test -n "$GIT_TEST_LONG"` check in the `EXPENSIVE` prerequisite with `test_bool_env GIT_TEST_LONG false`, ensuring the variable is parsed as a boolean. The `parse_option` function is also updated to set `GIT_TEST_LONG=true` when the `--long-tests` flag is passed.

This patch is uncontroversial and part of a broader effort to standardize how Git’s test suite handles boolean environment variables. The change is small but improves consistency, particularly for users who want to explicitly disable `GIT_TEST_LONG`. No behavioral changes are introduced—only the internal parsing logic is updated. The patch is ready for integration and has no dependencies or open questions.
