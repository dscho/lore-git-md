This is a test fix patch, part 2 of a 9-patch series from Patrick Steinhardt. The series targets test suite robustness, specifically addressing issues with `EXPENSIVE` tests that behave poorly on 32-bit platforms.

The patch skips a test in `t0021-conversion.sh` that writes and processes a 2 GB file. On 32-bit systems, this test doesn’t just fail—it hangs indefinitely, likely due to limitations around `SSIZE_MAX` and memory allocation. The fix is straightforward: the test now runs only when `SIZE_T_IS_64BIT` is defined, effectively restricting it to 64-bit platforms.

The commit message explains the context clearly: the issue only became visible after CI started running expensive tests by default (commit `7a094d68a2`), and attempts to detect or handle the failure reliably proved impractical. The solution—skipping the test—is pragmatic and uncontroversial. The patch itself is minimal, changing a single line in the test script.
