This is a brief follow-up in the now-merged `git refs` subcommand series. Patrick Steinhardt confirms that the `git refs rename` subcommand does **not** support renaming symbolic references (symrefs). The limitation stems from the underlying ref backends, not from an intentional design choice. While the code and documentation do not explicitly forbid symref renaming, the feature is simply not implemented, and attempting to rename a symref will fail.

The exchange is a minor clarification rather than a substantive discussion. Toon Claes’s question was a usability observation about whether symref renaming was supported and documented; Patrick’s reply closes the loop by stating the current behavior. No further changes are planned or expected, as the series is already merged and considered complete. The limitation may be revisited in future work, but for now, users who need to rename symrefs will have to continue using `git symbolic-ref` or manual file operations.
