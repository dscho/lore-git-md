This is the first patch in the v6 series refining Git’s Rust build system integration for macOS. It fixes a parallel-build race condition in the `git-credential-osxkeychain` helper by explicitly adding `$(RUST_LIB)` as a prerequisite, ensuring Cargo builds the Rust library before linking. The patch also avoids a duplicate `main()` symbol conflict by not using `$(GITLIBS)` (which includes `common-main.o`) and instead depending directly on `$(LIB_FILE)` and `$(RUST_LIB)`. The change is wrapped in `ifndef NO_RUST` guards, making it a clean no-op when Rust is disabled.

The commit message clearly explains the technical rationale: `git-credential-osxkeychain.c` defines its own `main()` function, so linking against `common-main.o` (via `$(GITLIBS)`) would cause a duplicate symbol error on macOS. The fix is minimal and targeted, touching only the `Makefile` and preserving backward compatibility. This resolves the blocking issue Junio C Hamano raised in v5, unblocking the series for integration. The patch is well-motivated and ready for review.
