This is the second patch in the v6 series adjusting Git's build system to support Rust components on macOS. It implements Universal Binary support for Rust libraries via the `RUST_TARGETS` environment variable, allowing a single Git build to run natively on both Intel and Apple Silicon Macs.

The patch bridges a gap between Apple's toolchain and Cargo: while clang natively supports universal builds via `-arch` flags, Cargo requires separate invocations for each target triple. When `RUST_TARGETS` specifies multiple triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`), the build system compiles each target separately, then combines the resulting static libraries into a single Universal Binary using `lipo`. The combined library integrates seamlessly with Git's C code during linking.

The implementation is clean and well-explained. It introduces declarative pattern rules for target-specific builds, uses `mkdir_p_parent_template` to ensure directory creation, and conditionally invokes `lipo` only when multiple targets are specified. The patch assumes `lipo` is available (part of Xcode Command Line Tools), an assumption validated in earlier discussion as reasonable for Git's build system. It maintains backward compatibility: when `RUST_TARGETS` is unset, behavior remains unchanged.

Patrick Steinhardt's unresolved question about the `target/` directory artifact layout remains open, but the current design is functionally complete and aligns with practical macOS distribution needs. The patch is ready for integration, with no known blockers. It is a key enabler for Rustification on macOS, particularly for internal distribution and CI packaging workflows.
