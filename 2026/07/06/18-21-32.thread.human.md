This thread is about a small but useful bugfix to `git rm`. A first-time contributor noticed that when `git rm` fails due to a system-level error (like permission issues), the error message doesn't include the system's explanation of what went wrong. The patch swaps a plain `die()` call for `die_errno()`, which automatically appends the system error message, making troubleshooting easier for users. The change is in `builtin/rm.c` and follows Git's established pattern for error reporting.

The patch itself is straightforward—just one line changed—and doesn't alter how the command behaves, only how it reports failures. There's no test coverage, but that's understandable for a tiny improvement like this. So far, the patch looks uncontroversial and ready to be picked up. No reviews or objections have been posted yet, so the next step is likely just waiting for a maintainer to queue it.
