This is the fifth patch in Patrick Steinhardt’s nine-patch series (v3) making `GIT_TEST_LONG` tests reliable and efficient for CI. It targets a specific test in `t7508-status.sh` that creates and tracks files larger than 4 GiB — an operation that only works on platforms where `size_t` is at least 64 bits. On 32-bit systems (where `size_t` is typically 32 bits), Git cannot accurately track object sizes this large, causing the test to fail and, in the case of the `linux32` CI job, hang indefinitely.

The fix is straightforward: the test now includes the `SIZE_T_IS_64BIT` prerequisite, ensuring it only runs on platforms where it can succeed. This resolves a long-standing issue in GitHub CI where the `linux32` job was failing and hanging since `GIT_TEST_LONG` tests were enabled for integration branches in May 2026. The change is minimal — just one line in the test script — and well-motivated, addressing both correctness and CI reliability.

This patch is uncontroversial and ready for integration. It complements the broader series goal of making `GIT_TEST_LONG` tests both reliable and efficient, and it aligns with the pragmatic approach taken elsewhere in the series (e.g., skipping tests on platforms where they are known to be broken).
