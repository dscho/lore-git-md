This is the **final version of a now-approved test infrastructure series** that introduces `greplint.pl`, a linter to convert bare `grep` assertions in Git’s test suite to `test_grep`. The series has evolved from a straightforward conversion tool into a careful audit of test reliability, addressing edge cases where automated conversion could mask or introduce bugs.

The core goal remains improving debuggability—`test_grep` prints file contents on failure, unlike bare `grep`—but v4 tightens the rules around when `test_grep` is appropriate. The key change since v3 is a **shift in philosophy**: instead of tolerating missing files with `# lint-ok` annotations, the series now **requires explicit guards** (prerequisites or `test -e` checks) for conditionally present files. For example, the NTFS 8.3 short-name check in `t7450-bad-git-dotfiles.sh` now uses `test -f` to guard the assertion, ensuring the file exists before calling `test_grep`. This removes the last `# lint-ok` exemption for an assertion (down from two in v3) and makes the logic more transparent.

The series also **fixes three pre-existing bugs** where `grep` was missing file arguments (now reading empty stdin), extracts `chainlint.pl`’s shell parser into a shared module (`lib-shell-parser.pl`) to avoid duplication, and documents `test_grep` in `t/README` with clear usage guidelines. The linter itself is wired into the build system via `test-greplint` and `check-greplint` Makefile targets, and its test fixtures cover edge cases like pipelines, redirects, and subshells.

**Why this matters**: The conversion touches ~340 test files and ~2800 `grep` assertions, making it one of the largest test-suite cleanups in recent years. The maintainer’s approval (after initial skepticism about `# lint-ok` exemptions) signals confidence in the approach. The series improves test reliability without false positives, and the shared parser infrastructure enables future lint rules. Expect this to graduate to `next` shortly.

**For the busy reader**: This is a **well-motivated, thoroughly reviewed** series that addresses a real pain point (silent test failures) while avoiding pitfalls of automated conversion. The final version is cleaner and more robust than earlier iterations, and the changes are now ready for merging. If you care about test infrastructure or Git’s reliability, this is worth a skim.
