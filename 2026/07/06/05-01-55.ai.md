This is the **third patch in a 6-patch series** introducing `greplint.pl`, a test-suite linter that converts bare `grep` assertions to `test_grep`. This specific patch **refactors `chainlint.pl`’s shell parser into a shared module** (`lib-shell-parser.pl`) so that `greplint.pl` can reuse the same tokenizer and parsing logic.

The patch is purely mechanical: it moves the `Lexer`, `ShellParser`, and `ScriptParser` classes from `chainlint.pl` into the new `lib-shell-parser.pl` file, then loads the shared module via `do()` in `chainlint.pl`. The only functional change is making `ScriptParser::check_test()` a no-op in the shared module; `chainlint.pl` now defines `ChainlintParser` (a subclass of `ScriptParser`) to implement its specific `&&`-chain checking logic. All existing behavior is preserved: `chainlint.pl` produces identical output, and its self-tests pass.

**Key technical details**:
- **Files touched**: `t/chainlint.pl` (shrinks by ~500 lines), `t/lib-shell-parser.pl` (new, ~500 lines).
- **New symbols**: `lib-shell-parser.pl` (shared module), `ScriptParser::check_test()` (no-op stub).
- **Inheritance changes**: `TestParser` and `ChainlintParser` now explicitly use `@ISA` instead of `use base` to avoid circular dependencies.
- **Motivation**: Enables `greplint.pl` (introduced in a later patch) to reuse the shell parser, avoiding code duplication and ensuring consistent tokenization of test scripts.

**Context in the series**: This patch is a prerequisite for `greplint.pl`, which needs the same shell parsing infrastructure to correctly identify command boundaries and distinguish assertion `grep` from filter `grep` (e.g., `grep | wc -l`). The shared parser also paves the way for future lint tools.

**Quality notes**: The refactoring is clean and well-contained, with no functional changes to `chainlint.pl`. The commit message clearly explains the purpose and scope. This patch is **ready for integration** and has no open technical concerns.
