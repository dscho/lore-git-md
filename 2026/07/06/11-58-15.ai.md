This is a **contributor housekeeping** patch in the `contrib/subtree` area. It adds a safety check to the legacy shell-script implementation of `git subtree` (`git-subtree.sh`) to detect when a repository has already been processed by the new Rust rewrite (`git-subtree` crate). If the Rust tool's configuration file (`.git-subtree/config`) is found, the script bails out with a fatal error and directs users to the new tool.

The patch touches only `contrib/subtree/git-subtree.sh`, adding a new helper function `reject_if_v2_config` and calling it in the `cmd_add`, `cmd_split`, and `cmd_merge` entry points. The check uses `git rev-parse --verify` to probe for the config file in the specified revision. The commit message explains that this is forward-compatible but not backward-compatible: once a project adopts the Rust tool, the shell script will refuse to run, preventing mixed-tool corruption.

The motivation is clear: the Rust rewrite is a complete reimplementation that uses a different on-disk format, so running the old script on a repository that has been processed by the new tool could produce broken output. The patch is part of a two-patch series (this is 1/2); the cover letter or second patch is not provided here, but the stated goal is to prevent silent data corruption during the transition period.

The change is minimal and targeted, with no behavior change for repositories that have not yet used the Rust tool. The commit message is explicit about the incompatibility and provides links to the new tool's home page and crate. No tests are included, but the logic is straightforward and self-contained. The patch looks well-crafted and addresses a real coordination problem during the tool's migration.
