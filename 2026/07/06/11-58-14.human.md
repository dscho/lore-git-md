This is a **contributor housekeeping** patch for `git-subtree`, part of a two-patch series. Ian Jackson is preparing a Rust rewrite of `git-subtree` (currently a shell script in `contrib/`) and wants to prevent the old and new versions from creating incompatible data. The patch adds a safety check: if the old shell-script version detects a config file that signals the presence of the new Rust implementation, it bails out with an error message rather than proceeding and potentially corrupting the repository.

The motivation is clear: the new Rust version will use a different commit format and a downstream-tree config file, making bidirectional compatibility impractical. By shipping this guardrail now, distros can backport it to protect users who might otherwise mix old and new versions. The patch itself is small (18 lines in the script, 18 in the test) and self-contained. It does not change any existing behavior yet, since the Rust rewrite is not yet usable, but it lays the groundwork for a clean transition.

The commit message is unusually detailed for a housekeeping patch, explaining both the technical rationale and the social plan (backports). This suggests the author anticipates pushback or at least questions about why the change is needed before the Rust version is ready. The error message wording is also carefully chosen to be future-proof.

If you maintain a distro or care about `git-subtree` workflows, this patch is worth reviewing now to understand the compatibility boundary being drawn. For everyone else, it is a heads-up that `git-subtree` is getting a major internal overhaul.
