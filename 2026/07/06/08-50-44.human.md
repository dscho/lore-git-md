This is the seventh and likely final iteration of Harald Nordgren’s `git history squash` feature, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now functionally complete, with all prior feedback addressed, and is ready for Junio’s final review.

The headline change in v7 is the adoption of `git rebase -i`’s squash-message template format for `--reedit-message`. The editor now shows the same banner ("This is a combination of N commits") and header structure ("This is the 1st commit message") that `git rebase -i` uses, with `fixup!` messages fully commented out under a "will be skipped" header and `squash!`/`amend!` messages retaining their bodies (only the marker subject is commented). This alignment resolves the last major usability concern from the thread, where Phillip Wood and others argued that `git history` should experiment with cleaner templates rather than blindly copying `git rebase -i`’s cluttered output. The implementation reuses the sequencer’s `add_squash_combination_header()`, `add_squash_message_header()`, and `squash_subject_comment_len()` helpers, ensuring consistency with the existing rebase code.

Other key improvements in v7 include stricter input validation (rejecting ranges whose oldest commit is a `fixup!`, `squash!`, or `amend!`, since their targets cannot be inside the range), CLI style fixes (dashed options now precede `<revision-range>` in the usage, and `@` shorthand is replaced with `HEAD` in documentation), and clearer documentation of the merge limitation (the command still folds interior merges but rejects ranges where the replayed commits include merges). The test suite has grown to 632 lines, covering the new template format, `fixup!`/`squash!`/`amend!` handling, and the stricter input validation.

The implementation remains a single three-way merge of the range against the oldest commit’s parent, followed by replaying descendants. The ref-handling logic (rejecting operations with interior refs by default, with `--update-refs=head` to retarget only the current branch) and range resolution (the base is the oldest in-range commit’s parent, with any other boundary commit treated as evidence of multiple bases) are unchanged from v6. The series touches `builtin/history.c` (390 insertions), `sequencer.c`/`sequencer.h` (for the template helpers), `advice.c`/`advice.h`, and adds a new test script `t/t3455-history-squash.sh`.

This iteration looks polished and addresses all remaining technical and usability concerns. The only open question is whether `--reedit-message` should be the default (Phillip Wood advocates for this as a commit hygiene measure), but that’s a minor UX tweak that could be handled in a follow-up if needed. The series is now ready for Junio’s final assessment.
