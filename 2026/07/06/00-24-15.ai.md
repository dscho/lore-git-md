This is a **substantive review** from Jeff King (Peff) on Trevor Gross’s `git rebase -i -x` patch series, challenging the design premise and proposing an alternative approach.

Peff argues that the feature’s conceptual foundation is misaligned: `git rebase` is fundamentally about *moving* history (rewriting commits to a new base and discarding the old ones), while `git cherry-pick` is about *duplicating* history (preserving the original commits). The `-x` flag’s purpose—recording the origin of a commit—makes little sense in a rebase workflow where the original commits are discarded, undermining the annotation’s utility. He suggests the problem might be better solved by improving `git cherry-pick` itself, particularly by adding an interactive mode (`cherry-pick -i`) that would allow users to edit the sequencer’s todo list mid-operation, mirroring `rebase -i`.

The review includes a concrete experiment demonstrating that `git cherry-pick` already uses the sequencer backend and generates a todo file (`.git/sequencer/todo`), implying that an interactive mode could be implemented with minimal additional work. Peff also notes a behavioral inconsistency: `cherry-pick -x` applies globally to all picked commits via a sequencer option (`record-origin = true`), whereas Trevor’s patch allows per-command `-x` flags in the rebase todo list. He suggests harmonizing this by having `cherry-pick -x` automatically add `-x` to each todo line, rather than relying on a global option.

Peff’s feedback is high-weight and technical, focusing on the *why* behind the feature rather than its implementation. The proposal to extend `cherry-pick` instead of `rebase` could obviate the need for Trevor’s patch entirely, but it would require significant design discussion and likely a separate patch series. The thread’s trajectory now hinges on whether Trevor (or others) can justify the rebase-centric approach or pivot toward Peff’s alternative.
