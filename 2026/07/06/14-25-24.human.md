This is the third patch in Tian Yuchen’s nine-patch refactoring series that continues the libification effort by moving more global configuration variables into `struct repo_config_values`. Specifically, this patch migrates the `editor_program` global variable into the repository-scoped configuration structure.

The commit message explains the rationale: while per-repository editor configuration might seem unnecessary for a single process, it respects developer workflows where different toolchains are used for different projects, and it eliminates mutable global state—a key goal of the libification effort. The patch itself is mechanical: it moves the `editor_program` field into `struct repo_config_values`, updates the config parser to store values there, and modifies the `git_editor()` function to read from the repository structure instead of the global variable. Memory management is handled via the existing `repo_config_values_clear()` function.

The patch is clean and well-explained, with no user-visible behavior changes. It follows the established pattern from the recently merged `excludes_file` migration, reinforcing the consistency of the approach. The only notable detail is that no standalone getter function is introduced; callers access the field directly via `repo_config_values(the_repository)`. This aligns with the series’ goal of centralizing configuration management without adding unnecessary abstraction layers.

This patch is part of a larger, well-motivated effort and looks ready for review. The author’s RFC questions about migrating program paths (raised in the cover letter) don’t block this specific change, but they’re worth keeping in mind for future iterations. For now, this is a straightforward and necessary step in the libification process.
