This is the third patch in Patrick Steinhardt’s 13-patch refactoring series to separate repository discovery from setup. The patch consolidates shallow-file configuration by having the `--shallow-file` command-line option set the `GIT_SHALLOW_FILE` environment variable instead of directly calling `set_alternate_shallow_file()`. The environment variable is then processed in `apply_repository_format()`, aligning shallow-file handling with other global options like object directories.

Justin Tobler’s review is substantive but brief. He accepts the change (“Ok”) and notes the consistency argument, but raises two questions: whether the new logic changes the order of precedence between `--shallow-file` and `GIT_SHALLOW_FILE` (does the option now overwrite the environment variable?), and whether the use of environment variables for global state is the right design. He suggests an alternative—storing configuration in an intermediate structure—but concedes it may not be worth the complexity. The review does not identify any bugs or regressions, only design-level concerns.

The patch itself is small (6 lines changed across `git.c` and `setup.c`) and clearly motivated. It is part of a larger effort to ensure `the_repository` contains no relevant state before `apply_repository_format()` is called, which will enable future cleanup. No behavior changes are intended, and the change looks uncontroversial. If Patrick clarifies the precedence question in a reply, this patch is likely to proceed without further discussion.
