This is a **test infrastructure bugfix** that corrects a latent line-counting error in Git's shared shell parser (`lib-shell-parser.pl`). The patch is the fourth in the six-part `greplint.pl` series, which is now approved for merging and ready for integration.

The bug affects how the lexer tracks line numbers inside double-quoted strings that contain multi-line command substitutions (e.g., `"$(echo foo\nbar)"`). Previously, newlines in the command substitution were counted twice: once during the recursive parse of the `$()` body, and again by the catch-all counter at the end of `scan_dqstring`. This could cause incorrect line numbers for subsequent tokens, though no existing consumers (like `chainlint.pl`) were affected because they use byte offsets rather than line numbers.

Michael Montalbo fixes the issue by moving newline counting into the main loop, where non-special characters are consumed. Each newline is now counted exactly once—whether it appears literally, as a line splice (via backslash), or inside a command substitution. The patch is minimal (6 insertions, 3 deletions) and self-contained, touching only the shared parser module.

This is a **low-risk, high-correctness** change. The bug was latent, so there’s no regression risk, and the fix aligns the lexer’s behavior with its design intent. The patch is part of the broader `greplint.pl` effort, which has already demonstrated value by uncovering pre-existing test suite bugs during its development. The series’ approval status (Junio C Hamano has signed off on v4) suggests this patch will graduate to `next` alongside the rest of the series.

For readers tracking the `greplint.pl` series, this patch is a minor but necessary housekeeping detail—it ensures the linter’s line-number reporting remains accurate in edge cases. The broader series’ goal (replacing bare `grep` with `test_grep` for better debuggability) remains unchanged, and this fix doesn’t alter that functionality. If you’re not following the series closely, this patch is skippable unless you’re debugging the shell parser itself.
