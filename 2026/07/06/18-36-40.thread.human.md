This thread is about enabling universal macOS builds in Git's Makefile when Rust code is present. The author has sent a fourth version of a patch series to support this, and this specific email covers the second patch in that series. The change adjusts the Makefile to use `lipo` to combine Rust static libraries (`libgitcore.a`) for both `x86_64` and `aarch64` architectures into a single universal binary when `RUST_TARGETS` includes both targets. The patch introduces the `RUST_LIB_UNIVERSAL` variable, which is conditionally set and used in the final link step, replacing the per-architecture `RUST_LIB` when building a universal binary.

The author has addressed the feedback from earlier versions, which was surface-level (e.g., fixing a typo and improving variable naming). The reasoning for preserving Cargo's directory structure (`target/$ARCH/$BUILD_CONFIG/`) is clear and well-justified, as flattening it would break Cargo's dependency caching. This patch is part of the broader Rustification effort and is specific to macOS, touching only the Makefile without affecting runtime behavior. The patch appears ready for integration, with no substantive objections or open questions remaining in the thread.
