This is **patch 5/13** in Patrick Steinhardt’s refactoring series to cleanly separate repository discovery from setup. Justin Tobler’s review is **substantive but brief**, focusing on the design intent of the new `struct repo_discovery` rather than code-level details.

The patch introduces `struct repo_discovery` as an intermediate container for gitdir and worktree paths discovered during repository setup. Instead of partially configuring the repository object as paths are found, the code now collects all discovery results in this structure and applies them in a single step. This two-phase approach (discovery → configuration) is meant to eliminate scattered setup logic and pave the way for consolidating repository initialization into `repo_init()`.

Justin’s review raises two forward-looking questions. First, he asks whether the design assumes all repository configuration happens *before* the discovery results are applied — implying that applying configuration more than once would be a bug. Second, he seeks confirmation that the structure is purely an intermediate holder, not a long-lived object. Neither question challenges the patch itself, but both probe whether the new API is future-proof for edge cases like environment variable overrides or worktree reconfiguration.

The commit message is clear, and the code changes are mechanical but thorough. No test failures or regressions are reported, and the series’ overall goal (decoupling discovery from setup) is well-motivated.
