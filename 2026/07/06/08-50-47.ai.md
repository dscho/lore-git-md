This is the core implementation patch (3/5) of Harald Nordgren’s `git history squash` feature, now in its seventh iteration. The patch adds the new subcommand to fold a commit range into its oldest commit while preserving descendant history. It is the centerpiece of the series and has absorbed all prior feedback, including strict input validation, merge commit handling, ref safety checks, and `--reedit-message` template alignment with `git rebase -i`.

The implementation resolves the revision range using `git rev-list` machinery, rejecting single-commit ranges, empty ranges, ranges whose oldest commit is a `fixup!`/`squash!`/`amend!`, and ranges with multiple bases (e.g., a side branch that forked before the range). It allows interior merges as long as all parents are reachable from the base, but rejects merges whose other parent lies outside the range. By default the command refuses if any ref points to a commit inside the squashed range, with an advice message suggesting `--update-refs=head` to rewrite only the current branch.

The patch touches `builtin/history.c` (245 insertions), adding the `resolve_squash_range()` helper that parses and validates the range, `reject_fixupish_oldest()` to block ranges starting with a marker, and `find_interior_ref()` to detect dangling refs. The main `cmd_history_squash()` function performs a single three-way merge of the entire range against the oldest commit’s parent, then replays descendants on top. The test script `t/t3455-history-squash.sh` (517 lines) exercises range parsing, merge handling, ref safety, authorship preservation, and `--update-refs` behavior.

Key names introduced: the `ADVICE_HISTORY_UPDATE_REFS` advice key, the `squash` subcommand, the `--update-refs=head` option, and the internal helpers `resolve_squash_range`, `reject_fixupish_oldest`, and `find_interior_ref`. The patch is ready for Junio’s final review; no further design changes are expected.
