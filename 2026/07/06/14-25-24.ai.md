This is the third patch in Tian Yuchen’s nine-patch refactoring series that continues the libification effort by migrating global configuration variables into `struct repo_config_values`. Specifically, this patch moves the `editor_program` global variable into the repository-scoped configuration structure.

The change is mechanical: the global `char *editor_program` is removed, and the field is added to `struct repo_config_values`. The `core.editor` config handler now stores the value in the repository’s `repo_config_values` instance instead of the global variable. Callers in `editor.c` are updated to access the value via `repo_config_values(the_repository)->editor_program`. Memory management is handled by the existing `repo_config_values_clear()` function, which now also frees the editor program string.

The commit message acknowledges the RFC question raised in the cover letter—whether migrating program paths like the editor is worthwhile given that they are rarely overridden per-repository. The author argues that per-repo configuration is still useful for developers using different toolchains across projects, and that eliminating mutable global state is necessary for long-running processes managing multiple repositories.

No new getter function is introduced; callers access the field directly through `repo_config_values()`. The patch touches `editor.c`, `environment.c`, and `environment.h`, and is part of the broader `the_repository` removal effort. It introduces no user-visible behavior changes and is CI-clean. The only unresolved aspect is the RFC question about the value of migrating program paths, which remains open for reviewer feedback.
