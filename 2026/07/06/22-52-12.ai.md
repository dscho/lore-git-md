This is the second patch in the v6 series refining Git's Rust build system integration for macOS, focusing on **Universal Binary support** for Rust components. It introduces the `RUST_TARGETS` environment variable, allowing users to specify multiple target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`) to produce a single Universal static library (`libgitcore.a`) via `lipo`. This aligns Rust's build process with macOS's standard distribution practices, where a single binary artifact supports both Intel and Apple Silicon architectures natively.

The patch modifies the `Makefile` to compile separate static libraries for each target triple (using Cargo's `--target` flag) and then combines them into a Universal Binary. The implementation assumes `lipo` is available (part of Xcode Command Line Tools), a reasonable assumption for Git's macOS build environment. The build system now uses `RUST_BUILD_CONFIG` (either `debug` or `release`) to unify the target directory structure, placing the final Universal library in `target/release/` or `target/debug/`, while per-architecture artifacts land in `target/<triple>/<config>/`.

Key technical details include the new `RUST_MEMBER_LIBS` build variable (tracking per-target libraries) and the use of `mkdir_p_parent_template` to ensure the output directory exists before invoking `lipo`. The patch maintains backward compatibility: if `RUST_TARGETS` is unset, the build falls back to the default single-target behavior. If only one target is specified, the build skips `lipo` and copies the single-architecture library directly. The patch also includes a safety check to error out if `RUST_TARGETS` is used on non-macOS platforms where `lipo` is unavailable.

This patch is **functionally complete** and addresses a practical need for macOS distribution and CI packaging. The unresolved artifact layout question (raised by Patrick Steinhardt) about whether to unify the `target/` directory structure under `target/$BUILD_CONFIG/` remains open, but it is not a blocker for integration. The current design is consistent with Cargo's conventions and meets the immediate goal of Universal Binary support. No new tests are introduced, but the change is implicitly covered by existing build tests and the CI verification added in the third patch of the series.
