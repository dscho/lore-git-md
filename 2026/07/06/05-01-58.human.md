This is the final patch in a **now-approved 6-part test infrastructure series** that introduces `greplint.pl`, a linter to enforce the use of `test_grep` over bare `grep` in Git’s test suite. The series is ready for merging, with this patch adding the linter itself and wiring it into the build system.

The linter’s job is to catch two anti-patterns: bare `grep` used as a test assertion (where `test_grep` should be used for better debuggability), and `! test_grep` (where `test_grep !` is preferred). It reuses the shared shell parser from `lib-shell-parser.pl` (introduced earlier in the series) to tokenize test bodies, avoiding false positives on `grep` inside heredocs, command substitutions, or quoted strings. The linter’s logic distinguishes assertion `grep` from filter `grep` (e.g., `grep | wc -l` or `x=$(grep ...)`) by tracking command position and pipeline state, and it skips greps annotated with `# lint-ok` (now reserved for data filters, not missing-file cases).

Key components added here:
- **`greplint.pl`**: The linter, with test fixtures under `t/greplint/` covering detection of bare `grep` in various contexts (after `&&`, `;`, in subshells, etc.), correct skipping of filters, and handling of `lint-ok` annotations.
- **`greplint-cat.pl`**: A helper script to assemble expected output for the `check-greplint` target.
- **Makefile integration**: Three new targets:
  - `test-greplint`: Runs the linter on all test scripts (`$(T)`, `$(THELPERS)`, `$(TPERF)`).
  - `check-greplint`: Validates the linter against its fixtures.
  - `clean-greplint`: Removes temporary files.
- **`.gitattributes`**: Ensures `greplint` fixtures use LF line endings for cross-platform compatibility.

The linter’s design is conservative: it flags only unambiguous assertion `grep` calls (those at command position without pipes/redirects), leaving edge cases like `grep pattern file >/dev/null` for future work. The fixtures demonstrate thorough coverage of both positive and negative cases, including line-number adjustments for double-quoted test bodies with backslash-continuation lines.

This patch completes the series, which has already addressed the maintainer’s concerns about `# lint-ok` annotations and edge-case handling. The linter is now poised to prevent regression of the ~2800 `grep` assertions converted earlier in the series, while its shared parser infrastructure enables future lint rules.
