Patrick Steinhardt clarifies the behavior of the `--no-deref` option and the atomic "must not exist" semantics, but the exchange leaves lingering usability questions about the interface.

Patrick confirms that `--no-deref` does *not* create symbolic references (symrefs); instead, it controls whether the command fails when the target reference already exists as a symref. For example, if `refs/heads/symref` is a symref pointing to `refs/heads/target`, `git refs create refs/heads/symref $OID` would create `refs/heads/target` (dereferencing the symref), while `--no-deref` would make the command fail. This behavior mirrors `git update-ref` and is consistent across all `git refs` subcommands, but Patrick acknowledges the default may not be intuitive and suggests it could be revisited globally if changed.

The discussion also clarifies that `git refs create` intentionally rejects attempts to create a reference that already exists, even with the same value. This enforces atomic "must not exist" semantics, which Patrick defends as the correct behavior for an explicit creation command. However, Toon’s proposed test for symref creation with `--no-deref` (which would fail under the current implementation) highlights the option’s obscurity: users must understand that `--no-deref` prevents dereferencing an existing symref, not that it enables symref creation. The lack of a dedicated `--symref` flag or clearer documentation leaves the interface feeling unintuitive, though Patrick does not propose changes here.
