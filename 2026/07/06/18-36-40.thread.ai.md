Core problem or goal
Add Makefile support for building universal macOS binaries when Rust code is present. The goal is to allow Git to be built as a single binary containing both x86_64 and aarch64 code when `RUST_TARGETS` includes both architectures, by using `lipo` to combine the per-architecture Rust static libraries (`libgitcore.a`) into a universal binary.

Current status
Under review. This is the second patch in the v4 series; the author has addressed prior feedback (typo fixes and variable naming) and the patch is now focused on the mechanical Makefile changes. No maintainer decision or merge status has been recorded.

Key technical details
- Files touched: `Makefile` only.
- New Makefile variable: `RUST_LIB_UNIVERSAL`, conditionally set when multiple Rust targets are specified.
- Build process: When `RUST_TARGETS` includes both `x86_64-apple-darwin` and `aarch64-apple-darwin`, the Makefile invokes `lipo` to combine the per-architecture `libgitcore.a` libraries (located in `target/$ARCH/$BUILD_CONFIG/`) into a single universal binary.
- Link step: The final link step for the Git binary now includes `RUST_LIB_UNIVERSAL` instead of per-architecture `RUST_LIB` when building a universal binary.
- Cargo constraints: The directory layout (`target/$ARCH/$BUILD_CONFIG/`) is dictated by Cargo's internal conventions and cannot be flattened without breaking Cargo's dependency caching.
- No runtime behavior changes; this is a build-system-only change.
