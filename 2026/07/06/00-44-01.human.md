This is a brief follow-up in Jeff King’s memory-leak bugfix series, specifically about the idempotency discussion for `git_hash_discard()`. Jeff clarifies a technical oversight in his earlier proposal: while adding an `active` flag to `struct git_hash_ctx` would make `git_hash_discard()` idempotent for callers using the public API (`git_hash_init()`), it would *not* protect callers that bypass the API by invoking backend functions directly (`algo->init_fn()`). These direct calls—found in `submodule--helper.c` and `test-synthesize.c`—would leave the `active` flag unset, risking leaks or double-free bugs if `git_hash_discard()` is later called.

The fix is straightforward: convert the direct callers to use `git_hash_init()` instead, which would centralize flag management. Jeff notes this is a matter of inertia rather than design, as there’s no reason to avoid the public API. This adjustment would unblock the idempotency design but doesn’t change the series’ current approach (which remains correct without idempotency). The observation reinforces the tradeoff: idempotency simplifies error paths but requires fixing legacy callers to avoid desynchronization. No objections or alternatives are raised; the focus remains on implementation pragmatics.
