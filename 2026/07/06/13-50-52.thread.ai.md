Subject: sparse-index: fix segfault on collapse with intent-to-add outside cone
Series version: standalone patch (no series)
Originating author: Derrick Stolee
Thread type: bug report and fix

Core problem or goal
A segfault occurs in the sparse-index subsystem when Git tries to collapse a full index into a sparse index while an intent-to-add (ITA) entry exists outside the sparse-checkout cone. The crash is caused by an out-of-bounds access in `convert_to_sparse_rec()` in `sparse-index.c`, where the loop over cache entries assumes a non-negative `entry_count` but the cache-tree node can be invalidated (indicated by a negative `entry_count`).

Current status
Patch submitted, under review. No prior versions. The fix is minimal: it checks if `entry_count` is negative before attempting to collapse a cache-tree node, skipping the collapse if so. This resolves the immediate crash but leaves some performance optimizations unrealized—specifically, the ability to collapse valid child trees even when an ITA entry is present. Stolee notes this trade-off is acceptable given the bug's obscurity.

Key technical details
- **Subsystems touched**: sparse-index (`sparse-index.c`), cache-tree, intent-to-add.
- **New behavior**: `convert_to_sparse_rec()` now skips cache-tree nodes with negative `entry_count`, preventing the out-of-bounds access.
- **Old behavior**: The loop assumed `entry_count` was non-negative, leading to a segfault when iterating over invalidated nodes.
- **Test coverage**: Two new tests:
  - `t3705-add-sparse-checkout.sh`: Verifies `git add` behavior with sparse-checkout and ITA entries.
  - `t1092-sparse-checkout-compatibility.sh`: Demonstrates the interaction with the sparse index and compares it to full-index behavior, highlighting the trade-off (some sparse directories that *could* be collapsed are left expanded due to the ITA entry).
- **Symbols**: `convert_to_sparse_rec()`, `entry_count` (cache-tree node field), `git add -N` (intent-to-add), `git sparse-checkout set`.

Open questions and loose ends
None yet raised. The patch is self-contained and addresses the immediate issue, but Stolee acknowledges that a more involved fix could recover the performance optimization of collapsing valid child trees even when an ITA entry is present. No follow-up work is promised or requested at this stage.
