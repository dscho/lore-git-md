This is the second patch in a v4 series that adds Makefile support for universal macOS builds when Rust code is present. The patch adjusts the build rules so that when `RUST_TARGETS` is set to include both `x86_64-apple-darwin` and `aarch64-apple-darwin`, the Makefile invokes `lipo` to combine the per-architecture Rust static libraries (`libgitcore.a`) into a single universal binary. The patch also ensures the final link step includes this universal library.

The key technical detail is the Makefile variable `RUST_LIB_UNIVERSAL`, which is conditionally set only when multiple Rust targets are specified. The patch adds this variable to the link step for the Git binary, replacing the per-architecture `RUST_LIB` when building a universal binary. The author has incorporated feedback from the thread: they now use `$(GITLIBS)` instead of directly referencing `$(LIB_FILE)` or `$(RUST_LIB)`, and they corrected a typo ("rust" -> "Rust"). The author explains that the directory layout (`target/$ARCH/$BUILD_CONFIG/`) is dictated by Cargo's internal conventions and cannot be flattened without breaking Cargo's dependency caching.

This patch is part of the ongoing Rustification effort and is platform-specific, targeting macOS universal binaries. The change is mechanical and well-motivated, with clear reasoning about why the directory structure must remain as-is. The patch touches only the Makefile and does not affect any runtime behavior. The thread context shows that the feedback was surface-level (typo fixes and variable naming), and the author addressed it promptly. The patch appears ready for integration.
