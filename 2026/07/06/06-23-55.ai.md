This is the v3 revision of a nine-patch series targeting Git’s test suite and CI infrastructure, specifically the `GIT_TEST_LONG` environment variable used to gate expensive or long-running tests. The series is now complete and uncontroversial, addressing all feedback from v1 and v2. The only changes in v3 are corrected commit subjects for patches 2 and 5, which now accurately describe the `SIZE_T_IS_64BIT` prerequisite (the tests are skipped *with* the prerequisite, not without it).

The series originated as a small effort to expose GitLab CI status in the README and enable `GIT_TEST_LONG` there, but expanded after Patrick Steinhardt discovered that several `GIT_TEST_LONG` tests were broken or hanging in both GitHub CI and GitLab CI. The patches fall into three categories: CI visibility and configuration (patches 1, 8, 9), test correctness fixes (patches 2, 5, 7), and test efficiency improvements (patches 3, 4, 6). Key changes include skipping tests that are broken on 64-bit platforms due to `size_t` limitations, replacing inefficient `dd` loops with faster alternatives, reducing disk usage in large tests, and enabling `GIT_TEST_LONG` in GitLab CI for integration branches. The series touches test scripts (`t0021`, `t4141`, `t5608`, `t7508`, `t7900`), CI configuration (`.gitlab-ci.yml`, `ci/lib.sh`), `README.md`, and `t/test-lib.sh`.

The technical approach is pragmatic and well-motivated. For example, patch 3 replaces a slow `dd` pipeline in `t4141` with direct `genzeros` generation, reducing runtime from 6 minutes to under a second, while patch 4 cuts peak disk usage in `t5608` by deleting repositories immediately after use. Patch 9 enables `GIT_TEST_LONG` for GitLab CI pushes to integration branches (`next`, `master`, `main`, `maint`), matching GitHub Actions behavior, but excludes Windows runners due to hardware limitations (7.5 GB RAM is insufficient for some `EXPENSIVE` tests). The `test_bool_env` helper introduced in patch 7 standardizes boolean parsing for `GIT_TEST_LONG`, ensuring it can be explicitly disabled. No new user-facing features or on-disk format changes are introduced.

Feedback from v1 and v2 has been fully addressed. SZEDER Gábor’s objection to removing the `EXPENSIVE` prerequisite in `t4141` was resolved by restoring it in v2, acknowledging that memory usage (>1 GiB) still justifies the label despite the runtime improvement. Jeff King (Peff) endorsed the efficiency improvements in patches 3 and 4, and Junio C Hamano’s nit about the commit message in patch 2 was fixed in v3. The series is now ready for integration, with no open technical or policy questions. The unresolved discussion about how Git defines "expensive" tests (runtime vs. resource usage) remains, but it does not block this series.

The patches are mechanical and focused, with clear commit messages explaining the rationale for each change. The series demonstrates thorough testing and attention to edge cases, such as platform-specific limitations and CI resource constraints. The exclusion of Windows runners in patch 9 is a pragmatic concession to hardware limitations and has not drawn objections. Overall, this is a well-crafted, uncontroversial effort that makes `GIT_TEST_LONG` tests reliable and efficient enough to run in CI without consuming excessive resources or hanging pipelines.
