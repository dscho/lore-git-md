This is the **fifth patch in the v4 series introducing `greplint.pl`**, a test-suite linter that converts bare `grep` assertions to `test_grep`. This patch is the **bulk conversion** of ~340 test scripts, replacing ~2800 `grep` assertions with `test_grep` to improve debuggability (since `test_grep` prints file contents on failure). The conversion is **mechanical but carefully scoped**: only assertion-style `grep` calls (those at command position) are replaced, while `grep` used as a filter in pipelines, command substitutions, or with redirected I/O is left unchanged and annotated with `# lint-ok`.

Key technical details:
- **Files touched**: 338 test scripts (`t/*.sh`, `lib-*.sh`, `*-tests.sh`), with ~2800 `grep` assertions replaced.
- **Edge cases handled**:
  - `! grep` is rewritten to `test_grep !` to preserve diagnostic output on failure.
  - Conditionally present files (e.g., `.git/packed-refs` under `files` backend, NTFS 8.3 short names) are guarded with `test_have_prereq REFFILES` or `test -f` to avoid BUGs when the file is absent.
  - The last remaining `# lint-ok` annotation for a missing-file case (in `t7450-bad-git-dotfiles.sh`) was converted to a guarded `test_grep`.
- **Manual interventions**: Two edge cases (`t1400-update-ref.sh` and `t7450-bad-git-dotfiles.sh`) required hand-editing to add guards; all other conversions were generated via `greplint.pl` and `sed` pipelines.
- **Verification**: The patch includes a `Makefile` target (`test-greplint`) to validate the conversion, ensuring no bare `grep` assertions remain.

The patch is **ready for integration** and addresses all prior feedback, including the maintainer’s concerns about edge-case handling and `# lint-ok` annotations. The conversion is **backward-compatible** and does not alter test behavior, only improving debug output on failure. Expect this to graduate to `next` shortly as part of the approved series.
