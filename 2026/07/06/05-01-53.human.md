This is the first patch in the **v4 series introducing `greplint.pl`**, a linter that converts bare `grep` assertions in Git’s test suite to the `test_grep` helper. This specific patch **documents `test_grep` in `t/README`**, filling a long-standing gap in the test suite’s reference material.

The new documentation explains `test_grep`’s purpose (printing file contents on failure for easier debugging), its syntax (including the `!` negation argument), and when to use it instead of bare `grep`. It also clarifies edge cases: `test_grep` should only be used for assertions, not data filtering (e.g., `grep | wc -l`), and it **requires the file to exist**—a key constraint that drove much of the series’ later work. The patch provides a worked example for guarding `test_grep` with prerequisites (e.g., `test_have_prereq REFFILES`) when file presence is conditional, addressing the maintainer’s prior concerns about `# lint-ok` annotations masking missing-file bugs.

This is a **pure documentation update** with no code changes, but it’s critical to the series’ goal. The guidance here—especially the emphasis on explicit guards for conditionally present files—replaces the problematic `# lint-ok` exemptions that Junio C Hamano objected to in earlier versions. The patch is **well-motivated and uncontroversial**, and it directly supports the linter’s adoption by making `test_grep`’s requirements clear to contributors. Expect this to merge as part of the approved series.
