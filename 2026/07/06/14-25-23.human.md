This is the second patch in Tian Yuchen’s nine-patch refactoring series that moves more global configuration variables into `struct repo_config_values`. It migrates the `excludes_file` global—a dynamically allocated string that holds the path to the global ignore file—into the repository-specific configuration struct.

The patch replaces the global `excludes_file` variable with a new getter, `repo_excludes_file()`, that encapsulates the lazy-loading fallback logic (defaulting to `$XDG_CONFIG_HOME/git/ignore` if the value is unset). Memory management is handled via the recently introduced `repo_config_values_clear()` function, which frees the heap-allocated string during repository teardown. The changes are mechanical: the global is removed, the getter is added, and all callers in `dir.c` and `environment.c` are updated to use the new repository-aware function.

This patch overlaps with work already merged in the prior `excludes_file` series (now in `next`), but the author has re-split it here for clarity and completeness. The motivation is consistent with the broader libification effort: eliminating globals, centralizing memory management, and preparing the codebase for further modularization. No user-visible behavior changes are introduced, and the patch is CI-clean.

The only loose end is the `NEEDSWORK` comment in `repo_config_values_clear()` about submodule support, which remains unresolved but is not a blocker for this series. The patch itself is well-explained and aligns with the established pattern for migrating repository-aware configuration variables. If the rest of the series holds up, this is a straightforward, uncontroversial step in the right direction.
