This is the first patch in a nine-patch refactoring series that continues the libification effort by migrating global configuration variables into `struct repo_config_values`. The patch introduces `repo_config_values_clear()`, a destructor to free heap-allocated strings stored in the repository’s configuration struct. For now, it only handles `attributes_file`, but the function is designed to grow as more variables are migrated.

The commit message is clear and well-motivated, explaining the need for memory cleanup as part of the broader effort to eliminate globals. The code itself is straightforward: a new function in `environment.c` that frees `attributes_file` and a one-line call in `repo_clear()`. The patch also includes a `NEEDSWORK` comment about submodule support, which remains unresolved from the prior `excludes_file` series—this is noted but not a blocker.

This patch overlaps with the recently merged `excludes_file` migration (now in `next`), but the author has re-split it for clarity in this follow-up series. The change is mechanical and aligns with the project’s memory-safety goals. No user-visible behavior changes are introduced, and the patch is CI-clean. The only loose end is the submodule limitation, which the author acknowledges but does not attempt to solve here.

If you’re following the libification effort, this is a foundational piece of infrastructure. The rest of the series will build on it to migrate seven more variables, including editor/pager/askpass programs and several enums. The patch itself is uncontroversial, but the RFC questions in the cover letter (about whether migrating program paths is worthwhile) may spark discussion later in the thread.
