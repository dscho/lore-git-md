This thread is part of Patrick Steinhardt’s nine-patch series addressing issues with `GIT_TEST_LONG` and expensive tests in Git’s test suite. The series aims to fix problems that surfaced after enabling expensive tests in CI in May 2026, particularly on 32-bit platforms where certain tests fail or hang due to limitations like `SSIZE_MAX`.

This specific patch (2/9) targets `t0021-conversion.sh`, which includes a test that writes and roundtrips a 2 GB file through clean/smudge filters. The test is problematic on 32-bit systems because they cannot reliably handle files of this size, leading to `ENOMEM` errors or indefinite hangs. The fix is straightforward: the test is now skipped on 32-bit platforms by adding `SIZE_T_IS_64BIT` to its prerequisites. The commit message clarifies that while CI includes a `linux32` job, the issue only became apparent after expensive tests were enabled, and detecting the failure reliably is challenging.

The series is still under review, and this patch is a targeted fix for a specific edge case rather than a broader design change. No objections or alternative approaches have been raised yet in the thread.
