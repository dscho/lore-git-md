This is the **final patch in a 6-part test infrastructure series** that introduces `greplint.pl`, a linter to enforce the use of `test_grep` over bare `grep` in Git's test suite. The series is now **approved for merging** by the maintainer and addresses all prior feedback, including edge cases and documentation concerns.

This patch adds the linter itself, which reuses the shared shell parser (`lib-shell-parser.pl`) to tokenize test bodies and distinguish assertion-style `grep` (which should use `test_grep`) from filter-style `grep` (e.g., `grep | wc -l`). The linter flags two anti-patterns: bare `grep` at command position and `! test_grep` (where `test_grep !` is preferred). It skips `grep` inside heredocs, command substitutions, or quoted strings, and respects `# lint-ok` annotations for greps used as data filters in compound commands (e.g., `(grep ... && sed ...) >out`).

Key technical details:
- **Detection logic**: The linter tracks command position (e.g., after `&&`, `;`, or `then`) and pipeline state to identify assertion `grep`. It adjusts line numbers for double-quoted test bodies with backslash-continuation lines, ensuring accurate error reporting.
- **Test fixtures**: 20+ fixtures under `t/greplint/` validate detection of bare `grep` in various contexts (subshells, compound bodies, negated forms) and correct skipping of filters (pipes, redirects, command substitutions).
- **Build integration**: Adds `test-greplint` (runs the linter on all test scripts), `check-greplint` (validates fixtures), and `clean-greplint` targets to the Makefile. `.gitattributes` entries ensure consistent line endings for fixtures on Windows.
- **Edge cases**: The linter handles `grep` with flags (`-E`, `-c`, `-f`), negated forms, and explicit patterns, while ignoring `grep` as an argument (e.g., `test_must_fail grep`) or value (e.g., `for cmd in grep sed`).

The patch is **well-tested and low-risk**: it only adds a linter and its infrastructure, with no changes to Git's core functionality. The shared parser refactoring (earlier in the series) ensures no duplication with `chainlint.pl`. The linter's strict scoping (assertion `grep` only) and `# lint-ok` mechanism balance enforcement with flexibility for legitimate filter uses.

**Files introduced**:
- `greplint.pl`: The linter, with detailed comments explaining its logic.
- `greplint-cat.pl`: Helper for the `check-greplint` target.
- `t/greplint/`: Fixtures and expected outputs for linter validation.

This patch completes the series, which is now ready for integration. The linter will help maintain the `test_grep` conversion by preventing regressions, while its shared parser infrastructure enables future lint rules.
