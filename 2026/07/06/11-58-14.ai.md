This is a **contributor housekeeping** patch series for `git-subtree`, part of the `contrib/` directory. The series adds a safeguard to the existing shell-script implementation of `git-subtree` to detect and reject repositories that have been modified by a forthcoming Rust rewrite of the same command.

The author, Ian Jackson, is working on a Rust reimplementation of `git-subtree` that is not yet usable but aims to be significantly faster and produce better output. The new implementation will not be backward-compatible with the current shell version: it will use a config file to store downstream project metadata, and it will assume that any commit showing signs of the new tool’s use is not an unmarked subtree merge from the old version. To prevent users from accidentally mixing the two implementations and creating unparseable history, this patch makes the old `git-subtree` bail out with an error message if it detects the new config file in the repository.

The series consists of two patches: the first adds the detection logic to the shell script, and the second adds a test to verify the behavior. The error message refers to the new tool as if it already exists, which the author justifies by noting that the message will only be seen once the new implementation is in use. The motivation is to ship this safeguard early so that distributions can backport it before the Rust rewrite becomes widely available, protecting users from potential data corruption. The patches are small, focused, and include test coverage.
