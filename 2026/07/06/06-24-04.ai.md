This is the final patch in Patrick Steinhardt’s nine-patch series making `GIT_TEST_LONG` tests reliable and efficient for CI. It enables the `GIT_TEST_LONG` environment variable in GitLab CI for pushes to integration branches (`next`, `master`, `main`, `maint`), matching the behavior already implemented for GitHub Actions in commit 7a094d68a2. The patch explicitly disables `GIT_TEST_LONG` on Windows runners due to their 7.5 GB RAM limit, which is insufficient for some `EXPENSIVE` tests.

The change is mechanical and well-motivated: it plugs a test coverage gap by ensuring GitLab CI runs the same long-running tests as GitHub Actions, while pragmatically excluding Windows runners where hardware constraints make the tests impractical. The patch touches `.gitlab-ci.yml` (adding `GIT_TEST_LONG: false` to Windows jobs) and `ci/lib.sh` (generalizing the event/branch logic to work with GitLab’s pipeline variables and ensuring `GIT_TEST_LONG` can be overridden). No new user-facing features or on-disk format changes are introduced.

This patch is uncontroversial and ready for integration. It completes the series’ goal of making `GIT_TEST_LONG` tests reliable and efficient across both CI platforms without consuming excessive resources. The exclusion of Windows runners is a pragmatic concession that has not drawn objections. The series as a whole is now fully reviewed and addresses all prior feedback.
