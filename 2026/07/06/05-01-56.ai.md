This is a **test infrastructure bugfix** in the shared shell parser (`lib-shell-parser.pl`), part of the `greplint.pl` series. The patch corrects a latent line-counting bug in the lexer that double-counts newlines inside multi-line command substitutions (`$()`) within double-quoted strings. The issue affects any consumer that relies on token line numbers (rather than byte offsets), though the existing `chainlint.pl` tool is unaffected because it uses byte offsets for annotation.

The fix moves newline counting into the main loop of `scan_dqstring`, ensuring each newline is counted exactly once—whether it appears literally, as a line splice (backslash-newline), or inside a `$()` substitution. The post-loop catch-all counter is removed. This change is purely internal to the lexer and does not alter the parser’s output or behavior for existing consumers.

The commit message clearly explains the bug’s origin (recursive parsing of `$()` bodies re-counting newlines) and its scope (latent, as no current tool uses token line numbers). The patch itself is minimal (6 insertions, 3 deletions) and focused, touching only the lexer’s newline accounting logic. No test failures or regressions are expected, as the bug was not triggered by any existing functionality.

This is the fourth patch in the six-patch `greplint.pl` series (v4), which is now approved for merging. The fix addresses a technical debt item surfaced during the series’ development but does not block the series’ core functionality. The shared parser (`lib-shell-parser.pl`) was extracted from `chainlint.pl` earlier in the series to avoid duplication, so this bugfix benefits future linters as well.
