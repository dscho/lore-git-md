This is the fourth iteration of Patrick Steinhardt’s five-patch series adding reference-writing capabilities to the new `git refs` builtin. The series is now fully merged into Junio’s `next` branch, but this reroll (v4) adds a few final polish items before the code ships in the next release.

The core goal remains unchanged: consolidate reference manipulation under a single, discoverable interface. The four new subcommands—`git refs delete`, `git refs update`, `git refs create`, and `git refs rename`—mirror or extend the functionality of `git update-ref` and `git symbolic-ref`. This version adds two small but important improvements: a new test for symref deletion with `--no-deref` (patch 2/5) and an explicit test confirming that `git refs rename` fails when given a symbolic reference (patch 5/5). The latter documents a known backend limitation that was previously undocumented; users who try to rename a symref will now get a clear error message instead of silent failure or undefined behavior.

The changes from v3 are minimal and purely test-related: a subshell for consistency in one test, and the two new symref tests. No code logic or user-facing behavior has changed since v3, which was already approved by Junio. The series looks ready for release; the only remaining loose ends are usability questions about `--no-deref` and symref handling that were raised in review but not addressed in code. These are now documented in the test suite rather than left as undocumented edge cases.
