This is a **contributor housekeeping** patch for `contrib/subtree`, part of a two-patch series. The author, Ian Jackson, adds a safety check to the legacy shell-script implementation of `git subtree` (in `contrib/subtree/git-subtree.sh`). If the repository contains a `.git-subtree/config` file — a marker introduced by a new, standalone Rust rewrite of `git subtree` — the script now bails out with a clear error message directing users to the new tool.

The motivation is forward compatibility: the Rust rewrite can read data produced by the old script, but the old script cannot handle data produced by the new tool. This patch prevents users from accidentally mixing the two and generating broken output. The commit message explicitly states that this change is not backward compatible — once a project adopts the Rust version, it cannot safely return to the shell version.

The patch is small and focused, touching only the shell script. It adds a helper function `reject_if_v2_config` that checks for the config file in a given revision, and calls this helper in the `add`, `split`, and `merge` subcommands. The error message includes links to the new tool’s homepage and crates.io page.

This is not a core Git feature or a user-facing change in the usual sense; it is a defensive measure to smooth the transition for users who might otherwise stumble into an interoperability trap. The patch looks well-crafted and addresses a real problem in a minimal way.
