This is the second patch in Tian Yuchen’s nine-patch refactoring series that continues the libification effort by migrating global configuration variables into `struct repo_config_values`. Specifically, this patch moves the `excludes_file` global variable (which tracks the path to the global ignore file) into `struct repo_config_values` and introduces a proper getter, `repo_excludes_file()`, to encapsulate the lazy-loading fallback logic.

The patch is mechanical but well-executed: it removes the global `excludes_file` variable, adds it to `struct repo_config_values`, updates `git_default_core_config()` to store the value in the repository-specific struct, and introduces the getter to handle the XDG default path fallback. Memory management is handled via the existing `repo_config_values_clear()` function, which now also frees `excludes_file` during repository teardown. The change touches `dir.c`, `environment.c`, and `environment.h`, with no user-visible behavior changes.

This patch overlaps with the recently merged `excludes_file` migration (from the prior series) but is re-split here for clarity. The commit message is clear and references the broader libification goal, though it doesn’t explicitly address the RFC questions raised in the cover letter (about migrating program paths or `git_branch_track`). The patch is CI-clean and aligns with the project’s memory-safety goals, but the submodule limitation noted in the cover letter (where `repo_config_values_clear()` silently returns for submodules) remains unresolved.

Key symbols for follow-up: `repo_excludes_file()`, `repo_config_values_clear()`, and the `excludes_file` field in `struct repo_config_values`.
