This thread is about a small but important safeguard for `git-subtree` (in `contrib/`). Ian Jackson proposed a patch series to add a runtime check that prevents mixing the existing shell-script implementation with a forthcoming Rust rewrite. The Rust version will use a config key (`subtree.rust-rewrite`) to store metadata and won’t be backward-compatible, so the safeguard detects and rejects repositories that have been modified by it.

The series is now in its final stages. Junio Hamano, the maintainer, reviewed the patches and confirmed the design is sound—it checks only the top-level repository config, not subtree-internal metadata, aligning with the Rust rewrite’s approach. All substantive feedback has been addressed, including a scoping fix for the detection logic and adjustments to the test style. The only remaining task is for Ian to post a v2 incorporating the agreed-upon test improvements, after which the series is likely to be merged. The thread is conceptually complete, with no open questions about the safeguard’s purpose or the Rust rewrite’s limitations (such as its lack of support for manual `-X subtree` merges). Colin Stagner, Phillip Wood, and D. Ben Knoble contributed surface-level reviews, and Junio’s latest email nudges the series toward completion.
