This thread is about a small but important safeguard for `git-subtree` in `contrib/`. Ian Jackson sent a two-patch series that adds a check to the existing shell-script version of `git-subtree`: if a repository has been touched by the upcoming Rust rewrite (which will store metadata in a config key `subtree.rust-rewrite`), the shell script will refuse to run, preventing unparseable history.

The series is now ready for the next step. Junio C Hamano reviewed the first version, caught a scoping bug in the detection helper function (it must use `$1` instead of the global `rev`), and later confirmed that the current error message—though long—is fine, since the script is on its way out. Ian acknowledged both points and will post a v2 that fixes only the scoping bug. Once that lands, the series should be accepted. No other objections or open questions remain.
