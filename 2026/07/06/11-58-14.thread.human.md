This thread is about a small but important safeguard for `git-subtree` (in `contrib/`), ensuring users don’t accidentally mix the existing shell-script implementation with a forthcoming Rust rewrite. The Rust version will store metadata in a config key (`subtree.rust-rewrite`) and won’t be backward-compatible, so the patch adds a check to block the old implementation if that key is present. The author, Ian Jackson, posted v1 after addressing all review feedback, including a scoping fix from Junio and test style suggestions from Colin Stagner and Phillip Wood.

The key design choice is to check only the top-level repository config, not the subtree directory, because the decision to adopt the Rust rewrite belongs to the downstream project (the one incorporating the subtree). The Rust rewrite won’t support manual `-X subtree` merges, and while it won’t actively prevent them, mixing them with the new implementation could create unpredictable history. Jackson clarified in this latest email that the Rust rewrite won’t discourage manual merges outright but will document the risks and may later offer a transition path for users migrating from manual workflows. The safeguard itself remains narrowly focused on preventing mixed implementations, not policing merge strategies.

Ben Knoble—raised only surface-level points, all addressed or declined with justification. The thread is now conceptually complete, and unless new concerns arise, the next step is for Jackson to post the final version.
