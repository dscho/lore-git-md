This thread is about a small but important safeguard for `git-subtree` (in `contrib/`), ensuring that repositories modified by a forthcoming Rust rewrite of the command won’t be accidentally mixed with the current shell-script version. The Rust rewrite will store its metadata in a top-level config key (`subtree.rust-rewrite`), and the safeguard checks for that key to block operations that could create unparseable history. The design is now settled: the check is scoped to the top-level repository config, reflecting the social relationship between upstream and downstream projects, and the Rust rewrite will document—but not enforce—limitations around manual `-X subtree` merges.
