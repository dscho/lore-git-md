This thread is about a small but important safeguard for `git-subtree` (in `contrib/`). The patch series, now at v1, adds a runtime check to the existing shell-script implementation to detect and reject repositories that have been modified by a forthcoming Rust rewrite of the same command. The Rust rewrite will use a config key (`subtree.rust-rewrite`) to store metadata and won’t be backward-compatible; mixing the two could create unparseable history. The design is now settled: the safeguard checks only the top-level repository config, reflecting the social relationship between upstream and downstream projects rather than their physical layout.
