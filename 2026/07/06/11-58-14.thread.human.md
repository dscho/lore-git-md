Ian Jackson sent a two-patch series to add a safeguard in the shell-script `git-subtree` (in `contrib/`) that detects and rejects repositories modified by a forthcoming Rust rewrite of the same command. The Rust version will use a config file to store metadata and won’t be backward-compatible, so mixing the two could corrupt history. The series adds a check for the config key `subtree.rust-rewrite` and includes a test case.

Junio C Hamano reviewed the first patch and found a **variable scoping bug** in the helper function `reject_if_v2_config`: it uses a local variable `rev` that isn’t passed as an argument, causing it to check the wrong tree (the index, not `HEAD`) when called with `"HEAD"`. The fix is simple—pass the revision as `$1`—and Junio didn’t question the rest of the patch (error message, config key, or test). The series is otherwise self-contained and under review; no other concerns have been raised yet. The next revision will likely address this issue quickly.
