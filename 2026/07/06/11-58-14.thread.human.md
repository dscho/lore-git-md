This thread is about a small but important safeguard for `git-subtree` (in `contrib/`), authored by Ian Jackson. The patch series adds a runtime check to prevent mixing the existing shell-script implementation with a forthcoming Rust rewrite, which will use a config key (`subtree.rust-rewrite`) to store metadata and won’t be backward-compatible. The design is now settled: the safeguard checks only the top-level repository config, and the decision to adopt the new implementation rests with the downstream project.

The series is effectively complete—all technical feedback has been addressed, and the only remaining step is a v2 reroll to restyle the test case for consistency with Git’s test framework idioms (using `test_commit` and orphan branches). Junio marked it as "Expecting a reroll" in his "What’s cooking" report, and Colin Stagner explicitly confirmed the current version is the correct path forward. In the latest email, Junio checks whether Ian’s travel plans might delay the v2 update, but the question is purely logistical; no new concerns or objections have been raised. Once v2 is posted, the series should be ready for inclusion. The forthcoming Rust rewrite will document its limitations (e.g., no support for manual `-X subtree` merges) but won’t enforce them at runtime.
