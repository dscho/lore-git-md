This thread is about a small but important safeguard for `git-subtree` in `contrib/`. Ian Jackson’s patch series (v1) adds a check to the existing shell-script version of `git-subtree` to detect and reject repositories that have been modified by a forthcoming Rust rewrite of the same command. The Rust rewrite will use a config key (`subtree.rust-rewrite`) to store metadata, and mixing the two implementations could create unparseable history.

The series is now under review and essentially complete. The initial version had a scoping bug in the detection helper function, which Junio C Hamano caught and fixed. Junio also confirmed the error message format, and Ian accepted minor test style improvements from Colin Stagner and Phillip Wood. The only remaining discussion was about where the safeguard should look for the config key—top-level repository config only, or also inside the subtree directory. Colin Stagner probed this design choice, but after clarifying terminology and intent, he agreed the current approach is correct. The Rust rewrite’s limitation (not supporting unmarked subtree merges) will be documented and tested, but not enforced at runtime.

Key participants are Ian Jackson (author), Junio C Hamano (maintainer), Colin Stagner, and Phillip Wood. All review points have been addressed or declined with justification, and no substantive objections remain. The series touches `contrib/subtree/git-subtree.sh` and adds a test case to `t/t7900-subtree.sh`. The next step is likely for Junio to pick it up for integration.
