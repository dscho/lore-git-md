This thread is about a small but important safeguard for `git-subtree` (in `contrib/`). The goal is to prevent users from mixing the current shell-script implementation with a forthcoming Rust rewrite, which will use a new config key (`subtree.rust-rewrite`) to store metadata and won’t be backward-compatible. The initial patch (v1) had a scoping bug in its detection helper function, which Junio C Hamano caught: the function used a local variable that wasn’t passed as an argument, causing it to check the wrong tree (the index instead of `HEAD`).

Ian Jackson has now acknowledged the feedback and confirmed the fix—making the revision a positional argument (`$1`)—which resolves the issue. The error message and the rest of the patch remain unchanged, though Ian is open to minor adjustments if Junio prefers a different style. No other concerns have been raised, and the series is on track for acceptance once the scoping fix is incorporated. The next revision will focus solely on this correction, keeping the scope narrow.
