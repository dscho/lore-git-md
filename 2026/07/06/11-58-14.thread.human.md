This thread is about a small but important safeguard for `git-subtree`, a contributed tool in Git's `contrib/` directory. Ian Jackson is preparing a Rust rewrite of `git-subtree` that will not be backward-compatible with the existing shell-script version. To prevent users from accidentally mixing the two implementations and creating unparseable history, he has sent a two-patch series that adds a detection mechanism to the current `git-subtree`: if the new config file used by the Rust version is found in the repository, the old tool will bail out with an error message.

The patches are straightforward—one adds the detection logic to the shell script, and the other adds a test to verify the behavior. The error message refers to the new tool as if it already exists, which the author defends on the grounds that users will only see it once the Rust rewrite is in use. The goal is to get this safeguard merged and backported by distributions before the Rust version becomes widely available, protecting users from potential data corruption. So far, the series appears uncontroversial, with no review feedback yet.
