This is the first patch in Tian Yuchen's v7 series migrating more global configuration variables into `struct repo_config_values`. It introduces `repo_config_values_clear()`, a destructor function that frees heap-allocated strings stored in the repository's configuration values struct. The immediate focus is on `attributes_file`, with a clear path forward for extending the function to handle additional variables as they are migrated.

The patch is a direct follow-up to the recently merged `excludes_file` series and reimplements part of that work (the destructor logic) with minor adjustments. The key technical detail is the submodule guardrail: `repo_config_values_clear()` silently returns if called on a submodule repository, avoiding a crash since `repo_config_values()` currently BUG()s out for non-`the_repository` instances. This limitation is explicitly marked as `NEEDSWORK` but is not a blocker for the current series.

The implementation is clean and well-documented, with a clear comment block explaining the function's purpose and future extensibility. The call to `repo_config_values_clear()` is added to `repo_clear()` in `repository.c`, ensuring proper cleanup during repository teardown. No user-visible behavior changes are introduced, and the patch is CI-clean.

This patch sets the stage for the rest of the series by establishing the memory management pattern for migrated variables. The `repo_config_values_clear()` function will be extended in subsequent patches to handle the additional variables being moved into `struct repo_config_values`. The submodule limitation is carried over from the prior series and remains unresolved, but the author has flagged it as future work.
