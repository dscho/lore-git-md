This is the second patch in the v4 series refining Git's build system for Rust components on macOS, focusing on Universal Binary support. Patrick Steinhardt's review raises a **substantive technical question** about the directory layout for Rust build artifacts.

The patch itself is well-motivated and addresses a real need: macOS Universal Binaries (multi-architecture executables) are standard for distribution, but Cargo requires separate invocations per target triple, unlike Apple's C toolchain which handles multiple architectures natively. The solution—allowing users to specify multiple Rust targets via `RUST_TARGETS`, compiling each separately, then combining them with `lipo`—is sound and uncontroversial in principle. All prior feedback (including Junio's style tweaks) has been addressed.

Patrick's concern is about **build artifact organization**: the patch creates two different directory layouts (`target/$ARCH/$BUILD_CONFIG/` for per-architecture artifacts and `target/$BUILD_CONFIG/` for the final universal library). He suggests unifying them under `target/$BUILD_CONFIG/$ARCH/` for consistency. This isn't a correctness issue—everything works as written—but it touches on maintainability and clarity. The question is whether the current layout is intentional (e.g., to match Cargo conventions) or an oversight. The answer will determine whether the patch needs a small revision or just a commit message tweak.

The rest of the patch is solid: the `RUST_TARGETS` environment variable is a clean user interface, the `lipo` assumption is reasonable (confirmed by D. Ben Knoble), and the build rules are declarative and robust. No new tests are needed; the changes are implicitly covered by existing build tests. If the directory layout question is resolved, this patch is ready to merge. The series as a whole (which also fixes a parallel build race condition in the macOS credential helper) is a **build system improvement** targeting the ongoing Rustification effort.
