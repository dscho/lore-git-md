This is a **contributor housekeeping** patch review for the `git-subtree` safeguard series. Junio C Hamano, the maintainer, replies to the first patch in Ian Jackson’s two-patch series that adds a detection mechanism to the shell-script `git-subtree` to prevent mixing with a forthcoming Rust rewrite.

The review is **substantive** but narrowly focused. Junio identifies a **variable scoping bug** in the helper function `reject_if_v2_config`: the function uses a local variable `rev` that is not passed as an argument, so it will not work correctly when called with the literal string `"HEAD"` (as in `cmd_add` and `cmd_merge`). Instead, the function silently checks the wrong tree (the index, not `HEAD`). The fix is straightforward: the helper should accept the revision as a positional argument (`$1`) rather than relying on a global variable.

The rest of the patch (the error message, the config key, and the test) is not questioned; Junio’s feedback is purely about the correctness of the detection logic. The issue is clear and actionable, so the next revision will likely address it quickly. No broader concerns about the series’ motivation or design are raised.
