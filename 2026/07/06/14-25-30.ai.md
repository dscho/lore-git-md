This is the final patch in Tian Yuchen's v7 series migrating global configuration variables into `struct repo_config_values`. It moves the `object_creation_mode` enum (which controls whether Git uses hardlinks or renames when creating object files) into the per-repository configuration structure.

The patch relocates the `enum object_creation_mode` definition in `environment.h` to make it visible to `struct repo_config_values`, initializes the per-repository value to `OBJECT_CREATION_MODE` in `repo_config_values_init()`, and updates `git_default_core_config()` to write directly to the repository-specific structure. The only caller (`object-file.c`) is updated to read from `repo_config_values(repo)->object_creation_mode` instead of the global variable.

This is a clean, mechanical change that follows the established pattern from earlier patches in the series. The commit message is clear, and the code changes are minimal and focused. No user-visible behavior changes are introduced; this is purely foundational work for libification. The patch touches `environment.c`, `environment.h`, and `object-file.c`, and the enum relocation is necessary to avoid circular dependencies.

Key symbols for follow-up: `object_creation_mode`, `OBJECT_CREATION_USES_HARDLINKS`, `OBJECT_CREATION_USES_RENAMES`, and `repo_config_values_init()`. The patch completes the series' goal of migrating the nine targeted variables, leaving only the RFC questions and promised follow-up cleanup (comments/variable classification in `repo_config_values`) as open items.
