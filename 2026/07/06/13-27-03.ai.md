This is the fourth iteration of Patrick Steinhardt’s five-patch series adding reference-writing subcommands to the `git refs` builtin. The series is now fully merged (v3 was already queued for the next release), and this reroll (v4) makes only minor test additions and stylistic tweaks in response to earlier review feedback. No functional changes were introduced.

The core goal remains consolidating reference manipulation under a unified `git refs` interface. The new subcommands—`delete`, `update`, `create`, and `rename`—mirror or extend existing functionality from `git update-ref` and `git symbolic-ref`, with improved discoverability and test coverage. The series touches the `refs/` subsystem, adds new test scripts (`t1464-refs-delete.sh`, `t1465-refs-update.sh`, `t1466-refs-create.sh`, `t1467-refs-rename.sh`), and updates the `git-refs` man page.

Key changes in v4 are limited to test improvements:
- Two new tests for symbolic reference (symref) handling in `git refs delete` and `git refs rename`. The `delete` test verifies that `--no-deref` correctly enforces atomic checks on the symref’s target OID, while the `rename` test explicitly documents that symref renaming is unsupported (failing with a clear error message). These address usability concerns raised by Toon Claes in earlier reviews.
- A stylistic tweak to use a subshell in one test for consistency with the rest of the test suite.

The series is technically complete and uncontroversial. The only open usability questions—whether `--no-deref` in `git refs create` is intuitive and whether symref renaming should be supported—remain unresolved but are now explicitly documented in tests and error messages. The symref renaming limitation is a known backend constraint, not a design choice, and Patrick’s response suggests it is unlikely to change soon.

For a future AI summarizer, note the following technical details:
- Files: `builtin/refs.c`, `Documentation/git-refs.adoc`, new test scripts (`t1464-` to `t1467-`).
