This is the sixth iteration of a build system patch series targeting Rust integration on macOS, specifically for the `git-credential-osxkeychain` helper. The series now consists of three patches addressing parallel build reliability, macOS Universal Binary support, and automated CI verification for macOS contrib utilities.

The key change since v5 is the reversion of the first patch to avoid a duplicate `main()` symbol conflict. Instead of depending on `$(GITLIBS)` (which includes `common-main.o`), the patch now explicitly lists `$(LIB_FILE)` and `$(RUST_LIB)` as prerequisites. This resolves Junio C Hamano's blocking concern about link-time conflicts while still fixing the parallel build race condition. The commit message now clearly explains why `$(GITLIBS)` cannot be used: `git-credential-osxkeychain.c` defines its own `main()` function, unlike standard Git builtins that rely on `common-main.o`.

The second patch remains unchanged, implementing Universal Binary support via the `RUST_TARGETS` environment variable. Users can specify multiple target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`), and the build system compiles separate static libraries per target, combining them into a single Universal Binary using `lipo`. This patch is functionally complete and ready for integration, with backward compatibility maintained by defaulting to the system's native Rust target when `RUST_TARGETS` is unspecified.

The newly added third patch addresses automated CI verification by wiring up `git-credential-osxkeychain` in `contrib/Makefile` on macOS. It introduces an `OS_CONTRIB` variable to conditionally include the osxkeychain helper in the `all`, `test`, and `clean` targets when running on Darwin. This ensures that standard CI test runs on macOS automatically compile and link the helper, preventing build regressions.

The series touches only the `Makefile` and `contrib/` directory, introduces no on-disk format changes, and maintains backward compatibility. The changes are well-motivated, with clear commit messages explaining the technical rationale and addressing prior feedback. The first patch's reversion to explicit dependencies is a direct response to Junio's review, demonstrating the authors' engagement with the feedback process. The Universal Binary support and CI verification patches are clean, self-contained improvements that address real-world distribution and testing needs.
