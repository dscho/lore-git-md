This is a completion-script discussion for `git send-email`. Junio C Hamano replies to D. Ben Knoble’s review of Yury Norov’s patch, which adds filesystem path completion for patch files. Junio agrees with Knoble’s suggestion to avoid the informal term “hashtag” in the commit message but questions whether the example in the patch is truly representative. He points out that the test uses a purely hexadecimal tag name (not an object name), which he finds unnecessarily ambiguous, and suggests the complaint about completion behavior might be unfair if the user has deliberately named a branch or tag with a numeric prefix. Junio also notes that he couldn’t reproduce the claimed expansion of abbreviated object names to full hashes in his own testing, though he acknowledges the core issue—when both a patch file and a ref share a prefix, both should be offered as completion candidates. His tone is measured, and he doesn’t object to the patch’s goal, but he clearly wants the commit message and test case to better reflect real-world scenarios. The discussion remains open, awaiting further input from completion-script experts or the author’s response.
