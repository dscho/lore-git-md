This is the second patch in Ted Nyman’s v3 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI and dumb HTTP downloads. It is a **bugfix** targeting the core HTTP transport subsystem, specifically the packfile URI feature and dumb HTTP fetches.

The patch addresses a long-standing race where multiple Git processes downloading the same packfile into a single object database can corrupt the temporary pack file or cause resume requests to fail at EOF. The core change is in `http.c`: instead of opening the partial pack in append mode (which forces each write to the current end of the file), the code now opens it read-write without `O_APPEND` and seeks once to its current end. Each downloader retains its own descriptor offset, ensuring that overlapping responses write identical bytes at identical offsets rather than appending duplicate data. This preserves resumable downloads while preventing corruption.

The implementation is careful about Windows (MinGW) compatibility: a newly created partial pack is opened exclusively, closed, and reopened without `O_CREAT` so that every retained descriptor permits another downloader to unlink the staging path. The patch also handles the HTTP 416 (Range Not Satisfiable) case gracefully when a partial pack is already complete, letting `index-pack` validate its contents.

Test coverage is thorough: new regression tests in `t/t5550-http-fetch-dumb.sh` exercise resumed transfers, EOF ranges, overlapping 200/206 responses, unlinking the staging path while `index-pack` holds its descriptor, and a deterministic overlapping-download test using a custom Perl server to verify pack integrity. The tests are narrowly scoped to the packfile URI download path and do not affect other HTTP fetch behaviors.

The patch is well-motivated, the implementation is clean, and the test coverage is comprehensive. It directly addresses feedback from Junio C Hamano, Taylor Blau, and Jeff King (Peff) on earlier versions, adopting Peff’s suggested improvements and Junio’s request to split the documentation cleanup into a separate patch. The changes are unlikely to affect backwards compatibility and should be uncontroversial. The key technical detail is the use of per-descriptor offsets to ensure safe overlapping writes without cross-process coordination.
