It makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, validating the reported pack hash against the advertised hash and only registering a keep lockfile when the current process created it (`created_keep` flag).

The patch touches `fetch-pack.c` and adds a new regression test in `t/t5702-protocol-v2.sh` that exercises a packfile URI fetch with a pre-existing `.keep` file. The test verifies that the existing `.keep` file is preserved, the pack and index files are created, and the expected object is retrievable. The implementation adopts Jeff King’s suggested `strbuf` refactor for clarity and robustness, replacing the fixed-size `packname` buffer with a more flexible approach.

This patch directly addresses feedback from the v2 discussion, where reviewers noted that `index-pack` reports `"pack"` rather than `"keep"` when it finds an existing `.keep` file. The change ensures that `fetch-pack` correctly handles both cases, preventing spurious failures when concurrent fetches encounter pre-existing `.keep` files. The validation of the pack hash against the advertised hash adds an important safety check, ensuring that the downloaded pack matches expectations even if the `.keep` file was created by a different process.
