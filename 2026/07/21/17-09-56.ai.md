This is a review reply in the `git send-email` completion thread. Junio C Hamano responds to D. Ben Knoble’s feedback on Yury Norov’s patch, which adds filesystem path completion for patch files. The core discussion here is about the framing of the original problem: Junio questions whether the patch’s motivation—completing patch files when a prefix matches both a revision and a patch file—is a genuine issue or an artifact of an unusual tag name (a long hexadecimal string used in the test). He argues that the test’s use of a purely hexadecimal tag name (e.g., `0123456789abcdef...`) is unnecessarily ambiguous and not representative of typical Git workflows, where branch names like `0-tolerance-policy` would not reasonably be confused with patch files like `0001-changes.patch`.

Junio also tests the current completion behavior and reports that it does not expand abbreviated object names to full hashes (contrary to the commit message’s implication), further weakening the case for the patch’s necessity. However, he concedes that if both a patch file and a branch share a prefix (e.g., `0`), the completion script *should* offer both as candidates, though he personally would prefer the script to prioritize filenames over refs. His tone suggests skepticism about the patch’s urgency but leaves the door open for the feature if others find it useful. The thread remains open, awaiting broader input from completion-script experts or other contributors.
