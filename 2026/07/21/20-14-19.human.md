This is the second patch in Harald Nordgren’s v3 series fixing push tracking after remote renames. It implements the core logic: when `branch.<name>.pushRemote` is set to a URL (or a remote that has been renamed away), Git now consults the URL-to-remote map to find a fallback remote that shares the same URL or `pushurl`. If exactly one such remote exists, it is used to resolve `@{push}` and update the remote-tracking branch after a push; if multiple remotes share the URL, the behavior remains unchanged to avoid ambiguity.

The patch touches `remote.c`, `remote.h`, `transport.c`, and updates `Documentation/config/branch.adoc` and `Documentation/revisions.adoc` to document the new behavior. A new test script (`t/t5505-remote.sh`) adds 124 lines of coverage for rename scenarios, URL resolution, `pushInsteadOf` handling, and edge cases. The key new function is `repo_remote_for_push_tracking()`, which consults the URL-to-remote map and handles `pushurl` and `pushInsteadOf` rewrites. The commit message and documentation are thorough, explaining the motivation (workflows involving GitHub’s `gh` CLI) and edge cases (duplicate URLs).
