This thread is about a bugfix for a long-standing issue in Git's submodule handling. Éric NICOLAS identified that `git submodule update --remote` fails when URL aliases (`url.<base>.insteadOf`) are used, because the unexpanded URL in `.gitmodules` doesn't match the resolved URL reported by the submodule's remotes. The fix modifies `repo_remote_from_url()` in `remote.c` to resolve aliases before comparing URLs, ensuring the correct remote is selected.

The patch is minimal and focused, touching only `remote.c` and adding a test case to `t/t7406-submodule-update.sh`. The test verifies the fix by setting up a global `insteadOf` alias, creating a submodule with the aliased URL, and confirming that `update --remote` works after renaming the default remote.
