This thread is about a bugfix for a regression in `git submodule update --remote` when URL aliases (`url.<base>.insteadOf`) are used. The issue, introduced in commit ca62f524c1 (2025), caused submodules with aliased URLs to fail to match their remotes because `.gitmodules` stores the unexpanded alias while the submodule’s remotes report the resolved URL.

Éric NICOLAS posted a v2 patch that addresses Junio C Hamano’s feedback on the initial version. The patch improves commit message clarity, removes a redundant variable, and streamlines the test while maintaining full coverage. The core fix modifies `repo_remote_from_url()` in `remote.c` to resolve aliases before comparing URLs, ensuring the correct remote is selected. The test in `t/t7406-submodule-update.sh` verifies the fix with a global `insteadOf` alias and submodule setup.

Junio has queued the patch for merging, indicating it is ready for inclusion. No open questions or objections remain, and the changes are narrowly scoped, well-tested, and do not alter the on-disk format. The fallback behavior’s limitations (e.g., failing when no "origin" remote exists) are now documented in the commit message.
