This is a **bugfix for the macOS fsmonitor backend**, addressing a performance regression introduced by an earlier change.

The patch fixes a timeout issue in Git’s fsmonitor daemon on macOS. Since April 2026, the daemon has enforced a one-second timeout while waiting for filesystem events (via FSEvents) to avoid hanging when the filesystem stops delivering notifications. However, FSEvents batches notifications and doesn’t guarantee immediate delivery, so even a working system can hit the timeout under load. The author reports that on a large repository (1M+ index entries), nearly all fsmonitor requests timed out, forcing Git to fall back to full index scans—degrading `git status` from sub-second to 50+ seconds.

The fix adds a call to `FSEventStreamFlushAsync()` after creating the "cookie" file (a synchronization marker) but before starting the timed wait. This nudges FSEvents to deliver any pending notifications without blocking the main thread. The change is macOS-specific; Linux and Windows backends get no-op stubs. The patch is small (23 lines), well-explained, and includes before/after measurements on real hardware. It looks like a targeted, low-risk fix for a real-world performance problem.
