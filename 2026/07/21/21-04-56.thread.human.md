This thread is about a macOS-specific fix for Git’s fsmonitor daemon, which has been timing out on loaded systems and causing multi-second delays in `git status`. The patch, by Tamir Duberstein, adds an asynchronous flush of pending FSEvents notifications before the daemon waits for a cookie file, addressing a known issue where the FSEvents queue doesn’t reliably drain within Apple’s documented 1 ms latency window.

The patch itself is narrowly scoped and has received a tested review from Koji Nakamaru, who called it low-risk but asked for more benchmark data in the commit message. Junio forwarded this request without further comment. Patrick Steinhardt raised two concerns: first, a technical question about FSEvents queue behavior, which Tamir answered by citing Apple’s documentation and the project’s own history; and second, a process objection to Tamir’s use of an AI-generated explanation, insisting on a first-hand rationale. Tamir has now replied, acknowledging that the flush call *feels* unnecessary under the 1 ms latency interpretation but confirming empirically that it works, with a reference to Watchman (Facebook’s filesystem monitor) adopting the same fix for the same issue. However, he still hasn’t provided the requested benchmark data or a deeper technical explanation grounded in Apple’s documentation, so the thread remains blocked on those two points. No code changes have been made since the initial patch.
