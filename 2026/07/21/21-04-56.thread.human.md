This thread is about a targeted bugfix for a macOS-specific performance regression in Git's fsmonitor backend. Tamir Duberstein identified that the fsmonitor daemon, introduced in April 2026, was timing out waiting for filesystem events on loaded macOS systems even when the event stream was working correctly. This led to excessive `lstat()` calls and multi-second delays during `git status`.

The fix is minimal and platform-specific: it adds an asynchronous flush of pending FSEvents notifications right after creating the cookie file and before starting the timed wait. This change is implemented only for macOS (using `FSEventStreamFlushAsync`), while Linux and Windows backends receive no-op stubs. Performance data in the commit message shows dramatic improvements—on an M4 Max Mac with a 1M-entry index, timeouts dropped from ~89% and ~81% of requests to zero, and nearly a million unnecessary `lstat()` calls were eliminated during a single `git status` operation.

The patch has not yet received any review feedback on the mailing list, but its scope is narrow and well-contained, focusing only on the fsmonitor daemon's cookie wait mechanism. No objections or alternative approaches have been raised so far. If this holds, it’s likely to be queued for `next` soon, given its clear benefit for macOS users and lack of impact on other platforms.
