This thread is about a macOS-specific bugfix for Git’s fsmonitor daemon, which began timing out on loaded systems after an April 2026 regression, causing slowdowns in `git status`. The patch, by Tamir Duberstein, flushes pending FSEvents notifications before the daemon’s cookie wait to prevent excessive lstat() calls. It’s a narrow, uncontested change touching only the macOS backend, with no impact on Linux or Windows.

The patch itself is technically sound—Koji Nakamaru tested it and called it low-risk—but the commit message needs more benchmark data to quantify the timeout reduction. Junio echoed this request but hasn’t signaled a merge. Patrick Steinhardt’s recent review digs deeper, asking why flushing helps despite the 1ms latency setting, as the commit message doesn’t cite macOS documentation about FSEvents queue behavior. His question is more about understanding the platform quirk than blocking the patch, which he still calls "sensible."

The only remaining loose end is Tamir’s response to the benchmark request. Once that’s addressed, the patch should be ready to merge, assuming no further technical objections arise.
