This thread is about a macOS-specific bugfix for Git’s fsmonitor daemon, which regressed in April 2026 (commit 56cef9cb1a) and caused multi-second delays during `git status` on loaded systems. The patch, authored by Tamir Duberstein, flushes pending FSEvents notifications before the daemon’s cookie wait to avoid timeouts. It’s a narrow fix targeting only the macOS backend, with no changes to other platforms or on-disk formats.

The patch has been under review since its submission, with Koji Nakamaru providing a tested review that confirmed its scope and low risk but requested additional benchmark data in the commit message. Junio echoed this request but offered no technical feedback. Patrick Steinhardt raised a substantive question about FSEvents queue behavior, which Tamir has now addressed in detail: the 1 ms latency setting is a userspace delay, not a kernel guarantee, and Apple’s documentation explicitly warns that queue drainage is non-deterministic. Tamir’s response cites both Apple’s docs and the project’s own history (including a 2022 warning about this exact issue and a 2026 discussion where Patrick’s concerns were initially dismissed). The explanation resolves the technical ambiguity but doesn’t add new benchmark data, so the commit message enhancement remains the only open request.

The patch is effectively ready to merge once Tamir updates the commit message with the requested performance measurements. No code changes are needed, and the discussion has clarified the fix’s necessity without surfacing new objections.
