This thread is about a targeted bugfix for a macOS-specific performance regression in Git’s fsmonitor daemon. The issue, introduced in April 2026, caused the daemon to time out waiting for filesystem events on busy macOS systems, leading to slow `git status` operations. Tamir Duberstein authored the patch, which flushes pending FSEvents notifications asynchronously before the cookie wait, avoiding the timeout without affecting other platforms.

The patch is under review and has received its first substantive feedback from Koji Nakamaru, who confirmed the fix is well-scoped and low-risk. Koji suggested improving the commit message with additional benchmark data to better demonstrate the timeout reduction, but raised no technical objections. The implementation touches only the macOS fsmonitor backend (`fsmonitor--daemon.c` and `compat/fsmonitor/fsmonitor-fs-listen-macos.c`) and introduces no new symbols or on-disk format changes. Performance measurements from an M4 Max Mac with a 1M-entry index were provided in the original submission, though Koji’s feedback implies these could be expanded for clarity. No further reviews or open questions have been recorded.
