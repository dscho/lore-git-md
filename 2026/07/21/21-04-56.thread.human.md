This thread is about a macOS-specific fix for Git’s fsmonitor daemon, which was timing out on loaded systems due to non-deterministic drainage of the FSEvents queue. The patch, authored by Tamir Duberstein, adds an asynchronous flush of pending FSEvents notifications before the cookie wait to address the issue. While the implementation itself is uncontested—Koji Nakamaru confirmed it’s well-scoped and low-risk—the thread has stalled over process concerns.

The key sticking point is Tamir’s use of an AI-generated explanation for the FSEvents queue behavior. Both Patrick Steinhardt and Junio C Hamano have insisted that Tamir provide a first-hand technical rationale grounded in Apple’s documentation, rather than empirical observation or third-party precedent. Additionally, Koji Nakamaru and Junio have requested more benchmark data in the commit message to quantify the timeout reduction. Tamir has acknowledged these requests but has not yet provided either the documentation-backed rationale or the additional performance measurements. Until these are addressed, the patch remains blocked, despite no technical objections to the code itself.
