This is a documentation and error-message cleanup patch, the first in Ted Nyman’s three-patch v3 series fixing race conditions in Git’s HTTP transport. It corrects the `--index-pack-arg` option name in both the `git-http-fetch` man page and the corresponding error messages in `http-fetch.c`. The old plural form (`--index-pack-args`) is replaced with the singular (`--index-pack-arg`), and the documentation now accurately describes that the option can be repeated for each argument passed to `index-pack`. The change is purely textual and does not alter any behavior or logic.

The patch directly addresses Junio C Hamano’s review feedback from the v2 series, which requested splitting the documentation cleanup into a standalone preliminary patch. This keeps the functional changes in the subsequent patches clean and easier to review. The motivation is clear: the current documentation and error messages are misleading because they refer to a non-existent plural option name, which could confuse users or scripts that rely on the documented interface.

The files touched are `Documentation/git-http-fetch.adoc` and `http-fetch.c`. The diff is small and focused, changing only the option name and its description. No new symbols or test coverage are introduced in this patch. The change is uncontroversial and unlikely to affect any existing functionality, as it merely aligns the documentation and error messages with the actual implementation.

This patch sets the stage for the more substantive fixes in patches 2 and 3, which address the core race conditions in packfile URI and dumb HTTP downloads. The series as a whole is well-motivated, and this preliminary cleanup demonstrates the author’s responsiveness to review feedback. The patch is ready for review and should be a straightforward merge.
