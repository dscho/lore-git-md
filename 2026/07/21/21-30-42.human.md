This is a bugfix patch for submodule handling. It addresses a long-standing issue where `git submodule update --remote` fails to match the submodule's configured remote when URL aliases (configured via `url.<base>.insteadOf`) are in use.

The problem arises because the URL stored in `.gitmodules` is the *pre-alias* version (e.g., `local:path`), while the submodule's own remote configuration stores the *resolved* URL (e.g., `/full/path`). The current code compares these directly, causing the lookup to fail and fall back to less reliable heuristics (like defaulting to "origin"). The patch fixes this by resolving the alias before comparing URLs, ensuring the correct remote is selected.

The change is minimal and focused: it modifies `repo_remote_from_url()` in `remote.c` to apply URL rewrites before matching, and adds a new test case in `t/t7406-submodule-update.sh` that verifies the fix works with a realistic alias setup. The test is well-structured, covering both the alias resolution and the fallback behavior when multiple remotes exist.

This looks like a clean, well-motivated fix for a real-world pain point. The commit message clearly explains the issue and the solution, and the test coverage is thorough. No controversy is evident, and the patch aligns with Git's existing patterns for URL alias handling. Worth attention from anyone who uses submodules with aliased URLs.
