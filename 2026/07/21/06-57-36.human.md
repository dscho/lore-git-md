This is a feature patch adding a built-in userdiff driver for the Swift programming language. The patch is now in its second version (`v2`), addressing all substantive feedback from the first round of review. It is currently queued in `seen` but requires validation from active Swift users on the mailing list before it can progress to `next`.

The implementation is thorough and well-tested. The funcname pattern covers Swift’s entire declaration grammar, including edge cases like failable initializers (`init?`), generics (`init<T>`), and operator functions. The word regex handles Swift identifiers, literals (hexadecimal, octal, binary, floating-point), and operators. The patch includes 13 new test fixtures in `t/t4018/` that exercise all major Swift declaration types (classes, structs, enums, protocols, extensions, actors, etc.) and edge cases like multi-line attributes and generics. The author also provided empirical validation against real-world Swift codebases, showing 99.9% accuracy in hunk header identification.

The changes since `v1` are minor but important: fixing ambiguous test fixtures by ensuring `RIGHT` appears only once per test, and simplifying the word regex by removing redundant single-character operator handling. The author retained some of Johannes Sixt’s other suggestions as-is, explaining the reasoning in a reply to the review.

This is a self-contained, uncontroversial contribution that fills a clear gap in Git’s built-in language support. The patch is technically complete and ready for validation by Swift users on the list. If those tests pass, it should be a straightforward merge.
