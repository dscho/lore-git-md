This is the cover letter for the v3 reroll of Ted Nyman's bugfix series targeting race conditions in Git's HTTP transport during concurrent packfile URI and dumb HTTP downloads. The series now consists of three patches, with the first patch split out as a preliminary cleanup to address Junio C Hamano's review feedback.

The core problem remains: concurrent Git processes fetching the same packfile into a single object database can corrupt the temporary pack file or cause resume requests to fail at EOF. The v3 series preserves resumable downloads for both packfile URIs and dumb HTTP by using deterministic staging paths opened in read-write mode without append. Each downloader seeks to the current end of the file, requests the corresponding range, and writes using its own descriptor offset, ensuring overlapping responses write identical bytes at identical offsets. This approach avoids cross-process coordination while maintaining resumability and correctness.

Key changes since v2 include splitting the `--index-pack-arg` documentation and error-message cleanup into a separate preliminary patch, clarifying the rationale for per-descriptor offsets and MinGW's sharing behavior, and adding a new regression test that exercises unlinking the staging path while `index-pack` holds its descriptor (this test can run on MinGW). The series is rebased onto current master and is now considered ready for serious review.

The patches touch `http.c`, `fetch-pack.c`, and their associated documentation, with new regression tests in `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`. The test coverage now includes resumed transfers, EOF ranges, overlapping 200/206 responses, unlinking the staging path while indexing, and pre-existing `.keep` files. The implementation is narrowly scoped to the packfile URI download path and does not affect other HTTP fetch behaviors.

The series addresses feedback from Junio C Hamano, Taylor Blau, and Jeff King (Peff), adopting Peff's suggested improvements for the `.keep` file handling in Patch 3 and Junio's request to split the documentation cleanup into a separate patch. The design unifies the solution for both packfile URIs and dumb HTTP, handling handoffs, stale-file cleanup, and the EOF-range/416 case. The MinGW-specific workaround for sharing behavior is well-documented and appears robust.

No open questions or loose ends remain from the v2 discussion. The series is well-motivated, the implementation is clean, and the test coverage is thorough. The changes are unlikely to affect backwards compatibility and should be uncontroversial. The key technical detail to note is the use of per-descriptor offsets to ensure safe overlapping writes, which is a clever solution to the race condition without requiring cross-process coordination.
