This is a substantive review reply in the ongoing `git send-email` completion thread. SZEDER Gábor weighs in on the debate about whether the completion script should offer both refs (branches, tags) and filesystem paths (patch files) when they share a common prefix (e.g., `0`). His position is clear: the current behavior—offering only refs for commands like `git diff`, `git log`, and `git send-email`—is intentional and preferable.

Gábor argues that mixing refs and paths in the same completion list would make the list longer and harder to navigate, and that users already have straightforward ways to trigger filename completion when they want it (e.g., `./foo<TAB>`, `foo<ALT-/>`, or `-- foo<TAB>`). He notes that `git send-email` does not support the disambiguating doubledash (`--`), but this does not change his overall stance: the existing design, which keeps ref and path completion separate, is more usable.

His message also clarifies a technical point raised earlier: Git’s completion script does *not* expand abbreviated object names to full hashes, so the original patch’s claim about "hashtag" expansion is doubly misleading—both because the term is incorrect and because the behavior it describes does not exist.

This makes the thread more contentious; the patch now faces not just wording and test-design objections, but a fundamental disagreement about whether the feature is needed at all.
