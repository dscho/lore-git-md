This thread tracks a performance regression in `git receive-pack` introduced by the ODB abstraction rework, specifically commit `a593373b09`. The issue causes a 12% slowdown on fast filesystems (worse on NFS) due to redundant loose object checks during connectivity checks for pushes. The root cause is a change in object lookup order: the ODB rework shifted from a "pack-first, loose-second" strategy *per backend* to a "pack-loose, pack-loose" strategy *across backends*, leading to unnecessary loose object checks in earlier backends (e.g., quarantine) before finding objects in packs in later backends.

The regression is now confirmed to affect not just the quarantine area in `git receive-pack` but *all* alternates-based workflows, including `clone -s`, `--reference`, and large-scale hosting deployments (e.g., GitHub, GitLab). This broadens the scope significantly, as the performance penalty would impact nearly every Git operation in these scenarios. The discussion has split into two tracks: a near-term fix to restore the "pack-first, loose-second" lookup order across backends, and a longer-term architectural redesign of ODB transactions to route writes directly to the transaction object. Peff’s latest critique argues that the architectural approach cannot fully resolve the regression due to cross-process constraints (e.g., coordination between `index-pack` and `rev-list`), reinforcing the need for a targeted fix. Junio and Peff agree the near-term fix is the most viable path forward, but no one has yet volunteered to implement it.

Key participants include Wolfgang Kritzinger (who reported the regression), Peff (who confirmed and quantified it, and broadened its scope), Taylor Blau (who provided a technical analysis of the root cause), Junio (who framed the regression as an opportunity for ODB optimization), and Patrick Steinhardt (who proposed the transaction-aware ODB redesign). The regression is tied to the ongoing ODB abstraction effort, and its resolution may interact with Patrick’s planned work, which is delayed until late July or August. The thread remains open, with the near-term fix still unclaimed and questions about how it will coexist with the long-term redesign.
