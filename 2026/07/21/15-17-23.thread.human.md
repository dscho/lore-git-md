Here’s the human-mode summary for a developer catching up on the thread:

This thread is about a performance regression in Git’s server-side operations—particularly pushes and alternates-based workflows like `clone -s`—introduced by the ODB abstraction rework. The issue was first reported by Wolfgang Kritzinger (Atlassian) and later confirmed by Peff, who quantified a 12% slowdown (worse on NFS) and traced it to commit `a593373b09`. The root cause is a change in object lookup order: the ODB rework shifted from checking all packs before loose objects *per backend* to checking packs and loose objects *per backend before moving to the next*, causing redundant loose object checks in alternates-heavy scenarios. The regression now affects nearly all operations using `GIT_ALTERNATE_OBJECT_DIRECTORIES`, making it a systemic issue for large-scale hosting environments.

The discussion has split into two tracks. The near-term focus was on restoring the "pack-first, loose-second" lookup order across backends, but Patrick Steinhardt (the ODB rework’s author) has now proposed a more ambitious architectural change: moving alternates handling from the ODB layer into the "files" backend itself. This would treat alternates as an implementation detail of the backend, enabling optimizations like pack-first-loose-second lookups while simplifying other subsystems (commit-graph, bitmap, maintenance). Patrick’s proposal directly addresses the regression’s root cause and resolves secondary issues like the `OBJECT_INFO_SECOND_READ` flag, but its timeline (initial patches in late July) means a separate near-term fix may still be needed. Peff’s earlier critique of Patrick’s transaction-aware ODB writes remains unresolved, though this new proposal sidesteps some of those concerns by focusing on alternates as a backend-specific optimization.

Key participants include Peff (who framed the regression as a systemic alternates issue and provided a reproduction recipe), Taylor Blau (who reconciled bisect results and proposed a two-phase lookup fix), and Junio (who suggested both near-term optimizations and long-term architectural improvements). The thread is now converging on Patrick’s alternates-in-backend proposal as the most principled solution, though its interaction with Peff’s cross-process constraints (e.g., `index-pack`/`rev-list` coordination) is still unclear. No one has yet volunteered to implement a near-term fix, but Patrick’s plan to remove `odb_prepare_alternates()` calls in late July could obviate the need for one. The regression remains unaddressed in the short term, but the architectural direction is now clearer.
