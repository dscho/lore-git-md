This thread is about a performance regression in `git receive-pack` connectivity checks introduced by the ODB (object database) abstraction rework, specifically commit `a593373b09`. The regression, reported by Wolfgang Kritzinger from Atlassian, causes a 12% slowdown on fast filesystems and significantly worse performance on NFS-backed deployments due to excessive loose object checks. The root cause is a change in object lookup order: the ODB rework shifted from a "pack-first, loose-second" strategy *per backend* to a "pack-loose, pack-loose" strategy *across backends*, leading to redundant loose object checks even when objects exist in packs.
