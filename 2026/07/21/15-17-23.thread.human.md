This thread is about a performance regression in `git receive-pack` connectivity checks introduced by the ODB (object database) abstraction rework, specifically commit `a593373b09`. The regression, reported by Wolfgang Kritzinger (Atlassian), causes a 12% slowdown on fast filesystems and worse on NFS due to excessive failing `open()` calls for loose objects across multiple ODB backends. The root cause is a shift from a "pack-first, loose-second" lookup strategy *per backend* to a "pack-loose, pack-loose" strategy *across backends*, leading to redundant loose object checks.

The discussion has coalesced around Patrick Steinhardt’s proposal to move alternates handling into the "files" backend itself, treating alternates as an implementation detail rather than a cross-backend concern. This would restore pack-first-loose-second lookups across all alternates while simplifying other subsystems like commit-graph and bitmap loading. The proposal has gained explicit endorsement from Jeff King (Peff) and Justin Tobler, who agree that the flexibility trade-offs (e.g., combining alternates with non-files backends) are unlikely to be a practical issue. Patrick plans to implement this in stages starting in late July, though a near-term targeted fix (e.g., restoring the old lookup order) remains possible but unclaimed.

Key participants include Peff, who confirmed the regression and framed it as a systemic alternates performance issue; Taylor Blau, who provided a detailed technical analysis of the root cause; and Junio Hamano, who proposed alternative optimizations like pre-loading loose object names. Justin Tobler has also proposed decoupling transaction handling from the ODB source list to simplify the ODB layer, contingent on updating all temporary object directory users to use ODB transactions. The thread has shifted from diagnosing the regression to debating architectural solutions, with Patrick’s redesign now the leading direction. Open questions include the timeline for implementation, validation of performance trade-offs, and how the redesign will interact with submodules and object storage extensions.
