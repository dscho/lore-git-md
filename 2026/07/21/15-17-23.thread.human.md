The `git receive-pack` connectivity check performance regression introduced by the ODB rework (commit `a593373b09`) remains a pressing issue for large-scale Git deployments, particularly those using NFS-backed alternates. Wolfgang Kritzinger initially reported the problem, which was later confirmed and quantified by Jeff King (Peff) as a 12% slowdown on fast filesystems—worse on NFS—due to a shift in object lookup order from "pack-first, loose-second" to "pack-loose, pack-loose" across backends. This change causes redundant loose object checks in earlier backends (e.g., quarantine or alternates) before objects are found in packs in later backends, exacerbating the cost of failing `open()` calls.

The discussion has now coalesced around Patrick Steinhardt’s proposal to **move alternates handling into the "files" backend itself**, treating alternates as an implementation detail rather than a cross-backend concern. This architectural shift would enable pack-first-loose-second lookups across all alternates while simplifying other subsystems like commit-graph and bitmap loading. Peff has endorsed this direction, dismissing concerns about lost flexibility (e.g., combining alternates with non-files backends) as unlikely to be a practical issue. The proposal directly addresses the root cause and resolves secondary issues, such as dropping the `OBJECT_INFO_SECOND_READ` flag, but its implementation is slated for late July, leaving open the question of whether a near-term fix (e.g., a targeted lookup order adjustment) will be pursued to mitigate the immediate regression.

Key participants—including Peff, Taylor Blau, Junio Hamano, and Patrick—have engaged deeply with the problem, with Taylor’s analysis reconciling bisect results and Junio framing the regression as an opportunity to optimize the ODB abstraction for specialized use cases. While Patrick’s redesign is now the leading solution, unresolved questions remain about its interaction with transaction-aware ODB writes, submodule compatibility, and edge cases like nested alternates or concurrent operations. The regression’s impact on hosting environments (e.g., GitHub, GitLab) underscores the urgency, but the path forward hinges on Patrick’s upcoming implementation and whether it can accommodate all constraints without introducing new regressions.
