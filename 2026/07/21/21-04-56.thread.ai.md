Subject: [PATCH] fsmonitor: macOS: flush pending FSEvents before cookie wait
Series version: standalone patch (no series)
Originating author: Tamir Duberstein
Thread type: bugfix

Core problem or goal
Fix a macOS-specific performance regression in Git’s fsmonitor daemon introduced by 56cef9cb1a (April 2026). The regression caused the daemon to time out waiting for filesystem events on loaded macOS systems, triggering excessive lstat() calls and multi-second delays during `git status`.

Current status
Under review; no prior versions. Patch is narrowly scoped to the fsmonitor daemon’s cookie wait mechanism and does not affect other backends.

Key technical details
- Files touched: `fsmonitor--daemon.c`, `compat/fsmonitor/fsmonitor-fs-listen-macos.c`, `fsmonitor.h`
- New symbols: none (macOS-only `FSEventStreamFlushAsync` call added)
- Behavior change: asynchronous flush of pending FSEvents notifications immediately after cookie file creation and before the timed wait
- On-disk format: unchanged
- Test coverage: performance data provided in commit message (M4 Max Mac, 1M-entry index); no new test files

Open questions and loose ends
None identified; patch appears technically sound with proper locking considerations.
