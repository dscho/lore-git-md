Subject: [PATCH] fsmonitor: macOS: flush pending FSEvents before cookie wait
Series version: standalone patch (no series)
Originating author: Tamir Duberstein
Thread type: bugfix

Core problem or goal
Fix a macOS-specific performance regression in Git’s fsmonitor daemon introduced by 56cef9cb1a (April 2026). The regression caused the daemon to time out waiting for filesystem events on loaded macOS systems, triggering excessive lstat() calls and multi-second delays during `git status`. The root cause was hypothesized to be non-deterministic drainage of the FSEvents queue within the 1 ms latency interval, a behavior documented by Apple and previously noted in the project’s history (b05880d357, 2022). However, further investigation by the author failed to confirm this hypothesis, and the proposed fix is now withdrawn.

Current status
Patch withdrawn by the author after empirical testing did not validate the root cause or the effectiveness of the proposed fix. No code changes were merged. The macOS fsmonitor daemon still exhibits the timeout behavior on loaded systems, but the thread is closed unless Tamir resubmits with new evidence. The discussion leaves open the question of whether the FSEvents queue drainage issue is the true culprit or if another factor is responsible.

Key technical details
- Files touched: `fsmonitor--daemon.c`, `compat/fsmonitor/fsmonitor-fs-listen-macos.c`, `fsmonitor.h` (proposed changes abandoned)
- New symbols: none (proposed macOS-only `FSEventStreamFlushAsync` call was not merged)

Open questions and loose ends
