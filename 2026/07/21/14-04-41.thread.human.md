This thread introduces a new `--[no-]edit` option for `git rebase --continue`, allowing users to skip the editor prompt when continuing a rebase after conflict resolution. The feature is controlled by command-line flags (`--no-edit`, `--edit`) and a new `rebase.noEdit` configuration option, aimed at improving workflow efficiency for frequent rebasers.

The initial patch, submitted by Hugo Sales, is under review but has drawn substantive criticism from Junio C Hamano. Junio questions the necessity of the feature, noting that the existing workaround (`GIT_SEQUENCE_EDITOR=: git rebase --continue`) already achieves the same result without new flags or configuration. He is particularly critical of the `rebase.noEdit` config option, arguing it could encourage users to default to skipping commit message edits, potentially omitting important changes. Junio also highlights unaddressed edge cases: how the config option interacts with interactive rebase steps like `edit` or `reword`, and whether the behavior differs when a rebase stops for reasons other than conflicts. The current test coverage only validates the conflict-resolution path, leaving other scenarios untested.

The thread is now in a holding pattern. Hugo will need to address Junio’s concerns—either by expanding the patch to handle the edge cases, justifying why they can be ignored, or reconsidering the feature’s viability. No other reviewers have weighed in yet, and the patch remains in its initial version with no merge status.
