Hugo Sales has proposed adding a `--[no-]edit` option to `git rebase --continue`, allowing users to skip the editor prompt when continuing a rebase after resolving conflicts. The feature is controlled by command-line flags (`--no-edit`/`--edit`) and a new configuration option `rebase.noEdit`, which sets the default behavior.

The patch is self-contained, touching `builtin/rebase.c` and `sequencer.c` for the core logic, along with documentation updates and new tests in `t/t3436-rebase-more-options.sh`. The implementation is careful to ensure the flags apply only to the current `--continue` invocation, not to subsequent commits in the same rebase, which avoids potential confusion. The author has included thorough test coverage, including edge cases like the interaction between the CLI flags and the config option.
