This is a small but user-facing feature patch for `git rebase`. The author, Hugo Sales, adds a `--[no-]edit` flag to `git rebase --continue`, letting users skip the editor when they’re happy with the existing commit message. A matching `rebase.noEdit` config key makes this the default, and `--edit` overrides it for a single invocation.

The patch touches the rebase backend (`builtin/rebase.c` and `sequencer.c`), updates the man pages, and adds tests in a new file (`t3436-rebase-more-options.sh`). The implementation looks straightforward: it reuses the existing `edit` flag in the sequencer state and plumbs it through the command-line parser. No edge cases or backward-compatibility concerns are mentioned, and the author reports that all tests pass locally.

The motivation is clear—users often just want to keep the message as-is—and the design keeps the flags scoped to the current `--continue` rather than affecting the rest of the rebase. If you’ve ever been annoyed by the editor popping up unnecessarily, this patch is worth a quick look.
