This is a bugfix patch for submodule handling. It addresses a long-standing issue (since ca62f524c1, 2023) where `git submodule update --remote` fails to match the submodule's configured remote when URL aliases (`url.<base>.insteadOf`) are used. The problem occurs because the URL stored in `.gitmodules` remains unexpanded (e.g., `local:path`), while the submodule's remotes report the resolved URL (e.g., `/full/path`). The patch modifies `repo_remote_from_url()` in `remote.c` to resolve aliases before comparing URLs, ensuring the correct remote is selected.

The change is minimal and focused: it introduces alias resolution via `alias_url()`, uses the rewritten URL for matching, and cleans up the temporary string. The test case in `t/t7406-submodule-update.sh` verifies the fix by setting up a global `insteadOf` alias, creating a submodule with the aliased URL, and confirming that `update --remote` works after renaming the default remote and adding a secondary one.

Key technical details:
- **Files touched**: `remote.c` (core logic) and `t/t7406-submodule-update.sh` (test).
- **Function modified**: `repo_remote_from_url()` now resolves aliases before matching.
- **Test coverage**: Adds a scenario with a global `insteadOf` alias, submodule setup, and remote renaming.
- **Behavior change**: Submodules using aliased URLs will now correctly match their remotes instead of falling back to the default logic.

The patch appears well-motivated and self-contained, with clear test coverage for the regression. No controversy is evident from the commit message or diff.
