Core problem or goal
Fix a regression (introduced in ca62f524c1, 2025) where `git submodule update --remote` fails to match the submodule’s configured remote when URL aliases (`url.<base>.insteadOf`) are in use. The `.gitmodules` file stores the unexpanded alias (e.g., `local:path`), but the submodule’s remotes report the resolved URL (e.g., `/full/path`), causing the lookup to fail and fall back to the default remote.

Current status
Merged to `master` (2025-06-10, exact date from Junio’s merge message). Junio C Hamano queued the v2 patch for merging after confirming all feedback was addressed. The commit message now explicitly references the original regression commit (ca62f524c1) and documents the fallback behavior’s limitations (e.g., failing when no "origin" remote exists). The implementation reuses the `url` variable instead of introducing `url_to_match`, simplifying the code. The test is streamlined but retains full coverage.

Key technical details
- **Files touched**: `remote.c` (core logic), `t/t7406-submodule-update.sh` (test).
- **Function modified**: `repo_remote_from_url()` resolves aliases via `alias_url()` before comparing URLs.
- **New behavior**: Submodules using aliased URLs correctly match their remotes instead of falling back to the default logic.
- **On-disk format**: unchanged.
- **Test coverage**: verifies the fix with a global `insteadOf` alias, submodule setup, and remote renaming.
