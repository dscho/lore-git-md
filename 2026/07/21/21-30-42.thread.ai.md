Core problem or goal
Fix a regression (introduced in ca62f524c1, 2023) where `git submodule update --remote` fails to match the submodule’s configured remote when URL aliases (`url.<base>.insteadOf`) are in use. The `.gitmodules` file stores the unexpanded alias (e.g., `local:path`), but the submodule’s remotes report the resolved URL (e.g., `/full/path`), causing the lookup to fail and fall back to the default remote.

Current status
Under review; no prior versions posted. Patch is self-contained and includes a test case in `t/t7406-submodule-update.sh` that verifies the fix by setting up a global `insteadOf` alias, creating a submodule with the aliased URL, and confirming `update --remote` works after renaming the default remote and adding a secondary one.

Key technical details
- **Files touched**: `remote.c` (core logic), `t/t7406-submodule-update.sh` (test).
- **Function modified**: `repo_remote_from_url()` now resolves aliases via `alias_url()` before comparing URLs.
- **New behavior**: Submodules using aliased URLs correctly match their remotes instead of falling back to the default logic.
- **On-disk format**: unchanged.
- **Test coverage**: adds a scenario with a global `insteadOf` alias, submodule setup, and remote renaming.
