This is a **performance regression report** targeting the object database (ODB) subsystem, specifically the connectivity check in `git receive-pack`. The author, Wolfgang Kritzinger from Atlassian, identifies a slowdown in server-side Git operations (pushes to Bitbucket) after upgrading from Git 2.50 to 2.54. The regression manifests as excessive failing `open()` calls for loose objects across multiple ODB backends (quarantine and main object stores), which is particularly costly on NFS-backed deployments.

The issue is traced to commit `8384cbcb4c`, part of the recent ODB rework. The author hypothesizes that the lookup order for objects changed from a "pack-first, loose-second" strategy *per backend* to a "pack-loose, pack-loose" strategy *across backends*, causing unnecessary loose object checks even when objects exist in packs. The commit message does not propose a fix but asks whether the costly lookups can be avoided, suggesting the problem is understood but not yet resolved.

This report is **high-signal for downstream users** (especially those on NFS) and **likely to generate follow-up discussion** about ODB backend iteration order, performance trade-offs in the rework, and potential optimizations. The regression is concrete, measurable, and tied to a specific commit, making it actionable for maintainers. Expect replies to focus on confirming the bisect result, discussing the intended ODB lookup semantics, and evaluating whether the current behavior is a bug or an unintended side effect of the abstraction effort.
