Subject: [PATCH] rebase --continue: add --[no-]edit option
Series version: v1 (initial submission)
Originating author: Hugo Sales <hugo@hsal.es>
Thread type: patch series (single patch)

Core problem or goal
Add a `--[no-]edit` option to `git rebase --continue` to allow users to skip the editor prompt when continuing a rebase after conflict resolution, controlled by command-line flags (`--no-edit`, `--edit`) and a new configuration option `rebase.noEdit`. The change is motivated by workflow efficiency for users who frequently rebase and want to accept the existing commit message without manual intervention.

Current status
Under review (initial submission). Junio C Hamano and Phillip Wood have raised substantive design concerns, particularly about the `rebase.noEdit` configuration option and its interaction with interactive rebase steps (`edit`, `reword`). The patch remains in its initial version with no revisions yet posted.

Key technical details
- **Files touched**: `builtin/rebase.c`, `sequencer.c`, `Documentation/git-rebase.adoc`, `Documentation/config/rebase.adoc`, `t/t3436-rebase-more-options.sh`.
- **New symbols**: CLI options `--no-edit`/`--edit` for `git rebase --continue`, config key `rebase.noEdit`.
- **Behavior**: Flags apply only to the current `--continue` invocation, not subsequent commits in the same rebase. The sequencer logic resets the `edit` flag after each `--continue` to prevent unintended persistence. The patch does not address how the feature interacts with interactive rebase steps (`edit`, `reword`) or whether behavior differs when the rebase stops for reasons other than conflict resolution.
- **On-disk format**: No changes.
- **Test coverage**: New tests in `t/t3436-rebase-more-options.sh` validate the feature for conflict-resolution paths only; other scenarios (e.g., `edit`/`reword` steps, non-conflict stops) are untested. Phillip Wood notes the correct environment variable for suppressing the editor is `GIT_EDITOR=:`, not `GIT_SEQUENCE_EDITOR=:`.

Open questions and loose ends
- **Design necessity**: Junio questions whether the feature is justified given the existing workaround (`GIT_EDITOR=: git rebase --continue`).
- **Config option scope**: Whether `rebase.noEdit` is too broad, as it could silently override user intent during interactive rebase steps like `edit` or `reword`. Phillip Wood reinforces this concern by noting that even his prior alias-based workaround does not prevent accidental suppression during `reword` steps.
- **Edge cases**: How the feature behaves when the rebase stops for reasons other than conflict resolution (e.g., `edit`/`reword` steps, merge failures). Junio explicitly asks whether users would need to remember to pass `--edit` in these cases.
- **Test coverage gaps**: The current tests do not validate behavior outside the conflict-resolution path. Phillip Wood’s reference to prior discussion (2024) highlights that these edge cases have been unresolved for over a year.

Related work
None. This is a standalone feature addition with no dependencies on other in-flight efforts. The existing workaround (`GIT_EDITOR=:`) is noted as a simpler alternative. Phillip Wood’s prior alias proposal (2024) is referenced but does not resolve the broader edge cases.
