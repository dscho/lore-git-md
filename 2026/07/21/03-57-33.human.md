This is a **performance regression discussion** in the ODB (object database) subsystem, specifically the connectivity check in `git receive-pack`. Jeff King (Peff) confirms Wolfgang Kritzinger's report of a slowdown in Git 2.54, reproducing the issue with a minimal test case and measuring a ~12% performance hit even on fast filesystems. The regression stems from a change in object lookup order introduced during the ODB rework, where loose objects are now checked *per backend* (e.g., quarantine directory, main object store) before moving to the next backend's packs, rather than checking all packs first.

Peff's bisect points to commit `a593373b09` (a refactor of `find_pack_entry()`), not `8384cbcb4c` as initially reported, suggesting the root cause may be slightly different or dependent on test conditions. He acknowledges the tension between the ODB abstraction goals and the need for performance optimizations like "packs-first" lookups, but calls the current behavior "wrong" and flags it as a regression worth fixing. Patrick Steinhardt, the ODB rework lead, is now CC'd and will likely weigh in on whether the abstraction can accommodate this optimization or if a targeted fix is needed.

The discussion is **high-signal for maintainers and downstream users** (especially NFS deployments like Bitbucket). Peff's reproduction recipe and timing measurements make the issue actionable, and his framing—prioritizing performance over abstraction purity—sets the stage for a focused technical debate. Expect follow-up on whether to revert the lookup order change, introduce a "fast/slow" backend classification, or find another mitigation.
