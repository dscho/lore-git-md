This is a refactoring patch targeting the `git show-branch` command. Gatla Vishweshwar Reddy sends v10 of a long-running effort to eliminate `git show-branch`'s reliance on the shared `object.flags` field for per-commit state, replacing it with a dedicated commit-slab that dynamically grows to support an arbitrary number of branches. The patch removes the previous 27-branch limit entirely, updates documentation, and adds tests for 30+ branches.

The immediate motivation is to fix the critical regression Junio identified in v9: the accidental removal of `init_commit_name_slab(&name_slab)` caused a division-by-zero crash in `commit_to_name()`. Gatla restores the initialization call in v10 and confirms manual testing of every mode (`--merge-base`, `--independent`, `--reflog`, etc.) passes without crashes. The patch is now technically sound and addresses all prior feedback.

Key technical details: the patch introduces a new `commit_rev_flags` slab with runtime-computed stride (`(ref_name_cnt + 63) / 64`), helper functions for bit manipulation (`has_only_rev_flag_bit`, `has_subset_rev_flags`), and dynamically allocated arrays for ref names and commit pointers. The `UNINTERESTING` bit remains in `object.flags` for revision-walking compatibility. Three new tests in `t/t3202-show-branch.sh` verify correct operation with 30+ branches.

The patch is part of the broader effort to eliminate misuse of `object.flags` across Git.
