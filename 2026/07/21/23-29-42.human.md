This is the third and final patch in Ted Nyman’s v3 series fixing race conditions in Git’s HTTP transport during concurrent packfile URI downloads. It makes `fetch-pack` accept both `"keep<TAB><hash>"` and `"pack<TAB><hash>"` output from `index-pack`, ensuring robust `.keep` file handling when multiple processes fetch the same packfile.

The patch addresses a subtle edge case: when `index-pack` encounters an existing `.keep` file, it reports `"pack"` instead of `"keep"`. The previous code only accepted `"keep"`, causing failures in concurrent scenarios. Now, `fetch-pack` validates the reported pack hash against the advertised hash and only registers a `.keep` lockfile if the current process created it (tracked via a `created_keep` flag). This prevents race conditions where one process might overwrite another’s `.keep` file.

The implementation is clean and adopts Jeff King’s suggested `strbuf` refactor for clarity. The new test in `t/t5702-protocol-v2.sh` exercises the fix by simulating a packfile URI fetch with a pre-existing `.keep` file, verifying that the file is preserved and the pack is correctly registered. The patch is narrowly scoped to the packfile URI path and does not affect other fetch behaviors.

This is a well-motivated bugfix with thorough test coverage. The change is uncontroversial and aligns with the series’ goal of unifying the solution for packfile URIs and dumb HTTP. The series as a whole is now ready for serious review, with no open questions remaining.
