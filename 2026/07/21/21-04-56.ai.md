This is a platform-specific bugfix for the macOS fsmonitor backend. The patch addresses a performance regression introduced in 56cef9cb1a (April 2026), where the fsmonitor daemon could time out waiting for filesystem events even when the event stream was functioning correctly. On loaded macOS systems, this led to excessive lstat() calls and multi-second delays during `git status`.

The fix adds an asynchronous flush of pending FSEvents notifications immediately after creating the cookie file and before starting the timed wait. The flush is implemented only for the macOS backend (using `FSEventStreamFlushAsync`), while Linux and Windows backends receive no-op stubs. The change preserves the existing one-second timeout and behavior of other backends.

The commit message provides concrete performance data: on an M4 Max Mac with a 1M-entry index, the patch reduced timeouts from ~89% and ~81% of requests to zero, and eliminated nearly a million unnecessary lstat() calls during a single status operation. The patch is narrowly scoped to the fsmonitor daemon's cookie wait mechanism and does not affect other parts of Git.

Code changes are minimal and well-contained: 3 lines added to the core daemon logic, 1 line to the macOS compatibility header, 5 lines to the macOS listener implementation, and no-op stubs for other platforms. The patch appears technically sound, with proper consideration of locking constraints (the flush must not block because the listener callback acquires the same lock).
