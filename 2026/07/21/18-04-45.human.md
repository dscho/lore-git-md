This is a review exchange on Hugo Sales’s patch adding `--[no-]edit` to `git rebase --continue`. Junio C Hamano raises two main concerns.

The first is a philosophical objection: the feature encourages users to skip editing commit messages during rebase, which Junio sees as undermining the value of recording meaningful changes. He suggests the existing `GIT_SEQUENCE_EDITOR=: git rebase --continue` idiom already solves the immediate problem without adding new options.

The second concern is technical: the patch does not clearly handle edge cases where the rebase stops for reasons other than conflict resolution (e.g., an `edit` or `reword` instruction in an interactive rebase). Junio asks whether the new `rebase.noEdit` config would override the user’s explicit intent to edit the message in these scenarios, and whether the behavior would differ depending on whether a conflict occurred. He also notes the test coverage is limited to conflict-resolution scenarios and suggests expanding it to verify the interaction with interactive rebase instructions.

The tone is constructive but skeptical; Junio does not outright reject the idea but wants the author to address the edge cases and reconsider whether the feature is necessary. The ball is now in Hugo’s court to either revise the patch or defend the current design.
