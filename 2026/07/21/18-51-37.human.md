This is Junio C Hamano’s reply to Gatla Vishweshwar Reddy’s v9 patch converting `git show-branch` to use a commit-slab for per-commit state. The patch is a refactoring effort to eliminate reliance on the shared `object.flags` field, removing the previous 27-branch limit and aligning with Git’s canonical pattern for per-commit data storage.

Junio reports a critical regression: the simplest invocation (`git show-branch master next`) now crashes with a floating-point exception. The root cause is straightforward: the patch removes the `init_commit_name_slab(&name_slab)` call without moving it elsewhere, leaving the `name_slab` structure zero-initialized. When `commit_to_name()` later attempts to compute `c->index / s->slab_size`, it divides by zero, triggering the crash. The regression is not subtle—it breaks basic functionality—and the fix should be obvious: restore the initialization call or explain why it is no longer needed.

This crash undermines the claim that the author "took time to read through the code carefully." The patch has been through nine iterations, addressing behavioral regressions, performance issues, and documentation inconsistencies, but this fundamental oversight suggests the review process has not been as thorough as the commit message implies. The patch is technically sound in its slab conversion but is not yet ready for integration due to this preventable error. Gatla will need to send a v10 that either restores the initialization or provides a clear rationale for its removal. Until then, the patch remains under review with a known blocker.
