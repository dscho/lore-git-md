Core problem or goal
A measurable performance regression in server-side Git operations (pushes) was introduced in Git 2.54 by commit `8384cbcb4c`, part of the ODB abstraction rework. The regression manifests as excessive failing `open()` calls for loose objects across multiple ODB backends (quarantine and main object stores), particularly costly on NFS-backed deployments. The author hypothesizes that the lookup order for objects changed from a "pack-first, loose-second" strategy *per backend* to a "pack-loose, pack-loose" strategy *across backends*, causing unnecessary loose object checks even when objects exist in packs.

Current status
Reported; no fix proposed or merged. The regression is tied to a specific commit (`8384cbcb4c`) and affects downstream users (Atlassian Bitbucket on NFS). The thread is open and awaiting maintainer or ODB subsystem owner (Patrick Steinhardt) response to confirm the bisect result, discuss intended ODB lookup semantics, and evaluate whether the current behavior is a bug or an unintended side effect of the abstraction effort.
