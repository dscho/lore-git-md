This is a bugfix series (v3) targeting race conditions in Git's HTTP transport when multiple processes concurrently fetch the same packfile URI or dumb HTTP pack. The series is now split into three patches, with the first addressing a documentation cleanup requested during review, the second fixing the core race condition, and the third handling a related `.keep` file race.

The key improvement in v3 is the removal of append mode when writing to partial packfiles. Instead, each downloader opens the file in read-write mode, seeks to the current end, and writes using its own descriptor offset. This ensures overlapping responses write identical bytes at identical offsets, preventing corruption while preserving resumable downloads for both packfile URIs and dumb HTTP. The solution avoids cross-process coordination and handles edge cases like EOF-range requests (HTTP 416) and Windows-specific file-sharing behavior.

The series touches `http.c`, `fetch-pack.c`, and documentation, with thorough test coverage in `t/t5550-http-fetch-dumb.sh` and `t/t5702-protocol-v2.sh`. The tests now include a new regression test for unlinking the staging path while `index-pack` holds its descriptor, which works on MinGW. The commit messages are clear and the implementation looks clean, addressing feedback from Junio C Hamano and Jeff King (Peff) without introducing controversial changes.

This is a well-motivated fix for a real problem affecting users with concurrent Git processes (e.g., CI systems). The v3 reroll incorporates all prior feedback and should be ready for merging. If you work with Git's HTTP transport or packfile URIs, this series is worth reviewing.
