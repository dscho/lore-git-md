This is the first patch in the v2 series fixing race conditions in Git's HTTP daemon test helpers. It targets `t/lib-httpd/apply-one-time-script.sh`, replacing its non-atomic `test -f`/`rm` sequence with an atomic `mv` operation to claim a one-time marker file. The change eliminates a race window where concurrent HTTP requests (e.g., a partial fetch lazily retrieving a promisor object) could both pass the `test -f` check, then have one remove the marker while the other fails to execute it, resulting in an HTTP 500 error. The patch also adds per-request scratch files (using `$$` suffixes) to prevent clobbering between concurrent invocations.

The commit message clearly explains the observed failure mode (a flaky `t5616.47` on macOS CI) and the atomicity fix, while explicitly noting that the script may still run multiple times—only the rename is serialized, ensuring exactly one modified response is served. This distinction was a key point in Junio's v1 feedback, and the v2 commit message now addresses it directly. The new test `t5567-one-time-script.sh` forces the race deterministically using FIFOs, verifying that neither request emits an empty body and that each behaves as expected (one modified, one passthrough).

The patch is minimal, targeted, and unlikely to be controversial. It touches only test infrastructure (`t/` directory) and adds a new test to lock down the behavior. The atomic `mv` idiom is well-established in Git's codebase (e.g., lockfile machinery), and the commit message's clarity about the remaining race window (script execution, not marker consumption) makes the design intent unambiguous. The v2 looks ready for integration, with Junio's feedback fully addressed.
