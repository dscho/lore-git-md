This is the eighth patch in Johannes Schindelin’s twelve-patch bugfix series `js/coverity-fixes-v2`, addressing a NULL-dereference vulnerability in `revision.c`. The patch plugs a hole in `add_parents_only()`, a helper that resolves revision suffixes like `commit^@` (all parents) and `commit^!` (commit minus parents). The function calls `get_reference()` to peel through tag objects, but the existing NULL check only handled the `ignore_missing` case. In reality, `get_reference()` can return NULL in three distinct scenarios: when the caller asked to skip missing objects (`ignore_missing`), when the object is a lazy promisor object that should be excluded (`exclude_promisor_objects`), or when the caller wants to record missing OIDs for later reporting (`do_not_die_on_missing_objects`). The patch now explicitly handles all three cases, preventing a NULL dereference in the latter two.

The fix is straightforward: if `get_reference()` returns NULL, the code now checks which flag is set and returns 0 for `ignore_missing` or `do_not_die_on_missing_objects` (matching the behavior in `handle_revision_arg()` and `process_parents()`), and -1 for everything else (the `exclude_promisor_objects` case). The patch also adds a regression test in `t/t0410-partial-clone.sh` to ensure that `git rev-list --exclude-promisor-objects` handles `commit^@` gracefully when the underlying commits are missing. This test was requested by Junio in the v1 review and is now included in v2.

The change is purely defensive and does not alter normal behavior. The subsystems touched (revision walking and partial clone handling) are core, so the fix is likely to affect a broad range of operations. The patch is well-motivated, small, and focused, with a clear commit message that names the function and the specific NULL condition being addressed.
