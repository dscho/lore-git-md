Thread identity: Patch series (single patch) introducing a bugfix for `--autosquash` behavior in `git rebase` when `fixup!`/`squash!` commits cancel out their target, resulting in empty commits. Originating author: Farid Zakaria. Thread type: bug report and fix.

Core problem or goal: Fix a long-standing edge case in the sequencer subsystem where `fixup!` or `squash!` commits that cancel out all changes in their target commit are not handled according to the `--empty` option (`drop`, `keep`, or `stop`). Currently, Git halts the rebase with an error instead of respecting the user's `--empty` configuration.

Current status: Under review. This is the initial version (`v1`) of the patch. No prior versions or related series mentioned. Discussion is now focused on the design approach: the author's implementation (which treats `fixup!`/`squash!` commits as empty only if the target was already empty) versus Phillip Wood's proposed alternative (adding a new check to detect when applying a `fixup!` makes the target empty, preserving existing behavior for `fixup!` commits that become empty).

Key technical details:
- **Files touched**: `sequencer.c` (core logic), `Documentation/git-rebase.adoc` (user-facing documentation), `t/t3415-rebase-autosquash.sh` (test coverage).
- **Subsystems**: Sequencer (`--autosquash` logic), rebase.
- **New/renamed symbols**: None explicitly introduced; the patch modifies `is_index_unchanged()` and `allow_empty()` to use the correct parent commit when amending (i.e., during `fixup!`/`squash!` operations).
- **Behavior changes**:
  - `is_index_unchanged()` and `allow_empty()` now compare the index against `HEAD`'s parent (rather than `HEAD`) when amending, correctly identifying cases where the melded commit cancels out its target.
  - `allow_empty()` now classifies such commits as "became empty" (subject to `--empty` handling) unless the target was already empty.
  - When `--empty=drop` applies, the patch ensures the emptied commit is dropped by moving `HEAD` back to its parent before flushing the rewritten-commit list, preserving mappings for `--update-refs` and other consumers.
- **On-disk format changes**: None.
- **Test coverage**: New tests in `t/t3415-rebase-autosquash.sh` cover all three `--empty` modes (`drop`, `keep`, `stop`) for both `fixup!` and `squash!` scenarios, including edge cases like root commits and already-empty targets.
- **Open design questions**:
  - Whether to modify the existing emptiness check (author's approach) or add a new check (Phillip's alternative).
  - Correctness of dropping commits: Phillip notes the patch should remove the `rewritten-pending` file to avoid recording the commit as rewritten, and labels/`--update-refs` commands after the dropped commit will now see HEAD pointing to the dropped commit's parent.

Open questions and loose ends:
- The author raises an open question about adding a `revert!` autosquash directive in a follow-up, suggesting this patch is part of a broader effort to improve rebase ergonomics. Phillip Wood endorses this idea, proposing an empty marker commit to avoid conflicts.
- Phillip notes the current patch still requires a force-push, which could be automated with a `GIT_SEQUENCE_EDITOR` script.

Participant positions:
- **Farid Zakaria (author)**: Proposes the current patch, which treats `fixup!`/`squash!` commits as empty only if the target was already empty. Motivated by a real-world workflow at Meta (automatically dropping both a commit and its revert when `--empty=drop` is used).
- **Phillip Wood (reviewer)**: Substantive technical review. Disagrees with the implementation, arguing it breaks his workflow (where empty commits are used as placeholders and later `fixup!` commits may become empty). Proposes an alternative: add a new check to detect when applying a `fixup!` makes the target empty, preserving existing behavior for `fixup!` commits that become empty. Also raises correctness concerns about dropping commits (e.g., `rewritten-pending` file handling).

Related work:
- The patch is motivated by a real-world workflow at Meta, where internal LLVM patches are managed as single commits using `fixup!` autosquash. The fix enables automatic dropping of both an original patch and its revert when `--empty=drop` is used.
- No dependencies or prior versions mentioned. The patch is self-contained.
