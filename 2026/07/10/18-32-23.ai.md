This is a platform-compatibility bugfix targeting Cygwin, authored by Ramsay Jones. The patch addresses long-standing test failures in Git’s test suite on Cygwin that have persisted since the 2019 security releases (v2.23.1 and related). Those releases introduced stricter path validation to fix CVEs, but the changes inadvertently broke Cygwin’s handling of IPv6-style SCP URLs (e.g., `[::1]:repo`), which Cygwin treats as invalid paths because `[` is interpreted as a potential Windows drive letter.

The patch makes three key changes. First, it adds Cygwin-specific implementations of `is_valid_path()` and `offset_1st_component()` in `git-compat-util.h` that avoid misinterpreting IPv6 addresses as drive letters. Second, it removes a conditional in `connect.c` that was incorrectly treating Cygwin like Git for Windows (GfW) for certain URL parsing cases. Third, it reverts test skips in `t5500-fetch-pack.sh` and `t5601-clone.sh` that were added in 2024 to paper over the failures, restoring full test coverage for IPv6 URLs on Cygwin.

The patch is well-motivated: it fixes a five-year-old regression, restores a clean test suite on Cygwin, and avoids conflating Cygwin’s POSIX path handling with Windows-specific quirks. Ramsay notes that a more comprehensive solution might involve deeper Cygwin API integration, but this patch is a pragmatic first step. The changes are narrowly scoped to the URL parsing and path validation logic, with no behavior changes for other platforms. The patch looks ready for review and inclusion.
