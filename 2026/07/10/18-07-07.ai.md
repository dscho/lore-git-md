This is a **substantive review** of the final patch in Pablo Sabater’s v8 series implementing cascading indentation for visual roots in `` `git log --graph` ``. The reviewer, Mirko Faina, identifies a **real edge case** where the feature fails: when using `` `--author` `` (or presumably other filters that exclude commits without filtering their parents), visual roots are not indented because the logic in `` `graph_is_visual_root_candidate()` `` assumes parents are either present or explicitly filtered to NULL. In this case, the commit’s parents exist but are excluded by the filter, so the function incorrectly returns false.

The review traces the root cause to the interaction between `` `simplify_commit()` `` and `` `get_commit_action()` ``: the filter (e.g., `` `--author` ``) is only applied *after* the commit is enqueued, so the graph renderer cannot determine visual root status until the next commit is processed—by which point it is too late to indent. This is a **design-level oversight** in the lookahead buffer’s logic, not a superficial bug.

The series is otherwise technically sound and ready for merging, but this feedback reveals a **gap in test coverage** (no tests for `` `--author` `` or similar filters) and a **limitation in the visualization rules**. The patch’s assumptions about parent filtering are too narrow, and the reviewer’s analysis suggests the fix may require revisiting how visual root status is detected during the revision walk. This is likely to generate follow-up discussion about whether to expand the lookahead buffer’s role or adjust the filtering logic.
