This is a refactoring patch in its final review stage. Junio C Hamano’s reply to v2 of Gatla Vishweshwar Reddy’s patch flags two mechanical issues and one behavioral concern. First, the patch violates Git’s `-Wdeclaration-after-statement` rule by declaring variables (`struct apply_state state` and `const char *apply_argv[]`) after executable code; these must be moved to the top of the function. Second, Junio raises a correctness question about subdirectory operation: `apply_all_patches()` prepends `state->prefix` to the patch file path, but it is unclear whether `repo_git_path(repo, "ADD_EDIT.patch")` returns a relative or absolute path, and thus whether `git add -e` will work correctly when run from a subdirectory (e.g., `cd t && git add -e`). He requests a test to verify this behavior. The patch remains under review; the author will need to address these points before it can be queued.
