This is patch 6/11 of Justin Tobler’s ODB transaction refactoring series, now at v4. The patch changes `odb_transaction_begin()` to return an error code instead of a transaction pointer, allowing backends to signal setup failures (e.g., temporary directory creation errors). It introduces an `out` parameter for the transaction and adds `odb_transaction_begin_or_die()` as a convenience wrapper for call sites that cannot handle errors. The patch also updates all existing callers to handle the new error-returning interface, including `cache_tree_update()` and `add_files_to_cache()`, which now check for an inflight transaction before starting a new one.

The change is motivated by the upcoming use of ODB transactions in `git-receive-pack`, where silent failures are unacceptable. The patch is purely mechanical: it propagates errors that were previously ignored, but does not alter behavior. All call sites are updated to either handle errors explicitly or use the new `_or_die()` wrapper. The patch touches eight files, with the heaviest changes in `odb/transaction.c` (error propagation logic) and `object-file.c` (conditional transaction handling). It carries Patrick Steinhardt’s Reviewed-by from v3 and addresses Junio C Hamano’s safety concern about guarding the assignment to `odb->transaction` with a conditional pattern. No new issues are introduced; the patch is ready for integration.
