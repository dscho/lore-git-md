This is the ninth patch in the sixteenth iteration of a security-focused feature series that adds remote object metadata querying to `git cat-file --batch-command`. This specific patch enables servers to advertise their support for the `object-info` capability, allowing clients to discover what metadata (currently just object size) a server can provide before making queries.

The patch updates both the protocol documentation and the server implementation. In `gitprotocol-v2.adoc`, it clarifies several protocol details: requiring full object IDs (not short OIDs), fixing a parenthesis typo, explicitly defining the `obj-size` field format, and documenting that servers will return just the object ID (with no metadata) for unrecognized objects. The server-side change in `serve.c` modifies `object_info_advertise()` to populate the capability value with "size" when the feature is enabled, controlled by the new `transfer.advertiseobjectinfo` configuration (disabled by default).

The implementation follows the established pattern for Git protocol capabilities and maintains backward compatibility. The documentation improvements address prior review feedback about ambiguity in the protocol specification. This patch is a prerequisite for the client-side implementation that follows in later patches, enabling the dynamic capability-based validation that's central to the series' security design. The changes are minimal and focused, with no behavior changes beyond what's necessary for capability advertisement.
