This is the v4 submission of Justin Tobler’s 11-patch series converting `git-receive-pack` from `tmp_objdir` to ODB transactions, part of the ongoing ODB abstraction effort led by Patrick Steinhardt. The series is now functionally complete and addresses all feedback from prior rounds: the safety concern in `odb_transaction_begin()`, the error-handling gap in `odb_transaction_env()`, and the latent transaction-leak in `odb_transaction_commit()` are all fixed. The two deferred design questions—header coupling and explicit abort in error paths—remain slated for follow-up work, but neither blocks integration.

The core change is in patch 11/11, which replaces the global `tmp_objdir` in `builtin/receive-pack.c` with a local `struct odb_transaction *`. The transaction’s object directory serves the same quarantine purpose as the old temporary directory, preserving the existing behavior of staging objects in an “incoming” directory until pre-receive hooks and connectivity checks pass. Error handling is now consistent: all transaction interfaces return `int` and propagate failures, and the new `ODB_TRANSACTION_RECEIVE` flag ensures the “files” backend maintains `receive-pack`’s eager directory creation and naming conventions during the transition.

Patch 6/11 is the most critical fix: `odb_transaction_begin()` now guards the assignment to `odb->transaction` with a conditional (`if (!ret) odb->transaction = *out;`), preventing a potential dangling reference if the backend call fails. Patch 8/11 plugs the error-handling gap by propagating `odb_transaction_files_prepare()`’s return value, so a failed preparation (e.g., temporary directory creation) no longer pushes invalid environment variables to child processes. Patch 7/11 fixes the latent transaction-leak by clearing the transaction even on commit failure.

The series touches 14 files, with the heaviest changes in `object-file.c` (161 lines) and `builtin/receive-pack.c` (69 lines). Test coverage relies on the existing test suite, which exercises `receive-pack` and its child processes (`git-index-pack`, `git-unpack-objects`). Patrick Steinhardt’s v3 review explicitly cleared all remaining feedback (“the changes all look good to me”), and the series is queued for `next`. The only loose ends are deferred improvements (explicit abort interface, lazy directory creation, detangling object-write paths), none of which affect correctness or block merging.
