This is the resolution of a design question in the final patch of Justin Tobler’s eleven-patch series converting `git-receive-pack` from `tmp_objdir` to ODB transactions. The series is part of the ODB abstraction effort led by Patrick Steinhardt and is now functionally complete, with all prior feedback addressed.

Junio C Hamano’s review raised whether an explicit `odb_transaction_abort()` call should be added in error paths where `execute_commands()` returns early without committing the transaction. Justin agrees that an explicit abort would improve clarity and consistency, particularly for non-file-based backends that might not rely on `atexit()` cleanup. However, he defers the change to a follow-up series, noting that the current behavior (relying on `atexit()` cleanup) is functionally correct and matches the old `tmp_objdir` behavior. The deferral is pragmatic: the series is otherwise ready for integration, carries Patrick Steinhardt’s Reviewed-by on all patches, and the explicit abort is not a blocker.

The patch itself is a mechanical conversion of `builtin/receive-pack.c`, replacing the global `tmp_objdir` with a local `struct odb_transaction *` and updating all relevant functions (`unpack`, `unpack_with_sideband`, `execute_commands`, `set_connectivity_errors`, `run_receive_hook`) to accept the transaction as a parameter. The `ODB_TRANSACTION_RECEIVE` flag (introduced earlier in the series) preserves receive-pack’s quarantine semantics, ensuring objects are staged in an "incoming" directory until pre-receive hooks and connectivity checks pass. Error handling is consistent with the rest of the series: `odb_transaction_begin()` returns an error code, and `odb_transaction_commit()` propagates failures to the caller. Test coverage relies on the existing `receive-pack` test suite, which exercises the quarantine flow and child processes (`git-index-pack`, `git-unpack-objects`).
