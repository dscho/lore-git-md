This is the first patch in a v2 bugfix series targeting a race condition in Git's HTTP daemon test helpers. It fixes a real, observed flake in `t5616.47` on macOS CI runners, where concurrent HTTP requests to the same endpoint could cause the `apply-one-time-script.sh` CGI helper to fail with an HTTP 500 error.

The patch replaces the non-atomic `test -f`/`rm` sequence in `apply-one-time-script.sh` with an atomic `mv` operation to claim the "one-time-script" marker. This ensures that only one request's modified output is served, while losing requests fall back to the unmodified response. The fix is minimal and targeted, touching only the test infrastructure (`t/lib-httpd/apply-one-time-script.sh` and a new test, `t5567-one-time-script.sh`). The new test uses FIFOs to force the race deterministically, confirming that neither request emits an empty body (which would trigger HTTP 500) and that each behaves as expected.

The commit message is thorough and well-explained, explicitly addressing Junio C Hamano's feedback from v1: it clarifies that the atomic rename shrinks but does not eliminate the race window for concurrent script execution, and that the goal is not to prevent the script from running multiple times (which is safe) but to ensure only one request's modified output is served. The v2 also retains the existing locale behavior (forcing C locale only when modifying output) as a deliberate choice.

This patch looks well-crafted and ready for integration. It addresses a concrete problem without changing user-visible behavior, and the new test provides robust coverage for the fix. The atomic idiom (`mv`) is a clean solution that aligns with Git's existing lockfile machinery. No controversy or loose ends remain.
