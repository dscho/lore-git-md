This is a test infrastructure bugfix, part of a three-patch series (v2, patch 2/3) that eliminates race conditions in Git’s HTTP daemon test helpers. The series targets a real, observed flake in `t5616.47` on macOS CI runners, where concurrent HTTP requests to the same endpoint caused HTTP 500 errors due to non-atomic state management in the CGI scripts.

This patch makes the first-request check in `t/lib-httpd/http-429.sh` atomic by replacing the non-atomic `test -f` followed by `touch` with a single `mkdir`, which fails if the directory already exists. This ensures exactly one request is rate-limited, while the rest are forwarded to `git-http-backend`. The commit message and code comments now explicitly state that skipping state for the `"permanent"` case is required for correctness, not just an optimization, because the original create-then-remove pattern left a race window where a concurrent request could see the marker and be incorrectly forwarded.

The fix is minimal and targeted, touching only the test helper script. No regression test is included because the race cannot be forced deterministically, but the atomic `mkdir` idiom is a well-established pattern in Git’s test infrastructure (documented in patch 3 of the series). Junio C Hamano’s feedback from v1 has been fully addressed, and the patch looks ready for integration. The series as a whole is well-motivated and unlikely to be controversial.
