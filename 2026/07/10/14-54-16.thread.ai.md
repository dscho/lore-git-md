Subject: [PATCH] object-file: fix double-free in object stream error path
Series version: standalone patch (no series)
Originating author: Patrick Steinhardt
Thread type: bugfix

Core problem or goal
Fix a double-free regression in the object-file subsystem's stream handling, introduced in commit 10a6762719 (February 2026). The regression occurs when `stream_object_signature()` fails to read from an externally created stream, leaving a leftover `odb_read_stream_close()` call in the error path that triggers a double-free.

Current status
Under review. The patch is a clean, targeted fix (removes 4 lines, adds 1) with a new test case in `t/t1450-fsck.sh` verifying `git rev-list --verify-objects` detects hash mismatches when reading truncated loose blobs. Built on v2.54.0 (where the regression was introduced) and merges cleanly to master. No prior versions or related series.

Key technical details
- Files touched: `object-file.c` (removal of `odb_read_stream_close()` in error path)
- Subsystem: object-file (stream handling)
- New test: `t/t1450-fsck.sh` (verifies `git rev-list --verify-objects` detects truncated loose blobs)
- Symbols: `stream_object_signature()`, `odb_read_stream_close()`
- Behavior change: eliminates double-free in error path; no functional change to successful reads
- On-disk format: unchanged
- Test coverage: regression test for hash mismatch detection in truncated loose blobs

Open questions and loose ends
None. The patch addresses the specific issue, includes test coverage, and explains why the issue is not a security vulnerability (affected code paths don't operate on the transport layer, and corrupted packfiles are detected during reception).
