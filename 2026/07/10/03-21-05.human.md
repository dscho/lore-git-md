This is the fourth patch in Johannes Schindelin’s eleven-patch bugfix series addressing NULL-dereference issues identified by Coverity. The patch adds a simple guard in the reftable backend’s `stack_destroy` function to prevent passing a NULL filename to `open()` when `reftable_new_stack()` fails partway through initialization.

The fix is minimal (two lines added, one removed) and clearly motivated: if `st->list_file` is NULL, there are no table files to clean up, so skipping the `read_lines()` call is correct. Junio C Hamano’s review is brief but positive, calling the fix "well done" and implicitly endorsing it. This patch is uncontroversial and ready for integration; it addresses a real crash risk with a narrow, targeted change that does not alter normal behavior. The series as a whole remains well-structured and well-explained, with each patch tackling a specific edge case.
