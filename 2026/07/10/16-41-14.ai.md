This is a refactoring patch in the `remote-object-info` series, specifically patch 8/13 of v16. The patch moves variable initialization from the `FETCH_CHECK_LOCAL` state to the function prologue of `do_fetch_pack_v2()` in `fetch-pack.c`. The change is mechanical and preparatory: it ensures the variables (`allow_unadvertised_object_request`, `use_sideband`, and `args->deepen`) are set regardless of the initial state, which will become necessary when a later patch introduces an alternative initial state for the `remote-object-info` command.

The patch touches only `fetch-pack.c` and makes no behavior changes. The moved code block is identical before and after, and the commit message explains the rationale clearly: future work will reuse the state machine with a different starting state, so the initialization must happen before the switch statement. This is a small but necessary step in the series' larger goal of integrating `remote-object-info` into the fetch machinery.
