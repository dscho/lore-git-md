This is a v2 bugfix series targeting the test infrastructure, specifically the HTTP daemon test helpers. The series fixes race conditions in two CGI scripts (`apply-one-time-script.sh` and `http-429.sh`) that use non-atomic shell operations to manage shared state in `HTTPD_ROOT_PATH`. These races can cause HTTP 500 errors when Apache serves concurrent requests to the same endpoint, as observed in `t5616.47` on macOS CI runners.

The fixes replace the problematic `test -f` followed by `rm` or `touch` with atomic operations: `mv` for the one-shot marker in `apply-one-time-script.sh` and `mkdir` for the first-request election in `http-429.sh`. The series is self-contained, touching only the `t/` directory, and includes a new test (`t5567-one-time-script.sh`) that exercises the helper directly to force the race deterministically. Patch 3 documents these atomic idioms in `t/README`, linking to Git’s lockfile machinery and `make_symlink()` as precedents.

Changes since v1 address Junio C Hamano’s feedback on patches 1 and 2. The commit messages now clarify that the goal is to shrink the race window (not prevent concurrent script execution) and explicitly state that the atomic `mkdir` check in `http-429.sh` is required for correctness in all cases, including when `retry_after` is set to `"permanent"`. The locale inconsistency in `apply-one-time-script.sh` (forcing C locale only when modifying output) was retained as a potential future cleanup. The series looks well-crafted, with thorough commit messages and a clear motivation tied to a real, observed flake.

This is a narrow but important fix for test reliability. The changes are mechanical and unlikely to be controversial, as they address a concrete problem without altering user-visible behavior. The new test and documentation patch are strong additions that generalize the pattern for future test helpers. The series is ready for further review or integration.
