This is the second patch in Paulius Zaleckas' v3 series introducing configurable submodule fetch error handling. It adds the user-facing controls (`fetch.submoduleErrors` config and `--submodule-errors` CLI option) that let users opt into non-fatal behavior when `git fetch --recurse-submodules` encounters a submodule whose gitlink points to an unreachable commit.

The patch wires the new setting through the fetch machinery: it parses the config and CLI option, forwards the setting to child fetches (so it works with `--all`/`--multiple` and nested recursion), and routes all submodule fetch errors through `record_fetch_error()` so they honor the warn/fail policy. The default remains `fail` for full backwards compatibility. Documentation updates cover both the config key and the CLI option, and the test suite grows new coverage for the warn mode, error reporting, and edge cases (including inaccessible submodules and `--all` forwarding).

This patch depends on the correctness fix in 1/2, which restructured error handling to ensure transient failures do not prematurely abort the fetch. Together, the two patches address the long-standing pain point of disruptive submodule fetch failures in workflows where upstream topic branches are still in flux. The implementation is clean, the tests are thorough, and the series has already incorporated substantive feedback from the list.
