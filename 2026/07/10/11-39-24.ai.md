This is the **v2 cover letter** for the twelve-patch bugfix series `js/coverity-fixes-v2` by Johannes Schindelin, addressing NULL-dereference issues identified by Coverity. The series is a direct follow-up to the previously merged `js/coverity-fixes` and remains focused on defensive programming: adding guards to prevent dereferencing NULL pointers or using invalid file descriptors across eleven files in core and plumbing subsystems.

The v2 iteration incorporates all feedback from Junio C Hamano’s reviews of v1. The most significant change is in the `remote.c` patch: Dscho now agrees with Junio’s position that a NULL `remote` in `remote_tracking()` is a contract violation and should trigger `BUG()` rather than silently returning `-1`. The `bisect.c` patch (`bisect_successful()`) now returns the symbolic `BISECT_FAILED` constant instead of the raw `-1` from `error()`, addressing Junio’s maintainability concern. The `revision.c` patch (`add_parents_only()`) now includes a regression test (`t/t0410-partial-clone.sh`) to prevent future regressions, as requested. The `bisect.c` patch (`bisect_start()`) no longer claims the bug can be triggered with current code; instead, it clarifies that Coverity flags the leftover use of `head` after the outer `if (!head)` on a formal reading, and assigns the literal string `"HEAD"` as a safe fallback to satisfy the analyzer without changing behavior in any reachable code path. Finally, the series now includes a follow-up patch (12/12) that addresses Junio’s identified latent bug in `write_one_shallow()`: the use of `oid_to_hex()`’s rotating static buffer is replaced with a stack-allocated buffer and `oid_to_hex_r()` to ensure the string remains valid throughout the function.

The series remains uncontroversial and well-motivated. All patches are small, focused, and well-scoped, with clear commit messages naming the function and the specific NULL condition being addressed. No new user-visible behavior is introduced beyond error messages for edge cases. The subsystems touched (diff, remote, reftable, mailsplit, bisect, replay, revision, pack-bitmap, shallow) are core or lower-level plumbing, so the fixes are likely to affect a broad range of operations. The series is queued as GitGitGadget pull request `pr-2174` and is ready for final review and integration. Given the mechanical nature of the fixes and Dscho’s track record, this series looks like a straightforward merge candidate once Junio confirms the v2 updates address his feedback.
