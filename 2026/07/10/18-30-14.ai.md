This is a **substantive follow-up in the `--autosquash` bugfix thread**, advancing the design discussion for a potential `revert!` (or `drop!`) autosquash directive. Yuxuan Chen, a colleague of the original patch author Farid Zakaria, responds to Phillip Wood’s suggestion of using an empty marker commit to represent a `revert!` directive.

Yuxuan argues that an empty marker would be semantically misleading: until the rebase actually runs, the repository still contains the target commit’s changes, so the marker should reflect the intended removal by carrying the inverse patch. This aligns with how `git revert` works today—conflicts during revert signal real difficulties in undoing the change, and Yuxuan sees no reason to treat `revert!` differently. The message does not propose code or touch the existing patch; it is purely a design-level reply to Phillip’s workflow suggestion.

The exchange remains open: Phillip’s marker idea prioritizes conflict avoidance, while Yuxuan’s inverse-patch approach prioritizes semantic clarity and consistency with existing Git commands. Neither side has conceded, but the discussion now has a clear technical trade-off on record.
