This is the fourth patch in Patrick Steinhardt’s eight-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch restructures how Git opens pack bitmaps by iterating over object sources first, then attempting to load a bitmap for each source, rather than searching all sources for a multi-pack index bitmap followed by all sources for a packfile bitmap.

The change is a refactoring of `pack-bitmap.c` that reverses the loop order in `open_bitmap()` (formerly `open_bitmap_1()`). Previously, Git would first check all object sources for a multi-pack index bitmap, then check all packfiles for a packfile bitmap. Now, it iterates over each object source and tries to load either type of bitmap for that source before moving to the next. This makes it easier to open bitmaps for a specific source, which will be needed in a later patch.

The patch also slightly changes bitmap precedence in edge cases: if an earlier object source has only a packfile bitmap and a later source has a multi-pack index bitmap, the earlier source’s packfile bitmap now takes precedence. This is arguably an improvement, as it prefers local bitmaps over those in alternates. The commit message notes that repositories with multiple bitmaps are already considered broken (Git warns about them), so the change is not expected to cause issues.

The diffstat shows a net reduction in code (31 insertions, 38 deletions), reflecting the simplification. The new helper function `open_bitmap_for_source()` encapsulates the logic for opening a bitmap for a single source, improving clarity. No behavior changes are expected for end users, and the patch is well-motivated as a stepping stone toward ODB abstraction. It looks clean and uncontroversial, addressing a technical debt issue in the bitmap-handling code.
