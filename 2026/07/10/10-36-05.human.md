This is the final version of a two-patch bugfix series targeting a quadratic performance regression in Git’s reftable backend. The issue surfaces when many tombstoned (deleted) refs accumulate: operations like ref lookups or D/F conflict checks become O(n) per call because the merged iterator’s `suppress_deletions` flag forces a full scan of all tombstones before higher-level bounds checks can terminate iteration.

The fix moves tombstone suppression from the merged iterator to the reftable backend’s call sites, where prefix and refname bounds are available. This allows early termination when tombstones exceed the relevant bound, restoring O(1) behavior. To preserve compatibility with downstream users like libgit2, the `suppress_deletions` flag is now configurable via `struct reftable_stack_options` (defaulting to off). Libgit2 can still enable it at stack creation time, but Git itself no longer sets it, avoiding the regression.

The series includes a new perf test (`p1401-ref-store-tombstones.sh`) that measures two scenarios: recreating the same refs after deletion (quadratic behavior) and creating new, differently-named refs after deletion (worst-case tombstone sorting). Both scenarios now run in ~0.2s (down from ~13s), demonstrating the fix’s effectiveness. The test uses separate repositories for each scenario to ensure isolation.

Changes since v2 are minimal but important: the `suppress_deletions` flag was moved to `reftable_stack_options` (as suggested by Patrick Steinhardt) to future-proof the API while preserving libgit2’s current behavior. The series is narrowly scoped to the reftable backend, with no on-disk format changes or impact on other ref backends. All prior feedback—including test isolation and compatibility concerns—has been addressed.

This looks like a well-motivated, thoroughly tested fix for a real-world performance issue. The regression was observed in production-scale repositories (noted by brian m. carlson), and the solution is cleanly contained. The series appears ready for integration.
