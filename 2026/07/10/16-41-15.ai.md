This is the ninth patch in the sixteenth iteration of a security-hardened series implementing `git cat-file --batch-command` support for querying remote object metadata. This specific patch adds server-side capability advertisement for the `object-info` feature, allowing clients to discover what metadata (currently only object size) a server supports before making requests.

The patch updates both the protocol documentation and the implementation. In `gitprotocol-v2.adoc`, it clarifies several protocol details: requiring full object IDs (not short OIDs), fixing a parenthesis mismatch, explicitly defining `obj-size` as a numeric field, and documenting that servers return only the object ID (with no metadata) for unrecognized objects. The implementation in `serve.c` modifies the `object_info_advertise()` function to populate the capability value with "size" when the feature is enabled, controlled by the `transfer.advertiseobjectinfo` configuration (disabled by default).

This is a well-scoped, mechanical change that directly enables the client-side functionality introduced later in the series. The documentation improvements address prior review feedback about protocol clarity, and the implementation follows established patterns for capability advertisement. The patch maintains the series' security focus by keeping the feature disabled by default and clearly documenting server behavior for edge cases.
