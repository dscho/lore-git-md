This is a bugfix patch targeting the object-file subsystem, specifically fixing a double-free issue in object stream handling.

The patch addresses a regression introduced in commit 10a6762719 (February 2026) where `stream_object_signature()` was refactored to take an externally created stream rather than creating its own. While the refactoring removed one stream-close call, it missed a second one in the error path, leading to potential double-free when reading from the stream fails. The fix removes the leftover `odb_read_stream_close()` call in the error path.

The commit message explains why this wasn't treated as a security vulnerability: the affected code paths (`parse_object_with_flags()` and `verify_packfile()`) don't operate on the transport layer, and corrupted packfiles would be detected during reception. The patch includes a new test case in `t/t1450-fsck.sh` that verifies `git rev-list --verify-objects` properly detects hash mismatches when reading truncated loose blobs.

The patch is cleanly targeted at the specific issue, with minimal code changes (removing 4 lines, adding 1) and thorough test coverage. It's built on v2.54.0 where the regression was introduced and merges cleanly to master. Patrick Steinhardt is the author, with Jeff King credited for help.
