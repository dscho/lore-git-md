This is the v2 cover letter for Patrick Steinhardt’s eight-patch series introducing object filters to `odb_for_each_object()`. The goal remains the same: enable `git cat-file --batch-all-objects` to work with pluggable object databases by removing its dependency on internal details of the "packed" backend, particularly for efficient handling of bitmapped objects. This is a key step in the ongoing ODB abstraction effort.

The series now includes an additional patch (5/8) that drops the `_1()` suffix from functions that open bitmaps, a cleanup made possible by earlier refactoring. Other changes in v2 include a revised approach in `open_bitmap_for_source()` using a boolean flag instead of an integer for clarity, and improved commit message explanations. The final patch (8/8) now clearly states the problem upfront: `git cat-file --batch-all-objects` currently reaches into ODB internals and manually manages bitmaps, creating tight coupling between the command and backend details.

The diffstat shows a net reduction in code (171 insertions, 137 deletions), with the most significant changes in `builtin/cat-file.c` (76 lines removed) and `pack-bitmap.c` (129 lines modified). The series touches the ODB subsystem, packed backend, and pack-bitmap code, with key files including `builtin/cat-file.c`, `pack-bitmap.c`, `odb/source-packed.c`, and ODB interface headers. New or modified symbols include `open_bitmap_for_source()`, `prepare_bitmap_git_for_source()`, and a `filter` field in the `odb_for_each_object_options` struct.

Review feedback from v1 has been addressed, including clarifications on object lookup behavior, condition changes, and design questions about whether backends should be required to support a subset of object filters. Junio C Hamano praised the final patch in v1 as "very nice" and requested only a minor commit message improvement, which Patrick has incorporated. Justin Tobler’s substantive reviews on patches 1/7, 3/7, 4/7, and 6/7 have been resolved, with no remaining objections.
