This is the seventh patch in Johannes Schindelin’s twelve-patch bugfix series (`js/coverity-fixes-v2`), which systematically addresses NULL-dereference vulnerabilities identified by Coverity. This specific patch targets the `git replay` command’s `--onto` option: it adds a defensive check to ensure that the object passed to `--onto` actually peels to a commit. If the object exists but is a tree or blob (not a commit), the command now dies with a clear error message instead of silently proceeding with a NULL pointer.

The fix is small and surgical: in the `peel_committish()` helper function, the return value of `repo_peel_to_type()` is now checked for NULL before being cast and returned. The commit message explains the edge case (passing a non-commit OID to `--onto`) and credits Coverity for flagging the unchecked return. The change is purely defensive and does not alter normal operation when `--onto` points to a valid commit.

This patch is uncontroversial and well-motivated. It follows the same pattern as the rest of the series—adding explicit NULL guards to prevent latent crashes—and the commit message is clear and concise. The fix is ready for integration and looks like a straightforward merge candidate.
