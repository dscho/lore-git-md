This thread is about Paulius Zaleckas’s patch series that lets users configure whether `git fetch --recurse-submodules` should fail hard or just warn when a submodule’s gitlink points to an unreachable OID. The series is now at version 6, incorporating all review feedback—including Junio’s latest mechanical requests—and is technically complete.

The core change adds a new config key `fetch.submoduleErrors` (values `fail` or `warn`) and a corresponding CLI option `--submodule-errors=(fail|warn)`. The default (`fail`) preserves backwards compatibility, while `warn` allows workflows where upstream topic branches are still in flux without disrupting the entire fetch. The series also fixes a pre-existing logic flaw where phase-1 fetch failures were recorded prematurely, even if a later phase-2 OID-based fetch could still succeed.

Key participants include Paulius (the author), Junio (who reviewed earlier versions and requested mechanical improvements), Ramsay Jones (who noted a test portability issue now fixed), and Jean-Noël Avila (who contributed documentation fixes). The series has been marked as ready for `next` by the author but hasn’t seen maintainer action yet. Paulius’s recent ping is procedural, aimed at nudging the series forward without introducing new changes. No open questions remain, and the implementation is narrowly scoped to the submodule fetch path.
