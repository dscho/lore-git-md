This thread is about a patch series by Paulius Zaleckas that adds configurable error handling for `git fetch --recurse-submodules`. The series is now at version 5 and introduces a new configuration option, `fetch.submoduleErrors`, which can be set to `fail` (the default, preserving backwards compatibility) or `warn`. When set to `warn`, submodule fetch errors are reported but do not abort the parent fetch, enabling workflows where upstream topic branches reference submodule commits that are not yet available.

The series also fixes a pre-existing logic flaw in submodule fetch error handling, ensuring that errors are only recorded after all fetch phases have failed. Key participants include the author, Paulius Zaleckas, who has incorporated all feedback from prior reviews, and Junio C Hamano, the maintainer, who requested mechanical improvements such as case-sensitive config values and centralized parsing. These improvements, along with test portability fixes, have been implemented in version 5. Ramsay Jones and Jean-Noël Avila also contributed feedback, with the latter providing documentation fixes.

The series is technically complete, with no remaining open questions or design objections. It touches several files, including `submodule.c`, `builtin/fetch.c`, and documentation, and adds thorough test coverage. The implementation is robust, with centralized parsing logic and proper forwarding of the resolved setting to child fetches. The series is currently under review and awaits maintainer action to be queued for integration.
