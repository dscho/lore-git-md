Paulius Zaleckas's patch series to make submodule fetch errors configurable has reached its fourth iteration, addressing Junio C Hamano's earlier concern about CLI override propagation. The series introduces a new `fetch.submoduleErrors` configuration (and matching `--submodule-errors` CLI option) that lets users choose between failing hard (`fail`) or merely warning (`warn`) when a submodule's gitlink points to an unreachable OID. The default remains `fail` for backwards compatibility.

His feedback is purely technical—no design objections—and suggests using helper functions to centralize the mapping between enum values and their string representations. The changes are mechanical and wouldn't alter the patch's behavior, but they would make the code more maintainable. The series remains under review with no merge status change.
