This thread is about a patch series by Paulius Zaleckas that adds configurable error handling for `git fetch --recurse-submodules`. The series, now at version 6, lets users choose whether submodule fetch errors should fail hard (the default, for backward compatibility) or just warn, which is useful when upstream topic branches are still in flux. It also fixes a pre-existing logic flaw where phase-1 fetch failures were recorded prematurely, even if a later phase-2 fetch could still succeed.

The series is technically complete, with all review feedback addressed, including Junio Hamano’s latest mechanical requests (changing array indexing from `size_t` to `unsigned` and renaming the array to singular form). It touches `submodule.c`, `builtin/fetch.c`, documentation, and tests, introducing a new config key (`fetch.submoduleErrors`) and CLI option (`--submodule-errors=(fail|warn)`). The implementation centralizes parsing and option formatting, fixes case-sensitivity, and ensures the setting is forwarded correctly to child fetches. Test coverage includes new scenarios for warn mode, error reporting, and CLI override propagation.
