This is the v8 submission of Pablo Sabater’s feature series implementing cascading indentation for visual roots in `` `git log --graph` ``. The series now consists of four patches, up from three in v7, due to the addition of a new helper function in `revision.c` to ensure the lookahead buffer is populated consistently.

The core goal remains unchanged: visual roots (commits with excluded parents) are indented to avoid appearing vertically adjacent to unrelated commits, improving clarity in graph output. The architectural foundation—a two-slot lookahead buffer in `struct git_graph`—is also unchanged, but v8 addresses a subtle bug in v7 where the buffer was populated from different sources depending on whether `--max-count-oldest` was used, breaking tests in `t4202`. The new patch (2/4) introduces `next_commit_to_show()` to unify the source of commits for the lookahead buffer, ensuring deterministic behavior regardless of command-line options.

Patch 1/4 is the same test infrastructure cleanup from v7 (now merged). Patch 2/4 is the new helper function in `revision.c`, which replaces the problematic conditional guard (`!revs->max_count_stage && !revs->reverse_output_stage`) with a consistent source for commits. Patch 3/4 is the lookahead buffer implementation, now with `ARRAY_SIZE()` for maintainability and an assertion in `graph_pop_lookahead()` to verify buffer invariants. Patch 4/4 is the visualization logic, unchanged from v7 except for expanded test coverage (now including `--max-count` and `--max-count-oldest` scenarios).

The series is technically sound and addresses the last known edge case (inconsistent lookahead population). The new helper function is a minimal, targeted fix that preserves compatibility with Jeff King’s `revs->commits` removal and Kristofer Haugsbakk’s `kk/prio-queue-get-put-fusion` topic. Junio Hamano and Phillip Wood’s final review of the visualization logic (patch 4/4) is still pending, but the architectural and correctness issues appear resolved. The redundant-indentation edge case (marked NEEDSWORK) remains, but it is documented and deemed acceptable for now. This version is likely the last before merging.
