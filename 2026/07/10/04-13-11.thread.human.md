This thread is about a bugfix for `git rebase --autosquash` when `fixup!` or `squash!` commits cancel out their target, leaving an empty commit. Farid Zakaria authored the patch, which has evolved through four iterations (`v1`–`v4`) to address substantive feedback from Phillip Wood. The `v4` patch is now ready for merging, with Phillip’s latest review confirming it resolves all prior concerns—including correctness around dropping commits, preserving existing behavior for empty commits, and handling edge cases like mid-chain fixups and conflict resolution.

The fix touches the sequencer subsystem (`sequencer.c`), updates documentation, and adds comprehensive test coverage for all `--empty` modes (`drop`, `keep`, `stop`). It introduces a new function (`is_amended_head_empty()`) to detect when a `fixup!`/`squash!` empties its target commit and ensures the `--empty` option is respected, while preserving existing behavior for commits picked empty to begin with. Phillip’s review suggests minor tweaks to code organization, performance, and cleanup, along with one additional test case, but endorses the patch as merge-ready.

The only unresolved discussion is a potential follow-up feature: a `revert!` (or `drop!`) autosquash directive. Three competing designs are on the table—Phillip’s empty marker commit, Yuxuan Chen’s inverse-patch approach, and a middle-ground `git revert --drop` proposal—but consensus remains elusive. This debate is orthogonal to the current patch, which stands on its own.
