This thread is about a bugfix for `--autosquash` behavior in `git rebase`, where `fixup!` or `squash!` commits that cancel out their target commit are not handled according to the user’s `--empty` option (`drop`, `keep`, or `stop`). Instead of respecting the option, Git currently halts with an error. The original patch, authored by Farid Zakaria, has received substantive feedback from Phillip Wood, and a revised version (`v2`) is in the works to address his concerns.

The key technical change in `v2` will be a new check to detect when applying a `fixup!` makes the target commit empty, ensuring the `--empty` option is respected while preserving existing behavior for `fixup!` commits that become empty. The patch touches the sequencer subsystem, updates documentation, and adds test coverage for all `--empty` modes. Phillip Wood’s review highlighted correctness issues, such as handling the `rewritten-pending` file when dropping commits, which `v2` will address.

A secondary discussion has emerged about adding a `revert!` (or `drop!`) autosquash directive, sparked by Farid’s suggestion and Phillip’s proposal to use an empty marker commit. Yuxuan Chen, a colleague of Farid’s, argues that an empty marker would be semantically misleading, advocating instead for an inverse patch (like `git revert`) to reflect the intended removal. This design debate remains unresolved, with Phillip prioritizing conflict avoidance and Yuxuan prioritizing consistency with existing Git commands. The thread is still under review, with no merge status yet.
