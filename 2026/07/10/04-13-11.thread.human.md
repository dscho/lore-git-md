This thread is about a bugfix for `git rebase --autosquash` that handles the edge case where a `fixup!` or `squash!` commit cancels out all changes in its target, resulting in an empty commit. The issue has been a long-standing pain point: Git would previously halt the rebase with an error instead of respecting the user’s `--empty` configuration (`drop`, `keep`, or `stop`). Farid Zakaria, the patch author, is motivated by a real-world workflow at Meta where internal LLVM patches are managed as single commits using `fixup!` autosquash, and the fix enables automatic dropping of both an original patch and its revert when `--empty=drop` is used.

The patch is now in its fourth iteration (`v4`), incorporating substantive feedback from Phillip Wood. The core fix introduces a new check, `is_amended_head_empty()`, to detect when applying a `fixup!` or `squash!` empties the target commit, ensuring `--empty` is honored for such cases. The patch also tracks whether the target commit was originally picked with changes (via a new on-disk state in `$GIT_DIR/rebase-merge/fixup-target`), so only commits that *become* empty are subject to `--empty` handling. This preserves existing behavior for workflows that rely on empty commits as placeholders, addressing Phillip’s earlier concerns. The implementation handles edge cases like mid-chain fixups, root commits, and conflict resolution, and ensures that dropping a commit (when `--empty=drop` applies) correctly updates `HEAD` and cleans up the `rewritten-pending` file.

The patch touches `sequencer.c`, updates `Documentation/git-rebase.adoc`, and adds thorough test coverage in `t/t3415-rebase-autosquash.sh` and `t/t5407-post-rewrite-hook.sh`. It is narrowly scoped, well-tested, and uncontroversial, with all prior review feedback addressed. While the thread has expanded to discuss a potential `revert!` autosquash directive (with competing designs from Phillip Wood and Yuxuan Chen), that discussion remains unresolved and is orthogonal to this patch. The current fix is ready for merging and should improve rebase ergonomics for users who rely on `--autosquash`.
