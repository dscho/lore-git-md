This is the second patch in a two-patch series introducing new `includeIf` conditions for Git configuration: `worktree` and `worktree/i`. The patch adds support for matching Git configuration includes based on the realpath of the current worktree's working directory, which is useful in multi-worktree setups where the `.git` directory path (handled by existing `gitdir` conditions) is not always intuitive.

The implementation reuses the `include_by_path()` helper from the previous patch, passing the worktree path (obtained via `repo_get_work_tree()`) instead of the gitdir. The new conditions are documented with examples showing how they differ from `gitdir` and `extensions.worktreeConfig`, and the patch includes thorough tests covering bare repositories, multiple worktrees, symlinked paths, case sensitivity, early config reading, and non-repository scenarios.

The feature addresses a real gap in Git's configuration system: users working with multiple worktrees can now apply configuration based on the worktree's location rather than the `.git` directory path, which is especially cumbersome in linked worktrees. The commit message and documentation are clear and well-motivated, and the test coverage is comprehensive. This looks like a well-crafted, uncontroversial addition that should be of interest to anyone using Git's worktree feature.
