This is the fifth patch in Justin Tobler’s v4 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch propagates errors from the "files" transaction backend’s lifecycle functions (`prepare`, `begin`, `commit`) to callers, replacing silent failure with explicit error codes.

The changes are mechanical and focused: the three core functions (`odb_transaction_files_prepare`, `odb_transaction_files_begin`, `odb_transaction_files_commit`) now return `int` instead of `void`, and their callers are updated to handle the new return values. The patch touches four files: `object-file.c` (26 lines added, 8 removed), `object-file.h` (signature change), `odb/source-files.c` (simplified error handling), and `odb/transaction.h` (updated docstring for the `commit` callback). No behavior changes are introduced; the patch merely surfaces previously ignored errors (e.g., temporary directory creation failures) so callers can handle them.

The motivation is clear: the "files" backend can fail during transaction setup or teardown (e.g., `tmp_objdir_create` or `tmp_objdir_migrate` failing), and these failures were previously swallowed. The patch aligns the "files" backend with the ODB transaction subsystem’s design, which already expects error propagation. The changes are uncontroversial and carry forward Patrick Steinhardt’s Reviewed-by from v3. The patch is part of the larger ODB abstraction effort and is queued for `next`.
