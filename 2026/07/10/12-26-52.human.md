This is the first patch in Paulius Zaleckas’s v3 series making submodule fetch errors configurable. It is a bugfix targeting the submodule subsystem.

The patch fixes a long-standing logic flaw in recursive submodule fetches: when the initial ref-based fetch (phase 1) fails, Git immediately marks the entire operation as failed, even though a subsequent OID-based fetch (phase 2) might still succeed. The result is a false-positive failure that disrupts workflows where the missing commits are already present or can be retrieved by hash. The fix defers error recording until after the OID-based retry has run, ensuring the outcome reflects whether the commits were actually obtained.

The implementation extracts a small helper (`record_fetch_error()`) to centralize error reporting, routes all submodule fetch failures through it, and adds a new test that verifies a failed submodule fetch is still reported when the gitlinked commits happen to be present locally. The patch is clean, well-explained, and directly addresses the NEEDSWORK comment added in 2019. It lays the groundwork for the second patch, which introduces the configurable error policy, without changing user-visible behavior on its own.
