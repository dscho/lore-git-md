This is the core implementation patch for the `remote-object-info` command in the `git cat-file --batch-command` series. It adds the new subcommand that lets users query object metadata (currently just size) from remote repositories without downloading the full objects.

The patch introduces the `remote-object-info` command which takes a remote URL followed by one or more object IDs. Unlike the existing `info` command which processes objects one at a time, this new command batches multiple object queries into a single request to avoid network overhead. The implementation handles both regular and `--buffer` modes, with special logic to collect all object IDs before making the remote request.

Key technical details include:
- A 10,000-object limit per request to prevent denial-of-service attacks
- Strict input validation that rejects short object IDs (requiring full 40-character hashes)
- Support for all three transport protocols (git://, file://, http://)
- Integration with the existing batch-command infrastructure while maintaining its own request/response flow
- Comprehensive error handling for unsupported capabilities, malformed input, and protocol mismatches

The patch includes 680 lines of new tests in `t/t1017-cat-file-remote-object-info.sh` that verify:
- Basic functionality across all transport protocols
- Batch processing of multiple objects
- Buffer mode operation
- Null-delimited output
- Error cases (unsupported capabilities, malformed OIDs, missing objects)
- Protocol version requirements
- Filter placeholder restrictions

The implementation appears solid and well-tested, with careful attention to edge cases and security considerations. The command maintains Git's established patterns while adding the new remote-query capability.
