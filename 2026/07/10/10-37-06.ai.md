This is the third patch in Pablo Sabater’s **v8 series** implementing cascading indentation for visual roots in `` `git log --graph` ``. It introduces a **two-slot lookahead buffer** in ``struct git_graph`` to allow the graph renderer to peek ahead at the next two commits without relying on fragile peeking at unsimplified commits or ``rev_info`` internals.

The patch adds three new functions to ``graph.h`` and ``graph.c``: ``graph_pop_lookahead()``, ``graph_get_lookahead_room()``, and ``graph_push_lookahead()``. These manage the buffer, which is populated by ``get_revision()`` in ``revision.c`` via the unified ``next_commit_to_show()`` helper introduced in patch 2/4. The buffer ensures commits are fully simplified before inspection, fixing the v7 bug where lookahead population varied depending on command-line options like ``--max-count-oldest``. The patch also updates ``graph_is_interesting()`` to treat commits in the lookahead buffer as interesting parents, preserving correct graph topology.

The implementation is minimal and defensive: ``ARRAY_SIZE()`` is used for maintainability, and ``graph_pop_lookahead()`` includes a ``BUG()`` assertion to catch buffer corruption. The buffer is small (two commits) and deterministic, with timestamps tweaked in tests to ensure stable output. This patch is a prerequisite for the visualization logic in patch 4/4, which uses the buffer to determine whether the next commit is a visual root. The series is now technically complete, with all known edge cases addressed, and this patch is ready for final review.
