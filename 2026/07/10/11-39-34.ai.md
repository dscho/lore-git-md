This is the tenth patch in the `js/coverity-fixes-v2` series, a bugfix targeting the bisect subsystem. It addresses a potential NULL-dereference in `bisect_start()` where the variable `head`—resolved from `refs_resolve_ref_unsafe()`—could remain NULL even after falling back to `repo_get_oid("HEAD")`. While no current ref backend can trigger this edge case (both files and reftable backends fail consistently in both calls), Coverity flags the leftover use of `head` after the outer `if (!head)` check as a formal violation. The fix assigns the literal string `"HEAD"` as a safe fallback, satisfying the analyzer without altering behavior in any reachable code path. The patch is small (three lines added), well-explained in the commit message, and uncontroversial—it follows Junio’s feedback from the v1 review to clarify the edge case rather than claim it can be triggered today. No new tests are added, as the issue is latent and not reproducible with existing backends. This patch is part of the broader series’ goal of hardening Git against NULL-dereference vulnerabilities.
