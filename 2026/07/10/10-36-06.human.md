This is the first patch in a two-patch bugfix series targeting a quadratic performance regression in Git’s reftable backend. It adds a new performance test (`t/perf/p1401-ref-store-tombstones.sh`) that measures two real-world scenarios where tombstoned refs (deleted refs that leave behind records) cause slowdowns.

The test creates 8,000 refs, deletes them all to generate tombstones, then measures the time to either recreate the same refs or create new, differently-named refs. The second scenario is particularly pathological: when tombstones sort after the new refs, every creation operation scans all tombstones, making the operation O(n²). The test uses separate repositories for each scenario to ensure clean isolation and avoid interference.

This patch is purely test infrastructure—no code changes to Git itself. The test is narrowly scoped to the reftable backend and does not touch other ref backends. It is well-motivated, as the scenarios it measures are directly tied to the performance regression the series aims to fix. The test’s design (separate repositories, clear setup/teardown) reflects feedback from Patrick Steinhardt on earlier versions, and the scenarios align with real-world performance issues observed by brian m. carlson.

For a reader following the reftable backend, this patch signals that the series is addressing a measurable, production-relevant problem. The test will serve as a regression guard once the fix lands. No controversy or design questions remain; this is a straightforward addition to the perf test suite.
