This thread is about a targeted bugfix for a double-free regression in Git's object stream handling, introduced in February 2026. The issue surfaced in the `stream_object_signature()` function after a refactoring removed one stream-close call but left another in the error path, risking a double-free when reading from the stream fails. Patrick Steinhardt authored the fix, which removes the redundant close call and adds a test case to `t/t1450-fsck.sh` to verify that `git rev-list --verify-objects` correctly detects hash mismatches with truncated loose blobs.

The patch is minimal—just four lines removed and one added—and focuses solely on the regression, which affects `parse_object_with_flags()` and `verify_packfile()`. Jeff King assisted, and the commit message clarifies why this wasn’t treated as a security issue: the vulnerable code paths don’t touch the transport layer, and corrupted packfiles would be caught earlier. The fix is based on v2.54.0 (where the regression originated) and merges cleanly to `master`. There’s no indication yet of maintainer review or merge status, but the patch is ready for integration.
