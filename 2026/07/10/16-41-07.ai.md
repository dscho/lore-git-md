This is the first patch in the GSoC v16 series implementing `git cat-file --batch-command` remote object metadata support. It fixes a memory leak in the transport helper subsystem where `data->name` (allocated in `transport_helper_init()`) was not being freed when disconnecting a transport whose helper had not fully started.

The fix is straightforward: move `FREE_AND_NULL(data->name)` outside the conditional block so it executes unconditionally during disconnect. This matches the established pattern of ensuring all allocated resources are freed regardless of helper state. The change is minimal (one line moved) and addresses a clear correctness issue identified during review of the larger series.

This patch demonstrates the series' attention to memory safety, which has been a recurring theme in reviews. While small, it's an important foundational fix for the subsequent protocol implementation work. The leak would be most likely to manifest in edge cases where transport initialization fails or is interrupted, making it a subtle but real concern for long-running Git processes.
