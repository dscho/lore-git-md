This is the eighth patch in the twelve-patch `js/coverity-fixes-v2` bugfix series. It targets a NULL-dereference vulnerability in `revision.c`’s `add_parents_only()` function, which resolves revision suffixes like `commit^@` (all parents) and `commit^!` (commit minus parents). The patch explicitly handles all three NULL-return scenarios from `get_reference()`: `ignore_missing`, `do_not_die_on_missing_objects`, and `exclude_promisor_objects`. The first two cases return 0 (consistent with existing patterns in `handle_revision_arg()` and `process_parents()`), while the third returns -1, matching the caller’s expectation that any nonzero return is treated as “handled.” The patch also adds a regression test (`t/t0410-partial-clone.sh`) that verifies graceful handling of `commit^@` when the underlying commits are missing promisor objects.

The fix is narrow and well-scoped: it plugs a latent crash without altering user-visible behavior. The commit message clearly explains the three NULL-return paths and the rationale for each return value, making the change easy to review. The regression test is minimal but sufficient to prevent future regressions. This patch directly addresses Junio’s feedback from the v1 review, which requested a test to ensure the fix remains robust. The series as a whole remains uncontroversial and ready for integration.
