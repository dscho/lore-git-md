This is the final patch in Justin Tobler’s 11-patch v4 series converting `git-receive-pack` from `tmp_objdir` to ODB transactions. It replaces the last direct `tmp_objdir` usage with the new ODB transaction subsystem, completing the infrastructure refactoring for ODB-backend agnosticism.

The patch touches only `builtin/receive-pack.c`, swapping out `tmp_objdir` for `struct odb_transaction`. The quarantine flow remains identical: incoming objects are staged in a temporary "incoming" directory and migrated into the main object database only after the pre-receive hook succeeds. The ODB transaction now manages the primary and alternate object databases, but this is invisible to `receive-pack` itself—it only cares that the newly written objects are accessible.

Key changes are mechanical: `tmp_objdir_env()` calls become `odb_transaction_env()`, `tmp_objdir_migrate()` becomes `odb_transaction_commit()`, and the global `tmp_objdir` variable is removed. The patch also propagates the transaction through the connectivity-check and hook-invocation paths, ensuring child processes (`git-index-pack`, `git-unpack-objects`, hooks) see the staged objects. The `ODB_TRANSACTION_RECEIVE` flag (introduced in an earlier patch) ensures the "files" backend creates the directory eagerly and uses the "incoming" prefix, preserving the old behavior.

All prior feedback is addressed; the series carries Patrick Steinhardt’s Reviewed-by on every patch and is queued for `next`. This is a clean, uncontroversial refactoring that advances the ODB abstraction effort without changing user-visible behavior.
