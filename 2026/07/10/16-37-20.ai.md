This is the ninth patch in Justin Tobler’s v4 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It introduces `enum odb_transaction_flags` and the `ODB_TRANSACTION_RECEIVE` flag to preserve the receive-pack-specific behavior (eager directory creation and "incoming" prefix) while maintaining the ODB abstraction.

The patch adds a `flags` parameter to the transaction lifecycle functions (`odb_transaction_begin`, `odb_source_begin_transaction`, `odb_transaction_files_begin`) and updates all call sites to pass `0` (no flags) except where the new `ODB_TRANSACTION_RECEIVE` flag is needed. In the "files" backend, the flag triggers eager directory creation and switches the prefix from "bulk-fsync" to "incoming", matching the old `tmp_objdir` behavior. The change is mechanical: 13 files are touched, but the only functional difference is the conditional logic in `odb_transaction_files_begin`.

The commit message clearly explains the motivation (preserving receive-pack’s quarantine semantics) and the NEEDSWORK comment acknowledges the flag’s backend-specific nature, deferring a cleaner design to follow-up work. Patrick Steinhardt’s Reviewed-by from v3 is carried forward, and the patch is uncontroversial. The series remains on track for `next`.
