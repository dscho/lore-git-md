This is the final patch in Christian Couder’s three-part series introducing a `fromAccepted` option to `GIT_NO_LAZY_FETCH`. It implements the core functionality: when the environment variable is set to `fromAccepted`, Git will permit lazy fetching only from promisor remotes that both the server advertises and the client accepts via the "promisor-remote" capability in protocol v2.

The patch adds the new enum value `LAZY_FETCH_ACCEPTED`, updates the environment variable parser to recognize `fromAccepted`, and modifies the lazy-fetch logic to skip non-accepted remotes while emitting a one-time warning that some objects may still be unavailable. Documentation in `git-upload-pack.adoc` and `git.adoc` is updated to describe the new option, and a new test script (`t/t5710-promisor-remote-capability.sh`) verifies that the feature works as intended: lazy fetching succeeds when an accepted promisor remote exists and fails when none is accepted.

The implementation is clean and well-motivated. The commit message explains the security rationale clearly, and the code changes are minimal and focused. Test coverage is thorough, including negative cases (bogus values, no accepted remotes). This looks like a solid, uncontroversial feature that addresses a real need without breaking backward compatibility.
