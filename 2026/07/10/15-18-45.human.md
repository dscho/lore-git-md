This is the second patch in Harald Nordgren’s seven-patch v18 series implementing `git branch --delete-merged`, which is now complete and ready for merging. The series introduces a new `--delete-merged` subcommand with safety mechanisms like per-branch opt-out, `--dry-run` preview, and refined stacked-branch protection.

This patch refactors `delete_branches()` to use a flags-based API instead of boolean arguments (`force` and `quiet`). The change is preparatory: later patches will add new flags (`DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`, `DELETE_BRANCH_DRY_RUN`) to support the `--delete-merged` command. The patch is purely mechanical, splitting the flags back into boolean locals inside the function, so behavior is unchanged.

Phillip Wood’s review points out a minor but important issue: the patch introduces two sources of truth by modifying the `flags` variable later in the function while also extracting `force` and `quiet` into local booleans. This could lead to inconsistencies if the flags are passed to another function. He suggests replacing all uses of `force` and `quiet` with direct flag checks (`flags & DELETE_BRANCH_FORCE`, etc.) to maintain a single source of truth. This is a surface-level but necessary fix to avoid potential regressions.

The patch itself is well-contained, touching only `builtin/branch.c`, and the refactoring is clean. The issue raised is straightforward to address and does not affect the series’ overall readiness. Once fixed, this patch will solidify the API foundation for the core `--delete-merged` logic in patch 5/7.
