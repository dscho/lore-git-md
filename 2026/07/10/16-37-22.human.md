This is a brief follow-up in the ongoing performance optimization thread for Git's priority queue. René Scharfe responds to Kristofer Karlsson's note about potential further optimizations to the `sift_up()` helper, suggesting the same copy-based optimization could apply to `sift_down_root()`.

The observation is technical and forward-looking: both `sift_up()` and `sift_down_root()` currently use element swaps, which involve three writes per operation, but could be rewritten to use a single write by holding the moved element in a temporary variable and shifting parents or children down in bulk. René notes this could nearly halve the number of writes, though caching effects might reduce the actual performance gain. The comment is purely speculative—no code is proposed or tested—and is framed as a possible follow-up rather than a blocker for the current series.

This exchange does not alter the current status of the patch series, which remains under consideration for its hardware-dependent performance tradeoffs. It simply flags an additional optimization opportunity that could be explored later if the maintainer decides to merge the cascade-down optimization.
