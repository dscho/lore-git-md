This is a bugfix patch from Patrick Steinhardt targeting the object-file subsystem. It fixes a double-free bug in the object stream handling that was introduced in February 2026 (commit 10a6762719). The issue occurs when reading from an object stream fails: the function `stream_object_signature()` incorrectly closes the stream a second time, even though ownership of the stream's lifecycle was already transferred to the caller in the earlier refactoring.

The patch is small and surgical: it removes the redundant `odb_read_stream_close()` call in the error path. The commit message explains the rationale clearly and notes that the issue was reported to the security list but deemed not to be a remote-exploitable vulnerability. The fix includes a new test in `t/t1450-fsck.sh` that verifies the behavior when encountering a truncated loose blob, ensuring the error is detected and reported correctly.

This looks like a well-crafted, low-risk fix for a real bug. The test coverage is appropriate, and the commit message provides all the necessary context. The patch is built on v2.54.0 (where the bug was introduced) and merges cleanly to `master`. No controversy or follow-up discussion is evident from the email.
