This is the final patch in a three-part bugfix series targeting race conditions in Git's HTTP daemon test helpers. The series addresses a real, observed flake in `t5616.47` on macOS CI runners, where concurrent HTTP requests to the same endpoint caused HTTP 500 errors due to non-atomic state management in two CGI scripts (`apply-one-time-script.sh` and `http-429.sh`).

This patch documents the concurrency-safe idioms introduced in the earlier fixes, adding a new section to `t/README` titled "Writing concurrency-safe helpers". The guidance explains the problem (non-atomic shell operations like `test -f` followed by `rm` or `touch` can race when scripts run concurrently), the solution (atomic operations like `mkdir` for electing a winner and `mv` for consuming one-shot markers), and the rationale (citing Git's lockfile machinery and `make_symlink()` as precedents). It also notes the use of `$$` suffixes for per-request scratch files to prevent clobbering. The patch adds a brief pointer to this section in `t/lib-httpd.sh` to help future contributors avoid similar pitfalls.

The documentation is clear, concise, and well-motivated, tying directly to the fixes in patches 1 and 2. It generalizes the atomic idioms beyond the HTTP daemon context, making them available to any test helper that might run concurrently. Junio C Hamano called this patch a "nice finishing touch" in his review of v1, and no changes were requested or made in v2. The patch is unlikely to be controversial, as it merely documents established patterns without changing behavior. The series as a whole looks well-crafted and ready for integration, with all review feedback addressed.
