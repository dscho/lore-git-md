This is the core implementation patch for the `remote-object-info` command in the `git cat-file --batch-command` series. It adds the final user-facing functionality that allows querying object metadata (currently just size) from remote repositories without downloading the full objects.

The patch introduces the `remote-object-info` command which takes a remote URL followed by one or more object IDs. Unlike the existing `info` command which processes objects one at a time, `remote-object-info` batches multiple object requests to minimize network overhead. The implementation carefully maintains the existing batch-command workflow while adding special handling for the remote case: instead of processing each object individually, it collects all objects for a given remote, makes a single network request, then processes and prints the results.

Key technical aspects include:
- Input validation with strict limits (10,000 objects max, 8KB URL length)
- Support for all three transport protocols (git://, file://, http://)
- Integration with the existing `--buffer` mode
- Proper error handling for unsupported capabilities, malformed OIDs, and missing objects
- Memory management via the new `free_object_info_contents()` helper
- Comprehensive test coverage (680 lines) across all transport types and edge cases

The implementation shows careful attention to security and robustness, with input size limits, strict protocol version requirements, and proper cleanup. The command currently only supports `%(objectname)` and `%(objectsize)` placeholders, with clear documentation about this limitation and future extensibility.

This patch completes the series by providing the actual user-facing functionality that was prepared in earlier patches. The implementation is well-structured, with clear separation between the remote-specific logic and existing batch-command infrastructure.
