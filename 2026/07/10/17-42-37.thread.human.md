This thread is about a small but practical fix to `git rebase --autosquash`: when a `fixup!` or `squash!` commit cancels out all changes in its target, Git should respect the `--empty` option (keep/drop/stop) instead of always halting the rebase. Farid Zakaria posted the patch to address a real-world issue in Meta’s LLVM workflow, where empty commits after autosquash operations were causing unnecessary manual intervention.

The patch is now at version 2, incorporating feedback from Phillip Wood, who reviewed the first version and suggested improvements to edge-case handling and test coverage. The changes are localized to `sequencer.c` (where the logic checks for emptiness by comparing the index to the parent tree) and the test suite (`t/t3415-rebase-autosquash.sh`), with a minor documentation tweak to clarify the behavior. The fix is well-tested, including edge cases like fixups on already-empty commits, and doesn’t touch the on-disk format.

The only remaining feedback is a surface-level test-script hygiene note from Michael Montalbo: the patch uses bare `grep` and `! grep` in its tests, but the project is moving toward requiring `test_grep` and `test_grep !` for better error messages. This is a trivial change and doesn’t affect the patch’s logic or behavior. With Phillip Wood’s substantive feedback already addressed, the patch appears ready for merging once the test-script adjustment is made. No objections or open questions remain.
