This is the first patch in Patrick Steinhardt’s eight-patch series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. It targets an inefficiency and subtle correctness issue in the packed object database backend.

When enumerating objects with a specific prefix, the code currently uses the multi-pack index or individual packfiles to find objects, but then ignores the index-provided data for the actual object lookup, instead falling back to the generic `odb_source_read_object_info()` function. This forces a redundant index traversal and risks looking up an object in the wrong pack if it exists in multiple packs. The patch fixes this by using `packed_object_info()` directly with the index-provided pack and offset, eliminating the redundant lookup and ensuring the correct pack is used.

The change is small (15 lines, 8 insertions, 7 deletions) and focused: it replaces the generic lookup with a direct call to `packed_object_info()`, adds a missing `data->request` check to ensure the pack is populated, and renames the `store` variable to `source` for clarity. The commit message explains the problem and solution clearly, and the patch itself is mechanical and well-contained. This is a solid, low-risk improvement that paves the way for the rest of the series. No controversy or open questions remain from the v1 review.
