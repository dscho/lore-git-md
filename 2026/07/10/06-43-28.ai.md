This is a feature patch series (v8) introducing `includeIf worktree:<pattern>` and `worktree/i:<pattern>` conditions to Git’s config system. The series is now down to two patches after the author dropped the symlink-preserving worktree path implementation in response to Patrick Steinhardt’s feedback about architectural invasiveness and conflicts with his in-flight `ps/setup-split-discovery-and-setup` series.

The core functionality remains unchanged: users can conditionally include config files based on the working tree’s realpath-resolved location, which is particularly useful in multi-worktree setups where the `.git` directory’s location is not intuitive. The implementation reuses the existing `include_by_path()` helper (refactored from `include_by_gitdir()` in the first patch) and supports glob patterns, `~` expansion, and case-insensitive matching via the `worktree/i:` variant. The documentation now explicitly notes that symlink spellings may not match, as the condition currently resolves to the real path.

The v8 iteration addresses the two major blockers from v7: Patrick’s design concerns (by removing the symlink-preserving logic) and the `t1305` test failure in `seen` (by simplifying the series and avoiding the conflicting setup-side changes). The series is now rebased onto Git 2.55 and includes all prior test coverage for bare repositories, early config reading, and non-repository scenarios. The changes are confined to `config.c` and the test suite, with no new CLI options or on-disk format changes.

This version looks ready for integration, assuming no new objections arise. The trade-off (documented symlink limitation) is a pragmatic compromise to avoid blocking on Patrick’s larger setup-discovery refactoring. The series maintains its clear motivation and thorough test coverage, and the author has demonstrated responsiveness to review feedback.
