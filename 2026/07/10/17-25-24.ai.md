This is the second patch in Harald Nordgren’s v18 series implementing `git branch --delete-merged`, which refactors the branch deletion API to use flags instead of boolean arguments. The patch converts `delete_branches()` and its helper `check_branch_commit()` to use a single `unsigned int flags` parameter with enum values (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`), replacing the previous `force` and `quiet` booleans. The change is mechanical but introduces a maintenance risk: the `flags` variable is split into local booleans (`force`, `quiet`) within the function, creating two sources of truth. Phillip Wood identified this issue and recommended replacing all local boolean uses with direct flag checks (`flags & DELETE_BRANCH_FORCE`, etc.) to avoid future regressions.

Harald Nordgren acknowledges the concern and agrees to make the fix. The adjustment is straightforward and does not affect functionality, but it ensures the flags remain a single source of truth throughout the function. This patch is purely preparatory for the core `--delete-merged` logic in patch 5/7 and introduces no behavioral changes. The fix will resolve the maintenance risk before the series is merged, keeping the implementation clean and future-proof. The discussion here is narrow and focused, with no broader design questions remaining.
