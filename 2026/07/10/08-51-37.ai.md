This is the third and final patch in Christian Couder’s three-part feature series introducing a `fromAccepted` option to `GIT_NO_LAZY_FETCH`. It implements the core functionality: when `GIT_NO_LAZY_FETCH=fromAccepted`, Git will permit lazy fetching only from promisor remotes that both the server advertises and the client accepts via the "promisor-remote" capability in protocol v2.

The patch adds the new enum value `LAZY_FETCH_ACCEPTED` to the `allow_lazy_fetch` enum (introduced in patch 2), extends the environment variable parser to recognize `fromAccepted`, and modifies the `lazy_fetch_objects()` helper to emit a one-time warning when the mode is active. The new behavior is guarded by a static flag so users see the warning only once per session. Documentation in `git-upload-pack.adoc` and `git.adoc` is updated to describe the new option, and a new test script (`t/t5710-promisor-remote-capability.sh`) verifies that lazy fetching succeeds only when an accepted promisor remote exists, fails cleanly when none is accepted, and rejects invalid values like `bogus`.

The implementation is clean and well-scoped: it reuses the refactored promisor-remote logic from patch 1, leverages the enum conversion from patch 2, and adds thorough test coverage. The commit message and code both acknowledge the usability limitation of an environment variable and suggest a future configuration variable (`upload-pack.allowLazyFetch`) as a more user-friendly alternative.
