This is the second patch in Harald Nordgren’s v18 series implementing `git branch --delete-merged`, which is now feature-complete and ready for merging. The series refactors the branch deletion API to use flags instead of boolean arguments, preparing for the core `--delete-merged` command and future extensions like `--dry-run`.

This patch converts `delete_branches()` and its helper `check_branch_commit()` from separate `force` and `quiet` boolean parameters to a single `unsigned int flags` parameter with enum values (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is mechanical, but Phillip Wood identified a subtle maintenance risk: the function splits the `flags` parameter into local booleans (`force`, `quiet`) while also modifying the `flags` variable later (e.g., `flags |= DELETE_BRANCH_FORCE` for remote branches). This creates two sources of truth, which could lead to regressions if future changes assume the flags remain unchanged. Harald agrees with Phillip’s suggestion to replace all local boolean uses with direct flag checks (`flags & DELETE_BRANCH_FORCE`, etc.) to maintain a single source of truth.

The fix is straightforward and does not affect functionality, but it eliminates a potential future regression. This patch is otherwise clean, touching only `builtin/branch.c` and introducing no behavioral changes. The series remains ready for merging once this mechanical adjustment is applied. The discussion here is a minor but important refinement to ensure long-term maintainability.
