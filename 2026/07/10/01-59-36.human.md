This is a maintainer feedback message on a bugfix patch for Git's SSH signature verification.

Junio C Hamano raises a practical concern about the patch: the new hint message advising users to configure `gpg.ssh.allowedSignersFile` is printed unconditionally and cannot be disabled. If a user runs `` `git log --show-signature -100` ``, they will see the same hint 100 times, which would be annoying. The patch bypasses Git's standard `advise_if_enabled()` mechanism, which would normally allow users to suppress such messages.

Junio questions the real-world use case for running `` `git log --show-signature` `` without the allowed signers file configured. He acknowledges that cryptographic verification still has value even without identity validation (it guarantees the commit content hasn't been modified), but notes that users who rely on this might not want to maintain an allowed signers file and would likely want to suppress the repetitive hint. The feedback suggests the patch should either use the standard advice mechanism or reconsider whether the hint is necessary at all.

The message is thoughtful and constructive, focusing on user experience and Git's existing mechanisms for controlling output. No decision has been made yet, but the concern is clear and actionable.
