This is the second patch in Pablo Sabater’s **v8 series** implementing cascading indentation for visual roots in `` `git log --graph` ``. The patch introduces `next_commit_to_show()`, a helper function in `revision.c` that unifies how commits are fetched for display, regardless of whether they come from the normal revision walk or from the staged list used by `--max-count-oldest`.

The motivation is clear: in v7, the lookahead buffer was populated from different sources depending on the command-line options, which broke tests in `t4202`. This patch ensures the buffer always uses the same source, fixing that inconsistency. The helper is minimal and preserves existing behavior—it simply extracts the conditional logic that was already in `get_revision()` into a reusable function. The `--reverse` branch is intentionally excluded from the helper to avoid unintended side effects (setting `SHOWN` and `CHILD_SHOWN` flags).

The patch is well-motivated and directly addresses the last known correctness issue in the series. It’s a small, targeted change that doesn’t alter behavior but makes the code more robust for the lookahead buffer introduced in patch 3/4. The commit message clearly explains the problem, the solution, and the edge case (`--reverse`) that’s handled separately. This looks like a solid, uncontroversial step toward finalizing the series.
