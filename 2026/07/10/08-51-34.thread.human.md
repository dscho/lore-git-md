This thread introduces a new `fromAccepted` option for `GIT_NO_LAZY_FETCH`, allowing lazy fetching only from promisor remotes that both server and client agree on via the "promisor-remote" capability in protocol v2. Christian Couder posted the initial three-patch series (v1) to provide a security middle ground between disabling lazy fetching entirely and allowing it unrestricted.

The series refactors the lazy-fetching logic, converts an internal boolean to an enum, and implements the new mode, with tests covering the new behavior. However, brian m. carlson has raised a strong security objection: they argue that expanding lazy-fetching flexibility while Git's network code remains in C increases the attack surface for untrusted repositories, particularly in tooling outside Git's formal threat model. This principled stance—opposed to any additional lazy-fetching flexibility until network code is rewritten in a memory-safe language—poses a significant hurdle for the series. No other reviews or counterarguments have appeared yet, leaving the thread at an impasse. The series remains under review with no merge status reported.
