This thread introduces a new `fromAccepted` option for `GIT_NO_LAZY_FETCH`, allowing users to restrict lazy fetching to only those promisor remotes that both the server advertises and the client accepts via the "promisor-remote" capability in protocol v2. Christian Couder posted the initial three-patch series, with the first two patches covering refactoring and the third implementing the core functionality.

The feature is now fully implemented in the v1 series. When `GIT_NO_LAZY_FETCH=fromAccepted` is set, Git will permit lazy fetching only from mutually agreed promisor remotes, providing a security middle ground between disabling lazy fetching entirely and allowing it from any remote. The implementation touches the promisor-remote subsystem, updates documentation, and includes a new test script to verify the behavior. A one-time warning is emitted when the mode is active to alert users. The series acknowledges the usability limitation of using an environment variable and suggests a future configuration variable (`upload-pack.allowLazyFetch`) as a more user-friendly alternative.
