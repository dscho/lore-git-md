This thread is about a patch series (v2) by Christian Couder that replaces an earlier client-side proposal (`GIT_NO_LAZY_FETCH=fromAccepted`) with a server-side configuration variable, `uploadpack.lazyFetchTrusted`. The goal is to let server operators explicitly mark repositories as safe for lazy fetching, addressing security concerns about untrusted repositories triggering arbitrary code execution. The series is complete but misthreaded—all patches incorrectly reply to the v1 cover letter—and Junio C Hamano has asked for a resend with proper threading before further review proceeds.

Junio has now finished reviewing the series, providing feedback on all five patches. His earlier reviews raised substantive design and scalability concerns (patches 1/5 and 3/5) and lingering conceptual doubts (patch 4/5), but his final review of patch 5/5 is purely editorial, flagging minor documentation ambiguities and a typo. The unresolved security objection from brian m. carlson remains, though the server-side trust model directly addresses it. No other contributors have weighed in yet, and the series is still under review, not yet in Junio’s integration branches.

Christian has acknowledged the threading issue and agreed to resend the series. Once that’s done, the only remaining action items are addressing Junio’s documentation tweaks and deciding whether to incorporate his design suggestions (e.g., a callback-based API for `path_allowlist_apply()` or a streaming alternative for `lazy_fetch_objects()`). The core implementation and security model appear sound, but the series won’t move forward until the resend happens.
