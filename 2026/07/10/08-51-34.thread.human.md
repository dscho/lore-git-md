This thread is about Christian Couder’s v2 patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration to mark repositories as trusted for lazy fetching. The series aims to replace the earlier client-side `GIT_NO_LAZY_FETCH=fromAccepted` proposal by shifting trust decisions to server operators, modeled after Git’s `safe.directory` mechanism.

The series is now complete with five patches: three refactorings (consolidating lazy-fetch logic, generalizing allowlist checks, and adding an `allow_dot` parameter to `path_allowlist_apply()`), the core implementation of `uploadpack.lazyFetchTrusted`, and the final patch wiring the trust check into `cmd_upload_pack()`, setting `GIT_NO_LAZY_FETCH=0` for trusted repositories, and adding documentation and tests. The series remains under review, with no merge status reported, and the high-weight security objection from brian m. carlson—though addressed by the server-side design—still unresolved.

The only new development is a procedural critique from Junio C Hamano: the v2 series is misthreaded. While the cover letter correctly replies to the v1 cover letter, each individual patch (1/5–5/5) also replies to the v1 cover letter instead of the v2 cover letter, breaking the expected thread structure. Junio notes this isn’t typical of `git send-email` or GitGitGadget and asks whether Christian used custom settings, providing a step-by-step example of how to correctly thread a patch series. No technical feedback on the feature itself has emerged yet.
