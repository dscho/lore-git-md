This thread is about a patch series from Christian Couder that replaces an earlier client-side proposal (`GIT_NO_LAZY_FETCH=fromAccepted`) with a server-side mechanism (`uploadpack.lazyFetchTrusted`) to let repository operators mark which repositories are safe for lazy fetching. The goal is to address security concerns about untrusted repositories triggering arbitrary code execution via lazy-fetch hooks or configuration.

The series is currently at version 2 but is misthreaded—all patches incorrectly reply to the v1 cover letter rather than the v2 one. Junio C Hamano has asked for a resend with correct threading, which Christian has agreed to do. The series is still under review and not yet in any integration branch. One high-weight security objection from brian m. carlson remains unresolved but is mitigated by the server-side trust model.

The latest email is a review from Junio of the first patch, which refactors the allowlist-checking logic from Git’s `safe.directory` machinery into a reusable helper. Junio’s feedback is purely stylistic—he suggests a minor naming tweak for clarity but raises no technical concerns. The patch itself is uncontroversial and preparatory, setting up the groundwork for the series’ core functionality. No other substantive reviews have been posted yet for the refactoring or integration patches. The series is waiting on the resend before further review proceeds.
