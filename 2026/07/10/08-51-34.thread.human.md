This thread is about a patch series (v2) by Christian Couder that replaces an earlier client-side proposal (`GIT_NO_LAZY_FETCH=fromAccepted`) with a server-side mechanism for controlling lazy fetching. The goal is to address security concerns by letting server operators explicitly mark repositories as trusted for lazy fetching, modeled after Git’s `safe.directory` configuration.

The series is now complete with the fifth and final patch, which implements the core behavior: when a repository is listed in the protected `uploadpack.lazyFetchTrusted` configuration, `upload-pack` sets `GIT_NO_LAZY_FETCH=0` in its environment, enabling lazy fetching for itself and its child processes. The patch ensures that an explicit `GIT_NO_LAZY_FETCH=1` from the environment overrides the trust setting, preserving security boundaries. Documentation is updated in `git-upload-pack.adoc`, `git.adoc`, and `Documentation/config/uploadpack.adoc`, and a new test script (`t/t5710-promisor-remote-capability.sh`) verifies the security model and precedence rules.

The first four patches (refactorings and configuration logic) remain unreviewed, but the final patch ties everything together with minimal, focused changes. The unresolved security objection from brian m. carlson—whether the server-side trust model sufficiently mitigates risks—remains the key open question, though the series now provides the mechanism for operators to make that decision. The series is still under review and not yet merged.
