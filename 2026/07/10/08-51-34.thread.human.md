This thread is about a patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration variable that lets operators mark repositories as trusted for lazy fetching—a security-conscious replacement for an earlier client-side proposal (`GIT_NO_LAZY_FETCH=fromAccepted`). The series is in its initial version (v1), with a v2 resend planned to fix a mechanical submission issue.

The core idea is to shift trust decisions entirely to the server operator, modeled after Git’s `safe.directory` configuration. This addresses the security objection that untrusted repositories could exploit lazy fetching to trigger arbitrary code execution. The series refactors promisor-remote and setup code, introduces a new protected configuration variable, and integrates it into `upload-pack`. Default behavior remains unchanged (lazy fetching disabled), and the new configuration is opt-in.
