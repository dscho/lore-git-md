This thread is about a patch series by Christian Couder that replaces an earlier client-side proposal (`GIT_NO_LAZY_FETCH=fromAccepted`) with a server-side mechanism (`uploadpack.lazyFetchTrusted`) to let operators explicitly mark repositories as safe for lazy fetching. The goal is to address security concerns about untrusted repositories triggering arbitrary code execution via lazy-fetch hooks or configuration, shifting trust decisions entirely to the server operator.

The series is now at version 2, though it was misthreaded—all patches incorrectly reply to the v1 cover letter instead of the v2 one. Junio C Hamano has confirmed the issue (caused by incorrect use of `--in-reply-to` with `git format-patch`) and asked for a resend with proper threading (`--no-chain-reply-to`). Christian has acknowledged this and agreed to resend. The series remains under review, with no merge status reported; it hasn’t been picked up in `seen`, `next`, or `master`.

Junio has provided substantive feedback on earlier patches (design and scalability in 1/5, API design in 3/5) and a minor naming suggestion in 2/5. His review of this fourth patch is surface-level: he finds the implementation reasonable but questions the broader soundness of using a configuration variable for this purpose. The unresolved high-weight security objection from brian m. carlson remains relevant but is mitigated by the server-side trust model. No other substantive reviews have been posted yet. The next step is the resend with correct threading, after which further review can proceed.
