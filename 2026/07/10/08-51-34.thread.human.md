This thread is about a patch series from Christian Couder that adds a `fromAccepted` option to `GIT_NO_LAZY_FETCH`, allowing lazy fetching only from promisor remotes that both the server and client agree on via the "promisor-remote" capability in protocol v2. The goal is to provide a middle ground between disabling lazy fetching entirely and allowing it unrestricted, improving security while maintaining usability.

The initial v1 series is under review, with all three patches available. However, it faces a significant security objection from brian m. carlson, who argues that the series expands the attack surface by allowing more network-facing C code to execute in untrusted repositories, potentially weakening security guarantees for tooling outside Git's formal threat model. Christian has responded by pushing back on the characterization of increased risk, noting that `fromAccepted` is more restrictive than the existing `GIT_NO_LAZY_FETCH=0` (which disables all lazy-fetch protections) and does not change defaults. He acknowledges the security concern but argues that server operators should be responsible for marking repositories as trusted, proposing future improvements like server-side configuration and repository scanning tools. The thread remains unresolved, with brian's objection still unaddressed in substance, and Christian plans to improve documentation in the next revision to clarify security considerations. No other substantive technical reviews have been posted yet.
