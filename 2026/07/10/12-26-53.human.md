This is the second patch in Paulius Zaleckas’s two-patch v3 series introducing configurable submodule fetch errors. It adds the user-facing controls (`fetch.submoduleErrors` config and `--submodule-errors` CLI option) that let users opt into non-fatal behavior when a submodule’s gitlink points to an unreachable commit.

The patch is clean and well-motivated: it builds on the correctness fix in patch 1/2, preserves backwards compatibility by defaulting to `fail`, and forwards the setting to child fetches so it works with `--all`, `--multiple`, and nested recursion. The documentation is clear, the tests are thorough (covering config, CLI, `--all`, and edge cases like inaccessible submodules), and the implementation is straightforward—routing all submodule fetch errors through `record_fetch_error()` so they honor the new policy. No obvious loose ends remain; this looks ready for `next`.
