This is the third patch in Justin Tobler’s 11-patch v4 series converting `git-receive-pack` from `tmp_objdir` to ODB transactions. The series is part of the larger ODB abstraction effort led by Patrick Steinhardt, and this patch is a pure refactoring with no behavior change.

The patch inlines the logic of `flush_loose_object_transaction()` directly into `odb_transaction_files_commit()`. The old helper function was misleadingly named—it did more than just flushing, including migrating the temporary object directory into the primary ODB and clearing the transaction’s `objdir` field. By embedding this logic into the commit function, the code now more accurately reflects what is actually happening: a full transaction commit, not just a flush. The change also prepares for future work where the temporary directory will stage packfiles as well as loose objects.

The diff is mechanical: 36 lines of the old helper are removed, and 28 lines of equivalent logic are added to `odb_transaction_files_commit()`. The only functional difference is the restructuring of the conditional check—`if (transaction->objdir)`—which is now explicit at the start of the commit function rather than hidden inside the helper. This makes the control flow slightly clearer without altering the fsync or migration behavior.

The patch carries Patrick Steinhardt’s Reviewed-by from v3, and the series as a whole is queued for `next`. There are no open questions or deferred items specific to this patch; all prior feedback has been addressed. If you are following the ODB abstraction effort, this is a straightforward step toward backend-agnostic object staging.
