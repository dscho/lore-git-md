This is the final patch in the `js/coverity-fixes-v2` series, a bugfix targeting a latent issue in the shallow commit handling code. The patch addresses a subtle but real risk in `write_one_shallow()`: the function currently relies on `oid_to_hex()`'s rotating static buffer, which means the returned string pointer is only valid until the next call to `oid_to_hex()` in the same thread. While this is safe today, any future edit that adds another `oid_to_hex()` call between the assignment and the last use of the `hex` variable would silently corrupt the output. The fix replaces the static buffer with a stack-allocated buffer and uses `oid_to_hex_r()` to ensure the hex string remains stable throughout the function.

The patch is small (three lines added, one removed) and touches only `shallow.c`. It is purely defensive and introduces no behavior change or new user-visible output.
