This is the sixth patch in Patrick Steinhardt’s eight-patch v2 series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch introduces `prepare_bitmap_git_for_source()`, a function that opens a bitmap exclusively for a single object source, addressing a critical limitation in the current `prepare_bitmap_git()`: its indiscriminate selection of the first available bitmap across all sources.

The new function ensures that bitmaps are correctly attributed to their source, preventing three specific problems: objects from one source being incorrectly associated with another, misattribution of object source info, and redundant bitmap enumeration across multiple sources. This is a preparatory step for the "packed" ODB backend to use bitmaps for object filtering, a key goal of the series. The implementation is minimal—12 lines in `pack-bitmap.c` and 2 in `pack-bitmap.h`—and leverages existing helpers (`open_bitmap_for_source()` and `load_bitmap()`) to avoid code duplication.

The patch is well-motivated and directly addresses a technical gap identified in the series’ cover letter. It builds on the refactoring in earlier patches (notably patch 4/8’s `open_bitmap_for_source()`) and sets the stage for patch 8/8, which will integrate object filters into `odb_for_each_object()`. No behavioral changes are introduced yet, but the foundation is now in place for the backend to safely use bitmaps during object enumeration. The design choice to allow backends to ignore unsupported filters (consistent with Git’s existing patterns) was previously debated and resolved in favor of this approach.

Review feedback from v1 (specifically Justin Tobler’s question about whether backends should be required to support a subset of filters) has been addressed, and the patch appears uncontroversial. The commit message clearly explains the problem and solution, and the code itself is straightforward. This is a clean, incremental step in the ODB abstraction effort, with no obvious pitfalls.
