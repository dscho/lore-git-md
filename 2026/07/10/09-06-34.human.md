This is the core implementation patch of Harald Nordgren’s `git history squash` feature, now in its eighth iteration. The patch adds a new subcommand that folds a commit range into its oldest commit while preserving descendant history, addressing all prior feedback and technical concerns.

The implementation centers on `builtin/history.c`, introducing the `squash` subcommand with robust input validation and merge handling. Key components include `resolve_squash_range()`, which parses and validates revision ranges (rejecting single-commit ranges, empty ranges, and ranges with multiple bases), and `reject_dangling_fixups()`, which ensures `fixup!`, `squash!`, and `amend!` commits are only folded if their target is within the range. The patch also sanitizes `rev-list` options to prevent silently incorrect results, a critical fix from v7.

Merge commit handling is carefully designed: the command rejects ranges with external parents but allows fully contained merges, using `--ancestry-path` to ensure only commits descended from the base are included. By default, the command refuses to proceed if any ref points to a commit inside the squashed range, with an advice message guiding users to `--update-refs=head` to rewrite only the current branch.

The test suite (`t/t3455-history-squash.sh`) is comprehensive, covering range parsing, merge handling (including nested and octopus merges), ref safety, authorship preservation, and edge cases like below-range fixups.
