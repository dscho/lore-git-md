This is the fourth patch in Patrick Steinhardt’s eight-patch v2 series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch refactors the bitmap-opening logic in `pack-bitmap.c` to iterate over object sources first, then attempt to load a bitmap for each source, rather than searching all sources for a multi-pack index bitmap and then all sources for a packfile bitmap. This change is mechanical and preparatory, enabling a later patch (6/8) to open bitmaps for a single source.

The refactoring replaces the two separate functions `open_midx_bitmap()` and `open_pack_bitmap()` with a single `open_bitmap_for_source()` helper that tries both multi-pack index and packfile bitmaps for a given source. The outer loop in `open_bitmap()` now iterates over object sources, calling `open_bitmap_for_source()` for each. This reverses the previous precedence: local packfile bitmaps now take precedence over multi-pack index bitmaps in alternates, which the commit message argues is an improvement since local sources are preferred.

Taylor Blau’s review is brief but substantive, agreeing with the design and the behavior change. He endorses the new precedence as a positive step, noting that the existing behavior (prioritizing multi-pack index bitmaps regardless of source) should be considered broken. The review does not raise any concerns or suggest further changes, and the tone is supportive. This patch appears uncontroversial and well-aligned with the series’ goals.
