Thread identity: Patch series replacing the `GIT_NO_LAZY_FETCH=fromAccepted` proposal with `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable to mark repositories as trusted for lazy fetching. Series version: v2 (complete but misthreaded, pending resend). Originating author: Christian Couder.

Core problem or goal: Provide a server-side mechanism for operators to explicitly declare which repositories are safe to lazy-fetch from, addressing the security objection that untrusted repositories could trigger arbitrary code execution via lazy-fetch hooks or configuration. The new approach shifts trust decisions entirely to the server operator, modeled after Git’s `safe.directory` configuration, and is intended as a replacement for the earlier client-side `fromAccepted` proposal.

When the served repository is trusted and `GIT_NO_LAZY_FETCH` was not explicitly set by the caller, `upload-pack` sets `GIT_NO_LAZY_FETCH=0` in its environment, enabling lazy fetching for itself and its `pack-objects` child process. The configuration is read from protected files only, and relative paths are rejected.
