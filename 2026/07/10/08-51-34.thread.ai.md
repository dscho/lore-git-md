Thread identity: Patch series introducing a `fromAccepted` option to `GIT_NO_LAZY_FETCH` to allow lazy fetching only from mutually agreed promisor remotes. Series version: initial (v1). Originating author: Christian Couder.

Core problem or goal: Extend `GIT_NO_LAZY_FETCH` from a boolean (disable all lazy fetching) to support a `fromAccepted` mode, enabling lazy fetching only from promisor remotes that both the server advertises and the client accepts via the "promisor-remote" capability in protocol v2. This provides a security middle ground between full disablement and unrestricted lazy fetching.

Current status: Under review (initial v1 posted). All three patches (1/3 refactoring, 2/3 enum conversion, 3/3 core functionality) available. No merge status reported; series is not in `seen`, `next`, or `master`. The series now faces a high-weight security objection from brian m. carlson that may block progress unless addressed.

Key technical details:
- Files touched: promisor-remote subsystem (`promisor-remote.c`, `promisor-remote.h`), `setup.c`, documentation (`git-upload-pack.adoc`, `git.adoc`), new test script (`t/t5710-promisor-remote-capability.sh`).
- New behavior: `GIT_NO_LAZY_FETCH=fromAccepted` permits lazy fetching only from promisor remotes negotiated via the "promisor-remote" capability.
- On-disk format: No changes.

- Test coverage: New test script (`t/t5710-promisor-remote-capability.sh`) validates `fromAccepted` behavior, promisor-remote capability negotiation, and rejection of invalid values.
