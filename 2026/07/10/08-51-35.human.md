This is the first patch in a three-part feature series introducing a `fromAccepted` option to `GIT_NO_LAZY_FETCH`. The series aims to allow lazy fetching only from promisor remotes that both the server and client agree on, providing a security middle ground between full disablement and unrestricted lazy fetching.

This patch is a pure refactoring of the promisor-remote subsystem. It extracts the lazy fetching logic from `fetch_objects()` and `promisor_remote_get_direct()` into a new `lazy_fetch_objects()` function. The refactoring consolidates the `GIT_NO_LAZY_FETCH` check to run once up front instead of once per promisor remote, which may improve performance. It also converts `try_promisor_remotes()` to return a `bool` instead of an `int` for clarity, since it only indicates whether all objects were fetched.

The changes are observably equivalent to the current behavior, with two minor shifts: the environment variable check now happens once, and `promisor_remote_init()` is no longer called when lazy fetching is disabled (which is safe since nothing downstream needs it in that case). The patch prepares the codebase for the `fromAccepted` option introduced in patch 3 by separating the fetching logic from error handling and validation.

The refactoring looks clean and well-motivated, with clear commit message explanations and no apparent behavior changes. It’s a sensible foundation for the feature work that follows. No review feedback has been posted yet, but the patch appears ready for technical scrutiny.
