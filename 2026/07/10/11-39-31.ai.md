This is the seventh patch in the `js/coverity-fixes-v2` series, a bugfix targeting the `replay.c` subsystem. The patch addresses a NULL-dereference vulnerability in the `--onto` code path of `git replay`: when `peel_committish()` is called with an object that exists but cannot be peeled to a commit (e.g., a tree or blob OID), the function returns NULL, which would then be dereferenced as a commit. The fix adds an explicit NULL check and calls `die()` with a descriptive error message if the object does not peel to a commit.

The change is minimal and focused: the `peel_committish()` helper now stores the return value of `repo_peel_to_type()` in a local variable, checks it for NULL, and dies if the object is not a commit. The commit message clearly names the function, the Coverity-flagged issue, and the edge case (non-commit objects passed as `--onto`). No new user-visible behavior is introduced beyond the error message; normal operation is unchanged.

This patch is part of the broader series’ goal of eliminating NULL-dereference vulnerabilities across core and plumbing subsystems. The fix is uncontroversial and aligns with the series’ defensive programming approach. The v2 iteration incorporates all feedback from Junio C Hamano’s review of the v1 series, and the patch itself was not singled out for any specific feedback, suggesting it is ready for integration. The `replay` command is relatively new, so the edge case is unlikely to have been encountered in production, but the fix is still a clear correctness improvement.
