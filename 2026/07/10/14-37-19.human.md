This is the final patch in Justin Tobler’s eleven-part refactoring series that replaces `tmp_objdir` with ODB transactions in `git-receive-pack`. The patch itself is a straightforward mechanical conversion: it removes the global `tmp_objdir` variable, introduces a local `struct odb_transaction *`, and updates all call sites to use the new transaction interfaces (`odb_transaction_begin`, `odb_transaction_commit`, `odb_transaction_env`). The quarantine semantics are preserved—objects are staged in an "incoming" directory until pre-receive hooks and connectivity checks pass—and the behavioral change is non-regressive.

Junio C Hamano’s review raised a **substantive design question** about error paths: if `unpack_with_sideband()` fails, `execute_commands()` returns early without committing or explicitly aborting the transaction. While the `atexit()` handler will clean up the temporary directory (matching the old `tmp_objdir` behavior), Junio asked whether an explicit `odb_transaction_abort()` call is warranted for clarity, consistency, or to handle non-file-based backends that might not rely on `atexit()` cleanup. Justin agrees that an explicit abort would be cleaner and plans to add it in a follow-up series, deferring the change to keep this patch focused.

The series as a whole is **well-reviewed and functionally complete**. All prior feedback—including mechanical cleanups, error-handling improvements, and design observations—has been addressed, and Patrick Steinhardt (the ODB subsystem owner) explicitly stated that all requested changes look good. The only remaining work is follow-up cleanup (e.g., error-handling improvements, explicit abort interface, lazy directory creation), which does not block integration. This patch is effectively ready to merge once the discussion about explicit abort in error paths concludes.

For a busy reader, this is a **refactoring** patch that advances the ODB abstraction effort. It touches `builtin/receive-pack.c` and the ODB transaction layer, replacing `tmp_objdir` with a more structured interface while preserving existing behavior. The open question is minor and deferred, so the patch is a safe, incremental step toward backend-agnostic object storage.
