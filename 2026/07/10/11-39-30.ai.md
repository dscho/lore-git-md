This is the sixth patch in the twelve-patch `js/coverity-fixes-v2` bugfix series. It targets a NULL-dereference edge case in `bisect_successful()` (`builtin/bisect.c`), where the commit returned by `lookup_commit_reference_by_name()` is passed unchecked to `repo_format_commit_message()`, which dereferences it. The fix adds a NULL guard: if the commit is NULL, the function now returns `BISECT_FAILED` (the symbolic constant) instead of propagating the error code `-1` from `error()`, addressing Junio C Hamano’s maintainability feedback from the v1 review. The edge case is rare but plausible: the ref could become dangling due to concurrent gc or repository corruption, even though `bisect_successful()` is only called after a successful bisect run. The patch is purely defensive and does not change normal operation. It is uncontroversial and ready for integration.
