This is the seventh patch in Justin Tobler’s 11-patch series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The series is part of the larger ODB abstraction effort led by Patrick Steinhardt, and this patch specifically addresses a latent robustness issue: `odb_transaction_commit()` now propagates errors from the backend commit callback, allowing callers (such as `git-receive-pack`) to detect and handle failures like filesystem errors during temporary object directory migration.

The change is straightforward: the commit callback signature is updated to return an `int` error code, and `odb_transaction_commit()` forwards this value to the caller. The patch also clears the transaction’s internal state even on failure, fixing a transaction-leak that was identified in review. No behavior changes are introduced—this is purely about surfacing previously ignored errors. The patch touches only two files (`odb/transaction.c` and `odb/transaction.h`) and carries Patrick Steinhardt’s Reviewed-by from earlier iterations.

This patch is uncontroversial and directly responds to feedback from v3. It is a necessary precursor to the later patches in the series that make `git-receive-pack` care about commit failures. The series as a whole is now functionally complete, with all prior feedback addressed, and is queued for `next` pending integration. If you are following the ODB abstraction work, this is a small but important step toward backend-agnostic object staging.
