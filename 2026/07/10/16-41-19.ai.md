This is the final patch in the GSoC v16 series implementing `git cat-file --batch-command`'s `remote-object-info` feature. It replaces the static allow-list for format placeholders with dynamic capability-based filtering, ensuring clients only request metadata that servers actually support.

The patch makes the placeholder validation system fully dynamic by mapping server-advertised capabilities (like "size" or "type") to their corresponding format atoms ("objectsize", "objecttype"). The implementation now checks what the server supports before making requests, then populates `remote_allowed_atoms` with only the placeholders that correspond to supported capabilities. This future-proofs the design for when servers start advertising additional metadata like object types.

Key changes include:
- Moving `object_info_options` out of `get_remote_info()` so callers can specify which metadata to request
- Adding a `remote_atom_map` that connects protocol options to format atoms
- Populating `remote_allowed_atoms` based on what the server actually supports
- Ensuring empty output lines when all placeholders are unsupported (maintaining compatibility with existing Git patterns)
- Adding "type" to the supported options in preparation for future server support

The implementation is clean and well-structured, with proper memory management (including clearing `remote_allowed_atoms` in cleanup) and comprehensive error handling. The backward iteration when filtering capabilities is a particularly nice touch to avoid element-skipping during removal.

This patch completes the series by making the placeholder validation system fully dynamic while maintaining all the security and compatibility properties established in earlier patches. The design successfully balances flexibility for future extensions with strict validation of what servers actually support.
