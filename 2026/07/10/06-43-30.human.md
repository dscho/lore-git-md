This is a feature patch introducing new `includeIf` conditions for Git's configuration system. The patch adds `worktree` and `worktree/i` keywords, allowing users to conditionally include configuration files based on the realpath of the current worktree's working directory. This is particularly useful in multi-worktree setups where the `.git` directory path (`gitdir`) is not intuitive for per-worktree configuration.

The implementation reuses the existing `include_by_path()` helper and handles edge cases like bare repositories (where it never matches), early config reading (where the repository isn't yet initialized), and symlinked worktree paths (which are resolved to their real paths). The patch includes thorough documentation and comprehensive tests covering bare repos, multiple worktrees, symlinks, case sensitivity, and non-repository scenarios.

This is the second patch in a v8 series, suggesting it has undergone significant review and iteration. The feature addresses a real gap in Git's configuration system, offering a more flexible alternative to `extensions.worktreeConfig` for users who want location-based configuration without per-worktree setup. The implementation looks clean, well-tested, and thoughtfully documented—worth attention from anyone working with multi-worktree setups.
