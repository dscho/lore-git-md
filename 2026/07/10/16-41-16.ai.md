This is the core client-side implementation patch in the GSoC v16 series that adds `remote-object-info` support to Git. Patch 10/13 introduces the `fetch_object_info()` function and integrates it into the transport layer, enabling clients to query object metadata (currently just size) from v2 servers without downloading full objects.

The implementation follows the established pattern of separating protocol logic into dedicated files (`fetch-object-info.c` and `fetch-object-info.h`). The new `fetch_object_info()` function handles the complete client-side workflow: verifying server support for the `object-info` capability, constructing and sending the request, and parsing the response. It strictly enforces protocol v2, returning an error for older protocols. The request construction mirrors the approach used in `fetch-pack.c`, writing the entire request into a buffer before sending.

Key technical details include the dynamic capability check (`server_supports_v2("object-info")`), the use of `parse_object_size()` for safe size parsing, and careful memory management for the size pointers in the response. When servers return empty strings for unrecognized objects (per protocol spec), the function sets the corresponding size pointer to NULL, allowing callers to detect and handle these cases. The implementation also includes proper stateless RPC handling and error checking throughout.

The transport layer integration adds a new vtable entry (`fetch_object_info`) and implements it for both the smart transport and transport-helper backends. This design keeps the object-info logic separate from the existing fetch infrastructure while following Git's established patterns for extensibility. The patch maintains the series' security focus through strict protocol enforcement, input validation, and careful memory handling.
