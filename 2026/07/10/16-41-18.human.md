This is the twelfth patch in the sixteenth iteration of a security-hardened feature series that adds `remote-object-info` support to `git cat-file --batch-command`. The patch implements runtime validation of format placeholders for remote object queries, replacing the previous static `strstr()` check with a proper allow-list.

The patch addresses two critical issues in the existing implementation: (1) uninitialized `data->type` values causing segmentation faults when remote servers return incomplete data, and (2) the `strbuf_expand_bad_format()` die() call blocking local queries when shared formats contain unsupported atoms. The solution introduces a static array of supported atoms (`remote_object_info_atoms`) and validates each placeholder against this list when operating in remote mode. Unsupported atoms now return empty strings, matching `for-each-ref`'s behavior for known-but-inapplicable atoms.

Key improvements include:
- Initializing `data->type` to `OBJ_BAD` and adding a NULL check for `type_name()` to prevent crashes
- Adding an `is_remote` flag to `struct expand_data` to distinguish between local and remote operations
- Updating documentation to clarify that unsupported placeholders return empty strings rather than raising errors
- Modifying tests to expect empty strings instead of die() behavior for unsupported atoms
- Adding explicit test coverage for empty string returns on unknown placeholders

The implementation is careful about memory safety and follows Git's established patterns for handling format placeholders. The patch maintains backward compatibility while providing a more robust foundation for future extensibility of the `remote-object-info` command. All changes are localized to `builtin/cat-file.c` and the associated test file, with no impact on other subsystems.
