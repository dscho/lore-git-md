Subject: [PATCH] Cygwin: fix IPv6-style SCP URL handling regression
Series version: standalone patch
Originating author: Ramsay Jones
Thread type: bugfix

Core problem or goal
Fix a five-year-old regression on Cygwin where stricter path validation introduced in the 2019 security releases (v2.23.1) misinterprets IPv6-style SCP URLs (e.g., `[::1]:repo`) as invalid paths because `[` is treated as a potential Windows drive letter. The regression causes test failures in `t5500-fetch-pack.sh` and `t5601-clone.sh` and has been papered over with test skips since 2024.

Current status
Under review. The patch is a standalone bugfix with no prior versions. It restores full test coverage on Cygwin by reverting the 2024 test skips and adds Cygwin-specific implementations of `is_valid_path()` and `offset_1st_component()` in `git-compat-util.h` to avoid misinterpreting IPv6 addresses. A conditional in `connect.c` that incorrectly treated Cygwin like Git for Windows for URL parsing is also removed. No merge status reported; no maintainer decision yet.

Key technical details
- Files touched: `git-compat-util.h` (Cygwin-specific path validation), `connect.c` (URL parsing logic), `t5500-fetch-pack.sh` and `t5601-clone.sh` (test coverage restoration).
- New/renamed symbols: Cygwin-specific `is_valid_path()` and `offset_1st_component()` implementations.
- Behavior change: IPv6-style SCP URLs are now correctly parsed on Cygwin without being misinterpreted as drive letters; no changes for other platforms.
- On-disk format: none.
- Test coverage: restores previously skipped IPv6 URL tests on Cygwin.

Open questions and loose ends
