Thread identity
Subject: [PATCH] Cygwin: fix IPv6-style SCP URL handling regression
Series version: standalone patch (v2 likely)
Originating author: Ramsay Jones
Thread type: bugfix

Core problem or goal
Fix a five-year-old regression on Cygwin where stricter path validation introduced in the 2019 security releases (v2.23.1) misinterprets IPv6-style SCP URLs (e.g., `[::1]:repo`) as invalid paths because `[` is treated as a potential Windows drive letter. The regression causes test failures in `t5500-fetch-pack.sh` and `t5601-clone.sh` and has been papered over with test skips since 2024.

Current status
Under review. The patch is a standalone bugfix with no prior versions. It restores full test coverage on Cygwin by reverting the 2024 test skips and adds Cygwin-specific implementations of `is_valid_path()` and `offset_1st_component()` in `git-compat-util.h` to avoid misinterpreting IPv6 addresses. A conditional in `connect.c` that incorrectly treated Cygwin like Git for Windows for URL parsing is contested: Torsten Bögershausen objects to its removal, citing UNC path breakage on Git for Windows. No merge status reported; no maintainer decision yet.

Key technical details
- Files touched: `git-compat-util.h` (Cygwin-specific path validation), `connect.c` (URL parsing logic), `t5500-fetch-pack.sh` and `t5601-clone.sh` (test coverage restoration).
- New/renamed symbols: Cygwin-specific `is_valid_path()` and `offset_1st_component()` implementations.
- Behavior change: IPv6-style SCP URLs are now correctly parsed on Cygwin without being misinterpreted as drive letters; no changes for other platforms. UNC path support on Git for Windows must be preserved.
- On-disk format: none.
- Test coverage: restores previously skipped IPv6 URL tests on Cygwin.

Open questions and loose ends
- Whether to remove or modify the `#ifdef DUMMY` block in `connect.c`. Torsten’s review argues removal would break Git for Windows UNC path support (commit `ebb8d2c90fb0`). Ramsay’s earlier suggestion to replace `#ifdef DUMMY` with `#ifdef GIT_WINDOWS_NATIVE` remains a possible resolution.
- No deeper Cygwin API integration is blocking the current fix, but it remains a potential future improvement.

Participant positions
- Ramsay Jones (author): submitted the patch as a narrowly scoped fix for a long-standing regression. Proposed removing the `#ifdef DUMMY` block in `connect.c` but later suggested replacing it with `#ifdef GIT_WINDOWS_NATIVE` to preserve Git for Windows UNC support.
- Torsten Bögershausen (reviewer): substantive review engaging with behavior and prior work. Objects to removing the `#ifdef DUMMY` block, citing UNC path breakage on Git for Windows. Position: the conditional must be preserved or replaced with a Windows-native guard, not removed.

Related work
- Regression originates from the 2019 security releases (v2.23.1).
- UNC path support on Git for Windows introduced in commit `ebb8d2c90fb0` (2018).
