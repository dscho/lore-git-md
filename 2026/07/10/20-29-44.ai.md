This is the fourth and final patch in Pablo Sabater’s v8 series implementing cascading indentation for visual roots in `` `git log --graph` ``. The patch introduces the core visualization logic, including a new ``GRAPH_PRE_ROOT`` state, indentation depth tracking, and cascading behavior for adjacent visual roots. It builds on the lookahead buffer infrastructure introduced in earlier patches (now merged or under final review) and includes extensive test coverage in ``t4218-log-graph-indentation.sh``.

The email is a reply to Mirko Faina’s **substantive review**, which identified a **design-level oversight**: the current implementation fails to indent visual roots when using filters like ``--author`` because ``graph_is_visual_root_candidate()`` assumes parents are either present or explicitly filtered to NULL. In reality, filters like ``--author`` exclude commits *after* enqueuing (via ``simplify_commit()`` and ``get_commit_action()``), leaving parent pointers intact. This means the function incorrectly returns false, and the lookahead buffer cannot detect the visual root until the next commit is processed—too late to indent.

Pablo acknowledges the issue and proposes a fix: iterating over each parent and calling ``graph_is_interesting()`` (which internally uses ``get_commit_action()``) to determine if the parent is excluded by the filter. This would generalize the logic to handle filters like ``--author`` and ``--grep``, which currently break the feature. The fix is straightforward but requires careful testing to ensure it does not introduce regressions in other scenarios (e.g., boundary commits, merge parents, or octopus merges). Pablo has not yet implemented or tested the change, so its effectiveness remains unproven.

The patch is otherwise technically sound, with robust test coverage for edge cases like ``--max-count``, ``--first-parent``, and octopus merges. The lookahead buffer (introduced in patch 3/4) ensures deterministic behavior, and the visualization logic is compatible with ongoing work like Jeff King’s removal of ``revs->commits`` and Kristofer Haugsbakk’s ``kk/prio-queue-get-put-fusion`` topic. However, Mirko’s feedback reveals a **critical gap in test coverage**: no tests exist for filters like ``--author`` or ``--grep``, which are now known to break the feature. This oversight must be addressed before the series can proceed.

The series is **under active review** and not yet ready for ``next``. Junio Hamano and Phillip Wood’s final reviews of patches 2/4 and 3/4 are pending, but the primary blocker is now this edge case. The proposed fix is plausible but needs validation, and the test suite must be expanded to cover the newly identified failure mode. The thread is likely to continue with a v9 addressing these issues.
