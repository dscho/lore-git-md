This is the v2 revision of a test infrastructure bugfix series that makes two CGI helper scripts in `t/lib-httpd/` concurrency-safe. The series targets a real, observed flake in `t5616.47` on macOS CI runners, where concurrent HTTP requests to the same endpoint caused a race condition in the scripts' state management, leading to HTTP 500 errors. The fixes replace non-atomic shell operations (`test -f` followed by `rm` or `touch`) with atomic ones (`mv` for one-shot markers, `mkdir` for first-request election), eliminating the race window.

The v2 updates address Junio C Hamano's feedback from v1, clarifying the commit messages and code comments to distinguish between shrinking the race window (achieved) and preventing concurrent script execution (not the goal). For `apply-one-time-script.sh`, the commit message now explicitly states that the script can and should run multiple times, with the atomic rename ensuring only one modified response is served. For `http-429.sh`, the commit message and code comment now make clear that skipping the `mkdir` check for `"permanent"` mode is required for correctness, not just an optimization, as the original code's create-then-remove pattern left a race window. The v2 also retains the existing locale behavior in `apply-one-time-script.sh` (forcing C locale only when modifying output) as a deliberate choice, leaving potential cleanup for the future.

The series remains self-contained, touching only the test infrastructure (`t/` directory) and adding a new test (`t5567-one-time-script.sh`) that exercises the fixed helper deterministically using FIFOs. The documentation patch (patch 3) generalizes the atomic idioms in `t/README`, linking to Git's lockfile machinery and `make_symlink()` as precedents. The fixes are minimal, targeted, and unlikely to be controversial, as they address a concrete problem without changing user-visible behavior. The v2 looks well-crafted and ready for integration, with Junio's feedback fully addressed.
