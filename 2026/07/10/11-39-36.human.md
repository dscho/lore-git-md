This is the final patch in Johannes Schindelin’s twelve-patch bugfix series (`js/coverity-fixes-v2`) that addresses NULL-dereference and latent memory-safety issues identified by Coverity. This specific patch fixes a subtle but real bug in `write_one_shallow()`: the function uses `oid_to_hex()`’s rotating static buffer for the commit’s hexadecimal representation, which can be silently corrupted if another call to `oid_to_hex()` happens before the string is used. The fix replaces the static buffer with a stack-allocated buffer and `oid_to_hex_r()`, ensuring the hex string remains valid throughout the function.

The patch is small (three lines added, one removed) and surgical, touching only `shallow.c`. It does not change behavior or introduce new error messages; it simply hardens the code against future edits that might add another `oid_to_hex()` call. Junio C Hamano suggested the fix during the v1 review, and Dscho implemented it with assistance from an AI tool (Claude Opus 4.7). The commit message clearly explains the latent bug and the rationale for the change.

This patch, like the rest of the series, is uncontroversial and well-motivated. The series as a whole is ready for integration, with all feedback from Junio’s v1 review incorporated in v2. If you care about memory safety or shallow repositories, this patch is worth a quick look; otherwise, it’s a straightforward merge candidate.
