This is a three-patch series from Christian Couder that introduces a new `fromAccepted` option to the `GIT_NO_LAZY_FETCH` environment variable, allowing lazy fetching only from promisor remotes that both the server advertises and the client accepts.

The series builds on recent work that added the "promisor-remote" capability to Git’s protocol v2, enabling safer lazy fetching by restricting it to agreed-upon promisor remotes rather than disabling it entirely. Currently, `GIT_NO_LAZY_FETCH` is a blunt boolean that defaults to `true` for security, but this change offers a more flexible middle ground. The commit message acknowledges that an `upload-pack.allowLazyFetch` configuration variable would be more user-friendly but defers that improvement to avoid the complexity of maintaining backward compatibility with the existing environment variable.

The first patch refactors the promisor-remote code to separate fetching logic from error handling, which could improve performance when multiple promisor remotes are involved. The second patch transitions `GIT_NO_LAZY_FETCH` from a boolean to an enum to support multiple states, and the third patch implements the `fromAccepted` option itself. The series touches `promisor-remote.c`, `setup.c`, documentation, and adds a new test script (`t/t5710-promisor-remote-capability.sh`).

CI tests have passed, and the patches appear well-structured, with clear motivations and incremental changes. This looks like a thoughtful, pragmatic improvement to lazy fetching, though the reliance on an environment variable (rather than a config option) might limit its usability. The series is likely to attract attention from contributors working on promisor remotes or partial clone functionality.
