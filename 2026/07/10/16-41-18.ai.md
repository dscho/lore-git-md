This is the twelfth patch in the sixteenth iteration of a security-hardened feature series implementing `git cat-file --batch-command`'s `remote-object-info` functionality. This specific patch introduces runtime validation of format placeholders against a dynamic allow-list, addressing two critical safety issues: potential segfaults from uninitialized data and the previous behavior of dying on unknown atoms (which could block local queries sharing the same format).

The implementation adds an `is_remote` flag to `struct expand_data` and a static `remote_object_info_atoms` array listing supported placeholders ("objectname" and "objectsize"). In remote mode, `expand_atom()` now checks each requested atom against this allow-list, returning an empty string for unsupported atoms rather than dying. This matches `for-each-ref`'s behavior for known-but-inapplicable atoms. Additional safety measures include initializing `data->type` to `OBJ_BAD` and adding a NULL check for `type_name()`.

The patch updates three tests to expect empty strings instead of failures for unsupported placeholders, and adds a new explicit test for this behavior. Documentation is updated to clarify that unsupported placeholders return empty strings rather than raising errors. This change is a key security improvement, preventing crashes while maintaining compatibility with existing Git patterns. The implementation is clean, well-tested, and addresses all prior review feedback about placeholder validation.
