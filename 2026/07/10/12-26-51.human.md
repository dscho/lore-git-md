This is a feature patch series that makes submodule fetch errors configurable. The series consists of two patches: the first fixes a pre-existing logic bug in submodule fetching, and the second introduces a new configuration option (`fetch.submoduleErrors`) and command-line flag (`--submodule-errors`) to control whether submodule fetch failures should cause the entire operation to fail or merely warn.

The motivation is clear: when fetching with `--recurse-submodules`, Git currently fails hard if a submodule references an unreachable OID, which can be unnecessarily disruptive when working with in-progress upstream branches. The new `warn` mode allows the fetch to continue while still alerting the user to the issue. The default behavior remains unchanged (`fail`) for backwards compatibility.

The series is well-structured, with the first patch cleaning up the error-handling logic to ensure phase-1 fetch failures are only recorded when there’s no phase-2 retry, and the second patch building on that to add the new configuration and flag. The changes in v3 address feedback from earlier iterations, including better error reporting, forwarding the flag to child fetches, and thorough test coverage. The documentation is also updated to reflect the new options.

This looks like a thoughtful, user-focused improvement that addresses a real pain point without breaking existing workflows. The commit messages and test additions are thorough, and the changes are scoped appropriately. If you work with submodules, this is worth reviewing.
