This thread is a design discussion started by Omri Sarig asking why Git’s porcelain commands (like `git log`) default to showing the *author date* rather than the *committer date*. The question stems from the observation that in rebase-heavy workflows, the committer date—reflecting when a commit was actually introduced into the main branch—might be more relevant than the static author date.

Jeff King (Peff) has weighed in with a substantive explanation: the current default is intentional and tied to Git’s own mailing-list-based workflow. In this model, the author date represents when the work was originally done, while the committer date reflects when the maintainer applied the patch. This rationale aligns the default with the project’s historical contribution process. However, the thread remains open, as Peff’s response doesn’t address whether the default should change for other workflows (e.g., rebase-heavy ones) or whether such a change would break existing scripts or user expectations. No decisions have been made yet, and the discussion is still gathering input from the community.
