This thread is a design discussion about why Git’s porcelain commands (like `git log`) default to showing the *author date* instead of the *committer date*. Omri Sarig started the conversation, questioning whether this choice is tied to specific workflows or is just a historical artifact. In rebase-heavy workflows, the committer date often reflects when a commit landed in the main branch, while the author date stays fixed, which some users find less intuitive.

Jeff King (Peff) and Junio C Hamano have defended the current default, arguing it’s intentional and aligns with Git’s mailing-list-based workflow. Peff noted that the author date reflects when the work was originally done, while Junio clarified that in practice, the author date is typically set to when the patch was *sent* to the list—not when it was written—making it a proxy for when the work became visible to others. No consensus has emerged on whether the default should change.

Oswald Buddenhagen recently weighed in with a concrete alternative: default to showing the *author name* alongside the *committer date*, which he argues better reflects when a commit "started to matter to users." To avoid confusion, he suggests renaming the field in the output (e.g., `Stamp:` instead of `Date:`) and introducing a new format like "compact" for this behavior. He dismisses backward compatibility concerns for users parsing porcelain output without specifying a format, calling it a self-inflicted issue. The proposal hasn’t addressed broader implications for tools like `git blame` or `git bisect`, and no implementation has been shared yet. The discussion remains open, with no decisions made.
