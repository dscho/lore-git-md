This is the eleventh patch in the `js/coverity-fixes-v2` series, a bugfix targeting a NULL-dereference in `shallow.c`. The patch addresses a latent crash in `write_one_shallow()` when a shallow graft entry references a commit object that is missing from the object store (e.g., after a partial fetch or repository corruption). In such cases, `lookup_commit()` returns NULL, but the verbose logging code still attempts to dereference `c->object.oid`, causing a segfault before the entry can be removed from `.git/shallow`. The fix is simple and defensive: use the graft entry’s OID (`graft->oid`) instead of the commit object’s OID for the log message, since the graft’s OID is always available and identical to the lookup key. The change is minimal (one line) and does not alter behavior beyond preventing the crash.

No new user-visible behavior is introduced beyond avoiding a crash, and the fix is uncontroversial.
