This is the sixth patch in Patrick Steinhardt’s eight-patch v2 series introducing object filters to `odb_for_each_object()`, part of the ongoing ODB abstraction effort. The patch introduces `prepare_bitmap_git_for_source()`, a new function that opens a bitmap exclusively for a single object source, addressing a correctness issue in the packed backend’s upcoming bitmap-based object filtering.

The problem is straightforward: the existing `prepare_bitmap_git()` function opens the first bitmap it finds across *all* object sources, which is fine for whole-repository operations but incorrect when the packed backend operates on a single source. Using a bitmap from a different source would misattribute objects, duplicate enumeration, and potentially yield objects outside the intended source. The new function ensures bitmaps are opened only for the specified source, preventing these issues.

The implementation is minimal: `prepare_bitmap_git_for_source()` allocates a `bitmap_index`, calls `open_bitmap_for_source()` (introduced in patch 4/8), and loads the bitmap if successful. The function is exposed in `pack-bitmap.h` alongside the existing bitmap-preparation functions. This is a preparatory change with no immediate behavior impact; the real payoff comes in patch 8/8, where the packed backend will use this function to safely apply bitmaps during object enumeration.

The patch is well-motivated and clearly explained in the commit message, which explicitly calls out the three correctness issues it resolves. It builds cleanly on the refactoring in earlier patches (notably patch 4/8’s `open_bitmap_for_source()`) and is a necessary step toward the series’ goal of enabling bitmap-based filtering in pluggable ODB backends. No review feedback has surfaced yet, but the design aligns with Git’s existing patterns—backends are allowed to ignore filters they don’t support, just as reference backends can ignore exclude patterns. This patch looks like a solid, uncontroversial piece of the larger ODB abstraction puzzle.
