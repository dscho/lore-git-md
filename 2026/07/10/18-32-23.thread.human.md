This thread is about fixing a five-year-old regression on Cygwin where IPv6-style SCP URLs (like `[::1]:repo`) are incorrectly treated as invalid paths due to stricter path validation introduced in Git 2.23.1. The patch, authored by Ramsay Jones, restores test coverage by removing 2024-era skips in `t5500-fetch-pack.sh` and `t5601-clone.sh` and adds Cygwin-specific path validation logic to avoid misinterpreting IPv6 addresses as Windows drive letters.

The patch is under review, with the main point of contention being a conditional in `connect.c` that Torsten Bögershausen argues must be preserved to avoid breaking UNC path support on Git for Windows. Ramsay initially proposed removing the block but later suggested replacing it with a Windows-native guard (`#ifdef GIT_WINDOWS_NATIVE`). Patrick Steinhardt has now weighed in, endorsing the patch’s goal of fixing the regression properly rather than relying on test skips, but he does not address the conditional dispute. He also raises a broader question about adding Cygwin to Git’s CI matrix to catch such regressions earlier, noting its behavioral differences from MSYS2 and native Windows.

The patch itself is ready aside from the unresolved conditional issue, and no maintainer decision has been made yet. The discussion remains focused on balancing Cygwin compatibility with preserving Git for Windows UNC path support.
