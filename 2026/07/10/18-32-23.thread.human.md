This thread is about fixing a five-year-old regression on Cygwin where IPv6-style SCP URLs (like `[::1]:repo`) are incorrectly rejected due to stricter path validation introduced in Git 2.23.1. The regression has caused test failures in `t5500-fetch-pack.sh` and `t5601-clone.sh`, which have been skipped since 2024.

Ramsay Jones proposed a patch that adds Cygwin-specific path validation logic to avoid misinterpreting `[` as a Windows drive letter. The core fix remains viable, but there’s an ongoing debate about whether to preserve a contested `#ifdef DUMMY` block in `connect.c` or replace it with `#ifdef GIT_WINDOWS_NATIVE` to avoid breaking Git for Windows UNC path support. Ramsay now plans to mark the failing tests as Cygwin-specific skips rather than attempting to fix mixed forward/back-slash URL handling in config files. No maintainer decision has been made yet, and the patch is still under review.

Key participants include Ramsay (the author), Torsten Bögershausen (who argued for preserving the `#ifdef DUMMY` block to avoid UNC path breakage), and Patrick Steinhardt (who supports the patch’s goal but remains neutral on the Windows-specific debate). Patrick also raised the question of adding Cygwin to Git’s CI matrix, but Ramsay’s recent reply suggests uncertainty about whether the user base justifies the effort. The regression itself stems from the 2019 security releases, and the patch touches `git-compat-util.h`, `connect.c`, and the affected test scripts.
