This thread is about fixing a five-year-old regression on Cygwin where IPv6-style SCP URLs (like `[::1]:repo`) are incorrectly rejected due to overly strict path validation introduced in Git 2.23.1. The regression has caused test failures in `t5500-fetch-pack.sh` and `t5601-clone.sh`, which have been skipped on Cygwin since 2024. Ramsay Jones proposed a standalone patch that restores test coverage and adds Cygwin-specific path validation logic to avoid misinterpreting IPv6 addresses as Windows drive letters.

The patch is under review, but Torsten Bögershausen raised a substantive objection: removing a conditional in `connect.c` (introduced in 2018 to support UNC paths on Git for Windows) would break UNC path handling on that platform. Torsten argues the conditional should be preserved, suggesting Ramsay’s earlier idea of replacing `#ifdef DUMMY` with `#ifdef GIT_WINDOWS_NATIVE` might be the right compromise. No maintainer decision has been made yet, and the patch’s future hinges on addressing this compatibility concern while still fixing the Cygwin regression.
