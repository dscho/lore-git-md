This is a follow-up in the ongoing discussion about a bugfix patch for Git’s SSH signature verification. The patch relaxes the requirement that `gpg.ssh.allowedSignersFile` must be configured before Git will display SSH signature details, allowing users to inspect signatures (key type, fingerprint, validity) without automated principal validation.

The author, Grayson Tinker, responds to Junio C Hamano’s usability concern about the unconditional advice message that appears for every SSH-signed commit when the allowed signers file is unset. Grayson acknowledges the trade-off: using Git’s standard `advise_if_enabled()` mechanism would make the message suppressible but would also expand it into three lines, disrupting the output of commands like `git log --show-signature`. He notes that the current behavior is no worse than the previous error message, which also appeared repeatedly. He offers to make the hint disableable if Junio prefers.

Grayson also confirms that the patch’s intent aligns with Junio’s observation: some users rely on purely cryptographic validation (ensuring the commit hasn’t been tampered with) without needing to validate the signer’s identity, and these users would benefit from suppressing the repetitive advice. The thread now awaits Junio’s guidance on whether to adjust the advice mechanism or proceed with the current approach. No code changes have been posted yet.
