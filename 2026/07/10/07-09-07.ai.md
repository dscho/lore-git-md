This is a reply in the ongoing ODB abstraction series, specifically addressing the design question raised in patch 6/7 about object filter handling in `odb_for_each_object()`. Patrick Steinhardt responds to Justin Tobler’s concern that the current design—allowing backends to ignore filters—is awkward because it forces callers to re-filter objects for correctness.

Patrick acknowledges the awkwardness but defends the design as consistent with Git’s existing patterns (e.g., reference backend exclude patterns). He argues that enforcing a subset of filters that all backends must support would artificially limit future backends, since even the current "loose" and "packed" backends cannot efficiently handle the same filters (e.g., type filtering). He suggests that an alternative—filtering objects inside `odb_for_each_object()`—could be explored later but is out of scope for this series, noting that the only current caller (`git cat-file --batch-all-objects`) already handles manual filtering. He plans to clarify the rationale in the commit message.

The response leaves the design unchanged but provides context for why the current approach was chosen. The open question is now resolved in favor of the original design, removing a potential blocker for the series’ acceptance. No new technical details or code changes are introduced.
