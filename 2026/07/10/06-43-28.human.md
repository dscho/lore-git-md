This is a feature patch series (v8) adding `includeIf worktree:<pattern>` and `worktree/i:<pattern>` conditions to Git’s config system. The feature allows users to conditionally include configuration files based on the working tree’s path, addressing a gap in multi-worktree setups where the `.git` directory’s location is not intuitive.

The v8 iteration simplifies the implementation by dropping the symlink-preserving worktree path logic introduced in v7. Instead, it now matches only the realpath-resolved worktree location, documenting this limitation as a known trade-off. This change resolves the architectural concerns raised by Patrick Steinhardt, who argued that the symlink-preserving logic was overly complex and conflicted with his in-flight `ps/setup-split-discovery-and-setup` series. The series is now reduced to two patches: a preparatory refactoring of `include_by_gitdir()` into `include_by_path()`, and the core feature implementation.

The patch remains well-motivated, with clear use cases for multi-worktree workflows. It includes thorough test coverage for bare repositories, multiple worktrees, case sensitivity, early config reading, and non-repository scenarios. The documentation explains the distinction between `worktree:` and `gitdir:`, provides usage examples, and compares the feature with `extensions.worktreeConfig`. The changes are confined to `config.c` and the test suite, with no behavior changes outside the new feature.

The unresolved `seen` integration failure reported by Junio in v7 is not mentioned in this update, so it may still be an open issue. The author has not yet responded to Patrick’s feedback about the symlink limitation, but the v8 changes suggest a willingness to compromise on design complexity. The patch looks ready for serious review, though the integration failure may need to be addressed before it can progress to `next`.
