This is the eighth iteration of Harald Nordgren’s `git history squash` feature, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now functionally complete and addresses all prior feedback, including the critical input validation gaps identified in v7.

The headline improvements in v8 are threefold. First, the `--reedit-message` flag now builds the same editor template as `git rebase -i --autosquash`: fixup!, squash!, and amend! commits are grouped under the commit they target rather than shown in commit order, and an amend! replaces its target’s message unless a squash! already folded into that target. This required plumbing the range through `todo_list_rearrange_squash()` and extracting the sequencer’s marker helpers into `sequencer.h` so both commands build the identical template from one source. Second, the command now refuses a fixup!, squash!, or amend! only when its target lies outside the range, so several fixups for an in-range commit fold together. A range made up entirely of markers for one below-range target is combined into a single commit, keeping the last amend! message if there is one. Third, rev-list options are now accepted and sanitized the way `git replay` does: the walk order is forced back with a warning if an option would change it, which also fixes the earlier bug where `git history squash -- --reverse` slipped past the option check.

The implementation remains a single three-way merge of the entire range against the oldest commit’s parent, followed by replaying descendants. The range is read like the arguments to `git rev-list`, supporting compound ranges such as `HEAD~3..HEAD ^topic`. The ref-handling logic rejects operations where any ref points to a commit inside the squashed range by default, with an advice message suggesting `--update-refs=head` to retarget only the current branch. The series touches `builtin/history.c` (522 insertions, 108 deletions), `sequencer.c`/`sequencer.h` (extracted helpers), `advice.c`/`advice.h`, `Documentation/git-history.adoc`, and a new test script `t/t3455-history-squash.sh` (776 lines). Junio’s “Will replace” sign-off from v7 still applies, and the unresolved questions from prior discussion (whether `--reedit-message` should be the default, and whether the template should reorder commits) have been deferred rather than blocking the series. The command is now ready for final review and integration.
