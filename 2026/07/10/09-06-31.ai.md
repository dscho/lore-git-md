This is the eighth iteration of Harald Nordgren’s `git history squash` feature, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now functionally complete and addresses all prior feedback, including the critical `rev-list` option validation gap identified in v7.

The headline changes in v8 are:
- **Autosquash alignment**: The `--reedit-message` template now groups `fixup!`, `squash!`, and `amend!` commits under their targets (rather than showing them in commit order), exactly matching `git rebase -i --autosquash`. This required reusing `todo_list_rearrange_squash()` and exposing the `TODO_REPLACE_FIXUP_MSG` flag from the sequencer.
- **Fixup/squash/amend handling**: A marker is now refused *only* when its target lies outside the range, allowing multiple fixups for the same in-range commit to fold together. A range made entirely of markers for one below-range target is combined into a single commit, taking its message from the last `amend!` if present.
- **Rev-list option validation**: The command now sanitizes `rev-list` options (including those after `--`) by forcing the walk order back to `--reverse --topo-order` and warning if the user’s options would have changed it. This fixes the v7 regression where `git history squash -- --reverse` could produce silently incorrect results.
- **Merge handling**: Interior merges are folded as long as the range has a single base, with `--ancestry-path` ensuring only commits descended from the base are included. A range reaching more than one base is rejected.

Key files touched:
- `builtin/history.c` (522 insertions, 108 deletions across the series): Core implementation, including the new `reject_dangling_fixups()` helper and rev-list option validation.
- `sequencer.c`/`sequencer.h` (70 insertions, 30 deletions): Extracted helpers (`add_squash_combination_header`, `add_squash_message_header`, `squash_subject_comment_len`) and the `TODO_REPLACE_FIXUP_MSG` flag for reuse.
- `t/t3455-history-squash.sh` (776 lines): Expanded test coverage for autosquash grouping, rev-list option validation, and fixup/squash/amend edge cases.

The series is now technically sound and ready for integration. Junio’s "Will replace" sign-off on v7 suggests this version will likely be queued for the next release. The only remaining discussion point is whether `--reedit-message` should be the default, but this is a minor usability tweak that does not block merging.
