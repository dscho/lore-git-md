This is the first patch in the sixteenth iteration of a security-hardened feature series implementing `git cat-file --batch-command` support for remote object metadata queries. The patch fixes a memory leak in the transport helper subsystem where `data->name` allocated during `transport_helper_init()` was not being freed when disconnecting a transport that hadn't fully started its helper process.

The fix is straightforward: move the `FREE_AND_NULL(data->name)` call outside the conditional block so it executes unconditionally during disconnect. This ensures the memory is properly released regardless of whether the helper process was fully initialized. The change is minimal (one line moved) and addresses a clear correctness issue identified during review of the larger series.

This patch is part of the preparatory refactoring that makes the later `remote-object-info` functionality possible. While small, it demonstrates the series' attention to memory safety - a critical concern given the feature's network-facing nature. The fix was prompted by Chandra Pratap's review and has been incorporated into the final version of the series after being identified as a blocker for the security hardening goals.

The patch itself is uncontroversial and appears ready for merging. It's a good example of the kind of foundational cleanup work that enables more complex features while maintaining Git's robustness standards.
