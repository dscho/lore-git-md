This is the second patch in Harald Nordgren’s seven-patch v18 series implementing `git branch --delete-merged`, which is now complete and ready for merging. The series refactors the branch deletion API to use flags instead of boolean arguments, enabling future extensibility for features like `--dry-run` and `--delete-merged`.

This specific patch converts `delete_branches()` and its helper `check_branch_commit()` from using separate `force` and `quiet` boolean parameters to a single `unsigned int flags` parameter with enum values (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is mechanical, splitting the flags back into local booleans within the function, but Phillip Wood points out a subtle issue: the `flags` variable is later modified (e.g., `flags |= DELETE_BRANCH_FORCE` for remote branches), creating two sources of truth. This could lead to regressions if future changes assume the flags remain unchanged. Phillip suggests replacing all uses of the local `force` and `quiet` variables with direct flag checks (`flags & DELETE_BRANCH_FORCE`, etc.) to maintain a single source of truth.

The patch is otherwise clean and well-contained, touching only `builtin/branch.c`. It introduces no functional changes, serving purely as a preparatory step for the core `--delete-merged` logic in patch 5/7. The feedback here is substantive but narrow, focusing on avoiding a potential maintenance pitfall rather than questioning the overall design. The fix would be straightforward and would not affect the series’ readiness for merging.
