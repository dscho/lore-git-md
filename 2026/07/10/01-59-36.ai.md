This is a maintainer review of a bugfix patch targeting Git's SSH signature verification subsystem.

Junio C Hamano raises a usability concern about the patch as written: the new advice message ("Configure gpg.ssh.allowedSignersFile...") is emitted unconditionally for every SSH-signed commit when the allowed signers file is unset. In a command like `git log --show-signature -100`, this would result in 100 identical messages, creating noise without adding value. The message bypasses Git's standard `advise_if_enabled()` mechanism, so users have no way to suppress it.

The review questions the underlying assumption of the patch: whether users commonly run signature inspection commands without the allowed signers file configured. Junio suggests that if such usage is rare or pointless, the repetitive warning might be acceptable (since users would configure the file to get meaningful output). However, he notes that cryptographic verification alone—without principal validation—still provides value by guaranteeing the commit content hasn't been tampered with since signing. Users who rely on this minimal validation (and don't want to maintain an allowed signers file) would likely find the repeated advice disruptive.

The review is substantive but open-ended, inviting the author to reconsider the trade-off between helpfulness and noise. No technical flaws in the code are identified, but the feedback highlights a potential UX regression for a specific user segment. The thread now awaits the author's response on whether to adjust the advice mechanism or rationale.
