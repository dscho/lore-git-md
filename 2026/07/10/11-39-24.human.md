This is the **v2 cover letter** for Johannes Schindelin’s twelve-patch bugfix series addressing NULL-dereference issues identified by Coverity. The series targets eleven files across diff, remote, reftable, mailsplit, bisect, replay, revision, pack-bitmap, and shallow subsystems, adding defensive guards to prevent crashes or undefined behavior in edge cases.

The v2 iteration incorporates all feedback from Junio C Hamano’s review of v1. The most notable change is in the `remote.c` patch: Dscho now agrees with Junio’s position that a NULL `remote` in `remote_tracking()` is a contract violation and should trigger `BUG()` rather than silently returning `-1`. The `bisect_successful()` patch now uses the symbolic `BISECT_FAILED` constant instead of the raw `-1` return value, addressing a maintainability concern. The `revision.c` patch (`add_parents_only()`) now includes a regression test, and the `bisect_start()` patch no longer claims the edge case can be triggered with current code, instead framing the fix as future-proofing against hypothetical ref-backend behavior. The shallow patches have been split: the NULL-dereference fix remains, and a new patch (12/12) addresses the latent `oid_to_hex()` static-buffer bug Junio identified, using a stack-allocated buffer and `oid_to_hex_r()` to ensure thread safety.

The series is now complete and uncontroversial. All patches are small, focused, and well-explained, with clear commit messages naming the function and the specific NULL condition being addressed. The changes are purely defensive and do not alter normal behavior or on-disk formats. The added test in `t/t0410-partial-clone.sh` provides regression coverage for the `revision.c` edge case, and the shallow patch’s thread-safety fix is a narrowly scoped improvement. Given Dscho’s track record and the mechanical nature of the fixes, this series looks ready for integration.
