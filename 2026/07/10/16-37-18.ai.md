This is patch 7/11 in Justin Tobler’s v4 series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch fixes a latent transaction leak by making `odb_transaction_commit()` propagate backend commit errors (e.g., filesystem failures during temporary directory migration) to callers. Previously, the function ignored the backend’s return value, leaving the ODB’s internal transaction pointer dangling on failure.

The change is mechanical: `odb_transaction_commit()` now returns an `int` error code, and the backend’s commit callback (`transaction->commit`) is updated to match. The patch touches only `odb/transaction.c` (10 lines) and `odb/transaction.h` (7 lines), with no behavior changes beyond surfacing previously ignored errors. This addresses the transaction-leak feedback from v3 (Patrick Steinhardt’s review) and aligns with the series’ broader goal of robust error handling. The fix is uncontroversial and carries Patrick’s Reviewed-by from v3.

This patch is part of the ODB abstraction effort led by Patrick Steinhardt, which aims to make Git’s object storage backend-agnostic. The series as a whole is queued for `next` and has addressed all prior feedback, including safety concerns in `odb_transaction_begin()` and error-handling gaps in `odb_transaction_env()`. The only remaining deferred items are design-level questions (e.g., merging `odb/transaction.h` and `odb/source.h`) and follow-up work like explicit `odb_transaction_abort()` calls.

Key interfaces modified:
- `odb_transaction_commit()`: now returns `int` (0 on success, negative on error).
- Backend commit callback: signature updated to return `int` (e.g., `odb_transaction_files_commit()`).

The patch is a prerequisite for patch 8/11, which updates `git-receive-pack` to handle commit failures. Test coverage relies on the existing `receive-pack` test suite, which exercises the quarantine flow. No new tests are introduced here.
