Subject: [PATCH v3 0/2] fetch: configurable submodule fetch errors

Originating author: Paulius Zaleckas
Thread type: patch series

Core problem or goal
Allow users to configure whether `git fetch --recurse-submodules` should fail hard or merely warn when a submodule’s gitlink points to an OID that is not reachable from the submodule’s remote. The default (`fail`) preserves backwards compatibility; the new `warn` mode enables workflows where upstream topic branches are still in flux without disrupting the entire fetch.

Current status
Under review; v4 posted addressing Junio C Hamano’s prior technical concern about CLI override propagation. Junio’s latest review identifies further technical improvements to config value parsing and option forwarding consistency but does not raise new design objections. The series remains under review with no merge status change.

Key technical details
- Files touched: `submodule.c`, `submodule.h`, `builtin/fetch.c`, `Documentation/config/fetch.txt`, `Documentation/fetch-options.txt`, `t/t5526-fetch-submodules.sh`
- New config key: `fetch.submoduleErrors` (values: `fail`, `warn`; case-sensitive per Junio’s feedback)
- New CLI option: `--submodule-errors=(fail|warn)`
- New behavior: when set to `warn`, submodule fetch errors are reported but do not abort the parent fetch
- Forwarding: the resolved value (whether from CLI or config) is propagated to child fetches (`--all`, `--multiple`, nested recursion) when explicitly set, preserving user intent
- Error routing: all submodule fetch errors flow through `record_fetch_error()`, which defers error recording until all fetch phases (refs and OID-based retry) have failed, fixing a logic flaw where phase-1 failures could abort the fetch prematurely. The helper also ensures errors are consistently reported with the submodule name in the final summary.
- Test coverage: new tests for warn mode, error reporting, CLI override propagation, and edge cases, including tests verifying that a failed submodule fetch is still reported even when the gitlinked commits are present locally, and that the setting is forwarded correctly with `--all`
- Test hygiene: one test script (`t/t5526-fetch-submodules.sh`) contains a raw `grep` invocation that should be replaced with `test_grep` for portability; Junio provided a one-line fixup commit.
- Implementation improvements requested: replace `strcasecmp()` with exact string matching (`strcmp`) for config values, refactor option forwarding to use centralized helper functions (`parse_submodule_error` and `submodule_error`), and align CLI and config parsing logic to reduce duplication.

Open questions and loose ends
- Junio’s latest review requests mechanical refactoring of config value parsing and option forwarding logic to improve maintainability and consistency. These changes are non-functional (behavior remains identical) but are considered substantive improvements.
- The test portability issue (raw `grep` → `test_grep`) remains unresolved but is mechanical and does not affect the feature’s logic.
