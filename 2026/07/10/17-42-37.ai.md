This is a bugfix patch for the sequencer subsystem, specifically addressing how `git rebase --autosquash` handles commits that become empty after applying a `fixup!` or `squash!` commit. The patch ensures that the `--empty` option (which controls whether empty commits are kept, dropped, or cause the rebase to stop) is respected in these cases, rather than defaulting to halting the rebase with an error.

The issue arises when a `fixup!` or `squash!` commit cancels out all changes in its target commit, resulting in an empty commit. Previously, Git would ignore the `--empty` option and always stop the rebase, forcing users to manually intervene. This made it cumbersome to back out changes from a series—users had to manually edit the rebase todo list to remove the commit and its fixups. With this patch, the rebase now behaves consistently: if `--empty=drop` is specified, the empty commit is dropped; if `--empty=keep`, it is retained; and if `--empty=stop` (the default), the rebase halts as before.

The patch touches `sequencer.c` to add logic that checks whether an amended commit (after applying a `fixup!` or `squash!`) is empty by comparing the index to the tree of HEAD's parent (rather than HEAD itself). If the commit is empty, the patch honors the `--empty` option, including dropping the commit by resetting HEAD to its parent when `--empty=drop` is specified. The patch also updates `t/t3415-rebase-autosquash.sh` with extensive tests covering edge cases, such as fixups applied to already-empty commits, and ensures that dropped commits are not incorrectly recorded as rewritten. Documentation in `git-rebase.adoc` is updated to clarify the behavior.

The motivation is practical: at Meta, the author maintains a fork of LLVM where internal patches are kept as single commits using `fixup!` commits. Retiring a patch currently requires manual todo-list surgery, but with this patch, users can simply commit a revert as a `fixup!` and let `--autosquash --empty=drop` handle the rest. The patch is well-motivated, includes thorough tests, and addresses a real workflow pain point. The changes are localized to the sequencer and do not introduce broader risks.
