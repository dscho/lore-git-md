This is the final patch in Pablo Sabater’s **v8 series** implementing **cascading indentation for visual roots** in `` `git log --graph` ``. The patch adds the actual visualization logic that indents commits whose parents are excluded (making them appear as "visual roots") to avoid misleading vertical adjacency with unrelated commits.

The core idea is simple: when a commit has no visible parents (either because it is a true root or its parents were filtered out), it is indented by two characters per level, except the first in a cascade. The indentation cascades for adjacent visual roots, so each subsequent root is indented further. A new graph state, `GRAPH_PRE_ROOT`, is introduced to draw the connecting edge between an indented root and its child. Merge parents are explicitly excluded from indentation to avoid redundant edges.

The patch is **well-tested**: it adds a new test script (`t4218-log-graph-indentation.sh`) with 453 lines of test cases covering single roots, cascading roots, merges, filtered parents, `--first-parent`, `--max-count`, and `--max-count-oldest`. All previously failing test cases from v6 and v7 now pass. The implementation is **deterministic** (timestamps are tweaked in the lookahead buffer) and **compatible** with other in-flight topics like Jeff King’s `revs->commits` removal and Kristofer Haugsbakk’s `kk/prio-queue-get-put-fusion`.

This is a **feature patch** that directly improves the readability of `git log --graph` output.
