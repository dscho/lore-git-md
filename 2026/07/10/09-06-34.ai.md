This is the core implementation patch (3/5) of Harald Nordgren’s `git history squash` feature, part of the v8 series that is now functionally complete and ready for integration. The patch adds the `squash` subcommand to the `git history` built-in, allowing users to fold a commit range into its oldest commit while preserving descendant history.

The implementation handles the full range of technical requirements identified in prior review: it resolves and validates the revision range, rejects invalid inputs (single-commit ranges, empty ranges, ranges with multiple bases, and merges with external parents), folds interior merges as long as they are fully contained, and replays descendants verbatim. It also enforces the ref-safety design: by default, the command refuses if any ref points to a commit inside the squashed range, with an advice message guiding users to `--update-refs=head` to rewrite only the current branch.

Key internal helpers introduced in this patch:
- `resolve_squash_range()` parses and validates the range, ensuring it meets structural requirements and sanitizing `rev-list` options (including those after `--`) by forcing `--reverse --topo-order` and warning if the user’s options would alter the walk order.
- `reject_dangling_fixups()` blocks ranges where any `fixup!`, `squash!`, or `amend!` marker’s target lies outside the range, while allowing multiple fixups for the same in-range commit to fold together.
- `find_interior_ref()` detects refs pointing to commits inside the squashed range, triggering the default rejection behavior.

The patch also adds the new advice key `ADVICE_HISTORY_UPDATE_REFS` and updates the documentation to clarify the merge limitation, input syntax, and `--reedit-message` behavior. The test script `t/t3455-history-squash.sh` (566 lines) exercises range parsing, merge handling, ref safety, authorship preservation, `--update-refs` behavior, and `--reedit-message` template construction.
