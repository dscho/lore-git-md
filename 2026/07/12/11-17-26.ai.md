This is patch 2/9 of Tian Yuchen’s v10 series migrating global configuration variables into `struct repo_config_values`. It moves the `excludes_file` global (the path to the global ignore file) into the repository-scoped configuration structure and replaces direct access with a getter, `repo_excludes_file()`.

The patch is a straightforward refactoring: the global `excludes_file` is removed, the field is added to `struct repo_config_values`, and the lazy-loading fallback logic (defaulting to `$XDG_CONFIG_HOME/git/ignore`) is encapsulated in the new getter. Memory management is handled by the existing `repo_config_values_clear()` destructor, which now frees the `excludes_file` field. The only caller (`setup_standard_excludes()` in `dir.c`) is updated to use the getter instead of the global.

This patch is **technically solid** and **ready for integration**. It addresses all prior feedback: the redundant call to `repo_config_values()` in the getter is cached (as suggested by Pablo Sabater in v9), and the destructor signature mismatch is resolved in patch 1/9. The commit message clearly explains the motivation (libification, memory safety) and the change’s scope. No user-visible behavior changes are introduced.

The patch is part of the broader `the_repository` removal effort and builds directly on the recently merged `excludes_file` migration (v6). It touches `environment.c`/`environment.h` and `dir.c`, with no cross-subsystem ripple effects. The getter’s implementation is clean, and the memory management is correct. Reviewers should note the cached `repo_config_values()` call in the getter, which was the last substantive change from v9 to v10.
