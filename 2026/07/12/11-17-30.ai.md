This is patch 6/9 of Tian Yuchen’s v10 series migrating global configuration variables into `struct repo_config_values` as part of the ongoing libification effort. It moves the `apply_default_whitespace` and `apply_default_ignorewhitespace` strings from global variables into the repository-specific configuration struct, mirroring the pattern established in earlier patches for `excludes_file`, `editor_program`, `pager_program`, and `askpass_program`.

The patch updates `git_apply_config()` to accept a `struct repository *` parameter (eliminating reliance on `the_repository`) and modifies all callers in `apply.c` to use the new repository-aware fields. Memory management is handled by extending `repo_config_values_init()` and `repo_config_values_clear()` to initialize and free the new fields. The changes are mechanical and follow the established pattern; no new getters are introduced, and callers access the fields directly via `repo_config_values(repo)->apply_default_whitespace`.

Files touched are `apply.c` (primary), `environment.c`, and `environment.h`. The patch is CI-clean, memory-leak-free, and ready for integration. It addresses no prior feedback specific to these variables but builds directly on the infrastructure established in patches 1–5. The only loose end is the deferred cleanup of comments and variable classification in `repo_config_values`, which the author has promised as follow-up work. Reviewers should focus on the updated function signature for `git_apply_config()` and the direct field access pattern, which are consistent with the rest of the series.
