This is the second patch in Tian Yuchen’s v10 series migrating global configuration variables into `struct repo_config_values`. It moves the `excludes_file` variable — the path to the global ignore file — into the repository-scoped configuration structure and introduces a proper getter, `repo_excludes_file()`, that encapsulates the lazy-loading fallback to the XDG default path.

The patch is a clean, mechanical refactoring: it removes the global `excludes_file` variable, adds a corresponding field to `struct repo_config_values`, updates the config parser to store the value in the repository’s config structure, and replaces direct access in `setup_standard_excludes()` with a call to the new getter. Memory management is handled by the existing `repo_config_values_clear()` destructor, which now frees the `excludes_file` field. The change is part of the ongoing `the_repository` removal effort and follows the pattern established by the recently merged `excludes_file` migration.

The patch addresses the performance nit Pablo Sabater raised in v9 by caching the result of `repo_config_values(repo)` in a local variable inside `repo_excludes_file()`, avoiding redundant calls. The commit message is clear and concise, and the diff is minimal and focused. No user-visible behavior changes are introduced; the patch is purely internal plumbing. It is CI-clean and ready for integration. Reviewers can focus on the getter implementation and the memory management in the destructor, but there are no obvious red flags.
