This is a follow-up in the RFC thread about adding a standardized debug-commit mechanism to Git. Junio C Hamano responds to Simon Richter’s proposal for a `discard!` (or similar) commit message prefix that would allow autosquash to automatically drop debug commits during interactive rebase.

Junio acknowledges the proposal is feasible and aligns with Git’s existing autosquash patterns, like `fixup!`. He suggests using `drop!` instead of `DISCARD` to match the existing `fixup!` convention and notes that the sequencer machinery (used by `git rebase -i`) could easily support this by converting `pick` instructions for such commits into `drop` instructions. He also points out that no changes to `git commit` would be needed—users could simply use `git commit -m 'drop!'`—but the sequencer would need to recognize the prefix.

The response is constructive and pragmatic, treating the idea as a small, incremental feature rather than a major change. Junio’s suggestion of a custom `GIT_SEQUENCE_EDITOR` script as a workaround shows the feature isn’t urgent, but his willingness to consider a built-in solution signals it’s worth exploring. No objections or deeper technical concerns are raised, but the thread is still in the early stages—no patches or implementation details have been proposed yet. The discussion remains focused on workflow and user experience, not on low-level mechanics or edge cases.
