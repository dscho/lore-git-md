Core problem or goal
Fix inconsistent handling of empty commits in `git rebase --autosquash`: when a `fixup!` or `squash!` operation cancels out its target commit, the resulting empty commit is currently *always* stopped at, ignoring the `--empty` option (drop/keep/stop). The patch aims to make autosquash respect `--empty` for these emptied commits, enabling workflows like reverting a commit via `fixup!` and having `--empty=drop` remove both the original and its revert. The goal includes distinguishing between commits that *become* empty during rebase (which should respect `--empty`) and commits that *were already empty* (which should not be dropped), and handling edge cases around conflict resolution, multiple fixups, and missing pick commands.
