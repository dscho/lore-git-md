Subject: [PATCH v3] sequencer: respect --empty for autosquash-induced empty commits
Series version: v3 (standalone patch)
Originating author: Farid Zakaria
Thread type: bugfix patch

Core problem or goal
Fix inconsistent handling of empty commits in `git rebase --autosquash`: when a `fixup!` or `squash!` operation cancels out its target commit, the resulting empty commit is currently *always* stopped at, ignoring the `--empty` option (drop/keep/stop). The patch makes autosquash respect `--empty` for these emptied commits, enabling workflows like reverting a commit via `fixup!` and having `--empty=drop` remove both the original and its revert.
