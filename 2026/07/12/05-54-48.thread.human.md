This thread is a proposal from Simon Richter for a new Git feature that would streamline a common developer workflow. When debugging, developers often commit temporary code (like `printf` statements) with a placeholder message such as "DISCARD", then manually remove these commits during an interactive rebase before sharing their work. Richter suggests formalizing this pattern by having Git's autosquash mechanism recognize a standardized marker—such as a commit message prefix like `discard!`—and automatically drop these commits during history cleanup. The proposal also floats the idea of enforcing this via push hooks or CI checks to prevent debug code from accidentally ending up in shared branches.

The idea is lightweight and user-focused, targeting developers who regularly clean up their commit history with `git rebase -i`. It wouldn’t change core Git behavior or on-disk formats, but would add a small convenience feature to interactive rebase and possibly client-side hooks. So far, the thread is just the initial proposal—no patches, implementation details, or prior discussion have been shared. The next steps would likely involve feedback on whether the community sees this as a worthwhile addition, followed by a concrete design and patch series if there’s interest.
