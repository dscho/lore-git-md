This thread is an RFC proposal by Simon Richter for a standardized way to mark debug commits (like temporary `printf` statements) so Git can automatically drop them during interactive rebase (`git rebase -i`). The goal is to simplify history cleanup before sharing code, potentially using push hooks or CI checks to block accidental inclusion of debug code.

Junio C Hamano responded with a technical assessment, noting the idea is feasible given Git’s existing sequencer machinery (which already handles `fixup!` commits). He suggested using `drop!` as a commit message prefix instead of `discard!` to align with Git’s conventions and proposed that the feature could automatically convert `pick` instructions to `drop` for such commits. However, he emphasized that no changes to `git commit` are needed—users could manually add the prefix today—and that a custom `GIT_SEQUENCE_EDITOR` script could achieve the same result without modifying Git. His response was neutral, focusing on implementation mechanics rather than endorsing the feature, and left broader workflow questions (like CI enforcement) unaddressed.

The thread remains in the conceptual phase, with no patches or deeper discussion yet. Key open questions include the exact prefix convention, how autosquash would handle these commits, whether the feature would be opt-in or opt-out, and how to handle edge cases like rebase conflicts. No other participants have weighed in, and the proposal is still lightweight, targeting only interactive rebase without altering core Git behavior or on-disk formats.
