This is the third patch in Tian Yuchen’s v10 series migrating global configuration variables into `struct repo_config_values`. It moves the `editor_program` global into the repository-scoped configuration structure, continuing the libification effort.

The patch is straightforward: it removes the `editor_program` global variable, adds it as a field to `struct repo_config_values`, updates the getter function `git_editor()` to access it via `repo_config_values(the_repository)->editor_program`, and ensures proper memory management in the `repo_config_values_clear()` destructor. The commit message explains the rationale—per-repository editor configuration is useful for developers working with different toolchains, and eliminating mutable global state is necessary for long-running processes managing multiple repositories.

This patch is part of the infrastructure and string-variable group (patches 1–6) and builds directly on the updated destructor signature introduced in patch 1/9. The changes are mechanical and well-motivated, with no user-visible behavior changes. The series as a whole is technically complete, CI-clean, and ready for `next`; this patch itself has no open questions or loose ends. Reviewers should note the cached access pattern in `git_editor()`, which avoids redundant calls to `repo_config_values()`—a small but important performance fix carried over from v10’s broader improvements.
