This is a **bugfix** for the sequencer subsystem, specifically addressing how `git rebase --autosquash` handles commits that become empty after a `fixup!` or `squash!` operation. The patch ensures that the `--empty` option (which controls whether empty commits are kept, dropped, or stopped at) is respected even when the emptiness results from autosquashing, not just from a regular `pick`.

### Problem
When a `fixup!` or `squash!` commit cancels out all changes in its target commit (e.g., reverting a previous change), the resulting commit is empty. Currently, `git rebase --autosquash` ignores the `--empty` option in this case and always stops with an error, forcing manual intervention. This makes it cumbersome to back out changes from a series (e.g., reverting a commit as a `fixup!` and expecting `--empty=drop` to remove both the original and its revert).

### Solution
The patch modifies `do_pick_commit()` in `sequencer.c` to:
1. Detect when a `fixup!`/`squash!` operation results in an empty commit by comparing the index against the parent of HEAD (not HEAD itself, as is done for regular picks).
2. Apply the `--empty` option’s behavior (drop, keep, or stop) to these emptied commits, just as it does for commits that become empty during a regular `pick`.
3. When dropping, reset HEAD to the parent of the emptied commit (since the commit was already created by the preceding `pick`) and discard rewrite records to avoid spurious post-rewrite actions.

### Documentation
The patch updates `git-rebase.adoc` to clarify that `--empty` now applies to autosquash-induced empty commits, and that this enables workflows like backing out changes by reverting them as `fixup!` commits.

### Tests
The patch adds comprehensive tests in `t/t3415-rebase-autosquash.sh` covering:
- `fixup!`/`squash!` that empties its target with `--empty=drop`, `--empty=keep`, and `--empty=stop`.
- Edge cases like `fixup!` filling in an empty commit or leaving an empty commit empty.
- Verification that dropped emptied commits are not recorded as rewritten (to avoid post-rewrite side effects).

The fix aligns autosquash with the existing `--empty` handling for regular picks, making the behavior more consistent.
