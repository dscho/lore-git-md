This is a design discussion about Git's default commit date display behavior. Oswald Buddenhagen challenges the current rationale for defaulting to the *author date* (when the patch was sent to the mailing list) rather than the *committer date* (when the commit was applied to the target branch). He argues that the committer date is more useful for most users exploring branch histories, as it reflects when the commit "started to matter to users," while acknowledging that the author name should remain the default.

Buddenhagen proposes a compromise: showing the *author name* alongside the *committer date* by default, which he believes would be more practical. To avoid confusion, he suggests renaming the field in the output (e.g., `Stamp:` instead of `Date:`) and introducing a new format name like "compact" for this behavior. He dismisses backward compatibility concerns for users parsing porcelain output without specifying a format, framing it as a self-inflicted issue.

The email advances the thread by introducing a concrete alternative to the current default and addressing potential usability concerns (e.g., field naming). However, it does not engage with the broader implications for tooling (e.g., `git blame`, `git bisect`) or workflows outside Git's traditional mailing-list model. The proposal remains speculative, with no implementation or patch attached.
