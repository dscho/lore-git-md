This thread reports a serious regression in Git's fsmonitor subsystem that causes a crash when Git is built without Rust support. The issue surfaces in test `t7527-builtin-fsmonitor.sh` (test 43) on the `next` and `seen` branches, as well as the upcoming Git 2.55.0 release. The crash occurs in the Linux-specific fsmonitor listener code (`fsm-listen-linux.c`) during a directory rename operation, triggering a `BUG_vfl` assertion due to a "double remove of watch" for a directory.

Đoàn Trần Công Danh, the reporter, provides a clear reproduction case and system details, noting that Rust support was disabled during the build. While fsmonitor has seen recent Rust-related work, this particular crash appears to originate in the C compatibility layer rather than Rust code. The severity of the issue—an invariant violation leading to a `BUG()` assertion—suggests this is a genuine regression that could affect users relying on fsmonitor for performance in large repositories. No responses or fixes have been posted yet, so the thread is currently focused on identifying and confirming the problem.
