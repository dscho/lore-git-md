This is patch 8/9 in the v10 series migrating global configuration variables into `struct repo_config_values` as part of the ongoing `the_repository` removal effort. This patch moves the `autorebase` enum (which controls whether newly created branches automatically rebase by default) from a global variable into the repository-specific configuration struct.

The change is mechanical and follows the established pattern from earlier patches in the series. The `enum rebase_setup_type` definition is relocated higher in `environment.h` to make it visible to `struct repo_config_values`, and the default value `AUTOREBASE_NEVER` is initialized in `repo_config_values_init()`. The configuration parser in `git_default_branch_config()` is updated to write directly to the repository's configuration instance rather than the global variable. Callers in `branch.c` now access the value via `repo_config_values(the_repository)->autorebase`.

No new getters are introduced; the series consistently uses direct field access for migrated variables. The patch maintains backward compatibility and introduces no user-visible behavior changes. Memory management is handled by the existing `repo_config_values_init()` and `repo_config_values_clear()` functions, which were updated in earlier patches to support submodule safety and avoid initialization-order crashes.

This patch is uncontroversial and ready for integration. The only remaining work in the series is patch 9/9 (migrating `object_creation_mode`), which follows the same pattern. Reviewers should note the relocated enum definition and the direct field access in `branch.c` as the key changes. The patch is well-motivated, with a clear commit message and no open technical concerns.
