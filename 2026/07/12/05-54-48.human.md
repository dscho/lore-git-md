This is a feature proposal from Simon Richter suggesting a new Git mechanism to mark commits for automatic removal during history cleanup.

Simon describes a common workflow where he commits temporary debug code (like `printf` statements) with a commit message of "DISCARD" so he can easily remove them during a final rebase. He proposes extending this concept with a standardized marker that Git's autosquash feature could recognize, and that could be checked by push hooks or CI systems.

The proposal is lightweight and targets a specific pain point in the development workflow. It doesn't include a patch or implementation details yet - this is an RFC to gauge interest before investing in coding. The idea appears well-motivated by a real development need, though it's unclear how widespread this particular workflow is among Git users.

This stands alone as a thread root rather than part of a larger series. The concept would likely be implemented as a new commit message trailer or special subject prefix that `git rebase --autosquash` would recognize.
