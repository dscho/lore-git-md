This is a follow-up in the RFC thread proposing a standardized debug-commit mechanism for Git. Junio C Hamano responds to Simon Richter’s idea of using a special commit message prefix (like `discard!`) to mark debug commits for automatic removal during interactive rebase.

Junio acknowledges the feasibility of the proposal, noting that the sequencer machinery already supports similar patterns (e.g., `fixup!` commits). He suggests using `drop!` instead of `DISCARD` to align with existing conventions and proposes that the feature could automatically convert `pick` instructions to `drop` for commits with this prefix. However, he stops short of endorsing an implementation, pointing out that no changes to `git commit` are necessary—users could simply use `git commit -m 'drop!'`—and that a custom `GIT_SEQUENCE_EDITOR` script could achieve the same result today without modifying Git.

The response is neutral and technical, focusing on how the feature *could* work rather than whether it *should*. It clarifies the scope (interactive rebase only) and avoids addressing the broader workflow questions (e.g., push hooks or CI enforcement) raised in the original RFC. No objections or alternatives are presented, but the tone suggests the idea is plausible but not urgent. The key technical detail introduced is the `drop!` prefix as a potential standard, along with the observation that the sequencer’s existing logic could be extended to support it. The thread remains in the conceptual phase, with no patches or deeper discussion yet.
