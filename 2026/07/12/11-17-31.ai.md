This is patch 7/9 of Tian Yuchen’s v10 refactoring series, continuing the libification effort by migrating the global `push_default` variable into `struct repo_config_values`.

The patch moves the `push_default` enum (which controls the default behavior of `git push` when no refspec is given) from a global variable into the per-repository configuration struct. The enum definition itself remains in `environment.h` rather than its ideal home in `remote.h` because moving it would create a circular dependency (`remote.h -> hash.h -> repository.h -> environment.h`). The author documents this as a `NEEDSWORK` item for future cleanup.

Callers in `builtin/push.c` and `remote.c` are updated to access the value via `repo_config_values(the_repository)->push_default` instead of the global. The configuration parser in `environment.c` is modified to update the per-repository struct directly. The patch is mechanical and maintains backward compatibility; no user-visible behavior changes are introduced.

The circular dependency workaround and the deferred enum relocation are the only loose ends. The patch is otherwise complete, CI-clean, and ready for integration. Reviewers should focus on the enum placement trade-off and the direct field access pattern, which is consistent with the rest of the series.
