This is patch 6/13 in Johannes Schindelin’s Coverity-driven cleanup series, targeting a memory leak in the line-log subsystem (`line-log.c`).

The patch fixes a redundant copy in `line_log_process_ranges_arbitrary_commit()`. When `bloom_filter_check()` determines a commit does not touch any tracked paths, the function currently makes an intermediate copy of the `range` structure (`line_log_data_copy(range)`) and passes it to `add_line_range()`. However, `add_line_range()` always makes its own internal copy, so the caller’s copy is never freed and leaks. The fix removes the redundant copy and passes the original `range` directly to `add_line_range()`, letting the callee handle ownership.

The change is a single-line deletion in `line-log.c` (line 1144), replacing `prange` with `range`. The commit message explains the leak clearly and cites Coverity as the source. This is a straightforward, uncontroversial cleanup that aligns with the series’ goal of plugging resource leaks without changing user-visible behavior. The patch touches only the line-log subsystem, specifically the `process_ranges` function and its interaction with `add_line_range()`. No new symbols are introduced; the fix is purely about resource ownership.
