This is the penultimate patch in a **15-part security-hardened feature series** that adds `remote-object-info` support to `` `git cat-file --batch-command` ``. The series is now complete and ready for merging, with all prior review feedback addressed.

This patch implements the actual `remote-object-info` command in `` `git cat-file --batch-command` ``, allowing users to query object metadata (currently just size) from remote repositories without downloading the full objects. The command is designed to minimize network overhead by accepting multiple object IDs in a single request, unlike the existing `info` command which processes one object at a time.

The implementation introduces a new code path that batches remote requests before processing local objects, reducing the number of round-trips to the server. Key details:
- The command syntax is `remote-object-info <remote> <oid>...`, where `<remote>` can be a URL or remote name, and multiple OIDs can be provided in a single line.
- Only `%(objectname)` and `%(objectsize)` placeholders are currently supported, with a warning that the default format may change when `%(objecttype)` is added.
- The command works with both buffered (`--buffer`) and unbuffered modes, and supports `-Z` for null-delimited output.
- Input validation includes checks for malformed OIDs, short OIDs (which are rejected), and missing objects (which return "missing" rather than failing).
- The implementation includes strict limits: 10,000 objects per request and 8KB for remote URLs.

The patch includes **680 lines of comprehensive new tests** in `t/t1017-cat-file-remote-object-info.sh`, covering all transport protocols (git://, file://, http://), edge cases (missing objects, malformed OIDs, legacy protocols), and integration with existing batch-command features like `--buffer` and `-Z`. The tests verify both functionality (correct metadata retrieval) and security (no unintended object downloads).

This is a well-crafted feature that addresses a real use case (querying object sizes without full downloads) while maintaining Git's security and compatibility standards. The implementation is mature, with thorough error handling, input validation, and protocol enforcement.
