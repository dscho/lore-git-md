This is the twelfth patch in the v15 series implementing `git cat-file --batch-command`'s `remote-object-info` feature. The patch addresses a security and robustness issue in the format placeholder validation for remote object queries.

The problem: previously, the code used a simple `strstr()` check to validate format placeholders like `%(objectsize)`, which was insufficient. This could lead to two failure modes: (1) if an atom was recognized by `expand_atom()` but not supported by the remote, `data->type` could contain garbage, causing a segfault; (2) if an atom was unknown to `expand_atom()`, the code would call `strbuf_expand_bad_format()`, which dies, breaking local queries that share the same format string.

The fix introduces a static allow-list of supported remote atoms (`objectname` and `objectsize`) at the top of `expand_atom()`. In remote mode, unsupported atoms now return 1 and leave the buffer empty, matching how `for-each-ref` handles known-but-inapplicable atoms. The patch also adds defensive initialization (`data->type = OBJ_BAD`) and a `NULL` check for `type_name()` to prevent segfaults from uninitialized data.

The documentation is updated to clarify that unsupported placeholders return empty strings rather than raising errors. Tests are adjusted to expect this new behavior, and a new test explicitly verifies that unknown placeholders return empty strings.

This is a well-motivated security patch that closes a real gap in the remote object info implementation. The allow-list approach is appropriate for the current limited feature set, and the defensive programming measures (initialization, `NULL` checks) are sensible. The change aligns remote behavior with established patterns in Git (like `for-each-ref`), which is good for consistency. The patch is small, focused, and addresses all the issues raised in review. It looks ready to merge.
