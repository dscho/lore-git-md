This is the seventh patch in Patrick Steinhardt’s 11-patch v8 series implementing `git history drop`. It refactors the reset machinery to allow callers to specify the commit that the working tree should be reset *from*, rather than always defaulting to HEAD.

The change is small and targeted: it adds an `oid_from` field to the `reset_working_tree_options` struct and updates `reset_working_tree()` to use it when provided. If the field is set, the function uses it as the source commit for the two-way merge; otherwise, it falls back to the current HEAD. The commit message explains that this flexibility is needed for `git history drop`, which replays descendants on top of a parent commit and thus needs to reset the working tree from a commit other than HEAD.

The patch is a clean preparatory refactoring with no behavior change for existing callers. It touches only `reset.c` and `reset.h`, and the diff is minimal. This is part of the broader reset API modernization effort in the series, which has already included renaming the function, converting flags to an enum, adding dry-run mode, and making HEAD updates opt-in. The series as a whole is now technically complete and appears ready for merging, with all prior feedback—including the high-impact dispute over ref resolution—addressed.
