Core problem or goal
A user reports that HTTP/HTTPS authentication using domain account passwords (NTLM) broke after upgrading Git for Windows from 2.53.0.windows.2 to 2.55.0.windows.1. The previously effective workaround `http."<url>".allowNTLMAuth true` no longer restores functionality. The issue is specific to Git for Windows; upstream Git is not implicated.

Current status
Report acknowledged by Git for Windows maintainer Johannes Schindelin. The Git mailing list thread is closed; all further discussion redirected to the Git for Windows issue tracker ([#6308](https://github.com/git-for-windows/git/issues/6308)). No root-cause analysis or resolution yet.

Key technical details
- Platform: Git for Windows 2.55.0.windows.1 (fork-specific)
- Subsystem: HTTP/HTTPS transport, NTLM authentication
- Configuration: `http."<url>".allowNTLMAuth` setting (now ineffective)
- No credential-helper involvement mentioned in original report
- No on-disk format or CLI changes
- Regression window: between 2.53.0.windows.2 and 2.55.0.windows.1
