This is the third patch in a four-patch bugfix series targeting the parse-options infrastructure. It updates `git rev-parse --parseopt` to exit 0 when help is requested via `--help` or `-h`, aligning with Unix conventions and the broader system-wide fix introduced in the previous patch.

The patch modifies `parse-options.c` to append `exit 0` after the heredoc terminator (`EOF`) when help output is generated in shell-eval mode (`PARSE_OPT_SHELL_EVAL`). This ensures the invoking script exits successfully after displaying help, rather than propagating the previous exit code 129. The change is minimal and surgical: it preserves the existing behavior for direct invocation (still exiting 129 for debugging purposes) while fixing the documented shell-eval usage pattern.

Test updates accompany the code change. The patch adjusts `t/t1502-rev-parse-parseopt.sh` to account for the new `exit 0` line in help output, modifying sed commands to strip the heredoc terminator and exit instruction when comparing against expected output. It also adds `exit 0` to the expected output in several test cases and updates two help-spec files (`optionspec-neg.help` and `optionspec.help`) to include the new exit instruction. In `t/t1517-outside-repo.sh`, three shell scripts (`instaweb`, `quiltimport`, and `request-pull`) are moved from the success to the failure case, anticipating the final patch in the series which will standardize their help-exit behavior.

The implementation is careful to maintain backward compatibility: the recommended shell-eval invocation pattern (`eval "$(git rev-parse --parseopt ... || echo exit $?)"`) remains unaffected because the `exit 0` from the heredoc takes precedence over the fallback `exit 129`. The patch touches only the shell-eval code path, leaving direct invocation mode unchanged as a debugging aid. The test adjustments are thorough, covering both positive and negative cases for help output.

Key technical details for follow-up: the patch introduces no new symbols or config keys, but updates test expectations across three test files. The change affects only the exit code behavior of `git rev-parse --parseopt` in shell-eval mode, with no impact on other parse-options users (those are addressed in the final patch). The commit message clearly explains the Unix convention rationale and the shell-eval mechanics, making the motivation and implementation approach unambiguous.
