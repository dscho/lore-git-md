This is the first patch in a four-part bugfix series targeting the parse-options infrastructure. It adds a test prerequisite to `t/t1517-outside-repo.sh` to detect whether Subversion Perl modules are installed, allowing the test suite to skip `git-svn` tests when they are missing. The change is a preparatory step for the broader exit-code consistency fix: without this prerequisite, the upcoming behavioral change (help flags exiting 0 instead of 129) would cause `git-svn` tests to fail if Subversion is not available, since `git-svn` would die on startup rather than exhibiting the expected help behavior.

The patch introduces a minimal `SVN` prerequisite that checks for the presence of `SVN::Core` and `SVN::Repos` Perl modules with a version requirement. This mirrors the approach used in `t/lib-git-svn.sh` but is simplified for the specific needs of `t1517`. The prerequisite is then applied to the `svn` test case in the loop that iterates over commands. The implementation is straightforward and aligns with existing test patterns, though it does not address the broader question of whether `git-svn` should remain part of the core test suite given its optional dependencies.

This patch is a minor but necessary piece of the series, ensuring the test suite remains robust as the exit-code behavior changes. It does not alter any user-facing functionality or introduce new technical debt, but it does highlight the complexity of maintaining tests for optional features. The commit message clearly explains the motivation and ties it to the upcoming behavioral change, making the purpose evident even without the cover letter.
