This is a review reply in the ongoing `remote-object-info` security-hardened feature series, specifically addressing patch 5/13 of v15. Junio Hamano raises a **substantive review concern** about the patch's handling of the `advertise_sid` variable.

The patch aims to eliminate a static variable (`advertise_sid`) in `write_fetch_command_and_capabilities()` to prepare the function for relocation to `connect.c`. Junio points out that while the patch introduces a local variable with the same name, it fails to remove the file-scope global variable, leaving it in place. More critically, the local variable is not initialized if the `transfer.advertisesid` configuration is unset, which could lead to undefined behavior later in the function.

Junio suggests initializing the local variable to `0` (the default value for "do not advertise") as a simple fix. He also recommends splitting the unrelated type change (`hash_algo` to `const unsigned int`) into a separate patch to keep the focus clean. The review is **substantive**—it identifies a real correctness issue that could cause subtle bugs—and the author will need to address it before the patch can proceed. The rest of the series (patches 6-13) depends on this refactoring, so this feedback blocks further progress until resolved.
