This is the third patch in the **v5 series optimizing `paint_down_to_common()`** for one-sided histories, a performance-critical function in Git’s merge-base calculations. The patch adds **test coverage for edge cases** in the side-exhaustion optimization, ensuring the new early-termination logic handles tricky topologies correctly.

The tests target four specific scenarios:
- **`in_merge_bases_many:self`**: A commit is both the query target and one of the inputs (e.g., `git merge-base A A`).
- **`get_merge_bases_many:duplicate-twos`**: Duplicate entries in the input list (e.g., `git merge-base A B B C`).
- **`get_merge_bases_many:pending-stale`**: A "diamond" topology where a commit transitions from `PARENT1|PARENT2` to `PARENT1|PARENT2|STALE` during the walk, exercising the code path where a merge-base candidate is a descendant of another.
- **`get_merge_bases_many:infinity-both-sides`**: A topology entirely outside the commit-graph with non-monotonic commit dates, testing the fallback to commit-date ordering when generation numbers are `INFINITY`.

The patch extends `t/t6600-test-reach.sh` with **110 lines of new test cases**, including setup for two custom topologies (`ps-*` and `pi-*`) that stress the optimization’s edge conditions. These tests are **deterministic** and run against all commit-graph modes (none, full, half, no-gdat), ensuring the optimization works regardless of graph availability.

This is **not a code change**—it’s pure test infrastructure. The tests were originally authored by Elijah Newren and are now part of Tian Yuchen’s series to validate the side-exhaustion optimization. The patch is **well-motivated**: the edge cases it covers were identified during review of earlier iterations, and their inclusion here demonstrates the author’s thoroughness in hardening the optimization. No controversy or open questions remain; this patch is **ready to merge** alongside the rest of the series.
