This is the fifteenth iteration of a security-focused feature series that adds `remote-object-info` support to `git cat-file --batch-command`, allowing clients to query object metadata (initially just size) from remote repositories without downloading the full objects. The series is now ready for merging, with all prior review feedback addressed and only minor documentation and style improvements remaining.

The implementation introduces a new `remote-object-info` command that works with protocol v2 servers advertising the `object-info` capability. Key security measures include dynamic capability-based validation: the client filters requested format placeholders against what the server advertises, preventing information leaks. This version makes the allow-list fully dynamic, adapting to server capabilities at runtime rather than using a static list.

Notable improvements since v14 include:
- Replaced `strtoul_szt()` with `strtoumax_szt()` to ensure platform-independent `size_t` handling
- Added `BUG()` calls in error paths for better debugging
- Moved protocol documentation updates to the appropriate patch (9/13)
- Further commit message rewording for clarity and consistency
- Style and nit fixes throughout

The series maintains strict protocol v2 enforcement, 10,000-object batching limits, and silent continuation for unsupported fields (returning empty strings rather than failing). The default format is `%(objectname) %(objectsize)`, with future support for `%(objecttype)` planned. All tests pass in GitHub CI, and the implementation includes comprehensive new test coverage in `t/t1017-cat-file-remote-object-info.sh`.

The patch stack is well-structured, with preparatory refactoring (patches 1-7) followed by core implementation (8-13). The transport layer integration (patch 3/13) and dynamic allow-list validation (patch 12/13) are particularly noteworthy for their attention to security and extensibility. The protocol design is now formally documented in `gitprotocol-v2.adoc`, resolving the forward-compatibility concerns raised in earlier reviews.

This is a mature, well-tested feature that addresses a real use case (querying object sizes without full downloads) while maintaining Git's security and compatibility standards. The remaining open question about error handling (silent continuation vs. explicit failure) is a philosophical difference rather than a technical blocker. The series demonstrates thorough review engagement and careful attention to detail.
