This is the first patch in a three-part bugfix series from Jeff King (Peff) targeting memory leaks in Git’s commit-graph Bloom filter code. The series addresses leaks that only appear when running the test suite with `GIT_TEST_COMMIT_GRAPH_CHANGED_PATHS=1`, making them invisible under normal conditions.

This patch makes the Bloom filter slab initialization (`init_bloom_filters()`) idempotent by adding a static flag to track whether the slab has already been initialized. Without this change, calling `init_bloom_filters()` multiple times (e.g., during split commit-graph parsing or in the `test-tool bloom` helper) overwrites the existing slab pointers, leaking memory. The fix is minimal—just five lines of code—and avoids deeper refactoring that might risk unintended side effects, such as unnecessary slab allocations in repositories without Bloom filter data.

The commit message is thorough, explaining the problem’s subtleties (e.g., why the leaks are hard to trigger and why the current code "gets lucky" in some cases) and justifying the conservative approach. The patch itself is clean and self-contained, touching only `bloom.c`. No behavior changes or on-disk format modifications are introduced.

This looks like a well-crafted, low-risk fix for a real (if niche) issue. Peff’s reputation for precise, well-explained patches and the series’ goal of eliminating CI-detectable leaks suggest this is worth attention, especially for those tracking memory safety or commit-graph internals. The remaining two patches in the series will address similar leaks in `revision.c` and `line-log.c`.
