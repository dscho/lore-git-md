This is the core client-side implementation patch in the GSoC v15 series that adds `git cat-file --batch-command` support for querying object metadata from remotes. It introduces the `fetch_object_info()` function and integrates it into Git's transport layer, enabling clients to request object sizes (and eventually other metadata) without downloading full objects.

The patch adds a new `fetch-object-info.c` file with the `fetch_object_info()` function, which sends an `object-info` command to a protocol v2 server, validates the response against advertised capabilities, and parses the results. Key implementation details include strict protocol v2 enforcement, dynamic capability checking, and careful memory management (e.g., `xcalloc` for size pointers, `FREE_AND_NULL` for missing objects). The function handles stateless RPC and properly cleans up resources, including closing file descriptors and checking connection status.

Transport layer integration is handled through a new vtable entry (`fetch_object_info`), with implementations for both smart HTTP/SSH transports (`fetch_object_info_via_pack`) and transport helpers (`fetch_object_info_helper`). The patch also updates `transport.h` to expose `transport_fetch_object_info()` and extends `git_transport_options` to include object-info-specific fields (`object_info_oids`, `object_info_data`, `object_info_options`).

The implementation follows the established pattern of writing the entire request to a buffer before sending (matching `send_fetch_request()` in `fetch-pack.c`) and handles missing objects by setting size pointers to `NULL` (per protocol v2 specification). The patch includes comprehensive error handling, with `die()` calls for unsupported protocols and `BUG()` assertions for internal consistency checks.

This is a well-structured, security-conscious addition that builds on the preparatory refactoring in earlier patches (e.g., function relocation, command generalization) and sets the stage for the final command integration in patch 13/13. The code is clean, with clear separation of concerns between request generation, response parsing, and transport integration.
