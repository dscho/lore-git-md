This is the final patch in a four-part bugfix series that standardizes help-flag exit codes across Git's parse-options API. The patch makes all commands using parse-options exit with status 0 (success) when `-h` or `--help` is specified, aligning with Unix conventions where help output is considered successful execution. Previously, these commands exited with 129, which was an accidental holdover from 2007 code.

The change touches 37 test files, updating them to expect exit 0 instead of 129 for help scenarios. Three built-in commands (`git blame`, `git shortlog`, and `git update-index`) are modified to explicitly exit 0 when `PARSE_OPT_HELP` is returned. The patch also distinguishes between help output triggered by valid `-h` requests (now exiting 0) and help output triggered by invalid options (still exiting 129 via `PARSE_OPT_HELP_ERROR`).

Notably, `git diff` is exempted from this change because it handles its own option parsing, so some tests are updated to accept either exit code. The patch also handles edge cases where certain commands (like `git instaweb`) behave differently with `-h` versus `--help-all`, splitting test expectations accordingly. The implementation preserves backward compatibility for direct invocation of `--parseopt` (still exiting 129 for debugging purposes) while fixing the documented shell-eval mode to exit 0.

This is a well-motivated, maintainer-approved bugfix that resolves a long-standing inconsistency. The thorough test updates and careful handling of edge cases suggest the change is ready for merging. The series has already been endorsed as a regular bugfix, not requiring a major version bump.
