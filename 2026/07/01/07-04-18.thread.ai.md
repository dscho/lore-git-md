Core problem or goal
Coverity Scan recently resumed after an outage; this 13-patch series addresses the first batch of real (non-false-positive) resource leaks and error-path bugs it flagged in core Git. The goal is to plug memory, file-descriptor, and process-handle leaks, and to ensure proper cleanup when functions return early due to errors. No user-visible behavior changes; purely internal correctness.

Patch 1/13 consolidates error-path cleanup in `load_one_loose_object_map` by introducing a `ret` variable to ensure `fclose(fp)` is always called before return.
Patch 2/13 adds a `fd >= 0` guard in `write_one_object` to prevent undefined behavior from `close(-1)` on open failure.
Patch 3/13 reorders `fclose(child_out)` in `download_https_uri_to_file()` to execute unconditionally before returning on error.
Patch 4/13 replaces `if (cmd->in)` and `if (cmd->out)` with `if (cmd->in > 0)` and `if (cmd->out > 0)` in `start_command()` to avoid closing the `-1` sentinel value (CID 1049722).
Patch 5/13 plugs a memory leak in `run_diff_files()` by freeing the `combine_diff_path` structure (`dpath`) when `changed < 0` triggers an early `continue` after allocation but before the normal cleanup block; the fix initializes `dpath` to NULL and adds an explicit `free(dpath)` on the error path.
Patch 6/13 removes a redundant copy in `line_log_process_ranges_arbitrary_commit()`: when `bloom_filter_check()` determines a commit does not touch any tracked paths, the function previously made an intermediate copy of the `range` structure (`line_log_data_copy(range)`) and passed it to `add_line_range()`, but `add_line_range()` always makes its own internal copy, so the caller’s copy was never freed and leaked. The fix deletes the redundant copy and passes the original `range` directly to `add_line_range()`, letting the callee handle ownership.
Patch 7/13 plugs two memory leaks in `read_one_dir()` (dir.c) that occur when parsing the untracked-cache data fails: `ud.untracked` (allocated at line 3846) and `ud.dirs` (allocated at line 3851) are now freed before the function returns -1 on either of the two error paths that lie between those allocations and the point where ownership is transferred to the final `xmalloc`’d struct at line 3857.
Patch 8/13 plugs a memory leak in `get_superproject_working_tree()` (submodule.c) by ensuring the `cwd` buffer allocated via `xgetcwd()` is freed on the two early-return paths that previously bypassed cleanup. The fix redirects the early returns through a new `out` label that calls `free(cwd)` before returning 0.
