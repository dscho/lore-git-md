Core problem or goal
Coverity Scan recently resumed after an outage; this 12-patch series addresses the first batch of real (non-false-positive) resource leaks and error-path bugs it flagged in core Git. The goal is to plug memory, file-descriptor, process-handle, and other resource leaks, and to ensure proper cleanup when functions return early due to errors. No user-visible behavior changes; purely internal correctness.

Current status
Series is at v2, with **patches 1/12, 2/12, 3/12, 4/12, and 8/12 revised** to address maintainer and reviewer feedback. **Junio C Hamano has stated he will queue the series for merging ("looking good" and will be queued), indicating strong maintainer approval for the series as a whole.** Patch 1/12’s correctness concern is resolved: the revised patch replaces the unsafe `errno`-based error detection with an explicit `ferror(fp)` check, using `ret = ferror(fp) ? -1 : 0` to distinguish between EOF and I/O errors. The `errno = 0` initialization is removed as no longer needed. **Patches 2/12, 3/12, 4/12, 6/12, and 7/12 carry Reviewed-by from Patrick Steinhardt, Jeff King (Peff), and/or Eric Sunshine.** Patch 2/12 v2 adds a guard (`if (fd >= 0) close(fd)`) to prevent undefined behavior when `open()` fails and `close(fd)` is called with `fd = -1`. Patch 3/12 ensures the `child_out` file handle is closed when `finish_command(&cp)` fails in `download_https_uri_to_file()` by moving the `fclose(child_out)` call before the `return 1` statement. Patch 4/12 v2 replaces the three `if (cmd->in)` / `if (cmd->out)` guards with `if (cmd->in > 0)` / `if (cmd->out > 0)` in `start_command()`’s error-path rollback to prevent `close(-1)` when the caller set `cmd->no_stdin` or `cmd->no_stdout` without supplying a real file descriptor. Patch 5/13 (v1) is withdrawn as it was already fixed by commit 949bb8f74f4a ("run_diff_files(): delay allocation of combine_diff_path", 2025-01-09). **Patch 8/12 v2 consolidates all cleanup into a single exit path**, eliminating the fragility risk of two separate `free(cwd)` calls and additionally closing a latent leak of `one_up`’s backing buffer on the `strbuf_realpath(&one_up, "../", 0)` failure path.

Test coverage: none added; fixes are mechanical and covered by existing tests. Jeff King (Peff) independently reproduced the leak fixed in patch 6/12 under `GIT_TEST_COMMIT_GRAPH_CHANGED_PATHS=1`, confirming the fix’s correctness and the leak’s real-world impact.
**Patch 1/12 v2**: ensures `FILE *fp` is closed on all error paths in `load_one_loose_object_map()` by consolidating cleanup into a single `err:` exit path. The unsafe `errno`-based error detection (`return errno ? -1 : 0`) is replaced with `ret = ferror(fp) ? -1 : 0`, reliably distinguishing between EOF and I/O errors. The `errno = 0` initialization is removed as unnecessary.
**Patch 2/12 v2**: adds a guard (`if (fd >= 0) close(fd)`) in `write_one_object()` to prevent undefined behavior when `open()` fails and `close(fd)` is called with `fd = -1`. This aligns with POSIX requirements and avoids potential sanitizer warnings.
**Patch 3/12**: plugs a file-descriptor leak in `download_https_uri_to_file()` by ensuring the `child_out` file handle is closed when `finish_command(&cp)` fails. The fix moves the `fclose(child_out)` call before the `return 1` statement so that it executes unconditionally on the error path.
**Patch 4/12 v2**: replaces the three `if (cmd->in)` / `if (cmd->out)` guards with `if (cmd->in > 0)` / `if (cmd->out > 0)` in `start_command()`’s error-path rollback to prevent `close(-1)` when the caller set `cmd->no_stdin` or `cmd->no_stdout` without supplying a real file descriptor. Coverity flagged this as CID 1049722.
**Patch 8/12 v2**: consolidates all cleanup in `get_superproject_working_tree()` into a single exit path (`out:` label) that releases `cwd`, `sb.buf`, and `one_up.buf`. This eliminates the fragility risk of two separate `free(cwd)` calls and additionally plugs a latent leak of `one_up`’s backing buffer on the `strbuf_realpath(&one_up, "../", 0)` failure path.

Open questions and loose ends
**Orthogonal bug in `read_one_dir()`**: uninitialized slots in `->dirs` and `->untracked` on the failure paths may cause `free_untracked()` to dereference garbage pointers, risking a crash. Johannes Schindelin plans to address this separately, keeping the current series focused on Coverity’s leak reports.
