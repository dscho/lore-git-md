Core problem or goal
Coverity Scan recently resumed after an outage; this 12-patch series addresses the first batch of real (non-false-positive) resource leaks and error-path bugs it flagged in core Git. The goal is to plug memory, file-descriptor, process-handle, and other resource leaks, and to ensure proper cleanup when functions return early due to errors. No user-visible behavior changes; purely internal correctness.

Current status
Series is at v2, with **patches 1/12, 2/12, 3/12, 4/12, 5/12 withdrawn, 6/12, 7/12, 8/12, and 9/12 revised or added** to address maintainer and reviewer feedback. **Junio C Hamano has stated he will queue the series for merging ("looking good" and will be queued), indicating strong maintainer approval for the series as a whole.** Patch 1/12’s correctness concern is resolved: the revised patch replaces the unsafe `errno`-based error detection with an explicit `ferror(fp)` check, using `ret = ferror(fp) ? -1 : 0` to distinguish between EOF and I/O errors. The `errno = 0` initialization is removed as no longer needed. **Patches 2/12, 3/12, 4/12, 6/12, 7/12, 8/12, 9/12, and 10/12 carry Reviewed-by from Patrick Steinhardt, Jeff King (Peff), and/or Eric Sunshine.** Patch 2/12 v2 adds a guard (`if (fd >= 0) close(fd)`) to prevent undefined behavior when `open()` fails and `close(fd)` is called with `fd = -1`. Patch 3/12 ensures the `child_out` file handle is closed when `finish_command(&cp)` fails in `download_https_uri_to_file()` by moving the `fclose(child_out)` call before the `return 1` statement. Patch 4/12 v2 replaces the three `if (cmd->in)` / `if (cmd->out)` guards with `if (cmd->in > 0)` / `if (cmd->out > 0)` in `start_command()`’s error-path rollback to prevent `close(-1)` when the caller set `cmd->no_stdin` or `cmd->no_stdout` without supplying a real file descriptor. **Patch 5/13 (v1) is withdrawn as it was already fixed by commit 949bb8f74f4a ("run_diff_files(): delay allocation of combine_diff_path", 2025-01-09).** Patch 5/12 (v2) removes a redundant intermediate copy of `struct line_log_data` in `line_log_process_ranges_arbitrary_commit()` that was leaking whenever `bloom_filter_check()` determined a commit did not touch any tracked paths. The caller was making a copy (`line_log_data_copy(range)`) and passing it to `add_line_range()`, but `add_line_range()` always makes its own internal copy, so the caller’s copy was never freed. The fix passes the original `range` directly to `add_line_range()`, letting the callee handle ownership. **Patch 6/12 plugs two memory leaks in `read_one_dir()` (in `dir.c`)** by adding explicit `free(ud.untracked)` and `free(ud.dirs)` calls on the early-return paths triggered by malformed input (truncated varint or missing NUL terminator). The fix is mechanical and well-scoped, ensuring resources allocated before the parse error are released. **Patch 7/12 plugs a memory leak in `get_superproject_working_tree()` (in `submodule.c`)** by redirecting two early-return paths through a new `out:` label that frees the current working directory (`cwd`) allocated via `xgetcwd()`, along with `sb.buf` and `one_up.buf`. The fix is mechanical and ensures all resources are released before returning. **Patch 8/12 v2 consolidates all cleanup in `get_superproject_working_tree()` into a single exit path**, eliminating the fragility risk of two separate `free(cwd)` calls and additionally closing a latent leak of `one_up`’s backing buffer on the `strbuf_realpath(&one_up, "../", 0)` failure path. **Patch 9/12 plugs four memory leaks in `builtin/worktree.c` (in the `add` subcommand)** by redirecting an early error return through the existing `cleanup:` label so that four allocations—`path`, `opt_track`, `branch_to_free`, and `new_branch_to_free`—are freed before the function exits. The change is mechanical: the `return -1` is replaced with `ret = -1; goto cleanup`, and the `cleanup:` block is moved to cover the entire function. **Patch 10/12 plugs a memory leak in `curl_append_msgs_to_imap()` (in `imap-send.c`)** by adding `strbuf_release(&msgbuf.buf)` alongside the existing libcurl cleanup calls, ensuring the buffer is freed unconditionally. Coverity flagged this as CID 1671507 ("Resource leak"). The change is mechanical and well-scoped, touching only `imap-send.c` with no user-visible behavior impact.
