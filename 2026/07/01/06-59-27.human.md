This is the second patch in Patrick Steinhardt’s RFC v3 series to reorganize Git’s source tree by moving all `libgit.a` components into a new `lib/` directory. It is a **pure refactoring** patch with no functional changes, focusing on the mechanical relocation of ~700 files and the corresponding updates to build system files (`Makefile`, `meson.build`, `CMakeLists.txt`, `config.mak.uname`) and CI workflows.

The patch moves core Git subsystems—object handling, refs, diff, merge, platform compatibility shims (`compat/`), and third-party dependencies like SHA-1 collision detection—into the `lib/` directory while preserving their internal structure. The bulk of the changes are path updates in build system files to reflect the new locations. The patch also incorporates Johannes Schindelin’s Windows CI fix from v2, adjusting `.github/workflows/main.yml` to reference `lib/compat` instead of `compat`, resolving the Visual Studio build regression.

The commit message explicitly acknowledges the trade-offs: disrupted `git log --follow` history, rebasing challenges for in-flight topics, and backporting difficulties. Patrick argues these are one-time costs justified by permanent improvements in code discoverability and onboarding, and suggests the change could incentivize tooling improvements for better rename tracking. The patch has been validated via GitLab and GitHub CI pipelines, and the series remains a **refactoring-only** effort with no changes to Git’s behavior or on-disk formats.

This patch is the centerpiece of the series, and the debate around it remains polarized. Proponents see it as a long-overdue cleanup that makes the codebase more navigable, while opponents—including Junio C Hamano and SZEDER Gábor—highlight the disruption to ongoing work and historical tracking. The explicit trade-off discussion in the commit message may help focus the debate on whether the structural benefits outweigh the logistical pain.
