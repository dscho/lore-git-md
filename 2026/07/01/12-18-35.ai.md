This is the first patch in the v15 series implementing `git cat-file --batch-command` remote object metadata support. It fixes a memory leak in the transport helper subsystem where `data->name` (allocated during `transport_helper_init()`) was not being freed when disconnecting a transport that had not fully started its helper process.

The change is minimal and surgical: it moves the `FREE_AND_NULL(data->name)` call outside the `if(data->helper)` conditional block so the field is always freed on disconnect, regardless of whether the helper was fully initialized. The fix addresses a real leak that could occur in edge cases where the transport is disconnected before the helper starts, and it aligns with the series' broader focus on memory safety and security hardening.

This is a straightforward bugfix with no behavioral changes or new functionality. The commit message clearly explains the problem, the solution, and references the relevant code path. The patch is well-motivated and uncontroversial, serving as a clean foundation for the more complex changes that follow in the series. No review feedback is expected to be contentious here.
