This is the core client-side implementation patch in the v15 series that adds `git cat-file --batch-command` support for querying object metadata from remotes. It introduces the `fetch_object_info()` function and integrates it into Git’s transport layer, enabling clients to request object sizes (and eventually other metadata) without downloading full objects.

The patch adds a new `fetch-object-info.c` file with the `fetch_object_info()` function, which sends an `object-info` command to a protocol v2 server, validates the response, and populates an array of `struct object_info` with the results. The implementation strictly enforces protocol v2 and the `object-info` capability; if the server doesn’t advertise support, the client errors out. The function handles the wire format documented in `gitprotocol-v2.adoc`, including the case where the server doesn’t recognize an object (returning just the OID followed by a space).

Transport layer integration is clean: the patch adds a new `fetch_object_info` vtable entry to both the smart transport and transport-helper backends, with a dedicated helper function (`fetch_object_info_via_pack`) that manages the connection lifecycle. The transport API is extended with `transport_fetch_object_info()`, a public function that dispatches to the appropriate backend. The patch also updates `fetch-pack.h` to include `object_info_data` in `struct fetch_pack_args`, though this field isn’t yet used in the fetch-pack code itself.

Security and robustness are evident: the request is buffered before sending (matching the pattern in `send_fetch_request`), the response is parsed with strict validation, and `strtoumax_szt()` ensures platform-independent `size_t` handling. The patch includes `BUG()` calls for unsupported features and unexpected protocol states, and it properly cleans up allocated memory when the server doesn’t recognize an object.

This is a well-crafted, thoroughly reviewed patch that addresses a real use case (querying object sizes without full downloads) while maintaining Git’s security and compatibility standards. The implementation is ready for merging, with all prior feedback incorporated and no remaining technical blockers. The only open question—whether to fail explicitly or continue silently when metadata is missing—is a philosophical difference rather than a technical issue.
