This is a design discussion about the commit-message template for `git history squash`. Junio C Hamano responds to Phillip Wood’s earlier example of how the current `git rebase -i` template can become cluttered when squashing multiple commits, and proposes a cleaner alternative.

Junio’s message focuses on refining the template format to reduce noise. He suggests omitting not just `fixup!` messages (which are purely mechanical) but also the original message of any commit marked `amend!`, since those are meant to replace the base commit’s message entirely. Instead, he proposes showing only a numbered list of commit subjects as context, followed by the editable message body. This would make the template shorter and easier to navigate, addressing the usability issue Phillip raised.

The exchange is part of the final polish for the `git history squash` series, which is otherwise complete and awaiting Junio’s review. No code changes are proposed here—just a tweak to the template layout. The discussion is narrow but important for usability, as the template’s design directly affects how users interact with the feature. If Junio’s suggestion is adopted, it would further differentiate `git history squash` from `git rebase -i`, reinforcing the idea that `git history` is a space for UX experimentation.
