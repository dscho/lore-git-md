This thread is a cleanup patch series from Johannes Schindelin (Dscho) addressing resource leaks and error-path bugs flagged by Coverity Scan after its recent outage. The series, now at version 2, consists of 12 patches targeting memory, file-descriptor, and process-handle leaks in core Git code, with no user-visible changes—just internal correctness fixes.

The series has strong maintainer approval: Junio C Hamano has stated he will queue it for merging, calling it "looking good." Key revisions in v2 include fixes to patches 1, 2, 3, and 8 to address feedback. For example, patch 1 now uses `ferror(fp)` instead of `errno` to reliably detect I/O errors, and patch 2 guards against undefined behavior when closing invalid file descriptors. Patch 4, the latest addition, plugs a latent bug in `start_command()` where error-path rollback could call `close(-1)` if the caller set `cmd->no_stdin` or `cmd->no_stdout` without supplying a real file descriptor. The fix is mechanical and confined to error-path logic.

Several patches have already received Reviewed-by tags from Patrick Steinhardt, Jeff King (Peff), and Eric Sunshine, with Peff independently confirming the leak fixed in patch 6. The only loose end is an orthogonal bug in `read_one_dir()` involving uninitialized slots, which Dscho plans to address separately. The series is self-contained and ready for merging, with no external dependencies or related in-flight topics.
