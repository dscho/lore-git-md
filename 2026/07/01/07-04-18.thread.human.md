This thread is a cleanup series from Johannes Schindelin (Dscho) that plugs resource leaks and error-path bugs flagged by Coverity Scan in Git's core code. The 13-patch series targets memory, file-descriptor, and process-handle leaks without changing user-visible behavior. Junio C Hamano has already signaled strong approval, stating he will queue the series for merging once the remaining minor issues are resolved.

The series is now effectively complete. Patch 8/13, which fixes a memory leak in `get_superproject_working_tree()` (submodule.c), was revised in response to Patrick Steinhardt’s review. The v2 patch consolidates all cleanup into a single exit path, eliminating both the original leak and a latent maintainability risk—an earlier version had two separate `free(cwd)` calls, which could have led to double-frees if the code were later modified. The revision also closes an additional leak on the `strbuf_realpath()` failure path. Other patches in the series have already been reviewed and approved by Patrick Steinhardt, Jeff King (Peff), and Eric Sunshine, with one patch (5/13) withdrawn after it was discovered the leak had already been fixed independently.

The only remaining loose end is an orthogonal bug in `read_one_dir()` (uninitialized slots in `->dirs` and `->untracked`), which Johannes plans to address separately. The series is self-contained and has no external dependencies. All fixes are mechanical and covered by existing tests, making this a straightforward cleanup effort with broad reviewer support.
