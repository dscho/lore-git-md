This is the **seventh patch in the v5 series** optimizing `paint_down_to_common()` for one-sided histories. It introduces a `paint_state` struct to track per-side commit counters (PARENT1-only, PARENT2-only, and merge-base candidates) and replaces the old `nonstale_queue` termination logic with a counter-based approach. The change is **mechanical and correctness-preserving**, with no behavioral regressions—step counts in tests drop by one in some topologies due to an earlier loop exit, but this is intentional and documented.

The patch touches `commit-reach.c` and updates `Documentation/technical/paint-down-to-common.adoc` to reflect the new termination condition (queue exhaustion when all counters reach zero). It also removes unused dedup wrappers (`nonstale_queue_put_dedup`, `nonstale_queue_get_dedup`), though these deletions are functionally separate from the core refactoring. The `paint_count_update()` helper centralizes flag-state transitions, making the logic more maintainable.

**Key symbols introduced**:
- `struct paint_state` (with `parent1_count`, `parent2_count`, `mb_candidate_count`, `gen_ordered`).
- `paint_count_update()`, `paint_queue_put()`, `paint_queue_get()`.

**Key symbols removed**:
- `nonstale_queue_put_dedup()`, `nonstale_queue_get_dedup()`.

**Behavioral change**: The loop now exits when counters reach zero, which happens one iteration earlier than the old `max_nonstale`-based termination in some topologies (e.g., `t6600-test-reach.sh` step counts drop from 6 to 5). The commit message explicitly calls this out as equivalent behavior.
