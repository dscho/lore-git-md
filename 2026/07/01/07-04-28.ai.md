This is patch 10/13 in Johannes Schindelin's 13-patch series addressing Coverity-identified resource leaks and error-path bugs in Git. The series is part of a larger cleanup effort following the resumption of Coverity scanning after an outage.

This patch plugs a memory leak in `imap-send.c` where the `msgbuf.buf` strbuf, used to accumulate messages during IMAP uploads via libcurl, was never released before the function returned. The fix adds a single line (`strbuf_release(&msgbuf.buf)`) alongside the existing libcurl cleanup calls in `curl_append_msgs_to_imap()`. The leak was flagged by Coverity as CID 1671507.

The change is mechanical and uncontroversial: it ensures the strbuf's memory is freed unconditionally at the end of the function, matching the pattern used elsewhere in the codebase for strbuf cleanup. No user-visible behavior is altered, and the fix is covered by existing tests. The patch touches only `imap-send.c` and introduces no new symbols or on-disk format changes.

Eric Sunshine previously reviewed patches 1–9 of this series, giving Reviewed-by tags with no objections. This patch follows the same pattern as the earlier ones—small, focused, and clearly motivated by static analysis. The series as a whole targets internal correctness and is unlikely to introduce regressions, making it suitable for early integration.
