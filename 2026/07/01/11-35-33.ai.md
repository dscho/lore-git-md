This is part of Patrick Steinhardt’s `git history drop` series (v8, patch 6/11), a **refactoring of the reset API** to make HEAD updates opt-in rather than mandatory. The patch introduces a new `RESET_WORKING_TREE_UPDATE_HEAD` flag that callers must explicitly set to update HEAD, and updates all existing callers in `builtin/rebase.c` and `sequencer.c` to include it. The change is **mechanical and preparatory**: it enables a future patch (11/11) where `git history drop` will update the index and working tree without touching HEAD, but does not alter behavior for any current command.

The patch also enforces a logical constraint: `RESET_WORKING_TREE_UPDATE_ORIG_HEAD` now requires `RESET_WORKING_TREE_UPDATE_HEAD` to be set, preventing nonsensical configurations where ORIG_HEAD would be updated without HEAD. This is a minor but sensible hardening of the API. The enum values in `reset.h` are reordered to reflect the new hierarchy, but the numerical values remain unchanged to avoid breaking compatibility.

Files touched: `reset.c` (core logic), `reset.h` (flag definitions), `builtin/rebase.c` (four call sites), and `sequencer.c` (two call sites). The changes are confined to flag handling and do not affect the reset machinery’s behavior. The patch is **well-motivated** by the needs of the `git history drop` command and aligns with the series’ broader goal of modernizing the reset API. No controversy or open questions are evident.
