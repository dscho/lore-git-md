This is a CI/build system patch targeting GitHub Actions workflows. Johannes Schindelin identifies a problem specific to private GitHub repositories: Dockerized CI jobs fail consistently with "cannot create async thread: Resource temporarily unavailable" errors, particularly in the t5xxx-t6xxx test range. The root cause appears to be differences in the hosted runners' PID limits between public and private repositories.

The patch modifies `.github/workflows/main.yml` to add container options that enforce a PID limit of 16,384 (along with matching nproc and nofile ulimits) when the repository is private. Schindelin's testing shows this value resolves the failures without the severe performance penalty observed at higher limits (64k caused 2-2.5x longer runtimes). The change is minimal, touching only the container configuration line.

The motivation is practical: Schindelin uses private repositories to test Microsoft Git changes not yet ready for public consumption, and the current setup fails entirely in that context. The commit message provides detailed benchmarking data comparing 64k, 16k, and public-repository runtimes across all 13 Dockerized jobs, demonstrating that 16k is the sweet spot between stability and performance.

This is a targeted fix rather than a general CI improvement. It won't affect public repository workflows, and the commit message makes clear this is about enabling private testing rather than optimizing CI performance overall. The patch itself is straightforward YAML modification with a conditional options string.
