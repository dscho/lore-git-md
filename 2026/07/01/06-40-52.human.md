This is the second patch in Jeff King’s three-patch bugfix series targeting memory leaks in Git’s commit-graph Bloom filter code. The series addresses leaks that only appear when running the test suite with `GIT_TEST_COMMIT_GRAPH_CHANGED_PATHS=1`, making them invisible under normal conditions.

This patch fixes a leak in `revision.c` where Bloom filter "keyvecs" are allocated during `prepare_revision_walk()` but not freed if the same `rev_info` struct is reused for multiple traversals. The leak surfaces in commands like `git show foo bar`, which performs separate traversals for each argument. The fix is straightforward: call `release_revisions_bloom_keyvecs()` at the start of `prepare_to_use_bloom_filter()` to discard old keyvecs before generating new ones. Peff explicitly rejects a riskier alternative (reusing existing keyvecs) to avoid subtle bugs if the pruning pathspec changes between traversals.

The change is minimal—just two lines added—and maintains existing behavior while plugging the leak. Like the rest of the series, it’s a pure memory-safety fix with no user-visible impact. The patch is well-motivated and clearly explained, typical of Peff’s contributions. No controversy or open questions are evident; this looks like a clean, uncontroversial fix that should proceed smoothly.
