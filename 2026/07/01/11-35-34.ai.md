This is the seventh patch in Patrick Steinhardt’s 11-patch v8 series introducing the `git history drop` subcommand. It extends the `reset_working_tree()` API by allowing the caller to specify the current HEAD object via a new `oid_from` field in the `reset_working_tree_options` struct.

The change is a small but important refactoring: instead of always deriving the "from" commit by reading HEAD, callers can now pass an explicit object ID. This is preparatory work for the `git history drop` command (patch 11/11), which needs to replay descendants on top of the dropped commit’s parent without assuming HEAD points to the commit being dropped. The patch itself is mechanical and confined to `reset.c` and `reset.h`, adding the new field and updating the logic to use it when provided. No behavior changes occur for existing callers, as the default remains reading HEAD when `oid_from` is NULL.

The commit message clearly states the motivation and the new capability, and the implementation is straightforward. This patch is part of the broader reset API modernization effort in the series, which has already included renaming the function, converting flags to an enum, adding dry-run mode, and making HEAD updates opt-in. The `oid_from` field is a natural extension of that work, enabling more flexible reset operations. No controversy or open questions are evident here; the patch appears ready for merging as part of the series.
