This is a utility patch in the GSoC `remote-object-info` series, now in its fifteenth iteration. It adds `strtoumax_szt()` to Git's compatibility layer, a helper function that safely converts strings to `size_t` values with proper error handling.

The function addresses a platform portability issue: `strtoul()` returns an `unsigned long`, but `size_t` can be larger or smaller depending on the platform. Instead, it uses `strtoumax()` (which returns `uintmax_t`, guaranteed to be at least as large as `size_t`) and adds a range check against `SIZE_MAX` to prevent overflow. The implementation also rejects negative values and checks for conversion errors, following Git's established pattern for robust numeric parsing.

This patch is preparatory work for a later commit in the series that needs to parse object sizes (a `size_t` value) from remote responses. The commit message clearly explains the motivation and the technical reasoning behind the choice of `strtoumax`. The implementation is clean, with good error handling and a clear contract: it returns 0 on success, -1 on failure, and sets `*result` only when the conversion is valid.

The patch is small, focused, and well-explained. It fits neatly into the broader series' goal of secure, robust remote object metadata queries. No controversy or open questions are apparent here -- this is a straightforward, necessary utility that addresses a real portability concern.
