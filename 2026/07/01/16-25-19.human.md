This is Junio’s reply to the first patch in Johannes Schindelin’s 13-patch Coverity-driven cleanup series. The patch fixes a resource leak in `load_one_loose_object_map` by ensuring the file pointer `fp` is closed on the error path and consolidates cleanup code.

Junio’s review identifies a critical flaw: the patch relies on `errno` to determine success or failure, but `errno` is not guaranteed to be valid at the point it is checked because the function may have called other library functions (e.g., `strbuf_release`) that could clobber it. He suggests replacing the `errno` check with `ferror(fp)` to reliably detect file-reading errors. The fix is otherwise sound, but this oversight risks masking real errors and could introduce subtle bugs. The patch will need revision before it can be merged.
