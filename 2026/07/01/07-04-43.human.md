This is a CI/build system patch from Johannes Schindelin. It adjusts GitHub Actions workflows to impose a PID limit of 16,384 on Docker containers when running in private repositories, addressing a resource exhaustion issue that causes test failures.

The problem surfaced when running Git’s test suite in private GitHub repositories, where Dockerized CI jobs consistently failed with "cannot create async thread: Resource temporarily unavailable" errors. Schindelin’s investigation found that hosted runners for private repositories behave differently than those for public ones, and that forcing a higher PID limit resolves the failures—though at the cost of significantly longer runtimes (up to 2.5x slower). The patch settles on 16k as a compromise between stability and performance, after testing showed that lower limits (8k) reintroduced failures while higher ones (64k) offered no runtime benefit.

The change is minimal: it modifies `.github/workflows/main.yml` to add container options (`--pids-limit`, `--ulimit nproc`, and `--ulimit nofile`) only when the repository is private. The patch is well-motivated and includes empirical data (a table of runtimes across configurations) to justify the chosen limit. It’s clearly targeted at a niche but real-world use case—verifying changes in private repositories before public release—and doesn’t affect public CI runs.

This looks like a pragmatic fix for a specific pain point, and the thorough testing suggests it’s ready for merging. The only potential concern is whether the PID limit might need adjustment in the future if Git’s test suite grows more resource-intensive, but that’s a minor caveat.
