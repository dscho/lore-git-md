This is the third patch in the **v5 series optimizing `paint_down_to_common()`** for one-sided histories. It adds **test coverage for edge cases** in the side-exhaustion optimization, ensuring the algorithm handles unusual topologies correctly.

The patch extends `t/t6600-test-reach.sh` with **four new test cases** that exercise scenarios not covered by the existing 10x10 grid topology. These include:
- **`in_merge_bases_many:self`**: A commit that is both the query tip and one of the merge-base candidates.
- **`get_merge_bases_many:duplicate-twos`**: Duplicate entries in the input list (e.g., `X:commit-4-8` repeated twice).
- **`get_merge_bases_many:pending-stale`**: A diamond topology (`ps-*`) where a commit transitions from `(PARENT1|PARENT2)` to `(PARENT1|PARENT2|STALE)` during the walk, testing the STALE propagation logic.
- **`get_merge_bases_many:infinity-both-sides`**: A topology (`pi-*`) where both query tips are outside the commit-graph, forcing a fallback to non-monotonic commit-date ordering. This verifies the INFINITY-gate in the optimization.

The setup phase constructs these topologies explicitly, with detailed comments explaining their purpose. For example, the `ps-*` diamond ensures the STALE flag propagates to a commit still marked as pending, while the `pi-*` topology uses non-monotonic dates to stress the commit-date fallback (now removed in patch 10/10, but the test remains relevant for regression prevention).

**Key technical details**:
- **File touched**: `t/t6600-test-reach.sh` (110 lines added).
- **Test patterns**: All cases use `test_all_modes` to validate behavior across commit-graph modes (none, full, half, no-gdat).
- **Edge cases**: Self-referential queries, duplicate inputs, STALE transitions, and INFINITY generation numbers.
- **Dependencies**: The tests rely on the `paint_state` counters (`parent1_count`, `parent2_count`, `mb_candidate_count`) introduced in earlier patches.
