This is the third iteration of Patrick Steinhardt’s RFC patch series to reorganize Git’s source tree by moving all `libgit.a` components into a new `lib/` directory. The series remains a **refactoring** effort with no functional changes, aiming to reduce root-directory clutter (from ~550 to ~80 files) and establish a clearer boundary for Git’s core library code.

Key updates in v3:
- The commit message now **explicitly acknowledges the downsides** of the mass rename, including disrupted `git log --follow` history and rebasing/backporting challenges for in-flight topics. Patrick frames these as one-time costs justified by permanent improvements in code discoverability, and argues that Git’s tooling should evolve to better handle such renames.
- Johannes Schindelin’s Windows CI fix (adjusting `.github/workflows/main.yml` to reference `lib/compat`) is now incorporated, resolving the Visual Studio build regression reported in v2.

The patch series still consists of two commits:
1. A preparatory change to `t/helper/test-example-tap.c` to ensure build integrity post-relocation.
2. The main patch, which moves ~700 files (including core subsystems like object handling, refs, diff, merge, and platform compatibility shims) into `lib/` while preserving internal structure. The bulk of the changes are path updates in build system files (`Makefile`, `meson.build`, `CMakeLists.txt`, `config.mak.uname`) and CI workflows.

The **core debate** remains unresolved:
- **Proponents** (Patrick, Oswald Buddenhagen, Johannes Schindelin) argue the reorganization improves discoverability, especially for newcomers, and could incentivize tooling improvements (e.g., better rename tracking in `git log`).
- **Opponents** (Junio C Hamano, SZEDER Gábor, Derrick Stolee) highlight the disruption to ongoing work, backporting, and historical tracking, viewing the change as cosmetic and risky during the prerelease freeze.

The series has been tested with GitLab and GitHub’s CI pipelines, and Patrick has signaled willingness to iterate further if the community reaches consensus. The explicit trade-off discussion in v3’s commit message may help focus the debate on whether the long-term benefits outweigh the short-term pain.
