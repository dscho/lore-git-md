This is the v8 iteration of Patrick Steinhardt’s 11-patch series introducing the `git history drop` subcommand, which removes a commit from history and replays its descendants on top of its parent. The series is now **unblocked** after resolving the high-impact technical dispute over ref resolution in `find_head_tree_change()` that stalled v7.

Key changes in v8:
- **Dispute resolution**: The patch now passes `RESOLVE_REF_READING` to `refs_resolve_ref_unsafe()`, ensuring it returns NULL when HEAD cannot be resolved (rather than a dangling pointer). This directly addresses Junio C Hamano’s concern that `find_head_tree_change()` was searching for the symbolic branch name in `result->updates[]` while `compute_pending_ref_updates()` filtered the array to contain only `HEAD` under `--update-refs=head`. The fix is minimal but critical: it guarantees the function correctly identifies HEAD movements even in detached-HEAD states.
- **Detached-HEAD test**: A new test case verifies the fix works with `--update-refs=head` and a detached HEAD, closing the edge case that triggered the dispute.
- **Cleanup**: Removed redundant code that set `head_target = "HEAD"` on detached HEAD, as the new flag handles this case more robustly.

The rest of the series remains unchanged from v7, which already addressed all prior feedback:
- **Reset API modernization** (patches 3–8): Renamed `reset_head()` to `reset_working_tree()`, converted flags to an enum, added dry-run mode, and made HEAD updates opt-in.
- **Code deduplication** (patch 9): Exposed `replay_result_queue_update()` to avoid duplicating ref-update logic.
- **Ref update phases** (patch 10): Split ref handling into two phases to support the drop operation.
- **Drop subcommand** (patch 11): Implements the user-facing command with conflict detection, bare repository support, and 537 lines of test coverage.

The series is **technically complete** and appears ready for merging, pending any new feedback. It advances several ongoing efforts: `the_repository` removal, reset API modernization, and the experimental `git history` command. The dispute resolution in v8 is a clear improvement, and the added test case provides confidence in the fix. No further blockages are evident.
