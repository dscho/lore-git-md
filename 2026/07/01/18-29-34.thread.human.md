This thread is about a **platform-specific bugfix for Git for Windows**, specifically in the `git gui` component. The issue affects users with non-ASCII characters in their Windows home directories (common in EntraID/AzureAD profiles), causing `git gui` to fail with a "configuration error" due to an encoding mismatch when processing shell paths.

The root cause is a Tcl encoding inconsistency: `git-gui.tcl` uses the system's default ANSI code page to capture output from `cygpath -m`, which emits UTF-8. When paths contain non-ASCII characters, this corrupts the path, breaking validation. The proposed fix replaces the problematic `safe_exec` call with `safe_open_command`, explicitly setting `-encoding utf-8` to match `cygpath`'s output—a pattern already used elsewhere in the codebase (e.g., `git_redir`, `_parse_config`).

The report is well-documented, including a reproduction case (Windows 11 with a Czech profile), system details, and confirmation that the fix resolves the issue. This is a **Git for Windows-specific issue** (not upstream Git), so the fix will need review from Johannes Schindelin or the Git for Windows team.
