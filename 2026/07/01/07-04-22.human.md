This is the fourth patch in Johannes Schindelin’s 13-patch series fixing resource leaks and error-path bugs flagged by Coverity. It targets the `run-command.c` subsystem, specifically the `start_command()` function.

The issue is straightforward: when `start_command()` fails partway through setting up pipes, it rolls back by closing file descriptors it has already opened. For descriptors supplied by the caller, the code tested `if (cmd->in)` or `if (cmd->out)` before calling `close()`. However, the `CHILD_PROCESS_INIT` default for these fields is `-1` (meaning "no descriptor"), which is non-zero, so the test passed and the code attempted `close(-1)`. This is undefined behavior and was flagged by Coverity as CID 1049722.

The fix is mechanical: replace the `if (cmd->in)` and `if (cmd->out)` checks with `if (cmd->in > 0)` and `if (cmd->out > 0)`, respectively. This ensures that only valid, positive file descriptors are closed. The patch is small (three lines changed) and follows the same idiom already used elsewhere in the function for the stdin pipe.

This is a clear, uncontroversial bugfix with no user-visible impact. The change is minimal and safe, making it suitable for early inclusion in a release cycle. The series as a whole is part of a broader Coverity-driven cleanup effort, but this patch stands alone and does not depend on the others.
