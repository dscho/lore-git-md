This is the fifth patch in the v5 series optimizing `paint_down_to_common()` in Git’s commit-reach subsystem. It adds **trace2 instrumentation** to measure the number of commits visited during the paint walk, enabling observable performance metrics without relying solely on wall-clock benchmarks.

The patch introduces a step counter in `commit-reach.c` that increments for each commit processed, then logs the total via `trace2_data_intmax()`. This allows developers to track optimization impact via `GIT_TRACE2_EVENT` output. The test suite (`t/t6600-test-reach.sh`) is updated to verify these metrics across all commit-graph modes (none, full, half, no-gdat) using a new helper, `test_paint_down_steps()`, which ensures the step count matches expected values for each test case.

Key changes:
- **New instrumentation**: A `steps` counter and `trace2_data_intmax()` call in `paint_down_to_common()`.
- **Test updates**: The `run_all_modes()` helper now captures trace2 output per mode, and `test_paint_down_steps()` validates step counts. For example, the `in_merge_bases_many:self` test expects 45 steps (no commit-graph) vs. 2–3 steps (with commit-graph).
- **Deterministic assertions**: Step counts are checked for all commit-graph modes, ensuring the optimization behaves consistently regardless of graph data availability.

This patch is **low-risk** (no behavior changes) and **high-value** for future performance work, providing a repeatable way to measure traversal efficiency. It complements the series’ broader goal of optimizing asymmetric merge-base queries by making the impact of changes observable. The instrumentation is uncontroversial and aligns with Git’s existing trace2 practices. All feedback from prior iterations has been addressed.
