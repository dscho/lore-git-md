This is the third patch in Patrick Steinhardt’s 11-patch v8 series introducing the `git history drop` subcommand. It performs a **mechanical rename** of the `reset_head()` function to `reset_working_tree()` in preparation for making HEAD updates optional in a later patch. The change is confined to four files (`builtin/rebase.c`, `reset.c`, `reset.h`, and `sequencer.c`) and updates all call sites and the function declaration to use the new name and corresponding `reset_working_tree_options` struct.

The rename is **pure refactoring** with no behavior change: the function still resets the working tree, updates the index, and (for now) updates HEAD. The motivation is clarity—once HEAD updates become optional, the old name would be misleading. Phillip Wood suggested the rename, and the patch follows the established pattern of preparing the API before modifying its semantics. All callers are updated in lockstep, so the series remains bisectable. This patch is a small but necessary step toward the larger goal of modernizing the reset API and enabling the `git history drop` command.
