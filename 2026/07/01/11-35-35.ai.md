This is the eighth patch in Patrick Steinhardt’s 11-patch `git history drop` series (v8). It adjusts the `reset_working_tree()` function to handle cases where the index is not clean before the reset, preparing for the new `git history drop` command which may call this function with a dirty index.

The patch removes the blanket assumption that the index is clean before calling `reset_working_tree()`. Previously, the function always skipped updating the index tree cache (`skip_cache_tree_update = 1`), relying on `prime_cache_tree()` to set the cache directly. This optimization was safe for existing callers (sequencer and rebase), which ensure a clean index, but would break the upcoming `git history drop` command, which may call `reset_working_tree()` with a dirty index.

The fix is minimal: it only skips the cache tree update (and uses `prime_cache_tree()`) when performing a hard reset. For non-hard resets, the cache tree is recomputed normally. The commit message notes that the original performance optimization was negligible, so this change has no meaningful performance impact. The patch touches only `reset.c` and is a straightforward, bisectable adjustment to support the new caller. No behavior changes occur for existing callers.
