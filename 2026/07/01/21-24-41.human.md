This is the third patch in a four-part bugfix series that standardizes help-flag exit codes across Git's parse-options infrastructure. The series addresses a long-standing inconsistency where `git rev-parse --parseopt` (and all commands using parse-options) exited with status 129 for `--help`/`-h`, violating Unix conventions.

This patch specifically updates `git rev-parse --parseopt` to exit 0 when help is requested, provided it is invoked as documented via shell eval. The change is minimal: it appends `exit 0` after the heredoc in the generated shell code. This ensures scripts using the recommended invocation pattern (`eval "$(git rev-parse --parseopt ... || echo exit $?)"`) will exit successfully when help is requested, while preserving the existing behavior for direct invocations (which still exit 129, serving as a debugging aid).

The patch updates test expectations in `t/t1502-rev-parse-parseopt.sh` to account for the new `exit 0` line in help output, and temporarily marks three shell scripts (`instaweb`, `quiltimport`, `request-pull`) as failing in `t/t1517-outside-repo.sh`—these will be corrected in the next patch. The implementation is careful to maintain backward compatibility for pipeline usage and debugging scenarios.

This is a well-motivated, low-risk change that aligns Git's behavior with Unix conventions. The series has maintainer approval and is slated for inclusion before Git 3.0. If you maintain scripts using `git rev-parse --parseopt`, this change will make them behave more predictably with `--help`.
