This is a refactoring patch in the `remote-object-info` feature series (v15, patch 5/13). It prepares the `write_fetch_command_and_capabilities()` function for relocation from `fetch-pack.c` to `connect.c` by eliminating its reliance on the static `advertise_sid` variable.

The patch makes three mechanical changes: it moves the `transfer.advertisesid` configuration lookup directly into the function, changes the `hash_algo` variable to match `hash_algo_by_name()`'s return type (`unsigned int`), and makes it `const`. The commit message explains that the protocol v1-specific `do_fetch_pack()` usage of `advertise_sid` is irrelevant here since the function is only used in protocol v2.

This is a clean, well-justified refactoring that addresses earlier review feedback about static variable usage. The changes are minimal and focused, with clear rationale for each adjustment. The patch maintains the existing behavior while making the code more modular and relocation-ready. No functional changes or new features are introduced.
