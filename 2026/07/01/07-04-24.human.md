This is the sixth patch in Johannes Schindelin’s 13-patch series fixing Coverity-flagged resource leaks and error-path bugs in Git. It targets a memory leak in the line-log subsystem (`line-log.c`), specifically in the `line_log_process_ranges_arbitrary_commit` function.

The patch removes a redundant copy of the `line_log_data` structure (`range`) that was being made before passing it to `add_line_range`. Since `add_line_range` always makes its own internal copy, the caller’s copy was never freed, causing a leak every time the code path was taken (when a commit doesn’t touch tracked paths, as determined by `bloom_filter_check`). The fix is straightforward: pass the original `range` directly to `add_line_range`, letting the callee handle ownership.

The change is minimal—just one line removed and another adjusted—and the commit message clearly explains the leak’s cause and the fix. This is a classic cleanup patch: no behavior change, no new tests needed, and the fix is mechanical. Eric Sunshine already reviewed the first five patches in the series (including this one’s predecessor), giving them a `Reviewed-by`, which suggests this patch is likely uncontroversial. The series as a whole is part of a broader Coverity-driven effort to improve Git’s internal correctness, and this patch fits neatly into that goal.
