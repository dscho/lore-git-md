This is a **test infrastructure patch** that improves diagnostic output for trace2 data assertions. It is the second patch in the **v5 series optimizing `paint_down_to_common()`** for one-sided histories, which is now fully reviewed and ready to merge.

The patch introduces `test_trace2_data_singular()`, a helper function in `t/test-lib-functions.sh` that verifies a trace2 event appears exactly once and matches an expected value. Unlike the existing `test_trace2_data` (a bare `grep` that fails silently), the new helper provides detailed error messages on FD 4, showing whether the key was missing, appeared multiple times, or had an incorrect value. This aligns with Git’s existing test diagnostics (e.g., `test_grep`) and makes debugging trace2-related test failures far more intuitive.

The implementation is straightforward: it extracts the value from the trace2 JSON using `sed`, checks for existence and uniqueness, and compares it to the expected value. The optional fourth argument (`<label>`) allows callers to add context to error messages, which is useful for distinguishing between multiple assertions in the same test. The patch touches only `t/test-lib-functions.sh` and adds 36 lines of shell code.

This change is **motivated by the broader series’ need for precise trace2 instrumentation**—later patches (e.g., patch 6/10) rely on step-count assertions to verify the optimization’s correctness. Without this helper, failures would be opaque, requiring manual inspection of trace2 logs. The helper is already used in the series’ test scripts, demonstrating its immediate utility.

The patch is **low-risk and uncontroversial**, addressing a clear gap in test infrastructure without altering Git’s behavior. It is **ready to merge** as part of the larger series, which has received unanimous approval from reviewers (Derrick Stolee, SZEDER Gábor, and Tian Yuchen). No further changes are expected.
