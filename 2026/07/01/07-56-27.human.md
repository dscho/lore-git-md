This is a brief, surface-level review of the fourth patch in Johannes Schindelin’s 13-patch Coverity-driven cleanup series. The series as a whole is a well-scoped, uncontroversial effort to plug resource leaks and error-path bugs flagged by Coverity Scan after its recent resumption.

Patrick Steinhardt’s reply confirms the patch’s correctness and completeness. The patch itself replaces two `if (cmd->in)` and `if (cmd->out)` checks with `if (cmd->in > 0)` and `if (cmd->out > 0)` in `start_command()`’s error paths, preventing the function from calling `close(-1)` when rolling back pipe setup after a partial failure. Patrick notes there is a fourth `close(cmd->out)` site elsewhere in the same function that already uses the correct `> 0` guard, so the fix is consistent with existing idiom. No new issues or edge cases are raised; the review is purely confirmatory.
