This is patch 11/13 of a security-hardened feature series implementing `git cat-file --batch-command`'s `remote-object-info` command, which allows querying object metadata (currently just size) from remote repositories without downloading the full objects. The series is now in its fifteenth iteration and is ready for merging, with all prior review feedback addressed.

This patch adds the core `remote-object-info` command to `git cat-file --batch-command`. Unlike the existing `info` command, which processes objects one at a time, `remote-object-info` accepts multiple object IDs in a single request to minimize remote communication overhead. The implementation batches requests to the server, retrieves metadata for all requested objects, and then prints the results sequentially. This approach is particularly efficient in `--buffer` mode, where commands are queued and flushed together.

Key technical details include:
- The command syntax is `remote-object-info <remote> <oid>...<oid>`, supporting multiple object IDs per request
- Only `%(objectname)` and `%(objectsize)` placeholders are currently supported, with explicit error messages for unsupported atoms
- Input validation includes checks for malformed OIDs, short OIDs (which are rejected), and missing object IDs
- The implementation handles all three transport protocols (git://, file://, http://) with comprehensive test coverage
- Security measures include a 10,000-object batch limit and strict protocol v2 enforcement
- The patch adds 680 lines of new tests in `t/t1017-cat-file-remote-object-info.sh`, covering edge cases like malformed input, unsupported filters, and protocol version mismatches

The implementation maintains consistency with existing `cat-file` behavior while adding remote capabilities. For example, it follows the same pattern of silent continuation for missing objects (returning "missing" rather than failing) and uses the same default format as local operations when no format is specified. The patch also includes proper memory management with a new `free_object_info_contents()` helper function.

This is a well-tested, security-conscious feature that addresses a real use case (querying object sizes without full downloads) while maintaining Git's compatibility standards. The remaining open question about error handling philosophy (silent continuation vs. explicit failure) is documented and doesn't block merging. The patch demonstrates careful attention to edge cases and thorough review engagement.
