This is the second patch in a four-part bugfix series that standardizes help-flag exit codes across Git's parse-options infrastructure. The patch introduces a new return code, `PARSE_OPT_HELP_ERROR`, to distinguish between help output triggered by explicit user request (`--help`/`-h`, which should exit 0) and help output triggered by invalid or ambiguous input (which should exit 129). The change is minimal and surgical: it adds the new enum value, updates the ambiguous-option case in `parse_long_opt()` to return it, and ensures all existing callers treat it the same as `PARSE_OPT_HELP` for now (both exit 129). Three built-in commands (`blame`, `shortlog`, and `update-index`) are updated to include the new case in their exit handlers.

The patch is clearly a preparatory step for the next one in the series, which will flip `PARSE_OPT_HELP` to exit 0. The commit message explains the rationale well, and the code changes are straightforward. There is no controversy here—this is a clean refactoring that sets up the behavioral change without breaking anything yet. The only files touched are the parse-options core and a handful of built-ins, so the blast radius is contained. If you care about consistent help behavior or parse-options internals, this patch is worth noting as the foundation for the actual fix.
