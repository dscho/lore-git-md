This is the second patch in Johannes Schindelin’s 13-patch Coverity-driven cleanup series. It fixes a latent error-path bug in `loose.c`’s `write_one_object()` function: when `open()` fails, the code jumps to the `errout` label and unconditionally calls `close(fd)`, but `fd` is still -1. While this is harmless on most platforms, POSIX declares `close(-1)` undefined behavior, and sanitizers can flag it as a use-after-free or fd-tracking violation. The patch adds a simple `fd >= 0` guard before the `close()` call. The change is minimal, well-motivated, and uncontroversial; it touches only the error-path cleanup in `loose.c` and does not affect any other files or user-visible behavior.
