This is the twelfth patch in the v15 series implementing `git cat-file --batch-command`'s `remote-object-info` feature. The patch introduces dynamic format-placeholder validation for remote queries, replacing the previous static `strstr()` check with an explicit allow-list that filters atoms based on what the server supports.

The change addresses two critical safety issues in the remote code path: (1) uninitialized `data->type` could cause segfaults when `expand_atom()` recognized an atom but the remote didn’t return data, and (2) `strbuf_expand_bad_format()` would `die()` on unknown atoms, breaking local queries if the same format string was reused. The new allow-list approach ensures unsupported atoms return empty strings (matching `for-each-ref` behavior) rather than crashing or failing.

Key implementation details:
- Adds a static `remote_object_info_atoms[]` array listing supported placeholders (`objectname`, `objectsize`)
- Introduces an `is_remote` flag in `struct expand_data` to distinguish remote vs. local queries
- Initializes `data->type` to `OBJ_BAD` and adds a `NULL` check for `type_name()` to prevent segfaults
- Updates documentation to clarify that unsupported placeholders return empty strings
- Modifies tests to expect empty strings instead of `die()` for unsupported atoms

The patch is a targeted security improvement that maintains backward compatibility while closing crash vectors. It’s part of the series’ broader security hardening (e.g., capability-based validation, input limits) and integrates cleanly with the dynamic capability checks introduced in earlier patches. The test updates are thorough, covering both the new empty-string behavior and edge cases like unsupported filter options.
