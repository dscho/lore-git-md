This is a bugfix patch from Johannes Schindelin, part of his 13-patch series addressing resource leaks and error-path bugs flagged by Coverity. This is the fifth patch in the series (5/13), which plugs a memory leak in `run_diff_files()` in `diff-lib.c`.

The leak occurs in a conditional block handling conflicted index entries (staged files). When `changed < 0` (indicating an error checking file status), the code skips to the next iteration without freeing the `dpath` structure allocated earlier in the block. The fix is minimal: initialize `dpath` to `NULL` and add a `free(dpath)` call before the `continue` statement.

The commit message references the original introduction of the problematic code path (4fc970c4388, 2007) and a related cleanup (b4b1550315c, 2006) that demonstrated the need to release `dpath`. The fix is straightforward and follows the pattern established in the earlier commit. No new tests are added, as the leak is covered by existing diff machinery tests.

This patch looks uncontroversial and well-justified. The series as a whole is a cleanup effort targeting Coverity-identified issues, and this patch fits neatly into that theme. The fix is mechanical and unlikely to introduce regressions. Eric Sunshine has already reviewed the first four patches in the series (including similar leak fixes), giving them his Reviewed-by, which suggests this patch will likely receive similar treatment.
