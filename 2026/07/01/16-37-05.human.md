This is the fourth patch in the **v5 series optimizing `paint_down_to_common()`** for one-sided histories. It adds **regression tests** for a specific edge case: when multiple merge-base candidates exist and one is an ancestor of another, the side-exhaustion optimization might exit early before the `remove_redundant` safety net can prune the ancestor. The new test script (`t6099-merge-base-side-exhaustion.sh`) verifies that `git merge-base --all` correctly excludes the redundant ancestor candidate, while `git merge-base` (single) still finds the shallowest merge base.

The test constructs a **diamond-shaped topology** where commits `A` and `X` are the query tips, and both `B` and `C` are merge-base candidates—but `B` is an ancestor of `C`. The side-exhaustion optimization could theoretically terminate before `STALE` propagation marks `C` as redundant, so the test ensures `remove_redundant` catches this. It also checks behavior **with and without commit-graph data**, confirming the optimization only fires when generation numbers are finite.

This patch is **pure test coverage**—no code changes—and directly addresses a **regression risk** identified in earlier iterations. The test is **deterministic, well-documented**, and exercises both the optimization and the safety net. It complements the **clock-skew topologies** added in patch 6/10 and the **mixed finite/INFINITY test** in `t6600` (patch 3/10). The series is **fully reviewed and ready to merge**, and this patch is uncontroversial.
