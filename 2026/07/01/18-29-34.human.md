This is a **platform compatibility bugfix** targeting Git for Windows, specifically the `git gui` component. A user reports that `git gui` fails to start when the Windows home directory contains non-ASCII characters (e.g., Czech diacritics like `ý`), showing a corrupted path error instead. The issue affects users logged in via Entra ID (AzureAD), which automatically creates home directories with localized usernames.

The root cause is an encoding mismatch in `git-gui.tcl`: the Tcl script captures `cygpath` output using the system's default ANSI code page, but `cygpath` emits UTF-8. This corrupts paths with non-ASCII characters during validation. The reporter includes a tested fix (provided by an AI agent) that explicitly sets UTF-8 encoding when reading `cygpath`'s output, matching patterns used elsewhere in the codebase.
