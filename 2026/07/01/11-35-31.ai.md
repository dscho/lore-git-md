This is a refactoring patch in Patrick Steinhardt’s `git history drop` series (v8, patch 4/11). It modernizes the flags passed to `reset_working_tree()` by converting them from `#define` macros to an `enum` and updating their names to match the function’s new name (previously `reset_head()`). The change is purely mechanical: all flag values and behavior remain identical, but the code now follows Git’s current style for flag definitions.

The patch updates four files: `reset.h` (where the enum is defined), `reset.c` (where the flags are used), and the callers in `builtin/rebase.c` and `sequencer.c`. Each flag is renamed from `RESET_HEAD_*` to `RESET_WORKING_TREE_*` to align with the function’s new name, and the `flags` field in `struct reset_working_tree_options` is now typed as the new enum. The commit message explicitly states this is a best-practice update with no functional changes.

This is a low-risk, bisectable refactoring that prepares the reset API for later patches in the series (e.g., making HEAD updates optional). The change is confined to the reset machinery and does not touch the core logic of the `git history drop` command. No new edge cases or behaviors are introduced, and the patch includes no tests because it is behavior-preserving. The thread context confirms this is part of a larger, technically complete series that has resolved all prior feedback, including a critical ref-resolution dispute in an earlier patch.
