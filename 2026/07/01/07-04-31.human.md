This is the final patch in Johannes Schindelin’s 13-patch series fixing Coverity-identified resource leaks and error-path bugs in Git. It targets a Windows-specific process-handle leak in the `exit_process()` helper used by `mingw_kill()`.

The issue is a subtle ownership inconsistency: `exit_process()` and `terminate_process_tree()` both take ownership of the process handle passed to them, but `exit_process()` fails to close it on one early-return path (when `GetExitCodeProcess()` fails or reports the process is still active). Meanwhile, `mingw_kill()` tries to compensate by closing the handle itself on error, which creates a double-close on every other error path. Coverity flagged this as a use-after-free (CID 1437238).

The fix is simple: make `exit_process()` close the handle on every return path, then remove the redundant `CloseHandle()` call from `mingw_kill()`. The patch adds one line to `exit_process()` and removes three from `mingw_kill()`, leaving the handle’s ownership clearly with the callee. This is a textbook cleanup—no behavior change, just plugging a leak and eliminating a latent bug.

Like the rest of the series, this patch is uncontroversial and looks ready to merge. Eric Sunshine already reviewed the first twelve patches; this one is the only holdout, but it follows the same mechanical, correctness-focused pattern. If the series lands, this patch will be the quiet capstone.
