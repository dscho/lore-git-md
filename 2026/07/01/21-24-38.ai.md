This is a bugfix series targeting the parse-options infrastructure. It standardizes the exit code behavior for `--help`/`-h` flags in `git rev-parse --parseopt` and all commands using the parse-options API, bringing them in line with Unix conventions (exit 0 on successful help display) while preserving error exits (129) for invalid options.

The series consists of four patches. The first is a minor test prerequisite fix (skipping SVN tests if SVN is missing). The second patch modifies `parse-options.c` to distinguish between help output triggered by `--help`/`-h` and help output triggered by invalid options, ensuring the former exits 0. The third patch updates `git rev-parse --parseopt` to exit 0 when help is requested, provided it is invoked as documented (via shell eval). The fourth patch ensures all parse-options users exit 0 on `-h`, completing the system-wide consistency fix.

The implementation is careful to preserve backward compatibility: the direct invocation mode of `--parseopt` still exits 129 on help, serving as a debugging aid to catch incorrect usage patterns. The change affects 37 test files, mostly updating hard-coded exit code expectations from 129 to 0 for help scenarios. The commit messages and code changes are well-motivated, referencing the prior discussion and confirming this was an accidental inconsistency dating back to 2007 rather than intentional design.

This series directly addresses the regression in `git instaweb -h` (which now exits 0 outside repositories where it previously exited 129) and implements the final consensus reached between brian m. carlson, Jeff King, and Junio C Hamano. The maintainer has explicitly endorsed this as a regular bugfix, not requiring a major version bump. The technical rationale is sound: scripts depending on help-exit behavior would be poorly designed, and pipeline usage is unaffected by the exit code change.

Key technical details for follow-up discussion: the change touches `parse-options.c` and `usage.c`, affects all built-in commands using parse-options, and updates test expectations across the `t/` directory. The series introduces no new options or config keys, but does document the behavioral change in the upcoming release notes. The implementation is minimal and focused, with thorough test coverage verifying both the shell-eval and direct invocation modes.
