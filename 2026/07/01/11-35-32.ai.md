This is the fifth patch in Patrick Steinhardt’s **v8 11-patch series** introducing the `git history drop` subcommand. It adds a **dry-run mode** to `reset_working_tree()` (formerly `reset_head()`), enabling callers to verify whether updating the index and working tree would succeed without actually performing the update.

The patch is a **preparatory refactoring** for the upcoming `git history drop` implementation (patch 11/11), which will use this mode to check for conflicts before replaying descendants. The changes are confined to `reset.c` and `reset.h`, introducing a new `RESET_WORKING_TREE_DRY_RUN` flag and modifying the function to skip all state-modifying operations when the flag is set. Key technical details:
- A **scratch index** (`struct index_state scratch_index`) is used to simulate the index state without affecting the real index.
- The `unpack_trees_options` struct is configured with `dry_run = 1` to prevent updates to the index or working tree.
- Locking (`repo_hold_locked_index`) and ref updates (`update_refs`) are skipped in dry-run mode.
- The scratch index is released on exit to avoid memory leaks.

The patch is **mechanical and bisectable**, with no behavior changes for existing callers. It advances the series’ goal of modernizing the reset API by making it more flexible for future use cases. The dry-run mode is a clean addition that aligns with Git’s existing patterns (e.g., `git merge --dry-run`). No controversies or open questions are evident here—this is a straightforward, well-scoped change that directly supports the series’ larger objectives.
