This is the final patch in Patrick Steinhardt’s 11-patch v8 series implementing the `git history drop` subcommand, which removes a commit from history and replays its descendants on top of its parent. The series is now technically complete, with all prior review feedback—including the high-impact dispute over ref resolution in `find_head_tree_change()`—fully addressed in earlier patches.

The patch adds the user-facing `drop` subcommand to the experimental `git history` command, enabling users to remove a commit and replay its descendants. Key behaviors include:
- **Conflict detection**: The command aborts if replaying descendants would result in conflicts or overwrite local changes.
- **Bare repository support**: Works in both bare and non-bare repositories.
- **Index/worktree updates**: When `HEAD` moves, the index and worktree are updated to match the new `HEAD`, preserving unrelated staged or unstaged changes.
- **Ref updates**: Moves branches pointing to the dropped commit to its parent, with configurable scope via `--update-refs=(branches|head)`.
- **Edge case handling**: Refuses to drop root commits, merge commits, or commits whose descendants contain merges (due to current limitations in `git replay`).
- **Dry-run mode**: Supports `--dry-run` to preview ref updates without modifying the repository.

The implementation reuses existing `git history` infrastructure (e.g., `replay_result_queue_update()` for ref updates) and the modernized reset API (introduced in earlier patches) to avoid code duplication. The patch includes **561 lines of test coverage** in `t/t3454-history-drop.sh`, verifying edge cases like detached `HEAD`, bare repositories, conflict detection, and preservation of local changes.

The commit message and documentation (`git-history.adoc`) clearly explain the command’s behavior, limitations, and use cases, including examples. The code is well-structured, with helper functions like `update_worktree()` and `find_head_tree_change()` encapsulating key logic. No new technical debt is introduced, and the patch aligns with the series’ broader goals: advancing `the_repository` removal, modernizing the reset API, and expanding the `git history` command’s capabilities.
