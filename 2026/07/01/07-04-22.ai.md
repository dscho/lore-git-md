This is the fourth patch in Johannes Schindelin’s 13-patch Coverity-driven cleanup series. It fixes an error-path bug in `start_command()` in `run-command.c` where the function could call `close(-1)` when rolling back pipe setup after a partial failure. The issue arises because the rollback logic tests `if (cmd->in)` or `if (cmd->out)` before closing, but the `CHILD_PROCESS_INIT` sentinel value of `-1` (meaning "no descriptor") is non-zero and so passes the test. The patch replaces these checks with `if (cmd->in > 0)` and `if (cmd->out > 0)`, which correctly reject both the `-1` sentinel and the parent’s standard streams (`0`, `1`, `2`). The fix is mechanical and matches the idiom already used elsewhere in the same function. Coverity flagged this as CID 1049722 ("Argument cannot be negative"). No new symbols or user-visible behavior changes are introduced; the patch is purely about internal correctness. The change is small (three lines modified) and uncontroversial, fitting the series’ goal of plugging resource leaks and error-path bugs.
