This is patch 9/13 in Johannes Schindelin's Coverity-driven cleanup series. It fixes resource leaks in the `git worktree add` subcommand when branch creation fails.

The patch targets `builtin/worktree.c`, specifically the `add()` function. When `run_command()` fails while creating a new branch (around line 948), the function previously returned -1 immediately, bypassing cleanup of four allocations: `path` (from `prefix_filename`), `opt_track`, `branch_to_free`, and `new_branch_to_free`. The fix redirects the error return through the existing cleanup block at the end of the function, ensuring all four allocations are freed.

The change is mechanical: it replaces the direct `return -1` with a `goto cleanup` that sets `ret = -1` before jumping to the cleanup label. No new allocations or user-facing behavior changes are introduced. The patch is part of the broader effort to address Coverity-identified leaks and error-path bugs, and follows the same pattern as earlier patches in the series (e.g., consolidating error paths through cleanup labels).

This fix is uncontroversial and aligns with the series' goal of plugging leaks without altering functionality. The commit message clearly identifies the leak sources and the solution, making it easy to verify. Like the rest of the series, it is unlikely to introduce regressions and is suitable for early-cycle merging.
