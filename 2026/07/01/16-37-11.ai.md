This is the **final patch (10/10) in the v5 series** optimizing `paint_down_to_common()` for one-sided histories. It **removes the commit-date ordering fallback** entirely, completing the transition to generation-number-based traversal. The patch deletes the `corrected_commit_dates_enabled()` function (no remaining callers) and updates `paint_down_to_common()` to enforce generation ordering unconditionally, relying on the side-exhaustion optimization (introduced in earlier patches) to handle asymmetric queries efficiently.

The commit message benchmarks confirm the fallback is obsolete: `git merge-base --all v4.8 v4.9` on the Linux kernel repo now runs in **17ms** (v1 commit-graph) with **5,725 steps**, down from **3.25s** and **167,413 steps** in the baseline. The change is **low-risk**—the side-exhaustion logic (patch 8/10) already ensures early termination when one side empties, and the `min_generation` check in `paint_queue_get()` remains intact to guard against premature exits. Documentation updates clarify that generation ordering is now mandatory for topological correctness.
