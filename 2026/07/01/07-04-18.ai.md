This is a 13-patch series from Johannes Schindelin targeting resource leaks and error-path bugs identified by Coverity in the Git codebase. The series is motivated by a recent Coverity outage that paused scanning; these patches address the first batch of real (non-false-positive) issues found in core Git.

The patches touch a wide range of subsystems: loose-object handling (`loose.c`, `load_one_loose_object_map`), the run-command API (`run-command.c`), diff machinery (`diff-lib.c`, `line-log.c`), directory traversal (`dir.c`), submodules (`submodule.c`), worktree creation (`builtin/worktree.c`), IMAP sending (`imap-send.c`), reftable (`reftable/table.c`), fsmonitor daemon (`builtin/fsmonitor--daemon.c`), and Windows-specific code (`compat/mingw.c`, `compat/win32/exit-process.h`). The common theme is plugging leaks (file descriptors, memory, process handles) and ensuring proper cleanup when functions return early due to errors.

Key names and concepts introduced or modified include: `load_one_loose_object_map`, `download_https_uri_to_file`, `start_command`, `run_diff_files`, `process_ranges` in `line-log.c`, `read_one_dir`, `get_superproject_working_tree`, the IMAP upload buffer, the reftable filter, fsmonitor token-data, and `exit_process` ownership on Windows. The series does not change user-visible behavior; it is purely about internal correctness.

The patches are small and focused, typically adding a single `free`, `close`, or `release` call on an error path or restructuring control flow to ensure resources are owned and released consistently. The commit messages are terse but clear about what leak is being fixed.

This is a cleanup series that looks well-scoped and uncontroversial. The fixes are mechanical and unlikely to introduce regressions, making them suitable for merging early in a release cycle. The series is part of a larger Coverity-driven effort, but this batch stands alone.
