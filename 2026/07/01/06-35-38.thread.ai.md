Core problem or goal
Fix three memory leaks in Git’s commit-graph Bloom-filter code that surface when the test suite is run with `GIT_TEST_COMMIT_GRAPH_CHANGED_PATHS=1`. The leaks are in Bloom-filter slab initialization (`bloom.c`), revision-walk keyvec handling (`revision.c`), and line-log range-copy logic (`line-log.c`). Together with two other recent fixes (one from Peff, one from Kaartic Sivaraam), this series will eliminate most leaks that would appear if the `linux-TEST-vars` CI jobs were run with leak-checking enabled; remaining OpenSSL SHA-1–related leaks are deferred to a future series.

Key technical details

Additional detail: In `revision.c`, the leak occurs when Bloom-filter "keyvecs" are overwritten during multiple traversals of the same `rev_info` structure (e.g., in `git show foo bar`). The fix explicitly releases the old keyvecs before generating new ones in `prepare_to_use_bloom_filter()`. The alternative approach of reusing existing keyvecs was rejected to avoid subtle bugs if the pruning pathspec changes between traversals. In `line-log.c`, the leak stems from `line_log_process_ranges_arbitrary_commit()` making an unnecessary copy of a range before passing it to `add_line_range()`, which already makes its own copy. The fix eliminates the redundant copy by passing the original range directly.
