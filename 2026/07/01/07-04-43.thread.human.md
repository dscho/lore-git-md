This thread is about a targeted fix to Git's GitHub Actions CI workflows, authored by Johannes Schindelin. The issue is specific to private GitHub repositories: Dockerized CI jobs consistently fail with "cannot create async thread: Resource temporarily unavailable" errors, particularly in the t5xxx-t6xxx test range. The root cause appears to be lower PID limits on hosted runners for private repositories compared to public ones.

Schindelin's patch modifies `.github/workflows/main.yml` to enforce a PID limit of 16,384 (along with matching nproc and nofile ulimits) when the repository is private. This value was chosen based on detailed benchmarking: higher limits (like 64k) caused severe performance penalties (2-2.5x longer runtimes), while 16k resolved the failures without significant slowdowns. The change is minimal, affecting only the container configuration line, and won't impact public repository workflows.

The motivation is practical—Schindelin uses private repositories to test Microsoft Git changes before public release, and the current setup fails entirely in that context. The commit message includes thorough benchmarking data across all 13 Dockerized jobs, showing 16k as the optimal balance between stability and performance. No objections or alternative proposals have been raised so far, and the patch appears ready for merging.
