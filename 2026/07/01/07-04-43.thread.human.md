This thread is about a small but critical fix to Git’s CI configuration. Johannes Schindelin identified that GitHub Actions workflows consistently fail in private repositories because Dockerized jobs hit default PID limits, causing the error “cannot create async thread: Resource temporarily unavailable” during the t5xxx-t6xxx test range. The fix, now in its second version, conditionally raises PID, process, and file descriptor limits (`--pids-limit=16384`, `--ulimit=nproc=16384`, `--ulimit=nofile=32768`) only for private repositories, leaving public workflows unchanged.

The technical approach has not been contested. Junio C Hamano’s review focused only on the commit message’s clarity, which was addressed in v2. With no open objections or requests for changes, Junio has now proposed merging the patch into the `next` branch, signaling it is ready for integration testing. The patch touches only the GitHub Actions workflow file (`.github/workflows/main.yml`) and does not affect Git’s on-disk format, CLI, or runtime behavior in public repositories. Benchmarking data in the commit message confirms the chosen limits are optimal, avoiding the performance penalties seen with higher values.
