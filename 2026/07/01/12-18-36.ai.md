The motivation is clear: `strtoul` returns an `unsigned long`, which may be too small or too large for `size_t` depending on the platform. The new function uses `strtoumax` (which returns `uintmax_t`, guaranteed to be at least as large as `size_t`) and adds a range check against `SIZE_MAX` to prevent overflow. This ensures consistent behavior across 32-bit and 64-bit systems, a real concern for code that deals with object sizes or memory allocation.

The implementation is straightforward and follows the established pattern of the existing `strtoul_ui()` and `strtol_i()` helpers. It checks for negative signs, validates the entire string was consumed, and ensures the parsed value fits in a `size_t`. The function is marked `static inline` and placed in the compatibility header, making it immediately available to the rest of the codebase.
