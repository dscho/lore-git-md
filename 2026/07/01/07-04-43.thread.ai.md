Subject: [PATCH] ci: limit PIDs in Dockerized jobs on private GitHub repositories
Series version: standalone patch
Originating author: Johannes Schindelin (Dscho)
Thread type: bug fix / CI configuration

Core problem or goal
GitHub Actions workflows for Git’s CI fail consistently in private repositories due to Dockerized jobs hitting PID limits on the hosted runners. The error “cannot create async thread: Resource temporarily unavailable” surfaces in the t5xxx-t6xxx test range, blocking private-repository testing of Microsoft Git changes.

Current status
Patch submitted; no prior iterations. No review trailers yet.

Key technical details
- File touched: `.github/workflows/main.yml`
- New container options: `--pids-limit=16384`, `--ulimit=nproc=16384`, `--ulimit=nofile=16384`
- Conditional: only applied when `github.repository` is private
- No on-disk format or CLI changes; purely CI runtime behavior
- Benchmarking data in commit message shows 16 k is the optimal trade-off between stability and performance (64 k caused 2–2.5× longer runtimes)

Open questions and loose ends
None identified; the patch is self-contained and addresses the immediate blocker.
