This is the first patch in the v15 iteration of Pablo Sabater’s GSoC series implementing `git cat-file --batch-command` support for remote object metadata queries. It fixes a memory leak in the transport helper subsystem.

The patch addresses a straightforward but important issue: in `disconnect_helper()`, the `data->name` field allocated during `transport_helper_init()` is only freed if the helper process has already started (`if(data->helper)`). If the transport disconnects before the helper is fully initialized, `data->name` leaks. The fix moves the `FREE_AND_NULL(data->name)` call outside the conditional block so it always runs on disconnect.

This is a small, targeted bugfix with no behavior change—just a cleanup that plugs a leak in an error path. The commit message clearly explains the problem and the fix, and the change itself is minimal and safe. It’s a good example of the kind of preparatory work that often appears early in a series to ensure the foundation is solid before adding new functionality.

The patch is uncontroversial and ready to merge. It’s part of a larger, security-conscious effort, but this particular change is purely about memory hygiene.
