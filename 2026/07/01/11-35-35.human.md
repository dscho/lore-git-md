This is the eighth patch in Patrick Steinhardt’s 11-patch v8 series introducing the `git history drop` subcommand. The series is now technically complete and ready for merging after resolving a critical ref-resolution dispute in an earlier patch.

This patch removes an implicit assumption in `reset_working_tree()` that the index is always clean when the function is called. The assumption was introduced in 2022 as a minor performance optimization, but it breaks the upcoming `git history drop` command, which may call `reset_working_tree()` with a dirty index. The fix is straightforward: the cache tree update is now skipped only during hard resets, where the index is guaranteed to match the target tree. For non-hard resets, the cache tree is updated normally, ensuring correctness at a negligible performance cost.

The change is minimal (5 insertions, 3 deletions) and confined to `reset.c`. It preserves the existing behavior for all current callers while enabling the new use case. The commit message clearly explains the motivation and the trade-off, and the patch itself is clean and bisectable. No controversy or follow-up work is evident here — this is a routine preparatory refactoring for the drop subcommand.
