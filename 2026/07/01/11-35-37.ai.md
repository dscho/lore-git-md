This is the tenth patch in Patrick Steinhardt’s 11-patch `git history drop` series (v8). It splits the `handle_reference_updates()` function into two phases: **computation** (`compute_pending_ref_updates()`) and **application** (`apply_pending_ref_updates()`). This refactoring is preparatory for the final patch (11/11), which will use the split phases to implement the `drop` subcommand’s conflict detection and dry-run verification.

The patch is a **mechanical refactoring** with no behavior changes. It moves the ref-transaction logic into a new helper (`apply_pending_ref_updates()`) while preserving the existing error handling, transaction semantics, and reflog messaging. The split is motivated by the need to inspect pending ref updates *before* committing them, which the `drop` subcommand will use to detect conflicts (e.g., if replaying descendants would fail due to index/worktree state). The new `compute_pending_ref_updates()` function populates a `replay_result` struct with all ref updates that would occur, while `apply_pending_ref_updates()` executes them.
