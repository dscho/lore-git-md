This is part of Patrick Steinhardt’s 11-patch series introducing the `git history drop` subcommand, now at v8. This specific patch (6/11) refactors the reset API to make HEAD updates opt-in rather than mandatory.

The patch introduces a new `RESET_WORKING_TREE_UPDATE_HEAD` flag to `reset_working_tree()`. Previously, the function always updated HEAD unless explicitly told not to update any refs at all (via `RESET_WORKING_TREE_REFS_ONLY`). This created an awkward inconsistency with the existing `RESET_WORKING_TREE_UPDATE_ORIG_HEAD` flag. Now, callers must explicitly opt in to HEAD updates, which aligns better with the API’s design and prepares for a future caller (the `git history drop` command) that only wants to update the index and working tree.

The change is mechanical and confined to four files: `reset.h` (flag enum), `reset.c` (logic to check the new flag), and the callers in `builtin/rebase.c` and `sequencer.c`. All existing callers are updated to include the new flag, preserving their current behavior. The patch also adds a safety check to prevent updating ORIG_HEAD without updating HEAD, which would be nonsensical.

This is a well-motivated refactoring that cleans up the reset API and enables the later `git history drop` implementation. The commit message clearly explains the rationale, and the patch itself is small and focused. No controversy or open questions are evident here—this looks like a straightforward improvement that addresses prior feedback.
