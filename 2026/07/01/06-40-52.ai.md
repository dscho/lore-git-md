This is the second patch in Jeff King’s three-patch bugfix series targeting memory leaks in Git’s commit-graph Bloom filter code. It addresses a leak in `revision.c` where Bloom-filter "keyvecs" are overwritten during multiple traversals of the same `rev_info` structure (e.g., in `` `git show foo bar` ``), preventing the old keyvecs from being freed. The fix is a two-line addition to `prepare_to_use_bloom_filter()` that explicitly releases the old keyvecs before generating new ones, ensuring no memory is leaked. The commit message explains why reusing the existing keyvecs (an alternative approach) was rejected: it could introduce subtle bugs if the pruning pathspec changes between traversals, even if such cases are rare in practice. The leak is only detectable when running the test suite with `GIT_TEST_COMMIT_GRAPH_CHANGED_PATHS=1` and leak sanitizers enabled. No behavior changes or on-disk format modifications are introduced. The patch is minimal, well-motivated, and directly addresses the stated problem.
