This is the tenth patch in Patrick Steinhardt’s 11-patch v8 series implementing the `git history drop` subcommand. The patch splits the ref-update logic in `builtin/history.c` into two distinct phases: **computation** (identifying which refs need updating) and **application** (executing the updates). This refactoring is preparatory for the final patch (11/11), which will use the split phases to support dry-run conflict detection before replaying descendants.

The change is mechanical and confined to `builtin/history.c`. The original `handle_reference_updates()` function is replaced by two new helpers:
- `compute_pending_ref_updates()` gathers refs that need updating by calling `replay_revisions()` and manually handling HEAD updates.
- `apply_pending_ref_updates()` prepares and commits the ref transaction using the results from the first phase.

The patch preserves all existing behavior while making the code more modular. No new functionality is introduced, but the split phases are necessary for the drop subcommand’s conflict-checking logic in the next patch. The commit message clearly explains the motivation and the two-step process, and the diff is cleanly organized. This is a well-executed refactoring that directly supports the series’ goal.
