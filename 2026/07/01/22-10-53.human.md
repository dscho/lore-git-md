This is the first patch in a now-merged four-part bugfix series that standardizes help-flag exit codes across Git’s parse-options infrastructure. The patch itself is a small but necessary test prerequisite update: it adds an `SVN` prerequisite to `t/t1517-outside-repo.sh` to detect whether Subversion Perl modules are installed. Without this, the upcoming behavioral change—making help flags (`--help`/`-h`) exit with status 0 instead of 129—would cause `git-svn` tests to fail when Subversion is not available, since `git-svn` would die on startup rather than exhibiting the expected help behavior.

The change is straightforward and aligns with existing test patterns. It introduces a minimal Perl-based check for `SVN::Core` and `SVN::Repos` (version ≥1.1.0) and applies the prerequisite to the `svn` test case in the command loop. The commit message clearly ties this to the broader series goal, though the patch itself does not alter any user-facing functionality. It is purely infrastructure work to ensure the test suite remains robust as the exit-code behavior changes.

The patch is well-motivated and uncontroversial. It does not introduce new technical debt but does highlight the complexity of maintaining tests for optional features like `git-svn`. Since the series has already been merged, this patch is now part of Git’s history as a preparatory step for the larger fix. No further discussion or changes are expected.
