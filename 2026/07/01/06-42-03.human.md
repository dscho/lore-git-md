This is the third and final patch in Jeff King’s three-part bugfix series targeting memory leaks in Git’s commit-graph Bloom filter code. The series as a whole plugs leaks that only surface when the test suite is run with `GIT_TEST_COMMIT_GRAPH_CHANGED_PATHS=1`, making them invisible under normal test conditions.

This patch fixes a leak in `line-log.c` where `line_log_process_ranges_arbitrary_commit()` unnecessarily copies a range before passing it to `add_line_range()`, which already makes its own copy. The extra copy is simply dropped, eliminating the leak. The bug dates back to the original Bloom filter integration in 2020 but went unnoticed because the test suite never explicitly combined line-log and Bloom filter features. Jeff provides a simple reproduction recipe using leak sanitizers and the existing `t4211-line-log.sh` test, though he notes that more targeted test coverage would be useful—though not strictly necessary for this fix.

The patch is small (one line changed, two removed) and self-contained, touching only `line-log.c`. It changes no behavior beyond plugging the leak, and the on-disk format remains untouched. Like the rest of the series, it’s a clean, well-explained fix from a seasoned contributor, and there’s no indication of controversy or open questions. If you care about leak-free Git or Bloom filter correctness, this series is worth a quick look.
