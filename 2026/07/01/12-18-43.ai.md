This is the ninth patch in the v15 series implementing `git cat-file --batch-command` support for remote object metadata queries. It adds server-side capability advertisement for the `object-info` feature, allowing clients to discover what metadata a server can provide before making requests.

The patch updates both the protocol documentation and the server implementation. In `gitprotocol-v2.adoc`, it clarifies several protocol details: full object IDs are now explicitly required (no short OIDs), the `obj-size` field is formally defined, and the response format is documented to return only the object ID when the server doesn't recognize it. The documentation also fixes a minor syntax error (removing an extra closing parenthesis).

On the implementation side, the patch modifies `serve.c` to advertise supported `object-info` attributes when the `transfer.advertiseobjectinfo` configuration is enabled. Currently only the "size" attribute is supported, so the server advertises "size" in the capability value. The advertisement is disabled by default, matching the project's conservative approach to new protocol features.

This is a well-motivated protocol design patch that addresses earlier review feedback about forward compatibility. The documentation improvements make the protocol behavior unambiguous for both implementers and future extensions. The implementation is minimal and focused, touching only the capability advertisement mechanism without changing core object lookup logic. The patch carries Helped-by trailers from Jonathan Tan and Christian Couder, indicating substantive review engagement.
