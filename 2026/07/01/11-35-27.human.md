This is the v8 iteration of Patrick Steinhardt’s 11-patch series introducing the `git history drop` subcommand, which removes a commit from history and replays its descendants on top of its parent. The series is now **unblocked** after resolving the high-impact technical dispute over ref resolution in `find_head_tree_change()` that stalled v7.

The key change in v8 is a targeted fix for the ref-resolution flaw identified by Junio C Hamano: `refs_resolve_ref_unsafe()` now receives the `RESOLVE_REF_READING` flag, ensuring it returns `NULL` when the reference cannot be resolved, and the code no longer assumes a detached HEAD will map to the literal string `"HEAD"`. A new test case verifies that `--update-refs=head` works correctly with a detached HEAD. The rest of the series is unchanged from v7, retaining all prior improvements: the `reset_working_tree()` rename, dry-run mode, opt-in HEAD updates, the `replay_result_queue_update()` helper, and the two-phase ref-update architecture.

This version looks ready for merging. The dispute that blocked v7 is resolved, the commit messages are clear, and the test coverage (561 lines in `t/t3454-history-drop.sh`) is thorough. The series advances several ongoing efforts—`the_repository` removal, reset API modernization, and the experimental `git history` command—while adding a significant new capability. If no new issues surface, this is likely the final iteration.
