This is a brief, surface-level review of the second patch in Jeff King’s three-patch series fixing memory leaks in Git’s commit-graph Bloom filter code. Derrick Stolee reaffirms his support for the fix in `revision.c`, calling it "obviously-correct and simple." The patch itself adds a single line to `prepare_to_use_bloom_filter()` that explicitly frees old Bloom-filter "keyvecs" before generating new ones, preventing leaks during multiple traversals of the same `rev_info` structure (e.g., in `` `git show foo bar` ``). This aligns with the approach Patrick Steinhardt previously endorsed as safer than reusing existing keyvecs, which could introduce subtle bugs if the pruning pathspec changes between traversals. The review offers no new technical critique or alternative suggestions—just a straightforward endorsement of the chosen solution. The series remains uncontroversial and ready for merging.
