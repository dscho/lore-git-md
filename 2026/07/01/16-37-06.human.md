This is the fifth patch in a **ready-to-merge performance optimization series** for Git’s commit-reach subsystem. The series targets `paint_down_to_common()`, the core function behind merge-base calculations, and this patch adds **trace2 instrumentation** to measure the number of commits visited during the walk.

The patch introduces a step counter in `paint_down_to_common()` and emits a `trace2_data_intmax` event at the end of the walk, making the step count observable via `GIT_TRACE2_EVENT`. This allows developers to quantify the impact of future optimizations without relying solely on wall-clock benchmarks. The test suite is updated to verify the step counts across all commit-graph modes (none, full, half, no-gdat) using a new helper, `test_paint_down_steps`, which checks that trace2 events appear exactly once and match expected values.

The changes are **minimal and focused**: five lines added to `commit-reach.c` and a refactoring of `t/t6600-test-reach.sh` to support per-mode trace2 logging. The test updates include a new test case (`merge-base --all commit-walk steps`) that verifies step counts for a simple query, demonstrating the instrumentation’s utility. The patch is **uncontroversial** and aligns with the series’ goal of providing self-verifying performance metrics.

This is a **clean, low-risk addition** that complements the series’ broader performance improvements. The instrumentation is already being used in later patches to validate the side-exhaustion optimization, and the test helper (`test_paint_down_steps`) will likely see reuse in future commit-reach patches. No further changes are expected.
