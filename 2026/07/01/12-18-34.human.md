This is the fifteenth iteration of a security-focused feature series that adds `` `git cat-file --batch-command` `` support for querying remote object metadata without downloading full objects. The series is now complete and ready for merging, addressing all prior review feedback including memory safety improvements, protocol documentation updates, and style fixes.

The core feature introduces a new `` `remote-object-info` `` command that lets clients request object sizes (and eventually other metadata) from servers supporting the `object-info` capability in Git’s protocol v2. The key security improvement remains dynamic capability-based validation: the client validates requested format placeholders against what the server advertises, preventing information leaks. This version adds stricter numeric conversion handling (`` `strtoumax_szt()` ``) and documents the protocol’s extensibility mechanism in `` `gitprotocol-v2.adoc` ``.

Notable changes since v14 include:
- Replaced `` `strtoul_szt()` `` with `` `strtoumax_szt()` `` to avoid platform-dependent `` `size_t` ``/`` `unsigned long` `` mismatches
- Added `` `BUG()` `` assertions in the object-info request path for invariant checking
- Moved protocol documentation updates into the server capability patch (9/13)
- Reworded commit messages for consistency and clarity
- Fixed minor style nits and typos

The series maintains backward compatibility while being forward-compatible for future metadata types like `` `%(objecttype)` ``. Currently only `` `%(objectsize)` `` is supported end-to-end; other fields return empty strings. The implementation includes comprehensive test coverage (699-line `` `t/t1017-cat-file-remote-object-info.sh` ``) and shared test infrastructure (`` `t/lib-cat-file.sh` ``).

All substantive reviews from prior versions have been addressed, with no outstanding objections. The GitHub CI run shows all tests passing. The series demonstrates careful attention to security, memory safety, and protocol design, making it a well-crafted addition to Git’s remote capabilities.
