This is the third patch in Patrick Steinhardt’s 11-patch series introducing the `git history drop` subcommand. It renames the `reset_head()` function to `reset_working_tree()` to better reflect its evolving purpose, as later patches will make HEAD updates optional. The change is purely mechanical—no behavior is altered yet—but it prepares the codebase for the more substantial API modernization coming in subsequent patches.

The patch touches four files (`builtin/rebase.c`, `reset.c`, `reset.h`, and `sequencer.c`), updating function and struct names to match the new nomenclature. All callers are adjusted to use `reset_working_tree()` and `struct reset_working_tree_options` instead of the old names. The commit message explains the rationale clearly: once HEAD updates become optional, the function’s name should no longer imply a focus on the HEAD reference.

This is a refactoring step in a larger effort to modernize Git’s reset machinery, which will later enable the `git history drop` command. The change is uncontroversial and aligns with prior feedback from Phillip Wood, who suggested the rename. No new issues are introduced, and the patch is ready for review as part of the series. If you’re following the `git history` work or the reset API overhaul, this patch is worth noting for its role in setting up the later functional changes.
