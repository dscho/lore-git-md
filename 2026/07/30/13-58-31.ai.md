This is the second patch in Harald Nordgren’s **v24 `git branch --delete-merged` series**, which is now ready for merging. This patch refactors the `delete_branches()` function in `builtin/branch.c` to replace its separate `force` and `quiet` boolean parameters with a single `unsigned int flags` argument and an enum (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is purely mechanical and introduces no behavioral differences, but it eliminates the risk of stale cached values by testing the flags directly at each use site rather than forwarding or mutating them.

The patch is part of a **flags-based API refactoring** that spans patches 2–4/7, enabling future additions (like `DELETE_BRANCH_SKIP_UNMERGED` and `DELETE_BRANCH_DRY_RUN`) without further signature churn. The enum and flag names follow Git’s established naming conventions, and the implementation is careful to avoid mixing local `ref_flags` with the new `flags` parameter. The call site in `cmd_branch()` is updated to construct the flags bitmask from the existing `delete` and `quiet` variables, preserving the current behavior for `git branch -d` and `git branch -D`.

This patch is **low-risk and well-tested**; the thread context confirms that the flags-based API was identified as a maintenance hazard in earlier versions due to local boolean caching, and this refactoring resolves that issue by ensuring flags remain the single source of truth. The change is a prerequisite for the `--delete-merged` subcommand (patch 5/7) and the `--dry-run` flag (patch 7/7), both of which rely on the new flags API.
