This is the first patch in a seven-part RFC v2 series introducing `--drop-filtered` to `git repack`, a feature aimed at partial clones. The patch adds the command-line options `--drop-filtered` and `--dry-run` to `git repack`, along with all the validation logic needed to enforce their constraints.

The new options are straightforward: `--drop-filtered` will eventually delete objects matching a filter spec (currently limited to `blob:limit=<n>`), while `--dry-run` reports what would be dropped without making changes. The patch keeps them separate rather than combining them (e.g., `--drop-filtered=dry-run`) to match Git’s existing `--dry-run` conventions and leave room for future expansion. The validation is thorough: `--drop-filtered` requires `--filter` and `-a`, rejects `--filter-to`, demands a promisor remote, and disables bitmaps (either by erroring on an explicit `-b` or silently overriding a config-driven setting). The patch also introduces the test script `t/t7706-repack-drop-filtered.sh`, which verifies all the option constraints before any object traversal happens.

This is a well-scoped, well-explained change that addresses the feedback from v1. The commit message clearly documents the design choices, and the validation logic is exhaustive. The patch is part of a larger effort to reclaim disk space in partial clones, and it looks like a solid foundation for the rest of the series. If you care about partial clones or repack optimizations, this is worth following.
