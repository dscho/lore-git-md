This is the **v24 submission of Harald Nordgren’s `git branch --delete-merged` series**, addressing the two blocking correctness issues identified in v23. The series is now **implementation-complete and ready for merging**, pending final review. The changes in v24 focus on:

1. **Correct push-detection logic**: The `branch_pushes_to_upstream()` function now maps branches through the configured *push* and *fetch* refspecs before deciding whether pushing would update their upstream. This fixes the v23 flaw that could produce false negatives (deleting branches that should be preserved) or false positives (keeping branches that should be deleted). The new implementation applies the *push* refspec to the local branch, applies the *fetch* refspec in reverse to the result, and compares that to the upstream branch, ensuring accurate detection regardless of `remote.pushDefault` configuration.

2. **Simplified stacked-branch protection**: The logic now protects only the *direct* upstream of a surviving branch, deleting deeper merged bases and clearing their stale upstream configurations. This resolves the v23 test discrepancy by aligning the implementation with the design goal of clearing upstream configs for kept (merged) branches whose own upstream is being deleted. The change removes the graph traversal (`visited_branch_names` strset) and updates the test to expect cleared upstream configs for kept merged branches, simplifying the implementation while maintaining safety.

The rest of the series remains **identical to v23**, which Junio C Hamano confirmed has no outstanding issues. The core command, `--delete-merged`, safely deletes local branches merged into their upstream (matching one or more `--delete-merged` patterns) while preserving branches used as upstreams for unmerged branches, checked-out branches, branches with missing upstreams, and branches opted out via `branch.<name>.deleteMerged=false`. The `--dry-run` flag provides a safe preview without modifying refs or config.

Key technical details:
- **Push-detection fix**: The new `branch_pushes_to_upstream()` implementation ensures branches like `main` tracking `origin/main` are preserved even when `remote.pushDefault` names a fork, addressing the v23 correctness issue.
- **Stacked-branch protection**: The simplified logic now clears upstream configs for kept (merged) branches whose own upstream is being deleted, avoiding broken dependency chains while cleaning up stale configs. The test for "clears the deleted upstream of a protected branch" verifies this behavior.
- **Flags-based API**: Patches 2-4/7 refactor `delete_branches()` to use `unsigned int flags` (e.g., `DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`) instead of boolean arguments, eliminating local caching to ensure flags remain the single source of truth.
- **`--forked` filter**: The foundation for `--delete-merged`, supporting exact refnames, remote shorthand, and shell-style globs. The v24 changes do not affect this component.

The series touches `builtin/branch.c`, `ref-filter.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.txt`, and `t/t3200-branch.sh`. The implementation is **well-motivated** (addressing a real workflow pain point), **thoroughly tested** (with comprehensive integration tests covering all safety checks and edge cases), and **aligned with Git’s API consistency expectations**. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.

Patch 5/7’s documentation now clarifies that `--delete-merged` takes upstream *patterns* (not just branch names) and that the push-detection logic uses the remote’s configured push and fetch refspecs. The test suite has been updated to verify the push-detection fix and the simplified stacked-branch protection logic.
