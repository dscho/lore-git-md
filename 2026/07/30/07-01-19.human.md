This is a feature patch introducing a new `--date=elapsed` format and corresponding `%aX`/`%cX` pretty-format placeholders. The patch is well-structured, thoroughly tested, and addresses a clear gap in Git's date formatting: the existing `--date=human` and `%cr`/`%ch` placeholders produce localized phrases like "2 days ago" that obscure the exact time elapsed, while raw timestamps (`%ct`) require manual calculation.

The new format mimics `uptime(1)` output, showing elapsed time in a compact, script-friendly way (e.g., "8h 7m 48s" or "01y 11M 05d 13h 05m 13s" for the padded variant). The implementation is clean: it adds a new `show_date_elapsed()` helper in `date.c`, wires it through the existing date infrastructure, and updates documentation, tests, and shell completion. The author even includes a thoughtful discussion of open questions (placeholder letter choice, future timestamp behavior, and whether the padded variant should be a separate flag), inviting maintainer feedback before finalizing the design.

The patch is self-contained and unlikely to break existing functionality. It passes the full test suite and includes targeted tests for both the date helper and pretty-format equivalence. The motivation is practical and aligns with Git's philosophy of providing precise, machine-readable output when needed. This looks like a polished RFC that could land with minimal iteration.
