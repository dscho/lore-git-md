Subject: `git config --global` reads only one file despite docs claiming it reads both
Series version: standalone bug report (now with proposed patch series v2)
Originating author: Nils Fahldieck
Thread type: bug report with proposed fix

Core problem or goal
The `--global` flag in `git config` is documented to read both `~/.gitconfig` and the XDG config file (`~/.config/git/config`), but the implementation reads only one file (prioritizing `~/.gitconfig` if readable, even if empty). This creates a discrepancy between documented and actual behavior, leading to user confusion, practical failures in tools relying on `--global`, and inconsistencies with `git config --get` (which *does* read both files). The issue is systemic: the single-file limitation also causes unintuitive behavior with `--global --no-includes` and violates user expectations of uniform behavior across commands.

The series aligns the code with the documentation (Option A: make `--global` read both files) and is nearly ready for submission. Nils Fahldieck has offered to review the v2 series once posted, signaling active community engagement. The maintainer (Junio C Hamano) previously agreed the documentation is incorrect but did not endorse a fix direction; the lack of consensus left the issue unresolved for over a year. Delilah’s revival of the series, combined with renewed emphasis on cross-command inconsistencies (`--get` vs. `--global`) and real-world tooling failures, strengthens the case for merging the code change. No evidence of integration branch status (e.g., `seen`, `next`, or `master`).

Backward compatibility is preserved: no existing configurations break, and users gain access to settings in the XDG file.
