This is the sixth patch in Harald Nordgren’s **v24 `git branch --delete-merged` series**, which is now implementation-complete and ready for merging. This patch adds a **per-branch opt-out mechanism** via the `branch.<name>.deleteMerged` config key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The change is straightforward and well-motivated: setting `branch.<name>.deleteMerged=false` prevents `--delete-merged` from deleting the branch, with a non-quiet skip message explaining the opt-out. The implementation checks the config during candidate filtering in `delete_merged_branches()` using `repo_config_get_bool()`, and the opt-out is ignored by traditional `git branch -d` (which continues to use the normal merge check). Documentation is updated in both `branch.adoc` and `git-branch.adoc`, and the test suite verifies opt-out behavior, skip messages, explicit deletion, and branch state via `git for-each-ref`.

The patch is **low-risk and narrowly scoped**, touching only `builtin/branch.c` and the documentation. The opt-out mechanism complements the series’ existing safety checks (checked-out branches, missing upstreams, push divergence, stacked-branch protection) and addresses a real workflow pain point: iterative topic branches that are partially merged upstream but still under active development. Phillip Wood’s earlier review suggested only a mechanical test improvement (`for-each-ref` verification via `check_branches`), which has been applied. The implementation is **complete and uncontroversial**, with no outstanding issues. This patch, like the rest of the series, is ready for merging.
