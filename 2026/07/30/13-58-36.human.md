This is the final patch in Harald Nordgren’s **`git branch --delete-merged`** series, adding `--dry-run` support to the new subcommand. The patch is part of a **feature** effort that is now **implementation-complete and ready for merging**, having resolved all prior blocking issues in v24.

The `--dry-run` flag lets users preview which branches would be deleted by `--delete-merged` without modifying any refs or configuration. It prints one line per affected branch (e.g., "Would delete branch merged (was abc123).") and is only valid when combined with `--delete-merged`—the command rejects it otherwise. The implementation avoids side effects during dry runs by skipping both ref deletion and the clearing of stale upstream configurations, ensuring the preview matches the real operation exactly. The patch also rejects the nonsensical `--dry-run --quiet` combination, as printing nothing would defeat the purpose of a preview.

The change touches `builtin/branch.c` (adding the `DELETE_BRANCH_DRY_RUN` flag and plumbing it through the deletion logic), `Documentation/git-branch.adoc` (documenting the new option), and `t/t3200-branch.sh` (adding tests for dry-run output, edge cases, and the rejection of invalid combinations). The tests verify that dry-run output matches the real deletion output, that no refs or config are modified, and that the command fails when `--dry-run` is used without `--delete-merged`.

This patch completes the series’ safety architecture, giving users a low-risk way to sanity-check broad patterns (like `--delete-merged 'origin/*'`) before committing to deletions. The implementation is straightforward and aligns with Git’s existing dry-run conventions (e.g., `git clean --dry-run`). With this patch, the series is now fully functional and ready for Junio’s queue.
