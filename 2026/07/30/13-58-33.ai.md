This is the fourth patch in Harald Nordgren’s **v24 `git branch --delete-merged` series**, which is now implementation-complete and ready for merging. This patch prepares the `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that prevents falling back to `HEAD` when checking whether a branch is merged into its upstream.

The change is minimal and targeted: it modifies `branch_merged()` to skip the `HEAD` fallback logic when `head_rev` is `NULL` (signaled by the new flag) and updates `delete_branches()` to avoid looking up `HEAD` when the flag is set. This ensures `--delete-merged` only deletes branches that are merged into their upstream, without considering `HEAD` as a fallback. Existing callers (e.g., `git branch -d`) retain their current behavior, as the flag is not set for them.

The patch is part of the **flags-based API refactoring** (patches 2-4/7) that replaces boolean arguments with an `unsigned int flags` parameter, eliminating local boolean caching to ensure flags remain the single source of truth. This refactoring was motivated by Phillip Wood’s feedback about API consistency and has been thoroughly tested to avoid behavioral regressions. The new flag is checked at both the commit-checking (`branch_merged()`) and deletion (`delete_branches()`) stages, ensuring the `--delete-merged` subcommand adheres to its design goal of only deleting branches merged into their upstream.

The patch touches only `builtin/branch.c` and is **low-risk**, as it introduces no behavioral changes for existing callers. The commit message clearly explains the motivation and the conditional logic, and the code is well-aligned with the series’ broader goal of enabling safe, automated local branch cleanup. This patch is a prerequisite for the core `--delete-merged` implementation (patch 5/7) and is ready for merging alongside the rest of the series.
