This is the sixth patch in the seven-patch RFC v2 series introducing `git repack --drop-filtered` for partial clones. It implements the two critical safety guards that were blocking concerns from the v1 review: refusing to run during ongoing operations (merge, rebase, cherry-pick, etc.) and refusing to drop blobs that the current index references.

The patch adds about 50 lines to `builtin/repack.c` and 36 lines to the test script. The first guard uses `wt_status_get_state()` to detect any in-progress operation and dies with a clear error message if one is found. The second guard reads the repository index and checks every cache entry against the `drop_oids` set; if a match is found, it dies and reports the offending path. Both guards are skipped for bare repositories, which have neither a worktree nor an index. The tests verify that the guards work as intended: one test creates a conflicting merge and confirms the command refuses to run, while the other adds a large blob to the index and confirms the command refuses to drop it.

This is a well-motivated, narrowly scoped patch that directly addresses the safety concerns raised in v1. The implementation is clean, the error messages are clear, and the test coverage is thorough. The patch is ready for review and should not be controversial.
