This is a brief follow-up in the ongoing `git rebase --update-refs` symref bugfix thread. The design debate is now definitively settled: Junio C Hamano concedes that the current patch’s robust approach (allowing HEAD to point outside `refs/heads/`) must be retained because TopGit, a real-world tool, actively relies on this behavior. TopGit sets HEAD to `refs/top-bases/...` and uses `git rebase` as part of its workflow, so narrowing the scope would break existing users. The concession closes the last open design question for this series; the author, Son Luong Ngoc, is expected to send a v4 incorporating only minor refinements (comments, test organization) rather than any functional change. The latent `head_ref` buffer clobbering bug remains unaddressed and is still slated for a follow-up patch.
