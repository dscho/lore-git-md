This is the first patch in the v2 RFC series introducing `--drop-filtered` to `git repack`, targeting partial clones. It adds the new command-line options `--drop-filtered` and `--dry-run` to `builtin/repack.c` and implements all validation logic, but does not yet perform the actual object enumeration or deletion (that comes in later patches).

The patch wires up the options, enforces their invariants, and ensures they interact correctly with existing repack flags. Key constraints: `--drop-filtered` requires `--filter` (currently limited to `blob:limit=<n>`), `-a`, and a configured promisor remote; it conflicts with `--filter-to` and `--write-bitmap-index` (with explicit command-line `-b` triggering an error, while config-driven bitmaps are silently disabled). The `--dry-run` flag is only valid when paired with `--drop-filtered`. All error messages are tested in the new `t/t7706-repack-drop-filtered.sh` script.

The commit message explains the CLI design rationale (keeping `--dry-run` separate for consistency with other Git commands) and documents the bitmap-handling logic (distinguishing command-line vs config-driven settings). The patch is well-scoped: it defers the actual object walking and deletion to follow-ups, but the validation layer is complete and tested. This is a solid foundation for the rest of the series, and the safety checks here address the critical feedback from v1.
