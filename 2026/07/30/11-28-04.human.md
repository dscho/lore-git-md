This is the second patch in a two-patch bugfix series for `git mv`, now in its fifth iteration (v5). The patch addresses a long-standing correctness and usability issue: `git mv` previously failed to detect missing destination directories, non-directory path components, or tracked symlinks in the destination path until the `rename()` syscall, leading to misleading error messages and potential index corruption.

The patch adds an early check in `builtin/mv.c` that rejects three problematic cases before attempting the move: missing leading directories, non-directory components, and *any* tracked symlink in the destination path (regardless of target type). The symlink check uses `has_symlink_leading_path()`, borrowed from `git apply`, to avoid following symlinks and align with Git's policy of not traversing tracked symlinks. The error messages now clearly identify the destination as the problem, improving usability. The check is guarded by a new helper function, `needs_worktree_rename()`, which deduplicates the logic determining whether a move requires a worktree rename, ensuring consistency between the early check and the actual `rename()` call.

Test coverage in `t/t7001-mv.sh` is comprehensive, adding 102 new lines that cover symlinks as both final and intermediate components, missing directories, non-directory components, `--dry-run` detection, and force-flag behavior. The tests include a regression case for the index corruption scenario, verifying that the index remains unchanged when a move through a symlink is rejected. The patch introduces two new translatable strings but does not change existing ones or the on-disk format.

This version implements Junio's requested refactoring to deduplicate logic and optimize memory allocation by deferring the `dirname` copy until needed. The series is technically complete, with no outstanding objections or unresolved technical concerns. Junio has explicitly approved the approach, and the only remaining loose ends are the acknowledged TOCTOU race (unaddressed) and potential bikeshedding on the helper function name. The patch is well-crafted, with clear commit messages and thorough test coverage, and looks ready for integration.
