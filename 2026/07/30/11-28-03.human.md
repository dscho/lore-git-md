This is the first patch in a two-patch bugfix series for `git mv`. It addresses a long-standing usability issue where `git mv` emits misleading error messages when a rename fails. Currently, the error message only mentions the source path, even when the failure is actually due to a missing directory in the *destination* path. For example, `git mv a/file b/no-such-dir/file` would blame `a/file`, which exists, rather than indicating that `b/no-such-dir/` is missing.

The fix is simple and surgical: the error message now includes both the source and destination paths, making it immediately clear which part of the operation failed. The change is a one-line modification in `builtin/mv.c`, replacing the existing `die_errno()` call with a version that prints both paths. This is a pure usability improvement with no behavior changes, no new edge cases, and no risk of regression. The commit message explains the rationale clearly, and the patch has been stable since v2 of the series.

Junio has already approved this patch ("Makes sense"), and it has seen no further discussion or objections. It is ready for integration and should be uncontroversial. The only reason it hasn’t landed yet is that it is part of a two-patch series, and the second patch (which adds an early directory existence check) was still being refined. With v5 now final, this patch can be merged alongside the second one.
