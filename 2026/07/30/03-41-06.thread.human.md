This thread is about a small but important safety improvement to `git stash`. Junio C Hamano has proposed a two-patch series that prevents `git stash drop` and `git stash pop` from accepting time-based stash selectors like `stash@{2.days.ago}`. These selectors can accidentally remove more stash entries than the user intends, so the change makes the commands safer by only allowing positional selectors (e.g., `stash@{4}`).

The first patch added a `stash_idx` field to track the positional index of a stash entry, and the second patch (just summarized) uses this field to reject time-based selectors in `drop` and `pop` while keeping them working in other subcommands like `show` and `apply`. The implementation is straightforward, touching only `builtin/stash.c`, the documentation, and the test suite. No reviews have come in yet, but the series is self-contained and doesn’t raise any open questions so far. If accepted, this will be a minor but welcome usability fix.
