This thread is a two-patch series from Junio C Hamano that tightens the safety of `git stash drop` and `git stash pop` by rejecting time-based stash selectors like `stash@{2.days.ago}`. These selectors can silently remove more stash entries than the user expects, so the series now makes them fail with an error while still allowing positional selectors like `stash@{4}`.

The implementation is complete and under review. The first patch adds a `stash_idx` field to track the positional index of a stash entry, and the second uses this field to enforce the new restriction. Tests confirm the behavior change works as intended. Ben Knoble raised a technical question about a hard-coded numeric limit in the `strtoul` conversion, but Junio clarified that the limit is intentional—it mirrors Git’s `approxidate` parser behavior to avoid treating large integers as positional indices when they could plausibly be timestamps. This resolves the only open question, and no further changes are expected unless new feedback emerges. The series remains under review with no objections so far.
