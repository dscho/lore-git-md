This is the fourth patch in Harald Nordgren’s **v24 `git branch --delete-merged` series**, which is now ready for merging. This patch prepares the `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that prevents falling back to `HEAD` when checking whether a branch is merged into its upstream.

The change is straightforward: when the new flag is set, `delete_branches()` skips the `HEAD` fallback entirely, ensuring that `--delete-merged` only deletes branches that are merged into their upstream (and not into `HEAD`). This aligns with the design goal of making `--delete-merged` a precise, upstream-focused cleanup tool. The patch also updates the `branch_merged()` helper to avoid printing a "gentle reminder" about `HEAD` fallback when `head_rev` is `NULL`, since callers using the new flag have already confirmed the branch has an upstream.

The implementation is minimal and targeted, touching only `builtin/branch.c`. It introduces no behavioral changes for existing callers (like `git branch -d` or `git branch -D`), which continue to use the `HEAD` fallback as before. The new flag will be used by the `--delete-merged` subcommand in patch 5/7 to enforce its stricter merge-checking logic. This patch is part of the series’ broader refactoring to replace boolean arguments with a flags-based API, improving clarity and extensibility. The series as a whole is well-tested, with this patch’s behavior verified by the test suite in later patches.
