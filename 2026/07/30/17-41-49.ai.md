This is the third patch in the RFC v2 series introducing `--drop-filtered` to `git repack` for partial clones. It extends `repack_promisor_objects()` to accept an optional `to_drop` oidset parameter, allowing the rebuilt promisor pack to exclude specified objects. The change is minimal and backward-compatible: all existing callers pass `NULL`, so behavior remains unchanged. The new parameter is plumbed through to the `write_oid()` callback, which skips objects present in `to_drop`. This is the core mechanism that later patches will use to remove filtered promisor blobs.

The patch touches three files: `builtin/repack.c` (updates the single existing call site to pass `NULL`), `repack-promisor.c` (adds the `to_drop` field to the `write_oid_context` struct and implements the exclusion logic in `write_oid()`), and `repack.h` (updates the function signature). The exclusion logic is straightforward: `write_oid()` checks `oidset_contains(ctx->to_drop, oid)` and returns early if the object is marked for removal. The commit message clearly states the purpose: this is the mechanism `--drop-filtered` will use to rebuild promisor packs without the filtered blobs.

This is a well-scoped refactoring that enables the feature without introducing new behavior. The patch is clean, with no functional changes for existing users, and the exclusion logic is simple and safe. The `to_drop` oidset is only consulted when non-NULL, so there is no performance impact for the default case. The change is a prerequisite for the later patches that implement the actual drop logic, and it integrates naturally with the existing promisor repack machinery. Reviewers familiar with the promisor subsystem (e.g., Christian Couder or Patrick Steinhardt) will likely focus on whether the exclusion logic is robust and whether the function signature change is the right abstraction. The patch is uncontroversial and looks ready for integration.
