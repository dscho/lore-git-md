This is part of Harald Nordgren’s `git branch --delete-merged` series, specifically **patch 2/7 of v24**, which refactors the branch deletion API to use a flags-based argument instead of separate boolean parameters. The patch converts `delete_branches()` and `check_branch_commit()` to accept an `unsigned int flags` parameter with enum values (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`), eliminating local boolean caching to ensure flags remain the single source of truth. This is a **pure refactoring** with no behavioral changes, serving as the foundation for later patches that add new flags (e.g., `DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_DRY_RUN`).

The implementation is mechanical and well-tested, directly addressing Phillip Wood’s earlier concern about maintaining API consistency. By testing flags at each use site (rather than caching them in local variables), the patch prevents stale values when flags are mutated or forwarded. The changes are confined to `builtin/branch.c` and introduce no new functionality—existing callers (like `git branch -d`) continue to work exactly as before. This patch is **low-risk and uncontroversial**, and the series as a whole is now ready for merging after the v24 fixes resolved the two blocking correctness issues.
