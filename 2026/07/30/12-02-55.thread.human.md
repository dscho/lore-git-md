This thread is about a small documentation patch to `git-format-rev.adoc` that’s part of the ongoing effort to standardize AsciiDoc markup across Git’s man pages. Kristoffer Haugsbakk sent a one-line change to wrap the `<subject>` placeholder in a `[synopsis]` block, following the pattern established in earlier patches like the `git-show` conversion. Patrick Steinhardt reviewed it and questioned whether `[synopsis]` is the right choice for a code example that isn’t actually a command synopsis, suggesting backticks as a simpler alternative.

The discussion has since shifted to whether to stick with the established pattern for consistency or adjust it for this case. Kristoffer acknowledged Patrick’s point and even proposed an alternative: rewriting the example to use literal `"%s"` and `"<subject>"` strings, which would avoid the need for special markup entirely. The tone remains collaborative, and there’s no disagreement about the patch’s goal—just the best way to implement it. The outcome could set a precedent for how strictly the project adheres to the synopsis-style conversion’s rigid pattern, especially for non-synopsis content. For now, the patch is still under review, and the next step will likely be a decision on which markup approach to take.
