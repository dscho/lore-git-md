This is the first patch in Harald Nordgren’s **v24 `git branch --delete-merged` series**, which is now ready for merging. This patch introduces the `--forked` filter for `git branch --list`, the foundational building block for the `--delete-merged` subcommand.

The `--forked` option lists only branches whose configured upstream matches a given pattern. The argument can be a full refname (e.g., `origin/main`), a remote name (e.g., `origin` for `origin/HEAD`), or a shell-style glob (e.g., `origin/*`). The option can be repeated to widen the filter, and it composes with existing filters like `--merged` and `--no-merged`. For example, `git branch --merged origin/main --forked 'origin/*'` lists branches forked from `origin` that are already merged into `origin/main`.

The implementation adds a new `forked` strvec to `struct ref_filter` and introduces two key functions: `ref_filter_forked_add()` (which resolves ref arguments to full refnames or accepts globs) and `filter_forked_match()` (which checks each branch’s upstream against the registered patterns). The filter is applied during ref iteration in `apply_ref_filter()`, ensuring it integrates cleanly with the existing ref-filter machinery.

The patch includes comprehensive tests covering exact refnames, remote shorthand, shell globs, repeated arguments, composition with other filters, and edge cases like unknown branches or missing values. The documentation updates `git-branch.adoc` to explain the new option and its syntax.
