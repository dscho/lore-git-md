This is the ninth patch in Kristoffer Haugsbakk’s now-merged 11-patch documentation series for `git-interpret-trailers`. It commits the man page to the term “trailer block” throughout the DESCRIPTION section, replacing looser phrasing about “existing trailers” and “the end of the input.”

The patch simplifies and tightens the prose by consistently using “trailer block” to describe the contiguous group of trailers at the end of a commit message. This eliminates an earlier ambiguity: the text previously said “a blank line will be added before the new trailer if there isn’t one already,” which could be read as either inserting a blank line before every new trailer or only when no trailer block exists. By framing everything in terms of the trailer block, the new wording makes it clear that Git either appends to an existing block or creates a new one, and that a blank line is inserted only when creating a new block.

The diff shows 14 insertions and 12 deletions in `Documentation/git-interpret-trailers.adoc`, all within the DESCRIPTION section. The changes are purely editorial—no code behavior is altered—and the commit message explains the motivation in detail, including a footnote that walks through the two possible interpretations of the old wording and why the trailer-block framing resolves the confusion.
