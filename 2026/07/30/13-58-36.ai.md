This is the final patch in Harald Nordgren’s **`git branch --delete-merged`** series, adding `--dry-run` support to the new subcommand. The patch is **ready for merging** and completes the feature set for safe, automated local branch cleanup.

The implementation adds a `DELETE_BRANCH_DRY_RUN` flag to the deletion API, which suppresses all ref and config modifications while printing the same output the real command would produce. The flag is passed through the existing flags-based API introduced in earlier patches, ensuring consistency. During dry runs, `delete_branches()` skips the actual deletion and prints "Would delete branch <name>" messages, while `spare_stacked_bases()` (the stacked-branch protection logic) skips clearing upstream configs to avoid side effects. The `--dry-run` option is rejected unless `--delete-merged` is also specified, and the nonsensical `--dry-run --quiet` combination is explicitly blocked.

The patch updates `Documentation/git-branch.adoc` to document the new option and adds comprehensive test coverage in `t/t3200-branch.sh`. Tests verify that `--dry-run` produces the correct output without modifying refs or config, that it respects stacked-branch protection (e.g., skipping branches used as upstreams for unmerged branches), and that it rejects invalid combinations. The test suite now includes `for-each-ref` verification via `check_branches` to confirm branch state, as suggested by Phillip Wood.

This patch touches `builtin/branch.c` (adding the `DELETE_BRANCH_DRY_RUN` flag and dry-run logic), `Documentation/git-branch.adoc` (documentation), and `t/t3200-branch.sh` (tests). The implementation is **low-risk**, as it only adds a preview mode without changing the core deletion logic, and it aligns with Git’s existing `--dry-run` conventions (e.g., in `git clean`). The series as a whole is now **implementation-complete**, with all planned features, safety mechanisms, and correctness fixes in place.
