This thread is about a long-standing discrepancy between Git’s documentation and its actual behavior: `git config --global` is documented to read both `~/.gitconfig` and the XDG config file (`~/.config/git/config`), but the implementation reads only one file (prioritizing `~/.gitconfig` even if empty). This mismatch causes user confusion, breaks tools that rely on `--global`, and creates inconsistencies with `git config --get` (which *does* read both files). The issue also affects `--global --no-includes` and violates expectations of uniform behavior across commands.

The thread has gained momentum with Delilah Ashley Wu’s imminent v2 patch series, which aligns the code with the documentation by making `--global` read both files. This approach preserves backward compatibility while resolving cross-command inconsistencies and edge cases like `--global --no-includes`. Nils Fahldieck, the original reporter, has offered to review the series, and the renewed focus on real-world tooling failures (e.g., the `git-get` helper tool) strengthens the case for merging the fix. The patch targets `config.c`, modifying `git_global_config()` to delegate to `do_git_config_sequence()`—the same function used by `--get`—and will include tests to verify the new behavior.

Junio C Hamano, the maintainer, previously agreed the documentation was incorrect but did not endorse a specific fix, implicitly leaning toward updating the docs to match the code. However, the thread’s emphasis on systemic issues (cross-command inconsistency, `--global --no-includes` problems) and Delilah’s concrete series have shifted the discussion toward implementation. The only remaining hurdle is Junio’s approval of the behavioral change, though the active collaboration between Delilah and Nils suggests the fix is likely to move forward. If accepted, this would resolve a bug that has lingered for over a year.
