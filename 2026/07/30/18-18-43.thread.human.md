This thread is about a discrepancy between the documented and actual behavior of `git config --global`. The documentation claims it reads both `~/.gitconfig` and the XDG config file (`~/.config/git/config`), but the implementation only reads one file (prioritizing `~/.gitconfig` if readable, even if empty). Nils Fahldieck reported the issue, arguing the code should be fixed to match the docs (Option A), while Junio C Hamano, the maintainer, has suggested the docs may need correction instead (Option B).

Ben Knoble has now weighed in, agreeing the documentation is incorrect and adding that the issue isn’t isolated—it also affects how `--global` interacts with include directives, as seen in a July 2026 thread. This broadens the scope of the problem, hinting the current behavior may be more unintuitive than initially thought. However, Ben doesn’t advocate for either fix, leaving the choice between Option A and Option B unresolved. The thread remains under review, with no consensus yet on whether to backport a fix or how to address the long-standing discrepancy.
