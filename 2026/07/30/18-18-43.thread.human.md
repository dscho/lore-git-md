This thread is about a long-standing discrepancy between the documented and actual behavior of `git config --global`. The documentation claims it reads both `~/.gitconfig` and the XDG config file (`~/.config/git/config`), but the implementation reads only one file—prioritizing `~/.gitconfig` even if it’s empty. This inconsistency causes user confusion, breaks tools relying on `--global`, and creates inconsistencies with `git config --get` (which *does* read both files). The issue also affects `--global --no-includes`, making the problem systemic rather than isolated.

The thread has recently gained momentum with Delilah Ashley Wu’s proposed v2 patch series, which aligns the code with the documentation by making `--global` read both files. This approach preserves backward compatibility while resolving edge cases like `--global --no-includes`. The maintainer, Junio C Hamano, previously agreed the documentation was incorrect but did not endorse a fix direction. However, the renewed emphasis on cross-command inconsistencies and real-world tooling failures may shift the balance toward merging the code change. Nils Fahldieck, the original reporter, has enthusiastically endorsed the series and offered to review it, signaling growing community support.

The patch targets `config.c`, specifically the `git_global_config()` and `do_git_config_sequence()` functions, and includes tests to verify the new behavior. The only remaining hurdle is whether Junio will accept the behavioral change or continue to favor updating the documentation instead. The series is nearly ready for submission, and the thread is now focused on collaboration rather than debate.
