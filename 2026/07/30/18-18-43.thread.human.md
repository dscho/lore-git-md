This thread is about a long-standing discrepancy in `git config --global`, where the documentation claims it reads both `~/.gitconfig` and the XDG config file (`~/.config/git/config`), but the implementation only reads one. The issue resurfaced when Nils Fahldieck reported it, highlighting user confusion and practical problems in tools relying on `--global`. The maintainer, Junio C Hamano, agreed the documentation was incorrect but leaned toward fixing the docs rather than the code, leaving the fix direction unresolved.

Now, Delilah Ashley Wu has revived a year-old patch series that aligns the code with the documentation by making `--global` read both files. This approach (Option A) preserves backward compatibility and resolves inconsistencies with `git config --get`, which already reads both files. The series also fixes edge cases like `--global --no-includes` and includes tests for the new behavior. Delilah’s patch is nearly ready for submission, with only minor feedback remaining, and addresses the systemic nature of the issue. The key question is whether the maintainer will accept this behavioral change or continue to favor updating the documentation. Given the renewed attention to the problem’s broader implications, this patch is the most concrete step toward resolution so far.
