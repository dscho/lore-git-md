This is patch 6/7 of Harald Nordgren’s `git branch --delete-merged` series, now in its 24th iteration. The patch adds a per-branch opt-out mechanism via the `branch.<name>.deleteMerged` configuration key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The implementation is straightforward: during candidate filtering in `delete_merged_branches()`, the code checks for `branch.<name>.deleteMerged=false` using `repo_config_get_bool()`. If set, the branch is skipped with a non-quiet message explaining the opt-out. The traditional `git branch -d` command ignores this setting and continues to use the normal merge check. Documentation is updated in both `branch.adoc` and `git-branch.adoc` to describe the new config key and its behavior.

The test coverage is thorough, verifying opt-out behavior, skip messages, explicit deletion, and branch state via `check_branches` (which uses `git for-each-ref`). The tests confirm that `branch.<name>.deleteMerged=false` prevents deletion under `--delete-merged` but does not interfere with manual deletion via `git branch -d`. This patch is a small but essential part of the series, addressing a real workflow need (iterative topic branches) without introducing complexity. The implementation is clean, well-tested, and aligns with Git’s config conventions. No issues are apparent; this patch is ready for merging alongside the rest of the series.
