Subject: [PATCH 0/2] stash: reject time-based stash selectors in "drop" and "pop"
Series version: v1 (initial submission)
Originating author: Junio C Hamano
Thread type: patch series

Core problem or goal
Tighten the safety of `git stash drop` and `git stash pop` by rejecting time-based stash selectors (e.g., `stash@{2.days.ago}`). These selectors can silently remove more stash entries than the user expects, acting as a footgun in the existing interface.

Current status
Under review; no prior versions. Two-patch series:
1. Adds a `stash_idx` field to `struct stash_info` to record the positional index of the stash entry.
2. Uses the `stash_idx` field to reject time-based selectors in `drop` and `pop`, while allowing them in other subcommands (`show`, `apply`). The implementation is complete; no further changes are anticipated unless review feedback requires them.

Key technical details
- Files touched: `builtin/stash.c`, `Documentation/git-stash.adoc`, `t/t3903-stash.sh`.
- New symbol: `stash_idx` field in `struct stash_info` (set to 0 for the default latest stash, numeric index for positional selectors, -1 for invalid or non-positional references).
- Behavior change: `git stash drop stash@{2.days.ago}` and `git stash pop stash@{2.days.ago}` now fail with an error; positional selectors (e.g., `stash@{4}`) remain accepted.
- On-disk format: unchanged.
- Test coverage: new tests in `t/t3903-stash.sh` verify the rejection of time-based selectors in `drop` and `pop` and confirm that positional selectors continue to work.
