This is the fifth patch in Siddharth Shrimali’s seven-patch RFC v2 series introducing `git repack --drop-filtered` for partial clones. It moves from dry-run to real object removal: when `--drop-filtered` is given without `--dry-run`, the enumerated promisor blobs are actually dropped from the local object store.

The patch wires the `drop_oids` set (computed in patch 4) into `repack_promisor_objects()`, which now rebuilds the promisor packs while excluding the dropped blobs. It also sets `delete_redundant = 1` so that the old promisor packs—still containing the dropped blobs—are removed, ensuring disk space is reclaimed. The repack machinery’s existing write-before-delete and fsync guarantees preserve crash safety. The test in `t/t7706-repack-drop-filtered.sh` verifies that a real `--drop-filtered` run removes the large promisor blob while leaving smaller blobs untouched.

This is the core behavior change that delivers the feature’s value: reclaiming space in partial clones by safely dropping locally cached promisor blobs that exceed the user’s size threshold. The patch is minimal, touching only `builtin/repack.c`, `repack-filtered.c`, and the test script, and it preserves the safety guards implemented in earlier patches. Reviewers focused on repack internals or promisor safety will want to check that the exclusion logic in `repack_promisor_objects()` is correct and that the implied `-d` does not introduce edge cases.
