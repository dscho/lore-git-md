This is the documentation patch for the `--drop-filtered` feature in `git repack`, completing the v2 RFC series. It adds 35 lines to `Documentation/git-repack.adoc` to describe the new `--drop-filtered` and `--dry-run` options, their behavior, constraints, and safety mechanisms.

The documentation explains that `--drop-filtered` removes local promisor objects matching the `--filter` specification (currently limited to `blob:limit`), reclaiming disk space by rebuilding promisor packs without those objects and deleting the now-redundant old packs. This implies `-d` and requires `-a`, ensuring space is actually freed. The option is only available in partial clones with a promisor remote configured, and it is incompatible with `--filter-to` and bitmap writing (which is silently disabled for the command).

Safety is a central theme: the documentation highlights that `--drop-filtered` refuses to run during merges, rebases, or other operations, and it will not drop blobs referenced by the current index to avoid immediate re-fetching. These checks are skipped in bare repositories. The `--dry-run` option lists candidate objects without making changes, providing a preview of what would be dropped.

The patch is well-aligned with the rest of the series, documenting the behavior implemented in earlier patches (e.g., the safety guards in patch 6/7, the enumeration logic in patch 4/7, and the repack machinery changes in patch 5/7). The constraints (e.g., `blob:limit` only, promisor remote required) and incompatibilities (e.g., with `--filter-to` and bitmaps) are clearly stated, and the rationale for the implied `-d` is explained. This is a thorough, user-facing complement to the technical implementation.
