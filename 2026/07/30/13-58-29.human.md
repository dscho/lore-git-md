This is the **v24 submission of Harald Nordgren’s `git branch --delete-merged` series**, now **implementation-complete and unblocked** after addressing the two correctness issues identified in v23. The series introduces a safe, automated local-branch cleanup command with comprehensive filtering and safety controls, including **order-independent stacked-branch protection**, per-branch opt-out, `--dry-run` preview, and repeatable upstream selectors.

The **key changes in v24** resolve the blocking technical concerns raised by Phillip Wood:
1. **Correct push-detection logic**: The `branch_pushes_to_upstream()` function now correctly maps branches through the configured *push* and *fetch* refspecs before deciding whether pushing would update their upstream. This fixes the risk of false negatives (deleting branches that should be preserved) or false positives (keeping branches that should be deleted) by applying the push refspec to the local branch and the fetch refspec in reverse to the result, then comparing that to the upstream branch.
2. **Simplified stacked-branch protection**: The logic now protects only the direct upstream of surviving work, deletes deeper merged bases, and clears stale upstream configuration for kept (merged) branches whose own upstream is being deleted. This aligns with the design goal of avoiding broken dependency chains while cleaning up stale configs, and it resolves the test discrepancy in v23 by removing the graph traversal (`visited` strset) and updating the test to expect cleared upstream configs for kept merged branches.

The series is **well-motivated** (addressing a real workflow pain point for iterative topic branch management) and **thoroughly tested**, with comprehensive integration tests covering all safety checks, edge cases, and the new `--dry-run` functionality. The implementation is **aligned with Git’s API consistency expectations**, including the flags-based refactoring in patches 2-4/7 (which now use `unsigned int flags` as the single source of truth) and the per-branch opt-out mechanism (patch 6/7). The `--forked` filter (patch 1/7) provides a composable foundation for future branch management features, and the repeatable `--delete-merged` arguments (e.g., `--delete-merged origin/main --delete-merged origin/next`) allow precise control over deletion scope.
