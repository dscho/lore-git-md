This is the third patch in Harald Nordgren’s **v24 `git branch --delete-merged` series**, which is now ready for merging. This patch adds a `DELETE_BRANCH_SKIP_UNMERGED` flag to the branch deletion API, allowing bulk callers (like `--delete-merged`) to silently skip unmerged branches instead of failing with an error. The change is minimal and targeted: it modifies `check_branch_commit()` and `delete_branches()` to suppress the "not fully merged" error and advice when the flag is set, preserving existing behavior for all current callers (e.g., `git branch -d`).

The patch is part of the **flags-based API refactoring** (patches 2-4/7) that replaces boolean arguments with an `unsigned int flags` parameter. This refactoring was motivated by Phillip Wood’s feedback to eliminate local boolean caching (e.g., `int force = 1`) and ensure flags remain the single source of truth. The `DELETE_BRANCH_SKIP_UNMERGED` flag enables the `--delete-merged` subcommand to handle unmerged branches gracefully during bulk operations, aligning with its design goal of safe automated cleanup.

The implementation is **low-risk**: the flag is checked at both the commit-checking (`check_branch_commit()`) and deletion (`delete_branches()`) stages, and the change introduces no behavioral regressions for existing callers. The patch touches only `builtin/branch.c` and is **well-tested** as part of the series’ comprehensive integration suite, which verifies that unmerged branches are skipped silently when the flag is set. This is a **substantive but mechanical** change that supports the series’ core functionality without altering its safety guarantees.
