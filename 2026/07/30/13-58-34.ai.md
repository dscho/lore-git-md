This is the **core implementation patch (5/7)** of Harald Nordgren’s `git branch --delete-merged` series, now in its **final v24** form and ready for merging. The patch adds the new `--delete-merged <pattern>` subcommand, which safely deletes local branches whose work has already landed on their upstream (as determined by reachability and the configured push/fetch refspecs). The v24 changes address the two blocking correctness issues identified in v23: **corrected push-detection logic** and **simplified stacked-branch protection**, both of which are now verified by updated tests.

The command supports **repeatable `--delete-merged` arguments** (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the upstream match, and **optional positional branch patterns** (e.g., `topic-*`) to limit deletion scope. Safety is enforced through multiple mechanisms: checked-out branches are never touched, branches with missing upstreams are preserved, and **order-independent stacked-branch protection** ensures no branch is deleted if it is used as an upstream for an unmerged branch. The v24 update simplifies this protection to clear upstream configs for kept (merged) branches whose own upstream is being deleted, avoiding broken dependency chains while cleaning up stale configs.

Key technical details:
- **Push-detection fix**: The `branch_pushes_to_upstream()` function now correctly applies the *push* refspec to the local branch, applies the *fetch* refspec in reverse to the result, and compares that to the upstream branch. This ensures branches like `main` tracking `origin/main` are preserved even when `remote.pushDefault` names a fork, fixing the v23 flaw that could produce false negatives or positives.
- **Stacked-branch protection**: The logic now protects only the *direct* upstream of a surviving branch, deleting deeper merged bases and clearing their stale upstream configurations. The test for "clears the deleted upstream of a protected branch" verifies this behavior.
- **Safety checks**: The command skips unmerged branches silently, respects `branch.<name>.deleteMerged=false` opt-out (added in patch 6/7), and never falls back to `HEAD` (enforced by the `DELETE_BRANCH_NO_HEAD_FALLBACK` flag added in patch 4/7).
- **Test coverage**: The expanded test suite verifies order-independent stacked-branch protection, push-detection edge cases, and the clearing of upstream configs for kept branches. Tests also confirm the command respects repeatable `--delete-merged` arguments and positional branch patterns.

The implementation touches `builtin/branch.c` (adding the core `delete_merged_branches()` function and stacked-branch protection logic), `Documentation/git-branch.adoc` (documenting the new option and its safety checks), and `t/t3200-branch.sh` (comprehensive integration tests). The patch is **well-motivated** (addressing a real workflow pain point), **thoroughly tested**, and **aligned with Git’s API consistency expectations**.
