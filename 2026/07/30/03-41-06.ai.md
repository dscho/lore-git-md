This is a two-patch series from Junio C Hamano that tightens the safety of `git stash drop` and `git stash pop` by rejecting time-based stash selectors (e.g., `stash@{2.days.ago}`).

The motivation is that time-based selectors can silently remove more stash entries than the user expects. For example, `git stash drop stash@{2.days.ago}` removes *all* stash entries no younger than the specified time, not just the single entry the user likely intended. The same issue affects `git stash pop`, which also removes multiple entries after applying one.

Patch 1/2 adds a `pos` field to `struct stash_info` to record the positional index of the stash entry being processed. This prepares the code to distinguish between positional selectors (e.g., `stash@{4}`) and time-based ones. Patch 2/2 then uses this field to reject time-based selectors in `drop` and `pop`, while still allowing them in other `git stash` subcommands (e.g., `show`, `apply`).

The series touches `builtin/stash.c`, updates `Documentation/git-stash.adoc` to document the new restriction, and adds tests in `t/t3903-stash.sh`. The change is a minor but clear safety improvement, addressing a footgun in the existing interface. The implementation is straightforward and the commit messages are well-explained.
