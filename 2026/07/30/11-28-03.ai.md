This is the first patch in the v5 series improving `git mv` error messages. It addresses a long-standing usability bug where `git mv` reports failures using only the source path, even when the problem lies with the destination's parent directory. The fix is simple and surgical: the error message now includes both source and destination paths, making it immediately clear which part of the operation failed. The change is a one-line modification to `builtin/mv.c` that replaces the old `die_errno(_("renaming '%s' failed"), src)` with `die_errno(_("renaming '%s' to '%s' failed"), src, dst)`.

The patch is well-motivated and uncontroversial. The commit message clearly explains why the old behavior was misleading (ENOENT from `rename(2)` does not distinguish between missing source and missing destination directory components) and why the fix avoids a TOCTOU race by not re-inspecting the paths after the syscall fails. This patch has been stable since v2 and was explicitly approved by Junio ("Makes sense") with no further feedback. It introduces one new translatable string but does not change any existing behavior beyond the error message wording.

This is a pure usability improvement with no functional side effects. The change is minimal, thoroughly tested in the series' test suite, and aligns with the project's preference for clear, actionable error messages. The patch is ready for integration and carries no risk of regression.
