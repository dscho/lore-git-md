This is the **core implementation patch** of Harald Nordgren’s `git branch --delete-merged` series, now in its **24th and final iteration**. The patch adds the new `--delete-merged` subcommand to `git branch`, which safely deletes local branches whose work has already landed on their upstream, while preserving branches that are still needed (checked-out, missing upstreams, push-divergent, or used as upstreams for unmerged work).

The command is **ready for merging** after addressing the two blocking correctness issues identified in v23: a flawed push-detection heuristic (now fixed to correctly apply push and fetch refspecs) and a test discrepancy in stacked-branch protection (now simplified to clear upstream configs for kept branches whose own upstream is deleted). The rest of the series is unchanged from v23, which Junio C Hamano confirmed has no outstanding issues.

Key behavior:
- **Safe deletion**: Only deletes branches whose tip is reachable from their upstream (i.e., fully merged), skipping unmerged branches silently.
- **Safety checks**: Preserves checked-out branches, branches with missing upstreams, branches where pushing would update their upstream (e.g., `main` tracking `origin/main`), and branches used as upstreams for unmerged work.
- **Order-independent protection**: Uses a single-pass algorithm to protect branches needed by unmerged work, regardless of ref iteration order. If a protected branch’s upstream is deleted, its upstream config is cleared.
- **Configurable opt-out**: Respects `branch.<name>.deleteMerged=false` to exempt specific branches from automated cleanup.
- **Repeatable patterns**: Supports multiple `--delete-merged` arguments (e.g., `--delete-merged origin/main --delete-merged origin/next`) and optional positional branch patterns (e.g., `topic-*`) to limit deletion scope.

The implementation touches `builtin/branch.c` (adding the new subcommand and stacked-branch protection logic), updates `Documentation/git-branch.adoc`, and expands `t/t3200-branch.sh` with comprehensive tests covering edge cases like push-divergent branches, stacked dependencies, and config clearing. The patch is **well-tested** and aligns with Git’s API consistency expectations, using the flags-based `delete_branches()` API introduced in earlier patches.

This is the **centerpiece of the series** and the most likely point of discussion for reviewers. The changes are **substantive but focused**, addressing a real workflow pain point (automated branch cleanup) with careful attention to safety and edge cases. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands.
