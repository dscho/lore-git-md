This is a **bugfix discussion** targeting the configuration subsystem. Junio C Hamano, the Git maintainer, has replied to Nils Fahldieck’s report about the discrepancy between `git config --global`’s documented and actual behavior when both `~/.gitconfig` and the XDG config file (`~/.config/git/config`) exist.

Junio’s response focuses on two points from Nils’s analysis. First, he dismisses the concern about the documentation’s wording around file existence versus readability, arguing that a file that exists but is unreadable is functionally equivalent to a non-existent file, and that the distinction is too pedantic to warrant a change. Second, and more substantively, he agrees that the documentation’s claim that `--global` reads from *both* files is incorrect, stating plainly that the documentation needs to be fixed to match the code’s single-file behavior.

This shifts the discussion toward **Option B** (aligning the documentation with the code) rather than Nils’s preferred **Option A** (fixing the code to read both files). Junio’s position is authoritative here, so the likely outcome is a documentation patch rather than a behavioral change. The thread is now at a decision point: will the project accept the documentation fix, or will someone push back to argue for changing the code instead? For now, the maintainer’s stance suggests the former.
