This is the ninth patch in Kristoffer Haugsbakk’s now-merged 11-patch documentation series for `git-interpret-trailers`. It commits the man page to the term “trailer block” throughout the DESCRIPTION section, replacing the earlier, more ambiguous phrasing.

The patch simplifies the explanation of how new trailers are added by consistently referring to the “trailer block” concept introduced in earlier patches. Where the old text said “If there is no existing trailer, the new trailer will appear at the end of the input. A blank line will be added before the new trailer if there isn’t one already,” the new version states “By default the new trailer will appear at the end of the trailer block. A trailer block will be created with only that trailer if a trailer block does not already exist. Recall that a trailer block needs to be preceded by a blank line, so a blank line will be inserted before the new trailer block in that case.” This change removes a logical inconsistency: the old wording could imply adding a blank line even when a trailer block already existed, whereas the new phrasing makes it clear that blank-line insertion only happens when creating a new block.

The commit message also explains why the term “trailer block” is preferable to “trailers” in this context: it avoids confusion between the general concept of trailers and the specific, well-defined block of lines at the end of a commit message. The patch touches only the DESCRIPTION section of `Documentation/git-interpret-trailers.adoc`, replacing 12 lines with 14 to achieve this clarity. No code behavior is altered; this is purely a documentation improvement.
