This is the first patch in a two-part series from Junio C Hamano that prepares the `git stash` code to distinguish between positional and time-based stash selectors. The patch adds a `stash_idx` field to the `struct stash_info` to record the 0-based positional index of the stash entry being processed. When a user specifies a stash like `stash@{4}`, the field is set to `4`; for time-based selectors like `stash@{2.days.ago}`, it is set to `-1`. If no index is given (e.g., just `stash`), it defaults to `0`, meaning the latest stash.

The change is confined to `builtin/stash.c` and is straightforward: the new field is populated in `get_stash_info()` by parsing the `@{...}` suffix of the revision argument. The logic is careful to reject malformed or non-numeric indices (e.g., `@{foo}`) by setting `stash_idx` to `-1`. This sets up the next patch, which will use the field to reject time-based selectors in `drop` and `pop` for safety. The patch is well-motivated and the implementation is clean, with no obvious edge cases missed.
