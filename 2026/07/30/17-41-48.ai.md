This is the second patch in the RFC v2 series introducing `--drop-filtered` for `git repack`. It adds a new helper function, `list_objects_filter__filter_oidset()`, to the `list-objects-filter` API, enabling callers to apply a filter to an existing set of OIDs without performing an object walk.

The helper is motivated by the `--drop-filtered` feature’s need to determine which promisor blobs exceed a size threshold (e.g., `blob:limit=10M`) after collecting them into an oidset. The existing filter machinery (`list_objects_filter__filter_object()`) is tied to the object-walk path and cannot be reused for this use case, so the patch reimplements the `blob:limit` size check directly. A `NEEDSWORK` comment acknowledges this duplication and flags it for future refactoring. The helper avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info, ensuring it never triggers a network request during enumeration.

The implementation is straightforward: it iterates over the input oidset, queries each object’s type and size, and inserts blobs exceeding the threshold into the `omitted` set. Only `blob:limit` filters are supported in this version, with an error returned for unsupported filter types. The patch includes a clear header declaration and a matching `NEEDSWORK` comment in the header file.

This is a well-scoped, mechanical addition that directly supports the series’ core functionality. The duplication of the size check is a pragmatic trade-off for now, and the `NEEDSWORK` comment ensures it won’t be overlooked. The helper’s design is clean and aligns with the series’ goal of avoiding object walks when the OIDs are already known. No controversy is evident here—this looks like a necessary and uncontroversial plumbing addition for the `--drop-filtered` feature.
