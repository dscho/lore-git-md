This is the fourth patch in Siddharth Shrimali’s seven-patch RFC v2 series introducing `git repack --drop-filtered` for partial clones. It implements the core enumeration logic that identifies which promisor blobs exceed the user-specified size threshold and are therefore safe to drop.

The patch walks the object database with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, collecting every promisor blob into an oidset. It then applies the filter (`blob:limit=<n>`) to that set using the helper introduced in patch 2, producing the final `to_drop` set. In `--dry-run` mode the patch simply prints the OIDs; actual removal is deferred to later patches. The enumeration is careful to avoid lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object-info query.

Tests verify that only promisor blobs over the threshold are listed, that locally created blobs are never candidates, and that `--dry-run` leaves the objects untouched. The patch is well-motivated: it directly addresses the v1 feedback that promisor objects must be enumerated separately from the main pack-objects run, and it lays the foundation for the subsequent removal and repack steps. The code is clean, the commit message is clear, and the safety properties (no lazy fetches, no local objects) are explicitly enforced.
