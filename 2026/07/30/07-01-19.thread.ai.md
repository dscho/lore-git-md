Thread identity: Patch series introducing `--date=elapsed` and `--date=elapsed-pad` date formats to Git, with `%aX`/`%cX` pretty-format placeholders. Originating author: Israel Roldan (via GitGitGadget). Thread type: feature patch series (single patch in this iteration).

Core problem or goal: Address a gap in Git's date formatting by providing a precise, script-friendly elapsed-time format (e.g., "1y 11M 5d 13h 5m 13s") modeled after `uptime(1)`, complementing the existing `--date=human` which offers only imprecise phrases like "2 days ago." The new format enables users to see exact time differences without manual calculation from raw timestamps (`%ct`).

Current status: Under initial review. This is the first iteration of the patch; no prior versions exist. The implementation is complete, self-contained, and passes all tests, including new tests for the elapsed format. The patch touches `date.c`, `pretty.c`, and documentation, adding the new date mode to the `date_mode_type` enum, implementing `show_date_elapsed()`, and exposing the placeholders. No merge status is reported; the series is not yet queued in Junio's integration branches.

Key technical details:
- Files touched: `date.c` (new `show_date_elapsed()` helper, `show_date()` integration), `pretty.c` (placeholder wiring), `Documentation/` (date-formats and pretty-formats updates).
- New symbols: `--date=elapsed`, `--date=elapsed-pad`, `%aX` (author elapsed), `%cX` (committer elapsed) pretty-format placeholders.
- Behavior: Elapsed time is formatted as "1y 11M 5d 13h 5m 13s" (compact) or "01y 11M 05d 13h 05m 13s" (padded), using `uptime(1)` conventions (30-day months, 365-day years). Future timestamps are clamped to "0s".
- On-disk format: No changes; this is purely a display feature.
- Test coverage: New tests in `t/t4202-log.sh` and `t/t6300-for-each-ref.sh` verify the date helper and pretty-format equivalence.

Open questions and loose ends:

2. Format naming: `--date=elapsed` and `--date=elapsed-pad` are the proposed names; feedback is requested.
3. Future timestamp behavior: Currently clamped to "0s"; alternatives (e.g., negative values) are open for discussion.
4. Symmetry of padded placeholders: The patch implements padding for both `%aX` and `%cX`, but the author questions whether this is necessary.
