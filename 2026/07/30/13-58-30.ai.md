This is the first patch in Harald Nordgren’s **v24 `git branch --delete-merged` series**, which is now **implementation-complete and ready for merging**. This patch introduces the `--forked` filter for `git branch --list`, the foundational building block for the `--delete-merged` subcommand.

The `--forked` filter lists only branches whose configured upstream matches a given pattern. The argument can be a ref (e.g., `origin/main`), a remote name (e.g., `origin` for `origin/HEAD`), or a shell-style glob (e.g., `origin/*`). The option can be repeated to widen the filter, and it composes with existing filters like `--merged` and `--no-merged`. For example, `git branch --merged origin/main --forked 'origin/*'` lists branches forked from `origin` that are already merged into `origin/main`.

The implementation adds a new `forked` strvec to `struct ref_filter` and introduces two key functions:
- `ref_filter_forked_add()` resolves ref arguments to full refnames (e.g., `origin/main` → `refs/remotes/origin/main`) or accepts shell-style globs.
- `filter_forked_match()` checks each branch’s upstream against the registered patterns, with exact matches compared against full upstream refnames and globs matched against abbreviated upstream names (e.g., `origin/main`).

The patch includes comprehensive tests covering exact refnames, remote shorthand, shell globs, repeated arguments, composition with other filters, and edge cases like unknown branches. The documentation updates `git-branch.adoc` to describe the new option and its usage.

This patch is **low-risk and well-tested**, with no behavioral changes to existing functionality. It is purely additive and serves as the foundation for the `--delete-merged` subcommand introduced in patch 5/7. The v24 changes do not affect this component, as the blocking issues (push-detection logic and stacked-branch protection) are addressed in later patches.
