This is the documentation patch for the `--drop-filtered` feature in `git repack`, completing the RFC v2 series from first-time contributor Siddharth Shrimali. The patch adds 35 lines to `Documentation/git-repack.adoc`, fully documenting the new `--drop-filtered` and `--dry-run` options introduced in earlier patches.

The documentation explains that `--drop-filtered` safely reclaims disk space in partial clones by removing locally cached promisor blobs that match the `--filter` specification (currently limited to `blob:limit=<n>`). It clarifies key constraints: the option requires `-a`, implies `-d` (so redundant packs are actually deleted), and is incompatible with `--filter-to` and bitmap writing. The safety guards are prominently described—`--drop-filtered` refuses to run during merges, rebases, or other operations, and won’t drop blobs referenced by the current index, preventing immediate re-fetching.

The patch is well-timed, arriving after the core functionality and safety mechanisms were implemented in patches 1–6. The documentation aligns with the series’ design goals and addresses the CLI rationale requested in earlier reviews. This is a clean, focused addition that rounds out the feature for end users. Worth noting for readers: the deferred work (drop log, remote verification) is *not* mentioned here, keeping the man page scoped to what’s actually implemented.
