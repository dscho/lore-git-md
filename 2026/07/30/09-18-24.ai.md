This is the final patch in Kristoffer Haugsbakk's 11-patch documentation series for `git-interpret-trailers`, now merged to `master`. It documents how comment lines (defined by `core.commentString`) are handled during trailer parsing, filling a long-standing gap in the man page.

The patch adds a new "OTHER RULES" section that explicitly states comment lines are ignored, tying this behavior to Git's hook system (`prepare-commit-msg` and `commit-msg`). The commit message acknowledges this is primarily for completeness, noting that comment characters are unlikely to conflict with valid trailer keys (ASCII alphanumeric + hyphen) in practice. A footnote highlights Jujutsu VCS's use of `JJ:` as a comment string as a potential edge case.

The v4 iteration refined the motivation after feedback, positioning this as thorough documentation rather than addressing a specific user pain point. The change is minimal (10 lines added) and purely explanatory, with no code or behavioral impact. This patch completes the series' goal of fully documenting the trailer format's parsing rules.
