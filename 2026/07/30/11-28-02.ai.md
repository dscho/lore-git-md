This is the v5 submission of a two-patch bugfix series for `git mv`, now titled "mv: report missing destination leading directory." The series is functionally complete and addresses a long-standing usability issue where `git mv` emits misleading error messages when the destination's parent directory does not exist or contains tracked symlinks.

The core problem remains the same: `git mv` previously blamed the *source* file when the destination's leading directories were missing or problematic, and it failed to detect symlinks in the destination path, which could lead to index corruption. The series fixes this in two commits: the first improves error messages to include both source and destination paths, and the second adds an early check for missing directories, non-directory components, and *any* tracked symlink in the destination path (regardless of target type). The symlink rejection aligns with `git apply`'s precedent and Junio's requirement that Git must not follow tracked symlinks.

In v5, the author implemented Junio's requested refactoring to deduplicate the logic determining whether a move requires a worktree rename. The new `needs_worktree_rename()` helper is used in both the early directory check and the actual rename operation, ensuring the two cannot drift. The patch also optimizes memory allocation by deferring the `dirname` copy until it is needed (when the destination contains a slash). Two new tests were added: one for moving into an existing directory (where the destination is normalized to a full path) and another for moving to a bare filename in the current working directory (no leading directory to check). The commit message was reworded for clarity, but the core behavior and edge-case handling are unchanged from v4.

Files touched remain `builtin/mv.c` and `t/t7001-mv.sh`, with 146 new test lines covering symlinks (as both final and intermediate components), missing directories, non-directory components, `--dry-run` detection, and force-flag behavior. The series introduces no new public symbols but adds two translatable strings. The TOCTOU race (where the destination could disappear between check and `rename()`) is still acknowledged as "the best we can do" for now.

This version is a final polish pass in response to Junio's feedback. The series is technically ready for integration, with no outstanding objections or unresolved technical concerns. The only remaining loose ends are the TOCTOU race (unaddressed) and potential bikeshedding on the helper function name, neither of which affect functionality. The author's implementation is thorough, with clear commit messages and comprehensive test coverage.
