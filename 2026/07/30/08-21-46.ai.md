This is a maintainer response to the RFC series proposing to restrict hex object IDs to lowercase only in Git 3.0. Junio C Hamano, the maintainer, is pushing back on the motivation and asking for a stronger case before the project considers adopting this breaking change.

Junio acknowledges brian m. carlson’s observation that Git has always emitted lowercase hex object IDs and that the parser currently accepts both cases, but he is not yet convinced that the benefit outweighs the risk. His key point is that "just because we might be able to do this without harming too many users" is insufficient justification—there must be a clear, long-term benefit to justify the disruption. The email does not attempt to evaluate the implementation itself (which brian described as "fully functional"), but instead focuses entirely on the rationale for the change.

The thread remains in the RFC stage, with no technical review of the patches yet. Junio’s response signals that the series will not advance further without a more compelling argument for why this change is necessary. This is likely to be a sticking point: brian’s original motivation (consistency and security) may not be enough to overcome the inherent conservatism around breaking changes in Git, especially one that touches core object ID parsing. The discussion is now squarely about whether the problem is severe enough to warrant action at all.
