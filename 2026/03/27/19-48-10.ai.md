This is a behavior change for `git format-patch`'s commit list formatting, part of an ongoing series refining the `--commit-list-format` option. The patch removes unconditional line wrapping at 72 characters (MAIL_DEFAULT_WRAP) from commit list entries when using custom formats, giving users full control over line lengths in their output. The wrapping behavior is now explicitly moved into the "modern" preset format definition as `%w(72)`.

The change affects both the implementation in `builtin/log.c` (removing the forced wrapping logic) and updates the documentation to reflect that "modern" now includes the wrapping directive. This follows logically from the earlier introduction of flexible commit list formatting, where the forced wrapping was an artifact of the original implementation rather than an intentional design choice.

The patch appears well-scoped and uncontroversial, building on established consensus from previous iterations in this thread.
