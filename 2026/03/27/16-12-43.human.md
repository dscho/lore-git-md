Performance improvement for promisor object repacking. This patch addresses a `NEEDSWORK` comment from commit 5d19e81 by improving how `git repack` handles promisor objects (those fetched on demand). Currently, when repacking these objects, Git only sends raw OIDs to `pack-objects`, forcing it to re-sort objects from scratch. The patch adds fake paths based on original pack basenames and offsets to preserve locality hints, which should produce better delta compression in the resulting packfile.

The change is focused and well-explained, with a clear commit message describing both the problem and solution. The implementation adds a new `build_ordering_hint()` function to construct these fake paths, modifying the existing `write_oid()` callback to include them when feeding objects to `pack-objects`. This looks like a straightforward improvement to an existing optimization opportunity, though the actual delta compression benefits would need real-world testing to confirm.
