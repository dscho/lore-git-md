This thread documents and fixes a long-standing discrepancy in Git's ignore pattern behavior. Dan Drake originally reported that the documentation incorrectly stated patterns in repository-level ignore files (`.git/info/exclude` and `core.excludesFile`) were relative to the containing directory, when in fact they have always been treated as root-relative. Junio Hamano confirmed this has been the actual behavior for over 20 years and explicitly invited a documentation patch to clarify the special case.

Shreyansh Paliwal has now submitted the requested documentation update to the gitignore(5) manpage. The patch clearly states that patterns in these repository-level files are root-relative, unlike regular `.gitignore` files where patterns are relative to their containing directory. The change includes both the technical explanation and a practical example, following the existing documentation style. 

With Junio's prior confirmation of the behavior and Shreyansh's well-formed patch that exactly matches the maintainer's request, this appears ready for merging. The change corrects a documentation oversight while maintaining consistency of the actual behavior that users have relied on for decades.
