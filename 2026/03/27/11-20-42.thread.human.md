This thread addresses a documentation clarification regarding gitignore pattern behavior in repository-level ignore files (`.git/info/exclude` and files specified by `core.excludesFile`). Dan Drake observed that while the gitignore manpage states patterns with leading slashes are relative to the directory containing the file, these special cases actually anchor to the repository root - a subtle but important difference that could confuse users trying to specify precise exclusions.

The proposed change would update the "pattern format" section of the gitignore documentation to explicitly note this exception for repository-level ignore files. The observation appears correct and the documentation gap is real, though no actual patch has been submitted yet. This seems like a straightforward improvement that would help users work more effectively with these configuration options. Someone familiar with the documentation format would need to implement the text change, possibly including an example to illustrate both relative and absolute pattern forms.
