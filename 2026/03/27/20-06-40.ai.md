This is a v3 patch series from Taylor Blau addressing pack-objects issues during geometric repacking when MIDX bitmap generation fails due to packs not being closed under reachability. The series introduces a new "excluded-open" pack state (marked with '!') to properly handle objects reachable through excluded packs while excluding their direct contents.

Key changes in v3:
- Introduces a named `stdin_pack_info_kind` enum for better type safety and readability
- Refactors pack handling from string_lists to strmap with proper flag accumulation
- Fixes a memory leak in `read_stdin_packs()`
- Adds thorough test coverage including t5331.8 which verifies handling of multiply-specified packs
- Addresses all reviewer feedback from v2

The series has received positive reviews from Derrick Stolee, Jeff King, and Patrick Steinhardt, with Junio C Hamano confirming the enum approach is appropriate. The changes improve both correctness (fixing the reachability issue) and code quality (strmap refactoring, enum usage). With all feedback addressed and approvals confirmed, this appears ready for merging.

Technical details:
- New `stdin_pack_info_kind` enum with `STDIN_PACK_EXCLUDE_OPEN` flag
- Refactored pack list reading using strmap instead of string_lists
- Proper flag accumulation with `|=` operator
- Modified `builtin/repack.c` to mark non-MIDX packs above the geometric split as excluded-open
- Added test case demonstrating the failure scenario with once-cruft objects becoming reachable

The solution cleanly handles the interaction between cruft packs, geometric repacking, and bitmap generation while maintaining separation of concerns. The changes are focused and well-explained, with careful attention to backward compatibility and edge cases.
