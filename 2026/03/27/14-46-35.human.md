This is a feature patch discussion in Adrian Ratiu's parallel hook execution series. Patrick Steinhardt is responding to v5 patch 9/12, which adds warnings when users configure job counts using hook friendly-names instead of event names.

Patrick acknowledges the warning system makes sense as implemented, but raises a deeper architectural question about whether the hook configuration should completely separate the namespaces for friendly-names and event names to prevent this confusion entirely. He notes he won't push for such a change at this stage, indicating this is more of a philosophical observation than a blocking concern.

The exchange shows the series is in its final refinement stages, with Patrick - a major contributor to Git's infrastructure - engaging with the design choices but not requesting changes to the current approach. This suggests the warning system is likely to be accepted as-is while leaving open the possibility of future namespace separation.
