This is a maintainer response in the ongoing discussion about per-remote SSH configuration options. Junio C Hamano weighs in to strongly support Johannes Sixt's position that SSH host aliases already solve the problem without requiring new Git configuration options.

Junio agrees with Hannes that the SSH host alias approach is both well-established and sufficient, suggesting this technique should be common knowledge among Git users. He expresses skepticism about adding transport-specific configuration under the "core" namespace, implying the proposed changes would introduce unnecessary complexity.

The maintainer's intervention signals this approach may face an uphill battle for acceptance. While not an outright rejection, Junio's endorsement of the status quo and questioning of the configuration namespace suggests the patch series would need to demonstrate much clearer advantages over existing solutions to gain traction. His comment about documentation gaps hints that improving docs about SSH host aliases might be a more productive direction than adding new configuration options.
