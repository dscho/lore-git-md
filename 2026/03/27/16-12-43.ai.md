Performance optimization for promisor object repacking. This patch addresses a known inefficiency in how `git repack` handles promisor objects (those stored in partial clone/promisor packs). Currently, when repacking these objects, Git only sends raw OIDs to `pack-objects`, losing the original pack ordering information which can lead to suboptimal delta compression.

The change modifies `repack-promisor.c` to construct "fake paths" for each object consisting of the pack basename and object offset (e.g. "pack-123abc/00420") when feeding objects to `pack-objects`. This gives the packer hints about the original pack ordering, allowing it to group related objects together during delta compression rather than falling back to type/size sorting.

The implementation:
- Adds a new `build_ordering_hint()` function that constructs these fake paths
- Modifies `write_oid()` to include the hint when writing to `pack-objects`
- Removes the NEEDSWORK comment this change addresses
- Passes object info to `odb_for_each_object()` to get pack/offset data

This appears to be a well-motivated change that directly targets a documented limitation in the promisor object repacking logic. The implementation is focused and follows existing patterns in the codebase. The commit message clearly explains both the problem and solution. This would likely be of interest to anyone working with large promisor packfiles where delta compression efficiency matters.
