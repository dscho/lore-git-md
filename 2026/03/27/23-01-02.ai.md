This is a technical analysis of a test failure in the xdiff refactoring series, where Junio C Hamano identifies a signed/unsigned comparison issue in patch 4/6. The patch aimed to clarify limit handling in `xdl_cleanup_records()` by introducing explicit per-file limit variables, but inadvertently changed behavior when `need_min` is true.

The key problem is that the refactoring assigns `SIZE_MAX` (unsigned) to `mlim1`/lim2` (signed `ptrdiff_t`), effectively making them -1. This causes the comparison `nm >= mlim1` to always evaluate as true when `need_min` is set, forcing INVESTIGATE where KEEP was previously used. Junio's analysis shows this behavioral difference explains the test failures in t4071 and t8015.

The issue reveals several technical points for future reference:
1. The subtle interaction between signed/unsigned types in the refactoring
2. How the `need_min` flag's original purpose was to bypass limit checks entirely
3. That the test failures validate the importance of Junio's integration testing
4. The need to preserve the original "KEEP if need_min" logic in any fix

This email doesn't propose a solution but provides the diagnostic foundation for Ezekiel Newren to revise the patch. The thread shows how even well-intentioned refactoring can introduce subtle behavioral changes, and how Git's maintainer workflow catches these through rigorous test verification before merging.
