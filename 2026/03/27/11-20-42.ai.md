Documentation patch clarifying gitignore pattern behavior for info/exclude and core.excludesFile.

Dan Drake points out an inconsistency between the gitignore documentation and actual behavior when patterns appear in `.git/info/exclude` or files specified by `core.excludesFile`. The manpage currently states that patterns with leading slashes are relative to the directory containing the ignore file, but in these special cases they are actually anchored to the repository root.

The patch proposes updating the documentation to explicitly note this exception for repository-level ignore files. This is a straightforward clarification that would help users correctly specify patterns in these files without trial-and-error. The change targets the "pattern format" section of the gitignore manpage, which is the authoritative reference for this behavior.

The patch appears well-motivated and correctly identifies a documentation gap. The change is small and focused, though it might be worth considering whether to include an example showing both the relative and absolute forms for clarity. The author doesn't provide a proposed patch, just the observation, so this would need to be implemented by someone familiar with the documentation format.
