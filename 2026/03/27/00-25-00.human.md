This is a documentation patch finalizing the wording around `git format-patch`'s `--commit-list-format` behavior. The thread has seen several iterations refining how the documentation describes the interaction between this option and cover letters.

The key settled points are:
1. The command-line `--commit-list-format` option implies `--cover-letter`, while the configuration variable `format.commitListFormat` does not
2. The default format is `shortlog` when neither option is specified
3. Any string containing '%' is treated as a custom format without strict validation

Mirko Faina and Junio C Hamano have converged on documentation that captures these behaviors while balancing completeness with conciseness. The patch represents the conclusion of this discussion, with Mirko planning to send a final version unless further feedback emerges. The changes affect both the command and configuration documentation, maintaining consistency with Git's flexible commit list formatting options.
