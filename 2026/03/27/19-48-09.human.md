This is a documentation patch clarifying the behavior of `git format-patch`'s `--commit-list-format` option and related configuration. It's part of an ongoing series refining how commit lists are formatted in cover letters.

The patch updates two documentation files to better explain the default behavior when neither `--commit-list-format` nor `format.commitListFormat` is set (it falls back to `shortlog` format). It also clarifies that only the command-line option (not the config setting) implies `--cover-letter`, and tightens the wording around format string parsing.

The changes are straightforward documentation improvements based on previous discussion with Junio Hamano. The patch maintains technical accuracy while making the behavior more transparent to users. This appears to be a well-scoped follow-up to earlier work on commit list formatting, addressing specific gaps identified during review.
