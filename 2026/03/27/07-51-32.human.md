This is a reply in an ongoing thread about adding per-remote SSH configuration options. Johannes Sixt (Hannes) argues that the proposed feature is unnecessary because the same functionality can already be achieved today using SSH's Host configuration in ~/.ssh/config. He demonstrates how to set up different SSH identities for different remotes by using fake hostnames that map to the same real host, each with their own IdentityFile.

Hannes' position is that this existing SSH capability makes the proposed Git-side configuration redundant, and that adding it to Git would introduce unnecessary complexity. This is a direct counterpoint to the original proposal's motivation about making multiple-identity management more convenient within Git itself.

The reply suggests that the feature may face resistance from those who prefer to keep SSH configuration concerns separate from Git's configuration system. Hannes is a long-time contributor with expertise in Windows and low-level platform work, so his perspective on configuration mechanisms carries weight. The thread now has clear opposing viewpoints to resolve before the feature could move forward.
