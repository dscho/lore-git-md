Thread summary:

Documentation clarification regarding gitignore pattern behavior in repository-level ignore files (`.git/info/exclude` and `core.excludesFile`). Dan Drake identified a discrepancy between documented behavior (patterns with leading slashes relative to directory containing ignore file) and actual implementation (patterns anchored to repository root). Junio C Hamano confirmed this has been the long-standing behavior for over 20 years and explicitly invited a documentation patch to clarify the special case for repository-level ignore files.

The thread now awaits implementation of the documentation update to gitignore(5) manpage's "pattern format" section. The change should clearly distinguish between normal .gitignore behavior (relative to containing directory) and repository-level files (relative to root). Junio's confirmation makes this an uncontroversial change suitable for new contributors. Key technical detail: leading slash patterns in `.git/info/exclude` and `core.excludesFile` have always been treated as root-relative despite documentation stating otherwise. The patch should maintain consistency with existing documentation style while adding this clarification, potentially including examples showing both pattern forms.
