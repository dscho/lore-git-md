Thread summary:

Documentation clarification regarding gitignore pattern behavior in repository-level ignore files (`.git/info/exclude` and `core.excludesFile`). Dan Drake identified a discrepancy between the documented behavior and actual implementation - while the gitignore manpage states patterns with leading slashes are relative to the directory containing the ignore file, in these special cases they are actually anchored to the repository root. The proposed change would update the "pattern format" section of gitignore(5) to explicitly note this exception for repository-level ignore files. This is a small but important clarification that would help users correctly specify patterns without trial-and-error. The patch would need to be implemented by someone familiar with the documentation format, potentially including examples showing both relative and absolute pattern forms for clarity. The issue appears uncontroversial and well-motivated, addressing a clear documentation gap.
