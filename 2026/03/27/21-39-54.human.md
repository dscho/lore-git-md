This is a review comment from Jeff King (Peff) on Wesley Schwengle's patch series introducing per-remote SSH configuration options. Peff raises two key concerns about the technical approach.

First, he questions whether plumbing the remote name down to `git_connect()` is the right level for handling SSH configuration, suggesting it may be too low-level. He proposes instead passing a structured `ssh_options_context` from higher-level commands, which would allow command-line overrides and be more flexible for future needs.

Second, he notes that much of the proposed functionality might already be achievable through existing SSH host configuration, referencing ongoing discussion elsewhere in the thread. This aligns with earlier feedback from Johannes Sixt and Junio Hamano about using native SSH features rather than adding Git-specific configuration.

Peff's comments focus on architectural considerations rather than implementation details, continuing the thread's split between debating the feature's necessity and improving the technical approach. His suggestion of a structured context object represents a potentially cleaner design, though it would require more substantial refactoring of the transport layer. The email doesn't take a position on whether the feature itself is worthwhile, instead focusing on how it should be implemented if pursued.
