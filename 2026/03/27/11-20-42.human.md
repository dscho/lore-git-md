This is a documentation patch clarifying how path patterns work in `.git/info/exclude` and `core.excludesFile` files. The `gitignore` man page currently describes pattern matching relative to the location of `.gitignore` files, but doesn't explicitly state that patterns in the info/exclude file are treated differently - they're anchored to the repository root when starting with a slash.

The patch identifies a real inconsistency between the documented behavior and actual behavior, though it's a relatively minor documentation gap rather than a functional issue. The author (Dan Drake) correctly notes that the current wording could mislead users into writing incorrect patterns like `../../foo*` when `/foo*` would be the proper syntax for matching from the repository root.

This is a straightforward documentation improvement that would help users understand the subtle but important distinction between these two similar-but-different ignore file locations. The patch is well-motivated and addresses a clear gap, though it's limited in scope to just this one clarification.
