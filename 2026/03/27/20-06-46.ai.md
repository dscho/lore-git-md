This is a refactoring patch in Taylor Blau's series addressing pack-objects issues during geometric repacking. The patch converts the pack handling in `read_packs_list_from_stdin()` from using two separate string_lists (for included and excluded packs) to a single strmap keyed by pack basename, with values being a new `stdin_pack_info` struct that tracks both the pack pointer and its kind (included/excluded).

The change prepares for future introduction of new pack kinds by making the data structure more flexible. Key technical aspects include:
- New `stdin_pack_info_kind` enum with `STDIN_PACK_INCLUDE` and `STDIN_PACK_EXCLUDE_CLOSED` flags
- Pack entries now stored in a strmap with pack basename as key
- Logic split into `stdin_packs_read_input()` for parsing and `stdin_packs_add_pack_entries()` for processing
- Maintains same sorting behavior by pack mtime
- Handles duplicate pack specifications cleanly via bitwise OR of kind flags

The refactoring is mechanical with no functional changes, but improves the code by:
- Eliminating duplicate handling for included/excluded packs
- Making it easier to add new pack kinds in future patches
- Using more appropriate data structure (strmap) for the use case
- Better separation of parsing vs processing logic

This is part of a well-reviewed series that has already received approvals from key reviewers (Derrick Stolee, Jeff King, Patrick Steinhardt). The change is focused and clearly motivated, with thorough test coverage already established in the series.
