This is a maintainer comment in the ongoing thread about per-remote SSH configuration options. Junio C Hamano weighs in to support Johannes Sixt's position that SSH host aliases already solve the problem without requiring Git changes.

Junio concurs with Hannes' assessment that the SSH host alias approach is both sufficient and widely known, though he notes this knowledge may not be well-documented. His brief response carries significant weight as the project maintainer, effectively endorsing the status quo over the proposed changes.

The key technical point is Junio's objection to putting SSH-specific configuration under the "core" namespace, suggesting this would be an inappropriate categorization even if the feature were accepted. This reinforces the architectural principle that Git should avoid duplicating functionality that properly belongs in lower-level tools like SSH.

The comment doesn't directly engage with Wesley Schwengle's arguments about workflow portability and team repository setups, but its alignment with Hannes' position suggests the maintainer sees those concerns as either insufficiently compelling or better addressed through other means. The thread now appears to be leaning against accepting the feature unless stronger use cases emerge that SSH host aliases cannot reasonably address.
