This is a status update on the experimental `git replay` command, part of the ongoing effort to build a more flexible alternative to `git rebase`. Christian Couder is responding to Junio Hamano's "What's cooking" report, providing feedback on two replay-related topics that are ready for merging to 'next'.

The first topic (`tc/replay-down-to-root`) adds support for replaying commits starting from the root commit. Christian notes that while there's a known issue with silent failures when using "topic" instead of "main..topic" syntax, this will be addressed separately and shouldn't block merging the current work.

The second topic (`sa/replay-revert`) introduces a `--revert` mode to `git replay`, building on earlier work by extracting revert message formatting from the sequencer into a shared function. Christian confirms that version 6 of this series has addressed the minor issues previously identified by Phillip Wood, making it ready for integration.

Both changes represent incremental improvements to the still-experimental replay command, with the revert functionality in particular being a significant addition that could eventually provide an alternative to `git revert` with more flexible history rewriting capabilities. The feedback suggests these changes have gone through thorough review and are uncontroversial additions to the feature.
