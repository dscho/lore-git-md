Documentation clarification regarding gitignore pattern behavior in repository-level ignore files.

Junio C Hamano confirms Dan Drake's observation about the discrepancy between gitignore documentation and actual behavior for `.git/info/exclude` and `core.excludesFile` files. He acknowledges this has been the case for over 20 years without being reported, and agrees these repository-level ignore files should be documented as behaving as if they were specified at the working tree root.

The maintainer explicitly invites a patch to update the documentation, marking this as an uncontroversial change that just needs implementation. This follows up on Dan Drake's original report that patterns with leading slashes in these files are anchored to the repository root, contrary to the current documentation which states they should be relative to the directory containing the file.

The thread now awaits someone to submit the actual documentation patch. Given Junio's confirmation of the behavior and encouragement to fix it, this would be a good opportunity for a new contributor to make their first documentation contribution by updating the gitignore(5) manpage's "pattern format" section with this clarification. The change should clearly distinguish between the behavior (relative to containing directory) for normal .gitignore files versus the special case (relative to repository root) for these repository-level ignore files.
