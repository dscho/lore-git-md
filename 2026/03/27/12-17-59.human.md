Christian Couder responds to Junio Hamano's security review of the URL-based promisor remote whitelisting feature (now renamed to "allowlist" terminology). This is part of a larger series introducing the `promisor.acceptFromServerUrl` config option.

The key changes in response to Junio's feedback:

1. The documentation now explicitly states that matching URLs allow the server to update fields (like authentication tokens) as if `promisor.acceptFromServer=all` was set.

2. The URL matching rules have been tightened - `*` can no longer cross part boundaries (scheme/port vs host vs path). This prevents dangerous patterns like `https://*.example.com` matching malicious domains.

3. The security warnings in the documentation have been expanded with concrete examples of dangerous patterns and specific guidance for shared hosting platforms.

The response also notes that while the scheme restrictions (limiting to https/ssh) could be enforced in code, there are edge cases where other schemes might be secure in certain environments. Christian suggests this could be addressed in a future series if needed.

The updated documentation provides much clearer guidance about the security implications while maintaining the feature's flexibility. The implementation now has stricter matching rules that should make accidental misconfiguration less likely. This addresses Junio's core concerns while keeping the feature usable for its intended purpose.
