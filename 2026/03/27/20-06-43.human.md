This is a memory leak fix in the pack-objects subsystem, part of Taylor Blau's v3 series addressing geometric repacking issues. The patch plugs a minor but real leak in `read_stdin_packs()` where a `rev_info` struct wasn't being properly released. While the leak wasn't causing test failures (the test suite passed cleanly even under leak detection), it's good hygiene to clean up properly.

The change is straightforward - just adding a call to `release_revisions()` before the function returns. This matches the pattern used elsewhere in the codebase for managing `rev_info` lifecycle. The commit message helpfully notes that this is fixing an oversight that dates back to the original introduction of the function in 2021, and was carried forward in a later refactoring.

As part of a well-reviewed series that has already received approvals from key contributors (Derrick Stolee, Jeff King, Patrick Steinhardt), this patch represents final polish before merging. The fix is small but demonstrates attention to detail in resource management.
