This is a review response in the ongoing thread about per-remote SSH configuration options. Johannes Sixt (Hannes) argues against the proposed feature, suggesting the existing SSH config mechanism already solves the problem without requiring Git changes.

Hannes proposes an alternative approach using SSH's Host aliases - configuring different fake hostnames in Git remotes that map to the same real host with different identity files in `~/.ssh/config`. He demonstrates this with concrete example configurations for two GitLab accounts (personal and corporate).

The key argument is that this workaround makes the proposed Git changes unnecessary, as the same functionality can be achieved through SSH configuration alone. Hannes concludes that adding the proposed complexity to Git isn't justified when existing tools provide equivalent capability.

This challenges the core motivation of the original patch series. The response is brief and to the point, focusing purely on the technical alternative rather than engaging with the implementation details of the proposed changes. As a Windows-focused contributor, Hannes brings a practical, toolchain-oriented perspective to the discussion.
