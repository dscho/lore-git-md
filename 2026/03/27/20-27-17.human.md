This is a final refinement to the `git format-patch --commit-list-format` behavior, wrapping up a thread that has clarified both documentation and implementation of this feature. Junio C Hamano gives his approval to Mirko Faina's change that removes the unconditional 72-character line wrapping from commit list entries when using custom formats. The wrapping behavior is now explicitly specified in the "modern" preset format via `%w(72)` rather than being globally applied.

The patch follows several iterations that established consensus on how commit list formatting should work, including the distinction between command-line and config-based format specifications, and the default `shortlog` behavior. With Junio's positive review ("Looks very good") and indication that he will queue the patch, this appears to be the conclusion of the series. The change gives users more control over formatting while maintaining sensible defaults for email-oriented use cases.
