This is a two-patch series improving `git format-patch`'s commit list formatting behavior and documentation. It follows up on the earlier `mf/format-patch-commit-list-format` series that introduced flexible commit list formatting options.

The first patch updates documentation to clarify the default behavior when neither `--commit-list-format` nor `format.commitListFormat` is set (it defaults to `shortlog`), and makes related documentation more precise. This continues the thread's earlier discussion where Junio C Hamano provided feedback on wording.

The second patch removes unconditional wrapping from commit list entries, a behavioral change that makes the output more flexible when using custom formats. The series builds on commit 36c16a5b7f which previously added the `--commit-list-format` option without prefix requirements.

The changes are well-scoped, touching documentation and the log.c implementation. The cover letter clearly states the series' dependencies and goals.
