[PATCH] read-cache: use istate->repo for trace2 in do_read_index

This patch series continues the `the_repository` removal effort by converting trace2 logging in read-cache.c from the global `the_repository` to using istate->repo. Author Jayesh Daga (GSoC participant) has incorporated maintainer feedback from Junio C Hamano and Derrick Stolee, agreeing that istate->repo should never be NULL when properly initialized (as INDEX_STATE_INIT ensures) and that the fallback to `the_repository` could mask bugs.

The work is now being split into two logical phases: first addressing the trace2 cases in do_read_index() with the fallback removed entirely, then expanding to other straightforward conversions where the index state is available (refresh_index(), tweak_untracked_cache(), do_write_index()). This phased approach maintains reviewability while aligning with the broader repository abstraction work led by René Scharfe.

Technical consensus has solidified around:
- Removing all fallback paths to `the_repository` in these conversions
- Verifying the stricter approach through full test suite runs
- Grouping related conversions by subsystem for logical progression
- Deferring more complex cases (where no istate exists) for later work
