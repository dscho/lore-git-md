This is a documentation clarification in response to Dan Drake's observation about gitignore pattern behavior in repository-level ignore files (`.git/info/exclude` and `core.excludesFile`). 

Junio C Hamano confirms Dan's finding that these special cases behave differently than documented - patterns with leading slashes are anchored to the repository root rather than being relative to the ignore file's directory as the current documentation states. This has apparently been the behavior for over 20 years without being documented or noticed.

Junio acknowledges this as an oversight and invites a patch to update the gitignore(5) manpage to clarify this exception for repository-level ignore files. The response suggests this is a straightforward documentation fix that would help users understand the actual behavior without trial-and-error. 

The issue appears uncontroversial - Junio's quick confirmation indicates this is a known (if undocumented) behavior that should be properly documented. The ball is now in Dan's (or another contributor's) court to submit the actual documentation patch. This would be a good first contribution opportunity for someone looking to get involved with Git documentation work.
