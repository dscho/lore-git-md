This is the second patch in Taylor Blau's v3 series addressing pack-objects issues during geometric repacking. The patch refactors the pack handling code to use a `strmap` instead of separate `string_list`s for included and excluded packs.

The change prepares for future extensions by introducing a more flexible data structure that can track additional pack "kinds" beyond just included/excluded. The key technical change replaces two string_lists with a single strmap that stores `stdin_pack_info` structs containing both the pack pointer and a bitfield of flags. This allows cleaner handling of cases where the same pack is specified multiple times with different flags.

While this is primarily a refactoring with no functional changes, it improves the foundation for the subsequent patches in the series that will introduce new pack handling behaviors. The code maintains all existing functionality while being more maintainable and extensible. The patch has already received positive reviews from key contributors like Derrick Stolee and Jeff King in earlier iterations.

This continues the series' focus on improving pack handling correctness and code quality, with particular attention to edge cases around geometric repacking and MIDX bitmap generation. The changes are well-contained and build logically on the previous patch while setting up for the new functionality to come.
