This is a follow-up in the ongoing discussion about per-remote SSH configuration options, where Wesley Schwengle responds to maintainer Junio C Hamano's concerns. The thread has established two clear positions: Junio and Johannes Sixt argue that SSH host aliases already solve the problem without Git changes, while Wesley maintains that Git-level configuration would provide better workflow portability.

Wesley reiterates his key arguments: that requiring SSH config changes is non-portable across team environments (citing myrepos and Perl metacpan as examples), and that current workarounds like `core.sshCommand` are cumbersome. He emphasizes that SSH identity management is logically a Git concern, drawing a parallel to how Git already handles email credentials. While open to moving the configuration out of the "core" namespace, he stands by the fundamental need for the feature.

The response doesn't introduce new technical elements but sharpens the workflow arguments against the maintainer's preference for SSH-native solutions. With Junio's architectural concerns now clearly stated and Wesley's use cases reiterated, the thread appears at an impasse unless new compelling examples emerge or a compromise configuration namespace can be agreed upon. The patch series remains technically sound but faces significant design philosophy objections from the maintainer.
