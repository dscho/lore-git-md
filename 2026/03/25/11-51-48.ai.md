This is the second patch in a refactoring series that improves help text handling for `git repo` subcommands. Building on the first patch's macro extraction, this change makes each subcommand (`info` and `structure`) show only its own usage information when invoked with `-h`, rather than the full command list.

The patch introduces separate usage arrays for each subcommand, referencing the macros from patch 1/2, and updates the `parse_options()` calls to use these instead of the shared `repo_usage` array. It includes tests verifying that `-h` output is properly scoped to each subcommand - checking that `info -h` shows only info-related help and excludes structure help, and vice versa.

The implementation looks clean and focused, with the behavior change clearly separated from the preparatory refactoring in the first patch. The test coverage is thorough for the new functionality, following Git's standard test patterns. This appears to be a well-structured conclusion to the series, delivering on the promised improvement to subcommand help output while maintaining the project's coding standards.
