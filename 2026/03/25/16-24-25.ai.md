Feature implementation for `git add -p` discard action, with review feedback from Phillip Wood.

Phillip Wood responds to Luiz Campos' implementation of the 'x' (discard) action for `git add -p`, providing detailed code review while maintaining reservations about the fundamental design choice of having `git add` modify the working tree. The review focuses on implementation quality rather than reopening the earlier RFC discussion about whether this behavior belongs in `git add`.

Key technical feedback includes:
- Simplifying the hunk merge logic by passing USE_HUNK/DISCARD_HUNK directly rather than boolean flags
- Correcting delta application direction during reverse patching by temporarily inverting s->mode->reverse
- Questioning the need for a separate test repository in t3701
- Suggesting additional test cases for split hunks and pathological context lines
- Noting that the discard action currently only appears when edit (e) is available, which may be unintentional

Phillip maintains his agreement with Jeff King's earlier position that working tree modification is unexpected from `git add`, but treats this as a settled design decision for the purposes of code review. The implementation appears technically sound aside from the noted issues, showing good integration with Phillip Wood's existing interactive patch machinery.

For future discussion, the review surfaces:
- Whether discard should be available in all `add -p` modes or just the default one
- How to handle the working-tree-modification philosophical concern
- Potential need for more robust test coverage of edge cases

The exchange demonstrates the project's careful review culture, where even conceptually controversial patches receive thorough technical feedback when the author chooses to proceed with implementation. Phillip's comments suggest the patch is nearing readiness pending resolution of the identified issues.
