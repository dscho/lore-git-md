Feature patch adding remote group support to `git push`, mirroring existing `git fetch` functionality. This is the second patch in a two-part series from Usman Akinyemi, implementing the ability to push to all remotes in a configured group (defined via `remotes.<name>` config) with a single command like `git push all-remotes`.

The implementation ensures group pushes behave identically to sequential individual pushes, with each remote processed independently using its own push mapping configuration. Key aspects include:
- Rebuilding refspec lists per-remote to respect `remote.<name>.push` config
- Isolating mirror/force-push flags per remote
- Continuing after ref rejections but stopping on fatal transport errors
- Using bitwise OR of individual exit codes for final status

The patch includes comprehensive documentation updates explaining the feature and its behavior, plus a new test script (t5566-push-group.sh) with extensive coverage of success cases, error isolation, and edge cases like mirror remotes in groups. The implementation appears clean and well-tested, with all feedback from Junio Hamano addressed in previous iterations. This looks ready for merging as a useful workflow enhancement.
