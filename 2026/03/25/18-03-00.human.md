This is a follow-up discussion in Justin Tobler's series about signature handling in `git fast-import` and `git fast-export`. The thread focuses on making the behavior consistent when invalid signature modes are provided.

Justin acknowledges Junio C Hamano's point that `fast-export` should reject invalid signature modes (like `abort-if-invalid`) during option parsing rather than waiting until encountering a signed commit. Currently, the code inconsistently fails early for nonsense modes but late for valid-but-unsupported modes.

The discussion reveals a design issue in how mode validation is shared between the import and export commands. Justin agrees to modify the next version to move validation into `parse_opt_sign_mode()` in `fast-export.c`, ensuring all invalid modes are caught at the same time during option parsing. This will provide a more consistent user experience between the two commands.

The exchange shows good progress on addressing the cross-tool consistency concern raised earlier in the thread. Justin's response indicates the series is moving toward resolution on this point, with the next version expected to implement the suggested validation timing fix.
