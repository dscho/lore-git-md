This is a follow-up discussion about Luiz Campos's proposed 'discard hunk' feature for `git add -p`. The thread has established the technical viability of the implementation, with reviewers Phillip Wood and Johannes Schindelin providing detailed feedback that has been addressed. The current discussion focuses on user experience considerations.

Luiz responds to D. Ben Knoble's earlier comments about two key aspects: recoverability of discarded hunks and the relationship to `git restore -p`. He acknowledges that providing a way to recover accidentally discarded hunks (as Vim's Fugitive plugin does) would be valuable, especially since changes not yet in the index would otherwise be permanently lost. On the `restore -p` question, Luiz clarifies that while similar functionality exists there, his goal is to allow discarding during `add -p` in a single pass rather than requiring a separate invocation.

The exchange reflects Git's careful approach to working tree modifications from staging commands. While the technical implementation appears sound, the discussion is now weighing design questions about command boundaries (whether this belongs in `add` or should leverage `restore`) and user safety (undo protection). These considerations may influence whether and how the feature ultimately lands.
