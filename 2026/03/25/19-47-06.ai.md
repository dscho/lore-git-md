Feature patch implementing remote group support for `git push`, completing the series started in previous patches. This version from Usman Akinyemi adds the core functionality to push to multiple remotes configured as a group, mirroring the existing `git fetch` group behavior.

The implementation handles each remote in the group sequentially, rebuilding refspec lists per-remote to respect individual `remote.<name>.push` configurations. It properly isolates mirror/force-push flags per remote and accumulates exit codes via bitwise OR to continue after failures. The documentation now clearly explains the failure handling behavior - push continues after ref rejections but stops on fatal transport errors.

Key technical details include:
- Uses the shared `add_remote_or_group()` function moved to remote.c in the previous patch
- Maintains identical behavior to sequential individual pushes (`git push G` == `git push r1; git push r2; ...`)
- Handles direct path arguments and URL fallback
- Includes comprehensive test coverage in t5566-push-group.sh verifying:
  - Basic group push functionality
  - Error isolation between remotes
  - Commit propagation
  - Mirror/refspec conflict detection
  - Push.default=current behavior
  - Failure handling (continues after ref rejections, stops on fatal errors)

The patch touches builtin/push.c (core logic changes), Documentation/git-push.adoc (new REMOTE-GROUPS section), and adds the new test file. All maintainer feedback from previous rounds has been addressed, including test improvements, documentation clarity, and type safety fixes. The series appears ready for merging with no outstanding technical issues, though parallel push support remains a potential future enhancement.
