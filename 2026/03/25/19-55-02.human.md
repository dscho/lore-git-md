This is a feature patch from Adrian Ratiu that makes disabled hooks visible in `git hook list` output, part of his ongoing series to modernize Git's hook configuration system. The patch builds on previous work that stored hook configurations in a cache, now extending it to track disabled hooks rather than filtering them out entirely.

Disabled hooks are now shown with a "disabled" prefix in the listing (or "disabled\t" when combined with the `--show-scope` flag). The implementation carefully maintains backward compatibility while adding the new visibility - traditional hooks from the hookdir remain unchanged, while configured hooks now show their disabled status. The patch also handles edge cases like disabled hooks without commands by emitting warnings rather than errors.

Key technical aspects include:
- New `disabled` flag in both the cache entry and hook struct
- Modified output formatting in `builtin/hook.c` to show status
- Updated `hook_exists()` to properly consider disabled state
- Comprehensive test coverage for the new behavior

The change is well-contained, touching primarily the hook subsystem files (`hook.c`, `hook.h`, `builtin/hook.c`) and adding several test cases. It follows the incremental improvement pattern seen throughout Adrian's series, building on established infrastructure while maintaining compatibility. The patch has already been through review iteration and is now part of the merged series in 'next'.
