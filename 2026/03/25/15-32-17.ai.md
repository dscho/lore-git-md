This is a documentation follow-up discussion for the already-approved `git replay` root commit handling patch. The technical implementation has been accepted by Junio Hamano and is queued for merging, but Christian Couder raises a documentation concern about potential user confusion with commit range syntax.

Christian points out that while the command now supports replaying from root commits, users might unintentionally trigger this behavior by omitting the proper range syntax (e.g. using just `topic` instead of `main..topic`). He suggests adding an explicit warning to the man page explaining this behavior and showing the correct syntax. Toon Claes acknowledges the value of this documentation improvement but suggests it could be handled separately from the current patch series.

The discussion reflects the transition of `git replay` from purely plumbing toward more user-facing functionality, with attention to preventing common usage pitfalls. While the technical change is settled, this exchange shows ongoing refinement of the command's UX through documentation, building on Ben Knoble's earlier suggestions about making the behavior more intuitive for monorepo workflows. The documentation clarification would help users understand when they might accidentally replay from root commits versus when they can intentionally use this new capability.
