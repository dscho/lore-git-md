This is a test infrastructure discussion in Junio Hamano's series to make the test suite more robust by enabling "set -e" (exit immediately on error). Patrick Steinhardt suggests an alternative approach to checking for SVN availability in the git-svn test helper script.

The current patch uses an explicit status capture pattern (`x=0; cmd || x=$?`) to work with "set -e", which is the consistent approach used throughout the series. Patrick proposes instead using `! svn help` directly in the conditional, which is more idiomatic shell but requires changing the check from looking for exit code 1 to testing command success/failure.

This is a stylistic suggestion rather than a functional change - both approaches would work with "set -e" but Patrick's version is more concise. The discussion reflects an ongoing theme in the thread about balancing explicit error handling with shell idioms when adapting tests for stricter error checking. Patrick's earlier feedback in the thread has favored clearer control flow patterns where possible.

The suggestion doesn't introduce new technical concerns but does raise the question of whether to maintain consistency with the series' established pattern or adopt more idiomatic shell constructs where they fit naturally. This is part of the broader test modernization effort to improve both reliability and readability of Git's test suite.
