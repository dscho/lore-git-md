[PATCH 0/3] refs: continue removing `the_repository` usage - now [PATCH 1-3/3]

Shreyansh Paliwal's series completes the current phase of `the_repository` removal in the refs subsystem with three focused patches eliminating global state. Patch 1/3 converts `get_files_ref_lock_timeout_ms()` to use explicit `struct repository*`, propagating through `lock_raw_ref()` via new `create_reflock_cb` wrapper while maintaining static timeout caching but using proper repository context for config lookup.

Patch 2/3 removes `the_hash_algo` in `refs.c` by converting core ref transaction functions (`ref_transaction_create()`, `ref_transaction_delete()`) to use hash algorithm from transaction's `ref_store->repo`, propagating changes through submodule ref stores and hooks while maintaining behavior.

Patch 3/3 (new) finalizes reftable backend conversion, replacing remaining `the_repository` uses in `reftable_be_init()` (using passed `repo` parameter for permissions/config) and `reftable_be_create_on_disk()` (using `ref_store->repo` for directory creation). The patch notes `USE_THE_REPOSITORY_VARIABLE` cannot yet be fully removed pending Patrick Steinhardt's upcoming `is_bare_repository()` conversion work.

Open issues remain around repository validity edge cases (invalid `GIT_DIR` paths) and deferred branch helper functions, with Jeff King's 2019 `startup_info->have_repository` comments and Tian Yuchen's `repo_has_repository()` proposal still under consideration. Test coverage gaps exist for invalid GIT_DIR scenarios. The series touches `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c` and related headers as part of René Scharfe's multi-year effort. Remaining work includes: finalizing repository validity semantics, integrating static timeout caching with `repo-settings`, replacing `startup_info`, Patrick's `is_bare_repository()` conversion, and branch helper updates. All three patches follow established patterns and appear ready for merging.
