[PATCH 0/3] refs: continue removing `the_repository` usage - now [PATCH 1-3/3]

Shreyansh Paliwal's series progresses the `the_repository` removal effort in refs subsystem, now narrowed to 3 focused patches after deferring branch helper conversions (original patches 1/5 and 5/5) due to unresolved edge cases. Current version systematically eliminates global state in three areas: file ref lock timeouts (1/3), hash algorithm usage in refs.c (2/3), and reftable backend (3/3).

Patch 1/3 (newly detailed) converts `get_files_ref_lock_timeout_ms()` to take explicit `struct repository*` parameter, propagating it through call chains from `lock_raw_ref()` (via transaction's ref_store) and via new `create_reflock_cb` wrapper for callback case. While timeout value remains statically cached, configuration lookup now uses proper repository context through `repo_config_get_int()`. This mechanical change follows established patterns from other parts of `the_repository` removal effort.

Patch 2/3 removes `the_hash_algo` in `refs.c` by using repository-specific versions. Patch 3/3 converts reftable backend by updating `reftable_be_init()` and `reftable_be_create_on_disk()` to use available repository context through function parameters or `ref_store` structure, while still depending on Patrick Steinhardt's upcoming `is_bare_repository()` conversion to fully remove `USE_THE_REPOSITORY_VARIABLE` macro.

Open issues remain around repository validity checking edge cases (notably when `GIT_DIR` points to non-existent path) and branch helper functions, now deferred for separate treatment. Jeff King's 2019 comment on `startup_info->have_repository` provides historical context, while Tian Yuchen's `repo_has_repository()` wrapper proposal remains under consideration as potential temporary solution. Current tests still lack coverage for invalid `GIT_DIR` scenario.

Series continues Rene Scharfe's multi-year effort, touching `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c` and related headers. Remaining work includes: resolving repository validity semantics, static timeout caching integration with `repo-settings`, `startup_info` replacement, Patrick's upcoming `is_bare_repository()` conversion in reftable backend, and final branch helper conversions. The focused approach demonstrates responsiveness to review feedback while maintaining clear division of labor between contributors on complex aspects.
