[PATCH 0/3] refs: continue removing `the_repository` usage - now [PATCH 1-3/3]

Shreyansh Paliwal's fifth iteration completes the refs subsystem's `the_repository` removal effort with three patches eliminating global state, now approved by Junio C Hamano for integration following Patrick Steinhardt's ack. The series systematically converts refs code to use explicit `struct repository*`: 1/3 updates `get_files_ref_lock_timeout_ms()` with wrapper struct for lock_file+repository callback passing; 2/3 removes `the_hash_algo` from core ref transaction functions via `ref_store->repo`; 3/3 cleans reftable backend's remaining `the_repository` uses in initialization and disk creation. This represents incremental but important progress in René Scharfe's long-running effort to eliminate global state.

Open issues remain around repository validity semantics (Jeff King's 2019 `startup_info->have_repository` comments, Tian Yuchen's `repo_has_repository()` proposal) and pending work on static timeout caching with `repo-settings`, `startup_info` replacement, Patrick Steinhardt's `is_bare_repository()` conversion, and branch helper updates - all deferred for separate follow-up. The series touches `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c`, with the reftable backend now largely converted except for bare repo checks. Version 5's main change was clarifying the first patch's commit message about remaining static variables and future work. Junio notes these iterations had previously escaped his attention, suggesting the series may have been queued in `seen` before reaching final approval.
