[PATCH 0/3] refs: continue removing `the_repository` usage - now [PATCH 1-3/3]

Shreyansh Paliwal's fifth iteration continues the `the_repository` removal effort in the refs subsystem with three focused patches. The series systematically eliminates global state: 1/3 converts `get_files_ref_lock_timeout_ms()` to use explicit `struct repository*` while maintaining static timeout caching, with improved commit messages addressing Tian Yuchen's feedback about remaining static variables and future work needed to fully repository-scope this functionality. The patch adds a small wrapper struct to pass both lock_file and repository through callbacks in `create_reflock()`. 2/3 removes `the_hash_algo` in core ref transaction functions by using `ref_store->repo`'s hash algorithm, updating `ref_transaction_create()`, `ref_transaction_delete()`, `repo_get_submodule_ref_store()`, `transaction_hook_feed_stdin()`, and `migrate_one_ref()` to use repository-specific hash algorithms. 3/3 finalizes reftable backend conversion by replacing remaining `the_repository` uses where repository context is available.

Open issues include repository validity edge cases (invalid `GIT_DIR` paths) with Jeff King's 2019 `startup_info->have_repository` comments and Tian Yuchen's `repo_has_repository()` proposal still under consideration. The series touches `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c` as part of René Scharfe's multi-year effort. Remaining work includes finalizing repository validity semantics, integrating static timeout caching with `repo-settings`, replacing `startup_info`, Patrick Steinhardt's upcoming `is_bare_repository()` conversion, and deferred branch helper updates. The review discussion shows constructive dynamics with feedback being incrementally incorporated, particularly around documentation clarity in version 5. The changes remain mechanical but important steps toward eliminating global state while maintaining existing behavior.
