[PATCH 0/5] refs: continue removing `the_repository` usage

Series from Shreyansh Paliwal eliminating global state in refs subsystem by converting functions to take explicit `struct repository *` parameters. Builds on jw/object-name-bitset-to-enum. Five mechanical conversions covering branch helpers, file ref lock timeouts, hash algorithm usage, reftable backend, and packed backend. All three ref backends (files, reftable, packed) now free of direct `the_repository` usage except for one remaining `is_bare_repository()` dependency in reftable.

Patrick Steinhardt reviewed the branch helper conversions (patch 1/5), noting the changes look good but suggesting placing `struct *` parameters first in function signatures per codebase convention. For patch 2/5 (ref lock timeouts), Patrick confirms the technical approach using a `create_reflock_cb` struct to pass both lock_file and repository context through to the `create_reflock()` callback is correct. This callback adaptation follows standard patterns for threading repository parameters through indirect function calls like those used by `raceproof_create_file()`.

Changes touch branch.c, ref-filter.c, builtin commands (branch, checkout, worktree), and refs backends, propagating repository parameters where no specific context exists. Series represents significant progress in the long-running `the_repository` removal effort led by René Scharfe, following established patterns without behavior changes. Builds cleanly on previous work. Known limitation remains in reftable backend requiring future follow-up. Patrick's positive review of patch 2/5 indicates this part of the series is technically sound and likely to proceed without further discussion.
