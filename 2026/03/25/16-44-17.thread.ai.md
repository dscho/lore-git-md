[PATCH 0/3] refs: continue removing `the_repository` usage - now [PATCH 1-3/3]

Shreyansh Paliwal's fifth iteration completes the refs subsystem's `the_repository` removal effort with three focused patches. The series systematically eliminates global state: 1/3 converts `get_files_ref_lock_timeout_ms()` to use explicit `struct repository*` while maintaining static timeout behavior, adding a wrapper struct for lock_file+repository callback passing. 2/3 removes `the_hash_algo` from core ref transaction functions by using `ref_store->repo`'s hash algorithm. 3/3 (this final patch) cleans up the reftable backend by replacing three remaining `the_repository` uses where local repository context exists - in `reftable_be_init()` and `reftable_be_create_on_disk()` for permissions, config, and directory handling. The commit notes `USE_THE_REPOSITORY_VARIABLE` remains due to outstanding `is_bare_repository()` calls.

Open issues include repository validity semantics (Jeff King's 2019 `startup_info->have_repository` comments, Tian Yuchen's `repo_has_repository()` proposal) and pending work on static timeout caching integration with `repo-settings`, `startup_info` replacement, Patrick Steinhardt's `is_bare_repository()` conversion, and branch helper updates. The series touches `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c` as part of René Scharfe's multi-year effort. Review discussion shows constructive feedback incorporation, particularly around documentation clarity in version 5. While mechanical, these changes represent important steps toward eliminating global state while maintaining behavior, with the reftable backend now largely converted except for bare repo checks.
