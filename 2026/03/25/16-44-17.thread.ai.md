[PATCH 0/5] refs: continue removing `the_repository` usage

Series from Shreyansh Paliwal eliminating global state in refs subsystem by converting functions to take explicit `struct repository *` parameters, building on jw/object-name-bitset-to-enum. Five mechanical conversions covering branch helpers (1/5), file ref lock timeouts (2/5), hash algorithm usage (3/5), reftable backend (4/5), and packed backend (5/5). All three ref backends (files, reftable, packed) now free of direct `the_repository` usage except one remaining `is_bare_repository()` dependency in reftable.

Version 2 incorporates review feedback from Patrick Steinhardt and Burak Kaan Karaçay on v1. Key changes: function signatures now place `struct repository *` parameters first per codebase conventions (Patrick's suggestion), while maintaining the `create_reflock_cb` struct design for passing lock_file and repository context through callbacks (Patrick-approved). Burak noted static variables for timeout caching remain a multi-repo concern, suggesting future migration to `repo-settings` - Shreyansh acknowledges this technical debt and agrees to address it in follow-up work while keeping current patches focused.

Patch 1/5 (branch helpers) completes review cycle with Patrick's feedback incorporated, now with additional refactoring of branch name helper functions (`copy_branchname()`, `check_branch_ref()`) to remove implicit `the_repository` usage when calling `repo_interpret_branch_name()`. Changes propagate through validation helpers (`validate_branchname()`, `validate_new_branchname()`) and their call sites in builtin commands (branch, checkout, worktree). Patch 2/5 (ref lock timeouts) makes `get_files_ref_lock_timeout_ms()` repository-aware by taking `struct repository*` parameter, affecting files backend lock handling. Patch 3/5 (hash algorithm) eliminates `the_hash_algo` usage in refs subsystem by propagating repository context through transaction creation/deletion, submodule ref store initialization, hook stdin feeding, and ref migration - removing `USE_THE_REPOSITORY_VARIABLE` and `environment.h` inclusion where no longer needed. Patch 4/5 (reftable backend) removes two `the_repository` uses while the persistent `is_bare_repository()` call remains a systemic blocker for complete `USE_THE_REPOSITORY_VARIABLE` removal.

Series builds cleanly with no behavior changes. Known limitations: reftable backend's bare repo dependency, ref lock timeout caching needing future `repo-settings` integration. Patrick's reviews indicate technical soundness for inclusion, with Burak's observation providing direction for refinement. The mechanical nature and incremental progress align with project's preference for focused, reviewable patches in this multi-year effort led by René Scharfe. All conversions follow established patterns of placing repository parameters first and maintaining existing behavior while removing global state.
