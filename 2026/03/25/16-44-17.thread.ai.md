[PATCH 0/3] refs: continue removing `the_repository` usage - now [PATCH 1-3/3]

Shreyansh Paliwal's fifth iteration completes the refs subsystem's `the_repository` removal effort with three focused patches eliminating global state. The series systematically converts refs code to use explicit `struct repository*`: 1/3 updates `get_files_ref_lock_timeout_ms()` with wrapper struct for lock_file+repository callback passing; 2/3 removes `the_hash_algo` from core ref transaction functions via `ref_store->repo`; 3/3 cleans reftable backend's remaining `the_repository` uses in initialization and disk creation. Patrick Steinhardt has acked version 5 as ready for integration, noting deferred complex aspects (mentioned in v4 cover letter) will be handled separately.

Open issues include repository validity semantics (Jeff King's 2019 `startup_info->have_repository` comments, Tian Yuchen's `repo_has_repository()` proposal) and pending work on static timeout caching with `repo-settings`, `startup_info` replacement, Patrick Steinhardt's `is_bare_repository()` conversion, and branch helper updates. The series touches `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c` as part of René Scharfe's multi-year effort. Version 5's main improvement was clarifying the first patch's commit message about remaining static variables and future work. While mechanical, these changes represent important steps toward eliminating global state while maintaining behavior, with the reftable backend now largely converted except for bare repo checks.
