[PATCH 0/5] refs: continue removing `the_repository` usage

Series from Shreyansh Paliwal completing the elimination of global state in the refs subsystem by making functions explicitly take `struct repository *` parameters. Builds on jw/object-name-bitset-to-enum. Five mechanical conversions:

1. Converts branch name helpers (branch.c, ref-filter.c) to take explicit repository parameters, updating `copy_branchname()`, `check_branch_ref()`, and related functions, with changes propagated through builtin commands (branch, checkout, worktree) where `the_repository` is passed when no specific context exists.

2. Makes file ref lock timeout handling (refs/files-backend.c) repository-aware by adding `struct repository` parameter to `get_files_ref_lock_timeout_ms()`, updating `lock_raw_ref()` to pass repository from transaction's ref_store, and introducing `create_reflock_cb` struct to pass both lock_file and repository through callback data.

3. Removes last `the_hash_algo` uses in refs.c by switching to repository-specific algorithms from transaction->ref_store->repo->hash_algo and repo->hash_algo in submodule ref store initialization, removing now-unused `USE_THE_REPOSITORY_VARIABLE` and `environment.h` include.

4. Eliminates remaining `the_repository` usage in reftable backend (reftable/backend.c) except for `is_bare_repository()` dependency, removing global state in `calc_shared_perm()`, `repo_config()`, and `safe_create_dir()` by using available repository parameters (`repo` and `ref_store->repo`).

5. Final patch removes last `the_repository` usage in packed backend (refs/packed-backend.c) by replacing it with `ref_store->repo` when reading packed refs timeout config, removing the now-unused `USE_THE_REPOSITORY_VARIABLE` macro from this file.

Series represents significant progress in the long-running `the_repository` removal effort led by René Scharfe. Changes are mechanical and focused, following established patterns without altering behavior. Touches refs/*, branch.c, ref-filter.c, and builtin commands. Builds cleanly on previous work. Known limitation remains in reftable backend (`is_bare_repository()` dependency) requiring future follow-up. With this series, all three ref backends (files, reftable, packed) are now free of direct `the_repository` usage except for the noted exception.
