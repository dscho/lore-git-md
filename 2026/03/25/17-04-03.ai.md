This is a follow-up in the thread about adding a 'discard hunk' feature to `git add -p`. Luiz Campos responds to D. Ben Knoble's review comments about recoverability and command boundaries.

The author acknowledges the valid concern about making discarded hunks recoverable, agreeing that storing them as blobs or providing undo capability would be a useful safety measure for changes never added to the index. This addresses the first part of Ben's feedback about protecting users from accidental data loss.

On the comparison with `git restore -p`, Luiz clarifies the motivation - allowing discard decisions during the same interactive pass as staging decisions, rather than requiring a separate invocation. However, they express openness to reconsidering whether integrating this into `add -p` is indeed the best approach, showing willingness to revisit the design choice based on further discussion.

The response maintains a constructive tone while demonstrating thoughtful engagement with the review feedback. It moves the discussion forward by identifying recoverability as a key gap to address while keeping the door open to alternative implementations. The technical exchange reflects Git community norms of carefully considering edge cases and user workflows even for seemingly simple features.
