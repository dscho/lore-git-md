This is an RFC proposing a new feature for `git add -p` that would allow directly discarding hunks from the working tree. The patch from Luiz Campos introduces an 'x' action that reverse-applies hunks, addressing a workflow pain point where users currently have to manually remove unwanted changes after skipping them in the interactive session.

The implementation modifies `add-patch.c` to handle the new discard action, adding a `DISCARD_HUNK` state and plumbing it through the hunk processing logic. The changes are relatively focused (3 files, ~150 lines net) and include test coverage in t3701 that verifies the discard functionality works as expected. The documentation is updated to explain that discarded hunks will be removed from the working tree before any staging occurs.

The patch builds on prior discussion where Jeff King raised related concerns about working tree modifications during interactive sessions. The author has clearly considered edge cases, with the implementation carefully handling hunk merging and refresh logic. The RFC status suggests the author is particularly interested in feedback about the timing of discards (immediate vs deferred) and handling of overlapping/edited hunks.

This appears to be a well-motivated quality-of-life improvement for `git add -p` users, implemented with appropriate caution given it modifies working tree state. The changes are cleanly scoped to the interactive patch machinery without broader architectural implications. Phillip Wood, as the primary maintainer of this area, would likely be a key reviewer.
