This is the final patch in a series adding `--revert` capability to `git replay`, now in its sixth iteration. The feature enables server-side reverts on bare repositories, primarily for GitLab's Gitaly service use case.

The patch implements commit-by-commit reversal by treating reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent), following the same approach used in `sequencer.c`. Reverts are processed newest-first to minimize conflicts, with commit messages following standard `git revert` conventions ("Revert" prefix and original commit reference). The implementation includes comprehensive test coverage for various scenarios including bare repos, revert-of-revert cases, and conflict handling.

The series has undergone extensive review from Phillip Wood, Patrick Steinhardt, and Junio Hamano, with all substantive feedback addressed. The v6 changes are minor final tweaks to fix a compiler warning and update documentation. The implementation is well-structured, with revert message generation consolidated in a helper function and clear separation between pick and revert modes.

This appears ready for merging as a useful addition to Git's server-side history rewriting capabilities, particularly for platforms like GitLab that need to operate on bare repositories. The careful review process and thorough test coverage suggest this is production-ready code.
