This is a refactoring patch in the xdiff subsystem, part of Ezekiel Newren's narrowed-down series to improve code clarity in `xdl_cleanup_records()`. The patch focuses specifically on making limit calculations more explicit and removing redundant conditions.

The key changes in this patch are:
1. Introduces separate `mlim1` and `mlim2` variables for per-file limits, initialized clearly at the start of the function rather than being recalculated in each loop
2. Removes the redundant `!need_min` condition that was previously checked alongside the limit comparison
3. Moves the limit calculation logic out of the loops where it was previously repeated
4. Uses `SIZE_MAX` to clearly indicate "infinity" for the minimal case

The changes are purely internal to the diff algorithm's record cleanup logic and don't affect behavior - this is strictly about making the code more readable and maintainable. The patch follows the series' theme of focusing on uncontroversial improvements after feedback on the broader v1 approach.

Technical details that might matter for future discussion include:
- The `mlim1`/`mlim2` variable names and their initialization pattern
- The removal of the `!need_min` check from the INVESTIGATE condition
- The use of `SIZE_MAX` to represent the minimal case
- The unchanged DISCARD/KEEP/INVESTIGATE action logic flow

This continues the series' pattern of small, focused improvements to xdiff's core algorithms while avoiding the more structural changes that generated discussion in v1.
