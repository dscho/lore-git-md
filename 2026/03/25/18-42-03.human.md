This is a feature patch completing the implementation of remote group support for `git push`, mirroring the existing group functionality in `git fetch`. The patch series is now in its final polishing stage after thorough review from maintainer Junio Hamano.

The feature allows pushing to all remotes in a configured group (defined via `remotes.<name>` config) with a single command like `git push all-remotes`. The implementation ensures group pushes behave identically to sequential individual pushes, with each remote respecting its own configuration (push URLs, refspecs, force/mirror flags). Failures are accumulated via bitwise OR, allowing the push to continue to other remotes after a failure.

This version addresses the last minor issues raised in review - fixing a type mismatch in a loop counter (`int` to `size_t`) and other small polish items. The core design questions were resolved earlier in the thread, establishing that group pushes should precisely match the behavior of individual pushes in all aspects including `push.default` modes and `--force-with-lease` semantics. 

Test coverage has been added and documentation updated. The patch appears ready for merging, with all maintainer feedback addressed. The only remaining limitation is lack of parallel push support (unlike fetch's parallel option), which could be added later.
