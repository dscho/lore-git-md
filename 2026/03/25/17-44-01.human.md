This is the second patch in Pablo Sabater's v5 series adding a `--graph-lane-limit` feature to `git log --graph`. The patch focuses on documentation and testing for the new option.

The documentation update in `rev-list-options.adoc` clearly explains the new `--graph-lane-limit=<n>` parameter, describing how it caps the number of graph lanes shown (with excess lanes marked by '~') and noting that zero/negative values mean no limit. 

The bulk of the patch adds comprehensive test coverage in `t4215-log-skewed-merges.sh`, demonstrating the feature's behavior in various scenarios:
- Basic lane limiting (2 lanes)
- Handling of octopus merges when limited to 1 lane
- Complex multi-merge graphs with 3 and 6 lane limits
- Verification that a 7-lane limit shows all parents of a 3-parent merge

The tests reuse existing graph structures from the test file while clearly showing the truncation behavior. The test expectations are well-formatted and easy to follow, with the '~' markers clearly indicating where lanes are being collapsed. This appears to be a thorough test suite that exercises both the happy path and edge cases.
