This is the v5 submission of Pablo Sabater's feature proposal for a `--graph-lane-limit` option in `git log --graph` output. The series addresses terminal readability issues with wide commit graphs by horizontally truncating excess lanes while preserving key commit markers, using '~' to indicate truncated lanes (changed from '.' to avoid conflict with octopus merge notation).

The implementation introduces a `graph_max_lanes` field in `struct rev_info` (type `int`, where negative/zero means no limit) and modifies graph.c's output logic to cap displayed columns. The series now merges the parsing and truncation logic into a single patch (fixing a prior build break) and adds comprehensive documentation and tests. Visual examples in the cover letter clearly demonstrate the horizontal truncation behavior, contrasting with gitk's vertical approach.

Key technical refinements since v4 include standardized error message formatting, improved code style (addressing Hannes' feedback), and explicit documentation of zero/negative value semantics. The patch touches graph.c's core rendering logic but maintains all existing behavior when the limit isn't reached.
