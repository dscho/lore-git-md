This is a documentation follow-up to the recently approved `git replay` root commit handling patch. Christian Couder suggests adding a clarification to the man page about commit range specification, noting that while the command now supports replaying from root commits, users might unintentionally trigger this behavior if they don't properly specify ranges like `main..topic`.

The proposed documentation change would explicitly warn that `git replay --onto main topic` will replay from the root commit rather than from `main`, and suggest the correct range syntax. This addresses a potential UX issue where users might misunderstand the command's behavior, especially as the tool evolves toward being more user-facing (as indicated by Elijah Newren's long-term goals for the command).

The suggestion comes after Junio Hamano's approval of the technical implementation, indicating this is purely a documentation polish rather than a blocker for merging. Christian's note about `git replay` currently being a plumbing command suggests this improvement is forward-looking, anticipating wider user adoption. The change would help prevent confusion without requiring any code modifications to the already-approved patch.
