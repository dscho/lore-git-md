This is the first patch in Junio C Hamano's test infrastructure series to make the test suite more strict by enabling "set -e" (exit immediately on errors) early in test execution. The patch fixes a framework-level issue where the initial Git binary check would fail under "set -e" due to its non-zero exit code.

The change modifies the test framework to properly handle Git's expected exit code 1 (which occurs when running plain `git` with no arguments) without triggering "set -e" termination. This is done by capturing the exit status in a variable rather than checking $? directly. The patch is straightforward and focused - it only touches the test framework's initialization code in t/test-lib.sh.

As the first step in a larger effort to catch test script errors earlier, this patch demonstrates the careful approach needed when making the test suite more strict. The change is minimal but important groundwork for the rest of the series, which will adjust individual test scripts to work with the new stricter mode. Given that it comes from the maintainer and addresses a clear pain point (misspelled test directives going unnoticed), this appears to be a well-justified improvement to the test infrastructure.
