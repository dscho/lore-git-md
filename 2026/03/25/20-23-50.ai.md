This is the final version (v6) of a feature addition to the `git replay` command, introducing a `--revert` mode for server-side history rewriting. The series has undergone extensive review from Phillip Wood, Patrick Steinhardt, and Junio Hamano, with all substantive feedback addressed across six iterations.

The changes enable `git replay` to reverse commits directly on bare repositories, which is particularly useful for GitLab's Gitaly service where server-side operations on bare repos are common. The implementation follows the same approach as `sequencer.c`, treating reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent) to effectively reverse the diff direction.

Key changes in v6 are minor final tweaks:
- Fixed a `-Werror=declaration-after-statement` compiler warning by moving a variable declaration in `builtin/replay.c`
- Updated documentation to mention `--revert` mode alongside `--advance` in the `<revision-range>` explanation

The implementation has comprehensive test coverage and builds on established patterns in the codebase. The higher-level interface design (flags vs subcommands) remains an ongoing discussion but is being deferred to avoid scope creep in this series. With these final adjustments, the series appears ready for merging.
