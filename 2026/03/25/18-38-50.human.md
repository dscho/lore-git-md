Feature implementation for `git add -p` discard action, with responses to review feedback.

Luiz Campos responds to Phillip Wood's detailed code review of the 'x' (discard) action for `git add -p`. The patch would allow users to discard selected hunks directly from the working tree during interactive staging. While the implementation appears technically sound, there are ongoing concerns about whether this functionality belongs in `git add` at all.

Key points from the response:
- Luiz acknowledges the concern about `git add` modifying the worktree being conceptually unexpected, but notes the workflow motivation (allowing stage-and-discard in one pass)
- Agrees to simplify the hunk merge logic by passing USE_HUNK/DISCARD_HUNK directly rather than using boolean flags
- Corrects the delta application direction during reverse patching by temporarily inverting s->mode->reverse
- Plans to restructure tests to avoid needing a separate repository
- Will add test cases for split hunks and pathological context lines
- Clarifies that the discard action should be available whenever edit (e) is, but not gated by ALLOW_EDIT

The thread now faces a fundamental design question raised by Junio Hamano - whether this functionality should live in `git add -p` at all, or if a new unified interactive command would be more appropriate.
