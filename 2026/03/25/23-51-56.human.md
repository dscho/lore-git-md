This is the fourth patch in Taylor Blau's series addressing pack-objects issues during geometric repacking, specifically when MIDX bitmap generation fails due to packs not being closed under reachability. The patch introduces a new "excluded-open" pack state (marked with '!') to properly handle objects reachable through excluded packs while excluding their direct contents.

The key technical contribution here is the new pack state that allows commits in excluded packs to serve as traversal starting points while still excluding their objects from the output. This solves a subtle edge case where objects could be missed during repacking if they were only reachable through excluded packs. The implementation adds a new `pack_keep_in_core_open` flag and corresponding `KEPT_PACK_IN_CORE_OPEN` constant to track this state.

The patch includes thorough documentation updates explaining the new behavior and adds test cases demonstrating both the happy path and error conditions. The tests verify that objects are properly rescued from excluded-open packs while respecting the closure boundary of excluded-closed packs.

This appears to be a well-considered solution to a complex edge case in Git's pack handling. The patch builds on previous work in the series (the strmap refactoring and test case addition) and has already incorporated feedback from Jeff King and Patrick Steinhardt. As the fourth of five patches, it represents the core technical solution to the problem identified earlier in the series.
