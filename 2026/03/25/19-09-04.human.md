This is a feature patch series that adds remote group support to `git push`, mirroring the functionality that already exists for `git fetch`. The v3 iteration from Usman Akinyemi refines the implementation based on maintainer feedback and adds more comprehensive test coverage.

The core change allows users to push to all remotes in a configured group (defined via `remotes.<name>` config) with a single command like `git push all-remotes`. The implementation ensures this behaves identically to running individual pushes sequentially, with each remote following its own push configuration and refspecs.

Key improvements in v3 include:
- Clearer documentation explaining failure handling (continues on rejections but stops on fatal errors)
- More robust test cases verifying commit propagation and error scenarios
- Type safety fixes (using `size_t` for loop counters)
- Removal of redundant test assertions in favor of direct commit verification
- Added tests for partial failure cases (non-fast-forward rejections vs transport errors)

The series has progressed through multiple review rounds with Junio Hamano, who has provided guidance on core behavior and presentation details. The implementation now cleanly unifies single-remote and group handling after Junio suggested treating a single remote as a group of one. All key design questions around push.default behavior and force-with-lease semantics have been resolved.

This is a well-scoped contribution that fills a real workflow gap, with thorough test coverage and documentation. The changes touch core remote-handling code but follow established patterns from the fetch implementation. The series appears ready for merging, though parallel push support remains a potential future enhancement.
