This is the second and final patch in a refactoring series that improves help text handling for `git repo` subcommands. Maintainer Junio C Hamano has reviewed and approved the changes, noting they make sense and appear ready for inclusion.

The patch completes the work started in the first patch by making each subcommand (`info` and `structure`) show only its own usage information when invoked with `-h`, rather than the full command list. It introduces separate usage arrays for each subcommand that reference the macros extracted in the first patch, and updates the `parse_options()` calls accordingly. Junio confirms the shared `repo_usage` array remains properly used for the top-level `git repo -h` output.

The implementation includes thorough test coverage verifying the scoped help output - checking that each subcommand's `-h` shows only its own help text while excluding the other's. Junio notes one minor caveat about the exit code behavior of `-h` (currently tested as failing but potentially changing to success in future), but considers this acceptable for now given existing test patterns.

This appears to be a clean, well-structured conclusion to the series, delivering the promised improvement to subcommand help output while maintaining Git's coding standards. With Junio's approval and the preparatory refactoring already acked, this patch seems ready for merging.
