This is a feature and refactoring patch from Adrian Ratiu, part of his completed series modernizing Git's hook configuration system. The patch adds validation to reject unknown hook names in `git hook run` and `git hook list` commands, helping catch typos like "prereceive" when "pre-receive" was intended.

The change introduces a new `--allow-unknown-hook-name` flag to bypass the validation when needed, maintaining flexibility for custom hooks. The list of known hooks comes from `hook-list.h`, which is generated from `Documentation/githooks.adoc`. The implementation includes Makefile updates to ensure proper header dependencies and comprehensive test coverage for the new behavior.

This patch builds on Adrian's previous work to make hooks more configurable through Git's configuration system. It follows the project's pattern of incremental improvement while maintaining backward compatibility. The series has already been through multiple review iterations and is now merged to 'next', with Patrick Steinhardt, Junio Hamano, and Eric Sunshine having provided feedback that's been incorporated.

The change is well-scoped, touching primarily `builtin/hook.c` and the test suite, with clear commit messages explaining each modification. It demonstrates careful attention to both user experience (helping avoid typos) and maintainability (using generated header for hook names).
