This is a review comment from Johannes Sixt (Hannes) on the final patch in Pablo Sabater's v4 series adding `--graph-lane-limit` support. Hannes raises concerns about the visual interpretation of the lane truncation behavior in the test cases.

Hannes expected truncation to mean that vertical graph lines would be interrupted and later resumed (with color being the only connection clue), but the implementation actually replaces excess lanes with '.' markers while keeping the commit markers ('*') visible. This creates a different visual effect than Hannes anticipated, where truncated lanes are simply omitted from display rather than being temporarily hidden.

The review focuses on two test cases where the output appears to show more lanes than the specified maximum (3 lanes when limit=2, 4 when limit=3). Hannes realizes this is because the test output includes the '.' markers that replace truncated lanes, making the display wider than expected. This leads him to reconsider his understanding of the truncation semantics.

This feedback suggests the documentation may need clarification about how truncation markers affect the visual width of the graph output. The implementation itself appears correct per the series' design, but the visual result differs from at least one reviewer's expectations. The author may need to either adjust the documentation to better set expectations or reconsider the display approach if this misunderstanding proves common among reviewers.

The comment does not block the series but indicates a potential usability concern that warrants discussion before final merge. Hannes explicitly states he needs to reconsider his position after this realization. This could lead to either documentation updates or design changes in a future revision.
