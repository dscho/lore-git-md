This is a feature patch for `git add -p` that adds a 'discard hunk' action, building on prior RFC discussion. Phillip Wood, the sequencer and interactive patch machinery expert, provides a detailed code review of Luiz Campos' implementation.

Phillip raises several technical concerns about the implementation details while acknowledging the usefulness of the feature. He questions whether `git add` should modify the working tree (agreeing with Jeff King's earlier concerns), suggests the discard operation might be better suited for a new command, and provides specific feedback on the code structure. Key points include:

1. The implementation needs to properly handle hunk offsets when applying in reverse
2. The discard action should likely not be shown for `checkout -p` and similar modes
3. The test suite should be expanded to cover more edge cases (split hunks, pathological context lines)
4. Several code simplifications are possible in the hunk merging logic

Phillip's review is thorough but cautious, reflecting his deep knowledge of the interactive patch machinery. While he doesn't outright reject the feature, his comments suggest the implementation needs refinement before it could be merged, particularly around the working tree modification behavior and test coverage.

The discussion continues the careful balancing act Git maintainers perform when adding new interactive features - weighing user convenience against command boundaries and implementation robustness. Phillip's position as the subsystem expert makes his feedback particularly important for this change.
