This is the third patch in Junio C Hamano's 11-part series to make Git's test suite more robust by enabling "set -e" (exit immediately on errors) during test execution. The patch focuses on fixing t6002-rev-list-bisect.sh to work correctly under this stricter mode.

The issue being addressed is that the test script uses `expr` for arithmetic calculations, which exits with status 1 when the result is 0 or null - a case that shouldn't fail the test. The patch modifies two `expr` calls to explicitly check the exit code (`test $? -le 1`) rather than letting "set -e" treat them as failures. This is a straightforward mechanical change that preserves the test's logic while making it compatible with the upcoming stricter error checking.

The change is part of a larger effort to catch test framework typos and silent failures earlier. While this particular adjustment is minor, it's one of several needed to safely enable "set -e" across the entire test suite. The patch follows the pattern established in earlier parts of the series for handling expected non-zero exit codes.
