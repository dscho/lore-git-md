This is a feature addition to the `git replay` command, now at v6, introducing a `--revert` mode for server-side history rewriting. The series has undergone extensive review from Phillip Wood, Patrick Steinhardt, and Junio Hamano, with all substantive feedback addressed.

The changes enable `git replay` to reverse commits directly on bare repositories, which is particularly useful for GitLab's Gitaly service where server-side operations on bare repos are common. The implementation follows the same approach as `sequencer.c`, treating reverts as merges with swapped arguments to effectively reverse the diff direction.

Key changes in v6 are minor final tweaks:
- Fixed a `-Wdeclaration-after-statement` compiler warning by moving a variable declaration
- Updated documentation to mention `--revert` mode alongside `--advance` in the `<revision-range>` explanation

The series builds on prior versions that:
- Extracted revert message formatting into a shared function (`sequencer_format_revert_message()`)
- Added comprehensive test coverage
- Refined error handling and documentation
- Ensured consistent behavior with existing revert operations

This appears ready for merging, with all technical points addressed and only a minor documentation nit remaining for potential future follow-up. The implementation follows established patterns and has thorough test coverage.
