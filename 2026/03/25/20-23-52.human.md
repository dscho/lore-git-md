This is the second patch in a v6 series adding `--revert` capability to `git replay`, now ready for merging. The feature enables server-side reverts on bare repositories, primarily for GitLab's Gitaly service.

The patch implements the core revert functionality, treating reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent) to reverse the diff direction. It processes commits newest-first to reduce conflicts, generates standard revert commit messages ("Revert ..." with original commit hash), and uses the current user as author (matching `git revert` behavior).

Key technical aspects:
- Adds `REPLAY_MODE_REVERT` alongside existing `REPLAY_MODE_PICK`
- Reuses `sequencer_format_revert_message()` for consistent message formatting
- Handles reverts of reverts by using "Reapply" prefix
- Includes comprehensive tests covering basic reverts, bare repos, revert-of-revert, and conflict cases

The implementation follows established patterns from `sequencer.c` and has been thoroughly reviewed by Phillip Wood, Patrick Steinhardt, and Junio Hamano across six iterations. All substantive feedback has been addressed, with v6 fixing a final compiler warning and documentation nit. The series appears production-ready and well-aligned with Git's existing revert behavior.
