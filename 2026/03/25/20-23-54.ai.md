This is the second patch in a v6 series adding `--revert` capability to `git replay`, now ready for merging after extensive review. The feature enables server-side reverts on bare repositories, primarily for GitLab's Gitaly service.

The implementation treats reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent) to reverse the diff direction, matching `sequencer.c`'s approach. Reverts are processed newest-first to minimize conflicts, with commit messages following standard revert conventions ("Revert" prefix, original commit reference). The patch introduces a new `REPLAY_MODE_REVERT` operation mode alongside the existing `REPLAY_MODE_PICK`.

Key technical changes include:
- Swapped merge tree ordering in `pick_regular_commit()` for revert case
- Consolidated revert message generation via `sequencer_format_revert_message()`
- New documentation explaining `--revert` behavior and constraints
- Comprehensive test coverage including bare repo scenarios and revert-of-revert cases

The patch builds on prior iterations that refined memory management, error handling, and test coverage. Reviewers Phillip Wood, Patrick Steinhardt, and Junio Hamano have signed off on the technical approach, with all substantive feedback addressed. The only remaining change in v6 fixes a compiler warning and updates documentation.

This represents a well-executed addition to Git's server-side history rewriting capabilities, with clear motivation (GitLab's bare repo use case) and thorough implementation that follows established patterns from the sequencer. The extensive test suite and documentation updates make this a high-quality contribution ready for integration.
