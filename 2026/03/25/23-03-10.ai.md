This is a follow-up discussion about a memory leak fix in the pack-objects geometric repacking series. Taylor Blau responds to Patrick Steinhardt's question about why tests didn't catch the `rev_info` leak in `read_stdin_packs()`.

Taylor explains that while the function declares a `rev_info` struct, the only memory allocation occurs in `revs->pending`, which gets copied to `old_pending` during `prepare_revision_walk()`. Since the traversal doesn't use other `rev_info` fields that would allocate memory, no actual leak occurs in practice - the patch is preventing a future leak rather than fixing a current one.
