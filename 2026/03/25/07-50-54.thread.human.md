This RFC and implementation thread explores adding an 'x' (discard) action to `git add -p`, allowing users to discard unwanted hunks directly from the working tree during interactive staging. Luiz Campos' implementation builds on Phillip Wood's interactive patch machinery, introducing new discard functionality while carefully maintaining the existing code structure.

Phillip Wood, the subsystem expert, has now reviewed the implementation in detail. While maintaining his philosophical objection to having `git add` modify the working tree (echoing Jeff King's earlier concerns), he focused his review on implementation quality. He suggested several technical improvements: simplifying the hunk merge logic, fixing delta application direction, refining test coverage, and addressing an apparent inconsistency in when the discard action is available. D. Ben Knoble had previously raised thoughtful UX considerations about undo safety and command boundaries.

The discussion has moved from whether this feature belongs in `git add` (a question largely treated as settled for this patch series) to how best to implement it. Phillip's review indicates the code is technically sound aside from the noted issues, suggesting it's nearing readiness. Open questions remain about the discard action's availability across different `add -p` modes and whether additional safeguards might be needed for the working tree modifications. The patch demonstrates good awareness of the interactive patch subsystem while proposing a user-visible behavior change that has undergone careful design validation through the mailing list review process.
