This thread proposes adding a 'discard hunk' ('x') action to `git add -p`, allowing users to directly remove unwanted changes from their working tree during interactive staging. Luiz Campos initially floated the idea as an RFC and has now followed up with a concrete implementation.

The implementation modifies the interactive patch machinery in `add-patch.c` to support reverse-applying hunks, eliminating the current workflow pain point where users must manually clean up skipped hunks. The patch introduces a `DISCARD_HUNK` state and handles the new operation while maintaining the existing staging behavior. It includes comprehensive test coverage and addresses edge cases raised in the RFC discussion, such as proper hunk merging when discards are involved.

Key open questions center on the safety and timing of working tree modifications - whether discards should happen immediately or be deferred - and how the new action interacts with other hunk operations like editing and splitting. The patch builds thoughtfully on Phillip Wood's work on the interactive patch machinery and incorporates prior feedback from Jeff King, showing good awareness of the subsystem's context. Reviewers will likely focus on these interaction details as the discussion progresses.
