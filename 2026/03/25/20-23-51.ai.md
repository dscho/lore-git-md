This is a refactoring patch that extracts revert message formatting logic from `sequencer.c` into a reusable function, as part of the ongoing `git replay --revert` feature series. The patch moves the complex message generation code (handling both regular reverts and revert-of-revert cases) from `do_pick_commit()` into a new `sequencer_format_revert_message()` function in `sequencer.h`.

The key technical changes include:
1. Extracting the message formatting logic that handles "Revert" vs "Reapply" prefixes and commit references
2. Modifying `refer_to_commit()` to take explicit `struct repository` and `bool` parameters instead of reading from `replay_opts`
3. Adding comprehensive documentation for the new public function
4. Maintaining all existing behavior while making the code more modular

This is the first of two patches in the final v6 series, which has already undergone extensive review from Phillip Wood, Patrick Steinhardt, and Junio Hamano. The changes are well-contained and focused on code organization rather than introducing new functionality. The patch follows established patterns from the sequencer code and includes proper documentation for the new API.

The refactoring enables code reuse for the upcoming `git replay --revert` feature while improving the overall code structure. The implementation appears clean separation of concerns and maintains all edge cases from the original code (like handling merge commits and repeated reverts). This foundational work will be used by the second patch in the series which implements the actual `--revert` functionality for `git replay`.
