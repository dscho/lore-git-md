This thread centers on Junio C Hamano's completed 12-patch series to make Git's test suite more robust by enabling "set -e" (immediate exit on error) earlier in test execution. The series has addressed most issues but revealed subtle shell compatibility differences, particularly around signal handling in dash versus bash. 

Jeff King (Peff) has been actively testing the changes in CI and confirms that Junio's proposed workaround for signal tests—using `&& echo 0 || echo $?` to capture exit status portably—is indeed the better approach, though it adds some complexity. Jeff also reports encountering additional cases needing adjustment under "set -e", including ACL-related tests and potential issues when no tests run (skip_all cases). These findings suggest more minor fixes may be needed beyond the current focus on signal tests.

The discussion reflects the ongoing tension between strict error checking and cross-shell compatibility. While the core series is finalized, these follow-up exchanges show how even well-tested infrastructure changes can surface edge cases. The maintainers are taking a pragmatic approach, prioritizing correctness while acknowledging that some shell-specific accommodations may be unavoidable. The git-daemon exit status checking remains deferred as lower priority.
