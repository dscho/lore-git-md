This is an RFC proposing a new feature for `git add -p` that would allow discarding hunks directly from the working tree. Currently, users can only stage or skip hunks during interactive patching, which can be inefficient when repeatedly skipping the same unwanted changes.

The patch introduces a new 'x' action that would reverse-apply the current hunk to discard it from the working tree. The author notes this was previously discussed on the mailing list and raises open questions about implementation details like whether discarding should be immediate or deferred, and how to handle edge cases with overlapping or edited hunks.

The changes touch the interactive patch machinery in `add-patch.c`, update the documentation, and add tests. As an RFC, the patch is clearly marked as seeking feedback rather than being ready for merging. The implementation looks like a reasonable starting point for discussion, though the edge cases mentioned will need careful consideration - particularly around how discarded changes interact with subsequent patch operations.
