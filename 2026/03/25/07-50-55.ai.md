Feature proposal for `git add -p` adding a 'discard hunk' action, building on prior RFC discussion.

Luiz Campos follows up their RFC with a concrete implementation of the 'x' (discard) action for `git add -p`. The patch modifies the interactive patch machinery in `add-patch.c` to support reverse-applying hunks to discard working tree changes, addressing the workflow pain point where users currently must manually remove unwanted changes after skipping hunks.

The implementation introduces a new `DISCARD_HUNK` state alongside the existing USE/SKIP states, with corresponding changes to the hunk display and application logic. Key technical aspects include:
- New `REASSEMBLE_DISCARD` mode for patch assembly
- `apply_discard_hunks()` function that runs `git apply -R` on selected hunks
- Updated prompt strings and help text throughout
- Comprehensive test coverage in t3701, including a new test case for the discard behavior

The patch appears well-structured, with clear separation between the discard logic and existing staging behavior. It handles edge case considerations from the RFC discussion, such as maintaining proper hunk merging behavior when discards are involved. The changes are focused on the interactive patch application subsystem without broader architectural impacts.

For future discussion, reviewers will likely examine:
- The safety of immediate working tree modification (vs deferred until apply)
- Interaction with other hunk operations (editing, splitting)
- Whether the discard operation should be available in all `add -p` modes or just the default one

The patch builds on Phillip Wood's work on the interactive patch machinery and references Jeff King's prior feedback, showing good awareness of the subsystem's context.
