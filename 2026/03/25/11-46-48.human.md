This is a GSoC proposal from Siddharth Shrimali to add "un-fetch" functionality for partial clones, allowing blobs to be moved back to a promised-but-not-present state to reclaim disk space. The proposal builds on earlier technical discussion with potential mentor Karthik Nayak and demonstrates a solid understanding of Git's promisor machinery.

The core idea addresses a current limitation where partial clones permanently fetch blobs with no built-in way to remove them later. Siddharth proposes a safe mechanism to identify and remove blobs that are still available from promisor remotes, handling both loose and packed objects while maintaining crash safety. Key technical aspects include using OBJECT_INFO_SKIP_FETCH_OBJECT for blob enumeration to avoid triggering lazy fetches, requiring Protocol v2 object-info for remote verification, and implementing write-before-delete ordering with .promisor sidecar files to ensure safety.

The proposal has evolved through discussion to position this as a git maintenance task rather than a backfill option, which better matches the use case. Siddharth shows good technical depth in addressing safety concerns around concurrent operations and crash recovery. The 12-week timeline is well-structured with clear milestones and buffer time for review cycles.

Siddharth has already contributed several relevant patches to Git, including work on t0410-partial-clone.sh and builtin/backfill.c, demonstrating familiarity with the codebase. The proposal is thorough and technically sound, with appropriate safety mechanisms and test coverage planned. This looks like a promising contribution that would fill a real gap in partial clone functionality.
