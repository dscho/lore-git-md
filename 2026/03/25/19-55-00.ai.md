This is a refactoring patch from Adrian Ratiu, part of his 12-patch series modernizing Git's hook configuration system (now merged to 'next'). The patch introduces a new `hook_config_cache_entry` struct to store per-hook data, replacing the direct use of string util pointers in the hook cache.

The change wraps the existing command string in a dedicated struct, which provides a foundation for adding more hook metadata in subsequent patches. The implementation carefully maintains memory ownership semantics while converting from the old string-util approach to the new struct-based storage. Key technical points include:
- New `hook_config_cache_entry` struct with `command` field
- Updated memory management in `hook_cache_clear()` to handle the struct
- Conversion of all util pointer accesses to use the new struct
- Preservation of existing behavior through careful string duplication

The patch touches only `hook.c` and follows the series' pattern of incremental, well-explained changes. It addresses no open issues but enables future metadata additions as noted in the commit message. This is a typical preparatory refactoring in Git's style - introducing structure before adding functionality, with clear ownership rules and no behavior changes.
