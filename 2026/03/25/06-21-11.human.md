This is part 8 of Junio Hamano's 11-patch series to make the Git test suite more robust by enabling "set -e" (exit immediately on errors) in test execution. The series aims to catch mistakes like misspelled test directives that currently fail silently.

This particular patch updates the CVS export test script (t9200-git-cvsexportcommit.sh) to work with the stricter error handling. The test previously checked for CVS availability by running `cvs` and examining `$?` directly, which would fail under "set -e". The patch rewrites this check using the now-standard pattern of explicitly storing the exit status (`status=0; cmd... || status=$?`) that works safely with "set -e" enabled.

The change is straightforward and follows the same conservative approach seen in earlier patches of the series. It maintains the test's original behavior while making it compatible with the stricter error checking. Since this is part of a well-structured series from the maintainer that's already passing the core test suite, it's likely to be merged without controversy.
