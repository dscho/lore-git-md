This is a feature patch series for the `git replay` plumbing command, introducing a refined version of the `--ref` option to control which reference gets updated during replay operations. The series comes from Toon Claes and builds on Siddharth Asthana's recent work adding `--revert` to `git replay`.

The cover letter explains the rationale for keeping the command's current structure rather than introducing subcommands, while still adding the useful `--ref` option that was requested in earlier discussion. The v2 series incorporates feedback from the previous iteration, dropping a test-only patch and focusing on core functionality.

Key changes in v2 include:
- Explicitly marking options as non-negatable (using PARSE_OPT_NONEG)
- Standardizing documentation to use the "stuck form" (`--option=value`) consistently
- Adding validation to ensure a single tip when using `--onto` with `--ref`
- Improved error handling for invalid refnames and multiple revision ranges

The implementation touches several files including the replay command implementation, its documentation, and test updates. The changes look well-considered, with test coverage expanded to verify the new validation rules. This appears to be a focused plumbing improvement that gives users more precise control over ref updates during replay operations while maintaining backward compatibility.
