This is a feature patch in the graph visualization subsystem, part of Pablo Sabater's v4 series adding `--graph-lane-limit` support. The email is Pablo's response to Johannes Sixt's (Hannes) review comments about the visual interpretation of lane truncation behavior.

Pablo clarifies that the implementation uses horizontal truncation (replacing excess lanes with '.' markers) rather than vertical truncation (interrupting and resuming lines) that Hannes expected. The extra columns Hannes observed in test output are these truncation markers, not actual lanes. Pablo explains this approach was chosen for accessibility and because vertical truncation would require significant graph rendering changes akin to gitk's implementation - a potential future enhancement but beyond this series' scope.

The response confirms Pablo will address all of Hannes' prior feedback in v5, including:
- Documenting that zero/negative values mean no limit
- Implementing Hannes' style suggestions (comment conciseness, whitespace, decrement operators)
- Fixing build system issues
- Restructuring the series
- Clarifying truncation semantics in documentation

Key technical details remain unchanged from v4:
- `graph_max_lanes` in `struct rev_info` with zero/negative meaning unlimited
- Truncation markers ('.') preserve commit markers ('*') while indicating omitted lanes
- Horizontal truncation maintains existing graph rendering behavior

The exchange reveals a potential usability concern: the current implementation's visual output differs from at least one reviewer's expectations. While the behavior is intentional and technically sound, Pablo acknowledges the need to better document the horizontal truncation approach to prevent similar misunderstandings. The series appears ready for final review after these documentation clarifications, with vertical truncation remaining as possible future work.
