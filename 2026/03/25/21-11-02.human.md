Refactoring patch improving xdiff record cleanup logic. This is the second patch in a 5-part series from Ezekiel Newren that focuses on making the xdiff subsystem's record cleanup code more readable, after feedback led to a narrower scope than the original proposal.

The patch clarifies how xdiff handles per-file limits when determining which records to keep, discard, or investigate during diff processing. Key changes include:
- Introducing explicit `mlim1` and `mlim2` variables for the per-file limits
- Moving the limit calculation outside the main loops for clarity
- Removing a redundant `!need_min` condition that is now handled by the limit initialization
- Using `SIZE_MAX` to clearly represent "infinity" for minimal diffs

The changes are purely internal refactoring with no behavior changes. The patch follows the series' narrowed focus on uncontroversial readability improvements after dropping broader structural changes from v1. The xdiff subsystem is core to Git's diff functionality, and these changes make the record cleanup logic more maintainable while preserving the performance characteristics.
