This is a feature patch adding a new `--graph-lane-limit` option to `git log --graph`, part of Pablo Sabater's GSoC project (now at v5). The patch addresses a long-standing TODO from 2008 about limiting graph width for better terminal display when repositories have many active branches.

The core change introduces a `graph_max_lanes` field in `struct rev_info` and modifies graph.c's rendering logic to cap visible lanes at the specified limit, showing excess lanes as '~' markers (chosen to avoid confusion with octopus merge notation). The implementation carefully preserves commit markers ('*') when they would appear on the first hidden lane, maintaining readability while compressing the output. The option follows Git's conventional handling of zero/negative values as "no limit".

The patch shows good attention to prior review feedback, with thorough documentation, test coverage, and visual examples in the cover letter. It contrasts the horizontal truncation approach with gitk's vertical method while staying focused on the core use case. The implementation touches graph.c's core rendering paths but appears well-contained, with clear conditionals for the new behavior.

This looks ready for final review - the technical concerns from earlier iterations have been addressed, and the feature solves a real usability pain point for repositories with wide commit graphs. The documentation and examples make the behavior easy to understand at a glance.
