This is a GSoC proposal from Siddharth Shrimali to add "un-fetch" functionality for partial clones, allowing blobs to be moved back to a promised-but-not-present state to reclaim disk space. The proposal builds on previous discussion with potential mentor Karthik Nayak and demonstrates a solid technical understanding of Git's promisor machinery.

The core problem is that partial clones currently have no way to remove locally-fetched blobs once they're no longer needed, forcing users to do a full re-clone to reclaim space. Siddharth proposes implementing this missing functionality with careful attention to safety, particularly around write-before-delete ordering to maintain repository consistency even during crashes or concurrent operations.

Key technical components include: blob enumeration with OBJECT_INFO_SKIP_FETCH_OBJECT to avoid triggering lazy fetches, Protocol v2 object-info for remote availability verification, and proper handling of both loose and packed objects. The implementation will be integrated as a git maintenance task rather than a backfill option, as this better matches the housekeeping nature of the operation.

The proposal shows good engagement with Git's internals, with Siddharth having already contributed relevant patches to the partial clone test infrastructure. The timeline is well-structured with clear milestones and buffer time for review iterations. Safety considerations are thorough, addressing crash recovery, concurrent operations, and various edge cases.

This appears to be a well-conceived proposal from a contributor who has demonstrated both technical capability and responsiveness to feedback in previous patches. The project would fill a genuine gap in Git's partial clone functionality while building on existing promisor-remote infrastructure.
