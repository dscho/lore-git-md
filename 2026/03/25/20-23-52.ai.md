This is the second patch in a v6 series adding `--revert` capability to `git replay`. The feature enables server-side reverts on bare repositories, primarily for GitLab's Gitaly service.

The patch implements core revert functionality by:
1. Treating reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent)
2. Processing commits newest-first to minimize conflicts
3. Generating standard revert commit messages with "Revert" prefix and original commit reference
4. Using current user as author (matching `git revert` behavior)

Key technical changes include:
- New `REPLAY_MODE_REVERT` operation mode alongside existing `REPLAY_MODE_PICK`
- Consolidated revert message generation via `sequencer_format_revert_message()`
- Swapped merge tree ordering in `pick_regular_commit()` for revert case
- Comprehensive test coverage including bare repo scenarios and revert-of-revert cases

The implementation follows established patterns from `sequencer.c` and the series has undergone extensive review from Phillip Wood, Patrick Steinhardt, and Junio Hamano across six iterations. All substantive feedback has been addressed, with v6 containing only minor documentation and compiler warning fixes.

This is a well-executed feature addition that fills a specific need for server-side operations while maintaining consistency with existing Git behavior. The thorough test coverage and careful attention to edge cases (like reverting reverts) suggest it's production-ready.
