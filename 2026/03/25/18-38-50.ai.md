Feature implementation for `git add -p` discard action, with responses to review feedback.

Luiz Campos responds to Phillip Wood's detailed code review of their `git add -p` discard ('x' action) implementation. The patch would allow users to discard hunks directly from the working tree during interactive staging, addressing workflow friction where users currently must manually remove unwanted changes after skipping hunks.

Key technical responses include:
- Agreeing to simplify hunk merge logic by passing USE_HUNK/DISCARD_HUNK directly rather than boolean flags
- Correcting delta application direction during reverse patching by temporarily inverting s->mode->reverse
- Removing redundant `git apply --check` call and just using `git apply -R` directly
- Fixing the unintentional nesting that made 'x' only available when edit ('e') was permitted
- Reworking tests to avoid a separate repository and adding new test cases for split hunks

Luiz acknowledges the philosophical concern about `git add` modifying the working tree (raised by both Phillip Wood and Jeff King) but notes the implementation would be similar whether this lives in `git add -p` or a separate command. He shows openness to reconsidering the design location while maintaining the core functionality.

The exchange demonstrates Git's review culture where even conceptually controversial patches receive thorough technical feedback. Phillip's review focused on implementation quality while maintaining his reservations about the fundamental design choice. Luiz's responses address all technical points while leaving the door open for further discussion about command boundaries.

For future discussion, the thread now needs to resolve:
- Whether working tree modification belongs in `git add` or should move to `git restore -p`
- How to handle the UX concern about immediate working tree modification safety
- Whether to make the discard action available in all `add -p` modes
- Additional test coverage for edge cases like split hunks and pathological context lines

The patch appears technically sound aside from the noted issues, showing good integration with Phillip Wood's existing interactive patch machinery. However, Junio Hamano's recent intervention questioning the fundamental design approach may redirect the effort toward a more comprehensive interactive command solution.
