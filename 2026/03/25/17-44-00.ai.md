This is the first patch in Pablo Sabater's v5 series introducing a `--graph-lane-limit` feature for `git log --graph` output. The patch implements core functionality to horizontally truncate wide commit graphs while preserving key commit markers, using '~' to indicate truncated lanes (changed from '.' in earlier versions to avoid confusion with octopus merge notation).

The implementation adds a `graph_max_lanes` field to `struct rev_info` (type `int`, where zero/negative means no limit) and modifies graph.c's rendering logic to cap displayed columns. When the limit is reached, excess lanes are replaced with '~' markers while maintaining '*' commit indicators for the first hidden lane. The patch handles edge cases like merges by only drawing post-merge lanes when needed for visible commits.

Key technical details include:
- New `graph_needs_truncation()` helper to check lane visibility
- Modified output routines for all graph states (pre-commit, post-merge, collapsing)
- Special handling for octopus merges and first hidden lane markers
- Logic to skip unnecessary post-merge lanes when both commit and first parent are hidden
- Option parsing that enforces `--graph` requirement
- Zero/negative value handling consistent with `--max-parents`
