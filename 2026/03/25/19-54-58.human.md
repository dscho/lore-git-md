This is a documentation patch from Adrian Ratiu, part of his larger series modernizing Git's hook configuration system. The patch standardizes terminology in the documentation and code comments to consistently use "friendly-name" rather than mixing it with the more generic "name" when referring to hook identifiers in configuration keys.

The changes are straightforward and mechanical, updating:
- The hook.adoc config documentation
- The git-hook.adoc man page
- A comment in hook.c
- A comment in hook.h

The patch follows Junio Hamano's suggestion to prefer the more descriptive "friendly-name" terminology. This is a small but useful consistency improvement that makes the documentation clearer, especially for users configuring hooks via Git's config system. As part of Adrian's well-reviewed series that's already been merged to 'next', this change represents final polish on the documentation side.
