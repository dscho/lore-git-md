This is a documentation follow-up to the recently approved `git replay` root commit handling patch. Christian Couder suggests adding a clarification to the man page about how commit ranges work with `git replay`, now that root commits are supported.

The core observation is that while the technical change enables `git replay` to handle root commits, the command's behavior around commit specification might be unintuitive. Previously, an incorrectly specified range would fail with an explicit error about root commits; now it would silently proceed, potentially replaying more history than intended. Christian proposes adding a note to the documentation explaining that `--onto main topic` replays from the root commit, while `main..topic` is likely what users want.

This is a thoughtful suggestion that addresses a real usability concern without requiring code changes. The proposed documentation addition is clear and directly relevant to the new capability. Since `git replay` is still marked experimental, this kind of incremental documentation improvement is particularly valuable as the command evolves toward wider use.
