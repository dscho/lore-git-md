This thread continues the multi-year effort to remove `the_repository` global variable from Git's codebase, focusing on the refs subsystem. Shreyansh Paliwal's three-patch series makes significant progress by converting ref lock timeouts and transaction functions to use explicit repository parameters, and updating the reftable backend to avoid global state. The changes touch core ref operations while maintaining existing behavior.

In the latest discussion, Tian Yuchen provided a thoughtful review of patch 1/3, noting that while the patch properly uses repository parameters for config lookups, the timeout value itself remains cached in a static variable. Yuchen suggests clarifying this in the commit message as an intentional intermediate step, with full multi-repo support to come later via the `repo-settings` mechanism. The exchange reflects the careful, incremental approach the project takes with these architectural changes - each patch moves things forward while acknowledging remaining work.

The series appears ready to merge with minor documentation tweaks, with follow-ups needed for repository validity handling, timeout caching integration, and other edge cases. This represents another solid step in René Scharfe's long-running effort to eliminate global state from Git's internals.
