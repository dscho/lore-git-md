Shreyansh Paliwal continues the multi-year effort to remove `the_repository` global variable from Git's refs subsystem, now focusing on three key areas in this patch series. The first patch converts ref lock timeouts to use explicit repository parameters, passing the repository context through from transaction callers and callback wrappers. This mechanical but important change follows established patterns in the ongoing cleanup effort.

The series has been narrowed from its original five patches after deferring more complex cases involving branch helpers, which will be addressed separately. Current work systematically tackles file ref lock timeouts, hash algorithm usage, and reftable backend conversions. The changes maintain existing behavior while making repository dependencies explicit - for example, while timeout values remain statically cached, the configuration lookup now properly uses repository context.

Open questions remain around edge cases like invalid repository paths and branch helper functions, with historical context from Jeff King and potential solutions from Tian Yuchen under consideration. The series builds on René Scharfe's long-running effort and coordinates with Patrick Steinhardt's upcoming work on bare repository detection. Reviewers have generally found the approach sound, with this first patch appearing straightforward and well-contained.
