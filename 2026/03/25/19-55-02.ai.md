This is a feature and refactoring patch from Adrian Ratiu that completes his work on making disabled hooks visible in `git hook list` output. The patch builds on his previous hook configuration improvements and has already been merged to 'next' after review feedback.

The key change makes disabled hooks appear in the listing with a "disabled" prefix, maintaining the tab-separated output style used for scope visibility. The implementation carefully handles edge cases - disabled hooks without commands now generate warnings rather than errors, and the `hook_exists()` function properly accounts for disabled hooks when checking availability. The patch includes comprehensive test coverage verifying the new output format, warning behavior, and interaction with the existing scope display.

Technically, the changes extend the `hook_config_cache_entry` struct with a `disabled` flag and modify the hook listing logic to preserve disabled entries while filtering them from actual execution. The implementation touches `hook.c`, `builtin/hook.c`, and the test suite, with careful attention to backward compatibility and consistent behavior across all hook types (configured vs traditional).

This represents the final piece of Adrian's multi-series effort to modernize Git's hook configuration system.
