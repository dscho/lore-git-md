This is part 9 of Junio C Hamano's test infrastructure patch series to make the test suite more robust by enabling "set -e" (exit immediately on errors) early in test execution. The patch focuses on the CVS server test scripts (t9400-t9402).

The change converts the CVS availability checks in these tests from the direct `cvs >/dev/null 2>&1; if test $? -ne 1` pattern to the status-capture pattern (`status=0; cmd || status=$?`) that works correctly under "set -e". This matches the approach used in earlier patches of the series for similar checks in other test scripts.

Junio notes that while this change gets the tests to the point where they properly skip when CVS is unavailable, there may still be other "set -e" issues in the CVS tests that need addressing. He doesn't personally run these tests, so the patch represents a conservative first step in making them compatible with the stricter error checking.

The patch follows the same pattern seen in previous parts of the series, applying a mechanical but careful transformation to maintain the original test behavior while making it work with the new "set -e" requirement. This continues the series' theme of incrementally hardening the test suite against silent failures.
