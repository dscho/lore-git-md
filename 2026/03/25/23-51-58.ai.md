This is the final patch in Taylor Blau's series addressing geometric repacking edge cases with MIDX bitmap generation. The patch focuses on handling packs above the geometric split point that weren't in the previous MIDX.

The core change modifies `builtin/repack.c` to mark such packs as excluded-open ('!') rather than excluded-closed ('^') when `repack.midxMustContainCruft` is false. This ensures pack-objects will traverse through these packs during the follow pass, rescuing any reachable objects that might otherwise be missed. The change fixes a subtle edge case where once-cruft objects could become unreachable if their containing pack was incorrectly treated as closed.

Key technical details:
- Adds logic to conditionally use '!' marker for non-MIDX packs above split
- Documents the assumption that non-MIDX packs may not be closed under reachability
- Updates the test case that previously expected failure to now succeed
- Maintains backward compatibility with existing MIDX behavior

The patch completes the series by implementing the final piece needed for correct geometric repacking behavior when excluding cruft packs from MIDX generation. It addresses the rare but important case where packs above the split point contain objects that become reachable through new references. Taylor has carefully considered the edge cases and tradeoffs, noting that while the solution isn't perfect for pre-existing MIDXs, the failure scenario is extremely unlikely in practice.
