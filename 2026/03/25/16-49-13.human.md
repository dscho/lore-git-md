This is a documentation discussion following up on the recently approved `git replay` root commit handling patch. Maintainer Junio C Hamano responds to Christian Couder's suggestion for improving the man page to clarify range specification behavior.

Junio acknowledges the need for better documentation, noting that even he found the current behavior unclear - a strong signal that users would benefit from clarification. He questions whether the command would truly fail silently in practice, suggesting it should still report conflicts when they occur. The discussion centers on how to best explain that `git replay --onto main topic` replays from the root commit rather than from `main`, and that `main..topic` is likely the intended syntax.

Junio proposes making the documentation more precise by explicitly stating what users achieve with each form: the current phrasing explains the difference between `topic` and `main..topic` but could better specify that the latter recreates changes made on `topic` since it diverged from `main`. This maintains the technical correctness of the command while improving its usability through clearer documentation.

The exchange shows the maintainer's careful attention to both technical accuracy and user experience, even for what is currently marked as an experimental plumbing command. The documentation improvement will proceed separately from the already-approved code changes.
