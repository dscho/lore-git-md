This is a documentation patch from Adrian Ratiu, part of his 12-patch v3 series modernizing Git's hook configuration system. The patch standardizes terminology in the hook documentation, replacing instances of "name" with "friendly-name" for consistency when referring to hook identifiers in configuration.

The changes touch documentation files (`hook.adoc` and `git-hook.adoc`) as well as comments in `hook.c` and `hook.h`. The modification is straightforward - it updates all references to maintain a single consistent term ("friendly-name") for describing how hooks are named in configuration, rather than mixing "name" and "friendly-name". This was suggested by Junio Hamano in earlier review feedback.

The patch is a small but meaningful improvement to documentation clarity, ensuring users see consistent term when reading about hook configuration. It doesn't change any functionality, just makes the documentation more coherent. As part of a larger series that's already been reviewed and merged to 'next', this represents final polish on the documentation side.
