This is the third version of a feature patch series adding remote group support to `git push`, mirroring the existing `git fetch` functionality. The series from Usman Akinyemi has progressed through multiple review rounds with Junio Hamano and appears functionally complete.

The core feature allows pushing to all remotes in a configured group (defined via `remotes.<name>` config) with a single command like `git push all-remotes`. The implementation now cleanly unifies single-remote and group handling after Junio suggested treating a single remote as a group of one. Key design questions around failure handling and behavior consistency have been resolved, establishing that group pushes should behave identically to sequential individual pushes.

Version 3 adds substantial documentation improvements and test coverage. The documentation now clearly explains failure handling - push continues after ref rejections but stops on fatal transport errors. Tests verify this behavior explicitly, along with proper commit propagation and error isolation. The implementation uses `size_t` for loop indices to match the remote group count type and avoid compiler warnings.

The changeset touches core remote-handling code in builtin/push.c and builtin/fetch.c, moving shared group resolution code to remote.c. A new test script t5566-push-group.sh provides comprehensive coverage of the feature. The series appears ready for merging with all maintainer feedback addressed and no outstanding technical issues. Parallel push support remains a potential future enhancement.
