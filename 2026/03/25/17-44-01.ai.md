This is the second patch in Pablo Sabater's v5 series introducing the `--graph-lane-limit` feature for `git log --graph`. The patch adds comprehensive documentation and test coverage for the new option.

The documentation update in `rev-list-options.adoc` clearly explains the option's behavior: it limits graph lanes to the specified number, showing excess lanes as '~' marks while preserving commit markers ('*'). It also notes that zero/negative values mean no limit, matching the implementation's behavior.

The test suite additions in `t4215-log-skewed-merges.sh` thoroughly exercise the feature across multiple scenarios:
- Basic lane limiting (2 lanes)
- Extreme truncation (1 lane) showing how it handles octopus merges
- Intermediate cases (3 and 6 lanes) demonstrating progressive lane display
- The full 7-lane case showing all parents when the limit isn't reached

The tests reuse the existing skewed merge test infrastructure while adding new verification points for the lane limiting behavior. The test cases are well-chosen to validate both the visual output and the underlying logic's edge cases. This completes the technical implementation from the first patch with proper documentation and verification, making the series ready for final review.
