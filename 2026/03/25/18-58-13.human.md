This is a feature implementation for `git add -p` that adds a 'discard hunk' action, responding to review feedback from Johannes Schindelin. The patch author Luiz Campos addresses two specific technical concerns about the implementation while keeping the core functionality intact.

The first issue involves improving code readability in the hunk merging logic by reverting from a `continue`-based flow back to the original `if-else` structure. The second optimization suggestion from Schindelin is to detect empty patches early in the discard application process, which would eliminate the need for a pre-scan loop in the main patch application function.

Luiz indicates they will incorporate both improvements in a v2 revision, while also acknowledging the ongoing discussion about whether this functionality might better belong in a different command (as suggested by Junio Hamano in earlier thread responses). The technical implementation appears sound and responsive to review feedback, though the ultimate home for this feature remains an open design question.

This email shows the patch moving forward with refinements while the broader architectural discussion about command boundaries continues in parallel - a common pattern in Git development where implementation and design discussions often proceed simultaneously.
