This is a refactoring patch that extracts revert message formatting logic from `sequencer.c` into a reusable function, as part of the ongoing `git replay --revert` feature series. The patch comes from Siddharth Asthana and represents the first of two patches in the v6 series.

The change moves the complex logic for formatting revert commit messages (handling both "Revert" and "Reapply" cases, plus commit references) from being inline in `do_pick_commit()` to a new standalone function `sequencer_format_revert_message()`. This makes the functionality available to the new `--revert` mode in `git replay` while maintaining consistency with how the sequencer handles reverts.

Key technical aspects include:
- The new function takes explicit parameters (repository, subject line, commit, parent, use_commit_reference flag) rather than relying on sequencer-specific state
- Updates `refer_to_commit()` to also take repository parameter instead of using `the_repository`
- Preserves all existing behavior including handling of merge parents and the "Reapply" case for revert-of-revert commits
- Adds thorough documentation in the header file

The patch has already undergone extensive review from Phillip Wood, Patrick Steinhardt, and Junio Hamano across six iterations, with all substantive feedback addressed. This appears to be a well-executed refactoring that follows established patterns while enabling the new `--revert` functionality in a clean way.
