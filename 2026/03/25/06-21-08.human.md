This is part 5 of Junio C Hamano's 11-patch series to make Git's test suite more robust by enabling "set -e" (exit immediately on errors) during test execution. The current patch fixes a conditional test in t7450-bad-git-dotfiles.sh that would fail under the stricter error checking.

The test checks whether Git properly handles symlinked dotfiles in repositories. The specific fix changes a test condition from `test -n "$refuse_index" &&` to `test -z "$refuse_index" ||` to ensure it works correctly with "set -e" enabled. This is a straightforward mechanical change that follows the same pattern seen in earlier patches of the series - rewriting conditionals to avoid false failures under the new stricter mode.

The patch is small and focused, exactly what we'd expect for this type of test suite modernization. As with the rest of the series, it demonstrates careful attention to maintaining the original test's intent while making it compatible with the new error handling regime. Since this comes from the Git maintainer himself and follows the established pattern from earlier patches, it's likely to be uncontroversial.
