This is the 9th patch in an 11-part series from Git maintainer Junio C Hamano to make the test suite more robust by enabling "set -e" (exit immediately on errors) during test execution. The patch focuses on the CVS server test scripts (t9400-t9402).

The change standardizes how these tests check for CVS availability by replacing direct `cvs` command checks with a "status-capture" pattern (`status=0; cmd || status=$?`) that works correctly under "set -e". This matches the approach used in earlier patches of the series for similar external tool checks (like in the git-svn tests).

Junio notes that while this gets the tests to the point where they properly skip when CVS isn't available, there may still be other "set -e" issues in the CVS tests that need addressing. The maintainer explicitly states he doesn't run CVS tests himself, so this is a conservative first step that makes the basic infrastructure work while leaving room for follow-up fixes if needed.

The patch follows the established pattern seen throughout this series - making minimal, mechanical changes to preserve existing behavior while enabling stricter error checking. It's part of the broader effort to catch test framework typos and silent failures earlier.
