This is part 2 of a 5-patch series continuing the `the_repository` removal effort, specifically targeting refs subsystem functions. The patch makes `get_files_ref_lock_timeout_ms()` repository-aware by adding a `struct repository` parameter and updating all callers to pass the appropriate repository context.

The change is mechanical but touches several call sites:
- Direct callers in `files-backend.c` now pass the repository from the transaction's ref_store
- A callback case (`create_reflock`) requires introducing a small wrapper struct to pass both the lock_file and repository through callback data

The patch follows the established pattern for these conversions and appears to be a straightforward continuation of the series' goal. The changes are limited to plumbing the repository parameter through without altering behavior, which is exactly what we want for this type of refactoring. This is uncontroversial technical debt cleanup that aligns with the project's ongoing architectural improvements.
