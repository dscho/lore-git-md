This is the third patch in a feature series enhancing the `git replay` plumbing command with a new `--ref` option for precise reference updates. The patch comes from Toon Claes and builds on previous work adding `--revert` functionality.

The change allows users to specify exactly which reference should be updated after a replay operation, rather than having Git infer it from the revision range or other options. When using `--ref`, the command will update only the specified reference, ignoring the usual behavior of updating refs from the revision range or the branches given to `--advance`/`--revert`.

Key aspects of this implementation:
- Requires a single tip when used with `--onto` to avoid ambiguity
- Validates refname format (must be fully qualified like `refs/heads/name`)
- Explicitly marked as incompatible with `--contained`
- Includes comprehensive tests covering various usage scenarios

The patch touches the command's documentation, option parsing, core replay logic, and test suite. It follows Git conventions for option handling and maintains backward compatibility when `--ref` isn't used. The test coverage is thorough, verifying both happy paths and error cases.

This appears to be a well-considered plumbing enhancement that gives users more precise control over reference updates during replay operations. The implementation looks clean and the documentation is clear about the new behavior.
