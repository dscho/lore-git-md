This is a platform compatibility patch series update addressing OpenSSL API deprecations in Git's IMAP send functionality. The current email is a response in an ongoing discussion about security implications in patch 3/4.

Beat Bolli acknowledges Oswald Buddenhagen's security concern about removing string length checks in the IMAP SSL certificate validation code. The checks were originally thought to be redundant internal consistency validations after switching to OpenSSL's newer API, but Buddenhagen correctly pointed out they serve the critical security purpose of detecting embedded nulls that could bypass hostname matching. Junio C Hamano had also questioned the removal, implicitly supporting Buddenhagen's position.

The author now understands the security implications and plans to send a v2 that keeps these checks, reversing the original patch 3 change. This leaves patches 1 and 2 (which update OpenSSL API usage for subject alternative names and common names) uncontroversial, while patch 4's hostname matching refactoring will need to accommodate the retained security validations. The thread demonstrates how security considerations can override what initially appeared to be straightforward API modernization.
