This is a discussion about the final design of the `commitListFormat` config option for `git format-patch`'s cover letter feature, part of a larger series that's now in its seventh iteration.

The thread focuses on how empty or unset config values should behave, with Junio C Hamano and Phillip Wood debating the semantics. Junio notes that `git -c config.key` (without a value) typically sets a boolean true, while Phillip points out that for list-valued configs, empty values often mean "clear the list". The discussion highlights the tension between intuitive boolean behavior and consistency with Git's existing config patterns for multi-valued options.

This is the last open question for a feature that otherwise has complete implementation and documentation. The series introduces configurable cover letter formatting through both CLI (`--cover-letter-format`) and config (`format.commitListFormat`) options, with new placeholders like `%(count)` and `%(total)`. All technical aspects are settled - this final debate is purely about config interface design philosophy.

Junio favors a boolean approach (unset=shortlog, set=default format) as more natural for a "use modern format?" question, while Phillip suggests named formats ("shortlog"/"numbered") might provide clearer semantics. The author had originally proposed string-based config but is reconsidering in light of this discussion. With all other aspects of the series ready, this config design question appears to be the last hurdle before merging.
