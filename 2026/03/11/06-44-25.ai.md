This is part 5/6 of Patrick Steinhardt's series completing the ODB abstraction for object counting functionality. The patch introduces generic object counting interfaces through new `odb_source_count_objects()` and `odb_count_objects()` APIs, replacing the old `repo_approximate_object_count()`.

The key point of discussion is whether to include loose object counts even in approximate mode. Junio noted that since the new loose counting implementation already scans one full shard directory (rather than stopping early), adding it to the count would provide better accuracy with minimal performance cost. Patrick acknowledges the tradeoff but chose to maintain existing semantics where approximate counts ignore loose objects, though he sees no strong technical reason against including them.

The implementation handles both packed and loose object counting through flags (ODB_COUNT_OBJECTS_APPROXIMATE), with packed objects always counted and loose objects only counted in exact mode. The changes affect object-file.c, odb/source-files.c, and related headers while preserving caching behavior. This patch is the penultimate step before the final API switch in patch 6/6.

Junio has indicated the technical soundness of the approach, leaving the loose-counting tradeoff as an open but non-blocking consideration. The series remains on track for integration, completing this phase of the ODB abstraction effort to enable future pluggable backends.
