This is a discussion about the final polish of a feature patch series introducing configurable cover letter formatting for `git format-patch`. The thread focuses on the behavior of the new `format.commitListFormat` config option.

Phillip Wood responds to Junio C Hamano's suggestion about how to handle boolean vs string values for the config option. Junio had proposed using boolean values (true/false) to toggle between the new default format and the traditional shortlog format, while the patch author Mirko Faina prefers string-based config with named formats. Phillip acknowledges Junio's point about boolean case behavior being more intuitive for enabling/disabling features, and agrees the boolean approach seems reasonable.

The discussion highlights a key design decision about how to represent the configuration - whether to use Git's standard boolean pattern (where an empty value means "true") or maintain string values that explicitly name the format variant. This is one of the last remaining open questions before the series can be merged, alongside the ongoing discussion about requiring a "log:" prefix for custom formats.

The exchange is constructive, with Phillip providing context about common config patterns while acknowledging the merits of Junio's suggestion. This represents the final refinement phase of a well-developed feature that has gone through seven iterations with extensive review from multiple contributors including Junio, Jeff King, and Phillip Wood.
