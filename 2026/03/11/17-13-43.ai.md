This is a discussion about the configuration interface for the cover letter formatting feature in `git format-patch`, part of the ongoing RFC-to-feature patch series (now at v7). The thread focuses on how to represent the format selection in config, with three approaches under consideration:

1. Junio C Hamano's boolean-based approach where `false` falls back to shortlog, `true` uses the default modern format, and strings allow custom formats
2. Phillip Wood's suggestion of named formats ("shortlog" and "numbered") as clearer alternatives to boolean values
3. The original string-based approach with custom formats

Junio defends the boolean approach as natural for the "use modern format?" question, comparing it to other Git options that accept boolean-or-custom values. Phillip Wood remains open to either approach if the names are clear, while expressing some preference against mixing types. The discussion remains technical and constructive, with Junio providing rationale for why boolean values can be sensible in this context despite being less descriptive than named formats.

This email doesn't introduce new technical changes but clarifies the design philosophy behind one of the proposed solutions. The thread appears to be in its final stages, with the implementation otherwise complete and only this configuration interface question remaining open before merging.
