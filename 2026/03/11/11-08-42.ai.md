Hook subsystem refactoring patch with build fix needed.

This is part of Adrian Ratiu's ongoing hook configuration series, specifically addressing a utility function relocation that introduced a build failure. The patch moves `unsorted_string_list_remove()` from hook.c to string-list.[ch] where it more logically belongs, adding documentation in the process. However, the function signature change (adding a `free_util` parameter) wasn't properly propagated to three call sites, causing compilation errors.

SZEDER Gábor identified the issue and provided the build failure output showing the missing parameter at hook.c lines 151, 163, and 180. Adrian acknowledges the oversight - the call site updates were meant to be in a later commit - and confirms the fix will be included in v2 along with proper documentation of the parameter addition.

The change is part of broader hook infrastructure cleanup that includes standardizing APIs and preparing for future metadata storage capabilities. While mechanically straightforward, this particular patch illustrates the careful coordination needed when moving utility functions between files while maintaining compatibility with existing callers. The series remains on track with all feedback being constructively incorporated.
