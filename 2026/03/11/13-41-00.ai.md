This is a platform compatibility patch in an ongoing thread about updating Git's IMAP send functionality for OpenSSL 4.0. The thread has established that patches 1-2 are essential fixes for OpenSSL API changes, while patches 3-4 are cleanups enabled by those changes.

The current email is a reply to patch 3, which proposed removing two string length checks in `imap-send.c` that verify ASN1_STRING consistency. Oswald Buddenhagen pushes back strongly against removing these checks, arguing they serve an important security purpose - detecting embedded nulls that could bypass hostname matching. This contradicts Beat Bolli's original rationale that the checks became unnecessary after switching to proper OpenSSL APIs.

The disagreement centers on whether these are redundant internal consistency checks (Bolli's view) or necessary security validations (Buddenhagen's view). The security concern about embedded nulls potentially creating matching vulnerabilities suggests this check should likely remain, making patch 3's removal questionable. This exchange highlights that what appeared to be a straightforward cleanup in the original series may actually touch security-sensitive validation logic.
