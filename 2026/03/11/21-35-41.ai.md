This is a test infrastructure patch from the maintainer Junio C Hamano that relaxes the portability restrictions on `sed` usage in Git's test suite. The change allows the `-E` flag (for extended regular expressions) which has been part of POSIX since Issue 8 (2018) and has been in use in the test suite since 2022 without reported issues.

The patch makes two changes: first it updates the `check-non-portable-shell.pl` linter to permit `-E` alongside the previously allowed `-n`, `-e`, and `-f` options. Second, it fixes a test in `t6030-bisect-porcelain.sh` that had been using `-E` and `-n` combined as `-En` (which bypassed the linter) to use them as separate flags `-E -n` for clarity and to ensure the linter would catch future uses.

The commit message provides historical context, noting that while the original 2019 restriction was based on POSIX Issue 7, the standard has since evolved. The change is well-motivated by both standards compliance and practical experience, as the `-E` flag has been in use without problems for years. This is a straightforward, uncontroversial update to the test infrastructure that brings the linter in line with current practice.
