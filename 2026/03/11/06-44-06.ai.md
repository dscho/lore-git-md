Bugfix for `merge-file --object-id` in worktrees. This patch addresses a BUG() that occurs when using `git merge-file --object-id` in a linked worktree, caused by a redundant `setup_git_directory()` call. The issue stems from commit e1068f0ad4 adding the `--object-id` option with an unnecessary setup call, which became fatal after 2816b748e5 made duplicate repository initialization trigger a BUG().

The fix guards the setup call behind a repository pointer check, ensuring proper behavior both inside and outside repositories. The patch includes a new test case verifying correct operation in linked worktrees. Mathias Rav has incorporated feedback from Karthik Nayak, Patrick Steinhardt, Kristoffer Haugsbakk, and Junio Hamano, including test modernization (using `git -C` instead of subshells) and commit message improvements. The change is minimal and focused, touching only builtin/merge-file.c and adding one test case. While the immediate issue is resolved, Junio has noted a broader architectural desire for `setup_git_directory()` to be idempotent, which case this workaround wouldn't be needed.
