This is a bugfix targeting zombie processes that can occur when Git runs as PID 1 in containers during network operation failures. The patch addresses a specific edge case where transport errors cause Git to exit(128) before normal cleanup paths can reap child processes like git-remote-https or ssh.

Andrew Au's v2 submission follows up on earlier discussion about contributor identity (now consistently using cshung@gmail.com) and maintains the same technical approach. The changes add symmetric atexit handlers in both connect.c and transport-helper.c to ensure child processes are reaped even during abnormal exits, while preserving existing cleanup behavior for normal paths. The handlers are cleared during regular cleanup to avoid double-waiting.
