This is the third and final patch in a platform compatibility series updating Git's IMAP send functionality to use modern OpenSSL APIs while addressing security concerns raised in earlier versions.

The patch consolidates common certificate validation code into a single `host_matches()` function, moving the ASN1_STRING access and embedded NUL byte checks that were previously duplicated in two places. The NUL check is rewritten to use `memchr()` for clarity, with an added comment explaining its security purpose - preventing embedded nulls from bypassing hostname validation.

This change follows through on the thread's security discussion where Oswald Buddenhagen and Junio C Hamano emphasized maintaining these checks while modernizing the OpenSSL API usage. The implementation shows careful attention to both the technical modernization (using proper OpenSSL accessors) and the security requirements (preserving validation of string lengths).

The patch appears well-constructed, completing the series' goal of updating deprecated OpenSSL calls while keeping the security checks that prevent certificate validation bypass. With no outstanding concerns raised in the thread, this looks ready for merging as part of the overall OpenSSL 4.0 compatibility effort.
