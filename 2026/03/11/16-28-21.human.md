This is a refactoring patch discussion in the ongoing effort to clean up strbuf usage in Git's codebase. Junio Hamano is reviewing Deveshi Dwivedi's v2 patch that rewrites `parse_combine_filter()` to avoid using `strbuf_split_str()`.

The key changes in this patch replace strbuf operations with direct string manipulation using `strchrnul()`, which simplifies the parsing of combined filter specifications (like "combine:foo+bar"). Junio notes that while the implementation is sound, the error handling for empty filter specs has some inconsistencies - the new version rejects empty strings in the middle (e.g., "foo++bar") while the old version rejected them at the end (e.g., "foo+").

Junio suggests two potential improvements: (1) considering whether to maintain backward compatibility with the old behavior regarding empty strings, and (2) possibly using a reusable strbuf instead of repeated allocations for temporary strings, which could be more efficient. The discussion shows careful attention to edge cases while acknowledging the overall approach is a clear improvement over the original strbuf-heavy implementation.
