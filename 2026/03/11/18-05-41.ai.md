Performance investigation follow-up on slow `git fetch` over SMB/CIFS. R. Diez reports that running `git gc` on the server reduced no-op fetch times from 25 seconds to 4 seconds, confirming that unpacked references were the primary bottleneck. The improvement comes from replacing many small reference files with a single `packed-refs` file (64KB in this case), which significantly cuts filesystem metadata operations over the high-latency network link.

This validates earlier suggestions about reference packing while demonstrating that even moderate latency (40ms) can dominate bandwidth constraints (1Mbps) when dealing with many small files. The results align with brian m. carlson's protocol analysis but show that basic repository maintenance (`git gc`) can provide substantial improvements without requiring reftable adoption or protocol changes. The thread now has a clear resolution path for this specific performance issue, though the broader discussion about Git's network assumptions remains relevant for future design considerations.
