This is a discussion about the portability of `sed -E` in Git's test suite, sparked by a proposed optimization in the help command's test script. The thread has evolved from a patch series standardizing string list sorting behavior to a more general consideration of test portability.

Junio C Hamano notes that while the test suite's `check-non-portable-shell.pl` script currently rejects `sed -E` (added in 2019 due to portability concerns), this restriction may now be outdated. He points out that POSIX Issue 8 documents `-E` for extended regular expressions, and Git has already been using it in some tests since 2022 (though sometimes hidden by combining options). Junio suggests either:
1. Reverting to the pre-2019 check that only prohibited `sed -i`, or
2. Updating the portability checker to allow `-E`, though he questions whether this is worth the effort given how easy it is to bypass the current pattern matching.

The discussion references Torsten Bögershausen's original 2019 change that added the restriction, which was based on concerns about non-standard extensions across different `sed` implementations. Junio seems inclined to relax this restriction now that `-E` is more widely supported, but is soliciting opinions before making a change.

This touches on Git's ongoing balance between portability and modernization in its test infrastructure. The immediate context is Amisha Chhajed's work on optimizing test pipelines for the help command's config listing functionality, but the implications could affect many other tests that might benefit from using extended regexes.
