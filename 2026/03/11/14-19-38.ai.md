Bugfix for promisor-remote subsystem addressing recursive lazy-fetch issue that can cause runaway resource consumption, now at v3.

This patch fixes a critical issue in the promisor-remote subsystem where a child fetch process could recursively trigger additional lazy fetches when processing REF_DELTA objects with missing bases. The core fix is straightforward - propagating `GIT_NO_LAZY_FETCH=1` into the child fetch's environment to prevent recursion. The v3 iteration strengthens the test coverage significantly by demonstrating the actual failure mode with a crafted thin pack that simulates GitHub's production server behavior, rather than just testing environment variable propagation.

The patch shows good technical judgment in its approach - hardening the client against server misbehavior while acknowledging the server protocol concerns. The test case is particularly thorough, covering: (1) the recursive fetch behavior with thin packs containing REF_DELTA objects referencing missing bases, (2) reproduction using GitHub server behavior, and (3) verification that the environment variable prevents the recursion. The commit message clearly explains both the client-side fix and the server protocol considerations.

Discussion has clarified this is both a useful client hardening measure and may indicate a separate server-side issue to be addressed later. The patch appears ready for merging with consensus forming around the technical approach, though there may be follow-up discussion about refining the commit message to more clearly separate the client fix from potential server protocol concerns.
