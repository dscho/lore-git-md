This is a platform compatibility patch series updating Git's IMAP send functionality to work with OpenSSL 4.0. Beat Bolli sends version 2 of his three-patch series that modernizes OpenSSL API usage in `imap-send.c`, addressing deprecation warnings that appeared with OpenSSL 4.0.0-alpha1.

The key change from v1 is that Bolli has kept the security checks for embedded null characters in certificate strings, responding to concerns raised by Oswald Buddenhagen and Junio C Hamano in the thread. The checks were initially removed in v1 but are now recognized as necessary defense against potential hostname matching bypasses.

The series remains focused on replacing direct OpenSSL struct field access with proper API calls (`GENERAL_NAME_get0_value`, `ASN1_STRING_get0_data` etc.) that have been available since OpenSSL 1.1.0 (2019). The patches handle subject alternative names (patch 1), common names (patch 2), and refactor hostname matching logic (patch 3) while maintaining the security checks.

This version appears to have addressed the main technical concern from the thread while still achieving the OpenSSL 4.0 compatibility goal. The changes are well-contained to `imap-send.c` and the commit messages clearly explain the OpenSSL API transitions. With the security validation now preserved, this looks like a solid update that should be ready for merging after any final review.
