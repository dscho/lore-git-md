This is a technical discussion about precompiled header (PCH) implementation details in Git's build system, specifically regarding how headers are included during compilation. The email comes from SZEDER Gábor in response to Phillip Wood's earlier analysis of Patrick Steinhardt's PCH patch series.

The key point being examined is whether GCC's precompiled header mechanism can work with nested includes (where one header includes another). SZEDER provides evidence from both documentation and strace output showing GCC does not automatically use PCHs for indirectly included headers - it only checks for PCH versions of headers explicitly included in the source file. This confirms Phillip Wood's observation that Meson's use of `-include` is necessary to force PCH usage.

The discussion is part of a larger 8-patch series introducing PCH support to speed up Git builds. This particular exchange focuses on ensuring the implementation correctly handles Git's header inclusion patterns, where `git-compat-util.h` is often included indirectly through other headers. The technical depth suggests this is a careful review by experienced contributors to get the PCH implementation right.
