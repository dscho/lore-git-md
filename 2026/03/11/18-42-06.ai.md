This is a technical discussion about the zombie process cleanup patch, focusing on potential deadlock risks in the proposed atexit handler implementation. Jeff King (Peff) responds to Andrew Au's v2 patch with concerns about the cleanup approach.

Peff notes that simply waiting for the child process to exit in the atexit handler could potentially deadlock if the child is waiting for the parent (Git) to perform some action like closing a pipe. He suggests using the existing `clean_on_exit` flag in the `child_process` struct which would kill the child before waiting, avoiding this risk.

The response also raises a broader design question about whether child process cleanup should be the default behavior in Git's run-command infrastructure, noting that most subprocesses shouldn't outlive their parent. Peff references commit afe19ff7b5 which introduced optional child cleanup, but suggests the default may need revisiting since the pager case mentioned in that commit no longer applies.

While supportive of the patch's goal, Peff recommends modifying the implementation to use the existing kill-then-wait mechanism rather than direct waiting. The discussion remains focused on technical merits without challenging the patch's core premise, which has already been established as addressing a real containerization pain point.
