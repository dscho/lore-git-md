Platform compatibility patch resolving security concerns in OpenSSL API updates.

This is a follow-up in the thread about updating Git's IMAP send functionality to use modern OpenSSL APIs. Beat Bolli acknowledges Junio C Hamano's and Oswald Buddenhagen's security concerns about removing string length checks when validating SSL certificates. The original patch 3/4 had removed these checks, thinking they were redundant with the new API usage, but it turns out they serve the important security purpose of detecting embedded nulls that could bypass hostname matching.

Beat confirms he'll send a v2 of the patch series that keeps these security checks while still updating to the modern OpenSSL APIs. This resolves the key technical disagreement in the thread - the security validations will remain in place. The first two patches in the series (updating subject alternative name and common name access patterns) remain uncontroversial, while patch 4's refactoring will need to accommodate the retained security checks. The discussion demonstrates how security considerations can override what initially appears to be straightforward API modernization.
