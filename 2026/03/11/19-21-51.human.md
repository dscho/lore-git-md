Refactoring patch for `git help` config output handling.

This patch cleans up how `git help -c` constructs and outputs configuration keys. The main changes are:

1. Moves the sorting of configuration keys to *after* processing, ensuring the final output is properly sorted regardless of input order. Previously, the code relied on the input being pre-sorted, which wasn't guaranteed.

2. Extracts key processing logic into separate functions (`set_config_vars` and `set_config_sections`) to handle different output formats (full variables, variable names, or section names).

3. Optimizes string buffer usage by moving `strbuf` initialization/release outside loops where possible.

4. Updates the test scripts to use `sed` more consistently instead of chaining `grep` and `sed`, and dedents some test commands for better readability.

The changes are mechanical refactoring with no intended behavior change - the output should remain identical, just produced in a more robust way. The patch comes from a relatively new contributor (Amisha Chhajed) with a suggested-by from Siddharth Shrimali. The changes look straightforward and focused on code quality rather than introducing new functionality.
