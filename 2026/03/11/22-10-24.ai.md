This is a platform compatibility patch series updating Git's IMAP send functionality to use modern OpenSSL APIs, addressing deprecation warnings in OpenSSL 4.0. The three-patch series follows up on security concerns raised in v1 discussion, where Oswald Buddenhagen identified that removing string length checks could allow embedded nulls to bypass hostname matching.

The updated series now keeps those security checks while still modernizing the OpenSSL API usage in `imap-send.c`. Patch 1 updates subject alternative name access to use `GENERAL_NAME_get0_value` and related functions rather than direct ASN1_STRING field access. Patch 2 similarly updates common name access patterns. Patch 3 refactors hostname matching logic while preserving the security checks that detect embedded nulls.

The changes demonstrate how security considerations shaped the API modernization - what initially appeared as straightforward deprecation fixes needed to maintain validation of certificate contents. All new APIs used have been available since OpenSSL 1.1.0 (2019), so compatibility remains broad while fixing the OpenSSL 4.0 warnings. The thread shows consensus forming around keeping the security checks while still achieving the API updates.
