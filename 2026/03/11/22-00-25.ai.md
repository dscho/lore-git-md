Platform compatibility patch resolving security concerns in OpenSSL API updates.

This is Beat Bolli's response in the thread about updating Git's IMAP send functionality to use modern OpenSSL APIs. The discussion had revealed that patch 3/4's removal of string length checks in `imap-send.c` was potentially unsafe, as those checks served to detect embedded nulls that could bypass hostname matching. Junio C Hamano pointed out that the security-sensitive hostname matching still operates on raw strings at this stage, making the checks necessary despite the API modernization.

Beat Bolli acknowledges the oversight and confirms he will send a v2 of the patch series that retains these security validations. This resolves the key technical disagreement in the thread - the defensive checks will remain while still achieving the OpenSSL 4.0 compatibility goals. The other patches in the series (1, 2, and 4) remain uncontroversial, with patch 4's refactoring now needing to accommodate the retained validation logic. The exchange demonstrates how security considerations can override what initially appeared to be straightforward API modernization work.
