This is the second patch in a refactoring series addressing strbuf overuse in Git's codebase. The patch focuses on `parse_combine_filter()` in the list-objects-filter-options code, eliminating unnecessary strbuf allocations when processing combine: filter specs.

The key change replaces `strbuf_split_str()` with direct string walking using `strchrnul()`, which avoids allocating an array of strbufs just to split on '+' characters. Each sub-filter spec is now copied into a single reusable strbuf for processing. The patch also makes several related improvements:
- Skips empty sub-specs consistently (including trailing '+')
- Updates helper functions to take `const char*` instead of `strbuf*`
- Removes a test case that incorrectly expected an error on trailing '+'

This is the third iteration of the patch, having incorporated feedback from both Jeff King and Junio Hamano. The changes are clean and focused, with no outstanding concerns from reviewers. The patch demonstrates careful attention to edge cases and maintains the same behavior while simplifying the implementation.
