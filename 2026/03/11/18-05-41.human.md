This is a performance follow-up in the ongoing investigation of slow `git fetch` operations over high-latency network shares. R. Diez reports that running `git gc` on the server side dramatically reduced fetch times from 25 seconds to just 4 seconds for no-op fetches. The improvement comes from consolidating many small reference files into a single `packed-refs` file, which significantly reduces the filesystem operations needed during reference resolution.

The email confirms that latency (rather than raw bandwidth) is the primary bottleneck when dealing with many small reference files over a network mount. With the packed format, the 64 kB `packed-refs` file transfers quickly even on the 1 Mbps connection, demonstrating how reference packing can mitigate network latency issues. This practical result aligns with earlier technical analysis in the thread about Git's sequential reference processing being particularly sensitive to filesystem latency.

The thread has now identified two concrete solutions for this class of performance problem: adopting the reftable backend (as previously discussed) and ensuring regular reference packing via `git gc`. The dramatic improvement shown here provides empirical validation of the protocol analysis from earlier in the thread.
