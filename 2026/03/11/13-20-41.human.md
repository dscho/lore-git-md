Refactoring patch improving combine filter parsing efficiency. This is the second patch in a v2 series addressing strbuf overuse cases identified by Junio Hamano, with feedback incorporated from Jeff King.

The patch rewrites `parse_combine_filter()` to replace its use of `strbuf_split_str()` with direct string manipulation via `strchrnul()`. The original approach allocated an array of strbufs and then mutated them to strip trailing '+' delimiters - an unnecessary overhead since the code only needs to read the string content. The new version walks the input string directly, copying each sub-filter spec into a temporary buffer while naturally excluding the delimiter.

Key changes from v1 include using `strchrnul()` for cleaner string walking and removing an incorrect test case that expected an error on trailing '+'. The patch also updates helper functions to take `const char*` instead of `strbuf*` since they only read the string content. The implementation is careful and well-explained, with clear rationale for each change.

This is a focused, mechanical improvement that makes the filter parsing both safer (avoiding potential strbuf mutation issues) and more efficient (eliminating unnecessary allocations). The series appears ready for merging with no outstanding review comments.
