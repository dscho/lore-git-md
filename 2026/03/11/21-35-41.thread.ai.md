Summary of test infrastructure patch from Junio C Hamano updating sed usage in Git's test suite, with follow-up from Ramsay Jones and Patrick Steinhardt. The patch modernizes the test suite by permitting the `-E` flag (extended regular expressions) in `check-non-portable-shell.pl`, aligning with POSIX Issue 8 (2018) standards. Original changes updated the linter to allow `-E` alongside existing permitted flags (`-n`, `-e`, `-f`) and fixed a test in `t6030-bisect-porcelain.sh` that used `-En` to use separate `-E -n` flags.

Ramsay Jones identified and Junio Hamano acknowledged one remaining inconsistency: while the linter's pattern was updated to permit `-E`, its error message still only listed `-n`, `-e`, and `-f` as allowed options. Junio's v2 revision addresses this by updating the error message to include `-E` and fixes a typo in the commit message ("unwated" -> "unwanted").

Patrick Steinhardt's review confirms the approach is reasonable, considering but ultimately rejecting the idea of hardening the linter's regex to detect squished options (like `-En`) as not worth implementing a full command-line parser for this purpose. He agrees with Junio's approach of both allowing `-E` and discouraging option-squishing by example. Changes remain minimal, touching only the linter script (`check-non-portable-shell.pl`) and one test file (`t6030-bisect-porcelain.sh`).

The thread demonstrates the project's attention to detail in test infrastructure, where even small documentation mismatches in error messages are addressed. All participants agree the changes align with Git's standards-compliance goals and evolving POSIX standards, with Patrick's review suggesting this uncontroversial change is ready for merging.
