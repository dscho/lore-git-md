This is a platform compatibility patch in an ongoing thread about updating Git's IMAP send functionality for OpenSSL 4.0. The third patch in the series had removed some string validation checks, arguing they were redundant with the new OpenSSL API usage. Oswald Buddenhagen pushes back strongly, pointing out these checks actually serve an important security purpose - detecting embedded nulls that could bypass hostname matching. This reveals a misunderstanding in the original patch's rationale, suggesting the validation should stay despite the API changes. The exchange highlights how security-sensitive this IMAP certificate verification code is, where seemingly redundant checks may have important protective roles. This patch will likely need revision to maintain both OpenSSL 4.0 compatibility and proper security validation.
