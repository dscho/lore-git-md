This is part 5/6 of Patrick Steinhardt's series to complete the ODB (object database) abstraction for object counting functionality. The patch introduces generic object counting interfaces through new `odb_source_count_objects()` and `odb_count_objects()` APIs, replacing the old `repo_approximate_object_count()`.

The key point of discussion with Junio centers on whether to include loose object counts even in approximate mode. While the current implementation follows historical behavior by excluding loose objects when approximating, both agree the performance impact would be negligible if included. Patrick notes the loose counting approximation itself is already somewhat imprecise (extrapolating from one shard directory), and preserving existing semantics tipped the balance toward the current approach.

The changes affect several core components (builtin/gc.c, commit-graph.c) while maintaining caching behavior. With Junio having already indicated the patches are sound and queued for integration, this appears to be a well-considered refinement of Git's internal object counting machinery as part of the larger ODB abstraction effort. The performance/accuracy tradeoff question remains open but non-blocking.
