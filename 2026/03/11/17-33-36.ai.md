Refactoring patch to optimize combine filter parsing by eliminating strbuf overhead. This is the second patch in Deveshi Dwivedi's v3 series addressing strbuf overuse cases flagged by Junio Hamano.

The patch rewrites `parse_combine_filter()` in list-objects-filter-options.c to process combine: specs more efficiently by:
- Replacing `strbuf_split_str()` with direct string walking using `strchrnul()`
- Using a single reusable strbuf instead of allocating temporary buffers
- Silently skipping empty sub-specs (including trailing '+') for robustness
- Converting helper functions to take `const char*` instead of `strbuf*`

Key changes from previous versions (v1-v2) incorporated from Jeff King and Junio Hamano's feedback:
- Added the reusable strbuf to avoid xmemdupz/free per iteration
- Made empty string handling consistent across all positions
- Refocused commit messages on behavior changes
- Removed an incorrect test case expecting error on trailing '+'

The implementation now cleanly handles edge cases while eliminating unnecessary allocations from the original strbuf-based approach. The patch touches both the filter implementation and its test suite, removing one test case that enforced incorrect behavior around trailing delimiters.
