This is a refactoring patch series addressing strbuf usage patterns, following up on Junio Hamano's earlier feedback about avoiding overuse of strbuf_split*() and passing strbufs by value. The series has gone through three iterations, with v3 incorporating Junio's review comments on the second patch.

The first patch modifies `write_worktree_linking_files()` to take plain string paths (`const char*`) instead of strbuf structs by value, eliminating a potential double-free risk in the worktree linking code. This affects `worktree.c`, its header, and the caller in `builtin/worktree.c`.

The second patch (significantly revised in v3) rewrites `parse_combine_filter()` to replace `strbuf_split_str()` with direct string manipulation using `strchrnul()`. Key changes in v3 include:
- Using a reusable strbuf instead of xmemdupz/free per iteration
- Consistently skipping empty sub-specs (both middle and trailing '+')
- Focusing the commit message on behavior rather than implementation details
- Removing an incorrect test case that checked for error on trailing '+'
