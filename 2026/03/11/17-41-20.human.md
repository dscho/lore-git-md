This is a test modernization patch as part of the SHA-256 hash algorithm transition effort. Siddharth Shrimali updates t/t3200-branch.sh to make it properly hash-agnostic while also strengthening its validation of error conditions.

The patch replaces a hardcoded 40-zero string (which only works for SHA-1) with the `$ZERO_OID` variable that automatically adapts to the current hash algorithm. More importantly, it now explicitly checks for the expected "must point to a commit" error message using `test_grep`, rather than just verifying that the command fails. This change was prompted by Patrick Steinhardt's review of the initial version, which revealed the test wasn't properly validating the intended error case.

The update serves two purposes: it makes the test work correctly with SHA-256 (where the 40-character string would fail for the wrong reason), and it better documents the test's intent by verifying the specific error condition we care about. This is a good example of how the SHA-256 transition is uncovering subtle test assumptions that weren't previously visible.
