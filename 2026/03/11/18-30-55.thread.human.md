The thread discusses a proposal to add a `--show-current-patch` option to `git cherry-pick`, mirroring similar functionality in `git rebase`. Florian Best initially suggested this to help users see which commit's changes are being applied during a conflicted cherry-pick operation, as the current workflow requires manually checking `.git/CHERRY_PICK_HEAD` and running `git show`.

His response reflects Git's general philosophy of favoring composable plumbing commands over specialized porcelain when possible.
