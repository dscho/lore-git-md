This thread began with Florian Best proposing a new `--show-current-patch` flag for `git cherry-pick` to help users see which commit's changes are being applied during a conflict. Phillip Wood pointed out that the existing `git show CHERRY_PICK_HEAD` command already provides this functionality with more formatting flexibility than a dedicated flag would offer.

After discussion, the participants have agreed that adding a new flag isn't necessary. Instead, they've settled on improving the cherry-pick documentation to make the existing `CHERRY_PICK_HEAD` mechanism more discoverable. Phillip has suggested adding an example to the man page showing how to use `git show CHERRY_PICK_HEAD` during conflicts, and invited Florian to contribute that documentation patch. This solution maintains Git's preference for composable plumbing commands while addressing the original usability concern. The thread demonstrates how sometimes better documentation can be the right answer when existing capabilities already meet the need but aren't sufficiently visible to users.
