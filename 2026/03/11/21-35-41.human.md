This is a test infrastructure patch from maintainer Junio C Hamano that relaxes the portability restrictions on `sed` options in Git's test suite. 

The change allows `sed -E` (extended regular expressions) in test scripts, which was previously blocked by a 2019 lint check that aimed to keep tests portable. The rationale is that POSIX has since standardized `-E` (as of Issue 8), and Git has already been using it successfully in one test since 2022 (albeit in a way that bypassed the check by combining it with another option).

The patch makes two changes:
1. Updates the `check-non-portable-shell.pl` linter to explicitly allow `-E`
2. Rewrites the existing `-En` usage in `t6030-bisect-porcelain.sh` to use `-E -n` to make the option visible to the linter

This is a straightforward maintenance change that brings the linter in line with current POSIX standards and actual practice in the test suite. The commit message provides clear historical context and justification for the change. As it comes from the maintainer and addresses a known inconsistency, it's likely to be uncontroversial.
