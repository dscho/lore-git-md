Build system refactoring in Patrick Steinhardt's meson PCH series. This is patch 7/8 in the series that introduces precompiled header support to the Meson build system while reorganizing build infrastructure.

Phillip Wood asks for clarification about how Meson handles precompiled header inclusion - specifically whether it forces inclusion of the PCH in every compilation unit or only where the original header is referenced. He notes that splitting compatibility sources into their own library (as done in this patch) provides additional build benefits through parallelization regardless of the PCH behavior.

The patch itself moves all platform-specific sources (Windows, Cygwin, Darwin, Linux compatibility code) from libgit_sources to a new compat_sources list, then builds them as a separate static library. This isolation is necessary because some compatibility sources deliberately avoid including git-compat-util.h, which would conflict with the upcoming PCH approach that implicitly includes it everywhere. The changes are mechanical relocations with no functional alterations, touching only meson.build to restructure the build graph. Platform-specific logic (like Windows vs MSVC vs MinGW paths) remains intact, just moved to the new organization.

This continues the series' dual focus: (1) structural cleanup separating core build components from optional contrib/ material, and (2) performance optimization via PCH. The thread shows active technical review probing design decisions, though no fundamental objections have emerged beyond Junio's earlier note about Coccinelle relocation impacts.
