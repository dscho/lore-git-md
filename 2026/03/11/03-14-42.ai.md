Test infrastructure patch improving unit test output readability by displaying symbolic escape sequence names. This is version 2 of a series that makes test failure output more human-readable by showing names like `\n` and `\t` instead of octal representations like `\012`.

The patch modifies `print_one_char()` in test-lib.c to recognize and display symbolic names for common control characters: bell (`\a`), backspace (`\b`), tab (`\t`), newline (`\n`), vertical tab (`\v`), form feed (`\f`), and carriage return (`\r`). Unrecognized control characters still print in octal. The changes are tested via new cases in test-example-tap.c and updated expectations in t0080-unit-test-output.sh.

Version 2 specifically reverts an unrelated test output change from v1 that affected how backslashes and quotes were displayed in comparisons, ensuring the output exactly matches previous behavior (`'\\\\' == '\\''` format is preserved). The author notes this was done to maintain consistency with existing test expectations.

The patch is focused and non-controversial, part of ongoing test infrastructure work but not tied to any larger effort. It demonstrates attention to detail in test output formatting while improving developer experience when debugging test failures involving control characters. The changes are well-contained to the test framework's output formatting logic.
