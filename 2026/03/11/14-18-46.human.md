This is a bugfix for the promisor-remote subsystem that prevents runaway resource consumption during lazy fetches. The patch addresses a recursive fetch scenario where a child `git fetch` could trigger another lazy fetch when processing REF_DELTA objects against missing bases, potentially creating an unbounded chain of fetches (as happened in production with 276GB of promisor packs written in 90 minutes).

The technical solution propagates `GIT_NO_LAZY_FETCH=1` into child fetch processes to prevent recursion. While the immediate fix is client-side hardening, Patrick Steinhardt has raised important questions about whether this addresses a server protocol violation (servers sending invalid packfiles) rather than purely a client bug. The author confirms this was encountered with GitHub's git-upload-pack but lacks server-side details.

The discussion has evolved to clarify the failure scenario and test coverage. The v3 test now demonstrates the actual failure mode by injecting a thin pack with problematic REF_DELTAs, rather than just checking the environment variable. The patch remains technically sound as client protection, though the justification may need refinement to separate the client hardening from potential server-side issues. This connects to broader concerns about promisor-remote behavior and partial clone edge cases.
