This is the final patch in a v4 series enhancing `git fast-import`'s signature handling capabilities, specifically adding a new mode to re-sign commits with invalid signatures.

The patch introduces a "sign-if-invalid" mode for `--signed-commits` that allows re-signing commits when their original signatures fail verification. The mode supports an optional key ID parameter (`sign-if-invalid[=<keyid>]`) to specify which key to use, defaulting to the configured signing key if none is provided. The implementation builds on earlier work that added signature verification infrastructure to fast-import.

Key technical aspects:
- New `SIGN_SIGN_IF_INVALID` enum value
- Updated `parse_sign_mode()` to handle the new mode and optional key ID
- Refactored signature handling logic to share warning messages between strip/sign modes
- Explicit error for unsupported interoperability mode cases (with NEEDSWORK comment)
- Comprehensive test coverage for OpenPGP/X.509/SSH signatures

The patch maintains the series' focus on signed commits only (not yet handling unsigned commits) and explicitly documents the current limitation around interoperability mode signatures. The implementation is clean and well-tested, with clear parallels to the existing `strip-if-invalid` mode.

This completes the core functionality for the signature re-signing feature, though the thread discussion indicates future directions may include signing unsigned objects and adding an abort-on-invalid mode. The patch series has been through multiple iterations with positive feedback, and this final piece looks ready for merging.
