This thread addresses updates to Git's IMAP send functionality to maintain compatibility with OpenSSL 4.0, focusing on modernizing certificate handling in `imap-send.c`. The original four-patch series from Beat Bolli updates deprecated OpenSSL calls, with patches 1 and 2 being uncontroversial fixes for accessing certificate fields. However, patch 3's removal of string length checks has sparked a security debate.

Oswald Buddenhagen first objected that these checks protect against embedded nulls that could bypass hostname verification. Now Junio Hamano has weighed in, questioning the removal's rationale since the hostname matching still uses raw string pointers at this stage. His intervention suggests the checks may indeed serve a security purpose that the new APIs don't fully address. While patches 1 and 2 remain essential updates, patch 3 appears problematic and may need revision or removal. The discussion highlights how seemingly routine updates to deprecated APIs can uncover deeper security considerations in certificate validation logic. The author will likely need to address these concerns before the series can proceed.
