This thread addresses updates to Git's IMAP send functionality to maintain compatibility with OpenSSL 4.0, focusing on replacing deprecated API usage in certificate validation. The original four-patch series modernized how Git accesses SSL certificate fields, but patch 3 sparked a security debate when it removed string length checks that Oswald Buddenhagen argued were necessary to prevent embedded nulls from bypassing hostname validation. Junio C Hamano weighed in, supporting this security concern.

The author, Beat Bolli, has now acknowledged the issue and plans to revise patch 3 to retain these critical checks while keeping the uncontroversial API updates in patches 1 and 2. The final patch's hostname matching refactoring will need adjustments to accommodate the retained validations. This exchange highlights how security considerations can reshape even seemingly straightforward technical updates, with the community quickly converging on a safer approach once the risks were clearly articulated. The thread now awaits the revised patch series.
