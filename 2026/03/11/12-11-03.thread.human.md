This thread addresses updates to Git's IMAP send functionality to modernize its OpenSSL APIs while carefully preserving security checks. The series, now at version 2, responds to deprecation warnings in OpenSSL 4.0 while ensuring no regression in security validation.

The discussion began with Beat Bolli proposing API updates across three areas of IMAP SSL handling. Oswald Buddenhagen and Junio C Hamano raised critical security concerns about the initial approach, particularly regarding potential bypasses of hostname validation through embedded nulls in certificate strings. This led to a restructured v2 series that maintains all necessary security checks while updating the deprecated APIs.

The current patch focuses on updating how Git accesses SSL certificate common names, replacing the deprecated `X509_NAME_get_text_by_NID` with newer OpenSSL 1.1.0+ APIs. Like the first patch (which handled subject alternative names), this change carefully preserves the length validation checks that prevent security bypasses. The implementation shows attention to detail in maintaining both backward compatibility and proper const-correctness across OpenSSL versions.

All participants now agree on the approach, with the v2 series representing a consensus solution that addresses both the technical debt of deprecated APIs and the security requirements. The third patch is expected to complete the modernization while maintaining the security standards established in this discussion.
