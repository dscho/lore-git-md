This is a bugfix discussion about preventing zombie processes when Git runs as PID 1 in containers. Jeff King (Peff) is reviewing Andrew Au's v2 patch that adds atexit handlers to clean up child processes during abnormal exits from network operations.

Peff identifies a potential deadlock risk in the current implementation - the cleanup handler waits for the child to exit, but the child might be waiting on the parent (e.g. for pipe input). He suggests using the existing `clean_on_exit` flag in `run-command.[ch]` which would kill the child first before waiting, avoiding deadlocks. 

The discussion reveals a deeper consideration - whether `clean_on_exit` should be the default behavior for all Git subprocesses, since it's rare for subprocesses to legitimately outlive their parent. Peff notes this would require auditing all `run_command()` callsites to identify exceptions like daemon processes.

While the immediate fix is focused on the transport helper/connect case, Peff's comment opens a broader design question about subprocess lifecycle management in Git. The patch appears technically sound but could be improved by adopting the existing kill-then-wait pattern rather than just waiting. This is a thoughtful review from a senior contributor with deep knowledge of Git's process management.
