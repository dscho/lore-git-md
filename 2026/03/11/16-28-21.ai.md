This is a review comment from Junio Hamano on Deveshi Dwivedi's refactoring patch to avoid strbuf usage in list-objects-filter parsing. The patch is part of a v2 series addressing strbuf overuse cases.

Junio notes that while the implementation is sound, the commit message focuses too much on implementation details rather than the higher-level changes. He analyzes the edge case behavior with empty strings in combine filters, pointing out that the new version rejects empty strings in the middle (like "foo++bar") while the old version rejected them at the end ("foo+"). This creates an inconsistency in error handling that could affect existing users of malformed filters.

Junio also suggests an alternative optimization approach using a reusable strbuf for temporary copies, which would be more efficient than repeated xmemdupz allocations. The patch removes a test case expecting an error on trailing '+', which Junio doesn't explicitly object to but notes the behavioral change.

The review is generally positive, with Junio calling the implementation "good" and "nothing surprising", while raising these edge case considerations. The thread appears to be converging toward acceptance with these minor observations noted.
