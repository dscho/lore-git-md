This is the third patch in a series adding advice for handling uncommitted changes during branch switches, building on prior work that was merged in Git 2.54.0. The patch removes the previously proposed `ADVICE_STASH_BEFORE_CHECKOUT` mechanism in favor of extending the existing warning message in `unpack-trees.c` to also suggest `git checkout -m <branch>` while clearly noting its limitations.

The key changes are:
1. Removes the `advise_on_checkout_dirty_files()` function and associated config/advice infrastructure that was introduced in earlier versions
2. Modifies the existing checkout warning message to include:
   - A suggestion to use `git checkout -m <branch>`
   - Clear warnings that this doesn't save changes but merges them directly
   - A note that unresolved conflicts followed by `--hard` will lose local changes
3. Updates test expectations to match the new message format

The patch follows the maintainers' guidance to integrate with the existing warning system rather than creating new advice infrastructure. It maintains the same test coverage from earlier iterations while simplifying the implementation. The message wording aims to balance suggesting a solution while being transparent about its risks.

This represents the final iteration of the feature, with all prior feedback from Junio C Hamano, Phillip Wood, and others incorporated. The changes demonstrate responsive refinement of both the user experience and implementation approach through the GSOC mentoring process.
