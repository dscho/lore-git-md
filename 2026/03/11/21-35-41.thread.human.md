This thread discusses a straightforward update to Git's test infrastructure that relaxes portability restrictions on `sed` usage in test scripts. Junio Hamano's patch allows the `-E` flag (extended regular expressions) in `check-non-portable-shell.pl`, bringing the linter in line with POSIX Issue 8 (2018) standards. The flag has been used in Git's tests since 2022 without issues, making the original restriction based on POSIX Issue 7 outdated.

The patch makes two specific changes: updating the linter to permit `-E` alongside existing allowed flags (`-n`, `-e`, `-f`), and fixing a test in `t6030-bisect-porcelain.sh` that used `-En` by separating the flags into `-E -n` for clarity and linter compliance. This is a minor but thoughtful maintenance update that aligns the test suite with current standards while improving code clarity. The changes are uncontroversial and well-justified by both standards evolution and years of successful usage in practice.
