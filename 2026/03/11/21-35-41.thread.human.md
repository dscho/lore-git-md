This thread discusses a small but thoughtful update to Git's test infrastructure regarding `sed` usage in the test suite. Junio Hamano originally sent a patch to allow the `-E` flag (extended regular expressions) in `sed` commands, bringing the test suite in line with current POSIX standards while maintaining the linter's role in preventing non-portable options. The change was well-justified by both standards evolution and years of successful usage in practice.

Ramsay Jones followed up with a friendly observation that while the linter's pattern was updated to permit `-E`, the corresponding error message still only listed the older permitted options (`-n`, `-e`, and `-f`). He suggested updating the message for consistency - a minor but worthwhile polish to avoid potential confusion. The exchange demonstrates the project's attention to detail in test infrastructure, where even small inconsistencies are worth addressing. The fix would be a straightforward one-line update to the same linter file Junio had already modified.
