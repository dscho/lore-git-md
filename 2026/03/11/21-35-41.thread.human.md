This thread centers on modernizing Git's test suite to support the `-E` flag for extended regular expressions in `sed` commands, aligning with POSIX Issue 8 (2018) standards. Junio Hamano's patch series updates the `check-non-portable-shell.pl` linter to permit `-E` alongside existing flags like `-n` and `-e`, while fixing an inconsistency in the linter's error message documentation. A test in `t6030-bisect-porcelain.sh` was adjusted to use separate `-E -n` flags instead of the squished `-En` form.

Ramsay Jones spotted the error message mismatch in the initial version, prompting Junio to correct it in v2 along with a commit message typo. Patrick Steinhardt reviewed the changes, agreeing that handling squished flags like `-En` wasn't worth the added complexity. brian m. carlson confirmed broad platform support for `-E`, noting the historical twist that Linux (via older Ubuntu) was the last major platform to standardize the flag after previously using `-r`. Todd Zullinger later contributed additional historical context, tracing GNU sed's `-E` support back to 2006—earlier than its documentation suggested.

The discussion highlights Git's meticulous approach to test infrastructure, where even minor documentation mismatches are addressed. With no outstanding objections and platform compatibility thoroughly vetted, this straightforward standards-compliance update is ready for merging.
