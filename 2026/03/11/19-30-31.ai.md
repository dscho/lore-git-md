This is a discussion about adding a `--show-current-patch` option to `git cherry-pick`, mirroring existing functionality in `git rebase`. Phillip Wood responds to Florian Best's initial proposal, pointing out that users can already inspect the current cherry-pick commit using `git show CHERRY_PICK_HEAD`, which offers more flexibility than a dedicated flag would.

Phillip notes that while the feature might be useful, the existing workflow using `CHERRY_PICK_HEAD` (and similarly `REVERT_HEAD`/`REBASE_HEAD` for other operations) already provides the needed information with additional formatting options. He suggests the documentation could perhaps be improved to make this more discoverable rather than adding a new flag. The response indicates this may not be the right solution to the discoverability problem Florian identified.

The thread shows a typical Git design consideration - whether to add new porcelain commands when existing plumbing could serve the same purpose with slightly more effort. Phillip's position suggests favoring the current composable approach over adding specialized flags, unless there's a compelling reason the existing method falls short. No technical objections are raised about implementation feasibility, but the utility of the proposal is questioned given existing alternatives.
