Build system discussion about Meson precompiled headers. This is part of Patrick Steinhardt's 8-patch series introducing build system improvements, including a new tools/ directory and precompiled header support in Meson.

Phillip Wood follows up on his own question about how Meson handles precompiled header inclusion, confirming that Meson uses `-include` to force inclusion before any C tokens appear. He notes this is technically required but observes that Git's code structure (where `git-compat-util.h` is always included first) might allow a more relaxed approach. Phillip also raises a new question about whether the reftable sources need special handling since they don't include `git-compat-util.h`.

The exchange shows careful technical review of the build system changes, with Phillip verifying both the general mechanism and Git-specific implications. This comes after Patrick's patch to split compatibility sources into a separate static library to accommodate the upcoming PCH changes. The discussion remains focused on implementation details rather than high-level design.
