This is a technical review follow-up in Patrick Steinhardt's ODB abstraction series, specifically addressing patch 6/6 which introduces generic object counting. Toon Claes notes that a comment in odb.h needs updating to reflect the new odb_count_objects() API rather than referencing the old repo_approximate_object_count(). The patch itself moves object counting logic to the ODB layer while preserving caching behavior, with flags to control whether loose objects are included (ODB_COUNT_OBJECTS_APPROXIMATE vs exact counts).

The changes touch several callers including gc.c, commit-graph.c and object-name.c, replacing repo_approximate_object_count() with odb_count_objects(). The implementation combines counts from all ODB backends while maintaining the existing caching mechanism, now extended to cache separately for approximate vs exact counts. Toon's review confirms the technical correctness of the changes aside from the outdated comment, continuing his pattern of detailed review throughout this series. The thread shows consensus on the approach, with Junio C Hamano having previously raised but accepted the performance tradeoffs in the loose object counting strategy.
