This is the second patch in a three-part series updating Git's IMAP send functionality to use modern OpenSSL APIs, addressing deprecation warnings in OpenSSL 4.0 while maintaining security checks. The patch focuses specifically on how Git accesses the common name field in SSL certificates.

The change replaces the deprecated `X509_NAME_get_text_by_NID` function with the recommended sequence of `X509_NAME_get_index_by_NID`, `X509_NAME_get_entry`, and `X509_NAME_ENTRY_get_data` calls. This maintains the same functionality while using APIs that have been available since OpenSSL 1.1.0 (2019). The patch carefully handles constness differences between OpenSSL versions and preserves the critical security check that verifies the certificate's common name string length matches its content (to prevent embedded nulls from bypassing hostname validation).

The implementation shows attention to detail in maintaining both backward compatibility and security - it conditionally declares variables with/without const qualifiers based on OpenSSL version, and keeps the existing hostname matching logic while using the newer API access pattern. This patch follows from the thread's earlier security discussion where Oswald Buddenhagen and Junio C Hamano emphasized the importance of maintaining these validation checks.
