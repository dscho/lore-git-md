This is a follow-up discussion about shell script portability in Git's test suite, specifically around `sed -E` usage. The thread is part of a larger series about standardizing string list sorting behavior across Git commands.

Eric Sunshine confirms that the test-lint script (`check-non-portable-shell.pl`) can detect `sed -E` usage when it appears as the first option (thanks to a 2018 improvement), but notes it misses cases where `-E` appears after other flags like `-n -i -e`. Junio Hamano had raised concerns about these portability gaps earlier in the discussion.

The exchange highlights ongoing challenges in maintaining portable shell scripts while modernizing the test suite. The test-lint script's current implementation has known limitations in flag detection, particularly with compound `sed` invocations. This technical note doesn't propose solutions but clarifies the scope of existing tooling, helping frame future discussion about balancing POSIX compliance with practical needs.
