Test modernization effort to support SHA-256 hash algorithm continues with changes to t/t3200-branch.sh. Siddharth Shrimali's initial patch replaced a hardcoded 40-zero string with `$ZERO_OID` variable to make the test hash-agnostic, maintaining test coverage while being future-proof. Patrick Steinhardt reviewed the change and identified a subtle issue - while the test now passes with both SHA-1 and SHA-256, it masks a behavioral difference in error messages between hash algorithms when using the null OID. With SHA-1, Git reports "option `merged' must point to a commit", while SHA-256 fails earlier with "malformed object name". The current test only checks for failure, not the specific error. Patrick suggests strengthening the test by explicitly checking for the "must point to a commit" message using `test_grep`, which would make the test more robust and catch any future divergence in behavior. This reveals the test was never properly validating the expected error case, and the SHA-256 transition exposed this gap. The discussion highlights how hash algorithm transitions can uncover previously hidden assumptions in test cases.
