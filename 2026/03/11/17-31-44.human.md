This is a v4 patch series from Justin Tobler that adds a new signing mode to `git fast-import`. The series builds on previous work that allowed stripping invalid signatures, now adding the ability to re-sign them instead.

The key addition is a new `sign-if-invalid` mode for `--signed-commits` that will replace invalid commit signatures with new ones (using either the default key or a specified key). The implementation refactors some signing infrastructure to make it reusable, moving `sign_commit_to_strbuf()` to `gpg-interface.c` as the more general `sign_buffer_with_key()`.

The series has gone through several iterations with improvements to naming (from "re-sign-if-invalid" to "sign-if-invalid"), better commit messages, and added test coverage. One known limitation is that interoperability mode (for SHA-1/SHA-256 compatibility) isn't supported yet for re-signing, as it would need to reconstruct commit buffers in both formats.

The changes since v3 are minor naming tweaks and documentation updates. The implementation looks solid, with thorough test coverage for OpenPGP, X.509, and SSH signatures. This appears ready for merging as it provides a useful extension to the signature handling capabilities in fast-import while leaving room for future enhancements like supporting unsigned objects.
