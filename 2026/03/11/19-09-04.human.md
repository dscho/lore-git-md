This is a follow-up in the `the_repository` removal thread about converting `start_command()` callers. The original series mechanically converted all 46 callers to pass a repository parameter, but René Scharfe and Jeff King proposed a more surgical approach - since only 3 callers (`gc`, `pull`, and `auto-maintenance`) actually need the repository-dependent `close_object_store` functionality, they suggest storing an explicit object store pointer in `struct child_process` just for those cases.

Author Burak Kaan Karaçay acknowledges this is an elegant solution and indicates they'll prepare a v2 series implementing this approach. This exchange demonstrates how experienced contributors are steering the `the_repository` removal effort toward interface redesigns when dependencies are narrow, rather than blanket mechanical conversions. The change will simplify the API for most callers while still eliminating the global variable dependency where it matters.
