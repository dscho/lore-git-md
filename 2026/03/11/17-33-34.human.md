This is a refactoring patch series addressing two cases of strbuf overuse, following up on Junio Hamano's earlier feedback about unnecessary strbuf usage. The series has gone through three iterations, with v3 incorporating Junio's review comments on the second patch.

The first patch changes `write_worktree_linking_files()` to take plain string paths (`const char*`) instead of strbuf structs by value, eliminating a potential double-free risk in the worktree linking code. This affects the worktree implementation and its callers.

The second patch (now refined in v3) rewrites `parse_combine_filter()` to avoid using `strbuf_split_str()` for parsing combine filter specs. The new version:
- Uses direct string walking with `strchrnul()`
- Reuses a single strbuf for temporary copies instead of allocating per iteration
- Handles empty sub-specs consistently (like "foo++bar")
- Skips implementation details in the commit message per Junio's suggestion

The changes are clean, focused improvements that address specific strbuf usage patterns while maintaining the same functionality. The series appears ready for merging, with all review feedback incorporated and no outstanding objections. These are mechanical refactorings that don't change behavior but improve code quality and safety.
