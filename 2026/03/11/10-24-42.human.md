This is a feature patch in Adrian Ratiu's ongoing hook configuration series, specifically addressing how disabled hooks are displayed in `git hook list`. The patch modifies the output format to show disabled status alongside hook names and their configuration source (local/global), while also making the internal storage of disabled state more robust.

Patrick Steinhardt raises several technical points in his review. He questions whether the output format with parenthetical annotations remains machine-parseable with `-z`, suggesting this might be a case where Git's custom formats struggle compared to something like JSON. He also notes the use of `int` for boolean flags where `bool` would be more semantically appropriate, and asks for clarification on the term "build time" in the documentation (which actually refers to cache construction time, not the make process).

The patch introduces a more nuanced handling of disabled hooks - they're now preserved in the cache with their disabled state marked, rather than being filtered out entirely. This allows `git hook list` to show them while still skipping them during actual execution. The implementation includes proper warning messages for disabled hooks with missing commands, rather than treating this as a fatal error.

Steinhardt's review is thorough but constructive, identifying opportunities to improve type safety and documentation clarity. The feedback suggests the series is nearing readiness but may need minor adjustments to the output format and internal type usage before final integration. This continues the pattern of careful review and incremental improvement that has characterized Adrian's hook configuration work.
