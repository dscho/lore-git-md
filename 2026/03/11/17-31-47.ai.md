This is the third patch in a v4 series expanding `git fast-import`'s signature handling capabilities, specifically adding a new mode to re-sign commits with invalid signatures. The work builds on earlier merged changes by Christian Couder and Justin Tobler that enabled signature preservation and stripping.

The patch introduces a `sign-if-invalid[=<keyid>]` mode for `--signed-commits` that verifies commit signatures and replaces invalid ones with newly created signatures while leaving valid signatures unchanged. The optional keyid parameter matches `git commit --gpg-sign` syntax. The implementation shares infrastructure with the existing `strip-if-invalid` mode but adds new signing logic through the generalized `sign_buffer_with_key()` helper.

Key technical changes include:
- New `SIGN_SIGN_IF_INVALID` enum value
- Updated `handle_signature_if_invalid()` to support both strip and re-sign modes
- Warning messages specific to each mode
- Explicit failure for interoperability mode (marked NEEDSWORK)
- Comprehensive test coverage for OpenPGP/X.509/SSH signatures
- Support for explicit key IDs in SSH signing tests

The patch maintains the series' current limitation to only re-signing previously-signed-but-invalid commits, leaving unsigned commits untouched. Junio C Hamano has suggested this could be extended later with a `--sign-commits=all` option. The implementation is careful to maintain separation between signature creation and stripping concerns while establishing reusable signing infrastructure.

Test coverage is thorough, verifying behavior for all supported signature types and including a case demonstrating explicit key ID specification. The tests also confirm the warning messages differentiate between stripping and re-signing invalid signatures.
