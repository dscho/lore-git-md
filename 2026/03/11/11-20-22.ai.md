Test modernization patch addressing SHA-256 compatibility in the t3200-branch.sh test script. Patrick Steinhardt responds to Siddharth Shrimali's patch that replaces a hardcoded 40-zero string with the `$ZERO_OID` variable to make the test hash-agnostic.

Patrick notes that while the change correctly makes the test work with both SHA-1 and SHA-256, it actually masks a difference in behavior - the error messages differ between hash algorithms when using the null OID. With SHA-1, Git reports "option `merged' must point to a commit", while with SHA-256 it fails earlier with "malformed object name". The test only checks for failure, not the specific error.

He suggests strengthening the test by explicitly checking for the "must point to a commit" message using `test_grep`, which would make the test more robust and catch any future divergence in behavior. This would require the test to verify both the failure and the specific reason, rather than just the fact that it failed. The underlying issue appears to be that the test was never properly validating the expected error case, and the SHA-256 transition exposed this gap.
