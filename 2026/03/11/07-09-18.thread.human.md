This thread addresses a regression in Git's EditorConfig file where a recent change inadvertently caused style rules to stop applying to certain subdirectories. Patrick Steinhardt identified the issue - how EditorConfig interprets glob patterns containing path separators - and proposed splitting the configuration into two clear sections to work around the quirk. One section handles general file types while another specifically targets hook templates, ensuring consistent formatting continues to apply throughout the source tree.

Phillip Wood has now reviewed the patch and concurs with Patrick's approach. He acknowledges the minor duplication this introduces is preferable to complex glob patterns that would be harder to maintain. Their exchange confirms this straightforward technical fix has reached consensus, with no objections raised to the solution's design. The small build system change appears ready to be picked up, addressing the regression without impacting core functionality. Both contributors agree the split-section approach provides the right balance between correctness and maintainability for this editor configuration edge case.
