This is a discussion about the configuration interface for Git's cover letter formatting feature, part of the ongoing RFC-to-feature patch series implementing comprehensive cover letter formatting for `git format-patch`.

Phillip Wood weighs in on Junio C Hamano's suggestion to use a boolean-based configuration for the `format.commitListFormat` setting. While Junio proposed treating the config as a boolean (with `false` falling back to shortlog and `true` using the modern default format), Phillip expresses openness to the approach but suggests using named formats ("shortlog" and "numbered") instead of boolean values for clearer semantics. He notes he doesn't have strong preferences between the approaches as long as the names are sensible.

The exchange shows the discussion converging toward a solution that maintains the feature's flexibility while improving the configuration clarity. Phillip's position aligns with the author Mirko Faina's earlier expressed preference for string-based configuration over boolean toggles, though he's now reconsidering that stance in light of Junio's suggestion. This represents one of the final open questions before the series can be merged, with the technical implementation otherwise complete and well-reviewed.
