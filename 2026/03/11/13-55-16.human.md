This is part of Patrick Steinhardt's ongoing ODB (object database) abstraction effort, specifically focusing on object counting functionality. The patch extracts packed object counting logic from `repo_approximate_object_count()` into a new `packfile_store_count_objects()` function, preparing for pluggable backends.

Toon Claes has been reviewing the series in detail and confirms his understanding of the MIDX (multi-pack-index) handling - that `m->num_objects` counts current pack objects while `m->num_objects_in_base` accumulates base pack objects recursively, and that packs already included in the MIDX are correctly skipped. Patrick confirms Toon's analysis is correct.

The change is a straightforward refactoring that moves existing logic while maintaining the same behavior. It's part of a larger six-patch series that Junio C Hamano has already reviewed and queued, with only minor considerations about loose object counting tradeoffs remaining open. The series touches core object storage code in packfile.c and related files, continuing Patrick's architectural work to make Git's object storage more modular.
