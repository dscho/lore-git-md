This is a security-related follow-up in the OpenSSL API modernization series for Git's IMAP send functionality. Beat Bolli acknowledges Oswald Buddenhagen's security concern about patch 3/4, which had proposed removing string length checks when accessing SSL certificate fields. Buddenhagen correctly pointed out these checks prevent embedded nulls from bypassing hostname matching, making them security-critical rather than redundant. Bolli now agrees with this assessment and plans to send a revised version of the patch that keeps these validations in place.

The exchange confirms that while the overall series (updating OpenSSL API usage in `imap-send.c` for compatibility with OpenSSL 4.0) remains important, this particular change was misguided. The thread shows the project's security-conscious culture in action - even seemingly minor validation removals get scrutinized when they might impact certificate verification. Junio C Hamano's earlier probing aligned with Buddenhagen's concerns, and the author's quick acknowledgment suggests the series will emerge stronger from this review.
