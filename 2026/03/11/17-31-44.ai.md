This is a v4 patch series adding signature handling capabilities to `git fast-import`, building on previous work to handle invalid commit signatures. The series introduces a new `sign-if-invalid` mode that allows re-signing commits with invalid signatures rather than just stripping them.

The series consists of three patches:
1. A cleanup removing an unused forward declaration
2. A refactoring that generalizes commit signing into a reusable `sign_buffer_with_key()` helper
3. The main implementation adding the new `sign-if-invalid` mode

Key technical details:
- New `sign-if-invalid[=<keyid>]` mode matches `git commit --gpg-sign` syntax
- Uses the new `sign_buffer_with_key()` helper from gpg-interface.c
- Explicitly fails for `extensions.compatObjectFormat` with NEEDSWORK comment
- Comprehensive test coverage for OpenPGP/X.509/SSH signatures
- Current limitation to only re-signing previously-signed-but-invalid commits

The implementation looks clean and well-tested, with clear commit messages explaining the changes. The series has gone through several iterations with improvements to naming and documentation based on feedback. The main open question is around handling interoperability mode signatures, which the author has deferred for now with a clear explanation of the technical challenges involved.

This builds on previous signature handling work in fast-import and connects to broader signature work in Git. The refactoring establishes reusable signing infrastructure that could support future extensions like signing unsigned objects or adding abort-on-invalid behavior.
