This is a bugfix patch for `git merge-file --object-id` in worktrees, now at version 2 with all reviewer feedback incorporated. The patch addresses a BUG() that occurs when using `--object-id` in a worktree due to a redundant `setup_git_directory()` call. Mathias Rav has updated the patch per feedback from Karthik Nayak, Patrick Steinhardt, Kristoffer Haugsbakk, and Junio Hamano.

Key changes in v2 include clearer terminology ("linked worktree" instead of just "worktree"), modern test syntax using `git -C` instead of subshells, and commit message cleanup. The implementation now properly guards the repository setup behind a pointer check when `--object-id` is used, cleanly separating the "need repository" and "have repository" states.

The patch appears ready for merging, with thorough test coverage and clear commit message. One minor open discussion remains about commit reference formatting preferences between gitk and command-line tools, but this doesn't affect the technical correctness of the fix. The core issue - making `merge-file --object-id` work correctly in worktrees - is fully addressed.
