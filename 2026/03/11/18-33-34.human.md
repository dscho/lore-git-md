This is a discussion about refactoring the experimental `git replay` command's interface from mutually-exclusive options to subcommands. Justin Tobler responds to Toon Claes's RFC patch proposing to replace `--onto`, `--advance`, and `--revert` options with `rebase`, `pick`, and `revert` subcommands respectively.

Justin raises several concerns about the proposed changes:
1. The `rebase` subcommand still requires `--onto`, making it unclear what simplification is achieved
2. The new interface makes previously optional arguments required (like `--ref` for `pick` and `revert`)
3. The change breaks backward compatibility for this experimental command
4. The subcommand+required option combination may not actually improve usability

The discussion focuses on interface design tradeoffs rather than implementation details. Justin suggests keeping required arguments as positional parameters might be better, and notes the experimental status should be more explicitly acknowledged when making breaking changes.

This is part of an ongoing effort to refine `git replay`'s interface before it graduates from experimental status. The thread shows active design discussion about how to balance clarity, consistency with Git conventions, and backward compatibility for an important plumbing command.
