This is a bugfix addressing zombie processes left behind when Git exits abnormally during network operations in container environments. The patch adds atexit handlers to ensure child processes are properly reaped even when Git crashes or exits early due to transport errors.

Andrew Au provides a concrete use case in response to Junio Hamano's question about real-world impact: a long-running containerized service that continuously spawns Git processes to monitor repositories. In this scenario, zombies accumulate over time rather than being cleaned up at container exit, with the author observing over 6,500 zombie processes before identifying this issue.

The technical solution (already implemented in v2) introduces symmetric atexit handlers in transport-helper.c and connect.c to track and clean up child processes. The implementation appears sound and well-contained, with handlers registered when child processes start and cleared during normal cleanup to avoid double-waiting.
