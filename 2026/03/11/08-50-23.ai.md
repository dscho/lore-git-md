This is a feature patch series (v4) from Arsh Srivastava adding a new advice type for handling uncommitted changes during branch switches. The series is part of a GSOC microproject and builds on previous discussion about improving user guidance when checkout would overwrite local modifications.

The key addition is `ADVICE_STASH_BEFORE_CHECKOUT`, which triggers when switching branches with uncommitted changes that would be lost. The advice suggests three options: stashing changes, discarding them, or using `git checkout -m` to merge (with explicit warnings about the irreversible nature of the merge option). The implementation follows Git's existing advice patterns, with configurable behavior via `advice.stashBeforeCheckout`.

The series has evolved through multiple versions with input from several reviewers:
- Junio C Hamano guided the safety messaging, particularly emphasizing the risks of `-m`
- Phillip Wood helped shape the initial approach
- Patrick Steinhardt ensured proper integration points
- Karthik Nayak reviewed formatting and test coverage

Notable technical aspects:
- Adds new enum in `advice.h` and implementation in `advice.c`
- Integrates with `checkout_worktree()` logic in `builtin/checkout.c`
- Includes test coverage in `t/t6439-merge-co-error-msgs.sh` and `t/t7406-submodule-update.sh`
- Updates documentation in `Documentation/config/advice.adoc`

The v4 iteration specifically adds clearer warnings about the irreversible nature of the merge option (`-m`) per Junio's feedback, while maintaining balanced presentation of all three options.
