This is a refactoring patch from Deveshi Dwivedi that changes how `write_worktree_linking_files()` handles path parameters. The function previously took `strbuf` structs by value, which could lead to dangerous double-free scenarios if the callee reallocated the buffer. The patch converts it to take simple `const char*` strings instead.

The change affects several worktree-related functions across `worktree.c` and `builtin/worktree.c`, updating all callers to pass the string buffers from their strbufs rather than the strbufs themselves. This is part of a larger thread where Junio Hamano flagged cases of strbuf overuse, with Jeff King (Peff) providing implementation feedback.

This is the first of two patches in v3 of the series, and it has remained stable through revisions while the second patch saw more significant changes. The patch appears ready for merging, with all reviewer feedback addressed and no outstanding concerns. It's a focused cleanup that eliminates a potential memory safety issue without changing behavior.
