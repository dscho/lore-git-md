This is a feature proposal for `git cherry-pick` to add a `--show-current-patch` option, mirroring existing functionality in `git rebase`. The patch would help users see which commit is being applied when a cherry-pick operation stops due to conflicts.

Currently, users must manually inspect `.git/CHERRY_PICK_HEAD` and run `git show` to view the problematic patch. The proposed option would make this workflow more discoverable and convenient, particularly during range cherry-picks where multiple commits are being applied sequentially.

The author, Florian Best, notes this would provide parity with `git rebase`'s existing `--show-current-patch` flag and help users understand conflicts, review changes, and debug large cherry-pick operations. The implementation would show the patch corresponding to `CHERRY_PICK_HEAD` when a cherry-pick is in progress, or error cleanly when none is active.

The proposal is straightforward and addresses a clear usability gap in the cherry-pick workflow. The similarity to the existing rebase functionality suggests the implementation would be relatively simple while providing tangible benefits to users dealing with merge conflicts.
