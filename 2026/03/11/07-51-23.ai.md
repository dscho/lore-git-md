This is a build system modernization discussion about deprecating autoconf in favor of Meson, continuing from Patrick Steinhardt's initial RFC proposal. The thread has clarified that autoconf is not itself a build system but rather a tool that generates Makefiles, making the real comparison between Makefile-based builds (with or without autoconf) versus Meson as an alternative build system.

Patrick responds to Junio's distinction by emphasizing that his goal is specifically to remove the autoconf infrastructure, which he describes as the "least-loved" part of Git's build system - difficult to maintain and not the recommended way to build Git (the direct Makefile approach is typically suggested instead). He references past discussions that appeared to favor autoconf removal but acknowledges Junio or others may disagree with proceeding now.

The key open question remains whether the project wants to:
1. Keep autoconf-generated Makefiles alongside Meson
2. Move to direct Makefile usage without autoconf
3. Fully transition to Meson as the primary build system

Patrick's position leans toward option 1 (removing autoconf while keeping Meson support), seeing autoconf as the pain point rather than advocating for complete Makefile replacement. Junio's earlier response suggested he may prefer modernizing the Make-based approach (option 2) over Meson adoption. The discussion needs to resolve this fundamental direction before the proposed deprecation timeline (targeting Git 2.55) can proceed.
