This is a refactoring patch that addresses a potentially dangerous strbuf usage pattern in the worktree linking code. It's the first of two patches in a series that has already gone through one revision (v2) incorporating feedback from Jeff King.

The patch changes `write_worktree_linking_files()` to accept plain string paths (`const char*`) instead of taking `strbuf` structs by value. The original implementation was problematic because passing strbufs by value creates a risk of dangling pointers if the callee reallocates the buffer, which could lead to double-free issues when the caller releases its copy.

The change is straightforward and mechanical - the function now takes string pointers directly, and all callers are updated to pass `.buf` from their strbufs. The implementation remains functionally identical but is now safer and more idiomatic. The patch touches the worktree implementation in `worktree.c`, its header, and one caller in `builtin/worktree.c`.

This appears to be a well-considered cleanup that follows through on prior feedback from experienced contributors. The commit message clearly explains the rationale and the diff shows careful attention to updating all relevant call sites. As part of a v2 series that has already addressed initial review comments, this patch looks ready for inclusion.
