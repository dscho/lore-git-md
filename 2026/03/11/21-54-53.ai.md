This is a technical discussion about shell script portability in Git's test suite, specifically around `sed -E` usage and the limitations of the test-lint script.

Eric Sunshine responds to Junio C Hamano's concerns about the test suite's portability checking, clarifying that while the linter can detect `sed -E` in some cases (thanks to line folding support added in a0a630192d), it has significant gaps. The main issue is that the linter only examines the first option after `sed`, missing non-portable flags like `-i` when they appear later in the command (as in `sed -n -i -e` patterns).

The exchange highlights ongoing challenges in balancing modern scripting practices with portability requirements. While POSIX Issue 8 standardized `-E`, Git's test suite still needs to support older systems. The discussion also surfaces limitations in the test-lint script's ability to catch all non-portable constructs, particularly around `sed` flag detection.
