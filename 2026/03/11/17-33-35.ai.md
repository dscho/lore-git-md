This is a refactoring patch that eliminates potentially dangerous strbuf usage in worktree linking code. It's the first of two patches in Deveshi Dwivedi's v3 series addressing strbuf overuse cases flagged by Junio Hamano.

The patch modifies `write_worktree_linking_files()` to accept plain C strings (`const char*`) instead of taking `strbuf` structs by value. The change is motivated by a subtle double-free risk: when strbufs are passed by value, both caller and callee share the underlying buffer pointer, which could become dangling if the callee reallocates it. Since the function only needs the string contents, not the strbuf machinery, the simpler string interface is more appropriate.

The changes affect `worktree.c`, its header, and `builtin/worktree.c`, updating all call sites to pass `.buf` from their strbufs. The implementation remains functionally identical but is now safer against reallocation issues. This patch has remained stable through all three iterations of the series, with reviewers Jeff King and Junio Hamano focusing their feedback on the second patch instead.

The refactoring is clean and focused, with no behavioral changes beyond eliminating the potential double-free scenario. The commit message clearly explains the technical rationale, and the diff shows straightforward mechanical conversions at both interface and implementation levels. This appears ready for merging as part of the overall strbuf cleanup effort.
