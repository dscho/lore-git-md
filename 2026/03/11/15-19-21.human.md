This is part 2/4 of a series converting callers of `start_command()` to use the new `repo_start_command()` variant as part of the ongoing `the_repository` removal effort. The patch updates five locations where callers already have repository context available and don't rely on the global `the_repository` variable.

The changes are mechanical replacements of `start_command()` with `repo_start_command()`, passing the local repository pointer that was already available at each call site. The affected subsystems are:
- `difftool` (two call sites)
- object database alternates handling
- pager setup
- promisor pack repacking
- send-pack protocol operations

This follows the pattern established in part 1 of the series, continuing the systematic elimination of implicit global state. The patch appears straightforward and well-scoped, touching only callers that were already prepared for this change by having their repository context available. No behavior changes are introduced beyond the explicit repository passing.
