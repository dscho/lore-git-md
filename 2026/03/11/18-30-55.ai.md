This is a feature proposal for `git cherry-pick` to add a `--show-current-patch` option, mirroring existing functionality in `git rebase`. The patch suggests adding this flag to help users understand which commit caused a conflict during a range cherry-pick operation.

The proposed behavior would show the patch being applied when a conflict occurs, similar to how `git rebase --show-current-patch` works. Currently, users must manually inspect `.git/CHERRY_PICK_HEAD` and run `git show` on it, which is less discoverable. The new flag would provide direct access to this information when a cherry-pick is in progress, and error out cleanly when no cherry-pick operation is active.

The motivation is clear: this would help users debug conflicts during range cherry-picks by showing exactly which commit's changes are being applied when a conflict occurs. The proposal is well-motivated and appears to be a straightforward addition that would provide feature parity with the rebase command. The implementation would likely be relatively simple since it can leverage existing mechanisms from the rebase implementation.
