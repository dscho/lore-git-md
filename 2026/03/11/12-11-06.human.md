This is a small refactoring patch in the `imap-send` subsystem, part of a 4-patch series (this being patch 3/4). The change removes two redundant string length checks when verifying SSL certificate hostnames in the IMAP send code.

The patch removes checks that were verifying internal consistency of ASN1_STRING structures, which the author argues are now unnecessary since the code uses proper OpenSSL API accessors rather than direct field access. The change simplifies the hostname verification logic while maintaining the same security checks - the actual hostname matching (`host_matches()`) remains in place.

The change looks straightforward and focused - it touches only the certificate verification path in `imap-send.c`, removing what appears to be legacy validation that OpenSSL now handles internally. The commit message could be more detailed about why these checks are redundant now (what changed in the API usage), but the change itself seems reasonable for this security-sensitive code path.
