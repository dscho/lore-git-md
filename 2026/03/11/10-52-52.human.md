This is a bugfix for the promisor-remote subsystem that prevents recursive lazy-fetching during index-pack operations. The patch addresses a real-world issue where a production system wrote 276GB of promisor packs in 90 minutes due to runaway recursive fetches.

The core problem occurs when a child `git fetch` process encounters a REF_DELTA against a missing base object, which can trigger another lazy fetch, creating an unbounded chain. The fix propagates `GIT_NO_LAZY_FETCH=1` into child fetch processes to prevent this recursion.

Patrick Steinhardt raises some important points in his review. While acknowledging the need for client-side protection, he questions whether this indicates a server-side bug, as proper servers shouldn't send REF_DELTAs against missing objects in the first place. He also suggests the test could be improved to demonstrate the actual failure behavior rather than just checking for the environment variable.

The discussion highlights an interesting tension between defensive programming (protecting against invalid server behavior) and proper protocol adherence (expecting servers to follow specs). The patch provides valuable protection against pathological cases, but the conversation suggests there may be deeper issues to investigate regarding server behavior.
