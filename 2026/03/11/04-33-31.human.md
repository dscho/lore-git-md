Documentation patch finalizing the handling of bare `-U` diff option behavior.

This patch series has settled on documenting the existing behavior where `-U` without a number is accepted (defaulting to 3 lines of context like `-p`) as a legacy compatibility feature, while making clear that `--unified=<n>` remains the canonical form requiring an explicit number. The current email confirms that Tian Yuchen's v3 patch incorporated Oswald Buddenhagen's suggested wording improvements, framing the bare `-U` behavior as "a historical accident" and clearly distinguishing it from the proper `--unified=<n>` form.

Jean-Noël Avila raises a new but minor documentation style question about whether to use `--unified[=<n>]` syntax in the docs to indicate optional parameters, even though the implementation requires the number for the long option. This is purely a documentation convention question that doesn't affect the already-settled behavior. The core patch is ready for merging with Junio's approval, having addressed the original inconsistency while preserving backward compatibility. Any remaining documentation refinements can be handled separately.
