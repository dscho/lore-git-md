This is a discussion about adding a `--show-current-patch` option to `git cherry-pick`, mirroring existing functionality in `git rebase`. The original proposal from Florian Best suggested this would help users understand conflicts during range cherry-picks by showing the current patch being applied.

Phillip Wood responds with a thoughtful counterpoint, noting that users can already inspect the current cherry-pick commit using `git show CHERRY_PICK_HEAD`, which offers more flexibility than a fixed `--show-current-patch` output. He suggests the existing solution may be sufficient if better documented, rather than adding new command-line surface area.

The exchange highlights a common Git design tension between discoverability (adding explicit commands for common operations) and flexibility (reusing existing plumbing in creative ways). Phillip's response carries weight of experience - as a frequent contributor to the sequencer and interactive rebase code, he's well-positioned to assess whether this change would meaningfully improve the user experience or just add redundant functionality. The thread remains open for further discussion about whether documentation improvements would suffice or if the new flag is truly warranted.
