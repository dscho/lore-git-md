This is the fourth patch in a series adding subcommand autocorrection to Git's parse-options API. The patch enables the new autocorrection feature for `git remote` and `git notes` by adding the `PARSE_OPT_SUBCOMMAND_AUTOCORR` flag to their parse-options calls.

The changes simplify both commands by removing their manual subcommand error handling - when an unknown subcommand is provided, the parse-options machinery will now automatically handle autocorrection based on the user's configured `help.autocorrect` setting. The patch notes this is safe for these commands because they either resolve to a single subcommand or take no subcommand at all.

The implementation adds a new flag bit to `parse-options.h` and modifies the subcommand handling logic in `parse-options.c` to only bypass autocorrection when explicitly disabled. The diff shows clean removal of redundant error handling code from both builtin commands while maintaining all existing functionality.

This continues the series' pattern of well-structured changes that build logically on the preparatory refactoring in earlier patches. The choice to start with `remote` and `notes` makes sense as they represent straightforward cases for the new feature.
