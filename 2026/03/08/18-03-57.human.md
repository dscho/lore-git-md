This is a refactoring patch series that continues Junio Hamano's earlier work to reduce unnecessary `strbuf` usage in the Git codebase. The series contains two independent changes:

1. The first patch modifies `write_worktree_linking_files()` to take plain string parameters instead of `strbuf` structs by value, following the same pattern Junio established in `builtin/clean.c`. This avoids unnecessary copying of `strbuf` structures when simple strings would suffice.

2. The second patch rewrites `parse_combine_filter()` to avoid using `strbuf_split_str()` for splitting filter specs, since the function doesn't actually need the full `strbuf` functionality for the temporary pieces it processes. The new version uses simpler string handling.

The changes are mechanical and focused - they don't introduce new functionality but make the code more efficient by removing unnecessary string buffer operations. Both patches follow established patterns from previous cleanups, suggesting they should be uncontroversial. The series touches worktree and object filtering code, but the changes are localized to internal implementation details rather than affecting user-facing behavior.
