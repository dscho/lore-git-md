This is a refactoring patch that continues Junio Hamano's earlier work to reduce unnecessary strbuf usage in Git's internals. The change focuses on the worktree linking file handling code.

The patch modifies `write_worktree_linking_files()` to take plain C strings (`const char*`) instead of `strbuf` structs by value. The author explains that passing strbuf by value is potentially dangerous since the caller and callee share the underlying buffer storage, which could lead to dangling pointers if reallocation occurs. Since the function only needs the string contents and not the strbuf machinery, the simpler string interface is more appropriate.

The change is mechanical but well-motivated, touching the worktree.c implementation and its callers in builtin/worktree.c. The patch follows established patterns from Junio's previous cleanups and appears to be a straightforward improvement with no behavior change. As the first in a 2-part series, it sets up a similar strbuf reduction for object filtering code in the next patch.
