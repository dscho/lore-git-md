This is a refactoring patch in Jiamu Sun's series adding subcommand autocorrection support to Git's parse-options API. The patch moves autocorrection logic from help.c into new autocorrect.{c,h} files, creating a cleaner separation of concerns.

The key changes:
- Introduces a new `struct autocorr` with explicit mode enum (IMMEDIATE/PROMPT/DELAY/HINTONLY/NEVER) and delay field
- Moves config parsing, TTY validation, and prompt handling into autocorrect.c
- Simplifies help.c by delegating autocorrection behavior to the new module
- Maintains all existing functionality while making the state handling more explicit

The refactoring prepares for later patches in the series that will extend autocorrection to subcommands. The implementation remains functionally equivalent but is now better organized for reuse. The patch follows Git's style conventions and includes thorough documentation of the new autocorrect API.

Files touched:
- Makefile (adds autocorrect.o)
- New autocorrect.c and autocorrect.h
- help.c (simplified by removing autocorrection logic)

This is a well-structured preparatory change that cleanly separates concerns without altering behavior. The modularization will make it easier to extend autocorrection support in subsequent patches.
