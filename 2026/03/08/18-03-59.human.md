Refactoring patch to simplify string handling in object filtering code. This is the second part of a series that follows Junio Hamano's pattern of replacing unnecessary strbuf usage with simpler string operations.

The patch modifies `parse_combine_filter()` in the list-objects-filter-options to avoid using `strbuf_split_str()` for splitting combine filter specs. Instead, it walks the input string directly with `strchr()`, copying sub-specs into temporary buffers only when needed. This eliminates the overhead of allocating an array of strbufs when the code only needs to read the string content.

The change maintains identical functionality while being more direct - the helpers `has_reserved_character()` and `parse_combine_subfilter()` are updated to take const char* instead of strbuf*. The patch appears well-contained, touching only the filter parsing logic while following established patterns from prior cleanups. It's a straightforward optimization that should be uncontroversial.
