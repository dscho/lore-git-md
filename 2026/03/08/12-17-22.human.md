This is the second patch in a series introducing subcommand autocorrection to Git's parse-options API. The patch refactors Git's existing command autocorrection logic from help.c into new autocorrect.{c,h} files, making the code more modular and maintainable.

The changes introduce a proper `struct autocorr` with an explicit mode enum (HINTONLY, NEVER, PROMPT, IMMEDIATELY, DELAY) to replace the previous integer-based approach. The refactoring moves all autocorrection configuration parsing, TTY validation, and prompt handling into the new autocorrect.c file while keeping the same behavior.

Key improvements in this patch:
- Better separation of concerns by moving autocorrection logic to dedicated files
- More explicit state handling through the new struct and enum
- Cleaner interface between the help system and autocorrection functionality
- Maintains all existing behavior including the various autocorrection modes (immediate, prompt, delay)

The patch is purely preparatory - it doesn't change any user-facing behavior yet. It sets up the infrastructure that will be used in later patches to enable subcommand autocorrection for commands like `git remote` and `git notes`. The commit message is clear and the changes appear well-contained and focused.
