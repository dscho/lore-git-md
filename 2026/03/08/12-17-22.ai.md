This is the second patch in a series introducing subcommand autocorrection support to Git's parse-options API. The patch refactors the existing command autocorrection logic from help.c into new autocorrect.{c,h} files, creating a cleaner separation of concerns.

The key changes:
- Moves autocorrection configuration parsing and handling into new autocorrect.c
- Introduces a structured `autocorr` type with explicit mode enum (HINTONLY, NEVER, PROMPT, IMMEDIATELY, DELAY)
- Separates alias resolution from autocorrection logic
- Keeps the same behavior but with clearer state management

The refactoring prepares for subsequent patches that will add subcommand-specific autocorrection. The commit message clearly explains this is a preparatory step with no behavior changes. The patch follows Git's style guidelines and includes appropriate header files and Makefile updates.

Technical details for future reference:
- New files: autocorrect.c, autocorrect.h
- Exported functions: autocorr_resolve(), autocorr_prompt_or_delay()
- Configuration handling moved from help.c to autocorrect.c
- Maintains all existing autocorrection behaviors (prompt, delay, immediate)
