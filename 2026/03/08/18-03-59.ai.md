This is the second patch in a refactoring series aimed at reducing unnecessary strbuf usage, focusing on the object filtering code. The change modifies `parse_combine_filter()` in `list-objects-filter-options.c` to avoid using `strbuf_split_str()` for splitting combine filter specs.

The patch replaces the strbuf-based splitting with direct string manipulation using `strchr()` and `xmemdupz()`. The key improvements are:
1. Eliminates the allocation of an array of strbufs just to process sub-filters sequentially
2. Changes helper functions `has_reserved_character()` and `parse_combine_subfilter()` to take `const char*` instead of `struct strbuf*`
3. Maintains the same functionality while being more direct about string ownership

The change follows the same pattern as the first patch in the series (which modified worktree linking code) by removing strbuf usage where simpler string handling suffices. The author notes this continues Junio Hamano's earlier cleanup work in builtin/clean.c.
