This is the first patch in a series adding subcommand autocorrection support to Git's parse-options API. The patch refactors subcommand handling in parse-options.c by extracting the logic into a new `handle_subcommand()` helper function and simplifying the return value from `parse_subcommand()` to a basic success/failure status.

The changes make the code more maintainable by:
- Removing a switch statement over impossible parse_opt_result values
- Making the non-option path clearer to follow
- Keeping the same functionality while improving code organization

This is a clean refactoring that doesn't change behavior, just structure. It's part of a well-structured series that has already addressed maintainer feedback in v2 by clarifying documentation about the new autocorrection feature. The implementation appears solid with thorough test coverage in later patches.
