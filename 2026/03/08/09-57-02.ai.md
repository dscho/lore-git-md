This is a bugfix patch targeting the `git history reword` command, part of the ongoing effort to improve code safety and prevent undefined behavior. 

René Scharfe identifies a potential memory corruption issue in the `cmd_history_reword()` function where an uninitialized `rev_info` struct could be passed to `release_revisions()` if argument validation fails. The fix is straightforward - initialize the struct to zero at declaration time. This ensures safe cleanup even in error paths.

The patch is minimal (just one line changed) and clearly motivated, addressing a real issue that could lead to crashes or undefined behavior. As with most of René's contributions, it's a precise, no-nonsense fix that improves code hygiene without changing functionality. The change is contained to the history command implementation and doesn't affect other subsystems.

For future reference in this thread, the key elements are:
- File modified: `builtin/history.c`
- Function: `cmd_history_reword()`
- Structure affected: `struct rev_info` initialization
- Potential issue: uninitialized memory access during cleanup
- Fix method: zero-initialize the struct at declaration
- Related command: `git history reword` argument validation path
