This is part 2 of Jiamu Sun's series adding subcommand autocorrection support to Git's parse-options API. The patch refactors the existing command autocorrection logic from help.c into new autocorrect.{c,h} files, creating a cleaner separation of concerns.

The changes introduce a proper `struct autocorr` with explicit mode enum (IMMEDIATE/PROMPT/DELAY/HINTONLY/NEVER) and separate delay field, moving all configuration parsing and TTY validation into the new module. The implementation maintains all existing behavior while making the state handling more explicit and easier to maintain.

Key technical details:
- New autocorrect.c/h files encapsulate all autocorrection logic
- Config parsing and mode resolution moved to `autocorr_resolve()`
- Prompt/delay behavior extracted to `autocorr_prompt_or_delay()`
- help.c simplified by ~86 lines while maintaining identical functionality
- Existing test coverage remains valid as behavior is unchanged

The patch is a clean refactoring that sets up the infrastructure needed for the series' later patches that will add subcommand autocorrection. It follows Git's typical pattern of extracting reusable components into separate modules. The changes are well-contained and the commit message clearly explains the motivation and implementation.
