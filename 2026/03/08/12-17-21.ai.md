This is the first patch in a series introducing subcommand autocorrection support to Git's parse-options API. The patch refactors the subcommand handling logic from parse_options_step() into a new handle_subcommand() helper function and simplifies parse_subcommand() to return a basic success/failure status rather than an enum.

The changes are primarily code organization improvements that:
1. Extract subcommand parsing into a dedicated function
2. Replace the switch statement over parse_opt_result values with a simpler boolean return
3. Make the control flow in parse_options_step() clearer by reducing nesting

The patch touches only parse-options.c and appears to be a straightforward refactoring with no behavior changes. The commit message explains the motivation well - making the code easier to follow and maintain by separating concerns. This looks like solid preparatory work for the subsequent patches that will add autocorrection functionality.
