This is a const-correctness documentation patch for the patch-id subsystem, following up on earlier discussion about a design conflict between type safety and lazy initialization.

Tian Yuchen addresses Junio Hamano's critique of their initial approach by documenting the intentional const-cast in `patch_id_neq()`. The patch removes an 8-year-old NEEDSWORK comment and replaces it with an explanation of why the function must cast away constness - the hashmap API requires const parameters, but the lazy evaluation of patch IDs requires modifying the objects. The commit message acknowledges that pre-computing all patch IDs for true const-correctness would be too expensive performance-wise.

The patch is narrowly focused and well-explained, showing responsiveness to Junio's earlier feedback. It represents the pragmatic solution path (documenting the trade-off) rather than the more invasive architectural restructuring that was also under consideration. This appears to be the likely resolution to the thread, as it remains technically honest about the const-cast while making the design choice explicit for future maintainers.
