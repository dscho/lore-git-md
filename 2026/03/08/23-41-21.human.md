This is a bugfix for the `git quiltimport` shell script, addressing edge cases in patch subject handling. Sasha Levin responds to Ben Knoble's review of their initial patch, which fixed two issues: using `printf` instead of `echo` to prevent backslash interpretation in patch subjects (which could produce invalid NUL bytes rejected by `git commit-tree`), and properly handling paths with spaces by quoting `$tmp_dir`.

The discussion reveals this was triggered by a real-world case where a Linux kernel patch with "\0" in its subject caused the import to fail under dash. Sasha agrees to split the path-quoting changes into a separate cleanup patch and considers Ben's suggestion to use POSIX parameter expansion (${patch_name%.patch}) instead of `sed` for removing `.patch` suffixes. The changes are focused on script robustness rather than user-facing behavior, with no major disagreements - just opportunities for further small improvements. Sasha plans to send a v2 incorporating these refinements.
