This is a refactoring patch series that continues Junio Hamano's earlier work to reduce unnecessary use of strbuf_split*() functions and strbuf-by-value parameters. The series consists of two cleanups:

1. The first patch modifies `write_worktree_linking_files()` to take plain string parameters instead of strbuf structs by value, following the same pattern Junio established in builtin/clean.c. This affects worktree.c and its callers.

2. The second patch rewrites `parse_combine_filter()` in list-objects-filter-options.c to avoid using strbuf_split_str() for processing combine: filter specs. The current implementation splits the entire string into strbufs up front, but the function only needs to process one sub-spec at a time and doesn't use strbuf editing capabilities on the pieces.

The changes are mechanical improvements that don't affect functionality but make the code more straightforward and efficient by removing unnecessary string buffer allocations and copies. The patches touch core worktree functionality and the object filtering system, but the modifications are low-risk since they don't change behavior - they just use simpler, more direct ways to achieve the same results.

The series appears well-targeted to address the specific issues Junio identified in his earlier work, and the changes follow established patterns for this type of cleanup. The commit messages clearly explain the rationale and connect the changes to prior work they're building upon.
