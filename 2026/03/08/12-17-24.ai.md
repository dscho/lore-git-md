This is patch 4/5 in a series adding subcommand autocorrection to Git's parse-options API. The patch enables the new autocorrection feature for `git remote` and `git notes` by adding the PARSE_OPT_SUBCOMMAND_AUTOCORR flag to their parse_options() calls.

The key changes are:
- Introduces PARSE_OPT_SUBCOMMAND_AUTOCORR flag in parse-options.h
- Modifies parse-options.c to only skip autocorrection when SUBCOMMAND_OPTIONAL is set without SUBCOMMAND_AUTOCORR
- Simplifies builtin/notes.c and builtin/remote.c by removing their manual subcommand error handling since the parse-options machinery now handles it
- Maintains the same behavior where these commands resolve to a default subcommand (list/show_all) when no subcommand is given

The patch builds on the previous refactoring and autocorrection implementation, applying it to real commands. The choice of `remote` and `notes` as initial targets makes sense since they have simple subcommand structures where any unknown argument must be a mistyped subcommand. The implementation cleanly removes duplicate error handling code from the builtins while preserving all existing functionality.
