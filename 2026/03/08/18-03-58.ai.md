Refactoring patch to eliminate unnecessary strbuf usage in worktree linking code.

This is the first of a two-patch series continuing Junio Hamano's earlier strbuf cleanup work. The change modifies `write_worktree_linking_files()` to take plain string parameters instead of strbuf structs, since the function only needs the string contents and not the strbuf machinery. The author notes that passing strbuf by value is potentially dangerous due to shared storage and reallocation risks.

The patch updates all callers to pass `.buf` from their strbufs and makes corresponding changes to the function signature in both implementation and header. The changes are mechanical but improve safety by making the string ownership clearer. This follows established patterns from Junio's previous cleanups in builtin/clean.c.

Key technical details:
- Changes function signature in worktree.h and worktree.c
- Updates 5 call sites in worktree.c and 1 in builtin/worktree.c
- Maintains identical functionality while using simpler string handling
- Part of ongoing effort to reduce unnecessary strbuf usage

The patch appears well-contained and follows the project's established cleanup patterns. As the first in a series, it sets up for the second patch which will address similar strbuf usage in the object filtering code.
