This is a review comment from maintainer Junio C Hamano on patch 2/5 of Jiamu Sun's subcommand autocorrection series. The patch attempts to refactor autocorrection handling into a new autocorrect.{c,h} module, but Junio identifies several issues that need addressing before it can be accepted.

Junio notes the patch combines multiple changes that should be separated: (1) pure code movement to create the new module, (2) style changes (converting if/return to if/else if), (3) semantic changes (renaming AUTOCORRECT_SHOW to AUTOCORR_HINTONLY), and (4) enum renaming (AUTOCORRECT_* to AUTOCORR_*). He requests the author split this into at least two patches - one for the pure refactoring with no behavior changes, followed by patches for the other changes.

The review suggests the current form makes it harder to review the actual changes, as the meaningful modifications are buried in what appears to be a simple code movement. This is a common maintainer request to keep patches focused and reviewable. The author will need to restructure the series to address these concerns before resubmitting.
