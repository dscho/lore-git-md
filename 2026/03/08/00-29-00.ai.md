This is a follow-up discussion in the ongoing thread about path format handling in `git repo-info`. Lucas Seiki Oshiro responds to brian m. carlson's suggestion about supporting both absolute and relative path formats, proposing a syntax for accessing both variants through virtual fields.

The email suggests using a dot notation (`path.git-dir.absolute` and `path.git-dir.relative`) to explicitly request path formats, building on Ayush Jha's earlier proposal. This approach would allow users to retrieve both formats in a single command without needing to toggle a global `--path-format` flag. Lucas indicates they're stepping back from driving this particular decision, noting that potential GSoC contributors may take up the implementation.

The discussion continues to explore the tradeoffs between global format flags versus per-field format specification, with this email leaning toward the virtual fields approach that Jayatheerth K recently demonstrated could handle mixed formats through local state management. The thread appears to reached technical consensus that both approaches can work, leaving the final design choice to Junio Hamano's maintainer preference.
