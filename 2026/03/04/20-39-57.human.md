This is part 4 of Patrick Steinhardt's 17-part series refactoring Git's object database (ODB) subsystem to enable pluggable storage backends. The patch moves repository working directory reparenting logic from the ODB layer into the specific "files" backend and temporary object directory subsystems.

Justin Tobler provides a detailed review, noting the patch makes the reparenting behavior more localized to the subsystems that actually need it. He questions whether storing paths in the base ODB source structure is temporary (suggesting a NEEDSWORK comment) and confirms the logic for temporary directories matches the existing behavior. The changes eliminate the need for separate unapply/reapply functions since each source now handles its own path updates through registered callbacks.

The review is thorough and technical, focusing on implementation details of how paths are managed during working directory changes. This is a typical intermediate step in the larger ODB abstraction effort - moving functionality to the right layer while maintaining existing behavior. Justin's comments suggest the architecture is sound but could benefit from clearer documentation of transitional states.
