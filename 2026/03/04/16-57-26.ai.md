This is a technical discussion about the object database (ODB) refactoring effort, specifically focusing on patch 2/17 in Patrick Steinhardt's series to enable pluggable storage backends. Justin Tobler is reviewing the patch that introduces a new "files" source structure to encapsulate loose objects and packfile storage.

The patch moves existing loose object and packfile store structures into a new `struct odb_source_files` that will eventually contain the base `struct odb_source` (rather than the current arrangement where the files source is contained within the base source). Justin notes this is primarily a structural reorganization at this stage, with most changes being mechanical updates to accommodate the new hierarchy.

Key observations from Justin's review:
1. The `files` field in `struct odb_source` currently holds a direct reference to the files backend, though this relationship will be inverted in subsequent patches
2. He questions whether to preserve an old comment about packfile access being restricted to specific files
3. He anticipates future changes where the base ODB source will need to be cast to concrete types rather than directly referencing the files implementation

The discussion reflects careful attention to header organization and the transitional state of this architectural change, with Justin identifying details that may need refinement even as the overall approach has been accepted. This is part of the systematic conversion of Git's object storage layer to support pluggable backends while maintaining the existing files-based implementation.
