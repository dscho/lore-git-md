This is a process management patch in the fsmonitor daemon series, adding a timeout to the daemon stop command. It's part of the larger effort to bring Linux fsmonitor support to parity with existing Windows and macOS implementations.

The patch addresses a specific issue where the `fsmonitor--daemon stop` command could hang indefinitely if the daemon fails to shut down properly. Currently, the command polls in a loop waiting for the daemon to exit after sending a quit command, with no timeout mechanism. The change introduces a 30-second timeout (configurable via `max_wait_ms`) that will return an error if the daemon doesn't exit within that window.

Key technical details:
- Adds timeout tracking with `max_wait_ms` (30 seconds) and `elapsed_ms` counters
- Maintains the existing 50ms polling interval but now tracks cumulative time
- Returns an error message if timeout is reached, preserving the trace2 region markers
- The change is localized to the client-side stop command logic in `builtin/fsmonitor--daemon.c`

This is the 10th patch in the 12-part v8 series, building on previous work that established the fsmonitor IPC protocol and process management infrastructure. The change is straightforward and well-contained, with clear motivation (preventing indefinite hangs) and a reasonable default timeout value. It follows the pattern of robust process management seen elsewhere in Git's codebase.
