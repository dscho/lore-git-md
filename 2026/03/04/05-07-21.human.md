This is a feature patch proposing URL-based configuration for partial clone filters, now narrowed to clone operations only as the thread has progressed. Patrick Steinhardt responds to Junio Hamano's question about URL matching granularity by suggesting it should follow the same pattern as Git's existing `http.<url>.*` configuration.

The proposal would allow setting default object filters via `clone.<url>.defaultObjectFilter` with three levels of specificity: domain-wide (e.g. "github.com"), namespace (e.g. "gitlab.com/example"), or per-repository (e.g. "gitlab.com/example/project.git"). This builds on the thread's earlier consensus to limit the feature to clone operations only, avoiding the complexity of affecting subsequent fetches.

The implementation appears straightforward, leveraging Git's existing URL matching infrastructure. Patrick's response suggests this is the final design consideration before the feature can be finalized, with Junio's earlier email having already endorsed the clone-only scope and URL-based configuration approach. The patch represents a practical compromise from the original broader proposal, focusing on the safest and most maintainable subset of functionality.
