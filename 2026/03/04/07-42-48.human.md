This is a platform compatibility patch adding Windows support for `pthread_cond_timedwait()` as part of the fsmonitor daemon effort. The patch implements the function using Windows' `SleepConditionVariableCS()` with proper timeout conversion from `timespec` to milliseconds.

Patrick Steinhardt points out two issues in his review:
1. The implementation should return `ETIMEDOUT` immediately when the timeout has already passed (matching POSIX behavior), rather than treating it as a zero timeout.
2. The error handling could be cleaner by extending the existing `err_win_to_posix()` helper rather than special-casing `ERROR_TIMEOUT`.

The patch is part of a larger series (v7 03/10) introducing Linux fsmonitor support with inotify. This particular piece provides Windows compatibility for the synchronization mechanism used in the fsmonitor IPC protocol. The review feedback suggests straightforward improvements to better match POSIX semantics and maintain consistency with the codebase's existing error handling patterns.
