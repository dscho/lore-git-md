Feature: Configurable branch comparisons in `git status` via `status.compareBranches`

This is the second and final patch in Harald Nordgren's series to make branch comparisons in `git status` configurable. After 31 iterations over two months (plus prior work from 2016-2018), the feature has now been merged to 'next' following thorough technical review.

The patch introduces a new `status.compareBranches` configuration option that accepts a space-separated list of branch specifiers (`@{upstream}` and/or `@{push}`) to show in status output. When unset, it maintains backward compatibility by defaulting to `@{upstream}` behavior. The implementation handles deduplication when upstream and push references resolve to the same branch, preserves config order in output, and provides context-aware advice messages (pull advice only for upstream, push advice only for push branches).

Key technical aspects include:
- New `resolve_compare_branch()` helper in remote.c to process specifiers
- String list processing with strset deduplication
- Flags (ENABLE_ADVICE_PULL/PUSH/DIVERGENCE) to control advice context
- 354 lines of new test coverage in t6040-tracking-info.sh covering:
  * Various ahead/behind/diverged states
  * Triangular workflows
  * --no-ahead-behind output
  * Single-branch configurations
  * Duplicate branch handling
  * Remapped refspec cases

The implementation addresses all review feedback from Junio Hamano and Jeff King, including test cleanup, documentation of deduplication behavior, and explicit testing of edge cases. This represents the culmination of a persistent contribution effort that followed Git's mailing list protocols while iterating to address all technical concerns.
