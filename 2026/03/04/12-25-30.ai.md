This is the first of two patches in the final version (v31) of Harald Nordgren's series to make branch comparisons in `git status` configurable. The patch is a pure refactoring that prepares for the new feature by extracting the branch comparison formatting logic from `format_tracking_info()` into a new `format_branch_comparison()` helper function.

The changes are mechanical and maintain all existing behavior - this is just moving code around to make the next patch's addition of push-branch comparisons cleaner. The refactoring:
- Splits out the message formatting for all branch states (up-to-date, ahead, behind, diverged) into the new function
- Keeps the upstream-is-gone case in the original function since it's a special case
- Preserves all existing advice messages and pluralization handling
- Maintains the same function signatures and return values

This preparatory work has already been thoroughly reviewed through 30 previous iterations, with all technical concerns addressed. The patch is now in its final form, having incorporated feedback from Junio Hamano and Jeff King about test organization and style. The actual feature addition (configurable @{push} comparisons) comes in the second patch of the series.
