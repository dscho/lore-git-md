This is a platform compatibility patch adding Windows support for `pthread_cond_timedwait()` as part of the fsmonitor Linux inotify implementation. The patch implements the POSIX function using Windows' `SleepConditionVariableCS()` with proper timeout conversion from `timespec` to milliseconds.

Patrick Steinhardt points out two technical issues in his review:
1. The implementation should return `ETIMEDOUT` immediately when the timeout has already passed (current code just sets `timeout_ms=0`), matching POSIX spec behavior
2. The error handling could be cleaner by extending `err_win_to_posix()` rather than special-casing `ERROR_TIMEOUT`

The change is part of a larger series (v7 03/10) enabling fsmonitor on Linux via inotify, where this Windows compatibility layer allows the same synchronization code to work across platforms. The review focuses narrowly on Windows-specific POSIX emulation details rather than the broader fsmonitor functionality.

This appears to be one of the final polish items in the otherwise mature fsmonitor series, which has already addressed numerous technical concerns across previous iterations. The feedback suggests straightforward fixes to better match POSIX semantics in the Windows compatibility layer.
