This thread focuses on improving test reliability by fixing subtle patterns where `git rev-parse` failures could be silently ignored in test scripts. Francesco Paparatto's initial patch modified `t/t3310-notes-merge-manual-resolve.sh` to store `rev-parse` outputs in variables before comparison, following Junio C Hamano's suggestion. The changes touched 18 lines across 10 test cases in a mechanical but important improvement.

Eric Sunshine, one of Git's most active reviewers, has now weighed in with constructive feedback. While agreeing with the goal of surfacing failures, he suggests two key improvements: using `test_cmp` with pre-stored expected values (which shows both expected/actual output on failure) and the specialized `test_cmp_rev` helper for revision comparisons. These changes would make test failures more developer-friendly while maintaining the original reliability improvements. Given Eric's reputation for thorough reviews and the alignment with test modernization efforts, we can expect Francesco to incorporate these suggestions in a v2 patch.
