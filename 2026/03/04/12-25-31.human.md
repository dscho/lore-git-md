Feature: Configurable branch comparisons in `git status` output

This is the second and final patch in Harald Nordgren's series to make branch comparisons in `git status` configurable. After 31 iterations over two months (plus earlier work from 2016-2018), the feature has now been merged to 'next' following thorough technical review.

The patch introduces a new `status.compareBranches` configuration option that lets users specify which branches to compare against in `git status` output. The supported values are `@{upstream}` (the current branch's upstream tracking branch) and `@{push}` (its push destination). When unset, it defaults to `@{upstream}` for backward compatibility.

The implementation handles triangular workflows where upstream and push branches differ, showing comparisons against both with appropriate context-aware advice messages.
- "git pull" advice appears only for upstream comparisons
- "git push" advice appears only for push comparisons
- Divergence advice appears only for upstream comparisons

The configuration preserves order and deduplicates identical refs. For example, setting `compareBranches = @{upstream} @{push}` will show both comparisons when they differ, but only one when they resolve to the same branch.

The patch includes extensive test coverage (354 new test lines) verifying:
- Various ahead/behind/diverged states
- Triangular workflows
- --no-ahead-behind output
- Single-branch configurations
- Duplicate branch handling
- Remapped push refspecs

This represents the culmination of a persistent contribution effort that followed all Git mailing list protocols and addressed all review feedback before merging. The feature is now fully documented and tested, providing useful flexibility for users with complex workflows while maintaining backward compatibility.
