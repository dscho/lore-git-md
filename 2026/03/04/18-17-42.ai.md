This is a bugfix patch addressing a memory leak in the fsmonitor daemon's cookie tracking system, part of the ongoing Linux fsmonitor implementation effort.

The patch fixes an oversight in the cleanup of the `state.cookies` hashmap where cookie names (allocated via `strbuf_detach()`) were not being freed during daemon shutdown. The v8 version now properly iterates through the hashmap to free each cookie's name before calling `hashmap_clear_and_free()`. This addresses Patrick Steinhardt's review comment from the previous version.

The change is focused and mechanical - it doesn't introduce new functionality but ensures proper resource cleanup in the fsmonitor daemon's cookie synchronization mechanism. The fix is part of a larger series (v8 02/12) that has been through multiple iterations with extensive review. The memory leak was one of several cleanup issues identified during the review process, and this patch represents the final resolution of that specific problem.

The patch demonstrates the careful attention to resource management required in long-running daemon processes, particularly around the inotify-based filesystem monitoring where cookie tracking is used to handle directory rename events. With this fix, the fsmonitor daemon's memory management appears to be in good shape, having addressed multiple leak scenarios identified through the v7 review cycle.
