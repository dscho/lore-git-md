This is a platform compatibility patch adding Windows support for pthread_cond_timedwait() as part of the fsmonitor daemon effort. The patch implements the POSIX-style condition variable wait with timeout for Windows, using the native Windows API SleepConditionVariableCS().

The implementation handles the Windows-to-POSIX error code conversion, specifically mapping WAIT_TIMEOUT to ETIMEDOUT to match POSIX behavior. In the v7 review, Patrick Steinhardt suggested extending the existing err_win_to_posix() function rather than handling the timeout case directly, but the author (Paul Tarjan) explains why that would be problematic - err_win_to_posix currently maps ERROR_TIMEOUT to EBUSY, which would break the expected POSIX semantics for this function.

This is a focused, well-justified change that completes the Windows compatibility layer needed for the fsmonitor daemon's cross-platform implementation. The discussion shows careful consideration of error handling semantics and backward compatibility concerns. The patch appears ready for inclusion, having been reviewed and updated through multiple iterations of the fsmonitor series.
