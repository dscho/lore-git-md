This is a technical discussion about process management in Git's fsmonitor daemon, part of the ongoing fsmonitor Linux inotify support effort. Patrick Steinhardt is reviewing Paul Tarjan's patch that addresses file descriptor inheritance and process group issues in the fsmonitor daemon.

The patch introduces two main changes: closing inherited file descriptors above stderr via a new `close_fd_above_stderr` flag in `struct child_process`, and calling `setsid()` when daemonizing to create a new session. These prevent the daemon from holding open unwanted descriptors and ensure it isn't tied to the parent's job control.

Patrick raises several points about the implementation:

2. Questions whether the 30-second timeout for daemon shutdown should be a separate commit
3. Notes an unrelated test timeout change that isn't mentioned in the commit message
4. Asks why process group handling changes are still needed if `setsid()` is called
5. Implies the patch ordering could be improved to avoid temporary test timeouts

The discussion reveals subtle process management considerations in the fsmonitor implementation, particularly around file descriptor inheritance and job control behavior across different shells.
