This is a bugfix for the promisor-remote subsystem that prevents runaway recursive lazy-fetching, which could previously cause excessive resource consumption (as seen in a production case that wrote 276GB of promisor packs in 90 minutes).

The patch addresses a recursive fetch scenario where a child `git fetch` process could trigger another lazy fetch when encountering a missing base object, creating an unbounded chain. The solution propagates `GIT_NO_LAZY_FETCH=1` into the child fetch's environment to prevent recursion while still allowing the initial lazy fetch to proceed.

Author Paul Tarjan has incorporated feedback from Junio Hamano, moving the test case into the existing `t0411-clone-from-partial.sh` file (rather than creating a new dedicated test file) and cleaning up some GitGitGadget-related formatting issues. The technical solution remains unchanged from v1 - a single-line environment variable propagation that Junio had already reviewed as sound.

This appears to be a well-motivated fix for a real production issue, with appropriate test coverage now integrated into the existing promisor test infrastructure. The patch is small and focused, addressing just the recursion problem while leaving the expected lazy-fetch behavior intact for the initial fetch case.
