This is a test patch in the ongoing fsmonitor Linux support series, which aims to bring filesystem monitoring capabilities to Linux matching the existing Windows and macOS implementations.

Patrick Steinhardt raises concerns about the reliability of the Linux inotify implementation in the test coverage. The patch adds a smoke test to detect when inotify watches succeed but events aren't delivered (as can happen with overlayfs on older kernels), skipping tests in such cases. Patrick questions whether this is the right approach, suggesting the team should first understand the root cause rather than working around it in tests. He references similar past issues on macOS where event loss was due to undersized buffers, and asks whether the Linux conditions have been properly investigated.

This exchange highlights an important quality consideration for the fsmonitor feature - while the tests are being made robust against flakiness, there may be underlying reliability issues that need addressing at the implementation level rather than just in the test harness. The discussion suggests the patch may need deeper investigation into inotify behavior before finalizing the test strategy.
