This is a review comment from Patrick Steinhardt on the fsmonitor Unix IPC path logic patch in Paul Tarjan's series. The patch renames the Darwin-specific IPC implementation to a more generic "unix" name in preparation for Linux support, but Patrick notes the commit message overstates the current deduplication since Linux support isn't fully implemented yet.

Patrick points out two specific issues with the patch:
1. The commit message claims "deduplication" is happening when it's really just preparatory renaming
2. The patch includes some unrelated "while-at-it" changes (like adding a BUG check for NULL worktree) that should be split into a separate commit

The context shows this is part of a larger effort to bring Linux fsmonitor support to parity with existing macOS/Windows implementations, with extensive prior discussion about race conditions, memory leaks, and platform-specific details. Patrick's review continues his pattern of thorough technical feedback on this series.
