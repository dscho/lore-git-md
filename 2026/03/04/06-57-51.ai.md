This is the final patch in a series converting Git's oidmap cleanup to use explicit, type-safe callbacks. Patrick Steinhardt responds to Junio C Hamano's review of Seyi Kuforiji's sequencer conversion patch, suggesting a refinement to the series' scope.

The patch being discussed converts the sequencer's string_entry oidmap to use the new `oidmap_clear_with_free()` API with a `free_string_entry()` helper. Junio noted that while the immediate benefit is minimal (since string entries are simple allocations), the conversion would ease future maintenance if entries grow more complex.

Patrick now proposes narrowing the series to only convert cases where the callback provides clear current value (rev-list and odb conversions), dropping the list-objects-filter and sequencer patches where the benefit is purely speculative. This would maintain the type-safety improvements where they matter most while avoiding unnecessary churn in simpler cases.

The thread's open questions remain:
1. Junio's earlier question about whether the new API needs to check `map->map.cmpfn`
2. Whether to keep all conversions (as originally proposed) or only those with immediate benefits (Patrick's new suggestion)

The series demonstrates clean, consistent conversions across multiple subsystems, with all patches reviewed and approved except for these two final discussion points. The technical approach using `container_of` for type safety has been validated, and the remaining questions are about scope rather than implementation.
