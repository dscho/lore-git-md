This is the second patch in Michael Montalbo's series addressing the interaction between `git log -L` (line-log) and pickaxe options (-G/-S/--find-object). The patch explicitly rejects using pickaxe options with `-L` since they currently have no effect on the line-log output, replacing previous tests that showed broken behavior with tests verifying the rejection.

The discussion with maintainer Junio Hamano reveals this is more of a stopgap solution - while it prevents crashes, the deeper architectural issue remains that line-log doesn't properly integrate with Git's diff machinery. Junio suggests line-log should use its own diff_options struct (similar to blame.c) rather than sharing the global one, which would provide a cleaner long-term solution.

Michael acknowledges this and indicates willingness to restructure the series accordingly. The current patch serves as a safety measure while the more fundamental fix is developed. As a first-time contributor, Michael is responsive to maintainer feedback and the thread shows productive collaboration toward a robust solution.

Key technical details:
- Modifies builtin/log.c to error on pickaxe+line-log combinations
- Updates t4211-line-log.sh tests to verify the error cases
- Preserves the crash fix from patch 1/2 (though may drop it per discussion)
- Sets stage for future work to properly integrate line-log with diff options

The patch is part of an ongoing effort to improve line-log's handling of diff options, with maintainer guidance steering it toward better architectural separation rather than just symptom-fixing.
