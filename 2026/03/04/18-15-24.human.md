This is a test patch (11/12) in a series adding Linux support for Git's filesystem monitoring (fsmonitor) using inotify. The patch focuses on adding comprehensive test coverage for the new Linux fsmonitor implementation.

The key additions are:

1. A new smoke test (`verify_fsmonitor_works`) that verifies the filesystem actually delivers inotify events, skipping all tests if event delivery fails (which can happen on some container/overlayfs setups).

2. A stress test for rapid nested directory creation that exercises race conditions in watch registration, particularly around EEXIST handling when IN_MASK_CREATE is used.

3. Several test infrastructure improvements:
   - Reduced daemon start timeout from 60 to 10 seconds for faster failure detection
   - Better process group handling for submodule tests
   - Fallback to reading /proc/$pid/stat when `ps` is unavailable
   - More robust process cleanup with stderr redirection
   - Job control (`set -m`) for submodule pull tests

The patch builds on previous work that implemented the core inotify functionality, with particular attention to edge cases identified during review. It's part of a well-tested series that has gone through multiple iterations addressing memory leaks, race conditions, and platform compatibility issues.

The tests demonstrate real-world concerns that emerged during development, like event delivery failures on certain filesystems and race conditions during rapid directory creation. The test infrastructure changes also make the tests more reliable across different environments (like CI systems without procps).

This appears to be a solid addition to the test coverage for the Linux fsmonitor implementation, addressing specific pain points that were found during development. The patch follows Git's testing conventions while adding some new helpers to handle platform differences.
