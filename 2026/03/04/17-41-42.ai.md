Bugfix for the promisor-remote subsystem preventing recursive lazy-fetching that could lead to runaway resource consumption. This addresses a production issue where missing delta bases triggered an unbounded chain of fetches, writing 276GB of promisor packs in 90 minutes.

The core fix is a one-line change in `promisor-remote.c` that propagates `GIT_NO_LAZY_FETCH=1` into the child fetch's environment, preventing index-pack from recursively triggering additional fetches when resolving missing REF_DELTA bases. The commit message provides thorough technical justification, noting that with noop negotiation, servers shouldn't send problematic deltas, and recursion wouldn't help if they do.

Junio Hamano reviews the patch and finds the technical solution sound, but provides meta-feedback about GitGitGadget usage patterns - specifically advising against including Cc trailers in commit messages and duplicating commit message content in the pull request description. He questions whether the new test needs its own dedicated file rather than being added to an existing promisor-related test script.

The patch includes two test cases in a new `t0412-promisor-no-lazy-fetch-recursion.sh` that verify: (1) only one fetch subprocess is spawned during lazy fetch, and (2) the child process environment contains the expected `GIT_NO_LAZY_FETCH=1` setting (checked via a reference-transaction hook). The test setup creates a partial clone scenario with missing object to trigger the lazy fetch behavior.
