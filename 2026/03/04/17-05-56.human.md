Feature enhancement for `git status` branch comparison configuration. This is a follow-up patch to the recently merged `status.compareBranches` feature, which allows configuring multiple branch comparisons in `git status` output (defaulting to just `@{upstream}`).

The patch adds documentation and tests clarifying how duplicate branch comparisons are handled when the same ref appears multiple times in the configuration. Specifically:
- Comparisons are shown in configuration order
- Duplicate refs are suppressed after their first occurrence
- The behavior is demonstrated through new test cases showing deduplication of `@{push}` and `@{upstream}` when they resolve to the same ref

This represents the final polish on a feature that has undergone extensive review over multiple years (31 patch iterations in the current effort, plus earlier work from 2016-2018). The implementation is robust with comprehensive test coverage of edge cases including remapped refspecs and triangular workflows. Junio Hamano has approved the changes and handled the final integration himself to avoid further roundtrips.
