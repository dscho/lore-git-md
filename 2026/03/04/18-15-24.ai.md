This is a test patch (11/12 in the series) adding Linux-specific tests for the fsmonitor daemon implementation. The patch focuses on verifying event delivery reliability and handling edge cases in the inotify-based filesystem monitoring.

The key additions are:

1. A new `verify_fsmonitor_works` smoke test that checks if the filesystem actually delivers inotify events, skipping the entire test suite if event delivery fails (common on some container/overlayfs setups). This prevents subsequent test failures when the fundamental mechanism isn't working.

2. A stress test for rapid nested directory creation that exercises race conditions between recursive directory scanning and queued inotify events, specifically handling EEXIST cases where duplicate directory creation events may arrive.

3. Test infrastructure improvements:
   - Reduced daemon start timeout from 60 to 10 seconds for faster failure
   - More robust process group handling in test helpers
   - Fallback to /proc/$pid/stat when `ps` is unavailable
   - Better cleanup of background processes
   - Job control for submodule tests to prevent hangs

The patch builds on the previous fsmonitor work that introduced Linux support via inotify, with special attention to real-world reliability issues seen in container environments. The tests specifically target edge cases identified during development, like event delivery failures and race conditions during rapid directory operations.

This appears to be a well-constructed test suite that complements the core implementation patches, focusing on practical reliability concerns rather than just happy-path scenarios. The test helpers show thoughtful consideration of portability across different Linux environments (including minimal CI setups).
