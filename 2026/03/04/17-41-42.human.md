This is a bugfix for the promisor-remote subsystem that prevents runaway recursive lazy-fetching, which could lead to excessive resource consumption (as seen in production where it caused 276GB of promisor packs to be written in 90 minutes).

The core issue occurs when `fetch_objects()` spawns a child `git fetch` for lazy fetching, and that child's `index-pack` encounters a REF_DELTA against a missing base object, triggering another lazy fetch recursively. The fix is straightforward - propagating `GIT_NO_LAZY_FETCH=1` into the child fetch's environment to prevent recursion while still allowing the initial lazy fetch to proceed.

Junio Hamano (the Git maintainer) has reviewed the patch and finds it technically sound, though he suggests some minor improvements to the submission process regarding GitGitGadget usage (specifically about where to place CC lines and avoiding duplication between commit message and pull request description). He also questions whether a new test file is necessary versus adding to an existing promisor-related test file.

The patch includes a new test that verifies both the environment variable propagation and that only one fetch subprocess is spawned. The fix builds on prior work addressing similar lazy-fetch recursion issues elsewhere in the codebase.
