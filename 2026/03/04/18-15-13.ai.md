This is the 8th iteration of a feature patch series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than performing full directory scans.

Key technical aspects of this version:
- Uses inotify with recursive directory watching via inotify_init1(O_NONBLOCK)
- Handles directory renames through IN_MOVED_FROM/TO event cookies
- Maintains watch descriptor <-> path mappings using hashmap
- Detects remote filesystems (NFS/SMB/vfat) via statfs()
- Falls back to $HOME/.git-fsmonitor-* for IPC socket when .git is remote
- Build configuration uses FSMONITOR_DAEMON_BACKEND=unix and FSMONITOR_OS_SETTINGS=unix
- Requires pthreads and Unix domain socket support
- Includes comprehensive test coverage with new tests for event delivery and race conditions

Changes since v7:
- Added patch 12 converting khash to strset in do_handle_client (Patrick's suggestion)
- Fixed redundant statfs() call in find_mount()
- Fixed CMake build configuration for FSMONITOR_* variables
- Fixed uninitialized strset on trivial response path

- Updated commit messages to describe all changes

The series appears well-tested and addresses previous review feedback, though Patrick Steinhardt has noted some remaining minor issues around memory management and Windows pthread compatibility that may need follow-up. The implementation looks production-ready and provides a significant performance improvement for Linux users.
