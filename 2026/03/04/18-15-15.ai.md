This is a bugfix patch addressing a memory leak in Git's fsmonitor daemon, part of the ongoing fsmonitor Linux support effort. The patch fixes a specific issue where the `state.cookies` hashmap and its allocated cookie names were not being properly freed during daemon shutdown.

The change adds cleanup code in the `fsmonitor_run_daemon()` function to:
1. Iterate through the hashmap entries to free each cookie name string
2. Clear and free the hashmap itself using `hashmap_clear_and_free()`

This is the second patch in an 8th iteration series (v8 02/12) that has seen extensive review and refinement. The fsmonitor implementation uses inotify on Linux to provide filesystem monitoring similar to existing macOS/Windows backends, with careful handling of directory watches, event synchronization, and platform-specific considerations.

The patch is straightforward and clearly motivated - it plugs a memory leak that was identified during the review process. The implementation follows Git's standard patterns for hashmap cleanup. While small, it's an important fix for the daemon's long-running operation. The change has been reviewed by Patrick Steinhardt and others in the context of the larger fsmonitor effort.
