This is a bugfix for the promisor-remote subsystem that prevents recursive lazy-fetching during index-pack operations. The issue occurs when a child `git fetch` process spawned by `fetch_objects()` encounters a REF_DELTA against a missing base object, which can trigger unbounded recursion with runaway resource consumption (as seen in production where 276GB of promisor packs were written in 90 minutes).

The fix propagates `GIT_NO_LAZY_FETCH=1` into the child fetch's process environment, preventing index-pack from recursively triggering additional lazy fetches when resolving missing bases. The technical solution was already approved in v1; this v2 iteration incorporates Junio's feedback by moving tests into existing infrastructure (`t0411-clone-from-partial.sh`) rather than creating a new test file, and removing redundant Cc trailers from the commit message.

The test verifies that the child fetch process has the environment variable set by using a reference-transaction hook to inspect the child's environment. The commit message provides clear justification that with noop negotiation, servers shouldn't send problematic deltas, and recursion wouldn't help if they do. This matches the fix pattern used in commit-graph.c (3a1ea94a49).

The patch is well-motivated by a real production issue and follows established patterns for similar fixes. The test coverage appears thorough for the specific behavior being modified. The changes since v1 are purely organizational (test location, commit message cleanup) rather than technical, suggesting the core solution is sound.
