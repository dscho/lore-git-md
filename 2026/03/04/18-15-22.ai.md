This is a process management patch in the fsmonitor daemon series, addressing file descriptor inheritance and process group issues in the daemon's background operation.

The patch focuses on two key improvements to the fsmonitor daemon's process handling:

1. **File descriptor cleanup**: Adds `close_fd_above_stderr` flag to child processes at both explicit (`fsmonitor--daemon start`) and implicit (client-triggered) spawn paths. This prevents the daemon from inheriting unnecessary file descriptors (like CI system pipes) that could cause parent processes to hang waiting for EOF. The implementation uses `sysconf(_SC_OPEN_MAX)` with a 4096 safety cap while preserving the child notifier fd.

2. **Process detachment**: On Unix systems, calls `setsid()` when daemon starts with `--detach` to create a new session and process group. This prevents the daemon from being tied to the spawning shell's process group, which could cause shells with job control to block on the daemon during foreground command waits.

The changes are platform-aware, maintaining Windows compatibility through the existing `FreeConsole()` call while adding Unix-specific session management. The patch also suppresses stdout/stderr on implicit spawns to prevent background daemon output from appearing in client terminals.

This appears to be a well-motivated improvement addressing real-world issues observed in CI systems and interactive shells. The implementation is clean and maintains cross-platform compatibility while solving concrete problems of process management and resource cleanup.
