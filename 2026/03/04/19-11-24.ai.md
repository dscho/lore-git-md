Bugfix completing the line-log/pickaxe interaction series. This is the second patch in Michael Montalbo's two-part series addressing how `git log -L` (line-log) handles pickaxe options (-G/-S/--find-object). The first patch fixed a crash when these options were combined with rename detection; this follow-up explicitly rejects the combination rather than silently ignoring the pickaxe options.

The patch modifies `builtin/log.c` to error out when pickaxe options are used with `-L`, since line-log's filtering logic doesn't actually consult the pickaxe machinery. The error message clearly states that the combination isn't yet supported. The test changes remove the earlier "known breakage" tests (which demonstrated the silent ignore behavior) and replace them with tests verifying the new error handling for all three pickaxe variants.

This is a clean, focused follow-up to the crash fix. The two-patch approach was sensible - first make the combination safe, then make the behavior explicit. The tests are thorough and the error message is clear. The commit message leaves the door open for future work to properly implement the feature, but for now this provides a clear user experience improvement over silent misbehavior.
