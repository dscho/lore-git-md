This is a feature patch for `git send-email` that adds client certificate support for SMTP authentication, now approved for merging. The patch has gone through review iterations and addresses all technical concerns raised, with Junio C Hamano giving the final approval to include it in the `next` integration branch.

The implementation adds three new configuration options following Git's existing SMTP configuration patterns: `sendemail.smtpSSLClientCert` for certificate files (accepting both PEM and PKCS12 formats), `sendemail.smtpSSLClientKey` for separate PEM key files when needed, and corresponding command-line flags. The design leverages Perl's IO::Socket::SSL library without introducing new dependencies, letting the library handle certificate presentation automatically per RFC 8446 standards.

The accompanying documentation thoroughly explains the security considerations, format-specific behaviors (embedded vs separate keys), and real-world compatibility with email clients like Thunderbird and K-9 Mail. This represents a complete solution for environments requiring certificate-based authentication while maintaining backward compatibility with existing SMTP auth methods. With no outstanding technical issues and maintainer approval, this feature is ready to graduate to wider testing in the `next` branch.
