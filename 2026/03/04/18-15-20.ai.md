This is part 7/12 of a feature series adding Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS implementations. The patch implements the core inotify listener that watches for filesystem changes.

The implementation uses inotify rather than fanotify since fanotify requires elevated privileges. It handles directory watches recursively, tracks renames via inotify cookies, and includes remote filesystem detection via statfs(). The listener uses non-blocking I/O with a poll loop to minimize queue overflows, and maintains bidirectional mappings between watch descriptors and paths for efficient event resolution.

Key technical details:
- Uses inotify_init1(O_NONBLOCK) with poll loop and 50ms timeout
- Tracks directory renames via IN_MOVED_FROM/TO event cookies
- Detects remote filesystems (NFS/SMB/etc) via statfs() magic numbers
- Falls back to $HOME/.git-fsmonitor-* for IPC socket when .git is remote
- Includes comprehensive error handling and cleanup
- Adds Linux-specific documentation about inotify watch limits

The patch appears well-structured with thorough error handling and cleanup. It builds on previous iterations that addressed memory leaks, race conditions, and test reliability. The implementation follows the same pattern as the existing macOS and Windows fsmonitor backends while adapting to Linux's inotify constraints.

This is a mature patch in its 8th iteration, with all major technical concerns from earlier reviews addressed. The main remaining discussion points are around the 1-second timeout for rename synchronization and Windows pthread compatibility, which are handled in other patches in the series.
