This is a bugfix patch in the fsmonitor series, specifically addressing a potential hang condition in the filesystem monitoring daemon. The patch introduces a timeout mechanism for cookie synchronization between the fsmonitor client and daemon.

The issue occurs when using certain container or overlay filesystems where inotify watches succeed but events are never delivered. Previously, the daemon would hang indefinitely waiting for a cookie event, which in turn caused the client to hang. This patch replaces the infinite wait with a 1-second timeout using `pthread_cond_timedwait()`. If the timeout fires, it reports an error and lets the client proceed with a full-scan response rather than blocking forever.

The implementation:
- Uses `gettimeofday()` to calculate the timeout timestamp
- Converts microseconds to nanoseconds for the timespec
- Checks for ETIMEDOUT and updates the cookie result accordingly
- Adds trace logging for timeout events

This is the 4th patch in the 12-patch v8 series that brings Linux fsmonitor support to parity with Windows and macOS. The change addresses a real-world reliability issue while maintaining the existing behavior in normal cases. The 1-second timeout value appears reasonable but remains a point of discussion in the thread (Patrick Steinhardt has questioned whether this duration is optimal).
