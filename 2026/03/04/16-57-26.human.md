This is a follow-up discussion on Patrick Steinhardt's object database (ODB) refactoring series, specifically addressing patch 2/17 which introduced the "files" source backend. Justin Tobler provides a technical review of the changes, noting that this patch primarily moves the loose objects and packfile storage into a new `struct odb_source_files` while maintaining the existing architecture where the files source is still a direct member of `struct odb_source`.

Justin observes that the patch is mostly structural reorganization at this stage, with the real architectural inversion (where the files source would contain the base ODB source) coming in the next commit. He questions whether an outdated comment about packfile access should be retained and speculates about future type casting patterns once the architecture evolves further.

The exchange reflects the careful, incremental nature of this refactoring work - each patch makes a small, verifiable change while keeping the system functional. Justin's review focuses on implementation details and forward-looking considerations rather than requesting changes, suggesting the patch is on the right track. This is typical of the thorough but constructive review culture around major refactoring efforts in the Git project.
