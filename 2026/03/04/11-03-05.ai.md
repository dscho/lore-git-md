This is a follow-up in the thread about `.git` directory validation errors, specifically addressing the Windows `/dev/null`/`nul` regression. Tian Yuchen confirms understanding Junio Hamano's architectural clarification that explicit `GIT_DIR` paths (like `GIT_DIR=/dev/null`) should not trigger repository discovery validation, while discovery paths still need strict checking. 

The email shows the author grasping the key distinction between these two validation modes, with Phillip Wood having previously identified the Windows-specific `nul` device file translation issue. Tian plans to audit all `read_gitfile_gently(path, NULL)` call sites to determine which should remain lenient (for explicit paths) versus strict (for discovery). This work will need to maintain security while accommodating platform quirks, particularly on Windows where device file handling differs from Unix-like systems. The thread remains active with implementation details still to be worked out.
