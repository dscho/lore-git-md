This is a bugfix series addressing an interaction between `git log -L` (line-log) and pickaxe options (-G/-S/--find-object). The cover letter explains that combining these features currently due to a regression introduced in a2bb801f6a ("line-log: avoid unnecessary full tree diffs", 2019-08-21).

The root issue is that diffcore_pickaxe() (run as part of diffcore_std()) can discard diff pairs that line-log's rename detection needs, leading to crashes when processing renamed files. The series takes a two-step approach:

1. First patch fixes the immediate crash by bypassing diffcore_std() and calling diffcore_rename() directly when processing line-log ranges. This restores the pre-a2bb801 behavior where pickaxe options were silently ignored rather than crashing.

2. Second patch makes this behavior explicit by actively rejecting the unsupported combination with an error message, since silently ignoring user-specified options is not ideal.

The changes touch the line-log machinery and add tests verifying both the crash fix and the new rejection behavior. The fix is relatively contained but addresses a real usability issue - the crash could surprise users trying to combine these features. The second patch's explicit error is a clear improvement over silent failure.

This appears to be a well-motivated fix from a new contributor (Michael Montalbo), with clear commit messages explaining both the technical issue and solution. The test coverage looks thorough, including both regression tests for the crash and new tests for the rejection case. The changes are focused on the line-log subsystem without broader implications.
