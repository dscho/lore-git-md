This is a patch in the fsmonitor thread that adds a new feature to `struct child_process` to help with file descriptor management in long-running child processes. It's part of the larger effort to bring Linux fsmonitor support to parity with Windows/macOS.

The patch introduces a `close_fd_above_stderr` flag that, when set, will close all file descriptors above stderr (fd 2) in child processes after forking but before exec. This prevents long-running daemons (like the fsmonitor daemon) from inheriting unwanted file descriptors from their parent process, which could cause issues with leaked pipe endpoints or test harness fds.

Key technical details:
- Uses `sysconf(_SC_OPEN_MAX)` to determine the maximum fd to check, with a safety cap at 4096
- Preserves the child notifier fd (used for process communication)
- Adds documentation to `run-command.h` explaining the purpose
- The implementation is straightforward - just loops through fds 3 to max_fd and closes them

This addresses a specific issue that came up in the fsmonitor work where the daemon could inherit fds it shouldn't. The patch is well-contained and follows Git's established patterns for process management. It's the 8th in a 12-part series that's been through multiple rounds of review, with this particular addition coming from Paul Tarjan who has been contributing Windows compatibility fixes to the thread.
