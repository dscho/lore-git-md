This is a status update on the SHA-1/SHA-256 interoperability effort, which has been in development for several years. brian m. carlson confirms their branch `bc/sha-256-interop-02` is ready for merging into Git's `next` integration branch, pending any last-minute objections. The 16-commit series introduces Rust infrastructure to maintain mappings between objects stored with different hash algorithms (SHA-1 and SHA-256), including new Rust wrappers for hashfile operations, object ID handling, and algorithm abstraction.

The changes represent a significant step in the long-running effort to enable repositories using different hash algorithms to exchange objects. Key technical components include a new binary object map format, Rust bindings for hash context functions, and infrastructure to safely convert between hash algorithms. The series builds on carlson's foundational work making Git's internals hash-agnostic, though they note at the 2025 Contributor's Summit that full interoperability shouldn't block Git 3.0.

Junio Hamano had previously included this in his "What's cooking" report with a tentative merge target of `next`, indicating the technical approach has consensus. The current email serves as final confirmation from the author that no further changes are needed from their side. Given the complexity of hash algorithm interoperability and the Rust dependencies being introduced, this would likely be one of the more consequential changes queued for the upcoming release cycle.
