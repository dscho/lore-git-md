Thread identity: Bugfix for promisor-remote subsystem addressing recursive lazy-fetch issue that can cause runaway resource consumption (276GB of promisor packs written in 90 minutes in production).

Core problem: When `fetch_objects()` spawns a child `git fetch` for lazy fetching, and that child's `index-pack` encounters a REF_DELTA against a missing base object, it can recursively trigger another lazy fetch, creating an unbounded chain of fetches.

Current status: Patch v2 incorporates Junio's feedback by moving tests into existing infrastructure while maintaining the same technical solution - propagating `GIT_NO_LAZY_FETCH=1` into child fetch processes to prevent recursion. Author Paul Tarjan has addressed stylistic concerns by removing redundant Cc trailers and consolidating test cases into `t0411-clone-from-partial.sh` rather than using a dedicated test file.

Key technical details: Single-line change to propagate environment variable in `fetch_objects()`. Test cases now in existing `t0411-clone-from-partial.sh` verify: (1) only one fetch subprocess spawned during lazy fetch, (2) child process environment contains `GIT_NO_LAZY_FETCH=1`. Test uses reference-transaction hook to inspect child environment and creates partial clone scenario with missing object to trigger lazy fetch behavior. Justification notes that with noop negotiation, servers shouldn't send problematic deltas, and recursion wouldn't help if they do.
