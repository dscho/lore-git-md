Thread identity: Bugfix for promisor-remote subsystem addressing recursive lazy-fetch issue that can cause runaway resource consumption (276GB of promisor packs written in 90 minutes in production), now at v3.

Core problem: When `fetch_objects()` spawns a child `git fetch` for lazy fetching, and that child's `index-pack` encounters a REF_DELTA against a missing base object in a blob:none partial clone, it can recursively trigger another lazy fetch. Paul Tarjan's production data demonstrates this occurs with GitHub's actual server behavior, though Patrick Steinhardt initially questioned whether this represents a server protocol violation since well-behaved servers shouldn't send such deltas.

Current status: Patch v3 strengthens test coverage to demonstrate the actual failure mode (not just environment variable propagation) and shows reproducibility with GitHub's server behavior. The technical solution remains sound - propagating `GIT_NO_LAZY_FETCH=1` into child fetch processes to prevent recursion. Discussion has clarified this is both client hardening and may indicate a separate server-side issue. The patch appears ready for merging with consensus forming around the technical approach.

Key technical details: Single-line change to propagate environment variable in `fetch_objects()`. Enhanced tests in `t0411-clone-from-partial.sh` now show: (1) actual recursive fetch behavior with thin packs containing REF_DELTA objects referencing missing bases, (2) reproduction using GitHub server behavior, (3) prevention via environment variable. Justification refined to acknowledge this may reveal server protocol concerns while still being valuable as client hardening.
