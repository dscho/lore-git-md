Thread identity: Bugfix for promisor-remote subsystem addressing recursive lazy-fetch issue that can cause runaway resource consumption (276GB of promisor packs written in 90 minutes in production).

Core problem: When `fetch_objects()` spawns a child `git fetch` for lazy fetching, and that child's `index-pack` encounters a REF_DELTA against a missing base object, it can recursively trigger another lazy fetch, creating an unbounded chain of fetches.

Current status: Patch v1 proposes fixing this by propagating `GIT_NO_LAZY_FETCH=1` into the child fetch's environment to prevent recursion while allowing the initial lazy fetch to proceed. Justification notes that with noop negotiation, servers shouldn't send problematic deltas, and recursion wouldn't help if they do.

Key technical details: Single-line change to propagate environment variable in `fetch_objects()`. New test script `t0410-lazy-fetch-recursion.sh` verifies: (1) only one fetch subprocess spawned during lazy fetch, (2) child process environment contains `GIT_NO_LAZY_FETCH=1`. Test uses reference-transaction hook to inspect child environment.
