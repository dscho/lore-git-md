Thread identity: Bugfix for promisor-remote subsystem addressing recursive lazy-fetch issue that can cause runaway resource consumption (276GB of promisor packs written in 90 minutes in production).

Core problem: When `fetch_objects()` spawns a child `git fetch` for lazy fetching, and that child's `index-pack` encounters a REF_DELTA against a missing base object, it can recursively trigger another lazy fetch, creating an unbounded chain of fetches.

Current status: Patch v1 proposes fixing this by propagating `GIT_NO_LAZY_FETCH=1` into the child fetch's environment to prevent recursion while allowing the initial lazy fetch to proceed. Junio Hamano has reviewed the technical solution as sound but provided meta-feedback about GitGitGadget usage patterns (Cc trailers and commit message duplication) and questioned whether the new test needs its own dedicated file rather than being added to an existing promisor-related test script.

Key technical details: Single-line change to propagate environment variable in `fetch_objects()`. Test cases in new `t0412-promisor-no-lazy-fetch-recursion.sh` verify: (1) only one fetch subprocess spawned during lazy fetch, (2) child process environment contains `GIT_NO_LAZY_FETCH=1`. Test uses reference-transaction hook to inspect child environment and creates partial clone scenario with missing object to trigger lazy fetch behavior. Justification notes that with noop negotiation, servers shouldn't send problematic deltas, and recursion wouldn't help if they do.

Open questions: Whether the test should be in a new file or integrated into existing promisor test infrastructure. GitGitGadget usage patterns (Cc trailers and commit message duplication) noted as stylistic concerns.
