Thread identity: Bugfix for promisor-remote subsystem addressing recursive lazy-fetch issue that can cause runaway resource consumption (276GB of promisor packs written in 90 minutes in production), now at v3 with packet traces confirming server behavior and deterministic reproduction.

Core problem: Recursive lazy fetching occurs when `fetch_objects()` spawns a child `git fetch` whose `index-pack` encounters REF_DELTA against missing base objects in blob:none partial clones. Paul Tarjan's packet traces confirm the server is protocol-compliant (proper noop negotiation and thin-pack response), with the issue arising when pack-reuse converts OFS_DELTAs to REF_DELTAs against filtered-out blob bases. Two reproduction scripts now conclusively demonstrate the failure mode: `repro-depth1.sh` shows single-level recursion, while `repro-unbounded.sh` simulates the production scenario (killed at depth 50 with 1.4GB temp files). Additional context reveals the production incident involved prefetch refs pointing to promised-but-never-downloaded commits from ephemeral CI branches, explaining the thin pack behavior without affecting core recursion.
