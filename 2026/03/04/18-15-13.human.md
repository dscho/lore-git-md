This is a feature patch series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The series is now in its 8th iteration, having addressed extensive review comments from Patrick Steinhardt and others.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename events, and remote filesystem detection. Key technical aspects include:
- Recursive directory watching with IN_MASK_CREATE flag
- Bidirectional watch descriptor ↔ path mapping
- Two-phase event synchronization with 1-second timeout
- Remote filesystem detection via statfs()
- Fallback IPC socket location when .git is remote

The series also includes several fixes and improvements:
- Memory leak fixes in the platform-independent daemon code
- Windows pthread compatibility additions
- Test reliability improvements
- Process management refinements (file descriptor cleanup, daemon detachment)
- Build system unification (renaming darwin implementations to unix)

The patches look well-tested and production-ready, with thorough test coverage including stress tests for concurrent directory operations. Patrick Steinhardt's detailed reviews have helped refine the implementation, though a few minor points remain open regarding hashmap cleanup and Windows pthread error handling.

This represents a significant step forward for Git's performance on Linux, particularly for large repositories where filesystem monitoring can dramatically speed up operations like `git status`. The careful attention to edge cases and platform compatibility suggests this will be a robust addition to Git's core functionality.
