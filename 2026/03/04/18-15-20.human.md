This is a feature patch adding Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to the existing Windows and macOS implementations. It's part of a larger 12-patch series (this is patch 7/12) that has gone through multiple iterations of review and refinement.

The implementation uses inotify rather than fanotify since it doesn't require elevated privileges. It handles directory renames via inotify's cookie mechanism, detects remote filesystems via statfs(), and includes proper cleanup of watches and resources. The patch adds new files for Linux-specific implementations of the fsmonitor listener, health monitoring, and path utilities.

Key technical aspects include:
- Recursive directory watching with IN_MASK_CREATE
- Bidirectional watch descriptor to path mappings using hashmap
- Special handling for directory renames via IN_MOVED_FROM/TO events
- Remote filesystem detection (NFS/SMB/vfat) with fallback to $HOME/.git-fsmonitor-* for IPC sockets
- Documentation updates noting Linux-specific caveats about inotify watch limits

The patch appears well-constructed with thorough error handling and cleanup. It builds on previous work from Eric DeCosta and Marziyeh Esipreh, and has been through extensive review iterations addressing race conditions, memory leaks, and test coverage. The implementation is now stable in Junio's 'seen' branch with production testing reported by Paul Tarjan.
