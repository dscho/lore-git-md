Feature: Configurable branch comparisons in `git status`

This is the final version of Harald Nordgren's long-running effort to make `git status` branch comparisons configurable via `status.compareBranches`. After 31 iterations over several years, the patch series is now fully reviewed and ready for merging. The implementation allows users to specify which branches (like `@{upstream}` and `@{push}`) should be compared in status output, with comprehensive test coverage for all edge cases.

The first patch refactors the existing comparison logic, while the second introduces the new config option and its test suite. Notable improvements in this version include:
- Clearer test names and organization
- Explicit testing of single-branch configurations
- Documentation of deduplication behavior
- Fixed test style issues flagged in review

The feature maintains backward compatibility (defaulting to `@{upstream}` behavior) while enabling triangular workflows where developers want to track both upstream and push targets. The implementation handles all expected cases: ahead/behind states, diverged branches, remapped refspecs, and duplicate branch specifications.

With maintainer approval and all technical concerns addressed, this represents a successful conclusion to a persistent contribution effort through Git's mailing list workflow. The comprehensive test matrix (337 lines across t6040-tracking-info.sh) ensures robust behavior across various workflow scenarios.
