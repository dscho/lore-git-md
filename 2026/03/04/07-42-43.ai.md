This is a follow-up review comment in the ongoing fsmonitor Linux inotify implementation thread. Patrick Steinhardt points out that the memory leak fix in patch 2/10 may not be complete - while the hashmap itself is now being cleared, the individual cookie names (allocated via strbuf) stored within it may still being leaked.

The original patch from Paul Tarjan added a `hashmap_clear()` call to clean up the `state.cookies` hashmap during daemon shutdown, but Patrick notes that each cookie entry contains a strbuf-allocated name that would need to be freed as well. This suggests the cleanup needs to either use `hashmap_clear_and_free()` with an appropriate free function, or manually iterate and free the names before clearing the hashmap.

This is a technical refinement to an already-reviewed patch series that has seen multiple iterations addressing various memory management and synchronization issues. The thread as a whole represents a mature implementation of Linux fsmonitor support that is nearing final approval, with this being one of the last remaining details to resolve. Patrick's review continues his pattern of thorough technical scrutiny of the implementation details.
