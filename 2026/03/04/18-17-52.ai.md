This is a test patch for the Linux fsmonitor implementation, addressing reliability concerns with overlayfs. The patch is part of the ongoing effort to bring filesystem monitoring support to Linux using inotify, matching existing Windows and macOS implementations.

Paul Tarjan responds to Patrick Steinhardt's concern about test reliability by explaining that the observed behavior is not a bug in their code but rather a kernel limitation in overlayfs. On older kernels, overlayfs fails to deliver inotify events despite successful watch registration, while newer kernels have partial fixes. The patch handles this by implementing a fallback to full scans when events aren't received, maintaining correctness while sacrificing performance in affected configurations. The test suite is updated to detect this condition early and skip affected tests rather than waiting for timeouts.

The exchange highlights a key technical tradeoff in the implementation - the choice between perfect reliability (impossible on some filesystems) versus graceful degradation. The 1-second timeout for inotify cookie waits remains unchanged as it represents a pragmatic balance between responsiveness and reliability. This patch completes the test coverage for the Linux fsmonitor backend while properly accounting for real-world filesystem limitations.
