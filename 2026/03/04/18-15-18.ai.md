This is part of the ongoing fsmonitor Linux support series, specifically addressing build system changes needed to share Unix IPC code between macOS and Linux implementations.

The patch renames `fsm-ipc-darwin.c` to `fsm-ipc-unix.c` to reflect that the IPC path logic is not macOS-specific and will be reused by Linux. It introduces a new `FSMONITOR_OS_SETTINGS` build variable (set to "unix" for non-Windows platforms) separate from `FSMONITOR_DAEMON_BACKEND` to distinguish between platform-specific files (listen, health, path-utils) and shared Unix files (ipc, settings).

Key changes include:
- Moving `fsm-ipc` to the `FSMONITOR_OS_SETTINGS` section in the Makefile
- Switching `fsm-path-utils` to use `FSMONITOR_DAEMON_BACKEND` since path utilities remain platform-specific
- Updating build configurations (Makefile, CMake, meson) to handle the new variable split
- Maintaining backward compatibility while setting up for Linux integration

The patch builds on previous work by Eric DeCosta and Marziyeh Esipreh, with Paul Tarjan now driving the Linux fsmonitor implementation forward. This is a mechanical but important change that enables code sharing between Unix platforms while keeping the build system cleanly organized.
