Here's a human-readable summary of the thread so far:

Patrick Steinhardt has proposed deprecating Git's autoconf build system in favor of Meson, with a tentative removal target of Git 2.55 (about 1.5 years from now). The RFC series consists of two patches that take initial steps toward this transition while giving packagers time to adapt. The first patch updated INSTALL documentation to recommend Meson over autoconf, while keeping the overall documentation structure intact. The second patch, just submitted, adds deprecation warnings to configure.ac that will make the autoconf build fail by default, with a `--disable-autoconf-deprecation` flag available for packagers who need more time. The warning explains the rationale (autoconf's unfixed bugs and missing features) and points to Meson as the recommended replacement.

The approach shows awareness of downstream impact, with both patches designed to signal intent clearly while allowing flexibility in the timeline based on packager feedback. The technical changes are minimal at this stage, focusing on establishing the deprecation path rather than immediate functional removal. This follows previous discussions that had reached rough consensus on moving to Meson, with open questions now centering on timing and packager readiness rather than technical objections to the direction itself.
