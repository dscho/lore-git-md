Junio C Hamano, the Git maintainer, has responded to Patrick Steinhardt's proposal to deprecate autoconf in favor of Meson. While Patrick's RFC framed this as moving from autoconf to Meson, Junio points out this oversimplifies the situation - autoconf is just a configuration tool that generates Makefiles, while Meson is a complete alternative build system. 

Junio's reply suggests he may not fully share Patrick's enthusiasm for adopting Meson as the primary build system, though he acknowledges the need for modernization. His comments indicate the discussion needs to more clearly separate three distinct questions: whether to just replace autoconf with Meson's configuration while keeping Make, fully replace Make with Meson, or maintain both approaches long-term. 

The thread now appears headed toward clarifying these fundamental distinctions before any deprecation timeline can be meaningfully evaluated. Junio's diplomatic but substantive response has shifted the discussion from implementation details to first establishing consensus on what exactly the project wants to modernize about its build process.
