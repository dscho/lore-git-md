Build system modernization discussion focused on deprecating autoconf infrastructure in favor of Meson, with Patrick Steinhardt's RFC series (2 patches) as the starting point. The thread has clarified that autoconf is not the build system itself but a tool generating Makefiles, making the core comparison between Makefile-based builds (with/without autoconf) versus Meson adoption. Patrick emphasizes autoconf as the primary pain point - difficult to maintain and not the recommended build method (direct Makefile usage is typically suggested instead). He references past discussions favoring autoconf removal but acknowledges Junio Hamano may disagree with timing.

Junio's intervention shifted focus to three possible paths: (1) remove autoconf while keeping Meson support, (2) modernize Make-based approach without autoconf, or (3) fully transition to Meson. Patrick leans toward option 1, seeing autoconf as the problematic component rather than advocating complete Makefile replacement. Junio's initial response suggested preference for option 2 (Makefile modernization). Open questions include long-term maintenance costs of dual build systems, packager needs, and whether the project wants to maintain Makefile compatibility indefinitely. The proposed deprecation timeline (targeting Git 2.55) remains pending until this fundamental direction is resolved, with Patrick expected to address Junio's concerns in a revised proposal. Key technical details involve INSTALL documentation updates, configure.ac deprecation warnings with `--disable-autoconf-deprecation` escape hatch, and implications for build infrastructure maintenance.
