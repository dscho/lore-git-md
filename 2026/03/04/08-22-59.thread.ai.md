Build system modernization proposal to begin autoconf deprecation in favor of Meson, targeting removal in Git 2.55 (~1.5 years out). Patrick Steinhardt's RFC series (2 patches) initially framed this as replacing autoconf with Meson, updating INSTALL documentation and adding deprecation warnings to configure.ac with a `--disable-autoconf-deprecation` escape hatch. Junio C Hamano's response clarifies a key distinction - autoconf is a build configuration tool that generates Makefiles, not the build system itself, suggesting the real comparison is between Makefile-based builds (with/without autoconf) versus Meson as an alternative build system. This intervention shifts the discussion's focus to three possible paths: replacing just autoconf while keeping Make, fully replacing Make with Meson, or maintaining parallel support. Junio's reply indicates he may favor modernizing the Make-based approach rather than wholesale Meson adoption, though he leaves room for continued discussion rather than rejecting the proposal outright. The thread now needs to resolve this fundamental question before the deprecation timeline can progress, with Patrick expected to address Junio's concerns in a revised proposal. Open questions include whether the project wants to maintain Makefile compatibility long-term maintenance costs of dual build systems, and how packager needs factor into the decision.
