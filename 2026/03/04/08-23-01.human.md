This is the second patch in a 2-part RFC series proposing to deprecate Git's autoconf build system in favor of Meson. The patch adds deprecation warnings to `configure.ac` that will make the autoconf build fail by default, encouraging packagers to switch to either the plain Makefile or Meson builds. The error message explains the rationale (autoconf being buggy and neglected) and provides migration instructions, while allowing an override via `--disable-autoconf-deprecation` for packagers who need more time to adapt.

The patch sets a tentative removal target of Git 2.55 (~1.5 years away), acknowledging this timeline may need adjustment based on downstream feedback. The approach shows awareness of real-world packaging constraints while making clear the project's direction. This follows earlier discussions where the community broadly agreed autoconf should be phased out, with Meson having now reached feature parity point where it can serve as the recommended replacement.

The technical changes are minimal but effective - just adding the warning infrastructure while leaving the actual autoconf removal for later. This gives packagers clear advance notice while allowing the project to gauge readiness before committing to a hard cutoff. The patch comes from Patrick Steinhardt, who has been a key driver of Git's build system modernization efforts.
