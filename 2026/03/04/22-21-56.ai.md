This is a test modernization patch in an ongoing thread about improving command substitution patterns in test scripts. Eric Sunshine reviews Francesco Paparatto's changes to `t/t3310-notes-merge-manual-resolve.sh` that make `git rev-parse` failures visible by storing outputs in variables before comparison.

Eric acknowledges the value of surfacing failures but suggests two improvements to make test failures more developer-friendly. First, he recommends using `test_cmp` with pre-stored expected values (in files) rather than direct string comparisons, as it shows both expected and actual values on failure. Second, for revision comparisons, he suggests using the specialized `test_cmp_rev` helper which is designed for this purpose and can handle negated comparisons with `!`.

The review is constructive and specific, pointing to concrete alternatives for each pattern in the patch. The changes would affect all 10 test cases being modified, replacing the variable-based comparisons with more informative test helpers. This aligns with the test suite's ongoing modernization while maintaining the original goal of properly detecting `rev-parse` failures. The feedback comes from one of Git's most active and respected reviewers, making it likely the author will incorporate these suggestions in a v2.
