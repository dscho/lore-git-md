Memory leak fix in fsmonitor daemon client handling.

This patch addresses a memory leak in the fsmonitor daemon's client handling code where a khash table (`shown`) was not being freed when processing trivial responses. The fix initializes the hash table to NULL and moves cleanup to a shared label using `kh_destroy_str()`, which safely handles NULL. This ensures proper cleanup regardless of whether the response path is trivial or non-trivial.

The change is straightforward and clearly motivated by the commit message. It's part of a larger fsmonitor effort to bring Linux support to parity with existing Windows and macOS backends, specifically addressing feedback from earlier iterations of the patch series. The fix targets a specific leak identified during review, demonstrating attention to detail in resource management for this long-running daemon process.
