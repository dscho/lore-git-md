This is a follow-up discussion in the ongoing "--trailer option for git rebase" series, now in its 8th iteration. The thread has reached consensus on most technical aspects, with this email addressing one of the final open questions about trailer ordering during rebase.

Phillip Wood responds to Junio Hamano and Kristoffer Haugsbakk's discussion about whether trailers added via `--trailer` should appear before or after the signoff when both options are used. Junio had suggested that the command-line order should dictate trailer placement, while Kristoffer questioned whether there was an established project convention. Phillip proposes keeping the current behavior (which matches `git commit --signoff --trailer`) where signoffs appear after other trailers, noting this hasn't caused complaints in the commit context.

The exchange shows the series is nearing completion, with this being one of the last behavioral details to settle. Phillip's position suggests favoring consistency with existing Git commands over introducing new ordering logic, at least for this initial implementation. The thread has previously established that the core functionality works and the patches are reviewed, with only a few documentation and error handling items remaining before the series can be merged.
