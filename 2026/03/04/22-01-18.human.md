This is a platform compatibility patch from Patrick Steinhardt, part of his larger series optimizing write syscalls in `git-upload-pack`. The patch introduces a `writev()` compatibility wrapper for systems that don't have this POSIX syscall natively (notably Windows).

Junio C Hamano points out a potential integer overflow issue in the implementation. The current code could wrap around `size_t` when accumulating written bytes, which would make the `cast_size_t_to_ssize_t()` helper ineffective. He suggests following POSIX more closely by first validating the total size won't overflow before attempting writes, then doing a simple cast for the return value.

The patch is technically sound but needs this refinement to properly handle edge cases. It's a small but important piece of the larger performance optimization effort that has already shown significant reductions in syscall counts (from 400k to 44k writes when cloning Linux repo). The series has received thorough review from Jeff King and appears ready for integration once this last issue is addressed.
