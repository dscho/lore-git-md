This is the final version of Harald Nordgren's feature patch series adding configurable branch comparison to `git status`. The 2-patch series introduces a new status.compareBranches configuration option that allows users to specify multiple branch comparisons (like @{upstream} and @{push}) in the status output.

The implementation has gone through extensive review over multiple iterations (v31 now), with all technical feedback addressed. The key changes in this version are test improvements requested by Junio Hamano - fixing inconsistent test styles, adding explicit tests for single-branch cases, and better documenting the deduplication behavior when the same branch appears multiple times.

The feature allows users to configure which branches `git status` compares against (defaulting to just @{upstream} for backward compatibility). The implementation handles various edge cases like:
- Preserving order of configured branches
- Deduplicating when upstream and push resolve to same ref
- Supporting both ahead/behind and --no-ahead-behind output modes
- Working with remapped push refspecs
- Triangular workflow scenarios

Test coverage is comprehensive with 354 new lines in t6040-tracking-info.sh covering all these cases. The documentation clearly explains the configuration syntax and behavior.
