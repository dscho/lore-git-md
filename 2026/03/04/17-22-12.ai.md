This is a feature patch in the ongoing "rebase --trailer" series by Phillip Wood (with Li Chen assisting), now in its 8th iteration. The email captures a resolved discussion point about trailer ordering during rebase operations.

The thread had previously debated whether trailers added via `--trailer` should appear before or after the signoff when both options are used. Junio C Hamano initially suggested following the command-line order, while Kristoffer Haugsbakk questioned whether project conventions should dictate placement. Phillip Wood proposes maintaining consistency with `git commit` behavior, where signoffs always appear after other trailers regardless of option order, and Junio accepts this resolution.

The series has now settled all major technical questions, with the implementation:
- Moving core trailer logic to `process_trailers()` while keeping I/O in `interpret_trailers()`
- Using `strbuf_write()` with tempfile+rename for atomicity
- Improving argument handling via `OPT_STRVEC` parsing
- Sharing helper functions like `create_in_place_tempfile()`
- Supporting all rebase modes while preserving trailers through conflicts
- Validating trailers early in the process

The only remaining work before merging appears to be documentation updates and some error handling improvements to the rebase state file. The series represents a significant refactoring of trailer handling to make it reusable across Git commands while maintaining backward compatibility.
