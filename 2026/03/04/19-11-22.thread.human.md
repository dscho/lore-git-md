Michael Montalbo has proposed a fix for a bug where `git log -L` (line-log) crashes when used with pickaxe options (-G/-S/--find-object). The issue stems from a 2019 change that optimized line-log by avoiding full tree diffs, but inadvertently broke rename detection when pickaxe options are present. The crash occurs because the pickaxe filter discards diff pairs that line-log's rename detection needs.

The fix comes as a two-patch series. The first patch (currently under discussion) addresses the immediate crash by modifying how line-log processes diffs, restoring the pre-2019 behavior where pickaxe options were silently ignored. The second patch will follow up by making this behavior explicit - rejecting the unsupported combination with an error message rather than silently ignoring it.

The changes are focused in line-log.c and come with new test cases that verify both the crash fix and document the current silent-ignore behavior (marked as a known breakage). This appears to be Michael's first contribution to Git, and he's taken care to follow project conventions with clear commit messages and thorough test coverage. The two-phase approach - fixing the crash first before changing the behavior - seems sensible as it isolates the regression fix from the policy decision about how to handle unsupported options. Reviewers will likely want to examine both the technical solution and whether the phased approach is the right way to handle this case.
