Bugfix addressing interaction between line-log (-L) and pickaxe options (-G/-S/--find-object). This is the second patch in a series where the first fixed a crash when these options were combined, and now explicitly rejects the combination since line-log doesn't actually honor the pickaxe options.

The patch adds a check in `builtin/log.c` to error out when both -L and pickaxe options are used, replacing the previous test cases that showed the broken behavior with new tests verifying the rejection. The change is straightforward - just adding the error condition alongside an existing similar check for pathspec conflicts.

Maintainer Junio Hamano questions whether the first patch (the crash fix) is still needed if we're now rejecting the combination entirely. Author Michael Montalbo explains the first patch was meant as future-proofing in case someone later implements proper pickaxe-with-line-log support, but is open to dropping it if the maintainer prefers. This suggests the series may be revised to either:
1. Keep both patches (crash fix + rejection) for future compatibility
2. Drop the crash fix and just keep the rejection

The thread shows the line-log feature has some known limitations in how it handles other diff options, and this patch takes the conservative approach of explicitly rejecting unsupported combinations rather than silently ignoring them. The test changes demonstrate the new behavior while removing now-unnecessary tests of the broken interaction.
