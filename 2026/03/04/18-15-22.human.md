This is a process management patch in the fsmonitor daemon series, addressing file descriptor inheritance and process group issues. It's the ninth patch in the v8 series introducing Linux fsmonitor support via inotify.

The patch fixes two problems in the fsmonitor daemon's process handling. First, it ensures the daemon closes inherited file descriptors above stderr (fd 2) when spawned, preventing hangs in parent processes that might be waiting on pipes the daemon doesn't need. This uses a new `close_fd_above_stderr` flag in `struct child_process` that safely caps at 4096 file descriptors while preserving the child notifier fd. Second, it properly detaches the daemon process on Unix systems by calling `setsid()` to create a new session, preventing shells with job control from waiting on the daemon.

The changes affect both explicit daemon startup (`fsmonitor--daemon start`) and implicit spawning when a client finds no running instance. The Windows-specific `FreeConsole()` call remains unchanged. The patch includes corresponding test coverage from earlier in the series to verify these process management improvements.

This appears to be a well-motivated fix addressing real-world issues seen in CI systems and interactive shells, with careful attention to cross-platform compatibility. The changes are focused and build on the existing process management framework in Git.
