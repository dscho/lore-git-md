This is a memory leak fix for the fsmonitor daemon, part of the larger Linux fsmonitor support series. The patch addresses a specific issue where the `state.cookies` hashmap and its allocated strings were not being properly freed during daemon shutdown.

The change adds cleanup code to iterate through the hashmap entries, freeing each cookie name string, then clearing and freeing the hashmap itself. This plugs a memory leak that would occur each time the fsmonitor daemon exited.

The patch is straightforward and clearly motivated - it fixes a real resource leak in code that's already been through multiple rounds of review. As part of the v8 iteration of the fsmonitor series, this represents one of the final cleanup items before the feature can be merged. The change is small, focused, and unlikely to be controversial.
