This is part of the ongoing fsmonitor Linux support series, specifically a refactoring patch to share IPC code between macOS and Linux implementations.

The patch renames `fsm-ipc-darwin.c` to `fsm-ipc-unix.c` since the IPC path logic is not macOS-specific and will be reused by Linux. It introduces a new `FSMONITOR_OS_SETTINGS` build variable (set to "unix" for non-Windows platforms) to distinguish between platform-specific files and shared Unix files, while keeping `FSMONITOR_DAEMON_BACKEND` for the actual backend implementations.

The changes affect multiple build systems (Makefile, CMake, meson) and include some file reorganization to properly separate the shared Unix IPC code from platform-specific components. The patch is well-structured with clear commit message explaining the motivation and changes, and builds on previous work from other contributors (Eric DeCosta and Marziyeh Esipreh).

This is a straightforward refactoring that helps pave the way for the Linux fsmonitor implementation while maintaining existing macOS functionality. The changes are mechanical and unlikely to be controversial, though they do require coordination across multiple build systems.
