This is the final patch in a series implementing Linux filesystem monitoring (fsmonitor) support using inotify. The patch addresses process management details for the fsmonitor daemon, ensuring proper cleanup of inherited file descriptors and process detachment.

The patch responds to review feedback from Patrick Steinhardt about how to best handle daemonization. The author explains why they can't use the existing `daemonize()` function (it would break the IPC handshake) and instead implements a lighter approach using `setsid()` for process detachment combined with `close_fd_above_stderr` to clean up file descriptors. 

The changes have been reorganized based on review comments - the timeout handling was split into a separate commit, and test-related changes were moved to the tests commit with better documentation. The implementation now cleanly handles the process lifecycle while maintaining the carefully designed IPC communication between Git and its fsmonitor daemon.

This completes the Linux fsmonitor implementation, which has been through multiple iterations to handle real-world filesystem behaviors (including overlayfs limitations) while maintaining cross-platform consistency with the Windows and macOS implementations. The series appears ready for merging, with all technical concerns addressed and positive reports from production use.
