This is a technical discussion about file descriptor handling and process management in Git's fsmonitor daemon, part of the ongoing fsmonitor Linux support effort.

Paul Tarjan's patch addresses two issues with the fsmonitor daemon: inherited file descriptors that can cause hangs in test environments, and process group management when the daemon runs detached. The solution introduces a `close_fd_above_stderr` flag to close unnecessary inherited FDs and uses `setsid()` for proper process detachment. It also adds a 30-second timeout for daemon shutdown.

Patrick Steinhardt raises several thoughtful questions in his review:
1. Whether the existing `daemonize()` function could be extended to handle FD closing rather than adding new mechanisms
2. If the 30-second timeout should be a separate commit since it's somewhat orthogonal
3. Why some test changes (like the start-timeout addition) appear in the diff without being mentioned in the commit message
4. Whether the process group handling changes are still needed given the `setsid()` call

The discussion shows careful attention to implementation details and architectural consistency. Patrick's questions suggest the patch might benefit from some reorganization to keep changes more focused and better explained. This is typical of the review process for complex subsystems like fsmonitor, where multiple concerns (correctness, testability, platform compatibility) need to be balanced.
