This is a process management patch in the fsmonitor daemon series, adding a mechanism to prevent file descriptor leaks in long-running child processes. The patch introduces a `close_fd_above_stderr` flag to `struct child_process` that, when set, closes all file descriptors above stderr (fd 2) in the child process after forking but before exec. This prevents the child from inheriting potentially problematic descriptors from the parent.

The implementation caps the scan at 4096 file descriptors (or the system's `_SC_OPEN_MAX` if lower) to avoid excessive iteration on systems with very high limits. Junio Hamano suggests in his reply that a more generic callback mechanism between fork and exec might be preferable to this specific solution, though he doesn't object to the current approach.

This change completes the process management improvements for the fsmonitor daemon, ensuring clean process isolation while maintaining the carefully designed IPC coordination. The patch is now in Junio's 'seen' branch with all technical concerns addressed, including Paul Tarjan's production validation and Patrick Steinhardt's reliability feedback.
