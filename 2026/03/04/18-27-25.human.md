This is a bugfix for the promisor-remote subsystem that prevents recursive lazy-fetching, which could lead to runaway resource consumption (as seen in production with 276GB of promisor packs written in 90 minutes).

The core issue occurs when `fetch_objects()` spawns a child `git fetch` for lazy fetching, and that child's `index-pack` encounters a REF_DELTA against a missing base object. Without this fix, it could recursively trigger another lazy fetch, creating an unbounded chain of fetches.

The solution propagates `GIT_NO_LAZY_FETCH=1` into the child fetch's environment to prevent recursion. The patch has been refined since v1 based on Junio's feedback - the tests have been consolidated into existing infrastructure (`t0411-clone-from-partial.sh`) rather than using a dedicated test file, and redundant Cc trailers were removed.

The test verifies that the child fetch environment contains the expected variable by using a reference-transaction hook to inspect the environment. The fix is well-motivated by real-world impact and builds on prior work around lazy fetching and environment variable handling. The technical solution was already approved as sound in v1, and the remaining stylistic/organizational concerns have now been addressed.
