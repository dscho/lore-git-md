This is a bugfix for the promisor-remote subsystem that prevents runaway recursive lazy-fetching, addressing a production issue where 276GB of promisor packs were written in 90 minutes due to unbounded fetch recursion.

The patch (now in its second iteration) propagates `GIT_NO_LAZY_FETCH=1` into child fetch processes spawned during lazy fetching, preventing recursive fetches while still allowing the initial lazy fetch to proceed. The technical solution remains unchanged from v1 - a single-line environment variable propagation in `fetch_objects()` - but the test infrastructure has been reorganized per Junio's feedback. The test cases verifying the non-recursive behavior have been moved into the existing `t0411-clone-from-partial.sh` rather than using a dedicated test file.

The commit message explains that while servers with noop negotiation shouldn't send problematic deltas that would require recursive fetching, this defense-in-depth protection ensures robustness even if malformed input is received. The test uses a reference-transaction hook to inspect child process behavior and creates a partial clone scenario to trigger the lazy fetch mechanism.

Paul Tarjan has incorporated Junio's stylistic feedback by removing redundant Cc trailers from the commit message and consolidating the test cases into existing infrastructure. The core technical approach remains sound, with the change now better integrated into Git's test organization. This appears ready for inclusion as a defensive fix for a potentially serious resource consumption issue in partial clone scenarios.
