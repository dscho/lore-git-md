This is a refactoring patch in Patrick Steinhardt's ongoing object database (ODB) abstraction series, specifically addressing how Git handles path reparenting when the working directory changes. Justin Tobler provides a detailed review of the changes.

The patch moves reparenting logic from the generic ODB layer into the specific "files" backend and temporary object directory subsystems. This better encapsulates the path-handling behavior that was previously spread across multiple layers. The key changes:

1. The "files" backend now registers a chdir-notify callback to update its paths when the working directory changes, rather than having the ODB layer manage this.

2. Similarly, temporary object directories handle their own path updates through a new callback.

3. The patch removes now-unused functions for managing primary ODB replacement, as the individual sources handle their own path updates.

Justin's review notes several thoughtful observations:
- The path field remains in the base ODB source struct despite being files-backend-specific, suggesting this may change in future work
- Questions whether a comment about relative paths should be marked as NEEDSWORK
- Confirms the logic properly handles multiple files sources independently
- Initially confused about why temporary directories needed reparenting but recognizes this matches existing behavior

The changes appear well-motivated as part of the larger ODB abstraction effort, cleanly separating concerns between the generic ODB interface and backend-specific implementations. Justin's review suggests the patch is technically sound but could potentially benefit from some minor documentation clarifications.
