This is a reply from the Git maintainer Junio C Hamano to Patrick Steinhardt's RFC proposing autoconf deprecation in favor of Meson. Junio questions the framing of the discussion, pointing out that autoconf is not a standalone build system but rather a tool that generates Makefiles. He suggests the more meaningful comparison is between Makefile-based builds (with or without autoconf) and Meson as alternative build systems.

Junio's response indicates he may not fully share Patrick's enthusiasm for Meson as the primary build system, though he acknowledges the question itself is valid. His comment hints at a potential preference for keeping the traditional Makefile approach while recognizing the need for modernization. The reply maintains Junio's characteristic diplomatic style - raising substantive concerns while leaving room for continued discussion rather than issuing a direct veto.

This exchange highlights an important nuance in the build system transition that wasn't fully addressed in the original proposal: the distinction between autoconf (a configuration tool) and Make (the actual build system). The thread now appears headed toward clarifying whether the project wants to:
1. Just replace autoconf with Meson's configuration while keeping Make
2. Fully replace the Make-based build with Meson
3. Maintain parallel support for both approaches indefinitely

Junio's intervention suggests the original proposal may need refinement to properly separate these concerns before the deprecation timeline can be meaningfully discussed.
