This is the final patch in a series converting Git's oidmap cleanup to use explicit, type-safe callbacks. Patrick Steinhardt weighs in on Junio C Hamano's review of Seyi Kuforiji's patch for the sequencer subsystem, suggesting a narrower scope for the overall effort.

The patch itself converts string_entry cleanup in sequencer.c to use the new `oidmap_clear_with_free()` API, adding a simple `free_string_entry()` helper. Junio notes that while this provides minimal immediate benefit (since the entries are just strings), it would make future maintenance easier if the entries grow more complex.

Patrick proposes keeping only the first two patches in the series (rev-list and list-objects-filter conversions) and dropping the remaining ones, arguing that converting all callsites without immediate benefit makes the code harder to understand. He suggests reserving the new API for cases where entries actually need resource cleanup.

The thread shows the series is technically sound but reveals differing opinions about when the new API should be adopted. Patrick's position reflects a pragmatic approach to API migration - introducing the capability but only applying it where immediately useful. The series now awaits a decision from Junio on whether to accept it as-is or trim it back.
