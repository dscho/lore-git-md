This is a technical follow-up in Patrick Steinhardt's ongoing object database (ODB) refactoring series, specifically addressing the pluggability of alternate object database handling. Justin Tobler raises a thoughtful question about the implications of making `read_alternates()` a pluggable callback in the ODB source interface.

The patch introduces a new callback in `struct odb_source` to allow different ODB backends to implement their own logic for reading alternate object database references. The interface expects alternates to be specified in a "objectStorage" extension format (`(backend://)?payload`), with paths resolved to absolute form.

Justin notes that while the change appears technically sound, the commit message could better explain the practical implications - particularly whether this enables alternates files to specify backends explicitly (like `files://` prefixes). He observes this functionality isn't yet implemented, suggesting either the documentation should clarify this is future-facing or the implementation should be more complete.

This exchange shows the series maturing into finer-grained interface discussions, with Justin providing his characteristic careful review focused on clear contracts between components. The question doesn't indicate any blocking issues, but rather seeks to ensure the design is properly documented and future-proof.
