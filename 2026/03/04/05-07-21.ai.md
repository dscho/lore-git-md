This is a follow-up in the thread about configurable partial clone filters, now focused on the URL matching implementation details. Patrick Steinhardt responds to Junio Hamano's question about URL matching granularity, proposing to reuse Git's existing `http.<url>.*` pattern matching behavior for the new `clone.<url>.defaultObjectFilter` configuration.

The key technical points are:
- The URL matching would support three levels of granularity: full domain (e.g. "github.com"), namespace (e.g. "gitlab.com/example"), and full project path (e.g. "gitlab.com/example/project.git")
- This matches Git's existing behavior for HTTP configuration, providing consistency
- The proposal maintains the previously agreed clone-only scope, avoiding impact on subsequent fetches

The discussion has narrowed to this final implementation detail after reaching consensus on the broader design. Patrick's response suggests this would cover most use cases while keeping the implementation simple and consistent with existing patterns. With Junio having already approved the URL-based configuration approach, this likely represents the last technical hurdle before finalizing the feature.
