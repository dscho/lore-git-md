Feature patch for `git send-email` client certificate support, now approved for merging.

This patch series adds client certificate authentication support to `git send-email`, addressing security requirements in environments that mandate certificate-based SMTP authentication. The implementation supports both PEM and PKCS12 certificate formats to match real-world email clients like Thunderbird and K-9 Mail, while maintaining compatibility with existing SMTP authentication methods.

The final version includes three new configuration options following Git's established SMTP configuration patterns: `sendemail.smtpSSLClientCert` for certificates (PEM or PKCS12), `sendemail.smtpSSLClientKey` for PEM keys when using separate key files, and corresponding command-line flags. The implementation builds on Perl's existing IO::Socket::SSL library without introducing new dependencies, and follows RFC 8446 by letting the SSL library handle certificate presentation automatically.

Junio C Hamano has reviewed and approved the technical approach after the author clarified SSL library behavior and real-world constraints. The accompanying documentation covers server-side verification, format-specific key handling, security rationale for dual-format support, and standards-compliant presentation behavior. With no outstanding technical issues, this feature is now cleared for merging into the `next` branch.
