This is a platform compatibility patch adding Windows support for `pthread_cond_timedwait()` to enable fsmonitor's inotify cookie synchronization on Windows. The implementation uses Windows' `SleepConditionVariableCS()` with proper timeout conversion from the absolute timespec deadline to milliseconds.

The patch:
- Adds the function to `compat/win32/pthread.c` with careful time conversion between timespec (nanoseconds) and Windows' millisecond timeout
- Handles the timeout expiration case by returning ETIMEDOUT if deadline has already been reached
- Maps Windows' ERROR_TIMEOUT to POSIX ETIMEDOUT while using existing `err_win_to_posix()` for other errors
- Includes the function declaration in the corresponding header file

This is part of the larger fsmonitor effort to bring Linux inotify support to parity with existing Windows/macOS backends. The timed wait functionality is needed for the fsmonitor daemon's cookie-based synchronization of directory rename events. While the implementation is correct, Patrick Steinhardt has noted two potential improvements that remain open: immediately returning ETIMEDOUT for already-passed timeouts (which this patch does correctly) and extending `err_win_to_posix()` to handle timeout errors more cleanly.
