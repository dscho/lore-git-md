This is a follow-up documentation and test improvement for the recently merged `status.compareBranches` feature, which allows configuring multiple branch comparisons in `git status` output. The patch comes from Junio Hamano incorporating Harald Nordgren's changes to clarify behavior that was already implemented but not fully documented.

The changes explicitly document that:
1. Branch comparisons are shown in config order
2. Duplicate entries resolving to same ref are suppressed
3. When `@{upstream}` and `@{push}` resolve to same branch, only one comparison shows

The test updates demonstrate this behavior more clearly by:
- Adding explicit tests for single-branch configurations
- Renaming test branches to avoid confusion
- Expanding the deduplication test case
- Using `git -C` consistently instead of subshells
- Verifying order preservation in the output

This represents the final polish on a feature that went through 31 iterations over two months (plus earlier work since 2016) before being merged to 'next'. The implementation already handled these cases correctly - this just makes the behavior more transparent to users and future maintainers.
