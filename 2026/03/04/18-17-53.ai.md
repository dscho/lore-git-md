This is the final patch in a series implementing Linux fsmonitor support, focusing on process management and cleanup in the daemon. The patch addresses file descriptor inheritance and process detachment issues that surfaced during testing.

The key changes here involve using `setsid()` to properly detach the fsmonitor daemon process and ensuring inherited file descriptors are closed before exec. This prevents resource leaks and ensures clean process separation. The implementation carefully balances between Unix daemonization patterns and Git's existing process management infrastructure, avoiding the full `daemonize()` approach which would break the parent-child IPC coordination.

The patch responds to review feedback by splitting out related but distinct changes (like timeout handling) into separate commits in the v8 series. It also clarifies why certain process group management remains necessary even with `setsid()`. The changes integrate with Git's `struct child_process` machinery through a new `close_fd_above_stderr` flag.

This completes the technical implementation of Linux fsmonitor support, with all review feedback addressed. The series has demonstrated production stability and handles edge cases like overlayfs limitations through fallback behavior. The patch represents the final polish on a major cross-platform feature that brings filesystem monitoring parity to Linux.
