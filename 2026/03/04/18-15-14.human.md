This is a bugfix patch addressing a memory leak in Git's fsmonitor daemon, part of the ongoing effort to bring Linux fsmonitor support to parity with Windows and macOS.

The patch fixes a specific issue where the `shown` hash table in the fsmonitor daemon's client handling code would leak memory when processing trivial responses. The leak occurred because cleanup was only reached in non-trivial response paths. Paul Tarjan's solution initializes the hash table to NULL and moves cleanup to a shared label, ensuring proper cleanup in all code paths.

This is the first patch in an 8th iteration series that has seen extensive review, with previous versions addressing race conditions, memory leaks, and portability issues. The fsmonitor work as a whole introduces Linux support using inotify, with performance benefits for status operations through filesystem event watching rather than full scans.

The change is straightforward and well-contained, touching only a few lines in `builtin/fsmonitor--daemon.c`. It follows the pattern of previous memory leak fixes in this series and appears ready for inclusion. The patch has already been tested in production at scale by the author.
