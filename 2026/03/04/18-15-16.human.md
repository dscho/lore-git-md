This is a platform compatibility patch adding Windows support for `pthread_cond_timedwait()` as part of the fsmonitor daemon effort. Paul Tarjan implements the function using Windows' `SleepConditionVariableCS()` with proper timeout conversion from the absolute timespec deadline to milliseconds.

The implementation handles edge cases like already-expired timeouts (returning ETIMEDOUT immediately) and maps Windows error codes to POSIX equivalents. This enables the fsmonitor daemon's synchronization logic to work consistently across platforms, particularly for the 1-second timeout used in the inotify cookie wait mechanism.

Patrick Steinhardt had raised questions about this implementation in earlier reviews, noting it should return ETIMEDOUT for passed deadlines (now addressed) and could benefit from cleaner error handling via `err_win_to_posix()`. Those refinements remain open but don't block the current functionality. The patch is part of a larger series that's been baking in Junio's 'seen' branch and appears production-ready.
