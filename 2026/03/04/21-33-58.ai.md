This is a technical discussion about the ongoing object database (ODB) refactoring effort, specifically addressing patch that makes `read_object_info()` pluggable via callbacks. The email is from Justin Tobler to Patrick Steinhardt, providing review feedback on the design decisions in patch 09/17 of the series.

Justin confirms his understanding of the complex interaction between object lookup and ODB reprepare operations. The key insight is that Git must first check all ODB sources for an object before triggering a reprepare (which might be expensive), since the object might exist in another source. The `OBJECT_INFO_SECOND_READ` flag introduced in the patch properly handles the case where a second read attempt is needed after reprepare, while avoiding redundant loose object checks.

The discussion reveals an important constraint in the ODB abstraction: while the reprepare logic conceptually belongs with the ODB source implementation, it must remain partially in the caller because the decision to reprepare depends on cross-source object lookup results. Justin's feedback indicates the design successfully navigates this complexity while maintaining the pluggable backend architecture.
