This is a process management patch in the fsmonitor daemon series, adding a mechanism to prevent file descriptor leaks in long-running child processes. The patch introduces a `close_fd_above_stderr` flag in `struct child_process` that, when set, closes all file descriptors above stderr (fd 2) in the child process after forking but before exec.

Junio Hamano suggests this might be better implemented as a more generic callback mechanism that callers could use for any pre-exec child setup, rather than baking in this specific behavior. The current implementation caps the scan at 4096 file descriptors for performance reasons when `sysconf(_SC_OPEN_MAX)` reports very high limits.

The change is part of the broader fsmonitor work to ensure clean process management, particularly important for the filesystem monitoring daemon that runs persistently. While the immediate need comes from fsmonitor, the mechanism could be useful for other long-running child processes in Git that need to avoid inheriting stray file descriptors from their parent.
