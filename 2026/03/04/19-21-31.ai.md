This is the second patch in a two-part bugfix series addressing issues with `git log -L` (line-log) when combined with pickaxe options (-G`, `-S`, `--find-object`). The first patch fixed a crash by modifying line-log's diff processing to call `diffcore_rename()` directly. This follow-up completes the solution by explicitly rejecting the unsupported combination with an error message rather than silently ignoring the pickaxe options.

The patch makes two main changes:
1. Adds error handling in `builtin/log.c` to detect and reject the combination of `-L` with any pickaxe option
2. Replaces the test cases that previously marked the silent ignore behavior as a known breakage with new tests verifying the explicit rejection

The implementation is clean and focused, with thorough test coverage that verifies the error message appears for all three pickaxe variants. The commit message clearly explains that while the current solution rejects the combination, the door remains open for a future series to properly implement support for these options with line-log.

This appears to be a well-contained fix from a first-time contributor that improves both stability (preventing crashes) and user experience (replacing silent failures with clear errors). The changes are limited to the relevant subsystems (`builtin/log.c` and the line-log test file) and maintain backward compatibility established by the first patch.
