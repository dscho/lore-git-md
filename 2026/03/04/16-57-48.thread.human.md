This thread addresses a critical bug in Git's promisor-remote subsystem where recursive lazy-fetching could lead to runaway resource consumption - a production issue that manifested as 276GB of promisor packs being written in just 90 minutes. The root cause was that when resolving missing REF_DELTA bases during a lazy fetch, index-pack could recursively trigger additional fetches in an unbounded chain.

The proposed fix is straightforward: propagate `GIT_NO_LAZY_FETCH=1` into the child fetch's environment to prevent recursion while still allowing the initial lazy fetch to proceed. The technical justification notes that with noop negotiation, servers shouldn't send problematic deltas in the first place, and recursion wouldn't help if they do. The patch includes tests verifying both the single-fetch behavior and proper environment variable propagation, using a reference-transaction hook to inspect the child process.

Maintainer Junio Hamano has reviewed the patch and agrees with the technical approach, though he provided some process feedback about GitGitGadget usage patterns and questioned whether the test needed its own dedicated file rather than being added to an existing promisor-related test script. The patch author hasn't yet responded to these meta-level suggestions, but the core technical solution appears sound and ready for merging once those minor points are addressed.
