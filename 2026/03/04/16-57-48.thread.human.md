Here's the updated human-readable thread summary:

This thread addresses a critical bug in Git's promisor-remote subsystem where recursive lazy-fetching could cause runaway resource consumption, with one production instance writing 276GB of promisor packs in 90 minutes. The issue occurs when a child `git fetch` process encounters a missing base object while processing a REF_DELTA, triggering an unbounded chain of fetches.

Paul Tarjan's solution propagates `GIT_NO_LAZY_FETCH=1` into child fetch processes to prevent recursion, following the pattern used in commit-graph.c. The technical approach was approved by Junio Hamano in v1, with v2 incorporating organizational improvements - consolidating tests into existing infrastructure (`t0411-clone-from-partial.sh`) and cleaning up commit message trailers. Tests verify both the single-fetch behavior and proper environment variable propagation using a reference-transaction hook.

The fix is well-motivated by real-world impact and maintains Git's existing behavior where servers using noop negotiation shouldn't send problematic deltas in the first place. With Junio's feedback addressed and no outstanding technical concerns, this appears ready for merging.
