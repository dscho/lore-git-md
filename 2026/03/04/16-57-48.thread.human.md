This thread addresses a critical bug in Git's promisor-remote subsystem where recursive lazy-fetching could lead to runaway resource consumption. The issue occurs when a child `git fetch` process spawned during lazy fetching encounters a missing REF_DELTA base object and itself triggers another lazy fetch, creating an unbounded chain. The author reports severe real-world impact, with one instance generating 276GB of promisor packs in 90 minutes.

The proposed fix is minimal but effective: propagating the existing `GIT_NO_LAZY_FETCH=1` environment variable into the child fetch's environment to prevent recursion while still allowing the initial lazy fetch. The patch includes a thorough commit message explaining why this is safe (servers shouldn't send problematic deltas with noop negotiation) and adds a new test that verifies both the single-fetch behavior and proper environment variable propagation using a reference-transaction hook. The change builds on prior related fixes (e6d5479e7a, 3a1ea94a49) and follows Git's standard patterns for environment variables and process spawning.
