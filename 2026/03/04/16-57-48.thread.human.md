This thread addresses a critical bug in Git's promisor-remote subsystem where recursive lazy fetches could cause runaway resource consumption, as demonstrated by Paul Tarjan's production data showing 276GB of promisor packs written in 90 minutes. The core issue occurs when a child `git fetch` process encounters REF_DELTAs against missing base objects in blob:none partial clones, triggering unbounded recursion.

The proposed fix, now at v3, propagates `GIT_NO_LAZY_FETCH=1` to child processes to prevent this recursion. Patrick Steinhardt has thoroughly reviewed the patch, questioning whether GitHub's behavior (sending such deltas) represents a server protocol violation. While the technical solution is sound, the discussion has revealed a potential server-side issue that may need separate attention. The v3 patch includes strengthened test coverage that clearly demonstrates both the failure mode and the fix's effectiveness.

Junio Hamano approved the technical approach earlier, and consensus is forming to merge the client-side hardening. Patrick has CC'd Jeff King for his expertise on partial clone behavior, as there's ongoing discussion about whether there are valid cases where servers should send such deltas. While the immediate fix is ready, this thread may spawn follow-up work on server-side pack generation for blob:none clones. The patch represents important client hardening regardless of the server protocol questions.
