The thread addresses a critical bug in Git's promisor-remote subsystem where recursive lazy fetches could cause runaway resource consumption (276GB of promisor packs written in 90 minutes in production). The issue occurs when a child `git fetch` process encounters REF_DELTA objects with missing bases in blob:none partial clones, triggering further fetches. 

Paul Tarjan's v3 patch provides a straightforward but effective fix by propagating `GIT_NO_LAZY_FETCH=1` to child processes, preventing the recursion. The latest iteration significantly strengthens test coverage, demonstrating the issue reproduces with GitHub's actual server behavior. While Patrick Steinhardt initially questioned whether this represented a server protocol violation, the production data has shown the client-side hardening is valuable regardless. 

Junio Hamano approved the technical approach earlier, and consensus is forming to merge the fix while potentially addressing server protocol concerns separately. The patch now includes thorough tests showing: (1) the recursive behavior with problematic thin packs, (2) reproduction using GitHub-like server behavior, and (3) the environment variable's effectiveness. The discussion suggests the commit message may be refined to better separate the client fix from server considerations, but the patch itself appears ready for merging.
