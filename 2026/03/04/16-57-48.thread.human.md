This thread addresses a critical bug in Git's promisor-remote subsystem where recursive lazy-fetching could cause runaway resource consumption (as evidenced by a production incident writing 276GB of promisor packs in 90 minutes). The issue occurs when `fetch_objects()` spawns child fetches that encounter REF_DELTA objects against missing bases in blob:none partial clones.

Paul Tarjan's v3 patch introduces a client-side fix by propagating `GIT_NO_LAZY_FETCH=1` to prevent recursion while maintaining correct delta resolution. Packet traces and two reproduction scripts (`repro-depth1.sh` and `repro-unbounded.sh`) conclusively demonstrate both the failure mode and solution effectiveness. The technical approach has been validated by Junio Hamano and Jeff King, with Patrick Steinhardt's questions leading to improved test coverage.

In follow-up discussion, Paul clarified that the "garbage collected" commits in the original report were actually prefetch refs from ephemeral CI branches, which doesn't affect the core issue but revealed two subtle behaviors: persistent blob filter rewriting during recursive fetches (despite previous fixes) and how manually unsetting promisor remote configuration served as a mitigation. While these edge cases may warrant separate fixes, the current patch is considered technically sound and ready for merging, having addressed all immediate concerns while identifying potential follow-up work in server-side pack generation and configuration management.
