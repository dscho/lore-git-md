This thread addresses a critical bug in Git's promisor-remote subsystem where recursive lazy-fetching could lead to runaway resource consumption (276GB of promisor packs written in 90 minutes in production). The original fix from Paul Tarjan proposed propagating `GIT_NO_LAZY_FETCH=1` to child fetch processes to break the recursion chain, which Junio Hamano had already reviewed as technically sound in v1. Paul's v2 incorporated Junio's feedback by cleaning up the test organization and commit message.

Patrick Steinhardt has now raised deeper questions about the root cause, suggesting the issue might stem from servers sending invalid packfiles containing REF_DELTA objects pointing to nonexistent bases - something that shouldn't happen with standard git-upload-pack behavior. While not opposing the client-side hardening, Patrick is seeking clarification on whether this is addressing an actual server protocol violation versus a theoretical edge case. He's requested the test demonstrate the actual failure mode rather than just verifying the environment variable propagation.

The core technical solution remains unchanged and was already approved by Junio, but Patrick's intervention has shifted the discussion to better understand the failure scenario. Paul will likely need to provide more context about the production environment where this occurred and whether non-standard server behavior was involved. The thread remains active with the fix conceptually sound but now undergoing deeper scrutiny of its underlying assumptions.
