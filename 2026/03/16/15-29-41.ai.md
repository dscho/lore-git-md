This is a cover letter for a 2-patch series that's part of the ongoing ODB (object database) abstraction effort. The series introduces a new helper function `odb_source_files_try()` to safely handle heterogeneous object source types during iteration, following the pattern used in the refs subsystem when adding the reftable backend.

The core problem is that 22 call sites currently assume all object sources are files-based (packfiles/loose objects) and downcast aggressively, which would BUG() if a non-files source were added. The series:
1. Adds a new `odb_source_files_try()` that returns NULL for non-files sources
2. Converts all iteration sites to use this helper, gracefully handling mixed source types

The changes touch 15 files including core object access paths, packfile handling, and adds a new unit test. The author notes this is a prerequisite for adding alternative ODB backends, though some display/optimization functions will still need follow-up work to properly account for non-files sources.

This appears to be a well-scoped, mechanical change that follows established patterns from similar refs backend work. The patch series is cleanly split between the new helper function and its application across the codebase. Given this is part of Patrick Steinhardt's larger ODB abstraction effort (with Justin Tobler also active in this area), it's likely to receive thorough review from that team.
