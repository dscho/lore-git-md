This is a localization (l10n) infrastructure patch in response to maintainer feedback about standardizing PO file filters. Jiang Xin proposes renaming and restructuring the `.gitattributes` configuration for Git's translation files to address Junio Hamano's concerns about language-specific filter assignments being misleading.

The key changes in this response:
1. Renames the filters to better match gettext terminology: `gettext-no-location` (strips both filenames and line numbers) becomes the default, while `gettext-no-line-number` (keeps filenames) is explicitly marked as requiring gettext 0.20+ and used only by specific l10n teams by preference.
2. Documents the technical rationale - the `gettext-no-line-number` variant's only benefit is helping locate source files from comments when not using `make po-update`.
3. Confirms both approaches provide equivalent storage savings, addressing Junio's concern about personal preferences versus technical requirements.
4. Explicitly calls out legacy unmaintained PO files that need filter disabling to avoid inconsistencies.

The response resolves Johannes Sixt's alignment question by providing clear recommendation for Gitk (use the simpler `gettext-no-location` default) while maintaining flexibility for teams that prefer keeping filenames.
