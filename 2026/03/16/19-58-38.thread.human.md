This thread addresses an improvement to `git apply`'s error reporting when parsing patch headers. Currently, when applying multiple patches, error messages only show line numbers when header parsing fails, making it difficult to identify which input file contains the error.

Jialong Wang (a GSoC participant) has submitted a patch that enhances this by including the patch input filename in error messages. The changes involve tracking the input source in `struct gitdiff_data` and updating error messages across several parsing routines in `apply.c`. The patch maintains backward compatibility while adding clearer context for debugging failed patch applications.

The implementation appears thorough, touching all major error paths in patch header parsing while following Git's coding standards. Test cases in t4100-apply-stat.sh verify the improved behavior. This seems like a straightforward quality-of-life improvement that will make `git apply` more user-friendly, particularly when working with multiple patches or corrupted input.
