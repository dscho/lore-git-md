This is a bugfix patch that improves error reporting in `git apply` for corrupt patches, now being merged by Junio Hamano after three iterations. The patch adds source file context to error messages (showing whether the patch came from stdin or a specific file) and properly resets line numbers between patch inputs - a subtle issue that went unnoticed for 20 years since Linus's original implementation.

The changes are minimal but impactful, touching just a few lines in `apply.c` while significantly improving debuggability for patch application failures. Junio notes this is particularly interesting because it reveals that almost nobody uses `git apply` with multiple patches in a single invocation (unlike `git am` which processes patches one at a time). He confirms the implementation is correct and queues the patch, while helpfully pointing out a few remaining spots in the codebase that could benefit from similar error message improvements as future work.

This was a Google Summer of Code contribution from Jialong Wang, who has been responsive to reviewer feedback throughout the process (notably incorporating Karthik Nayak's test case additions in v2). The patch is a clean, focused improvement that makes the codebase more maintainable while solving a real-world debugging pain point.
