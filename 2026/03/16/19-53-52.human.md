This is a feature addition to the `git replay` command, introducing revert capability primarily for GitLab's Gitaly service. The v4 patch series has already received thorough review from Phillip Wood and Junio Hamano, with all substantive technical issues addressed. Toon Claes now provides final stylistic feedback on the implementation.

The series adds a `--revert` mode that processes commits newest-first (matching `git revert` behavior) and drops empty revert commits by default. The implementation consolidates message formatting into a new `sequencer_format_revert_message()` helper function, following Phillip Wood's suggestion to handle all formatting in one place. The changes touch builtin/replay.c, sequencer.{c,h}, and related files.

Toon's review focuses on minor documentation and style nits rather than functional concerns, suggesting this is in the final polishing stage. The higher-level discussion about whether to use flags (`--revert`) versus subcommands (`replay revert`) continues but is being deferred to avoid scope creep. With Phillip Wood's approval and Junio's confirmation that the changes meet project standards, this appears ready for merging after addressing Toon's final suggestions.
