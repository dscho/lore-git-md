This is a review response to an RFC feature proposal for adding a `--graph-max` option to limit Git's graph output columns. The email comes from Karthik Nayak, who provides detailed feedback on Pablo Sabater's initial patch submission.

Karthik raises several substantive points about the proposal:
1. Questions the need for the feature given the TODO has existed since 2008 without being addressed
2. Suggests improving the message to better explain the problem being solved
3. Recommends against implicit behavior with `--graph`
4. Proposes `--graph-col-limit` as a clearer alternative name
5. Notes the implementation should use `unsigned int` rather than `int` for the column count
6. Suggests allowing 0 to mean "no limit" rather than introducing `MINIMUM_GRAPH_COLUMNS`
7. Provides example output showing the current behavior with '.' truncation

The review is thorough and focuses on both design questions (naming, behavior) and implementation details (type choices, validation). Karthik's feedback suggests the patch needs more justification for why this feature is needed now after 16 years, and that the implementation could be simplified by using unsigned integers with 0 meaning unlimited.

Key technical points for future reference:
- Current implementation uses `int graph_max_columns` in `rev_info`
- Proposed name change to `--graph-col-limit`
- Suggestion to remove `MINIMUM_GRAPH_COLUMNS` in favor of 0=unlimited
- Truncation currently shown with '.' character
- Test cases demonstrate 2 and 3 column limits

The review moves the discussion forward by identifying concrete areas for improvement while remaining constructive. It leaves open the fundamental question of whether this feature should be added at all, which will likely require input from other contributors familiar with the graph rendering code.
