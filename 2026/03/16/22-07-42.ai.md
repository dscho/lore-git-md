Bugfix for `git rev-parse --parseopt` help flag behavior. This patch implements the final agreed solution from the discussion between brian m. carlson and Jeff King about making help requests exit successfully (status 0) rather than reporting an error (status 129).

The change modifies the shell-eval mode of `--parseopt` to append an `exit 0` after the help text heredoc, ensuring scripts evaluating this output will exit cleanly when help is requested. The direct invocation mode retains the error exit code as a debugging aid to catch cases where shell eval is mishandled. Test updates verify both modes work as intended.

This brings the behavior in line with Unix conventions where help requests should exit cleanly, while maintaining the ability to detect incorrect usage patterns. The implementation is minimal and focused, touching only the heredoc output in `parse-options.c` and updating related test expectations. The solution carefully preserves backward compatibility with existing scripts that follow the recommended eval pattern from the documentation.
