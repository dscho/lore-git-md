Documentation patch converting the trailers configuration section to synopsis style, part of Kristoffer Haugsbakk's 4-part series standardizing the `git-interpret-trailers` documentation. This is the third patch in v2 of the series, following review feedback from Jean-Noël Avila and Junio C Hamano.

The patch mechanically reformats `Documentation/config/trailer.adoc` to match the project's documentation standards, making these key transformations:
- Wraps all config keys in backticks (e.g. `trailer.separators`)
- Replaces camel case `<keyAlias>` with kebab case `<key-alias>` throughout
- Standardizes formatting of placeholders and variables (using _underscores_ for placeholders)
- Updates cross-references to use linkgit macros
- Maintains all existing content while improving consistency with other modern Git documentation

The changes align with prior documentation conversions (0ae23ab5, 806337c7) and are part of the ongoing effort led by Jean-Noël Avila to standardize Git's documentation. No behavioral changes to the trailer configuration system are introduced - this is purely a formatting update (+61/-60 lines).

The patch follows established patterns from earlier in the series, with particular attention to:
- Consistent handling of command-line examples and config keys
- Precise formatting of placeholder variables
- Proper escaping of special characters in examples
- Clear deprecation notices for legacy syntax (`trailer.<key-alias>.command`)

This conversion completes the standardization of the trailers documentation, bringing it in line with the main command documentation converted in patch 1 and the option documentation in patch 2. The series demonstrates Git's collaborative documentation process, with both the documentation lead and maintainer providing careful review before accepting these mechanical changes.
