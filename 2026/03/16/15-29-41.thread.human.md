Justin Tobler has posted a 2-part series introducing infrastructure for Git's ongoing object database (ODB) abstraction effort. The first patch adds a new helper function, `odb_source_files_try()`, which safely handles mixed object source types by returning NULL for non-files sources rather than crashing. This enables iteration over different backend types while maintaining type safety.

The second patch, just posted, converts 22 call sites across core object access paths to use this new helper. The changes touch loose object handling, packfile management, and MIDX access, consistently replacing unsafe downcasts with the safer variant and adding NULL checks. A new unit test verifies the behavior. Some display and optimization functions will need follow-up work to fully support non-files sources.

This work is part of Patrick Steinhardt's multi-year effort to enable pluggable ODB backends, following patterns established in the reftable backend work. The changes appear well-executed and focused, adding necessary safety boundaries while maintaining existing behavior. As infrastructure for a major architectural change, it's likely to draw review from other ODB abstraction contributors like Karthik Nayak. The series looks uncontroversial so far, with no reviews posted yet.
