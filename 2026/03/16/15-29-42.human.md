This is a preparatory patch for the ODB (object database) abstraction effort, introducing a new helper function to safely handle mixed object source types. The patch comes from Aaron Paterson (not Justin Tobler as the thread context suggested - this appears to be a different contributor).

The change adds `odb_source_files_try()` as a graceful alternative to the existing `odb_source_files_downcast()` function. While the downcast version asserts the source must be files-based (BUG()ing if not), the new try variant returns NULL for non-files sources, allowing iteration code to skip incompatible sources. This follows a pattern established during the reftable backend work.

The patch is clean and focused - just 14 lines adding the new inline function with clear documentation. It touches only the header file, leaving the actual call site conversions for the follow-up patch. This appears to be a well-scoped, mechanical change that follows established project patterns for backend abstraction.

As part of Patrick Steinhardt's larger ODB effort, this foundational work will enable future introduction of alternative object storage backends. The change looks straightforward and uncontroversial, though it may receive careful review from the ODB abstraction contributors given its role in that ongoing effort.
