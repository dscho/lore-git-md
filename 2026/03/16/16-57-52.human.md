This is a feature addition to the `git replay` command, introducing a `--revert` mode that has now reached its final technical form after extensive review. The patch comes from Siddharth Asthana with feedback from Phillip Wood, addressing GitLab's need to revert commits directly on bare repositories without a working tree.

The implementation follows Git's established revert mechanics, treating reverts as merges with swapped arguments to reverse the diff direction. Key behaviors include processing commits newest-first (to reduce conflicts), generating standard revert commit messages, and dropping empty reverts by default. The code consolidates message formatting into a shared helper function from `sequencer.c`.

Phillip Wood's review confirms the technical implementation is sound, with only a minor documentation nit remaining about test script quoting style (using `${SQ}` rather than `'"'"'`). The patch includes comprehensive tests covering basic reverts, bare repository operation, revert-of-revert behavior, conflict handling, and mode incompatibilities.

This represents the culmination of a well-reviewed series that has incorporated feedback from multiple core contributors. While higher-level discussions about command interface design continue, the technical implementation is now complete and ready for merging. The change touches `builtin/replay.c`, test scripts, and documentation while maintaining clear boundaries with existing code.
