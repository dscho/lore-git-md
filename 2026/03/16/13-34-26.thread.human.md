This thread explores improvements to Git's commit graph visualization, focusing on two key issues: root commit spacing and lane limiting. Pablo Sabater, a GSoC participant, is leading the effort with guidance from maintainer Junio C Hamano. The current work centers on root spacing through minimal padding in graph.c, which Junio endorses as it maintains the graph's clean visual language of using `*` for all commits while improving readability through spatial layout.

Junio has reinforced the project's design philosophy that graphical output should primarily convey parent-child relationships through positioning rather than special markers or symbols. This aligns with Pablo's prototype implementation that uses empty rows to separate root commits, avoiding more intrusive solutions like separator lines or color coding. The approach has been demonstrated to properly space commits A1/A2 from B while preserving backward compatibility.

While the root spacing solution is taking shape, the related lane limiting redesign (addressing display glitches with `~` markers) remains on hold pending integration with these layout changes. Pablo is preparing a formal RFC patch for the root spacing implementation, after which attention will turn to combining both solutions. Johannes Sixt, who originally reported the lane truncation issues, has not yet weighed in on the spacing discussion. The thread shows promising progress toward a comprehensive solution that addresses both layout challenges while respecting Git's established visualization principles.
