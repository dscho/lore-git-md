This RFC thread centers on Pablo Sabater's proposal to add a graph column limiting option (`--max-columns`) to Git's log output, now at version 2. The feature caps displayed graph columns with '.' for excess lanes while preserving commit markers, addressing a 2008 TODO in graph.c (though not implementing gitk's rearrangement approach). The technical implementation is solid, with Karthik Nayak's review incorporated, including unsigned int usage, input validation, and explicit `--graph` requirement.

Junio Hamano's review of v2 raises key design questions. He suggests more precise option names like `--limit-graph-columns` to avoid implying general output width control, and questions whether the option should implicitly enable `--graph` rather than erroring. The maintainer also notes the current implementation's ancestry truncation does lose some information despite claims otherwise, and requests better documentation of the column calculation's magic numbers.

While the patch is functionally complete, Junio's feedback indicates the naming and user experience need refinement. Pablo will likely send a v3 addressing these higher-level concerns before the feature can proceed. The discussion has shifted from technical implementation to ensuring the interface aligns with Git's conventions and user expectations.
