Initial feedback from Karthik Nayak questioned the need for the feature and suggested technical improvements, including using `unsigned int` for the column count and making 0 mean "unlimited".

While the naming is still under discussion (`--graph-col-limit` vs `--graph-max-cols`), the technical direction is converging. Pablo plans a v2 addressing padding calculations, error handling when used without `--graph`, and improved commit messages, though there remains some disagreement about whether 0 should mean "no limit" (Karthik's preference) or be invalid (Pablo's position based on other Git options).

The discussion remains active, with the author waiting for broader consensus before sending the next version. Key files involved are graph.c (implementation), revision.h (API), and t4202-log.sh (tests). The patch series is still in design discussion, with no clear indication yet whether it will proceed to the next stage of review.
