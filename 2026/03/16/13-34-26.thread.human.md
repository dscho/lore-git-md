Pablo Sabater (a GSoC participant) has proposed adding a `--graph-lane-limit` option to Git's graph output, now in its fourth iteration. The feature addresses terminal readability for complex commit histories by capping the number of displayed graph columns, showing excess lanes as '.' markers while preserving the important '*' commit indicators. The implementation follows Git's conventions, using an `int` parameter where zero/negative values mean "no limit" (consistent with options like `--max-parents`).

The three-patch series is now complete, with all prior feedback from Junio Hamano, Karthik Nayak, and Johannes Sixt addressed. The final patch adds thorough documentation explaining the option's behavior and includes test cases verifying the lane limiting works correctly with different commit graph topologies. The tests specifically check that the display properly truncates excess lanes while maintaining the first hidden lane's commit indicator.

The changes are well-contained to the graph rendering code and documentation, with no outstanding technical issues. The series appears ready for final maintainer consideration. This implements a long-standing TODO from 2008 about improving graph output readability, though it stops short of the more extensive graph rearrangement seen in gitk. Future work could explore those directions, but the current solution provides a solid foundation for managing wide commit histories in terminal output.
