This thread discusses an RFC proposal from Pablo Sabater (a GSoC participant) to add a `--graph-max` option that would limit the number of columns shown in Git's graph output, displaying excess columns as dots while preserving commit markers. The initial implementation adds a `graph_max_columns` field to `rev_info` and modifies the graph rendering logic, with test cases for 2-3 column limits.

Karthik Nayak has provided a thorough review of the proposal, questioning whether this feature is needed given the TODO has existed since 2008 without being addressed. He suggests several improvements: a clearer name (`--graph-col-limit`), using `unsigned int` with 0 meaning "no limit" rather than introducing `MINIMUM_GRAPH_COLUMNS`, and avoiding implicit behavior with `--graph`. Karthik's review moves the discussion forward constructively while leaving open the fundamental question of whether this feature should be added at all.

Key open questions include the feature's naming and behavior (should it imply `--graph`?), technical implementation details (type choices for the column count), and how to handle edge cases in graph rendering. The thread awaits further discussion, particularly from contributors familiar with Git's graph rendering code, to determine whether this feature should proceed and in what form.
