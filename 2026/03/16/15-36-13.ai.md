This is a feature patch series that adds subcommand autocorrection to Git's parse-options API, now in its fourth iteration. The series extracts existing autocorrection logic from help.c into reusable components and applies it to subcommands in commands like `git remote` and `git notes`.

The key changes in v4 include:
- Complete build system integration (Makefile and meson.build)
- Renamed API prefixes from "autocorr" to "autocorrect" for consistency
- Adoption of standard Damerau-Levenshtein distance thresholds instead of legacy magic numbers
- Added comprehensive API documentation
- Various style fixes and commit message improvements

The implementation now cleanly separates:
1. Core autocorrection logic in new autocorrect.{c,h} files
2. TTY detection moved from help.c
3. Config resolution API for consistent behavior
4. Test coverage in t9004-autocorrect-subcommand.sh

Notable technical details:
- Defaults to enabling autocorrection for builtins with mandatory subcommands
- Requires explicit opt-in (PARSE_OPT_SUBCOMMAND_AUTOCORR flag) for commands with optional subcommands
- Currently implemented for `git remote` and `git notes` as examples
- Uses length-based thresholds (1 for <3 chars, 3 for 3-5 chars, 6 for longer) following common practice

The series appears well-polished with thorough test coverage and has addressed all previous feedback. The main outstanding question from earlier versions - about prefix matching behavior - has been resolved by abandoning the legacy weights in favor of standard algorithms. With build system integration now complete and all style/documentation feedback addressed, this looks ready for final review and potential merging.
