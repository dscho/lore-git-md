This is a feature proposal to add a `--graph-max` option to limit the number of columns displayed in Git's graph output. The patch comes from Pablo Sabater as part of Google Summer of Code (GSoC).

The proposed change would allow users to cap the width of the graph visualization with `--graph-max=<n>`, replacing any columns beyond the limit with a single dot ('.'). The commit character ('*') would still be shown regardless of the limit. The implementation includes validation to ensure the minimum column count is respected.

The patch addresses a longstanding TODO in graph.c about limiting columns similar to gitk's approach. It touches the graph rendering logic across several functions to handle the truncation consistently. The author has included some test cases but notes there are still open design decisions around:

- Whether `--graph-max` should imply `--graph`
- The choice of '.' as the truncation character
- How to handle merges and outside branches in truncated output
- Edge cases around commits appearing in truncated columns

The implementation currently has some known issues with post-merge line padding. The author is seeking feedback on the overall approach before adding more comprehensive test coverage. This appears to be a well-motivated change that could make complex graphs more readable in constrained terminal widths.
