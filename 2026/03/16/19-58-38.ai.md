This is a bugfix patch that improves error reporting in `git apply` when parsing patch headers. The patch comes from Jialong Wang as part of Google Summer of Code (GSoC).

The core issue is that when applying multiple patches, current error messages only report line numbers when header parsing fails, making it hard to identify which input file contains the error. The patch modifies several error paths in `apply.c` to include the patch input filename in error messages when available. Key changes include:

1. Adding a `patch_input_file` field to `struct gitdiff_data` to track the input source
2. Updating error messages in functions like `parse_traditional_patch()`, `gitdiff_verify_name()`, and `parse_mode_line()` to include filename context
3. Modifying `parse_git_diff_header()` to accept and pass through the input filename
4. Adding new test cases in t4100-apply-stat.sh to verify the improved error reporting

The changes are mechanical but thorough, touching all the major error paths in patch header parsing. The patch includes good test coverage for the new behavior. This appears to be a well-scoped quality-of-life improvement that makes `git apply` more user-friendly when dealing with multiple patches or corrupted input.

From the implementation perspective, the patch follows Git's coding style and maintains backward compatibility by still supporting the line-number-only error messages when no input filename is available. The changes to `parse_git_diff_header()`'s signature could potentially affect other callers, but the patch updates the only external caller in `range-diff.c` to pass NULL for the filename parameter, preserving existing behavior there.
