This is the second patch in a 2-part series that's part of the ongoing ODB (object database) abstraction effort. The patch converts 22 call sites across 11 files to use the new `odb_source_files_try()` helper introduced in patch 1, which safely handles mixed object source types during iteration by returning NULL for non-files sources rather than BUG()ing.

The changes touch core object access paths including loose object handling, packfile management, and MIDX access. Each conversion follows the same pattern: replacing `odb_source_files_downcast()` with `odb_source_files_try()` and adding a NULL check before accessing files-specific members. The patch maintains the invariant that direct access to odb->sources (the primary source) still uses the BUG()-enforced downcast variant.

A new unit test verifies the helper's behavior for both files and non-files sources. The author notes that some display and optimization functions like `repo_approximate_object_count()` will still need follow-up work to properly account for non-files sources.

This appears to be a well-executed mechanical conversion that follows established patterns from similar refs backend work. The changes are focused and consistent, touching only the necessary call sites while maintaining clear safety boundaries. Given this is part of Patrick Steinhardt's larger ODB abstraction effort (with Justin Tobler also active in this area), it's likely to receive thorough review from that team. The patch series as a whole provides important infrastructure for enabling pluggable ODB backends while maintaining type safety.
