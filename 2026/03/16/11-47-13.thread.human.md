Jialong Wang has proposed extending the new `git repo info` command to provide structured path information (like git directory, working tree root, and superproject paths) as a more maintainable alternative to piecing together `git rev-parse` calls. The initial proposal received detailed feedback from Karthik Nayak (GitLab), who suggested improvements to the proposal structure, emphasized the need for clear integration with existing `rev-parse` tests, and recommended combining implementation with documentation and testing in each commit.

In a follow-up, Jialong acknowledged the feedback and indicated plans to revise the proposal to better clarify the project's direction and timeline. The discussion is now focused on refining the design - particularly around output format decisions (relative vs absolute paths) and determining which metadata to include initially - before implementation begins. This is part of Google Summer of Code preparatory work, building on Jialong's earlier microproject contributions. The thread remains in the design phase with active technical disagreements, awaiting an updated proposal that addresses the review feedback.
