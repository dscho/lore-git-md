This is part 1 of a 2-patch series introducing infrastructure for the ODB (object database) abstraction effort, specifically adding a helper function to safely handle mixed object storage backends.

The patch adds `odb_source_files_try()`, a variant of the existing `odb_source_files_downcast()` that returns NULL rather than crashing when encountering non-files object sources. This follows the pattern used elsewhere in Git where "try" variants provide graceful fallback paths while maintaining strict type safety where needed. The change enables future work to introduce alternative ODB backends by allowing iteration over mixed source types without requiring every source to be files-based.

The implementation is straightforward - a static inline function that checks the source type before performing the container_of cast. The commit message clearly explains when to use the new function versus the existing downcast variant, and notes this is preparatory work for a follow-up patch that will convert iteration sites to use the new function.

This appears to be a well-scoped, mechanical change that follows established patterns from similar refs backend work. The patch touches core object access paths but is limited to adding the helper function without yet modifying any call sites. Given this is part of Patrick Steinhardt's larger ODB abstraction effort, it's likely to receive thorough review from that team.
