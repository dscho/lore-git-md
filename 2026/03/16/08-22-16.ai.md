This is a follow-up clarification about Git repository discovery behavior, specifically regarding `git describe --dirty` when used with repository specification options. Patrick Steinhardt adds to Junio C Hamano's explanation by suggesting the simpler `-C` option as an alternative to explicitly specifying both `--git-dir` and `--work-tree`.

The thread has established that the original reported behavior is not a bug but rather expected interaction between repository discovery and working tree state checking. Patrick's contribution reinforces this by noting that `--git-dir` is typically only for specialized cases, while `-C` (change directory before operation) provides a more straightforward way to run Git commands from outside a repository.

The key technical point remains that commands checking working tree state (like `describe --dirty`) need proper working tree context - either via being run from the correct directory, using `-C`, or explicitly specifying both `--git-dir` and `--work-tree`. This thread appears to be converging on documentation improvements as the appropriate next step rather than code changes.
