This is a bugfix patch that improves error reporting in `git apply` for corrupt patches, now being queued by Junio C Hamano after three iterations. The patch adds input source identification (filename or stdin) to error messages and properly resets line numbers between patch inputs - changes that help debugging when multiple patches are processed in one invocation.

Junio notes the patch reveals an interesting historical detail: this issue went undetected for 21 years because `git apply` is rarely used with multiple patches in practice (unlike `git am` which processes them separately). He confirms the implementation is correct but points out similar error reporting improvements could be made in other parts of `apply.c` (like `find_header()` and `parse_git_diff_header()`) as future work.

The patch appears ready for merging, having incorporated all prior feedback from Karthik Nayak and maintained a clean, focused scope. This was a Google Summer of Code contribution by Jialong Wang, who demonstrated good responsiveness to review comments across the three versions. The changes are minimal but meaningful - just a few lines modifying error format strings and resetting state, plus comprehensive test coverage. This should particularly benefit automated systems that process multiple patches at once.
