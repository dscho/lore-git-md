This is a bugfix patch that improves error reporting in `git apply` when parsing patch headers. The patch comes from Jialong Wang as part of Google Summer of Code (GSoC).

The core issue is that when applying multiple patches, current error messages only report line numbers when header parsing fails, making it hard to identify which input file contains the error. The patch modifies various error paths in `apply.c` to also report the input filename where available, providing more context for debugging.

Key changes include:
1. Adding a `patch_input_file` field to track the source of patch content
2. Updating error messages in functions like `parse_mode_line()`, `gitdiff_verify_name()`, and `parse_git_diff_header()` to include filename context
3. Adding new test cases in t4100-apply-stat.sh to verify the improved error reporting

The patch appears well-structured with clear commit message and motivation. It touches only the intended areas and includes corresponding test updates. This should be a straightforward improvement that makes `git apply` more user-friendly when dealing with malformed patches, particularly in batch operations.
