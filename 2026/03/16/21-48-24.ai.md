Documentation patch converting the `git-interpret-trailers` man page to the project's standard "synopsis style" format, part of Kristoffer Haugsbakk's 4-part series to align this command's documentation standards. This first patch focuses on restructuring the main command documentation with standardized SYNOPSIS section, backtick-wrapped inline code, and updated trailer examples.

The changes are mechanical formatting updates (+73/-72 lines) following established patterns from prior documentation conversions (0ae23ab5, 806337c7). Key transformations include replacing camel case `<keyAlias>` with kebab case `<key-alias>`, using "`:`{nbsp}" for verbatim text with trailing spaces (citing `pretty-formats.adoc` as precedent), and converting option descriptions to the standard format. The patch carefully handles self-referential documentation by using plain "git-interpret-trailers(1)" rather than a linkgit macro that would create a circular reference.

This patch introduces no behavioral changes to the command itself - it purely updates documentation formatting to match the project's evolving standards.
