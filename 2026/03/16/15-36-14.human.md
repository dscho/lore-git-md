This is a refactoring patch that extracts subcommand handling logic from `parse_options_step()` into a new `handle_subcommand()` helper function. It's the first patch in Jiamu Sun's series adding subcommand autocorrection support to Git's parse-options API.

The change simplifies the flow by:
1. Making `parse_subcommand()` return a simple success/failure status instead of multiple parse_opt_result values
2. Moving the subcommand branch into a dedicated function
3. Removing the switch statement over impossible return values

The patch maintains all existing behavior while making the code easier to follow. It's a clean preparatory change for the autocorrection feature that follows in later patches of the series. The implementation looks solid and well-tested, with no obvious issues. This foundational work will support the more visible autocorrection functionality being added in subsequent commits.
