This is a documentation patch discussion about improving discoverability of cherry-pick conflict information. Phillip Wood and Florian Best have concluded that adding a new `--show-current-patch` flag to `git cherry-pick` is unnecessary since `git show CHERRY_PICK_HEAD` already provides equivalent functionality with more flexibility. 

The thread has shifted focus to improving the man page documentation to make this existing capability more visible. Phillip suggests adding an example showing `git show CHERRY_PICK_HEAD` to the Examples section of the cherry-pick documentation, and invites Florian to contribute that patch. This would address the original discoverability concern without introducing new porcelain.

The discussion highlights Git's design philosophy of favoring composable plumbing commands over specialized porcelain when possible. The resolution demonstrates how documentation improvements can sometimes be preferable to adding new features when existing capabilities already meet the need but aren't sufficiently visible to users. No technical objections remain - the remaining work is purely documentation-focused.
