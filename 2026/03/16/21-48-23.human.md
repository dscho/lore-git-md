This is a documentation patch series (now 4 parts) converting the `git-interpret-trailers` man page and related config documentation to the project's standard "synopsis style" format. It's part of the ongoing documentation standardization effort led by Jean-Noël Avila, with Kristoffer Haugsbakk as the author.

The series has evolved through review feedback, with v2 adding a new patch (4/4) to align the source code's translation strings with the documentation's kebab-case `<key-alias>` convention. The changes are mechanical formatting updates (+220/-198 lines total) following established patterns from prior documentation conversions.

Key changes in v2 include:
- Replacing camelCase `<keyAlias>` with kebab-case `<key-alias>` throughout
- Using "`:`{nbsp}" for verbatim text with trailing spaces
- Adding missing negated options (like `--no-only-input`)
- Improving option ordering and descriptions
- Updating the source code to match documentation conventions

The patches have received thorough review from both Jean-Noël Avila (documentation lead) and Junio C Hamano (maintainer), with all initial concerns addressed. The series demonstrates Git's collaborative documentation process, where even minor formatting choices like space handling in verbatim examples receive careful scrutiny. With the final placeholder naming adjustment, the series is now ready for integration.
