This is a final refinement to the reference-transaction hook patch, addressing internationalization and error message clarity. Eric Ju (with contributions from Patrick Steinhardt and Justin Tobler) updates the error messages to precisely identify the reference-transaction hook as rejecting updates during specific phases ("preparing" or "prepared"), rather than using the phase names as if they were separate hooks.

The changes follow Junio Hamano's guidance that phase names like "preparing" are fixed API tokens that should not be translated, while making the error messages more technically accurate. The new wording clearly distinguishes between the hook's identity (reference-transaction) and its operational phase (preparing/prepared), maintaining the stable hook API contract.

This represents the last polishing of an already-approved patch that adds a "preparing" phase to Git's reference-transaction hook mechanism. The change enables distributed Git storage systems like GitLab's Gitaly/Praefect to coordinate concurrent writes earlier in the transaction flow. With all review feedback addressed, including Junio's suggested improvements to error messaging, the patch is ready for integration.
