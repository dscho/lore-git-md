This is a discussion about improving cherry-pick documentation rather than adding a new feature. Phillip Wood and Florian Best have been discussing whether `git cherry-pick` needs a `--show-current-patch` flag similar to what `git rebase` offers. Phillip pointed out that users can already inspect the current cherry-pick commit using `git show CHERRY_PICK_HEAD`, which provides more flexibility than a dedicated flag would.

Florian has now agreed that adding the flag might not be necessary, acknowledging that the existing functionality was just not clearly documented. He suggests improving the man page's Examples section to show the `git show CHERRY_PICK_HEAD` usage pattern. Phillip supports this direction and invites Florian to contribute the documentation patch.

The thread shows how Git often prefers improving documentation of existing capabilities over adding new porcelain commands when the plumbing already provides equivalent functionality. The discussion has reached consensus that better documentation is the right solution here, avoiding the need for new code while making the existing feature more discoverable.
