This is a bugfix patch (v2) that improves error reporting in `git apply` when processing corrupt patches. The patch is part of Jialong Wang's Google Summer of Code contribution and has already incorporated reviewer feedback from Karthik Nayak.

The core improvement makes `git apply` report both the input source (filename or stdin) and line number when encountering a corrupt patch, rather than just the line number. This helps users quickly identify which patch in a sequence contains the error. The v2 update adds two key refinements: resetting the line counter for each new patch input (so line numbers are always relative to the current file), and adding a test case for multiple patch inputs where one is corrupted.

The implementation is clean and focused, touching only a few lines in `apply.c` while adding comprehensive test coverage in `t4100-apply-stat.sh`. The changes include tests for single file input, stdin input, and the new multi-patch scenario. The patch appears complete and ready for merging, with all reviewer feedback addressed and no outstanding questions. This is a straightforward quality-of-life improvement that will make debugging patch application issues significantly easier.
