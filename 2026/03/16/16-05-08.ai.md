This is a GSoC (Google Summer of Code) proposal from Pablo Sabater to complete and extend the `remote-object-info` functionality for `git cat-file`. The proposal builds on Eric Ju's previous work that stalled after v11 due to unresolved issues, with mentorship from Christian Couder and feedback from Chandra Pratap.

The revised proposal (v3) addresses specific questions about backward compatibility raised in previous feedback, clarifying how different client/server version combinations will behave when handling the new `%(objecttype)` placeholder. It also reorganizes sections for better clarity and adds details about Pablo's pre-GSoC contributions, including several merged test patches and a newly discovered cleanup bug in Eric's implementation.

The technical work remains focused on two phases:
1. Rebasing and fixing Eric's existing implementation by:
   - Replacing the problematic `strstr()` validation with an `allow_list` approach (as suggested by Jeff King)
   - Addressing all outstanding code/style feedback from Junio Hamano and Jeff King
   - Fixing the cleanup issue between local/remote queries that Pablo discovered
2. Extending support for `%(objecttype)` by:
   - Modifying the v2 protocol on both server and client sides
   - Adding tests and documentation
   - Making type information part of the default output format

Pablo demonstrates strong preparation through his study of Eric's v11 series, merged test patches, and identification of new issues. The timeline is well-structured with clear milestones and includes community bonding activities. The proposal also outlines potential future extensions like supporting additional placeholders (`%(objectsize:disk)`, `%(deltabase)`) if time permits.

This represents a thoughtful continuation of stalled work that would benefit partial clone users. Pablo has already engaged productively with the Git community through smaller contributions and shows good understanding of the technical challenges involved. The mentorship from Christian Couder and feedback from other contributors suggests this is a promising candidate for GSoC selection.
