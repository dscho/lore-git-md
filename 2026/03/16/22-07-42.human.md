This is a bugfix patch addressing an inconsistency in `git rev-parse --parseopt`'s behavior with help flags. brian m. carlson implements the solution discussed in the thread, making the command exit with status 0 (success) when `--help` or `-h` is used, which matches Git's standard help behavior.

The key change is in `parse-options.c` where an "exit 0" is now appended after the help text in shell-eval mode. This ensures scripts using `--parseopt` will properly exit successfully when displaying help, while maintaining backward compatibility with existing usage patterns. The patch includes thorough test updates to verify both the new behavior and that error cases still produce the expected output.

The implementation follows the consensus reached with Jeff King (Peff) - keeping the error exit code in direct mode (for debugging) while fixing the shell-eval case that affects real-world usage. This is a clean, focused change that improves consistency with Unix conventions without breaking existing scripts.
