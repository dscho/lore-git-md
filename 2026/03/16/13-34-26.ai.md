This is a feature proposal for adding a `--graph-max` option to limit the number of columns displayed in Git's graph output. The patch comes from Pablo Sabater as part of Google Summer of Code (GSoC) and is marked as RFC (Request For Comments).

The proposed change adds a `--graph-max=<n>` option that caps the number of columns shown in graph output, replacing excess columns with a single dot ('.'). The commit character ('*') is always shown regardless of the limit. The implementation addresses a TODO comment in graph.c about limiting columns similar to gitk.

Key technical details:
- Adds `graph_max_columns` to `struct rev_info`
- Defines `MINIMUM_GRAPH_COLUMNS` as 1
- Modifies graph rendering logic in multiple functions to handle truncation
- Includes test cases showing 2 and 3 column limits

The author raises several design questions in the commit message:
- Should `--graph-max` imply `--graph`?
- Is `int` the right type for `graph_max_columns` (vs `uint32_t`)?
- Is '.' the best character for truncation?
- How to handle commits in truncated columns?
- How to show '/' lines to outside branches?

The patch appears to be a solid first attempt at implementing this feature, though the author acknowledges some limitations with post-merge line padding. The implementation touches core graph rendering logic and would benefit from thorough review, particularly around edge cases in complex merge scenarios. The test coverage is a good start but would need expansion as the design solidifies.
