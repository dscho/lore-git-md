Refactoring patch converting branch interpretation flags to an enum type (v2).

This is the second iteration of Jialong Wang's patch to replace the `INTERPRET_BRANCH_*` macro constants with an enum type, now renamed to `interpret_branch_kind` per Junio Hamano's suggestion in the v1 review. The change maintains the same bitmask behavior while providing stronger type safety for branch interpretation flags used across several Git subsystems.

The patch updates function signatures in `object-name.[ch]`, `refs.[ch]`, and `builtin/branch.c` to use the new enum type where branch interpretation options are passed. Key changes from v1 include:
- Renaming the enum from `interpret_branch_name_allowed` to `interpret_branch_kind` to better reflect that it describes branch types rather than permission semantics
- Keeping the original `INTERPRET_BRANCH_*` constant names as enum values
- Adjusting line wrapping and formatting to meet project conventions

The technical implementation remains straightforward - the enum preserves the existing bitmask values (1<<0, 1<<1, 1<<2) while making the type system enforce proper usage. Functions like `copy_branchname()` and `reinterpret()` now explicitly declare they operate on branch kind flags rather than generic integers. The patch also fixes header dependencies (refs.h now includes object-name.h).

This appears to be part of Google Summer of Code work focused on type system improvements. The changes are purely mechanical with no behavior modifications, addressing Junio's feedback from the previous version while maintaining the original goal of making the code more self-documenting and type safety. The patch looks ready for inclusion pending any final review comments.
