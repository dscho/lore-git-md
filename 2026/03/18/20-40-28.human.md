Feature implementation adding remote group support to `git push`, mirroring existing `git fetch` functionality. This is the second patch in a two-part series from Usman Akinyemi, implementing the core functionality after the preparatory refactoring in patch 1.

The patch teaches `git push` to accept a remote group name (configured via `remotes.<name>` config) and push to each member remote sequentially. Key implementation details:

- Rebuilds refspec lists per-remote to respect `remote.<name>.push` configurations
- Handles mirror flag per-remote to prevent force-push bleeding between remotes
- Accumulates exit codes via bitwise OR across all pushes
- Maintains identical behavior to individual pushes for `push.default=simple` and `--force-with-lease`

The documentation is expanded to explain remote group syntax and behavior, emphasizing that group pushes are exactly equivalent to sequential individual pushes. New test cases verify basic functionality, refspec handling, mirror conflicts, and edge cases.

This appears to be a well-considered implementation that follows the design principles established in discussion with Junio Hamano. The code changes are focused and the test coverage thorough. The feature fills a clear workflow gap while maintaining consistency with existing push semantics.
