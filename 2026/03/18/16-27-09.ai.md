Maintainer feedback on branch interpretation flags enum conversion.

Junio C Hamano responds to Jialong Wang's patch converting branch interpretation flags from macros to an enum type. While generally supportive of the type safety improvement, Junio raises several specific concerns about the implementation details.

He notes the patch has formatting issues - overlong lines without sign-off and inconsistent line wrapping in function declarations. More substantively, he questions whether "allowed" is the right name for the enum type itself, suggesting "interpret_branch_kind" would better reflect that the values represent types of branches rather than permissions. He also hints at potential future unification with similar enums used elsewhere in the branch machinery, though explicitly states this should not block the current patch.

The feedback maintains the project's characteristic attention to naming precision and long-term code structure while keeping the scope of the immediate change focused. Junio's comments suggest the patch is conceptually sound but needs minor adjustments to naming and formatting before being ready for inclusion. This is typical of the maintainer's style - catching subtle semantic and stylistic points while encouraging incremental improvements.
