This is a bugfix for gitweb that addresses a potential security issue where a hash parameter could be misinterpreted as a command-line option. Nicolas George reports that when gitweb's `hb` parameter (used to specify a tree hash) starts with a dash (e.g. `hb=-c`), it gets incorrectly interpreted as an option to `git ls-tree` rather than as a hash value. While this doesn't currently pose an active security risk due to `ls-tree`'s limited option set, it could become problematic if new options are added.

The patch adds a double-dash (`--`) before the hash parameter to prevent option parsing, which is a straightforward and effective fix. The report also notes that error messages from invalid hashes are being logged server-side when they should either be shown to the client or ignored, though this secondary issue would require more involved changes to address properly.

The patch appears well-targeted and uncontroversial - it's a clear correctness fix for an edge case that could have security implications. The author has thoughtfully considered the broader context, suggesting a code audit for similar patterns elsewhere in gitweb. The fix is small (just adding `--`) but meaningful for robustness.
