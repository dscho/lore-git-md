This is a performance optimization patch targeting the commit-reach.c code, specifically the `ahead_behind()` function. The change comes from René Scharfe, known for his clean refactoring patches.

The patch simplifies how leftover bitmaps are cleaned up in the `ahead_behind()` function. Instead of using a priority queue to free bitmaps one by one (which involves heap rebalancing overhead), it now uses the `deep_clear_bit_arrays()` function to free all remaining bitmaps at once. The new approach is more direct since the order of freeing doesn't matter at this cleanup stage.

Key technical details:
- Introduces a new helper function `free_bitmap_pointer()` to properly free bitmap pointers
- Replaces the prio_queue cleanup loop with a single call to `deep_clear_bit_arrays()`
- Maintains the same memory safety as the original (handles NULL pointers correctly)
- Touches only commit-reach.c, modifying the bitmap cleanup logic

The change is small (11 lines modified) but meaningful - it removes unnecessary heap operations during cleanup while maintaining the same functionality. This is characteristic of René's patches: focused, clean, and removing unnecessary complexity. The commit message clearly explains the motivation and notes that the change is safe (bitmap_free() handles NULL pointers).
