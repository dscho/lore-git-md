This is a feature proposal for `git log --graph` that would add a `--max-columns` option to limit the width of the graph output. The patch is now at v2 and has incorporated feedback from Karthik Nayak, but Junio Hamano raises several concerns in his review.

Junio questions whether the option name `--max-columns` is clear enough about only affecting the graph portion of the output, suggesting alternatives like `--limit-graph-columns` or `--limit-graph-lanes`. He notes that users might expect `--max-columns` to limit the entire output width rather than just the graph portion. He also points out that the current implementation silently ignores the option when `--graph` isn't specified, which could be confusing.

The maintainer provides specific feedback on the implementation details, asking for better comments explaining the magic numbers in the column width calculation (each lane takes 2 columns plus 2 columns for padding). He suggests the option could either be made to imply `--graph` automatically or be renamed to more clearly indicate it's graph-specific.

Junio also gently pushes back on the claim that "no information is lost" with this approach, noting that ancestry information is indeed lost when graph lines aren't drawn, though commit subjects remain visible. The thread shows the patch is nearing readiness but needs some final polishing around naming and documentation clarity.
