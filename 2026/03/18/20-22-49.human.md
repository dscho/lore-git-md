This is a bugfix for gitweb, addressing an issue where a hash parameter could be misinterpreted as a command-line option. Nicolas George reports that when gitweb URL parameters include `hb=-c` (hash base parameter set to "-c"), gitweb passes this directly to `git ls-tree -z` without proper argument separation, causing error messages in the server logs.

The patch adds a double-dash (`--`) before the hash parameter to prevent it from being interpreted as an option. While not currently a security issue (since `ls-tree` has limited options), this could become problematic if new options are added. The report also notes that error handling could be improved to avoid logging client-induced errors, though that would require more extensive changes.

The fix is straightforward and well-motivated, targeting a real (if minor) issue in gitweb's parameter handling. The patch appears to be a clean, focused solution to the immediate problem while flagging related concerns for future consideration.
