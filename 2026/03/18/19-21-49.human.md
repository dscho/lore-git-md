This is a feature patch in Adrian Ratiu's parallel hook execution series (v4 7/9), addressing maintainer feedback about configuration naming schemes. The patch implements per-event job count configuration via `hook.<event>.jobs`, allowing users to specify different parallelism levels for different hook events (e.g., `hook.post-receive.jobs = 4`).

Adrian responds to Junio Hamano's review by agreeing to add validation that warns when `hook.foo.jobs` is set for unknown event types, helping users avoid confusion between per-hook friendly names and per-event names. He also accepts Junio's suggestion to consider adding a master `hook.<event>.enabled` switch to disable all hooks for a particular event, though this would be implemented in a follow-up patch.

The exchange demonstrates the series' careful attention to configuration ergonomics and forward compatibility. With Junio having already approved the technical implementation ("looking quite well done"), this iteration focuses on refining the user-facing aspects of the feature. The patch maintains the series' layered approach to parallel hook execution while addressing edge cases that could confuse users.
