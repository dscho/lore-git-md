This is part 8/9 of Adrian Ratiu's parallel hook execution series (v3), focusing on output stream handling for hooks. The patch originally proposed a repository-wide `extensions.hookStdoutToStderr` configuration to merge stdout/stderr streams for parallel execution compatibility, but Junio Hamano suggested considering a per-hook approach instead.

Adrian acknowledges the feedback and proposes a simpler solution: since parallel execution is now opt-in (defaulting to serial), they can document that enabling parallelism implies merged output streams, eliminating the need for the extension. This maintains backward compatibility while allowing parallel execution when explicitly requested. The discussion reveals only one known case (git-lfs's pre-push hook) that depends on separate stdout/stderr streams.

The exchange shows Adrian's responsiveness to maintainer feedback and willingness to simplify the design. With this change, the series maintains its safety-first approach while removing unnecessary configuration complexity. The patch will be dropped in the next revision, demonstrating how technical discussions on the list lead to cleaner solutions.
