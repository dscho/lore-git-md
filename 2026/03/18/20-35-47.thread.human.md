This thread is about adding test coverage for `git repo info`'s behavior with linked worktrees and repositories using separate git directories. Jialong Wang's initial patch added tests for these cases, following existing patterns in t1900-repo-info.sh to verify both default and nul-delimited output formats.

Tian Yuchen reviewed the patch and noted that while technically correct, the tests create worktrees from an empty repository. They suggested using `test_commit` to add at least one commit first, as this would better reflect real-world usage where worktrees are typically created from repositories with content. The discussion remains focused on test quality improvements rather than functionality changes, since the patch only adds test coverage without modifying production code.

The review highlights an edge case in the implementation - while Git allows creating worktrees from empty repositories, testing with actual content would provide more representative coverage. This is a testing gap that could be addressed in a follow-up revision of the patch.
