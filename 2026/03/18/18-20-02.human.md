This is a feature patch (v3 pending) that adds graph column limiting to `git log` output, part of Pablo Sabater's GSoC project. The patch series has evolved through two rounds of review, with the latest iteration addressing maintainer feedback on naming and design.

The core feature lets users cap the width of the ancestry graph portion of `--graph` output, showing excess lanes as '.' characters while preserving commit markers ('*'). The implementation adds a `graph_max_columns` parameter to `rev_info` (minimum value 1) and modifies graph.c's rendering logic. Test cases demonstrate 2-3 column limits with merge scenarios.

Junio Hamano's review raised several key concerns that will shape v3 iteration: the current `--max-columns` name doesn't clearly indicate it affects only graph output (suggesting alternatives like `--limit-graph-lanes`), the need for better documentation of magic numbers in the column calculations, and whether the option should implicitly enable `--graph` rather than requiring it explicitly. The maintainer also noted the "no information lost" claim is overstated since ancestry lines are truncated, unlike gitk's interactive approach referenced in a 2008 TODO comment.

Pablo plans to address these in v3 by renaming the option to something like `--graph-limit-lanes`, adding explanatory comments about the column calculations (2 columns per lane plus 2 padding), and making the option imply `--graph`. The patch remains technically sound but needs these UX refinements before potential merging. This represents a focused, well-scoped addition to Git's visualization capabilities, with the main open question being how to best name and document the feature for users.
