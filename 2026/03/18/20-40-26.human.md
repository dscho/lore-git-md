This is an RFC patch series proposing to add remote group support to `git push`, mirroring the existing functionality in `git fetch`. The series comes from Usman Akinyemi, a relatively new contributor, and has already gone through one round of review with maintainer Junio Hamano.

The core idea is to allow pushing to all remotes in a configured group (defined via `remotes.<name>` in config) with a single command like `git push all-remotes`, similar to how `git fetch all-remotes` already works. The implementation splits into two parts: first moving some group-handling code from fetch.c to remote.c to make it reusable, then modifying push.c to leverage this shared infrastructure.

The v2 iteration addresses Junio's feedback by unifying the single-remote and group handling code paths, fixing some edge cases around direct path pushes, and adding initial test coverage. The author has also documented the key design principle that group push should behave identically to sequential individual pushes.

Several design questions were resolved in the RFC discussion:
- push.default=simple behavior will follow each remote's own upstream config
- force-with-lease semantics apply uniformly across the group
- The implementation now properly handles direct path pushes like `git push /tmp/foo.git`

The patch touches core remote-handling code in builtin/fetch.c and builtin/push.c, plus adds new declarations to remote.h. This looks like a well-scoped contribution that addresses a real workflow gap (fetch supports groups but push doesn't). The RFC phase appears largely complete with design questions answered, allowing implementation to proceed toward finalization.
