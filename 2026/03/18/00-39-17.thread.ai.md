Refactoring branch interpretation flags to enum type (v2). Jialong Wang's patch series converts `INTERPRET_BRANCH_*` macro constants to an enum named `interpret_branch_kind` in `object-name.[ch]`, `refs.[ch]`, and `builtin/branch.c`, affecting `copy_branchname()` and `reinterpret()` function signatures. The v2 changes addressed Junio Hamano's v1 feedback by renaming the enum from `interpret_branch_name_allowed` to better reflect branch type semantics while maintaining the original bitmask behavior (1<<0, 1<<1, 1<<2) and `INTERPRET_BRANCH_*` constant names as enum values.

Karthik Nayak's review raises a technical question about whether the bitmask capability (allowing flag combinations like `LOCAL | HEAD`) is actually needed in practice, suggesting the enum could potentially be simplified to sequential values if the combination behavior isn't required.
