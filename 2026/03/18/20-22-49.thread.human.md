This thread addresses a security edge case in gitweb where a tree hash parameter starting with a dash (e.g. `hb=-c`) could be misinterpreted as a command-line option to `git ls-tree`. Nicolas George reported the issue, noting that while currently harmless due to `ls-tree`'s limited options, this could become a security risk if new options are added.

The proposed fix is straightforward: adding a double-dash (`--`) before the hash parameter to prevent option parsing. The patch is small but important for robustness, and the author suggests a broader audit for similar patterns in gitweb. A secondary issue about error message handling was noted but would require more extensive changes to address properly.

The fix appears uncontroversial and well-targeted, addressing a clear correctness issue with potential security implications. The discussion so far suggests this is likely to be accepted as-is.
