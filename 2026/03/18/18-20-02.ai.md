This is a feature patch in the graph rendering subsystem, part of Pablo Sabater's GSoC project to add column limiting for graph output. The v3 iteration responds to Junio Hamano's design feedback on naming and behavior.

The patch now proposes `--graph-limit-lanes` as the option name, addressing Junio's concern that `--max-columns` was too generic. The implementation will make this option implicitly enable `--graph` rather than erroring when used alone. Pablo clarifies the column calculation (2 columns per lane plus 2 for padding/truncation) and agrees to document these magic numbers. The "no information lost" claim is retracted in favor of acknowledging the tradeoff between display width and ancestry visibility.

Key technical changes coming in v3:
- Renamed option to `--graph-limit-lanes` to clarify graph-specific behavior
- Implicit `--graph` when the option is used
- Better documentation of the column calculation (2*lanes + 2 padding)
- Removal of the redundant `--graph` requirement check
- More accurate description of information loss in truncation

The patch remains focused on the core column-limiting functionality while addressing the maintainer's UX concerns. The gitk-style rearrangement mentioned in the 2008 TODO remains out of scope, though Pablo notes it could be a future extension. This iteration appears ready for final review if the naming and documentation changes satisfy Junio's concerns.
