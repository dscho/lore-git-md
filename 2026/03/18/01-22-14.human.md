This is a bugfix discussion about standardizing exit codes for help flags in Git's option parsing. Jeff King (Peff) responds to brian m. carlson's analysis of potential backward compatibility issues when changing `git rev-parse --parseopt` to exit with status 0 (success) rather than 129 (error) for help requests.

Peff concurs with brian m. carlson's assessment that the change would be a strict improvement, noting that existing scripts either won't care about the exit status or are already working around the current behavior. He agrees this should be treated as a straightforward bug fix rather than waiting for Git 3.0, as the change is unlikely to cause problems and aligns with Git's standard help behavior.

The discussion appears to be reaching consensus, with both technical contributors and maintainer Junio C Hamano favoring the standardization. The patch will likely proceed as a regular fix, affecting all commands using Git's parse-options infrastructure. This follows earlier analysis showing the current 129 exit code was an accidental inheritance from 2007 code without intentional rationale.
