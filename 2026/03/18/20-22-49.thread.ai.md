Gitweb security fix for hash parameter interpretation. Nicolas George reports that gitweb's `hb` parameter (used to specify tree hashes) could be misinterpreted as a command-line option when starting with a dash (e.g. `hb=-c`), causing `git ls-tree` to parse it incorrectly. While not currently exploitable due to `ls-tree`'s limited option set, this could become a security issue if new options are added.

The proposed fix adds a double-dash (`--`) before the hash parameter to prevent option parsing, which cleanly addresses the issue. The patch is small but important for robustness. The report also notes a secondary issue where invalid hash error messages are incorrectly logged server-side rather than shown to clients or ignored, though fixing this would require more extensive changes.

The author suggests auditing gitweb for similar parameter-passing patterns elsewhere. The fix appears uncontroversial and well-targeted, addressing a clear edge case that could have security implications if left unpatched.
