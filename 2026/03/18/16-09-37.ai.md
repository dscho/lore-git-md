This is a performance regression report from René Scharfe regarding his earlier optimization patch for commit-reach.c's bitmap cleanup. The patch aimed to simplify the cleanup process by replacing a priority queue with a bulk-free approach, but benchmark results show it actually makes the operation about 10% slower.

The key finding is that while the original approach using `deep_clear_bit_arrays()` seemed theoretically cleaner, it ends up visiting more commit entries (including those with NULL bitmaps) than necessary. The priority queue approach, despite its heap operations, proves more efficient because it only processes the few remaining unvisited commits.

René suggests an alternative approaches - either reverting to the original method or trying an array-order traversal of the queue - but notes these show equivalent performance in his local repository. The thread demonstrates a valuable case where theoretical cleanliness didn't translate to actual performance gains, with the author promptly identifying and reporting the regression.
