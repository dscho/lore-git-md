This thread began with Randy Dunlap reporting that `git grep` failed to find a string ("vm_area_desc") in the Linux kernel repository. Junio Hamano quickly diagnosed the issue: Randy had used `git apply` without `--index`, which left the file untracked and thus excluded from `git grep`'s default search scope. Jeff King (Peff) elaborated on the key differences between `git apply` (which only modifies the working tree) and `git am` (which creates commits), recommending `git am` as the preferred workflow for email patches.

In a follow-up, Junio provided additional conceptual framing, explaining that `git apply` without `--index` is designed as a Git-enhanced replacement for the traditional `patch` command, operating outside Git's tracking context. He compared it to `git diff --no-index`, both being examples of Git commands that deliberately avoid repository integration. This helped explain not just what went wrong in Randy's case, but why these commands behave differently. The thread serves as a clear reference for understanding how Git's repository-aware and repository-agnostic operations interact, with the consensus being that this was a user education case rather than a Git issue. Randy confirmed the resolution and acknowledged the learning point about patch application methods.
