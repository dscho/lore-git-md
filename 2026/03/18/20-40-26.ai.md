This is an RFC cover letter for a feature adding remote group support to `git push`, mirroring the existing `git fetch` functionality. The series from Usman Akinyemi has progressed to v2 with significant refinements based on maintainer feedback.

The core feature allows pushing to all remotes in a configured group (defined via `remotes.<name>` config) with a single command like `git push all-remotes`. The implementation now cleanly unifies single-remote and group handling after Junio Hamano suggested treating a single remote as a group of one. Key design questions around `push.default=simple` and force-with-lease semantics have been resolved, establishing that group pushes should behave identically to sequential individual pushes.

Version 2 adds substantial improvements: a new test script (t5566-push-group.sh), documentation updates, removal of the UNUSED macro from headers, and proper handling of direct path arguments. The implementation now checks mirror/refspec conflicts per-remote and includes URL/path fallback support. The RFC phase appears complete with architectural alignment achieved - remaining work is final implementation polish, though parallel push support remains a potential future enhancement.

This is a well-scoped contribution that addresses a real workflow gap, with the author demonstrating responsiveness to maintainer feedback. The changes touch core remote-handling code but follow established patterns from the fetch implementation. The addition of tests and documentation in this iteration moves the series closer to being merge-ready.
