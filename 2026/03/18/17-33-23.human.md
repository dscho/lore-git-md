This thread concludes a discussion about `git describe --dirty` behavior when used with `--git-dir` outside the repository. The original reporter, Thomas Braun, acknowledges that the behavior he observed (incorrect dirty state reporting) is expected and not a bug, as clarified by Junio C Hamano and Patrick Steinhardt.

The key takeaway is that when using `--git-dir` without `--work-tree`, Git assumes the current directory is the working tree root, which can lead to incorrect dirty state detection. The proper solutions are either using both `--git-dir` and `--work-tree` together, or more simply using the `-C` option to change to the repository directory before the operation.

Thomas notes that his original use of `--git-dir` in 2014 predated widespread adoption of the `-C` option (added in 2013), and acknowledges the documentation already explains the correct approach. The thread serves as a useful reminder about Git's repository discovery rules and the preferred modern way to specify repository locations.
