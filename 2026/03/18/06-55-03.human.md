This is an RFC (Request for Comments) about path representation in the proposed `git repo info` command, focusing on whether paths should be relative or absolute by default. The author, Jayesh Daga, is considering extending this command to include various repository path information (like common_dir, toplevel, and git-path equivalents) and wants to establish consistent behavior before implementing.

The key question is that while some commands like `git rev-parse` return relative paths, other internal APIs use absolute paths. Daga suggests defaulting to relative paths for consistency with existing behavior and portability, while offering an `--absolute` flag for cases where explicit absolute paths are needed. The email seeks feedback on this design approach before proceeding further.

The patch appears well-motivated and thoughtfully presented, raising a clear design question that would benefit from community input. Since this is an RFC rather than a concrete implementation, the main value is in sparking discussion about path representation consistency in Git's output. The proposal seems reasonable but will likely need feedback from experienced contributors about edge cases and compatibility concerns.
