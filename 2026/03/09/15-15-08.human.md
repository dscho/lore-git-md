Junio C Hamano responds to Florian Schmidt's proposal to add parent repository execution to `git submodule foreach`. The maintainer expresses skepticism about the idea, pointing out that the superproject isn't technically a submodule. He suggests the existing workflow of running the command separately on the parent and submodules is clearer and more explicit.

This is a brief but significant response from the project maintainer that effectively rejects the proposed feature direction. Junio's position suggests the current approach is preferable to adding complexity to the submodule command. The exchange highlights Git's philosophy of keeping commands focused on their core purpose rather than accumulating convenience features.

For those following submodule-related development, this indicates the maintainer's preference for composable commands over monolithic ones, even if it means slightly more typing for users. The thread may be effectively closed unless Florian can present a stronger case that changes Junio's mind.
