This is part 6/9 of a feature series introducing parallel hook execution, building on Adrian Ratiu's prior work on configurable hooks. The patch adds a `-j/--jobs` command-line option to `git hook run` for controlling parallel execution, complementing the existing `hook.jobs` config option.

The implementation ensures TTY behavior differs between serial (`-j1`) and parallel (`-jN`) modes - parallel hooks output to pipes rather than directly to the terminal. The patch includes extensive test coverage verifying:
- Output grouping in parallel execution (no interleaving)
- Correct serial vs parallel behavior based on job count
- TTY handling differences between modes
- Interaction with `parallel=false` hook configurations

The tests use a sentinel/detector pattern to validate execution order and demonstrate that parallel execution respects safety constraints (hooks marked `parallel=false` still run serially even with `-jN`). The documentation is updated to explain the new option and its relationship to other parallelization controls in the series.

This is a well-tested addition to the parallel hooks infrastructure, providing users direct control over job concurrency while maintaining safety through careful handling of output streams and respecting existing serialization requirements. The patch fits cleanly into the larger series' architecture.
