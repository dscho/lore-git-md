This is a refactoring patch in a series aimed at reducing unnecessary strbuf usage, following patterns established by Junio Hamano's earlier cleanup work. The second patch modifies parse_combine_filter() in list-objects-filter-options.c to avoid using strbuf_split_str() when processing combine: filter specs.

The change replaces the strbuf-based splitting with direct string manipulation using strchr() and xmemdupz(), which is more straightforward for this case since the code only needs to read the string content. Junio notes the new approach may handle trailing '+' characters differently (not processing empty strings after them) but isn't sure if this behavioral difference matters in practice.

Junio suggests an alternative approach that would make a single copy of the input string and modify it in-place by replacing '+' delimiters with NULs, though he doubts the performance difference would be measurable. The patch appears technically sound and follows established cleanup patterns, though the subtle behavior change around trailing delimiters may need verification.

This continues the series' theme of making string ownership clearer while maintaining functionality. The first patch in the series was already approved, and this second one looks similarly uncontroversial aside from the minor question about edge case handling.
