This is a feature patch in the parallel hook execution series (v3 6/9), adding a command-line `-j/--jobs` option to `git hook run`. The patch builds on Emily Shaffer's prior work identifying mandatory serial hooks and Adrian Ratiu's configurable hooks infrastructure.

The key changes introduce:
- A new `-j/--jobs` option for `git hook run` that overrides the `hook.jobs` config when set
- TTY behavior differentiation between serial (-j1) and parallel (-jN) execution
- Test coverage verifying:
  - Output grouping in parallel mode
  - Serial execution order with -j1
  - Parallel execution detection with -j2
  - That parallel=false hooks block parallel execution even with -j2

The implementation maintains backward compatibility by defaulting to serial execution when neither config nor command-line specifies jobs. The patch includes thorough documentation updates explaining the new option and its interaction with the existing config hierarchy (global `hook.jobs`, per-hook `hook.<name>.parallel`, and now command-line `-j`).

This continues the series' careful balance between performance optimization and safety, ensuring critical hooks like commit-related ones always run sequentially while allowing parallel execution where explicitly configured. The tests demonstrate the system's behavior under various job count scenarios, including edge cases around TTY handling and output interleaving.
