Bugfix addressing unsafe argument parsing in `git apply -p`. The patch replaces `atoi()` with `strtol_i()` to properly validate the `-p` option's numeric argument, catching malformed inputs like "1q" that were previously silently accepted. The change maintains backward compatibility while adding proper error handling.

Junio C Hamano (the Git maintainer) has reviewed the technical change and finds it acceptable, but suggests consolidating the new test cases into an existing test script rather than creating a dedicated test file. The patch currently adds a new test script `t4142-apply-args.sh` with four test cases covering valid, malformed, non-numeric, and negative inputs.

This is a straightforward improvement to input validation that follows a similar pattern to previous fixes in the codebase. The change is small and focused, touching only the argument parsing logic in `apply.c`. While not a critical security issue, the fix prevents potentially confusing behavior when invalid arguments are passed to `git apply -p`.
