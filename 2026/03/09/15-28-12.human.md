This is a feature proposal for a new caching mechanism in Git. Skye Soss suggests adding an untrusted caching proxy that would work alongside existing remote repositories. Unlike current HTTP/SSH proxies that rewrite URLs and require full trust, this cache would be read-only and only used after verifying metadata from the real remote. The cache would be validated to prevent spoofing, with fallback to the real remote if needed.

The motivation is to enable simple per-site caching (similar to apt's DNS-SD caching) without requiring the full trust model of current proxies. This would help networks cache cloned repositories more safely, addressing Git's common (if unintended) use as a CDN. The proposal asks whether this is technically feasible given Git's internals.

The idea appears well-motivated for improving caching while maintaining security, though the technical details of implementation aren't specified. This would likely be a significant architectural change touching Git's remote fetching and object verification logic. The proposal is at an early stage, seeking feedback on feasibility before implementation.
