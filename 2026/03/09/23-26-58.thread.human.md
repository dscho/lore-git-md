This thread documents the resolution of a bug in `git apply -p`'s argument parsing, where malformed inputs were silently accepted due to unsafe use of `atoi()`. The fix, submitted by Mirko Faina, replaces this with proper validation via `strtol_i()` to ensure invalid inputs like "1q" are rejected with clear error messages.

After three iterations of review addressing technical feedback and test portability issues (particularly around Windows CRLF line endings), Junio Hamano merged the patch. Jeff King helped resolve the test portability problems by demonstrating the CRLF reproduction case and proposing the final approach of embedding patch data directly in the test script via heredocs. Post-merge, Tian Yuchen provided non-blocking stylistic suggestions around heredoc formatting and error message improvements, which the author and maintainer incorporated. The tests now comprehensively cover valid and invalid cases while avoiding platform-specific issues.

The solution follows Git's established patterns for argument validation, similar to a prior fix for the `-j` option. The thread concluded with the author sending a final version bump (v5) to document the complete history, showing how Git's merged patches often receive collaborative polish from both the maintainer and other contributors even after the initial merge.
