This thread addresses a bug in `git apply -p` where malformed arguments like "1q" were silently accepted (treated as "1") and non-numeric strings were treated as 0, due to unsafe `atoi()` usage. Mirko Faina's patch series replaces this with proper validation via `strtol_i()` in `apply.c`, fixing the issue while maintaining backward compatibility.

The test cases cover valid inputs, malformed numbers, non-numeric strings, and negative values.
