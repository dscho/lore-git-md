This thread addressed a bug in `git apply -p` where unsafe `atoi()` usage could silently accept malformed inputs. Mirko Faina submitted the initial fix, replacing `atoi()` with proper validation via `strtol_i()`. After three iterations and thorough review, Junio Hamano merged the core fix while noting some Windows-specific test failures remained to be addressed.

Jeff King later identified that the test failures stemmed from CRLF line endings in external patch files on Windows. He proposed two solutions, strongly advocating for inlining the test patch data directly in the script rather than relying on external files. The newly submitted patch implements this preferred approach, embedding test cases via heredocs to avoid platform-specific line ending issues while maintaining the same validation coverage. This completes the fix, with four comprehensive test cases now verifying both correct behavior and proper rejection of invalid inputs. The underlying CRLF parsing issue in `apply.c` remains open but is no longer blocking this particular fix.
