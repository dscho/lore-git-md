This thread addresses a bugfix for `git apply -p`'s argument parsing, where malformed inputs like "1q" were silently accepted due to unsafe `atoi()` usage. The original patch from Mirko Faina proposed replacing `atoi()` with proper validation via `strtol_i()` in `apply.c`, along with new test cases in a standalone file.

Junio C Hamano agreed with the technical fix but suggested consolidating the tests into an existing test script rather than creating a new one. In response, Mirko has sent a v2 patch that moves the test cases into `t4103-apply-binary.sh` while maintaining the same thorough coverage of valid/invalid inputs, including a new test patch file. The core fix remains unchanged - it still replaces `atoi()` with `strtol_i()` for proper validation, matching the pattern used in a prior similar fix for the `-j` option.

The patch now appears ready for merging, having incorporated the technical improvement and addressed the maintainer's feedback about test organization. This small but important change will make `git apply -p` more robust by properly rejecting invalid numeric inputs rather than silently accepting them.
