This is part of Adrian Ratiu's ongoing parallel hook execution series (v3 2/9), introducing infrastructure for unsigned integer config values. The patch adds a new `repo_config_get_uint()` helper and supporting functions to properly handle unsigned config values, which will be used by the upcoming `hook.jobs` configuration option in later patches.

The change is straightforward plumbing - it mirrors the existing signed integer config APIs but for unsigned values. The commit explains that while alternatives like using `int` with casting or `ulong` were possible, a dedicated `uint` helper is the cleanest solution for the job count use case. The implementation follows Git's established patterns for config value parsing.

This is a preparatory patch that enables the parallel hook execution feature to use proper type safety when reading job count configurations. The change is uncontroversial and well-contained, touching only config parsing infrastructure without any behavior changes to existing code paths.
