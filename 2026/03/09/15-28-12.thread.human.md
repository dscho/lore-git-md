Skye Soss has proposed adding an untrusted caching proxy mechanism to Git's remote operations. The key idea is that clients would first try fetching objects from a read-only cache while still connecting directly to the real remote for metadata. All cached objects would be cryptographically validated to prevent spoofing, with automatic fallback to the real remote if the cache is unavailable or missing objects.

The motivation comes from real-world usage patterns - while Git wasn't designed as a CDN, organizations often use it that way, and this proposal would allow network-level caching without requiring the full trust model of traditional proxies. It's positioned as being similar to apt's DNS-SD caching approach.

This is currently an RFC-level proposal without implementation details. The technical challenges would involve modifying Git's remote fetching and object verification subsystems to support this hybrid model while maintaining security. The thread appears to be in early discussion, as there are no code or detailed design documents attached yet. The core question is how to implement this caching layer without introducing new attack surfaces or complicating Git's existing object transfer protocols.
