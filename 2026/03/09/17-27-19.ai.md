Documentation patch updating the `-U` option syntax to match actual behavior. This follows up on Junio Hamano's discovery that `git show -U` without a number was being accepted despite documentation implying the number was mandatory. Tian Yuchen's analysis confirmed this lenient parsing is relied upon by test 157 in t4013, which expects `-U` to default to 3 lines of context like `-u` does.

The patch makes the documentation accurate by showing `-U[<n>]` as accepting an optional number, while keeping the existing implementation behavior. This resolves the discrepancy without breaking backward compatibility for tests or scripts. The change is minimal one-line edit to diff-context-options.adoc, clarifying that the short form can omit the number and will use the same context defaults as `--unified`.

This is a straightforward documentation fix that aligns the docs with long-standing behavior, avoiding the more disruptive alternatives of either breaking existing usage or changing the implementation to match the previously incorrect documentation. The patch is uncontroversial and well-motivated by the prior discussion.
