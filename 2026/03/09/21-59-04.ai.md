This is a follow-up discussion on Adrian Ratiu's hook configuration series, specifically addressing patch 9/10 which adds a `--show-scope` flag to `git hook list`. The patch displays the configuration scope (local, global, etc.) alongside hook names when requested.

Junio Hamano notes that the implementation meets expectations overall, particularly praising how it builds on the new `hook_config_cache_entry` structure introduced earlier. However, he raises a usability question about the output format when combining `-z` (NUL-terminated lines) with `--show-scope`. The current implementation concatenates the hook name and scope in parentheses on a single line, which might not be optimal for machine parsing.

Junio suggests that machine consumers might prefer the hook name and scope as separate, easily parseable fields within the same record when using `-z`. This isn't a blocking concern but represents a final polish opportunity before the series is merged. The discussion focuses on output formatting rather than core functionality, indicating the patch is otherwise in good shape.
