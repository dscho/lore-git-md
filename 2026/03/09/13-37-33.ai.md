This is part 3 of a 9-patch series introducing parallel hook execution, building on Adrian Ratiu's prior work on configurable hooks. The series provides multiple opt-in control points for parallelization, with this patch focusing on the global `hook.jobs` configuration.

The patch adds infrastructure to parse and cache a `hook.jobs` config value that specifies how many hooks can run simultaneously. The value defaults to 1 (serial execution) if unset, maintaining backward compatibility. The implementation includes validation to ensure the value is a valid positive integer, with appropriate warnings for invalid inputs.

Key technical details:
- Adds `hook.jobs` documentation in `Documentation/config/hook.adoc`
- Extends `hook_all_config_cb` struct to store the jobs value during config parsing
- Adds validation logic in `hook_config_lookup_all()` to parse and validate the unsigned integer
- Stores the final value in `hook_config_cache.jobs` for later use by the parallel execution logic
- The patch is mostly plumbing - the cached value isn't yet used (that comes in later patches)
- Follow-up patches will add per-event and per-hook overrides that can supersede this global setting

This continues the series' careful approach to parallelization by making it strictly opt-in at multiple levels while maintaining safety through explicit configuration. The implementation builds on the existing hook config infrastructure while adding the new unsigned integer parsing capability introduced in patch 2/9.
