This is a follow-up discussion about a bugfix targeting the diff option parsing inconsistency. Tian Yuchen investigates Junio Hamano's proposed fix for `git show -U` argument handling, where the current implementation incorrectly accepts `-U` without a number while properly rejecting malformed inputs like `-Unan`.

Yuchen confirms the patch would break test 157 in t4013, which explicitly expects `git diff -U` to default to 3 lines of context (matching `-u` behavior) rather than erroring out. The test suite's reliance on this lenient parsing presents a backward compatibility concern, as noted by Junio. The email also points out that the documentation in diff-context-options.adoc inaccurately suggests the number is mandatory when the current implementation treats it as optional.

The thread highlights a classic maintenance dilemma: whether to fix technically incorrect behavior that existing tests (and potentially user scripts) depend on. The patch would make the implementation match the stricter documented behavior, but at the cost of breaking established usage patterns. The discussion remains open-ended, with no clear resolution yet on whether to prioritize correctness or preserve backward compatibility.
