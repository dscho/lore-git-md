Thread identity: Bugfix patch addressing argument parsing in `git apply -p` by replacing unsafe `atoi()` usage with proper validation via `strtol_i()`.

Core problem: The `-p` option in `git apply` silently accepted malformed inputs like "1q" (treated as "1") and non-numeric strings (treated as 0) due to `atoi()`'s lack of input validation. This could lead to unexpected behavior when scripts or users provide invalid arguments.

Current status: Single patch version proposed, not yet reviewed or merged. The change is contained to `apply.c`'s argument parsing logic and adds new test coverage in `t/t4142-apply-args.sh`.

Key technical details: 
- Replaces `atoi(p_value)` with `strtol_i(p_value, 10, &nr)` in `apply.c`
- New test file `t4142-apply-args.sh` contains 4 test cases:
  - Valid numeric input ("1")
  - Malformed numeric input ("1q")
  - Non-numeric input ("q")
  - Negative number ("-1")
- Maintains backward compatibility with valid numeric arguments while rejecting invalid ones
