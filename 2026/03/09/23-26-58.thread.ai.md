Thread identity: Bugfix patch addressing argument parsing in `git apply -p` by replacing unsafe `atoi()` usage with proper validation via `strtol_i()`, submitted by Mirko Faina. Now merged by maintainer Junio C Hamano with follow-up test portability fixes completed.

Core problem: The `-p` option in `git apply` silently accepted malformed inputs due to `atoi()`'s lack of input validation. The fix ensures proper validation while maintaining backward compatibility, with subsequent discovery and resolution of Windows test portability issues related to CRLF line endings in test patch files.

Current status: Merged after three iterations, with test portability issues now fully resolved by inlining test patch data directly in the script (`t4120-apply-popt.sh`). This implements the solution proposed by Jeff King and completes the CRLF workaround.

Key technical details:
- Core change replaces `atoi(p_value)` with `strtol_i(p_value, 10, &nr)` in `apply.c`
- Final test solution uses heredocs to embed patch data directly in test script
- Comprehensive test coverage includes four new cases:
  1. Valid numeric input
  2. Non-numeric input rejection
  3. Malformed numeric input (trailing non-digit) rejection
