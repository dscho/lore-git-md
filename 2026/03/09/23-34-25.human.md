This is a patch series adding HTTP 429 (rate limiting) support to Git's HTTP client, now in its fifth iteration. Junio Hamano has reviewed and approved the first three patches, which fix strbuf_attach() usage across several files and introduce a helper function in remote-curl.c. These strbuf fixes ensure proper memory allocation for NUL termination and could potentially be merged independently.

The final patch - implementing HTTP 429 retry logic with Retry-After header parsing and configurable limits - still needs review from an HTTP transport expert (likely Jeff King or Taylor Blau, who have reviewed previous versions). The implementation includes comprehensive features: support for both delay-seconds and HTTP-date formats, new config options (http.maxRetries, http.retryAfter, http.maxRetryTime), environment variable overrides, and Trace2 integration.

The series appears technically sound with extensive test coverage, following Git's conservative defaults (maxRetries=0 by default). Junio's request for additional review suggests this is functionally complete but wants a second pair of eyes on the HTTP-specific changes before merging. The strbuf fixes could land sooner if the HTTP portion needs more work.
