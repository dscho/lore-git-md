Summary of RFC proposal for untrusted fetch caching:

Skye Soss proposes adding an untrusted caching proxy mechanism to Git's remote fetching, where clients would first attempt to fetch objects from a read-only cache while maintaining direct connections to the real remote for metadata. The cache would be treated as untrusted - all objects would be validated cryptographically before use, with fallback to the real remote if the cache is unavailable or missing objects. This aims to provide network-level performance benefits similar to apt's DNS-SD caching while avoiding the trust requirements of traditional HTTP/SSH proxies that rewrite URLs.

The proposal acknowledges Git wasn't designed as a CDN but recognizes its frequent use in such scenarios. Key technical questions center on whether Git's internals could support this model without major complications, particularly around the object transfer protocols and verification subsystems. The security model would need careful design to prevent cache poisoning while maintaining the untrusted nature. No implementation is yet attached - this is an initial RFC seeking feedback on feasibility and design direction.
