This is a feature proposal for `git submodule foreach` that would add two new options:

1. A flag to run the command on the parent repository in addition to submodules
2. A flag to continue execution when submodule commands fail (rather than aborting)

The author, Florian Schmidt, describes a workflow where they frequently need to run the same command on both submodules and the parent repo - for example when creating or deleting development branches across a project. While this can currently be done by running the command twice (once with `foreach` and once directly), they suggest this pattern might be common enough to warrant built-in support.

The proposal seems well-motivated by a concrete use case, though the author acknowledges workarounds exist. The second suggestion about error handling appears to be an afterthought rather than a core part of the proposal. This seems like a reasonable quality-of-life improvement that could benefit others with similar workflows, though it's not clear how widely needed this functionality would be. The patch would likely be small and focused if implemented.
