This is a patch series adding HTTP 429 (rate limiting) support to Git's HTTP client, now in its fifth iteration. Junio Hamano has reviewed and approved the first three patches, which fix strbuf_attach() usage across several files (ensuring proper NUL termination) and introduce a helper function in remote-curl.c for centralized error handling. The fourth patch - the actual HTTP 429 implementation - needs review from an HTTP transport expert (likely Jeff King or Taylor Blau) before merging.

The HTTP 429 support includes parsing Retry-After headers (both delay-seconds and HTTP-date formats), configurable retry behavior via http.maxRetries, http.retryAfter, and http.maxRetryTime settings, and Trace2 integration. The implementation is conservative by default (maxRetries=0) to maintain Git's fail-fast philosophy. The series has extensive test coverage through new infrastructure in t/lib-httpd/http-429.sh.

Junio suggests the strbuf fixes could potentially be queued independently if the HTTP patch needs more work. The technical scope spans memory management fixes, HTTP protocol handling, and test infrastructure. The series appears functionally complete and well-tested, with only final review of the HTTP transport changes remaining before it can be merged.
