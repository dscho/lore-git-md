Documentation patch from the maintainer clarifying patch submission expectations. Junio C Hamano updates the SubmittingPatches guide to explicitly discourage the practice of sending incremental fixup patches during review iterations, instead advocating for complete series replacements that present as if perfect from the start. 

The change formalizes a long-standing maintainer preference that Junio has articulated in prior emails (three examples are cited in the commit message). The new text instructs contributors to use `git rebase -i` to rewrite their history when addressing review feedback, presenting each iteration as a fresh, clean series rather than accumulating fixup commits. 

Kristoffer Haugsbakk provided light review, suggesting two minor wording tweaks: changing "stress on this" to "stress this point" and expanding "IOW" to "In other words". The patch appears uncontroversial and likely to be merged with these minor adjustments, as it codifies existing review practices that Junio has consistently advocated for. 

This is a straightforward documentation improvement that helps set clearer expectations for new contributors about the project's preferred patch submission workflow. The change touches core contribution guidelines but doesn't introduce any new technical requirements - it simply makes explicit what has long been the maintainer's expectation.
