This is a response in an ongoing thread about extending `git submodule foreach` functionality. Junio C Hamano (the Git maintainer) is replying to Florian Schmidt's proposal to add options for running commands on both the parent repository and submodules, and for continuing execution when submodule commands fail.

Junio expresses skepticism about the first part of the proposal - running commands on the parent repository via `submodule foreach`. He argues that the superproject isn't technically a submodule, so the command name would be misleading. Instead, he suggests the simpler approach of running the command directly on the parent followed by `submodule foreach`, which he sees as more conceptually clear.

The response doesn't address the second part of Florian's proposal (continuing execution after submodule command failures), which remains open for discussion. Junio's position here carries significant influence as the maintainer, suggesting this particular direction may not gain traction unless stronger use cases are presented. The thread remains active for others to weigh in on both proposals.
