This is a documentation patch that follows up on a thread about the `-U` diff option handling. The original issue was that `git show -U` without a number was being accepted (defaulting to 3 lines of context) while the documentation implied the number was mandatory. Tian Yuchen's patch updates the docs to show `-U[<n>]` as accepting an optional number, matching the actual behavior.

D. Ben Knoble's reply suggests two potential improvements: first, that the long form `--unified` could similarly be documented as `--unified[=<n>]` to show its optionality, and second, that the wording around defaults could be clarified to explicitly state that the number itself defaults to 3 when omitted. He also notes the documentation is duplicated between two files, though doesn't propose addressing that here.

The thread has already converged on keeping the lenient parsing behavior for backward compatibility, so this is now purely about polishing the documentation. Knoble's suggestions are minor but reasonable - they would make the docs slightly more precise and consistent with other option documentation in Git. The patch is straightforward and uncontroversial, just awaiting potential tweaks to the wording before being finalized.
