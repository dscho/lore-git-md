This is a small bugfix patch addressing a compiler warning in the bloom filter code. The issue arises when building with glibc-2.43, which warns about discarding a `const` qualifier when assigning a pointer that will later be used to modify the data.

The patch removes the misleading `const` qualifier from a path variable in `bloom.c` since the code clearly modifies the string through this pointer (by writing null terminators to split path components). The change is straightforward and correct - the `const` was incorrectly applied in the first place given the actual usage.

This appears to be a clean, well-motivated fix for a real (though minor) issue. The commit message clearly explains both the symptom (compiler warning) and why the change is correct (the pointer is used for writing). The diff is minimal and focused.
