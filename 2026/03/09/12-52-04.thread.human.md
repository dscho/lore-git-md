This thread proposes two enhancements to `git submodule foreach` to address workflow pain points. Florian Schmidt describes a use case where they need to create and later clean up development branches across all submodules, which would benefit from being able to run the same command on the parent repository as well. Currently this requires manual workarounds.

The first proposed change would add a flag to execute the given command in the parent repository alongside all submodules. The second would introduce an option to continue execution even if a submodule command fails, eliminating the current need for `|| :` workarounds. Both changes appear to be well-scoped quality-of-life improvements that wouldn't break existing behavior.

While these could be accomplished with aliases or manual steps, having built-in support would make the workflow more robust and convenient for users who frequently need to run identical commands across parent and submodule repositories. The implementation would involve modifying the submodule command's option parsing and execution logic, but shouldn't require deep architectural changes.
