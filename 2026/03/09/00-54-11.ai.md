This is a refactoring patch in Adrian Ratiu's ongoing hook configuration series, currently in its second iteration (v2). The patch replaces a custom hook cleanup function with Git's standard string_list_clear_func() pattern, simplifying the API.

The key change converts hook_list_clear() to use string_list_clear_func() with a new hook_free() helper. This requires storing the data-free callback in the hook struct itself rather than passing it at cleanup time. The patch also updates all callers to use the new approach, including the necessary struct field and documentation updates.

The changes touch hook.c, hook.h, and builtin/hook.c, with careful attention to maintaining the existing functionality while making the API more consistent with Git's conventions. The patch follows Patrick Steinhardt's suggestion to adopt the more standard string_list clearing pattern, continuing the series' trend of cleaning up review feedback from previous versions.

This is a mechanical improvement that doesn't change user-visible behavior but makes the code more maintainable by using established patterns. The patch fits into the larger context of Adrian's work to modernize Git's hook subsystem with configurable hooks and better internal APIs.
