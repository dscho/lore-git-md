This is a technical clarification about partial clone configuration and promisor remote behavior, part of a GSoC project discussion thread.

Christian Couder confirms Lorenzo Pegorari's understanding of how `extensions.partialClone` interacts with multiple promisor remotes. The current behavior is that without the global config, remotes are tried in config order when marked with `remote.<name>.promisor`, while the `extensions.partialClone` setting makes its specified remote a last-resort fallback. This matches the documented behavior in the partial clone documentation.

This suggests the GSoC project will need to design the new feature to gracefully handle both the legacy configuration and new ordering preferences.
