This is a bugfix patch in Adrian Ratiu's ongoing series to improve Git's hook configuration support. The patch adds defensive programming checks to catch two invalid hook states that should never occur during normal operation: encountering an unknown hook type, and finding a configured hook that is enabled but lacks a command to run.

The changes are minimal but important for code robustness - they add BUG() calls that will trigger if these invalid states are ever reached. The first check verifies that any configured hook marked as enabled has an associated command string, while the second ensures the hook subsystem only handles known hook types. Both cases represent programming errors rather than user-facing issues.

Patrick Steinhardt suggested these checks as part of the code review process. The patch builds on Adrian's prior work to make hooks configurable via Git's configuration system, which is currently in the 'next' integration branch. This continues the series that includes both cleanups and small user-facing features for `git hook list`.
