This is a feature proposal for the experimental `git replay` command, introducing subcommands to replace the current mutually-exclusive option-based interface. The patch comes from Toon Claes and builds on Siddharth Asthana's earlier work adding revert functionality to `git replay`.

The key changes:
1. Replaces `--onto`, `--advance`, and `--revert` options with three subcommands:
   - `rebase`: Equivalent to `--onto` behavior
   - `pick`: Equivalent to `--advance` behavior
   - `revert`: Equivalent to `--revert` behavior
2. Introduces a new `--ref` option that works consistently across subcommands to specify which reference to update
3. Maintains backward compatibility by still accepting `--onto` (required for `rebase` subcommand)
4. Updates documentation and tests to reflect the new interface

The motivation is to make the command's interface more intuitive by following Git's conventional subcommand pattern rather than having mutually-exclusive options that change the command's fundamental behavior. The implementation appears thorough, touching all expected files (documentation, implementation, tests) and maintaining existing functionality while adding the new interface.

The patch is marked RFC (Request For Comments) as the author seeks feedback on the design before polishing the implementation. The changes are currently bundled in one large patch, which the author acknowledges makes review challenging, with plans to split into smaller pieces once the direction is agreed upon.

This builds on ongoing work around `git replay`, an experimental alternative to `git rebase` that operates at a lower level and works with bare repositories. The command is still marked experimental in the documentation.
