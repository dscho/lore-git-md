This is a documentation patch from Git maintainer Junio C Hamano that updates the SubmittingPatches guide to clarify patch iteration best practices. The change addresses a common pattern where contributors send incremental "fixup" patches rather than rewriting their series to incorporate feedback cleanly.

Junio emphasizes that during early review iterations, contributors should fully replace their patch series rather than stacking fixes on top. The new text explains this is an opportunity to "pretend to be a perfect developer" by using tools like `git rebase -i` to rewrite history and present a cleanly progressing series without showing intermediate missteps. The rationale is that the project's history should focus on the logical progression of ideas rather than preserving every mistake made along the way.

The patch is a straightforward documentation improvement that codifies existing maintainer expectations. It includes references to past discussions where this principle was mentioned, showing this is a new rule but rather making explicit what has been long-standing practice. As a maintainer-authored patch addressing a recurring issue in the contribution workflow, it's likely to be merged without controversy.
