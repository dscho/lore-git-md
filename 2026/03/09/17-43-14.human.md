This is a feature proposal for `git submodule foreach` that has evolved through discussion. The original patch suggested adding two options: one to run commands on the parent repository alongside submodules, and another to continue execution when submodule commands fail.

Junio Hamano has pushed back on the parent-repository execution feature, arguing it's conceptually wrong since the parent isn't a submodule. He suggests the clearer workflow is to run the command directly on the parent followed by `submodule foreach`. The author, Florian Schmidt, concedes this point, noting the feature was just a minor convenience.

The failure-tolerance option remains open for discussion, though it hasn't been addressed in this reply. The thread shows a typical Git development pattern - a feature gets proposed, the maintainer provides architectural feedback, and the author adjusts their approach while keeping parts that still have merit. The discussion remains constructive, with both sides acknowledging valid points.
