This is a discussion about extending submodule command execution behavior, following up on Florian Schmidt's now-abandoned proposal to add `--also-parent` to `git submodule foreach`. Jeff King suggests an alternative approach using the existing `git for-each-repo` command as a more natural place to implement the desired functionality.

Jeff proposes that `git for-each-repo --submodules --current` could serve as a cleaner alternative to modifying `git submodule foreach`, since it already handles running commands across multiple repositories. The `--submodules` flag would discover submodules (similar to the existing foreach behavior), while `--current` would include the parent repository in the execution set. This approach would avoid the conceptually problematic aspect of treating the parent repository as a submodule.

The suggestion is presented as speculative - Jeff notes he doesn't personally need this functionality and is "just thinking out loud." However, it offers a technically sound alternative path that maintains clearer conceptual boundaries between parent repositories and submodules. The proposal aligns with Git's existing command structure where `for-each-repo` is the designated multi-repository operation command, while `submodule foreach` specifically handles submodule operations.

This email keeps the discussion alive for the still-open part of Florian's original proposal (failure tolerance) by demonstrating there are alternative approaches to achieve similar workflow goals. The technical implementation would involve adding new options to `git for-each-repo` rather than modifying `submodule foreach`, which may be more maintainable long-term.
