This is a bugfix patch that addresses a memory leak in `repo_init()`. It's the first patch in a 9-part series introducing parallel hook execution, but this particular patch stands alone as a cleanup fix.

The patch fixes a pre-existing memory leak that occurs when `repo_init()` fails after parsing repository format extensions. The leak happens because `clear_repository_format()` isn't called in the error path. While the conditions to trigger this are rare (requiring v1 extensions in a v0 repository format), the fix is straightforward and correct.

Adrian Ratiu (who has been working on hook-related improvements) includes this as part of his larger series, though it's independent of the parallel hooks functionality. The change is minimal - just one line added to ensure proper cleanup. This appears to be a solid, uncontroversial fix that should be easy to merge regardless of how the rest of the parallel hooks series progresses.
