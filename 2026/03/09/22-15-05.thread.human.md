This thread documents a straightforward but important update to Git's contribution guidelines. Maintainer Junio C Hamano has proposed adding explicit instructions to SubmittingPatches that contributors should use `git rebase -i` to completely rework patch series between review iterations, presenting each version as if perfect from the start rather than sending incremental fixup patches. This formalizes a long-standing maintainer preference that Junio has articulated in prior code review feedback, three examples of which are cited in the commit message.

Kristoffer Haugsbakk provided light review, suggesting two minor wording improvements to the new paragraph - changing "stress on this" to "stress this point" and expanding the abbreviation "IOW" to "In other words." Junio appears receptive to these suggestions. As this change codifies existing review practices rather than introducing new requirements, and comes directly from the maintainer with supporting precedent, it is likely to be merged with minimal further discussion. The update targets the core SubmittingPatches documentation that all contributors reference, making explicit what was previously implicit in maintainer feedback about patch series hygiene.
