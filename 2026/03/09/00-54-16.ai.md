This is the final patch in Adrian Ratiu's series improving Git's hook configuration support, specifically addressing the visibility of disabled hooks.

The patch modifies `git hook list` to show disabled hooks (previously filtered out entirely) with a "(disabled)" annotation. When combined with the new `--show-scope` flag from earlier in the series, disabled hooks display their scope as well (e.g. "myhook (local, disabled)"). The implementation adds a `disabled` flag to the hook struct and related configuration cache entries, propagating this state through the hook execution pipeline.

Key technical details include:
- Disabled hooks without commands now trigger warnings rather than fatal errors
- The `hook_exists()` function now skips disabled hooks when checking for existence
- Traditional hooks (from hookdir) remain unaffected by these changes
- Comprehensive test coverage verifies the new behavior across listing, scoping, and existence checks

The changes touch `builtin/hook.c`, `hook.[ch]`, and `t/t1800-hook.sh`, with Patrick Steinhardt suggesting the original idea. This completes the series' goal of making hook configuration more transparent and manageable while maintaining backward compatibility.
