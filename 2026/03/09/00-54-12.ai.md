This is a documentation patch from Adrian Ratiu's ongoing hook configuration series, standardizing terminology in the hook subsystem documentation. The patch replaces inconsistent uses of "name" with "friendly-name" throughout the documentation and related code comments to make the terminology more precise and consistent.

The changes affect both the config documentation (hook.adoc) and the git-hook man page, updating all references to hook configuration keys like `hook.<name>.command` to use `hook.<friendly-name>.command` instead. The patch also updates a few related code comments in hook.c and hook.h to match this terminology. The change was suggested by Junio C Hamano in prior review feedback.

This is a straightforward cleanup that improves consistency without changing any functionality. It's part of Adrian's larger effort to improve Git's hook configuration system, with this particular patch being the 6th in a 10-patch series that's currently being iterated on. The series builds on Adrian's previous work that's already in the 'next' branch.
