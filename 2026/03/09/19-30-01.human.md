This is a discussion about extending submodule command functionality, continuing a thread where Florian Schmidt had proposed adding a `--also-parent` option to `git submodule foreach`. Jeff King (Peff) suggests an alternative approach using the existing `git for-each-repo` command instead of modifying `submodule foreach`.

Peff proposes that `git for-each-repo --submodules --current` could achieve the same goal of running a command in both the parent repository and its submodules, while avoiding the conceptual issues Junio raised about treating the parent as a submodule. He notes this is just a thought experiment rather than a concrete proposal, as he doesn't personally need this functionality.

The suggestion keeps the discussion alive after Florian effectively withdrew the original proposal, offering a potential path forward that might satisfy both the use case and maintainer concerns about command semantics. The thread remains focused on finding the right conceptual model for repository traversal operations.
