This is part of Adrian Ratiu's ongoing parallel hook execution series (v3 8/9), introducing a new `extensions.hookStdoutToStderr` configuration to handle output stream consistency for parallel hooks. The patch addresses a compatibility issue where `pre-push` hooks (notably used by git-lfs) expect separate stdout/stderr streams, unlike other hooks that merge stdout to stderr by default.

The change adds repository-level configuration to enforce stdout-to-stderr merging across all hooks when enabled, which is required for proper parallel execution output handling. Without this extension, `pre-push` hooks will always run sequentially to maintain backward compatibility. The implementation includes:
- New `hook_stdout_to_stderr` flag in repository format
- Documentation updates explaining the extension's effect
- Test cases verifying the extension's behavior
- Modified `transport.c` to respect the repository setting

The patch maintains careful backward compatibility while providing a path forward for parallel execution of all hooks. It follows the series' pattern of explicit opt-in controls, here via a repository extension rather than direct configuration. The test suite demonstrates both the default behavior (separate streams for `pre-push`) and the extension-enabled behavior (merged streams).
