Adrian Ratiu's series modernizing Git's hook configuration has been merged to 'next' after several iterations. The work introduces three main user-facing improvements to `git hook list`: showing configuration scope (matching `git config --show-scope`), displaying disabled hooks, and validating hook names (with an `--allow-unknown-hook-name` escape hatch). Under the hood, it establishes infrastructure for future hook metadata storage while cleaning up the codebase and expanding test coverage.

The series went through thorough review, with Patrick Steinhardt particularly involved in shaping the hook name validation approach. Memory management design was carefully considered, settling on a string-list-based solution that leverages existing Git APIs. Post-merge, Adrian continues to refine the code - his latest patch fixes an uninitialized strbuf in the receive-pack hook infrastructure that Patrick spotted. While this wasn't causing immediate issues (child processes properly initialize their own copies), the fix follows Git's defensive programming practices.

The work positions Git for future hook customization while maintaining backward compatibility. The cleanups and test expansions make the hook subsystem more maintainable, and the careful API design demonstrates Git's commitment to thoughtful evolution of long-standing systems. With the series now in 'next', the focus shifts to real-world testing before the changes graduate to 'master' in an upcoming release.
