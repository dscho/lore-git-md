Adrian Ratiu's hook configuration series, which modernizes Git's hook subsystem with improved configuration support, has been merged to the 'next' branch after extensive review. The series introduces user-facing improvements to `git hook list` including scope visibility and disabled hook display, while laying groundwork for future metadata storage.

In the latest discussion, Adrian is implementing Patrick Steinhardt's suggestion to validate standard hook names by default in `git hook list` (helping catch common typos) while providing an `--allow-unknown-hook-name` flag for custom hooks. This aligns with Git's philosophy of helpful defaults with escape hatches. Adrian confirms the implementation works well and will include it in his upcoming v3 revision, which also adds test coverage for how scope display interacts with hooks from `.git/hooks`.

The series has undergone thorough refinement, with post-merge improvements including memory management design decisions (settling on a string-list approach), style fixes, and boolean type modernization. Patrick has approved the core design while continuing to review the hook name validation changes. The work represents the culmination of Adrian's multi-series effort to integrate the hook subsystem with Git's configuration system, following the project's pattern of iterative improvement even after initial merging.
