Adrian Ratiu's series modernizing Git's hook configuration has been merged to the 'next' branch after extensive review, marking the culmination of his multi-series effort to integrate hooks with Git's config system. The changes introduce user-facing improvements to `git hook list`, including scope visibility and disabled hook display, while laying groundwork for future metadata storage.

Post-merge refinements have focused on finalizing design decisions, particularly around memory management. After discussion, the project settled on using the existing string-list API with a specialized callback for cleanup, rather than introducing a new general-purpose `hook_free()` function. Patrick Steinhardt, who had initially proposed alternatives, ultimately endorsed Adrian's preferred approach for its encapsulation benefits and consistency with existing patterns. The only remaining change is a small documentation fix to remove a duplicated comment.

The series has also incorporated several improvements during this final review phase: better hook name validation (with an escape hatch for non-standard hooks via `--allow-unknown-hook-name`), boolean type modernization, initialization fixes, and style refinements. These changes demonstrate Git's culture of continuous improvement, where even merged code undergoes scrutiny and refinement. With the memory management design now settled and Adrian preparing final tweaks, this long-running effort appears ready for stable inclusion.
