This is a documentation patch from Adrian Ratiu, part of his ongoing series to improve Git's hook configuration support. The patch standardizes terminology in the documentation and code comments, replacing "name" with "friendly-name" when referring to hook identifiers in configuration keys like `hook.<name>.command`.

The change follows a suggestion from Junio Hamano to use the more descriptive "friendly-name" consistently rather than the generic "name". The patch updates both the config documentation and man pages, plus a few related code comments. While mechanical, this improves clarity by making it obvious that these names are meant to be human-readable identifiers rather than internal implementation details.

This is the sixth patch in a 10-part series that builds on Adrian's prior work to make hooks configurable via Git's configuration system. The series is currently in the 'next' branch and includes both cleanups and small user-facing features. This particular patch is a straightforward documentation improvement that aligns with the project's emphasis on clear, consistent terminology.
