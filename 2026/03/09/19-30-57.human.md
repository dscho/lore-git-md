This is a feature proposal for the experimental `git replay` command, introducing subcommands to replace the current mutually exclusive options (`--onto`, `--advance`, `--revert`). The patch comes from Toon Claes and is marked as RFC (Request For Comments) to gather feedback before finalizing the design.

The key changes:
1. Replaces the option-based modes with three subcommands:
   - `rebase`: Equivalent to current `--onto` behavior
   - `pick`: Equivalent to current `--advance` behavior
   - `revert`: Equivalent to current `--revert` behavior
2. Introduces a new `--ref` option that works consistently across subcommands to specify which reference to update
3. Maintains backward compatibility by still accepting `--onto` (required for `rebase` subcommand)
4. Updates documentation and tests to reflect the new interface

The motivation is to make the command's interface more intuitive and consistent with other Git commands that use subcommands for distinct operations. The patch appears well-structured with thorough documentation updates and test coverage, though the author notes it may need splitting into smaller patches for final submission.

This builds on previous work by Siddharth Asthana that added the `--revert` option. The change seems likely to be uncontroversial as it improves usability without changing core functionality, though the RFC status suggests the author wants to confirm the design approach before proceeding.
