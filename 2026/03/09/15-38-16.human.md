This is a refactoring patch in a series aimed at reducing unnecessary strbuf usage, following patterns established by Junio Hamano's earlier cleanup work. The second in a two-part series, it modifies parse_combine_filter() in the list-objects-filter-options code to avoid using strbuf_split_str() when processing combine: filter specs.

The patch replaces the strbuf-based approach with direct string manipulation using strchr() and xmemdupz(), which is more straightforward for this use case. Junio notes the change looks reasonable but raises a subtle edge case question about handling trailing '+' characters - the new implementation behaves slightly differently by not processing empty strings after trailing delimiters, though it's unsure if this matters in practice.

This follows the first patch in the series (already approved by Junio) that similarly simplified worktree linking file handling. Both changes maintain identical functionality while being more direct about string ownership. The approach aligns with established cleanup patterns in the codebase, making this a low-risk improvement that's likely to be accepted after addressing Junio's observation about the edge case behavior.
