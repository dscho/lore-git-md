This is part 2/9 of a series introducing parallel hook execution, building on Adrian Ratiu's prior work on configurable hooks. The patch adds infrastructure for unsigned integer config values, specifically to support the upcoming 'hook.jobs' configuration option.

The change introduces a new `git_config_uint()` helper and related functions to properly handle unsigned integer config values, filling a gap in the config API which previously only supported signed integers and unsigned longs. The implementation follows the existing pattern for other numeric types, with matching functions at the parse, configset, and repository levels.

The patch is a straightforward plumbing addition that:
- New `git_parse_uint()` function in parse.c
- Corresponding `git_config_uint()` in config.c
- Configset and repository-level accessors
- Documentation in config.h headers

This is a preparatory change for the parallel hook execution feature, ensuring proper type handling for job counts. The implementation is clean and follows existing patterns, though it's worth noting that unsigned integers are relatively rare in Git's config system - most numeric values use signed ints or unsigned longs. The justification for using uint here (rather than casting from int) is sound given the semantic meaning of job counts.
