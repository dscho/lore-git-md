This is a documentation refinement in the ongoing thread about `-U` option behavior in Git's diff machinery. Junio C Hamano responds to Tian Yuchen's patch that proposed documenting `-U` without a number as valid syntax. While acknowledging the current behavior (where `-U` defaults to 3 lines like `-p`), Junio expresses reservations about explicitly endorsing this in the docs, calling it a "historical accident" rather than intentional design.

Junio suggests alternative wording that would:
1. Group `-U<n>` and `--unified=<n>` together as equivalent forms
2. Explicitly state the 3-line default when config is unset
3. Note the `-U`-without-number case as a legacy behavior rather than a feature

The response maintains the thread's established position that the implementation behavior must stay for backward compatibility (supporting test 157 in t4013), but pushes back against documenting it as a first-class feature. This continues the careful balancing act between accurately describing current behavior and not encouraging what the maintainer views as a historical quirk.

The email doesn't address D. Ben Knoble's earlier suggestions about doc syntax alignment, leaving those questions open. Junio's counter-proposal focuses specifically on how to frame the `-U` behavior without expanding the scope to other documentation conventions.
