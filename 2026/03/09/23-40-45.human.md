Bugfix for submodule fetching that removes the hardcoded assumption of "origin" as the default remote name. This patch completes a 7-year-old NEEDSWORK item from commit be76c21282, allowing `git fetch --recurse-submodules` to work correctly when submodules use non-origin remote names.

The implementation introduces a new `get-default-remote` submodule helper command and updates the fetching logic to use it. The patch includes comprehensive test coverage across multiple test files and has been through several review iterations addressing style issues, test portability concerns, and output ordering problems. 

Key reviewers Jacob Keller and Junio Hamano have confirmed the technical soundness of the approach. The final version removes problematic test assertions about fetch progress output ordering that were causing flakiness, while maintaining validation through GIT_TRACE output. 

The patch is now cleared for inclusion in the integration branches, marking the successful resolution of this long-standing submodule limitation.
