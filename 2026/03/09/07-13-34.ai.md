This is a follow-up discussion in Dorna Raj Gyawali's patch series to make `trust_executable_bit` repository-scoped as part of the `the_repository` removal effort. Tian Yuchen points out two process issues - the v2 iteration wasn't CC'd to Junio Hamano (the maintainer) and didn't include responses to previous reviews. 

On the technical side, Yuchen identifies a key architectural concern: the current implementation calls `prepare_repo_settings()` during global config parsing in `environment.c`, which conflicts with the intended lazy-loading behavior of repository settings. They suggest the more idiomatic approach would be to completely remove the variable from `environment.c` and handle the config reading in `repo-settings.c` via `repo_config_get_bool()`. 

The exchange highlights an ongoing tension in the `the_repository` removal project between making incremental progress (as Dorna's patch does) and achieving the full architectural goals (proper lazy-loading patterns). Yuchen's feedback suggests this particular issue may need another iteration to align with the project's standards for repository settings initialization. The thread remains active with this technical question unresolved.
