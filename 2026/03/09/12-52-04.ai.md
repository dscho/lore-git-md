This is a feature proposal for `git submodule foreach` that would add two new options:

1. A flag to run the given command on the parent repository in addition to all submodules
2. A flag to continue execution even if a submodule command returns non-zero (currently `|| :` is needed as a workaround)

The author, Florian Schmidt, describes a concrete use case where they create development branches across all submodules and later clean them up - a workflow where running the same command on the parent repo would be useful. They acknowledge this could be done manually or via an alias, but are gauging interest in making it a built-in option.

The proposal seems well-motivated by a real workflow pain point, though the impact appears limited to users who frequently need to run identical commands across both parent and submodule repositories. The implementation would touch the submodule command's option parsing and execution logic, but shouldn't require deep architectural changes.

The second part about error handling is a smaller but related quality-of-life improvement that would make the command more robust when some submodule operations fail. Both changes appear to be straightforward additions that wouldn't break existing behavior.
