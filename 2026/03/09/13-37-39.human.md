This is the final patch in Adrian Ratiu's series enabling parallel hook execution, specifically adding runtime configuration to control output stream handling for parallel hooks.

The patch introduces a new `hook.forceStdoutToStderr` config option that globally enables the `extensions.hookStdoutToStderr` behavior, which merges stdout and stderr streams for all hooks. This allows parallel execution of hooks like `pre-push` that normally require separate streams (for compatibility with tools like git-lfs). The change makes it easier to adopt parallel hooks without manually configuring the repository extension.

Key technical details:
- The config is checked during repository initialization (`git init`) and clone operations
- When enabled, it automatically sets the repository format version to at least 1 if needed
- The setting is applied before job count determination to ensure proper parallelization decisions
- Comprehensive tests verify the behavior across init/clone operations and existing repositories

This builds on the series' earlier work that identified mandatory serial hooks and implemented multiple control points for parallel execution. The patch maintains backward compatibility while providing a convenient global switch for users who want to enable parallel hooks across all their repositories.
