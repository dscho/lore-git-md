This thread addresses a const-correctness warning in Git's bloom filter code when building with glibc-2.43. The issue stems from a mismatch between a const-qualified path variable and subsequent string modification via a strrchr() result.

The patch, which is the first and only email in the thread so far, proposes a straightforward fix by removing the misleading const qualifier from the path variable declaration in bloom.c. The change is minimal (just two lines) and well-justified, as the code was already treating the string as mutable in practice. The commit message clearly explains both the compiler warning being addressed and why the solution is safe.

As this appears to be a simple, uncontroversial bugfix with no outstanding questions or objections, it will likely be picked up by the maintainer in the next integration cycle unless any concerns are raised in follow-up messages.
