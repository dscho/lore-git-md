This is part of Adrian Ratiu's ongoing parallel hook execution feature series (v3 7/9), building on his prior configurable hooks work. The patch introduces per-event job count configuration via `hook.<event>.jobs`, allowing users to override the global `hook.jobs` setting for specific hook events while maintaining the existing parallelization safety checks.

The implementation adds a new `event_jobs` strmap to the hook config cache to store per-event job counts, with the same validation rules as the global setting (must be positive integer). The job count resolution logic in `get_hook_jobs()` now checks for an event-specific override before falling back to the global setting. The documentation explains the distinction between event names and hook friendly names, noting that the config key must use the event name (e.g. `hook.post-receive.jobs` not `hook.my-hook.jobs`).

The patch includes three new test cases verifying that:
1. Per-event jobs override global jobs when specified
2. Per-event jobs=1 forces serial execution even when global jobs>1
3. Parallel execution still depends on individual hooks being marked parallel=true

This continues the series' pattern of providing multiple control points for parallelization while maintaining safety through explicit opt-in requirements. The per-event granularity allows performance tuning for specific workflows (e.g. higher parallelism for post-receive) without affecting other hooks.
