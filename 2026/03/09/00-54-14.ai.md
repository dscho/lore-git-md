This is a refactoring patch in Adrian Ratiu's ongoing hook configuration series, currently the 8th of 10 patches. The change prepares the hook subsystem for future extensions by replacing a direct `strmap` with a named `struct hook_config_cache` that wraps the map, and converting the simple `char*` command storage into a proper `struct hook_config_cache_entry`.

The patch introduces two new structs:
- `hook_config_cache` to replace the bare `strmap` in `struct repository`
- `hook_config_cache_entry` to replace direct string storage of hook commands

Key technical changes:
- Moves from storing raw command strings to storing them in a dedicated struct
- Updates all related functions to use the new types
- Maintains identical behavior while enabling future metadata additions
- Touches hook.c, hook.h, and repository.h
- Includes thorough updates to comments and documentation strings

The refactoring is cleanly separated from behavior changes, with clear commit message and code comments explaining the transition. This appears to be a preparatory step for additional hook metadata that will be added in subsequent patches. The changes follow Git's established patterns for similar configuration caches elsewhere in the codebase.
