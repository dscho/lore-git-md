Feature patch enabling parallel hook execution with opt-in controls. This is part 4 of a 9-part series (v3) building on Adrian Ratiu's configurable hooks work, now rebased and updated from v2.

The patch removes Git's hardcoded serial execution of hooks, allowing parallel runs when explicitly configured. Key aspects:

- Introduces `hook.<name>.parallel` config to mark individual hooks as safe for parallel execution (defaults to false for safety)
- Respects the global `hook.jobs` setting from previous patches, but only when all hooks for an event are marked safe
- Maintains backward compatibility by defaulting to serial execution (jobs=1) when any hook opts out
- Adds comprehensive tests verifying serial vs parallel behavior under different config combinations
- Documents the parallel execution controls in `Documentation/config/hook.adoc`

The implementation carefully balances performance potential with safety, requiring explicit opt-in at multiple levels. This continues the series' theme of giving users control while protecting against unsafe concurrency. The patch appears well-tested and thoughtfully integrated with the existing hook infrastructure.
