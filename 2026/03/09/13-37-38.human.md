This is part of Adrian Ratiu's ongoing series to enable parallel hook execution in Git (v3 8/9). The patch introduces a new extension `extensions.hookStdoutToStderr` to standardize hook output behavior.

The change addresses a compatibility issue where most hooks already merge stdout to stderr, but `pre-push` (used by git-lfs) expects separate streams. The extension enforces consistent output merging when enabled, which is required for safe parallel execution. Without it, `pre-push` hooks must run sequentially to avoid interleaved output.

The implementation adds repository format handling for the new extension flag and updates the pre-push hook in transport.c to respect it. Tests verify the behavior, including that pre-push defaults to serial execution when the extension is disabled. This maintains backward compatibility while providing a path forward for parallel execution where desired.

The patch is well-structured with thorough documentation and test coverage. It represents a pragmatic solution to a real-world compatibility issue uncovered during the parallel hooks development. As part of a larger series, it fits cleanly into the overall design while handling a specific edge case.
