This is the final patch in Adrian Ratiu's parallel hook execution series, introducing a runtime configuration option to enable the `extensions.hookStdoutToStderr` behavior globally. The patch adds a new `hook.forceStdoutToStderr` config that allows users to opt into merged stdout/stderr streams for all hooks, which is required for parallel execution of hooks like `pre-push` that normally expect separate streams.

The implementation adds the config option to the hook config cache and modifies `get_hook_jobs()` to check this setting first, before determining parallel execution eligibility. The `setup.c` changes ensure the extension is automatically enabled during repository initialization when the config is set globally. New test cases verify the behavior during `git init` and `git clone`, plus validation that existing repositories respect the global setting.

This completes the series' output stream handling strategy by providing both repository-specific (`extensions.hookStdoutToStderr`) and global (`hook.forceStdoutToStderr`) control points. The design maintains backward compatibility while enabling parallel execution where explicitly configured, with thorough test coverage of the new configuration pathway. The patch builds on the series' earlier work establishing parallel execution safety through mandatory serial hooks and job count controls.
