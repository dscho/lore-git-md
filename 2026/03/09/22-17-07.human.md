This is a documentation patch addressing the handling of `-U` in diff options. The thread has established that Git historically accepts `-U` without a number (defaulting to 3 lines of context) despite the documentation implying the number is mandatory. While Tian Yuchen proposed simply documenting the current behavior, Junio Hamano suggests a more nuanced approach that explains this as a historical accident rather than an intentional feature.

Junio's counter-proposal would:
1. Explicitly show both short (`-U<n>`) and long (`--unified=<n>`) forms
2. Document the default value (3 lines) when config is unset
3. Acknowledge the inconsistency as a historical artifact
4. Make clear this is not an encouraged usage pattern

The patch remains focused on documentation only - no code changes are needed or proposed. This is a minor but precise clarification of edge case behavior that maintains backward compatibility while setting clearer expectations. The discussion shows the project's typical attention to detail in documenting historical quirks without endorsing them.
