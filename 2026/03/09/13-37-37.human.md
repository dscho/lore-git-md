This is part 7 of a 9-patch series introducing parallel hook execution, building on Adrian Ratiu's earlier work on configurable hooks. The series is now in its fourth iteration (v4).

The patch adds per-event job count configuration via `hook.<event>.jobs`, allowing users to override the global `hook.jobs` setting for specific hook events. For example, you could configure `post-receive` hooks to run with 4 parallel jobs while keeping other events at the global default. The implementation carefully maintains all existing safety checks - hooks must be explicitly marked as parallel-capable, and certain critical ones (like commit-related hooks) always run sequentially regardless of configuration.

The change includes thorough documentation explaining the interaction between global and per-event job counts, plus tests verifying the override behavior works as expected while still respecting the parallel-safety requirements. This continues the series' pattern of providing multiple opt-in control points for parallel execution while maintaining safety through explicit configuration.

The implementation is clean and well-tested, with clear documentation of the precedence rules (command-line `-j` overrides per-event config which overrides global config). This patch fits naturally into the larger series' goal of making hook execution more flexible while keeping it safe by default.
