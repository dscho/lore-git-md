This is a refactoring patch from Vaidas Pilkauskas that fixes incorrect buffer size allocations when using `strbuf_attach()` across several Git commands. The patch is part of a larger series adding HTTP 429 rate limit handling, though this particular change is a preparatory cleanup that has already been approved by Junio Hamano.

The core issue addresses a subtle memory management problem where callers were passing the exact string length to `strbuf_attach()` rather than length+1 to account for the NUL terminator. While this worked in practice due to `strbuf_grow()`'s reallocation behavior, it was technically incorrect and could lead to unnecessary reallocations. The patch updates five call sites in `am`, `fast-import`, `mailinfo`, `refs/files-backend`, and `trailer` to properly account for the terminator byte.

The changes are mechanical one-line fixes that simply add +1 to the allocation size parameter. Each modified function handles NUL-terminated strings where the extra byte is genuinely needed. The patch demonstrates good attention to detail in tracking down these edge cases across different subsystems, though the impact is primarily internal code hygiene rather than user-visible behavior changes.

This work shows the author's responsiveness to maintainer feedback, as earlier versions of the HTTP 429 series prompted Jeff King to suggest broader strbuf correctness improvements. The changes here are now properly separated from the HTTP functionality and represent the final strbuf fixes needed before the main feature can proceed.
