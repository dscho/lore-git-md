This is a feature patch series (v6) from Vaidas Pilkauskas adding HTTP 429 rate limit retry support to Git's HTTP client. The series has evolved through multiple rounds of review, with Jeff King providing architectural guidance and Junio Hamano handling the strbuf fixes separately.

The core functionality remains HTTP 429 response handling with Retry-After header support, configurable via http.maxRetries, http.retryAfter, and http.maxRetryTime. Key changes in v6 include: dropping the show_http_message_fatal() helper patch, restructuring the retry logic to use http_get_options for passing retry_after values, fixing the retry counter separation between REAUTH and RATE_LIMITED cases, and addressing test timing race conditions.

The implementation now properly handles both delay-seconds and HTTP-date Retry-After formats, with libcurl 7.66.0+ using CURLINFO_RETRY_AFTER and falling back to manual parsing on older versions. The test suite has been expanded to verify various retry scenarios including header parsing, configuration limits, and timing behavior.

Jeff King's earlier review identified needed improvements to the retry loop logic and transport layer integration, which this version appears to address by moving the CURLINFO_RETRY_AFTER handling into http_request() and restructuring the retry flow. The changes show responsiveness to maintainer feedback while maintaining the core functionality.

The series is now split into three focused patches: two strbuf fixes (already approved by Junio) and the main HTTP 429 feature. The strbuf changes are straightforward correctness fixes for buffer allocation sizes, while the HTTP work represents a significant new capability for Git's HTTP client when interacting with rate-limited servers.
