This is a feature proposal for a `--max-columns` option to limit graph output width, part of Pablo Sabater's GSoC project. The v2 patch improves upon the initial RFC by addressing several technical concerns while keeping the core functionality: truncating wide graph outputs with '.' markers while preserving commit markers ('*') in key positions.

The patch now requires explicit `--graph` when using `--max-columns`, adds proper input validation, fixes padding alignment issues, and handles merge scenarios more cleanly. The author provides concrete examples showing how a 35+-branch graph becomes readable when limited to 2-3 columns. While this doesn't fully address the 2008 TODO about gitk-style column rearrangement, it offers a practical middle ground for terminal viewing.

The implementation adds `graph_max_columns` to `rev_info` and modifies graph.c's rendering logic across multiple functions. Test coverage demonstrates the 2- and 3-column cases. Open questions remain about the truncation character ('.' vs alternatives) and whether the option name should include a `--graph-` prefix, but the technical foundation looks solid. This appears ready for serious consideration as a user-facing feature, particularly given the demonstrated need for managing wide graphs in active repositories.
