This is version 6 of a feature patch series that enhances `git checkout -m` to automatically stash and restore local changes when switching branches with conflicts. The series has evolved through multiple rounds of review with input from Junio Hamano and Phillip Wood.

The key improvements in this version are:
1. Better error handling in `merge_working_tree()` with proper lock file cleanup
2. More robust index state management during branch switching
3. Preserved behavior for submodules (changes are discarded rather than stashed)

The series maintains its core functionality of:
- Autostash creation when branch switching would clobber changes
- Custom conflict marker labels showing branch names
- Silent stash creation during checkout operations
- Backward compatibility with existing workflows

The implementation touches multiple components including checkout, stash, and sequencer logic, with thorough test coverage in t7201-co.sh. While the submodule handling remains unchanged from Git's current behavior (changes are discarded), this version improves the core branch switching experience by making conflict resolution more seamless through autostash integration.

The patch appears technically sound and addresses all major concerns raised in previous reviews. With these final refinements to error handling and lock management, the series looks ready for merging as it provides a more intuitive workflow for branch switching with uncommitted changes.
