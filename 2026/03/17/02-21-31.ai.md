This is a feature patch series that improves Git's line-log functionality (`git log -L`). The series routes line-log output through Git's standard diff pipeline, enabling several previously-unsupported features to work with `-L`:

1. The cover letter explains that `-L` has historically bypassed the standard diff machinery, using a hand-rolled `dump_diff_hacky()` function. This meant features like `--word-diff`, `--color-moved`, `-w`, and pickaxe options (`-S`, `-G`) didn't work with `-L`.

2. The series fixes a crash when combining `-L` with pickaxe options and renames (patch 1), then introduces the core change to route through `builtin_diff()` (patch 2). This brings several benefits:
   - Pickaxe options now work with `-L`
   - Other diff formatting options (`--word-diff`, `--color-moved`, etc.) work
   - `--orderfile` and `--diff-filter` now work with `-L`
   - Output now shows index lines, file mode headers, and funcname context that were previously missing

3. The changes come with some user-visible output differences that may affect tools parsing `-L` output, and some known limitations remain (non-patch diff formats still don't work with `-L`).

4. The series includes comprehensive test coverage (patch 3) and documentation updates (patch 4) to reflect the new capabilities.

The implementation introduces callback wrappers to filter xdiff output to tracked line ranges and carries line ranges on diff_filepair structs. This is a significant improvement to line-log functionality that makes it properly integrate with Git's diff machinery while maintaining backward compatibility with existing `-L` use cases. The changes touch core diff infrastructure (`diff.c`, `diffcore.h`) and the line-log implementation (`line-log.c`), with extensive test updates to verify the new behavior.
