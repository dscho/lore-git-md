This is part 3/4 of a feature patch series enhancing `git checkout -m` with autostash behavior and conflict resolution improvements. The patch focuses on plumbing support for custom conflict marker labels during autostash application.

The change extends the sequencer's autostash machinery to accept optional labels for conflict markers when applying stashed changes. It introduces a new `apply_autostash_ref_with_labels()` function that passes through label parameters to the underlying `git stash apply` command via new `--ours-label`, `--theirs-label`, and `--base-label` options (added in patch 1/5 of this series).

The implementation modifies several internal functions in sequencer.c to thread the label parameters through the autostash application process while maintaining backward compatibility for existing callers. The changes are straightforward plumbing work - the actual label handling happens in the stash backend.

This patch is a technical prerequisite for the main `checkout -m` behavior changes coming in later patches, allowing branch-specific labels to be passed through during conflict resolution. The implementation looks clean and focused, with clear parameter passing and proper NULL handling for backward compatibility.
