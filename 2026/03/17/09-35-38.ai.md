This is part 3/4 of a feature patch series enhancing `git checkout -m` with autostash behavior and adding conflict marker labeling capabilities. The patch focuses on plumbing changes to support custom labels in autostash operations.

The key addition is a new `apply_autostash_ref_with_labels()` function that allows callers to specify custom labels for conflict markers when applying a stash. This builds on the new `--ours-label`, `--theirs-label`, and `--base-label` options added to `git stash apply` in patch 1/4. The implementation threads these label parameters through the existing autostash machinery in sequencer.c, adding them to the child process invocation of `git stash apply`.

The changes are straightforward plumbing work:
- Adds label parameters to internal functions `apply_save_autostash_oid()` and `apply_save_autostash_ref()`
- Introduces new public function `apply_autostash_ref_with_labels()` in sequencer.h
- Maintains backward compatibility by making all label parameters optional
- Preserves existing behavior when labels aren't specified

This patch is a technical prerequisite for the checkout changes in patch 4/4, which will use these new capabilities to provide better context in merge conflicts during branch switching. The implementation looks clean and follows the established pattern for autostash operations, with the label handling neatly contained within the existing infrastructure.

The patch appears ready for merging as part of the complete series, with all major technical concerns addressed in previous iterations. It provides the necessary building block for the user-facing checkout improvements while keeping the sequencer changes minimal and focused.
