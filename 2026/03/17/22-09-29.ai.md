This is a feature proposal (v2) from Pablo Sabater adding a `--max-columns` option to limit graph output width in `git log --graph`. The patch addresses a 2008 TODO about column limiting, though it truncates rather than rearranges columns as gitk does.

The implementation adds `graph_max_columns` to `struct rev_info` and modifies graph.c to replace excess columns with '.' while preserving commit markers ('*') for the first hidden branch. The v2 incorporates feedback from Karthik Nayak, including:

- Renamed from `--graph-max` to `--max-columns`
- Added explicit `--graph` requirement with error if missing
- Fixed padding/alignment issues
- Added pre-commit truncation
- Uses parse_long_opt/parse_count for validation
- Rejects zero/negative values
- Renamed `graph_is_truncated` to `graph_needs_truncation`

Key technical details:
- Stores limit as `unsigned int` in `rev_info`
- Defines `MINIMUM_GRAPH_COLUMNS=1`
- Modifies graph rendering in 5 functions
- Adds tests for 2-3 column limits
- Touches graph.c, graph.h, revision.c, revision.h

Open questions remain about:
- Final option name (`--max-columns` vs prefixed alternatives)
- Truncation character ('.' vs '~' or '-')
- Whether to keep the 2008 TODO given this doesn't fully implement gitk-style rearrangement

The patch appears well-constructed with thorough test coverage. The author has been responsive to review feedback while maintaining the feature's utility for terminal viewing of complex graphs. The implementation cleanly handles edge cases like merge scenarios while preserving commit subject visibility.
