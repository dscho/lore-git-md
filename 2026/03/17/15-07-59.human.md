This is a historical investigation into Git's use of exit code 129 for help requests, following up on a regression caused by changing `git rev-parse --parseopt` behavior. Jeff King (Peff) traces the origin of the 129 exit code back to 2007, finding it was originally used for error cases and may have been unintentionally inherited by help requests.

Peff's research suggests the current behavior wasn't a deliberate design choice but rather an artifact of how the parse-options machinery evolved. The exit code 129 initially served both error cases and help requests, with no distinction between them. His analysis of commit ff43ec3e2d shows how the code paths merged historically.

The email raises important questions about whether Git should now separate these cases - maintaining 129 for errors while using 0 for explicit help requests. This would require careful changes to the parse-options infrastructure to properly distinguish between the two scenarios. The investigation provides valuable context for resolving the regression while considering the implications for Git's option parsing behavior as a whole.
