This thread introduces a patch series enabling the `git replay` command to handle root commits (initial commits with no parents), which it previously rejected. The initial patch modifies `replay.c` to properly process root commits by using the empty tree for diffs and removing explicit rejection checks, while maintaining all existing behavior for non-root commits. Test coverage was added in t3650-replay-root-commits.sh.

Maintainer Junio Hamano has reviewed the first version and generally approves the change, noting it correctly handles the empty tree case for root commits. However, he raises a design question about why root commits set `replayed_base` directly to `onto` rather than going through the `mapped_commit()` function like non-root commits do. While not requesting changes, Junio suggests this special-case logic might better belong inside `mapped_commit()` itself for consistency. The author now has the option to either adjust the implementation to address this design point in a follow-up version or proceed with the current approach, which Junio has indicated is acceptable.
