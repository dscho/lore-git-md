This thread introduces a patch to enable `git replay` to handle root commits (commits with no parents), removing a previous limitation. The change modifies `replay.c` to properly process root commits by checking for parent existence, using the empty tree when needed, and removing the error message that blocked such operations. A test case verifies the functionality by replaying a history including the root commit.

The patch is focused and maintains existing behavior for non-root commits. The author notes a potential trivial conflict with an in-progress `--revert` series but considers the changes well-contained. This appears to be a straightforward improvement to `git replay`'s capabilities.
