This thread documents the evolution of `git replay`'s ability to handle root commits, from initial implementation through to final documentation polish. The technical changes, which refactored root commit handling into `mapped_commit()` with proper NULL checks and empty tree labeling, have been approved by maintainer Junio Hamano and are queued for merging.

The discussion has now shifted to documentation clarity. Christian Couder originally suggested adding warnings about accidentally replaying root commits when omitting range syntax (like using just `topic` instead of `main..topic`). Junio responded with a nuanced perspective - while acknowledging the need for better documentation, he pointed out that replaying from the root commit is sometimes the intended behavior. He proposes explaining when each form is appropriate rather than treating one as inherently wrong. This reflects Git philosophy of documenting capabilities accurately while trusting users to choose the right tool for their situation.
