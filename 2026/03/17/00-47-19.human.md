Maintainer follow-up on a bugfix for `git rev-parse --parseopt` help behavior. Junio C Hamano notes a test failure in `t1517` when applying brian m. carlson's patch that makes help requests exit successfully (status 0) rather than reporting an error (status 129). The failure occurs in the `git instaweb -h` test outside a repository, which still expects status 129.

This appears to be an oversight in the patch's scope - while it fixed the `--parseopt` behavior, it didn't account for how that change might affect other commands using the option parsing infrastructure. The test failure reveals that `git instaweb` (and likely other commands) still rely on the old error-exit behavior for help requests in certain contexts.

The patch itself was well-reasoned and carefully implemented, but this shows the challenge of changing fundamental behaviors in Git's option parsing. Junio's note is characteristically concise but points to a real issue that will need addressing before the change can be merged. This kind of subtle interaction is exactly why Git's extensive test suite is so valuable.
