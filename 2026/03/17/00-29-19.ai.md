This is the third patch in Derrick Stolee's 5-part series enhancing the `git backfill` command for partial clone functionality. The patch adds support for revision arguments like `--first-parent`, commit ranges, and pathspecs to allow more targeted blob downloads in blobless partial clones.

The key changes in this patch:
- Uses `setup_revisions()` to parse revision arguments, enabling all standard Git revision walk options
- Maintains backward-compatible HEAD-only behavior when no arguments are given
- Adds comprehensive tests demonstrating various revision walk scenarios (ranges, stdin input, `--all`, `--first-parent`, `--since`)
- Documents that `git backfill` now accepts the same revision options as `git rev-list`

Notable implementation details:
- The patch currently downloads all blobs regardless of pathspecs (marked with TODO comments)
- Test cases verify the expected blob counts after each operation
- The test repository includes complex branching/merging to exercise different walk scenarios
- Performance considerations are deferred to later patches (prefix pathspec optimization in patch 4, wildcard support in patch 5)

This builds cleanly on the test infrastructure from patch 2 and sets up the foundation for the more targeted pathspec optimizations coming in the next patches. The implementation appears thorough and well-tested, with clear documentation of both current behavior and planned future improvements.
