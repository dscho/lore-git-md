This is the core patch in a series that improves Git's line-log functionality (`git log -L`). The patch removes the hand-rolled `dump_diff_hacky()` function that was producing line-log output and replaces it with proper integration into Git's standard diff pipeline via `builtin_diff()`.

The key change routes line-log output through the same path used by regular diffs, which enables several previously-unsupported features to work with `-L`:
- Diff formatting options like `--word-diff`, `--color-moved`, and `-w` now work
- Pickaxe options (`-S`, `-G`) are properly supported
- Output now includes standard diff headers (index lines, file mode changes) and funcname context in `@@` headers that were previously missing

The implementation introduces callback wrappers that filter xdiff output to only the tracked line ranges while maintaining proper diff structure. The patch also makes `-L` imply `--patch` during revision setup rather than forcing it at output time.

This is a user-visible change that may affect tools parsing `-L` output, as the format is now more complete and standardized. The commit message notes there's no measurable performance impact, and extensive test updates verify the new behavior.
