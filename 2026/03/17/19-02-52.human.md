This is a bugfix for the commit-graph generation number computation, addressing a regression introduced by Patrick Steinhardt's own recent change. The issue occurs when commit dates exceed 34 bits (dates after year 2514), causing generation number calculations to underflow during commit-graph writing.

The patch introduces a new helper function `compute_generation_offset()` that explicitly masks commit dates to 34 bits before calculating generation offsets, matching how commit-graph actually stores dates. This fixes a mismatch that could occur when commits were parsed both from the object database (with full 64-bit dates) and from the commit-graph (with 34-bit dates).

The fix is well-motivated and comes with a new test case that verifies the behavior with artificially large commit dates. The commit message clearly explains the technical background and impact of the regression. Given Patrick's deep involvement in the commit-graph subsystem and the clear regression test, this appears to be a solid fix for a real issue found in GitLab's test suite.
