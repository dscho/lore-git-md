This is a follow-up bump for a Google Summer of Code (GSoC) proposal about implementing prioritized fetching from multiple promisor remotes. The student, Abraham Samuel Adekunle, is seeking final reviews on his v2 proposal before the GSoC application deadline.

The proposal builds on Christian Couder's promisor-remote work to optimize object fetching in partial clone scenarios. Key changes in v2 include dropping the originally proposed `promisor.honorServerFetchOrder` config in favor of reusing the existing `promisor.storeFields`, expanding the scope to handle all partial clone objects (not just blobs), and adding documentation for edge cases in partial-clone.adoc.

The implementation will proceed in two phases: first adding local priority ordering via `remote.<name>.priority` configuration, then extending to protocol-level negotiation with a new v2 promisor-remote capability that includes a priority field. Some open questions remain about the exact protocol negotiation flow and whether to extend existing configs versus introducing new ones.

Abraham has demonstrated responsiveness to feedback and technical understanding through prior contributions (including a merged `git add -p` patch and another currently in `next`). Christian Couder's review indicates this addresses a real need for partial clone users while being appropriately scoped for a GSoC project. The proposal is now in its final review stage before the GSoC application deadline.
