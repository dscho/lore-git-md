This is a bugfix patch that extends `git apply`'s error reporting to include input file locations for header parsing errors. It's part of Jialong Wang's ongoing series to improve error diagnostics when applying patches.

The patch modifies `parse_git_diff_header()` and related functions in `apply.c` to report which input file (or stdin) contained malformed headers, rather than just showing line numbers. This helps users identify problematic patches when applying multiple files at once. The changes maintain backward compatibility while adding more context to error messages for:
- Missing filename information
- Invalid mode specifications
- Malformed patch fragments
- Inconsistent old/new filenames
