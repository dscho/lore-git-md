Git replay root commit handling patch series (v1 -> v2)

Thread identity: Patch series enabling `git replay` to handle root commits (commits with no parents), authored by Toon Claes. Technical change to the relatively new `git replay` command.

Core problem: The `git replay` command previously rejected attempts to replay commit histories that included root commits (initial commits with no parents). This limitation prevented complete history replay operations in some cases.

Technical changes:
- Modified `replay.c` to properly handle root commits by:
  - Adding parent existence checks before parent access
  - Using empty tree for root commit diffs
  - Removing explicit root commit rejection
- Updated test case in t3650-replay-root-commits.sh to verify functionality
- Minimal changes focused only on root commit handling
- Maintains all existing behavior for non-root commits

Current status: Version 2 will incorporate maintainer feedback by:
1. Moving root commit handling into `mapped_commit()` for API consistency
2. Improving merge ancestor labels to show "empty tree" for root commits
These changes address both the technical design point raised by Junio and an orthogonal UX improvement identified by the author.

Open questions: None remaining - the maintainer's design concern has been confirmed as valid and will be addressed in v2, along with additional messaging improvements.

Participant positions:
- Toon Claes: Confirmed technical constraint in `mapped_commit()` and will implement suggested refactoring plus additional UX improvement in v2
- Junio C Hamano: Original design question about API boundaries validated by contributor
