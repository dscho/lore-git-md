Git replay root commit handling patch series (v1)

Thread identity: Patch series enabling `git replay` to handle root commits (commits with no parents), authored by [author name]. Technical change to the relatively new `git replay` command.

Core problem: The `git replay` command previously rejected attempts to replay commit histories that included root commits (initial commits with no parents). This limitation prevented complete history replay operations in some cases.

Technical changes:
- Modified `replay.c` to properly handle root commits by:
  - Adding parent existence checks before parent access
  - Using empty tree for root commit diffs
  - Removing explicit root commit rejection
- Updated test case in t3650-replay-root-commits.sh to verify functionality
- Minimal changes focused only on root commit handling
- Maintains all existing behavior for non-root commits

Current status: Initial version (v1) of patch. Maintainer Junio C Hamano has reviewed and generally approved the change while raising a design question about `replayed_base` handling consistency between root and non-root commits. He suggests the special case might better belong inside `mapped_commit()` but acknowledges this is a minor point.

Open questions: Whether to refactor the `replayed_base` handling to be more consistent between root and non-root cases by moving logic into `mapped_commit()`. Maintainer indicates this is optional refinement rather than a blocking issue.
