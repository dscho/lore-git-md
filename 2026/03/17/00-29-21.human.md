This is the final patch in Derrick Stolee's 5-part series enhancing `git backfill` for partial clones. The series adds revision arguments and pathspec filtering to enable targeted blob downloads in blobless clones.

Patch 5/5 implements wildcard pathspec support, completing the feature set. The key changes are:

1. A new `exact_pathspecs` flag distinguishes simple prefix matches (handled efficiently via tree walking) from complex patterns requiring full pathspec matching.

2. Disabling commit pruning (`revs->prune=0`) for wildcards ensures all relevant commits are visited, since TREESAME detection doesn't work well with glob patterns across directory boundaries.

3. Actual blob filtering happens via `match_pathspec()` in `walk_path()`, which checks each blob's full path against the wildcard.

The test case demonstrates the improvement - from downloading all 48 blobs to just 40 when using a `d/file.*.txt` pattern. This matches the expected behavior where only blobs matching the glob are fetched.

The implementation is careful to maintain backward compatibility while adding the new functionality. Stolee's methodical approach throughout the series shows his characteristic attention to large-repository performance implications. With this patch, the feature set appears complete and well-tested, ready for real-world use in optimizing workflows like `git blame` in partial clones.
