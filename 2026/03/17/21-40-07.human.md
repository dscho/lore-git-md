This is a refactoring patch from René Scharfe that replaces uses of `prio_queue` in LIFO (stack) mode with the more appropriate `commit_stack` type. The change affects three files: `builtin/name-rev.c` and two negotiation implementations (`negotiator/default.c` and `negotiator/skipping.c`).

The patch demonstrates René's characteristic style - a focused, mechanical improvement that makes the code more type-safe and self-documenting. The key insight is that when `prio_queue` is used with a NULL compare function, it effectively behaves as a stack (last-in-first-out), so using the dedicated `commit_stack` type better expresses the intent while also saving some memory (since `prio_queue` carries extra overhead for tie-breaking counters that aren't needed for stack operations).

The changes are straightforward replacements of `prio_queue` operations with their `commit_stack` equivalents. The behavior remains identical, but the code now more clearly communicates that it's using stack semantics. This is part of René's ongoing work to improve code clarity and type safety throughout the Git codebase.
