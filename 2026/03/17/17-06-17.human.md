This is a follow-up in the ongoing discussion about exit codes for help flags in Git commands. Junio C Hamano weighs in on Jeff King's (Peff) suggestion to standardize help flag behavior across Git.

Junio agrees with Peff's position that `-h`/`--help` should generally exit with status 0 (success) rather than 129 (error). He acknowledges this would be a behavioral change rather than just a bugfix, and suggests investigating the historical rationale for the current 129 exit code. 

Notably, Junio indicates openness to making this change at the Git 3.0 boundary if needed, treating it as a deliberate backward-incompatible change rather than sneaking it in as a bugfix. This positions the discussion as a policy decision about Git's interface conventions rather than just a technical fix.

The email reinforces that this is now a broader discussion about Git's help behavior across all commands, not just the original `rev-parse --parseopt` case. Junio's willingness to consider this for Git 3.0 suggests the change may have legs if the historical investigation doesn't reveal strong reasons to keep the current behavior.
