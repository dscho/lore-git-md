This is a technical discussion about standardizing help flag exit codes in Git's option parsing infrastructure. Jeff King (Peff) follows up on Junio C Hamano's suggestion to research the historical rationale for using exit code 129 for help requests, reporting that he found no convincing justification in the commit history or mailing list archives.

Peff analyzes potential backward compatibility risks of changing to exit 0 for help requests, considering scenarios where scripts might unintentionally continue execution after a help request. He concludes that while theoretically possible, such cases would be rare and likely indicate poor script design that should be fixed regardless. The most concerning case would be a script that silently processes help output as if it were normal command output, but Peff argues this represents an edge case that shouldn't block the change.

The email reinforces the maintainer's position (established in Junio's previous message) that standardizing on exit 0 is the right direction, while addressing the remaining open question about compatibility impact. Peff's analysis suggests the change could proceed without waiting for Git 3.0, as the risks appear minimal. This moves the discussion toward implementation, with the technical concerns now thoroughly vetted and the maintainer's approval in place.
