This is the core patch in a series that improves Git's line-log functionality (`git log -L`). The patch removes the hand-rolled `dump_diff_hacky()` function that was bypassing Git's standard diff pipeline, and instead routes line-log output through `builtin_diff()` and `fn_out_consume()` like regular diffs.

The change enables several previously-unsupported diff features to work with `-L`, including `--word-diff`, `--color-moved`, pickaxe options (`-S`, `-G`), `--orderfile`, and `--diff-filter`. It also makes the output more complete by including index lines, file mode headers, and funcname context in `@@` headers that were previously missing.

The implementation introduces callback wrappers that filter xdiff's output to only the tracked line ranges while maintaining proper diff formatting. The patch also makes `-L` imply `--patch` during revision setup rather than forcing it at output time, and switches `diff_filepair_dup()` to use `xcalloc` for proper initialization of new fields.

The changes touch core diff infrastructure (`diff.c`, `diffcore.h`) and the line-log implementation (`line-log.c`), with extensive test updates to verify the new behavior. While this is a user-visible output change that may affect tools parsing `-L` output, benchmarks show no measurable performance impact.

This is part of a larger effort to properly integrate line-log with Git's diff machinery while maintaining backward compatibility. The patch follows up on a longstanding NEEDSWORK comment that acknowledged the hand-rolled diff approach wasn't ideal.
