This is a feature patch that introduces a new "preparing" phase to Git's reference-transaction hook, allowing distributed Git systems to coordinate reference updates earlier in the transaction flow. The patch comes from Eric Ju (with contributions from Patrick Steinhardt, Justin Tobler, and Karthik Nayak) and has undergone several rounds of review, now in its final polished form.

The change adds a new notification point before reference locks are acquired, giving systems like GitLab's Gitaly/Praefect a chance to coordinate concurrent writes. This complements the existing "prepared", "committed", and "aborted" phases. The implementation updates documentation, adds test coverage, and improves error messages to clearly indicate which phase caused an abort.

The patch has been thoroughly reviewed by Junio Hamano and other ref backend experts, with all substantive concerns addressed. The remaining changes in this version are minor polish items like error message formatting and documentation clarity. This is a well-considered addition to Git's hook system that should help distributed Git implementations while maintaining backward compatibility.
