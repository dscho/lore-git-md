This is the first patch in a series fixing and improving Git's line-log functionality (`git log -L`). The patch specifically addresses a crash that occurs when combining `-L` with pickaxe options (`-G`, `-S`, `--find-object`) in repositories with renamed files.

The core issue stems from how rename detection interacts with pickaxe filtering. When detecting renames for line-level history tracking, the code was passing the caller's diff_options (which may include pickaxe filters) directly to the rename detection. This could cause diffcore_pickaxe() to discard diff pairs needed for proper rename tracking, leading to either silent history truncation (before a2bb801f6a) or assertion failures (after that commit).

The fix follows blame's approach by creating a private diff_options struct for rename detection, isolating it from user-specified pickaxe options. This ensures rename detection sees the complete set of diff pairs regardless of any pickaxe filters. The patch includes tests verifying the fix works with various pickaxe options (-G, -S, --find-object) across rename boundaries.

While this prevents crashes, the patch notes that commit-level filtering by pickaxe options doesn't yet work properly with `-L` (marked with test_expect_failure). This limitation will be addressed in later patches in the series. The changes are localized to line-log.c and come with extensive test coverage in t4211-line-log.sh.

This is a well-motivated fix that addresses a real crash scenario while laying groundwork for broader line-log improvements. The implementation is clean and follows established patterns from blame's rename handling. The thorough test cases demonstrate both the fixed behavior and known limitations that will be tackled next in the series.
