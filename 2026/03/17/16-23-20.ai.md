This is a bugfix patch that extends `git apply`'s error reporting to include input file locations in header parsing errors. It's part of Jialong Wang's ongoing series to improve error diagnostics when applying patches.

The patch modifies `parse_git_diff_header()` and related functions in `apply.c` to report the input filename (or stdin) alongside line numbers when header parsing fails. This helps users identify which patch in a multi-patch input caused the error. The changes maintain backward compatibility by falling back to line-number-only messages when no filename context is available.

Key technical changes include:
- Adding `patch_input_file` to `gitdiff_data` struct to track the input source
- Updating error messages in `parse_mode_line()`, `gitdiff_verify_name()`, and other header parsing functions to include filename context
- Modifying test expectations in `t4100-apply-stat.sh` and `t4254-am-corrupt.sh` to verify the new error formats
- Adding new test cases for malformed headers, missing filenames, and invalid modes
