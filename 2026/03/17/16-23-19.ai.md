This is a bugfix patch that continues Jialong Wang's work to improve `git apply` error reporting by adding source file information to corrupt patch detection messages. The patch specifically addresses cases where a patch contains malformed hunk headers that overflow line number limits.

The changes modify `apply.c` to include the input filename (or `<stdin>`) in error messages when reporting corrupt patches, and resets the line counter between patch inputs to maintain accurate reporting. The implementation adds test coverage for file input, stdin, and multiple patch scenarios in `t4100-apply-stat.sh`, while updating existing binary patch tests in `t4012-diff-binary.sh` to expect the new error format.

This appears to be a straightforward extension of the previously merged work, maintaining the same clean approach and thorough test coverage. The changes are focused and well-contained, touching only the error reporting paths without modifying core patch application behavior. The patch follows the established pattern of "error: corrupt patch at <file>:<line>" formatting that was already accepted in the earlier series.

Key technical details for future reference:
- Modifies error reporting in `parse_single_patch()` to include `state->patch_input_file`
- Resets `state->linenr` in `apply_patch()` when processing new input files
- Updates test expectations in `t4012-diff-binary.sh` to check for filename in errors
- Adds new test cases in `t4100-apply-stat.sh` covering stdin and multiple file scenarios
- Maintains consistent error message format with previous work

As part of a GSoC contribution, this demonstrates continued progress in addressing the original problem comprehensively while maintaining code quality and test coverage.
