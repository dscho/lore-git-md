This thread addresses a regression in commit-graph generation number calculations for commits with extremely large timestamps (dates after year 2514). The bug was introduced by Patrick Steinhardt's earlier commit 024b4c9697 and was caught by GitLab's test suite, which happened to include a repository with a commit dated in year 2600+.

Patrick has provided a fix that adds a new helper function, compute_generation_offset(), to properly handle 34-bit date truncation consistently across all code paths. The solution maintains backward compatibility while adding a test case that verifies correct behavior with timestamps as far out as year 292,471,210,647. Junio Hamano has reviewed and approved the fix for inclusion in the integration queue.

Patrick clarified that the test case wasn't artificially constructed - GitLab actually encountered this issue with real repository data containing these extreme dates. This confirmation strengthens the case for the fix's test coverage. With the maintainer's approval and no outstanding technical concerns, this appears ready to be merged as part of the next release cycle.
