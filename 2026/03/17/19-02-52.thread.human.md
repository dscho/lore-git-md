This thread addresses a regression in commit-graph generation number calculations that was introduced by Patrick Steinhardt's recent commit 024b4c9697. The issue affects commit dates after year 2514, where the commit-graph format's 34-bit date storage could cause generation number mismatches when commits were parsed both from the commit-graph and the object database (which uses full 64-bit timestamps).

Patrick has submitted a fix that introduces a new `compute_generation_offset()` helper function to consistently mask dates to 34 bits before calculations. The solution has been well-received, with Junio C Hamano and Derrick Stolee both approving the approach. A key strength of the fix is its test case, which uses real-world data from GitLab's test suite containing extremely large dates (year 292,471,210,647) to verify the edge case handling. The patch maintains backward compatibility while resolving the regression.

The discussion highlights how production test environments can surface edge cases that might otherwise go unnoticed. With the fix now in its second version and having addressed all feedback, it's expected to be merged into the integration queue shortly. The combined review from Steinhardt (the original author), Hamano (the maintainer), and Stolee (a commit-graph expert) gives high confidence in the solution's correctness.
