This is a refactoring patch (part 2/3 of a series) fixing incorrect buffer size allocations when using `strbuf_attach()`. The patch corrects several call sites that were passing `alloc == len` to `strbuf_attach()`, which violates the function's requirement that the buffer must have at least `len+1` bytes to accommodate the NUL terminator.

The changes touch five files (`builtin/am.c`, `builtin/fast-import.c`, `mailinfo.c`, `refs/files-backend.c`, and `trailer.c`), each following the same pattern of adding `+1` to the allocation size when attaching NUL-terminated strings. This is part of a larger cleanup effort around strbuf memory management that has been progressing through the mailing list, with some preparatory strbuf fixes already merged by Junio.

The patch appears straightforward and mechanical, addressing a clear correctness issue. Since it's part of a series that has already undergone multiple rounds of review (primarily focused on the HTTP 429 rate limiting feature in other patches), this particular change seems uncontroversial and well-contained. The author (Vaidas Pilkauskas) has demonstrated responsiveness to feedback in previous iterations of the series.
