This is a bugfix for the commit-graph generation number computation, addressing a regression introduced by Patrick Steinhardt's recent commit 024b4c9697. The issue occurs when dealing with commit dates that exceed 34 bits of precision (dates after year 2514).

The commit-graph format stores only 34 bits of commit dates to save space, while the full `timestamp_t` type has 64 bits. The regression caused mismatches when a commit was parsed both from the commit-graph (with 34-bit dates) and then re-parsed from the object database (with full 64-bit dates), leading to generation number calculation errors during commit-graph writes.

The fix introduces a new helper function `compute_generation_offset()` that explicitly masks commit dates to 34 bits before calculating generation offsets, ensuring consistent behavior regardless of how the commit was parsed. The patch includes a test case that verifies the fix works with extremely large dates (year 292,471,210,647) that would trigger the overflow condition.

This is a well-contained fix with clear motivation, thorough explanation in the commit message, and includes a regression test. The change affects commit-graph writing performance but maintains backward compatibility with existing graphs. The patch comes from a trusted contributor (Patrick Steinhardt) who maintains deep expertise in this area of the codebase.
