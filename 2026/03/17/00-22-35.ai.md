This is a bugfix patch that improves error reporting in `git apply` when processing binary patches and garbage input. The patch comes from Jialong Wang as part of Google Summer of Code (GSoC).

The main change enhances error messages to include the input file name along with line numbers when reporting issues with binary patches. Previously, errors would show only line numbers, which could be ambiguous when multiple patch files are processed together. The patch updates three error cases: corrupt binary patches, unrecognized binary patches, and patches containing only garbage.

The changes are straightforward - modifying error message formats in `apply.c` to include `state->patch_input_file` alongside line numbers. The patch includes corresponding test updates in `t4100-apply-stat.sh` and `t4103-apply-binary.sh` to verify the new error reporting behavior. The tests specifically check that:
1. Garbage patches report the input file in the error
2. Corrupt binary diffs show the input file and correct line number
3. Unrecognized binary formats properly identify the input file

This appears to be a well-scoped improvement to user feedback, with clear test coverage. The changes are mechanical and unlikely to be controversial, focusing solely on error reporting without altering core functionality. The patch follows Git's style conventions and includes a proper sign-off.
