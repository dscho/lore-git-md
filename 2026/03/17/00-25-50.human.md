This is Junio Hamano's biweekly "What's cooking in git.git" status report, providing updates on the state of various Git development topics. The report covers patches that have graduated to 'master' (stable), new topics under consideration, ongoing work in 'next' and 'seen' branches, and discarded efforts.

Several notable patches have recently graduated to 'master':
- `ds/for-each-repo-w-worktree` fixes `git for-each-repo` behavior in worktrees
- `hn/status-compare-with-push` adds configurable branch comparison to `git status`
- `jk/unleak-mmap` plugs memory leaks in mmap handling
- `ps/odb-sources` restructures the object source API for pluggable backends
- `sp/wt-status-wo-the-repository` reduces global variable usage in wt-status

New topics under consideration include:
- `ej/ref-transaction-hook-preparing` adds a "preparing" phase to reference-transaction hooks
- `hn/git-checkout-m-with-stash` teaches `checkout -m` to use autostash
- `kh/name-rev-custom-format` adds format options to `git name-rev`
- `pw/worktree-reduce-the-repository` reduces global repository usage in worktree code
- `dd/cocci-do-not-pass-strbuf-by-value` adds a Coccinelle rule to prevent strbuf by value

Ongoing work includes:
- `ps/object-counting` cleaning up object counting logic
- `ps/upload-pack-buffer-more-writes` optimizing upload-pack performance
- `pt/fsmonitor-linux` implementing fsmonitor for Linux
- `tb/incremental-midx-part-3.2` improving MIDX/bitmap repacking
- `ar/parallel-hooks` enabling parallel hook execution

The report also notes several documentation improvements, test cleanups, and platform-specific fixes. Junio is holding some potentially controversial changes (like sideband sanitization) in 'next' longer than usual for additional testing.

This status update shows Git development remains active across multiple fronts, with particular focus on performance optimizations, API restructuring, and expanding functionality of existing commands. The maintainer continues his careful curation of patches, allowing complex changes to mature before merging while quickly accepting straightforward improvements.
