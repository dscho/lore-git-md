This is the final patch in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The patch implements the core functionality where local changes are automatically stashed before the branch switch and reapplied afterward, with conflict handling similar to `git rebase --autostash`.

Key improvements in this version:
- Adds proper lock file cleanup in error paths
- Preserves the optimized dry-run approach from previous versions
- Maintains silent stash creation behavior
- Includes branch-specific conflict marker labeling
- Adds comprehensive test coverage (18 new test cases in t7201-co.sh)

The behavior now:
1. Automatically stashes local changes when `-m` encounters conflicts
2. Only shows "Applied autostash" on success
3. Preserves the stash with conflict resolution instructions if reapplying fails
4. Skips stashing when changes don't conflict with the branch switch
5. Handles both staged and unstaged changes appropriately

The implementation touches multiple components:
- `builtin/checkout.c` for the merge/checkout logic
- `builtin/stash.c` for stash application
- `sequencer.c` for autostash handling
- Documentation updates for both `git-checkout` and `git-switch`

The patch appears technically complete with all major concerns addressed from previous reviews. It builds on the stash labeling options introduced earlier in the series and cleanly integrates with existing autostash infrastructure. The extensive test coverage gives confidence in the behavior across various edge cases.
