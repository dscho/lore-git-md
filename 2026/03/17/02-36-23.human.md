Feature patch extending Git's reference-transaction hook with a new "preparing" phase. This is the third iteration of Eric Ju's patch, now incorporating all requested changes from maintainer Junio Hamano and reviewers Patrick Steinhardt, Justin Tobler, and Karthik Nayak.

The patch adds a new hook phase that fires before reference locks are acquired, enabling distributed Git systems like GitLab's Gitaly/Praefect to coordinate concurrent writes earlier in the transaction flow. The implementation maintains clean error handling while improving the error messages to be more concise and consistent. Documentation and tests have been updated to reflect the new phase.

Key changes in v3:
- Error messages were shortened and reordered to highlight the phase name earlier
- The error string was extracted as a shared constant to avoid duplication
- Commit message formatting was improved for better readability

The patch appears ready for integration, having addressed all substantive technical feedback while maintaining backwards compatibility with existing hook implementations. The changes are focused and well-tested, with clear motivation from real-world distributed Git storage needs.
