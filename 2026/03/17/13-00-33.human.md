This is a bugfix patch from Vaidas Pilkauskas, part of a larger effort to improve HTTP 429 rate limit handling (though this particular patch stands alone). It fixes an off-by-one allocation error in `strbuf_reencode()` where the function was passing an allocation size one byte too small to `strbuf_attach()`. 

The issue caused unnecessary reallocations since the buffer would always appear too small. The fix is straightforward - passing `len + 1` instead of `len` to account for the NUL terminator. This patch was already approved by Junio Hamano in earlier iterations of the series and is being included here for completeness alongside the main HTTP 429 feature work.

The change is small (just one line modified) but corrects a subtle memory management issue that could impact performance when reencoding strings. The commit message clearly explains both the problem and solution, and the patch has already gone through review cycles as part of the larger series. This appears ready to merge as a standalone improvement.
