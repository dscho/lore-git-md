This is the third patch in Derrick Stolee's series enhancing `git backfill` for partial clones. The patch adds revision argument support to the command, allowing users to specify commit ranges, pathspecs, and other revision-limiting options.

The key change is integrating Git's revision parsing machinery via `setup_revisions()`, which enables all the commit-walking options familiar from `git rev-list`. This includes features like `--first-parent`, `--since`, and commit ranges. The implementation maintains backward compatibility - when no arguments are given, it still defaults to walking from HEAD.

The patch includes extensive test coverage showing the command working with:
- Commit ranges (both direct and via stdin)
- Pathspecs (though these don't yet limit downloads as noted in TODOs)
- `--all` to cover all refs
- `--first-parent` to follow only mainline history
- `--since` to filter by commit timestamp

This is a solid foundation for the remaining patches which will optimize pathspec handling. The tests demonstrate the new flexibility while making it clear there's more work coming on the pathspec front. Stolee's approach here is characteristic of his large-repository optimization work - methodical, well-tested, and building incrementally toward more powerful functionality.
