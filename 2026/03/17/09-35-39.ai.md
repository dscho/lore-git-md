This is the final patch in a feature series (v6) that implements autostash behavior for `git checkout -m` when switching branches with conflicts. The patch builds on previous versions that introduced stash labeling options and silent stash creation, now completing the integration with checkout's merge behavior.

The key changes in this patch:
1. Modifies `git checkout -m` to automatically stash local changes when branch switching would cause conflicts, then reapply them after the switch
2. Preserves the existing merge conflict resolution workflow but integrates it with stash operations
3. Adds comprehensive error handling including proper cleanup of lock files
4. Extends the stash labeling capability (introduced in earlier patches) to work with autostash operations
5. Includes 18 new test cases in t7201-co.sh covering various edge cases

The implementation touches multiple subsystems:
- `builtin/checkout.c` for the core merge/checkout logic
- `builtin/stash.c` for the labeling options
- `sequencer.c` for autostash handling
- Conflict marker generation infrastructure

When conflicts occur during the autostash reapplication, the stash entry is preserved and the user is given clear instructions on how to proceed (either resolve conflicts and drop the stash, or reset and pop later). The patch maintains backward compatibility and integrates with existing merge configuration like `merge.conflictStyle`.

The series has evolved through multiple iterations with input from Junio Hamano and Phillip Wood, and appears technically complete with thorough test coverage. The only outstanding work noted is final documentation polish. This represents a significant quality-of-life improvement for users who frequently switch branches with uncommitted changes.
