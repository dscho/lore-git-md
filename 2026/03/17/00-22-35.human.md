This is a bugfix patch that improves error reporting in `git apply` when handling binary patches and garbage input. The patch comes from Jialong Wang as part of Google Summer of Code (GSoC).

The core change makes `git apply` report which input file contains errors when processing binary patches or garbage lines, rather than just giving line numbers. This is particularly helpful when applying multiple patches in a single invocation, as it helps users identify which specific patch file has issues.

The patch modifies three error messages in `apply.c` to include the input filename along with the line number. It also adds corresponding test cases in `t4100-apply-stat.sh` and `t4103-apply-binary.sh` to verify the new error reporting behavior works as expected.

The changes are straightforward and well-contained, touching only the error reporting paths while maintaining the existing functionality. The test coverage looks thorough, checking both the "corrupt binary patch" and "unrecognized binary patch" cases, plus the "patch with only garbage" scenario. This should be a non-controversial quality-of-life improvement for users dealing with patch application errors.
