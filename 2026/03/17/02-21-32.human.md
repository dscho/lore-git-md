This is the first patch in a series that improves Git's line-log functionality (`git log -L`). It fixes a crash that occurs when combining `-L` with pickaxe options (`-G`, `-S`) and renames. The issue arises because the rename detection machinery was using the caller's diff_options, which could include pickaxe filters that discard diff pairs needed for rename tracking.

The patch isolates rename detection by creating a private diff_options struct, following the same pattern used by `git blame`. This prevents user-specified pickaxe options from interfering with rename detection while still allowing them to filter the final output. The change is well-tested with new test cases that verify the fix works with `-G`, `-S`, and `--find-object` across rename boundaries.

The patch also notes that while this fixes the crash, commit-level filtering with pickaxe options doesn't yet work properly with `-L` (marked with `test_expect_failure`). That limitation will be addressed in later patches in the series. The implementation is clean and follows established patterns, with clear commit message explaining both the problem and solution.
