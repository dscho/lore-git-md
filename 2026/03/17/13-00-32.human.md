This is the sixth iteration of a feature patch series adding HTTP 429 rate limit retry support to Git's HTTP client. The series has been under review for several months, with Jeff King providing architectural guidance and Junio Hamano handling the simpler strbuf fixes separately.

The current version drops a helper function patch from v5 and makes several key refinements:
- Moves retry-after handling closer to the http_request core
- Fixes the retry counter separation between authentication and rate limiting
- Tightens test timing checks to avoid race conditions
- Improves documentation about libcurl version requirements

The implementation provides comprehensive support for HTTP 429 responses, including:
- Automatic retries with configurable limits (http.maxRetries)
- Both delay-seconds and HTTP-date Retry-After header formats
- Configurable defaults (http.retryAfter) when no header is present
- Maximum delay enforcement (http.maxRetryTime)
- Trace2 integration for monitoring retry behavior

The series appears well-tested with new test scripts covering various rate limiting scenarios. The changes are focused on remote-curl.c and http.c, with thorough documentation updates. Jeff King's earlier architectural concerns about the retry loop logic appear addressed in this version.

This is a mature implementation of a useful feature for working with rate-limited Git servers. The series has gone through multiple rounds of review and iteration, suggesting it's ready for final consideration. The strbuf fixes from earlier versions have already been merged separately by Junio.
