This is the final patch in Derrick Stolee's 5/5 series enhancing `git backfill` with wildcard pathspec support for blob filtering in partial clones. The patch completes the functionality introduced in earlier patches by properly handling wildcard and magic pathspecs rather than ignoring them.

The key changes introduce:
1. An `exact_pathspecs` flag to distinguish between simple prefix matches (handled via fast-path) and complex patterns requiring full matching
2. Disabled commit pruning for wildcard pathspecs to ensure all relevant trees are visited (since TREESAME detection doesn't work well across directory boundaries with fnmatch)
3. Actual pathspec matching at the blob level using `match_pathspec()`

The implementation shows measurable improvements in the test case - reducing downloaded blobs from 48 to 40 when using a "d/file.*.txt" pattern, demonstrating effective filtering. The changes touch the path-walk machinery and test suite, maintaining compatibility with the existing prefix optimization from patch 4 while adding the more general wildcard support.

This completes the series' goal of enabling targeted blob downloads via revision walking with pathspec filtering, particularly useful for operations like `git blame` and `git log -L` in large repositories. The careful handling of both exact prefixes and wildcards provides a balance between optimization and correctness.
