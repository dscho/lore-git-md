This is the third patch in Christian Couder's 16-part series introducing URL-based whitelisting for promisor remotes. The patch adds a new validation helper function to the urlmatch subsystem.

The change introduces `url_is_valid_pattern()`, a utility function that checks if a string appears to be a valid URL or URL pattern (allowing globs with `*`). The function leverages the existing `url_normalize_1()` infrastructure but adds a boolean return value for convenience. The commit message makes clear this is not a full URL validator - it's meant to catch obvious malformations while allowing some invalid hostnames to pass through.

This is a preparatory change for the series' main feature, which will use URL patterns to auto-configure promisor remotes. The implementation is straightforward and well-contained, with clear documentation in the header file about the function's limitations. The patch follows the series' pattern of careful, incremental refactoring before introducing new functionality.
