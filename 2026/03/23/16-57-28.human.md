This is the first patch in a feature series improving `git format-patch`'s commit list formatting capabilities. The patch focuses on improving error messages when unsupported format placeholders are used.

The change makes error messages for `%(count)` and `%(total)` placeholders more specific by explicitly naming the problematic placeholder in the error text, rather than using a generic "this format specifier" message. This helps users immediately understand which part of their format string caused the issue.

The patch is straightforward - it modifies two error messages in `pretty.c` to include the placeholder name. This is part of a larger effort to enhance the usability of `git format-patch`'s formatting options, but stands alone as a clear improvement to error reporting.

The change is small, well-contained, and clearly motivated - better error messages help users diagnose issues faster. It's a solid foundation for the rest of the series which will build on this with more substantial formatting improvements.
