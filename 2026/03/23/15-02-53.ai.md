This is part 2/12 of Patrick Steinhardt's v2 series refactoring Git's fsck subsystem to remove its dependence on the global `the_repository` variable, continuing the `the_repository` removal effort. The patch introduces a new `fsck_options_init()` function to handle initialization of `struct fsck_options`, replacing previous macro-based initialization patterns.

The change is motivated by the need to properly initialize a new repository field that will be added to `fsck_options` in the next patch. The initialization function provides a clean way to handle cases where options are initialized at file-static scope without access to a repository pointer. The patch updates all callers that previously used the `FSCK_OPTIONS_*` macros to instead use the new initialization function.

Key technical aspects:
- Adds `fsck_options_init()` in `fsck.c` with four initialization types (DEFAULT, STRICT, MISSING_GITMODULES, REFS)
- Removes the old initialization macros from `fsck.h`
- Updates initialization in 9 files across built-in commands and core functionality
- Maintains identical behavior while changing the initialization mechanism
- Prepares for repository pointer storage in the options struct (coming in patch 3/12)

The patch demonstrates careful mechanical refactoring with clear boundaries - it changes only initialization patterns without altering any fsck behavior. The series continues to show Patrick's characteristic thoroughness in large-scale refactorings, with each patch focused on a clear subtask. This foundational change enables the more substantial architectural shift coming in the next patch.
