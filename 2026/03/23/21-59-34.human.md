This is the second patch in a 3-part series implementing a new `--graph-lane-limit` feature for `git log --graph`. The patch focuses on the core graph truncation logic, modifying the graph rendering code to respect the lane limit while maintaining readability.

The implementation handles several edge cases:
- Excess lanes are shown as '.' markers rather than being silently dropped
- Commits on the first hidden lane still show their '*' marker (rather than a '.')
- Merge connections are preserved when needed but omitted when they'd be redundant
- The graph width calculation now accounts for the truncation marker

The changes touch graph.c extensively, modifying all the state-specific output functions (commit line, pre-commit line, post-merge line, etc.) to handle truncation consistently. The patch maintains the existing graph layout logic while adding the new constraints.

This iteration (v4) incorporates Junio Hamano's feedback by standardizing on `int` type for the lane limit and improving commit message clarity. The implementation appears thorough, with careful attention to edge cases in merge handling and lane collapsing. The changes are focused on the graph output without disrupting the underlying graph computation.
