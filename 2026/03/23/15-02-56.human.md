This is part 5/12 of Patrick Steinhardt's v2 series refactoring Git's fsck subsystem to remove dependence on the global `the_repository` variable. The patch focuses on `builtin/fsck.c`, converting trivial uses of `the_repository` to instead use the repository pointer already available in the function context.

The changes are mechanical but thorough - nearly 100 lines of code are modified to pass through or use the local `repo` parameter instead of the global variable. Key conversions include:
- Progress reporting functions now use the repository parameter
- Object checking and connectivity verification functions take the repository explicitly
- Cache tree and resolve-undo checking uses the index's repository
- Pack verification and bitmap checking uses the passed repository

This patch follows the series' systematic approach, building on the earlier structural change that stored the repository pointer in `fsck_options`. The changes maintain identical behavior while removing global state, making the code more explicit about its dependencies. As with the rest of the series, this is a well-contained change that moves incrementally toward the goal of eliminating `the_repository` from fsck entirely.
