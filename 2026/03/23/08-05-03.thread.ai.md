The series is being restructured into two parts based on Patrick Steinhardt's review feedback: (1) preparatory fixes/refactorings and (2) new functionality. Key technical components:
- New `promisor_info` struct with `local_name` field for remote tracking (consolidated from three separate data structures in patch 7)
- Strict URL pattern validation enforcing `*` cannot cross part boundaries (scheme/host/path)
- `url_matches_accept_list()` helper for secure allowlist matching
- Automatic remote creation via `sanitize_remote_name()` and `promisor_remote_name_from_url()`
- Collision handling with numeric suffixes and `remote.<name>.advertisedAs` for auditing
- Security model now explicitly documented:
  - Allowlisted URLs bypass `promisor.acceptFromServer=none`
  - Terminology from "whitelist" to "allowlist"
  - Warnings about protocol schemes and glob patterns
  - Risks of broad patterns on shared hosting
