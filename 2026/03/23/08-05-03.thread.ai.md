Christian Couder's 16-patch series introduces URL-based whitelisting for auto-configuring promisor remotes through new `promisor.acceptFromServerUrl` config option. The series systematically refactors promisor-remote handling (1-11), cleans tests (12), implements feature (13-15), and updates documentation (16).

Key technical components:
- New `promisor_info` struct with `local_name` field for remote tracking (consolidated from three separate data structures in patch 7)
- URL pattern validation and normalization (lowercasing, percent-decoding, path resolution)
- `url_matches_accept_list()` helper for secure whitelist matching
- Automatic remote creation via `sanitize_remote_name()` and `promisor_remote_name_from_url()`
- Collision handling with numeric suffixes and `remote.<name>.advertisedAs` for auditing
- Patch 8 refactors internal tracking by removing redundant `accepted` strvec in favor of unified `accepted_remotes` string_list

Security measures include:
- Default `ACCEPT_NONE` policy
- Configurable name prefixes ("promisor-auto-")
- Strict URL normalization to prevent bypass attempts
- Comprehensive test coverage of edge cases
