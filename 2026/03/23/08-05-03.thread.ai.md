Christian Couder's 16-patch series introduces URL-based whitelisting for auto-configuring promisor remotes through new `promisor.acceptFromServerUrl` config option. The series systematically refactors promisor-remote handling (1-11), cleans tests (12), implements feature (13-15), and updates documentation (16).

Key technical components:
- New `promisor_info` struct with `local_name` field for remote tracking
- URL pattern validation and normalization (lowercasing, percent-decoding, path resolution)
- `url_matches_accept_list()` helper for secure whitelist matching
- Automatic remote creation via `sanitize_remote_name()` and `promisor_remote_name_from_url()`
- Collision handling with numeric suffixes and `remote.<name>.advertisedAs` for auditing

Security measures include:
- Default `ACCEPT_NONE` policy
- Configurable name prefixes ("promisor-auto-")
- Strict URL normalization to prevent bypass attempts
- Comprehensive test coverage of edge cases

Junio Hamano's reviews raise important security concerns:
1. Need explicit definition of "trusted" behavior - likely equivalent to `promisor.acceptFromServer=all` but should be documented
2. Security tightening suggestions:
   - Limit protocol schemes to just `https://` and `ssh://` in code
   - Prevent `*` from matching across `/` boundaries in domain portions of glob patterns while maintaining backward compatibility for path portions
3. Terminology note about potential "allowlist" vs "whitelist" preference
4. Specific concerns about dangerous patterns like `https://*.example.com` matching malicious domains containing the substring

The discussion focuses on balancing security hardening with backward compatibility, particularly around glob pattern matching rules. Junio suggests restricting `*` in domain portions from matching slashes while maintaining current behavior for path portions, preventing exploits while preserving existing configurations like `[http "https://example.com/*"]`.

The final patch (16) currently documents both existing `promisor.acceptFromServer` and new `promisor.acceptFromServerUrl` options with:
- Clearer formatting showing all choices
- Fixed description of "knownName" behavior
- Security warnings for less secure choices
- Integration between old and new configuration methods

The series maintains backward compatibility while reducing manual configuration burden, with Junio's reviews highlighting areas needing stronger security defaults and clearer trust model documentation before integration. These concerns will likely be addressed in follow-up patches adjusting URL matching rules (particularly domain portion globbing behavior) and expanding security documentation. All other aspects of the series have been reviewed and are ready pending these security refinements.
