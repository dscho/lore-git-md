Bugfix addressing a NULL pointer dereference in path-walk error handling, now with a concrete reproduction case for the error path. The patch originally fixed a clear NULL dereference when reporting missing objects during path traversal, but initial discussion questioned whether the error path was actually reachable. Yuvraj Singh Chauhan now provides a specific test case involving a malformed tree that references a commit OID as a blob entry, demonstrating the error path is indeed reachable when object types conflict.

The core fix remains unchanged - using `entry.oid` instead of the potentially NULL `o->oid` in the error message. The new test case shows this occurs when:
1. A commit is registered in the object hash (e.g. via `--all` walk)
2. A tree entry incorrectly references that commit OID as a blob
3. `lookup_blob()` fails due to the type mismatch, returning NULL

This complements Derrick Stolee's earlier partial clone scenario and René Scharfe's malformed tree demonstration, providing three independent validations that the error path is reachable. The discussion has progressed from theoretical concern to practical validation, with all participants now agreeing the fix is correct and necessary. The patch appears ready for maintainer pickup in the next integration cycle.
