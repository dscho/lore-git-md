This is a refactoring patch in Christian Couder's series on URL-based whitelisting for promisor remotes. The patch modifies the `all_fields_match()` function to take a direct `config_entry` parameter instead of an `in_list` boolean, eliminating redundant config lookups when checking remote fields.

The key change replaces the dual-path logic (where `in_list` determined whether to scan all config entries or look up a specific one) with a more direct approach. Now callers pass either NULL (to check all entries) or a specific `promisor_info` struct (to check just one). This removes an implicit dependency on `advertised->name` that would become problematic in later patches when auto-configured remotes introduce a distinction between server-advertised names and local config names.

The patch maintains all existing functionality while improving efficiency and preparing for upcoming changes. It's a clean, focused refactor that follows the series' pattern of methodical preparation before introducing new features. The commit message clearly explains both the immediate benefit (avoiding redundant lookups) and the future-proofing aspect.
