This is a feature patch series introducing URL-based whitelisting for auto-configuring promisor remotes advertised by servers. The 16-part series from Christian Couder aims to reduce manual configuration burden while maintaining security.

The core addition is a new `promisor.acceptFromServerUrl` config option that lets clients specify URL glob patterns to automatically accept and configure promisor remotes from servers. The implementation includes several security measures: URL normalization before matching, sanitized auto-generated remote names, and configurable name prefixes to prevent conflicts. The series also refactors existing promisor-remote handling to support these changes while maintaining backward compatibility.

Notable technical aspects include:
- URL matching uses the existing urlmatch API with new helpers
- Auto-configured remotes get names like "promisor-auto-<sanitized-url>" or use specified prefixes
- Server-advertised names are preserved in `remote.<name>.advertisedAs` for debugging
- The promisor_remote_get_direct() function is modified to prioritize accepted remotes

The series appears well-structured with preparatory refactoring (patches 1-11), test cleanup (12), core feature implementation (13-15), and documentation updates (16). The CI tests pass, suggesting the changes are functionally sound. This looks like a substantial but carefully planned improvement to the promisor remote configuration system.
