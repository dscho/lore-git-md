This is a feature patch in Christian Couder's series introducing URL-based whitelisting for promisor remotes. Patch 14/16 implements the core URL matching logic that allows trusted remotes to update their configuration even when the strictest security setting (ACCEPT_NONE) is enabled.

The patch adds a new `url_matches_accept_list()` helper that checks if a remote's normalized URL matches any pattern in the `promisor.acceptFromServerUrl` whitelist. Key technical aspects include:

1. URL normalization before matching (lowercasing, percent-decoding, path resolution) to prevent bypass attempts
2. Integration with the existing `should_accept_remote()` logic to maintain security while allowing updates to trusted remotes
3. Documentation updates explaining the security implications and best practices for URL patterns
4. Comprehensive test cases covering whitelist matching, multiple patterns, and edge cases

The implementation builds on previous refactoring in the series, particularly the string_list-based config handling and promisor_info struct changes. Security considerations are prominent, with warnings about overly broad patterns and guidance for safe usage. The tests verify both the happy path and security edge cases, including URL mismatches and partial whitelisting.

This appears to be a well-constructed patch that carefully balances functionality with security, maintaining the series' focus on reducing manual configuration while preventing unsafe automatic remote additions. The documentation is thorough and the test coverage looks comprehensive.
