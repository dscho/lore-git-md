This is a refactoring patch in Christian Couder's series to improve promisor remote configuration. It's part 7 of 16 in the effort to introduce URL-based whitelisting for auto-configuring promisor remotes.

The patch simplifies the handling of accepted promisor remotes by keeping the `promisor_info` structs alive in a single list rather than splitting their data across multiple structures. This makes the code more straightforward by:
- Eliminating parallel data structures for names and filters
- Allowing iteration through one list instead of three
- Preparing for future additions (like a 'local_name' field) without requiring more parallel arrays

The changes are mechanical and don't affect behavior - they improve maintainability by reducing complexity of the data flow. The patch follows the established pattern in this series of cleaning up the existing code before adding new functionality in later patches.
