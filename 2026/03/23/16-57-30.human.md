This is a feature patch (part 3/8 in a series) from Mirko Faina that renames the `--cover-letter-format` option to `--commit-list-format` in `git format-patch`. The change aligns the command-line option name with the existing `format.commitListFormat` configuration variable and improves tab completion behavior by removing ambiguity with `--cover-letter`.

The patch makes two key changes: first, it renames the option throughout the codebase (documentation, implementation, and tests), and second, it makes specifying the format imply `--cover-letter` unless `--no-cover-letter` is explicitly given. This matches user expectations that specifying a format for the commit list means they want a cover letter.

The changes are well-contained and mechanical, updating all references to the old option name while maintaining the same functionality. The test suite is thoroughly updated to use the new name while verifying the same behaviors. This appears to be a straightforward improvement that follows Git's conventions for option naming and behavior.

This patch is part of a larger series that has already gone through multiple iterations with comprehensive review feedback incorporated. The series as a whole improves commit list formatting in patch emails with features like line wrapping, preset formats, and better documentation. This particular patch is a foundational piece that establishes the proper naming convention before the subsequent patches build on it.
