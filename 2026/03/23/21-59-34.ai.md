This is the implementation patch (2/3) in Pablo Sabater's v4 series adding `--graph-lane-limit` to `git log --graph`. The patch modifies graph.c to actually truncate graph output when the lane limit is exceeded, showing dots for hidden lanes while preserving commit markers.

The key technical changes in this patch:
- Adds width capping logic when `graph_max_lanes` is set, calculating maximum display width as `(lanes * 2) + 2` (accounting for "| " per lane and the truncation mark)
- Modifies all graph output states (padding, pre-commit, commit, post-merge, collapsing) to respect the lane limit:
  - Shows '.' for lanes beyond the limit
  - Preserves '*' commit markers on the first hidden lane
  - Skips post-merge state when both commit and first parent are hidden
- Maintains edge connections between visible lanes while truncating others
- Adds special handling for octopus merges to properly truncate while showing merge connections

The implementation is thorough, touching all graph rendering states while maintaining the visual integrity of the commit graph. It addresses the core challenge of the feature - balancing information density with readability by:
1. Clearly indicating truncation with dots
2. Preserving commit markers on the boundary lane
3. Maintaining necessary connection lines between visible commits

The patch builds on the infrastructure from patch 1/3 (which added the option plumbing) and will be complemented by patch 3/3 (documentation and tests). The author has incorporated all prior feedback, particularly around type handling and edge case behavior. This appears ready for final review, representing a focused solution to the long-standing graph width issue.
