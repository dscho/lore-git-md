This is a feature patch series introducing URL-based auto-configuration for promisor remotes, with security considerations around remote name sanitization and URL pattern matching. Christian Couder proposes a new `promisor.acceptFromServerUrl` config option that allows clients to whitelist remote URLs that can be automatically configured when advertised by a server.

The 16-part series starts with preparatory refactoring (patches 1-11) to clean up the promisor-remote handling code, then introduces the core functionality (patches 13-15) that enables auto-configuration of remotes whose URLs match patterns specified in the whitelist. The implementation includes name collision resolution (appending numeric suffixes when needed) and URL normalization to prevent bypass attacks. The final patch updates documentation.

The changes look well-considered, with thorough test coverage (t5710 updates show careful handling of file:// URIs across platforms) and clear security boundaries. The feature addresses a real usability pain point in partial clone workflows where administrators currently must pre-configure all possible promisor remotes. The series appears ready for review, with all CI tests. Given the security-sensitive nature of remote configuration, reviewers will likely scrutinize the URL matching and name sanitization logic closely.
