This is the second patch in a 2-part series improving Git's handling of custom bisect terms (like "old"/"new" instead of default "good"/"bad"). It fixes `git rev-parse --bisect` to properly respect configured bisect terms when looking up references.

The patch modifies `builtin/rev-parse.c` to read the current bisect terms (via `read_bisect_terms()`) and use them when constructing ref paths, rather than hardcoding "good"/"bad". This ensures `rev-parse --bisect` works correctly when alternate terms are in use. The change is straightforward - it just wraps the existing ref lookup logic with term-aware path construction.

This completes the series' goal of making Git's bisect functionality fully respect custom terminology. The first patch fixed `bisect status` output, and this one handles the ref lookup case. Together they provide consistent behavior when users configure alternate terms via `git bisect start --term-good`/`--term-bad`.

The patch appears well-crafted - it's a focused change with clear motivation, and builds on the existing bisect term infrastructure. It follows the pattern established in the first patch of the series, making the codebase more consistent in how it handles custom bisect terminology.
