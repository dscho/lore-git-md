This is patch 6/12 in Patrick Steinhardt's v2 series refactoring Git's fsck subsystem to remove dependence on the global `the_repository` variable. The patch focuses on converting the ref snapshotting functionality in `builtin/fsck.c` to use explicit repository pointers.

The key changes introduce a new `snapshot_ref_data` struct to carry both the repository pointer and snapshot context through the ref iteration callbacks. This replaces direct use of `the_repository` in several functions:
- `snapshot_ref()` now uses the repository from the callback data
- `snapshot_refs()` takes an explicit `repo` parameter and passes it through
- All ref-related operations (parse_object, is_promisor_object, repo_get_oid, etc. are updated to use the passed repository

The patch maintains the same behavior while eliminating global state access. It's a straightforward mechanical conversion that follows the pattern established in earlier patches of the series. The changes are well-contained to the fsck command's ref snapshotting logic and don't introduce any functional changes - this is purely about removing implicit state.

This continues the series' systematic approach to converting fsck's code paths one by one.
