This is part 7 of Patrick Steinhardt's 12-patch series refactoring the fsck subsystem to remove `the_repository` global variable usage. The patch focuses on converting ref-checking functionality in `builtin/fsck.c` to use explicit repository pointers.

The changes modify how repository context is passed through the ref processing call chain. Previously, these functions implicitly relied on `the_repository` when checking refs. The patch:
1. Modifies `fsck_handle_ref()` to take the repository as callback data rather than ignoring the parameter
2. Updates `process_refs()` to accept and pass through a `struct repository*` parameter
3. Adjusts the call site in `cmd_fsck()` to pass the repository pointer
4. Maintains identical behavior while eliminating global state

The changes are mechanical but important for the series' goal of removing `the_repository` dependencies. This continues the pattern seen in earlier patches of systematically converting callback chains to carry repository context explicitly. The patch is well-contained, touching only the ref processing path while leaving other fsck functionality unchanged.

This work connects to the broader `the_repository` removal effort and Patrick's ongoing work on object storage abstraction. The changes are low-risk since they don't modify behavior, just how repository context is passed. The patch follows the established pattern from earlier in the series and appears ready for merging as part of the complete set.
