This is a refactoring patch in Christian Couder's series on URL-based whitelisting for promisor remotes. It extracts control character checking logic into a new `has_control_char()` helper function that will be reused in upcoming patches. The change is straightforward: it moves the control character detection loop from `valid_token()` into a standalone function while maintaining the same behavior for token validation. The warning message about invalid tokens remains unchanged. This appears to be a preparatory change for future work in the series where control character checking will be needed in other contexts.
