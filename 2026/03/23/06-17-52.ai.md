This is a patch withdrawal notice in the ongoing `git backfill` argument validation thread. Siddharth Shrimali acknowledges that his v3 patch to reject unexpected arguments would conflict with Derrick Stolee's planned revision argument support for the command, and formally withdraws the patch.

The key technical point is that Stolee's approach will handle unknown arguments through Git's standard revision parsing machinery, producing "unknown revision" errors rather than the simpler "unknown argument" validation that Shrithmali's patch implemented. This makes Shrimali's validation approach obsolete since the responsibility for argument handling will shift to the revision walker.

Shrimali suggests it might still be valuable for Stolee to include a test case demonstrating the revision-parsing error behavior for unexpected arguments, since those error strings are less immediately clear to users than a direct "unknown argument" message. However, he defers to Stolee on whether to include such a test in the revision argument series.

The thread now concludes this particular validation approach, with all participants in agreement that the patch should be dropped in favor of the upcoming revision argument support. This clears the way for Stolee's work while maintaining the original goal of proper argument validation, just through different technical means. The discussion demonstrates how Git contributors coordinate to avoid conflicting changes, even when it means withdrawing otherwise sound work.
