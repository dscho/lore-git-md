This is patch 2/12 in Patrick Steinhardt's v2 series refactoring Git's fsck subsystem to remove its dependence on the global `the_repository` variable. The series is part of the ongoing `the_repository` removal effort.

The patch introduces a new `fsck_options_init()` function to initialize `struct fsck_options` instances, replacing the previous macro-based initialization approach. This change is necessary because future patches will add a repository field to the options struct that can't be initialized via macros in global scope. The patch updates all callers to use the new initialization function.

The changes are mechanical but thorough, touching fsck usage in several built-in commands (`fsck`, `index-pack`, `mktag`, etc.) and core object-file handling. The implementation maintains the same initialization patterns but moves them into function scope where repository pointers will be available.

This is a typical preparatory patch in a larger refactoring series - it doesn't change behavior but enables the architectural changes that follow. Given Patrick's track record with similar refactorings and the careful response to maintainer feedback in v1, this looks like a solid step toward the series' goal.
