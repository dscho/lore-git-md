Platform compatibility discussion about a macOS build workaround that may be needed in the future. Junio C Hamano responds to Johannes Schindelin's analysis of the Homebrew clang/REG_ENHANCED issue by proposing a different approach than keeping the original workaround patch in the integration branches.

Rather than applying the workaround now, Junio suggests adding a comment in `compat/regcomp_enhanced.c` that points to the original discussion and patch. This serves as documentation for future maintainers who might encounter the same issue when GitHub Actions updates their runner images again. The comment explains that if compilation fails on macOS with clang, the linked email thread contains a relevant workaround.

This approach avoids baking the workaround into the code when it's not currently needed, while still preserving the knowledge for when the issue resurfaces. The patch itself is minimal - just 5 lines adding a comment with context. Junio signs off with his characteristic pragmatic humor about letting future compilers detect the breakage themselves.

The exchange shows the project's preference for minimal, well-documented solutions over proactive workarounds when issues are currently mitigated. It also demonstrates how the mailing list archive serves as a knowledge base that can be referenced from the code itself.
