This is the core feature implementation patch in Christian Couder's series introducing URL-based whitelisting for promisor remotes. It adds the new `promisor.acceptFromServerUrl` config option that allows clients to specify URL glob patterns for automatically configuring promisor remotes advertised by servers.

The patch introduces key infrastructure:
- A new `struct allowed_url` to hold parsed remote name prefixes and URL patterns
- `valid_accept_url()` for validating and parsing config entries (checking remote name validity and URL pattern syntax)
- `accept_from_server_url()` to read and cache the config values
- Initial validation hook in `filter_promisor_remote()`

The config syntax allows optional remote name prefixes before URL patterns (e.g., "myremote=*.example.com"). The implementation uses Git's existing urlmatch API for pattern matching, though the actual matching logic will come in a follow-up patch. Error handling includes warnings for invalid remote names or URL patterns.

This builds on the preparatory refactoring from earlier patches in the series, particularly the string_list-based config handling and promisor_info struct changes. The patch maintains the series' focus on security by validating all inputs before use. The static initialization pattern for config caching follows established Git conventions.
