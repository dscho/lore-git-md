This is a follow-up in the `diff-highlight` optimization thread, where Jeff King (Peff) addresses a Perl version issue raised by Tian Yuchen. The patch in question optimizes config fetching in the contrib script by reducing multiple `git config` calls to a single invocation.

Jeff acknowledges that his earlier change to support Perl 5.8 (down from 5.26) introduced a compatibility issue with `length(undef)` behavior in Perl 5.8.8, which throws an uninitialized value warning where newer versions would return `undef`. He shares that he had originally written the code with an `exists()` check but simplified it for the patch, and now proposes using `defined($s) ? $s : $default` as a version-safe alternative that clearly expresses the intent without relying on newer Perl features like the `//` operator (added in 5.10).

The exchange demonstrates Jeff's responsiveness to compatibility concerns while maintaining the script's goals of broad Perl version support. This technical clarification resolves the open question about Perl 5.8 behavior and paves the way for a revised patch series that will address both this issue and the previously noted test script command chaining problem.
