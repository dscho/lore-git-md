This is a refactoring patch in Christian Couder's series on URL-based whitelisting for promisor remotes. It's the seventh of sixteen patches that aim to auto-configure promisor remotes from servers based on URL patterns.

The patch simplifies the handling of accepted promisor remotes in `filter_promisor_remote()` by keeping the `promisor_info` structs alive in a single `accepted_remotes` list rather than breaking them apart into separate parallel structures. This change:

1. Replaces three separate data structures (for server names, filter strings, and acceptance marking) with a single list of `promisor_info` structs
2. Makes the code more maintainable by reducing the number of parallel data structures that need to be kept in sync
3. Prepares for future changes by preserving the complete `promisor_info` structs, which will be needed when adding a `local_name` member in a subsequent patch

The refactoring doesn't change the external behavior but makes the internal implementation cleaner and more extensible. The patch follows the series' pattern of careful preparatory work before introducing new functionality, with all CI tests passing.
