Feature patch series improving bisect terminology flexibility.

This two-patch series from Jonas Rebmann addresses a limitation in Git's bisect functionality where some commands still use hardcoded "good"/"bad" terminology even when alternate terms (like "old"/"new") have been selected. The first patch ensures the bisect status output respects the chosen terms, while the second makes `git rev-parse --bisect` work with alternate terms too.

The changes are well-motivated by the inconsistency they fix, and the v2 iteration adds tests and improves the commit message. The implementation looks straightforward, modifying the relevant commands to use the configured terms rather than hardcoding "good"/"bad". This is a nice quality-of-life improvement for users who prefer different terminology in their bisect sessions.

The series builds on Git's existing support for custom bisect terms (added in Git 2.7.0) by making it more consistently applied throughout the bisect workflow. The changes are focused and the test additions provide good coverage of the new behavior.
