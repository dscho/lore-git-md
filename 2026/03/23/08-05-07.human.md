This is a documentation/UX improvement patch in Christian Couder's series on URL-based whitelisting for promisor remotes. It clarifies warning messages when Git ignores a promisor remote due to URL mismatches or empty URLs.

The patch modifies two warning messages in `promisor-remote.c` to explicitly state that the remote is being ignored, rather than just describing why it might be problematic. This makes the user experience clearer by directly communicating the consequence (the remote is ignored) rather than just the condition (URL mismatch or empty URL).

The changes are straightforward and focused - just adding ", ignoring this remote" to two existing warning messages. This is part of the larger refactoring effort (patches 1-11) that's preparing the groundwork for the main feature of auto-configuring promisor remotes based on URL patterns. The patch maintains the same code paths and logic while improving the messaging, so it's a low-risk change that makes the system more user-friendly.
