This is a refactoring patch in Christian Couder's series for URL-based whitelisting of promisor remotes. It's the second of 16 patches in the series.

The patch makes a straightforward type change in the urlmatch subsystem, converting a `char` parameter to `bool` in the `url_normalize_1()` function to better reflect its boolean usage. It also updates the two call sites to pass `true`/`false` literals instead of `1`/`0`. This is a small code hygiene improvement that makes the intent clearer while maintaining identical behavior.

The change is part of the preparatory work for the larger feature that will use URL matching for promisor remote configuration. While minor on its own, it's a clean, focused change that follows Git's coding guidelines and helps set up the infrastructure needed for the more substantial functionality coming later in the series.
