This is a refactoring patch (6/16) in Christian Couder's series introducing URL-based whitelisting for promisor remotes. The patch extracts the logic for parsing the `promisor.acceptfromserver` config value into a new `accept_from_server()` helper function, cleaning up the more complex `filter_promisor_remote()` function that will need additional logic in upcoming patches.

The change is straightforward - it moves the config parsing code while maintaining identical behavior. The new helper function returns an enum value (ACCEPT_NONE, ACCEPT_KNOWNURL, etc.) based on the config string, which `filter_promisor_remote()` then use as before. This prepares for future patches that will add more filtering logic while keeping the config parsing separate and testable.

The patch follows the series' pattern of incremental refactoring before introducing new functionality. It touches only `promisor-remote.c`, modifying how the code is organized without changing any user-visible behavior. The commit message clearly explains the motivation (reducing complexity in `filter_promisor_remote()` before adding more logic) and the change is cleanly implemented with proper type safety via the enum.
