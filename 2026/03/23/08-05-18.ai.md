This is a feature patch in Christian Couder's series introducing URL-based whitelisting for auto-configuring promisor remotes. Patch 15/16 implements the automatic remote creation when a server advertises a promisor remote with a URL matching the whitelist patterns in `promisor.acceptFromServerUrl`.

The patch adds several key components:
- `sanitize_remote_name()` transforms URLs into valid remote names by replacing special chars with dashes and prefixing with "promisor-auto-"
- `promisor_remote_name_from_url()` extracts host/port/path from normalized URLs to create human-readable base names
- `configure_auto_promisor_remote()` writes the new remote configuration including URL, promisor flag, and original advertised name
- Collision handling appends numeric suffixes when names conflict with existing remotes

The implementation integrates with the URL matching logic from earlier patches, automatically creating remotes when advertised URLs match whitelist patterns. It maintains security by:
- Strict name sanitization
- Preserving original server-advertised names in `remote.<name>.advertisedAs` for auditing
- Rejecting invalid patterns (like those with spaces in names)
- Limiting numeric suffix attempts to prevent DoS

The documentation is updated to explain auto-creation behavior, name generation rules, and collision handling. Extensive tests verify the functionality including:
- Basic auto-creation
- Named pattern matching
- Name collision handling
- Existing remote reuse
- Invalid pattern rejection

This completes the core functionality of the series, allowing servers to advertise promisor remotes that clients can automatically configure based on URL patterns, reducing manual setup burden while maintaining security controls. The implementation appears thorough with careful attention to edge cases and backward compatibility.
