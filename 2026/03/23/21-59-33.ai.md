This is the first patch in a v4 series introducing a `--graph-lane-limit` feature for `git log --graph`. The patch adds core infrastructure for limiting graph width in terminal output.

The change introduces a new `graph_max_lanes` field in `struct rev_info` to store the lane limit, with zero/negative values treated as "no limit" (This matches `--max-parents` behavior as requested in prior reviews.) The patch includes basic option parsing and validation, requiring `--graph` when the limit is set. The helper function `graph_needs_truncation()` is added to check when lanes should be truncated (implementation coming in patch 2/3).

Key technical details:
- New `revs->graph_max_lanes` field (type `int` per Junio's feedback)
- Option parsing via `--graph-lane-limit=<n>`
- Validation ensuring `--graph` is present when limiting
- Zero/negative values silently ignored (no limit)
- Core infrastructure without yet implementing truncation behavior

The patch follows through on design decisions from earlier rounds, particularly around type consistency and option semantics. It sets up the plumbing needed by subsequent patches while keeping the initial change focused. The implementation appears clean and well-contained, touching only the necessary files (graph.c, revision.c, revision.h) with straightforward additions.
