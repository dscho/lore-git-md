This is a refactoring patch that's part of the ongoing `the_repository` removal effort. Patrick Steinhardt moves fsck options from global scope into function scope in `fetch-pack.c`, where they are actually used.

The patch addresses two issues: first, global fsck options could accumulate state if reused, and second, upcoming changes will need to associate these options with a repository pointer (which isn't available at static initialization time). The changes move the fsck options into the `do_fetch_pack` and `do_fetch_pack_v2` functions where they're used, and properly clean them up with `fsck_options_clear()`.

The changes are mechanical and focused - just moving and cleaning up the fsck options declarations while maintaining identical behavior. This appears to be groundwork for future repository pointer changes rather than fixing any immediate bug. The patch follows Git's style well and includes a clear commit message explaining the rationale.
