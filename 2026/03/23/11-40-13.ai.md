This is a feature enhancement for the `git backfill` command, part of Git's partial clone functionality. The v2 series from Derrick Stolee expands the command's capabilities to support revision arguments and pathspec filtering, enabling more targeted blob downloads in blobless partial clones.

The key improvements in v2 include:
- Documentation formatting fixes (SEE ALSO section now matches Git standards)
- Code quality improvements using `add_head_to_pending()` instead of direct `handle_revision_arg()`
- Simplified prefix matching logic by reusing `dir_prefix()` from path.c
- Fixed a temporary memory leak in pathspec handling
- Re-enabled commit pruning optimization (confirmed safe for wildcard pathspecs)
- Added new test coverage for unknown argument handling

The series builds on Stolee's prior work on partial clones and large-repository performance. It enables use cases like downloading all versions of specific files/directories to accelerate `git blame` and `git log -L` operations. The implementation carefully handles both simple prefix pathspecs (optimized) and complex wildcard patterns (via post-filtering).

All substantive feedback from v1 has been addressed, including technical suggestions from Patrick Steinhardt and documentation notes from Kristoffer Haugsbakk. Junio C Hamano has acked all patches, indicating the series is ready for integration. The only remaining open items are a memory leak fix (already identified) and future considerations for `git blame` integration.
