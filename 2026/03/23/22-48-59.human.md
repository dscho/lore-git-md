This is the first patch in a 2-part series improving Git's handling of custom bisect terms. The patch focuses on making `git bisect status` output respect user-configured alternate terms (like "old"/"new") instead of always showing the default "good"/"bad" terminology.

The change addresses a real inconsistency - while Git allows configuring custom terms via `git bisect start --term-good/--term-bad`, some status messages still hardcoded "good"/"bad", leading to confusing output like showing "good commit known" while expecting the user to type "old" to mark commits. The patch updates all status messages in builtin/bisect.c to use the configured terms, with corresponding test updates in t6030.

The implementation looks clean and focused, touching only the necessary output strings while maintaining all existing functionality. Test coverage is thorough, verifying both the status output and bisect run behavior with custom terms. This appears to be a well-executed improvement to Git's bisect interface, particularly useful for users who prefer alternate terminology when tracking issue resolutions rather than regressions.
