This is a test infrastructure patch in Derrick Stolee's series enhancing `git backfill` for partial clones. The patch prepares a more complex test repository structure to properly exercise the upcoming revision and pathspec handling features.

The changes create a branched repository with:
- A main branch containing 8 linear commits plus a merge of a side branch
- A side branch adding `s/file.{1,2}.txt` with two versions (4 new blobs)
- An unmerged "other" branch adding `o/file.{1,2}.txt` (2 more blobs)
- Total of 54 blobs reachable from --all

Key test setup improvements:
- Adds `test_tick` before each commit for deterministic timestamps (enables reliable --since` testing)
- Renames `d/e/` to `d/f/` to create ambiguous pathspec cases
- Creates distinct server clones (srv.bare and srv-revs.bare) for different test scenarios

This is part of the v2 series that has already addressed all prior review comments and received Junio's ack. The test structure will be used in subsequent patches to verify that `git backfill` correctly handles revision ranges (--all, --first-parent, --since) and complex pathspec matching. The careful branching structure provides meaningful differences between these revision specifications.
