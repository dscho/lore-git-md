This is a refactoring patch in Christian Couder's series on URL-based whitelisting for promisor remotes. It introduces a `local_name` field to `struct promisor_info` to distinguish between server-advertised remote names and the names used for local configuration.

The change prepares for upcoming functionality where auto-configured promisor remotes will use generated names (like "promisor-auto-<sanitized-url>") while preserving the original server-advertised names. The patch adds helper functions to cleanly handle both names, with `promisor_info_internal_name()` returning the appropriate name for local operations. The modifications touch key promisor-remote handling functions like `promisor_store_advertised_fields()` and `filter_promisor_remote()` to use the new field.

This is a mechanical change that maintains existing behavior while setting up infrastructure for the auto-configuration feature coming in later patches. The implementation looks clean, with proper memory management for the new field and clear documentation updates explaining the name distinction. The patch fits well into the series' progression from refactoring to feature implementation.
