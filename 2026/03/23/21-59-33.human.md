This is the first patch in a feature series introducing a `--graph-lane-limit` option for `git log --graph`. The patch adds core infrastructure to limit the number of displayed graph lanes (columns) in wide commit histories, addressing a long-standing TODO from 2008.

The implementation introduces a `graph_max_lanes` field in `struct rev_info` and handles option parsing with `--graph-lane-limit=<n>`. The design follows existing conventions - negative/zero values mean "no limit" (matching `--max-parents` behavior) and the option requires `--graph` to be meaningful. The patch includes basic validation to prevent invalid combinations.

This is the fourth iteration of the series, with all prior feedback addressed. The author has standardized on `int` type for the limit (was previously `unsigned int`) and improved commit message clarity. The change is focused on the plumbing layer, with the actual graph truncation logic coming in patch 2/3.

The patch touches core graph and revision handling code (graph.c, revision.c) but maintains backward compatibility. It's part of a Google Summer of Code project and shows careful attention to review feedback while solving a real usability pain point for repositories with many active branches.
