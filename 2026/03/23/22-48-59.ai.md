Bugfix for bisect's custom term handling, addressing output inconsistencies when alternate terms (like "old"/"new") are used instead of default "good"/"bad". This is the first patch in a 2-part series that follows up on v1 by expanding coverage to more commands.

The patch focuses on `git bisect status` output messages, ensuring they consistently use the configured terms rather than hardcoded "good"/"bad". Changes touch the status reporting in builtin/bisect.c, updating several message formats to use the terms from the bisect_terms struct. Test coverage in t6030 is expanded to verify the new behavior, including checks for the status output and bisect run messages.

Key technical changes:
- Updates status messages in bisect_print_status() to use terms->term_good/bad
- Modifies error messages in bisect_run() to use configured terms
- Adds test cases in t6030-bisect-porcelain.sh for term-aware output
- Verifies behavior with custom terms like "term1"/"term2"

This is a straightforward improvement that makes bisect's output more consistent when using custom terminology. The changes are well-contained to the status reporting paths and come with thorough test coverage. The patch appears ready for review, building on the v1 feedback by being more comprehensive in its handling of custom terms.
