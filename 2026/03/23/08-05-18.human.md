This is the 15th patch in Christian Couder's 16-part series introducing URL-based whitelisting for auto-configuring promisor remotes. The series builds on previous work to allow automatic creation of promisor remotes when their URLs match configured patterns.

The key addition in this patch is automatic remote configuration when a server advertises a promisor remote that matches `promisor.acceptFromServerUrl` patterns but isn't already configured locally. It introduces several new helpers:

- `sanitize_remote_name()` converts URLs into valid remote names by replacing special characters with dashes and prepending "promisor-auto-"
- `promisor_remote_name_from_url()` extracts host/port/path from URLs to generate human-readable base names
- `configure_auto_promisor_remote()` writes the new remote configuration
- `handle_matching_allowed_url()` handles name collisions by appending numeric suffixes

The patch also updates documentation to explain the auto-creation behavior, name generation rules, and new `remote.<name>.advertisedAs` config option that preserves the server's original remote name for debugging. Extensive test coverage verifies the behavior with various URL patterns, name collisions, and edge cases.

This appears to be a well-constructed implementation that completes the series' goal of reducing manual configuration burden while maintaining security. The careful handling of name collisions and URL sanitization shows thoughtful attention to edge cases. With this patch, administrators can now define URL patterns that automatically provision promisor remotes without requiring per-client configuration.
