This is part 6 of Mirko Faina's 8-patch series improving `git format-patch --commit-list-format`. The series is now in its third iteration and appears merge-ready after addressing all feedback.

The current patch adds line wrapping to commit messages in the cover letter/commit list output. While Git commit messages typically follow line length conventions, this change ensures that any unusually long lines will be properly wrapped at the standard 72-column width (MAIL_DEFAULT_WRAP) when included in the formatted output. The implementation uses Git's existing `strbuf_add_wrapped_text()` utility function and maintains the existing output structure while adding the wrapping capability.

The change is straightforward and well-contained, touching only the `generate_commit_list_cover()` function in builtin/log.c. It introduces a second strbuf for the wrapped output while preserving the existing commit_line buffer for the raw formatting. The patch follows Git's established patterns for text wrapping and maintains the series' focus on improving the usability and robustness of patch email generation.
