This thread introduces Christian Couder's 16-patch series that adds URL-based whitelisting for automatically configuring promisor remotes. The key feature is a new `promisor.acceptFromServerUrl` config option that lets users specify URL patterns to safely auto-configure promisor remotes from trusted sources.

The first patch, which just arrived, refactors the promisor remote fetching logic to prioritize "accepted" remotes (those explicitly approved by the client) over other configured remotes. It modifies `promisor_remote_get_direct()` to first try fetching from accepted remotes before falling back to others, extracting this logic into a new `try_promisor_remotes()` helper function. This change lays groundwork for the series' main feature while maintaining backward compatibility.

The full series will include URL normalization, auto-generated remote names, security measures to prevent conflicts, and documentation updates. The initial patch shows careful attention to maintaining existing behavior while preparing for the new functionality.
