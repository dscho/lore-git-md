Christian Couder's series introduces URL-based whitelisting for promisor remotes, reducing manual configuration while maintaining security. The core feature allows auto-configuring remotes through `promisor.acceptFromServerUrl` with strict URL pattern matching. Junio Hamano has been closely reviewing the security implications, initially raising concerns about trust models and documentation.

In the latest exchange, Junio focuses on tightening the glob pattern matching rules to prevent potential security bypasses. While maintaining backward compatibility with Git's existing `urlmatch` behavior, he proposes restricting how `*` wildcards can match across `/` boundaries in domain portions of URLs. This would prevent dangerous cases where patterns like `https://*.example.com` could match malicious domains containing the substring, while still allowing legitimate uses like `https://example.com/*` for path matching.

The series is otherwise ready, with comprehensive test coverage and security measures including default-deny policies, configurable name prefixes, and strict URL normalization. Christian will likely address Junio's latest feedback with follow-up patches adjusting the URL matching implementation before the feature graduates to `next`. The discussion exemplifies Git's careful balance between usability improvements and security hardening.
