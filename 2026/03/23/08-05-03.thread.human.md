Christian Couder's 16-patch series introduces URL-based whitelisting for auto-configuring promisor remotes through a new `promisor.acceptFromServerUrl` config option. The series systematically refactors promisor-remote handling, implements the new feature with security measures like strict URL normalization, and updates documentation. All patches have been reviewed and appear ready for integration.

Junio Hamano has now raised important security and documentation concerns in review. He suggests tightening the implementation by restricting protocol schemes to just `https://` and `ssh://` in code rather than documentation advice, preventing `*` from crossing `/` boundaries in URL patterns, and explicitly defining what "trusted" means for these remotes (likely equivalent to `promisor.acceptFromServer=all`). While not challenging the core functionality, these recommendations would make the feature safer by default. The series will likely see follow-up version addressing these points with stricter URL matching rules and expanded security documentation before final approval.
