Feature patch adding line wrapping to `git format-patch` commit lists, part of Mirko Faina's series improving commit list formatting. This specific patch teaches `generate_commit_list_cover()` to wrap long commit message lines using Git's existing `strbuf_add_wrapped_text()` function with `MAIL_DEFAULT_WRAP` settings.

The change adds a second strbuf to handle the wrapped output and modifies the output loop to wrap each commit line before writing. The implementation follows Git's standard text-wrapping conventions, using the same width and indentation settings as other mail-formatted output. This maintains consistency with Git's email formatting while preventing overly long lines from making patch emails harder to read.

This is the sixth patch in an 8-part series that has already addressed all review feedback in previous iterations. The change is straightforward and unlikely to be controversial, building on established mail formatting infrastructure. The series as a whole improves `format-patch` usability by standardizing and enhancing commit list presentation.
