This is a preparatory patch in Christian Couder's series adding URL-based whitelisting for promisor remotes. It introduces a new helper function `url_is_valid_pattern()` to the urlmatch subsystem, which will be used later in the series to validate URL patterns for promisor remote configuration.

The function checks if a string looks like a valid URL or URL pattern (allowing '*' globs) by attempting to normalize it with globbing enabled. The commit message notes this is not a full validation - some invalid hostnames may pass - but it will catch most malformed URLs. The implementation is straightforward, building on the existing `url_normalize_1()` function with a new public wrapper.

This change is part of the infrastructure needed for the series' main feature of auto-configuring promisor remotes based on URL patterns. The patch appears clean and focused, with clear documentation of the function's purpose and limitations in the header. As an early patch in the series, it follows the common pattern of introducing needed helpers before the features that will use them.
