Feature enhancement for `git backfill` (partial clone functionality), part 3/6 in Derrick Stolee's v2 series. This patch adds revision argument support to `git backfill`, allowing users to specify commit ranges, pathspecs, and other rev-list options when downloading missing blobs in partial clones.

The key change is switching from hardcoded HEAD traversal to using `setup_revisions()`, which unlocks all the standard Git revision selection capabilities. The implementation includes tests for various scenarios: revision ranges, stdin input, pathspec filtering (though pathspec limiting isn't fully functional yet), `--all`, `--first-parent`, and `--since` date-based filtering.

The patch builds on earlier feedback by using `add_head_to_pending()` instead of direct `handle_revision_arg()` calls, and properly handles cleanup with `release_revisions()`. Test coverage is extensive, verifying blob download counts match expectations for each filtering mode. While pathspec support is noted as incomplete (currently downloads all blobs regardless of pathspec), this will be addressed in a follow-up patch.

This is a well-tested, incremental step in the series that cleanly integrates with Git's existing machinery while maintaining the partial clone performance characteristics. The v2 iteration has addressed all prior review feedback and received Junio's ack.
