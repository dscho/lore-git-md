This thread continues the discussion about making Git's bisect functionality properly respect custom terminology (like "old"/"new" instead of "good"/"bad"). The core approach is settled, and the conversation has moved to implementation details.

Jonas Rebmann's v2 patch series addresses two remaining gaps: making `git bisect status` show the custom terms and ensuring `git rev-parse --bisect` uses them too. Phillip Wood, reviewing the patches, initially suggested adding a NULL check that Jonas correctly pointed out is unnecessary - the `read_bisect_terms()` function always returns valid strings, defaulting to "good"/"bad" if no custom terms are set.

Phillip now suggests a more significant improvement: having `rev-parse` reuse the existing `for_each_bisect_ref()` function rather than constructing refnames manually. This would both centralize the bisect ref-handling logic and likely avoid the memory leak Junio spotted in the current implementation. The discussion shows the review process working well - the author and reviewer are catching each other's technical points and refining the solution.

The remaining work appears to be: (1) adopting Phillip's architectural suggestion to use `for_each_bisect_ref()`, (2) fixing the memory leak either way, and (3) incorporating Phillip's earlier suggestion to wrap terms in quotes in the status output for clarity.
