This is a feature patch series for `git-replay`, adding a new `--ref` option to give users more control over which ref gets updated. The series comes from Toon Claes and builds on Siddharth Asthana's recent work adding `--revert` to `git-replay`.

The main addition is a new `--ref` flag that lets users specify exactly which reference should be updated, rather than relying on the refs mentioned in the revision range or `--advance`/`--revert` arguments. This addresses a use case where more precise control over ref updates is needed. The first two patches clean up documentation and test consistency as groundwork for the new feature.

The changes look well-motivated and build logically on existing functionality. The commit messages clearly explain the rationale, and the implementation appears straightforward. This seems like a useful addition to the plumbing command's capabilities, particularly for scripted use cases where explicit ref specification is valuable than implicit behavior.

The series is based on current `master` (specifically commit ba5c0d03d3 from Siddharth's `--revert` series) and includes thorough test updates to verify the new behavior. Given that `git-replay` is still relatively new plumbing, this seems like a good time to expand its capabilities in this direction.
