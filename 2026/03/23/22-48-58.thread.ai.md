Thread identity: 2-patch series on improving custom bisect term handling in Git, addressing inconsistencies when alternate terms (e.g. "old"/"new") are used instead of default "good"/"bad". Follow-up to v1 which only partially addressed the issue.

Core problem: When users configure custom bisect terms via `git bisect start --term-(good|bad)`, some commands (`bisect status`, `rev-parse --bisect`) were hardcoding "good"/"bad" in their output/behavior rather than respecting the configured terms. The series makes all bisect-related commands consistently use the configured terminology.
