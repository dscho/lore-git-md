This is part 14 of Christian Couder's 16-patch series introducing URL-based whitelisting for promisor remotes. The series aims to reduce manual configuration while maintaining security by allowing automatic acceptance of promisor remotes from trusted URLs.

This patch implements the core URL matching logic for the new `promisor.acceptFromServerUrl` config option. When a promisor remote is already configured locally but needs field updates (like authentication tokens), this change allows those updates to proceed if the remote's URL matches a whitelist pattern, even when the stricter `promisor.acceptFromServer=None` setting is in effect.

Key technical changes:
- Adds `url_matches_accept_list()` helper to check URLs against whitelist patterns
- Modifies `should_accept_remote()` to consider URL matches as an override for `ACCEPT_NONE`
- Updates documentation with security guidelines for URL patterns
- Adds tests verifying the whitelist behavior

The implementation appears careful about security, normalizing URLs before matching to prevent bypass attempts. The documentation provides clear warnings about the risks of overly broad patterns. This looks like a well-considered addition to the series, maintaining the security model while adding useful flexibility for trusted remotes.
