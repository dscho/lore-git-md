This is a refactoring patch in Christian Couder's series on URL-based whitelisting for promisor remotes. It's the second of 16 patches, focusing on a preparatory cleanup of the urlmatch API.

The patch changes the `allow_globs` parameter of `url_normalize_1()` from `char` to `bool` to better reflect its actual usage as a boolean flag. It also updates the two call sites to pass `true`/`false` instead of `1`/`0` for clarity. This is a straightforward type cleanup that doesn't change behavior but improves code correctness and readability.

The change is minimal (3 lines modified) and mechanical, with no impact on functionality. It's part of the foundational work needed for later patches in the series that will use this API for URL pattern matching in promisor remote configuration. The patch follows Git's coding conventions by using the `bool` type consistently for boolean parameters.
