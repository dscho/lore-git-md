Junio Hamano is responding to security concerns about URL pattern matching in Christian Couder's promisor remote whitelisting feature. This is part of the ongoing discussion about tightening the `promisor.acceptFromServerUrl` configuration option's security defaults.

Junio questions whether allowing glob patterns (`*`) to match across path segments (slashes) in URLs is ever actually useful in practice, despite the documentation warning against it. He acknowledges that completely forbidding this would break some existing configurations, but suggests a middle ground: only allowing `*` to match across slashes when it appears in the path portion of the URL (after the domain), not in the domain portion itself. This would prevent dangerous patterns like `https://*.example.com` matching malicious domains while still supporting legitimate use cases.

The tone is thoughtful rather than dismissive - Junio is looking for a way to make the matching rules secure by default without breaking real-world configurations. This suggests the feature is nearing readiness but needs these security refinements before integration. The discussion is focused specifically on the URL pattern matching behavior, separate from the earlier questions about documenting the trust model.
