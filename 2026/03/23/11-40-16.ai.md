This is the third patch in a 6-part series enhancing `git backfill` for partial clone functionality. The series is now at v2 with all patches reviewed and acked by Junio C Hamano.

The patch extends `git backfill` to accept revision arguments like `--all`, commit ranges, and time-based filters (`--since`), using Git's standard revision parsing machinery. This allows more targeted blob fetching in blobless partial clones - for example, downloading only blobs from recent commits or specific branches. The implementation:

1. Integrates `setup_revisions()` to handle arbitrary revision specs
2. Adds comprehensive tests covering:
   - Basic range specifications (`HEAD~2..HEAD`)
   - Stdin input for revision lists
   - Various pathspec cases (though pathspec filtering isn't fully functional yet)
   - Special revision flags like `--first-parent` and `--since`

Notable technical details:
- Uses `add_head_to_pending()` instead of direct `handle_revision_arg()` for better code quality
- Maintains the existing batch download behavior but now scoped to the specified revisions
- Includes a test repository with 54 blobs across multiple branches to properly exercise the features

The patch builds cleanly on the previous work while addressing all feedback from v1. It represents a significant step toward making partial clone workflows more flexible, particularly for operations like `git blame` that benefit from targeted history access. The pathspec limitations noted in the tests will be addressed in subsequent patches.
