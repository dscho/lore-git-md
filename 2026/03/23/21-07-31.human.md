This is a documentation patch in Lorenzo Pegorari's GSoC series on promisor file handling during repacks. The patch adds comments explaining the purpose of ref names and hashes stored in `.promisor` files, which are used for debugging partial clone issues.

Junio Hamano provides review feedback suggesting two improvements: first, to reference commit 5374a290 which originally introduced this behavior, making the explanation more authoritative; and second, to fix the comment formatting to match Git's style (proper asterisk alignment with tab indentation). The patch itself is straightforward and uncontroversial - it just needs these minor adjustments before being ready for inclusion.

This is part of a larger effort to properly handle promisor packfiles during repacks, where the debug information in `.promisor` files needs to be preserved. The series has already gone through one round of review from Eric Sunshine, with this being the documentation foundation for the subsequent technical changes.
