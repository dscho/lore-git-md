This is patch 6/12 in Patrick Steinhardt's v2 series refactoring Git's fsck subsystem to remove dependence on the global `the_repository` variable. The patch focuses on converting the ref snapshotting functionality in `builtin/fsck.c` to use explicit repository pointers.

The changes introduce a new `snapshot_ref_data` struct to carry both the repository pointer and snapshot state, then update all ref-related functions to use this context rather than `the_repository`. Key conversions include:
- Replacing direct `the_repository` calls with repository pointers from the context struct
- Updating `parse_object()` and `is_promisor_object()` calls to use the passed repository
- Modifying `snapshot_refs()` to take a repository parameter and pass it through
- Converting worktree-related ref lookups to use the repository parameter

The patch follows the series' consistent approach of mechanical conversions that maintain identical behavior while eliminating global state. It builds on the structural changes from earlier patches (particularly the repository pointer storage in `fsck_options`) and demonstrates careful attention to edge cases like worktree handling. The changes are well-contained to the fsck command's ref snapshotting logic, keeping the scope focused.
