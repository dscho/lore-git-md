This is the documentation patch (16/16) in Christian Couder's series introducing URL-based whitelisting for auto-configuring promisor remotes. It significantly improves the documentation for the `promisor.acceptFromServer` config option to better explain its behavior and relationship with the new `promisor.acceptFromServerUrl` feature introduced earlier in the series.

The patch clarifies several points that were unclear in the original documentation: whether new remotes can be created (they can't with this option alone), the default value ("none"), and corrects a mistake about whether names are advertised by client or server. The rewrite organizes the information into clear bullet points for each option and explicitly connects this feature to the new URL-based whitelisting capability.

The changes make the documentation more scannable and precise while maintaining all the important technical details about security implications and case sensitivity. This is a straightforward but valuable improvement to the series' documentation that will help users understand how to properly configure promisor remote acceptance.
