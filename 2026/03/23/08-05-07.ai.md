This is a documentation/UX improvement patch in Christian Couder's series on URL-based whitelisting for promisor remotes. The patch clarifies warning messages in `should_accept_remote()` to explicitly state when a promisor remote is being ignored, rather than just explaining why.

The changes make two warning messages more explicit by adding ", ignoring this remote" to clarify the consequence of the described situation. The first case handles empty or missing URLs, while the second addresses URL mismatches between advertised and configured remotes. This improves user feedback without changing any functionality.

As part of the larger series (04/16), this patch follows preparatory refactors and precedes the core URL pattern matching implementation. It's a small but thoughtful improvement to error messaging that will help users better understand promisor remote rejection behavior. The change is straightforward and uncontroversial, with no apparent technical concerns.
