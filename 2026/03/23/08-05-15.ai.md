This is a test cleanup patch in Christian Couder's series introducing URL-based whitelisting for promisor remotes. The patch fixes cross-platform issues with file:// URIs in the test suite.

The change addresses a subtle Windows-specific problem where `file://` URIs constructed with absolute paths behave differently than on Unix. On Windows, paths starting with drive letters (like `D:/repo`) were being incorrectly interpreted as hostnames rather than path components when passed through URL normalization. The patch introduces new `$PWD_URL` and `$ENCODED_PWD_URL` test helpers to ensure consistent 3-slash `file:///` URI format across platforms.

The changes are mechanical - replacing all `file://$(pwd)` instances with the new helpers and simplifying some test logic that previously handled URL encoding manually. This prepares the test suite for upcoming patches that will use URL normalization for promisor remote matching. The patch maintains all existing test behavior while making it more robust for future changes.

This is a necessary prerequisite for the URL-based matching functionality coming later in the series, ensuring the tests will pass consistently across platforms once URL normalization is introduced. The changes are straightforward and well-contained to test infrastructure.
