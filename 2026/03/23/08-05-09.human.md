This is a refactoring patch in Christian Couder's series on URL-based whitelisting for promisor remotes. It's patch 6/16 in the sequence.

The patch extracts the logic for checking the `promisor.acceptfromserver` config value into a new `accept_from_server()` helper function, cleaning up the larger `filter_promisor_remote()` function. The change is purely structural - no behavior is modified, just code organization. The new helper handles parsing the config value and returns an enum indicating what level of promisor remotes should be accepted (NONE, KnownUrl, or All).

This is part of the preparatory refactoring mentioned in the thread summary, making the codebase more maintainable before introducing the new URL-based whitelisting functionality in later patches. The change follows good practice by keeping the diff focused and clearly separating concerns.
