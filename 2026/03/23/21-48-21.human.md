This is a technical follow-up in Lorenzo Pegorari's GSoC series about preserving promisor file contents during repacks. Junio Hamano raises an important design question about the patch's assumption that all promisor files will be processed in a single repack operation.

The patch in question (v2 3/4) introduces logic to copy debug information from all existing promisor files into the first new one created during repack. Junio points out this may not hold true for geometric repacking, where only some packs (the "smallish ones") get repacked while others remain untouched. This could lead to debug information being lost from the unrepacked promisor files.

The concern suggests the current approach might need rethinking - either by finding a way to preserve information across partial repacks, or by documenting the limitation. This is a significant architectural consideration that could affect how the debugging information behaves in real-world partial clone scenarios. The thread shows the maintainer engaging deeply with the technical implications of what initially appeared to be a straightforward improvement.
