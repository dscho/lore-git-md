This is a documentation and error handling improvement patch from Mirko Faina, part of a larger series enhancing `git format-patch --commit-list-format`. The patch focuses specifically on making error messages more user-friendly when unsupported format placeholders are used.

The change modifies the error messages for `%(count)` and `%(total)` placeholders to explicitly name the problematic format specifier rather than using a generic "this format specifier" message. This makes it clearer to users which part of their format string caused the error. The new messages follow Git's typical error message style by including the exact problematic syntax.

This patch is the first in an 8-part series that has already gone through multiple iterations (now at v3) with comprehensive review feedback incorporated. The series as a whole improves commit list formatting in patch emails, with this particular change being a small but meaningful usability improvement for error cases. The implementation is straightforward - just two line changes in pretty.c to update the die() messages.

The patch maintains the existing behavior while making error cases more informative. It's a clear improvement with no apparent downsides, and fits well with Git's emphasis on clear user feedback. Since this is part of a well-reviewed series that appears ready for merging, this particular change can be considered non-controversial and low-risk.
