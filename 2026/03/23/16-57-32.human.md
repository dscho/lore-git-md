This is a refactoring patch in Mirko Faina's series improving `git format-patch --commit-list-format`. The patch simplifies how empty values are handled for the `format.commitListFormat` configuration.

The change removes special handling of empty values, treating them the same way as other Git config variables - an empty value now means "unset" rather than falling back to a default format. This makes the behavior more consistent with Git's configuration conventions. The patch removes the temporary strbuf that was previously constructing a default format when the value was empty, and drops a now-redundant test case that verified the old fallback behavior.

This is a straightforward cleanup that aligns with the series' goal of standardizing and simplifying the commit list formatting code. The change is mechanical and low-risk, removing complexity without affecting the user-visible behavior when the config is properly set. As with the rest of the series, this appears ready for merging.
