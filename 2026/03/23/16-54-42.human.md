This is a platform compatibility discussion about a macOS build issue that may resurface in the future. Junio C Hamano proposes a middle-ground solution for Johannes Schindelin's earlier workaround patch for Homebrew clang's missing REG_ENHANCED support. While the immediate CI breakage was fixed by GitHub rolling back their runner images, the underlying Homebrew behavior that caused the issue remains.

Junio suggests adding a comment in `compat/regcomp_enhanced.c` pointing to the original workaround discussion, rather than keeping the actual code change in the tree. This serves as documentation for future maintainers who might encounter the same issue, without forcing all macOS users to use the workaround unnecessarily. The comment specifically references Schindelin's original email with the fix, making it easy to find if the problem reappears.

The approach shows Git's typical conservative stance on platform-specific workarounds - keeping the solution lightweight and only applying it when absolutely needed, while still ensuring the knowledge isn't lost. This is particularly relevant given that GitHub's CI could reintroduce the problematic image update at any time. The patch is minimal and non-intrusive, just adding a documentation pointer without changing any actual behavior.
