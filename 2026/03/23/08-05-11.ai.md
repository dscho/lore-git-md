This is a refactoring patch in Christian Couder's series on URL-based whitelisting for promisor remotes. It continues the cleanup work from earlier patches by simplifying how accepted promisor remotes are tracked.

The patch removes the `accepted` strvec parameter from `filter_promisor_remote()` and replaces it with direct use of the `accepted_remotes` string_list that was introduced in patch 7. This eliminates redundant storage of the same information in parallel data structures. The change affects both the internal filtering logic and the public `promisor_remote_reply()` function, which now builds its output string directly from the string_list rather than an intermediate strvec.

The refactoring makes the code more straightforward by having a single canonical representation of accepted remotes throughout the filtering process. This is part of the broader effort to improve the promisor remote configuration system's maintainability while preparing for the URL-based whitelisting feature that will be introduced in later patches. The changes are purely internal - no user-visible behavior is modified.
