This is part 11 of Patrick Steinhardt's v2 series refactoring the fsck subsystem to remove `the_repository` dependence, continuing the broader `the_repository` removal effort. The patch focuses on converting object marking functionality in `builtin/fsck.c` to use explicit repository pointers rather than relying on the global variable.

The changes systematically replace `the_repository` usage in several key functions related to object marking and connectivity checking:
- `mark_object()` now uses the repository from `fsck_options->repo` for promisor object checks and ODB lookups
- `mark_unreachable_referents()` and `mark_object_for_connectivity()` now take the repository as callback data
- All callers are updated to pass the repository pointer through the callback chains
- The changes maintain identical behavior while removing implicit state

The patch follows the established pattern of the series - mechanical conversions that preserve functionality while eliminating global state. It touches core object marking paths that are critical for fsck's connectivity verification, including promisor object handling and alternate ODB traversal. The changes are focused and well-contained within `builtin/fsck.c`, with no ripple effects to other subsystems.

This continues the series' thorough approach - after converting ref checking, reflog verification, and object checking in previous patches, this addresses one of the last remaining areas where fsck relied on `the_repository`. The changes are straightforward and appear to maintain all existing behavior while properly propagating repository context through the object marking callbacks. Given the careful progression of the series and Patrick's track record with similar refactorings, this looks like a solid step toward making fsck fully repository-agnostic.
