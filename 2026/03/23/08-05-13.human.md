This is a refactoring patch in Christian Couder's series on URL-based whitelisting for promisor remotes. It's the 10th of 16 patches in the series.

The patch eliminates redundant config lookups in the promisor remote acceptance logic. Previously, `all_fields_match()` would re-lookup the remote configuration even though the caller had already done this work. The change replaces a boolean `in_list` parameter with a direct `config_entry` pointer, which either:
- To NULL in ACCEPT_ALL mode (scan all config entries)
- To the already-looked-up config entry in other modes

This prepares for upcoming changes where auto-configured remotes will have different local names than their server-advertised names, making the current name-based lookup approach problematic. The change is cleanly implemented with updated function documentation and maintains the same behavior while being more efficient.

The patch fits well into the series' broader goal of improving promisor remote configuration, showing careful attention to both current needs and future requirements. The implementation looks straightforward and maintains the existing functionality while removing an inefficiency.
