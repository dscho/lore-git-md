This is the final patch in Pablo Sabater's v4 series adding a `--graph-lane-limit` option to `git log --graph`. The patch adds documentation and test coverage for the new feature, which truncates wide commit graphs to improve terminal display.

The documentation explains that the option limits the number of graph lanes shown, replacing excess lanes with dots while preserving the '*' commit marker on the first hidden lane. Two tests verify the behavior: one limiting to 2 lanes on a single tip, and another limiting to 3 lanes across multiple tips. The test cases reuse existing graph structures from the test file.

This completes the series that addresses a 2008 TODO in graph.c about column limiting. The implementation has evolved through four versions with feedback from Junio Hamano and other reviewers, now using consistent `int` type for the limit parameter and matching Git's conventions for "no limit" (zero/negative values). The patch appears well-polished with clear documentation and thorough test coverage.
