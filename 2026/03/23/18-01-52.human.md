This is a review comment on the final patch in a series adding a `--ref` option to `git replay`. Tian Yuchen points out two potential issues with the implementation:

1. **Comment-code mismatch**: The comment suggests `--ref` ignores `--contained`, but the code shows a `die_for_incompatible_opt2()` check that would prevent using them together. The comment needs updating to match the actual behavior.

2. **Multiple branch handling**: When replaying multiple branches (like `topic1` and `topic2`) with `--ref`, only the specified target ref gets updated, potentially orphaning the other branches. The current implementation doesn't warn about this or handle it gracefully.

The review is technically focused, identifying specific edge cases the patch doesn't yet handle correctly. The concerns appear valid - the interaction between `--ref` and multiple input branches needs clarification in both code and documentation. This is the first substantive review feedback on the series, which until now had appeared well-structured and complete. The author (Toon Claes) will need to address these points in a v2.
