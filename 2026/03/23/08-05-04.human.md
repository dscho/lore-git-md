This is the first patch in Christian Couder's 16-part series introducing URL-based whitelisting for auto-configuring promisor remotes. It's a refactoring that prepares for the main feature by changing how promisor remotes are prioritized during object fetching.

The patch modifies `promisor_remote_get_direct()` to try accepted promisor remotes (those explicitly configured by the user) before falling back to non-accepted ones. This better reflects the intended behavior where server-advertised promisor remotes should be preferred over other configured remotes. The change is implemented by extracting a new `try_promisor_remotes()` helper function that can be called with different filtering conditions.

The commit message clearly explains the motivation: currently the order depends on config file ordering, which doesn't properly respect the server's intent about preferred remotes. The change is well-contained and includes a clean refactoring that will be useful for the auto-configuration feature coming later in the series. The diff shows careful handling of memory management and error cases.

This is a solid foundational change that doesn't introduce new user-facing behavior yet, but sets up the plumbing needed for the more visible features in subsequent patches. The implementation looks correct and the commit message provides good context about how this fits into the larger series.
