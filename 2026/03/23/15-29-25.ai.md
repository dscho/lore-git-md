This is a test patch completing the `git backfill` feature series, now with Junio C Hamano providing final review comments on argument parsing behavior.

Junio notes that while the test verifies basic unknown argument handling, the deeper revision/pathspec parsing behavior should follow Git's standard conventions - specifically the disambiguation rules around `--` that govern when arguments are treated as revisions versus pathspecs. He outlines the expected behavior for commands that accept both revisions and pathspecs (like `git log`), where:
- Without `--`, parsing stops at the first non-revision argument and treats remaining arguments as pathspecs (requiring them to exist in the working tree)
- With `--`, arguments before are strictly revisions and after are strictly pathspecs

While not objecting to the current test, Junio suggests this behavior is better tested centrally for all revision-taking commands rather than per-command. His comment implies the `backfill` implementation should inherit these standard parsing rules from `setup_revisions()`, which it already using. This matches the series' goal of making `backfill` behave consistently with other Git commands.

The exchange confirms the technical approach while identifying an area where the test coverage could be more comprehensive by including `--` disambiguation cases. However, since the series has already been acked and this is more of a general observation about Git's parsing conventions, it's unlikely to block integration.
