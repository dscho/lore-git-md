This is a technical clarification from Junio Hamano on patch 3 of Lorenzo Pegorari's series about promisor file handling during repacks. The patch aims to preserve debug information from `.promisor` files when repacking, but Junio questions whether the current approach properly accounts for all cases where promisor packs might be repacked.

Junio notes that the patch assumes all existing promisor packs will be handled in a single repack operation, allowing their `.promisor` file contents to be safely consolidated into one new file. However, he points out that with geometric repacking enabled, Git's repack strategy might only coalesce smaller packs while leaving larger ones intact. This could lead to debug information preservation if some promisor packs (and their associated `.promisor` files) remain untouched during the repack.

The question suggests the current implementation may need to either:
1. Handle cases where only a subset of promisor packs are repacked
2. More carefully document the limitations of the debug information preservation
3. Reconsider the consolidation approach entirely

This feedback indicates the patch may need revision to properly account for geometric repacking behavior before proceeding. The author will need to either adjust the implementation or provide reasoning why the current approach is sufficient despite this edge case.
