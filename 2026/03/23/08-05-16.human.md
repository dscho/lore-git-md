This is the core feature patch in Christian Couder's series introducing URL-based whitelisting for promisor remotes. It adds the new `promisor.acceptFromServerUrl` config option that lets clients automatically configure promisor remotes when their URLs match specified patterns.

The patch introduces key infrastructure for handling the new config:
- A `struct allowed_url` to store parsed remote name prefixes and URL patterns
- A `valid_accept_url()` helper that validates the config syntax (optional remote name prefix and URL pattern)
- The main `accept_from_server_url()` function that loads and validates all configured patterns

The implementation is careful about validation - it checks for control characters, invalid remote names, and malformed URL patterns, issuing warnings for any issues. The patterns will be matched against advertised remote URLs in a follow-up patch (this one just sets up the parsing infrastructure).

This is a significant step in the series' goal to reduce manual promisor remote configuration while maintaining security. The code follows the project's style and builds on previous preparatory refactors in the series. The patch appears well-structured with clear helper functions and thorough input validation.
