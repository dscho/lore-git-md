This is a style discussion about test formatting in the context of Toon Claes' `git replay --ref` series. Junio Hamano weighs in on Kristoffer Haugsbakk's suggestion to standardize test option syntax.

Junio expresses skepticism about enforcing a single style for CLI invocations in tests, suggesting that a mix of forms might better reflect real-world usage. He notes that since Git supports both `--option=value` and `--option value` forms, having tests use both could help verify they work equivalently. His position contrasts with Kristoffer's earlier argument that tests should follow `gitcli(7)`'s preference for the "stuck form" (`--option value`) to prevent option/argument confusion.

The exchange highlights a tension between test consistency and testing realistic variation. Junio implies that mechanical style changes without functional impact may not be worth the churn, while Kristoffer had advocated for aligning with documented best practices. This discussion could influence how future test cleanups are evaluated, though Junio's maintainer perspective carries significant weight.
