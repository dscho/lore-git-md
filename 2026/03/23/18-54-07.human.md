This is a review comment from Junio Hamano on Christian Couder's promisor remote configuration series, specifically addressing the documentation for the new `promisor.acceptFromServerUrl` option in patch 14/16.

Junio raises several concerns about the security documentation for URL-based whitelisting. He questions whether the term "trusted" is sufficiently defined - what exactly does trusting a URL enable the remote to do? He suggests the behavior might be equivalent to setting `promisor.acceptFromServer` to "all" for matching URLs, but wants this made explicit.

The maintainer also scrutinizes the security advice about wildcard patterns, suggesting the documentation may be working around overly permissive matching behavior rather than fixing it. He questions whether allowing `*` to match across slashes is ever actually useful in practice, implying the matching rules should perhaps be tightened rather than documenting workarounds.

Junio proposes replacing "whitelist" with "allow list" (a more modern term) and suggests the code could enforce secure protocols like https/ssh rather than just recommending them. His comments focus on making the security implications clearer and the rules more strict by default.

This is typical of Junio's review style - probing the security model, questioning assumptions, and pushing for clearer documentation when behavior affects safety. The feedback will likely lead to revisions in both the docs and possibly the matching implementation before the series is merged.
