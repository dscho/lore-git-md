Git thread summary:

Junio C Hamano identified an inconsistency in `git show -U` argument handling where bare `-U` was accepted while malformed `-Unan` properly errored. The thread established that while the lenient `-U` parsing (defaulting to 3 lines like `-p`) must be preserved for backward compatibility (test 157 in t4013 depends on it), the documentation should frame this as legacy behavior rather than an intentional feature.

Tian Yuchen has now submitted a documentation patch updating `diff-context-options.adoc` and `diff-options.adoc` to explicitly document that `-U` without a number is accepted as legacy behavior, defaulting to 3 lines of context. The patch frames this as a "historical accident" while maintaining the existing behavior for test 157 and user scripts. The changes are documentation-only with no behavioral modifications.

Key technical details:
- Default 3-line context matches `-p` behavior
- `--unified=<n>` remains the canonical long form
- Documentation now explicitly marks bare `-U` as legacy
- Default applies both when `<n>` is omitted and when config is unset
