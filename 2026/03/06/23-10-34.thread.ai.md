Git thread summary:

Junio C Hamano identified an inconsistency in `git show -U` argument handling where bare `-U` was accepted while malformed `-Unan` properly errored. The thread established that while the lenient `-U` parsing (defaulting to 3 lines like `-p`) must be preserved for backward compatibility (test 157 in t4013 depends on it), the documentation should frame this as legacy behavior rather than an intentional feature.

Tian Yuchen initially proposed documenting `-U[<n>]` syntax, but consensus shifted toward Junio's position that bare `-U` should be explicitly noted as legacy while keeping primary documentation focused on proper `-U<n>` and `--unified=<n>` forms. The current patch updates `diff-options.adoc` and `diff-context-options.adoc` to reflect this, though D. Ben Knoble's earlier suggestions about:
1) Using `--unified[=<n>]` syntax to match Git doc conventions
2) Clarifying default value applies to both unset config and omitted `<n>`
remain unaddressed and may require follow-up.

Key technical details:
- Default 3-line context matches `-p` behavior
- Test 157 in t4013 depends on current lenient parsing
- `--unified=<n>` is canonical long form
- Documentation now explicitly marks bare `-U` as legacy

Open questions:
