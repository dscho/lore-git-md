Git thread summary:

Junio C Hamano identified and fixed an inconsistency in `git show -U` argument handling where `-U` without a number was incorrectly accepted while `-Unan` properly errored out. The patch modifies `diff_opt_unified()` to consistently validate the argument when present, moving error checking outside the conditional block. This affects the diff machinery's option parsing specifically for the `--unified` flag. 

Tian Yuchen investigated the implications and confirmed the patch would break test 157 in t4013, which expects `git diff -U` to default to 3 lines of context (matching `-u` behavior) rather than erroring out. The test suite's reliance on this lenient parsing presents a backward compatibility concern, as the current implementation treats the number as optional while the documentation in diff-context-options.adoc inaccurately suggests it is mandatory.

The discussion now centers on whether to:
1. Fix the technically incorrect behavior to match documentation (breaking existing tests/scripts)
2. Preserve backward compatibility by keeping the lenient parsing
3. Update both implementation and documentation to explicitly support the current behavior

Junio initially raised the compatibility concern, and Yuchen's analysis confirms the concrete impact on the test suite. The diff machinery's option parsing behavior for `-U` remains unresolved, with tradeoffs between correctness and backward compatibility still being weighed. The patch itself is small and focused, only touching unified diff option validation logic in `diff_opt_unified()`.
