Core problem/goal: Add mechanism to automatically abort Git clone operations when network throughput drops below 128 KiB/s, intended for automated scripts to detect and retry when connecting to unusually slow servers.

Implementation details:
- New `--no-turtle-speed` command-line option
- New `GIT_NO_TURTLE_SPEED` environment variable
- Speed check implemented in `progress.c` throughput calculation
- Triggers `die()` when receiving objects if rate < 128 KiB/s
- Affected files: builtin/clone.c, git.c, progress.c, environment.c

Open questions/considerations:
- Should the 128 KiB/s threshold be configurable rather than hardcoded?
- Should the check apply to all network operations or just object transfer?
- Is "turtle speed" terminology appropriate for error messages?
- Should this functionality be in core Git or handled by wrapper scripts?
