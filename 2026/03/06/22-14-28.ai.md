This is a feature patch proposing a new `--no-turtle-speed` option for `git clone` that would abort the operation if the download speed drops below 128 KiB/s. The motivation is to help automated scripts detect and retry when they've been directed to an unusually slow Git server during cloning.

The implementation adds a new environment variable `GIT_NO_TURTLE_SPEED` and hooks it into both the clone command and the general git command-line parser. The actual speed check happens in `progress.c`'s throughput calculation, where it will call `die()` if the rate falls below the threshold while receiving objects.

The patch appears to be a straightforward implementation of the proposed feature, though it raises some questions that may need discussion:
- The 128 KiB/s threshold is hardcoded rather than configurable
- The check only triggers during "Receiving objects" phase, not other network operations
- The error message uses informal "turtle speed" terminology rather than more formal wording

The changes touch several files but are narrowly focused on adding this one feature. The implementation looks technically sound, though reviewers may want to discuss whether this belongs in core Git or would be better handled by wrapper scripts.
