This thread started when Junio Hamano noticed that `git show -U` without a number was being accepted, contrary to what the documentation implied. The discussion considered three options: fixing the behavior to match docs (breaking tests), keeping the lenient behavior (inconsistent with docs), or updating the docs to match reality. The latest email brings a resolution - a documentation patch that updates the `-U` option syntax to show it accepts an optional number, making the docs accurately reflect the long-standing behavior. This avoids breaking existing usage while fixing the documentation.

The change is minimal (a one-line edit to diff-context-options.adoc) and uncontroversial, closing the discrepancy in the least disruptive way. The thread shows how even small inconsistencies between docs and implementation can surface interesting tradeoffs between correctness and backward compatibility.
