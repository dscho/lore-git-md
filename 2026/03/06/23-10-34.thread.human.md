This thread documents an inconsistency in Git's `-U` argument handling where `-U` without a number (defaulting to 3 lines of context) was accidentally accepted while `-Unan` properly errored out. After analysis, the group determined this behavior must be preserved for backward compatibility with existing test 157 in t4013, but shouldn't be encouraged as a feature.

The discussion has converged on documenting this as legacy behavior rather than an intentional feature. Tian Yuchen initially proposed showing `-U[<n>]` as optional syntax, but Junio Hamano pushed back, preferring to frame the bare `-U` case as a historical accident. The documentation will now explicitly note this while keeping the primary focus on proper `-U<n>` and `--unified=<n>` forms.

Ben Knoble contributed two refinements that remain to be addressed: aligning the documentation with Git's standard `--option[=<value>]` syntax pattern and clarifying when the default value applies. These may be handled in a follow-up, as the immediate priority is properly framing the legacy behavior without breaking existing tests that rely on it.

The solution preserves the current implementation where `-U` defaults to 3 lines (matching `-p` behavior) while making the documentation more accurate about what constitutes supported usage. The changes will appear in both `diff-options.adoc` and `diff-context-options.adoc`.
