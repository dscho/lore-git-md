The thread focuses on clarifying the documentation around Git's `-U` diff context option, which has historically accepted a bare `-U` (defaulting to 3 lines of context) despite the expected syntax being `-U<n>`. Junio Hamano established that this lenient parsing must be preserved for backward compatibility, as test 157 in t4013 and likely existing user scripts depend on it.

Tian Yuchen has submitted a documentation patch that updates two man pages to explicitly frame the bare `-U` behavior as a legacy quirk rather than an intentional feature. The patch clarifies that the default 3-line context applies both when `<n>` is omitted and when the config is unset, matching `-p`'s behavior. While this addresses the core issue, D. Ben Knoble's suggestions about aligning the documentation syntax (`--unified[=<n>]`) and more explicitly noting the default value's dual application remain open for potential follow-up. The changes are purely documentation-focused with no behavioral impact, preserving compatibility while making the historical behavior clearer to users.
