This is a feature proposal for automatic prefixing of new branch names, now in its third iteration. The series has evolved significantly from previous versions based on maintainer feedback, shifting from a boolean config option to a more flexible string-based approach.

The core idea remains: when creating a new branch, automatically prefix its name with either a static string or the current branch name (via `@{current}` token). The v3 series restructures the implementation into three logical steps:

1. First introduces a `--name-prefix` command-line option that accepts either literal strings or the `@{current}` token
2. Then adds a `branch.namePrefix` config parameter for persistent setting
3. Finally provides `--no-name-prefix` to override both CLI and config settings

The implementation now focuses solely on `git branch`, having dropped support for `git checkout`/`git switch` that was present in earlier versions. Test coverage in t3200-branch.sh verifies the behavior with various prefix combinations and the override mechanism.

Key technical details:
- New `add_branch_prefix()` helper in branch.c handles the prefix logic
- Supports recursive prefixing (creating "main-test-sub" when on "main-test")
- Maintains backward compatibility when no prefixing is configured
- Includes comprehensive tests for both CLI and config usage

The motivation remains simplifying workflows that involve hierarchical branch naming, particularly backports across multiple branches. However, the design now allows for more flexible naming schemes beyond just current-branch prefixing. The series appears well-structured with clean separation of concerns between the three patches.
