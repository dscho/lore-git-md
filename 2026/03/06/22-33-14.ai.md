Feature patch series for configurable `git format-patch` cover letters, now ready for merging. This is the final iteration of a series that introduces flexible formatting options for cover letters through both command-line (`--cover-letter-format`) and configuration (`format.commitListFormat`) interfaces.

The implementation provides comprehensive control over cover letter generation while maintaining backward compatibility with the existing shortlog-based output. Key technical components include new `%(count)` and `%(total)` placeholders for patch numbering, clean separation of shortlog generation into a dedicated function, and proper integration with Git's existing formatting infrastructure. The series has undergone five iterations with thorough review from Jeff King (Peff) and maintainer Junio C Hamano, who now considers it ready for inclusion.

Documentation is complete with clear examples of format strings and configuration options. The design enforces a "log:" prefix requirement for all non-shortlog formats to maintain consistency between CLI and config options. Test coverage in `t4014-format-patch.sh` verifies all behaviors including custom formats, shortlog fallback, and default output.

With all technical requirements met and maintainer approval confirmed, this series represents a production-ready enhancement to `git format-patch` that will allow users to customize cover letter output while preserving the familiar default behavior. The modular implementation and comprehensive documentation suggest this will be a maintainable addition to the project.
