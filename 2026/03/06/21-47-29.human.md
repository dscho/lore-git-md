Feature: URL-based default partial clone filters via `clone.<url>.defaultObjectFilter`

This patch implements configurable partial clone filters that automatically apply when cloning repositories matching specific URL patterns. The feature builds on Git's existing URL matching infrastructure (used for HTTP configuration) to let users specify different filters per repository location.

Key aspects:
- Filters are specified in config as `clone.<url>.defaultObjectFilter` (e.g. `blob:none`, `tree:0`)
- Most specific URL match wins (domain/namespace/full path)
- Command-line `--filter` overrides the config, while `--no-filter` forces a full clone
- The filter setting only affects the initial clone and is then recorded in the remote config
- Comprehensive test coverage verifies URL matching precedence, filter types, and edge cases

This is the final version of a well-discussed feature that went through multiple review iterations. The implementation addresses all feedback, including simplifying the internal struct handling and clarifying documentation. The thread concluded with consensus that this provides a useful quality-of-life improvement for partial clone users while maintaining clear boundaries (limited to clone operations only) and override mechanisms.
