This is a refactoring patch in the ongoing `git replay` revert capability series. Siddharth Asthana responds to Phillip Wood's review feedback by agreeing to consolidate all revert message formatting logic into a single helper function, `sequencer_format_revert_message()`. The new approach cleanly handles both regular reverts and revert-of-revert cases while eliminating the awkward NULL oid path that earlier reviewers noted.

The patch will be split into two commits: first updating `refer_to_commit()` to take a repository parameter, then introducing the consolidated message formatter. For `git replay`, the helper will be called with `use_commit_reference=false` to ensure full OID paths are shown. This addresses the technical concerns raised in previous rounds while maintaining clean separation between the sequencer and replay components.

The implementation looks solid and well-motivated, following established patterns from the sequencer while adapting them for the new use case. This is part of a larger effort to enable bare repository reverts for GitLab's Gitaly service, with the series now progressing to v4 based on thorough review feedback.
