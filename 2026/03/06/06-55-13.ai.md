This is the final version of Alan Braithwaite's feature to configure partial clone filters via URL patterns (`clone.<url>.defaultObjectFilter`), addressing all of Junio C Hamano's review feedback from the previous iteration. The patch implements URL-based configuration for partial clone filters while maintaining Git's boundaries by limiting the feature to clone operations only.

The implementation uses Git's existing urlmatch infrastructure for URL pattern matching, with three specificity levels (domain/namespace/full path) where the most specific match wins. Command-line `--filter` options override the config, and the filter setting persists in the remote configuration after clone. The patch includes comprehensive test coverage for filter application, command-line override behavior, different filter types, URL matching precedence, and edge cases.

Key changes from v2 include:
- Simplified the implementation by removing the single-member `clone_filter_data` struct in favor of a direct char** pointer
- Set `cascade_fn` to NULL to avoid unnecessary config re-processing
- Added NULL check for filter value
- Updated documentation to clarify that the bare `clone.defaultObjectFilter` form applies to all clones while URL-qualified forms take precedence

The thread has reached consensus on this being the right approach, with Junio's final review feedback incorporated. The feature provides a clean solution that maintains consistency with Git's HTTP configuration patterns while preserving safety boundaries by limiting to clone operations. With all technical decisions settled and implementation refinements complete, this appears ready for merging.
