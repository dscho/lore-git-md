Test infrastructure issue: brian m. carlson identifies the root cause of test failures on Arch/Artix Linux, where credential helper and askpass scripts cannot execute despite correct permissions. The key insight is that `/dev/shm` (where tests are being run) is not a general-purpose temp directory and may be mounted with `noexec`, preventing script execution. This explains why `chmod -R 755` didn't help - the issue is at the filesystem level, not the file permissions.

The response provides concrete guidance: tests should run in the repository's `t/` directory or another filesystem that allows execution, not in `/dev/shm`. This matches the observed symptoms across multiple test suites (t0300-t0302 credentials tests and now t5003 HTTP auth) where helper scripts fail with "Permission denied" errors. The explanation is technically sound and comes from a long-time contributor with deep knowledge of Git's test infrastructure.
