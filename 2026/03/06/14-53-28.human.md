This is a refactoring patch from Phillip Wood, part of the ongoing series to add `--trailer` support to `git rebase`. The patch focuses on moving the `create_in_place_tempfile()` function from `builtin/interpret-trailers.c` to `trailer.c` so it can be reused by other commands.

The key changes are:
- Changing the function to return a `struct tempfile*` instead of `FILE*` to better match modern Git tempfile handling conventions
- Replacing `die()` calls with `error()` to allow graceful error handling by callers
- Using `find_last_dir_sep()` instead of `strchr()` for more robust path handling
- Removing the static `trailers_tempfile` variable since tempfiles are now auto-allocated on the heap

This is a mechanical change that prepares for sharing the tempfile creation logic between `git interpret-trailers` and the upcoming rebase trailer functionality. The patch follows Git's established patterns for tempfile handling and error reporting, and maintains all existing behavior while making the code more reusable.

As part of the larger series (now in its 8th iteration), this change helps enable in-process trailer manipulation during rebase operations without forking `git interpret-trailers`. The series has been thoroughly reviewed and is nearing merge readiness.
