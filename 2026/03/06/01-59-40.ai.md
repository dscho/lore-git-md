This is a test infrastructure issue involving execution permissions for helper scripts. brian m. carlson responds to Ivan Ivanov's report of test failures in t0300-credentials and t5003 tests on Arch/Artix Linux, where helper scripts fail with "Permission denied" errors despite correct permissions being set.

The key technical insight is that the tests are being run from `/dev/shm`, which brian identifies as problematic since this shared-memory filesystem is often mounted with `noexec` flags. They explain that Git's test suite requires a fully functional filesystem for its helper scripts, and suggest the failures stem from attempting to execute scripts in an inappropriate location rather than a Git bug.

The response provides context about proper test environment setup, contrasting with Debian's build configuration as an example. This moves the discussion from "why are tests failing" to "how to properly configure the test environment", suggesting the issue lies in the test execution context rather than the tests themselves. The mention of `TEST_OUTPUT_DIRECTORY` points to a likely misconfiguration in how the tests are being invoked.
