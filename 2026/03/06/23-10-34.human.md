This is a small bugfix patch from Junio C Hamano addressing an inconsistency in how `git show -U` handles its argument. The command currently accepts `-U` without a number (which should be invalid) while rejecting malformed inputs like `-Unan`. The patch would make both cases fail consistently with an error message.

However, Junio notes this would break existing tests in t4013 that rely on the current behavior, suggesting we might want to leave this as-is since changing it could break real-world scripts that depend on the current lenient parsing. The change itself is straightforward - it modifies the validation logic in diff.c to consistently check for valid numerical input.

This falls into the category of "technically a bug but probably not worth fixing" due to backward compatibility concerns. The patch demonstrates the kind of subtle command-line parsing edge cases that can linger in mature codebases.
