Thread identity: Bug report and fix proposal for `git subtree` (a contrib script) regarding incorrect branch deletion during repeated pushes of same commit.

Core problem: When pushing the same commit to a subtree remote branch twice, the second push incorrectly deletes the remote branch instead of being a no-op. This occurs in `cmd_push` when `cmd_split` exits successfully (status 0) but doesn't output the expected revision hash, leaving `localrev` empty which gets interpreted as a deletion refspec.

Current status: Bug reported with clear reproduction case and analysis. Proposed fix checks `localrev` non-empty before push. No maintainer response or version updates yet.
