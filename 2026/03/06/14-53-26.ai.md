This is the final patch in Phillip Wood and Li Chen's series adding `--trailer` support to `git rebase`, now in its 8th iteration. The feature enables in-process trailer manipulation during rebase by refactoring trailer handling to be reusable across commands.

The core functionality is now complete with all patches reviewed. The series includes shared helper functions, improved error handling, and resolves the final behavioral question about trailer ordering (maintaining consistency with `git commit` behavior where signoffs appear after other trailers). Junio Hamano has accepted the implementation and ordering approach. Only minor documentation and error handling improvements remain before merge.

Key technical details in this version:
- Initializes trailer config when continuing a rebase started with `--trailer`
- Reports errors when reading trailer state file
- Includes small documentation fixes
- Maintains all previous functionality including handling all rebase modes (interactive/non-interactive) and conflict scenarios
- Preserves the merge-backend-only restriction (rejects `--apply`)
- Still implies `--force-rebase` to ensure trailers are added even to fast-forwarded commits

The patch builds on the previous refactoring work that moved core trailer logic to `process_trailers()` in `trailer.c` while keeping `interpret_trailers()` for I/O operations. It uses `strbuf_write()` for atomic updates via tempfile+rename and maintains Git's established trailer ordering where signoffs appear after other trailers.

This represents the culmination of a multi-iteration effort to enable trailer manipulation during rebase while avoiding forks of `git interpret-trailers` and maintaining existing functionality through careful refactoring. With maintainer approval and all major technical questions resolved, this version appears ready for final merge pending the minor documentation updates noted in Phillip Wood's review.
