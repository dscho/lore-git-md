This is a feature patch for git-gui that adds automatic maintenance runs after commits, mirroring behavior already present in the command-line `git commit`. The change triggers `git maintenance run --auto` between rerere and the post-commit hook, always running detached (non-blocking) in the GUI context.

The patch is straightforward - it adds a 6-line block to the Tcl code that checks the `maintenance.auto` config and runs maintenance if enabled. The author notes this intentionally differs from the command-line version by always detaching, since blocking the GUI would be undesirable. 

This appears to be a sensible quality-of-life improvement that brings git-gui behavior in line with the CLI. The implementation looks correct and the commit message clearly explains the rationale for the divergence from the CLI behavior.
