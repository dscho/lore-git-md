This is a refactoring patch from Phillip Wood, part of the ongoing series to add `--trailer` support to `git rebase`. The patch focuses on moving trailer-related functionality to be reusable across commands.

The key change refactors `create_in_place_tempfile()` in `builtin/interpret-trailers.c` to:
1. Return a `struct tempfile*` instead of `FILE*` to eliminate the need for a file-scoped tempfile variable
2. Replace `die()` calls with `error()` and `NULL` returns for graceful error handling
3. Use `find_last_dir_sep()` instead of `strchr()` for finding parent directories
4. Move tempfile creation logic to be more self-contained

This is preparatory work for moving the function to `trailer.c` where it can be shared with the rebase command's trailer handling. The changes follow Git's modern patterns for tempfile handling (auto-allocated on heap since 2017) while maintaining the same functionality. Error handling is improved to let callers decide how to handle failures rather than dying immediately.

The patch is part of the final polishing for this feature, with all core functionality already reviewed and accepted by Junio Hamano. This particular change is a straightforward refactoring with no expected controversy, cleaning up the code before the shared function is moved to its new home.
