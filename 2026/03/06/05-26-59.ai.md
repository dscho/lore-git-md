This is the first patch in a series modernizing git-gui's maintenance behavior to align with Git's built-in auto maintenance feature. The patch modifies git-gui's TCL code to run auto maintenance run --auto after each commit, matching the behavior of the CLI's `git commit`.

The change adds a new block to git-gui/lib/commit.tcl that checks the maintenance.auto config and, if enabled, runs maintenance in detached mode (always detaching rather than honoring autoDetach, as the author notes this makes more sense for a GUI context). This follows the same pattern as builtin/commit.c but with the GUI-specific decision to force detach.

The patch is part of a larger effort to remove git-gui's legacy maintenance warnings and manual GC options in favor of Git's more sophisticated auto maintenance system. This first step ensures the actual maintenance behavior matches before the subsequent patches remove the now-redundant UI elements. The implementation appears straightforward and uncontroversial, following established patterns from the CLI while making appropriate GUI-specific adjustments.
