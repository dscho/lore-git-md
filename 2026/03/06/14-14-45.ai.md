This is a follow-up in the ongoing thread about test failures on Arch/Artix Linux due to `/dev/shm` being mounted with `noexec` flags. The contributor, Ivan Ivanov, confirms the root cause diagnosis from earlier in the thread (that the issue stems from helper scripts being copied to a non-executable location) and shares two practical workarounds they've found effective: either skipping the affected tests via `GIT_SKIP_TESTS` or redirecting test output to `/tmp` instead of `/dev/shm`.

The email also suggests a potential longer-term solution - modifying Git's test infrastructure to run helper scripts from their original locations rather than copying them to potentially restricted temporary directories. This would make the tests more portable across different system configurations. The note about 12 specific tests failing while others pass cleanly helps bound the scope of the issue.

Key technical details include the two workaround approaches (test skipping vs. alternate temp directory) and the observation that this is fundamentally a portability issue that could be addressed in the test infrastructure. The thread remains focused on practical solutions rather than debating the underlying system configuration, with the contributor providing concrete data points about what works in their environment.
