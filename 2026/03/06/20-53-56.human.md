This is a feature patch series for `git fast-import` that adds a new `re-sign-if-invalid` mode to handle invalid commit signatures during import. The series builds on prior work allowing signature stripping during import.

Justin Tobler's v2 series introduces the ability to re-sign commits with invalid signatures using the user's current signing key, with optional explicit key specification. The implementation now explicitly fails when encountering `extensions.compatObjectFormat` rather than silently dropping the signature, addressing feedback from the v1 review. The series includes improved warning messages, better documentation, and additional test coverage.

Key changes in v2 include:
- Support for specifying a signing key via `--signed-commits=re-sign-if-invalid[=<keyid>]`
- Explicit failure when attempting to re-sign in interoperability mode (with `extensions.compatObjectFormat`)
- Renamed `handle_invalid_signature()` to `handle_signature_if_invalid()`
- More detailed commit messages explaining the current limitations
- Additional test cases covering the new functionality

The series maintains the conservative approach to experimental features that reviewers requested, while providing a useful new capability for users who need to re-sign commits during import. The implementation is clean and well-tested, with clear documentation of the current limitations around interoperability mode. This looks ready for consideration by the maintainer.
