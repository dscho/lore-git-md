This is a build system patch that follows up on Jeff King's series fixing mmap-related memory leaks in Git's pack handling. The series already added `NO_MMAP` to the Makefile for leak sanitizer (LSan) builds; this patch makes the same change in meson.build for consistency.

The change ensures that when Git is built with leak detection (`b_sanitize=leak`), it will use heap allocations rather than mmap for pack index handling, just as it already does for address sanitizer builds. This matches the behavior in the Makefile and helps catch similar memory management issues in the future. The patch is straightforward and has been tested to confirm it catches the same test failures fixed earlier in the series. 

This is a minor but sensible follow-up to ensure build system consistency between Makefile and meson configurations. The discussion notes that while this removes some flexibility (you can't force mmap with sanitizers), that tradeoff is reasonable given the performance impact of sanitizers already dwarfs any mmap vs heap differences.
