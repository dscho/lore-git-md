This is the first patch in a series modernizing git-gui's maintenance behavior by aligning it with Git's built-in auto maintenance feature. The patch modifies git-gui's TCL code to automatically run maintenance (like garbage collection) after each commit, matching the behavior already present in the CLI's `git commit`.

The change adds a new block to `git-gui/lib/commit.tcl` that checks the `maintenance.auto` config and, if enabled, runs `git maintenance run --auto --quiet --detach`. The CLI version's auto-detach behavior is intentionally not preserved here since blocking the GUI during maintenance would create a poor user experience.

This is part of a larger effort to remove git-gui's redundant maintenance features now that Git core provides more sophisticated auto-maintenance. The patch appears straightforward and well-motivated, following established patterns from the CLI implementation. As noted in the thread summary, this direction was previously discussed and appears uncontroversial.
