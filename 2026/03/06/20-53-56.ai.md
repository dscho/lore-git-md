This is a feature patch series for `git fast-import` that adds a new `re-sign-if-invalid` mode to handle invalid commit signatures during import. The series builds on prior work allowing signature stripping during import and is now in its second version.

The core addition is a new mode for `--signed-commits` that can re-sign commits with invalid signatures using the user's current signing key, rather than just stripping them. The implementation now includes support for explicitly specifying a key ID via `re-sign-if-invalid[=<keyid>]` similar to `git commit --gpg-sign`. The series also properly handles failure cases by dying when signature regeneration fails or when attempting to use the feature in interoperability mode (which requires reconstructing commit buffers in both repository and compatibility formats, not yet implemented).

Key technical changes in v2 include:
- New `sign_buffer_with_key()` helper in gpg-interface.c
- Explicit failure for `extensions.compatObjectFormat` cases using `repo_oid_to_algop`
- Improved warning messages specific to commit resigning
- Renamed `handle_invalid_signature()` to `handle_signature_if_invalid()`
- Added NEEDSWORK comment documenting the interoperability mode limitation
- Expanded test coverage to verify behavior with explicit key IDs

The series consists of three patches:
1. A cleanup removing an unused forward declaration
2. Introduction of `sign_buffer_with_key()` plumbing
3. The main implementation adding the new mode with all the above features

The conservative approach to experimental feature handling (explicit failure rather than silent conversion) appears to have satisfied earlier concerns.
