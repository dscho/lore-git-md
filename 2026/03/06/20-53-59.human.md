Feature patch adding a re-signing mode for invalid commit signatures in `git fast-import`. This is the third and final patch in a v2 series that introduces a new `re-sign-if-invalid[=<keyid>]` mode for `--signed-commits`, allowing invalid signatures to be replaced with fresh signatures during import.

The patch builds on preparatory refactoring from earlier in the series that moved signing logic into shared plumbing. The new mode works similarly to `git commit --gpg-sign`, accepting an optional key ID to specify which key should be used for re-signing (falling back to the default key if none is provided). Invalid signatures trigger warnings with details about the original signer before being replaced.

The implementation includes comprehensive test coverage for various signature types (OpenPGP, X.509, SSH) and handles both the key specification and warning message cases. One current limitation is explicit: the mode does not yet support interoperability mode (where commits would need to be signed with both repository and compatibility hash algorithms), though the code includes a NEEDSWORK comment noting this for future work.

Justin Tobler carries this patch after incorporating review feedback from Christian Couder and Patrick Steinhardt on the v1 submission. The changes appear well-considered, with clear documentation of both functionality and limitations. The conservative approach to experimental features (explicitly failing rather than silently degrading) follows Git's typical pattern for new functionality.
