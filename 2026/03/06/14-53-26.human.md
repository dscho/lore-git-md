Feature: Final patch in the `--trailer` option series for `git rebase`, completing the ability to append trailers during rebase operations.

This is the 8th and likely last iteration of Phillip Wood and Li Chen's series to support `--trailer` in `git rebase`, building on their earlier work to refactor trailer handling into reusable library code. The series now has maintainer approval after addressing all major technical concerns, particularly around trailer ordering where signoffs are consistently placed after other trailers to match `git commit` behavior.

The implementation handles all rebase modes (interactive/non-interactive), preserves trailers through conflicts, and properly processes them during fixup/squash operations. The changes include moving more trailer-related functions into trailer.c as shared library code, improving error handling for trailer state files, and adding documentation. The series maintains the merge-backend-only restriction (rejecting --apply) and implies --force-rebase to ensure trailers are added even to fast-forwarded commits.

With all core functionality complete and reviewed, this version focuses on final polish - fixing minor documentation issues and improving error reporting when reading the trailer state file. The changes since v7 are relatively small, mostly around sharing more code between commands that use trailers. The test coverage in t3440-rebase-trailer.sh verifies the behavior across various rebase scenarios.
