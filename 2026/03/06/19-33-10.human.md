This is a follow-up discussion in the concluded thread about configurable partial clone filters via URL patterns. 

Junio C Hamano responds to brian m. carlson's late-stage concerns about the potential for unexpected partial clones in scripts that assume full clones. While acknowledging scalar as an alternative place for such configurations, Junio expresses his personal view that having this configuration directly in Git's clone command isn't inherently problematic. 

The key technical point raised is about ensuring there's a way to override any configured filter from the command line - which the implementation already provides (command-line `--filter` overrides config). This exchange represents final thoughts rather than substantive changes, as the feature has already been implemented and reviewed with maintainer approval. The discussion highlights differing perspectives on where such configuration belongs (core Git vs. scalar) without challenging the technical implementation.
