This is a follow-up in a thread about test failures on Arch/Artix Linux systems. The original issue involved credential helper and askpass tests failing due to execution from `/dev/shm` (a `noexec` filesystem), as diagnosed by brian m. carlson.

Ivan Ivanov confirms the `/dev/shm` hypothesis but notes the failures have different root causes in the test output files. While the credential tests (t0300-t0302) and askpass test (t5003) show similar user-facing symptoms (infinite password prompts), the underlying issues may be distinct. He's currently working around the problem by skipping these tests via `GIT_SKIP_TESTS`, along with several HTTP-related tests (t5411, t5540-t5541, t5550-t5551, t5559, t5563-t5564), though he's puzzled why the distro's packager didn't encounter these issues.

The thread highlights a tension between test portability and system configuration - specifically how filesystem mount options can interfere with test execution. The discussion suggests this may warrant either documentation updates or test infrastructure improvements to detect and handle `noexec` environments more gracefully.
