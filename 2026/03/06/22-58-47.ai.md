This is the fourth patch in a five-part series introducing configurable cover letter formatting for `git format-patch`. The series is now in its sixth iteration and considered final, with all technical requirements met and maintainer feedback addressed.

The current patch adds a `format.commitListFormat` configuration option that allows users to specify the cover letter commit list format via Git config rather than requiring the `--cover-letter-format` CLI option. The config supports three modes:
1. When unset, defaults to the traditional shortlog format
2. When set to "shortlog", explicitly selects shortlog format
3. When set to a format string prefixed with "log:", uses that format (with "[%(count)/%(total)] %s" as the default if empty)

The implementation integrates with the existing format processing from previous patches, maintaining the same validation rules (including the "log:" prefix requirement) and placeholder support (`%(count)` and `%(total)` for zero-padded numbering). The patch includes comprehensive tests verifying all config scenarios and their interactions with CLI options.

This continues the series' clean separation of concerns - the config handling builds on patch 2/5's refactored shortlog generation and patch 3/5's format string processing. The implementation is production-ready with no outstanding issues, as confirmed by the author and reviewers (including Junio Hamano and Jeff King) through six iterations of review.
