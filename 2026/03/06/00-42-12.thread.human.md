This thread documents a test infrastructure issue affecting multiple test suites when running on Arch/Artix Linux systems. The core problem stems from the test suite's temporary directory being set to `/dev/shm`, which is mounted with `noexec` flags, preventing execution of helper scripts needed for credential handling, HTTP tests, and SOCKS proxy verification.

brian m. carlson initially diagnosed the issue as being related to the `noexec` mount flag, which Ivan Ivanov confirmed while noting some variations in test failures. Jeff King (Peff) has now provided a detailed technical explanation of why these failures manifest as infinite password prompts - when helper scripts can't execute due to filesystem restrictions, Git falls back to terminal prompting. This explains why multiple test categories (credentials, HTTP auth, protocol tests) show similar symptoms despite testing different functionality.

The discussion has identified several workarounds, including using `TEST_OUTPUT_DIRECTORY` to specify a writable, executable location or skipping affected tests via `GIT_SKIP_TESTS`. Peff suggests two potential improvements: notifying the Arch Linux package maintainer about the problematic configuration, and possibly adding `GIT_TERMINAL_PROMPT=0` to `test-lib.sh` to prevent terminal spam from failing tests.

Open questions remain about why the distro packager didn't encounter these issues and whether the test infrastructure should be enhanced to better detect and warn about `noexec` environments. The thread has evolved from initial failure reports to a deeper understanding of the underlying mechanisms and potential solutions, with contributions from both the original reporter and experienced Git contributors.
