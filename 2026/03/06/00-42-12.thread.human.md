This thread documents test failures on Arch/Artix Linux where multiple test suites (including credential helpers, HTTP authentication, and SOCKS proxy tests) were failing due to `/dev/shm` being mounted with `noexec` flags, preventing helper scripts from executing. Ivan Ivanov initially reported the issue and confirmed the root cause diagnosis by brian m. carlson and Jeff King (Peff), who explained how the silent script execution failures led to infinite terminal prompting loops.

Two workarounds have proven effective: skipping affected tests via `GIT_SKIP_TESTS` or redirecting test output to `/tmp` instead of `/dev/shm`. The discussion then turned to whether the test infrastructure should be modified to handle `noexec` cases more gracefully, with Ivan suggesting running helper scripts from their original locations rather than copying them to potentially restricted temporary directories.

Peff has weighed in against this approach, arguing that while technically possible, it would add unnecessary complexity to the test infrastructure. His position is that this is a rare edge case not worth complicating the system for, especially when straightforward workarounds exist (simply avoiding `noexec` mounts for test execution). The thread now appears to be concluding with this pragmatic approach favored over more invasive test infrastructure changes.
