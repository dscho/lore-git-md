This is a documentation clarification from Junio C Hamano regarding pathspec behavior in Git commands, particularly `git stash`. The thread began with a question about whether `git stash` pathspecs are interpreted relative to the current directory or toplevel, and Junio weighs in with broader context.

Junio notes that in modern Git, there's no good reason for commands to require toplevel-relative pathspecs unless they specifically can't work from subdirectories. He points out that top-relative pathspecs would break shell tab-completion. He suggests it would be valuable for someone to audit which commands still require toplevel pathspecs and proposes standardizing the documentation to make current-directory-relative the default unless explicitly noted otherwise.

The email also acknowledges Erik88's observation that only `git stash push` actually supports pathspecs (despite `list` showing pathspec-like syntax in its help text) and confirms the workaround of using `git log stash` with pathspecs for listing. Junio's response indicates this would be a good opportunity for documentation cleanup, possibly suitable for a newer contributor to tackle.
