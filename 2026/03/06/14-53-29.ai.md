This is patch 3/6 in Phillip Wood and Li Chen's series to add `--trailer` support to `git rebase`. The patch moves two key functions from `builtin/interpret-trailers.c` to `trailer.c` to make them reusable across Git commands.

The main changes are:
1. `create_in_place_tempfile()` is moved and renamed to `trailer_create_in_place_tempfile()`. It now returns a `struct tempfile*` instead of a `FILE*` and uses `error()`/`NULL` returns rather than `die()` for better error handling. The function creates a temporary file in the same directory as the original file with proper permissions checking.

2. `process_trailers()` is moved verbatim to become a public function in `trailer.c`. This is the core logic for processing and rewriting trailers that will be reused by the rebase implementation.

The patch effectively reverts most of ae0ec2e0e0b which had moved trailer processing into the interpret-trailers builtin, now making these functions available to other parts of Git. This is a key enabler for the `--trailer` rebase functionality being added in later patches.

The changes are mechanical moves with no behavior changes, just exposing the functionality through the trailer.h header. Both functions are signed off by both authors, with Li Chen as primary author and Phillip Wood handling the final integration. This continues the series' pattern of careful refactoring to enable trailer manipulation during rebase without forking the interpret-trailers process.
