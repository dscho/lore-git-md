This is a bugfix for `git clone` that prevents a segfault when using `--revision` with servers that ignore the ref-prefix filtering. The issue occurs when a server advertises more refs than requested (including HEAD), causing `git clone` to dereference a NULL pointer when trying to update remote refs.

The patch adds a check for `remote_head_points_at->peer_ref` being non-NULL before proceeding with the ref update logic. The commit message clearly explains both the good case (server respects ref prefixes) and bad case (server ignores them), and provides a concrete reproduction case using an Azure DevOps repository.

The fix is small and focused - just a single line change in `builtin/clone.c` with a clear safety check. The author demonstrates understanding of the ref handling logic and provides a signed-off-by line. This appears to be a straightforward and well-justified fix for a real crash scenario.
