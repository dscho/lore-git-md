This is a feature patch for the `git replay` command, adding a `--revert` mode to support reversing commits directly on bare repositories. The patch is part of an ongoing effort primarily driven by GitLab's needs for their Gitaly service.

The implementation follows the same three-way merge approach as `git revert`, just with swapped arguments to reverse the diff direction. It maintains the standard revert commit message format ("Revert ...") and sets the author to the current user, matching existing `git revert` behavior. The patch includes thorough documentation updates and test coverage.

The technical implementation has evolved through several versions with input from multiple contributors, now reaching v4. The core functionality is solid, but there's an ongoing discussion about whether to use subcommands (`git replay revert`) instead of flags (`--revert`). While the subcommand approach is gaining traction for long-term interface clarity, there's consensus to defer that change to a follow-up series to avoid scope creep here.

The patch touches several key files including `builtin/replay.c`, `replay.c`, and adds significant test coverage in `t/t3650-replay-basics.sh`. It has received detailed review from Git experts including Phillip Wood, Patrick Steinhardt, and Junio Hamano, suggesting it's technically sound and likely to be merged once the interface discussion concludes.
