This is a test failure report for the credentials subsystem tests on Arch/Artix Linux. Ivan Ivanov reports that several credential-related tests (t0300-credentials, t0301-credential-cache, t0302-credential-store) are failing by entering an infinite credential prompt loop, while t0303-credential-external succeeds.

The core issue appears in t0300.2 where the test's credential helper scripts (which should provide fixed "foo"/"bar" credentials) are not being executed as expected. Instead, the test falls back to interactive prompting. The failure output shows empty username/password fields where "foo"/"bar" should appear, and the test helper's debug output (which should log credential operations) is missing.

The problem seems specific to how the test environment executes helper scripts - while the test sets up local scripts and modifies PATH to use them, something is preventing their execution. The fact that t0303 (which tests external credential helpers) passes suggests this may be related to how the test-local helpers are being handled rather than a general credential system failure.

This looks like a platform-specific test infrastructure issue rather than a bug in Git's credential handling itself. The infinite prompting behavior is particularly concerning as it suggests the test isn't failing cleanly when helpers aren't available. The reporter has provided detailed logs showing the exact test failures and environment setup, which should help diagnose the PATH or script execution issue.
