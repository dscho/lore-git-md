This is the second patch in a three-part series introducing branch name prefixing functionality to `git branch`. The patch adds a `branch.namePrefix` configuration parameter that mirrors the `--name-prefix` command-line option introduced in the first patch.

The config parameter accepts either a static string or the special `@{current}` token to use the current branch name as a prefix. The implementation reuses the same `add_branch_prefix()` helper function from patch 1, now checking for the config value when no command-line prefix is provided. The patch includes tests verifying that the config works with both static strings and dynamic `@{current}` expansion, including proper handling of duplicate branch names.

This continues the series' narrowed focus on `git branch` after dropping `checkout`/`switch` support in response to earlier feedback. The implementation is clean and maintains consistency between CLI and config options. The test coverage is thorough, showing the config works as expected and properly interacts with the command-line interface.

The patch represents a logical next step in the feature's evolution, providing persistent configuration after establishing the core functionality in patch 1. The remaining patch in the series will introduce a `--no-name-prefix` override option.
