Shreyansh Paliwal's GSoC 2026 proposal to reduce Git's reliance on global state has progressed to its third version, with Christian Couder having approved the previous iteration. The project continues the long-running effort to eliminate `the_repository` and other global variables, building on work by Ayush Chandekar, Olamide Bello, and René Scharfe.

The updated proposal maintains the two-phase approach: first tackling straightforward refactors in subsystems like xdiff-interface.c, archive*.c, and fsmonitor*.c where repository context exists in the call stack, followed by more complex structural changes for environment.c globals. Shreyansh has demonstrated readiness through several merged patches addressing global state in wt-status.c and tree-diff.c, including contributions that made it into Git v2.43.1.

The work is well-integrated with ongoing efforts - Phillip Wood has continued some of Shreyansh's worktree API changes, and Karthik Nayak reviewed editor.c modifications. While the v3 proposal only makes minor updates to wording and patch statuses, open design questions remain about how to scope repository-level variables, particularly editor configuration. The timeline remains structured with planned weekly updates throughout the coding period. This represents a mature proposal from a contributor who has already proven capable through concrete, merged contributions to the codebase.
