This is a follow-up in the ongoing discussion about `git stash` pathspec behavior documentation. Erik88 (erik88@gmail.com) adds technical details to Mirko Faina's earlier confirmation that pathspecs in `git stash push` are interpreted relative to the current directory.

The email clarifies that `git stash push` is the only stash subcommand that accepts pathspecs, as shown by its help output. It also notes that while `git stash list` shows `[<log-options>]` in its usage, it doesn't actually accept pathspecs - a potential documentation inconsistency. As a workaround, the author suggests using `git log stash` with pathspecs when needing this functionality.

This contribution strengthens the case for documentation clarification by:
1. Confirming pathspec support is limited to `push` among stash subcommands
2. Pointing out an apparent mismatch between `list`'s help text and actual behavior
3. Providing a practical alternative (`git log stash`) for pathspec-based stash listing

The technical details about which subcommands do/don't support pathspecs would be valuable to include in any documentation update, alongside the pathspec interpretation rules. The email doesn't propose specific documentation changes but provides concrete information that could inform them.
