This is a follow-up in the thread about test failures on Arch/Artix Linux due to `/dev/shm` being mounted with `noexec` flags. The original reporter, Ivan Ivanov, confirms the diagnosis from brian m. carlson and Jeff King (Peff) about the root cause - credential helper and askpass scripts failing to execute when tests are run from `/dev/shm`.

Ivan provides two concrete workarounds that have allowed successful package builds: either skipping the affected tests via `GIT_SKIP_TESTS` or changing the test root directory to `/tmp`. He also suggests a potential long-term solution - modifying the test infrastructure to run helper scripts from their original locations rather than copying them to potentially restricted directories.

The email shows the issue is now well-understood with clear workarounds available, though it raises the question of whether the test infrastructure should be made more robust against such filesystem restrictions. The thread has progressed from problem diagnosis to discussing solution approaches, with Ivan demonstrating practical ways to proceed while the broader test system improvements are considered.
