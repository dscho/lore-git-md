This is a refactoring patch in the ongoing `git replay` revert capability series. Siddharth Asthana responds to Toon Claes' feedback about the split handling of `commit_use_reference` in the revert message formatting code. The patch extracts shared revert message formatting into `sequencer_format_revert_header()`, but the current implementation leaves some logic split between the helper and its caller when handling commit references. 

Toon points out this creates confusion, particularly with the helper being called with NULL OID. Siddharth acknowledges the awkwardness and plans to adopt Phillip Wood's cleaner approach in v4 - moving all formatting (including commit reference handling) into a single `sequencer_format_revert_message()` function with a boolean flag. This will fully address Patrick Steinhardt's earlier suggestion and eliminate the NULL OID case.

The exchange shows the careful attention being paid to API boundaries and helper function responsibilities in this feature. While the current patch works, the planned v4 refactoring will produce a more maintainable division of concerns. This is part of the final polish before the revert capability can be merged.
