This is a test infrastructure discussion about handling `noexec` mount flags in Git's test suite.

Jeff King (Peff) responds to Ivan Ivanov's report of test failures when running Git's test suite with `--root=/dev/shm` on a system where `/dev/shm` is mounted with `noexec`. The issue affects credential helper and askpass scripts that need to be executable but fail silently when execution is blocked by the mount flags.

Peff acknowledges the technical possibility of modifying the test infrastructure to separate executable scripts from repository operations (using two directories instead of one), but argues this approach would add significant complexity. His position is that supporting `--root` on `noexec` filesystems isn't worth the effort - the simpler solution is to avoid using such filesystems for test execution in the first place ("if it hurts, don't do it").

The exchange highlights a tension between test portability (working in any environment) and keeping the test infrastructure simple. Peff's response suggests the project's preference leans toward simplicity, expecting users to configure their test environment appropriately rather than making the test suite handle all possible edge cases. This aligns with Git's general philosophy of keeping core infrastructure lean while allowing users to adapt their workflows to their specific needs.
