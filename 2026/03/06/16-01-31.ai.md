This is a test infrastructure discussion about handling `noexec` mount flags in Git's test suite.

Jeff King (Peff) responds to Ivan Ivanov's suggestion about making the test system more portable by running helper scripts from their original locations rather than copying them to potentially `noexec` temporary directories. Peff acknowledges the technical possibility but argues against the complexity this would introduce, suggesting instead that users simply avoid pointing `--root` to `noexec` filesystems like `/dev/shm`.

The discussion stems from test failures where credential helper and askpass scripts fail silently when executed from `/dev/shm` (mounted with `noexec`), causing Git to fall back to terminal prompting in an infinite loop. While workarounds exist (using `GIT_SKIP_TESTS` or redirecting output to `/tmp`), Peff's position is that this is an edge case not worth complicating the test infrastructure for, given the straightforward alternative of not using `noexec` mounts for test execution.

Key technical points include the current test directory model (single scratch directory per test) and the trade-offs involved in splitting this into separate executable and non-executable areas. The exchange reflects Git's pragmatic approach to test infrastructure - favoring simplicity over handling every possible environment configuration, especially when clear workarounds exist. This continues the thread's exploration of how to handle test execution in constrained environments while maintaining the suite's reliability and portability.
