Feature implementing configurable partial clone filters via URL patterns (`clone.<url>.defaultObjectFilter`). This is the final version of the patch that addresses all review feedback from the thread.

The patch adds a new configuration option that lets users specify default partial clone filters per URL pattern. When cloning a matching repository, Git automatically applies the filter as if `--filter` was passed on the command line. URL matching follows Git's existing urlmatch infrastructure with three specificity levels (domain/namespace/full path), where the most specific match wins.

Key technical details:
- Command-line `--filter` overrides the config (explicitly confirmed in final discussion)
- `--no-filter` can force a full clone despite the setting
- Only URL-qualified config entries are honored (bare `clone.defaultObjectFilter` is ignored)
- The filter is recorded in `remote.<name>.partialCloneFilter` for subsequent fetches
- Comprehensive test coverage for filter application, command-line override, different filter types, URL matching precedence, and edge cases

The implementation represents the consensus design from the thread, providing a clean solution that maintains Git's boundaries while offering a quality-of-life improvement for partial clone users. The final version includes refinements requested by Junio Hamano (removing a single-member struct, setting `cascade_fn` to NULL, adding NULL checks) and adds a test for `--no-filter` behavior.
