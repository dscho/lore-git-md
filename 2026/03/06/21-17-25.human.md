This is a test infrastructure discussion about handling `/dev/shm` noexec constraints in the Git test suite. The thread involves multiple test failures on Arch/Artix Linux where credential helper scripts and askpass helpers can't execute when tests run from `/dev/shm`.

brian m. carlson responds to Ivan Ivanov's suggestion about running askpass helpers from their original locations rather than copying them to the test directory. They explain that many test scripts are dynamically generated during test execution, making it impractical to guarantee test suite functionality in noexec environments. While sympathetic to the issue (having worked with noexec `/tmp` systems themselves), they argue the maintenance burden of supporting noexec cases isn't justified given available workarounds like using `GIT_SKIP_TESTS` or `TEST_OUTPUT_DIRECTORY=/tmp`.

The response maintains the position that this is an edge case the project isn't likely to accommodate, though the tone remains professional and acknowledges the real-world constraints some users face. This effectively closes the door on infrastructure changes for this issue while leaving the documented workarounds as the recommended solution.
