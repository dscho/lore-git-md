Feature patch adding a `re-sign-if-invalid` mode to `git fast-import`'s signature handling, with key specification support. This is the third and final patch in a v2 series that builds on preparatory refactoring in the first two patches.

The patch introduces a new `re-sign-if-invalid[=<keyid>]` mode for `--signed-commits` that will re-sign commits with invalid signatures using either a specified key or the default signing key. Valid signatures are left unchanged. The implementation leverages the shared signing infrastructure from patch 2/3 and includes comprehensive test coverage for various signature types (OpenPGP, X.509, SSH).

Key technical aspects include:
- New `SIGN_RESIGN_IF_INVALID` enum value and parsing logic in gpg-interface.c
- Updated `handle_signature_if_invalid()` to handle both strip and re-sign modes
- Explicit failure for interoperability mode (with NEEDSWORK comment)
- Warning messages that match the existing strip-if-invalid style
- Test cases verifying behavior with explicit key specification

The patch maintains the series' conservative approach to experimental features by explicitly failing when attempting to use the new mode in interoperability scenarios. The implementation is cleanly integrated with the existing signature handling code and follows Git's standard patterns for shared functionality.

This completes the feature work started in v1, incorporating all review feedback including improved warning messages, function renaming, and expanded test coverage. The series has received positive feedback from Patrick Steinhardt and brian m. carlson, with no outstanding objections from maintainers. Future work may address tag signature support and interoperability mode handling.
