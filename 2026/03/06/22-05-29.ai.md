Follow-up clarification in the mmap leak fix series.

This email from Junio C Hamano seeks final confirmation about the behavior of Git's `NO_MMAP` emulation layer when handling multiple `munmap()` calls on the same memory. Ramsay Jones had previously noted that the emulation layer (used when `mmap()` isn't available) doesn't properly handle duplicate `munmap()` calls, potentially causing double-free issues. Junio questions whether this is actually a problem in practice, since calling `munmap()` twice on the same region would already be invalid with real `mmap()`.

The exchange confirms that the emulation layer's current behavior - while technically incorrect for invalid duplicate calls - matches the real `mmap()` contract where such usage would be invalid anyway. This appears to be the final technical clarification needed before Junio can merge Jeff King's series fixing mmap-related memory management issues. The discussion highlights Git's careful handling of platform-specific edge cases, even in compatibility layers.
