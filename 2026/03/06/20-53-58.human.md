This is the second patch of a three-part series adding a `re-sign-if-invalid` mode to `git fast-import` for handling invalid commit signatures. The patch focuses on refactoring GPG signing logic to make it reusable.

Justin Tobler introduces a new `sign_buffer_with_key()` function in gpg-interface.c that centralizes the logic for signing arbitrary buffers while handling the default signing key lookup. This generalizes functionality that was previously specific to commit signing in `sign_commit_to_strbuf()`, which is now replaced with calls to the new helper.

The change is a key enabler for the series' main feature - allowing `fast-import` to re-sign commits with invalid signatures. By moving this logic to gpg-interface.c, it becomes available for reuse by both commit.c and the upcoming fast-import changes. The patch maintains all existing behavior while making the signing infrastructure more flexible.

This is a clean refactoring that follows Git's typical pattern of moving specialized helpers to more general plumbing when reuse is needed. The implementation looks solid, with proper handling of the signing key resolution and memory management. As part of a well-structured series addressing all prior review feedback, this change appears ready for inclusion.
