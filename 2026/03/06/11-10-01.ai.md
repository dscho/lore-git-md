This is a bugfix for `git clone` that addresses a segfault when using `--revision` with servers that ignore the ref_prefixes filter. The issue occurs when a server advertises more refs than requested, including HEAD, leading to a NULL pointer dereference in `update_remote_refs()`.

The patch modifies the guard condition in `update_remote_refs()` to also check that `remote_head_points_at->peer_ref` is non-NULL before proceeding. This prevents the segfault when the remote server doesn't respect the ref filtering requested by the client. The commit includes a reproduction case using an Azure DevOps repository.

The fix is straightforward and appears well-motivated - it handles an edge case where server behavior doesn't match client expectations. The patch touches only one line in `builtin/clone.c` and includes a clear explanation of both the good and bad code paths. This looks like a solid fix for a real-world issue that could affect users cloning from certain servers with the `--revision` flag.
