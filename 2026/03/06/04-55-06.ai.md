This is a technical implementation patch in the ongoing `git replay` revert capability series, specifically addressing message formatting consolidation. The patch responds to feedback from Toon Claes and Junio Hamano about split logic in revert message generation.

The key change moves all revert message formatting into the shared `sequencer_format_revert_message()` helper, eliminating the previous partial handling of `opts->commit_use_reference` in different places. Siddharth Asthana confirms this resolves Toon's concern about split logic by having `git replay` always pass `use_commit_reference=false` to get full OID paths, regardless of whether the command is classified as plumbing.

The discussion reveals an underlying question about `git replay`'s classification (plumbing vs porcelain) that remains unresolved, though the current implementation side-steps this by explicitly controlling the reference format behavior. The patch represents progress toward the v4 iteration that Phillip Wood suggested, which will fully encapsulate the message formatting logic while maintaining the desired behavior for the revert use case.

Technical details show the message formatting now cleanly separates between the header generation (handled by the shared helper) and the commit reference portion (still handled by the caller via `refer_to_commit()`). This maintains the architectural boundary while addressing the specific review feedback about split responsibilities in the previous version.
