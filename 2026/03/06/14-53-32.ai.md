This is the final patch in Phillip Wood and Li Chen's series adding `--trailer` support to `git rebase`, now in-process trailer manipulation during rebase by refactoring trailer handling to be reusable across commands. The patch implements the actual `--trailer` option for `git rebase` after the preparatory refactoring in earlier patches.

The implementation adds a new `--trailer=<trailer>` option that appends trailers to each rewritten commit message during rebase, processed via `git interpret-trailers`. The option only works with the merge backend (rejecting `--apply`), implies `--force-rebase`, and validates trailer arguments early to avoid starting an interactive rebase with invalid input. The patch includes comprehensive tests covering error paths, trailer insertion across rebase modes, conflict handling, fixup commands, and configuration integration.

Key technical details:
- Adds `trailer_args` to `struct rebase_options` and `struct replay_opts`
- Implements trailer validation and state file handling for rebase continuation
- Preserves trailers through conflicts and fixup/squash operations
- Maintains Git's established trailer ordering (signoffs after other trailers)
- Includes integration tests for CLI behavior, error cases, and edge conditions

The patch builds on the shared trailer processing infrastructure introduced earlier in the series and completes the functionality with all reviews addressed. Junio Hamano has accepted the implementation approach, and only minor documentation updates remain before merging. This enables future command integrations while following Git's pattern of separating core logic from I/O operations.
