This is a build system discussion about memory leak detection in the context of Jeff King's mmap-related fixes. Jacob Keller points out that the Makefile change to enable `NO_MMAP` for leak sanitizer builds (which forces heap allocations to catch mmap-related leaks) should likely be mirrored in the meson.build configuration. He notes that meson currently only enables `NO_MMAP` for address sanitizer builds, not leak sanitizer ones, and questions whether this should be aligned with the Makefile behavior.

The email highlights an inconsistency between the two build systems' handling of sanitizer configurations. Jacob observes that meson's current approach is less flexible since it doesn't allow forcing mmap usage with sanitizers enabled, though he acknowledges this is likely acceptable given the performance impact of sanitizers in general. This is a follow-up to Jeff King's series fixing mmap-related memory leaks that were only visible under certain toolchain configurations.
