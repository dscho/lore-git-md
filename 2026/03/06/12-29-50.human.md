This is a documentation discussion thread about `git stash` pathspec interpretation.

Erik responds to Mirko Faina's observation that most Git commands don't explicitly document whether pathspecs are interpreted relative to the current directory or repository toplevel. He confirms that `git stash push` does accept pathspecs (as shown by its help output) and believes they are relative to current directory, though this isn't explicitly stated.

The email also notes an inconsistency - while `git stash list` shows `[<log-options>]` in its help, it doesn't actually accept pathspecs. Erik suggests using `git log stash` with pathspecs as an alternative for similar functionality.

This continues the thread's exploration of undocumented behaviors around pathspec handling in Git commands, with `git stash` serving as a specific example. The discussion remains focused on clarifying current behavior rather than proposing changes, though the implicit question of whether documentation should be more explicit remains open.
