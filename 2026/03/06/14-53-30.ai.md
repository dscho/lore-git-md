This is the 4th patch in the 8th iteration of Phillip Wood and Li Chen's series adding `--trailer` support to `git rebase`. The patch introduces in-process trailer manipulation to avoid forking `git interpret-trailers`.

The patch adds `amend_strbuf_with_trailers()` to apply trailers directly to a message buffer using the existing `process_trailers()` infrastructure. It updates `amend_file_with_trailers()` to use this new function while maintaining the same in-place file modification semantics via tempfile+rename. The implementation includes early validation of trailer arguments and proper error handling.

Key technical changes include:
- Moving trailer validation and processing into the main process
- Preserving backwards compatibility with existing `--trailer=<trailer>` argument format
- Adding early config initialization in `cmd_commit()` and `cmd_tag()`
- Implementing proper error handling throughout the trailer application process
- The patch builds on previous refactoring work to make trailer processing reusable
- It maintains the same atomic file update behavior as the fork/exec version
- Error cases are now properly propagated rather than using die()

This is part of the larger effort to enable trailer manipulation during rebase operations without spawning external processes.
