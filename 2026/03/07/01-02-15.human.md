Bugfix for line-log functionality when combined with pickaxe options (-G/-S/--find-object). This is the first patch in a series that aims to improve `git log -L` by routing its output through Git's standard diff pipeline.

Michael Montalbo fixes a crash that occurs when using line-log (`-L`) with pickaxe options on a history containing file renames. The issue stems from how rename detection interacts with pickaxe filtering - the pickaxe options could discard diff pairs needed for rename tracking, leading to an assertion failure. The fix introduces a private diff_options struct for rename detection, isolating it from user-specified pickaxe options.

The patch includes a thorough test case that sets up a repository with renames and merges, then verifies the combination of `-L` with various pickaxe options. Some test cases are marked as `test_expect_failure` for filtering behavior that will be addressed in later patches in the series.

This appears to be a well-constructed fix with clear commit message explanation and comprehensive test coverage. The change is focused and follows existing patterns from the blame machinery. The series as a whole promises to bring more diff features to line-log, but this first patch sticks to fixing the immediate crash issue.
