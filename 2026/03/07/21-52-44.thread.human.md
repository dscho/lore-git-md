Dana Escoli has reported a terminal input issue specific to Git for Windows when using `git add --patch`. After editing a hunk and closing the editor, keyboard input stops being echoed to the terminal in certain environments. The problem occurs when using `bash.exe` from the Git installation on Windows 10, but works correctly with `git-bash.exe`.

The issue manifests across different editors (Notepad, Notepad++) and terminals (including IntelliJ's terminal and cmd.exe), suggesting it's not IDE-specific. Interestingly, while Ctrl+C becomes unresponsive, Ctrl+Z reveals that inputs are being processed but appear malformed with unexpected single quotes. 

This appears to be a Windows-specific terminal handling problem during interactive patch editing. The differing behavior between `bash.exe` and `git-bash.exe` suggests the issue lies in how these shells handle terminal control after editor invocation. While a workaround exists (using git-bash.exe), the core problem remains for users who need to use standard Windows terminal paths.
