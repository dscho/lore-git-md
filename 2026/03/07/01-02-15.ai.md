This is the first patch in a series improving Git's line-log functionality (`git log -L`). The patch fixes a crash that occurs when combining line-log with pickaxe options (`-G`, `-S`, `--find-object`) and renames.

The core issue stems from how line-log`'s rename detection interacts with pickaxe filtering. Currently, the rename detection path shares the same diff_options as the user-specified pickaxe options, causing diffcore_pickaxe()` to incorrectly discard diff pairs needed for rename tracking. This leads to assertion failures when processing subsequent commits.

The fix introduces a private diff_options struct for rename detection, isolating it from user-specified options. This follows the same pattern used in blame's find_rename()`. The patch includes comprehensive tests that verify the fix works with various pickaxe options (-G, -S, --find-object) across rename boundaries.

The test changes reveal some remaining limitations - while the crash is fixed, the pickaxe filtering functionality itself doesn't yet work properly with line-log` (marked as test_expect_failure). These will presumably be addressed in later patches in the series.

The changes are focused in line-log.c` with additions to the test suite. The patch appears well-structured with a clear commit message explaining both the problem and solution. The test coverage is thorough, including edge cases with merges and multiple renames.
