This is the final version of a feature patch implementing configurable partial clone filters via URL patterns (`clone.<url>.defaultObjectFilter`). The patch has gone through multiple rounds of review and addresses all feedback, with only minor documentation/test consistency nits remaining for a follow-up v5.

The feature allows users to configure default partial clone filters that automatically apply when cloning matching repositories, similar to how `http.<url>.*` config works. The implementation uses Git's existing urlmatch infrastructure to determine the most specific URL match, with three key behaviors: command-line `--filter` overrides the config, `--no-filter` forces a full clone despite config, and the filter setting is stored in `remote.<name>.partialCloneFilter` for subsequent fetches.

Key technical details in this version include:
- URL matching with domain/namespace/full path specificity
- Support for both bare (`clone.defaultObjectFilter`) and URL-qualified config forms
- Comprehensive test coverage of filter application, command-line overrides, different filter types, and URL matching precedence
- Explicit implementation of `--no-filter` behavior as requested in review
- Modernized test scripts using `test_cmp` instead of shell comparisons

The patch maintains clear boundaries by being clone-specific and provides override mechanisms addressing all technical concerns raised during review.
