This is the second patch in a 4-part series improving Git's line-log functionality (`git log -L`). The series aims to route line-log output through Git's standard diff pipeline, enabling previously unsupported features like `--word-diff`, `--color-moved`, pickaxe options (`-S`, `-G`), `--orderfile`, and `--diff-filter` to work with `-L`.

The patch removes the hand-rolled `dump_diff_hacky()` function that was producing line-log output, replacing it with a mechanism that routes through `builtin_diff()` and `fn_out_consume()`. The key changes include:

1. Introducing callback wrappers that filter xdiff output to only show tracked line ranges while maintaining proper diff formatting
2. Wiring up `-L` to imply `--patch` during revision setup rather than forcing it at output time
3. Adding line range tracking to `diff_filepair` structs
4. Switching `xmalloc` to `xcalloc` in `diff_filepair_dup()` to ensure proper initialization

The patch includes extensive test updates to verify the new behavior. The output format changes mean tools parsing `-L` output may need updates to handle additional header lines like `index` and `new file mode` headers, and funcname context in `@@` headers.

The implementation appears thorough, with careful handling of edge cases and performance considerations (benchmarks show no measurable regression). The commit message clearly explains both the technical approach and user-visible impacts. This is a significant improvement to line-log functionality that enables many previously unavailable diff features to work with `-L`.
