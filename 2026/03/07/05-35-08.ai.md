This is a bugfix patch addressing a memory leak in the object streaming code, part of Jeff King's ongoing series to fix mmap-related leaks. The issue occurs in `odb_source_loose_read_object_stream()` where error handling incorrectly tries to munmap a struct field that hasn't been populated yet, leaving the actual mmap allocation leaked. The fix changes the error path to munmap the local variable instead.

The leak was introduced by Patrick Steinhardt's 2025 change to restructure the streaming backend logic, which moved the mmap result into a local variable before assigning it to the struct. The issue only manifests under specific conditions: when built with clang (not gcc), with leak detection enabled (SANITIZE=leak), and with mmap emulation (NO_MMAP=1) which causes the mmap to use malloc internally. The test case t1060-object-corruption.sh can detect this leak.

This patch is effectively "3.5/4" - a mid-series addition to Jeff's original 4-patch set, addressing a new issue discovered during final verification. It demonstrates the careful attention being paid to resource management in mmap-related code paths, particularly around error conditions. The fix is straightforward and clearly correct, continuing the series' pattern of thorough error path cleanup.
