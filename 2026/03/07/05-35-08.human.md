This is a bugfix patch addressing a memory leak in the object streaming code, part of Jeff King's ongoing series to fix mmap-related leaks. The issue occurs when reading loose objects: the error path incorrectly tries to clean up an uninitialized struct member rather than the local mmap variable, causing leaks under clang with leak sanitizer enabled.

The patch is a straightforward one-line fix that changes which variable gets passed to `munmap()` in the error path. The leak was introduced by a 2025 change from Patrick Steinhardt that restructured the streaming code, and manifests specifically when built with `NO_MMAP=1` and clang (gcc doesn't detect it due to compiler-specific stack handling differences).

This is the sixth patch in what was originally a 5-patch series, added after Junio discovered the issue during final testing. The fix is small but important, closing a leak that could occur during object streaming operations. The series as a whole demonstrates careful attention to resource management in error paths across Git's object handling code.
