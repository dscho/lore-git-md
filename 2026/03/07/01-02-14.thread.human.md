This thread documents the successful completion of a series improving Git's line-log functionality (`git log -L`). The core change routes line-log output through Git's standard diff pipeline, enabling previously unsupported features like `--word-diff`, `--color-moved`, pickaxe options (`-S`, `-G`), and various formatting options to work with `-L`. The series was authored by Michael Montalbo, with post-merge documentation fixes from Kristoffer Haugsbakk.

The work progressed through four main patches: first fixing a crash when combining `-L` with pickaxe options in repositories with renamed files, then implementing the core pipeline change, followed by comprehensive test coverage, and finally documentation updates. Maintainer Junio C Hamano expressed enthusiasm for the direction and confirmed the approach to documenting remaining limitations (like unsupported non-patch diff formats). The series is now fully merged with all technical and documentation aspects complete.

The implementation carefully preserves backward compatibility while eliminating the special-case `dump_diff_hacky()` function in favor of the standard `builtin_diff()` path. This brings consistent formatting (including previously missing index lines and file mode headers) and enables a wide range of diff features that previously didn't work with `-L`. The thorough test suite verifies all newly enabled functionality, from basic formatting options to edge cases like range boundaries and no-newline markers. Two post-merge documentation formatting corrections were the final touches on this now-complete improvement to line-log functionality.
