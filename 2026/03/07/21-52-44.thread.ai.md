Bug report about terminal input handling in Git for Windows during `git add --patch` sessions. Reporter Dana Escoli describes input echo stopping after closing editor during hunk editing, occurring with `bash.exe` but working correctly with `git-bash.exe`. Issue manifests across multiple editors (Notepad, Notepad++) and terminals (IntelliJ, cmd.exe), suggesting Windows-specific interaction problem between Git's terminal handling and shell behavior after editor invocation. Inputs are processed but appear malformed (unexpected single quotes visible after Ctrl+Z). Workaround is to use `git-bash.exe` instead of `bash.exe`. Relevant to Git for Windows maintainers (Johannes Schindelen) and interactive patch machinery (Phillip Wood's area). No debug traces or bisect info provided yet.
