This thread explores how Git handles multiple promisor remotes in partial clone scenarios, particularly focusing on the interaction between the `extensions.partialClone` configuration and newer per-remote promisor settings. Lorenzo Pegorari, a prospective GSoC contributor, has done careful research into the current behavior where multiple promisor remotes can work together, with the `extensions.partialClone` remote serving as a fallback. The discussion touches on core object-fetching behavior that has seen recent work from established contributors, and raises important questions about backward compatibility as the fetch ordering mechanism evolves. This represents exactly the kind of thoughtful, well-researched inquiry that makes for a strong GSoC proposal.
