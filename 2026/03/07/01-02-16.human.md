This is the second patch in a 4-part series improving Git's line-log functionality (`git log -L`). The patch routes `-L` output through Git's standard diff pipeline instead of using a custom hacky implementation, enabling previously unsupported diff features like `--word-diff`, `--color-moved`, pickaxe options (`-S`, `-G`), `--orderfile`, and `--diff-filter` to work with `-L`.

The key change removes the hand-rolled `dump_diff_hacky()` function and replaces it with callback wrappers that filter xdiff output to only show tracked line ranges while preserving the standard diff format. This brings several benefits:
- More consistent output format including index lines, file mode headers, and funcname context
- Support for all standard diff formatting options
- Proper handling of rename detection and other diffcore features
- Better performance by leveraging existing diff infrastructure

The patch includes extensive test updates to verify the new behavior. Some minor output format changes may affect tools that parse `-L` output, but the changes bring the output in line with regular diff output.

This appears to be a well-constructed change that addresses a long-standing limitation (the NEEDSWORK comment dates back to the feature's introduction). The implementation carefully preserves backward compatibility while adding significant new capabilities. The patch series as a whole looks like a solid improvement to line-log functionality.
