This is a bugfix patch addressing a memory leak in the object streaming code when handling mmap'd loose objects. It's part of Jeff King's ongoing series to fix mmap-related memory leaks, though this particular issue was discovered by Junio during testing.

The patch fixes a regression introduced in commit 595296e124 where error handling incorrectly tried to munmap() a struct field that hadn't been populated yet, leaving the actual mmap'd region leaked. The issue manifests when using clang with SANITIZE=leak and NO_MMAP=1, particularly in t1060-object-corruption.sh. Interestingly, the leak wasn't detected with gcc due to compiler-specific stack handling differences.

The fix is straightforward - munmap() the local mapped variable rather than the struct field. This matches the original intention of the error handling path. The commit message provides excellent technical detail about how the leak was discovered through bisection and why it appears differently across compilers.

This patch should logically slot in before patch 4 of Jeff's series, which enables NO_MMAP for leak-check builds. While the series is technically complete, this additional fix addresses a related but distinct issue that surfaced during final testing. The patch is small, focused, and well-explained - typical of Jeff's high-quality contributions.
