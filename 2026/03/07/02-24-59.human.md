This is a bugfix patch addressing a memory leak in the object-file subsystem, part of Jeff King's ongoing series to fix mmap-related leaks. The patch specifically fixes a case where mmap'd memory for loose object files wasn't being cleaned up properly in error paths when using the streaming interface.

The issue was introduced in a 2025 commit that restructured how streaming handles object sources. The fix changes the error cleanup to use the correct local variable rather than the uninitialized struct field. The leak is detectable under specific conditions (NO_MMAP builds with clang) and was found through CI failures during Junio's testing.

This is patch 3.5 in what has now become a 4-patch series, inserted between the original patches 3 and 4. The series as a whole addresses multiple mmap-related leaks discovered during clone and fsck operations. While technically sound, the series' merge is currently on hold pending investigation of a related streaming leak and broader mmap handling considerations raised by Ramsay Jones.

The patch demonstrates Jeff King's characteristic attention to detail - it includes thorough analysis of why the leak wasn't caught earlier (compiler-dependent stack behavior) and connects it to historical changes in the code. The fix itself is small and focused, changing just one line to properly clean up resources.
