This is a feature and bugfix series that improves `git log -L` (line-log) functionality by routing its output through Git's standard diff pipeline. The line-log feature, which shows history of specific file ranges, previously used a custom output mechanism that bypassed standard diff formatting options.

The key changes in this 4-patch series:

1. Fixes a crash when combining `-L` with pickaxe options (`-S`/`-G`) and renames
2. Reworks the line-log output to flow through `builtin_diff()` and `fn_out_consume()`, enabling support for diff options like `--word-diff`, `--color-moved`, `-w`, and pickaxe
3. Adds comprehensive tests for the newly-supported options
4. Updates documentation to reflect the expanded functionality

The patchset represents a significant improvement to line-log's integration with Git's diff machinery. The implementation is careful to maintain existing behavior while adding support for standard diff features. Some known limitations remain (like support for non-patch diff formats), but the core functionality is now properly integrated.

The changes touch several key areas - diff.c gets the bulk of the new logic for handling line ranges through the pipeline, while line-log.c sees major simplification by removing its custom output code. The extensive test updates show thorough validation of the new capabilities.

This appears to be a well-constructed series that addresses a long-standing limitation in a maintainable way. The commit messages clearly explain the changes and rationale, and the patch structure makes the evolution easy to follow. The work builds on previous discussion about pickaxe support but takes a more comprehensive approach than the earlier rejected patch that would have disabled those options entirely.
