Feature: Configurable partial clone filters via URL patterns (`clone.<url>.defaultObjectFilter`)

This final version of the patch implements URL-based configuration for partial clone filters, allowing users to specify default filters that automatically apply when cloning matching repositories. The implementation follows the consensus design from the review discussion, with all technical concerns addressed and comprehensive test coverage.

The feature works by:
- Supporting both global (`clone.defaultObjectFilter`) and URL-specific (`clone.<url>.defaultObjectFilter`) configurations
- Using Git's existing urlmatch infrastructure for URL pattern matching (domain/namespace/full path)
- Respecting command-line overrides (`--filter` takes precedence, `--no-filter` disables the feature)
- Storing the filter in `remote.<name>.partialCloneFilter` for subsequent fetches

The patch includes thorough documentation explaining the precedence rules and usage examples, plus extensive test coverage for:
- Filter application and inheritance
- URL matching behavior
- Command-line override scenarios
- Different filter types (blob:limit, blob:none, tree:0)

Review feedback has been fully incorporated, including:
- Simplifying the internal implementation by removing a redundant struct
- Adding explicit `--no-filter` test coverage
- Modernizing test script style (using `test_cmp` instead of shell comparisons)
- Clarifying documentation about config forms and precedence

The thread is effectively concluded with only minor documentation/test consistency nits being addressed in this final version. Maintainer Junio C Hamano has approved the implementation, and the feature is ready for integration. This provides a clean solution for partial clone users while maintaining Git's safety boundaries by limiting the feature to clone operations only.
