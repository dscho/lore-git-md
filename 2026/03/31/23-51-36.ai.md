This is patch 9/12 in Jeff King's series addressing C23 const-correctness warnings. The patch focuses on the packet_reader subsystem, specifically the `line` field which was incorrectly marked as const despite being writable in practice.

The core issue is that `packet_reader.line` points into a non-const buffer but was declared const, which worked historically because strchr() would implicitly cast away constness. With C23's stricter type checking, this now generates warnings. The patch makes `line` non-const and updates related variables in receive-pack.c and send-pack.c where packet contents are parsed by writing NULs over delimiters.

The change interacts with the skip_prefix() improvements from patch 8, allowing safe modification of reader->line while maintaining type safety. The patch reveals that the const marking was always somewhat misleading since the line buffer is routinely modified during protocol parsing. The changes are mechanical but necessary for C23 compliance while preserving existing behavior.

This continues the series' pattern of precise, localized fixes that address compiler warnings without introducing new risks. The patch touches core protocol handling code but the changes are straightforward and well-justified.
