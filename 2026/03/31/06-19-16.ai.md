This is a test patch in the fsmonitor series implementing Linux support via inotify. The patch adds several important test cases to verify the fsmonitor daemon's behavior on Linux systems, particularly around edge cases and platform-specific behaviors.

The key additions include:
1. A smoke test that verifies the filesystem actually delivers inotify events (important for detecting non-functional configurations like older overlayfs)
2. A test for rapid nested directory creation that exercises the EEXIST race condition between recursive scans and queued inotify events
3. Reduced start-timeout from 60 to 10 seconds for faster test feedback
4. Improved test robustness in environments without procps (like Fedora CI) by falling back to /proc/$pid/stat
5. Job control fixes for the submodule-pull test to properly handle process groups

The patch demonstrates careful attention to real-world deployment scenarios, including container environments and constrained CI systems. The new tests specifically target known pain points in the Linux implementation, particularly around overlayfs and process management. This continues the series' pattern of thorough, production-focused testing that has characterized previous iterations.

The changes are part of the mature v12 series that has been production-tested for months and brings Linux fsmonitor to parity with Windows and macOS backends. The test additions here address the last-mile validation needed to ensure reliable operation across diverse Linux environments.
