This is patch 11 in Jeff King's 12-part series addressing C23 const-correctness warnings, specifically focusing on `strstr()` usage in the HTTP subsystem. The patch fixes a warning in `redact_sensitive_header()` where C23's stricter `strchr()` handling would complain about assigning a pointer from a const to non-const variable.

The change drops const from `sensitive_header` and `cookie` variables since they ultimately point to writable memory from a strbuf. To maintain compatibility with `skip_iprefix()` which expects a const out-parameter, the patch also extends the same "const outparam" macro trick used earlier in the series to `skip_iprefix()`. 

This continues the series' pattern of precise, localized fixes that balance C23 compliance with actual memory safety. The change is small but demonstrates careful attention to both compiler requirements and Git's internal invariants.
