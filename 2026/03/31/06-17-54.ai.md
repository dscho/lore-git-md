This is a bugfix for the Linux fsmonitor implementation, addressing an interaction between split-index and fsmonitor's EWAH bitmap that was exposed when the Linux inotify backend became active. The issue manifests as an out-of-bounds array access when fsmonitor_dirty bitmap references positions from a previous index state while split-index has not yet loaded all entries.

Paul Tarjan identifies two specific problem points in fsmonitor.c where the code fails to properly handle split-index cases. The first is in `tweak_fsmonitor()` which asserts the bitmap size without checking for split-index, and the second is in `fsmonitor_ewah_callback()` which unconditionally accesses cache entries based on bitmap positions. Both issues occur when the split-index hasn't merged all entries yet, causing the bitmap to reference positions beyond the current cache_nr.

The fix adds proper guards for split-index cases, matching the pattern already used elsewhere in the file. This follows up on a known issue that was previously worked around in t9210 by disabling GIT_TEST_SPLIT_INDEX. The patch properly resolves the fsmonitor side of the index.skipHash interaction remains outstanding as a separate concern.
