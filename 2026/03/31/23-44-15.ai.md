This is patch 6/12 in Jeff King's series addressing C23 const-correctness warnings, specifically around `strchr()` usage. The patch converts the `find_last_dir_sep()` inline function to a macro to resolve compiler warnings about const-correctness while maintaining compatibility with both const and non-const callers.

The issue stems from C23's stricter handling of const in `strrchr()`, which caused warnings when the inline function implicitly removed const from pointers. The macro approach preserves the original type information passed to `strrchr()`, letting the compiler handle const checking naturally. Peff notes this is a pragmatic solution that avoids requiring C23 generics, though he acknowledges the Windows-specific implementation in `compat/win32/path-utils.h` still uses explicit const-casting that could be improved later.

The change is mechanical but well-justified, showing Peff's characteristic attention to both technical correctness and practical constraints. As with the rest of the series, this patch balances compiler compliance with maintaining existing behavior for callers that rely on non-const returns. The diff is minimal (replacing a 3-line function with a 1-line macro) but effectively resolves the warning without introducing new risks.
