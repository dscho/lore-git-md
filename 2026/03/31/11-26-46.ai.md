This is a patch series focused on platform compatibility improvements for the reftable backend, part of the ongoing effort to make Git's reftable implementation fully portable for use in libgit2. Patrick Steinhardt, a key driver of the reftable effort, introduces six patches that address various system-level dependencies in the reftable code.

The series tackles several portability pain points: introducing a cross-platform `REFTABLE_INLINE` macro, removing hard dependencies on `fsync()`, standardizing unused parameter annotations, adding time and memory-mapping abstractions, and consolidating system-specific declarations into a new "reftable-system.h" header. These changes allow libgit2 to reuse Git's reftable implementation with minimal platform shims.

The patches appear well-motivated and focused, with clean separation of concerns. Each change is small and mechanical, touching only the reftable subsystem. The test coverage appears solid, with Patrick referencing both Git and libgit2 test runs. This series looks like the final step before libgit2 can fully adopt Git's reftable implementation, marking an important milestone in the reftable backend's maturation.

Key technical details include: the `REFTABLE_INLINE` macro replacing compiler-specific inline attributes, a new `time_ms()` abstraction for millisecond timestamps, and `mmap()`/`munmap()` wrappers in the new system abstraction layer. The changes are mostly internal plumbing - no user-visible behavior changes - but crucial for cross-platform consistency. The series builds on prior work to align Git and libgit2's reftable implementations, with only test fixes remaining after this merge.
