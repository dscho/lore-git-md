This is a follow-up discussion in the reftable portability series, specifically about the `REFTABLE_INLINE` macro introduced in patch 1/6. René Scharfe clarifies his earlier point about Git's handling of the `inline` keyword after Junio C Hamano notes that Git's build system does let users override `inline` via `config.mak`.

René acknowledges he missed the build system aspect but points out practical issues when `INLINE` is set to an empty string - it leads to warnings and linking errors, though he hopes pre-C99 compilers might handle this better. The exchange remains technical and constructive, with René accepting Junio's suggestion that the original commit message could be more precisely worded to say Git "knows to let users redefine" rather than implying a built-in fallback.

This discussion doesn't block the series but exemplifies the project's attention to technical accuracy, even in infrastructure details.
