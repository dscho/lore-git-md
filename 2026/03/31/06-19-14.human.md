This is a bugfix patch in the fsmonitor series, specifically addressing process isolation issues in the filesystem monitoring daemon. The patch ensures proper cleanup of inherited file descriptors and process group management when the fsmonitor daemon runs in the background.

The key changes are:
1. Adding `close_fd_above_stderr` to child processes at both explicit daemon startup and implicit spawn paths, preventing hangs when the daemon inherits unneeded file descriptors (like test harness pipes)
2. Implementing proper detach behavior on Unix via `setsid()` to prevent shell job control from waiting on the daemon
3. Suppressing stdout/stderr on the implicit spawn path to avoid terminal interference

This is part of the mature v12 series that brings Linux fsmonitor support to parity with Windows/macOS backends. The patch demonstrates careful attention to edge cases in process management, particularly important for CI systems and test environments. The implementation appears solid, with platform-specific handling for both Windows and Unix systems.

The patch has been production-validated and addresses a real issue where inherited file descriptors could cause hangs. It's a focused improvement to the already well-tested fsmonitor infrastructure.
