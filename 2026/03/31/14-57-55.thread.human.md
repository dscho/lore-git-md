Giorgos Gasparis has proposed adding a new `git whoami` command that would conveniently display the user's configured name and email in one place. This would address a common workflow need - developers often need to verify their Git identity when switching between different repositories (like work vs personal projects). Currently, users must run two commands (`git config user.name` and `git config user.email`) or create custom aliases to get this information.

The proposal makes a strong case for this being a quality-of-life improvement that would benefit many users, given how frequently people need to check their active Git identity. While the email doesn't include implementation code, the concept appears straightforward and well-aligned with Git's existing configuration model. The next step would be for someone (likely Giorgos or another interested contributor) to follow up with a concrete patch implementation for review and discussion.
