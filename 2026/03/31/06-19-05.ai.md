This is a bugfix patch in the fsmonitor series implementing Linux support via inotify. The patch specifically addresses an interaction between fsmonitor's EWAH bitmap and split-index mode that could cause out-of-bounds array access when the split-index hasn't fully loaded all entries yet.

The fix adds guards in `tweak_fsmonitor()` and `fsmonitor_ewah_callback()` to ensure we don't access the fsmonitor_dirty bitmap beyond the number of entries actually present in the split-index. This resolves a BUG assertion that was previously worked around in t9210 by disabling GIT_TEST_SPLIT_INDEX.

The patch is part of a mature series (now at v12) that has been production-tested for months and has addressed all substantive technical feedback. The implementation brings Linux fsmonitor to parity with existing Windows and macOS backends, with careful handling of directory watches, rename tracking, and remote filesystem detection.

This particular fix demonstrates the thoroughness of the testing - it catches an edge case in split-index interaction that wasn't apparent in earlier versions.
