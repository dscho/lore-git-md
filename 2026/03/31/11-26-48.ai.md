This is the second patch in Patrick Steinhardt's 6-part series improving reftable portability for libgit2 integration. The change removes a direct `fsync()` call from the reftable stack implementation, making the behavior depend solely on the caller-provided fsync callback.

The patch addresses a specific portability issue: some platforms may not provide `fsync()`, but the reftable code was calling it directly when no callback was supplied. The new behavior simply returns success (0) when no fsync callback is provided, pushing the responsibility for synchronization entirely to the caller. This matches the library's design philosophy of letting users control I/O behavior.

The change is minimal (just one line modified) and focused on the reftable subsystem. It's a straightforward improvement that makes the code more portable without changing its core functionality. The patch continues the series' pattern of small, mechanical changes that remove system dependencies while maintaining the same logical behavior. This particular change helps libgit2 use the reftable code without requiring it to implement platform-specific fsync behavior.
