This is the 12th iteration of a feature series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The series has been in development for months and appears technically sound, having addressed all substantive review feedback.

The key change in v12 is a bugfix for split-index interaction with fsmonitor's EWAH bitmap, resolving an out-of-bounds array access when the split-index hasn't loaded all entries. This addresses an issue Junio Hamano identified in integration testing. The fix adds guards in `tweak_fsmonitor()` and `fsmonitor_ewah_callback()` to handle cases where the split-index has fewer entries than the bitmap expects.

The implementation has been production-tested and includes comprehensive cross-platform support:
- Uses inotify with recursive directory watching and rename tracking
- Handles remote filesystems via statfs() detection
- Includes Windows compatibility through pthread emulation
- Features robust process isolation and cleanup
- Has extensive test coverage including edge cases

The series also deduplicates shared IPC and settings logic between macOS and Linux, and fixes several memory leaks in the platform-independent daemon code. All known technical issues appear resolved at this point, with the remaining discussion focusing on process considerations around AI-assisted development and securing final fsmonitor subsystem expert review.

This represents the completion of a major cross-platform feature that brings fsmonitor to Linux users while maintaining compatibility with existing implementations. The series is now technically complete and ready for integration.
