This is a process isolation patch in the fsmonitor series, adding Linux support via inotify. The patch introduces a new `close_fd_above_stderr` flag to `struct child_process` that ensures spawned processes don't inherit unwanted file descriptors from their parent.

When enabled, the flag makes child processes close all file descriptors above stderr (FD 2) between fork and exec, skipping only the child-notifier pipe. The cleanup is bounded by either `sysconf(_SC_OPEN_MAX)` or 4096 (whichever is smaller) for safety. This prevents test harness pipes and other parent FDs from leaking into child processes, which is particularly important for the fsmonitor daemon's reliability.

The change is part of the mature fsmonitor series (now at v12) that has been production-tested for months.
