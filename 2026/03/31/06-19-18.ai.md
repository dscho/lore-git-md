This is a bugfix patch in the fsmonitor series, specifically addressing an edge case in the Linux inotify implementation when used with split-index mode. The patch fixes two locations where the fsmonitor_dirty bitmap could reference positions beyond the current index state during split-index operations.

The first fix adds a guard in `tweak_fsmonitor()` to skip the bitmap assertion when working with a split index, matching existing protections in the read/write paths. The second change replaces an assertion in `fsmonitor_ewah_callback()` with a bounds check that safely handles out-of-range positions. This resolves a BUG() that was previously worked around in the test suite by disabling split-index testing.

The patch demonstrates the thoroughness of the fsmonitor implementation, catching a subtle interaction between the EWAH bitmap tracking and Git's split-index feature. As part of the mature v12 series that has been production-tested for months, this fix brings the implementation closer to finalization by addressing one of the last known edge cases. The remaining issue with index.skipHash interaction is noted as being outside this patch's scope.
