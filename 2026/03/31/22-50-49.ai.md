This is a technical follow-up about memory management in Taylor Blau's MIDX repacking series, specifically addressing the cleanup of MIDX files. The discussion reveals an unexpected complexity in the planned transition from `string_list` to `strset` for tracking kept hashes.

Taylor Blau revisits Jeff King's earlier observation about memory leaks in the string list handling and finds that moving to `strset` doesn't cleanly solve the problem. The `strset` API doesn't automatically free keys when cleared, requiring manual cleanup that would involve directly accessing the underlying hashmap - an approach Taylor describes as "pretty gross" due to its violation of abstraction boundaries. 

The proposed solution shows the manual cleanup would require:
1. Initializing the strset without string duplication
2. Explicitly iterating through the hashmap to free each key
3. Then clearing the strset itself

Taylor concludes this approach is worse than sticking with the original `string_list` implementation (with proper `STRING_LIST_INIT_DUP` usage to avoid leaks), demonstrating the careful tradeoffs being made in this low-level memory management code. The exchange highlights how even seemingly straightforward refactorings can uncover subtle API limitations that affect design decisions in Git's core infrastructure.
