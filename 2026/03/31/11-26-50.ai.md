This is the fourth patch in Patrick Steinhardt's series improving reftable portability for libgit2 integration, focusing on time measurement abstraction. The change replaces direct `gettimeofday()` calls in the reftable stack code with a new `reftable_time_ms()` function that uses Git's existing `getnanotime()` infrastructure.

The patch simplifies the timeout handling in `reftable_stack_reload_maybe_reuse()` by converting from `struct timeval` comparisons to direct millisecond arithmetic. This eliminates platform-specific time handling while maintaining the same 3-second timeout behavior. The implementation in `system.c` leverages Git's high-resolution timer, dividing nanoseconds by 1,000,000 to get milliseconds.

This change follows the series' pattern of isolating platform dependencies behind reftable-specific abstractions. The patch is small (30 lines net) and focused, touching only reftable internals with no user-visible impact. Test coverage appears maintained through existing reftable tests. The abstraction cleanly addresses a portability concern while reducing code - the custom `tv_cmp()` helper is removed entirely in favor of simpler integer comparisons.
