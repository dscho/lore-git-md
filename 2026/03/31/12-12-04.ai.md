This is a performance optimization patch for the experimental `git backfill` command, which is part of Git's partial clone functionality. The patch addresses an inefficiency where `backfill` would perform unnecessary object database preparation even when no objects needed to be downloaded.

The key changes are:
1. Adding a check to skip the `download_batch` call when the current batch is empty (nr == 0)
2. Adding trace2 instrumentation to track batch requests
3. Adding a test case that verifies no batches are requested when the repository is already up-to-date

The patch appears well-scoped and focused on a clear optimization opportunity. The author has thoughtfully included both instrumentation and test coverage to verify the behavior. The commit message clearly explains the problem and solution, though it might benefit from mentioning that this is particularly relevant for partial clones where the object database preparation could be expensive.

The RFC nature comes from the author's question about whether trace2 is the preferred way to verify this behavior in tests versus checking progress messages. This seems like a reasonable approach, as trace2 provides structured logging that's easier to test against reliably. The test case added follows existing patterns in the backfill test suite.
