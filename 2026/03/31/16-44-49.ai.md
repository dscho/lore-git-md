This is a documentation follow-up to a feature patch about configurable submodule fetch errors. Jean-Noël Avila (the Git documentation maintainer) provides review feedback on Paulius Zaleckas's patch that added the `fetch.submoduleErrors` config option.

Jean-Noël points out two documentation issues:
1. The syntax for command-line alternatives should use parentheses rather than angle brackets (`--submodule-errors=(fail|warn)` instead of `--submodule-errors=<fail|warn>`) to match Git's synopsis style
2. The new `--submodule-errors` command-line option is not documented in the relevant man pages, only the config option is covered

The feedback is specific to documentation conventions and completeness, not the underlying implementation. As the maintainer driving the synopsis-style conversion effort, Jean-Noël is ensuring the new feature follows established documentation patterns. This appears to be a straightforward documentation polish that the original author can address in a v2.
