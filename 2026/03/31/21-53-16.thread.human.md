Nick Golden reported a crash in `git commit -a` that occurs during unresolved merges when rename detection is involved. The issue manifests when there's both an unresolved merge conflict and a tracked file deletion, causing Git to incorrectly attempt to stat a deleted path during rename detection. The bug is reproducible on Git 2.53.0 (macOS) and comes with a clear test case demonstrating the failure.

The expected behavior would be for Git to either stage the deletion while stopping due to the unresolved merge, or refuse the commit entirely - not crash with a stat error. The problem appears to lie in `add_files_to_cache()` during rename detection. While this email only contains the bug report (not a fix), it clearly identifies a legitimate edge case that needs addressing.
