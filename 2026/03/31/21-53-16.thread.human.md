This thread addresses a bug where `git commit -a` would crash during unresolved merges when rename detection incorrectly paired a deleted file with an unmerged path. Nick Golden reported and fixed the issue by disabling rename detection in `add_files_to_cache()` during this specific scenario, as rename tracking isn't needed when staging worktree changes.

The fix went through two iterations, with Junio C Hamano reviewing the test improvements in v2. The final version incorporates all requested changes: replacing Perl with sed, simplifying assertions using `git ls-files`, and making the test more robust against future output changes. The test case carefully reproduces the scenario by creating identical files, generating a merge conflict on one while deleting the other, then verifying correct handling.

Nick has confirmed auditing similar code paths and finding no other instances of this issue. With the maintainer's feedback addressed and the narrowly targeted fix properly tested, this appears ready for inclusion. The solution maintains merge semantics while preventing the crash, without broader impacts to rename detection behavior.
