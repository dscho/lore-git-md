This is patch 8/12 in Jeff King's series addressing C23 compatibility warnings around `strchr()` const-correctness. The patch introduces a clever macro hack to enforce type safety in `skip_prefix()` calls while maintaining flexibility.

The core problem is that `skip_prefix()` takes a const input string but needs to handle both const and non-const output pointers safely. The new `CONST_OUTPARAM` macro uses a ternary trick to ensure the output pointer is at least as const as the input, catching dangerous cases at compile time while allowing valid use cases. This enables cleaner fixes in subsequent patches without unsafe casts.
