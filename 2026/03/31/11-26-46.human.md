This is a series of platform compatibility improvements for the reftable backend, part of the ongoing effort to make Git's reftable implementation fully reusable by libgit2. Patrick Steinhardt, who has been leading much of the reftable work, sends these final portability fixes needed for libgit2 integration.

The series focuses on abstracting system-specific behaviors like file operations, memory mapping, and timing functions behind portable interfaces. Key changes include adding a new `reftable-system.h` header to consolidate these abstractions, removing direct calls to `fsync()`, and introducing platform-independent ways to get millisecond timestamps. The patches also clean up some existing macros and unused parameter markers to be more consistent.

These changes are already being tested in libgit2 (linked in the cover letter) and appear to be the last remaining pieces needed before libgit2 can fully adopt Git's reftable implementation. The work looks well-motivated and carefully done - it's part of a larger cross-project effort to share infrastructure between Git and libgit2, with Patrick coordinating between both codebases. The patch series is small (6 focused commits) and touches only reftable-specific code, so it shouldn't impact other parts of Git.
