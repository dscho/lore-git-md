This is a bugfix patch in the long-running fsmonitor series, specifically addressing a potential hang condition in the daemon's cookie wait mechanism. The patch replaces an infinite `pthread_cond_wait()` with a one-second timeout using `pthread_cond_timedwait()`, preventing indefinite hangs when filesystem events fail to be delivered (a known issue on certain container/overlay filesystems).

The change is well-motivated by real-world scenarios where inotify watches succeed but events never arrive. When the timeout fires, the daemon now reports an error and allows the client to proceed with a full scan rather than blocking forever. The implementation includes proper time handling and error checking, with trace logging for debugging.

This patch is part of the mature v12 series that has been production-tested for months and brings Linux fsmonitor support to parity with Windows and macOS. The series has addressed all substantive technical feedback, with remaining discussion focused on process questions around AI-assisted development rather than implementation concerns. This particular fix demonstrates the thoroughness of the testing, catching an edge case that could cause hangs in specific environments.
