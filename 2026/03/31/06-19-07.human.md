This is a memory leak fix in the fsmonitor daemon implementation, part of the long-running series adding Linux inotify support. The patch addresses a case where the `state.cookies` hashmap and its string entries were not being freed during daemon shutdown.

The fix properly cleans up the hashmap by iterating through all cookie items to free their names, then clearing the hashmap itself. This is a straightforward and necessary cleanup that was missed in earlier versions of the series. The patch demonstrates the thoroughness of the testing process - even after months of production use, subtle resource management issues like this are still being discovered and fixed.

This is part of the mature v12 series that has already addressed all major technical concerns. The implementation appears solid, with this being one of the final cleanup items needed before the feature can be considered complete. The patch itself is small and focused, exactly what we'd want to see for a memory leak fix.
