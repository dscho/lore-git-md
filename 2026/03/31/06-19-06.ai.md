This is a bugfix patch in the fsmonitor series, addressing a memory leak in the daemon's client handling code. The patch fixes a case where a khash table (`shown`) would not be freed when the client receives a trivial response, as the cleanup was only happening on the non-trivial code path.

The fix initializes the hash table pointer to NULL and moves its cleanup to a shared cleanup section using `kh_destroy_str()`, which safely handles NULL pointers. This ensures the hash table is properly freed regardless of which response path is taken. The change is small (5 lines modified) but important for correct memory management in the fsmonitor daemon.
