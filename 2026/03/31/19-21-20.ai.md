Feature addition to `git cat-file`'s batch mode, now merged with final maintainer refinements.

Junio Hamano provides the last round of review feedback on Siddharth Asthana's mailmap toggle feature for `git cat-file --batch-command`. The implementation is fundamentally sound and ready to merge, but Junio suggests several documentation and code clarity improvements. He notes the commit message could drop implementation details about `git_parse_maybe_bool()` in favor of simply describing the boolean argument support, and recommends adding an in-code comment explaining the `strdup_strings` check used in the lazy-loading mailmap mechanism.

The review also surfaces two subtle interface considerations: the inability to specify a "true" value by omitting the argument (as in config syntax) and the potentially surprising interpretation of an empty string as "false". While these don't require changes, they're worth noting for future documentation. Junio questions the temporary `value` variable in `parse_cmd_mailmap()`, observing the logic could directly use `use_mailmap` since the order of operations doesn't matter.

This represents the final polish on a well-reviewed feature that solves GitLab Gitaly's need for dynamic mailmap control in long-running processes. All substantive technical concerns were addressed in earlier rounds, leaving only these last documentation and code presentation refinements before merging. The changes are confined to `builtin/cat-file.c` and its tests, with no impact on other subsystems.
