This is patch 7/12 in Jeff King's series addressing C23 const-correctness warnings, specifically targeting the pseudo-merge bitmap subsystem. The patch fixes a const warning but uncovers deeper issues in how pseudo-merges handle on-disk data.

The core issue is that `find_pseudo_merge()` returns a non-const pointer to mmap'd disk data, which new glibc versions flag as unsafe. Peff's solution changes the function to fill a caller-provided struct instead, properly byte-swapping the values. This reveals that the original code was missing necessary byte-swapping entirely, suggesting the interface was fundamentally flawed.

The patch also notes this code path isn't exercised by tests (a BUG()` inserted for testing never triggers), indicating potential gaps in test coverage for pseudo-merges. While the immediate goal is silencing the compiler warning, Peff acknowledges this may uncover real bugs in the experimental pseudo-merge feature, though further investigation is needed.

Key changes:
- Converts `find_pseudo_merge()` from returning a pointer to filling an output struct
- Adds proper byte-swapping via `read_pseudo_merge_commit_at()`
- Updates callers to use the new interface
- Notes the untested nature of this code path

This is typical of Peff's work - a seemingly simple const-correctness fix that reveals deeper architectural problems, addressed with careful consideration of both immediate needs and long-term correctness. The patch maintains the series' theme of balancing C23 compliance with robust code, though the pseudo-merge subsystem's test gaps remain an open question.
