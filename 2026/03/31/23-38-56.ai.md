This is a cover letter for a 12-patch series addressing C23 compatibility issues, specifically warnings about const-correctness in `strchr()` usage. The series comes from Jeff King (Peff), a long-time contributor known for precise fixes and deep system knowledge.

The core issue stems from C23 making `strchr()` more strictly const-correct, which causes warnings when const pointers are assigned to non-const variables. The series takes a multi-pronged approach: some patches add const where safe (converting, http, transport-helper), others use explicit casts when necessary (pager, run-command), and one converts a problematic inline function to a macro (find_last_dir_sep). Patch 7 fixes what may be actual bugs in pseudo-merge disk reads, while patch 8 introduces a clever but potentially compiler-unfriendly macro hack for `skip_prefix()` that enables cleaner fixes in subsequent patches.

The series builds on prior work from Collin Funk and Michael Forney, but takes different approaches in several cases. Peff notes some patches may be controversial (particularly the skip_prefix macro) and that Coverity already flags false positives on the construct. The changes span multiple subsystems but are textually independent, touching config, http, transport, pager, pseudo-merges, and refs backend code.

This is typical Peff work: thorough, technically sound, and addressing a real but subtle compatibility issue before it becomes a problem. The cover letter clearly explains the motivation, approach, and potential sticking points. The changes are mostly mechanical but demonstrate careful consideration of tradeoffs between type safety and code clarity.
