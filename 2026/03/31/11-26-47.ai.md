Platform compatibility patch introducing `REFTABLE_INLINE` macro for cross-platform support in the reftable library. This first patch in Patrick Steinhardt's 6-part series standardizes inline function declarations to work across compilers that may not support the `inline` keyword. The change replaces all `static inline` declarations in reftable headers with a new `REFTABLE_INLINE(type)` macro that can be adapted per-platform.

The patch mechanically updates inline functions across four reftable headers (`basics.h`, `pq.h`, `record.h`, and `system.h`), introducing the macro definition in `system.h`. This is purely a portability change with no behavior impact - the same functions will be inlined, just in a more compiler-agnostic way. The motivation is to make the reftable code usable as a standalone library (particularly by libgit2) without depending on Git's existing `inline` macro.

Key technical details: the macro preserves the same static linkage and type safety as the direct `static inline` declarations it replaces. The patch follows the series' pattern of small, focused changes to eliminate platform assumptions from the reftable codebase. As the first step in the portability series, it sets up the infrastructure needed for subsequent patches to handle other system dependencies like timestamps and memory mapping.
