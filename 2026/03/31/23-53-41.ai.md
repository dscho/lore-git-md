This is the final patch in Jeff King's 12-part series addressing C23 const-correctness warnings, specifically targeting the refs backend. The patch fixes a strchr() warning in the reflog parsing code by removing an incorrect const qualifier while maintaining type safety.

The issue occurs in `show_one_reflog_ent()` where a strbuf buffer (which is writable) gets parsed into reflog components. The code needs to write a NUL terminator over `email_end`, making the pointer non-const, but C23's stricter strchr() causes warnings when assigning to non-const from const. The solution involves making the source pointer non-const and extending the CONST_OUTPARAM() macro pattern (introduced earlier in the series) to `parse_oid_hex_algop()`.

This requires careful handling since `parse_oid_hex_algop()` isn't inline like previous cases - the patch renames the implementation to `_impl` suffix while keeping the macro wrapper for callers. The changes touch hex.c, hex.h, and refs/files-backend.c with minimal but precise modifications.
