This is a performance patch in Justin Tobler's series to refactor Git's object database write operations, part of the ongoing ODB abstraction effort.

The patch optimizes how Git handles large blobs when writing to packfiles with size limits. Previously, when a blob exceeded the packfile size limit, Git would write it partially, then seek back and restart in a new packfile. The new approach checks the blob's inflated size upfront to avoid the need for seek operations, which will be important for future changes that use stream interfaces that don't support seeking.

The key change replaces the seek-and-retry logic with a simple size check before writing. While this might leave packfiles slightly underutilized (since compressed sizes can vary), it eliminates expensive seek operations and prepares for upcoming stream interface changes. The patch touches core object-file handling code but maintains backward compatibility with existing behavior.

This is patch 4/6 in a series that's part of Patrick Steinhardt's broader ODB abstraction work. The changes are well-motivated and technically sound, though the performance impact isn't quantified in the commit message. Reviewers will likely focus on whether the tradeoff between packfile density and seek elimination is justified.
