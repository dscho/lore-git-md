Patrick Steinhardt's series to improve reftable portability for libgit2 integration is now complete with the addition of memory mapping abstractions in the fifth and final patch. The series, now at v2, establishes four key platform-agnostic interfaces: header organization, fsync behavior, time measurement, and now memory mapping - each implemented as minimal, focused changes to enable code sharing between Git and libgit2.

The final patch introduces a `reftable_mmap` struct and wrapper functions that replace direct mmap/munmap calls in the reftable block source code. This follows the same careful approach seen throughout the series: using Git's existing `xmmap_gently()` internally while providing a clean interface that libgit2 can implement differently. The change maintains all existing error handling semantics and behavior while making the implementation replaceable.

With all five patches now complete, the collaboration between Patrick (Git) and Ed Thomson (libgit2) has successfully created the necessary portability layer. The series addresses all concerns raised in v1, particularly by simplifying the fsync approach and removing the controversial `REFTABLE_INLINE` macro. Test coverage remains comprehensive across both implementations, and the changes are well-contained within the reftable subsystem. This work clears the path for libgit2 to adopt Git's reftable implementation while maintaining each project's platform-specific needs.
