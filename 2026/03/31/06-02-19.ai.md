Performance optimization follow-up for promisor object repacking. Patrick Steinhardt responds to Abraham Samuel Adekunle's patch that aimed to improve delta compression in promisor packs by adding fake paths to preserve pack ordering information. While acknowledging the general soundness of the approach, Patrick requests empirical validation through benchmarks to demonstrate actual pack size improvements and identify any potential regressions.

The review focuses on three main points:
1. The need for concrete performance measurements to justify the change
2. Code style nits (removing an empty line, consistent brace usage)
3. Performance concerns about the implementation's syscall overhead (four write() calls per object)

Patrick suggests optimizing the write path by reusing buffers to reduce syscall frequency. He also questions whether including "loose" as a hint for non-packed objects provides any benefit. The response maintains the technical focus of the original patch while pushing for more rigorous validation of the claimed improvements. This continues the thread's theme of optimizing promisor object handling, now shifting from implementation to validation and refinement.
