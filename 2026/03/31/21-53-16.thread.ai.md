Bug report and fix for `git commit -a` crash during unresolved merges with rename detection. Nick Golden originally reported a reproducible crash when (1) there's an unresolved merge conflict and (2) a tracked file is deleted from working tree, where rename detection would incorrectly pair the deleted file with the unmerged path, causing an "unable to stat" error in `add_files_to_cache()`. 

blindmansion has now provided a fix that disables rename detection in `add_files_to_cache()` since staging worktree changes doesn't need rename detection. The patch includes a thorough test case reproducing the original scenario (creating two identical files, generating merge conflict on one, deleting the other) and verifying correct behavior: unmerged state remains, deleted file is properly staged, and no crash occurs. The change is minimal (one line disabling rename detection) and well-justified, with the test preventing future regressions. The fix addresses the core issue while maintaining expected merge semantics.
