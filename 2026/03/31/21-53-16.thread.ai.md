Bug report: `git commit -a` crash during unresolved merges with rename detection. Nick Golden reports a reproducible crash when (1) there's an unresolved merge conflict and (2) a tracked file is deleted from working tree. The crash occurs when rename detection pairs the deleted file with the unmerged path, causing an "unable to stat" error. Reproducible on Git 2.53.0 (macOS) with provided test case: create two identical files, generate merge conflict on one, delete the other, then attempt commit. Expected behavior would be to either stage deletion while stopping for unresolved merge, or refuse commit entirely - not crash. Issue appears in `add_files_to_cache()` during rename detection. No patch provided yet - this is just the bug report. Next step: someone familiar with index/merge machinery needs to propose fix.
