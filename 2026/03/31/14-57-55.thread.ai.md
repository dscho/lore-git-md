Proposal for `git whoami` command to display user identity, initiated by Giorgos Gasparis as a more ergonomic alternative to querying separate config values. Junio C Hamano notes existing functionality via `git var GIT_AUTHOR_IDENT` which provides formatted name+email+timestamp string, raising the bar for justifying a new command. Kristoffer Haugsbakk observes that the timestamp-free name+email format appears in `git-interpret-trailers` documentation, suggesting broader need for this presentation style. Current discussion centers on whether the proposal offers sufficient advantages over existing mechanisms - either in output format simplicity (avoiding timestamp-stripping postprocessing) or in addressing demonstrated user confusion with current workflow. The tension between command proliferation (Git has 147 commands) and workflow convenience remains unresolved. No implementation yet proposed; next steps would require either concrete use cases where `git var` falls short, metrics showing widespread need, or a patch demonstrating the proposed command. Technical risk remains low but value proposition still needs stronger validation given existing solution.
