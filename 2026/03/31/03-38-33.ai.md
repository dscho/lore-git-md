This is patch 4/6 in Justin Tobler's series introducing write operations to Git's object database (ODB) transaction interface, part of the ongoing ODB abstraction effort. The patch focuses on optimizing packfile handling when writing large blobs.

The key change removes the need for file descriptor seek operations when handling blobs that would exceed the configured packfile size limit. Instead of writing the blob first and then rewinding when the limit is hit, the patch now checks the inflated blob size upfront to determine if writing it would exceed the limit. This eliminates the seekback operation while still respecting packfile size constraints.

The patch simplifies the code significantly - the `stream_blob_to_pack()` function no longer needs to return an error status for size limit violations, and the retry loop in `index_blob_packfile_transaction()` is removed entirely. The tradeoff is that packfiles may not be filled to their absolute maximum size due to zlib compression making the final size unpredictable, but the commit message argues this is an acceptable compromise.

This change prepares for future work where blob streaming will use `struct odb_write_stream` instead of direct file descriptors, since the stream interface doesn't support seeking. The patch maintains all existing functionality while making the code more straightforward and better aligned with the planned transaction interface changes coming in later patches.

The modification touches core object-file handling code but shouldn't affect end users directly. Reviewers will likely focus on whether the upfront size check is sufficiently accurate given compression variability, though the commit message makes a reasonable case that it's "good enough" for practical purposes.
