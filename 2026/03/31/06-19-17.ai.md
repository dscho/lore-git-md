This is a refactoring patch in the fsmonitor series, converting from a khash implementation to strset for pathname deduplication in the fsmonitor daemon's client handling code. The change follows Patrick Steinhardt's suggestion to use the higher-level strset interface rather than the lower-level khash primitives.

The patch modifies `do_handle_client()` in `builtin/fsmonitor--daemon.c` to use `struct strset` instead of khash for tracking which paths have already been shown to the client. The strset provides a cleaner API for string set operations while maintaining the same functionality. Since the paths are already interned strings from the batch data, the patch sets `strdup_strings=0` to avoid unnecessary string copying.

This change is part of the v12 iteration of the fsmonitor series, which has been production-tested and addresses all substantive technical feedback. The conversion to strset is a straightforward improvement that doesn't affect the core fsmonitor functionality but makes the code more maintainable by using Git's standard string set abstraction rather than direct khash operations. The patch demonstrates the continued refinement of the series as it approaches finalization.
