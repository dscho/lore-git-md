[PATCH 0/6] odb: improve flag handling in object database interface

Patrick Steinhardt's six-part series standardizing flag handling in the object database (ODB) subsystem is now complete with this final cleanup patch. The series systematically converted ODB flag handling to use typed enums following documented conventions (enum types with function-prefixed names in all-caps). Changes spanned odb.c, odb.h, packfile.c, packfile.h, object-file.[ch], and 22 other files, with each patch focusing on a specific ODB function's flags: odb_for_each_object(), odb_write_object(), and odb_has_object(). Flag renames included WRITE_OBJECT_* -> ODB_WRITE_OBJECT_* and HAS_OBJECT_* -> ODB_HAS_OBJECT_*.

The final patch (6/6) removes now-unnecessary headers and forward declarations from odb.h, dropping unused includes (hashmap.h) and redundant forward declarations (struct oidmap, struct oidtree, etc.) while keeping only the actually used declarations. This completes the mechanical but systematic conversion as part of the larger ODB abstraction effort to enable pluggable backends. All changes are non-functional code hygiene improvements maintaining strict backward compatibility. The series demonstrates Patrick's characteristic careful, well-structured approach to refactoring - touching many files while keeping each change focused and clearly documented. This work continues the ongoing ODB abstraction effort that has included recent changes to odb_find_abbrev_len() and related interfaces.
