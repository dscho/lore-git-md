[PATCH 0/6] odb: improve flag handling in object database interface

Patrick Steinhardt continues his ODB abstraction work with this six-part series standardizing flag handling across the object database subsystem. The first patch documented conventions for function flags in `Documentation/CodingGuidelines`: enum types with function-prefixed names in all-caps, bit-shifted values. The second patch converted `odb_for_each_object()` flags from `unsigned` to `enum odb_for_each_object_flags` across odb.c, odb.h, packfile.c, and packfile.h. The third patch now renames flags for `odb_write_object()` to follow these conventions: `WRITE_OBJECT_PERSIST` becomes `ODB_WRITE_OBJECT_PERSIST` and `WRITE_OBJECT_SILENT` becomes `ODB_WRITE_OBJECT_SILENT`, updating cache-tree.c, object-file.c, and odb.h.

This mechanical cleanup work prepares the codebase for pluggable backends by making interfaces more consistent. The series touches 28 files total with no functional changes, following Patrick's characteristic style of careful, well-structured changes. The patches appear ready for merging as non-controversial internal improvements to the ongoing ODB abstraction effort. Remaining patches will presumably apply similar renaming to `odb_has_object` and other ODB functions, standardizing flag names (e.g. `ODB_HAS_OBJECT_*`) while cleaning up headers and forward declarations. The work builds on Patrick's recent `odb_find_abbrev_len()` changes and targets master.
