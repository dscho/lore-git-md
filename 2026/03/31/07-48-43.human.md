This is patch 4/6 in Justin Tobler's series introducing write operations to Git's object database transaction interface, part of the ongoing ODB abstraction effort. Patrick Steinhardt provides a detailed review of the optimization that avoids seek operations when handling large blobs in packfiles.

The patch changes how Git handles blobs that would exceed packfile size limits - instead of writing first and rewinding when the limit is hit, it now checks the inflated blob size upfront. Patrick agrees this is a reasonable tradeoff, noting that while it may slightly reduce packfile utilization efficiency, the simplification is worth it given that pack size limits are rarely used and the change enables future stream-based interfaces.

Patrick's review confirms the technical approach while making a few minor observations: he questions whether a zero-byte read guard is necessary in the hashing code, suggests explicitly documenting the use of inflated sizes in the comments, and notes the existing safeguard against infinite loops with oversized objects. His approval carries weight as the primary driver of the ODB abstraction effort.

This continues the series that has been well-received so far, with Patrick having approved the previous patches with only minor feedback. The changes align with the broader goal of making object storage more flexible while maintaining backward compatibility. Reviewers can expect the remaining patches in the series to build on these foundations with further interface generalizations.
