This is a follow-up in the long-running fsmonitor Linux support thread, addressing a split-index interaction issue. Junio C Hamano responds to Paul Tarjan's quick fix for the fsmonitor/split-index bug, suggesting the fix should be applied earlier in the patch series rather than as a final patch.

The technical issue involves two fsmonitor functions (`fsmonitor_ewah_callback()` and `tweak_fsmonitor()`) that were not properly handling split-index cases, leading to out-of-bounds accesses. Paul's fix adds appropriate guards, but Junio points out that placing it at the end of the series would leave the code broken during bisection until the final patch is applied.

This exchange highlights the final polishing stage of the fsmonitor implementation, where the technical work is complete (as evidenced by Paul's successful test validation in a Fedora container) but the patch organization needs refinement. Junio's comment reflects Git's strong emphasis on maintaining a bisectable history - even for fixes to pre-existing issues that aren't introduced by the current series. The thread shows the maintainer's attention to both technical correctness and project process requirements as this long-running feature nears completion.
