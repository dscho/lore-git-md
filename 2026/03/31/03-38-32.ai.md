This is the third patch in Justin Tobler's 6-part series introducing write operations to Git's object database (ODB) transaction interface, part of the ongoing ODB abstraction effort. The patch refactors how blob objects are written to packfiles during transactions.

The key change removes the conditional `INDEX_WRITE_OBJECT` flag check from packfile write operations, splitting the functionality into two paths: a new `hash_blob_stream()` helper that only computes the OID when writing isn't needed, and an unconditional write path in `index_blob_packfile_transaction()`. This prepares for making packfile writes part of the transaction interface in a subsequent patch.

The patch touches core object-file handling code, particularly the `index_fd()` function used by commands like `git add` and `git update-index`. It maintains the same behavior while simplifying the control flow - writes are now either fully enabled or fully disabled at the `index_fd()` level rather than being checked repeatedly during the streaming process.

This is a preparatory refactoring that doesn't change user-visible behavior but makes the code more amenable to the transaction interface changes coming in later patches. The changes are part of Patrick Steinhardt's broader ODB abstraction effort to make Git's object storage more modular. Reviewers will likely examine whether the split between hashing-only and hashing-plus-writing operations is cleanly implemented.
