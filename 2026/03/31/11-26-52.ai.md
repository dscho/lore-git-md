This is the final patch in Patrick Steinhardt's series to improve reftable portability for libgit2 integration, focusing on platform compatibility. The patch introduces a new "reftable-system.h" header that consolidates system header dependencies, allowing projects like libgit2 to provide their own implementations of required system interfaces.

The change replaces direct includes of standard headers like `<stdint.h>` and `<unistd.h>` with the new umbrella header throughout the reftable subsystem. The header itself simply includes Git's existing "compat/posix.h" while maintaining the `MINGW_DONT_HANDLE_IN_USE_ERROR` define needed for Windows compatibility. This is a mechanical but important change that completes the abstraction layer for system dependencies.

The patch touches 13 files but makes only straightforward include adjustments - no behavior changes. It builds on the previous five patches in the series that abstracted inline declarations, time handling, memory mapping, and other platform-specific details. With this change, the reftable codebase now has a clean separation between its core logic and system dependencies, fulfilling the goal of making the implementation portable enough for libgit2 adoption.

Patrick's approach here is characteristically thorough - he's updating every reftable header to use the new system abstraction, even in cases where the immediate need isn't obvious. This ensures consistent behavior and makes future platform adaptations simpler. The patch appears ready for merging as the capstone to this portability effort.
