This is the third patch in Justin Tobler's 6-part series introducing write operations to Git's object database (ODB) transaction interface, part of the ongoing ODB abstraction effort. The patch refactors how blob objects are written to packfiles during transactions, removing the conditional behavior based on the `INDEX_WRITE_OBJECT` flag.

The key change splits the existing `index_blob_packfile_transaction()` function into two paths: a new `hash_blob_stream()` helper that only computes the object ID when writing isn't needed, and the main function that now unconditionally writes to the packfile when called. This prepares for making packfile writes part of the transaction interface in a future patch.

The changes affect core object-file handling code but don't introduce user-visible behavior changes. The patch appears well-structured, with clean separation of concerns between the hash-only and write paths. The commit message clearly explains the motivation - removing the flag makes the interface more straightforward as these writes become part of the transaction system.

This continues the series' pattern of preparatory refactoring before the main transaction interface changes in later patches. Reviewers will likely check that the split between hash-only and write paths maintains all necessary functionality while simplifying the interface. The changes align with Patrick Steinhardt's broader ODB abstraction work to make Git's object storage more modular.
