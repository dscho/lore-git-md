This is a documentation patch updating `git-var(1)` to properly reference the current `git config list` subcommand instead of the deprecated `git config -l` option. It's part of a series that Kristoffer Haugsbakk is sending to clean up references to the old syntax across Git's documentation.

The patch makes two changes to the man page: it removes the parenthetical note about the deprecation and replaces it with a more prominent WARNING admonition, and updates the reference to point directly to the modern `git config list` subcommand rather than the transitional `-l` option. The change is straightforward and well-motivated, continuing work that Patrick Steinhardt started when introducing the subcommand.

Since this is purely documentation with no behavior changes, the main consideration is whether the warning is appropriately visible and the reference accurate - both of which appear correct here. The patch follows the series' pattern of focused, single-file updates with clear commit messages.
