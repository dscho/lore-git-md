This is a technical discussion about memory management in Taylor Blau's MIDX repacking series, specifically addressing cleanup of MIDX files. Jeff King responds to Taylor's concerns about using `strset` versus `string_list` for tracking kept hashes.

Jeff clarifies that `strset` (built on `strmap`) does handle string ownership when properly initialized with `STRMAP_INIT` or `strmap_init()`, which sets `strdup_strings` to 1. He acknowledges the challenge when transferring ownership of existing strings, particularly those generated with `xstrfmt()`, which would require either keeping two copies or adding a new `strset_add_nodup()` function.

The exchange reveals deeper API design considerations - Jeff agrees that Taylor's proposed solution of manually freeing keys before clearing the `strset` is problematic, calling it "horrible" and noting similar patterns have caused bugs with `string_list`. He suggests two cleaner alternatives: either accepting the temporary duplicate allocation (allocating, adding to set, then freeing) or using a reusable `strbuf` to avoid allocations altogether.
