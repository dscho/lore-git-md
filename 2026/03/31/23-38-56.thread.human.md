Jeff King (Peff) continues his series addressing C23 const-correctness warnings, now tackling the pseudo-merge bitmap subsystem in patch 7/12. What initially appeared as a straightforward compiler warning fix revealed deeper issues in how pseudo-merges handle on-disk data. The key problem was that `find_pseudo_merge()` was returning a non-const pointer to mmap'd disk data, which newer glibc versions flag as unsafe. 

Peff's solution restructures the interface to have the function fill a caller-provided struct with properly byte-swapped values instead. This change exposed that the original code was missing necessary byte-swapping entirely, suggesting the interface had fundamental flaws. Notably, the patch reveals this code path isn't exercised by existing tests - a test insertion (BUG()) never triggered, indicating gaps in pseudo-merge test coverage. While the immediate goal is silencing the compiler warning, Peff acknowledges this may uncover real bugs in the experimental pseudo-merge feature.

The series continues to demonstrate Peff's characteristic thoroughness - what begins as a const-correctness fix often reveals and addresses deeper architectural issues.
