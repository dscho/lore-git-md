Reftable portability improvements for libgit2 integration - Patrick Steinhardt's 6-patch series completing platform abstraction work to enable shared reftable implementation between Git and libgit2. The series introduces cross-platform abstractions for inline declarations (`REFTABLE_INLINE`), time measurement (`reftable_time_ms()`), memory mapping (`reftable_mmap` struct and wrappers), and system headers via "reftable-system.h".

Key technical changes and status:
- Patch 1/6 standardizes inline declarations with `REFTABLE_INLINE` macro - approved by Junio C Hamano as aligning with Git's existing `inline` macro
- Patch 2/6 removes direct `fsync()` dependency via caller-provided callback - Junio raised design question about explicit failure when no fsync callback is provided (still open)
- Patch 3/6 replaces Git's `UNUSED` macro with `REFTABLE_UNUSED` - approved by Junio as achieving desired self-containment
- Patch 4/6 abstracts time handling using Git's `getnanotime()`
- Patch 5/6 introduces memory-mapping wrappers (`reftable_mmap`/`munmap`)
- Patch 6/6 consolidates system headers through "reftable-system.h" - Junio's latest review identifies architectural boundary concerns about mixing platform-neutral and Git-specific content in headers

Junio's review of patch 6/6 highlights a need to clarify the separation between:
1) Reftable's portable core (should be platform-neutral)
2) Platform abstraction interfaces (system.h)
3) Git-specific implementations (reftable-system.h)

He specifically questions whether `REFTABLE_INLINE` and zlib-compat.h belong in the platform-neutral system.h or should move to Git-specific reftable-system.h. This feedback suggests the series needs revision to better separate these concerns, likely by moving more Git-specific details into reftable-system.h while keeping system.h purely abstract.

Open questions:
1) Fsync behavior design from patch 2/6 (explicit failure vs silent success when callback missing)
2) Header organization boundaries from patch 6/6 (how to cleanly separate platform-neutral from Git-specific declarations)

The series continues to show test coverage against both Git and libgit2 test suites. Collaboration between Git (Patrick Steinhardt) and libgit2 (Ed Thomson) remains active, with Junio providing detailed architectural guidance. The maintainer's engagement indicates the series is progressing toward integration after addressing these final design considerations about error handling and header organization.
