Reftable portability improvements for libgit2 integration - a 6-patch series from Patrick Steinhardt completing platform abstraction work to enable shared reftable implementation between Git and libgit2. The series introduces cross-platform abstractions for inline declarations (`REFTABLE_INLINE`), time measurement (`reftable_time_ms()`), memory mapping (`reftable_mmap` struct and wrappers), and now system headers via new "reftable-system.h". 

Key technical changes:
- Patch 1/6 standardizes inline declarations with `REFTABLE_INLINE` macro
- Patch 2/6 removes direct `fsync()` dependency via caller-provided callback
- Patch 3/6 enforces subsystem boundaries by replacing Git's `UNUSED` macro
- Patch 4/6 abstracts time handling using Git's `getnanotime()`
- Patch 5/6 introduces memory-mapping wrappers (`reftable_mmap`/`munmap`)
- Patch 6/6 (new) consolidates system headers through "reftable-system.h"

The final patch replaces direct includes of `<stdint.h>`, `<unistd.h>` etc. with the new umbrella header throughout reftable subsystem, while maintaining Windows compatibility via `MINGW_DONT_HANDLE_IN_USE_ERROR`. This mechanical change completes the abstraction layer, allowing libgit2 to provide its own system implementations. All patches are focused on reftable/ directory with no user-facing impact.

The series represents the culmination of collaboration between Git (Patrick Steinhardt) and libgit2 (Ed Thomson) to unify implementations. With these changes, the reftable code is now fully portable between projects. Test coverage verified against both Git and libgit2 test suites. Only test fixes remain before libgit2 can adopt the shared code.
