Reftable portability improvements for libgit2 integration - Patrick Steinhardt's completed 5-patch v2 series establishing platform abstractions to enable shared reftable implementation between Git and libgit2. The series provides four key abstractions after addressing v1 feedback: time measurement (`reftable_time_ms()`), memory mapping (`reftable_mmap` struct and wrappers), system headers via a three-layer "reftable-system.h" model, and fsync behavior standardization.

Key technical changes and status:
- Patch 1/5 introduced the three-layer header organization system: `reftable-system.h` (platform-specific POSIX setup), `system.h` (platform-agnostic interface definitions), and `system.c` (project-specific implementations). Replaced direct standard header usage throughout reftable code.
- Patch 2/5 standardized fsync behavior by replacing the callback approach from v1 with a mandatory `reftable_fsync()` function implemented via Git's `fsync_component()` infrastructure. Junio C Hamano reviewed and approved this change, noting that since the reftable library manages all file operations internally, a single consistent fsync implementation is sufficient. Removes fsync callback from `reftable_write_options` and updates all call sites.
- Patch 3/5 standardizes unused parameter annotations with `REFTABLE_UNUSED`, replacing a single instance of Git's `UNUSED` macro in `reftable/fsck.c`. Notes architectural constraints preventing full isolation of `UNUSED` due to mingw-posix.h dependencies.
- Patch 4/5 introduces time measurement abstraction (`reftable_time_ms()`) that uses Git's getnanotime()/1000000 to replace direct `gettimeofday()` calls in reftable stack retry logic. Junio suggested clarifying in the function's header comment that callers should only rely on relative time comparisons, not absolute epoch values, as implementations may vary in epoch choice while maintaining consistency. This documentation improvement represents final polish on an otherwise complete implementation.
- Patch 5/5 implements memory mapping abstractions (`reftable_mmap` struct and related functions) to allow platform-specific mmap implementations while maintaining a consistent interface. Replaces direct mmap/munmap calls in the reftable block source code with new wrapper functions `reftable_mmap()` and `reftable_munmap()`, using Git's `xmmap_gently()` internally while providing a clean interface for libgit2 to implement differently.

Closed issues from v1:
1) `REFTABLE_INLINE` macro - removed from Git scope, now handled in libgit2
2) Fsync behavior - simplified to use Git's existing `fsync_component()` via direct interface, with Junio's approval confirming the architectural approach
3) Header organization - implemented via the three-layer model in patch 1/5

The collaboration between Git (Patrick Steinhardt) and libgit2 (Ed Thomson) has reached completion with this series, establishing consensus on minimal necessary abstractions. Junio's latest feedback on the time measurement documentation represents the final refinement to an already technically complete series. Each patch maintains the pattern of small, focused compatibility improvements with comprehensive test coverage across both Git and libgit2 test suites. The path is now clear for libgit2 adoption of the shared reftable code with all platform-specific concerns addressed through these well-defined interfaces.
