Reftable portability improvements for libgit2 integration - Patrick Steinhardt's 5-patch v2 series completing platform abstraction work to enable shared reftable implementation between Git and libgit2. The series focuses on four key abstractions after dropping controversial elements from v1: time measurement (`reftable_time_ms()`), memory mapping (`reftable_mmap` struct and wrappers), system headers via a three-layer "reftable-system.h" model, and fsync behavior standardization.

Key technical changes and status:
- Patch 1/5 introduced the three-layer header organization system: `reftable-system.h` (platform-specific POSIX setup), `system.h` (platform-agnostic interface definitions), and `system.c` (project-specific implementations). Replaced direct standard header usage throughout reftable code.
- Patch 2/5 standardized fsync behavior by replacing the callback approach from v1 with a mandatory `reftable_fsync()` function implemented via Git's `fsync_component()` infrastructure. Removes fsync callback from `reftable_write_options` and updates all call sites.
- Patch 3/5 standardizes unused parameter annotations with `REFTABLE_UNUSED`, replacing a single instance of Git's `UNUSED` macro in `reftable/fsck.c`. Notes architectural constraints preventing full isolation of `UNUSED` due to mingw-posix.h dependencies.
- Patch 4/5 introduces time measurement abstraction (`reftable_time_ms()`) that uses Git's getnanotime()/1000000 to replace direct `gettimeofday()` calls in reftable stack retry logic. Simplifies timeout comparisons while maintaining 3-second behavior.
- Patch 5/6 implements the full three-layer header model as agreed with Junio C Hamano

Closed issues from v1:
1) `REFTABLE_INLINE` macro - removed from Git scope, now handled in libgit2
2) Fsync behavior - simplified to use Git's existing `fsync_component()` via direct interface
3) Header organization - implemented via the three-layer model in patch 1/5

The collaboration between Git (Patrick Steinhardt) and libgit2 (Ed Thomson) continues with consensus on minimal necessary abstractions. Each patch maintains the series' pattern of small, focused compatibility improvements. Test coverage remains comprehensive across both Git and libgit2 test suites, with all tests passing on both implementations. The series remains on track to provide the portability layer libgit2 requires while keeping Git's implementation clean and maintainable. The time measurement abstraction in patch 4/5 follows the established pattern of introducing platform-specific interfaces only where absolutely necessary.
