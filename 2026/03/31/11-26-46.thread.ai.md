Reftable portability improvements for libgit table integration - Patrick Steinhardt's 6-patch series completing platform abstraction work to enable shared reftable implementation between Git and libgit2. The series introduces cross-platform abstractions for inline declarations (`REFTABLE_INLINE`), time measurement (`reftable_time_ms()`), memory mapping (`reftable_mmap` struct and wrappers), and system headers via "reftable-system.h".

Key technical changes and status:
- Patch 1/6 standardizes inline declarations with `REFTABLE_INLINE` macro - approved by Junio C Hamano with documentation clarifications, now challenged by brian m. carlson who questions the continued need for such abstraction given universal C99 `inline` support. Patrick Steinhardt defends the abstraction by noting libgit2's C90 compatibility requirements, including niche platforms like Amiga OS, though acknowledges this may be more theoretical than practical. René Scharfe previously clarified technical details about Git's build system allowing `inline` redefinition via `config.mak`, noting edge cases when `INLINE` is empty but maintaining support for the abstraction approach.
- Patch 2/6 removes direct `fsync()` dependency via caller-provided callback - Patrick Steinhardt now agrees with Junio C Hamano that the library should fail explicitly when no fsync callback is provided, rather than silently succeeding. He raises an architectural follow-up about whether fsync behavior belongs in write options (current implementation) or should move to the system abstraction layer.
- Patch 3/6 replaces Git's `UNUSED` macro with `REFTABLE_UNUSED` - approved by Junio as achieving desired self-containment
- Patch 4/6 abstracts time handling using Git's `getnanotime()`
- Patch 5/6 introduces memory-mapping wrappers (`reftable_mmap`/`munmap`)
- Patch 6/6 consolidates system headers through "reftable-system.h" - Patrick Steinhardt responds to Junio's architectural boundary concerns by acknowledging the current split between internal ("reftable/foo.h") and external ("reftable/reftable-foo.h") API surfaces is confusing. He suggests an alternative where callers would handle basic dependencies like <stdint.h> themselves, potentially simplifying header structure while remaining open to other organization approaches that maintain clean separation between reftable's core and system dependencies.

Open questions:
1) Fsync behavior design from patch 2/6 - now resolved in favor of explicit failure when callback missing, with remaining question about architectural placement (write options vs system abstraction layer)
2) Header organization boundaries from patch 6/6 - active discussion between Patrick Steinhardt and Junio C Hamano about optimal structure, with Patrick proposing caller-handled basic dependencies as one potential simplification path
3) Ongoing debate about `REFTABLE_INLINE` justification between brian m. carlson (questioning need given C99) and Patrick Steinhardt (citing libgit2's C90 requirements), with René Scharfe's technical clarifications about build system behavior adding nuance

The series continues to show test coverage against both Git and libgit2 test suites. Collaboration between Git (Patrick Steinhardt) and libgit2 (Ed Thomson) remains active, with Junio providing architectural guidance, René Scharfe contributing precise technical corrections, and brian m. carlson questioning the abstraction philosophy. The maintainer's engagement indicates progress on resolving the fsync behavior question, while the `inline` discussion and header organization remain as the primary open items requiring further refinement. The technical depth of these exchanges reflects the project's careful attention to architectural purity in system abstractions while balancing practical implementation needs across Git and libgit2.
