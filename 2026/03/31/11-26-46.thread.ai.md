Reftable portability improvements for libgit table integration - Patrick Steinhardt's 6-patch series completing platform abstraction work to enable shared reftable implementation between Git and libgit2. The series introduces cross-platform abstractions for inline declarations (`REFTABLE_INLINE`), time measurement (`reftable_time_ms()`), memory mapping (`reftable_mmap` struct and wrappers), and system headers via "reftable-system.h".

Key technical changes and status:
- Patch 1/6 standardizes inline declarations with `REFTABLE_INLINE` macro - approved by Junio C Hamano with documentation clarifications, now challenged by brian m. carlson who questions the continued need for such abstraction given universal C99 `inline` support
- Patch 2/6 removes direct `fsync()` dependency via caller-provided callback - Junio's design question about explicit failure when no fsync callback is provided remains open
- Patch 3/6 replaces Git's `UNUSED` macro with `REFTABLE_UNUSED` - approved by Junio as achieving desired self-containment
- Patch 4/6 abstracts time handling using Git's `getnanotime()`
- Patch 5/6 introduces memory-mapping wrappers (`reftable_mmap`/`munmap`)
- Patch 6/6 consolidates system headers through "reftable-system.h" - Junio's architectural boundary concerns about mixing platform-neutral and Git-specific content in headers still need addressing

Open questions:
1) Fsync behavior design from patch 2/6 (explicit failure vs silent success when callback missing)
2) Header organization boundaries from patch 6/6 (how to cleanly separate platform-neutral from Git-specific declarations)
3) Whether `REFTABLE_INLINE` abstraction remains justified given brian m. carlson's argument about universal C99 support, raising broader questions about backward compatibility tradeoffs in the portability effort

The series continues to show test coverage against both Git and libgit2 test suites. Collaboration between Git (Patrick Steinhardt) and libgit2 (Ed Thomson) remains active, with Junio providing architectural guidance, René Scharfe contributing precise technical corrections, and brian m. carlson now questioning the abstraction philosophy for modern compiler features. The maintainer's engagement indicates the series is progressing toward integration after addressing the remaining design considerations, though the new discussion about `inline` may prompt reevaluation of which abstractions truly need platform-neutral treatment in 2026 context. The exchange exemplifies Git's ongoing tension between maximal portability and modernization, with Patrick likely needing to either defend the macro approach's continued value or adjust the series' scope based on this feedback.
