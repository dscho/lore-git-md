Bugfix for `git commit -a` crash during unresolved merges.

Nick Golden reports a reproducible crash in `git commit -a` when there's both an unresolved merge conflict and a deleted tracked file. The command fails with "fatal: unable to stat" when it encounters the deleted file while trying to process rename detection during the commit.

The bug manifests when:
1. Two tracked files have identical content
2. A merge conflict exists on one file
3. The other file is deleted from the working tree
4. `git commit -a` is run

The expected behavior would be for Git to either stage the deletion and stop due to the unresolved merge, or refuse the commit entirely because of the conflict. Instead, it crashes while attempting to stat the deleted file during rename detection. The report includes a detailed reproduction script that reliably triggers the issue on Git 2.53.0 on macOS.

This appears to be a genuine bug in the interaction between the merge state handling and the rename detection logic during `add_files_to_cache()`. The patch seems well-documented with clear reproduction steps and analysis of the likely cause. Given the straightforward reproduction case and the potential for this to affect users during merge conflicts, this would likely be a high-priority fix for the next maintenance release.
