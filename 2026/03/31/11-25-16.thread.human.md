This thread addresses a bug in `git backfill` where it was ignoring sparse-checkout configurations. Trieu Huynh (a GSoC contributor) identified that the command was hardcoding `sparse=0` during initialization, forcing full backfills even in sparse repositories. His patch changes this to use `-1` as a sentinel value, allowing the command to properly respect `core.sparseCheckout` settings when no explicit `--sparse` or `--no-sparse` flag is given.

The fix received initial review from Junio Hamano, who questioned whether the commit message's framing as "auto-detection" was accurate versus simply respecting the config. Derrick Stolee, the original author of the sparse backfill feature, has now confirmed that Trieu's implementation correctly achieves the intended behavior that his own earlier attempt (commit 85127bcdea) had failed to fully realize. Stolee endorsed both the code change and test case, suggesting only a minor commit message update to reference the prior incomplete implementation.

With Stolee's confirmation resolving Junio's question about terminology, the technical discussion appears settled. Trieu is expected to send a final version with the suggested commit message tweak. This is a small but important correction for sparse repository workflows, ensuring `git backfill` behaves as originally designed by properly honoring the sparse-checkout configuration by default.
