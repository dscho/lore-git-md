This is a bugfix patch for the `git backfill` command's handling of sparse-checkout configurations. The patch comes from Trieu Huynh as part of Google Summer of Code (GSoC).

The issue addresses a case where `git backfill` was ignoring the repository's sparse-checkout configuration (core.sparseCheckout) because it was hardcoding the sparse field to 0 (false) during initialization. This meant the command would always perform a full backfill even when sparse-checkout was enabled. The fix changes the initial value to -1 (sentinel value), allowing the command to properly detect and respect the repository's sparse-checkout settings when no explicit `--sparse` or `--no-sparse` flags are provided.

The patch includes a test case in t5620-backfill.sh that verifies the command now correctly auto-detects sparse-checkout from config. The test creates a sparse clone, checks for missing objects, runs backfill, and verifies the expected behavior through trace2 data. The change is small (just one line modified in builtin/backfill.c) but fixes what appears to be an oversight in the original implementation.

This looks like a straightforward and well-motivated fix. The commit message clearly explains the problem and solution, and the test case provides good coverage of the changed behavior. The patch touches only the relevant parts of the codebase and follows Git's coding style. Since this is a GSoC contribution, it's likely part of a larger effort to improve the backfill command, but the patch stands well on its own.
