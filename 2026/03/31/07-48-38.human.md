This is a review response from Patrick Steinhardt on the third patch in Justin Tobler's series to introduce write operations to Git's object database transaction interface. The patch refactors blob writing to packfiles by splitting the hashing and writing operations.

Patrick generally approves the changes but offers several technical observations:

1. He agrees with removing the conditional write flag (INDEX_WRITE_OBJECT) from the transaction interface, noting it would be awkward to have partial write capability in transactions.

2. He suggests minor improvements to the new `hash_blob_stream()` helper:
   - Could potentially accept an object type parameter for future flexibility
   - Recommends cleaner error checking for read operations
   - Notes the benefit of avoiding unnecessary deflation when only hashing

3. Points out some remaining issues that could be addressed later:
   - The code still reaches into files backend internals
   - The transaction commit doesn't return an error code

The review maintains a constructive tone while identifying both immediate improvements and longer-term technical debt. As the primary driver of the ODB abstraction effort, Patrick's feedback carries weight about the architectural direction. His comments suggest this patch is on the right track but leaves some cleanup for future work.
