This is a bugfix patch series addressing incorrect behavior in `receive.denyCurrentBranch=updateInstead` when pushing to bare repositories with worktrees. The fix has now been approved by Junio C Hamano for inclusion in the `next` integration branch, marking the conclusion of this thread.

The issue occurs when pushing to a bare repository that has an associated worktree, where the bare repository's HEAD points to an unborn branch while the worktree itself is clean. Previously, Git would incorrectly reject such pushes. The solution changes the logic in `builtin/receive-pack.c` to examine the worktree's HEAD rather than the bare repository's HEAD when determining if staged changes exist.

The series includes three patches: Runxi Yu's original test case demonstrating the issue, a test infrastructure cleanup from Pablo Sabater to properly handle temporary repositories and worktrees, and the core fix from Sabater that refactors the staged changes detection. Junio notes the fix is "surprisingly small" given the impact, and approves it for merging after careful review.

This represents a clean resolution to an edge case that was well-documented through test cases and carefully addressed with minimal code changes.
