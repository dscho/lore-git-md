Bugfix in the fsmonitor Linux inotify support series, addressing a memory leak in the daemon's client handling code. This is part of the long-running effort to bring Linux fsmonitor support to parity with Windows and macOS.

The patch fixes a case where the `shown` hash table could leak when the fsmonitor daemon sends a trivial response to a client. The fix initializes the hash table to NULL and moves cleanup to a shared exit path, ensuring it's freed in all cases. This is a straightforward cleanup of a minor oversight in the otherwise mature v12 series.

The fsmonitor implementation has been through extensive review and production testing, with this being one of the final polish patches. The series as a whole appears technically sound, with discussion now focused more on process questions (AI-assisted development practices) than implementation concerns.
