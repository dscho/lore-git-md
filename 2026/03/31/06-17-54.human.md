This is a bugfix for the Linux fsmonitor implementation, addressing an interaction between fsmonitor and split-index that was exposed when the fsmonitor daemon became active on Linux. The issue causes test failures in t9210 when GIT_TEST_SPLIT_INDEX is enabled, specifically when the fsmonitor bitmap references positions from a previous index state that don't match the current split-index state.

Paul Tarjan identifies two problematic code paths in fsmonitor.c where assertions and array accesses weren't properly guarded against split-index cases. He provides a fix that adds the necessary checks, noting this builds on previous work that had disabled GIT_TEST_SPLIT_INDEX in t9210 as a temporary workaround. The patch appears well-targeted, addressing only the immediate issue while leaving the broader split-index interaction for a future series.

This comes after Junio Hamano reported the test breakage when the fsmonitor-linux series was merged into 'seen', marking a shift from earlier process concerns to concrete technical debugging. The fix demonstrates the series is now being actively maintained in production-like environments, with Paul reproducing the issue in a Fedora container and verifying the solution. While the core implementation remains sound (having gone through 11 iterations), this shows the value of real-world testing in uncovering edge cases.
