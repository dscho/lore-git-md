This is a refactoring patch from Patrick Steinhardt, part 5/6 in his series standardizing flag handling in the object database (ODB) subsystem. The patch renames the flags for `odb_has_object()` to follow the established convention of prefixing with the function name (`ODB_HAS_OBJECT_*`).

The changes are mechanical but widespread, updating 22 files that use these flags. The two flags being renamed are:
- `HAS_OBJECT_RECHECK_PACKED` -> `ODB_HAS_OBJECT_RECHECK_PACKED`
- `HAS_OBJECT_FETCH_PROMISOR` -> `ODB_HAS_OBJECT_FETCH_PROMISOR`

This continues the pattern seen in earlier patches of the series, bringing consistency to how flags are named across the ODB interface. The changes are purely about code hygiene and don't affect functionality. As with the rest of the series, the patch is well-structured and carefully handles all call sites that use these flags.

The patch touches many parts of Git's codebase that check object existence, including fetch/push operations, ref handling, and object verification. While the diff is large, the changes are straightforward and follow the same pattern throughout. This is another incremental step in Patrick's broader ODB abstraction work to enable pluggable backends.
