This is patch 4/12 in Jeff King's series addressing C23 const-correctness warnings around `strchr()` usage. The patch focuses on the pager subsystem, specifically handling environment variable parsing.

The change explicitly casts away constness when using `strchr()` to find '=' in pager environment variables. While the variables come from `split_cmdline()` (which uses const pointers), the code needs to modify them by writing a NUL terminator. Rather than changing `split_cmdline()`'s interface (which would affect many callers), Peff adds an explicit cast with a comment explaining why it's safe - the strings are actually writable as they come from the `pager_env` variable.

This is a small but thoughtful change that balances type safety with practical needs, typical of Peff's careful approach. The patch is well-explained and fits cleanly into the larger series' goal of making Git C23-compliant while maintaining correct behavior.
