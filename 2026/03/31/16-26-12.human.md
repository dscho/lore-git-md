The Git maintainer Junio C Hamano responds to Giorgos Gasparis's `git whoami` proposal by pointing out that Git already has similar functionality through `git var GIT_AUTHOR_IDENT`. This existing command displays the author identity in a format that includes both name and email, which appears to address the core use case of the proposed `whoami` command.

This brief response suggests the proposal may not be necessary as-is, since equivalent functionality exists through a less-known plumbing command. The thread now hinges on whether the proposed `whoami` would offer meaningful improvements over `git var` in terms of user experience or output formatting. The maintainer's mention of the existing alternative implies the proposal would need to clearly articulate what value it adds beyond what's already available.
