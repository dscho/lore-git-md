This is a platform compatibility patch in Patrick Steinhardt's series to make Git's reftable implementation portable for libgit2. Patch 5/6 introduces memory-mapping abstractions through a new `reftable_mmap` struct and associated functions in the reftable system layer.

The change replaces direct `mmap`/`munmap` calls in the reftable blocksource implementation with wrapper functions that handle the mapping through a new `reftable_mmap` structure. This provides a clean interface for platforms (like Windows) that may need alternative implementations. The patch moves error handling into the new `reftable_mmap()` and `reftable_munmap()` functions while maintaining the same behavior - failed mappings still return `REFTABLE_IO_ERROR`.

Key technical details include:
- New `reftable_mmap` struct to hold mapping state (data pointer, size, and private field for future extension)
- `reftable_mmap()` wrapper that uses Git's existing `xmmap_gently()` internally
- `reftable_munmap()` that cleans up the mapping and zeroes the struct
- Updated blocksource implementation to use the new interface

The change is mechanical and focused, touching only the reftable subsystem. It follows the pattern seen in earlier patches of this series - introducing platform-agnostic interfaces while maintaining identical functionality. This abstraction is particularly important for libgit2 integration since different embedding environments may need custom memory-mapping implementations.
