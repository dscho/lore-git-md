This is patch 7/12 in Jeff King's series addressing C23 const-correctness warnings, specifically targeting the pseudo-merge bitmap subsystem. The patch fixes a const-correctness warning but uncovers a deeper issue with how pseudo-merge commits are read from disk.

The core problem involves `find_pseudo_merge()` returning a non-const pointer to memory-mapped disk data that should be treated as read-only. While fixing the const warning, Jeff discovered the function was also missing necessary byte-swapping when reading the on-disk data. The patch changes the interface to have callers provide a struct that gets properly filled in with byte-swapped values.

Interestingly, Jeff notes this code path isn't exercised by the test suite, suggesting a potential testing gap for the pseudo-merge feature. The changes appear correct but remain somewhat speculative since the affected code isn't currently tested. This is typical of his thorough approach - fixing not just the immediate warning but addressing the architectural issue it revealed.

The patch is part of a larger, carefully constructed series that demonstrates Jeff's deep understanding of Git's internals. While this particular change is narrow in scope, it touches low-level bitmap handling that could affect performance in large repositories.
