This is a bugfix patch in the fsmonitor series that addresses process isolation issues in the daemon startup paths. The patch ensures proper cleanup of inherited file descriptors and process group management when the fsmonitor daemon runs in the background.

The key changes are:
1. Setting `close_fd_above_stderr` in both explicit (`fsmonitor--daemon start`) and implicit (client-triggered) daemon startup paths to prevent inheriting unnecessary file descriptors that could cause hangs
2. Adding `setsid()` call on Unix systems when detaching, to prevent the daemon from being tied to the parent shell's process group
3. Suppressing stdout/stderr on the implicit spawn path to avoid terminal interference

The patch demonstrates careful consideration of edge cases - particularly around CI/test environments where inherited pipes could cause hangs, and shell job control scenarios. It builds on the existing process isolation infrastructure (the `close_fd_above_stderr` flag in `struct child_process`) that was previously established in this series.

This is part of the mature v12 iteration of the fsmonitor Linux support series, which has been production-validated for months. The changes here address subtle but important process management details that complete the cross-platform behavior parity between Linux, Windows and macOS implementations.
