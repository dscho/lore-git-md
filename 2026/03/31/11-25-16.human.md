This is a bugfix for the `git backfill` command's handling of sparse-checkout configurations. The patch comes from Trieu Huynh as part of Google Summer of Code (GSoC).

The issue is that `git backfill` currently ignores the repository's sparse-checkout configuration by default, always performing a full backfill. This happens because the command initializes its `sparse` field to 0 (meaning "not sparse") rather than -1 (meaning "detect from config"). The patch changes this initialization to -1, allowing the command to properly fall back to the repository's core.sparseCheckout setting when no explicit `--sparse` or `--no-sparse` option is given.

The change is small (just one line in builtin/backfill.c) but meaningful for users who rely on sparse-checkout configurations. The patch includes a new test case in t5620-backfill.sh that verifies the command now correctly auto-detects and respects the sparse-checkout setting. The test uses GIT_TRACE2_EVENT to confirm the expected behavior through trace2 data.

This appears to be a straightforward and well-motivated fix. The commit message clearly explains both the problem and solution, and the test case provides good coverage of the changed behavior. The patch targets a relatively new command (`backfill` was introduced in Git 2.42) and improves its integration with sparse-checkout, which has been a focus area for Git development.
