This is patch 4/6 in Justin Tobler's series introducing write operations to Git's object database transaction interface, part of the ongoing ODB abstraction effort. Patrick Steinhardt reviews the optimization that avoids file descriptor seek operations when handling large blobs in packfiles.

The patch replaces the previous approach (which wrote blobs first and rewound if packfile size limits were exceeded) with an upfront size check using the inflated blob size. While this means packfiles may not be filled to their absolute maximum due to compression variability, Patrick agrees this is a reasonable tradeoff given that large blobs (over core.bigFileThreshold) are typically binary files that don't compress well anyway. He notes the change aligns well with the documented expectation that pack.packSizeLimit is "rarely useful" and may increase on-disk size.

Patrick provides detailed line-by-line feedback, approving the overall approach while questioning whether a zero-byte read guard is necessary in the hash update code. He confirms the new logic properly handles edge case where a single blob exceeds the size limit by relying on an existing escape hatch in stream_blob_to_pack(). The review maintains the technical depth expected from a core ODB expert, validating both the immediate changes and their fit with the broader transaction interface work.
