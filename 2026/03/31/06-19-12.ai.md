This is a feature patch in the fsmonitor series implementing Linux support via inotify, bringing it to parity with existing Windows and macOS backends. The patch is part of a mature v12 series that has been production-tested for months.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include:

- Recursive directory watch registration with IN_MASK_CREATE optimization
- Bidirectional hashmap tracking of watch descriptors and paths
- Cookie-based rename correlation with stale detection
- Statfs-based remote filesystem identification (NFS/CIFS/SMB/FUSE)
- Poll loop with 50ms timeout to prevent queue overflows
- Documentation updates covering Linux-specific inotify limits

The patch demonstrates thorough edge case handling, including split-index interactions addressed in previous patches. It completes the cross-platform fsmonitor implementation, with remaining discussion focused on process/acceptance questions rather than technical concerns. The series appears production-ready, having addressed all substantive feedback through 12 iterations.
