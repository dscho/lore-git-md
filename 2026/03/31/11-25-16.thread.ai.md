Subject: [PATCH] backfill: respect sparse-checkout configuration  
Author: Trieu Huynh (GSoC)  
Thread type: Bug fix for `git backfill` sparse-checkout behavior  

Core problem: `git backfill` incorrectly forced full backfills by initializing `ctx.sparse=0`, overriding `core.sparseCheckout` configuration. Patch changes initialization to -1 to properly defer to config when no explicit `--sparse/--no-sparse` flag is given, implementing Derrick Stolee's original design intent from 85127bcdea.  

Current status: Technical resolution reached with consensus from Stolee (original sparse backfill author) and Junio Hamano (maintainer). Trieu will resend with commit message referencing 85127bcdea's incomplete implementation. Test in t5620-backfill.sh verifies correct sparse behavior when config is set.  

Technical details: Changes in builtin/backfill.c replace hardcoded 0 with -1 initialization, allowing proper config reading. The existing code already contained logic to check repository configuration when no command-line override exists - the bug was solely in the initialization value pretending `--no-sparse` was specified. Test verifies via sparse clone creation, missing object checks, and trace2 data.  

Key files: builtin/backfill.c (initialization fix), t/t5620-backfill.sh (verification)  

Participants: Trieu Huynh (author, GSoC), Derrick Stolee (confirmed design intent), Junio Hamano (acknowledged technical resolution). Stolee endorsed solution as correct implementation of his original vision where 85127bcdea had failed to fully achieve this behavior.  

Related work: Part of GSoC effort to improve backfill command. Resolves subtle bug in sparse backfill behavior dating to 85127bcdea. Connects to sparse-checkout subsystem (Stolee, Elijah Newren). Final patch pending documentation reference to original incomplete implementation.
