Subject: [PATCH] backfill: respect sparse-checkout configuration
Author: Trieu Huynh (GSoC)
Thread type: Bug fix for `git backfill` command behavior with sparse-checkout

Core problem: `git backfill` was ignoring repository's sparse-checkout configuration (core.sparseCheckout) due to hardcoding sparse=0 during initialization, causing full backfills regardless of sparse settings. Initial patch changes this to use -1 sentinel value for auto-detection.

Current status: Patch v1 under review. Junio C Hamano questions whether -1 sentinel truly represents auto-detection since code defaults to sparse mode rather than actively detecting sparse status. Junio notes reliance on `get_sparse_checkout_patterns()` being harmless in non-sparse repos, suggesting this might be framed as defaulting to `--sparse` behavior. Derrick Stolee (original sparse backfill author) CC'd for technical input.

Technical details: Changes in builtin/backfill.c replace hardcoded 0 with -1 initialization, allowing sparse-checkout config to take effect when no explicit --sparse/--no-sparse flags given. Test case in t5620-backfill.sh verifies behavior by creating sparse clone, checking missing objects, and examining trace2 data. Test implementation remains uncontested.

Open questions: Whether current -1 sentinel approach accurately represents auto-detection semantics or should be reframed as default sparse behavior. Need clarification from Derrick Stolee on original design expectations for sparse handling in backfill command.
