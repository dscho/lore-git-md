This is the second patch in Patrick Steinhardt's 6-part series improving reftable portability for libgit2 integration. The change removes a direct `fsync()` call from the reftable stack implementation, instead relying entirely on the caller-provided sync callback.

The patch fixes a portability issue where the reftable code was unconditionally calling `fsync()` even when running on platforms that might not support it. Now it only uses the sync mechanism provided via the write options structure, defaulting to a no-op if none was specified. This is a small but important step in making the reftable code truly platform-agnostic.

The change is minimal (just one line modified) and well-contained to the reftable subsystem. It follows the pattern established in the first patch of the series, where system dependencies are abstracted away behind portable interfaces. The patch appears straightforward and low-risk, with no user-visible behavior changes beyond improved portability.
