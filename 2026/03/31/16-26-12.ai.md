Maintainer response to `git whoami` proposal. Junio C Hamano points out that Git already has a built-in way to query author identity through `git var GIT_AUTHOR_IDENT`, which returns a formatted string containing both name and email (along with timestamp). This suggests the requested functionality may already exist in a slightly different form.

The response is characteristically terse but technically precise - Junio identifies an existing mechanism that solves the core use case without requiring a new command. This doesn't necessarily reject the proposal outright, but sets a high bar by showing the problem might already have a solution. Future discussion would need to address whether `git var`'s output format meets user needs or if a dedicated `whoami` command would provide substantially better ergonomics.

The thread now hinges on whether the original proposer can demonstrate meaningful advantages over the existing `git var` approach. Junio's response implies that any implementation would need to justify its addition given the current functionality, likely requiring either a demonstration of widespread user confusion about `git var` or additional use cases that `GIT_AUTHOR_IDENT` doesn't cover.
