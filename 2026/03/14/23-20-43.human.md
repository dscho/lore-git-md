This is a cover letter for a 7-part series improving `git format-patch --commit-list-format` (formerly `--cover-letter-format`). The series comes from Mirko Faina and builds on previous work to enhance how Git formats commit lists in patch series.

The main goals are to:
1. Improve user interaction with the commit list formatting option and its config variable
2. Remove ambiguous uses of the configuration variable that could cause CLI issues
3. Introduce a new format preset for common use cases

The series starts with some preparatory refactoring and error message improvements (patches 1-2), then renames the option to be more accurate (patch 3). Patch 4 tightens up the config variable handling to avoid ambiguity. The later patches (5-7) add new functionality, including a preset format option and support for omitting prefixes.

The changes touch documentation, the pretty-printing code, and the format-patch implementation, with corresponding test updates. This looks like a well-structured series that addresses both technical debt and usability improvements for a niche but useful feature. The patches appear focused and the commit messages provide clear rationale for each change.
