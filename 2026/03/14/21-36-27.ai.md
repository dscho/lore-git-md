This is a follow-up in the long-running thread about recursion depth limitations in `git subtree`. Colin Stagner has prepared a patch series (v2) that aims to address the mutual recursion issue between `process_split_commit()` and `check_parents()` in the shell script implementation. The patch comes several years after Arun Sharma's original report about hitting recursion limits when working with PostgreSQL's large history (52k commits). 

Colin's email serves two purposes: first, checking whether Arun still experiences the issue (suggesting it hasn't been fixed in the interim), and second, requesting testing and review of the proposed solution. The patch series appears to be a fresh attempt at solving the problem, distinct from the 2020 PR #493 that Johannes Schindelin had previously referenced as a potential solution.

This represents progress in the thread by moving from problem identification to a concrete proposed fix. The key technical details remain the same - shell recursion limits affecting large repository operations - but now there's code to evaluate. The patch's effectiveness will depend on whether it properly addresses the mutual recursion while maintaining all existing subtree functionality, particularly for edge cases in large histories like PostgreSQL's.
