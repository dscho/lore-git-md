This is version 4 of a feature patch series that reworks `git checkout -m` to use autostash behavior for branch switching conflicts, following maintainer Junio C Hamano's architectural direction from the thread discussion. The patch replaces the three-way merge implementation in `checkout -m` with autostash-based conflict resolution while maintaining backward compatibility.

Key changes in this version:
- Implements the maintainer's preferred approach of modifying `-m` behavior rather than adding a separate autostash option
- Adds a `checkout_would_clobber_changes()` helper for dry-run conflict detection
- Improves conflict marker labeling to show branch names rather than generic "Updated upstream"/"Stashed changes"
- Makes stash creation silent during checkout to reduce noise
- Updates documentation to reflect the new autostash behavior for `-m`
- Expands test coverage with 18 test cases in t7201-co.sh
- Preserves backward compatibility while changing the underlying mechanism

The implementation builds on existing autostash infrastructure from the sequencer, now used for both explicit `--autostash` and the unified `-m` behavior. The patch touches multiple components including checkout logic, documentation, and test infrastructure, with thorough test coverage of the new unified behavior.

This version addresses Phillip Wood's submodule handling concerns by keeping the existing submodule behavior unchanged. The author has also incorporated Junio's feedback on documentation wording and conflict message presentation. The patch appears well-tested and aligns with the maintainer's architectural vision for improving `checkout -m`.
