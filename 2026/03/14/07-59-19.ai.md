This is part 3 of a 6-patch series implementing responsive design improvements for kernel.org, following Rito Rhymes' earlier work on GitGitGadget and gitweb. The series aims to make kernel.org properly render on mobile devices while preserving the desktop layout.

Patch 3 specifically addresses horizontal overflow issues that occur when the viewport width drops below 848px (the site's existing fixed-width scale). The banner structure becomes too wide at these sizes, forcing horizontal scrolling. The solution introduces a mobile breakpoint at 848px with targeted CSS adjustments to the banner, including:
- Removing side borders and rounding to maximize usable width
- Reducing the Tux gear logo size
- Adjusting heading sizes and list item padding
- The changes are scoped to only affect the banner at mobile widths, with main content and footer fixes coming in later patches
- The implementation follows Rito's established approach of incremental, validated improvements demonstrated in prior Git-related responsive design work
- The patch maintains clear separation between mobile and mobile-specific rules while preserving the desktop layout

This continues the well-structured series that began with viewport meta tag setup (patch 1) and heading line-height fixes (patch 2). The changes are focused on specific rendering issues rather than visual redesign, with each patch building on the last to progressively improve mobile usability. The Git list remains CC'd for continuity, though this is fundamentally a kernel.org infrastructure change.
