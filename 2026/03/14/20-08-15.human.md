This is a follow-up discussion about a previously merged refactoring patch that simplified pluralization in remote.c's branch status messages. Phillip Wood points out a subtle internationalization consideration regarding the original change.

The patch in question had removed Q_() pluralization for diverged branch status, since the code path always deals with plural cases (minimum 2 commits). However, Phillip notes that some languages (like Polish) have complex plural forms where the exact wording depends on the count, even within plural ranges. Using _() without ngettext() would lose this nuance.

The observation doesn't invalidate the original change - the singular case was indeed impossible - but highlights that even when we know we're in a plural context, we might still want the count for proper localization. This is more of a general note about translation best practices than a request to revert the specific change.

The thread shows the project's attention to detail in internationalization, even for small cleanups. Phillip's comment serves as a useful reference for future similar cases, though no action is needed on the already-merged patch.
