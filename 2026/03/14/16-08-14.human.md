This is a follow-up bugfix from Jeff King addressing a memory leak that surfaced after Andrew Au's zombie process cleanup patch was queued. The leak isn't caused by Andrew's changes but was revealed by them - a classic case of one cleanup exposing another latent issue.

Jeff identifies that `transport_color_config()` has been leaking strings from `repo_config_get_string()` since 2018, but the leaks only became detectable with the recent changes to transport helper cleanup. The fix switches to using `repo_config_get_string_tmp()` to avoid allocations for these short-lived config values. 

Interestingly, the leak only manifests under specific conditions (clang + reftable format), showing how subtle such issues can be. Jeff provides thorough analysis of both the fix and the unusual circumstances that made the leak detectable now. The patch is minimal (4-line change) and clearly correct.

While technically unrelated to the zombie process work, this fix logically follows it since the original changes altered the execution patterns that kept the leak hidden. Jeff leaves it to Junio whether to apply this separately or as a follow-on to Andrew's patch. Either way, it's a straightforward improvement that closes a long-standing (if rarely visible) resource leak.
