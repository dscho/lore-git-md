This is a refactoring patch proposing a Coccinelle rule to detect when `struct strbuf` is passed by value rather than by pointer, which is Git's preferred convention.

The patch comes from Deveshi Dwivedi in response to a suggestion by Jeff King during review of an earlier worktree-related fix. The proposed Coccinelle rule would automatically flag functions that incorrectly take `strbuf` parameters by value, transforming them to use pointers in the function signature (though callers would still need manual updating).

The rule already identifies two instances in the codebase:
1. `write_worktree_linking_files()` in worktree.c (already being fixed)
2. `save_untracked_files()` in builtin/stash.c (a new finding)

The approach is consistent with existing strbuf-related Coccinelle rules that similarly enforce coding conventions. The author presents this as an RFC to gather feedback before submitting a formal patch. The change is purely mechanical and doesn't affect runtime behavior - it's about maintaining code consistency and preventing future instances of this anti-pattern.

This appears to be a well-motivated, narrowly-scoped contribution that follows established patterns in the codebase. The patch demonstrates good awareness of Git's conventions and the Coccinelle infrastructure. The two findings suggest the rule would provide real value in catching subtle API misuse.
