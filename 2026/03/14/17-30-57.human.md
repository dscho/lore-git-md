This is a review response from Christian Couder on Lorenzo Pegorari's GSoC proposal about promisor remote fetch ordering. Christian provides technical feedback and suggestions while generally supporting the proposal.

Christian confirms the proposal's technical soundness while offering several clarifications about promisor remote behavior - notably correcting some assumptions about when filters apply during lazy fetching versus initial clone/fetch operations. He suggests considering a simpler config name (`remote.<name>.priority`) and questions whether using `UCHAR_MAX` is appropriate for the priority range, proposing a fixed range like 1-100 instead.

The review highlights one key limitation in the proposal's approach - that global priority settings might not handle per-server priority contexts well - but Christian notes this edge case may not be common enough to warrant the added complexity. He also points out some minor formatting issues in the proposal (stray '$' signs and a truncated sentence).

Overall, Christian's feedback indicates this is a well-conceived proposal from an already-proven contributor (Lorenzo has three merged patches), with some implementation details to refine during the community bonding period. The review maintains a constructive tone while ensuring the technical foundations are solid before the project begins.
