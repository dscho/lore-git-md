This thread is a Google Summer of Code proposal from Siddharth Shrimali to enhance partial clone functionality in Git. The key idea is to add an "un-fetch" capability that would let users reclaim disk space by reverting fetched blobs back to a promised-but-not-present state, something not currently possible without re-cloning.

Shrimali, who has already contributed several test modernization patches, demonstrates solid technical preparation. The proposal carefully addresses how to safely identify removable blobs (those still available from the promisor remote), handle both loose and packed objects (the latter requiring careful repacking), and maintain crash safety through proper write-before-delete ordering. The student has clearly studied the relevant code (backfill.c, promisor-remote.c) and even submitted preparatory patches to the test infrastructure.

The well-structured proposal includes a detailed timeline and shows promising understanding of Git's internals, particularly around the challenges of packed objects and crash safety. This work would complement ongoing efforts around partial clones and the object database abstraction, making it a strong candidate for GSoC selection.
