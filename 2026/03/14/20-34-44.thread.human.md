This thread discusses Siddharth Shrimali's GSoC 2024 proposal to add "un-fetch" functionality for partial clones in Git. The core idea is to allow removing locally-fetched blobs that are still available from promisor remotes, reclaiming disk space without requiring a full re-clone - a capability currently missing in Git.

The technical approach has evolved through discussion with potential mentor Karthik Nayak, now focusing on implementing this as a git maintenance task rather than a backfill option. Key safety mechanisms include write-before-delete ordering to maintain repository consistency during crashes, using OBJECT_INFO_SKIP_FETCH_OBJECT to enumerate blobs without triggering unwanted fetches, and Protocol v2 object-info for remote availability checks. The proposal handles both loose and packed objects while maintaining crash safety.

Siddharth has demonstrated strong technical understanding of Git's promisor machinery through detailed responses to feedback and prior contributions to partial clone test infrastructure. The proposal includes thorough safety considerations and a well-structured timeline with review buffers. This would fill an important gap in partial clone functionality while building on existing infrastructure, making it a promising candidate for GSoC 2024.
