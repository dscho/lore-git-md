Siddharth Shrimali has proposed a Google Summer of Code project to add "un-fetch" functionality for partial clones, which would allow removing locally fetched blobs while keeping them available from promisor remotes. This addresses a current limitation where partial clone fetches are permanent. Siddharth has already studied the relevant code and submitted preparatory test infrastructure patches, demonstrating solid technical preparation.

Karthik Nayak, one of the proposed mentors, has provided detailed technical feedback on the proposal. He agrees with the core safety approach of writing before deleting but raises important questions about blob enumeration in 'blob:none' clones and remote reachability verification. Karthik suggests positioning the functionality as a `git maintenance` task rather than part of backfill operations, given its cleanup nature. His review is constructive and supportive, focusing on implementation details that would strengthen the design.

The proposal shows promise, with the student having done solid preparatory work and now receiving targeted technical guidance from an experienced mentor. The next steps will involve refining the design based on this feedback during the GSoC bonding period. This interaction exemplifies Git's thorough review culture, where even student proposals receive careful technical scrutiny from domain experts.
