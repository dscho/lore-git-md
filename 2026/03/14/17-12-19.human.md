This is a refactoring proposal to detect and help fix incorrect usage of `struct strbuf` being passed by value rather than by pointer.

The patch introduces a Coccinelle semantic patch that identifies functions taking a `struct strbuf` parameter by value and transforms the signature to use a pointer instead. While the transformation alone doesn't produce compilable code (callers and function bodies would need updating), it serves as an effective detection mechanism, similar to other rules in `strbuf.cocci`.

The rule already catches two instances in the codebase:
1. `write_worktree_linking_files()` in worktree.c (already fixed in another series)
2. `save_untracked_files()` in builtin/stash.c, which represents the same class of bug

The author is seeking feedback on whether this would be a worthwhile addition before submitting a formal patch. The approach is technically sound and aligns with Git's existing Coccinelle infrastructure for catching similar anti-patterns. Since `strbuf` is designed to be passed by pointer (to allow for dynamic growth), this rule would help prevent subtle bugs and performance issues.
