This is version 4 of a feature patch series that modifies `git checkout -m` to use autostash behavior for branch switching conflicts, following maintainer Junio C Hamano's direction to prioritize architectural improvements over adding a separate autostash option.

The key changes in this version:
- Fully implements the maintainer's suggested approach of unifying `-m` with autostash behavior rather than adding a new flag
- Adds a `checkout_would_clobber_changes()` helper for dry-run conflict detection
- Improves conflict marker labeling to show branch names rather than generic "Updated upstream"/"Stashed changes"
- Makes stash creation silent during checkout to reduce noise
- Updates documentation to reflect the new unified behavior
- Expands test coverage with 18 test cases in t7201-co.sh

The implementation builds on existing sequencer autostash infrastructure while maintaining backward compatibility. The patch touches multiple components including checkout logic, documentation, and test infrastructure, with particularly thorough test coverage of the new unified behavior.

This version addresses Junio's feedback by:
- Dropping the separate `--autostash` option in favor of enhancing `-m`
- Improving conflict marker labels to show branch context
- Making stash creation silent during checkout operations
- Updating documentation to clearly explain the new behavior
- The submodule handling issue raised by Phillip Wood remains unresolved and will need to be addressed separately

The patch represents a significant architectural improvement to conflict handling during branch switching, though the original use case that motivated the separate autostash option may now need to be handled via aliases or other means.
