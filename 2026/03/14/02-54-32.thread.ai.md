GSoC proposal from Mansi Singh to enhance `git repo structure` with repository analysis metrics, building on prior small contributions to the codebase. The command currently lacks functionality compared to `git-sizer` in three areas: object size metrics, history structure analysis, and checkout size statistics. Karthik Nayak's review notes overlapping prior work by Lucas Seiki Oshiro and eslam reda on related functionality that hasn't been merged, particularly around path handling (relative vs absolute paths) with unresolved discussions involving brian m. carlson. Karthik also mentions unaddressed discussions about histogram metrics that could extend the proposal's scope. The phased implementation plan starts with tracking maximum object sizes, then adds commit graph traversal for history depth metrics, and finally extends path analysis for checkout statistics. A stretch goal aligns with the ongoing `the_repository` removal effort by eliminating global state usage. The review suggests Mansi will need to engage with existing discussions about path handling and metrics format during implementation. The proposal demonstrates familiarity with Git's codebase through prior test improvements and cleanup patches related to the `repo` command, and Karthik's feedback generally supports the direction while highlighting technical discussions to resolve. The work would expand Git's built-in capabilities for analyzing repository characteristics, particularly useful for large repositories.
