Thread identity: GSoC proposal from Siddharth Shrimali to add "un-fetch" functionality for partial clones, allowing blobs to be moved back to promised-but-not-present state to reclaim disk space.

Core problem: Currently, partial clones fetch blobs permanently with no built-in way to remove them later. The proposal aims to safely identify and remove blobs that are still available from promisor remotes, handling both loose and packed objects while maintaining crash safety.

Technical approach: Would modify backfill.c and promisor-remote.c to implement write-before-delete ordering, repacking with exclusions for packed objects, and safety checks. Student has already studied relevant code and submitted test infrastructure patches.

Current status: Proposal stage for GSoC 2024. Student has demonstrated mailing list competence through prior accepted patches (test modernization). Technical approach shows good understanding of Git internals and partial clone challenges.

Participant positions: Siddharth Shrimali (author) has shown preparatory work and technical competence. No other participants yet as this is a new proposal.

Related work: Complements ongoing partial clone improvements and object database abstraction efforts. Builds on existing promisor-remote infrastructure.
