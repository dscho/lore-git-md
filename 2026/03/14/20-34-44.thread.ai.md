Thread identity: GSoC proposal from Siddharth Shrimali to add "un-fetch" functionality for partial clones, allowing blobs to be moved back to promised-but-not-present state to reclaim disk space.

Core problem: Partial clones currently fetch blobs permanently with no built-in way to remove them later. The proposal aims to safely identify and remove blobs that are still available from promisor remotes while maintaining crash safety and handling both loose and packed objects.

Technical approach: Modifying backfill.c and promisor-remote.c to implement write-before-delete ordering, repacking with exclusions for packed objects, and safety checks. Uses OBJECT_INFO_SKIP_FETCH_OBJECT for blob enumeration in 'blob:none' clones to avoid triggering lazy-fetches during walk, and requires Protocol v2 object-info for remote availability verification. The functionality will be implemented as a git maintenance task rather than backfill option per Karthik's suggestion, as this better matches the housekeeping use case.
