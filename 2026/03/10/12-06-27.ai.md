This is part 6 of an 8-patch series refactoring repository-specific global variables into `struct repo_config_values`, continuing the project's effort to reduce global state and improve repository isolation. The series relocates various environment-related globals into per-repository storage.

The current patch moves `core_sparse_checkout_cone` from a global variable to the repository-specific struct. This setting controls whether sparse checkout uses cone mode patterns (a more restrictive but faster pattern matching approach). The change follows the established pattern of the series: removing the global from environment.h/c, adding it to the repository struct, and updating all call sites (6 files) to access it through `the_repository`.

The patch touches core sparse checkout functionality in builtin/mv.c, builtin/sparse-checkout.c, dir.c, and sparse-index.c, along with the environment.h/c plumbing. The conversion is mechanical but thorough, preserving all existing behavior while eliminating potential cross-repository state leakage. Like previous patches in the series, this helps enable proper isolation when multiple repositories are active simultaneously, important for library-style usage.

The work builds on prior infrastructure introducing `repo_config_values` and aligns with René Scharfe's ongoing `the_repository` elimination effort. While straightforward, the change demonstrates good attention to detail in updating all relevant call sites. The patch maintains the series' pattern of small, focused diffs that methodically chip away at global state.
