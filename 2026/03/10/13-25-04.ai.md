This is part of Patrick Steinhardt's performance optimization series (v3 08/10) addressing lock contention in `git-upload-pack`. The patch introduces a new `hashfd_ext()` function in `csum-file.c` that generalizes the existing hashfile creation interface with an options structure, replacing the internal `hashfd_internal()` helper.

The new function accepts a `struct hashfd_options` containing progress reporting and buffer length configuration, providing a more flexible foundation than the current split between `hashfd()` and `hashfd_throughput()`. The patch maintains existing behavior by converting both functions to use the new interface - `hashfd()` keeps its 128KB buffer while `hashfd_throughput()` retains its 8KB buffer for more frequent progress updates.

This change appears to be preparatory work for further optimizations in the series, likely enabling more sophisticated buffer management strategies. The implementation is clean and maintains backward compatibility while providing room for future extension. As with the rest of the series, this shows careful attention to both performance characteristics and maintainability.
