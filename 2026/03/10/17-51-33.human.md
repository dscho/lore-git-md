This is a review response from Junio C Hamano on Patrick Steinhardt's ODB abstraction series, specifically addressing patch 5/6 which introduces generic object counting interfaces. The patch is part of the ongoing effort to make Git's object database backend pluggable.

Junio notes that the design choice to ignore loose objects when approximating counts (inherited from pre-abstraction code) remains valid, but suggests an alternative approach: even in approximate mode, we could cheaply include a rough count of loose objects by sampling one shard directory (as the new implementation already does) rather than skipping them entirely. He acknowledges this might have tradeoffs Patrick has already considered.

The maintainer indicates the patch is ready to merge ("Queued"), marking this as the likely conclusion of the technical discussion on this part of the series. This follows Junio's earlier review of the loose object counting implementation in patch 3/6, where he observed the new code does slightly more work in some cases by always scanning a full shard directory rather than stopping early when exceeding GC thresholds.

The series as a whole represents a significant step in the ODB abstraction effort, moving object counting functionality into properly abstracted interfaces while preserving existing behavior. With Junio's approval, this patch appears set to proceed to integration.
