This is a follow-up discussion in Patrick Steinhardt's ongoing object database (ODB) abstraction series, responding to Junio Hamano's design question about callback contracts in the pluggable ODB interface.

Patrick acknowledges Junio's concern about undefined behavior when future backends omit certain operations, agreeing that clearer documentation of mandatory vs optional callbacks will be needed as alternative backends are developed. He notes that currently all callbacks are effectively mandatory since the files backend implements everything, but expects this to change with upcoming patches converting existing sources to proper ODB backends.

The exchange reveals an important architectural consideration that wasn't fully addressed during the initial review period - while the technical implementation is sound and the series has already been merged to 'next', there's now recognition that the interface contract needs more explicit documentation as the abstraction matures. Patrick indicates he'll address this in future work rather than holding up the current series, suggesting this is more about forward-compatibility than an immediate issue.

This response maintains the high technical quality seen throughout the series while pragmatically deferring the interface documentation question until concrete needs emerge from actual backend implementations. The thread shows how even well-reviewed large-scale refactorings can surface new architectural considerations late in the process, and how the project handles such cases when they don't block immediate work.
