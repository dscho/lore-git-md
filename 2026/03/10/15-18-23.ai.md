This is the third patch in Patrick Steinhardt's six-part series continuing the ODB (object database) abstraction effort. The patch moves the loose object counting logic from `builtin/gc.c` to `object-file.c` as part of preparing for pluggable ODB backends.

The change extracts the existing heuristic for approximating loose object counts (which checks one shard directory and multiplies by 256) into a new `odb_source_loose_approximate_object_count()` function. This follows the pattern of previous ODB abstraction work by moving implementation details into the ODB layer while maintaining identical behavior. The patch touches core object storage files (`object-file.c/h`) and updates the GC's auto-repack threshold check to use the new API.

The commit message clearly explains the motivation - this is groundwork for future changes that will introduce object counting at the ODB source level. The implementation is careful to preserve error handling and the existing counting semantics. This continues the series' focus on internal refactoring without user-visible changes, maintaining backward compatibility while making the codebase more modular for future ODB backends.
