Refactoring of Git's parse-options subcommand handling. This is the first patch in Jiamu Sun's v3 series implementing subcommand autocorrection support.

The patch extracts subcommand parsing logic from `parse_options_step()` into a new `handle_subcommand()` helper function and simplifies the return value of `parse_subcommand()` to a basic success/failure boolean. The changes improve code organization by:

1. Moving subcommand-specific logic out of the main option parsing flow
2. Replacing the enum-based return from `parse_subcommand()` with a simpler 0/-1 scheme
3. Consolidating error handling for unknown subcommands in one place

The diff shows mechanical restructuring with no behavior changes - the existing test coverage continues to pass. This is foundational work for the autocorrection feature that follows in later patches. The changes align with the series' goal of making subcommand handling more maintainable while preparing for new functionality.

Key technical details:
- New `handle_subcommand()` function centralizes subcommand logic
- `parse_subcommand()` now returns simple `0` (success) or `-1` (failure)
- All existing subcommand behavior preserved (error messages, optional subcommands)
- Part of larger effort to enable "did you mean" suggestions for mistyped subcommands

The patch has already addressed Junio Hamano's feedback from previous rounds, including style fixes and proper separation of concerns. It appears ready for inclusion as the first step in the autocorrection series.
