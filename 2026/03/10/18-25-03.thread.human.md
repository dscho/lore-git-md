Lorenzo Pegorari has proposed a Google Summer of Code project to improve how Git handles fetch ordering for promisor remotes in partial clones. Currently, Git tries remotes in config file order without any prioritization. Lorenzo's proposal would add both client-side configuration (`remote.<name>.promisorPriority`) and server-side priority advertisement to let users control which remotes are tried first when fetching missing objects.

Christian Couder has reviewed the proposal and provided constructive technical feedback. He suggests simplifying the configuration name to just `priority` and recommends against using `UCHAR_MAX` due to portability concerns, proposing a fixed 1-100 range instead. Christian also clarifies that lazy fetch behavior depends on filters rather than server object availability, and agrees that global priorities would be more practical than per-server contexts in most cases. 

The discussion shows Lorenzo has done solid preparatory work, with Christian helping refine the implementation details. Lorenzo has already contributed three related patches (two merged), demonstrating his understanding of the partial clone machinery. The project is well-scoped to benefit users managing multiple promisor remotes, and the feedback is moving it toward a robust design.
