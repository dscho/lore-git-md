Bugfix patch addressing argument parsing in `git apply -p`, now at version 2 with test improvements pending. This is a follow-up to maintainer feedback on the initial submission.

The patch replaces unsafe `atoi()` usage in `apply.c` with proper validation via `strtol_i()`, fixing silent acceptance of malformed inputs like "1q" (treated as "1") and non-numeric strings (treated as 0). The technical implementation is sound and maintains backward compatibility with valid numeric arguments while rejecting invalid ones.

In response to Junio C Hamano's review, Mirko Faina will make several test improvements in the next version: moving tests to the more appropriate `t4120` file, using `test_path_is_dir` for clearer assertions, and adding cleanup code with `rm -rf` to prevent test pollution. The test cases cover valid numeric input, malformed numeric input, non-numeric input, and negative numbers, using a new test patch file in `t4103/patch`.

This follows a similar prior fix for the `-j` option parsing (commit 8f0a265). While the current version's technical approach has been approved as "great" by Junio, the remaining test improvements are minor and non-blocking. The fix applies to all `-p` usage, not just binary patches as initially suggested in the test placement.
