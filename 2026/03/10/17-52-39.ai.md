Build system improvement preparing for Meson precompiled headers. This is patch 6/8 in Patrick Steinhardt's series that both reorganizes build tooling and adds PCH support.

The patch addresses a technical challenge in making `git-compat-util.h` work with precompiled headers (PCH). Currently, sign-compare warnings are disabled via a pragma inside the header's include guards, which won't work with PCH since the pragma would be compiled before knowing if the warning should be disabled. The solution moves the warning suppression code outside the include guards, maintaining functionality while enabling PCH support.

This is a mechanical change that doesn't affect behavior - it's groundwork for the actual PCH implementation coming in patches 7-8. The commit message explains the tradeoff between this approach and a more flexible (but churn-heavy) alternative of having callers explicitly disable warnings after including the header.

The change touches a fundamental header (`git-compat-util.h`) that's included nearly everywhere, but the risk appears low since it's just moving existing code rather than modifying logic. Reviewers will want to verify this doesn't introduce any warning-related regressions across platforms, particularly on compilers where sign-compare warnings matter. The patch maintains the series' focus on build performance (with PCHs promising ~30% faster compiles) while being careful not to break existing warning behavior.
