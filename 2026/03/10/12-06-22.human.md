This is part of a refactoring series moving repository-specific configuration into `struct repo_config_values`, continuing the project's broader effort to reduce global state. The first patch relocates the `trust_ctime` setting (which controls whether Git checks file ctime changes) from a global variable to per-repository storage.

The change is mechanical but meaningful - it ensures each repository maintains its own `core.trustctime` setting rather than sharing a single global value. The patch updates three files: removing the global declaration, initializing the new struct field, and modifying the stat comparison logic to read from the repository's config. While the behavior remains identical for now, this enables future work where different repositories might need different settings.

The patch follows the established pattern for these migrations and appears well-scoped, touching only the necessary call sites. As the first in an 8-part series, it sets up the template for similar moves of other configuration variables. The commit message clearly explains the motivation and maintains the project's preference for small, focused changes.
