Patrick Steinhardt's ongoing ODB abstraction work has reached the object counting functionality, with this thread focusing on how Git estimates the number of objects in a repository. The six-part series restructures the counting logic to support pluggable backends, moving packed object counting to packfile.c and loose object counting to object-file.c.

Junio C Hamano has been actively reviewing the changes, particularly noting the performance/accuracy tradeoff in the new loose object counting implementation. The current approach samples one shard directory (number 17) and extrapolates by multiplying by 256, rather than the previous method that could stop early when exceeding GC thresholds. While this provides more consistent counting, Junio suggested including loose objects in approximate counts might offer better accuracy with minimal overhead.

Toon Claes provided detailed technical review of both the packed and loose counting implementations. For packed objects, he verified correct handling of MIDX files to avoid double-counting. His latest review examines the loose object sampling approach, noting that while the multiplication could theoretically approach ULONG_MAX, practical filesystem limitations make this a non-issue. The reviews collectively validate the technical soundness of the changes.

The series is currently at version 1, with Junio having queued it for integration. The loose counting tradeoff remains an open but non-blocking consideration. When complete, this work will replace repo_approximate_object_count() with new odb_count_objects() APIs, marking another step toward full ODB abstraction while maintaining existing behavior for most use cases.
