Patrick Steinhardt's patch series is nearing completion of the object database (ODB) abstraction work, specifically focusing on object counting functionality. The current discussion centers on patch 5/6, which introduces new APIs (`odb_source_count_objects()` and `odb_count_objects()`) to replace the existing `repo_approximate_object_count()`.

Junio Hamano, the maintainer, raised an interesting point about whether to include loose object counts even in approximate mode. While the new implementation already scans one full shard directory (for performance reasons), Junio notes this could provide more accurate counts with minimal additional cost. Patrick acknowledges this tradeoff but has chosen to maintain the current behavior where approximate counts ignore loose objects, though he sees no technical barrier to changing this.

The series has progressed through careful review, with Justin Tobler contributing to earlier header cleanup work. Junio has indicated the technical soundness of the approach, with the loose-counting question remaining as an open but non-blocking consideration. The changes maintain existing caching behavior while properly abstracting the counting functionality across multiple files (object-file.c, odb/source-files.c, and related headers).

This penultimate patch sets the stage for the final API switch in patch 6/6, completing this phase of the ODB abstraction effort. The work remains on track for integration, paving the way for future pluggable backends while preserving Git's internal object counting semantics.
