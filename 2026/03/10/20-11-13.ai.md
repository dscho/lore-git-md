This is the third version of a three-patch series adding a `re-sign-if-invalid` mode to `git fast-import`'s signature handling, building on previous work that added `strip-if-invalid` mode. The series is now complete with all feedback addressed from previous rounds.

The core change introduces a new mode that allows `git fast-import` to re-sign commits with invalid signatures rather than just stripping them. The implementation builds on shared signing infrastructure moved to gpg-interface.c in patch 2, and includes support for specifying a key ID (`re-sign-if-invalid[=<keyid>]`) matching `git commit --gpg-sign` syntax.

Key technical points in this version:
- Renamed `SIGN_RESIGN_IF_INVALID` to `SIGN_RE_SIGN_IF_INVALID` per feedback
- Extracted warning message handling into a separate helper function
- Explicitly fails when attempting to use the feature with `extensions.compatObjectFormat` (with NEEDSWORK comment about future support)
- Comprehensive test coverage for OpenPGP/X.509/SSH signatures
- Conservative experimental feature handling

The series has evolved through multiple rounds of review with Christian Couder (original author of the cleanup patch) and Patrick Steinhardt providing feedback. All v1 and v2 feedback has been addressed, including improved warnings, function renaming, expanded tests, and explicit interoperability failure handling. The implementation is clean and well-tested, though tag signature support remains for future work.
