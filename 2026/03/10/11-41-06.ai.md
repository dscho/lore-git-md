This is the final patch in Jiamu Sun's series adding subcommand autocorrection to Git's parse-options API, now at v3. The patch enables autocorrection for `git-remote` and `git-notes` by adding the new `PARSE_OPT_SUBCOMMAND_AUTOCORR` flag to their parse-options calls.

The change removes manual error handling for unknown subcommands from these commands, letting the parse-options infrastructure handle mistyped subcommands through the autocorrection system implemented in earlier patches. The implementation is safe for these commands because they either resolve to a single subcommand or take no subcommand at all - any unknown argument must be a mistyped subcommand.

Key technical details:
- Adds new `PARSE_OPT_SUBCOMMAND_AUTOCORR` flag in parse-options.h
- Modifies parse-options.c to only skip autocorrection when both SUBCOMMAND_OPTIONAL is set and SUBCOMMAND_AUTOCORR is not
- Simplifies builtin/notes.c and builtin/remote.c by removing their custom error handling
- Maintains all existing behavior while centralizing the autocorrection logic

The patch demonstrates the series theme of moving subcommand handling into the parse-options infrastructure while maintaining backward compatibility. With this change, the autocorrection feature is fully integrated for these two commands, completing the practical application of the infrastructure work done in previous patches.
