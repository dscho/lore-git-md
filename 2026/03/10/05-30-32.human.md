This is a documentation patch clarifying the behavior of `git show -U` when used without a line count argument. The patch updates two man pages to explicitly state that bare `-U` (without `<n>`) is accepted as a legacy behavior, defaulting to 3 lines of context like `-p` does.

The change follows discussion where Junio C Hamano noted this lenient parsing must be preserved for backward compatibility, particularly since test 157 in t4013 depends on it. Tian Yuchen's initial proposal evolved through review feedback from D. Ben Knoble to frame this as a historical accident rather than an intentional feature.

The documentation now clearly explains the default context behavior applies both when `<n>` is omitted and when the config is unset. While the patch addresses the immediate need, some stylistic suggestions from Knoble about using `--unified[=<n>]` syntax and further clarifying the default value application remain open for potential follow-up.

This is a straightforward documentation improvement that brings the man pages in line with long-standing behavior, reducing potential confusion for users who might otherwise assume `-U` requires an argument. The patch is well-contained and uncontroversial, with the core issue already vetted in the thread.
