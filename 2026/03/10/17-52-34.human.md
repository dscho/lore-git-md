This is the first patch in an 8-part series introducing build system improvements. Patrick Steinhardt proposes creating a new `tools/` directory to house build-related scripts that currently live in various locations (including `contrib/`), arguing these are core development tools rather than optional extras. The patch is purely organizational at this stage - it adds the directory skeleton and updates build system exclusions, but doesn't yet move any actual tools.

The change is straightforward and uncontroversial in isolation, though it sets up for more substantive follow-on patches that will relocate existing scripts. The motivation is sound - having build tools scattered between `contrib/`, `Documentation/` and `t/` is indeed messy. The patch touches both Makefile and Meson build systems, showing the change is being implemented consistently across build methods.

This appears to be a well-considered first step in a larger cleanup effort. The commit message clearly explains the rationale and what to expect in subsequent patches. Build system experts like D. Ben Knoble and Johannes Schindelin will likely want to review the full series once all tool relocations are shown.
