This is part 3 of an 8-patch series moving repository-specific configuration variables into `struct repo_config_values`, continuing the project's effort to reduce global state. The patch relocates the `zlib_compression_level` global variable into per-repository storage.

The change moves the zlib compression level setting (used when compressing Git objects) from a process-wide global to repository-specific storage in `repo_config_values`. This prevents cross-repository state leakage when multiple repositories are active in the same process. The patch updates all call sites that initialize zlib streams to use the repository-specific value instead of the global, maintaining identical behavior while improving isolation.

The diff touches 6 files, with mechanical changes to replace `zlib_compression_level` with `cfg->zlib_compression_level` where `cfg` is obtained from `the_repository`. The initialization value (Z_BEST_SPEED) is preserved in `repo_config_values_init()`. Like the previous patches in the series, this follows the established approach for migrating globals to repository-specific storage, though the commit message could better explain why compression level specifically benefits from being repository-specific rather than process-wide.
