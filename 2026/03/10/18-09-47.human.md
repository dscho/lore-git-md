This is the final patch in a three-part series adding re-signing capability to `git fast-import` for invalid commit signatures. The series has already been merged, with this email capturing some final review feedback from Christian Couder on naming consistency and warning message handling.

The patch implements the core functionality for the new `re-sign-if-invalid[=<keyid>]` mode, allowing `fast-import` to replace invalid signatures with fresh ones using a specified key. Christian suggests two improvements: using "RE_SIGN" instead of "RESIGN" for enum naming consistency, and factoring out the warning message logic to avoid duplication. Justin Tobler (the implementer) agrees with both points and indicates these will be addressed in a follow-up version.

The discussion here is purely about polish - the technical approach and implementation have already been vetted through earlier rounds of review. The changes are straightforward and unlikely to be controversial, focused on code organization rather than behavior.
