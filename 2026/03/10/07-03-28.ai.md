Performance optimization patch for `builtin/help.c`'s part of the `git help` command's config listing functionality. The patch moves a `strbuf` declaration outside of loops where it was previously being repeatedly allocated and freed, instead reusing the same buffer with `strbuf_reset()`.

The change affects how `list_config_help()` handles configuration variable names when displaying help output. The original code created and destroyed a `strbuf` in each iteration of two nested loops, which the author notes caused unnecessary heap pressure. The new version maintains a single buffer throughout the function's execution.

The patch also incidentally fixes a minor memory leak in the `SHOW_CONFIG_HUMAN` case where a `continue` statement would skip the buffer cleanup. The change is straightforward - just 4 lines removed and 3 added - but touches performance-sensitive code paths in the help system. The commit message clearly explains both the performance rationale and the leak fix.
