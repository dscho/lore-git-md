This is the final patch in a three-part series adding a `re-sign-if-invalid` mode to `git fast-import`'s signature handling. The feature allows invalid commit signatures to be replaced with new signatures during import, complementing the `strip-if-invalid` mode that simply removes them.

The patch introduces the new mode with optional key specification (`re-sign-if-invalid[=<keyid>]`), matching `git commit --gpg-sign` syntax. When enabled, invalid signatures are detected via the existing in `gpg-interface.c` and replaced using the new `sign_buffer_with_key()` helper (extracted from commit.c in an earlier patch). The implementation includes comprehensive test coverage for OpenPGP, X.509, and SSH signatures, plus a test case for explicit key specification.

Key technical points:
- New `SIGN_RE_SIGN_IF_INVALID` enum value
- Updated `handle_signature_if_invalid()` to handle both strip and re-sign modes
- Dedicated warning message helper function extracted post-merge
- Explicit failure for `extensions.compatObjectFormat` with NEEDSWORK comment
- Conservative experimental feature handling

The patch builds on the preparatory refactoring from earlier in the series and has been reviewed by Christian Couder and Patrick Steinhardt. It represents the completion of the core functionality, though future work may add tag signature support and interoperability mode handling. The implementation is clean and well-tested, with clear documentation of current limitations.
