This is a feature patch in the final iteration (v7) of a series adding configurable cover letter formatting to `git format-patch`. The thread context shows this is a mature proposal that has undergone extensive review and is now in its final polishing stage.

Junio C Hamano weighs in on the config behavior design, suggesting an alternative approach to handling empty vs unset values for the new `format.commitListFormat` config option. He proposes treating boolean values specially: `false` would revert to shortlog format, `true` would use the modern default format ("log:[%c/%t] %s"), and any other string would be treated as a custom format specifier (either "shortlog" or a "log:"-prefixed format). This would make the config behavior more intuitive when using `-c` to set values.

The patch itself (4/5 in the series) implements the config option with the current behavior where:
- Unset: defaults to shortlog
- Set but empty: uses default format ("log:[%(count)/%(total)] %s")
- Set to "shortlog": uses shortlog format
- Set to any other string: uses that format specifier (must be "shortlog" or "log:"-prefixed)

The implementation includes comprehensive tests verifying all these cases. The discussion indicates this is the final substantive design question before merging, with Junio providing maintainer guidance on the preferred config behavior pattern. The author (Mirko Faina) will likely incorporate this feedback in a final version before the series is merged.
