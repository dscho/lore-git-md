This is part 5/8 of Jiamu Sun's series adding subcommand autocorrection support to Git's parse-options API. The patch focuses on improving the config resolution for autocorrect functionality.

The key changes in this patch:
- Introduces a new `autocorr_resolve()` API that handles config resolution internally, hiding the callback implementation details
- Makes the config callback `resolve_autocorr()` static since it's now an implementation detail
- Separates the alias resolution from autocorrect config handling in `help.c` by using two distinct config callbacks
- Maintains all existing behavior while improving code organization

The patch continues the architectural improvements from earlier in the series by further separating concerns - autocorrect config handling is now fully encapsulated within autocorrect.c, with a clean public API. The split from alias resolution in help.c makes the code paths more focused and easier to reason about.

The implementation looks clean and well-motivated, following through on the modularization approach established in earlier patches. The use of `the_repository` is noted (via the explicit `#define`) as part of the ongoing effort to eventually remove this global.
