This is a follow-up discussion in the completed `git fast-import` signature handling series, focusing on future extension possibilities. Justin Tobler (the implementer) and Junio C Hamano are exploring additional signing modes that could build on the recently merged infrastructure.

The conversation centers around two potential enhancements:
1. A new `--sign-commits=all` mode that would sign all rewritten objects (including previously unsigned ones), extending beyond the current capability which only re-signs invalid signatures
2. A planned `--abort-if-invalid` mode that would stop processing upon encountering invalid signatures

The technical foundation for these extensions is already in place from the v2 series, which:
- Moved commit signing logic to `gpg-interface.c` as the reusable `sign_buffer_with_key()`
- Added the `sign-if-invalid[=<keyid>]` mode with comprehensive test coverage
- Established clear separation between signature creation and stripping concerns

Junio notes the natural progression from the current re-signing capability to a more general signing facility, while Justin confirms these directions align with his planned follow-up work. The discussion remains at the conceptual level, with no immediate patches proposed - this is post-merge planning for how to evolve the feature based on the now-merged infrastructure.
