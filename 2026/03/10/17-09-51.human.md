This is a performance optimization patch in Patrick Steinhardt's series addressing lock contention in `git-upload-pack`. The patch focuses on improving keepalive handling when buffering data for transmission to clients.

The change makes `upload-pack` prioritize flushing buffered data over sending empty keepalive packets when the keepalive timeout is reached. This is a sensible optimization since sending actual data serves the same keepalive purpose while making progress. The patch maintains the existing behavior when no buffered data is available, falling back to traditional empty keepalive packets.

The implementation carefully preserves the last byte of buffered data to maintain pktline framing, showing attention to protocol details. Junio C Hamano has reviewed the change and confirmed its correctness, noting it matches the described behavior in the commit message.

This is one of several optimizations in the series that together reduce write syscalls during high-concurrency operations from ~400k to ~44k when cloning the Linux repository. While this particular change may not yield dramatic gains (as Patrick notes most keepalives occur before pack data starts), it's a clean improvement that fits well with the series' overall goal of reducing kernel lock contention.
