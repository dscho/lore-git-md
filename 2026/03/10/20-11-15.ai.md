This is a refactoring patch that moves signing logic from commit-specific code to a more general location in preparation for the `git fast-import` re-signing feature. It's part of a completed series that added `re-sign-if-invalid` mode to handle invalid commit signatures during import.

The patch extracts the `sign_commit_to_strbuf()` helper from commit.c, renames it to the more generic `sign_buffer_with_key()`, and moves it to gpg-interface.c where it can be shared. The new function maintains the same behavior of falling back to the default signing key when none is specified. All existing callers in commit.c are updated to use the new shared implementation.

This is a straightforward code reorganization that follows Git's standard pattern of moving shared functionality to common locations. The change is well-contained with minimal churn - just moving and renaming code while preserving all existing behavior. The patch builds on previous work in the series that established the signing infrastructure and will be followed by the final patch implementing the actual re-signing feature in fast-import.
