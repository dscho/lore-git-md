This is a follow-up comment on the ongoing GSOC microproject to add `ADVICE_STASH_BEFORE_CHECKOUT` advice for uncommitted changes during branch switches. Patrick Steinhardt notes that while the patch adds the new advice infrastructure (enum in `advice.h`, config support, and a function prototype in `advice.c`), it doesn't actually call the new function anywhere in the codebase. This appears to be an oversight in the v2 submission - the advice is defined but never triggered.

The thread context shows this is part of a well-scoped effort that has already addressed several review comments from Phillip Wood in previous iterations. The current version splits unrelated commits and follows Git's conventions for advice messages, though it still needs to incorporate the recommendation to prioritize `git checkout -m` over stashing (planned for v3). Patrick's observation about the missing call site is a new technical point that will need to be addressed in the next revision.

The patch remains focused and follows the project's patterns, but this gap means the current version doesn't yet provide the intended user-facing behavior. The author will need to identify where in the checkout workflow this advice should be shown (likely in `builtin/checkout.c` when detecting dirty files) and add the appropriate call. This is a straightforward fix that aligns with the thread's productive collaboration pattern.
