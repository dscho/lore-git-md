This is a documentation patch addressing the behavior of `git diff -U` without a number argument. The thread has established that while `-1.0.0` accidentally accepted `-U` without a number (defaulting to 3 lines of context like `-p`), this behavior should be documented as a historical accident rather than an intentional feature.

Tian Yuchen initially proposed documenting `-U[<n>]` as an optional argument, but Junio Hamano pushed back, arguing this would encourage a behavior that was never meant to be supported. The consensus now is to explicitly note the bare `-U` case as legacy behavior while keeping the primary documentation focused on the proper `-U<n>` and `--unified=<n>` forms.

The patch will update `diff-options.adoc` and `diff-context-options.adoc` to clarify that while `-U` without a number works (for backward compatibility with test 157 in t4013), it should not be considered a supported usage pattern. D. Ben Knoble's earlier suggestions about aligning the documentation with Git's standard `--option[=<value>]` syntax and clarifying the default value behavior remain outstanding but may be addressed in a follow-up.

Key technical points for future reference:
- The default 3-line context matches `-p` behavior
- Test 157 in t4013 depends on current lenient parsing
- Documentation will now explicitly call out bare `-U` as legacy
- `--unified=<n>` remains the canonical long form
