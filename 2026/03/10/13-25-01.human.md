This is a platform compatibility patch in Patrick Steinhardt's ongoing series to reduce lock contention in `git-upload-pack`. It introduces a `writev()` compatibility layer for systems that don't natively support the POSIX syscall, particularly Windows.

The patch adds a fallback implementation of `writev()` that:
- Handles the same interface as POSIX writev (scatter/gather I/O)
- Properly checks for `ssize_t` overflow per POSIX specs
- Falls back to sequential `xwrite()` calls when needed
- Is automatically enabled on Windows builds via `config.mak.uname`

This is groundwork for the series' main optimization - using `writev()` to batch writes and reduce syscall overhead in high-concurrency scenarios. The implementation is careful to maintain POSIX semantics while providing Windows compatibility, continuing the series' attention to cross-platform concerns. The patch follows Git's standard pattern for platform compatibility shims, similar to existing wrappers` like `pread()`.
