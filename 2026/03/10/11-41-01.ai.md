This is part of Jiamu Sun's ongoing series to add subcommand autocorrection support to Git's parse-options API, now at v3. The patch moves autocorrect handling from help.c to new files autocorrect.{c,h} to make the functionality reusable across commands that don't link against git.o (like git-daemon).

Key changes:
- Extracts config parsing and prompt/delay handling into standalone autocorrect.c
- Defines public API in autocorrect.h with constants for autocorrect modes
- Preserves all existing behavior while improving modularity
- Splits the changes from v2 to make diffs clearer

The refactoring enables future patches to use autocorrection for subcommands without help.c dependencies. The implementation shows careful attention to maintainer feedback from previous rounds, with clean separation of concerns and thorough test coverage. The series appears technically sound and well-prepared for maintainer consideration.
