First patch in Patrick Steinhardt's v3 series optimizing `git-upload-pack` performance by reducing write syscalls. This is a preparatory cleanup that removes a leftover debug message ("flushed.") that was inadvertently being sent to clients during packfile transfers. The message dates back to 2006 and appears to have been a debugging aid that was never meant to be visible to end users.

The patch is straightforward - it simply removes the `fprintf()` call while keeping the buffer flush logic intact. The commit message includes a reproduction showing the Linux kernel clone output where the debug message appears, demonstrating the real-world impact. This is a clear bugfix that should be uncontroversial, though it's worth noting this is just the first step in a larger series addressing lock contention in high-concurrency scenarios.
