This is a documentation patch addressing the legacy behavior of `-U` without a number in Git's context diff options. Oswald Buddenhagen provides minor wording suggestions to Tian Yuchen's patch that clarifies the backward compatibility status of bare `-U` handling.

The thread has already established that Git must keep accepting bare `-U` (defaulting to 3 lines like `-p`) for backward compatibility, particularly to preserve test 157 in t4013. Tian's patch updates the documentation to explicitly note this as legacy behavior rather than an intentional feature.

Oswald suggests two phrasing improvements: (1) making the backward compatibility rationale more direct by saying "we retain this fallback behavior" rather than implying it's a side effect, and (2) using "silently accepted as a synonym" instead of "accepted as a silent synonym" for more natural wording. These are purely editorial suggestions that don't affect the technical content or behavior.

The patch remains documentation-only, touching `diff-context-options.adoc` and `diff-options.adoc` to clarify that bare `-U` is a legacy form that defaults to 3 lines of context. The core behavior remains unchanged - `-U` still works without a number, `--unified=<n>` remains the canonical long form, and the 3-line default applies both when `<n>` is omitted and when the config is unset.

Junio had previously indicated the core requirements were satisfied, and D. Ben Knoble's remaining documentation syntax suggestions (like `--unified[=<n>]` formatting) were noted as non-blocking. Oswald's suggestions represent final polish on the wording before potential merging.
