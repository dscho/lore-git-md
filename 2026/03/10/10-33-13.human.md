This is a reply in an ongoing thread about adding a `ADVICE_STASH_BEFORE_CHECKOUT` warning for uncommitted changes during branch switches, which was proposed as a GSOC microproject. The thread also includes unrelated patches about diffstat width calculations that have already been merged for Git 2.54.0.

Phillip Wood points out that the patch series appears to have some branch contamination, as it includes unrelated commits from other authors (Junio, K Jayatheerth, LorenzoPegorari) alongside the intended advice feature. He suggests the author rebase onto upstream master to clean this up. 

More substantively, Phillip questions whether recommending `git stash` is the best approach, suggesting that `git checkout -m` (which performs a three-way merge of the changes) might be more convenient for users than the stash/checkout/unstash workflow. This raises a design question about the proposed advice's user experience that wasn't addressed in the original proposal.

The reply doesn't introduce new code - it's purely feedback on the existing proposal. The core technical aspects of the advice implementation (new enum, config option, and output formatting) appear uncontroversial based on the thread summary, but Phillip's comment suggests the behavioral recommendation may need reconsideration. The author will likely need to address both the branch hygiene issue and the UX feedback in a v2 submission.
