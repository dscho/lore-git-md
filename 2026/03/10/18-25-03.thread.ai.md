GSoC proposal from Lorenzo Pegorari to implement configurable fetch ordering for promisor remotes in partial clones. Current behavior tries remotes in config file order with no prioritization. Proposal introduces:

1. Client-side `remote.<name>.promisorPriority` config option
2. Server-side priority advertisement via promisor-remote protocol

Implementation would modify promisor_remote.c's linked list handling and related functions. Testing shows current behavior and edge cases. Proposal notes one uncovered scenario (per-remote priority contexts) and suggests solution direction. 

Lorenzo has contributed 3 patches (2 merged, 1 pending) and demonstrates deep understanding of partial clone machinery. 350-hour schedule planned across community bonding, implementation, testing and documentation. Well-scoped project that would benefit users managing multiple promisor remotes.
