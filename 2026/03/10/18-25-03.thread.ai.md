GSoC proposal from Lorenzo Pegorari to implement configurable fetch ordering for promisor remotes in partial clones. Current behavior tries remotes in config file order with no prioritization. Proposal introduces client-side `remote.<name>.priority` (simplified from original `promisorPriority` name) and server-side priority advertisement via promisor-remote protocol. Christian Couder reviewed, suggesting technical refinements: recommends fixed priority range (1-100) over `UCHAR_MAX`, confirms global priorities are preferable to per-server contexts for lazy fetches (which depend on filters not server object presence), and notes minor formatting issues in proposal. 

Implementation would modify promisor_remote.c's linked list handling. Testing shows current behavior and edge cases.
