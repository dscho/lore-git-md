GSoC proposal from Lorenzo Pegorari to implement configurable fetch ordering for promisor remotes in partial clones, addressing current behavior that tries remotes in config file order without prioritization. The design introduces client-side `remote.<name>.priority` (simplified from original `promisorPriority` name) with fixed 1-100 range and server-side priority advertisement via promisor-remote protocol. 

Christian Couder's technical feedback led to key refinements: clarified that lazy fetches don't use filters (unlike initial partial clones) and that promisor-remote capability depends on filter usage rather than server object presence, making global priorities sufficient (per-server contexts would add unnecessary complexity). Lorenzo has incorporated these corrections and will fix minor proposal formatting issues before official GSoC submission.

Implementation will modify promisor_remote.c's linked list handling, with testing planned for current behavior and edge cases. Lorenzo has demonstrated partial clone expertise through 3 prior patches (2 merged, 1 pending). The 350-hour schedule covers community bonding, implementation, testing and documentation phases. The well-scoped project addresses real needs for users managing multiple promisor remotes, with design now technically validated through Christian's review.
