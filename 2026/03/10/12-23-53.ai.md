This is a bugfix patch in an ongoing thread about memory leaks in mmap handling during Git operations. The patch addresses a specific leak in the object streaming subsystem that was introduced by Patrick Steinhardt's 2025 restructuring of the streaming backend.

The issue occurs in `odb_source_loose_read_object_stream()` where error paths were not properly cleaning up mmap'd memory. Jeff King's fix changes the error handling to munmap the local `mapped` variable rather than the uninitialized `st.mapped` field in the stream struct. This completes a series of fixes that now comprehensively address mmap-related leaks across multiple subsystems.

The thread has shown effective collaboration between Jeff King (who authored all fixes), Junio C Hamano (who discovered this particular leak during verification), and Patrick Steinhardt (whose earlier commit introduced the issue). The series demonstrates thorough attention to resource management edge cases, particularly under sanitizers and with `NO_MMAP` builds.
