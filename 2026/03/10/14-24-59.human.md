This is a follow-up discussion about the `ADVICE_STASH_BEFORE_CHECKOUT` feature, which aims to help users understand their options when switching branches with uncommitted changes.

Patrick Steinhardt points out a critical gap in the implementation: while the advice infrastructure has been added (with enum, config option, and message formatting), there's no actual call site that triggers this advice during checkout operations. He notes that simply defining the function in `advice.c` isn't enough - it needs to be integrated into the checkout workflow to have any effect.

The exchange highlights a mentoring moment where Patrick corrects the contributor's misunderstanding about how advice gets activated. The contributor had incorrectly assumed the advice would automatically apply because it was defined in `advice.h`, but Patrick explains that explicit calls are needed in the relevant code paths (likely `checkout.c`).

This is the last remaining blocker for the feature, as all other aspects (message wording, safety considerations, config plumbing) have been addressed in previous iterations. The thread shows the project's careful attention to both user experience and implementation completeness - even well-designed advice is worthless if it never actually appears when needed.
