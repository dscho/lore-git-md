Feature addition to `git fast-import` adding commit re-signing capability. This is the final patch in a merged v3 series that introduces a new `re-sign-if-invalid[=<keyid>]` mode for `--signed-commits`, allowing invalid commit signatures to be replaced with fresh signatures during import.

The patch builds on preparatory refactoring that moved signing logic to gpg-interface.c, now exposing a `sign_buffer_with_key()` helper. When invalid signatures are detected (using the same verification as `git verify-commit`), the commit is re-signed either with a specified key or the default signing key. The implementation includes comprehensive test coverage for OpenPGP, X.509, and SSH signatures.

Notable technical details include:
- Explicit failure for interoperability mode (currently unsupported, with NEEDSWORK comment)
- Shared warning message infrastructure between strip/re-sign modes
- Conservative handling of experimental features
- Clean removal of obsolete declarations from earlier refactoring

The patch appears well-constructed with thorough test coverage and clear documentation. It represents a natural extension of the existing signature handling in fast-import, providing users more flexibility when dealing with invalid signatures during repository imports. The implementation follows Git's standard patterns for signature handling and builds on prior work in gpg-interface.c.
