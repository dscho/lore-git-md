This is a small refactoring patch that addresses compiler warnings about discarded const qualifiers in `ident_to_worktree()`. 

The patch changes the types of two local variables (`dollar` and `spc`) from `char*` to `const char*` since they are only used to point into the const input string `src` and never modified. This silences warnings that appeared when building with glibc-2.43, where `memchr()` returns a const pointer when given a const input.

The change is straightforward and low-risk - it doesn't modify any behavior, just makes the const-correctness explicit. The patch is cleanly formatted with a clear commit message explaining both the problem and solution. Since it touches a sensitive area (the ident conversion code that handles $Id$ expansion), the conservative approach of just adding const qualifiers rather than any deeper changes is appropriate.
