Performance optimization series for `git-upload-pack` lock contention, part 8/10. This patch introduces `hashfd_ext()` as an extended version of the internal `hashfd_internal()` function, moving optional parameters into a new `hashfd_options` struct while keeping mandatory parameters (algorithm, file descriptor, and name) as direct arguments. The change follows Git's common pattern for extended function variants and is part of the broader effort to reduce write syscalls in high-concurrency scenarios. The patch maintains the series' focus on measurable performance improvements while addressing Junio C Hamano's question about parameter grouping rationale - optional parameters go in the struct, mandatory ones remain as direct arguments. This interface design allows future extensibility without signature changes, though the current discussion thread shows ongoing debate about whether to use `writev()` (as in this approach) versus alternative buffer management strategies proposed by Jeff King. The patch stands as one architectural option in the larger performance optimization effort that has already demonstrated significant syscall reduction (from ~400k to ~44k writes when cloning Linux).
