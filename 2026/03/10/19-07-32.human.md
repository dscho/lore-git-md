HTTP transport expert Jeff King (Peff) provides detailed technical feedback on Vaidas Pilkauskas's HTTP 429 rate limit retry implementation. This is the final patch in a series adding comprehensive HTTP 429 support to Git's HTTP client.

Peff identifies several issues with the manual Retry-After header parsing for older curl versions, noting it doesn't properly handle header continuations and could allow header injection. He suggests dropping this legacy support entirely since curl 7.66.0 (which provides native Retry-After handling) is now 7 years old.

The review also suggests improvements to the retry logic: moving retry_after initialization, consolidating the retry counter with the existing auth retry counter, and potentially moving the retry_after parameter into the http_get_options struct. Peff questions whether some test timing checks might be too tight and could fail on slow systems.

While the core functionality appears sound, the review highlights areas where the implementation could be simplified or made more robust. The author will need to decide whether to address these suggestions in a v6 or proceed with the current approach. This patch remains technically solid but may benefit from some refinement based on the feedback.
