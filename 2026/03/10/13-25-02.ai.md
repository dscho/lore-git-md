This patch introduces new `writev()` wrapper functions as part of Patrick Steinhardt's ongoing performance optimization series for `git-upload-pack` lock contention. The patch adds two key functions:

1. `writev_in_full()` - A robust wrapper that handles partial writes, EINTR/EAGAIN retries, and iovec adjustment, similar to the existing `write_in_full()` but for vectorized I/O. It carefully manages the iovec array during partial writes by advancing through completed buffers and adjusting partially written ones.

2. `writev_or_die()` - A fatal-error variant that calls `writev_in_full()` and dies with an error message if the operation fails, matching Git's existing `write_or_die()` pattern.

The implementation shows careful attention to edge cases:
- Proper handling of partial writes by modifying the iovec in place
- Correct propagation of errno for error cases
- Integration with Git's existing error handling infrastructure
- Maintenance of POSIX semantics across all supported platforms

This is a foundational piece for the larger optimization effort, providing the safe, portable `writev()` interface that subsequent patches will use to batch writes in `upload-pack`, `sideband`, and other subsystems. The wrapper design follows established Git patterns while adding the vectorized I/O capabilities needed to reduce syscall overhead in high-concurrency scenarios.
