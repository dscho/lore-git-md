This is a feature patch in the final stages of review, part of a series adding configurable cover letter formatting to `git format-patch`. The discussion focuses on how to handle boolean vs string values for the new `format.commitListFormat` config option.

The author (Mirko Faina) is responding to Junio C Hamano's suggestion to use boolean values to toggle between the traditional shortlog format and the new default format. Junio proposed that `false` would mean "use shortlog", `true` would mean "use the new numbered format", and any string value would be treated as a custom format specification.

Mirko pushes back against mixing boolean and string types for the config value, preferring to keep the option purely string-based. They suggest introducing a new named format (like "numbered") as an alternative to "shortlog" rather than using boolean toggles. This maintains type consistency in the config while still providing the same functionality.

The exchange shows the series is nearly ready, with this being one of the final design decisions before merging. The implementation already has:
- Comprehensive test coverage
- Documentation updates
- Backward compatibility
- Support for custom formats via both CLI and config

The remaining question is purely about the most intuitive way to specify the default behavior in the config file - whether through boolean values or through named format strings. The author favors the type-consistent string approach, while Junio's suggestion would align with some existing Git config patterns that use booleans for feature toggles.
