This is a refinement patch in Jiamu Sun's subcommand autocorrection series, specifically addressing the TTY check and config parsing logic. Karthik Nayak provides review feedback on naming consistency.

The patch moves TTY detection for autocorrection prompts from help.c to autocorrect.c, making it the responsibility of the config parser to ensure valid settings. It introduces a new `struct autocorr` to bundle the mode and delay parameters, replacing the previous integer-based approach. The enum values are also redefined to be more explicit.

Key changes include:
- TTY check now happens in `autocorr_resolve_config()` rather than at prompt time
- Cleaner control flow in `parse_autocorrect()` with explicit enum returns
- Removal of redundant float casting in delay calculation
- New struct to encapsulate autocorrection configuration state

Karthik suggests renaming `struct autocorr` to `autocorrect_config` for better clarity of purpose. This is the only outstanding feedback on this patch, which otherwise appears technically sound and well-integrated with the rest of the series. The changes maintain backward compatibility while improving code organization and type safety.

The patch represents incremental progress in the larger effort to make subcommand autocorrection a reusable component of Git's parse-options infrastructure. With Karthik's naming suggestion addressed, this appears ready for inclusion.
