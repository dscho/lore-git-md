Feature: subcommand autocorrection for parse-options API

This patch implements autocorrection for mistyped subcommands in Git commands that use the parse-options API. When a user provides an invalid subcommand (like `git remote ad` instead of `git remote add`), Git will now suggest the closest matching valid subcommand if the autocorrect feature is enabled.

The implementation:
- Uses Levenshtein distance to find the closest matching subcommand
- Applies a dynamic threshold for similarity based on subcommand length (shorter commands require closer matches)
- Respects the existing autocorrect configuration (never/hint/immediate)
- Skips optional subcommands (marked with PARSE_OPT_SUBCOMMAND_OPTIONAL)
- Maintains the existing error flow when no good match is found

The patch builds on previous refactoring work that separated subcommand handling into its own function. It introduces new helper functions to:
- Collect all valid subcommands into a string list
- Calculate and evaluate similarity between the input and valid commands
- Handle the autocorrection prompt and confirmation

This is part of a larger series that splits autocorrect functionality into reusable components. The implementation appears clean and well-tested, with clear separation between the core autocorrection logic and the parse-options integration. The dynamic threshold for similarity is a thoughtful touch that should improve accuracy across commands with varying subcommand lengths.
