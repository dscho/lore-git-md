This is part 2/10 of Patrick Steinhardt's performance optimization series addressing lock contention in `git-upload-pack` during high-concurrency scenarios. The patch focuses on improving keepalive packet timing when buffering data.

The change modifies how `upload-pack` calculates when to send keepalive packets during packfile transmission. Previously, keepalives were based purely on poll() timeouts, which could lead to unnecessarily long gaps in communication if data was being received but buffered. The new approach tracks the last time data was actually sent to the client and adjusts keepalive timing accordingly.

Key technical changes:
1. Adds tracking of last data transmission time via `last_sent_ms`
2. Modifies `relay_pack_data()` to report when data was actually sent via new `did_send_data` parameter
3. Adjusts poll timeout calculation to consider time since last transmission
4. Maintains existing behavior when keepalives are disabled

The patch is part of a larger effort to reduce write syscalls in high-concurrency scenarios, with this change specifically addressing edge cases where buffering could delay keepalives. It builds on previous discussion about buffer management while incorporating feedback about keepalive integration. The implementation appears thorough, with clear handling of edge cases and proper integration with existing timeout mechanisms.
