This is the final implementation patch in a three-part series adding a `re-sign-if-invalid` mode to `git fast-import`'s signature handling. The patch completes the feature by adding the actual re-signing logic when invalid signatures are encountered, building on the preparatory refactoring in the previous patches.

The core addition is a new `SIGN_RESIGN_IF_INVALID` mode that matches `git commit --gpg-sign` syntax, allowing either automatic re-signing with the default key or specifying an explicit key ID. The implementation handles warning messages consistently with the existing `strip-if-invalid` mode and includes explicit failure for interoperability mode (where signatures would need to be generated in both repository and compatibility object formats).

Christian Couder's review notes a few minor issues: a suggestion to use "RE_SIGN" rather than "RESIGN" for consistency, a couple of typos in "compatibility", and a possible opportunity to deduplicate warning logic. These appear to be straightforward fixes that don't affect the overall approach. The patch maintains the series' thorough test coverage and conservative experimental feature handling.

With this patch, the series provides a complete solution for handling invalid signatures during fast-import, addressing a gap where previously only stripping or preserving signatures were options. The implementation builds on shared signing infrastructure moved to gpg-interface.c in the previous patch, following Git's standard pattern for reusable functionality. While tag signature support remains for a future series, this completes the commit signature handling as originally proposed.
