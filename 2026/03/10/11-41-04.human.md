This is part 5/8 of Jiamu Sun's series adding subcommand autocorrection support to Git's parse-options API. The patch focuses on improving the config resolution for autocorrect behavior.

The key changes in this patch:
- Introduces a new `autocorr_resolve()` API that handles config resolution internally rather than exposing the callback
- Makes the config callback private to enforce the intended high-level API usage
- Moves alias resolution into a separate config pass (acknowledging this may impact performance slightly on cold paths)
- Simplifies the help.c implementation by using the new API

The patch continues the series' trend of cleanly separating concerns - here specifically around config handling. While it does introduce an additional config pass for aliases, the author notes this is acceptable since the path is cold. The changes maintain all existing behavior while improving encapsulation.

This appears to be a well-considered refinement of the autocorrect infrastructure, following earlier feedback to better modularize the components. The patch fits naturally into the series' progression toward a reusable autocorrect API.
