Feature addition for checkout advice during dirty working state.

This is version 2 of a patch series (now reduced to a single patch) that adds a new advice message when users attempt to switch branches with uncommitted changes. The patch follows up on feedback from Phillip Wood in the thread, though it doesn't yet incorporate his suggestion to recommend `git checkout -m` as the primary solution - that appears planned for a future version.

The change adds `ADVICE_STASH_BEFORE_CHECKOUT` to the advice system, triggered when branch switching would overwrite local modifications. The advice lists affected files and suggests using `git stash` to preserve changes. The implementation follows existing patterns from similar advice functions like `advise_on_updating_sparse_paths()`.

Key technical elements:
- New enum in `advice.h`
- Advice implementation in `advice.c` showing affected files and stash commands
- Documentation update in `advice.adoc`
- Configurable via `advice.stashBeforeCheckout`

The patch appears well-structured and follows Git's advice subsystem conventions. The thread shows this is part of a GSOC microproject, with active mentoring from Phillip Wood who suggested enhancing the advice to recommend the merge option (`-m`) first before falling back to stashing. The author has acknowledged this feedback but hasn't implemented it in v2, suggesting it may come in a future iteration.

This continues a productive thread where earlier technical feedback about unrelated commits in v1 has already been addressed by splitting them out. The current patch focuses cleanly on the advice addition while leaving the `-m` recommendation improvement for the next round.
