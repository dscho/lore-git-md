This is a bugfix for the `git history reword` command, addressing a memory safety issue in the argument validation path. The patch was originally submitted by René Scharfe and is receiving positive review from Patrick Steinhardt.

The issue occurs when argument validation fails in `cmd_history_reword()` - the function would pass an uninitialized `struct rev_info` to `release_revisions()`, potentially leading to undefined behavior during cleanup. The fix is straightforward: zero-initialize the struct at declaration to ensure safe cleanup in all code paths.

The patch is minimal and focused, affecting only `builtin/history.c`. It doesn't change any functionality but makes error handling more robust. Patrick Steinhardt's review confirms the fix looks correct, suggesting this will likely be merged without further discussion.
