This is a bugfix for the `git history reword` command, addressing a memory safety issue in the argument validation path. The patch was originally submitted by René Scharfe and is receiving positive feedback from Patrick Steinhardt.

The core issue is that `cmd_history_reword()` could pass an uninitialized `struct rev_info` to `release_revisions()` if argument validation fails, potentially leading to undefined behavior during cleanup. The fix is straightforward - zero-initializing the `rev_info` struct at declaration to ensure safe cleanup in all code paths.

The change is minimal and focused, affecting only `builtin/history.c` where the `git history reword` command is implemented. While this doesn't modify any functionality, it makes the error handling more robust by preventing potential memory corruption when invalid arguments are provided. The patch follows René Scharfe's characteristic style of precise, safety-oriented code hygiene improvements.

Patrick Steinhardt's review confirms the correctness of the approach, suggesting this is likely to be merged without further discussion. The fix is contained to the history command implementation and doesn't appear to have broader implications for other parts of the codebase.
