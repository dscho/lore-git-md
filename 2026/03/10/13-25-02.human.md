This is part 6/10 in Patrick Steinhardt's performance optimization series targeting lock contention in `git-upload-pack` during high-concurrency scenarios. The patch introduces new `writev()` wrapper functions (`writev_in_full` and `writev_or_die`) that will be used by the buffering system being added across multiple Git subsystems.

The new wrappers follow Git's existing pattern for I/O utilities, providing both a non-fatal version (`writev_in_full`) that returns error codes and a fatal version (`writev_or_die`) that terminates on failure. The implementation handles partial writes by adjusting the iovec structures, similar to how `write_in_full` manages partial writes for single buffers.

This is a foundational piece for the series' broader goal of reducing write syscalls through `writev()`-based buffering. The patch is straightforward and well-contained, building on the compatibility layer added in the previous commit. It demonstrates the careful attention to cross-platform considerations that has characterized this performance optimization work.
