This is a follow-up discussion in the completed `git fast-import` signature handling series, focusing on potential future extensions to the signing functionality. Junio C Hamano responds to Justin Tobler's consideration of handling unsigned objects during history rewriting.

The exchange explores architectural directions beyond the current scope of the merged v2 series, which only handles re-signing previously-signed-but-invalid commits. Junio suggests that the infrastructure added for re-signing could naturally extend to signing previously unsigned objects through a new `--sign-commits=all` option, while maintaining the existing `--signed-commits=strip-if-invalid` for signature stripping.

The discussion highlights that the current implementation deliberately limits itself to signed objects (as noted in Justin's earlier implementation), but the refactored signing infrastructure in gpg-interface.c positions the codebase well for these future extensions. This appears to be forward-looking design discussion rather than a request for immediate changes to the merged series.
