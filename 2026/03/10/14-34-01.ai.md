This is a review comment on patch 4/5 of a series adding configurable cover letter formatting to `git format-patch`. The series is now in its seventh iteration and considered final, with this patch implementing the `format.commitListFormat` config option.

Phillip Wood raises two main points about the config behavior design:

1. The current implementation treats an empty config value differently from an unset one (empty uses a default format while unset falls back to shortlog). He notes this is unusual in Git's config handling and suggests using an explicit "default" value instead to trigger the default format.

2. He suggests it would be nice to support this same "default" format behavior on the command line as well, for consistency.

The patch itself adds comprehensive test coverage for the config option, verifying:
- Custom formats with count/total/author placeholders
- Empty config value behavior
- Explicit "shortlog" setting
- Unset config falling back to shortlog

The implementation follows the established pattern from earlier patches, with the config value behaving identically to the `--cover-letter-format` CLI option (requiring "log:" prefix for custom formats). This maintains consistency between the two interfaces while providing persistent configuration.

This is a final polish suggestion on an otherwise appears to be a complete and well-tested implementation that has already addressed all substantive feedback through seven iterations. The series as a whole introduces flexible cover letter formatting while maintaining backward compatibility, with strict validation of format strings and comprehensive documentation.
