This is a performance-oriented patch in Patrick Steinhardt's ongoing ODB abstraction series. Junio C Hamano provides a detailed review of the changes to how Git estimates loose object counts for auto-GC decisions.

The patch moves loose object counting logic from `too_many_loose_objects()` to a new `odb_source_loose_approximate_object_count()` function. The key behavioral change is that instead of stopping early when exceeding the threshold (as the old code did), the new implementation always scans one full shard directory (chosen arbitrarily as "17") and multiplies by 256 to estimate the total count. Junio notes this is functionally equivalent in terms of the threshold check but represents a subtle performance tradeoff - the new code may do slightly more work in pathological cases with many objects in the sampled shard.

The discussion highlights the careful balance in this abstraction work between clean interfaces and preserving existing behavior. Junio's review confirms the mathematical equivalence of the counting approach while surfacing the implementation difference for consideration. This patch appears to be proceeding as expected in the larger ODB abstraction effort, with no major concerns raised about the direction.
