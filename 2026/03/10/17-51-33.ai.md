This is a review response from Junio C Hamano on Patrick Steinhardt's ODB abstraction series, specifically addressing patch 5/6 which introduces generic object counting interfaces. Junio acknowledges the design choice to ignore loose objects when approximating counts (inherited from pre-abstraction behavior) but raises an interesting question about whether the new loose object counting implementation could provide slightly more accurate approximations at minimal cost. The loose counting now fully scans one shard directory (always "17") and multiplies by 256, rather than stopping early when exceeding the auto-GC threshold as the old code did. Junio notes this is mathematically equivalent for threshold checking but wonders if including the loose count even in approximate mode might offer better accuracy with little performance impact. He leaves this as an optional consideration rather than a blocking issue, indicating the patch is otherwise sound and has been queued for integration. The exchange shows Junio engaging thoughtfully with the performance/accuracy tradeoffs while recognizing Patrick's deeper familiarity with the implementation constraints.
