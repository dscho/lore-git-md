This is a performance patch in Patrick Steinhardt's ongoing ODB abstraction series. Junio Hamano notes that while the patch maintains the same approximate counting behavior for loose objects (sampling one shard directory and multiplying by 256), it does introduce a subtle performance change: the new implementation counts all objects in the sampled shard rather than stopping early once the threshold is exceeded. 

The change moves the loose object counting logic from `too_many_loose_objects()` to a new `odb_source_loose_approximate_object_count()` function in object-file.c. While functionally equivalent in terms of the final count, Junio observes that for repositories with extremely large numbers of loose objects, this could theoretically be slower since it no longer short-circuits the count. However, he acknowledges this is likely negligible in practice for the auto-GC use case.

This patch is part of a larger effort to abstract object counting from repository-specific code to the ODB layer, enabling future pluggable backends. The implementation remains internal-facing with no user-visible changes. Junio's review suggests the patch is sound but flags the behavioral nuance for completeness.
