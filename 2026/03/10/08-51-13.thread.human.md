This thread documents the evolution of a Google Summer of Code microproject to improve user guidance when switching branches with uncommitted changes. The work builds on two parallel tracks: merged diffstat width calculation improvements (now in Git 2.54.0) and the ongoing `ADVICE_STASH_BEFORE_CHECKOUT` feature.

The advice system implementation has progressed through three versions from Arsh Srivastava, with active mentoring from Phillip Wood (message design), Patrick Steinhardt (integration points), and Junio C Hamano (safety considerations). The current state includes all core infrastructure - enum definition, config option, and documentation - but faces two critical open questions: where to trigger the advice in the checkout workflow (Patrick's outstanding request) and how to frame the recommendation of `git checkout -m` given Junio's concerns about its irreversible nature.

Junio's latest feedback cautions against presenting `-m` as the primary solution, noting that stashing provides a recoverable safety net if the merge fails. This introduces a new design constraint requiring either stronger caveats about `-m` or repositioning stash as the default recommendation. While the technical implementation is otherwise complete, these unresolved integration and UX decisions must be addressed before the feature can graduate from its current "cooking" state in Junio's integration branches.
