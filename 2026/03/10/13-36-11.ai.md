This is a discussion about the ongoing GSOC microproject to add `ADVICE_STASH_BEFORE_CHECKOUT` advice for uncommitted changes during branch switches. Junio C Hamano weighs in on Phillip Wood's suggestion to recommend `git checkout -m` as the primary solution for carrying over changes between branches.

Junio expresses reservations about unconditionally recommending `git checkout -m` to new users, noting that while both approaches (`-m` and stash/pop) can result in merge conflicts, the stash method provides a safety net - the stash entry remains available if the pop fails, allowing recovery via `git reset --hard`. In contrast, `checkout -m` leaves the user with no automatic backup if conflict resolution fails, making it a higher-risk operation.

This feedback suggests the advice message should either: (1) avoid positioning `-m` as the primary recommendation, or (2) if it does recommend `-m`, include appropriate caveats about its irreversible nature. The discussion continues the thread's pattern of careful consideration around user experience tradeoffs in this feature.
