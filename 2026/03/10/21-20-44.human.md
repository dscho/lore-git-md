This is a follow-up discussion on the recently merged `git fast-import` signature handling series. The thread focuses on refining the naming of the new `re-sign-if-invalid` mode that allows rewriting commits with invalid signatures using a specified key.

Junio C Hamano notes that the "re-" prefix in `re-sign-if-invalid` may be redundant since the "if-invalid" part already implies the signature exists but is invalid. He suggests "sign-if-invalid" would be more accurate. Justin Tobler, the series implementer, acknowledges the point but doesn't feel strongly either way, leaving the door open for a follow-up patch.

Junio also raises a usability consideration: the current design ties the re-signing capability to the `--signed-commits` option, which might not cover all use cases. He suggests it could be more flexible to allow combining signature stripping with a separate signing option for projects that want to ensure all commits are signed (not just re-sign invalid ones).

The discussion is a post-merge refinement of functionality that's already in place, showing the project's attention to detail in naming and interface design. While the core implementation is stable, there may be follow-up patches to adjust terminology or expand the feature's flexibility.
