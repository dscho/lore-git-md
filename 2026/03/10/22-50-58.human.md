This is a technical clarification in the ongoing performance investigation of slow `git fetch` operations over SMB/CIFS networks. brian m. carlson responds to R. Diez's question about how Git uses SSH for remote operations, explaining that Git does not use standard SSH file transfer operations (SFTP) but instead invokes `git-upload-pack` on the remote system over SSH. This approach avoids downloading entire pack files unnecessarily and allows for more efficient authentication handling compared to SFTP. The response includes a trace example showing the SSH command used to invoke `git-upload-pack` on GitHub's repository.

The email confirms that Git requires the remote system to have Git installed when using SSH transport, as the operation will fail otherwise. brian m. carlson also notes that while `sshfs` could be used to mount a remote filesystem, this would have different performance characteristics than Git's native SSH transport. This clarification helps frame the earlier performance discussion by showing how Git's design assumes remote capabilities beyond simple file access.
