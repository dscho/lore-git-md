This is a GSoC proposal for a feature to improve partial clone functionality by implementing configurable fetch ordering for promisor remotes. Lorenzo Pegorari, a returning GSoC contributor with prior experience (having successfully completed BRL-CAD's 2025 program), proposes adding priority-based ordering when fetching from promisor remotes.

The proposal demonstrates solid research, including hands-on testing with a multi-remote setup to understand current behavior. The key idea is to introduce `remote.<name>.promisorPriority` configuration to control fetch order, with lower numbers indicating higher priority. The server would also be able to advertise suggested priorities via protocol extensions.

Lorenzo has already contributed several small patches to Git (documentation improvements and diffstat fixes) that were merged to master, showing they can navigate the codebase and review process. The proposal is thorough, addressing potential edge cases and including a detailed timeline. One noted limitation is the inability to set different priority orders per remote server, though this seems like a niche case.

The work would build on the promisor remote infrastructure, particularly around `promisor-remote.c`. If implemented, this would give users more control over fetch behavior in partial clone scenarios, which is valuable for large repositories with multiple object storage backends. The proposal is well-scoped for a GSoC project and shows good understanding of both the technical and community aspects of contributing to Git.
