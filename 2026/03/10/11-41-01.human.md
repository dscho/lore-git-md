This is part 2/8 of Jiamu Sun's series to make Git's command autocorrection functionality reusable across different commands. The patch moves the autocorrect config parsing and user interaction logic from `help.c` into new files `autocorrect.{c,h}`, making it available to other parts of Git that don't link against `git.o`.

The change is motivated by the need to support autocorrection for subcommands (like those in `git remote` and `git notes`) without requiring those commands to link against all of `help.c`'s dependencies. The implementation cleanly separates the autocorrect logic while maintaining all existing behavior.

This version (v3) shows the patch has matured through review, with the author splitting the changes to make the code movement more obvious in the diff. The series appears technically sound and ready for maintainer consideration, with Junio having previously approved the architectural approach. The change is well-contained and comes with thorough test coverage.
