This is part 9/10 of Patrick Steinhardt's performance optimization series addressing lock contention in `git-upload-pack`. The patch removes the specialized `hashfd_throughput()` function from the csum-file interface, replacing its single use in `pack-objects` with a direct call to the more general `hashfd_ext()` function.

The change is straightforward - the progress meter and smaller buffer size that were hardcoded in `hashfd_throughput()` are now specified via options when calling `hashfd_ext()`. This continues the series' theme of generalizing interfaces while maintaining the same performance characteristics (the 8KB buffer size for more granular progress reporting remains unchanged).

This appears to be a clean refactoring that removes a single-use function in favor of the newer, more flexible interface introduced earlier in the series. The commit message clearly explains the change and its motivation. As with the rest of the series, this is a well-constructed patch that moves toward the goal of reducing syscalls while keeping the code maintainable.
