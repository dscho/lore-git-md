This is the final patch in a three-part series adding a re-signing mode to `git fast-import` for handling invalid commit signatures. The series was originally proposed by Christian Couder, with implementation work by Justin Tobler.

The patch implements the new `re-sign-if-invalid[=<keyid>]` mode for `--signed-commits`, which allows fast-import to automatically replace invalid commit signatures with new valid signatures during import. This complements the existing options to either preserve or strip invalid signatures.

Christian's review notes a few minor issues: suggests using "RE_SIGN" instead of "RESIGN" for consistency, points out some typos ("compatability" should be "compatibility"), and recommends extracting the warning logic into a helper function to avoid duplication. He also confirms the overall approach looks good aside from these small points.

The implementation builds on shared signing infrastructure moved to gpg-interface.c in the previous patch, and includes a clear NEEDSWORK comment about interoperability mode limitations with signatures. The patch maintains thorough test coverage and conservative experimental feature handling that satisfied earlier reviewer concerns.

With this final patch, the series appears ready for merging, addressing all the technical requirements while leaving room for future improvements to tag signature handling and interoperability support.
