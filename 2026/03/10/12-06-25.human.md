This is the fourth patch in an 8-part series refactoring repository-specific global variables into `struct repo_config_values`, part of the ongoing effort to reduce global state and improve repository isolation. The patch moves the `pack_compression_level` configuration from a process-wide global variable to per-repository storage in `repo_config_values`.

The change updates all usage sites in `builtin/fast-import.c`, `builtin/pack-objects.c`, `environment.c`, and `object-file.c` to access the compression level through the repository-specific struct rather than the global variable. The default compression level remains Z_DEFAULT_COMPRESSION. Like previous patches in the series, this maintains existing behavior while eliminating cross-repository state leakage.

The patch follows the established pattern seen in earlier parts of the series, with mechanical but careful updates to all affected code paths. It touches core files (environment.h/c) and related subsystems that use pack compression. The commit message could better explain why pack compression level specifically benefits from repository-specific storage, but the implementation appears correct and consistent with the series' goals.
