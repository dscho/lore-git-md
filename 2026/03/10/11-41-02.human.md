This is part 3/8 of Jiamu Sun's series implementing subcommand autocorrection in Git's parse-options API. The patch moves TTY checking for autocorrection prompts from help.c to autocorrect.c, consolidating the logic where the autocorrect configuration is resolved.

The key changes are:
- Moves the TTY check (which disables interactive prompts in non-interactive sessions) into `autocorr_resolve_config()`
- Introduces a new `struct autocorr` to bundle the mode and delay values
- Cleans up the control flow in `parse_autocorrect()` with explicit `else if` chains
- Removes redundant float casting in delay calculation

This continues the architectural work from earlier patches to properly modularize the autocorrection functionality. The changes are focused on code organization rather than behavior changes - the actual autocorrection behavior remains the same, just with cleaner internal structure.

The patch appears well-constructed with:
- Clear commit message explaining the rationale
- Clean separation of concerns
- No functional changes to the user-facing behavior
- Follows the project's style guidelines

This is part of the larger effort to make autocorrection available to more Git commands beyond just the help system. The series has gone through multiple rounds of review and appears ready for inclusion.
