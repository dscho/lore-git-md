This is a follow-up discussion about signature handling in `git fast-import`, specifically addressing naming and potential future extensions to the recently merged re-signing functionality.

The thread focuses on two main points: First, there's agreement that the current `re-sign-if-invalid` option name should be simplified to `sign-if-invalid` since the "re-" prefix is redundant when combined with "if-invalid" (which already implies the object was previously signed). Junio C Hamano suggests this change, and Justin Tobler appears open to implementing it in a follow-up patch.

Second, the discussion explores whether the current --signed-commits option should be expanded to handle unsigned commits during history rewriting. While both agree this would be useful, they recognize it's a separate concern from the just-merged functionality that only handles invalid signatures. Justin notes that supporting unsigned commits would require additional granularity beyond the current options provide, possibly needing a new `--sign-commits` flag in the future.

The exchange maintains the project's typical technical depth while remaining constructive - it's clear both participants understand the signature handling domain well and are thinking through the interface design carefully. The merged functionality appears stable, with this being a post-merge refinement discussion about naming and potential future directions rather than any issues with the implementation itself.
