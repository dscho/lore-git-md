This is the third version of a feature series adding commit signature re-signing capability to `git fast-import`. The series builds on previous work that allowed stripping invalid signatures, now enabling re-signing them with a specified key.

The core change introduces a new `re-sign-if-invalid[=<keyid>]` mode for `--signed-commits`, matching `git commit --gpg-sign` syntax. The implementation moves shared signing logic to gpg-interface.c and adds comprehensive test coverage for OpenPGP/X.509/SSH signatures. The series explicitly defers interoperability support (handling `extensions.compatObjectFormat`) as a future enhancement, currently failing with a clear error if attempted.

Changes since v2 include improved commit message clarity, fixed typos, renaming SIGN_RESIGN_IF_INVALID to SIGN_RE_SIGN_IF_INVALID per feedback, and extracting warning message handling into a helper function. The implementation appears thorough, with careful consideration of edge cases and clear documentation of current limitations.

This completes the three-patch series that was previously discussed and refined on-list, with all v1 feedback addressed. The changes look well-considered and the test coverage appears robust. The only open question is whether to tackle interoperability support now or later - the author leans toward deferring it.
