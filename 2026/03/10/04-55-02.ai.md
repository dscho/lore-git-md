This is a documentation patch addressing the handling of the `-U` option in Git's diff output. The thread has established that while bare `-U` (without a line count) defaults to 3 lines of context for backward compatibility, this behavior should be documented as legacy rather than as an intentional feature. Tian Yuchen is responding to D. Ben Knoble's review, agreeing that the current documentation could be clearer about when the default value applies (both when `<n>` is omitted and when the config is unset). 

The patch will update `diff-options.adoc` and `diff-context-options.adoc` to better document this behavior, though there remains some discussion about whether to adopt Knoble's suggested documentation syntax (using `--unified[=<n>]` format) and how explicitly to note the default value's dual application. The core technical points are settled - the lenient parsing must remain for compatibility with existing test 157 in t4013, and `--unified=<n>` remains the canonical long form. This appears to be a straightforward documentation improvement with no outstanding technical objections.
