This is a bugfix patch in Adrian Ratiu's hook configuration series, addressing a build failure introduced by moving a utility function between files. SZEDER Gábor points out that the patch moves `unsorted_string_list_remove()` from `hook.c` to `string-list.[ch]` but fails to account for the function's new `free_util` parameter in the call sites. The build fails because the existing calls in `hook.c` don't pass this parameter.

The function is a helper that removes items from an unsorted string list, now generalized to optionally free the `util` pointer. The patch adds proper documentation to the header but misses updating three call sites that now need to specify whether to free the utility data. This appears to be an oversight in what was otherwise a straightforward code movement suggested by Patrick Steinhardt.

The issue is straightforward to fix - the callers need to pass 0 for `free_util` to maintain the original behavior (not freeing the utility pointer). This is a mechanical change that doesn't affect the series' overall direction but needs addressing before the patch can be applied. The thread context shows this is part of a larger cleanup effort in Adrian's hook configuration work, where such utility function consolidation makes sense.
