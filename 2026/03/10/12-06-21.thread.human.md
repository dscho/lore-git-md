This thread presents an 8-patch series by Usman Akinyemi (mentored by Christian Couder) that refactors repository-specific global variables into `struct repo_config_values`, continuing Git's broader effort to reduce global state and improve repository isolation. The series systematically moves eight configuration-related globals into per-repository storage, with each patch following the same careful pattern: removing a global from environment.h/c, adding it to the repository struct, and updating all access sites.

The patches cover diverse settings including filesystem metadata handling (`trust_ctime`, `check_stat`), compression levels (`zlib_compression_level`, `pack_compression_level`), Unicode normalization (`precomposed_unicode`), sparse checkout behavior (`core_sparse_checkout_cone`, `sparse_expect_files_outside_of_patterns`), and now object/refname ambiguity warnings (`warn_on_object_refname_ambiguity`). The changes touch 47 files cumulatively, with the final patch modifying 7 files including object-name.c and several commands that temporarily disable warnings during bulk operations.

While mechanical in nature, this work significantly advances repository isolation - a prerequisite for proper library-style usage with multiple active repositories. The series builds on prior infrastructure introducing `repo_config_values` and aligns with René Scharfe's ongoing `the_repository` elimination effort. All patches maintain existing behavior while eliminating cross-repository state leakage. The thread has seen no objections, suggesting consensus on both the approach and value of these changes. With this final patch, the mechanical portion of the series is complete, though future could bring similar efforts for remaining globals.
