This thread documents an 8-patch series refactoring repository-specific global variables into `struct repo_config_values`, continuing the project-wide effort to reduce global state. The series systematically moves environment-related globals like compression settings and sparse-checkout configurations into per-repository storage, following established patterns from prior work in this area. Christian Couder provided initial minor feedback on the cover letter documentation, which was quickly addressed.

A new technical concern has emerged regarding the handling of `pack_compression_level`. Tian Yuchen identified that while most functions now correctly access this setting through repository-specific storage, the command-line option parsing in `cmd_pack_objects` still modifies a local variable rather than updating the repository's config value. This could cause CLI-specified compression levels to not properly propagate. The discussion highlights the subtle challenges in fully converting global variables, especially when they're modified through multiple pathways. Tian suggests updating the option parsing to write directly to the repository's config value to maintain consistency with the series' approach.

The series remains largely uncontested beyond this one technical point, suggesting it's nearing readiness for merging. The work demonstrates the project's pattern of onboarding new contributors through focused refactoring tasks, with Olamide Caleb Bello being mentored by Christian Couder and Usman Akinyemi on this effort.
