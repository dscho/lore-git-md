[PATCH 0/8] ci/build: introduce tools/ directory and meson PCH support

Thread identity: Patrick Steinhardt (ps@pks.im) proposing build system improvements via an 8-patch series. Thread type: infrastructure/developer tooling.

Core problem/goal: Two parallel improvements - (1) consolidate scattered build/development tooling into a new "tools/" directory (separating essential build infrastructure from optional contrib/ material, following up on prior cleanup), and (2) add precompiled header support to Meson build for ~30% faster compilation. Changes span multiple build systems (Makefile, CMake, Meson).

Current status: Version 1 series progressing with patch 7/8 now posted. Patch 1/8 established tools/ directory structure. Patch 2/8 relocated Coccinelle semantic patches from contrib/coccinelle/ to tools/coccinelle/. Patch 3/8 moved coverage-diff.sh from contrib/ to tools/. Patch 4/8 relocates update-unicode.sh from contrib/ to tools/. Patch 5/8 moves core build script generators (generate-*.sh) and helpers (check-builtins.sh, detect-compiler) from top-level to tools/. Patch 6/8 modified git-compat-util.h to prepare for PCH support by moving sign-compare warning suppression outside include guards. Patch 7/8 splits compatibility sources into their own static library to handle special cases where certain compatibility files intentionally avoid including git-compat-util.h. Remaining patch 8/8 will implement Meson precompiled headers.

Key technical details:
- tools/ directory now contains relocated Coccinelle infrastructure, coverage-diff.sh, update-unicode.sh, and core build generators
- generate-cmdlist.sh, generate-configlist.sh, generate-hooklist.sh, generate-perl.sh, generate-python.sh, generate-script.sh moved from top-level
- check-builtins.sh and detect-compiler helpers relocated
- git-compat-util.h modified to move sign-compare warning suppression outside include guards for PCH compatibility
- New compat_sources list created in meson.build, built as separate 'compat' static library
- Compatibility sources (previously mixed with libgit_sources) now isolated to handle special include cases
- All changes maintain original functionality across platforms (Windows, Cygwin, Darwin, Linux)
- Build system references updated in Makefile, CMake, Meson (including contrib/subtree meson.build)
- CI scripts and spatchcache helper updated to new paths
- Performance claim: ~30% compilation speed improvement with PCH
- PCH groundwork ensures warning behavior remains consistent while enabling precompilation

Open questions/loose ends:
1. Directory organization validation before further tool migrations
2. PCH changes cross-platform compatibility (Windows)
3. No unintended interactions between directory moves and PCH work
4. Need verification that warning suppression change doesn't introduce new issues on all supported compilers
5. Compatibility library separation impact on build times and final binary size

Participant positions: Only author Patrick Steinhardt so far. Key reviewers to watch: D. Ben Knoble (build systems), Johannes Schindelen (Windows/CMake), Ramsay Jones (portability), René Scharfe (include file changes). Coccinelle maintainers may weigh in on relocation.
