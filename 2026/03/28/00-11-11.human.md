This is the first patch in Pablo Sabater's v6 series adding a `--graph-lane-limit` feature to `git log --graph`. The patch introduces the core behavior of limiting graph width to 15 lanes (30 columns) by default, with excess lanes hidden while still showing commit markers ('*') for the first hidden lane.

The implementation modifies graph.c's rendering logic to:
- Skip drawing lanes beyond the limit
- Preserve commit markers for the first hidden lane
- Handle merges specially (only showing merge lanes when needed to connect visible commits)
- Fix octopus merge column calculations
- Add a NULL check in `first_interesting_parent()`

The changes are well-contained to graph.c file and maintain all existing behavior when the limit isn't reached. This is the foundational patch that will be followed by two more adding the user-facing option and visual polish. The series has gone through multiple rounds of review and appears technically sound, now in final polishing phase with maintainer guidance focused on code comprehension norms rather than implementation changes.
