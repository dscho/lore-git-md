Feature addition to `git cat-file`'s batch mode, adding dynamic mailmap toggling.

Siddharth Asthana proposes adding `use-mailmap` and `no-use-mailmap` subcommands to `git cat-file --batch-command`, allowing mailmap processing to be controlled dynamically during a batch session. Currently, the `--use-mailmap` option must be specified at process startup, which is limiting for long-running processes like those used by GitLab's Gitaly service.

The implementation introduces two new subcommands that mirror the existing CLI options. `use-mailmap` enables mailmap processing (lazily loading the mailmap data on first use) while `no-use-mailmap` disables it while keeping the data cached. The patch includes thorough tests verifying the new commands work both with and without `--buffer` mode, checking that the output size changes appropriately when toggling mailmap processing.

The changes touch the command documentation, the batch command dispatch logic in `builtin/cat-file.c`, and add several test cases to `t/t4203-mailmap.sh`. The implementation appears clean and well-tested, with clear motivation from real-world use in GitLab's infrastructure. This seems like a straightforward quality-of-life improvement for systems that maintain persistent `git cat-file` processes.
