This is the first patch in Pablo Sabater's v6 series introducing horizontal graph truncation for `git log --graph`. The feature caps displayed graph columns at a hard-coded limit (15 lanes by default, with excess lanes shown as '~' characters) to improve readability of repositories with many active branches.

The implementation modifies graph.c's rendering logic to:
- Skip rendering lanes beyond the limit while preserving commit markers ('*') for the first hidden lane
- Handle octopus merges by checking truncation affects parent lane calculations
- Maintain existing behavior when the lane count is under the limit
- Fix a pre-existing indentation issue

The patch introduces key infrastructure like the `graph_needs_truncation()` helper and modifies core rendering functions (`graph_output_commit_line`, `graph_output_post_merge_line`, etc.) to respect the lane limit. It carefully preserves graph connectivity by only showing merge lanes when either the commit or first parent is visible.

This is the foundational patch in the three-part series, implementing the core behavior before the user-facing option is added in subsequent patches. The changes are well-contained to graph.c and maintain all existing functionality when the limit isn't reached. With thorough handling of edge cases (like octopus merges) and clear separation from the future configurable limit, this appears ready for inclusion as the base for the feature.
