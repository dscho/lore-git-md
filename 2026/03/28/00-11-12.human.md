Feature patch adding `--graph-lane-limit` option to `git log`, part of Pablo Sabater's GSoC project. This is the second patch in a 3-part series that introduces horizontal truncation of wide commit graphs in `git log --graph` output.

The patch replaces the hard-coded lane limit from the previous patch with a user-configurable `--graph-lane-limit=<n>` option. When the graph exceeds the specified number of lanes, excess lanes are shown as '~` characters while preserving commit markers ('*'). The option requires `--graph` and treats zero/negative values as "no limit" (the default).

Key implementation details:
- Adds `graph_max_lanes` field to `struct rev_info`
- Modifies graph.c's rendering logic to respect the limit
- Includes comprehensive tests showing truncation scenarios
- Documents the new option in rev-list-options.adoc

The patch follows Johannes Sixt's suggested organization, with this middle patch focusing on the user-facing option after establishing core behavior in patch 1. All technical feedback from previous iterations appears addressed, with Junio C Hamano now providing final mentoring on Git's code comprehension norms rather than requesting implementation changes.

This is a well-structured addition that cleanly solves the problem of unreadably wide graphs in terminals while preserving the graph's structural information. The thorough test coverage and clear documentation make this likely to be a useful and maintainable feature.
