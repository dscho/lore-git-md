Documentation patch clarifying gitignore behavior for repository-level exclude files.

Shreyansh Paliwal follows up on Dan Drake's report and Junio Hamano's confirmation with a straightforward documentation update. The patch clarifies that patterns in `.git/info/exclude` and `core.excludesFile` are treated as if they were specified at the repository root, meaning leading slashes anchor to the root directory. This corrects the previous documentation which incorrectly stated these patterns were relative to the file location.

The change is minimal and well-targeted, adding just a few lines to the "PATTERN FORMAT" section of gitignore.adoc. It maintains the existing documentation style while making the special case for repository-level ignore files explicit. The patch includes Dan Drake's Reported-by tag, properly crediting the original report.

This is exactly the kind of documentation fix Junio invited in the thread, and given the maintainer's prior confirmation of the behavior, the patch should be uncontroversial. It would be surprising if this didn't get merged quickly, as it just codifies the long-standing (20+ year) behavior that was previously undocumented.
