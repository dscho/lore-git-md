This is the second patch in Pablo Sabater's v6 series introducing a `--graph-lane-limit` option for `git log --graph`. The feature allows capping the number of displayed graph columns to improve readability of complex histories in terminal output.

The patch replaces the hard-coded lane limit from the previous patch with a user-configurable `--graph-lane-limit=<n>` option that requires `--graph`. Values <= 0 are treated as "no limit" (the default). The implementation modifies graph.c's rendering logic to respect the limit while maintaining connectivity markers, showing excess lanes as '~' characters.

Key technical details:
- Adds `graph_max_lanes` field to `struct rev_info`
- Updates `graph_needs_truncation()` to check against the configured limit
- Modifies lane width capping calculations in `graph_update_columns()`
- Adds comprehensive tests demonstrating truncation behaviors
- Documents the option in rev-list-options.adoc
- Enforces `--graph` requirement via setup_revisions()

The patch builds on the core truncation behavior from patch 1/3, now making it configurable. Test cases verify correct handling of octopus merges and multi-parent scenarios at various limit values. The implementation appears thorough, with all prior technical feedback from reviewers addressed. This positions the series well for final review and potential inclusion.
