Documentation patch clarifying gitignore behavior for repository-level exclude files.

Shreyansh Paliwal follows up on Dan Drake's report and Junio Hamano's confirmation with a straightforward documentation update to the gitignore(5) manpage. The patch adds explicit text stating that patterns in `.git/info/exclude` and `core.excludesFile` are treated as root-relative, unlike regular `.gitignore` files where patterns are relative to the containing directory. This matches the actual behavior that has existed for 20+ years but was previously undocumented.

The change is well-formed and uncontroversial, adding exactly the clarification Junio invited in the parent email. The patch follows standard documentation style, using the same terminology as surrounding text and placing the new paragraph logically within the "PATTERN FORMAT" section. It includes both the technical explanation and a practical example (the effect of leading slashes) that will help users understand the distinction.
