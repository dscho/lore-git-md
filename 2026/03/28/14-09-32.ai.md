This is a refactoring patch that's part of the ongoing `the_repository` removal effort. Shreyansh Paliwal continues their series by making branch name helper functions explicitly repository-aware, eliminating implicit dependencies on global state.

The patch focuses on branch-related functions in refs.c and their callers, particularly `copy_branchname()` and `check_branch_ref()`. These functions previously relied on `the_repository` when calling `repo_interpret_branch_name()`. The changes propagate through several layers of branch validation helpers (`validate_branchname()`, `validate_new_branchname()`) and their call sites in builtin commands like checkout, branch, and worktree.

Key technical changes include:
- Adding `struct repository *` parameters to branch helper functions
- Updating all call sites to pass the repository context explicitly
- Maintaining existing behavior while removing global state
- Following codebase conventions by placing repository parameters first

The changes are mechanical but wide-ranging, touching multiple files across the refs implementation and builtin commands. This appears to be a well-scoped incremental step in the larger effort to make Git's codebase more explicit about repository context. The patch builds on previous work (jw/object-name-bitset-to-enum) and follows established patterns from René Scharfe's long-running `the_repository` removal effort.
