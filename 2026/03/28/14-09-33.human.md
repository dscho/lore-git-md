This is a refactoring patch that's part of the ongoing `the_repository` removal effort. It's the second in a 5-patch series from Shreyansh Paliwal that makes the refs subsystem more repository-aware by eliminating global state usage.

The patch focuses on making `get_files_ref_lock_timeout_ms()` repository-aware by having it take a `struct repository` parameter instead of implicitly using `the_repository`. This affects how Git handles timeouts when locking refs in the files backend. The changes include:

1. Adding the repository parameter to the function signature
2. Updating callers to pass the correct repository context
3. Introducing a small wrapper struct (`create_reflock_cb`) to pass both lock_file and repository through callback contexts

The implementation looks clean and follows established patterns for this kind of conversion. Review feedback from Patrick Steinhardt in v1 has been incorporated, particularly around function signature conventions. The patch maintains existing behavior while making the repository context explicit.

This is a mechanical but important step in the larger effort to remove global state from Git's codebase. The changes are focused and well-contained, touching only the necessary files while keeping the diff size manageable. The patch appears ready for inclusion, though reviewers may want to double-check the callback wrapper design.
