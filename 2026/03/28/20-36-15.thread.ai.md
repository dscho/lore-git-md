Siddharth Asthana's implementation of dynamic mailmap toggling for `git cat-file --batch-command` is finalized in v5 and ready for merging. The feature adds a `mailmap <bool>` subcommand accepting standard Git boolean values (yes/no, true/false, on/off) to control name/email rewriting dynamically, addressing GitLab Gitaly's need to modify mailmap behavior in long-running processes without restarting.

Technical implementation includes lazy-loaded mailmap data caching (loaded on first use and preserved when disabled), restructured dispatch logic in `builtin/cat-file.c` with unified `parse_cmd_mailmap` function using `git_parse_maybe_bool()`, and comprehensive test coverage in `t/t4203-mailmap.sh`. The interface is documented with the subtle difference from Git config syntax where the argument cannot be omitted to mean "true" and empty strings are interpreted as "false".

All review feedback from Junio Hamano (documentation focus), Patrick Steinhardt (boolean parsing), Karthik Nayak (documentation structure), and Jean-Noël Avila (AsciiDoc formatting) has been incorporated. The final v5 patch simplifies documentation to focus on user-visible behavior while noting one-time data loading, removing implementation details about internal caching as suggested by Junio. Changes remain well-scoped to `builtin/cat-file.c` and its tests, with consensus that the implementation satisfies GitLab's use case and is ready for merging into mainline.
