This is the final patch in Pablo Sabater's v6 series adding a `--graph-lane-limit` option to `git log --graph`. The patch focuses on visual polish, introducing a '~' character to indicate where graph columns have been truncated due to the lane limit.

The change makes it visually clear when lanes are being hidden, addressing a usability concern that wasn't fully resolved in earlier versions. The '~' marker was chosen because it doesn't conflict with existing graph symbols. The patch updates both the core graph output logic and the test expectations to reflect this new visual indicator.

This completes the three-patch structure suggested by Johannes Sixt: core behavior first (patch 1), then the user-facing option (patch 2), and now the visual polish (patch 3). The implementation appears solid, with thorough test coverage showing the truncation markers in various merge-heavy scenarios. 

With all technical feedback addressed and now adding this final clarity improvement, the series looks ready for inclusion.
