This is a technical clarification in Patrick Steinhardt's build system series introducing precompiled header (PCH) support. Toon Claes confirms his understanding of how the warning suppression mechanism works with the new PCH approach.

The key point is that moving the `DISABLE_SIGN_COMPARE_WARNINGS` pragma outside the include guards in `git-compat-util.h` (as done in patch 6/8) allows it to work correctly with PCHs. When a compilation unit includes `tools/precompiled.h` (the PCH entry point), it gets the precompiled version of `git-compat-util.h` without knowing whether warnings should be suppressed. The actual `.c` file can then define `DISABLE_SIGN_COMPARE_WARNINGS` and have it take effect on the second include, since the pragma is now after the guards.
