This is part 9/14 of Patrick Steinhardt's series to make object name lookups more extensible, continuing the ODB abstraction effort. The patch merges two related functions (`update_candidates()` and `match_prefix()`) into a single `update_disambiguate_state()` function that handles both roles.

The change is a straightforward refactoring that eliminates an unnecessary wrapper function while maintaining the same behavior. The key points are:

1. The previous implementation had `match_prefix()` as a thin wrapper around `update_candidates()`, with the only difference being that `match_prefix()` returned the ambiguous state. This patch combines them into one function that handles both responsibilities.

2. The new `update_disambiguate_state()` function now directly returns the ambiguous state (0 or 1) rather than just updating the disambiguation state structure. This makes the control flow more explicit while keeping the same logic.

3. All callers are updated to use the new unified function, including both the object-file iteration and the ODB-wide iteration paths. The changes are mechanical and don't affect behavior.
