This is patch 5/14 in Patrick Steinhardt's ongoing ODB abstraction series, continuing the work to make object name lookups more extensible for pluggable backends. The patch moves the logic for iterating through packed objects with a given prefix from `object-name.c` to `packfile.c`, completing the relocation of prefix-based iteration that began in the previous patch.

The changes:
- Extract and relocate the `match_hash()` helper function and all packed object iteration logic (`unique_in_midx()` and `unique_in_pack()`) to `packfile.c`
- Replace the direct iteration calls in `find_short_packed_object()` with a new `packfile_store_for_each_prefixed_object()` interface
- Add comprehensive new implementations for MIDX and single-pack iteration that properly handle the prefix matching
- Maintain all existing behavior while making the code more modular

The patch continues the series' pattern of separating concerns between:
- `object-name.c` handling disambiguation logic
- `packfile.c` implementing storage-specific operations
- Key technical details:
  - Introduces new `for_each_prefixed_object_in_midx()` and `for_each_prefixed_object_in_pack()` helpers
  - Adds proper error handling throughout the relocated code
  - Maintains the same binary search and prefix matching behavior
  - Updates callers to use the new interface

This is a mechanical but important step in the ODB abstraction effort, further decoupling the object naming/disambiguation logic from the storage implementation details. The changes are well-contained and follow the established pattern from previous patches in the series. Given Patrick's track record with this refactoring and the lack of controversy in previous iterations, this patch is likely to proceed smoothly through review.
