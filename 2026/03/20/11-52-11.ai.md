Feature patch in Adrian Ratiu's hook configuration series, adding disabled hook visibility to `git hook list`. This is the final patch in a 10-part series that has been through multiple review iterations and is now queued for integration.

The patch makes disabled hooks visible in `git hook list` output, marking them with a "disabled" prefix (or "disabled\t" when combined with `--show-scope`). Previously these hooks were silently filtered out. The implementation:
- Adds a `disabled` flag to both the cache entry and hook struct
- Modifies output formatting to include disabled status while maintaining the tab-separated format established earlier in the series
- Changes error handling to warn rather than die for disabled hooks without commands
- Updates `hook_exists()` to skip disabled hooks when checking availability
- Adds comprehensive tests covering the new behaviors

The changes align with the series' goal of making hook configuration more transparent and manageable. The implementation appears solid, with careful attention to backward compatibility and consistent behavior with the existing hook execution logic (which already skips disabled hooks). Test coverage is thorough, verifying both the display formatting and behavioral changes.

This completes the series' work on core hook configuration visibility, leaving the infrastructure in place for future metadata additions via the `hook_config_cache_entry` struct introduced earlier. The patch follows established patterns from prior iterations and addresses all outstanding feedback from reviewers.
