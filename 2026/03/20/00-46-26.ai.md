This is a refactoring patch that expands René Scharfe's earlier work to simplify strvec handling by adding a Coccinelle semantic patch to automate the conversion of manual strvec loops to `strvec_pushv()` calls. The v2 patch follows up on Junio C Hamano's suggestion to generalize the approach across the codebase.

The patch introduces a new Coccinelle rule in contrib/coccinelle/strvec.cocci that automatically detects and converts patterns where elements from one strvec are pushed individually to another via a loop, replacing them with a single `strvec_pushv()` call. The rule handles several variants including separate loop index declarations and unused indices.

In addition to the three conversions from v1 (fetch-pack.c, git.c, submodule.c), this version adds a new conversion in builtin/rebase.c where trailer arguments are copied between strvecs. The semantic patch is comprehensive enough to catch similar patterns throughout the codebase, making this a maintainable solution for future similar cases.

This is a typical René Scharfe contribution - a mechanical but thoughtful cleanup that improves code hygiene without changing behavior. The Coccinelle approach ensures consistency and reduces the chance of manual conversion errors. Given Junio's positive reception of the initial patch and René's reputation for careful refactoring work, this change is likely to be accepted without controversy.
