This is a bugfix for Git's bisect functionality, addressing an inconsistency in how alternate bisect terms are displayed. The patch ensures that when users specify custom terms (like "old/new" instead of "good/bad"), those terms are used consistently throughout the bisect output rather than falling back to the default "good/bad" terminology.

The issue arises when users employ `git bisect start --term-new=old --term-old=new` to customize the bisect process - the internal state messages would show the hardcoded "good/bad" terms, which could be confusing. The patch updates several status messages in builtin/bisect.c to use the selected terms from the bisect_terms struct rather than the defaults.

The change is straightforward and well-motivated, with the commit message clearly explaining the problem and solution. The patch touches only the output messages, not the underlying bisect logic, and maintains all existing functionality while improving consistency. This should help users who prefer alternate terminology for their bisect operations.
