This is a follow-up discussion in the `user.signoffcomment` feature thread, where maintainer Junio C Hamano expands on his earlier concerns about the proposed Signed-off-by line customization. The email introduces new architectural considerations that would need resolution before such a feature could be accepted.

Junio suggests a more generalized approach to identity configuration, proposing a three-level scheme (`user.<context>.name/email`) that could handle different identity formats for author, committer, tagger, and potentially sign-off contexts. This would extend the existing `enum want_ident` in `ident.c` rather than adding a one-off comment mechanism. He notes this could allow project-specific sign-off identities (like "Uwe Kleine-König (Current Sponsor)") while keeping global defaults.

The maintainer raises deeper philosophical concerns about whether varying identities within a single project is desirable, even if technically possible. This touches on Git's historical approach where identities are typically consistent across a commit's metadata. The reply maintains Junio's characteristic focus on long-term maintainability, suggesting the proposal needs to address both the technical implementation (how to structure the configuration) and the conceptual model (whether per-context identities align with Git's design principles).

Key unresolved questions now include: whether to implement a general identity-context system versus the original comment-only approach, how to handle project-local versus global identity configuration, and whether the use case justifies diverging from Git's traditional single-identity-per-project practice. The discussion has clearly moved beyond the initial implementation details to more fundamental design considerations that will require significant iteration.
