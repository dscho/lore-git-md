This is a refactoring patch in Adrian Ratiu's hook configuration series, focusing on cleanup and API simplification. The patch replaces a custom hook list clearing function with Git's standard `string_list_clear_func()` pattern, making the code more consistent with the project's idioms.

The key change moves from a specialized `hook_list_clear()` that took a list and callback to using the more generic `string_list_clear_func()` with a new `hook_free()` helper. This required storing the data-free callback in the hook struct itself rather than passing it at cleanup time. The patch maintains all existing functionality while reducing custom code.

The changes touch the hook subsystem internals, modifying how hook state is cleaned up when hooks are no longer needed. This is part of Adrian's larger effort to improve Git's hook configuration capabilities, with this particular patch addressing code organization and maintainability rather than adding user-facing features. The implementation appears clean and well-motivated, following Patrick Steinhardt's suggestion to align with common Git patterns.
