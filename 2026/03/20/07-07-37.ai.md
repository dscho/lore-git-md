This is patch 11/14 in Patrick Steinhardt's series refactoring object name handling as part of the ODB abstraction effort. The patch simplifies how Git computes common prefixes between object IDs by introducing a new `oid_common_prefix_hexlen()` function that compares binary OIDs directly rather than converting to hex strings first.

The key changes are:
1. Adds `oid_common_prefix_hexlen()` to hash.c/hash.h to efficiently find the length of matching hex digits between two OIDs by comparing their binary representations
2. Removes the now-unnecessary `hex` field from `struct min_abbrev_data` since the hex string is no longer needed
3. Updates `extend_abbrev_len()` to use the new function, making the code both simpler and more efficient by avoiding hex conversion

This is a clean optimization that maintains the exact same behavior while removing an unnecessary conversion step. The patch follows the series' pattern of methodically improving the object name handling infrastructure while keeping the changes focused and well-contained. The new function will also be reused in subsequent patches, showing good forward-looking design.

The change touches core object handling code but is low-risk since it's a straightforward optimization with clear test coverage. As with the rest of the series, this moves toward the goal of making object name lookups properly extensible for alternative storage backends.
