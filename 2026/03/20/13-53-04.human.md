This is a feature patch (part 2/9 in the series) that adds the foundational plumbing for parallel hook execution by introducing the global `hook.jobs` configuration. The patch focuses on parsing and storing the configuration value that will control how many hooks can run simultaneously.

The key changes are:
1. Adds documentation entry for `hook.jobs` in `hook.adoc`
2. Extends the hook configuration callback to parse `hook.jobs` values (with validation for positive integers)
3. Stores the parsed value in the repository struct's new `hook_jobs` field
4. Maintains backward-compatible default of 1 (serial execution) when unset

This is primarily infrastructure work - the actual parallel execution logic comes in later patches. The implementation follows Git's standard config parsing patterns and includes appropriate warnings for invalid values. The patch builds on Adrian Ratiu's prior configurable hooks work and has already received maintainer ack for the overall approach in earlier versions of the series.
