This is a performance optimization patch in Patrick Steinhardt's ongoing ODB abstraction series (11/14), with Karthik Nayak providing a detailed review. The patch simplifies how Git computes common prefixes between object IDs during abbreviation by introducing a new `oid_common_prefix_hexlen()` function that compares binary object IDs directly rather than first converting them to hex strings.

Karthik's review confirms the technical soundness of the approach, walking through the bit manipulation logic in detail. He notes the new function properly handles the case where only part of a byte matches (the final nibble) and explains how this replaces the previous roundabout method of comparing hex strings. The change removes the need for the `hex` field in `struct min_abbrev_data` and makes the code more efficient by avoiding unnecessary hex conversions.

This continues the series' pattern of methodical refactoring to support pluggable object backends. Karthik's approval ("The patch looks good") indicates this piece is ready to proceed, with the change being well-contained in `hash.c` and `object-name.c`. The new function will also be reusable in future changes, as noted in the commit message. This represents another incremental improvement in the larger ODB abstraction effort.
