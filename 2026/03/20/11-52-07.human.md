This is a documentation patch from Adrian Ratiu, part of his 10-patch series improving Git's hook configuration system. The patch standardizes terminology in the documentation and code comments, replacing inconsistent uses of "name" with "friendly-name" when referring to hook identifiers in configuration keys.

The change was suggested by Junio Hamano to make the terminology more precise, since "name" is too generic in the hooks context. The patch updates both man pages and internal comments to consistently use "friendly-name" when referring to the user-defined identifier portion of hook configuration keys (like `hook.linter.command`).

This is a straightforward cleanup that doesn't change any functionality, just improves documentation clarity. It's one of several small refinements being made as Adrian's hook configuration work gets ready for integration. The series as a whole has already gone through review iterations and appears well-polished.
