This is a follow-up in the macOS regex compatibility thread, where Junio C Hamano responds to René Scharfe's research about the REG_ENHANCED flag availability. The discussion centers around unexpected CI failures on macOS 14 despite historical evidence suggesting the flag should be present.

Junio notes the failures appeared suddenly in today's CI runs without any corresponding Git changes, and points out that other macOS 14 jobs in the same CI run are passing successfully. This observation leads him to conclude that his initial patch proposal (which would have conditionally disabled REG_ENHANCED) is actually the wrong approach, as it would mask the underlying issue rather than solve it. He's particularly concerned this could silently break regex tests that rely on enhanced mode functionality.

The technical heart of the matter remains the mysterious absence of REG_ENHANCED in some macOS 14 CI environments, despite René's documentation showing it existed in macOS 10.12 and later. Junio's response shifts the focus from working around the missing flag to understanding why it's missing in the first place, suggesting the CI environment itself might be misconfigured or inconsistent. This moves the thread toward needing deeper investigation of the CI setup rather than a code change.
