This is a platform compatibility discussion about macOS regex handling, continuing the investigation into CI build failures. Junio Hamano responds to Johannes Schindelin's proposed `NO_REGEX` workaround for missing `REG_ENHANCED` flag in Homebrew's clang.

Junio raises an important concern about potential functionality loss when bypassing the system regex library, questioning whether the tradeoff is acceptable. He suggests an alternative approach - forcing the build to use `/usr/bin/clang` (Apple's system version) rather than Homebrew's clang, as previously proposed by René Scharfe. This would maintain access to Apple's regex extensions while avoiding the CI failures.

The discussion has now narrowed to evaluating two solution paths: Schindelin's `NO_REGEX` approach (which sacrifices some regex features for consistency) versus the clang redirection approach (which preserves functionality but may have other implications). Junio's response indicates he's leaning toward preserving regex capabilities if possible, making this a key decision point in the thread.
