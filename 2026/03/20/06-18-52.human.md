Performance-focused benchmark results for strbuf_getwholeline() buffer reuse.

Jeff King (Peff) provides concrete measurements showing the performance impact of Junio Hamano's proposed strbuf_getwholeline() changes. Using `git cat-file --batch-check` on a Linux kernel repository as a benchmark, Peff demonstrates a 7% slowdown when forcing fresh buffer allocations on each call rather than reusing the existing strbuf buffer. While acknowledging this is an extreme case, the results show the optimization provides meaningful real-world benefits.

The benchmark methodology is sound - using a real-world repository (linux.git) and a command that stresses line-reading performance (`git cat-file --batch-check`). The results show consistent slowdowns across multiple runs, with the patched version taking about 200-300ms longer. Peff notes this overhead remains proportionally smaller but still present when the command does more work per line.

This email advances the discussion by moving from theoretical concerns to concrete data.
