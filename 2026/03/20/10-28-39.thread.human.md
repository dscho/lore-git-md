This thread explores a proposal to add a `user.signoffcomment` configuration option that would let contributors append organizational affiliation notes to their Signed-off-by lines (e.g., "Uwe Kleine-König <u.kleine-koenig@pengutronix.de> (for Kernel Concepts)"). The initial implementation from Uwe Kleine-König addresses a real need for consultants and corporate contributors to note client affiliations while maintaining Developer Certificate of Origin compliance.

Maintainer Junio C Hamano has raised substantial concerns that go beyond the immediate implementation. While not rejecting the use case outright, he questions whether modifying Signed-off-by lines is the right approach given potential ripple effects across Git's toolchain—particularly for commands that parse identities (like `git log --author`). He suggests a more generalized identity configuration system (`user.<context>.name/email`) that could handle different formats for authors, committers, and sign-offs, rather than a one-off comment mechanism. This would require careful design to address project-local versus global identity needs.

The discussion has evolved from technical specifics to broader philosophical questions about whether varying identities within a project align with Git's design principles. Junio's feedback indicates that any solution will need to demonstrate not just that it works, but that it fits coherently into Git's ecosystem without creating maintenance burdens or breaking assumptions elsewhere. The path forward likely involves significant design iteration to address these concerns before the feature could be reconsidered for inclusion.
