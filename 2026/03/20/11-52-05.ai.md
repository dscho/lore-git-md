This is a bugfix patch in Adrian Ratiu's ongoing hook configuration series, specifically addressing two potential error cases in the hook execution path. The patch adds defensive programming checks to catch invalid hook states that could lead to undefined behavior.

The changes detect and report two specific error conditions:
1. When a configured hook is marked as enabled but has no actual command to execute (which would result in an empty shell invocation)
2. When an unknown hook type is encountered during execution setup

Both cases now trigger Git's BUG() macro, which will terminate with an error message rather than proceeding with invalid state. The implementation is minimal - just two BUG() calls added to hook.c with accompanying condition checks.

The patch follows the series' focus on robustness in the hook subsystem, and appears straightforward with no obvious issues. It implements a suggestion from Patrick Steinhardt to add these defensive checks. As part of a larger series that's already been reviewed and queued for integration, this patch seems uncontroversial and likely to be merged as-is.
