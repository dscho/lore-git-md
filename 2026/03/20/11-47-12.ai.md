This is patch 7/14 in Patrick Steinhardt's series to remove `the_repository` dependencies from the fsck subsystem. The patch focuses on the ref snapshotting functionality in `builtin/fsck.c`.

The change introduces a new `struct snapshot_ref_data` to pass both the repository and snapshot context through the ref iteration callback chain, replacing direct usage of `the_repository`. The key modifications are:

1. The `snapshot_ref()` callback now receives a `struct snapshot_ref_data` containing both the repository and snapshot pointers, rather than just the snapshot.
2. All calls to repository-dependent functions (`parse_object()` and `is_promisor_object()`) are updated to use the passed repository instead of `the_repository`.
3. The ref iteration calls in `snapshot_refs()` are updated to pass the new context structure.

The patch maintains the same behavior while removing the global state dependence. It's a mechanical but necessary refactoring that follows the pattern established in earlier patches of the series. The changes are focused and well-contained, touching only the fsck builtin's ref snapshotting logic. This continues the series' consistent approach of converting implicit global state to explicit parameter passing.
