This is a feature patch (7/9 in the series) introducing per-event job control for Git hooks, building on Adrian Ratiu's parallel hook execution work. The patch adds a new `hook.<event>.jobs` configuration that allows overriding the global `hook.jobs` setting for specific hook events, providing finer-grained control over parallelism.

The implementation stores per-event job counts in a new `event_jobs` strmap in the repository struct, with values cached alongside the existing hook configuration. The precedence rules are clear: per-event jobs override the global setting, but still require all hooks for that event to be marked as parallel-safe via `hook.<name>.parallel=true`. The patch includes comprehensive documentation explaining the interaction between these settings and adds three new test cases verifying the override behavior.

Key technical changes include:
- New strmap event_jobs in struct repository to cache per-event job counts
- Updates to get_hook_jobs() to check for event-specific overrides
- Repository lifecycle management for the new cache
- Documentation clarifying the distinction between per-hook and per-event settings
- Tests covering:
  - Per-event override allowing parallel when global is serial
  - Per-event override forcing serial when global allows parallel
  - Requirement that hooks still need parallel=true regardless of event jobs setting

The patch fits cleanly into the series' existing architecture while adding another layer of control. It maintains all the safety mechanisms from earlier patches (parallel flag requirements, output stream handling) while giving users more flexibility in configuring parallelism. The implementation appears well-considered, with clear commit message and thorough test coverage.
