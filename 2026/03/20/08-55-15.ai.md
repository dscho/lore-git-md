This is a platform compatibility fix addressing macOS CI failures related to regex handling. Johannes Schindelin provides a detailed analysis and solution for build failures that emerged when GitHub Actions runners updated their Homebrew installation, causing `clang` to silently switch from Apple's system version to Homebrew's LLVM 15.0.7.

The core issue stems from Homebrew's clang using different include paths that lack the `REG_ENHANCED` flag (an Apple-specific extension), while Git's build system assumed this flag would be available on all Darwin platforms. Schindelin traces the exact chain of events: Homebrew 5.1.0's new auto-linking behavior changed which `clang` gets used, and the different header paths exposed the missing flag.

The proposed solution adds `NO_REGEX` to the Darwin configuration when using `clang`, forcing Git to use its bundled regex implementation instead of the system one. This maintains consistent behavior while properly documenting the platform limitation. The patch includes extensive background in the commit message explaining the root cause, affected configurations, and why this solution is preferable to alternatives like Junio's earlier behavior-changing workaround.

Key technical details include the precise Homebrew version change (5.0.15 to 5.1.0), the PATH resolution difference, and how meson build's robust feature detection avoided this issue. The solution is narrowly targeted to only affect the problematic configuration while leaving other build scenarios unchanged.
