This is patch 11 in Patrick Steinhardt's 14-part series to remove `the_repository` usage from Git's fsck subsystem. The patch focuses on eliminating implicit repository access when checking packed objects.

The key change modifies `verify_pack()` and related functions in the pack-check subsystem to accept and pass through a callback data parameter. This allows the fsck callback (`fsck_obj_buffer`) to receive the repository instance explicitly rather than relying on `the_repository`. The patch updates:
- The `verify_fn` callback signature to include a `void *fn_data` parameter
- `verify_packfile()` and `verify_pack()` to pass through the callback data
- `fsck_obj_buffer()` to use the passed data (casting it to `struct repository *`)
- All call sites to provide the repository parameter

The changes are mechanical but necessary plumbing to maintain functionality while removing global state. The patch maintains the same behavior while making the repository dependency explicit. This continues the series' pattern of methodically converting each fsck-related code path to work without `the_repository`.

The patch touches core packfile verification infrastructure, so reviewers will likely scrutinize the callback signature changes for any potential impacts on other pack-checking code paths. The changes appear straightforward and focused solely on the fsck use case.
