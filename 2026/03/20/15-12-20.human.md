This is a platform compatibility discussion about macOS regex handling, continuing the investigation into CI failures caused by Homebrew's clang lacking the REG_ENHANCED flag. Johannes Schindelin responds to René Scharfe's alternative proposal in the ongoing thread.

Schindelin acknowledges René's technical explanation that the root cause is __MAC_OS_X_VERSION_MIN_REQUIRED not being properly defined in Homebrew's clang environment. While agreeing with the analysis, Schindelin expresses reservations about René's suggested solution of hardcoding /usr/bin/clang usage on macOS. He argues this would only fix CI while potentially exposing end users who set CC=clang to the same issue.

The discussion highlights the tradeoffs between two valid approaches: Schindelin's NO_REGEX solution (which handles the environment as-is by falling back to Git's bundled regex) versus René's proposal (which enforces toolchain consistency by always using system clang). Both solutions would address the immediate CI failure, but with different implications for user builds.

Schindelin notes he cannot test locally without a macOS setup, and observes that CI runners may exhibit different behavior than developer machines due to being built from scratch. The thread demonstrates careful consideration of both technical correctness and real-world usability impacts in resolving this subtle build system issue.
