This is a refactoring patch from Patrick Steinhardt that continues his object database (ODB) abstraction work, specifically focusing on the oidtree implementation. The patch modifies the crit-bit tree (cbtree) and oidtree iteration interfaces to allow callback functions to return arbitrary values rather than being restricted to CB_CONTINUE/CB_BREAK constants.

The key changes include:
- Converting the cb_each() and related functions to return an int instead of void
- Changing the callback typedef to return int rather than enum cb_next
- Updating all callers (including oidtree and test code) to match the new interface
- Improving documentation to clarify the new callback behavior

This change enables a more natural error-handling pattern where callers can propagate error codes directly through the iteration. The patch maintains all existing functionality while making the interface more flexible for future use cases. It's part of Patrick's larger 14-part series refactoring object name handling to support alternative storage backends.

The changes are mechanical but well-contained, touching only the cbtree/oidtree subsystems and their immediate callers. The patch follows the established pattern of the series and has already incorporated feedback from earlier reviews (as noted in the thread context). Given Patrick's track record with this kind of refactoring and the uncontested technical direction of the ODB abstraction work, this appears to be a straightforward improvement that moves the project forward.
