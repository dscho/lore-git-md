This is a refactoring patch from René Scharfe that follows up on his earlier work to simplify strvec handling. The v2 patch adds a Coccinelle semantic patch to automate converting manual loops that copy strvec elements into single `strvec_pushv()` calls, as suggested by Junio Hamano.

The patch introduces a new Coccinelle rule in `contrib/coccinelle/strvec.cocci` that matches several patterns of for-loops copying strvec elements and replaces them with `strvec_pushv()`. It also applies this conversion to one additional case in `builtin/rebase.c` that wasn't covered in v1, while keeping the previous conversions in `fetch-pack.c`, `git.c`, and `submodule.c`.

This is a typical René Scharfe contribution - a clean, mechanical refactoring that improves code hygiene without changing behavior. The Coccinelle rule will help prevent similar manual loops from being written in the future. The changes are straightforward and unlikely to be controversial, building on the positive reception of the initial patch. The semantic patch appears well-crafted to handle various loop declaration styles while avoiding false positives.
