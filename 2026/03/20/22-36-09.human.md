This is a follow-up discussion in the thread about adding `user.signoffcomment` configuration for customizing Signed-off-by lines. Maintainer Junio C Hamano expands on his earlier concerns with additional architectural considerations.

The email suggests a more general approach than the original patch's focused solution - proposing a three-level configuration scheme (`user.<context>.name/email`) that could handle different identities for author/committer/tagger contexts. This would allow per-context customization without special-case syntax. Junio notes this could naturally extend Git's existing `enum want_ident` mechanism.

However, he expresses skepticism about the fundamental premise of using different identities within a single project, suggesting this may create more problems than it solves. The tone remains constructive but maintains the high bar for changes that affect identity handling across Git's toolchain.

Key new considerations raised:
1. A more generalized identity context system as an alternative to comment-specific syntax
2. Questions about the wisdom of varying identities within one project
3. Implicitly sets a higher design standard - solutions should address identity handling holistically rather than just the immediate use case

The discussion remains open but makes clear the patch needs significant design iteration to address these broader concerns before being mergeable. Junio's response exemplifies Git's conservative approach to changes affecting core subsystems with wide-ranging implications.
