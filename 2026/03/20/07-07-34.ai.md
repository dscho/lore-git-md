This is patch 8/14 in Patrick Steinhardt's ongoing ODB abstraction series, continuing the effort to make object name lookups backend-generic. The patch refactors `get_short_oid()` to use the new `odb_for_each_object()` interface rather than backend-specific functions.

The key change replaces the separate `find_short_object_filename()` (for loose objects) and `find_short_packed_object()` (for packed objects) calls with a single `odb_for_each_object_ext()` call. This unifies the ambiguous object collection logic under the ODB abstraction layer, allowing it to work with any backend implementation. The now-unused `find_short_packed_object()` function is removed entirely.

The patch maintains the same behavior while making the code more extensible - it still handles the same cases of ambiguous prefixes and retries after reprepare if objects are missing. The changes are mechanical and follow the established pattern from earlier patches in the series.

This continues the systematic decomposition of object name handling that separates core disambiguation logic in `object-name.c` from backend-specific operations. The changes align with the series' overall goal of enabling pluggable storage backends while preserving existing functionality. Given the careful progression of this refactoring and Patrick's track record with major architectural changes, this patch appears ready for inclusion.
