This is part 3/9 of a feature patch series introducing parallel hook execution, building on Adrian Ratiu's prior configurable hooks work. The patch implements the core parallel execution logic, allowing multiple hooks for a single event to run concurrently when explicitly configured.

The patch introduces several key mechanisms:
- A new `hook.<name>.parallel` config option that must be set to `true` for each hook that can safely run in parallel (defaults to false for safety)
- Logic to determine the effective job count, respecting both global `hook.jobs` and per-hook parallel flags
- Special handling to ensure hooks requiring separate output streams (like pre-push) always run sequentially
- Comprehensive tests verifying serial vs parallel behavior using sentinel files to detect execution timing

The implementation carefully layers controls:
1. CLI `-j/--jobs` override takes highest precedence
2. Per-hook `hook.<name>.parallel` flags must all be true for parallel execution
3. Global `hook.jobs` provides the default job count
4. Fallback to serial execution (jobs=1) if any of the above indicate it's unsafe

The patch includes extensive test coverage in t/t1800-hook.sh, with scenarios testing:
- Explicit job counts via config
- Per-hook parallel flags
- Mixed parallel/non-parallel hooks
- Default serial fallback behavior

This builds on the foundation from patches 1-2 (config infrastructure and `hook.jobs`) while leaving room for follow-up work in later patches (like special-casing the pre-push hook).
