This is a feature patch in Adrian Ratiu's parallel hook execution series, specifically addressing the pre-push hook's special handling. The patch enables parallel execution for pre-push hooks while maintaining backward compatibility.

The key change is that pre-push hooks, which traditionally kept stdout and stderr separate (important for tools like git-lfs), can now run in parallel when explicitly requested via `hook.jobs > 1` or `-jN`. When parallel execution is enabled, stdout is automatically merged into stderr to allow proper output buffering and de-interleaving. The patch documents this behavior change and adds comprehensive tests verifying both the output merging and actual parallel execution of pre-push hooks.

The implementation is clean and maintains the series' careful layering of controls - parallel execution remains opt-in at multiple levels (global config, per-hook flag, CLI override). The tests added in t/t1800-hook.sh demonstrate both the output stream behavior and actual parallel execution of pre-push hooks when configured appropriately.

This patch follows naturally from the foundational work in earlier parts of the series and shows good attention to backward compatibility while still enabling the new functionality. The approach of making output stream merging implicit with parallel execution (rather than requiring separate configuration) simplifies the interface while preserving the needed behavior.
