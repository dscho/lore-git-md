This is patch 4/14 in Patrick Steinhardt's ongoing ODB abstraction series, continuing the effort to make object name handling backend-generic. The patch moves logic for iterating through loose objects with a given prefix from `object-name.c` to `object-file.c`, where it properly belongs as part of the object storage backend implementation.

The changes introduce structured options for prefix-based iteration through the new `odb_for_each_object_options` struct, which now includes `prefix` and `prefix_hex_len` fields. The patch also makes the `odb_source_loose_cache()` function file-scoped since it's no longer needed outside `object-file.c`.

Key technical details:
- Adds new callback `for_each_prefixed_object_wrapper_cb` to handle prefix matching
- Modifies `odb_source_loose_for_each_object` to use the prefix options
- Updates the disambiguation code in `object-name.c` to use the new interface
- Maintains all existing behavior while making the code more backend-agnostic

This is a mechanical but important step in the larger ODB abstraction effort, cleanly separating concerns between the object naming/disambiguation logic and the storage backend implementation. The changes are well-contained and follow the established pattern of the series, with no apparent behavioral changes. Given Patrick's track record with this refactoring work and the lack of controversy in previous patches, this appears to be another solid step toward the goal of pluggable object backends.
