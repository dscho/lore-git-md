This is patch 6/14 in Patrick Steinhardt's series to make object name lookups more extensible, part of the ongoing ODB abstraction effort. The patch extracts the object ID prefix parsing logic from `init_object_disambiguation()` into a new standalone function `parse_oid_prefix()`. 

The change is a straightforward refactoring that maintains all existing behavior while making the parsing logic reusable. The new function handles both hex string output (for display) and binary OID output (for internal use), with the same validation rules as before. This prepares for a future patch that will need the same parsing logic at another callsite.

As with previous patches in the series, this continues the pattern of methodically restructuring the code to support pluggable backends while maintaining backward compatibility. The change is mechanical and well-contained, touching only `object-name.c` with no behavioral changes. Given Patrick's track record with this refactoring work and the clear motivation, this patch appears ready to proceed toward inclusion.
