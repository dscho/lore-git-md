This is part 12/14 of Patrick Steinhardt's series to make object name lookups more extensible, continuing the object database (ODB) abstraction effort. The patch moves the logic for computing loose object abbreviation lengths into the ODB backend interface.

The change extracts the loose-object-specific abbreviation length calculation from `object-name.c` into a new `odb_source_loose_find_abbrev_len()` function in `object-file.c`. This follows the pattern established in earlier patches of moving storage-specific operations into the backend interface, making the code more generic while maintaining the same behavior.

The patch is a straightforward refactoring that:
1. Introduces a new callback-based helper function
2. Moves the core logic while keeping the same algorithm
3. Updates the calling code to use the new interface

This continues the series' systematic approach to making object name handling work with alternative storage backends. The changes are mechanical and well-contained, following the established pattern from previous patches in the series. Given Patrick's track record with this refactoring work and the lack of controversy in earlier patches, this appears to be another solid step toward the ODB abstraction goal.
