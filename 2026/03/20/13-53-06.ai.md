This patch enables parallel execution for the pre-push hook, which previously required special handling due to its unique stdout/stderr separation. The change makes parallel execution opt-in while maintaining backward compatibility - when no parallelism is requested (jobs=1), pre-push behaves exactly as before. When users explicitly enable parallelism (via hook.jobs > 1 or -j flag), stdout is automatically merged into stderr to allow proper output de-interleaving.

The implementation removes the need for any extension infrastructure by having get_hook_jobs() set stdout_to_stderr=1 automatically when jobs > 1. The patch includes clear documentation of this behavior change and adds comprehensive tests verifying both the merged output behavior and actual parallel execution of pre-push hooks. The transport.c changes reflect this new automatic behavior while keeping the default serial case unchanged.

This is part of Adrian Ratiu's ongoing parallel hooks series (v4 4/9) and builds on the foundational work in earlier patches. The approach shows good judgment in balancing backward compatibility with clean design, following maintainer feedback to simplify the output handling mechanism. The pre-push hook's special status as the only hook needing separate streams makes this a key test of the parallel execution infrastructure's flexibility.
