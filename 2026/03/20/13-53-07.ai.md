This is part 5/9 of a feature patch series introducing parallel hook execution. The patch marks several hooks as non-parallelizable by initializing them with RUN_HOOKS_OPT_INIT_FORCE_SERIAL, which overrides any parallel execution settings. The affected hooks are those that operate on shared state: commit message hooks (applypatch-msg, prepare-commit-msg, commit-msg), working tree/index hooks (pre-commit, post-checkout, push-to-checkout), and post-commit.

The changes update hook calls in builtin commands (am, checkout, clone, receive-pack, worktree, commit) to use the force-serial option. Documentation is added explaining why these hooks cannot be parallelized safely. A new test case verifies that hook.jobs settings are ignored for force-serial hooks, demonstrating that pre-commit hooks still run sequentially even when parallel execution is requested.

This patch builds on the parallel execution infrastructure from earlier in the series while recognizing the constraints of certain hook types. The implementation is straightforward - adding the force-serial flag to existing hook calls - but important for maintaining correctness in cases where hooks modify shared state. The test coverage helps ensure this safety mechanism works as intended.
