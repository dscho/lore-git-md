Refactoring discussion about strbuf_getwholeline() buffer management.

Junio Hamano responds to Jeff King's concerns about buffer handling in strbuf_getwholeline(), proposing a more radical simplification than previously discussed. His patch completely decouples the temporary buffer used with getdelim() from the strbuf's internal state, eliminating the need for careful buffer preservation on error paths.

The key change is replacing the current approach (which carefully preserves the strbuf's buffer for reuse) with a simpler model where getdelim() operates on an independent buffer that only gets attached to the strbuf on success. On failure (EOF or error), the temporary buffer is simply freed and the strbuf is emptied via strbuf_release(). This avoids all the edge cases around buffer reuse and NULL checks that the current implementation handles.

Junio acknowledges this makes the strbuf_reset() at function entry unnecessary (agreeing with Peff's earlier observation) and demonstrates how strbuf_attach() inherently handles the buffer transfer on success. The error path becomes trivial - just free the temporary buffer and reset the strbuf, with no special cases for slopbuf or NULL checks.

This represents a significant simplification of the function's logic at the cost of potentially more frequent allocations in the EOF case (since the buffer isn't preserved for reuse). The discussion continues to weigh this tradeoff between simplicity and performance in a core string-handling function used throughout Git's codebase.
