This is a discussion response to Uwe Kleine-König's feature patch adding `user.signoffcomment` configuration. Kristoffer Haugsbakk raises several thoughtful questions about the proposal's design and broader implications.

The response questions whether customizing Signed-off-by lines with organizational affiliations is a sufficiently common practice to warrant core Git support, though it acknowledges Linux kernel examples exist. Haugsbakk suggests alternative approaches like using commit-msg hooks with `git-interpret-trailers` to achieve similar effects without modifying the S-o-b line itself.

Key technical concerns raised include potential incompatibility with existing trailer grouping in `git-shortlog` and whether this change might compound what the response characterizes as the "historical mistake" of making Signed-off-by configurable at all (referencing Git's explicit decision not to make `commit.signoff` a default configuration). The response implies the change might encourage fragmentation of identity tracking across organizations over time.

The discussion remains constructive but signals this may be a more contentious change than the initial patch's simplicity suggests, touching on longstanding Git conventions around identity representation and the project's philosophy about what belongs in core versus hook scripts. No concrete objections to the implementation itself are raised - the concerns are primarily about design philosophy and precedent.
