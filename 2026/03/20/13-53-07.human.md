This is part 5/9 of a feature series introducing parallel hook execution, focusing on marking certain hooks as non-parallelizable. The patch identifies several hooks that must always run sequentially due to their access to shared resources like commit messages or repository state. These include commit-related hooks (applypatch-msg, prepare-commit-msg, commit-msg, pre-commit, post-commit) and checkout-related hooks (post-checkout, push-to-checkout).

The changes enforce serial execution by initializing these hooks with RUN_HOOKS_OPT_INIT_FORCE_SERIAL, which overrides any parallel execution settings. The patch updates hook calls in builtin commands (am, checkout, clone, receive-pack, worktree, commit) and adds documentation explaining why these hooks can't be parallelized. A new test case verifies that hook.jobs is ignored for force-serial hooks like pre-commit.

This patch builds on the parallel execution infrastructure from earlier in the series while recognizing practical limitations for certain hook types. The implementation appears thorough, touching all relevant call sites and maintaining backward compatibility. The documentation clearly explains the constraints while the test provides concrete verification of the serial execution guarantee.
