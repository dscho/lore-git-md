This is a refactoring patch from Patrick Steinhardt that continues his object database (ODB) abstraction series. It's patch 7/14 in the v2 series aimed at making object name lookups more extensible for alternative storage backends.

The patch replaces the backend-specific `repo_collect_ambiguous()` implementation with a generic version that uses the new odb_for_each_object()` infrastructure introduced earlier in the series. The function collects objects matching a given hash prefix, which is used when reporting ambiguous object names to users. The change eliminates separate paths for loose and packed objects, instead using the unified iteration interface.

Key technical details:
- Removes direct calls to `find_short_object_filename()` and `find_short_packed_object()`
- Uses `odb_for_each_object_ext()` with prefix filtering
- Maintains the same behavior through the new generic interface
- Touches the object name disambiguation subsystem in `object-name.c`

The change is mechanical and builds on the foundation established in the series. It demonstrates the payoff of the earlier infrastructure work by showing how backend-specific code can be replaced with generic implementations. The patch appears well-contained and follows the established pattern of the series, making it likely to be accepted without significant discussion.
