This is part 8/9 of Adrian Ratiu's feature series introducing parallel hook execution. The patch adds a warning when users mistakenly configure `hook.<friendly-name>.jobs` instead of the intended `hook.<event>.jobs` setting.

The change detects misconfigurations by checking if the name has any hook-specific attributes (like `.command`, `.event`, or `.parallel` configured) - if so, it's likely a friendly name rather than an event name. The warning helps users correct their configuration by pointing out the proper event-based namespace for job settings.

The implementation introduces a new `is_friendly_name()` helper function that will also be useful for future per-event config handling. The patch includes comprehensive tests verifying the warning appears for various friendly-name patterns but not for legitimate event names.

This is a defensive addition to the parallel hooks infrastructure, catching a likely user error scenario. The warning maintains the series' focus on clear user experience while keeping the technical implementation clean. The patch follows maintainer Junio Hamano's suggestion and fits well with the series' overall approach to configuration validation.
