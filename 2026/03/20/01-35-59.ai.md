This is a follow-up in the ongoing discussion about `git send-email` script execution support. Junio C Hamano weighs in on the proposed feature that would allow executable scripts to be passed directly to `--to/--cc/--bcc` flags, rather than using the existing `--*-cmd` options.

Junio acknowledges the conceptual appeal of the simpler "executable detection" approach, but observes that this change comes too late given the existing `--cc-cmd` and `--to-cmd` interfaces that users already rely on. His comment suggests the ship has sailed on redesigning this interface from first principles, implying that any new functionality should probably extend the existing pattern rather than introduce a parallel mechanism.

The maintainer's perspective here provides important context - while the technical implementation may be clean, backward compatibility and existing user expectations constrain what changes are practical at this stage. This positions the discussion as needing to either justify why the new approach is sufficiently better to warrant the inconsistency, or to adapt the proposal to fit within the established `--*-cmd` pattern (including potentially adding the missing `--bcc-cmd`).
