This is patch 12/14 in Patrick Steinhardt's series to make object name lookups more extensible, part of the ongoing ODB (object database) abstraction effort. The patch moves the logic for computing loose object abbreviation lengths into the ODB backend interface.

The change extracts the loose-object-specific logic from `repo_find_unique_abbrev_r()` into a new `odb_source_loose_find_abbrev_len()` function in object-file.c. This continues the pattern of moving storage-specific operations into the backend interface, making the code more generic while maintaining the same behavior. The patch:

1. Introduces a new callback-based `find_abbrev_len_cb()` that uses the recently added `oid_common_prefix_hexlen()` for direct binary OID matching
2. Creates the new backend interface function `odb_source_loose_find_abbrev_len()`
3. Updates the caller in `object-name.c` to use the new interface
4. Removes the now-unused `extend_abbrev_len_loose()` and `find_abbrev_len_loose()` functions

This is a mechanical but important step in the ODB abstraction - it moves another piece of loose-object-specific logic behind the backend interface while preserving all existing behavior. The change is well-contained and follows the established pattern from previous patches in the series. Given Patrick's track record with this refactoring work and the lack of controversy in previous patches, this change is likely to proceed smoothly toward inclusion.
