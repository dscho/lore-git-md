This is patch 12/14 in Patrick Steinhardt's series refactoring the fsck subsystem to remove `the_repository` dependencies. The patch focuses on converting object marking functionality in `builtin/fsck.c` to use explicit repository parameters rather than the global variable.

The key changes introduce a new `struct mark_object_data` to carry repository context through callback chains, replacing direct `the_repository` usage in several functions. The patch updates:
- `mark_object()` to use the callback data's repository for promisor object checks and ODB lookups
- `mark_object_reachable()` to take an explicit repository parameter
- `traverse_one_object()` to pass repository context to `fsck_walk()`
- `mark_unreachable_referents()` and `mark_object_for_connectivity()` to use repository from callback data
- Updates all call sites to pass the repository through

The changes are mechanical but thorough, touching all paths where objects are marked during fsck operations. The patch maintains existing behavior while removing implicit global state, continuing the series' pattern of focused, incremental refactoring. This brings the fsck command closer to being fully independent of `the_repository`.
