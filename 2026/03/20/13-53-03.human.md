This is the first patch in a 9-part series introducing parallel hook execution, building on Adrian Ratiu's prior work on configurable hooks. The patch adds a new helper function `repo_config_get_uint()` to properly handle unsigned integer configuration values, which will be needed for the upcoming `hook.jobs` setting.

The change is straightforward plumbing - it follows the existing pattern of config value parsers, adding support for unsigned int alongside the existing int, ulong, and int64 variants. The commit message explains the rationale for choosing unsigned int over other numeric types for the jobs count. The implementation touches config.c/h and parse.c/h to add the new helper and its supporting functions.

This foundational change has already received an ack from maintainer Junio Hamano, indicating it's uncontroversial and likely to be merged. The patch is cleanly separated from the parallel hooks functionality that will use it, following Git's convention of small, focused changes.
