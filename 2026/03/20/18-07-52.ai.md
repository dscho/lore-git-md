This is a bugfix patch for the bisect subsystem, addressing inconsistent terminology when alternate bisect terms are used. The patch ensures that when users specify custom terms (like "old/new" instead of "good/bad"), those terms are consistently used throughout the bisect output rather than falling back to the default "good/bad" terminology.

The issue arises when users employ `git bisect start --term-new=old --term-old=new` to customize the bisect process - the internal status messages and error outputs would revert to "good/bad" language, creating confusion. The patch modifies several output strings in builtin/bisect.c to use the configured terms from the bisect_terms structure rather than hardcoded values.

The changes are straightforward string substitutions in the status reporting and error message paths, affecting both singular and plural forms where applicable. The patch maintains all existing functionality while making the terminology consistent. This should particularly help cases where the default "good/bad" terms don't match the actual bisect goal (like finding when a bug was fixed rather than introduced).
