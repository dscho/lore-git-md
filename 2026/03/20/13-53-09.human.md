This is a feature patch in a series introducing parallel hook execution. Patch 7/9 adds per-event job configuration, allowing users to override the global `hook.jobs` setting for specific hook events. 

The patch introduces `hook.<event>.jobs` configuration that takes precedence over the global `hook.jobs` setting. For example, users can now configure `hook.post-receive.jobs = 4` to run post-receive hooks with more parallelism while keeping other hooks at the global default. The implementation carefully maintains all existing safety checks - per-hook `hook.<name>.parallel` flags must still be true for any parallel execution to occur.

Key technical changes include:
- New strmap in repository.h to cache per-event job counts
- Updates to get_hook_jobs() to check event-specific and global settings
- Comprehensive tests verifying precedence rules and interaction with parallel flags
- Clear documentation explaining the naming distinction between event names and hook friendly names

The patch fits cleanly into the series' layered control approach, adding another configuration option while maintaining the safety-first design. Test coverage is thorough, verifying edge cases like event-specific jobs=1 overriding a global jobs>1 setting. The documentation clearly warns about the easy-to-misuse distinction between event names and hook friendly names in the config keys.

This continues the series' pattern of well-structured, incremental changes with clear commit messages and thorough testing. The per-event control is a natural extension of the parallel execution infrastructure introduced earlier in the series.
