This is the final patch in Adrian Ratiu's series introducing parallel hook execution, adding a high-level `hook.<event>.enabled` configuration switch to disable all hooks for a specific event. The patch is part of a larger effort to modernize Git's hook system.

The new configuration allows users to disable entire hook events (like `pre-commit` or `post-receive`) with a single setting, overriding any per-hook `hook.<friendly-name>.enabled` configurations. Disabled hooks appear in `git hook list` with an "event-disabled" prefix, clearly indicating why they won't run. The implementation carefully distinguishes between event names and friendly names to avoid confusion with existing per-hook settings.

The patch includes comprehensive tests verifying the new behavior: event-level disabling takes precedence over per-hook settings, disabled events don't affect other events, and the listing output correctly shows disabled status. The changes integrate cleanly with the existing hook infrastructure while maintaining backward compatibility.

This completes the parallel hooks feature set by providing both granular control (per-hook settings) and broad control (event-level switches). The series has evolved through multiple iterations with maintainer feedback, and this final piece implements Junio Hamano's suggestion for a cleaner user experience when managing hook execution.
