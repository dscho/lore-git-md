Refactoring discussion about strbuf_getwholeline() error handling.

Jeff King (Peff) responds to Junio Hamano's suggestion about simplifying the EOF path in strbuf_getwholeline(), which reads lines from a file into a strbuf using getdelim(). The current implementation carefully manages the strbuf state even on error paths, but Junio proposed just freeing any allocated buffer and returning without further state restoration.

Peff explains that while Junio's suggestion would work for EOF cases (where buffer reuse doesn't matter), the function still needs careful handling because getdelim() may have modified the buffer pointer. He suggests an alternative minimal cleanup approach of freeing the buffer and reinitializing the strbuf, preserving the ability to reuse buffers in the common case of reading multiple lines.

This continues the technical discussion about balancing correctness with simplicity in this low-level string handling function. While both agree the EOF path could be simplified, Peff notes the importance of maintaining correct behavior for the non-EOF case where buffer reuse provides performance benefits. The exchange shows two experienced maintainers carefully weighing implementation tradeoffs in core string handling code.
