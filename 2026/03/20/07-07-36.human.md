This is patch 10/14 in Patrick Steinhardt's series refactoring Git's object name handling to support pluggable storage backends. The patch simplifies how Git calculates the minimum unique abbreviation length for loose objects by removing an unnecessary indirection through the disambiguation state machinery.

The change replaces the previous approach that reused the disambiguation infrastructure (which was overkill for this purpose) with a direct implementation that tracks the abbreviation length in a dedicated `min_abbrev_data` structure. This makes the code more straightforward while maintaining the same behavior.

Key technical changes:
- Removes the `always_call_fn` flag from `disambiguate_state` since it's no longer needed
- Introduces `extend_abbrev_len_loose()` as a direct callback for loose object iteration
- Replaces `find_short_object_filename()` with the simpler `find_abbrev_len_loose()`
- Updates `repo_find_unique_abbrev_r()` to use the new direct approach

The patch continues the series' pattern of methodically untangling object name handling from specific storage implementations, making the code more maintainable and better suited for alternative backends. It's a clean, focused change that builds on the infrastructure established in earlier patches.
