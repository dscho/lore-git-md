This is a refactoring patch in Adrian Ratiu's series improving Git's hook configuration system. The patch introduces a new `hook_config_cache_entry` struct to store per-hook data, replacing the direct use of string_list's util pointer for command strings.

The change is purely internal - no user-visible behavior is modified. The new struct provides a more structured way to store hook metadata, setting up for future additions in subsequent patches. The struct currently just holds the command string but is designed to accommodate more fields later.

Key technical changes:
- Adds `struct hook_config_cache_entry` to hold hook command strings
- Updates cache management to allocate/free these structs properly
- Modifies hook lookup to access commands through the new struct
- Maintains all existing functionality while improving internal organization

This is part of Adrian's ongoing work to make Git's hook system more configurable and maintainable. The patch follows Git's standard memory management patterns and appears well-integrated with the existing hook infrastructure.
