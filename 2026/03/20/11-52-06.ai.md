This is a refactoring patch in Adrian Ratiu's hook configuration series, focusing on memory management cleanup. The patch replaces a custom hook clearing function with Git's standard string_list_clear_func() pattern, making the API more consistent with the rest of the codebase.

The key change moves from a specialized hook_list_clear() function to using string_list_clear_func() with a new hook_free() callback. This requires storing the data_free callback in the hook struct itself rather than passing it at cleanup time. The patch also renames related callback typedefs (cb_data_free_fn -> hook_data_free_fn) for better subsystem-specific naming.

Implementation details include:
- hook_clear() is renamed to hook_free() and modified to work as a string_list callback
- The data_free callback is now stored in each hook struct during creation
- All call sites are updated to use the new pattern
- Documentation is updated to reflect the changes

The change follows Patrick Steinhardt's suggestion to standardize on string_list patterns. It eliminates NULL callback parameters in cleanup paths while maintaining the same functionality. The patch appears well-contained and mechanically sound, continuing the series' trend of cleaning up the hook subsystem's internal APIs.
