This is the third patch in Patrick Steinhardt's 14-part series refactoring the fsck subsystem to remove `the_repository` dependence. The patch focuses on the configuration parsing component of fsck.

The key change is replacing the indirect `git_fsck_config()` callback function (which relied on the caller passing a repository via callback payload) with a direct `fsck_options_parse_config()` function that explicitly takes both the fsck options and repository as parameters. This makes the interface more self-documenting and prepares for further refactoring to remove global state.

The patch updates three call sites in builtin commands (`fsck`, `mktag`, and `refs`) to use the new interface. The implementation splits the original callback into a private helper (`fsck_options_parse_config_key`) that does the actual parsing, while the new public function handles the repository configuration lookup.

This is a straightforward mechanical change that maintains all existing functionality while improving the interface clarity. The patch follows the series' pattern of incrementally converting fsck's repository dependence from implicit to explicit. Given Patrick's track record with such refactoring work and the focused scope of this change, it appears to be a solid step toward the series' overall goal.
