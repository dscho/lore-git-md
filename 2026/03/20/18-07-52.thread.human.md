This thread concerns a bugfix patch from Jonas Rebmann addressing terminology consistency in `git bisect` when custom terms (like "old/new") are configured instead of the default "good/bad". While the technical changes to update output messages in builtin/bisect.c are correct, Junio Hamano has identified two key improvements needed before merging.

First, the patch lacks test coverage to verify the custom term behavior and prevent regressions. Tests should be added to t/t6030-bisect-*.sh demonstrating both default and custom term usage in status messages. Second, the commit message needs expansion to clearly document which parts of the bisect system handle custom terms (currently just output messages) versus where hardcoded "good/bad" remains. Junio approved the code changes but maintains these are standard requirements for user-facing behavior modifications. The patch appears ready to proceed once these documentation and testing gaps are addressed.
