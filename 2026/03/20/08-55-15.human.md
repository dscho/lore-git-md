This is a platform compatibility patch addressing macOS regex behavior in CI builds. Johannes Schindelin provides a definitive solution for the recent CI failures where Homebrew's clang was silently being used instead of Apple's system clang, leading to missing REG_ENHANCED flag errors.

The patch carefully traces the root cause to a Homebrew 5.1.0 update that changed how versioned LLVM installations are linked, causing CI builds to unexpectedly use Homebrew's clang (which lacks Apple's REG_ENHANCED extension) rather than the system clang. Schindelin's solution is to explicitly set NO_REGEX when using clang on Darwin, forcing Git to use its bundled regex code instead of the system implementation.

This approach maintains consistent behavior across builds while properly documenting the platform-specific quirk in config.mak.uname. The solution contrasts with earlier workarounds that would have silently changed regex functionality, and aligns with how meson already handles this case through feature detection. The patch shows thorough investigation into the CI environment changes and provides a maintainable fix that clearly explains the platform limitation.
