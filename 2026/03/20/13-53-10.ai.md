This is part 8/9 of Adrian Ratiu's feature series introducing parallel hook execution. The patch adds a warning when users mistakenly configure `hook.<friendly-name>.jobs` instead of the intended `hook.<event>.jobs` setting.

The change introduces a new `is_friendly_name()` helper that detects when a configured name appears to be a hook friendly-name (having `.command`, `.event`, or `.parallel` settings) rather than an event name. When such a misconfiguration is found, Git issues a warning explaining the setting will be ignored and pointing users to the correct syntax (`hook.<event>.jobs`).

The implementation includes comprehensive tests verifying the warning appears for various friendly-name patterns but not for legitimate event names. This addresses a potential confusion point in the parallel hooks configuration system while maintaining backward compatibility - the misconfigured settings are ignored rather than causing errors.

The patch follows maintainer Junio Hamano's suggestion and fits cleanly into the series' layered configuration approach. It demonstrates good attention to user experience by catching likely mistakes early with clear guidance, while avoiding breaking changes. The warning system could be extended in future to cover other similar configuration pitfalls.
