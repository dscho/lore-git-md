This is a feature patch (v2) from Kristoffer Haugsbakk that adds `--format` support to `git name-rev`, allowing it to output formatted commit information similar to `git log --format`. The patch builds on previous feedback from Junio C Hamano and others.

The implementation introduces a new `--format` option that implies `--name-only` and adds support for displaying notes via `--notes`. The core changes include:
- A new `struct format_cb_data` to track formatting state
- Integration with the existing pretty-print infrastructure
- Notes handling via `display_notes_opt`
- Comprehensive test coverage for various format specifiers (`%s`, `%N`) and edge cases

The motivation explains this fills a gap where users need to format individual commits that can't be easily processed through `git log` or `git show`, particularly when dealing with mixed input or duplicate commits. The patch demonstrates careful attention to memory management and edge cases raised in previous reviews.

Technical details of note:
- Uses `FREE_AND_NULL()` for notes cleanup
- Maintains backward compatibility with existing `--name-only` behavior
- Adds tests for format/notes interaction and stdin processing
- Handles both direct arguments and annotated stdin input

The patch appears well-considered with thorough test coverage, addressing all points from the v1 review while maintaining the core functionality. This continues to look like a useful addition that aligns with Git's existing formatting conventions.
