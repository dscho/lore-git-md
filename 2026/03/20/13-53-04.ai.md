This is part 2/9 of Adrian Ratiu's parallel hook execution feature series. The patch introduces the foundational `hook.jobs` configuration option that will control how many hooks can run simultaneously.

The change adds a global `hook.jobs` setting that defaults to 1 (serial execution) when unspecified. The value is parsed during configuration and stored in the repository's `hook_jobs` field. The implementation includes validation to ensure the value is a positive integer, with appropriate warnings for invalid inputs.

Key technical details:
- Adds documentation for the new config in `Documentation/config/hook.adoc`
- Extends the `hook_all_config_cb` struct to track the jobs value during config parsing
- Implements parsing logic in `hook_config_lookup_all()` that validates the input
- Stores the parsed value in `r->hook_jobs` for later use by the parallel execution machinery
- Follows Git's existing config parsing patterns with proper error handling

This is plumbing work that sets up the configuration infrastructure needed by later patches in the series. The actual parallel execution functionality will be built on top of this in subsequent commits. The patch maintains backward compatibility by defaulting to serial execution when no value is specified.
