This is patch 13/14 in Patrick Steinhardt's series refactoring Git's object name handling to support pluggable storage backends. The patch moves the logic for computing unique abbreviation lengths for packed objects from `object-name.c` to `packfile.c`, continuing the pattern established in previous patches of moving storage-specific operations into their respective files.

The change:
- Extracts packed/MIDX abbreviation length calculation into new `packfile_store_find_abbrev_len()` function
- Removes 123 lines of now-unused code from `object-name.c`
- Adds 111 lines to `packfile.c` implementing the same logic in a backend-specific way
- Updates the calling code to use the new interface

This is a mechanical but important step in the series' goal of making object name lookups work with alternative storage backends. The patch follows the established pattern of the series and appears to be a straightforward relocation of code with no functional changes. Given the thorough review of earlier patches in the series and Patrick's track record with this refactoring work, this change is likely to proceed smoothly toward inclusion.
