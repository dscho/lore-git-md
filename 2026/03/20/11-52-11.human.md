This is the final patch in Adrian Ratiu's 10-part series improving Git's hook configuration system. The patch makes disabled hooks visible in `git hook list` output rather than filtering them out entirely.

The key changes are:
1. Disabled hooks now appear in the list with a "disabled\t" prefix (or "scope\tdisabled\tname" when using --show-scope)
2. A disabled hook without a command emits a warning rather than a fatal error
3. The hook_exists() function now properly skips disabled hooks when checking for existence
4. Comprehensive tests verify the new behavior

The implementation builds on the series' earlier work with the hook_config_cache_entry struct and maintains consistency with the tab-separated output format established in prior patches. The changes appear well-tested and follow the project's patterns for configuration scope handling.

This completes the series' goal of making hook configuration more transparent and consistent, with all hooks (including disabled ones) now visible through the standard interface. The patch is polished after multiple rounds of review and fits cleanly with the rest of the queued series.
