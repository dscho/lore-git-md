This is a refactoring patch from Adrian Ratiu, part of his 10-patch series improving Git's hook configuration system. The patch moves a utility function (`unsorted_string_list_remove()`) from hook.c to the more appropriate string-list.[ch] files, where it logically belongs alongside other string-list operations.

The change makes the function more generic by adding a `free_util` parameter (matching the pattern of similar functions) and adds proper documentation. All existing callers in hook.c are updated to pass 0 for this new argument, maintaining the current behavior of not freeing the util pointer. The implementation remains functionally identical - this is purely an organizational improvement.

The patch appears straightforward and well-justified, with a clear benefit to code organization. It's a small but sensible piece of the larger hook configuration work, helping to keep utility functions in their proper place while making the API more consistent with the rest of the codebase. The change has already been reviewed and suggested by Patrick Steinhardt, indicating technical consensus on the approach.
