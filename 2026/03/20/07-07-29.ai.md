This is part 3/14 of Patrick Steinhardt's ongoing ODB abstraction series, introducing a new options structure for object iteration. The patch refactors the `odb_for_each_object()` interface to use a `struct odb_for_each_object_options` rather than passing flags directly, in preparation for future extensions to the iteration functionality.

The key change replaces direct flag parameters with an options structure throughout the object database iteration code. This affects:
- The core `odb_for_each_object()` function (now `odb_for_each_object_ext()`)
- Packfile iteration
- Loose object handling
- Various callers like `cat-file` and `pack-objects`

The patch maintains all existing behavior while making the interface more extensible. The motivation is to support future features like prefix-based iteration without requiring further signature changes. The changes are mechanical but touch many files, showing Patrick's characteristic thoroughness in ensuring all call sites are updated consistently.

This continues the high-quality refactoring seen in previous patches of the series, with clean separation of concerns and careful attention to backward compatibility. The changes align with the overall ODB abstraction goal while being minimally disruptive to existing code. Given the prior positive reception of earlier patches and the uncontroversial nature of this change, it's likely to be accepted without significant discussion.
