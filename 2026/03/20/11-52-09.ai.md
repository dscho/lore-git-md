This is a refactoring patch from Adrian Ratiu's ongoing hook configuration series, specifically part 8/10. The patch introduces a new `hook_config_cache_entry` struct to store per-hook data in the configuration cache, replacing the previous direct use of string_list's util pointer for just the command string.

The change is purely structural at this point - it allocates a small struct to hold the hook command string rather than storing the string directly in the util field. This prepares for future additions where more metadata will need to be associated with each hook in the cache. The patch includes careful memory management updates to properly free both the new struct and its contents when clearing the cache.

Key technical details:
- Adds `struct hook_config_cache_entry` with single `command` field (for now)
- Updates cache clearing to free both the struct and its command string
- Modifies hook lookup to access command via the new struct
- Maintains same behavior - just changes internal representation
- Touches only hook.c with no interface changes

This is a straightforward preparatory change that follows the series' pattern of incremental improvements to the hook configuration infrastructure. The patch appears well-contained and properly handles memory allocation/deallocation. It sets up for the metadata additions coming in subsequent patches while keeping the diff focused and readable.
