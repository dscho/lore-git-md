Subject: fsck subsystem refactoring to remove `the_repository` dependence
Series version: v1 (14 patches)
Author: Patrick Steinhardt
Thread type: patch series (architectural refactoring)

Core problem/goal: Remove fsck subsystem's dependence on the global `the_repository` variable by converting all fsck-related functions to take explicit `struct repository *` and hash algorithm parameters. This is part of the `the_repository` removal effort and preparatory work for making backend-specific fsck checks pluggable.

Files/subsystems touched:
- Core fsck logic in `fsck.c` and `fsck.h`
- Built-in commands using fsck: `fsck`, `index-pack`, `mktag`, `unpack-objects`, `verify-tag`, `verify-commit`
- Related test files
- Fetch-pack and object-file code that interacts with fsck
- Configuration parsing infrastructure
- Reflog checking functionality in `builtin/fsck.c`
- Loose object checking path in `builtin/fsck.c`
- Packfile checking infrastructure
- Object marking functionality in `builtin/fsck.c`
- Error reporting mechanism in `fsck.c` and `builtin/fsck.c`

Key technical changes:
- Complete conversion of fsck subsystem to explicit repository parameters
- Removal of all `the_repository` usage in fsck code paths
- Conversion of error reporting functions (`printable_type()`, `objerror()`) to use repository parameters
- Removal of `USE_THE_REPOSITORY_VARIABLE` compatibility define
- Updates to call sites throughout `builtin/fsck.c`
- Maintained identical behavior while removing global state
- Follows same systematic pattern as rest of series
