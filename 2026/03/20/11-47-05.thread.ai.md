Subject: fsck subsystem refactoring to remove `the_repository` dependence
Series version: v2 (12 patches)
Author: Patrick Steinhardt
Thread type: patch series (architectural refactoring)

Core problem/goal: Remove fsck subsystem's dependence on global `the_repository` by converting functions to take explicit `struct repository *` parameters. Part of broader `the_repository` removal effort and preparatory work for pluggable backend-specific fsck checks. Key structural change in v2: repository pointer now stored in `fsck_options` struct per Junio's feedback, requiring new initialization function for file-static scope cases.

Key development: Patch 11/12 completes the conversion of fsck's object marking functionality, addressing one of the last remaining areas where fsck relied on `the_repository`. The changes systematically update `mark_object()`, `mark_unreachable_referents()`, and `mark_object_for_connectivity()` to use the repository pointer from `fsck_options->repo` and properly propagate it through callback chains. This maintains identical behavior while removing implicit state, particularly important for promisor object checks and alternate ODB traversal. The patch follows the series' established pattern of mechanical but thorough conversions, focusing on `builtin/fsck.c` without ripple effects to other subsystems. With object marking now converted alongside the earlier ref, reflog, and object checking changes, the fsck subsystem is nearly fully repository-agnostic, demonstrating Patrick's systematic approach to removing implicit state dependencies across all levels of the call chain.
