Subject: fsck subsystem refactoring to remove `the_repository` dependence
Series version: v1 (14 patches)
Author: Patrick Steinhardt
Thread type: patch series (architectural refactoring)

Core problem/goal: Remove fsck subsystem's dependence on the global `the_repository` variable by converting all fsck-related functions to take explicit `struct repository *` and hash algorithm parameters. This is part of the `the_repository` removal effort and preparatory work for making backend-specific fsck checks pluggable.

Files/subsystems touched:
- Core fsck logic in `fsck.c` and `fsck.h`
- Built-in commands using fsck: `fsck`, `index-pack`, `mktag`, `unpack-objects`, `verify-tag`, `verify-commit`
- Related test files
- Fetch-pack and object-file code that interacts with fsck
- Configuration parsing infrastructure
- Reflog checking functionality in `builtin/fsck.c`
- Loose object checking path in `builtin/fsck.c` (added in patch 10)
- Packfile checking infrastructure (added in patch 11)

Key technical changes:
- Patch 1 converts `fsck_walk()` and type-specific helpers to take explicit `struct repository *`
- Patch 2 converts `fsck_finish()` and `fsck_blobs()` to explicit repository parameters
- Patch 3 refactors fsck configuration parsing:
  - Replaces `git_fsck_config()` callback with direct `fsck_options_parse_config()`
  - Splits parsing logic between public interface and private helper
- Patch 4 eliminates `the_repository` in `fsck_set_msg_types()`:
  - Takes explicit `const struct git_hash_algo *` parameter
  - Updates call sites in `index-pack`, `unpack-objects`
- Patch 5 removes last `the_repository` dependency in `fsck.c`:
  - Replaces `parse_oid_hex()` with `parse_oid_hex_algop()`
  - Updates `fsck_commit()`, `fsck_tag()`, `fsck_object()` to use explicit hash algorithm
  - Removes `USE_THE_REPOSITORY_VARIABLE` from `fsck.c`
  - Propagates changes through all builtin command callers
- Patch 6 converts `builtin/fsck.c` to explicit repository parameters:
  - Updates helper functions `traverse_one_object()`, `check_object()`, `fsck_cache_tree()`
  - Modifies calls to `repo_get_oid()`, `parse_object()`, `odb_for_each_object()`
  - Passes repository through call chain from `cmd_fsck()`
- Patch 7 refactors ref snapshotting in `builtin/fsck.c`:
  - Introduces `struct snapshot_ref_data` to pass repository and snapshot context
  - Updates `snapshot_ref()` callback to use passed repository instead of `the_repository`
  - Modifies calls to `parse_object()` and `is_promisor_object()`
  - Updates ref iteration in `snapshot_refs()` to pass new context
- Patch 8 converts ref-checking functionality in `builtin/fsck.c`:
  - `struct repository *` parameter to `process_refs()`
  - Passes repository through to `fsck_handle_ref()` via callback data
  - Updates `fsck_handle_ref()` to use passed repository for `parse_object()`
  - Modifies `cmd_fsck()` call site to pass repository instance
- Patch 9 converts reflog checking in `builtin/fsck.c`:
  - Adds `struct repository *` parameter to `fsck_handle_reflog_oid()`
  - Passes repository through callback chain from `fsck_handle_reflog_ent()`
  - Uses repository parameter for `lookup_object()` and `is_promisor_object()`
  - Updates `fsck_handle_reflog()` to pass worktree's repository
- Patch 10 converts loose object checking in `builtin/fsck.c`:
  - Introduces `struct for_each_loose_cb` with `struct repository *` field
  - Updates `fsck_obj()` to take explicit repository parameter
  - Modifies `fsck_loose()` to use repository from callback data
  - Passes repository through to `read_loose_object()` and `parse_object_buffer()`
- Patch 11 converts packed object checking:
  - Modifies `verify_pack()` and related functions to accept callback data parameter
  - Updates `verify_fn` callback signature to include `void *fn_data`
  - Passes repository through to `fsck_obj_buffer()` via callback data
  - Maintains same behavior while removing implicit global state
- No new functionality added - purely mechanical refactoring
- Remaining patches will:
  - Convert low-level fsck functions (patches 12-13)
  - Complete conversions and cleanups (patch 14)
