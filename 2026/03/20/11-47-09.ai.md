This is the fourth patch in Patrick Steinhardt's 14-part series to remove `the_repository` dependence from Git's fsck subsystem. The patch focuses on eliminating `the_repository` usage in `fsck_set_msg_types()` by requiring callers to explicitly pass the hash algorithm.

The key change is modifying `fsck_set_msg_types()` to take a `const struct git_hash_algo *` parameter instead of implicitly using `the_repository->hash_algo`. This affects several call sites:
- Updates in `builtin/index-pack.c` and `builtin/unpack-objects.c` to pass `the_hash_algo`
- Configuration parsing infrastructure in `fsck.c` now passes the repository's hash algorithm through a new `fsck_options_parse_config_key_data` struct
- Function signature updated in `fsck.h`

The patch follows the series' pattern of mechanical, focused changes to remove global state dependencies. It maintains existing behavior while making the hash algorithm dependency explicit. The changes are straightforward and well-contained, touching only the necessary call sites and maintaining the same error handling patterns.

This continues the architectural refactoring work to make fsck more modular and less dependent on global state, which is important for both the `the_repository` removal effort and future plans to make backend-specific fsck checks pluggable. The patch appears technically sound and aligns with the project's direction.
