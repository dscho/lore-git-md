This is a discussion about trailer ordering in Git's rebase functionality, specifically regarding the `--trailer` option being added in Phillip Wood's patch series.

The thread focuses on whether trailers added via `--trailer` should appear before or after signoffs during rebase operations. Kristoffer Haugsbakk questions Phillip Wood's suggestion that trailers should come before signoffs by default, asking if this reflects project conventions. Junio suggests that if precise control over trailer placement is needed, the rebase command should adopt the same `--where` option and configuration mechanism used by `git interpret-trailers`, rather than hardcoding a particular order. This would provide more flexibility while maintaining consistency with existing trailer handling.

The discussion represents one of the final polish items for this otherwise well-reviewed patch series, with both technical and UX considerations at play regarding how Git should handle trailer ordering by default.
