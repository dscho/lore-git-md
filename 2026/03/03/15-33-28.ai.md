This is the first patch in a five-part series introducing AI-assisted workflows for Git's localization (l10n) process, specifically focused on .po file handling. The patch adds infrastructure component to simplify location filtering in translation files.

The patch creates a new `po/.gitattributes` file that defines two types of filters for PO files:
1. `gettext-no-file-no-location` - strips both filenames and line numbers (used by most languages)
2. `gettext-no-location` - preserves filenames but removes line numbers (used by Chinese, Indonesian, and potentially others)

The filters are selectively applied to specific language files that have been properly prepared, avoiding legacy files that might cause discrepancies between the index and working tree. The patch also reorganizes the `po/README.md` documentation, moving the location filtering instructions to a new "Preparing a XX.po file for commit" section for better organization.

This is a technical foundation for the AI-assisted workflows that will be introduced in later patches. The implementation shows careful consideration of different translation team preferences (complete location stripping vs filename preservation) while maintaining backward compatibility with existing workflows. The maintainer had previously expressed mild regret about the filter bifurcation approach, but it appears this compromise solution has been accepted in the v2 iteration.
