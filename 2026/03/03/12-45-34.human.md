This is a performance fix for the hook subsystem in `git-receive-pack`, addressing a regression introduced during the recent hook API conversion. The patch restores an optimization where sideband hooks would exit early if no hook existed, avoiding the overhead of spinning up async threads unnecessarily.

Adrian Ratiu confirms Patrick Steinhardt's observation that the older `find_hook()` function should eventually be removed entirely, with all hooks migrating to the new `hook.[ch]` API. While this wasn't in scope for the current performance fix, Adrian notes that converting the remaining "proc-receive" hook usage would be straightforward and plans to tackle it in a follow-up patch series.

The discussion highlights the ongoing transition to the new hook API, which provides clearer functions like `hook_exists()` and supports both config-defined hooks and traditional hookdir hooks. The end goal is to make `find_hook()` internal to `hook.c` once all external uses have been converted. This exchange shows the project's careful, incremental approach to API migrations - fixing the immediate performance regression first while clearly signaling the intended future direction.
