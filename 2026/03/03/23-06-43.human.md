This is a feature patch adding a `pre-add` hook mechanism, now in its third iteration with all technical concerns addressed. The hook allows inspecting and potentially rejecting staged changes before they are finalized in the index, filling a gap between `git add` computation and the existing `pre-commit` hook.

The implementation provides the hook with paths to both the original index and the proposed new state in a lockfile, enabling comprehensive validation without requiring manual path interpretation. Notable refinements in v3 include proper sequencing with the `post-index-change` hook via a new `SKIP_INDEX_CHANGE_HOOK` flag, correct handling of mixed-result adds, and thorough test coverage.
