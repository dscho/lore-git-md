Here's a human-readable summary of the thread so far:

Matthew Hughes has reported a crash in `git log` when combining the `-L` (line log) and `-G` (pickaxe) options on repositories containing file renames across merge commits. The bug manifests as an assertion failure in `line-log.c` when processing renamed files during merge commit traversal.

The crash occurs in a specific scenario: when a file is created in one branch, renamed in another branch, merged, then renamed back in a subsequent commit. Running `git log -L:func:file.rs -G '.'` on this history triggers the assertion failure because the code isn't properly tracking file identities across renames during merge processing. Notably, either option works fine alone - it's only their combination that exposes this edge case.

Matthew has provided a minimal reproduction script and verified the issue affects both system Git (2.53.0) and recent master builds. The bug was originally discovered in the rustfmt repository but has been isolated to this test case. This appears to be a genuine issue in Git's line log and diff machinery that needs fixing, particularly around how file identities are tracked across renames during merge commit processing.
