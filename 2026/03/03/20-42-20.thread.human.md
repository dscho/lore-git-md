The thread reports a crash in `git log` when combining the `-L` (line log) and `-G` (pickaxe) options on repositories with file renames across merge commits. Matthew Hughes originally encountered this in the rustfmt repository and has provided a minimal test case. The crash occurs as an assertion failure in `line-log.c` when processing renamed files during merge diff processing, specifically when `pair->two->oid_valid` is false.

The bug triggers when: (1) a file exists in one branch, (2) gets renamed in another branch, (3) those branches are merged, and (4) the file is renamed back in a subsequent commit. Running `git log -L:func:file.rs -G '.'` on this history reliably reproduces the crash. Kristoffer Haugsbakk has verified the issue exists in current `master`, `next`, and `seen` branches, confirming this is an unresolved regression.

While either option works fine alone, their combination crashes, suggesting the bug lies in how line-log handles file identity tracking during merge processing when pickaxe is also active. No workaround is currently known. The core issue appears to be in `line-log.c`'s handling of rename chains across merges when both options are present.
