Refactoring patch in Patrick Steinhardt's performance optimization series for `git-upload-pack` lock contention. This patch removes the specialized `hashfd_throughput()` function from the csum-file interface, replacing its single caller in `pack-objects.c` with direct use of the more general `hashfd_ext()` interface.

The change simplifies the API by eliminating a thin wrapper that was only used in one place. The functionality remains identical - when packing to stdout, the code still uses a smaller 8KB buffer to provide more frequent progress updates, just now configured directly via the `hashfd_options` struct rather than through a dedicated function.

This is part of a larger effort to reduce write syscalls in high-concurrency scenarios by introducing batched writes via `writev()`. The series has already shown dramatic improvements, reducing write syscalls from ~400k to ~67k when cloning the Linux repository. This particular patch is a straightforward cleanup that maintains all existing behavior while removing a now-redundant API surface.
