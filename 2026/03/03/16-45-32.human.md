This is a discussion about the deprecation of `git whatchanged`, a long-standing Git command that shows commit history with file modifications. Kristoffer Haugsbakk responds to Antoine Cousson's inquiry about why the command is being removed and what alternatives exist.

The thread clarifies that `git whatchanged` is scheduled for removal in Git 3.0 (though no release date is set) because its functionality is fully covered by `git log` with appropriate flags. The key difference is that `git whatchanged` shows file modifications by default, while `git log` requires explicit `--raw`, `--stat`, or `--name-only` flags to display similar information.

Kristoffer provides specific migration advice: replacing `git whatchanged` with `git log --no-merges --raw` for equivalent output, while suggesting `--stat` or `--name-only` might be more readable for human consumption. The response is helpful and matter-of-fact, though it doesn't address whether there might be reconsideration of the deprecation given user feedback about the command's convenience.

This touches on Git's ongoing effort to streamline its interface by removing redundant commands when their functionality can be achieved through existing alternatives. The discussion may prompt maintainers to consider whether `git log`'s defaults could be adjusted to better serve users who relied on `git whatchanged`'s behavior.
