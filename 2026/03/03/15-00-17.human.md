Performance optimization in `git-upload-pack` to improve keepalive handling during buffered transfers. This is patch 2/10 in Patrick Steinhardt's series addressing lock contention in high-concurrency scenarios.

The patch modifies how `upload-pack` handles keepalive packets when buffering data from `pack-objects`. Previously, keepalives were sent based purely on poll() timeouts, which could lead to delayed communication if data was being buffered (like when waiting for the initial "PACK" signature). The new approach tracks time since the last data transmission and adjusts keepalive timing accordingly, preventing extended silent gaps during buffering.

This change supports the series' broader goal of reducing write syscall contention by enabling more aggressive buffering in subsequent patches. The implementation adds timestamp tracking and modifies the relay logic to report when data was actually sent. Jeff King (Peff) had raised concerns about keepalive behavior in the v1 discussion, and this patch directly addresses them while maintaining the performance improvements seen in testing (~130k writes vs original ~400k when cloning Linux repo).
