This is a GSoC proposal for adding priority-based fetch ordering to promisor remotes, building on Christian Couder's existing promisor-remote capability work. Abraham Samuel Adekunle proposes extending the protocol to let servers advertise priority values for their promisor remotes, with clients optionally honoring these priorities when fetching missing objects.

Christian Couder's review suggests starting with local `remote.<name>.priority` configuration before tackling protocol changes, and questions the need for a new `promisor.honorServerFetchOrder` config when existing `promisor.storeFields` could handle the same functionality. He emphasizes the solution should work for all partial clone objects, not just blobs, and points to undefined current behavior in partial-clone.adoc when using multiple promisor remotes.

Abraham has prior Git contribution history with two merged patches (one in `master`, one in `next`) and appears responsive to feedback. The proposal addresses a real need for partial clone users, though implementation will need careful handling of fetch ordering edge cases and server-client negotiation. Key open questions remain about whether to use new vs existing config mechanisms and the exact protocol negotiation flow for priority advertisement.
