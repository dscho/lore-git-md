Documentation patch adding explicit coverage of Git's external command execution feature. This is the second iteration of a patch that documents how Git runs `git-*` executables found in PATH when no built-in command matches, including their precedence over aliases and argument passing behavior.

The v2 revision follows maintainer Junio Hamano's suggestion to place this documentation under the "Environment Variables > System" section rather than in a standalone section, better integrating it with related PATH behavior documentation. The 7-line addition explains the lookup order (built-ins first, then external commands, then aliases) and notes that arguments are passed through unchanged. The patch fills a gap where this long-standing but under-documented extensibility mechanism was previously only mentioned in passing in `--list-cmds` and `--no-external-commands` help text.

The thread shows consensus on documenting this behavior with no technical objections raised. The patch is purely additive, follows Git's documentation conventions, and makes the command dispatch system's behavior more discoverable for users who want to extend Git with their own `git-*` scripts. The implementation details reference `execv_dashed_external()` in git.c, which has handled this functionality since at least Git 1.5.0.
