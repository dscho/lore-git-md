This is a refactoring patch from Patrick Steinhardt as part of his larger performance optimization series to reduce write syscalls in `git-upload-pack`. The patch introduces a new `hashfd_ext()` function that generalizes the existing `hashfd()` and `hashfd_throughput()` functions by accepting an options structure.

The key changes:
- Adds a `struct hashfd_options` to bundle configuration parameters
- Implements `hashfd_ext()` as a unified interface that replaces both existing functions
- Maintains backward compatibility by having `hashfd()` and `hashfd_throughput()` call the new function with appropriate defaults
- Keeps the same buffer size behaviors (128KB for normal operation, 8KB when showing progress)

This appears to be a preparatory change for further optimizations in the series, with the next commit (mentioned in the message) planning to fully replace `hashfd_throughput()`. The patch follows the established pattern of the series by introducing infrastructure changes incrementally while maintaining existing behavior.
