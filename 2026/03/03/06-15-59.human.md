This is a CI/build system patch addressing a Windows-specific issue in GitLab CI pipelines. The problem stems from the `GITLAB_FEATURES` environment variable growing too large (6.3KB), causing the total environment size (17KB) to exceed POSIX argument length limits (12KB) when running xargs(1) from Git for Windows.

Patrick Steinhardt's initial solution was to simply unset the problematic variable in `ci/lib.sh`, which reduces the environment size to 10.7KB - safely under the limit. Justin Tobler confirms the analysis but raises the question of whether increasing the system limits might be preferable. Patrick responds that unlike Linux systems, MSYS2 has these limits hardcoded, making the unset approach the only viable solution.

The patch appears straightforward and well-motivated, targeting a concrete CI pipeline failure. The discussion remains focused on this specific Windows CI issue, with no apparent broader implications for other parts of the system. Given Patrick's position leading GitLab's Git team and his familiarity with their CI infrastructure, the solution seems likely to be effective.
