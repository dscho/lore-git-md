Antoine Cousson started this thread by asking about the future of `git whatchanged`, a command marked as deprecated that shows file modifications per commit in a format different from `git log --name-status`. He expressed appreciation for its current behavior and surprise at the deprecation.

Kristoffer Haugsbakk responded, confirming that `git whatchanged` is indeed planned for removal in Git 3.0 (though no release date is set yet). He explained that the command shares the same machinery as `git log` but with different defaults, and provided specific replacement commands: `git log --no-merges --raw` produces identical output, while `--stat` or `--name-only` offer more readable alternatives. The response links to Git's BreakingChanges documentation but doesn't address why the deprecation warning wasn't more visible earlier.

This exchange highlights Git's ongoing effort to consolidate functionality while maintaining backward compatibility through equivalent flags. The thread may prompt further discussion about whether the deprecation timeline is appropriate or if `git log`'s defaults should better accommodate this use case. No maintainers have weighed in yet on whether the removal plan might be reconsidered based on user feedback.
