This thread discussed the deprecation and planned removal of the `git whatchanged` command, which has been marked for removal in Git 2.52 or later (correcting an initial mention of Git 3.0). The discussion clarified that deprecation warnings have been present since Git v2.51.1, though some users like thread initiator Antoine Cousson were still on older versions without these warnings.

The key outcome was establishing two clear alternatives to `git whatchanged`: `git log --raw --no-merges` for exact output compatibility (though showing hexadecimal object names that Junio Hamano described as "ugly"), and `git log --stat` which Antoine ultimately preferred for its clearer presentation of file changes with statistics. The thread demonstrated successful user adoption of these alternatives, with Antoine confirming that after testing, they found `--stat` superior to both the original command and the exact-compatibility option.

Junio Hamano and Kristoffer Haugsbakk provided authoritative guidance throughout, with Kristoffer correcting the removal timeline and Junio suggesting the alternatives that proved successful. The discussion shows how Git's interface consolidation - removing redundant commands in favor of configurable alternatives - can lead to improved workflows when handled with clear documentation and migration paths. With no outstanding technical questions and at least one user successfully transitioned, the thread reached a natural conclusion.
