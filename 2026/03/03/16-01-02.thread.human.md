This thread discusses the planned deprecation and eventual removal of `git whatchanged`, a command that shows file modifications per commit. The discussion was initiated by Antoine Cousson, who appreciated the command's output format. Kristoffer Haugsbakk confirmed the deprecation plan (targeting Git 3.0) and provided the exact `git log` equivalents: `--no-merges --raw` for identical output, or `--stat`/`--name-only` for more readable alternatives.

Maintainer Junio C Hamano has now weighed in, confirming the removal remains on track. While personally preferring `git log --stat` for its cleaner presentation, he acknowledges some users may want the hexadecimal object names from `--raw --no-merges` and suggests creating an alias for those who need the exact old behavior. The thread reveals this is part of Git's broader effort to consolidate interfaces by removing redundant commands in favor of configurable `git log` options. No timeline is set for Git 3.0, but the deprecation path appears firm. The discussion highlights the balance between backward compatibility and interface simplification that the project regularly navigates.
