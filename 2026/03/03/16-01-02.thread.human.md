This thread discusses the deprecation and planned removal of the `git whatchanged` command, which shows file modifications per commit. The discussion was initiated by Antoine Cousson, who appreciated the command's behavior, with key contributions from Kristoffer Haugsbakk and maintainer Junio C Hamano.

Junio confirmed the command will be removed, initially mentioning Git 3.0 as the target, though Kristoffer later clarified it will actually happen in Git 2.52 - sooner than some might have expected. The deprecation warning first appeared in Git 2.51.1. Two replacement options were provided: `git log --stat` for a more readable summary, and `git log --raw --no-merges` for output matching whatchanged exactly (including the hexadecimal object names some find less user-friendly).

The thread reveals some tension between maintaining backward compatibility and simplifying Git's interface. While the deprecation was documented in BreakingChanges, participants noted this might not have been prominent enough. Junio expressed no plans to reconsider the removal, seeing this as part of Git's ongoing interface consolidation where redundant commands are removed in favor of configurable `git log` options. The discussion serves as a case study in how the project handles command deprecation, balancing technical changes with communication to users.
