Maintainer response in the `git whatchanged` deprecation thread. Junio C Hamano confirms the command's removal and offers alternatives.

Junio acknowledges the user's preference for `git whatchanged`'s file modification display but suggests `git log --stat` as a more readable alternative showing change magnitude. He confirms the command's planned removal and provides two migration paths: a direct replacement via `git log --raw --no-merges` that matches whatchanged's exact output format (including the "ugly hexadecimal gibberish" of object IDs), or the more user-friendly `--stat` view.

This response from the maintainer settles any remaining questions about the deprecation timeline - the removal is proceeding as planned. The tone is characteristically pragmatic, offering both a behaviorally equivalent solution and a suggested improvement, while making clear the project's direction. No indication is given that the deprecation warning visibility or Git 3.0 timeline will be revisited.
