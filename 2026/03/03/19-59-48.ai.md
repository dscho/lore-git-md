This is a follow-up in the thread about deprecating `git whatchanged`. Antoine Cousson confirms they've tested the suggested `git log --stat` alternative and found it preferable to both the original `git whatchanged` output and the `--raw --no-merges` option, appreciating its clearer presentation of file changes with statistics rather than hexadecimal object names. They also acknowledge being on an older Git version (v2.43.0) and plan to update to receive deprecation warnings.

The email serves as a positive conclusion to the thread, showing successful user adoption of the recommended replacement. No new technical points are raised - it primarily confirms the transition path works for at least one real user case. The thread demonstrates how Git's interface consolidation can lead to improved workflows when deprecated commands are replaced by more configurable alternatives.
