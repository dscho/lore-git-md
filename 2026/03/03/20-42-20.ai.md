This is a bug report describing a crash in `git log` when using both `-L` (line log) and `-G` (pickaxe) options on a repository with file renames across merge commits. The reporter, Matthew Hughes, provides a detailed reproduction script that creates a minimal repository where the crash occurs.

The crash manifests as an assertion failure in `line-log.c` when processing a diff filepair where `pair->two->oid_valid` is false, suggesting the code isn't properly tracking file identities across renames during merge commit processing. The reporter notes this only happens when both `-L` and `-G` are used together - either option alone works fine.

The issue appears when:
1. A file exists in one branch
2. The file is renamed in a separate branch
3. The branches are merged
4. The file is renamed back in a subsequent commit
5. `git log -L:func:file.rs -G '.'` is run on this history

The reporter has verified this occurs on both system Git (v2.53.0) and a recent master build (2cc719175). The bug was originally discovered in the rustfmt repository but has been isolated to this minimal test case. This looks like a genuine edge case in Git's line log and diff machinery that needs to be fixed, likely requiring careful handling of file identity tracking across renames during merge commit processing.
