Documentation patch clarifying how Git handles external `git-*` commands in PATH. This is the third iteration of a straightforward addition to the man pages, now properly formatted after fixing a whitespace issue in v2.

The patch adds a short section under "Environment Variables > System" in git.adoc, explaining that when users run `git <command>` for a non-built-in, Git will look for an executable named `git-<command>` in PATH and run it with the given arguments. The text notes this lookup happens before alias expansion.

The thread shows consensus on this being a useful documentation improvement, with maintainer Junio Hamano having suggested the placement in v1. The change is purely additive and uncontroversial, just making explicit a long-standing but under-explained feature (implemented in `execv_dashed_external()` in git.c). No further discussion seems needed unless someone spots an inaccuracy in the description.
