Performance fix for hook subsystem in `git-receive-pack`, restoring an optimization lost during the hook API conversion. This is a follow-up to Adrian Ratiu's patch that was already improved and queued by Junio C Hamano.

Patrick Steinhardt confirms the fix successfully restores performance in the `receive-pack` sideband hook handling, showing a 2.7x speedup in benchmarks with 10,000 refs (from 485ms back down to ~178ms). The regression had occurred when the hook API conversion removed an early-exit check for non-existent hooks, causing unnecessary thread creation overhead.

The discussion now turns to a related question about the `find_hook()` function, which Patrick notes is still used for the "proc-receive" hook. He suggests this could be addressed in a future patch if it represents an oversight in the hook API migration. The thread shows consensus on the current fix while identifying a potential follow-up area for cleanup.
