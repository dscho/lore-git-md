This is a Google Summer of Code (GSoC) 2026 proposal from Pushkar Singh to improve the experimental `git repo` command, focusing on exposing repository path information in a more structured way. The proposal comes from a contributor who has already successfully landed several small patches in Git's codebase, including test modernization, documentation fixes, and a bugfix for `git subtree`.

Pushkar's plan centers on incrementally adding path-related functionality to `git repo info`, matching capabilities currently available through `git rev-parse` but with a more consistent interface. The work would be delivered in small, reviewable patches, starting with core path keys like `path.git-dir` and `path.common-dir` before potentially expanding to other paths if maintainers agree. The proposal emphasizes careful semantic design, thorough testing across different repository types (bare repos, worktrees, submodules), and maintaining compatibility with existing tooling.

The timeline accounts for Git's review-heavy workflow, prioritizing foundational work first and leaving optional enhancements for later. Pushkar demonstrates familiarity with Git's contribution process through their prior merged patches and participation in mailing list discussions. The proposal is detailed and shows the author has studied both the technical implementation and community norms, though as an RFC it's still early in the design phase.
