Performance optimization addressing lock contention in `git-upload-pack` during high-concurrency scenarios. This is patch 3/10 in Patrick Steinhardt's series, building on earlier feedback from Jeff King (Peff) and Junio Hamano.

The patch reduces write syscall contention by modifying `upload-pack.c` to buffer more data before writing to clients. When cloning the Linux repository, this cuts write syscalls from ~400,000 to ~130,000. The change uses existing buffering but waits until the buffer is 2/3 full before flushing, striking a balance between write reduction and avoiding excessive read syscalls.

The implementation is narrowly focused on `upload-pack.c`, adding just 7 lines to adjust the buffering threshold. A later patch in the series will handle the related `pack-objects` buffer size. The commit message notes this approach is preferable to only modifying `pack-objects` since the pack generator can be replaced via `uploadpack.packObjectsHook`.

This appears to be a well-motivated change with clear performance data, addressing a real production bottleneck. The patch is part of a carefully constructed series that has already incorporated significant review feedback.
