This is a bugfix follow-up to the submodule default remote patch series. Junio Hamano reports that the tests in v4 of the patch are broken, with `test_when_finished` calls incorrectly placed in subshells in t5526-fetch-submodules.sh, causing CI failures. The issue appears in test cases 40 and 44.

The original patch from Nasser Grainawi aimed to remove the hardcoded assumption that submodule remotes are named "origin" by introducing a `get-default-remote` helper. While the core functionality was technically sound (as confirmed by Jacob Keller's earlier review), this test regression slipped through in the final version. Junio notes he already merged the broken version to 'seen', so tonight's CI run will fail.

The test failures are purely mechanical - incorrect use of test infrastructure rather than flaws in the submodule remote logic itself. This appears to be a straightforward fix to relocate the `test_when_finished` calls outside subshell contexts, maintaining all the substantive improvements to submodule remote handling while fixing the test harness usage.
