This is a bug report and analysis of a crash in `git log` when combining the `-L` (line log) and `-G` (pickaxe) options on repositories with file renames across merge commits. The issue was originally reported by Matthew Hughes and has been confirmed by Kristoffer Haugsbakk across multiple Git versions.

The crash occurs as an assertion failure in `line-log.c` when processing a diff filepair where `pair->two->oid_valid` is false, indicating improper file identity tracking during merge processing. The minimal reproduction case involves a file being renamed in one branch, merged, then renamed back - triggering the crash when both `-L` and `-G` are used together.

The bug appears specific to the interaction between line log and pickaxe options when processing rename chains across merges. While either option works fine alone, their combination crashes. The core issue likely lies in `line-log.c`'s handling of file identity during merge commit diff processing. No workaround is mentioned beyond avoiding the option combination.

This looks like a legitimate bug that needs fixing - the reproduction case is clear and the crash occurs on current master. The report is well-documented with both a minimal test case and the original real-world scenario where it was discovered (in the rustfmt repository). The confirmation from Kristoffer Haugsbakk across multiple integration branches adds weight to the report.
