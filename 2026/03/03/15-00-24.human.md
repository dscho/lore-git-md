This is part of Patrick Steinhardt's performance optimization series addressing lock contention in `git-upload-pack`. The patch removes the specialized `hashfd_throughput()` function from the csum-file subsystem, replacing its single use in `pack-objects.c` with a direct call to the more general `hashfd_ext()` interface.

The change simplifies the API by eliminating a thin wrapper that existed solely to configure progress reporting and buffer size for pack-objects' stdout case. The functionality remains identical - the progress meter still updates frequently due to the smaller 8KB buffer - but the implementation is now more direct and explicit about its parameters.

This appears to be a straightforward cleanup as part of the larger series, removing a function that was effectively a one-off helper. The patch maintains all existing behavior while reducing API surface area, which aligns with the series' goal of optimizing I/O patterns. Since this is part of an already-reviewed series that has addressed previous feedback, it seems likely to be uncontroversial.
