This is a performance fix for the hook subsystem in `git-receive-pack`, addressing a regression introduced by the recent hook API conversion. The patch restores an optimization where sideband hooks would exit early if no hook existed, avoiding the overhead of spinning up async threads unnecessarily.

The fix adds `hook_exists()` checks in three hook execution paths (`run_receive_hook`, `run_update_hook`, `run_update_post_hook`) and consolidates hook name strings into static constants. Performance testing shows a 2.7x speedup at 10k refs. The patch has been improved by Junio Hamano's suggestion to handle the "post-update" hook consistently.

This appears to be a well-motivated fix for a clear performance regression, with consensus from key contributors (Patrick Steinhardt identified the issue, Jeff King root-caused it, and Junio improved the patch). The discussion also surfaces a plan to convert the remaining `find_hook()` usage (particularly for "proc-receive" hook) to the new API in follow-up work.
