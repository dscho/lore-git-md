The core challenge involves converting functions that rely on global variables (particularly environment and configuration state) to take explicit `struct repository*` parameters. The proposal identifies concrete problems this addresses: thread safety issues in library contexts, memory leaks from repeated invocations, and testing difficulties. Tian's approach emphasizes careful lifecycle management and API boundary definition over mechanical conversion, with a refined understanding of parsing distinctions between startup and lazy configuration.

Key technical details include the v6 classification of variables into those that should remain global (like user preference settings such as commit encoding) versus repository state that will be parameterized. The proposal outlines a phased timeline targeting `setup.c` first, with plans to use CI and AddressSanitizer for validation.
