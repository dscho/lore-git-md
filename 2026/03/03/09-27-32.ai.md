This is a feature proposal for prioritized fetching from multiple promisor remotes, building on Christian Couder's existing promisor-remote capability work. The email is Christian's review of Abraham Samuel Adekunle's GSoC proposal on the topic.

Christian provides detailed feedback on the proposal, noting several typos and suggesting improvements to the technical approach. He emphasizes that the first step should be implementing a local `remote.<name>.priority` config option to control fetch order before extending the protocol to advertise priorities. Christian questions the need for a separate `promisor.honorServerFetchOrder` config, suggesting the existing `promisor.storeFields` mechanism could handle this more cleanly.

The review highlights that the priority system should work for all partial clone objects, not just large blobs. Christian points to relevant documentation (partial-clone.adoc) that the current behavior is undefined when using multiple promisor remotes, making this a meaningful improvement area. He suggests simplifying the client-side logic by leveraging existing configuration mechanisms rather than introducing new ones.

The proposal demonstrates Abraham's prior Git contribution experience (including merged patches for `git add -p`) and shows understanding of the protocol negotiation flow. Christian's feedback indicates this is a well-scoped project that builds appropriately on existing infrastructure while addressing a clear need for partial clone users with multiple remotes. The implementation will need to carefully handle edge cases around fetch ordering and server-client negotiation.
