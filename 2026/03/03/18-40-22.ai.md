This is a documentation patch that adds information about Git's support for external commands prefixed with "git-" in PATH. The thread shows consensus on documenting this existing but under-documented behavior, with Junio Hamano providing final review feedback on the v3 patch.

The patch explains that when users run `git <command>` not found in core Git, Git will look for and execute `git-<command>` from PATH if available, passing arguments unchanged. This mechanism takes precedence over alias expansion. The documentation is placed in the Environment Variables > System section of git.adoc alongside other PATH-related information.

Junio suggests minor wording improvements, noting the description of "runnable program" could be simplified to just "program". He also questions whether the alias expansion precedence detail is clear enough, and proposes adding cross-references to alias documentation in the GIT COMMANDS section to help users discover both alias and external command features.

The patch references `execv_dashed_external()` in git.c, which has implemented this behavior since at least Git 1.5.0. This is a straightforward documentation improvement with no technical changes needed - the v3 iteration just fixed a whitespace issue from v2. The thread shows the patch is ready for merging once the minor wording clarifications are addressed.
