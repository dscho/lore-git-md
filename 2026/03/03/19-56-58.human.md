This is a follow-up in the ongoing discussion about the deprecation of `git whatchanged`. The thread has established that the command will be removed in Git 2.52 or later, with deprecation warnings already present in Git v2.51.1.

Antoine Cousson responds positively to Junio C Hamano's suggestion to use `git log --stat` as an alternative, appreciating its clearer display of file changes compared to the hexadecimal object names shown by `git whatchanged`. He confirms he's currently using Git v2.43.0 and plans to update, indicating the deprecation notice may not have reached all users yet.

The exchange highlights a successful outcome where a user has found a preferred alternative (`git log --stat`) to the deprecated command, suggesting the transition path is working as intended. The thread shows how practical suggestions from maintainers can help users adapt to interface changes, with Antoine's positive reception of `--stat` validating this approach to command consolidation.
