This is a follow-up in the ongoing discussion about the deprecation of `git whatchanged`. Antoine Cousson responds positively to Junio C Hamano's suggestion to use `git log --stat` as an alternative, finding its display of file changes and modification statistics more useful than the hexadecimal object names from `git whatchanged`'s default output. He confirms he'll update from his current Git v2.43.0 to a newer version that includes the deprecation warnings.

The email reinforces the thread's consensus that `git log --stat` provides a superior alternative for most `whatchanged` use cases, while still acknowledging the exact compatibility option (`git log --raw --no-merges`) remains available for those who need it. Antoine's practical acceptance of the change suggests the transition path is working as intended, though his outdated Git version highlights how deprecation warnings can miss users who don't frequently update. The exchange shows the community successfully guiding a user through the interface consolidation with clear, working alternatives.
