Performance optimization series addressing lock contention in `git-upload-pack` during high-concurrency scenarios. This is version 2 of Patrick Steinhardt's patch series, expanding the scope from the original two patches to ten. The series now tackles the write contention problem from multiple angles: buffering strategy in `upload-pack`, `pack-objects` buffer sizing, and introducing `writev()` for pktline writes.

The core optimization remains reducing lock contention during packfile transfers by modifying buffering works in `upload-pack.c`, but now with additional changes to address feedback from Jeff King (Peff). Key improvements in v2 include:
- Adapting the keepalive logic to account for buffering
- Increasing buffer size in `pack-objects` to reduce write syscalls
- Introducing `writev()` support to combine header and data writes
- Better handling of buffer size calculations using `sizeof()` instead of magic numbers

The series shows measured improvements reducing write syscalls from ~400,000 to ~130,000 when cloning the Linux repository. Patrick acknowledges Peff's concerns about edge cases with custom hooks (via `uploadpack.packObjectsHook`) and buffer synchronization, with v2 specifically addressing these through the expanded changes.

The patch set is quite comprehensive, touching multiple subsystems (`upload-pack`, `pack-objects`, `sideband`, `csum-file`) with coordinated changes. The implementation appears well-considered, with production-tested performance data and clear attention to edge cases. Junio's prior approval of the approach suggests this will likely be merged once the v2 changes are reviewed.
