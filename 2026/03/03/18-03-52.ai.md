This is a maintainer response in the ongoing discussion about the deprecated `git whatchanged` command. Junio C Hamano confirms the command's removal is still on track for Git 3.0 (though no timeline is specified) and offers practical alternatives.

The email provides two replacement suggestions for `git whatchanged` users: `git log --stat` for a more readable summary of changes, and `git log --raw --no-merges` for those who want the exact same output format (including the hexadecimal object names). Junio notes the latter produces "ugly hexadecimal gibberish" but acknowledges some users may prefer it.

This response carries the maintainer's implicit endorsement of the deprecation path, suggesting no reconsideration is planned. The tone is pragmatic - while expressing personal preference for `--stat`, Junio provides the exact mechanical equivalent for those who want to preserve the old behavior via an alias. The message reinforces that this is part of Git's broader interface consolidation efforts, where redundant commands are being removed in favor of configuring `git log` to match specific use cases.
