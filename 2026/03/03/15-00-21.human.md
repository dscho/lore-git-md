Performance optimization patch introducing `writev()` wrappers for Git's I/O subsystem. This is part of Patrick Steinhardt's series to reduce lock contention in `git-upload-pack` during high-concurrency operations.

The patch adds two new wrapper functions for the `write()` system call: `writev_in_full()` and `writev_or_die()`. These follow Git's existing pattern for I/O operations, providing retry-on-interrupt behavior and error handling. The implementation carefully handles partial writes by adjusting the iovec structures, similar to how the existing `write_in_full()` works for single-buffer writes.

This change supports the series' broader goal of reducing system calls during packfile transfers by enabling batched writes of multiple buffers. The wrappers are designed to work with the platform-compatible `writev()` implementation introduced in the previous patch, particularly important since Windows/MinGW lacks native POSIX `writev()` support.

The patch appears well-constructed with thorough error handling and maintains consistency with Git's existing I/O patterns. It addresses a key piece of the performance optimization by enabling more efficient write operations across all supported platforms.
