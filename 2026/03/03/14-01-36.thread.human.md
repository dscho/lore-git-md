This thread explores how to manage concurrent automated workflows in Git repositories, where multiple agents (like coding and reviewing systems) need simultaneous access without stepping on each other's toes. Klaus Ma kicked off the discussion by framing the core tension between the overhead of frequent fresh clones versus the risk of branch conflicts when sharing a single clone.

D. Ben Knoble responded with two existing Git features that could help: `git worktree` for multiple working directories from one clone (sharing object storage while keeping branch work separate), or local clones which—though more isolated—are still efficient due to Git's local cloning optimizations. The discussion is still early, but it's clear this is primarily about leveraging Git's existing capabilities rather than proposing new functionality. The tradeoffs between worktrees (shared state) and local clones (stronger isolation) will likely shape the ongoing conversation as participants weigh which approach best suits their automation needs.
