This is a performance fix for the hook subsystem in `git-receive-pack`, addressing a regression introduced during the hook API conversion. The patch restores an optimization where sideband hooks would early-exit if no hook existed, avoiding the overhead of spinning up async threads unnecessarily.

The fix modifies three hook execution paths in `builtin/receive-pack.c` (`run_receive_hook`, `run_update_hook`, `run_update_post_hook`) to use the new hook API's `hook_exists()` function before proceeding with hook execution. This provides a 2.7x speedup when pushing to repositories with 10k refs. The patch also consolidates hook name strings into static constants as suggested by Junio.

The change is part of an ongoing effort to migrate from the legacy `find_hook()` API to the new hook subsystem. While this patch addresses the immediate performance regression, future work is planned to convert the remaining `find_hook()` usage (particularly for the "proc-receive" hook) to the new API, after which `find_hook()` can be made internal/static.

The patch has been reviewed and improved by Junio C Hamano, with problem identification by Patrick Steinhardt and root cause analysis by Jeff King. Performance improvements have been verified through the Bencher infrastructure. The fix is straightforward and uncontroversial, with no open questions remaining for this specific change.
