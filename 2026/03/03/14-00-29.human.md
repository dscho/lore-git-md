This is a feature proposal for configurable partial clone filters, now evolving into a more general design discussion. Alan Braithwaite responds to Patrick Steinhardt's suggestion for URL-specific configuration by proposing a concrete implementation pattern modeled after Git's existing `http.<url>.*` settings.

The new design would allow both global defaults and per-URL overrides for partial clone filters, supporting any filter specification (not just blob size limits). The configuration would use `fetch.partialCloneFilter` as the global default, with more specific `fetch.<url>.partialCloneFilter` settings taking precedence. The proposal carefully considers edge cases: command-line `--filter` overrides config, existing per-remote settings are preserved, and unsupported server filters are silently ignored.

The discussion has moved beyond the original blob-size-specific focus to address broader configuration philosophy. Alan demonstrates thoughtful engagement with Git's existing patterns (leveraging `urlmatch_config_entry()` infrastructure) while maintaining backward compatibility.
