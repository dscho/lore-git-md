This is a bugfix patch addressing submodule fetching behavior that incorrectly assumed all submodule remotes are named "origin". The patch is the final v5 iteration of a series that adds a new submodule helper command `get-default-remote` to properly handle submodules with differently-named remotes.

The core change introduces a new submodule--helper subcommand that determines the default remote name for a submodule, falling back to "origin" if detection fails. This fixes cases where `git fetch --recurse-submodules` would fail when submodules used non-origin remote names. The implementation includes comprehensive test coverage across multiple test scripts (t5526, t5572, and the new t7426) demonstrating the fix works for both direct fetches and pull operations.

Key technical details include:
- New helper command in builtin/submodule--helper.c
- Changes to submodule.c to use the helper instead of hardcoded "origin"
- Test cases covering nested submodules, multiple remotes, and edge cases
- GIT_TRACE output verification of remote name handling
- Fallback to "origin" when default remote detection fails

The patch has been reviewed by Jacob Keller and incorporates feedback from Junio Hamano and Ben Knoble across previous iterations. All identified test issues (including subshell cleanup and portability concerns) have been resolved. The series is now fully resolved with no outstanding technical issues and ready for inclusion.
