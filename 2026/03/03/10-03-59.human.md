This is a follow-up to a bug report and test case documenting incorrect behavior in `receive.denyCurrentBranch=updateInstead` when pushing to bare repositories with worktrees. The original patch demonstrated that Git incorrectly rejects pushes with "Working directory has staged changes" when the bare repository's HEAD points to an unborn branch, even though the worktree is clean.

The author, Runxi Yu, is politely bumping the thread after a week of inactivity, hoping to revive discussion about this edge case. The underlying issue appears to be a long-standing bug in how `builtin/receive-pack.c` checks for staged changes - it examines the bare repository's HEAD rather than the worktree's HEAD, leading to false positives when the bare HEAD is unborn.

While the test case was marked as `test_expect_failure` to document the current broken behavior, the thread seems to have stalled without reaching consensus on how to fix the core logic. The bump suggests the author believes this deserves attention, though no new technical content is added in this email.
