This is a follow-up in the ongoing discussion about deprecating `git whatchanged`. Kristoffer Haugsbakk confirms Junio C Hamano's statement that the command will be removed, noting the specific version cutoff (v2.51.1 being the last version where it remains available, with removal coming in Git 2.52 and higher).

The thread has settled on two replacement approaches: using `git log --raw --no-merges` for exact output matching whatchanged's format (including the hexadecimal object names Junio describes as "ugly gibberish"), or `git log --stat` for a more readable summary. The discussion has moved from debating whether to remove the command to documenting the transition path, with Junio's position being clear that the deprecation will proceed as planned.

Kristoffer's brief reply serves to anchor the version numbers where this change will take effect, providing a concrete reference point for users who need to update their workflows. The tone suggests this thread is winding down now that the maintainer has given definitive guidance on both the timeline and alternatives.
