This is a feature patch adding a `pre-add` hook mechanism, now in its third iteration with all technical aspects resolved. The hook allows inspecting and potentially rejecting staged changes before they are finalized in the index, addressing a gap where existing hooks like `pre-commit` fire too late to prevent unwanted content from being staged.

The implementation provides the hook with paths to both the original index and a lockfile containing the proposed new state, enabling comprehensive validation. Key technical challenges around hook sequencing (particularly with respect to the existing `post-index-change` hook) have been addressed through a new `SKIP_INDEX_CHANGE_HOOK` flag. The patch includes thorough test coverage in t/t3706-pre-add-hook.sh demonstrating real-world use cases like blocking sensitive file patterns.

Maintainer Junio Hamano has confirmed the technical approach and naming (using backtick-formatted "`pre-add`" in documentation) as correct. The only open item is final polish of error message wording, which the author has committed to address. The patch touches documentation (both git-add and githooks man pages), core add functionality, and index handling infrastructure.

This represents the culmination of several rounds of review, with v3 incorporating all requested technical refinements around lockfile handling, index change contracts, and hook sequencing. The maintainer's feedback now focuses solely on improving the clarity of end-user facing messages before merging.
