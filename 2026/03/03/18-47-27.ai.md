Feature implementation in the `git-history` command family, specifically adding a `split` subcommand. This is the 8th patch in a series from Patrick Steinhardt that builds on earlier refactoring work.

D. Ben Knoble provides feedback on the implementation, focusing on edge case behavior and naming. The key points:

1. Knoble suggests the command could silently handle cases where all/no hunks are selected (which currently errors out) by making it a no-op, though acknowledges this might be better addressed later.

2. He questions the "ext" suffix in the new `commit_tree_with_edited_message_ext()` function, wondering whether it stands for "extended" or "extracted" and suggesting clarification would help.

3. The rest of the implementation (which he didn't review in detail) appears to follow the expected patterns from previous `git-history` commands like `reword`.

The patch itself implements commit splitting with interactive hunk selection, preserving authorship and handling various edge cases (merge commits, empty splits, pathspecs). It includes extensive test coverage (755 lines) for scenarios like splitting tip/root/middle commits, detached HEAD, and branch updates. The implementation builds on earlier refactoring of the add-patch infrastructure to support in-memory index operations.

This continues Patrick Steinhardt's ongoing work on the experimental `git-history` command family, following similar patterns to the previously implemented `reword` subcommand.
