Bugfix for submodule fetching that addresses test failures in the final patch version. This is the conclusion of a series that removes the hardcoded assumption that submodule remotes are named "origin", instead using a new `get-default-remote` helper to properly handle custom remote names.

The patch had been through multiple rounds of review and was thought to be ready, but Junio Hamano notes that the tests in v4 are broken - specifically, `test_when_finished` is being misused in a subshell context in t5526-fetch-submodules.sh, causing two test failures. This was caught by the integration CI after the patch was merged to the 'seen' branch.

The author Nasser Grainawi had removed Jacob Keller's Reviewed-by tag from v4 due to significant test changes, but the new version introduced these test script errors. The core solution remains sound (as confirmed by earlier reviews), but the test infrastructure issues need to be addressed before this can proceed. Junio's message serves as both a notification of the CI failure and a prompt for the author to fix the test script issues in a follow-up version.
