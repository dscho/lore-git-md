This is a bug report describing a crash in `git log` when using both `-L` (line log) and `-G` (pickaxe) options on a file that has been renamed across merge commits. The reporter provides a clear reproduction script that creates a repository with a file that gets renamed in a branch, merged back, and then renamed again - triggering an assertion failure when both options are used together.

The core issue appears to be in `line-log.c` where an assertion fails during `process_ranges_merge_commit`, suggesting the code isn't properly handling the case where a file is renamed on both sides of a merge. The reporter notes this only occurs when both `-L` and `-G` are used together - either option alone works fine.

The bug affects at least Git 2.53.0 and the current master branch (as of March 2026). The reporter originally encountered this while working with the rustfmt repository, but helpfully distilled it down to a minimal test case that doesn't require any special configuration. This looks like a legitimate edge case in Git's line-log and diff machinery that needs fixing.
