This is a CI/build system patch addressing a Windows-specific issue in GitLab's CI pipelines. The thread has already established that the `GITLAB_FEATURES` environment variable (6.3KB) causes the total environment size (17KB) to exceed POSIX argument length limits (12KB) when running xargs(1) from Git for Windows.

Justin Tobler confirms Patrick Steinhardt's earlier assessment that MSYS2's argument length limits are hardcoded, making variable removal the only viable solution. The discussion is now settled - the 4-line change to `ci/lib.sh` that unsets `GITLAB_FEATURES` in GitLab CI environments appears to be the correct approach, with no remaining open questions. Both participants are GitLab team members who understand their CI system's requirements.

The fix is narrowly scoped to Windows CI infrastructure and doesn't affect core Git functionality. With environment size dropping from 17KB to 10.7KB after the change, this should reliably resolve the xargs(1) failures in Windows CI pipelines.
