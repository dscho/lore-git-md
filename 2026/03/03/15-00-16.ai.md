Performance optimization series targeting `git-upload-pack` lock contention, part 1/10. This initial patch removes a debug message ("flushed.") that was inadvertently being sent to clients during packfile transfers. The message dates back to 2006 and appears to be a leftover debugging artifact that was never intended to be client-visible. 

The change is straightforward - simply deleting the `fprintf(stderr)` line that was printing the message. While minor on its own, this cleanup prepares for subsequent patches in the series that will modify the buffering behavior in `upload-pack.c`. The patch demonstrates good attention to detail in catching and removing this long-standing quirk.

This is part of a larger effort by Patrick Steinhardt to reduce write syscall contention in high-concurrency scenarios, with the full series showing significant reductions in write operations (from ~400k to ~130k in Linux repository clones). The debug message removal is a small but logical first step before making more substantial changes to the buffering logic.
