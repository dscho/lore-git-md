Thread identity: Discussion about the deprecated `git whatchanged` command, initiated by Antoine Cousson, with responses from Kristoffer Haugsbakk and Junio C Hamano.

Core problem or goal: Clarifying the deprecation and removal timeline for `git whatchanged` (marked as deprecated) and documenting exact `git log` equivalents for its file modification output format. The thread explores whether the deprecation warning was sufficiently visible and if `git log` defaults could better serve this use case.

Current status: Maintainer Junio C Hamano confirms `git whatchanged` will be removed in Git 3.0 (no set release date). Two replacement options are provided: `git log --stat` for a more readable summary, and `git log --raw --no-merges` for exact output matching whatchanged (including hexadecimal object names). The deprecation was documented in BreakingChanges but may not have been prominent enough.

Key technical details: Both commands use the same diff machinery but with different defaults. `git whatchanged` implicitly shows file modifications per commit without merge commits, while `git log` requires explicit flags. Junio notes the `--raw` output includes "ugly hexadecimal gibberish" but provides it for exact compatibility. This is part of Git's ongoing interface consolidation where redundant commands are removed in favor of configurable `git log`.

Open questions: Should the deprecation warning have been more visible? Are there plans to make `git log` defaults more aligned with this common use case? Will the Git 3.0 timeline allow sufficient migration time? Maintainer response suggests no reconsideration of the deprecation path is planned.
