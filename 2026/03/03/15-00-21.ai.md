Performance optimization series adding writev() wrappers for Git's I/O subsystem. This is patch 6/10 in Patrick Steinhardt's series to reduce lock contention in `git-upload-pack` during high-concurrency scenarios. The patch introduces platform-compatible `writev()` wrappers (`writev_in_full()` and `writev_or_die()`) that handle partial writes and errors consistently with Git's existing I/O patterns.

The implementation provides:
- A robust `writev_in_full()` that retries on EINTR/EAGAIN and properly handles partial writes by adjusting the iovec array
- A `writev_or_die()` variant that terminates on failure, matching Git's existing `write_or_die()` pattern
- Careful handling of iovec modifications during partial writes to maintain correctness
- The wrappers follow Git's established patterns for platform compatibility, building on the POSIX `writev()` compatibility layer added in the previous patch
- Changes touch `wrapper.[ch]` and `write-or-die.[ch]` to maintain consistency with existing I/O utilities

This patch is part of the broader effort to optimize packfile transfers by reducing write syscalls through buffering and vectorized I/O. The implementation addresses earlier review feedback about platform compatibility and error handling, particularly for Windows and other non-POSIX systems. The new functions will be used by subsequent patches in the series to implement batched writes in the sideband and pack-objects subsystems.
