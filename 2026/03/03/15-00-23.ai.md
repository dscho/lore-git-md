This is a refactoring patch in Patrick Steinhardt's performance optimization series targeting write syscall reduction in `git-upload-pack`. The patch introduces a new `hashfd_ext()` function that generalizes the existing `hashfd()` and `hashfd_throughput()` functions by accepting an options structure.

The key changes are:
1. Adds a `struct hashfd_options` to bundle configuration parameters (progress meter and buffer length)
2. Implements `hashfd_ext()` as the new unified backend for hashfile creation
3. Modifies existing functions to use this new backend while maintaining their current behavior
4. Keeps the same default buffer sizes (128KB for normal operation, 8KB when throughput measurement is enabled)

The change is part of a larger effort to optimize I/O patterns in high-concurrency scenarios, though this particular patch is purely structural - it doesn't change behavior but prepares for future optimizations by providing a more flexible interface. The patch follows the series' pattern of careful, incremental changes with clear commit messages explaining each step.
