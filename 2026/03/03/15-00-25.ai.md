This is a performance optimization patch in Patrick Steinhardt's series addressing lock contention in `git-upload-pack`. The patch focuses on reducing write syscalls when writing packfile data through `git pack-objects --stdout`.

The key change increases the buffer size from 8KB to ~64KB (specifically `LARGE_PACKET_DATA_MAX - 1`) when writing packfiles to stdout. This choice is carefully motivated: it matches the pktline chunking used by `git-upload-pack` while still providing frequent enough progress updates (since most networks exceed 64KB/s bandwidth). Benchmarking shows the change reduces write syscalls from 355,000 to 44,000 when packing the Linux repository.

The patch maintains all progress meter functionality while optimizing for the common case where packfiles are large (often megabytes or gigabytes). It builds on Jeff King's earlier work increasing buffer sizes for performance, applying similar reasoning to the stdout packing case. The implementation uses the now-standard `hashfd_ext()` interface that was consolidated earlier in the series.

This appears to be a well-considered optimization that completes the series' transition to the unified hashfile interface while preserving all demonstrated performance gains. The change is narrowly scoped to the pack-objects stdout case and maintains compatibility with existing progress reporting and sideband protocols.
