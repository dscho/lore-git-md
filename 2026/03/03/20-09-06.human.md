This is a bugfix patch addressing submodule fetching behavior that incorrectly assumed all submodule remotes are named "origin". The patch is the fifth iteration (v5) of a series that adds a new submodule helper command `get-default-remote` to properly handle submodules with differently-named remotes.

The key change is that `git fetch --recurse-submodules` will now work correctly when submodules use a remote name other than "origin". The implementation maintains backward compatibility by falling back to "origin" if default remote detection fails. The patch includes comprehensive test coverage across multiple test scripts (t5526, t5572, and a new t7426) demonstrating the fix works as expected.

The v5 iteration specifically addresses test infrastructure issues found in earlier versions, particularly around `test_when_finished` usage within subshells and trace file handling. The implementation has been reviewed by Jacob Keller and Junio Hamano, with all identified issues resolved. The patch is now in its final form and ready for integration.

This fixes a 7-year-old NEEDSWORK comment from commit be76c21282, showing it addresses a long-standing limitation in submodule handling. The solution is well-tested and non-disruptive, making it a solid improvement to the submodule fetching infrastructure.
