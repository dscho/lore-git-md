This is a maintainer review comment on the second patch in a 2-part series about custom bisect term handling. Junio C Hamano points out a memory leak in the `rev-parse --bisect` implementation where dynamically allocated strings for the ref paths aren't being freed after use.

The patch had modified `builtin/rev-parse.c` to respect custom bisect terms (like "old"/"new" instead of default "good"/"bad") when looking up refs, but failed to free the memory allocated by `xstrfmt()` for the constructed ref paths. This is a straightforward oversight that needs fixing before the patch can be merged. The core functionality of respecting custom terms is sound, but the implementation needs this cleanup to avoid leaking memory.

This follows up on Phillip Wood's earlier concern about memory management in the thread. The patch author Jonas Rebmann will need to address this in a v3 by either freeing the strings immediately after use or restructuring the code to avoid the allocations altogether. The fix should be simple and won't require major changes to the patch's approach.
