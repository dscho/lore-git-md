This is a Google Summer of Code (GSoC) proposal for implementing prioritized fetching from multiple promisor remotes, part of the ongoing Large Object Promisor (LOP) effort. Abraham Samuel Adekunle proposes adding configurable fetch ordering for promisor remotes, allowing both clients and users to specify priority when fetching missing objects from multiple sources.

The proposal builds on Christian Couder's previous work extending the promisor-remote protocol capability. The key additions would be:
1. A `remote.<name>.priority` config option for clients to specify their preferred fetch order
2. Server-side advertisement of recommended fetch priorities via the promisor-remote capability
3. Client-side logic to choose between server-recommended, locally-configured, or default fetch ordering

The implementation would touch protocol negotiation, remote configuration handling, and the promisor object fetching logic. Adekunle demonstrates familiarity with the codebase through prior contributions to `git add -p` and test modernization, though this would be their first substantial protocol-level work. The 12-week timeline shows careful planning with code study, incremental implementation, and regular mentor checkpoints.

This is a well-structured proposal that addresses a real need in partial clone workflows while building logically on existing infrastructure. The technical approach appears sound, though protocol changes always carry risk of subtle edge cases. The mentoring from Christian Couder (original author of the promisor-remote capability) provides strong domain expertise.
