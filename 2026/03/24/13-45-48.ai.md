This is a maintainer review comment on the second patch in a 2-part series about custom bisect term handling. Junio C Hamano points out a memory leak in the `rev-parse --bisect` implementation where dynamically allocated strings from `xstrfmt()` are not freed after use.

The patch being reviewed makes `git rev-parse --bisect` respect custom bisect terms (like "old"/"new" instead of default "good"/"bad") when looking up refs. While the core functionality works, Junio notes the technical oversight that the formatted ref paths leak memory since they're assigned to `opts.prefix` but never freed. This confirms Phillip Wood's earlier concern about memory management in the thread.

The issue is straightforward to fix - the code needs to free the strings after the ref iteration completes. This is a typical pattern when using `xstrfmt()` in Git's codebase. The rest of the patch's approach remains sound, just needing this one memory management fix before it can be merged.

This review keeps the thread moving toward resolution, with Junio identifying a concrete technical issue that needs addressing in the next iteration. The core concept of respecting custom bisect terms in ref lookups remains uncontested.
