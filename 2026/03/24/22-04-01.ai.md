This is a feature addition to the `git replay` command, introducing a `--revert` mode for server-side history rewriting. The patch is the second in a v5 series that has undergone extensive review and is now ready for merging.

The change enables `git replay` to reverse commits directly on bare repositories, which is particularly useful for GitLab's Gitaly service where server-side operations on bare repos are common. The implementation follows the same approach as `sequencer.c`, treating reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent) to effectively reverse the diff direction.

Key technical details:
- Adds new `REPLAY_MODE_REVERT` enum alongside existing `REPLAY_MODE_PICK`
- Implements revert message generation using `sequencer_format_revert_message()`
- Processes reverts newest-first (matching `git revert` behavior) to reduce conflicts
- Uses current user as author for revert commits (unlike cherry-pick which preserves original author)
- Includes comprehensive test coverage in t/t3650-replay-basics.sh
- Documents the feature in Documentation/git-replay.adoc

The implementation has been thoroughly reviewed by Phillip Wood, Patrick Steinhardt, and Junio Hamano, with all technical points from prior discussion addressed. The patch appears well-considered with clear commit messages and follows established patterns in the codebase.
