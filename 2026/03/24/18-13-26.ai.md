Test infrastructure robustness patch. Junio C Hamano continues his effort to make the test framework more resilient by enabling `set -e` (exit on error) in test scripts, building on previous fixes for t4032 and t6002. This patch addresses a foundational issue in test-lib.sh where the initial Git binary check would fail under `set -e` due to its non-zero exit code.

The change modifies how the test framework verifies that Git is properly built, replacing a direct `git` invocation that would trigger `set -e` with a pattern that captures the exit status without causing an immediate exit. This allows the test suite to properly distinguish between a working Git binary (which exits with status 1 when run without arguments) and a missing or broken binary.

This represents another incremental improvement toward Junio's goal of making the test suite fail more visibly when errors occur, particularly for issues like misspelled test macros that currently pass silently. The patch itself is small but demonstrates the careful attention needed to maintain backward compatibility while adding stricter error checking. The accompanying note suggests this is just the first of potentially many such changes needed to fully enable `set -e` across the test suite.

The change is low-risk since it doesn't modify test behavior - it makes the existing check compatible with stricter error handling. As the maintainer driving this effort, Junio's patch follows the pattern seen in his previous test framework fixes: surgical changes that preserve existing semantics while enabling better error detection. This continues the thread's progression from specific typo discovery to systematic test infrastructure hardening.
