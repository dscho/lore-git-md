This is a follow-up discussion on Adrian Ratiu's hook configuration series, now merged to 'next'. Patrick Steinhardt suggests an enhancement to `git hook list` that would warn about unknown hook names by default, while preserving the ability to list custom hooks via an explicit `--allow-unknown-hook-name` flag.

The proposal stems from the observation that most users will work with Git's standard hooks (like "pre-receive"), and typos in these names currently fail silently. Patrick argues this could be improved by making the command more proactive about detecting likely mistakes, while still supporting the existing custom hook use case through an opt-in flag.

He also asks whether the test coverage should include an example of how the `--show-scope` flag interacts with traditional hookdir hooks (which don't show scope since they're not configured via Git's config system). This continues the thread's focus on making hook behavior more transparent and user-friendly.

The discussion occurs post-merge, showing how the Git community often continues refining ideas even after code lands in the integration branches. Patrick's suggestions appear aimed at catching common user errors while maintaining the flexibility that motivated the original hook configuration work.
