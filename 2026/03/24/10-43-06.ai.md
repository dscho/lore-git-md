Review feedback on bisect custom term handling patch. Phillip Wood suggests two improvements to Jonas Rebmann's v2 patch that fixes bisect output to use configured terms (like "term1"/"term2") instead of hardcoded "good"/"bad".

The first suggestion is to wrap the custom terms in single quotes in status messages (e.g. "'term1'" rather than "term1") to make it clearer they are term names being referenced. This would affect the output in `bisect_print_status()` and related messages.

The second is a test improvement - recommending use of `test_grep` instead of plain `grep` in the test assertions, as it provides better failure diagnostics. This would apply to several test cases that verify the status output contains the expected term names.

The feedback is constructive and focused on polish - the core approach of the patch (making bisect status respect custom terms) remains sound. These would be straightforward changes to incorporate in a v3. No new technical concerns are raised about the implementation.
