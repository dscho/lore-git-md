This is a refactoring patch that extracts revert message formatting logic from `sequencer.c` into a reusable function, as part of the ongoing `git replay --revert` feature series. The patch comes from Siddharth Asthana and represents the first of two patches in v5 of the series.

The change moves the detailed logic for formatting revert commit messages (handling both "Revert" and "Reapply" cases) from `do_pick_commit()` into a new `sequencer_format_revert_message()` function. This makes the functionality available to the new `git replay --revert` command while keeping the behavior consistent with existing `git revert` operations.

Key technical aspects include:
- The new function takes explicit parameters (repository, subject line, commit, parent, and a flag for reference style) rather than relying on sequencer-specific state
- Updates `refer_to_commit()` to no longer depend on `the_repository` or `replay_opts`
- Maintains all existing behavior including handling of reverts-of-reverts and merge commit cases
- Adds thorough documentation in the header file

This appears to be a clean, well-contained refactoring that follows the project's established patterns. The change has already gone through multiple rounds of review from core contributors (Phillip Wood, Patrick Steinhardt, and Junio Hamano) and addresses all prior feedback. The patch series as a whole is now in its fifth iteration and seems ready for merging.
