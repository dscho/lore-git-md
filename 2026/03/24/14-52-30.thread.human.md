This thread documents Junio Hamano's systematic effort to harden Git's test infrastructure by making the test suite compatible with `set -e` (exit on error) mode. The work began when Patrick Steinhardt noticed a typo in t4014-format-patch.sh where `test_expected_success()` was incorrectly used instead of `test_expect_success()`, highlighting how such errors could silently pass. 

Junio has been methodically fixing test scripts one by one, addressing subtle edge cases that would break under stricter error checking. He's tackled several test files so far: fixing config value handling in t4032, `expr` command behavior in t6002, the Git binary check in test-lib.sh, `grep -v` exit status in t0008, and now conditional test patterns in t7450. Each fix preserves the original test behavior while making it robust against silent failures.

The latest patch to t7450 demonstrates the emerging pattern - inverting test conditions (`test -n` to `test -z`) to properly handle empty variables under `set -e`. Junio's approach shows both the careful attention needed (his "It was fun to figure this one out" comment on t6002 reveals the detective work involved) and the systematic nature of the effort. While the format-patch issue that originally surfaced the problem has been fixed separately, this infrastructure work continues to uncover and address subtle test framework behaviors, making the entire test suite more reliable.
