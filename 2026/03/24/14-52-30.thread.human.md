This thread examines how to make Git's test infrastructure more robust after discovering that a typo in test macros (`test_expected_success` instead of `test_expect_success`) went undetected in t4014-format-patch.sh. The discussion has evolved from fixing specific issues to debating methodology for catching such errors systemically.

Junio Hamano has been leading an effort to make test scripts compatible with `set -e` (exit on error), which would catch misspelled macros by causing immediate failures. He's made significant progress, with 80-90% of test scripts now clean. However, Jeff King (Peff) demonstrated subtle behavioral inconsistencies with `set -e` in shell contexts and proposed an alternative stderr monitoring approach that would analyze test output files. While Junio remains open to alternatives, he's continued advancing the `set -e` work.

Patrick Steinhardt - who originally spotted the triggering typo - now reports he had independently been working on the same `set -e` approach and is nearly done with the implementation. He agrees with Junio that the changes are manageable but advocates for completing them soon rather than treating it as a student project. This suggests the `set -e` direction is gaining momentum, though the discussion remains open about whether it's the best long-term solution or if Peff's stderr monitoring might offer more comprehensive error detection.

Key questions remain about how to handle edge cases under either approach, performance implications, and documentation standards. The thread shows the project carefully weighing technical tradeoffs between immediate improvements and potentially more robust (but more involved) solutions to prevent silent test failures.
