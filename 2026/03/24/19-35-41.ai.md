This is a feature patch for `git replay`, version 2 of a series enabling the command to handle root commits (commits with no parents). The patch addresses feedback from the maintainer by moving root commit handling into the `mapped_commit()` function for better API consistency and improving the merge ancestor labels to show "empty tree" for root commits.

The changes in v2` include:
1. Adding a NULL pointer check for `commit` in `mapped_commit()`
2. Changing the ancestor message to "empty tree" when replaying root commits
3. Maintaining all existing behavior for non-root commits

The test case is updated to verify the new capability by replaying a history that includes the root commit onto another branch, confirming the full history is properly replayed. The author notes this might still conflict with an in-progress `--revert` functionality series but considers the conflict resolution trivial.

The patch is well-contained, touching only the necessary parts of `replay.c` and the test file. It follows the maintainer's guidance from v1 while adding a small UX improvement (the "empty tree" message) that wasn't specifically requested but makes sense given the changes. The implementation looks clean and focused on the root commit handling problem without introducing broader changes.
