This thread continues the long-running effort to eliminate Git's `the_repository` global variable by migrating repository-specific configuration settings. The current series (now at v4) tackles eight configuration globals that affect performance-sensitive paths, particularly in file status checking.

The first patch in the series, already reviewed and ready for merging, moved `core.trustctime` to repository-specific storage while preserving its eager parsing to avoid performance regressions in `git status`. The new email covers the second patch, which similarly migrates `core.checkstat` - another configuration that affects `match_stat_data()` performance. The changes are mechanical but important for preventing cross-repo state issues.

The series has received positive reviews from Christian Couder, Usman Akinyemi, and others, with only minor documentation polish remaining. Junio Hamano has indicated readiness to merge pending final confirmations. Performance analysis by Tian Yuchen confirmed the approach maintains speed while eliminating globals. The work connects to broader efforts around repository independence, performance optimization, and platform compatibility being driven by multiple contributors across the project.
