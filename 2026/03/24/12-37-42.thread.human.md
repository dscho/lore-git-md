This thread continues Olamide Caleb Bello's work on the long-running `the_repository` removal effort, systematically moving repository-dependent configuration from global variables into per-repository storage. The series is now at version 2, with the latest patch migrating the `core.checkstat` configuration (which controls how Git performs file status checks) into `struct repo_config_values`.

The changes follow the established pattern seen in prior migrations of other settings like `trust_ctime`, compression levels, and sparse-checkout configurations. The current work touches four files, with the most significant changes in `statinfo.c` where stat comparison logic is updated to use the repository-specific value. While the change is mechanical - preserving existing defaults and behavior - it affects core file status checking used across many Git operations, making thorough review important.

So far there hasn't been any feedback on this version of the series, though similar prior work has involved contributors like René Scharfe who have been active in the broader `the_repository` removal effort. The patch appears uncontroversial as it follows the same well-tested approach used for other configuration migrations. The main consideration is verifying there are no subtle behavioral changes in how Git detects file modifications, particularly given the wide impact across operations like checkout and diff.
