Bugfix for `git-remote-http` segfault when parsing refspecs outside a repository, following up on previous discussion. This is the fourth iteration of the patch from K Jayatheerth, implementing Jeff King's suggested solution to initialize the default hash algorithm in repository-less contexts.

The patch addresses a crash that occurs when `git ls-remote -h` is run outside a Git repository with global fetch refspecs configured. The root cause was `the_hash_algo` being NULL when `parse_refspec()` tried to access it. The solution mirrors the approach used in `git ls-remote` (commit 9e89dcb66a) by explicitly setting `GIT_HASH_DEFAULT` in `remote-curl.c` when operating without a repository.

The changes are minimal - just a few lines to initialize the hash algorithm and a test case that verifies the fix works by reproducing the crash scenario in a genuine non-repo environment. The patch maintains consistency with how other commands handle repository-less operations and preserves SHA-256 compatibility.

This appears to be the final version of the fix, having gone through several rounds of review and discussion.
