This is the second patch in a v5 series adding revert capability to `git replay`, primarily for GitLab's Gitaly service. The patch implements the core `--revert` mode functionality, building on the established approach from `sequencer.c` where reverts are treated as merges with swapped arguments.

The implementation handles reverts commit-by-commit in newest-first order (matching `git revert` behavior) to reduce conflicts. Each revert builds on the previous one, with commit messages following standard revert conventions ("Revert" prefix and "This reverts commit <hash>" footer). The author is set to the current user rather than preserving the original author, consistent with `git revert`.

Key technical aspects include:
- Swapping merge base/commit trees to reverse the diff direction
- Newest-first commit ordering for reverts
- Proper handling of revert-of-revert cases (using "Reapply" prefix)
- Comprehensive test coverage including bare repo scenarios
- Integration with existing replay infrastructure

The patch has undergone extensive review across five iterations, with all substantive feedback addressed. It's now in final polishing state with improved documentation, consolidated variable handling, and test cleanup. The higher-level interface discussion (flags vs subcommands) continues separately but doesn't block this series.

This appears ready for merging as a well-considered addition to `git replay`, particularly useful for server-side operations on bare repositories. The implementation follows established patterns while adding the specialized revert behavior needed by GitLab's use case.
