This is a bugfix addressing a regression in commit-graph generation number calculations for commits with dates after year 2514. The issue was introduced by Patrick Steinhardt's own earlier commit 024b4c9697 and was caught by GitLab's test suite using real-world data with extremely large timestamps (year 2600+).

The core problem stems from how commit-graph stores only 34 bits of commit dates while the full timestamp_t uses 64 bits. When commits were parsed both from commit-graph (34-bit dates) and object database (64-bit dates), generation number calculations could mismatch during commit-graph writes. The fix introduces a new `compute_generation_offset()` helper that explicitly masks commit dates to 34 bits before calculations, ensuring consistent behavior.

The patch is well-crafted with clear motivation, thorough explanation, and includes a regression test verifying the fix works with extreme dates (year 292,471,210,647). It has already received positive reviews from both Junio Hamano and Derrick Stolee, indicating high confidence in the solution. The fix maintains backward compatibility while properly handling edge cases in date parsing.
