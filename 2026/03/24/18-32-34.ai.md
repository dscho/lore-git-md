Test infrastructure robustness patch. Junio C Hamano continues his systematic effort to make the test suite compatible with `set -e` (exit on error) mode, this time addressing t7450-bad-git-dotfiles.sh. The change fixes a conditional test pattern that would incorrectly fail under `set -e` when the `refuse_index` variable is empty.

The patch demonstrates the careful attention needed when converting test conditions for `set -e` compatibility. The original code used `test -n "$refuse_index" && test_expect_success...` which would exit immediately if `refuse_index` was empty. The new version inverts the logic to `test -z "$refuse_index" || test_expect_success...` which properly handles the empty case while maintaining the same test behavior.

This continues the pattern seen in Junio's previous test suite fixes (t4032, t6002, test-lib.sh, t0008) where shell constructs that worked in the original test framework need adjustment to be compatible with stricter error checking. The change is small but meaningful - part of the broader effort to catch silent failures from misspelled test macros and other errors that currently pass unnoticed.

The patch shows Junio's methodical approach to this infrastructure work, addressing one test script at a time while establishing patterns (like the inverted test condition shown here) that can be applied to similar cases elsewhere in the test suite. No new edge cases or complications are introduced in this particular change, suggesting the solution approach is stabilizing as the effort progresses.
