This is a feature patch in the final stages of review, adding high-level event control to Adrian Ratiu's parallel hook execution series. Patrick Steinhardt raises a thoughtful question about potential ambiguity when a hook's friendly name matches an event name (like having a hook named "pre-commit" for the pre-commit event). While the documentation already addresses this by specifying that the event name must be used, Patrick suggests it might be clearer to outright forbid such naming collisions.

The discussion shows careful attention to edge cases in what is otherwise a polished series - all core patches have maintainer acks, and this final piece builds on well-tested infrastructure. The proposed config switch (`hook.<event>.enabled`) provides a clean way to disable entire hook events at once, complementing the existing per-hook controls. The implementation handles display logic cleanly in `git hook list`, showing event-disabled status as the primary indicator when relevant.

This appears to be one of the last open questions before the series can be merged, with Patrick's feedback focusing on making the naming rules as intuitive as possible. The thread demonstrates the project norms in action: even approved patches receive thorough review, and edge cases get attention even when the main functionality is sound.
