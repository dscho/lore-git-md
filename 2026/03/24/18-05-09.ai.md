Test infrastructure robustness patch. Junio C Hamano continues his investigation into making the test suite compatible with `set -e` (exit on error) mode, this time addressing t6002-rev-list-bisect.sh. The patch fixes a subtle interaction where `expr` commands could cause the test to fail under `set -e` even when the computation is working as intended.

The issue stems from `expr` returning status code 1 when evaluating to 0 or null - a valid mathematical result that shouldn't trigger an error exit. The patch modifies two `expr` calls to explicitly check the exit code with `test $? -le 1`, allowing the expected exit codes while still catching genuine errors (exit codes 2 for syntax errors or 3 for other problems).

This change is part of Junio's broader effort to make the test framework more robust by enabling `set -e`, which would help catch issues like misspelled test macros that currently fail silently. The patch demonstrates the careful attention needed to maintain backward compatibility while adding stricter error checking - a pattern we may see repeated across other test scripts as this effort progresses.

The modification is localized to bisection-related calculations in t6002, showing the incremental nature of this test suite modernization. While small, it represents an important step toward the goal of running the entire test suite with `set -e` enabled.
