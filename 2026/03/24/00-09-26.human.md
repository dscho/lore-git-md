This is a Google Summer of Code (GSoC) proposal from Amisha Chhajed for a new `git evict` command to manage disk space in partial clones. The proposal builds on Amisha's prior Git contributions, including optimizations to string list handling and sparse-checkout improvements.

The `git evict` command would allow users to manually remove objects from partial clones that can be re-fetched from remotes, with filtering options like `--outside-cone` and `--large-only`. Amisha has already prototyped basic functionality that can evict individual objects by modifying `want_object_in_pack()` during repacking. The proposal includes a detailed implementation plan and timeline, with mentors including Christian Couder, Karthik Nayak and Justin Tobler - all active in relevant subsystems.

Key open questions include whether this functionality belongs in `git maintenance` rather than as a new command, and how to handle edge cases where evicted objects become unavailable on remotes. The proposal appears technically sound and well-scoped for a GSoC project, though the mailing list may want to discuss the actual utility of such a command versus existing partial clone behaviors.
