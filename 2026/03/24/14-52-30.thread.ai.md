Thread examining test infrastructure robustness after discovery of a typo in t4014-format-patch.sh where `test_expected_success()` was incorrectly used instead of `test_expect_success()`. Original issue was introduced in commit 6005932d95 ("format-patch: add ability to use alt cover format") and fixed in Mirko Faina's mf/format-patch-cover-letter-format series.

Maintainer Junio C Hamano is systematically making the test suite compatible with `set -e` (exit on error) to catch silent failures from misspelled macros. The effort has revealed multiple subtle failure modes requiring careful fixes across test scripts. Junio has addressed:
- t4032-diff-inter-hunk-context.sh (handling unset config values)
- t6002-rev-list-bisect.sh (fixing `expr` command behavior)
- test-lib.sh foundational Git binary check (new patch)
- t0008-ignores.sh (`grep -v` exit status handling)
- t7450-bad-git-dotfiles.sh (empty variable condition handling)

Key technical details:
- Current test framework allows macro typos to pass silently with incorrect test counts
- `set -e` implementation requires handling edge cases like:
  - Config operations on potentially unset values (t4032)
  - `expr` returning status 1 for valid zero/null results (t6002)
  - Initial Git binary check exiting with status 1 (test-lib.sh)
  - `grep -v` exit status when no matches found (t0008)
  - Empty variable conditions in test sequences (t7450)
- Fixes demonstrate consistent patterns:
  - Replacing direct commands with status capture (test-lib.sh)
  - Adding `|| :` to ignore exit status when only output matters (t0008)
  - Inverting test conditions to handle empty cases (t7450)
- Eric Sunshine proposes alternative approach for t7450 using test prerequisites (PREREQ) instead of condition inversion
- Junio clarifies PREREQ is better suited for static environment checks while conditionals handle dynamic cases

Open questions:
- Full scope of `set -e` compatibility work needed across remaining test scripts
- How to document and standardize the appropriate use of PREREQ vs condition inversion
- Impact on test suite performance with stricter error checking
- Whether to modernize additional test patterns while addressing `set -e` issues

Participant positions:
