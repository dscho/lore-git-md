Thread examining test infrastructure robustness after discovery of a typo in t4014-format-patch.sh where `test_expected_success()` was incorrectly used instead of `test_expect_success()`. Original issue was introduced in commit 6005932d95 ("format-patch: add ability to use alt cover format") and fixed in Mirko Faina's mf/format-patch-cover-letter-format series.

Maintainer Junio C Hamano has been systematically making the test suite compatible with `set -e` (exit on error) to catch silent failures from misspelled macros, with fixes already applied to multiple test scripts. Jeff King (Peff) proposed an alternative stderr monitoring approach via Makefile modifications that would catch test errors by analyzing output files. Junio now acknowledges Peff's proposal as worth considering, noting his current `set -e` work has made 80-90% of test scripts clean but is willing to pause implementation to evaluate the alternative approach.

Key technical details:
- Current test framework allows macro typos to pass silently with incorrect test counts
- `set -e` implementation requires handling edge cases like config operations on unset values, `expr` status handling, and empty variable conditions
- Peff's stderr monitoring would redirect output to per-test files for post-run analysis
- Junio's `set -e` work has already made most test scripts compatible
- Approaches differ philosophically: exit-on-error (Junio) vs output monitoring (Peff)
- Stderr method catches more error types but doesn't work with --verbose-log
- Eric Sunshine previously proposed using PREREQ for static environment checks
- Junio established PREREQ (static) vs condition inversion (dynamic) distinction
- Peff demonstrates concrete `set -e` behavioral inconsistency where function call context in &&-chains affects error handling
- Example shows `false` followed by `echo` either terminating or continuing based on calling context

Open questions:
- Whether to proceed with `set -e`, adopt stderr monitoring, or combine both approaches
- Relative merits of each method in catching different error types
- Impact on test suite performance with stricter checking
- Documentation standards for test script modifications
- Handling of --verbose-log case under stderr monitoring
- How to address `set -e` context-sensitivity issues demonstrated by Peff
- Whether stderr monitoring could be made to work with --verbose-log
