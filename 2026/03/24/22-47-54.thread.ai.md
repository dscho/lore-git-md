Thread identity: GSoC proposal for prioritized fetching from multiple promisor remotes, part of Large Object Promisor (LOP) effort, from Abraham Samuel Adekunle.

Core problem: Currently no way to specify or negotiate priority order when fetching missing objects from multiple promisor remotes in partial clone workflows. This can lead to suboptimal performance when some remotes are faster or more reliable than others.

Proposed solution: Add configurable fetch ordering through three mechanisms - 1) client-specified priority via `remote.<name>.priority` config, 2) server-advertised recommended priorities via promisor-remote capability extension, 3) fallback default ordering. Builds on Christian Couder's existing promisor-remote protocol work.

Implementation scope: Will touch protocol negotiation (remote.c), configuration handling (config.c), and promisor object fetching logic (promisor-remote.c). Requires careful handling of edge cases in capability negotiation and fallback behavior.

Participant positions: Christian Couder (mentor) provides domain expertise as original author of promisor-remote capability. Abraham Samuel Adekunle (author) has prior experience with `git add -p` and test modernization but this is first protocol-level work.

Timeline: 12-week plan includes code study, incremental implementation with regular mentor checkpoints, focusing first on config handling before protocol changes. Demonstrates thoughtful approach to riskier protocol work.
