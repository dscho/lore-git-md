This is a feature addition to the `git replay` command, now at v5, introducing a `--revert` mode for server-side history rewriting. The series has undergone extensive review and is ready for merging, with all substantive feedback addressed.

The changes enable `git replay` to reverse commits directly on bare repositories, which is particularly useful for GitLab's Gitaly service where server-side operations on bare repos are common. The implementation follows the same approach as `sequencer.c`, treating reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent) to effectively reverse the diff direction.

Key changes in v5 include:
- Improved function documentation for `sequencer_format_revert_message()` with more concise wording
- Consolidated `revs.reverse` handling using a single `desired_reverse` variable throughout
- Better error handling with `die_for_incompatible_opt2()` for option conflicts
- Restored `the_repository` guard in replay.c
- Test script improvements using `${SQ}` for single-quote escaping
- Fixed SYNOPSIS formatting by removing erroneous ellipsis

The implementation has been thoroughly reviewed by Phillip Wood, Patrick Steinhardt, and Junio Hamano, with all technical points from prior discussion addressed. The higher-level interface design discussion (flags vs subcommands) continues but is being deferred to avoid scope creep in this series.
