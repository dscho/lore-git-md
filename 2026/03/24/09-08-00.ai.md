This is a follow-up discussion on the parallel hooks feature series, specifically addressing the per-event job configuration patch (7/9). Patrick Steinhardt suggests adding a user-friendly warning when someone mistakenly uses `hook.<friendly-name>.jobs` instead of the correct `hook.<event>.jobs` syntax.

The concern is valid - the current implementation silently ignores misconfigured keys that use hook names rather than event names in the jobs setting. Patrick proposes detecting these cases to help users understand why their configuration isn't taking effect. This would improve the debugging experience when users inevitably mix up the two similar-looking but semantically different configuration patterns.

The suggestion doesn't require any architectural changes to the series, just an additional validation check during config parsing. It aligns with the series' overall attention to user experience and configuration clarity. Since the core implementation already has maintainer acks, this would be a relatively small but valuable polish before final integration.
