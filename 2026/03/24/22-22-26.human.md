This is a review comment from Junio C Hamano on the first patch of Justin Tobler's series about signature handling in `git fast-import`. Junio points out an inconsistency in how invalid signature modes are handled between `fast-import` and `fast-export`.

The core issue is that the error checking for invalid modes (like `abort-if-invalid`) happens too late in `fast-export` - only when encountering a signed commit during export, rather than failing immediately during command-line parsing. Junio suggests two alternative approaches: either move the validation to the option parser in `fast-export`, or modify the shared `parse_sign_mode()` function to know when it's being called from `fast-export` and reject unsupported modes early.

This isn't a fundamental problem with the patch's functionality, but rather a UX polish point about when and how errors should be reported. The feedback suggests the implementation could be made more consistent with Git's usual pattern of failing fast on invalid options. Since this is Junio's first review in the thread, we can expect Justin to respond with either an explanation of the current approach or a revised patch addressing the concern.
