Justin Tobler has proposed a 4-patch series to make `git fast-import`'s signature handling more consistent between commits and tags, adding all three modes (`strip-if-invalid`, `sign-if-invalid`, and `abort-if-invalid`) for both operations. The series builds on recent work in this area and appeared complete with comprehensive test coverage.

However, Junio Hamano has raised a design-level concern about the first patch. While the implementation works correctly for `fast-import`, Junio notes an inconsistency with how `fast-export` handles invalid signature modes. Currently, `fast-export` rejects the `abort-if-invalid` mode only when processing signed commits, rather than failing immediately during option parsing like it does for other invalid modes. Junio suggests two approaches to fix this - either moving validation into `fast-export`'s option parser or enhancing the shared parsing function to be context-aware.

This feedback means Justin will need to revise the patch to address the validation timing issue before the series can proceed. The core functionality appears sound, but the user experience needs to be consistent across both import and export operations. No other open issues have been raised with the series.
