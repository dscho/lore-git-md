This is a review comment from Junio C Hamano on the first patch of Justin Tobler's series about fast-import signature handling. Junio points out an inconsistency in how invalid signature modes are handled between `fast-import` and `fast-export`.

The core issue is that while the patch adds an `abort-if-invalid` mode to `fast-import`, the same mode is being rejected in `fast-export` only when encountering signed commits during export, rather than failing immediately during option parsing. Junio notes this creates an inconsistent user experience where invalid modes like `i-dont-know-what-i-am-doing` would be caught early, but `abort-if-invalid` would only fail later during commit processing.

Junio suggests two potential solutions: either move the mode validation into `parse_opt_sign_mode()` in `fast-export.c`, or enhance the shared `parse_sign_mode()` function to be context-aware about whether it's being called from import or export operations. The latter approach would provide earlier and more consistent error reporting.

This is a design-level concern about user experience rather than a bug in the implementation. The feedback indicates the patch needs refinement in how it handles mode validation across the import/export boundary, though the core functionality for `fast-import` appears sound. Justin will likely need to revise the patch to address this validation timing issue before the series can proceed.
