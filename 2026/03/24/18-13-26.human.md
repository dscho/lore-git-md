Test infrastructure robustness patch. Junio C Hamano continues his work to make the test framework more resilient by enabling `set -e` (exit on error) in test scripts, building on earlier discussions about catching misspelled test macros. This patch specifically addresses the first hurdle in that effort - modifying how the test framework checks for a valid Git binary at startup.

The change rewrites the Git binary verification to handle `set -e` properly by capturing the exit status in a variable rather than checking `$?` directly. This prevents the script from immediately exiting when `git` returns non-zero (as it does when listing commands). The patch demonstrates the careful approach needed to maintain existing behavior while adding stricter error checking.

This is part of a larger effort to surface hidden issues in the test suite, following the discovery that typos in test macros (like writing `test_expect_successo` instead of `test_expect_success`) could silently pass. Junio notes this is just the first of likely several changes needed to make the test framework fully compatible with `set -e`, suggesting more patches will follow as other edge cases are identified.

The change is small but foundational, touching the core test-lib.sh that all tests source. It shows the maintainer's hands-on approach to improving test reliability while maintaining backward compatibility. The patch appears straightforward and well-justified, with no obvious downsides to the proposed change.
