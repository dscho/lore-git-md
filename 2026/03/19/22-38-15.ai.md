This is a refactoring patch in Mirko Faina's series improving `git format-patch --commit-list-format`. The patch simplifies the handling of empty values for the `format.commitListFormat` configuration variable by removing special-case logic that previously provided a default format when the value was empty.

The change makes the behavior more consistent with Git's typical configuration handling - an empty value now means "no format" rather than falling back to a default. The patch removes both the special-case code in `builtin/log.c` and the corresponding test case that verified the old behavior. This aligns with the series' goal of cleaning up and standardizing the commit list formatting feature.

The modification is straightforward and maintains the existing functionality for non-empty format strings. Since this is part of an established series that has already addressed review feedback, the change appears uncontroversial and well-justified as part of the overall cleanup effort. The patch keeps the focus on code quality while not introducing any new user-facing behavior.
