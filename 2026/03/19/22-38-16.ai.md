This is a feature patch in Mirko Faina's series improving `git format-patch --commit-list-format`. The patch adds line wrapping to commit messages in the generated cover letter when they would otherwise be too long.

The change introduces a new `wrapped_line` strbuf and uses Git's existing `strbuf_add_wrapped_text()` function to wrap commit message lines at `MAIL_DEFAULT_WRAP` width (72 characters by convention). This makes long commit messages more readable in email clients by preventing overly wide lines. The implementation is straightforward - it wraps each formatted commit line before writing to the cover file and properly cleans up the temporary buffers.

This is part of the ongoing effort to improve the usability and output quality of `git format-patch`'s commit list formatting feature. The patch fits naturally in the series, following earlier work that renamed the option and improved its behavior. The change is small and focused, touching only the commit list generation code in builtin/log.c while maintaining all existing functionality.
