This is a refactoring patch in Taylor Blau's series addressing geometric repacking and MIDX bitmap generation issues. It's the second of five patches, focusing on restructuring how pack-objects handles pack lists from stdin.

The patch replaces two separate `string_list`s (for included and excluded packs) with a single `strmap` that tracks pack information more generically. This prepares for future extensions to support different pack "kinds" (like the upcoming "excluded-open" packs). The key changes:

1. Introduces a `stdin_pack_info` struct to track both the pack pointer and its kind (included/excluded)
2. Splits the logic into two clearer functions: one for reading stdin input and building the pack map, another for processing the packs
3. Uses `strmap` instead of `string_list` to avoid quadratic behavior when handling duplicate pack entries

The refactoring maintains all existing functionality while making the code more extensible. This is a preparatory step for the actual fix in later patches, which will introduce the new "excluded-open" pack state. The changes are well-contained to pack-objects' stdin handling and come with thorough comments explaining the rationale.
