This is the seventh patch in Patrick Steinhardt's 14-part series refactoring Git's object name handling to be backend-generic as part of the ODB abstraction effort. The patch simplifies how Git collects ambiguous object IDs (when a short hash prefix matches multiple objects) by leveraging the new generic object iteration infrastructure introduced earlier in the series.

Previously, `repo_collect_ambiguous()` used separate backend-specific functions to find matching objects in loose and packed storage. Now it uses the unified `odb_for_each_object()` interface that was made prefix-aware in earlier patches. The change removes about half the code while maintaining identical behavior, demonstrating the benefits of the new abstraction layer.

The patch continues the series' pattern of systematically replacing direct backend access with the ODB interface. It's a clean, mechanical conversion that builds on the foundation laid by previous patches. Given Patrick's track record with this kind of careful refactoring and the thoroughness of the series so far, this appears to be a solid step toward the goal of pluggable storage backends. No reviews have been posted yet, but the changes are straightforward and unlikely to be controversial.
