Maintainer-submitted Coccinelle rule to formalize strbuf invariants.

Junio Hamano follows up on his earlier rerere.c cleanup with a more general effort to codify the strbuf invariant that `.buf` is never NULL. He proposes a Coccinelle semantic patch that would automatically rewrite `SB.buf ? SB.buf : ""` to just `SB.buf` (finding only the rerere.c case he already fixed), and also flag questionable NULL checks of strbuf.buf elsewhere in the codebase.

The patch identifies two exceptions where NULL checks remain valid:
1. In `parse_list_objects_filter()`, where checking an uninitialized strbuf is a legitimate BUG() case
2. In `strbuf_getwholeline()`, which temporarily breaks the invariant to interface with getdelim()

Junio suggests `strbuf_getwholeline()` could be rewritten to avoid this temporary invariant violation by using raw pointers with getdelim() followed by strbuf_attach(). This would be a follow-up cleanup opportunity.

The proposed Coccinelle rule is simple but effectively captures a subtle invariant that has persisted through nearly two decades of Git development. Coming from the maintainer, this carries significant weight as both a technical clarification and a style guideline for future code. The patch doesn't change any behavior but establishes clearer expectations around strbuf usage that could prevent bugs.
