René Scharfe's patch series to simplify strvec handling has progressed from manual conversion examples in v1 to a comprehensive Coccinelle-based solution in v2, now covering builtin/rebase.c in addition to the initial files. The semantic patch handles multiple variants of the strvec copying pattern, including cases with separate loop index declarations and unused indices.

Maintainer Junio C Hamano has responded positively to the approach while raising thoughtful questions about Coccinelle's role in code hygiene. He notes the patch produces good results in the fetch-pack.c conversion, though it doesn't apply cleanly to the maintenance branch (which is acceptable for this cleanup). Junio questions whether Coccinelle rules should aim for "ideal" output (like removing excess braces) or leave some formatting polish for humans - an open philosophical point about automation's role in code style. While not fully understanding the `unused_loop_index` rule's syntax, he doesn't consider this a blocking issue.

The discussion reflects René's reputation for careful mechanical cleanups and Junio's maintainer role in ensuring changes align with the project's evolving standards. The patch appears on track for acceptance, with this exchange serving to clarify expectations around Coccinelle's use as a tool for systematic code improvements.
