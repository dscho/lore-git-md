This thread explores a proposal to add a `--cc` option to the Linux kernel's `get_maintainer.pl` script, which would format its output as comma-separated emails for direct use with `git send-email`. The original author argues this would create tighter integration between the tools, offering performance benefits, more accurate dry-runs, and cleaner configuration compared to current shell script workarounds.

Joe Perches has expressed skepticism about the need for this change, maintaining that existing scripting solutions are adequate. In response, Jim Cromie detailed four specific advantages of direct integration, particularly emphasizing how configuration through `.git/config` could prevent maintainers from missing parts of patch series. The discussion now centers on whether these workflow improvements justify the change, with the technical implementation appearing sound but adoption still uncertain. The cross-project nature of the proposal - involving both Linux kernel tooling and Git - adds an extra layer of coordination complexity to the decision.
