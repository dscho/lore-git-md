This thread discusses the behavior of `check_repository_format_gently()` in Git's repository initialization code. Tian Yuchen raised the issue, noting that despite its name suggesting a pure" validation function, it modifies global state (setting `is_bare_repository_cfg` and `git_work_tree_cfg`), which could cause problems for tools working with multiple repositories.

Git maintainer Junio C Hamano responded by explaining that in Git's codebase, the word "check" doesn't necessarily imply side-effect-free operation - it's about returning error codes rather than aborting ("gently" means it won't call `die()`). While this clarifies the naming convention, the core question about separating validation from state modification for multi-repo scenarios remains open. The discussion now needs input from contributors familiar with repository internals about whether and how these concerns could be decoupled.
