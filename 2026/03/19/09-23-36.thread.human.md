This thread explored a proposal to add message-ID fetching capability directly to `git am`, allowing it to retrieve patches from public-inbox archives like lore.kernel.org. The original author, Shreyansh Paliwal, suggested a `--fetch-mid` option with configurable endpoints. However, maintainer Junio Hamano firmly rejected this approach, establishing a clear architectural boundary: `git am` should focus solely on applying patches from a mailbox, while tools like `b4` (which already provides this functionality via `b4 am -o-`) should handle mailbox acquisition from external sources.

Junio's position was categorical, calling the duplication of `b4`'s functionality in core Git "crazy" given the existing solution. His rejection cited both philosophical (core vs. external tool boundaries) and practical considerations. In a follow-up, Shreyansh acknowledged Junio's guidance and accepted the architectural separation without further argument. The thread concludes with consensus that message-ID fetching belongs in ecosystem tooling rather than core Git, and no outstanding questions remain. The matter is now cleanly resolved.
