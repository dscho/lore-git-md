This thread discusses a proposed enhancement to `git send-email` that would allow passing executable scripts directly to the `--to`, `--cc`, and `--bcc` flags, with the tool running these scripts to dynamically determine recipients. The original patch, based on Google-internal tooling from Jim Cromie, modifies `git-send-email.perl` to safely execute these scripts with proper argument escaping.

Kristoffer Haugsbakk raised a key question about how this new functionality differs from the existing `--cc-cmd` and `--to-cmd` options, which already provide script-based recipient selection. In a follow-up, D. Ben Knoble notes that while he uses `--cc-cmd` in his workflow (with `git-contacts` for Git project contributions), there is currently no `--bcc-cmd` equivalent. This suggests the new feature might primarily address that gap rather than replacing existing mechanisms. However, the discussion still lacks a clear technical justification for introducing a new interface rather than extending the current `--*-cmd` pattern. The thread remains open for the original author to clarify the design rationale and use cases that aren't served by the current options.
