This is the 11th patch in Patrick Steinhardt's 14-part series refactoring Git's name handling for the ODB abstraction effort. The patch simplifies how Git computes common prefixes between object IDs during abbreviation.

The change introduces a new `oid_common_prefix_hexlen()` function in `hash.c` that directly compares binary object IDs to find their common prefix length, rather than first converting them to hex strings. This is more efficient and eliminates the need for the `hex` field in `struct min_abbrev_data`. The function properly handles the final nibble case where only part of a byte matches.

The patch touches core hashing infrastructure (`hash.c`, `hash.h`) and object name handling (`object-name.c`), continuing the series' pattern of methodically modernizing the code while maintaining behavior. This appears to be a straightforward optimization that removes some indirection in the abbreviation logic, with the new function being reusable in future changes (as noted in the commit message). The change is well-contained and follows the series' incremental approach to refactoring the ODB interface.
