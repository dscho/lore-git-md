This is a test patch adding coverage for repository path reporting in non-default layouts, part of the ongoing "[PATCH v6 0/6] repo: enhanced repository path reporting" series. The patch extends test suite validation for the new `repo info` command's path resolution in three special cases: linked worktrees, separate git-dir repositories, and submodules with relative paths.

The new tests verify that `repo info` produces the same paths as equivalent `rev-parse` invocations for:
1. `path.git-dir`, `path.common-dir`, and `path.toplevel` in a linked worktree
2. The same paths plus relative-format `path.git-dir` in a repository created with `--separate-git-dir`
3. Relative-format `path.superproject-working-tree` in a submodule context

The test cases follow the same pattern as existing coverage - setting up the special repository state, then comparing `repo info` output against `rev-parse` for each path key. The implementation is straightforward shell scripting that creates the test repositories and validates the path outputs match.

This patch addresses test coverage gaps identified in the ongoing discussion about the path reporting functionality. It doesn't modify the core implementation but strengthens validation of edge cases that could reveal subtle bugs in path resolution. The tests are narrowly focused on the path reporting behavior and don't touch the broader repository metrics functionality that was split out in earlier series iterations.
