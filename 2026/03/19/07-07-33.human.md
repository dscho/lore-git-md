This is a design discussion in Pablo Sabater's GSoC project to add column limiting for `--graph` output, now at v3. Johannes Sixt (Hannes) weighs in on the naming and behavior of the proposed `--graph-limit-lanes` option, disagreeing with Junio Hamano's earlier suggestion that the option should implicitly enable `--graph`.

Hannes argues that since this could eventually become a configurable parameter, having it imply `--graph` would be problematic - you wouldn't want setting the config to automatically enable graph output. He suggests alternative names like `--edge-limit` or `--lane-limit` that don't tie the parameter so tightly to the `--graph` option itself.

This introduces a new perspective in the naming discussion, highlighting the tension between making the option's purpose clear while keeping it decoupled from the graph display decision. The thread shows how even seemingly small UX decisions in Git can involve balancing multiple concerns - in this case, command-line ergonomics versus future configuration flexibility. Hannes' feedback suggests the naming may need another iteration to satisfy both the immediate use case and potential future extensions.
