This is the second patch in Patrick Steinhardt's 14-part series refactoring Git's object name handling as part of the ODB abstraction effort. The patch modifies the crit-bit tree (cbtree) and oidtree iteration interfaces to allow callback functions to return arbitrary values rather than just continue/break statuses.

The key change is replacing the `enum cb_next` return type (which only allowed `CB_CONTINUE` or `CB_BREAK`) with a plain `int` return that can propagate any value from the callback up through the iteration stack. This matches Git's common pattern where callbacks return error codes that should abort iteration and bubble up to the caller.

The patch updates both the low-level cbtree implementation and the oidtree wrapper (which uses cbtree internally for storing OIDs), along with their unit tests. The oidtree documentation is also updated to clarify that callbacks can now return any non-zero value to stop iteration, with that value being propagated back.

This is a straightforward but important infrastructure change that makes the iteration interfaces more flexible while maintaining existing behavior. As part of Patrick's larger ODB abstraction work, it helps prepare the codebase for more sophisticated object storage backends. The changes are mechanical but well-contained, with thorough updates to both implementation and tests.
