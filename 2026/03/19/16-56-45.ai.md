This is a feature proposal for tighter integration between `get_maintainer.pl` and `git send-email`. Jim Cromie responds to Joe Perches' skepticism about the utility of the proposed `--cc` option by outlining four specific advantages over current scripting approaches.

The response makes a technical case for why direct integration would be superior to shell wrappers: (1) performance benefits by avoiding per-patch script execution, (2) better dry-run accuracy by keeping the operation within `send-email`, (3) reduced risk of errors from duplicate patch list arguments, and (4) cleaner configuration through `.git/config` settings. The last point about configuration is presented as particularly compelling, suggesting it could prevent maintainers from missing parts of patch series.

The exchange highlights a fundamental disagreement about workflow improvements - while Joe Perches sees existing scripting as sufficient, Jim Cromie argues the proposed integration offers tangible benefits around performance, reliability, and configuration. The cross-project nature (Linux kernel tooling + Git) remains a complicating factor, as does the need to demonstrate these advantages convincingly enough to overcome resistance to change. The technical merits appear sound, but adoption may hinge on whether the Git community finds these workflow improvements compelling enough to warrant the change.
