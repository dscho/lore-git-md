This is a design discussion in Pablo Sabater's graph column limiting feature series, now at v3. Johannes Sixt (Hannes) weighs in on the proposed `--graph-limit-lanes` option that would implicitly enable `--graph`, arguing against the implicit behavior. He suggests alternative names like `--edge-limit` or `--lane-limit` and raises a configuration concern - if this becomes a config option later, having it imply `--graph` would be problematic.

The thread had previously converged on `--graph-limit-lanes` with implicit `--graph` behavior after Junio Hamano's feedback, but Hannes introduces new considerations about future configurability. His position suggests the option should remain purely about setting the limit without affecting graph display behavior, keeping the concerns separate.

This creates a potential conflict with Junio's earlier direction, as the author now faces competing design inputs. The core technical implementation (column limiting via `graph_max_columns` in `rev_info`) remains unchanged, but the user-facing behavior and naming are back in discussion. Hannes' perspective comes from experience with graphical Git tools (as gitk maintainer) and suggests thinking ahead to configuration scenarios.
