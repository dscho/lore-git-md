This is the second patch in Patrick Steinhardt's 14-part series refactoring Git's object name handling to be backend-generic in the ODB layer. The patch focuses on the oidtree and crit-bit tree (cbtree) subsystems.

The change makes the iteration interface more flexible by allowing callback functions to return arbitrary integer values rather than being restricted to CB_CONTINUE/CB_BREAK. This matches Git's common pattern where callbacks return error codes that should propagate up. The patch:

1. Modifies cbtree.c/h to replace the enum cb_next with direct integer returns
2. Updates oidtree.c/h to pass through callback return values
3. Adjusts related callers in object-name.c and unit tests
4. Improves documentation to clarify the new behavior

This is a preparatory change that maintains existing functionality while making the code more flexible for future use cases. It's part of the larger ODB abstraction effort to enable pluggable storage backends, though this particular change is more about general code quality than backend-specific functionality. The patch appears clean and focused, with thorough updates to both implementation and tests.
