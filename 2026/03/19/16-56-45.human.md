This is a feature proposal for tighter integration between `git send-email` and the Linux kernel's `get_maintainer.pl` script. Jim Cromie responds to Joe Perches' skepticism about the utility of a proposed `--cc` option by outlining four concrete advantages over current scripting approaches.

The key benefits highlighted are performance (avoiding per-patch script execution), dry-run accuracy, argument deduplication, and configuration synergy - particularly the ability to set `sendemail.cc` to directly invoke the maintainer script. The author argues this would reduce maintainer annoyance from incomplete patchset deliveries.

While the technical implementation appears sound, the discussion reveals a philosophical divide: the author sees value in deeper tool integration while the reviewer prefers simpler scripting solutions. The cross-project nature (Git tooling + Linux kernel workflow) adds coordination complexity beyond the technical merits. The proposal's fate likely hinges on whether these workflow improvements convince enough kernel maintainers to adopt the change.
