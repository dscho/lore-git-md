This thread discusses Taylor Blau's patch series addressing an edge case in Git's geometric repacking where MIDX bitmap generation could fail when packs weren't properly closed under reachability. The series introduces a new "excluded-open" pack state (marked with '!') to handle objects reachable through excluded packs while excluding their direct contents.

The v2 series maintains its 5-patch structure, with the first three patches already reviewed. Patch 1 fixed a memory leak, Patch 2 refactored pack handling based on Patrick Steinhardt's feedback, and Patch 3 added a test demonstrating the failure case. The newly submitted Patch 4 implements the core solution, adding a `pack_keep_in_core_open` flag to distinguish between fully excluded packs ('^') and excluded-but-open packs ('!'). It includes thorough documentation and test coverage for both the new functionality and backward compatibility.

Taylor Blau (a Git PLC member and GitHub engineer) has incorporated feedback from Jeff King and Patrick Steinhardt throughout the series. The changes show careful attention to edge cases in geometric repacks while improving the code organization for future maintenance. The solution appears well-constructed, with comprehensive test coverage that exercises both the new functionality and existing behavior. The final patch in the series will update `builtin/repack.c` to properly mark packs as excluded-open when needed.
