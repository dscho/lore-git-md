This thread addresses issues in Git's pack-objects and geometric repacking machinery, where certain pack files not closed under reachability were causing MIDX bitmap generation failures. Taylor Blau's 5-patch series introduces a solution through a new "excluded-open" pack state that properly handles reachable objects from excluded packs.

The discussion has been technically detailed, with Jeff King catching a subtle NULL pointer issue in the object-walking logic that Taylor is addressing through either assertion or control flow restructuring. The series includes both core fixes and a test demonstrating the failure scenario with once-cruft objects above the geometric split point.

Patrick Steinhardt recently weighed in on the first patch, which fixed a memory leak in `read_stdin_packs()`. While acknowledging the correctness of the fix, Patrick raised an important question about why the test suite didn't catch this leak, highlighting a gap in the project's memory-leak detection for revision walking. This reflects Patrick's characteristic thoroughness in review, even for preparatory patches.

The series remains under active discussion, with particular focus on patch 4's handling of edge cases in the object-walking logic. Taylor Blau, as both a GitHub engineer and PLC member, is driving this work to solve real-world issues encountered in large repository maintenance at GitHub. The changes maintain backward compatibility while addressing specific pain points in geometric repacking scenarios.
