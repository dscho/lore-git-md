This is the twelfth patch in Patrick Steinhardt's 14-part series refactoring Git's object name handling for the ODB abstraction effort. The patch moves the logic for computing loose object abbreviation lengths into the ODB backend interface.

The change extracts the loose-object-specific abbreviation calculation from `object-name.c` into a new `odb_source_loose_find_abbrev_len()` function in `object-file.c`. This function uses the new `oid_common_prefix_hexlen()` helper introduced in patch 11 to directly compare OIDs in binary form rather than converting to hex strings first. The implementation maintains the same behavior while being more efficient and properly abstracted for pluggable backends.

Key technical details:
- Introduces `find_abbrev_len_cb` callback that uses binary OID matching
- Adds new public `odb_source_loose_find_abbrev_len()` interface
- Removes now-unused `extend_abbrev_len_loose` and `find_abbrev_len_loose` functions
- Updates `repo_find_unique_abbrev_r()` to use the new backend interface

This continues the pattern seen throughout the series of systematically moving object-handling logic into backend-specific implementations while maintaining the existing behavior. The changes are focused on `object-file.c`, `object-file.h`, and `object-name.c`, with the goal of making abbreviation calculation work consistently across different storage backends.
