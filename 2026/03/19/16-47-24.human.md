This is a bug report thread about `git grep` behavior, where Randy Dunlap confirms the resolution of his issue with help from Jeff King and Junio Hamano. The problem stemmed from Randy using `git apply` without `--index`, which left the patched file untracked and thus excluded from `git grep`'s default search scope. 

Jeff had previously contrasted this with `git am`, which automatically stages changes and creates a commit. Randy acknowledges the explanation, recognizing his mistake as a simple user error and noting the behavioral difference between `git apply` and `git am`. The thread serves as a good reminder about how Git's various patch application methods interact with the working tree and index in ways that can affect other commands' behavior.

The discussion is now resolved, with Randy understanding the distinction between the two commands and how they affect file status. No further action is needed unless someone wants to document this subtlety more prominently in the Git documentation.
