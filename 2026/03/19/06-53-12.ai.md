This is the final patch in Patrick Steinhardt's 14-part series refactoring Git's object name handling for the ODB (object database) abstraction effort. The series systematically modularizes object name disambiguation and abbreviation to support pluggable backends.

The patch introduces a new generic `odb_find_abbrev_len()` function that provides a backend-agnostic way to determine the minimum prefix length needed to make an object ID unique. Key changes:

1. Moves the core abbreviation length calculation logic from `object-name.c` to the new ODB interface in `odb.c`
2. Adds a new callback `find_abbrev_len` to the `odb_source` vtable
3. Implements the callback for the files-based backend in `odb/source-files.c`
4. Updates `repo_find_unique_abbrev_r()` to use the new interface

The implementation maintains identical behavior while making the functionality backend-specific. The patch completes the series' goal of moving all object name handling logic into the ODB layer, with the files backend providing its own optimized implementations (building on the packed/loose object changes from previous patches).

This is a significant infrastructure change that enables alternative storage backends to implement their own abbreviation logic while maintaining consistent behavior. The series appears thorough and well-structured, following Patrick's characteristic incremental refactoring approach. Given the complexity of the changes and their impact on core object handling code, careful review will be needed, though the systematic nature of the series and Patrick's track record with major refactorings suggest this is likely production-ready work.
