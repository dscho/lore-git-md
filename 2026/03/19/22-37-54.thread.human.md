This thread investigates a macOS CI build failure that surfaced when GitHub Actions runners updated their Homebrew installation, causing regex handling to break. The root cause was traced to Homebrew's clang switching from Apple's system version to LLVM 15.0.7, which lacks Apple's REG_ENHANCED flag that Git's build system assumed would be available.

Johannes Schindelin provided the definitive analysis, showing how Homebrew 5.1.0's auto-linking behavior changed the clang version being used. He proposed a targeted solution: adding NO_REGEX to the Darwin configuration when using clang, which forces Git to use its bundled regex implementation. This maintains consistent behavior while properly documenting the platform limitation, avoiding the behavior-changing workaround Junio initially considered.

The discussion revealed deeper build system insights - notably that USE_ENHANCED_BASIC_REGULAR_EXPRESSIONS in config.mak.uname indicates system capability rather than triggering compat/regex.c usage. The meson build's robust feature detection served as a reference implementation that avoided this issue entirely. The solution is now focused on adding explicit configuration for this specific Homebrew/clang case while leaving other build scenarios unchanged.
