This thread investigates macOS CI failures caused by Homebrew's clang compiler unexpectedly lacking the REG_ENHANCED regex flag. The issue stems from GitHub Actions runners updating to Homebrew 5.1.0, which changed how clang links libraries and omitted the crucial __MAC_OS_X_VERSION_MIN_REQUIRED macro needed for REG_ENHANCED support.

Johannes Schindelin (Dscho) initially diagnosed the environmental changes and implemented a solution forcing Git to use its bundled regex implementation (NO_REGEX) when detecting Homebrew's clang. René Scharfe later pinpointed the exact technical cause but proposed an alternative approach: hardcoding /usr/bin/clang to ensure consistent system compiler behavior.

In the latest exchange, Schindelin acknowledges René's precise diagnosis but expresses reservations about the system-clang approach. While it would fix CI, it might not help end users who explicitly set CC=clang in their environment. Schindelin favors his NO_REGEX solution as it handles both CI and real-world cases consistently, while thoroughly documenting the root cause in the build configuration.

The discussion highlights the project's careful approach to platform-specific issues - balancing immediate CI fixes with long-term maintainability. Both solutions would work, but they represent different philosophies: René's focuses on CI stability through environment control, while Schindelin's prioritizes consistent behavior across all usage scenarios. The thread remains open for further discussion or implementation refinement.
