Taylor Blau's 5-patch series addresses pack-objects issues when geometric repacking encounters packs not closed under reachability, causing MIDX bitmap generation failures. The problem occurs when objects are reachable through excluded packs but missing from the MIDX. The solution introduces a new "excluded-open" pack state (marked with '!') that includes reachable objects from these packs while excluding their direct contents.

Patch 1 fixed a memory leak in builtin/pack-objects.c where `read_stdin_packs()` wasn't calling `release_revisions()`. Patch 2 refactored pack handling by replacing two `string_list`s with a unified `strmap` containing `stdin_pack_info` structs that bundle pack pointers with kind flags. Patch 3 added a test demonstrating the failure scenario: geometric repacking failing to maintain object closure for once-cruft objects (previously unreachable but made reachable again) above the geometric split point.

Patch 4 implemented the core fix by introducing the "excluded-open" pack state with '!' prefix, allowing pack-objects to include objects reachable from these packs while excluding their direct contents. It added a `pack_keep_in_core_open` flag to `struct packed_git` and corresponding `KEPT_PACK_IN_CORE_OPEN` constant, with key modifications to `want_object_in_pack()` and `add_object_entry_from_pack()` to ensure proper commit traversal from excluded-open packs. Jeff King (Peff) identified a potential NULL pointer dereference in patch 4's changes to `add_object_entry_from_pack()` where the removed `want_object_in_pack()` check previously guarded against NULL `p` values, creating a logical inconsistency with the remaining `if (p)` check. This requires either restoring the safety check or documenting/asserting that `p` is never NULL at this point.

The final patch 5 completes the solution by modifying `builtin/repack.c` to mark packs above the geometric split point as excluded-open ('!') when they weren't in the previous MIDX and `repack.midxMustContainCruft` is false. This ensures pack-objects traverses commits from these packs during the follow pass, rescuing reachable objects that might otherwise be missing. The test from patch 3 now passes with this change, demonstrating the fix works for rescuing once-cruft objects above the geometric split. Taylor acknowledges a rare edge case with pre-existing MIDXs but explains why this is extremely unlikely in practice and how an all-into-one repack would resolve it.

The series carefully extends behavior via opt-in notation without altering defaults, focusing on pack machinery used in geometric repacking and MIDX bitmap generation. Taylor Blau (GitHub engineer and PLC member) drives this work addressing real-world issues at GitHub, with key areas being reachability handling in patch 4 and geometric/MIDX interactions in patch 5. Jeff King's review caught a subtle NULL pointer issue in the object-walking logic that needs resolution. The test in patch 3 serves as both documentation of the bug and validation mechanism for the fix. The changes maintain an incremental approach, introducing new behavior only where needed while preserving existing functionality.
