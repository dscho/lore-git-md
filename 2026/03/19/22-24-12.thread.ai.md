Taylor Blau's v2 patch series (5 patches) addresses pack-objects issues during geometric repacking when MIDX bitmap generation fails due to packs not being closed under reachability. The solution introduces a new "excluded-open" pack state (marked with '!') to properly handle objects reachable through excluded packs while excluding their direct contents.

Key technical components:
- Fixes memory leak in `read_stdin_packs()`
- Refactors pack handling from string_lists to strmap (currently contains two bugs: incorrect `pack_mtime_cmp()` assumption about `->util` contents and flag accumulation issue using '=' instead of '|=')
- Demonstrates failure case with once-cruft objects becoming reachable
- Implements core fix with `pack_keep_in_core_open` flag
- Modifies `builtin/repack.c` for excluded-open marking

Review status:
- Derrick Stolee identified the flag accumulation bug in patch 2/5 and maintains his approval pending this fix
- Jeff King and Patrick Steinhardt have provided positive feedback on the overall approach
- Junio C Hamano confirmed anonymous enum is appropriate for internal `stdin_pack_info` constants
- Stolee suggests naming the enum type for future clarity despite current limited scope
- Series has thorough test coverage except for the newly discovered comparator issue

Open issues:
1. `pack_mtime_cmp()` incorrectly assumes `->util` points to `packed_git` when it contains `stdin_pack_info`
2. Flag accumulation in pack specification uses '=' instead of '|=' for multiply-specified packs

The core functionality (handling excluded-open packs during geometric repacking) remains sound and has consensus approval. Taylor will submit v3 addressing the remaining strmap refactoring issues in patch 2/5 while preserving the working solution for MIDX bitmap generation edge cases. The series maintains compatibility with geometric repack behavior and documents non-MIDX pack reachability assumptions.
