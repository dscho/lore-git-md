Taylor Blau's v2 patch series (5 patches) resolves pack-objects issues during geometric repacking when MIDX bitmap generation fails due to packs not being closed under reachability. The solution introduces a new "excluded-open" pack state (marked with '!') to properly handle objects reachable through excluded packs while excluding their direct contents.

Key patches:
1. Fixes memory leak in `read_stdin_packs()`
2. Refactors pack handling from string_lists to strmap (currently contains a bug where `pack_mtime_cmp()` incorrectly assumes `->util` points to `packed_git` when it actually contains `stdin_pack_info` structs)
3. Demonstrates failure case with once-cruft objects becoming reachable
4. Implements core fix with `pack_keep_in_core_open` flag
5. Modifies `builtin/repack.c` for excluded-open marking

Technical discussion confirmed anonymous enum is appropriate for `stdin_pack_info` constants (STDIN_PACK_INCLUDE/EXCLUDE_CLOSED) since they're only used within struct context. Junio C Hamano provided rationale that naming would only help if constants needed external visibility. Taylor noted naming could introduce edge case bugs with duplicate pack specs.

- Resolved all technical and stylistic questions except the strmap comparator
- Maintains compatibility with geometric repack behavior
- Documents non-MIDX pack reachability assumptions
- Updates test expectations
- Finalizes strmap lookup behavior (except for the mtime comparison case)
