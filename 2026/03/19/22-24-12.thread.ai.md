Taylor Blau's v2 patch series (5 patches) addresses pack-objects issues during geometric repacking when MIDX bitmap generation fails due to packs not being closed under reachability. The solution introduces a new "excluded-open" pack state (marked with '!') to properly handle objects reachable through excluded packs while excluding their direct contents.

Patch 1 fixes a memory leak in `read_stdin_packs()`. Patch 2 refactors pack handling from string_lists to a strmap keyed by pack basename, with values in a new `struct stdin_pack_info` tracking pack pointers and inclusion status, addressing Patrick Steinhardt's feedback. Patch 3 demonstrates the failure case with once-cruft objects that become reachable again through new references, showing how geometric repacking with bitmap generation fails when object closure isn't maintained.

Patch 4 (new in this update) implements the core fix by:
- Adding `pack_keep_in_core_open` flag to `struct packed_git` and `KEPT_PACK_IN_CORE_OPEN` constant
- Modifying `add_object_entry_from_pack()` to handle excluded-but-open packs ('!')
- Adding new `include_check` callbacks to limit traversal at closed-excluded pack boundaries
- Including thorough documentation of the new '!' pack prefix behavior
- Adding test cases for both happy path and edge cases

Key technical details:
- New test in patch 3 verifies `repack.midxMustContainCruft=false` behavior
- Demonstrates interaction between cruft packs, geometric repacking, and bitmap generation
- Core fix uses BUG()` assertion for pack pointer validity
- Maintains compatibility with existing geometric repack behavior

Taylor Blau (GitHub engineer and PLC member) has addressed all review feedback from Jeff King and Patrick Steinhardt. The series now includes both the strmap refactoring improvements, test case documenting the edge case, and the actual fix. The changes maintain focus on solving subtle edge cases in geometric repacks while improving code organization for future maintenance of the pack-objects and repack machinery. One remaining patch (5) is expected to update `builtin/repack.c` to mark packs above the geometric split point as excluded-open when needed.
