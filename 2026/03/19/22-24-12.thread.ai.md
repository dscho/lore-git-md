Taylor Blau's 5-patch series addresses pack-objects issues when geometric repacking encounters packs not closed under reachability, causing MIDX bitmap generation failures. The problem occurs when objects are reachable through excluded packs but missing from the MIDX. The solution introduces a new "excluded-open" pack state (marked with '!') that includes reachable objects from these packs while excluding their direct contents.

Patch 1 fixed a memory leak in builtin/pack-objects.c's `read_stdin_packs()` by adding a missing `release_revisions()` call. Patrick Steinhardt acknowledged the fix's correctness but questioned why the test suite didn't catch this leak, highlighting a testing gap for revision-walking memory leaks that had persisted since the function's 2021 introduction. This exemplifies Patrick's thorough review approach even for preparatory patches.

Patch 2 refactored pack handling with a unified `strmap` containing `stdin_pack_info` structs. Patch 3 added a test demonstrating the failure scenario with once-cruft objects above the geometric split point.

Patch 4 implemented the core fix with "excluded-open" pack state and `pack_keep_in_core_open` flag, modifying `want_object_in_pack()` and `add_object_entry_from_pack()`. Jeff King (Peff) identified a potential NULL pointer dereference in patch 4's changes where the removed `want_object_in_pack()` check previously guarded against NULL `p` values. Taylor Blau responded with two solutions: adding a BUG() assertion or restructuring to preserve the check more intentionally. The proposed diff shows storing the `want_object_in_pack()` result and only creating entries for wanted objects, maintaining behavior for excluded-open packs while being explicit about control flow. Taylor seeks further review on edge cases.

Patch 5 modifies `builtin/repack.c` to mark packs above the geometric split point as excluded-open when needed, ensuring proper commit traversal. The test from patch 3 validates the fix for rescuing once-cruft objects. Taylor acknowledges a rare edge case with pre-existing MIDXs but explains why it's unlikely in practice.

The series participants include Taylor Blau (GitHub engineer and PLC member) driving the geometric repacking fixes, Jeff King providing critical review catching a NULL pointer issue in object-walking logic, and Patrick Steinhardt engaging on testing implications. The changes maintain an incremental approach while preserving existing functionality, with key areas being reachability handling in patch 4 and geometric/MIDX interactions in patch 5. The test in patch 3 serves as both documentation of the bug and validation mechanism. Open items include resolving the NULL pointer handling approach in patch 4 and considering broader test coverage for revision-walking memory leaks.
