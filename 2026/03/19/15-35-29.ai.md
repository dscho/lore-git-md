This is a continuation of the discussion about integrating message-ID fetching into `git am`. Junio C Hamano firmly rejects the proposal, arguing that interacting with lore.kernel.org to fetch patches is outside Git's core scope and is already well-handled by the `b4` tool.

Junio makes a clear architectural distinction: `git am` should remain focused on applying patches from a mailbox, while tools like `b4` should handle the mailbox acquisition from external sources. His response is categorical - not only is the external solution acceptable, but attempting to duplicate this in core would be "crazy" given `b4`'s existing capability.

The response effectively closes the technical discussion by establishing a bright line between core functionality and external tooling. Junio's position as maintainer makes this a strong signal that the proposal won't be accepted in its current form. The thread now has clear guidance that message-ID fetching belongs in the ecosystem (via `b4`) rather than in Git itself.
