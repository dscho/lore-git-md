Refactoring discussion about strbuf.buf NULL checks.

Jeff King (Peff) responds to Junio Hamano's RFC about eliminating unnecessary NULL checks for strbuf.buf, agreeing with the technical approach while offering nuanced feedback on the proposed exceptions. He concurs that the BUG() check in parse_list_objects_filter() could potentially be removed now that LIST_OBJECTS_FILTER_INIT usage is more established, though he's fine keeping it as a safeguard against uninitialized structs.

The more substantial discussion centers on strbuf_getwholeline(), where Junio had suggested a refactoring using strbuf_attach() could eliminate the need for a special case. Peff provides a concrete diff showing how this would look, but observes that the proposed rewrite doesn't simplify the code as hoped - the same complexity around maintaining strbuf invariants remains, just rearranged. The strbuf_init() case would still be needed to handle getdelim()'s allocation behavior.

This exchange represents experienced maintainers carefully evaluating edge cases in a systematic cleanup effort. Peff's response validates the overall direction while providing grounded technical analysis of the strbuf_getwholeline() case, suggesting that particular exception might need to remain even if others can be eliminated. The discussion remains focused on implementation details rather than challenging the core premise that these NULL checks are obsolete.
