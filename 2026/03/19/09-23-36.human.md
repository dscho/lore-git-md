This is a feature proposal for `git am` that would allow applying patches directly from message IDs without manually downloading them first.

Shreyansh Paliwal suggests adding a `--fetch-mid` option to `git am` that would fetch patches from public-inbox URLs (like lore.kernel.org) using the standard message ID format. The proposal includes making the base URL configurable via `am.publicInboxUrl` and suggests it could potentially handle entire patch series by just providing a cover letter's message ID.

The idea appears well-motivated for developers who frequently apply patches from mailing lists, as it would eliminate the manual step of downloading patch files. The implementation seems straightforward since public-inbox already serves patches in mbox format that `git am` can process directly.

This is an RFC (Request for Comments), so the author is seeking feedback on whether this would be useful and if there are existing alternatives they might have missed. The proposal looks clean and focused, though it would need to address potential edge cases like network connectivity issues, authentication for private inboxes, and handling malformed message IDs.
