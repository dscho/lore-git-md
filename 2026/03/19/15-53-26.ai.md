This is a follow-up in a bug report thread about `git grep` behavior, where Jeff King (Peff) clarifies the root cause of Randy Dunlap's issue. The key insight is that Randy used `git apply` without `--index`, leaving the patched file untracked, which `git grep` ignores by default. Jeff contrasts this with his own successful reproduction using `git am`, which automatically stages changes. 

Jeff explains the behavioral difference between `git apply` (which just modifies working tree files) and `git am` (which creates commits). He suggests Randy either use `git add` + `git commit` to track the changes, or better yet, use `git am` directly to handle both steps at once while preserving the original commit message. The email reinforces Junio's earlier diagnosis while providing practical workflow advice for future cases.
