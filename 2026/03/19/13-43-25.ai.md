This is the maintainer's response to a feature proposal for `git am` to fetch patches directly from message IDs. Junio C Hamano points out that the proposed functionality already exists in the `b4` tool, which can fetch patches from message IDs and output them in a format suitable for piping to `git am`.

The reply is brief but significant - it indicates the core idea isn't novel since `b4` (a tool specifically designed for working with mailing list patches) already implements this workflow. This suggests the proposal would need to demonstrate why integrating this directly into Git would be better than using the existing external tool.

The response doesn't outright reject the idea but sets a higher bar for justification - the author would need to show why this functionality belongs in Git core rather than remaining a `b4` feature. This is typical of Junio's maintainer style: concise but decisive when pointing out prior art or existing solutions.

Key technical context:
- `b4` is a Python tool for working with patches on mailing lists
- Its `b4 am` command can fetch patches by message ID
- The `-o-` option outputs the mbox to stdout, allowing piping to `git am`
- The thread now hinges on whether direct Git integration offers advantages over this existing workflow
