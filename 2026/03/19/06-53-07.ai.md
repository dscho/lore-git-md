This is the ninth patch in Patrick Steinhardt's 14-part series refactoring Git's object name handling to be backend-generic as part of the ODB abstraction effort. The patch simplifies the disambiguation logic by merging two closely related functions.

The change combines `match_prefix()` and `update_candidates()` into a single `update_disambiguate_state()` function. The original split was artificial since `match_prefix()` was just a trivial wrapper around `update_candidates()` with only one caller. The new unified function handles both the prefix matching and candidate updating logic in one place while maintaining the same behavior.

Key technical details:
- The new function takes the same parameters as the old `match_prefix()` callback (object ID, object info, callback data)
- It preserves all the existing disambiguation logic for handling ambiguous object prefixes
- Updates all call sites to use the new unified function
- Maintains the same return value semantics (returning whether ambiguity was detected)

This is a clean internal refactoring that reduces indirection without changing functionality. It continues the series' pattern of simplifying the object name handling code while making it more suitable for pluggable backends. The patch touches only `object-name.c` and builds on the ODB iteration infrastructure introduced in earlier patches.
