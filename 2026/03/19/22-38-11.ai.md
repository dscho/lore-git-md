This is the first patch in a feature series improving `git format-patch --commit-list-format`. The patch focuses on error message clarity for the `%(count)` and `%(total)` placeholders.

The change makes error messages more specific by naming the problematic placeholder when a command doesn't support it, rather than using a generic "this format specifier" message. The new messages will help users immediately understand which placeholder caused the error rather than having to infer it.

This is a straightforward improvement to user experience with no behavioral changes beyond the error text. The patch is small (just 2 lines changed) and well-contained, modifying only the pretty.c file where these format placeholders are handled. As the first patch in the series, it sets up for later changes that will expand the use of these placeholders.

The change follows Git's conventions for error messages and maintains consistency with how other format specifier errors are reported. It's a clear improvement that makes the code more user-friendly without introducing any complexity or risk.
