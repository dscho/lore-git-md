This is the 10/14 patch in Patrick Steinhardt's series refactoring Git's object name handling to be backend-generic as part of the ODB abstraction effort. The patch simplifies how Git calculates minimum unique abbreviations for loose objects by removing an unnecessary indirection through the disambiguation state machinery.

The change eliminates the `find_short_object_filename()` function and its use of `disambiguate_state` for loose object abbreviation, replacing it with direct use of `min_abbrev_data` via new helper functions `extend_abbrev_len_loose()` and `find_abbrev_len_loose()`. This makes the code more straightforward by:
- Removing the `always_call_fn` flag from `disambiguate_state` since it's no longer needed
- Directly using the ODB iteration interface with the new helpers
- Keeping the same behavior while reducing indirection

The patch continues the series' pattern of methodically moving object name handling into the ODB layer while maintaining compatibility. It touches the same core files as previous patches (`object-name.c`, `odb.c`) and follows the established approach of incremental, behavior-preserving refactoring. The changes are focused and well-contained, with no apparent impact on functionality or performance.
