This is the 13th patch in Patrick Steinhardt's 14-part series refactoring Git's object name handling for the ODB (object database) abstraction effort. The patch continues the systematic modularization of object name disambiguation and abbreviation logic.

The key change moves the packed object abbreviation length calculation from `object-name.c` to `packfile.c`, introducing a new `packfile_store_find_abbrev_len()` function. This parallels the previous patch's move of loose object abbreviation logic and completes the pattern of making abbreviation calculation backend-specific. The implementation:

1. Extracts and relocates three core functions:
   - `extend_abbrev_len()` (now takes direct OID comparison)
   - `find_abbrev_len_for_midx()` (handles multi-pack-index cases)
   - `find_abbrev_len_for_pack()` (handles single packfiles)

2. Updates `repo_find_unique_abbrev_r()` to use the new backend interface rather than the removed `find_abbrev_len_packed()` helper.

3. Maintains identical behavior while reducing indirection - the packed and loose object abbreviation paths now share a more direct calling convention.

The changes touch `object-name.c`, `packfile.c`, and `packfile.h`, with 123 lines removed from the former and 111 added to the latter. This continues the series' pattern of methodically decomposing object name handling while preparing for pluggable backends. The patch appears to be another clean, incremental step in the ODB abstraction effort with no obvious technical concerns.
