This is the third patch in Taylor Blau's 5-patch series addressing pack-objects issues with geometric repacking and MIDX bitmap generation. The patch adds a test case demonstrating the failure scenario that the series aims to fix.

The test shows how geometric repacking can fail to maintain object closure when dealing with once-cruft objects (objects that were unreachable but later made reachable again) that sit above the geometric split point. The test creates a commit, makes it unreachable (via reset and reflog expiration), packs it as cruft, then makes it reachable again through a new reference. The final repack --geometric command with --write-bitmap-index is expected to fail because the MIDX can't properly account for objects that transitioned from cruft to reachable.

The test is marked with test_expect_failure since the fix comes in the next patch. This follows Git's standard practice of first proving a bug exists before fixing it. The test setup is thorough, exercising the exact scenario where the geometric repacking logic breaks down when dealing with object reachability across pack boundaries.

This patch is part of a well-structured series from Taylor Blau (a GitHub engineer and PLC member) addressing real-world issues encountered with Git's pack machinery. The test will serve as both documentation of the bug and validation that the subsequent fix works as intended. Reviewers can expect the next patch to explain the failure mode in detail and implement the solution using the new "excluded-open" pack state mechanism introduced earlier in the series.
