Junio Hamano started this thread with a cleanup to the rerere subsystem, removing obsolete NULL checks for strbuf.buf that had persisted for 19 years despite the strbuf behavior changing in 2007 to guarantee .buf is never NULL. Patrick Steinhardt reviewed and confirmed the change was correct, noting strbuf.buf now always points to valid memory (either allocated content or a static NUL byte).

Building on this, Junio has now proposed a broader effort to modernize strbuf handling across the codebase. He's created Coccinelle rules to systematically eliminate unnecessary NULL checks of strbuf.buf, with careful exceptions for two legitimate cases where the checks serve specific purposes. The first exception guards against uninitialized structs in parse_list_objects_filter(), while the second handles a temporary invariant violation in strbuf_getwholeline(). Junio suggests even this second case could be cleaned up in future work.

This represents a natural progression from the initial rerere.c cleanup to a project-wide code hygiene effort. As the maintainer and original author of many core data structures, Junio's deep understanding of strbuf invariants lends authority to these changes. The RFC tag indicates he's seeking confirmation there are no other valid exceptions before applying these rules more widely. The changes are purely internal with no user-visible impact.
