This is the 10th patch in Patrick Steinhardt's 14-part series refactoring Git's object name handling to be backend-agnostic, part of the ongoing ODB abstraction effort. The patch simplifies how Git calculates minimum unique abbreviations for loose object names (like short hashes).

Previously, the code reused the object disambiguation infrastructure (with its `disambiguate_state` struct) just to iterate through loose objects matching a prefix, even though it didn't need the full disambiguation logic. Now that the ODB interface provides direct prefix-based iteration via `odb_for_each_object()`, the patch removes this indirection. It introduces a dedicated `find_abbrev_len_loose()` function that works directly with the `min_abbrev_data` struct, making the code more focused and dropping unused disambiguation infrastructure (like the `always_call_fn` flag).

The change continues the series' pattern of methodically replacing backend-specific code with generic ODB interfaces while maintaining identical behavior. This patch in particular shows the benefits of the earlier infrastructure work - now that the ODB layer handles prefix iteration, higher-level code can be simpler and more direct. As with previous patches in the series, this appears to be a clean, focused improvement that moves toward the goal of pluggable storage backends.
