This is a refactoring and feature patch from Mirko Faina that renames the `--cover-letter-format` option to `--commit-list-format` in `git format-patch`. The change makes the option name clearer about its purpose (formatting the commit list rather than the cover letter itself) and aligns it with the existing configuration variable name `format.commitListFormat`.

The patch also changes the behavior so that specifying `--commit-list-format` now implies `--cover-letter` unless `--no-cover-letter` is explicitly given. This makes the interface more intuitive since requesting a specific commit list format would naturally suggest the user wants a cover letter. The change maintains backward compatibility while improving the user experience.

Documentation is updated throughout, and the test suite is modified to use the new option name while expanding test coverage. The tests verify both the new implied cover letter behavior and the continued functionality with explicit `--no-cover-letter`. The changes are straightforward and focused, with no apparent technical concerns.

This patch is part of a larger series improving commit list formatting in format-patch, building on Mirko's prior work. The series has already incorporated feedback from Kristoffer Haugsbakk and appears ready for merging. The refactoring improves code clarity while maintaining all existing functionality, following Git's established patterns for format string handling.
