This is a follow-up in a bug report thread about `git grep` behavior, where Jeff King (Peff) clarifies the root cause of Randy Dunlap's issue. 

Jeff explains that Randy's use of `git apply` without `--index` left the patched file untracked, which is why `git grep` didn't find the string (as it only searches tracked files by default). He contrasts this with his own successful reproduction using `git am`, which automatically stages changes. The email offers two solutions: either manually `git add` the file after applying, or use `git am` from the start to handle staging automatically. 

This wraps up the mystery cleanly, showing the behavioral difference between `git apply` and `git am` when it comes to staging changes. The thread demonstrates Git's sometimes subtle distinctions between commands that appear similar but have important differences in workflow implications. Jeff's response is characteristically clear and practical, offering concrete next steps while explaining the underlying mechanics.
