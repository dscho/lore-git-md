This is the fourth patch in Taylor Blau's series addressing pack-objects issues with geometric repacking and MIDX bitmap generation. The patch implements the core fix by introducing a new "excluded-open" pack state (marked with '!') that allows pack-objects to include objects reachable from these packs while still excluding their direct contents.

The key technical change is that commits in '!'-prefixed packs are now used as starting points for the follow traversal, unlike '^'-prefixed packs which act as closure boundaries. The implementation adds a new `pack_keep_in_core_open` flag to `struct packed_git` and corresponding `KEPT_PACK_IN_CORE_OPEN` constant to distinguish these cases. The patch carefully moves the `want_object_in_pack()` check in `add_object_entry_from_pack()` to ensure commits from excluded-open packs are still traversed even when their objects won't included in the output.

The documentation is updated to explain the new '!' prefix behavior, and new tests verify both the happy path and edge cases like using '!' without --stdin-packs=follow. The test from patch 3 that demonstrated the failure now passes with this change, though that verification will come in patch 5 which wires up the new functionality in the repack layer.

This appears to be a well-constructed solution to the geometric repacking issue, with thorough test coverage and clear documentation. The changes are focused on the pack-objects plumbing while maintaining backward compatibility - the new behavior is opt-in via the '!' notation rather than changing defaults. Reviewers will want to pay particular attention to the reachability handling changes in `add_object_entry_from_pack()` and the new include_check callbacks.
