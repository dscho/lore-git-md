Thread summary:

This thread discusses a proposed `--cc` option for `get_maintainer.pl` (a Linux kernel development tool) to format output as comma-separated emails for direct use with `git send-email --cc`. The original patch modified the Perl script's output formatting to support this use case, enabling both piping output and potential direct execution from `git send-email`.

Jim Cromie has responded to Joe Perches' objections by outlining four specific advantages of direct integration over shell wrappers: (1) performance benefits by avoiding per-patch script execution, (2) improved dry-run accuracy within `send-email`, (3) reduced error risk from duplicate patch list handling, and (4) cleaner configuration via `.git/config`. The configuration argument is presented as particularly compelling for preventing maintainers from missing parts of patch series.

The discussion remains active with two clear positions: Jim's case for workflow improvements in performance, reliability and configuration versus Joe's skepticism about the necessity of these changes. The cross-project nature (Linux kernel tooling + Git) adds coordination complexity beyond the technical merits. Key unresolved points include whether the demonstrated advantages are sufficient to justify the change and if there are unaddressed use cases that could strengthen the proposal. The technical implementation appears sound, but adoption may require broader consensus on the Git side about the value of tighter integration with kernel development tooling.
