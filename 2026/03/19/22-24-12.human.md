This is a patch series addressing a pack-objects/repack issue related to geometric repacking and MIDX bitmap generation. Taylor Blau (a core contributor and PLC member focused on pack storage) identifies a case where geometric repacking can produce a MIDX that's missing reachable objects, causing bitmap generation to fail.

The root issue occurs when:
1. A pack with incomplete reachability (like a cruft pack) is deemed large enough to avoid repacking
2. Objects from this pack are reachable via excluded packs
3. The resulting MIDX omits these objects while keeping objects that reference them, breaking bitmap generation

The series introduces a new "excluded-open" pack state (marked with '!' instead of '^') that tells pack-objects to include objects reachable from these packs while still excluding their direct contents. This ensures reachability closure while keeping the intended exclusions.

The patches include:
1. A leak fix
2. Refactoring of stdin pack reading
3. Test demonstrating the failure case
4. Implementation of excluded-open packs
5. Integration with geometric repack

This appears to be a well-motivated fix for a real-world issue encountered in GitHub's infrastructure. The changes are focused and come with thorough explanation and testing. Given Taylor's expertise in this area and the clear problem being solved, this seems likely to be uncontroversial and valuable for large repository performance.
