This is a feature proposal for `git am` to support applying patches directly from message IDs without manual downloading.

Shreyansh Paliwal suggests adding a `--fetch-mid` option to `git am` that would fetch patches from public-inbox URLs (like lore.kernel.org) using message IDs. The proposal includes making the base URL configurable via `am.publicInboxUrl` and mentions potential future expansion to automatically fetch entire patch series from a cover letter's message ID.

The feature would streamline workflow by eliminating the manual step of downloading patches before applying them. The implementation appears straightforward since public-inbox already serves patches in mbox format that `git am` can process directly. However, the RFC nature suggests this is an early proposal seeking feedback before implementation.

Key technical details include:
- New `--fetch-mid` option accepting one or more message IDs
- Default fetch URL `https://lore.kernel.org/git/<message-id>/raw`
- Configurable base URL via `am.publicInboxUrl`
- No changes needed to patch application logic (works with existing mbox handling)

The proposal seems well-motivated for Git's mailing-list-centric workflow, though it would need to handle error cases (invalid message IDs, network failures) gracefully. The configurable URL makes it flexible for both public and private inbox setups. This could be a quality-of-life improvement for frequent patch reviewers and maintainers.
