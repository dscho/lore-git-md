Feature enhancement for `git cat-file --batch-command` with mailmap toggling.

Siddharth Asthana responds to Junio C Hamano's feedback on their patch to add dynamic mailmap control to `git cat-file --batch-command`. The original proposal introduced separate `use-mailmap` and `no-use-mailmap` subcommands, but Junio suggested consolidating these into a single `mailmap` command with `yes`/`no` parameters for better API design.

The author confirms they will implement this simplification in v2, noting it will reduce code duplication in the command dispatch table. They also clarify that the mailmap data remains cached in memory when disabled - the toggle only controls application of the underlying data, not its presence. This addresses Junio's question about cache behavior while maintaining the performance benefit of keeping loaded mailmaps available.

This appears to be straightforward maintainer-requested refinement of an otherwise well-received feature. The change should make the interface more intuitive while preserving the core functionality needed by GitLab's Gitaly service. The v2 patch will be worth watching for to confirm the implementation matches the discussed design.
