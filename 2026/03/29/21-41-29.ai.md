This is a feature patch introducing incremental MIDX repacking mode, part of Taylor Blau's ongoing work to improve Git's repacking strategy for large repositories. The patch exposes the incremental MIDX repacking mode (implemented in previous patches) via a new `--write-midx=incremental` option for `git repack`.

The key additions are:
- New configuration options `repack.midxSplitFactor` (default: 2) and `repack.midxNewLayerThreshold` (default: 8) to control compaction behavior
- Integration with geometric repacking that only packs in sufficiently large tip layers are considered for repacking
- Extensive test coverage in t/t7705-repack-incremental-midx.sh exercising various scenarios including threshold behavior, multi-layer compaction, and edge cases

The patch builds on the previous MIDX chain infrastructure to provide a more scalable repacking strategy where older layers contain fewer, larger packs while newer layers contain many smaller packs. This represents the final major component of Taylor's multi-year effort to improve Git's scalability for large repositories.

The implementation appears thorough, with careful attention to edge cases and comprehensive test coverage.
