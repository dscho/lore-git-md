This is a refactoring patch in Taylor Blau's incremental MIDX/bitmap-based repacking series. It converts the `keep_hashes` array in `write_midx_internal()` to use Git's `strvec` type instead of a manually managed array of strings. The change simplifies memory management and provides a more ergonomic interface for manipulating the checksums of MIDX files that should be retained when pruning stale entries from the MIDX chain.

The patch modifies both `midx-write.c` and `midx.c`, replacing direct array manipulation with `strvec` operations. Key changes include:
- Using `STRVEC_INIT` and `strvec_init_alloc()` for initialization
- Replacing array indexing with `strvec` access
- Simplifying cleanup with `strvec_clear()`
- Updating related functions `clear_midx_files()` and `clear_incremental_midx_files_ext()` to accept a `strvec` instead of an array

The ordering of hashes remains important as they determine the contents of the `multi-pack-index-chain` file when writing with "--incremental". The change appears well-contained within the MIDX infrastructure and maintains the existing functionality while improving code maintainability. This is part of the larger effort to improve Git's repacking strategy for large repositories.
