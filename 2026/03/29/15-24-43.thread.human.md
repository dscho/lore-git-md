This thread discusses adding progress reporting to the `git backfill` command, which downloads missing objects from a repository. Trieu Huynh's initial patch (v1) introduced a `--[no-]progress` option following Git's standard conventions, showing batch download progress by default on TTYs. 

Derrick Stolee, an expert in large-repository performance, has raised several thoughtful points in response. He notes that the current implementation isn't truly silent - it shows verbose remote output for each batch fetch. Stolee suggests the progress meter might be more useful tracking objects rather than batches, and recommends demonstrating the full output with/without the change to better evaluate the improvement. He also flags some technical considerations around test prerequisites and recent rev-list changes that need checking.

The discussion is now focusing on whether progress reporting should supplement or replace the existing verbose output, and what metrics would provide the most actionable feedback during potentially lengthy backfill operations. Stolee's input indicates this may evolve into a more substantial change than the initial straightforward progress meter addition.
