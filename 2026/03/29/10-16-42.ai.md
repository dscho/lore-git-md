This is part 4/5 of a refactoring series in the ongoing `the_repository` removal effort. Shreyansh Paliwal continues converting the reftable backend to explicitly pass repository context rather than relying on global state.

The patch removes three remaining uses of `the_repository` in `refs/reftable-backend.c`, replacing them with either the direct `repo` parameter or `ref_store->repo` where available. The changes are mechanical but important for eliminating global state:
1. `calc_shared_perm()` now uses the passed `repo` parameter
2. `repo_config()` uses the same `repo` parameter
3. `safe_create_dir()` uses `ref_store->repo`

The commit message notes that `USE_THE_REPOSITORY_VARIABLE` can't be fully removed yet because `is_bare_repository()` still uses it - this will be addressed in future work. The changes maintain identical behavior while making repository dependencies explicit.

This follows the established pattern seen in previous patches of the series, with clean, focused changes that have already incorporated review feedback from earlier versions. The patch touches only the reftable backend implementation while small in scope, it's another step toward the larger goal of removing global state from the refs subsystem.
