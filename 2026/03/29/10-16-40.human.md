This is part 2 of a 5-part series continuing the `the_repository` removal effort, specifically targeting the refs subsystem. Shreyansh Paliwal's patch converts the file ref lock timeout mechanism to use explicit repository parameters rather than relying on the global `the_repository`.

The change modifies `get_files_ref_lock_timeout_ms()` to take a `struct repository*` parameter, then updates all callers to pass the appropriate repository context. The most interesting part is the callback handling - since `create_reflock()` is used as a callback that couldn't previously access repository state, the patch introduces a small wrapper struct to pass both the lock file and repository through the callback data.

This is a mechanical but necessary change that follows the established pattern for `the_repository` removal. The patch looks straightforward and well-contained, touching only the expected files (refs.c, files-backend.c, and refs-internal.h). It maintains the existing behavior while making the repository dependency explicit.

The changes align with prior feedback from reviewers and continue the incremental approach to this long-running refactoring effort. This appears ready for merging as part of the larger series.
