Feature addition to `git cat-file`'s batch mode, now with simplified mailmap toggling interface.

Siddharth Asthana follows up on his earlier proposal to add dynamic mailmap control to `git cat-file --batch-command`, incorporating Junio C Hamano's feedback to simplify the interface. The new version replaces the original `use-mailmap`/`no-use-mailmap` subcommands with a single `mailmap` command that takes `yes` or `no` arguments. This reduces code duplication in the command dispatch table while maintaining the same functionality - mailmap data is still cached when disabled to avoid reload costs when re-enabled.

The patch remains focused on GitLab's Gitaly service use case, where long-running `git cat-file` processes need to toggle mailmap processing without restarting. The implementation appears clean, with thorough tests verifying the behavior both with and without `--buffer` mode. Documentation updates clearly explain the new subcommand syntax.

This version shows good responsiveness to maintainer feedback while keeping the core functionality intact. The simplification makes the interface more maintainable without compromising on the original goal of supporting dynamic mailmap toggling. The changes are well-contained to `builtin/cat-file.c` and its tests, with no new technical concerns introduced.
