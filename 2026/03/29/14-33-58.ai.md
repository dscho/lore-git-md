This is a discussion thread about the proposed per-remote SSH configuration feature, with Ben Knoble weighing in on the architectural debate. The email continues the ongoing philosophical divide about where SSH configuration should live - in Git's config or in SSH's native config files.

Ben Knoble's position aligns with the maintainers' minimalism stance, arguing that SSH client configuration naturally belongs in SSH's own config files since the connection is fundamentally an SSH operation, not a Git one. He shares his personal workflow of using SSH host configs for identity management across both Git and non-Git hosts, suggesting this demonstrates the existing system's flexibility.

The key technical point Ben raises is about separation of concerns - that Git should handle Git-specific configuration while letting SSH handle connection-level details. He specifically counters Wesley's "one knob in Git" argument by suggesting it's actually cleaner to have "each knob where it belongs" in their respective systems.

This response doesn't introduce new technical arguments but reinforces the architectural perspective that's been consistently voiced by Johannes Sixt, Jeff King, and brian m. carlson. The discussion remains at an impasse between those wanting Git-native configuration for version control benefits versus those advocating for leveraging SSH's existing capabilities. Ben's contribution strengthens the latter position by providing another concrete example of successful SSH config usage in a real workflow.
