This is a refactoring patch introducing a new `strvec_init_alloc()` function, part of Taylor Blau's incremental MIDX/bitmap repacking series. The change adds a way to pre-allocate space in a strvec (Git's string array type) when the caller knows how many elements will be needed upfront, avoiding reallocations.

The new function allows initializing a strvec with enough capacity for `alloc` elements plus the terminating NULL, while maintaining the existing zero-initialization behavior when `alloc` is 0. The implementation uses Git's `st_add()` helper for safe allocation math and reimplements `strvec_init()` as a special case of the new function.

This appears to be a preparatory change for the larger repacking work, where knowing the exact number of packs/MIDX files ahead of time could allow more efficient memory management. The patch is straightforward and well-contained, touching only strvec implementation details while maintaining the existing API contract. Junio Hamano provided input on the change (as noted in the Helped-by trailer), suggesting it has already received some maintainer review.
