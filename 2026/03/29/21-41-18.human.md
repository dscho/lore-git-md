This is part 11 of Taylor Blau's 16-patch series introducing incremental MIDX/bitmap-based repacking. The series aims to improve Git's scalability for large repositories by avoiding periodic full repacks in favor of incrementally maintained MIDX chains.

The current patch teaches `pack_geometry_init()` to handle MIDX-aware repacking by:
1. Optionally restricting repacking candidates to only packs in the tip MIDX layer when a threshold is set
2. Tracking whether any tip-layer packs were rewritten (`midx_tip_rewritten`), which will inform MIDX chain updates in later patches

The change introduces new fields in `struct pack_geometry` to track the MIDX layer threshold and rewrite status, while maintaining the existing geometric repacking logic. This is a preparatory step that enables the incremental MIDX strategy to work properly with geometric repacking of packs in the tip layer.

The patch follows the series' pattern of careful, well-documented changes that build toward the larger goal. It touches key repacking infrastructure files (`repack-geometry.c`, `repack.h`) and integrates with the existing MIDX handling code. As with previous patches in the series, this appears to be a solid incremental step toward the overall goal.
