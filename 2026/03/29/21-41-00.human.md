This is a refactoring patch in Taylor Blau's incremental MIDX/bitmap-based repacking series. The patch converts the `keep_hashes` array in MIDX writing code to use Git's `strvec` type instead of manual array management. This change simplifies the code by eliminating explicit memory management and length tracking while maintaining the same functionality.

The `keep_hashes` array tracks checksums of MIDX files that should be preserved when pruning stale entries from MIDX chains. The switch to `strvec` provides a more ergonomic interface and better integrates with Git's string handling utilities. The ordering remains important as it determines the contents of the `multi-pack-index-chain` file when writing incrementally.

The patch touches both the MIDX writing logic and cleanup routines, updating function signatures and call sites to use the new `strvec` interface. While this is primarily a code hygiene change, it's part of the larger effort to improve Git's scalability for large repositories by optimizing the repacking strategy. The change appears straightforward and well-contained within the existing MIDX infrastructure.
