This is a bugfix patch for the `git backfill` command, addressing an edge case where the command would silently succeed when run in an empty repository. The issue occurs because `handle_revision_arg()` fails to parse the unborn HEAD in an empty repo, but the error was being ignored.

The patch makes two key changes:
1. It properly checking the return value of `handle_revision_arg()` and propagating the error with a clear "unable to parse HEAD revision" message
2. It adds a test case that verifies the command fails as expected in an empty repository

The fix follows the same pattern used in `builtin/pack-objects.c` for handling revision parsing failures. The test coverage is straightforward and verifies both the error condition and the error message. This appears to be a well-contained, focused fix for a clear edge case.
