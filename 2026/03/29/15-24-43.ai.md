Feature addition to the `git backfill` command, adding progress reporting functionality.

This patch introduces a `--[no-]progress` option to `git backfill`, bringing it in line with other Git commands like `fetch` and `gc` that show progress indicators during potentially long-running operations. The implementation follows Git's standard progress reporting conventions:

1. Progress is shown by default when stderr is a terminal (checked via `isatty(2)`), matching `git fetch`'s behavior
2. Users can explicitly enable/disable with `--progress` or `--no-progress`
3. The progress meter tracks batches of objects being downloaded, showing "Downloading batches" as the status message

The patch includes thorough test coverage verifying:
- Progress appears with `--progress` on a TTY
- Progress is suppressed with `--no-progress` even on a TTY
- The default behavior matches other Git commands (silent on non-TTY)

The changes are cleanly implemented, adding the necessary progress tracking fields to the `backfill_context` struct and properly initializing/cleaning up the progress meter. The tests follow existing patterns in the test suite and cover all the new behavior.

This appears to be a well-scoped, self-contained improvement to the backfill command's user experience, particularly valuable for large repositories where the operation might take noticeable time. The patch follows Git's conventions and includes appropriate documentation via the option help text.
