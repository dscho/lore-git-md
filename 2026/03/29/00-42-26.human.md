Maintainer feedback on TypeScript userdiff pattern series.

Junio C Hamano responds to Dhruv Arora's patch series adding TypeScript support to Git's built-in diff patterns. The series currently consists of two patches - one adding the initial pattern and a second fixing its position in the test files. Junio suggests this two-step approach isn't ideal for the mailing list workflow.

The maintainer advises that patch series should present a clean progression where each commit builds logically on the last, rather than showing intermediate mistakes that get fixed later. He recommends using `git rebase -i` to combine the two patches into a single, polished commit that adds the TypeScript pattern correctly from the start, with tests included.

This is standard guidance for new contributors about Git's patch submission culture - the expectation is to present a clean history even if it means rewriting local development history before submission. The feedback is constructive and points to established project norms rather than finding fault with the technical content of the patches themselves.
