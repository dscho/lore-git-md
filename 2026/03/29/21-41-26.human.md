This is patch 14/16 in Taylor Blau's series implementing incremental MIDX/bitmap-based repacking, a major performance feature for large repositories. The patch introduces the core logic for building and maintaining an incremental MIDX chain during geometric repacking.

The key innovation here is avoiding periodic full repacks by instead maintaining a chain of MIDX layers that grow and shrink incrementally. The strategy:
1. Always writes a new MIDX layer containing fresh packs
2. Compacts adjacent layers when their combined object count exceeds half the next layer's size (controlled by `repack.midxSplitFactor`)
3. Uses `--checksum-only` for atomic updates to the MIDX chain
4. Handles edge cases like rewritten tip layers and preferred pack selection

The implementation is thorough, with careful attention to lockfiles, memory management, and error cases. It includes extensive trace2 instrumentation for debugging. While currently hidden behind an enum flag, this will be exposed via `git repack --write-midx=incremental` in a later patch.

This represents the culmination of Taylor's multi-year effort to improve Git's scalability for large repositories, building on his previous work on geometric repacking and MIDX compaction. The patch is well-structured and appears ready for review.
