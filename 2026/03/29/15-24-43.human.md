Feature addition to `git backfill` command, with progress reporting option.

This patch adds a `--[no-]progress` option to `git backfill`, bringing it in line with similar commands like `git fetch` and `git gc`. The change makes the command more user-friendly by providing feedback during potentially long operations where objects are being downloaded in batches.

The implementation follows Git's standard progress reporting pattern:
- Progress is shown by default when stderr is a terminal
- Can be explicitly enabled/disabled with `--progress`/`--no-progress`
- Includes proper progress meter cleanup
- Adds comprehensive tests verifying the TTY/non-TTY behavior

The patch appears well-structured with:
- Clear commit message explaining the motivation
- Straightforward implementation adding progress tracking fields to the context struct
- Tests covering all three cases (explicit progress, explicit no-progress, and default non-TTY behavior)
- Follows existing Git conventions for progress reporting

This seems like a solid quality-of-life improvement for users of partial clones who rely on `git backfill`. The change is small and focused, with good test coverage showing attention to detail.
