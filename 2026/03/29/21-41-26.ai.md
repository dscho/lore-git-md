This is patch 14/16 in Taylor Blau's series implementing incremental MIDX/bitmap-based repacking, a performance feature targeting large repositories. The patch introduces the core implementation of `write_midx_incremental()`, which builds and maintains a chain of MIDX (multi-pack-index) layers during geometric repacking.

The key innovation here is avoiding periodic full repacks by maintaining an incrementally updated MIDX chain where older layers contain fewer, larger packs while newer layers contain many smaller packs. The implementation:

1. Acquires a lock on the MIDX chain file
2. Writes a new MIDX layer containing fresh packs and any surviving packs from the previous tip layer
3. Compacts adjacent MIDX layers when the accumulated object count exceeds half the next layer's count (controlled by `repack.midxSplitFactor`)
4. Atomically updates the MIDX chain file
5. Cleans up unused MIDX layers

The patch includes extensive trace2 instrumentation to help diagnose the compaction decisions. It builds on previous preparatory work in the series (like the enum-based `repack_write_midx_mode` and refactored MIDX writing logic) while introducing new structures like `midx_compaction_step` to represent each compaction operation.

This is a significant architectural change to Git's repacking strategy, completing Taylor's multi-year effort to improve scalability for large repositories. The implementation appears thorough, with careful attention to edge cases and resource management. The series remains rebased on current master and looks ready for final review.
