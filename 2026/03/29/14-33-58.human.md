This is a discussion thread about the proposed per-remote SSH configuration feature, with Ben Knoble weighing in on the architectural debate. The conversation continues the divide between those who believe SSH configuration belongs in Git (Wesley Schwengle) and those who argue it should stay in SSH's domain (Johannes Sixt, Jeff King, and now Ben Knoble).

Ben makes two key points in his response: First, he questions why SSH-specific configuration wouldn't naturally belong in the SSH client itself, noting he already uses SSH host configs for both Git and non-Git connections. Second, he suggests the "each tool does what it does best" philosophy favors keeping this configuration in SSH rather than duplicating functionality in Git.

The exchange highlights the core tension - Wesley wants a Git-native solution for version control and centralization benefits, while others see this as unnecessary complexity when SSH already handles the use case. Ben's perspective as someone successfully using SSH configs in practice adds weight to the "existing solutions work" argument.

This doesn't advance the technical discussion so much as reinforce the philosophical divide. The patch series remains in limbo until Wesley can demonstrate concrete problems with the SSH-based approach that justify expanding Git's configuration surface.
