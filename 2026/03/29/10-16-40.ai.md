This is part 2/5 of Shreyansh Paliwal's series to remove `the_repository` usage from the refs subsystem, specifically focusing on file ref lock timeouts. The patch converts `get_files_ref_lock_timeout_ms()` to take an explicit `struct repository*` parameter instead of relying on the global `the_repository`.

The changes are mechanical but require careful plumbing through the call stack. The main technical challenge is handling the callback case in `create_reflock()`, which is solved by introducing a small wrapper struct to pass both the lock file and repository context. The patch updates three files:
- `refs.c` changes the function signature and implementation
- `refs/files-backend.c` updates callers and adds the callback wrapper
- `refs/refs-internal.h` updates the function declaration

The changes maintain the existing behavior while making the repository dependency explicit. This continues the incremental approach established in previous versions of the series, following patterns approved by Patrick Steinhardt. The patch builds cleanly and appears ready for merging as part of the broader `the_repository` removal effort.
