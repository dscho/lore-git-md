Bugfix for the `git backfill` command, addressing a silent failure case when run on an empty repository.

The patch fixes an issue where `git backfill` would silently continue with an empty revision walk when HEAD cannot be parsed (such as in a new, empty repository), rather than properly reporting the error. The fix makes the command check the return value of `handle_revision_arg()` and propagate the error, matching how other commands like `pack-objects` handle this case.

The change is small and focused - just a 3-line modification to the core logic plus a new test case. The test verifies that backfill now fails with a clear error message when run on an empty repo. The patch appears well-constructed with a clear commit message explaining both the problem and solution.

This is a straightforward correctness fix that improves error handling in a relatively new command (`backfill` was introduced in Git 2.42). The change is unlikely to be controversial and seems ready for inclusion.
