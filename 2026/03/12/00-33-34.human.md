This is a test infrastructure patch addressing a minor inconsistency in Git's shell script linter. Junio C Hamano follows up on Ramsay Jones' observation that while the linter was recently updated to allow `sed -E` (extended regex) as a portable option, its error message still only mentions `-n`, `-e`, and `-f` as permitted flags. The change is trivial - just updating the error string to include `-E` - but maintains consistency between the linter's behavior and its user feedback.

The patch demonstrates Git's attention to detail in test infrastructure, where even small documentation mismatches in error messages are worth fixing. This follows an earlier change that aligned the linter with POSIX Issue 8 standards by permitting `-E`, which has been in practical use since 2022. The thread shows the project's careful approach to standards compliance and developer experience, with changes being minimal and uncontroversial.
