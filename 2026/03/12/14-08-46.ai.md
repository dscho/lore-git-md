This is a follow-up discussion in the ongoing `git fast-import` signature handling series, specifically addressing warning messages and documentation clarity in the commit signing functionality.

The exchange between Justin Tobler and Patrick Steinhardt focuses on two main points from the v4 patch series that adds `sign-if-invalid` mode to `git fast-import`. First, while reviewing the warning messages for invalid signatures being re-signed, Patrick questions whether these warnings are necessary since users explicitly request the re-signing behavior. Justin agrees the warnings may be noisy and suggests consistently removing them for both `sign-if-invalid` and `strip-if-invalid` modes if the team agrees.

Second, Patrick catches an imprecise NEEDSWORK comment about "signing signatures" in interoperability mode, which Justin acknowledges should say "signing commits" instead. This relates to the current limitation where the implementation doesn't properly handle signing in repositories with compatibility object formats.

The discussion shows the series is nearing completion with only minor wording and warning behavior adjustments remaining. The core architecture using a unified `sign_buffer()` with flags (as suggested in earlier feedback) appears settled, and the focus has shifted to polishing the user experience around warning messages. Justin indicates he'll address both points in the next version of the patch series.
