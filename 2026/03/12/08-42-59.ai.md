This is part 4 of Patrick Steinhardt's ODB abstraction series, introducing a generalized object counting interface for loose objects. The patch builds on the previous extraction of counting logic by adding a flag to toggle between approximate and exact counting modes.

The new `odb_source_loose_count_objects()` function replaces `odb_source_loose_approximate_object_count()` from patch 3/6, adding an `ODB_COUNT_OBJECTS_APPROXIMATE` flag to control whether to use the existing sampling-based approximation (scan one shard and multiply by 256) or perform an exact count by iterating all objects. The change updates `builtin/gc.c` to use the new API while maintaining the same approximate counting it relied on before.

The implementation splits into two paths: the approximate count reuses the existing shard-scanning logic, while the exact count leverages the `odb_source_loose_for_each_object()` callback infrastructure to increment a counter for each object. This preserves the existing behavior where needed while providing more accurate counts when requested.

This is a well-structured change that cleanly extends the abstraction introduced earlier in the series. The commit message clearly explains the motivation and the implementation approach matches the project's style. The patch touches object-file.c, object-file.h, and odb.h to expose the new flag and function, with corresponding updates to builtin/gc.c. No behavioral changes are introduced for existing callers since they continue using the approximate mode.
