This is a bug report for the `remote-object-info` feature in `git cat-file --batch-command`. Pablo Sabater discovered that when mixing local `info` and remote `remote-object-info` commands in the same batch session, stale type information from a local query can incorrectly affect subsequent remote queries.

The key issue is that `data->type` isn't being cleared between commands, causing a blob to be misreported as a commit if a commit was queried locally first. The size remains correct (as it comes from the server), but the type persists from the previous local query. This silent corruption is particularly concerning as users wouldn't receive any error indication.

The report includes a clear reproduction case using a file:// protocol setup with `transfer.advertiseobjectinfo` enabled. This follows up in the context of Jeff King's earlier discussion about format string handling, but represents a distinct implementation bug rather than a design question. The issue appears in Eric's v11 implementation and warrants attention before the feature is finalized.
