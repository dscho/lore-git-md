This is a maintainer review comment on the final patch of a v5 series enhancing `git fast-import`'s signature handling capabilities. Junio C Hamano suggests rewording warning messages in the `sign-if-invalid` mode to more clearly indicate that the operation is replacing existing invalid signatures rather than adding new invalid ones.

The proposed changes would clarify three warning message variants that currently say "signing commit with invalid signature" by making them to explicitly mention replacement of invalid signatures (e.g., "re-signing commit that has an invalid signature"). This is a minor wording improvement to prevent potential confusion about whether the operation is creating invalid signatures versus replacing existing invalid ones with valid signatures.

The comment comes after the series has already been approved for merging, indicating this is a final polish suggestion rather than a blocking issue. The warning messages in question are part of the shared infrastructure between the sign/strip modes that was extensively discussed and refined throughout the series' iterations. Junio's suggestion aligns with the series' overall goal of clear separation between signature verification, stripping/signing operations, and user feedback.
