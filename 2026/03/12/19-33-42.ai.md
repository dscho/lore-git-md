This is a v2 feature patch adding conditional `--autostash` support to `git checkout` and `git switch`, responding to maintainer feedback from the initial submission. The patch now only creates a stash when local changes would conflict with the branch switch, rather than stashing unconditionally.

The key changes in this version:
- Adds conflict detection via a new `checkout_would_clobber_changes()` helper that performs a dry-run merge
- Only creates an autostash when changes would be lost or conflict with the target branch
- Updates documentation to clarify the conditional stashing behavior
- Rewrites tests to verify the new conditional logic
- Maintains backward compatibility with `--force` to always stash

The implementation builds on existing autostash infrastructure from the sequencer, adding conflict detection before stashing. The test coverage is comprehensive, verifying behavior with dirty worktrees, staged changes, clean merges, and various flag combinations. Documentation updates explain when stashing occurs and how conflicts are handled.

This version addresses Junio C Hamano's feedback by making the stashing behavior more precise while maintaining the core functionality. The patch touches multiple components including checkout logic, documentation, and test infrastructure, with particularly thorough test coverage in the new `t/t2061-switch-autostash.sh`.
