This is a response from the Git maintainer (Junio C Hamano) to a bug report about missing command completions in Git's bash completion script. Junio clarifies that the behavior is intentional - plumbing commands like `symbolic-ref` and `bugreport` are deliberately excluded from bash tab completion to avoid cluttering the interface for end users. 

He suggests that if zsh completion includes these plumbing commands, that may actually be a bug in zsh's implementation rather than bash's, as it goes against Git's design principle of keeping plumbing commands out of interactive completion. The response indicates this isn't a regression but rather a conscious choice in the bash completion implementation.

The exchange highlights an interesting philosophical difference in how completion scripts handle Git's plumbing vs porcelain commands, with the maintainer taking a firm position that plumbing commands shouldn't appear in interactive completion by default. This suggests any fix would need to respect that design decision rather than simply matching zsh's behavior.
