This is a follow-up in the thread about zombie process cleanup in containerized Git environments. Andrew Au acknowledges brian m. carlson's suggestion to use the `tini` init process as a general solution, but argues that Git's own process cleanup remains worth fixing independently. The key point is that abnormal exits should not leave zombies regardless of whether an init helper is present.

The discussion continues to balance two perspectives: fixing specific Git behaviors versus relying on container orchestration tools. Andrew's position is that these are complementary approaches - Git should handle its own process cleanup properly, and containers should also use proper init systems. This maintains the thread's technical focus while recognizing the broader architectural context.

The patch itself (not shown in this email) would add atexit handlers to ensure child processes are reaped even on abnormal exits from network operations. The conversation has evolved from an initial assumption about Git as PID 1 to a more nuanced understanding of real-world container deployments where Git runs under a service process.
