This thread examines differences in Git command completion behavior between bash and zsh shells, particularly regarding which commands are shown. The discussion began when Andrey noticed that zsh displays plumbing commands (like `symbolic-ref` and `bugreport`) in completions while bash does not, despite both shells potentially using the same completion script.

Junio Hamano clarified that the bash behavior (excluding plumbing commands) is intentional design, as plumbing commands are meant for scripting rather than interactive use. The thread then explored why zsh might behave differently, considering whether it processes the shared completion script differently or loads an alternate version.

A new development came when Andrey pointed out that the bash completion script actually documents a `GIT_COMPLETION_SHOW_ALL_COMMANDS` environment variable that can override the default behavior to show plumbing commands. This suggests the zsh inconsistency might stem from configuration rather than a bug, though it remains unclear why zsh would default differently when using what appears to be the same script.

The core questions now are: whether zsh behavior reflects an intentional configuration choice or an implementation quirk, and whether any commands (like `bugreport`) might warrant reclassification given their occasional interactive use. Junio maintains the position that plumbing commands should not appear by default, while the existence of the toggle variable adds nuance to how strictly this principle should be enforced.
