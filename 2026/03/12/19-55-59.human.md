This is a bugfix patch addressing zombie process cleanup in Git's network operations when running in containers. The v3 iteration from Andrew Au simplifies the approach based on Jeff King's feedback, using Git's existing `clean_on_exit` mechanism rather than custom atexit handlers.

The patch ensures child processes like `git-remote-https` and SSH connections are properly reaped when Git exits abnormally (e.g., due to transport errors). It modifies `connect.c` and `transport-helper.c` to set `clean_on_exit` and `wait_after_clean` flags on relevant child processes, causing them to be terminated and waited on during any exit path.

The key improvements from v2 are avoiding potential deadlocks (by using SIGTERM-then-wait rather than direct waiting) and better handling of signal-based exits. While the original motivation involved Git-as-PID-1 scenarios, the discussion has shifted to treating this as general correctness - Git should clean up its own processes regardless of the init system.

The patch is narrowly focused on network operations, leaving broader process management questions (like default run-command behavior) for future discussion. The changes are minimal (6 lines total) and well-contained to the specific child process spawning points.
