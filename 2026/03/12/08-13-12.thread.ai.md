Submodule worktree integration inquiry from Xavier Morel. Core issue: submodules do not work well with parent repositories using worktree-based workflows, particularly when the parent is a bare repository with worktrees. Current workarounds like `--reference --dissociate` have limitations in this scenario. Two open questions: (1) Is there any existing way to make submodules share objects from a central location when used with worktrees, beyond basic reference/dissociate options? (2) Could submodules gain first-class worktree support in the future to better accommodate this workflow? The email highlights a gap in submodule functionality for advanced repository management patterns, particularly affecting developers working with large projects where object duplication is costly. Potential discussion directions: examination of submodule internals (`.git/modules` structure, alternate object stores), possible design changes to integrate with worktrees, and evaluation of existing workaround limitations.
