Feature patch adding conditional `--autostash` support to `git checkout` and `git switch`, addressing maintainer feedback from the initial version. This is version 2 of the patch series.

Harald Nordgren's updated implementation now makes the autostash behavior conditional - it only stashes when local changes would conflict with the branch switch, rather than stashing unconditionally. The patch introduces a new `checkout_would_clobber_changes()` function to detect these conflicts by performing a dry-run merge between the current and target branches.

Key improvements in v2:
- Only stashes when local changes overlap with branch differences
- Adds thorough test coverage for the new conditional behavior
- Documents the more precise semantics in man pages and config docs
- Maintains backward compatibility with existing autostash behavior in other commands

The implementation builds on Git's existing autostash infrastructure from the sequencer. The test suite (`t/t2061-switch-autostash.sh`) is comprehensive, covering various scenarios including clean worktrees, non-conflicting changes, staged changes, and explicit force flags.

This looks like a well-executed response to the maintainer's feedback, delivering a more precise implementation that avoids unnecessary stashing while maintaining the convenience of the autostash feature. The conditional behavior makes it more useful in practice while reducing potential confusion from unexpected stash operations.
