This is a submodule worktree integration discussion, continuing an ongoing thread about limitations in how submodules interact with worktrees. Xavier Morel follows up on Kristoffer Haugsbakk's question about whether the issue is specific to bare repositories.

Xavier confirms that the problem persists with non-bare parent repositories too - the core limitation appears to be that submodules don't properly recognize or support worktree references (the `gitdir:` pointers used by worktrees) when setting up the `.git/modules` structure. This suggests the issue is a general submodule-worktree integration gap rather than something specific to bare repositories.

The discussion remains focused on object storage efficiency, with Xavier noting that current workarounds like `--reference --dissociate` still result in object duplication and redundant fetches. The thread is exploring potential design changes to better support worktree-based workflows with submodules, though no concrete solutions have been proposed yet. This appears to be an underdeveloped area of Git's functionality that affects users managing large projects with worktree-heavy workflows.
