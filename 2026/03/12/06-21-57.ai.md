This is a technical clarification in the ongoing build system improvements thread about precompiled header (PCH) implementation details. Patrick Steinhardt responds to SZEDER Gábor's question about GCC's PCH behavior, confirming that the documentation does state PCHs cannot be included from inside another header and that the `-include` approach is necessary for Git's case.

The exchange clarifies that while Git's header inclusion patterns (where `git-compat-util.h` is always included first) might theoretically allow avoiding `-include`, the safer approach is to force-include the PCH via compiler flags. This maintains compatibility with projects not originally designed for PCHs and preserves the ability to build without PCHs when needed. The discussion serves as final verification of the technical approach taken in patch 8/8 of the series, which implements Meson PCH support with a demonstrated 40% build speedup.
