This is part 3 of Patrick Steinhardt's six-part series completing the ODB abstraction for object counting functionality. The patch relocates the loose object counting logic from `builtin/gc.c` to a new `odb_source_loose_approximate_object_count()` function in `object-file.c`.

The change extracts the existing sampling-based counting approach (which scans just one shard and multiplies by 256) into a reusable API. This prepares for introducing generic counting interfaces in later patches. The implementation maintains the same behavior while making the logic available to other callers through the ODB abstraction layer.

Key technical details:
- The new function takes a `struct odb_source` and returns the count via an `out` parameter
- Preserves the legacy behavior of rounding GC thresholds to multiples of 256
- Handles ENOENT gracefully (returning 0 for missing shards)
- Moves the counting logic while keeping the same directory scanning approach

This is a mechanical refactoring with no intended behavior change, part of the larger ODB abstraction effort to enable pluggable backends. The patch follows the pattern established in earlier parts of the series, with clean separation between the moved code and its new interface.
