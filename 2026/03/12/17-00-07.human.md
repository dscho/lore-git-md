This is the final patch in a feature series adding configurable cover letter formatting to `git format-patch`. The patch introduces a `format.commitListFormat` config option that mirrors the existing `--cover-letter-format` CLI option, allowing users to set their preferred cover letter format in config rather than specifying it each time.

Junio C Hamano suggests renaming the CLI option to `--commit-list-format` to better match the config name and improve tab completion. This would make the interface more consistent - currently `--cover-letter-format` is the only option that includes "format" in its name while relating to the commit list portion of the cover letter.

The series has gone through eight iterations and is now in its final form, having addressed all feedback. Key features include:
- Clean separation of shortlog generation via refactoring
- New `%(count)` and `%(total)` placeholders with zero-padding
- Configurable formats requiring "log:" prefix
- A new "chronological" preset format
- Comprehensive documentation and bash completion

The implementation is production-ready with all technical requirements met, including Junio's final suggestions about test improvements and making `--cover-letter-format` imply `--cover-letter`. The config option's empty value semantics follow Junio's preference for boolean-like behavior where empty=default.

This represents a well-executed feature addition that provides more flexibility in cover letter generation while maintaining backward compatibility. The only remaining question is whether to rename the CLI option as Junio suggests, which would be a minor but potentially worthwhile consistency improvement.
