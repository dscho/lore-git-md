This is a review response from the maintainer (Junio C Hamano) regarding a feature patch that implements `--autostash` support for `git checkout` and `git switch`. The patch had aimed to bring these commands in line with existing autostash functionality in `git rebase` and `git merge`.

Junio suggests a more sophisticated approach than the initial implementation. He proposes making autostash behavior conditional - only stashing when there are actual local changes that would conflict with the target branch. This would make the feature more useful than a simple alias could provide, while also potentially replacing the existing `-m` (merge) option with better conflict handling.

Key technical points raised:
- Current implementation stashes unconditionally, which could be done via user aliases
- Proposed alternative would only stash when local changes conflict with target branch
- Suggests this could subsume/replace the `-m` option's functionality
- Envisions the conflict detection logic being reusable for `git rebase` optimizations

The review indicates the patch needs reworking to:
1. Add smarter conflict detection before stashing
2. Consider integrating with/replacing the `-m` option
3. Structure the code for potential reuse in rebase

This is a substantive design-level review that will require significant reimplementation work from the original author. The maintainer is pushing for a more architecturally integrated solution rather than a straightforward port of existing autostash behavior.
