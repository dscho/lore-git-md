This is the final patch in a feature series adding configurable cover letter formatting to `git format-patch`. The patch introduces the `format.commitListFormat` configuration option, allowing users to specify the commit list format in their config file rather than always passing it via `--cover-letter-format` on the command line.

Junio C Hamano suggests renaming the command-line option from `--cover-letter-format` to `--commit-list-format` to better match the config option name and improve tab completion. This would make the interface more consistent and user-friendly, as `--cover-<TAB>` would uniquely expand to `--cover-letter` without forcing users to choose between that and the format option.

The series has gone through eight iterations with all technical requirements met, including:
- Clean separation of shortlog generation via refactoring
- New `%(count)` and `%(total)` placeholders with strict validation
- Comprehensive test coverage
- Finalized documentation following Junio's suggestions
- A new "chronological" format preset was added in v8 as a middle ground between shortlog and custom formats
- Config empty value semantics were resolved to follow boolean-like behavior (empty=default)
- The implementation maintains the "log:" prefix requirement for future extensibility

The feature is production-ready with all design decisions finalized, including Junio's documentation and implementation suggestions. The config option follows Git's standard precedence rules where command-line arguments override config settings. This patch represents the culmination of a well-executed feature addition that has undergone rigorous review across eight iterations.
