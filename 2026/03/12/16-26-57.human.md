This is a follow-up in the thread about Git command completion behavior, specifically addressing the difference between bash and zsh implementations. 

Andrey points out that while the completion script appears to be shared between bash and zsh (`/usr/share/bash-completion/completions/git`), the two shells show different behavior - with zsh completing commands that bash intentionally excludes. This observation comes after Junio Hamano's earlier clarification that the bash behavior (excluding plumbing commands like `symbolic-ref` and `bugreport`) is deliberate design, not a bug.

The email highlights an implementation inconsistency between shells that may warrant investigation. While Junio has established the principle that plumbing commands shouldn't appear in interactive completion, the fact that zsh shows them suggests either a bug in zsh's handling of the shared script or a different design choice in that implementation. This could prompt discussion about whether all completion implementations should uniformly respect Git's porcelain/plumbing distinction.
