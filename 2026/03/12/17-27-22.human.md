This is a design discussion in the final stages of a feature patch series implementing configurable cover letter formats for `git format-patch`. The thread has reached v8 with all technical aspects resolved, but maintainer Junio C Hamano is strongly objecting to the removal of a "log:" prefix for format names that was implemented in this latest version.

Junio argues the prefix serves two critical purposes: preventing typos in format names (like "chrnological" instead of "chronological") and maintaining clear namespacing for future format additions. He emphasizes this is a fundamental design issue affecting long-term maintainability, not just a stylistic preference. The author had removed the prefix in v8 based on earlier feedback, but Junio considers this a regression that needs to be reverted despite the series' advanced state.

The exchange highlights Git's emphasis on interface stability and error prevention, even late in the review process. Junio notes the practical concern of users running different Git versions across machines, where the prefix helps catch unsupported formats cleanly. The discussion remains technical but firm, with Junio stating plainly "It is a bad idea to drop 'log:', period" - signaling this will need to be addressed before final merge.
