This is a bugfix patch addressing zombie process accumulation in containerized Git operations. The patch is the final version (v4) of a series that has already received technical approval from Jeff King and Junio C Hamano, with only minor documentation formatting tweaks since v3.

The issue occurs when Git spawns child processes like git-remote-https or ssh during network operations, then exits abnormally (e.g. due to transport errors). Normally these children would be cleaned up, but the abnormal exit bypasses the usual cleanup paths, leaving zombie processes when running in containers where Git acts as PID 1. The solution leverages Git's existing `run-command` infrastructure by setting `clean_on_exit` and `wait_after_clean` flags on the child processes in both `connect.c` (for proxy connections) and `transport-helper.c`.

The implementation sends SIGTERM to child processes before waiting, avoiding potential deadlocks that could occur with a direct wait approach. This is a focused solution that specifically targets network operation children during abnormal exits, deliberately not attempting to solve broader container process management questions. The patch is small (6 lines of actual changes) and has been thoroughly reviewed, with all technical concerns addressed in previous iterations. It's now ready for merging.
