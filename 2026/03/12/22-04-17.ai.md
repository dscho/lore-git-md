This is the final approval for a bugfix patch addressing zombie process cleanup in containerized Git operations. Junio C Hamano has queued Andrew Au's v4 patch after it received technical approval from Jeff King and addressed all documentation concerns from earlier versions.

The patch solves a specific problem where network helper processes (git-remote-https, ssh) would become zombies when Git exits abnormally in container environments. The solution leverages Git's existing `run-command` infrastructure by setting `clean_on_exit` and `wait_after_clean` flags in three key locations (`connect.c` and `transport-helper.c`), ensuring proper SIGTERM-then-wait cleanup on any exit path. The 6-line change is minimal but effective, building on prior work (commit afe19ff7b5) and avoiding potential deadlocks that could occur with alternative approaches.

Key technical points confirmed through review include the safety of the kill-then-wait approach (approved by Jeff King) and the deliberate limitation to network operations (not expanding to broader process management). The patch has gone through multiple iterations to meet project standards, with v4 addressing Junio's earlier requests about trailer formatting and removing non-compliant AI attribution.
