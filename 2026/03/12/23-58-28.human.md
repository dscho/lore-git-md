This is a bugfix follow-up to the `git fast-import` signature handling series. Jeff King (Peff) points out a test failure in the Windows CI environment where a test case incorrectly assumes GPG prerequisites when it should be using SSH prerequisites instead. The test in question is part of the recently added `sign-if-invalid` mode functionality.

The issue is straightforward: the test tries to export from an "openpgp-signing" branch that only exists when GPG is available, but the test itself is marked with GPGSSH prerequisites. This creates a mismatch in test environments where only SSH signing is available. Peff suggests two possible fixes - either changing the test to reference the "ssh-signing" branch instead, or adding both GPG and GPGSSH prerequisites to cover both cases.

This appears to be a minor oversight in test setup rather than any fundamental issue with the signature handling implementation itself. The patch series has otherwise received positive feedback and is in its final polishing stages before merging. This test fix would likely be a quick follow-up to address the CI failure.
