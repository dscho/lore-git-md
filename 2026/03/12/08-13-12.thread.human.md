This thread explores limitations in Git's submodule support when used with worktrees, initiated by Xavier Morel with follow-up from Kristoffer Haugsbakk. The core issue affects both bare and non-bare parent repositories: submodules don't properly integrate with worktree workflows, forcing duplicate object storage through current workarounds like `--reference --dissociate`. This leads to redundant fetches and inefficient storage, particularly problematic for large projects.

The discussion has clarified that the limitation isn't specific to bare repositories, as Xavier's testing shows the same issues occur with non-bare parents. The technical focus remains on how `.git/modules` interacts with object storage in worktree contexts, with participants examining whether submodules could be enhanced to reference central repository locations more effectively. While no concrete solutions have been proposed yet, the thread highlights an important gap in Git's functionality for advanced repository management patterns where object duplication becomes costly. The conversation continues to explore potential design changes to improve this integration.
