This thread has been working through the implementation of autostash behavior for `git checkout -m`, a feature that will automatically stash changes when switching branches with conflicts. The series, now at version 12, has settled all major technical questions—including the use of `CHECKOUT_AUTOSTASH_HEAD` as the refname—and is in final polishing before being merged into the `next` branch. The implementation includes new options for customizing conflict marker labels in `git stash apply`, silent autostash creation, and integration with the sequencer.

Junio Hamano and Phillip Wood have been closely reviewing the series, with Junio approving it pending some final refinements to commit messages and user experience details. The last point under discussion is the format of the autostash message shown to users during branch switching. Junio advocates for including both the source and destination branch names (e.g., "autostash while switching from 'master' to 'topic'") to provide clearer context, particularly for workflows where users frequently switch from a common branch like `master`. Harald Nordgren, the series author, had initially proposed showing only the source branch. While this is a minor UX detail, it reflects Git's attention to real-world usability even after the technical implementation is complete.

The series is otherwise ready to go, with all feedback addressed over its 12 iterations. Once these final touches are settled, it will proceed to `next` for broader testing before eventual inclusion in a release.
