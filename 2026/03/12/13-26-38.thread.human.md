This thread documents the evolution of a feature that improves conflict resolution when switching Git branches with `git checkout -m`. The original proposal aimed to add autostash behavior to branch switching, but through discussion with maintainer Junio Hamano and reviewer Phillip Wood, it evolved into a more comprehensive solution that unifies conflict handling while maintaining backward compatibility.

The final implementation introduces several key improvements:
1. When conflicts occur during branch switching, local changes are now automatically stashed and reapplied (similar to how `git rebase` handles conflicts)
2. Conflict markers show helpful branch names for clarity
3. The stash creation happens silently during checkout operations to avoid unnecessary output
4. The implementation preserves existing behavior like showing modified files

The series went through five iterations, with each version addressing feedback. Notable changes included moving status output to stderr, adding comprehensive test coverage (18 new test cases), and implementing custom conflict marker labels through new `git stash apply` options. The technical implementation touches multiple core components including checkout, stash, and sequencer logic.

While the series is now complete and ready for merging, one open question remains regarding submodule handling. Junio has indicated he prefers to defer submodule support to future work rather than expanding `git stash`'s scope. The author may address this separately later.

This represents a significant quality-of-life improvement for users who frequently switch between branches with uncommitted changes, making conflict resolution more consistent with other Git commands while maintaining the expected behavior for existing workflows.
