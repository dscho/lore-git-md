This thread documents a 12-iteration patch series by Harald Nordgren that enhances `git checkout -m` with autostash behavior during branch switching conflicts. The feature automatically stashes uncommitted changes when conflicts occur during a branch switch, then reapplies them afterward - a significant quality-of-life improvement that brings this workflow in line with Git's existing autostash behavior in rebase and merge.

The implementation is thorough, handling both staged and unstaged changes while maintaining backward compatibility. It introduces new `git stash apply` labeling options (`--label-ours`, `--label-theirs`, `--label-base`) and implements silent autostash creation. The refname convention (`CHECKOUT_AUTOSTASH_HEAD`) was validated by Jeff King, and the final naming refinements were implemented per Junio Hamano's request. Phillip Wood provided key technical review throughout the series' development.

With 19 new test cases in t7201-co.sh and 2 in t3903-stash.sh, the series has comprehensive test coverage. It modifies several core components including `builtin/checkout.c`, `builtin/stash.c`, and the sequencer, while integrating with Git's existing conflict marker infrastructure. All technical concerns have been resolved over the 12 iterations, and Junio has approved the series for merging. This represents a polished, well-reviewed contribution that significantly improves the branch switching experience for users with uncommitted changes.
