Harald Nordgren's patch series implementing autostash behavior for `git checkout -m` has been merged into the `next` branch after twelve iterations of review. The series enhances branch switching by automatically stashing changes when conflicts occur, with new options to customize conflict marker labels and support for silent autostash operations. Key reviewers Phillip Wood and Jeff King provided extensive technical feedback that was fully addressed, including settling on the `CHECKOUT_AUTOSTASH_HEAD` refname convention.

Junio Hamano merged the series but has since followed up with process feedback, noting that future submissions should include concise human-written summaries of changes between versions. This would help reviewers navigate the large range-diffs that currently obscure minor refinements like the function renaming and message handling consolidation in v12. While the technical changes in this version were minimal, Junio's suggestion reflects his focus on maintaining efficient review processes even for already-accepted work. The core functionality - which handles both staged and unstashed changes during branch switching while preserving the stash if conflicts occur - remains unchanged and is now in wider testing in the `next` branch.
