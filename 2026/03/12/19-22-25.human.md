This is the fifth version of a patch series adding signature handling capabilities to `git fast-import`, specifically introducing a new `sign-if-invalid` mode that allows re-signing commits with invalid signatures rather than just stripping them. The series builds on previous work that enabled handling of invalid commit signatures in fast-import.

The key changes in v5:
- Instead of introducing a separate `sign_buffer_with_key()` helper, the series now extends `sign_buffer()` with a `SIGN_BUFFER_USE_DEFAULT_KEY` flag to handle default signing key fallback
- Fixed an error message to clarify it's about "signing commits" rather than "signing signatures"
- Maintains all the core functionality from previous versions including comprehensive test coverage for OpenPGP/X.509/SSH signatures

The implementation looks clean and well-tested, with clear commit messages explaining the changes. The series has gone through several iterations with improvements based on feedback, and appears to be in its final polishing phase. The main remaining limitation is handling signatures in interoperability mode (when working across different hash algorithms), which the author has deferred for now with a clear explanation of the technical challenges involved.

This builds on previous signature handling work in fast-import and connects to broader signature work in Git. The refactoring establishes reusable signing infrastructure that could support future extensions. The series seems ready for merging pending any final review comments.
