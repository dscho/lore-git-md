This is the maintainer's response to v2 of a feature patch adding conditional autostash support to `git checkout` and `git switch`. Junio C Hamano suggests two significant conceptual improvements to the feature's design.

First, he proposes that the existing `-m` flag (which currently enables a three-way merge during checkout) should become a synonym for `--autostash`, since the new behavior is effectively a safer version of what `-m` already does. This would unify the two approaches rather than introducing a parallel mechanism.

Second, he questions whether "autostash" is the right framing for users, since the stash is an implementation detail. He suggests `--merge` might better describe the actual user-visible behavior (merging local changes into the new branch) rather than focusing on the stashing mechanism.

The response is generally positive about the implementation quality while pushing for these higher-level design considerations. This suggests the technical approach in v2 is sound, but the user interface may need refinement before merging. The author will likely need to address these naming and flag integration suggestions in a v3 submission.
