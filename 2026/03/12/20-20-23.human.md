This is a maintainer review comment on the final patch in a v5 about `git fast-import` signature handling. Junio C Hamano suggests rewording some warning messages to be clearer about what's happening when re-signing commits with invalid signatures.

The current messages say "signing commit with invalid signature" which could be misread as adding an invalid signature. Junio proposes alternatives like "replacing an invalid signature for commit" or "re-signing commit that has an invalid signature" to better convey that we're fixing bad signatures rather than creating them.

This is a minor wording polish on an otherwise complete patch series that:
- Adds `sign-if-invalid` mode to re-sign commits with bad signatures
- Shares infrastructure with existing signature stripping
- Has thorough test coverage
- Was already approved for merging with only this small clarification needed

The series builds on earlier work by Christian Couder and Justin Tobler to handle signatures in fast-import, with this being the last piece adding re-signing capability. The implementation looks solid and the discussion has converged, with this being the last minor tweak before merging.
