This is a response from the Git maintainer clarifying the design intent behind command completion behavior. Junio C Hamano explains that the reported "bug" in bash completion (missing certain commands like `symbolic-ref` and `bugreport`) is actually working as intended - the bash completion script deliberately excludes plumbing commands from tab completion to avoid cluttering the interface for interactive users. 

The key points are:
1. The behavior is not a bug but a design choice to separate porcelain (user-facing) from plumbing (internal) commands
2. If zsh completion shows these commands, that implementation may be incorrect or misunderstanding Git's command classification
3. Commands like `cat-file` and `commit-tree` are similarly excluded as they're plumbing

This response shifts the discussion from being about a technical bug to being about design philosophy and command categorization. The maintainer's position is clear - plumbing commands should not appear in interactive completion, and any implementation showing them is likely wrong. This may close the issue unless the reporter can argue these commands should be reclassified as porcelain.
