This is a v5 patch series adding signature handling capabilities to `git fast-import`, specifically introducing a `sign-if-invalid` mode that allows re-signing commits with invalid signatures. The series builds on previous work that enabled stripping invalid signatures.

The key changes in v5:
- Replaces the proposed `sign_buffer_with_key()` helper with an extended `sign_buffer()` function that takes a `SIGN_BUFFER_USE_DEFAULT_KEY` flag
- Fixes a die() message to clarify it's about "signing commits" rather than "signing signatures"
- Maintains the limitation of not supporting interoperability mode signatures (with explicit NEEDSWORK comment)

The series consists of three cleanly separated patches:
1. A cleanup removing an unused forward declaration
2. The refactoring of signing infrastructure to support default key fallback
3. The main implementation adding `sign-if-invalid` mode

Technical details:
- New `sign-if-invalid[=<keyid>]` mode matches `git commit --gpg-sign` syntax
- Uses enhanced `sign_buffer()` with flags parameter
- Comprehensive test coverage for OpenPGP/X.509/SSH signatures
- Explicit failure for `extensions.compatObjectFormat` with clear explanation
