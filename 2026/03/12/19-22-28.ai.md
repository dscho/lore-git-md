This is the final patch in a v5 series adding signature handling capabilities to `git fast-import`, specifically implementing the `sign-if-invalid` mode that allows re-signing commits with invalid signatures. The patch builds on previous work that enabled stripping invalid signatures.

The key addition is the `sign-if-invalid[=<keyid>]` mode for `--signed-commits`, which verifies commit signatures and replaces invalid ones with newly created signatures while leaving valid signatures unchanged. The implementation shares infrastructure with the existing `strip-if-invalid` mode but adds signing capability through the consolidated `sign_buffer()` function introduced in patch 2 of this series.

Technical details include:
- New `SIGN_SIGN_IF_INVALID` enum value
- Updated `parse_sign_mode()` to handle optional keyid parameter
- Shared warning infrastructure between sign/strip modes via `warn_invalid_signature()`
- Explicit test coverage for OpenPGP/X.509/SSH signatures
- Key limitation: interoperability mode signatures are explicitly unsupported (with NEEDSWORK comment)
- Comprehensive tests showing both default key and explicit keyid usage

The patch maintains clean separation from the existing signature stripping functionality while reusing common verification infrastructure. Test coverage is thorough, exercising both the happy path (keeping good signatures) and the re-signing of invalid signatures. The implementation appears solid and well-integrated with the series' earlier refactoring work.

This completes the v5 series' goal of enabling re-signing capability in fast-import, building on the merged v2 work that first introduced signature handling. The series has evolved through multiple iterations with improvements to API design and documentation clarity. With all major design questions resolved and only warning message cleanup remaining for follow-up, this appears ready for merging.
