This is a follow-up in the discussion about Git command completion behavior, specifically addressing the porcelain/plumbing command distinction in shell completions.

Andrey points out that while the completion script appears to be shared between bash and zsh (`/usr/share/bash-completion/completions/git`), the two shells exhibit different behavior - zsh shows plumbing commands like `symbolic-ref` and `bugreport` while bash does not. This observation comes in response to Junio's earlier clarification that the bash behavior (excluding plumbing commands) is intentional design.

The email raises an interesting technical point: if the script is truly shared between shells, the divergent behavior suggests either shell-specific interpretation of the same code or different configuration/loading paths that affect the final behavior. This could indicate an implementation bug in how the shared script is processed by zsh versus bash, or perhaps that zsh is loading a different version of the completion script than the one being examined.

The thread continues to center around Git's philosophy of keeping plumbing commands out of interactive completion, with Junio having firmly established this as the intended behavior. Andrey's observation about the zsh behavior potentially being inconsistent with this principle could prompt further investigation into why the shells differ, though the maintainer has already indicated that any completion showing plumbing commands is likely incorrect.
