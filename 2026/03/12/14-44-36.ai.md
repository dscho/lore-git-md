This is part of the ongoing `the_repository` removal effort, specifically targeting the `start_command()` function and related maintenance code. The patch replaces the `close_object_store` boolean flag in `struct child_process` with an explicit `odb_to_close` pointer, allowing callers to specify which object store needs closing during process spawning.

The change affects several built-in commands (`gc`, `pull`, and auto-maintenance) that spawn child processes while needing to close the object store. The conversion is mechanical but important for eliminating implicit repository dependencies. The patch follows René Scharfe's suggestion and builds on prior review feedback from Patrick Steinhardt and others.

Key technical details include the new `odb_to_close` field in `struct child_process` and updates to the affected call sites in `builtin/gc.c`, `builtin/pull.c`, and `run-command.c`. The change maintains the same behavior while making the repository dependency explicit. This is the first of two patches in v3 of the series, with the second patch extending the conversion to additional maintenance code as suggested by Patrick Steinhardt.
