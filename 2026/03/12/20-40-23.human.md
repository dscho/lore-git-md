This is a review response in an ongoing thread about zombie process cleanup in Git's network operations. Jeff King (Peff) is reviewing Andrew Au's v3 patch that addresses abnormal exits during network operations (like git-remote-https or ssh connections).

Peff confirms the technical approach of using both `clean_on_exit` and `wait_after_clean` flags in the child process structs is correct, noting this avoids potential deadlocks from the earlier atexit handler approach. He approves the implementation as being straightforward once the design is accepted.

The review also touches on a minor formatting question about how to properly credit AI-assisted work (the patch includes a Co-authored-by trailer for GitHub Copilot). Peff notes there isn't yet an established project convention for this, but suggests that if such credits are included, they should follow standard trailer formatting without blank lines.

This moves the thread closer to resolution, with Peff's approval of the technical implementation leaving only the broader architectural question (how much child process management should be Git's responsibility versus the container/system's) as the remaining open discussion point. The patch appears ready for final consideration by the maintainer.
