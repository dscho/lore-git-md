This is a follow-up discussion in the promisor-remote bugfix thread, now at v3. Patrick Steinhardt is probing deeper into the root cause of the recursive lazy-fetch issue that Paul Tarjan encountered in production. While the technical solution (propagating GIT_NO_LAZY_FETCH) has consensus, Patrick raises important questions about server-side behavior that might be contributing to the problem.

The exchange reveals that GitHub's server is sending REF_DELTA objects against missing bases in blob:none partial clones, which Patrick finds surprising. He suggests there might be an underlying server protocol issue, possibly related to object filters not being consistently applied across fetches. While acknowledging the client-side hardening is valuable regardless, Patrick wants to ensure the fix doesn't inadvertently break valid cases where thin packs with REF_DELTAs are expected.

The discussion remains productive, with Patrick bringing in Jeff King (Peff) for additional expertise on partial clone behavior. The patch itself is sound and ready to merge, but this thread highlights that the issue may have broader implications for how servers handle delta chains in partial clone scenarios. The thorough test case Paul added in v3 gives confidence that the client-side fix addresses the immediate problem while leaving room for future server-side improvements.
