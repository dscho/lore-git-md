Bugfix for `git backfill` argument validation, addressing maintainer feedback.

Siddharth Shrimali sends v3 of his patch to make `git backfill` properly reject unexpected arguments, responding to Junio C Hamano's detailed review of v2. The command previously silently ignored extra arguments, violating Git's standard behavior. This version makes three key changes: replacing backticks with single quotes in error messages (addressing style consistency concerns), showing only the short usage string rather than full options (matching `git bugreport`'s tiered output), and enhancing the test to verify the full option list isn't shown.

The patch modifies `builtin/backfill.c` to check for leftover arguments after `parse_options()` and error out with a clear message. The test in t5620-backfill.sh now confirms both the presence of the error message and absence of verbose option output. While small, this change shows the project's attention to detail - even a 5-line fix undergoes multiple rounds of review to ensure it aligns with established patterns for error handling and user experience.
