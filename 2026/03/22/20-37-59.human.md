This is a feature patch (v3) from Pablo Sabater proposing a `--graph-lane-limit` option to constrain the width of `git log --graph` output. The patch addresses readability issues with wide commit graphs by allowing users to cap the number of displayed columns, with excess lanes shown as '.' characters while preserving commit markers ('*').

The implementation adds a `graph_max_lanes` field to `struct rev_info` and enforces a minimum of 1 column. The option requires `--graph` and will error if used without it. This version responds to Junio Hamano's feedback by renaming the option from `--max-columns` (v2) to `--graph-lane-limit` and improving validation.

The patch appears well-constructed with clear boundaries - it modifies graph.c, graph.h, revision.c and revision.h while maintaining the existing graph rendering logic. The author has been responsive to review feedback through three iterations, though design discussion remains active regarding the implicit `--graph` requirement and option naming. Johannes Sixt has raised concerns about how the implicit behavior might complicate future configuration options.

This is part of a larger effort to improve graph rendering usability, addressing a 2008 TODO comment in graph.c. The patch series shows good technical execution but the design discussion around UX implications isn't fully settled yet.
