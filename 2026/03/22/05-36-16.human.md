This is a bugfix addressing a segfault in `parse_refspec()` when Git operations are performed outside a repository context. The issue was originally reported by Jo Liss and affects commands like `git ls-remote -h` when global fetch refspecs are configured but no repository exists.

K Jayatheerth's v3 patch follows the approach suggested by Jeff King (Peff) in previous discussion - rather than initializing a fallback hash algorithm, it simply skips hash-algorithm-dependent checks when operating outside a repository. The changes are minimal but effective, adding NULL checks for `the_hash_algo` before accessing its `hexsz` field in both standard and negative refspec parsing paths.

The patch includes a new test case that reproduces the crash scenario in a genuine non-repo environment using Git's `nongit` helper and `-c` configuration, as suggested by reviewers. This version also properly retains the `git-curl-compat.h` include that was incorrectly marked for removal in v2.

The solution cleanly resolves both the immediate crash and the underlying architectural question of whether hash-algorithm checks make sense without a repository context. It maintains compatibility with Git's SHA-256 transition while avoiding unnecessary initialization of hash algorithms. The patch appears ready for merging, having addressed all feedback from Jeff King, brian m. carlson, and Junio C Hamano.
