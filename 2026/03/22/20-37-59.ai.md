This is the first patch in a feature series (v3) from Pablo Sabater introducing a `--graph-lane-limit` option to constrain `git log --graph` output width. The patch adds core infrastructure for the feature by:

1. Defining `MINIMUM_GRAPH_COLUMNS=1` in graph.h
2. Adding `graph_max_lanes` to `struct rev_info` to store the user's column limit
3. Implementing `graph_needs_truncation()` helper to check when columns exceed the limit
4. Adding option parsing for `--graph-lane-limit` with validation against the minimum
5. Enforcing that the option requires `--graph` to be set

The implementation follows the design direction from Junio Hamano in previous rounds, with the option now finalized as `--graph-lane-limit` (was `--max-columns` in v2). The patch handles basic plumbing while leaving the actual graph rendering changes to subsequent patches in the series.

Key technical details:
- Uses `parse_long_opt`/`parse_count` for option validation
- Rejects values below `MINIMUM_GRAPH_COLUMNS` (1)
- Stores limit as `unsigned int` in `rev_info`
- Maintains separation between limit checking (this patch) and display logic (future patches)

The patch appears well-structured and focused on its narrow scope. It sets up the necessary infrastructure while deferring the more complex rendering changes to later in the series. The validation and error handling seem thorough, and the implementation aligns with Git's existing patterns for revision option handling.
