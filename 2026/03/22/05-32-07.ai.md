Bugfix for `git backfill` argument validation.

Siddharth Shrimali sends v3 of a patch to make `git backfill` properly reject unexpected arguments, addressing Junio C Hamano's feedback from the previous iteration. The command previously silently accepted extra arguments, violating Git's standard behavior. The new version now shows an error message with the invalid argument and a short usage string, matching the pattern used by other Git commands like `git bugreport`.

Key changes in this version:
- Replaced backticks in the error message with single quotes to align with the project's predominant quoting style
- Simplified the output to show only the short usage string rather than full option descriptions when arguments are invalid
- Enhanced the test in t5620-backfill.sh to verify both the error message appears and the full option list does not

The patch touches `builtin/backfill.c` to add the argument check and `t/t5620-backfill.sh` for testing. Junio's earlier review identified subtle inconsistencies with reference implementations and style issues, which this small change has now addressed. The implementation follows the maintainer's preference for precise error handling and output behavior while cleaning up a minor inconsistency in the codebase's message formatting.
