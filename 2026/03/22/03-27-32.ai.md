This is a follow-up discussion about a feature patch that would add a `paths.git_dir` key to `git repo info`. Tian Yuchen points out a discrepancy between the patch's stated goal (matching `git rev-parse --git-dir` behavior) and its implementation.

The key issue is that `git rev-parse --git-dir` returns context-sensitive paths (relative or absolute depending on current directory), while the current implementation simply uses `repo_get_git_dir()` which doesn't account for this. The test coverage is insufficient as it only verifies behavior in the repository root.

This is a valid technical concern about the patch's correctness, though the tone remains constructive. The thread now has two open questions: the GSoC process considerations raised earlier by Karthik Nayak, and this new technical issue about path handling. Both would need resolution before the feature could proceed. The core idea (exposing gitdir path programmatically) still seems useful, but the implementation needs adjustment to properly match rev-parse's behavior.
