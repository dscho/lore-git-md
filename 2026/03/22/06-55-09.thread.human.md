Mateo Patino, a new contributor, has proposed an RFC for a `STRBUF_INIT_CONST` macro to initialize strbufs with constant strings without heap allocation, potentially as a GSoC project. This idea has a history - three previous attempts (2019-2021) were discussed but never merged, most recently being marked as #leftoverbit by Patrick Steinhardt in 2025. The optimization aims to handle constant strings more efficiently but lacks concrete performance data.

Eric Sunshine provided crucial context about why past attempts failed. The core issue isn't implementation details but a fundamental conflict with strbuf's design - the API guarantees buffers are always writable, while `STRBUF_INIT_CONST` would point to read-only string literals. Jeff King had raised this architectural objection back in 2020, and previous submissions stalled when authors didn't address this concern. Unless Mateo can propose a solution that preserves strbuf's writability guarantee while achieving the optimization, this approach appears to remain blocked by the same technical hurdle that stopped prior efforts. The thread serves as both a technical reality check and an invitation for innovative thinking about this long-standing challenge.
