This is the second patch in a feature series (v3) implementing `--graph-lane-limit` for `git log --graph` output. The patch focuses on the actual graph rendering changes needed to truncate wide graphs while preserving commit markers ('*').

The implementation:
- Adds truncation markers ('.') when graph width exceeds the lane limit
- Handles merge commits specially - only showing merge lanes when at least one parent is visible
- Maintains commit markers even in truncated sections
- Updates the various graph line types (pre-commit, post-merge, collapsing) to respect the limit
- Preserves the existing graph structure while truncating excess lanes

The changes touch graph.c extensively, modifying how each line type handles truncation. The patch appears thorough in its handling of edge cases, particularly around merge commits where it must decide whether to show merge lanes based on parent visibility.

This is a clear step forward in the series, implementing the core visualization behavior while building on the infrastructure from patch 1/3. The implementation seems well-considered, though the complexity of graph.c's lane handling (some unchanged since 2008) makes this non-trivial. The patch maintains good separation of concerns while adding the new truncation behavior.
