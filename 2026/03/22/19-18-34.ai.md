This is the third patch in a 4-part series addressing promisor file handling during repacks, part of Lorenzo Pegorari's GSoC work under Eric Sunshine's mentorship. The patch focuses on preserving debug information in `.promisor` files when repacking promisor packfiles.

The key change modifies `repack-promisor.c` to use the new `copy_all_promisor_files()` helper (introduced in patch 2) to consolidate debug information from all existing `.promisor` files into the first new one created during repack. This addresses the `NEEDSWORK` comment from commit 5374a290 about losing ref/hash debug information during repacks. The patch also updates `git-repack.adoc` documentation to clarify that the resulting `.promisor` file will contain "arbitrary contents" (the preserved debug info) rather than being empty.

The implementation introduces an `is_first_promisor` flag to ensure we only copy contents once, into the first new promisor file created. This maintains the series' approach of keeping debug information consolidated rather than duplicated across files. The changes demonstrate good attention to detail in preserving existing debugging capabilities while cleaning up the repack behavior.

This patch builds cleanly on the previous work in the series and shows thoughtful handling of the edge case where promisor files might contain valuable debug information. The documentation update is appropriately minimal, just clarifying the changed behavior without over-explaining implementation details.
