Maintainer feedback on backfill argument validation patch.

Junio C Hamano responds to Siddharth Shrimali's v2 patch that aimed to make `git backfill` reject unexpected arguments consistently with other Git commands. While acknowledging the improvement, Junio points out that the current implementation isn't actually consistent with `git bugreport`'s behavior as claimed - bugreport shows just a short usage message for plain arguments but full option details for invalid options, whereas this patch always shows the full usage.

Junio also flags the use of backticks in error messages (`unknown argument `%s'`) as undesirable, noting they're already overused in the codebase (16 instances) compared to straight quotes (2012 instances). He suggests this could be a good cleanup task for future contributors.

The test coverage comes under scrutiny too - while it verifies the error message appears, it doesn't confirm the command doesn't show unwanted additional output (like the full option list). This leaves room for false positives where the test would pass even if the implementation regressed to showing too much information.

The thread shows the maintainer's attention to both user experience details (error message formatting) and long-term codebase consistency (quote style proliferation), even for a straightforward 5-line change. Siddharth will likely need to send a v3 addressing these finer points about output behavior and message formatting.
