RFC proposal from Mateo Patino (new contributor) for `STRBUF_INIT_CONST` macro to initialize strbuf with constant strings without heap allocation, presented as GSoC candidate. This revives a concept with three prior attempts (2019-2021), most recently noted by Patrick Steinhardt as #leftoverbit in 2025. Eric Sunshine provides critical historical context: past submissions stalled because authors didn't address Jeff King's (Peff) 2020 architectural objection - strbuf's API guarantees writable buffers, while `STRBUF_INIT_CONST` would violate this by pointing to read-only string literals, creating an API contract violation requiring extensive audits of strbuf consumers. The fundamental challenge is preserving strbuf writability guarantee while achieving the optimization, making current approach impractical unless a fundamentally different solution emerges. Open question remains whether any viable path exists that satisfies both goals, or if this should be considered a dead end based on past feedback.
