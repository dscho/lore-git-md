This is a bugfix addressing a segfault in `git ls-remote` when parsing refspecs outside a repository context. The patch follows up on discussion in the thread about how to handle hash algorithm checks when no repository exists.

K Jayatheerth's v2 patch takes Jeff King's suggestion to skip the hash algorithm checks entirely in `parse_refspec()` when `the_hash_algo` is NULL, rather than initializing a fallback algorithm. This makes sense since fetching isn't possible without a repository anyway. The change is minimal - just adding NULL checks before two hash-algorithm-dependent comparisons in `refspec.c`.

The patch keeps the same test case from v1 that reproduces the crash by running `git ls-remote` with a global fetch refspec but no repository. The test uses `GIT_CEILING_DIRECTORIES` to ensure a genuine non-repo environment. The author also removed an unused `git-curl-compat.h` include from `remote-curl.c` while working in that area.

This appears to be a clean solution to the immediate crash, though the broader thread discussion suggests there may be more architectural questions about whether these hash checks should exist at all for repository-less operations. The patch is well-contained and maintains compatibility with Git's SHA-256 transition plans.
