This is a response to an RFC about introducing `STRBUF_INIT_CONST`, a proposed optimization for initializing `strbuf` with constant strings. Eric Sunshine provides historical context, noting that while the idea has been proposed multiple times (2019-2021), prior attempts failed because submitters didn't address critical feedback rather than because the project rejected the concept outright.

The key technical obstacle is that `strbuf`'s API assumes its buffer is always writeable, while string literals are read-only. Jeff King (Peff) previously identified this as a fundamental incompatibility that would require auditing all `strbuf` consumers - a potentially impractical undertaking. Eric suggests that unless Mateo can propose a novel approach to this problem, reviving the effort may not be productive.

The response serves as a reality check for the new contributor, tempering enthusiasm with the project's historical experience while leaving the door open for innovative solutions. It's a constructive but cautious reply that sets clear expectations about the challenges involved.
