This is a feature patch from Pablo Sabater (a GSoC participant) introducing a `--graph-lane-limit` option to constrain `git log --graph` output width. It's part of a completed v3 series that adds infrastructure for limiting graph columns while preserving commit markers.

Junio Hamano provides review feedback on the patch's commit message and implementation details. He questions whether the width problem occurs primarily with active branches or merge commits, and suggests improving the explanation of the design rationale rather than focusing on implementation minutiae like the `MINIMUM_GRAPH_COLUMNS` macro. He also notes a type consistency issue where `graph_max_lanes` is `unsigned int` but some related variables use `int`.

The patch itself adds core infrastructure:
- Defines minimum column limit (1)
- Adds `graph_max_lanes` to `rev_info`
- Implements truncation checking
- Handles option parsing and validation
- Enforces that `--graph` must be set

This is the first of three patches in a series that appears technically sound but could benefit from clearer documentation of the design choices. The review conversation suggests the feature is nearing readiness, with some minor polish needed on the explanation side.
