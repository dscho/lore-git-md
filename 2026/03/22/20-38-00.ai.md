This is the second patch in a feature series (v3) implementing `--graph-lane-limit` for `git log --graph`. The patch modifies graph.c to actually truncate the graph output when the number of columns exceeds the user-specified limit, showing excess lanes as '.' while preserving commit markers ('*').

The implementation handles several edge cases:
- Maintains POST_MERGE status when either commit or parent is in a visible lane
- Adds truncation marks ('.') when lanes exceed the limit
- Preserves commit markers ('*') even when truncated
- Adjusts spacing and merge lane rendering around truncation points

Key technical changes:
- Modifies graph_output_* functions to check graph_needs_truncation()
- Adds special handling for merge commits when truncated
- Updates state transitions to account for truncation
- Preserves horizontal edges in collapsing lines when possible
- Adds '.' markers consistently across all graph line types

The patch appears thorough in its handling of the graph rendering edge cases, though it touches some complex logic in graph.c's lane management. The changes maintain backward compatibility while adding the new truncation behavior. The implementation follows the design established in patch 1/3, with careful attention to how truncation interacts with existing graph states (POST_MERGE, COLLAPSING, etc.).

This represents the core part of the feature - where the actual visual truncation behavior is implemented. The changes are focused on the rendering logic while maintaining the separation from the option plumbing added in patch 1/3.
