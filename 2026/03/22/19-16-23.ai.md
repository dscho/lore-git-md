This is a documentation patch in Lorenzo Pegorari's GSoC series on promisor file handling during repacks. The patch adds clarifying comments to `pack-write.c` explaining the purpose of the ref names and hashes stored in `.promisor` files. 

The new comment explains that these records are purely for debugging purposes - they help identify which refs were fetched when the packfile was downloaded, allowing comparison with the promisor remote's current state if issues arise in partial clones. This documentation addresses a gap where the purpose of these records was previously only implicit in the code.

As the first patch in the v2 series, it remains unchanged from v1 version that Eric Sunshine reviewed. The comment provides useful context for the subsequent patches that will modify how these promisor files are handled during repacks. The explanation is clear and technically accurate, matching the implementation behavior. This is a straightforward documentation improvement that helps future maintainers understand the debug information stored in promisor files.
