This is an RFC (Request for Comments) proposal from a new contributor about implementing `STRBUF_INIT_CONST`, a macro to initialize a `strbuf` with a constant string without heap allocation. The proposal comes from Mateo Patino, a first-year student looking to work on this as a Google Summer of Code (GSoC) project.

The email notes this idea has a long history in the Git project, with three previous attempts (in 2019, 2020, and 2021) that generated discussion but weren't merged. Most recently, Patrick Steinhardt mentioned it as a #leftoverbit in a 2025 patch series. Mateo is asking whether this feature would be worth pursuing now, given this context.

The technical motivation would be to optimize cases where a `strbuf` is initialized with a constant string that never needs modification, avoiding unnecessary heap allocation. However, the email doesn't provide concrete performance measurements or use cases where this would help - it's primarily surveying whether there's still interest given the feature's stalled history.

As an RFC from a new contributor, this appears to be a genuine inquiry rather than a fully formed proposal. The tone is appropriately cautious given the feature's history, and the email shows good research by citing all prior discussions. The next steps would depend on whether maintainers see value in reviving this optimization or if they consider it a dead end based on past feedback.
