This is patch 3/6 in Justin Tobler's series adding repository statistics to `git repo`. The patch focuses on tracking the largest objects in the repository by type (commits, trees, blobs, and tags).

The key technical additions are:
- A new `struct largest_objects` containing `object_data` pairs (OID + size) for each object type
- The `check_largest()` helper function that updates tracking when larger objects are found
- Integration with the existing object counting infrastructure to record sizes during traversal
- Output formatting additions for both table and key-value formats showing maximum sizes
- Test coverage in t1901 verifying the new statistics appear correctly

The implementation handles edge cases like empty repositories through NULL OID checks in `check_largest()`. The output shows both the maximum size and the OID of the largest object (though the OID is only visible in key-value format in this patch - a follow-up will add it to table annotations).

This builds on the series' foundation while maintaining the established performance characteristics (3-6s runtime). The changes are well-contained within the existing architecture, with clear separation between data collection and presentation layers.
