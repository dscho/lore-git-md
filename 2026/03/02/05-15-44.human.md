This is the second patch in a feature series enhancing repository path reporting. It introduces category-based key requests to the new `repo info` command, allowing users to request all keys under a category (e.g. `layout.*`) with a single request.

The patch adds a new `print_category_fields()` helper that expands category requests by matching against the dot-separated prefix of available keys. When a user requests "layout", it will automatically include all keys starting with "layout." while maintaining the existing behavior for explicit key requests. Unknown keys or categories still produce clear error messages.

The implementation is straightforward - it loops through the available fields, checks for matching prefixes, and prints each matching field. The change maintains backward compatibility while adding the new functionality. This builds on the `struct repo_info` plumbing introduced in patch 1 of the series.

The patch appears well-contained and focused, with clean separation between the new category expansion logic and the existing key-based lookup. It follows the series' goal of providing more flexible path reporting while keeping the interface clean and predictable.
