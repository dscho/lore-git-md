This is a maintainer intervention in the ongoing discussion about adding repository path fields to `git repo info`. Junio C Hamano steps in to express concern about the lack of coordination around this effort.

The thread had seen active development from Pushkar Singh and Patrick Steinhardt to add structured path output (like `path.git-dir` and `path.common-dir`) as a machine-readable alternative to `git rev-parse`. While the technical implementation was uncontroversial - using existing path APIs and following Lucas Skeggs' prior work on structured output - Lucas Seiki Oshiro had raised procedural concerns about whether the base `git repo info` command would be accepted at all.

Junio's email highlights two key issues: First, he observes that multiple contributors appear to be working independently on path-related fields without sufficient coordination. Second, he implies skepticism about whether this effort is properly scoped and aligned, given that the foundational command's acceptance remains unresolved.

This maintainer feedback effectively puts the brakes on further development of path fields until the project reaches consensus on whether `git repo info` should exist as a command. The technical merits of the individual patches become moot until this higher-level question is settled. Junio's intervention suggests the discussion needs to step back and address the command's fundamental purpose before proceeding with field additions.
