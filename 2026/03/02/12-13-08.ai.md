This is the fourth patch in Patrick Steinhardt's series introducing a new `git history split` subcommand. The patch extends the add-patch infrastructure to support applying changes to in-memory indexes rather than just the repository's main index.

The key technical addition is a new `run_add_p_index()` function that allows callers to specify an arbitrary `index_state` and `index_file` to operate on, rather than always using the repository's index. This builds on the refactoring done in earlier patches by extracting common logic into `run_add_p_common()` that both the original `run_add_p()` and new `run_add_p_index()` can share.

The patch makes several supporting changes to enable this:
- Adds `index` and `index_file` fields to `struct add_p_state`
- Updates index operations to use the specified index rather than `s->r->index`
- Handles the case where the in-memory index differs from the repository's index
- Introduces proper cleanup paths for error cases

This infrastructure will be used in subsequent patches to implement the actual commit splitting functionality, where changes need to be applied to temporary in-memory indexes during the split operation. The patch maintains all existing behavior when using the original `run_add_p()` function.

As with the rest of the series, this is a well-structured change that follows Git's incremental development style - introducing the needed infrastructure before the feature that will use it. The patch touches the add-patch subsystem and prepares for upcoming work in the history command family.
