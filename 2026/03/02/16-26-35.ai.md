Windows-specific regression in gitdir validation handling.

This is Junio Hamano's follow-up to Tian Yuchen's v11 patch series that aimed to improve error diagnosis for invalid `.git` files. The core issue involves Windows-specific behavior where `stat("nul")` fails differently than on Unix systems, causing widespread test failures. The patch had been merged but was reverted after CI revealed these Windows-specific regressions.

Junio is now explicitly calling for Windows platform experts to help diagnose why the patch breaks nearly all tests on Windows, particularly noting that `GIT_DIR=/dev/null git diff --no-index` now fatally errors when reading `nul` (Windows' equivalent of `/dev/null`). The failure suggests the patch's stricter error handling is correctly identifying a platform-specific case that was previously silently ignored, but the question remains whether this represents a true security issue that should fail or a Windows quirk that should be special-cased.

The thread shows how platform-specific behaviors can surface architectural tensions in security-sensitive code. While the original patch's security model (treating all stat failures as fatal) is conceptually clean, Windows' device file handling appears to require special consideration. Junio has removed the topic from his integration branches to unblock other development while awaiting Windows expertise to evaluate whether special-casing `nul` is viable or if alternative approaches can satisfy both security and portability requirements.
