This is the final patch in a series converting Git's oidmap cleanup mechanism to use explicit, type-safe callbacks. The patch updates the sequencer subsystem to use the new `oidmap_clear_with_free()` API for its string_entry maps, introducing a `free_string_entry()` helper that follows the same `container_of` pattern seen in previous conversions.

Junio C Hamano's review notes that while this change provides little immediate benefit (since the string entries are simple allocations), it follows the established pattern and would make future maintenance easier if the entries grow more complex resource ownership. The patch maintains the same high quality as the rest of the series, with minimal diffs and careful attention to maintaining behavior while improving the API contract.

With this patch, all four planned subsystem conversions are now submitted for review. Three have already been approved (rev-list, list-objects-filter, odb), leaving only Junio's question about the cmpfn check in the foundational API as the remaining open issue. The series demonstrates a consistent approach to making memory management more explicit while preserving backward compatibility.
