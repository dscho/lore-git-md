This is a technical discussion about the proposed `fetch.blobSizeLimit` config option for partial clones. Patrick Steinhardt raises concerns about making blob size limits the default due to server-side performance implications. He notes that size-based filters require expensive per-blob lookups that can't be optimized with existing caches like bitmaps, unlike `--filter=blob:none` which can be computed efficiently. 

Patrick suggests two key considerations: (1) whether a computationally cheaper filter like `blob:none` would be a better default, despite potentially requiring more backfill fetches, and (2) whether a global config is appropriate given that filter support varies by repository host. The discussion highlights the tradeoffs between discoverability and performance in partial clone configurations.

- Current inability to optimize size filters with bitmaps
- Potential need for host-specific rather than global configuration
