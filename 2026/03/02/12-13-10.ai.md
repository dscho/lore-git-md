This is part 6 of Patrick Steinhardt's 8-patch series introducing a new `git history split` subcommand, focusing on cache-tree infrastructure changes needed for the feature.

The patch modifies `write_in_core_index_as_tree()` to accept an arbitrary `struct index_state` parameter rather than always using the repository's main index. This allows callers to write temporary in-memory indexes as trees, which will be used by the upcoming split command implementation. The change is straightforward - the function signature is updated to take the index parameter, and the single caller in `builtin/checkout.c` is adjusted to pass `the_repository->index` explicitly.

This is a mechanical change that builds on the earlier refactoring work in patches 1-5, continuing the pattern of generalizing infrastructure to support the history editing operations. The patch maintains all existing behavior while adding the flexibility needed for the split command's workflow. Given Patrick's track record with architectural changes and the focused nature of this modification, it's likely to be uncontroversial.
