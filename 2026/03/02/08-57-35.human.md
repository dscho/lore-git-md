This is the first patch in Tian Yuchen's v4 series to migrate encoding-related globals to repository-specific storage, part of the ongoing `the_repository` removal effort. The patch plumbs a `struct repository*` parameter through commit creation APIs (`commit_tree()` and `commit_tree_extended()`) as preparation for later storing encoding information per-repository rather than globally.

The changes are mechanical but widespread, touching 13 files across commit handling, builtin commands (commit, merge, rebase, stash), and the sequencer. Each caller now passes either an explicit repository pointer or falls back to `the_repository` where needed (like in `notes_cache_write()`). The patch maintains existing behavior while setting up the plumbing for subsequent changes.

This appears to be a well-scoped preparatory change - it doesn't yet migrate the encoding state but enables that work by ensuring all commit creation paths have repository context available. The patch follows established patterns for `the_repository` removal and builds on Olamide Caleb Bello's `repo_config_values` infrastructure.
