This is a security patch in the ongoing series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). The patch delays the secure-by-default sanitization behavior until Git v3.0, maintaining backward compatibility while committing to future hardening.

The change modifies the default behavior to remain permissive (ALLOW_ALL_CONTROL_CHARACTERS) in current versions, only switching to the safer default (ALLOW_ANSI_COLOR_SEQUENCES) in Git 3.0 when compiled with WITH_BREAKING_CHANGES. This addresses concerns about changing defaults in a minor release while still providing a clear path to security hardening.

The implementation includes conditional compilation flags, updated documentation explaining the version-dependent behavior, and test prerequisite adjustments (TURN_ON_SANITIZING) to handle both current and future default modes. The patch preserves URL-specific configuration capabilities while removing the problematic 'default' configuration value that had caused earlier concerns.

This represents a compromise position in the security vs compatibility tradeoff, with Junio Hamano now signing off on the approach after earlier reservations about version-dependent behavior. The change has seen production validation in Git for Windows and Red Hat environments, suggesting the transitional period will be manageable for users.
