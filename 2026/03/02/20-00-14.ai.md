This is the second patch in a 5-part series refactoring Git's oidmap cleanup API, specifically converting `builtin/rev-list.c` to use the new `oidmap_clear_with_free()` function introduced in patch 1/5. The change focuses on the `missing_objects` map which stores `struct missing_objects_map_entry` instances containing path strings.

The patch introduces a new `free_missing_objects_entry()` callback that properly handles cleanup of both the path string and entry structure, replacing the previous manual cleanup that freed the string before calling `oidmap_clear()`. This version fixes a memory leak identified by Junio C Hamano in the initial submission by changing the path field from `const char*` to `char*` to allow proper freeing.

The change follows the series' pattern of making memory management more explicit and type-safe while maintaining identical behavior. The 15-line diff is focused and well-contained, with the new callback using the `container_of` pattern to safely access entries. Existing tests for rev-list continue to verify the behavior, though this particular change doesn't require new tests since the functionality remains the same - just implemented more cleanly.
