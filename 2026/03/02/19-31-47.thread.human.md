This thread documents Git's support for running external `git-*` executables found in PATH as if they were built-in commands. The discussion began with Omri Sarig proposing to add documentation for this long-standing but under-documented feature, which was previously only mentioned in passing in help text for `--list-cmds` and `--no-external-commands`.

Maintainer Junio Hamano agreed the behavior should be documented but suggested moving the explanation from a standalone section to the "Environment Variables > System" part of the documentation, where it would better fit alongside other PATH-related details. Omri revised the patch accordingly in v2, maintaining the same core content about the command lookup order (built-ins first, then external commands, then aliases) and argument passing behavior, while better integrating it with related documentation.

The thread shows clear consensus on documenting this functionality, with no technical objections raised. The purely additive patch makes Git's extensibility mechanism more discoverable for users who want to create their own `git-*` scripts, referencing the `execv_dashed_external()` function in git.c that has handled this behavior since at least Git 1.5.0.
