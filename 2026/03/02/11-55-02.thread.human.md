This thread addresses a CI pipeline failure on Windows where the `GITLAB_FEATURES` environment variable (6.3KB) causes the total environment size (17KB) to exceed POSIX argument length limits (12KB) when running xargs(1) from Git for Windows. Patrick Steinhardt proposed a minimal fix - unsetting `GITLAB_FEATURES` in `ci/lib.sh` when running under GitLab CI.

Justin Tobler has now joined the discussion, confirming Patrick's analysis that removing the variable would solve the immediate issue. However, Justin raises an interesting question about whether adjusting the system limits might be a better long-term solution than removing the variable. The patch remains small and focused (just 4 lines), specifically targeting the Windows CI environment without affecting other platforms.

The discussion is still in its early stages, with Patrick's initial solution on the table and Justin suggesting an alternative approach worth considering. Both agree on the root cause and that some change is needed to keep the Windows CI pipelines working reliably.
