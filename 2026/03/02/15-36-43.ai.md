This is a refactoring patch in Derrick Stolee's series improving environment handling for `git for-each-repo`. The series is now at v3, with this being patch 2/4.

The patch extracts a new `clear_local_repo_env()` helper from `prepare_other_repo_env()`, separating the logic that strips repository-specific environment variables from the part that sets GIT_DIR. This allows callers to use just the environment-clearing functionality when needed, such as when using `-C` to specify the repository location rather than GIT_DIR.

The change is mechanical but meaningful - it enables more flexible environment handling while maintaining the existing behavior. The new helper properly preserves GIT_CONFIG_* variables that need to propagate to child processes, addressing feedback point from earlier versions. The patch touches `run-command.[ch]` and follows Git's pattern of small, focused refactorings with clear documentation.

This continues the thread's theme of improving environment isolation for repository operations, with the implementation now more modular and better aligned with Git's existing patterns for environment handling. The change is well-motivated by the upcoming use case in patch 3/4, where the separation of concerns will be utilized.
