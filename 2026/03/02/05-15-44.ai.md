This is the second patch in a 6-part series introducing enhanced repository path reporting functionality. The series has evolved through multiple iterations, with this version focusing purely on path reporting after removing metrics-related components from earlier versions.

The patch adds category-based key expansion to the `repo info` command, allowing users to request groups of related paths with a single category name (e.g. "layout" expands to all "layout.*" keys). The implementation:

1. Introduces a new `print_category_fields()` helper that scans the predefined field table for keys matching the requested category prefix
2. Modifies the main field-printing logic to first try exact key matches, then fall back to category expansion
3. Maintains the existing error reporting when neither an exact key nor matching category is found

The change is mechanical and maintains backward compatibility - explicit key requests work exactly as before, while adding the new category expansion capability. The implementation handles the expansion by scanning the static `repo_info_fields` array at runtime, which keeps the category logic centralized rather than requiring per-category registration.

This builds on the `struct repo_info` plumbing introduced in patch 1 of the series, using it to provide the repository context needed for path resolution. The patch follows the series' overall goal of providing clean, future-proof access to repository locations while avoiding implementation-tied paths.
