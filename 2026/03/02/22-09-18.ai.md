This is a bugfix patch for submodule fetching behavior, addressing a long-standing issue where submodule operations incorrectly assumed the remote would always be named "origin". The patch implements a new submodule helper command `get-default-remote` to properly handle submodules with differently-named remotes, fixing cases where `git fetch --recurse-submodules` would fail.

The implementation maintains backward compatibility by falling back to "origin" if default remote detection fails. The patch includes comprehensive test coverage across multiple test files (t5526, t5572, and new tests in t7426) and addresses a 7-year-old NEEDSWORK comment from commit be76c21282. The solution handles real-world use cases like the "repo" tool's differently-named remotes.

The v4 iteration incorporates all feedback from previous rounds, including Junio Hamano's suggestions to remove parse_options() from the helper and fix test portability issues by using tags instead of branch names. Jacob Keller reconfirms the technical soundness of the approach with a fresh review tag, noting the significant test changes in this version. The patch is now ready for integration with all identified edge cases handled and all test validations passed.
