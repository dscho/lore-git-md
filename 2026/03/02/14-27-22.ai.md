Performance regression investigation in `receive-pack` with reftable backend.

Patrick Steinhardt confirms the separation of two distinct issues in the ongoing performance regression investigation. The current focus is specifically on the reftable-related slowdown in `receive-pack` operations, which bisects to commit fc148b146a ("receive-pack: convert update hooks to new API"). This shows a 2.66x performance degradation when handling 10,000 refs, with system time increasing from 89ms to 376ms.

Adrian Ratiu had initially suspected the regression might be related to an earlier hooks configuration series, but Patrick clarifies these are separate concerns. The issue appears specifically tied to the update hooks conversion path in the reftable backend, independent of configuration changes. Patrick provides instructions for reproducing the issue using standard development infrastructure and the hyperfine` benchmarking tool with the provided test scripts.

The email marks a narrowing of focus to the reftable-specific regression, with Adrian taking lead on investigating the interaction between the update hooks conversion and reftable performance. The geometric repacking issue mentioned in earlier messages is now understood to be a separate benchmarking artifact. This thread continues the technical investigation into why the hooks API conversion specifically impacts reftable performance.
