This is the first patch in Justin Tobler's v3 series for repository statistics in `git repo`, which has already been approved pending final polish. The patch refactors the object counting logic in `builtin/repo.c` to process statistics per-object rather than in bulk.

The change moves the statistics accumulation inside the object iteration, updating counts and sizes for each individual object as it's processed. This prepares for more granular statistics collection in later patches. The diff shows the mechanical transformation from batch processing (where totals were accumulated first and then applied to stats) to per-object updates.

Key technical details:
- Maintains the same statistics (type counts, inflated sizes, disk sizes) but updates them incrementally
- Preserves all existing type handling (tags, commits, trees, blobs) with the same switch statement structure
- Keeps the same error handling for invalid object types via BUG()
- The overall object counting behavior remains identical, just with finer-grained updates

This is a straightforward refactoring with no behavior change, serving as groundwork for the more substantive statistics additions in subsequent patches. The patch has already been reviewed and approved as part of the larger series, with discussion now focused on final polishing touches.
