This is patch 7/8 in Patrick Steinhardt's series introducing a new `git history split` command. The patch refactors commit creation logic in preparation for the actual split functionality.

The change extracts a new extended version of `commit_tree_with_edited_message()` that gives callers control over parents and trees, rather than deriving them from a single commit. The original function becomes a thin wrapper that maintains the existing behavior for rewording commits. This prepares for the split command which needs to create two commits with different trees and potentially different parents.

The refactoring is mechanical and well-contained, touching only `builtin/history.c`. It follows the pattern seen in earlier patches of the series - breaking down functionality into reusable components before implementing new features. Given Patrick's track record with the history command family and the careful preparation in previous patches, this change looks like a solid foundation for the split functionality to come in patch 8/8.
