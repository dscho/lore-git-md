This is a follow-up from the maintainer (Junio Hamano) regarding a Windows-specific regression in a security-sensitive bugfix series about `.git` directory validation. The series, originally from Tian Yuchen, was merged as v10 but had to be reverted due to test failures on Windows where `GIT_DIR=/dev/null` (or `nul` on Windows) now fatally errors when it was previously ignored.

Junio is calling for Windows platform experts to help diagnose why the patch breaks nearly all tests on Windows, particularly around the handling of the `nul` device file. The core tension is between maintaining strict validation (which treats all stat failures as fatal for security) and Windows portability (where `stat("nul")` fails in a way that now triggers these fatal errors). CI logs show the failure occurs when Git tries to read the Windows equivalent of `/dev/null`.

The thread is currently blocked awaiting Windows-specific expertise to evaluate whether special-casing `nul` is viable or if an alternative approach can satisfy both security and portability requirements. Junio has removed the topic from integration branches to unblock testing of other patches while this issue is resolved.
