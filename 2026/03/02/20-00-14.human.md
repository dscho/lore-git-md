This is the second patch in a 5-part series refactoring Git's oidmap cleanup API. The series replaces the boolean-flag based `oidmap_clear(map, 1)` with a new type-safe`oidmap_clear_with_free()` function that takes an explicit callback for memory cleanup.

This particular patch converts the `missing_objects` map in `builtin/rev-list.c` to use the new API. The map stores `missing_objects_map_entry` structs that contain dynamically allocated path strings. Previously, the code manually freed these paths before calling `oidmap_clear()`. The patch introduces a dedicated `free_missing_objects_entry()` callback that handles both the path and entry cleanup in one place, making the memory management more explicit and type-safe.

The change is straightforward - about 15 lines of new/changed code - and follows the pattern established in the series' first patch. This version fixes a memory leak identified by Junio C Hamano in the initial submission by properly freeing the path strings. The patch appears well-contained and maintains existing behavior while improving code organization.
