This is a follow-up in the performance regression investigation for the reftable backend's `update` hooks. Adrian Ratiu confirms Jeff King's root cause analysis of the 2.66x slowdown in `receive-pack` operations, which stems from unnecessary sideband muxer setup/teardown for each hook invocation even when no hook exists.

Ratiu indicates he has independently arrived at the same conclusion and is preparing a more comprehensive fix that will address the issue across all three affected hook types (not just the `update` hook that triggered the initial report). His upcoming patch will modify the hook infrastructure to avoid spinning up async threads when no hooks are present, eliminating the overhead entirely rather than just optimizing the sideband case.

The confirmation from Ratiu suggests this is now a well-understood issue with a clear path to resolution. His mention of fixing it in "3 places" implies the solution will be more thorough than the initial targeted fix proposed by Jeff King, potentially preventing similar performance issues in other hook contexts. This represents progress toward closing out the regression while maintaining the hook system's functionality.
