Documentation patch completing the repository path reporting series.

This is the final patch in Eslam Reda Ragheb's 6-part series adding structured repository path reporting to Git. The patch documents all the new path-related keys and categories introduced in the earlier patches, including:

- The new `--path-format` option for controlling absolute vs relative output
- All 10 path keys (`path.git-dir`, `path.toplevel`, etc)
- Category-based expansion (requesting `path` returns all path keys)
- The alias relationship between `path.toplevel` and `path.working-tree`

The documentation follows Git's standard man page format and provides clear examples of each key's output. It also notes edge cases like empty strings for bare repositories and submodule contexts. The patch completes the series by providing the user-facing documentation to match the implementation added in patches 1-5.

With this patch, the series appears complete - it has implementation, tests, and now thorough documentation. The only remaining open question from earlier discussion is whether `path.toplevel` should be the canonical name or if `path.working-tree` should take precedence, but that appears to be a minor naming issue rather than a blocker.
