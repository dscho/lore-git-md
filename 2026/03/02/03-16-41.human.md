This is a feature patch adding client certificate support to `git send-email`, enabling certificate-based SMTP authentication for security-sensitive environments. The patch introduces three new configuration options: `sendemail.smtpSSLClientCert` (for the client certificate file), `sendemail.smtpSSLClientKey` (for the private key), and corresponding command-line flags.

The implementation builds on Perl's IO::Socket::SSL capabilities while following established patterns in Git's SMTP configuration. It supports both PEM and PKCS12 certificate formats, accommodating real-world constraints from major email clients like Thunderbird and K-9 Mail. The patch carefully handles edge cases like missing key files and provides clear error messages for misconfigurations.

Maintainer Junio C Hamano has already validated the technical approach, and the implementation now follows RFC 8446 requirements by removing explicit control over certificate presentation. The patch appears well-tested and ready for merging once the documentation (which is included) meets maintainer standards. This fills an important gap in Git's email workflow for organizations requiring mutual TLS authentication.
