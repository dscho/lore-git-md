This is the fourth patch in Patrick Steinhardt's series introducing a new `git history split` subcommand. The patch extends the add-patch infrastructure to support applying changes to an in-memory index rather than just the repository's main index.

The key addition is a new `run_add_p_index()` function that allows callers to specify a custom index state and index file location. This builds on the refactoring done in earlier patches to separate the add-patch machinery from interactive add specifics. The implementation shares most of its logic with the existing `run_add_p()` via a new `run_add_p_common()` helper.

The patch is a technical prerequisite for the actual split functionality that will come in later patches. It touches the add-patch subsystem and prepares it to work with temporary in-memory indexes during history editing operations. The changes are focused and well-contained, following the pattern of earlier patches in the series.

Given Patrick's role as a core contributor and the careful preparation shown in this series so far, this infrastructure work is likely to be uncontroversial. The patch maintains all existing functionality while adding the new capability needed for the history split feature.
