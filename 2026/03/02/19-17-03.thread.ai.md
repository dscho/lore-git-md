Thread identity: Performance fix for hook subsystem in `git-receive-pack`, addressing regression in sideband hook handling from hook API conversion. Patch series by Adrian Ratiu, with problem identification by Patrick Steinhardt and root cause analysis by Jeff King.

Core problem: Hook API conversion removed optimization where sideband hooks would exit early if no hook existed, causing unnecessary overhead from spinning up async threads. Affects `builtin/receive-pack.c` specifically in three hook-related paths (`run_receive_hook`, `run_update_hook`, `run_update_post_hook`).

Current status: Patch v1 submitted and improved by Junio C Hamano, adding back early-exit checks using new hook API's `hook_exists()` function. Junio suggested consolidating hardcoded hook name strings into static constants ("update" and "post-update") for better maintainability. Patrick Steinhardt's benchmarks confirm the fix restores performance to pre-regression levels, showing 2.7x speedup for `receive-pack` operations with 10,000 refs. Junio indicates he will queue the patch with his improvement squashed in.

Key technical details:
- Restores optimization in `builtin/receive-pack.c` for sideband hooks
- Uses new hook API's `hook_exists()` to check both config-defined and traditional hookdir hooks
- Now uses static const char arrays for hook names instead of literals
- Specifically modifies three hook execution paths that were missing the check
- Performance impact most noticeable with large numbers of refs (2.7x speedup at 10k refs)
