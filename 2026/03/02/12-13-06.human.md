This is a refactoring patch from Patrick Steinhardt, part of an 8-patch series introducing a new `git history split` subcommand. The series builds on the experimental `git-history` command family.

The patch disentangles the interactive add-patch machinery by splitting out common configuration options into a new `struct interactive_options`. This addresses confusion around the current design where `struct add_p_opt` is reused across subsystems but ultimately initializes a `struct add_i_state` that serves both. The change moves color configuration, diff settings, and other interactive options into dedicated structures.

The refactoring is mechanical but thorough, touching 10 files with 290 lines added and 258 removed. It doesn't yet fully separate the subsystems (a follow-up patch will handle that), but establishes clearer boundaries. The patch maintains all existing functionality while making the codebase more maintainable.

Given Patrick's role driving architectural changes in Git and the careful structuring of this series, this foundational refactoring is likely to be well-received. The changes are focused and don't introduce new behavior, making them relatively low-risk despite touching multiple commands (`add`, `commit`, `stash`, etc.).
