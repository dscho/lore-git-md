This is part 5/8 of Patrick Steinhardt's series introducing a new `git history split` command, which follows earlier refactoring of the add-patch infrastructure in patches 1-4.

The patch adds a new flag `ADD_P_DISALLOW_EDIT` to disable hunk editing in the interactive patch interface. This is needed because the upcoming `git history split` command will use the add-patch machinery but needs to prevent users from editing hunks directly - the command's splitting logic requires maintaining tree consistency between the two resulting commits.

The change adds the flag through the full call chain from `run_add_p()` down to the hunk processing logic, updating all existing callers to pass 0 (maintaining current behavior). The implementation is straightforward - it touches several files to thread the new parameter through, but the core change is a simple condition in `patch_update_file()` that skips adding the 'e' (edit) option when the flag is set.

This continues the careful preparation for the actual split command implementation, which will follow in later patches. The series is shaping up to be a well-structured architectural change, with each patch building logically on the previous ones.
