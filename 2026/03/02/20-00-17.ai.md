This is the final patch in a 5-part series refactoring Git's oidmap cleanup API, converting the sequencer subsystem to use the new callback-based approach. The series replaces the old `oidmap_clear(map, 1)` pattern with explicit `oidmap_clear_with_free()` calls that take a type-safe callback function.

The patch introduces a `free_string_entry()` helper that properly frees `struct string_entry` objects using the `container_of` pattern to safely access the containing structure. It then updates two oidmap cleanup sites in the sequencer code to use this new callback instead of the old boolean flag approach. The changes are minimal (8 lines added, 2 removed) and follow the same pattern established in previous patches of the series.

This completes the migration across all Git subsystems that were using the old oidmap cleanup API. The series as a whole improves type safety and makes memory management more explicit while maintaining identical behavior. The implementation is careful to use `container_of` for safe structure access without making assumptions. Existing sequencer tests continue to verify the behavior remains correct.

The patch series has already addressed feedback from Junio C Hamano about a memory leak in an earlier version, and this final piece appears ready for merging as part of the overall API improvement effort.
