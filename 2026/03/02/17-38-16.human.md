This is a discussion about potential enhancements to Justin Tobler's repository statistics series, specifically around commit size metrics.

Lucas Seiki Oshiro suggests expanding the "largest objects" reporting to include commits with the most changed lines (similar to GitLab's interface) rather than just tracking commit object sizes. Justin responds that while this would be interesting, it would require expensive on-the-fly computation since this data isn't stored in the repository, and may not fit the scope of the `git repo` command which focuses on repository structure statistics.

The exchange shows thoughtful consideration of feature scope versus performance impact. Justin maintains the series' focus on efficiently computable structural metrics while acknowledging the validity of the use case Lucas raises. This appears to be a constructive side discussion rather than a blocking issue for the already-approved series.
