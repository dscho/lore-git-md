This thread investigates a performance regression in `receive-pack` operations when using Git's reftable backend, initially reported by Patrick Steinhardt. Benchmarking showed a 2.66x slowdown (89ms to 376ms system time) when handling 10,000 refs, which was bisected to a recent hooks API modernization commit. Jeff King (Peff) identified the root cause: unnecessary sideband muxer setup and teardown for all hook invocations, even when no hooks exist.

Adrian Ratiu has taken the lead on implementing a comprehensive fix that will modify the hook infrastructure to skip async thread creation when no hooks are present, addressing the issue for all three hook types (update, pre-receive, and post-receive). Junio has acknowledged the quick progress, indicating the fix is likely to be accepted. The regression is specific to the reftable backend and doesn't affect the traditional ref storage. While the immediate performance impact is being addressed, the discussion has also highlighted the need for better benchmarking infrastructure to catch similar issues earlier in development.
