This thread investigates two initially conflated performance regressions in Git's `receive-pack` and `fetch` operations. The discussion has now separated into distinct tracks. 

The primary focus is a 2.66x slowdown in `receive-pack` operations when using the reftable backend with 10,000 refs, where system time jumps from 89ms to 376ms. Patrick Steinhardt bisected this to commit fc148b146a ("receive-pack: convert update hooks to new API"). While Adrian Ratiu initially suspected an interaction with earlier hooks configuration changes, Patrick has confirmed this is a separate issue specific to the update hooks conversion path in the reftable backend. Adrian is now leading the investigation into why this API change specifically impacts reftable performance.

A second issue involving geometric repacking during fetch operations was initially reported alongside the reftable regression, but has since been identified as a benchmarking artifact rather than a true regression. The team now recognizes the need to adjust benchmarking infrastructure to properly isolate maintenance-related effects during performance measurements. 

Junio Hamano is monitoring both threads but has not yet intervened. The discussion continues to focus on understanding and resolving the reftable-specific regression, with Patrick providing reproduction instructions using the `hyperfine` benchmarking tool to help others investigate.
