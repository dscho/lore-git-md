This thread introduces a new `git history split` subcommand, part of Patrick Steinhardt's ongoing work on the experimental `git-history` command family. The command allows splitting commits while maintaining tree consistency, with careful design choices to avoid common pitfalls - it prompts for both resulting commit messages (not just the first) and avoids hunk editing to prevent tree conflicts. The 8-patch series includes substantial refactoring of the add-patch infrastructure and implements thorough test coverage (755 lines of new tests).

The discussion has been relatively quiet, with only minor feedback from D. Ben Knoble about empty split behavior (erroring vs being a silent no-op) and a brief question from Junio Hamano about naming that was quickly resolved. Both Patrick and Junio now agree the series is technically ready, with no remaining blockers. The empty split behavior could potentially be adjusted later via a `--allow-empty` option if needed, but this isn't holding up integration. Given Patrick's strong track record with architectural changes and the lack of substantive objections, this feature is expected to be included in an upcoming release.
