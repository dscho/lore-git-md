This is a technical discussion about path formatting options in the `git repo-info` command, part of an ongoing series to add path-related fields.

Tian Yuchen proposes an alternative to the current global `--path-format` flag approach, suggesting instead using format modifiers like `(%path:relative)` and `(%path:absolute)` that could be specified per-field. This would allow mixed-format output without requiring multiple command invocations, addressing a limitation of the current design where path format applies globally to all fields.

The suggestion comes in response to Junio C Hamano's observation that while `git rev-parse` allows per-option format control (which can be confusing), the simpler `repo-info` interface intentionally gives up this flexibility for clarity. Yuchen's proposal attempts to regain some of that flexibility while maintaining readability.

This represents a new consideration in the thread's ongoing discussion about balancing interface simplicity with functionality. The core design decision to prioritize maintainability over `rev-parse`-style flexibility had previously been confirmed by the maintainer, but Yuchen is exploring whether a middle ground exists through field-specific modifiers rather than global flags.
