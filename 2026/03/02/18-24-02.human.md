Performance optimization confirmation for duplicate option validation.

Jeff King follows up on René Scharfe's performance measurements for the duplicate option name validation patch series. The discussion focuses on benchmarking results across different architectures, with René's Apple M1 showing different characteristics than Jeff's Intel i9 system. 

Key observations from the exchange:
- The strset implementation adds about 5ms (7% overhead) to help output generation on René's M1 (77.5ms baseline -> 82.6ms)
- Jeff's proposed sorted-array alternative actually performs worse on the M1 (85.6ms) despite showing better results on his Intel system
- Absolute timing differences between architectures are significant (4x slower on M1) but the relative cost of validation remains small
- Both agree the overhead is acceptable since validation only runs during help display, not normal command execution

This confirms the strset approach is the right choice across platforms, wrapping up the performance analysis for this series. The thread shows how Git contributors carefully validate optimizations across different hardware configurations before settling on an implementation.
