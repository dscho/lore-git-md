[Security] Junio Hamano removes the problematic 'default' configuration option from the sideband control character sanitization feature. This patch is part of the ongoing effort to secure Git's sideband channel against ANSI escape sequence injection (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329).

The change eliminates a design flaw where the 'default' setting would have changed behavior across Git versions, undermining the purpose of explicit configuration. The patch removes both the documentation and implementation of this option, simplifying the configuration to explicit choices ('color', 'cursor', 'erase', or 'all') without any version-dependent behavior. This aligns with Junio's earlier concerns about maintaining stable configuration semantics.

The implementation removes the `ALLOW_DEFAULT_ANSI_SEQUENCES` bitmask flag (which was equivalent to `ALLOW_ANSI_COLOR_SEQUENCES`) and updates the parsing logic in `sideband.c` to skip the now-removed 'default' option. The documentation in `Documentation/config/sideband.adoc` is correspondingly simplified.

This change represents a resolution to one of the key points of contention in the thread, where Junio had objected to version-dependent defaults. The patch follows through on his earlier feedback and clears the way for the security feature to proceed to broader testing in the `next` branch. The removal of this configuration option makes the behavior more predictable and maintainable while preserving the core security protections against terminal state corruption and input buffer injection attacks.
