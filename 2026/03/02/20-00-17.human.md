This is the final patch in a 5-part series refactoring Git's oidmap cleanup API to use explicit callback-based memory management rather than boolean flags. The series converts various subsystems to use the new `oidmap_clear_with_free()` function introduced in patch 1.

The current change updates the sequencer subsystem to properly clean up `string_entry` structures in two oidmaps (`commit2todo` and `commit2label`). It introduces a new `free_string_entry()` helper that uses the `container_of` pattern (consistent with the rest of the series) to safely free each entry. The 10-line diff replaces two `oidmap_clear(..., 1)` calls with the new callback-based version.

This is a clean, focused change that completes the series' goal of making memory cleanup explicit and type-safe. Like the previous patches, it maintains existing behavior while improving the API contract. The series has already addressed Junio C Hamano's feedback about a memory leak in the rev-list conversion (patch 2), and this final piece follows the same careful pattern. The change is well-contained and unlikely to be controversial.
