This is a performance regression fix targeting the hooks infrastructure, specifically addressing a slowdown in `receive-pack` operations with the reftable backend.

The thread has progressed from initial benchmarking by Patrick Steinhardt (showing a 2.66x slowdown) through root cause analysis by Jeff King, to Adrian Ratiu now preparing a comprehensive fix. The issue stems from unnecessary sideband muxer setup/teardown for hook invocations, even when no hooks exist - particularly problematic for the update hook which runs per-ref. Ratiu confirms the problem affects all three hook types (update, pre-receive, post-receive) and is preparing a systematic solution rather than case-by-case optimizations.

Junio's brief response serves as an acknowledgment of the quick progress, signaling the fix is on track for inclusion. The regression is reftable-specific and unrelated to earlier configuration or repacking issues. Ratiu's upcoming patch will modify the hook infrastructure to skip async thread creation when no hooks exist, which should restore performance while maintaining the modernized hook API introduced in fc148b146a.
