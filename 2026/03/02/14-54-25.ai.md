This is a bugfix for the histogram diff algorithm (XDF_HISTOGRAM_DIFF) in xdiff, addressing an edge case where shifted change groups during compaction produce redundant diff output containing matching lines from both files. The patch comes from Yee Cheng Chin as version 2, incorporating feedback from Junio Hamano and Phillip Wood.

The issue occurs when the compaction phase (xdl_change_compact()) shifts and merges change groups, potentially creating new matching groups where both sides now have identical lines. This results in diff output that appears redundant to human readers. The fix detects this situation and re-diffs the affected sections using Myer's algorithm via xdl_fall_back_diff(), while preserving all original diff flags (including --ignore-all-space handling).

The patch includes comprehensive test coverage in t/t4074-diff-shifted-matched-group.sh, demonstrating both triggering scenarios: case #1 (no further shifting needed but previous shifts may have occurred) and case #2 (where slide-up shifting remains). The tests also verify that diff flags are properly preserved during re-diffing.

Changes since v1 include:
- Simplified entry condition checking for go.end!=go.start
- Removed redundant go_orig tracking
- Used assignment instead of memcpy()
- Improved comments and test case naming
- Added test for case where no shifting was possible but previous shifts occurred

The solution is technically sound and ready for merging, having addressed all substantive technical concerns with consensus on the approach. The commit message provides clear motivation with both synthetic and real-world examples showing how this affects <1% of diffs but fixes clearly undesirable output when it occurs.
