This is a performance discussion about the proposed `fetch.blobSizeLimit` config option for partial clones. Jeff King (Peff) responds to Patrick Steinhardt's concerns about server-side performance with size-based filters, clarifying that bitmap optimizations do in fact work for blob size limits (contrary to Patrick's initial assumption). However, he shares Patrick's broader concern about enabling partial clones by default, noting there may still be unaddressed performance and correctness issues with the feature.

The exchange highlights an important technical nuance - while size-based filters are more expensive than type-based ones (`blob:none`), the difference isn't as severe as Patrick thought due to existing bitmap support. Both maintainers seem aligned that making partial clones the default via this config may be premature, though for slightly different technical reasons. The thread continues to explore the tradeoffs between discoverability and performance in partial clone configuration.
