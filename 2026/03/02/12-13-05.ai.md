Refactoring patch that splits the add-patch declarations from add-interactive.h into a new add-patch.h header. This is the first in an 8-part series introducing a new `git history split` command.

The change moves all add-patch related declarations (struct add_p_opt, enum add_p_mode, and run_add_p function) into the new header while keeping the add-interactive specific parts in the original file. The motivation is to better separate concerns between the two subsystems and make code boundaries clearer.

This is a mechanical refactoring with no behavior changes - it just reorganizes code in preparation for later patches in the series that will build on the add-patch infrastructure. The patch touches three files: creates add-patch.h, removes declarations from add-interactive.h, and adds the new header to add-patch.c.

As the first patch in a series from Patrick Steinhardt (a core contributor driving the git-history command family), this sets up infrastructure needed by subsequent patches. The change follows Git's coding style and appears straightforward, though reviewers may want to verify the header split makes logical sense for the subsystems involved.
