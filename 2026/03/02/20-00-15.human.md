This is part 3 of a 5-patch series refactoring Git's oidmap cleanup API to make memory management more explicit. The series replaces the old `oidmap_clear(map, 1)` pattern with a new `oidmap_clear_with_free()` function that takes an explicit callback for freeing entries.

This particular patch updates the list-objects-filter subsystem to use the new API for cleaning up its `seen_at_depth` oidmap. The map stores heap-allocated `struct seen_map_entry` objects. The patch introduces a new `free_seen_map_entry()` helper that properly frees these entries using the `container_of` pattern to safely access the full structure.

The change is straightforward - just 9 lines of code that replace one function call with another while maintaining identical behavior. The patch follows the same pattern established in earlier parts of the series, applying the new API consistently across the codebase. It's a clean, focused change that improves type safety and makes memory management more explicit without introducing any new behavior.
