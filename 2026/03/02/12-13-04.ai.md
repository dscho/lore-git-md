This is a cover letter for a feature patch series introducing a new `git history split` subcommand, part of Patrick Steinhardt's ongoing `git-history` effort. The series builds on previous discussions to implement commit splitting with specific design choices: it prompts for commit messages for both resulting commits (not just the first), avoids hunk editing (preventing conflicts by keeping the second commit's tree matching the original), and updates dependent branches like the recent `git history reword` command.

The 8-patch series refactors several underlying components to support this functionality:
- Extracts and generalizes parts of the add-patch machinery to work with in-memory indexes
- Adds capability to write in-memory indexes as trees
- Implements the actual split command in `builtin/history.c`

The implementation touches multiple subsystems (add-patch, cache-tree, history) and includes extensive test suite (755 lines of new tests). Given Patrick's track record with architectural changes and the thorough test coverage, this appears to be a well-considered addition to the experimental history command family. The patch structure suggests careful separation of preparatory refactoring from the feature implementation itself.
