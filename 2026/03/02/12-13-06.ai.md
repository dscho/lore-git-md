This is the second patch in Patrick Steinhardt's 8-part series introducing a new `git history split` subcommand. The patch refactors the interactive add-patch machinery to better separate concerns between `git add -p` and `git add -i`.

The change introduces a new `struct interactive_options` to hold configuration shared between both commands, moving it out of the previous `struct add_p_opt`. This clarifies which options apply to which parts of the code. The patch also relocates color and configuration handling into a new `interactive_config` struct with dedicated init/clear functions.

The refactoring touches several files that use the interactive add machinery, including `builtin/add.c`, `builtin/commit.c`, and `builtin/stash.c`, updating them to use the new structure. While this patch doesn't fully decouple the subsystems (that's left for a follow-up), it makes the codebase more maintainable by reducing circular dependencies.

This is a mechanical change that prepares for the actual `git history split` functionality in later patches. The changes are thorough and consistent, with 10 files modified and around 500 lines changed (mostly deletions from moving code to the new location). As part of a larger series from a core contributor, this refactoring is likely to be well-received, though reviewers may want to verify the changes don't break any edge cases in the add-patch workflow.
