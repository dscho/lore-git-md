This is patch 3/6 in Justin Tobler's series adding repository statistics to `git repo`. The patch focuses on tracking the largest objects in the repository by type (commits, trees, blobs, and tags).

The key addition is a new `largest_objects` struct that records both the size and OID of the largest object encountered for each type. A new `check_largest()` helper function updates these records during object iteration. The statistics are displayed in both the default table format (showing just sizes) and the keyvalue format (showing both sizes and OIDs).

The implementation handles edge cases like empty repositories through careful initialization of the largest objects tracking. The patch includes corresponding test updates in t1901 to verify the new output formats work correctly with both empty and populated repositories.

This is a well-contained addition to the series that builds logically on the previous object counting infrastructure. The code is cleanly structured with appropriate helper functions (`print_object_data` and `check_largest`) to avoid duplication. The tests provide good coverage of both the happy path and edge cases.

The patch maintains the series' focus on providing useful repository metrics without introducing expensive operations - the largest object tracking adds minimal overhead to the existing object iteration. It's a straightforward but valuable addition that helps users identify potential repository size outliers.
