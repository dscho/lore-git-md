This is a maintainer intervention in the proposed `git repo info` feature discussion. Junio C Hamano steps in to express concern about the coordination of efforts around adding path-related fields to the new command's output.

The thread had seen Pushkar Singh and Patrick Steinhardt collaborating on adding structured path output (`path.git-dir` and `path.common-dir`) as an alternative to `git rev-parse`, building on Lucas Skeggs' earlier format/keys work. While the technical implementation was uncontroversial (using existing path APIs), Lucas Seiki Oshiro raised procedural concerns about whether the base `git repo info` command would even be accepted.

Junio's brief response highlights two key issues: First, he notes the apparent lack of coordination among contributors working on similar path-related additions. Second, his phrasing ("many people stomping on each others' toes") suggests he's observing multiple parallel efforts to extend this not-yet-accepted command, which risks fragmentation. His intervention effectively puts the broader discussion on hold until the fundamental question of whether `git repo info` belongs in Git is resolved.

This maintains the project's typical conservative approach to new commands - Junio is signaling that foundational additions need clear consensus before extensions are considered. The patch series remains in limbo, with both its technical merits and the command's future now awaiting maintainer guidance.
