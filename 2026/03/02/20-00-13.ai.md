This is a refactoring patch that changes how oidmap handles memory cleanup, making it more explicit and type-safe. It introduces a new `oidmap_clear_with_free()` function that takes a callback for freeing entries, replacing the old boolean-flag approach in `oidmap_clear()`. The patch includes comprehensive unit tests verifying both the callback and no-callback cases.

The change removes reliance on struct layout assumptions in the hashmap implementation while maintaining the same functionality. The new API is more explicit about ownership semantics - when entries should be freed and by what mechanism. The implementation carefully iterates through entries and uses the `container_of` pattern to safely access them.

Test coverage is thorough, with two new test cases in t/unit-tests/u-oidmap.c that verify the callback is called when provided and skipped when not. The patch maintains backward compatibility by keeping the original `oidmap_clear()` as a wrapper that passes either `free()` or NULL to the new function.
