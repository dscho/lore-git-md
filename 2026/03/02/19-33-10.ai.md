This is a documentation patch that concludes the investigation into the behavior of `git fetch --jobs=0` and `fetch.parallel=0`. The thread has established that since d54dea77dba (2019-10-05), these settings consistently fall back to using `online_cpus()` (available CPU count) when set to 0, though this was only mentioned in Git 2.40.0 release notes and not in the main documentation.

Johannes Schindelin's research confirms there was no recorded discussion or intentional rationale for keeping this behavior undocumented, resolving the final open question. The implementation history traces back to 2015 when "some reasonable default" phrasing first appeared in submodule parallel fetching, later adopted for the general fetch case in 2019.

Junio C Hamano notes the original vague documentation may have been deliberate, while also suggesting `--jobs=auto` might be a clearer name for this behavior in the future. The discussion has reached consensus on documenting the current CPU-counting behavior, with all historical context now accounted for. This non-controversial change is ready for finalization, having addressed both the immediate documentation gap and broader questions about the interface's evolution. The patch affects Documentation/fetch-options.adoc and Documentation/config.txt, bringing them in line with the stable implementation that has existed since 2019.
