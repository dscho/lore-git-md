This is a performance bugfix for the hook subsystem in `git-receive-pack`, addressing a regression introduced during the recent hook API work. The patch restores an optimization that was accidentally lost when converting to the new hook API - checking for hook existence before spinning up async threads for sideband hooks.

The issue was identified by Patrick Steinhardt and root-caused by Jeff King, showing that the missing early-exit check was causing unnecessary overhead from creating async threads that would do nothing when no hooks were present. Adrian Ratiu's fix adds back the `hook_exists()` checks in three hook-related functions in `builtin/receive-pack.c` (`run_receive_hook`, `run_update_hook`, and `run_update_post_hook`), using the new hook API that properly handles both config-defined hooks and traditional hookdir hooks.

The impact is measurable in the receive-refs benchmark, particularly with large numbers of refs. The change is small (9 lines added) and focused, with clear test coverage showing it fixes the regression. This is part of the ongoing hook subsystem improvements following the recent API conversion.
