This is a feature patch adding client certificate support to `git send-email`, addressing feedback from maintainer Junio C Hamano. The patch follows up on earlier discussion about proper TLS client certificate behavior and removes some implementation details that could be problematic.

The updated version simplifies the approach by removing explicit control over when certificates are presented (`SSL_use_cert` flag) and instead relies on the underlying SSL library to handle certificate presentation according to RFC 8446 requirements. The author notes this better aligns with the standard's requirement that clients only send certificates when explicitly requested by the server.

The patch maintains support for both PEM and PKCS12 certificate formats, which was a point of discussion in the previous round. The author has removed some defensive code around format handling, reasoning that this behavior should be documented rather than hardcoded, as SSL library implementations could change. The documentation additions explain the certificate options and their usage.

From a technical perspective, this adds three new configuration options: `sendemail.smtpSSLClientCert` (accepting PEM or PKCS12), `sendemail.smtpSSLClientKey` (PEM only), and corresponding command-line flags. The implementation builds on Perl's IO::Socket::SSL capabilities while maintaining compatibility with existing SMTP authentication methods.

The patch appears ready for merging pending final documentation review. Junio had previously validated the technical approach and the author has addressed the remaining feedback about clarifying the security motivations and certificate handling behaviors in the documentation. This represents the final iteration of a well-scoped feature addition that has gone through thorough review.
