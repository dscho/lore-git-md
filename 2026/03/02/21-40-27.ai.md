This is a performance fix for the hook subsystem in `git-receive-pack`, addressing a regression in sideband hook handling. The patch series by Adrian Ratiu restores an optimization that was lost during the hook API conversion, where sideband hooks would unnecessarily spin up async threads even when no hook existed.

Junio C Hamano provides a minor but important improvement to the patch - suggesting the consolidation of hardcoded hook name strings into static constants. This makes the code more maintainable by ensuring the hook names are defined in one place per function. The change affects three hook execution paths in `builtin/receive-pack.c` (`run_receive_hook`, `run_update_hook`, and `run_update_post_hook`), where the early-exit check using `hook_exists()` is being added back.

The technical change is straightforward: introducing `static const char hook_name[]` constants for "update" and "post-update" hooks, then using these constants consistently in both the existence check and the actual hook execution. This maintains the performance optimization while improving code quality. Junio indicates he will queue the patch with this improvement squashed in.

This follows the thread's established context where Patrick Steinhardt identified the performance regression, Jeff King root-caused it to missing early-exit checks, and Adrian Ratiu implemented the fix using the new hook API's capabilities. The change has already passed CI testing and shows measurable performance improvements in receive-refs benchmarks.
