This is a refactoring patch that splits header declarations from the add-patch subsystem out of add-interactive.h into a new add-patch.h header. It's the first in an 8-part series introducing a new `git history split` command.

Patrick Steinhardt notes that while the code was already logically separated between add-patch.c and add-interactive.c, the declarations were all in add-interactive.h, making the boundaries unclear. The patch moves add-patch specific declarations (struct add_p_opt, enum add_p_mode, and run_add_p function) to the new header while keeping add-interactive specific ones in the original file.

This is a straightforward code organization change with no behavior modifications. The patch is cleanly separated - it touches only header files and adds the necessary include in add-patch.c. As the first in a series, it sets up cleaner boundaries for subsequent patches that will build on this infrastructure to implement the new history splitting functionality.
