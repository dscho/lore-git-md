This is a refactoring patch that's part of the ongoing `the_repository` removal effort, specifically targeting commit creation APIs. It's the first in a 3-patch series by Tian Yuchen to migrate encoding-related functionality from global variables to repository-specific storage.

The patch updates `commit_tree()` and `commit_tree_extended()` to take a `struct repository*` parameter, plumbing it through 13 files that call these functions. The changes are mechanical - each caller now passes either an explicit repository pointer or falls back to `the_repository` where needed (like in `notes_cache_write()`). The patch maintains existing behavior while preparing for subsequent changes that will move encoding state into repository-specific storage.

Key technical details for future reference:
- Adds `struct repository*` parameter to both commit creation functions
- Updates call sites across builtins (commit, merge, rebase, stash) and core code
- Falls back to `the_repository` for unconverted subsystems
- Part of larger effort to use Olamide Caleb Bello's `repo_config_values` infrastructure
- Touches commit creation path but doesn't yet change behavior
- Follows established patterns for global variable migration

The patch appears well-scoped and follows the project's typical approach for this type of refactoring. It's a preparatory step for the actual encoding state migration that will come in later patches.
