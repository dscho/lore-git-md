CI/build system patch addressing Windows CI pipeline issue with large environment variables.

Justin Tobler replies to Patrick Steinhardt's patch about a GitLab CI pipeline failure on Windows. The root cause is that the `GITLAB_FEATURES` environment variable (6.3KB) causes the total environment size (17KB) to exceed POSIX argument length limits (12KB) when running xargs(1) from Git for Windows, triggering an assertion failure. 

Justin confirms Patrick's analysis that unsetting `GITLAB_FEATURES` would reduce the environment size below the limit, and asks whether the limit itself could be increased rather than removing the variable. The patch itself is minimal - just 4 lines added to `ci/lib.sh` to unset the problematic variable when running under GitLab CI.

This appears to be a straightforward fix for a specific CI infrastructure issue, though Justin's question about alternative solutions suggests there might be room for discussion about whether removing the variable is the best approach versus adjusting system limits. The change is narrowly scoped to the Windows CI environment and doesn't appear to affect other platforms or Git's core functionality.
