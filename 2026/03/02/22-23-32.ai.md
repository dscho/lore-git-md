This is a review response from the maintainer (Junio C Hamano) on the oidmap cleanup series. He's commenting on the first patch which introduces the new callback-based API for oidmap clearing.

Junio notes that the typedef for the free callback is properly compatible with both NULL and the standard `free()` function. This appears to be a subtle behavior change that wasn't explained in the commit message.

He confirms that the patch successfully removes the struct layout dependency through use of `container_of()`, which was a TODO item in the original code. The implementation follows the expected pattern of iterating through entries and invoking the callback when provided, then clearing the underlying hashmap.

The review is generally positive but raises one important question about the cmpfn check that the author will need to address - either by justifying the change or removing it if unnecessary.
