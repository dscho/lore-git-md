Junio Hamano reviews Adrian Ratiu's patch that restores an optimization for sideband hook handling in `git-receive-pack`, which was lost during the hook API conversion. The original patch added early-exit checks using `hook_exists()` to avoid spinning up unnecessary threads when no hooks are present.

Junio suggests a small but meaningful improvement: consolidating the hardcoded hook names ("update" and "post-update") into static constants within their respective functions. He provides the exact diff to make this change and indicates he will queue the patch with this modification squashed in. This is a typical maintainer polish pass - catching a minor code quality issue that doesn't affect functionality but improves maintainability.

The change is straightforward and uncontroversial, addressing a performance regression that was already well-analyzed in the thread. Junio's involvement at this stage signals the patch is likely to be merged soon. The optimization particularly benefits cases with many ref updates where hooks aren't configured, avoiding the overhead of thread creation for non-existent hooks.
