This is a feature patch series focused on improving repository path reporting in `git repo info`. The series has been significantly refined from previous versions based on review feedback, now focusing solely on path-related functionality after splitting out metrics features into a separate effort.

The key changes in v6 include:
- A new `--path-format` option to control whether paths are output as absolute or relative
- Simplified path key naming (`path.prefix` instead of `path.git-prefix`)
- Added `path.working-tree` as an alias for `path.toplevel`
- Removed several implementation-tied path keys that reviewers felt were too specific (`logs-directory`, `packed-refs-file`, `refs-directory`, `shallow-file`)
- Better handling of bare repositories (returning values rather than errors for work-tree paths)
- Cleaner commit history with context plumbing and category expansion split into separate commits

The series introduces 10 path-related fields that provide programmatic access to common repository locations like the git directory, working tree, objects directory, and more. The implementation uses a new `repo_info` context to handle path resolution consistently.

Reviewers had previously raised concerns about exposing paths that might change with future ODB abstraction work, which the author has addressed by removing the most implementation-specific paths. The current version focuses on stable, high-level paths that scripts would commonly need to reference.

The patch appears well-tested with 194 lines of new test coverage validating all path keys against equivalent `rev-parse` invocations. Documentation has been updated to describe the new functionality.

This represents a more focused iteration of the original proposal, having incorporated feedback from Junio Hamano and Phillip Wood about naming, scope, and future compatibility. The changes suggest the author is responsive to review input while maintaining the core value proposition of the feature.
