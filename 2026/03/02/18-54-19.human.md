This is a performance regression fix targeting the hooks infrastructure, specifically addressing a slowdown in `receive-pack` operations when using the reftable backend. The issue was originally reported by Patrick Steinhardt, who observed a 2.66x slowdown when handling 10k refs (89ms to 376ms system time). Jeff King (Peff) identified the root cause - unnecessary sideband muxer setup/teardown for all hook invocations, even when no hook exists.

Adrian Ratiu has confirmed the analysis and is preparing a comprehensive fix that will address this issue across all three affected hook types (update, pre-receive, and post-receive). The fix will modify the hook infrastructure to skip async thread creation when no hooks exist, providing a systematic solution rather than case-by-case optimization. 

Junio C Hamano has acknowledged the quick response to the problem but is waiting for Ratiu's complete patch before proceeding. The regression is reftable-specific and doesn't affect the traditional ref backend. This appears to be a well-understood issue with a clear path to resolution, and the fix should significantly improve performance for users of the reftable backend.
