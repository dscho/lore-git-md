This is a follow-up discussion in the thread about adding a `fetch.blobSizeLimit` config option for partial clones. The author, Alan Braithwaite, responds to feedback from Patrick Steinhardt, Jeff King, and Junio Hamano.

Key points in this email:
- Clarifies the config would be opt-in, not a default behavior
- Confirms bitmap support works with blob size limits (contrary to initial concerns)
- Notes the patch only affects client-side behavior, matching existing `--filter` CLI behavior
- Questions whether `remote.*.partialCloneFilter` can achieve the same goal, as it appears to require additional config and doesn't work for initial clone
- Asks for confirmation about server-side requirements (needing only `uploadpack.allowFilter`)

The discussion has shifted from implementation details to whether the feature is justified given existing mechanisms.
