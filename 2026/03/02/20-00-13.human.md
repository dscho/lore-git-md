This is the first patch in a 5-part series refactoring Git's oidmap API to make memory cleanup more explicit and type-safe. The patch introduces a new `oidmap_clear_with_free()` function that replaces the old boolean-flag approach with an explicit callback mechanism for freeing entries.

The change removes reliance on internal struct layout assumptions while maintaining the same functionality. The patch includes thorough unit tests verifying both the callback and non-callback cases, ensuring entries are freed (or not) as expected. The implementation uses the standard `container_of` pattern to safely access entries.

This is a well-structured foundation for the series, with clear motivation and test coverage. The changes are contained to the oidmap subsystem while providing the infrastructure needed for subsequent patches to convert specific call sites. The patch follows Git's coding style and includes appropriate documentation updates.
