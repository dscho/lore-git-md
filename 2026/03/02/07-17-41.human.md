Performance regression report from Patrick Steinhardt about two issues affecting `git-receive-pack` and `git-fetch`. The first is a clear 2.6x slowdown in `receive-pack` when handling many refs (10,000 in the benchmark), bisected to commit fc148b146a which converted update hooks to a new API. The regression appears specific to the reftable backend.

The second issue affects both commands and stems from commit 452b12c2e0, which changed the default maintenance strategy to "geometric". This causes unwanted ref packing during fetch operations with many refs, though the problem doesn't manifest with reftable. Patrick identifies this as a benchmarking infrastructure problem rather than a core issue, and plans to fix it by disabling auto-maintenance in the tests.

The email is characteristically thorough from Patrick - it includes detailed benchmark results, clear bisection targets, and distinguishes between actual regressions versus testing artifacts. The first issue appears more serious and may warrant closer examination of the hook API changes.
