This is the third patch in Patrick Steinhardt's 8-part series introducing a new `git history split` subcommand. The patch continues the refactoring work started in earlier patches to separate the add-patch machinery from the add-interactive subsystem.

The key change here is removing the dependency on `add-interactive.h` by directly embedding the interactive configuration` struct in `add_p_state` rather than including it via `add_i_state`. This follows through on the separation of concerns started in patch 2/8, where the shared interactive configuration was split out into its own module.

The patch makes several mechanical changes:
- Replaces `s->s.r` with `s->r` throughout
- Updates color/config access to use the new `s->cfg` path
- Changes initialization from `init_add_i_state()` to `interactive_config_init()`
- Updates cleanup from `clear_add_i_state()` to `interactive_config_clear()`

The changes are straightforward and maintain all existing functionality while reducing circular dependencies. This appears to be a well-executed refactoring that paves the way for the later patches in the series that will implement the actual `git history split` functionality. The patch touches only `add-patch.c` and keeps the diff focused on the structural changes needed to complete the decoupling from add-interactive.
