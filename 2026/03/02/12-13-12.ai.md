This is the final patch in Patrick Steinhardt's 8-part series introducing a new `git history split` subcommand, building on the infrastructure changes from earlier patches. The command provides an interactive way to split a commit into two while maintaining tree consistency, addressing a common but complex workflow that currently requires manual rebase operations.

The implementation handles several key cases:
- Splitting tip commits, root commits, and in-between commits
- Preserving original authorship and commit metadata
- Supporting pathspec-limited splits and partial hunk selection
- Properly updating dependent branches (with configurable --update-refs behavior)
- Maintaining worktree and index state during the operation

The patch adds 755 lines of tests covering edge cases like empty splits, merge commits, detached HEAD, and hook interactions. The command integrates with the existing `git-history` family (following similar patterns to `git history reword`) and builds on the refactored add-patch infrastructure from earlier in the series.

The implementation appears thorough, with careful handling of index operations and tree writing. Given Patrick's role driving the git-history effort and the preparatory refactoring in earlier patches, this seems likely to be a well-considered addition. The extensive test coverage (nearly 3x the implementation code) suggests serious attention to correctness.

This completes the initial version of a feature that could significantly simplify a common advanced Git workflow. Reviewers familiar with the history-editing and add-patch subsystems (potentially Phillip Wood or Elijah Newren) would be well-positioned to evaluate the approach.
