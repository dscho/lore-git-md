This is the third patch in Tian Yuchen's v4 series migrating encoding-related functionality from global variables to repository-specific storage, part of the `the_repository` removal effort.

The patch moves the encoding configuration variables `git_commit_encoding` and `git_log_output_encoding` into `struct repo_config_values`, using Olamide Caleb Bello's infrastructure for repository-specific config storage. The change ensures these encoding settings are properly scoped to repository instances rather than being global state.

Key technical aspects:
- Adds `commit_encoding` and `log_output_encoding` fields to `struct repo_config_values`
- Updates all callers of the encoding getters to pass a repository parameter
- Maintains backward compatibility by falling back to `the_repository` when needed
- Updates config parsing in `git_default_i18n_config()` to store values in `the_repository`'s config
- Adds cleanup of encoding strings in `repo_clear()`
- Touches 19 files across commit handling, mail operations, revision walking, and builtin commands

The patch follows established patterns for global variable migration, though it notes that fully plumbing the repository pointer through the config callback machinery remains future work item. The changes are mechanical but widespread, affecting many call sites that deal with commit messages and log output encoding.

This completes the encoding migration portion of Tian's series, building on the API plumbing changes in the first two patches.
