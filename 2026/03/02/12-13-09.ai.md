This is part 5/8 of Patrick Steinhardt's series introducing a new `git history split` command, focusing on refactoring the add-patch infrastructure to support the new functionality.

The patch modifies the add-patch machinery to allow disabling hunk editing, which is incompatible with the upcoming `git history split` command's requirements. It introduces a new `ADD_P_DISALLOW_EDIT` flag that prevents the "edit hunk" option from being presented to users during interactive sessions. The change propagates through all callers of `run_add_p()` and `run_add_p_index()`, which now require a flags parameter (defaulting to 0 for existing callers).

The modification touches several key files:
- Adds the flag definition in add-patch.h
- Updates the core patch_update_file() logic to respect the flag
- Modifies all builtin commands that use add-patch (add, checkout, reset, stash) to pass 0 as the default flags value
- Maintains backward compatibility while enabling the new split command to disable editing

This is a preparatory change for the actual split command implementation that will follow in later patches. The careful handling of flags suggests the author is maintaining existing behavior while cleanly extending the API for new use cases. Given Patrick Steinhardt's role in driving the git-history command family and his track record with architectural changes, this refactoring is likely well-considered, though reviewers may want to verify the flag propagation doesn't introduce any subtle behavior changes in existing commands.
