This is a feature patch series introducing a new `git history split` subcommand, part of Patrick Steinhardt's ongoing work to expand the `git-history` command family. The series builds on previous discussions about commit splitting functionality, now presented as a standalone feature after being separated from the larger `git-history` effort. The new subcommand allows splitting a single commit into multiple commits while automatically updating dependent branches, similar to the existing `git history reword` behavior.

Key characteristics of this implementation:
- It prompts for commit messages for both resulting commits (not just the first one)
- Avoids potential conflicts by not allowing hunk editing - the second commit's tree always matches the original
- Handles branch updates automatically

The series includes significant refactoring of the add-patch machinery to support in-memory index operations and remove dependencies on the interactive add subsystem. Test coverage appears thorough with over 750 lines of new tests. Given Patrick's track record with complex features and the evident care taken to address previous mailing list feedback, this looks like a well-prepared contribution likely to progress smoothly through review.
