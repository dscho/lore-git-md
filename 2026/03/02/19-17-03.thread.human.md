This thread addresses a performance regression in `git-receive-pack`'s hook handling that was introduced during recent hook API conversions. The issue, originally spotted by Patrick Steinhardt and root-caused by Jeff King, involved sideband hooks unnecessarily spinning up async threads even when no hook existed - a previously optimized path that was lost during the API transition.

Adrian Ratiu submitted a fix (v1) that restores the optimization by using the new hook API's `hook_exists()` function to check for hooks early in three key execution paths. The small but impactful change shows measurable performance improvements in receive-refs benchmarks. 

Junio C Hamano has now reviewed the patch and suggested a maintainability improvement: consolidating the hardcoded hook names into static constants. This change makes the hook names single-sourced within each function while preserving the performance fix. Junio indicates he will queue the patch with this refinement incorporated. The fix appears ready to go, with no outstanding questions or objections from other contributors.
