This thread addresses a performance regression in `git-receive-pack`'s hook handling that was introduced during recent hook API conversions. The issue caused unnecessary overhead by spinning up async threads for hooks even when no hooks were configured. Adrian Ratiu submitted a fix that restores the optimization by using the new `hook_exists()` API to check for hooks before thread creation, with Junio C Hamano improving the patch by consolidating hardcoded hook names into constants.

Patrick Steinhardt has now confirmed through benchmarks that the fix successfully reverts the regression, showing a 2.7x speedup for operations on repositories with 10,000 refs. He praised the solution as "delightfully simple" and verified the performance improvements through both local testing and the project's Bencher infrastructure. While Patrick noted a tangential question about potentially removing the older `find_hook()` function (particularly for the "proc-receive" hook), he considers this a separate matter for future work. With Junio having already indicated he will queue the improved patch, this appears to be a successful resolution to the performance issue.
