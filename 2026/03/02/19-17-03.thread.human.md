This thread addresses a performance regression in `git receive-pack`'s hook subsystem, where sideband hooks were no longer exiting early when no hook was found - an issue introduced during the recent hook API conversion. The problem was independently spotted by Patrick Steinhardt and root-caused by Jeff King, with Adrian Ratiu now providing the fix.

The 12-line patch adds back the missing early-exit check for sideband hooks in `builtin/receive-pack.c`, avoiding the overhead of spinning up and tearing down async threads when there's no hook to run. The change is narrowly scoped to the receive-pack builtin and has already passed GitHub CI testing. With the regression clearly identified and the fix vetted by two experienced contributors (Patrick and Peff), this appears to be a straightforward and well-justified performance improvement.
