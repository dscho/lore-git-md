This thread addresses a performance regression in `git-receive-pack`'s hook handling that was introduced during the recent hook API conversion work. Patrick Steinhardt first noticed the issue, and Jeff King identified the root cause: the new implementation was missing an optimization where sideband hooks would check for existence before spinning up async threads, causing unnecessary overhead when no hooks were present.

Adrian Ratiu has submitted a focused fix (9-12 lines) that restores this optimization by adding `hook_exists()` checks in three hook-related functions in `builtin/receive-pack.c`. The change properly handles both config-defined hooks and traditional hookdir hooks through the new API. Benchmarking shows measurable improvements, particularly for operations involving large numbers of refs. The patch has already passed GitHub CI testing and appears ready for merging as a straightforward performance fix to the recent hook subsystem changes.
