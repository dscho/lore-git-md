This thread addresses a performance regression in `git-receive-pack`'s hook handling that was introduced during the recent hook API conversion. The issue, identified by Patrick Steinhardt and root-caused by Jeff King, involved the loss of an optimization where sideband hooks would early-exit if no hook existed, causing unnecessary overhead from spinning up async threads.

Adrian Ratiu submitted a fix that restores this optimization by using the new hook API's `hook_exists()` function in three hook execution paths (`run_receive_hook`, `run_update_hook`, `run_update_post_hook`). Junio C Hamano improved the patch by consolidating hook name strings into static constants. Benchmarks show a 2.7x speedup when pushing to repositories with 10k refs.

The discussion revealed consensus on converting the remaining `find_hook()` usage (particularly for the "proc-receive" hook) to the new API in follow-up work, after which `find_hook()` can be made internal. The current fix is straightforward and uncontroversial, with no open questions remaining. This is part of the ongoing effort to modernize Git's hook subsystem following the recent API conversion.
