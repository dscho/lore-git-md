This is a documentation clarification in an ongoing thread about `git fetch` parallel job behavior. Johannes Schindelin responds to Patrick Steinhardt's investigation into why the behavior of `--jobs=0` and `fetch.parallel=0` wasn't clearly documented. 

Schindelin confirms there was no historical discussion about keeping the behavior undocumented, despite Junio Hamano's speculation that it might have been deliberate. Through code archaeology, he traces the implementation back to 2019, showing that the fallback to `online_cpus()` has been consistent since then. He also notes this was mentioned in the v2.40.0 release notes when a related bug was fixed.

The email provides technical details about how the value flows through the fetch and submodule processing code to ultimately use the number of available CPU cores when zero is specified. This confirms the behavior that the documentation patch series aims to clarify.

The thread appears to be reaching consensus that documenting the CPU fallback is appropriate, though there may still be discussion about whether to use more abstract terms like "auto" in the interface itself. Schindelin's response provides the missing historical context that the original vague wording wasn't intentionally leaving the behavior unspecified.
