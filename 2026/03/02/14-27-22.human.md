Performance regression investigation in `receive-pack` with reftable backend.

Patrick Steinhardt and Adrian Ratiu are investigating a 2.66x slowdown in `git receive-pack` operations when using the reftable backend with 10,000 refs. The regression was initially bisected to commit fc148b146a ("receive-pack: convert update hooks to new API"), but Adrian has now determined this is separate from his hooks configuration series that was prematurely merged.

The benchmarks show system time increasing dramatically from 89ms to 376ms after the problematic commit, suggesting the update hooks conversion is interacting poorly with the reftable backend. Adrian is now focused on reproducing and analyzing this specific regression while Patrick provides guidance on the benchmarking setup. The thread has cleanly separated this issue from a separate geometric repacking behavior change that was initially reported alongside it.

This appears to be a genuine performance regression in a critical path (ref updates) that affects users of the reftable backend. The investigation is still early, but the focus has narrowed to the original hooks API conversion rather than later configuration changes.
