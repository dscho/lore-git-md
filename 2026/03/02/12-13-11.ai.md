This is patch 7/8 in Patrick Steinhardt's series introducing a new `git history split` command. The patch refactors commit creation logic in preparation for the actual split functionality.

The change extracts a new `commit_tree_with_edited_message_ext()` function from the existing `commit_tree_with_edited_message()`, making the commit creation more flexible by allowing explicit parent commits and tree objects rather than deriving them from a single commit. The original function becomes a thin wrapper that maintains the existing behavior for rewording commits.

Key technical details:
- The new extended function takes explicit parameters for parents, old tree, and new tree
- The original function now just calculates these values from the input commit and calls the extended version
- Both functions share the same core logic for handling commit messages and extra headers
- This prepares for the split command which will need to create commits with different parent/tree combinations

The patch continues the series' pattern of careful refactoring before introducing new functionality. It touches the same `builtin/history.c` file as previous patches and maintains the same style. Given Patrick's role driving the git-history effort and the incremental nature of this change, it's likely to be uncontroversial.
