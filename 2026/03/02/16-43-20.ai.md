This is a feature patch adding client certificate support to `git send-email`, now approved by the maintainer for merging. The patch enables certificate-based SMTP authentication, addressing security requirements in environments that mandate mutual TLS verification. It supports both PEM and PKCS12 certificate formats to match real-world email clients like Thunderbird and K-9 Mail.

The implementation adds three new configuration options following Git's existing SMTP configuration patterns: `sendemail.smtpSSLClientCert` (accepting either PEM or PKCS12), `sendemail.smtpSSLClientKey` (PEM only), plus corresponding command-line flags. The design leverages Perl's IO::Socket::SSL library without introducing new dependencies, letting the SSL library handle certificate presentation automatically per RFC 8446.

Junio C Hamano has reviewed and approved the technical approach after the author clarified SSL library behavior and real-world constraints. The final version includes thorough documentation explaining certificate handling nuances - particularly the different key management behaviors between PEM (which may use separate key files) and PKCS12 (where keys are embedded). The commit message now fully addresses security considerations and standards compliance.

This represents the culmination of a focused effort to bring Git's email submission capabilities in line with modern security practices while maintaining backward compatibility.
