This is a discussion thread about potential enhancements to Justin Tobler's repository statistics series, specifically regarding commit size metrics.

Lucas Seiki Oshiro suggests expanding the "largest objects" reporting to include commits with the most changed lines (similar to GitLab's interface) rather than just tracking commit object sizes. Justin responds that this would require computing diffs across the commit history, which would be expensive for large repositories and may not fit the scope of the `git repo` command's focus on repository structure statistics.

The exchange highlights a design boundary question - whether to include derived metrics (like diff statistics) versus sticking to direct object store measurements. Justin indicates this would be both computationally intensive and conceptually different from the current approach of reporting raw repository structure characteristics. The thread shows active consideration of user needs versus implementation costs, but doesn't propose concrete changes to the current patch series.
