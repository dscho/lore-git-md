This is the third patch in a 5-part series refactoring Git's oidmap cleanup API. The patch converts the list-objects-filter subsystem to use the new `oidmap_clear_with_free()` function introduced in the first patch, replacing the older oidmap_clear(map, 1)` pattern.

The change focuses on the `seen_at_depth` map in `list-objects-filter.c`, which stores `struct seen_map_entry` objects. The patch introduces a new `free_seen_map_entry()` helper that properly frees these entries using the `container_of` pattern to safely access the full structure from its embedded hashmap entry. This makes the memory cleanup explicit and type-safe, removing reliance on the old boolean flag approach.

The implementation follows the same pattern established in previous patches of the series - defining a type-specific cleanup callback and using it with the new API. The 9-line diff is focused and straightforward, with the existing list-objects-filter tests providing verification that behavior remains unchanged. This continues the series' consistent approach to improving memory management clarity across Git's codebase.
