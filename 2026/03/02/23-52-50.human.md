Maintainer test review for configurable branch comparison feature

Junio Hamano is conducting the final review of the test suite for Harald Nordgren's `status.compareBranches` feature before merging to 'next'. This 2-patch series (refactoring + implementation) enables configurable `@{upstream}`/`@{push}` comparisons in `git status` while maintaining default `@{upstream}` behavior.

The review focuses on the comprehensive test coverage in t6040-tracking-info.sh, which handles various scenarios including:
- Duplicate branch handling
- Different ahead/behind/diverged states
- Triangular workflows
- --no-ahead-behind output
- Edge cases with multiple remotes

Junio notes the tests are thorough but raises a few minor points:
- Inconsistency between using `cd test && git` vs `git -C test` in test setup
- Requests clarification on deduplication behavior when `@{upstream}` and `@{push}` resolve to the same branch
- Suggests documenting the ordering semantics when multiple comparison branches are specified

The implementation itself appears sound, having gone through 28 iterations over two months (plus earlier efforts from 2016-2018). Jeff King helped broker the final technical approach, and all previous feedback has been addressed. This represents the final step before merging, with only these minor test/documentation clarifications remaining.

The feature provides flexible branch comparison configuration while maintaining backward compatibility, marking the successful conclusion of a persistent contribution effort through Git's mailing list workflow.
