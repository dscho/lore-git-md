This is a feature patch series focused on improving repository path reporting in `git repo info`. The v6 iteration narrows the scope to just path-related functionality after feedback on previous versions that had grown to include metrics features.

The series introduces several key improvements:
1. A new `repo_info` context structure to manage path resolution state
2. Category-based key requests (e.g. `layout` expands to all `layout.*` keys)
3. New `path.*` keys for common repository locations (10 total, down from 13 in v5)
4. A `--path-format` option to control absolute vs relative path output

Notable changes from v5 based on review feedback:
- Renamed `path.git-prefix` to simpler `path.prefix`
- Added `path.working-tree` as an alias for `path.toplevel`
- Removed implementation-tied path keys that may change with ODB abstraction (`logs-directory`, `packed-refs-file`, `refs-directory`, `shallow-file`)
- Bare repositories now return empty values for work-tree paths rather than errors
- Split context plumbing and category expansion into separate commits
- Rebased to clean up history and avoid fix-on-fix commits

The implementation provides thorough test coverage in t1900-repo.sh and documents all path keys and formats in the man page. The path resolution is designed to be context-aware, using both the repository handle and prefix information to produce correct paths in subdirectory and submodule contexts.

This version appears well-focused and responsive to prior review feedback, particularly around avoiding implementation-tied paths and improving naming consistency. The test coverage is comprehensive, validating all path keys against equivalent `rev-parse` invocations. The documentation clearly explains the new capabilities for both human readers and script consumers.

The series is now strictly about path reporting, having split out the metrics functionality that was present in earlier versions. This tighter focus should make review and integration more straightforward.
