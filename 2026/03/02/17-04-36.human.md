This is a follow-up to Adrian Ratiu's config-based hooks series, now in its fourth iteration (12 patches). The series introduces configuration-based hooks as an alternative to filesystem hooks, with features like global hook definitions and per-hook enable/disable controls.

In this email, Adrian acknowledges Junio Hamano's request to rebase the series onto 'master' rather than 'next', since the prerequisite config-hooks topic has already been in 'next' for several days. This is an administrative adjustment rather than a technical change - the series itself has already addressed all substantive review feedback from previous rounds.

The core functionality remains unchanged: users can now define hooks through Git config (hook.<name>.command, hook.<name>.event, etc.) while maintaining backward compatibility with traditional filesystem hooks. The series has evolved through multiple rounds of review, with Junio and Patrick Steinhardt providing detailed feedback that has been incorporated into the current version.
