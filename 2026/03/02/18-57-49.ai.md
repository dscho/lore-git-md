This is a follow-up discussion in the ongoing thread about adding a `fetch.blobSizeLimit` config option for partial clones. Junio C Hamano responds to Patrick Steinhardt's concerns about performance implications and global configuration scope.

Junio makes two key points: First, he notes that setting this globally for clones would require either command-line overrides or a user's global config, which may not be as problematic as initially suggested. Second, he questions the need for a new config option at all, pointing out that the same functionality could be achieved through the existing `remote.*.partialCloneFilter` mechanism.

The exchange highlights the maintainer's perspective on configuration proliferation and backward compatibility. Junio's comments suggest skepticism about adding new knobs when existing ones could serve the same purpose, while still acknowledging the technical merits of the discussion around performance characteristics that Patrick and Jeff King raised earlier in the thread.

This moves the conversation toward evaluating whether the proposed config offers enough unique value to justify its addition, given both the existing alternatives and the operational characteristics of size-based filtering that the thread has surfaced. The technical details about bitmap support and performance tradeoffs remain relevant background, but the immediate question is whether the feature's design needs rethinking at the configuration level.
