Performance regression report regarding hook API conversion.

Patrick Steinhardt flags a significant performance regression in the update hook functionality introduced by Adrian Ratiu's series converting various hooks to use the new hook API. The series (already merged to 'next') replaces direct run_command() calls with the new hook API across multiple hook types including receive-pack's update hooks. While the conversion provides architectural benefits, Patrick has measured concrete performance degradation in update hook execution.

The regression appears serious enough that Patrick requests Junio hold off merging the series to master until it can be addressed. He references a separate email (not provided in this digest) containing performance measurements and analysis. This intervention comes late in the process - after the series has already graduated to 'next' - suggesting the performance impact may not have been caught during earlier review.

The hook API conversion effort has been ongoing for several months with multiple related branches (ar/config-hooks and ar/parallel-hooks) building on this work. The regression affects a critical path in receive-pack where performance is particularly important for server-side operations. Given Patrick's involvement in performance-sensitive areas like the object database and reftable backend, his assessment carries weight regarding operational impact.
