This is a documentation patch from Lorenzo Pegorari, part of a 3-patch series addressing promisor file handling during repacks (as noted in the thread context). This first patch adds explanatory comments to `pack-write.c` clarifying the purpose of ref names and hashes stored in `.promisor` files.

The patch documents that these entries in `.promisor` files serve only for debugging purposes - specifically to help diagnose issues with partial clones by recording what refs were fetched when the packfile was downloaded. The comment explains this allows comparing the recorded hashes against what the promisor remote currently reports.

This appears to be groundwork for the larger series which will modify how these files are handled during repacks. The comment itself is clear and well-written, though as noted in the thread context, the overall approach to handling promisor files during repacks is still under discussion. The author is participating in GSoC and this seems to be their first significant contribution to this area of the codebase.
