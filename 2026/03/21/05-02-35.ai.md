This is a follow-up to the bisect terminology consistency bugfix patch. Git maintainer Junio C Hamano acknowledges the technical changes in the patch (which updates bisect output messages to use custom terms when configured) as correct, but notes two remaining issues:

First, he points out the patch lacks test coverage to verify the behavior and prevent regression. This is a significant gap since the changes affect user-visible output. The test suite should ideally include cases demonstrating both default and custom term usage in status messages.

Second, while not explicitly restated here, Junio's earlier review noted the commit message should more thoroughly document which parts of the bisect system handle custom terms versus where hardcoded "good/bad" still appears. The current patch focuses only on output messages, leaving open whether other components might need similar updates.

The patch appears technically sound but needs these two improvements before merging: (1) adding test cases in t/t6030-bisect-*.sh to exercise the custom term output, and (2) expanding the commit message to clarify the scope of term usage coverage. These are standard expectations for Git contributions - especially for user-facing behavior changes like this one.
