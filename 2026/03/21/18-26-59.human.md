Bugfix follow-up addressing Junio's review comments about the `git fetch --prune-tags` behavior patch.

Junio Hamano responds to Orgad Shaneh's patch that aimed to make `--prune-tags` force-update changed tags as documented. He raises two key questions: (1) what exactly was the previous behavior if not the documented one, and (2) whether this was broken from the start in Git 2.17 or changed later. Junio speculates that since Ævar Arnfjörð Bjarmason was involved in the original implementation, it's unlikely the behavior was wrong from the beginning, suggesting the documentation might need updating instead.

Junio also points out a gap in the test coverage - while the patch adds tests for clobbering changed tags, it doesn't verify that `--prune-tags` actually removes tags that no longer present on the remote. The test only checks command exit status, not the post-fetch tag state.

This moves the discussion from a straightforward bugfix to needing historical investigation of when/why the behavior diverged from docs. Junio's questions suggest the patch may need reworking or the documentation may need adjustment instead. The test coverage will likely need expansion to fully verify both aspects of `--prune-tags` behavior.
