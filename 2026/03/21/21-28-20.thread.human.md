Lorenzo Pegorari's GSoC patch series addresses how Git handles `.promisor` files during repacks, fixing an issue noted in commit 5374a290 where ref-to-packfile mappings weren't properly preserved. The initial version (v1) consists of three patches: documentation improvements, a helper function for consolidating promisor files, and integration with the repack logic. The implementation currently uses inefficient file scanning for duplicate checking and mixes variable declarations with code, both of which Eric Sunshine flagged in his review. Eric, a prolific Git reviewer known for his thorough feedback, suggested using Git's `strset` for O(1) duplicate checks instead of the current O(n²) file scanning, and pointed out memory leaks from un-freed strbufs. His review maintains a constructive tone appropriate for a GSoC participant's first significant contribution.

The series now awaits Lorenzo's revision addressing these points - particularly the memory management issues and duplicate-checking strategy - before further review. The core approach of consolidating promisor files during repack remains valid, but the implementation needs refinement to meet Git's standards for both correctness and efficiency. Eric's feedback provides clear direction for these improvements while leaving the high-level design decisions (like single-file consolidation versus per-pack files) open for further discussion.
