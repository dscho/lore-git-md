This is a documentation patch that's part of a GSoC series addressing promisor file handling during repacks. The patch adds clarifying comments to `pack-write.c` explaining the purpose of ref names and hashes stored in `.promisor` files.

Lorenzo Pegorari's patch documents that these entries are purely for debugging purposes - they help identify which refs were fetched when the packfile was downloaded, allowing comparison with the remote's current state if needed. The explanation is clear and well-motivated, addressing a gap where this behavior was previously only implied by the code.

This appears to be a solid first step in the series, providing necessary context for the subsequent implementation changes. The patch is focused and uncontroversial, just adding documentation without changing any behavior. As part of a GSoC project, it shows good practice of documenting first before modifying.
