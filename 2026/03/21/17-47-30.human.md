Bugfix for `git backfill` argument validation.

Siddharth Shrimali has sent a revised version of his patch to make `git backfill` properly reject unexpected arguments. The command previously silently ignored extra arguments, which could confuse users when they made typos or incorrect invocations. The new version follows Junio C Hamano's feedback by adding both clearer error messaging and test coverage.

The patch now explicitly calls out unknown arguments with an error message before showing the usage string, matching the behavior of commands like `git bugreport`. It also includes a test case in t5620-backfill.sh that verifies the command fails with the expected error when given an invalid argument. The changes are minimal but important for consistency with Git's standard command-line behavior.

This version addresses all the maintainer's previous concerns - it provides better user feedback than just showing the usage message, and it includes the requested test coverage. The implementation is straightforward and follows established patterns from other parts of Git. Unless further issues surface in review, this looks ready to be picked up by Junio.
