This is a bugfix addressing a segfault in `git-remote-http` when parsing refspecs outside a repository context. The issue was originally reported by Jo Liss, who found that running `git ls-remote -h <url>` outside a Git repository with a global `remote.origin.fetch` setting would crash due to a NULL dereference in `parse_refspec()` when accessing `the_hash_algo`.

K Jayatheerth's patch fixes this by initializing a fallback SHA-1 hash algorithm when operating outside a repository, mirroring the behavior of Git's main built-ins. The solution is straightforward - setting the hash algorithm when `the_repository->hash_algo` is NULL - and comes with a test case in t5551 that reproduces the original crash scenario using `GIT_CEILING_DIRECTORIES` to ensure a genuine non-repository environment.

The patch appears well-constructed: it addresses the root cause, includes a regression test, and follows Git's conventions for similar cases. The test is appropriately placed in t5551, which already contains other http-fetch tests. This looks like a solid fix for a legitimate (though edge-case) crash scenario.
