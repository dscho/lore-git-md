This is the second patch in a 3-part series addressing promisor file handling during repacks, part of Lorenzo Pegorari's GSoC work. The patch introduces a helper function `copy_all_promisor_files()` that consolidates the contents of multiple `.promisor` files into a single file when repacking promisor packfiles.

The function works by:
1. Iterating through all packfiles in the repository
2. For each promisor packfile, reading its corresponding `.promisor` file line by line
3. Checking each line's presence in the destination file to avoid duplicates
4. Writing only new lines to the consolidated output file

The implementation shows some technical concerns - the author acknowledges the duplicate checking approach (using repeated `fseek` and line-by-line comparison) is inefficient and likely needs improvement. The function handles file I/O directly rather than using Git's higher-level abstractions, which may raise review questions about error handling and performance.

This patch builds on the documentation added in patch 1/3 and will be used by the repack logic in patch 3/3. The work touches core packfile handling code (`pack-write.c`) and adds to the growing promisor packfile infrastructure. As a GSoC contribution from a new contributor, the patch demonstrates understanding of the problem space but will likely need refinement based on reviewer feedback, particularly around the I/O handling and duplicate checking strategy.
