This is the third patch in a GSoC series addressing promisor file handling during repacks, focusing on preserving debug information in `.promisor` files. The patch modifies the repack process to consolidate the contents of all existing `.promisor` files into the first new one created during repack, rather than creating empty files as before.

The change affects `repack-promisor.c` and updates documentation in `git-repack.adoc` to clarify that the new `.promisor` files will contain "arbitrary contents" (the consolidated debug info) rather than being empty. The implementation uses the `copy_all_promisor_files()` helper introduced in patch 2/3, though the author has previously noted inefficiencies in the helper's duplicate checking approach.

This appears to be a straightforward application of the series' proposed solution, completing the work to address the `NEEDSWORK` comment from commit 5374a290. The patch maintains the series' focus on preserving debug information while acknowledging these contents are only used for debugging purposes. As this is the first iteration of the series, reviewers will likely comment on both the high-level approach and the implementation details of the helper function being used here.
