Thread subject: [PATCH] backfill: reject unexpected arguments. Thread type: bugfix patch for the `git backfill` command. Originating author: Siddharth Shrimali.

Core problem: The `git backfill` command currently silently ignores unexpected command-line arguments, violating Git's standard behavior of erroring out on invalid input. The patch aims to bring it in line with other Git commands like `gc` and `repack` that properly validate arguments.

Technical details: The initial patch added 3 lines to `builtin/backfill.c` to check for remaining arguments after `parse_options()` and call `usage_with_options()` if any exist. Junio C Hamano reviewed this approach, noting that while technically correct, simply showing the usage message may not provide enough context when invalid arguments are provided. He suggested studying `git bugreport`'s more informative error handling as a better model.

Current status: Initial patch version proposed by Siddharth Shrimali, now under review from the maintainer. The discussion has shifted from a simple bugfix to considering the user experience of invalid input handling. The author will likely need to revise the approach to provide more specific error messaging rather than just showing usage.

Open questions: How to best implement error messaging that guides users when they provide invalid arguments, potentially following `git bugreport`'s example. The maintainer's feedback indicates this simple change may need more thoughtful design around error cases.

Participant positions: Junio C Hamano has provided maintainer feedback suggesting improvements to the initial approach, moving beyond just technical correctness to consider usability. The author has not yet responded to this feedback.
