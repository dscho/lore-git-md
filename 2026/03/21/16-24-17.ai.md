This is a refactoring patch that continues Junio's effort to eliminate unnecessary NULL checks of strbuf.buf, now focusing on strbuf_getwholeline(). The patch restructures the function to maintain strbuf invariants while preserving the buffer reuse optimization that Jeff King's benchmarks showed provides meaningful performance benefits (7% speedup in line-heavy operations).

The key changes are:
1. Instead of temporarily breaking strbuf invariants by setting sb->buf to NULL, the function now works with local variables (buf and alloc) that track the buffer state during getdelim().
2. The EOF path is simplified - if getdelim() allocated memory when we had none, we free it directly rather than going through strbuf_reset().
3. The function now leaves the strbuf untouched in the EOF case, which Junio notes matches the existing behavior for the initial EOF check.

This builds on the ongoing discussion between Junio, Jeff King, and René Scharfe about balancing performance optimizations with code maintainability. The patch demonstrates that the buffer reuse optimization can be preserved while making the code more straightforward and eliminating the temporary NULL state that violated strbuf invariants.

The changes are surgical and focused - Junio explicitly leaves updating the xrealloc() commentary for a future patch, keeping this one narrowly scoped to the NULL check elimination effort. This continues the pattern of careful, incremental refactoring that characterizes much of Junio's maintenance work.
