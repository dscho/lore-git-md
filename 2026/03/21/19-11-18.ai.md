This is a bugfix report for a segfault in `git-remote-http` when parsing refspecs outside a repository. The issue occurs when `remote.<name>.fetch` is configured but there is no repository context, causing a NULL dereference in `parse_refspec()` when it accesses `the_hash_algo`.

Jo Liss provides a detailed reproduction case showing the crash happens when running `git-remote-http` with specific environment variables set, or more practically when running `git ls-remote -h <url>` outside a Git repository with a global `remote.origin.fetch` setting. The backtrace shows the crash occurs in `parse_refspec()` when it tries to access `the_hash_algo->hexsz` while `the_repository->hash_algo` is NULL.

The bug affects both current master (7ff1e8dc1e16) and Git 2.51.0, and has been reproduced on both Ubuntu and macOS. This appears to be a legitimate crash scenario that needs fixing, though the impact is limited to edge cases where remote-curl operations are performed outside a repository with certain configurations. The report is thorough, including environment details, backtrace, and clear reproduction steps - all signs of a well-prepared bug report.
