This is a bugfix report for a segfault in `git-remote-http` when run outside a repository with certain remote.fetch configurations. Jo Liss demonstrates that when `remote.<name>.fetch` is set in the environment (via `GIT_CONFIG_*` variables) and `git-remote-http` is invoked outside any Git working tree, it crashes while trying to parse refspecs.

The root cause appears to be that `the_repository->hash_algo` is NULL when `parse_refspec()` attempts to access `the_hash_algo->hexsz`. The backtrace shows the crash occurs during config parsing when trying to handle the remote.fetch setting. This affects both current master and Git 2.51.0.

The reporter encountered this in practice when running `git ls-remote -h <url>` outside a repository while having `remote.origin.fetch` globally configured. The bug is well-documented with a clear reproduction recipe and backtrace, making it straightforward for maintainers to investigate. This looks like a legitimate edge case that needs fixing in the remote-curl code's handling of repository-less operations.
