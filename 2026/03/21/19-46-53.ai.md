This is a bugfix addressing a segfault in `git-remote-http` when parsing refspecs outside a repository context. The patch follows up on Jo Liss's detailed bug report that identified the issue - when `remote.<name>.fetch` is configured globally but no repository exists, `parse_refspec()` would dereference a NULL `the_hash_algo` pointer.

K Jayatheerth's solution mirrors how other Git built-ins handle this case: when operating outside a repository, remote-curl now initializes a fallback hash algorithm (SHA-1) to safely check hexadecimal lengths during refspec parsing. The fix is minimal (4 lines) and comes with a test case in t5551 that reproduces the original crash scenario using `GIT_CEILING_DIRECTORIES` to ensure a genuine non-repo environment.

The test is well-placed in t5551-http-fetch-smart.sh, which already contains related remote-http functionality tests. The patch demonstrates good understanding of both the immediate issue and Git's broader patterns for handling repository-less operations. This appears to be a clean solution to a real edge case that could affect users with global fetch refspecs.
