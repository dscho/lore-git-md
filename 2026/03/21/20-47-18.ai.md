Refactoring discussion about strbuf_getwholeline() error handling.

René Scharfe builds on the ongoing conversation about strbuf_getwholeline() optimizations, pointing out a subtle memory leak in the current implementation when the function fails after allocating a buffer. He demonstrates how an empty strbuf (initialized with STRBUF_INIT) could leak memory if strbuf_getwholeline() allocates a buffer but then hits an error, as the caller's strbuf_release() would not free the allocated buffer in this case.

The proposed alternative implementation simplifies the function by always growing the buffer upfront with strbuf_grow(), then directly using getdelim() on the strbuf's buffer. This approach eliminates the need for special NULL checks while maintaining the same functionality. On success, it updates the strbuf's length; on failure, it resets the strbuf (freeing any allocated memory) before returning EOF. The implementation handles ENOMEM explicitly with die() while letting other errors propagate naturally.

This suggestion represents a refinement of the earlier proposals from Junio and Peff, addressing both the performance goals and the memory safety concerns. The key technical points are the upfront buffer growth to avoid NULL checks, and the consistent error handling that prevents memory leaks while maintaining the strbuf invariants. The change would affect any code path using strbuf_getwholeline() with an initially empty strbuf, making the behavior more predictable.
