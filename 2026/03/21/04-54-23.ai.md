This is a follow-up discussion about a bisect terminology bugfix patch. Junio C Hamano (the Git maintainer) is reviewing Jonas Rebmann's patch that makes bisect output consistently use custom terms (like "old/new") instead of default "good/bad" terminology when configured.

Junio acknowledges the patch's correctness but suggests improving the commit message to be more exhaustive about where custom terms are currently used versus where they should be used. He notes three specific areas: input commands, ref names, and output messages (the latter being what this patch fixes). The review also includes minor wording suggestions ("can give confusion" -> "can cause confusion").

The technical changes in the patch itself are approved as "looking good" - they modify status messages and error outputs in builtin/bisect.c to use terms from the bisect_terms structure rather than hardcoded values. Junio does raise the open question of whether there might be other places still using hardcoded terms that should also be updated.

This continues the thread's focus on improving bisect's terminology consistency when custom terms are specified. The patch appears ready to proceed with minor documentation improvements, though Junio's comment about exhaustiveness suggests there may be value in checking for other hardcoded term references that might need similar updates.
