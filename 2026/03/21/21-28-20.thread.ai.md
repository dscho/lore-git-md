Thread identity: Patch series from Lorenzo Pegorari addressing promisor file handling during repacks, part of GSoC work. Current version is v1 (initial submission) with Eric Sunshine's review feedback received.

Core problem: When repacking promisor packfiles, Git does not properly preserve the mapping between refs and their corresponding packfiles in `.promisor` files (noted in `NEEDSWORK` comment from commit 5374a290). The work involves both documenting and fixing this behavior.

Current status: Initial submission (v1) consisting of 3 patches now has substantive review feedback from Eric Sunshine. First patch added documentation clarifying `.promisor` file contents. Second patch introduced helper function `copy_all_promisor_files()` with acknowledged inefficiencies. Third patch modifies repack logic to use this helper. Eric's review identifies specific improvements needed before next version.

Key technical details:
- First patch added documentation to `pack-write.c` explaining `.promisor` file contents are debug-only records of refs/hashes from fetch time
- Second patch adds helper function in `repack-promisor.c` that:
  - Currently uses strbufs that leak memory (needs fixing)
  - Mixes variable declarations with code (style violation)
  - Uses inefficient `fseek`-based duplicate checking (O(n²))
- Third patch modifies `pack-write.c` and `pack.h` to use this helper:
  - Marks first promisor file as special for debug info
  - Updates `git-repack.adoc` to note promisor files may contain "arbitrary contents"
  - Leaves subsequent promisor files empty
- Eric Sunshine suggests improvements:
  - Use strset from strmap.h for O(1) duplicate checking
  - Fix memory leaks in strbuf handling
  - Separate variable declarations from executable code
  - Consider Git's higher-level I/O abstractions

Open questions:
- Implementation of strset-based duplicate checking
- Memory management fixes for strbuf usage
- Style compliance for variable declarations
- Whether to refactor using Git's I/O utilities
- General design validation still pending

Participant positions:
- Lorenzo Pegorari (author): Acknowledged implementation inefficiencies in initial submission
- Eric Sunshine (reviewer): Provided detailed technical feedback on memory management, style, and algorithmic efficiency while maintaining constructive tone. Suggested specific improvements using Git's strset data structure.

Related work: Builds on commit 5374a290 which originally noted the issue. Part of GSoC project. Eric Sunshine's review references Git's strmap.h utilities as existing solution for duplicate tracking.
