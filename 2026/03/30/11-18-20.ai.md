This is a test case submission for a bugfix targeting the `receive.denyCurrentBranch=updateInstead` behavior with bare repositories containing worktrees. The test demonstrates an edge case where Git incorrectly rejects pushes when the bare repository's HEAD points to an unborn branch, even when the linked worktree is clean and on a different branch.

The test case shows that when pushing to a worktree branch while the bare repo's HEAD points to an unborn ref, Git wrongly claims there are staged changes. The test is marked as `test_expect_failure` to document the current incorrect behavior, with a NEEDSWORK comment explaining the failure mode. The test creates a bare repo with a worktree, sets `updateInstead`, points the bare HEAD to an unborn branch, then verifies a push to the worktree branch should succeed (but currently fails).

This is part 1 of a 3-patch series that will ultimately fix the issue by modifying `builtin/receive-pack.c` to check the worktree's HEAD rather than the bare repository's HEAD. The test serves both to document the bug and provide verification for the upcoming fix. The test appears well-constructed to isolate the specific failure scenario while maintaining the existing test suite structure.
