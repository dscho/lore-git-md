This thread introduces a configurable way to handle submodule fetch errors when unreachable commits are encountered, addressing workflow pain points when working with in-progress upstream branches. The two-patch series first fixes a timing issue in error reporting, then adds new `fetch.submoduleErrors` configuration and `--submodule-errors` CLI options to let users choose between failing (current default) or just logging warnings.

Jean-Noël Avila, the Git documentation maintainer, has reviewed the patches and provided feedback focused on documentation polish. He notes the command-line syntax should use parentheses rather than angle brackets for alternatives (`--submodule-errors=(fail|warn)`), and that the new CLI option needs to be added to the relevant man pages. These are straightforward documentation fixes that maintain consistency with Git's established style. The core implementation remains uncontested, with no technical objections raised to the feature itself.
