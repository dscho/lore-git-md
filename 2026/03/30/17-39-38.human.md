This is the second patch in a two-part series that makes submodule fetch errors configurable. The first part fixed a timing issue in error reporting, and this patch introduces the main feature: allowing users to choose whether submodule fetch failures should be fatal (current behavior) or just warnings.

The patch adds a new `fetch.submoduleErrors` config option (with corresponding `--submodule-errors` CLI flag) that accepts "fail" (default) or "warn". When set to "warn", encountering unreachable submodule commits during recursive fetches will print an error message but not fail the overall fetch operation. This is useful when working with in-progress branches where some submodule commits may not yet be pushed upstream.

The implementation touches config handling in `builtin/fetch.c`, adds the new option to the submodule fetch machinery in `submodule.c`, and includes thorough documentation and test coverage. The tests verify both config and CLI override behavior, ensuring warnings appear when expected while successful fetches remain silent.

This appears well-considered and addresses a real workflow pain point - particularly for developers working with topic branches that reference unpushed submodule commits. The patch maintains backward compatibility while providing flexibility that many users will appreciate. The implementation is clean and the test coverage looks comprehensive.
