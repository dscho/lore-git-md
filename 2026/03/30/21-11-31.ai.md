Documentation patch clarifying git-interpret-trailers' key format restrictions. This two-patch series follows up on the recent discussion about trailer keys containing periods, aiming to improve the man page to explicitly document the current behavior (alphanumeric + hyphen only) that was confirmed as intentional by the maintainers.

The first patch reframes the introduction to focus on "key-value pairs" rather than RFC 822 headers, making the subsequent key format explanation flow more naturally. The second patch then explicitly states the allowed character set for keys, addressing the documentation gap that led to the original bug report. The changes are minimal but important for users who might otherwise lose metadata due to syntax errors.

This appears to be a well-targeted documentation improvement that directly addresses the settled conclusion from the thread - that the strict parsing behavior should remain but be better documented. The patches are focused and maintain the existing technical accuracy while improving clarity. The author has appropriately credited Linus Arver for the example being modified.
