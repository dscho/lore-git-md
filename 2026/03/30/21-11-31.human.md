This is a documentation patch clarifying the format requirements for trailer keys in `git-interpret-trailers`, following up on a recent thread about version-numbered keys containing periods.

The two-patch series aims to better document the current behavior where trailer keys must use alphanumeric characters and hyphens only, no periods. This comes after maintainer Junio Hamano firmly upheld the strict parsing rules in response to a bug report about version-tracking use cases (like "My-6.11-Version" keys).

The first patch reframes the man page introduction to emphasize the key-value pair nature of trailers, moving away from RFC 822 terminology. The second patch then documents the actual key format restrictions that were at the heart of the recent discussion. The changes are straightforward and align with the thread's conclusion that better documentation is the appropriate resolution rather than relaxing the parser's rules.

Kristoffer Haugsbakk (a frequent documentation contributor) handles this sensitively by not reopening the settled technical debate, instead focusing on making the existing constraints clearer for users. The patches look clean and well-motivated, directly addressing the documentation gap that became apparent in the earlier discussion.
