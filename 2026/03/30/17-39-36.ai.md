This is a feature patch series that makes submodule fetch errors configurable. The series consists of two patches that work together to address how Git handles unreachable submodule commits during recursive fetches.

The first patch fixes a subtle timing issue in the submodule fetch logic where errors were being recorded too early, before the retry mechanism had a chance to succeed. This preserves the existing behavior but makes the code more correct by only recording failures after all retry attempts.

The second patch introduces the main feature: new configuration options `fetch.submoduleErrors` and `--submodule-errors` that let users choose between failing (current behavior) or just showing a warning when submodule fetches encounter unreachable commits. This is particularly useful when working with in-progress upstream branches where missing commits are expected.

The changes touch the submodule fetch machinery in `submodule.c`, add new options to `builtin/fetch.c`, and include thorough documentation and test coverage. The implementation looks well-considered, with clear commit messages explaining both the technical details and the user-facing motivation. The feature appears ready for review, offering a practical solution to a real workflow pain point while maintaining backward compatibility.
