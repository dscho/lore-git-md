This is the second patch in a two-part series introducing configurable submodule fetch error handling. It builds on the first patch's error reporting improvements to add user control over how unreachable submodule commits are handled during recursive fetches.

The patch adds a new `fetch.submoduleErrors` config option (with `--submodule-errors` CLI counterpart) that lets users choose between failing (current default behavior) or just warning when submodule fetches encounter unreachable commits. This is particularly valuable when working with in-progress upstream branches where missing commits are expected but not required for the current work.

Implementation touches several areas:
- Adds config parsing in `builtin/fetch.c` for the new config and CLI option
- Extends `submodule.c`'s fetch machinery to respect the error mode
- Introduces `SUBMODULE_ERRORS_{FAIL,WARN}` constants in `submodule.h`
- Includes comprehensive tests in `t5526-fetch-submodules.sh` covering:
  - Default failure behavior
  - Config-based warning mode
  - CLI override of config
  - Successful fetch case (ensuring warnings don't appear unnecessarily)

The changes are well-contained and maintain backward compatibility while solving a real workflow pain point. The test coverage is thorough, verifying both the happy path and error cases. This appears ready for review as a useful quality-of-life improvement for developers working with complex submodule setups.
