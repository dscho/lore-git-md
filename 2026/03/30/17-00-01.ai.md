Part of Ezekiel Newren's xdiff refactoring series, this patch improves clarity in the record cleanup logic by making limit calculations more explicit. The changes focus on `xdl_cleanup_records()` in xdiff/xprepare.c, specifically around how per-file limits (`mlim1` and `mlim2`) are handled when determining which records to keep, discard, or investigate.

The key changes in this iteration:
- Introduces separate limit variables for each file (`mlim1` and `mlim2`) initialized upfront
- Removes redundant `!need_min` condition that was previously part of the limit checks
- Uses `PTRDIFF_MAX` to represent "infinity" when minimal diffs are requested
- Moves the limit calculations outside the record iteration loops for better clarity

This builds on prior work in the series that converted types to `ptrdiff_t` and `uint64_t` for safety. The patch maintains the same behavior while making the control flow more straightforward. The changes are purely internal - no user-visible effects - and have already been verified against the test suite (t4071, t8015) with DEVELOPER=1 builds.
