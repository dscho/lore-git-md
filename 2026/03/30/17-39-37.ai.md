This is a bugfix patch that corrects premature error reporting in recursive submodule fetches. It's the first of two patches in a series addressing submodule fetch error handling.

The patch fixes a timing issue where Git would mark a submodule fetch as failed immediately after the first phase (ref-based fetch), even though a second phase (OID-based fetch) might still retrieve the needed commits. The new logic defers error reporting until after both phases complete, only recording failures if the OID-based fetch also fails or if no OID-based retry is possible (as with `RECURSE_SUBMODULES_ON` fetches).

The changes are focused in `submodule.c`, introducing a new `record_fetch_error()` helper and restructuring `fetch_finish()` to make smarter decisions about when to report failures. The commit message explains the four distinct cases handled, resolving a longstanding NEEDSWORK comment from 2019. The implementation looks clean and maintains backward compatibility while fixing the premature error reporting.

This appears to be a well-considered fix for a subtle edge case in submodule fetching behavior. The patch has clear commit message explanations and maintains the existing test coverage while preparing the ground for the second patch's configurable error handling.
