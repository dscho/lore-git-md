Refactoring suggestion for mailmap toggle implementation in `git cat-file --batch-command`.

Patrick Steinhardt suggests using `git_parse_maybe_bool()` instead of direct string comparisons in the mailmap subcommand parser. This would handle the `yes`/`no` argument parsing more robustly, as the helper function already understands common boolean variants (1/0, true/false, on/off) while maintaining case insensitivity. The change would affect only the argument parsing logic in `parse_cmd_mailmap()` within `builtin/cat-file.c`, leaving the mailmap caching behavior and core functionality unchanged.

This is a minor implementation polish that surfaced after the main design discussion had concluded. The suggestion aligns with Git's established patterns for boolean parameter handling but doesn't impact the already-approved user interface or the feature's integration with GitLab's Gitaly service. The thread shows no disagreement with the core approach, and this refinement could be incorporated as a follow-up if Siddharth Asthana chooses to adopt it.
