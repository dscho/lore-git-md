Feature addition to `git cat-file`'s batch mode, finalizing the mailmap toggling capability.

Junio C Hamano provides final review feedback on Siddharth Asthana's patch implementing dynamic mailmap control for `git cat-file --batch-command`. The patch adds a `mailmap` subcommand that accepts `yes`/`no` arguments to toggle mailmap processing without restarting the process, addressing GitLab Gitaly's need to reuse long-running `cat-file` processes.

Junio suggests two potential improvements to the implementation: (1) extracting the mailmap loading logic into a helper function to avoid duplication between initialization and the new subcommand handler, and (2) making the mailmap object self-aware of its loaded state by leveraging the existing `strdup_strings` flag rather than adding a new `mailmap_loaded` variable. These are presented as optional refinements rather than blockers, indicating the patch is otherwise technically sound.

The review also corrects a minor documentation point about Gitaly's process management (clarifying it maintains persistent interactions rather than "caching" processes) and removes an over-attribution credit line. With no substantive objections raised and only optional cleanups suggested, this marks the final approval needed before the feature can be merged. The changes maintain the simplified interface from v2 while ensuring efficient mailmap data handling.
