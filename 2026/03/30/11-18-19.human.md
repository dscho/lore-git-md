This is a bugfix patch series addressing incorrect behavior in `receive.denyCurrentBranch=updateInstead` when pushing to bare repositories with worktrees. The issue occurs when the bare repository's HEAD points to an unborn branch while the worktree itself is clean - Git incorrectly rejects the push due to checking the wrong context.

The series includes three patches:
1. A test case from Runxi Yu demonstrating the bug (originally marked as `test_expect_failure`)
2. A cleanup of test infrastructure that could interfere with the new test
3. The actual fix from Pablo Sabater that makes `receive-pack` check the worktree's HEAD rather than the bare repository's HEAD when determining if there are staged changes

The fix modifies `builtin/receive-pack.c` to properly handle this worktree edge case, correcting behavior that appears to have worked incorrectly since the original 2021 implementation. The changes are focused and well-motivated, with clear test coverage for the previously failing scenario.

This looks like a solid contribution addressing a real-world edge case in Git's worktree handling. The patch series is well-structured with the test coming first (following Git's standard practice), and the commit messages provide good context about both the problem and solution.
