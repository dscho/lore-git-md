Refactoring patch adding repository path plumbing as part of the `the_repository` removal effort. This is the first of two patches in Jayesh Daga's v3 series, introducing a new `paths.git_dir` key to expose a repository's git directory path through the repo info mechanism.

The change provides programmatic access to the git directory path (equivalent to `git rev-parse --git-dir`) without requiring external command execution. The implementation adds a new field handler in builtin/repo.c, documents the key in git-repo.adoc, and includes a test verifying the output matches the rev-parse command.

This appears to be infrastructure work supporting the series' main goal of converting trace2 logging in read-cache.c to use repository-specific state rather than the global `the_repository`. The patch follows standard patterns for adding new repo info fields and includes appropriate documentation and test coverage. The implementation is straightforward and aligns with the project's ongoing architectural direction.
