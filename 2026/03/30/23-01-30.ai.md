This is a review response from Jeff King (Peff) on Taylor Blau's patch converting MIDX `keep_hashes` to use `strvec`. The review focuses on implementation details and suggests alternative approaches.

Peff questions whether using `strvec` is worth the complexity in this case, since the patch ends up manipulating the `strvec` internals directly rather than using its higher-level APIs. He suggests simpler alternatives like using `strvec_push()` with amortized allocation, though acknowledges this may not work for the backwards-filling case. He also notes the patch mixes concerns by changing string allocation patterns in `clear_incremental_midx_files_ext()` unrelated to the `strvec` conversion.

Key technical points raised:
- Direct `strvec.v[]` access violates abstraction
- `strvec_init_alloc()` may be overkill for small MIDX layer counts
- Backwards array filling complicates the conversion
- String list handling in the cleanup function had pre-existing memory leaks
- The strbuf change in cleanup is orthogonal to the main patch purpose

The review maintains the thread's technical depth while keeping the discussion constructive, typical of Peff's thorough review style. This continues the pattern of his earlier reviews in this series where he focuses on maintainability and correctness of supporting infrastructure changes.
