This is a documentation patch in the ongoing thread about git-interpret-trailers' key format restrictions, responding to Junio Hamano's review feedback on the v2 series.

Kristoffer Haugsbakk addresses two points from Junio's review: first agreeing to replace the Unicode floral symbol (❦) with ASCII `***` or nothing at all for better accessibility, and second discussing how to handle the explanation of the colon delimiter between keys and values. The author maintains that showing the normalized `:SP` form throughout the documentation is sufficient, arguing that while the email-header analogy was helpful to some readers, the current approach of demonstrating the standard format directly is clearer.

The exchange shows the thread moving toward finalizing the documentation improvements, with careful attention to both technical accuracy and readability. The core technical decision - maintaining strict parsing of trailer keys while clearly documenting the allowed character set - remains unchanged from earlier in the thread. This email focuses purely on polishing the presentation of that information in the man page.
