This is a documentation patch in a series clarifying git-interpret-trailers' key format restrictions, following up on a settled discussion about trailer parsing behavior.

Junio Hamano provides review feedback on Kristoffer Haugsbakk's v2 patch that removed RFC 822 comparisons from the man page. While agreeing with the general direction, Junio notes two concerns: first, that the floral Unicode symbol (❦) used as a thematic break may be unnecessarily hostile to ASCII-only readers, and second, that removing the email header comparison loses useful context about the colon delimiter convention between keys and values.

The feedback suggests the documentation should better balance technical accuracy with accessibility - keeping the key-value pair framing but potentially reintroducing some email-header context to explain the colon syntax. Junio acknowledges this is a minor point that doesn't block the patch series, which has already addressed the core issue of clearly documenting the alphanumeric+hyphen key format restriction.

This continues the thread's trajectory toward documentation-only improvements while maintaining the strict parsing behavior for trailer keys. The exchange shows the maintainer's attention to both technical precision and documentation clarity, even for seemingly small wording choices.
