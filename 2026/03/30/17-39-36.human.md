This is a feature patch series that makes submodule fetch errors configurable rather than always fatal. The two patches address a common workflow pain point when working with in-progress upstream branches.

Currently, `git fetch --recurse-submodules` fails completely if any submodule references an unreachable commit, even when the local branch doesn't actually need that commit. This is particularly disruptive during merge windows when topic branches are still being prepared. The series fixes a subtle bug in the error handling logic (patch 1) and then adds configuration to make these errors non-fatal (patch 2).

The implementation introduces `fetch.submoduleErrors` (with `fail` or `warn` options) and a corresponding `--submodule-errors` CLI flag, maintaining backward compatibility by defaulting to the original fatal behavior. The changes touch the fetch machinery and submodule handling code, with thorough test coverage in t5526.

The patches appear well-structured with clear commit messages explaining both the problem and solution. This seems like a practical quality-of-life improvement for users who work with complex submodule setups during active development. The change is particularly relevant for CI/CD pipelines where temporary upstream inconsistencies might otherwise break workflows unnecessarily.
