This is patch 8/18 in Patrick Steinhardt's series refactoring `setup.c` as part of the ongoing `the_repository` removal effort. The patch converts `enter_repo()` to take an explicit `struct repository *` parameter instead of implicitly using the global `the_repository`.

The change is mechanical but touches several callers across different commands (`receive-pack`, `upload-archive`, `upload-pack`, `daemon`, and `http-backend`). Each caller now passes `the_repository` explicitly to `enter_repo()`. The core logic of `enter_repo()` remains unchanged - it still performs the same repository validation and setup, just using the passed-in repository parameter rather than the global.

This continues the series' pattern of small, focused patches that incrementally remove global state while maintaining backward compatibility. The changes are straightforward and unlikely to be controversial, though they do touch several important server-side commands. The patch follows the same careful design as previous ones in the series, with the global state removal pushed up one level to the callers.
