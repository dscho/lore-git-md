This is patch 7/18 in Patrick Steinhardt's series refactoring `setup.c` as part of the ongoing `the_repository` removal effort. The patch converts `verify_non_filename()` to take an explicit `struct repository *` parameter instead of implicitly using the global `the_repository`.

The change is mechanical but touches several callers across `builtin/checkout.c`, `builtin/grep.c`, `builtin/reset.c`, and `revision.c`, each of which now passes `the_repository` explicitly. The core logic in `verify_non_filename()` remains the same - it still checks whether we're inside a worktree or gitdir and skips verification in those cases - but now uses the passed-in repository parameter rather than the global.

This continues the series' pattern of small, focused patches that incrementally remove implicit state while maintaining backward compatibility. The changes are straightforward and unlikely to be controversial, though they do require updating multiple call sites. The patch demonstrates careful attention to maintaining the existing behavior while moving toward the larger goal of eliminating `the_repository` usage.
