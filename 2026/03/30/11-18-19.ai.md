This is a bugfix patch series addressing incorrect behavior in `receive.denyCurrentBranch=updateInstead` when pushing to bare repositories with worktrees. The series builds on previous discussion that identified a test case showing Git incorrectly rejects pushes when the bare repo's HEAD points to an unborn branch, even when the worktree is clean.

The patch series contains three parts: First, Runxi Yu's test case demonstrating the issue (marked as test_expect_failure in previous iterations). Second, a cleanup of test infrastructure that was interfering with the new test. Third, the actual fix from Pablo Sabater that changes `builtin/receive-pack.c` to check the worktree's HEAD rather than the bare repository's HEAD when determining if staged changes exist.

The core fix refactors the staged changes detection logic to properly handle worktree contexts, removing 24 lines of code while adding more targeted checks. This addresses the root cause where the original implementation was examining the wrong HEAD reference. The changes appear well-scoped to the specific failure case while maintaining the existing behavior for non-worktree scenarios.

This represents the next step in an ongoing thread that began with test case submission and analysis. The series is now proposing a concrete solution to the identified issue, with the test case serving both as verification and documentation of the edge case being fixed. The changes touch sensitive areas of push/receive behavior but appear carefully constrained to the worktree interaction case.
