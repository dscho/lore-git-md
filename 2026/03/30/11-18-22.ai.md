This is a bugfix patch addressing incorrect behavior in `receive.denyCurrentBranch=updateInstead` when pushing to bare repositories with worktrees. The patch completes a series that began with identifying the issue and now provides the solution.

The core change modifies `builtin/receive-pack.c` to properly check the worktree's HEAD rather than the bare repository's HEAD when determining if staged changes exist. This fixes the case where pushes were incorrectly rejected when the bare repo's HEAD pointed to an unborn branch while the worktree was clean. The implementation removes 24 lines of now-unnecessary code and replaces it with a more targeted check of `worktree->head_oid`.

Key technical details:
- Changes the `push_to_deploy()` function to take a `worktree` parameter instead of `work_tree` path
- Updates all child process invocations to use the worktree's path
- Replaces the `head_has_history()` helper with direct `is_null_oid()` check on worktree's HEAD
- Maintains existing behavior for non-worktree cases
- Updates the test case from `test_expect_failure` to `test_expect_success`
