This is a review response from Jeff King (Peff) on Taylor Blau's patch converting MIDX's `keep_hashes` to use `strvec`. Peff raises several technical concerns about the implementation approach.

He questions whether manually manipulating the `strvec` internals (directly accessing `v` and `nr`) is worth the complexity compared to simpler `strvec_push()` operations, noting the number of MIDX layers will always be small. He also spots an unexpected change in string handling (switching from `xstrfmt` to `strbuf`) that seems unrelated to the main conversion.

Peff identifies a memory leak in the original code where `xstrfmt` results were being appended to a `NODUP` string list. He suggests the proper fix would be either using `DUP` with normal append or `NODUP` with `append_nodup`.

The review maintains a constructive tone while being technically thorough, focusing on implementation details rather than the overall approach. This is typical of Peff's reviews - he catches subtle correctness and maintainability issues that others might miss. The feedback will likely lead to a v2 of the patch addressing these points.
