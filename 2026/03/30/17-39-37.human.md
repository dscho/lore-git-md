This is a bugfix patch that corrects premature error reporting in recursive submodule fetches. The patch addresses a timing issue where failures were being logged too early in the fetch process, before retry attempts could complete.

The key change restructures the error handling in `submodule.c` to only record failures after all retry attempts (including the OID-based fallback fetch) have been exhausted. This preserves the existing behavior while making the implementation more correct - a fetch will now only be marked as failed if both the initial ref fetch and subsequent OID-based fetch attempts fail.

The patch extracts common error recording logic into a new `record_fetch_error()` helper function and updates the logic in `fetch_finish()` to handle several cases more carefully: when OID-based retries succeed, when submodules are fetched unconditionally, and when required commits are already present locally. The changes resolve a longstanding NEEDSWORK comment about this behavior.

This is the first of two patches in a series that together will make submodule fetch errors configurable. The implementation looks solid, with clear commit messages and thorough consideration of edge cases. No reviews have been posted yet as the series is newly submitted.
