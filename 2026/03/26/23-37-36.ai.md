This is a refactoring patch that clarifies variable naming in Git's connection handling code. It's the first in a series introducing SSH configuration options, but this particular change stands alone as a code clarity improvement.

The patch renames the `name` parameter to `command` in `connect_git()` and related functions, since the variable actually represents the Git command being sent over the wire (like `git-receive-pack`) rather than a remote name as the original name might suggest. The change affects three files: `connect.c`, `connect.h`, and `transport.c`, with straightforward mechanical updates to both declarations and call sites.

The motivation is clearly explained - the original name was misleading and the new name better reflects the parameter's actual purpose. This is a small but meaningful improvement to code readability that should make the codebase slightly more approachable for future contributors working in the connection handling logic. The change is purely internal and doesn't affect any user-facing behavior.
