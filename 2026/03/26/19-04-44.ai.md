This is the first patch in Jeff King's (Peff) 4-part series addressing const-correctness in Git's revision parsing code, specifically focusing on the handling of range operators (".." and "..."). The patch refactors the `handle_dotdot()` interface to avoid modifying const strings, replacing the previous approach of in-place string munging with allocation-based string copying.

The key changes in this patch:
1. Eliminates the unsafe practice of temporarily modifying const strings by NUL-terminating them in place
2. Introduces `xmemdupz()` to create modifiable copies of string segments when needed
3. Simplifies the interface by passing parsed components (left/right sides, symmetric flag) explicitly rather than reconstructing them from a modified buffer
4. Maintains the same functionality while properly respecting const semantics

The patch touches core revision walking code in `revision.c`, changing about 20 lines while preserving all existing behavior. This represents a structural improvement over the previous casting-based workarounds discussed in the thread, aligning with Junio Hamano's preference for solutions that minimize type system violations.

As the first step in Peff's series, this patch lays the groundwork for the subsequent changes that will apply similar allocation-based fixes to other parts of the revision parsing code. Given Peff's deep expertise in this area and the prior consensus in the thread about this being the right direction, this change appears well-positioned for acceptance.
