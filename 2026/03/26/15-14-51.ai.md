This is the third patch in a 6-part series enhancing Git's `backfill` command for partial clone functionality. The patch adds revision argument support to `git backfill`, allowing users to specify commit ranges, time filters (`--since`), and other standard revision specifications.

The implementation uses `setup_revisions()` to parse arguments, enabling all standard Git revision syntax while maintaining the command's core functionality of downloading missing blobs. The patch includes comprehensive tests covering:
- Basic revision ranges (`HEAD~2..HEAD`)
- Stdin input for revisions
- Various pathspec patterns (prefix, multiple, wildcard)
- Special revision flags (`--all`, `--first-parent`)
- Time-based filtering (`--since`)

Notably, the pathspec handling is marked with TODOs as it currently downloads all blobs rather than limiting to the specified paths - this will be addressed in a future patch. The test suite uses a repository with 54 blobs and complex branching to validate the behavior.

This continues Derrick Stolee's work on improving partial clone performance, building on feedback from previous versions to handle edge cases and add robust testing infrastructure. The patch maintains Junio C Hamano's ack from earlier in the thread.
