This is a const-correctness fix in Git's revision parsing code, part of Jeff King's (Peff) series addressing ISOC23 compiler warnings. The email follows Junio Hamano's approval of the allocation-based approach for handling ".." and "..." range operators in `revision.c`.

Peff acknowledges Junio's correction about a typo in the original patch ("digit" vs "dot") and expands on the technical rationale. He confirms there's no good alternative to making temporary allocations when processing range operators like "..HEAD", as the string literals must remain const. While removing const from the interface would work, it would push the copying burden onto callers. A more thorough solution using ptr/len pairs would be possible but overly invasive.

The discussion shows the project's careful approach to const-correctness - accepting necessary allocations despite initial preferences, with clear technical justification. This patch (and the series) establishes patterns for future work while maintaining existing functionality. The maintainer's approval suggests this direction is now considered the right solution.
