Feature patch in Adrian Ratiu's parallel hook execution series (v5 9/12) that adds warnings for misconfigured hook job counts. This patch specifically addresses cases where users might confuse hook friendly-names with event names when setting parallel job counts.

The patch introduces a warning system that detects when `hook.<name>.jobs` is set for a name that appears to be a hook friendly-name (indicated by the presence of `.command`, `.event`, or `.parallel` configurations) rather than an actual event name. This helps users avoid configuration mistakes by clearly indicating when their job count settings will be ignored due to namespace confusion.

Key technical components:
- New `is_friendly_name()` helper function to detect hook friendly-names by checking for related config keys
- `warn_jobs_on_friendly_names()` function that scans the event jobs configuration and issues warnings for any names that look like friendly-names
- Comprehensive test coverage verifying warnings appear for various friendly-name patterns but not for legitimate event names

The implementation builds on Junio Hamano's suggestion to help users distinguish between the two configuration namespaces. This is part of the broader parallel hook execution infrastructure that includes global, per-hook, per-event, and CLI job count controls. The warning system helps maintain the clear separation between these configuration layers while providing helpful feedback when users might be confused.
