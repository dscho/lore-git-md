This is a documentation patch updating the man pages for `git format-patch` to clarify behavior around the `--commit-list-format` option and cover letters. It's the second version of a patch that follows up on feedback from Junio C Hamano.

The patch makes several documentation improvements:
1. Clarifies that when neither `--commit-list-format` nor `format.commitListFormat` is set, the default is `shortlog` (previously only mentioned the config would be used if present)
2. Updates the description of `--cover-letter` to use "commit list" rather than "shortlog" since the format is now customizable
3. Adds more detail about format string parsing - specifically that any string containing '%' is treated as a custom format without validation of placeholders
4. Explicitly states that only command-line `--commit-list-format` (not the config variable alone) implies `--cover-letter`

The changes touch both the config documentation (format.adoc) and command documentation (git-format-patch.adoc), with the author noting they've made the explanations more verbose than Junio originally suggested to help users better. This appears to be part of an ongoing series (mf/format-patch-commit-list-format) that introduced flexible commit list formatting options.

The patch is well-scoped and addresses the feedback from the previous round, making the documentation more precise about implementation details while maintaining clarity. The commit message clearly explains the rationale for each change.
