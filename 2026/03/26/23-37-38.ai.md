This is the third and final patch in a feature series introducing per-remote and per-namespace SSH configuration options. The patch implements the core functionality for managing SSH identities and options through Git config, building on the preparatory refactoring from the first two patches.

The implementation adds two new structs (`cnx_context` and `ssh_options`) to cleanly manage the configuration hierarchy, which follows this precedence order:
1. Per-remote settings (`remote.<name>.sshIdentityFile` and `remote.<name>.sshOpts`)
2. Per-namespace settings (`core.sshIdentityFile.<owner>` and `core.sshOpts.<owner>`)
3. Global defaults (`core.sshIdentityFile` and `core.sshOpts`)

Notable behaviors include automatically adding `-F /dev/null` when using identity files without custom SSH options (to prevent picking up unintended identities from `~/.ssh/config`), and including `IdentitiesOnly=yes` when an identity file is specified. The patch comes with extensive tests in `t57xx-ssh-options-config.sh` covering various configuration scenarios across different Git commands (fetch, push, ls-remote etc.).

The implementation maintains backward compatibility and focuses on OpenSSH support. As noted in previous patches, some limitations remain - notably no support for separate push/pull URIs. The documentation updates clearly explain the new configuration options and their precedence rules.

This appears to be a well-considered implementation that solves a real pain point for users managing multiple Git identities. The thorough test coverage and clear commit message suggest it's production-ready work. The main discussion points from previous patches (configuration organization and push/pull URI support) remain open but don't block merging this solid implementation.
