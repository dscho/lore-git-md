Thread identity: Documentation discussion about `git stash` command behavior versus documentation, focusing on when the `push` subcommand is required for various options and pathspecs.

Core problem: The SYNOPSIS in git-stash documentation inaccurately suggests `push` is mandatory for most options, when in reality non-option arguments (pathspecs) are the only elements that need explicit `push` (or `--` disambiguation). Options like `-m/--message` and `-u/--include-untracked` work with both `git stash` and `git stash push` forms. The discussion now includes clarifying that `git stash -- <pathspec>` is valid shorthand for `git stash push -- <pathspec>`.

The fix requires updating both the SYNOPSIS section and command help text to properly separate standalone `git stash` from `git stash push` cases while showing options work with both, and explicitly documenting the `--` disambiguation syntax.
