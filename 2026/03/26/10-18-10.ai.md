This is a feature patch (3/12 in v5) from Adrian Ratiu's parallel hook execution series, introducing the global `hook.jobs` configuration option. The patch lays groundwork for parallel hook execution by adding infrastructure to parse and cache a default job count that will later be overridden by more specific per-hook and per-event settings.

The implementation adds a `hook_jobs` field to `struct repository` to store the parsed value from config, with validation that rejects zero and non-integer values (emitting warnings for invalid inputs). The change follows Git's config parsing patterns, using the new `git_parse_uint()` helper introduced earlier in the series. Documentation is added to `Documentation/config/hook.adoc` explaining the purpose of the setting.

The patch is well-contained, touching only hook configuration plumbing while leaving the actual parallel execution logic for later in the series. It demonstrates good attention to edge cases with proper validation and warning messages. The change builds on prior work in the series (notably the unsigned int parsing infrastructure) while maintaining clean separation of concerns - this commit purely handles config parsing without yet implementing the parallel execution behavior that will consume the value.

As part of an already-reviewed series with maintainer approval, this patch appears ready for integration, providing a solid foundation for the more complex parallel execution controls that follow in subsequent commits. The implementation aligns with Git's established patterns for config handling and repository state management.
