This is the third and final patch in Phillip Wood's series to eliminate `the_repository` usage from worktree subsystem functions, part of the ongoing global variable removal effort. The patch removes NULL worktree handling from `get_worktree_git_dir()`, requiring all callers to explicitly pass a worktree structure.

The change converts a silent NULL parameter into a BUG() assertion, tightening the API contract. Phillip's analysis shows all existing callers either loop over all worktrees (where NULL would be incorrect) or already pass non-NULL worktrees. The patch follows naturally from the previous changes that made `is_current_worktree()` require an explicit worktree parameter.

The diff is minimal - just removing the NULL case and updating the function's documentation - but represents an important step in making worktree behavior more explicit and less dependent on global state. The series as a whole improves consistency when dealing with multiple repositories and worktrees, particularly around ref store handling. This final patch completes the transition by eliminating the last vestige of implicit current-worktree behavior in the worktree API.
