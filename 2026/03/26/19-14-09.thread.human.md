Justin Tobler's series to bring consistent signature handling between commits and tags in `git fast-import` is now complete with this fifth patch. The series started by refactoring error handling in `git fast-export` and systematically implemented three signature validation modes (strip-if-invalid, sign-if-invalid, and abort-if-invalid) for both commits and tags. 

The final patch adds the last remaining mode - abort-on-invalid for tags - which causes the import to stop immediately if any tag signature fails verification. This matches the behavior already available for commits. The implementation is clean and well-tested, covering OpenPGP, X.509, and SSH signatures, including edge cases like forged signatures. 

With all three modes now implemented for both object types, users have granular control over how signed objects are handled during imports. The series builds on prior work and maintains parallel handling between commit and tag processing throughout. The thorough test coverage across signature types and edge cases gives confidence in the implementation. This appears ready for merging as it completes the feature set without leaving any loose ends.
