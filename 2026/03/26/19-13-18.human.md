This is the third patch in Jeff King's (Peff) series addressing const-correctness in Git's revision parsing code, specifically focusing on parent mark handling ("^@", "^!", "^-"). The patch continues the series' approach of replacing in-place string modifications with allocated copies to properly respect const semantics.

The change targets the revision parser's handling of parent marks like "HEAD^-" where Git previously modified the input string by inserting NUL terminators. Peff's solution makes temporary copies via xmemdupz() when needed, adding cleanup for the allocated strings. The patch preserves the existing behavior (including some edge cases in mark ordering) while making the code safer by avoiding modification of const strings.

Notable aspects include:
- Three separate allocations (arg_minus_at, arg_minus_excl, arg_minus_dash) to handle different mark types
- Careful preservation of the existing mark processing order and fallback behavior
- Fixes an incidental bug where original strings weren't restored after parsing
- The changes are focused and surgical (25 lines modified in revision.c)
- Follows the pattern established in earlier patches of the series
- Includes Peff's characteristic thorough analysis of edge cases and alternatives considered

This patch represents a clear improvement over the previous const-violating approach and aligns well with the series' goal of proper const handling through allocation rather than casting. Given Peff's expertise and the code's careful construction, it seems likely to be accepted as part of the overall solution.
