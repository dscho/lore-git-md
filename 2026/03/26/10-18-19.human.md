This is the final patch in Adrian Ratiu's feature series introducing parallel hook execution, now in its fifth iteration. The patch adds support for `-1` as a special value in hook job count configurations (`hook.jobs`, `hook.<event>.jobs`, and the `-j` CLI flag) to automatically use all available CPU cores, matching conventions in other subsystems like `fetch.parallel`.

The implementation resolves `-1` to `online_cpus()` at parse time, ensuring the rest of the code always works with positive counts. Invalid values (like `-2`) are rejected with warnings for config settings or fatal errors for CLI usage. The patch includes comprehensive tests verifying the behavior across all configuration points and edge cases.

This change builds on the series' earlier work establishing parallel execution controls, with all core components already having maintainer approval from Junio Hamano. The implementation is clean and consistent with Git's existing job-count handling patterns, though the special pre-push hook output merging (from earlier patches) remains a notable exception that may warrant future refinement.

The patch appears well-tested and ready for integration, completing the parallel hooks feature with a familiar configuration option for automatic CPU core detection.
