This is a refactoring patch addressing compiler warnings related to const-correctness with string functions. Michael Gruber fixes cases where string functions like `strchr()` and `strstr()` return `const char*` when given const inputs (a behavior that varies by glibc version and compiler flags), but the code expects non-const pointers.

The patch makes the minimal change needed to silence the warnings by adding explicit casts to `(char *)` when assigning the results of these functions to non-const pointers. The changes are mechanical and touch several files (`builtin/config.c`, `http.c`, `remote.c`, etc.), all following the same pattern. The commit message clearly explains the technical background and shows an example warning.

This appears to be a straightforward and uncontroversial change - it doesn't modify behavior, just makes the code more portable across different compiler/glibc versions. The patch is part of a 6-patch series, though this first one stands alone as addressing the "simple cases."
