This is a feature patch in a series introducing parallel hook execution, specifically adding a `-j/--jobs` command-line option to control parallelism. The patch builds on Adrian Ratiu's earlier configurable hooks work and has maintainer approval from Junio C Hamano.

The patch adds a `-j` flag to `git hook run` that overrides both the global `hook.jobs` config and per-hook `hook.<name>.parallel` settings, forcing parallel execution when requested. The implementation includes warnings when non-parallel hooks are run in parallel due to the flag, and comprehensive tests verify:
- TTY behavior differs between serial (-j1) and parallel (-jN) modes
- Output streams remain properly ordered during parallel execution
- The flag correctly overrides config settings
- Warnings appear for hooks not marked as parallel-safe

The tests use a new `write_sentinel_hook` helper to verify actual parallel execution timing. While most of the series has already been acked, this patch solidifies the CLI interface for controlling parallelism, completing the configuration hierarchy (CLI > per-hook > global). The implementation appears robust with clear documentation and thorough test coverage.
