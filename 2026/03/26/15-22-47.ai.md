This is a refactoring patch addressing compiler warnings about discarded const qualifiers when using string functions like strchr(). The patch is part of a 6-patch series (position 1/6) focused on const-correctness issues.

The core issue stems from newer glibc versions and C23 standards where string functions may return const pointers when given const inputs. This causes warnings when the return value is assigned to a non-const pointer. The patch fixes this by adding explicit casts to (char *) in several locations across multiple files (builtin/, http.c, refs/, etc.) where strchr(), strstr(), and similar functions are used with non-const pointers.

The changes are mechanical and straightforward - each case simply adds a cast to silence the warning while maintaining the existing behavior. The patch touches several subsystems but makes no functional changes. The commit message clearly explains the technical background and shows an example warning that motivated the changes.
