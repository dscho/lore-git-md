This thread documents improvements to the documentation around `git format-patch`'s `--commit-list-format` option and related configuration. The original patch updated the man pages to clarify that when neither the command-line flag nor the `format.commitListFormat` config is set, the default behavior is to use `shortlog` format (previously the documentation only mentioned the config would be used if present). It also updated the `--cover-letter` description to use the more general "commit list" terminology rather than "shortlog" since the format is now customizable.

Junio C Hamano has reviewed the documentation changes and suggested two refinements to make the behavior even clearer. First, he proposed rewording the format string parsing section to avoid implying validation of placeholders - the documentation should state plainly that any string containing '%' is treated as a custom format. Second, he noted the need to clarify that only the command-line option (not the config alone) triggers cover letter generation. These changes maintain the original goal of precise documentation while addressing potential user confusion points. The discussion shows careful attention to technical writing details that will help users understand the behavior of this relatively new formatting system.
