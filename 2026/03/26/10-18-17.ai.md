This is a refactoring patch in Adrian Ratiu's parallel hook execution effort (v5 10/12). The change moves the `is_known_hook()` function from being a static helper in `builtin/hook.c` to being a public function in `hook.c` with a proper declaration in `hook.h`. This prepares for the next patch which will use this function to detect and reject hook friendly-names that collide with known event names.

The implementation is straightforward - it checks if a given name matches any of Git's built-in hook names by iterating through the `hook_name_list`. The patch makes two small improvements while moving it: changing the return type from `int` to `bool` for clarity, and renaming the iterator variable from `p` to `h` to better reflect its purpose. The Makefile is updated to ensure `hook.o` gets rebuilt when `hook-list.h` changes.

This is a mechanical change with no behavior difference, just code organization to support upcoming functionality. The patch is already part of a well-reviewed series that has maintainer approval for the core technical components. This particular change appears uncontroversial and correctly implemented.
