This is a test infrastructure patch from Jeff King addressing shell compatibility issues that surfaced after Junio Hamano's series to enable stricter error detection in the test suite. The discussion focuses on handling signal tests (particularly SIGPIPE) across different shells when using `set -e`.

Jeff confirms Junio's proposed workaround (`&& echo 0 || echo $?`) for the SIGPIPE test in t0005-signals.sh is technically better, though functionally equivalent for this specific case. He reports seeing multiple test failures in CI after applying the `set -e` changes, including:
- A simple ACL test that needs `|| true` to handle non-Linux systems
- Potential issues with `test_done` when no tests run (e.g., in skip_all cases)

The email highlights the ongoing tension between the benefits of strict error checking and the practical challenges of shell compatibility. While individual fixes are possible (like the ACL case), Jeff's experience suggests broader fallout that may require more investigation. The thread shows the maintainers carefully weighing whether this is sustainable long-term or if a different approach might be needed.
