This is a feature patch (7/12 in v5 series) introducing a `-j/--jobs` command-line option for `git hook run`, allowing direct control over parallel hook execution without relying solely on configuration. The patch builds on the parallel hooks infrastructure established earlier in the series.

The new `-j` flag lets users specify the number of hooks to run simultaneously, overriding both the global `hook.jobs` config and per-hook `hook.<name>.parallel` settings. The implementation includes:
- CLI option parsing in `builtin/hook.c`
- A warning when forcing parallel execution of hooks not explicitly marked as parallel-safe
- Comprehensive test coverage verifying:
  - TTY behavior differs between serial (-j1) and parallel (-jN) execution
  - Output remains properly grouped when running in parallel
  - The flag correctly overrides config settings
  - Warnings appear for non-parallel hooks forced to run concurrently

Notable technical details:
- Parallel execution redirects stdout to stderr (via existing `merge_output_if_parallel()`)
- The warning system helps users understand when they're overriding safety constraints
- Tests use the `write_sentinel_hook` infrastructure to verify actual parallel behavior

The patch appears well-integrated with the series' existing parallel execution controls and maintains the safety constraints for hooks that cannot run in parallel (like commit-related hooks). Emily Shaffer's sign-off indicates this builds on her prior work in the area.
