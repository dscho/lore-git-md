This is a bugfix patch addressing const-correctness violations in Git's argument parsing code. The patch reveals that Git has been silently mutating `const char*` arguments in place when handling revision ranges (like `..` and `^@` syntax) and parent shorthands. The changes add explicit casts to acknowledge this behavior in two key areas:

1. In `builtin/rev-parse.c`, the functions `try_difference()` and `try_parent_shorthands()` are modified to take non-const `char*` parameters, with callers now explicitly casting the const arguments.

2. In `revision.c`, several `strstr()` calls that modify their input strings now have their results cast to non-const `char*`.

The commit message references "ISOC23" (likely meaning C23 standard compliance checking) as the mechanism that uncovered these violations. The changes don't fundamentally alter behavior - they make explicit what was already happening implicitly, effectively documenting these intentional violations of const-correctness.
