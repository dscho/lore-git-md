This is a feature patch proposing a new `git-format-rev` builtin command, building on recent work that added `--format` support to `git name-rev`. Kristoffer Haugsbakk is taking the existing name-rev formatting capability and proposing to extract it into a dedicated command.

The patch comes in response to Junio's "What's cooking" query about the `kh/name-rev-custom-format` topic, which added format specifiers to `git name-rev`. Rather than keeping this as an extension to name-rev, the author suggests creating a new command focused specifically on revision formatting.

The approach appears to follow Git's pattern of splitting functionality into focused commands when features grow beyond their original scope. The implementation would reuse code from name-rev.c but present a cleaner interface. This seems like a logical next step after the format capability was proven in name-rev first.

The patch is at an early stage - the author mentions they're "working on" the functionality rather than presenting finished code. Given the recent addition of the format capability to name-rev, this follow-up proposal makes sense but will need review of the new command's design and interface. The change touches core revision-walking code, so careful consideration of the API boundaries will be important.
