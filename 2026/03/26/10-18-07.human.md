This is a feature patch series (v5) introducing parallel hook execution, building on Adrian Ratiu's prior configurable hooks work. The 12-patch series has expanded from its original 4-patch version to incorporate extensive feedback and additional functionality.

The series establishes comprehensive controls for parallel hook execution:
- Global `hook.jobs` default (now supporting `-1` for automatic CPU core detection)
- Per-hook `hook.<name>.parallel` flags
- CLI `-j/--jobs` override (which Patrick Steinhardt confirmed overrides all config settings)
- Per-event `hook.<event>.jobs` settings
- Per-event `hook.<event>.enabled` master switch

The implementation handles output streams (stdout redirected to stderr except pre-push hook) with extensive test coverage in t/t1800-hook.sh. The series includes safety constraints for non-parallelizable hooks via RUN_HOOKS_OPT_INIT_FORCE_SERIAL.

Key changes in v5 address feedback from Junio Hamano and Patrick Steinhardt:
- Replaced unsigned int:1 with proper bool types
- Renamed caching struct from event_disabled to disabled_events
- Added back a dropped commit
- Improved handling of hook name/event name collisions
- Added warnings for unparseable configs
- Documented CLI override precedence more clearly

The series appears well-structured with clear commit messages and motivation. All core technical components have maintainer approval, with the final refinements ensuring unambiguous configuration and consistency with Git's conventions. The implementation touches several builtin commands (am, checkout, clone, etc.) to update their hook calls.
