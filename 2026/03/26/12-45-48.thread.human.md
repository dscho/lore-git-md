This thread clarified the behavior and documentation of `git stash` command syntax, particularly around when the `push` subcommand is required. The discussion established that while options like `-m` (message) and `-u` (include-untracked) work with either `git stash` or `git stash push`, pathspecs still need explicit disambiguation via either `push` or `--`. Quentin Bernet submitted the final documentation patch that accurately reflects this behavior in both the man page and built-in help text.

Junio Hamano has approved the technical approach, though he notes the commit message could better highlight the pathspec disambiguation requirement upfront - the very issue that prompted this discussion. The thread also identified a potential future enhancement to make `git stash -m foo <pathspec>` work without explicit push, but this parser improvement remains separate from the current documentation fix. With maintainer approval and testing verification by D. Ben Knoble and Mirko Faina, this documentation clarification is now complete. The exchange serves as a useful case study in writing commit messages that anticipate likely points of confusion.
