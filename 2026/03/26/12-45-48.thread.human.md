This thread examines a discrepancy between how `git stash` is documented versus how it actually behaves. The core issue is that the man page incorrectly suggests most options require the `push` subcommand, when in reality only pathspec arguments need this (or can use `--` for disambiguation). Options like `-m` for messages or `-u` for including untracked files work fine with just `git stash`.

Quentin Bernet, a first-time contributor, proposed documentation fixes to clarify this. Junio Hamano confirmed the implementation indeed differs from the docs, while D. Ben Knoble and Mirko Faina verified through testing that only pathspecs require special handling. The latest development came from Junio, who pointed out that `git stash -- <pathspec>` is valid shorthand for `git stash push -- <pathspec>`, particularly useful when filenames might conflict with subcommand names (like a file called "pop"). 

The discussion now centers on how best to represent these syntax variations in the documentation - whether to explicitly call out pathspec handling and the `--` disambiguation, while maintaining clarity about which forms work with options versus pathspecs. The patch appears headed for acceptance once these final documentation wording questions are resolved. This ties into broader efforts to improve Git's consistency and accuracy, particularly in command syntax documentation.
