This thread clarified the documentation for `git stash` to accurately reflect when the `push` subcommand is required versus optional. The discussion started with confusion around the SYNOPSIS section, which the documentation incorrectly suggested `push` was mandatory for most options when in fact only pathspecs require it (or `--` disambiguation).

Quentin Bernet submitted a v2 patch that Junio Hamano has now approved. The updated documentation makes clear that:
- Options like `-m` (message), `-u` (include-untracked), and `-p` (patch) work with both `git stash` and `git stash push`
- Pathspecs still need either explicit `push` or `--` 
- The incorrect special-case claim about `-p` being an exception was removed

Junio confirmed the patch properly aligns the actual behavior in `builtin/stash.c` with both the man page and built-in help text. While he noted the test suite doesn't explicitly verify this documentation (since the behavior itself isn't changing), the patch is complete and will be merged. Any potential future improvements to make the parser more lenient (like accepting `git stash -m foo <pathspec>` without explicit push) would be separate work. The thread is now resolved with accurate documentation of the current behavior.
