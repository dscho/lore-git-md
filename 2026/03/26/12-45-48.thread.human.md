This thread examines a documentation discrepancy in `git stash`'s command syntax, specifically around when the `push` subcommand is required. Quentin Bernet's patch initially corrected the man page and code to show that options like `-m/--message` work with `git stash push` (not just `git stash save`), adjusting the syntax notation. D. Ben Knoble questioned whether the original bracketing was incorrect, noting the help text implies `push` is required for most options. Mirko Faina then demonstrated that while pathspecs require `push`, many options (like `--include-untracked`) work fine without it—contrary to the documentation.

Junio Hamano has now joined the discussion, confirming Faina's observation that the current behavior accepts option flags without `push`, despite the SYNOPSIS suggesting otherwise. He notes the documentation inaccurately implies all options (except `-p`) require `push`, when in reality only non-option arguments do. While Junio doesn't dictate a specific resolution, his input clarifies that the docs don't match the actual behavior. The open question remains whether to adjust the documentation, modify the command's rules, or find a compromise. The discussion involves `Documentation/git-stash.txt` and `builtin/stash.c`, with key contributions from Bernet, Knoble, Faina, and now the maintainer.
