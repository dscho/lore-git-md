This is the final patch in a feature series (v5 12/12) introducing parallel hook execution, building on Adrian Ratiu's prior configurable hooks work. The patch adds support for `-1` as a special value in hook job count configurations (`hook.jobs`, `hook.<event>.jobs`, and the `-j` CLI flag) to automatically use all available CPU cores, matching conventions in other subsystems like `fetch.parallel`.

The implementation resolves `-1` to `online_cpus()` at parse time, ensuring the rest of the code always works with positive counts. Invalid values (0, -2, etc.) are rejected with warnings for config settings and fatal errors for CLI usage. The patch includes comprehensive tests verifying the behavior across config, per-event, and CLI contexts, including TTY handling and output ordering.

This change completes the series' job count configuration system, which now supports:
- Global `hook.jobs` default
- Per-hook `hook.<name>.parallel` flags
- CLI `-j/--jobs` override
- Per-event `hook.<event>.jobs` settings
- Automatic core detection via `-1`

The series has undergone extensive review, with all core components receiving maintainer approval from Junio C Hamano. This final patch incorporates feedback to ensure consistent behavior with Git's existing job-count conventions while maintaining the safety constraints for non-parallelizable hooks.
