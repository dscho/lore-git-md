This is a const-correctness fix for the config subsystem, part of the ongoing effort to address ISOC23 compiler warnings about const pointer handling. Jeff King (Peff) follows up on earlier discussion with Junio C Hamano about the preferred approach for handling modifications to strings that will ultimately be stored in const-marked structures.

The patch modifies `builtin/config.c` to properly handle URL-matching configuration sections. The key change replaces a pattern that involved casting away constness with a cleaner approach using a separate non-const pointer during string manipulation. Specifically, it introduces a local `section` variable to track the allocated string while modifications occur, then assigns the const `config.section` pointer to this same memory once the string is in its final form.

This implements the pattern Junio endorsed earlier in the thread - avoiding casts by maintaining clear ownership of the writable string during modification phases. The change affects how Git handles the '.' separator between subsections and keys in URL-matching config entries, fixing an implicit const violation in the `strchr()` operation while preserving all existing functionality.

The patch is small (7 lines changed) but demonstrates the architectural approach the project is converging on for these const-correctness issues: proper allocation tracking rather than casting. As part of Peff's planned series to address ISOC23 warnings, this particular fix focuses narrowly on the config URL-matching code path while establishing a pattern likely to be reused elsewhere.
