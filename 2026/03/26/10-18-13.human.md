This is a feature patch in a series introducing parallel hook execution, specifically identifying and enforcing serial execution for hooks that cannot safely run in parallel. The patch marks several hooks as non-parallelizable by initializing them with RUN_HOOKS_OPT_INIT_FORCE_SERIAL, which overrides any parallel execution settings.

The affected hooks are those that operate on shared resources or state:
- Message-related hooks (applypatch-msg, prepare-commit-msg, commit-msg) that modify commit messages in-place
- Hooks that interact with working tree, index, or repository state (pre-commit, post-checkout, push-to-checkout, post-commit)

The patch updates both the implementation and documentation, adding a clear list of these special-case hooks to the hook.adoc config documentation. It also includes a test case verifying that parallel settings are properly ignored for force-serial hooks like pre-commit.

This is part of Adrian Ratiu's ongoing work to modernize Git's hook system, building on prior configurable hooks infrastructure. The patch has been reviewed and signed off by both Emily Shaffer (original author) and Adrian Ratiu (series maintainer). The changes appear straightforward and well-justified, with clear documentation of the constraints.
