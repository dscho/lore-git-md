This is a feature patch in a series introducing parallel hook execution. Patch 8/12 adds per-event job count configuration, allowing users to override the global `hook.jobs` setting for specific hook events. 

The patch enables fine-grained control by introducing `hook.<event>.jobs` config keys. For example, you could configure `post-receive` hooks to run with 4 parallel jobs while keeping other events at the global default. The implementation carefully handles precedence rules - per-event jobs override the global setting but still respect the `hook.<name>.parallel` flags that determine which individual hooks can run in parallel.

The changes include documentation updates, core logic in hook.c to look up and apply per-event job counts, repository struct additions to cache these settings, and comprehensive tests verifying the behavior. The tests cover cases like per-event overrides forcing serial execution even when the global setting allows parallel, and ensuring parallel execution still requires explicit `hook.<name>.parallel=true` flags.

This continues Adrian Ratiu's work on configurable hooks, building on prior patches that established the parallel execution infrastructure.
