This is a small UX improvement patch in Christian Couder's larger series on URL-based whitelisting for promisor remotes. The patch clarifies warning messages in `should_accept_remote()` to explicitly state when a promisor remote is being ignored, rather than just explaining why.

Patrick Steinhardt's review notes that the change makes sense but questions whether there should be corresponding test updates to verify the new warning messages. The patch itself is straightforward - it just adds ", ignoring this remote" to two existing messages that warn about invalid or mismatched remote URLs. This helps users better understand the consequences when a promisor remote is rejected.

As the fourth patch in a 16-part series, this is a minor but thoughtful improvement to error messaging that fits into the broader effort to make promisor remote configuration more robust and user-friendly. The change is uncontroversial and likely to be accepted once any test coverage questions are addressed.
