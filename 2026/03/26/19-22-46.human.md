This is a follow-up in the discussion about revision formatting functionality, where Kristoffer Haugsbakk responds to Junio Hamano's question about why a new `git-format-rev` command is needed rather than extending existing tools. 

Kristoffer explains that he initially didn't want to create another builtin but found existing commands unsuitable for the use case. He suggests that if `git log` could be modified to produce one output per input line (like `git name-rev`) and avoid deduplication, that might solve the problem without needing a new command. The email shows Kristoffer adapting his position in response to Junio's feedback, moving away from the separate command approach toward exploring how existing tools might be extended instead.

The exchange highlights the project's preference for extending existing commands where possible, with Kristoffer now investigating whether `git log` can be adjusted to meet the requirements.
