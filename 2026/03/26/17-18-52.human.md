This is a follow-up discussion in the const-correctness patch series addressing ISOC23 compiler warnings. Junio C Hamano is reviewing Michael J Gruber's patch that deals with `bsearch()` behavior changes in ISOC23, specifically in the pseudo-merge commit lookup code.

Junio points out that the patch's explanation is unclear about why the cast is needed - the issue stems from ISOC23 making `bsearch()` preserve const qualifiers from its input array, which affects the case when searching through `pm->commits`. The current patch adds an explicit cast to maintain the existing non-const return type, but Junio suggests the commit message should better explain this ISOC23 context for future readers who might encounter this change through tools like `git blame`.

The discussion highlights the tension between maintaining compiler compliance and keeping code understandable. While the technical change is small (a single cast addition), Junio emphasizes the importance of documentation to explain the ISOC23 motivation behind what might otherwise look like an arbitrary cast. This continues the thread's theme of balancing compiler requirements with code clarity, though here the focus is more on commit message quality than the technical approach itself.
