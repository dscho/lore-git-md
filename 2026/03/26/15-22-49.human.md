This is part 3 of a 6-part series addressing const-correctness issues triggered by ISOC23's stricter string handling. The patch makes mechanical adjustments to two files where non-const pointers were being implicitly assigned from const-aware string functions.

The changes add explicit casts in `http-push.c` and `run-command.c` when using `strchr()` on const strings, where the result needs to be stored in non-const pointers. The author notes this is a pragmatic solution rather than introducing new const-aware data types, as some existing structures (like string_list's util member) aren't designed for const correctness. 

The modifications are straightforward and focused - just adding `(char *)` casts where needed to maintain existing behavior while satisfying the new compiler warnings. This continues the series' theme of minimal, targeted changes to adapt to ISOC23 without deeper architectural changes. The patch appears well-contained and unlikely to introduce new issues, though reviewers may want to verify the specific casting locations.
