This is a refactoring patch in Adrian Ratiu's parallel hook execution series (v5 10/12). The change moves the `is_known_hook()` function from being a static helper in `builtin/hook.c` to a public function in `hook.c` that can be used throughout the codebase. 

The patch makes the function available for reuse by exporting it via `hook.h` and changes its return type to `bool` for clarity. The implementation remains functionally the same - it checks if a given hook name exists in Git's list of known hooks. This refactoring enables the next patch in the series to use this function to detect and reject hook friendly-names that collide with known event names.

The change is straightforward and mechanical, with proper Makefile updates to handle the moved dependency on `hook-list.h`. The commit message clearly explains the motivation and the patch follows Git's coding style. This appears to be a preparatory change for the more substantial friendly-name collision detection coming in the next patch.
