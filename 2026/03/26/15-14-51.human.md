This is the third patch in a 6-part series enhancing Git's `backfill` command for partial clone functionality. The patch focuses on adding revision argument support to `git backfill`, allowing users to specify commit ranges, time filters, and other revision-limiting options.

The key changes in this patch:
- Uses `setup_revisions()` to parse revision arguments, enabling standard Git revision syntax like `HEAD~2..HEAD`, `--all`, and `--since=<date>`
- Maintains backward compatibility by defaulting to `HEAD` when no revisions are specified
- Adds comprehensive tests covering various revision specification methods (direct arguments, stdin, pathspecs)
- Documents that the command accepts standard `git-rev-list` options

The implementation builds on the series' preparatory work to handle unknown arguments safely and manage path manipulation correctly. While the pathspec support is noted as incomplete (currently downloading all blobs regardless of pathspec), this will be addressed in a future patch. The test suite now includes a complex repository structure with 54 blobs across multiple branches to validate the revision handling.
