This is a review response from Junio Hamano on the final patch in Michael Gruber's const-correctness series targeting ISOC23 compliance. The patch deals with string mutation in revision parsing code.

Junio notes that the patch takes two different approaches to handling const strings that are temporarily modified: in `builtin/rev-parse.c` the functions are changed to take non-const `char*` parameters, while in `revision.c` the changes are made through casts within the functions. He questions this inconsistency, suggesting the `revision.c` functions should perhaps also be updated to take non-const parameters for clarity.

The core issue involves Git's revision parsing code temporarily modifying input strings (like inserting NULs into ".." or "^@" sequences) while ultimately restoring them. Junio observes that while this is safe when callers pass writable strings, it could break if callers pass read-only strings based on the const signature. He seems to favor the more honest approach taken in `rev-parse.c` of declaring the functions as taking mutable strings.

This is a technical review focused on implementation consistency rather than rejecting the approach - the series appears headed for acceptance with minor adjustments. The changes are mechanical const-correctness fixes rather than functional modifications, continuing the theme of the overall series.
