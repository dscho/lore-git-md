This is a bug report from Jeff King (Peff) about an edge case in Junio C Hamano's test infrastructure series that enables "set -e" (exit on error) early in test execution. The change causes unexpected behavior in two test scripts (t0005 and t3600) when run under dash (but not bash), due to differences in how command substitution interacts with "set -e" and the && operator.

The core issue involves signal handling tests that check for SIGPIPE (signal 13) by capturing the exit status of a command that should fail. With "set -e" enabled, dash's behavior differs from bash's when the subshell exits, causing the status capture to fail. Jeff provides a detailed analysis of the shell behavior and demonstrates the problem with minimal test cases.

While Jeff suggests a possible fix (modifying the test to use `||` instead of `;`), he notes it's not ideal as it would mask successful cases. The issue highlights a subtle interaction between shell behaviors that wasn't caught in earlier review. This appears to be the first report of platform-specific behavior in the otherwise finalized series.

The email maintains a constructive tone typical of Jeff's technical contributions, focusing on clearly explaining the problem rather than criticizing the change. It provides Junio with the information needed to decide whether to adjust the series or accept the dash-specific behavior as a known limitation.
