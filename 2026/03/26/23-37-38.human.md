This is the final patch in a feature series adding per-remote and per-namespace SSH configuration options. The patch implements the core functionality after the preparatory refactoring in earlier patches.

The change allows configuring SSH identity files and options at three levels of precedence: per-remote (highest priority), per-namespace (based on repository path), and globally (lowest priority). This solves a common pain point for users managing multiple Git forge accounts, who previously needed workarounds like SSH config files or wrapper scripts.

Key implementation details:
- Introduces `cnx_context` to track remote name and repository owner
- Adds `ssh_options` struct to manage resolved configuration
- Automatically adds `-F /dev/null` when using identity files without custom SSH options for safety
- Includes comprehensive tests covering various configuration scenarios

The patch maintains backward compatibility and appears well-structured with clear documentation. Limitations include no support for separate push/pull URIs and OpenSSH-only support. The thorough test coverage in t57xx-ssh-options-config.sh suggests this is production-ready work.

This completes the series that began with preparatory refactoring (patch 1 renamed variables for clarity, patch 2 plumbed remote names through the connection code). The implementation looks solid and addresses a real usability need for multi-account workflows.
