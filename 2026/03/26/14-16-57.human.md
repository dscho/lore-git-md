This is the first patch in a 3-part series continuing the `the_repository` removal effort, specifically targeting worktree subsystem functions. Phillip Wood builds on his previous work to eliminate remaining uses of the global `the_repository` in worktree-related code.

The patch focuses on `is_current_worktree()`, changing it to compare against the worktree's own repository (`wt->repo`) instead of the global `the_repository`. This fixes a subtle issue where worktrees weren't properly recognized as "current" when their repository wasn't `the_repository`. The commit message provides historical context about the `is_current` field's origins in 2016 and explains how the current behavior can cause `die_if_checked_out()` to incorrectly fail to skip the current worktree.

The changes affect both core worktree functionality and the `git worktree add` command. The patch has already undergone review from Patrick Steinhardt and Junio Hamano, with feedback incorporated in this v3 iteration (expanded commit messages, fixed indentation). The discussion has surfaced important technical details about worktree semantics, particularly around the definition of "current worktree" behavior when dealing with multiple repositories.
