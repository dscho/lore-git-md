This is a const-correctness refactoring in Git's revision parsing code, part of Jeff King's (Peff) ongoing series to address ISOC23 compiler warnings. The patch simplifies the `handle_dotdot()` interface that processes range operators (".." and "...") by eliminating unsafe const-cast patterns and replacing them with proper string allocation.

The key improvement is moving from in-place string modification (which risked segfaults with string literals) to using `xmemdupz()` for temporary copies. The change makes the code both safer and clearer by explicitly passing parsed components rather than reconstructing them from a modified buffer. Junio Hamano acknowledges the allocation is necessary given the constraints, though he initially hoped to avoid it.

This is the first of four patches in Peff's series, building on earlier work by Michael J Gruber. The approach aligns with Git's gradual move toward proper const-correctness, replacing quick fixes with structural solutions. The patch touches core revision walking code but maintains all existing behavior while making it more robust. Given Peff's expertise and Junio's approval, this appears to be a solid step forward in the broader const-correctness effort.
