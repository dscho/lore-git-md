Feature patch series from [author] introducing per-remote and per-namespace SSH configuration options to manage multiple Git forge accounts. Current workarounds require SSH config files or wrapper scripts. The solution adds three configuration layers: per-remote (remote.*.sshIdentityFile, remote.*.sshOpts), per-namespace (core.sshIdentityFile.* for includeIf patterns), and global overrides (core.sshIdentityFile, core.sshOpts).

Implementation introduces two new structs (ssh_options, cnx_context) in connect.c to manage configuration cleanly. Includes comprehensive tests in new t57xx-ssh-options-config.sh covering various scenarios. Maintains backward compatibility. Intentional limitations include no support for separate push/pull URIs. Automatically adds -F /dev/null when using identity files without custom SSH options for safety.

Open questions: configuration namespace organization (currently core.* but considering ssh.*), whether to support push/pull URI differences. Well-motivated solution to real pain point with thorough test coverage and clear commit messages. Production-quality work awaiting review feedback on namespace choice and potential feature expansion.
