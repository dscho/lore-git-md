This is a refactoring patch that concludes a two-part series improving help text handling for `git repo` subcommands. The patch has already been reviewed and approved by maintainer Junio C Hamano, with Patrick Steinhardt also expressing satisfaction with the final version.

The series makes each `git repo` subcommand (`info` and `structure`) show only its own usage information when invoked with `-h`, rather than displaying the full command list. This second patch implements the behavior change after the first patch did the preparatory macro extraction work. The implementation is clean and well-tested, with thorough coverage verifying the scoped help output.

With both patches approved and Junio indicating he will queue them, this appears to be a straightforward improvement that follows Git's established patterns for command-line interface refinements. The only minor consideration is a potential future change to how `-h` exit codes are handled, but this doesn't affect the current acceptance. The patch series seems ready to be merged as-is.
