This is the second patch in Jeff King's (Peff) series addressing const-correctness in Git's revision parsing code. It follows up on his earlier structural changes to `revision.c` by applying the same allocation-based approach to the similar code in `builtin/rev-parse.c`.

The patch modifies how `try_difference()` handles range operators (".." and "...") to avoid modifying const strings. Instead of temporarily NUL-terminating the input string (which required casting away const), it now makes a modifiable copy of the left-hand side using `xmemdupz()`. The changes are straightforward - about 15 lines modified with a net reduction in code - and maintain all existing behavior while properly respecting const semantics.

This continues the thread's progression from Michael J Gruber's initial const-cast fixes toward Peff's more architecturally sound solution. The patch is cleanly focused, touching only the range operator case in rev-parse while leaving the function's overall logic intact. Given Peff's expertise and the prior consensus that allocation is the right approach, this seems likely to be accepted as part of the series.
