This is a discussion about const-correctness in Git's revision parsing code, specifically around how the code handles modification of argv strings. Jeff King (Peff) responds to Michael J Gruber's patch that added explicit casts to acknowledge string mutations that ISOC23's stricter const handling revealed.

Peff notes that while mutating argv strings is technically legal (which is why it doesn't currently segfault), the preferred approach would be to modify the revision parser to avoid touching incoming buffers entirely. He suggests replacing the current in-place string modifications with xmemdupz() allocations, trading a small efficiency cost for cleaner const-correctness. This would prevent potential issues with string literals (which do segfault when modified) while maintaining the same functionality.

The discussion references prior work by Collin Funk that explored similar issues, indicating this is a known pain point in the codebase. Peff mentions having unpolished patches that take this allocation-based approach, suggesting this may be an area where he plans to contribute follow-up work. The exchange highlights the ongoing tension between pragmatic compatibility fixes (like Gruber's casts) and more structural solutions that better respect const semantics.
