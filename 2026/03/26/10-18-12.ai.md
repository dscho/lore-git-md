This is a feature patch (5/12 in v5 series) enabling parallel execution for the pre-push hook, which previously had special output stream handling that prevented parallelization. The patch removes this limitation while maintaining backwards compatibility - when run serially (jobs=1), pre-push behaves exactly as before with separate stdout/stderr streams. When parallel execution is explicitly requested (via hook.jobs >1, hook.<event>.jobs >1, or -jN), stdout is automatically merged into stderr to allow proper output de-interleaving by run-command.c.

The implementation adds a new merge_output_if_parallel() helper that enforces this behavior change when jobs >1, documented clearly in both code and config documentation. The patch includes comprehensive tests verifying both the output stream merging behavior and actual parallel execution of pre-push hooks when configured. 

This change completes the parallel execution support for all hook types while respecting the pre-push hook's special historical behavior in the default case. The approach cleanly handles the tradeoff between backwards compatibility and parallel execution capability without requiring additional configuration knobs. The patch builds on prior work in the series that established the parallel execution infrastructure and job count controls.
