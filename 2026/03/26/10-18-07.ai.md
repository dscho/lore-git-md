This is a feature patch series (v5 12/12) introducing parallel hook execution, building on Adrian Ratiu's prior configurable hooks work. The series has grown from 4 to 12 patches since v4 to address feedback and add new functionality, with all core technical components now having maintainer approval from Junio C Hamano.

The series establishes comprehensive controls for parallel hook execution:
- Global `hook.jobs` default (now supporting `-1` for automatic CPU core detection)
- Per-hook `hook.<name>.parallel` flags
- CLI `-j/--jobs` override (which Patrick Steinhardt confirmed overrides all config settings)
- Per-event `hook.<event>.jobs` settings
- Per-event `hook.<event>.enabled` master switch

Key implementation details include proper output stream handling (stdout redirected to stderr except pre-push hook) and extensive test coverage in t/t1800-hook.sh. The series also introduces safety constraints for non-parallelizable hooks via RUN_HOOKS_OPT_INIT_FORCE_SERIAL.

Notable changes in v5:
- Rebased on config-cleanups-v3 with minor conflict resolution
- Replaced unsigned int:1 with proper bool types (Patrick's suggestion)
- Added back a dropped commit (Junio's catch)

- Fixed potential NULL dereference in repo_config_get_uint (Patrick)
- Clarified CLI override precedence in documentation (Patrick)

The series appears well-structured with clear commit messages and motivation, though the pre-push hook's special casing suggests this area may need further refinement based on list feedback.
