This is a feature patch extending the ODB (object database) abstraction effort, adding three new vtable methods to support packfile ingestion, object abbreviation iteration, and hash algorithm conversion. The changes are part of Patrick Steinhardt's ongoing work to make Git's object storage backend pluggable.

The patch introduces three key vtable methods:
1. `write_packfile` - Handles packfile ingestion, choosing between index-pack and unpack-objects based on size and configuration. This replaces direct spawning of these commands by callers.
2. `for_each_unique_abbrev` - Provides object disambiguation by iterating objects matching a hex prefix across loose objects and packs.
3. `convert_object_id` - Translates between hash algorithms using loose object maps, supporting SHA-1/SHA-256 migration.

The implementation routes object-name.c's abbreviation/disambiguation logic through the new vtable methods rather than directly accessing files-backend internals. This properly extends these features to non-files backends. The patch also adds ODB_SOURCE_HELPER to the source type enum, preparing for an upcoming helper backend.

The changes appear thorough and well-motivated, with careful attention to maintaining existing behavior while abstracting it behind the vtable interface. The commit message is detailed and well-structured, explaining both the technical changes and their motivation (supporting the helper backend series and sqlite-git prototype). This builds on prior work in the ps/odb-sources series and addresses Patrick's feedback about proper abstraction boundaries.
