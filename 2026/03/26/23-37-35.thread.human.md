This thread discusses Wesley Schwengle's proposal to add per-remote and per-namespace SSH configuration options to Git (v1, 3 patches). The changes would allow specifying SSH identities and options through Git config rather than relying on SSH host aliases. The technical implementation involves new structs in connect.c and transport.c, with comprehensive tests added.

Key contributors have raised substantial concerns. Johannes Sixt (Hannes) and Junio Hamano argue that existing SSH host aliases provide equivalent functionality and are widely used, if under-documented. Jeff King (Peff) has provided multiple rounds of detailed technical review, suggesting alternative approaches using includeIf patterns and url.insteadOf mappings, while also improving code quality through parameter naming suggestions. brian m. carlson reinforced that existing solutions like core.sshCommand and SSH host aliases offer more flexibility.

Wesley maintains that Git-level configuration would be more portable and version-controllable, particularly for team workflows, though he acknowledges technical limitations in his approach. The discussion has evolved into three tracks: whether Git should provide this functionality at all, code quality improvements to the patches, and architectural design questions.

In the latest exchange, Peff clarified his includeIf suggestion while acknowledging its limitations for multiple remotes, then reiterated that SSH host aliases combined with url.insteadOf mappings can solve the problem without Git changes. The thread remains constructive but shows little movement toward accepting the feature as proposed, with experienced contributors consistently demonstrating how existing mechanisms can achieve similar outcomes. The technical merits of each approach continue to be debated, with workflow portability versus configuration flexibility being the central tension.
