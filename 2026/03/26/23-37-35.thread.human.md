Wesley Schwengle proposed adding per-remote and per-namespace SSH configuration options to Git (v1, 3 patches), arguing this would improve workflow portability for team repositories compared to requiring SSH host aliases. The technical implementation was well-received, but Johannes Sixt (Hannes) objected that SSH host aliases already solve this problem without Git changes.

Now maintainer Junio C Hamano has weighed in, siding with Hannes. Junio acknowledges the SSH host alias approach may not be well-documented, but agrees it's the proper solution rather than adding SSH-specific configuration to Git. He particularly objects to putting SSH options under Git's "core" namespace, reinforcing that such configuration belongs in SSH itself. While Junio doesn't directly engage with Wesley's team workflow arguments, his endorsement of the status quo suggests the feature would need much stronger justification to be reconsidered. Unless new compelling use cases emerge that SSH can't address, this proposal appears unlikely to move forward.
