This thread discusses Wesley Schwengle's proposal to add per-remote and per-namespace SSH configuration options to Git. The initial patches would allow configuring SSH identity files and options at different levels (remote-specific, namespace-based via includeIf, and global). However, several experienced contributors have pushed back, arguing that existing SSH and Git mechanisms already cover these use cases.

Johannes Sixt and Junio Hamano initially objected that SSH host aliases provide equivalent functionality. Jeff King later demonstrated that Git's existing `includeIf` patterns can handle namespace-based configuration without new syntax. Now brian m. carlson has reinforced this position by detailing two more existing solutions: `url.<URL>.insteadOf` for URL rewriting and `core.sshCommand` with `-i` for key selection. He argues the proposed feature would actually reduce flexibility compared to these more general approaches.

While Wesley maintains that Git-level configuration would improve workflow ergonomics, the weight of technical arguments from multiple respected contributors - including the maintainer - suggests the feature is unlikely to be accepted in its current form. The discussion has evolved into a broader examination of Git's configuration philosophy, with maintainers consistently favoring flexible, general-purpose mechanisms over specialized configuration options when possible. Key open questions remain about whether any aspects of the original proposal might be salvaged, but the core idea of adding SSH-specific configuration appears increasingly doubtful given the demonstrated alternatives.
