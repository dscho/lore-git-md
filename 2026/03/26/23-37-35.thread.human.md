This thread discusses Wesley Schwengle's proposal to add per-remote and per-namespace SSH configuration options to Git (v1, 3 patches). The changes would allow specifying SSH identities and options through Git config (remote.*.ssh* and core.ssh*), with automatic handling of SSH behaviors when identities are specified. The technical implementation adds new structures in connect.c/transport.c and includes comprehensive tests.

The proposal has met strong resistance from core maintainers and experienced contributors. Johannes Sixt (Hannes) leads the opposition, arguing that SSH's native config files already solve these problems without expanding Git's configuration surface. Jeff King (Peff) provided detailed technical review, suggesting alternative approaches using existing Git features like includeIf and url.*.insteadOf. brian m. carlson reinforced this position, citing existing documentation solutions.

Wesley expanded on his use cases, emphasizing version control benefits for freelancers managing multiple client identities and projects requiring URL rewriting. However, Ben Knoble's recent contribution strengthens the maintainers' position by sharing his successful use of SSH configs across both Git and non-Git contexts, arguing for proper separation of concerns between systems.

The discussion remains at a philosophical impasse: Wesley sees value in consolidating configuration within Git for version control and workflow portability, while maintainers view this as unnecessary given SSH's existing capabilities. The burden remains on Wesley to demonstrate concrete scenarios where current solutions fail before this proposal could gain traction. No technical consensus has formed beyond some minor implementation details, and the core architectural objections remain unresolved.
