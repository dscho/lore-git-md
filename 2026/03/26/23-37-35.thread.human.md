This thread discusses Wesley Schwengle's proposal to add per-remote and per-namespace SSH configuration options to Git (v1, 3 patches). The series would allow specifying SSH identities and options through Git config (remote.*.ssh* and core.ssh* namespaces), with automatic handling of SSH security flags.

Several experienced contributors have raised concerns that existing SSH host aliases (via ~/.ssh/config) combined with Git's url.*.insteadOf and core.sshCommand already solve this problem. Jeff King (Peff) demonstrated how includeIf can handle namespace cases without new syntax, while brian m. carlson pointed to existing documentation about these solutions. Maintainer Junio Hamano objected to putting SSH config under core.* as architecturally inappropriate.

Wesley maintains that Git-level configuration offers better version control and portability, especially for team workflows, though he acknowledges the technical validity of the alternatives. The latest response from Johannes Sixt (Hannes) reinforces that user-specific SSH config (not system-wide) addresses the identity management needs, though he admits unfamiliarity with Wesley's specific use cases (myrepos, Perl metacpan).

The discussion has revealed a philosophical divide: whether Git should duplicate SSH functionality or leverage existing mechanisms. While the code quality aspects (parameter naming, type safety) are converging, the feature itself faces significant resistance from maintainers who view it as unnecessary given current capabilities. The burden remains on Wesley to demonstrate concrete cases where existing solutions fail before the proposal is likely to progress.
