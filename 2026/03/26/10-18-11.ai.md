This is a feature patch (4/12 in v5) from Adrian Ratiu that enables parallel execution of Git hooks, building on his earlier configurable hooks work. The patch introduces the core parallel execution logic while maintaining safety through opt-in controls.

The key addition is a `hook.<name>.parallel` config flag that must be explicitly set to `true` for each hook that can safely run concurrently. This conservative approach ensures hooks that might conflict (e.g., by writing to the same file) won't break when parallelized. The implementation integrates with Git's existing parallel process infrastructure while adding new constraints:

- Hooks default to serial execution (jobs=1) unless both `hook.jobs` is set >1 AND all hooks for the event are marked parallel=true
- Output streams are properly handled (stdout redirected to stderr except for pre-push hook)
- The patch includes comprehensive tests verifying serial vs parallel behavior via sentinel files that track execution timing

Notable technical details include:
- New `parallel` field in `struct hook` to track per-hook parallel capability
- `get_hook_jobs()` helper that implements the precedence rules (CLI -j override > config > default 1)
- `RUN_HOOKS_OPT_INIT_FORCE_SERIAL` macro for hooks that must never parallelize
- Test infrastructure (`write_sentinel_hook`/`sentinel_detector`) to verify parallel behavior

It follows the pattern established in earlier patches of the series, building incrementally toward the full parallel execution feature while maintaining backward compatibility.
