This is a feature patch in Adrian Ratiu's parallel hook execution series, specifically addressing the pre-push hook's special output handling. The patch allows pre-push hooks to run in parallel while maintaining backward compatibility.

The key change is that when parallel execution is requested (via hook.jobs > 1, per-event settings, or -jN), the pre-push hook's stdout will be merged into stderr to enable proper output buffering and de-interleaving. This represents a behavior change from the traditional pre-push hook behavior where stdout and stderr remain separate (important for git-lfs compatibility), but the change only occurs when the user explicitly opts into parallelism.

The patch includes:
1. Documentation updates explaining the output behavior change
2. Core logic to automatically merge streams when parallel execution is requested
3. Test cases verifying both the output merging behavior and actual parallel execution of pre-push hooks

The implementation is well-considered, maintaining the existing behavior by default while cleanly handling the parallel case. The test coverage is thorough, including both output stream verification and timing-based parallel execution checks. This patch appears ready for integration, having already received maintainer acks in previous iterations.
