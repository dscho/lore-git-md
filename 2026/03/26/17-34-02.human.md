This is a technical review response from Jeff King (Peff) regarding const-correctness fixes in Git's codebase. The email focuses on patch 1/6 in Michael J Gruber's series addressing ISOC23 compiler warnings about const pointer handling.

Peff suggests an alternative approach to the const-casting solution proposed in the patch. Rather than casting the const away from strchr()'s return value in builtin/config.c, he recommends creating a non-const alias for the string being manipulated. This approach better communicates the code's intent while still satisfying the compiler's requirements. The example shows how to restructure the config section parsing to avoid the const cast entirely.

The review demonstrates Peff's characteristic attention to both correctness and clarity. While the original patch's solution works technically, Peff's alternative maintains type safety more explicitly by keeping the const/non-const separation clear in the code structure. This is particularly important in config.c where the string manipulation is legitimate (the memory is writeable) but the current structure obscures that fact.

The response indicates that similar improvements could be made elsewhere in the series, such as in the packet_reader code. This feedback will likely lead to a revised version of the series that better balances compiler compliance with code clarity.
