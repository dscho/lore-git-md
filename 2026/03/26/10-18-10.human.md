This is a feature patch (3/12 in v5) adding the global `hook.jobs` configuration for parallel hook execution. It's part of Adrian Ratiu's ongoing work to make hooks more configurable and parallelizable.

The patch introduces the `hook.jobs` config key, allowing users to set a default number of hooks that can run simultaneously across all hook events. The value is parsed and stored in the repository's `hook_jobs` field (defaulting to 0 for serial execution if unset). The implementation includes validation to ensure the value is a positive integer, with appropriate warnings for invalid inputs.

The change is well-contained, adding documentation in `Documentation/config/hook.adoc` and plumbing the config value through the existing hook configuration infrastructure. While the value isn't yet used (that comes in later patches), this establishes the foundation for the parallel execution controls that follow. The patch follows Git's standard patterns for config handling and includes clear commit message explaining its role in the larger series.
