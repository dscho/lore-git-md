This is a refactoring patch that adds unsigned integer parsing support to Git's config subsystem, part of Adrian Ratiu's parallel hooks series. The patch introduces a new `repo_config_get_uint()` helper and supporting infrastructure to properly handle unsigned integer config values, which will be used for the upcoming `hook.jobs` configuration.

The change adds four key components:
1. A `git_config_uint()` function to parse unsigned int values from config
2. A `git_configset_get_uint()` function to retrieve unsigned ints from a config set
3. A `repo_config_get_uint()` repository-level wrapper
4. A new `git_parse_uint()` helper in parse.c for the actual value parsing

The implementation follows the existing pattern for other numeric types in the config system, with clear documentation added to config.h. The commit message explains the motivation - while alternatives like using signed ints or unsigned longs were possible, this approach provides proper type safety for the upcoming hook.jobs setting.

This is a well-contained infrastructure patch that follows Git's established patterns. The changes are focused and clearly motivated by the needs of the parallel hooks feature. The patch itself is straightforward, adding only the necessary plumbing without any behavior changes to existing code paths.
