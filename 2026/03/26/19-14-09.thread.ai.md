Justin Tobler's 5-patch series completes the implementation of consistent signature handling between commits and tags in `git fast-import`. The series builds on prior work (c20f112e51, ee66c793f8) to systematically implement three matching modes for signature validation: strip-if-invalid, sign-if-invalid, and abort-if-invalid. The final patch adds the last remaining mode - abort-on-invalid for tags - making all three behaviors available for both commits and tags.

The implementation maintains parallel handling between commit and tag signature processing throughout. The series refactors error handling in `git fast-export` (patch 1), introduces abort-if-invalid for commits (patch 2), then systematically implements the three modes for tags: strip-if-invalid (patch 3), sign-if-invalid (patch 4), and now abort-if-invalid (patch 5). Each patch includes thorough test coverage across signature types (OpenPGP, X.509, SSH) and edge cases, with the final patch adding tests for abort behavior with forged signatures.

The changes provide users with granular control over signature validation during imports, allowing them to choose whether to strip, re-sign, or abort on invalid signatures for both commits and tags. The implementation appears clean and well-tested, completing the feature set while maintaining consistency between commit and tag handling. The series touches gpg-interface.c, fast-import.c, and the test suite, introducing new functions like `handle_tag_signature_if_invalid()` and variables like `signed_tag_keyid` to support the new behaviors.
