Feature: Adding 'sign-if-invalid' mode for signed tags in fast-import.

This is the fourth patch in Justin Tobler's series to bring parity between commit and tag signature handling in `git fast-import`. The patch introduces the 'sign-if-invalid' mode for the `--signed-tags` option, mirroring the behavior already available for commits via `--signed-commits`.

When this mode is active, `fast-import` will verify tag signatures during import and replace any that fail verification with new signatures generated using the specified key. The implementation adds a new `signed_tag_keyid` variable to store the signing key and modifies the tag signature handling logic to support re-signing invalid signatures. The test suite is expanded to verify the new behavior works correctly with both OpenPGP and SSH signatures, including cases where the tag message is modified to invalidate the original signature. A specific test case demonstrates using an explicit key ID when the default signing key is invalid.

This change completes two of the three planned signature handling modes for tags (strip-if-invalid and sign-if-invalid), leaving only abort-if-invalid to be implemented in the final patch of the series. The implementation follows the same pattern as the earlier commit signature handling changes, maintaining consistency across both object types.
