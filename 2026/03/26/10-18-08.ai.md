Bugfix patch addressing a memory leak in `repo_init()` when handling repository format errors. This is the first patch in Adrian Ratiu's 12-part series introducing parallel hook execution, though it stands alone as a general repository initialization fix.

The patch fixes a pre-existing memory leak that occurs when `repo_init()` encounters a v1 extension in a v0-format repository - an edge case that only surfaces in development environments. The solution is straightforward: call `clear_repository_format()` in the error path before `repo_clear()`, matching the cleanup pattern used in successful cases.

While this is a minor fix, it demonstrates good hygiene of addressing infrastructure issues before building new features on top. The commit message clearly explains both the trigger condition and why the leak went undetected in normal usage. As the first patch in a larger series, it helps establish confidence in the author's attention to detail.
