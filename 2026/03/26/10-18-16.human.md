This is a feature patch in a series introducing parallel hook execution, specifically addressing configuration warnings. Patch 9/12 in v5 adds a warning when users mistakenly set `hook.<friendly-name>.jobs` instead of the intended `hook.<event>.jobs` configuration.

The patch detects this confusion by checking if the configured name has any hook-specific settings (like .command, .event, or .parallel) that indicate it's a hook name rather than an event name. It introduces a new helper function `is_friendly_name()` to make this determination, which will also be useful for future per-event config handling.

The implementation includes comprehensive tests verifying the warning appears in all cases where a hook name is misused (when it has .command, .event, or .parallel set) but not for legitimate event names. This follows Junio Hamano's suggestion to help users avoid configuration mistakes in the new parallel hooks system.

The patch fits cleanly into the larger series, which has already received maintainer approval for its core technical components. This particular change improves the user experience by catching a likely source of confusion in the new configuration options.
