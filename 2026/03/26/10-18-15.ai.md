This is a feature patch (8/12 in v5) adding per-event job count configuration to Git's parallel hook execution system. The patch builds on Adrian Ratiu's ongoing work to make hooks configurable and parallelizable.

The change introduces `hook.<event>.jobs` configuration to override the global `hook.jobs` setting for specific hook events. This allows fine-grained control - for example, setting `hook.post-receive.jobs = 4` would run post-receive hooks with up to 4 parallel jobs while keeping other events at their global default. The implementation carefully handles precedence rules and maintains safety constraints - parallel execution still requires each individual hook to be marked as parallel-safe via `hook.<name>.parallel`.

Key technical aspects include:
- New `event_jobs` strmap in `struct repository` to cache per-event job counts
- Config parsing that validates positive integers and warns on invalid values
- Clear documentation explaining the event/hook name distinction (the config key must use the event name, not hook friendly name)
- Comprehensive test coverage verifying precedence rules and interaction with parallel flags

The patch fits cleanly into the series' established architecture, using the same job count validation and parallel safety checks as the global `hook.jobs` implementation. It maintains backwards compatibility while adding the new configuration layer. The tests demonstrate correct behavior when mixing global and per-event settings, including cases where per-event config forces serial execution despite a parallel global setting.

This appears to be a well-constructed addition to the parallel hooks infrastructure, with clear documentation and thorough test coverage. The implementation follows the series' established conventions and handles edge cases appropriately.
