This is a bug report from Jeff King (Peff) about test infrastructure changes in Junio's series to enable "set -e" in the test suite. The issue reveals a subtle shell behavior difference between dash and bash when "set -e" interacts with command substitution and pipe failures.

The core problem occurs in two test scripts (t0005 and t3600) that check signal handling by capturing the exit status of a command that should die with SIGPIPE. With "set -e" enabled, dash shell behaves differently than bash - it terminates the subshell before the status can be captured when the command fails. This breaks the test assertions that verify the expected signal was received.

Jeff provides a detailed analysis showing how dash's handling of "set -e" differs from bash's in this edge case, particularly when command substitution is involved. He demonstrates the issue with minimal test cases and proposes a workaround (adding `||` before the status capture) that would make the test pass under dash, though he notes this solution is imperfect as it would mask unexpected successes.

The email highlights an important compatibility consideration for the test framework changes - shell-specific behaviors around error handling that may require test-by-test adjustments beyond the initial series. Jeff's analysis suggests the need for either shell-specific test modifications or reconsideration of how signal tests are structured under "set -e". The issue remains unresolved in this email, with Jeff expressing dissatisfaction with the proposed workaround.
