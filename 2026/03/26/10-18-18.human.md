This is a feature patch adding a master switch to disable all hooks for a given event via `hook.<event>.enabled`. It's part of Adrian Ratiu's ongoing parallel hooks series (v5 11/12) that builds on his earlier configurable hooks work.

The patch introduces a new config key that acts as a high-level kill switch for hook events. When set to false, no hooks will run for that event, regardless of individual hook settings. Disabled hooks are clearly marked in `git hook list` output with an "event-disabled" prefix, taking precedence over per-hook "disabled" status in the display.

The implementation handles several edge cases:
- Friendly names that match known event names are rejected (fatal error)
- Friendly names matching unknown events trigger a warning about potential ambiguity
- The display logic ensures users see the most relevant disable reason (event-level overrides per-hook settings)

The patch includes comprehensive tests verifying the new behaviors, including TTY handling, output ordering, and precedence rules. It follows the pattern established in earlier patches of the series, with clear commit messages and thorough documentation updates.

This appears to be a well-considered addition to the parallel execution infrastructure, addressing feedback from both Patrick Steinhardt and Junio Hamano. The special handling of pre-push hooks from earlier in the series remains the only notable exception to the general parallel execution model.
