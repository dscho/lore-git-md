Feature: Adding 'abort-if-invalid' mode for signed commits in fast-import.

This is the second patch in Justin Tobler's series to extend signature handling in `git fast-import`. It introduces a new 'abort-if-invalid' mode for the `--signed-commits` option, which causes the import to fail immediately when encountering an invalid commit signature. This provides stricter validation than the existing 'strip-if-invalid' and 'sign-if-invalid' modes.

The patch adds the new mode to the documentation, gpg-interface plumbing, and implements the actual abort behavior in fast-import's commit handling. It also includes test cases verifying the new mode works as expected - the import fails when given a forged signature, while still allowing valid signatures and unsigned commits to pass through. The implementation is clean and follows the same pattern as the existing signature modes.

This change is part of a broader effort to bring parity between commit and tag signature handling in fast-import, with subsequent patches in the series extending these same modes to tags. The abort mode in particular could be useful for automated workflows where strict signature validation is required.
