This is a feature patch (11/12 in v5) adding a high-level event disable switch to Adrian Ratiu's parallel hook execution series. The patch introduces `hook.<event>.enabled` configuration to disable all hooks for a given event, complementing the per-hook `hook.<friendly-name>.enabled` settings.

The implementation shows event-disabled hooks in `git hook list` with an "event-disabled" prefix, prioritizing this status over per-hook disabled states for clarity. The patch handles naming collisions by:
- Fatal error when using known event names as friendly-names (e.g. `hook.pre-commit.event`)
- Warning when friendly-names match unknown event names (potential ambiguity)

Key technical changes include:
- New `disabled_events` string_list in struct repository
- Updated hook listing to show event-disabled status
- Config parsing that separates event-level from per-hook disables
- Comprehensive tests covering CLI output, precedence rules, and error cases

The patch builds on prior work in the series while addressing feedback from Patrick Steinhardt and Junio Hamano about naming collisions. It maintains the series' focus on clear configuration semantics while adding this final layer of event-level control. The implementation appears thorough with careful attention to edge cases and user visibility of disabled states.
