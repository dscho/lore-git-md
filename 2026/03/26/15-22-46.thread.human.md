The key breakthrough came when Junio Hamano, after initial reservations, endorsed using `xmemdupz()` to create copies of strings rather than modifying them in-place - establishing this as the preferred pattern for const-correct string handling.

The latest exchange between Peff and Junio focuses on the `handle_dotdot()` interface in revision.c, which processes range operators like "..". Peff acknowledges a typo fix from Junio and reinforces why the allocation approach is necessary - it properly respects const semantics while avoiding pushing copying burdens to callers. They considered but rejected more invasive approaches like ptr/len pairs as overkill for this problem. With Junio's explicit approval, this series now sets important precedents for how to handle string operations in a const-correct way throughout Git's codebase, particularly affecting revision parsing logic while maintaining backward compatibility.
