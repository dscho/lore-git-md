This thread documents the collaborative effort between Michael J Gruber, Jeff King (Peff), and Junio Hamano to address const-correctness issues raised by ISOC23 compiler warnings. The discussion began with Gruber's initial mechanical fixes using casts, but evolved into a more structural solution under Peff's guidance, focusing on proper string handling in revision parsing and config code.

The key technical decision was to use `xmemdupz()` for string allocation rather than in-place modification, establishing clear ownership semantics while maintaining const casts. Junio initially preferred non-allocating solutions but ultimately endorsed this approach after technical discussion. The solution particularly affects the `handle_dotdot()` function in revision.c, which processes range operators like ".."), where they confirmed allocation is necessary despite initial reservations about overhead.

The current patch series (now 7 patches) implements this pattern across multiple areas: revision range parsing, parent mark handling, and config URL-matching. The most recent discussion between Peff and Junio confirms their alignment on this being the right technical solution, rejecting more invasive approaches like ptr/len modifications as ultimately requiring NUL-terminated strings anyway when interfacing with system libraries.
