This thread addresses const-correctness fixes needed for ISOC23 compliance in Git's codebase, focusing initially on string handling in revision parsing. Michael J Gruber started with a series using explicit casts across multiple files to quickly address compiler warnings. Jeff King (Peff) then proposed a more structural solution, replacing in-place string modifications with safer allocation-based approaches.

Peff's current 4-part series implements this cleaner approach, with this first patch specifically refactoring the `handle_dotdot()` interface for range operators (".." and "..."). The changes eliminate unsafe const-cast operations by using `xmemdupz()` to create modifiable string copies when needed, while simplifying the parsing interface. The patch touches about 20 lines in `revision.c`, maintaining all existing functionality while properly respecting const semantics.

Junio Hamano has previously expressed preference for this allocation-based approach over type system violations, and given Peff's expertise in this area, the series appears headed for acceptance. The thread demonstrates Git's typical incremental improvement pattern - starting with immediate fixes (Gruber's casts) then evolving toward architecturally cleaner solutions (Peff's allocations). Remaining patches in the series will apply similar fixes to other revision parsing cases.
