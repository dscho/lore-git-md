This is a follow-up to the const-correctness discussion in Git's revision parsing code. Jeff King (Peff) delivers on his earlier promise to refactor the code to avoid modifying const strings, submitting a 4-patch series that replaces the problematic in-place string modifications with safer allocation-based approaches.

The series focuses on two key areas where Git was temporarily modifying argv strings: handling range operators ("..") and parent shorthands ("^@"). Instead of the previous approach of casting away const to modify these strings directly, Peff's patches introduce xmemdupz() allocations to create writable copies when needed. This maintains the same functionality while properly respecting const semantics.

The changes touch core revision parsing code in `revision.c` and `builtin/rev-parse.c`, with each patch addressing a specific case:
1. Simplifying the dotdot parsing interface
2. Cleaning up rev-parse's dotdot handling
3. Removing const violations in parent mark parsing
4. Applying the same fix to rev-parse's parent mark handling

Peff notes the refactoring not only fixes the const issues but also makes the code easier to understand. The approach aligns with the maintainer's preference (expressed earlier in the thread) for solutions that properly respect const semantics rather than working around them with casts. This series represents the more robust, allocation-based solution that was hinted at in previous discussions, moving beyond the temporary cast-based fixes that were initially proposed.
