This is the second patch in Jeff King's (Peff) series addressing const-correctness in Git's revision parsing code, specifically focusing on the `git rev-parse` command. The patch follows the same allocation-based approach established in the first patch, applying it to the dotdot range operator parsing in `builtin/rev-parse.c`.

The key change replaces the previous pattern of modifying const strings in-place (by temporarily NUL-terminating them) with a cleaner approach that allocates a modifiable copy of the string portion before the ".." operator. The patch introduces a `to_free` variable to track this allocation, ensuring proper cleanup across all code paths. This eliminates the need for const-casting while maintaining identical functionality.

Technically, the patch:
- The range parsing logic in `try_difference()`
- Changes about 15 lines while preserving all behavior
- Uses `xmemdupz()` to create modifiable copies of string segments
- Adds proper memory cleanup with `free(to_free)`
- Maintains the same error handling and fallback cases

This continues the series' pattern of structural fixes rather than temporary workarounds, aligning with the maintainer's preference for proper const-correctness solutions. The changes are focused and well-contained, touching only the rev-parse implementation while building on the conceptual approach established in the first patch for revision.c.
