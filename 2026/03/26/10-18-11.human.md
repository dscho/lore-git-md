Feature patch introducing parallel hook execution, part of Adrian Ratiu's ongoing hooks configuration work. This is patch 4/12 in a series that has received maintainer approval from Junio C Hamano after several iterations of review.

The patch enables parallel execution of hooks when explicitly configured, with careful safety constraints. Key aspects:
- Hooks remain serial by default (jobs=1) unless marked parallel-safe via `hook.<name>.parallel=true` in config
- The global `hook.jobs` setting controls default parallelism (with CLI `-j` override)
- One non-parallel hook forces the entire event to run sequentially
- Output streams are properly handled (stdout redirected to stderr except for pre-push hook)
- Includes comprehensive tests verifying serial vs parallel behavior

The implementation builds on new infrastructure from earlier patches in the series (unsigned int config parsing) and introduces RUN_HOOKS_OPT_INIT_FORCE_SERIAL for hooks that must never run in parallel. The patch appears well-structured with clear commit messages and thorough test coverage, though the pre-push hook's special output handling remains an area that may need future refinement.
