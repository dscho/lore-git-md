Documentation patch clarifying the behavior of `--commit-list-format` in `git format-patch`. 

This update fixes two documentation issues: first, it clarifies that when neither `--commit-list-format` nor `format.commitListFormat` config is set, the default is `shortlog`. Second, it updates the description of `--cover-letter` to reflect that the commit list can now be formatted output (not just a shortlog).

The changes are straightforward and uncontroversial, aligning the docs with the actual behavior introduced in the earlier series mf/format-patch-commit-list-format. The patch is well-formed and clearly motivated, though it might have been helpful to include a reference to the commit that changed this behavior (36c16a5b7f) in the commit message.
