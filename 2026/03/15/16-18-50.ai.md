This is the first patch in Phillip Wood's 3-part series to remove `the_repository` usage from worktree functions, part of the broader global variable removal effort. The patch focuses on `is_current_worktree()`, which previously compared worktree paths against `the_repository`'s gitdir, leading to inconsistent behavior when worktrees used different repository instances.

The key change makes `is_current_worktree()` use the worktree's own repository (`wt->repo`) rather than the global `the_repository`. This ensures consistent behavior - a worktree is now always considered current when its path matches its repository's worktree path. As a result, the patch can simplify `get_worktree_from_repository()` by removing its `is_current_worktree()` call since the worktree will always be current in that context.

The patch also updates `get_worktree_git_dir()` to use the worktree's repository rather than falling back to `the_repository`. This is groundwork for the series' later patches which will further harden the interface by removing NULL worktree handling entirely. The changes maintain existing behavior while advancing the `the_repository` removal goal, with test coverage in t2400 confirming functionality remains intact.
