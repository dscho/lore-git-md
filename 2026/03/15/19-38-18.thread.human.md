This thread presents a GSoC proposal from Amisha Chhajed to add disk space recovery functionality for partial clones via a new `git evict` command. The proposal comes from an experienced contributor with several prior Git patches merged, including optimizations to the string-list API.

The core idea is to safely remove blobs from partial clones when they're no longer needed but can be refetched from promisor remotes. The proposed `git evict` command would offer several filtering options to target different categories of reclaimable objects: those outside sparse-checkout cones (`--outside-cone`), stale objects (`--older-than`), large blobs (`--large-only`), and deep objects (`--tree-depth`). The implementation would leverage Git's existing promisor object infrastructure to verify objects can be refetched before eviction.

The student has outlined a clear 12-week implementation plan and demonstrated both technical understanding of Git's internals and familiarity with the project's contribution workflow. The functionality would fill a practical gap in partial clone usability while building sensibly on existing infrastructure.
