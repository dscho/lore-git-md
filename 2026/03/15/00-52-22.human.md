Bugfix proposal for `git rev-parse --parseopt` help behavior. brian m. carlson reports that when scripts use `git rev-parse --parseopt` to handle command-line options, the helper currently exits with status 129 (indicating an error) even when the user explicitly requests help with `-h` or `--help`. This contradicts the Unix convention where help requests should exit successfully (0) since they fulfill the user's intent.

The issue is demonstrated with a sample script that shows `--help` and invalid options both producing exit code 129, despite the help output going to stdout (correct) versus stderr for errors (also correct). The author notes that Git's main commands handle this correctly by routing help through `man`, but the low-level `--parseopt` helper does not.

brian m. carlson is seeking input on how to fix this - whether to change the exit code directly or add a compatibility option. The patch would affect scripts using `--parseopt` for option parsing, making their help behavior consistent with standard Unix tool expectations. This appears to be a straightforward quality-of-life improvement for script authors.
