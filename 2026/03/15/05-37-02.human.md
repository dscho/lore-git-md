This is the final version of a feature patch implementing configurable partial clone filters via URL patterns (`clone.<url>.defaultObjectFilter`). The patch has gone through five previous iterations and addresses all review comments, including a final safety check for URL normalization and test cleanup improvements suggested by Patrick Steinhardt.

The feature allows users to configure default partial clone filters that automatically apply when cloning matching repositories, similar to how `http.<url>.*` config works. The implementation uses Git's existing urlmatch infrastructure to determine the most specific URL match, with command-line `--filter` and `--no-filter` options providing explicit overrides. The filter setting is stored in `remote.<name>.partialCloneFilter` for subsequent fetches.

Key improvements in this version include:
- Added NULL check when URL normalization fails (Patrick's review)
- Used `test_when_finished` for test directory cleanup (Patrick's suggestion)
- Modernized test scripts using `test_cmp` instead of shell comparisons
- Added explicit test for `--no-filter` behavior
- Final documentation polish

The patch includes comprehensive test coverage for all major scenarios: filter application, command-line overrides, different filter types, URL matching precedence, and edge cases. The thread shows consensus on the design, with Junio C Hamano confirming the URL-based configuration approach and approving the final implementation. This is a well-tested, carefully reviewed feature that provides a useful quality-of-life improvement for partial clone users while maintaining clear boundaries by being clone-specific.
