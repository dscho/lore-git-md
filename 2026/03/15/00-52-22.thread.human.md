This thread addresses a bug in Git's option parsing behavior where `git rev-parse --parseopt` (and consequently many Git commands) was incorrectly exiting with status 129 (error) when processing `--help` or `-h` flags, contrary to Git's standard convention of exiting 0 for help requests. The issue was originally reported and implemented by brian m. carlson, with significant technical analysis from Jeff King (Peff) and final approval from maintainer Junio C Hamano.

Through careful historical research, Peff determined the 129 exit code was an accidental inheritance from 2007 code rather than an intentional design choice. While the initial implementation caused a regression in `git instaweb -h` (which previously exited 129 outside repositories), the consensus is that this behavior was itself incorrect and the change represents a strict improvement. All parties agree the fix should proceed as a regular bug fix before Git 3.0, with minimal risk to existing scripts since well-designed programs shouldn't depend on help requests returning error status.

The implementation will standardize exit code 0 for help requests across all commands using Git's parse-options infrastructure, update the release notes to document this behavioral change, and include comprehensive testing. With maintainer approval confirmed and all technical questions resolved, the discussion has now shifted to implementation, marking a small but meaningful step toward greater consistency in Git's command-line interface.
