This thread discusses standardizing the exit code behavior when `--help` or `-h` flags are used with Git commands. The issue originated when brian m. carlson noticed that `git rev-parse --parseopt` was exiting with status 129 (error) for help requests, which violated Git's convention of exiting 0 for help. His initial fix was merged but caused a regression in `git instaweb`, prompting reconsideration.

Jeff King (Peff) investigated the history and found the 129 exit code dates back to 2007 code where it was used for both errors and help requests, suggesting it was an accidental inheritance rather than intentional design. Junio C Hamano, the maintainer, agrees that standardizing on exit0 for help requests is the right approach, though initially suggested waiting until Git 3.0 for the change. 

Peff's latest analysis addresses potential backward compatibility concerns, concluding that while scripts could theoretically break if they depend on the current behavior, such cases would be rare and likely indicate poor script design. He argues the change could proceed without waiting for Git 3.0. With the technical concerns now thoroughly vetted and maintainer approval in place, the discussion is shifting toward implementation details. brian m. carlson is preparing a revised patch that will standardize the behavior across all commands using Git's option parsing infrastructure.
