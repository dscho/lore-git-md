This thread addresses a long-standing inconsistency in `git rev-parse --parseopt` where help requests (`-h`/`--help`) incorrectly exit with status 129 (error) rather than the standard success code 0. brian m. carlson identified the issue and initiated the discussion, with Jeff King (Peff) contributing a key technical solution.

The core challenge was maintaining backward compatibility, particularly for the shell-eval mode which outputs a here-doc with help text rather than exiting directly. Peff proposed appending an `exit 0` to the here-doc output, which both fixes the behavior and preserves compatibility with existing scripts. brian m. carlson has agreed with this approach and will implement it, noting they'll also update `rev-parse` itself to return 0 for help requests while adding tests for both cases.

Both participants have demonstrated their characteristic thoroughness - Peff in crafting a solution that handles the shell-eval case elegantly, and brian m. carlson in carefully considering backward compatibility implications. The patch appears ready to proceed, cleanly resolving the inconsistency without breaking existing usage.
