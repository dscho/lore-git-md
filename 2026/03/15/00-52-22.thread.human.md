This thread is about a long-standing inconsistency in Git’s parse-options API, where `--help`/`-h` flags incorrectly exited with status 129 (error) instead of 0 (success). The issue was fixed in a four-patch series by brian m. carlson, which has now been fully merged as a regular bugfix ahead of Git 3.0. The series standardizes help-exit behavior across all Git commands using the parse-options infrastructure, resolving a 17-year-old quirk that was accidentally inherited from early code.

Key participants include brian m. carlson (author), Jeff King (Peff, reviewer), and Junio C Hamano (maintainer). The fix was straightforward in principle but revealed three post-merge issues and two behavioral trade-offs. The most significant was a flawed `SVN` test prerequisite, where a Perl version check (`$SVN::Core::VERSION gt '1.1.0'`) failed due to Perl treating dotted version strings as ASCII sequences (e.g., `1.14.5` < `1.2.0` lexicographically). This caused tests to run even when SVN was unavailable, leading to false negatives. Junio confirmed the root cause, and brian will simplify the prerequisite by removing the version check entirely, leaving only a check for SVN module availability. Another issue was a refactoring gap in `usage_with_options_internal()`, where Peff noted that the new `PARSE_OPT_HELP_ERROR` logic wasn’t consistently applied. This is a minor inconsistency with no immediate impact but may be addressed in a follow-up.

The behavioral trade-offs are more nuanced. Peff highlighted that scripts wrapping Git commands (e.g., `git log --my-options "$@"`) may now feed garbage to downstream logic because `--help` exits 0 instead of 129. Junio acknowledged this as a real risk but accepted it as a necessary side effect of the broader fix. The shell-eval mode of `git rev-parse --parseopt` also presents a theoretical edge case where nonsense output could be processed if `--help` is accidentally passed, though this is less likely. The series itself touches `parse-options.c`, 37 test files, and three built-in commands, introducing a new `PARSE_OPT_HELP_ERROR` return code to distinguish between direct help requests and help triggered by errors. The shell-eval mode achieves exit 0 by appending `exit 0` to its heredoc output, a solution Junio called "yuck" but functionally correct.

The thread is now largely resolved, with only the prerequisite simplification and the optional refactoring gap remaining. The core fix is in place, and the trade-offs are documented and accepted. No further controversy or major discussion is expected.
