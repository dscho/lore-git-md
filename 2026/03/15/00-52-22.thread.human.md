This thread discusses improving how `git rev-parse --parseopt` handles help flags (`-h`/`--help`), which currently exit with error status 129 instead of the standard success code 0. brian m. carlson initiated the discussion by identifying this inconsistency with Git's normal help behavior, which causes problems for scripts trying to distinguish help requests from actual errors.

Jeff King (Peff) agreed with the principle of the change but noted a technical complication: since `--parseopt` generates shell code for eval, simply changing its exit code wouldn't solve the problem for calling scripts. He proposed a more complete solution - modifying the command to output an explicit `exit 0` after the help text when in shell-eval mode. This approach would properly signal successful completion to scripts while maintaining backward compatibility. Both participants appear to agree on the value of the change, with the discussion now focused on implementation details rather than the merit of the idea itself. Peff's solution demonstrates his characteristic attention to edge cases and backward compatibility, offering a path forward that satisfies both Unix conventions and existing script usage.
