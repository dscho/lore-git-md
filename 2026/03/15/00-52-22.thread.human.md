This thread discusses improving `git rev-parse --parseopt`'s handling of help flags (`-h`/`--help`). brian m. carlson reports that unlike most Git commands which exit successfully when showing help, `--parseopt` currently exits with status 129 (error), which breaks scripts trying to distinguish between help requests and actual errors. 

The author provides a concrete example demonstrating how this inconsistency causes problems for scripts using `--parseopt` for their own option parsing. They're considering two solutions: either changing the exit code directly (more consistent but potentially breaking) or adding a compatibility option (safer but more complex). The change would be small and focused on `rev-parse.c`, but requires care since it affects script behavior. The proposal is well-motivated and aligns with Unix conventions where help requests shouldn't be treated as errors.
