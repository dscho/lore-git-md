This thread is about a now-completed bugfix series that standardizes how Git commands exit when users request help (`--help` or `-h`). The series, authored by brian m. carlson and reviewed by Jeff King (Peff) and Junio C Hamano, fixes a long-standing inconsistency where Git's parse-options infrastructure exited with status 129 (error) instead of the Unix-standard 0 for help requests. The issue was traced back to 2007 code and became more noticeable after a regression in `git instaweb -h`.

The fix was implemented in four patches, all now merged. The first two addressed prerequisite logic and refactoring in the parse-options API, while the third handled shell-eval mode for `git rev-parse --parseopt`. This final patch updates the core logic in `parse-options.c` and `usage.c` to exit 0 for help flags, and adjusts 37 test files and three built-in commands (`git blame`, `git shortlog`, `git update-index`) to match. The only exception is `git diff`, which does its own option parsing and still exits 129; tests for it now accept either exit status.

The series was accepted as a regular bugfix and is fully merged, with all identified issues resolved. The trade-offs—such as potential edge cases in scripts delegating option parsing to Git—were acknowledged but deemed acceptable. No further discussion or follow-up is expected.
