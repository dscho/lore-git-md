This thread is about a long-standing inconsistency in Git’s parse-options API, where help flags (`--help`/`-h`) incorrectly exited with status 129 instead of the Unix-standard 0. The issue was first noticed when `git instaweb -h` regressed, exiting 0 outside repositories where it previously exited 129, revealing a broader problem across all commands using the parse-options infrastructure.

The fix was implemented as a four-patch series by brian m. carlson, addressing the core inconsistency, a refactoring gap in `usage_with_options_internal()`, and test expectations across 37 files and three built-in commands. The series was fully merged as a regular bugfix before Git 3.0, with Junio C Hamano approving the changes and confirming the updated conditional logic in `parse-options.c`. A post-merge cleanup patch (v3) later simplified the `SVN` test prerequisite, replacing a broken Perl version check with a minimal script that tests only for module availability, avoiding a shell-quoting bug and aligning with the project’s test infrastructure. Junio explicitly endorsed this cleanup, confirming it avoids the known-broken pattern from `t/lib-git-svn.sh`.

Jeff King (Peff) initially raised concerns about potential downstream breakage but ultimately endorsed the direction, stating he had “no complaints” on the final version and was comfortable proceeding to see if any issues surfaced during the development cycle. The community verified the changes across parse-options users, and all identified issues—including the prerequisite logic flaw, shell-quoting bug, and refactoring gap—are now resolved. No open questions remain, and the thread is effectively closed.
