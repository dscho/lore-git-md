This thread began as a four-patch series to fix a long-standing inconsistency in how Git commands exit when given `--help` or `-h`: the parse-options API, used by nearly every built-in command, incorrectly returned exit code 129 (error) instead of 0 (success), violating Unix conventions. The series, authored by brian m. carlson and reviewed by Jeff King (Peff) and Junio C Hamano, was merged as a regular bugfix ahead of Git 3.0, resolving the issue system-wide while preserving backward compatibility for debugging use cases.

Since merging, three technical issues and two behavioral trade-offs have surfaced. Peff identified a critical shell-quoting bug in the `SVN` test prerequisite’s Perl version check, which caused silent test failures, and a logical gap in the `PARSE_OPT_HELP_ERROR` refactoring that left one code path inconsistent. Junio questioned whether the prerequisite’s `NO_SVN_TESTS` guard was overly restrictive. The behavioral trade-offs—scripts in shell-eval mode accidentally processing `--help` output, and wrapped commands feeding garbage to downstream logic—were documented but deemed acceptable. In this latest exchange, brian acknowledges the prerequisite logic flaw and confirms the version check is both unnecessary (SVN 1.0 is obsolete) and broken (shell-quoting causes Perl to compare strings, not versions). He plans to simplify the prerequisite to skip tests only when SVN modules are genuinely unavailable, addressing both Junio’s and Peff’s concerns in a follow-up patch. The core exit-code fix remains settled, and the thread is now focused on tidying up test infrastructure.
