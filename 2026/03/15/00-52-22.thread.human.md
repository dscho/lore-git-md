This thread addressed a long-standing inconsistency in Git's parse-options API, where `--help`/`-h` flags incorrectly exited with status 129 (error) instead of 0 (success). The issue was traced back to 2007 code and confirmed as unintentional. Brian m. carlson authored a four-patch series to standardize help exit codes across all parse-options users, which Junio C Hamano merged as a regular bugfix ahead of Git 3.0. The series included a core refactoring of `usage_with_options_internal()`, updates to 37 test files and three built-in commands, and a fix for `git rev-parse --parseopt`'s shell-eval mode to ensure scripts evaluating its output exit successfully on help requests.

After merging, a post-merge cleanup patch (v3) tidied up the `SVN` test prerequisite, replacing a broken Perl version check with a minimal script that tests only for module availability. This resolved a shell-quoting bug and aligned the prerequisite with the project's test infrastructure. Jeff King (Peff) reviewed the cleanup and dropped his earlier hypothetical concern about downstream breakage, endorsing the approach of proceeding and observing for issues during the development cycle. Junio echoed this sentiment in his latest reply, effectively closing the thread. All identified issues are resolved, and the series is now fully integrated.
