This is the final version of a feature patch implementing configurable partial clone filters via URL patterns (`clone.<url>.defaultObjectFilter`). The patch has gone through six iterations and is now being merged by Junio C Hamano after addressing all review feedback.

The feature allows users to configure default partial clone filters that automatically apply when cloning matching repositories, similar to how HTTP configuration works. The implementation uses Git's existing urlmatch infrastructure to determine the most specific URL match, with command-line `--filter` and `--no-filter` options providing explicit overrides.

Junio notes the patch is ready for integration but points out two minor documentation improvements that would help future reviewers understand the rationale behind specific test changes. The first is adding a comment about the NULL check for URL normalization (a safety measure suggested by Patrick Steinhardt). The second is clarifying why a large test file was removed (likely because its purpose is now covered by other tests).

This represents the conclusion of a well-reviewed feature that provides a quality-of-life improvement for partial clone users while maintaining Git's boundaries by limiting the configuration to clone operations only. The implementation includes comprehensive test coverage and clear documentation of the URL matching behavior and override mechanisms.
