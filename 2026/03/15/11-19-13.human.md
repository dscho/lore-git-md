This is the final patch in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The patch implements the core functionality after several iterations based on maintainer feedback.

The key change makes `checkout -m` automatically stash local changes when they would conflict with the target branch, then reapply them after switching. If the stash application results in conflicts, Git preserves the stash entry and provides clear instructions for resolution. The implementation includes:

1. Silent stash creation during checkout via a new `create_autostash_ref_silent()` function
2. Custom conflict marker labels showing branch names through new `git stash apply` options (`--ours-label`, `--theirs-label`, `--base-label`)
3. Comprehensive documentation updates explaining the new behavior
4. 18 new test cases in t7201-co.sh covering various scenarios

The patch represents a significant UX improvement for branch switching, making conflict resolution more intuitive by leveraging Git's existing autostash infrastructure. It maintains backward compatibility while providing clearer conflict resolution guidance. The implementation is thorough, with careful attention to edge cases and user feedback.

This version addresses all previous review feedback except for submodule handling, which remains deferred per Junio's preference. The series appears ready for final approval with these refinements.
