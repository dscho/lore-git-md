This is a discussion about internationalization (i18n) edge cases in Git's message pluralization. Junio C Hamano responds to Phillip Wood's observation about complex pluralization rules in some languages (like Polish) that require more than just singular/plural forms. While the original patch removing Q_() was correct for English, Junio acknowledges that Phillip's example reveals a broader issue: any message with a numeric placeholder that could be pluralized might need ngettext() handling for full i18n correctness.

Junio demonstrates this by running `git grep` for messages with numeric placeholders that use _() instead of Q_(), finding several potential candidates in just the first few files (add-patch.c, archive-zip.c, etc.). His tone suggests this is more an observation than an immediate call to action - noting the complexity of the problem while recognizing Phillip's point about proper pluralization. The thread highlights how even small i18n considerations can surface non-trivial technical debt in a codebase as large as Git's.
