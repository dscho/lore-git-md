This thread concerns a bugfix patch series (now at v2) from GSoC contributor Jialong Wang that improves error reporting in `git apply` when processing corrupt patches. The original issue was that error messages only showed line numbers without indicating whether the corrupt patch came from a file or stdin, making debugging difficult - especially when applying multiple patches at once.

The solution adds source identification to error messages by including `state->patch_input_file` in the output. The implementation is minimal, touching just a few lines in `apply.c` to modify error format strings and reset line counters between patches. Test coverage was expanded across three scenarios: single file input, stdin input, and (new in v2) multiple patch inputs where one is corrupt - this last case added in response to reviewer feedback from Karthik Nayak.

The patch appears complete and ready, having cleanly addressed all feedback. The changes maintain backward compatibility while significantly improving debuggability, particularly for automated systems processing multiple patches. As a focused, well-tested improvement to a core command's error reporting, this seems like a strong candidate for merging.
