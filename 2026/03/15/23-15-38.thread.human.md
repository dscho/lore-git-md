Jialong Wang continues their GSoC work improving `git apply` error reporting with a new patch that adds source file context to corrupt patch detection messages. This follows their earlier merged work that established a consistent "error: corrupt patch at <file>:<line>" format for basic corrupt patch cases. The current patch specifically handles malformed hunk headers that exceed line number limits, ensuring the error messages identify whether the input came from a file or stdin.

The implementation modifies `apply.c` to track input sources and reset line counters between patches, while adding test coverage in `t4100-apply-stat.sh` and updating expectations in `t4012-diff-binary.sh`. The changes maintain the clean, non-invasive approach of the original series - enhancing diagnostics without altering core behavior. This appears to be a straightforward extension of the accepted pattern, building on the foundation of Wang's previous work that Junio merged after positive review from Karthik Nayak. The series continues to demonstrate effective incremental improvement, with all changes focused on completing the comprehensive error reporting solution.
