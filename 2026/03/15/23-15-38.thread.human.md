This thread introduces a bugfix patch to improve error reporting in `git apply` when processing corrupt patches. Currently, Git only reports the line number of the corruption, which can be ambiguous when applying multiple patches or reading from stdin. The patch modifies the error message to include the input source (filename or "<stdin>") alongside the line number, making it clearer where the problem occurred.

The change is implemented by adding `state->patch_input_file` to the error message format string in `apply.c`. The patch includes two test cases - one for file input and one for stdin - to verify the new error message format works correctly in both scenarios. This appears to be a well-motivated quality-of-life improvement, particularly useful when debugging patch application issues in complex patch sequences or automated tooling environments.

The patch is part of a Google Summer of Code (GSoC) contribution, as indicated by its subject prefix. The implementation looks clean and focused, with appropriate test coverage for the change.
