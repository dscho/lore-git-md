This is version 5 of a feature patch series that enhances `git checkout -m` to use autostash behavior when switching branches with local changes. The series has evolved through maintainer feedback to focus on architectural improvements rather than adding a new flag.

The key changes in this version:
- Splits the implementation into 4 logical patches (previously 1)
- Adds new stash labeling options (`--ours-label`, `--theirs-label`, `--base-label`) to improve conflict markers
- Makes stash creation silent during checkout operations
- Improves documentation to better explain the new behavior
- Preserves the modified files listing output that was accidentally dropped in v4
- Adds more precise control over when stash messages appear

The implementation now:
1. First adds stash labeling capabilities (patch 1)
2. Then enables silent stash creation (patch 2) 
3. Teaches autostash to use custom labels (patch 3)
4. Finally implements the unified `-m` behavior (patch 4)

The documentation has been refined to clarify:
- Conflict resolution steps when stashing occurs
- That users should resolve conflicts before popping the stash
- The branch switching message now shows "Switched to branch" rather than autostash details

The series appears well-tested with:
- 18 new test cases in t7201-co.sh
- Coverage of edge cases and backward compatibility
- Updates to existing autostash tests

This version addresses Junio's feedback from v4 by:
- Better organizing the patch series
- Preserving the modified files listing
- Making stash operations quieter
- Improving documentation clarity

The submodule handling discussion remains unresolved but is being tracked separately. The series looks ready for integration pending any final minor tweaks from the maintainer.
