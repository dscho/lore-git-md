This is the second patch in Phillip Wood's 3-part series to remove `the_repository` usage from worktree functions, part of the broader effort to eliminate this global variable. The patch simplifies the warning message in `can_use_local_refs()` when HEAD is invalid or points to an unborn branch.

Previously, the function would attempt to read and display the contents of ".git/HEAD" as part of the warning. This patch removes that filesystem-specific behavior since it doesn't work with reftable backends (where HEAD isn't stored as a file) and provides questionable value even with files backends. The warning now just states that HEAD is invalid/orphaned without trying to show file contents.

The patch also updates to the test suite in t2400 to use `test_grep` instead of raw `grep` for better test output, and removes the now-unnecessary checks for HEAD file paths and contents. These changes maintain the same test coverage while being backend-agnostic.

This is a straightforward cleanup that follows the series' pattern of removing filesystem assumptions while preserving functionality. The changes have already been reviewed by Junio C Hamano in v1, with Phillip incorporating feedback about warning message formatting. The patch fits cleanly into the series' progression toward eliminating `the_repository` dependencies in worktree code.
