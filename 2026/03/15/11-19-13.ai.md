This is the final patch in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The patch implements the core functionality after several iterations of review and refinement.

The key changes in this version:
- Replaces the previous three-way merge approach with autostash-based conflict resolution
- Adds silent stash creation during checkout operations via `create_autostash_ref_silent()`
- Preserves the modified files listing that was accidentally dropped in v4
- Improves conflict marker labeling to show branch names
- Updates documentation to clearly explain the new behavior

The implementation now properly integrates with the existing stash and sequencer infrastructure while maintaining backward compatibility. When conflicts occur during branch switching, local changes are automatically stashed and reapplied, with clear user guidance provided when conflicts arise during reapplication.

The patch touches multiple components including checkout, stash, and sequencer logic, with comprehensive test coverage in t7201-co.sh. Documentation updates in git-checkout.adoc and git-switch.adoc explain the new unified behavior and user workflow.

This appears to be the culmination of a well-reviewed series that has addressed all technical feedback except for submodule handling, which remains deferred per maintainer preference. The implementation is thorough and the documentation is clear, making this a solid contribution that should improve the user experience when dealing with conflicts during branch switching.
