This is the first patch in a 3-part series removing `the_repository` usage from worktree functions, part of the broader effort to eliminate this global variable. Phillip Wood focuses on `is_current_worktree()`, which previously compared paths using `the_repository` even when a specific repository was available via `wt->repo`.

The change makes the function consistently use the worktree's own repository rather than falling back to the global one, fixing an inconsistency where worktrees might not be recognized as current if their repository wasn't `the_repository`. This allows simplifying `get_worktree_from_repository()` by removing its `is_current_worktree()` call entirely, since the worktree will now always be considered current in that context.

The patch updates both `is_current_worktree()` and `get_worktree_git_dir()` to use `wt->repo` instead of `the_repository`. The changes are straightforward and maintain existing behavior while making the code more explicit about which repository it operates on. This is a clean, focused change that advances the `the_repository` removal effort in the worktree subsystem.
