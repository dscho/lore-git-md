This is a refactoring patch that adds a Coccinelle rule to detect when `struct strbuf` is passed by value rather than by pointer, continuing the thread started by Jeff King's earlier observation about this anti-pattern.

The patch introduces a semantic rule that will flag functions taking `strbuf` parameters by value and suggest converting them to pointer parameters. The commit message clearly explains the motivation: passing `strbuf` by value can lead to dangling pointers if the callee reallocates the buffer, since the caller's copy would still point to the old memory. This builds on Jeff King's earlier fix for `write_worktree_linking_files()` but provides a systematic way to catch all such cases.

The Coccinelle rule follows the project's existing patterns in `strbuf.cocci` by performing a transformation rather than just reporting. While the output won't be immediately compilable (callers and function bodies would need updating), it serves as a clear indicator that the signature needs attention. The patch is cleanly implemented and well-documented, with a reference to the prior discussion that motivated it.

This appears to be a straightforward and useful addition to Git's code quality tooling, addressing a subtle but potentially dangerous pattern. The fact that only one remaining case was found (fixed in patch 2/2) suggests the project has been good about avoiding this anti-pattern, but having an automated check will help prevent regressions.
