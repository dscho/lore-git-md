This is a bugfix patch that improves error reporting in `git apply` when processing corrupt patches. Currently, when encountering a malformed patch, Git only reports the line number where the corruption occurred, which can be ambiguous if the patch comes from multiple sources. 

The patch modifies the error message to include both the input file path (or "<stdin>" for standard input) and the line number, making it easier to locate the problematic patch. The change is small and focused on a single error message in `apply.c`, with corresponding test updates to verify both file and stdin input cases.

The patch appears well-contained and clearly motivated - it solves a real usability issue when debugging patch application failures. The test coverage is thorough, checking both file and stdin input paths. This looks like a solid improvement that should be uncontroversial to merge.
