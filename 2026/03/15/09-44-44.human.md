Refactoring patch fixing a `strbuf` parameter passing issue in the stash command. This is the second patch in a two-part series that systematically addresses passing `struct strbuf` by value - an anti-pattern that can lead to dangling pointers and double-free bugs.

The patch changes `save_untracked_files()` in `builtin/stash.c` to take its `files` parameter as a pointer to `strbuf` rather than by value. The change is straightforward but important - while the original code worked (since the buffer was shared between copies), it risked subtle bugs if the callee reallocated the buffer. The patch updates both the function signature and its single caller sites to use the pointer form.

This follows up on Jeff King's earlier identification of this pattern and builds on the first patch in the series which introduced a Coccinelle rule to detect such cases. The fact that only two instances were found (this one and the prior `write_worktree_linking_files()` case) speaks well of the project's existing code hygiene around `strbuf` usage. The patch appears well-executed and properly motivated by the technical risks of the anti-pattern.
