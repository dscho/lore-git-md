This is a refactoring patch series that addresses a subtle code quality issue in Git's codebase - passing `struct strbuf` by value rather than by pointer. The series comes from a suggestion by Jeff King during code review of another patch.

The first patch introduces a Coccinelle semantic rule to detect functions that incorrectly take `struct strbuf` parameters by value, automatically rewriting them to use pointers. This static analysis tool will help prevent similar issues in the future. The second patch fixes the one remaining instance found by this rule in `builtin/stash.c`.

The motivation stems from the fact that `strbuf` is designed to be passed by pointer (like most structs in Git), as passing by value can lead to inefficient copying and potential bugs. The series is small and focused, with clean commit messages that reference prior discussion. Since the original case that prompted this (in `worktree.c`) was already fixed, this appears to be finishing the job by catching the last instance.

The changes are straightforward - converting a parameter type and updating the single affected caller. The Coccinelle rule looks correct and follows similar patterns used elsewhere in Git's semantic patches. This seems like a worthwhile cleanup that improves code consistency and prevents a class of potential issues.
