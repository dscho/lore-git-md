This is a feature patch in its final review phase, implementing autostash behavior for `git checkout -m` branch switching as directed by maintainer Junio C Hamano. The patch represents a significant architectural improvement to conflict handling during branch switches by unifying the `-m` behavior with autostash functionality rather than adding a separate flag.

Junio's review identifies several areas needing attention:
1. The current documentation oversimplifies the conflict resolution steps, potentially misleading users about when to use `git stash pop`
2. The implementation drops the "Auto-merging" messages that show which files were merged, which Junio questions as unnecessary
3. The dry-run conflict detection could be optimized further by reusing the index from the initial check
4. The stash-related changes should be split into preparatory patches for better logical progression

The patch already includes thorough test coverage (18 new test cases) and maintains backward compatibility. Junio-approved approach of enhancing `-m` rather than adding new flags has been fully implemented, with only these final polish items remaining before the series can be considered ready.

Notably, the submodule handling question raised earlier by Phillip Wood remains unresolved but is being treated as a separate concern. The maintainer has clearly stated opposition to expanding `git stash`'s responsibilities to handle submodules, suggesting they should manage their own stashing independently.

This represents the last round of refinement for a well-executed feature that improves the branch switching experience while following Git's architectural principles. The remaining issues are documentation clarity and minor implementation polish rather than fundamental design questions.
