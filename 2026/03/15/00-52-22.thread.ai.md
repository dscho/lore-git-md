Thread identity: Bug report and proposal to change `git rev-parse --parseopt` exit code behavior for help flags (`--help`/`-h`), authored by brian m. carlson.

Core problem: `rev-parse --parseopt` currently exits with status 129 (error) when help flags are used, contrary to Git's standard behavior where help requests exit successfully (status 0). This creates problems for scripts using `--parseopt` for option parsing, as they cannot distinguish between legitimate help requests and actual errors.

Current status: Initial proposal stage. No patches submitted yet. Author is seeking input on implementation approach - whether to change the exit code directly or add a compatibility option to preserve old behavior.

Key technical details: Affects `builtin/rev-parse.c`'s handling of the `--parseopt` mode. The change would modify how the `PARSE_OPT_HELP` case sets the exit code. Scripts using `--parseopt` would need to be checked for compatibility.

Open questions: Should this be a direct behavior change (breaking existing scripts that may rely on status 129) or introduce a new opt-in flag to enable the correct exit code? Need to assess impact on existing scripts.

Participant positions: brian m. carlson has identified the issue and is proposing to implement a fix, seeking community input on the best approach. No other participants have commented yet.

Related work: This would align `rev-parse --parseopt` with Git's standard help behavior seen in other commands. The change is conceptually similar to other consistency improvements in Git's option parsing.
