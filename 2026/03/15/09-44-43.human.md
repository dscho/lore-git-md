This is a refactoring patch that adds a Coccinelle rule to detect when `struct strbuf` is incorrectly passed by value rather than by pointer. The change stems from a review comment by Jeff King, who noted this anti-pattern can lead to dangerous behavior since the caller and callee end up with different copies of the struct while sharing the underlying buffer.

The patch adds a semantic rule to `strbuf.cocci` that will flag functions taking `strbuf` parameters by value and suggest converting them to pointers. While the rule alone won't produce compilable code (callers and function bodies would still need updating), it serves as an effective detection mechanism. This follows the same pattern as other rules in the file and helps prevent subtle bugs where reallocations in the callee could leave the caller with dangling pointers.

The change is well-motivated and builds on prior fixes for this issue. As the first part of a two-patch series, it lays the groundwork for systematically addressing this pattern throughout the codebase. The commit message clearly explains the rationale and connects it to the earlier discussion, making this a solid contribution to Git's code quality tooling.
