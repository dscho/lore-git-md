This is a Google Summer of Code (GSOC) proposal for a new feature to improve disk space management in partial clones. The proposal comes from Amisha Chhajed, a third-year computer science student with prior open source experience including contributions to Git (several merged string-list optimizations) and Bitcoin Core.

The core idea is to add a `git evict` command that would safely remove blobs from partial clones when they are no longer needed but can be refetched from promisor remotes. The command would offer several filtering options:
- `--outside-cone` for blobs outside the current sparse-checkout
- `--older-than` for stale blobs
- `--large-only` for large blobs
- `--tree-depth` for deep objects

The implementation would involve checking each candidate object against promisor remotes (using `is_promisor_object()`) before evicting, then repacking without those objects. The proposal is well-motivated by the observation that partial clone users want to actively manage their disk usage, and the design sensibly defers to user choice rather than trying to predict what should be evicted.

Amisha demonstrates solid familiarity with Git's internals through their prior contributions (particularly around string-list optimizations) and shows good awareness of the partial clone ecosystem. The timeline is realistic, allocating time for design discussion, core implementation, and testing. This looks like a promising proposal from an engaged contributor.
