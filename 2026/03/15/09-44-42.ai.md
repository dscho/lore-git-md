This is a refactoring patch series that introduces a Coccinelle rule to detect and fix instances where `struct strbuf` is passed by value rather than by pointer.

The series stems from a review comment by Jeff King, who noticed an issue with `write_worktree_linking_files()` taking a `strbuf` by value. While that specific case was already fixed, Deveshi Dwivedi proposes a more systematic solution by creating a Coccinelle semantic patch to catch all such cases. 

The first patch adds a Coccinelle rule that detects functions taking `struct strbuf` parameters by value and suggests converting them to pointer parameters. The second patch applies this rule to fix the one remaining instance found in `builtin/stash.c`, where `show_stash()` was incorrectly passing a `strbuf` by value.

This appears to be a well-motivated change - passing `strbuf` by value is both inefficient (due to copying) and potentially dangerous (since the caller and callee would operate on different copies). The patch series is small and focused, with clear references to prior discussion. The Coccinelle rule looks correct and the stash.c fix is straightforward. Since this addresses a subtle anti-pattern that could lead to bugs, it seems like a worthwhile addition to the project's code quality tooling.
