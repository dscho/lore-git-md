This is version 5 of a feature patch series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has evolved significantly from its original proposal based on maintainer feedback, now focusing on architectural improvements rather than adding a new flag.

The key changes in this version:
- Splits the implementation into 4 logical patches (previously 1)
- Adds new stash labeling capabilities via `--ours-label`, `--theirs-label`, and `--base-label` options
- Makes stash creation silent during checkout operations
- Improves conflict marker labeling to show branch names
- Updates documentation to better explain the new unified behavior
- Preserves the modified files listing output that was accidentally dropped in v4

The implementation now properly handles the stash creation flow while maintaining backward compatibility. The documentation updates clarify the conflict resolution steps and user workflow when conflicts occur during branch switching.

Notable technical changes:
- New `create_autostash_ref_silent()` function for quiet stash creation
- Enhanced `apply_save_autostash_oid()` to support custom conflict labels
- Modified checkout logic to track whether an autostash was created
- Preserved `show_local_changes()` output that was unintentionally removed

The patch touches multiple components including stash, sequencer, and checkout logic, with thorough test coverage in t7201-co.sh. While the core approach remains the same as v4 (unifying `-m` with autostash behavior), this version better handles the user experience aspects and documentation clarity that Junio highlighted in previous reviews.

The submodule handling discussion from previous versions remains unresolved and will need to be addressed separately, as noted in the thread context. This series appears to be converging toward final approval with these documentation and implementation refinements.
