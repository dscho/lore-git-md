This is part 3/9 in Adrian Ratiu's series introducing parallel hook execution, building on his earlier configurable hooks work. The patch adds a global `hook.jobs` configuration option that sets the default number of hooks that can run in parallel, with finer-grained per-hook controls coming in later patches.

Junio Hamano (the maintainer) acknowledges this as a logical next step after the preparatory unsigned integer parsing infrastructure in patch 2/9. The implementation carefully maintains backward compatibility by defaulting to serial execution (jobs=1) when the config is unset, and includes validation to ensure the value is a positive integer.

The patch is mostly plumbing - it documents the new config option and stores the parsed value, but doesn't yet use it (that comes in later patches). This continues the series' methodical approach to parallelization, making it strictly opt-in at multiple levels while maintaining safety through explicit configuration.
