This is the final version of a feature patch implementing configurable partial clone filters via URL patterns (`clone.<url>.defaultObjectFilter`). The patch has gone through five previous iterations and addresses all review comments, including final refinements from Patrick Steinhardt and Junio C Hamano.

The feature allows users to configure default partial clone filters that automatically apply when cloning matching repositories, similar to how `http.<url>.*` config works. The implementation uses Git's existing urlmatch infrastructure to determine the most specific URL match, with three key behaviors: command-line `--filter` overrides the config, `--no-filter` forces a full clone despite config, and the filter setting is stored in `remote.<name>.partialCloneFilter` for subsequent fetches.

Key technical improvements in v6 include:
- Added NULL check when URL normalization fails (Patrick's review)
- Used `test_when_finished` for test directory cleanup (Patrick's suggestion)
- Modernized test scripts using `test_cmp` instead of shell comparisons
- Comprehensive test coverage of all edge cases and precedence rules
- Clear documentation of the URL matching behavior and override mechanisms

The patch is well-tested and ready for integration, with no outstanding issues. It represents the consensus design that emerged from the review process, providing a clean solution that maintains Git's boundaries while offering useful quality-of-life improvements for partial clone users. The implementation is careful to preserve existing behavior when no config is present and provides clear override mechanisms via `--filter` and `--no-filter`.
