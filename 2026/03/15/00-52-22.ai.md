This is a bug report and proposal for improving `git rev-parse --parseopt`'s behavior with help flags. brian m. carlson identifies an inconsistency where the command exits with status 129 (indicating error) when `--help` or `-h` is used, despite this being a successful user request. They contrast this with Git's normal behavior where help requests exit successfully.

The issue specifically affects scripts using `rev-parse --parseopt` for option parsing, as they currently cannot distinguish between legitimate help requests and actual errors. The author provides a concrete example showing how a script using this feature incorrectly reports failure when help is requested. They're seeking input on the best approach to fix this - either changing the exit code directly or adding a compatibility option.

This appears to be a well-motivated change that would improve consistency with Unix conventions. The author demonstrates clear understanding of the problem and is offering to implement the fix themselves. The patch would likely be small and focused, touching only the `rev-parse` command's handling of help flags. Since this affects script behavior, some care would be needed to avoid breaking existing scripts that might rely on the current behavior, suggesting an opt-in approach might be preferable.
