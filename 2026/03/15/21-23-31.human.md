This is a contributor housekeeping patch that fixes an unintended side effect in Git's `.editorconfig` file. Taylor Blau noticed that a recent change (046e1117d5d) inadvertently altered how EditorConfig applies formatting rules to files throughout the Git tree.

The issue stems from an EditorConfig specification quirk: when a section contains any pattern with path separators (like `templates/hooks/*.sample`), all patterns in that section become relative to the `.editorconfig` file's directory level. This meant C files in subdirectories (e.g., `builtin/pack-objects.c`) stopped receiving the intended formatting rules after the hooks sample change.

The patch splits the configuration into two sections - one for tree-wide patterns and another for the specific hooks samples - restoring the original behavior. It also adds a clarifying comment to help prevent similar issues in the future. The change is straightforward and well-explained, with clear motivation and reference to the EditorConfig specification.
