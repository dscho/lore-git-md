This is a follow-up discussion on the parallel hook execution feature series, specifically addressing the documentation of non-parallelizable hooks. Junio C Hamano responds to Adrian Ratiu's patch that marked certain hooks as always serial, seeking clarification on the underlying principles that determine which hooks cannot be parallelized.

Junio suggests expanding the documentation to include clear rules explaining why certain hooks must remain serial, rather than just listing them. He provides the example of message-editing hooks (like `applypatch-msg`) which operate on a single file and thus cannot safely run concurrently. The maintainer is looking for similar rationales for the other non-parallel hooks (`pre-commit`, `post-commit`, etc.) to help future contributors understand when new hooks should be marked as serial-only.

This feedback doesn't challenge the technical implementation (which was already acked in previous rounds) but focuses on improving the explanatory documentation. Junio's request indicates the series is nearing completion, with attention now turning to making the design principles clear for future maintenance. The response maintains the conservative safety approach of the original patch while pushing for better conceptual documentation of the parallelization constraints.
