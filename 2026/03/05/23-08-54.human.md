This is the first patch in Jeff King's series fixing memory leaks in pack index mmap handling during clone operations. The patch refactors `check_connected()` to delay opening a packfile until just before it's needed, which simplifies error handling by ensuring we don't have to clean up the pack if we exit early.

The change moves the pack opening logic after the `start_command()` call for `git rev-list`, since we only need the pack when checking if objects are already contained in it. This avoids having to clean up the pack in multiple early-exit paths. Jeff notes this could potentially be optimized further by skipping `rev-list` entirely for self-contained packs, but leaves that as future work since the current approach is already efficient enough. The patch touches core connectivity checking code but is a straightforward refactor with clear benefits for resource management.

This is part of a larger effort to fix mmap-related leaks that were uncovered by AddressSanitizer, particularly affecting clone operations. The series as a whole addresses multiple leak scenarios in packfile handling.
