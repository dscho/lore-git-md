This is a bugfix patch in the fsmonitor series, addressing a potential hang condition in the fsmonitor daemon shutdown process. The patch adds a 30-second timeout to the `fsmonitor--daemon stop` command, which previously could spin indefinitely if the daemon failed to exit after receiving the quit command.

The implementation polls every 50ms while waiting for the daemon to exit, tracking elapsed time up to the 30-second limit. If the timeout is reached, it returns an error rather than continuing to wait. The change includes trace2 regions to help diagnose shutdown timing issues and maintains the existing IPC state checking behavior.

This is part of the larger cross-platform fsmonitor implementation effort that has been through extensive review over 11 iterations. The patch follows the established pattern of the series, using the same timing mechanism (sleep_millisec) seen elsewhere in the codebase. It addresses a real-world reliability concern while being minimally invasive to the existing shutdown logic.
