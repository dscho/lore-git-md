This is a platform compatibility patch adding Windows support for pthread_cond_timedwait() as part of the cross-platform fsmonitor implementation. 

The patch implements pthread_cond_timedwait() for Windows using SleepConditionVariableCS() with proper timeout calculation from an absolute timespec deadline. The implementation handles time conversion from the timespec parameter to milliseconds, checks for timeout conditions, and properly translates Windows error codes to POSIX equivalents (including ETIMEDOUT for timeout cases).

This is patch 3/12 in the v10 series bringing fsmonitor to Linux with full Windows compatibility. The series has already addressed all major technical concerns through multiple iterations, including memory leaks, container environment stability, and now complete pthread emulation on Windows. The implementation matches the behavior needed by the fsmonitor daemon's two-phase synchronization with 1-second timeout.

The patch is narrowly focused on the Windows compatibility layer, adding just the timed wait functionality while maintaining the existing pthread emulation approach. It follows the same pattern as the existing pthread_cond_wait() implementation in the same file, using Windows' native condition variable API with appropriate error translation.
