This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with the existing Windows and macOS implementations. It's part of a larger series (patch 7/12) that has been through multiple iterations and is now stable in Junio's 'seen' branch.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename events, and filesystem detection. Key technical aspects include:
- Recursive directory watching via inotify_init1(O_NONBLOCK)
- Bidirectional watch descriptor <-> path mappings using hashmap
- Special handling for directory renames through IN_MOVED_FROM/TO event cookies
- Remote filesystem detection via statfs() with /proc/mounts fallback
- Comprehensive error handling for watch limits and filesystem changes

The patch includes documentation updates noting Linux-specific caveats around inotify watch limits, and moves shared Unix functionality (IPC and settings) into appropriately named files. All review feedback from previous iterations appears to have been addressed, including memory leak fixes and reliability improvements for container environments.

This represents the culmination of a long effort to provide cross-platform fsmonitor support, with the Linux implementation now matching the stability and functionality of the Windows and macOS backends. The code is well-structured with thorough error handling and extensive tracing support.
