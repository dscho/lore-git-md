This is a bugfix series addressing memory leaks in mmap handling during Git operations, building on Jeff King's earlier analysis of a clone operation issue. The series expands the fix to cover additional leak cases found through systematic testing with leak-checking enabled.

The patches address two distinct but related issues: First, fixing a known leak in `check_connected()` during repository cloning where pack index mmap memory wasn't properly freed in error paths. Second, fixing a newly discovered case where `.rev` files could be double-loaded in the pack-revindex code. The series concludes by enabling `NO_MMAP` for all leak-checking builds to catch similar issues more reliably.

Jeff King's approach is characteristically thorough - after identifying the specific leak reported by Jacob Keller, he systematically tested the entire codebase under leak-checking conditions to find related issues. The changes are focused and well-explained, touching core packfile handling code in `connected.c` and `pack-revindex.c`. The final patch makes this kind of issue more visible by default in development builds.

This is a solid maintenance series that fixes real resource management issues, though the operational impact is limited to small memory leaks during specific operations. The changes are likely to be uncontroversial and quickly merged given Jeff King's deep expertise in this area of the codebase.
