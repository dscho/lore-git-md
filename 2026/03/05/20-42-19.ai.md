This is a follow-up discussion on Patrick Steinhardt's completed 17-part series refactoring Git's object database (ODB) subsystem to enable pluggable storage backends. The series has already received Justin Tobler's final Reviewed-by and addressed all technical feedback, but Junio Hamano raises a design question about callback contracts in the new ODB source interface.

Junio notes that while the series cleanly abstracts ODB operations into callback-based dispatch, the header files don't specify which callbacks are mandatory versus optional for backend implementations. He observes that the current wrapper functions directly dereference function pointers without NULL checks, which could cause crashes if a backend omits certain operations (like a read-only network proxy skipping write callbacks). Junio suggests either documenting mandatory callbacks in `struct odb_source` or adding NULL checks to wrappers with appropriate error handling.

This touches on an important design consideration for the new pluggable interface - how strictly to enforce implementation requirements versus allowing partial implementations. The question comes late in the process (after the series is otherwise ready for integration) but addresses a legitimate architectural concern about how future-proof the abstraction will be as alternative backends are developed. The thread context shows this was not previously raised during Justin Tobler's thorough review of the series.
