This is a refactoring patch that adds a pre-exec callback mechanism to Git's process spawning infrastructure. It's part of a larger series implementing cross-platform filesystem monitoring (fsmonitor) support, specifically addressing process management needs that surfaced during development.

The patch introduces a `pre_exec_cb` function pointer in `struct child_process` that gets called between fork and exec in the child process. This provides a clean way to perform child-specific setup like closing inherited file descriptors. The implementation includes a ready-made `close_fd_above_stderr()` callback that closes all file descriptors above stderr (skipping the child-notifier pipe), with a cap at either `sysconf(_SC_OPEN_MAX)` or 4096 for safety.

The change is motivated by the fsmonitor daemon's need to clean up file descriptors in the child process, but the mechanism is general enough to be useful elsewhere. The implementation carefully handles edge cases like the child-notifier pipe and system-specific maximum file descriptor limits. This addresses feedback from Junio Hamano about making the process management more flexible while maintaining the existing architecture.

The patch is well-contained, touching only `run-command.c` and `run-command.h` with clear documentation of the new field and callback function. It's the 8th of 12 patches in a series that has already gone through extensive review, with all technical concerns resolved in previous iterations. The series is currently in Junio's 'seen' branch and considered production-ready.
