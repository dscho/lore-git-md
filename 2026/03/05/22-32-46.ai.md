This is an RFC proposal to add remote group support to `git push`, mirroring the existing `git fetch` functionality. The series comes from a new contributor (Usman Akinyemi) and is marked as RFC to solicit design feedback before finalizing the implementation.

The core idea is to allow pushing to all remotes in a configured group (defined via `remotes.<name>` in config) with a single command like `git push all-remotes`, similar to how `git fetch all-remotes` already works. The implementation splits into two parts: first moving some group-handling code from fetch.c to remote.c to make it reusable, then modifying push.c to leverage this shared infrastructure.

Several open questions are raised about the design:
1. Whether to add parallel push support (mirroring fetch.parallel)
2. How to handle push.default=simple cases where branch upstreams differ across remotes
3. The semantics of force-with-lease across multiple remotes
4. The author notes tests and documentation will follow in future iterations

The patch touches core remote-handling code in builtin/fetch.c and builtin/push.c, plus adds new declarations to remote.h. This looks like a well-scoped first contribution that addresses a real workflow gap (fetch supports groups but push doesn't), though the edge cases around push semantics will need careful handling. The RFC framing suggests the author is being appropriately cautious about the design implications.
