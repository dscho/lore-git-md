Bugfix for memory leak in fsmonitor daemon's client handling. This patch is part of the final version of the Linux fsmonitor implementation series that has been cooking in Junio's 'seen' branch.

The fix addresses a khash table memory leak that occurs when the fsmonitor daemon sends a trivial response to a client. In this case, the code was skipping the hash table cleanup. Paul Tarjan's solution initializes the hash table pointer to NULL and moves the cleanup to a shared cleanup label using kh_destroy_str(), which safely handles NULL pointers.

The change is small but important for the daemon's long-running stability. It demonstrates the kind of careful resource management needed in the fsmonitor implementation, particularly around the IPC communication paths. The patch follows the established pattern seen elsewhere in the series where cleanup is consolidated at the end of functions.

This is a straightforward fix that was likely caught during final review or testing of the larger fsmonitor series. The patch maintains the series' high standard of resource handling while not introducing any new complexity. With this fix, the fsmonitor daemon's client handling should be completely leak-free.
