Bugfix for a long-standing memory leak in repository cloning, found by Jacob Keller and diagnosed by Jeff King. The leak occurs in the connectivity check phase when mmap'ed pack index memory isn't properly freed, particularly noticeable when building with AddressSanitizer and NO_MMAP (which converts mmaps to heap allocations).

Jeff identifies the root cause: `close_pack()` is missing in several error paths in `connected.c`, allowing the pack index mmap to leak. While this has likely been present for years, it was detected now because the ASan+NO_MMAP combination makes the leak more visible. The proposed fix adds proper cleanup in all code paths.

This is a legitimate resource management issue in core packfile handling code, though its real-world impact is limited to slightly increased memory usage during clones. The fix is straightforward but needs to handle NULL cases properly. Given Jeff's deep knowledge of Git's memory management and packfile subsystems, this diagnosis and solution are likely trusted to be correct.
