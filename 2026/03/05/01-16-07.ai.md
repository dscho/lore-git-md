Memory leak fix for fsmonitor daemon's client handling. This patch is part of the final iteration (v10) of the cross-platform fsmonitor implementation series that brings Linux support using inotify.

The change fixes a memory leak in the fsmonitor daemon's client response path where a khash table (`shown`) was not being freed when the client received a trivial response. The fix initializes the hash table pointer to NULL and moves cleanup to a shared exit path using `kh_destroy_str()` which safely handles NULL. This ensures proper cleanup regardless of whether the response is trivial or non-trivial.

The patch demonstrates careful attention to resource management in the final polishing of the fsmonitor implementation. It addresses one of the last remaining issues identified in production testing, showing the series' progression toward production readiness. The change is small but important for long-running daemon stability.
