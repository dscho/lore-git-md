This is a follow-up in the thread about worktree creation timestamps, now shifting from a feature request to a practical workaround implementation.

Norbert Kiesel shares a Zsh script that approximates the requested functionality by using filesystem creation timestamps (`stat -f '%B'`), while acknowledging the limitation that moving a worktree updates these timestamps. The script parses `git worktree list --porcelain` output, captures timestamps, and presents a sorted view with formatted dates. This demonstrates the original use case while working within Git's current constraints.

The email confirms Junio Hamano's earlier point that Git doesn't currently store worktree creation times, making the original `--created` flag proposal unworkable without deeper changes. Norbert's script represents a pragmatic interim solution for personal use, though its filesystem timestamp approach has the same reliability issues previously discussed in the thread.

The exchange shows the thread moving from feature request to workaround sharing, with no immediate path forward for core Git changes unless someone takes up Junio's suggestion about generalized worktree metadata files. The script may serve as a useful reference for others with similar needs while the broader design questions remain open.
