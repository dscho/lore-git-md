Here's the updated human-readable thread summary:

Jacob Keller reported a memory leak during clone operations when using AddressSanitizer, which Jeff King (Peff) traced to improper cleanup of mmap'ed pack index files in error paths of `check_connected()`. This was a real but previously unnoticed leak since normal builds don't track mmap allocations as strictly as ASan does. 

Peff has now sent a fix series addressing this and related issues. The first two patches properly free pack index mmaps in the error paths where the leak occurred. A third patch prevents double-mapping of revindex files, and the final change makes these checks more systematic by enabling `NO_MMAP` for all leak-checking builds - converting mmaps to heap allocations that ASan can track. 

The fixes target core packfile handling code used during operations like clone. While the leaks were small and operationally minor (just wasting some memory during certain operations), they represent legitimate resource management issues. Peff has thoroughly tested the changes by running the entire test suite with leak-checking enabled. The series appears well-contained and unlikely to be controversial, addressing subtle bugs in widely-used code paths.
