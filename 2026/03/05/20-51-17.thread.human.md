This thread documents a memory leak in Git's clone operation when dealing with pack index mmap handling, originally reported by Jacob Keller. Jeff King (Peff) has prepared a 4-patch series that addresses multiple mmap-related leaks, particularly those visible under AddressSanitizer. The fixes cover pack index cleanup during clone operations, prevent .rev file double-loading in fsck, and improve error path handling when using the NO_MMAP compatibility layer. All patches have been reviewed and are ready for merging, with Jacob Keller confirming the technical approach for the first patch's refactoring of check_connected().

Ramsay Jones recently added historical context, recalling a similar issue from 2012 in Cygwin builds that used NO_MMAP, where a double-free bug occurred in the mmap emulation layer. He shared an unmerged patch he wrote at the time that took a different approach - tracking allocations to prevent double-frees - though it became unnecessary when Cygwin dropped NO_MMAP support. This anecdote highlights how platform-specific build configurations have long exposed subtle resource management challenges in Git's memory handling. While no action is needed on the current patch set, Ramsay's note provides valuable perspective on the recurring nature of these issues across different platforms and Git versions.
