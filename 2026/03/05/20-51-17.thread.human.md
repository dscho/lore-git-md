This thread addresses memory leaks in Git's pack index handling, particularly during clone and fsck operations. The issues were discovered by Jacob Keller using AddressSanitizer, which revealed small but legitimate resource management problems in core packfile operations. Jeff King (Peff) has been leading the fixes with a carefully structured patch series.

The first two patches tackled leaks during clone operations, where mmap'd pack index data wasn't being properly cleaned up in error paths. The third patch, just submitted, fixes a related issue in fsck where .rev index files could be loaded twice without cleaning up the first mapping. This was a subtle interaction that only manifested when built with NO_MMAP (which converts mmaps to heap allocations).

Jeff's fixes demonstrate his characteristic attention to resource lifecycle details. Each patch is small and focused - the latest being just 4 lines - but effectively plugs leaks that were causing test failures under leak detection. While these leaks were minor (27KB in the original report), the fixes improve Git's robustness, especially for builds using ASan or other memory checkers. The series is progressing well, with the first two patches already reviewed and this third one maintaining the same careful approach to mmap cleanup.
