Feature proposal to add remote group support to `git push`, mirroring the existing `git fetch` functionality. This is the second patch in a two-part series, implementing the actual push-to-group capability after the first patch refactored shared code.

The patch enables pushing to all remotes in a configured group (defined via `remotes.<name>` config) with a single command like `git push all-remotes`. Key implementation details include:

- Rebuilding refspec lists per remote to handle `remote.<name>.push` configs correctly
- Isolating mirror flag evaluation per remote to prevent force-push bleeding between remotes
- Preserving existing behavior when pushing to a single remote
- Documenting known interaction with `push.default=simple` (will fail if branch has no upstream)

The author notes this is an RFC with several open design questions around parallel push support, force-with-lease semantics, and error handling strategies. The implementation looks clean and follows Junio Hamano's suggested approach from the preparatory refactoring patch. This would be a useful feature for users who maintain multiple remotes, though the interaction with `push.default=simple` may need refinement before finalizing.
