Feature patch for `pre-add` hook support, now in version 5. This patch series from Chandra Kethi-Reddy introduces a new hook that validates staged changes before they're finalized during `git add`. The latest iteration addresses Adrian Ratiu's feedback by switching from `find_hook()` to `hook_exists()` to properly handle hooks defined via configuration (like `core.hooksPath`), and fixes Windows path handling in tests.

The implementation provides temporary files representing both the original index state and proposed changes, allowing comprehensive policy enforcement (like blocking secret keys in `.env` files). The hook is skipped for interactive/patch/dry-run modes and `git commit -a`. Documentation clearly explains these limitations, including the hook's inability to selectively reject individual paths in multi-file adds.

All technical concerns from previous reviews appear addressed, with Junio Hamano having confirmed the "pre-add" naming and backtiff formatting. The patch now aligns with Adrian Ratiu's ongoing hook infrastructure work. Phillip Wood's UX concerns about argument scope showing all staged changes (rather than just the current add) remain acknowledged but not fully resolved - this may be the last open question before merging.
