This is a feature patch series for a `pre-add` hook mechanism, now facing fundamental design reconsideration from the maintainer despite being complete from a technical perspective.

The series implements a hook that validates staged changes during `git add` operations, providing temporary files representing the original and proposed index states. While version 5 addresses all technical feedback (including Windows compatibility, config-defined hooks, and test coverage), Junio Hamano now questions whether the feature's limited scope - it only sees changes from the current `git add` rather than all staged changes - provides enough value to justify its complexity.

Phillip Wood has raised several usability concerns, suggesting the hook might need to see all staged changes since the last commit to be truly useful. The rapid iteration (v4 to v5 in minutes) has also drawn criticism for not allowing proper review time. The discussion previously focused on implementation details, but has now shifted to whether the core concept is worth pursuing in its current form. The author has implemented all requested technical changes, but the series may not proceed without addressing these fundamental design questions.
