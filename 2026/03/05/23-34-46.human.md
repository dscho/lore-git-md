This is a security patch addressing ANSI escape sequence injection vulnerabilities (CVE-2024-32002, CVE-2024-52005) in Git's sideband channel. The patch introduces basic sanitization of control characters in remote output, replacing them with caret notation (e.g., `^[` for escape sequences) to prevent terminal state manipulation and input buffer injection attacks.

The change affects how Git processes output from remote operations like `git clone`, where server-controlled content could previously include malicious control sequences. The implementation adds a new `strbuf_add_sanitized()` function that filters all control characters except tabs and newlines, with test coverage verifying the sanitization works for ANSI color sequences.

This is the first patch in a 7-part series that will later introduce more granular controls. The immediate change takes a conservative security-first approach while leaving room for future refinements. The patch has already seen production validation in Git for Windows and Red Hat environments.

The security impact is significant as it closes a potential attack surface where malicious servers could manipulate client terminals. The accompanying test demonstrates the sanitization in action, showing that color sequences from a pack-objects hook are properly filtered out.
