This patch is part of Patrick Steinhardt's ongoing ODB abstraction series, specifically moving reparenting logic for relative paths into the files backend subsystem. The change relocates working directory tracking from the generic ODB layer to the files-specific implementation, where it more naturally belongs.

The patch removes the global `odb_update_commondir()` handler and replaces it with two targeted callbacks: `odb_source_files_reparent()` for the main files backend and `tmp_objdir_reparent()` for temporary object directories. This better encapsulates the path-handling logic within the subsystems that actually need it, rather than having the ODB layer coordinate everything.

Review discussion with Justin Tobler raised questions about the clarity of working directory change descriptions and path storage design. Patrick clarified that the current path storage in the base structure is temporary and will be removed in future work, though declined to add a NEEDSWORK comment since the relative path issue isn't immediately actionable.

This is a mechanical but important architectural change that helps separate concerns as part of the larger ODB abstraction effort. The patch maintains all existing behavior while better isolating filesystem-specific logic.
