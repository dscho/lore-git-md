This is a performance and compatibility patch series for `contrib/subtree`, specifically targeting recursion limits in `git subtree split` on systems with restricted shell recursion depth (notably Debian/Ubuntu's POSIX shell).

Colin Stagner sends version 2 of a three-patch series that restructures the split operation's rejoin-deepening algorithm to avoid hitting shell recursion limits. The core issue is that some shells (like Debian's default POSIX sh) impose a 1000-call recursion limit, which `git subtree split` can exceed when processing deep history graphs. The series builds on version 1 with a rebase onto current master (628a66ccf6) but no substantive changes to the patches themselves.

The series takes a three-step approach: first reducing function side effects in the trailer processing, then functionalizing the traversal logic, and finally replacing recursive processing in `check_parents()` with bulk range processing. The final patch is the most significant, adding 54 lines to handle commit ranges in bulk until the next rejoin point, with extensive comments explaining the history graph cases. The changes are confined to `contrib/subtree/git-subtree.sh` with 88 lines added and 7 removed across the series.

Notably, the cover letter still lacks performance measurements or confirmation that the changes resolve the issue on affected Debian/Ubuntu systems, despite mentioning testing on a large repository. The series appears technically complete but awaits review feedback. The changes are specific to the subtree implementation and don't interact with other in-flight topics.
