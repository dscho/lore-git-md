This is part of the ongoing security effort to address ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Patch 4/7 in the v5 series expands the configurable sanitization options for control sequences.

The patch introduces finer-grained control over which ANSI escape sequences are allowed through the sideband channel. Building on the existing `sideband.allowControlCharacters` configuration, it now supports comma-separated values to selectively permit cursor movement sequences (`cursor`) and character erasure sequences (`erase`), in addition to the existing color sequence support (`color`). The implementation uses bitmask flags to track allowed sequence types.

The changes maintain security as the default - only ANSI color sequences are permitted unless explicitly configured otherwise. The test suite is expanded to verify the new configuration options work as expected, including proper handling of cursor movement and erase sequences when enabled. This represents a middle ground between security and compatibility, addressing concerns about legitimate uses of these sequences in hooks while still providing protection against malicious use.

The series has undergone extensive production validation in Git for Windows and Red Hat environments, and Junio Hamano has indicated plans to merge patches 1-6 to 'next' for further testing while deferring the default behavior change (to block non-color sequences) until Git 3.0.
