This is a bugfix discussion thread about memory leaks in pack index handling during clone operations. Jacob Keller reports seeing leaks when using AddressSanitizer, which Jeff King traces to improper cleanup of mmap'd pack indexes in `check_connected()`. The issue becomes visible because ASan builds use `NO_MMAP` (converting mmaps to heap allocations), making leaks detectable that would otherwise go unnoticed.

Jeff provides a fix adding proper `close_pack()` calls in `connected.c`'s error paths. The discussion reveals subtle interactions between build configurations - ASan enables `NO_MMAP` while leak checking typically uses LSan without it, meaning these leaks were previously invisible due to toolchain quirks rather than being truly harmless.

The exchange demonstrates Jeff's characteristic attention to resource lifecycle details, explaining both the immediate fix and the broader context of why this leak surfaced now. Jacob confirms the analysis while noting the practical impact is currently minor (leaks during program exit), though worth fixing to prevent future issues if code paths change. The thread shows Git's careful approach to memory management even in cases where leaks might seem benign.
