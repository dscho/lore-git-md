This is a bugfix patch in the fsmonitor series, specifically addressing a potential hang condition in the filesystem monitoring daemon. The patch replaces an infinite wait for cookie file events with a one-second timeout, preventing indefinite blocking when filesystem events fail to arrive (a known issue on certain container/overlay filesystems).

The technical change converts a `pthread_cond_wait()` to `pthread_cond_timedwait()`, adding timeout handling that will:
1. Calculate a timeout 1 second in the future using `gettimeofday()`
2. Break the wait if the timeout expires (`ETIMEDOUT`)
3. In timeout cases, mark the cookie result as an error which triggers a full scan response rather than hanging

The patch maintains all existing functionality while adding the safety net. It's part of the larger cross-platform fsmonitor effort that has gone through 11 iterations, with this particular change addressing a reliability concern observed in production container environments. The implementation now properly handles cases where inotify watches succeed but events never arrive, which was a known gap in the previous version.
