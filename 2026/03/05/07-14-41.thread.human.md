The thread began with Norbert Kiesel requesting a `--created` flag for `git worktree list` to help manage repositories with many worktrees, where the current unspecified output order makes it difficult to identify recently created ones. Johannes Sixt suggested using filesystem timestamps via shell pipelines, but Norbert demonstrated these are unreliable since directory modification times update when files are added, not just at creation.

Maintainer Junio Hamano has now weighed in, clarifying that Git doesn't track worktree creation timestamps, making the original request unfeasible in its current form. With characteristic humor, he suggested the output might be manageable with a tall enough terminal, then proposed a more general direction: enhancing worktree metadata storage, possibly modeled after the `.git/description` file pattern. This would allow `git worktree list --verbose` to display various descriptive attributes rather than just creation times.

Junio's response effectively closes the door on the immediate timestamp-sorting request while opening a broader discussion about worktree metadata design. The thread now faces a pivot - whether contributors will pursue the generalized metadata approach Junio suggested or continue advocating for creation timestamp tracking specifically. Given Junio's maintainer role, his metadata-storage direction appears the most likely path forward if this feature is to be implemented.
