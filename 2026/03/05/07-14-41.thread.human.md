This thread began with a feature request from Norbert Kiesel for `git worktree list --created` to help manage many worktrees by sorting them by creation time. The discussion took a turn when Junio Hamano pointed out that Git doesn't track worktree creation timestamps at all, shifting the conversation from a specific sorting flag to a broader question of how Git should store worktree metadata. Junio suggested modeling this after `.git/description` files as a general solution.

Norbert demonstrated a practical workaround using filesystem timestamps in a Zsh script, though this approach has limitations since moving worktrees updates their timestamps. The script serves as both a temporary solution and proof of concept for the desired functionality.

Erik Cervin Edin has now joined the discussion, expressing support for Junio's general metadata approach. While Erik notes that worktree names currently serve as informal metadata, he agrees a dedicated system would be cleaner. This reinforces the maintainer's direction that any solution should be general-purpose metadata infrastructure rather than timestamp-specific.

The core question now is whether contributors will pursue this generalized metadata storage approach. Technical details remain open - file format, location, and how it would integrate with commands like `git worktree list --verbose`. While the original timestamp sorting need remains valid, the solution space has clearly expanded to consider a more comprehensive metadata system that could include creation dates among other fields.
