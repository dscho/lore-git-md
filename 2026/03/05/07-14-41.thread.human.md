This thread explores adding creation timestamp support to `git worktree list` to help users manage repositories with many worktrees. Norbert Kiesel originally proposed a `--created` flag to sort worktrees by creation time, citing his need to identify recent worktrees among 20+ in his workflow. Johannes Sixt (Hannes) suggested an alternative using filesystem timestamps via shell commands, arguing against expanding Git's core functionality for this use case.

In the latest exchange, Norbert points out a key limitation of Hannes' approach: directory modification times don't reliably indicate creation since they update when files change. He maintains that only proper creation timestamp tracking in Git's metadata would solve his problem. The discussion has revealed a philosophical divide - between keeping Git's interface minimal versus accommodating power user needs - without clear technical consensus yet.

The thread awaits input from maintainers on whether this functionality warrants core changes. Key questions remain about timestamp accuracy requirements and where to draw the line between built-in features and external tooling solutions. For now, users needing this capability must choose between unreliable filesystem timestamps or waiting for potential core changes.
