This is the final version of a feature series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The series has undergone extensive review and testing over 11 iterations.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include recursive directory watching via inotify_init1(O_NONBLOCK), bidirectional watch descriptor mapping, and rename tracking using inotify cookies. The daemon properly handles process isolation and cleanup, with a 30-second timeout for shutdown.

The series also includes important fixes for memory leaks in the platform-independent daemon code and deduplicates IPC and settings logic shared between macOS and Linux. Notable changes in this final version include reverting to a simpler flag-based file descriptor cleanup approach (rather than a callback mechanism) per Junio's preference, and converting pathname deduplication from khash to strset as suggested.

The implementation has been production-tested and addresses all prior review concerns, including overlayfs reliability, container environment stability, and Windows compatibility (now including pthread timed wait support). The test suite provides comprehensive coverage of real-world filesystem behaviors and edge cases.

This represents the completion of a major cross-platform feature that brings fsmonitor to Linux users with full Windows compatibility, while maintaining the carefully designed architecture of the existing implementations. The series is now ready for integration with no remaining open questions.
