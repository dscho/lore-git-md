This RFC series from Usman Akinyemi adds remote group support to `git push`, mirroring the existing functionality in `git fetch`. The feature allows pushing to all remotes in a configured group (defined via `remotes.<name>` config) with a single command like `git push all-remotes`. The implementation has gone through several iterations with thorough review from maintainer Junio Hamano, who has provided guidance on both architectural decisions and final polish items.

The series is now functionally complete, with all key design questions resolved. Junio recently caught one final issue - the test script hardcodes 'main' as the branch name, which will break when Git 3.0 changes the default branch name to 'master'. He provided a simple fix (adding `GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME=default`) to future-proof the tests. This was caught by Git's CI infrastructure, demonstrating the value of the project's testing setup.

With this last test adjustment, the series appears ready for merging. The implementation preserves the principle that group pushes should behave identically to sequential individual pushes, handles all push modes and force-with-lease semantics correctly, and includes comprehensive test coverage. The author has been responsive to all feedback throughout the review process, and Junio's attention to this final detail suggests high confidence in the implementation.
