Usman Akinyemi has proposed an RFC series to add remote group support to `git push`, mirroring the existing `git fetch` functionality. The series would allow pushing to all remotes in a configured group with a single command like `git push all-remotes`. The implementation comes in two parts: first a mechanical refactoring to move group-handling code from fetch.c to remote.c, followed by the actual push-to-group functionality.

Junio Hamano has reviewed the first (refactoring) patch and found it generally sound, with only a minor stylistic concern about an `UNUSED` macro in a public header declaration. His approval of the naming and structure suggests the preparatory work is on the right track. The second patch implements the core functionality, handling each remote in the group sequentially while respecting per-remote push configurations and properly isolating flags and exit codes.

The implementation currently has some limitations around parallel push support and force-with-lease semantics for groups, which remain open design questions. The author has indicated that documentation and test coverage will follow in future iterations. With Junio's early engagement and positive feedback on the refactoring, the series appears to be moving in a promising direction toward eventual inclusion.
