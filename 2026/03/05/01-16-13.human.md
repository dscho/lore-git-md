This is part 7/12 of a series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The patch introduces the core inotify listener implementation that watches for filesystem changes.

The implementation uses inotify rather than fanotify since fanotify requires elevated privileges. It handles directory watches recursively, tracks renames via event cookies, and includes robust error handling for cases like unmounts or queue overflows. The code maintains bidirectional mappings between watch descriptors and paths for efficient event resolution.

Key technical aspects include:
- Uses inotify_init1(O_NONBLOCK) with a poll loop and 50ms timeout
- Tracks directory renames via IN_MOVED_FROM/TO event pairs with cookie matching
- Detects remote filesystems (NFS/SMB) via statfs() and /proc/mounts scanning
- Includes comprehensive logging via trace facilities
- Handles edge cases like stale renames and watch descriptor management
