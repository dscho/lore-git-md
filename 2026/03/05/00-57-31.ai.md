This is a feature patch implementing URL-based partial clone filter configuration, representing the final technical piece of Alan Braithwaite's proposal after extensive discussion. The patch adds a new `clone.<url>.defaultObjectFilter` config option that automatically applies partial clone filters based on URL patterns.

The implementation uses Git's existing urlmatch infrastructure to support three levels of URL matching (domain, namespace path, or full project path), with the most specific match winning. The filter is only applied during the initial clone operation and gets recorded in the remote's config for subsequent fetches. Command-line `--filter` overrides the config, and non-URL-qualified config entries are ignored.

The patch includes thorough test coverage verifying:
- Basic filter application via URL config
- Command-line override behavior
- Support for different filter types (blob:limit, blob:none, tree:0)
- URL matching precedence rules
- Proper handling of non-matching URLs and bare config keys

This represents the consensus design from the thread, addressing Patrick Steinhardt's concerns about safety boundaries by limiting the feature to clone operations only while maintaining consistency with Git's HTTP configuration patterns. The implementation is clean and well-tested, with clear documentation of the behavior and precedence rules.

The patch appears ready for merging pending any final maintainer review, as the key technical decisions have been settled in the discussion. It provides a useful quality-of-life improvement for users who regularly clone repositories that benefit from partial clone filters.
