Bugfix targeting a memory leak in the clone operation. Jacob Keller reports a consistent 27KB memory leak when cloning repositories, detected by AddressSanitizer. The leak originates in `check_packed_git_idx()` via `git_mmap()`, ultimately called through the clone` command's ref update path. The stack trace shows the leak occurs during packfile index handling but the connected-check phase of cloning.

The commit message doesn't propose a fix - it's just reporting the issue with a clear reproduction case (current `next` branch at 7842e34a6654). This looks like a legitimate leak that warrants investigation, though the impact appears limited to the relatively small 27KB per clone operation. The clear ASAN output and reproduction instructions make this easy for someone familiar with the packfile or mmap code to investigate further.
