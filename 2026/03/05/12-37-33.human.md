This is a feature patch introducing a new `pre-add` hook mechanism, now in its fifth iteration. The hook allows inspecting and potentially rejecting staged changes before they are finalized during `git add` operations.

The patch series has seen significant review engagement, with all technical concerns from previous rounds addressed. Version 5 makes two key changes: switching from `find_hook()` to `hook_exists()` to properly support config-defined hooks (per Adrian Ratiu's suggestion), and adding a test case for config-based hook discovery. The implementation also includes Windows CI fixes for the test suite.

The hook receives two arguments: the path to the current index and a lockfile containing the proposed staged state. It can inspect the changes using standard Git commands but must accept or reject the entire update (no per-path filtering). The hook is bypassed with `--no-verify` and doesn't run for interactive/patch/dry-run modes or `git commit -a`.

The documentation clearly explains the hook's capabilities and limitations, including its inability to filter individual paths in multi-file adds. Test coverage is thorough, including real-world use cases like blocking `.env` files and secret keys. The implementation ensures the original index remains unchanged if the hook rejects the changes.

Maintainer Junio Hamano has confirmed the technical approach and documentation style in previous iterations, suggesting this is likely nearing merge readiness. The remaining open question is Phillip Wood's concern about the hook seeing all staged changes rather than just the current add operation.
