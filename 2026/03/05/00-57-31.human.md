This is a feature patch implementing configurable partial clone filters, now narrowed to URL-based configuration for clone operations only, as previously discussed in the thread.

Alan Braithwaite's patch adds `clone.<url>.defaultObjectFilter` configuration that lets users specify default partial clone filters per URL pattern. When cloning a repository whose URL matches a configured pattern, Git automatically applies the filter as if `--filter` was passed on the command line. The URL matching follows Git's existing HTTP configuration rules, with the most specific match winning.

Key aspects:
- Only affects the initial clone operation (not subsequent fetches)
- Command line `--filter` takes precedence over the config
- Uses Git's urlmatch infrastructure for URL pattern matching
- Records the filter in remote config so subsequent fetches inherit it
- Includes comprehensive tests covering different filter types, URL matching precedence, and edge cases

The implementation looks clean and well-tested, with thorough documentation. This represents the final technical implementation of the feature after the mailing list discussion converged on URL-based configuration limited to clone operations. The patch appears ready for review and potential merging.
