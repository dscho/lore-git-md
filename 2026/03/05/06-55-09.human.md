This is part of the cross-platform fsmonitor implementation series, specifically addressing process isolation and cleanup in the daemon. Patch 9/12 focuses on ensuring the fsmonitor daemon properly detaches from its parent process and cleans up inherited file descriptors.

The patch makes two key changes to prevent hangs and resource leaks:
1. Adds `close_fd_above_stderr` to both explicit daemon startup (`fsmonitor--daemon start`) and implicit spawn paths, closing unnecessary inherited file descriptors that could cause parent processes to wait indefinitely.
2. Implements proper session detachment on Unix via `setsid()` (matching the existing Windows `FreeConsole()` behavior) to prevent shells from waiting on the daemon when it's spawned implicitly.

The changes address real-world issues seen in test harnesses and CI systems where inherited pipe file descriptors could cause hangs. The implementation is careful to maintain cross-platform compatibility while solving these process isolation problems.

This is a well-motivated change in the final iteration of a long-running series, with all technical concerns already addressed in previous rounds of review. The patch completes the process management aspects of the fsmonitor daemon implementation.
