This is part of a security-focused patch series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). The patch introduces a configurable escape hatch (`sideband.allowControlCharacters`) to selectively permit control characters in sideband messages, while maintaining the default security protections added in the previous patch.

The change allows remote servers to deliberately use ANSI color sequences (like `\033[31m` for red text) when explicitly permitted by configuration, addressing use cases where colored output increases message urgency. The implementation adds a new config option documented in `Documentation/config/sideband.adoc` and modifies `strbuf_add_sanitized()` to bypass control character filtering when the setting is enabled.

Test coverage in `t5409-colorize-remote-messages.sh` verifies both the default blocking behavior and the opt-in allowance of color sequences. The patch represents a compromise between security hardening and backward compatibility, with production validation already completed in Git for Windows and Red Hat environments. This is the second of seven patches in a mature series that Junio Hamano proposes merging to 'next' for extended testing.
