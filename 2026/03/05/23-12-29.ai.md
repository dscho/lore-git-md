This is the third patch in Jeff King's series addressing memory leaks in pack index handling, specifically focusing on `.rev` file double-loading. The patch fixes a case where `fsck` could overwrite an existing mmap'd revindex without properly cleaning up the previous mapping, leading to leaks that only become visible when built with `NO_MMAP` (which converts mmaps to heap allocations that leak detection tools can catch).

The issue stems from `fsck` directly using `load_pack_revindex_from_disk()` instead of the usual `load_pack_revindex()` entry point, bypassing the check for already-loaded data. This causes problems when the revindex is accessed earlier (like during promisor object checks) and then overwritten during fsck validation. The fix adds a simple check for existing `revindex_data` before loading from disk - a clean solution that maintains the current code structure rather than complicating `fsck`'s logic.

The patch demonstrates Jeff King's characteristic attention to resource lifecycle details, catching a subtle interaction between different code paths that only manifests under specific build configurations. While the leaks were small (and only detectable with `NO_MMAP`), the fix ensures proper cleanup in all cases. The change is minimal (just 4 lines) but effectively plugs the leak that was causing test failures in several scripts when built with leak detection enabled.
