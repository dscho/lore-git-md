This is a memory leak fix in the fsmonitor daemon, part of a larger series adding Linux support for filesystem monitoring. The patch addresses a cleanup oversight where the `state.cookies` hashmap and its allocated strings were not being freed when the daemon shuts down.

The fix is straightforward: it adds proper cleanup code to iterate through the hashmap entries, free each cookie name string, then clear and free the hashmap itself. This plugs a leak that would accumulate memory over time with each daemon restart.

As part of the 12-patch series (now in its 11th iteration), this contributes to the overall goal of robust cross-platform fsmonitor support. The series has undergone extensive review and testing, with this being one of the final cleanup items identified. The patch appears well-contained and correctly implements the needed cleanup without introducing new complexity.
