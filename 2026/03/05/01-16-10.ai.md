This patch completes the cross-platform fsmonitor implementation by adding Windows compatibility for pthread_cond_timedwait(), a critical piece that was previously missing. The change addresses a potential hang condition where the fsmonitor daemon could wait indefinitely for cookie events on certain filesystems (notably container/overlay setups where inotify watches succeed but events never arrive).

The implementation replaces an infinite pthread_cond_wait() with a 1-second timeout using pthread_cond_timedwait(), falling back to a full scan if the timeout occurs. This matches the behavior already established for other platforms and completes the Windows compatibility story by ensuring all pthread requirements are met (the Windows emulation layer now properly handles timed waits via SleepConditionVariableCS() with timespec conversion).

Key technical details:
- Uses gettimeofday() and timespec for timeout calculation
- Maintains the same cookie tracking system (FCIR_INIT/FCIR_ERROR states)
- Preserves existing lock/unlock patterns around the condition variable
- Adds trace logging for timeout cases
- Keeps the same error fallback behavior (trivial full-scan response)

This change represents the final piece needed for reliable cross-platform fsmonitor operation, particularly in container environments where filesystem event delivery cannot be guaranteed. The patch has been through extensive review and testing, with all memory leaks and hang conditions resolved in previous iterations of the series.
