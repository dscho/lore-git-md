This is the second patch in Jeff King's series fixing memory leaks in pack index mmap handling, specifically addressing a leak in `check_connected()`. The patch fixes a case where mmap'd pack index data wasn't being properly cleaned up when checking connectivity during clone operations.

The issue occurs when Git creates a temporary `packed_git` struct to verify the contents of a newly received pack. While a previous commit added `free()` to clean up the struct itself, it missed cleaning up the mmap'd index data inside. The leak only becomes visible when using Git's compatibility layer that converts mmaps to heap allocations (enabled via `NO_MMAP=MapsBecomeMallocs`), which is why it wasn't caught by normal leak checking.

The fix is straightforward: call `close_pack()` before freeing the struct, which properly handles both the mmap cleanup and NULL checks. This matches the pattern used elsewhere in the codebase for pack cleanup. The patch demonstrates Jeff King's characteristic attention to resource lifecycle management - he not only fixes the immediate leak but explains why it wasn't caught earlier and how the fix interacts with different build configurations.

This change is part of a broader effort to improve resource management in core Git operations, particularly around packfile access. The series as a whole addresses several similar leaks that were made visible by more rigorous leak checking configurations.
