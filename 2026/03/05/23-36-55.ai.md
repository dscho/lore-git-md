This is a follow-up in the worktree metadata discussion thread, where the original feature request for creation timestamp sorting has evolved into a broader conversation about worktree metadata storage.

Norbert Kiesel shares a Zsh script workaround that uses filesystem creation timestamps (via `stat -f %B`) to approximate worktree age, while acknowledging the limitation that moving a worktree updates these timestamps. The script parses `git worktree list --porcelain` output, collects timestamps, and presents a sorted view with formatted dates. This demonstrates the practical need while highlighting why filesystem timestamps alone are insufficient.

The email reinforces Junio Hamano's earlier point that Git currently doesn't track worktree creation times, making the original request unfeasible without core changes. Norbert's script serves as both a temporary solution and a proof-of-concept for what users want from the feature. The thread has clearly shifted from a simple sorting request to deeper questions about metadata persistence in Git's worktree system.

Key technical details include:
- The script's parsing of porcelain format worktree data
- Use of Zsh arrays and sorting capabilities
- Filesystem timestamp limitations (modification on move)
- Implicit endorsement of Junio's suggestion for a `.git/worktrees/<id>/description`-style solution

The discussion remains open-ended, with no clear consensus yet about how to implement persistent worktree metadata, though the maintainer's preference for a general metadata file approach (rather than timestamp-specific solutions) seems established.
