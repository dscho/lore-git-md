This is a bugfix patch in Jeff King's series addressing mmap-related memory leaks in Git's packfile handling. The patch specifically fixes a leak in `check_connected()` where pack index mmap allocations weren't being properly cleaned up when using the `NO_MMAP` compatibility layer (which converts mmaps to heap allocations).

The issue was originally detected under AddressSanitizer but wasn't caught by standard leak checking due to toolchain quirks. The fix adds proper cleanup by calling `close_pack()` to free associated memory, with careful NULL checking since `close_pack()` doesn't handle NULL pointers like `free()` does. Jacob Keller has reviewed and approved the patch with a Reviewed-by tag.

This is the second of four patches in the series, which collectively address similar leaks across clone operations, fsck, and build configurations. The changes demonstrate Jeff King's characteristic attention to resource lifecycle details, particularly in edge cases that only manifest under specific build configurations. The series is now fully reviewed and ready for merging.
