This is part 8/12 of the fsmonitor series introducing Linux inotify support, focusing on process isolation by closing inherited file descriptors in child processes. The patch adds a `close_fd_above_stderr` flag to `struct child_process` that, when enabled, closes all file descriptors above stderr (FD 2) between fork and exec, skipping the child-notifier pipe. This prevents children from inheriting unwanted descriptors from the parent environment (like test harness pipes).

The implementation caps the close operation at the smaller of `sysconf(_SC_OPEN_MAX)` or 4096, handling platform differences in maximum FD limits. The change is minimal - just 12 lines added to `run-command.c` for the FD closing loop and 9 lines in `run-command.h` documenting the new flag. This builds on the series' earlier work to ensure clean process isolation, now using a simpler flag-based approach rather than the callback mechanism considered in earlier iterations.

The patch fits into the broader fsmonitor effort by ensuring the monitoring daemon starts with no inherited file handles that could cause issues. It's a focused, well-contained change that addresses a specific isolation requirement while maintaining compatibility with existing process spawning behavior. The implementation is straightforward and unlikely to be controversial given its narrow scope and clear benefit for daemon reliability.
