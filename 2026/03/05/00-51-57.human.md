This is a process management patch in the fsmonitor series, addressing file descriptor inheritance and process group issues in the fsmonitor daemon. It's part of a larger effort to provide cross-platform filesystem monitoring support in Git.

The patch fixes two specific problems that can occur when the fsmonitor daemon runs in the background. First, it ensures the daemon closes inherited file descriptors it doesn't need, which prevents hangs in parent processes (like test harnesses or CI systems) that might be waiting for those descriptors to close. Second, it properly detaches the daemon process on Unix systems using `setsid()` to avoid being tied to the spawning shell's process group.

The changes affect both explicit daemon startup (via `fsmonitor--daemon start`) and implicit spawning when a client finds no running daemon. The implementation is careful to maintain Windows compatibility while adding the new Unix-specific behavior. The patch appears well-contained and addresses real-world issues observed in container environments and CI systems.

This is the 9th patch in a 12-part series that has undergone extensive review, with all previous feedback incorporated. The changes here complete the process management aspects of the fsmonitor implementation, complementing the earlier filesystem monitoring and IPC work.
