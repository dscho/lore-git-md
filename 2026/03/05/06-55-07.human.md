This is patch 7/12 in a series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The patch introduces the core inotify listener implementation that watches for filesystem changes.

The implementation uses inotify rather than fanotify to avoid requiring elevated privileges. It handles directory watches recursively, tracks renames via event cookies, and includes robust handling of edge cases like stale renames and remote filesystems. The code establishes bidirectional mappings between watch descriptors and paths, with special handling for directory moves and deletions.

Key technical aspects include:
- Uses inotify_init1(O_NONBLOCK) with a poll loop to drain events efficiently
- Implements recursive directory watching with IN_MASK_CREATE where available
- Tracks renames using inotify's cookie mechanism with timeout-based stale detection
- Detects remote filesystems via statfs() and /proc/mounts scanning
- Includes comprehensive error handling and shutdown procedures
