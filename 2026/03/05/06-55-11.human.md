This is a test patch in the final iteration of a series adding Linux fsmonitor support via inotify. The patch adds comprehensive test coverage for the new Linux backend, including:

1. A smoke test that verifies the filesystem actually delivers inotify events (skipping the entire test suite if events aren't delivered, which handles cases like older overlayfs kernels)
2. A stress test for rapid nested directory creation that exercises race conditions in the daemon's event handling
3. Several reliability improvements to the test infrastructure:
   - Reduced daemon start timeout from 60 to 10 seconds for faster failure detection
   - Better process group handling in test helpers
   - Fallback to /proc/$pid/stat when `ps` isn't available
   - Cleaner process termination handling

The patch demonstrates thorough testing of edge cases that were identified during the 11-iteration development of the Linux fsmonitor support. It completes the test coverage needed to verify the production readiness of this cross-platform filesystem monitoring capability. The changes show careful attention to real-world deployment scenarios (containers, overlayfs) and robust test infrastructure that works across different environments.
