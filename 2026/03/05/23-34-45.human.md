This is a security patch series addressing ANSI escape sequence injection vulnerabilities (CVE-2024-32002, CVE-2024-52005) in Git's sideband channel. Maintainer Junio C Hamano is forwarding Johannes Schindelin's v5 series with adjustments to unblock the stalled discussion.

The core issue is that Git currently passes server output directly to client terminals without sanitizing ANSI escape sequences, which could be exploited to manipulate terminal state or inject malicious input. The series introduces configurable sanitization via `sideband.allowControlCharacters`, allowing per-URL configuration through `sideband_apply_url_config()`. Control characters are replaced with caret notation (e.g., `^[`) to prevent attacks.

Key changes in this version:
- Removes the problematic 'default' configuration value that would have changed meaning across Git versions
- Splits the series to first merge the allowlist approach (patches 1-6) while deferring the default behavior change to Git 3.0 (patch 7)
- Maintains backward compatibility by conditionally compiling the secure-by-default behavior

The implementation has seen extensive real-world validation - over a year in Git for Windows and six months in Red Hat deployments. Junio proposes merging patches 1-6 to 'next' for further testing while keeping open the possibility of switching to a blocklist approach ("filter known-bad sequences") if the allowlist proves too restrictive.

This represents a compromise between immediate security hardening and backward compatibility concerns, with the transitional approach allowing time to evaluate real-world impact before locking in behavior for Git 3.0. The series is well-tested and addresses a clear security vulnerability, though some may find the allowlist approach overly restrictive compared to a blocklist alternative.
