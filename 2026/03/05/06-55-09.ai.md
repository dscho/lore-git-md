This is part 9/12 of the fsmonitor daemon series, focusing on process isolation and cleanup. The patch ensures proper file descriptor handling and process detachment for the fsmonitor daemon in both explicit and implicit startup scenarios.

The key changes include:
1. Adding `close_fd_above_stderr` flag to child processes to prevent inheriting unnecessary file descriptors (particularly important for CI/test environments where pipe inheritance can cause hangs)
2. Implementing proper process detachment via `setsid()` on Unix and `FreeConsole()` on Windows to prevent shell job control interference
3. Suppressing stdout/stderr on the implicit spawn path to avoid terminal pollution
4. Applying these changes consistently across both explicit (`fsmonitor--daemon start`) and implicit (client-triggered) daemon startup paths

The changes address real-world issues seen in CI systems where inherited file descriptors could cause hangs, and improve the robustness of daemon operation by ensuring proper process isolation. This builds on the series' cross-platform approach with platform-specific implementations for process detachment.

The implementation is clean and focused, with clear commit message explanations of both the problem and solution. This patch represents the final iteration of process isolation improvements in the fsmonitor series, having incorporated all previous review feedback.
