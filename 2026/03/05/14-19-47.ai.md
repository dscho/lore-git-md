ODB abstraction patch making `reprepare()` operation pluggable.

This is part 7/17 of Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem to enable pluggable storage backends. The patch introduces a new `reprepare` callback in `struct odb_source` to allow different backends to handle cache invalidation in their own way.

The change moves the existing files backend's reprepare logic (which clears loose and packed object caches) into a new `odb_source_files_reprepare()` function and wires it up via the callback. The high-level `odb_reprepare()` function is simplified to just iterate through sources and call their reprepare callbacks.

Justin Tobler raised concerns in review about whether cache invalidation is truly a backend-agnostic concept, suggesting it might be better handled at a higher level. Patrick acknowledged this as a valid point but explained the current approach maintains consistency with the series' direction, with potential for future refinement via a `prepare()` function with `force` flag. Both agreed that minimizing cache management would be ideal long-term.

This is another mechanical step in the larger ODB abstraction effort, following the established pattern of moving backend-specific operations into callbacks. The change maintains existing behavior while preparing for future backend implementations that may need different cache invalidation strategies.
