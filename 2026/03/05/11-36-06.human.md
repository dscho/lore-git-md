This is the fourth version of a feature patch introducing a `pre-add` hook for Git. The hook allows inspecting or rejecting proposed index updates during `git add` operations before they are finalized.

The implementation provides temporary files representing the original and proposed index states, enabling comprehensive policy enforcement. The hook receives two arguments: the current index path and a lockfile containing the proposed changes. It can inspect the changes using standard Git commands but must treat both files as read-only. The hook accepts or rejects the entire update - per-path filtering is not supported.

Key technical aspects include:
- Bypass options for `--no-verify` and certain modes (interactive, patch, edit, dry-run)
- Proper sequencing with the existing `post-index-change` hook via a new `SKIP_INDEX_CHANGE_HOOK` flag
- Correct handling of mixed-result adds (tracked changes + ignored files)
- Comprehensive test coverage in t/t3706-pre-add-hook.sh with real-world examples

The patch has undergone significant review iteration, with v4 focusing on documentation refinements and clarifying that per-path filtering isn't supported.
