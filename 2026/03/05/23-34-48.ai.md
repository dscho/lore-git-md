This is a security patch in the ongoing series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Patch 3/7 modifies the default behavior to selectively allow ANSI color sequences while still blocking other potentially dangerous control characters.

The change responds to real-world use cases where `pre-receive` hooks rely on color sequences for message visibility, while maintaining protection against terminal state corruption and input buffer injection attacks. The implementation introduces granular control through `sideband.allowControlCharacters` configuration with options for "default" (allow colors only), "false" (block all non-whitespace controls), and "true" (allow all controls).

Key technical details include:
- New `handle_ansi_color_sequence()` function validates SGR (Select Graphic Rendition) sequences
- Default behavior (`ALLOW_ANSI_COLOR_SEQUENCES`) permits `ESC[...m` color codes but blocks other control chars
- Caret notation (`^G`) still replaces blocked characters for visibility
- Test coverage in `t5409-colorize-remote-messages.sh` verifies color passthrough and control character blocking

The patch represents a compromise between security and backward compatibility, with production validation from Git for Windows and Red Hat deployments. It builds on the core sanitization mechanism from earlier patches while addressing brian m. carlson's concern about legitimate color usage in hooks. The series is being queued for 'next' testing with an eye toward Git 3.0's secure-by-default transition.
