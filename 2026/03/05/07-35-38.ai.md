Feature request discussion for `git worktree list` sorting. Johannes Sixt (Hannes) responds to Norbert Kiesel's proposal for a `--created` flag to sort worktrees by creation timestamp.

Hannes argues the use case is too narrow to warrant a dedicated flag, suggesting instead a shell pipeline that sorts worktree directories by filesystem modification time. His proposed alternative uses `cut` to extract paths from `git worktree list` output, then pipes to `ls -ldtr` for time-based sorting. This approach relies on the assumption that worktree directory modification times correlate with creation times, and that paths contain no spaces.

The response indicates skepticism about adding specialized sorting options to the core command when existing Unix tools can compose to solve the problem. Hannes' position suggests a preference for keeping Git's interface minimal and leveraging the Unix philosophy of small, composable tools. This may set up a design philosophy discussion if the thread continues - whether Git should incorporate more workflow-specific conveniences or maintain stricter adherence to doing one thing well.
