This is part 3 of Patrick Steinhardt's 17-part series refactoring Git's object database (ODB) subsystem to enable pluggable storage backends. The patch focuses on embedding the base `struct odb_source` within the files backend's `struct odb_source_files`, establishing the foundation for future backend implementations.

Karthik Nayak raises two key points in review: whether read/write permission checks should be added to the downcast logic (similar to the refs DB), and notes that the current direct call to `odb_source_files_new()` will need to become more modular when additional backends are added. Patrick confirms the permission check idea has merit but isn't currently planned, and explains the eventual modularization will follow the reference backend's extension pattern.

The discussion shows careful attention to the architectural direction, with Karthik considering future needs while Patrick maintains focus on the current incremental step. This continues the series' pattern of thorough technical review from key contributors familiar with the ODB and ref backend work. The patch itself is a mechanical but important step in the larger ODB abstraction effort, preparing the codebase for future backend implementations while maintaining existing files backend behavior.
