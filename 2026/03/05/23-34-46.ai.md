This is the first patch in a security-focused series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). The patch introduces basic sanitization of control characters in sideband output, replacing them with caret notation (e.g., `^[` for escape sequences) to prevent terminal state corruption and input buffer injection attacks.

The implementation adds a new `strbuf_add_sanitized()` function that validates input without allocations, preserving tabs and newlines while escaping other control characters. This provides a security baseline while subsequent patches will introduce more granular controls. The change is tested via a new case in `t5409-colorize-remote-messages.sh` that verifies color sequences are properly sanitized during clone operations.

This initial patch takes a conservative "block all control characters" approach as a starting point, with later patches in the series (not shown here) planned to introduce configurable allowlists for specific ANSI sequences like colors. The implementation has already seen production validation in Git for Windows and Red Hat environments. While this represents a breaking change for workflows relying on raw control sequences in sideband output, the security implications justify the tradeoff.
