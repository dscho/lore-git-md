This is a bugfix patch in the fsmonitor series, specifically addressing a potential hang condition in the filesystem monitoring daemon. The patch replaces an infinite wait for cookie file events with a one-second timeout, preventing indefinite hangs on filesystems where inotify watches succeed but events never arrive (such as certain container/overlay configurations).

The technical change modifies `with_lock__wait_for_cookie()` in `builtin/fsmonitor--daemon.c` to use `pthread_cond_timedwait()` instead of `pthread_cond_wait()`. When the timeout occurs, it logs the event and returns an error response rather than blocking forever. The implementation handles time calculations and proper error checking, including converting between timeval and timespec structures.

This patch is part of a larger effort to provide cross-platform fsmonitor support, now including Windows compatibility through pthread emulation. The change is particularly important for reliability in containerized environments where filesystem event delivery cannot be guaranteed.
