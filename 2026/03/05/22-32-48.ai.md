This is the second patch in a two-part RFC series adding remote group support to `git push`, mirroring the existing `git fetch` functionality. The patch implements the actual push-to-group capability after the first patch refactored the shared group-handling code.

The core change allows pushing to all remotes in a configured group (defined via `remotes.<name>` config) with a single command like `git push all-remotes`. When pushing to a group, each member is processed sequentially with proper handling of per-remote configurations:

1. Refspec lists are rebuilt for each remote to correctly resolve `remote.<name>.push` configurations
2. Mirror flags are evaluated per-remote to prevent force-push bleeding between remotes
3. The implementation preserves existing behavior when pushing to a single remote

The patch addresses several technical challenges:
- Maintaining correct refspec resolution across multiple remotes
- Isolating mirror/force-push flags per remote
- Accumulating exit codes from multiple pushes (using bitwise OR)

Notable limitations called out in the commit message:
- `push.default=simple` will fail if branch upstreams differ across remotes
- No parallel push support yet, unlike `fetch.parallel`
- Force-with-lease semantics across multiple remotes remain undefined

The implementation touches `builtin/push.c` with significant changes to the command's core logic, adding a group-handling path alongside the existing single-remote case. The changes appear carefully considered to maintain backward compatibility while adding the new functionality.

This builds on the refactoring from part 1 (moving group utilities to `remote.c`) and represents the substantive feature implementation. The author indicates tests and documentation will follow in future iterations. The patch carries Junio's Suggested-by for the overall approach.
