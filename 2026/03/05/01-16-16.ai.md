This is the final patch in the fsmonitor daemon series, adding a timeout to the daemon stop command to prevent indefinite hangs. The patch would hang if the daemon failed to shut down properly after sending a quit command over IPC.

The change introduces a 30-second timeout (polling every 50ms) when waiting for the daemon to exit. If the timeout is reached, it returns an error rather than blocking forever. This addresses the last potential hang scenario in the fsmonitor implementation, complementing earlier fixes for container environments and process management.

The implementation tracks elapsed time and includes trace2 regions for observability. This completes the series' reliability improvements by ensuring the stop command fails predictably rather than hanging when the daemon is unresponsive. All review feedback has been addressed in previous iterations, and this final patch adds the last piece of robustness to the cross-platform fsmonitor implementation.
