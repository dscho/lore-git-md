This is part 4 of Patrick Steinhardt's 17-part series refactoring Git's object database (ODB) subsystem to enable pluggable storage backends. The patch moves reparenting logic (handling working directory changes) into the files backend implementation.

The key change relocates path adjustment during working directory changes from generic ODB code to the files-specific backend. Justin Tobler's review identified two main points: the potentially confusing description of working directory changes (which Patrick agreed could be clearer) and questions about the path storage design. Patrick confirms the current storage of paths in the base structure is temporary - he plans to remove it entirely once all direct path access is addressed, but this requires more preparatory work. He declines to add a NEEDSWORK comment about relative paths since the issue isn't immediately actionable.

The technical discussion shows careful attention to both current implementation details and future architectural direction. The review exchange demonstrates the series' thoroughness, with Patrick providing clear explanations of temporary design choices that will evolve as the abstraction matures.
