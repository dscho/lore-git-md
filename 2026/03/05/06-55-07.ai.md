This is patch 7/12 in a series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The patch introduces the core inotify listener implementation that watches directories recursively and handles filesystem events.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory renames via event cookies and bidirectional watch registration. It includes remote filesystem detection via statfs() and /proc/mounts scanning, with fallback behavior when the .git directory is on a network filesystem. The listener maintains watch descriptor to path relationships using hash maps and handles edge cases like stale renames with timeouts.

Key technical details:
- Uses inotify_init1(O_NONBLOCK) with poll loop and 50ms timeout
- Tracks directory renames via IN_MOVED_FROM/TO event cookies
- Detects remote filesystems via statfs() magic numbers
- Implements recursive directory watching
- Handles edge cases like unmounts and queue overflows
- Includes comprehensive error handling and logging

The patch builds on prior work from Eric DeCosta and Marziyeh Esipreh, with all review feedback from previous iterations addressed. It's part of a mature series that has undergone extensive testing, with Paul Tarjan reporting production reliability across large deployments. The implementation is now stable and ready for integration.
