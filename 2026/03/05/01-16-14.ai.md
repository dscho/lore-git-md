This is a refactoring patch in the fsmonitor series that introduces a pre-exec callback mechanism for child processes. The patch adds a `pre_exec_cb` function pointer to `struct child_process` that gets called between fork and exec, providing a clean way to perform child-specific setup like closing inherited file descriptors.

The key changes are:
1. Adds `pre_exec_cb` field to `struct child_process` with documentation
2. Provides a ready-made `close_fd_above_stderr()` callback that closes all file descriptors above stderr (skipping the child-notifier pipe)
3. Implements the callback execution in the child process flow
4. Handles platform differences (no-op on Windows)

This change was motivated by the fsmonitor daemon's need to clean up file descriptors in the child process, but provides a general mechanism that could be useful elsewhere. The implementation is careful to maintain existing behavior on Windows where there is no fork/exec model.

The patch is part of the final iteration (v10) of the fsmonitor series and addresses Junio Hamano's earlier suggestion for a generalized fork/exec callback mechanism. It's a clean, focused change that improves the child process API while maintaining backward compatibility.
