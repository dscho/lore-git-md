This is part of the fsmonitor feature series adding Linux support via inotify, specifically addressing daemon shutdown reliability. Patch 10/12 introduces a 30-second timeout for the `fsmonitor--daemon stop` command, preventing indefinite hangs if the daemon fails to exit cleanly.

The patch modifies the shutdown polling loop to track elapsed time and return an error if the daemon remains active after 30 seconds (polling every 50ms). This completes the series' reliability improvements by ensuring the stop command fails predictably rather than blocking forever in edge cases like a wedged daemon.

The implementation is straightforward - it adds timing logic around the existing state check while maintaining the same IPC communication flow. This comes after extensive testing and review across the 11-iteration series, with all major technical concerns already addressed in prior patches. The change aligns with the series' goal of robust cross-platform fsmonitor support.
