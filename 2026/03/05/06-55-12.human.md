This is the final patch in a 12-part series introducing Linux fsmonitor support using inotify, bringing feature parity with existing Windows and macOS implementations. The series has undergone 11 iterations with extensive review and testing.

The patch converts the pathname deduplication in `do_handle_client()` from using a khash-based string set to the newer strset API, as suggested by Patrick Steinhardt. This is a clean-up change that simplifies the code while maintaining the same functionality - the strset provides a more straightforward interface for string set operations. Since the paths are already interned strings, the patch sets `strdup_strings=0` to avoid unnecessary copies.

This change follows through on earlier feedback and represents the last technical refinement in the series that has already addressed all major concerns around reliability, platform support, and edge case handling. The fsmonitor implementation is production-ready across all major platforms with comprehensive test coverage.
