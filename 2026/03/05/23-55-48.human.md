This is a refactoring patch for the `contrib/subtree` script, part of the `git subtree` command's implementation. It's the second in a three-part series (v2) from Colin Stagner.

The patch extracts the commit traversal logic used by `git subtree split` into a new function `find_commits_to_split()`. This function handles the ancestor-first history traversal needed for subtree operations, taking the starting point and excluded revisions as parameters. The change also switches from passing excluded revisions via command-line arguments (which could hit length limits) to passing them via stdin, and removes an unnecessary `eval` that was previously used.

The refactoring appears clean and focused - it doesn't change behavior but makes the code more maintainable by:
1) Giving the traversal logic a clear name
2) Documenting its purpose and parameters
3) Eliminating a potential command-line length issue
4) Removing an eval that could be a security concern

The patch is small (30 lines changed) and well-contained to the subtree script. Since `git subtree` is in contrib/ rather than core Git, this change is unlikely to affect most users but will be appreciated by those working on or with the subtree command.
