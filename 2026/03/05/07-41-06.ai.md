This is a discussion about adding creation timestamp support to `git worktree list`, part of an ongoing thread about worktree management.

Norbert Kiesel responds to Johannes Sixt's suggestion of using filesystem timestamps via shell pipelines, pointing out that directory modification times don't reliably track worktree creation since they update when files are added. He reiterates his need for an explicit creation timestamp in the worktree metadata to properly identify recently created worktrees among his 20+ worktrees per repository.

The technical disagreement centers on whether this functionality belongs in core Git (Norbert's position) or can be adequately handled by external tools (Hannes' position). Norbert's reply suggests the filesystem-based workaround doesn't solve his actual use case since directory mtimes don't correspond to creation events. This moves the discussion toward whether Git should start tracking and exposing worktree creation timestamps as first-class metadata.

The exchange highlights a tension between Git's minimalist design philosophy and practical workflow needs for power users managing many worktrees. No maintainers have weighed in yet, leaving the architectural question open - whether to add this metadata tracking or consider it out of scope for core Git functionality.
