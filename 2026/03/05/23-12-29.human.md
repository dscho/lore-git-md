This is the third patch in Jeff King's series fixing memory leaks in pack index handling, specifically addressing a case where `.rev` files could be double-loaded during fsck operations. The patch fixes a subtle leak that occurs when fsck directly calls `load_pack_revindex_from_disk()` without checking if the revindex is already loaded, potentially overwriting an existing mmap without freeing it.

The issue was discovered through ASan reports when built with `NO_MMAP` (which converts mmaps to heap allocations), though it affects normal builds too. The fix adds a simple check to avoid reloading already-loaded revindex data. Jeff notes this shows up in several test cases (t5601, t0410, t5702, t5616) when leak checking is enabled.

This continues the series' theme of careful resource management in packfile handling. The patch follows Jeff's characteristic style - a small, well-explained change with clear justification for the chosen solution over alternatives. The commit message provides helpful context about why this wasn't caught earlier and how different build configurations interact with the issue.
