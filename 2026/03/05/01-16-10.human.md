This is a bugfix patch in the fsmonitor series, specifically addressing a hang condition in container environments. The patch modifies the cookie wait mechanism in the fsmonitor daemon to use a timeout rather than an infinite wait, preventing indefinite hangs when filesystem events fail to be delivered.

The change replaces an infinite `pthread_cond_wait()` with a one-second timeout using `pthread_cond_timedwait()`. If the timeout expires without receiving the expected event (which can happen on certain container/overlay filesystems where inotify watches succeed but events never arrive), the daemon will report an error and allow the client to proceed with a full scan rather than blocking forever.

This is part of the larger cross-platform fsmonitor implementation effort, now in its 10th iteration. The patch specifically addresses a reliability concern that emerged during testing, where the daemon could hang indefinitely in certain environments. The solution maintains the existing functionality while adding a safety net for edge cases.

The implementation is straightforward and well-contained, modifying only the wait logic in `builtin/fsmonitor--daemon.c`. The patch includes clear error handling and tracing, and the commit message provides good context for why this change is needed. As part of a mature patch series that's been through multiple rounds of review, this appears ready for integration.
