This is a test patch for the Linux fsmonitor implementation, part of the cross-platform filesystem monitoring series. It adds two key test scenarios and improves test infrastructure robustness.

The patch introduces a smoke test that verifies the filesystem actually delivers inotify events to the daemon, skipping all tests if event delivery fails (as can happen with older overlayfs kernels). It also adds a stress test for rapid nested directory creation to catch race conditions where directory watches may be added concurrently during event processing and recursive scanning.

Several test infrastructure improvements are included:
- Reduced daemon start timeout from 60 to 10 seconds for faster test feedback
- Added fallback to /proc/$pid/stat when `ps` is unavailable (Fedora CI compatibility)
- Improved process group handling with better cleanup and error suppression
- Added job control (`set -m`) for submodule tests to prevent hangs

The changes demonstrate careful attention to real-world deployment scenarios, particularly container environments and edge cases in filesystem event delivery. The test coverage appears thorough, exercising both basic functionality and known problematic edge cases from earlier iterations of the implementation.

This patch represents the final test coverage additions for the fsmonitor series, which has now addressed all review feedback and demonstrated production reliability across multiple platforms. The test improvements here specifically target the Linux implementation's stability and robustness in containerized environments.
