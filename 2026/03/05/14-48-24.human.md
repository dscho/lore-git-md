Maintainer feedback on pre-add hook design concerns.

Junio Hamano, the Git maintainer, concurs with Phillip Wood's critique of the proposed `pre-add` hook's design limitations. The key issue is that the hook only sees changes from the current `git add` invocation, not the cumulative staged state. This creates an awkward workflow where users would need to bypass the hook repeatedly or duplicate checks in a `pre-commit` hook.

Junio explicitly states he remains unconvinced of the hook's value, echoing Phillip's concern that the current design prioritizes implementation convenience over coherent user experience. The maintainer's skepticism suggests this feature may not proceed in its current form unless these fundamental UX issues are addressed.

This email represents a significant hurdle for the proposal, as Junio's reservations go beyond implementation details to question the feature's core utility. The technical implementation may be sound, but the maintainer sees the design as creating more problems than it solves.
