Feature patch adding a `pre-add` hook for staging validation. This is version 5 of the series, now using `hook_exists()` instead of `find_hook()` to support config-defined hooks via `core.hooksPath`. The hook allows inspecting proposed index changes before they're finalized, receiving paths to both the original index and proposed lockfile as arguments. It can be bypassed with `--no-verify` and is skipped for interactive/patch/dry-run modes.

Key technical details:
- Hook receives original index path ($1) and proposed lockfile path ($2)
- Uses new `SKIP_INDEX_CHANGE_HOOK` flag to properly sequence with `post-index-change` hook
- Handles mixed-result adds (tracked changes + ignored files) correctly
- Test coverage in t/t3706-pre-add-hook.sh includes example use cases (blocking .env files/secret keys)
- Now supports hooks defined via `core.hooksPath` configuration
- Includes Windows-compatible path handling in tests
- Documents limitations: cannot reject individual paths in multi-file adds, bypassed in certain modes

The implementation appears solid with thorough test coverage. Documentation clearly explains the hook's behavior and limitations. This version addresses all previous technical concerns and incorporates Adrian Ratiu's suggestion to support config-defined hooks. Phillip Wood's UX concerns about argument scope showing all staged changes (not just current add) remain acknowledged but not fully addressed.
