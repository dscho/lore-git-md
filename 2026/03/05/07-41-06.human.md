This is a follow-up in the discussion about adding creation timestamp sorting to `git worktree list`. Norbert Kiesel responds to Johannes Sixt's suggestion of using filesystem timestamps, pointing out that directory modification times get updated when files are created within them, so they don't reliably indicate worktree creation time.

The exchange highlights a technical limitation of the shell-based workaround proposed by Johannes Sixt (Hannes) - while convenient, directory mtimes don't preserve the original creation timestamp that Norbert needs. Norbert reiterates his case for having explicit creation timestamps in the worktree metadata, suggesting this would provide more accurate information than filesystem timestamps.

The discussion remains at the design phase, with Norbert making a technical counterpoint to Hannes' skepticism about adding a new flag. The core question remains whether this use case justifies modifying Git's worktree metadata versus relying on external tools, with Norbert now providing a concrete reason why the filesystem-based approach may be insufficient. No maintainers have weighed in yet on this latest point.
