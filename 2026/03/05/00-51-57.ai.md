This is a process management patch in the fsmonitor daemon series, addressing file descriptor inheritance and process group issues. The patch ensures the fsmonitor daemon properly detaches from its parent process by closing inherited file descriptors and creating a new session when running in detached mode.

The changes prevent two specific issues: first, inherited file descriptors (particularly from test harnesses or CI systems) that could cause parent processes to hang waiting for EOF, and second, process group relationships that might cause shells with job control to block on the daemon. The solution introduces `close_fd_above_stderr` as a pre-exec callback and adds `setsid()` for proper session detachment, while maintaining Windows compatibility through the existing `FreeConsole()` call.

The implementation touches both the explicit daemon startup path (`fsmonitor--daemon start`) and the implicit spawn path when clients detect no running daemon. The patch is part of a larger effort to make fsmonitor reliable across platforms, with this iteration specifically addressing production concerns around process management and resource cleanup. All review feedback appears incorporated, and the changes align with the series' goal of robust cross-platform filesystem monitoring.
