This is a feature request discussion about worktree listing functionality, now with input from the maintainer Junio C Hamano. The thread began with Norbert Kiesel requesting a `--created` flag for `git worktree list` to help manage repositories with many worktrees (20+), where identifying recently created ones is difficult with the current unspecified output order.

Junio's response clarifies that Git currently does not track worktree creation timestamps, making the immediate request unfeasible. He suggests the output could be manageable with a tall enough terminal (a lighthearted deflection of the core issue) and proposes an alternative direction - enhancing worktree metadata storage. Specifically, he references the underused `.git/description` file and suggests worktrees could have similar metadata files that `git worktree list --verbose` could display.

The maintainer's position introduces new considerations: rather than adding timestamp tracking specifically, he hints at a more general solution for worktree metadata that could accommodate various descriptive attributes. This shifts the discussion from a narrow sorting feature to broader questions about worktree metadata design. Junio's response leaves the door open for contributions in this direction while effectively closing the door on the original timestamp-sorting proposal due to lack of existing infrastructure.

Key technical points:
- Confirmation that Git lacks worktree creation timestamp tracking
- Suggestion to model worktree metadata after the repository description file pattern
- Implicit rejection of filesystem timestamp approaches previously discussed
- The `--verbose` flag is mentioned as a potential vehicle for enhanced metadata display

The thread now faces a pivot point - whether to pursue generalized worktree metadata (as Junio suggests) or continue advocating for creation timestamp tracking specifically. Junio's involvement as maintainer makes his metadata-storage direction the likely path forward if the feature is to be implemented.
