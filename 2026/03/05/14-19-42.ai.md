This is part of Patrick Steinhardt's ongoing object database (ODB) abstraction effort, specifically patch 2/17 in the series. The patch introduces a new "files" source type that encapsulates access to both loose objects and packfiles, mirroring how the refs backend handles loose refs and packed-refs.

The key change moves the loose and packfile storage into a new `struct odb_source_files` that contains both components, replacing the direct `loose` and `packfiles` members in `struct odb_source`. This is a preparatory step for the next patch which will reverse the ownership relationship so the files source contains the base `struct odb_source` rather than the other way around.

The patch is mechanical in nature, updating all callers to access the components via the new `files` member rather than directly. It includes the expected build system updates (Makefile and meson.build) and new header/source files for the files source type. The changes are widespread but straightforward, touching many parts of the codebase that interact with object storage.

This continues the systematic conversion of Git's object storage layer to support pluggable backends. The patch appears well-structured with clear commit message and purpose, though as noted in the thread context, some reviewers have raised questions about specific design choices that will be addressed in future iterations. The changes maintain existing behavior while setting up for the architectural inversion in the next patch.
