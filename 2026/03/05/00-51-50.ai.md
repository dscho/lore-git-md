Bugfix for a memory leak in the fsmonitor daemon's cookie tracking. This is part of the larger cross-platform fsmonitor implementation series that has been in development for several months.

The patch fixes a specific issue where the `state.cookies` hashmap, used to track filesystem event cookies in the Unix fsmonitor daemon, was not being properly cleaned up during shutdown. Each cookie entry contains a dynamically allocated name string (via `strbuf_detach()`) that was also not being freed. The fix iterates through the hashmap to free each cookie name individually before clearing and freeing the hashmap itself.

This is a straightforward cleanup patch that addresses the last known issue in the fsmonitor daemon implementation. The series as a whole has undergone extensive review and testing, with this being a final polish before integration. The change is mechanical and low-risk, following the established pattern for hashmap cleanup elsewhere in the codebase.
