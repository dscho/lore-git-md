RFC series adding remote group support to `git push`, mirroring existing `git fetch` functionality. Authored by Usman Akinyemi. Core idea: enable pushing to all remotes in a configured group (defined via `remotes.<name>` config) with single command like `git push all-remotes`.

Implementation in two parts:
1. [PATCH 1/2] Refactored group-handling code from fetch.c to remote.c for reuse
   - Moved `get_remote_group()`, `add_remote_or_group()`, and `remote_group_data` struct
   - Updated remote.h declarations
   - Purely mechanical code movement with no functional changes
   - Suggested-by: Junio Hamano
   - Maintainer review: Junio confirms naming/scoping appropriate, notes minor `UNUSED` macro concern in header
   - Author follow-up acknowledges `UNUSED` macro feedback, confirms public function naming
2. [PATCH 2/2] Implements push-to-group functionality
   - Processes each remote in group sequentially
   - Rebuilds refspec lists per-remote to respect `remote.<name>.push`
   - Isolates mirror/force-push flags per remote
   - Accumulates exit codes via bitwise OR
   - Currently has separate handling for single remotes vs groups
   - Junio suggests unifying to always use remote_group structure
   - Author agrees with unification approach in follow-up
   - Preserves existing single-remote behavior
   - Suggested-by: Junio Hamano

Key technical details:
- Touches builtin/fetch.c, builtin/push.c, remote.h
- Follows same group config syntax as fetch (`remotes.<name>` lists URLs)
- Significant changes to push.c core logic to handle groups
- Current limitations:
  - `push.default=simple` fails if branch upstreams differ (design question raised)
  - No parallel push support (unlike fetch.parallel)
  - Force-with-lease semantics undefined for groups (design question raised)

Open design questions:
1. Whether to add parallel push support
2. Finalizing force-with-lease behavior across remotes (explicitly raised in follow-up)
3. Error handling strategy for partial failures
4. Documentation and test coverage (promised in future iterations)
5. Resolution of `UNUSED` macro placement in headers (acknowledged, pending fix)
6. Implementation approach for single vs group remote handling (now agreed to unify)
7. Behavior of `push.default=simple` with divergent upstreams (explicitly raised in follow-up)
