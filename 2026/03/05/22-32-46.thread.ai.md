Usman Akinyemi's v5 RFC series adding remote group support to `git push` (mirroring existing `git fetch` functionality). The feature enables pushing to all remotes in a configured group (`remotes.<name>`) via commands like `git push all-remotes`. Implementation uses child processes via `run_command` for each remote to ensure failure isolation as directed by maintainer Junio Hamano.

Key technical details:
- Spawns separate `git push` subprocesses per remote with identical flags/refspecs
- Rebuilds refspec lists per-remote to handle `remote.<name>.push` configs
- Preserves mirror flag isolation (mirror remotes don't affect others in group)
- Touches builtin/fetch.c, builtin/push.c, remote.h, remote.c
- Follows same group config syntax as fetch (`remotes.<name>` lists URLs)
- Preserves single-remote behavior when not using groups
- Accumulates exit codes via bitwise OR (continues after failures)
- Explicitly rejects `--atomic` for group pushes
- Each remote's push follows its own config (`remote.<name>.push`, `push.default`)
- Shares remote group resolution logic between fetch and push via refactored helpers in remote.c (get_remote_group(), add_remote_or_group(), remote_group_data struct)
- Final type safety fixes in v5: consistent `size_t` usage in push_cas_option and remote.h resolves all compiler warnings, including sign-compare issues in CAS option handling
- Comprehensive test coverage in t5528-push-group.sh and t5566-push-group.sh verifying basic functionality, error handling, config interactions, atomic rejection, failure isolation, and mirror flag isolation

Design decisions:
- Group push behaves identically to sequential individual pushes
- `--force-with-lease` semantics apply uniformly
- Failure handling continues pushing after failures with final exit code as bitwise OR
- Process isolation ensures failures don't affect other pushes
- Shared group resolution logic between fetch and push commands via refactored helpers in remote.c
- Mirror flags remain isolated per-remote
- Atomic push explicitly rejected for groups
- Type safety: consistent use of `size_t` for array indices/counts (final v5 fix covering push_cas_option)
