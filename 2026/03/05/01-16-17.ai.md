This is the final test patch in the Linux fsmonitor daemon series, adding comprehensive test coverage for the new inotify-based filesystem monitoring implementation. The tests verify real-world behavior across different filesystems and edge cases, with particular attention to container environments and overlayfs limitations.

The patch introduces several key test scenarios:
- A smoke test that detects non-functional inotify setups (common in overlayfs) and skips the entire test suite if events aren't being delivered
- A stress test for rapid nested directory creation that exercises race conditions in the daemon's event handling
- Improved process group handling and timeout management for reliable test execution
- Platform-agnostic process detection that works without procps utilities
- Background process management fixes for submodule tests

Notable technical details include:
- The smoke test uses a 30-second timeout with trace logging to detect non-functional inotify setups
- The rapid directory creation test verifies handling of EEXIST races during recursive scanning
- Test timeouts are reduced from 60 to 10 seconds for faster failure detection
- Process group handling is hardened to work in CI environments without `ps`
- The submodule pull test now uses job control (`set -m`) for proper background process management

This completes the test coverage for the Linux fsmonitor implementation, addressing all remaining edge cases and platform-specific behaviors identified during review. The tests validate the daemon's stability under heavy filesystem activity and in container environments, while gracefully handling filesystem limitations like overlayfs event delivery issues.
