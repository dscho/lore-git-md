This is a bugfix patch in the fsmonitor Linux support series, addressing a memory leak in the daemon's client handling code. The patch fixes a case where a khash table (`shown`) used for deduplication wasn't being freed when the client received a trivial response, as the cleanup was only happening on the non-trivial code path.

The fix is straightforward: initialize the hash table to NULL and move its cleanup to a shared cleanup section that runs in all cases. This ensures proper resource management regardless of which response path is taken. The change is small (5 lines modified) and focused, with a clear commit message explaining both the problem and solution.

This patch is part of the final v11 iteration of the fsmonitor Linux support series, which has undergone extensive review and testing. The series as a whole introduces inotify-based filesystem monitoring for Linux, bringing feature parity with existing Windows and macOS implementations. This particular fix addresses one of the last remaining memory leak issues identified during the review process.
