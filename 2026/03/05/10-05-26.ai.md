This is the second patch in a two-part series introducing type-safe cleanup for oidmap structures via a new `oidmap_clear_with_free()` API. The series has been narrowed down to just two conversions (rev-list and odb) after maintainer feedback, with other potential conversions definitively dropped.

The patch converts `builtin/rev-list.c` to use the new API for its `missing_objects` map, which stores `missing_objects_map_entry` structs containing dynamically allocated path strings. Previously, the code manually freed paths before calling `oidmap_clear()`. The patch introduces a dedicated callback `missing_objects_map_entry_free()` that handles both path and entry cleanup, then passes it to `oidmap_clear_with_free()`.

Key technical details:
- Changes `path` field from `const char*` to `char*` to enable freeing
- New callback uses container_of() to get full entry from oidmap_entry
- Callback frees both path and entry in one operation
- Maintains same behavior while making cleanup semantics explicit
- Follows pattern established in first patch of the series

The patch has already been approved by both Junio and Patrick Steinhardt, with the callback name updated in v3 per Patrick's request. It includes comprehensive unit tests (added in this patch) to verify the API behavior. The series appears ready for merging with this being the final iteration.
