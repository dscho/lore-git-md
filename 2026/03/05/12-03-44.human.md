This is a follow-up review comment on the pre-add hook patch from Adrian Ratiu, who has been working on hook-related improvements. The email focuses on a technical suggestion to use `hook_exists()` rather than `find_hook()` in the implementation, since the former properly supports hooks defined via Git configuration (not just filesystem paths). 

Adrian notes this is a minor API improvement that would make the pre-add hook more flexible, and suggests adding tests to verify config-based hooks work. While acknowledging that broader cleanup of `find_hook()` usage would be valuable, he clarifies this is out of scope for the current series. The comment comes after the v4 patch has already addressed all major technical concerns and documentation refinements, with Junio Hamano indicating the changes appear merge-ready. Adrian's suggestion represents a final polish that could be incorporated before merging.
