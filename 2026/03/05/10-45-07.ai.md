This is part of Patrick Steinhardt's ongoing object database (ODB) abstraction effort, specifically patch 3/17 in the series. The patch refactors the "files" backend implementation to embed the base `struct odb_source` directly within the specialized `struct odb_source_files`, following the project's standard pattern for pluggable backends.

Karthik Nayak's review confirms the technical approach, noting this change eliminates an allocation while making downcasting between generic and specialized structures more straightforward. The review highlights several benefits: implementation details are better hidden, backend-specific logic becomes more explicit, and it becomes easier to move generic logic out of individual backends. Karthik also raises a forward-looking question about whether read/write permission checks will be added to the refs database's downcast logic.

The patch maintains the existing behavior while preparing for future backend implementations. Karthik observes that while the current implementation directly calls files backend internals (since it's the only backend), this will become more modular as additional backends are added. The review concludes with approval of the patch's technical approach.
