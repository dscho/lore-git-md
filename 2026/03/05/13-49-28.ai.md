This is the final patch in the rebase --trailer series, implementing the new --trailer option for git rebase. The series has now reached its 8th iteration with all major technical questions resolved.

The patch adds support for appending trailers during rebase operations by:
- Validating trailer arguments early in the rebase process
- Forcing rebase (--force-rebase) when trailers are specified
- Properly handling trailers through conflicts and fixup/squash operations
- Maintaining git commit's established trailer ordering (signoffs after other trailers)
- Supporting all rebase modes (interactive and non-interactive)

The implementation builds on the shared trailer infrastructure from earlier patches in the series, which moved core trailer logic into trailer.c while keeping I/O in interpret-trailers.c. The rebase integration follows the pattern of other rebase option additions and enables future command integrations.

Phillip Wood has taken a more active implementation role in this final version while maintaining Li Chen's authorship. The series now includes all requested changes from reviewers, with only minor error handling and documentation updates remaining before merge. The maintainer (Junio Hamano) has accepted the proposed trailer ordering behavior that matches git commit's conventions.

This represents the completion of a significant feature addition to git rebase, allowing in-process trailer manipulation during rebase operations without fork/exec overhead. The shared trailer infrastructure it introduces will also benefit future command integrations.
