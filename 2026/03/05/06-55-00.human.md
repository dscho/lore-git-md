This is the final version of a feature series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The series has undergone extensive review and testing over 11 iterations, with all feedback addressed.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include recursive directory watching, efficient event resolution using bidirectional hashmaps, and robust handling of edge cases like rapid directory creation and container environments.

The series also includes important fixes for memory leaks in the platform-independent daemon code and deduplicates IPC/settings logic between macOS and Linux. Notable changes in this version include reverting to a simpler flag-based file descriptor cleanup approach (rather than a callback mechanism) per Junio's preference, and converting pathname deduplication to use strset as suggested by Patrick Steinhardt.

With comprehensive test coverage, Windows compatibility through pthread emulation, and all known issues resolved, this production-ready implementation represents the completion of a major cross-platform feature that will bring fsmonitor's performance benefits to Linux users. The series is now fully ready for integration with no remaining open questions.
