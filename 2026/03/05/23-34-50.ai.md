Security patch adding per-URL configuration for sideband control character handling. This is part of the ongoing effort to address ANSI escape sequence injection vulnerabilities (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329).

The patch implements URL-scoped configuration for sideband control character sanitization, mirroring Git's existing `http.<url>.*` pattern. Users can now set `sideband.<url>.allowControlCharacters` to override the global setting for specific servers. The implementation builds on Johannes Schindelin's earlier work that introduced configurable sanitization levels via `sideband.allowControlCharacters`, with Junio Hamano now co-authoring this extension.

Key technical changes include:
- New `sideband_apply_url_config()` function called during transport initialization
- Updated configuration parsing in `sideband_allow_control_characters_config()`
- URL matching logic using the existing `urlmatch` infrastructure
- Test coverage in `t5409-colorize-remote-messages.sh` verifying URL-specific behavior

The patch maintains backward compatibility while allowing stricter security policies for untrusted remotes. It represents a compromise between the initial "block all" approach and the need for some workflows (like colored hook output) to pass through certain control sequences. The implementation has seen production validation in Git for Windows and Red Hat environments.

This is patch 5/7 in a series that Junio proposes merging to 'next' for extended testing, with the secure-by-default behavior (only allowing ANSI colors) planned for Git 3.0. The transitional approach uses conditional compilation to manage the compatibility path.
