This is a technical follow-up in Patrick Steinhardt's object database (ODB) abstraction series, specifically addressing questions about patch 5/17 which introduced type safety mechanisms for ODB sources. The patch added an `enum odb_source_type` to enable runtime type checking when downcasting between the generic `struct odb_source` and backend-specific implementations (currently just the files backend). Justin Tobler's original question focused on whether the type enum would have uses beyond downcast validation, to which Patrick confirms there will be cases where callers need to explicitly know the backend type due to files-backend-specific behavior that can't be abstracted away. He also notes his experimental branch already has four distinct backend types (files, loose, packed, inmemory), each requiring its own enum value. This exchange highlights the careful balance being struck in the ODB abstraction between enforcing type safety and maintaining flexibility for future backend implementations. The discussion remains focused on forward-looking design considerations rather than requesting changes to the merged code.
