Final cleanup patch in the fsmonitor series, converting path deduplication from khash to strset. This is a straightforward refactoring that replaces the manual khash string set implementation with Git's built-in strset data structure for tracking seen paths in the fsmonitor daemon's client response logic. The change simplifies the code by using a higher-level abstraction while maintaining the same functionality - the strset handles string interning and deduplication automatically with strset_init_with_options(&shown, NULL, 0) avoiding string copies since the paths are already interned. 

This was the last remaining khash usage in the fsmonitor code, completing the transition to more maintainable data structures. The patch follows Patrick Steinhardt's suggestion and addresses the final code quality issue in the series. With this change, the cross-platform fsmonitor implementation is now fully production-ready with all technical concerns resolved, including memory management, process handling, and now data structure cleanliness. The series has been baking in 'seen' with positive reports from production use.
