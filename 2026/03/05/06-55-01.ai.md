This is a memory leak fix in the fsmonitor daemon's client handling code, part of the final v11 iteration of the Linux fsmonitor support series. The patch addresses a specific issue where the `shown` hash table (used for pathname deduplication) was not being freed when the client received a trivial response, causing a memory leak. 

Paul Tarjan fixes this by initializing the hash table pointer to NULL and moving its cleanup to the shared `cleanup` label using `kh_destroy_str()` (which safely handles NULL). This ensures the hash table is properly freed regardless of which code path is taken. The change is minimal (5 lines modified) but important for resource management in the long-running daemon process.

This patch represents one of the final cleanups in the comprehensive fsmonitor Linux support effort, which has now addressed all memory leaks (including this one in the client response path) and is production-ready across all major platforms. The fix demonstrates the attention to detail in this mature series, where even edge cases in resource cleanup are being caught and resolved.
