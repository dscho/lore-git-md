This is the final patch in a series adding Linux fsmonitor support, specifically addressing process management by adding a timeout to the daemon stop command. The patch ensures the `fsmonitor--daemon stop` command won't hang indefinitely if the daemon fails to shut down, implementing a 30-second timeout with 50ms polling intervals.

The change is straightforward - it adds a timeout check to the existing polling loop that waits for the daemon to exit after sending a quit command. If the daemon doesn't exit within 30 seconds, the command now fails with an error message rather than blocking forever. This completes the process management improvements in the fsmonitor implementation.

The patch is well-contained, touching only the daemon client code, and includes appropriate trace2 instrumentation. It represents the last piece needed for robust process handling in the cross-platform fsmonitor feature, which has been through extensive review and testing across multiple iterations. With this change, the series appears ready for integration.
