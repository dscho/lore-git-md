This is a bugfix patch targeting the `contrib/subtree` script, specifically addressing a recursion depth limitation in POSIX shells on Debian-based systems. The patch is the third in a series (v2 3/3) and focuses on the `git subtree split --rejoin` functionality.

The issue occurs when splitting repositories with thousands of commits, where the current recursive implementation can hit Debian's hardcoded 1000-call recursion limit in POSIX sh. The problem manifests in the `check_parents` function, which processes commit history one commit at a time when looking for rejoin points.

The solution changes the approach from processing commits individually to discovering and processing the complete range of commits back to the next rejoin point in one operation. This significantly reduces the recursion depth needed, though some recursion remains. The patch includes a detailed explanation of the commit message with ASCII-art diagrams showing example commit graphs where this optimization helps.

The change appears well-motivated and technically sound, addressing a real-world limitation while maintaining the same functionality. The patch includes testable examples in the commit message and preserves all existing behavior, just making it more robust against stack overflow in constrained environments. This seems like a worthwhile improvement to the subtree script's reliability.
