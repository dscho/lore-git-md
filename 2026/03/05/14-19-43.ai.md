This patch is part of Patrick Steinhardt's ongoing ODB (object database) abstraction effort, specifically patch 3/17 in the v2 series. It refactors the "files" backend implementation to follow Git's standard pattern for pluggable backends by embedding the base `struct odb_source` within the specialized `struct odb_source_files`.

The change provides several benefits: avoiding an extra allocation, hiding implementation details, enabling compile-time offset calculations for type casting, and making backend-specific dependencies more explicit through required downcasting. The patch introduces `odb_source_files_downcast()` to convert generic sources to files sources, though it always succeeds for now since only the files backend exists. Future backends will make this cast stricter.

The diff shows widespread mechanical changes updating callers to use the new downcast function when accessing files backend internals. The patch maintains existing behavior while preparing for future backend implementations. Review discussion from Justin Tobler and Karthik Nayak on earlier iterations focused on API design details and documentation, with Patrick explaining the temporary nature of some design choices that will evolve as more backends are added.

This is a foundational change in the larger ODB abstraction work, systematically converting core operations to callback-based dispatch while maintaining the existing files backend behavior. The thorough review process and careful architectural boundaries suggest this is a well-considered step in the multi-patch series.
