Bugfix addressing a long-standing memory leak in repository cloning's pack index handling. Jeff King (Peff) confirms Jacob Keller's report of a 27KB leak during clone operations when using AddressSanitizer. The leak occurs in `connected.c` where mmap'ed pack index memory isn't properly freed during connectivity checks.

The root cause involves the `NO_MMAP` compatibility layer that ASan enables - it converts mmaps to heap allocations, making the leak detectable. Peff provides a patch adding missing `close_pack()` calls in three error paths of `check_connected()`. He notes this has likely been leaking small amounts of memory unnoticed in normal builds, only surfacing under ASan's stricter checking.

Technical context: The leak stems from pack index handling during clone's object connectivity verification. The stack trace shows allocation via `git_mmap` through `check_packed_git_idx` and `open_pack_index`. Peff explains the interaction between ASan, `NO_MMAP`, and leak detection settings that made this visible now. His proposed fix would properly clean up resources in all code paths.

This appears to be a legitimate resource management issue in core packfile code, though with limited operational impact (small memory waste during clones). The fix is straightforward but needs to handle NULL pack cases. The discussion may expand to consider whether similar leaks exist elsewhere in the pack handling code paths.
