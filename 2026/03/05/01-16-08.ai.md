This is a memory leak fix for the fsmonitor daemon's cookie tracking system, part of the larger cross-platform fsmonitor implementation effort. The patch addresses a cleanup oversight where the `state.cookies` hashmap and its dynamically allocated cookie names were not being freed when the daemon shuts down.

The fix adds proper cleanup in the daemon's shutdown path by:
1. Iterating through the hashmap to free each cookie's name string
2. Using `hashmap_clear_and_free()` to release the hashmap entries and table itself
3. Placing this cleanup alongside other resource release operations under the `done:` label

This is the final memory-related issue being addressed in the fsmonitor daemon series, which all dynamically allocated resources should be properly managed. The change is straightforward and mechanical - it doesn't modify any behavior while running, only ensuring proper cleanup at shutdown. The patch follows the established pattern seen elsewhere in the codebase for hashmap cleanup.

The fix comes from Paul Tarjan, who has been actively involved in testing and improving the fsmonitor implementation's reliability and resource management. This appears to be the last remaining memory leak in the series, bringing the implementation to a fully production-ready state with no resource management issues.
