This is part of the security-focused series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Patch 4/7 expands the configurable sanitization introduced earlier by adding granular control over which ANSI control sequences are allowed through.

The patch introduces two new categories of permitted sequences beyond just color codes: cursor movements (like `ESC[nA` for moving up n lines) and erase operations (like `ESC[K` for clearing a line). These are controlled via a comma-separated list in `sideband.allowControlCharacters` that now accepts `cursor` and `erase` keywords alongside the existing `color` and boolean values. The implementation uses bitmask flags (`ALLOW_ANSI_CURSOR_MOVEMENTS` and `ALLOW_ANSI_ERASE`) to track these permissions, with the sanitization logic in `handle_ansi_sequence()` updated to validate the additional sequence types. While these sequences are disabled by default due to their potential for hiding malicious activity, the patch acknowledges legitimate uses in hooks and other server-side scenarios.

Test coverage in `t5409-colorize-remote-messages.sh` verifies the new behaviors, including a helper `test_decode_csi` to parse escape sequences in test output. The tests confirm blocked sequences are replaced with caret notation while explicitly allowed sequences pass through when configured. This builds on the production validation already performed in Git for Windows and Red Hat environments, maintaining the series' careful balance between security hardening and backward compatibility.
