This is the fourth and final patch in Jeff King's series addressing memory leaks in mmap handling during clone and fsck operations. The patch modifies the build system to enable `NO_MMAP` when building with leak sanitizer (LSan), ensuring that mmap-related leaks will be caught by the sanitizer.

The change forces Git to use its compatibility layer (which allocates heap buffers instead of mmap) when built with LSan, allowing the sanitizer to detect leaks that would otherwise be invisible since LSan only tracks heap allocations. While this makes the build slightly less performant, the tradeoff is worthwhile for leak detection purposes since LSan builds are already slow and the additional overhead is negligible.

This patch completes the series by ensuring future mmap-related leaks will be caught during development, complementing the three previous fixes that addressed specific leak scenarios in pack index handling during clone and fsck operations. The series demonstrates Jeff King's characteristic attention to resource management details across multiple subsystems.
