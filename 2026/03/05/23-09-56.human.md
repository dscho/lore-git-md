This is the second patch in Jeff King's 4-part series fixing memory leaks in pack index mmap handling during clone operations. The patch addresses a specific leak where `check_connected()` would fail to properly clean up mmap'd pack index data when verifying object connectivity during a clone.

The issue occurs because `check_connected()` creates a temporary `packed_git` struct to verify the pack contents, but while previous fixes added `free()` calls, they missed cleaning up the associated mmap'd index data. Jeff's solution is to call `close_pack()` before freeing the struct, which properly releases both the mmap resources and heap allocations. The patch includes a careful NULL check since `close_pack()` can't handle NULL pointers.

This is a precise, well-explained fix from one of Git's most experienced contributors. The commit message clearly traces the history of related fixes and explains why the leak wasn't caught by normal leak checking. The change is small (just 5 lines) but important for correct resource management in a core operation. The series as a whole shows Jeff's characteristic attention to edge cases and thorough understanding of Git's internals.
