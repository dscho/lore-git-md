This is a memory leak fix in the fsmonitor daemon implementation, part of a larger series adding Linux support for filesystem monitoring. The patch addresses a specific oversight where the `state.cookies` hashmap and its allocated string entries were not being freed during daemon shutdown.

The fix adds proper cleanup code in the `done:` label of `fsmonitor_run_daemon()`, iterating through the hashmap to free each cookie's name string before clearing and freeing the hashmap itself. This completes the memory management for the cookie tracking system used by the fsmonitor daemon to handle filesystem events.

The change is straightforward and clearly correct - it follows the pattern seen elsewhere in the codebase for cleaning up hashmap structures. As part of the final v11 iteration of this long-running series, this patch helps ensure the Linux fsmonitor implementation is fully production-ready with no resource leaks. The series as a whole has already addressed all major technical concerns through extensive review and testing.
