This is a bugfix series addressing memory leaks in mmap handling during Git operations, particularly focused on the packfile subsystem. The series stems from Jeff King's investigation of a leak Jacob Keller reported during clone operations when using AddressSanitizer.

The root issue involves how Git handles memory mapping of pack index files in error paths. The first two patches fix specific leaks in `check_connected()` where pack index mmaps weren't properly freed. Patch 3 addresses a related issue where revindex files could be double-mapped. The series concludes by making these checks more systematic by enabling `NO_MMAP` for all leak-checking builds, which helps surface similar issues by converting mmaps to detectable heap allocations.

Key technical details: The fixes touch core packfile handling code paths that are widely used during operations like `git clone`. The leaks were previously masked in normal operation but became visible under ASan due to its stricter memory tracking. The changes add proper cleanup in error paths and adjust the Makefile to catch similar issues more systematically.

This appears to be a well-motivated series addressing real resource management issues, though the operational impact is limited to small memory waste during certain operations. Jeff King's thorough investigation and test coverage (running the entire test suite with leak-checking enabled) give confidence in the fixes. The changes are focused and unlikely to be controversial, targeting subtle but legitimate bugs in widely-used code paths.
