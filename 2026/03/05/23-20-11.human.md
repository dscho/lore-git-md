This is a bugfix patch addressing a memory leak in the `check_connected()` function during clone operations. The patch is part of Jeff King's 4-part series fixing mmap-related leaks that were discovered under AddressSanitizer builds.

The specific issue occurs when Git creates a temporary `packed_git` struct to verify connectivity of received packfiles during clone. While the struct itself was properly freed in a previous fix, the mmap'd pack index data was being leaked. The patch adds proper cleanup by calling `close_pack()` to release the mmap'd memory.

Jacob Keller, who originally reported the issue, has reviewed and approved this patch with a Reviewed-by tag. The series as a whole appears well-vetted and ready for merging, with all patches receiving positive reviews. This is a focused, technical fix that demonstrates Jeff King's characteristic attention to resource lifecycle details. The change is small but important for preventing memory leaks in a core operation path.
