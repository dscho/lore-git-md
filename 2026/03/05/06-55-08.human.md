This is part 8 of a 12-patch series introducing Linux fsmonitor support using inotify, bringing feature parity with existing Windows and macOS implementations. The series has gone through 11 iterations and is now production-ready.

The current patch adds a `close_fd_above_stderr` flag to `struct child_process`. When enabled, this makes child processes automatically close all file descriptors above stderr (FD 2) between fork and exec, with two exceptions: it skips the child-notifier pipe and caps at either `sysconf(_SC_OPEN_MAX)` or 4096 (whichever is smaller). This prevents children from accidentally inheriting open file descriptors from the parent process, which could cause issues with test harnesses or other environments where stray FDs might interfere.

The implementation is straightforward - it adds the flag to the struct and implements the FD-closing logic in the child process setup code. The patch comes from Paul Tarjan, who has been driving this fsmonitor implementation to completion. Given the extensive review history of this series and the focused nature of this particular change, it appears well-considered and low-risk.
