This is the final patch in the fsmonitor series, implementing process management improvements for the Unix daemon backend. It addresses Junio Hamano's suggestion to generalize the file descriptor handling mechanism.

The patch replaces the specific `close_fd_above_stderr` flag with a more flexible `pre_exec_cb` function pointer in `struct child_process`. The fd-closing logic is now as a standalone `close_fd_above_stderr()` function that fsmonitor callers can use as needed. This maintains the same functionality while providing a more extensible interface for future needs.

Key technical details:
- The new callback mechanism runs between fork and exec
- Existing fd-closing behavior is preserved but now implemented via callback
- All fsmonitor daemon callers updated to use the new interface
- No functional changes to the actual fd handling behavior
- The implementation caps fd scanning at 4096 descriptors or the system's `_SC_OPEN_MAX`
- Maintains all existing process isolation guarantees

This change concludes the fsmonitor series by addressing the last piece of review feedback while keeping the carefully designed architecture intact. The series is now complete with comprehensive filesystem monitoring support across all major platforms, including proper handling of edge cases like overlayfs limitations and remote filesystems.
