This is a process management patch in the fsmonitor daemon series, addressing file descriptor inheritance and process group issues. It's part of the larger cross-platform fsmonitor implementation that brings Linux support (via inotify) alongside existing Windows and macOS backends.

The patch ensures the fsmonitor daemon properly detaches from its parent process by:
1. Adding `close_fd_above_stderr` callback to close inherited file descriptors in both explicit (`fsmonitor--daemon start`) and implicit (client-triggered) daemon startup paths
2. Using `setsid()` on Unix to create a new session when daemonizing, preventing shell job control from blocking on the daemon
3. Using `FreeConsole()` on Windows for equivalent detach behavior
4. Suppressing stdout/stderr on implicit spawn to avoid terminal interference

The changes prevent hangs when the parent process (like test harnesses or CI systems) waits for pipe EOF from descriptors the daemon might inherit. This builds on earlier work to make the daemon reliable in container environments, now with complete process isolation.

Key technical details:
- New `pre_exec_cb` usage with `close_fd_above_stderr` for clean FD handling
- Cross-platform session detachment (Unix `setsid`/Windows `FreeConsole`)
- Output suppression in implicit spawn path
- Maintains existing behavior while adding robustness

The patch represents the final process management piece of the fsmonitor implementation, with all prior review feedback addressed. It's part of a series that's been baking in Junio's 'seen' branch and reported stable in production by the author.
