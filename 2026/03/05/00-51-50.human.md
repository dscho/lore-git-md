This is a bugfix patch addressing a memory leak in Git's filesystem monitoring (fsmonitor) daemon, part of the larger cross-platform fsmonitor implementation effort. The patch is the second in a 12-part series that has been through multiple iterations (now at v9) and is currently in Junio's 'seen' branch.

The specific issue fixed here involves the `state.cookies` hashmap in the fsmonitor daemon, which tracks filesystem change notifications. While the hashmap was initialized during daemon operation, it wasn't properly cleaned up during shutdown, leaking both the hashmap structure itself and the individual cookie names (which were allocated via strbuf_detach()). The patch adds proper cleanup code to iterate through and free all cookie names before clearing the hashmap.

This appears to be a straightforward and well-contained fix to a real issue, discovered by Paul Tarjan during production testing. The change is small (9 lines) and focused, with no behavioral impact beyond fixing the leak. Given that the larger fsmonitor series has already addressed all major technical concerns and review feedback, this late-stage memory leak fix suggests the implementation is now production-ready across all major platforms.
