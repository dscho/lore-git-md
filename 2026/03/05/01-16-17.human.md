This is the final test patch in the fsmonitor Linux support series, adding comprehensive test coverage for the new inotify-based filesystem monitoring implementation. The patch focuses on real-world reliability scenarios and edge cases.

The tests verify that inotify events are properly delivered (with special handling for problematic filesystems like overlayfs), exercise race conditions during rapid directory creation, and ensure proper process group management. The test infrastructure is hardened to work in container environments and CI systems with limited tooling.

Key additions include:
- A smoke test that detects and skips the entire test file if the filesystem can't deliver inotify events (common in overlayfs)
- A stress test for rapid nested directory creation to catch EEXIST race conditions
- Reduced daemon start timeout from 60 to 10 seconds for faster test feedback
- Improved process group handling in test helpers to work without procps
- Proper job control for submodule tests to prevent hangs

The patch represents the culmination of a long series bringing full fsmonitor support to Linux, now with production-ready reliability across all major platforms. All prior review feedback has been addressed, including overlayfs detection, process management improvements, and memory leak fixes. The tests validate that the implementation handles real-world filesystem behaviors correctly.
