This is the fourth version of a feature patch series introducing a `pre-add` hook for Git. The hook allows inspecting or rejecting proposed index updates during `git add` operations before they are finalized.

The implementation provides the hook with two arguments: the path to the current index file and a lockfile containing the proposed staged state. Hook authors can compare these using standard Git commands to validate changes. The hook must accept or reject the entire update - per-path filtering is not supported.

Key technical aspects:
- Uses new `SKIP_INDEX_CHANGE_HOOK` flag to properly sequence with `post-index-change` hook
- Handles mixed-result adds (tracked changes + ignored files) correctly
- Includes comprehensive test coverage in t/t3706-pre-add-hook.sh
- Documents the hook in both `git-add` and `githooks` man pages
- Bypasses hook for interactive/patch/dry-run modes and `git commit -a`

The v4 changes focus on documentation refinements and code cleanup:
- Clarifies that per-path filtering is not supported
- Removes implementation details about stdin handling
- Improves error message wording
- Adds example use cases in tests (blocking .env files and secret keys)

The patch appears well-tested and addresses all technical concerns raised in previous reviews. Documentation now clearly communicates the hook's capabilities and limitations. The implementation provides a clean way to validate staged changes while maintaining Git's existing index change contracts.
