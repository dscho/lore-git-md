This is a bugfix patch in the fsmonitor series, addressing a potential hang when waiting for filesystem events on certain container/overlay filesystems. The patch changes an infinite wait loop to use a 1-second timeout with `pthread_cond_timedwait()`, falling back to a full scan if the timeout occurs.

The change is motivated by real-world cases where inotify watches succeed but events never get delivered, particularly on container/overlay filesystems. The original implementation could hang indefinitely in these cases, blocking both the daemon and client. The new version gracefully handles this by timing out and falling back to a full scan after one second.

The implementation carefully preserves the existing locking behavior while adding the timeout mechanism. It includes proper error handling and tracing, and maintains all the existing cookie tracking infrastructure. The patch is part of a larger series that has already addressed several rounds of review feedback and is now in Junio's 'seen' branch.
