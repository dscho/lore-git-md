This is a memory leak fix for the Linux fsmonitor daemon implementation, part of the larger cross-platform filesystem monitoring series. The patch addresses a specific issue where a string hash table (`shown`) would leak when the daemon sent a trivial response to a client, as the cleanup code was only being called for non-trivial responses.

The fix is straightforward: initialize the hash table pointer to NULL and move its cleanup to a shared cleanup section that runs in all code paths. This ensures proper resource management regardless of which branch the execution takes.
