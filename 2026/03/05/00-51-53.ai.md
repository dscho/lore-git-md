This is a refactoring patch in the fsmonitor daemon series, specifically part of the cross-platform filesystem monitoring implementation. The patch renames `fsm-ipc-darwin.c` to `fsm-ipc-unix.c` to reflect that the IPC path logic is shared across Unix platforms, not just macOS. It introduces a new `FSMONITOR_OS_SETTINGS` build variable to distinguish between platform-specific files (listen, health, path-utils) and shared Unix files (ipc, settings).

The changes affect multiple build systems (Make, CMake, meson) to properly handle the new variable and file organization. The patch maintains all existing functionality while making the codebase more maintainable for the upcoming Linux fsmonitor support. This is a straightforward mechanical change that follows the architectural direction established earlier in the thread, with no behavior changes beyond the build system reorganization.

Key technical points:
- Splits build configuration between `FSMONITOR_DAEMON_BACKEND` (platform-specific) and `FSMONITOR_OS_SETTINGS` (shared)
- Updates all three build systems (Make, CMake, meson) consistently
- Keeps the same IPC implementation but moves it to a more appropriately named file
- Maintains compatibility with existing macOS and Windows implementations

The patch is well-contained and follows the established pattern of the series, with proper attribution to previous contributors via "Based-on-patch-by" lines. It's a typical mid-series refactoring that prepares for subsequent platform support additions.
