Final cleanup patch in the fsmonitor daemon series. This is the last patch in a 12-part series adding Linux inotify support to Git's filesystem monitoring, bringing it to parity with the existing Windows and macOS implementations.

The patch replaces a khash-based string set with the newer strset data structure for deduplicating pathnames in the fsmonitor daemon's client response handling. This was suggested by Patrick Steinhardt as a cleanup to use Git's more modern string set API rather than the lower-level khash implementation. The change is straightforward - the strset provides a cleaner interface for the same string deduplication functionality while avoiding unnecessary string copies since the paths are already interned strings from the batch data.

This completes the technical implementation work for the Linux fsmonitor support. The series has gone through 11 iterations addressing all feedback, with this final patch being a minor code quality improvement. The implementation is now stable with comprehensive test coverage, proper process isolation, cross-platform compatibility (including Windows pthread emulation), and handling of real-world filesystem edge cases.
