This is a refactoring patch that makes oidmap entry cleanup more explicit by introducing a new `oidmap_clear_with_free()` API. It's part of a narrowed-down series that has already received maintainer approval for the rev-list and odb conversions.

The patch replaces the existing `oidmap_clear()` implementation (which relied on internal hashmap layout assumptions) with an explicit iteration approach. The new API takes a callback function to handle entry cleanup, while maintaining backward compatibility through a wrapper that preserves the old `free_entries` boolean parameter.

Key changes include:
- New `oidmap_free_fn` typedef for cleanup callbacks
- `oidmap_clear_with_free()` that iterates through entries and invokes the callback
- Two new unit tests verifying callback behavior (with and without a free function)
- Keeps the existing `oidmap_clear()` as a wrapper for compatibility

The patch has already been through several iterations with maintainer feedback incorporated, including a rename of the callback function pattern. Junio Hamano and Patrick Steinhardt have approved this approach, and the series appears ready for merging. The changes are focused and well-tested, with clear ownership semantics for memory management.
