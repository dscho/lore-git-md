This is the first patch in Jeff King's series fixing memory leaks in pack index mmap handling during clone operations. The patch refactors `check_connected()` to delay opening a pack index until it's actually needed, which simplifies cleanup paths and prevents a potential resource leak.

The change moves the pack opening logic after the `start_command()` call for `git rev-list`, since we only need the pack when checking if objects are already present. This ensures we don't have to clean up the pack if we exit early (like when checking promisor remotes). The patch maintains all existing functionality while making the code more robust against leaks.

Jeff notes in the commit message that there might be further optimizations possible (like skipping `rev-list` entirely for self-contained packs), but those out of scope for this leak-focused series. The change touches core connectivity checking code but is relatively contained, affecting only `connected.c`.

This is a well-motivated cleanup that addresses a real issue (leaks under ASan) while improving the code structure. The patch follows Git's style guidelines and includes thoughtful analysis of alternative approaches in the commit message. As the first in a series, it sets up the foundation for the more direct leak fixes that follow.
