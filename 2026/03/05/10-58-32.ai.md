This is a review comment on patch 8/17 of Patrick Steinhardt's ODB abstraction series, focusing on the `close()` callback interface. Karthik Nayak provides feedback on the documentation wording around resource reopening expectations.

The patch introduces a pluggable `close()` operation for ODB sources, allowing backends to manage their own resource cleanup while keeping the source structure intact for potential reuse. Karthik notes an inconsistency between the header comment (which says resources "may" need reopening) and the function documentation (which states they "need" reopening). He prefers the more explicit wording in the function documentation, as it makes the contract clearer while still allowing no-op implementations for backends that don't need reopening.

This is a minor documentation nit in an otherwise straightforward mechanical conversion - part of the systematic callback-ization of ODB operations that forms the core of the abstraction effort. The exchange demonstrates the careful attention to interface contracts that has characterized reviews throughout this series, with Karthik ensuring the documentation accurately reflects the expected behavior for both implementers and consumers of the API.
