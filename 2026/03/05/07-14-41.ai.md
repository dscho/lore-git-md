This is a feature request for `git worktree` to support sorting worktrees by creation time. The author, Norbert Kiesel, describes a practical use case where they manage repositories with over 20 worktrees and occasionally need to identify recently created ones. They propose adding a `--created` flag to `git worktree list` to sort output by creation timestamp rather than the current unspecified order.

The request is straightforward and well-motivated by a real workflow pain point. The author offers to implement the feature themselves if the idea is accepted. This would be a relatively small but useful quality-of-life improvement for users who maintain multiple worktrees. The change would likely touch the `builtin/worktree.c` file and possibly the worktree API to expose creation timestamps that are already tracked internally.

The proposal doesn't mention whether creation timestamps are currently exposed anywhere in Git's plumbing, so implementation might require plumbing new data through the worktree subsystem. The change would be backward compatible since it just adds a new sorting option without modifying default behavior.
