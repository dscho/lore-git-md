This is the final version of a feature series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The series has undergone extensive review and testing over multiple iterations.

The implementation provides a complete fsmonitor daemon for Linux that watches filesystem changes via inotify, with careful handling of directory renames, remote filesystems, and edge cases like overlayfs limitations. Key technical aspects include:

- Uses inotify with recursive directory monitoring and cookie-based rename tracking
- Detects and handles remote filesystems appropriately
- Includes comprehensive test coverage with special handling for problematic filesystems
- Shares IPC and settings logic between macOS and Linux via unified "unix" implementations
- Adds process management improvements including file descriptor cleanup and proper daemon detachment

The series also fixes memory leaks in the fsmonitor code and introduces a generalized pre-exec callback mechanism in the run-command infrastructure, which is used to clean up inherited file descriptors in spawned processes.

This version incorporates all review feedback, including Junio Hamano's suggestion to generalize the file descriptor cleanup mechanism. The implementation is now production-ready across all major platforms, with Paul Tarjan reporting stability in large deployments. The series is fully baked and ready for integration.
