This is part 4/17 of Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem to enable pluggable storage backends. The patch moves path reparenting logic - which updates relative paths when the working directory changes - from the ODB layer into the specific subsystems that need it (the "files" backend and temporary object directories).

The change makes the code more modular by keeping path handling logic with the implementations that actually use paths, rather than having it centralized in the ODB layer. This is important because future ODB backends may not use filesystem paths at all. The patch maintains all existing behavior while better isolating implementation details.

Review discussion with Justin Tobler noted that the description of working directory changes could be clearer, and raised questions about path storage design. Patrick clarified that the current path storage approach is temporary and will be removed in future work. The patch was accepted with these minor documentation clarifications.

This continues the systematic conversion of ODB operations to callback-based dispatch while maintaining existing behavior, preparing for future backend implementations. The change is mechanical but important for the architectural goal of making the ODB subsystem properly abstracted.
