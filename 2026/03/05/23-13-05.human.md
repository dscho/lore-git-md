This is the fourth and final patch in Jeff King's series addressing memory leaks in mmap handling during Git operations. The patch enables the `NO_MMAP` compatibility layer when building with leak sanitizer (LSan) to help detect mmap-related memory issues.

The key insight is that LSan normally only detects heap allocations from `malloc()`, but by forcing mmap operations to use heap buffers (via `NO_MMAP`), we can extend leak detection to cover mmap'd resources as well. While this makes the build slightly less performant (since it reads entire files rather than memory-mapping them), the tradeoff is worthwhile for leak detection purposes.

This patch completes the series by ensuring future leak checking will catch similar mmap-related issues. It follows three earlier patches that fixed specific leaks in clone and fsck operations. The change is minimal - just a one-line addition to the Makefile to set `NO_MMAP` when LSan is enabled.

The series as a whole demonstrates Jeff King's characteristic attention to resource management details, with each patch carefully addressing leaks in different scenarios while maintaining clean code structure. This final patch provides infrastructure to help prevent similar issues from slipping through in the future.
