This is the final patch in the fsmonitor Linux support series, converting the pathname deduplication in `do_handle_client()` from using a khash to a strset. The change follows Patrick Steinhardt's suggestion to use the higher-level strset interface rather than the lower-level khash implementation.

The patch is a mechanical conversion that:
1. Replaces khash initialization with strset initialization (using `strset_init_with_options` with `strdup_strings=0` since the paths are already interned strings)
2. Changes the duplicate detection from `kh_get_str` to `strset_add`
3. Removes the explicit hash insertion since strset handles it internally
4. Updates the cleanup to use `strset_clear` instead of `kh_destroy_str`

This change doesn't affect functionality but makes the code more readable by using Git's standard string set abstraction rather than direct khash operations. The patch is well-contained and follows the established pattern of the series - it's a final cleanup that improves code quality without changing behavior.

As the last patch of a long series that has already addressed all review feedback, this appears ready for integration. The change is straightforward and unlikely to be controversial, serving as a nice capstone to the fsmonitor Linux implementation work.
