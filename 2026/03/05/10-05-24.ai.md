This is a refactoring patch series introducing type-safe cleanup for oidmap structures. The series has been narrowed down to just two patches after maintainer feedback, focusing on converting rev-list and odb usage to the new `oidmap_clear_with_free()` API.

The key technical change introduces a callback-based cleanup mechanism for oidmap entries, replacing the previous boolean flag approach that implicitly assumed plain `free()`. The new API uses `container_of` to properly handle embedded structures. The series shows this in action by converting the missing_objects map in rev-list to use an explicit free callback.

The thread context shows this is the third iteration of the series that originally had five patches. Maintainers have agreed to drop the list-objects-filter and sequencer conversions from scope, leaving just these two focused changes. Junio Hamano and Patrick Steinhardt have both approved the current approach, with the only remaining change being a function name adjustment requested by Patrick (from `free_missing_objects_entry` to `missing_objects_map_entry_free`).

The patch touches core oidmap infrastructure (adding the new API) and one builtin command (rev-list). The changes are mechanical but improve type safety and make memory ownership more explicit. The test coverage includes new unit tests for the oidmap API. This appears ready for merging once the final naming tweak is incorporated.
