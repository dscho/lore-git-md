This is the final version of a feature series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The series has undergone extensive review and testing over multiple iterations.

The implementation provides a robust Linux fsmonitor daemon that uses inotify with recursive directory watching, handling edge cases like directory renames through IN_MOVED_FROM/TO event cookies. It includes comprehensive filesystem detection to avoid monitoring remote filesystems (NFS/SMB) and falls back gracefully when running on overlayfs with incomplete inotify support. The daemon uses efficient bidirectional watch descriptor mappings and implements two-phase event synchronization with timeouts.

Key technical improvements in this version include:
- Replacing a close_fd_above_stderr flag with a more general pre_exec_cb callback mechanism in struct child_process
- Providing close_fd_above_stderr() as a ready-made callback function
- Finalizing the build system configuration across Make, Meson and CMake
- Refining filesystem detection logic
- Adding comprehensive test coverage including new smoke and stress tests
- Implementing proper Unix process detachment via setsid()
- Handling overlayfs limitations through detection and fallback behavior

The series also fixes memory leaks in the platform-independent daemon code and deduplicates IPC and settings logic shared between macOS and Linux. All review feedback has been addressed, including Junio Hamano's suggestion for a more general fork/exec callback mechanism. The implementation is now production-ready across all major platforms with no remaining open questions.
