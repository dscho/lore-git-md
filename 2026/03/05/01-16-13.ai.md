This is part 7 of a 12-part series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS implementations. The series is now in its 10th iteration and appears production-ready, with all technical concerns addressed.

The patch implements the core inotify listener for Linux, handling directory watches, event processing, and rename tracking. Key technical aspects include:
- Uses inotify_init1(O_NONBLOCK) with a poll loop and 50ms timeout to avoid queue overflows
- Maintains bidirectional watch descriptor <-> path mappings using hashmap
- Tracks directory renames via inotify's cookie mechanism with timeout-based stale detection
- Recursively watches directories while handling create/delete/rename events
- Detects remote filesystems via statfs() and falls back to /proc/mounts scanning
- Includes comprehensive error handling and shutdown logic

The implementation avoids fanotify due to its privilege requirements, instead using the more widely-available inotify API. The patch also notes Linux-specific caveats around inotify watch limits and provides documentation on adjusting them.

This appears to be a well-constructed implementation with thorough error handling, detailed tracing, and careful attention to edge cases like stale renames and filesystem unmounts. The code follows Git's established patterns for fsmonitor backends while adding Linux-specific optimizations.
