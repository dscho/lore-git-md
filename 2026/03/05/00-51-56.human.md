This is part of the cross-platform filesystem monitoring (fsmonitor) series, specifically addressing process management improvements. The patch introduces a pre-exec callback mechanism for child processes, allowing cleanup operations to run between fork and exec.

Paul Tarjan adds a `pre_exec_cb` function pointer to `struct child_process` that gets called in the child process context before execution. The primary use case shown is closing inherited file descriptors (FDs) above stderr (FD 2), which helps prevent FD leaks into child processes. The patch includes a ready-made `close_fd_above_stderr()` callback that handles this common case, respecting system FD limits and preserving the child-notifier pipe.

This change emerged from the fsmonitor work where proper FD handling was needed, but the implementation is general-purpose and could benefit other parts of Git. The callback mechanism follows Junio Hamano's suggestion for a more flexible approach than hardcoding specific cleanup logic. The patch is well-contained, touching only run-command.c/h, and includes clear documentation of the new field and utility function.

As part of the now-complete fsmonitor series (which Junio has in 'seen'), this represents one of the final architectural pieces needed for robust cross-platform process management. The implementation looks solid, with proper handling of edge cases like system FD limits.
