This is a bugfix patch in the fsmonitor series, addressing a potential hang condition when stopping the daemon. It's part of the larger cross-platform filesystem monitoring implementation that has been in Junio's 'seen' branch.

The patch adds a 30-second timeout to the `fsmonitor--daemon stop` command's polling loop. Previously, if the daemon failed to shut down (e.g. became stuck), the stop command would block indefinitely. The new version will return an error after 30 seconds, making the behavior more robust in edge cases.

Key technical details:
- Uses a 30,000ms (30 second) timeout threshold
- Tracks elapsed time in milliseconds
- Maintains the existing 50ms polling interval
- Preserves the trace2 instrumentation for monitoring
- Returns a user-friendly error message on timeout

This is the 10th patch in the 12-part v9 iteration of the fsmonitor series. The thread context shows the overall implementation is stable and production-ready, with this being one of the final refinements. The change is straightforward and unlikely to be controversial, addressing a clear edge case in the shutdown sequence.
