This is a post-merge follow-up discussion about test portability in the recently merged `git apply -p` argument parsing fix. The thread has already established that the core bug (unsafe `atoi()` usage) was properly fixed with `strtol_i()` validation, but now reveals a Windows-specific test failure due to CRLF line endings in the external test patch file.

Jeff King identified that Windows' automatic CRLF conversion during checkout causes `apply.c` to misparse filename headers when removing path components, because the header parsing doesn't properly handle CRLF line endings. While the underlying issue in `git_header_name()` could be fixed to recognize CRLFs, Jeff suggests the simpler solution of inlining the test patch data directly in `t4120-apply-popt.sh` using heredocs, which avoids the CRLF problem entirely since test scripts are checked out with LF line endings.

Junio Hamano's response acknowledges the Windows quirk with resigned humor ("Joy of working with Windows. Sigh...") and implicitly accepts Jeff's proposed solution. The exchange demonstrates Git's post-merge refinement process, where even after a patch is merged, platform-specific issues uncovered by wider testing can prompt follow-up improvements from trusted contributors. The underlying CRLF parsing issue in `apply.c` remains known but is deemed separable from this immediate test fix.
