Phillip Wood has completed a 3-patch series eliminating `the_repository` usage from worktree subsystem functions, part of the broader effort to remove this global variable. The series has now received Junio C Hamano's approval and will be merged.

The changes follow a clear progression: first removing `the_repository` from internal worktree logic, then simplifying interfaces based on that change, and finally hardening the API by eliminating NULL fallbacks. Key changes include modifying `is_current_worktree()` to use the worktree's own repository, streamlining the invalid HEAD warning in `can_use_local_refs()`, and making NULL worktree handling in `get_worktree_git_dir()` trigger a BUG() rather than falling back to `the_repository`.

Phillip addressed all of Junio's feedback from earlier versions, fixing minor formatting issues and updating documentation to match the new behavior. Junio noted that explicitly documenting NULL rejection would be unnecessary since the function's contract doesn't promise to handle NULL inputs - the BUG() makes this clear through enforcement. The series maintains existing behavior while advancing the `the_repository` removal goal, with test coverage confirming functionality remains intact. This work builds on Phillip's prior worktree refactoring and represents another step in the multi-year effort to eliminate implicit repository dependencies.
