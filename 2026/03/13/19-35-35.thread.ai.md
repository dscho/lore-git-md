Thread summary:

This thread introduces a proposed extension to Git's reference-transaction hook mechanism, adding a new "preparing" phase that fires before reference locks are acquired. The patch comes from Eric Ju (with help from Patrick Steinhardt and Justin Tobler) and targets distributed Git storage systems like GitLab's Gitaly/Praefect, allowing them to coordinate concurrent writes earlier in the transaction flow. The core change modifies `refs.c` to add the new phase while maintaining existing "prepared", "committed", and "aborted" phases. Documentation updates in `githooks.adoc` explain the new phase's behavior (noting it doesn't resolve symbolic refs), with test coverage added in `t1416` and `t5510` showing the new phase in action.

The implementation allows hooks to validate or reject transactions before any locks are taken, addressing a limitation where the existing "prepared" phase only fires after locking. The patch acknowledges this isn't strictly backwards compatible since existing hooks might error on unknown phases, but argues this is acceptable given the hook's documented nature as exposing implementation details. The author considered but rejected introducing a v2 hook interface as too heavyweight. The changes are focused and well-motivated, with clear documentation and test updates. The implementation appears clean and the use case (coordinating distributed reference updates) is well-justified. This seems likely to be uncontroversial, though reviewers may want to confirm the backwards compatibility stance holds up under scrutiny. No reviews or responses have been posted yet beyond the initial patch submission.
