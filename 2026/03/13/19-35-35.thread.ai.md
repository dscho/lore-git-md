This thread introduces Eric Ju's patch (with contributions from Patrick Steinhardt and Justin Tobler) adding a "preparing" phase to Git's reference-transaction hook mechanism, enabling distributed Git storage systems like GitLab's Gitaly/Praefect to coordinate concurrent writes earlier in the transaction flow. The implementation modifies `refs.c` to add this new phase while maintaining existing "prepared", "committed", and "aborted" phases, with documentation updates in `githooks.adoc` and test coverage in `t1416` and `t5510`.

Git maintainer Junio C Hamano has reviewed and approved the patch for inclusion, providing minor editorial feedback about standardizing the author's email address (suggesting using GitLab address for company-sponsored work) and adjusting the commit subject line to follow "refs: ..." convention. Junio praised the clear commit message and documentation while lightly questioning how concurrent transactions would be "rearranged" without pressing the technical point since the implementation appears correct.

Following Junio's approval, Justin Tobler raised an internationalization consideration regarding whether the new "preparing" and "prepared" phase names should be marked for translation in error messages. Junio clarified these are fixed API tokens that hooks must match exactly and should not be translated, while suggesting improved error message wording to be more precise - indicating the reference-transaction hook rejected updates during its preparing phase rather than saying "aborted by preparing hook". This maintains technical accuracy while making errors more informative.

The patch remains queued for integration (seen -> next -> master) with this internationalization question now resolved. The changes address a real limitation in distributed reference coordination while maintaining clean backwards compatibility, with both the maintainer's approval and technical review confirming the approach meets Git's standards. The discussion demonstrates Git's thorough review process where post-approval feedback leads to meaningful improvements in error messaging while keeping the stable hook API contract intact.
