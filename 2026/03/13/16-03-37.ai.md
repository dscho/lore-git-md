This is a coding style patch (refactoring) that prepares for a subsequent feature addition to `git name-rev`. It's the first of two patches in Kristoffer Haugsbakk's series introducing a `--format` option to `git name-rev`.

The patch makes purely mechanical changes to `builtin/name-rev.c` to ensure consistent brace usage in conditional blocks, bringing the code into compliance with Git's CodingGuidelines. The changes wrap single-line blocks in braces when they are part of a multi-arm conditional, making the style uniform throughout the file. Specifically, it modifies two functions (`get_rev_name` and `name_rev_line`) to add braces around previously unbraced single-line blocks in `if-else statements.

This is a straightforward cleanup with no behavior change, clearly motivated by the project's style rules. The patch serves as groundwork for the more substantial change in patch 2/2, which will add the new formatting capability. The separation of style fixes from functional changes follows Git project best practices for patch submission.
