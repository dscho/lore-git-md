Kristoffer Haugsbakk's experimental `git format-rev` command has gone through several iterations, evolving from an extension of `git name-rev` to a standalone command with shared formatting infrastructure. The v3 series is now functionally complete with comprehensive test coverage and documentation, though marked as experimental to allow for future refinement.

The command offers two input modes (line-oriented revision processing and freeform text parsing) while supporting standard pretty formats and tag peeling. After addressing an initial compiler warning about an uninitialized variable, a reviewer has now caught another small but important improvement: the error message for failed tag dereferencing will now show the actual object name rather than potentially unrelated command-line arguments. This doesn't change the core functionality but makes debugging easier when edge cases occur.

The series demonstrates Git's iterative development process - even after thorough testing and CI validation, careful review continues to surface opportunities for polish. While no Reviewed-by tags have been added yet (likely due to the experimental status), the implementation appears solid with all planned features working as intended. The command fills a niche for workflows needing efficient commit formatting without full graph traversal.
