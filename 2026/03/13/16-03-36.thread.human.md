Kristoffer Haugsbakk has completed a v3 patch series introducing a new experimental `git format-rev` command, which provides flexible formatting of revision information. The command fills a gap in Git's tooling by offering two specialized input modes: line-oriented revision processing (`--stdin-mode=revs`) and freeform text parsing (`--stdin-mode=text`), building on infrastructure shared with `git name-rev`.

The series evolved through careful iteration, starting as an extension to `git name-rev` before becoming a standalone command. The final patch adds comprehensive testing and documentation, demonstrating practical use cases like processing `git last-modified` output. While marked EXPERIMENTAL to allow for interface refinement, the implementation appears solid with thorough test coverage of edge cases and support for standard pretty formats and notes display.

This represents a thoughtful addition to Git's revision formatting capabilities, particularly useful for scripting workflows that need to process commit references without the overhead of full commit graph traversal. The series shows Git's iterative development process in action, with architectural refinements based on review feedback while preserving the original use cases.
