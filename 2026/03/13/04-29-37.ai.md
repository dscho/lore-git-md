This is the final approval and merge of the v6 patch series adding `sign-if-invalid` mode to `git fast-import`. Junio C Hamano confirms all review feedback has been addressed and will merge the series. The three patches in this version fixed a test branch reference, clarified warning messages about signature replacement (not creation), and added parentheses for operation order clarity in a conditional statement. 

This concludes the multi-iteration effort that began with Christian Couder and Justin Tobler's earlier work on signature handling in fast-import. The series establishes reusable signing logic through a consolidated `sign_buffer()` API while maintaining clean separation between signature creation and re-signing concerns. The implementation includes comprehensive test coverage for OpenPGP, X.509, and SSH signatures, though it currently limits re-signing to previously-signed-but-invalid commits.

The merged changes enable `git fast-import --signed-commits=sign-if-invalid[=<keyid>]` as a counterpart to the existing `strip-if-invalid` mode, with syntax matching `git commit --gpg-sign`. Future work could extend this to support signing unsigned objects or handling tags, but those remain separate efforts. The series demonstrates Git's iterative development model where features mature through careful review and incremental improvement.
