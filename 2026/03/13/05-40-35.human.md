This is a feature addition to the `git replay` command, introducing a `--revert` mode for server-side history rewriting. The patch is part of a v4 series that has undergone extensive review from key contributors including Phillip Wood, Patrick Steinhardt, and Junio Hamano.

The change enables `git replay` to reverse commits directly on bare repositories, which is particularly useful for GitLab's Gitaly service where server-side operations on bare repos are common. The implementation follows the same approach as `sequencer.c`, treating reverts as merges with swapped arguments to effectively reverse the diff direction.

Key technical aspects include:
- Reverts are processed newest-first (matching `git revert` behavior) to reduce conflicts
- Commit messages follow standard revert conventions with "Revert" prefix and hash references
- Empty revert commits are dropped by default (aligning with `git cherry-pick` behavior)
- The implementation shares logic with the sequencer through a consolidated message formatting helper

The patch appears well-considered with comprehensive test coverage, building on established patterns in the codebase. It addresses all substantive feedback from prior rounds of review, making it likely ready for merging. The higher-level interface design discussion (flags vs subcommands) continues but is being deferred to avoid scope creep in this series.
