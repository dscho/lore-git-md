Kristoffer Haugsbakk's patch series (v1) introduces a `--format` option to `git name-rev` to enable pretty-printed commit information similar to `git log --format`. The series consists of two patches:

1. A preparatory coding style fix (patch 1/2) that standardizes brace usage in `builtin/name-rev.c` for single-line blocks in multi-arm conditionals (`get_rev_name` and `name_rev_line` functions), bringing the code into compliance with Git's CodingGuidelines without functional changes.

2. The feature implementation (patch 2/2) adds format specifier parsing and output generation using `pretty_print_commit`, modifying `builtin/name-rev.c` to:
   - Add a `pretty_format` struct for formatting context
   - Update `get_rev_name`, `show_name`, and `name_rev_line` to handle formatted output
   - Support display notes (with potential for future `--[no-]notes` flags)
   - Include comprehensive tests in `t6120-describe.sh` covering:
     * Basic format specifiers
     * Stdin annotation with mixed text
     * Note display
     * Tree object formatting in running text

The implementation addresses limitations of existing commands (`log`, `show`, `rev-list`, `cat-file`) for on-demand commit formatting while maintaining backward compatibility. The commit messages document considered approaches and note minor output differences from `git log`. Changes are contained to `builtin/name-rev.c` with thorough test coverage, though no reviews or feedback have been received yet on this initial submission.
