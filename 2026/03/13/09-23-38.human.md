This is version 3 of a feature patch series introducing conditional stashing behavior to `git checkout` and `git switch`, now unifying the functionality with the existing `-m` flag as suggested by maintainer Junio C Hamano. The patch completely rewrites the `-while-switching` behavior to use autostash rather than direct merging, while maintaining backward compatibility.

The key changes in this version:
- The `-m` flag now triggers autostash behavior instead of performing a three-way merge
- Conflict detection is done via a dry-run merge to determine when stashing is needed
- Documentation is updated to reflect the new behavior and conflict resolution flow
- Test coverage is expanded to verify the unified behavior across various scenarios

The implementation builds on Git's existing autostash infrastructure from the sequencer. When conflicts are detected during the dry-run, changes are stashed before the switch and reapplied afterward. If conflicts persist during reapplication, the stash is preserved for manual resolution.

The patch touches multiple components including checkout logic, documentation, and test infrastructure. The test changes are particularly thorough, covering cases like:
- Non-conflicting changes that don't require stashing
- Mixed staged/unstaged changes
- Various conflict styles (merge, diff3, zdiff3)
- Config-driven behavior via merge.conflictStyle
- Backward compatibility with existing `-while-switching` workflows

This represents a significant behavioral change for the `-m` flag, but the careful test coverage and documentation updates suggest the author has thoughtfully considered the transition path. The implementation appears well-crafted to maintain compatibility while providing a more consistent user experience with Git's other autostash-enabled commands.
