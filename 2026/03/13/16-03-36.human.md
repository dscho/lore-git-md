This is a feature patch series introducing a new `--format` option to `git name-rev`. The main change comes in the second patch, which allows `name-rev` to output revisions using the same pretty-formatting options as `git log`, rather than just showing symbolic names.

Kristoffer Haugsbakk has clearly put thought into the implementation, trying three different approaches before settling on using `pretty_print_commit`. The commit message explains the tradeoffs considered, particularly around handling notes and output formatting differences compared to `git log`. The patch includes tests covering the new functionality.

The first patch is a minor coding style fix (adding braces to conditional blocks) that appears unrelated to the main feature - likely included just because it touched the same file. The implementation looks thorough, with good test coverage showing various format options work as expected. This could be a useful addition for scripting scenarios where you want name-rev's revision naming combined with log-style formatting.

The series is cleanly structured and well-documented, making it easy to review. The only potential area for discussion might be whether to add explicit `--[no-]notes` options rather than relying on environment variables, as hinted in the cover letter.
