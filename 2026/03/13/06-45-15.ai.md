This is patch 4/10 in Patrick Steinhardt's v4 series optimizing write contention in `git-upload-pack`. The series has already been approved by Junio for merging after addressing feedback from Johannes Sixt and others.

The patch specifically targets lock contention observed in high-concurrency server environments where hundreds of `upload-pack` processes contend around kernel-level locks during packfile streaming. The root cause was traced to excessive `pipe_write()` calls, with Git making one write per read (or two writes when using sidebands) from `pack-objects`.

The solution introduces buffering threshold in `upload-pack.c` - only flushing when the buffer is at least 2/3 full. This reduces write syscalls from ~400k to ~130k when cloning Linux, with measurements showing diminishing returns from trying to fill the buffer completely. The change is careful to maintain existing behavior for pack-objects hooks via the `uploadpack.packObjectsHook` mechanism.

The implementation builds on existing buffering infrastructure in `upload-pack`, adding just 7 lines to implement the 2/3 fill threshold while preserving all edge case handling. Performance impact is validated through production measurements showing the change resolves the kernel lock contention while maintaining throughput. The patch includes a helpful-by from Matt Smiley at GitLab where the production issue was originally observed.
