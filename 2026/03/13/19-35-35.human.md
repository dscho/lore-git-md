This is a feature proposal to extend the reference-transaction hook with a new "preparing" phase. The patch comes from Eric Ju, who works on GitLab's distributed storage layer (Gitaly/Praefect).

The change adds a hook phase that fires *before* Git acquires reference locks, allowing distributed systems to coordinate transactions across nodes before any locks are taken. Currently, the earliest available phase ("prepared") only runs after locks are already held, which is too late for systems that need to serialize writes across replicas.

The implementation adds the new phase while maintaining the existing hook interface, though the author notes this technically breaks backward compatibility for hooks that don't expect unknown phase strings. They considered but rejected introducing a v2 hook interface as unnecessarily heavy. The patch includes documentation updates and test coverage.

This appears to be a well-motivated change targeting a real pain point in distributed Git storage systems. The implementation looks clean, touching only the expected areas (hook documentation, refs.c internals, and relevant tests). The commit message thoroughly explains the rationale and compatibility considerations. Given GitLab's production use case and the careful handling of backward compatibility, this seems likely to be accepted after review.
