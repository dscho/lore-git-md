This is patch 6/10 in Patrick Steinhardt's performance optimization series, which introduces `writev()` wrappers as part of the effort to reduce lock contention in `git-upload-pack`. The patch adds two key functions to Git's I/O infrastructure: `writev_in_full()` (a robust wrapper for partial writes) and `writev_or_die()` (a fatal-error variant), following the pattern of existing `write_in_full()` and `write_or_die()` functions.

The implementation handles edge cases including EINTR/EAGAIN retries, ENOSPC detection, and partial write adjustments to the iovec array. The wrappers will be used by subsequent patches in the series to batch writes across multiple subsystems (`upload-pack`, `pack-objects`, `sideband`, etc.). Johannes Sixt has already validated the platform-specific behavior, particularly around zero-byte write handling and Windows compatibility.

This foundational change enables the performance improvements demonstrated in the series (reducing write syscalls from ~400k to ~44k when cloning Linux) while maintaining POSIX compliance and cross-platform support. The patch follows Git's established patterns for I/O utilities and has been reviewed as part of the now-finalized v4 series.
