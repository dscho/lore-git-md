Thread identity: Bug report about `git describe --dirty` behavior when used with `--git-dir` outside repository, reported by Thomas Braun.

Core problem: `git describe --dirty` incorrectly reports repository as dirty when run from outside repository with `--git-dir` specified but without `--work-tree`. The command fails to properly establish working tree context needed for dirty state detection.

Current status: Bug exists in current code. Workaround is to specify both `--git-dir` and `--work-tree`. Suspected related to commit 2ed5c8e174 ("describe: setup working tree for --dirty", 2019-02-03).

Key technical details: Issue involves interaction between repository discovery (handling of `--git-dir`), working tree setup, and dirty state detection in `builtin/describe.c`. The command needs working tree access to check for modifications but isn't properly initializing this when only given `--git-dir`.

Open questions: Where exactly in code the working tree setup fails when only `--git-dir` is provided. Whether fix should modify describe's working tree handling or repository discovery behavior.
