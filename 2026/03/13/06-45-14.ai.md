This is the third patch in Patrick Steinhardt's v4 performance optimization series for `git-upload-pack` lock contention. The patch implements a specific optimization for keepalive handling when buffering data.

The change modifies `upload-pack.c` to prioritize flushing buffered data over sending empty keepalive packets when the keepalive timeout is reached. The patch checks if there's pending data in the output state buffer (and if the packfile transmission has started), and if so, flushes that data instead of sending a minimal keepalive packet. This avoids unnecessary network roundtrips while maintaining the same keepalive signaling effect, since the data transmission itself serves to indicate the connection is alive.

The optimization was suggested by Jeff King and builds on the buffering infrastructure introduced earlier in the series. The implementation carefully preserves the packet framing by maintaining the buffer state correctly after partial flushes. While the author notes this won't be a major performance win in most cases (since keepalives typically occur before pack data starts flowing), it's a logical optimization given the new buffering behavior.

This patch represents a final refinement to the series' keepalive handling, having been reviewed and approved along with the rest of the v4 iteration. The change is well-contained and maintains all existing protocol semantics while opportunistically reducing network traffic when possible.
