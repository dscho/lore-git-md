This is patch 8/10 in Patrick Steinhardt's performance optimization series, which has already been approved for merging. The patch introduces a new `hashfd_ext()` function in the csum-file subsystem as part of the broader effort to reduce write syscalls through `writev()`-based buffering.

The change replaces the internal `hashfd_internal()` function with a more flexible `hashfd_ext()` that takes an options structure, allowing callers to specify both progress reporting and buffer length in a single call. The existing `hashfd()` and `hashfd_throughput()` functions are updated to use this new interface while maintaining their current behavior (128KB buffer for regular hashing, 8KB for throughput measurement).

This is a straightforward refactoring that provides the foundation for the next patch in the series. The implementation is clean and maintains all existing functionality while making the interface more extensible. Since the series has already been reviewed and approved, this patch represents the final form of this particular change.
