[Cross-project coordination] Proposal to extend responsive web design from GitGitGadget to kernel.org. Johannes Schindelin introduced contributor Rito Rhymes, who implemented mobile-friendly design for GitGitGadget and created a proof-of-concept responsive version of kernel.org (demo at kernel.ritovision.com). Rito's responsive design patches for gitweb have been merged into Git's master branch. The kernel.org effort transitioned from private discussions with Konstantin Ryabitsev (Linux Foundation infrastructure lead) to public coordination on this thread (message ID DH2ADSKXNCXG.2DM7T0NF5NH59@ritovision.com) due to kernel.org lacking its own public mailing list, Git community stake in kernel.org's usability as host of Git mailing list archives, and maintaining context in one thread.

Rito has now submitted a 6-patch series implementing responsive design changes for kernel.org, beginning with patch 1 which adds a viewport meta tag to kernel.org's base template to establish proper mobile rendering (width=device-width, initial-scale=1.0). This foundational change fixes the "tiny text" problem on mobile devices by enabling proper vertical scrolling, serving as the baseline for subsequent CSS adjustments in patches 2-6. The implementation is clean (single line addition to base template) and low-risk as it doesn't modify existing layout logic. The series continues with planned CSS improvements for text overlap/overflow (patches 2-3) and table/footer layout (patches 4-6), following Rito's demonstrated approach of targeted, validated incremental improvements from GitGitGadget and gitweb work. A follow-up patch for mobile navigation header remains pending initial series acceptance. The Git mailing list remains CC'd for continuity, though this is fundamentally a kernel.org infrastructure change. No technical objections have been raised yet - current status awaits kernel.org's review of submitted patches and discussion of proposed mobile navigation changes. The series demonstrates Rito's responsive design approach previously validated through GitGitGadget and gitweb contributions.
