This is a clarification from the Git maintainer about the reported `git describe --dirty` behavior when used with `--git-dir` outside the repository. Junio C Hamano explains this is not actually a bug but expected behavior - when only `--git-dir` is specified, Git assumes the current directory is the working tree root, which leads to incorrect dirty state detection when run from outside the repository.

The maintainer confirms the workaround (adding `--work-tree`) is the correct solution and suggests the issue lies in understanding Git's working tree handling rather than a code defect. He proposes that if the documentation about `--git-dir` and `--work-tree` behavior is unclear, that would be a valid area for improvement.

This response effectively closes the bug report as "working as intended" while leaving open the possibility of documentation enhancements. The documentation for repository discovery and working tree handling in Git's man pages could potentially be made clearer about this interaction between `--git-dir`, working tree context, and commands that check working tree state like `describe --dirty`.
