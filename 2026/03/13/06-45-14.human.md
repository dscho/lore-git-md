This is the third patch in Patrick Steinhardt's v4 performance optimization series for `git-upload-pack`, which has been approved for merging. The patch focuses on optimizing keepalive behavior during high-concurrency operations.

The change makes `git-upload-pack` prioritize flushing buffered data over sending keepalive packets when both are possible. When the keepalive timeout triggers, the code has buffered data ready to send, it will now send that data instead of an empty keepalive packet. This is a small but sensible optimization - while the impact will be minor (as most keepalives occur before pack data starts), it's easy to implement and maintains better protocol efficiency.

The patch includes careful handling of the buffer state to ensure proper packet boundaries are maintained. Jeff King suggested this optimization, and Johannes Sixt has already validated the edge case handling in the broader series. This is one of several performance improvements in the series that collectively reduce write syscalls during clones by nearly 90%.
