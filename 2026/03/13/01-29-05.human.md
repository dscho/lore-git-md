This is a follow-up discussion about test portability in the recently merged `git apply -p` argument parsing fix. Jeff King provides additional technical details about the Windows test failures caused by CRLF line endings in test patch files.

The core issue is that Windows' automatic CRLF conversion affects test patch files, causing `apply.c` to misparse filenames when removing path components. Jeff demonstrates two potential solutions: either inline the test patch data directly in the script (his preferred approach, since test scripts themselves use LF line endings) or add a `.gitattributes` file to force LF handling for test patches.

The email includes a handy snippet to reproduce the CRLF parsing issue on Linux, showing how malformed headers can lead to NULL `patch->def_name`. While this deeper parsing issue could be fixed separately, Jeff suggests focusing first on the immediate test portability problem through the simpler inlining approach.
