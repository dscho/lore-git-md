This is the second patch in a two-part series introducing a `--format` option to `git name-rev`, allowing pretty-printed output similar to `git log --format`. The patch builds on the preparatory style fixes from part 1.

The core change enables `git name-rev` to format revision output using the same pretty-print machinery as `git log`, while maintaining its unique ability to process mixed input (revisions interspersed with arbitrary text). The implementation handles both command-line arguments and stdin input, supports notes display, and includes comprehensive tests.

Key aspects:
- Adds `--format=<pretty>` option with the same specifiers as `git log`
- Implicitly enables `--name-only` when formatting
- Preserves `name-rev`'s ability to process mixed revision/text input
- Includes tests verifying format specifiers, stdin processing, and notes handling

The commit message makes a strong case for why this functionality belongs in `name-rev` rather than other commands, citing its unique ability to handle piecemeal input and mixed content. The implementation looks clean and well-tested, with careful consideration given to edge cases and backward compatibility. This appears to be a thoughtful addition that fills a real gap in Git's tooling.
