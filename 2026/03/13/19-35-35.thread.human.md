Eric Ju has proposed extending Git's reference-transaction hook mechanism with a new "preparing" phase that fires before reference locks are acquired, primarily to help distributed Git storage systems like GitLab's Gitaly/Praefect coordinate concurrent writes earlier in the transaction flow. The implementation, developed with input from Patrick Steinhardt and Justin Tobler, modifies `refs.c` to add this phase while preserving the existing "prepared", "committed", and "aborted" phases. Documentation in `githooks.adoc` has been updated to explain the new phase's behavior, and tests in `t1416` and `t5510` demonstrate its use.

The change isn't strictly backwards compatible since existing hooks might error on unknown phases, but the author argues this is acceptable given the hook's documented nature as exposing implementation details. They considered but rejected introducing a v2 hook as too heavyweight for the use case. The patch appears well-considered and cleanly implemented, with clear motivation for distributed systems coordination. While likely uncontroversial, reviewers may want to scrutinize the backwards compatibility tradeoff before this moves forward.
