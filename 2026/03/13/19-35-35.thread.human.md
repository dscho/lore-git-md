This thread introduces Eric Ju's patch series (with contributions from Patrick Steinhardt, Justin Tobler, and Karthik Nayak) that extends Git's reference-transaction hook with a new "preparing" phase. The change helps distributed Git storage systems like GitLab's Gitaly/Praefect coordinate concurrent writes earlier in the transaction flow, before locks are acquired, rather than during the existing "prepared" phase.

The implementation modifies `refs.c` to add this pre-lock notification while maintaining all existing phases ("prepared", "committed", "aborted"), with corresponding updates to `githooks.adoc` and test coverage in `t1416` and `t5510`. The patch went through multiple iterations with feedback from maintainer Junio Hamano, who approved the final version. Key refinements included standardizing the author's email address, adjusting commit subject conventions, and improving error messages to clearly identify rejection phases. Junio initially sought clarification about how concurrent transactions would be "rearranged" - Eric explained this refers to GitLab's system consulting a central coordinator during the new phase.

Patrick Steinhardt, a major contributor to Git's ref backend work, validated the technical approach and confirmed the v2 changes looked good, noting only a minor documentation formatting issue. Justin Tobler raised an internationalization consideration about phase names in error messages, which Junio clarified should remain fixed API tokens. The final version incorporates Junio's suggestions for concise error message formatting (under 80 columns with quoted phase names) and extracts shared error strings into constants.

With maintainer approval and all substantive technical concerns addressed, this feature is now ready for integration. The core functionality remains unchanged from the initial proposal, while the review process improved documentation clarity and error message precision. The patch demonstrates Git's thorough review culture where feedback leads to meaningful improvements while preserving API stability for hooks that expose internal implementation details.
