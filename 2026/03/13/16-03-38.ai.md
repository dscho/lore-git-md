This is a feature patch adding `--format` support to `git name-rev`, completing the series started in the previous patch. The implementation allows `name-rev` to pretty-print commit information similar to `git log --format`, addressing several use cases where other commands fall short.

The patch modifies `builtin/name-rev.c` to handle format parsing using `pretty_print_commit`, while maintaining all existing functionality. Key technical changes include:
- Adding a `pretty_format` struct to hold formatting context
- Modifying `get_rev_name` to handle formatted output when requested
- Updating `show_name` and `name_rev_line` to pass through the format context
- Adding comprehensive tests in `t6120-describe.sh` covering argument-based formatting, stdin annotation with mixed text, and note display

The commit message makes a strong case for this feature by detailing limitations of existing commands (`log`, `show`, `rev-list`, `cat-file`) when trying to format individual commits on demand. The implementation appears well-considered, with the author having evaluated edge cases like note handling and mixed input/output scenarios. The tests verify both basic functionality and more complex cases like formatting tree objects in running text.

This completes the series' goal of bringing `--format` parity to `name-rev`, providing a flexible tool for commit formatting in contexts where other commands are unsuitable. The changes are contained and focused, with thorough test coverage.
