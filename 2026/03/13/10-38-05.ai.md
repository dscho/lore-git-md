This is a final discussion thread about the cover letter formatting feature, specifically debating the "log:" prefix requirement for format names. Phillip Wood weighs in with a technical counterproposal to Junio Hamano's insistence on keeping the prefix.

Phillip argues that requiring "log:" is unnecessarily cumbersome since no other Git formatting interfaces use such prefixes. He suggests an alternative validation approach: rejecting format strings that neither contain a '%' placeholder nor match known fixed format names like "shortlog". This would catch typos while avoiding the artificial namespace requirement. His proposal would prevent using literal fixed strings as formats, but he notes this would be an unusual use case anyway.

The exchange represents the last unresolved point in this otherwise complete series. Phillip's position contrasts with Junio's maintainer stance that the prefix provides important future-proofing. The discussion remains technical and constructive, with Phillip offering a concrete alternative rather than simply disagreeing. This shows the project's culture of working through design disagreements with specific technical arguments even at late stages of patch review.

Key technical points in Phillip's proposal:
- Rejects unknown fixed strings (catches typos)
- Allows %-based formats without prefix
- Maintains backward compatibility with "shortlog"
- Sacrifices ability to use literal fixed formats (deemed unimportant)

The thread demonstrates how even small interface details receive careful scrutiny in Git development, with contributors proposing alternative solutions when they disagree with maintainer preferences.
