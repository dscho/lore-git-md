This is a refactoring patch that completes the technical implementation for the `git replay --revert` feature by finalizing the shared message formatting logic. Junio Hamano reviews Siddharth Asthana's extraction of revert message generation from `sequencer.c` into a reusable `sequencer_format_revert_message()` helper function.

The patch consolidates all revert message formatting (including "Revert"/"Reapply" prefixes and commit references) into a single well-documented function that both `git revert` and the new `git replay --revert` can use. Junio notes two key improvements over the previous version: the function now handles more of the message generation (reducing work for callers), and the parameter changes to `refer_to_commit()` make the dependencies clearer by explicitly passing only what's needed (a `repository` and boolean flag) rather than the full `replay_opts`.

The implementation appears clean and well-reviewed, with Phillip Wood having previously suggested this consolidation approach. This represents the last major technical piece needed for the revert functionality in `git replay`, following extensive discussion about commit ordering, empty commit handling, and message formatting.
