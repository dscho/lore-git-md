This is a GSoC (Google Summer of Code) proposal from Pablo Sabater to complete and extend the `remote-object-info` command for `git cat-file`. The proposal builds on Eric Ju's previous work that remains unmerged after v11 due to unresolved issues.

The project has two main goals:
1. Rebase and finish Eric's work by addressing known issues:
   - Fixing format validation that currently uses `strstr()` and can cause segfaults
   - Resolving style and code issues noted by Junio Hamano and Jeff King
   - Adding missing checks and fixing error messages
   - Implementing proper cleanup between local and remote queries

2. Extend support for `%(objecttype)` placeholder by:
   - Modifying the v2 protocol on server side
   - Updating client-side handling
   - Adding tests and documentation
   - Making the default format include type information

The proposal demonstrates solid understanding of the existing code and its issues. Pablo has already contributed several test-related patches to Git (some merged) and has studied Eric's work in depth. The timeline is well-structured with clear milestones and includes consideration of backward compatibility. If time permits, Pablo suggests future extensions like supporting additional placeholders (`%(objectsize:disk)`, `%(deltabase)`) and functionality for identifying missing blobs in partial clones.

This appears to be a well-researched proposal from an engaged contributor who has already demonstrated ability to work with the Git codebase and mailing list workflow. The work would complete an existing feature that's been stalled in review while adding useful functionality for partial clone users.
