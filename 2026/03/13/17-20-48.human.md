This is a maintainer response in the ongoing discussion about cover letter formatting in `git format-patch`, specifically addressing the debate over requiring a "log:" prefix for format names. Junio C Hamano weighs in on Phillip Wood's proposal to drop the prefix requirement.

Junio indicates openness to a DWIM (Do What I Mean) approach similar to how `git log --pretty` handles format strings - where the "format:" prefix is technically required but can be omitted when the string contains %-placeholders. This suggests a potential compromise position between Phillip's proposal (which would drop the prefix entirely) and the current strict prefix requirement.

The exchange represents the final design decision needed before this otherwise complete feature can be merged. The discussion remains technical and constructive, with Junio showing willingness to consider alternatives while maintaining interface stability. This follows eight iterations of review where all other aspects of the feature have been settled, including the format naming ("log:chronological" vs "chrono"), config behavior, and integration with existing cover letter generation.

The patch series implements configurable cover letter formatting through both command-line (`--commit-list-format`) and config (`format.commitListFormat`) options, with comprehensive test coverage and documentation. The only remaining question is whether to require, make optional, or eliminate the "log:" prefix for format names - a decision that now appears headed toward a DWIM-style compromise.
