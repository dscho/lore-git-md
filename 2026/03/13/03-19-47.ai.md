This is a bugfix patch addressing Windows test portability issues in the `git apply -p` argument parsing fix that was previously merged. The patch inlines test patch data directly in the script to work around CRLF line ending issues on Windows, implementing the solution proposed by Jeff King.

The core change remains the same - replacing unsafe `atoi()` with `strtol_i()` for proper validation of the `-p` argument in `apply.c`. The new work here focuses on the test infrastructure: rather than using external patch files (which caused Windows test failures due to CRLF handling), the test patch content is now embedded directly in the script using heredocs. This matches the preferred solution identified in earlier discussion.

The patch adds four new test cases that verify:
1. Successful application with valid numeric input
2. Rejection of non-numeric input
3. Rejection of malformed numeric input (trailing non-digit)
4. Rejection of negative numbers

Each test includes proper cleanup via `test_when_finished`. The approach maintains the same validation behavior while avoiding platform-specific line ending issues. This version addresses the final loose end from the merged series, completing the fix for this edge case in argument parsing.
