Bugfix follow-up addressing test portability in the recently merged `git apply -p` validation patch. Jeff King provides additional technical details about the Windows test failures caused by CRLF line endings in the test patch file, offering two potential solutions while clearly favoring one approach.

The core issue stems from how `apply.c` parses diff headers when CRLF line endings are present, which affects path component removal during patch application. Jeff demonstrates this can be reproduced on Linux by manually creating a patch with CRLF endings. He notes the test suite already handles similar cases through `.gitattributes` declarations in other test directories (like `t/t4101/`), suggesting this as one possible fix.

However, Jeff strongly advocates for inlining the test patch data directly in the script (`t4120-apply-popt.sh`) as the cleaner solution, since test scripts are checked out with LF line endings regardless of platform. This approach would avoid the CRLF parsing issue entirely while also being more maintainable. The email leaves the underlying CRLF parsing bug in `apply.c` as a potential separate fix, though no immediate plans are indicated to address it.

This follow-up highlights the careful attention to cross-platform testing in Git's development process, particularly around line ending handling. Jeff's analysis draws on both deep knowledge of the codebase and awareness of historical solutions to similar problems, providing the original author with clear guidance while documenting the tradeoffs for future reference.
