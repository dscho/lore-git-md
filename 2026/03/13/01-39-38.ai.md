This is the final patch in a v6 series adding signature handling capabilities to `git fast-import`, specifically implementing a `sign-if-invalid` mode that allows re-signing commits with invalid signatures. The series builds on previous work that enabled stripping invalid signatures.

The patch introduces a new `sign-if-invalid[=<keyid>]` mode for `--signed-commits` that will verify commit signatures and replace invalid ones with newly created signatures using either a specified key or the default signing key. Valid signatures remain unchanged. The implementation shares infrastructure with the existing `strip-if-invalid` mode but adds signing capability through the consolidated `sign_buffer()` API introduced earlier in the series.

Key technical details include:
- New `SIGN_SIGN_IF_INVALID` enum value and parsing logic that handles optional key IDs
- Shared warning infrastructure via `warn_invalid_signature()` with updated messages to clarify signature replacement
- Explicit failure for interoperability mode (with NEEDSWORK comment explaining the limitation)
- Comprehensive test coverage for OpenPGP/X.509/SSH signatures
- Special test case demonstrating explicit key ID usage with SSH signatures

The implementation appears solid with thorough test coverage. The series has evolved through multiple iterations with improvements based on feedback, particularly around API design and documentation clarity. This final version addresses all review comments and is ready for merging, completing the feature addition that began in earlier versions of the series.

The patch maintains clean separation of concerns from the signature stripping functionality while sharing common verification infrastructure.
