This is a technical discussion about the ongoing effort to improve conditional stashing behavior in `git checkout` and `git switch`. Phillip Wood responds to Junio Hamano's suggestion about optimizing the autostash implementation by pointing out a potential complication with submodule handling.

Phillip raises an important edge case: the current `-m` (merge) option for checkout handles submodule updates, while the proposed autostash-based approach would not, since `git stash` doesn't support submodules. He suggests that while teaching stash to handle submodules would be ideal, it's not a simple change due to the need to track submodule states within the parent stash.

The exchange highlights a key design consideration for the feature - the tension between unifying the stash-based approach with existing merge behavior while maintaining all current functionality. Phillip's input suggests the solution may need to either extend stash's capabilities or maintain some separate merge logic for submodule cases.

This is part of the third iteration of a series that has already addressed significant maintainer feedback about unifying the `-m` and `--autostash` behaviors. The discussion now focuses on ensuring the solution handles all edge cases, with submodule support emerging as a remaining technical challenge.
