Bugfix targeting git-upload-pack's packfile output handling. This is part 1 of a 10-patch series addressing write contention in upload-pack.

Patrick Steinhardt fixes a leftover debug statement in upload-pack.c that was inadvertently sending "flushed." to stderr during packfile transfers. This message, introduced in 2006, was being forwarded to clients during clone operations, as demonstrated in the commit message's example output. The patch simply removes the fprintf statement while preserving the buffer flushing logic.

The change is straightforward and clearly motivated - debug output shouldn't leak to clients. This appears to be a preparatory cleanup for more substantial changes to the buffering mechanism coming in subsequent patches. The commit message provides clear evidence of the issue and historical context, though it doesn't specify whether this was causing any functional problems beyond the cosmetic message.

The patch touches the packfile transfer path in upload-pack.c, specifically the create_pack_file function where the buffering occurs. While small, this change could be considered part of the ongoing effort to improve upload-pack's performance and reliability, which has seen recent attention from multiple contributors.
