This is a bug report about `git describe --dirty` behavior when used with `--git-dir` outside a repository. The reporter, Thomas Braun, observes that `--dirty` incorrectly reports a dirty state when the command is run from outside the repository directory, even when the repository is clean. The behavior is correct when either run from inside the repository or when explicitly specifying `--work-tree`.

The issue appears to be related to commit 2ed5c8e174 ("describe: setup working tree for --dirty", 2019-02-03), which modified how `--dirty` interacts with the working tree. The reporter is asking for guidance on where to start investigating a fix.

This looks like a legitimate bug in how Git handles working tree detection for the `--dirty` flag when using `--git-dir` from outside the repository. The workaround of specifying `--work-tree` suggests the issue lies in the automatic working tree detection logic. The bug affects users who script Git operations from outside repository directories, a common practice in CI/CD systems and other automation.
