This is a bug report about `git describe --dirty` behavior when used with `--git-dir` outside the repository. The issue occurs when running `git describe --dirty` from outside a repository while specifying `--git-dir` - it incorrectly reports the repository as dirty even when it's clean. The reporter, Thomas Braun, notes this can be worked around by also specifying `--work-tree`, and suspects commit 2ed5c8e174 ("describe: setup working tree for --dirty", 2019-02-03) may be related.

The bug appears to be in how `git describe` handles working tree setup when only `--git-dir` is provided. The command needs access to the working tree to properly check for dirty state, but isn't properly establishing that context when run from a different directory. The reporter is asking for guidance on where to start investigating a fix, suggesting this may be a good candidate for someone looking to contribute their first patch to Git. The issue touches the interaction between repository discovery, working tree handling, and the describe command's dirty-state detection.
