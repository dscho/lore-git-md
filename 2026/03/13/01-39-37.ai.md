This is a refactoring patch that consolidates signing infrastructure in preparation for the `sign-if-invalid` mode in `git fast-import`. It's part of a v6 series that builds on earlier work by Christian Couder and Justin Tobler.

The patch removes the commit-specific `sign_commit_to_strbuf()` helper from commit.c and extends the more general `sign_buffer()` function in gpg-interface.c to handle default key fallback logic through a new `SIGN_BUFFER_USE_DEFAULT_KEY` flag. This creates a unified signing API that can be reused across different contexts, including the upcoming fast-import signature handling.

Key technical changes:
- Introduces `enum sign_buffer_flags` with `SIGN_BUFFER_USE_DEFAULT_KEY` flag
- Moves default key fallback logic from commit.c to gpg-interface.c
- Updates all callers (tag.c, commit.c, send-pack.c) to use the new flag-based API
- Maintains backward compatibility by keeping the same behavior when flag is not set

The implementation is clean and focused, with clear commit message explaining the motivation. The changes are well-contained and properly documented in the header file. This refactoring enables the subsequent patch in the series to implement `sign-if-invalid` mode while keeping the signing logic centralized.

The patch follows Git's incremental development model, building on previous signature handling work while establishing reusable infrastructure for future extensions. It demonstrates good architectural separation of concerns by moving commit-specific logic out of the general signing interface.
