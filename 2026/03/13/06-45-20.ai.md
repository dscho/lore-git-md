This is patch 9/10 in Patrick Steinhardt's performance optimization series, focusing on the csum-file subsystem. The patch removes the `hashfd_throughput()` function, which was only used by `git pack-objects` to write packfiles to stdout with progress reporting. The function is replaced with direct use of the more flexible `hashfd_ext()` interface introduced earlier in the series.

The change moves the progress reporting configuration (including the 8KB buffer size optimization for more frequent updates) into the pack-objects caller rather than keeping it in the csum-file layer. This prepares for future changes to the pack-objects caller while maintaining the same behavior. The patch is a straightforward mechanical conversion that doesn't change functionality, just moves where the configuration happens.

This is part of the larger effort to reduce write syscalls in high-concurrency scenarios, though this particular change is more about API cleanup than direct performance impact. The series has already been approved by Junio for merging, with Johannes Sixt having reviewed the platform-specific aspects.
