This is a feature addition to the `git replay` command, introducing a `--revert` mode for server-side history rewriting. The patch is part of a v4 series that has undergone extensive review from key contributors including Phillip Wood, Patrick Steinhardt, and Junio Hamano.

The change enables `git replay` to reverse commits directly on bare repositories, which is particularly useful for GitLab's Gitaly service. The implementation follows the same approach as `sequencer.c`, treating reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent) to effectively reverse the diff direction.

Key technical aspects include:
- Reverts are processed newest-first (matching `git revert` behavior) to reduce conflicts
- Commit messages follow standard revert conventions with "Revert" prefix and hash references
- Empty revert commits are dropped by default, aligning with `git cherry-pick` behavior
- The implementation consolidates message formatting logic into `sequencer_format_revert_message()`
- Extensive test coverage verifies the behavior in both regular and bare repositories

The patch touches several files including `builtin/replay.c`, `replay.c`, documentation, and test scripts. It introduces a `REPLAY_MODE_REVERT` enum to distinguish this operation from existing modes. The technical implementation appears solid, with careful attention to edge cases and alignment with existing Git conventions.

This represents the final technical patch in the series, with all substantive review feedback addressed. The higher-level discussion about interface design (flags vs subcommands) continues but is being deferred to avoid scope creep in this already well-reviewed series.
