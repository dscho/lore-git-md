This is patch 8/10 in Patrick Steinhardt's performance optimization series, introducing a new `hashfd_ext()` function to the csum-file subsystem. The patch refactors the hashfile creation interface to use an options structure, replacing the internal `hashfd_internal()` function and setting up for the deprecation of `hashfd_throughput()` in the next commit.

The new `hashfd_ext()` function accepts a `struct hashfd_options` containing progress reporting and buffer length configuration, providing a unified interface that will eventually replace both `hashfd()` and `hashfd_throughput()`. The default buffer sizes (128KB for normal operation, 8KB when progress reporting is enabled) are preserved from the previous implementation.

This change is part of the broader effort to reduce write syscalls through `writev()`-based buffering, with the csum-file subsystem being one of several components receiving optimization. The patch maintains all existing functionality while providing a more flexible interface for future extensions. The implementation has been reviewed and approved as part of the overall series, with Johannes Sixt having validated the platform-specific aspects.
