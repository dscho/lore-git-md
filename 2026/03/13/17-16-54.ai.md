This is a feature patch series (now at version 3) that reworks `git checkout -m` to use autostash behavior instead of three-way merging, as part of an ongoing effort to unify conflict resolution approaches across Git commands. The patch comes from maintainer Junio C Hamano responding to Harald Nordgren's implementation.

The key development in this email is Junio's detailed review of the documentation and implementation. He highlights several important considerations:
1. The commit message needs updating to reflect that this is now more about improving `checkout -m` than just adding autostash support
2. Documentation should maintain clarity about when the `-m` flag applies
3. The stash creation message might be too verbose and could be suppressed until actually needed
4. The labels in merge conflicts ("Updated upstream"/"Stashed changes") lose useful context compared to the original branch names
5. Some preparatory changes (like the new `conflict_style_name()` function) might belong in separate patches

Junio expresses enthusiasm for the general direction of simplifying the checkout code by leveraging autostash infrastructure, but wants to ensure the user experience remains polished. He suggests potential improvements to conflict messaging and considers how to handle the stash creation notification more elegantly. The review also surfaces an important technical consideration about preserving branch name context in conflict markers.

This email moves the discussion from conceptual approval to implementation refinement, with Junio providing specific guidance on documentation wording and suggesting possible follow-up work to improve the stash application labeling. The patch appears headed toward acceptance once these presentation and messaging details are addressed.
