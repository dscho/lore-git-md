This is a feature patch series introducing a new `--format` option for `git name-rev`. The primary change is in patch 2/2, while patch 1/2 is a minor coding style fix.

The series aims to `git name-rev` what `--format` does for `git log` - allowing pretty-printed output of revision information. The author (Kristoffer Haugsbakk) describes experimenting with different implementation approaches before settling on using `pretty_print_commit`, though notes some minor output differences from `git log`'s behavior.

Key technical details:
- Adds `--format=<pretty>` option to `git name-rev`
- Handles notes via display refs (though suggests `--[no-]notes` flags might be better)
- Modifies `builtin/name-rev.c` to support format parsing and output
- Includes tests in `t6120-describe.sh`
- First patch is an unrelated brace-style fix to comply with CodingGuidelines

The implementation appears well-considered, with the author having evaluated multiple approaches. The commit message thoroughly documents the design decisions and tradeoffs. This looks like a useful addition that aligns with existing Git conventions while providing more flexible output formatting for `name-rev`.
