This thread clarifies the behavior of `git describe --dirty` when run from outside a repository. Thomas Braun initially reported what appeared to be a bug where the command incorrectly reported a repository state as dirty when using `--git-dir` without `--work-tree`. Junio C Hamano explained this is actually expected behavior - when only `--git-dir` is specified, Git assumes the current directory is the working tree root, which leads to incorrect dirty state detection if that's not actually the case.

The discussion has established two proper ways to use the command from outside the repository: either specify both `--git-dir` and `--work-tree` explicitly, or use the simpler `-C` option to change to the repository directory first. Patrick Steinhardt reinforced this by noting `-C` is generally more straightforward than `--git-dir` for most use cases. The consensus is that the behavior is working as designed, though the documentation could be improved to make this interaction clearer for users. No code changes are needed, but the thread may lead to future documentation updates about repository discovery and working tree state checks.
