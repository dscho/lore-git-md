The thread began with Thomas Braun reporting what appeared to be a bug in `git describe --dirty` when used with `--git-dir` outside the repository, where it incorrectly marked repositories as dirty. The initial analysis suggested this might stem from commit 2ed5c8e174 and could be a good first contribution opportunity.

Junio C Hamano has now clarified that this is actually expected behavior - when only `--git-dir` is specified, Git defaults to treating the current directory as the working tree root, which explains the incorrect dirty state detection when run from outside. The maintainer confirmed that specifying both `--git-dir` and `--work-tree` is the proper solution, and that the issue lies in understanding Git's working tree handling rather than being a code defect. While closing the bug report as "working as intended", Junio left open the possibility of improving the documentation around `--git-dir` and working tree interactions if the current explanations are unclear.
