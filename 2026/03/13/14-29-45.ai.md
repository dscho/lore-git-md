This is a technical discussion about implementing conditional stashing in `git checkout` and `git switch`, specifically addressing edge cases with submodules. Phillip Wood responds to Junio Hamano's earlier suggestion about optimizing the autostash behavior to only stash when local changes would conflict with the target branch.

Phillip raises two key technical concerns about the proposed approach: First, he questions whether the pre-check for conflicts is necessary if the stashing could be triggered by `unpack_trees()` failing due to local changes. Second, he notes that replacing the `-m` option's three-way merge with autostash behavior would break submodule handling, since `git stash` doesn't currently support `--recurse-submodules` while `checkout -m` does.

The email highlights an important implementation challenge - the proposed unification of `-m` and `--autostash` would need to either extend stash to handle submodules or find another way to preserve submodule updates during branch switching. Phillip suggests teaching `git stash` to recurse into submodules would be ideal but non-trivial, as it would require storing submodule stash states within the parent stash commit.

This discussion represents a refinement of the earlier design proposal, focusing on preserving existing functionality (particularly for submodules) while still achieving the underlying goal of more intelligent conflict handling during branch switches.
