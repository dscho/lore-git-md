Bugfix follow-up addressing test failure on Windows for the recently merged `git apply -p` argument parsing fix.

Jeff King reports that the test case for `git apply -p 1` fails on Windows CI with an error about missing filename information when removing path components. He suggests moving the test patch data inline to the test script rather than using an external file, which would both fix the Windows issue and follow Git's convention of keeping small test data with the tests. The proposed change also removes unquoted `$TEST_DIRECTORY` references that could cause issues in some environments.

This is a minor refinement to the already-merged fix that improved `git apply -p`'s argument validation. The core functionality remains sound - this just cleans up the test implementation. Jeff's suggestion follows established patterns in Git's test suite and addresses a platform-specific edge case that wasn't caught during initial review.
