This is a documentation patch from Junio C Hamano proposing to update to the SubmittingPatches document. It follows up on Jeff King's observation about shell portability checks in the test suite, where he noted that running individual test scripts directly might miss some portability issues that `make test` would catch.

The patch adds a reminder to the contribution guidelines that changes should be verified with `make test` from the top-level directory, not just by running individual test scripts. This is positioned as an important best practice since the full test suite includes additional checks (like shell portability validation) that aren't run when executing tests directly.

The change is small but meaningful - it codifies a lesson learned from the recent partial clone test modernization effort into Git's official contribution documentation. This demonstrates how the project captures knowledge from specific review experiences to improve the general contributor experience. The patch follows Git's standard documentation style and would slot naturally into the existing SubmittingPatches file.
