This is the third patch in Tian Yuchen's series to migrate encoding-related functionality from global variables to repository-specific storage, part of the ongoing `the_repository` removal effort. The patch moves the encoding configuration variables (`git_commit_encoding` and `git_log_output_encoding`) directly into `struct repository` rather than the previously considered `repo_settings` approach, following feedback from Phillip Wood. The change affects commit creation and display paths across 20 files, updating them to use repository-aware versions of the encoding accessors.

Key technical details include:
- New repository fields: `struct repository` gains `commit_encoding` and `log_output_encoding` members
- Updated APIs: `get_commit_output_encoding()` and `get_log_output_encoding()` now take a `struct repository*` parameter
- Config parsing still uses `the_repository` temporarily due to callback machinery constraints
- Fallback behavior maintained for unconverted callers via `the_repository`
- Memory management: repository clearing now frees the encoding strings

The patch demonstrates careful attention to maintaining behavior during transition, with thorough updates to commit creation (`commit_tree()`, `write_commit_tree()`), pretty-printing (`pretty_print_commit()`), and various builtin commands that handle commit messages. The changes are mechanical but widespread, touching commit, log, rebase, merge, and other subsystems.

This appears to be a well-executed step in the global variable migration effort, following established patterns from prior work. The main open question remains how to eventually plumb the repository pointer through the config callback machinery, which the commit message notes as future work. The patch maintains all existing behavior while moving the architecture forward.
