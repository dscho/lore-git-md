This is the first patch in Adrian Ratiu's v3 series introducing config-based hooks. The patch lays groundwork for running multiple hook commands by adding alloc/free callbacks for hook state management.

The change refactors how hook state is handled to support future parallel execution. Previously, hooks using internal state (like receive-pack and reference-transaction hooks) stored this state on the stack since hooks ran sequentially. Now the patch introduces alloc/free functions to properly manage this state when multiple hooks may run concurrently.

Key technical changes:
- Adds `hook_data_alloc_fn` and `hook_data_free_fn` typedefs in hook.h
- Updates receive-pack, refs, and transport code to use the new alloc/free pattern
- Enforces that alloc/free functions must be provided together via BUG() check
- Uses `CALLOC_ARRAY()` for allocations and designated initializers where possible

The patch is part of a larger effort to make hooks configurable via Git config while maintaining filesystem hook compatibility. It shows careful attention to memory management and lays important groundwork for the series. Review feedback from Junio Hamano and Patrick Steinhardt has already been incorporated, suggesting this iteration is nearing final form.
