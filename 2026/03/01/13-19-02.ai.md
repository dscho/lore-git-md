This is a discussion thread about the ongoing `the_repository` removal effort, specifically regarding Shreyansh Paliwal's patch to refactor editor.c. Burak Kaan Karaçay, another GSoC applicant, suggests an alternative approach to handling the editor_program configuration.

Burak acknowledges that Shreyansh's patch successfully moves the editor_program global from environment.c to editor.c while maintaining current behavior. However, he proposes going further by eliminating the global state entirely - suggesting the editor program configuration could be looked up via repo_config_get* when needed, passing a struct repository parameter.

This would represent a more thorough removal of global state, though with the tradeoff that config errors would be caught later (at editor startup rather than config load time). Burak notes this seems like a reasonable compromise since it wouldn't cause data loss or serious issues.

The suggestion aligns with the broader project goal of eliminating global state, but takes it a step further than the current patch series. This is the first substantive technical discussion on the thread - the original patches had not yet received review feedback. The exchange demonstrates how even mechanical refactorings can prompt deeper architectural discussions about state management in the codebase.
