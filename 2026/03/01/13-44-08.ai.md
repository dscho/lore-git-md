This is a feature patch series adding structured path output to `git repo info`, part of the ongoing effort to move repository introspection functionality from `git rev-parse` to a more purpose-built command. The two patches add `path.git-dir` and `path.common-dir` fields that mirror the existing `git rev-parse --git-dir` and `--common-dir` options, while integrating with the new `--path-format` flag for consistent path representation.

The implementation builds on prior work by Lucas Skeggs on structured output fields and recent path-related additions to `git repo info`. The patches use existing repository path APIs like `repo_get_git_dir()` to avoid reinventing path resolution logic. The changes are focused and mechanical - each patch adds one field with corresponding tests.

Patrick Steinhardt has previously expressed support for consolidating repository introspection in `git repo` rather than overloading `git rev-parse`. This series continues that direction while deliberately avoiding broader questions about path resolution semantics, leaving those to parallel discussions. The narrow technical scope and clear precedent from existing `rev-parse` behavior suggest these additions are uncontroversial and likely to progress smoothly through review.
