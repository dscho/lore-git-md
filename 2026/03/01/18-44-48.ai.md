This is a feature patch series (v3, 12 patches) implementing config-based hooks, allowing hooks to be specified via Git configuration rather than just filesystem scripts. The series introduces `hook.<friendly-name>.command`, `hook.<friendly-name>.event`, and `hook.<friendly-name>.enabled` configuration options while maintaining backward compatibility with traditional hookdir scripts.

Key technical developments in this version:
- Rebased on 'next' branch after prerequisite hook dependency series landed
- Simplified callback data allocation validation using (!A != !B) pattern per Junio's suggestion
- Added support for listing disabled hooks in `git hook list`
- Introduced config scope tracking (global/local) for hooks
- Refactored hook config cache from strmap to named struct
- Standardized on `CALLOC_ARRAY()` and renamed cleanup functions to `*_free()` variants
- Added defensive `BUG()` checks for unknown hook types
- Renamed config keys from `hook.<name>` to `hook.<friendly-name>` for clarity

The series maintains clear separation between cached config data (strmaps) and runtime hook state, with `struct hook` instances containing pipe callback data that cannot be cached. It implements Patrick Steinhardt's suggestion to store enabled/disabled state directly in `struct hook` and defers parallel execution functionality to a follow-up series.

Notable review feedback incorporated:
- Junio approved the core approach while requesting documentation updates
- Patrick provided detailed reviews across all patches including modernization to `CALLOC_ARRAY`
- Consensus reached to defer `--disabled` flag functionality while keeping door open for future enhancements
- The implementation now fully manages feed pipe callback data lifecycle via alloc/free functions

The thread shows steady progress toward configurable hooks, with maintainer Junio Hamano signaling readiness to move forward with the core functionality while treating parallel execution as a separate track. The parallel execution concerns have been addressed in a v2 series that preserves TTY handling and maintains backward compatibility.
