This is a refactoring patch series that continues the `the_repository` removal effort, specifically targeting encoding-related global variables. The series represents version 3 of Tian Yuchen's work to migrate `git_commit_encoding` and `git_log_output_encoding` from global state to repository-specific storage.

The key change in this iteration is a pivot from the v2 approach - instead of moving the encoding configurations into `struct repo_settings`, they are now being placed directly in `struct repository`. This adjustment came in response to feedback from Phillip Wood about problems with lazy evaluation of these eagerly-parsed user preferences. The new approach maintains immediate validation while still plumbing repository context through all the relevant APIs.

The series consists of three patches that systematically update commit creation, pretty-printing, and configuration handling to work with repository-aware versions of the encoding functions. Over 30 files are touched across the codebase, with changes to builtins (commit, log, rebase, etc.), core commit handling, and the sequencer. The author notes that while the config parsing still uses `the_repository` temporarily, all the read/write paths now properly accept any repository instance, setting up for future config machinery updates.

This appears to be a well-considered iteration that addresses prior technical concerns while making measurable progress on the broader global state elimination goal. The changes are mechanical but widespread, following established patterns for this type of migration. Test suite passing with sanitizers suggests the behavior-preserving nature of the refactoring. As part of a GSoC 2026 project, this represents solid incremental work toward libification.
