A small but useful addition to Adrian Ratiu's config-based hooks series. This patch adds a `-z` option to `git hook list` that makes the output NUL-terminated, which is helpful for handling hook names that might contain unusual characters like newlines. The change is straightforward - it modifies the output formatting in `builtin/hook.c` while maintaining the existing behavior as default. 

The implementation follows Git's standard pattern for NUL-terminated output options, similar to other commands like `git ls-files -z`. Test coverage verifies both the new option and that it doesn't break existing functionality. This was suggested by Patrick Steinhardt during review of earlier versions and fits naturally with the series' goal of making hooks more robust and configurable.

The patch touches three files: the documentation to describe the new option, the hook command implementation to add the formatting logic, and the test suite to verify the behavior. It's a focused change that doesn't affect the core hook execution or configuration machinery introduced earlier in the series.
