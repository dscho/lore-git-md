This is the final patch in Adrian Ratiu's config-based hooks series, implementing visibility of disabled hooks in `git hook list`. The patch ensures disabled hooks remain in the cache (marked by a new `disabled` field) rather than being filtered out, allowing them to be displayed with a "(disabled)" annotation. When using `--show-scope`, the output includes both scope and disabled status (e.g. "myhook (local, disabled)").

The change maintains backward compatibility while adding more visibility into hook configuration state. Disabled hooks without commands now trigger warnings rather than fatal errors, as requiring commands for disabled hooks was deemed unnecessarily strict. The patch includes thorough test coverage verifying the new display behavior and proper interaction with `hook_exists()` checks.

This completes the core functionality of the config-based hooks series, which has undergone extensive review and iteration. The implementation carefully handles edge cases while maintaining the separation between config-based hooks (which work anywhere) and filesystem hooks (which require a repository). With this patch, users gain full visibility into their hook configurations regardless of enabled state.
