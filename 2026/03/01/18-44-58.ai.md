This is a refactoring patch in Adrian Ratiu's config-based hooks series (now at v3, patch 10/12). The change replaces the direct `struct strmap*` hook config cache in `struct repository` with a named `struct hook_config_cache` wrapper, and moves the command strings from raw string_list util pointers into a dedicated `struct hook_config_cache_entry`.

The patch introduces proper type safety by:
1. Defining `struct hook_config_cache` to wrap the strmap (preparing for future expansion)
2. Creating `struct hook_config_cache_entry` to hold hook command strings (replacing direct char* util pointers)
3. Updating all cache access code to use the new types
4. Adjusting memory management to properly free the new structures

The changes are mechanical with no behavior modifications - this is pure infrastructure work to support upcoming patches that will add more metadata to the hook config cache. The patch maintains all existing functionality while making the code more maintainable and type-safe.

Reviewers had previously approved the overall approach, and this patch follows through on the agreed direction. The careful memory management (using `CALLOC_ARRAY` and proper cleanup) matches Git's standards, and the changes are well-contained to the hook subsystem internals.
