This is a bugfix patch addressing submodule fetching behavior that incorrectly assumes all submodule remotes are named "origin". The patch is the final v4 iteration of a series that has been thoroughly reviewed and is now cleared for integration.

The core change introduces a new `get-default-remote` subcommand in `submodule--helper` to properly handle submodules with differently-named remotes. This fixes cases where `git fetch --recurse-submodules` would fail when submodules used non-origin remote names. The implementation maintains backward compatibility by falling back to "origin" if default remote lookup fails.

Key technical details include:
- New helper command in builtin/submodule--helper.c that determines the correct remote name
- Changes to submodule.c to use the helper instead of hardcoded "origin"
- Comprehensive test coverage across multiple test files (t5526, t5572, and new t7426)
- Fixes a 7-year-old NEEDSWORK comment from commit be76c21282
- Includes GIT_TRACE output validation to verify remote name handling
- Handles edge cases like nested submodules and repositories with no remotes
