[GSoC proposal] git repo info improvements - Jayatheerth Kulkarni proposes enhancing the new `git repo` command's `info` subcommand with category-based querying (replacing exact-match binary search), removal of `the_repository` dependency (part of ongoing libification), `rev-parse`-like path resolution, and sparse-checkout/submodule awareness. Builds on Lucas Oshiro's GSoC 2025 work introducing `git repo`. Jayatheerth has relevant prior contributions to `builtin/repo.c` and path handling in `dir.c`.

Karthik Nayak reviews the proposal, suggesting glob pattern matching extensions to the category-based query system (e.g. `path*`, `*object*`). Notes technical challenges in removing `the_repository` dependencies, particularly around `is_bare_repository()` call chains. Recommends incorporating newer path resolution discussions from Mansi's proposal. Expresses concern about timeline being overly ambitious, especially for Phase 1 path resolution and Phase 2 libification work, emphasizing need for review cycle buffer time.

Technical specifics mentioned include: `strbuf_add_path` API usage, `get_layout_bare()` refactoring, path resolution targets (`path.git-dir`, `path.common-dir`), and sparse topology awareness. The work connects to Git's broader libification effort and repository introspection modernization. Open questions remain about glob pattern implementation complexity and realistic timeline adjustments needed to accommodate review iterations.
