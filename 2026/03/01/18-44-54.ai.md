This is part 6/12 of Adrian Ratiu's config-based hooks series, implementing the ability to disable configured hooks via a new `hook.<friendly-name>.enabled` config option. The patch builds on the config parsing infrastructure established in previous patches.

The change allows users to temporarily turn off hooks without removing their configuration, particularly useful for overriding global hooks in specific repositories. The implementation:
- Adds a new `hook.<friendly-name>.enabled` config (defaults to true)
- Tracks disabled hooks in a new `disabled_hooks` string list in the config callback struct
- Filters out disabled hooks when building the hook config map
- Includes comprehensive tests covering basic disabling, `git hook list` behavior, and local override of global disabled hooks

The patch follows the series' established patterns, using the `unsorted_string_list_remove()` helper added earlier and maintaining the same cleanup discipline. Test coverage is thorough, verifying the interaction between global and local config scopes. This is a straightforward addition that cleanly extends the config-based hooks functionality while maintaining backward compatibility with existing hook behavior.
