This is a feature patch series adding path-related fields to `git repo-info`, building on existing path formatting from `git rev-parse`. The discussion focuses on design decisions around path formatting approaches.

Phillip Wood raises two key points in response to Lucas Seiki Oshiro's cover letter: First, he asks how this work relates to an earlier similar effort (referencing a specific mailing list thread), noting Junio's past suggestion to use "path.working-tree" rather than copying "rev-parse" naming. Second, he expresses support for the `--path-format` flag approach as the clearest solution, arguing that having different defaults for different paths (like `rev-parse`) would be confusing, and that separate keys for absolute/relative versions would be too verbose.

The thread context shows this is part of an ongoing architectural discussion about path formatting in `repo-info`, with multiple approaches being considered (global flags vs format modifiers vs per-field naming). Phillip's comments add weight to the `--path-format` approach while surfacing historical context about naming conventions that may need revisiting. His perspective as an experienced contributor familiar with the sequencer and worktree handling lends credibility to his design opinion.
