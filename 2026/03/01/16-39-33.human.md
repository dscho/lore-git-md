This is a discussion about refactoring editor configuration as part of the `the_repository` removal effort. Tian Yuchen weighs in on the ongoing debate between Shreyansh Paliwal and Burak about how to handle Git's editor settings.

The core disagreement is whether editor configuration should remain process-wide (Shreyansh's position) or become repository-specific (Burak's proposal). Tian argues strongly for repository-specific behavior, pointing out that users often configure different editors per repository (e.g., vim` in one repo, `nvim` in another) and that local configs like `git config --local core.editor` imply per-repo settings should be possible.

Tian suggests storing `editor_program` in `repo-settings.c` as a way to both eliminate global state and maintain early config validation. This would allow each `struct repository` to have its own editor setting while still catching invalid configurations early during `prepare_repo_settings()`.

The email highlights a real tension in the refactoring - between strict removal of globals versus preserving practical workflows. Tian's use case for different editors in different repositories (especially with submodules) makes a concrete argument that repository-specific behavior would better match how people actually work. The discussion remains unresolved but is moving toward technical specifics of where and how to store the per-repo setting.
