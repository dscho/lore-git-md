This is part 3/12 of Adrian Ratiu's config-based hooks series, introducing a new `git hook list` subcommand to inspect configured hooks. The patch builds on previous infrastructure work to support multiple hooks per event.

The new `git hook list` command shows which hooks would run for a given event, currently only listing traditional filesystem hooks (with "hook from hookdir" output). The implementation includes proper error handling when no hooks exist and adds tests verifying the command's behavior in both empty and populated hook directories.

The patch moves two previously static functions (`hook_free()` and `list_hooks()`) from hook.c to hook.h to make them available to the new list command, while maintaining their existing behavior. Documentation is updated to describe the new subcommand, which will be expanded in future patches to also show config-based hooks once that functionality lands.

This is a straightforward addition that provides visibility into hook configuration, which will become more important as the series introduces config-based hooks alongside traditional filesystem hooks. The implementation is clean and well-tested, with clear error messages and proper memory management.
