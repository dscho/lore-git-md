This is part 2/12 of Adrian Ratiu's config-based hooks series (v3), which builds infrastructure to support multiple hooks per event via configuration while maintaining filesystem hook compatibility. The patch refactors hook execution to work with a list of hooks rather than a single hook path, though initially the list still only contains the traditional filesystem hook.

The key technical changes include:
- Introducing a `struct hook` to represent individual hook commands (currently only traditional hooks)
- Adding `list_hooks()` to collect hooks from multiple sources (currently just filesystem)
- Moving hook state management into the `struct hook` rather than `run_hooks_opt`
- Implementing proper cleanup via `hook_free()` callback
- Maintaining backward compatibility while preparing for config-based hooks

The patch shows careful attention to memory management with `CALLOC_ARRAY` and designated initializers, and includes defensive `BUG()` checks for invalid states. It builds on the memory management foundations from patch 1/12 while keeping the parallel execution work for a future series.

Review feedback from Patrick Steinhardt and Junio Hamano has been incorporated, particularly around naming and cleanup patterns. The changes are well-contained to hook.[ch] with no user-visible behavior change yet - that comes in later patches when config-based hooks are actually implemented. This is a solid infrastructure patch that does the necessary plumbing work for the series' goals.
