This is the final confirmation for Harald Nordgren's long-running effort to make `git status` branch comparisons configurable. The feature allows users to specify which branches to compare (upstream, push, or both) via a new `status.compareBranches` config option, with upstream remaining the default for backward compatibility.

The patch series has gone through 28 iterations over two months (plus earlier work from 2016-2018) and has now received maintainer approval from Junio Hamano. The implementation is technically complete with comprehensive test coverage, including edge cases like duplicate branches and triangular workflows. The changes touch remote.c's branch comparison logic while maintaining all existing behavior.

Harald is checking if Junio has completed his promised final review of the test suite before the patches are merged to 'next'. With all feedback addressed and no outstanding objections, this marks the successful conclusion of a multi-year contribution effort that navigated Git's mailing list workflow to completion. The feature is expected to appear in an upcoming release.
