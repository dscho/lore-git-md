This thread continues the discussion about refactoring editor configuration as part of the broader effort to eliminate Git's global state. The original patches by Shreyansh Paliwal proposed moving editor settings to editor.c while maintaining process-wide behavior, but Tian Yuchen later presented compelling use cases for repository-specific editor configurations, particularly for users working with submodules or multiple projects.

The debate has centered on whether editor settings should remain global (as Phillip Wood and Shreyansh argue, citing practical usage patterns) or become repository-specific (as Burak Kaan Karaçay and Tian advocate, for consistency with Git's configuration model). Burak's latest contribution notes that while per-repo editors may be uncommon, Git already allows local configuration of `core.editor`, creating a potential inconsistency if the implementation remains global. He raises an important point about libification - maintaining some global settings while others become repository-specific could cause problems for tools using Git as a library.

Key participants remain divided: Phillip questions the practicality of per-repo editors, while Burak and Tian emphasize architectural consistency. The discussion has surfaced a broader question about which user-configurable settings should remain global during the `the_repository` removal effort. No clear consensus has emerged yet, but the concrete examples and libification concerns raised may tilt the balance toward repository-specific handling. The thread awaits further input, particularly from maintainers, on how to resolve this architectural tradeoff.
