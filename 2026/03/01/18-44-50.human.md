This is part 2/12 in Adrian Ratiu's config-based hooks series (v3), which introduces infrastructure to support multiple hooks per event. The patch refactors the hook execution logic to work with a list of hooks rather than a single hook, though initially the list only contains the traditional filesystem hook.

The key changes include:
- Adding a `struct hook` to represent individual hook commands (currently only traditional hooks are supported)
- Introducing a `list_hooks()` function that builds the hook list (currently just finds the traditional hook)
- Moving hook state management into the new `struct hook` rather than `run_hooks_opt`
- Adding proper memory management with alloc/free helpers
- Maintaining backward compatibility while preparing for future config-based hooks

The patch is well-structured and follows the project's incremental approach - it introduces the list infrastructure without yet adding config-based hooks (which come in later patches). Review feedback from Junio Hamano and Patrick Steinhardt has been incorporated, particularly around memory management patterns and API documentation.

This is a foundational change that enables the rest of the series while keeping behavior identical for existing hook users. The code is cleanly separated between the new list infrastructure and the traditional hook support that will be built on top of it.
