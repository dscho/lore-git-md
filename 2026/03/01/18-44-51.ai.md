This is patch 3/12 in Adrian Ratiu's config-based hooks series, introducing a new `git hook list` subcommand. The patch builds on the infrastructure from previous patches to provide visibility into which hooks would run for a given event.

The new command lists all hooks configured for a specified event, currently only supporting traditional filesystem hooks (with config-based hooks coming in later patches). When no hooks exist for an event, it prints a warning and exits with status 1. The implementation includes:

1. A new `list` subcommand in `builtin/hook.c` that:
   - Takes a single required hook name argument
   - Uses the existing `list_hooks()` infrastructure
   - Prints hook source information (currently just "hook from hookdir")
   - Properly cleans up allocated memory

2. Documentation updates in `git-hook.adoc` explaining the new subcommand

3. Test coverage in `t1800-hook.sh` verifying:
   - Usage errors and help text
   - Behavior with nonexistent hooks
   - Correct output for traditional hooks

The patch makes `list_hooks()` and `hook_free()` non-static since they're now used by both the run and list subcommands. This is part of the series' broader goal to support multiple hooks per event while maintaining backward compatibility with filesystem hooks.

Review context shows this builds on Patrick Steinhardt's earlier feedback about memory management patterns, using consistent `CALLOC_ARRAY()` and cleanup functions. The implementation is straightforward and well-tested, with clear room for expansion in later patches to handle config-based hooks. The series remains on track for integration after addressing final documentation updates.
