This is part of an ongoing effort to move repository introspection functionality from `git rev-parse` to the new `git repo info` command. The patch adds structured output for the Git directory path, similar to what `git rev-parse --git-dir` provides but with consistent path formatting via the existing `--path-format` flag.

The implementation is straightforward - it exposes the repository's Git directory through a new `path.git-dir` field, using the same path resolution logic as other fields in `git repo info`. The change builds on prior work by Lucas Skeggs and aligns with Patrick Steinhardt's vision for making `git repo` the canonical place for this type of metadata.

The patch follows the established pattern of the series - each commit adds one well-scoped field with corresponding tests (though the test changes aren't shown in this diff). This incremental approach has kept the discussion focused and uncontroversial so far. The change looks like a mechanical but useful addition that moves the project toward the long-term goal of deprecating `rev-parse` for repository metadata queries.
