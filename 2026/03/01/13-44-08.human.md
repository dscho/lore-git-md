This is a feature patch series adding structured path output to `git repo info`, part of the ongoing effort to move repository introspection functionality from `git rev-parse` to a more modern interface.

Pushkar Singh proposes adding `path.git-dir` and `path.common-dir` fields to `git repo info`'s structured output, matching what's currently available through `git rev-parse`. The implementation builds on recent work adding path-related fields to `repo info` and respects the existing `--path-format` flag for controlling absolute vs relative path output.

The changes are straightforward - adding the new fields while reusing Git's existing repository path APIs (`repo_get_git_dir()` etc.). The patch series is small (just 32 lines added across two commits) and appears well-scoped, focusing only on exposing existing path information through the new structured interface rather than changing any path resolution behavior.

This continues the collaborative effort between Pushkar Singh and Patrick Steinhardt to establish `git repo` as the canonical command for repository metadata, with Patrick having previously noted that `rev-parse` has outgrown its original purpose. The patches look like a clean incremental addition to this ongoing project.
