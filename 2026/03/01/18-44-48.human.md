This is a feature patch series (v3) introducing configurable hooks in Git, allowing hooks to be defined via configuration rather than just filesystem scripts. The series is a collaboration between Adrian Ratiu and Emily Shaffer, building on prior work to modernize Git's hook infrastructure.

The key additions in this version include:
- Support for `hook.<friendly-name>.command` and `hook.<friendly-name>.event` config options
- A `hook.<friendly-name>.enabled` toggle to disable hooks without removing config
- The ability to reset hook events with an empty value (`hook.name.event=`)
- A `git hook list` subcommand showing configured hooks with `-z` option for scripting
- Infrastructure for tracking hook config scope (global/local) and disabled state
- Memory management improvements using `CALLOC_ARRAY` consistently

The series has undergone significant review iteration, with feedback from Junio Hamano and Patrick Steinhardt leading to simplifications in the callback validation logic and naming conventions. The implementation now properly handles hook execution order (config hooks run before traditional hookdir hooks) and maintains backward compatibility.

This represents a major step in making hooks more flexible and maintainable, particularly for large-scale deployments where system-wide hooks need to be configured. The changes are well-tested with extensive new test coverage in t/t1800-hook.sh.

The series is based on prerequisite hook infrastructure patches that have already landed in 'next', positioning this work for potential inclusion once final reviews are complete. Parallel execution remains a separate follow-up effort.
