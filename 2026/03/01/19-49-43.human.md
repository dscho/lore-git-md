This is a discussion about path formatting options for the `git repo-info` command, part of an ongoing series adding path-related fields. The thread has been exploring different approaches to handling path formats (absolute vs relative) in the output.

Lucas Seiki Oshiro weighs in on the design discussion, agreeing with the preference for Option 1 - using a global `--path-format` flag rather than per-field format modifiers or duplicating field names. He notes this keeps the API clean and predictable for scripting use cases, avoiding namespace bloat that would come with duplicating all path-related fields for each format variant.

The discussion builds on previous consensus that while this approach means users can't get mixed-format output in a single command invocation (e.g. some paths absolute and others relative), the tradeoff is worth it for API simplicity. The thread shows the project carefully considering how this new command's design will scale as more path-related fields are added in future work.
