This is part 7 of Adrian Ratiu's config-based hooks series, implementing the ability to clear previously configured hook events by setting an empty value for `hook.<name>.event`. The change makes the event configuration behave consistently with other multi-valued Git config keys.

The patch is applied to the hook subsystem and modifies the config parsing logic to handle empty event values by clearing any previously configured events for that hook. The implementation uses the existing `strmap` infrastructure to iterate through and remove entries when an empty value is encountered. Test coverage in t1800-hook.sh verifies the behavior by showing a hook's events can be reset.

Key technical details:
- Empty `hook.<name>.event` values now trigger cleanup of prior event mappings
- Uses `strmap_for_each_entry()` to find and remove all references to the hook
- Maintains the existing last-seen ordering for non-empty values
- Updates documentation to clarify the reset behavior
- Adds test case showing event list can be cleared while other hooks remain

The change follows Patrick Steinhardt's suggestion and maintains the series' pattern of comprehensive test coverage. This is a focused improvement to the config parsing logic that doesn't introduce new concepts or structures, building on the foundation established in earlier patches. The implementation is straightforward and fits naturally with the existing multi-value config handling.
