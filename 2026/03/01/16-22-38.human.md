This is a discussion about refactoring editor configuration as part of the ongoing `the_repository` removal effort. Phillip Wood weighs in on a technical debate between two GSoC participants (Shreyansh Paliwal and Burak Kaan Karaçay) about how to handle the editor program configuration.

Phillip supports Shreyansh's current approach of moving the `editor_program` variable to be static within editor.c with controlled access, rather than Burak's suggestion to make it repository-specific. His key point is that editor preference is logically a process-wide setting - there's no practical reason someone would want different editors for different repositories within the same Git process. This reinforces the design choice to keep the variable as process state rather than pushing it into per-repository configuration.

The exchange remains technical and collegial, with Phillip providing experienced perspective on what constitutes reasonable process state versus what should be repository-specific. His intervention suggests the original approach may be more aligned with Git's actual use cases, though the thread remains open for further input.
