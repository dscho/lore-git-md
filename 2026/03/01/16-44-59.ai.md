This is a feature patch introducing a new `fetch.blobSizeLimit` config option to enable partial clone behavior by default. The patch comes from Alan Braithwaite and appears to be a first version (v1) of the series.

The change allows users to configure a size threshold (like "1m" or "100k") that will automatically apply a `--filter=blob:limit=<size>` during clone and fetch operations. This provides a more discoverable way to enable partial clone functionality compared to requiring explicit `--filter` flags on every command. The config follows: command-line --filter > remote.partialclonefilter > fetch.blobSizeLimit.

The implementation touches both `builtin/clone.c` and `builtin/fetch.c` to handle the new option, with corresponding documentation updates. The patch includes thorough test coverage in `t/t5616-partial-clone.sh` verifying the precedence rules and interaction with existing partial clone configurations.

Key technical details for future reference:
- New config key: `fetch.blobSizeLimit` (documented in config/fetch.adoc)
- When set, automatically applies blob size filter during clone/fetch
- Registers remote as promisor with the filter spec
- Precedence clearly defined between command line, remote config, and global config
- Server-side filter support is required but silently ignored if unavailable
- Tests cover basic functionality, precedence rules, and interaction with existing partial clones
