This is a discussion thread about refactoring editor configuration as part of the `the_repository` removal effort. Burak Kaan Karaçay responds to Phillip Wood's skepticism about making editor settings repository-specific.

Burak acknowledges that users typically don't need different editors per repository, but argues for consistency with Git's configuration model. He notes that while `.editorconfig` files handle most editor-related needs, Git's lack of system-wide-only configuration settings creates a potential issue for libification - if `core.editor` remains global while other settings become repository-specific, it could lead to configuration conflicts when working with multiple repositories through a libgit interface.

The key technical point is that Git currently allows `core.editor` to be set in local repository configs, which creates tension with the proposed process-wide behavior. Burak suggests that if the project wants to maintain editor settings as process-global, it should explicitly prohibit local configuration of `core.editor` to avoid inconsistent behavior. This discussion highlights the broader challenge of deciding which settings should remain global versus becoming repository-specific during the `the_repository` removal effort.

The exchange represents a typical architectural debate in the refactoring effort, weighing practical usage patterns against consistency and future libification needs. Burak's response moves the discussion forward by identifying the configuration model inconsistency as a key consideration.
