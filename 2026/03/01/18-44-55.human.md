This is part 7 of Adrian Ratiu's config-based hooks series, implementing the ability to clear previously configured hook events by setting an empty value. The patch follows Patrick Steinhardt's suggestion to make the "hook.*.event" configuration behave consistently with other multi-valued keys in Git.

The change allows users to reset a hook's event assignments by setting `hook.<name>.event` to an empty string, which clears any previously configured events for that hook. The implementation handles this by iterating through all event mappings and removing the hook name when an empty value is encountered. The documentation is updated to reflect this behavior.

The patch includes a new test case verifying that an empty event value correctly resets the hook's event assignments. This maintains the series' pattern of thorough test coverage for all new functionality. The implementation builds on the existing strmap-based configuration cache introduced in earlier patches, with careful handling of string list manipulation to avoid memory leaks.

This is a focused, well-tested addition to the config-based hook system that follows established Git configuration patterns. The change is relatively small but provides important consistency with how other multi-valued config options work in Git.
