This is a refactoring patch that's part of the ongoing `the_repository` removal effort, specifically targeting commit creation APIs. It's the first in a 3-patch series by Tian Yuchen to migrate encoding-related functionality from global variables to repository-specific storage.

The patch modifies core commit creation functions (`commit_tree()` and `commit_tree_extended()`) to take a `struct repository*` parameter, plumbing this context through 13 files including builtins like `commit`, `merge`, and `rebase`. The changes are mechanical - adding repository parameters and updating call sites - with no functional changes intended. Unconverted callers fall back to `the_repository` temporarily.

Key technical points for future reference:
- Adds `struct repository*` parameter to commit creation APIs
- Updates call sites across multiple builtins and subsystems
- Maintains backward compatibility via `the_repository` fallbacks
- Touches commit creation paths in sequencer, stash, notes, and replay
- Prepares ground for subsequent encoding migration patches

The patch follows established patterns for global variable migration and appears well-scoped, though it will need verification that all commit display paths properly handle NULL repository cases. This is part of Tian Yuchen's GSoC 2026 proposal work on global state libification.
