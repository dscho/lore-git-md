This is a discussion about refactoring editor configuration as part of the ongoing `the_repository` removal effort. Burak Kaan Karaçay responds to Phillip Wood's skepticism about making editor settings repository-specific, arguing that while users rarely need different editors per repo, the libification of Git requires consistent handling of all configuration.

Burak makes two key points: First, that Git currently has no system-wide-only configuration settings, so treating `core.editor` differently would be inconsistent. Second, that if the setting remains global while allowing per-repo configuration, it could cause problems when libgit interacts with multiple repositories having different editor settings.

The exchange highlights a tension between practical user behavior (where per-repo editors are uncommon) and architectural purity (where global state complicates libification). Burak suggests that if we want to keep editor settings process-wide, we should explicitly prohibit local configuration of `core.editor` - otherwise the current hybrid approach creates potential for confusion.

This reply advances the thread by directly addressing Phillip's concerns while maintaining the technical case for repository-specific handling, though it doesn't yet propose concrete code changes. The discussion remains focused on design principles rather than implementation details.
