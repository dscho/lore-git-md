This is a follow-up in the thread about `git log`'s decoration behavior, where Junio C Hamano (the Git maintainer) is responding to Marc Branchaud's analysis. The discussion has reached consensus that `--decorate=no` should consistently suppress all decoration output, including when using the `%d` format placeholder.

Junio indicates he's now convinced by Marc's argument that the current behavior is inconsistent and that making `--decorate=no` affect `%d` would be a logical improvement. He's willing to proceed with the change, though cautiously - planning to let it bake in the 'next' integration branch longer than usual to catch any potential issues before it reaches a release.

This represents the maintainer's approval for the proposed behavior change after thorough technical discussion. The patch implementing this will need to modify `pretty.c` to make the decoration suppression consistent, along with corresponding documentation updates. Junio's cautious approach reflects Git's conservative stance on behavior changes, even when they appear safe.
