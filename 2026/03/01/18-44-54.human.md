This is part of Adrian Ratiu's ongoing series to implement config-based hooks (v3, patch 6/12). The patch adds a `hook.<friendly-name>.enabled` configuration option that defaults to true, allowing users to disable hooks without removing their configuration - particularly useful for temporarily disabling global hooks in a specific repository.

The implementation introduces a `disabled_hooks` string list in the config parsing callback to track disabled hooks, which are then filtered out when building the hook config map. The patch includes comprehensive tests covering basic disabling, interaction with `git hook list`, and the ability to override global disable settings locally.

This follows Patrick Steinhardt's suggestion and builds on the config parsing infrastructure established in earlier patches. The change maintains the series' pattern of thorough test coverage while keeping the implementation clean and focused. With this addition, the config-based hook system gains an important usability feature for managing hook activation.
