This is part 10/12 of Adrian Ratiu's config-based hooks series, a refactoring patch that prepares for future additions to the hook configuration system. The patch replaces the direct `strmap` storage in the repository's hook config cache with a named `struct hook_config_cache` wrapper, and changes the command string storage from a simple `char*` util pointer to a dedicated `struct hook_config_cache_entry`.

The change is purely structural with no behavior modifications - it creates room to add more metadata to hook configurations in subsequent patches. The patch carefully maintains all existing functionality while introducing the new types, including proper memory management for both in-repo and out-of-repo cases. 

Review feedback from Patrick Steinhardt led to using `CALLOC_ARRAY` for allocations and keeping the cache management clean. The patch follows the series' established patterns while making the internal structures more explicit and extensible. With the core approach already agreed upon in earlier reviews, this incremental step keeps the series moving toward completion of the config-based hooks feature.
