Here's a human-readable summary of the thread so far:

Wolfgang Faust has proposed a UI improvement for git-gui that would visually distinguish commit message comment lines (those that will be stripped from the final message) by displaying them in gray. The initial implementation uses Tcl/Tk text widget tags with a regex pattern matching the same lines as git's commit message processing.

Johannes Sixt (Hannes), the git-gui maintainer, has reviewed the patch and generally supports the concept of graying out comment lines rather than highlighting them, as this better communicates what will be stripped. However, he suggested several technical improvements to the Tcl implementation: simplifying the regex pattern by using line-based matching, restructuring the code to avoid nested list indexing, and reusing computed indices more efficiently. Hannes also noted some formatting issues with the patch submission and recommended using Gitgitgadget for future contributions.

The discussion is currently focused on refining the Tcl implementation details while maintaining the core improvement - clearer visual feedback during commit message composition. The changes would help git-gui users better understand which parts of their draft messages will be included in the final commit.
