brian m. carlson weighs in with a practical perspective from Git LFS's needs, arguing that both absolute and relative path formats should be available. While `git rev-parse` allows switching formats between invocations, this approach wouldn't work well with `git repo-info`'s single-call model.

The discussion builds on previous consensus about using a global `--path-format` flag (Option 1 from the original proposal) while acknowledging the limitation that mixed-format output in a single `--all` call isn't possible. brian's input reinforces the real-world need for both formats while highlighting platform-specific challenges that make Git's canonical paths particularly valuable for tooling integration.
