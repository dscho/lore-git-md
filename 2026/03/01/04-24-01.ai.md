This is a follow-up discussion in an ongoing thread about adding path-related fields to `git repo-info`. The email from Tian Yuchen responds to Lucas Seiki Oshiro's patch series that introduced `path.toplevel` field support.

Tian raises several technical concerns about the implementation:

1. **Path Formatting Design**: Suggests considering format modifiers (similar to `git-for-each-ref`) for more precise path output control, proposing syntax like `%(path:relative)` and `%(path:absolute)`.

2. **Function Scope**: Questions whether `strbuf_add_path()` should handle path formatting logic, arguing this may be too high-level for a generic string concatenation function. Notes that other `strbuf_add*` functions are more basic.

3. **Performance**: Flags potential performance issues with repeated `xgetcwd()` calls when processing multiple submodules, suggesting the prefix should be computed once at a higher level.

4. **API Design**: Critiques the approach of adding `prefix` and `format` parameters to all `get_*` functions, even when unused (like `get_object_format`). Suggests this may not scale well as more fields are added.

The email maintains a constructive tone while challenging some architectural choices, positioning itself as exploratory discussion ("just throwing out ideas"). It builds on the thread's established context of standardizing path handling between `repo-info` and `rev-parse`, but pushes back on specific implementation details that could affect future extensibility.

Key technical points referenced:
- Existing `print_path` function from `rev-parse`
- `PATH_FORMAT_*` enums for path formatting
- `strbuf_add_path()` implementation
- Performance implications of `xgetcwd()`
- The patch's changes to `get_value_fn` signature

The discussion appears to be transitioning from initial implementation to design refinement, with multiple contributors (including GSoC participants) now engaging with the code structure. Tian's comments suggest the path handling infrastructure may need further iteration before serving as a stable foundation for additional fields.
