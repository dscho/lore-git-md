This is part 11 of Adrian Ratiu's config-based hooks series, adding scope visibility to configured hooks. The patch implements a `--show-scope` flag for `git hook list` that displays where each hook was defined (local, global, or system config), matching the behavior of `git config --show-scope`.

The change stores the config scope during the initial config parsing pass and carries it through to the hook cache. When `--show-scope` is used, the output shows the scope in parentheses after each hook name, while traditional filesystem hooks remain unaffected. The implementation maintains backward compatibility - without the flag, the output remains identical to previous versions.

The patch includes thorough test coverage verifying both the new scope display and the unchanged behavior when the flag isn't used. It builds on the series' existing config parsing infrastructure while keeping the scope tracking lightweight. This provides users with visibility into hook origins without complicating the core hook execution logic.

As with previous patches in this well-reviewed series, the change is cleanly implemented and follows established patterns. It addresses Junio Hamano's suggestion for scope visibility while maintaining the careful separation between config-based and filesystem hooks that has been a key design principle throughout the series.
