This is a discussion thread about refactoring editor configuration as part of the `the_repository` removal effort. Tian Yuchen weighs in on the debate between Shreyansh Paliwal and Burak about whether editor settings should remain process-wide or become repository-specific.

Yuchen argues strongly for repository-specific editor configuration, pointing out that Git already allows per-repository `core.editor` settings via local config. They provide concrete examples where users might reasonably want different editors for different repositories (e.g., vim vs nvim, different configurations for different languages). The email suggests storing `editor_program` in `repo-settings.c` would both eliminate global state and maintain early config validation.

The discussion highlights a tension in the `the_repository` removal effort: while eliminating globals is the goal, some settings may genuinely be process-wide in nature. Editor configuration sits at this boundary - technically configurable per-repo but often treated as a user preference. Yuchen's position challenges Phillip Wood's earlier argument that editor settings are inherently process-wide.

Key technical points raised:
- Current patch only moves the global rather than eliminating it
- Local config already allows per-repo editor settings
- Early validation could be preserved via `prepare_repo_settings()`
- Use case presented for different editors in different repos/submodules)

This moves the discussion forward by providing concrete user workflows that favor repository-specific behavior, potentially shifting the consensus away from the process-wide approach. The suggestion to use `repo-settings.c` offers a specific implementation path that addresses both state elimination and validation concerns.
