This is patch 5/12 in Adrian Ratiu's config-based hooks series, implementing the core functionality to read hooks from Git configuration. The patch teaches Git to parse `hook.<friendly-name>.command` and `hook.<friendly-name>.event` config entries, allowing hooks to be defined in config files while maintaining backward compatibility with traditional filesystem hooks.

The key technical additions include:
- A strmap cache in struct repository to avoid re-reading configs on each hook run
- Support for multiple commands per hook event, executed in config parse order
- Documentation explaining the new config syntax and usage patterns
- Comprehensive test coverage in t1800-hook.sh for config-based hook ordering and execution

The implementation runs configured hooks before traditional hooks from the hookdir, with each hook receiving the same way as before. The patch includes examples showing how to migrate from filesystem hooks to config-based ones and how wrappers can leverage the new system for custom hook events.

This is a significant step in the series, establishing the core infrastructure that subsequent patches will build upon. The implementation follows established patterns from earlier patches in the series, with careful attention to allocation/cleanup and clear API boundaries. Review feedback from Junio Hamano and Patrick Steinhardt has been incorporated, particularly around config parsing efficiency and memory management.
