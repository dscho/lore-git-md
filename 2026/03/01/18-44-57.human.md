This is part 9/12 of Adrian Ratiu's config-based hooks series, adding a `-z` option to `git hook list` for NUL-terminated output. The change allows handling hook names containing unusual characters like newlines, addressing a suggestion from Patrick Steinhardt.

The patch modifies the documentation, implementation, and tests to support the new option. The `-z` flag makes the command output hook names separated by NUL bytes instead of newlines, following Git's convention for machine-readable output. Test coverage verifies both traditional and configured hooks work correctly with the new option.

This is a straightforward addition to the hook listing functionality that maintains consistency with Git's existing `-z` conventions (seen in commands like `ls-files`). The implementation is cleanly integrated with the existing hook infrastructure from earlier patches in the series.
