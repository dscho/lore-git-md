This is a bugfix patch addressing submodule fetching behavior that incorrectly assumes all submodule remotes are named "origin". The patch is the final v4 version of a series that has gone through thorough review, with all feedback incorporated.

The fix introduces a new submodule helper command `get-default-remote` that properly handles submodules with differently-named remotes. This allows `git fetch --recurse-submodules` to work correctly when submodules use custom remote names. The implementation maintains backward compatibility by falling back to "origin" if default remote detection fails.

The patch includes comprehensive test coverage across multiple test files (t5526-fetch-submodules.sh, t5572-pull-submodule.sh, and a new dedicated test file t7426-submodule-get-default-remote.sh). The tests demonstrate the fix works for various scenarios including nested submodules and submodules with multiple remotes.

Review history shows this has been carefully vetted, with Junio Hamano and Jacob Keller providing feedback that has been addressed in the final version. The patch resolves a 7-year-old NEEDSWORK comment from commit be76c21282 and handles real-world use cases like the "repo" tool. The implementation is now clean and ready for integration, with all test portability issues and style concerns resolved.
