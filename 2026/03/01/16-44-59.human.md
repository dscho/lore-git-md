This is a feature patch introducing a new `fetch.blobSizeLimit` config option to enable partial clone behavior by default. The patch comes from Alan Braithwaite and appears to be a first iteration (v1).

The change allows users to configure a size threshold (like "1m" or "100k") that automatically applies a `--filter=blob:limit=<size>` during clone and fetch operations. This means blobs exceeding the limit won't be downloaded initially, but fetched on demand when needed. The motivation is to provide a more discoverable and convenient alternative to manually specifying `--filter` on every command.

The implementation touches both `builtin/clone.c` and `builtin/fetch.c` to handle the new option, with clear precedence rules: explicit `--filter` flags override the config, as do existing `remote.<name>.partialclonefilter` settings. The patch includes thorough tests in `t/t5616-partial-clone.sh` covering the basic functionality, precedence rules, and interaction with existing partial clone setups.

The change looks well-considered and cleanly implemented, with good test coverage. It addresses a real usability pain point for partial clones while maintaining backward compatibility. The documentation clearly explains the behavior and precedence. This seems like a useful quality-of-life improvement for users working with repositories containing large binary files.
