Subject: [PATCH 0/2] refactor editor.c to remove global state  
Author: Shreyansh Paliwal  
Thread type: refactoring (the_repository removal effort)  

Core problem: Refactoring editor.c to eliminate global state as part of project-wide the_repository removal, specifically addressing editor_program variable and sequence editor dependencies. Debate continues about process-wide behavior (Shreyansh/Phillip) versus repository-specific lookups (Burak/Tian/Karthik), with ongoing discussion about incremental approaches and libification tradeoffs.  

Current status: Karthik Nayak has approved Shreyansh's patch that removes `the_repository` usage from `git_sequence_editor()`, marking progress in the mechanical dependencies while the higher-level architectural debate remains open. The patch properly passes a `struct repository*` through callers (rebase-interactive.c) while temporarily keeping `the_repository` in builtin/var.c. This removes the last `USE_THE_REPOSITORY_VARIABLE` define from editor.c.  

Key technical details:  
- Current implementation makes editor_program static in editor.c with set_editor_program()  
- git_sequence_editor() now takes explicit struct repository* (used properly in rebase-interactive.c)  
- builtin/var.c still uses the_repository as temporary measure  
- Tian's proposal to store editor_program in repo-settings.c via prepare_repo_settings() remains pending  
- Burak's identification of core.editor local config capability despite global behavior still relevant  
- Karthik's suggested intermediate step (isolate global first) being followed  
- Changes affect editor.[ch], environment.[ch], builtin/var.c, rebase-interactive.c  
- Part of Google Summer of Code project  

Open questions: Architectural tension remains between immediate practicality (rare per-repo editor needs) and long-term libification goals (clean configuration model). Burak's concern about configuration model consistency if core.editor remains global while other settings become repository-specific still needs resolution. The approved patch doesn't address the core editor_program storage debate.  

Participant positions:  
- Shreyansh: defends process-wide behavior as natural for editor settings  
- Burak: maintains repository-specific lookups for config model consistency, emphasizes libification needs  
- Phillip: questioned practicality of per-repo editors, favoring process-wide  
- Tian: strongly supports repository-specific with repo-settings.c solution  
- Karthik: approved mechanical removal patch while broader discussion continues, previously proposed isolating global first  

Related work: Part of larger the_repository removal project. Similar architectural tradeoffs have appeared in other subsystems during global state elimination. The incremental approach here mirrors patterns seen in other refactorings where technical debt was reduced in stages. Karthik's approval signals this patch aligns with project direction despite unresolved higher-level questions.
