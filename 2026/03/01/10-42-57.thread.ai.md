Subject: [PATCH 0/2] refactor editor.c to remove global state
Author: Shreyansh Paliwal
Thread type: refactoring (the_repository removal effort)

Core problem: Remove remaining global state in editor.c as part of ongoing project-wide elimination of the_repository variable, specifically targeting editor_program variable and sequence editor functionality dependencies.

Current status: Initial patch series moves editor_program from environment.c to editor.c with new set_editor_program() helper and eliminates the_repository usage in sequence editor. Burak Kaan Karaçay has proposed an alternative approach that would eliminate the editor_program global entirely by looking up config at editor startup time.

Key technical details:
- Current patches move editor_program from environment.c to static in editor.c with controlled access via set_editor_program()
- git_sequence_editor() now takes explicit struct repository* parameter
- Burak's suggestion would replace static editor_program with repo_config_get* lookups when needed
- Tradeoffs: current approach maintains early config error checking while Burak's would eliminate global state more completely but delay error detection
- Changes currently limited to editor.[ch], environment.[ch], builtin/var.c, rebase-interactive.c
- Part of Google Summer of Code project

Open questions: Whether to accept current incremental approach or pursue Burak's more thorough global state elimination. Need to evaluate tradeoffs between early error checking and complete state removal.

Participant positions: Shreyansh submitted initial patches following established refactoring patterns. Burak proposed alternative approach that would eliminate global state more completely. No other reviews or positions expressed yet.

Related work: Part of larger the_repository removal project driven by René Scharfe and others. Similar mechanical relocations of globals have been proceeding across codebase. Discussion mirrors broader architectural questions about state management in the project.
