Subject: [PATCH 0/2] refactor editor.c to remove global state  
Author: Shreyansh Paliwal  
Thread type: refactoring (the_repository removal effort)  

Core problem: Refactoring editor.c to eliminate global state as part of project-wide the_repository removal, specifically addressing editor_program variable and sequence editor dependencies. Debate centers on whether to maintain process-wide behavior (Shreyansh/Phillip) or implement repository-specific lookups (Burak/Tian).  

Current status: Initial patches move editor_program to editor.c with controlled access but don't fully eliminate global. Tian Yuchen's new arguments for repository-specific configuration challenge Phillip Wood's earlier process-wide position, citing existing per-repo core.editor support and concrete multi-editor workflows.  

Key technical details:  
- Current implementation makes editor_program static in editor.c with set_editor_program()  
- git_sequence_editor() takes explicit struct repository* but doesn't use it for config  
- Tian proposes storing editor_program in repo-settings.c via prepare_repo_settings()  
- Existing local config already allows per-repo core.editor settings  
- Use cases presented for different editors in different repos/submodules  
- Changes affect editor.[ch], environment.[ch], builtin/var.c, rebase-interactive.c  
- Part of Google Summer of Code project  

Open questions: Whether to maintain early validation with process-wide behavior (current approach) or fully eliminate global state via repository-specific lookups while preserving validation through repo-settings. Tian's concrete examples may shift consensus toward per-repo approach.  

Participant positions:  
- Shreyansh: defends process-wide behavior as natural for editor settings  
- Burak: originally advocated repository-specific lookups  
- Phillip: questioned practicality of per-repo editors, favoring process-wide  
- Tian: strongly supports repository-specific with examples and repo-settings.c solution  

Related work: Part of larger the_repository removal project. Similar architectural tradeoffs have appeared in other subsystems during global state elimination. Tian's arguments parallel discussions about other user-configurable settings during this effort.
