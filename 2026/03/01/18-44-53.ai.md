This is patch 5/12 in Adrian Ratiu's config-based hooks series, implementing the core functionality to read hooks from Git configuration. The patch teaches Git to parse `hook.<friendly-name>.command` and `hook.<friendly-name>.event` configurations, running them in config order before any traditional filesystem hooks.

The implementation introduces a strmap cache in struct repository to avoid re-reading configs on each hook run, which is particularly important for frequently-run hooks like ref-transaction. Hooks can be shared across repositories by specifying absolute paths in the config, and multiple commands can be configured per event. The traditional hookdir hook runs last if present.

The patch includes comprehensive documentation explaining the configuration format and behavior, plus extensive test coverage in t1800-hook.sh verifying config ordering, path resolution, stdin handling, and error cases. Review feedback from Patrick Steinhardt and Junio Hamano has been incorporated, including proper use of CALLOC_ARRAY and BUG() checks.

This represents the main architectural piece of the config-based hooks functionality, with subsequent patches in the series building on this foundation. The implementation maintains backward compatibility while providing a more flexible hook configuration system. The strmap cache design follows established patterns in the codebase and includes proper cleanup via hook_cache_clear().
