This is a follow-up in the GSOC proposal thread about improving disk space recovery in partial clones, specifically addressing Derrick Stolee's technical guidance. Amisha Chhajed responds to Stolee's suggestion to focus on temporal (age-based) rather than spatial (sparse-checkout cone-based) criteria for object cleanup.

The key new proposal is a user-driven `git evict` command that would allow explicit control over which objects to remove, with options like `--older-than=30.days` or `--outside-cone`. This contrasts with Stolee's implicit suggestion of integrating with `git gc`/`git maintenance` for automatic cleanup. The email highlights the tension between automated background cleanup (which risks unexpected re-downloads from tools like VS Code's background `git blame`) versus explicit user control.

Technical considerations in play include: the object lifecycle management interface (new command vs existing maintenance), criteria for safe removal (temporal access patterns vs spatial location), and the disk-vs-network tradeoff when tools might re-request evicted objects. The thread remains open on whether this functionality should live in core maintenance or as a separate user-facing operation.
