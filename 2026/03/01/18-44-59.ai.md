This is part 11/12 of Adrian Ratiu's config-based hooks series, adding scope visibility to configured hooks. The patch implements `--show-scope` for `git hook list`, displaying where each hook was defined (local, global, system config) while maintaining backward compatibility with filesystem hooks.

The key technical changes:
- Stores config scope during the config callback phase in `hook_config_lookup_all()`
- Carries scope through the cache via `hook_config_cache_entry`
- Adds `scope` field to `struct hook`'s configured variant
- Implements `--show-scope` flag that mirrors `git config --show-scope` behavior
- Maintains identical output format when flag is not used
- Adds comprehensive coverage in t1800-hook.sh

The implementation follows Junio Hamano's suggestion and builds on the series' existing config parsing infrastructure. The scope information flows naturally through the existing cache mechanism without requiring new allocations. Traditional filesystem hooks remain unaffected since they don't originate from config.

This patch represents a logical extension of the config-based hooks functionality, providing users visibility into hook definitions while keeping the core behavior cleanly separated from filesystem hooks. The test coverage verifies both the new scope display and backward compatibility.
