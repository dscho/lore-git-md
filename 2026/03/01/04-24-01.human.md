This is a follow-up discussion on a patch series that added path-related fields to `git repo-info`, specifically focusing on the implementation of `path.toplevel`. The thread has transitioned from initial implementation to design considerations for future extensions.

Tian Yuchen raises several thoughtful points about the current approach:

1. **Format Modifiers**: Suggests exploring ref-filter style format modifiers (`%(path:relative)`, `%(path:absolute)`) as an alternative to the current `--path-format` flag, which could provide more flexible output control.

2. **Function Design**: Questions whether `strbuf_add_path()` should handle path formatting concerns, arguing that string buffer functions should remain simple concatenation operations without higher-level formatting logic.

3. **CWD Performance**: Notes potential performance issues with repeated `xgetcwd()` calls when processing many submodules, suggesting the caller should manage the current directory prefix.

4. **API Design**: Expresses concern about adding path-related parameters to all `get_*` functions, even when unused, as seen in functions like `get_object_format()`.

The discussion reflects active engagement from multiple contributors, with Tian building on Lucas Seiki Oshiro's original work while proposing alternative approaches. The thread shows healthy technical debate about API design and performance considerations, though no clear consensus has emerged yet. The core functionality appears stable, with the conversation now on how best to extend it.
