This is the first patch in Adrian Ratiu's v3 series implementing config-based hooks, focusing on internal state management for hook callbacks. The patch introduces alloc/free helpers for hook callback data structures, enabling proper memory management when multiple hooks run in sequence or concurrently.

The key technical change moves from stack-allocated state structures to dynamically allocated ones, preparing for future parallel execution support. Each hook type (reference-transaction, pre-push, receive-pack) gets its own alloc/free pair that properly initializes and cleans up the callback-specific data structures. The patch enforces that alloc/free functions must be provided together through a BUG() check.

The implementation standardizes on `CALLOC_ARRAY()` for allocations and adds designated initializers for clarity. The changes touch several hook implementations while maintaining their existing behavior. This foundational work enables the subsequent patches in the series to safely manage multiple hook commands per event.

Review feedback from Patrick Steinhardt and Junio Hamano has been incorporated, particularly around memory management patterns and API documentation. The patch represents a clean separation of concerns between the core hook runner and individual hook implementations' state management needs.
