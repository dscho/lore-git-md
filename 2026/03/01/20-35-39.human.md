This is the third patch in Tian Yuchen's series to migrate encoding-related functionality from global variables to repository-specific storage, part of the ongoing `the_repository` removal effort. The patch moves the encoding configuration variables (`git_commit_encoding` and `git_log_output_encoding`) directly into `struct repository` rather than the previously considered `repo_settings` approach, following feedback from Phillip Wood. 

The changes are mechanical but widespread, updating over 50 call sites across commit handling, mail operations, revision walking, and builtin commands to use the new repository-aware APIs (`repo_get_commit_output_encoding()` and `repo_get_log_output_encoding()`). The config parsing still temporarily uses `the_repository` due to the complexity of plumbing repository pointers through the config callback machinery.

The patch maintains backward compatibility by falling back to `the_repository` for unconverted callers, and the test suite passes with sanitizers. This appears to be a well-executed refactoring that follows established patterns for global variable migration, though reviewers will likely want to verify edge cases around NULL repository handling in commit display paths.
