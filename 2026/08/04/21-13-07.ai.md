This is the first patch in the v2 RFC series for `git repack --drop-filtered`, now updated to fix a subtle validation bug in the bitmap-handling logic. The patch adds the `--drop-filtered` and `--dry-run` options to `git repack`, enforces their invariants, and ensures they interact correctly with existing repack flags, but does not yet perform the actual object enumeration or deletion.

The key change in this revision is a fix for the bitmap validation logic: the original code failed to detect when a user explicitly passed `-b` (or `--write-bitmap-index`) on the command line if `repack.writeBitmaps` was already true in the config. The updated patch now correctly rejects such explicit `-b` usage with `--drop-filtered`, while still silently disabling config-driven bitmaps for the duration of the command. This distinction is important because `--drop-filtered` breaks the pack closure that bitmaps require, so explicit `-b` is a hard conflict, whereas config-driven bitmaps can be temporarily overridden.

The patch remains well-scoped: it defers the actual object walking and deletion to later patches, but the validation layer is now complete and tested. The new test script (`t/t7706-repack-drop-filtered.sh`) covers all the error cases, including the bitmap validation fix. This is a solid foundation for the rest of the series, and the safety checks here address the critical feedback from v1.
