This thread is about a patch by Tim Wiederhake that adds user-configurable custom commands to `gitk`'s context menus, allowing workflows like editing a specific line at a point in history. The patch is self-contained to the `gitk` Tcl/Tk frontend and has been under review since its submission, but progress has been blocked on process issues: the maintainer, Johannes Sixt, required the commit message to include the feature's motivation and the author to confirm they reviewed and understood every line of the AI-assisted code.

The thread took a sharp turn with Junio C Hamano's recent review, which uncovered a critical security flaw in the command substitution mechanism. The patch fails to quote or sanitize placeholders (like commit titles or messages) when interpolating them into shell commands, creating a vector for arbitrary command injection. Junio demonstrated how a malicious commit title could execute unintended commands, raising serious concerns about the feature's safety. This is now the primary blocker, overshadowing the earlier process issues. The author must address this by either quoting interpolated values, avoiding shell execution, or restricting placeholder usage. Until then, the patch remains stalled, with no technical review of other aspects of the implementation.
