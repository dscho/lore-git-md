This thread is about adding user-configurable custom commands to `gitk`'s context menus, allowing workflows like editing a specific line at a particular point in history. The author, Tim Wiederhake, proposes a generic extension system where users define commands with placeholder substitutions (e.g., file, line, commit ID), while the `gitk` maintainer, Johannes Sixt, prefers an incremental approach starting with a minimal use case (e.g., "open an editor at this line") and deferring advanced functionality.

The discussion is currently stalled on two key issues: **design scope** and **security**. Tim argues that splitting the feature into smaller pieces would create a half-usable system, as the substitutions are interdependent parameters of a single mechanism. Meanwhile, Sixt insists on incremental implementation for reviewability. Additionally, Junio C Hamano identified a critical security flaw—unquoted shell command substitution allows arbitrary command injection via malicious commit metadata—which Tim acknowledges but has not yet fixed. A secondary policy question about AI-assisted code (Tim used Claude to generate Tcl from his design) remains unresolved, though Tim maintains he reviewed and understood every line.

The patch touches only the `gitk` Tcl script and stores configuration in `~/.gitk`. No prior versions exist, and no substantive technical review beyond the security critique has occurred. The thread’s tone is constructive but unresolved; progress depends on aligning on scope and addressing the security concern. If these blockers are resolved, the feature could move forward, though the AI policy question may attract broader discussion.
