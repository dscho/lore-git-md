This thread is about adding user-configurable custom commands to `gitk`'s context menus, allowing workflows like editing a file at a specific point in history. The feature is designed as a generic extension system with placeholder substitution (file, line, commit ID, etc.) and shell execution, configured via a new "Commands" tab in preferences.

The patch, submitted by Tim Wiederhake, is currently blocked on four fronts. The most critical is a confirmed security flaw: unquoted shell command substitution allows arbitrary command injection via malicious commit titles or messages (e.g., `title?'; echo no'`). Junio Hamano provided an exploit example, and Tim is evaluating fixes—either reverting to direct command execution (requiring wrapper scripts for advanced use) or implementing proper escaping. The maintainer, Johannes Sixt (Hannes), has also rejected the monolithic implementation, insisting on an incremental approach starting with a minimal use case (e.g., editor integration with `%f` substitution) before adding more placeholders. Tim argues the feature must be complete to be useful, while Hannes counters that even a single placeholder delivers immediate value and aligns with the project’s review process. Additionally, Hannes has raised concerns about whether Tim’s iterative reworking of AI-generated code meets the project’s requirement that authors "review and understand every line," though this policy question remains unanswered by the community.

The thread is now at an impasse over design scope, with no resolution in sight on either the security flaw or the incremental vs. complete implementation debate. No substantive technical review beyond the security critique has occurred, and the patch remains confined to the `gitk` Tcl script with no test coverage. Key participants—Tim, Hannes, and Junio—have staked out firm positions, leaving the feature’s future uncertain.
