This is a user support question from Randall S. Becker about a change in Git’s textconv behavior. Since Git 2.50, external textconv filters receive an empty temporary file (`/tmp/git-blob-*/<name>`) instead of the actual file from the working tree. Randall reports that this breaks his workflow when multiple files share the same name, as the filter can no longer locate the correct file. He asks whether this is intentional or if he’s missing a configuration detail.

The question suggests a potential regression or undocumented behavior change in textconv. No patch or code is proposed—this is purely a request for clarification. If the change is confirmed as intentional, it may warrant a documentation update or a workaround in the release notes. For now, this is a heads-up for maintainers and users who rely on textconv filters.
