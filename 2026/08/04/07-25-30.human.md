This is the second patch in Patrick Steinhardt’s seven-patch series refactoring the object database (ODB) streaming API. It removes the `is_finished` field from `struct odb_write_stream`, a small but meaningful step toward unifying the read and write stream APIs.

The change is straightforward: instead of tracking completion state inside the stream structure, callers now infer it from the return value of `odb_write_stream_read()` (zero bytes means done). The patch updates all callers to handle this logic locally, with one notable adjustment in `builtin/unpack-objects.c` where a loop ensures at least one byte is produced before yielding. The diff touches seven files, including core ODB backends (`odb/source-inmemory.c`, `odb/source-loose.c`), object handling (`object-file.c`), and the unit test for the in-memory backend.

This is a clean, mechanical refactor with no behavior changes. The commit message clearly explains the rationale—eliminating redundant state tracking—and the implementation is consistent with the series’ goal of aligning the write stream’s design with the read stream. Reviewers may focus on edge cases (e.g., ensuring the loop in `unpack-objects.c` doesn’t mask errors), but the patch itself looks solid and uncontroversial. It’s a natural follow-up to the first patch (which embedded the stream size in the structure) and sets the stage for the later unification of the two stream types.
