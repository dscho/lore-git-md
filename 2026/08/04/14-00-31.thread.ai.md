Core problem or goal
Fix a regression in `git worktree add` where the `-b` or `-B` options were ignored when a branch name could be DWIMmed to a remote-tracking branch. The intended behavior is that explicit `-b` or `-B` should take precedence over DWIM, preventing unintended branch creation.

Current status
Patch posted (v2); incorporates Junio C Hamano’s feedback from v1. The revised patch preserves warning behavior when `-b` is used with `HEAD` and refines the test case to remove redundant setup and validate the error message. No merge status reported; under review for final confirmation.
