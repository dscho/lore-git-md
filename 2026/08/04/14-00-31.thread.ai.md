Core problem or goal
Fix a regression in `git worktree add` where the `-b` or `-B` options were ignored when a branch name could be DWIMmed to a remote-tracking branch. The intended behavior is that explicit `-b` or `-B` should take precedence over DWIM, preventing unintended branch creation.

Current status
Patch posted (v1); under review. Junio C Hamano provided substantive feedback requesting changes to avoid unintended side effects (skipping `can_use_local_refs()` when `-b` is used with `HEAD` and preserving warning behavior). No merge status reported.

- On-disk format: unchanged.
- Test coverage: added one test case; Junio recommends improvements for precision.
