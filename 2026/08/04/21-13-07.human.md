This is the first patch in the v2 RFC series introducing `--drop-filtered` to `git repack` for partial clones. The patch adds the new command-line options `--drop-filtered` and `--dry-run` to `builtin/repack.c` and implements all validation logic, but does not yet perform object enumeration or deletion (that comes in later patches).

The key update here is a fix for a subtle edge case in the bitmap-handling logic. The original patch correctly distinguished between command-line and config-driven bitmap settings, but missed a scenario: if `repack.writeBitmaps` is already true *and* the user explicitly passes `-b`, the code would not error out, even though `--drop-filtered` and `--write-bitmap-index` are incompatible. Siddharth Asthana caught this in review, and the author acknowledges the oversight. This is a surface-level correction—no new functionality is added, but the validation layer is now more robust.

The rest of the patch remains unchanged: it wires up the options, enforces their invariants (e.g., `--drop-filtered` requires `--filter`, `-a`, and a promisor remote; `--dry-run` is only valid with `--drop-filtered`), and tests all error paths in the new `t/t7706-repack-drop-filtered.sh` script. The commit message and code structure are clear, and the patch sets a solid foundation for the rest of the series. The fix itself is small but important for correctness.
