This is the fourth patch in Pablo Sabater’s nine-patch GSoC series (v4) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch replaces the `struct object_info` used by `fetch_object_info()` with a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests (currently size, with type coming in a later patch). The design avoids sentinel values and boolean flags by using caller-controlled flags (`wants_size`) and separate arrays for each attribute; a non-NULL array means the attribute is both requested and available. The patch also drops the `object_info_options` string list, `remote_atom_map[]`, and `free_object_info_contents()`, simplifying the code and aligning with the protocol’s transmission of raw strings (e.g., `"blob"`, `"1234"`).

Key changes include:
- Introducing `struct fetch_object_info_results` and its initializer `FETCH_OBJECT_INFO_RESULTS_INIT`.
- Updating `fetch_object_info()` and `send_object_info_request()` to use the new struct and explicit `ask_size`/`wants_size` flags instead of string lists.
- Adding `free_fetch_object_info_results()` to release the allocated arrays.
- Converting the final `else` in `fetch_object_info()` to `die()` for protocol violations (unknown attributes), replacing a `BUG()`.
- Mechanical updates to `builtin/cat-file.c`, `transport.c`, and `transport.h` to use the new struct and flags.

The patch is a refactoring that prepares for the `%(objecttype)` support added in later patches (6/9 and 7/9). It touches `fetch-object-info.c`, `fetch-object-info.h`, `builtin/cat-file.c`, `transport.c`, `transport.h`, `object-file.c`, and `odb.h`, with no behavior changes or test coverage in this patch. The design follows the hybrid approach proposed by Junio and Peff in earlier reviews, and the implementation is clean and well-motivated. No open questions remain; the patch is ready for review.
