This is the first patch in the **v12 iteration of Harald Nordgren’s `git history squash` feature**, a refactoring that extracts a helper function to centralize logic for resolving a commit’s first-parent tree. The patch touches only `builtin/history.c` and makes no behavior changes—its sole purpose is to deduplicate code that appears in three places, each handling the same parse-and-copy dance for a commit’s parent tree (or the empty tree for root commits).

The new `first_parent_tree_oid()` helper takes a `struct repository *`, a `struct commit *`, and an output `struct object_id *`. It parses the first parent (if any), copies its tree OID to the output, and returns 0 on success or -1 on error. The three callers—`commit_tree_with_edited_message()`, `commit_became_empty()`, and `split_commit()`—are updated to use the helper, eliminating 32 lines of duplicated logic.

This is a clean, mechanical refactoring that prepares the ground for the later patches in the series. It is uncontroversial and aligns with Git’s coding guidelines for small, focused patches. The commit message is clear and the diff is straightforward, making it an easy candidate for review and integration. No substantive discussion is expected on this patch itself; any feedback will likely be surface-level (e.g., naming or style). The patch is a necessary precursor to the core functionality introduced in patch 4/4.
