Subject: [PATCH v3 0/4] completion: add git history
Series version: v3 (four-patch series)
Originating author: Vincent Mailhol
Thread type: patch series

Core problem or goal
Add comprehensive bash completion support for the `git history` command, covering its four existing subcommands (`drop`, `fixup`, `reword`, `split`) and the upcoming `squash` subcommand, along with their options, option values, and positional arguments. The completion must handle revision names, option-specific value completion (e.g., `--empty`, `--update-refs`), and pathspecs for the `split` subcommand after its first argument.

Current status
Under review; this is the third iteration of the series. The v3 series is split into four logical patches: (1) subcommand and option completion, (2) `--empty` value completion, (3) `--update-refs` value completion, and (4) pathspec completion for the `split` subcommand. The key technical improvement since v2 is the elimination of hard-coded option names in revision detection logic, replacing it with a more maintainable approach that ignores `<option> <value>` syntax. Tests now verify that options are not completed before a subcommand, that revision completion stops after the first required argument, and that edge cases like `--` argument termination and subcommand-specific pathspecs are handled. The series is ready for integration pending a trivial rebase to include the `squash` subcommand once it graduates from `seen`. No substantive objections remain from the prior review cycle.
