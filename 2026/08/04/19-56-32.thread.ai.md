Core problem or goal
Add bash completion support for the `git history` command, covering its four subcommands (`drop`, `fixup`, `reword`, `split`), their options, and positional revision arguments. The completion should handle both revision names and, for the `split` subcommand, pathspecs after the first argument.

Current status
Under review; no prior version recorded in this thread. Patrick Steinhardt’s substantive review and D. Ben Knoble’s surface-level endorsement both describe the patch as a clear improvement. Junio C Hamano’s maintainer comment notes the boilerplate duplication in the completion script and suggests a future refactoring into a shared helper, but does not block or request changes to the current patch. Vincent Mailhol’s follow-up defends the current per-subcommand structure as more maintainable for future extensions, illustrating with a sketch of how he would handle the `split` subcommand’s pathspec edge case. Patrick Steinhardt’s latest email requests a status update within a few days on whether Vincent plans to submit a v2 incorporating the `split` subcommand’s pathspec refinement, framing it as a procedural courtesy to help maintainers and reviewers plan, not as a demand for changes. The `split` subcommand’s pathspec handling remains a non-blocking refinement opportunity, and the patch will require a trivial rebase once the `squash` subcommand (currently in `seen`) lands.
