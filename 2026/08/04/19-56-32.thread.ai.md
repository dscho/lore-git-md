Series version: v3 (four-patch series)
Originating author: Vincent Mailhol
Thread type: patch series

Core problem or goal
Add comprehensive bash completion support for the `git history` command, covering its four existing subcommands (`drop`, `fixup`, `reword`, `split`) and the upcoming `squash` subcommand, along with their options, option values, and positional arguments. The completion must handle revision names, option-specific value completion (e.g., `--empty`, `--update-refs`), and pathspecs for the `split` subcommand after its first argument.

Current status
Under review; this is the third iteration of the series. The v3 series is feature-complete for the current `git history` subcommands, with all prior feedback incorporated. Patrick Steinhardt’s latest reply explicitly endorses the v3 series as a whole, stating he is "happy with this version" and considers it "a good base to build on," signaling readiness for integration. Junio C Hamano has confirmed he will integrate the series into `seen` and handle the trivial merge conflict with the in-flight `squash` subcommand (currently in `seen`) as an "evil merge" by adding `squash` to the test’s candidate list. The series is split into four logical patches: (1) subcommand and option completion, (2) `--empty` value completion, (3) `--update-refs` value completion, and (4) pathspec completion for the `split` subcommand. Key technical improvements since v2 include the elimination of hard-coded option names in revision detection logic, subcommand-aware value completion for `--empty` and `--update-refs`, and idiomatic pathspec completion for `split` using existing Git completion helpers. Tests verify subcommand/option ordering, revision completion termination, `--` argument handling, and pathspec behavior for `split`. The series is ready for integration pending the mechanical addition of the `squash` subcommand. No substantive objections remain. The cover letter formatting glitch noted by Kristoffer Haugsbakk (a line starting with `#3` misinterpreted as a comment by `b4`) is purely editorial and does not affect the patches themselves; Vincent Mailhol has confirmed the intended text and proposed to avoid `#` in future descriptions, but no v4 reroll is required. Key technical details
- Files touched: `contrib/completion/git-completion.bash` (implementation), `t/t9902-completion.sh` (tests).
- New or renamed symbols: `_git_history()` (completion function), `__git_history_has_revision()` (helper for revision detection).
- Behavior: Bash completion now supports `git history` subcommands (`drop`, `fixup`, `reword`, `split`, and soon `squash`), their options, option values (e.g., `--empty={drop,keep,abort}`, `--update-refs={branches,head}`), and positional arguments (revisions and pathspecs). The `split` subcommand’s pathspec completion is handled correctly after the first argument using `__git_complete_index_file --cached`, matching the behavior of other Git commands. The `__git_history_has_revision()` helper improves maintainability by dynamically ignoring `<option> <value>` pairs during revision detection. `--empty` and `--update-refs` value completion are restricted to supported subcommands and support only the documented `--<option>=<value>` form. Revision completion terminates after the first required argument, and `--` argument handling is preserved.
- On-disk format changes: none.
- Test coverage: expanded in `t/t9902-completion.sh` to verify subcommand/option ordering, revision completion termination, `--` argument handling, `split` subcommand pathspecs (before and after `--`), and `--empty`/`--update-refs` value completion for supported subcommands and values.
