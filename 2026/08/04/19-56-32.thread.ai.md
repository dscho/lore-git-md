Core problem or goal
Add bash completion support for the `git history` command, covering its four subcommands (`drop`, `fixup`, `reword`, `split`), their options, and positional revision arguments. The completion should handle both revision names and, for the `split` subcommand, pathspecs after the first argument.

Current status
Under review; no prior version recorded in this thread. Patrick Steinhardt’s substantive review and D. Ben Knoble’s surface-level endorsement both describe the patch as a clear improvement. Junio C Hamano’s maintainer comment notes the boilerplate duplication in the completion script and suggests a future refactoring into a shared helper, but does not block or request changes to the current patch. Vincent Mailhol’s follow-up defends the current per-subcommand structure as more maintainable for future extensions, illustrating with a sketch of how he would handle the `split` subcommand’s pathspec edge case. The `split` subcommand’s pathspec handling remains a non-blocking refinement opportunity, and the patch will require a trivial rebase once the `squash` subcommand (currently in `seen`) lands.

Key technical details
- Files touched: `contrib/completion/git-completion.bash`, `t/t9902-completion.sh`
- New symbols/functions: none (uses existing `__gitcomp_builtin` and `__git_complete_refs`)
- Behavior: completion of subcommands, options (e.g., `--update-refs=` for `fixup`), and revision names (e.g., `main`). For `split`, the first argument is a revision, but subsequent arguments are pathspecs, which should ideally complete as file paths rather than revisions.
- On-disk format: unchanged
- Test coverage: added in `t/t9902-completion.sh` for subcommands, options, and revision arguments. Pathspec completion for `split` is not yet covered.

Ben Knoble consider this a non-blocking improvement for a future iteration; D. Ben Knoble suggests modeling it after `_git_reflog` or `_git_config`. Vincent Mailhol’s follow-up sketches a possible implementation but does not commit to it.
2. The patch will need a trivial rebase to include the upcoming `squash` subcommand once it graduates from `seen`.
3. Junio C Hamano’s suggestion to refactor duplicated completion boilerplate into a shared helper is now countered by Vincent Mailhol’s argument that the current per-subcommand structure is more maintainable for future extensions. No concrete refactoring proposal has been made, and the discussion remains forward-looking.
