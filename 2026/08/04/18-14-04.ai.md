This is the fourth patch in Domen Kožar's v2 series introducing worktree lifecycle hooks, adding the `post-worktree-move` hook. The patch completes the series by addressing the gap identified in earlier discussion: tools that track worktree paths (e.g., AI-driven development environments) need a reliable way to update their state when a worktree is relocated, not just when it is created or destroyed.

The implementation is clean and consistent with the rest of the series. The hook runs in the new worktree directory with `GIT_DIR` and `GIT_WORK_TREE` cleared, receiving the old absolute path as its sole argument. This design allows a single configured command to handle all three worktree hooks by argument count: `post-worktree-add` (0 args), `post-worktree-move` (1 arg), and `post-worktree-remove` (2 args). The hook's exit status propagates to `git worktree move` but does not affect the operation's outcome, matching the behavior of the other two hooks.

The patch touches `builtin/worktree.c` (adding the hook invocation in `move_worktree`), updates `Documentation/config/hook.adoc` and `Documentation/githooks.adoc` to document the new hook, and adds thorough test coverage in `t/t2403-worktree-move.sh`. The tests verify both successful hook execution (checking argument and environment) and the behavior when the hook fails (ensuring the move is not undone). The commit message clearly explains the motivation, design choices, and edge cases, making it easy for reviewers to assess the patch without digging into the code.

This patch looks technically sound and well-integrated with the rest of the series. The hook signature is minimal but sufficient, and the implementation avoids introducing new edge cases. The only loose end from earlier discussion -- the relative order of `post-worktree-add` and `post-checkout` -- is not addressed here, but that is a separate concern from the move hook. The series as a whole now covers all three worktree lifecycle events (add, remove, move) and is ready for final review.
