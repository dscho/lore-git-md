This is a bug report about `git replay` and `git history` dropping Git notes during history rewriting.

D. Ben Knoble reports that both `git replay --onto=...` and `git history fixup` silently discard notes attached to commits, rather than preserving or migrating them to the rewritten commits. He notices the issue when reviewing `range-diff` output before pushing and recovers tip notes with `git notes copy @{1}`, but intermediate commits require more manual effort. The email asks whether notes are intentionally out of scope for these commands or if this is an unimplemented feature. No patch is included—this is purely a problem statement.
