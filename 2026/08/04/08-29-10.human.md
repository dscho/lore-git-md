This is the fifth and final patch in Patrick Steinhardt’s v2 series making the creation of on-disk object database (ODB) structures pluggable. It completes the architectural refactoring begun in earlier patches by moving the creation of backend-specific directories (`objects/pack`, `objects/info`) into the "files" ODB backend’s `create_on_disk` callback.

The patch is a clean, mechanical change that touches three files: `odb/source-files.c` (adding the callback implementation), `odb/source.h` (defining the callback interface), and `setup.c` (replacing hardcoded directory creation with a call to the new callback). The only exception is the top-level `objects/` directory, which remains mandatory for repository discovery and is still created unconditionally.

This is a well-motivated refactoring that aligns with the series’ overall goal of enabling custom ODB backends. The implementation is straightforward and the commit message clearly explains the rationale. The callback name (`create_on_disk`) was retained for consistency with the ref subsystem’s `ref_store_create_on_disk()`, despite Junio’s earlier suggestion to use a more generic term like `initialize`; this is a reasonable choice given the current scope.

No new open questions are introduced by this patch, and the changes are uncontroversial. The patch is ready for merging once the rest of the series stabilizes. It has no user-visible impact but is a critical enabler for future ODB backends that do not follow the traditional loose/pack layout.
