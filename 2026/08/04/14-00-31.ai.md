This is a bugfix for `git worktree add`. The patch addresses a regression introduced in Git v2.42.0 where the `-b` or `-B` options were incorrectly ignored when a branch name was provided that could be DWIMmed to a remote-tracking branch. The fix ensures that DWIM behavior is disabled when `-b` or `-B` is explicitly given, preventing the creation of a worktree with an unintended branch.

The change is minimal: a single condition is added to `builtin/worktree.c` to skip DWIM logic when `new_branch` is set, and a new test case in `t/t2400-worktree-add.sh` verifies the corrected behavior. The regression was introduced by commit 128e5496b325640f0a09cc1d5b1e346c069b410f, which the commit message explicitly references.

The patch is well-motivated and narrowly scoped, targeting a clear user-facing issue. The test coverage is appropriate, and the fix aligns with the expected behavior of `-b` and `-B` (i.e., they should take precedence over DWIM). No controversy is evident from the patch itself, though follow-up discussion might clarify edge cases or related behaviors.

Key technical details for future reference:
- Files touched: `builtin/worktree.c` (logic change), `t/t2400-worktree-add.sh` (test addition).
- Regression commit: 128e5496b325640f0a09cc1d5b1e346c069b410f.
- Test case: `add <path> <branch> does not dwim with -b`.
- Behavior change: DWIM is now suppressed when `-b` or `-B` is provided.
