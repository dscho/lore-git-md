This is a user support thread about a suspected regression in Git’s textconv feature, specifically affecting binary files on the NonStop platform.

Randall S. Becker reports that the issue is narrower than initially thought: textconv filters receive empty temporary files *only* when processing binary files, not text files or ELF binaries. On NonStop, binary files often begin with a null byte, which Randall suspects may be triggering the problem. This observation refines the scope of the regression to binary-file handling and suggests a possible root cause tied to how Git creates or populates temporary files for textconv filters when the input contains null bytes.

The thread remains diagnostic rather than solution-focused. Randall’s update clarifies the conditions under which the regression appears, but no one has yet proposed a fix, identified the commit that introduced the change, or confirmed whether the behavior is intentional. The discrepancy between Randall’s experience (empty temp files for binaries) and D. Ben Knoble’s (populated temp files even with `binary = true`) is still unexplained, leaving open questions about platform-specific behavior or configuration differences. For now, this looks like a niche but potentially disruptive issue for workflows that rely on textconv for binary files.
