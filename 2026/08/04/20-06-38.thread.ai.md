Thread identity
Subject: `git-replay` and `git-history` silently drop notes during history rewriting
Series version: none (standalone bug report)
Originating author: D. Ben Knoble
Thread type: bug report

Core problem or goal
`git-replay` (specifically `git replay --onto=...`) and `git-history` (specifically `git history fixup`) silently drop Git notes when rewriting commits. The reporter observes that only the tip commit’s notes can be manually recovered (`git notes copy @{1}`), while notes on intermediate commits are permanently lost. The thread seeks to clarify whether notes are intentionally out of scope for these commands or if this is an unimplemented feature.

Current status
Under review; no patches or detailed design discussion yet. Patrick Steinhardt has acknowledged the issue as an unimplemented feature for `git history` (user-facing) and a likely gap for `git replay` (plumbing). Phillip Wood has now proposed a design direction: a command-line option for `git replay` to enable note copying (not config-based), while `git history` should handle notes automatically. The shared implementation would reside in the history-rewriting codebase, allowing both commands to reuse it once the plumbing flag is exposed. A GitLab issue tracks the work for the next release cycle, but no assignee or timeline exists. Community contributions are invited.

Key technical details
- Commands affected: `git replay --onto=...`, `git history fixup` (and likely other `git-history` modes)
- Subsystems touched: notes, history rewriting (replay/history)
- Behavior: notes on rewritten commits are silently dropped; no warning or error is emitted
- Workaround: manual `git notes copy @{1}` recovers only the tip commit’s notes
- Distinction between user-facing (`git history`) and plumbing (`git replay`) commands noted; intent to address differs accordingly
- New symbols: proposed `--[no-]copy-notes` command-line option for `git replay` (not config-based)
- Implementation plan: shared note-copying logic in the history-rewriting codebase, reused by both commands
