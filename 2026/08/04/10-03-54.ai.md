This is the **behavior-changing patch** in Christian Couder’s 12-patch `git fast-import` libification series. It switches the command-line parser from a hand-written loop to the standard `parse_options()` API, completing the integration begun in earlier patches.

The patch **removes support for five undocumented options** (`--alias`, `--get-mark`, `--ls`, `--notes`, and `--cat-blob`) on the command line. These were previously accepted as no-ops because the old parser fell through to the in-stream feature parser. They are only meaningful inside the input stream, so the change aligns behavior with documentation. A new test (`t9300-fast-import.sh`) verifies that each of these options now fails when given on the command line.

Other user-visible changes are minor: abbreviated options like `--dep=5` now work (unambiguous prefixes), and error messages for some options may differ slightly. The code shrinks by 29 lines, replacing a bespoke loop with a single `parse_options()` call.

The patch is the **only one in the series that intentionally changes behavior**; everything else is preparatory refactoring. It touches only `builtin/fast-import.c` and the test suite, with no new symbols or on-disk format changes. CI results are clean except for a likely unrelated Windows+Meson failure. The series remains under review, awaiting broader feedback beyond Junio’s initial comments.
