This is a refactoring patch that prepares the sequencer’s squash-message helpers for reuse by `git history squash`. It extracts three static functions (`add_squash_combination_header`, `add_squash_message_header`, and `squash_subject_comment_len`) and the `todo_item_flags` enum from `sequencer.c` into `sequencer.h`, making them available to other commands. The patch is part of Harald Nordgren’s v12 series implementing `git history squash`, which is now functionally complete and ready for integration.

The extracted helpers standardize how Git formats squash commit messages: the combination banner ("This is a combination of N commits."), the per-commit headers ("This is the 1st commit message:" or "The commit message #2 will be skipped:"), and the logic for commenting out `fixup!`, `squash!`, or `amend!` subjects. By moving these to the header, the patch enables `git history squash` to present the same autosquash-style template as `git rebase -i`, ensuring consistency across Git’s history-editing commands. The `todo_item_flags` enum, which includes `TODO_REPLACE_FIXUP_MSG`, allows callers to distinguish between `amend!` and plain `fixup!` commits when processing the output of `todo_list_rearrange_squash()`.

The patch touches only `sequencer.c` and `sequencer.h`, with no behavior change. It is uncontroversial and a prerequisite for the core implementation in patch 4/4. The new public interface (`add_squash_combination_header`, `add_squash_message_header`, `squash_subject_comment_len`, and `TODO_REPLACE_FIXUP_MSG`) will be used by `git history squash` to build its default editor template. This refactoring is part of the series’ broader effort to align the new command with Git’s existing autosquash infrastructure.
