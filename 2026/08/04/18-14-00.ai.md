This is a feature patch series (v2) introducing four new Git hooks: `post-worktree-add`, `post-worktree-remove`, and `post-worktree-move`. The series is authored by Domen Kožar and targets the worktree subsystem. It directly addresses the thread's core goal: providing reliable automation triggers for worktree lifecycle events (creation, removal, and now also movement) to support high-velocity tooling, particularly AI-driven development environments that create and destroy worktrees frequently.

The v2 series incorporates feedback from Phillip Wood's substantive review of v1. Key changes include: (1) `post-worktree-add` now runs unconditionally after `post-checkout`, even if `post-checkout` fails, because the worktree remains present; (2) `post-worktree-add` no longer takes arguments (its working directory is the new worktree, so details like path and ID can be queried with Git commands); (3) a new `post-worktree-move` hook is added, which runs in the new location and receives the old absolute path as its sole argument. These changes simplify hook signatures and make it easier to share a configured command across all three hooks by distinguishing events by argument count.

The implementation touches `builtin/worktree.c`, `worktree.c`, and `worktree.h`, and adds comprehensive test coverage in `t/t2400-worktree-add.sh`, `t/t2401-worktree-prune.sh`, and `t/t2403-worktree-move.sh`. The hooks are documented in `Documentation/githooks.adoc` and registered in `hook-list.h` via `Documentation/config/hook.adoc`. The series is well-motivated and addresses a real gap in Git's automation story, particularly for tooling that manages ephemeral worktrees. The commit messages and cover letter clearly explain the design choices, including edge cases like hook ordering and path resolution during pruning.

One open question from v1 remains unaddressed: Phillip Wood's proposal to document the relative order of `post-worktree-add` and `post-checkout`. The v2 series does not add this documentation, though the behavior is now clear from the code (post-worktree-add runs after post-checkout, even if the latter fails). The new `post-worktree-move` hook is a direct response to Phillip's suggestion in v1, though Domen did not explicitly acknowledge it in the cover letter.

The series looks technically sound and is likely to be of interest to anyone building tooling around Git worktrees. The changes since v1 are sensible and address the main points of contention from the review. The addition of `post-worktree-move` rounds out the lifecycle coverage and should make the hooks more useful for external tools.
