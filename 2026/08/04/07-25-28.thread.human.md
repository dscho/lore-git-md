This thread is Patrick Steinhardt’s seven-patch series refactoring Git’s object database (ODB) streaming API to eliminate redundancy between read and write streams. The goal is to consolidate them into a single `odb_stream` structure as part of the broader ODB abstraction effort, enabling pluggable backends. The series is under review, with no prior versions, and targets inclusion in `next` or `master` soon.

The first two patches are mechanical refactors. The first made the write stream self-describing by embedding the expected size in `struct odb_write_stream`, aligning it with the read stream’s design. The second, just posted, removes the `is_finished` field from `struct odb_write_stream`, replacing it with direct checks on the stream’s read function return value or internal state. This touches seven files, including core ODB logic, callers in `object-file.c` and `builtin/unpack-objects.c`, and the unit test for the in-memory backend. The changes are straightforward, but reviewers may focus on edge cases in the new loop logic, particularly in `object-file.c` and `builtin/unpack-objects.c`.
