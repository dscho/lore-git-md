This thread is about Patrick Steinhardt’s eight-patch series refactoring Git’s object database (ODB) streaming API to unify the previously separate read and write paths into a single, direction-agnostic `odb_stream` structure. The goal is purely structural—no behavior changes—but it’s a key step in the larger ODB abstraction effort to enable pluggable backends. The series is now in its second version, posted after feedback on v1 resolved a critical bug in the in-memory ODB backend (where non-blob objects were incorrectly hashed as blobs) and addressed naming and documentation gaps.

The latest email covers Patch 5/8, which merges `struct odb_read_stream` and `struct odb_write_stream` into `struct odb_stream`. The change is mostly mechanical, updating type names and function signatures across 14 files, but it introduces wrapper structures in two special cases (`builtin/unpack-objects.c` and `odb/streaming.c`) to handle the transition. These wrappers will be renamed in later patches to better reflect their roles. The patch is uncontroversial and ready for review, with no intended behavior changes or new edge cases beyond ensuring the wrapper allocation logic is correct.

So far, the series has drawn substantive feedback from Justin Tobler and Junio Hamano. Justin’s reviews have been thorough, focusing on alignment with the read stream’s design, edge-case handling, and naming consistency. Junio’s review of v1 caught the critical bug in Patch 3/8, which has since been fixed. The series is under active review, with all patches now complete and targeting `next` or `master` in the near term. Open questions center on potential performance regressions from the added indirection and whether the unified API’s error handling is robust enough for mixed read/write operations. No new tests have been added, but existing coverage (limited to the in-memory backend) remains in place.
