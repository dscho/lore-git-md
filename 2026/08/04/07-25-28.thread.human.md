This thread is about Patrick Steinhardt’s seven-patch series refactoring Git’s object database (ODB) streaming API to unify the previously separate read and write paths into a single `odb_stream` structure. The goal is purely structural—no behavior changes—and is part of the larger ODB abstraction effort to enable pluggable backends. The series has been under review and is now complete, though Patrick plans an eighth cosmetic commit to rename a structure for clarity.

The key development is that the series hit a critical snag in Patch 3/7, where Junio C Hamano spotted a bug in the in-memory ODB backend: it was hard-coding `OBJ_BLOB` when computing object names, which could cause silent corruption or hash collisions for non-blob objects like trees or commits. Patrick has now fixed this in a follow-up, ensuring the correct object type is used. This was the only blocker, and with it resolved, the series can move forward. Other patches have received positive feedback, including from Justin Tobler, who reviewed most of the series in detail and endorsed the approach, though some naming consistency questions remain for later cleanup.

The refactoring touches 37 files and introduces a unified `odb_stream` structure that replaces the old `odb_write_stream` and `odb_read_stream`, along with new wrapper types and renamed functions. The changes are incremental, with each patch building on the last to align the read and write paths. No on-disk format changes or new CLI options are involved, and the series is targeting Junio’s integration branches for the upcoming release. The main open questions now are edge cases in the unified API, potential performance regressions, and the planned cosmetic rename, but none of these are blockers.
