This thread is a seven-patch refactoring series by Patrick Steinhardt to unify Git’s object database (ODB) streaming API, consolidating the previously separate `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure. The goal is purely structural—no behavior changes are intended—as part of the broader ODB abstraction effort to enable pluggable backends. The series is now complete and under initial review, with all patches posted against Junio’s "10th batch" for the upcoming release.

So far, the only feedback has come from Justin Tobler, who reviewed the first patch—a mechanical change embedding the expected size in `struct odb_write_stream`. His response was surface-level, endorsing the approach but offering no technical critique or engagement with edge cases. The remaining patches, which include the core unification (Patch 5/7) and renames (Patches 6–7/7), are still uncommented on. While the early patches are likely uncontroversial, reviewers may focus on the correctness of the wrapper structures (`odb_stream_write` and `odb_stream_read`) and the renamed `fd_stream` lifecycle in later patches, as well as potential performance regressions in stream-heavy code paths.

The series touches 37 files and introduces new symbols like `struct odb_stream`, `odb_stream_from_object()`, and `odb_stream_from_fd()`, while standardizing function names and documenting file descriptor ownership. No new tests have been added, and existing coverage remains limited to the in-memory backend. The thread is self-contained, depending only on prior ODB refactoring work, and is targeting `next` or `master` in the near term.
