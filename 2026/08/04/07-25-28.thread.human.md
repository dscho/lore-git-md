This thread is about Patrick Steinhardt’s eight-patch series **“odb: unify streaming API”**, which refactors Git’s object-database streaming layer to merge the previously separate `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure. The goal is purely structural—no behavior change—and is a stepping stone in the larger ODB abstraction effort that will eventually allow pluggable backends.

The v2 series is now complete and has incorporated all feedback from v1, including a critical bug fix in the in-memory ODB backend (Patch 3/8) that ensures the object type is correctly propagated to `hash_object_file()`. Other key changes include removing the redundant `is_finished` field (Patch 2/8), introducing wrapper structures for the two remaining special cases (Patch 5/8), and standardizing function names and documentation (Patch 8/8). Thirty-eight files are touched in total, but there are no on-disk format changes, new CLI options, or config keys.

Justin Tobler and Junio C Hamano provided substantive reviews on v1, catching the in-memory backend bug and suggesting cosmetic improvements that have since been addressed. Karthik Nayak has now reviewed the entire v2 series and called it “already in a good state,” though his feedback remains surface-level. All patches have at least one review, and the series is based on Junio’s “10th batch” for the upcoming release, targeting `next` or `master` in the near term. The only open questions are around edge-case handling in the unified API and potential performance regressions in stream-heavy code paths, neither of which have been raised as blockers by reviewers.
