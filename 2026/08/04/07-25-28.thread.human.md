This thread is a refactoring patch series by Patrick Steinhardt that unifies Git’s object database (ODB) streaming API, consolidating the previously separate `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure. The goal is purely structural—no behavior changes are intended—and it’s part of the broader ODB abstraction effort to enable pluggable backends. The series has grown from seven to eight patches in its second version (v2), addressing all known correctness issues, including a critical bug in the in-memory ODB backend that could cause silent corruption or hash collisions for non-blob objects.

The key changes in v2 include fixing the bug by propagating the correct object type to `hash_object_file()`, removing a stale comment in `odb/transaction.h`, and adding a new cosmetic patch to rename `struct input_zstream_data` to better reflect its role as a stream wrapper. The unified `odb_stream` structure now supports bidirectional streaming, allowing operations like reading an object and writing it elsewhere without intermediate buffering. The series touches 23 files, including core object handling, archive formats, and packfile operations, and updates the unit test for the in-memory backend to match the new API.

Justin Tobler and Junio C Hamano provided the most substantive feedback on v1. Justin’s reviews confirmed the removal of the `is_finished` field and the loop restructuring in `builtin/unpack-objects.c`, while Junio identified the critical bug in Patch 3/7. Both issues have been resolved in v2, and the series is now considered a strong candidate for merging. The remaining open questions are minor: edge cases in error handling for mixed read/write operations, potential performance regressions due to the additional indirection from wrapper structures, and the cosmetic rename in Patch 7/8. These are unlikely to block progress, though reviewers familiar with the ODB (e.g., Justin Tobler, Taylor Blau) may focus on them in subsequent rounds. The series is based on Junio’s "10th batch" for the upcoming release and targets `next` or `master` soon.
