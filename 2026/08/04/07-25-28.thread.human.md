This thread is Patrick Steinhardt’s seven-patch series refactoring Git’s object database (ODB) streaming API to unify the previously separate read and write paths into a single, direction-agnostic `odb_stream` structure. The goal is purely structural—eliminating redundancy and aligning the API design as part of the broader ODB abstraction effort to enable pluggable backends—with no intended behavior changes.

The series is now complete with the final patch, which standardizes function names (`odb_read_stream_open()` → `odb_stream_from_object()`, `odb_write_stream_from_fd()` → `odb_stream_from_fd()`) and adds documentation clarifying file descriptor ownership. The first six patches were mechanical refactors: embedding expected size in the write stream, removing redundant fields, extending write-stream support to non-blob objects, renaming structures, merging the read/write streams, and renaming internal types to reflect their expanded roles. The cumulative changes touch 29 files, introduce wrapper structures for backward compatibility, and update unit tests to match the new API.

No substantive reviews have landed yet, but the series is expected to be uncontroversial. The final patch is a straightforward cleanup, and the documentation addition should address most edge-case questions about file descriptor lifecycle. The series is based on Junio’s "10th batch" for the upcoming release and targets `next` or `master` in the near term. Open questions remain about potential performance regressions in stream-heavy code paths and test coverage for pathological cases, but these are unlikely to block progress. The work is part of Patrick’s ongoing ODB abstraction effort and doesn’t depend on or block other in-flight series.
