This thread is a seven-patch refactoring series by Patrick Steinhardt that unifies Git’s object database (ODB) streaming API, eliminating redundancy between the read and write stream interfaces. The goal is structural cleanup—no behavior changes—as part of the broader ODB abstraction effort to support pluggable backends. All patches are now posted and under review, with the final patch (7/7) standardizing function names and documenting file descriptor ownership.

Justin Tobler has reviewed most of the series, offering substantive feedback on the core design changes in Patches 2/7, 3/7, and 5/7 (e.g., loop logic in `unpack-objects.c`, the addition of an object type field, and wrapper structure naming). His reviews confirmed the changes align the write and read stream behaviors and prepared the API for unification. The final patch received a surface-level endorsement, noting the renames match earlier feedback but not engaging with deeper edge cases. No other reviews have appeared, leaving Patch 7/7 as the only one still under initial scrutiny.

The series touches 37 files, introducing a unified `odb_stream` structure and renaming several symbols (e.g., `odb_stream_from_object()`, `fd_stream`). While the changes are mechanical, open questions remain about error handling in the new bidirectional API, potential performance regressions from added indirection, and test coverage for edge cases like oversized non-blob objects. The stale comment in `odb/transaction.h` about blob-only streaming should also be updated. The series is based on Junio’s "10th batch" for the upcoming release and targets `next` or `master` once reviews conclude.
