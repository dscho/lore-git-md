This thread is about Patrick Steinhardt’s seven-patch series refactoring Git’s object database (ODB) streaming API to unify the previously separate read and write streams into a single `odb_stream` structure. The goal is purely structural—eliminating redundancy to simplify the API and support the broader ODB abstraction effort for pluggable backends—with no intended behavior changes. The series is now complete and under active review, targeting inclusion in Junio’s `next` or `master` branch for the upcoming release.

Justin Tobler has provided substantive feedback on two of the seven patches so far. His review of the second patch (removing the `is_finished` field from `struct odb_write_stream`) confirmed the change aligns the write stream’s behavior with the read stream’s design, where callers infer completion from a zero-byte return rather than an explicit flag. He praised the loop restructuring in `builtin/unpack-objects.c` for ensuring correct edge-case handling and noted the existing documentation already matched the intended behavior. His earlier review of the first patch (embedding the expected size in `struct odb_write_stream`) was more surface-level, endorsing the approach but not engaging with deeper implications. The remaining five patches—including the core unification in Patch 5/7 and the final API standardization in Patch 7/7—have yet to receive feedback.

The series touches 37 files and introduces new symbols like `struct odb_stream`, `struct fd_stream` (renamed from `read_object_fd_data`), and standardized functions such as `odb_stream_from_object()` and `odb_stream_from_fd()`. While the refactoring is mechanical, reviewers are likely to focus on edge cases like error handling in mixed read/write operations, lifecycle management of the new wrapper structures, and potential performance regressions in stream-heavy code paths. No new tests have been added, and existing coverage remains limited to the in-memory backend. The series is part of Patrick’s ongoing ODB abstraction work but doesn’t block or depend on other in-flight topics.
