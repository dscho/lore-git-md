This thread is a v2 patch series from Patrick Steinhardt refactoring Git’s object database (ODB) streaming API to unify the previously separate read and write paths. The goal is to eliminate redundancy by consolidating `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure, part of the broader ODB abstraction effort to enable pluggable backends. The series is now complete with eight patches, all under review.

Key changes include embedding object size and type in the stream structure, removing redundant fields like `is_finished`, and introducing wrapper structures for read/write special cases. The critical bug in the in-memory ODB backend—where non-blob objects were incorrectly hashed as blobs—has been fixed in v2, along with stale documentation updates. Reviewers Justin Tobler and Junio C Hamano provided substantive feedback on v1, with Justin focusing on naming consistency and edge-case handling, and Junio identifying the correctness issue that blocked progress until resolved.

The series is now ready for merging, with all patches reviewed and the final patch standardizing function names and clarifying file descriptor ownership. Open questions remain about edge cases in the unified API and potential performance regressions from added indirection, but these are minor compared to the structural improvements. The refactoring is purely internal, with no user-visible changes or on-disk format modifications. If accepted, it will simplify future ODB backend work and reduce code duplication.
