This is the fourth and final patch in Domen Kožar’s v2 series introducing worktree lifecycle hooks. It adds the `post-worktree-move` hook, completing the trio (`post-worktree-add`, `post-worktree-remove`, and now `post-worktree-move`) that lets external tools reliably track worktree creation, deletion, and relocation.

The hook runs in the new worktree directory after the move completes, with `GIT_DIR` and `GIT_WORK_TREE` cleared, and receives the old absolute path as its only argument. This design keeps the signature minimal while allowing a single script to handle all three hooks by argument count: zero for add, one for move, two for remove. The hook’s exit status propagates to `git worktree move` but cannot prevent the move from happening.

The implementation is clean: a new helper `run_post_worktree_move_hook` in `builtin/worktree.c`, a two-line update to the `move_worktree` function, and a new test script (`t/t2403-worktree-move.sh`) that verifies both successful and failing hook execution. Documentation is added to `githooks.adoc` and the hook is registered in `hook-list.h`.

This patch directly addresses the gap Phillip Wood noted in earlier review: without a move hook, tools that record worktree paths would see stale mappings after a `git worktree move`. The solution is well-motivated, technically sound, and consistent with the rest of the series. If the earlier patches in the series are acceptable, this one looks ready to go.
