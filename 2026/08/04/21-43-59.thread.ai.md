Subject: [PATCH] gitk: add user-configurable custom commands to context menus
Series version: standalone patch (no series)
Originating author: Tim Wiederhake
Thread type: feature patch

Core problem or goal
Add user-configurable custom commands to `gitk`'s right-click context menus (commit list and diff display) to enable workflows like "edit this line at that point in history" (e.g., rebasing to a commit, opening an editor at a specific line, amending, and continuing). The feature avoids hardcoding niche functionality by letting users define up to three commands per area, with placeholder substitution (commit ID, title, author, blame origin, etc.) and shell execution. Configuration is exposed via a new "Commands" tab in the preferences dialog.

Current status
Under review; no prior versions or discussion on-list. Patch is self-contained to `gitk` (Tcl/Tk frontend), touching only the `gitk` script (217 lines added, 3 removed). No impact on Git's core C code or plumbing. **Blocked on process and security**: maintainer (Johannes Sixt) has stated he will not review the implementation until (1) the commit message is revised to include the feature's motivation, and (2) the author confirms they have personally reviewed and understood every line of the AI-assisted code, per project AI contribution rules. The author has provided the motivation and a partial response to the AI assistance requirement, but the maintainer has not yet accepted either. Additionally, Junio C Hamano has raised a **critical security concern** about the command substitution mechanism: placeholders (e.g., `%t` for commit title) are interpolated into shell commands without proper quoting or sanitization, enabling arbitrary command injection via malicious commit titles/messages. This must be resolved before the patch can proceed.

Key technical details
- Files touched: `gitk` (Tcl script)
- New global variables: command templates for commit-list and diff-display menus
- New procedures: dynamic menu population, preferences-page UI
- Execution: commands run via `sh -c`; exit code 42 displays command output
- Symbols: none in C; Tcl variables and procedures internal to `gitk`
- On-disk format: none; configuration stored in `~/.gitk` (existing file)
- Test coverage: none in this patch
- **Security vulnerability**: Placeholder substitution in shell commands is unquoted, allowing injection of arbitrary shell metacharacters (e.g., `title?'; echo no'` in a commit title would execute both the intended command and the injected payload).
