Thread identity
Subject: [PATCH] gitk: add user-configurable custom commands to context menus
Series version: standalone patch (now suggested to become a patch series)
Originating author: Tim Wiederhake
Thread type: feature patch

Core problem or goal
Add user-configurable custom commands to `gitk`'s right-click context menus (commit list and diff display) to enable workflows like "edit this line at that point in history" (e.g., rebasing to a commit, opening an editor at a specific line, amending, and continuing). The feature avoids hardcoding niche functionality by letting users define commands with placeholder substitution (commit ID, title, author, blame origin, etc.) and shell execution. Configuration is exposed via a new "Commands" tab in the preferences dialog.

Current status
Under review; no prior versions on-list. The patch is self-contained to `gitk` (Tcl/Tk frontend), touching only the `gitk` script. **Blocked on three fronts**: (1) **Process**: the maintainer (Johannes Sixt) has rejected the monolithic implementation and now suggests breaking the feature into an incremental patch series, starting with a minimal use case (e.g., "open an editor at this line in the diff") and deferring less essential functionality (e.g., placeholder substitutions for author/committer data) to later patches. (2) **AI assistance policy**: Hannes remains uncertain whether the author’s iterative reworking of Claude-generated code meets the project’s requirement that the author "review and understand every line," and has explicitly asked for community input on whether this level of AI involvement is acceptable. (3) **Security**: Junio C Hamano’s critical security concern about unquoted shell command substitution (enabling arbitrary command injection via malicious commit titles/messages) is now **confirmed by Hannes** as a blocker that must be fixed before further review. The author has not yet responded to Hannes’ guidance on process, policy, or the security flaw.

Key technical details
- Files touched: `gitk` (Tcl script)
- New global variables: command templates for commit-list and diff-display menus
- New procedures: dynamic menu population, preferences-page UI
- Execution: commands run via `sh -c`; exit code 42 displays command output
- Symbols: none in C; Tcl variables and procedures internal to `gitk`
- On-disk format: none; configuration stored in `~/.gitk` (existing file)
- Test coverage: none in this patch
- **Security vulnerability**: Placeholder substitution in shell commands is unquoted, allowing injection of arbitrary shell metacharacters (e.g., `title?'; echo no'` in a commit title would execute both the intended command and the injected payload). Junio provided a concrete exploit example; Hannes endorsed the concern as "very important."

Open questions and loose ends
1. **Implementation structure**: The author must decide whether to follow Hannes’ suggestion to split the feature into an incremental patch series, starting with a minimal use case (e.g., "open an editor at this line in the diff") and deferring less essential functionality.
2. **AI-assisted code ownership**: The project’s guidelines are ambiguous about whether iterative reworking of AI-generated code meets the requirement that the author "review and understand every line." Hannes has asked for community input on this policy question; no response yet.
3. **Security flaw**: The command substitution mechanism remains unsafe. The author must either (a) properly quote all interpolated values, (b) avoid shell execution entirely, or (c) restrict placeholders to safe subsets. Junio’s review provides a concrete exploit example; Hannes has confirmed the issue as a blocker.
4. **Motivation gap**: Resolved in substance (author provided a concrete use case), but the commit message must still be revised to include it in future iterations.
5. **Technical review**: None yet beyond Junio’s security critique and Hannes’ process guidance; the thread remains focused on structure, policy, and security.
