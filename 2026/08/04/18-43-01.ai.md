This is the seventh patch in Pablo Sabater’s nine-patch GSoC series (v4) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now feature-complete and merge-ready, with all prior review feedback addressed.

This patch teaches the client to parse object type data from the server’s response. It adds a `wants_type` flag and a `types` array to `struct fetch_object_info_results`, mirroring the existing `wants_size`/`sizes` machinery. When the server transmits a type string (e.g., `"blob"`), the client maps it to Git’s internal `enum object_type` using `type_from_string_gently()` and stores the result in the `types` array. A safety check `die()`s if the server sends an invalid type string, matching the existing behavior for malformed size data.

The patch updates `send_object_info_request()` to include the "type" keyword in the protocol request when `ask_type` is set, and extends `fetch_object_info()` to parse the "type" attribute from the server’s response. The `builtin/cat-file.c` caller is updated to propagate the parsed type to the batch output formatter when `results.types` is populated. No server-side capability advertisement is added yet (that comes in patch 8/9), so the client will only request type data once the server advertises support.

Files touched: `fetch-object-info.c`, `fetch-object-info.h`, and `builtin/cat-file.c`. New symbols: `results->wants_type`, `results->types`, and the "type" keyword in the object-info protocol. The changes are narrowly scoped and follow the established pattern for size data, making them easy to review. No open questions remain; the patch is a straightforward extension of the protocol and is ready for review.
