This is the third patch in Patrick Steinhardt’s five-part series making Git’s on-disk object database (ODB) structures pluggable. It introduces a new flag, `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION`, that defers the creation of the ODB until after the ref database is set up. This refactoring is a prerequisite for the planned `objectStorage` extension, which will enable non-filesystem ODB backends.

The patch splits the current `create_object_directory()` function into two steps: `apply_repository_format()` (which now skips ODB creation when the flag is set) and a new `create_object_database()` function that handles the deferred creation. The change is mechanical, moving the `odb_new()` call and directory creation logic into the new function and introducing a helper, `get_object_directories()`, to centralize environment variable handling. The patch also renames `create_object_directory()` to `create_object_database()` to reflect its broader scope.

This is infrastructure work with no immediate user-visible impact, but it’s a critical step toward the ODB abstraction effort. The flag-based approach is a pragmatic choice, as Patrick explains in the thread: splitting object directory and alternate logic from `apply_repository_format()` is complex, and this design may simplify in the future when environment variable handling moves into the "files" backend. The patch is well-motivated and addresses a clear technical need, though the initialization sequence design remains a point of discussion (Justin Tobler suggested an explicit `odb_new()` call might be cleaner). No objections to correctness have been raised.
