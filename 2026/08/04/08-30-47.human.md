This is the **v12 iteration of Harald Nordgren’s `git history squash` feature**, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now **functionally complete** and incorporates **all feedback from Phillip Wood**, including stricter range validation, improved fixup/squash/amend handling, and refined ref protection.

Key improvements in v12:
- **Single-pass range validation**: Rejects root commits, multiple tips, and ranges with external parents in one walk, while preserving merge topology. This replaces the earlier multi-step validation and fixes edge cases like misidentified boundaries.
- **Fixup/squash/amend resolution**: Directly resolves marker targets during the walk, preserving message intent and consolidating related markers safely. A `squash!` or `amend!` is now rejected unless its target is the first commit in the range or `--edit` is used, preventing accidental message loss.
- **Editor template accuracy**: Builds the template from the exact selected revisions (including exclusions) while retaining `--no-edit` behavior.
- **Ref-handling**: Protects only local branches descended from the squashed range, leaving tags and remote-tracking refs unchanged. This simplifies the `--update-refs=head` workflow.

The series remains a **4-patch feature addition** targeting `builtin/history.c`, with **comprehensive test coverage** in `t/t3455-history-squash.sh`. The implementation is **aligned with `git rebase -i --autosquash`** and reuses sequencer helpers for template consistency.
