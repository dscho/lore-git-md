This is the fourth patch in Patrick Steinhardt’s five-part series making Git’s on-disk object database (ODB) structures pluggable. It is a small, mechanical refactoring that improves error messages in the ODB source downcasting macros.

The patch introduces `odb_source_type_to_name()`, a helper function that maps an ODB source type (e.g., `ODB_SOURCE_FILES`, `ODB_SOURCE_LOOSE`) to a human-readable string. It then updates the downcasting macros in each backend (`files`, `loose`, `packed`, `in-memory`) to use this function in their BUG messages. Instead of printing raw enum values (`trying to downcast source of type '2' to files`), the messages now show the symbolic names (`trying to downcast source of type 'packed' to 'files'`). This makes debugging easier without changing any behavior.

The change is confined to the ODB source subsystem and touches only the downcasting macros and their supporting code. It is a pure refactoring with no functional impact, but it is a prerequisite for the next patch, which will use the same mapping function in the new `create_on_disk` callback. Junio’s review of v1 was surface-level (a spelling nit for “in-memory”), which Patrick has already addressed. The patch is uncontroversial and looks ready to merge.
