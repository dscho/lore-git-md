This is the tenth and final patch in the v7 RFC series introducing Git’s **diff provider interface**, specifically addressing a **portability fix** for the external process provider (`diff.<driver>.process`). The patch corrects a type mismatch in `blob_line_cap()` where an `unsigned long` was used to store a blob size, breaking the build on platforms where `size_t` differs from `unsigned long` (e.g., 32-bit systems and 64-bit Windows).

The fix is minimal: replace `unsigned long size` with `size_t size` in `diff-process.c`. This aligns the variable with the type expected by `odb_read_object_info_extended()`’s `sizep` field, resolving the `-Wincompatible-pointer-types` warning. The change is purely mechanical and does not affect functionality, as the subsequent bounds check (`size > INT32_MAX`) remains valid.

This patch is part of the **external process provider** implementation (introduced in patch 11/11 of the series), which enables Git to consult long-running external processes for diff hunks via a pkt-line protocol. The provider is authoritative—its answers may override the builtin diff and the `diff-hunks` store—and is wired into `git blame` and summary formats (`--stat`, `--numstat`, `--shortstat`). The fix ensures the provider works across all supported platforms without regressing the existing functionality.

The series as a whole is **technically complete** and ready for design feedback on the framework. This patch is a straightforward build fix and does not alter the interface, protocol, or integration logic. If the framework is accepted, the external process provider will return as a separate series alongside the `diff-hunks` store and future content-carrying extensions.
