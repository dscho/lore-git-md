This is the fourth patch in Patrick Steinhardt’s five-part series making on-disk ODB structures pluggable, part of the ongoing ODB abstraction effort. It introduces a helper function, `odb_source_type_to_name()`, that maps ODB source types (e.g., `ODB_SOURCE_FILES`, `ODB_SOURCE_LOOSE`) to human-readable strings. The function is immediately used to improve error messages in the downcasting macros across all ODB source backends.

The patch is a small but meaningful quality-of-life improvement. By replacing numeric type codes (`'%d'`) with descriptive names (`'%s'`) in BUG messages, it makes debugging easier for developers encountering type mismatches. The implementation is straightforward: a static array maps enum values to strings, with bounds checking and a fallback to "unknown" for invalid types. The change touches six files but is purely mechanical, with no behavior changes or new functionality.

The patch is uncontroversial and ready for merging, though its value is incremental rather than transformative. It serves as a building block for the series’ larger goal of enabling custom ODB backends by making the codebase more maintainable. No open questions or objections remain.
