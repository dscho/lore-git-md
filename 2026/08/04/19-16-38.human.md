This is a small but user-visible behavioral change to `git interpret-trailers`. The patch stops Git from treating lines that begin with `<token>://` (like `https://example.com`) as trailers, which was causing false positives in commit messages or pull-request descriptions where URLs appeared at the start of a line.

The patch is part of a two-topic stack: it depends on `kh/doc-trailers`, which is still under review and not yet in `next`. The author acknowledges that the dependency blocks merging and plans to let both topics sit for a few days to gather more feedback. There is no urgency or controversy here—just a routine correctness fix waiting for its base to stabilize. If you use trailers in commit messages, this change may affect how your text is parsed, but only in edge cases where URLs start a line.
