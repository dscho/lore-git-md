This is the tenth and final patch in Michael Montalbo’s v7 RFC series introducing a **diff provider interface** for Git. The patch implements the **external process provider**, allowing Git to consult a long-running external process (configured via `diff.<driver>.process`) for diff hunks before falling back to the builtin xdiff or the in-process `diff-hunks` cache. The email is a self-reply addressing a **portability bug** in the patch: the use of `unsigned long` for blob size breaks the build on platforms where `size_t` differs from `unsigned long` (e.g., 32-bit systems and 64-bit Windows). The fix is a one-line change replacing `unsigned long size` with `size_t size`.

The patch itself is technically complete and integrates the external process provider into the repository’s provider chain. The provider speaks a pkt-line protocol over stdin/stdout, answering requests by object names alone (no content is sent), which allows it to serve as a persistent cache or fetch blobs itself. The process is authoritative: its answers may differ from the builtin diff and override the `diff-hunks` store. Key features include:
- **Protocol**: Versioned handshake (`git-diff-client`/`git-diff-server`, version=1), per-pair requests (`command=hunks-by-oid`), and hunk responses (`hunk <old_start> <old_count> <new_start> <new_count>`).
- **Error handling**: Protocol errors (malformed packets, crashes) disable the process for the remainder of the command, falling back to the builtin diff. Invalid hunks skip only the affected pair.
- **Lifecycle**: The provider manages a repository-owned pool of processes, launched on first use and stopped when the repository is cleared. Failed processes are retained to avoid retries.
- **Gating**: Consulting is opt-in per command (e.g., `git blame` and summary formats like `--stat` allow it; plumbing commands like `diff-tree` forbid it by default). Options like `--ignore-space-change` bypass the process entirely.
- **Integration**: Wired into `git blame` and summary formats (`--stat`, `--numstat`, `--shortstat`). A `status=success` response with zero hunks asserts blob equivalence, omitting the pair from the stat or passing the whole commit through in blame. Patch output and `git log -L` remain builtin due to the lack of content-carrying requests.

The patch adds 669 lines to `diff-process.c`, including protocol parsing, process pool management, and validation. It also introduces `subprocess_read_status_gently()` (from an earlier patch in the series) to handle protocol errors gracefully for optional processes. The test helper `test-diff-process-backend.c` (349 lines) and `t/t4080-diff-process.sh` (593 lines) verify the protocol, integration, gating, and error paths.

The portability fix is trivial and does not affect the patch’s functionality or design. The series as a whole is **technically complete** and ready for design feedback on the framework. If accepted, the external process provider will return as a separate series alongside the `diff-hunks` store and future content-carrying extensions. The RFC explicitly seeks feedback on the direction, not a merge of the 11 patches as one.
