This is a **maintainer review** of the v2 patch moving `fetch_if_missing` into `struct repository`. Junio C Hamano responds to Patrick Steinhardt’s observation about the inconsistency in `builtin/index-pack.c` (checking for `repo` but then setting `the_repository->fetch_if_missing`) by raising a deeper design question: whether `fetch_if_missing` should be tied to a repository at all, given that commands like `git index-pack` can run outside a repository.

Junio outlines three possible approaches to resolve this, ranging from pragmatic to conceptually pure. The first approach would require `index-pack` to always run inside a repository, making `repo` non-NULL and eliminating the need for the conditional. The second would use `the_repository` as a fallback when `repo` is NULL, but this would require ensuring all code paths that reference `fetch_if_missing` pass `the_repository` in repository-less contexts. The third, most ambitious approach would introduce a new global "basic settings" structure to hold flags like `fetch_if_missing` that apply even outside a repository, with per-repository settings overriding them.

The review is substantive, questioning the patch’s fundamental design rather than just its implementation. Junio’s framing suggests the current approach may be flawed, and the patch will likely need a v3 that either restricts `index-pack` to repository-bound operation or adopts one of the more complex solutions. The discussion now centers on whether the libification goal of eliminating globals justifies the added complexity of a repository-agnostic settings framework. No clear consensus has emerged, but the thread is now focused on this architectural decision.
