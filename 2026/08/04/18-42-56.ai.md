This is a robustness patch (2/9) in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support `%(objecttype)` in remote-object-info queries. The patch addresses a latent protocol hygiene issue in `fetch-object-info.c`: the client did not validate whether the server sent exactly the expected number of object-info lines.

The change extracts the packet-reading logic from the loop condition so the loop no longer consumes the final flush packet. Inside the loop, if the reader returns anything other than `PACKET_READ_NORMAL` before all requested objects are read, the client now `die()`s with a clear error message. After the loop, it checks that the next packet is a flush; if not, it `die()`s again. These checks prevent the caller from using uninitialized data (under-length responses) or silently ignoring extra data (over-length responses), aligning with Git’s defensive programming practices.

The patch is a direct response to Junio’s review feedback on v3, which noted that while the code was safe against buffer overflow, it should detect and reject protocol violations. Pablo implemented the fix exactly as suggested, and the commit message now explicitly calls out both under-length and over-length cases. No test coverage is added for these specific checks, but the series expands test coverage elsewhere (patches 6/9 and 8/9). The change is mechanical, uncontroversial, and ready to merge.
