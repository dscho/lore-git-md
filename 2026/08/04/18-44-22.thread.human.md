This thread is a user support discussion about a suspected regression in Git’s textconv feature that surfaced in Git 2.50. Randall S. Becker, the NonStop port maintainer, reports that external textconv filters now receive empty temporary files when processing *binary files* (those beginning with a null byte), while text files and ELF binaries work as expected. This breaks workflows that rely on the original file path to locate repository files. D. Ben Knoble, however, observes that temp files are populated on his system (Git 2.53.0), suggesting the issue may be platform-specific or tied to binary content handling.

The regression’s scope is now clearer: it affects only binary files on NonStop, implying the root cause may involve how Git handles null bytes during textconv filter invocation. Despite this narrowing, the discussion remains diagnostic—no maintainer has weighed in, and no patch or root-cause analysis has been provided. The discrepancy between Randall’s and Ben’s observations (empty vs. populated temp files) remains unresolved, and the question of whether this change was intentional is still open. The thread is still seeking clarity on the regression’s cause and a potential fix.
