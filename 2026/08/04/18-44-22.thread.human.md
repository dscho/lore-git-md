This thread is a user support discussion about a regression in Git’s textconv feature that appeared in Git 2.50. Randall S. Becker, the NonStop port maintainer, reported that external textconv filters now receive empty temporary files when processing *binary* files (those beginning with a null byte) on the NonStop platform, breaking workflows that rely on the original file path. Text files and ELF binaries (which don’t start with null bytes) work as expected, narrowing the issue to null-byte-prefixed content.

Jeff King (Peff) responded to clarify Git’s intended behavior around tempfile reuse, explaining that Git sometimes passes the working-tree file directly to textconv filters as an optimization—but only when the file is clean and one diff endpoint is the index. This accounts for earlier inconsistencies in Randall’s observations but doesn’t address the core regression: empty temp files for binary files on NonStop. Peff confirmed he couldn’t reproduce the issue even with files containing null bytes, leaving the root cause unresolved. The discussion now hinges on whether this is a platform-specific I/O issue (e.g., NonStop’s handling of null bytes) or a deeper bug in Git’s tempfile logic. No patch or workaround has been proposed yet, and the regression remains user-facing.
