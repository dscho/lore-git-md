This thread is a user support report from Randall S. Becker, the maintainer of Git’s NonStop port, about a regression in Git’s textconv feature. Since Git 2.50, external textconv filters receive empty temporary files instead of the actual file content from the working tree, breaking workflows that rely on the filter being able to locate the correct file in the repository—especially when multiple files share the same name. Randall is asking whether this change was intentional or a bug and how to restore the previous behavior.

So far, this is a straightforward bug report with no technical analysis of the root cause, patches, or responses from other contributors. The issue affects users who depend on textconv filters, and the key details (empty temp files, reliance on working-tree paths) are clearly described. If this is indeed a regression, it may prompt further investigation or a patch to address the behavior change. No decisions or resolutions have been made yet.
