This thread is about Vincent Mailhol’s patch adding bash completion for the `git history` command, covering its subcommands (`drop`, `fixup`, `reword`, `split`), their options, and revision arguments. The patch is under review and has drawn positive feedback from Patrick Steinhardt and D. Ben Knoble, who both see it as a clear improvement.

The implementation touches `contrib/completion/git-completion.bash` and adds test coverage in `t/t9902-completion.sh`. It handles subcommand and option completion, as well as revision names, though the `split` subcommand’s pathspec handling (where arguments after the first should ideally complete as file paths rather than revisions) is noted as a non-blocking refinement for a future iteration. The patch will also need a trivial rebase once the `squash` subcommand, currently in Junio’s `seen` branch, lands.

Junio C Hamano’s recent comment observes that the new completion function follows a boilerplate pattern seen in other subcommands and suggests a future refactoring to consolidate this duplicated code into a shared helper. This is a forward-looking note about maintainability, not a request for changes to the current patch. With no outstanding objections and two endorsements, the patch appears ready to proceed once the `squash` subcommand is merged.
