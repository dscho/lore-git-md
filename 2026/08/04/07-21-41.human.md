This is the third patch in Patrick Steinhardt’s ongoing ODB abstraction series, which aims to make Git’s object database backends pluggable. The patch defers the creation of on-disk ODB structures (like `objects/pack` and `objects/info`) until after the repository’s object database is fully configured, using a new flag `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` to control the timing.

Justin Tobler’s review questioned whether the flag-based approach is the cleanest design, suggesting that requiring an explicit `odb_new()` call after `apply_repository_format()` might be simpler. Patrick’s reply clarifies that the current logic for determining object directories and alternates is complex and tightly coupled with the repository setup process. He acknowledges that the design might simplify in the future once environment variable handling moves into the "files" backend, but for now, the flag-based approach is the pragmatic choice. This exchange does not block the patch but leaves the door open for future refactoring.

The patch itself is a small but necessary step toward pluggable ODB backends, touching `setup.c` and `repository.c`. It does not change on-disk formats or user-visible behavior, and the implementation looks clean. The discussion here is about design clarity rather than correctness, and Patrick’s reasoning is grounded in the current state of the codebase. If you are following the ODB abstraction effort, this patch is worth noting for its role in enabling backend-specific initialization, but it is not a standout on its own.
