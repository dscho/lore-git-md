This is a bugfix for the `contrib/credential/libsecret` helper. The patch addresses a silent failure in the GNOME keyring integration where Git could lose stored credentials due to assertion failures in the libsecret library.

The issue occurs when `secret_service_search_sync()` returns an item whose secret isn't loaded, despite the `SECRET_SEARCH_LOAD_SECRETS` flag being set. This happens because the search silently discards secret-loading failures, and the keyring daemon may omit locked or recently deleted items from its response. When Git then tries to access the NULL secret value, it triggers assertion failures in `secret_value_get_text()` and `secret_value_unref()`.

Daniel Martí's fix removes the `SECRET_SEARCH_LOAD_SECRETS` flag and instead explicitly loads the secret for the single item being used via `secret_item_load_secret_sync()`. This approach properly reports errors for genuinely inaccessible items while successfully retrieving secrets that would have been silently dropped before. The change maintains the same performance characteristics while making the credential retrieval more reliable.

The patch is small and focused, touching only the credential helper's error handling. It includes a clear explanation of the problem and solution in both the commit message and code comments. This looks like a well-crafted fix for what appears to be a real and annoying edge case for users of the libsecret credential helper.
