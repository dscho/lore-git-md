This is a Google Summer of Code feature patch series (v4) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now nine patches long, up from eight in v3, and is feature-complete and ready for merging.

The core goal remains unchanged: object type is the last piece of metadata guaranteed to match between client and server after a fetch, making it a natural fit for remote-object-info. The series adds end-to-end support—server capability advertisement, client request logic, protocol extension, and client-side parsing—while explicitly ruling out other metadata (disk size, delta base, object mode) as unreliable or context-dependent.

Key improvements in v4 address all remaining review feedback. The most significant change is the addition of patch 5/9, which converts the last error return in `fetch_object_info()` to a `die()` call, making the function void and simplifying error handling. Patch 2/9 now checks for both under-length and over-length server responses, addressing Junio’s protocol hygiene concern by ensuring the client fails fast if the server sends more objects than requested. The `ask_type` flag and related machinery are correctly introduced in patch 7/9 (previously 4/8 in v3), eliminating the premature flag issue Junio raised. Patch 1/9’s commit message has been updated to clarify that the test cleanup also preserves command exit statuses, a point Junio noted in his review.

The refactoring in patches 3/9 and 4/9 is now finalized: `struct object_info_args` is removed in favor of direct parameter passing, and `struct fetch_object_info_results` replaces `struct object_info` to hold only the fields the caller requests (size and type), avoiding sentinel values and boolean flags. The design uses a single array of lightweight structs where the caller controls which fields are populated, aligning with the protocol’s transmission of raw strings (e.g., `"blob"`, `"1234"`).

Patches 6/9 through 9/9 complete the implementation: the server parses and transmits type data (patch 6/9), the client maps the string to an internal `enum object_type` (patch 7/9), the server advertises the "type" capability (patch 8/9), and the default format in `cat-file` is unified to `%(objectname) %(objecttype) %(objectsize)` (patch 9/9). Test coverage in `t5701` and `t1017` has been expanded to verify the new functionality and backward compatibility.

The series is well-motivated, thoroughly reviewed, and addresses all prior feedback. The architectural changes are clean and follow Git’s conventions, and the implementation is defensive (e.g., `die()` on malformed responses). No further design changes are expected, and the series is now merge-ready. CI passed on GitHub.
