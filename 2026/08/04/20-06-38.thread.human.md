This thread is about a bug report from D. Ben Knoble noting that `git replay --onto=...` and `git history fixup` silently drop Git notes when rewriting commits. Only the tip commit’s notes can be manually recovered, while notes on intermediate commits are lost entirely.

Patrick Steinhardt has confirmed that for `git history`—a user-facing command—this behavior is an unimplemented feature rather than a deliberate design choice. He is less certain about `git replay`, which he considers plumbing, but still views the omission as something that should be addressed. He has opened a GitLab issue to track the work for the next release cycle but encourages community contributions to resolve it sooner.

The key open question remains whether notes should be preserved on all rewritten commits or just the tip, and whether other history-rewriting commands (like `git rebase` or `git cherry-pick`) already handle notes correctly. No patches or detailed design proposals have been posted yet, so the discussion is still in the early stages.
