This thread is a bug report from D. Ben Knoble about `git-replay` and `git-history` silently dropping Git notes during history rewriting. When using `git replay --onto=...` or `git history fixup`, notes attached to commits are lost, which the author finds surprising and problematic. They currently work around the issue by manually copying notes for the tip commit (`git notes copy @{1}`), but intermediate commits remain affected. The report questions whether notes are intentionally excluded from these commands or if this is an unimplemented feature, though the tone suggests the latter.

No prior discussion or patches are referenced, so this appears to be the first time the issue has been raised on the list. The report is clear but lacks reproduction steps or test cases, relying instead on the assumption that notes should be preserved during rewriting. So far, there are no replies or reviews, so the thread is still open—whether this is a bug or a design limitation remains unresolved.
