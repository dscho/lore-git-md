This thread is about a bug in Git’s history-rewriting commands: `git replay --onto` and `git history fixup` silently drop Git notes attached to commits, preserving only the tip commit’s notes (which can be manually recovered). D. Ben Knoble reported the issue, and Patrick Steinhardt acknowledged it as an unimplemented feature for `git history` and a likely gap for `git replay`.

The discussion has confirmed the behavior but made little progress toward a fix. No patches or design proposals have emerged, and the only tracking mechanism is a GitLab issue opened by Patrick. The key open questions—whether all rewritten commits or just the tip should preserve notes, and how this compares to other history-rewriting commands like `git rebase`—remain unresolved. The thread suggests the issue is recognized but not urgent, with community contributions welcomed. For now, users must manually recover notes after rewriting.
