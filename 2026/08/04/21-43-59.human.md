This is a feature patch for `gitk`, the built-in Git history browser. It adds user-configurable custom commands that appear in the right-click context menus of both the commit list and the diff display. Users can define up to three commands per area, with support for placeholder substitution (commit ID, title, author, file path, blame origin, etc.) and shell execution. The configuration lives in a new "Commands" tab in the preferences dialog.

The implementation is self-contained: it touches only the `gitk` script, adding roughly 220 lines of Tcl/Tk code. The patch introduces new global variables for the command templates, extends the context-menu procs to populate the menus dynamically, and provides a helper that substitutes placeholders and executes the command via `sh -c`. Exit code 42 is treated specially—its output is displayed in a dialog—while other non-zero codes trigger an error message.

The feature looks well-scoped and immediately useful for power users who want to integrate `gitk` with external tools (e.g., opening a file in an editor, running a custom blame script, or piping diffs to a formatter). The commit message is clear, and the code follows `gitk`’s existing patterns. No controversy is evident from the patch itself, though the usual review questions about persistence, security implications of shell execution, and UI polish are likely to come up.
