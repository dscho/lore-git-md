This is the sixth patch in Pablo Sabater’s nine-patch GSoC series (v4) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the server-side object-info handler to accept "type" as a requested field and transmit the object type alongside the existing size data.

The change is narrowly scoped: it adds a `type` bit field to `struct requested_info`, updates the server to parse the "type" keyword in client requests, and extends `send_info()` to append the object type (e.g., `"blob"`) to the response when requested. The patch also includes a mechanical cleanup—fixing a bit-field style nit (`size:1` → `size: 1`) and wrapping an over-long line in `send_info()`—and adds a test in `t5701` verifying the server handles requests for both "size" and "type", including duplicate OIDs.

The implementation follows the established pattern from the predecessor series (Eric Sunshine’s `ps/cat-file-remote-object-info`) and aligns with the architectural refactoring in earlier patches (3–5/9), which replaced `struct object_info` with a dedicated `struct fetch_object_info_results` to avoid sentinel values. The server transmits type data as a string (e.g., `"blob"`), matching the protocol’s existing behavior for size, and the client will parse this in patch 7/9 using `type_from_string_gently()`.

No open questions or loose ends remain for this patch; it is a straightforward extension of the protocol and is ready for review. The test coverage is thorough, including edge cases like duplicate OIDs, and the changes are confined to `protocol-caps.c` and `t5701`.
