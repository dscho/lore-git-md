This is a brief follow-up in the ongoing discussion about the `git receive-pack` performance regression caused by the ODB abstraction rework. Patrick Steinhardt responds to Justin Tobler’s endorsement of his proposal to move alternates handling into the "files" backend, a change that would treat alternates as an implementation detail rather than a cross-backend concern.

Patrick acknowledges Justin’s concern about losing flexibility—specifically, the ability to mix alternates of different backend types (e.g., files and reftable) in the same repository—but downplays it as a theoretical rather than practical limitation. He notes that if the need for such flexibility ever arises, it would be straightforward to introduce a new ODB source type to support it. This keeps the door open for future extensibility without complicating the current design.

The exchange reinforces the consensus around Patrick’s architectural direction, which has gained explicit support from both Justin and Peff. The proposal aims to resolve the regression by enabling pack-first-loose-second lookups across all alternates while simplifying other subsystems like commit-graph and bitmap loading. Implementation is planned for late July, though no near-term fix for the immediate performance issue has been volunteered yet. This reply is a minor but clarifying note in the thread, confirming that the proposed redesign does not preclude future flexibility.
