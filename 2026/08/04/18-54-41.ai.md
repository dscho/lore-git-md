This is Junio C Hamano's **substantive review** of Patrick Steinhardt's [PATCH 3/7] in the ODB streaming API refactoring series. Junio identifies a **critical correctness issue** in the in-memory ODB backend: the patch updates the object type passed to `odb_source_inmemory_write_object()` but does not update the object type passed to `hash_object_file()`, which still hard-codes `OBJ_BLOB`. This mismatch means the object name (`oid`) is computed as if the object were a blob, even when it is not, which could lead to silent corruption or hash collisions when streaming non-blob objects (e.g., large trees or commits) into the in-memory backend.

The review is narrowly focused on this specific bug, which Junio discovered while reading the patch in isolation (he notes he is only at patch 3/7 and has not yet reached the unification patches). The issue is not theoretical: the commit message explicitly motivates the patch by citing pathological repositories with oversized non-blob objects, and the in-memory backend is used in unit tests and by some third-party tools. The fix will likely require propagating the `stream->type` parameter into `hash_object_file()` or introducing a helper that computes the object name consistently with the intended type.

No other aspects of the patch are addressed in this reply, and Junio does not express an opinion on the broader unification goal at this stage. The review is a clear blocker for the series: the bug must be fixed before the patch can proceed.
