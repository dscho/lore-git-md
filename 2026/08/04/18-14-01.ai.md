This is the first patch in Domen Kožar's v2 series introducing `post-worktree-add`, `post-worktree-remove`, and `post-worktree-move` hooks. It implements the `post-worktree-add` hook, which fires after a new worktree is created, regardless of whether `--no-checkout` or `--orphan` is used. The hook runs in the new worktree's directory with no arguments, allowing tools to query details like the worktree path or branch via Git commands.

The patch touches `builtin/worktree.c` to add the hook invocation logic, updates `Documentation/githooks.adoc` and `Documentation/config/hook.adoc` to document the new hook, and adds comprehensive test coverage in `t/t2400-worktree-add.sh`. The hook runs unconditionally after `post-checkout`, even if `post-checkout` fails, and its exit status becomes the exit status of `git worktree add` (though a failing hook does not delete the worktree). This design choice was debated in v1 and is now settled in favor of unconditional execution.

Key technical details include the hook's environment (GIT_DIR and GIT_WORK_TREE are cleared), its placement in the execution flow (after `post-checkout`), and its behavior during failures (non-destructive but propagates exit status). The tests verify edge cases like relative worktree paths, bare repositories, and hook ordering. This patch is well-motivated and addresses a clear gap for tooling that manages ephemeral worktrees, such as AI-driven development environments. The implementation is clean and aligns with existing hook conventions.
