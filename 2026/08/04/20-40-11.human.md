This is a small but important robustness patch in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch closes a protocol hygiene gap in `fetch-object-info.c`: the client now explicitly checks that the server sends exactly the expected number of object-info lines, failing fast with a clear error message if the response is either too short or too long.

The change is mechanical and uncontroversial. It moves the packet-reading call out of the loop condition so the loop no longer consumes the final flush packet, then adds two `die()` calls: one inside the loop if the reader returns anything other than `PACKET_READ_NORMAL` before all requested objects are read, and one after the loop if the next packet is not a flush. These checks prevent the caller from using uninitialized data (under-length responses) or silently ignoring extra data (over-length responses), aligning with Git’s defensive programming practices.
