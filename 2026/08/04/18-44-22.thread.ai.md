Thread identity: user support question regarding a regression in Git’s textconv feature introduced in Git 2.50; originating author Randall S. Becker (NonStop port maintainer). The regression is confirmed to be **platform-specific to NonStop**, affecting only files beginning with a null byte, and is now further isolated to NonStop’s I/O stack behavior during tempfile creation.

Core problem or goal: since Git 2.50, external textconv filters receive an empty temporary file when processing *binary* files (those beginning with a null byte) **only on NonStop**, breaking workflows that depend on the original file path to locate repository files. Text files and ELF binaries (which do not begin with null bytes) work as expected on all platforms, including NonStop. The question remains whether this change was deliberate or a bug, and how to restore the previous behavior **specifically for NonStop**.

Current status: reported as a breaking change with a confirmed scope—empty temp files occur **only for binary files (null-byte-prefixed) on NonStop**, and the regression is now attributed to platform-specific I/O behavior (e.g., early truncation or failure to write during tempfile creation). Jeff King (Peff) and D. Ben Knoble have both confirmed they **cannot reproduce the issue** on non-NonStop platforms, even with files containing NUL bytes, reinforcing the platform-specific nature of the regression. No patch, root-cause analysis, or maintainer response addressing the regression itself. The issue remains unresolved and user-facing.

Key technical details: textconv filters now receive empty `/tmp/git-blob-*/<name>` files **only for binary files (null-byte-prefixed) on NonStop**; prior behavior passed the actual working-tree file content. The regression appears tied to null-byte handling during tempfile creation, likely involving NonStop-specific I/O behavior (e.g., early truncation or failure to write). Peff’s explanation of tempfile reuse (working-tree file passed for clean files in `git diff HEAD^` or `git diff --cached HEAD^`, tempfiles always used for `git show HEAD`) accounts for earlier inconsistencies but does not resolve the regression. The discrepancy between Randall’s and Knoble/Peff’s observations is now fully explained by **platform-specific I/O differences** rather than file content type or command context alone.
