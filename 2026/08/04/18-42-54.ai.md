This is a feature patch series (v4, nine patches) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now feature-complete and addresses all prior review feedback, including robustness fixes and architectural refinements.

The core goal remains unchanged: object type is the last piece of metadata guaranteed to match between client and server after a fetch, making it a natural fit for remote-object-info. The series adds end-to-end support—server capability advertisement, client request logic, protocol extension, and client-side parsing—while explicitly ruling out other metadata (disk size, delta base, object mode) as unreliable or context-dependent.

Key changes in v4 include:
- A new patch (5/9) converting the last error path in `fetch_object_info()` to `die()`, aligning with Git’s defensive programming practices.
- The `ask_type` flag and related machinery are now introduced in patch 7/9 (client-side parsing) rather than patch 4/9, addressing Junio’s forward-compatibility concern about premature capability handling.
- Patch 2/9 now checks for *both* under-length and over-length server responses, failing fast if the server sends more objects than requested (a protocol violation).
- The test cleanup in patch 1/9 now explicitly notes its benefit in preserving command exit statuses, addressing Junio’s observation about robustness.

The architectural refactoring (patches 3–5) replaces `struct object_info` with a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests (size and type), avoiding sentinel values and boolean flags. This design uses a single array of lightweight structs where the caller controls which fields are populated, aligning with the protocol’s transmission of raw strings (e.g., `"blob"`, `"1234"`).

Files touched span the protocol layer (`protocol-caps.c`, `serve.c`), client logic (`fetch-object-info.c`, `builtin/cat-file.c`), and documentation. Tests in `t5701` and `t1017` are updated to verify the new functionality, including edge cases like duplicate OIDs and unsupported placeholders. The series is rebased onto `master` following the merge of its predecessor (Eric Sunshine’s `ps/cat-file-remote-object-info`).

No open technical questions remain; the series is merge-ready. Reviewers familiar with the protocol subsystem may want to verify the error handling in patches 2/9 and 7/9, though the implementation follows established patterns. The changes are narrowly scoped and do not affect on-disk formats or other Git commands.
