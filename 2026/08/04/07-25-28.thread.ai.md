Thread identity
Subject: [PATCH 0/7] odb: unify streaming API
Series version: v1 (complete)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Refactor the object database (ODB) streaming API to eliminate redundancy between `odb_write_stream` and `odb_read_stream` by consolidating them into a single `odb_stream` structure. The change is purely structural, with no intended behavior changes, and is part of the ongoing ODB abstraction effort to enable pluggable backends. The series incrementally aligns the write and read stream designs: Patch 1/7 embeds the expected size in `struct odb_write_stream`, Patch 2/7 removes the `is_finished` field and adjusts loop logic in `builtin/unpack-objects.c` to infer completion from zero-byte returns, Patch 3/7 extends the write-stream infrastructure to support arbitrary object types (not just blobs), Patch 4/7 renames `struct odb_read_stream` to `struct odb_stream` in preparation for unification, Patch 5/7 merges the two structures into a single `odb_stream` that can handle both read and write operations, Patch 6/7 renames `struct read_object_fd_data` to `struct fd_stream` to reflect its expanded role in the unified API, and Patch 7/7 standardizes function names (`odb_read_stream_open()` → `odb_stream_from_object()`, `odb_write_stream_from_fd()` → `odb_stream_from_fd()`) and adds documentation clarifying file descriptor ownership semantics.

Current status
Under review; no prior versions. The series is now complete with all seven patches posted. It is based on Junio’s "10th batch" (`5b2471720c`) for the upcoming release, targeting `next` or `master` in the near term.

Key technical details
- Unified `odb_stream` structure replaces both `odb_write_stream` and `odb_read_stream`, supporting bidirectional streaming via a direction-agnostic interface.
- Patch 2/7 removes the `is_finished` field from `struct odb_write_stream` and restructures the loop in `feed_input_zstream()` (in `builtin/unpack-objects.c`) to ensure at least one byte is produced before yielding, aligning the write stream’s completion semantics with the read stream’s existing design (inferring completion from zero-byte returns).
- Patch 3/7 adds an `enum object_type type` field to `struct odb_write_stream` and updates callers (e.g., renaming `hash_blob_stream` to `hash_stream`) to reflect the new generic infrastructure. A stale comment in `odb/transaction.h` still assumes blob-only streaming and should be updated.
- Patch 5/7 introduces wrapper structures (`struct odb_stream_write` and `struct odb_stream_read`) around the new `odb_stream` base for `builtin/unpack-objects.c` and `odb/streaming.c`, replacing direct embedding of the old `odb_write_stream` data.
- Patch 6/7 renames `struct read_object_fd_data` to `struct fd_stream` in `odb/streaming.c`, along with its constructor and callback functions (`read_object_fd` → `fd_stream_read`, `close_object_fd` → `fd_stream_close`). The rename reflects the structure’s expanded role in the unified API, holding both stream state and file descriptor data.
- Patch 7/7 standardizes function names: `odb_stream_from_object()` (formerly `odb_read_stream_open()`) and `odb_stream_from_fd()` (formerly `odb_write_stream_from_fd()`). The patch documents that the caller retains ownership of the file descriptor passed to `odb_stream_from_fd()`.
- The unified `odb_stream` structure includes fields from both original structures: `size` (from `odb_write_stream`), `type` (from Patch 3/7), and the read/write function pointers and internal state from both.
- Files touched in Patch 7/7: `archive-tar.c`, `archive-zip.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `object-file.c`, `object.c`, `odb/streaming.c`, and `odb/streaming.h`.
- Cumulative files touched across all patches: 37 files.
- Symbols: `struct odb_stream`, `struct odb_stream_write`, `struct odb_stream_read`, `struct fd_stream` (formerly `struct read_object_fd_data`), `fd_stream_read()` (formerly `read_object_fd`), `fd_stream_close()` (formerly `close_object_fd`), `odb_stream_from_object()` (formerly `odb_read_stream_open()`), `odb_stream_from_fd()` (formerly `odb_write_stream_from_fd()`), `odb_stream_read()`, `odb_stream_close()`, `odb_stream_open()`, `enum object_type type`.
- Unit test `t/unit-tests/u-odb-inmemory.c` updated to match the unified API in Patch 5/7.
- No on-disk format changes; no new CLI options or config keys.
- Edge cases addressed: field initialization (ensuring `stream->size` and `stream->type` are always set before use), loop logic in `builtin/unpack-objects.c` (correctly handling zlib decompression and ensuring at least one byte is produced before yielding), wrapper allocation correctness in the two special cases, completeness of renames (no lingering references to old type or function names), and file descriptor ownership semantics (documented in Patch 7/7).

Open questions and loose ends
- Edge cases in the unified API, particularly error handling for mixed read/write operations and ensuring the new wrapper structures (`odb_stream_write`, `odb_stream_read`) and renamed `fd_stream` correctly manage the base `odb_stream` lifecycle.
- Potential performance regressions in stream-heavy code paths (e.g., `pack-objects`, archive generation) due to the additional indirection introduced by wrapper structures.
- No new tests added; existing test coverage remains limited to the in-memory backend. Pathological cases with oversized non-blob objects (e.g., large trees or commits) are noted but not yet exercised in tests.
- Reviewers may focus on completeness of the rename (no lingering references to `read_object_fd_data`, `read_object_fd`, `close_object_fd`, `odb_read_stream_open()`, or `odb_write_stream_from_fd()`) and the correctness of the wrapper allocations and `fd_stream` lifecycle management.
- The stale comment in `odb/transaction.h` (noting blob-only streaming) should be updated to reflect the new generic infrastructure.
- The series is now complete, but the final patch may still attract feedback on documentation clarity and file descriptor ownership edge cases.
