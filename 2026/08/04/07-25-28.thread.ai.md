Thread identity
Subject: [PATCH 0/7] odb: unify streaming API
Series version: v1 (complete, with planned cosmetic follow-up)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Refactor the object database (ODB) streaming API to eliminate redundancy between `odb_write_stream` and `odb_read_stream` by consolidating them into a single `odb_stream` structure. The change is purely structural, with no intended behavior changes, and is part of the ongoing ODB abstraction effort to enable pluggable backends. The series incrementally aligns the write and read stream designs: Patch 1/7 embeds the expected size in `struct odb_write_stream`, Patch 2/7 removes the `is_finished` field and adjusts loop logic in `builtin/unpack-objects.c` to infer completion from zero-byte returns, Patch 3/7 extends the write-stream infrastructure to support arbitrary object types (not just blobs), Patch 4/7 renames `struct odb_read_stream` to `struct odb_stream` in preparation for unification, Patch 5/7 merges the two structures into a single `odb_stream` that can handle both read and write operations, Patch 6/7 renames `struct read_object_fd_data` to `struct fd_stream` to reflect its expanded role in the unified API, and Patch 7/7 standardizes function names (`odb_read_stream_open()` → `odb_stream_from_object()`, `odb_write_stream_from_fd()` → `odb_stream_from_fd()`) and adds documentation clarifying file descriptor ownership semantics.

Current status
Under review; no prior versions. The series is now complete with all seven patches posted, and Patrick Steinhardt plans to add an **eighth cosmetic commit** to rename `struct input_zstream_data` (in `builtin/unpack-objects.c`) to better reflect its role as a stream wrapper (e.g., `input_zstream_stream`). This change is purely naming-related and does not affect functionality. The series is based on Junio’s "10th batch" (`5b2471720c`) for the upcoming release, targeting `next` or `master` in the near term. The **critical correctness issue** in Patch 3/7 identified by Junio C Hamano -- the in-memory ODB backend computing the object name (`oid`) using `OBJ_BLOB` even when streaming non-blob objects -- has been **fixed** in a follow-up. The fix ensures `hash_object_file()` uses `stream->type` instead of hard-coding `OBJ_BLOB`, resolving the risk of silent corruption or hash collisions. All other patches have received at least one review; Patch 7/7, the final patch, received a surface-level review from Justin Tobler confirming the rename aligns with earlier feedback and endorsing the changes as sensible. In response to Justin Tobler’s feedback, Patrick Steinhardt updated Patch 3/7 to fix a stale comment in `odb/transaction.h` that previously assumed blob-only streaming; the comment now reflects the new generic infrastructure.

Key technical details
- Unified `odb_stream` structure replaces both `odb_write_stream` and `odb_read_stream`, supporting bidirectional streaming via a direction-agnostic interface.
- Patch 2/7 removes the `is_finished` field from `struct odb_write_stream` and restructures the loop in `feed_input_zstream()` (in `builtin/unpack-objects.c`) to ensure at least one byte is produced before yielding, aligning the write stream’s completion semantics with the read stream’s existing design (inferring completion from zero-byte returns).
- Patch 3/7 adds an `enum object_type type` field to `struct odb_write_stream` and updates callers (e.g., renaming `hash_blob_stream` to `hash_stream`) to reflect the new generic infrastructure. The patch now correctly propagates `stream->type` to `hash_object_file()` in the in-memory ODB backend, fixing the critical bug that previously hard-coded `OBJ_BLOB`. A stale comment in `odb/transaction.h` (noting blob-only streaming) was updated to reflect the new generic infrastructure.
- Patch 5/7 merges `struct odb_read_stream` and `struct odb_write_stream` into `struct odb_stream` and introduces wrapper structures (`struct odb_stream_write` and `struct odb_stream_read`) around the new base for `builtin/unpack-objects.c` and `odb/streaming.c`. The patch replaces direct embedding of the old `odb_write_stream` data in `struct input_zstream_data` (in `builtin/unpack-objects.c`) and `struct read_object_fd_data` (in `odb/streaming.c`) with embedding of the new `odb_stream` base, eliminating redundancy.
- Patch 6/7 renames `struct read_object_fd_data` to `struct fd_stream` in `odb/streaming.c`, along with its constructor and callback functions (`read_object_fd` → `fd_stream_read`, `close_object_fd` → `fd_stream_close`). The rename reflects the structure’s expanded role in the unified API, holding both stream state and file descriptor data.
- Patch 7/7 standardizes function names: `odb_stream_from_object()` (formerly `odb_read_stream_open()`) and `odb_stream_from_fd()` (formerly `odb_write_stream_from_fd()`). The patch documents that the caller retains ownership of the file descriptor passed to `odb_stream_from_fd()`.
- The planned eighth commit will rename `struct input_zstream_data` (in `builtin/unpack-objects.c`) to better reflect its role as a stream wrapper (e.g., `input_zstream_stream`).
- The unified `odb_stream` structure includes fields from both original structures: `size` (from `odb_write_stream`), `type` (from Patch 3/7), and the read/write function pointers and internal state from both.
- Files touched in Patch 7/7: `archive-tar.c`, `archive-zip.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `object-file.c`, `object.c`, `odb/streaming.c`, and `odb/streaming.h`.
- Cumulative files touched across all patches: 37 files (including the updated `odb/transaction.h` in Patch 3/7).
- Symbols: `struct odb_stream`, `struct odb_stream_write`, `struct odb_stream_read`, `struct fd_stream` (formerly `struct read_object_fd_data`), `fd_stream_read()` (formerly `read_object_fd`), `fd_stream_close()` (formerly `close_object_fd`), `odb_stream_from_object()` (formerly `odb_read_stream_open()`), `odb_stream_from_fd()` (formerly `odb_write_stream_from_fd()`), `odb_stream_read()`, `odb_stream_close()`, `odb_stream_open()`, `enum object_type type`, `struct input_zstream_data` (target of planned rename), `write_object_stream` callback.
- Unit test `t/unit-tests/u-odb-inmemory.c` updated to match the unified API in Patch 5/7.
- No on-disk format changes; no new CLI options or config keys.
- Edge cases addressed: field initialization (ensuring `stream->size` and `stream->type` are always set before use), loop logic in `builtin/unpack-objects.c` (correctly handling zlib decompression and ensuring at least one byte is produced before yielding), wrapper allocation correctness in the two special cases, completeness of renames (no lingering references to old type or function names), file descriptor ownership semantics (documented in Patch 7/7), stale comment updates (in `odb/transaction.h`), and the critical bug fix in Patch 3/7 (propagating `stream->type` to `hash_object_file()`).

Open questions and loose ends
- Edge cases in the unified API, particularly error handling for mixed read/write operations and ensuring the new wrapper structures (`odb_stream_write`, `odb_stream_read`) and renamed `fd_stream` correctly manage the base `odb_stream` lifecycle.
- Potential performance regressions in stream-heavy code paths (e.g., `pack-objects`, archive generation) due to the additional indirection introduced by wrapper structures.
- No new tests added; existing test coverage remains limited to the in-memory backend. Pathological cases with oversized non-blob objects (e.g., large trees or commits) are noted but not yet exercised in tests.
- The planned eighth commit to rename `struct input_zstream_data` (in `builtin/unpack-objects.c`) to better reflect its role as a stream wrapper (e.g., `input_zstream_stream`). This change is purely cosmetic and does not affect functionality, but it may prompt minor follow-up discussion about naming conventions in the unified API.
- Patch 7/7’s documentation of file descriptor ownership may attract further feedback on edge cases (e.g., descriptor leaks, double-close scenarios).

Participant positions
Justin Tobler provided **substantive reviews** of Patches 2/7, 3/7, and 5/7, confirming the removal of the `is_finished` field and the loop restructuring in `builtin/unpack-objects.c` align the write stream’s behavior with the read stream’s design, noting the addition of the `type` field and mechanical updates to callers prepare the API for unification, and raising naming consistency questions for the wrapper structures and functions introduced in Patch 5/7 (specifically, whether `struct input_zstream_data` should be renamed to better reflect its role as a stream wrapper). His feedback on these patches was positive and detailed, addressing core logic, edge-case handling, and documentation gaps (e.g., the stale comment in `odb/transaction.h`). Justin also provided **surface-level reviews** of Patches 1/7, 6/7, and 7/7, endorsing the approach in Patch 1/7 ("Storing the object size in the stream directly makes complete sense"), confirming the rename in Patch 6/7 aligns with his earlier feedback on Patch 5/7, and endorsing the function renames and documentation in Patch 7/7 as sensible, but not engaging with edge cases or broader API design.
Junio C Hamano provided a **substantive review** of Patch 3/7, identifying a **critical correctness issue** in the in-memory ODB backend: the patch updates the object type passed to `odb_source_inmemory_write_object()` but does not update the object type passed to `hash_object_file()`, which still hard-codes `OBJ_BLOB`. This mismatch causes the object name (`oid`) to be computed incorrectly for non-blob objects, potentially leading to silent corruption or hash collisions. The issue was confirmed by Patrick Steinhardt as a blocker and has since been **fixed** by propagating `stream->type` to `hash_object_file()`. No other aspects of the patch or the broader unification goal are addressed in this review.
Patrick Steinhardt acknowledged Justin Tobler’s naming consistency feedback regarding `struct input_zstream_data` and confirmed the rename was intentionally deferred to minimize churn in Patch 5/7. He now plans to add an eighth cosmetic commit to address this, though the exact name (e.g., `input_zstream_stream`) is not yet specified. The change is purely cosmetic and does not affect functionality. In response to Justin’s feedback, Patrick also updated Patch 3/7 to fix the stale comment in `odb/transaction.h` that previously assumed blob-only streaming.
