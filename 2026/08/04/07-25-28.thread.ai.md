Thread identity
Subject: [PATCH 0/7] odb: unify streaming API
Series version: v1 (initial)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Refactor the object database (ODB) streaming API to eliminate redundancy between `odb_write_stream` and `odb_read_stream` by consolidating them into a single `odb_stream` structure. The change is purely structural, with no intended behavior changes, and is part of the ongoing ODB abstraction effort to enable pluggable backends. The series incrementally aligns the write and read stream designs: Patch 1/7 embeds the expected size in `struct odb_write_stream`, and Patch 2/7 removes the `is_finished` field, replacing it with direct checks on the stream’s read function return value or internal state.

Current status
Under review; no prior versions. The series is based on Junio’s "10th batch" (`5b2471720c`) for the upcoming release, targeting `next` or `master` in the near term.

Key technical details
- Unified `odb_stream` structure (introduced in later patches) will replace both `odb_write_stream` and `odb_read_stream`.
- Patch 1/7 moves the write stream’s expected size from a separate `size_t` parameter into `struct odb_write_stream`, making the stream self-describing.
- Patch 2/7 removes the `is_finished` field from `struct odb_write_stream`, replacing its use with direct checks on the stream’s read function return value (zero bytes read) or internal state (e.g., `data->remaining` or `data->status`).
- Files touched: 23 files total across the series; Patch 1/7 updates 14 files, Patch 2/7 updates 7 files, including `odb/streaming.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, `object-file.c`, `builtin/unpack-objects.c`, and the unit test `t/unit-tests/u-odb-inmemory.c`.
- Symbols: `odb_stream` (later in series), `odb_stream_open()` (later in series), `struct odb_write_stream` (now includes `size` field and lacks `is_finished` field).
- Unit test `t/unit-tests/u-odb-inmemory.c` updated in both patches to match the new API.
- No on-disk format changes; no new CLI options or config keys.

Open questions and loose ends
- Edge cases in the unified API, particularly error handling for mixed read/write operations (e.g., ensuring `stream->size` is always set before use and that the new loop logic in `builtin/unpack-objects.c` correctly handles zlib decompression).
- Potential performance regressions in stream-heavy code paths (e.g., `pack-objects`, archive generation).
- No new tests added; existing test coverage is limited to the in-memory backend.

Participant positions
None yet; the series remains under initial review. The first two patches are mechanical refactors and are expected to be uncontroversial, though reviewers may focus on edge cases (e.g., size field initialization, loop logic in `builtin/unpack-objects.c`).
