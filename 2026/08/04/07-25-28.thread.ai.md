Subject: [PATCH 0/7] odb: unify streaming API
Series version: v2 (complete, eight patches)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Refactor the object database (ODB) streaming API to eliminate redundancy between `odb_write_stream` and `odb_read_stream` by consolidating them into a single `odb_stream` structure. The change is purely structural, with no intended behavior changes, and is part of the ongoing ODB abstraction effort to enable pluggable backends. The series incrementally aligns the write and read stream designs: Patch 1/8 embeds the expected size in `struct odb_write_stream`, Patch 2/8 removes the `is_finished` field and adjusts loop logic in `builtin/unpack-objects.c` to infer completion from zero-byte returns, Patch 3/8 extends the write-stream infrastructure to support arbitrary object types (not just blobs) and fixes the critical bug in the in-memory ODB backend by propagating `stream->type` to `hash_object_file()`, Patch 4/8 renames `struct odb_read_stream` to `struct odb_stream` in preparation for unification, **Patch 5/8 merges the two structures into a single `odb_stream` that can handle both read and write operations, introducing wrapper structures (`struct odb_stream_write` and `struct odb_stream_read`) for the two special cases in `builtin/unpack-objects.c` and `odb/streaming.c`**, Patch 6/8 renames `struct read_object_fd_data` to `struct fd_stream` to reflect its expanded role in the unified API, Patch 7/8 renames `struct input_zstream_data` to `struct zlib_stream` to better reflect its role as a stream wrapper after the API unification, and **Patch 8/8 standardizes function names (`odb_stream_from_object()` and `odb_stream_from_fd()`) and adds documentation clarifying file descriptor ownership semantics, completing the series.**

Key technical details
- Unified `odb_stream` structure replaces both `odb_write_stream` and `odb_read_stream`, supporting bidirectional streaming via a direction-agnostic interface.
- Patch 1/8 embeds the `size` field in `struct odb_write_stream` and updates all callers (14 files) to use `stream->size` instead of passing the size as a separate argument.
- Patch 2/8 removes the `is_finished` field from `struct odb_write_stream` and restructures the loop in `feed_input_zstream()` to ensure at least one byte is produced before yielding, addressing edge cases in zlib decompression.
- Patch 3/8 adds an `enum object_type type` field to `struct odb_write_stream` and propagates `stream->type` to `hash_object_file()`, fixing the critical bug in the in-memory ODB backend. The stale comment in `odb/transaction.h` was updated to reflect the new generic infrastructure.
- Patch 4/8 renames `struct odb_read_stream` to `struct odb_stream` across 18 files, preparing for unification.
- **Patch 5/8 merges the two structures into a single `odb_stream` and introduces wrapper structures (`struct odb_stream_write` and `struct odb_stream_read`) for the two special cases in `builtin/unpack-objects.c` and `odb/streaming.c`. The patch replaces direct embedding of the old structures with embedding of the new `odb_stream` base, requiring allocation and container-of access.**
- Patch 6/8 renames `struct read_object_fd_data` to `struct fd_stream` in `odb/streaming.c`, along with its constructor and callback functions (`read_object_fd` → `fd_stream_read`, `close_object_fd` → `fd_stream_close`).
- **Patch 7/8 renames `struct input_zstream_data` to `struct zlib_stream` in `builtin/unpack-objects.c` to better reflect its role as a stream wrapper, updating the structure definition, its constructor (`in_stream`), and the callback function (`feed_input_zstream` → `zlib_stream_read`).**
- **Patch 8/8 standardizes function names: `odb_stream_from_object()` (formerly `odb_read_stream_open()`) and `odb_stream_from_fd()` (formerly `odb_write_stream_from_fd()`). The patch documents that the caller retains ownership of the file descriptor passed to `odb_stream_from_fd()`.**
- Files touched in Patch 8/8: `archive-tar.c`, `archive-zip.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `object-file.c`, `object.c`, `odb/streaming.c`, and `odb/streaming.h`.
- Cumulative files touched across all patches: 38 files (including the updated `odb/transaction.h` in Patch 3/8).
- Symbols: `struct odb_stream`, `struct odb_stream_write`, `struct odb_stream_read`, `struct fd_stream` (formerly `struct read_object_fd_data`), `struct zlib_stream` (formerly `struct input_zstream_data`), `fd_stream_read()`, `fd_stream_close()`, `zlib_stream_read()`, `odb_stream_from_object()`, `odb_stream_from_fd()`, `odb_stream_read()`, `odb_stream_close()`, `odb_stream_open()`, `enum object_type type`, `write_object_stream` callback.
- Unit test `t/unit-tests/u-odb-inmemory.c` updated to match the unified API in Patch 5/8.
- No on-disk format changes; no new CLI options or config keys.
- Edge cases addressed: field initialization (ensuring `stream->size` and `stream->type` are always set before use), loop logic in `builtin/unpack-objects.c` (correctly handling zlib decompression), wrapper allocation correctness in the two special cases, completeness of renames (no lingering references to old type or function names), file descriptor ownership semantics (documented in Patch 8/8), stale comment updates (in `odb/transaction.h`), and the critical bug fix in Patch 3/8 (propagating `stream->type` to `hash_object_file()`).

Open questions and loose ends
- Edge cases in the unified API, particularly error handling for mixed read/write operations and ensuring the new wrapper structures (`odb_stream_write`, `odb_stream_read`) and renamed `fd_stream`/`zlib_stream` correctly manage the base `odb_stream` lifecycle.
- Potential performance regressions in stream-heavy code paths (e.g., `pack-objects`, archive generation) due to the additional indirection introduced by wrapper structures.
- No new tests added; existing test coverage remains limited to the in-memory backend. Pathological cases with oversized non-blob objects (e.g., large trees or commits) are noted but not yet exercised in tests.
- The documentation of file descriptor ownership in Patch 8/8 may attract further feedback on edge cases (e.g., descriptor leaks, double-close scenarios).
- The wrapper structures in Patch 5/8 (`struct odb_stream_write` and `struct odb_stream_read`) and their allocation logic may attract scrutiny from reviewers to ensure the container-of pattern is used correctly and no memory leaks or double-frees are introduced.
- The renames in Patches 6/8 (`fd_stream`) and 7/8 (`zlib_stream`) are cosmetic but may prompt feedback on naming clarity.

Participant positions
Justin Tobler provided **substantive reviews** of Patches 2/7, 3/7, and 5/7 in v1, confirming the removal of the `is_finished` field and the loop restructuring in `builtin/unpack-objects.c` align the write stream’s behavior with the read stream’s design, noting the addition of the `type` field and mechanical updates to callers prepare the API for unification, and raising naming consistency questions for the wrapper structures and functions introduced in Patch 5/7 (specifically, whether `struct input_zstream_data` should be renamed to better reflect its role as a stream wrapper). His feedback on these patches was positive and detailed, addressing core logic, edge-case handling, and documentation gaps (e.g., the stale comment in `odb/transaction.h`). Justin also provided **surface-level reviews** of Patches 1/7, 6/7, and 7/7 in v1, endorsing the approach in Patch 1/7 ("Storing the object size in the stream directly makes complete sense"), confirming the rename in Patch 6/7 aligns with his earlier feedback on Patch 5/7, and endorsing the function renames and documentation in Patch 7/7 as sensible, but not engaging with edge cases or broader API design. **In v2, Justin’s feedback on Patches 6/8 and 7/8 is now addressed by the renames, and his earlier naming consistency feedback is fully incorporated.**
Junio C Hamano provided a **substantive review** of Patch 3/7 in v1, identifying a **critical correctness issue** in the in-memory ODB backend: the patch updates the object type passed to `odb_source_inmemory_write_object()` but does not update the object type passed to `hash_object_file()`, which still hard-codes `OBJ_BLOB`. This mismatch causes the object name (`oid`) to be computed incorrectly for non-blob objects, potentially leading to silent corruption or hash collisions. The issue was confirmed by Patrick Steinhardt as a blocker and has since been **fixed** in v2 by propagating `stream->type` to `hash_object_file()`.
Patrick Steinhardt acknowledged Justin Tobler’s naming consistency feedback regarding `struct input_zstream_data` and confirmed the rename was intentionally deferred to minimize churn in Patch 5/7. He has now addressed this in v2 with Patch 7/8, renaming the structure to `struct zlib_stream`. In response to Justin’s feedback, Patrick also updated Patch 3/8 to fix the stale comment in `odb/transaction.h` that previously assumed blob-only streaming. The series is now complete and ready for final review.
