This thread is about a bugfix for the `contrib/credential/libsecret` credential helper, which currently crashes and silently loses data when credential items are locked or deleted concurrently. Daniel Martí posted a patch two weeks ago that replaces the `SECRET_SEARCH_LOAD_SECRETS` flag with explicit error handling to prevent these issues. The patch is self-contained and touches only the libsecret helper, with no test coverage due to the difficulty of reproducing the race condition.

Junio C Hamano, the maintainer, has now reviewed the patch and proposed an alternative approach. While he agrees the crash and data loss need fixing, he suggests a more conservative solution: keep the `SECRET_SEARCH_LOAD_SECRETS` flag for its batch-fetch optimization (since the race is rare) and only fall back to explicit loading if `secret_item_get_secret()` returns NULL. This preserves performance for the common case while still addressing the crash. The discussion is now focused on whether the original patch’s more aggressive change (dropping the flag entirely) is justified, or if Junio’s incremental fix is preferable. The patch remains under review, awaiting a response or v2 from Daniel.
