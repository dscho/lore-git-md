This is a bugfix for the `contrib/credential/libsecret` helper, targeting a crash and silent data loss in the GNOME keyring credential storage backend.

The patch addresses a flaw in how the libsecret helper retrieves stored credentials. Currently, `secret_service_search_sync()` is called with `SECRET_SEARCH_LOAD_SECRETS`, but this flag does not guarantee that secrets are actually loaded: the search silently discards failures, and the GNOME keyring daemon omits locked or concurrently deleted items from its reply. When the helper later calls `secret_value_get_text()` or `secret_value_unref()` on a NULL secret, it triggers assertion failures, losing the password even if it was still retrievable.

The fix removes the `SECRET_SEARCH_LOAD_SECRETS` flag and instead loads the secret of the matched item explicitly with `secret_item_load_secret_sync()`, which properly reports errors. This ensures that genuinely inaccessible items produce a useful error message rather than assertion spew, and that secrets the search would have silently dropped are now retrieved normally. The change does not increase the number of round-trips to the keyring daemon, since the search no longer batch-fetches secrets for all matching items.

The patch touches only `contrib/credential/libsecret/git-credential-libsecret.c`, adding 13 lines and removing 1. It is a standalone fix with no dependencies on other patches or ongoing efforts. The commit message is clear and detailed, explaining both the problem and the solution. No tests are included, but the change is small and self-contained, and the problem it fixes is easy to reproduce with concurrent credential operations.
