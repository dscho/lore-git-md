This is a bugfix patch targeting the `git worktree add` command.

The patch addresses a regression introduced in Git v2.42.0 where `git worktree add -b <new-branch> <path> <branch>` would still perform DWIM (Do What I Mean) resolution on `<branch>`, effectively ignoring the `-b` option and creating a worktree tracking the wrong branch. The commit message clearly identifies the problematic commit (128e5496b325640f0a09cc1d5b1e346c069b410f) and explains the expected behavior: when `-b` or `-B` is given, DWIM should not occur.

The fix itself is minimal: a one-line change in `builtin/worktree.c` that adds a check for `!new_branch` to prevent DWIM when a new branch is explicitly specified. The patch also includes a new test case in `t/t2400-worktree-add.sh` that verifies the corrected behavior by ensuring `git worktree add -b branch ../foo foo` fails when `foo` would otherwise be DWIM-resolved.

The patch is well-motivated and narrowly scoped, addressing a clear regression with a targeted fix and test coverage. It looks like a straightforward candidate for merging.
