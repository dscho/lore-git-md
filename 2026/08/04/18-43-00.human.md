This is the sixth patch in Pablo Sabater’s nine-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now at v4, feature-complete, and under active review.

This patch teaches the server-side object-info handler to accept "type" as a requested field. When the client includes "type" in its object-info request, the server returns the object type alongside the existing size field. The implementation is straightforward: a new `type` bit field is added to `struct requested_info`, the server parses the "type" keyword in client requests, and the response includes the type name (e.g., "blob") when requested. The patch also cleans up minor style issues (bit field formatting, line wrapping) in the surrounding code.

The test in `t5701` verifies the end-to-end flow: the client requests both "size" and "type" for the same OID twice, and the server responds with the expected output (`$oid $size blob`). The test confirms that duplicate OIDs are handled correctly and that the server’s response matches the requested fields.

This patch is a key building block for the series’ overall goal—enabling clients to fetch object type metadata from the server, the last piece of metadata guaranteed to match after a fetch. The implementation follows the established pattern from the predecessor series (Eric Sunshine’s `ps/cat-file-remote-object-info`), and the changes are narrowly scoped to the protocol layer. No open questions or review feedback remain on this patch; it appears ready for integration.
