This is the seventh patch in Pablo Sabater’s nine-patch GSoC series (v4) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now feature-complete and under final review.

This patch teaches the client to parse object type data from the server’s response. It adds a `wants_type` flag and a `types` array to `struct fetch_object_info_results`, mirroring the existing `wants_size`/`sizes` machinery. When the server sends a "type" attribute, the client maps the string (e.g., `"blob"`) to Git’s internal `enum object_type` using `type_from_string_gently()`, and stores the result in the `types` array. A safety check `die()`s if the server sends an invalid type string, matching the existing behavior for malformed size data.

The patch is narrowly scoped and uncontroversial. It builds directly on the architectural refactoring in earlier patches (notably the introduction of `struct fetch_object_info_results` in patch 4/9) and prepares the client for the server-side capability advertisement in patch 8/9. No open questions remain; the implementation follows established patterns for protocol handling and error reporting. Reviewers familiar with the protocol subsystem may want to verify the error handling, though the approach is consistent with the rest of the series. The patch is ready for merging.
