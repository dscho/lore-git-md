This is the third patch in Patrick Steinhardt’s seven-patch series refactoring the object database (ODB) streaming API. It extends the write-stream infrastructure to support arbitrary object types (not just blobs), a prerequisite for unifying `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure later in the series.

The patch adds an `enum object_type type` field to `struct odb_write_stream` and updates all callers to pass the object type explicitly. The primary changes are mechanical: renaming functions (e.g., `hash_blob_stream` → `hash_stream`, `stream_blob_to_pack` → `stream_to_pack`) and updating error messages to reflect the broader scope ("object data" instead of "blob data"). The patch touches seven files, including core object handling (`object-file.c`), ODB backends (`odb/source-inmemory.c`, `odb/source-loose.c`), and the unit test (`t/unit-tests/u-odb-inmemory.c`). No new functionality is exposed yet—this is purely preparatory work for the unified API.

The motivation is clear: the current limitation to blobs is artificial, and supporting other object types (e.g., large trees or commits) aligns the write stream’s design with the read stream, simplifying the eventual unification. The commit message notes that while such cases are rare, users have been known to create pathological repositories with oversized non-blob objects. The changes are straightforward and unlikely to be controversial, though reviewers may focus on edge cases like ensuring the `type` field is always initialized before use (e.g., in `builtin/unpack-objects.c`).

This patch is a logical next step after the first two (which embedded the stream size and removed the `is_finished` field), and it sets the stage for the later patches that introduce the unified `odb_stream` structure. The series remains part of the broader ODB abstraction effort, with no behavior changes or new user-facing features.
