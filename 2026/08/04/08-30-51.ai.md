This is the **core implementation patch (4/4) of the `git history squash` feature** in its **v12 iteration**, now **technically complete** and ready for integration. The patch introduces a new subcommand that folds a commit range into its oldest commit while preserving descendant history, addressing a long-standing workflow gap where users had to resort to manual `git rebase -i` or `git reset --soft`/`git commit --amend` sequences.

The implementation is **robust and well-tested**, incorporating all feedback from Phillip Wood’s **substantive review** of v10 and v11. Key features include:
- **Single-pass range validation** using object flags (`SQUASH_SEEN`, `SQUASH_TIP`) to reject root commits, multiple tips, and ranges with external parents, improving error messages and efficiency.
- **Merge-parent preservation**: The squashed commit retains the full parent list of the original merge commit (the first commit in the range), preventing silent history corruption.
- **Autosquash message handling**: Resolves `fixup!`, `squash!`, and `amend!` targets during the range walk, enforcing stricter rules to prevent accidental message loss. Supports nested fixups (e.g., `fixup! fixup! target`) and preserves `amend!` messages when squashing into a `fixup!`.
- **Ref-handling**: Protects all local branches descended from the squashed range by default, with `--update-refs=head` to restrict updates to the current branch. Tags and remote-tracking refs are left unchanged.
- **Editor template**: Builds an autosquash-style template matching `git rebase -i --autosquash`, grouping markers under their targets and commenting out `fixup!` messages while preserving `squash!` and `amend!` bodies.
- **Rev-list option sanitization**: Standardizes walk settings (e.g., `--reverse --topo-order`) and warns when user-provided options would alter the range walk.
