This is the fifth and final patch in Patrick Steinhardt’s v2 series making the creation of on-disk object database (ODB) structures pluggable. It introduces a `create_on_disk` callback to the ODB source interface, allowing each backend to handle its own directory setup. The patch is part of the ongoing ODB abstraction effort and is a prerequisite for future non-filesystem backends.

The change moves the creation of backend-specific directories (`objects/pack`, `objects/info`) from the generic `create_object_database()` function into the "files" backend’s `create_on_disk` callback. The top-level `objects/` directory remains hardcoded and is created unconditionally (unless overridden by an environment variable), as it is required for repository discovery regardless of backend. The patch touches three files: `odb/source-files.c` (implements the callback), `odb/source.h` (declares the interface), and `setup.c` (replaces hardcoded directory creation with the new callback).

The implementation is straightforward: the "files" backend’s callback creates `pack/` and `info/` subdirectories, while the generic `odb_source_create_on_disk()` helper invokes the callback if it exists. The callback name (`create_on_disk`) was retained for consistency with the ref subsystem’s `ref_store_create_on_disk()`, despite Junio’s earlier suggestion to use a more generic term like `initialize`. This decision was pragmatic and not controversial in the v2 discussion.

This patch is uncontroversial and ready for merging. It has no user-visible impact but is a critical step toward enabling custom ODB backends. The only open question from v1—whether the callback name should be more generic—was deferred in favor of consistency, and no new concerns were raised in the v2 review. The patch is well-motivated, with clear commit message and code comments explaining the design choices.
