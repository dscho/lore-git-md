This is the second patch in Patrick Steinhardt’s seven-patch series refactoring the object database (ODB) streaming API. It removes the `is_finished` field from `struct odb_write_stream`, replacing its use with direct checks on the stream’s read function return value (zero bytes read) or internal state (e.g., `data->remaining` or `data->status`). The change is mechanical and aligns the write stream’s design with the read stream, which already lacks an explicit `is_finished` flag.

The patch touches seven files, including core ODB logic (`odb/streaming.c`, `odb/source-inmemory.c`, `odb/source-loose.c`), callers in `object-file.c` and `builtin/unpack-objects.c`, and the unit test `t/unit-tests/u-odb-inmemory.c`. The diff is straightforward: each site that previously checked `stream->is_finished` is updated to use a local `is_finished` variable or a loop condition based on the read function’s return value. The only non-trivial adjustment is in `builtin/unpack-objects.c`, where the zlib decompression loop is restructured to ensure at least one byte is produced before yielding.

This is a clean, incremental step toward the series’ goal of unifying the read and write stream APIs. The change is uncontroversial in principle, but reviewers may scrutinize edge cases—particularly in `object-file.c` and `builtin/unpack-objects.c`, where the new loop logic replaces the former `is_finished` flag. No behavior changes are intended, and the patch maintains compatibility with existing callers. The unit test update ensures the in-memory backend’s test coverage remains valid.
