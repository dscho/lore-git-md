This is the third patch in Domen Kožar's v2 series introducing `post-worktree-add`, `post-worktree-remove`, and `post-worktree-move` hooks. The series targets the worktree subsystem and aims to provide reliable automation triggers for worktree lifecycle events, particularly for tooling that creates and destroys worktrees frequently (e.g., AI-driven development environments).

This patch specifically extends the `post-worktree-remove` hook to run during `git worktree prune`, ensuring that tooling can observe worktree deletions even when the worktree directory is removed manually rather than via `git worktree remove`. The hook is invoked once for each administrative entry pruned, including duplicates, and receives the worktree's absolute path and identifier as arguments. If the path cannot be determined (e.g., due to a missing or corrupt gitdir file), the hook receives an empty string for the path. The hook's exit status is propagated to `git worktree prune`, though it does not affect the prune operation itself.

The implementation touches `builtin/worktree.c` (modifying `prune_worktree`, `prune_dups`, and `prune_worktrees` to return exit status and invoke the hook), updates `worktree.c` to ensure `should_prune_worktree` always returns the worktree path (even for pruned entries), and adds comprehensive test coverage in `t/t2401-worktree-prune.sh`. The documentation in `Documentation/githooks.adoc` is updated to clarify the hook's behavior during pruning, including the edge case of undetermined paths.

The patch is technically sound and addresses a real gap in Git's automation story. The changes are well-motivated, and the test coverage is thorough, including edge cases like dry runs, duplicate entries, and relative worktrees. The only loose end from the thread context—how to handle path resolution for pruned worktrees with missing gitdir files—is explicitly documented here (hook receives an empty string). This patch is likely to be uncontroversial, as it aligns with the series' goal of providing consistent automation triggers for all worktree removal paths.
