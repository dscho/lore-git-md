This is the fourth patch in Pablo Sabater’s nine-patch GSoC series (v4) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now feature-complete and under active review.

This patch replaces the `struct object_info` used by `fetch_object_info()` with a dedicated `struct fetch_object_info_results`. The old struct was designed for `read_object_info()`, which fills in optional outputs for a single object; using it for batch queries meant allocating one scalar per object per attribute just to have pointers to point at. The new struct holds only the fields the caller actually wants (currently size, with type coming in a later patch), using a single array per attribute. The caller sets `wants_*` flags to indicate interest, and the function allocates arrays only for the attributes the server both advertised and answered. A helper function (`free_fetch_object_info_results()`) releases the arrays.

The change also drops the `object_info_options` string list and `remote_atom_map[]`, since filtering against the server’s advertisement now happens locally via `ask_*` flags. The patch touches seven files, with the bulk of the work in `fetch-object-info.c` and `builtin/cat-file.c`. The commit message is clear and the code looks clean; no open questions remain on this patch. It is a refactoring that paves the way for the object-type support added in later patches.
