This is the third patch in Patrick Steinhardt’s seven-patch series refactoring the object database (ODB) streaming API, part of the ongoing ODB abstraction effort. The patch removes the artificial restriction that streaming writes are only allowed for blobs, extending the infrastructure to support any object type (commit, tree, tag, or blob). While the commit message notes that huge non-blob objects are rare, the change future-proofs the API and brings the write stream closer in design to the read stream, a prerequisite for the eventual unification into a single `odb_stream` structure.

The patch is mechanical and well-scoped: it adds an `enum object_type type` field to `struct odb_write_stream`, propagates the type through all callers (notably `object-file.c`, `builtin/unpack-objects.c`, and the in-memory and loose backends), and renames functions to reflect their broader scope (`hash_blob_stream` → `hash_stream`, `stream_blob_to_pack` → `stream_to_pack`). The unit test is updated to match the new API. No behavior changes are intended, and the patch does not introduce new CLI options, config keys, or on-disk format changes.

This looks like a solid, uncontroversial step in the series. The only likely discussion points are edge cases around type validation (e.g., ensuring callers don’t pass invalid types) and whether the new field is always initialized before use—both of which should be easy to verify during review. The patch is incremental and aligns with the series’ goal of unifying the read and write streams.
