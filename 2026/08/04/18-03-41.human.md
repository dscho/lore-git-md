This is a **substantive review** of the third patch in Patrick Steinhardt’s seven-patch series refactoring Git’s object database (ODB) streaming API. The series aims to unify `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure as part of the broader ODB abstraction effort.

Justin Tobler’s review is positive and focuses on the patch’s core goal: extending the write-stream infrastructure to support arbitrary object types (not just blobs). He notes that the change is a logical step toward unifying the read and write APIs, though the current patch doesn’t yet expose this functionality to callers—it’s purely preparatory. The review highlights a minor oversight: an outdated comment in `odb/transaction.h` that still refers to blob-specific streaming, which should be updated to reflect the new generic design. Justin also observes that while the infrastructure is now generic, the immediate use case (in `index_fd`) still targets blobs, which is fine for now.

The patch itself is mechanical but well-motivated. It adds an `enum object_type type` field to `struct odb_write_stream`, renames functions (e.g., `hash_blob_stream` → `hash_stream`), and updates error messages to use "object data" instead of "blob data." The changes touch seven files, including core object handling (`object-file.c`), ODB backends, and a unit test. No behavior changes are introduced, and the patch is unlikely to be controversial, though reviewers may check for edge cases like ensuring the `type` field is always initialized before use.

This patch is a small but necessary step in the series, setting the stage for the later unification of the read and write stream APIs. The review suggests the patch is on track, with only a minor documentation nit to address. The series remains under active review, with no prior versions posted.
