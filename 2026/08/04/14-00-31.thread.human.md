This thread is about a regression fix for `git worktree add` where the `-b` or `-B` options were being ignored when a branch name could be DWIMmed to a remote-tracking branch. The issue, introduced in Git v2.42.0, caused unintended branch creation when users explicitly specified a branch name with `-b` or `-B`.

Yoichi Nakayama posted an initial patch to address the problem, which Junio C Hamano reviewed with substantive feedback. Junio pointed out that the fix risked suppressing important warnings when `-b` was used with `HEAD` and suggested improvements to the test case. Yoichi responded with a revised patch (v2) that narrows the fix to preserve warning behavior while still disabling DWIM when `-b` or `-B` is given. The test case has also been refined to remove redundant setup and validate the expected error message.

The patch is now well-scoped, with clear test coverage and no remaining controversy. It touches only `builtin/worktree.c` and the test suite, avoiding broader behavioral changes. The fix appears ready for integration once the final refinements are confirmed.
