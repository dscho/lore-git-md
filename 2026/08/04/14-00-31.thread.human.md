This thread is about fixing a regression in `git worktree add` where the `-b` or `-B` options were being ignored when a branch name could be DWIMmed to a remote-tracking branch. The goal is to ensure that explicit branch creation options take precedence over DWIM behavior, preventing unintended branch creation.

Yoichi Nakayama posted a patch to address this, but Junio C Hamano raised concerns about unintended side effects—specifically, that the fix might suppress warnings when `-b` is used with `HEAD`. Yoichi has now responded with a plan to adjust the fix to preserve this warning behavior, while also improving the test case by removing redundant setup and adding checks for the expected error message. The discussion is collaborative and focused on refining the implementation, with no major disagreements.

The patch touches `builtin/worktree.c` and adds a test case in `t/t2400-worktree-add.sh`. The regression was introduced in Git v2.42.0, and the fix aims to restore the intended behavior without introducing new issues. The patch is still under review, with no merge status reported yet.
