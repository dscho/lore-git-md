This thread is about a bugfix for `git worktree add` that restores the intended behavior when the `-b` or `-B` options are used. The regression, introduced in Git 2.42.0, caused these options to be ignored when a branch name could be DWIMmed to a remote-tracking branch, leading to unintended branch creation.

Yoichi Nakayama posted a patch (now at v3) that surgically fixes the issue by ensuring explicit branch creation options take precedence over DWIM. Junio C Hamano reviewed the earlier versions, identifying edge cases and test improvements, all of which have been addressed in the final patch. Junio has now given his final sign-off, approving the patch for merging. The fix is minimal, narrowly scoped to the regression, and includes a test case to verify the corrected behavior.

The patch touches `builtin/worktree.c` and adds a test in `t/t2400-worktree-add.sh`. It preserves warning behavior for edge cases (like invalid references) and restores the pre-regression behavior without side effects. The regression was introduced by commit `128e5496b3` in May 2023. With all feedback incorporated and Junio’s approval, the patch is effectively merged and will appear in the next integration cycle. No further discussion or controversy is expected.
