This thread is about a bugfix for a regression in `git worktree add` where the `-b` or `-B` options were being ignored when a branch name could be DWIMmed to a remote-tracking branch. The regression, introduced in Git v2.42.0, caused the command to prioritize DWIM behavior over the user's explicit branch specification, leading to unintended branch creation.

Yoichi Nakayama posted a third version of the patch, which surgically addresses the issue by ensuring DWIM logic only triggers when no explicit branch name is provided (`-b`/`-B`). The fix preserves warning behavior for edge cases (like using `-b` with `HEAD`) and includes a refined test case that verifies the expected error message. Junio C Hamano's feedback from earlier versions has been fully incorporated, and the patch is now narrowly scoped to the regression with no unintended side effects.

The patch touches `builtin/worktree.c` and adds a test in `t/t2400-worktree-add.sh`. It restores the pre-v2.42.0 behavior where explicit `-b`/`-B` takes precedence over DWIM. The discussion has converged, and the patch appears ready for integration, pending final confirmation. No open questions or controversy remain.
