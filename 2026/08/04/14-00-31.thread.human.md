This thread is about a small but important bugfix for `git worktree add`. The issue was that when you used `-b` or `-B` to create a new branch, Git would sometimes ignore your explicit branch name and instead "DWIM" (Do What I Mean) it to a remote-tracking branch, which wasn't what users expected. This regression was introduced in Git 2.42.0.

Yoichi Nakayama sent a patch to fix it, and after a few iterations of review and testing, Junio C Hamano merged it to `master` around July 10, 2024. The fix itself is simple: in `builtin/worktree.c`, the DWIM logic is now skipped when a branch name is explicitly provided via `-b` or `-B`. The test suite was updated with a new test case to verify the corrected behavior. The latest version (v4) was just a documentation tweak to the commit message, ensuring it cites the regression commit in the project-preferred format. No further changes are expected, and the fix is uncontroversial.
