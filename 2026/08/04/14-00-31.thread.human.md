This thread is about a bugfix for `git worktree add` that addresses a regression where the `-b` or `-B` options were ignored when a branch name could be DWIMmed to a remote-tracking branch. The patch, submitted by Yoichi NAKAYAMA, aims to ensure that explicit branch creation options take precedence over DWIM behavior.

Junio C Hamano reviewed the patch and identified two technical issues. First, the current implementation skips a necessary warning when `-b` is used with `HEAD`. Second, he suggests a more targeted fix that preserves existing behavior for `HEAD` while still disabling DWIM when `-b` or `-B` is specified. Junio also noted minor improvements for the test case, such as avoiding redundant setup and checking for specific error messages.

The patch is narrowly scoped and aligns with documented expectations, but Junio’s feedback indicates it needs refinement before merging. There’s no controversy here—just a technical discussion about correctness. The regression was introduced in Git v2.42.0, and the fix is still under review. No other participants have weighed in yet.
