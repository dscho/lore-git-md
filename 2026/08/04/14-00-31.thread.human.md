This thread is about a small but important bugfix for `git worktree add`. The issue was a regression introduced in Git v2.42.0 where the `-b` or `-B` options were being ignored if Git could "DWIM" (Do What I Mean) a branch name to a remote-tracking branch. This meant users could accidentally create unintended branches when they explicitly specified `-b` or `-B`.

Yoichi Nakayama sent a patch to fix this, and after three iterations incorporating feedback from Junio C Hamano, the fix was merged to `master`. The solution is simple and targeted: it suppresses DWIM behavior when `new_branch` is set, restoring the pre-v2.42.0 behavior. The patch also preserves warning messages for edge cases (like using `-b` with `HEAD`) and includes a precise test case that avoids redundant setup steps.

The fix is now complete, with no loose ends or open questions. The thread is effectively closed, and the regression is resolved.
