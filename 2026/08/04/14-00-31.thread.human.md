This thread is about a small but important bugfix to `git worktree add`. The issue was a regression in Git 2.42.0 where the `-b` or `-B` options were being ignored if Git could DWIM (Do What I Mean) a branch name to a remote-tracking branch. This meant that explicitly specifying a branch name with `-b` or `-B` didn't always work as intended, leading to unintended branch creation.

Yoichi Nakayama authored the fix, which has now been merged to `master`. The solution is straightforward: the DWIM logic in `builtin/worktree.c` is now only applied when no explicit branch name is given via `-b` or `-B`. The patch also includes a test case to verify the corrected behavior. Junio C Hamano reviewed the patch across several iterations, catching edge cases like preserving warning behavior for `HEAD` and suggesting improvements to the test precision. The final version (v4) addressed all feedback, including a minor tweak to the commit message format.

The fix is narrowly scoped to the regression and doesn't introduce any side effects. The regression itself was introduced by commit `128e5496b3` in Git 2.42.0, and this patch restores the pre-2.42.0 behavior. No further discussion or changes are expected.
