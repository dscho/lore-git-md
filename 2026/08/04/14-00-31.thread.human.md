This thread is about a bugfix for `git worktree add` that addresses a regression introduced in Git v2.42.0. The issue occurs when the `-b` or `-B` options are used alongside a branch name that could be DWIMmed to a remote-tracking branch: the options were incorrectly ignored, leading to the creation of a worktree with an unintended branch. Yoichi NAKAYAMA identified the root cause (commit `128e5496b325`) and submitted a minimal fix in `builtin/worktree.c` to disable DWIM logic when `new_branch` is explicitly set. A new test case in `t/t2400-worktree-add.sh` verifies the corrected behavior.

The patch is narrowly scoped and well-motivated, focusing on restoring the expected precedence of `-b`/`-B` over DWIM. There’s no controversy evident in the patch itself, though follow-up discussion might explore edge cases or related behaviors. The fix is ready for review, and if no objections arise, it should proceed to Junio’s integration branches.
