This is the first patch in the **v12 iteration of Harald Nordgren’s `git history squash` feature**, a new subcommand that folds a commit range into its oldest commit. This patch is a **pure refactoring** with no behavior change, extracting the repeated logic for resolving a commit’s first-parent tree into a helper function, `first_parent_tree_oid()`.

The helper centralizes the logic used in three places in `builtin/history.c`: determining the parent tree of a commit (or falling back to the empty tree for a root commit), parsing the parent commit, and copying its tree OID. The existing callers are updated to use the new helper, reducing code duplication and making future changes easier. The patch is small (26 insertions, 32 deletions) and mechanical, touching only `builtin/history.c`.

This refactoring is part of the **ongoing `git history` effort**, which aims to provide faster, non-interactive alternatives to existing history-editing commands like `git rebase`. The `squash` subcommand, once merged, will serve as a foundational piece for future integration with `git rebase --autosquash` (via `git replay`), offering a performance improvement by avoiding repeated conflict resolution.

The series is **technically complete and ready for integration**, with Junio’s prior "Will replace" sign-off and all feedback (including Phillip Wood’s fixup patches) fully incorporated in v12. This patch is uncontroversial and unlikely to draw further discussion; it’s a clean preparatory step for the core implementation in patch 4/4.
