This is the fifth patch in Patrick Steinhardt’s seven-patch series refactoring the object database (ODB) streaming API. It merges the previously separate `odb_write_stream` and `odb_read_stream` structures into a single `odb_stream` type, completing the unification begun in earlier patches.

The patch is a mechanical but non-trivial refactor. It replaces all direct uses of `struct odb_write_stream` with `struct odb_stream`, updates function signatures (e.g., `odb_write_stream_read()` → `odb_stream_read()`), and introduces wrapper structures where the new stream type needs to carry additional context (e.g., `input_zstream_data` in `builtin/unpack-objects.c`). The changes touch 14 files, including core ODB code (`odb/streaming.c`, `odb/source-*.c`), callers like `object-file.c` and `builtin/unpack-objects.c`, and the unit test `t/unit-tests/u-odb-inmemory.c`.

Two sites require special handling: `builtin/unpack-objects.c` (which creates a write stream from compressed data) and `odb/streaming.c` (which creates one from a file descriptor). Both now allocate a wrapper around `struct odb_stream` instead of embedding data directly in the old `odb_write_stream`. The patch also removes the now-redundant `odb_write_stream_release()` function, replacing it with `odb_stream_close()`.

This is a clean, well-scoped refactor that aligns with the series’ goal of simplifying the ODB API. The commit message is clear, and the changes are incremental and testable. Reviewers may focus on edge cases—such as ensuring the new wrapper structures correctly initialize all fields or that the zlib loop in `builtin/unpack-objects.c` handles errors properly—but the patch itself looks solid and uncontroversial. It’s part of the broader ODB abstraction effort and should be ready for `next` once reviewed.
