This is a bugfix for `git worktree add` that addresses a regression in Git v2.42.0. The patch prevents the `-b` or `-B` options from being ignored when a branch name could be DWIMmed to a remote-tracking branch, ensuring explicit branch creation takes precedence. The fix is narrowly scoped and well-motivated, with a clear test case added to verify the corrected behavior.

Junio’s review identifies a subtle edge case: the patch as written also skips the `can_use_local_refs()` check when `-b` is used with `HEAD`, which could suppress a warning. He suggests a more targeted fix that disables only the DWIM logic while preserving the `HEAD`-related check. This adjustment would make the patch even more precise without changing its core intent.

The test case is mostly sound but could be tightened: it currently expects a generic failure (`test_must_fail`) without verifying the specific error message, and it redundantly initializes a repository that `setup_remote_repo()` already creates. These are minor issues, but addressing them would make the test more robust.
