This is part of Patrick Steinhardt’s ODB abstraction series, specifically the third patch which defers object database (ODB) creation to support pluggable on-disk structures. The email is a brief follow-up to Justin Tobler’s review question about why the patch uses a flag (`APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION`) to defer ODB creation instead of requiring an explicit `odb_new()` call after `apply_repository_format()`.

Patrick clarifies that the current design is a pragmatic choice due to the complexity of splitting object directory and alternate logic from `apply_repository_format()`. He acknowledges that the approach might simplify in the future when environment variable handling is moved into the "files" backend (as discussed in a related thread), but for now, the flag is a transitional step. The reply does not introduce new technical details or objections, but it reaffirms the patch’s role as infrastructure for the broader ODB abstraction effort. No further discussion or design changes are proposed here—this is a straightforward clarification of intent.
