This is the third patch in Patrick Steinhardt’s five-patch series making on-disk object database (ODB) structures pluggable, part of the ongoing ODB abstraction effort. The patch defers the creation of the object database until after the reference database is set up, introducing a new flag (`APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION`) to leave the repository in a partially-initialized state. This is a prerequisite for the planned `objectStorage` extension, which will enable non-filesystem ODB backends.

The patch refactors `setup.c` to split the ODB creation into two steps: first, the repository format is applied (with ODB creation skipped via the new flag), then the ODB is created later via a new helper function, `create_object_database()`. The helper consolidates the logic for reading environment variables (`DB_ENVIRONMENT`, `ALTERNATE_DB_ENVIRONMENT`) and creating the ODB, replacing the previous `create_object_directory()` function. The change is mechanical but necessary for future backends that may not follow the traditional loose/pack layout.

Key technical details:
- **New flag**: `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` (bit `1 << 1`) allows `apply_repository_format()` to skip ODB creation, leaving the repository in a partially-initialized state.
- **New helper**: `create_object_database()` replaces `create_object_directory()`, consolidating ODB creation logic and environment variable handling.
- **Behavior change**: ODB creation is deferred until after the ref database is set up, enabling future backends to handle their own initialization.
- **Files touched**: `setup.c` (primary changes) and `setup.h` (flag definition).

The patch is well-motivated and aligns with the series’ goal of decoupling backend-specific logic from core setup code. The flag-based approach is pragmatic, though Justin Tobler’s review in v1 suggested an explicit `odb_new()` call might be cleaner. Patrick’s reply acknowledged this but framed the flag as a transitional step due to the complexity of splitting object directory and alternate logic from `apply_repository_format()`. The design may simplify in future iterations when environment variable handling is moved into the "files" backend.

No test coverage is added here, but the patch is a refactoring with no immediate user-visible impact. It is critical infrastructure for the planned `objectStorage` extension and should be evaluated in that context. The patch is under review and looks ready for merging, assuming the broader series is accepted.
