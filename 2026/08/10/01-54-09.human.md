This is Junio C Hamano’s review of the final patch in Justin Tobler’s seven-patch v2 series that makes `git receive-pack` backend-agnostic for packfile writes. The series extends the ODB transaction system to replace `git receive-pack`'s hardcoded use of `git index-pack` and `git unpack-objects` with a generic `odb_transaction_write_pack()` interface, enabling alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles.

Junio’s comment is substantive and technical: he identifies a latent bug in the "files" backend implementation (`odb_transaction_files_write_pack()`). The code currently calls `odb_source_prepare()` on `repo->objects->sources`, which is the *first* ODB source in the repository’s linked list. This is incorrect when the transaction is associated with a different source (e.g., a promisor remote or an alternative backend). Junio suggests using `base->source` instead, which is the ODB source tied to the transaction. The fix is straightforward but critical for correctness: the current code would silently prepare the wrong ODB source, potentially causing cache inconsistencies or subtle corruption in multi-source setups.

The rest of the series is unaffected; this is a localized issue in the new backend implementation. The patch is otherwise well-structured, with thorough test coverage and no on-disk format changes. The series as a whole is part of Patrick Steinhardt’s ongoing ODB abstraction effort and has already addressed all v1 feedback on interface naming, error reporting, and transaction lifecycle ergonomics. Junio’s observation does not challenge the series’ direction but flags a specific correctness risk that will need to be fixed before the patch can graduate from `seen`.
