This is a review comment on the third patch in Justin Tobler’s seven-patch v2 series extending the ODB transaction system to make `git receive-pack` backend-agnostic. The patch removes the global `unpack_limit` variable and replaces it with a lazy, per-repository lookup via `get_unpack_limit()`.

Junio Hamano’s review questions the design choice of using a `static int` inside `get_unpack_limit()` to cache the unpack limit. He observes that this approach is functionally equivalent to a global variable and suggests instead storing the unpack limit as a new member in either `repo->settings` or `repo->config_values`, making the setting truly per-repository. This would align with Git’s broader pattern of avoiding static variables in favor of explicit repository state, especially as the ODB abstraction effort progresses toward supporting multiple backends and repositories.

The review does not object to the patch’s direction or correctness but flags a potential technical debt in the implementation. The current design, while simpler, may complicate future work if the unpack limit needs to vary across repositories or backends. Junio’s suggestion is a forward-looking improvement that would make the code more maintainable and consistent with Git’s repository-centric architecture.

This feedback is substantive but not blocking; it addresses a design trade-off rather than a bug. The author will likely consider this suggestion in the next iteration, particularly if other reviewers echo the concern or if the ODB abstraction effort’s roadmap makes per-repository unpack limits a near-term requirement. The patch remains under review, and the series as a whole is still cooking in `seen`.
