This is Junio Hamano’s review of the final patch in Justin Tobler’s seven-patch v2 series, which introduces `odb_transaction_write_pack()` to make `git receive-pack` backend-agnostic for packfile writes. The patch moves packfile ingestion logic into `object-file.c` as the "files" backend implementation and uses the transaction’s `finalize` callback to clean up ".keep" lockfiles post-commit.

Junio’s concern centers on the interaction between the transaction’s commit and finalize steps. The commit phase (`odb_transaction_files_commit()`) migrates the quarantine directory (including ".keep" files) to the main object store, but the finalize step (`odb_transaction_files_finalize()`) attempts to delete the lockfiles using their original quarantine paths. Junio is puzzled: if the ".keep" files have already been migrated, how can the finalize step delete them using the old paths? The review suggests a logical gap in the cleanup sequence—either the paths are stale, or the migration step is not preserving the lockfile state as expected.

The question is substantive: it identifies a potential bug in the transaction lifecycle where deferred cleanup could fail silently, leaving ".keep" files stranded. This is not a surface-level nit but a correctness issue that could affect repository integrity. The author will need to clarify how the lockfile paths are tracked across the migration step or adjust the cleanup logic to account for the new locations. The outcome may require a v3 iteration to resolve the ambiguity.
