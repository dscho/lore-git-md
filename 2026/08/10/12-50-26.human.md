This is the core patch in D. Ben Knoble’s series converting the build-time `USE_NSEC` macro into a runtime `core.useNanosec` configuration option. Patrick Steinhardt’s reply is a brief but substantive review comment that clarifies a key platform-compatibility detail.

The patch itself removes the `USE_NSEC` macro from the build system and replaces it with a runtime config key, allowing users to enable nanosecond precision on supported filesystems without recompiling Git. The change is well-motivated, addressing the "racy Git" problem by making nanosecond precision configurable at runtime, and the implementation is clean, touching `environment.c`, `read-cache.c`, and related files.

Patrick’s comment here is a small but important technical observation: he notes that Git already has two macros (`NO_NSEC` and `USE_NSEC`) to handle platform support for nanoseconds, and the patch correctly preserves this logic. This means the runtime option (`core.useNanosec`) will only take effect on platforms where nanosecond precision is actually available, avoiding potential issues on filesystems or operating systems that don’t support it. The comment doesn’t challenge the patch’s direction but confirms that the platform-compatibility story is sound.

The rest of the series (a Meson build-system fix and a no-op refactor) remains uncontested, and the main open question is still where to cache the config value for performance—either in `repo_config_values` (modern but limited to `the_repository`) or in `repo_settings` (supports per-repository variation). This reply doesn’t address that architectural decision, but it does remove one potential roadblock by confirming the patch handles platform support correctly. The patch is clearly worth attention, especially once the caching fix is incorporated in v2.
