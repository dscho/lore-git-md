This is patch 6/7 of the `git repack --drop-filtered` series, adding safety guards to prevent `--drop-filtered` from running during ongoing operations (merge, rebase, etc.) or dropping blobs referenced by the current index. The patch is production-ready and integrates cleanly with the rest of the series, which is now complete in its v4 iteration.

The implementation adds two new checks, both skipped for bare repositories. First, it uses `wt_status_get_state()` to detect and block `--drop-filtered` during merge, rebase, am, cherry-pick, revert, or bisect operations, with a clear error message. Second, it validates the index (via `repo_read_index()`) to ensure no blob slated for removal is referenced by the current index, reporting the offending path if found. These guards are explicitly framed as UX optimizations—lazy-fetching would transparently restore dropped objects, but triggering network operations mid-operation or immediately after a drop would create a poor user experience.

The patch touches `builtin/repack.c` (adding the guards and new includes for `wt-status.h` and `read-cache-ll.h`) and extends the test script (`t/t7706-repack-drop-filtered.sh`) with two new cases: one verifying the merge-conflict refusal, and another confirming the index-referenced blob check. The test coverage is thorough, using `test_when_finished` to clean up merge state and `test_grep` to validate error messages. The guards are minimal and focused, avoiding lazy fetches by design (they only inspect locally available data) and maintaining backward compatibility (all existing callers are unaffected).

This patch is the focal point of Junio’s proposed time-based heuristic alternative, which would replace these guards with a mechanism to avoid culling recently fetched objects. The current implementation’s trade-off—simplicity and immediate safety versus smarter but more complex heuristics—will likely be the main discussion point in follow-up reviews. The patch itself is uncontroversial and ready for integration, assuming the heuristic debate does not block the series.
