This is a **substantive review** of the third patch in Justin Tobler’s seven-patch v2 series making `git receive-pack` backend-agnostic for packfile writes. The patch removes the global `unpack_limit` variable and replaces it with a lazy, per-repository lookup via `get_unpack_limit()`.

Patrick Steinhardt’s review identifies two technical issues in the implementation. First, the function’s return type should be `unsigned int` (not `int`) because the unpack limit is always a non-negative value, and the final commit in the series will need an explicit cast to reconcile this. Second, the static variable caching the limit is unnecessary because `unpack()` is only called once per `receive-pack` invocation, and the cache would become stale if the function were ever called for multiple repositories. He proposes a simpler, non-caching version that directly reads the configuration and defaults to 100.

The review is narrowly focused on the patch’s mechanical correctness and does not revisit the broader design decisions (e.g., moving the unpack limit resolution into the backend-agnostic transaction interface). The feedback is actionable and aligns with the series’ goal of lifting global state, but the changes are minor and unlikely to affect the patch’s core value. The next iteration will likely adopt Patrick’s suggested implementation.
