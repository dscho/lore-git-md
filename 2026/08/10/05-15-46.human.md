This is a **refactoring patch review** in the ongoing ODB abstraction effort. The exchange is a focused, **substantive review** of patch 3/7 in Justin Tobler’s v2 series, which removes the global `unpack_limit` variable from `builtin/receive-pack.c` and replaces it with a lazy, per-repository lookup.

Patrick Steinhardt’s feedback is technical and precise. He identifies two issues: the return type of `get_unpack_limit()` should be `unsigned int` (not `int`) because the value is always non-negative, and the static caching of the limit is unnecessary and potentially problematic. The function is only called once per `git receive-pack` invocation, so caching adds no value and could cause stale data if the function were ever reused across repositories. His suggested rewrite is simpler and more robust, avoiding both the signed/unsigned mismatch and the caching pitfall.

The review is **surface-level in scope** (type correctness and caching logic) but **substantive in impact** — these are not nits, but real correctness concerns. The discussion is narrow and unlikely to derail the series, but the changes are worth incorporating before the next iteration. The patch itself is a small, well-motivated step toward making packfile writes backend-agnostic, and the feedback reflects the kind of careful scrutiny the ODB abstraction effort routinely receives.
