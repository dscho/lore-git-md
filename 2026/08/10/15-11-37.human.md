This is the second patch in a two-patch bugfix series for `git maintenance`, addressing a regression in the `--auto` trigger for geometric repacking when promisor packs are involved. The patch is small but important: it updates the auto-condition logic in `builtin/gc.c` to check `geometry.promisor_split` alongside `geometry.split`, ensuring the maintenance task runs when promisor packs are ready for rollup even if ordinary packs or loose objects don’t require attention.

The change itself is a one-line modification to `geometric_repack_auto_condition()`, and the accompanying test coverage in `t/t7900-maintenance.sh` is thorough. The test creates three promisor packs (two small, one large) and verifies that `--auto` triggers the task when the smaller packs should be combined. A minor adjustment in `t/t5331-pack-objects-stdin.sh` disables auto-maintenance in a filtered clone fixture to avoid test interference, which Patrick Steinhardt acknowledges as sensible given how `git clone` can fetch multiple promisor packs during backfill.

Patrick’s review is brief but clearly positive—he calls the change "obviously correct" and raises no concerns. This patch completes the series’ goal of making promisor pack handling consistent across both the repack decision logic (fixed in patch 1) and the auto-trigger mechanism. The regression it addresses was introduced in January 2026 (dcc9c7ef47), and the fix aligns well with the existing code structure. For users of partial clones, this should resolve a real-world issue where maintenance tasks were being skipped despite promisor packs being ready for optimization. The patch looks ready to merge.
