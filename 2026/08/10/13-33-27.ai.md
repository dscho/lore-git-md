This is a refactoring patch series targeting the object database (ODB) subsystem, specifically the handling of alternate object databases. The series consists of four patches that collectively remove lazy-loading of alternates, simplifying the codebase by eagerly initializing all alternate ODBs during the primary ODB setup.

The motivation is that Git historically deferred loading alternates until they were needed, but over time, the codebase has evolved to parse alternates eagerly in many places anyway (e.g., during object lookups). This makes the lazy-loading optimization ineffective and results in scattered calls to `odb_prepare_alternates()` throughout the code. The series aims to clean this up by initializing alternates upfront, which also paves the way for future work to move alternates into the "files" backend.

Key changes include:
- Decoupling source path comparisons from `the_repository` (patch 1/4).
- Eagerly initializing alternates during ODB setup (patch 2/4).
- Removing the now-unused `loaded_alternates` and `alternates_db` fields from the ODB structure (patches 3/4 and 4/4).

The series touches 12 files, primarily in the `odb/` subsystem, but also affects higher-level code like `builtin/fsck.c`, `builtin/pack-objects.c`, and `commit-graph.c`. The net effect is a reduction of 17 lines of code (68 insertions, 85 deletions). It builds on Patrick Steinhardt’s recent ODB refactoring work (`ps/odb-make-creation-pluggable`).

This is part of the broader ODB abstraction effort led by Patrick, which aims to make Git’s object storage layer more modular. The series appears well-motivated and mechanically sound, with clear commit messages and a focused scope. It should not introduce behavioral changes but may have subtle implications for performance or error handling in edge cases (e.g., corrupt alternates). The removal of lazy-loading could also affect commands that previously avoided loading alternates entirely, though the commit message suggests this is rare in practice.
