This is a reply in the ongoing ODB transaction series from Justin Tobler, addressing Junio Hamano’s review of patch 7/7. The patch introduces `odb_transaction_write_pack()` to make `git receive-pack` backend-agnostic for packfile writes, replacing hardcoded calls to `git index-pack` and `git unpack-objects` with a generic transaction interface. Junio’s review flagged a design flaw in the "files" backend implementation: it hardcodes `repo->objects->sources[0]` instead of respecting the transaction’s source (`base->source`), risking subtle bugs if multiple ODB backends are in use.

Justin acknowledges the awkwardness and fragility of relying on the first source in the list, confirming that `base->source` cannot be used directly in the current design. He outlines a future plan to stop reordering the source list during transaction startup and instead track the source separately, which would simplify the logic. For the next version of this series, he proposes exploring whether the ODB transaction itself should track its own source, though this would be a minor addition rather than a core change. The response is pragmatic and forward-looking, treating the issue as a technical debt item to be addressed in a follow-up rather than a blocker for the current series. The tone is collaborative, and the plan aligns with the broader ODB abstraction effort’s goal of making backend selection explicit and robust. No other aspects of the patch are revisited, and the focus remains narrowly on the source-tracking mechanics.
