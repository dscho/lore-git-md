This is a feature patch series introducing `git repack --drop-filtered`, a new option that lets users of partial clones safely reclaim disk space by removing locally cached promisor blobs over a specified size threshold. The series is now in its fourth iteration (v4), posted by first-time contributor Siddharth Shrimali as part of Google Summer of Code.

The feature addresses a long-standing gap in partial clone workflows: while Git can lazily fetch missing blobs on demand, there has been no built-in way to safely remove accumulated blobs once they are no longer needed. The implementation is careful to only target objects marked as promisor (ensuring they remain recoverable from the promisor remote), avoids touching locally created objects, and reuses Git’s existing repack machinery for crash safety. The series also introduces a `--dry-run` mode to preview which objects would be dropped without making changes.

v4 is functionally identical to v3 but incorporates three mechanical fixes identified by Junio: a missing newline in the usage string, a stray bracket in the documentation SYNOPSIS, and a test script style nit (replacing bare `grep` with `test_grep`). The core logic—enumerating promisor objects, filtering by size, and rebuilding the promisor pack while excluding the selected blobs—remains unchanged. The series is now complete, with thorough test coverage and clear documentation of the new options, their constraints (e.g., `--filter=blob:limit` only, `-a` required, promisor remote required), and the safety optimizations (merge/rebase/cherry-pick checks and index validation).

The patch set looks production-ready, with no known blocking issues. Junio’s feedback on v3 was limited to these mechanical fixes, and the author has acknowledged his reminder to run the full test suite and perform trial merges into `next` and `seen` before the next revision. The remaining work—remote verification, a "don’t cull recently fetched objects" heuristic, and a drop log—is explicitly scoped as follow-up efforts and does not block the core functionality. The series is well-structured, with tests distributed across commits and clear commit messages explaining each step.

The most likely point of future discussion is the design of the safety guards. Junio has proposed replacing the current merge/rebase/cherry-pick checks and index validation with a time-based heuristic (avoiding culls of recently fetched objects), arguing that the current guards are merely UX optimizations since lazy-fetching would transparently restore dropped objects. The author has framed the guards as optional, leaving the door open for this change in a future revision. Reviewers with expertise in repack, promisor infrastructure, or partial clones (e.g., Patrick Steinhardt or Christian Couder) may weigh in on this trade-off. For now, the series delivers a practical and safe solution to a real problem for partial clone users.
