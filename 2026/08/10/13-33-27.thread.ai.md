Thread identity
Subject: [PATCH 0/4] odb: remove lazy-loading of alternates
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove lazy-loading of alternate object databases. The current implementation defers loading alternates until they are needed, but many code paths already parse alternates eagerly (e.g., during object lookups), making the lazy-loading optimization ineffective. The goal is to simplify the code by initializing all alternate ODBs upfront during primary ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The first patch in the series decouples path comparisons for alternate ODB sources from `the_repository` to address long-standing issues with inconsistent case-sensitivity handling when alternates are registered before repository configuration is parsed.

Current status
Under review (initial submission). No prior versions of this series exist. The series consists of 4 patches:
1. Decouple source path comparisons from `the_repository` (new details: replaces `fspathhash()`/`fspatheq()` with a self-contained comparison mechanism using `struct hashmap` and ODB-specific case-sensitivity tracking; adds 41 lines net).
2. Eagerly initialize alternates during ODB setup.
3. Remove the now-unused `loaded_alternates` field from the ODB structure.
4. Remove the now-unused `alternates_db` field from the ODB structure.

Key technical details
- **Subsystems/files touched**: Primarily `odb/` (`odb.c`, `odb.h`, `odb/source.h`), with later patches affecting `builtin/fsck.c`, `builtin/pack-objects.c`, and `commit-graph.c`.
- **Symbols changed/removed**: `loaded_alternates` (field, unused after patch 3), `alternates_db` (field, unused after patch 4), `odb_prepare_alternates()` (usage reduced). New symbols: `source_paths_icase` (field in `struct object_database`), `odb_source_paths_cmp()`, `odb_source_by_path_cmp()` (comparison functions).
- **Behavioral changes**: No intended user-visible changes, but the series removes lazy-loading, which may affect performance or error handling in edge cases (e.g., corrupt alternates). Commands that previously avoided loading alternates entirely may now load them upfront. Patch 1 introduces ODB-specific case-sensitivity handling for alternate paths, resolving inconsistencies when `core.ignoreCase` is not yet parsed.
- **Code delta**: Net reduction of 17 lines across the series (68 insertions, 85 deletions). Patch 1 alone adds 41 lines (63 insertions, 22 deletions) due to new comparison logic.
- **Dependencies**: Builds on Patrick Steinhardt’s recent ODB refactoring work (`ps/odb-make-creation-pluggable`).
- **Related work**: Part of the broader ODB abstraction effort led by Patrick Steinhardt.

Open questions and loose ends
- Performance implications of eager alternate loading, particularly for commands that previously avoided loading alternates (e.g., `git fsck` with no alternates).
- Edge-case handling (e.g., corrupt alternates, repositories with thousands of alternates) may need validation, especially given the added complexity in patch 1.
- No objections or requests for changes have been raised yet, as this is the initial submission.
