Subject: [PATCH 0/4] odb: remove lazy-loading of alternates
Series version: v2 (revision of initial v1 submission)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove lazy-loading of alternate object databases. The current implementation defers loading alternates until they are needed, but many code paths already parse alternates eagerly (e.g., during object lookups), making the lazy-loading optimization ineffective. The goal is to simplify the code by initializing all alternate ODBs upfront during primary ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The first patch decouples path comparisons for alternate ODB sources from `the_repository` to resolve long-standing issues with inconsistent case-sensitivity handling when alternates are registered before repository configuration is parsed.

All patches in v2 are unchanged from v1 except for minor commit message clarifications and the addition of a comment in patch 4 to explain environment variable handling during cache flushing:
1. Decouple source path comparisons from `the_repository` (replaces `fspathhash()`/`fspatheq()` with a self-contained comparison mechanism using `struct hashmap` and ODB-specific case-sensitivity tracking; adds 41 lines net). The design discussion remains open following Jeff King’s (Peff) critique and Junio’s endorsement of Peff’s preference for simplifying the patch by dropping case-insensitivity entirely. Peff argues that `core.ignoreCase` is a flawed proxy for alternate path comparisons, as it reflects the repository’s filesystem, not the alternate’s, and could lead to missing objects in edge cases (e.g., a repository on a case-insensitive filesystem referencing alternates on a case-sensitive filesystem). Junio agrees that the added complexity is not justified and raises additional concerns about `stat()`-based deduplication (e.g., macOS filesystem transformations like Unicode normalization), reinforcing the push toward simplicity. The current implementation remains in place, but consensus has shifted toward revisiting the design before integration. Justin Tobler reviewed this patch substantively in v1, confirming the motivation and validating the implementation. Karthik Nayak’s v2 review suggested a minor stylistic simplification in `odb_source_paths_cmp()`, which Patrick rejected as functionally incorrect.
2. Eagerly initialize alternates during ODB setup (removes 13 calls to `odb_prepare_alternates()` across 10 files, centralizes initialization in `odb_new()` and `odb_prepare()`, and makes `odb_prepare_alternates()` static). Justin Tobler’s v1 review noted a minor commit message typo, which Patrick corrected in v2. The review did not engage with deeper technical implications (e.g., performance trade-offs for commands like `git fsck` that previously avoided loading alternates when none were present).
3. Remove the now-unused `loaded_alternates` field from the ODB structure (mechanical cleanup following patch 2; 9 lines removed, 1 added). Justin Tobler and Karthik Nayak reviewed this patch in v1/v2, confirming it as sensible and uncontroversial.
4. Remove the now-unused `alternates_db` field from the ODB structure (mechanical cleanup; removes 7 lines, adds 2, net -5). Justin Tobler raised a clarifying question about environment variable handling during cache flushing in v1, which Patrick resolved in v2 by adding a comment.

Key technical details
- **Subsystems/files touched**: Primarily `odb/` (`odb.c`, `odb.h`, `odb/source.h`), with changes in `builtin/fsck.c`, `builtin/pack-objects.c`, `commit-graph.c`, `pack-bitmap.c`, and others (12 files total in patch 2). Patches 3 and 4 are confined to `odb.c` and `odb.h`.
- **Symbols changed/removed**: `loaded_alternates` (field, removed in patch 3), `alternates_db` (field, removed in patch 4), `odb_prepare_alternates()` (usage removed; made static in patch 2). New symbols in patch 1: `source_paths_icase` (field in `struct object_database`), `odb_source_paths_cmp()`, `odb_source_by_path_cmp()` (comparison functions). Patch 4 updates `odb_prepare_alternates()` to accept the alternate database path as a parameter (passed via `odb_new()`) instead of reading it from the ODB struct.
- **Behavioral changes**: No intended user-visible changes, but the series removes lazy-loading, which may affect performance or error handling in edge cases (e.g., repositories with thousands of alternates, corrupt alternates, or commands that previously avoided loading alternates entirely). Patch 1’s design remains contested: the current implementation uses ODB-specific case-sensitivity handling for alternate paths, but Peff and Junio argue for simplifying this to case-sensitive comparisons only, accepting occasional duplicates as a low-risk trade-off. Junio additionally cautions against `stat()`-based deduplication due to platform-specific filesystem behaviors (e.g., macOS Unicode normalization). The performance implications of eager alternate loading (e.g., for `git fsck`) remain unaddressed in reviews.
- **Code delta**: Net reduction of 16 lines across the series (70 insertions, 86 deletions). Patch 1 adds 41 lines (63 insertions, 22 deletions); patch 2 removes 33 lines (1 insertion, 34 deletions); patch 3 removes 9 lines (0 insertions, 9 deletions, 1 line moved); patch 4 removes 5 lines (2 insertions, 7 deletions).
- **Dependencies**: Builds on Patrick’s prior ODB refactoring series (`ps/odb-make-creation-pluggable`).
- **Related work**: Part of the broader ODB abstraction effort led by Patrick Steinhardt.
