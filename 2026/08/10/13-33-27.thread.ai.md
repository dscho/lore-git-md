Subject: [PATCH 0/4] odb: remove lazy-loading of alternates
Series version: v3 (current)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove lazy-loading of alternate object databases. The current implementation defers loading alternates until they are needed, but many code paths already parse alternates eagerly (e.g., during object lookups), making the lazy-loading optimization ineffective. The goal is to simplify the code by initializing all alternate ODBs upfront during primary ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The series now consists of five patches, with the new first patch reordering repository initialization to ensure the object database is created *after* the full repository configuration is written, fixing a correctness issue with `core.ignoreCase` lookups. The design discussion has converged on retaining case-insensitive deduplication for now but documenting it as `NEEDSWORK` and acknowledging the consensus that it may be removed in the future for simplicity.

Key technical details
- **Subsystems/files touched**: Primarily `odb/` (`odb.c`, `odb.h`, `odb/source.h`), with changes in `builtin/fsck.c`, `builtin/pack-objects.c`, `commit-graph.c`, `pack-bitmap.c`, `setup.c` (new in v3), and others (14 files total). The new first patch (1/5) touches `setup.c` to reorder repository initialization, while patch 2/5 migrates from `khash` to `hashmap` to support dynamic comparison functions. Patch 3/5 removes calls to `odb_prepare_alternates()` from 11 files, centralizing alternate initialization in `odb.c`. Patch 4/5 removes the `loaded_alternates` field from `odb.h` and simplifies `odb_add_to_alternates_file()`.
- **Symbols changed/removed**: `loaded_alternates` (field, removed in patch 4/5), `alternates_db` (field, to be removed in patch 5/5), `odb_prepare_alternates()` (usage removed; made static in patch 3/5). Patch 2/5 introduces `source_paths_icase` (field in `struct object_database`) and the case-insensitive comparison functions (`odb_source_paths_cmp()`, `odb_source_by_path_cmp()`) but documents them as `NEEDSWORK`. The new first patch ensures `core.sharedRepository` and `core.ignoreCase` are set before `create_object_directory()` is called, addressing the timing issue without requiring a cherry-pick from a later series.
- **Behavioral changes**: No intended user-visible changes, but the series removes lazy-loading, which may affect performance or error handling in edge cases (e.g., repositories with thousands of alternates, corrupt alternates, or commands that previously avoided loading alternates entirely). Patch 2/5 retains case-insensitive deduplication but documents it as a candidate for future removal. The new first patch is a critical correctness fix for `core.ignoreCase` lookups. Patch 3/5 centralizes alternate initialization, which may slightly increase startup time for commands that previously avoided loading alternates when none were present (e.g., `git fsck`). Patch 4/5 is a mechanical cleanup with no behavioral impact.
- **Code delta**: Net reduction of 10 lines across the series (92 insertions, 102 deletions). The new first patch adds 6 lines, patch 3/5 removes 42 lines (46 deletions, 4 insertions), patch 4/5 removes 9 lines (1 insertion, 10 deletions), and the revised second patch reduces complexity by migrating from `khash` to `hashmap` (exact line count unchanged from v2 for patch 5/5).
- **Dependencies**: Builds on Patrick’s prior ODB refactoring series (`ps/odb-make-creation-pluggable`). The new first patch resolves the timing issue without external dependencies.
- **Related work**: Part of the broader ODB abstraction effort led by Patrick Steinhardt.
