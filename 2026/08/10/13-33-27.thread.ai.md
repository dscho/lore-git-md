Subject: [PATCH 0/4] odb: remove lazy-loading of alternates
Series version: v3 (anticipated; v2 is current)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove lazy-loading of alternate object databases. The current implementation defers loading alternates until they are needed, but many code paths already parse alternates eagerly (e.g., during object lookups), making the lazy-loading optimization ineffective. The goal is to simplify the code by initializing all alternate ODBs upfront during primary OB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The first patch originally decoupled path comparisons for alternate ODB sources from `the_repository` but retained case-insensitive deduplication; the design discussion has now converged on switching to case-sensitive comparisons only, eliminating the complexity of case-insensitive handling. However, Jeff King has raised a correctness concern about the timing of `core.ignoreCase` lookups in the current implementation, which may require further revision.

- **Subsystems/files touched**: Primarily `odb/` (`odb.c`, `odb.h`, `odb/source.h`), with changes in `builtin/fsck.c`, `builtin/pack-objects.c`, `commit-graph.c`, `pack-bitmap.c`, and others (12 files total in patch 2). Patches 3 and 4 are confined to `odb.c` and `odb.h`.
- **Symbols changed/removed**: `loaded_alternates` (field, removed in patch 3), `alternates_db` (field, removed in patch 4), `odb_prepare_alternates()` (usage removed; made static in patch 2). Patch 1 will be revised to remove `source_paths_icase` (field in `struct object_database`), `odb_source_paths_cmp()`, and `odb_source_by_path_cmp()` (comparison functions), replacing them with case-sensitive path comparisons. The revision may also replace inline `core.ignoreCase` lookups with `repo_ignore_case()` to address the timing concern. Patch 4 updates `odb_prepare_alternates()` to accept the alternate database path as a parameter (passed via `odb_new()`) instead of reading it from the ODB struct.
- **Behavioral changes**: No intended user-visible changes, but the series removes lazy-loading, which may affect performance or error handling in edge cases (e.g., repositories with thousands of alternates, corrupt alternates, or commands that previously avoided loading alternates entirely). Patch 1’s design will now use case-sensitive path comparisons for alternate deduplication, eliminating the `NEEDSWORK` note and simplifying the code. The consensus (Jeff King, Junio Hamano, Patrick Steinhardt) is that the risk of duplicate alternates is negligible and acceptable for the sake of simplicity. Jeff King’s new concern about `core.ignoreCase` timing may require additional changes to ensure correctness.
- **Code delta**: Net reduction of 16 lines across the series (70 insertions, 86 deletions) in v2. Patch 1’s revision will further reduce complexity by removing case-insensitive handling (exact line count TBD) and may include additional changes to address the timing issue. Patches 2–4 are unchanged from v2.
- **Dependencies**: Builds on Patrick’s prior ODB refactoring series (`ps/odb-make-creation-pluggable`).
- **Related work**: Part of the broader ODB abstraction effort led by Patrick Steinhardt.
