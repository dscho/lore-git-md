Subject: [PATCH 0/4] odb: remove lazy-loading of alternates
Series version: v2 (revision of initial v1 submission)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove lazy-loading of alternate object databases. The current implementation defers loading alternates until they are needed, but many code paths already parse alternates eagerly (e.g., during object lookups), making the lazy-loading optimization ineffective. The goal is to simplify the code by initializing all alternate ODBs upfront during primary ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The first patch decouples path comparisons for alternate ODB sources from `the_repository` to resolve long-standing issues with inconsistent case-sensitivity handling when alternates are registered before repository configuration is parsed.

The design discussion for patch 1 is now converging toward a consensus to simplify the patch by dropping case-insensitivity handling entirely. Jeff King (Peff) and Junio Hamano argued that the added complexity is not justified, and Patrick Steinhardt has now accepted this trade-off, noting that pathological alternate configurations (e.g., multiple case-varied paths) are user errors. Patrick also raised a practical obstacle to Peff’s proposed `stat()`-based deduplication: Windows filesystems often lack reliable `st_ino`/`st_dev` values, making this approach ineffective where case-insensitivity is most common. The performance implications of eager alternate loading (e.g., for `git fsck`) and edge-case handling (e.g., repositories with thousands of alternates or corrupt alternates) remain unaddressed, but the primary design objection to patch 1 is now resolved in principle. No revised implementation has been posted yet; it is unclear whether this change will be made as a follow-up or as a v3 revision.

Key technical details
- **Subsystems/files touched**: Primarily `odb/` (`odb.c`, `odb.h`, `odb/source.h`), with changes in `builtin/fsck.c`, `builtin/pack-objects.c`, `commit-graph.c`, `pack-bitmap.c`, and others (12 files total in patch 2). Patches 3 and 4 are confined to `odb.c` and `odb.h`.
- **Symbols changed/removed**: `loaded_alternates` (field, removed in patch 3), `alternates_db` (field, removed in patch 4), `odb_prepare_alternates()` (usage removed; made static in patch 2). New symbols in patch 1: `source_paths_icase` (field in `struct object_database`), `odb_source_paths_cmp()`, `odb_source_by_path_cmp()` (comparison functions). Patch 4 updates `odb_prepare_alternates()` to accept the alternate database path as a parameter (passed via `odb_new()`) instead of reading it from the ODB struct.
- **Behavioral changes**: No intended user-visible changes, but the series removes lazy-loading, which may affect performance or error handling in edge cases (e.g., repositories with thousands of alternates, corrupt alternates, or commands that previously avoided loading alternates entirely). Patch 1’s design is now contested in principle: the current implementation uses ODB-specific case-sensitivity handling for alternate paths, but consensus has shifted toward simplifying this to case-sensitive comparisons only, accepting occasional duplicates as a low-risk trade-off. Junio additionally cautioned against `stat()`-based deduplication due to platform-specific filesystem behaviors (e.g., macOS Unicode normalization), and Patrick noted that Windows filesystems lack reliable `st_ino`/`st_dev` values, making this approach ineffective on that platform. The performance implications of eager alternate loading (e.g., for `git fsck`) remain unaddressed in reviews.
- **Code delta**: Net reduction of 16 lines across the series (70 insertions, 86 deletions). Patch 1 adds 41 lines (63 insertions, 22 deletions); patch 2 removes 33 lines (1 insertion, 34 deletions); patch 3 removes 9 lines (0 insertions, 9 deletions, 1 line moved); patch 4 removes 5 lines (2 insertions, 7 deletions).
- **Dependencies**: Builds on Patrick’s prior ODB refactoring series (`ps/odb-make-creation-pluggable`).
- **Related work**: Part of the broader ODB abstraction effort led by Patrick Steinhardt.
