Thread identity
Subject: [PATCH 0/4] odb: remove lazy-loading of alternates
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove lazy-loading of alternate object databases. The current implementation defers loading alternates until they are needed, but many code paths already parse alternates eagerly (e.g., during object lookups), making the lazy-loading optimization ineffective. The goal is to simplify the code by initializing all alternate ODBs upfront during primary ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The first patch decouples path comparisons for alternate ODB sources from `the_repository` to resolve long-standing issues with inconsistent case-sensitivity handling when alternates are registered before repository configuration is parsed.

Current status
Under review (initial submission). The series consists of 4 patches, all posted:
1. Decouple source path comparisons from `the_repository` (replaces `fspathhash()`/`fspatheq()` with a self-contained comparison mechanism using `struct hashmap` and ODB-specific case-sensitivity tracking; adds 41 lines net). Justin Tobler reviewed this patch substantively, confirming the motivation and validating the implementation. He raised questions about the necessity of the added complexity for deduplicating alternates but concluded the patch "looks good" after discussion. No bugs or requests for changes were identified, though the performance trade-offs for edge cases (e.g., repositories with thousands of alternates) remain open for broader scrutiny.
2. Eagerly initialize alternates during ODB setup (removes 13 calls to `odb_prepare_alternates()` across 10 files, centralizes initialization in `odb_new()` and `odb_prepare()`, and makes `odb_prepare_alternates()` static).
3. Remove the now-unused `loaded_alternates` field from the ODB structure (mechanical cleanup following patch 2; 9 lines removed, 1 added).
4. Remove the now-unused `alternates_db` field from the ODB structure (mechanical cleanup; removes 7 lines, adds 2, net -5). The field was previously used to store `GIT_ALTERNATE_OBJECT_DIRECTORIES` but is no longer needed after patch 2 centralized alternate initialization. `odb_prepare_alternates()` now accepts the alternate database path as a parameter, and `odb_free()` no longer frees the field.

Key technical details
- **Subsystems/files touched**: Primarily `odb/` (`odb.c`, `odb.h`, `odb/source.h`), with changes in `builtin/fsck.c`, `builtin/pack-objects.c`, `commit-graph.c`, `pack-bitmap.c`, and others (10 files total in patch 2). Patches 3 and 4 are confined to `odb.c` and `odb.h`.
- **Symbols changed/removed**: `loaded_alternates` (field, removed in patch 3), `alternates_db` (field, removed in patch 4), `odb_prepare_alternates()` (usage removed; made static in patch 2). New symbols in patch 1: `source_paths_icase` (field in `struct object_database`), `odb_source_paths_cmp()`, `odb_source_by_path_cmp()` (comparison functions). Patch 4 updates `odb_prepare_alternates()` to accept the alternate database path as a parameter (passed via `odb_new()`) instead of reading it from the ODB struct.
- **Behavioral changes**: No intended user-visible changes, but the series removes lazy-loading, which may affect performance or error handling in edge cases (e.g., repositories with thousands of alternates, corrupt alternates, or commands that previously avoided loading alternates entirely). Patch 1 introduces ODB-specific case-sensitivity handling for alternate paths, resolving inconsistencies when `core.ignoreCase` is not yet parsed. Justin Tobler’s review highlighted the trade-off between linear search and hashmap complexity for alternate deduplication, noting that while the current approach avoids regressing performance for repositories with many alternates, such cases are rare.
- **Code delta**: Net reduction of 30 lines across the series (69 insertions, 99 deletions). Patch 1 adds 41 lines (63 insertions, 22 deletions); patch 2 removes 33 lines (1 insertion, 34 deletions); patch 3 removes 9 lines (0 insertions, 9 deletions, 1 line moved); patch 4 removes 5 lines (2 insertions, 7 deletions).
- **Dependencies**: Builds on Patrick Steinhardt’s recent ODB refactoring work (`ps/odb-make-creation-pluggable`).
- **Related work**: Part of the broader ODB abstraction effort led by Patrick Steinhardt.

Open questions and loose ends
- Performance implications of eager alternate loading, particularly for commands like `git fsck` that previously avoided loading alternates when none were present. Reviewers may want to validate edge-case handling (e.g., repositories with thousands of alternates or corrupt alternates). Justin Tobler’s review surfaced the design trade-off in patch 1 (hashmap complexity vs. linear search for deduplication), but no objections were raised.
- The series is mechanically clean but may benefit from broader reviewer scrutiny on the performance trade-offs and the added complexity in patch 1. No objections or requests for changes have been raised yet.
