Subject: [PATCH 0/4] odb: remove lazy-loading of alternates
Series version: v3 (current)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove lazy-loading of alternate object databases. The current implementation defers loading alternates until they are needed, but many code paths already parse alternates eagerly (e.g., during object lookups), making the lazy-loading optimization ineffective. The goal is to simplify the code by initializing all alternate ODBs upfront during primary ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The series consists of five patches, with the first patch reordering repository initialization to ensure the object database is created *after* the full repository configuration is written, fixing a correctness issue with `core.ignoreCase` lookups. The design discussion has converged on retaining case-insensitive deduplication for now but documenting it as `NEEDSWORK` and acknowledging the consensus that it may be removed in the future for simplicity. However, the first patch’s approach to the `core.ignoreCase` timing issue is now blocked by a technical constraint: `repo_ignore_case()` cannot be used because it relies on `repo_config_values()`, which is hardcoded to `the_repository` and would break submodule support.

Key technical details
- **Subsystems/files touched**: Primarily `odb/` (`odb.c`, `odb.h`, `odb/source.h`), with changes in `builtin/fsck.c`, `builtin/pack-objects.c`, `commit-graph.c`, `pack-bitmap.c`, `setup.c` (new in v3), and others (14 files total). Patch 3/5 removes calls to `odb_prepare_alternates()` from 11 files, centralizing alternate initialization in `odb.c`. Patch 4/5 removes the `loaded_alternates` field from `odb.h` and simplifies `odb_add_to_alternates_file()`. Patch 5/5 removes the `alternates_db` field from `odb.h` and updates `odb_new()` and `odb_prepare()` to pass the environment variable directly.
- **Symbols changed/removed**: `loaded_alternates` (field, removed in patch 4/5), `alternates_db` (field, removed in patch 5/5), `odb_prepare_alternates()` (usage removed; made static in patch 3/5). Patch 2/5 introduces `source_paths_icase` (field in `struct object_database`) and the case-insensitive comparison functions (`odb_source_paths_cmp()`, `odb_source_by_path_cmp()`) but documents them as `NEEDSWORK`. The first patch’s approach to `core.ignoreCase` is now blocked by `repo_config_values()` (hardcoded to `the_repository`), which prevents the use of `repo_ignore_case()` in submodule contexts.
- **Behavioral changes**: No intended user-visible changes, but the series removes lazy-loading, which may affect performance or error handling in edge cases (e.g., repositories with thousands of alternates, corrupt alternates, or commands that previously avoided loading alternates entirely). Patch 2/5 retains case-insensitive deduplication but documents it as a candidate for future removal. The first patch’s correctness fix for `core.ignoreCase` lookups is now blocked by the `repo_config_values()` constraint. Patch 3/5 centralizes alternate initialization, which may slightly increase startup time for commands that previously avoided loading alternates when none were present (e.g., `git fsck`). Patches 4/5 and 5/5 are mechanical cleanups with no behavioral impact.
- **Code delta**: Net reduction of 16 lines across the series (98 insertions, 114 deletions). The first patch adds 6 lines, patch 3/5 removes 42 lines (46 deletions, 4 insertions), patch 4/5 removes 9 lines (1 insertion, 10 deletions), and patch 5/5 removes 6 lines (9 insertions, 15 deletions).
