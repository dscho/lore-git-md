This is a CI/build system discussion in the ongoing thread about bumping the Ubuntu image for Git's static-analysis job. Patrick Steinhardt responds to Junio C Hamano's proposal to improve Coccinelle rule maintenance by adding exit criteria and updating the README.

Patrick clarifies that Git's build system (both Makefile and Meson) currently runs *all* Coccinelle files against the codebase without classification, except for files with a `.pending` suffix, of which there is only one (`config_fn_ctx`). He suggests that many existing rules—such as those for `refs`, `object_id`, and `the_repository` migrations—were likely misclassified and should have been marked as `.pending`. More fundamentally, he questions whether the Coccinelle rules have provided real value: while they were intended to help contributors adjust in-flight patches during API migrations, he doubts anyone has ever used them for that purpose. His tone is skeptical, and he floats the idea of discontinuing the practice altogether.

The email is substantive, shifting the discussion from the immediate image bump to a broader critique of Coccinelle's role in Git's workflow. It does not address the performance regression SZEDER Gábor reported, nor does it propose a concrete alternative—just a provocative question about whether the effort is worth continuing.
