This is a bugfix patch addressing a use-after-free in `get_oid_with_context_1()` when resolving relative paths in the `:<stage>:<path>` syntax against a sparse index. The patch is now in its second version, with no functional changes from v1—only an added `Original-patch-by:` trailer to credit Johannes Schindelin.

Patrick Steinhardt’s review confirms the fix is correct and the test reliably reproduces the bug under address sanitization. The issue occurs when `resolve_relative_path()` allocates a new string for the resolved path, but the code frees it while still holding a pointer (`cp`) to it, leading to a use-after-free in `reject_tree_in_index()`. The fix consolidates the exit paths to ensure the string is freed only after its final use. Patrick suggests a minor stylistic tweak (inverting the `reject_tree_in_index()` call) but does not insist on it, calling the current version "a clear improvement."

The test in `t1092-sparse-checkout-compatibility.sh` exercises the three necessary conditions—relative path, sparse directory, and leading colon followed by a digit—and Patrick’s test run shows it catches the bug, replacing a valid path with garbage characters in the error message. René Scharfe’s earlier substantive review and explicit approval ("OK") suggest this is uncontroversial and ready for integration.
