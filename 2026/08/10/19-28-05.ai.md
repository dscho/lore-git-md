This is a **security-focused follow-up** in the `gitk` custom commands thread. The author (Tim Wiederhake) acknowledges Junio C Hamano’s critical security concern: the current implementation is vulnerable to shell injection via unquoted placeholder substitution (e.g., `%t` for commit title, `%m` for commit message). The vulnerability arises from interpolating arbitrary commit metadata into shell commands without proper escaping.

Tim explains that the initial version of the patch avoided this issue by calling commands directly (without `sh -c`), but later added `sh -c` to support process forking (`&`) and exit-code manipulation (e.g., `command && exit 42`). He now expresses uncertainty about the best path forward: either (1) revert to direct command execution and require users to write wrapper scripts for advanced use cases, or (2) implement proper escaping for all interpolated values while retaining the convenience of shell features.

The email does not propose a concrete fix or updated patch, but explicitly invites opinions on the trade-off between security and usability. This keeps the thread open on the security blocker while deferring the implementation decision.
