This is a follow-up discussion in the ongoing refactoring thread about Git’s repository configuration handling. Patrick Steinhardt expands on Junio C Hamano’s earlier skepticism about the current design, proposing a concrete path forward for decoupling configuration from `the_repository`. He suggests merging `repo_settings` and `repo_config_values` into a single `git_config_values` or `git_settings` structure, then splitting it into two levels: one tied to a repository (as today) and one truly global (for system- and user-wide settings). The `repo_config_values()` function would then return a constant pointer to the appropriate structure based on whether a repository is passed, with callers forbidden from modifying it directly. Patrick acknowledges that enforcing immutability could require significant caller-side changes (e.g., passing `struct git_config_values` down call chains instead of `struct repository`), but argues this is the right direction for subsystems that operate independently of repositories. He reiterates that this discussion is exploratory and does not block Tian Yuchen’s current cleanup series, which remains technically complete and ready for final review. Key technical details for future reference: the proposal centers on unifying `repo_settings` and `repo_config_values`, introducing a global `git_config_values` structure, and adapting `repo_config_values()` to handle both repository-bound and global contexts.
