This thread is about a Windows-specific bugfix in Git's sequencer subsystem, authored by Johannes Schindelin. The issue occurs during interactive rebase when the sequencer holds the object database (ODB) lock while spawning `git commit`, which can deadlock on Windows if the child process triggers auto-maintenance (like repacking). The fix is a one-line change in `sequencer.c` that releases the ODB before spawning the commit command, following an established pattern from a prior fix (28d04e1ec197).

The patch includes a Windows-specific regression test that forces a repack via a post-commit hook and uses `GIT_TEST_LEGACY_DELETE=1` to expose the issue on modern Windows systems. The test confirms the ODB is properly released by checking that only one packfile remains after the repack. The commit message traces the bug's origin to 2017 (4557f1add261) and references the Git for Windows issue tracker. While the fix is narrowly scoped to Windows, it aligns with cross-platform resource management practices in the codebase. No objections or review feedback have been reported yet.
