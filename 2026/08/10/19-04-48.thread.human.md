This thread is about a Windows-specific bugfix for a deadlock in Git's sequencer during interactive rebase. The issue occurs when the sequencer holds the object database (ODB) lock while spawning `git commit`, causing child processes that trigger auto-maintenance (like repacking) to fail on Windows due to locked files. Johannes Schindelin (Dscho) authored the fix, which follows an established pattern by releasing the ODB before spawning commands that might run maintenance, then reacquiring it afterward.

The patch is minimal—a single line in `sequencer.c`—and includes a Windows-specific regression test in `t/t3404-rebase-interactive.sh`. Junio C Hamano initially raised a concern about the safety of releasing resources mid-operation, but this was addressed in an updated commit message that clarifies the reacquisition strategy. No further objections remain, and Junio has marked the patch for inclusion in the `next` branch, signaling it’s ready for integration testing. The fix is narrowly scoped to the sequencer’s resource management and introduces no on-disk format changes.
