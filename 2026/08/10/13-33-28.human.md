This is the first patch in Patrick Steinhardt’s four-part refactoring series to remove lazy-loading of alternate object databases in Git’s ODB subsystem. It addresses a technical debt issue in how alternate sources are deduplicated during registration.

The patch decouples the comparison of object database source paths from Git’s global `the_repository` variable. Currently, the code uses `fspathhash()` and `fspatheq()` for deduplication, which implicitly depend on `the_repository` and its `core.ignoreCase` setting. This creates a subtle bug: if alternates are registered before the repository’s configuration is parsed, the case-sensitivity check may return the wrong result, leading to inconsistent deduplication.

The fix replaces the `khash`-based map with a `hashmap` that uses custom comparison logic. The new implementation resolves `core.ignoreCase` manually during the first comparison, ensuring consistent behavior regardless of when alternates are registered. The patch also introduces a new field, `source_paths_icase`, in the `object_database` struct to cache the case-sensitivity setting.

While the change is technically sound, Patrick notes that the complexity might not be justified. The original optimization (introduced in 2021) was aimed at handling repositories with thousands of alternates, a rare edge case. However, he opts to preserve the performance benefit rather than regress it. The patch is a prerequisite for the rest of the series, which will remove lazy-loading entirely.

No behavioral changes are intended, but the patch touches core ODB internals, so careful review is warranted. The commit message is clear and well-motivated, and the code delta is focused. This looks like a solid cleanup step in the broader ODB abstraction effort.
