This is a review comment on the third patch in Justin Tobler’s seven-patch v2 series, which refactors `git receive-pack` to read the unpack limit configuration lazily rather than using global variables. The series is part of the ongoing ODB abstraction effort to make packfile writes backend-agnostic.

Junio Hamano questions whether the proposed `get_unpack_limit()` helper, which caches its result in a static variable, is an improvement over the original global variables. He suggests that the setting should be stored in `repo->settings` or `repo->config_values` to make it truly per-repository, avoiding the implicit global state of a static variable. The comment is brief but targets a core design choice: whether the patch’s approach to lifting global state is sufficiently thorough or merely replaces one form of global state with another.

The feedback is substantive but not blocking; it invites the author to reconsider the implementation rather than rejecting the patch outright. The series as a whole remains under active review, with the next iteration (v3) expected to address Junio’s feedback on transaction lifecycle and backend design flaws in other patches. This specific comment does not appear to require changes to the rest of the series, but it may prompt a small refactoring in this patch to align with Git’s broader pattern of per-repository configuration storage.
