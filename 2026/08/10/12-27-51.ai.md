This is the core patch of D. Ben Knoble’s three-part series converting the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The author responds to Junio C Hamano’s performance critique by benchmarking both the original implementation (which parses the config key on every `is_racy_stat()` call) and a proposed fix that caches the value in the repository’s `repo_config_values` struct.

The benchmarks confirm Junio’s concern: in a new worktree, `git diff` is ~41× slower with the original implementation (`~854 ms` vs `~20 ms`). The proposed fix restores performance to parity with the baseline (`~21 ms` vs `~20 ms`), eliminating the hot-path regression. The author acknowledges the need to move the setting into `repo_settings` (rather than `repo_config_values`) for consistency with other runtime-configurable options and plans to include this change in v2. A minor naming debate (`core.useNanosec` vs a more generic name) and coordination with the conflicting `ty/repo-config-cleanups` topic remain open but are not blockers for the next iteration. The patch touches `read-cache.c`, `environment.c`, and documentation files, and the on-disk format is unchanged.
