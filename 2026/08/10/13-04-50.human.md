This is a usability-focused bugfix patch for `git worktree add`. The author, Yoichi Nakayama, is revising the error message shown when a user tries to create a worktree from a branch name that exists on multiple remotes (e.g., `git worktree add foo` when both `origin/foo` and `upstream/foo` exist). The current warning is terse ("matched multiple remote tracking branches"), and the patch aims to replace it with actionable advice.

The discussion has converged on the core problem: the advice should help users *discover* which remotes have the branch, not just tell them to use a fully qualified name. Junio C Hamano’s review pushed for listing the conflicting remotes directly (e.g., "the branch exists on `origin`, `upstream`, and `home`"), while Yoichi initially proposed showing a command to list them (`git branch -r`). In this reply, Yoichi agrees to shift the advice toward discovery, saying he will update the patch to present the remotes directly rather than a workaround.

The patch touches `builtin/worktree.c` (where the DWIM logic lives) and updates tests in `t/t2400-worktree-add.sh`. The new advice is gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key, which defaults to true. This is a small, self-contained change that follows Git’s established advice-message conventions. The remaining work is purely about the advice message’s content and formatting—no behavioral changes are in dispute.
