This is a refactoring patch series from Patrick Steinhardt targeting the object database (ODB) subsystem. It removes the lazy-loading behavior for alternate object databases, which currently delays their initialization until first access. The series consists of four patches that collectively simplify the codebase by eagerly loading alternates during ODB initialization.

The motivation is that Git has evolved to parse alternates eagerly in many places anyway, making the lazy-loading optimization largely obsolete. The current approach scatters `odb_prepare_alternates()` calls throughout the code, which Patrick argues is awkward and doesn't provide meaningful performance benefits since most Git commands end up reading objects. This change also prepares the ground for moving alternates into the "files" backend, as discussed in a linked discussion.

The patches touch 12 files, primarily in the ODB subsystem (`odb.c`, `odb.h`, `odb/source.h`), with minor changes to built-in commands (`fsck.c`, `pack-objects.c`) and other core components (`commit-graph.c`, `object-name.c`, etc.). The series builds on Patrick's recent work to make ODB creation pluggable (`ps/odb-make-creation-pluggable`).
