This is a follow-up in the thread improving the error message for `git worktree add` when an ambiguous remote branch name is provided. The patch, part of a single-patch series by Yoichi NAKAYAMA, aims to replace the terse "matched multiple remote tracking branches" warning with a detailed advice message listing conflicting remotes to help users resolve the ambiguity.

In this reply, Yoichi responds to Junio C Hamano’s review feedback, which questioned whether the advice message should be tailored to the two distinct scenarios where the ambiguity arises: when `worktree.guessremote` is set (implying the user expects Git to infer the branch name from the path) and when it is not (implying the user explicitly provided a branch name). Junio suggested the advice might be more helpful if it accounted for these differing intents. Yoichi clarifies that the original concern—whether the guess was successful—is already addressed by an existing message (`branch 'name' set up to track 'remote/name'`), and thus no changes are needed to distinguish the scenarios. This narrows the focus of the patch to the advice message’s content and formatting, rather than its contextual relevance.

The patch remains a well-motivated usability improvement, touching `builtin/worktree.c` and `t/t2400-worktree-add.sh`, with the new advice gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default). Junio’s earlier feedback also flagged surface-level issues (unnecessary newline in the warning, unnecessary braces in the code), which Yoichi has not yet addressed in this reply. The next iteration will likely focus on refining the advice message’s wording and formatting, as well as incorporating Junio’s style nits, while leaving the core logic unchanged. No other participants have weighed in since the initial review.
