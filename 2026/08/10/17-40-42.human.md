This is the second patch in the v4 series introducing `git repack --drop-filtered` for partial clones. It adds a new helper function, `list_objects_filter__filter_oidset()`, to the list-objects-filter API. This helper allows callers to apply a filter (currently only `blob:limit`) to an existing set of OIDs without performing an object walk, which is exactly what `--drop-filtered` needs: it collects promisor blobs into an oidset and then filters out those exceeding the size threshold.

The implementation is straightforward but pragmatic. Instead of reusing the existing filter machinery (which is tied to the object-walk path), it duplicates the `blob:limit` size check logic directly. A `NEEDSWORK` comment marks this duplication for future refactoring. The helper avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info, ensuring it only operates on locally available data. It silently skips objects that cannot be read, which is appropriate for this use case.

The patch is well-scoped and production-ready. It adds 45 lines to `list-objects-filter.c` and 16 lines to `list-objects-filter.h`, with no behavior changes to existing code. The new function is immediately used in patch 4/7 (`enumerate_promisor_blobs()`) to filter the set of promisor blobs collected from the ODB. The duplication of the size check is a minor wart, but it doesn’t affect correctness and is clearly flagged for future cleanup.

This is a refactoring-style patch that enables the core functionality of the series. It’s uncontroversial and unlikely to draw substantive feedback beyond the `NEEDSWORK` comment, which the author has already acknowledged. The patch is part of a well-reviewed series that has addressed all prior feedback, and the helper it introduces is a clean, focused addition to the filter API.
