This is a small but well-crafted bugfix for `git send-email`. The patch updates the error message shown when a patch file lacks a "Subject:" header, replacing the cryptic "No subject line in <file>?" with the clearer "No 'Subject:' line in '<file>'". It also suppresses Perl's internal source location by terminating the message with a newline.

The change is minimal—just one line in `git-send-email.perl`—and includes a new test in `t/t9001-send-email.sh` that verifies the error message is clean and matches expectations. The test creates a patch file without a subject, runs `git send-email --dry-run`, and checks the output.

This version (v2) addresses feedback from Junio C Hamano on the initial submission. The original wording incorrectly implied the "Subject:" header must be on the first line; the revised message now accurately reflects that the code scans the entire header section for the "Subject:" line. The fix is uncontroversial, well-tested, and directly improves usability for users unfamiliar with Git's patch format conventions. It looks ready for merging.
