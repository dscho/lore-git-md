This is a CI/build system discussion reply from Patrick Steinhardt in the thread about bumping the Ubuntu image for Git's static-analysis job. Patrick responds to Junio C Hamano's proposal to improve Coccinelle rule maintainability by clarifying that Git's build system does not currently classify or selectively run `.cocci` files—it simply concatenates and runs all of them. He notes the `.pending` suffix as the sole exception (with only one such file in the tree) and suggests that many other rules should have been marked as pending but were not, likely due to oversight.

Patrick then questions the broader value of Coccinelle rules altogether, observing that while he has introduced some to ease API migrations, he doubts anyone has ever used them to adapt in-flight patch series. He proposes discontinuing the practice of writing Coccinelle rules for API changes, framing it as a potential simplification rather than an immediate action. The reply is substantive, raising a fundamental question about tooling utility and inviting discussion on whether the current approach is worth maintaining. No merge status or technical objections are raised; the thread remains under review.
