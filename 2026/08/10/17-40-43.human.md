This is the third patch in the v4 series introducing `git repack --drop-filtered` for partial clones. It extends `repack_promisor_objects()` to accept an optional `to_drop` oidset; when provided, the function rebuilds the promisor pack while excluding those objects. The change is minimal and backward-compatible: all existing callers pass `NULL`, so their behavior is unchanged. This is the mechanism `--drop-filtered` will use to remove promisor blobs from the repository.

The patch touches three files: `builtin/repack.c` (updates the call site to pass `NULL`), `repack-promisor.c` (core logic: the `write_oid()` callback now checks `to_drop` and skips objects present in the set), and `repack.h` (function signature change). The implementation is straightforward and well-contained, with clear comments explaining the purpose of the `to_drop` parameter. The `write_oid()` callback’s new check is concise and avoids lazy fetches by design, since it operates only on locally available data.

This patch is a refactoring that enables the core functionality introduced later in the series (patch 5/7 wires up the `to_drop` set computed by `enumerate_promisor_blobs()`). It is production-ready and has no known issues. The backward-compatibility guarantee means it can be merged independently if needed, though it is logically part of the larger `--drop-filtered` feature. No new tests are added here, as the functionality is exercised by the higher-level tests in patch 5/7.
