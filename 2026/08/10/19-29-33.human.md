This is the final patch in Justin Tobler’s v2 series converting `git receive-pack` to use the ODB transaction system for pluggable packfile writes. The patch introduces `odb_transaction_write_pack()` as a generic interface, replacing the hardcoded calls to `git index-pack` and `git unpack-objects` with a backend-agnostic mechanism. The "files" backend implementation reuses the existing `unpack()` logic, including handling `.keep` lockfiles, which the transaction now owns and removes post-commit via its release callback.

Junio Hamano’s review of this patch identified a design flaw: the "files" backend hardcodes `repo->objects->sources[0]` when calling `odb_source_prepare()`, ignoring the transaction’s own source (`base->source`). Justin acknowledges the awkwardness and fragility of this approach and plans to address it in v3 by tracking the transaction’s ODB source separately, rather than relying on the source list’s ordering. This change would align with the broader ODB abstraction effort and improve robustness when multiple backends are in use.

The patch itself is well-motivated and clearly part of a larger architectural push. The commit message explains the rationale (enabling alternative ODB backends) and the mechanics (transaction ownership of `.keep` lockfiles) thoroughly. The design flaw Junio pointed out is real but fixable, and Justin’s response suggests he’s already thinking about a cleaner solution. The series as a whole looks like a serious, incremental step toward pluggable backends, and this patch is the linchpin that makes the abstraction usable for `receive-pack`. Worth watching for the v3 iteration, especially if you care about ODB flexibility or the transaction system’s evolution.
