This is a detailed bug report about a critical concurrency issue in Git’s geometric repacking auto-maintenance feature, introduced in Git 2.54.0. Stefan Haller identifies two interconnected problems: (1) the auto-repack condition triggers far too eagerly—on repositories with as few as four objects, rather than the documented 100—due to a scaling bug in the loose-object count estimator, and (2) the resulting background repacks race with concurrent Git commands, causing intermittent failures (e.g., "invalid object" errors, failed commits, or temporary-file creation errors) at a rate of roughly one per 1,100 commits in stress testing.

The root cause is a mismatch between the documented threshold (100 loose objects) and the implementation, which uses a directory-based estimator that effectively rounds up to the nearest 256 objects. This makes the condition sensitive to hash collisions in the `.git/objects/17/` directory, triggering repacks unpredictably even in tiny repositories. The background repacks then interfere with concurrent operations by removing loose objects or directories mid-flight, leading to race conditions that Git’s single-retry logic cannot handle. Stefan’s reproducer and stress test demonstrate the issue clearly, and he traces the problem back to the geometric repacking default introduced in February 2026.

This is a serious regression with real-world impact: Stefan reports that lazygit’s CI tests started failing intermittently after upgrading to Git 2.54.0, and the workaround (disabling auto-maintenance) is not ideal for users. The report is thorough, with code references, test cases, and a clear explanation of the failure modes. Patrick Steinhardt has already acknowledged the issue as a legitimate bug, and this email provides the reproducer he requested. The problem is likely to block the geometric repacking series from merging until resolved, as it undermines the safety of the auto-maintenance mechanism. Developers working on maintenance, repacking, or object storage should pay attention—this touches core concurrency and reliability guarantees.
