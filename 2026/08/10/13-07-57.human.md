This is a substantive review of Yoichi NAKAYAMA’s patch improving the error message for `git worktree add` when an ambiguous remote branch name is provided. D. Ben Knoble raises a key behavioral change: the patch now calls `die()` when an ambiguous branch name is detected, whereas the original code did not. This is a significant shift—previously, the command might have failed later with a less helpful error, but now it fails immediately with a clearer diagnostic.

The review questions whether this change could disrupt existing workflows that might have relied on the command proceeding further before failing. Knoble suggests the commit message should clarify whether the early `die()` is safe (e.g., because the ambiguity would have caused a failure later anyway) or if it introduces a new failure mode. The concern is well-placed: while the improved error message is a usability win, the change in control flow could have unintended consequences for scripts or automation that expected the command to continue.

The patch itself remains focused on `builtin/worktree.c` and the test script, and the advice message (now command-based) is still the central feature. However, Knoble’s feedback highlights that the *behavioral* change (early termination) needs justification, not just the *message* change. This is a substantive point that could shape the next iteration of the patch.
