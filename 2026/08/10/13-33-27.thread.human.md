This thread is about Patrick Steinhardt’s four-patch series to remove lazy-loading of alternate object databases in Git’s ODB subsystem. The goal is to simplify the code by initializing all alternates upfront during ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work on the ODB abstraction. The series also resolves a long-standing inconsistency in case-sensitivity handling for alternate paths when they are registered before repository configuration is parsed.

The v2 patches are unchanged from v1 except for minor clarifications: a commit message typo fix and a comment explaining environment variable handling during cache flushing. The series is queued in Junio’s `seen` branch, with a minor merge conflict resolved during integration. Patrick has asked Junio to verify the merge result, and a procedural question about the merge strategy remains unanswered, but neither affects the series’ content. Reviews from Justin Tobler and Karthik Nayak have been largely positive, with no substantive objections or requests for changes. Justin’s v1 review engaged with the technical rationale for patch 1 (case-sensitivity handling) and raised a clarifying question about patch 4 (environment variable handling), both of which Patrick addressed in v2. Karthik’s v2 review was surface-level, focusing on commit message clarity and confirming the series is ready for integration.

The only open technical concern is whether eager loading could regress performance for commands like `git fsck` that previously avoided loading alternates when none were present. This trade-off was acknowledged in the commit message but has not been revisited in reviews. The series touches 12 files, primarily in the `odb/` subsystem, and removes 16 lines of code net. It depends on Patrick’s prior ODB refactoring work and is part of the broader ODB abstraction effort. No further changes are expected unless Patrick’s verification of the merge result surfaces issues.
