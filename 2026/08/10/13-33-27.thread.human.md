Patrick Steinhardt’s patch series to remove lazy-loading of alternate object databases in Git’s ODB subsystem is now in its third iteration, with the latest discussion focused on a correctness issue in the first patch. The series aims to simplify the code by loading all alternate ODBs upfront during primary ODB setup, eliminating scattered calls to `odb_prepare_alternates()` and paving the way for future work to move alternates into the "files" backend. The current version (v2) is queued in Junio’s `seen` branch, but a v3 is needed to address design feedback and a timing issue with `core.ignoreCase` lookups.

The key sticking point is patch 1, which originally retained case-insensitive deduplication of alternate paths but has since converged on a simpler, case-sensitive approach. Jeff King raised a correctness concern: the current implementation might cache the wrong value of `core.ignoreCase` if alternates are loaded before the repository’s configuration is fully initialized (e.g., during `git init` or `git clone`). Patrick proposes a targeted fix by cherry-picking a patch from a later series to ensure `core.sharedRepository` is set before `create_object_directory()` is called, but he rejects using `repo_ignore_case()` due to its reliance on `the_repository`, which would break submodule support. The discussion remains narrowly focused on this timing issue, with no new debate about the broader design or the earlier consensus to drop case-insensitive handling entirely.

The series touches 12 files, primarily in the `odb/` subsystem, and removes or modifies several symbols, including `loaded_alternates`, `alternates_db`, and `odb_prepare_alternates()`. While the changes are intended to be user-invisible, they may affect performance or error handling in edge cases, such as repositories with thousands of alternates or corrupt alternates. Reviewers have largely endorsed the simplification, but the performance implications for commands like `git fsck`—which previously avoided loading alternates when none were present—remain untested. Patrick is expected to post a v3 revision soon, incorporating the fix for the timing issue and likely reverting to case-sensitive comparisons. The procedural question about Junio’s merge strategy is still unanswered but doesn’t affect the series’ content.
