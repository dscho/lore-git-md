This thread is about Patrick Steinhardt’s four-patch series to remove lazy-loading of alternate object databases in Git’s ODB subsystem. The goal is to simplify the code by initializing all alternate ODBs upfront during primary ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work like moving alternates into the "files" backend. The series also resolves long-standing case-sensitivity inconsistencies in alternate path handling.

The patches are queued in Junio’s `seen` branch as of July 10, with all feedback from reviewers Justin Tobler and Karthik Nayak addressed in the v2 update. The only unresolved procedural question is Junio’s merge strategy, which Patrick clarified but Junio hasn’t yet responded to. The latest email is a minor stylistic discussion between Karthik and Patrick about a one-line simplification in patch 1, which Patrick rejected as functionally incorrect. No changes to the series are expected from this exchange.

The series is uncontroversial and ready for integration, with no open technical objections. The main loose end is Patrick’s pending verification of the merge result, which may surface integration issues. Performance implications for commands like `git fsck` (which previously avoided loading alternates when none were present) remain unaddressed but are acknowledged as low-risk. Key participants include Patrick (author), Justin Tobler (substantive review of patch 1), Karthik Nayak (surface-level reviews), and Junio (maintainer, queued the series).
