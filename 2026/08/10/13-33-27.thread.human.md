This thread is about Patrick Steinhardt’s five-patch series (v3) refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternate object databases. The goal is to simplify the code by initializing all alternates upfront during ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The series also fixes a correctness issue with `core.ignoreCase` lookups, though this fix is now blocked by a technical constraint: `repo_ignore_case()` cannot be used because it relies on `repo_config_values()`, which is hardcoded to `the_repository` and would break submodule support.

The series is currently queued in Junio’s `seen` branch, but its integration is uncertain due to unresolved issues. The first patch attempts to fix the `core.ignoreCase` timing issue by reordering repository initialization, but this approach is blocked by the `repo_config_values()` limitation. The second patch migrates the deduplication mechanism from `khash` to `hashmap` to support dynamic comparison functions, retains case-insensitive deduplication, and documents it as `NEEDSWORK` to signal it may be removed later. Patches 3–5 proceed as previously described, centralizing alternate initialization and removing redundant fields.

Junio’s latest review focuses on the second patch, raising substantive concerns about the use of `core.ignoreCase` for case-insensitive path comparisons. He questions whether the repository configuration is the right place for this setting, noting that if a repository spans filesystems with different case sensitivities, the current approach could lead to inconsistent behavior. Junio suggests alternatives, such as requiring users to spell paths consistently or declaring that repositories cannot span mixed filesystems, and proposes that each ODB source should report its own case-sensitivity. He also flags a correctness issue: `odb_source_paths_cmp()` might be called before the repository’s configuration is fully loaded, risking unsafe behavior. His feedback aligns with the broader consensus that the case-insensitive deduplication mechanism may not be worth retaining, though no final decision has been made.

Key participants include Patrick (author), Junio (maintainer), Jeff King (Peff), Justin Tobler, and Karthik Nayak. Peff previously critiqued the design, arguing for dropping case-insensitivity entirely, while Justin and Karthik provided surface-level reviews. The unresolved `core.ignoreCase` timing issue and Junio’s latest concerns about case-sensitivity handling are the main blockers. The series’ future depends on whether Patrick can address these issues or whether the project will opt to simplify the design by removing the case-insensitive logic.
