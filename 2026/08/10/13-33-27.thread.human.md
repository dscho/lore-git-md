This thread is about Patrick Steinhardt’s five-patch series (v3) to refactor Git’s object database (ODB) subsystem by removing lazy-loading of alternate object databases. The goal is to simplify the code by initializing all alternates upfront during ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work to move alternates into the "files" backend. The series also fixes a correctness issue with `core.ignoreCase` lookups by reordering repository initialization, though this approach is now blocked by technical constraints and design concerns raised by Junio Hamano.

The key sticking point is the deduplication mechanism for alternate ODB sources, which currently uses `core.ignoreCase` for case-insensitive path comparisons. Junio has questioned whether this mechanism should exist at all, given the potential for inconsistent behavior across filesystems with mixed case sensitivity. Patrick argues that the mechanism, while imperfect, has worked reliably for years and removing it could regress edge cases like repositories with thousands of alternates. The v3 patch retains the mechanism but documents it as `NEEDSWORK`, signaling it may be removed later. Junio also raised a correctness concern about repository initialization timing, which Patrick addressed by ensuring the repository is fully initialized before ODB creation.

The series is queued in Junio’s `seen` branch, but integration is delayed by the unresolved `core.ignoreCase` constraints. Reviewers like Jeff King (Peff) and Justin Tobler have engaged with earlier versions, but the latest discussion focuses on the trade-offs between simplicity and backward compatibility. No consensus has emerged on whether to drop the case-insensitive deduplication entirely, default to case-sensitive comparisons, or retain the current behavior with its limitations. The series touches 14 files, primarily in the `odb/` subsystem, and introduces no intended user-visible changes, though eager alternate loading may slightly increase startup time for some commands.
