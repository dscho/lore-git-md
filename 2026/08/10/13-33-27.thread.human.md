This thread is a four-patch series from Patrick Steinhardt refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternate object databases. The goal is to simplify the code by initializing all alternates upfront during ODB setup, reducing scattered calls to `odb_prepare_alternates()` and paving the way for future work like moving alternates into the "files" backend. The first patch decouples path comparisons for alternate ODB sources from `the_repository` to fix long-standing case-sensitivity inconsistencies, while the remaining patches centralize alternate initialization and remove now-unused fields.

The series is under review, with Justin Tobler as the primary reviewer. His feedback on the first patch was substantive, engaging with the technical rationale and validating the implementation, though he questioned the added complexity for deduplicating alternates. His reviews of the later patches were more surface-level, focusing on mechanical correctness and commit message clarity. The latest exchange clarifies a narrow but important detail: whether the removal of the `alternates_db` field in the fourth patch means `GIT_ALTERNATE_OBJECT_DIRECTORIES` no longer needs to be passed when flushing caches. This suggests the eager initialization in patch 2 already handles environment variables, but the question remains open for Patrick to confirm.

No objections or requests for changes have been raised, but the series could benefit from broader scrutiny on performance trade-offs, particularly for commands like `git fsck` that previously avoided loading alternates when none were present. The code is mechanically clean, with a net reduction of 30 lines, and builds on Patrick’s prior ODB refactoring work. The only open questions revolve around edge-case handling and the added complexity in the first patch.
