This thread is a four-patch series from Patrick Steinhardt refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternate object databases. The goal is to simplify the code by initializing all alternates upfront during ODB setup, reducing scattered calls to `odb_prepare_alternates()` and paving the way for future work like moving alternates into the "files" backend. The series is now at v2, incorporating feedback from Justin Tobler on the initial submission.

The first patch decouples path comparisons for alternate ODB sources from `the_repository`, fixing long-standing inconsistencies in case-sensitivity handling when alternates are registered before repository configuration is parsed. Justin Tobler reviewed this substantively in v1, questioning the added complexity for deduplication but ultimately approving the approach. The second patch eagerly initializes alternates during ODB setup, removing 13 calls to `odb_prepare_alternates()` across 10 files and centralizing initialization. The third and fourth patches are mechanical cleanups, removing now-unused fields (`loaded_alternates` and `alternates_db`) from the ODB structure. Justin’s reviews of these were surface-level, focusing on commit message clarity and minor technical clarifications, such as how `GIT_ALTERNATE_OBJECT_DIRECTORIES` is handled during cache flushing—a point Patrick addressed in v2 with an added comment.

The series touches 12 files in total, primarily in the `odb/` directory, and results in a net reduction of 16 lines of code. While the changes are not intended to alter user-visible behavior, they remove lazy-loading, which could affect performance or error handling in edge cases (e.g., repositories with many alternates or commands like `git fsck` that previously avoided loading alternates when none were present). These concerns remain unaddressed in reviews, though Patrick’s commit messages acknowledge them as low-risk trade-offs. The series builds on Patrick’s prior ODB refactoring work and is part of the broader effort to make Git’s object storage layer more modular. With Justin’s feedback incorporated and no outstanding objections, the series appears ready for integration.
