This thread is about Patrick Steinhardt’s patch series to refactor Git’s object database (ODB) subsystem by removing lazy-loading of alternate object databases. The goal is to simplify the codebase by initializing all alternate ODBs upfront during primary ODB setup, eliminating scattered calls to `odb_prepare_alternates()` and paving the way for future work to move alternates into the "files" backend. The series is now at version 3 (v3) and consists of five patches, with the first patch addressing a critical timing issue with `core.ignoreCase` lookups by reordering repository initialization.

The series has seen significant design discussion, particularly around whether to retain case-insensitive deduplication of alternate paths. The consensus leaned toward removing it for simplicity, but the current implementation retains it while documenting it as `NEEDSWORK` for potential future removal. The series was queued in Junio’s `seen` branch on July 10, 2024, but its integration status remains uncertain as Junio’s "What's cooking" report has not yet mentioned it. Key reviewers include Jeff King (Peff), who raised concerns about the timing of `core.ignoreCase` lookups and the viability of using `repo_ignore_case()` in submodule contexts, and Justin Tobler and Karthik Nayak, who provided feedback on earlier versions.

The latest email from Peff highlights a technical blocker: `repo_ignore_case()` cannot be used in the current patch because it relies on `repo_config_values()`, which is hardcoded to `the_repository` and would break submodule support. Peff called this limitation "gross" but accepted that the function is not yet suitable for Patrick’s use case. This leaves the timing issue in patch 1 unresolved, with no clear path forward—Patrick may need to implement a submodule-compatible version of `repo_ignore_case()`, revert to case-sensitive comparisons, or proceed with the current approach while documenting the limitation. The broader series remains queued, but this unresolved issue could delay its progress.
