This thread is a four-patch series from Patrick Steinhardt refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternate object databases. The goal is to simplify the codebase by initializing all alternate ODBs upfront during primary ODB setup, reducing scattered calls to `odb_prepare_alternates()` and paving the way for future work to move alternates into the "files" backend.

The series is now complete with the fourth patch, which removes the now-unused `alternates_db` field from the ODB structure. This is a mechanical cleanup following the architectural shift in the second patch, which centralized alternate initialization in `odb_new()`. The first patch decoupled path comparisons for alternate ODB sources from `the_repository` to resolve long-standing case-sensitivity inconsistencies, while the third patch removed the unused `loaded_alternates` field. The net result is a 25-line reduction across the series, with no intended user-visible changes.

The series is under review, with no objections or requests for changes raised yet. Key areas for reviewer scrutiny include the performance implications of eager alternate loading—particularly for commands like `git fsck` that previously avoided loading alternates when none were present—and the added complexity in the first patch, which introduces ODB-specific case-sensitivity handling. The series builds on Patrick’s prior ODB refactoring work and is part of the broader effort to make Git’s object storage layer more modular.
