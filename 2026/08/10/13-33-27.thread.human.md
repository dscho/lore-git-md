This thread is a four-patch series from Patrick Steinhardt refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternate object databases. The goal is to simplify the code by initializing all alternates upfront during ODB setup, reducing scattered calls to `odb_prepare_alternates()` and enabling future work on the ODB abstraction effort. The series is under review, with all patches posted and no major objections raised.

The first patch decouples path comparisons for alternate ODB sources from `the_repository`, fixing long-standing inconsistencies in case-sensitivity handling. Justin Tobler reviewed this substantively, validating the implementation but questioning the added complexity for deduplicating alternates. Patrick defended the change as a "safe side" measure, and the discussion confirmed the patch’s correctness. The second patch centralizes alternate initialization, removing redundant calls across the codebase. Justin’s review here was surface-level, focusing on a commit message typo rather than deeper technical implications. The third and fourth patches are mechanical cleanups, removing now-unused fields from the ODB structure.

The only open question—Justin’s request for clarification on how `GIT_ALTERNATE_OBJECT_DIRECTORIES` is handled during cache flushing—was resolved in the latest exchange. Patrick confirmed that alternates are fully initialized during `odb_new()` and that subsequent calls only re-read the alternates file, not the environment variable. He plans to add a comment to clarify this behavior. The series is now uncontroversial, with no outstanding technical concerns, though performance implications for edge cases (e.g., repositories with thousands of alternates) remain unaddressed in reviews. The net result is a 30-line reduction in code, improving maintainability.
