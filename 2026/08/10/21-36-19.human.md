This is a usability-focused bugfix for `git worktree add`. The patch improves error messages when users provide an ambiguous remote branch name (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The current behavior fails with a generic "invalid reference" error, but the patch now detects ambiguity earlier and provides a clearer diagnostic, along with an advice message that suggests a command (`git branch -r --list '*/<name>'`) to help users explore conflicting remotes.

The discussion has converged on the core design: the advice message is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and uses a command-based approach to avoid overwhelming users with static lists. The patch also refines error handling by moving an existing `die()` call earlier in the code path, replacing the misleading "invalid reference" message with a more specific diagnostic. This change was initially questioned by D. Ben Knoble, but the author clarified that the command was already failing—just with less clarity—and the commit message now traces the problematic flow to justify the early `die()` as intentional.

The implementation touches `builtin/worktree.c` and updates tests in `t/t2400-worktree-add.sh`. Junio C Hamano’s feedback on the commit message’s clarity has been addressed, and the only remaining loose ends are minor code nits (unnecessary newline, braces), which are secondary to the usability improvements. The patch is well-motivated, localized, and unlikely to be controversial. If you care about Git’s user experience, this is worth a quick look.
