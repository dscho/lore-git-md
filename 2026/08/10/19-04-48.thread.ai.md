Thread identity: Bugfix for Windows-specific resource contention in the sequencer during interactive rebase (single patch, no series version). Author: Johannes Schindelin (Dscho).

Core problem or goal: Fix a deadlock on Windows where the sequencer holds the ODB lock while spawning `git commit`, causing child processes that trigger auto-maintenance (e.g., repacking) to fail when attempting to replace files still locked by the parent. The fix releases the ODB before spawning commands that might run maintenance, following an established pattern.

Current status: Under review. Junio C Hamano has raised a substantive concern about the safety of releasing resources mid-operation, requesting clarification in the commit message that the ODB will be reacquired in a "refreshed state" after auto-maintenance completes. The patch remains technically sound and aligns with existing patterns, but the rationale needs strengthening before acceptance.

Key technical details:
- **Subsystem**: Sequencer (`sequencer.c`).
- **Files touched**: `sequencer.c` (single-line change to set `cmd.odb_to_close` before spawning `git commit`).
- **Test**: New regression test in `t/t3404-rebase-interactive.sh`, guarded by `MINGW`, using a post-commit hook to trigger repacking and `GIT_TEST_LEGACY_DELETE=1` to expose the issue.
- **Behavior change**: ODB is released before spawning `git commit` during interactive rebase, preventing deadlocks on Windows. The commit message must clarify that the ODB is reacquired post-maintenance.
- **Related symbols**: `cmd.odb_to_close`, `GIT_TEST_LEGACY_DELETE`.
- **On-disk format**: No changes.
