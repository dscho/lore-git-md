Thread identity: Bugfix for Windows-specific resource contention in the sequencer during interactive rebase (single patch, v2). Author: Johannes Schindelin (Dscho).

Core problem or goal: Fix a deadlock on Windows where the sequencer holds the ODB lock while spawning `git commit`, causing child processes that trigger auto-maintenance (e.g., repacking) to fail when attempting to replace files still locked by the parent. The fix releases the ODB before spawning commands that might run maintenance, following an established pattern, and explicitly clarifies in the commit message that the ODB will be reacquired in a "refreshed state" after auto-maintenance completes.

Current status: Marked for inclusion in `next`. Junio C Hamano has accepted the updated commit message and signaled intent to queue the patch for integration testing. No further concerns are outstanding regarding the immediate fix, but Phillip Wood has raised forward-looking questions about broader implications.

Key technical details:
- **Subsystem**: Sequencer (`sequencer.c`).
- **Files touched**: `sequencer.c` (single-line change to set `cmd.odb_to_close` before spawning `git commit`).
- **Test**: Windows-specific regression test in `t/t3404-rebase-interactive.sh`, guarded by `MINGW`, using a post-commit hook to trigger repacking and `GIT_TEST_LEGACY_DELETE=1` to expose the issue. The test verifies repacking completes successfully and only one packfile remains.
- **Behavior change**: ODB is released before spawning `git commit` during interactive rebase, preventing deadlocks on Windows. The commit message now explicitly states the ODB is reacquired post-maintenance.
- **Related symbols**: `cmd.odb_to_close`, `GIT_TEST_LEGACY_DELETE`, `gc.auto`, `run_auto_maintenance()`.
- **On-disk format**: No changes.
- **Test coverage**: Unchanged from v1; covers the regression scenario. No new test scenarios introduced for the broader questions raised.

Open questions and loose ends:
- **Forward-looking questions**: Phillip Wood raised two alternative approaches for preventing similar issues in the future:
  1. Passing `-c gc.auto=false` to `git commit` when spawned from the sequencer, since `run_auto_maintenance()` is called at the end of the rebase anyway.
  2. Automatically closing the ODB whenever any Git command is spawned, noting that reopening the ODB is presumably cheap compared to the cost of forking.
  Neither suggestion is presented as a blocker, and no action is required for the current patch, but these ideas may inform future work.
