This is the first patch in Patrick Steinhardt’s four-part refactoring series to remove lazy-loading of alternate object databases in Git’s ODB subsystem. The patch decouples path comparisons for alternate ODB sources from `the_repository`, addressing two long-standing issues in the current implementation.

The current code uses `fspathhash()` and `fspatheq()` to deduplicate alternate ODB sources by their paths, but these functions implicitly depend on `the_repository` and derive case-sensitivity from `repo_ignore_case()`. This creates problems when alternates are registered before the repository’s configuration is parsed, leading to inconsistent behavior. The patch replaces these functions with a self-contained comparison mechanism tied to the specific ODB instance, using a `struct hashmap` instead of khash to allow custom hash and equality functions.

Key changes include:
- Adding a `source_paths_icase` field to `struct object_database` to track case-sensitivity for path comparisons.
- Introducing `odb_source_paths_cmp()` and `odb_source_by_path_cmp()` to handle path comparisons based on the ODB’s `core.ignoreCase` setting.
- Migrating the `source_by_path` map from khash to `struct hashmap`, which allows dynamic comparison functions.
- Resolving `core.ignoreCase` manually during path comparisons rather than relying on `repo_ignore_case()`.

The patch touches `odb.c`, `odb.h`, and `odb/source.h`, adding 63 lines and removing 22 for a net increase of 41 lines. While the change is technically a refactoring, it introduces new complexity to handle case-sensitivity correctly, which the author acknowledges is debatable given the rarity of repositories with thousands of alternates. The patch is well-motivated and lays the groundwork for the series’ later changes, but the added complexity may warrant scrutiny during review, particularly around edge cases like repositories where `core.ignoreCase` is not yet parsed.
