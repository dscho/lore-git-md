This is the first patch in a seven-part series introducing `git repack --drop-filtered` for partial clones. It adds the `--drop-filtered` and `--dry-run` command-line options to `git repack`, along with all the necessary validation logic, but does not yet implement the actual object enumeration or deletion. The patch is well-structured and thoroughly tested, covering all the preconditions and incompatibilities documented in the man page (e.g., `--filter` and `-a` are required, `--filter-to` and bitmaps are incompatible, a promisor remote must be configured).

The implementation distinguishes between an explicit `-b` (which is rejected as a conflict) and a config-driven `repack.writeBitmaps` setting (which is silently disabled for the duration of the command), a subtle but important correctness fix. The `--dry-run` option is kept separate from `--drop-filtered` to maintain consistency with other Git commands and to allow future expansion. The test script (`t/t7706-repack-drop-filtered.sh`) is comprehensive, covering all validation scenarios, including the bitmap-handling fix.

This patch is part of a larger effort to extend `git repack` for partial clones, enabling users to reclaim disk space by safely removing locally cached promisor blobs exceeding a specified size threshold.
