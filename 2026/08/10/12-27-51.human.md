This is the core patch in D. Ben Knoble’s three-part series converting the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The author responds to Junio C Hamano’s performance critique by benchmarking both the original implementation (which parses the config key on every `is_racy_stat()` call) and a proposed fix that caches the value in the repository’s config struct.

The benchmarks confirm Junio’s concern: in a new worktree, `git diff` is ~41× slower with the original implementation when `core.useNanosec` is enabled, but only ~7× slower with the cached version. After an index refresh, both versions perform equally, showing the regression is confined to the racy-Git case. The author plans to include the caching fix in v2 and is seeking input on whether to place the cached value in `repo_settings` or `repo_config_values`. The rest of the series (build-system cleanup, documentation updates, and a no-op refactor) remains uncontested.
