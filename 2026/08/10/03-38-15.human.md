This is a review comment on the first patch of Justin Tobler’s v2 series, which introduces `odb_transaction_finalize()` to decouple transaction cleanup from commit. Junio Hamano raises two small but pointed concerns about the patch’s implementation.

First, he notes that in `builtin/add.c` (and other call sites), the only non-local exit between transaction begin and finalize is an `exit(128)` after `report_path_error()`. He suggests it might be conceptually cleaner to restructure the code so the cleanup sequence always runs, rather than relying on `odb_transaction_finalize()` being called only on the happy path. This is a surface-level observation about control flow hygiene, not a functional critique.

Second, he points out that none of the callers added in this patch check the return value of `odb_transaction_finalize()`, and asks whether the function should return `void` instead of `int`. The same question applies to `odb_transaction_commit()`. This is a minor interface design question, not a blocker, but it touches on the ergonomics of the new API.

The review is surface-level: it focuses on control flow and return-value semantics without engaging with the patch’s core purpose (enabling backend-specific deferred cleanup). The feedback is constructive and invites clarification rather than a rewrite. Justin’s response (not shown here) would likely address whether the return value is intended to be used in future patches or whether it should be dropped.
