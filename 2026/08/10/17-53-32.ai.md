This is a bugfix patch for `git send-email`, the second iteration of a small but clear usability improvement.

Harald Nordgren addresses feedback from Junio C Hamano on the first version: the error message now simply states "No 'Subject:' line in '<file>'" (with proper quoting) and omits the earlier incorrect claim that the "Subject:" header must be on the first line. The message is still terminated with a newline to suppress Perl's internal source location, which was universally agreed as a nice touch.

The patch remains minimal: one line changed in `git-send-email.perl` and a new test in `t/t9001-send-email.sh` that verifies the error output is clean and matches the expected wording. The test creates a patch file with no "Subject:" header, runs `git send-email --dry-run`, and checks the error message against a golden string.

The motivation is unchanged: the old error was cryptic to users unfamiliar with Git's patch format conventions. The new wording is accurate, actionable, and free of implementation noise. The patch is self-contained, includes a test, and touches only the send-email subsystem. It looks ready to merge.
