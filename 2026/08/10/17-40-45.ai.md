This is patch 5/7 of the v4 series introducing `git repack --drop-filtered` for partial clones. It implements the actual removal of filtered promisor blobs by wiring the `to_drop` oidset—computed in patch 4/7—to `repack_promisor_objects()`. On a real run (`--drop-filtered` without `--dry-run`), the rebuilt promisor pack excludes the dropped blobs, and the old packs containing them are removed via the implied `-d` flag. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. The test script is extended with a new case verifying that a large promisor blob is absent after `--drop-filtered` runs, while a smaller one remains.

The patch is minimal and backward-compatible: all existing callers of `repack_promisor_objects()` pass `NULL` for the new `to_drop` parameter, so their behavior is unchanged. The change to `builtin/repack.c` is straightforward—it passes the `drop_oids` set to `repack_promisor_objects()` only when `--drop-filtered` is active and `--dry-run` is not—and the implied `-d` is clearly documented in the code comment. The `repack-filtered.c` update adds a clarifying comment about the caller’s responsibility for clearing the `to_drop` set, but this is purely documentary and does not affect behavior.

This patch is production-ready and integrates smoothly with the rest of the series. The test coverage is thorough, verifying both the removal of the targeted blob and the preservation of smaller blobs. The only technical detail worth noting for follow-up discussion is the implied `-d`, which ensures redundant packs are deleted but could be made explicit in the documentation if reviewers prefer. The patch does not introduce new dependencies or alter the series’ core functionality.
