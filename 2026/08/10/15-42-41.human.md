This is the third patch in Justin Tobler’s seven-patch v2 series making `git receive-pack` backend-agnostic for packfile writes. The patch removes the global `unpack_limit` variable and replaces it with a lazy, per-repository lookup via a new `get_unpack_limit()` helper. The change is a small but necessary step toward lifting global state as part of the ODB abstraction effort.

The email is a reply to Patrick Steinhardt’s review, which identified two technical issues: the function’s return type should be `unsigned int` (not `int`) because the unpack limit is always non-negative, and the static variable caching the limit is unnecessary because `unpack()` is only called once per `receive-pack` invocation. Justin agrees with both points and proposes a simplified implementation that directly reads the configuration without caching, using `repo_config_get_uint()` to overwrite the default value of 100 only if the relevant config keys are set.

The discussion is purely mechanical and uncontroversial. The next iteration will adopt the simpler, non-caching version, which aligns with the series’ goal of removing global state while avoiding unnecessary complexity. This patch is unlikely to attract further debate; it is a tidy refactoring that does not alter behavior.
