This is the second patch in Patrick Steinhardt’s four-patch series refactoring the object database (ODB) subsystem to remove lazy-loading of alternate object databases. It is a refactoring patch that eagerly initializes alternates during ODB setup, eliminating scattered calls to `odb_prepare_alternates()` throughout the codebase.

The patch removes 13 calls to `odb_prepare_alternates()` across 10 files, including `builtin/fsck.c`, `builtin/pack-objects.c`, `commit-graph.c`, and `pack-bitmap.c`. These calls were previously needed to ensure alternates were loaded before iterating through ODB sources, but with this change, alternates are now initialized upfront in `odb_new()` and during cache flushing in `odb_prepare()`. The function `odb_prepare_alternates()` is also made static, as it is no longer needed outside `odb.c`.

The motivation is straightforward: lazy-loading alternates was an optimization that no longer pays off, since most Git commands access the object database and thus require alternates to be loaded anyway. The change simplifies the code by centralizing alternate initialization, reducing the risk of bugs from missing calls to `odb_prepare_alternates()`. The preceding patch (1/4) resolved the historical blocker for eager initialization—case-sensitivity handling for alternate paths—by decoupling path comparisons from `the_repository`.

This patch is mechanically clean, with a clear diff showing the removal of redundant calls. It does not introduce behavioral changes, but it may affect performance in edge cases (e.g., commands that previously avoided loading alternates entirely). The commit message explains the rationale well, and the changes align with the broader ODB abstraction effort led by Patrick. The patch looks ready for review, though reviewers may want to validate the performance implications for commands like `git fsck` that could now load alternates unnecessarily.
