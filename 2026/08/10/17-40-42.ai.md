This is the second patch in the v4 series introducing `git repack --drop-filtered` for partial clones. It adds a new helper function, `list_objects_filter__filter_oidset()`, to the list-objects-filter API. This helper allows callers to apply a filter (currently only `blob:limit`) to an existing oidset without performing an object walk, which is exactly what `--drop-filtered` needs: it collects promisor blobs into an oidset and then filters out those exceeding the size threshold.

The implementation is straightforward but notable for what it *doesn’t* do: it reimplements the `blob:limit` size check directly rather than reusing the existing filter machinery in `list_objects_filter__filter_object()`. The commit message explains that the existing machinery is tied to the object-walk path and cannot easily be driven from a plain oidset. A `NEEDSWORK` comment marks this duplication for future refactoring. The helper avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info, ensuring it only operates on locally available data.

The patch touches `list-objects-filter.c` and `list-objects-filter.h`, adding 45 and 16 lines respectively. The new function is well-documented, with clear parameter descriptions and a note about the current limitation to `blob:limit` filters. The code is clean and follows Git’s style, though the duplication of the size check logic is a wart that will likely be addressed in a follow-up.

This is a refactoring patch that enables the core functionality of the series. It’s a necessary building block for `--drop-filtered` but doesn’t change behavior on its own. The duplication of logic is a minor technical debt that doesn’t affect correctness or safety, and the `NEEDSWORK` comment ensures it won’t be forgotten. The patch is production-ready and integrates smoothly with the rest of the series.
