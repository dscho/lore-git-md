This is a **design discussion contribution** in the ongoing thread about improving Git’s interactive patch selection workflow. Patrick Steinhardt responds to Junio C Hamano’s focus on unifying triage actions (stage/discard/defer) by proposing a more ambitious UI overhaul: adopting a full **TUI (text-based user interface)** inspired by Jujutsu (JJ) and its `jj split --interactive` command.

Patrick describes JJ’s approach as superior to Git’s current linear prompt-loop model. In JJ, users interact with a hierarchical TUI that first lists all changed files (allowing bulk selection/deselection), then lets them drill down to individual hunks or even lines. This model enables non-linear navigation—users can jump between files and hunks freely, revisit earlier decisions, and see the full context at once. He suggests that Git could benefit from similar TUI-based interfaces, not just for patch selection but also for other interactive workflows like `git history` (e.g., visually rearranging commits, squashing, or dropping them).

While Patrick acknowledges Junio’s narrower goal of unifying triage actions *without* abandoning the linear prompt-loop, his proposal shifts the discussion toward a more radical redesign. He frames TUIs as a way to make Git’s interactive features more intuitive and user-friendly, arguing that visual interfaces could lower the barrier to entry for complex workflows. However, this approach would require significant implementation effort (e.g., integrating ncurses or a similar library) and could introduce platform compatibility challenges (e.g., Windows terminal support).

The email does not include patches or technical details about how such a TUI might integrate with Git’s existing machinery (e.g., `add--interactive` or `add-interactive.c`). Instead, it serves as a high-level counterpoint to Junio’s incremental proposal, suggesting that the project might consider a broader UI paradigm shift. This could spark debate about whether to prioritize immediate workflow improvements (Junio’s focus) or invest in a more modern, flexible interface (Patrick’s vision). The thread’s next steps may hinge on whether other participants see TUIs as a worthwhile direction or a distraction from the core triage problem.
