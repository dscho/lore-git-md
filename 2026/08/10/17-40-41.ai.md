This is the first patch in the v4 series introducing `git repack --drop-filtered` for partial clones. It adds the `--drop-filtered` and `--dry-run` command-line options to `git repack`, along with all validation logic, but does not yet implement object enumeration or deletion. The patch is well-scoped and production-ready, incorporating Junio’s mechanical fixes from v3 (usage string formatting and documentation SYNOPSIS cleanup).

The new options are documented in `git_repack_usage` and enforced through a series of preconditions: `--drop-filtered` requires `--filter` (currently limited to `blob:limit`), `-a`, and a promisor remote, and is incompatible with `--filter-to` and explicit `-b` (bitmap writing). The implementation distinguishes between an explicit `-b` (reported as a conflict) and a config-driven `repack.writeBitmaps` setting (silently disabled for the duration of the command), fixing a subtle validation bug in the process. The `--dry-run` option is kept separate from `--drop-filtered` to maintain consistency with other Git commands and allow future expansion.

The patch introduces a new test script (`t/t7706-repack-drop-filtered.sh`) covering all validation scenarios, including the bitmap-handling fix. The test suite is comprehensive and follows Git’s testing conventions. The core logic is isolated in `builtin/repack.c`, with no functional changes to other files in this patch. The actual object enumeration and deletion will be added in follow-up patches, but the validation logic is complete and correct.
