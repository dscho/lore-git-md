Thread identity: Patch series improving `git push` performance from shallow clones by avoiding redundant tree transfers. Originating author: Elijah Newren. Thread type: patch series (now six patches at v3).

Core problem or goal: Eliminate the inefficiency where `git push` from shallow clones resends the entire toplevel tree (gigabytes in large repos) even for tiny changes, due to walking back to shallow grafts and assuming the server lacks them. The goal is to reduce unnecessary data transfer while maintaining backward compatibility and addressing usability concerns raised in review. The series introduces a tri-state config option (`push.shallowExcludeBoundary`) to balance performance, correctness, and user control, with improved error messages and recovery advice. **The fifth patch (new in v3) changes the default value of `push.shallowExcludeBoundary` from `false` to `true`, enabling the optimization by default.** The sixth patch adds user-facing advice to split multi-ref pushes when a shallow boundary exclusion causes the push to fail, addressing the false-positive failure mode identified by Derrick Stolee.
