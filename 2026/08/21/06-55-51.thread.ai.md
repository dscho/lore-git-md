Thread identity: Patch series improving `git push` performance from shallow clones by avoiding redundant tree transfers. Originating author: Elijah Newren. Thread type: patch series (single patch).

Core problem or goal: Eliminate the inefficiency where `git push` from shallow clones resends the entire toplevel tree (gigabytes in large repos) even for tiny changes, due to walking back to shallow grafts and assuming the server lacks them. The goal is to reduce unnecessary data transfer while maintaining backward compatibility. A key clarification emerged: `--depth=2` clones do not reliably solve this problem unless combined with `push.negotiate=true`, as they still resend the toplevel tree when the server has advanced, and workflow-specific quirks (e.g., forge configurations, branch deletion, or squash merges) can break even the accidental workaround they provide.

1. **Elijah’s original patch**: Introduces a new config option, `push.shallowExcludeBoundary` (default: `true`), which instructs `send-pack` to treat shallow grafts as uninteresting tips during pack generation, avoiding redundant transfers. The rare case where a server is being seeded with new shallow roots (requiring the full tree) can opt out by setting the config to `false`.

Elijah suggests `push.negotiate` could default to `true` for large repositories but insists his patch is still necessary for edge cases.
