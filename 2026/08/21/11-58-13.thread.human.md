This thread is a bug report from Victor about a potential interaction issue between sparse checkout and submodules. When `fetch.recurseSubmodules=on-demand` is set and an updated submodule is excluded by the sparse checkout configuration, `git fetch` fails. Victor provides a self-contained reproduction case in a GitHub Gist, noting that they couldn’t find prior reports of this issue in the mailing list archives.

The problem affects users with sparse checkouts who rely on recursive submodule fetching. The report is concise but clearly identifies the affected subsystems (sparse-checkout, submodules, and fetch configuration) and the triggering condition (submodule updates excluded by sparse patterns).
