This is a substantive review of Elijah Newren's patch to optimize `git push` performance from shallow clones. Patrick Steinhardt engages deeply with the technical details, raising several questions and suggestions about the implementation and edge cases.

Patrick begins by acknowledging the real-world pain point the patch addresses — the common advice to use `--depth=2` instead of `--depth=1` to avoid redundant tree transfers — and notes that the current behavior is unintuitive for most users. He then probes the core assumption of the patch: that the server already has the shallow graft commits. While he accepts the server-side connectivity check as a safety net, he wonders about scenarios where a user locally amends a shallow graft commit and then pushes, which could lead to insufficient information being sent to the server. This is a valid edge case that the patch does not explicitly address in its current form.

He also suggests a more aggressive optimization: negotiating down to the tree level during reference negotiation to verify whether the server already has the tree of the grafted commit. This would be a deeper change to Git's negotiation protocol and could break compatibility with older clients, so it’s a forward-looking idea rather than an immediate request.

On the implementation side, Patrick asks why the code loops through the refs twice (once to build the set of known objects, and again to start the walk), suggesting it could be combined for efficiency. He also notes that the manual commit walk could potentially use higher-level interfaces like `repo_is_descendant_of()`, though he acknowledges the trade-off between simplicity and leveraging commit-graph optimizations.

The review is thorough and constructive, focusing on correctness, edge cases, and potential future improvements. While Patrick does not outright object to the patch, his questions suggest that further discussion — or at least clarification — is needed before this can be considered ready for merging. The patch itself remains well-motivated and addresses a clear performance issue, but the review highlights areas where the design could be refined or better documented.
