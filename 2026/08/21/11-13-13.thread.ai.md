Core problem or goal
Anselm Schüler asks why Git provides the `--ext-diff` option and why custom diff filters are not executed by default in all commands that show diffs (e.g., `git diff` vs. `git show`). The inquiry seeks the design intent behind this behavior, speculating briefly about security but rejecting that explanation because Git already executes configured diff filters in some contexts.

Current status
No decisions or agreements; the thread is at the inquiry stage. No patch versions or technical changes are involved.

Key technical details
- `--ext-diff`: a command-line flag that forces Git to use external diff drivers (configured via `diff.<driver>.command` or `diff.external`) even when they would not normally be invoked.
- Commands that *do* invoke external diffs by default when configured: `git diff`, `git log -p`, `git format-patch`.
- Commands that *do not* invoke external diffs by default: `git show`, `git stash show -p`, `git cherry-pick -n` (when showing the diff).
- External diff drivers are arbitrary executables; Git passes filenames and labels to them, so they can read and write the working tree.

Open questions and loose ends
- Why does Git suppress external diffs in some commands (`git show`) but not others (`git diff`)?
- Is `--ext-diff` a legacy quirk, a deliberate safety valve, or a mechanism for performance/usability?
- Are there concrete scenarios where a user would want a diff filter to run in `git diff` but not in `git show`?
