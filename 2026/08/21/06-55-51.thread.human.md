This thread is about a performance optimization for `git push` from shallow clones, authored by Elijah Newren. The issue is that shallow clones often resend entire top-level trees (potentially gigabytes of data) even for minor changes, due to Git walking back to shallow grafts and assuming the server lacks them. Elijah's patch introduces a new config option, `push.shallowExcludeBoundary`, which defaults to `true` and instructs `send-pack` to treat shallow grafts as uninteresting tips during pack generation, avoiding redundant transfers. The rare case where a server needs the full tree (e.g., seeding new shallow roots) can opt out by setting the config to `false`.

The implementation is clean and focused, adding a helper function (`append_reachable_shallow_grafts()`) to walk from pushed tips to their shallow grafts and mark them as negative tips in the pack boundary. The patch stops early at commits the server already has, ensuring efficiency for deeper clones. Tests in `t5538-push-shallow.sh` cover the new behavior, including edge cases like rejected refs not over-excluding objects needed by accepted refs, and interactions with `receive.shallowUpdate`. The commit message is thorough, explaining the motivation, tradeoffs, and backward compatibility.

So far, this appears to be a well-scoped fix addressing a real-world performance issue in large repositories. No reviews or objections have been posted yet, so the thread is still in its early stages. If the patch holds up under review, it could significantly improve push performance for shallow clones.
