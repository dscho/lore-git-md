This thread is about a patch series by Elijah Newren that improves `git push` performance from shallow clones by avoiding redundant tree transfers. The series is now at version 3 with six patches, and the goal is to eliminate the inefficiency where `git push` resends entire toplevel trees (even for tiny changes) due to shallow grafts.

Key developments in this version include preparatory patches that improve error reporting and robustness, the core optimization introducing a tri-state config option (`push.shallowExcludeBoundary`), and a change in the default value of this option from `false` to `true` in the fifth patch. The sixth and latest patch adds user-facing advice to split multi-ref pushes when a shallow boundary exclusion causes the push to fail, addressing usability concerns raised by Derrick Stolee. This advice provides a clear recovery path for the rare false-positive failure mode, making the trade-off between performance and correctness more acceptable.

The discussion has focused on balancing performance, correctness, and usability. Elijah argues that the new default (`push.shallowExcludeBoundary=true`) is justified because sending shallow boundaries is almost always wasted work, and users can opt out if needed. Patrick Steinhardt and Derrick Stolee have raised concerns about the false-positive failure mode and usability, with Stolee proposing alternative approaches. While Patrick has not yet responded to the latest version, the sixth patch directly addresses Stolee’s usability concerns by offering actionable advice for recovery. The series remains under review, with open questions about the acceptability of the new default and the long-term approach to shallow push optimizations.
