This thread is about a patch series from Elijah Newren aimed at improving `git push` performance from shallow clones by avoiding redundant tree transfers. The series is now at version 3 with six patches, addressing feedback from earlier iterations while maintaining backward compatibility.

The core issue is that `git push` from shallow clones resends entire toplevel trees—sometimes gigabytes of data—even for tiny changes, due to how shallow grafts are handled. The series introduces a tri-state config option, `push.shallowExcludeBoundary`, to let users balance performance and correctness. The default remains conservative (`false`) for now, but the fifth patch argues for switching it to `true` in the future. The sixth patch adds advice for users to retry problematic multi-ref pushes separately, improving usability.

The latest email covers the second patch in the series, a small but useful improvement to `receive-pack`. It silences redundant error messages during per-ref connectivity checks, reducing noise while preserving the rejection logic. This change is uncontroversial and supports the series' broader goal of clearer error handling. Earlier feedback from Patrick Steinhardt and Derrick Stolee focused on safety and usability concerns, particularly around false-positive failures where valid refs might be rejected. While Stolee hasn’t yet responded to the latest version, the series now includes better error messages and recovery advice to address these issues. The discussion remains open on whether the default behavior should change and if the config-based approach is the right long-term solution.
