This thread is about a patch from Elijah Newren that improves `git push` performance from shallow clones by avoiding redundant transfers of the entire toplevel tree. The patch introduces a new config option, `push.shallowExcludeBoundary` (defaulting to `true`), which tells `send-pack` to treat shallow grafts as uninteresting tips during pack generation, reducing unnecessary data transfer.

Elijah has responded to Patrick Steinhardt’s detailed review, addressing concerns about locally modified shallow grafts (e.g., via `git commit --amend`). He discovered that Git currently treats amended grafts as new root commits—a behavior he considers a separate issue and plans to fix later. On Patrick’s suggestion to negotiate tree objects for graft verification, Elijah argued that protocol changes would be required and the benefit is limited. He accepted Patrick’s minor implementation suggestions (e.g., marking parameters as `const` and combining loops) but declined to use higher-level commit-graph interfaces, explaining that an explicit walk is needed to stop at commits the peer already has.

The discussion remains constructive, with no blocking objections, but the graft modification edge case and negotiation scope could lead to refinements in future versions. The patch is still under review, and Elijah plans to add test coverage for graft modification scenarios. Key files (`send-pack.c`, `t5538-push-shallow.sh`) and the new config option remain central to the effort.
