This is a performance optimization for `git push` from shallow clones. Elijah Newren identifies a long-standing inefficiency: when pushing from a shallow repository, Git often resends the entire toplevel tree of files (gigabytes in large repos) even for tiny changes, because it walks back to shallow grafts and assumes the server lacks them. The patch introduces a new config option, `push.shallowExcludeBoundary`, defaulting to `true`, which tells `send-pack` to treat shallow grafts as uninteresting tips during pack generation, avoiding the redundant transfer. The rare case where a server is being seeded with new shallow roots (requiring the full tree) can opt out by setting the config to `false`.

The implementation adds a helper function, `append_reachable_shallow_grafts()`, that walks from pushed tips to their shallow grafts, adding those grafts to the pack boundary as negative tips. It stops early at any commit the server already has, keeping the walk short for deeper clones. The patch updates `t5538-push-shallow.sh` with tests for the new behavior, including edge cases like a rejected ref not over-excluding objects needed by an accepted ref, and the interaction with `receive.shallowUpdate`.

The commit message is thorough, explaining the motivation, the tradeoffs, and the backward-compatibility story. The code is clean and well-scoped, touching only `send-pack.c` and the relevant documentation. The tests cover both the happy path and the rare opt-out case. This looks like a well-crafted fix for a real-world performance pain point in large repositories.
