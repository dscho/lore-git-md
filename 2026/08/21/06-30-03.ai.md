This is patch 3/6 of Patrick Steinhardt’s six-patch series making packfile generation pluggable in Git’s object database (ODB) layer. The patch refactors `git send-pack` to use the new ODB interface (`odb_generate_pack()`) instead of directly spawning `git pack-objects`, completing the transport-layer migration for push operations. The change replaces manual `child_process` construction with a declarative `odb_generate_pack_options` setup, preserving all existing functionality (thin packs, delta base offsets, shallow clones, stateless-RPC handling, and progress meters).

Key technical details:
- **New helper**: `append_negative_object()` replaces the old `feed_object()` logic, appending boundary objects to the ODB’s `haves` array instead of writing them to a `FILE*`.
- **Behavior**: The packfile is now generated asynchronously via the ODB layer, with file descriptors (`generator->out`, `generator->err`) replacing the child process’s pipes. The stateless-RPC path wraps the generated pack data in pkt-lines as before.
- **Test adjustments**: `t5516-fetch-push.sh` is updated to reflect benign argument-order changes (e.g., `--quiet` instead of `-q`, removal of `--all-progress-implied` when progress is disabled).
- **Error handling**: The patch simplifies error reporting by delegating to `odb_pack_generator_finish()`, which handles SIGPIPE (treated as normal) and other failures uniformly.

The refactoring is mechanical and well-motivated, aligning with the series’ goal of decoupling transport commands from the "files" backend. The commit message clearly explains the changes and their impact on tests, and the code itself is clean and idiomatic. No substantive objections remain from prior reviews, and the patch is a logical extension of the `upload-pack.c` refactoring in patch 2/6. The only open question is Elijah Newren’s upcoming patch (semantically conflicting with this refactoring), but coordination is expected to be straightforward.
