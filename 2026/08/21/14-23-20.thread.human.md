This thread is about a patch series from Alexey Samsonov that replaces the deprecated `utime()` function with `utimensat()` for POSIX.1-2024 compatibility. The goal is to future-proof Git by removing reliance on a function that may disappear from libc implementations like LLVM-libc, while also enabling nanosecond-precision timestamps. The series introduces a `git_utimensat()` wrapper, updates 23 files across the codebase (including core components, build systems, and MinGW compatibility layers), and removes legacy headers and shims. There’s no intended functional change beyond preserving sub-second timestamps that were previously truncated.

Junio Hamano acknowledged the series, noting that macOS has supported `utimensat()` since 2017 (High Sierra), which is now end-of-life. This adds confidence to the cross-platform viability of the migration, though no explicit approval or merge intent has been stated yet. The series is still under review, and while Junio’s comment suggests it’s uncontroversial, reviewers may still scrutinize edge cases like timestamp conversion logic or fallback behavior on older systems. No objections or conditional approvals have been raised so far, and the patches appear to be a straightforward, well-motivated refactoring.
