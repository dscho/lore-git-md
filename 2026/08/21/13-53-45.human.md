This is the second patch in a two-part feature series adding Unicode box-drawing characters to the output of `git repo structure` when a UTF-8 locale is detected. The patch implements the actual rendering logic in `builtin/repo.c`, replacing ASCII bullets (`*`) and table borders (`|`, `-`) with Unicode equivalents (`•`, `│`, `├`, `─`, `┼`, `┤`) when `is_utf8_locale()` returns true. The changes are internal to `stats_table_setup_structure()` and `stats_table_print_structure()`, with no new symbols introduced.

The patch also updates the test suite in `t/t1901-repo-structure.sh` to detect an available UTF-8 locale and define a `UTF8_LOCALE` prerequisite, while explicitly pinning existing ASCII tests to `LC_ALL=C` to ensure deterministic behavior. Two new tests verify Unicode output under UTF-8 locales, including an edge case where the locale directory is missing (exercising the fallback logic fixed in patch 1). The test coverage is thorough, covering both the happy path and the edge case, and the commit message clearly explains the motivation and implementation.

This is a well-scoped, opt-in feature that maintains backward compatibility and avoids broader Unicode changes elsewhere in Git. The patch is part of a GSoC effort mentored by Justin Tobler and Lucas Seiki Oshiro, and the implementation looks clean and self-contained. If the first patch (which fixes a latent bug in `is_utf8_locale()`) is accepted, this one is likely to follow without controversy.
