This is a platform-compatibility cleanup series that replaces the deprecated `utime()` function with `utimensat()` for POSIX.1-2024 compliance. Junio C Hamano’s reply to the cover letter adds a data point: macOS has supported `utimensat()` since 10.13 High Sierra (2017), which reached end-of-life in 2020, so the new API is safe to use across all major platforms.

The series is now complete with all three patches posted and under review. It introduces a `git_utimensat()` wrapper in `compat/posix.h`, replaces all `utime()` calls across the codebase (23 files touched), removes legacy headers and shims, and includes MinGW-specific support. The goal is future-proofing—`utime()` may disappear from future libc implementations like LLVM-libc—while enabling nanosecond-precision timestamps, which were previously truncated to second-level precision. The fallback to `utimes()` on older systems ensures backward compatibility.

Junio’s comment suggests the series is uncontroversial and likely to be accepted once review is complete. The only remaining open question is whether the patches have been tested on older systems where `utimensat()` might not be available, but the fallback mechanism should handle this gracefully. No objections or conditional approvals have been raised yet. This is a well-motivated, mechanical refactoring with clear benefits for long-term maintainability.
