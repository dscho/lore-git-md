This is a follow-up in the ongoing discussion about Elijah Newren’s patch to improve `git push` performance from shallow clones by avoiding redundant tree transfers. The email is a detailed reply to Patrick Steinhardt’s substantive review, addressing each of his technical questions and suggestions.

Elijah clarifies that `--depth=2` does not meaningfully improve negotiation over `--depth=1` unless `push.negotiate=true` is also set; without negotiation, both depths resend the entire toplevel tree. He then explores Patrick’s concern about locally modified shallow grafts (e.g., via `git commit --amend`), discovering that Git currently treats amended shallow grafts as new root commits—a behavior he considers a separate foot-gun and plans to fix in a future series. On Patrick’s suggestion to negotiate tree objects for graft verification, Elijah argues it would require protocol changes and offers limited benefit over existing commit-based negotiation, especially since the server learns about shallow grafts too late in the current protocol flow.

The reply also accepts Patrick’s minor implementation suggestions: marking input-only parameters as `const` and combining two loops over `refs` for efficiency. Elijah declines to use higher-level commit-graph interfaces like `repo_is_descendant_of()`, explaining that the explicit walk is necessary to stop at commits the peer already has and identify graft boundaries. He agrees to add test coverage for graft modification scenarios but notes that the current behavior (amended grafts becoming root commits) is tangential to this patch.

Finally, Elijah addresses Patrick’s question about defaulting `push.shallowExcludeBoundary` to `true`, acknowledging the trade-off between reduced bandwidth/CPU and increased latency due to an extra round-trip. The discussion remains constructive, with no blocking objections, but the graft modification edge case and negotiation scope could lead to design refinements in future iterations. Key files touched (`send-pack.c`, `t5538-push-shallow.sh`) and the new config key (`push.shallowExcludeBoundary`) remain central to the patch.
