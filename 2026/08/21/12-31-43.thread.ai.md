Subject: [PATCH 0/2] fetch-pack: parallelize packfile URI downloads
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (performance feature)

Core problem or goal
Enable parallel fetching of multiple packfile URIs during `git fetch` and `git clone` when the server advertises them, aiming to reduce transfer time. The change is opt-in via a new `fetch.parallelPackfileURIs` configuration key (renamed in this patch to `fetch.packfileURIThreads`).

Current status
Under review; no prior versions. Two patches:
1. Refactor packfile URI handling in `fetch-pack.c` into preparation, fetching, and aggregation phases to prepare for threading (228 lines changed, no behavior change). Introduces `fetch_packfile_uri_result` struct and splits logic into `fetch_packfile_uri` (single URI) and `fetch_packfile_uris` (orchestrator).
2. Implement parallel downloads using POSIX threads, add `fetch.packfileURIThreads` config (default: 1, preserving sequential behavior; 0 auto-detects CPU cores), document it in `fetch.adoc`, and add tests in `t/t5702-protocol-v2.sh`. The implementation includes thread-safe state management via `fetch_packfile_uris_state`, worker threads, mutex synchronization, and graceful fallback on platforms without `HAVE_THREADS`.

Key technical details
- Files touched: `fetch-pack.c`, `Documentation/config/fetch.adoc`, `t/t5702-protocol-v2.sh`.
- New symbols: `fetch_packfile_uri_result` struct, `fetch_parallel_config` struct, `fetch_pack_args.parallel_packfile_uris` field, `fetch.packfileURIThreads` config key, `fetch_packfile_uris_state` struct, `fetch_packfile_uris_thread` worker function.
- Behavior: parallel downloads are opt-in; default remains sequential. No on-disk format changes or protocol behavior changes. Threads are used only for downloading; `git-index-pack` execution remains sequential per packfile.
- Test coverage: new tests in `t/t5702-protocol-v2.sh` verify parallel fetch functionality, thread spawning (when pthreads are available), and configuration handling.
- Benchmarks: commit message includes detailed measurements showing 5.35x–7.58x speedups in both bandwidth-limited and CPU-bound scenarios (e.g., 8x1MB packfiles with 8 threads).
