This is a performance-focused bugfix for `git push` from shallow clones. Elijah Newren identifies a long-standing inefficiency: when pushing from a shallow repository, Git often resends the entire toplevel tree of files—gigabytes in large repos—even for tiny changes. The root cause is that `send-pack` walks back to shallow grafts and, lacking evidence the server already has those commits, includes their full trees in the pack.

The fix adds a new config option, `push.shallowExcludeBoundary` (default `true`), that treats shallow grafts as negative tips during pack generation. This skips objects beneath the graft, assuming the server already has them (a safe assumption because `receive-pack` rejects pushes referencing missing objects). The patch includes thorough tests covering the default optimization, the opt-out path, edge cases where a rejected ref must not over-exclude objects needed by an accepted ref, and the rare `receive.shallowUpdate` workflow that genuinely needs the full tree.

The commit message is exemplary: it explains the problem, the fix, the trade-offs, and the backward-compatibility story. The code is clean and well-scoped, touching only `send-pack.c` and adding a new config knob. This looks like a clear win for users of shallow clones, especially in large repositories.
