This is a bugfix patch (v3) targeting the worktree repair functionality. It addresses a long-standing asymmetry in how Git handles relative versus absolute paths in `.git` files when the `worktree.useRelativePaths` configuration is toggled. The core issue is that `read_gitfile_gently()` always returns an absolute path, obscuring the original path style and preventing the repair logic from detecting mismatches when switching from relative to absolute paths.

The patch introduces a new function, `read_gitfile_raw()`, which returns the path verbatim (absolute or relative) without normalization, enabling the worktree repair logic to detect and correct mismatches between the configured path style and the `.git` file contents. This version (v3) incorporates Junio C Hamano’s feedback by replacing the static `strbuf` in `read_gitfile_raw()` with a caller-provided buffer, aligning with Git’s modern API conventions for reentrancy. The existing `read_gitfile_gently()` now delegates to `read_gitfile_raw()` to obtain the verbatim path before normalizing it to an absolute path.

Files touched include `setup.c`, `setup.h`, `worktree.c`, and the test script `t/t2406-worktree-repair.sh`. The test suite is expanded with four new test cases that verify the repair logic correctly handles transitions between absolute and relative paths in both main and side worktrees, including error message correctness for mismatches. The patch is well-motivated, addressing a real-world issue that has existed since the feature’s introduction in 2024, and the design direction is now settled after Junio’s feedback. The author (Yoichi NAKAYAMA) has incorporated the API tweak, and the patch appears ready for integration.

Key technical details include the new `read_gitfile_raw()` function, which returns an integer error code and populates a caller-provided `strbuf` with the verbatim path, and the removal of dead code branches in the worktree repair logic that could never execute due to the prior behavior of `read_gitfile_gently()`. The patch also fixes a subtle bug in `repair_gitfile()` where the repository existence check was skipped when using the raw path, ensuring the repair logic remains robust.
