This thread introduces a performance optimization for `git fetch` and `git clone` that allows parallel downloading of packfile URIs when advertised by the server. The feature is opt-in via a new configuration key, `fetch.packfileURIThreads` (defaulting to 1 to preserve sequential behavior), and is implemented in two patches by Patrick Steinhardt.

The first patch refactors the existing packfile URI handling in `fetch-pack.c` to prepare for threading, while the second patch implements the parallelization using POSIX threads. The implementation includes thread-safe state management, graceful fallback on platforms without thread support, and comprehensive test coverage. Benchmarks in the commit message show significant speedups—up to 7.58x in bandwidth-limited scenarios and 5.3x in CPU-bound cases—without altering on-disk formats or protocol behavior.

The series is under review and appears self-contained, with no open questions or objections raised so far. The changes are confined to `fetch-pack.c`, documentation, and tests, making the scope narrow and the risk minimal. If merged, this would be a welcome performance boost for users fetching repositories with multiple packfile URIs.
