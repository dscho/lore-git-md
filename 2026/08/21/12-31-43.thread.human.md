This thread introduces a performance feature to parallelize packfile URI downloads during `git fetch` and `git clone`, authored by Patrick Steinhardt. The series is currently under review and consists of two patches: the first refactors packfile URI handling in `fetch-pack.c` to prepare for threading, while the second implements parallel downloads using POSIX threads, controlled by a new `fetch.packfileURIThreads` configuration key (defaulting to sequential behavior).

The implementation is opt-in, preserves existing behavior by default, and includes benchmarks showing significant speedups (5.3x–7.5x) in both bandwidth-limited and CPU-bound scenarios. The code touches `fetch-pack.c`, adds documentation, and includes test coverage in `t/t5702-protocol-v2.sh`. No major objections or open questions have been raised yet, but Justin Tobler has flagged a potential coordination issue: his planned ODB transaction work could conflict with this series, suggesting that landing his changes first might simplify the parallelization effort. The discussion is now considering the best order for these two in-flight features.
