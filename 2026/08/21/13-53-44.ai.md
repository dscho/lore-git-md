This is the first patch in a two-part feature series that enables Unicode box-drawing characters in `git repo structure` output for UTF-8 locales. The patch fixes a latent bug in `is_utf8_locale()` where the function incorrectly reported a UTF-8 locale when the `charset` variable was unset—typically in uninstalled builds where `git_setup_gettext()` returns early. The fix ensures the function falls back to environment-derived charset values (`LC_ALL`, `LC_CTYPE`, `LANG`) whenever `charset` is unset, regardless of whether gettext support is enabled. This change is internal to `gettext.c` and does not introduce new symbols or user-visible behavior on its own, but it is a prerequisite for the second patch, which implements the Unicode rendering logic.

The patch is narrowly scoped and technically sound, addressing a clear edge case with a straightforward solution. The commit message is detailed and explains both the problem and the fix well. The code itself is clean, using a static buffer to cache the fallback charset and avoiding unnecessary allocations. The change maintains backward compatibility and does not affect existing behavior when `charset` is properly initialized. The only file touched is `gettext.c`, and the diff is minimal, making the patch easy to review.

This patch is part of a GSoC effort mentored by Justin Tobler and Lucas Seiki Oshiro, and it adopts the same `GIT_TEST_UTF8_LOCALE` test helper convention used elsewhere in the test suite (e.g., in `t/lib-git-svn.sh`). The series as a whole is well-motivated: the Unicode rendering feature is opt-in based on locale detection, and the fix here ensures the detection logic is robust. The patch is unlikely to be controversial, as it corrects a clear bug without introducing new complexity.

Key technical details for follow-up discussion include the `is_utf8_locale()` function, the `charset` variable, and the environment-derived fallback logic. The patch also sets the stage for the second patch, which introduces the Unicode characters (`│`, `├`, `─`, `┼`, `┤`, `•`) in the `repo structure` output. The series is under review, and this patch appears ready for inclusion once the second patch is also approved.
