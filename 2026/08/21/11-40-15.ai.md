This is a **follow-up discussion** in the thread about Patrick Steinhardt’s bugfix patch adjusting the geometric repacking threshold. The patch itself remains unchanged and ready for integration, but this email explores a deeper architectural question raised by Elijah Newren: whether Git should stop pruning loose object sharding directories entirely.

Patrick engages substantively with Newren’s tangential question, weighing two trade-offs. On one hand, pruning empty shards slightly speeds up lookups for nonexistent objects and reduces filesystem clutter during object database iteration. On the other, it forces frequent directory recreation during loose object writes, exacerbating race conditions in high-concurrency repositories—the very issue the original patch aims to mitigate. Patrick leans toward the latter concern, arguing that the performance cost of pruning is negligible (since Git prioritizes packfile searches) while the write churn is both frequent and problematic. He concludes that not pruning could be worth exploring, though he acknowledges uncertainty about hidden reasons for the current behavior.

This exchange does not alter the status of the original patch, which remains a targeted, uncontroversial fix. However, it surfaces a potential future direction for addressing the root cause of the instability Patrick’s patch works around. The discussion is speculative and technical, with no immediate action items or objections to the existing patch. For a busy reader, this email signals that while the current fix is sufficient, the project may revisit loose object directory handling in a later effort.
