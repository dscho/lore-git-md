This is a follow-up in the thread improving `git push` performance from shallow clones. Elijah Newren responds to Patrick Steinhardt’s substantive review of his patch, which introduces the `push.shallowExcludeBoundary` config option to avoid redundant tree transfers.

The exchange clarifies several key points. Elijah corrects a common misconception: `--depth=2` does not inherently fix the shallow-push inefficiency—what matters is `push.negotiate`, which works equally well at `--depth=1`. He also addresses Patrick’s concern about locally modified shallow grafts: `git commit --amend` on a shallow graft creates a new root commit (a foot-gun in itself), not a corrupt repo, and this behavior is tangential to the current patch. Elijah plans a separate series to prevent amending shallow grafts.

On Patrick’s suggestion to negotiate tree objects for graft integrity, Elijah argues it’s impractical: the server learns about shallow grafts too late in the protocol, and the narrow use case (rewriting a grafted commit while preserving its tree) doesn’t justify the complexity. He also notes that the patch’s default (`push.shallowExcludeBoundary=true`) adds a round-trip to every push, trading latency for bandwidth savings—a tradeoff worth testing but not a blocker.

The discussion wraps up with Elijah agreeing to minor implementation tweaks (marking input parameters `const`, combining loops) and confirming that the explicit reachability walk is necessary, as higher-level commit-graph interfaces can’t handle the patch’s specific needs. The patch remains well-motivated and technically sound, with no unresolved objections—just refinements.
