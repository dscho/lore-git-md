This is a brief update on the ongoing effort to fix the discrepancy between `git config --global`'s documented and actual behavior. Nils Fahldieck, the original reporter, responds to Delilah Ashley Wu’s progress on a v2 patch series that would make `--global` read both `~/.gitconfig` and the XDG config file (`~/.config/git/config`), aligning the code with the documentation.

Nils expresses enthusiasm for Delilah’s work and offers to review the upcoming v2 series. The patch series has been dormant for over a year due to lack of community feedback, but Delilah’s revival of the effort—along with renewed attention to cross-command inconsistencies (e.g., `--global` vs. `--get`) and edge cases like `--global --no-includes`—has reignited momentum. The series is nearly ready, with only minor review feedback remaining, and Delilah plans to submit it soon despite limited time for side projects.

The core issue remains unresolved: the maintainer (Junio C Hamano) previously agreed the documentation is incorrect but did not endorse a fix direction. The current discussion, however, strengthens the case for updating the code rather than the docs, as the systemic nature of the problem (affecting tools and user expectations) becomes clearer. For readers tracking this thread, Delilah’s v2 series is the most concrete step toward resolution, and Nils’s offer to review signals growing community support for the change. If the goal is to eliminate user confusion and align behavior with expectations, this patch is the leading candidate.
