This is the second patch in Patrick Steinhardt’s six-patch series (v4) making packfile generation pluggable via Git’s object database (ODB) layer. It refactors `upload-pack.c` to use the new ODB interface (`odb_generate_pack()`) instead of directly spawning `git pack-objects`, eliminating backend-specific code while preserving all existing functionality: thin packs, shallow clones, progress meters, stateless-RPC handling, and URI protocol support.

The patch replaces manual `child_process` construction with a declarative `struct odb_generate_pack_options` setup, reducing the `create_pack_file()` function from 125 lines to 80. Key changes include:
- Renaming `write_one_shallow()` to `append_one_shallow()` to reflect its new role in appending shallow commit OIDs to an `oid_array` (part of the ODB options struct).
- Replacing the `FILE*` pipe with direct OID array population for wants, haves, and extra edges.
- Delegating packfile generation to `odb_generate_pack()`, which returns file descriptors for the pack and progress output.
- Updating the poll loop to read from the ODB generator’s descriptors (`generator->out` and `generator->err`) instead of a child process’s pipes.
- Rewording the error message from `"unable to fork git-pack-objects"` to `"unable to generate pack"` to avoid leaking backend-specific terminology (addressing Karthik Nayak’s feedback).

The patch is a mechanical refactoring with no behavior changes, but it demonstrates the ODB interface’s applicability to fetch operations. The test suite (`t5516-fetch-push.sh`) is adjusted for benign argument-order changes, and deeper edge-case testing (e.g., error paths, shallow clone interactions) remains pending. The series’ broader goal—decoupling the transport layer from the "files" backend—is advanced here by making `upload-pack` backend-agnostic.

This patch is well-executed and uncontroversial, with no substantive objections in prior iterations. The ODB interface’s design (asynchronous operation via file descriptors, declarative options) is preserved, and the refactoring aligns with the series’ goal of hoisting shared pack-generation logic into the ODB layer. The unresolved `get_log_output_encoding()` dependency in `bundle.c` (patches 5/6 and 6/6) does not affect this patch. Elijah Newren’s upcoming semantic conflict with `send-pack.c` (patch 3/6) may require coordination but is unlikely to impact this change. The patch is a strong candidate for `next` once the series stabilizes.
