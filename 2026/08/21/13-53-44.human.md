This is the first patch in a two-part feature series adding Unicode box-drawing characters to `git repo structure` output when a UTF-8 locale is detected. The patch fixes a latent bug in the `is_utf8_locale()` function in `gettext.c`.

The issue: when Git runs from an uninstalled source tree (or any environment where `git_setup_gettext()` fails to locate the locale directory), the `charset` variable remains unset. Since `is_encoding_utf8(NULL)` defaults to true, `is_utf8_locale()` incorrectly reports a UTF-8 locale even under `LC_ALL=C`. The existing fallback logic that inspects `LC_ALL`, `LC_CTYPE`, and `LANG` was previously compiled only under `NO_GETTEXT`, leaving gettext-enabled builds without a fallback.

The fix makes the fallback conditional on `charset` being unset rather than on `NO_GETTEXT`, ensuring accurate locale detection regardless of gettext support. The patch introduces a static `fallback_charset` buffer to cache the environment-derived value, avoiding repeated string duplication. The change is minimal and focused, touching only the `is_utf8_locale()` function.

This is a well-motivated bugfix with a clear technical rationale. The commit message explains the problem, the solution, and the edge case (uninstalled builds) that triggers it. The patch is part of a larger feature effort, but it stands on its own as a correctness improvement. No objections or review comments have appeared yet.
