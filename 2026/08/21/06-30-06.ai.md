This is the final patch in Patrick Steinhardt’s six-patch series making packfile generation pluggable via Git’s object database (ODB) layer. It migrates `git bundle` to the new ODB interface, completing the series’ goal of centralizing all pack streams leaving the repository under a single spawn point.

The patch replaces the direct `git pack-objects` invocation in `write_pack_data()` with a declarative setup using `struct odb_generate_pack_options`. The new code preserves all existing functionality: thin packs, delta base offsets, and filter specs for partial clones. The function is simplified from 45 lines to 37, eliminating manual `child_process` construction and replacing it with a single call to `odb_generate_pack()` followed by a loop to relay the generated pack data. The patch also removes the last vestige of the `pack_opts` strvec from `builtin/bundle.c`, consolidating progress-meter handling into the boolean `progress` flag introduced in patch 4/6.

The changes are mechanical and well-motivated, with no behavior changes or edge-case regressions. The patch builds on the progress-meter refactoring (patch 4/6) and the `the_repository` removal (patch 5/6), fully realizing the ODB abstraction for `git bundle`. The only remaining loose end in the series—the `get_log_output_encoding()` dependency in `bundle.c`—is unrelated to this patch and was addressed in patch 5/6.

Key technical details for follow-up discussion:
- **Files touched**: `builtin/bundle.c` (simplifies `cmd_bundle_create()` by removing `pack_opts` strvec), `bundle.c` (migrates `write_pack_data()` to the ODB interface), and `bundle.h` (updates `create_bundle()` signature to accept a `progress` boolean instead of `pack_options`).
- **New symbols used**: `odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`.
- **Behavior**: `git bundle` now delegates packfile generation to the ODB layer, reducing backend-specific code while preserving all existing functionality.
- **Test coverage**: No new tests are added, but the patch maintains compatibility with existing test cases (e.g., `t5704-bundle.sh`).

The series is now functionally complete, with no substantive objections remaining. This patch is a clean, focused migration that aligns `git bundle` with the ODB abstraction introduced in earlier patches.
