This is the first patch in Patrick Steinhardt’s six-patch series introducing a pluggable interface for packfile generation in Git’s object database (ODB) layer. It defines the core ODB interface (`odb_generate_pack()` and related structures) and implements it for the "files" backend, which delegates to the existing `git pack-objects` command. The patch adds 355 lines across four files (`odb.c`, `odb.h`, `odb/source-files.c`, `odb/source.h`), introducing new structures (`odb_generate_pack_options`, `odb_pack_generator`, `odb_pack_generator_files`) and functions (`odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`).

The interface is designed to support the transport layer’s needs (fetch, push, bundle) while remaining backend-agnostic. It exposes options for wants/haves, shallow boundaries, filter specs, URI protocols, progress settings, delta policies, and file descriptors for pack and progress output. The files-backend implementation translates these options into `git pack-objects` command-line arguments (e.g., `--thin`, `--shallow`, `--filter`), handles shallow boundaries by neutralizing the repository’s shallow state, and supports asynchronous operation by returning file descriptors when the caller requests pipes. Error handling includes proper cleanup of descriptors and reporting of `pack-objects` failures (except SIGPIPE, which is treated as normal).

This patch is a foundational step in the ODB abstraction effort, enabling future patches to refactor transport commands (`upload-pack`, `send-pack`, `bundle`) to use the new interface. The design is forward-looking: the `source` parameter in the `generate_pack` callback is unused in the files-backend implementation but included for interface consistency with future ODB backends. The patch addresses prior feedback by fixing a use-after-scope bug (moving `child_process` to the heap) and resolving descriptor lifecycle questions (the "consumed by the generator" contract applies only when the primary ODB source supports packfile generation).

It introduces no on-disk format changes and preserves all existing functionality. The unresolved `source` parameter is a minor loose end unlikely to block progress.
