This is a follow-up in the `git push` shallow-clone performance thread, where Elijah Newren clarifies a common misconception about `--depth=2` clones. The email explains why `--depth=2` does not reliably solve the redundant tree-transfer problem unless combined with `push.negotiate=true`. Without negotiation, both `--depth=1` and `--depth=2` resend the entire toplevel tree when the server has advanced, though `--depth=2` may *accidentally* help in specific workflows (e.g., forges that retain merge-request refs and advertise them, and users who never push directly to main branches or use squash merges). Elijah notes that GitHub’s configuration (hiding `refs/pull/` and users deleting branches on merge) breaks this workaround, and even if it didn’t, squash merges would still prevent it from working. The clarification reinforces the need for the proposed `push.shallowExcludeBoundary` config, which directly addresses the negotiation gap by treating shallow grafts as uninteresting tips. No code changes are proposed here—this is purely a design discussion refinement.
