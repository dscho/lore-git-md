This is the final version of a bugfix patch that stops Git from incorrectly interpreting URLs in commit messages as trailers. The patch is part of a previously discussed and now resolved thread where the root cause—a loose trailer matching heuristic—was identified and agreed upon.

The implementation modifies `find_separator()` in `trailer.c` to reject lines containing `://` immediately after a colon separator, unless whitespace has already been encountered. This prevents URLs (e.g., `https://example.com`) from being misparsed as trailers while preserving legitimate trailers that might coincidentally contain `://`. The patch includes comprehensive test coverage: three new unit tests in `t/unit-tests/u-trailer.c` and an integration test in `t/t7513-interpret-trailers.sh`, all verifying the fix for the three real-world scenarios documented in the commit message (non-trailer URLs, line-wrapped URLs, and patch-processing artifacts). Documentation in `git-interpret-trailers.adoc` is updated to explain the new behavior.

The patch is well-motivated, with concrete examples from the Linux kernel showing how the bug manifests in practice (245 affected commits). The solution is minimal and targeted, addressing only the trailer parsing logic without changing other Git behaviors. Jeff King’s Ack and the prior discussion confirm the technical soundness of the approach, including the trade-off of accepting benign false positives (e.g., `1://`) for implementation simplicity. The interdiff against v2 shows only the addition of Jeff’s Ack, indicating no substantive changes since the previous version.

This patch is now merged to `master` (confirmed in Junio’s "What's cooking" report) and resolves a long-standing edge case that affected both `--only-trailers` and `%(trailers:only)` formatting.
