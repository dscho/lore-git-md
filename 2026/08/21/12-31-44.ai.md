This is the first patch in Patrick Steinhardt's two-patch series enabling parallel packfile URI downloads during `git fetch` and `git clone`. It refactors the existing packfile URI handling in `fetch-pack.c` to prepare for parallelization by splitting the logic into three distinct phases: preparation, fetching, and aggregation.

The patch introduces a new `fetch_packfile_uri_result` struct to hold per-URI results (including gitmodules OIDs, pack hash, and keep file status) and reorganizes the code into two new functions: `fetch_packfile_uri` (which handles downloading a single URI) and `fetch_packfile_uris` (which orchestrates the overall process). The changes are purely structural—no behavior changes are introduced, and the patch maintains the existing sequential download order.

Key technical details include the use of `CALLOC_ARRAY` to allocate per-URI result storage, careful initialization of `oidset` structures for gitmodules tracking, and a clear separation between the fetch phase (which will later run in parallel) and the aggregation phase (which combines results). The patch touches only `fetch-pack.c` and replaces the original inline URI-fetching loop with a call to the new `fetch_packfile_uris` function.

This refactoring is well-motivated and necessary for the parallelization work in the next patch. The commit message clearly explains the three-phase design, and the code changes are focused and mechanical. No new configuration or user-facing behavior is introduced at this stage.
