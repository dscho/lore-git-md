This is a bugfix series targeting the submodule subsystem, specifically the experimental `submodule.propagateBranches` feature. The patches address a crash (BUG) and incorrect error handling when `git branch` is used with `--recurse-submodules` and a start point that is not a ref name (e.g., a raw object ID).

The issue manifests in two ways: in repositories without submodules, Git aborts with a BUG after already moving the branch, leaving the operation partially completed but reporting failure; in repositories with submodules, the command fails earlier due to a truncated argument list passed to a helper. The root cause is the same: a missing tracking name when the start point is not a ref. The fix adds guards at the call sites to prevent these edge cases from reaching the problematic code paths.

The series consists of two patches:
1. The first patch prevents tracking a start point that has no ref, aligning with existing logic in `create_branch()`.
2. The second patch allows recursion to proceed even when there is no tracking name, fixing the submodule case.

The commit messages are detailed and well-motivated, explaining the problem, the fix, and the reasoning behind the approach. The author notes that the exposure is limited to the experimental `submodule.propagateBranches` feature combined with specific conditions (submodule recursion enabled, a configured remote, and a non-ref start point), but within those bounds, the bug is reproducible and problematic for scripting use cases. The patches include new tests in `t/t3207-branch-submodule.sh` to cover both scenarios.

The author acknowledges two open questions: whether to also fix a similar unguarded call in `dwim_and_setup_tracking()` (which currently survives due to a caller-specific argument) and whether the first test should live in `t3200` instead of `t3207`. The series is based on `maint` and merges cleanly into `next` and `seen`, with full test suite passes on the topic.

Key technical details for follow-up discussion:
- Files touched: `branch.c`, `builtin/submodule--helper.c`, and `t/t3207-branch-submodule.sh`.
- Functions modified: `create_branches_recursively()` and its call to `setup_tracking()`.
- New test cases cover both the BUG abort and the submodule helper failure.
- The fix avoids changing behavior for start points that *are* ref names.
