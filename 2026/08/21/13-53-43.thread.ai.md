Subject: [PATCH 0/2] repo structure: use Unicode box-drawing characters in UTF-8 locale
Series version: v1 (initial submission)
Originating author: K Jayatheerth (GSoC participant)
Thread type: patch series (feature addition)

Core problem or goal
Add Unicode box-drawing characters (`│`, `├`, `─`, `┼`, `┤`) and bullets (`•`) to the output of `git repo structure` when the user’s locale is UTF-8, while preserving ASCII fallback for non-UTF-8 environments. The series also fixes a latent bug in `is_utf8_locale()` that incorrectly reported UTF-8 when `git_setup_gettext()` returned early (e.g., in uninstalled builds) and `charset` remained unset.

Current status
Under review (no maintainer decision yet). Two patches:
1. Fix `is_utf8_locale()` in `gettext.c` to use environment-derived fallbacks (`LC_ALL`, `LC_CTYPE`, `LANG`) when `charset` is unset, ensuring robust locale detection even in uninstalled builds or when gettext support is disabled. The fix caches the fallback charset in a static buffer to avoid repeated environment lookups.
2. Implement Unicode rendering in `stats_table_setup_structure()` and `stats_table_print_structure()` in `builtin/repo.c`, guarded by `is_utf8_locale()`. The patch updates `t/t1901-repo-structure.sh` to verify Unicode output under a UTF-8 locale using the `GIT_TEST_UTF8_LOCALE` test helper (borrowed from `t/lib-git-svn.sh`), while pinning existing tests to `LC_ALL=C` to guarantee ASCII fallback. No new symbols are introduced; the changes are internal to these functions.

Key technical details
- Files touched: `gettext.c`, `builtin/repo.c`, `t/t1901-repo-structure.sh`
- New symbols: none (internal-only changes)
- New test helper: `GIT_TEST_UTF8_LOCALE` (adopted from `t/lib-git-svn.sh`) to define a `UTF8_LOCALE` test prerequisite
- Unicode characters introduced: `│`, `├`, `─`, `┼`, `┤`, `•`
- On-disk format: unchanged
- Test coverage: existing tests pinned to `LC_ALL=C` for ASCII fallback; new tests verify UTF-8 output when `GIT_TEST_UTF8_LOCALE` is set, including edge cases like missing locale directories

Open questions and loose ends
- **Maintainer concern**: Junio C Hamano expressed skepticism about the feature’s cross-terminal reliability, noting that Unicode box-drawing characters often render inconsistently due to varying width assumptions. This objection raises questions about the feature’s suitability for inclusion unless the author can demonstrate robust compatibility or address rendering issues. No technical counterarguments or alternative proposals have been offered yet.
