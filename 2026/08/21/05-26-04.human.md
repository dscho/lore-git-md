This is a bugfix patch that completes the effort to stop Git from incorrectly interpreting URLs in commit messages as trailers. It implements the solution previously agreed upon in the thread, modifying `trailer.c` to exclude lines containing `://` from trailer parsing unless whitespace has already been encountered. The patch is the third iteration (v3) and includes Jeff King’s Ack, signaling strong consensus.

The change is minimal and targeted: it adds a check in `find_separator()` to reject lines where `://` immediately follows a colon separator, preserving legitimate trailers while preventing URLs from being misparsed. The commit message provides clear real-world examples from the Linux kernel, demonstrating how this bug manifests in practice—mangling URLs, compounding line-wrapping mistakes, and even introducing false trailers during patch application. Test coverage is thorough, with both integration tests (in `t7513-interpret-trailers.sh`) and unit tests (in `t/unit-tests/u-trailer.c`) covering all three problematic scenarios identified in the original report.

The patch also updates the documentation to explain the new behavior, noting that lines starting with `https://` or similar schemes will no longer be treated as trailers. The implementation is intentionally simple, using a heuristic (`://`) rather than a full URL parser, which introduces a minor theoretical edge case (e.g., `1://` would be rejected even though it cannot be a valid URL scheme). This trade-off was explicitly accepted in prior discussion as a reasonable compromise for implementation simplicity.

Given the prior review and Jeff King’s Ack, this patch looks ready for integration. It addresses a real-world issue with documented impact (245 instances in the Linux kernel history) and does so with a clean, well-tested solution. The thread has already explored broader enhancements (like special-casing bracketed text), but this patch focuses on the immediate problem without introducing unnecessary complexity.
