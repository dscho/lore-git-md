This is the first patch in a two-patch bugfix series for the submodule subsystem, addressing a crash in the experimental `submodule.propagateBranches` feature. The patch prevents `git branch --recurse-submodules` from attempting to set up tracking when the start point is not a ref name (e.g., a raw object ID), which previously triggered a BUG in `refspec_find_match()` due to a missing `tracking_name`.

The fix aligns the recursive branch creation path (`create_branches_recursively()`) with the non-recursive path (`create_branch()`), which already guards against this case. The change is minimal: a single condition (`tracking_name && track`) replaces the existing `track` guard in `branch.c`. The commit message explains the crash scenario in detail, including the four prerequisites (submodule recursion enabled, `propagateBranches` set, a configured remote, and a non-ref start point) and why the abort occurs after the branch is already updated, creating a misleading failure state for scripts.

The patch adds a new test in `t/t3207-branch-submodule.sh` that verifies the fix by creating a repository without submodules (to isolate the bug) and forcing a branch to a raw object ID. The test confirms the branch moves successfully without crashing. The author notes the fix could alternatively be placed inside `setup_tracking()`, but argues the current approach is clearer and maintains consistency between the recursive and non-recursive paths.

Key technical details for follow-up: the crash occurs in `refspec.c:442` (`refspec_find_match`), the fix touches only `branch.c` and the test file, and the exposure is limited to the experimental `propagateBranches` feature. The patch is well-motivated and includes all necessary context for reviewers to assess the edge case and the solution.
