This is a bugfix patch targeting the worktree repair functionality, specifically the handling of relative versus absolute paths in `.git` files. This is the third iteration (v3) of a single-patch series by Yoichi NAKAYAMA, addressing feedback from Junio C Hamano on the previous version.

The patch fixes a long-standing asymmetry in `git worktree repair`: when `worktree.useRelativePaths` is toggled, the command correctly converts paths from absolute to relative but fails to do the reverse. The root cause is `read_gitfile_gently()`, which always returns an absolute path, obscuring the original path style stored in the `.git` file. The fix introduces a new function, `read_gitfile_raw()`, which returns the path verbatim (absolute or relative) without normalization. The existing `read_gitfile_gently()` now delegates to `read_gitfile_raw()` to obtain the original path before converting it to absolute form.

This version incorporates Junio’s API feedback: `read_gitfile_raw()` now takes a caller-provided `strbuf` instead of using a static buffer, making the API reentrant and consistent with Git’s modern conventions. The change is mechanical and uncontroversial, touching `setup.c`, `setup.h`, `worktree.c`, and the test script `t/t2406-worktree-repair.sh`. The test suite is expanded with four new cases that verify the repair logic correctly handles transitions between absolute and relative paths in both main and side worktrees, including proper error messages for mismatches.

The patch is well-motivated, addresses a real correctness issue, and has converged on a design that avoids API churn. The only remaining step is for the author to confirm the API tweak, after which this looks ready for merging.
