This thread is a two-patch bugfix series from Volodymyr Vriukalo that addresses crashes and incorrect error handling in Git’s experimental `submodule.propagateBranches` feature when `git branch --recurse-submodules` is used with a non-ref start point (like a raw object ID). The issue manifests differently depending on whether submodules are present: in repositories without submodules, Git aborts with a BUG after partially completing the operation, while in repositories with submodules, the command fails earlier due to a truncated argument list passed to a helper.

The first patch, already detailed in the thread, prevents tracking a start point that lacks a ref name, aligning the recursive path with existing logic in `create_branch()`. The second patch, now described, makes the tracking name argument optional in the `submodule--helper create-branch` command, allowing recursion to proceed even when no tracking name exists. Both patches are minimal and focused, touching only `branch.c` and `builtin/submodule--helper.c`, with new tests in `t/t3207-branch-submodule.sh` to verify the fixes. The series is under review, with no prior versions, and is based on `maint`. While the bug is limited to the experimental feature, it is reproducible and problematic for scripting use cases. No substantive reviews have been posted yet, and minor questions remain, such as whether the first test should live in `t3200` instead of `t3207` and whether the approach to handling the submodule case is optimal.
