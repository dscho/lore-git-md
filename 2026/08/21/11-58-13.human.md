This is a bug report about sparse checkout interacting poorly with submodules.

Victor reports that `git fetch` fails when `fetch.recurseSubmodules` is set to `on-demand` and an updated submodule is excluded by the sparse checkout definition. He provides a self-contained reproduction case in a GitHub gist but has not yet included a patch or detailed analysis of the root cause.

The issue appears to be a real edge case: sparse checkout is explicitly designed to exclude certain paths, yet the submodule recursion logic may not account for that exclusion, leading to a failure when Git tries to fetch into a path that is not checked out. This is the kind of subtle interaction that the sparse-checkout and submodule subsystems are known to have, and it is plausible that the behavior is unintended.
