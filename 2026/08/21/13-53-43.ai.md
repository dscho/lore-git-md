This is a two-patch feature series introducing Unicode box-drawing characters to the `git repo structure` command when a UTF-8 locale is detected, authored by a GSoC participant. The series touches the gettext subsystem (`gettext.c`) and the `repo` built-in (`builtin/repo.c`), with corresponding test updates in `t/t1901-repo-structure.sh`.

The first patch fixes a latent bug in `is_utf8_locale()`: when `git_setup_gettext()` returns early (e.g., in uninstalled development builds), the `charset` variable remains unset, causing `is_encoding_utf8(NULL)` to default to true and incorrectly report a UTF-8 locale even under `LC_ALL=C`. The fix ensures environment-derived fallbacks (`LC_ALL`, `LC_CTYPE`, `LANG`) are used whenever `charset` is unset, regardless of `NO_GETTEXT`.

The second patch implements the Unicode rendering logic in `stats_table_setup_structure()` and `stats_table_print_structure()`. It queries `is_utf8_locale()` and emits Unicode box-drawing characters (`│`, `├`, `─`, `┼`, `┤`) and bullets (`•`) when appropriate, falling back to ASCII otherwise. The test suite adopts the `GIT_TEST_UTF8_LOCALE` convention from `t/lib-git-svn.sh` to define a `UTF8_LOCALE` prerequisite, pins existing tests to `LC_ALL=C` to ensure ASCII fallback coverage, and adds new tests for UTF-8 output.

The series is narrowly scoped to the `repo structure` command and avoids broader Unicode changes elsewhere in Git. The commit messages are detailed and the test coverage appears thorough, including edge cases like missing locale directories. The feature is opt-in based on locale detection and maintains backward compatibility. Key technical details for follow-up discussion include the `is_utf8_locale()` function, the `GIT_TEST_UTF8_LOCALE` test helper, and the specific Unicode characters introduced.
