This is the fourth patch in Patrick Steinhardt’s six-patch series making packfile generation pluggable in Git’s ODB layer. It refactors `git bundle`’s progress-meter option handling to use a simple boolean flag instead of four separate passthrough options.

The patch consolidates `--progress`, `--all-progress`, `--quiet`, and `--all-progress-implied` into a single `progress` boolean, simplifying the interface. The default behavior (show progress if stderr is a TTY) is preserved, and the `--all-progress-implied` option (which does nothing in this context) is retained for backward compatibility but no longer affects the logic. The change reduces the code from 33 lines to 16 in `builtin/bundle.c`, replacing `OPT_PASSTHRU_ARGV` macros with `OPT_BIT`, `OPT_NEGBIT`, and `OPT_NOOP_NOARG`.

This is a preparatory refactoring for patch 6/6, which migrates `git bundle` to the new ODB interface. The patch is mechanical and well-motivated, with no behavior changes or edge-case regressions. Karthik Nayak’s review of v3 praised the refactored code as “much nicer to read,” and the v4 iteration includes no substantive changes to this patch. The only loose end is a tangential documentation inconsistency in `git-pack-objects`’s man page (noted by Karthik), which omits the `--quiet` long form but is unrelated to this patch.

Key details for follow-up:
- **Files touched**: `builtin/bundle.c` (only).
- **New symbols**: None (internal boolean `progress`).
- **Behavior**: Unchanged; only the internal representation of progress-meter options is simplified.
- **Test coverage**: None required; the patch is purely refactoring with no functional impact.
- **Dependencies**: Patch 6/6 depends on this refactoring to eliminate the `pack_opts` strvec.

The patch is uncontroversial and ready for `next`. It demonstrates the series’ broader goal of reducing backend-specific code in transport commands.
