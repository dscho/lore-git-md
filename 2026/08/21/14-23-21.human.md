This is the first patch in a three-part series replacing the deprecated `utime()` function with `utimensat()` for POSIX.1-2024 compatibility. The patch introduces a `utimensat()` wrapper in `compat/posix.h` and implements platform-specific fallbacks: a generic `git_utimensat()` using `utimes()` for older systems, and a MinGW-specific `mingw_utimensat()` that converts `struct timespec` to Windows `FILETIME` with 100ns precision. It also adds the `ST_ATIME_NSEC(st)` macro to complement existing nanosecond-resolution macros for modification and creation times.

The implementation handles the `UTIME_NOW` and `UTIME_OMIT` flags, which allow selective timestamp updates, though it currently rejects non-zero `fd` or `flag` arguments with `ENOSYS` (not implemented). Build system files (`Makefile`, `meson.build`, `CMakeLists.txt`, and `configure.ac`) are updated to detect and conditionally compile the fallback implementation when `utimensat()` is unavailable. The MinGW implementation reuses the existing `mingw_utime()` logic but extends it to support nanosecond timestamps and the new flags.

This is a well-structured, mechanical refactoring that lays the groundwork for the rest of the series. The wrapper design is clean, and the fallback implementations appear robust. The patch is likely uncontroversial, though reviewers may focus on edge cases in timestamp handling or the decision to reject non-zero `fd`/`flag` arguments rather than implementing them. The build system updates suggest thorough cross-platform testing.
