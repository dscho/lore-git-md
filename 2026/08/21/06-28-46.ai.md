This is a follow-up in the ODB packfile generation series, specifically addressing Junio C Hamano’s question about the `pack_fd` file descriptor lifecycle in the `odb_generate_pack()` interface. The exchange clarifies that the "consumed by the generator" contract applies only when the primary ODB source supports packfile generation, which is guaranteed for all current and future primary sources. In the error case where the primary source lacks the `generate_pack` callback (which should never occur in practice), the descriptor is not consumed, and the caller remains responsible for cleanup. Patrick Steinhardt confirms that this edge case is unreachable because the callback is non-optional for primary sources, and the interface’s design assumes all primary backends will implement it. The resolution leaves the interface’s documentation intact but underscores that the descriptor lifecycle contract is contingent on successful delegation to the backend. This detail is now settled for the series, though it may inform future interface design discussions.
