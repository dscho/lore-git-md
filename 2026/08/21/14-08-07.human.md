This is the sixth patch in K Jayatheerth’s seven-patch series adding new path-related keys to `git repo info`. The patch implements `path.git-prefix`, which exposes the relative path from the repository’s top-level working tree to the current directory. The series is now effectively complete in scope after Junio C Hamano’s intervention settled the design debate: `path.git-prefix` is included, and the author has agreed to add a complementary `path.cdup` key in the next iteration.

The patch itself is straightforward: it adds the new key by reading `repo->prefix` and formatting it with the existing `format_path()` helper. The implementation matches the established pattern for relative-path keys in the series, and the commit message justifies the feature by noting that scripts sometimes need this information but currently have to derive it through less direct means. No substantive technical objections remain; the only open question is the exact implementation of `path.cdup`, which the author plans to address in the next version.

This patch is part of a well-motivated feature effort that has been through four iterations and addresses all prior feedback. The series is now mechanically clean and ready for deeper technical review, though the addition of `path.cdup` may prompt minor adjustments. If you care about scriptable access to repository paths, this is worth tracking.
