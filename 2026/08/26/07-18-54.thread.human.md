This thread is a user feedback discussion about the recent deprecation of `git whatchanged`, which now requires the `--i-still-use-this` flag to invoke. The originating user, edvard.jo@gmail.com, reports that while the change initially disrupted their workflow, modern alternatives like `git log --oneline --name-status` or `git diff --stat main` are sufficient replacements. Their primary attachment to `whatchanged` stems from muscle memory and command-name convenience rather than a specific output format.

Kristoffer Haugsbakk followed up to clarify the user’s needs, confirming that the deprecation itself isn’t problematic—just the loss of a familiar command name. The user plans to adopt an alias (`git config --global alias.whatchanged 'log --stat --no-merges'`) as a workaround, which addresses their workflow without requiring the legacy command to remain in Git. The thread also notes that the deprecation message was improved in Git v2.51.0 to provide clearer guidance, which the user encountered. No technical objections or requests for reverting the deprecation have been raised; the discussion remains constructive and focused on understanding user habits to inform future documentation or messaging.
