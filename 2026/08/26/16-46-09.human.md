This is a surface-level review comment on the second patch in the v9 series improving error messages for ambiguous remote branch names. Junio C Hamano points out a minor but unnecessary double indirection in the `tracking_name_data` struct: the `remote_names` field is currently a pointer to a pointer (`struct string_list **`), but it could simply be a pointer (`struct string_list *`) since the function only needs to append to the list, not reassign it. The suggested change would simplify the code slightly by removing one level of indirection in the callback (`check_tracking_name`) and the caller (`unique_tracking_name`).

The patch itself is part of a well-reviewed and functionally complete series that has already been merged to `next`. This feedback is purely mechanical and uncontroversial—it addresses a small inelegance in the implementation without changing behavior. The author, Yoichi NAKAYAMA, will likely incorporate the suggestion in a follow-up iteration or as a trivial fixup before the series graduates to `master`. The change is unlikely to affect the series' overall trajectory or the usability improvements it delivers.
