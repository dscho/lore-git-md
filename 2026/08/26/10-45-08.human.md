This is the second patch in the v9 series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. The series is already merged to `next` and this iteration is a final refinement.

The patch extends the `unique_tracking_name()` function to optionally collect the names of matching remotes when multiple branches with the same name exist across remotes. This data is then used to enhance the error message: instead of the generic "matched multiple (2) remote tracking branches", users now see a detailed advice listing the conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes: origin upstream"). The advice also suggests using `--track <remote>/<branch>` or setting `checkout.defaultRemote` to avoid future ambiguity.

The implementation is clean: the new `advise_disambiguating_remotes()` helper (introduced in patch 1/4) is reused here, avoiding code duplication. The advice is gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and respects the `--quiet` flag. The patch also fixes a grammatical error in the advice message ("Branches ... appears" → "Branch name '%s' appears").

This is a usability improvement with no behavior changes beyond the error message itself. The series has been thoroughly reviewed, and this patch addresses the last organizational feedback from Junio by moving the advice helper earlier in the series. Test coverage is already in place. The follow-up item for the one-argument `git worktree add` case remains scoped separately.
