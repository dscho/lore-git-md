Thread identity: documentation update to the deprecation warning message in `usage.c` for deprecated Git commands. Originating author: Junio C Hamano. Thread type: single-patch documentation fix (v2).

Core problem or goal: reword the user-facing deprecation warning in `you_still_use_that()` to eliminate misleading language that could imply the Git project might reverse a deprecation decision. The new message is shorter (6 lines, down from 8), more direct, and guides users to the breaking changes documentation, mailing list archives, and the mailing list for help finding a replacement or alternative workflow. The latest version changes the opening line from "this command is nominated for removal" to "this command will be removed" to reinforce the finality of deprecation. Kristoffer Haugsbakk proposes an additional line (*"The decision is final and will not be reconsidered"*) to further deter users from lobbying to reverse deprecations, citing real-world cases where users have misinterpreted deprecation warnings as invitations to advocate for command reinstatement.

Current status: patch posted (v2); replaces v1. Under review. The opening line refinement ("will be removed" instead of "is nominated for removal") is now endorsed by Michael Montalbo and Elijah Newren. Two minor editorial nits remain unresolved: Elijah Newren’s grammatical suggestion (adding "list" to "mailing") and Kristoffer Haugsbakk’s proposal to add a line explicitly stating the finality of the deprecation decision.
