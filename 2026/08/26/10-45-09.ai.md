This is the third patch in the v9 series improving error messages for ambiguous remote branch names in `git worktree add`. It extends the advice and error-handling logic introduced in earlier patches to `git worktree add`, completing the coverage for all three commands (`checkout`, `switch`, and `worktree add`).

The patch addresses the specific case where `git worktree add ../foo-dir bar-topic` fails due to ambiguity in remote branch names (e.g., `bar-topic` exists in both `origin` and `upstream`). Previously, the command would silently give up on resolving the ambiguity, then later fail with a generic "invalid reference" error. Now, it immediately dies with a clear diagnostic: the error message includes the number of matching remotes (e.g., "matched multiple (2) remote tracking branches"), and a detailed advice message lists the conflicting remotes and suggests workarounds like `git worktree add -b bar-topic ../foo-dir origin/bar-topic` or setting `checkout.defaultRemote`.

The implementation reuses the `advise_disambiguating_remotes()` helper introduced in the first patch, ensuring consistent advice formatting across all commands. The advice is suppressed in quiet mode (`--quiet`) and controlled by the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default). The patch also extends `unique_tracking_name()` to collect remote names via a `struct string_list`, which the helper uses to generate the static list of conflicting remotes. The scope of the `oid` variable in `builtin/worktree.c` is narrowed, and the test in `t/t2400-worktree-add.sh` is updated to verify the new error message format.

This patch is part of a functionally complete series merged to `next`. The only remaining loose end is the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), which is scoped for a follow-up fix. The series has no open technical objections, and this patch aligns `git worktree add` with the behavior already implemented for `git checkout` and `git switch`.
