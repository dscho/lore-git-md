This patch is a **bugfix** targeting the merge machinery. Elijah Newren extends Git's existing protection against `git commit --amend` during conflict resolution to cover additional operations that can produce conflicts: `git am`, `git revert`, and all forms of `git rebase` (both the apply and merge backends). The change prevents users from accidentally amending the wrong commit when resolving conflicts, which can corrupt the repository state.

The logic is careful to distinguish between genuine conflict stops and the internal use of `--amend` by interactive rebase (for `squash`, `reword`, `edit`, and `break` directives). The patch checks for the presence of `.git/rebase-merge/stopped-sha` and the absence of `.git/rebase-merge/amend` to identify conflicted stops, while allowing clean `edit` and `reword` stops to proceed. New tests in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh` verify the behavior across all affected operations.

The commit message is thorough, explaining the motivation, the technical approach, and the edge cases considered. The code itself is clean and well-documented, with clear comments about the meaning of the rebase-merge directory files. This is a targeted, well-crafted fix that addresses a real foot-gun without disrupting legitimate workflows. It looks ready for review and likely to be uncontroversial.
