This is a maintainer response to a bugfix patch for `git apply`. Junio C Hamano has reviewed the patch after it sat unreviewed for over a month and is rejecting it.

The patch aimed to fix a memory leak and state corruption bug in `find_header()`, where abandoned Git-style diff headers could leave partially parsed state in the `struct patch`, corrupting subsequent parsing of traditional "---/+++" headers. The fix used a temporary `struct patch` to isolate Git header parsing and explicitly rejected empty default names from "diff --git" lines.

Junio's objection is not technical but philosophical: he views the current behavior as a *feature*, not a bug. The parser's current behavior of aborting on malformed patches (such as those with stray "diff --git" lines) is intentional, serving as a sanity check that forces users to inspect and fix broken patches. He does not want to change this behavior to silently handle or recover from such cases. The patch is therefore unlikely to be merged in its current form.
