This is the **final review request** for a security feature patch that adds `http.sslVerifyStatus`, a boolean config option (default `false`) to enable OCSP staple validation in Git’s HTTPS certificate verification. The patch is now **technically complete and ready for merging** after six iterations addressing all review feedback, including Junio C Hamano’s latest documentation wording tweak in v6.

The feature closes a security gap where Git’s HTTPS certificate verification ignores OCSP staples, leaving OpenSSL-linked binaries (common in FIPS-compliant deployments like US Department of Defense PKI) vulnerable to accepting revoked certificates. When enabled, `http.sslVerifyStatus` causes connections to fail if the server does not provide a valid staple, aligning Git’s behavior with government and enterprise security mandates. The default remains `false` to avoid breaking remotes that do not support stapling, but the design is fail-closed for security.
