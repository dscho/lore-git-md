This is the final patch in Karthik Nayak’s three-part series introducing the new `receive-report` hook for `git-receive-pack`. The series is now technically complete and queued in `seen`, awaiting graduation to `next`.

The patch implements the core hook logic: after all ref updates are committed but before the status report is sent to the client, `receive-pack` invokes the `receive-report` hook, feeding it the pkt-line encoded report on stdin. The hook’s stdout replaces the report; its stderr is forwarded to the client via the sideband channel. A zero exit code means the hook’s output is used; a non-zero exit rewrites every ref status line to “receive-report hook failed” and discards the hook’s stdout, matching the behavior of the `pre-receive` hook. The implementation is self-contained and does not use the config-based hook infrastructure, avoiding the complexity of chaining multiple scripts.

The commit message clearly motivates the hook with GitLab’s MVCC use case—reporting the correct repository state after external post-update operations—and explains why none of the existing hooks (`pre-receive`, `update`, `reference-transaction`, `post-receive`, `post-update`) can serve this purpose. The documentation in `githooks.adoc` and `git-receive-pack.adoc` is thorough, covering the pkt-line format, exit semantics, and sideband forwarding. The test suite (`t/t5412-receive-report-hook.sh`) exercises passthrough, failure modes, stdin/stdout handling, and sideband relay, giving good coverage of the new behavior.

All prior feedback has been addressed: the hook name was changed from `report` to `receive-report` to avoid ambiguity, the exit semantics were aligned with `pre-receive`, and the series was split into three patches (documentation, refactoring, core implementation) for clarity.
