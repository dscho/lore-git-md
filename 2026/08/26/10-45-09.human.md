This is the third patch in the v9 series improving error messages for ambiguous remote branch names, now targeting `git worktree add`. The patch extends the shared advice helper introduced earlier to provide clear, actionable guidance when the user runs `git worktree add <path> <branch>` and the branch name exists in multiple remotes (e.g., `origin/foo` and `upstream/foo`).

The change moves the error handling earlier in the code path, replacing a generic "invalid reference" message with a specific diagnostic that lists the conflicting remotes and suggests how to resolve the ambiguity. The advice is gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and includes a static list of remotes, the branch name, and the number of matches (e.g., "matched multiple (2) remote tracking branches"). The helper function `advise_disambiguating_remotes()` is reused from earlier patches, ensuring consistent messaging across `git checkout`, `git switch`, and `git worktree add`.

The patch also narrows the scope of the `oid` variable and updates the test in `t/t2400-worktree-add.sh` to verify the new error message format. The implementation aligns with the behavior already established for `git checkout` and `git switch` in earlier patches, treating ambiguity as an error rather than silently proceeding. The series is now functionally complete, with only minor organizational refinements remaining in the final patch. This looks like a well-crafted usability improvement with thorough test coverage.
