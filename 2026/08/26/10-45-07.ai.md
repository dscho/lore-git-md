This is the first patch in the v9 series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. It extracts the advice message logic into a new shared helper function, `advise_disambiguating_remotes()`, to avoid code duplication and prepare for reuse in later patches.

The patch moves the advice block from `parse_remote_branch()` into a standalone function that takes the `enum checkout_command` as an argument, allowing it to tailor the message for either `git checkout` or `git switch`. The advice itself remains unchanged: it suggests using `--track` or setting `checkout.defaultRemote` to resolve ambiguity. The extracted function is called only when `advice.checkoutAmbiguousRemoteBranchName` is enabled (the default) and multiple remote branches match the given name.

This is a refactoring patch with no behavior change; the error message and advice content are identical to the previous version. The motivation is purely structural, setting up the shared helper for use in the `git worktree add` command in patch 3/4. The patch is clean and uncontroversial, addressing prior feedback to avoid duplicating the advice logic.
