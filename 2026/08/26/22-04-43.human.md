This is a bugfix for zsh completion that Junio has marked for inclusion in the `next` branch. The patch addresses a long-standing issue where zsh’s Git completion script fails to work after global options like `-C <path>`, `-p`, or `--git-dir`. For example, `git -C some/dir checkout <TAB>` would previously offer no completions, and `git -p checkout <TAB>` would fail to suggest branch names.

The fix aligns the zsh wrapper (`contrib/completion/git-completion.zsh`) with the bash implementation by scanning past all global options and their arguments to correctly identify the command index. It also collects `-C` paths into `__git_C_args` so that bash helpers run `git` in the intended directory, ensuring aliases and refs resolve properly. The patch is small (25 lines), well-tested, and fully addresses the feedback from v1, including Junio’s architectural concerns and D. Ben Knoble’s technical review.

The commit message clearly documents the remaining limitations: chained `-C` directory completion (e.g., `git -C dir -C <TAB>`) is still broken, `-c` is missing from the `_arguments` spec, and `--git-dir` only accepts `--git-dir=<path>` (not `--git-dir <path>`). These are explicitly deferred to follow-ups, and the unrelated `git -<tab>` bug (redundant output) is confirmed as pre-existing. The patch is effectively ready for merging, with Junio’s explicit marking for `next` signaling confidence in its readiness.

This is a practical, low-risk improvement that fixes a common frustration for zsh users. If you use zsh and Git’s completion, this patch will make your workflow noticeably smoother. The remaining gaps are minor and well-documented, so there’s no reason to hold up the core fix.
