This is the first patch in the v9 series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. It extracts the advice message logic into a new shared helper function, `advice_disambiguating_remotes()`, to avoid code duplication and prepare for reuse in later patches. The helper takes an `enum checkout_command` parameter to tailor the advice to either `checkout` or `switch`, and the advice itself remains unchanged: it suggests using `--track` or setting `checkout.defaultRemote` to resolve ambiguity.

The refactoring is mechanical and well-motivated, moving the advice block from `parse_remote_branch()` into a standalone function. This is a clean preparatory step for the rest of the series, which will extend the same advice to `git worktree add` and align error handling across all three commands. The patch touches only `builtin/checkout.c` and makes no behavioral changes — the advice message, its config key (`advice.checkoutAmbiguousRemoteBranchName`), and the `die()` call remain identical. The commit message is minimal but sufficient for this kind of refactoring.
