This is a documentation patch refining the deprecation warning message shown when users run a deprecated Git command. The change is part of a small, focused thread initiated by Junio C Hamano to clarify the language in `usage.c`'s `you_still_use_that()` function. The new message is shorter, more direct, and removes any implication that the Git project might reconsider a deprecation decision—it now points users to the breaking changes documentation, mailing list archives, and the mailing list itself for help finding a replacement.

The patch itself is trivial: it modifies only the error message string in `usage.c`, with no behavior changes. The updated message is six lines (down from eight) and uses clearer phrasing. Junio confirms that the double newlines after the `BreakingChanges` and lore.kernel.org links are intentional, addressing a formatting nit raised by Michael Montalbo in his review. Montalbo had also suggested a minor phrasing tweak to the email-help line to further emphasize the finality of deprecation, but this email doesn’t revisit that point.

This is a well-motivated, uncontroversial fix. The commit message explains the rationale clearly, and the change aligns with the project’s goal of setting accurate expectations for users. The discussion so far has been limited to surface-level refinements, with no substantive objections or technical concerns. If you’re tracking Git’s user-facing messaging or deprecation policies, this patch is worth noting—but it’s unlikely to generate further debate.
