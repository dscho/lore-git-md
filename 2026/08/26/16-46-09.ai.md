This is a surface-level review comment on the second patch of the v9 series improving error messages for ambiguous remote branch names. Junio C Hamano points out a minor code structure issue: the `remote_names` field in `struct tracking_name_data` is currently a pointer-to-pointer (`struct string_list **`), but this double indirection is unnecessary. The function `unique_tracking_name()` receives a pointer to a string list from the caller, and the callback (`check_tracking_name()`) only needs to append to that list, not replace it. Junio suggests simplifying this to a single pointer (`struct string_list *`), which would make the code cleaner and more straightforward.

The change is mechanical and uncontroversial: it removes an extra level of indirection without altering the patch’s behavior or goals. The patch remains part of a functionally complete series merged to `next`, with this feedback addressing a small implementation detail rather than a functional concern. The series as a whole is still on track, and this adjustment is unlikely to delay its progress.
