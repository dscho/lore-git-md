This is a documentation patch refining the deprecation warning message in `usage.c`. It updates the user-facing instructions shown when someone invokes a deprecated Git command, replacing the previous 8-line message with a shorter, clearer 6-line version. The new wording removes language that could mislead users into thinking the Git project might reverse a deprecation decision, instead emphasizing that the command *will* be removed and guiding users toward finding a replacement workflow.

The patch modifies only the `you_still_use_that()` function in `usage.c`, changing the error message string and its formatting. The opening line now reads "'%s' will be removed soon" (previously "is nominated for removal"), reinforcing the finality of the deprecation. The rest of the message directs users to the breaking changes documentation, mailing list archives for prior discussion, and the mailing list itself for help—though the email-help line is intentionally generic, covering cases where a deprecated command may not have a direct replacement but rather a new workflow.

This is the second iteration of the patch (v2), incorporating feedback from Michael Montalbo. Junio confirmed the intentional double newlines after the `BreakingChanges` and lore.kernel.org links, resolving a formatting nit, and clarified that the omission of the word "replacement" in the email-help line is deliberate. The only remaining open question is whether to adopt Junio’s proposed refinement to the opening line ("will be removed" instead of "is nominated for removal"), which aligns with the thread’s goal of making the deprecation’s irreversibility clearer. Michael’s earlier phrasing tweak to the email-help line (explicitly tying email help to cases where alternatives "do not work") remains unresolved but is not actively contested.

The patch is well-motivated, with a clear commit message explaining the rationale, and the changes are narrowly scoped to the deprecation warning’s text and formatting. No behavior changes are introduced, and the new message is more direct and user-friendly. The thread has converged on the core direction, with only minor wording refinements still under discussion.
