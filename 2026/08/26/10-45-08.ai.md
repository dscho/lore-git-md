This is the second patch in the v9 series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. The patch extends the `unique_tracking_name()` function to optionally collect the names of matching remotes, then uses this information to provide a detailed, actionable advice message when ambiguity is detected.

The core change is in `checkout.c`, where `unique_tracking_name()` now accepts an optional `struct string_list *dwim_remote_names` parameter. When provided, the function populates this list with the names of all remotes that have a matching branch. The caller (`parse_remote_branch()` in `builtin/checkout.c`) then passes this list to the new `advise_disambiguating_remotes()` helper, which formats a user-facing message listing the conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes: origin, upstream"). The advice also suggests using `--track` or setting `checkout.defaultRemote` to resolve future ambiguity.

The patch touches four files: `builtin/checkout.c` (where the advice logic is implemented), `builtin/worktree.c` (trivial updates to call the extended `unique_tracking_name()`), `checkout.c` (core extension to collect remote names), and `checkout.h` (updated function signature). The advice message is gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and respects the `--quiet` flag.

This is a well-scoped refactoring that prepares the ground for the third patch, which will apply the same advice logic to `git worktree add`. The implementation is clean, with no behavior changes beyond the new advice message, and the commit message clearly explains the motivation. The patch is part of a functionally complete series merged to `next`, with only minor organizational refinements remaining in later patches.
