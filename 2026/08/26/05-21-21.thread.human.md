This thread is about a five-patch bugfix series by Elijah Newren that extends Git's existing protections against unsafe commit operations during conflict resolution. The series targets `git commit --amend` and `git commit <paths>` when used during conflict resolution in `git am`, `git revert`, and all forms of `git rebase`, preventing users from accidentally corrupting repository state.

The core logic reliably distinguishes between genuine conflict stops (where amending or partial commits would corrupt state) and internal `--amend` usage by interactive rebase directives like `squash` or `reword`. Earlier versions of the series sparked a substantive discussion about whether blocking `git commit <paths>` during conflict resolution for empty commits was necessary; this was resolved in v3 after Junio C Hamano noted that the result would still be an empty commit and thus harmless, leading to the restriction being removed. The final patch (5/5) reintroduces the protection for partial commits during conflict resolution, now covering all relevant commands with clear error messages and comprehensive test coverage.

The series is now complete and ready for final review. Junio and Phillip Wood have both engaged substantively with the patches, raising and resolving technical questions and maintainability concerns. Junio’s only remaining feedback is a stylistic preference for a less verbose error message, which is unlikely to block progress. The preparatory patches (1-2/5) refactor the code to improve clarity and maintainability, while patches 3-5 implement the new protections. The series is uncontroversial and expected to proceed to Junio’s `next` branch soon.
