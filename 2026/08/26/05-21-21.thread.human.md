This thread is about a five-patch bugfix series by Elijah Newren that extends Git's existing protections against unsafe commit operations during conflict resolution. The series blocks `git commit --amend` and `git commit <paths>` during conflict resolution for `git am`, `git revert`, and all forms of `git rebase`, while still allowing these operations for interactive rebase directives like `squash` or `edit`. The restriction on partial commits for empty commits was removed in the latest version (v4) after Junio C Hamano noted it was unnecessary, as the result would still be an empty commit.

The series is now complete and ready for integration. All five patches have been approved by Junio and Phillip Wood, with no outstanding technical objections. The only remaining discussion point is a minor UI consistency question raised by Phillip: why partial commits are allowed during rebase for empty commits but blocked during cherry-pick, given that both operations write similar state files. This isn’t a blocker, but it may warrant a follow-up patch or documentation update.

Key changes include renaming some internal symbols for clarity (e.g., `FROM_REBASE_EMPTY` to `FROM_REBASE_NOW_EMPTY`) and refining error messages to better distinguish between conflict stops and clean rebase stops. The series touches `builtin/commit.c`, `sequencer.c`, and related test files, with no on-disk format changes. It’s a straightforward improvement to Git’s conflict-resolution safety net and is expected to land in `next` soon.
