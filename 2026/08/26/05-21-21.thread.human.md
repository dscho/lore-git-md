This thread is about a bugfix patch from Elijah Newren that extends Git's existing protection against `git commit --amend` during conflict resolution to cover `git am`, `git revert`, and all forms of `git rebase`. The goal is to prevent users from accidentally amending the wrong commit and corrupting repository state, while still allowing `--amend` for interactive rebase operations like `squash` or `reword` that explicitly require it.

The patch is under review and remains uncontroversial. Phillip Wood provided a substantive review suggesting a structural improvement—moving the conflict-resolution checks from `builtin/commit.c` to `sequencer_determine_whence()`—to avoid hardcoded paths and improve maintainability. Junio C Hamano endorsed the patch as correct and well-reasoned but noted that the same principle should eventually extend to `git commit <paths>` during conflict resolution, leaving a `#leftoverbits` marker for future work. In the latest email, Junio offered a minor cleanup suggestion: replacing the global `the_repository` with the repository instance already available in the `wt_status` struct, aligning with the ongoing effort to remove `the_repository`.

The patch touches `builtin/commit.c` (with potential refactoring to `sequencer.c`) and includes test coverage in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh`. No on-disk format changes or new CLI options are introduced. The open questions are whether Elijah will adopt Phillip Wood’s refactoring suggestion and whether future work will address `git commit <paths>` during conflict resolution. A v2 is likely if Elijah incorporates the feedback.
