This thread is about a bugfix patch series by Elijah Newren that extends Git's existing protections against unsafe commit operations during conflict resolution. The series targets `git commit --amend` and `git commit <paths>` (partial commits) during conflict stops in `git am`, `git revert`, and all forms of `git rebase`, preventing users from accidentally corrupting repository state by amending the wrong commit or updating individual paths when the entire tree state must be recorded.

The series is now effectively ready for integration. Version 2 addressed all substantive feedback from Junio C Hamano and Phillip Wood, including a maintainability concern about hardcoded paths in the new `sequencer_ongoing_operation()` helper (which Elijah is expected to resolve in v3 or as a follow-up). Phillip Wood's final review of the third patch—blocking partial commits—was positive, calling it a "good idea" and confirming the changes look good. The only remaining loose end is a minor stylistic suggestion about error message phrasing, which is unlikely to block progress.

Key participants include Elijah Newren (author), Phillip Wood (reviewer), and Junio C Hamano (maintainer). Junio endorsed the series as correct and well-reasoned, while Phillip acknowledged its maintainability improvements and called it a "useful improvement to our UI." The series touches `builtin/commit.c`, `sequencer.c`, and `sequencer.h`, with test coverage in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh`. No on-disk format changes or new CLI options are introduced.
