This bugfix series by Elijah Newren aims to prevent users from accidentally corrupting repository state by using unsafe commit operations (`git commit --amend` and `git commit <paths>`) during conflict resolution for `git am`, `git revert`, and all forms of `git rebase`. The series is now in its fourth iteration and is complete, with all substantive feedback addressed.

The first two patches are preparatory: the first renames `FROM_REBASE_PICK` to `FROM_REBASE_NOW_EMPTY` and `is_from_rebase()` to `is_from_rebase_now_empty()` to clarify that these symbols refer to commits that *became* empty during a rebase, addressing Junio C Hamano’s stylistic feedback. The second removes an unnecessary restriction on `git commit <paths>` during conflict resolution for empty commits, as Junio noted the result would still be harmless. The remaining patches extend existing protections to cover additional commands, with improved error messages (e.g., "The now-empty commit has been dropped -- cannot amend") and comprehensive test coverage.

Junio has explicitly approved all five patches, and Phillip Wood has called the series "pretty sound" and a "useful improvement to our UI." The series is technically complete, with no outstanding objections or loose ends, and is ready for integration into Junio’s `next` branch. The changes touch `builtin/commit.c`, `sequencer.c`, `sequencer.h`, and `wt-status.h`, along with test updates, but introduce no new CLI options or on-disk format changes.
