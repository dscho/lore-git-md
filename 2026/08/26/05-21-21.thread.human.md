This thread is about a five-patch bugfix series from Elijah Newren that tightens Git's protections against unsafe commit operations during conflict resolution. The series prevents users from accidentally amending the wrong commit or updating individual paths with `git commit --amend` or `git commit <paths>` while resolving conflicts in `git am`, `git revert`, or any form of `git rebase`. The core logic reliably distinguishes between genuine conflict stops (where these operations would corrupt repository state) and internal `--amend` usage by interactive rebase directives like `squash` or `reword`.

The series is now at version 3, incorporating all feedback from Junio C Hamano and Phillip Wood. The most substantive change was removing the restriction on `git commit <paths>` for empty commits after Junio noted the result would still be harmless. Junio also requested mechanical improvements—renaming `FROM_REBASE_PICK` to `FROM_REBASE_EMPTY_PICK` and the helper function `is_from_rebase()` to `is_from_rebase_empty()`—which Elijah implemented as the first two patches. Phillip Wood's maintainability concern about hardcoded paths was addressed, and he explicitly called the series "pretty sound" and ready for integration. The only remaining loose end is Junio's stylistic objection to the phrasing of an error message, which is unlikely to block progress.

The patches touch `builtin/commit.c`, `sequencer.c`, and test files, with no on-disk format changes or new CLI options. The series is now ready for final review and is expected to move to Junio's `next` branch soon.
