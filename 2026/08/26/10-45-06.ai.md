This is the cover letter for the ninth iteration (v9) of a four-patch series improving user-facing error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The series is now functionally complete and addresses all prior feedback, including the `--guess-remote` edge case and organizational refinements.

The goal remains unchanged: replacing the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message that lists conflicting remotes (e.g., "Branch name '%s' appears in multiple remotes:") and suggests workarounds like `--track` or setting `checkout.defaultRemote`. The advice is controlled by the new `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default). The series also moves an existing `die()` call earlier in the code path to provide a more specific diagnostic, replacing a generic "invalid reference" error with one that explains the ambiguity and includes the number of matching remotes. This change is justified in the commit message as intentional, tracing the problematic flow (silent failure to resolve ambiguity -> `NULL` remote -> misleading error).

Key updates in v9 are minor: the `advise_disambiguating_remotes()` helper is moved earlier in the third patch to improve code organization, and the series now treats `--guess-remote` as an error when multiple matches exist, aligning its behavior with `git checkout` and `git switch`. The one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`) remains scoped for a follow-up fix, as previously agreed. Test coverage in `t/t2400-worktree-add.sh` verifies the new error case for `--guess-remote` and advice suppression in quiet mode.

Files touched include `builtin/worktree.c`, `builtin/checkout.c`, `checkout.c`, `checkout.h`, and documentation. The implementation extends `unique_tracking_name()` to collect remote names, introduces the shared `advise_disambiguating_remotes()` helper, and updates `dwim_branch()` to respect `--quiet`. The series is well-tested, with no remaining open questions or objections.
