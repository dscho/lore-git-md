This is the third and final patch in Karthik Nayak’s v4 series introducing the `receive-report` hook for `git-receive-pack`. The series is now technically complete and queued in `seen`, awaiting graduation to `next`.

The patch implements the core hook logic in `builtin/receive-pack.c`. The hook runs after all ref updates are committed but before the status report is sent to the client. It receives the pkt-line encoded report on stdin and replaces it with its stdout; stderr is forwarded to the client via the sideband channel. A zero exit code means the hook’s stdout is used as the report; a non-zero exit rewrites all ref status lines to `"receive-report hook failed"` and discards the hook’s stdout, matching the behavior of the `pre-receive` hook. The implementation is self-contained and does not use the config-based hook infrastructure, avoiding the complexity of coordinating multiple scripts.

The patch touches `builtin/receive-pack.c` (adding the `run_receive_report_hook()` function and integrating it into `report()` and `report_v2()`), updates `Documentation/git-receive-pack.adoc` and `githooks.adoc` to document the hook’s behavior and exit semantics, and adds a new test script `t/t5412-receive-report-hook.sh` with 200 lines of coverage for passthrough, failure modes, stdin/stdout handling, sideband relay, and the interaction between exit status and stderr output. The test suite exercises both success and failure cases, including custom failure messages and stderr relay.

The hook is motivated by GitLab’s need to implement MVCC (multi-version concurrency control) on the server side, where the status report must reflect the state of the repository after all ref updates are committed but before the client receives confirmation. The commit message justifies the single-script design and documents the pkt-line format by linking to `gitprotocol-pack[5]`. All prior feedback has been addressed, including the hook naming objection (renamed from `report` to `receive-report`) and the exit status semantics (aligned with `pre-receive`).
