This thread is a small but important internal refactoring by Junio C Hamano to replace Git’s fixed-arity `die_for_incompatible_optN()` helpers (which handle 2–4 mutually exclusive command-line options) with a single varargs function, `die_for_incompatible_opts()`, that can handle any number of options. The series is currently at version 1 and under review, with two patches: the first reorders parameters in the existing helpers to prepare for varargs, and the second introduces the new helper and updates all call sites.

The change touches 14 built-in commands and the revision subsystem, but it’s purely internal—no user-visible behavior changes. The main open issue was a memory leak in the varargs usage (missing `va_end()`), flagged by Elijah Newren. Jeff King (Peff) has now weighed in with a substantive review of the second patch, accepting the design but suggesting two mechanical improvements: adding a `LAST_ARG_MUST_BE_NULL` annotation to catch missing sentinels at compile time, and avoiding hard-coded formatting in the error message to make future changes easier. Neither of these is a blocker, but they’d make the code more robust. The series is otherwise uncontroversial and ready for a v2 incorporating these tweaks and the `va_end()` fix. Key participants are Junio (author), Elijah (reviewer), and Peff (reviewer).
