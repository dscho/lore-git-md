This thread introduces a small but widespread refactoring in Git’s option-parsing internals. Junio C Hamano is replacing the fixed-arity `die_for_incompatible_opt2()`, `die_for_incompatible_opt3()`, and `die_for_incompatible_opt4()` helpers with a single varargs function, `die_for_incompatible_opts()`, that can handle any number of mutually exclusive command-line options. The series is split into two patches: the first reorders the parameters of the existing helpers to prepare for the varargs change, and the second introduces the new helper and updates all call sites. Fourteen built-in commands and the revision subsystem are touched, but the change is purely internal—no user-visible behavior or on-disk format is altered.

The series is currently under review, with no feedback recorded yet. The refactoring is mechanical and self-contained, so it’s expected to be uncontroversial, but reviewers may want to verify that the parameter reordering doesn’t introduce subtle bugs in the existing call sites. No test coverage is mentioned, as the change is plumbing-only and assumed to be safe. If you’re catching up on the list, this is a straightforward cleanup effort with no open questions or design debates at this stage.
