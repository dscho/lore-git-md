This thread is a refactoring patch series from Junio C Hamano that replaces the fixed-arity `die_for_incompatible_optN()` family with a single varargs helper, `die_for_incompatible_opts()`. The goal is purely internal API cleanup—no user-visible behavior changes—but the series has hit a few snags during review.

The initial version proposed reordering parameters to enable a NULL sentinel, but after feedback from Jeff King (Peff) and Elijah Newren, Junio is revising the approach. The key issue was a missing `va_end()` call (a C standard violation), which Junio has acknowledged and will fix. Peff also pointed out that the varargs helper lacked compile-time protection for the NULL sentinel and had hard-coded error-message formatting, both of which Junio now plans to address by keeping the old function signatures and using an `EOF` sentinel instead of NULL. The error-message cap at four options remains for now, as dynamic allocation would complicate i18n.

The series touches `parse-options.c`, 14 built-in commands, and the `revision` subsystem, but the changes are mechanical and confined to plumbing. No test coverage was added, as the refactoring is expected to be safe. The only remaining blockers are the `va_end()` fix and the sentinel choice, both of which Junio is addressing in the next iteration. The discussion has been constructive, with both Peff and Elijah providing substantive feedback, and no major objections to the core design. The series is still under review, with no merge in sight yet.
