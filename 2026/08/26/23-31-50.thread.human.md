This thread is a small but clean refactoring series from Junio C Hamano that replaces the fixed-arity `die_for_incompatible_optN()` family (for 2, 3, or 4 options) with a single varargs helper, `die_for_incompatible_opts()`. The goal is to remove an artificial limit on the number of mutually exclusive command-line options Git can handle, though the change is purely internal—no user-visible behavior changes.

The series consists of two patches. The first reorders parameters in the existing helpers to prepare for the varargs conversion, and the second (this email) introduces the new helper and updates all call sites. The implementation is straightforward: the new function collects the first four set options into a static array and reports them with the same error message as before, justified by the observation that reporting all incompatible options at once isn’t practically useful. The change touches `parse-options.c` and `parse-options.h`, along with 14 built-in commands and the `revision` subsystem, but is mechanical and safe—no on-disk formats or test coverage are affected.

The series is now complete and ready for review. No objections or open questions have been raised yet, and the motivation (removing the fixed-arity limit) is uncontroversial. If reviewers agree the implementation is sound, this could be merged without further iteration.
