This thread is a refactoring patch series from Junio C Hamano that replaces the fixed-arity `die_for_incompatible_optN()` helper family with a single varargs `die_for_incompatible_opts()` function. The goal is purely internal API cleanup—no user-facing changes—while preserving backward compatibility. The revised v2 submission (now a single patch) addresses earlier feedback by fixing a `va_end()` omission and adopting an `EOF` sentinel, though Jeff King (Peff) still prefers a `NULL`-terminated design for better compile-time safety.

The discussion has focused on the trade-off between flexibility and type safety. Peff initially raised concerns about the varargs helper’s lack of compile-time protection, while Junio defended the `EOF` sentinel as a pragmatic choice for backward compatibility. René Scharfe has now proposed two concrete alternatives to improve safety without breaking existing callers: one combining `EOF` and `NULL` sentinels via a macro, and another using a compound literal (`struct used_option`) to enforce correct argument patterns at compile time. Both approaches preserve the series’ core objective while addressing the thread’s central tension. The conversation remains technical and collaborative, with no objections to the overall direction—just a shared interest in making the internal API as robust as possible.
