This thread is a refactoring patch series from Junio C Hamano that replaces the fixed-arity `die_for_incompatible_optN()` family with a single varargs helper, `die_for_incompatible_opts()`. The goal is purely internal API cleanup—no user-visible behavior changes—though the new helper can now handle an unbounded number of mutually exclusive command-line options.

The series is now at v2, addressing earlier feedback: the `va_end()` omission is fixed, the parameter-reordering patch is dropped, and the design uses an `EOF` sentinel to preserve existing fixed-arity signatures. The static inline wrappers for 2–4 options remain for compile-time safety, and the hard-coded error-message formatting (capped at four options) is retained to avoid breaking i18n.

Jeff King (Peff) has been the primary reviewer, engaging with two key trade-offs: compile-time safety and i18n compatibility. While he initially raised concerns about the loss of compile-time protection in the varargs helper, he now accepts the design as low-risk, given that the helper remains internal and hidden behind static inline wrappers. His latest feedback restates a preference for `LAST_ARG_MUST_BE_NULL` (a compile-time-enforced `NULL` sentinel) over the `EOF` sentinel, but this is framed as a design preference rather than a blocker. Elijah Newren’s earlier review caught the `va_end()` omission, which was fixed in v2. Junio has incorporated all feedback, and the series is now under review with no outstanding objections.

The patch touches `parse-options.c` and `parse-options.h`, with 14 built-in commands and the `revision` subsystem using the new helper through existing wrappers. No call sites change, and no new symbols are exposed beyond the varargs helper itself. The change is plumbing-only, so no new test coverage is mentioned. The only open question remains whether the compile-time safety trade-off is worth the flexibility, but consensus seems to have settled on the current design.
