Thread identity
Subject: [PATCH 0/2] Introduce die_for_incompatible_opts() helper
Series version: v1 (initial submission)
Originating author: Junio C Hamano
Thread type: patch series (refactoring)

Core problem or goal
Replace the fixed-arity `die_for_incompatible_optN()` family (N = 2, 3, 4) with a single varargs helper `die_for_incompatible_opts()` that can handle an unbounded number of mutually exclusive command-line options. The change is purely internal API refactoring; no user-visible behavior is altered.

Current status
Under review (initial version). Two patches:
1. Reorder parameters of existing `die_for_incompatible_optN()` from `(int set, const char *name)` to `(const char *name, int set)` to enable NULL sentinel in varargs.
2. Introduce `die_for_incompatible_opts()` and update all call sites; the fixed-arity helpers are now thin wrappers around the new varargs function.

Key technical details
- Files touched: `parse-options.c`, `parse-options.h`, 14 built-in commands (`add`, `clone`, `commit`, `difftool`, `gc`, `grep`, `log`, `merge-tree`, `pack-objects`, `push`, `repack`, `replay`, `rev-list`, `show-ref`), and the `revision` subsystem.
- New symbol: `die_for_incompatible_opts()` (varargs, NULL-terminated).
- Renamed symbols: none; the fixed-arity helpers remain but with reordered parameters.
- Old-vs-new behavior: identical; only the internal calling convention changes.
- On-disk format: unaffected.
- Test coverage: none mentioned; the change is plumbing-only and expected to be safe.

Open questions and loose ends
- **Memory leak in varargs usage**: Elijah Newren reports that `die_for_incompatible_opts()` calls `va_start()` but never calls `va_end()`, violating the C standard and risking undefined behavior. This is a correctness issue that must be fixed before the series can be accepted.
- **Missing compile-time protection for NULL sentinel**: Jeff King notes that the varargs function lacks compile-time enforcement of the required NULL sentinel, unlike the old fixed-arity functions. He suggests adding a `LAST_ARG_MUST_BE_NULL` annotation in the header to catch such mistakes early.
- **Hard-coded error-message formatting**: The error-message formatting in the new implementation still hard-codes the four-option case, despite using `ARRAY_SIZE()` for flexibility elsewhere. This makes it harder to change the cap later without touching multiple places.

Participant positions
- **Elijah Newren**: Substantive review identifying the `va_end()` omission. No other concerns raised; the rest of the patch (parameter reordering, error message formatting, call-site updates) is implicitly accepted.
- **Jeff King (Peff)**: Substantive review clarifying the design intent (reporting only the first four *specified* options, not all conflicting options) and identifying two mechanical improvements: the missing NULL-sentinel annotation and the hard-coded error-message formatting. Accepts the core design and implementation; feedback is actionable and low-risk.
