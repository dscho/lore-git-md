Thread identity
Subject: [PATCH 0/2] Introduce die_for_incompatible_opts() helper
Series version: v1 (initial submission, now with revised design direction and known correctness fix pending)
Originating author: Junio C Hamano
Thread type: patch series (refactoring)

Core problem or goal
Replace the fixed-arity `die_for_incompatible_optN()` family (N = 2, 3, 4) with a single varargs helper `die_for_incompatible_opts()` that can handle an unbounded number of mutually exclusive command-line options. The change is purely internal API refactoring; no user-visible behavior is altered.

Current status
Under review (initial version). The series is being revised in response to feedback:
- The first patch (parameter reordering) will be dropped.
- The varargs helper will now accept `<int, const char *>` pairs terminated by `EOF` (-1) instead of a NULL sentinel, preserving the existing fixed-arity signatures.
- The static inline wrappers for 2–4 options will be retained for compile-time safety.
- The known `va_end()` omission will be fixed in the next iteration.
- The hard-coded error-message formatting (capped at four options) remains unchanged to avoid i18n breakage.

Key technical details
- Files touched: `parse-options.c`, `parse-options.h`, 14 built-in commands (`add`, `clone`, `commit`, `difftool`, `gc`, `grep`, `log`, `merge-tree`, `pack-objects`, `push`, `repack`, `replay`, `rev-list`, `show-ref`), and the `revision` subsystem.
- New symbol: `die_for_incompatible_opts()` (varargs, EOF-terminated).
- Renamed symbols: none; the fixed-arity helpers remain with their original signatures.
- Old-vs-new behavior: identical; only the internal calling convention changes.
- On-disk format: unaffected.
- Test coverage: none mentioned; the change is plumbing-only and expected to be safe.

Open questions and loose ends
- **Memory leak in varargs usage**: `die_for_incompatible_opts()` calls `va_start()` but never calls `va_end()`, violating the C standard. Junio has acknowledged the issue and will fix it in the next iteration.
- **Sentinel choice**: The new design uses `EOF` (-1) as the sentinel instead of NULL, preserving the existing fixed-arity signatures. This resolves Jeff King’s concern about compile-time protection for the common cases (2–4 options).
- **Hard-coded error-message formatting**: The error-message formatting remains hard-coded for four options, despite the varargs helper’s flexibility. Junio defers dynamic allocation to avoid breaking i18n message templates; the cap at four is retained for now.
- **Future-proofing**: The new helper is designed to handle more than four options, but no callers currently need this capability.
