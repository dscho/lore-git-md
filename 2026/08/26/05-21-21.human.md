This is a bugfix patch from Elijah Newren that closes a long-standing safety gap in Git’s conflict resolution workflow.

For years, `git commit --amend` has been blocked during conflict resolution in merges and cherry-picks, but the same protection was never extended to `git am`, reverts, or rebases. The patch now detects when the user is in the middle of any of these operations and refuses to amend, preventing accidental overwrites of the conflicted state. The logic is careful to preserve the expected behavior for interactive rebase’s `edit`, `reword`, and `break` directives, which legitimately need `--amend`.

The implementation is straightforward for `am` and revert (just check for the presence of `REBASE_APPLY` or `REVERT_HEAD`), but the rebase merge backend required finer-grained detection: the patch looks for a `stopped-sha` file without an `amend` marker, which signals a genuine conflict stop rather than an internal squash or reword operation.

Tests cover all four conflict scenarios (`am`, revert, rebase apply backend, and rebase merge backend) plus the positive cases where amending is still allowed. The patch is small, well-explained, and addresses a real foot-gun; it looks ready for review.
