This is a refactoring patch series from Junio C Hamano that modernizes Git’s option-parsing helper functions. The existing `die_for_incompatible_optN()` family (for N = 2, 3, 4) can only check up to four mutually exclusive options. The series first reorders the arguments to make them varargs-friendly, then introduces a new `die_for_incompatible_opts()` that accepts an unbounded list of option pairs terminated by a NULL sentinel.

Patch 1/2 flips the parameter order from `(int set, const char *name)` to `(const char *name, int set)` in every caller and implementation, ensuring the new varargs function can use a NULL string as its sentinel. Patch 2/2 adds the new function and updates the same 17 files to use it where more than four options need to be checked.

The motivation is straightforward: the current limit of four options is arbitrary and forces awkward workarounds when more are needed. The change is purely internal plumbing—no user-visible behavior changes—so the risk is low. The commit messages are clear and the diffstat shows only mechanical reordering and call-site updates. If you maintain a script or tool that parses Git’s command-line options, this series is worth noting for future compatibility, but most readers can safely skip the details.
