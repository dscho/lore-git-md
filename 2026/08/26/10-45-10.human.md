This is the final patch in a four-part series improving error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The series is now merged to `next` and functionally complete.

This patch specifically addresses the `--guess-remote` option in `git worktree add`. Previously, when multiple remote branches matched the given name, the command silently fell back to creating a branch from HEAD—a behavior that could lead to unexpected results. Now, it treats this scenario as an error, aligning with the behavior of `git checkout` and `git switch`. The error message clearly states the ambiguity (e.g., "matched multiple (2) remote tracking branches") and, when advice is enabled, suggests how to resolve it.

The change is straightforward: the `dwim_branch()` function now checks for multiple matches and calls `die()` if found, after optionally emitting advice. The patch updates both the code (`builtin/worktree.c`) and documentation (`Documentation/git-worktree.adoc`, `Documentation/config/worktree.adoc`) to reflect the new behavior. Test coverage in `t/t2400-worktree-add.sh` verifies the error case and message format.

This is a usability improvement with no downsides—it prevents silent failures and makes the command’s behavior more predictable. The patch is well-motivated, clearly explained, and thoroughly tested. The only remaining loose end is a follow-up fix for the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), which was scoped separately.
