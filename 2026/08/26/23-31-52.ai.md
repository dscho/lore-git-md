This is the second patch in Junio C Hamano's two-patch refactoring series introducing `die_for_incompatible_opts()`, a varargs helper that replaces the fixed-arity `die_for_incompatible_optN()` family (N=2,3,4). The patch implements the new helper and redefines the existing fixed-arity functions as thin wrappers around it.

The implementation is straightforward: `die_for_incompatible_opts()` takes a NULL-terminated list of `(const char *name, int set)` pairs, collects the first four set options into a static array, and reports them using the same error message as before. The commit message justifies the "first four only" behavior by noting that reporting all incompatible options at once is not practically useful—users would still need to resolve conflicts iteratively, and the error message would become unwieldy.

Files touched are `parse-options.c` and `parse-options.h`; the change is purely internal API refactoring with no behavior change. The patch is mechanical, well-scoped, and safe: it touches only the option-parsing plumbing, preserves existing error messages, and does not affect on-disk formats or user-visible behavior. The motivation (removing an artificial limit on the number of mutually exclusive options) is clear and uncontroversial. No test failures or edge cases are mentioned, and the implementation is clean. The series as a whole is now complete and ready for review.
