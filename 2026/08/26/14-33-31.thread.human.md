This thread is about a small but important documentation tweak: rewording the deprecation warning that Git shows when users run a command slated for removal. The goal is to make the message clearer and more direct, so users don’t mistake a deprecation as reversible. Junio C Hamano posted the patch (now at v2) to replace the old 8-line warning with a shorter, firmer 6-line version that starts with *"this command will be removed"* instead of *"this command is nominated for removal"*—a change that Junio, Michael Montalbo, and Elijah Newren all support.

The patch is nearly ready, with just two minor editorial nits still open. Elijah Newren pointed out a missing word (*"mailing list"* instead of *"mailing"*), and Kristoffer Haugsbakk suggested adding a line explicitly stating *"The decision is final and will not be reconsidered"* to deter users from lobbying to reverse deprecations. Junio has not yet responded to either suggestion, though he did acknowledge Kristoffer’s feedback on the overall tone of the message. The patch itself is uncontroversial—it only changes the text in `usage.c`, with no functional impact—and the remaining discussion is about fine-tuning the wording to avoid ambiguity.
