This thread is a small but important documentation cleanup by Junio C Hamano, tweaking the deprecation warning users see when running a deprecated Git command. The goal is to remove language that could misleadingly suggest the project might reverse a deprecation, replacing it with a shorter, more direct message that points users to the breaking changes documentation and mailing list archives for help finding alternatives.

The patch itself is straightforward: it only changes the text of the warning in `usage.c`, with no code or behavior changes. Junio’s version is now six lines (down from eight) and uses intentional double newlines for better visual separation, a formatting choice he confirmed after Michael Montalbo raised it as a nit. The only remaining open question is whether to adopt Montalbo’s optional phrasing tweak—adding “[now?] deprecated” to the email-help line to emphasize finality—but Junio has rejected this, explaining that the message is intentionally generic to cover cases where a deprecated command might not have a direct replacement, only a new workflow.

So far, the discussion has been limited to surface-level review, with Montalbo’s feedback focusing on wording and formatting rather than technical substance. The patch remains under review, with no substantive objections or requests for changes. If no further feedback emerges, this is likely to be merged as-is.
