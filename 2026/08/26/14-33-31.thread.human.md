This thread is about a small but important documentation tweak to Git’s deprecation warning message. Junio C Hamano posted a patch (now at v2) that rewords the warning shown when users run a deprecated command, making it shorter, more direct, and clearer about the finality of deprecation. The new message replaces "this command is nominated for removal" with "this command will be removed" and guides users to the breaking changes documentation, mailing list archives, and the mailing list for help finding alternatives.

The patch is under review and has broad support for its direction. Michael Montalbo and Elijah Newren both endorsed the core changes, though Elijah flagged a minor grammatical nit (adding "list" to "mailing"). Junio clarified that the message’s generic wording—omitting explicit mention of a "replacement"—is intentional, as some deprecated commands may not have direct replacements but rather new workflows. The only unresolved feedback is Kristoffer Haugsbakk’s suggestion to add a line explicitly stating that the deprecation decision is final and won’t be reconsidered, aiming to deter users from lobbying to reverse it. This proposal aligns with the patch’s goal of eliminating ambiguity but hasn’t yet been addressed by Junio. The patch itself remains a straightforward, text-only change with no behavioral impact.
