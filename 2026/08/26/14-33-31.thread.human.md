This thread is a small but important documentation fix to the deprecation warning Git shows when users run deprecated commands. Junio Hamano posted a patch (now at v2) to reword the message in `usage.c` to make it clearer that deprecated commands *will* be removed, not just "nominated" for removal, and to guide users to the breaking changes documentation and mailing list for help finding alternatives. The new version is shorter, more direct, and avoids implying that deprecation decisions might be reversed.

The patch has converged quickly. Junio addressed Michael Montalbo’s formatting nit (double newlines) and refined the opening line to "this command will be removed," which Montalbo endorsed. The only remaining feedback is a minor grammatical tweak from Elijah Newren, who noted that the phrase *"Check what others on the mailing suggest as a replacement"* should include the word "list" for correctness. This is purely editorial—no substantive changes are needed. The patch is ready for adoption once this nit is addressed.
