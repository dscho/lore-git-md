This thread is about a small but important documentation update to the deprecation warning Git shows when users run a deprecated command. Junio Hamano, the maintainer, posted a patch to reword the message to be clearer and more direct—removing language that could mislead users into thinking deprecation decisions might be reversed. The latest version (v3) is now cooking in `next` and is essentially ready to go.

The patch shortens the warning from eight lines to six, with the key change being the opening line: it now says the command *"will be removed"* instead of *"is nominated for removal"*, reinforcing that the decision is final. The message also guides users to the breaking changes documentation, mailing list archives, and the mailing list itself for help finding alternatives. All prior feedback has been addressed, including a minor grammatical fix (adding "list" to "mailing") suggested by Elijah Newren. Junio declined a proposal from Kristoffer Haugsbakk to add an explicit line stating the decision is irreversible, arguing the current wording is already clear enough.

The patch touches only the error message in `usage.c` and updates two tests to match the new text. No behavior changes are involved—it’s purely about improving the clarity of the warning. The thread has been straightforward, with all reviews being surface-level (focused on wording and formatting rather than technical correctness). The only unresolved item from earlier versions was the grammatical nit, which has now been fixed. Junio has signaled satisfaction with the current state, and the patch is poised to graduate to `master` in the near future.
