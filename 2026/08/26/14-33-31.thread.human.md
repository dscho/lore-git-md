This thread is about a small but important documentation update to the deprecation warning message shown when users run a deprecated Git command. Junio C Hamano posted a patch (now at v2) to reword the message in `usage.c` to be shorter, clearer, and less ambiguous about whether a deprecation decision might be reversed. The new version replaces "this command is nominated for removal" with "this command will be removed" to reinforce finality, and it guides users to the breaking changes documentation, mailing list archives, and the mailing list for help finding alternatives.

The patch is under review and has already incorporated feedback from Michael Montalbo and Elijah Newren, who endorsed the refinements to the opening line and formatting. Junio has signaled satisfaction with the current wording but left two minor editorial suggestions unresolved: Elijah’s grammatical nit (adding "list" to "mailing") and Kristoffer Haugsbakk’s proposal to add a line explicitly stating the deprecation decision is final. Junio has now addressed Kristoffer’s suggestion by pushing back on its necessity, arguing that the current message’s focus on helping users find replacements already implies irreversibility. While he doesn’t outright reject the idea, his response makes it clear he won’t adopt the additional line, effectively closing the last open question in the thread.

All substantive feedback has been resolved, and the patch is now cooking in `next`. The discussion has narrowed to a philosophical difference about how explicit the message should be about the finality of deprecations, with Junio favoring brevity and Kristoffer citing real-world cases where users have misinterpreted warnings as invitations to lobby for reinstatement. The update remains a purely textual change with no behavior impact.
