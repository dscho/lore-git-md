Thread identity: bugfix patch series (3 patches) by Elijah Newren via GitGitGadget, targeting the merge machinery to prevent unsafe commit operations (`git commit --amend` and `git commit <paths>`) during conflict resolution for `git am`, `git revert`, and all forms of `git rebase`.

Core problem or goal: extend Git's existing protection against unsafe commit operations during conflict resolution to cover both `git commit --amend` and `git commit <paths>`, preventing users from accidentally amending the wrong commit or updating individual paths during conflict resolution, which can corrupt repository state. The fix distinguishes between genuine conflict stops and internal `--amend` usage by interactive rebase (e.g., `squash`, `reword`, `edit`, `break`). Conflict resolution must record the entire tree state on top of the current HEAD, never updating individual paths.

Current status: patch series v2 is ready for integration, incorporating all feedback from Junio C Hamano and Phillip Wood. The series is split into three logical patches: (1) rewording rebase error messages for clarity to avoid misleading users about when restrictions apply (now explicitly referencing "empty commits"), (2) extending protection against `git commit --amend` to `git am`, `git revert`, and rebase conflict stops while preserving interactive rebase directives, and (3) extending protection to `git commit <paths>`. The core logic is consolidated into a new helper function, `sequencer_ongoing_operation()`, in `sequencer.c`. Junio endorsed the series as correct and well-reasoned, and Phillip Wood acknowledged its maintainability improvements. No merge status recorded; the series remains under final review.

Key technical details:
- Files touched: `builtin/commit.c`, `sequencer.c`, `sequencer.h`, and test coverage in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh`.
- New behavior: blocks both `git commit --amend` and `git commit <paths>` during conflict resolution for `git am`, `git revert`, and all `git rebase` variants, except for interactive rebase directives (`squash`, `reword`, `edit`, `break`, `fixup`) that explicitly require `--amend`. Error messages now clarify that restrictions apply specifically when resolving a commit that became empty, not during rebase in general.
