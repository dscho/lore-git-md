Thread identity: bugfix patch series (3 patches) by Elijah Newren via GitGitGadget, targeting the merge machinery to prevent unsafe commit operations (`git commit --amend` and `git commit <paths>`) during conflict resolution for `git am`, `git revert`, and all forms of `git rebase`.

Core problem or goal: extend Git's existing protection against unsafe commit operations during conflict resolution to cover both `git commit --amend` and `git commit <paths>`, preventing users from accidentally amending the wrong commit or updating individual paths during conflict resolution, which can corrupt repository state. The fix must reliably distinguish between genuine conflict stops (where amending or partial commits would corrupt state) and internal `--amend` usage by interactive rebase directives (`squash`, `reword`, `edit`, `break`). Junio C Hamano has confirmed that the series' core logic (`whence == FROM_REBASE_PICK`) is technically sound for identifying rebase stops caused by empty commits, as `sequencer_determine_whence()` only sets this value when the rebase-head and cherry-pick-head are identical (indicating an empty-pick situation). However, Junio has now raised a **substantive technical question** about the necessity of blocking `git commit <paths>` during conflict resolution for empty commits, noting that the result would still be an empty commit and questioning whether the restriction is justified.
