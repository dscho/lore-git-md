Thread identity: bugfix patch series (3 patches) by Elijah Newren via GitGitGadget, targeting the merge machinery to prevent unsafe commit operations (`git commit --amend` and `git commit <paths>`) during conflict resolution for `git am`, `git revert`, and all forms of `git rebase`.

Core problem or goal: extend Git's existing protection against unsafe commit operations during conflict resolution to cover both `git commit --amend` and `git commit <paths>`, preventing users from accidentally amending the wrong commit or updating individual paths during conflict resolution, which can corrupt repository state. The fix distinguishes between genuine conflict stops (where amending or partial commits would corrupt state) and internal `--amend` usage by interactive rebase directives (`squash`, `reword`, `edit`, `break`). Conflict resolution must record the entire tree state on top of the current HEAD, never updating individual paths.

Current status: patch series v2 is ready for integration, incorporating all feedback from Junio C Hamano and Phillip Wood. The series is split into three logical patches: (1) rewording rebase error messages for clarity to avoid misleading users about when restrictions apply (now explicitly referencing "empty commits"), (2) extending protection against `git commit --amend` to `git am`, `git revert`, and rebase conflict stops while preserving interactive rebase directives, and (3) extending protection to `git commit <paths>` (final patch). The core logic is consolidated into a new helper function, `sequencer_ongoing_operation()`, in `sequencer.c`. Junio endorsed the series as correct and well-reasoned, and Phillip Wood acknowledged its maintainability improvements. In the latest review, Phillip Wood raised a **substantive maintainability concern**: the new `sequencer_ongoing_operation()` helper hardcodes paths (`rebase-merge/stopped-sha` and `rebase-merge/amend`) that are already abstracted by existing helpers (`rebase_path_stopped_sha()` and `rebase_path_amend()`). Adopting these helpers would eliminate redundancy and align the new code with established patterns in the sequencer subsystem. Elijah is expected to address this in v3 or as a follow-up. Phillip Wood's final review reply confirms the third patch is ready for integration, calling it a "good idea" and stating "the changes look good too." The series remains under final review, with no merge status recorded.

- New behavior: blocks both `git commit --amend` and `git commit <paths>` during conflict resolution for `git am`, `git revert`, and all `git rebase` variants, except for interactive rebase directives (`squash`, `reword`, `edit`, `break`, `fixup`) that explicitly require `--amend`.
