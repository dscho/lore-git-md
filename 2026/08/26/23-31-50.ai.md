This is a refactoring series introducing a new `die_for_incompatible_opts()` helper to handle an unbounded number of mutually exclusive command-line options, replacing the existing fixed-arity `die_for_incompatible_optN()` family (for N=2,3,4). The series is authored by Junio C Hamano and consists of two patches.

The first patch reorders the parameters of the existing `die_for_incompatible_optN()` functions from `(int set, const char *name)` to `(const char *name, int set)`. This preparatory change makes it possible to use a NULL sentinel to terminate a varargs list in the new helper, since there is no clear sentinel value for an `int`. The patch touches 14 built-in commands (`add`, `clone`, `commit`, `difftool`, `gc`, `grep`, `log`, `merge-tree`, `pack-objects`, `push`, `repack`, `replay`, `rev-list`, `show-ref`) and the `parse-options` and `revision` subsystems, updating all call sites to match the new parameter order.

The second patch introduces `die_for_incompatible_opts()`, a varargs function that accepts any number of `(const char *name, int set)` pairs terminated by NULL. The implementation is a straightforward loop over the argument list, checking for conflicts and calling `error()` and `usage()` as before. The commit message notes that while the first patch could have been avoided by keeping the old parameter order in the fixed-arity helpers, consistency across the API is preferable.

The series is mechanical and well-scoped: it does not change behavior, only the internal API shape. The motivation is clear (removing an artificial limit on the number of mutually exclusive options) and the implementation is clean (varargs with a sentinel). No test failures or edge cases are mentioned, suggesting the change is safe. The files touched (`parse-options.c`, `parse-options.h`, and the built-in commands) are all part of the option-parsing plumbing, so the risk of unintended side effects is low.
