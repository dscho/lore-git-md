This is a documentation patch refining the deprecation warning message shown when users invoke a deprecated Git command. It’s the second iteration of a patch originally posted by Junio C Hamano, the project maintainer, and follows up on minor wording and formatting feedback from Michael Montalbo.

The patch replaces the existing eight-line message with a shorter, six-line version that removes any suggestion that the Git project might reconsider removing the command. The new text opens with “this command will be removed soon” instead of “is nominated for removal,” reinforcing the finality of the deprecation. It also tightens the guidance: users are now directed to the breaking changes documentation and mailing-list archives for replacement suggestions, and told to email the list only if those suggestions don’t work. Double newlines after the two main links improve visual separation in the terminal.

No code behavior changes; the patch modifies only the string in `usage.c`’s `you_still_use_that()` function. Junio has already addressed the formatting nit raised in the first round, and the only remaining open question is whether to adopt his proposed refinement to the opening line (“will be removed” instead of “is nominated for removal”), which he argues better conveys irreversibility. Michael Montalbo’s earlier phrasing tweak to the email-help line remains unresolved but is uncontroversial and optional.

The patch is narrowly scoped, well-motivated, and unlikely to generate further debate. It’s ready for Junio to merge once he finalizes the opening line.
