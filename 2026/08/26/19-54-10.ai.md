This is a CI/build system patch, specifically a maintainer's review of Harald Nordgren's proposal to cancel stale GitHub Actions workflow runs for pull requests.

Junio C Hamano reviews the patch after it sat unreviewed for some time. He walks through the proposed change line-by-line, confirming the intended behavior: for pull requests, workflow runs are now grouped by pull request number (not commit hash) and stale runs are canceled when a new push occurs. For non-pull-request events, the group remains commit-based and no cancellation occurs.

The review is substantive but cautious. Junio identifies a potential edge case: if multiple workflows sharing the same concurrency group are triggered simultaneously for the same commit, the new grouping might cause some workflows to be skipped entirely. He asks for this concern to be either verified or explicitly addressed in the commit message. Otherwise, he sees no regression for non-pull-request events and endorses the pull-request-specific cancellation as a clear improvement.

No code changes are suggested yet; the ball is back in the author's court to clarify the edge case or adjust the commit message. The patch remains under review, not yet queued in any integration branch.
