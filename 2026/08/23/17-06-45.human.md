This is a brief but substantive review comment in the ongoing thread about adding Unicode box-drawing characters to `git repo structure`. Tuomas Ahola points out that the email client *mutt*—one of the examples Oswald Buddenhagen cited as proof that Unicode box-drawing characters are widely supported—actually falls back to the terminal’s **alternative character set (ACS)** when UTF-8 is unavailable. ACS is a legacy mechanism (part of terminfo) that maps box-drawing glyphs to ASCII approximations like `+` and `-` on terminals that lack Unicode support. The implication is that mutt’s apparent success with box-drawing characters may owe more to ACS fallback than to universal UTF-8 compatibility, which could weaken the argument that Unicode rendering is reliably portable across all terminals. This observation adds nuance to the earlier discussion and may inform how the feature should be implemented—particularly whether Git should adopt a similar fallback strategy or rely solely on locale detection. The comment is narrowly scoped and does not address the maintainer’s requirement for an opt-out configuration option, but it does provide a concrete data point for evaluating the technical feasibility of the proposed feature.
