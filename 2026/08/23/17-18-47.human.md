This is the third patch in Michael Montalbo’s **14-patch RFC series** introducing `git organize`, a new command designed to systematically restructure Git’s source tree by moving files into subsystem-specific directories (e.g., `odb/`, `refs/`) based on rules recorded in a `.gitorganize` file. This patch adds the `--exit-code` option to `git organize status`, allowing the command to fail (exit non-zero) when the tree drifts from the declared layout. This is a **feature enhancement** for the `git organize` command, enabling CI/CD pipelines or scripts to gate on the tree’s reconciliation status.

The change is small and focused: it modifies `builtin/organize.c` to pass an `exit_code` flag to `organize_status()`, which now returns 1 if any file is out of place, unrecorded, or missing, and 0 otherwise. The documentation (`git-organize.adoc`) and test suite (`t/t0096-organize.sh`) are updated to reflect the new behavior. The patch is well-motivated: the commit message clearly explains why a non-zero exit code is useful (e.g., for gating checks), and the implementation is straightforward. The test coverage is thorough, verifying that `--exit-code` behaves as expected for all drift scenarios (out-of-place files, unrecorded files, missing paths) while ignoring a standing backlog (which is not considered drift).

This patch is part of the broader `git organize` effort, which aims to externalize file placement decisions into a tracked configuration file, making structural changes auditable and reversible. The `--exit-code` option is a practical addition that aligns with the tool’s goal of enabling automated enforcement of layout rules. The patch itself is uncontroversial and appears ready for review, though the larger series (and the demonstrated reorganization of Git’s codebase) is still under initial discussion. If the series gains traction, this feature will be a key enabler for CI integration.
