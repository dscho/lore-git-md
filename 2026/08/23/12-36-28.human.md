This is a focused follow-up in the ongoing thread about Git's global config file handling. The author of the original patch series, Delilah Ashley Wu, has just sent a v2 that fixes the inconsistency where `git config list --global` only read from `$HOME/.gitconfig` despite Git actually using both that and `$XDG_CONFIG_HOME/git/config`. The series is technically complete, addresses all prior feedback, and has Johannes Schindelin's Reviewed-by tags.

Chris Torek's question is narrow but important: when you run `git config --global --edit`, which file does Git open for editing, and which file *should* it open? The current implementation (and the v2 patch series) does not change the edit behavior—it still opens only `$HOME/.gitconfig`—but Torek is asking whether that is the right long-term choice. This is not a review of the patch series itself, but a design question that could lead to a follow-up patch if the answer is "both files" or "the XDG file". The question is well-timed because the series has just clarified the read path; the write path is now the obvious next point of discussion.
