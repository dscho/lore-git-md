This is the third patch in Michael Montalbo’s **14-patch RFC series** introducing `git organize`, a new command designed to restructure Git’s source tree by moving files into subsystem-specific directories (e.g., `odb/`, `refs/`) based on rules recorded in a `.gitorganize` file. This patch adds the `--exit-code` option to `git organize status`, allowing the command to return a non-zero exit code when the tree is out of sync with the declared layout (e.g., files are misplaced, unrecorded, or missing). The change is small (34 lines added across documentation, implementation, and tests) and does not alter the command’s output or behavior beyond the exit code.

The motivation is clear: projects that want to enforce a consistent layout (e.g., via CI or pre-commit hooks) need a way to programmatically detect drift. The patch distinguishes between *backlog* (files with labels but no matching rule) and *drift* (files that are misplaced, unrecorded, or missing), ensuring that only the latter triggers a failure. This aligns with the series’ goal of making tree reorganization auditable and repeatable.

The implementation is straightforward. The `organize_status()` function now takes an `exit_code` flag and returns `1` if any drift is detected. The test suite expands to verify the new behavior, including edge cases like shared basenames and missing files. The documentation updates are minimal but precise, clarifying that `--exit-code` does not affect output.

This patch is a **well-scoped, low-risk addition** to the series. It addresses a practical need (CI/gating) without complicating the core workflow, and the tests cover the key scenarios. The only potential point of discussion might be whether the exit code should also fail for backlog files (the current design does not), but the commit message justifies this choice clearly. The patch looks ready for review and is unlikely to be controversial.
