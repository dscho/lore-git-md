This is an RFC proposing a new configuration knob to make Git's stash stack per-worktree rather than global. The motivation is a real-world problem: when multiple worktrees (or AI coding agents) share the same repository, their stashes collide silently, leading to data loss or unintended cross-worktree changes. The author, Vladimir Sitnikov, documents this as a growing issue reported by users of tools like GitHub Copilot CLI and Stably Orca.

The proposal is pragmatic: introduce a `stash.ref` config key that defaults to `refs/stash` but can be set to a per-worktree ref (e.g., `refs/worktree/stash`). This leverages existing Git machinery—per-worktree refs, `extensions.worktreeConfig`, and the `stash export/import` commands—without breaking backward compatibility. The author explicitly rejects more disruptive alternatives like making stashes per-worktree by default or inventing a new naming scheme.

The email is well-structured, with clear examples of the problem, a concise proposal, and thoughtful consideration of trade-offs (e.g., reachability under `refs/worktree/`). It’s aimed at soliciting early feedback on design choices (config key naming, visibility of other worktrees’ stashes, GC safety) before coding begins. This looks like a serious, well-motivated effort to address a real pain point, and the approach seems technically sound. Worth watching for reviewers’ reactions to the config key and GC implications.
