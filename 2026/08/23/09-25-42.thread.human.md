This thread is about a documentation patch to `gitk`'s `README.md` that adds a warning discouraging AI-generated contributions, aligning with Git's upstream policy. The patch itself is simple—just a few lines clarifying the project's stance—but the discussion has taken a turn toward broader policy questions.

Johannes Sixt proposed the patch to make `gitk`'s policy explicit, citing the Developer Certificate of Origin (DCO) and prior discussions with brian m. carlson about provenance concerns. So far, there’s been no technical pushback, but Weijie Yuan has raised a substantive policy question: *Should Git distinguish between AI-"generated" and AI-"assisted" work?* They note that Johannes Schindelin has used `Assisted-by:` trailers in commits without objection, suggesting some AI involvement is already tolerated. Weijie contrasts this with the Linux kernel’s approach, which allows AI assistance if disclosed, and asks whether Git should adopt a similar model rather than an outright discouragement.

The thread is now at a crossroads: the original patch is uncontroversial in its wording, but the underlying policy may need refinement. No decisions have been made yet, and the discussion is still open to input from maintainers and other contributors. If the project moves toward a disclosure-based policy, the patch may need revisiting to reflect that shift. For now, the patch remains under review, with the policy debate as the main open question.
