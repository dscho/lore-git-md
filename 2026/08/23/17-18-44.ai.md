This is an **RFC feature proposal** introducing `git organize`, a new command designed to restructure Git's source tree by moving files into subsystem-specific directories (e.g., `odb/`, `refs/`, `pack/`) based on recorded placement rules. The series is **14 patches long** and includes both the tool itself and a demonstration of its use to reorganize Git's own codebase.

The core idea is to externalize file placement decisions into a tracked `.gitorganize` file, which defines *scope* (which files are governed), *layout* (rules mapping labels to directories), and *labels* (metadata about each file, such as its component and role). The tool provides two main workflows:
1. **Recording labels**: `git organize apply --labels-only` populates the `[labels]` section by running a project-specific *labeler* script (here, one that mines commit messages for "area:" prefixes and analyzes `#include` coupling and co-change patterns).
2. **Applying moves**: `git organize apply` moves files to their designated directories, updates references (e.g., `#include` lines, build system entries), and stages the changes. The tool delegates reference updates to a project-specific *organizer* script, which can veto moves it cannot handle.

The series demonstrates the tool by carving out eight subsystems (`odb`, `refs`, `pack`, `diff`, `revision`, `index`, `setup`, `transport`), each as a separate commit. These commits are self-contained: they move files, update references, and leave the tree buildable. The author emphasizes that the placement rules are *project-specific* and open to debate—this series is a concrete proposal, not a final layout.

Key technical details for follow-up discussion:
- The `.gitorganize` file format (INI-style with `[scope]`, `[layout]`, and `[labels]` sections).
- The `contrib/organize/labeler` script, which uses `git log --follow` to mine commit prefixes and a static `git-layout.map` to consolidate them into components.
- The `contrib/organize/organizer` script, which handles reference updates (e.g., `#include` rewrites, Makefile/Meson adjustments).
- The `organize/` directory, which holds the tool's implementation (`gitorganize-format.c`, `organize.c`, etc.).
- The test script `t/t0096-organize.sh`, which covers basic functionality.

The series touches **609 files** (mostly moves) and adds **6.9k lines**, but the net churn is lower due to the high percentage of renames. The tool is designed to be opt-in: projects can adopt it incrementally, and individual carve-outs (e.g., moving `odb/` files) can be merged independently of the tool itself. The author notes that the same tool could later be used to nest subsystems under `lib/` (e.g., `lib/odb/`), aligning with Patrick Steinhardt's `libgit.a` series.
