This thread is about an RFC patch from Vladimir Sitnikov proposing a new `stash.ref` configuration knob to make Git's stash stack per-worktree rather than global. The goal is to prevent silent interference between worktrees—particularly problematic for automated agents like AI tools—where stash operations in one worktree can unintentionally affect another. The discussion has evolved from debating *how* to implement this change to questioning *whether* it’s necessary at all.

Key participants include Vladimir, who argues the change is needed to prevent data loss, and Kristoffer Haugsbakk, who is skeptical, suggesting that automated agents could avoid the stash or block `git stash` commands instead. The most significant development is Phillip Wood’s recent review, which challenges the RFC’s premise and proposes an alternative: associating stashes with the branch they were created on and adding an option to `git stash pop` to only apply stashes from the current branch. This approach avoids introducing new configuration and aligns better with Git’s existing patterns. The thread is now focused on evaluating this alternative, with no decisions or merges yet. The discussion remains open, and the eventual solution—if any—will likely be shaped by whether the community finds Phillip’s proposal more compelling than the original `stash.ref` knob.
