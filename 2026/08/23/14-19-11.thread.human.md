This thread is an RFC discussion about preventing silent interference between Git stashes in different worktrees, which can lead to data loss or unintended changes. Vladimir Sitnikov initially proposed a `stash.ref` configuration knob to isolate stashes per worktree, but the conversation has shifted toward a branch-aware design suggested by Phillip Wood. This approach associates stashes with the branch they were created on by leveraging existing stash message metadata, avoiding new configuration or ref namespaces.

The branch-aware design is now technically feasible and addresses most of the original problem, since Git prevents checking out the same branch in multiple worktrees. However, Vladimir highlights a gap: detached HEAD worktrees (common in automated workflows) all record stashes with the same "(no branch)" label, which would group them together rather than isolating them per worktree. He suggests a hybrid approach where users could configure the scope—shared ref, per-branch, or per-worktree—to accommodate both branch-aware and worktree-aware use cases. The discussion remains open, with no clear consensus on whether the solution should prioritize branch-awareness, worktree-awareness, or a configurable hybrid.

Key participants include Vladimir (the author), Kristoffer Haugsbakk (skeptical of the proposal’s necessity), Phillip Wood (proposed the branch-aware design), and Junio C Hamano (refined the design and resolved parsing concerns). The thread is still in the RFC stage, with focus on refining the user interface and addressing edge cases like detached HEAD states and branch renames. No implementation has been posted yet, and the maintainers have not signaled a preferred direction.
