This thread began as an RFC by Vladimir Sitnikov proposing a new `stash.ref` configuration knob to make Git's stash stack per-worktree rather than global, aiming to prevent silent interference between worktrees (or AI coding agents) sharing a repository. The discussion has since shifted toward a branch-aware stash design, which associates stashes with the branch they were created on and enables branch-filtered operations like `git stash pop --current-branch`.

The branch-aware approach, now the focus of the thread, avoids introducing new configuration by leveraging existing Git machinery. Phillip Wood and Junio C Hamano clarified that Git already encodes branch information in stash messages (e.g., `"On $branch: "`), making the design technically feasible without breaking backward compatibility. Key open questions remain about the user interface (e.g., whether `git stash pop` should default to the current branch or require an explicit flag) and edge cases like detached HEAD or branch renames. Kristoffer Haugsbakk remains skeptical of the necessity of any change, arguing the current behavior can be useful for humans and that automated agents could avoid the stash entirely.

No major technical blockers have been identified, and the original `stash.ref` proposal is effectively superseded unless the branch-aware design encounters unforeseen issues. The thread is now centered on refining the implementation details of the branch-aware approach.
