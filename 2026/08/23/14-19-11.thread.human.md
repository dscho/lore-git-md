This thread proposes a new Git configuration option, `stash.ref`, to make the stash stack per-worktree instead of global. The issue is increasingly relevant as tools like AI coding agents and parallel worktrees become more common—currently, stash operations in one worktree can silently interfere with another, risking data loss. Vladimir Sitnikov, the author, presents a clear reproduction case and real-world bug reports from tools like GitHub Copilot CLI to motivate the change.

The design is pragmatic and backward-compatible: `stash.ref` would default to `refs/stash` but could be set to a per-worktree ref (e.g., `refs/worktree/stash`), leveraging existing Git machinery like `extensions.worktreeConfig`. The author explicitly avoids more disruptive alternatives, such as making the stash per-worktree by default or introducing named stashes. Key open questions include whether the config value should enforce valid ref names and whether `git stash list` should gain a `--all` flag to show stashes across all worktrees. There’s also a potential concern about the reachability of stash entries under `refs/worktree/*` for `gc` and `fsck`.

The proposal is well-structured and addresses a growing pain point without breaking changes. If the discussion resolves the edge cases, this could be a strong candidate for inclusion. No reviews or decisions have been posted yet—this is the first email in the thread.
