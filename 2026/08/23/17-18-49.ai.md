This is the fifth patch in Michael Montalbo’s 14-patch RFC series introducing `git organize`, a new command for restructuring Git’s source tree. It adds the `.gitorganize` configuration file that defines which files are in scope and how they should be laid out.

The file declares that all `.c` and `.h` files at the root are governed by the tool. It then maps two roles—`public` (interface headers) and `program` (standalone executables)—to stay at the root, while each of the thirteen components (`odb`, `refs`, `pack`, etc.) is routed to a directory of its own. This patch is purely declarative; the labels that assign each file to a component and role come in the next patch, and the actual moves are implemented in later patches.

The configuration is Git-specific and open to debate, but the patch itself is straightforward: it creates the file, adds no new code, and touches no other part of the tree. The `.gitorganize` format is INI-style with `[scope]` and `[layout]` sections, matching the design described in the cover letter.
