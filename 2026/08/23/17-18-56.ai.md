This is the twelfth patch in Michael Montalbo’s **14-patch RFC series** introducing `git organize`, a tool designed to restructure Git’s source tree by moving files into subsystem-specific directories. This patch gathers the **index subsystem** (20 C sources and 24 headers) into a new `index/` directory, updating all references—`#include` directives, build system entries (Makefile and meson.build), and documentation examples—to reflect the new paths.

The patch is **mechanical and self-contained**: it moves files as renames (95–100% similarity), updates every reference it can find, and leaves the tree buildable. The `.gitorganize` file is updated to reflect the new layout, relocating the index-related labels from the root to `index/`. The net line churn is zero, confirming the patch’s mechanical nature.

Key files touched:
- **`index/` directory**: 44 files moved here (e.g., `cache-tree.c` → `index/cache-tree.c`, `read-cache.c` → `index/read-cache.c`).
- **Build system**: Makefile and meson.build updated to point to the new paths (e.g., `LIB_OBJS += index/read-cache.o`).
- **Documentation**: `Documentation/MyFirstContribution.adoc` updated to reference `index/wt-status.h`.
- **`#include` directives**: 144 files across the codebase updated (e.g., `#include "read-cache.h"` → `#include "index/read-cache.h"`).

The patch demonstrates the `git organize` tool’s ability to handle **cross-subsystem dependencies**: the index subsystem is heavily referenced by other subsystems (e.g., diff, transport, revision), and the organizer script successfully updates all `#include` paths. The move also highlights the tool’s **atomicity guarantees**: the patch is a single commit that leaves the tree in a buildable state.

This patch is part of the **demonstration phase** of the series (patches 7–11 moved ODB, refs, pack, diff, and revision subsystems; this patch moves index). The remaining patches (13–14) will move the setup and transport subsystems. The series remains under review, with no substantive feedback yet. Reviewers may focus on:
- **Completeness of reference updates**: Whether all `#include` paths, build system entries, and documentation references were caught (e.g., test fixtures, scripts, or external tools like Git for Windows).
- **Subsystem boundaries**: Whether `index/` is the right name/location for these files, or if they should be nested under `lib/` (aligning with Patrick Steinhardt’s `libgit.a` series).
- **Performance impact**: The index subsystem is central to Git’s operation; reviewers may request benchmarks to ensure the move doesn’t introduce overhead.
- **Backward compatibility**: Whether the move breaks external tools or forks (e.g., libgit2, Git for Windows) that rely on the old paths.
