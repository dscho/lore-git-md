This is the final patch in Delilah Ashley Wu’s three-part series fixing Git’s inconsistent `--global` config handling. The patch makes `git config list --global` and `git config get --global` read from both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`, matching the documented behavior and the way unscoped config commands already work.

The implementation reuses `do_git_config_sequence()`—the function that reads all config scopes—by adding `ignore_system`, `ignore_repo`, `ignore_worktree`, and `ignore_cmdline` flags to restrict it to the global scope. This avoids duplicating the logic that already handles both global config files. The patch also updates tests in `t1300-config.sh` and `t1306-xdg-files.sh` to verify that both files are respected and that error handling works as expected: `--global` now fails only if *both* files are unreadable, while unscoped commands continue to succeed as long as at least one file is readable.
