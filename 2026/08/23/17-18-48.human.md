This is the fourth patch in Michael Montalbo’s **14-patch RFC series** introducing `git organize`, a new command designed to restructure Git’s source tree by moving files into subsystem-specific directories (e.g., `odb/`, `refs/`) based on recorded placement rules in a `.gitorganize` file. This patch adds the `--label` selector to `git organize status` and `git organize apply`, enabling users to reconcile one group of files at a time (e.g., only files labeled `component=odb`).

The change is **narrow and well-scoped**: it extends the existing `organize_plan_build()` function to accept a list of label selectors, filters the moves to only those files matching any selector, and updates the command-line interface to expose the new option. The documentation is thorough, explaining how selectors work (bare keys vs. key-value pairs), their repeatability, and their interaction with other options like `--exit-code`. Tests cover edge cases like shared basenames, missing files, and the distinction between backlog and drift, ensuring the selector logic is robust.

This patch is **clearly motivated** by the need to make large reorganizations reviewable in smaller, incremental steps. The implementation is clean, with no behavioral changes to the core functionality—just a new filtering mechanism. The test coverage is particularly strong, including cases for C-quoted paths and malformed input, which suggests the author has thought carefully about edge cases. If the broader `git organize` proposal gains traction, this feature will be essential for practical adoption. For now, it’s a **well-crafted incremental improvement** that doesn’t introduce controversy or technical debt.
