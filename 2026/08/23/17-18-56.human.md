This is the **twelfth patch in Michael Montalbo's 14-patch RFC series** introducing `git organize`, a tool for restructuring Git's source tree. This patch moves the **index subsystem** (20 C sources and 24 headers) into a new `index/` directory, updating all references—`#include` directives, build system entries (Makefile and meson.build), and documentation examples—to reflect the new paths.

The patch is **mechanical and self-contained**: it moves files as renames (preserving 95-100% similarity) and updates every reference to their old paths. The net line churn is zero, confirming the changes are purely structural. The `.gitorganize` file is updated to reflect the new layout, moving the index-related entries from the root to the `index/` section. The patch leaves the tree buildable and passes the existing test suite, which serves as a regression check for the move.

This is part of the **demonstration phase** of the series, showing how `git organize` can be used to carve out subsystems incrementally. The index subsystem is the sixth such carve-out (after ODB, refs, pack, diff, and revision), and the patch follows the same pattern: move files, update references, and rely on the existing test suite to validate correctness. The patch does not introduce new functionality or symbols, but it does touch **188 files**, making it one of the larger moves in the series.

The patch is **well-structured and low-risk**: the mechanical nature of the changes and the use of the existing test suite as a safety net make it unlikely to introduce bugs. However, reviewers may scrutinize the completeness of the reference updates (e.g., whether all `#include` paths, build system entries, and documentation examples were caught) and the alignment with other ongoing efforts (e.g., Patrick Steinhardt's `libgit.a` series, which might prefer `lib/index/` over `index/`). The patch is also a good candidate for incremental merging, as it is independent of the `git organize` tool itself.
