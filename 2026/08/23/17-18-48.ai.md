This is the fourth patch in Michael Montalbo’s **14-patch RFC series** introducing `git organize`, a new command designed to restructure Git’s source tree by moving files into subsystem-specific directories (e.g., `odb/`, `refs/`) based on recorded placement rules in a `.gitorganize` file. This patch adds the `--label` selector to `git organize status` and `git organize apply`, enabling users to reconcile one component or label group at a time rather than acting on all out-of-place files at once.

The patch extends the existing `organize_plan_build()` function to accept a `strvec` of label selectors, filters moves to only those files whose labels match any selector, and updates the command-line interface and documentation accordingly. A selector can be a bare key (matching any value) or a `key=value` pair (matching exactly). The test suite expands to cover edge cases like shared basenames, quoted paths, and malformed reject lines, ensuring the selector logic is robust.

This is a **feature enhancement** to the `git organize` command, not a standalone feature. It directly supports the series’ goal of enabling incremental, reviewable carve-outs of large layouts (e.g., moving the `odb` component first, then `refs`). The change is opt-in and backward-compatible: omitting `--label` retains the original behavior of acting on all out-of-place files. The patch is well-scoped, with clear test coverage and a straightforward implementation that builds on the existing label infrastructure. It looks like a sensible, low-risk addition that addresses a practical workflow need.
