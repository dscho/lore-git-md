Thread identity: RFC proposing a new `stash.ref` configuration knob to make Git's stash stack per-worktree rather than global. Originating author: Vladimir Sitnikov. Thread type: RFC patch series (single patch).

Core problem or goal: Address the pain point where multiple worktrees (or AI coding agents) sharing a repository experience silent interference in stash operations, leading to data loss or unintended cross-worktree changes. The goal is to introduce a configurable per-worktree stash ref while preserving backward compatibility.

Current status: RFC stage; no prior versions. The proposal is under initial discussion, with key technical details and open questions raised but no decisions or merges yet.

Key technical details:
- New config key: `stash.ref`, defaulting to `refs/stash` but configurable to per-worktree refs (e.g., `refs/worktree/stash`).
- Subsystems touched: stash subcommands (`push`, `pop`, `list`, etc.), refs backend, and potentially `gc`/`fsck` for reachability.
- No new CLI options or on-disk format changes, but a potential `--all` flag for `git stash list` is proposed.
- Leverages existing Git machinery: `refs/worktree/*`, `extensions.worktreeConfig`, and `git config --worktree`.

Open questions and loose ends:
1. Should `stash.ref` config values be restricted to valid ref names?
2. Should `git stash list` gain a `--all` flag to show stashes from all worktrees?
3. Reachability of stash entries under `refs/worktree/*` for `gc` and `fsck`.
4. No substantive reviews or objections yet; discussion is in early stages.

Participant positions: Only the author (Vladimir Sitnikov) has contributed so far. No reviews, acks, or objections recorded.

Related work: None mentioned in the thread. The proposal is self-contained and does not depend on other in-flight efforts.
