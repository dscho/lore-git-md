This is the **first patch in a 14-patch RFC series** introducing `git organize`, a new command designed to restructure Git's source tree by moving files into subsystem-specific directories (e.g., `odb/`, `refs/`) based on rules defined in a `.gitorganize` configuration file. This patch implements the core command and its two subcommands: `status` (reporting misplaced files) and `apply` (moving files and updating references).

The patch adds the `git-organize` builtin, which parses the `.gitorganize` file (an INI-style config with `[scope]`, `[layout]`, and `[labels]` sections) and reconciles the working tree against the declared layout. The `status` subcommand identifies files that need to be moved, while `apply` performs the moves as content-identical renames (preserving `git log --follow` and `git blame` history) and updates the `.gitorganize` file to reflect the new paths. The implementation includes:
- **New files**: `builtin/organize.c` (command logic), `organize/gitorganize-format.c` (parser/writer for `.gitorganize`), `organize/organize.h` (engine API), and `Documentation/git-organize.adoc` (man page).
- **Key symbols**: `git organize` command, subcommands `status` and `apply`, and the `.gitorganize` file format (with `label:value = directory` rules).
- **Behavior**: The tool operates as a single `git apply --index` transaction to ensure atomicity, requires a clean worktree, and stages changes without committing them. It delegates label assignment and reference updates to external scripts (introduced in later patches).
- **Test coverage**: Basic functionality is verified in `t/t0096-organize.sh`, including move detection, backlog reporting, and error handling for malformed `.gitorganize` files.

The patch is **well-structured and self-contained**, with clear commit messages and thorough documentation. It lays the groundwork for the series' goal of enabling auditable, reversible source tree reorganizations, though the actual file moves (demonstrated in later patches) and the project-specific layout rules (e.g., `odb/`, `refs/`) remain open for discussion. The design prioritizes safety (e.g., atomic transactions, clean worktree requirement) and flexibility (e.g., external scripts for label assignment). Likely points of contention include the `.gitorganize` file format, the tool's generality for other projects, and its interaction with ongoing efforts like Patrick Steinhardt's `libgit.a` series.
