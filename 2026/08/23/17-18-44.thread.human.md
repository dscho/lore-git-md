This thread is an RFC proposal for `git organize`, a new command designed to restructure Git's source tree by moving files into subsystem-specific directories (like `odb/` or `refs/`) based on rules defined in a `.gitorganize` configuration file. The series, now 14 patches long, is authored by Michael Montalbo and remains under initial review.

The tool introduces a two-phase workflow: a **labeler** assigns semantic labels (e.g., `component=refs`) to files using project-specific heuristics, and an **organizer** updates references (like `#include` paths or build system entries) after moves. The first seven patches established the infrastructure, including the `.gitorganize` file, labeler heuristics, and a concrete example moving the ODB subsystem to `odb/`. The latest patch (eighth) demonstrates the tool's practical use by moving all refs-related C sources and headers into a new `refs/` directory, updating 347 files to reflect the new paths while keeping the codebase buildable. The changes are purely mechanical, with no logic alterations.

Key open questions include whether the labeler's Git-specific heuristics generalize to other projects, the organizer's scalability for complex reference graphs, and alignment with ongoing efforts like Patrick Steinhardt's `libgit.a` series. Reviewers may also debate the naming and placement of subsystem directories (e.g., `refs/`) and the completeness of reference updates. No substantive reviews have been posted yet, so the discussion is still in its early stages. The series is a significant proposal with potential to streamline future reorganizations, but its adoption path and tool generality remain unresolved.
