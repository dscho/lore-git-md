This is the **seventh patch in the 14-patch RFC series introducing `git organize`**, a new command for restructuring Git's source tree. This patch demonstrates the tool's practical application by moving all 23 ODB (object database) C sources and 26 headers from the root directory into a new `odb/` subdirectory. The patch updates every reference to the old paths—including `#include` directives, build system entries (Makefile and meson.build), documentation, and tutorial examples—to point to the new locations.

The patch is purely mechanical: it renames files (e.g., `alloc.c` → `odb/alloc.c`) and updates path references, leaving the code itself unchanged. The `.gitorganize` file is updated to reflect the new paths for the ODB files, and the build remains functional after the move. This serves as a concrete example of how `git organize` can be used to carve out subsystem-specific directories while maintaining build integrity.

This patch is part of the broader goal of making Git's source tree more modular and navigable. The ODB move is one of eight such carve-outs proposed in the series (others include `refs/`, `pack/`, etc.), each demonstrated in a separate patch. The patch is well-scoped and self-contained, making it easier to review and merge independently of the tool itself. The high percentage of renames (95-100% similarity) in the diffstat confirms the mechanical nature of the changes.

Key technical details for follow-up discussion:
- **Files touched**: 347 files, with 1006 insertions and deletions (net zero, as expected for a rename-heavy patch).
- **Subsystems affected**: Primarily the build system (Makefile, meson.build), documentation, and all code that includes ODB headers or references ODB files.
- **Behavior**: No functional changes; the patch ensures the tree remains buildable after the move.
- **Test coverage**: The patch relies on the existing test suite to validate the build and functionality. No new tests are introduced here, but the `t/t0096-organize.sh` test script (added earlier in the series) covers the tool's behavior.
- **Integration**: This patch is designed to be merged independently of the `git organize` tool, though the tool was used to generate the move and reference updates.

The patch is a strong example of the tool's intended use case and demonstrates the feasibility of large-scale source tree reorganization without breaking the build. Reviewers may focus on whether the ODB move itself is desirable (e.g., whether `odb/` is the right name or location) and whether the reference updates are complete (e.g., no missing `#include` fixes). The patch's mechanical nature and self-contained scope make it a low-risk candidate for early merging, even if the tool itself remains under discussion.
