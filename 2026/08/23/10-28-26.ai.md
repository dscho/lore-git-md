This is the first patch in Delilah Ashley Wu's v2 series fixing Git's global config listing inconsistency. It addresses Windows path normalization for XDG config paths by ensuring `xdg_config_home_for()` always returns forward slashes, aligning with Git's cross-platform conventions and test expectations.

The patch modifies `path.c` to apply `convert_slashes()` to paths constructed from `$XDG_CONFIG_HOME` or `$HOME` on Windows, preventing mixed-slash output in `git config --show-origin`. The change is narrowly scoped to XDG config paths, avoiding the broader `cleanup_path()` modification that concerned reviewers in v1. New tests in `t1300-config.sh` verify both slash conversion and default path handling, including edge cases with backslash-containing environment variables.

This preparatory work directly responds to Johannes Schindelin's feedback from v1, where he noted that mixed slashes in `--show-origin` output were undesirable but cautioned against modifying `cleanup_path()` due to potential side effects. The solution here is minimal and targeted, focusing only on the XDG config path construction. The test coverage appears thorough, exercising both environment variable sources and verifying the slash conversion behavior.

The patch is uncontroversial and well-motivated, addressing a clear presentation inconsistency without changing core functionality. It paves the way for the subsequent patches that implement the actual config listing fix. No new CLI options or on-disk format changes are introduced. Reviewers familiar with the v1 discussion will recognize this as a direct response to earlier concerns about path normalization scope.
