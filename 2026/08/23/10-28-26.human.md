This is the first patch in Delilah Ashley Wu’s v2 series fixing Git’s inconsistent `--global` config listing behavior. It addresses a Windows-specific path normalization issue where `git config --show-origin` displays XDG config paths with mixed forward and backward slashes (e.g., `file:"C:\\Users\\delilah/.config/git/config"`). The patch enforces forward slashes in `xdg_config_home_for()` on Windows by applying `convert_slashes()` to the constructed path, aligning with Git’s cross-platform preference for forward slashes.

The change is narrowly scoped to XDG config paths, avoiding the broader `cleanup_path()` modifications that Junio C Hamano cautioned against in v1. The patch also adds test coverage in `t/t1300-config.sh` to verify slash conversion and confirm the default XDG path behavior. Johannes Schindelin’s Reviewed-by from v1 remains applicable, as the technical approach is unchanged—only the scope has been refined.

This is a preparatory patch for the series’ core fix (patch 2/3), which will make `git config list --global` read from both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`. The Windows path normalization here ensures consistent path formatting in `--show-origin` output, which is critical for the later patches’ error handling and test assertions. The patch looks well-crafted, with clear motivation and thorough test coverage for edge cases. No controversy is expected.
