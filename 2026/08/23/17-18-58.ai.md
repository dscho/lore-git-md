This is the fourteenth and final patch in Michael Montalbo’s **14-patch RFC series** introducing `git organize`, a new command designed to restructure Git’s source tree by moving files into subsystem-specific directories. This patch specifically **moves the transport subsystem**—22 C sources and 21 headers—into a new `transport/` directory, updating all references (build system entries, `#include` directives, documentation, and test helpers) to maintain build integrity.

The patch is purely mechanical: it renames files from the root to `transport/` and updates every reference to their old paths (e.g., `#include "remote.h"` → `#include "transport/remote.h"`). The `.gitorganize` file is updated to reflect the new layout, and the build system (Makefile, meson.build) and CMakeLists.txt are adjusted accordingly. The net line churn is zero, confirming the move is a straightforward rename with no functional changes.

This patch completes the series’ demonstration of `git organize` by carving out the last major subsystem. The transport subsystem is a foundational layer for Git’s network operations, so its move touches a broad swath of the codebase (347 files updated). The patch’s thoroughness in updating cross-subsystem dependencies (e.g., `index/`, `odb/`, `setup/`) underscores the tool’s ability to handle complex reference graphs, though reviewers may scrutinize edge cases (e.g., interactions with platform-specific shims in `compat/` or external tools like Git for Windows).

The patch is part of the RFC’s **second phase** (patches 7–14), which applies the tool to Git’s own codebase to demonstrate its practical utility. The transport move is the largest in the series by file count, making it a critical test of the organizer’s scalability and completeness.
