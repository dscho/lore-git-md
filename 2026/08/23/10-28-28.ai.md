This is the final patch in Delilah Ashley Wu’s three-patch v2 series fixing Git’s inconsistent `--global` config listing behavior. The patch makes `git config list --global` and `git config get --global` read from both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`, aligning with documented behavior and the actual config application logic.

The implementation reuses `do_git_config_sequence()`—the function that already reads all scopes—by introducing `ignore_system`, `ignore_repo`, `ignore_worktree`, and `ignore_cmdline` flags to restrict it to the global scope. This avoids duplicating config-file reading logic and ensures consistent behavior between scoped and unscoped commands. The patch also updates tests in `t1300-config.sh` and `t1306-xdg-files.sh` to verify that both config files are respected during `--global` operations, including edge cases where one or both files are unreadable.

Key technical details include the `ignore_global` flag (currently unused but included for completeness) and the preservation of `opts->source.file` for write operations, with a comment clarifying its role. The patch builds on the infrastructure introduced in patch 2 (error handling and `success_count` tracking) and the Windows path normalization from patch 1, completing the series’ goal of resolving the user-facing inconsistency without introducing regressions.

The series is now technically complete, with Johannes Schindelin’s Reviewed-by tags carried forward from v1 and all prior feedback addressed. No new CLI options or on-disk format changes are introduced, and the change is uncontroversial in principle, as it aligns `--global` behavior with documented expectations.
