This is a discussion reply in the ongoing RFC thread about making Git's stash stack per-worktree via a new `stash.ref` configuration knob. The thread remains in early exploration, with no code changes yet.

Kristoffer Haugsbakk engages with Vladimir Sitnikov's proposal, acknowledging both the current behavior's occasional utility (e.g., manually moving stashes between worktrees) and its growing pain points in automated setups (AI coding agents). He agrees that a configuration option is the pragmatic path forward, given backward compatibility constraints, but notes that per-worktree stashes would have been the more elegant default if not for historical reasons.

The exchange surfaces a key tension: while the stash's global nature can be confusing for manual users, the real urgency comes from automated tools (like GitHub Copilot CLI) that now routinely operate across multiple worktrees. Kristoffer suggests that agents could adapt by avoiding the stash entirely, but Vladimir's original patch makes a stronger case that Git itself should evolve to meet this emerging use case.

No objections or alternative designs are proposed here—just a thoughtful weighing of trade-offs. The discussion is still shaping the problem space rather than converging on solutions.
