This is the fourteenth and final patch in Michael Montalbo’s **14-patch RFC series** introducing `git organize`, a new command designed to systematically restructure Git’s source tree by moving files into subsystem-specific directories. This patch gathers the **transport subsystem**—22 C sources and 21 headers—into a new `transport/` directory, updating every reference to their old paths across the codebase, build system (Makefile and Meson), and documentation.

The patch is purely mechanical: it moves files like `bundle.c`, `connect.c`, `fetch-pack.c`, `http.c`, `pkt-line.c`, `remote.c`, `send-pack.c`, `transport.c`, and others into `transport/`, then updates all `#include` directives, build entries, and test helpers to point to the new paths. The diff shows **net-zero line churn**, confirming the changes are simple renames with no functional modifications. The `.gitorganize` file is updated to reflect the new labels and paths for the transport files, completing the tool’s configuration for this subsystem.

This patch demonstrates the practical application of `git organize` by carving out the transport subsystem, following the same pattern established in earlier patches for ODB, refs, pack, diff, revision, index, and setup. The tree remains buildable after the move, and the patch relies on the existing test suite to validate functionality. The transport subsystem is a foundational part of Git, so this patch’s broad impact (347 files updated) may draw scrutiny from reviewers concerned about completeness of reference updates or potential breakage in external tools like Git for Windows or libgit2. However, the patch itself is straightforward and aligns with the series’ goal of making structural changes auditable and reversible.
