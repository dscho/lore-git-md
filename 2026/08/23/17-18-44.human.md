This is an ambitious **RFC feature proposal** introducing `git organize`, a new command designed to restructure Git's own source tree by moving related files into subsystem-specific directories (e.g., `odb/`, `refs/`, `pack/`). The series is **14 patches long** and includes both the tool itself and its immediate application to Git's codebase, demonstrating the concept by carving out eight subsystems.

The tool works by recording a project's file-placement rules in a tracked `.gitorganize` file, then applying those rules to move files and mechanically update references (e.g., `#include` lines, build system entries). The placement logic is project-specific: Git's implementation uses a labeler script that mines commit messages for "area:" prefixes and consolidates them into components, but the tool is designed to be configurable for any project. The series includes a new test script (`t/t0096-organize.sh`) and updates nearly every build file and source reference to reflect the moves.

The patches are **self-contained**: each carve (e.g., moving `odb/` files) is a single commit that both moves the files and updates all references, making it reviewable in isolation. The tool itself is not required for the moves to be useful—once a carve is merged, the `.gitorganize` entries can be dropped. The series leaves 36 files uncarved (e.g., `archive/`, `merge/`) and 79 files in "backlog" with no assigned directory, inviting discussion about where they belong.

This is **not a small refactoring**: it touches 609 files and introduces a new built-in command with its own configuration, file format, and protocol for project-specific logic. The motivation is clear—addressing the long-standing desire to group related files—but the scope is large enough that it will likely spark debate about whether the tool is the right approach, whether the chosen groupings are correct, and how much churn is acceptable for organizational improvements. The series is well-structured for incremental review, but the overall concept is what will draw the most attention.
