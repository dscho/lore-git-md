This is the second patch in Delilah Ashley Wu’s three-patch v2 series fixing the inconsistency in Git’s `--global` config listing. It introduces the infrastructure that the next patch will use to make `git config list --global` read from both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`.

The patch teaches `do_git_config_sequence()` to track how many configuration files were successfully read (`success_count`) and to optionally fail if none were read (`require_successful_config` flag). The flag is currently disabled everywhere; the next patch will enable it for the `--global` code path. Tests are added to lock in the current behavior: `git config list` succeeds when no global config exists, while `git config list --global` fails.

The implementation is clean and minimal: a helper function (`attempt_git_config_from_file_with_options`) wraps the existing config-file reader, increments a counter on success, and accumulates the return value. The main function then checks the counter and returns -1 if no files were read and the flag is set. The tests are narrowly scoped to exit codes, avoiding any output sensitivity.

Johannes Schindelin’s Reviewed-by from v1 still applies to the technical content. Junio’s earlier concerns about error handling and temporary regressions appear to be addressed by the flag being off-by-default and the tests locking in the current behavior. The only remaining question is whether the `nonzero_ret_on_global_config_error` flag (introduced in patch 3) will interact correctly with this counter, but that is a matter for the next patch, not this one.

Files touched: `config.c` (core logic) and `t/t1300-config.sh` (tests). No new CLI options or on-disk formats. The patch is uncontroversial and ready for maintainer review.
