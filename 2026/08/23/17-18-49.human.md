This is the fifth patch in Michael Montalbo’s 14-patch RFC series introducing `git organize`, a new command for restructuring Git’s source tree. This patch adds the `.gitorganize` configuration file that defines which files are in scope and how they should be laid out.

The file declares that all `.c` and `.h` files at the root are governed by the tool. It then maps each of Git’s thirteen components (e.g., `odb`, `refs`, `pack`) to a directory of the same name, while keeping files marked as `role:public` or `role:program` at the root. This is purely declarative—no files are moved yet. The next patch will record labels for each file, and subsequent patches will perform the actual moves.

The patch is small and mechanical, but it is the linchpin of the series: the `.gitorganize` file is what makes the reorganization auditable, reversible, and project-specific. The layout rules are open to debate, but the patch itself is uncontroversial—it simply commits the proposed structure to the repository so that the tool can reference it. If reviewers want to adjust the component list or directory names, this is the patch where those changes would land.
