This is a v2 resubmission of Delilah Ashley Wu's patch series fixing the inconsistency in Git's `--global` config listing behavior. The series makes `git config list --global` read from both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`, aligning it with documented behavior and the actual config application logic. The v2 addresses feedback from v1 by reordering patches to avoid temporary regressions, narrowing Windows path normalization scope, and squashing test-only changes into their corresponding implementation patches.

The core change modifies `config_sequence()` in `config.c` to handle the global scope by reading both config files, using new flags (`ignore_system`, `ignore_global`) and counters (`global_config_success_count`) to track reads and enforce error handling. The series also includes preparatory work: patch 1 ensures forward slashes in XDG config paths on Windows (without modifying `cleanup_path()` to avoid breaking callers), and patch 2 adjusts error handling to prevent regressions when unreadable config files are encountered.

The implementation appears technically sound, with thorough test coverage in `t1300-config.sh` and `t1306-xdg-files.sh` verifying both the fix and edge cases. Johannes Schindelin's Reviewed-by tags from v1 remain applicable to the technical aspects, though Junio C Hamano previously raised concerns about path normalization and test methodology, and noted the series was at risk of being dropped from `seen` due to inactivity. This resubmission directly responds to those concerns, particularly by limiting the scope of Windows path changes and improving test clarity.

Key technical details for follow-up discussion include the `nonzero_ret_on_global_config_error` flag behavior, the interaction between `ignore_global` and `global_config_success_count`, and whether the error handling in patch 2 fully addresses Junio's regression concerns. The series touches the config subsystem (`config.c`, `builtin/config.c`), path handling (`path.c`), and test infrastructure, with no apparent platform-specific issues beyond the Windows path normalization. The change is motivated by clear user-facing inconsistency and aligns with documented behavior, making it likely to be uncontroversial if the remaining technical questions are resolved.
