This is the first patch in the v2 series overhauling gitk's color-preference dialog. It consolidates the initial color-setting logic for the dialog's color swatches into the existing `prefspage_set_colorswatches` helper procedure, eliminating duplicate code and ensuring the UI elements are colored consistently from a single source. The change is purely mechanical: the patch removes the hard-coded background colors from the label widgets in `prefspage_colors` and instead calls `prefspage_set_colorswatches` at the end of the procedure to apply the initial colors. This refactoring has no user-visible effect and serves as a prerequisite for the subsequent UI improvements in the series.

The patch touches only `gitk-git/gitk`, removing 13 lines of redundant color-setting code and adding a single call to the helper procedure. The `prefspage_set_colorswatches` procedure itself is unchanged except for the addition of the `linkfgcolor` global variable, which was previously missing but required for completeness. This is a clean, low-risk refactoring that simplifies the codebase and prepares the ground for the more substantive UI changes in later patches. No edge cases or behavioral changes are introduced, and the patch is ready for review as part of the series.
