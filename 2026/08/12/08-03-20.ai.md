This is the final patch in Johannes Schindelin’s v3 series fixing unchecked return values reported by Coverity. It addresses a resource leak in `builtin/bisect.c`’s `bisect_run()` function, where a failed `dup(1)` call left `saved_stdout` set to `-1`, causing `close(saved_stdout)` to misbehave and `dup2()` to fail silently, leaving stdout redirected to a temporary file for the remainder of the bisect run.

The fix adds explicit checks for both `dup(1)` and `dup2(temporary_stdout_fd, 1)` return values. If either fails, the function closes `saved_stdout` (if valid), closes `temporary_stdout_fd`, reports the error via `error_errno()`, and breaks out of the loop to let the existing cleanup path handle the rest. This matches the defensive pattern used elsewhere in the function and closes the resource leak identified by Jeff King in v2.

The patch is minimal (eight lines added, one removed) and purely mechanical, with no behavior changes beyond making the failure path explicit. It touches only `builtin/bisect.c` and is uncontroversial, completing the series’ goal of hardening Git’s error paths against silent failures. The commit message clearly explains the latent bug and the fix, crediting Coverity and Opus 4.7 for assistance. This patch, like the rest of the series, is now ready for integration.
