This is the ninth patch in Johannes Schindelin’s 12-patch **platform compatibility** series, targeting Windows-specific build adjustments. The patch disables the generation of hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/` for Windows builds by setting `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname`.

The change is motivated by three practical concerns: it eliminates a 30-second build-time overhead on Windows, avoids confusion in Windows Explorer (which misreports disk usage for hard-linked files), and aligns with the long-standing deprecation of the "dashed form" (officially deprecated since Git 1.5.4 in 2008). The commit message confirms that the `git` executable’s built-in command dispatch remains fully functional, so end users will see no behavioral change—this is purely a build-time optimization.

The patch is minimal and self-contained, touching only `config.mak.uname` to add the `SKIP_DASHED_BUILT_INS` assignment under both the `Windows` and `MINGW` sections. The value `YabbaDabbaDoo` is a non-empty placeholder; the build system only checks for the variable’s presence, not its value. Junio C Hamano’s earlier review noted that the dashed-form executables could be removed entirely in Git 3.0, but this patch does not address that forward-looking proposal—it merely stops generating them on Windows now.

This is a routine cleanup with no downsides for Windows users and no impact on other platforms. The patch is uncontroversial and ready for integration. If you maintain Windows build infrastructure or care about build-time optimizations, this patch is worth noting; otherwise, it can be safely ignored. The series as a whole remains under review, with no merge status reported.
