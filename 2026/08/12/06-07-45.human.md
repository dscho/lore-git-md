This is patch 8/9 in Justin Tobler’s nine-patch v3 series making `git receive-pack` fully backend-agnostic by extending the ODB transaction system. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and has already addressed all critical design flaws raised in earlier rounds, including a lockfile lifecycle flaw, transaction lifecycle management, and global state removal.

This specific patch removes a fragility in the current design: the assumption that the temporary ODB source is always the first entry in the source list. The change is small and mechanical: `odb_set_temporary_primary_source()` now returns the newly installed source directly and reports the previous primary source via an optional out-parameter. The return value is propagated through `tmp_objdir_replace_primary_odb()` and stored in the "files" ODB transaction struct, ensuring the temporary source remains accessible post-commit without depending on source list ordering. No user-visible behavior changes; the patch is purely an internal refactor to improve robustness.

Patrick Steinhardt, the ODB abstraction lead and primary reviewer, approves the change with a brief but positive reply. His comment ("Makes sense. I'm looking forward to the day where we get rid of this mechanism altogether") signals that while the patch is a necessary step, the long-term goal is to eliminate the temporary ODB source mechanism entirely as the ODB abstraction matures. This aligns with the series’ broader goal of making the transaction interface more explicit and less reliant on global state.

The patch is uncontroversial and directly addresses feedback from earlier iterations. It is a clean, targeted fix that removes an implicit assumption, making the design more resilient to future changes. With Patrick’s approval, this patch looks ready to proceed, though the series as a whole still has one substantive design question open regarding the placement of ".keep" files in the transaction system.
