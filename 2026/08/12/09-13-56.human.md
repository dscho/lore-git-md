This is the second iteration of a refactoring series targeting Git’s object database (ODB) subsystem. The goal is to remove lazy-loading of alternate object databases, simplifying the codebase by initializing all alternates upfront during primary ODB setup. The series consists of four patches and is part of Patrick Steinhardt’s broader ODB abstraction effort, which aims to make Git’s object storage layer more modular.

The motivation is straightforward: while Git originally deferred loading alternates until they were needed, the codebase has evolved to parse alternates eagerly in many places (e.g., during object lookups). This makes the lazy-loading optimization ineffective and results in scattered calls to `odb_prepare_alternates()` across the code. By initializing alternates upfront, the series reduces complexity and prepares the ground for future work, such as moving alternates into the "files" backend. The first patch also resolves a long-standing inconsistency in case-sensitivity handling for alternate paths when alternates are registered before repository configuration is parsed.

This version addresses minor feedback from the initial submission. Patch 2’s commit message now fixes a typo ("where read" → "where we read"), and patch 4 adds a comment clarifying why the `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variable does not need to be reprocessed during cache flushing. The series touches 12 files, primarily in the `odb/` subsystem, but also affects higher-level code like `builtin/fsck.c` and `builtin/pack-objects.c`. The net effect is a reduction of 16 lines of code (70 insertions, 86 deletions).

The patches are mechanically sound and well-explained, with clear commit messages. The series does not introduce user-visible behavioral changes, but it may have subtle performance implications for commands like `git fsck` that previously avoided loading alternates when none were present. The discussion in the first iteration confirmed that the current behavior—where alternates are not always registered after repository configuration is parsed—is an existing quirk, not a bug, and the series preserves this behavior while fixing the case-sensitivity inconsistency.

Justin Tobler’s reviews of the first iteration were thorough for patch 1 but more surface-level for the others. No substantive objections or requests for changes were raised, and the feedback that was addressed in this version was minor. The series looks ready for further review, though reviewers may want to validate edge-case handling (e.g., repositories with thousands of alternates or corrupt alternates) and confirm that the performance trade-offs are acceptable. Overall, this is a clean, well-motivated refactoring that aligns with the project’s ongoing ODB abstraction goals.
