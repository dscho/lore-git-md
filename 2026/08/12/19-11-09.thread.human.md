This thread fixes a severe performance regression in Git v2.53 that caused quadratic-time slowdowns when loading many packfiles, particularly affecting shell prompts (`git rev-parse --short HEAD`) in Microsoft Git Scalar environments. The regression, introduced in October 2025, was traced to `packfile_store_add_pack()` performing a linear scan for duplicates before each insertion, undoing a 2019 fix. Johannes Schindelin’s patch (now merged to `next`) adds a fast-path optimization to skip duplicate checks when the caller guarantees the packfile is new, restoring linear-time performance.

Key participants include Johannes (author), Junio C Hamano (maintainer), Jeff King (Peff), and Patrick Steinhardt. The patch was merged despite unresolved design concerns: Junio questioned the long-term maintainability of the fast-path’s reliance on caller discipline, while Patrick proposed a broader hashmap refactoring that Peff later deemed premature due to implementation constraints. The regression’s real-world impact—slowdowns from 0.4s to 4.5s in Scalar’s shared cache repositories—drove the patch’s urgency, though an unrelated CI clone regression remains unresolved.

The thread leaves two open questions: whether Patrick’s hashmap refactoring is viable given its complexity, and whether the fast-path’s design risks future breakage. The patch’s merge to `next` signals confidence in the immediate fix, but the deferred architectural discussion may resurface if new use cases emerge.
