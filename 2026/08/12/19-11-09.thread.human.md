This thread addresses a severe performance regression in Git v2.53 that causes quadratic-time behavior when loading many packfiles, particularly affecting shell prompts (`git rev-parse --short HEAD`) in Microsoft Git Scalar environments. The regression, introduced in October 2025, undoes a prior fix from 2019 and has real-world impact, slowing operations from 0.4s to 4.5s in repositories with tens of thousands of packfiles.

Johannes Schindelin’s v2 patch introduces a fast-path optimization in `packfile_list_append()` by adding a `skip_dup_check` parameter (renamed from `is_new` in v1) to bypass duplicate checks for packfiles the caller guarantees are new. This targeted fix eliminates the O(N²) scan for that case, offering a simpler alternative to Patrick Steinhardt’s deferred hashmap refactoring. While Junio C Hamano initially endorsed the patch as "clever and clean," his latest review raises substantive maintainability concerns about the fast-path’s reliance on caller discipline, questioning whether the consequences of duplicates (faster existence checks but slower non-existence checks) are fully understood. This critique may prompt further iteration or accelerate Patrick’s hashmap work.

Jeff King (Peff) recently identified a critical oversight in Patrick’s hashmap counterproposal: Git already maintains a hashmap for tracking packfiles, introduced in the 2019 fix. This reframes the debate, as the fast-path optimization is not a workaround for a missing hashmap but a targeted optimization to avoid the O(N) scan *even when the existing hashmap guarantees uniqueness*. Peff’s observation shifts the burden to Patrick to explain how his proposed hashmap improves upon the status quo. Meanwhile, the patch’s scope has narrowed—it does not address an unrelated CI clone regression (clone times increasing from under 2 minutes to over 30 minutes), which remains unresolved.

The patch touches `packfile-list.c`, `packfile-list.h`, and `packfile.c`, and includes a new perf test (`p5303-many-packs.sh`) to measure performance with 10,000 packs. While Peff initially questioned the test’s redundancy, he later acknowledged its value in targeting the quadratic-time behavior most pronounced in high-pack scenarios. The regression’s root cause lies in Scalar’s "shared cache repository" architecture, where scheduled fetches outpace maintenance repacks, leaving repositories with excessive packfiles. No on-disk format changes are involved, and the patch remains under review with the design discussion still open.
