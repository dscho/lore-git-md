This thread is about a critical performance regression in Git v2.53 that causes quadratic-time slowdowns when loading many packfiles, particularly affecting Microsoft Git Scalar environments. The issue was introduced in October 2025 (commit `589127caa730`) and undoes a prior fix from 2019. The regression manifests in `git rev-parse --short HEAD` (used in shell prompts), slowing it from 0.4s to 4.5s in repositories with tens of thousands of packfiles.

Johannes Schindelin proposed a targeted fix that adds a fast-path optimization to `packfile_list_append()` via a new `skip_dup_check` parameter. This allows callers to bypass duplicate checks when the packfile is known to be new, eliminating the O(N²) scan for that case. The patch includes a new performance test (`t/perf/p5303-many-packs.sh`) and has been refined based on feedback from Junio C Hamano, Jeff King (Peff), and Patrick Steinhardt. While the fix is uncontroversial in principle—Peff confirmed the regression's severity and the fix's reasonableness—Junio recently reopened the design discussion, raising concerns about the fast-path's long-term maintainability. The `skip_dup_check` parameter relaxes the uniqueness invariant of `packfile_list`, relying on caller discipline, which could introduce subtle performance or correctness issues if future changes violate this assumption.

Patrick Steinhardt had previously proposed a more robust hashmap-based refactoring but conceded the fast-path as the correct immediate fix. The hashmap approach remains deferred as a longer-term improvement. The patch is now in active review, with the design question as the primary open issue. No prior versions exist, and the patch is considered production-critical for environments like Scalar's shared cache repositories. The unrelated CI clone-time regression (clone times increasing from under 2 minutes to over 30 minutes) remains unresolved.
