This thread is about a severe performance regression in Git v2.53 that causes quadratic-time slowdowns in common operations like `git rev-parse --short HEAD` (used in shell prompts) and `git clone`. The regression was introduced in October 2025 (commit `589127caa730`) and undoes a prior fix from 2019. Johannes Schindelin proposed a targeted fix that adds a fast path to skip duplicate checks in `packfile_store_add_pack()`, eliminating the O(N²) scan. The patch has received positive feedback from Junio C Hamano, who called the design "clever and clean," and Jeff King (Peff), who confirmed the regression's severity but questioned whether the new performance test is redundant.

The discussion took a new turn with D. Ben Knoble's recent reply, which raises a pragmatic question: could enabling `git maintenance` mitigate the slowdowns in monorepo checkouts and CI clones, rather than (or in addition to) the proposed code fix? Ben notes that maintenance might help in long-running monorepo checkouts by repacking loose objects into fewer packfiles, but he's unsure whether it would address CI clones unless the server also repacks. This introduces a strategic dimension to the thread—whether the problem should be solved at the infrastructure level (via maintenance) or the code level. The patch is currently under review, with no objections to its technical design, but this new question could influence whether it's merged as-is or revised to include maintenance-related guidance. Resolution will likely require input from Johannes or another domain expert on whether maintenance is a viable workaround for the reported scenarios.
