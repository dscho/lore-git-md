This thread fixes a severe performance regression in Git v2.53 that caused quadratic-time slowdowns when loading many packfiles, particularly hitting shell prompts (`git rev-parse --short HEAD`) in Microsoft Git Scalar environments. The regression, introduced in October 2025, undid a 2019 fix and was traced to `packfile_store_add_pack()` scanning the entire packfile list before each insertion. Johannes Schindelin’s patch adds a fast-path optimization by letting callers skip duplicate checks when they can guarantee the packfile is new, avoiding the O(N²) scan entirely.

The fix was initially uncontroversial—Junio C Hamano called it "clever and clean"—but Patrick Steinhardt later proposed a more robust hashmap-based refactoring. After discussion, the fast-path was chosen as the immediate fix, with Patrick conceding it’s the right stopgap while his hashmap work is deferred. However, Junio’s latest review raises concerns about the fast-path’s long-term maintainability, warning that future changes might break the "new pack" guarantee and introduce subtle correctness or performance issues. This doesn’t block the current patch but adds weight to Patrick’s deferred refactoring.

The patch touches `packfile.c` and adds a new perf test (`t/perf/p5303-many-packs.sh`) to catch similar regressions. No prior versions exist, and the fix is ready for `next`.
