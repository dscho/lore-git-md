This thread is about a performance regression in Git’s packfile handling that caused quadratic-time slowdowns when loading many packfiles, particularly affecting shell prompts (`git rev-parse --short HEAD`) in Microsoft Git Scalar environments. The regression, introduced in Git v2.53, was fixed by Johannes Schindelin’s patch (now merged to `next`), which added a fast-path optimization to skip duplicate checks when the caller guarantees a packfile is new.

The patch is now cooking in `next` and addresses the immediate issue, but broader design questions remain unresolved. Junio Hamano raised maintainability concerns about the fast-path’s reliance on caller discipline, while Patrick Steinhardt proposed a longer-term hashmap refactoring to eliminate the quadratic-time inefficiency in both `append()` and `prepend()` operations. Jeff King (Peff) recently clarified that the `prepend()` inefficiency is already mitigated by an MRU optimization in `find_pack_entry()`, reducing the urgency for a hashmap-based solution. Peff also cast doubt on the feasibility of Patrick’s refactoring due to the existing hashmap’s entanglement with other logic.

The thread has narrowed in scope: the fast-path fix is accepted as the immediate solution, while the hashmap refactoring is deferred pending further analysis or additional use cases. The unrelated CI clone regression (clone times increasing from under 2 minutes to over 30 minutes) remains unresolved. Key participants include Johannes (author), Junio (maintainer), Peff (reviewer), and Patrick (proposing refactoring). The patch is expected to graduate to `master` unless new issues emerge during integration testing.
