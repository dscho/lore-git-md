This is a documentation patch correcting a misleading short help message for the `-l` option in `git diff`.

The patch updates the one-line description of the `-l` option (used to set the `rename_limit` in diff operations) to clarify that it only affects the *exhaustive* portion of rename/copy detection, not all rename detection. The commit message explains that this aligns the short help text with a previous documentation update (commit 6623a528e00b from 2021) that already clarified this distinction in the full documentation. That earlier commit noted that exact rename detection and basename-guided rename detection (both linear-time operations) still run regardless of the `-l` limit.

The change is minimal: a single line in `diff.c` where the option’s help string is defined. The new wording replaces "prevent rename/copy detection" with "prevent exhaustive portion of rename/copy detection," making it clear that the limit is not a hard cutoff for all rename detection.

This is a follow-up to settled prior work, not a new feature or controversial change. The patch is well-motivated by the earlier documentation effort and addresses a specific, narrow inconsistency. No test or code behavior changes are involved.
