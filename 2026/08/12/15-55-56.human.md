This is a security bugfix targeting the `bundle-uri` subsystem, specifically addressing CVE-2026-62960. The patch prevents Git from automatically fetching bundle URIs advertised by servers unless their protocol is explicitly allowed by Git's `protocol.*.allow` configuration. By default, this blocks file-based URIs (including UNC paths on Windows), which could otherwise be exploited to leak NTLM credentials via outbound SMB connections.

The fix is narrowly scoped to the `fetch_bundle_list()` function, which is the entry point for clone and fetch operations. It introduces a new `sanitize_bundle_list()` helper that filters out URIs with disallowed protocols, issuing a warning for each skipped URI. The patch preserves the ability to list all advertised URIs via `ls-remote` and does not affect user-supplied `--bundle-uri` arguments. Users can re-enable file URIs by setting `protocol.file.allow=always`.

The commit message is unusually detailed for a security fix, explaining the Windows-specific attack vector (transparent NTLM authentication via UNC paths) and the patch's history—it was originally developed for Git for Windows v2.55.0(4) and reviewed privately due to the vulnerability's sensitivity. The test coverage is thorough, including cases for bare paths, `file://` URIs, and UNC paths (on Windows), as well as verifying that the block can be overridden with `protocol.file.allow=always`.

This is a well-crafted fix with clear motivation and robust testing. The patch has already been deployed in Git for Windows, suggesting it has undergone real-world validation. Given the severity of the credential-leak risk on Windows, this is likely to be fast-tracked into `master` and `maint`.
