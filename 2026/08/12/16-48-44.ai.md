This is the first patch in Junio C Hamano’s v2 series fixing Bash completion for `git checkout -C <dir>`. It is a pure refactoring of the `_git_checkout()` function in `contrib/completion/git-completion.bash` that prepares the ground for the functional changes coming in patches 2/3 and 3/3.

The patch reorganizes the control flow so that the early return when `--` is detected (`__git_has_doubledash`) is removed. Instead, the entire existing logic is wrapped in an `if ! __git_has_doubledash` block, and explicit `return` statements are added to each completion branch (option arguments, `--conflict=*`, `--*`, and the default ref-completion case). The result is functionally identical to the current code but makes it easier to add new behavior later in the series when no revision candidates are found or when `--` is present.

No tests are touched; this is strictly a no-op reshuffling of the existing Bash logic. The patch is clean, well-motivated by the follow-up changes, and uncontroversial. It is part of a three-patch series that is already under review and appears ready for integration.
