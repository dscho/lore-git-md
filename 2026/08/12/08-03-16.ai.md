This is the eighth patch in Johannes Schindelin’s v3 series fixing unchecked return values identified by Coverity. It targets the transport-helper subsystem, specifically the `get_exporter()` function in `transport-helper.c`.

The patch adds a check for the return value of `dup(helper->in)`, which duplicates the helper’s input file descriptor for use by the fast-export process. If `dup()` fails (e.g., due to file descriptor exhaustion), it currently returns `-1`, which the child_process machinery misinterprets as a request to create a new pipe for stdout. This would silently redirect the fast-export process’s output to an unread pipe, breaking the transport-helper’s data flow. The fix propagates the error upward with `error_errno()` if `dup()` fails, preventing the silent miswiring.

The change is minimal (two lines added) and follows the established pattern of hardening error paths without altering behavior on success. The commit message clearly explains the latent bug and its consequences, and the fix is uncontroversial. This patch is part of a larger, well-scoped series addressing Coverity-reported issues; the series as a whole is now technically complete and ready for integration.
