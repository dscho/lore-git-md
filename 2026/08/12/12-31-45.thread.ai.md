Subject: Unexpected pseudo-commits in custom `git lg` alias output

Originating author: Marcel Svitalský
Thread type: bug report

Core problem or goal
A user observes four spurious pseudo-commits—three labeled “Notes added by 'git notes append' - rewrite-analytics” and one “chatter: initialize notes ref - chatter”—that appear at the top of the graph produced by a custom `git lg` alias (`git log --graph --all --oneline --decorate`). The commits are invisible in Sublime Merge and IntelliJ IDEA, appear inconsistently after resets or new commits, and are believed to originate from Git’s notes or hook machinery despite the user’s enabled hooks list being empty. The goal is to understand why these commits surface only in the CLI alias and how to suppress them while retaining the alias’s intended project-commit output.

Current status
Under review. The root cause has been identified: the `--all` flag in the alias includes all refs, including Git notes (`refs/notes/rewrite-analytics` and `refs/notes/chatter`), which form a disconnected graph. This is not a bug but an expected consequence of `--all`. No maintainer decision or merge status has been recorded. Marcel Svitalský now seeks a practical workaround to exclude notes refs from the alias output and clarification on whether this behavior is new or environment-specific. D. Ben Knoble has proposed two workarounds: replacing `--all` with `--branches --tags --remotes` (omitting notes, stash, and other refs) or using `--exclude='refs/notes/*' --all` (explicitly filtering notes while preserving `--all`’s broader coverage).

Key technical details
- Command: `git log --graph --all --oneline --decorate` (custom alias `git lg`)
- Spurious refs: `refs/notes/rewrite-analytics` and `refs/notes/chatter` (legitimate Git notes, likely generated by background tooling such as `rewrite-analytics` or `chatter`)
- Environment: tmux + mate-terminal, Git 2.55.0 (with Rust support and fsmonitor--daemon)
- Discrepancy: CLI shows pseudo-commits due to `--all`; GUI tools (Sublime Merge, IntelliJ IDEA) likely filter or display refs differently by default (e.g., omitting `--all` or applying implicit exclusions)

- On-disk: no format changes reported; issue is purely cosmetic in log output
- Workaround candidates: `--exclude='refs/notes/*' --all` or `--branches --tags --remotes` to exclude notes refs while preserving the intended coverage of project commits
