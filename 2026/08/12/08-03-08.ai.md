This is the v3 revision of Johannes Schindelin’s 12-patch series fixing unchecked return values reported by Coverity. The series now addresses all open correctness issues from v2: the reftable block-writer memory leak (patch 3 and 4), the bisect-run resource leak (patch 12), and Junio’s question about checking `close()` return values (resolved by not adding the check, as the patch’s error path already closes the descriptor and the question was treated as a low-level detail rather than a blocker).

The new patch 3 (`reftable: handle block-writer initialization errors`) is a refactoring that moves error handling from `block_writer_init()` into its sole caller, `reftable_writer_new()`, ensuring that `bw->zstream` is properly deinitialized if initialization fails. This change is purely internal to the reftable backend and does not affect any public APIs or on-disk formats. The commit message for patch 4 was also updated to clarify that silent corruption from an uninitialized `z_stream` is not possible with current zlib versions, addressing Junio’s earlier concern about the severity of the issue.

Patch 12 (`bisect: handle dup() failure when redirecting stdout`) now closes the file descriptor stored in `saved_stdout` if `dup2()` fails, fixing the resource leak identified by Jeff King in v2. The fix is minimal (two lines added) and follows the established pattern of cleaning up resources in error paths.

All other patches remain unchanged from v2, and the series is now technically complete. The patches touch `http.c`, `builtin/config.c`, `reftable/block.c`, `reftable/writer.c`, `t/unit-tests/u-reftable-table.c`, `builtin/last-modified.c`, `compat/pread.c`, `transport-helper.c`, `bisect.c`, and `builtin/bisect.c`. No new config keys, options, or on-disk formats are introduced, and the error paths are all fatal (`die()`) or propagate to the caller. The subsystems involved are HTTP, config, reftable, last-modified, compat/pread, transport-helper, and bisect; future discussion is likely to reference these filenames or the specific functions (`get_active_slot`, `show_editor`, `reftable_table_init_ref_iterator`, `repo_parse_commit`, `git_pread`, `get_exporter`, `read_bisect_terms`).

The series is uncontroversial and well-scoped, with each patch addressing a single Coverity report in a mechanical way. The commit messages are clear and concise, naming the function whose return value is now checked and the file it appears in. The only minor quirk is the use of GitGitGadget’s pull-request URL instead of a lore.kernel.org link, but the patches themselves are properly formatted and threaded. The series is now ready for integration, pending Junio’s final review.
