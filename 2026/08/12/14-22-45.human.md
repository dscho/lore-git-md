This is a documentation patch — a minor but useful correction to the short help message for `git diff -l`. Junio responds to Elijah Newren’s patch, which updates the one-line description of the `-l` option to clarify that it only affects the *exhaustive* portion of rename/copy detection, not all rename detection. The patch itself is uncontroversial and follows up on a 2021 documentation update that already made this distinction clear in the full documentation.

Junio’s reply is brief and constructive: he accepts the intent of the patch but suggests the new wording might still be too technical for a short help message. Instead of "prevent exhaustive portion of rename/copy detection," he proposes something like "limit to exact rename/copy if ..." to make the message more accessible to end users. This is a surface-level review — it focuses on phrasing rather than functionality — but it’s a meaningful one, since short help messages are often the first thing users see when running `git diff -h`.

The patch is part of a settled effort to clarify how rename limits work, and there’s no disagreement about the underlying behavior. The only open question is how to phrase the help text in a way that’s both accurate and user-friendly. This is a small detail, but it’s the kind of polish that makes Git more approachable.
