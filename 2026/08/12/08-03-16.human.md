This is the eighth patch in Johannes Schindelin’s v3 series fixing unchecked return values identified by Coverity. It targets the transport-helper subsystem, specifically the `get_exporter()` function in `transport-helper.c`.

The patch adds a missing error check for `dup(helper->in)`, which duplicates a file descriptor used to wire the fast-export process’s output back to the helper. Without this check, a `dup()` failure (e.g., due to file descriptor exhaustion) would silently redirect the fast-export process’s output to a pipe that nobody reads, breaking the transport-helper protocol. The fix propagates the error upward with `error_errno()`, ensuring the failure is visible to the caller rather than causing silent data loss.

The change is minimal (two lines added) and uncontroversial. It follows the established pattern of hardening error paths without altering behavior or on-disk formats. The commit message clearly explains the latent bug and the consequences of leaving it unaddressed. This patch is part of a well-scoped, technically complete series that has already resolved all open correctness issues from earlier iterations. It’s ready for integration.
