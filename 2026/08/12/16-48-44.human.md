This is the first patch in Junio C Hamano’s v2 series fixing Bash completion for `git checkout`. It is a no-op refactoring that reorganizes the control flow in `_git_checkout()` to avoid an early return when `--` is detected. The change wraps the existing logic in an `if ! __git_has_doubledash` block and adds explicit `return` statements to each completion branch, making the function’s structure clearer without altering its behavior.

The patch prepares the ground for the next two patches: patch 2/3 will modify the function to prioritize tracked paths when no revision matches the input, and patch 3/3 will add a fallback to untracked paths. The refactoring is clean and uncontroversial, touching only `contrib/completion/git-completion.bash`. No functional changes or test updates are included here, as expected for a preparatory patch. This is a well-scoped, low-risk change that aligns with the project’s preference for small, incremental improvements.
