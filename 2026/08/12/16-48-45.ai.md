This is the second patch in Junio C Hamano’s v2 series fixing Bash completion for `git checkout`. It implements the core behavior change: when `git checkout` path completion is triggered (either because no revision matches the input or because `--` is present), the completion now offers only **tracked paths** (files in the index) instead of falling back to untracked files in `$PWD`. This aligns `git checkout` completion with the earlier `git diff` fix and addresses a long-standing usability gap, especially when using `git -C <path>`.

The patch modifies `_git_checkout()` in `contrib/completion/git-completion.bash` to call `__git_complete_index_file ""` (equivalent to `--cached`) when `COMPREPLY` is empty after revision completion. This ensures only tracked paths are suggested, avoiding the previous inconsistency where untracked files in the current directory could appear in the completion list. The change is minimal and surgical: a four-line addition that checks `COMPREPLY`’s length and delegates to the index-file helper.

Test coverage in `t/t9902-completion.sh` is thorough. Two new tests verify the behavior:
1. `git checkout f` (no refs matching "f") completes only tracked paths (`file1`, `file2`), ignoring untracked files.
2. `git -C <path> checkout o` completes tracked paths in the specified repository, not the current directory, and correctly handles edge cases like missing files (`lostfile`).

The patch is well-motivated and uncontroversial. It builds on the refactoring in patch 1/3 and sets the stage for the fallback-to-untracked logic in patch 3/3. The use of `__git_complete_index_file ""` is explicit and correct, addressing Junio’s clarification from v1 that `--cached` (or its empty-string equivalent) is required to enforce tracked-path completion. No open questions remain; this patch is ready for integration.
