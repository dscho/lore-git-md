This is the second patch in Junio C Hamano’s v2 series fixing Bash completion for `git checkout`. It implements the core fix: when no revision references match the input (or when `--` is present), completion now suggests only *tracked* paths from the index, not untracked files in the working directory.

The change is small but precise: `_git_checkout()` now calls `__git_complete_index_file ""` (equivalent to `--cached`) when `COMPREPLY` is empty, ensuring only paths present in the index are offered. The accompanying tests verify that `git checkout f` (no refs matching "f") completes only `file1` and `file2` (tracked) and ignores untracked files, and that `git -C <path> checkout o` completes tracked paths in the specified repository, not the current directory. Edge cases like missing-but-tracked files (`lostfile`) are also covered.

This patch directly addresses the usability gap identified in the series: `git checkout` now behaves consistently with its purpose (operating on repository files) rather than defaulting to arbitrary files in `$PWD`. The fix is uncontroversial, well-tested, and aligns with the earlier `git diff` completion fix. No open questions remain; this looks ready for integration.
