This is the first patch in Justin Tobler’s v3 series extending ODB transactions to `git receive-pack`. The patch fixes a critical lockfile lifecycle flaw that left stale `.keep` files behind after an ODB transaction commit. The bug was introduced when `receive-pack` switched to ODB transactions: the temporary transaction directory became the primary ODB source, causing `index_pack_lockfile()` to derive the `.keep` path relative to the temporary directory instead of the main object directory. After the transaction committed, the `.keep` path became invalid, preventing cleanup.

The fix updates `index_pack_lockfile()` to accept an explicit `struct odb_source *` parameter and modifies call sites to pass the main ODB source. A new test in `t/t5547-push-quarantine.sh` verifies that `.keep` files are removed after a successful push. The change is narrowly scoped to the lockfile path derivation logic and is a prerequisite for the rest of the series, which depends on proper lockfile cleanup.

Patrick Steinhardt’s review is substantive. He questions the current design: if the `.keep` file is written to the temporary directory but the packfile is migrated to the main object directory, the `.keep` file cannot prevent the race it was meant to avoid. He suggests an alternative sequence where the `.keep` file is written to the main object directory at commit time and removed during finalization. His feedback also includes a minor nit about header inclusion (preferring a forward declaration over including `odb/source.h`).

The patch itself is well-crafted and addresses a real correctness issue. The open design question about `.keep` file placement is worth watching; if Patrick’s alternative is adopted, it would require a more invasive change. For now, the patch is a necessary step forward, but the broader transaction design may still evolve.
