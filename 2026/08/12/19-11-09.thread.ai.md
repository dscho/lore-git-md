Subject: [PATCH] packfile: fix quadratic-time performance regression in packfile_store_add_pack()
Series version: standalone patch (no series)
Originating author: Johannes Schindelin
Thread type: bugfix (packfile subsystem)

Core problem or goal
A severe performance regression was introduced in Git v2.53 (commit 589127caa730, October 2025) that causes O(N²) behavior when loading many packfiles. The regression manifests in common operations like `git rev-parse --short HEAD` (used in shell prompts) and `git clone`, with real-world slowdowns from 0.4s to 4.5s and from under 2 minutes to over 30 minutes, respectively. The root cause is `packfile_store_add_pack()`’s linear scan of the packfile list before each insertion to check for duplicates.

Current status
Under review. The patch is queued for review via GitGitGadget (PR #2202) and has not yet been merged to any integration branch. No prior versions exist.

Key technical details
- **Files touched**: `packfile.c` (core logic), `t/perf/p5303-many-packs.sh` (new perf test)
- **Subsystem**: packfile list management
- **New/renamed symbols**: `packfile_list_append()` extended with `is_new` parameter (backward-compatible signature change)
- **Behavior change**: Adds a fast path to skip duplicate checks when the packfile is known to be new, eliminating the O(N²) scan
- **Test coverage**: New perf test `p5303-many-packs.sh` measures `git rev-parse --short HEAD` performance with 10,000 packs
