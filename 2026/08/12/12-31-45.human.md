This is a bug report about unexpected pseudo-commits appearing in the output of a custom `git lg` alias. The reporter, Marcel Svitalský, observes four unconnected commits at the top of their Git graph log, all attributed to internal Git components (`rewrite-analytics` and `chatter`). These commits do not appear in other Git GUI tools (Sublime Merge, IntelliJ Idea) and seem to be tied to Git’s notes system, though the reporter does not recall explicitly using notes.

The issue is intermittent: the pseudo-commits sometimes disappear after new commits or merges, only to reappear after a `git reset --hard`. They are not consistently positioned—sometimes they sit beside the graph rather than on top. The reporter’s environment is Git 2.55.0 on Manjaro Linux, with Rust enabled and fsmonitor active. The custom `git lg` alias uses `--all`, which includes all refs (including notes), and the pseudo-commits are likely notes refs being rendered as if they were regular commits.

This is not a regression in Git’s core functionality but rather an edge case in how the custom alias interacts with Git’s ref namespace. The `--all` flag in `git log` includes notes refs, and the alias’s formatting treats them as ordinary commits. The behavior is surprising but not technically wrong—it’s a consequence of the alias’s design. That said, the reporter’s confusion is understandable, and the issue highlights a potential usability pitfall for users who customize their log output.

No patch or fix is proposed here; this is purely a report. If the Git project decides to address it, the solution might involve better documentation for `--all` or a tweak to how notes refs are displayed in graph mode. For now, this is a heads-up for anyone who uses custom log aliases and sees unexpected entries in their output.
