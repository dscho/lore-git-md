This is the first patch in Patrick Steinhardt’s four-part series refactoring the object database (ODB) subsystem to remove lazy-loading of alternates. It decouples the comparison of alternate object database source paths from `the_repository`, resolving a long-standing inconsistency in case-sensitivity handling.

The patch replaces the use of `fspathhash()` and `fspatheq()`—which implicitly depend on `the_repository` and its `core.ignoreCase` setting—with a self-contained comparison mechanism. This is necessary because alternates can be registered before repository configuration is parsed, leading to inconsistent behavior. The new implementation uses a `struct hashmap` to track source paths, with case-sensitivity determined by explicitly checking `core.ignoreCase` at comparison time. The hash function (`strihash()`) is chosen to work correctly for both case-sensitive and case-insensitive comparisons.

The patch adds 41 lines of code (63 insertions, 22 deletions) and touches three files: `odb.c`, `odb.h`, and `odb/source.h`. The changes are confined to the ODB internals and introduce no user-visible behavior changes. The commit message acknowledges the added complexity but justifies it as necessary for correctness, noting that the current implementation avoids regressing performance for repositories with many alternates (though such cases are rare).

Justin Tobler’s review of the v1 version validated the technical rationale and implementation, though he questioned whether the complexity was warranted. Patrick defended the approach as a "safe side" measure, and no objections remain. The patch is well-motivated and appears ready for integration, though the broader series’ performance implications (e.g., for commands like `git fsck`) remain untested. This is a foundational change for the rest of the series, which centralizes alternate initialization and removes now-unused fields.
