This is the second patch in a two-part test fix series that resolves a flaky CI failure in `t/t7900-maintenance.sh`. The series is ready to merge and addresses a real, recurring race condition in GitLab CI.

The flake occurs in the `maintenance.strategy` test when a detached background `git maintenance` process—triggered by `test_commit()`—holds the `maintenance.lock` file long enough to block the foreground test from running its expected `gc` tasks. The root cause is that the test suite globally unsets `GIT_TEST_MAINT_AUTO_DETACH`, allowing auto-detach behavior that introduces the race. This patch restores the default test-suite behavior (auto-detach disabled) and only enables it in the three tests that explicitly require it, eliminating the race without changing user-visible maintenance logic.

The fix is minimal and targeted: it touches only three lines in `t/t7900-maintenance.sh`, adding `sane_unset GIT_TEST_MAINT_AUTO_DETACH` inside the subshells of the affected tests. The commit message clearly explains the root cause, the evidence (Trace2 output showing missing `gc` tasks), and why the chosen approach is correct. Feedback from Karthik Nayak on wording was incorporated, and the series has received substantive review.

This is a clean, uncontroversial test-only fix that improves CI reliability without affecting Git’s functionality. If you care about test stability or the `git maintenance` subsystem, this patch is worth a quick look.
