This is the third and final patch in Junio C Hamano’s v2 series fixing Bash completion for `git checkout`. It adds a pragmatic fallback: when no tracked paths match the user’s input, the completion now suggests untracked files in the working directory before giving up entirely.

The change is minimal — just four lines in `contrib/completion/git-completion.bash` — and follows the pattern established in the previous patch. After trying tracked paths with `__git_complete_index_file ""`, the function now calls `__git_complete_index_file "--others"` if no completions were found. The tests in `t/t9902-completion.sh` verify that `git checkout u<TAB>` (where "u" matches no refs or tracked files) now offers untracked files like `ufile`, both with and without `--`, and that `-C <dir>` respects the same logic in the specified repository.

Junio notes in the commit message that this fallback may have limited utility for `git checkout` workflows, since untracked files are rarely the target of `git checkout another-branch <path>`. Still, it’s a reasonable consistency measure: users who expect completion to work everywhere will appreciate not being left empty-handed. The series as a whole is now complete, well-tested, and uncontroversial. It should be ready for integration once the earlier patches land.
