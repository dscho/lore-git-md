This thread began when Marcel Svitalský noticed odd pseudo-commits—labeled as notes from `rewrite-analytics` and `chatter`—cluttering the output of his custom `git lg` alias (`git log --graph --all --oneline --decorate`). These commits didn’t appear in GUI tools like Sublime Merge or IntelliJ IDEA, and their visibility fluctuated with new commits or resets. After some back-and-forth, the root cause was pinned on the `--all` flag, which includes *all* refs, including Git notes, creating a disconnected graph. Marcel confirmed that workarounds like replacing `--all` with `--branches --tags --remotes` or using `--exclude='refs/notes/*' --all` cleaned up the output as desired.

Junio C Hamano later weighed in, noting that while `--all`’s behavior might make sense for plumbing commands like `git rev-list`, it feels unintuitive for end-user-facing `git log`. Still, he acknowledged that changing this late in Git’s lifecycle would be impractical. In a final follow-up, Junio directly answered Marcel’s lingering question about alternatives to `--all` by listing the narrower flags `--branches`, `--tags`, and `--remotes`—a concise, practical solution that leaves the thread resolved. The notes themselves were traced to background tooling (like IDE integrations or `rewrite-analytics`), and the discrepancy between CLI and GUI tools was chalked up to default ref filtering in the GUIs. No further action is expected, and the thread is effectively closed.
