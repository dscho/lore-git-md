This thread began when Marcel Svitalský noticed strange pseudo-commits—labeled as notes from `rewrite-analytics` and `chatter`—cluttering the output of his custom `git lg` alias, which runs `git log --graph --all --oneline --decorate`. These commits didn’t appear in GUI tools like Sublime Merge or IntelliJ IDEA, leading to initial confusion about their origin. The root cause turned out to be the `--all` flag, which includes *all* refs in Git’s namespace, not just branches, tags, and remotes. This meant notes refs (likely created by background tooling or IDE integrations) were being treated as first-class commits in the log graph, creating a disconnected but technically correct history.

The issue was resolved with two practical workarounds: replacing `--all` with `--branches --tags --remotes` to narrow the scope, or using `--exclude='refs/notes/*' --all` to retain `--all`’s coverage (including stashes) while filtering out notes. Marcel preferred the latter, as it preserved stashes in the output. Junio C Hamano later reflected on the unintuitive nature of `--all` for end-user commands like `git log`, noting that while its inclusivity might make sense for plumbing commands like `git rev-list`, changing this behavior now would be impractical. Kristoffer Haugsbakk added historical context in a follow-up, suggesting `--all` predates Git notes and was designed to include custom refs users were expected to manage explicitly. He also highlighted that notes, unlike branches or tags, require manual refspecs to share, making them less likely to propagate unintentionally—though third-party tools can still create them, exposing implementation details when `--all` is used.

The thread closed with no action needed from maintainers, but it serves as a useful precedent for users encountering similar cosmetic issues. The discussion underscored a broader tension between Git’s plumbing-level flexibility and porcelain-level usability, with no clear path to reconcile the two without breaking backward compatibility. For now, the workarounds remain the best solution for users who want cleaner log output.
