This is the third and final patch in Junio C Hamano’s v2 series fixing Bash completion for `git checkout`. It adds a fallback to untracked paths when no tracked paths match, completing the series’ goal of making completion behavior more robust and user-friendly.

The patch modifies `_git_checkout()` in `contrib/completion/git-completion.bash` to call `__git_complete_index_file "--others"` if the earlier attempt to complete tracked paths (`__git_complete_index_file ""`) yields no results. This ensures that untracked files in the target directory (including when using `-C <dir>`) are offered as completion candidates only as a last resort. The change is minimal—just four lines of code—but it addresses edge cases where users might want to check out untracked files (e.g., `git -C another-directory checkout untracked-file`).

The test coverage in `t/t9902-completion.sh` is expanded to verify the new behavior. Two new tests confirm that `git checkout u` (where "u" matches no refs or tracked paths) now completes untracked files like `ufile`, and that this works consistently with `--` and `-C <dir>`. The existing test for `-C <path> checkout` is updated to include an untracked file (`ufile`) and verify its completion, alongside tracked and missing files. The tests are thorough, covering both the happy path and edge cases like missing files.

This patch is a pragmatic addition to the series. While Junio notes that the fallback may have limited utility for typical `git checkout` workflows (since untracked files are rarely the target of `git checkout another-branch <path>`), it ensures completion never fails silently. The change aligns with the series’ broader goal of making completion behavior more predictable and consistent with user expectations.
