This is the final patch in Patrick Steinhardt’s four-part series refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternate object directories. The series is part of the broader ODB abstraction effort and has been under review since its v1 submission.

This patch removes the now-unused `alternates_db` field from the `object_database` struct. The field previously tracked the `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variable, but since the series eliminates lazy-loading of alternates (initializing them all upfront in `odb_new()`), the value can now be passed directly to `odb_prepare_alternates()` instead of being stored. The change is mechanical: the patch updates `odb_prepare_alternates()` to accept the alternate database path as a parameter, removes the field from the struct, and adds a comment clarifying why the environment variable does not need reprocessing during cache flushing. The net effect is a small reduction in code complexity (7 lines removed, 2 added).

The patch addresses a question Justin Tobler raised in the v1 review about whether `GIT_ALTERNATE_OBJECT_DIRECTORIES` is still properly handled when flushing caches via `odb_prepare(o, ODB_PREPARE_FLUSH_CACHES)`. Patrick’s response in v2 confirms that alternates are fully initialized during `odb_new()`, and subsequent calls to `odb_prepare_alternates()` only re-read the alternates *file* (not the environment variable), making the field redundant. The added comment in `odb_prepare()` makes this behavior explicit for future maintainers.

No behavioral changes are intended, and the patch is uncontroversial. It follows logically from the architectural shift in patch 2 (eager initialization of alternates) and patch 3 (removal of the `loaded_alternates` field). The series as a whole simplifies the ODB codebase by centralizing alternate initialization and reducing scattered calls to `odb_prepare_alternates()`, though the performance implications of eager loading (e.g., for commands like `git fsck` that previously avoided loading alternates when none were present) remain untested. This patch is ready for integration.
