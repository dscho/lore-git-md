This is the first patch in Patrick Steinhardt’s v2 series refactoring the object database (ODB) subsystem to remove lazy-loading of alternates. It decouples path comparisons for alternate ODB sources from `the_repository`, resolving a long-standing inconsistency in case-sensitivity handling when alternates are registered before repository configuration is parsed.

The patch replaces the existing `khash`-based map (using `fspathhash()` and `fspatheq()`) with a `struct hashmap` that tracks case-sensitivity per ODB. The new implementation resolves `core.ignoreCase` manually during comparisons, avoiding reliance on `repo_ignore_case()`, which may return a default value before configuration is parsed. The change adds 41 lines net (63 insertions, 22 deletions) and introduces new symbols: `source_paths_icase` (a field in `struct object_database`), `odb_source_paths_cmp()`, and `odb_source_by_path_cmp()`.

The motivation is technical correctness: the current code can produce inconsistent deduplication results depending on when alternates are registered. The patch preserves the existing behavior (alternates may still be registered before configuration is parsed) while fixing the case-sensitivity inconsistency. The discussion in v1 confirmed this is an intentional quirk, not a bug.

Patrick acknowledges the added complexity is debatable but defends it as necessary for correctness and as a "safe side" measure against performance regressions in repositories with many alternates. Justin Tobler’s v1 review validated the approach, though he questioned whether the hashmap complexity was justified for a rare edge case. No objections were raised, and the v2 version is unchanged from v1 except for minor commit message clarifications in later patches. The patch is well-motivated and appears ready for integration, though the trade-off between complexity and performance remains a potential discussion point.
