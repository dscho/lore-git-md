This is the tenth patch in Johannes Schindelin’s v3 series fixing unchecked return values reported by Coverity. The series as a whole is a bugfix effort targeting latent error-handling gaps across multiple subsystems.

This patch specifically addresses two functions that read the `BISECT_TERMS` file: `get_terms()` in `builtin/bisect.c` and `read_bisect_terms()` in `bisect.c`. Both functions previously ignored the return value of `strbuf_getline_lf()`, which can return `EOF` if the file is truncated (e.g., due to a crash or disk-full condition). Without the check, the code would proceed with an empty string for the term name, silently producing incorrect results instead of failing visibly.

The fix is straightforward and consistent with the surrounding error-handling patterns. In `get_terms()`, a failed read now returns `-1`, matching the existing behavior for a missing file. In `read_bisect_terms()`, which uses `die()` for all other error paths, the patch adds a descriptive `die()` message when a line cannot be read. The commit message clearly explains the truncation scenario and why the chosen error handling is appropriate for each function.

The patch is well-motivated and uncontroversial. It touches only the bisect subsystem and does not introduce new behavior or on-disk format changes. The error paths are now robust against silent failures, aligning with the defensive patterns used elsewhere in Git. This is a clear improvement and ready for integration.
