This thread is a straightforward documentation fix for the `git diff -l` option, which controls the `rename_limit` setting. The short help message previously suggested that the option disabled all rename/copy detection, when in fact it only limits the *exhaustive* (quadratic-time) portion of the process. Elijah Newren submitted a patch to correct this, replacing the misleading wording with a clearer description: "limit to cheap rename/copy detection if the number of rename/copy targets exceeds this value." This aligns the short help text with the full documentation, which already used the term "cheap" to describe linear-time rename detection methods.
