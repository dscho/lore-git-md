This thread is about a small but persistent source of user confusion: the short help message for `git diff -l` (the `rename_limit` option). The option's help text previously implied it disabled all rename/copy detection, but it actually only affects the *exhaustive* portion of that detection. Elijah Newren submitted a one-line patch to `diff.c` to correct this, aligning the short help message with a 2021 documentation update that already clarified this distinction.

Junio C Hamano replied with a suggestion to simplify the wording further, proposing a more user-friendly phrasing like "limit to exact rename/copy if ..." to avoid technical jargon in the short help. The patch remains uncontroversial and follows settled prior work, with no functional changes or unresolved concerns. The only open question is the exact wording of the help text, which Junio's feedback has elevated from a mechanical alignment to a small design choice about balancing precision and clarity for end users. No new symbols, tests, or files are involved beyond the single-line change to `diff.c`.
