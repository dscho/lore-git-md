This thread is a small but useful documentation fix to `git diff`. Elijah Newren submitted a patch correcting the short help message for the `-l` option, which sets the `rename_limit` for diff operations. The current one-line description misleadingly suggests that the option disables all rename/copy detection, when in fact it only affects the *exhaustive* portion—exact and basename-guided rename detection (both linear-time) still run regardless of the limit. This aligns the short help text with a 2021 documentation update (commit 6623a528e0) that already clarified this distinction in the full man page.

The change is a single-line edit in `diff.c`, replacing "prevent rename/copy detection" with "prevent exhaustive portion of rename/copy detection." There’s no code behavior or test change involved, and the patch is uncontroversial—it’s a follow-up to settled prior work rather than a new feature. No further discussion or revisions are expected.
