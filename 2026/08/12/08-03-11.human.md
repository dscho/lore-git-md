This is the third patch in Johannes Schindelin’s v3 series fixing unchecked return values flagged by Coverity. It addresses a latent bug in the reftable backend where `reftable_writer_new()` ignored initialization failures in `writer_reinit_block_writer()`, potentially returning a partially initialized writer that could later cause memory leaks or undefined behavior.

The fix is straightforward: `reftable_writer_new()` now checks the return value of `writer_reinit_block_writer()` and, on failure, frees the allocated `block` and `writer` structures before propagating the error upward. This ensures no resources are leaked and no invalid writer object is returned. The change is internal to the reftable subsystem and does not affect any public APIs or on-disk formats.

The patch is well-motivated and clearly explained in the commit message, which notes that the issue was surfaced by static analysis (GPT-5.6 Sol and Claude Opus 4.8). It directly resolves a correctness issue identified in the v2 review cycle, where Junio raised concerns about the block-writer’s error handling. The fix is minimal and focused, touching only `reftable/writer.c` and adding just seven lines of code.

This patch is uncontroversial and ready for integration. It is part of a larger, technically complete series that has addressed all open review feedback, and the reftable-specific changes here are consistent with the project’s emphasis on robust error handling.
