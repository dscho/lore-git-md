This is the sixth patch in Johannes Schindelin’s v3 series fixing unchecked return values reported by Coverity. It targets the `git last-modified` command, which walks commit history to report when files were last changed.

The patch adds error checks for `repo_parse_commit()` at three call sites in `builtin/last-modified.c`. Without these checks, a corrupt or missing commit object leaves the commit’s internal fields (parents, tree, date) unpopulated, causing silent misbehavior: the main walk loop treats unparsable commits as root commits (skipping their ancestors), the `--not` exclusion walk stops prematurely (including commits that should be excluded), and `process_parent()` produces incorrect diff results or fails to enqueue ancestors. The fix skips unparsable commits entirely, matching the defensive pattern used in other revision walkers like `limit_list()` and `get_revision_internal()`.

The change is minimal (six lines added) and uncontroversial. It does not alter on-disk formats or introduce new behavior—only ensures that parse failures are handled gracefully. The commit message clearly explains the consequences of the bug and the rationale for the fix, making it easy to assess the patch’s importance. This is a clear bugfix with no downsides, part of a well-scoped series that’s now technically complete and ready for integration.
