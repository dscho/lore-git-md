This is a follow-up in a bug report thread about unexpected Git notes appearing in a custom `git lg` alias. The thread remains under review but is effectively resolved from the user’s perspective.

Marcel Svitalský confirms that D. Ben Knoble’s proposed workarounds—replacing `--all` with `--branches --tags --remotes` or using `--exclude='refs/notes/*' --all`—successfully suppress the spurious notes refs (`refs/notes/rewrite-analytics` and `refs/notes/chatter`) in the alias output. He attributes the notes’ appearance to background tooling (e.g., lazygit or IntelliJ IDEA) without further investigation, accepting that the behavior is environment-specific rather than a Git regression. The thread can now be considered closed, as the user’s immediate usability concern is addressed.

Key technical takeaways for future reference:
- The `--all` flag in `git log` includes *all* refs, including Git notes, which form a disconnected graph.
- GUI tools (Sublime Merge, IntelliJ IDEA) likely filter refs by default, explaining the discrepancy with CLI output.
- Workarounds to exclude notes: `--branches --tags --remotes` (narrower scope) or `--exclude='refs/notes/*' --all` (preserves `--all` coverage while filtering notes).
- The notes themselves are legitimate and not a bug, though their origin (e.g., `rewrite-analytics` or `chatter`) remains unexplored.

No maintainer action is expected, as the issue is resolved through configuration. The thread provides a clear precedent for users encountering similar cosmetic log output issues.
