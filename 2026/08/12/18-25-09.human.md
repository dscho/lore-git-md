This is a security feature patch that adds `http.sslVerifyStatus`, a new boolean configuration option (default `false`) to enable OCSP staple validation in Git’s HTTPS certificate verification. The patch is now in its third iteration, addressing only a test numbering conflict from Junio’s feedback on v2.

The feature targets a specific security gap: Git’s OpenSSL-linked builds ignore stapled OCSP responses, allowing revoked certificates to be accepted. This is particularly relevant for government and FIPS-compliant deployments (e.g., US Department of Defense PKI) where OCSP stapling is mandated. The patch enables staple validation via libcurl’s `CURLOPT_SSL_VERIFYSTATUS`, causing connections to fail if the server does not provide a staple. The design is fail-closed for security but defaults to `false` to avoid breaking remotes that do not support stapling.

The implementation is minimal and well-scoped. It adds the new config key (`http.sslVerifyStatus` and its per-URL override), sets the corresponding libcurl option, and fails loudly if the TLS backend cannot check staples. The test coverage is thorough, exercising the fail-closed path and per-URL configuration. The patch is ready for review beyond procedural feedback, with the substantive discussion now focused on whether the maintenance burden is justified by the use case.

This looks like a clean, well-motivated contribution that addresses a real security concern for a specific audience. The author has responded effectively to earlier skepticism by providing concrete evidence of the feature’s practical value.
