This is a v2 of a two-patch test fix series targeting the flaky `maintenance.strategy` test in `t/t7900-maintenance.sh`. The series is now ready for integration after addressing minor feedback on commit message wording.

The core issue remains a race condition between the foreground test process and the auto-detaching background maintenance logic in `git maintenance`, which has caused flaky CI failures (e.g., GitLab job #15762975482). Patch 1/2 refactors three tests to use throwaway repositories instead of the default trash directory, making them more self-contained and isolating environment changes. The commit message now explicitly explains why `test_config` was replaced with `git config set`: `test_config` relies on `test_when_finished` cleanup, which doesn’t work in subshells, and the throwaway repository’s `rm -rf` cleanup makes per-config cleanup unnecessary.

Patch 2/2 fixes the flake by restoring the default test suite behavior (auto-detach disabled) and only enabling auto-detach in the specific tests that require it. This eliminates the race condition caused by the `maintenance.lock` file from concurrently running detached tasks. The commit message was updated to clarify the root cause (a concurrently running `git-maintenance` process) and the role of `GIT_TEST_MAINT_AUTO_DETACH`.

The series touches only `t/t7900-maintenance.sh` (46 insertions, 30 deletions) and makes no user-visible behavior changes. Key technical details for follow-up discussion include:
