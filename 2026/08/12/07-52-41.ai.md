This is the first patch in Johannes Schindelin’s 12-patch **platform compatibility** series, which upstream Git for Windows build and runtime adjustments. This specific patch enables Python support in MinGW builds by removing the `NO_PYTHON` flag from `config.mak.uname` for the MINGW platform.

The change is minimal: a single line (`NO_PYTHON =`) is added to the MINGW section of `config.mak.uname`, allowing Git to build with Python support when compiled on Windows. The motivation is practical: while Git for Windows does not ship Python (to save bandwidth), MSYS2 provides Python interpreters that users can install separately. Enabling Python support in the build allows users to leverage these interpreters within Git for Windows’ SDK environment.

This patch has no effect on non-Windows platforms and introduces no new symbols or behavior changes. It is a straightforward build-system adjustment, well-motivated by the real-world need to support Python in MSYS2-based Windows builds. The commit message is clear and self-contained, though it could have briefly noted that this reverses a long-standing exclusion of Python from MinGW builds.

If you care about Windows build flexibility or Python integration, this patch is worth noting; otherwise, it can be safely ignored. The series as a whole remains under review, with no unresolved technical concerns for this specific patch.
