This is a performance bugfix targeting the packfile subsystem, authored by Johannes Schindelin.

The patch addresses a severe performance regression introduced in Git v2.53 (commit 589127caa730, October 2025) that causes quadratic-time behavior when loading many packfiles. The regression surfaces in repositories with tens of thousands of packfiles—common in large monorepos—where simple operations like `git rev-parse --short HEAD` (used in shell prompts) slow from 0.4 seconds to 4.5 seconds, and clones balloon from under 2 minutes to over 30 minutes.

The root cause is a linear scan performed before every packfile insertion to check for duplicates. The fix adds a fast path: callers can now declare a packfile as "known-new," skipping the scan. The patch updates the `packfile_list_append()` signature to accept an `is_new` flag and modifies the sole current caller (`packfile_store_add_pack()`) to use it. The change is minimal and backward-compatible, preserving the existing API for external callers.

A new perf test (`p5303-many-packs.sh`) measures the impact on `git rev-parse --short HEAD` with 10,000 packs, providing a baseline for future regression checks. The fix is well-motivated, clearly explained, and targets a real-world pain point reported by Microsoft’s Git team. It looks ready for review and likely to be uncontroversial.
