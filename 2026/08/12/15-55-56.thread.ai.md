Subject: [PATCH] bundle-uri: restrict advertised bundle URIs by protocol allow-list
Series version: standalone patch (no series)
Originating author: Johannes Schindelin (via GitGitGadget)
Thread type: security bugfix (CVE-2026-62960)

Core problem or goal
Prevent Git from automatically fetching bundle URIs advertised by servers unless their protocol is explicitly allowed by Git’s `protocol.*.allow` configuration. The immediate security concern is blocking "file" URIs (including Windows UNC paths) that could leak NTLM credentials via outbound SMB connections. The fix is narrowly scoped to the clone/fetch code path (`fetch_bundle_list()`), leaving `ls-remote` and user-supplied `--bundle-uri` arguments unaffected.

Current status
Under review. The patch has been privately reviewed in a GitHub security advisory and was already released in Git for Windows v2.55.0(4), but has not yet appeared in Junio’s "What's cooking" report or integration branches.

Key technical details
- **Files touched**: `bundle-uri.c` (core logic), `t/lib-bundle-uri-protocol.sh` (new test file).
- **New functions**: `bundle_uri_protocol()` (extracts protocol from URI), `sanitize_bundle_list()` (filters disallowed URIs using existing `is_transport_allowed()` logic).
- **New symbols**: none (functions are static).
- **Behavior change**: Advertised bundle URIs are now filtered by `protocol.*.allow`; skipped URIs trigger a warning. User-supplied `--bundle-uri` arguments bypass the check.
- **On-disk format**: no changes.
- **Test coverage**: new test file verifies blocking of local paths, `file://` URIs, and UNC paths (on Windows), with and without `protocol.file.allow=always`.
