This is the eleventh patch in Johannes Schindelin’s v3 series fixing unchecked return values identified by Coverity. It targets the bisect subsystem, where six callers of `get_terms()` silently discard its return value, leading to confusing downstream behavior when the `BISECT_TERMS` file is missing or truncated—empty term strings produce nonsensical ref names like `refs/bisect/` with no suffix.

The patch extends `get_terms()` to accept a `file_missing_is_ok` flag, allowing one caller (`bisect_terms()`) to treat a missing file as an error while the others treat it as non-fatal. All call sites now check the return value and propagate errors with a consistent error message. The change is minimal (15 insertions, 9 deletions) and confined to `builtin/bisect.c`, with no new symbols or behavior changes beyond surfacing previously silent failures.

This is a straightforward bugfix that aligns with the series’ goal of hardening error paths. The commit message clearly explains the problem and solution, and the patch itself is uncontroversial—it merely enforces existing error-handling patterns already used elsewhere in the bisect code.
