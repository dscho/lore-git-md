This is the second patch in Patrick Steinhardt’s four-part series refactoring the object database (ODB) subsystem to eagerly load alternate object databases. It is part of the broader ODB abstraction effort and builds on the first patch, which decoupled alternate path comparisons from `the_repository`.

The patch removes 13 scattered calls to `odb_prepare_alternates()` across 10 files, centralizing alternate initialization in `odb_new()` and `odb_prepare()`. This eliminates the lazy-loading optimization, which the commit message argues has become ineffective due to most code paths already parsing alternates eagerly. The change simplifies the codebase by reducing redundancy and potential bugs from missing calls to prepare alternates before iterating through sources. It also prepares the ground for future work to move alternates into the "files" backend.

The diff shows a net reduction of 33 lines (1 insertion, 34 deletions), with changes spanning `builtin/fsck.c`, `builtin/pack-objects.c`, `commit-graph.c`, and other files that previously called `odb_prepare_alternates()` before iterating through ODB sources. The function itself is made static, as it is no longer needed outside `odb.c`. The patch does not introduce new behavior but may have subtle performance implications for commands like `git fsck` that previously avoided loading alternates when none were present.
