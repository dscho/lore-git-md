This is the sixth patch in Johannes Schindelin’s v3 series addressing unchecked return values identified by Coverity. It targets `builtin/last-modified.c`, where three calls to `repo_parse_commit()` previously ignored failures, leading to silent misbehavior in the `git last-modified` command when encountering corrupt or missing commit objects.

The patch adds explicit error checks at all three call sites. In `process_parent()`, a failed parse now causes an early return, skipping the parent entirely. In the main walk loop (`last_modified_run()`), an unparsable commit triggers a jump to the cleanup block, while in the `--not` exclusion walk, the commit is simply skipped. This matches the defensive pattern used elsewhere in Git’s revision walkers and ensures that corrupt commits do not produce incorrect "last modified" results or prematurely terminate exclusion walks.

The change is minimal (six lines added) and purely defensive: no new behavior is introduced, and the command’s output remains unchanged for well-formed repositories. The commit message clearly explains the consequences of the unchecked return values—silent attribution errors, incorrect exclusions, and diff failures—and justifies the chosen remedy (skipping unparsable commits) by analogy to existing code. The patch is uncontroversial and ready for integration, with no open questions or dependencies.
