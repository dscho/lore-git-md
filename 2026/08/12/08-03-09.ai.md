This is the first patch in Johannes Schindelin’s v3 series addressing unchecked return values flagged by Coverity. It targets the HTTP subsystem (`http.c`), specifically the `get_active_slot()` function, which duplicates the default libcurl handle to create per-slot session handles. The patch adds a NULL check for `curl_easy_duphandle()`’s return value and calls `die()` if the handle duplication fails, preventing undefined behavior (and likely crashes) when subsequent libcurl operations are attempted with a NULL handle.

The fix is minimal and mechanical: two lines added to an existing conditional block. The commit message clearly explains the risk (out-of-memory conditions leading to NULL handles) and the rationale for `die()` (no reasonable recovery path). This aligns with the series’ goal of hardening error paths without changing behavior or on-disk formats. The HTTP subsystem is critical for all remote operations over HTTP/HTTPS, so the patch addresses a latent crash vector in a high-impact area.

No new symbols or APIs are introduced, and the change is uncontroversial. The patch is ready for integration as part of the broader series, which has already resolved all open correctness issues from earlier revisions. Future discussion may reference the function name (`get_active_slot`) or the file (`http.c`).
