This is a bugfix patch (part 7/12 in v3 of the Coverity unchecked return values series). It targets the `compat/pread.c` subsystem, which provides a portable `pread()` implementation for platforms that lack it.

The patch addresses a latent bug in `git_pread()`: the function saves the current file offset via `lseek(fd, 0, SEEK_CUR)` but does not check whether the call succeeds. If the descriptor is non-seekable (e.g., a pipe), `lseek()` returns `-1`, leaving `current_offset` set to an invalid value. This negative offset is later passed to `lseek(fd, -1, SEEK_SET)`, which either sets the file position to an unintended location or fails with `EINVAL` on some platforms. The fix adds a two-line check that returns `-1` immediately if the initial `lseek()` fails, matching the existing error handling for the other `lseek()` calls in the function.

The commit message is clear and concise, naming the function (`git_pread()`), the file (`compat/pread.c`), the specific error path (initial `lseek()`), and the consequence (unintended file position). It also credits Coverity and Claude Opus 4.6 for identifying the issue. The patch is mechanical and uncontroversial, touching only the error-handling path without changing behavior for seekable descriptors. No new config keys, options, or on-disk formats are introduced, and the fix is exercised by any code path that calls `git_pread()` on a non-seekable descriptor.
