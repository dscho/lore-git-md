This is a brief follow-up in the ongoing Bash completion thread. Junio C Hamano clarifies a technical point about the earlier discussion of completing paths from arbitrary trees (e.g., `git checkout other-branch:foolish`). He acknowledges Ben Knoble’s suggestion that similar functionality exists for `git show <tree>:<path>` but explains that the existing machinery isn’t reusable for `git checkout`. The distinction is subtle but important: the completion logic for `git show` handles a single `<tree>:<path>` argument, while `git checkout` requires separate handling of a tree-ish and a path, which isn’t currently supported in the Bash completion script. The exchange doesn’t propose any changes to the current patch series, which remains focused on fixing `git checkout -C <dir>` path completion to suggest only tracked files. The thread is now effectively closed, with no further action expected on the enhancement idea.
