This is the fourth and final patch in Patrick Steinhardt’s four-part series refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternate object databases. The patch itself is a mechanical cleanup: it removes the now-unused `alternates_db` field from the ODB structure and updates `odb_prepare_alternates()` to accept the alternate database path as a parameter (passed via `odb_new()`) instead of reading it from the struct.

Justin Tobler’s review raised a clarifying question about whether the `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variable is still properly handled when flushing caches via `odb_prepare(o, ODB_PREPARE_FLUSH_CACHES)`. Patrick confirms that alternates are fully initialized during `odb_new()` and that subsequent calls to `odb_prepare_alternates()` only re-read the alternates *file* (not the environment variable), since the environment variable is not expected to change during a process’s lifetime. He plans to add a comment to clarify this.

The patch is uncontroversial and aligns with the series’ goal of simplifying the ODB codebase. The discussion here is purely about confirming the reasoning behind the change, not about correctness or performance trade-offs. If the earlier patches in the series hold up under review, this one should too. The entire series is part of Patrick’s broader ODB abstraction effort, which aims to make Git’s object storage layer more modular.
