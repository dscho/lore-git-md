This is the first patch in Johannes Schindelin’s 12-patch v3 series hardening Git against unchecked return values reported by Coverity. It fixes a potential crash in the HTTP transport layer by adding a missing NULL check for `curl_easy_duphandle()` in `get_active_slot()`.

The patch is a straightforward bugfix: `curl_easy_duphandle()` can return NULL on memory allocation failure, but the code previously used the result without checking, leading to undefined behavior when `curl_easy_setopt()` is called with a NULL handle. The fix adds a `die()` call with a clear error message, which is the appropriate response since the process cannot recover from an out-of-memory condition during HTTP operations. This affects all HTTP-based Git operations (clone, fetch, push, bundle-uri downloads).

The change is minimal (two lines added) and uncontroversial. The commit message clearly explains the problem, the potential impact, and the rationale for the chosen solution. This patch is part of a larger, well-scoped series that addresses Coverity-reported issues in a mechanical way, with each patch targeting a single unchecked return value. The series has already addressed all open correctness issues from earlier revisions and is now ready for integration.
