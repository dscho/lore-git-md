This is a v2 patch series from Junio C Hamano that refines Bash completion for `git checkout` (with or without `-C <dir>`). The series now consists of three patches: the first is a no-op refactoring, the second fixes the core issue (completing only tracked paths), and the third adds a fallback to untracked paths as a last resort. The series builds on the earlier `git diff` completion fix and is rebased onto the `complete-diff` topic for better test organization.

Patch 1/3 restructures `_git_checkout()` to avoid an early return when `--` is detected, making the logic clearer without changing behavior. Patch 2/3 modifies the function to use `__git_complete_index_file ""` (equivalent to `--cached`) when no revision matches the input, ensuring only tracked paths are suggested. The tests in `t/t9902-completion.sh` verify that `git checkout f` (no refs matching "f") completes only tracked paths (`file1`, `file2`) and ignores untracked files, and that `git -C <path> checkout o` completes tracked paths in the specified repository.

Patch 3/3 is new in v2 and adds a fallback to untracked paths when no tracked paths match. This is a pragmatic addition, though Junio notes it may have limited utility since untracked files are unlikely to be the target of `git checkout another-branch <path>`. The range-diff shows the key change in patch 2/3: replacing `__git_complete_index_file` with `__git_complete_index_file ""` to enforce tracked-path completion, along with expanded test coverage for edge cases like missing files (`lostfile`).
