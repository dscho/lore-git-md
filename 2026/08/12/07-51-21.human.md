This is a **platform compatibility** follow-up in the MinGW/Windows build adjustment series. Johannes Schindelin responds to Junio C Hamano’s review of the final patch (12/12), which allows `git.exe` to be invoked directly instead of through the Git wrapper. The exchange centers on a correctness edge case: whether the build system should guard against exporting an empty `MSYSTEM` environment variable if `$(MSYSTEM)` is undefined or empty at build time.

Junio’s review identified that the current patch could export `MSYSTEM` as an empty string, which might not be a "sane state" for scripts that rely on it as an indicator. Johannes pushes back, calling the wording "quite the strong wording for such a minor issue" and noting that Git itself tolerates empty or nonsensical `MSYSTEM` values. He argues that the scenario is unlikely—requiring deliberate action by the builder—and that the primary goal is ensuring the `PATH` is set correctly by prepending the MSYS2 `bin/` directories.

The technical crux is whether the Makefile’s `COMPAT_CFLAGS` definition for `ENSURE_MSYSTEM_IS_SET` should replicate the `ifneq (,$(MSYSTEM))` guard used elsewhere in `config.mak.uname`. Junio suggests it should, to prevent the empty-string export; Johannes dismisses the concern as not worth additional complexity. No code changes are proposed in this email, and the disagreement remains unresolved. If you are tracking Windows compatibility or build-system hygiene, this is a minor but open design question; otherwise, it is a routine review exchange unlikely to derail the series.
