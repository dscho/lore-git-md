This is a **bugfix review** targeting a type mismatch in the new `list_objects_filter__filter_oidset()` helper introduced in patch 2/7 of the `--drop-filtered` series. The issue is subtle but important: `struct object_info` expects `size_t *` for its `sizep` field, but the code passes the address of an `unsigned long` variable. While this works on most platforms (where `size_t` and `unsigned long` are the same size), it violates strict aliasing rules and could cause problems on platforms where they differ (e.g., Windows 64-bit, where `size_t` is 64-bit but `unsigned long` is 32-bit).

Junio flags this as a correctness issue, not a style nit. The fix is straightforward: change the local variable `size` from `unsigned long` to `size_t`. This aligns with the API contract of `struct object_info` and ensures portability. The patch is otherwise well-structured, but this oversight could lead to silent data corruption or crashes on affected platforms, making it a blocking issue for merging.

The review is **substantive** and **tested** (Junio clearly checked the API definition and considered platform implications). This is not a matter of taste or style; it’s a real bug that needs to be fixed before the series can proceed. The author should address this in a v5 iteration.
