This is a test fix series targeting a flaky test in `t/t7900-maintenance.sh`. The v2 iteration addresses minor feedback on commit messages and is now ready for integration.

The series fixes a race condition in the "maintenance.strategy" test where the auto-detaching background maintenance logic in `git maintenance` sometimes interferes with the foreground test process. The flake has been observed in GitLab CI (linked in the cover letter), making this a practical reliability improvement for the test suite. No user-visible behavior changes are involved—this is purely a test hygiene fix.

Patch 1 refactors three tests to use throwaway repositories instead of the default trash directory, isolating test state and making the environment modifications in patch 2 safer. The commit message now clearly explains why `test_config` was replaced with `git config set`: `test_config` relies on `test_when_finished`, which doesn’t work in subshells, and the throwaway repository already handles cleanup via `test_when_finished "rm -rf repo"`.

Patch 2 directly resolves the flake by restoring the default (auto-detach disabled) behavior for the test script and only enabling auto-detach in the specific tests that need it. This eliminates the race condition caused by the `maintenance.lock` file from concurrently running background tasks. The commit message was tweaked to improve clarity about the root cause (a concurrently running `git maintenance` process).

The series is uncontroversial, well-motivated, and narrowly scoped. Both patches have received substantive review from Karthik Nayak, who confirmed the approach is correct. The only feedback was minor wording improvements to the commit messages, which Patrick incorporated. This looks like a clean, low-risk fix for a real CI pain point.
