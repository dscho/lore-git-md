This is the tenth patch in Johannes Schindelin’s v3 series fixing unchecked return values reported by Coverity. It targets the bisect subsystem, specifically the functions `get_terms()` (in `builtin/bisect.c`) and `read_bisect_terms()` (in `bisect.c`), both of which read the `BISECT_TERMS` file but previously ignored the return value of `strbuf_getline_lf()`.

The patch adds explicit checks for `EOF` when reading each line of the `BISECT_TERMS` file. In `get_terms()`, a truncated file (e.g., due to a crash or disk-full condition) now causes the function to return `-1`, matching the existing behavior for a missing file. In `read_bisect_terms()`, which uses `die()` for all error paths, the patch instead calls `die()` with a descriptive message when a line cannot be read, consistent with the existing `die_errno` for open failures. The change ensures that empty or truncated `BISECT_TERMS` files do not silently produce empty term names (e.g., `""` instead of `"bad"` or `"good"`), which could lead to confusing or incorrect bisect behavior.

The fix is minimal and mechanical, touching only the two functions that read `BISECT_TERMS`. No new symbols or on-disk formats are introduced, and the error handling aligns with the existing patterns in each function. The commit message clearly explains the truncation scenario and the rationale for the chosen error paths. This patch, like the rest of the series, is uncontroversial and ready for integration. Future discussion is likely to reference the filenames (`bisect.c`, `builtin/bisect.c`) or the specific functions (`get_terms`, `read_bisect_terms`).
