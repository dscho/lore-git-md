This is a **security feature patch** under review, focusing on the new `http.sslVerifyStatus` option to validate OCSP staples in Git's HTTPS connections. The patch itself is well-crafted, with thorough testing and documentation, but Patrick Steinhardt's reply raises substantive questions about its practical value and design choices.

The core issue is that Git currently ignores OCSP staples—revocation status information sent by the server—leaving it vulnerable to accepting revoked certificates. The patch adds a boolean config option (defaulting to `false`) to enable staple validation via libcurl's `CURLOPT_SSL_VERIFYSTATUS`. This is a fail-closed design: if the server doesn't provide a staple, the connection fails. The default is `false` to avoid breaking remotes that don’t support stapling, and the option can be set per-URL (e.g., `http.https://example.com/.sslVerifyStatus`).

Patrick’s review questions the patch’s real-world impact. He notes that the option doesn’t resolve the behavioral difference between OpenSSL (which ignores staples unless explicitly enabled) and GnuTLS (which checks them by default). With the default set to `false`, OpenSSL continues to ignore staples, while GnuTLS still enforces them—so the inconsistency remains. Enabling the option globally would break remotes that don’t staple, and per-host configuration is unlikely to see widespread adoption. He also points out that OCSP stapling is being phased out (e.g., Let’s Encrypt dropping support), which further limits the feature’s long-term utility.

The review asks a direct question: *who is this feature for?* The patch’s fail-closed design and per-host configuration make it impractical for most users, and the security benefit is minimal unless users actively opt in. The author’s rationale (in the commit message) explains the technical gap but doesn’t address whether there’s a concrete use case driving this change. The discussion now hinges on whether the patch solves a real problem or is a theoretical improvement with limited adoption potential. The ball is in the author’s court to clarify the intended audience or adjust the design.
