This is the third iteration of Johannes Schindelin’s 12-patch series fixing unchecked return values reported by Coverity. The series is now complete: all open correctness issues from v2 have been resolved.

The new third patch (“reftable: handle block-writer initialization errors”) splits the previous v2 patch 3 into two commits. The first (new) commit moves the `REFTABLE_CALLOC_ARRAY` allocation into `block_writer_init()` and makes the function return an error if the allocation fails, ensuring the `block_writer` is never left in a half-initialized state. The second commit (formerly v2 patch 3) adds the `deflateInit()` check and now also frees the `zstream` memory if initialization fails, closing the memory-leak Junio identified.

The eleventh patch (formerly v2 patch 11, now patch 12) now closes the file-descriptor leak Jeff King spotted: if `dup2()` fails, the code closes `saved_stdout` before breaking out of the bisect-run loop. Junio’s question about checking the return value of `close(temporary_stdout_fd)` is left unaddressed in this version; the patch simply calls `close()` without inspecting its return code.

All other patches are unchanged from v2. The series touches ten files across HTTP, config, reftable, last-modified, compat/pread, transport-helper, and bisect subsystems, adding only fatal error paths (`die()`) or propagation to the caller. No new behavior, config keys, or on-disk formats are introduced. The patches are small, mechanical, and well-motivated; the series looks ready for integration once Junio’s final nit is resolved.
