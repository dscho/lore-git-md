This is the second patch in a two-patch test fix series (v2) targeting a flaky test in `t/t7900-maintenance.sh`. The series is ready for integration and addresses a race condition in CI that causes intermittent failures in the `maintenance.strategy` test.

The patch fixes the flake by restoring the default test suite behavior (auto-detach disabled) and only enabling auto-detach in the three tests that explicitly require it. The root cause is a `maintenance.lock` file left by a detached background `git-maintenance` process triggered by `test_commit()`, which races with the foreground test. The fix isolates the auto-detach logic to where it is needed, eliminating the race without changing user-visible behavior. The commit message now clearly documents the root cause (a concurrently running `git-maintenance` process) and the role of `GIT_TEST_MAINT_AUTO_DETACH`.

The patch touches only `t/t7900-maintenance.sh` (3 insertions, 3 deletions) and is uncontroversial. It follows the refactoring in patch 1/2, which prepared the test file by converting three tests to use throwaway repositories and subshells. Key technical details for follow-up discussion include the environment variable `GIT_TEST_MAINT_AUTO_DETACH`, the config keys `maintenance.auto` and `gc.auto`, and the race condition involving the `maintenance.lock` file. The fix has been substantively reviewed by Karthik Nayak, who confirmed the approach and suggested minor commit-message wording improvements that were incorporated.
