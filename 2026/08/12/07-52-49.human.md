This is the ninth patch in Johannes Schindelin’s 12-patch **platform compatibility** series, which upstream Git for Windows build and runtime adjustments into the main Git codebase. This specific patch disables the generation of hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/` for Windows builds.

The change is a long-overdue cleanup: the "dashed form" of Git commands has been deprecated since Git 1.5.4 (February 2008), but the hard links have persisted for backward compatibility. On Windows, these links add a 30-second build-time overhead, confuse disk-usage tools, and generate frequent "bug" reports. The patch sets `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname` for both `Windows` and `MINGW` environments, which prevents the build system from creating the links. The value is arbitrary (a placeholder to trigger the skip logic) and has no functional impact beyond disabling the links.

This is a **Windows-only change** with no effect on other platforms. The `git` executable’s built-in command dispatch remains fully functional, so end users should notice no difference. Junio C Hamano’s review of the v1 series suggested that the dashed-form executables could be removed entirely in Git 3.0, but this patch only skips their generation for Windows builds—aligning with the series’ goal of incremental, low-risk adjustments.

The patch is well-motivated and uncontroversial. If you maintain Windows builds or care about build-time optimizations, this is worth noting; otherwise, it’s a safe, routine cleanup that can be ignored. The series as a whole remains under review, with no merge status reported.
