This is a **bugfix** targeting the packfile subsystem, authored by Johannes Schindelin. It addresses a severe performance regression introduced in Git v2.53 (commit `589127caa730`, October 2025) that causes quadratic-time behavior (`O(N²)`) when loading many packfiles. The regression was reported in Microsoft’s Git fork, where a simple `git rev-parse --short HEAD` (commonly used in shell prompts) slowed from 0.4s to 4.5s with 37,815 packfiles, and clone times ballooned from under 2 minutes to over 30 minutes in CI scenarios.

The root cause is `packfile_store_add_pack()`’s linear scan of the packfile list before each insertion to check for duplicates. The fix adds a fast path by extending `packfile_list_append()` with an `is_new` parameter, allowing callers to skip the scan when the packfile is known to be new. The patch updates the sole current caller (`packfile_store_add_pack()`) to use this fast path and adds a new perf test (`p5303-many-packs.sh`) to measure `git rev-parse --short HEAD` performance with 10,000 packs.

The change is minimal and targeted: it modifies only the packfile list management logic, preserves the existing API for external callers (via a backward-compatible signature change), and includes a regression test. The commit message clearly documents the problem, the fix, and the rationale for the API design. This is a well-motivated, production-critical fix likely to be uncontroversial.
