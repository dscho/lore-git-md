This is the first patch in a five-part **bugfix series** targeting the merge machinery. It is a **refactoring patch** that clarifies naming to better reflect the intent of existing code. Specifically, it renames `FROM_REBASE_PICK` to `FROM_REBASE_EMPTY` and `is_from_rebase()` to `is_from_rebase_empty()` to make it clear these symbols are about commits that become empty during a rebase, not about rebase operations in general. The patch also replaces direct enum checks with the renamed helper function.

The changes are mechanical and touch `builtin/commit.c`, `sequencer.c`, and `wt-status.h`. There is no behavior change—this is purely about improving code clarity. The patch addresses feedback from Junio C Hamano, who requested these renames in earlier review rounds to avoid confusion. This preparatory work sets the stage for the later patches in the series, which extend Git's protection against unsafe commit operations during conflict resolution.

The patch is uncontroversial and well-motivated. It is part of a larger, technically sound effort to prevent users from accidentally corrupting repository state during conflict resolution. Since this is a pure refactoring with no functional impact, it could likely be merged independently if needed, but it is intended to be part of the full series. The series as a whole is now ready for final review and is likely to proceed to `next`.
