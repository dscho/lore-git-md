This is the final patch in Junio C Hamano’s eight-part series refactoring the `git checkout`, `git switch`, and `git restore` internals. It moves the `post_checkout_hook()` function from `builtin/checkout.c` to the new top-level `checkout.c` file and declares it in `checkout.h`, making it available to other parts of Git without requiring a dependency on the built-in command code.

The patch itself is small and mechanical: 18 lines removed from `builtin/checkout.c`, 22 lines added to `checkout.c`, and 8 lines added to `checkout.h`. The function’s logic is unchanged; it still runs the `post-checkout` hook with the same arguments (old commit OID, new commit OID, and a boolean indicating whether files changed). The only difference is that the function now lives in a shared utility file rather than being buried inside the built-in command.

Junio explicitly calls this step “optional” and includes it primarily for illustration. The immediate motivation is to demonstrate how libification works in practice: reusable logic is extracted from built-in commands into standalone helpers that can be called by any subsystem. A potential future use case mentioned in the commit message is teaching `git worktree` to trigger the `post-checkout` hook, which would be easier if the hook logic is available in a shared location.

This patch completes the architectural shift begun in the sixth patch, where the monolithic `checkout_main()` choke point was eliminated. By moving `post_checkout_hook()` to `checkout.c`, the series reinforces the pattern of placing reusable logic in top-level files rather than inside built-in commands. The change is consistent with the broader `the_repository` removal effort and the recent architectural clarification that built-in commands should not be libified, but their internals should be.

The patch is uncontroversial and passes the test suite. It does not change CLI behavior or on-disk formats, and the libification is purely internal. The main value of this patch is as a template for similar refactorings in other built-in commands, showing how to extract and expose reusable logic without disrupting existing functionality.
