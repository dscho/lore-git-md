This is the fifth patch in Junio C Hamano's 8-patch series refactoring the `git checkout`, `git switch`, and `git restore` internals to eliminate the monolithic `checkout_main()` function. The patch extracts branch setup and tracking logic into three new static helper functions in `builtin/checkout.c`: `validate_branch_options()`, `dwim_branch_track_option()`, and `setup_branch_name_and_info()`. These helpers isolate the validation of branch-creation options (`-b`, `-B`, `--orphan`), the DWIM inference of branch names from `--track`, and the parsing of branch name arguments, respectively. The patch moves roughly 50 lines of logic out of `checkout_main()` and into the new helpers, improving code organization and readability without changing CLI behavior.

The patch is a direct continuation of the libification path established in the parent thread, where reusable logic is factored out of built-in commands into standalone helpers. Here, the focus is on branch-related logic, which was previously entangled with pathspec handling and option validation in `checkout_main()`. The extracted helpers are called from `checkout_main()` and accept the same parameters, ensuring the refactoring is mechanical and passes the test suite. The patch does not introduce new top-level files (unlike later patches in the series) but lays the groundwork for further extraction by isolating branch setup logic.

The patch is uncontroversial and self-contained, touching only `builtin/checkout.c` and maintaining the existing behavior. It complements the fourth patch in the series, which extracted pathspec and option validation helpers, and prepares for the sixth patch, which will rewrite the top-level command entry points to call these helpers directly. The extracted functions are static and not yet intended for external use, but their isolation aligns with the series' goal of making reusable logic available to both built-in commands and external programs.

No objections or alternatives have been raised for this patch, and its focus on branch setup logic is consistent with the architectural direction of the series. The patch is part of the broader `the_repository` removal effort, as the extracted helpers could later be modified to accept a `struct repository *` parameter, though this patch does not yet make that change.
