This is Junio’s "What’s cooking" report for August 2026 (#12), summarizing the state of integration branches and in-flight topics. The report is **not a patch** but a high-level snapshot of the project’s current activity, aimed at contributors tracking what is queued, cooking, or stalled.

The report lists 567 non-merge commits in `master` since Git 2.55, with 76 topics in `next` and 215 in `seen`. Two topics graduated to `master` this cycle: a documentation fix for `git format-rev` (kh/format-rev-doc-synopsis) and a heap-use-after-free fix in object name parsing (sk/object-name-use-after-free). Both are small, targeted fixes with clear motivation and no controversy.

New topics this cycle include:
- **jc/die-for-incompatible-opts**: A refactoring that generalizes the `die_for_incompatible_opt[234]()` family to handle an unbounded number of mutually exclusive options via variadic arguments. This is a clean plumbing improvement with no user-visible behavior change.
- **jc/you-still-use-that**: A rewording of the deprecation notice for obsolete commands, making the removal decision more explicit and the replacement guidance more assertive. This is a documentation-adjacent change with no code impact.
- **ws/squelch-svn-migrate**: Adds a `NO_GIT_SVN` build knob to skip building `git-svn` and silences the v1-layout migration noise when there is nothing to migrate. This is a build system and user-experience improvement, motivated by reducing noise in environments where `git-svn` is unused.

Stalled topics (those waiting for author response for an extended period) include:
- **ec/commit-fixup-options**: Extends `--fixup` to support `-m`, `-F`, `-c`, and `-C` for all fixup variants. The topic is technically sound but has been stalled since May 2026, likely due to lack of reviewer bandwidth or unresolved edge cases.
- **ps/libgit-in-subdir**: Moves `libgit.a` sources into a `lib/` directory. This is a large refactoring that caused integration conflicts and was ejected from `next`; it remains stalled pending a rebase or redesign.
- **tb/pack-with-duplicates**: Hardens packfile handling for duplicate object entries. This is a correctness fix for a subtle edge case but has been stalled since July 2026, possibly due to insufficient test coverage or reviewer skepticism about the approach.

Cooking topics (in `next` or awaiting review) include:
- **kn/reftable-optimize-reloading**: Optimizes reftable stack reloads by avoiding redundant `stat()` calls when the list file is already locked. This is a targeted performance improvement with no behavior change, and it has received positive feedback from Peff.
- **ps/odb-pluggable-pack-generation**: Makes packfile generation pluggable via ODB callbacks, enabling alternative backends to serve packfiles directly. This is part of the ongoing ODB abstraction effort and has been reviewed by Elijah Newren and others.
- **en/no-amend-during-conflicts**: Teaches `commit --amend` and partial commits to refuse operation during conflict resolution, aligning behavior with `cherry-pick` and `merge`. This is a user-facing safety improvement with some discussion about edge cases (e.g., empty commits during rebase).
- **yn/worktree-repair-relative**: Fixes a bug in `git worktree repair` where relative paths in `.git` files were not correctly detected. This is a small bugfix with a clear reproduction case.

Notable stalled or controversial topics:
- **cl/regexec-macos-leak**: A macOS-specific workaround for a TRE regex engine memory leak. The topic has been stalled due to concerns about the complexity of the workaround and whether it should be upstreamed to macOS instead.
- **cc/lazy-fetch-trusted-bit**: Introduces `uploadpack.lazyFetchTrusted` to allow lazy fetches from promisor remotes in trusted repositories. This has been stalled due to security concerns about trusting arbitrary remotes and the lack of a clear threat model.
- **bc/restrict-hex-to-lowercase**: Prepares for Git 3.0 by rejecting uppercase hex characters in object IDs when in breaking-changes mode. This is part of the broader Git 3.0 transition effort but has been stalled due to disagreements about whether the restriction should be opt-in or mandatory.

The report also highlights several large-scale efforts:
- **ODB abstraction** (Patrick Steinhardt): Multiple topics (`ps/odb-alternates-at-creation`, `ps/odb-pluggable-fsck`, `ps/odb-pluggable-pack-generation`) are advancing the pluggable ODB backend work.
- **Reftable backend** (Karthik Nayak): `kn/reftable-optimize-reloading` is a targeted optimization for the reftable stack.
- **Git 3.0 preparation**: `bc/restrict-hex-to-lowercase` is part of the ongoing effort to enforce lowercase-only object IDs in the next major release.

Overall, this cycle is dominated by backend refactoring (ODB, reftable, packfile generation) and targeted bugfixes, with a few user-facing changes (e.g., `en/no-amend-during-conflicts`). The stalled topics suggest areas where the project could benefit from renewed contributor attention, particularly around `git-svn` noise reduction, macOS regex workarounds, and the Git 3.0 transition.
