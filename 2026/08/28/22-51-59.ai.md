This is the first patch in Junio C Hamano’s 8-patch series refactoring the `git checkout`, `git switch`, and `git restore` internals to eliminate the monolithic `checkout_main()` helper. The patch targets a specific piece of technical debt: the file-scope static variable `cb_option`, which records whether a new branch is being created via `-b` (checkout) or `-c` (switch) and is used for error reporting in branch name parsing functions.

The change is a straightforward refactoring: `cb_option` is removed as a file-scope static and instead passed explicitly as a parameter to `parse_remote_branch()` and `parse_branchname_arg()`. The value is now set locally in `checkout_main()` based on the command being executed (`'c'` for `git switch`, `'b'` otherwise) and passed down the call chain. The patch is small (9 insertions, 14 deletions) and mechanical, touching only `builtin/checkout.c`. It does not alter CLI behavior or on-disk formats, and the test suite passes unchanged.

This patch is an isolated cleanup that could stand alone, but it also serves as preparatory work for the larger architectural refactoring in later patches. By eliminating the global mutable state, it makes the code easier to reason about and refactor further, aligning with the series’ broader goal of extracting reusable logic into standalone helpers. The change is uncontroversial and directly addresses a "cheating" pattern (global state) identified in earlier discussions.

The patch is part of the libification effort clarified in the parent thread, where reusable logic is factored out of built-in commands into standalone helpers that accept a `struct repository *` parameter. While this patch does not yet extract any helpers, it removes an obstacle to doing so by eliminating a dependency on file-scope state. The series as a whole is explicitly marked as an early draft for discussion, not for merging to `seen`, due to potential conflicts with in-flight topics. This patch, however, is self-contained and could be merged independently if desired.
