This is the third patch in Elijah Newren’s five-patch **bugfix series** that extends Git’s protection against unsafe commit operations during conflict resolution. The series targets `git commit --amend` and `git commit <paths>` during `git am`, `git revert`, and all forms of `git rebase`, preventing users from accidentally amending the wrong commit or updating individual paths while resolving conflicts.

This specific patch rewords the error message shown when a user attempts `git commit --amend` after a rebase operation drops an empty commit. The new phrasing—**"The now-empty commit has been dropped -- cannot amend."**—is more precise and less misleading than the previous generic message ("You are in the middle of a rebase -- cannot amend."), which incorrectly implied that amending is never allowed during rebase stops (e.g., for `edit` or `break` directives). The change is minimal: one line in `builtin/commit.c` and a corresponding test update in `t/t3404-rebase-interactive.sh`. Junio C Hamano explicitly approves the new wording ("Much less awkward than the previous round"), confirming the patch addresses the **usability concern** raised in earlier reviews.

The patch depends on the preparatory work in patches 1-2/5 (renaming enum values and helpers, and removing the restriction on partial commits for empty commits) but is otherwise self-contained. It is uncontroversial and aligns with the series’ goal of preventing repository corruption by clarifying error messages. The updated phrasing better distinguishes between conflict stops (where amending would affect the wrong commit) and clean interactive rebase stops (where amending is allowed). The test adjustment ensures the new message is covered.

No further changes are expected; this patch is ready for integration and likely to proceed to `next` alongside the rest of the series. The **key symbols** introduced or modified include the error message in `builtin/commit.c` and the test case in `t/t3404-rebase-interactive.sh`. The series as a whole touches `sequencer.c`, `sequencer.h`, and `wt-status.h`, consolidating logic for detecting active operations via `sequencer_ongoing_operation()`.
