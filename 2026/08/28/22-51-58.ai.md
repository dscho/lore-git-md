This is a major refactoring series from Junio C Hamano that restructures the `git checkout`, `git switch`, and `git restore` code to eliminate the monolithic `checkout_main()` choke point. The series is explicitly part of the libification effort clarified in recent threads, where reusable logic is factored out of built-in commands into standalone helpers that accept a `struct repository *` parameter.

The series consists of eight patches. The first three are isolated cleanups that could stand alone: passing `cb_option` explicitly to branch name parsers, validating the new branch name in `checkout_branch()`, and validating stage/merge option compatibility in `checkout_paths()`. Patches 4 and 5 extract utility functions for option validation, pathspec handling, branch setup, and tracking. Patch 6 is the core refactoring: it rewrites the three top-level command entry points (`cmd_checkout()`, `cmd_switch()`, `cmd_restore()`) to call the extracted helpers directly, bypassing `checkout_main()`. Patch 7 is a post-refactoring style cleanup, and patch 8 moves `post_checkout_hook()` to `checkout.c` as an illustration of libification.

The series touches `builtin/checkout.c` heavily (545 lines changed) and introduces new top-level files `checkout.c` and `checkout.h`. It does not change CLI behavior or on-disk formats, but it is a large-scale architectural change that affects how the three commands are implemented. Junio explicitly marks this as an early draft for illustration, not for merging to `seen`, due to potential conflicts with in-flight topics. The refactoring aligns with the recent architectural direction: built-in commands are not libified, but their reusable logic is extracted into standalone helpers that can be called by both built-ins and external programs.

The series directly addresses the "cheating" pattern identified in earlier threads, where `git switch` and `git restore` were bolted onto `git checkout` via a monolithic helper. By eliminating `checkout_main()` and allowing each command to call the appropriate backend (`checkout_branch()` or `checkout_paths()`) directly, the code becomes more modular and easier to maintain. The final patch demonstrates the libification goal by moving a helper to a top-level file, reinforcing the architectural shift toward reusable utility functions.
