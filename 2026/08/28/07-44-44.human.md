This is the fourth patch in a five-patch **bugfix series** that extends Git's existing protection against unsafe commit operations during conflict resolution. Specifically, this patch blocks `git commit --amend` during conflict resolution for `git am`, `git revert`, and all forms of `git rebase` (both apply and merge backends), preventing users from accidentally amending the wrong commit and corrupting repository state.

The patch introduces a new helper function, `sequencer_ongoing_operation()`, which consolidates logic for detecting active operations that record their results as new commits on top of HEAD. This function distinguishes between genuine conflict stops (where amending would be unsafe) and clean interactive rebase stops (e.g., `edit`, `break`, `squash`, `reword`), where amending is expected and allowed. The logic relies on the presence or absence of specific files in the `rebase-merge/` and `rebase-apply/` directories (`stopped-sha` and `amend` for the merge backend, `applying` for the apply backend) to determine the context.

The commit message explains the rationale clearly: amending during conflict resolution is a "foot-gun" that can lead to repository corruption, and this patch closes a gap in Git's existing protections (which previously only covered merges and cherry-picks). The implementation is careful to avoid breaking interactive rebase workflows, where `git commit --amend` is a legitimate and expected operation.

Test coverage is thorough, with new tests in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh` verifying that the restriction works as intended for all affected commands while preserving expected behavior for interactive rebase directives. The error messages are specific and actionable, guiding users toward the correct workflow.

This patch is technically sound and addresses a real usability hazard. The preparatory patches (1-2/5) have already resolved the last substantive technical questions, and this patch is narrowly focused on extending the existing protection logic. The series is now ready for final review and likely to proceed to `next`. If you care about merge/rebase safety or have ever accidentally amended the wrong commit during conflict resolution, this patch is worth your attention.
