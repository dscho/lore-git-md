This is a refactoring series from Junio C Hamano that restructures the `git checkout`, `git switch`, and `git restore` code to eliminate the awkward monolithic `checkout_main()` choke point. The goal is to make the three commands more independent and the codebase cleaner by having `cmd_switch()` and `cmd_restore()` call the appropriate backend helpers (`checkout_branch()` or `checkout_paths()`) directly, rather than funneling everything through `checkout_main()`.

The series starts with three small, self-contained cleanups (patches 1–3) that improve option validation and could stand alone. Patches 4 and 5 extract utility functions for option validation, pathspec handling, branch setup, and tracking. Patch 6 is the core refactoring: it rewrites the three command entry points to bypass `checkout_main()` entirely. Patch 7 is a cosmetic cleanup, and patch 8 moves one helper function to a top-level file as a step toward libification, illustrating the architectural direction discussed in recent threads.

Junio explicitly marks this as an early draft for illustration, not for merging to `seen` yet. The changes are mechanical and pass the test suite, but the scale of the refactoring could interact poorly with other in-flight topics touching `git checkout`. The series is well-motivated: it addresses the long-standing awkwardness of the shared `checkout_main()` dispatch and aligns with the broader goal of making built-in commands more modular and reusable. If the community accepts this direction, it will likely become the new baseline for future work on these commands.
