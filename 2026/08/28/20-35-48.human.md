This is a bugfix patch targeting the pathspec handling in `git ls-files` and `git add`. The issue is that negative pathspecs (exclusion patterns) are incorrectly truncated by the common prefix length calculated from *positive* pathspecs, leading to either false exclusions or out-of-bounds memory access. The bug was introduced in 2013 (commit `ef79b1f870`) and affects only these two commands.

The patch itself is small and surgical: it modifies `do_match_pathspec()` in `dir.c` to skip prefix stripping for negative pathspecs, since the common prefix calculation only considers positive ones. The commit message is exceptionally clear, walking through the bug's mechanics with concrete examples and linking to the original report. Three new tests in `t/t6132-pathspec-exclude.sh` cover the edge cases—empty negative pathspecs, pathspecs matching the common prefix length, and shorter exclusions—demonstrating both the bug and the fix.

The contribution looks well-crafted: the rationale is thorough, the fix is minimal, and the tests are comprehensive. There’s no obvious controversy here—this appears to be a straightforward correctness fix for a long-standing but narrow bug. If you care about pathspec accuracy or use negative patterns in scripts, this patch is worth watching.
