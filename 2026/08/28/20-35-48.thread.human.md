This thread is about a bug in `git ls-files` and `git add` where negative (exclusion) pathspecs are incorrectly affected by the common-prefix optimization meant only for positive pathspecs. The bug can cause negative pathspecs to degenerate into empty strings or trigger out-of-bounds reads. Diogo Castro posted a minimal patch (11 lines in `dir.c`) with three new tests to fix this by ensuring negative pathspecs are not stripped of the positive-path prefix.

The discussion has centered on whether the fix should preserve the current performance optimization (Diogo's patch) or recalculate the common prefix to include negative pathspecs when they share a prefix with positives (Junio C Hamano's proposal). Junio initially suggested recalculating the prefix to include negatives for more intuitive semantics but has since refined his position to apply this only when negatives share a meaningful prefix with positives. Diogo argues that Junio's approach could degrade performance in cases like `git add -- a/b/c a/b/d ':!a/**/x'`, where the common prefix would shrink from `a/b/` to `a/`, forcing a broader working-directory walk. No alternative implementation has been proposed yet, and the design direction remains unresolved.

Key participants are Diogo (author), Thomas Haller (original bug reporter), and Junio (maintainer). The thread is still under review, with no prior versions of the patch. The core trade-off is between preserving performance (Diogo's patch) and making negative pathspec semantics more intuitive (Junio's proposal).
