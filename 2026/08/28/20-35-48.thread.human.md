This thread is about a bugfix patch from Diogo Castro that prevents Git from incorrectly stripping the common prefix of positive pathspecs from negative (exclusion) pathspecs in `git ls-files` and `git add`. The bug, which dates back to 2013, can cause negative pathspecs to degenerate into empty strings or trigger out-of-bounds reads. The patch is minimal, touching only `dir.c` and adding three new tests, and has been well-received for its narrow scope and thorough testing.

The discussion took a turn with Junio C Hamano’s review, which raises a substantive design question: whether the current fix (skipping prefix-stripping for negative pathspecs entirely) is the right approach. Junio suggests that the common prefix should instead be calculated across *both* positive and negative pathspecs, using the example `git ls-files -- a/b/c a/b/d !a/b/` to argue that stripping `a/b/` from all pathspecs (including the negative one) might be more intuitive. This implies the fix could be better implemented by modifying `common_prefix()` rather than adding a conditional guard in `do_match_pathspec()`. The patch is now paused while this design question is resolved, and Diogo Castro will need to address Junio’s feedback before the patch can move forward. No other reviews have been posted yet.
