This thread is about a bug in `git ls-files` and `git add` where negative (exclusion) pathspecs were incorrectly affected by the common-prefix optimization meant only for positive pathspecs. The bug could cause negative pathspecs to degenerate into empty strings or trigger out-of-bounds reads. Diogo Castro proposed a minimal fix (11 lines in `dir.c`) that ensures negative pathspecs are ignored when computing the common prefix, preserving the performance optimization for positive pathspecs only.

After some back-and-forth, Junio C Hamano, the maintainer, has now accepted Diogo’s original patch as the correct solution. The fix will limit the working-directory traversal to the common prefix of positive pathspecs and then filter out excluded paths by matching against the full negative patterns. While there was earlier discussion about recalculating the common prefix to include negative pathspecs for more intuitive semantics, Junio has agreed that this is unnecessary for the current bug and could introduce performance trade-offs. Any future optimizations for cases with many negative patterns are deferred as a separate topic.

The patch includes three new tests in `t/t6132-pathspec-exclude.sh` and traces the bug back to its introduction in 2013. With Junio’s acceptance, the thread is effectively resolved, and the fix is ready to be merged. No further changes or alternative implementations are expected.
