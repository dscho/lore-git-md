This is the seventh patch in Junio C Hamano’s eight-patch series refactoring the internals of `git checkout`, `git switch`, and `git restore`. The series as a whole extracts reusable logic from these built-in commands into standalone utility functions, eliminating the monolithic `checkout_main()` helper that previously served as a shared choke point. This patch is a surface-level cleanup that tidies up long lines and replaces manual option-compatibility checks with the `die_for_incompatible_optN()` helper macros, improving readability without changing behavior.

The patch addresses two specific issues introduced by earlier refactoring steps. First, it wraps overly long lines—particularly in `die()` calls and option-parsing macros—to stay within Git’s 80-column guideline. Second, it replaces manual checks like `if (opts->foo && opts->bar) die(...)` with the standardized `die_for_incompatible_opt2()` and `die_for_incompatible_opt3()` macros, making the error handling more consistent. The changes are confined to `builtin/checkout.c` and affect 54 lines (34 insertions, 20 deletions).

Junio notes a minor typo in the commit message example (`new_new_branch_force` instead of `new_branch_force`), but this does not affect the patch itself. The cleanup is uncontroversial and aligns with Git’s coding style, though its value is primarily aesthetic. The patch depends on the earlier architectural changes in the series, which have already passed the test suite, and is part of an early draft intended for discussion rather than immediate merging.

For readers following the broader refactoring effort, this patch is a low-risk, low-impact step that polishes the work done in the first six patches. It does not introduce new functionality or touch other subsystems, but it makes the codebase slightly easier to maintain. The series remains a work in progress, with the eighth patch (relocating `post_checkout_hook()` to a top-level utility file) still pending.
