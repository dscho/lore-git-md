This is a surface-level review comment on the sixth patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling. The series is part of the ongoing ODB abstraction effort and aims to simplify the ODB interface by removing the ability to write alternates after repository creation.

Toon Claes points out a minor code organization issue in `odb/source.h`: the patch adds a `#include "strvec.h"` at the top of the file, but a forward declaration of `struct strvec` already exists further down. He suggests removing the include and placing the new `odb_create_on_disk_options` struct (which uses `strvec`) after the existing forward declaration. This is a straightforward, uncontroversial observation about header hygiene and does not engage with the patch’s technical substance, correctness, or design.

The comment is unlikely to prompt significant changes or further discussion, as it addresses a cosmetic detail rather than a functional concern. The patch itself remains well-scoped and solid, implementing the core design change (writing alternates at ODB creation time) that enables the removal of the `write_alternates()` callback in the next patch. Reviewers are still expected to focus on the error handling and deduplication logic introduced here, but Toon’s feedback does not raise any red flags in those areas.
