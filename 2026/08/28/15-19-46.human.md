This is a bugfix patch targeting the worktree repair functionality, specifically how Git handles relative versus absolute paths in `.git` files. The patch is now at version 4, addressing Junio’s feedback on the commit message to better explain the design rationale.

The core issue is that `git worktree repair` fails to convert relative paths to absolute paths when `worktree.useRelativePaths` is toggled from `true` to `false`. This happens because `read_gitfile_gently()` always returns an absolute path, obscuring the original path style stored in the `.git` file. The fix introduces `read_gitfile_raw()`, a new function that reads the path verbatim (relative or absolute) without normalization or repository validation. The existing `read_gitfile_gently()` now delegates to `read_gitfile_raw()` to obtain the verbatim path before normalizing it to an absolute path and performing validation.

The patch touches `setup.c`, `setup.h`, `worktree.c`, and the test script `t/t2406-worktree-repair.sh`. The test suite is expanded with four new test cases that verify the repair logic correctly handles transitions between absolute and relative paths in both main and side worktrees, including proper error messages for mismatches. The changes are mechanical and focused, preserving the existing path resolution logic while removing dead code branches.

The commit message now clearly explains why `read_gitfile_raw()` omits repository validation (`is_git_directory()`), which is instead handled by the caller (`repair_gitfile()` in `worktree.c`). This avoids redundant path resolution and keeps the raw-reading function narrowly focused on parsing the `.git` file. The patch appears technically sound, well-tested, and ready for integration. The only remaining action was the commit message clarification, which this version provides.
