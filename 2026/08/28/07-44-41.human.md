This is the first patch in Elijah Newren’s **v3 bugfix series** (1/5), a **refactoring** that clarifies naming to better reflect the intent of the existing logic. The patch renames `FROM_REBASE_PICK` to `FROM_REBASE_EMPTY` and `is_from_rebase()` to `is_from_rebase_empty()` to make it clear these identifiers are specifically about commits that became empty during a rebase. It also replaces direct enum checks with the renamed helper function.

The change is purely mechanical and uncontroversial, addressing Junio C Hamano’s feedback from earlier rounds to improve code clarity. It touches `builtin/commit.c`, `sequencer.c`, and `wt-status.h`, with no behavior changes—only symbol renames and helper usage updates. This patch is a prerequisite for the later substantive changes in the series, which extend Git’s protection against unsafe commit operations during conflict resolution.

The series as a whole is technically sound and targets a real usability hazard: preventing users from accidentally corrupting repository state by amending the wrong commit or committing only a subset of paths during conflict resolution. This preparatory patch is ready for review and likely to proceed to `next` alongside the rest of the series.
