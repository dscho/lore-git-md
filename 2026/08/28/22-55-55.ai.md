This is the seventh patch in Junio C Hamano’s 8-patch series refactoring the internals of `git checkout`, `git switch`, and `git restore`. The patch addresses readability issues introduced by earlier patches in the series: it wraps overly long lines and replaces manual option-compatibility checks with the `die_for_incompatible_optN()` helper macros. The changes are purely stylistic and do not affect functionality or behavior.

The patch corrects a typo in the commit message and diff: `opts->new_new_branch_force` should be `opts->new_branch_force`. This is a minor error that does not impact the patch’s correctness but would need to be fixed before merging. The patch touches only `builtin/checkout.c`, changing 54 lines (34 insertions, 20 deletions). Key changes include breaking up long `die()` calls (e.g., for `--unified` requiring `--patch`), replacing manual `if (opts->foo && opts->bar) die(...)` checks with `die_for_incompatible_opt2()` and `die_for_incompatible_opt3()`, and wrapping long `OPT_BOOL()` and `parse_pathspec_file()` argument lists to stay within 80 columns.

This patch depends on the earlier patches in the series, which eliminated the `checkout_main()` choke point and extracted reusable logic into standalone helpers. It is uncontroversial and aligns with Git’s coding guidelines, but its value is primarily aesthetic. The series as a whole remains an early draft for discussion, not yet intended for merging to `seen`. The patch itself is ready for review once the typo is fixed, but its integration depends on the broader series’ acceptance and coordination with other in-flight topics.
