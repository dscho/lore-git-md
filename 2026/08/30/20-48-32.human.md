This is the fifth patch in Junio C Hamano’s eight-patch series refactoring the internals of `git checkout`, `git switch`, and `git restore`. The series aims to eliminate the monolithic `checkout_main()` function by extracting reusable logic into standalone helpers, aligning with the architectural direction established in the parent thread.

This patch focuses on branch setup and tracking logic. It extracts three new static helper functions from `checkout_main()`: `validate_branch_options()`, `dwim_branch_track_option()`, and `setup_branch_name_and_info()`. These helpers encapsulate the validation of branch-creation options (`-b`, `-B`, `--orphan`), the DWIM (Do What I Mean) logic for `--track` without an explicit branch name, and the parsing of branch name arguments, respectively. The patch moves roughly 50 lines of logic into these helpers, reducing `checkout_main()`’s complexity while preserving all behavior. The new `setup_branch_name_and_info()` helper is called from `checkout_main()` to drive branch validation and parsing, replacing the inline logic that previously handled these tasks.

The refactoring is mechanical and uncontroversial, with no changes to CLI behavior or on-disk formats. The patch passes the test suite and is part of a larger effort to make the checkout internals more modular and reusable. The extracted helpers are static for now, as the series’ broader goal of exposing reusable logic to other subsystems (e.g., `git worktree`) is addressed in later patches. This patch is a stepping stone toward eliminating the `checkout_main()` choke point, which the series targets in the sixth patch.
