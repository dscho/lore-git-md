This is the second patch in Junio C Hamano’s eight-patch series refactoring the internals of `git checkout`, `git switch`, and `git restore`. The series is part of the broader effort to eliminate the monolithic `checkout_main()` helper and extract reusable logic into standalone functions that accept a `struct repository *` parameter, aligning with the `the_repository` removal architectural direction.

This patch moves the validation of new branch names (`validate_branchname()` and `validate_new_branchname()`) from `checkout_main()` into `checkout_branch()`. The change is straightforward and logical: since `checkout_paths()` (which handles path-based operations) does not create new branches, the validation only belongs in `checkout_branch()`. The patch also notes that `checkout_paths()` already checks and fails if `.new_branch` is set, confirming the safety of this relocation.

The diff is clean and mechanical, moving 11 lines of code from `checkout_main()` to `checkout_branch()` without altering behavior. The commit message clearly explains the rationale and safety of the change, making it easy to review. This patch is uncontroversial and could be merged independently if the rest of the series is deferred. It reduces the size of `checkout_main()` and improves code locality by keeping branch-related validation with the branch-handling logic.
