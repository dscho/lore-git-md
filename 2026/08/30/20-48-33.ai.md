This is the sixth patch in Junio C Hamano’s eight-patch series refactoring the `git checkout`, `git switch`, and `git restore` internals. It is the core architectural change: it eliminates the monolithic `checkout_main()` choke point by rewriting the three command entry points (`cmd_switch()`, `cmd_restore()`, `cmd_checkout()`) to call the extracted utility helpers directly, placing all callers on equal footing.

The patch removes `enum checkout_command` and `checkout_main()`, which were previously used to funnel all three commands through a single entry point. Instead, each command now initializes its own `struct checkout_opts`, parses its own options, and dispatches directly to `checkout_branch()` or `checkout_paths()`. The restructuring is mechanical and preserves all existing behavior, but it eliminates the "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper. The extracted helpers (`init_checkout_opts()`, `setup_branch_name_and_info()`, `validate_path_options()`, `prepare_common_options()`, `parse_pathspec_from_file_options()`) are now called directly by each command, making the code more modular and easier to maintain.

The patch touches only `builtin/checkout.c`, moving roughly 150 lines of logic from the monolithic `checkout_main()` into the three command-specific functions. The changes are isolated to the command entry points and do not affect the core checkout logic (`checkout_branch()` and `checkout_paths()`). The restructuring is uncontroversial and passes the test suite, but it is part of a larger series that is explicitly not intended for merging to `seen` due to potential conflicts with in-flight topics. The patch is self-contained and could be merged independently if the final two patches are deferred.

Key symbols introduced: none (this patch removes `checkout_main()` and `enum checkout_command`). Key symbols removed: `checkout_main()`, `enum checkout_command`. The patch does not change CLI behavior or on-disk format. The restructuring aligns with the architectural direction established in the parent thread: built-in commands are not libified, but their reusable internals are extracted into standalone helpers that accept a `struct repository *` parameter. This patch is the concrete implementation of that direction for the checkout family of commands.
