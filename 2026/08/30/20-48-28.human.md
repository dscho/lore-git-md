This is the first patch in Junio C Hamano’s eight-patch series refactoring the internals of `git checkout`, `git switch`, and `git restore`. The patch removes a file-scope static variable (`cb_option`) that tracked whether a new branch was being created via `-b` (checkout) or `-c` (switch), replacing it with an explicit parameter passed to the branch-name parsing functions.

The change is a straightforward refactoring that eliminates global mutable state, making the code easier to reason about and safer for future refactoring. The patch touches only `builtin/checkout.c`, reducing its line count by 5 (9 insertions, 14 deletions). No behavior changes are introduced—error messages and advice remain identical, just derived from the passed parameter instead of a global variable.

This is a preparatory step for the larger goal of eliminating the monolithic `checkout_main()` function, which the series treats as a "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper. The patch aligns with the architectural direction established in the parent thread: reusable logic should be extracted into standalone helpers that accept explicit parameters (like `struct repository *`) rather than relying on globals.

The patch is uncontroversial and passes the test suite. It’s part of a larger refactoring that’s still under discussion, but this step could be merged independently if the rest of the series is deferred. No objections or alternatives have been raised so far.
