This is the first patch in Junio C Hamano’s eight-patch series refactoring the `git checkout`, `git switch`, and `git restore` internals to eliminate the monolithic `checkout_main()` helper. The patch removes the file-scope static variable `cb_option` (which tracks whether a new branch is created via `-b` or `-c`) and instead passes it explicitly as a parameter to `parse_remote_branch()` and `parse_branchname_arg()`.

The change is a targeted refactoring that addresses a specific instance of global mutable state, making the code easier to reason about and refactor further. The patch is mechanical and uncontroversial: it replaces the static variable with a local `cb_option` in `checkout_main()` and updates the call sites to pass the value explicitly. The logic remains identical, and the test suite passes. This aligns with the series’ broader goal of extracting reusable logic into standalone helpers that accept explicit parameters, a key step in eliminating the "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper.

The patch touches only `builtin/checkout.c` and is a prerequisite for later patches in the series, which further extract initialization, validation, and branch setup logic. No CLI behavior or on-disk format changes are introduced. The change is small (9 insertions, 14 deletions) and focused, but it sets the stage for the larger architectural shift in the series. The explicit parameter passing also prepares the code for future multi-repository support, as it avoids reliance on file-scope state.

This patch is part of the libification path clarified in the parent thread, where reusable logic is factored out of built-in commands into standalone helpers. The series is still an early draft for discussion, but this patch is self-contained and could be merged independently if the rest of the series is deferred. No objections or alternatives have been raised, and the change is consistent with the project’s preference for eliminating global state.
