This is a reply in the ongoing bugfix discussion about negative pathspec handling in `git ls-files` and `git add`. The author, Diogo Castro, pushes back against Junio C Hamano’s suggestion to recalculate the common prefix to include negative pathspecs. Castro argues that the current approach—skipping prefix-stripping for negative pathspecs entirely—preserves the performance optimization that the prefix-stripping feature was designed to provide.

The core of the disagreement is whether negative pathspecs should be treated as absolute paths (Castro’s position) or relative to the common prefix of *all* pathspecs (Junio’s suggestion). Castro’s example (`git add -- a/b/c a/b/d ':!*.md'`) illustrates the trade-off: if the common prefix is recalculated to include negative pathspecs, the optimization could be lost, forcing Git to walk the entire working directory even when a narrower scope would suffice. This is a substantive design question with implications for both correctness and performance, and the discussion is now focused on weighing these trade-offs.

No alternative implementation has been proposed yet, and the thread remains open. The next step will likely involve further clarification or a revised patch from Castro, depending on whether Junio’s concerns are addressed. For now, the patch is not ready to proceed, as the design direction is still under debate.
