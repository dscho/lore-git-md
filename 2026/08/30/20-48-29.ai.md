This is the second patch in Junio C Hamano’s eight-patch series refactoring the `git checkout`, `git switch`, and `git restore` internals. It moves branch name validation logic (`validate_branchname()` and `validate_new_branchname()`) from the monolithic `checkout_main()` helper into `checkout_branch()`, where it logically belongs.

The change is a straightforward cleanup: `checkout_paths()` (used for path-based operations) does not create branches, so validating branch names there is unnecessary. The patch relocates the validation block—unchanged except for indentation—into `checkout_branch()`, which handles branch creation and switching. The commit message confirms that `checkout_paths()` already checks for `.new_branch` and fails early, making this move safe and improving code locality.

No behavior changes are introduced; the patch is purely refactoring. It reduces `checkout_main()`’s size by 11 lines and aligns with the series’ goal of eliminating the "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper. The extracted logic remains identical, preserving the existing validation rules (e.g., branch name syntax, force flag handling).

This patch is uncontroversial and could be merged independently if the rest of the series is deferred. It touches only `builtin/checkout.c` and has no dependencies on later patches. The test suite passes, and the change is mechanical, making it a low-risk step toward the broader libification effort. Future patches in the series will further extract reusable logic into standalone helpers, but this one stands alone as a targeted improvement.
