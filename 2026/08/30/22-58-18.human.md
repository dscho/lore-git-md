This is a reply in the ongoing bugfix thread about negative pathspec handling in `git ls-files` and `git add`. The maintainer, Junio C Hamano, clarifies his earlier suggestion: he agrees that computing the common prefix *only* from positive pathspecs and then stripping it from both positive and negative pathspecs is incorrect, but he still believes the common prefix should be recalculated to include *all* pathspecs (both positive and negative). He provides a new example, `git add -- a/b/c a/b/d ':!a/b/x'`, to illustrate the kind of case where the current patch's approach might produce unintuitive results.

The discussion remains at an impasse. The author (Diogo Castro) argues that the prefix-stripping optimization is a performance feature for positive pathspecs only and should not be extended to negatives, while Junio suggests that including negative pathspecs in the common prefix calculation would make the semantics more intuitive. Neither side has proposed an alternative implementation yet, and the thread is still open. The patch itself is small, well-tested, and fixes a real bug, but the design question about how negative pathspecs should interact with the prefix-stripping optimization is unresolved.
