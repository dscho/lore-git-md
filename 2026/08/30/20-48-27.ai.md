This is the second iteration of Junio C Hamano’s eight-patch series refactoring the `git checkout`, `git switch`, and `git restore` internals. The goal remains the same: eliminate the monolithic `checkout_main()` choke point by extracting reusable logic into standalone helpers that accept a `struct repository *` parameter, placing all callers on equal footing. The series is still an early draft for illustration, not intended for merging to `seen` due to potential conflicts with in-flight topics.

The key updates in this version are two correctness fixes. Patch 7 now preserves the original option-compatibility error messages by reordering the arguments to `die_for_incompatible_optN()` and fixes a typo (`opts->new_new_branch_force` → `opts->new_branch_force`). Patch 8 makes `post_checkout_hook()` fully reusable in multi-repository contexts by accepting a `struct repository *` parameter and using `repo->hash_algo` instead of `the_hash_algo`. These changes address the architectural shortcomings identified in the first iteration and align the series with the `the_repository` removal effort.

The refactoring is mechanical and passes the test suite, but its scale (557 lines changed in `builtin/checkout.c`, plus new top-level files `checkout.c` and `checkout.h`) makes it a candidate for careful review. The first six patches are isolated cleanups and extractions that could be merged independently if the final two are deferred. The seventh patch is a post-refactoring style cleanup, and the eighth demonstrates the libification goal by moving a helper to a top-level file. No CLI behavior or on-disk format changes are introduced.

The series directly implements the libification path clarified in the parent thread, eliminating the "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper. The extracted helpers (`validate_branch_name()`, `setup_branch_tracking()`, `post_checkout_hook()`, etc.) are now available to other subsystems (e.g., `git worktree`) without depending on built-in command code. The sixth patch is the core architectural change, rewriting the three command entry points to call the extracted helpers directly.

No objections or alternatives have been raised, but the series remains a discussion starter.
