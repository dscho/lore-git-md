Thread identity: Bug report – use-after-free regression in `git stash show` with `--src-prefix`/`--dst-prefix` introduced in Git 2.52.0 (commit 3ea35c64b). Originating author: Nicolas Le Cam. Series version: single-patch bugfix (v1) plus a refactoring follow-up.

Core problem or goal: A use-after-free bug in `git stash show` causes garbage diff headers (e.g., `diff --git Uf.txt Uf.txt`) when `--src-prefix` or `--dst-prefix` is used. The regression was introduced by commit 3ea35c64b, which enabled freeing of `argv` elements in `setup_revisions()` while `struct diff_options` still held dangling pointers to those strings. The issue affects scriptability (e.g., `lint-staged`) and is deterministic across versions but varies between runs in 2.53.0 due to heap memory reuse.

Current status: **Patch proposed (v1) with refactoring follow-up; under review**. Jeff King posted a fix that introduces a `strvec argv_to_free` field in `struct rev_info` to delay freeing "freed" `argv` elements until `release_revisions()` is called, ensuring references stored in `diff_options` (like `a_prefix`/`d_prefix`) remain valid. A follow-up patch refactors `mark_argv_for_free()` to move the `free_removed_argv_elements` flag check into the helper itself, eliminating redundant checks in callers. Both patches are targeted at the regression’s source (commit 3ea35c64b) and are suitable for `maint`. The centralized approach is endorsed by Patrick Steinhardt as more defensive than per-option string copying, though he raises a maintainability concern about the `mark_argv_for_free()` helper’s `const char *` parameter hiding ownership transfer. Jeff King has since clarified that the helper’s single purpose (freeing strings) justifies the syntactic convenience of pushing the `const` cast into the function, and that the follow-up patch ("2/1") further simplifies callers. No controversy over correctness; the fix restores correct diff header output and improves code maintainability without user-visible impact.

Key technical details:
- **Files/subsystems touched**: `revision.c` (core logic and refactoring), `revision.h` (new `argv_to_free` field in `struct rev_info`), `builtin/stash.c` (implied by regression context), and `t/t3903-stash.sh` (new regression test for prefix handling).
- **New/renamed symbols**: `struct rev_info.argv_to_free` (new field); `mark_argv_for_free()` (refactored helper, now takes ownership of its `const char *` argument and consolidates the `free_removed_argv_elements` flag check).
- **Old vs. new behavior**: Restores expected diff headers (e.g., `diff --git a/f.txt b/f.txt`) instead of garbage (e.g., `diff --git Uf.txt Uf.txt`). No user-visible changes from the refactoring.
- **On-disk format changes**: None.
- **Test coverage**: Reproduction case provided by Nicolas Le Cam; Jeff King’s original patch adds a regression test in `t/t3903-stash.sh` to verify the fix and prevent future regressions.
- **Memory management**: The original patch trades immediate freeing for delayed cleanup via `argv_to_free`, avoiding leaks while preventing dangling pointers. The refactoring consolidates flag logic into `mark_argv_for_free()`, reducing redundancy. The helper’s `const char *` parameter is safe for current call sites (all heap-allocated strings) but could theoretically mislead future contributors if non-heap strings are passed.

Open questions and loose ends:
- Whether to backport the fix closer to the original leak-fix (commit cd43948798) for minimal backporting scope. Current patch is correct and self-contained, so this is a minor consideration.
- Potential for similar bugs in other diff options parsed via `OPT_STRING_F` (not addressed by these patches).
- Resolution of the `mark_argv_for_free()` API design: Jeff King has defended the `const char *` parameter as justified by the helper’s single purpose, but the thread awaits Patrick Steinhardt’s reaction to the follow-up patch.

Participant positions:
- **Nicolas Le Cam**: Author of the report; provided reproduction steps, root cause analysis, and impact assessment. Position: This is a serious regression requiring a fix.
- **Jeff King**: Author of the proposed fix and refactoring follow-up; argues for a centralized solution (delayed freeing via `rev_info.argv_to_free`) over per-option string copying. Position: Both patches are straightforward, non-disruptive improvements for a real bug, with the refactoring improving code clarity. The `const char *` parameter in `mark_argv_for_free()` is justified by the helper’s single purpose and is safe for existing call sites.
- **Patrick Steinhardt**: Reviewer; endorses the centralized approach as more defensive but raises a maintainability concern about `mark_argv_for_free()`’s `const char *` parameter hiding ownership transfer. Position: The fix is correct and suitable for `maint`, but the API design could lead to subtle lifetime issues if misused. No alternative implementation proposed.

Related work: None mentioned. The regression is isolated to `stash show` and commit 3ea35c64b.
