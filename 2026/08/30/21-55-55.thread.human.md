This thread is about a **use-after-free regression in `git stash show`** introduced in Git 2.52.0. The bug surfaces when using `--src-prefix` or `--dst-prefix`, causing corrupted diff headers (e.g., `diff --git Uf.txt Uf.txt` instead of `diff --git a/f.txt b/f.txt`). Nicolas Le Cam identified the root cause: commit 3ea35c64b enabled freeing `argv` elements in `setup_revisions()` while `struct diff_options` still held dangling pointers to those strings. The issue is deterministic and reproducible, with real-world impact on tools like `lint-staged` that parse diff output.

The report is thorough, including a clear reproduction case, version scope (regression in 2.52.0), and a plausible root cause analysis. The author also notes that other diff options parsed via `OPT_STRING_F` could be similarly affected. No prior reports exist, and the bisect result (Debian/Alpine) adds credibility. The fix will likely involve either disabling the `free_removed_argv_elements` flag for `stash show` or ensuring `diff_options` fields are copied rather than referenced. The patch is self-contained and ready for review. No responses or decisions have been made yet.
