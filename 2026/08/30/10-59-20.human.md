This is a CI/build system patch. Harald Nordgren updates his earlier proposal to cancel stale GitHub Actions workflow runs for pull requests, addressing feedback from Junio C Hamano.

The patch modifies `.github/workflows/main.yml` to group workflow runs by pull request number (rather than commit hash) when triggered by a pull request event, and cancels any in-progress runs when a new push occurs. For non-pull-request events, it retains the existing behavior of grouping by commit hash to preserve the `skip-if-redundant` optimization. The commit message now explains the change in detail, including the edge case Junio raised: the new configuration ensures each workflow has its own concurrency group, avoiding unintended cancellation between different workflows triggered by the same commit.
