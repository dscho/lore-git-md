This is the third patch in Junio C Hamano’s eight-patch series refactoring the `git checkout` internals to eliminate the monolithic `checkout_main()` helper. The series is part of the broader effort to libify reusable logic from built-in commands, aligning with the `the_repository` removal architectural direction.

This patch moves the validation of `--ours`, `--theirs`, `--force`, and `--merge` option compatibility from `checkout_main()` into `checkout_paths()`. The change is a straightforward refactoring: the validation logic is unchanged, but it now runs inside `checkout_paths()` rather than in the monolithic `checkout_main()`. This improves code locality, since the validation only applies when pathspecs are present (i.e., when checking out files from the index, not when switching branches). The patch reduces `checkout_main()` by five lines and adds five lines to `checkout_paths()`, with no functional impact.

The patch is uncontroversial and mechanical, passing the test suite as part of the series. It is one of several preparatory steps that extract logic from `checkout_main()` before the sixth patch eliminates the helper entirely. No CLI behavior or on-disk format changes are introduced.

This patch is a small but necessary part of the series’ goal: to place all callers (`git checkout`, `git switch`, `git restore`) on equal footing by extracting reusable logic into standalone helpers. The change is unlikely to attract debate, but the series as a whole remains an early draft for discussion, not yet intended for merging to `seen`.
