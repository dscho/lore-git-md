This is the seventh patch in Junio C Hamano’s eight-patch series refactoring the internals of `git checkout`, `git switch`, and `git restore`. The series as a whole extracts reusable logic from these commands into standalone helpers, eliminating the monolithic `checkout_main()` function and aligning with the ongoing `the_repository` removal effort.

This specific patch addresses readability issues introduced by earlier refactoring steps. It wraps overly long lines—particularly in error messages and `die()` calls—and replaces manual option-compatibility checks with the `die_for_incompatible_optN()` helper macros. For example, it breaks up long `die()` calls like `die(_("the option '%s' requires '%s'"), "--unified", "--patch")` into multi-line statements for better readability. It also replaces manual `if (opts->foo && opts->bar) die(...)` checks with the `die_for_incompatible_opt2()` and `die_for_incompatible_opt3()` macros, which standardize error reporting and reduce boilerplate.

The patch fixes a typo from the first iteration (`opts->new_new_branch_force` → `opts->new_branch_force`) and ensures the original option-compatibility error messages are preserved by reordering the arguments to the `die_for_incompatible_optN()` macros. The changes are purely stylistic and do not alter behavior or CLI functionality. The patch touches only `builtin/checkout.c` and is uncontroversial, as it addresses mechanical readability issues rather than introducing new logic.

This patch is part of the series’ cleanup phase, following the core refactoring in patches 1–6. It is self-contained and could be merged independently if the rest of the series is deferred. The series as a whole is not yet intended for merging to `seen` due to potential conflicts with other in-flight topics, but this patch is ready for review and unlikely to generate debate. The broader refactoring remains a discussion starter, with the architectural direction already agreed upon by Junio and D. Ben Knoble.
