This is the fourth patch in Junio C Hamano’s eight-patch series refactoring the `git checkout`, `git switch`, and `git restore` internals. It extracts option validation and pathspec handling logic from the monolithic `checkout_main()` function into four new static helpers: `init_checkout_opts()`, `validate_path_options()`, `prepare_common_options()`, and `parse_pathspec_from_file_options()`. The patch is a mechanical refactoring that improves code locality and readability without changing behavior.

The patch moves roughly 100 lines of initialization, validation, and pathspec logic into standalone helpers, reducing `checkout_main()`’s complexity. `init_checkout_opts()` centralizes default option values and repository configuration, `validate_path_options()` consolidates patch-mode and index/worktree flag validation, `prepare_common_options()` handles progress, merge, and force option logic, and `parse_pathspec_from_file_options()` encapsulates pathspec-from-file parsing and validation. The changes are uncontroversial and pass the test suite, but the patch’s scale (96 insertions, 75 deletions) makes it a candidate for careful review.

This patch is part of the broader effort to eliminate the `checkout_main()` choke point by extracting reusable logic into standalone helpers, as directed by the parent thread’s architectural clarification. The extracted helpers are not yet exposed to other subsystems (that happens in patch 8), but they lay the groundwork for future libification. The patch is self-contained and could be merged independently if the later patches are deferred.
