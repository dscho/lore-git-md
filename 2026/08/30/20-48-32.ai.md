This is the fifth patch in Junio C Hamano’s eight-patch series refactoring the `git checkout`, `git switch`, and `git restore` internals to eliminate the monolithic `checkout_main()` function. The patch extracts branch setup and tracking logic into three new static helpers—`validate_branch_options()`, `dwim_branch_track_option()`, and `setup_branch_name_and_info()`—and updates `checkout_main()` to call them. This continues the series’ goal of improving code locality and preparing for the eventual removal of `checkout_main()`.

The refactoring is mechanical and behavior-preserving: the extracted helpers encapsulate the same validation and DWIM logic previously inlined in `checkout_main()`, but now with clearer separation of concerns. `validate_branch_options()` checks for incompatible combinations of `-b`, `-B`, and `--orphan`; `dwim_branch_track_option()` infers a branch name when `--track` is given without one; and `setup_branch_name_and_info()` orchestrates the two and calls `parse_branchname_arg()` to handle the branch name argument. The patch reduces `checkout_main()`’s complexity by moving ~50 lines of branch-related logic into focused helpers, though the function remains large for now.

No CLI behavior or on-disk format changes are introduced. The patch touches only `builtin/checkout.c` and passes the test suite, confirming the refactoring is correct. The extracted helpers are static and not yet exposed to other subsystems, but they lay the groundwork for the sixth patch, which will eliminate `checkout_main()` entirely by rewriting the command entry points to call these helpers directly. The patch is uncontroversial and aligns with the series’ architectural direction, though broader feedback from contributors like René Scharfe or Patrick Steinhardt is still pending.

Key symbols introduced: `validate_branch_options()`, `dwim_branch_track_option()`, and `setup_branch_name_and_info()`. The patch removes the inlined branch validation and DWIM logic from `checkout_main()`, reducing its size by ~50 lines. The helpers are called only when `opts->accept_ref` is true, preserving the original control flow. The patch is part of a larger effort to libify reusable checkout logic, but it does not yet expose any functionality outside `builtin/checkout.c`.

The patch is self-contained and could be merged independently if the later patches in the series are deferred. It demonstrates the series’ approach to extracting reusable logic into focused helpers, a pattern that will be repeated in subsequent patches. No open questions or loose ends are introduced by this patch alone, though the series as a whole remains a discussion starter.
