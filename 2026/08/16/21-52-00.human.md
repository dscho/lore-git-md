This is a reply in the `git squash` feature proposal thread, offering a counterpoint and historical context.

Matej Dujava responds to The Super Techie’s RFC by pointing out that Git already supports a more flexible workflow for squashing commits: using `fixup!` or `squash!` commits during interactive rebase (`git rebase --autosquash`). This approach allows developers to mark commits for squashing or fixup during development, then automatically apply those changes later, which is particularly useful when addressing review feedback.

Matej also links to a long-running patch series (v13) that proposed a `git history squash` command, which would have preserved the message of the first commit in the squashed range. This shows the idea has been discussed before, though the linked series appears to have stalled without being merged. The thread context suggests no maintainer has weighed in on the current proposal, so the discussion remains at the brainstorming stage. For now, this reply shifts the conversation from "should we add this?" to "how does this compare to existing tools?"
