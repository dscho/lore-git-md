Subject: [RFC] Proposal for new `git squash` command
Series version: none (feature proposal only)
Originating author: The Super Techie <thesupertechie1@gmail.com>
Thread type: RFC / feature discussion

Core problem or goal
Add a built-in `git squash <n>` command that combines the last `<n>` commits into a single new commit, equivalent to `git reset --soft HEAD~<n> && git commit`. An optional `-s` flag would automatically add a Signed-off-by trailer. The discussion now also encompasses whether existing tools (`git rebase --autosquash` with `fixup!`/`squash!` commits or the proposed `git history squash` from a long-running patch series) already address the use case, making a new command redundant or complementary.

Current status
Proposal stage; no patches posted. No maintainer response or integration status. The thread has expanded to include two distinct approaches: (1) the original simple `git squash <n>` and (2) the more flexible `git history squash` from a linked v13 patch series. No consensus or maintainer guidance has emerged.

Key technical details
- Proposed command: `git squash <n>` (original RFC)
- Optional flag: `-s` (add Signed-off-by trailer)
- Equivalent to: `git reset --soft HEAD~<n> && git commit`
- Existing alternative: `git rebase --autosquash` with `fixup!`/`squash!` commits (Matej Dujava)
- Related work: `git history squash` patch series (v13), which preserves the message of the first commit in the squashed range (Matej Dujava)
- No discussion of edge cases (merge commits, conflicts, partial staging, index interaction) in either proposal
- No interaction with existing squash-like functionality (`git merge --squash`, `git commit --amend`, `git rebase -i`) explicitly addressed

Open questions and loose ends
