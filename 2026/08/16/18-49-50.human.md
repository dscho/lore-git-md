This is a feature proposal for a new `git squash` command.

A new contributor, The Super Techie, suggests adding a built-in `git squash <n>` command that would combine the last `<n>` commits into one. The proposed behavior is equivalent to the existing two-step workflow: `git reset --soft HEAD~<n>` followed by `git commit`. The email also floats the idea of an `-s` flag to automatically add a Signed-off-by trailer, mirroring the Developer Certificate of Origin requirement in some projects.

The commit message does not cite prior discussion or link to any earlier threads, so it is unclear whether this idea has been raised before. The proposal is brief and does not address edge cases (e.g., merge commits, conflicts, or what happens when `<n>` exceeds the number of available commits). There are no tests, no implementation sketch, and no performance or compatibility considerations. While the suggestion is straightforward and would save a few keystrokes, it is currently under-motivated: the email does not explain why the existing two-command idiom is insufficient or what concrete pain point the new command would solve.
