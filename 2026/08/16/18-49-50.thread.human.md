This thread is a feature discussion about adding a new `git squash` command, proposed by The Super Techie as a convenience wrapper for combining the last *n* commits into one. The proposal suggests a simple `git squash <n>` command, optionally with a `-s` flag to add a Signed-off-by trailer, but it doesn’t address edge cases like merge commits, conflicts, or partial staging.

Matej Dujava’s reply shifts the conversation by pointing out that Git already supports squashing through `fixup!`/`squash!` commits with `git rebase --autosquash`, which offers more flexibility by allowing selective squashing based on commit content. Matej also links to a long-running patch series (v13) for a `git history squash` command, which would preserve the message of the first commit in the squashed range—showing that similar ideas have been discussed before, though with different scope. The thread now has two competing directions: the original simple `git squash <n>` proposal and the more nuanced `git history squash` approach. No maintainer or core contributor has weighed in yet, so the discussion remains open-ended, with no clear consensus on whether a new command is needed or how it should work.
