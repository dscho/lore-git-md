This is the sixth patch in the v4 series adding path-related keys to `` `git repo info` ``. The patch introduces `` `path.git-prefix` ``, which exposes the relative path from the repository’s working tree root to the current directory — a value scripts often need but currently have to derive through other Git commands.

Lucas Seiki Oshiro’s reply questions whether this key belongs in `` `git repo info` `` at all. He argues that `` `path.git-prefix` `` describes the *current working directory* rather than the *repository* itself, making it conceptually misplaced in a command whose purpose is to report repository metadata. The objection is not about the implementation (which is straightforward and well-tested) but about whether the feature aligns with the command’s intended scope. This is the first substantive pushback on the series’ design, and it may prompt broader discussion about what `` `git repo info` `` should and should not expose.
