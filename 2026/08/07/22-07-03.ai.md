This is the eighth patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch prepares the client to parse object type metadata from the server response, though the server does not yet advertise the "type" capability (that comes in patch 9/10).

The patch adds the `wants_type` flag and `types` array to `struct fetch_object_info_results`, mirroring the existing `wants_size`/`sizes` pattern. In `fetch_object_info()`, it extends the protocol request to include the "type" keyword when the caller requests it and the server supports the feature. The response parsing logic maps the server’s type string (e.g., `"blob"`) to an internal `enum object_type` using `type_from_string_gently()`, with a `die()` if the string is unrecognized. The `builtin/cat-file.c` caller is updated to populate the `typep` field from the results and append "objecttype" to the allowed-atoms list when the server provides type data.

The change is mechanical and follows the established pattern for size metadata. It introduces no new behavior yet—since the server does not advertise "type", the client will never request it—but it is a necessary precursor to the server-side capability advertisement in the next patch. The patch touches three files (`fetch-object-info.c`, `fetch-object-info.h`, `builtin/cat-file.c`) and adds 45 lines, primarily in the response-parsing loop. The design is consistent with the hybrid array-of-structs approach implemented in earlier patches, and the error handling aligns with Git’s defensive programming practices. No open technical concerns remain; this patch is ready for integration.
