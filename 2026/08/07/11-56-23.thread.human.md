This thread is about D. Ben Knoble’s patch series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The goal is to let users enable nanosecond precision on supported filesystems without recompiling, reducing "racy Git" problems. The series is now in its fifth version (`v5`) and has been applied under the topic `dk/use-nsec-runtime`, meaning it’s effectively complete and ready to graduate to `master`.

The series consists of three patches. The first fixes a Meson build-system issue (`MAN_BASE_URL` configuration), the second is a no-op refactor of `repo_config_values_init()` to improve readability, and the third introduces `core.useNanosec` and removes `USE_NSEC`. The no-op refactor, which is the focus of this latest email, reorders assignments in `repo_config_values_init()` to match the struct declaration, making future additions easier to validate. Junio Hamano and Patrick Steinhardt have reviewed the series thoroughly, addressing performance regressions, cross-platform correctness, and code clarity. The only remaining loose end is a trivial conflict with `ty/repo-config-cleanups` in `seen`, which removes comments in `struct repo_config_values`.

Key participants include D. Ben Knoble (author), Junio Hamano (maintainer), and Patrick Steinhardt, all of whom agree the series is ready to advance. The performance regression identified in earlier versions has been fixed by caching the config value in `repo_config_values`, and the cross-platform correctness blocker (silent corruption risk on `NO_NSEC` platforms) is resolved by unconditionally initializing the `use_nanosec` field but treating it as false when `NO_NSEC` is defined. No runtime warning will be added for unsupported platforms, as both Junio and Patrick deemed it unnecessary. The series is uncontroversial and awaits graduation to `master`.
