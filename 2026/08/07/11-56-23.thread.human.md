This thread is about D. Ben Knoble’s patch series that replaces Git’s build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, allowing users to enable nanosecond precision on supported filesystems without recompiling Git. The series, now at version 5 (`v5`), is effectively complete and ready to graduate to `master` under the topic `dk/use-nsec-runtime`. It includes three patches: a Meson build-system fix, a no-op refactor of `repo_config_values_init`, and the core change introducing `core.useNanosec`.

The series has addressed all prior review feedback, including a performance regression in the initial implementation (fixed by caching the config value in `repo_config_values`), a cross-platform correctness blocker (resolved by unconditionally including the `use_nanosec` field but treating it as false on `NO_NSEC` platforms), and minor polish items like documentation warnings and code clarity. Junio Hamano and Patrick Steinhardt have reviewed the series, with both agreeing that no runtime warning is needed for unsupported platforms, prioritizing user experience for shared configurations. The only remaining loose ends are platform-dependent test coverage (not blocking) and a routine conflict with `ty/repo-config-cleanups` in `seen`.

The latest discussion clarifies a forward-looking architectural constraint: the new call to `repo_config_values()` in `is_racy_stat()` introduces an ordering dependency for future work, as any effort to support in-process submodule operations (e.g., `git diff --recurse-submodules`) will require `repo_config_values()` to work on arbitrary repositories, not just `the_repository`. This is not a regression but makes the existing limitation more visible. The author confirms that no such `--recurse-submodules` option currently exists for `git diff` and asks for guidance on testing the new code path, though this does not block graduation. The series remains uncontroversial and ready for `master`.
