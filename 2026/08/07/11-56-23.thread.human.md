This thread is about D. Ben Knoble’s patch series (v2) that replaces the build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, to allow users to enable nanosecond precision without recompiling Git. The goal is to reduce "racy Git" problems on supported filesystems, but the series has sparked discussion about performance, architectural trade-offs, and cross-platform correctness.

The v2 series addressed a significant performance regression in the initial version, where calling `repo_config_get_bool()` on every `is_racy_stat()` invocation caused a ~41× slowdown in `git diff` benchmarks. The fix—caching the value in the repository’s `repo_config_values` struct—restored performance to baseline, but the architectural question of where to cache `core.useNanosec` remains unresolved. Options include `repo_config_values` (modern but limited to `the_repository`), `repo_settings` (supports per-repository variation), or a global variable as a temporary measure. Patrick Steinhardt has suggested that requiring `the_repository`-cleanliness could block the series indefinitely, while D. Ben Knoble’s analysis shows that all current call paths to `repo_config_values()` already terminate at `the_repository`, meaning the limitation is not new.

Junio C Hamano’s latest review raises a critical cross-platform correctness issue: if `core.useNanosec=true` is set in a shared configuration (e.g., a network-mounted `.gitconfig`) and Git is used on a platform where `NO_NSEC` is defined, the code may compare nanosecond fields containing garbage or zero, leading to silent data corruption or undefined behavior. This affects users in heterogeneous environments (e.g., Linux and older Unix variants). Junio suggests either forcing `use_nanosec` to false in `NO_NSEC` builds or adding a runtime check to disable the feature on unsupported platforms. This issue is now a blocker for the patch’s correctness.

The first two patches—a Meson build-system fix and a no-op refactor of `repo_config_values_init`—are uncontroversial and ready to advance independently. The series is under review, with the core change (third patch) still the focus of architectural and correctness discussions. A conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics advance. Testing for platform-dependent behavior remains an open question, and broader performance implications (e.g., for `git status` or `git add`) are unmeasured.
