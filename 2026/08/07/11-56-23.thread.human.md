This thread is about a patch series by D. Ben Knoble that replaces Git’s build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision on supported filesystems without recompiling Git. The goal is to reduce "racy Git" problems, where timestamp granularity causes false conflicts.

The series is currently under review in its first version (v1). Junio C Hamano, the maintainer, has identified a critical performance flaw in the core patch: the implementation calls `repo_config_get_bool()` on every `is_racy_stat()` invocation, creating a prohibitively expensive hot-path regression. Junio proposed caching the value in the repository’s `repo_settings` struct for constant-time access. The rest of the series—including a Meson build-system fix for `MAN_BASE_URL`, a no-op refactor of `repo_config_values_init`, and documentation updates—is uncontested. The series is based on `master` and consists of three patches, though it conflicts textually and semantically with `ty/repo-config-cleanups` in `seen` (which removes comments this series adds). Benchmark results show a ~57x performance improvement for `git diff` in new worktrees when `core.useNanosec` is enabled.

The only new feedback in this email is from SZEDER Gábor, who commented on the commit message’s `Best-viewed-with: --ignore-space-change` directive. Gábor suggested keeping the hint for future readers but did not engage with the technical substance, performance concerns, or the caching proposal. The series remains open for a v2 addressing Junio’s performance critique, with unresolved questions about naming (`core.useNanosec` may be too specific), platform-dependent testing, and broader performance implications.
