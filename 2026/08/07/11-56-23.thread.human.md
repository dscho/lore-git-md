The `dk/use-nsec-runtime` series, which graduated to Junio’s `next` branch on 2024-07-10, replaces the build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`) to let users enable nanosecond precision without recompiling Git. The change reduces "racy Git" problems on supported filesystems and includes a Meson build-system fix and a no-op refactor of `repo_config_values_init`. All prior feedback has been addressed, and the series is now in its final holding period before graduating to `master`.

The key technical trade-off is the retained `#ifndef NO_NSEC` guard in `environment.c`, which prevents users on `NO_NSEC` builds from enabling `core.useNanosec` without recompiling. Jeff King (Peff) and D. Ben Knoble agree this guard is reasonable, though it leaves a theoretical edge case where mixed builds (one with `NO_NSEC` and one without) could produce false "racy" comparisons. The series also introduces a latent architectural constraint: `is_racy_stat()` now calls `repo_config_values()`, which only works for `the_repository`, so submodule operations that rely on this code path will silently default `core.useNanosec` to false. Knoble’s partial analysis confirms this limitation isn’t a regression, but Junio’s latest message warns it could block future recursive submodule features. No further code changes are planned, though routine conflict resolution with `ty/repo-config-cleanups` may be needed before final graduation.
