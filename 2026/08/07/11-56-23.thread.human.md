This thread is about D. Ben Knoble’s patch series that replaces the build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`), aiming to reduce "racy Git" problems by allowing users to enable nanosecond precision on supported filesystems without recompiling Git. The series also includes a Meson build-system fix and a no-op refactor of `repo_config_values_init`.

The series is currently under review, with v1 posted. The core change introduces `core.useNanosec` (defaulting to false) and removes `USE_NSEC` from the build system, showing a significant performance improvement for `git diff` in new worktrees when enabled. However, Junio C Hamano’s recent review highlights a critical performance issue: the current implementation calls `repo_config_get_bool()` on every invocation of `is_racy_stat()`, which is prohibitively expensive for a hot code path. Junio suggests caching the value in the repository’s `repo_settings` struct instead, which would require a v2 iteration. The rest of the patch—including the config key introduction, build system cleanup, and documentation updates—is uncontested.

Open questions remain about the naming of `core.useNanosec` (which may be too specific if platforms offer extended precision), how to test platform-dependent behavior, and coordination with the conflicting `ty/repo-config-cleanups` topic in `seen`. The series touches several files, including `environment.c`, `read-cache.c`, and build system files, but does not change the on-disk format. No test coverage updates have been proposed yet for the nanosecond-precision change. The author has acknowledged the naming and testing concerns and noted the conflict with `ty/repo-config-cleanups`. The next steps will likely involve addressing Junio’s performance feedback and resolving the conflict before the series can advance.
