This thread is about D. Ben Knoble’s patch series that replaces Git’s build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision without recompiling. The series is now in Junio’s `next` branch (integration testing) after addressing all prior feedback, including a performance regression and cross-platform correctness concerns.

The key technical change is making nanosecond precision configurable at runtime, with the new `core.useNanosec` option defaulting to false. The series also includes a Meson build-system fix and a no-op refactor of `repo_config_values_init`. Performance is restored to baseline after caching the config value, and the code ensures backward compatibility on platforms lacking nanosecond support by treating `use_nanosec` as false when `NO_NSEC` is defined.

A recent discussion between Jeff King (Peff) and Knoble clarified the necessity of the `#ifndef NO_NSEC` guard around the config handler. While the guard prevents false negatives in racy timestamp checks, it also restricts users on `NO_NSEC` builds from enabling `core.useNanosec` without recompiling. Peff surfaced a subtle edge case where mixed builds (one with `NO_NSEC` and one without) on a nanosecond-capable system could lead to false "racy" comparisons, though this is unlikely in practice. Both agreed the guard is justified given the complexity of eliminating `NO_NSEC` entirely, and no changes were proposed.

The series is technically complete, with Junio locally amending a minor typo fix ("comparisions" → "comparisons"). The only remaining loose end is a routine conflict with `ty/repo-config-cleanups` in `seen`, which will need resolution if both topics advance.
