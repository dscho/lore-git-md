This thread is about replacing Git’s build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, allowing users to enable nanosecond precision on supported filesystems without recompiling. The series, now at version 3, is effectively complete and cooking in Junio’s `next` branch under the topic `dk/use-nsec-runtime`. D. Ben Knoble is the author, and the patches have received thorough review from Junio C Hamano and Patrick Steinhardt.

The core change removes the compile-time switch in favor of a runtime setting, with backward compatibility ensured by `#ifdef`-ing out the `use_nanosec` field and related code paths on platforms lacking nanosecond support (`NO_NSEC`). A performance regression in the initial version—caused by repeatedly parsing the config key—was fixed by caching the value in the repository’s `repo_config_values` struct. The remaining polish items, all agreed upon, include unconditionally initializing the `use_nanosec` field to avoid uninitialized reads, simplifying preprocessor guards in `is_racy_stat()`, and adding a documentation warning about platform limitations. The idea of a runtime warning for unsupported platforms was rejected to avoid user friction in shared configurations.

The series also includes two uncontroversial patches: a Meson build-system fix and a no-op refactor of `repo_config_values_init`. A minor conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics advance, but the series is otherwise ready to graduate to `master`. Testing remains a loose end due to the platform-dependent nature of the change, though this isn’t blocking progress.
