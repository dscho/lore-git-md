This thread is about replacing Git’s build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, allowing users to enable nanosecond precision on supported filesystems without recompiling Git. The series, now at v3 and cooking in `next` under the topic `dk/use-nsec-runtime`, aims to reduce "racy Git" problems by making nanosecond precision configurable at runtime.

The author, D. Ben Knoble, has addressed the key technical hurdles: a cross-platform correctness blocker (silent corruption risk on `NO_NSEC` platforms) was resolved by `#ifdef`-ing out the `use_nanosec` field and related code paths in such builds, and a performance regression in `git diff` (a ~41× slowdown in v1) was fixed by caching the config value in the repository’s `repo_config_values` struct. Benchmark results confirm performance is now restored to baseline. Junio C Hamano and Patrick Steinhardt reviewed v3 and identified final polish items—unconditional initialization of `use_nanosec`, simplified `#ifndef` guards, and a missed reference in `builtin/update-index.c`—all of which the author has agreed to address. The Meson build-system fix and a no-op refactor in the series are uncontroversial and ready to advance independently.

The series is now effectively complete from a technical standpoint, with only minor documentation and code clarity improvements remaining. The author declined to add a runtime warning for `NO_NSEC` builds where `core.useNanosec` is enabled, opting instead for better documentation to warn users about platform/filesystem limitations. A textual conflict with `ty/repo-config-cleanups` in `seen` may require resolution if both topics advance. The broader architectural question of where to cache `core.useNanosec` (`repo_config_values`, `repo_settings`, or a global variable) remains unresolved but does not block the series’ progress. The series is on track for graduation to `master` once the final polish is applied.
