This thread is about D. Ben Knoble’s patch series to replace Git’s build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, allowing users to enable nanosecond precision without recompiling Git. The series is now in its third version and is cooking in Junio C Hamano’s `next` branch under the topic `dk/use-nsec-runtime`.

The core change is technically complete, with the performance regression from the first version resolved by caching the config value in the repository’s `repo_config_values` struct. Cross-platform correctness is ensured by `#ifdef`-ing out the `use_nanosec` field and related code paths in builds where `NO_NSEC` is defined, preventing silent corruption when the option is enabled on unsupported platforms. The series also includes two uncontroversial patches: a Meson build-system fix and a no-op refactor of `repo_config_values_init`, both of which are ready to advance independently.

Junio’s latest review identified a correctness issue in the initialization logic, where the `use_nanosec` field was unconditionally defined but only initialized when `NO_NSEC` was *not* defined, risking uninitialized reads. He proposed unconditionally initializing the field to `0` and simplifying the preprocessor guards in `is_racy_stat()`. Patrick Steinhardt’s recent review adds final polish items: the documentation should warn users about platform/filesystem limitations, the initialization fix should be applied, the preprocessor guards should be simplified, and a lingering `USE_NSEC` reference in `builtin/update-index.c` needs updating. These are straightforward fixes, and the series is otherwise ready to graduate to `master` once they are addressed. The only remaining architectural question—whether to cache the config value in `repo_config_values`, `repo_settings`, or a global variable—has been deferred, with Patrick suggesting a global variable as a fallback if the project prefers to avoid expanding the `the_repository`-only surface area. A textual conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics advance.
