This thread is about D. Ben Knoble’s patch series that replaces Git’s build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision without recompiling Git. The series, now in its sixth version, graduated to Junio’s `next` branch on July 10, 2024, meaning it is undergoing integration testing and is on track for the next release. The only remaining action is a trivial documentation typo fix ("comparisions" → "comparisons") requested by Junio.

The series addresses a long-standing "racy Git" problem by making nanosecond precision configurable at runtime, with performance and cross-platform correctness concerns resolved in prior iterations. Jeff King (Peff) recently raised a subtle edge case: if a user builds two versions of Git (one with `NO_NSEC` and one without) on a system that supports nanosecond timestamps, an index generated by the non-`NO_NSEC` build could store real nanosecond values that the `NO_NSEC` build would misinterpret as zero, leading to false "racy" comparisons. While this scenario is unlikely in practice, it adds a new dimension to the platform-compatibility discussion. The author may choose to document this risk, but no code changes are required unless the maintainer or author decides otherwise.

Key participants include D. Ben Knoble (author), Junio C Hamano (maintainer), Patrick Steinhardt, and Jeff King. Junio and Patrick have confirmed the series is technically sound, with all prior feedback addressed, while Peff’s review surfaces a hypothetical but valid correctness concern. The series also includes a Meson build-system fix and a no-op refactor, both uncontroversial and ready to advance independently.
