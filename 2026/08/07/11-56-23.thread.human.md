This thread replaces Git’s build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, allowing users to enable nanosecond precision on supported filesystems without recompiling. The series, now at v5 under the topic `dk/use-nsec-runtime`, is effectively complete and ready to graduate to `master` after one final cosmetic tweak.

The core change—introducing `core.useNanosec`—resolves long-standing "racy Git" issues by letting users toggle nanosecond precision at runtime. Earlier versions faced a performance regression (a ~41× slowdown in `git diff` benchmarks) and a cross-platform correctness risk (silent corruption if the option was set on a `NO_NSEC` platform). Both are now fixed: the performance issue by caching the config value in `repo_config_values`, and the correctness risk by unconditionally including the field in the struct but treating it as false on unsupported platforms. Junio and Patrick Steinhardt reviewed the series thoroughly, addressing initialization logic, documentation warnings, and code clarity. The only remaining action is a trivial comment change in `builtin/update-index.c` ("defined" → "enabled") to better reflect the runtime nature of the option.

This could complicate future work on in-process submodule operations (e.g., `git diff --recurse-submodules`), but it’s not a regression—`repo_config_values` was already limited to `the_repository`—and doesn’t block graduation. Patrick Steinhardt suggested that if future edge cases arise, the value could be moved to `struct repo_settings` (which supports multiple repositories). The author confirmed no such option exists for `git diff` today, and existing tests pass with the new config. The series also includes a Meson build-system fix (configurable `man_base_url`) and a no-op refactor of `repo_config_values_init`, both uncontroversial.
