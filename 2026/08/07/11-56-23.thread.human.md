This thread is about D. Ben Knoble’s patch series (v3) converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision on supported filesystems without recompiling Git. The series is cooking in Junio’s `next` branch under the topic `dk/use-nsec-runtime` and consists of three patches: a Meson build-system fix, a no-op refactor of `repo_config_values_init`, and the core change introducing `core.useNanosec`.

The key goal—reducing "racy Git" problems by making nanosecond precision configurable at runtime—has broad support, and the series has addressed major technical hurdles. A performance regression in the initial version (~41× slowdown in `git diff` benchmarks) was fixed by caching the `core.useNanosec` value in the repository’s `repo_config_values` struct, restoring performance to baseline. A cross-platform correctness blocker—silent corruption risk when `core.useNanosec=true` is set on a `NO_NSEC` platform—was resolved by `#ifdef`-ing out the `use_nanosec` field and related code paths in `NO_NSEC` builds. The Meson build-system fix and no-op refactor are uncontroversial and ready to advance independently.

The sole remaining architectural question is where to cache `core.useNanosec`: `repo_config_values` (modern but limited to `the_repository`), `repo_settings` (supports per-repository variation, e.g., for submodules), or a global variable. The author’s analysis shows that all current call paths to `repo_config_values()` terminate at `the_repository`, but Patrick Steinhardt has suggested a global variable as a fallback if the project is unwilling to accept the current limitation. Junio’s latest review focuses on implementation correctness, identifying an uninitialized-value risk in `NO_NSEC` builds and proposing a cleaner conditional structure in `is_racy_stat()`. These are mechanical fixes that won’t affect performance or functionality.

The series is technically complete and ready for integration once Junio’s suggestions are incorporated. A textual conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics advance. Testing and naming (`core.useNanosec` may be too specific if platforms offer higher precision) remain open but are not blockers. Participants include D. Ben Knoble (author), Junio (maintainer), Patrick Steinhardt, and SZEDER Gábor (surface-level review).
