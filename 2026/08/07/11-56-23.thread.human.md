This thread is about D. Ben Knoble’s patch series (v3) converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The goal is to let users enable nanosecond precision on supported filesystems without recompiling Git, reducing "racy Git" issues. The series is now technically complete, with all correctness and performance concerns resolved, and is cooking in Junio’s `next` branch under the topic `dk/use-nsec-runtime`.

The core change replaces `USE_NSEC` with `core.useNanosec` (defaulting to false) and caches the value in `repo_config_values` to avoid a ~41× performance regression in `git diff` benchmarks. A cross-platform correctness blocker—silent corruption risk when `core.useNanosec=true` is set on a `NO_NSEC` platform—was fixed by `#ifdef`-ing out the `use_nanosec` field and related code paths in such builds. The series also includes a Meson build-system fix and a no-op refactor of `repo_config_values_init`, both of which are uncontroversial and ready to advance independently.

The sole remaining open question is where to cache `core.useNanosec`: `repo_config_values` (modern but limited to `the_repository`), `repo_settings` (supports per-repository variation), or a global variable. The author’s analysis shows all current call paths to `repo_config_values` terminate at `the_repository`, but Patrick Steinhardt has suggested a global variable as a fallback if the project prefers to avoid expanding the `the_repository`-only limitation. The series is otherwise ready for integration, though a conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics advance. Key participants—Junio C Hamano, Patrick Steinhardt, and the author—have all signed off on the technical approach, with only the cache location left to decide.
