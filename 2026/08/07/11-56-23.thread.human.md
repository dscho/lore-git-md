This thread is about a patch series (v3, now cooking in `next`) that replaces Git's build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, allowing users to enable nanosecond precision on supported filesystems without recompiling Git. The goal is to reduce "racy Git" problems, where timestamp resolution can cause false conflicts.

The series has resolved its major technical hurdles: a cross-platform correctness issue (silent corruption risk on `NO_NSEC` platforms) was fixed by conditionally compiling out the `use_nanosec` field and related code paths, and a performance regression in `git diff` (a ~41× slowdown in v1) was addressed by caching the config value in the repository’s `repo_config_values` struct. Junio and Patrick Steinhardt’s recent reviews of v3 focused on final polish—unconditional initialization of the `use_nanosec` field, simplifying preprocessor guards, updating a missed reference in `builtin/update-index.c`, and adding a documentation warning about platform limitations. The maintainer rejected the idea of a runtime warning for unsupported platforms, prioritizing user experience for shared configurations, and the author agreed, noting that users can work around the limitation with per-machine overrides.

The patches are uncontroversial and ready to advance, though a textual conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics graduate. The series is now waiting on the author to address the remaining review feedback before it can move forward.
