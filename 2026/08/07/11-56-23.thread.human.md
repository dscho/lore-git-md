This thread is about replacing Git’s build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, to allow users to enable nanosecond precision on supported filesystems without recompiling Git. The series, now at version 3, is cooking in Junio’s `next` branch under the topic `dk/use-nsec-runtime` and consists of three patches: a Meson build-system fix, a no-op refactor of `repo_config_values_init`, and the core change introducing `core.useNanosec`.

The key technical goal—reducing "racy Git" problems by making nanosecond precision configurable at runtime—has been achieved, with cross-platform correctness and performance regressions resolved. The remaining open items are minor polish: unconditionally initializing the `use_nanosec` field, simplifying preprocessor guards, updating a missed reference in `builtin/update-index.c`, and adding a documentation warning about platform limitations. The Meson fix and refactor are uncontroversial and ready to advance independently. A recent decision by Junio rejects adding a runtime warning for `core.useNanosec=true` on `NO_NSEC` platforms, favoring documentation over proactive alerts to avoid annoying users with shared configurations.

The series is largely complete, pending the author’s response to the final review comments. The only unresolved architectural question is where to cache the `core.useNanosec` value—whether in `repo_config_values` (modern but limited to `the_repository`), `repo_settings` (supports per-repository variation), or a global variable—but this is not blocking progress. The author has expressed willingness to accept any of these options based on project preference.
