This thread is about D. Ben Knoble’s patch series to replace Git’s build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision without recompiling. The series also includes a Meson build-system fix and a no-op refactor.

The first version introduced a severe performance regression—every call to `is_racy_stat()` parsed the config key, slowing `git diff` by about 41×. The author has since benchmarked a fix that caches the value in the repository’s `repo_settings` struct, restoring baseline performance. The rest of the series remains uncontested, though there’s a textual conflict with another topic in Junio’s `seen` branch.

Patrick Steinhardt’s recent review focuses on where to cache the config value. He confirms that `repo_config_values()` is the modern place for config-driven settings but notes it’s currently limited to `the_repository`. He raises the question of whether `core.useNanosec` might ever need to vary per-repository (e.g., for submodules), which would favor `repo_settings` over `repo_config_values()`. The author will need to address this architectural choice in the next version. Other open questions include the config key’s naming, platform-dependent testing, and broader performance implications.
