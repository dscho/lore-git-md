This thread is about D. Ben Knoble’s patch series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision without recompiling Git. The goal is to reduce "racy Git" problems on supported filesystems. The series is now at v2, addressing a critical performance regression in the initial version—a ~41× slowdown in `git diff` benchmarks—by caching the configuration value in the repository’s `repo_config_values` struct. Benchmarks confirm the fix restores performance to baseline.

The series consists of three patches: a Meson build-system fix (uncontroversial and ready to advance), a no-op refactor of `repo_config_values_init` (mechanical and uncontested), and the core change introducing `core.useNanosec`. The core patch removes the `USE_NSEC` build knobs, updates documentation, and replaces compile-time checks with runtime logic. While the performance regression is resolved, an architectural question remains: where to cache the `core.useNanosec` value. Options include `repo_config_values` (modern but limited to `the_repository`), `repo_settings` (supports per-repository variation), or a global variable as a temporary measure. The author’s analysis shows that `repo_config_values` is already exposed via public `libgit.a` interfaces, meaning the `the_repository`-only limitation is not new. Patrick Steinhardt and the author frame this as a pragmatic choice—land now with `repo_config_values` or use a global variable until the broader `the_repository` issue is resolved.

The series is under active review, with Junio C Hamano and Patrick Steinhardt engaging on the architectural trade-offs. SZEDER Gábor provided a surface-level review on commit message formatting. A textual conflict with `ty/repo-config-cleanups` in `seen` will require resolution if both topics advance. Testing for the nanosecond-precision change remains a loose end due to platform dependencies, and broader performance implications (e.g., for `git status` or `git add`) are unmeasured. The series is based on `master` and awaits further feedback on the cache location decision.
