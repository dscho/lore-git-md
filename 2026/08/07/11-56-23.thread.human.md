This thread is about replacing Git’s build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`, allowing users to enable nanosecond precision on supported filesystems without recompiling. The series, now at v5 under the topic `dk/use-nsec-runtime`, is effectively complete and ready to graduate to `master` pending one trivial cosmetic change: replacing "defined" with "enabled" in a comment in `builtin/update-index.c` to better reflect the runtime nature of the new setting.

The core change removes the last preprocessor directives tied to `USE_NSEC` and introduces a cached config value in `repo_config_values`, resolving a ~41× performance regression identified in v1. Junio and Patrick Steinhardt reviewed v3 and v4, identifying final polish items—unconditional initialization of the config field, simplified guards in `is_racy_stat()`, and clearer documentation warnings—all now addressed. The only remaining design question, whether to warn users who set `core.useNanosec=true` on platforms lacking nanosecond support, was settled: no runtime warning will be added, as shared `.gitconfig` files would make such warnings obnoxious. Users can work around the limitation with per-machine overrides like `includeIf`.

The series also includes two uncontroversial patches: a Meson build-system fix exposing a configurable `man_base_url` knob (mirroring the Makefile’s `MAN_BASE_URL`), and a no-op refactor of `repo_config_values_init` to group assignments by config section. A textual conflict exists with `ty/repo-config-cleanups` in `seen` but will require routine resolution if both topics advance.

The only forward-looking concern is architectural: the new call to `repo_config_values()` in `is_racy_stat()` introduces an ordering constraint for future work, as `repo_config_values()` currently only works on `the_repository`. This isn’t a regression—it was already limited—but the new call site makes the limitation more visible. Patrick Steinhardt suggests that if future edge cases arise, the series could be refactored to move `use_nanosec` into `struct repo_settings`, which already supports multiple repositories. The author confirms no `--recurse-submodules` option currently exists for `git diff`, so the constraint doesn’t block graduation. Testing remains platform-dependent but isn’t blocking; existing tests pass when `core.useNanosec=true` is set.
