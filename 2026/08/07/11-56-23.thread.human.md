This thread is about D. Ben Knoble’s patch series to replace Git’s build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision without recompiling Git. The series, now at version 3, is cooking in Junio’s `next` branch under the topic `dk/use-nsec-runtime` and is effectively complete, pending final polish.

The core change introduces `core.useNanosec` (defaulting to false) and removes the `USE_NSEC` macro, while ensuring backward compatibility on platforms lacking nanosecond support by `#ifdef`-ing out the relevant code paths. A performance regression in the initial version—caused by calling `repo_config_get_bool()` on every `is_racy_stat()` invocation—was fixed by caching the value in the repository’s `repo_config_values` struct. The series also includes a Meson build-system fix and a no-op refactor of `repo_config_values_init`, both of which are uncontroversial and ready to advance.

The last open design question—whether to emit a runtime warning when `core.useNanosec=true` is set on a `NO_NSEC` platform—has been resolved: **no warning will be added**. Junio and Patrick Steinhardt agreed that such warnings would be "too obnoxious" for users sharing a `.gitconfig` across machines with different Git builds, prioritizing user experience over proactive alerts. The responsibility for avoiding misconfiguration on unsupported platforms now rests on documentation, which will include a warning about platform/filesystem limitations. The remaining polish items (unconditional initialization of `use_nanosec`, simplifying preprocessor guards, and updating a missed `USE_NSEC` reference in a comment) are minor and expected to be addressed shortly. The series is on track to graduate to `master` once these final tweaks are made.
