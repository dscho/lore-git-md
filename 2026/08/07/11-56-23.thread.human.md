This thread is about a patch series that converts Git’s build-time `USE_NSEC` macro to a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision on supported filesystems without recompiling Git. The series, authored by D. Ben Knoble, is now complete and has graduated to the `next` branch for integration testing. The latest version (v6) includes a trivial cosmetic fix requested by Patrick Steinhardt and addresses all prior feedback.

The core change replaces the compile-time decision with a runtime setting, reducing "racy Git" problems while preserving backward compatibility on platforms lacking nanosecond support. Performance concerns raised in earlier versions were resolved by caching the configuration value, and architectural constraints (such as the dependency on `repo_config_values()`) were acknowledged but deemed non-blocking. The series also includes two smaller patches: a Meson build-system fix to align `MAN_BASE_URL` behavior with the Makefile, and a no-op refactor of `repo_config_values_init` for maintainability.

Key participants—Junio C Hamano, Patrick Steinhardt, and the author—agree the series is technically sound and ready for advancement. The only remaining loose ends are a routine conflict with another topic (`ty/repo-config-cleanups`) and the forward-looking constraint on submodule support, which may require future refactoring. The Meson build fix is uncontroversial and could advance independently. No further objections or open questions remain.
