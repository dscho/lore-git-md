This thread is about D. Ben Knoble’s patch series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision without recompiling Git. The series, now at v3, is cooking in Junio’s `next` branch under the topic `dk/use-nsec-runtime`.

The core change replaces the compile-time flag with a new `core.useNanosec` setting, defaulting to false, while preserving backward compatibility on platforms lacking nanosecond support. Earlier versions faced a performance regression (a ~41× slowdown in `git diff` benchmarks) due to repeated config lookups, but this was fixed by caching the value in the repository’s `repo_config_values` struct. A cross-platform correctness issue—silent corruption risk when `core.useNanosec=true` was set on a `NO_NSEC` platform—was resolved by `#ifdef`-ing out the field and related code paths in such builds.

The series also includes two uncontroversial patches: a Meson build-system fix and a no-op refactor of `repo_config_values_init`. Junio and Patrick Steinhardt’s reviews of v3 focused on final polish: unconditionally initializing `use_nanosec` to `0` to avoid uninitialized reads, simplifying preprocessor guards in `is_racy_stat()`, updating a missed reference in `builtin/update-index.c`, and adding platform/filesystem warnings to the documentation. Knoble has now agreed to all these changes, resolving the last technical blocker. The series is effectively ready to advance, though broader questions—like whether to cache the setting in `repo_config_values` (limited to `the_repository`) or a global variable—remain open but don’t block progress. A minor conflict with `ty/repo-config-cleanups` in `seen` may need resolution if both topics graduate.
