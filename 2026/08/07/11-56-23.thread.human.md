This thread is about D. Ben Knoble’s patch series that replaces Git’s build-time `USE_NSEC` macro with a runtime configuration option, `core.useNanosec`. The goal is to let users enable nanosecond precision on supported filesystems without recompiling Git, which should reduce "racy Git" problems. The series is currently under review as v1.

The core patch (the third in the series) removes `USE_NSEC` from the build system and introduces `core.useNanosec`, defaulting to false. It updates key files like `read-cache.c` and `environment.c` to replace compile-time checks with runtime logic, and documents the change in the config and technical docs. Benchmark results show a significant performance improvement for `git diff` in new worktrees when the option is enabled. The patch is well-structured, but the naming (`core.useNanosec`) might still be debated, as some platforms could offer precision beyond nanoseconds. There’s also a known conflict with `ty/repo-config-cleanups` in Junio’s `seen` branch, which will need resolution if both topics advance.

The first two patches in the series are minor: one fixes a Meson build-system issue (`MAN_BASE_URL`), and the other is a no-op refactor of `repo_config_values_init` to reorder assignments and add section comments. These are unlikely to be controversial. The main discussion points are likely to be the naming of the new config key, how to handle platform-dependent testing, and coordinating with the conflicting topic. So far, only the author has weighed in, acknowledging these open questions.
