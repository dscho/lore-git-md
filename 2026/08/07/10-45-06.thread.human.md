This thread is about Patrick Steinhardt’s five-patch series introducing a pluggable interface for packfile generation in Git’s object database (ODB) layer. The goal is to decouple Git’s transport layer (fetch, push, bundle) from the "files" ODB backend, a key step in Patrick’s broader ODB abstraction effort to support alternative backends. This is the first public iteration of the series, posted on August 5, 2026, and it’s currently under review.

The first patch lays the groundwork by defining the core ODB interface, `odb_generate_pack()`, and implementing it for the "files" backend. It introduces a new `struct odb_generate_pack_options` to encapsulate transport-layer parameters like wants, haves, and progress settings, while intentionally omitting backend-specific options. The files backend’s implementation delegates to the existing `git pack-objects` command, spawning it as a child process. The interface is designed for asynchronous operation, returning file descriptors for the pack and progress output. This patch touches the ODB core and the files backend, adding about 350 lines of new code.

The series is still in its early stages, with no reviews yet. Key open questions include the long-term plan for `git-pack-objects` and repository maintenance, which are deferred to a future `git-objects` command, and whether the new interface will need to evolve once that work begins. There’s also some uncertainty about potential performance or edge-case regressions in transport operations, such as progress meters or option handling. The next patches will refactor `upload-pack`, `send-pack`, and `bundle` to use this new interface.
