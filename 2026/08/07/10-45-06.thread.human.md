This thread is about Patrick Steinhardt’s six-patch series (v2) making Git’s packfile generation pluggable through a new object database (ODB) interface. The goal is to decouple Git’s transport layer—fetch, push, and now bundle—from the "files" ODB backend, paving the way for alternative backends beyond loose objects and packfiles. This is part of Steinhardt’s larger ODB abstraction effort, though repository maintenance and `git-pack-objects` are deferred to a future `git-objects` command.

The series is now complete with the v2 iteration, which splits the original fifth patch into three to address Junio C Hamano’s review concerns about lingering `the_repository` usage. All transport commands now delegate packfile generation to the ODB layer, using a declarative `struct odb_generate_pack_options` to encapsulate settings like wants, haves, shallow boundaries, filter specs, and progress meters. The files-backend implementation translates these options into the equivalent `git pack-objects` command-line arguments, preserving existing functionality like thin packs, shallow clones, and partial clones. The only user-visible change is a simplification of progress-meter options in `git bundle`, though default behavior remains unchanged.

The series is queued in Junio’s `seen` branch after he resolved a merge conflict with the `--no-ref-delta` topic by temporarily dropping the latter. No substantive objections have been raised, but the series is still under active review, with a focus on testing edge cases like error handling during pack generation and interactions with shallow or partial clones. Junio’s review of v1 flagged two instances of `the_repository` usage, which v2 addresses by refactoring `bundle.c` to eliminate most global repository references. The remaining `extern` dependency in `get_log_output_encoding()` is noted as a minor loose end. Taylor Blau confirmed the `--no-ref-delta` series is still in development but agreed to pause it to unblock the ODB work. Contributors working on alternate ODB backends or transport-layer improvements may want to monitor the new `odb_generate_pack()` interface.
