This is the final patch in Harald Nordgren’s v13 series implementing `git history squash`, a new subcommand that folds a commit range into a single commit while preserving merge topology and descendant history. This patch adds the **message editing** feature, completing the series.

The patch enables editing the squashed commit message by default, matching the behavior of `git rebase -i --autosquash`. When the user runs `git history squash`, an editor opens with a pre-filled template that groups `fixup!`, `squash!`, and `amend!` commits under their targets, just like interactive rebase. The `--no-edit` flag skips the editor, using the oldest commit’s message (or the last `amend!` targeting it) instead. The implementation reuses Git’s existing sequencer machinery (`todo_list_rearrange_squash`) to rearrange the todo list and build the template, ensuring consistency with `git rebase`.

Key details:
- **Editor template**: The template mirrors `git rebase -i --autosquash` exactly. `fixup!` messages are commented out entirely, `squash!` messages retain their bodies with only the marker subject commented, and `amend!` replaces its target’s message unless a preceding `squash!` requires both bodies.
- **Abort handling**: If the user clears the editor buffer, the command aborts with a clear error message, leaving the repository unchanged.
- **Test coverage**: The patch adds 200+ lines to `t/t3455-history-squash.sh`, covering edge cases like empty messages, `amend!` replacing its target, and grouping `fixup!` commits under their targets. The tests verify both the template format and the final commit message.

The patch is **well-structured and uncontroversial**. It builds on the sequencer helpers extracted in Patch 3/8 and the range validation/ref-handling logic from earlier patches, ensuring the message editing path aligns with the `--no-edit` behavior. The documentation updates clarify the default behavior and autosquash grouping rules. With this patch, the series is **functionally complete** and ready for integration, pending any final adjustments to address Phillip Wood’s remaining roadmap items (e.g., the ref-filter display bug in patch 3.5).
