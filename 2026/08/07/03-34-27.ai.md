This is the third patch in Patrick Steinhardt’s six-patch series (v5) making Git’s on-disk object-database (ODB) structures pluggable. The patch moves handling of the `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables from `apply_repository_format()` in `setup.c` into `odb_new()` itself, eliminating a potential duplication point and preparing the ground for a future where alternates are managed inside the “files” backend.

The change is mechanical and self-contained: `odb_new()` gains an `enum odb_new_flags` parameter (`ODB_NEW_HONOR_ENV`) that tells it to read the environment variables, and `apply_repository_format()` now passes the flag instead of duplicating the environment-variable logic. The patch also switches `odb_new()` to use `CALLOC_ARRAY` and removes the redundant `xstrdup_or_null`/`free` dance for `o->alternate_db` (the value is already duplicated or NULL at this point). The only external caller that needs adjustment is the in-memory ODB unit test, which now passes `0` instead of empty strings.

This is a refactoring patch with no behavior change; the motivation is to keep ODB creation logic in one place and to align with the planned `objectStorage` extension that will enable non-filesystem backends. The patch is uncontroversial and has been approved by Justin Tobler and Toon Claes. It is part of the ODB abstraction effort and is listed in Junio’s “What’s cooking” report (2025-06-10) as ready for `next`.
