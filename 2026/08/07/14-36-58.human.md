This is a **refactoring patch** in Johannes Sixt’s five-part series to overhaul gitk’s color-preference dialog. The patch consolidates the logic that sets the initial colors of the color-swatch labels into the existing helper procedure `prefspage_set_colorswatches`, eliminating duplicate code. Currently, the swatch colors are set twice: once when the dialog is created and again when the user picks a new color. This change removes the duplication by calling the helper once at dialog construction, ensuring the same code path is used for both initial and updated colors.

The patch is purely mechanical—thirteen lines of inline color assignments are removed, and a single call to `prefspage_set_colorswatches` is added at the end of the dialog setup. There are no behavior changes, and the patch serves as a prerequisite for later UI improvements in the series, such as making the swatches themselves clickable. Mark Levedahl’s review is **surface-level**, noting only that the change is a clean consolidation of logic. No substantive feedback or concerns have been raised yet. The patch is confined to `gitk-git/gitk` and does not affect any other part of Git.
