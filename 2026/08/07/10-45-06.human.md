This is the cover letter for a five-patch series from Patrick Steinhardt that makes packfile generation pluggable in Git’s object database (ODB) layer. The goal is to allow alternative ODB backends to generate packfiles without being tied to the traditional "files" backend implementation.

The series focuses specifically on the parts of packfile generation needed for the transport layer (fetch, push, bundle), leaving maintenance-related generation (e.g., `git repack`) unchanged for now. Patrick notes that `git-pack-objects` remains backend-specific due to its many options, but he plans to address this later by introducing a new `git-objects` command to handle ODB operations more generically.

Key changes include:
- A new ODB interface for packfile generation (patch 1).
- Updates to `upload-pack`, `send-pack`, and `bundle` to use the new interface (patches 2–5).
- Refactoring in `builtin/bundle.c` to clean up progress meter handling.

The series is well-scoped and builds on Patrick’s ongoing ODB abstraction work. It’s a logical next step for making Git’s storage layer more modular, though the commit messages don’t detail how this interacts with existing backends (e.g., reftable). If you’re following the ODB effort or care about transport-layer internals, this is worth tracking. The code looks clean, and the motivation is clear.
