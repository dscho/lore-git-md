This is a refactoring patch targeting the `the_repository` removal effort. It moves the global `fetch_if_missing` variable into `struct repository`, making it a per-repository flag that controls whether missing objects should trigger lazy fetches from promisor remotes. This is the third iteration of the patch, addressing feedback from Junio C Hamano and Patrick Steinhardt on the v2 submission.

The patch updates 15 files to replace the global `fetch_if_missing` with the repository-specific `repo->fetch_if_missing`. The default value remains `1` (enabled), preserving existing behavior. Special handling is added in `builtin/fsck.c` and `builtin/index-pack.c` to defer operations on the repository until after parameter parsing is complete, avoiding null pointer dereferences when these commands are invoked with `-h`. The partial clone documentation is updated to reflect the new per-repository nature of the flag.

Key changes in v3 include:
- Removing the conditional check for `repo` in `builtin/index-pack.c` and instead using `(repo ? repo : the_repository)->fetch_if_missing = 0` to handle both repository-bound and repository-less invocations. This addresses the null pointer dereference risk identified in v2 while preserving the existing behavior for `index-pack` when run outside a repository.
- The patch now requires `index-pack` to always receive a valid `repo` parameter, eliminating the need for the `UNUSED` annotation and simplifying the logic. This aligns with Junio’s preferred approach of restricting `index-pack` to repository-bound operation, though the broader design question of whether `fetch_if_missing` belongs in `struct repository` remains unresolved.
- The `setup.c` fix remains unchanged, setting `the_repository->fetch_if_missing = 0` when `NO_LAZY_FETCH_ENVIRONMENT` is set.

The patch is well-structured and addresses the immediate correctness issues raised in v2. However, the architectural debate about whether `fetch_if_missing` should be tied to `struct repository` is still open. Junio’s review in v2 outlined three possible approaches, and the author has adopted the first (restricting `index-pack` to repository-bound operation) as a pragmatic solution. The other two approaches—a fallback to `the_repository` or a new global "basic settings" structure—remain on the table for future discussion.

No new test coverage is introduced, but the changes are expected to preserve existing behavior. The patch is part of the broader libification and `the_repository` removal efforts, making it a logical step toward eliminating global state. The author has acknowledged the need for further testing, particularly around per-repository behavior and repository-less invocations, but the v3 patch is a clear improvement over v2 and appears ready for further review.
