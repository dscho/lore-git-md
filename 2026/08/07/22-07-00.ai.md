This is the fifth patch in Pablo Sabater’s GSoC v5 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch converts the last remaining error path in `fetch_object_info()` from returning `-1` to calling `die()`, aligning it with the function’s other error paths and making its signature `void`. The change is purely mechanical and uncontroversial, touching only `fetch-object-info.c`, `fetch-object-info.h`, and `transport.c`.

The patch addresses a latent robustness issue: previously, a short read while parsing attribute lines would return `-1`, which propagated through `fetch_object_info_via_pack()` and `get_remote_info()` before eventually dying with a generic message in `cat-file`. Now, the function fails fast with a clear error message (`"object-info: expected X attributes, got Y"`), matching Git’s defensive programming practices. The updated signature (`void`) reflects that the function no longer returns success/failure codes, and callers in `transport.c` are updated to drop the now-unused return value check.

No behavior changes or new functionality are introduced. The patch is part of the series’ broader effort to harden the remote-object-info protocol handling, complementing earlier patches that added validation for under-length and over-length server responses. Junio’s prior feedback on protocol hygiene is fully addressed, and the patch is explicitly marked as ready to merge. The files modified are `fetch-object-info.c` (function body and signature), `fetch-object-info.h` (declaration), and `transport.c` (caller updates). The change preserves `const` qualifiers on parameters, matching the original function signature.
