This is a bugfix targeting the `git push` porcelain output. Xavier Morel follows up on his earlier report about inconsistent `--porcelain` behavior when deleting non-existent refs, now proposing a concrete implementation plan.

The patch is not yet written, but the discussion has moved from "is this a bug?" to "how should we fix it?". Xavier outlines a three-step approach: (1) modify `match_explicit` to create dummy refs with failure status instead of bailing early, (2) ensure `set_ref_status_for_push` preserves pre-set statuses, and (3) adapt the reporting code to handle the new case. He asks whether to introduce a new status code (`REF_STATUS_REJECT_NODELETE`) or repurpose an existing one.

The maintainer (Junio) has already signaled openness to a patch, so this looks like a well-scoped, uncontroversial fix. The main open question is the status-code design, which is a minor technical detail rather than a fundamental disagreement. If implemented cleanly, this should resolve the script-breaking inconsistency in `--porcelain` output.
