This is the final patch in Patrick Steinhardt’s six-part series making on-disk object-database (ODB) structure creation pluggable. The patch implements the `create_on_disk` callback in the "files" backend, completing the architectural shift begun in earlier patches. The top-level `objects/` directory remains hard-coded (required for repository discovery), but backend-specific subdirectories (`objects/pack/`, `objects/info/`) are now created by the backend itself via `safe_create_dir()` calls. This change enables future ODB backends to implement custom on-disk layouts without modifying core setup code.

The patch touches three files: `odb/source-files.c` (adds the callback implementation), `odb/source.h` (declares the callback and its wrapper), and `setup.c` (replaces hard-coded directory creation with the callback invocation). The `create_object_database()` function now delegates subdirectory creation to the backend after initializing the ODB, while still ensuring the mandatory `objects/` directory exists when not overridden by environment variables. The callback is optional (NULL-checked), so backends that don’t need on-disk setup (e.g., in-memory ODBs) remain unaffected.

This is a clean, well-motivated refactoring that aligns with the ongoing ODB abstraction effort. The implementation is straightforward and addresses the last technical hurdle for pluggable ODB backends. The series is fully approved, with only minor docstring and formatting nits resolved in v5, and Junio’s "What’s cooking" report (2025-06-10) lists it as ready for `next`. The patch itself introduces no new open questions—it simply wires up the callback mechanism established in earlier patches.
