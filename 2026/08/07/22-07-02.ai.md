This is the seventh patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the server-side object-info handler to accept "type" as a requested field and transmit the object type as a string (e.g., `"blob"`) alongside the existing size field.

The change is straightforward and mechanical: it adds a `type` bit field to `struct requested_info` in `protocol-caps.c`, updates the server-side handler to parse the "type" keyword in client requests, and modifies `send_info()` to include the object type in the response when requested. The patch also includes two minor cleanups—fixing a bit-field style nit (`size:1` → `size: 1`) and wrapping an over-long line in `send_info()`—that were noted in earlier reviews. Test coverage is expanded in `t5701-git-serve.sh` with a new test verifying the server handles requests for both "size" and "type", including duplicate OIDs.

The implementation follows the established pattern from the predecessor series and is uncontroversial. The server transmits type data as a string, matching the protocol’s existing behavior for size, and the client-side parsing logic (introduced in patch 8/10) will map this string to an internal `enum object_type`. The patch is part of the end-to-end chain for object type metadata and is ready for integration. No open technical concerns remain, and the series as a whole is now feature-complete and merge-ready.
