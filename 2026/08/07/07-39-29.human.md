This is part of the `git history squash` feature series, now in its thirteenth iteration. This specific patch (6/8) implements **branch protection** during range squashing: it detects and blocks operations that would leave local branches dangling, offering a clear error message and a `--update-refs=head` escape hatch.

The patch adopts Phillip Wood’s ref-filter-based approach, replacing the earlier `oidset` mechanism. It now **prints sorted branch names** in the error message (e.g., "topic-1, topic-2") and adds an advice hint (`advice.historyUpdateRefs`) that guides users to the `--update-refs=head` flag. The protection is limited to local branches, matching the scope of the default rewrite mode; tags and remote-tracking refs are unaffected. Tests cover both the error case and the advice-silencing behavior.
