This is the first patch in Patrick Steinhardt’s six-part series making Git’s on-disk object database (ODB) structures pluggable. It fixes a latent correctness bug: when Git loads the loose-object map (used for compatibility hash algorithms like SHA-256 with SHA-1), it was always reading from the repository’s common `objects/` directory instead of the path specific to each ODB source. This meant alternates’ loose-object maps were silently ignored, breaking repositories that rely on compatibility hashes.

The fix is surgical: `load_one_loose_object_map()` now constructs the map path from `loose->base.path` instead of the repository’s common directory. The patch also adds a regression test in `t/t1016-compatObjectFormat.sh` that verifies `git rev-parse` correctly resolves an object borrowed from an alternate when using a compatibility hash algorithm. The test is minimal but effective, covering the exact scenario that was previously broken.

This patch stands out because it is both a correctness fix and a prerequisite for the rest of the series. Junio’s “What’s cooking” report (2025-06-10) lists it as “will merge to ‘next’” — meaning it is ready to graduate independently — while the rest of the series remains under review. The fix is uncontroversial, well-tested, and directly addresses a real-world issue (alternates with compatibility hashes). If you care about repository compatibility or the ODB abstraction effort, this patch is worth your time.
