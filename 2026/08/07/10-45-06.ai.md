This is the cover letter for a five-patch series that makes packfile generation pluggable in Git’s object database (ODB) layer. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort, which aims to allow alternative backends beyond the traditional loose-object and packfile storage.

The motivation is to decouple the transport layer (fetch, push, bundle) from the "files" backend by introducing a generic ODB interface for packfile generation. The series does not yet tackle repository maintenance operations or the `git-pack-objects` command, which remain backend-specific due to their many options. Patrick notes that a future `git-objects` command is planned to address this gap, but this series focuses only on the transport layer’s needs.

Key changes include:
- A new ODB interface (`odb_generate_pack()`) and its implementation in the files backend.
- Refactoring `upload-pack`, `send-pack`, and `bundle` to use the new interface, reducing backend-specific code.
- Minor adjustments to option handling in `builtin/bundle.c` to support progress meters.

The series touches core transport mechanisms (`upload-pack`, `send-pack`) and the bundle subsystem, so it’s likely to draw attention from contributors working on fetch/push plumbing or alternate ODB backends. The commit messages are detailed, and the refactoring appears targeted, though the long-term goal of a fully pluggable `git-pack-objects` remains unresolved.
