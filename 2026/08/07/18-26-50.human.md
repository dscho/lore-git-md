This is the fourth patch in Toon Claes’s six-patch v2 series that speeds up the experimental `git last-modified` command by reusing Git’s Bloom filters. It introduces a new public helper, `revs_maybe_changed_in_bloom_with_parents()`, which answers the question “did this commit possibly change the queried path or any of its parent directories?” The helper is needed for the `--show-trees` option, which reports the last-modifying commit for every tree entry from the queried path up to the root. The patch is a straightforward plumbing addition: it wraps the existing `bloom_filter_contains_any_vec()` helper in a new function exposed in `revision.h`, with no callers yet (the next patch will wire it up). The commit message clearly explains the motivation and the distinction from the existing `revs_maybe_changed_in_bloom()` function. The change is small, well-explained, and uncontroversial; it looks like a clean building block for the `--show-trees` correctness fix that follows.
