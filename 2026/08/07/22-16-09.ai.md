This is a **security-focused substantive review** of the `gitk` custom commands feature patch. Junio C Hamano raises a critical security concern about the command substitution mechanism: the current implementation does not properly quote or sanitize placeholders (like `%t` for commit title or `%m` for commit message) when interpolating them into shell commands. Since commit titles and messages can contain arbitrary text—including shell metacharacters—this creates a vector for arbitrary command injection if a user interacts with a malicious repository.

The review identifies a concrete example: a commit title containing `title?'; echo no'` would cause the interpolated command `echo 'title?'; echo no''` to execute both the intended `echo` and the injected `echo no`. Junio notes that this could be exploited for more serious actions, such as running arbitrary processes under the user’s identity. He explicitly questions whether the Tcl `{exec sh -c $cmd}` invocation includes any safeguards against this, and implies that the current design is unsafe unless proven otherwise.

This is a **tested-level concern**: Junio is not merely speculating—he traces the code path, identifies the vulnerable interpolation logic, and demonstrates how an attacker could craft a payload. The review is narrowly focused on the security implications of the placeholder substitution, not on the broader feature design or Tcl implementation quality. No prior discussion of this issue exists in the thread, making this the first substantive technical critique.

The patch author will need to address this by either (1) properly quoting all interpolated values to prevent shell injection, (2) avoiding shell execution entirely (e.g., using direct system calls or a safer API), or (3) documenting and enforcing strict limitations on which placeholders can be used in commands. Until this is resolved, the feature poses a significant security risk. The maintainer (Johannes Sixt) has not yet weighed in on this specific issue, but Junio’s review carries high weight due to his maintainer role and security expertise.
