This is the v13 iteration of the `git history squash` feature, which lets users fold a range of commits into a single commit while preserving descendant history. Harald Nordgren has split the implementation into eight patches, addressing the last structural feedback from Phillip Wood and Junio C Hamano.

The series now cleanly separates range validation, branch protection, commit creation, and message editing into distinct patches. The most visible change is that `--no-edit` is now the only way to skip the editor; message editing is the default, matching `git rebase -i --autosquash`. When `--no-edit` is used, the command preserves the oldest commit’s message or the last `amend!` targeting it, while still folding all changes.

Branch protection has been refined: the command now prints the sorted names of any local branches that would be left dangling, with clearer advice to use `--update-refs=head` if the user only wants to update the current branch. Tags and remote-tracking refs are left untouched.

The test suite remains thorough, covering range parsing, merge commit handling, autosquash message grouping, and ref protection. All prior edge cases (root commits, multiple tips, external parents, nested fixups) are still rejected with clear error messages.

This version looks technically solid and ready for final review. The split patches make the changes easier to follow, and the default behavior aligns with the project’s established autosquash conventions. If no new issues surface, this should be the last reroll before integration.
