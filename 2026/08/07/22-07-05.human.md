This is the final patch in Pablo Sabater’s ten-part GSoC series adding `%(objecttype)` support to `git cat-file --batch-command`’s remote-object-info queries. The patch removes the temporary workaround that used a different default format (`%(objectname) %(objectsize)`) for `remote-object-info` commands and unifies it with the standard default (`%(objectname) %(objecttype) %(objectsize)`) used by all other `cat-file` batch commands.

The change is purely mechanical: it drops the conditional format override in `builtin/cat-file.c`, updates the documentation to reflect that `%(objecttype)` is now supported by `remote-object-info`, and adjusts the test suite (`t1017`) to expect the new unified format. The patch touches four files—`Documentation/git-cat-file.adoc`, `Documentation/gitprotocol-v2.adoc`, `builtin/cat-file.c`, and `t/t1017-cat-file-remote-object-info.sh`—and is uncontroversial. All prior review feedback has been addressed, and the series is now feature-complete and ready for integration. The tests confirm that mixing `info` and `remote-object-info` commands produces consistent output across all transport protocols (git://, file://, http://), ensuring backward compatibility.
