This is the first patch in Patrick Steinhardt’s six-patch series making on-disk ODB structures pluggable, and it is a **bugfix** with dedicated test coverage. The patch corrects a latent correctness issue in loose-object map loading: when iterating through multiple ODB sources (e.g., the main repository and its alternates), Git was always loading the loose-object map from the repository’s common `objects/` directory instead of the path specific to each source. This caused alternates’ loose-object maps to be silently ignored, breaking repositories that rely on compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility).

The fix is surgical: `load_one_loose_object_map()` now constructs the map path from `loose->base.path` instead of using the repository’s common directory. The patch also adds a regression test in `t/t1016-compatObjectFormat.sh` that verifies `git rev-parse` correctly resolves an object borrowed from an alternate when using a compatibility hash algorithm. The test creates two repositories (one as an alternate, one as the borrower), commits an empty commit in the alternate, and confirms that the borrower can resolve the object’s OID in the alternate’s hash format.

The change touches only `loose.c` and the test script, with no new symbols introduced. Junio’s "What's cooking" report (2025-06-10) explicitly lists this patch as "will merge to 'next'" due to its status as a correctness fix, while the rest of the series remains "under review". The patch is uncontroversial and fully approved by Justin Tobler and Toon Claes.
