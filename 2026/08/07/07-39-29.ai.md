This is the sixth patch in the v13 series implementing `git history squash`, a new subcommand that folds a commit range into a single commit. This patch focuses on **branch protection**: it detects and rejects operations that would leave local branches dangling after the squash, unless the user explicitly opts to update only the current branch.

The patch introduces a `ref-filter`-based mechanism to identify all local branches descended from the squashed range. If any such branch exists, the command fails with a clear error listing the sorted branch names (e.g., `topic-1`, `topic-2`) and advises the user to use `--update-refs=head` to restrict updates to the current branch. The protection is limited to local branches, matching the scope of the default rewrite mode; remote-tracking refs and tags are ignored. A new advice key, `advice.historyUpdateRefs`, provides the hint.

The implementation is clean and well-scoped: it reuses Git’s existing `ref-filter` infrastructure, sorts the output for readability, and integrates naturally with the series’ earlier patches (e.g., `resolve_squash_range`). The test coverage is thorough, verifying both the error message format and the advice suppression via config. This patch is a **substantive, uncontroversial refinement** that directly addresses the usability concern raised in prior reviews about silent history corruption. It is ready for integration.
