This is a **substantive review** of Sahitya Chandra’s sparse-index performance patch. Elijah Newren, the sparse-checkout/sparse-index domain expert, raises fundamental questions about the real-world motivation for the change and points out a potential flaw in the test helper implementation.

The review centers on two main concerns. First, Elijah questions the practical utility of the patch: he cannot envision a plausible scenario where a user with an unborn HEAD (e.g., a newly created orphan branch) would simultaneously be using a sparse index containing millions of uncommitted files. He asks whether the patch is addressing a genuine use case or merely cleaning up a TODO in the code. Second, he identifies a bug in the test helper (`test-tool read-cache --index-has-changes`): the helper assumes at most one dirty file and prints the output in a way that would be misleading if multiple paths are dirty, since it prints the entire `strbuf` as a single line under the `dirty=` label.

The patch itself remains under review; no revised version has been posted yet. The thread is part of the broader sparse-checkout/sparse-index performance effort led by Elijah and Derrick Stolee.
