This is patch 3/5 in the v2 series reintroducing a `writev(3p)`-like wrapper for performance. It addresses a platform-specific limitation (`MAX_IO_SIZE`) that affects systems like NonStop, where overly large `iovec` entries can cause `writev(2)` to fail with `EINVAL`. The patch introduces `xwritev()`, a new wrapper that mirrors `xwrite()`'s handling of `MAX_IO_SIZE` by splitting large requests into smaller chunks, ensuring compatibility while maintaining the performance benefits of batched writes.

The core change is the addition of `xwritev()`, which processes `iovec` entries to ensure no single write exceeds `MAX_IO_SIZE`. If the first `iovec` entry is too large, it delegates to `xwrite()` (which already handles this case). For subsequent entries, it truncates the request to fit within the limit, simulating a short write. The wrapper also handles `EINTR` and `EAGAIN` retries, matching `xwrite()`'s behavior. `writev_in_full()` is updated to use `xwritev()`, simplifying its loop and aligning it with `write_in_full()`'s logic for zero-length writes (translated to `ENOSPC`).
