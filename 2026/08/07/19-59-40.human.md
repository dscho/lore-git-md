This is a bugfix patch that plugs a use-after-free in Git's object-name parsing.

The issue surfaces when Git processes a `:<stage>:<path>` argument where `<path>` is a relative path pointing to a sparse directory in a repository with a sparse index. The function `get_oid_with_context_1()` resolves the relative path into a newly allocated string, then later frees that string while still holding a pointer to it. The subsequent call to `reject_tree_in_index()` dereferences the freed memory, leading to undefined behavior—typically a crash under AddressSanitizer or garbled error messages in production builds.

The patch collapses two exit paths into one, ensuring the allocated buffer is freed only after its last use. The commit message walks through the three conditions needed to trigger the bug (relative path, sparse directory, and a specific syntax that bypasses an early check), includes a minimal reproduction recipe, and cites prior discussion that identified the problem but never landed a fix.

A new test in `t1092-sparse-checkout-compatibility.sh` exercises the exact scenario; it fails under `SANITIZE=address` without the code change and passes with it. The fix itself is small (six lines changed) and surgical, touching only the control flow around the free call. The author is a first-time contributor, but the patch is well-motivated, thoroughly tested, and directly addresses a real memory-safety issue.
