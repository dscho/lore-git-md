This is the eighth patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now feature-complete and merge-ready, with all prior review feedback addressed.

This patch prepares the client to parse object type data from the server’s response, though the server does not yet advertise the "type" capability (that comes in patch 9/10). The implementation follows the established pattern from the predecessor series: it adds a `wants_type` flag and a `types` array to `struct fetch_object_info_results`, updates the request logic to include "type" in the protocol exchange, and maps the server’s string response (e.g., `"blob"`) to an internal `enum object_type` using `type_from_string_gently()`. The patch also adds a defensive check to fail fast if the server sends an invalid type string, aligning with Git’s defensive programming practices.

The changes are confined to three files: `builtin/cat-file.c` (updating the batch-command handler to request and store type data), `fetch-object-info.c` (adding the parsing logic and request plumbing), and `fetch-object-info.h` (extending the results struct). The patch is mechanical and uncontroversial, with no behavior changes until the server-side capability is enabled in the next patch. All tests continue to pass, and the series remains on track for integration.
