This thread is a two-patch series from Patrick Steinhardt fixing a flaky test in `t/t7900-maintenance.sh`. The issue is a race condition where auto-detaching background maintenance tasks (triggered by `test_commit()`) interfere with foreground test processes, causing sporadic CI failures. The first patch refactored the test scaffolding to use throwaway repositories, and the second (now posted) applies the actual fix: instead of globally disabling `GIT_TEST_MAINT_AUTO_DETACH` for the entire script, it restores the default behavior and only unsets the variable in the three tests that explicitly require it. This isolates the auto-detach logic to where it’s needed, eliminating the flake without changing the test’s intent or user-visible behavior.

The series is uncontroversial and well-motivated, with a clear explanation of the failure mode (missing `gc` tasks in trace output due to a `maintenance.lock` file from a concurrent detached task) and a minimal, targeted fix. The linked CI failure (GitLab job #15762975482) provides concrete evidence of the issue.
