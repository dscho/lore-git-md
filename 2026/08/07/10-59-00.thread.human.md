This thread is a two-patch series from Patrick Steinhardt aimed at fixing a flaky test in `t/t7900-maintenance.sh`, which has been causing CI reliability issues in GitLab. The flake stems from a race condition between the test process and the auto-detaching background maintenance logic in `git maintenance`. The series is now under review, with no prior versions.

The first patch refactors the test scaffolding by moving three tests (`maintenance.auto config option`, `gc.auto config option`, and `maintenance.auto overrides gc.auto`) into throwaway repositories to isolate environment changes and prevent interference. Karthik Nayak, a GitLab colleague of Patrick’s and a frequent contributor to the maintenance and ref backend areas, reviewed this patch and found it mechanically sound. His only suggestion was to clarify in the commit message why `test_config` was replaced with `git config set` in the isolated repositories—a minor, non-blocking point. The second patch, which addresses the flake itself by restoring default auto-detach behavior and isolating the environment variable `GIT_TEST_MAINT_AUTO_DETACH`, remains unreviewed but is uncontroversial and well-motivated. The series is self-contained, touches only the test file, and does not alter user-visible behavior. No open questions or objections have been raised so far.
