This is the first patch in the v2 series optimizing `git last-modified` by reusing Bloom filters. It refactors the internal Bloom filter helper `check_maybe_different_in_bloom_filter()` to handle the precondition check (`revs->bloom_keyvecs_nr != 0`) internally, simplifying the two callsites in `rev_compare_tree()` and `rev_same_tree_as_empty()`. The change is purely mechanical: the logic remains identical, but the guard is now centralized in the helper function. The commit message notes that the behavioral change (returning `-1` when no Bloom key vectors exist) is unobservable because Bloom statistics are only reported when key vectors are present. This patch sets the stage for the subsequent API refactoring in patch 2/6 by reducing redundancy in the codebase. It’s a clean, uncontroversial refactor with no user-visible impact.
