This is patch 7/10 in the v7 series optimizing `paint_down_to_common()` for one-sided histories. The patch introduces a `paint_state` struct to track per-side commit counters during the paint walk, replacing the old `max_nonstale` pointer-based termination logic with explicit counters for PARENT1-only, PARENT2-only, and pending merge-base candidates.

The refactoring is clean and well-motivated. The new `paint_state` struct and helper functions (`paint_queue_put()`, `paint_queue_get()`, `paint_count_update()`) make the termination logic more explicit and easier to reason about. The counters are maintained via a signed delta system that adjusts the appropriate bucket when commits are enqueued or dequeued, and the termination condition now checks whether all counters are zero. This is functionally equivalent to the old logic but improves code clarity.

Elijah Newren’s review confirms the change is correct and sets the stage well for the later optimization patches. The "pop first" logic in `paint_queue_get()` causes the loop to exit one iteration earlier in some topologies, reducing step counts by one in affected test cases (e.g., `pending-stale` and `se2-*`). The test adjustments are minimal and well-explained, and the documentation updates reflect the new counter-based approach.
