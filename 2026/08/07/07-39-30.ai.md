This is the **seventh patch in the v13 series** for `git history squash`, implementing the core commit-creation logic when `--no-edit` is used. The patch enables the command to fold a range of commits into a single replacement commit without opening an editor, while preserving merge topology, authorship, and descendant history.

**Key functionality introduced**:
- **Commit creation**: Uses `commit_tree_ext()` to build a new commit with the oldest commit’s parents, the tip’s tree, and a message derived from the range’s autosquash markers. The reflog records the full revision expression (e.g., `squash: updating start..HEAD ^keep`).
- **Autosquash handling**: Resolves `fixup!`, `squash!`, and `amend!` targets during the range walk, rejecting markers whose targets lie outside the range. A range made entirely of related markers (e.g., `fixup! fixup! target`) is consolidated into a single commit, with the last `amend!` message used if present.
- **Message preservation rules**: With `--no-edit`, `squash!` or `amend!` commits are rejected unless their target is the first commit in the range (to avoid silent message loss). `amend!` messages are preserved when squashing into a `fixup!` commit by converting the subject prefix to `amend!` and appending the body.
- **Merge commit support**: Retains the full parent list of the original merge commit (the first in the range), ensuring merge topology is preserved. The test suite verifies this behavior for interior merges, nested merges, and octopus merges.

**Files modified**:
- `builtin/history.c`: Adds 260+ lines, including new helpers like `squash_check_subject()`, `squash_amend_message()`, and `squash_squash_message()`. These functions track commit subjects and their autosquash targets using a `strintmap` to enforce message preservation rules.
- `Documentation/git-history.adoc`: Updates the `squash` subcommand description to clarify `--no-edit` behavior, autosquash message handling, and merge commit restrictions.
- `t/t3455-history-squash.sh`: Expands test coverage (330+ lines) for autosquash edge cases, merge handling, and `--no-edit` scenarios. New helpers (`check_commit_author`, `check_log_messages`) improve test readability.

**Notable edge cases tested**:
- **Autosquash interactions**: Nested fixups (`fixup! fixup! target`), `amend!` into `fixup!`, and `squash!` into `fixup!` (which appends messages and changes the subject prefix).
- **Merge commits**: Folding ranges with interior merges, nested merges, and octopus merges (rejected if any parent is outside the range).
- **Ref protection**: Ensures branches pointing to commits inside the range are detected and rejected unless `--update-refs=head` is used.

**Implementation details**:
- **Message template**: The `message_template` parameter (added in Patch 2/8) is used to pass the resolved autosquash message to `commit_tree_ext()`.
- **Object flags**: Extends the existing `SQUASH_SEEN`/`SQUASH_TIP` flags with `SQUASH_AMEND_TARGET` to track `amend!` commits during the range walk.
- **Error clarity**: Messages include commit OIDs and specific advice (e.g., "use `--edit` to combine messages").

**Context in the series**:
This patch is the **first of two** implementing the core squash logic (Patch 8/8 will add message editing). It builds on the range validation (Patch 5/8) and ref protection (Patch 6/8) introduced earlier. The structural decomposition addresses Phillip Wood’s request for incremental review by isolating commit creation from message editing.

The patch is **well-crafted and thoroughly tested**, addressing all prior feedback on autosquash handling, merge preservation, and message rules. The test suite’s focus on edge cases (e.g., nested fixups, merge parents) suggests robustness.
