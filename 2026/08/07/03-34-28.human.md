This is the fourth patch in Patrick Steinhardt’s six-part series making Git’s on-disk object database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort and is now in its final form after addressing all review feedback.

This patch defers the creation of the object database until after the repository format has been applied. Previously, `apply_repository_format()` both configured the repository and created the ODB by calling `odb_new()`. Now, `odb_new()` is lifted out of that function and called explicitly by each caller (`repo_init()`, `enter_repo()`, `setup_git_directory_gently()`, and `init_db()`). The change is mechanical: every site that used to rely on `apply_repository_format()` to set up the ODB now does so itself, passing the same `ODB_NEW_HONOR_ENV` flag when environment variables should be respected.

The motivation is architectural: a subsequent patch will move the creation of on-disk ODB structures (e.g., `objects/pack/`, `objects/info/`) into the ODB backends themselves via a new `create_on_disk` callback. By deferring ODB creation, this patch keeps initialization and on-disk creation together in a single place, simplifying the path for that change. The only exception is `init_db()`, where ODB creation is now encapsulated in a new helper, `create_object_database()`, which combines `odb_new()` and the existing directory-creation logic.

The diff is small (11 insertions, 11 deletions) and touches only three files: `repository.c`, `setup.c`, and `setup.h`. The patch also renames `create_object_directory()` to `create_object_database()` to reflect its expanded role. No new symbols are introduced, and the change is purely refactoring with no behavior difference. All review feedback has been addressed in this version, and the series is fully approved by Justin Tobler and Toon Claes.
