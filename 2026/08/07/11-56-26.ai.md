This is the core patch in D. Ben Knoble's three-part series converting the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). It directly addresses the "racy Git" problem by allowing users to enable nanosecond precision on supported filesystems without recompiling Git.

The patch removes the `USE_NSEC` macro from the build system (Makefile and configure.ac) and introduces a new `core.useNanosec` config key, defaulting to false. The implementation touches `environment.c` and `environment.h` to add the config field, and updates `read-cache.c` and `statinfo.c` to replace compile-time `#ifdef` checks with runtime logic that consults the new config value. Documentation is updated in `Documentation/config/core.adoc` and `Documentation/technical/racy-git.adoc` to reflect the change, with the latter now listing which filesystems are known to work with nanosecond precision.

The author includes benchmark results showing a dramatic performance improvement for `git diff` in new worktrees when `core.useNanosec` is enabled, reducing execution time from ~217ms to ~3.8ms. The patch is well-motivated and technically sound, though the naming (`core.useNanosec`) may still be debated, as the author acknowledges that some platforms might offer extended precision beyond nanoseconds. The change preserves the on-disk format and doesn't require test updates, though platform-dependent behavior could complicate future test coverage.

This is the most substantive patch in the series and the one most likely to generate discussion about naming, testing strategy, and coordination with the conflicting `ty/repo-config-cleanups` topic in `seen`. The runtime approach is a clear usability win, and the implementation is clean, but the naming question could lead to a v2 iteration.
