Subject: [PATCH] fix use-after-free in get_oid_with_context_1 with sparse index
Series version: standalone patch
Originating author: Shlok Kulshreshtha
Thread type: bug report and fix

Core problem or goal
A use-after-free bug in `get_oid_with_context_1()` occurs when resolving relative paths in the `:<stage>:<path>` syntax against a sparse index. The function `resolve_relative_path()` allocates a new string for the resolved path, but the code later frees this string while still holding a pointer (`cp`) to it, leading to a use-after-free in `reject_tree_in_index()`. The bug requires three specific conditions to trigger: a relative path, a sparse directory in the index, and a leading colon followed by a digit (e.g., `:0:./dir/`).

Current status
Under review. The patch is a standalone bugfix with no prior versions. It includes a regression test in `t1092-sparse-checkout-compatibility.sh` that verifies the fix under `SANITIZE=address`. The test reliably reproduces the heap-use-after-free error and confirms the fix resolves it.

Key technical details
- **Subsystems touched**: `sha1-name.c` (core function `get_oid_with_context_1`), sparse index handling, and memory management.
- **New/renamed symbols**: None.
- **Behavior change**: The fix ensures the allocated string from `resolve_relative_path()` is freed only after its final use in `reject_tree_in_index()`, eliminating the use-after-free.
- **On-disk format**: No changes.
- **Test coverage**: New test in `t1092-sparse-checkout-compatibility.sh` exercises the bug under `SANITIZE=address`.
