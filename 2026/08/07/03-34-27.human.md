This is the third patch in Patrick Steinhardt’s six-patch series making Git’s on-disk object-database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort and is now fully approved, with only minor docstring and formatting nits left to address in the final reroll.

This patch moves the handling of ODB-related environment variables (`GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`) from `apply_repository_format()` in `setup.c` into `odb_new()` itself. The motivation is twofold: first, a later patch in the series will defer ODB creation to a second call site, and duplicating the environment-variable logic there would be awkward; second, this change aligns with a planned future series that will move alternates handling into the ODB backends themselves, making environment-variable handling a backend concern.

The refactoring is straightforward. `odb_new()` gains a new `enum odb_new_flags` parameter (`ODB_NEW_HONOR_ENV`), which tells it to read the environment variables. The call site in `apply_repository_format()` now passes the flag instead of pre-resolving the variables. The patch also removes redundant string duplication: `odb_new()` no longer needs to duplicate the alternate sources string because the caller (`apply_repository_format()`) no longer passes a pointer that might need freeing. The unit test in `t/unit-tests/u-odb-inmemory.c` is updated to pass `0` instead of empty strings.

The change is mechanical and uncontroversial. Justin Tobler and Toon Claes have both reviewed it and given their approval; the only feedback was a minor cleanup suggestion (removing redundant `xstrdup_or_null()` and `free()` calls) that Patrick addressed in v4. The patch touches four files (`odb.c`, `odb.h`, `setup.c`, and the unit test) and introduces no new behavior—it simply moves existing logic into a more self-contained location.
