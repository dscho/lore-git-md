This is the first patch in a v2 performance series reintroducing a `writev(3p)`-like wrapper to Git. The patch adds a compatibility layer for platforms that lack the `writev` system call (notably Windows), enabling later patches to use batched writes for performance gains.

The implementation defines a `git_writev()` function in `compat/writev.c` that emulates `writev` by writing only the first non-empty `iovec` entry. This design ensures the call remains non-interleaving (matching POSIX guarantees) while avoiding the complexity of handling partial writes or overflow checks. The wrapper is guarded by a `NO_WRITEV` flag and integrated into all three build systems (Makefile, CMake, and Meson). The patch also introduces a `git_iovec` struct to avoid including `<sys/uio.h>` on platforms without `writev`.

This is a refactoring and platform-compatibility patch that lays the groundwork for the performance improvements in later patches. The code is clean and well-isolated, with no behavior changes in this patch itself. The simplification of the compatibility wrapper (writing only the first `iovec`) resolves prior concerns about interleaving and integer overflow, making this version safer than the one reverted from Git 2.54. The patch is uncontroversial and appears ready for merging, assuming the series as a whole is accepted.
