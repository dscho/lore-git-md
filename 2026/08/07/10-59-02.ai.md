This is the second patch in a two-patch test fix series targeting a flaky test in `t/t7900-maintenance.sh`. The series addresses a race condition in the "maintenance.strategy" test, where the auto-detaching background maintenance logic (triggered by `test_commit()`) can interfere with foreground test processes, causing the test to fail sporadically in CI.

The fix is surgical: instead of globally disabling `GIT_TEST_MAINT_AUTO_DETACH` for the entire test script (which introduced the race), the patch restores the default behavior (auto-detach disabled) and only unsets it in the three specific tests that explicitly require it (`maintenance.auto config option`, `gc.auto config option`, and `maintenance.auto overrides gc.auto`). This isolates the auto-detach logic to where it is actually needed, eliminating the flake without altering the test's intent. The change is confined to the test file, with no impact on user-visible behavior.

The commit message is exemplary: it walks through the failure mode (missing `gc` tasks in the trace output), rules out alternative explanations (disk state, `--auto` flag), identifies the root cause (the `maintenance.lock` file from a concurrently running detached task), and explains why the chosen fix is preferable to a narrower workaround. The linked CI failure (GitLab job #15762975482) provides concrete evidence of the issue, and the patch itself is minimal and targeted.

This patch completes the series. Patch 1/2 refactored the tests to use throwaway repositories, and this patch applies the actual fix. The series is uncontroversial, well-motivated, and addresses a real CI pain point. It should be a straightforward merge once reviews confirm the approach.
