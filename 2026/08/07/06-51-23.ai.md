This is a follow-up in a bugfix thread targeting the `git push --delete --porcelain` output inconsistency. The author, Xavier Morel, now proposes a concrete implementation strategy after Junio C Hamano acknowledged the issue and invited a patch.

Xavier outlines a three-step plan to fix the problem: (1) modify `match_explicit` to create a dummy destination ref with a failure status instead of aborting when the remote ref does not exist, (2) ensure `set_ref_status_for_push` skips refs that already have a status set, and (3) adapt the reporting logic to handle the new failure case. The goal is to make the command report failures in the documented `--porcelain` format (using `!` as a prefix) rather than falling back to human-readable error messages. He also considers whether to introduce a new status code (`REF_STATUS_REJECT_NODELETE`) or extend an existing one, noting that the latter might require fewer code changes but could make the behavior less explicit.

The proposal is technically grounded, referencing specific functions (`match_explicit`, `set_ref_status_for_push`, `push_refs_with_push`) and edge cases (atomic pushes, concurrent deletions). Xavier’s approach avoids disrupting valid pushes unless `--atomic` is set, aligning with the existing behavior for pre-push rejections. The question about status codes is a minor design choice; the thread’s prior consensus on using `!` for errors suggests either option would be acceptable if it achieves the desired output format.

This is a well-scoped, low-risk bugfix with clear value for script authors. The maintainer’s earlier invitation to submit a patch signals that a clean implementation following this plan would likely be accepted. No objections or alternative approaches have been raised in the thread so far. The next step is for Xavier (or another contributor) to write the patch and add test coverage for the edge case.
