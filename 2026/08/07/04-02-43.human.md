This is a feature request from Junio C Hamano, the Git maintainer, proposing an enhancement to the interactive patch selection workflow.

Junio describes a common scenario where he uses both `git checkout -p` (to discard unwanted changes) and `git add -p` (to stage wanted changes) in the same session. Currently, these are separate commands, and there’s no easy way to move a hunk from one category to the other—e.g., if you realize during `git add -p` that a hunk should be discarded rather than staged, you can’t do so without aborting and switching to `git checkout -p`.

His workaround is to manually edit the hunk into a no-op (e.g., removing and re-adding the same line), but this is clunky and lacks a proofreading step before applying. The request is for a unified interface that would let users stage, discard, or defer hunks in a single session, likely by adding new actions to the interactive prompt.

This is a well-motivated, user-centric proposal from a highly credible source, so it’s likely to get attention. The next steps would probably involve someone drafting a patch to implement the feature, possibly by extending the existing `git add -p` machinery to include discard actions. If you use interactive staging often, this could be worth following.
