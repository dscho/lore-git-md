This is the first patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration variable that lets operators mark repositories as trusted for lazy fetching. The patch itself is a pure refactoring of the promisor-remote subsystem, extracting the lazy-fetching logic into a new `lazy_fetch_objects()` helper function.

The motivation is straightforward: the current code checks the `GIT_NO_LAZY_FETCH` environment variable once per promisor remote, which is inefficient, and the `promisor_remote_get_direct()` function mixes the logic for deciding which remotes to try with the logic for validating promisor objects. The refactoring addresses both issues by moving the lazy-fetching check into a dedicated function that runs once up front, and by separating the remote-selection logic from the object-validation logic. The patch also converts `try_promisor_remotes()` to return a `bool` instead of an `int` for clarity, and documents its return value.

The changes are confined to `promisor-remote.c` and are observably equivalent to the current behavior, with two minor shifts: the `GIT_NO_LAZY_FETCH` check now runs once instead of per remote, and `promisor_remote_init()` is no longer called when lazy fetching is disabled (which is safe because nothing downstream needs it in that case). The patch is well-motivated and cleanly executed, serving as a preparatory step for the later patches in the series.
