This is the second patch in Patrick Steinhardt’s five-patch series introducing a pluggable interface for packfile generation in Git’s object database (ODB) layer. It refactors `git upload-pack` to use the new ODB interface (`odb_generate_pack()`) instead of directly spawning `git pack-objects`, removing a hard dependency on the "files" backend.

The patch replaces the manual construction of a `child_process` for `git pack-objects` with a call to the ODB layer’s `odb_generate_pack()`, which abstracts away backend-specific details. The changes are mechanical but substantial: the function `create_pack_file()` is rewritten to populate a `struct odb_generate_pack_options` (wants, haves, shallows, filter specs, progress settings, etc.) and delegate packfile generation to the ODB. The patch also renames `write_one_shallow()` to `append_one_shallow()` to reflect its new role (appending to an `oid_array` instead of writing to a `FILE*`).

The diff shows a net reduction of ~35 lines in `upload-pack.c`, with the new code being more declarative and less error-prone. The patch preserves all existing functionality (thin packs, progress meters, shallow clones, partial clones, URI protocols) by mapping the old command-line options to the new ODB interface. No behavior changes are introduced, and the on-disk format remains unchanged.

This is a targeted refactoring that advances the series’ goal of decoupling the transport layer from the "files" backend. The patch is well-scoped and appears to be a clean adaptation of the existing logic to the new ODB interface. Reviewers will likely focus on edge cases (e.g., error handling, progress meter fidelity) and whether the new interface’s design is sufficiently flexible for future backends. The patch does not address repository maintenance or `git-pack-objects` itself, which are deferred to a future `git-objects` command.
