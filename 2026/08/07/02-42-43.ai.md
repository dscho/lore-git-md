This is a maintainer response to a feature request for `git fetch` to decouple explicit branch fetches from the default fetch refspec. Junio C Hamano acknowledges the problem described by Douglas Puchalski but suggests an alternative approach: instead of modifying the default fetch behavior, he proposes making the existing `--refmap` option more accessible via configuration.

Junio points to the `--refmap` flag as a potential solution. Currently, `--refmap` allows users to override the default refspec mapping for a single fetch operation (e.g., `git fetch --refmap="refs/heads/*:refs/remotes/origin/*" origin topic/example`). His suggestion is to extend this mechanism, possibly by introducing a configuration variable (e.g., `remote.<name>.refmap`) that would apply a custom refmap automatically for all fetches from that remote. This would preserve backward compatibility while enabling the desired workflow without requiring users to repeat the refmap on every command.

The response is brief and exploratory, with no concrete design or implementation details. Junio does not express a firm position on whether the feature is worth pursuing, but his framing ("perhaps it would make a good starting point") suggests cautious openness to the idea. The ball is now in the author's court to either propose a patch based on this suggestion or clarify why `--refmap` (even with configuration support) does not fully address the problem. Key technical details to watch in follow-up discussion include how the proposed configuration would interact with existing `remote.<name>.fetch` settings and whether it would apply globally or only to explicitly named branches.
