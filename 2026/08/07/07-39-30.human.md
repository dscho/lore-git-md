This is the **seventh patch in the v13 series** for `git history squash`, which implements the core commit-creation logic when `--no-edit` is used. The patch is part of the ongoing effort to fold a range of commits into a single commit while preserving merge topology and descendant history.

The patch focuses on **creating the squashed commit without opening an editor**, using the oldest commit’s message (or the last `amend!` targeting it) as the default. It handles `fixup!`, `squash!`, and `amend!` markers by resolving their targets during the range walk, rejecting any that would discard messages without `--edit`. The implementation preserves the authorship and parent list of the oldest commit, replays descendants using Git’s existing history rewrite machinery, and records the full revision expression in the reflog.

### Key technical details

- **Autosquash handling**: The patch enforces stricter rules for `squash!` and `amend!` commits, rejecting them unless their target is the first commit in the range or `--edit` is used. Nested fixups (e.g., `fixup! fixup! target`) are supported, and `amend!` messages are preserved when squashing into a `fixup!` commit.
- **Merge-parent preservation**: The squashed commit retains the full parent list of the original merge commit (the first commit in the range), ensuring merge topology is preserved.
- **Reflog accuracy**: The full revision expression (e.g., `squash: updating start..HEAD ^keep`) is recorded in the reflog to preserve user intent.
- **Error clarity**: Rejections for invalid autosquash targets or message discards include specific commit OIDs and clear explanations.
