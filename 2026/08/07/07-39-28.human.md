This is the fifth patch in Harald Nordgren’s v13 series implementing `git history squash`, a new subcommand that folds a range of commits into a single commit while preserving merge topology. This patch focuses on **range validation**: ensuring the selected history has exactly one boundary and one tip, rejecting root commits, multi-tip ranges, and merges with external parents.

The patch introduces `resolve_squash_range()`, a helper that walks the selected commits in topological order, marking each with `SQUASH_SEEN` and `SQUASH_TIP` flags. It enforces three key invariants: (1) every parent after the oldest commit must either be selected or a parent of the oldest commit (accepting contained merges while rejecting external merge arms), (2) the range must have exactly one tip, and (3) the range must not reach a root commit. Error messages now include specific commit OIDs for multi-tip rejection and root-commit errors, improving clarity.

The test suite (`t/t3455-history-squash.sh`) covers all validation cases: empty ranges, single-commit ranges, root commits, multi-tip ranges, and merges with external parents. The patch fully adopts Phillip Wood’s v10 review fixes, including his fixup for multi-tip rejection and his boundary-detection logic. This is a **well-crafted, uncontroversial plumbing patch** that isolates a critical safety check; it looks ready for integration. The only remaining process question is whether Harald will address Phillip’s outstanding roadmap items (e.g., the ref-filter display bug in patch 3.5), but this patch itself is complete.
