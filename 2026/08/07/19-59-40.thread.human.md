This thread is about a bugfix for a use-after-free in Git’s `get_oid_with_context_1()` function, which occurs when resolving relative paths in the `:<stage>:<path>` syntax against a sparse index. The issue, introduced in 2022, was reported and initially patched by Johannes Schindelin, but the fix was never merged. Shlok Kulshreshtha revived the effort with a v2 patch that adds proper attribution and a regression test.

The fix is minimal and targeted: it ensures the heap-allocated string from `resolve_relative_path()` is freed only after its final use in `reject_tree_in_index()`. The patch includes a new test in `t1092-sparse-checkout-compatibility.sh` that reliably reproduces the bug under `SANITIZE=address` and covers all three necessary conditions (relative path, sparse directory, and leading colon followed by a digit). René Scharfe reviewed the patch substantively, confirmed the bug’s origin, and explicitly approved the fix. Junio Hamano had previously suggested a similar approach in prior discussion.

Patrick Steinhardt recently tested the patch and confirmed it resolves the issue, though he suggested a minor stylistic improvement to the control flow (using the return value of `reject_tree_in_index()` directly). He made it clear this is non-blocking, and the patch remains functionally unchanged. With no open technical objections and all substantive feedback addressed, this fix appears ready for integration. The thread is now in its final review stage, with no remaining loose ends.
