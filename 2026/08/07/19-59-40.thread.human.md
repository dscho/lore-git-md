This thread is about a memory-safety bug in Git’s path resolution code when used with sparse indexes. Shlok Kulshreshtha posted a fix for a use-after-free in `get_oid_with_context_1()` that occurs when resolving relative paths like `:0:./dir/` against a sparse index. The bug, which dates back to 2022, was independently reported by Johannes Schindelin and requires three specific conditions to trigger: a relative path, a sparse directory in the index, and a leading colon followed by a digit.

The patch itself is straightforward: it ensures the string allocated by `resolve_relative_path()` is freed only after its final use in `reject_tree_in_index()`. A new regression test in `t1092-sparse-checkout-compatibility.sh` reliably reproduces the heap-use-after-free under `SANITIZE=address` and confirms the fix works. René Scharfe reviewed the patch and gave it an unqualified "OK," suggesting only that an `Original-patch-by` trailer be added to credit Schindelin for the original report. No objections or requests for changes have been raised, and the fix appears ready for integration.
