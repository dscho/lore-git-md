This thread is about a straightforward bugfix for a use-after-free in Git’s path resolution code when using sparse indexes. The issue, first reported by Johannes Schindelin, occurs when resolving relative paths in the `:<stage>:<path>` syntax under specific conditions: a relative path, a sparse directory in the index, and a leading colon followed by a digit (e.g., `:0:./dir/`). The fix, authored by Shlok Kulshreshtha, ensures the allocated path string is freed only after its final use, eliminating the use-after-free in `reject_tree_in_index()`.

The patch has been reviewed and approved by René Scharfe, who confirmed the bug’s origin (dating back to 2022) and suggested crediting Schindelin with an `Original-patch-by:` trailer. Shlok posted a v2 to incorporate this change, leaving the core fix and test unchanged. The regression test in `t1092-sparse-checkout-compatibility.sh` reliably reproduces the bug under address sanitization and verifies the fix. Junio Hamano’s prior suggestion for addressing this issue aligns with the approach taken here, and there are no open technical objections or loose ends.

This is a standalone bugfix with no dependencies or follow-up work, and it appears ready for integration. The only remaining step is Junio’s merge to `next` or `master`.
