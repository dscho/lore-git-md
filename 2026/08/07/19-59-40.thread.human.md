This thread is about a straightforward bugfix for a use-after-free in Git’s path resolution code when using sparse indexes. The issue, first reported in 2022, occurs when resolving relative paths in the `:<stage>:<path>` syntax—specifically when a relative path, a sparse directory, and a leading colon followed by a digit all coincide. The fix, now in its third version, ensures the heap-allocated string from `resolve_relative_path()` is freed only after its final use, eliminating the use-after-free in `reject_tree_in_index()`.

The patch is uncontroversial and ready for integration. It has been thoroughly reviewed and tested, with explicit approvals from René Scharfe and Patrick Steinhardt. The only change in this version is a minor stylistic tweak suggested by Patrick—using the return value of `reject_tree_in_index()` directly—which makes the control flow slightly cleaner without altering the fix’s behavior. The regression test in `t1092-sparse-checkout-compatibility.sh` reliably reproduces the bug under `SANITIZE=address` and confirms the fix works as intended. All feedback has been addressed, and there are no open questions or loose ends.
