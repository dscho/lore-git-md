This is a refactoring patch in the `git history squash` series, now at v13. It adds an optional `message_template` parameter to the internal `commit_tree_ext()` helper in `builtin/history.c`. When the caller supplies a template, the function uses it instead of the commit message from the passed-in commit object; when NULL, the original behavior is preserved. This plumbing change enables the default message editing feature introduced later in the series.

The patch modifies three existing callers (`commit_tree_with_edited_message`, `cmd_history_fixup`, and `split_commit`) to pass NULL, preserving their current behavior. The change is minimal and uncontroversial, touching only 16 lines in a single file. It is a prerequisite for Patch 8/8, which implements the default message editing feature by constructing an autosquash-style template.

This is a well-crafted, low-risk refactoring that cleanly separates the message-seeding logic from the commit-creation plumbing. It does not alter behavior on its own but provides the necessary hook for the later patch to customize commit messages. The patch is ready for integration and should not require further review.
