This is the final patch in Patrick Steinhardt’s six-part series making on-disk object-database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort and is now fully approved, with only two minor documentation and formatting nits addressed in this v5 reroll.

The patch implements the `create_on_disk` callback in the "files" backend, replacing hard-coded directory creation in `setup.c` with backend-specific logic. The top-level `objects/` directory remains hard-coded (it is required for repository discovery), but the creation of `objects/pack/` and `objects/info/` is now delegated to the backend via `safe_create_dir()` calls in `odb_source_files_create_on_disk()`. The callback is invoked in `create_object_database()` after ODB initialization, and the function now dies with a translatable error message if the callback fails.

The change is mechanical and well-motivated: it completes the architectural shift begun in earlier patches, enabling future ODB backends to implement custom on-disk layouts without modifying core setup code. The patch touches only three files (`odb/source-files.c`, `odb/source.h`, and `setup.c`) and introduces no new user-visible behavior. All substantive review feedback has been addressed, and the series is ready for merging to `next`.
