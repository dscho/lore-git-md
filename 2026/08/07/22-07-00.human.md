This is a bugfix patch in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder. It is the fifth of ten patches in v5, which is now feature-complete and merge-ready.

The patch addresses a latent robustness issue in the remote-object-info subsystem: `fetch_object_info()` previously returned `-1` on a short read (fewer attribute lines than requested OIDs), but this error code was propagated up through two layers (`fetch_object_info_via_pack()` and `get_remote_info()`) before being converted to a generic `die()` in `cat-file`. The fix moves the `die()` into `fetch_object_info()` itself, making the error handling consistent with the rest of the function’s error paths and eliminating the need for callers to check the return value. The function signature is updated to `void`, and the call site in `transport.c` is simplified accordingly.

The change is purely mechanical (19 insertions, 23 deletions) and touches only three files: `fetch-object-info.c`, `fetch-object-info.h`, and `transport.c`. It introduces no new behavior or symbols, and the commit message clearly explains the rationale. This patch is uncontroversial and aligns with Git’s defensive programming practices. Junio has already endorsed the earlier patches in the series as ready to merge, and this one follows the same pattern.
