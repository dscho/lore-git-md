This is the second patch in the v2 series optimizing `git last-modified` by reusing Bloom filters. It refactors the internal Bloom filter helper to expose a cleaner public API for other built-ins to reuse.

The patch extracts the core filter-consulting logic from `check_maybe_different_in_bloom_filter()` into a new public function `revs_maybe_changed_in_bloom()` declared in `revision.h`. The new function takes an already-looked-up `struct bloom_filter` and returns a boolean (`false` if the commit definitely did not change any paths, `true` if it might have), while the original function remains as a thin wrapper that handles Bloom filter lookup and tristate return values for statistics tracking. This design avoids redundant Bloom filter lookups for callers like `git last-modified` that already have the filter in hand, and aligns the public API with the needs of the new caller rather than the internal statistics machinery.

The change is mechanical and well-motivated: the commit message clearly explains the redundancy being eliminated and the rationale for the boolean return type. The diff is clean, with no behavior change—only a refactoring that centralizes the filter-checking logic. This patch directly enables the performance gains in later patches by letting `git last-modified` reuse the same filtering logic as `git log` without paying the cost of a second filter lookup. The new function is properly documented in the header, and the original function’s semantics are preserved.
