This is the first patch in Junio C Hamano’s three-part bugfix series for `git diff` bash completion. It is a pure refactoring with no behavior change, preparing the ground for the next two patches.

The patch rearranges the control flow in `_git_diff()` so that the early return on `--` (double-dash) is removed. Instead, the existing option-parsing logic is wrapped in an `if ! __git_has_doubledash` block. This keeps the current behavior—letting Bash fall back to file-name completion when `--` is present—but makes it easier to add new logic that runs after the option-parsing block in the next patches. The diff touches only `contrib/completion/git-completion.bash` and is purely mechanical: no new helpers, no new test cases, and no change in what the user sees.
