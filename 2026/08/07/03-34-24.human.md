This is the fifth iteration of Patrick Steinhardt’s six-patch series making the creation of on-disk object database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort and is now fully approved, with only two minor documentation and formatting nits remaining before it can be merged.

The goal is to decouple the creation of backend-specific directories (like `objects/info` and `objects/pack`) from the generic repository setup code. The top-level `objects/` directory remains mandatory for repository recognition, but individual backends now handle their own subdirectory creation via a new `create_on_disk` callback in the ODB source interface. This enables future ODB backends to implement custom on-disk layouts without modifying core setup logic.

The series starts with a correctness fix: when iterating through multiple ODB sources (e.g., the main repository and its alternates), Git previously loaded the loose-object map from the common `objects/` directory instead of the path specific to each source. This caused alternates’ loose-object maps to be silently ignored, breaking repositories that rely on compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility). The fix is now well-tested, with a dedicated regression test in `t/t1016-compatObjectFormat.sh`.

The remaining patches detangle loose object map loading from repository setup, move environment variable handling into `odb_new()`, defer ODB creation until after the backend is known, and introduce the `create_on_disk` callback. The fourth patch was revised in this version to abandon the `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag in favor of explicit `odb_new()` calls at every call site, addressing feedback from Toon Claes. The final patch implements the callback in the "files" backend, completing the series.

Files touched include `odb.c`, `odb.h`, `setup.c`, `repository.c`, `loose.c`, and several ODB source files. The changes are mechanical but foundational, introducing new functions like `odb_source_type_to_name()` and `safe_create_dir()`, while removing hardcoded assumptions about directory layouts. The series is based on the recent "7th batch" integration (commit `9a0c4701dc`) and is ready for merging once the two minor issues (a stale comment and a leftover formatting change) are addressed.

This is infrastructure work with no immediate user-visible impact, but it’s a prerequisite for any future ODB backend that doesn’t follow the traditional loose/pack layout. The first patch is already listed in Junio’s "What's cooking" report as "will merge to 'next'", and the rest of the series is uncontroversial and ready to follow.
