This is a three-patch series from D. Ben Knoble that converts Git’s `USE_NSEC` build-time define into a runtime configuration option, `core.useNanosec`. The goal is to reduce “racy Git” problems on filesystems that support nanosecond timestamps by making the feature available without requiring a custom build.

The series is built on `master` (2c78326f81) and is currently cooking in `seen` under the topic `dk/use-nsec-runtime`. The first patch is a minor Meson build documentation fix that surfaced while working on the main change. The second patch reorganizes `repo_config_values_init` to prepare for the new config key. The third patch does the actual conversion, removing the `USE_NSEC` define from the build system and introducing `core.useNanosec` as a runtime toggle.

The commit message is clear about the motivation: build-time configuration is too early for distributing Git, so exposing this as a runtime option makes the feature more widely usable. The author also flags a small textual and semantic conflict with `ty/repo-config-cleanups` in `seen`, which removes comments from `struct repo_config_values` that this series adds to. They also raise a naming concern—whether `useNanosec` is too specific, since the feature is really about *extended precision* in the index, not strictly nanoseconds.

No tests have been updated yet, and the author is seeking advice on how to test this change, especially since it won’t be equally valid on all systems. The series looks well-structured and addresses a real usability issue, though the naming question and test coverage are open points that may draw discussion.
