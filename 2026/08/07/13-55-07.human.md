This is the first patch in Christian Couder’s five-part series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration to control lazy fetching. The patch is a pure refactoring of the promisor-remote subsystem, extracting the lazy-fetch logic into a new `lazy_fetch_objects()` helper function.

The motivation is twofold: first, the current code checks the `GIT_NO_LAZY_FETCH` environment variable once per promisor remote, which is inefficient; second, the logic for deciding which remotes to try is tangled with the logic for checking whether objects are promisor objects. The refactoring moves the environment variable check to a single up-front call and separates the remote-selection logic from the object-checking logic. The patch also converts `try_promisor_remotes()` to return a `bool` instead of an `int` for clarity, since it only indicates whether all objects were fetched.

No behavior change is intended, and the patch is careful to preserve existing semantics: `promisor_remote_init()` is no longer called when lazy fetching is disabled, but this is safe because nothing downstream (like `is_promisor_object()`) needs it in that case. The diff is clean and focused, touching only `promisor-remote.c` and adding clear documentation for the new helper.

This patch is a prerequisite for the rest of the series, which builds on the refactored code to introduce the new `uploadpack.lazyFetchTrusted` configuration. It looks well-crafted and uncontroversial, serving as a solid foundation for the feature work to come.
