This is a **substantive follow-up in the already-merged `git diff` bash-completion series**, specifically about a latent API design issue in the completion script. Elijah Newren identifies that `__git_complete_index_file()` is documented as requiring one argument, but the merged patch (v4 2/3) invokes it with none. While the call chain (`__git_complete_index_file` → `__git_index_files` → `__git_ls_files_helper`) currently tolerates an empty argument due to unquoted parameter expansion, this is accidental and could break in the future. Both Junio and Elijah agree this should be fixed defensively: Junio plans to pass an explicit empty string (`""`) in a follow-up reroll to clarify intent and future-proof the code. The discussion also surfaces a broader API design oddity: `__git_complete_index_file` expects a single argument, forcing callers to concatenate multiple options (e.g., `"--cached --others --directory"`), which would be more intuitive as separate parameters. This observation is noted but not acted upon; no immediate refactoring is proposed. The exchange is purely technical and does not affect the series' integration status (already merged to `master`), but it closes the loop on Elijah’s feedback and confirms the issue will be addressed.
