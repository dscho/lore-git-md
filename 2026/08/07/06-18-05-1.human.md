This is the third patch in Patrick Steinhardt’s v2 series reintroducing a `writev(3p)`-like wrapper for performance. It addresses a platform-specific nuance: systems like NonStop define a small `MAX_IO_SIZE` that limits how many bytes can be written in a single `writev(2)` call, causing EINVAL if exceeded. The patch introduces `xwritev()`, a new wrapper that mirrors `xwrite()`’s handling of `MAX_IO_SIZE` by breaking large requests into chunks that fit the limit, ensuring callers see a short write rather than an error. The wrapper also handles EINTR and EAGAIN retries, just like `xwrite()`.

The change is confined to `wrapper.c` and `wrapper.h`, adding 43 lines to implement `xwritev()` and updating `writev_in_full()` to use it. The logic is straightforward: if the first `iovec` entry exceeds `MAX_IO_SIZE`, it punts to `xwrite()`; otherwise, it passes only the leading entries that fit the limit to `writev(2)`. This ensures compatibility with platforms that enforce small write limits while maintaining the expected behavior for callers.

The patch is well-motivated and directly responds to a reported issue from Randall Becker (NonStop port maintainer). It incorporates feedback from Jeff King and Junio C Hamano, and the commit message clearly explains the design choices. The absence of test coverage is notable but unsurprising given the low-level nature of the change; the existing `xwrite()` tests likely provide indirect coverage. This is a clean, targeted fix that resolves a real portability concern without introducing new complexity. The series as a whole looks technically sound and ready for merging, pending Junio’s final assessment of whether the performance gains justify the added code.
