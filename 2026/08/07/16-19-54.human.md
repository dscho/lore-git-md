This is the first patch in Junio C Hamano’s v5 cleanup series for the recently merged bash completion bugfix. The series addresses two post-merge technical nits in the `git diff` completion logic, and this patch is a no-op refactoring that prepares the ground for the next one.

The change reorganizes the control flow in `_git_diff()` to avoid an early return when `--` is detected on the command line. Previously, the function would punt immediately in that case, letting Bash fall back to its default file completion. Now, the code simply falls through to the end of the function instead. The behavior remains identical—this is purely a structural change to make the next patch (which will adjust what happens when we "punt") easier to implement.

The diff shows the entire `_git_diff()` function being rewritten with the same logic but now wrapped in an `if ! __git_has_doubledash` block. The indentation and line breaks are adjusted for readability, but no functional changes are introduced. This patch is cosmetic and preparatory, setting the stage for the API compliance fix in patch 2/3. Since v4 of this series is already in `master`, this v5 iteration is a cleanup pass with no risk of regression.
