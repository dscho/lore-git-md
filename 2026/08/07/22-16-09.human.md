This is a security-focused review of Tim Wiederhake’s patch adding user-configurable custom commands to `gitk`. Junio C Hamano raises a critical concern: the current implementation does not properly escape shell metacharacters in commit metadata (title, message, author, etc.) when substituting placeholders like `%t` or `%m` into commands. This creates a command injection vulnerability—an attacker could craft a commit with a title containing `'; rm -rf /; echo '` and trick a user into executing arbitrary code simply by right-clicking the commit in `gitk`.

The patch touches only the Tcl/Tk frontend (`gitk` script) and does not affect Git’s core C code, but the security implications are serious. Junio’s example shows how a seemingly innocuous template like `echo '%t'` could become `echo 'title?'; echo no''` if the title contains single quotes, demonstrating the injection risk. He explicitly questions whether Tcl’s `{exec sh -c $cmd}` provides any built-in escaping or if the patch needs to handle it manually.

This is a **substantive review**—it identifies a real, high-impact flaw in the design. The author will need to address this before the patch can proceed, likely by implementing proper shell escaping for all substituted values. Until then, the feature remains blocked on both process (AI assistance disclosure) and technical (security) grounds. The thread’s focus has now shifted from motivation to correctness.
