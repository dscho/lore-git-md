This is the fourth patch in the v13 series implementing `git history squash`, a new subcommand that folds a commit range into a single commit. This patch establishes the **revision input contract** for the command: it adds the subcommand entry point, parses options, and sets up the `rev_info` struct to accept revision ranges and `rev-list` options while enforcing the ordering and simplification invariants required for the squash operation.

The patch defines the CLI interface (`git history squash [--dry-run] [--update-refs=(branches|head)] [--[no-]edit] <revision-range>`) and implements `setup_squash_revisions()`, which configures the revision walk to traverse the range in reverse topological order with ancestry-path filtering. It explicitly rejects ranges that lack a bottom commit (e.g., `HEAD` alone) because the squashed commit needs a parent outside the selected range. If the user supplies `rev-list` options that would alter the walk (e.g., `--boundary`), the command issues a warning and resets them to the required values.

This is a **pure plumbing patch** with no user-visible behavior beyond error messages. It lays the foundation for the range validation, ref protection, and commit-creation logic that follow in patches 5–8. The commit message is clear and the code is well-structured, reflecting the series’ overall focus on incremental review. The patch is uncontroversial and ready for integration.
