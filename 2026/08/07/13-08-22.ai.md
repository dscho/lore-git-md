This is a review reply in the ongoing `git fetch` refspec-mapping feature discussion. Phillip Wood endorses the general goal—decoupling explicit branch fetches from the default fetch refspec—and suggests extending the idea to the push side as well. He proposes a new configuration variable (e.g., `remote.<remote>.fetchMap`) that would act purely as a mapping layer, leaving the default fetch/push sets untouched. The comment also notes a long-standing quirk in Git’s refspec matching: the first matching refspec wins, not the longest, which complicates adding branch-specific mappings via `git config`. No implementation details or patches are provided; this remains a conceptual sketch.
