This is patch 6/10 in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder. The patch is a targeted refactoring by Jeff King (Peff) that removes the `object_info_oids` and `object_info_results` fields from `git_transport_options` and instead passes them as explicit parameters to `transport_fetch_object_info()` and its vtable implementations.

The change addresses a latent design issue: the current implementation stores pointers to the OID array and results struct in the transport struct, but these are only valid for a single request. This creates a subtle risk—if the transport were reused, the struct could retain dangling pointers to stack variables from the previous call. The refactoring makes ownership clearer: the caller retains responsibility for the OID array and results, and the transport no longer needs to manage their lifetimes. The OID array is also marked as `const` to emphasize its input-only role.

The patch is mechanical (25 insertions, 19 deletions) and touches seven files: `transport.c`, `transport-helper.c`, `builtin/cat-file.c`, `fetch-object-info.c`, `fetch-object-info.h`, `transport-internal.h`, and `transport.h`. It updates function signatures and call sites to reflect the new parameter list but does not alter behavior. The change prepares the codebase for future enhancements, such as reusing transport connections for multiple object-info requests, and reduces technical debt by eliminating a misleading abstraction.

Peff’s original patch is signed-off and tested; Pablo has integrated it into the series with only minor commit message typo fixes. The patch is uncontroversial and explicitly endorsed by Junio in the thread context as ready to merge. No open questions or technical concerns remain. This refactoring is part of the broader effort to cleanly extend the remote-object-info protocol to support object type metadata, which is the final piece of metadata guaranteed to be identical on client and server after a fetch.
