This is a **substantive review** of the Bash completion patch for `git history`. Patrick Steinhardt identifies a maintainability issue in the `__git_history_has_revision` helper function: it hardcodes the list of options that take arguments (e.g., `--empty`, `--update-refs`), requiring manual updates whenever new such options are added. He suggests simplifying the logic by always completing references unless a `--` has been seen, which can be checked via the existing `__git_hash_doubledash` helper. This would reduce complexity at the cost of occasionally offering irrelevant completions (e.g., suggesting revisions when an option argument is expected). The trade-off is framed as acceptable for now, with the possibility of refining the logic later if needed.

The review is narrowly scoped to the helper function’s design and does not question the overall approach or correctness of the patch. It advances the discussion by proposing a concrete, lower-maintenance alternative that aligns with existing completion infrastructure. Key technical details for follow-up: the `__git_history_has_revision` function, the use of `__git_hash_doubledash`, and the balance between precision and maintainability in completion logic. The patch remains uncontroversial, but this feedback may prompt a v3 iteration.
