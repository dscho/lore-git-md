This is the v5 cover letter for Pablo Sabater’s GSoC feature series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now ten patches, up from nine in v4, due to the inclusion of Jeff King’s (Peff) refactoring patch that removes the remote object-info fields from the transport struct and passes them as explicit function parameters.

The series remains feature-complete and merge-ready, with all prior review feedback addressed. The new patch (6/10) by Peff is a targeted refactoring that clarifies ownership semantics in the transport layer: it removes the `object_info_oids` and `object_info_results` fields from `git_transport_options` and instead passes them as explicit parameters to `transport_fetch_object_info()` and its vtable implementations. This eliminates a latent bug (dangling pointers if the transport were reused) and prepares the codebase for future enhancements like connection reuse. The change is mechanical (25 insertions, 19 deletions) and touches seven files, primarily `transport.c`, `transport-helper.c`, and `builtin/cat-file.c`. Pablo has integrated this patch with only minor commit message typo fixes, and it is uncontroversial.

The remaining patches are unchanged in substance from v4, though patch 5/10 (formerly 5/9) now preserves the `const` qualifiers on the parameters of `fetch_object_info()`, matching the original function signature. The series continues to focus narrowly on object type support, with the preparatory patches (1-6/10) refactoring the object-info handling to use a dedicated `struct fetch_object_info_results` and dynamically request all supported options. Patches 7-10/10 complete the end-to-end implementation: the server parses and transmits type data (patch 7/10), the client parses it (patch 8/10), the server advertises the "type" capability (patch 9/10), and the final patch (10/10) unifies the default format string for all `cat-file` batch commands.

Key files touched include `fetch-object-info.c`, `protocol-caps.c`, `serve.c`, `transport.c`, and the man pages for `git-cat-file` and Git protocol v2. The test suite (`t1017` and `t5701`) is updated to cover the new functionality, including verification of the `%(objecttype)` placeholder and protocol robustness checks. The series is based directly on the recently merged "cat-file: add remote-object-info to batch-command" work (Eric Sunshine’s v21 series) and has no external dependencies.

The motivation remains clear: object type is the last piece of metadata guaranteed to be identical on client and server after a fetch, making it a natural candidate for remote-object-info. The commit messages explicitly rule out other metadata (disk size, delta base, object mode) as unreliable or context-dependent, so the scope is intentionally narrow. The implementation follows the established pattern from the predecessor series and is well-tested, with CI passing on GitHub. All prior review feedback—including Junio’s protocol robustness concerns, Peff’s design refinements, and Karthik Nayak’s commit message clarifications—has been addressed. The series is now effectively complete, with no open technical concerns.
