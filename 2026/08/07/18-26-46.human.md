This is a performance optimization for the experimental `git last-modified` command, now in its second iteration (v2). The series makes `git last-modified` nearly as fast as `git log` when querying the last commit that modified files matching a pathspec, including wildcards like `*.c`. The v2 reroll addresses all the technical feedback from the first round: it refactors the public API to use a boolean return for clarity, restores the original Bloom-filter statistics behavior, fixes a correctness bug with `--show-trees`, and adds two new helper functions to handle parent-directory checks.

The benchmarks in the cover letter show a 3.7× speedup without `--show-trees` (from 60.7 ms to 16.2 ms) and a 1.95× speedup with `--show-trees` (from 61.9 ms to 31.8 ms) on the ziglang/zig repository. The series touches `revision.c`, `revision.h`, `bloom.c`, `bloom.h`, `builtin/last-modified.c`, and adds a new test in `t/t8020-last-modified.sh`.
