This is a substantive review in the `git-replay`/`git-history` notes-loss thread. Elijah Newren adds `git filter-repo` (and by extension `git fast-export`/`fast-import`) to the list of commands that silently drop notes during history rewriting. He explains that the root cause in this case is architectural: notes are stored as ordinary commits, so any filtering operation that touches the underlying commit graph will detach or discard the notes unless they are explicitly handled as a special case. While this behavior is consistent with the design of `filter-repo`, it reinforces the broader pattern that notes are often an afterthought in history-rewriting tools. The comment does not propose a solution or take a position on whether the current behavior is correct, but it provides useful context for anyone considering how to implement note-preserving logic in `git-replay` or `git-history`.
