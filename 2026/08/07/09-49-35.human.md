This is a brief follow-up in the ongoing thread about Git commands silently dropping notes during history rewriting. The author, erik88, points to a GitHub issue comment in the `git-filter-repo` repository that describes workarounds for preserving notes when using `git filter-repo`. The comment acknowledges Elijah Newren’s explanation that `filter-repo` (and by extension `fast-export`/`fast-import`) drops notes because they are stored as ordinary commits, making them vulnerable to filtering operations. While erik88 does not propose a solution or argue for a specific design direction, the link provides practical context for anyone looking to mitigate the issue in the short term. The workarounds appear to be user-level scripts or manual steps rather than built-in functionality, reinforcing the thread’s broader observation that notes are often an afterthought in history-rewriting tools. This contribution is useful but does not advance the core design discussion about whether `git replay` and `git history` should handle notes automatically or via a command-line option.
