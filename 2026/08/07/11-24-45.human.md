This is a **feature discussion** about improving Git’s interactive patch selection workflow, specifically the `git add -p`/`git checkout -p` experience.

D. Ben Knoble chimes in with a practical perspective from the Vim ecosystem, highlighting how Fugitive (a popular Vim plugin for Git) handles the same problem. Fugitive’s interface, inspired by Magit (the Emacs Git interface), lets users browse all hunks in a working tree and apply actions like stage, unstage, or revert with a few keystrokes. The workflow is more fluid than Git’s current prompt-loop: users can toggle between views (e.g., unstaged vs. staged changes), operate on hunks or line ranges, and even undo reverts—all without leaving the editor. Knoble suggests this kind of TUI (text-based user interface) could serve as inspiration for a built-in Git solution, though he acknowledges it might be heavier than the current lightweight approach.

The email doesn’t propose a concrete implementation or patch, but it adds a real-world example of how other tools solve the same friction. Fugitive’s design demonstrates that a unified, interactive session for staging, discarding, and deferring hunks is both feasible and user-friendly. This could inform the ongoing discussion about whether Git should extend `add -p`, introduce a new command (e.g., `git triage -p`), or adopt a more editor-integrated approach. The thread remains in the design phase, but Knoble’s input provides a tangible reference point for what a polished solution might look like.
