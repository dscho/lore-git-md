This is the final patch in Pablo Sabater’s ten-patch GSoC series, completing the feature by unifying the default format for `git cat-file --batch-command`’s `remote-object-info` and local `info` commands. The patch removes the temporary workaround that used a different default format (`%(objectname) %(objectsize)`) for remote queries, switching them to the standard default (`%(objectname) %(objecttype) %(objectsize)`) now that `%(objecttype)` is fully supported. Documentation is updated to reflect the new functionality, and tests are adjusted to expect the unified format across all transport protocols (git://, file://, http://).

The change is mechanical and uncontroversial: it touches only four files (`Documentation/git-cat-file.adoc`, `Documentation/gitprotocol-v2.adoc`, `builtin/cat-file.c`, and `t/t1017-cat-file-remote-object-info.sh`), removing the conditional format logic in `parse_cmd_remote_object_info()` and updating the protocol documentation to list "type" as a supported attribute. The test suite is updated to expect the full default format (including object type) for all queries, ensuring consistent output regardless of transport or whether the query is local or remote. The patch also removes the warning in the man page that cautioned users not to rely on the temporary default format, as the format is now stable.

This patch is the culmination of the series, which has been feature-complete and merge-ready since v5. All prior review feedback—including architectural design refinements, protocol robustness fixes, and commit message clarifications—has been addressed, and the series has been explicitly endorsed by Junio as ready for integration. The files touched are limited to documentation, the `cat-file` builtin, and the test suite; no core object storage or transport logic is modified. The patch ensures backward compatibility by maintaining the same default format for all queries, and the updated tests validate that mixing `info` and `remote-object-info` commands produces identical results.
