Subject: [PATCH 0/5] odb: make packfile generation pluggable
Series version: v3 (six patches, third public iteration)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Decouple Git’s transport layer (fetch, push, bundle) from the "files" ODB backend by introducing a pluggable interface for packfile generation. This is a step in Patrick Steinhardt’s larger ODB abstraction effort, which aims to support alternative backends beyond loose objects and packfiles. The series does not yet address repository maintenance or the `git-pack-objects` command, deferring those to a future `git-objects` command.

Current status
The series is now in its third iteration, posted as [PATCH v3 0/6] (six patches). It remains queued in `seen` and under active review. The v3 iteration addresses two key issues from prior reviews: a use-after-scope bug in the files-backend implementation (identified by Elijah Newren) and Junio C Hamano’s objection to lingering `the_repository` usage. The bug fix moves the `child_process` struct from the stack to the heap in `odb_source_files_generate_pack()`, eliminating the risk of stale pointer dereferencing during abnormal exits. The `the_repository` issue is now fully resolved: patch 5/6 refactored `bundle.c` to eliminate most `the_repository` references, replacing them with an explicit `struct repository *` parameter, and patch 6/6 completes the ODB migration for `git bundle` without introducing new `the_repository` dependencies. The only remaining dependency was `get_log_output_encoding()`, which still implicitly used `the_repository`; Patrick Steinhardt addressed this in patch 5/6 with an `extern` declaration as a workaround, sidestepping the compile-time guard (`USE_THE_REPOSITORY_VARIABLE`). Junio C Hamano objected to this workaround in prior review, arguing it undermines the guard’s purpose, but no further resolution has been reached. Patch 3/6 migrated `git send-pack` to the ODB interface, completing the transport-layer refactoring for push operations alongside the prior `upload-pack.c` migration (patch 2/6). Patch 4/6 refactored `git bundle`’s progress-meter option handling, consolidating four related options (`--quiet`, `--progress`, `--all-progress`, and `--all-progress-implied`) into a single boolean `progress` flag. The `--all-progress-implied` option is retained as a no-op for backward compatibility, and `--all-progress` is kept as a hidden alias for `--progress`. No prior versions have been merged to `next` or `master`.

Key technical details
- New ODB interface: `odb_generate_pack()` and its files-backend implementation, which delegates to the existing `git pack-objects` command.
- New structures: `struct odb_generate_pack_options` (encapsulates wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies, and file descriptors for pack and progress output) and `struct odb_pack_generator` (asynchronous operation handle with file descriptors for the generated pack and progress output, plus a finish callback).
- New/renamed symbols: `odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`, `append_one_shallow()` (renamed from `write_one_shallow()`), `append_negative_object()` (new helper in `send-pack.c`), `write_pack_data()` (updated in `builtin/bundle.c` to use the ODB interface).
- Files touched: `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source.h` (core ODB layer, patch 1/6); `upload-pack.c` (patch 2/6); `send-pack.c` (patch 3/6); `builtin/bundle.c` (patch 4/6, consolidating progress-meter option handling); `bundle.c`, `bundle.h` (patches 5/6 and 6/6, completing the ODB migration and `the_repository` removal).
- Behavior: transport commands delegate packfile generation to the ODB layer, reducing backend-specific code. The interface is designed for asynchronous operation, returning file descriptors for pack and progress output. The refactoring in `upload-pack.c` (patch 2/6) and `send-pack.c` (patch 3/6) replaces manual `child_process` construction with a declarative `odb_generate_pack_options` setup, preserving all existing functionality (thin packs, progress meters, shallow clones, partial clones, URI protocols, bitmap usage). The files-backend implementation (`odb_source_files_generate_pack()`) translates ODB options into `git pack-objects` command-line arguments (e.g., `--thin`, `--shallow`, `--filter`, `--uri-protocol`). It handles shallow boundaries by neutralizing the repository’s shallow state when caller-provided shallows are present, and it supports asynchronous operation by returning file descriptors for the pack and progress output when the caller requests pipes. Error handling includes proper cleanup of descriptors and reporting of pack-objects failures (except SIGPIPE, which is treated as a normal occurrence). Patch 2/6 refactored `upload-pack.c` to use the ODB interface, replacing 35 lines of backend-specific code with a single call to `odb_generate_pack()` and a loop to relay the generated pack data. Patch 3/6 applies the same pattern to `send-pack.c`, replacing 63 lines of backend-specific code with a declarative setup while preserving all existing functionality (thin packs, delta policies, shallow clones, progress meters, stateless-RPC handling). The patch introduces `append_negative_object()` (renamed from prior `feed_object()` logic) to append boundary objects to the ODB’s `haves` array, and the poll loop now reads from the ODB generator’s file descriptors (`generator->out` and `generator->err`) instead of a child process’s pipes. Patch 4/6 refactors `git bundle`’s progress-meter option handling, replacing `OPT_PASSTHRU_ARGV` macros with `OPT_BIT`, `OPT_NEGBIT`, and `OPT_NOOP_NOARG` to manage a boolean `progress` flag directly. The logic for determining whether to show progress (defaulting to `isatty(STDERR_FILENO)`) is preserved, and the resulting boolean is used to push either `--progress` or `--quiet` into the `pack_opts` strvec. Patch 5/6 refactors `bundle.c` to eliminate most `the_repository` references, replacing them with an explicit `struct repository *` parameter passed through the call stack. Functions like `is_tag_in_date_range()` and `write_bundle_refs()` now take a `struct repository *` parameter, and all downstream calls are updated accordingly. The patch also replaces hard-coded `the_hash_algo` references with the repository’s `hash_algo` field, ensuring hash algorithm agnosticism. The only remaining dependency was `get_log_output_encoding()`, addressed with an `extern` declaration. Patch 6/6 migrates `git bundle` to the ODB interface, replacing the direct `git pack-objects` invocation in `write_pack_data()` with a declarative setup using `struct odb_generate_pack_options`. The new code preserves all existing functionality: thin packs, delta base offsets, and filter specs for partial clones. The function is simplified from 45 lines to 37, eliminating manual `child_process` construction and replacing it with a single call to `odb_generate_pack()` followed by a loop to relay the generated pack data. The patch removes the last vestige of the `pack_opts` strvec from `builtin/bundle.c`, consolidating progress-meter handling into the boolean `progress` flag introduced in patch 4/6. The `create_bundle()` function signature is updated to accept `progress` directly, and the call in `cmd_bundle_create()` now passes the flag without intermediate string manipulation.
- On-disk format: unchanged.
- Test coverage: patches 2/6 and 3/6 adjust `t5516-fetch-push.sh` to account for benign argument-order changes and the replacement of `-q` with `--quiet`; deeper verification of edge cases (e.g., shallow clones, partial clones, protocol v2 interactions, error handling during pack generation) remains pending.

- Potential performance or edge-case regressions in transport operations (e.g., progress meter fidelity, option handling in `upload-pack.c` and `send-pack.c`).
- Test coverage and verification of edge cases (e.g., error handling during pack generation, shallow clone interactions, partial clone filter specs).

Patrick Steinhardt acknowledged the trade-off and expressed openness to revising the approach, but no resolution has been reached.
