Subject: [PATCH 0/5] odb: make packfile generation pluggable

Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Decouple Git’s transport layer (fetch, push, bundle) from the "files" ODB backend by introducing a pluggable interface for packfile generation. This is a step in Patrick Steinhardt’s larger ODB abstraction effort, which aims to support alternative backends beyond loose objects and packfiles. The series does not yet address repository maintenance or the `git-pack-objects` command, deferring those to a future `git-objects` command.

Current status
The series is now in its second iteration, posted as [PATCH v2 0/6] (six patches, with the original fifth patch split into three in v2). It is queued in `seen` after Junio C Hamano administratively resolved the merge conflict with the `--no-ref-delta` topic by removing the latter from `seen` and queuing the ODB series in its place. The series remains under active review, with no prior versions merged to `next` or `master`. The next steps will focus on testing edge cases (e.g., shallow clones, partial clones, error handling during pack generation) and addressing any performance or fidelity regressions in transport operations. With the arrival of patch 6/6, the series has now completed its stated goal: all pack streams leaving the repository (fetch, push, bundle) delegate generation to the ODB layer.

Key technical details
- New ODB interface: `odb_generate_pack()` and its files-backend implementation, which delegates to the existing `git pack-objects` command.
- New structures: `struct odb_generate_pack_options` (encapsulates wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies, and file descriptors for pack and progress output) and `struct odb_pack_generator` (asynchronous operation handle with file descriptors for the generated pack and progress output, plus a finish callback).
- New/renamed symbols: `odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`, `append_one_shallow()` (renamed from `write_one_shallow()`), `append_negative_object()` (new helper in `send-pack.c`), `write_pack_data()` (updated in `builtin/bundle.c` to use the ODB interface).
- Files touched: `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source.h` (core ODB layer); `upload-pack.c` (patch 2/6); `send-pack.c` (patch 3/6); `bundle.c`, `builtin/bundle.c`, `bundle.h` (patches 4/6, 5/6, and 6/6).
- Behavior: transport commands delegate packfile generation to the ODB layer, reducing backend-specific code. The interface is designed for asynchronous operation, returning file descriptors for pack and progress output. The refactoring in `upload-pack.c` (patch 2/6) and `send-pack.c` (patch 3/6) replaces manual `child_process` construction with a declarative `odb_generate_pack_options` setup, preserving all existing functionality (thin packs, progress meters, shallow clones, partial clones, URI protocols, bitmap usage). Patch 2/6 migrates `git upload-pack` to the ODB interface, eliminating manual `child_process` setup for `git pack-objects` and replacing it with a declarative `struct odb_generate_pack_options` populated with the same settings (wants, haves, shallows, filter specs, URI protocols, progress flags, delta policies). The ODB layer’s files-backend implementation translates these options into the equivalent `git pack-objects` command-line arguments. Patch 3/6 migrates `git send-pack` to the ODB interface, preserving all existing functionality (thin packs, shallow boundaries, stateless RPCs) while delegating pack generation to the ODB layer. The new `append_negative_object()` helper ensures only valid boundary objects are passed to the ODB. The files-backend implementation (`odb_source_files_generate_pack()`) constructs a `child_process` for `git pack-objects`, translating ODB options into command-line arguments (e.g., `--thin`, `--shallow`, `--filter`, `--uri-protocol`). It handles shallow boundaries by neutralizing the repository’s shallow state when caller-provided shallows are present, and it supports asynchronous operation by returning file descriptors for the pack and progress output when the caller requests pipes. Error handling includes proper cleanup of descriptors and reporting of pack-objects failures (except SIGPIPE, which is treated as a normal occurrence). Patches 4/6, 5/6, and 6/6 migrate `git bundle` to the ODB interface: patch 4/6 refactors progress-meter option handling to replace four overlapping command-line options (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`) with a single boolean `progress` flag, preserving default behavior (progress shown if stderr is a TTY, `--all-progress-implied` still passed to `git pack-objects`); patch 5/6 refactors `bundle.c` to eliminate most `the_repository` references, replacing them with explicit `struct repository *` parameters; patch 6/6 migrates `git bundle` to the ODB interface, completing the transport-layer refactoring. The remaining `the_repository` dependency in `get_log_output_encoding()` is left as an `extern` to minimize churn.
- On-disk format: unchanged.
- Test coverage: patch 2/6 adjusts `t5516-fetch-push.sh` to account for benign argument-order changes and the replacement of `-q` with `--quiet`; patch 3/6 makes similar adjustments for `send-pack`. Deeper verification of edge cases (e.g., shallow clones, partial clones, protocol v2 interactions, error handling during pack generation) remains pending.

Open questions and loose ends
- Long-term plan for `git-pack-objects` and repository maintenance (deferred to future `git-objects` command).
- Whether the new interface will need to evolve once `git-objects` is introduced.
- Potential performance or edge-case regressions in transport operations (e.g., progress meter fidelity, option handling in `upload-pack.c` and `send-pack.c`).
- Test coverage and verification of edge cases (e.g., error handling during pack generation, shallow clone interactions, partial clone filter specs).
- The remaining `get_log_output_encoding()` dependency in patch 5/6. Junio C Hamano raised a substantive objection to the `extern` declaration as a workaround that bypasses the compile-time guard (`USE_THE_REPOSITORY_VARIABLE`) against reintroducing `the_repository` usage. Patrick Steinhardt acknowledged the trade-off and expressed openness to revising the approach, but no resolution has been reached. The discussion highlights the tension between compile-time enforcement and incremental refactoring progress.
- Elijah Newren identified a potential use-after-scope bug in the files-backend implementation (`odb_source_files_generate_pack()` in patch 1/6). The issue arises from the interaction between `clean_on_exit = 1` (which registers the local `child_process cp` for later cleanup) and the fact that `cp` is stack-allocated. While the normal teardown path avoids dereferencing the stale pointer (because `finish_command()` matches by PID), an abnormal exit would trigger `cleanup_children()`, which would attempt to read from the reclaimed stack space. This safety concern affects the robustness of the ODB interface’s error handling during pack generation and has not yet been addressed.
- **New**: Justin Tobler raised a clarifying question about the architectural intent of patch 6/6: whether `git bundle` will work with non-files ODB backends while still producing packfiles as the common interchange format. This question reflects curiosity about the series’ long-term goals and does not constitute a request for changes or a critique of the implementation.
