Subject: [PATCH 0/5] odb: make packfile generation pluggable
Series version: v3 (six patches, third public iteration)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Decouple Git’s transport layer (fetch, push, bundle) from the "files" ODB backend by introducing a pluggable interface for packfile generation. This is a step in Patrick Steinhardt’s larger ODB abstraction effort, which aims to support alternative backends beyond loose objects and packfiles. The series does not yet address repository maintenance or the `git-pack-objects` command, deferring those to a future `git-objects` command.

Current status
The series is now in its third iteration, posted as [PATCH v3 0/6] (six patches). It remains queued in `seen` and under active review. The v3 iteration addresses two key issues from prior reviews: a use-after-scope bug in the files-backend implementation (identified by Elijah Newren) and Junio C Hamano’s objection to an `extern` declaration workaround for `the_repository` usage. The bug fix moves the `child_process` struct from the stack to the heap in `odb_source_files_generate_pack()`, eliminating the risk of stale pointer dereferencing during abnormal exits. The `the_repository` issue remains unresolved, but Patrick Steinhardt has signaled openness to revisiting it. No prior versions have been merged to `next` or `master`.

Key technical details
- New ODB interface: `odb_generate_pack()` and its files-backend implementation, which delegates to the existing `git pack-objects` command.
- New structures: `struct odb_generate_pack_options` (encapsulates wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies, and file descriptors for pack and progress output) and `struct odb_pack_generator` (asynchronous operation handle with file descriptors for the generated pack and progress output, plus a finish callback).
- New/renamed symbols: `odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`, `append_one_shallow()` (renamed from `write_one_shallow()`), `append_negative_object()` (new helper in `send-pack.c`), `write_pack_data()` (updated in `builtin/bundle.c` to use the ODB interface).
- Files touched: `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source.h` (core ODB layer, patch 1/6); `upload-pack.c` (patch 2/6); `send-pack.c` (patch 3/6); `bundle.c`, `builtin/bundle.c`, `bundle.h` (patches 4/6, 5/6, and 6/6).
- Behavior: transport commands delegate packfile generation to the ODB layer, reducing backend-specific code. The interface is designed for asynchronous operation, returning file descriptors for pack and progress output. The refactoring in `upload-pack.c` (patch 2/6) and `send-pack.c` (patch 3/6) replaces manual `child_process` construction with a declarative `odb_generate_pack_options` setup, preserving all existing functionality (thin packs, progress meters, shallow clones, partial clones, URI protocols, bitmap usage). The files-backend implementation (`odb_source_files_generate_pack()`) translates ODB options into `git pack-objects` command-line arguments (e.g., `--thin`, `--shallow`, `--filter`, `--uri-protocol`). It handles shallow boundaries by neutralizing the repository’s shallow state when caller-provided shallows are present, and it supports asynchronous operation by returning file descriptors for the pack and progress output when the caller requests pipes. Error handling includes proper cleanup of descriptors and reporting of pack-objects failures (except SIGPIPE, which is treated as a normal occurrence). Patch 2/6 (new email) refactors `upload-pack.c` to use the ODB interface, replacing 35 lines of backend-specific code with a single call to `odb_generate_pack()` and a loop to relay the generated pack data. The patch renames `write_one_shallow()` to `append_one_shallow()` (now appending to an `oid_array` instead of writing to a `FILE*`) and updates the poll loop to read from the ODB generator’s file descriptors (`generator->out` and `generator->err`) instead of the child process’s pipes. Patch 4/6 refactors progress-meter option handling in `git bundle` to replace four overlapping command-line options (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`) with a single boolean `progress` flag, preserving default behavior (progress shown if stderr is a TTY, `--all-progress-implied` still passed to `git pack-objects`). Patch 5/6 refactors `bundle.c` to eliminate most `the_repository` references, replacing them with explicit `struct repository *` parameters. Patch 6/6 migrates `git bundle` to the ODB interface, completing the transport-layer refactoring. The remaining `the_repository` dependency in `get_log_output_encoding()` is left as an `extern` to minimize churn.
- On-disk format: unchanged.
- Test coverage: patch 2/6 adjusts `t5516-fetch-push.sh` to account for benign argument-order changes and the replacement of `-q` with `--quiet`; patch 3/6 makes similar adjustments for `send-pack`. Deeper verification of edge cases (e.g., shallow clones, partial clones, protocol v2 interactions, error handling during pack generation) remains pending.

The review was narrowly scoped to this safety concern and did not comment on the rest of the series. The bug arose from `clean_on_exit = 1` registering the stack-allocated `child_process cp` for later cleanup, which would dereference a stale pointer during abnormal exits (triggering `cleanup_children()`). The normal teardown path (via `odb_pack_generator_files_finish()`) avoided the bug because `finish_command()` matches by PID, but abnormal exits exposed the vulnerability. The bug has been fixed in v3.
