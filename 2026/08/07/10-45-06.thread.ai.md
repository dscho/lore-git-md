Subject: [PATCH 0/5] odb: make packfile generation pluggable
Series version: v1 (first public iteration)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Decouple Git’s transport layer (fetch, push, bundle) from the "files" ODB backend by introducing a pluggable interface for packfile generation. This is a step in Patrick Steinhardt’s larger ODB abstraction effort, which aims to support alternative backends beyond loose objects and packfiles. The series does not yet address repository maintenance or the `git-pack-objects` command, deferring those to a future `git-objects` command.

Key technical details
- New ODB interface: `odb_generate_pack()` and its files-backend implementation, which delegates to the existing `git pack-objects` command.
- New structures: `struct odb_generate_pack_options` (encapsulates wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies) and `struct odb_pack_generator` (asynchronous operation handle).
- New/renamed symbols: `odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`, `append_one_shallow()` (renamed from `write_one_shallow()`), `append_negative_object()` (new helper in `send-pack.c`), `write_pack_data()` (updated in `builtin/bundle.c` to use the ODB interface).
- Files touched: `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source.h` (core ODB layer); `upload-pack.c` (patch 2/5); `send-pack.c` (patch 3/5); `builtin/bundle.c`, `bundle.c`, `bundle.h` (patch 5/5).
- Behavior: transport commands delegate packfile generation to the ODB layer, reducing backend-specific code. The interface is designed for asynchronous operation, returning file descriptors for pack and progress output. The refactoring in `upload-pack.c` (patch 2/5) and `send-pack.c` (patch 3/5) replaces manual `child_process` construction with a declarative `odb_generate_pack_options` setup, preserving all existing functionality (thin packs, progress meters, shallow clones, partial clones, URI protocols, bitmap usage). Patch 5/5 migrates `git bundle` to the ODB interface, simplifying its progress-meter option handling to a single boolean (`progress`) instead of four overlapping options (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`), with no change to default behavior (progress shown if stderr is a TTY, `--all-progress-implied` still passed to `git pack-objects`). The `append_negative_object()` helper ensures the ODB layer only receives valid boundary objects.
- On-disk format: unchanged.
- Test coverage: patch 3/5 adjusts `t5516-fetch-push.sh` to account for benign argument-order changes and the replacement of `-q` with `--quiet`; deeper verification of edge cases (e.g., shallow clones, partial clones, protocol v2 interactions, error handling during pack generation) remains pending.
