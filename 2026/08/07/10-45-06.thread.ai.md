Subject: [PATCH 0/5] odb: make packfile generation pluggable
Series version: v1 (first public iteration)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Decouple Git’s transport layer (fetch, push, bundle) from the "files" ODB backend by introducing a pluggable interface for packfile generation. This is a step in Patrick Steinhardt’s larger ODB abstraction effort, which aims to support alternative backends beyond loose objects and packfiles. The series does not yet address repository maintenance or the `git-pack-objects` command, deferring those to a future `git-objects` command.

Current status
Under review; no prior versions. The series is based on a recent commit (2026-08-05) from `master`.

Key technical details
- New ODB interface: `odb_generate_pack()` and its files-backend implementation, which delegates to the existing `git pack-objects` command.
- New structures: `struct odb_generate_pack_options` (encapsulates wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies) and `struct odb_pack_generator` (asynchronous operation handle).
- New/renamed symbols: `odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`.
- Files touched: `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source.h` (core ODB layer); subsequent patches will touch `upload-pack.c`, `send-pack.c`, `builtin/bundle.c`.
- Behavior: transport commands will delegate packfile generation to the ODB layer, reducing backend-specific code. The interface is designed for asynchronous operation, returning file descriptors for pack and progress output.
- On-disk format: unchanged.
- Test coverage: not yet detailed in the cover letter or patch 1/5.

Open questions and loose ends
