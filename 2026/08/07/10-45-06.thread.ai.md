Subject: [PATCH 0/5] odb: make packfile generation pluggable
Series version: v4 (six patches, fourth public iteration)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Decouple Git’s transport layer (fetch, push, bundle) from the "files" ODB backend by introducing a pluggable interface for packfile generation. This is a step in Patrick Steinhardt’s larger ODB abstraction effort, which aims to support alternative backends beyond loose objects and packfiles. The series does not yet address repository maintenance or the `git-pack-objects` command, deferring those to a future `git-objects` command.

Current status
The series is now in its fourth iteration, posted as [PATCH v4 0/6] (six patches). It remains queued in `seen` and under active review. The v4 iteration is a minor revision addressing feedback from v3: it improves an error message in `upload-pack.c` (replacing the backend-specific "unable to fork git-pack-objects" with the generic "unable to pack objects"), fixes a pre-existing style nit in `builtin/bundle.c` (opening brace placement in `cmd_bundle_create()`), and leaves the rest of the series functionally unchanged. The use-after-scope bug in `odb_source_files_generate_pack()` (identified by Elijah Newren) and Junio C Hamano’s concerns about lingering `the_repository` usage remain resolved from v3. The `pack_fd` file descriptor lifecycle question (raised by Junio) is settled: the "consumed by the generator" contract applies only when the primary ODB source supports packfile generation, which is guaranteed for all current and future primary sources. The unresolved `get_log_output_encoding()` dependency in `bundle.c` remains an open question with two proposed resolutions: Patrick Steinhardt’s `extern` declaration workaround or Elijah Newren’s `#define the_repository DO_NOT_USE_THE_REPOSITORY` pattern. The latest exchange reaffirms Patrick’s preference for removing `USE_THE_REPOSITORY_VARIABLE` entirely and using an `extern` declaration, arguing that it eliminates implicit dependencies on `the_repository` at the cost of bypassing the compile-time guard for one function. Elijah’s proposal preserves the guard’s compile-time enforcement while still allowing the function to compile. No resolution has been reached. No prior versions have been merged to `next` or `master`. The latest exchange confirms that the use-after-scope bug was surfaced via AI-assisted review, which Elijah Newren manually verified, and Patrick Steinhardt endorses the utility of AI for pre-submission and peer review.

Key technical details
- New ODB interface: `odb_generate_pack()` and its files-backend implementation, which delegates to the existing `git pack-objects` command.
- New structures: `struct odb_generate_pack_options` (encapsulates wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies, and file descriptors for pack and progress output) and `struct odb_pack_generator` (asynchronous operation handle with file descriptors for the generated pack and progress output, plus a finish callback).
- New/renamed symbols: `odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`, `append_one_shallow()` (renamed from `write_one_shallow()`), `append_negative_object()` (new helper in `send-pack.c`), `write_pack_data()` (updated in `builtin/bundle.c` to use the ODB interface).
- Files touched: `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source.h` (core ODB layer, patch 1/6); `upload-pack.c` (patch 2/6); `send-pack.c` (patch 3/6); `builtin/bundle.c` (patches 4/6 and 6/6, consolidating progress-meter option handling and ODB migration); `bundle.c`, `bundle.h` (patches 5/6, completing the `the_repository` removal).
- Behavior: Transport commands delegate packfile generation to the ODB layer, reducing backend-specific code. The interface is designed for asynchronous operation, returning file descriptors for pack and progress output. The refactoring in `upload-pack.c` (patch 2/6) and `send-pack.c` (patch 3/6) replaces manual `child_process` construction with a declarative `odb_generate_pack_options` setup, preserving all existing functionality (thin packs, progress meters, shallow clones, partial clones, URI protocols, bitmap usage). The files-backend implementation (`odb_source_files_generate_pack()`) translates ODB options into `git pack-objects` command-line arguments (e.g., `--thin`, `--shallow`, `--filter`, `--uri-protocol`). It handles shallow boundaries by neutralizing the repository’s shallow state when caller-provided shallows are present, and it supports asynchronous operation by returning file descriptors for the pack and progress output when the caller requests pipes. Error handling includes proper cleanup of descriptors and reporting of pack-objects failures (except SIGPIPE, which is treated as a normal occurrence). Patch 2/6 refactored `upload-pack.c` to use the ODB interface, replacing backend-specific code with a single call to `odb_generate_pack()` and a loop to relay the generated pack data. The patch renames `write_one_shallow()` to `append_one_shallow()` to reflect its new role in appending shallow commit OIDs to an `oid_array` instead of writing them to a `FILE*`. It rewords the error message from `"git upload-pack: unable to fork git-pack-objects"` to `"git upload-pack: unable to pack objects"` to avoid leaking backend-specific terminology (addressing Karthik Nayak’s feedback). Patch 3/6 applies the same pattern to `send-pack.c`, replacing manual `child_process` construction with a declarative setup while preserving all existing functionality (thin packs, delta base offsets, shallow clones, stateless-RPC handling, progress meters). The patch introduces `append_negative_object()` to append boundary objects to the ODB’s `haves` array, and the poll loop now reads from the ODB generator’s file descriptors (`generator->out` and `generator->err`) instead of a child process’s pipes. Test adjustments in `t5516-fetch-push.sh` account for benign argument-order changes (e.g., `--quiet` instead of `-q`, removal of `--all-progress-implied` when progress is disabled). Patch 4/6 refactors `git bundle`’s progress-meter option handling, replacing `OPT_PASSTHRU_ARGV` macros with `OPT_BIT`, `OPT_NEGBIT`, and `OPT_NOOP_NOARG` to manage a boolean `progress` flag directly. The logic for determining whether to show progress (defaulting to `isatty(STDERR_FILENO)`) is preserved, and the resulting boolean is used to push either `--progress` or `--quiet` into the `pack_opts` strvec. The patch is mechanical and well-motivated, with no behavior changes or edge-case regressions. Karthik Nayak’s review of v3 praised the refactored code as “much nicer to read.” Patch 5/6 refactors `bundle.c` to eliminate most `the_repository` references, replacing them with an explicit `struct repository *` parameter passed through the call stack. Functions like `is_tag_in_date_range()` and `write_bundle_refs()` now take a `struct repository *` parameter, and all downstream calls are updated accordingly. The patch also replaces hard-coded `the_hash_algo` references with the repository’s `hash_algo` field, ensuring hash algorithm agnosticism. The only remaining dependency is `get_log_output_encoding()`, addressed with an `extern` declaration; Elijah Newren’s proposal offers an alternative using `#define the_repository DO_NOT_USE_THE_REPOSITORY` to maintain compile-time enforcement. The latest exchange reaffirms Patrick’s preference for removing `USE_THE_REPOSITORY_VARIABLE` entirely and using an `extern` declaration, arguing that it eliminates implicit dependencies on `the_repository` at the cost of bypassing the compile-time guard for one function. The patch is clean and focused, with no behavior changes or edge-case regressions. It builds on the progress-meter refactoring in patch 4/6 and sets the stage for the ODB migration in patch 6/6. Patch 6/6 migrates `git bundle` to the ODB interface, replacing the direct `git pack-objects` invocation in `write_pack_data()` with a declarative setup using `struct odb_generate_pack_options`. The new code preserves all existing functionality: thin packs, delta base offsets, and filter specs for partial clones. The function is simplified from 45 lines to 37, eliminating manual `child_process` construction and replacing it with a single call to `odb_generate_pack()` followed by a loop to relay the generated pack data. The patch removes the last vestige of the `pack_opts` strvec from `builtin/bundle.c`, consolidating progress-meter handling into the boolean `progress` flag introduced in patch 4/6. The patch updates the `create_bundle()` signature in `bundle.h` to accept a `progress` boolean instead of `pack_options`, completing the interface cleanup.
- On-disk format: unchanged.
- Test coverage: patches 2/6 and 3/6 adjust `t5516-fetch-push.sh` to account for benign argument-order changes and the replacement of `-q` with `--quiet`; deeper verification of edge cases (e.g., shallow clones, partial clones, protocol v2 interactions, error handling during pack generation, descriptor lifecycle in error paths) remains pending. Elijah Newren’s follow-up confirms the use-after-scope bug was real and surfaced via AI-assisted review, which he manually verified.

The latest exchange reaffirms Patrick’s preference for the former, but no resolution has been reached. The choice between these approaches will determine whether the compile-time guard is preserved or bypassed, and whether `replay.c` or `bundle.c` serves as the precedent for future refactoring.
- The `source` parameter in the `generate_pack` callback remains unused in the files-backend implementation, a minor interface inconsistency noted in review but deemed acceptable for forward compatibility.
- Elijah Newren’s upcoming patch, which semantically conflicts with patch 3/6 (`send-pack.c` refactoring), may require coordination with the ODB series. He plans to submit it using this series as a base, which could introduce additional review overhead or merge considerations.
