This is the first patch in Patrick Steinhardt’s five-part series introducing a pluggable interface for packfile generation in Git’s object database (ODB) layer. It defines the core ODB interface (`odb_generate_pack()`) and implements it for the "files" backend, which delegates to the existing `git pack-objects` command.

The patch adds a new `struct odb_generate_pack_options` that encapsulates all the parameters needed for transport-layer packfile generation: wants, haves, shallows, filter specs, URI protocols, progress settings, and delta policies. The interface is intentionally minimal, omitting backend-specific options like cruft packs or keep packs, which are irrelevant for transport. The files backend’s implementation spawns a `git pack-objects` child process, feeding it the provided options and object lists.

Key symbols introduced: `odb_generate_pack()`, `odb_pack_generator_finish()`, `odb_generate_pack_options_release()`, and the `odb_pack_generator` structure. The patch touches `odb.c`, `odb.h`, `odb/source-files.c`, and `odb/source.h`, adding roughly 350 lines of new code. The interface is designed for asynchronous operation, returning file descriptors for the pack and progress output so the caller can consume them while generation proceeds.

This is a foundational piece of the ODB abstraction effort; subsequent patches will refactor `upload-pack`, `send-pack`, and `bundle` to use this interface. The design is clean and well-scoped, but the long-term plan for `git-pack-objects` and repository maintenance remains unresolved.
