This is a refactoring patch in the `git last-modified` performance series. It moves the check for `revs->bloom_keyvecs_nr != 0` from the two callers of `check_maybe_different_in_bloom_filter()` into the function itself, simplifying the code. The change is purely internal: the function now returns `-1` when no Bloom key vectors are present, which prevents `count_bloom_filter_false_positive` from being incremented, but this is unobservable because Bloom statistics are only reported when key vectors are set up. The patch touches only `revision.c` and is part of the larger effort to reuse Bloom filters for faster pathspec queries in `git last-modified`. It looks clean and uncontroversial, addressing a minor stylistic nit from the v1 review.
