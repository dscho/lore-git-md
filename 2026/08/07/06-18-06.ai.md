This is the fourth patch in Patrick Steinhardt’s six-patch v2 series reintroducing a `writev(3p)`-like wrapper for performance. It applies the new `git_write_gather()` infrastructure to `sideband.c`, replacing two `write()` calls per pktline (header and payload) with a single `writev()` call. The patch is a direct performance optimization for `git-upload-pack`, reducing syscall count by roughly half (from ~133,000 to ~67,000 in the benchmark scenario).

The change is confined to `send_sideband()` in `sideband.c`, where the pktline header and payload are now batched into a two-element `iovec` array and written via `writev_or_die()`. The patch demonstrates measurable speedup: in a synthetic benchmark that precomputes the packfile and serves it via a pack-objects hook, `git-upload-pack` latency drops from 193 ms to 141 ms (a 1.37× improvement). While the absolute numbers are modest, the commit message explains that GitLab and other forges cache packfiles, making the relative gain significant under repeated requests. The patch also hints at a deeper kernel-level bottleneck in the pipe write path that is mitigated by reducing syscall pressure.

No new symbols or build-system changes are introduced here; the patch simply consumes the plumbing added in earlier patches. The commit message includes a self-contained reproduction recipe, making it easy for reviewers to verify the performance claim. The patch is technically straightforward and uncontroversial, assuming the underlying `writev()` wrapper is accepted. It is part of a larger, well-motivated effort that has already resolved all prior technical objections (platform compatibility, integer-overflow safety, API naming, and atomicity concerns).
