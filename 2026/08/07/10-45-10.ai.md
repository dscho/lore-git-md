This is the fourth patch in Patrick Steinhardt’s five-patch series introducing a pluggable ODB interface for packfile generation. It refactors the `git bundle` command’s progress-meter option handling to use a simple boolean flag (`progress`) instead of four separate, overlapping options (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`).

The patch touches only `builtin/bundle.c`, replacing the current `OPT_PASSTHRU_ARGV` pattern with `OPT_BIT`/`OPT_NEGBIT` and a single boolean. The default behavior remains unchanged: progress is shown if stderr is a TTY, and `--all-progress-implied` is still passed unconditionally to `git pack-objects`. The refactoring is mechanical and prepares the code for the next patch, which will migrate `git bundle` to the new `odb_generate_pack()` interface.

No new symbols or files are introduced; the change is confined to option parsing and the construction of the `pack_opts` strvec. The commit message explains the motivation clearly, and the diff is small and focused. This patch is unlikely to be controversial, but it may draw attention from reviewers who care about command-line interface consistency or who are following the ODB abstraction effort closely.
