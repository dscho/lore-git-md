This is the sixth patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch is a targeted refactoring by Jeff King (Peff) that removes the `object_info_oids` and `object_info_results` fields from the `git_transport_options` struct and instead passes them as explicit parameters to `transport_fetch_object_info()` and its vtable implementations.

The change is purely mechanical and addresses a latent design issue: the current implementation stores pointers to the OID array and results struct in the transport struct, but these are only valid for a single request. This creates a subtle risk—if the transport were reused, the struct could retain dangling pointers to stack variables from the previous call. The refactoring makes ownership clearer: the caller retains responsibility for the OID array and results, and the transport no longer needs to manage their lifetimes. The patch also marks the OID array as `const` to emphasize its input-only role.

The patch touches seven files (`transport.c`, `transport-helper.c`, `builtin/cat-file.c`, `fetch-object-info.c`, `fetch-object-info.h`, `transport-internal.h`, and `transport.h`) and updates function signatures to reflect the new parameter list. No behavior changes are involved, and the patch is uncontroversial. It has been integrated into Pablo’s series with only minor commit message typo fixes and is explicitly endorsed by Junio as ready to merge. The refactoring prepares the codebase for future enhancements, such as reusing transport connections for multiple object-info requests, and aligns with the series’ broader goal of cleanly extending the remote-object-info functionality.
