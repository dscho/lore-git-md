This is a review reply from Patrick Steinhardt to the first patch in Justin Tobler’s six-patch series extending ODB transactions for pluggable packfile writes in `git receive-pack`. The series is part of the ongoing ODB abstraction effort led by Patrick.

Patrick’s review is substantive. He engages with the design of the new `odb_transaction_release()` interface, questioning whether "release" is the right name (suggesting "finalize" instead) and whether the function should be able to report errors—specifically, whether failures in cleaning up ".keep" files (which can happen in the "files" backend) should be ignored or surfaced to the caller. He also notes that `builtin/receive-pack.c` is the only caller where the transaction is not released immediately after commit, because it needs to hold on to ".keep" files until references are updated, and suggests highlighting this in the commit message.

The review does not object to the patch’s direction but raises ergonomic and robustness concerns about the new interface. No tested feedback is provided; this is a design-level discussion. The author’s uncertainty about the transaction lifecycle design (flagged in the cover letter) is now concretely engaged: Patrick’s questions about error reporting and naming reflect the same concerns. The thread is still in the design phase; no follow-up patches or resolutions are present yet.
