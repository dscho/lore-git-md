This is the final patch in Toon Claes’s six-part series optimizing the experimental `git last-modified` command by reusing Bloom filters. It addresses a subtle but important edge case: wildcard pathspecs like `*.c` that cannot be converted into a single Bloom key.

The issue is that `prepare_revision_walk()`—which builds the pathspec key vectors for Bloom filter lookups—clears `bloom_filter_settings` entirely when it encounters a pathspec that doesn’t map cleanly to a Bloom key (such as a top-level wildcard). Without those settings, the per-path Bloom filter checks in `git last-modified` fail, forcing the command to fall back to the slower diff-based path for every commit. This patch restores the settings immediately after `prepare_revision_walk()` returns, ensuring that the per-path Bloom filter logic continues to work even for wildcard pathspecs.

The fix is minimal—just eight lines in `builtin/last-modified.c`—and well-motivated. It preserves the 3.7× speedup the series achieves for wildcard queries, which would otherwise be lost. The commit message clearly explains the problem and the solution, and the code itself is straightforward. This is a tidy, uncontroversial cleanup that rounds out the series. No further changes are expected unless new edge cases emerge in testing.
