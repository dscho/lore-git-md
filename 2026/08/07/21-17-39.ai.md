This is a substantive review from Junio C Hamano on the core patch of D. Ben Knoble’s series converting `USE_NSEC` to a runtime config (`core.useNanosec`). The review identifies a performance-critical flaw in the implementation: the patch calls `repo_config_get_bool()` on every invocation of `is_racy_stat()`, which parses the config key as a string each time. Junio suggests this is prohibitively expensive for a hot code path and proposes instead caching the value in the repository’s `repo_settings` struct, where it can be accessed in constant time. The rest of the patch (config key introduction, build system cleanup, documentation updates) is not contested. This feedback is likely to require a v2 iteration focused on the performance regression.
