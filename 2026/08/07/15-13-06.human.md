This is a brief follow-up in the now-merged `git diff` bash-completion series. Junio acknowledges Elijah Newren’s observation about the latent API misuse in `__git_complete_index_file()`: the function is documented as requiring exactly one argument, but the patch invokes it with none. While the call chain silently tolerates this (the empty argument disappears in the unquoted expansion), it is accidental and could break if the helper functions’ argument handling changes. Junio agrees to pass an explicit empty string (`""`) in the next reroll, though he notes the API’s current design feels unnecessarily rigid—it forces callers to bundle multiple `ls-files` options into a single string rather than accepting them as separate arguments. The fix is purely defensive and does not affect the series’ already-merged functionality. No other changes are planned; this is a minor cleanup for future-proofing.
