This is the second patch in Patrick Steinhardt’s v2 series reintroducing a `writev(3p)`-like wrapper for performance. It adds the core plumbing: `writev_in_full()` in `wrapper.c` and `writev_or_die()` in `write-or-die.c`, mirroring Git’s existing `write_in_full()` and `write_or_die()` helpers.

The new `writev_in_full()` function handles partial writes by adjusting the `iovec` array in-place, discarding fully written segments and shrinking the current segment for the next attempt. It loops until all data is written or an unrecoverable error occurs, matching the semantics of `write_in_full()`. The companion `writev_or_die()` wrapper calls `writev_in_full()` and dies on failure, just like `write_or_die()` does for scalar writes.

No behavior changes are introduced yet; this patch only establishes the infrastructure. The commit message is minimal, but the code is straightforward and follows Git’s established patterns for I/O wrappers. The patch is a prerequisite for the later performance-critical conversions in `sideband.c` and `fast-import.c`.
