This is the fourth patch in Patrick Steinhardt’s five-part series making Git’s packfile generation pluggable. It cleans up the progress-meter option handling in `git bundle`.

The patch replaces four overlapping progress-related flags (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`) with a single boolean `progress` that is true by default when stderr is a terminal. The `--all-progress-implied` option becomes a no-op, and the other three collapse into one `--progress`/`--quiet` toggle. The change is purely internal: the command-line interface remains the same, but the code is now simpler and ready for the next patch, which will switch `git bundle` to the new ODB packfile-generation interface.

The diff touches only `builtin/bundle.c` and is mechanical: remove the old `OPT_PASSTHRU_ARGV` declarations, add `OPT_BIT`/`OPT_NEGBIT` for the new boolean, and adjust the `strvec_push` calls accordingly. The commit message explains the motivation clearly, and the patch looks uncontroversial. It’s a small, focused refactoring that paves the way for the larger ODB abstraction work.
