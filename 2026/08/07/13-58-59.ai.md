This is the first patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration variable for controlling lazy fetching. The patch is a refactoring of the promisor-remote subsystem, extracting lazy-fetching logic into a new `lazy_fetch_objects()` helper function. The refactoring is clean and well-motivated, addressing inefficiencies in the current code (e.g., redundant `GIT_NO_LAZY_FETCH` checks) and separating remote-selection logic from object-validation logic. The changes are confined to `promisor-remote.c` and are observably equivalent to the current behavior, with minor optimizations like skipping `promisor_remote_init()` when lazy fetching is disabled.

The patch serves as a preparatory step for the rest of the series, which builds on this refactoring to introduce the new configuration variable and integrate it into `upload-pack`. No substantive review feedback has appeared yet, but the author notes a minor issue with the sign-off email address, which will be corrected in the next iteration. This patch is uncontroversial and appears ready for integration, assuming the rest of the series holds up under review.
