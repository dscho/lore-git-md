This thread is exploring how to improve Git’s interactive patch selection workflow, specifically the friction of juggling `git add -p` (stage hunks) and `git checkout -p` (discard hunks) in separate steps. Junio C Hamano kicked off the discussion by proposing a unified session where users could triage hunks into three categories—stage, keep in working tree, or discard—without leaving the interactive prompt. The group quickly agreed that the core value lies in unifying the *workflow* (a single command set for all three actions) rather than the UI, with Junio emphasizing that extending `git add -p` to support a "discard" action would be the simplest path forward.

Patrick Steinhardt has now shifted the conversation toward a more ambitious redesign, advocating for a full text-based user interface (TUI) inspired by tools like Jujutsu (JJ). His proposal would replace Git’s current linear prompt-loop with an ncurses-based interface, allowing users to navigate changes hierarchically (files → hunks → lines) and toggle selections out of order. This approach would address both the workflow limitations and UI frustrations in one stroke but introduces new questions: whether Git should adopt ncurses as a dependency, how to maintain backward compatibility, and whether this should be part of a broader modernization of Git’s interactive commands. The thread is now at a crossroads—whether to prioritize Junio’s incremental fix (unifying triage actions in the existing UI) or Patrick’s holistic overhaul (a TUI-based redesign). No patches or implementation sketches have been posted yet, so the discussion remains conceptual.
