This thread is about improving Git’s interactive patch selection workflow—specifically, how to efficiently triage hunks into staged, discarded, or deferred states during commands like `git add -p`. The discussion kicked off with Junio C Hamano’s proposal to unify these actions into a single session, avoiding the need to juggle multiple commands or tools. The core friction is real: users often have hunks that are "good but not yet ready," and Git currently lacks a built-in way to defer them without discarding or staging.

The conversation has settled on three competing visions. Junio’s latest position is that Git should include only minimal, "usable but not pretty" workflow improvements—like extending `git add -p` to support a "discard" action—while avoiding anything that competes with external tools (e.g., a full TUI). Patrick Steinhardt refined his earlier TUI proposal to focus on *basic* UI enhancements, like navigable hunk selection, arguing these wouldn’t overlap with tools like lazygit. Stefan Haller, meanwhile, advocates for no internal UI changes at all, instead pushing for better APIs to support external tools.

Johannes Schindelin (Dscho) just revived a previously rejected patch series that could short-circuit much of this debate. The series, originally by Luiz Eduardo Dias Carneiro, adds a `--stash` option to `git add -p`, letting users defer hunks by stashing them. Dscho argues this directly addresses Junio’s core goal (unified triage in one session) without introducing new UI complexity or dependencies. The stash-mode approach sidesteps open questions about how to represent deferred hunks (it uses the stash) and aligns with Junio’s minimalist philosophy—though it’s unclear whether the stash mechanism itself might be seen as overloading `add -p`. The patch was rejected in March 2026, but Dscho frames its revival as a response to a demonstrated need, not a rehash of old arguments.

Key open questions now include whether the stash-mode approach is viable (or if it risks stash clutter), how it interacts with external tools, and whether it obviates the need for even basic UI improvements like navigable hunks. The thread is still in the design phase, with no implementation posted yet, but Dscho’s revival of the stash-mode patch gives the discussion a concrete starting point. If the project adopts it, the focus may shift to refining the stash integration rather than debating UI scope.
