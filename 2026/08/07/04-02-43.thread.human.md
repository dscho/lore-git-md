This thread is a feature request from Junio C Hamano to improve Git’s interactive patch selection workflow. Currently, `git add -p` and `git checkout -p` handle only two of three common use cases: staging hunks ("good") and discarding hunks ("bogus"), but offer no built-in way to defer hunks that are "good but not yet ready." Junio proposes unifying these workflows into a single interactive session where users can stage, discard, or defer hunks, eliminating the need for awkward workarounds like editing hunks into no-ops.

The discussion is still conceptual, with no patch or implementation details yet. Key technical considerations include coordinating the `add--interactive` machinery (or its C rewrite) with the `apply` and index logic, and deciding how deferred hunks should be represented—whether they persist in the working tree, are stashed, or ignored until the next session. The thread may spark debate about whether this enhancement belongs in `add -p` or merits a new command (e.g., `git triage -p`), as well as concerns about complicating the existing UI. So far, only Junio has weighed in, framing the problem and inviting feedback on the design.
