This thread is exploring how to improve Git’s interactive patch selection workflow, specifically addressing the long-standing pain point of handling "good but not yet ready" hunks during `git add -p` or `git checkout -p`. Junio C Hamano kicked off the discussion by proposing a unified interactive session that would let users stage, discard, or *defer* hunks in a single pass, rather than forcing workarounds like editing hunks into no-ops. The idea is still in the early design phase, with no patches or concrete implementation details yet.

Christian Couder has expanded the scope of the discussion by raising additional use cases that go beyond the original three actions. He points out that users might want to *squash* a hunk into an earlier commit (e.g., `HEAD~2`) or move it to a new branch mid-session, suggesting that Git could leverage the experimental `git history` command or adopt a more modular approach inspired by GitButler’s intent-based commands (e.g., `git butler commit amend`). This broadens the conversation to include whether the solution should be a single, all-encompassing command or a set of more focused tools. The thread is still wide open, with no decisions made on how to handle deferred hunks, whether to extend `add -p` or introduce a new command, or how to design the UI without overcomplicating the existing workflow. The discussion is now grappling with whether the original proposal is too narrow and how to balance flexibility with usability.
