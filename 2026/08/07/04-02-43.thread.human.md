This thread is about a proposed enhancement to Git’s interactive patch selection workflow, aiming to unify the currently fragmented process of triaging hunks into staged, kept, discarded, or stashed states. The discussion was sparked by Junio C Hamano, who framed the goal as a *minimal, reference-like* solution that avoids overloading existing commands like `git add -p` or `git checkout -p`. Instead, the focus has narrowed to implementing a new command (e.g., `git triage -p`) or mode (e.g., `git add --triage`) that consolidates these actions into a single session, with stash included as a deferral mechanism.

Key participants include Junio, who has ruled out extending `git add -p` due to philosophical objections, and Jeff King (Peff), who suggested a separate command to house the stash-mode functionality—a path that now aligns with Junio’s vision. Johannes Schindelin (Dscho) previously proposed a stash-mode patch for `git add -p`, but this would need reworking to fit the new direction. Other voices, like Patrick Steinhardt and Stefan Haller, have weighed in on UI considerations and external tool integration, though Junio’s latest stance prioritizes functionality over polish.

The discussion remains in the design phase, with no patches yet posted. Open questions include how stash integration would interact with existing workflows, whether the new command should be standalone or a mode of an existing one, and how it would coexist with tools like lazygit. The thread’s next steps will likely involve sketching out the new command’s interface and addressing stash-related concerns, such as avoiding clutter or interference with other stash operations. For now, the core goal—a unified triage workflow—is agreed upon, but the implementation details are still up in the air.
