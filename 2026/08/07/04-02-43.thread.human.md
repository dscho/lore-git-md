This thread is exploring how to improve Git’s interactive patch selection workflow, specifically the friction of needing two separate commands (`git add -p` and `git checkout -p`) to triage hunks into staged, kept, or discarded states. Junio C Hamano kicked off the discussion by proposing a unified session where users could stage, discard, or defer hunks in one go, prioritizing the *mechanism* (a single command set for all three actions) over UI style. The conversation has since converged on this core goal, with D. Ben Knoble clarifying that the value lies in the workflow itself—not the interface—using the Vim plugin Fugitive as an example of how this could work in practice.

So far, no patches or implementation details have emerged, and the discussion remains conceptual. Junio’s latest reply reaffirms the focus on unifying the triage workflow, likely by extending `git add -p` to support a "discard" action alongside "stage" and "defer." Christian Couder has broadened the scope slightly, suggesting advanced use cases like squashing hunks into older commits or moving them to new branches, but these remain secondary to the immediate goal of eliminating the two-step process. Key open questions include how deferred hunks should persist (e.g., in the working tree, stashed, or ignored) and whether this functionality belongs in `git add -p` or a new command. The thread is still in the design phase, with no clear timeline for implementation.
