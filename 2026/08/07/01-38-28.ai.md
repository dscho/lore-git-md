This is the first patch in Junio C Hamano’s three-part v4 series fixing `git diff` bash completion. It is a pure refactoring patch that prepares the ground for the behavioral changes in patches 2/3 and 3/3.

The patch removes the early `return` in `_git_diff()` that fired whenever `--` was present on the command line. Instead, it wraps the existing option-parsing logic in an `if ! __git_has_doubledash` block, so the function now falls through to the end rather than punting to Bash’s default file completion. The behavior is unchanged—completion still does nothing “Git-specific” when `--` is seen—but the control flow is now open to the later patches that will add tracked and untracked path completion. The diff touches only `contrib/completion/git-completion.bash`, moving 28 lines of option-parsing code into a conditional block and reformatting it for readability. No new functions, symbols, or CLI options are introduced.
