Core problem or goal
Fix a flaky test in `t/t7900-maintenance.sh` caused by a race condition between the foreground test process and the auto-detaching background maintenance logic in `git maintenance`. The flake has been observed in GitLab CI and is a recurring CI reliability issue.

Current status
Ready to merge. Both patches have received substantive review and all feedback has been addressed. The series is uncontroversial, self-contained, and targets only the test file. Junio’s integration branch status is not yet stated in the thread.

Key technical details
- Files touched: `t/t7900-maintenance.sh` (patch 1 refactors test scaffolding; patch 2 fixes the flake)
- New test helpers: none
- Behavior change: none (test-only fix; user-visible maintenance behavior unchanged)
- Test coverage: regression test for the flake; no new user-facing functionality
- CI evidence: GitLab job #15762975482 (linked in cover letter)
- **Refactoring details (patch 1)**:
  - Three tests (`maintenance.auto config option`, `gc.auto config option`, `maintenance.auto overrides gc.auto`) now use throwaway repositories (`git init repo`) instead of the default trash directory
  - Tests run in subshells (`(cd repo && ...)`) to scope environment changes
  - Cleanup via `test_when_finished "rm -rf repo"`
  - Config keys involved: `maintenance.auto`, `gc.auto`, `maintenance.autoDetach`, `gc.autoDetach`
  - Mechanical change: `test_config` → `git config set` inside throwaway repositories (rationale: `test_config` cannot be used in subshells due to its reliance on `test_when_finished`; cleanup is handled at the repository level by `test_when_finished "rm -rf repo"`)
  - Commit message explicitly documents the constraint and rationale for the mechanical change, including the subshell limitation and the repository-level cleanup strategy
- **Fix details (patch 2)**:
  - Restores default behavior (auto-detach disabled) for the test script by not setting `GIT_TEST_MAINT_AUTO_DETACH` globally
  - Unsets `GIT_TEST_MAINT_AUTO_DETACH` only in the three tests that explicitly require auto-detach
  - Eliminates the race condition by isolating auto-detach logic to where it is needed
  - Root cause: `maintenance.lock` file from a concurrently running detached `git-maintenance` process
  - Evidence: Trace2 output showing missing `gc` tasks in the flake
  - Commit message clarifies the role of `GIT_TEST_MAINT_AUTO_DETACH` and the root cause (a concurrently running `git-maintenance` process)
