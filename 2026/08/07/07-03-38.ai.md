This is a substantive review of the third patch in Justin Tobler’s six-patch series making `git receive-pack` backend-agnostic via ODB transactions. Patrick Steinhardt’s feedback focuses on the mechanical soundness of lifting global state into `struct unpack_opts` and flags ergonomic concerns about the new abstraction.

The patch replaces eight global variables (`fsck_msg_types`, `shallow_file`, `max_input_size`, `fsck_objects`, `unpack_limit`, `reject_thin`, `err_fd`, `quiet`) with an explicit `struct unpack_opts` passed through the call chain. Steinhardt’s review is positive on the direction but notes three friction points: (1) the diff is hard to audit for completeness because the old global references are scattered, (2) the ternary initialization of `fsck_objects` inside the struct initializer is visually awkward, and (3) the late assignment of `err_fd` in `unpack_with_sideband()` forces mutation of the passed-in struct, which feels unergonomic. He accepts the trade-offs as necessary for the larger goal but invites future scrutiny when the function moves to a different file in a later patch. No functional bugs are identified; the review is purely about code clarity and maintainability.
