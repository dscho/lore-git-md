This is the v5 reroll of Patrick Steinhardt’s six-patch series that makes the creation of on-disk object-database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort and is now ready for merging after addressing the last two minor issues raised by Toon Claes.

The core change is architectural: while the top-level `objects/` directory remains hard-coded (it is required for repository discovery), the creation of backend-specific subdirectories (`objects/info`, `objects/pack`, etc.) is now delegated to the ODB backend via a new `create_on_disk` callback. This enables future backends to implement custom on-disk layouts without touching core setup code.

The first three patches are preparatory. Patch 1 fixes a latent correctness bug in loose-object map loading: Git was always loading the map from the repository’s common `objects/` directory instead of the path specific to each ODB source, causing alternates’ loose-object maps to be silently ignored. The fix is minimal (use `loose->base.path` instead of the repository’s common directory) and comes with a regression test in `t/t1016-compatObjectFormat.sh`. Patch 2 detangles loose-object map loading from repository setup by moving the logic into the loose backend itself, eliminating an unconditional downcast that would BUG if a non-files backend were ever used with a compatibility hash algorithm. Patch 3 moves environment-variable handling (`GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`) into `odb_new()`, deduplicating logic and preparing for a future where alternates are handled inside the “files” backend.

Patch 4 is the mechanical refactoring that defers ODB creation until after the backend is known. In v4 Patrick abandoned the `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag in favor of Toon Claes’s alternative: ODB creation is now an explicit step at every call site (`repo_init()`, `enter_repo()`, `setup_git_directory_gently()`, and `create_object_database()`). This keeps ODB initialization and on-disk creation together, simplifying the path for the final patch. Patch 5 introduces `odb_source_type_to_name()`, a helper that improves BUG-message clarity in downcasting macros. Patch 6 implements the `create_on_disk` callback in the “files” backend, replacing hard-coded directory creation with `safe_create_dir()` calls for `pack/` and `info/`.

The series touches 17 files across loose-object handling (`loose.c`, `loose.h`), ODB source management (`odb/source*.c`, `odb/source*.h`), and repository setup (`setup.c`, `repository.c`). New symbols include `enum odb_new_flags` (`ODB_NEW_HONOR_ENV`), the `create_on_disk` callback, `safe_create_dir()`, and the downcast macros (`ODB_SOURCE_CAST_TO_FILES`, `odb_source_files_downcast()`). The only remaining direct caller of `repo_read_loose_object_map()` is in `object-file-convert.c`, which reloads the map after potential concurrent updates; Patrick suggests this could eventually be replaced by a `FLUSH_CACHES` operation on the ODB source.

This reroll removes a leftover formatting change and fixes a stale comment. All substantive review feedback has been addressed: the series is fully approved by Justin Tobler and Toon Claes, and Junio’s “What’s cooking” report (2025-06-10) lists the first patch as “will merge to ‘next’” and the rest as “under review”. The two minor issues noted by Toon Claes (misleading docstring for `apply_repository_format()` and a formatting inconsistency in `init_db()`) are the only remaining items before the series graduates.
