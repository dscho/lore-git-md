This is a **bugfix** that plugs a use-after-free in `get_oid_with_context_1()` when resolving relative paths in `:<stage>:<path>` syntax against a sparse index.

The patch addresses a memory management flaw where `resolve_relative_path()` allocates a new string for relative paths, but the code later frees that string while still using its pointer (`cp`) in `reject_tree_in_index()`. The fix consolidates the control flow to ensure the string is freed only after its final use. The bug requires three specific conditions to trigger: a relative path, a sparse directory in the index, and a leading colon followed by a digit (e.g., `:0:./dir/`).

The commit includes a regression test in `t1092-sparse-checkout-compatibility.sh` that verifies the fix under `SANITIZE=address`. Without the patch, the test fails with heap-use-after-free errors and garbled error messages; with it, the error message is stable and the sanitizer remains quiet. The reproducer is non-trivial to trigger manually, but the test provides a reliable way to exercise the bug.

The patch is well-motivated, with clear references to prior discussion (including a suggested fix from Junio) and a thorough explanation of the edge case. The code change is minimal and focused, and the test coverage is appropriate. This looks like a solid fix for a subtle but real issue.
