This is the second patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable for controlling lazy fetching. The patch extracts and generalizes the allowlist-checking logic from Git’s existing `safe.directory` machinery into a reusable `path_allowlist_apply()` helper, preparing the ground for the new `uploadpack.lazyFetchTrusted` feature.

The refactoring moves the core path-matching logic from `safe_directory_cb()` into a standalone function that takes a key, value, target path, and output pointer. The helper is intentionally generic: it handles wildcard (`*`) and dot (`.`) values, validates absolute paths, normalizes them with `real_pathdup()`, and supports directory-globbing via `/*` suffixes. The original `safe_directory_cb()` is reduced to a thin wrapper that delegates to the new helper. No behavior changes are introduced—this is purely a code reorganization to enable reuse in the next patch.

The patch touches only `setup.c` and is small (59 insertions, 48 deletions). The commit message is clear and concise, explaining both the immediate goal (preparing for a new config variable) and the technical approach (extracting reusable logic). The code itself is clean and follows Git’s style; the helper’s interface is straightforward and well-documented in the source.

This is a well-motivated refactoring that directly supports the series’ goal of server-side trust control. The extracted helper will be used in patch 4 to check whether a repository path is in the `uploadpack.lazyFetchTrusted` allowlist, mirroring how `safe.directory` works.
