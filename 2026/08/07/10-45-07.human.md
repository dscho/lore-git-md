This is the first patch in Patrick Steinhardt’s five-part series introducing a pluggable interface for packfile generation in Git’s object database (ODB) layer. It lays the groundwork for decoupling the transport layer (fetch, push, bundle) from the "files" backend by defining a new ODB interface (`odb_generate_pack()`) and implementing it for the files backend.

The patch adds roughly 350 lines across four files (`odb.c`, `odb.h`, `odb/source-files.c`, `odb/source.h`). The core of the change is a new `struct odb_generate_pack_options` that encapsulates the parameters needed for transport-layer packfile generation—wants, haves, shallows, filter specs, progress settings, and so on. The files backend’s implementation spawns `git pack-objects` as a child process, feeding it the appropriate arguments and object lists. The interface is asynchronous: callers consume the pack data and progress output via file descriptors while generation proceeds in the background.

This is a well-structured refactoring with a clear motivation: the current `git-pack-objects` command is too tightly coupled to backend-specific details (cruft packs, keep packs, etc.) to be easily ported to alternative ODB backends. By exposing only the subset of options needed for transport, the new interface avoids that complexity while still allowing backends to generate packfiles. The commit message is thorough, and the code is cleanly organized. No test coverage is included in this patch, but that is typical for infrastructure work that later patches will exercise.

The patch is part of Patrick’s larger ODB abstraction effort and is a prerequisite for the follow-up commits that convert `upload-pack`, `send-pack`, and `bundle` to use the new interface. It does not change on-disk format or user-visible behavior, but it is a foundational step toward pluggable backends. Reviewers will likely focus on the interface design—whether the option set is complete and whether the asynchronous model is ergonomic for callers.
