This is the second patch in Toon Claes’s six-patch v2 series that speeds up the experimental `git last-modified` command by reusing Git’s Bloom filters. It extracts the core filter-lookup logic from the internal `check_maybe_different_in_bloom_filter()` helper and exposes it as a new public function, `revs_maybe_changed_in_bloom()`, in `revision.h`.

The change is a clean refactoring: the existing tristate return (`-1`, `0`, `1`) is preserved for internal statistics counting, while the new public function returns a simple boolean (`false` = definitely unchanged, `true` = possibly changed). This lets other built-ins reuse the exact same filtering logic without redundant Bloom-filter lookups. The patch is small (32 lines added, 10 removed), well-motivated, and directly addresses the feedback from v1 that the API should be clearer for external callers. No behavioral changes are introduced; the only difference is that the logic is now accessible outside `revision.c`.
