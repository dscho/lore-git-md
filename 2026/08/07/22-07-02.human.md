This is the seventh patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now feature-complete and merge-ready, with all prior review feedback addressed.

This patch teaches the server-side object-info handler to accept "type" as a requested field. When the client includes "type" in its object-info request, the server returns the object type alongside the existing size field. The implementation is straightforward: it adds a `type` bit field to the `requested_info` struct, updates the server-side handler to parse the "type" keyword in client requests, and extends `send_info()` to transmit the object type as a string (e.g., `"blob"`) when requested. The patch also includes two mechanical cleanups: fixing a bit-field style nit (`size:1` → `size: 1`) and wrapping an over-long line in `send_info()`.

The test in `t5701-git-serve.sh` verifies the server handles requests for both "size" and "type", including duplicate OIDs, and confirms the output matches expectations. The test is well-scoped and covers the new functionality without introducing flakiness. The patch is uncontroversial and aligns with the established pattern from the predecessor series (Eric Sunshine’s "cat-file: add remote-object-info to batch-command"). No behavior changes or protocol-level adjustments are involved beyond the new capability.

This is a server-side plumbing patch that enables the end-to-end object type support completed in later patches (8/10 and 9/10). The series as a whole is narrowly scoped to object type metadata, with other metadata (disk size, delta base, object mode) explicitly ruled out as unreliable or context-dependent. The implementation is clean, well-tested, and ready for integration.
