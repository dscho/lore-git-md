This is the final patch in Patrick Steinhardt’s five-part series making Git’s packfile generation pluggable. It converts `git bundle` to use the new ODB interface (`odb_generate_pack()`) introduced earlier in the series, completing the goal of having every transport mechanism (fetch, push, bundle) delegate packfile generation to the object database layer.

The patch replaces the direct `git pack-objects` invocation in `bundle.c` with a declarative setup of `struct odb_generate_pack_options`, passing the same thin-pack, delta-base-offset, and filter-spec settings through the new interface. The progress-meter logic is simplified: instead of four overlapping options (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`), the caller now passes a single boolean (`progress`) that the ODB layer maps to the appropriate verbosity level. Default behavior remains unchanged (progress shown if stderr is a TTY).

The diff is clean and mechanical: 44 lines removed, 37 added, touching only `builtin/bundle.c`, `bundle.c`, and `bundle.h`. The commit message is concise but sufficient, and the change aligns with the series’ stated goal of centralizing packfile generation. No new edge cases are introduced, and the patch does not alter on-disk format or user-visible behavior. This looks like a well-executed, low-risk step in the ODB abstraction effort.
