This is the third patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration variable that lets operators mark repositories as trusted for lazy fetching. The series is a deliberate pivot from the earlier `GIT_NO_LAZY_FETCH=fromAccepted` proposal, addressing the security objection that untrusted repositories could trigger arbitrary code execution via lazy-fetch hooks or configuration.

This patch prepares the reusable `path_allowlist_apply()` helper—introduced in patch 2/5 by extracting the logic from `safe.directory`—for its second use case. It adds a `bool allow_dot` argument so the function can reject non-absolute paths (including single-dot paths) when needed, and exports the function with full documentation in `setup.h`. The change is small (nine lines added, four removed) and mechanical: the existing `safe_directory_cb()` wrapper continues to pass `allow_dot=true`, preserving the current behavior for `safe.directory`, while future callers (in patch 4/5) will pass `allow_dot=false` to enforce stricter path validation.

The patch is clearly motivated and well-explained; the commit message and in-code documentation spell out the intended reuse and the semantic difference between allowing `.` and requiring absolute paths. No substantive review feedback has appeared yet, but the patch looks like a clean, uncontroversial refactoring that directly supports the series’ overall goal.
