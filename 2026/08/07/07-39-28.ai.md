This is the fifth patch in the v13 series implementing `git history squash`, a new subcommand that folds a range of commits into a single commit while preserving merge topology and descendant history. This patch focuses on **range validation**, ensuring the selected history has exactly one boundary and one tip, rejects ranges that reach a root commit or have external parents, and standardizes error messages.

The patch introduces `resolve_squash_range()`, a helper that walks the selected commits in topological order, marking each with `SQUASH_SEEN` and tracking tips with `SQUASH_TIP`. It enforces three key invariants: (1) every parent after the oldest commit must either be selected or a parent of the oldest commit (accepting contained merges while rejecting external merge arms), (2) the range must have exactly one tip, and (3) the range must not reach a root commit. The validation is performed in a single pass, improving efficiency over earlier multi-phase approaches. Error messages now include specific commit OIDs for multi-tip rejection and root-commit errors, making diagnostics clearer.

The test suite (`t/t3455-history-squash.sh`) covers the new validation logic with cases for empty ranges, single-commit ranges, root commits, multiple tips, and external merge parents. The patch fully adopts Phillip Wood’s v10 review patches for boundary detection and multi-tip rejection, replacing the earlier `--boundary`-based approach with object flags. This is a **substantive refactoring** that addresses prior robustness concerns without changing user-visible behavior.

This patch is **ready for integration** as part of the larger series. It is a focused, well-tested component that isolates range validation from the rest of the squash logic, aligning with the series’ goal of incremental review.
