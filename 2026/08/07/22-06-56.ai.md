This is the first patch in Pablo Sabater’s v5 GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder. It is a test cleanup patch targeting `t5701-git-serve.sh`, replacing the use of `wc -c | xargs` with the `test_file_size()` helper and caching the output of `git rev-parse two:two.t` in variables.

The change is purely mechanical and uncontroversial, motivated by portability and the preservation of command exit statuses within here-documents. The original version used `wc -c | xargs` to strip whitespace from the file size output, but this approach masked the exit status of `wc -c` if it failed. The new version uses `test_file_size()`, which outputs the size directly, and stores the results in variables (`two_oid` and `two_size`) outside the here-document, ensuring that the exit statuses of the commands are preserved. Junio has explicitly endorsed this patch as ready to merge, noting that the change is a straightforward improvement with no behavior changes or technical concerns.
