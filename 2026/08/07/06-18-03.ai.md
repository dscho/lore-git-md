This is the first patch in a five-part performance series reintroducing a `writev(3p)`-like wrapper for Git. It adds the compatibility layer for platforms that lack the `writev` system call, specifically Windows (both MSVC and MinGW builds). The patch introduces a new `compat/writev.c` file that implements `git_writev()`, a wrapper that emulates `writev` by writing only the first non-empty `iovec` in the loop. This design ensures the call remains non-interleaving, matching the behavior of `write(2)` and addressing a forward-compatibility concern raised in earlier review.

The implementation includes bounds-checking logic to prevent integer overflow in the sum of `iov_len` values, returning `EINVAL` if the total exceeds `SSIZE_MAX`. The wrapper is conditionally compiled via `NO_WRITEV`, which is set for Windows builds in `config.mak.uname` and detected in `CMakeLists.txt` and `meson.build`. The patch also defines a `git_iovec` struct and renames the `iovec` symbol to avoid conflicts on platforms without native `writev` support.

This is a refactoring and platform-compatibility patch, laying the groundwork for the performance improvements in later patches. The changes are confined to build system and compatibility code, with no user-visible behavior changes. The wrapper’s design—writing only the first non-empty `iovec`—simplifies the code by removing the need for complex loop logic and overflow checks, while still providing the batched-write semantics needed for performance. The patch is technically sound and addresses all prior objections, though the series as a whole still awaits Junio C Hamano’s assessment of whether the performance gains justify the added complexity.
