This is a maintainer follow-up in the ongoing refactoring thread about repository configuration handling in `environment.c`. Junio C Hamano responds to Patrick Steinhardt’s forward-looking question about lifting the `the_repository` restriction in `repo_config_values()`. Junio expresses skepticism about the current design, noting that while repository instances can be initialized with `repo_init()`, it is unclear whether that alone makes the embedded `repo_settings` and `repo_config_values` structures usable. He also questions why both structures exist and how variables are divided between them, and points out that some code paths still need to read per-user or per-system settings outside any repository, which currently relies on `the_repository` as a global fallback. Junio suggests that unless the project moves toward free-standing configuration structures (not tied to any repository instance), the effort might simply recreate a different set of global variables. He concludes that this broader design discussion is largely separate from Tian Yuchen’s current cleanup series, which remains ready for final review and does not alter behavior. The email does not object to the v3 patches or propose changes to them, but it signals that the long-term direction of repository configuration handling may need deeper architectural work.
