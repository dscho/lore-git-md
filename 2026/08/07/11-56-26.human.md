This is the third and final patch in D. Ben Knoble’s three-part series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The patch directly addresses the "racy Git" problem by allowing users to enable nanosecond precision on supported filesystems without recompiling Git.

The change removes the `USE_NSEC` macro from the build system (Makefile and configure.ac) and introduces a new `core.useNanosec` config key, defaulting to false. The implementation touches `read-cache.c` and `statinfo.c` to replace compile-time `#ifdef` checks with runtime boolean logic, and updates `environment.c` and `environment.h` to store the new setting in `struct repo_config_values`. Documentation in `Documentation/config/core.adoc` and `Documentation/technical/racy-git.adoc` is updated to reflect the new runtime option and clarify which filesystems are known to work with nanosecond precision.

The author includes benchmark results showing a dramatic performance improvement for `git diff` in new worktrees when `core.useNanosec` is enabled, reducing execution time from ~217 ms to ~3.8 ms. The patch is well-motivated and technically sound, though the naming of the config key (`core.useNanosec`) may still be debated, as it could be too specific if future platforms offer extended precision beyond nanoseconds. The series as a whole looks like a clear usability win, and this patch is the core of the change. The conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics advance.
