Thread identity
Subject: [PATCH 0/3] convert USE_NSEC to runtime config
Series version: v3 (cooking in `next` as `dk/use-nsec-runtime`)
Originating author: D. Ben Knoble
Thread type: patch series

Core problem or goal
Replace the build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`) to allow users to enable nanosecond precision on supported filesystems without recompiling Git, reducing "racy Git" problems. The series also includes a Meson build-system fix (`MAN_BASE_URL` configuration) and a no-op refactor of `repo_config_values_init`.

Current status
Cooking in `next` under the topic `dk/use-nsec-runtime`; v3 posted. The cross-platform correctness blocker (silent corruption risk when `core.useNanosec=true` is set on a `NO_NSEC` platform) is resolved by `#ifdef`-ing out the `use_nanosec` field and all related code paths in `NO_NSEC` builds, ensuring backward compatibility. The performance regression identified in v1 (~41× slowdown in `git diff` benchmarks due to calling `repo_config_get_bool()` on every `is_racy_stat()` invocation) remains fixed by caching the value in the repository’s `repo_config_values` struct; benchmark results confirm performance is restored to baseline (21 ms vs 20 ms). Junio’s and Patrick Steinhardt’s reviews of v3 3/3 identify final polish items, all of which the author now agrees to address: (1) the `use_nanosec` field in `struct repo_config_values` will be unconditionally initialized to `0` in `repo_config_values_init()` to avoid uninitialized reads, (2) the `#ifndef NO_NSEC` guards in `is_racy_stat()` will be simplified to a single ternary expression for readability, (3) the missed reference to `USE_NSEC` in `builtin/update-index.c` will be updated, and (4) the documentation for `core.useNanosec` will include a warning about platform/filesystem limitations. Junio’s latest reply rejects the idea of a runtime warning when `core.useNanosec=true` is set on a `NO_NSEC` platform, prioritizing user experience for shared configurations over proactive warnings. The Meson build-system fix (first patch) and the no-op refactor (second patch) are confirmed correct, uncontroversial, and ready to advance independently after Patrick Steinhardt’s review; both are purely mechanical and pose no risk. The series is based on master (2c78326f81) and consists of three patches: (1) the Meson build-system fix, (2) the no-op refactor of `repo_config_values_init`, and (3) the core change introducing `core.useNanosec` and removing `USE_NSEC`. A textual and semantic conflict exists with `ty/repo-config-cleanups` in `seen` (removes comments in `struct repo_config_values` that this series adds). Benchmark results show a ~57× performance improvement for `git diff` in new worktrees when `core.useNanosec` is enabled (from ~217 ms to ~3.8 ms) in the original v1 implementation, but this is now overshadowed by the hot-path regression fix and the cross-platform correctness resolution. The `Best-viewed-with: --ignore-space-change` hint remains in the commit message body as requested by SZEDER Gábor.

Key technical details
Files touched: `Documentation/config/core.adoc`, `Documentation/meson.build`, `meson_options.txt`, `environment.c`, `environment.h`, `read-cache.c`, `statinfo.c`, `Documentation/technical/racy-git.adoc`, `compat/posix.h`, `Makefile`, `configure.ac`, `builtin/update-index.c`.
New config key: `core.useNanosec` (defaults to false).
Behavior change: nanosecond precision becomes configurable at runtime rather than compile time; performance impact documented for `git diff` in new worktrees. The patch preserves existing behavior on platforms lacking nanosecond support by `#ifdef`-ing out the `use_nanosec` field and all related code paths in `NO_NSEC` builds, preventing silent corruption when `core.useNanosec=true` is set on a platform where `NO_NSEC` is defined. No runtime warning will be emitted when `core.useNanosec=true` is set on a `NO_NSEC` platform; users must rely on documentation to understand the risks.
On-disk format: unchanged.
Test coverage: not yet updated; platform-dependent nature complicates testing. The Meson build-system fix and the no-op refactor are self-contained and unlikely to require additional testing. Documentation now lists filesystems known to support nanosecond precision (ext2, ext4, XFS, CEPH, CIFS, NTFS, UFS, FUSE, FAT).
Performance regression: the v1 implementation introduced a hot-path cost by parsing the config key on every `is_racy_stat()` call; caching in `repo_config_values` is confirmed as the fix. Junio’s and Patrick’s reviews do not affect performance but address initialization correctness and code clarity.
Code structure: the nested `#ifndef NO_NSEC` guards in `is_racy_stat()` will be simplified to a single ternary expression, since `use_nanosec` will now be unconditionally initialized. The `use_nanosec` field will be initialized to `0` in `repo_config_values_init()` regardless of `NO_NSEC` to ensure no uninitialized reads occur. The documentation will warn users about platform/filesystem limitations (e.g., "may not be safe on all platforms").

Open questions and loose ends
- Cache location: whether to use `repo_config_values` (modern but limited to `the_repository`), `repo_settings` (supports per-repository variation, e.g., for submodules), or a global variable as a temporary measure for caching `core.useNanosec`. The author’s partial control-flow analysis shows that all 214 call paths to `repo_config_values()` currently terminate at `the_repository`, even though some intermediate nodes are exposed via public `libgit.a` interfaces, meaning the `the_repository`-only limitation is already exposed and may grow with this change. Patrick Steinhardt suggests that requiring `the_repository`-cleanliness could block the series indefinitely and offers a global variable as a fallback if the project is unwilling to accept the current limitation of `repo_config_values`.
- Naming: `core.useNanosec` may be too specific if platforms offer extended precision beyond nanoseconds (e.g., picoseconds).
- Testing: how to handle platform-dependent behavior in the test suite for the nanosecond-precision change.
- Coordination: conflict with `ty/repo-config-cleanups` in `seen` will require resolution if both topics advance.
- **Resolved**: Runtime warning for `NO_NSEC` builds where `core.useNanosec=true` is set: rejected in favor of documentation-only warnings.
