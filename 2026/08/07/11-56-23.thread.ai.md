Thread identity
Subject: [PATCH 0/3] convert USE_NSEC to runtime config
Series version: v1 (v2 imminent)
Originating author: D. Ben Knoble
Thread type: patch series

Core problem or goal
Replace the build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`) to allow users to enable nanosecond precision on supported filesystems without recompiling Git, reducing "racy Git" problems. The series also includes a Meson build-system fix (`MAN_BASE_URL` configuration) and a no-op refactor of `repo_config_values_init`.

Current status
Under review; v1 posted, v2 imminent. Junio C Hamano identified a performance-critical flaw in the core patch: the v1 implementation called `repo_config_get_bool()` on every `is_racy_stat()` invocation, creating a ~41× slowdown in `git diff` benchmarks (854 ms vs 20 ms). The author has benchmarked a fix that caches the value in the repository’s `repo_settings` struct, restoring performance to baseline (21 ms vs 20 ms). The architectural question of where to cache `core.useNanosec`—`repo_config_values` (modern but currently limited to `the_repository`), `repo_settings` (supports per-repository variation, e.g., for submodules), or a global variable—is now informed by new evidence: a CI run confirms the test suite passes when using `repo_config_values`, and a partial control-flow analysis of 214 call paths leading to `repo_config_values()` reveals that every analyzed path currently terminates at `the_repository`, even though some intermediate nodes are exposed via public `libgit.a` interfaces. This means the "must only use `the_repository`" surface area is already exposed and may grow further with this change. Patrick Steinhardt responds pragmatically, noting that while `repo_config_values()` is the modern target for config-driven settings, its current limitation to `the_repository` is a blocker for further expansion until the project resolves how to support other repositories (e.g., submodules). He does not oppose landing the series with `repo_config_values()` if the CI and analysis suggest it is safe, but offers a fallback—using a global variable as a temporary measure—if the project prefers to avoid expanding the `the_repository`-only surface area. The author expresses concern that requiring `the_repository`-cleanliness could block the series indefinitely unless the project accepts `repo_settings` or a global variable as a stopgap. The Meson build-system fix (first patch) is confirmed correct and uncontroversial after Patrick Steinhardt’s review; it aligns Meson’s `man.base.url.for.relative.links` default with the Makefile’s behavior and adds a configurable `man_base_url` option for downstream flexibility. The no-op refactor and documentation changes remain uncontested. The series is based on master (2c78326f81) and consists of three patches: (1) the Meson build-system fix, (2) a no-op refactor of `repo_config_values_init`, and (3) the core change introducing `core.useNanosec` and removing `USE_NSEC`. A textual and semantic conflict exists with `ty/repo-config-cleanups` in `seen` (removes comments in `struct repo_config_values` that this series adds). Benchmark results show a ~57× performance improvement for `git diff` in new worktrees when `core.useNanosec` is enabled (from ~217 ms to ~3.8 ms) in the original v1 implementation, but this is overshadowed by the hot-path regression. The next iteration will include the performance fix, a cosmetic commit-message adjustment (moving the `Best-viewed-with: --ignore-space-change` hint into the body), and the cache location decision.

Key technical details
Files touched: `Documentation/config/core.adoc`, `Documentation/meson.build`, `meson_options.txt`, `environment.c`, `environment.h`, `read-cache.c`, `statinfo.c`, `Documentation/technical/racy-git.adoc`, `compat/posix.h`, and related build files (Makefile, configure.ac).
New config key: `core.useNanosec` (defaults to false).
Behavior change: nanosecond precision becomes configurable at runtime rather than compile time; performance impact documented for `git diff` in new worktrees. The patch preserves existing behavior on platforms lacking nanosecond support by retaining the `NO_NSEC` conditional in `compat/posix.h`.
On-disk format: unchanged.
Test coverage: not yet updated; platform-dependent nature complicates testing. The Meson build-system fix and the no-op refactor are self-contained and unlikely to require additional testing. Documentation now lists filesystems known to support nanosecond precision.
Performance regression: the v1 implementation introduced a hot-path cost by parsing the config key on every `is_racy_stat()` call; caching in `repo_settings` or a global variable is confirmed as the fix. The choice of cache location (`repo_config_values`, `repo_settings`, or a global variable) now hinges on whether the project is willing to accept the current `the_repository`-only limitation of `repo_config_values` or prefers a stopgap (global variable or `repo_settings`) until the broader `the_repository` issue is resolved.
