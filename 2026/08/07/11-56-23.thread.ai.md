Thread identity
Subject: [PATCH 0/3] convert USE_NSEC to runtime config
Series version: v1
Originating author: D. Ben Knoble
Thread type: patch series

Core problem or goal
Replace the build-time `USE_NSEC` macro with a runtime configuration option (`core.useNanosec`) so users can enable nanosecond precision on supported filesystems without recompiling Git, reducing "racy Git" problems. The series also includes a build-system fix for Meson (`MAN_BASE_URL` configuration) and a no-op refactor of `repo_config_values_init`.

Current status
Under review; v1 posted. The series is based on master (2c78326f81) and consists of three patches: (1) a Meson build-system fix for `MAN_BASE_URL` (unrelated to nanosecond precision), (2) a no-op refactor of `repo_config_values_init` that reorders assignments to match the `struct repo_config_values` declaration order and adds section comments grouping assignments by config section (`core`, `sparse`, `branch`), and (3) the core change introducing `core.useNanosec` and removing `USE_NSEC` from the build system. A textual and semantic conflict exists with `ty/repo-config-cleanups` in `seen` (removes comments in `struct repo_config_values` that this series adds). Benchmark results in the core patch show a ~57x performance improvement for `git diff` in new worktrees when `core.useNanosec` is enabled (from ~217ms to ~3.8ms).

Key technical details
Files touched: `Documentation/config/core.adoc`, `Documentation/meson.build`, `meson_options.txt`, `environment.c`, `environment.h`, `read-cache.c`, `statinfo.c`, `Documentation/technical/racy-git.adoc`, and related build files (Makefile, configure.ac).
New config key: `core.useNanosec` (defaults to false).
Behavior change: nanosecond precision becomes configurable at runtime rather than compile time; performance impact documented for `git diff` in new worktrees.
On-disk format: unchanged.
Test coverage: not yet updated; platform-dependent nature complicates testing. The Meson build-system fix and the no-op refactor are self-contained and unlikely to require additional testing. Documentation now lists filesystems known to support nanosecond precision.

Open questions and loose ends
- Naming: `core.useNanosec` may be too specific if platforms offer extended precision that isn’t strictly nanosecond-based (e.g., picoseconds).
- Testing: how to handle platform-dependent behavior in the test suite for the nanosecond-precision change.
- Coordination: conflict with `ty/repo-config-cleanups` in `seen` will require resolution if both topics advance.
- Performance: while the benchmark shows a clear win for `git diff` in new worktrees, broader performance implications (e.g., for `git status` or `git add`) remain unmeasured.
