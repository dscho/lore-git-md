This is a refactoring patch in the `git history squash` series, part of the ongoing effort to implement a standalone command for folding commit ranges. Patch 2/8 adds an optional `message_template` parameter to the internal `commit_tree_ext()` helper in `builtin/history.c`. When the caller supplies a template, the function uses it instead of the commit message from the passed-in commit object; when NULL, the original behavior is preserved.

The change is minimal and mechanical: the new parameter is checked at the start of the function, and the template is used wherever the original commit message was previously referenced. Three existing callers (`commit_tree_with_edited_message`, `cmd_history_fixup`, and `split_commit`) are updated to pass NULL, ensuring their behavior remains unchanged. This plumbing change enables the default message editing feature introduced later in the series (Patch 8/8), where `git history squash` constructs an autosquash-style template for the user to edit.

The patch is uncontroversial and ready for integration. It touches only `builtin/history.c` and makes no functional changes to user-visible behavior. The motivation is clear: future patches will need to seed commit messages from sources other than a single commit, and this refactoring centralizes that logic. The commit message succinctly explains the purpose and impact.
