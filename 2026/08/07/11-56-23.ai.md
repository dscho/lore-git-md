This is a three-patch series from D. Ben Knoble that converts the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The goal is to reduce "racy Git" problems on supported filesystems by allowing users to enable nanosecond precision without recompiling Git.

The series builds on master (2c78326f81) and is motivated by the observation that build-time configuration is too early for distributing Git, as filesystem support for nanosecond precision varies. The cover letter notes a minor textual and semantic conflict with `ty/repo-config-cleanups` in `seen`, which removes comments in `struct repo_config_values` that this series adds to. The author also raises a naming concern: `core.useNanosec` might be too specific, as some platforms could offer extended precision that isn’t strictly nanosecond-based.

Patch 1 is a small documentation fix for Meson, unrelated to the main change but spotted during review. Patch 2 reorganizes `repo_config_values_init` as a no-op preparatory step. Patch 3 is the core change, introducing `core.useNanosec` and removing the `USE_NSEC` macro from the build system. The series touches `Documentation/config/core.adoc`, `environment.c`, `read-cache.c`, and several other files, but the author notes that tests haven’t been updated yet, as it’s unclear how to handle the platform-dependent nature of the change.

The patch looks technically sound but may need adjustments for naming and testing. The conflict with `ty/repo-config-cleanups` suggests coordination will be needed if both topics advance. The runtime config approach addresses a real usability issue, and the series is well-structured, though the naming question could spark discussion.
