This is a brief follow-up in the ongoing GSoC patch series extending `git cat-file --batch-command` to support `%(objecttype)` in remote-object-info queries. Jeff King (Peff) and Pablo Sabater discuss a potential future optimization: making the `remote-object-info` protocol stateful to allow multiple object-info requests over a single transport connection.

Peff acknowledges Pablo’s suggestion to make the remote URL optional but expresses skepticism about the added complexity. Instead, he proposes leaving the current syntax (`remote-object-info <remote> <objs...>`) unchanged and letting `git cat-file` handle connection reuse internally as an optimization. This would avoid protocol changes while still allowing the transport to remain open between requests, reducing overhead for repeated queries. Peff notes that the cost of keeping a connection open (e.g., an SSH session) is low, as most transports either time out naturally or are used in contexts where additional requests are likely.

Pablo agrees but defers the optimization to a follow-up series, citing time constraints and the current focus on object type support. Peff endorses this approach, emphasizing that the protocol remains unchanged and the optimization can be added later without affecting the current patch series. The discussion is speculative and does not alter the immediate patch set, which remains on track for integration. Key technical details: no new symbols or files are introduced, and the proposed optimization would be invisible to users.
