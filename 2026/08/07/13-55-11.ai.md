This is the final patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that allows operators to mark repositories as trusted for lazy fetching. This patch wires the configuration into `upload-pack.c`, enabling the feature to actually work: when the served repository is listed in `uploadpack.lazyFetchTrusted`, the code sets `GIT_NO_LAZY_FETCH=0` in the environment, permitting `upload-pack` and its `pack-objects` child to lazily fetch objects as needed.

The patch adds 70 lines of new test coverage in `t/t5710-promisor-remote-capability.sh`, validating four scenarios: (1) lazy fetching succeeds when the repository is trusted, (2) it fails when the repository is not trusted, (3) the configuration is ignored if set in the repository’s own config (not protected), and (4) an explicit `GIT_NO_LAZY_FETCH=1` overrides the trusted setting. The implementation is minimal: it checks whether the environment variable was already set, and if not, relaxes the default `GIT_NO_LAZY_FETCH=1` to `0` when the repository is trusted. The change is confined to `builtin/upload-pack.c` and the documentation files, with no new helper functions or on-disk format changes.

This patch completes the series’ pivot from the earlier client-side `GIT_NO_LAZY_FETCH=fromAccepted` proposal to a server-side trust model, addressing brian m. carlson’s security objection by shifting responsibility to the server operator. The unresolved question remains whether this satisfies the objection’s substance—whether expanding lazy-fetching flexibility at all is acceptable while Git’s network code remains in C. The patch itself is straightforward and well-tested, but the series’ fate hinges on that broader discussion. No review feedback has appeared yet on this patch.
