This is the fifth patch in Toon Claes’s six-patch v2 series that speeds up the experimental `git last-modified` command by reusing Git’s Bloom filters. It teaches `git last-modified` to consult the Bloom filter **before** it starts the per-path diff machinery, exactly the way `git log` already does. The patch adds a 12-line pre-filter in `maybe_changed_path()` that calls either `revs_maybe_changed_in_bloom()` (for the normal case) or `revs_maybe_changed_in_bloom_with_parents()` (when `--show-trees` is given), so commits that definitely did not touch any relevant path are discarded early. A new 21-line test in `t8020-last-modified.sh` verifies that the Bloom-filter fast-path still produces the same results as the slow path when `--show-trees` is used. The change is purely internal to `builtin/last-modified.c` and the test suite; no new public symbols are introduced. The patch is well-motivated by the 3.7× speedup reported in the cover letter and is ready for review.
