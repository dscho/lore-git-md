This is a Google Summer of Code feature patch series (v5, ten patches) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now feature-complete and ready for integration, with all prior review feedback addressed and a new patch from Jeff King (Peff) integrated to improve the transport layer’s design.

The goal is narrowly scoped: object type is the last piece of metadata guaranteed to match between client and server after a fetch, so it is a natural candidate for remote-object-info. The series adds end-to-end support—server capability advertisement, client request logic, protocol extension, and client-side parsing—while explicitly ruling out other metadata (disk size, delta base, object mode) as unreliable or context-dependent. The implementation is mechanical and follows the established pattern from the recently merged predecessor series.

Key changes in v5:
- Patch 6/10 (new) is Peff’s refactoring to remove the `object_info_oids` and `object_info_results` fields from `git_transport_options` and pass them as explicit parameters to `transport_fetch_object_info()`. This clarifies ownership semantics, eliminates a latent bug (dangling pointers if the transport were reused), and prepares the codebase for future enhancements like connection reuse. The change is purely mechanical (25 insertions, 19 deletions) and touches seven files.
- Patch 5/10 now preserves `const` qualifiers on `fetch_object_info()` parameters, matching the original signature.
- The series is rebased onto `master` following the merge of the predecessor series (`ps/cat-file-remote-object-info`).

The first six patches are preparatory: test cleanup, robustness fixes (detecting malformed server responses), refactoring to replace `struct object_info` with a dedicated `struct fetch_object_info_results`, and removing redundant abstractions. Patches 7–10 implement the object type support: server-side parsing and transmission, client-side parsing, capability advertisement, and unifying the default format string. The `*_type` machinery is now introduced in the correct patch (8/10), addressing a forward-compatibility concern raised in v3.

Files touched include `protocol-caps.c`, `fetch-object-info.c`, `serve.c`, `transport.c`, and the man pages for `git-cat-file` and Git protocol v2. Tests in `t5701` and `t1017` are updated to cover the new functionality, including verification of the `%(objecttype)` placeholder and protocol robustness checks. All tests pass, and GitHub CI confirms the series is green.

The series is uncontroversial and merge-ready. Junio and Peff have explicitly endorsed the mechanical refactoring patches (3/10 and 6/10), and all substantive feedback from v4 has been addressed. The architectural design—using a single array of lightweight structs where the caller controls which fields are populated—is now finalized and implemented. No open technical concerns remain.
