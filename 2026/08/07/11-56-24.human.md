This is a build system patch, part of D. Ben Knoble’s three-patch series converting the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). This first patch is a small but useful fix for Meson builds: it exposes a knob (`man_base_url`) that lets distributions control where relative links in manual pages point, matching a long-standing feature in the Makefile-based build.

The issue is straightforward: Meson hard-codes the base URL for relative links in man pages to `$prefix/$mandir`, which is usually wrong for HTML documentation. The result is broken links like `/usr/share/manuser-manual.html` instead of the intended `file:///usr/share/doc/git/user-manual.html`. The patch changes the default to `file://$(htmldir)/` (with a trailing slash) and adds a configurable option so distributions can override it if needed. The change is safe because all current relative links in the documentation point to HTML files, not man pages.

This patch is not directly related to the series’ main goal (runtime nanosecond precision), but the author noticed the broken link while working on the later patches and decided to fix it. It’s a minor improvement that makes Meson builds more consistent with Makefile builds, and it’s unlikely to be controversial. The only open question is whether any distributions actually use this knob today, but the patch doesn’t break anything for those that don’t. If the series advances, this patch is a low-risk, high-value addition.
