This is the third patch in Patrick Steinhardt’s five-part series making Git’s packfile generation pluggable. It converts `git send-pack` to use the new ODB interface introduced in the first two patches, removing another direct dependency on the "files" backend.

The patch replaces the manual `child_process` setup for `git pack-objects` with a declarative call to `odb_generate_pack()`, passing the same options (thin packs, delta base offset, progress meters, shallow clones, bitmap handling) through the new `struct odb_generate_pack_options`. The refactoring is mechanical but touches a critical path: every push operation now delegates packfile generation to the ODB layer. The test suite (`t5516-fetch-push.sh`) is updated to reflect benign changes in argument order and flag naming (`--quiet` instead of `-q`, `--all-progress-implied` dropped when progress is off).

The commit message is clear and the code looks clean, though the series is still early in review. If the ODB abstraction effort is on your radar, this patch is worth watching—it’s the first transport command beyond `upload-pack` to adopt the new interface, and any edge-case regressions (e.g., shallow clone handling, progress meter fidelity) are likely to surface here.
