Subject: [PATCH 0/10] Make ODB fsck checks pluggable
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring, infrastructure)

Core problem or goal
Restructure Git’s object integrity verification (fsck) so that each ODB backend (loose, packed, multi-pack, etc.) can implement its own consistency checks instead of relying on a single monolithic fsck function in `builtin/fsck.c`. This is a pure refactoring with no user-visible behavior change; it prepares the codebase for future pluggable ODB backends (e.g., reftable, alternate storage systems).

Current status
Under review; v1 posted 2026-08-24. Depends on two earlier topics (`ps/odb-eagerly-load-alternates` and `ps/odb-pluggable-pack-generation`) and is based on Junio’s integration branch as of that date.
