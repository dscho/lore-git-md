Subject: [PATCH 0/10] Make ODB fsck checks pluggable
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring, infrastructure)

Core problem or goal
Restructure Git’s object integrity verification (fsck) so that each ODB backend (loose, packed, multi-pack, etc.) can implement its own consistency checks instead of relying on a single monolithic fsck function in `builtin/fsck.c`. This is a pure refactoring with no user-visible behavior change; it prepares the codebase for future pluggable ODB backends (e.g., reftable, alternate storage systems). Patch 4/10 additionally fixes a long-standing discrepancy between the documented and actual behavior of the `--full` flag, ensuring it controls verification of both loose objects and alternates as documented. Patch 6/10 moves packfile verification into the packed ODB backend, eliminating redundancy and simplifying error reporting by replacing the undocumented `ERROR_PACK` bit with the generic `ERROR_OBJECT` bit. Patch 7/10 continues this pattern by moving reverse-index verification into the packed ODB backend and replacing the dedicated `ERROR_PACK_REV_INDEX` bit with `ERROR_OBJECT`. Patch 8/10 moves bitmap verification from `builtin/fsck.c` into `odb/source-packed.c`, replacing the dedicated `ERROR_BITMAP` bit with `ERROR_OBJECT` and extending tests to verify that bitmap checks respect the `--no-full` and `--connectivity-only` flags. Patch 9/10 moves multi-pack index (MIDX) verification from `builtin/fsck.c` into the packed ODB backend, replacing the dedicated `ERROR_MULTI_PACK_INDEX` bit with `ERROR_OBJECT` and ensuring the new implementation respects the `--no-full` and `--connectivity-only` flags. A new test in `t/t5319-multi-pack-index.sh` verifies that MIDX checks are skipped when `--connectivity-only` is passed and are performed when `--no-full` is used. Patch 10/10 completes the refactoring by moving loose-object verification from `builtin/fsck.c` into the loose ODB backend (`odb/source-loose.c`), introducing a new `ODB_FSCK_VERBOSE` flag to preserve the original behavior of printing status messages when `--verbose` is passed. The patch also fixes a latent bug in the progress-meter logic: the old code captured the progress meter in the callback data before it was initialized, causing the meter to jump from 0 to 256 at completion; the new code initializes the meter first, restoring incremental updates.

Key technical details
- Files touched: `builtin/fsck.c`, `odb.h`, `odb/source.h`, `odb/source-files.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, `odb/source-packed.c`, `pack-bitmap.c`, `pack-bitmap.h`, plus test scripts (`t1450-fsck.sh`, `t5319-multi-pack-index.sh`, `t5325-reverse-index.sh`, `t5326-multi-pack-bitmaps.sh`, etc.).
- New or renamed symbols: `fsck_obj_buffer()` (the sole entry point for object verification), backend-specific verification hooks (`odb_source_fsck_fn`), `struct odb_fsck_options`, `ODB_FSCK_FULL` flag, `ODB_FSCK_VERBOSE` flag, `odb_fsck()` helper, progress meter and object callback fields in `struct odb_fsck_options`, `verify_reverse_indices()` (replaces `check_pack_rev_indexes()`), `verify_bitmap_files()` (relocated to `odb/source-packed.c`), `verify_midx()` (spawns `git multi-pack-index verify` as a child process).
- No on-disk format changes; no CLI changes.
- Patch 1/10 replaces 16 lines of open-coded loose-object verification in `builtin/fsck.c` with a single call to `fsck_obj_buffer()`, removing redundancy without altering behavior. Karthik Nayak’s review suggested dropping the word "Almost" from the commit message ("Almost the exact same steps" → "the exact same steps") and noted minor, harmless changes in the patch (moving `free(contents)` and redundant `ERROR_OBJECT` flag-setting). Patrick Steinhardt accepted the wording nit and explained the redundant flag-setting as a defensive measure to avoid calling the function without checking its return value.
- Patch 2/10 merges `fsck_obj_buffer()` and `fsck_obj()` into a single function, eliminating an early return check for the `SEEN` flag that was always cleared by the caller. The merged function unconditionally sets the `SEEN` and `HAS_OBJ` flags and clears `REACHABLE`, preserving prior behavior. Karthik Nayak provided a surface-level review, suggesting a minor wording improvement in the commit message (“early” → “early return”) but did not engage with the patch’s technical content. Patrick Steinhardt has accepted this editorial change.
- Patch 3/10 moves global fsck option variables (`show_root`, `show_tags`, `show_unreachable`, etc.) into the `cmd_fsck()` function, converting them to local variables and relocating the option-parsing array into the function body. This reduces global state and improves code clarity ahead of later patches that will rework option handling for pluggable ODB backends. Karthik Nayak acknowledged the patch’s design rationale, noting that the variables were only used locally and did not need to be global. Feedback was purely observational and did not engage with technical implementation or correctness.
- Patch 4/10 fixes the `--full` flag behavior by ensuring it controls verification of loose objects in addition to alternates, aligning the code with the documentation. The change is minimal (three lines in `builtin/fsck.c`) and adds a regression test in `t/t1450-fsck.sh` to verify the new behavior. Karthik Nayak’s review confirms the patch’s intent and logic, validating that the implementation matches the documented behavior without raising technical concerns or edge cases. In the latest reply, Patrick corrected Karthik’s restatement of the intended behavior from “latter” to “former” to accurately reflect the patch’s logic.
- Patch 5/10 introduces the infrastructure for pluggable fsck checks: a new `fsck` callback in the `struct odb_source` vtable, empty stubs for all existing source types (`files`, `inmemory`, `loose`, `packed`), and the `odb_fsck_options` structure with the `ODB_FSCK_FULL` flag. The patch replaces the old `check_full` boolean with the new options structure and adds the `odb_fsck()` helper, which iterates over all sources and invokes their respective `fsck` callbacks. No behavior changes yet—this is pure scaffolding. Karthik Nayak’s substantive review of this patch raised two technical points: (1) whether `OPT_BIT` provides equivalent `--no-full` functionality to `OPT_BOOL` (it does, via bitwise negation), and (2) whether the new `odb_fsck()` helper will centralize the fsck logic that will later be moved into backend-specific callbacks. The review confirmed the scaffolding "looks good" and that the helper’s iteration over all ODB sources aligns with the patch’s stated goal. The question about `OPT_BIT` has since been resolved by Patrick Steinhardt, who confirmed that the bitwise negation behavior of `OPT_BIT` fully replicates the `--no-full` semantics of `OPT_BOOL`.
- Patch 6/10 moves packfile verification from `builtin/fsck.c` into `odb/source-packed.c`, threading the progress meter and object callback through the new `struct odb_fsck_options` to respect caller preferences without exposing backend details. The patch removes 33 lines from `cmd_fsck()` and adds 46 lines to `odb/source-packed.c`, along with a small addition to `odb.h` to expose the progress flag and callback fields. It also simplifies error reporting by replacing the undocumented `ERROR_PACK` bit (never exercised in the test suite) with the generic `ERROR_OBJECT` bit.
- Patch 7/10 moves reverse-index verification from `builtin/fsck.c` into `odb/source-packed.c`, replacing the `check_pack_rev_indexes()` function (37 lines deleted) with `verify_reverse_indices()` (39 lines added). It drops the dedicated `ERROR_PACK_REV_INDEX` bit in favor of `ERROR_OBJECT`, matching the pattern established in patch 6/10. The new implementation respects the `--connectivity-only` and `--no-full` flags, skipping reverse-index checks when either flag is passed. A new test in `t/t5325-reverse-index.sh` verifies these semantics.
- Patch 8/10 moves bitmap verification from `builtin/fsck.c` into `odb/source-packed.c`, relocating and adapting `verify_bitmap_files()` to operate on a single `odb_source_packed` instance. The patch removes 5 lines from `builtin/fsck.c` and adds 3 lines to `odb/source-packed.c`, with 26 lines changed in `pack-bitmap.c` and an updated function signature in `pack-bitmap.h`. It replaces the dedicated `ERROR_BITMAP` bit with `ERROR_OBJECT` and extends `t/t5326-multi-pack-bitmaps.sh` to verify that bitmap checks respect the `--no-full` and `--connectivity-only` flags. Karthik Nayak’s surface-level review of this patch flagged a single spelling nit ("focussed" → "focused"), which Patrick Steinhardt acknowledged and accepted. The review did not engage with the patch’s technical content, design trade-offs, or edge cases beyond the spelling correction.
- Patch 9/10 moves multi-pack index (MIDX) verification from `builtin/fsck.c` into the packed ODB backend, removing 18 lines from `cmd_fsck()` and adding 27 lines to `odb/source-packed.c`. The new `verify_midx()` helper spawns `git multi-pack-index verify` as a child process, checks the repository’s `core_multi_pack_index` setting, and threads the progress meter flag through the `odb_fsck_options` structure. The dedicated `ERROR_MULTI_PACK_INDEX` bit is replaced with `ERROR_OBJECT`, and the implementation respects the `--no-full` and `--connectivity-only` flags. A new test in `t/t5319-multi-pack-index.sh` verifies these semantics.
- Patch 10/10 moves loose-object verification from `builtin/fsck.c` into `odb/source-loose.c`, removing 90 lines from `cmd_fsck()` and adding 89 lines to `odb/source-loose.c`. The patch introduces the `ODB_FSCK_VERBOSE` flag to preserve the original behavior of printing status messages when `--verbose` is passed. It also fixes a latent bug in the progress-meter logic: the old code captured the progress meter in the callback data before it was initialized, causing the meter to jump from 0 to 256 at completion; the new code initializes the meter first, restoring incremental updates.
