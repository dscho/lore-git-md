Thread identity
Subject: [PATCH 0/10] Make ODB fsck checks pluggable
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring, infrastructure)

Core problem or goal
Restructure Git’s object integrity verification (fsck) so that each ODB backend (loose, packed, multi-pack, etc.) can implement its own consistency checks instead of relying on a single monolithic fsck function in `builtin/fsck.c`. This is a pure refactoring with no user-visible behavior change; it prepares the codebase for future pluggable ODB backends (e.g., reftable, alternate storage systems). Patch 4/10 additionally fixes a long-standing discrepancy between the documented and actual behavior of the `--full` flag, ensuring it controls verification of both loose objects and alternates as documented.

Current status
Under review; v1 posted 2026-08-24. Depends on two earlier topics (`ps/odb-eagerly-load-alternates` and `ps/odb-pluggable-pack-generation`) and is based on Junio’s integration branch as of that date.

Key technical details
- Files touched: `builtin/fsck.c`, `odb.h`, `odb/source.h`, `odb/source-files.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, `odb/source-packed.c`, plus test scripts (`t1450-fsck.sh`, `t5319-multi-pack-index.sh`, etc.).
- New or renamed symbols: `fsck_obj_buffer()` (the sole entry point for object verification), backend-specific verification hooks (`odb_source_fsck_fn`), `struct odb_fsck_options`, `ODB_FSCK_FULL` flag, `odb_fsck()` helper.
- No on-disk format changes; no CLI changes.
- Patch 1/10 replaces 16 lines of open-coded loose-object verification in `builtin/fsck.c` with a single call to `fsck_obj_buffer()`, removing redundancy without altering behavior.
- Patch 2/10 merges `fsck_obj_buffer()` and `fsck_obj()` into a single function, eliminating an early return check for the `SEEN` flag that was always cleared by the caller. The merged function unconditionally sets the `SEEN` and `HAS_OBJ` flags and clears `REACHABLE`, preserving prior behavior.
- Patch 3/10 moves global fsck option variables (`show_root`, `show_tags`, `show_unreachable`, etc.) into the `cmd_fsck()` function, converting them to local variables and relocating the option-parsing array into the function body. This reduces global state and improves code clarity ahead of later patches that will rework option handling for pluggable ODB backends.
- Patch 4/10 fixes the `--full` flag behavior by ensuring it controls verification of loose objects in addition to alternates, aligning the code with the documentation. The change is minimal (three lines in `builtin/fsck.c`) and adds a regression test in `t/t1450-fsck.sh` to verify the new behavior.
- Patch 5/10 introduces the infrastructure for pluggable fsck checks: a new `fsck` callback in the `struct odb_source` vtable, empty stubs for all existing source types (`files`, `inmemory`, `loose`, `packed`), and the `odb_fsck_options` structure with the `ODB_FSCK_FULL` flag. The patch replaces the old `check_full` boolean with the new options structure and adds the `odb_fsck()` helper, which iterates over all sources and invokes their respective `fsck` callbacks. No behavior changes yet—this is pure scaffolding.
