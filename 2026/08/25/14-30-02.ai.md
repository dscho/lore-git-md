This is a cover letter for a 10-patch series from Patrick Steinhardt that makes object database (ODB) consistency checks pluggable. The series is part of the ongoing ODB abstraction effort, restructuring how Git verifies object integrity by moving fsck logic out of `builtin/fsck.c` and into the respective ODB source implementations (loose, packed, multi-pack, etc.).

The goal is to allow different ODB backends to implement their own consistency checks rather than relying on a monolithic fsck function. Key changes include de-globalizing fsck option handling, splitting verification logic into `odb/source-*.c` files, and introducing infrastructure for pluggable checks. The series touches `builtin/fsck.c` heavily (259 lines removed), along with new code in `odb/source-loose.c` and `odb/source-packed.c`. Tests are added to verify the behavior of the new backend-specific checks.

This is a refactoring with no user-visible behavior change, but it lays groundwork for future ODB backends (e.g., reftable, alternate storage systems). The series depends on two earlier topics (`ps/odb-eagerly-load-alternates` and `ps/odb-pluggable-pack-generation`) and is based on Junio’s integration branch as of 2026-08-24.

Files introduced or modified: `odb.h`, `odb/source.h`, `odb/source-files.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, `odb/source-packed.c`, and test scripts (`t1450-fsck.sh`, `t5319-multi-pack-index.sh`, etc.). Key functions: `fsck_obj_buffer()`, `fsck_obj()`, and backend-specific verification hooks. The series does not change the on-disk format or command-line interface.
