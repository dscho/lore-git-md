This is a surface-level review of the fifth patch in brian m. carlson’s six-patch RFC series proposing to restrict Git 3.0 to lowercase-only hex object IDs. The patch itself is a straightforward refactoring: it replaces an open-coded, non-table-driven hex-parsing loop in `object-name.c` with a call to the existing `hexval()` helper, which is already table-driven and constant-time. Junio’s feedback focuses on a subtle behavioral change during the transition period: the original code lower-cased any uppercase hex digits in the output buffer (`hex_out`), while the new code preserves the original case until the breaking change is activated in patch 6. This is not a bug—it is a deliberate API contract change that will only be visible during the transition window—but Junio suggests documenting it in the commit message to avoid surprising callers who might rely on the canonicalization side effect. The review is narrowly scoped to this one detail and does not engage with the broader motivation or design of the series. The patch remains uncontroversial and is likely to be accepted once the commit message is updated.
