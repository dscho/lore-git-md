This is the final patch in the v5 series adding path-related keys to `git repo info`. It implements `path.cdup`, which returns the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root). The patch completes the design symmetry with `path.git-prefix` (added in patch 6/7), addressing the last open design question from earlier iterations.

The implementation is straightforward: `get_path_cdup()` counts slashes in the repository’s `prefix` field and constructs the corresponding `../` sequence. The patch includes tests for both the root and subdirectory cases, and updates the documentation to describe the new key’s behavior. The commit message clearly explains the motivation—scriptability—and the relationship to `git rev-parse --show-cdup`.

This patch is mechanically clean and well-motivated. It resolves the only remaining design objection from v4 (the lack of a `path.cdup` counterpart to `path.git-prefix`) and aligns with Junio’s earlier proposal. The series is now feature-complete and ready for final technical review. Reviewers may still suggest minor naming tweaks (e.g., `path.cdup.relative` for consistency with other keys), but the core functionality is uncontroversial. The patch is a tidy addition that rounds out the series’ goal of exposing repository paths in a scriptable format.
