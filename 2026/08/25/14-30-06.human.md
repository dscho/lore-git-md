This is the fourth patch in Patrick Steinhardt’s 10-patch series refactoring Git’s fsck checks to make them pluggable per ODB backend. The series is part of the larger ODB abstraction effort, preparing for future pluggable backends like reftable.

This patch fixes a behavioral inconsistency in `git fsck --no-full`. The `--full` flag is documented to control whether Git checks objects in alternate object pools, but the code currently ignores this setting for loose objects—it always checks loose objects in all sources, regardless of the flag. The patch makes the code honor the flag for loose objects too: when `--no-full` is given, only the local object source is checked. A new test in `t1450-fsck.sh` verifies the corrected behavior.

The change is small (3 lines in `builtin/fsck.c`, 5 in the test) and purely internal—no user-visible behavior change beyond fixing the documented semantics. It’s a straightforward bugfix that aligns the code with the man page, and the test coverage is appropriate. The patch looks well-crafted and uncontroversial.
