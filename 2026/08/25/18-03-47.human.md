This is a bugfix patch from René Scharfe, the first in a four-part series addressing issues in `git worktree add`. The patch fixes an out-of-bounds read in the `worktree_basename()` helper function, which could lead to data corruption when processing paths of zero length. The fix is straightforward: the code now checks whether `len` is zero before decrementing, preventing the pointer from moving before the start of the string.

The issue was originally reported in the Git for Windows issue tracker (linked in the commit message), and the patch credits Matthias Aßhauer for the initial fix. René’s version simplifies the logic further by replacing a `for` loop with a `while` loop that stops at the first directory separator or the start of the string. The change is minimal—just three lines modified in `builtin/worktree.c`—and the commit message clearly explains both the problem and the solution.

This is a clear correctness fix with no behavioral changes beyond preventing the out-of-bounds access. René’s patches are typically well-tested, and the series includes new tests for edge cases, so this looks like a solid contribution. If you care about `git worktree` stability or have encountered crashes with malformed paths, this patch is worth reviewing. The rest of the series (patches 2–4) builds on this fix to handle trailing slashes and other edge cases more cleanly.
