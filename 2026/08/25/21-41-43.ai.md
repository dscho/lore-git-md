This is a substantive review from Junio C Hamano of the `git whoami` patch. Junio raises two main concerns about the command's design and usability.

First, he questions the necessity of adding yet another subcommand to Git, suggesting the project should avoid "random subcommands" unless absolutely necessary. This echoes brian m. carlson’s earlier skepticism about whether this functionality belongs in Git core at all.

Second, he identifies a confusing inconsistency in how the flags interact. The `--name` (`-n`) and `--email` (`-e`) flags override `--author` (`-a`) and `--committer` (`-c`), but when neither `-n` nor `-e` is specified, `--author` and `--committer` behave independently. This creates a counterintuitive user experience where `-a` and `-c` are not treated as equals despite their parallel documentation. Junio proposes a more additive design where flags combine predictably (e.g., `git ident -a -e -n` would show the full author identity), which would align better with user expectations and Git’s existing command conventions.

The review does not address the technical gaps (e.g., `the_repository` usage, X.509 support) raised by brian m. carlson, but it shifts the discussion toward usability and project scope. The patch’s future likely hinges on whether the author can justify the command’s inclusion in Git core and redesign the flag interactions to be more intuitive.
