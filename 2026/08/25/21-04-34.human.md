This is the third patch in the v8 series improving error messages for ambiguous remote branch names in Git. It targets `git worktree add`, extending the clearer, actionable advice introduced in earlier patches to this command.

When `git worktree add` is run with a branch name that exists in multiple remotes (e.g., `git worktree add ../foo-dir bar-topic`), the command previously failed with a generic "invalid reference" error after silently giving up on resolving the ambiguity. This patch replaces that opaque failure with a detailed error message and advice, including the number of matching remotes (e.g., "matched multiple (2) remote tracking branches") and a static list of conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes:"). The advice suggests using `--track` or setting `checkout.defaultRemote` to disambiguate in the future.

The implementation reuses the shared `advise_disambiguating_remotes()` helper introduced in patch 1/4, avoiding code duplication. The advice is gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and is only shown if the user hasn’t suppressed it with `--quiet`. The patch also moves the `die()` call earlier in the code path, replacing the misleading "invalid reference" message with a more specific diagnostic that explains the ambiguity.

Test coverage is updated to verify the new error message format and advice output. The patch looks well-crafted, with a clear commit message that traces the problematic flow (silent failure to resolve ambiguity -> misleading error) and justifies the early `die()` as intentional. This aligns `git worktree add` with the behavior already implemented for `git checkout` and `git switch` in earlier patches.

The series is now functionally complete, with this patch covering the last of the three commands.
