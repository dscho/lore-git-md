This is patch 4/8 in Patrick Steinhardt’s ODB alternates refactoring series, targeting the `builtin/clone.c` file. The patch moves the logic for setting up alternates during shared local clones (`git clone --shared`) from `clone_local()` into the newly refactored `collect_alternates()` function. This change unifies alternate handling and prepares for writing alternates at ODB creation time, a key goal of the series.

The patch adds two new parameters to `collect_alternates()`: `src_repo` (the source repository path) and `is_local` (a boolean indicating whether the clone is local). The logic for shared local clones is now handled inside `collect_alternates()`, where it checks `option_shared` and pushes the source repository’s objects directory into the `alternates` strvec. The call to `collect_alternates()` in `cmd_clone()` is updated to pass these new parameters, and the redundant alternate setup in `clone_local()` is removed.

This is a mechanical refactoring with no behavior changes. The patch is well-motivated by the series’ goal of consolidating alternates handling, and the changes are straightforward. Reviewers will likely focus on ensuring the new parameter passing doesn’t introduce edge cases, particularly in scenarios involving `insteadOf` URI rewriting or required/optional alternates. The patch is uncontroversial and aligns with the broader ODB abstraction effort.
