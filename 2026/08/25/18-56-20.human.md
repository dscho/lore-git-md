This is the sixth patch in Derrick Stolee’s seven-part series hardening the trace2 subsystem against crashes caused by `die()`-triggering helpers. The patch removes `ALLOC_GROW()` from the trace2 thread-local storage (TLS) code, replacing it with a manual reallocation strategy that avoids process termination under memory pressure.

The change targets the nested region stack in `tr2tls_push_self()`, which tracks timing data for nested trace2 regions. Instead of using `ALLOC_GROW()`—which calls `die()` on failure—the patch introduces a `nr_skipped_regions` counter to track how many regions were entered but not recorded due to allocation failures. When memory runs out, the code increments this counter and skips recording the region, allowing the process to continue with degraded telemetry rather than crashing. The counter is decremented in `tr2tls_pop_self()`, and `tr2tls_region_elasped_self()` returns `0` for skipped regions to avoid incorrect timing data.

The patch updates `banned-die.h` to block `ALLOC_GROW()` and adds the new `nr_skipped_regions` field to `struct tr2tls_thread_ctx`. The implementation is careful to check for integer overflow before reallocation and uses `realloc()` directly, with fallbacks to skip recording if the allocation fails. This preserves the existing behavior for successful allocations while gracefully handling failures.

Like the rest of the series, this patch prioritizes process stability over telemetry completeness. The trade-off is that trace consumers may see missing or zeroed timing data under memory pressure, but this is intentional and documented. The commit message clearly explains the motivation and the defensive strategy, making the change easy to review.

This looks like a well-crafted fix that fits neatly into the series’ broader goal. The only potential concern is whether the `nr_skipped_regions` counter could itself become a source of confusion for trace consumers, but the patch handles this by ensuring skipped regions don’t corrupt timing data (they return `0`).
