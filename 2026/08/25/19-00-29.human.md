This is the final patch in a four-part bugfix series addressing a critical race condition in Git's geometric repacking mechanism. The issue causes objects to be incorrectly reported as missing when a multi-pack-index (MIDX) references a packfile that has been removed by a concurrent repack, leading to crashes in `git replay` and failures in other server-side operations like `git merge-tree`, `git diff`, and object resolution commands.

The patch introduces a targeted recovery mechanism in `find_pack_entry()` to handle cases where the MIDX routes an object lookup to a removed pack. The core change is a tri-state return value from `fill_midx_entry()` (`MIDX_FILL_MISS`, `MIDX_FILL_HIT`, `MIDX_FILL_OWNER_UNAVAILABLE`), which distinguishes between objects absent from the MIDX, those present but with an unavailable owning pack, and successful lookups. When the owning pack is missing (`MIDX_FILL_OWNER_UNAVAILABLE`), the recovery logic scans all MIDX-covered packs for a surviving copy—but only during the second read (`OBJECT_INFO_SECOND_READ`). This ensures objects relocated into new (non-covered) packs are found by the regular fallback, while genuine hidden duplicates are recovered transparently.

The fix is well-motivated by production evidence and includes thorough test coverage. The new tests simulate both the `git replay` crash scenario and MIDX-packfile mismatches, including a test for repeated `QUICK` lookups that verifies the recovery logic works even when the owning pack is removed. The patch also ensures the `stale_packs_detected` flag (introduced in patch 3/4) is re-armed on every lookup of a vanished pack, preventing `QUICK` readers from skipping the recovering second read.

The discussion around this series has converged, with no remaining technical objections. The design adopts feedback from Jeff King (Peff) and Patrick Steinhardt, and the series is now rebased on `ps/odb-generic-corrupt-objects`. This is a high-quality, focused fix that should be a priority for merging. Derrick Stolee's suggestion to defer pack deletion via `git multi-pack-index expire` is acknowledged as a complementary mitigation but is not part of this series.
