This is the sixth and final patch in brian m. carlson’s RFC series proposing a Git 3.0 breaking change: enforcing lowercase-only hex object IDs. Junio C Hamano’s reply focuses narrowly on the test adjustment in `t5324-split-commit-graph.sh`, where brian changed the corruption character from uppercase `"A"` to lowercase `"a"` (first hunk) and `"b"` (second hunk).

Junio finds the change puzzling and hard to follow. The test corrupts two positions in a commit-graph chain file: position 30 (unchanged in effect, since `"a"` and `"A"` are both invalid in SHA-1 mode) and position 70 (where `"A"` is invalid in SHA-1 but coincidentally valid in SHA-256 because the correct character happens to be `"a"`). The second hunk’s change to `"b"` ensures the test fails as intended in both hash modes, but Junio questions why the original used `"A"` at all if the goal was to test corruption—since `"A"` could be a valid character in some modes, it doesn’t reliably simulate corruption.

The review is surface-level, addressing only the test’s clarity and correctness, not the series’ broader design or motivation. Junio’s confusion suggests the test adjustment could be better explained in the commit message or code comment. This is a minor nit in an otherwise complete series; the patch itself is ready, but the test’s rationale needs clarification before integration.
