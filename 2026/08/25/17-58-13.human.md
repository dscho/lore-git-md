This is the second patch in the v5 series adding path-related keys to `git repo info`. It implements `path.superproject-root.absolute` and `path.superproject-root.relative`, which expose the top-level working tree of a superproject when the current repository is a submodule. The keys return an empty string when not inside a submodule, matching the behavior of other path keys in the series.

The implementation reuses Git’s existing `get_superproject_working_tree()` function and the `format_path()` helper introduced in the first patch. The absolute variant returns a canonical path (resolved symlinks, no `.` or `..`), while the relative variant returns the path from the current directory, including a trailing slash. Tests cover both submodule and non-submodule cases, verifying absolute path resolution with `test-tool path-utils real_path` and relative path formatting.

The commit message is clear and explains the motivation: scripts in multi-repository setups often need to locate the superproject root, and this key provides a scriptable alternative to `git rev-parse --show-superproject-working-tree`. The patch is mechanically clean, with no obvious edge cases left untested. The naming (`superproject-root`) aligns with the rest of the series and was suggested by Justin Tobler in earlier feedback.

This patch is uncontroversial and fits neatly into the series’ goal of exposing repository paths in a consistent, scriptable format. The only potential discussion point is whether the key name should match `git rev-parse --show-superproject-working-tree` more closely (e.g., `path.superproject-working-tree`), but the current name is concise and has already been adopted in the series. The patch is ready for final review.
