This is the second patch in Derrick Stolee’s seven-part **bugfix and hardening series** for the trace2 subsystem, targeting the specific crash caused by `xsnprintf()` failures in timestamp formatting. The patch replaces all uses of `xsnprintf()` in `trace2/tr2_tbuf.c` with `snprintf()` and adds defensive fallbacks to prevent `die()` calls when formatting fails—whether due to memory allocation errors (as seen on Git for Windows) or other system call failures.

The changes are surgical and self-contained: the three timestamp-formatting functions (`tr2_tbuf_local_time()`, `tr2_tbuf_utc_datetime_extended()`, and `tr2_tbuf_utc_datetime()`) now initialize their `timeval` and `tm` structs to zero, use `snprintf()` instead of `xsnprintf()`, and fall back to hardcoded timestamps (e.g., `"1900-00-00T00:00:00.000000Z"`) if formatting fails. This ensures trace2 never crashes, even under memory pressure, though trace consumers may now see malformed or placeholder timestamps under failure conditions. The patch also updates `banned-die.h` to block `xsnprintf()` in trace2 code, enforcing the constraint introduced in the series’ first patch.

The commit message is thorough, explaining the root cause (allocation failures in `libintl_vsnprintf()` on Git for Windows), the recursive crash loop triggered by `die()` during `atexit` events, and the rationale for defensive fallbacks. No test coverage is included, as the issue depends on transient system failures, but the fallback values are intentionally "obviously wrong" to signal problems to trace consumers. This patch directly addresses the original crash while aligning with the series’ broader goal of eliminating all `die()`-triggering helpers from trace2. The changes are minimal and focused, making review straightforward.
