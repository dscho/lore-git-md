This is the cover letter for an eight-patch series from Patrick Steinhardt that refactors how Git handles alternates in the object database (ODB). The series is part of the ongoing ODB abstraction effort, specifically aiming to move alternates handling into the "files" backend.

The core change is straightforward: instead of writing alternates ad-hoc via `odb_source_write_alternate()` at arbitrary points, the series introduces a new option to `odb_source_create_on_disk()` so alternates are configured at creation time. This simplifies the API (removing the need for a `write_alternates()` callback) and gives backends more control over how alternates are set up. The motivation is sound—alternates are currently only written when creating a new repository anyway, and future backends may not support them at all.

The series touches `builtin/clone.c` heavily (patches 1-7) to defer ODB setup, refactor reference handling, and move alternates configuration into the new creation-time flow. Patch 6 introduces the new ODB creation option, and patch 8 removes the now-unused `write_alternates()` functionality. The changes are mechanical but invasive, spanning 11 files with a net reduction of 30 lines.

This is well-aligned with Patrick’s broader ODB work and looks like a clean architectural improvement. The commit messages are detailed, and the series builds on recent ODB changes (like `ps/odb-eagerly-load-alternates`). If you care about the ODB abstraction or `git clone` internals, this is worth following. The new test in `t/t5604-clone-reference.sh` suggests edge cases are being covered.
