Core problem or goal
Fix the `worktree_basename()` helper in `git worktree add` to prevent data corruption (out-of-bounds read), reject malformed paths (including paths consisting solely of separators), handle trailing slashes consistently, and simplify the code by returning a string copy. The series supersedes an earlier stalled effort (linked in the cover letter) and addresses a real-world issue reported in Git for Windows (issue #6346).

Current status
Under review; no prior version of this series exists. Four patches posted, targeting `builtin/worktree.c` and adding tests in `t/t2400-worktree-add.sh`. The first three patches (out-of-bounds read fix, separator-only path rejection, and trailing-slash trimming) address the most critical issues (corruption, BUG assertion, and invalid branch names), while the fourth patch simplifies memory management.

Key technical details
- Files: `builtin/worktree.c`, `t/t2400-worktree-add.sh`
- Symbols: `worktree_basename()`
- Behavior changes:
  • Patch 1: fixes out-of-bounds read by adding a bounds check before pointer decrement, preventing corruption; simplifies loop logic by removing redundant `name++` adjustment. Root cause attributed to Matthias Aßhauer (Git for Windows issue #6346).
  • Patch 2: rejects paths consisting solely of one or more separators (e.g., `"/"` or `"//"`) with the error message `"invalid path '<path>'"`; previously, such paths would trigger a BUG assertion when `sanitize_refname_component()` returned an empty string.
  • Patch 3: trims trailing slashes from derived branch names by calculating the true basename length and using `xmemdupz()` to extract only the relevant portion. Adds two new tests in `t/t2400-worktree-add.sh` covering default and `--orphan` modes to verify the fix.
  • Patch 4: returns a string copy, simplifying memory management (not yet summarized)
- Test coverage: new tests in `t/t2400-worktree-add.sh` for edge cases (trailing slashes, separator-only paths, e.g., `git worktree add "" HEAD` fails as expected)
