Subject: [PATCH 0/4] worktree add: fix basename handling
Series version: v1 (initial)
Originating author: René Scharfe
Thread type: patch series

Core problem or goal
Fix the `worktree_basename()` helper in `git worktree add` to prevent data corruption (out-of-bounds read), reject malformed paths (including paths consisting solely of separators), handle trailing slashes consistently, and simplify the code by returning a string copy. The series supersedes an earlier stalled effort (linked in the cover letter) and addresses a real-world issue reported in Git for Windows (issue #6346).

Current status
Under review; no prior version of this series exists. Four patches posted, targeting `builtin/worktree.c` and adding tests in `t/t2400-worktree-add.sh`. The series is effectively ready to advance pending a minor commit-message tweak in Patch 4. Junio C Hamano has reviewed all patches and signaled approval ("OK") for the code changes; his only request is a clarification in the commit message of Patch 4 to avoid ambiguity about whether callers already free the returned string.

Key technical details
- Files: `builtin/worktree.c`, `t/t2400-worktree-add.sh`
- Symbols: `worktree_basename()` (renamed to `worktree_basename_dup()` in Patch 4)
- Behavior changes:
  • Patch 1: fixes out-of-bounds read by adding a bounds check before pointer decrement, preventing corruption; simplifies loop logic by removing redundant `name++` adjustment. Root cause attributed to Matthias Aßhauer (Git for Windows issue #6346).
  • Patch 2: rejects paths consisting solely of one or more separators (e.g., `"/"` or `"//"`) with the error message `"invalid path '<path>'"`; previously, such paths would trigger a BUG assertion when `sanitize_refname_component()` returned an empty string.
  • Patch 3: trims trailing slashes from derived branch names by calculating the true basename length and using `xmemdupz()` to extract only the relevant portion. Adds two new tests in `t/t2400-worktree-add.sh` covering default and `--orphan` modes to verify the fix. Junio C Hamano confirmed the user-visible symptom: `git worktree add waffle/bit/` previously attempted to create a branch named `bit/` (invalid due to trailing slash), which now works correctly.
  • Patch 4: renames `worktree_basename()` to `worktree_basename_dup()` and makes it return a freshly allocated string copy instead of a pointer into the input buffer. This eliminates the need for callers to perform pointer arithmetic and manually copy the basename, simplifying memory management. Three call sites are updated to use the new helper. The commit message has been clarified to state that two callers already make their own copies of the returned string, making their conversion to `worktree_basename_dup()` straightforward.
- Test coverage: new tests in `t/t2400-worktree-add.sh` for edge cases (trailing slashes, separator-only paths, e.g., `git worktree add "" HEAD` fails as expected)
