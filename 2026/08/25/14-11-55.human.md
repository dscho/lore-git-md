This is the sixth patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort, which aims to give backends more control over their configuration by making alternates an implementation detail.

This patch adds support for writing alternates when creating the object database, a key step toward removing the `write_alternates()` callback in a later patch. The change modifies the `odb_source_files_create_on_disk()` function in `odb/source-files.c` to accept a new `odb_create_on_disk_options` struct, which includes a `strvec` of alternates to write. The function now reads any existing alternates file to avoid duplicates, appends the new alternates, and ensures the ODB is reprepared to activate them. The patch also updates `setup.c` to pass an empty options struct to `odb_source_create_on_disk()`, maintaining backward compatibility for now.

The implementation is careful to handle edge cases, such as preexisting alternates files (e.g., from template directories) and error conditions during file operations. The use of `strset` to track seen alternates ensures no duplicates are written, and the code properly cleans up resources in error paths. The patch is well-motivated and aligns with the series’ goal of simplifying the ODB interface by consolidating alternates handling into the creation step.

This is a foundational change for the series, and while it doesn’t introduce user-visible behavior, it sets the stage for removing the `write_alternates()` callback entirely. The patch looks clean and addresses the technical requirements without introducing unnecessary complexity. Reviewers will likely focus on ensuring the alternates file handling is robust, particularly in error scenarios, and that the repreparation step doesn’t introduce regressions. The next patches in the series are expected to build on this work by removing the now-redundant callback.
