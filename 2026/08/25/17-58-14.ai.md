This is the third patch in the v5 series adding path-related keys to `git repo info`. It implements `path.hooks.absolute` and `path.hooks.relative`, exposing the repository’s hooks directory in a scriptable format while respecting the `core.hooksPath` configuration. The patch touches `builtin/repo.c` (adding two new getter functions), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding tests for standard hooks, custom hooks, and `/dev/null` handling).

The implementation reuses `repo_git_path_replace()` and `format_path()` to ensure consistency with existing path keys. The absolute variant returns a canonical path, while the relative variant computes the path from the current directory. Both keys respect `core.hooksPath` and explicitly document that `/dev/null` is returned verbatim when configured as such, matching `git rev-parse --git-path hooks` behavior. Tests cover edge cases like `/dev/null` (non-Windows platforms only) and custom hooks paths, including path resolution without prepending the repository root.

The patch is mechanically clean and aligns with the series’ design principles: it avoids special-casing `/dev/null` to return an empty string, instead documenting the behavior and locking it in with tests. The naming (`path.hooks`) and suffix semantics (`.absolute`/`.relative`) follow the established pattern from earlier patches. No substantive design questions remain for this patch; the only open discussion points for the series are minor naming adjustments (e.g., `path.hookdir` vs. `path.hooks`) and the unconditional path-return behavior, which has been endorsed by Junio for consistency with `git rev-parse --git-path`.
