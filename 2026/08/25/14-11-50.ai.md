This is the first patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation. It defers initialization of the object database in `git clone` to a later point, after the clone source URI has been fully resolved.

The patch introduces a new `INIT_DB_SKIP_ODB` flag to `init_db()`, which tells the function to skip creating the object database. The `create_object_database()` function is made public and called later in `cmd_clone()`, after the URI is resolved and any alternates (via `--reference` or `--reference-if-able`) are known. This change is a prerequisite for the later patches in the series, which will move alternates writing into the ODB creation step.

The motivation is twofold: first, to future-proof the code for alternate ODB backends that may need to know the object hash at creation time, and second, to ensure the clone source URI is fully resolved (including any `insteadOf` rewrites) before writing alternates. The patch is mechanical and does not change user-visible behavior, but it lays the groundwork for the more substantial refactoring in subsequent patches.

Files touched are `builtin/clone.c`, `setup.c`, and `setup.h`. The changes are confined to repository initialization logic and are unlikely to introduce regressions, though reviewers will want to verify that the deferred ODB creation doesn’t break any edge cases in clone behavior. This patch is a clear step toward the series’ goal of simplifying the ODB interface by moving alternates handling into the backend.
