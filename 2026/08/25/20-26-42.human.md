This is a follow-up in the `git am --3way` bugfix thread. Nikita Leshenko responds to Junio C Hamano’s performance objection with a counterproposal that trades some efficiency for simplicity. Instead of Junio’s “lazy reconstruction” (which would surgically apply only the patches needed to build the missing preimage blob), Nikita suggests a simpler but heavier approach: whenever `build_fake_ancestor()` fails, apply *all* already-applied patches (1..N-1) on their fake ancestors to ensure the missing blob exists. A new field in `am_state` (`postimage-attempted`) would track how far this blanket reconstruction has already been done, so subsequent patches only re-apply the minimal suffix of the chain. The clean-apply path remains untouched, and the extra work happens only when a patch would otherwise fail. Nikita acknowledges the trade-off—more blobs written than strictly necessary—but argues the complexity of Junio’s original suggestion isn’t justified for what he calls a “niche” edge case. The ball is back in Junio’s court to decide whether this simpler design is acceptable or if the lazy approach is still required.
