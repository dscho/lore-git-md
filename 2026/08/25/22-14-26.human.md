This is a **surface-level review** of the first patch in Derrick Stolee’s seven-part bugfix and hardening series for the trace2 subsystem. Elijah Newren points out two minor but important technical issues in the new `banned-die.h` header.

First, he notes that the patch uses `banned(die)` instead of `BANNED(die)`, which would deviate from the project’s existing convention (used elsewhere in the codebase) and could trigger a less helpful compiler warning about an implicit function declaration. The fix is trivial: uppercase the macro name to match the established pattern and ensure the intended error message (`sorry_die_is_a_banned_function`) appears.

Second, Elijah raises a subtle ordering risk: if `banned-die.h` is included in the middle of a file’s include list, any later includes could pull in functions that are later added to the banned list, but those functions would not be blocked because the header has already been processed. This could silently undermine the enforcement mechanism. The suggestion is to ensure `banned-die.h` is always the last include in any file that uses it, or to document this requirement clearly.

Neither issue questions the overall goal or design of the series — both are mechanical fixes that strengthen the enforcement mechanism without changing its intent. The review is narrowly focused on correctness and consistency, and the feedback is actionable and precise. No substantive concerns about the hardening effort itself are raised.
