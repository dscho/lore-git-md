This is a two-patch feature series that changes `git branch -d` to protect local branches that are upstream dependencies of other branches. The goal is to prevent accidental deletion of a branch when another branch still depends on it through a local upstream chain.

The series starts with a refactoring patch ("branch: move stacked branch helpers") that reorganizes helper functions in `builtin/branch.c` to prepare for the behavioral change. The second patch ("branch: protect local upstreams from -d") implements the core logic: when `git branch -d` is run, Git now checks whether the branch being deleted is the upstream of any other local branch, and if so, refuses to delete it unless `-D` (force) is used.

The commit message and cover letter are clear about the motivation: protecting users from accidentally breaking their branch topology. The implementation touches `builtin/branch.c` and updates documentation (`git-branch.adoc`) and tests (`t3200-branch.sh`, `t1507-rev-parse-upstream.sh`, `t6040-tracking-info.sh`). The new behavior is tested in `t3200-branch.sh` with a dedicated test case.

This is a user-facing change that affects a common workflow (`git branch -d`). The protection only applies to local branches; remote-tracking branches are not considered. The series does not introduce new options or config keys, but it does change the semantics of an existing command flag (`-d`). The change is backward-incompatible in the sense that some deletions that previously succeeded will now fail, but the failure mode is safe (requiring `-D` to override).

The patch is well-structured: the refactoring is separated from the behavioral change, and the tests cover the new edge case. The commit messages are descriptive, and the cover letter states the goal upfront. This looks like a thoughtful, well-motivated feature that addresses a real usability pain point.
