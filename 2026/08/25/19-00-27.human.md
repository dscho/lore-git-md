This is a small but well-targeted bugfix patch, the second in Elijah Newren’s four-patch series that fixes a race condition in Git’s geometric repacking mechanism. The patch plugs a memory leak in `git mktree --batch` mode: when processing multiple trees, the command reuses its entry buffer but never frees the `treeent` structures from the previous tree, causing those allocations to be lost once the buffer is overwritten. The fix is straightforward—free each entry when resetting the buffer and free the buffer itself before returning—and is uncontroversial.

The leak is minor (it only manifests in batch mode and the memory is reclaimed at process exit), but fixing it is necessary because the new test cases in the series rely on `git mktree --batch` to simulate the race condition. The patch touches only `builtin/mktree.c` and adds three lines of cleanup code, making it a clean, low-risk change. Junio has already reviewed the series and there are no open technical objections, so this patch is ready to be merged alongside the rest of the series.
