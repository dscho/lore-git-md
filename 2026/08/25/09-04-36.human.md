This is a review comment on the final patch of brian m. carlson’s RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. The series as a whole is now complete and under active discussion, with Junio C Hamano signaling tentative acceptance ("Will queue") but the broader community still debating whether the change is justified.

Phillip Wood’s question is substantive and directly targets the core motivation of the series. He asks for concrete examples of the security problems caused by Git’s current case-insensitive parsing of object IDs, noting that while `abcdef^0` and `ABCDEF^0` resolve to the same object, the former is not considered a security risk. His question is not a nitpick—it challenges the premise that uppercase hex is inherently dangerous, and his tone is constructive, seeking clarification rather than dismissal.

The question is timely and relevant. The thread has so far focused on philosophical arguments (Robustness Principle, ecosystem compatibility) and implementation details (micro-optimizations, derived hashes), but Phillip’s request for concrete security examples cuts to the heart of the matter: if the change is to be justified as a security improvement, the threat model needs to be explicit. His question is likely to resonate with other contributors who are on the fence about the breaking change, and brian’s response (or lack thereof) will be critical in determining whether the series gains broader support.

The patch itself is minimal and uncontroversial—it flips the switch on the infrastructure introduced in earlier patches, documents the change, and adds test coverage. The real debate is whether the project wants this breaking change at all, and Phillip’s question is a key part of that discussion. If brian can provide compelling examples of real-world security vulnerabilities caused by Git’s current behavior, it will strengthen the case for the change; if not, it may weaken the justification and push the project toward Junio’s proposed compromise (normalizing inputs internally while accepting mixed-case externally). Either way, this exchange is a pivotal moment in the thread.
