This is the first patch in a seven-part bugfix and hardening series targeting the trace2 subsystem. It introduces `banned-die.h`, a new header that systematically blocks functions capable of terminating the Git process (starting with `die()` itself) from being used in trace2 code. The patch adds this header to every trace2 implementation file, laying the groundwork for the rest of the series, which will replace all `die()`-triggering helpers (like `xsnprintf()`, `xstrdup()`, and `ALLOC_ARRAY()`) with defensive fallbacks.

The motivation is clear: trace2 is a low-level telemetry layer that runs during `atexit()` handlers, and any call to `die()` here can trigger infinite recursion in the die handler, crashing Git. The commit message ties this directly to the earlier crash on Git for Windows, where `xsnprintf()` failures in trace2 timestamp formatting were traced to `libintl_vsnprintf()` memory allocations. While this patch only bans `die()` (which trace2 already avoids), it establishes a centralized enforcement mechanism that the rest of the series will expand to cover other problematic functions.

The implementation is straightforward: `banned-die.h` includes `banned.h` (Git’s existing banned-function infrastructure) and redefines `die` as a banned function. The patch then adds `#include "banned-die.h"` to all 13 trace2 `.c` files. The choice to place this header at the root of the tree (rather than in `trace2/`) suggests Derrick envisions this pattern being adopted by other subsystems in the future, though for now it’s scoped entirely to trace2.

This patch is purely preparatory—it doesn’t change any behavior on its own—but it’s a critical architectural step. The commit message is concise but explains the "why" well, and the mechanical nature of the changes (adding a single include line to each file) makes it easy to review. No objections are expected here, as this aligns with the thread’s earlier agreement to harden trace2 against `die()`-triggering functions. The real discussion will likely center on the follow-up patches, which implement the actual fallbacks.
