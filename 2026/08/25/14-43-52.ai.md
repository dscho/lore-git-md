This is a follow-up in the ongoing RFC thread about making Git's stash stack configurable or branch-aware. Phillip Wood responds to Junio C Hamano's refinement of the branch-aware stash design, clarifying how stash messages are already structured in the current implementation.

Phillip points out that Git already encodes branch information in stash messages: when a user supplies a custom message via `-m`, the code prepends `"On $branch: "`; when no message is supplied, it uses `"WIP on $branch ..."`. This means the branch name is already machine-readable at the start of the message, not buried in the middle or end. The current structure avoids the parsing ambiguity Junio raised (e.g., colons in user messages) and suggests that extending this pattern for branch-aware operations would be straightforward.

The observation is substantive: it removes a technical obstacle to Junio’s proposed design and shifts the discussion toward how to *use* the existing metadata (e.g., adding a `--current-branch` flag to `git stash pop`) rather than how to encode it. No new alternatives or objections are introduced; the thread remains focused on refining the branch-aware approach. The original `stash.ref` config knob proposal is now effectively superseded unless the branch-based design hits unforeseen snags.
