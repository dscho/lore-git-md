This is the sixth patch in the v5 series adding path-related keys to `git repo info`. It implements `path.git-prefix`, which returns the relative path from the repository’s working tree root to the current directory, including a trailing slash. At the root, it returns an empty string.

The patch is straightforward: it adds a new getter function (`get_path_git_prefix`) that reads `repo->prefix` (which is NULL at the root), wires it into the key table, documents the behavior, and tests both the root and subdirectory cases. The implementation reuses Git’s existing `repo->prefix` field, so there is no new logic or edge-case handling beyond what Git already does.

This key was the subject of a design debate in earlier iterations: Lucas Seiki Oshiro argued it represented “current directory information” rather than “repository information,” but Junio C Hamano rejected that objection, analogizing it to `git rev-parse --show-cdup` and `path.commondir.relative`. The debate is now settled; this patch simply carries out the agreed design. The addition of `path.cdup` (the inverse) in the seventh patch completes the symmetry.

The patch is mechanically clean, well-tested, and ready for final review. Any remaining discussion is likely to focus on minor naming or documentation tweaks rather than the core functionality.
