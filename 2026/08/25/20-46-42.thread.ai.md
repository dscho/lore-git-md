Thread identity: new thread introducing `git whoami`, a built-in command to display the current Git identity (author/committer names/emails) and signing configuration (GPG/SSH key, `commit.gpgsign` status). Originating author: Andrew Pleeter (via GitGitGadget). Thread type: patch series (single patch, now v1 under review).

Core problem or goal: provide a single, user-friendly command to consolidate Git’s identity and signing configuration, which currently requires checking multiple `git config` or `git var` settings. The command is designed for both interactive use and scripting, with flags to query specific fields (`--author`, `--committer`, `--name`, `--email`, `--signing-key`, `--verbose`).

Current status: initial version (`v1`) posted; under active review with no merge status (still in `seen` or earlier). The patch’s inclusion in Git core is now contested, with maintainer-level skepticism about its necessity and usability.

Key technical details:
- New built-in command: `git whoami`, implemented in `builtin/whoami.c`.
- Files touched: `builtin/whoami.c`, `Documentation/git-whoami.adoc`, `t/t0015-whoami.sh`, build system files (Makefile, meson.build), `command-list.txt` (classified as `ancillaryinterrogators`).
- New symbols: `cmd_whoami()` (entry point), supporting functions in `whoami.c`.
- Behavior: displays author/committer names/emails and signing configuration (GPG/SSH key, `commit.gpgsign` status). Supports targeted querying via flags. Works outside of a repository.
- Test coverage: comprehensive, including environment variable overrides, incompatible flag combinations, and signing key resolution.
- No on-disk format changes or new configuration options.
- **New requirements**: must support machine-readable output (e.g., `key=value` pairs) and NUL-terminated output (`-z`) for scripting (brian m. carlson), avoid `the_repository` (ongoing removal effort), support X.509 signing keys, and redesign flag interactions to be additive and predictable (Junio).

Open questions and loose ends:
- **Project scope**: whether this functionality belongs in Git core (raised by brian m. carlson and now echoed by Junio). The commit message must justify why this isn’t better served by `git var` or a third-party script.
- **Flag design**: Junio’s critique of the current `--author`/`-a`, `--committer`/`-c`, `--name`/`-n`, and `--email`/`-e` interactions as counterintuitive. The flags must be redesigned to combine additively (e.g., `-a -e -n` shows full author identity) rather than overriding each other.
- **Technical gaps**: `the_repository` usage, missing X.509 signing key support, and lack of machine-readable/NUL-terminated output remain unresolved.
