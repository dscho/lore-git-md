Thread identity: patch series introducing a unified identity and signing configuration command, originally proposed as `git whoami` v1, redesigned as `git ident` v2, and now under discussion as an extension to `git var`. Originating author: Andrew Pleeter (via GitGitGadget). Thread type: patch series (v2) transitioning to design discussion.

Core problem or goal: provide a unified, user-friendly command to consolidate Git’s identity (author/committer names/emails) and signing configuration (GPG/SSH/X.509 keys, `commit.gpgsign` status), which currently requires checking multiple `git config` or `git var` settings. The solution must support both interactive use and scripting, with composable flags and machine-readable output. The discussion has shifted to whether this functionality should be implemented as a standalone command (`git ident`) or as an extension to the existing `git var` command.

Current status: v2 of the `git ident` series was posted, addressing all prior maintainer-level critiques (command renamed to `git ident`, additive/composable flags, machine-readable/NUL-terminated output, removal of `the_repository` usage, and support for X.509 signing keys). However, **Jeff King (Peff) proposed an alternative design** extending `git var` instead of introducing a new command, arguing that `git var` could be enhanced to support all `git ident` functionality (including NUL-terminated output and signing-key resolution) while avoiding command proliferation. **Junio C Hamano has endorsed Peff’s proposal**, signaling consensus among maintainers that extending `git var` is the preferred path. The thread remains under review, with no merge status reported; the next step is for Andrew Pleeter to adapt the series to extend `git var` or provide a rationale for a standalone command.

Key technical details:
- **Proposed new built-in command**: `git ident`, implemented in `builtin/ident.c` (v2).
- **Files touched in v2**: `builtin/ident.c`, `Documentation/git-ident.adoc`, `t/t0015-ident.sh`, build system files (Makefile, meson.build), `command-list.txt` (classified as `ancillaryinterrogators`), `builtin.h`.

- **Behavior in v2**: displays author/committer names/emails and signing configuration (GPG/SSH/X.509 keys, `commit.gpgsign` status). Flags are additive (e.g., `-a -e -n` shows full author identity) and work outside of a repository. Supports `--porcelain` (machine-readable) and `-z` (NUL-terminated) output for scripting.
- **Test coverage in v2**: comprehensive, including environment variable overrides, incompatible flag combinations, and signing key resolution.
- **No on-disk format changes or new configuration options** in either proposal.
- **Resolved requirements from v1**: machine-readable/NUL-terminated output (brian m. carlson), removal of `the_repository`, support for X.509 signing keys, and additive flag design (Junio).
- **Peff’s `git var` extension proposal**: would add new keys (e.g., `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_SIGNING_KEY`) and general improvements (NUL-terminated output, multi-value support) to `git var`, making it a superset of `git ident`’s functionality. This would require refactoring `git var` to support the new features while maintaining backwards compatibility.

Open questions and loose ends:
- **Implementation path**: whether to proceed with extending `git var` (as endorsed by Junio and Peff) or to argue for a standalone `git ident` command. The burden is now on Andrew Pleeter to adapt the series to the `git var` approach or justify why a new command is necessary.
- **Implementation scope for `git var`**: if the `git var` path is chosen, the series must be rewritten to add new keys (e.g., for signing configuration), NUL-terminated output, and other features while preserving existing `git var` behavior. This may involve significant refactoring of `git var`’s internals.
- **Backwards compatibility**: Peff’s proposal would not break existing `git var` usage but would add new features (e.g., NUL-terminated output) that could affect scripts expecting the current format. Care must be taken to ensure these changes do not introduce regressions.
- **Signing key resolution**: the `git var` extension would need to resolve signing keys (GPG/SSH/X.509) in a way that is consistent with `git ident`’s current implementation.
