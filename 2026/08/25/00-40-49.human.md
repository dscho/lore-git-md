This is a **bugfix** for Git's HTTP authentication layer, addressing a long-standing issue where `WWW-Authenticate` headers are lost during HTTP redirects. Junio C Hamano's reply in this thread is a gentle nudge for reviewers, noting that the patch (v2) remains uncontroversial and is ready for deeper scrutiny.

The core problem is straightforward: when Git follows an HTTP redirect, the `credential_from_url()` call in `http_request_recoverable()` clears the `wwwauth_headers` field, breaking authentication for redirect targets that rely on credential helpers (e.g., OAuth2 Bearer tokens). The v2 patch refines the solution by introducing `credential_update_url()`, a reusable helper in `credential.c` that preserves `wwwauth_headers` across URL updates using `SWAP()` for efficiency. This approach centralizes the preservation logic, making it available for future credential fields that may need similar treatment.

The patch touches two key subsystems: `http.c` (updated to use `credential_update_url()`) and `credential.c` (where the new helper is defined). Test coverage is thorough, with a new test in `t/t5563-simple-http-auth.sh` verifying that `wwwauth_headers` survive redirects. The test uses a custom Apache rewrite rule (`/custom_auth_redir/`) to simulate a redirect to a bearer-auth-protected endpoint, checking both the credential query (with preserved headers) and subsequent credential storage.
