This is the fifth patch in Derrick Stolee’s seven-part **bugfix and hardening series** for the trace2 subsystem, which aims to eliminate all `die()`-triggering helpers to prevent Git crashes during telemetry operations. This patch removes the use of `xstrfmt()`—a function that calls `die()` on formatting failures—from `trace2.c`, replacing it with manual string concatenation using `memcpy()` to avoid crashing while still redacting sensitive information (like passwords) in traced URLs.

The change is surgical and well-motivated: `xstrfmt()` is banned in `banned-die.h` (updated in this patch), and the new implementation in `redact_arg()` carefully handles memory allocation failures by returning `NULL` instead of terminating the process. The calling function, `redact_argv()`, now checks for `NULL` and cleans up any partially allocated memory before propagating the failure. This ensures trace2 degrades gracefully under memory pressure, prioritizing process stability over telemetry completeness—a trade-off explicitly documented in the series.

The patch touches only two files (`banned-die.h` and `trace2.c`) and maintains the series’ incremental approach (one banned function per patch). The commit message clearly explains the rationale and the defensive fallbacks, and the code itself is meticulous about overflow checks and cleanup. No test coverage is added, which is consistent with the series’ acknowledgment that allocation failures are hard to reproduce, but the logic is straightforward and unlikely to introduce regressions.
