This is the v2 of a four-patch bugfix series targeting a race condition in Git's geometric repacking mechanism that causes objects to be incorrectly reported as missing, even when they are present in another pack. The issue arises when a multi-pack-index (MIDX) references a packfile that is subsequently removed by a geometric repack, leaving processes using the stale MIDX unable to locate objects. The series now includes two additional patches: one fixing a leak in `git mktree --batch` (used in new test cases) and another demonstrating and fixing problems with `OBJECT_INFO_QUICK` readers.

The core fix (patch 4/4) has evolved significantly since v1, adopting Jeff King (Peff)'s tri-state design for `fill_midx_entry()` and gating the recovery logic on `SECOND_READ` to optimize performance for `QUICK` callers. The tri-state return values (`MIDX_FILL_MISS`, `MIDX_FILL_HIT`, `MIDX_FILL_OWNER_UNAVAILABLE`) distinguish between objects absent from the MIDX, those present but with an unavailable owning pack, and successful lookups. The recovery logic now scans MIDX-covered packs only during the second read, ensuring that objects relocated into new (non-covered) packs are found by the regular fallback, while genuine hidden duplicates are recovered transparently.

The series touches the packed-object backend (`odb/source-packed.c`), MIDX internals (`midx.c`, `midx.h`), and introduces new test coverage (`t/t5319-multi-pack-index.sh`, `t/t5336-repack-reader-race.sh`). The new test cases simulate both the `git replay` crash scenario and MIDX-packfile mismatches, including a test for repeated `QUICK` lookups that verifies the recovery logic works even when the owning pack is removed. The fix is well-motivated by production evidence, affecting multiple server-side operations (`git replay`, `git merge-tree`, `git diff`, `git rev-list`, and object resolution commands like `rev-parse` and `cat-file`).

The discussion around this series has converged on the core fix, with no remaining technical objections. Derrick Stolee's suggestion to defer pack deletion via `git multi-pack-index expire` is acknowledged as a complementary mitigation but is not part of this series. The patches are small, focused, and include thorough test coverage, making this a high-quality fix that should be a priority for merging. The series is now rebased on `ps/odb-generic-corrupt-objects`, resolving a minor conflict with an in-flight topic.
