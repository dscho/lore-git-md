This is the fifth patch in the v5 series adding new path-related keys to `git repo info`. It implements `path.grafts.absolute` and `path.grafts.relative`, exposing the location of Git’s grafts file in a scriptable format.

The patch follows the established pattern from earlier patches in the series: it adds two new keys (`path.grafts.absolute` and `path.grafts.relative`) that respect the `GIT_GRAFT_FILE` environment variable and return paths regardless of whether the file exists on disk. This aligns with the behavior of `git rev-parse --git-path info/grafts` and the precedent set by `path.index` and `path.hooks` in this series. The implementation uses `repo_get_graft_file()` and the existing `format_path()` helper to generate canonical absolute paths and relative paths from the current directory, respectively.

The documentation update in `Documentation/git-repo.adoc` clearly describes the keys’ behavior, including their respect for `GIT_GRAFT_FILE` and their unconditional path-return behavior. The tests in `t/t1900-repo-info.sh` cover both the standard case (`.git/info/grafts`) and an environment override (`GIT_GRAFT_FILE`), verifying that the keys work as expected.

This patch is mechanically clean and well-motivated. The grafts file is a legitimate repository component, and exposing its location through `git repo info` makes sense for scripts that need to inspect or modify grafts. The implementation reuses existing Git internals and follows the series’ design principles, so there are no surprises here. The only potential point of discussion is whether the unconditional path-return behavior is the right choice, but that question was settled in earlier iterations of the series and is consistent with the rest of the patch set.

If you care about scriptable access to Git’s internal paths, this patch is worth a quick look. Otherwise, it’s a straightforward addition that fits neatly into the larger effort.
