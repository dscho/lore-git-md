This is the third patch in René Scharfe’s four-patch series fixing edge cases in `git worktree add`’s path handling. It addresses a subtle bug in how branch names are derived from worktree paths: when the path contains multiple components (e.g., `/new/worktree/`), the current code incorrectly includes trailing slashes in the branch name, which are invalid characters.

The fix is straightforward: instead of copying a fixed-length substring (`xstrndup(s, n)`), the code now calculates the actual basename length and extracts only that portion (`xmemdupz(s, path + n - s)`). This ensures trailing slashes are trimmed, preventing malformed branch names. The patch updates two call sites in `builtin/worktree.c` and adds two new tests to `t/t2400-worktree-add.sh`—one for the default case and one for `--orphan` mode—both verifying that trailing slashes are handled correctly.
