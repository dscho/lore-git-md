This is a bugfix patch from René Scharfe, the first in a four-part series addressing issues in the `worktree_basename()` helper used by `git worktree add`. The patch fixes an out-of-bounds read that occurs when the input path has zero length, which could lead to data corruption. The fix is minimal: it adds a bounds check before decrementing the pointer, preventing it from moving before the start of the string. The change also simplifies the loop logic by removing the redundant `name++` adjustment after the loop.

The patch touches only `builtin/worktree.c` and is motivated by a real-world issue reported in Git for Windows (issue #6346). René attributes the original fix to Matthias Aßhauer, indicating this is a collaborative effort. The change is narrowly scoped and appears to address the root cause without introducing new complexity. Given René’s track record, this is likely a well-tested and safe fix, though the series as a whole will need review for edge cases beyond the immediate bounds issue. This patch is the most critical in the series, as it prevents potential data corruption.
