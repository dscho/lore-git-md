This is a bugfix patch for `git am --3way` that addresses a specific edge case in patch application.

The patch fixes a scenario where a multi-patch series modifies the same file, and while the first patch applies cleanly, the second fails because its preimage hash (the postimage of the first patch) was never recorded in the repository. Currently, `git am --3way` fails in this case with "sha1 information is lacking or useless" because it cannot build a fake ancestor for the second patch. The fix ensures that even when a patch applies cleanly, its postimage is recorded if `--3way` is enabled, so subsequent patches can reference it for 3-way merges.

The change is isolated to `builtin/am.c` and introduces a new helper function `try_record_patch_postimage()` that applies the patch to a temporary index to record the postimage blob. The patch also updates `run_apply()` and `build_fake_ancestor()` to support quiet operation, suppressing error output when the recording is best-effort. The test in `t/t4150-am.sh` verifies the fix by constructing a two-patch series where the first patch applies cleanly and the second requires a 3-way merge.

The commit message is clear and includes a detailed explanation of the problem, the solution, and the trade-offs (one extra `git apply` process per clean patch when `--3way` is used). The patch looks well-motivated and the implementation is straightforward, with no obvious downsides beyond the minor performance cost. The test coverage is thorough and covers the exact edge case described. This appears to be a targeted, high-quality fix for a real-world issue.
