The `git ident` thread has taken a decisive turn. Originally proposed as a new built-in command to unify Git’s identity and signing configuration display, the series (now at v2) addressed all prior feedback—renaming from `git whoami`, adding machine-readable output, removing `the_repository` usage, and supporting X.509 keys. However, Junio C Hamano has now endorsed Jeff King’s (Peff) alternative: extending `git var` to subsume `git ident`’s functionality, avoiding command proliferation while improving `git var`’s scripting support (e.g., NUL-terminated output). This consensus among maintainers shifts the focus to whether Andrew Pleeter will rewrite the series to target `git var` or argue for a standalone command.

Key participants have weighed in: brian m. carlson’s high-weight review requests (machine-readable output, X.509 support) are satisfied in v2, and Junio’s earlier usability concerns (flag interactions) are resolved. Peff’s proposal—enhancing `git var` with new keys and general improvements—now represents the project’s preferred direction, though no technical objections to `git ident` remain. The thread is still under review, with no merge status reported, but the path forward hinges on adapting the implementation to `git var` or justifying a departure from the maintainers’ preference.
