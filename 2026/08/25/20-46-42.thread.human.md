This thread is about extending `git var` to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing an earlier `git ident` proposal. The series, authored by Andrew Pleeter, has reached design consensus and is now in its third iteration, with Junio C Hamano and Phillip Wood providing detailed reviews.

The patch adds new variables like `GIT_AUTHOR_NAME`, `GIT_DEFAULT_KEY`, and others to `git var`, supporting multiple arguments, NUL-terminated output (`-z`), and signing key resolution. While the design is settled, the current focus is on code-level polish—particularly output format and argument parsing. Junio and Phillip have identified critical issues with `-z` mode, where the current `key=value\0` format fails if keys contain `=` characters, and they propose adopting `git config -z`’s `key\neolvalue\0` format instead. They also agree that flags like `-z` should precede variable names to avoid ambiguity, a change that could set a precedent for Git 3.0’s CLI rules.

The series remains under review in Junio’s `seen` branch, with no merge timeline yet. Open questions include whether to allow empty variable lists, how to handle multi-valued variables in `-z` mode, and whether the `GIT_SIGNING_KEY` alias is necessary. The next revision (v4) will likely address these points, along with documentation clarifications and code structure improvements. The discussion is collaborative, with no fundamental objections, and the patch is expected to land once these edge cases are resolved.
