This thread is about extending `git var` to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing an earlier `git ident` proposal. The series, authored by Andrew Pleeter, has reached design consensus and is now in its third iteration, with active review focused on implementation details.

Junio C Hamano and Phillip Wood have both posted substantive reviews of v3. Junio’s feedback centered on documentation clarity, code structure (such as using an `enum` for `ident_part()` and table-driven alias handling), and usability edge cases like empty argument lists. Phillip’s review raises more critical issues: the `-z` output format is ambiguous when keys contain `=` characters, and argument parsing logic (e.g., interleaved flags and variable names) could make the command unpredictable for scripting. He also questions the utility of the `GIT_SIGNING_KEY` alias for `GIT_DEFAULT_KEY`, noting that scripts signing external data would need more context than the variable provides.

The patch is still under review and not yet merged, likely remaining in Junio’s `seen` branch. A v4 revision is expected to address these concerns, particularly the output format and argument parsing issues, before the series can graduate to `next`. Other participants, including Jeff King and brian m. carlson, have previously endorsed the design, while Ben Knoble’s surface-level review deferred to Junio on usability questions. The focus now is on refining the implementation to ensure it’s both correct and ergonomic for both interactive and scripted use.
