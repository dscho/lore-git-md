This thread is about extending Git’s `git var` plumbing command to provide a unified, scriptable interface for identity and signing configuration, replacing an earlier proposal for a new `git ident` command. The design—using `git var` instead of a new command—has already been agreed upon by Junio C Hamano (the maintainer) and Jeff King (Peff), with Andrew Pleeter implementing the consensus.

The latest patch (v3) teaches `git var` to expose individual identity components (author/committer names, emails, dates), resolve signing keys (GPG/SSH/X.509), support multiple variable arguments in a single call, and produce NUL-terminated output for scripting. The implementation touches `builtin/var.c`, documentation, and tests, with no on-disk format changes or new configuration options. It’s currently under review, with no merge status reported yet.

Junio’s recent review is substantive but focused on polish rather than design. He suggests improvements to documentation clarity (e.g., rewording variable descriptions to better reflect commit object fields), code structure (e.g., using an `enum` for identity parts, table-driven aliases, and `parse_options()` for argument parsing), and usability edge cases (e.g., allowing empty variable lists for scripting, clarifying signing key resolution logic). His feedback is constructive and collaborative, indicating the patch is close to ready but will need a v4 to address these points. No fundamental objections were raised, and the changes are primarily about maintainability and ergonomics.

The thread is now in the final stages of code-level review, with Andrew expected to post an updated version incorporating Junio’s suggestions. The only open questions are implementation details, not design, and the patch is on track for integration once these are resolved.
