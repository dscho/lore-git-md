The `git whoami` thread has evolved into a second iteration now called `git ident`, a built-in command that consolidates Git’s identity and signing configuration into a single, user-friendly interface. Originally proposed as `git whoami` by Andrew Pleeter, the v1 patch faced maintainer-level skepticism from Junio C Hamano and brian m. carlson over its necessity and usability, particularly around flag design and whether the functionality belonged in Git core at all.

The v2 patch addresses all prior concerns comprehensively. The command has been renamed to `git ident` to better align with Git’s existing naming conventions (`git var`, `git config`), and its flag interactions have been redesigned to be additive and predictable—resolving Junio’s usability critique. For example, `-a -e -n` now shows the full author identity, and the command supports machine-readable `--porcelain` output and NUL-terminated (`-z`) output for scripting, fulfilling brian m. carlson’s requests. The implementation also removes `the_repository` usage, supports X.509 signing keys, and works outside of a repository. The commit message now clearly justifies the command’s inclusion in Git core, contrasting it with `git var` and `git config` by emphasizing its unified design and scripting support.

The patch touches `builtin/ident.c`, `Documentation/git-ident.adoc`, `t/t0015-ident.sh`, build system files, and `command-list.txt`, with no on-disk format changes or new configuration options. Test coverage is thorough, including edge cases like environment variable overrides and signing key resolution. With all open questions from the v1 review resolved, the patch appears technically sound and ready for further review. If no new concerns arise, it is likely to advance to Junio’s `next` branch for integration testing.
