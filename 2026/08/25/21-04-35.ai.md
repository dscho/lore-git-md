This is the final patch in the v8 series improving error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. It specifically addresses the `--guess-remote` option in `git worktree add`, treating multiple matches as an error rather than silently falling back to creating a branch from HEAD.

The patch fixes a latent bug where `git worktree add --guess-remote <path>` would succeed even when multiple remote-tracking branches matched the basename of `<path>`, potentially leading to unexpected behavior. Now, when ambiguity is detected, the command fails with a clear error message (e.g., "'foo' matched multiple (2) remote tracking branches") and suggests how to resolve it. This aligns the behavior with `git checkout` and `git switch`, which already error out in similar scenarios.

Key changes include:
- Updating `dwim_branch()` to accept the `add_opts` struct and pass it through to the advice helper, enabling quiet mode suppression.
- Extending `unique_tracking_name()` to collect remote names and count matches, then using this information to trigger the error when multiple matches exist.
- Adding test coverage for the new error case in `t/t2400-worktree-add.sh`.
- Updating documentation to reflect the changed behavior.
