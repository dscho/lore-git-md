This is the third patch in Patrick Steinhardt’s 10-patch series making Git’s object-database fsck checks pluggable. It is a refactoring step that moves global option variables into the `cmd_fsck()` function, preparing the code for later patches that will split fsck logic across ODB backends.

The patch itself is small and mechanical: it relocates four global variables (`check_full`, `keep_cache_objects`, `name_objects`, and `check_references`) into the function scope, re-declares the option array locally, and initializes the variables to their previous default values. No behavior changes are introduced; the goal is purely to reduce global state so that subsequent patches can safely add backend-specific option handling without risking unintended interactions.

The commit message is clear and concise, explaining the motivation (“a bit of a mess due to lots of global state”) and the immediate benefit (making it easier to see which flags are used where). The diff is straightforward and well-contained, touching only `builtin/fsck.c` and changing no interfaces outside the file.

This patch is part of the larger ODB abstraction effort and depends on two earlier topics (`ps/odb-eagerly-load-alternates` and `ps/odb-pluggable-pack-generation`). It is currently under review as part of the v1 series posted on 2026-08-24.
