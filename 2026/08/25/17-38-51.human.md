This is a brief follow-up in the ongoing RFC thread about making Git's stash stack branch-aware. Junio C Hamano acknowledges Phillip Wood's clarification that Git already encodes branch information at the start of stash messages, either as `"On $branch: "` (for user-supplied messages) or `"WIP on $branch ..."` (for default messages). This resolves the earlier technical concern about parsing ambiguity and confirms that the branch-aware design is feasible without changes to the on-disk format or new configuration.

The thread remains focused on refining the branch-aware approach, which now looks like the likely path forward. No new alternatives or objections are raised here; the discussion can proceed to implementation details, such as how to expose branch-filtered operations in the CLI (e.g., a `--current-branch` flag for `git stash pop`). The original `stash.ref` config knob proposal is effectively superseded by this design.
