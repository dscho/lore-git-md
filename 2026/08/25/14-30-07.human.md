This is the fifth patch in Patrick Steinhardt’s 10-patch series refactoring Git’s object database (ODB) fsck checks to make them pluggable. The patch introduces the infrastructure needed for each ODB backend (loose, packed, multi-pack, etc.) to implement its own consistency checks, replacing the current monolithic approach in `builtin/fsck.c`.

The core change is adding a new `fsck` callback to the `odb_source` struct, along with a set of stub implementations for the existing backends (`odb/source-files.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, and `odb/source-packed.c`). These stubs currently do nothing but will be fleshed out in later patches. The patch also introduces `struct odb_fsck_options` to pass flags (like `ODB_FSCK_FULL`) to the backend-specific checks, and a new `odb_fsck()` function that iterates over all ODB sources and invokes their `fsck` callbacks.

In `builtin/fsck.c`, the patch replaces the old `check_full` boolean with the new `odb_fsck_opts` struct, updating the option-parsing logic to use `OPT_BIT` for the `--full` flag. The `cmd_fsck()` function now calls `odb_fsck()` to delegate backend-specific checks, reducing direct coupling between `fsck` and the ODB internals. The changes are mechanical and do not alter behavior—this is purely infrastructure work for the later patches in the series.

The patch is well-structured and clearly motivated, fitting neatly into the broader ODB abstraction effort. It touches eight files but keeps the changes focused and minimal, avoiding any user-visible behavior changes. The commit message explains the layering violation being addressed and the long-term goal of supporting pluggable ODB backends. No review feedback has been posted yet, but the patch looks like a solid step toward the series’ goal.
