This is a **bugfix and hardening series** targeting the trace2 subsystem. Derrick Stolee expands his earlier patch (which addressed a crash caused by `xsnprintf()` failures in trace2 timestamp formatting) into a comprehensive effort to eliminate all `die()`-triggering helpers from the trace2 API. The series introduces a new `banned-die.h` header that systematically blocks functions like `xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`, `xstrfmt()`, `ALLOC_GROW()`, and `xcalloc()` from being used in trace2 code, replacing them with defensive fallbacks that avoid process termination.

The motivation is clear: trace2 is a low-level telemetry layer that should never cause Git to crash, even under memory pressure or system call failures. The series is well-structured, with each patch targeting one banned function and ensuring trace2 remains "as correct as possible" when allocations fail—prioritizing stability over completeness (e.g., dropping trace messages or using hardcoded fallbacks). The cover letter explicitly ties this to the earlier discussion about Git for Windows’s `libintl_vsnprintf()` behavior, where allocation failures in `xsnprintf()` were identified as the root cause of the original crash.

Key technical details:
- **Files touched**: 15 files, including `banned-die.h` (new), all trace2 `.c` files, and `trace2/tr2_tls.h`. The series is self-contained to the trace2 subsystem.
- **Behavior change**: Trace2 now tolerates allocation failures by falling back to degraded operation (e.g., truncated messages, hardcoded timestamps, or dropped events) instead of crashing. This is a breaking change for trace consumers, who may now see malformed or missing data under failure conditions, but the trade-off is intentional.
- **Platform focus**: Primarily Git for Windows, where `libintl_vsnprintf()`’s allocation behavior differs from POSIX, but the hardening applies to all platforms.
- **Test coverage**: None, as the issue depends on transient failures (allocation/system calls) that are hard to reproduce. The series acknowledges this limitation.
- **Related work**: This supersedes the earlier standalone patch (v1) and implements the two-part solution agreed upon in the thread (Derrick’s hardening + Taylor Blau’s MinGW-specific fix). The MinGW fix is not included here but is still planned as a follow-up.

The series is ambitious but pragmatic, addressing a real stability problem with a systematic approach. The commit messages are detailed, explaining both the "what" and the "why" for each change, and the incremental structure (one function per patch) makes review manageable. The introduction of `banned-die.h` is a notable architectural decision—it centralizes the enforcement of "no `die()` in trace2" and could serve as a template for hardening other low-level subsystems in the future.

No objections or technical concerns were raised in the thread context, and the series aligns with Junio’s feedback to avoid `die()` in trace2. The only loose end is the MinGW-specific fix, which Derrick confirms will follow separately. This looks like a solid, well-motivated effort that directly addresses the crash risk while minimizing disruption to trace consumers.
