This is a new feature patch introducing a `git whoami` command. The patch adds a built-in command that displays the current Git identity (author and committer names/emails) and signing configuration (GPG/SSH key and `commit.gpgsign` status) in a single, user-friendly output. It supports multiple flags (`--author`, `--committer`, `--name`, `--email`, `--signing-key`, and `--verbose`) for targeted querying, making it useful for both interactive use and scripting.

The implementation is self-contained in `builtin/whoami.c` and integrates with Git’s existing identity and GPG interfaces (`ident.h` and `gpg-interface.h`). The patch includes a man page (`Documentation/git-whoami.adoc`), build system updates (Makefile, meson.build), and a comprehensive test suite (`t/t0015-whoami.sh`) covering edge cases like environment variable overrides, incompatible flag combinations, and signing key resolution. The command works outside of a repository, which is a notable design choice.

The motivation is clear: users often juggle multiple identities or signing keys across environments, and verifying the active configuration currently requires checking multiple `git config` or `git var` settings. This command consolidates that information into a single porcelain command. The patch is well-structured, with thorough test coverage and attention to error handling (e.g., incompatible flag combinations). It avoids controversial design choices, such as modifying existing commands or introducing new configuration options.

Key files touched: `builtin/whoami.c`, `Documentation/git-whoami.adoc`, `t/t0015-whoami.sh`, and build system files. The command is classified as `ancillaryinterrogators` in `command-list.txt`. No prior discussion or RFC is referenced, so this appears to be the first iteration of the proposal. The patch is likely to generate discussion about whether this functionality belongs in Git core or should remain a third-party script, but the implementation itself is technically sound and ready for review.
