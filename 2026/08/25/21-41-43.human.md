This is a review of the `git whoami` patch from Junio C Hamano, the Git maintainer. The review is substantive, focusing on the command-line interface design and internal consistency.

Junio raises a fundamental concern about the proliferation of Git subcommands, though he does not outright reject the feature. His main technical critique centers on the confusing interaction between the `--author`/`-a`, `--committer`/`-c`, `--name`/`-n`, and `--email`/`-e` flags. The current implementation treats `--name` and `--email` as mutually exclusive with `--author` and `--committer`, so `--name --committer` silently ignores the committer flag, while `--author --committer` shows both. This inconsistency makes the command harder to predict and use correctly.

Junio suggests a more additive design where flags combine naturally, similar to how `git log --author --grep` works. His proposed alternative (`git ident -a -e -n` to show name and email for the author) would make the command more intuitive and scriptable. The review does not address the broader questions raised by brian m. carlson (e.g., machine-readable output, X.509 support, or `the_repository` usage), but Junio’s feedback is likely to shape the next iteration of the patch. The tone is constructive but firm, signaling that the interface needs rethinking before the feature can proceed.
