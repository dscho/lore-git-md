This is the v8 cover letter for the patch series improving user-facing error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The series now consists of four patches, adding a new commit to fix the behavior of `--guess-remote` when multiple matches exist.

The core goal remains the same: replacing terse "matched multiple remote tracking branches" warnings with detailed, actionable advice messages. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and now includes a static list of conflicting remotes (e.g., "Branch name '%s' appears in multiple remotes:") for immediate usability. The series also refines error handling by moving an existing `die()` call earlier in the code path, replacing generic "invalid reference" messages with more specific diagnostics.

The new patch (4/4) addresses a latent bug in the `--guess-remote` option of `git worktree add`: when multiple remote branches match the given name, the command previously succeeded silently, which could lead to unexpected behavior. The fix treats this scenario as an error, aligning it with the behavior of `git checkout` and `git switch`. This change is well-motivated and follows the discussion in the thread, where Junio C Hamano identified the issue and agreed it should be addressed.

The series is now functionally complete, covering all three commands (`checkout`, `switch`, and `worktree add`) and addressing the `--guess-remote` edge case. Test coverage has been updated to verify the new behavior, including the `--guess-remote` error case.
