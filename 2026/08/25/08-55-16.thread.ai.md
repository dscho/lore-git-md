This thread is a single-patch bugfix series from Nikita Leshenko addressing a specific edge case in `git am --3way`. The patch fixes a scenario where a multi-patch series modifies the same file, and while the first patch applies cleanly, the second fails with "sha1 information is lacking or useless" because its preimage hash (the postimage of the first patch) was never recorded in the repository. The original patch proposed recording the postimage of every cleanly applied patch when `--3way` is enabled, ensuring subsequent patches can perform 3-way merges. The change introduced a new helper function `try_record_patch_postimage()`, updates to `run_apply()` and `build_fake_ancestor()` for quiet operation, and a test in `t/t4150-am.sh`.

Junio C Hamano reviewed the patch and identified a critical performance issue: the proposed solution would spawn an extra `git apply --build-fake-ancestor` process, write and unlink a temporary index file, perform an in-core patch application, and generate unneeded loose objects for *every* cleanly applied patch in a series. For a 50-patch series, this would mean 49 unnecessary operations, which Junio deemed "simply unacceptable." This would avoid per-patch overhead while preserving the fix's intent.
