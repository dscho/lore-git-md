This thread is about Patrick Steinhardt’s 10-patch series making Git’s object database (ODB) consistency checks pluggable. The goal is to move fsck logic out of `builtin/fsck.c` and into the respective ODB backends (loose, packed, multi-pack, etc.), allowing each backend to implement its own integrity checks. This is a foundational refactoring for the ongoing ODB abstraction effort, which aims to support future backends like reftable or alternate storage systems.

The series is a pure refactoring with no user-visible changes, but it significantly restructures the codebase: 259 lines are removed from `builtin/fsck.c`, and new backend-specific verification logic is added in `odb/source-loose.c`, `odb/source-packed.c`, and related files. Key functions like `fsck_obj_buffer()` and `fsck_obj()` are de-globalized, and infrastructure for pluggable checks is introduced. Tests are added to verify the new backend-specific behavior.

The series depends on two earlier topics (`ps/odb-eagerly-load-alternates` and `ps/odb-pluggable-pack-generation`) and is based on Junio’s integration branch as of August 24, 2026. No on-disk format or CLI changes are involved, and the work is currently under review. If you’re tracking the ODB abstraction effort, this is a critical step toward enabling more flexible storage backends.
