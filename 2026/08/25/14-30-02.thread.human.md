This thread is Patrick Steinhardt’s ten-part series refactoring Git’s object integrity checks (`git fsck`) to make them pluggable per ODB backend. The goal is to prepare the codebase for future storage backends (e.g., reftable) without changing user-visible behavior. The series is under review, with the first four patches already posted and now patch 5/10 introducing the core infrastructure: a new `fsck` callback in the `odb_source` vtable and an `odb_fsck_options` structure. This patch is scaffolding only—no functional changes yet—but it wires up the hooks that later patches will use to move the existing fsck logic into backend-specific implementations. The series depends on two earlier topics (`ps/odb-eagerly-load-alternates` and `ps/odb-pluggable-pack-generation`) and is based on Junio’s integration branch as of late August 2026. No reviews or objections have been recorded so far.
