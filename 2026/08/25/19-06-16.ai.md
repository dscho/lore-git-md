This is a performance optimization patch for `git push` from shallow clones, updating the previously discussed series to v2. The patch introduces a new config option, `push.shallowExcludeBoundary` (default: `true`), which avoids resending the entire toplevel tree when pushing from a shallow repository by treating shallow grafts as uninteresting tips during pack generation. This addresses a long-standing inefficiency where even small changes trigger gigabytes of redundant data transfer in large repositories.

Key changes since v1 include minor code style fixes (e.g., marking input parameters as `const`, combining loops over `refs` for efficiency) and an updated cover letter clarifying why `push.negotiate=true` is not a complete solution. The patch remains based on Patrick Steinhardt’s `ps/odb-pluggable-pack-generation` branch to resolve a conflict with the removal of `feed_object()`.

The implementation adds a helper function, `append_reachable_shallow_grafts()`, which walks from pushed tips to their shallow grafts, adding those grafts to the pack boundary as negative tips. The walk stops early at any commit the server already has, keeping the operation efficient for deeper clones. The patch updates `t5538-push-shallow.sh` with extensive test coverage, including edge cases like a rejected ref not over-excluding objects needed by an accepted ref, and the interaction with `receive.shallowUpdate`.

The config option defaults to `true` (optimization enabled), but users can set it to `false` to restore the previous behavior for rare workflows like seeding a receiver that adopts new shallow roots. The commit message and tests thoroughly document the tradeoffs and backward-compatibility story. This version of the patch is well-scoped, touching only `send-pack.c` and the relevant documentation, and appears ready for further review. The ongoing discussion with Patrick Steinhardt about whether to prefer this approach or a `push.negotiate=shallow` mode remains unresolved, but this patch stands as a self-contained solution.
