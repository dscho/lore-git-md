This is the eighth patch in Patrick Steinhardt’s 10-patch series making Git’s object-database fsck checks pluggable. It moves bitmap verification — currently a standalone function in `pack-bitmap.c` — into the packed ODB backend’s `fsck` callback.

The patch deletes the call to `verify_bitmap_files()` from `cmd_fsck()` and instead invokes it inside `odb_source_packed_fsck()`. The function itself is narrowed from scanning all ODB sources to operating on a single `odb_source_packed` instance, which matches the per-backend design established in earlier patches. As with the previous two patches, the dedicated `ERROR_BITMAP` bit is dropped in favor of the generic `ERROR_OBJECT` bit, simplifying error reporting. The change also ensures that `--connectivity-only` and `--no-full` flags are respected: bitmap checks are now skipped when either flag is passed, which the new test in `t/t5326-multi-pack-bitmaps.sh` verifies.

The diff is clean and mechanical, touching only the files that need to change (`builtin/fsck.c`, `odb/source-packed.c`, `pack-bitmap.c`, `pack-bitmap.h`, and the test script). No user-visible behavior changes; this is pure refactoring that continues the series’ goal of pushing fsck logic down into the appropriate ODB backends.
