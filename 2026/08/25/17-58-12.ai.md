This is the first patch in the **v5 series** adding seven new path-related keys to `git repo info`. It implements `path.toplevel.absolute` and `path.toplevel.relative`, which expose the top-level working tree directory in absolute and relative (to the current directory) formats. The patch touches `builtin/repo.c` (adding two new getter functions), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding tests for bare and non-bare repositories, including subdirectory cases).

The implementation reuses `repo_get_work_tree()` and the existing `format_path()` helper, ensuring consistent behavior with other path keys. In bare repositories, both keys return an empty string, matching the series' design principle of using empty strings only for inapplicable contexts. The tests verify absolute path resolution (using `test-tool path-utils real_path`) and relative path formatting (e.g., `../` from a subdirectory), as well as the bare-repository edge case.

This patch is mechanically clean and aligns with the series' established patterns. The commit message clearly states the motivation (scriptability and predictability) and avoids relying on `git rev-parse`. No substantive design questions remain for this key; the focus here is on correctness and consistency with the rest of the series. The only potential follow-up discussion might involve minor naming preferences (e.g., `path.top-level` vs. `path.toplevel`), but the current choice is uncontroversial.
