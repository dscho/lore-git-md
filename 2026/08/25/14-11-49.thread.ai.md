Thread identity: Refactoring ODB alternates handling during repository creation. 8-patch series (`[PATCH 0/8]`) by Patrick Steinhardt, part of the ongoing ODB abstraction effort. Thread type: patch series.

Core problem or goal: Remove the ability to write ODB alternates after repository creation, simplifying the ODB interface. Currently, alternates can be added at any time via `odb_source_write_alternate()`, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback. This change prepares for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration.

Current status: Under review. The series is built on `ps/odb-eagerly-load-alternates` and remains in the review phase. All 8 patches have been posted and reviewed, with substantive feedback now resolved regarding the locking strategy for alternates file updates. Patches 1-5 refactored reference handling in `git clone`, deferring ODB setup and consolidating alternates logic into `collect_alternates()`. Patch 5 addressed a latent bug in worktree alternates handling (fixing unresolved common directory paths) and added test coverage for worktree clones and relative path resolution. A minor code hygiene suggestion from Toon Claes (moving `fclose(in)` before the `out` label) was declined by Patrick Steinhardt, who explained that the current placement reduces fragility for future extensions. Patch 6 implemented the core design change, introducing `odb_create_on_disk_options` to write alternates during ODB creation, and will be revised to use Git’s standard lockfile API for writing the `info/alternates` file, addressing Junio C Hamano’s security and correctness concern about TOCTOU races or partial writes. Patch 7 wired up the new mechanism in `cmd_clone()`, removing the last direct use of `odb_add_to_alternates_file()`. Patch 8 removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure across all ODB backends, but the removal of the lockfile mechanism remains under scrutiny due to concurrent access concerns raised by Toon Claes and now acknowledged as a necessary fix.

Key technical details:

The `write_alternates()` callback, `odb_add_to_alternates_file()` helper, and lockfile mechanism have been removed. `odb_source_write_alternates()` is now unused and deleted.
- Subsystems: ODB (object database), alternates handling, repository creation, worktree handling.
- Old-vs-new behavior: No user-visible changes. The series defers ODB creation in `git clone` until after the clone source URI is resolved, ensuring alternates are written with full context. Patch 7 removed the last manual alternates writing step in `cmd_clone()`, consolidating alternates setup into `create_object_database()`. Patch 8 removes the unused `write_alternates()` infrastructure, but the removal of the lockfile mechanism is now acknowledged as premature; the lockfile API will be adopted in the new implementation.

The revised locking implementation in patch 6 may require additional test coverage for concurrent repository creation scenarios to ensure safety against partial writes or corruption.
