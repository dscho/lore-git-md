Thread identity: Refactoring ODB alternates handling during repository creation. 8-patch series (`[PATCH 0/8]`) by Patrick Steinhardt, part of the ongoing ODB abstraction effort. Thread type: patch series.

Core problem or goal: Remove the ability to write ODB alternates after repository creation, simplifying the ODB interface. Currently, alternates can be added at any time via `odb_source_write_alternate()`, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback. This change prepares for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration.

Current status: Under review. The series is built on `ps/odb-eagerly-load-alternates` and remains in the review phase. All 8 patches have now been posted. Patches 1-5 refactored reference handling in `git clone`, deferring ODB setup and consolidating alternates logic into `collect_alternates()`. Patch 6 implemented the core design change, introducing `odb_create_on_disk_options` to write alternates during ODB creation. Patch 7 wired up the new mechanism in `cmd_clone()`, removing the last direct use of `odb_add_to_alternates_file()`. Patch 8 (this update) removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure across all ODB backends, completing the refactoring.

Key technical details:
- Files touched: `builtin/clone.c` (patches 1-5 refactored reference handling, deferring ODB setup and consolidating alternates logic into `collect_alternates()`; patch 7 removed manual alternates writing), `setup.c`/`setup.h` (added `INIT_DB_SKIP_ODB` flag, exposed `create_object_database()`, and updated it to accept a `strvec` of alternates paths), `odb/source-files.c` (patch 6 added support for writing alternates during creation via `odb_source_files_create_on_disk()` with `odb_create_on_disk_options`; patch 8 removed the `write_alternate` callback), `odb/source-inmemory.c`, `odb/source-loose.c`, `odb/source-packed.c` (patch 8 removed backend-specific `write_alternate` implementations), and `t/t5604-clone-reference.sh` (updated tests for worktree alternates handling and relative path resolution).
- New or renamed symbols: `INIT_DB_SKIP_ODB` flag added to `init_db()`; `create_object_database()` made public and updated to accept a `strvec` of alternates paths; `collect_alternates()` (renamed from `setup_reference()`, now with `src_repo` and `is_local` parameters), `add_one_alternate()` (replaces `add_one_reference()`), `struct add_one_alternate_data` (tracks whether an alternate is required/optional and holds the `strvec` of paths), `read_alternates()` (renamed from `copy_alternates()`), and `odb_create_on_disk_options` (new struct carrying alternates `strvec` for ODB creation). The `write_alternates()` callback and `odb_add_to_alternates_file()` helper have been removed. `odb_source_write_alternates()` is now unused and deleted.
