This is the third patch in the v8 series improving error messages for ambiguous remote branch names in `git worktree add`. It extends the shared advice helper (`advise_disambiguating_remotes`) introduced in patch 1/4 to the `git worktree add` command, providing users with actionable guidance when multiple remote branches match the given branch name.

The patch addresses a usability gap where `git worktree add ../foo-dir bar-topic` would fail with a generic "invalid reference" error if `bar-topic` existed in multiple remotes. The new behavior detects ambiguity early, emits a tailored advice message listing the conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes:" followed by the remote names), and dies with a clear error: "'bar-topic' matched multiple (2) remote tracking branches". The advice suggests using `--track` with a fully qualified remote branch or setting `checkout.defaultRemote` to avoid future ambiguity.

Key changes include:
- Extending `unique_tracking_name()` to collect remote names via a new `struct string_list *matched_remote_names` parameter.
- Introducing the `advise_disambiguating_remotes()` helper in `builtin/worktree.c` to format the advice message, mirroring the logic added to `checkout.c` in patch 2/4.
- Moving the `die()` call earlier in the code path to replace the misleading "invalid reference" error with a specific diagnostic.
- Narrowing the scope of the `oid` variable to the block where it is used.
- Updating the test in `t/t2400-worktree-add.sh` to verify the new error message format and advice behavior.

The implementation is clean and aligns with the series' goal of consistent, user-friendly error handling across `git checkout`, `git switch`, and `git worktree add`. The advice message is grammatically correct (fixing the "Branches ... appears" error from earlier iterations) and includes the number of matching remotes for clarity. Test coverage ensures the new behavior is exercised, including the advice message and error message format.
