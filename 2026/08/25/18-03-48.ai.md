This is the second patch in René Scharfe’s four-patch series fixing `git worktree add` basename handling. It addresses a specific edge case: paths consisting solely of one or more path separators (e.g., `"/"` or `"//"`). Previously, `worktree_basename()` would extract an empty string from such paths, leading to a BUG assertion later in the code when the sanitized refname component also turned out empty. This patch adds explicit validation to reject such paths early with a clear error message (`"invalid path '<path>'"`) instead of triggering the BUG.

The change is minimal: two lines added in `builtin/worktree.c` to check if the constructed basename string (`sb`) is empty after extraction, and a corresponding test in `t/t2400-worktree-add.sh` that verifies `git worktree add "" HEAD` fails as expected. The fix is grounded in the real-world issue reported in Git for Windows (issue #6346) and attributed to Matthias Aßhauer, ensuring the edge case is both motivated and tested.

This patch is a straightforward correctness fix with no behavioral ambiguity. It complements the first patch (which fixed an out-of-bounds read) by tightening input validation, and it sets the stage for the subsequent patches that normalize trailing-slash handling and simplify memory management. The test addition is minimal but sufficient to cover the reported edge case.
