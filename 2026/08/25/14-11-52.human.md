This is the third patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The patch focuses on `builtin/clone.c`, renaming and refactoring the `setup_reference()` function to `collect_alternates()` to better reflect its purpose—collecting alternate object store paths into a `strvec` rather than immediately writing them to the ODB.

The change is mechanical and preparatory: it gathers alternate paths into a `strvec` so that later patches can consolidate the writing of alternates into a single step during ODB creation. This aligns with the series’ broader goal of simplifying the ODB interface by removing the ability to write alternates after repository creation. The patch itself does not alter behavior—it merely reorganizes the code to enable future changes.

The refactoring is clean and well-motivated, with a clear commit message explaining the rationale. The new function name (`collect_alternates`) is a significant improvement over the old (`setup_reference`), which was misleadingly named given its actual purpose. The patch also introduces a small helper struct (`add_one_alternate_data`) to pass context to the callback, improving readability.

This patch is unlikely to be controversial, as it’s purely internal refactoring with no user-visible changes. Reviewers may focus on ensuring the new `strvec`-based approach doesn’t introduce edge cases (e.g., memory leaks or incorrect handling of invalid alternates), but the changes are straightforward and well-contained. The patch is part of the ongoing ODB abstraction effort, and its value lies in setting up the groundwork for later patches in the series.
