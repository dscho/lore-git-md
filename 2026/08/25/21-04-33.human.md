This is the second patch in a four-part series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. The series is now in its eighth iteration and has been merged to `next`.

This patch enhances the `unique_tracking_name()` function to optionally collect the names of matching remotes when ambiguity arises. It then uses this information to provide a more detailed and actionable advice message when the user runs `git checkout <branch>` or `git switch <branch>` and the branch name exists in multiple remotes (e.g., both `origin/foo` and `upstream/foo`). Instead of a terse "matched multiple remote tracking branches" warning, the user now sees a list of conflicting remotes and clear instructions on how to resolve the ambiguity, such as using `--track` or setting `checkout.defaultRemote`.

The implementation is clean: the advice logic is refactored into a shared helper (`advise_disambiguating_remotes()`), and the error message now includes the number of matching remotes (e.g., "matched multiple (2) remote tracking branches"). The patch also moves an existing `die()` call earlier in the code path to provide a more specific diagnostic, replacing a generic "invalid reference" message. This change is well-justified in the commit message, which traces the problematic flow (silent failure to resolve ambiguity leading to a misleading error).

The patch touches `builtin/checkout.c`, `checkout.c`, and `checkout.h`, and updates the advice message to be more user-friendly. The grammatical error in the advice ("Branches ... appears") has been fixed, and the message is tailored to the command context. Test coverage is handled in later patches, but the changes here are straightforward and well-motivated. The series as a whole addresses a real usability pain point and aligns the behavior of `git checkout` and `git switch` with the improved error handling introduced for `git worktree add` in other patches.
