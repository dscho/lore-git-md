This is the third patch in Elijah Newren’s four-patch bugfix series (v2) that addresses a race condition in Git’s geometric repacking mechanism. The series targets a scenario where a multi-pack-index (MIDX) references a packfile that is subsequently removed by a concurrent repack, causing processes using the stale MIDX to fail to locate objects. This patch specifically fixes the issue for `OBJECT_INFO_QUICK` lookups, which previously skipped the recovery mechanism that normal lookups use, leading to false negatives and incorrect behavior in commands like `git mktree --batch` and `git upload-pack`.

The fix introduces a new flag, `stale_packs_detected`, in the `object_database` struct to track when a packfile vanishes mid-lookup. The flag is set in three places where a reader can observe a pack’s disappearance: when `open_pack_index()` fails due to a missing `.idx` file, when opening a `.pack` file fails after its `.idx` was already mapped, and when `prepare_midx_pack()` cannot open a pack referenced by a MIDX. The flag forces `odb_read_object_info_extended()` to issue a second read (reprepare) even for `OBJECT_INFO_QUICK` lookups, ensuring the object is found in its new location. The flag is reset during the reprepare in `odb_source_packed_prepare()`.

The patch includes thorough test coverage in `t/t5336-repack-reader-race.sh`, which simulates the race condition deterministically by driving a resident `git mktree --batch` process across both removal windows (`.idx` first, then `.pack`). The tests confirm the reader recovers the relocated object instead of failing or producing incorrect output. The fix is well-motivated by production evidence and addresses a correctness issue affecting multiple server-side operations, including `git upload-pack`, where a spurious miss can degrade negotiation performance.

This patch is part of a converged series with no remaining technical objections. The design has evolved to adopt Jeff King’s tri-state approach and `SECOND_READ`-gated fallback, ensuring the recovery logic is both correct and performant. The series is a high-priority candidate for merging, as it fixes a race condition that can cause crashes and data corruption in critical workflows.
