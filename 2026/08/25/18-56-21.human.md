This is the final patch in Derrick Stolee’s seven-part bugfix and hardening series for the trace2 subsystem. It removes the last remaining `die()`-triggering helper—`xcalloc()`—from the trace2 API, completing the effort to eliminate all such functions and prevent Git crashes during telemetry operations.

The patch replaces `xcalloc()` with `calloc()` in `tr2tls_create_self()`, the function that allocates thread-local storage for trace2 contexts. When allocation fails, instead of crashing, the code now falls back to a statically allocated "fallback" context with a hardcoded thread name (`"unknown"`). This ensures the process can continue running, albeit with degraded telemetry (e.g., missing timing data or counter values). The patch also introduces a new helper function, `tr2tls_is_fallback()`, to let callers detect and handle the fallback context gracefully, and updates all trace2 operations to skip processing when the fallback is active.

The changes are confined to the trace2 subsystem and touch five files: `banned-die.h` (updated to block `xcalloc()`), `trace2/tr2_tls.c` (the core logic), `trace2/tr2_tls.h` (new helper function), and two minor updates in `tr2_ctr.c` and `tr2_tmr.c` to check for the fallback context. The patch preserves the existing interface while making it resilient to allocation failures, and the commit message clearly explains the trade-off: telemetry may be incomplete or missing under memory pressure, but the process will not crash.

This is a well-crafted, incremental fix that directly addresses the crash risk identified in the original bug report.
