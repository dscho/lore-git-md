This is the fifth patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the broader ODB abstraction effort, aiming to simplify the ODB interface by moving alternates handling into the backend.

This patch moves the setup of alternates for non-shared local clones into the `collect_alternates()` function, completing the consolidation of alternates handling begun in earlier patches. The change is more than just code reorganization—it fixes a bug where Git failed to resolve the common directory of a referenced repository when cloning from a worktree. Previously, alternates setup for worktrees was incomplete because the code didn’t account for the worktree’s common directory. The patch reuses the already-resolved common directory path from `collect_alternates()` to ensure alternates are correctly set up.

The patch also adds two new tests to prevent regressions. The first verifies that cloning from a linked worktree correctly carries over alternates, while the second ensures relative alternates in a worktree are properly resolved. These tests are straightforward but important, as they cover edge cases that were previously broken.

The diff shows the patch renames `copy_alternates()` to `read_alternates()` and refactors it to push alternates into a `strvec` instead of directly writing them to the alternates file. This aligns with the series’ goal of deferring alternates setup until repository creation. The change is mechanical but necessary for the later patches that will remove the `write_alternates()` callback entirely.

This patch is a small but meaningful step in the series. It’s well-motivated, fixes a real bug, and includes test coverage. The changes are localized to `builtin/clone.c` and the test suite, with no user-visible behavior changes. Reviewers will likely focus on whether the refactoring introduces any edge cases, particularly around worktree handling and relative paths. The patch looks solid and uncontroversial.
