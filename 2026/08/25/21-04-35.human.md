This is the final patch in a now-complete four-part series improving error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The series is in `next` and addresses a real usability pain point.

This patch specifically fixes a latent bug in `git worktree add --guess-remote`: when multiple remote branches match the given name, the command previously succeeded silently, creating a branch from HEAD instead of the intended remote branch. The fix treats this scenario as an error, aligning the behavior with `git checkout` and `git switch`. The error message includes the number of matching remotes (e.g., "matched multiple (2) remote tracking branches") and, when advice is enabled, suggests how to resolve the ambiguity (e.g., specifying the remote explicitly with `git worktree add -b <branch> <path> <remote>/<branch>`).

The implementation is clean: it extends the existing `unique_tracking_name()` function to collect remote names, reuses the shared `advise_disambiguating_remotes()` helper introduced earlier in the series, and updates the documentation to reflect the new behavior. Test coverage verifies the error case and the advice message. The patch is well-motivated and follows directly from the thread discussion, where Junio C Hamano identified the issue and agreed it should be addressed.

The series as a whole is now functionally complete, with all prior review feedback addressed. The only remaining loose end is a follow-up fix for the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), which is scoped for a separate commit. This patch looks ready to graduate to `master`.
