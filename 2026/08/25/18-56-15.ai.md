This is the first patch in a **bugfix and hardening series** targeting the trace2 subsystem. It introduces `banned-die.h`, a new header that systematically blocks functions capable of terminating the process (starting with `die()`) from being used in trace2 code. The patch is purely infrastructural—it creates the enforcement mechanism but does not yet replace any banned functions with defensive fallbacks.

The motivation is clear: trace2 runs during `atexit()` and must never trigger `die()`-handler recursion, as seen in the original crash caused by `xsnprintf()` failures on Git for Windows. By centralizing the ban in a header, the series ensures consistency and makes it easy to extend the list of banned functions (e.g., `xsnprintf()`, `xstrdup()`) in subsequent patches. The commit message explains the long-term vision: this header could eventually be adopted by other low-level subsystems beyond trace2.

The patch touches 14 files, all within the trace2 subsystem, adding a single `#include "banned-die.h"` line to each. The changes are mechanical and self-contained, with no behavior changes yet. The new header itself is minimal, currently only banning `die()` (which trace2 already avoids), but its structure is designed for expansion. The choice to place it at the root of the tree (rather than in `trace2/`) signals intent to reuse it elsewhere, though no other subsystems are modified here.

This is a foundational patch—it sets up the scaffolding for the rest of the series, which will replace banned functions with defensive fallbacks in later patches. The commit message is concise but sufficient, and the patch itself is straightforward.
