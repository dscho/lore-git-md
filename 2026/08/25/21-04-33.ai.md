This is the second patch in the v8 series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. It extends the `unique_tracking_name()` function to optionally collect the names of matching remotes, then uses that information to provide a detailed, actionable advice message when ambiguity is detected. The advice now lists the conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes: origin, upstream") and suggests using `--track` or setting `checkout.defaultRemote` to resolve the issue.

The patch touches `builtin/checkout.c`, `checkout.c`, and `checkout.h`, introducing a new helper function `advise_disambiguating_remotes()` that formats the advice message based on the command (`checkout` or `switch`) and the list of matching remotes. The `unique_tracking_name()` function is updated to accept an optional `struct string_list *` parameter, which it populates with the names of remotes that have a matching branch. The advice message is gated behind the existing `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default).

The implementation moves the `die()` call earlier in the code path, replacing a generic "invalid reference" error with a more specific diagnostic that includes the number of matching remotes. This change is intentional and justified in the commit message: the problematic flow (silent failure to resolve ambiguity -> `NULL` remote -> misleading error) is explicitly traced to avoid disrupting existing workflows. The patch also fixes a grammatical error in the advice message ("Branches ... appears" -> "Branch name '%s' appears").

This patch is part of a well-reviewed, functionally complete series that has been queued for `next`. It addresses a real usability pain point by making ambiguous branch names easier to resolve, and the changes are cleanly integrated with the existing advice infrastructure. The test coverage (updated in later patches) verifies the new advice format and error message behavior.
