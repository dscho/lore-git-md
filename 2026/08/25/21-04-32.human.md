This is the first patch in a now-complete four-patch series improving error messages for ambiguous remote branch names in `git checkout`, `git switch`, and `git worktree add`. The series is already cooking in `next` and addresses a real usability pain point: users who run commands like `git checkout foo` when both `origin/foo` and `upstream/foo` exist now get clear, actionable advice instead of a terse warning.

This patch extracts the advice message logic into a shared helper function, `advice_disambiguating_remotes()`, so it can be reused across all three commands. The refactoring is clean and mechanical, moving the advice text from `parse_remote_branch()` into a separate function that takes the command type (`checkout` or `switch`) as an argument. The commit message is minimal, but the change itself is well-motivated: it reduces code duplication and sets the stage for the rest of the series.

The patch touches only `builtin/checkout.c` and makes no behavior changes—it’s pure refactoring. The extracted function will be extended in later patches to handle `git worktree add` and the `--guess-remote` edge case. If you care about Git’s usability or work on the checkout/switch code, this is a solid, uncontroversial step toward better error messages. The rest of the series (patches 2–4) builds on this foundation to deliver the actual improvements.
