This is the fourth patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort, which aims to simplify the ODB interface and move alternates handling into the "files" backend.

This patch moves the logic for setting up alternates in shared local clones from `clone_local()` into `collect_alternates()`. Previously, when cloning a local repository with `--shared`, the source repository’s objects directory was added to the new repository’s alternates file directly in `clone_local()`. Now, this logic is unified under `collect_alternates()`, which gathers all alternates (from `--reference` options and local clones) into a `strvec` before writing them to the alternates file. The change prepares for alternates to be written at ODB creation time, rather than after the fact.

The patch touches only `builtin/clone.c`, updating `collect_alternates()` to accept the source repository path and a flag indicating whether the clone is local. It also removes the now-redundant alternates setup from `clone_local()`. The change is mechanical and does not alter behavior, but it lays the groundwork for later patches that will eliminate the `write_alternates()` callback entirely. The commit message notes that `--no-shared` local clones are not yet handled in `collect_alternates()`; that will be addressed in the next patch.

This is a well-executed refactoring step with a clear purpose. The patch is uncontroversial and aligns with the series’ goal of unifying alternates handling. Reviewers will likely focus on ensuring the change doesn’t introduce regressions in local clone behavior, particularly around `--shared` and `--reference` interactions. The patch is part of a larger, well-motivated effort, and its incremental nature makes it easy to verify.
