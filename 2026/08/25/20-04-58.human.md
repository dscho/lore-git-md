This is the final patch in René Scharfe’s four-part series fixing and cleaning up `git worktree add`’s basename handling. Junio C Hamano’s reply is a **substantive review** that focuses on the commit message clarity rather than the code itself.

The patch renames `worktree_basename()` to `worktree_basename_dup()` and makes it return a freshly allocated string, eliminating the need for callers to perform pointer arithmetic or manual string slicing. Junio’s only concern is a minor wording ambiguity in the commit message: the phrase “Two already do” could be misread as “two callers already free the result,” which would be incorrect (and crash-prone). He suggests rephrasing to clarify that two callers already make their own copies, so returning a copy from the helper is a natural fit. The code change itself is uncontroversial and already improves readability in the three call sites.
