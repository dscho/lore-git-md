This is the second iteration of a four-patch bugfix series addressing a race condition in Git's geometric repacking mechanism that can cause objects to be incorrectly reported as missing, even when they exist in the repository. The issue arises when a multi-pack-index (MIDX) references a packfile that is subsequently removed by a geometric repack, leaving processes using the stale MIDX unable to locate objects. The series now includes two additional patches: one fixing a memory leak in `git mktree --batch` (used in new test cases) and another demonstrating and fixing problems with `OBJECT_INFO_QUICK` readers.

The core fix (patch 4/4) has evolved significantly since the first iteration. It now uses a tri-state return value from `fill_midx_entry()` to distinguish between objects missing from the MIDX, objects present but with an unavailable owning pack, and successfully located objects. The recovery logic is now gated on `OBJECT_INFO_SECOND_READ`, ensuring that `QUICK` callers (like `git replay`) only incur the cost of scanning MIDX-covered packs if the initial lookup fails and a refresh is attempted. This addresses performance concerns raised by Jeff King (Peff) while preserving correctness. The fix is well-motivated by production evidence, touching multiple server-side operations including `git replay`, `git merge-tree`, `git diff`, and object resolution commands like `rev-parse` and `cat-file`.

The series is now rebased on `ps/odb-generic-corrupt-objects`, with conflicts resolved. Test coverage has been expanded to include scenarios for both the `git replay` crash (patch 1/4) and the MIDX recovery logic (patch 4/4), as well as new tests for `QUICK` reader problems (patch 3/4) and the `git mktree --batch` leak (patch 2/4). The patches are small, focused, and include clear commit messages, suggesting a high-quality fix. The discussion in the thread has converged on the design, with no remaining technical objections to the core fix. This series is likely to be uncontroversial and should be a priority for merging. Derrick Stolee's suggestion to defer pack deletion via `git multi-pack-index expire` is acknowledged as a complementary mitigation but is not part of this series.
