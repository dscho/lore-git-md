This is the final patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort, and this patch removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure.

The patch deletes the `write_alternate` callback from all ODB source implementations (`files`, `inmemory`, `loose`, and `packed`), along with the public `odb_add_to_alternates_file()` function and its helper `odb_source_write_alternate()`. This cleanup is the logical conclusion of the series: earlier patches moved all alternates handling into the ODB creation phase, making post-creation alternates writing unnecessary. The changes are mechanical and remove roughly 120 lines of code across seven files, with no user-visible behavior changes.

This is a well-justified refactoring. The commit message clearly states that there are no remaining users of the removed functionality, and the series’ earlier patches have already consolidated alternates setup into a single step during ODB creation. The patch is uncontroversial—it simply removes dead code—and aligns with the broader goal of simplifying the ODB interface by making alternates an implementation detail of the backend.

Reviewers are unlikely to raise substantive objections, though they may verify that all alternates handling has indeed been routed through the new mechanism (introduced in patch 6). The patch is ready for merging once the rest of the series is approved, and it represents a clean step forward in the ODB abstraction effort.
