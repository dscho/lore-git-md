This is a refactoring patch from René Scharfe, part of a small series (4/4) targeting the worktree subsystem. It simplifies the `worktree_basename()` function by having it return a freshly allocated string copy of the basename instead of requiring callers to perform pointer arithmetic. The function is renamed to `worktree_basename_dup()` to remind callers that they must free the result.

The patch touches only `builtin/worktree.c`, converting three call sites to use the new API. Two already freed the result; the third switches from resetting a shared `strbuf` to freeing the allocated string, keeping the line count the same but removing the need for manual offset calculations. The commit message notes that the added allocation is negligible since it happens only once per `git worktree add` invocation.

This is a clean, mechanical change that aligns with the project’s ongoing preference for reducing manual memory management footguns. The rationale is clear, the implementation is straightforward, and the patch looks ready for review. If you care about worktree internals or memory hygiene, it’s worth a quick look.
