This is the fifth patch in Derrick Stolee’s seven-part **bugfix and hardening series** for the trace2 subsystem, continuing the effort to eliminate all `die()`-triggering helpers from the trace2 API. This patch removes the use of `xstrfmt()`—a function that calls `die()` on formatting failures—from `trace2.c` and replaces it with manual string concatenation using `memcpy()` to avoid crashing Git when memory allocation or string formatting fails.

The change targets the `redact_arg()` function, which redacts sensitive information (e.g., passwords) from URLs in trace2 output. Previously, `xstrfmt()` was used to construct the redacted string, but this could trigger a `die()` if formatting failed. The new implementation manually allocates memory for the redacted string, checks for overflow, and uses `memcpy()` to concatenate the prefix, redacted placeholder (`:<REDACTED>`), and suffix. If any step fails (e.g., allocation or overflow), the function returns `NULL`, and the calling code (`redact_argv()`) propagates the failure by freeing any partially allocated memory and returning `NULL` to its callers. This ensures trace2 degrades gracefully under failure conditions rather than crashing.

The patch also updates `banned-die.h` to block `xstrfmt()`, enforcing the constraint across the trace2 subsystem. The manual string construction is more verbose but necessary to avoid `die()` calls while preserving the redaction logic. The behavior change is subtle: trace2 will now drop redacted arguments (or entire trace events) when allocation or formatting fails, rather than crashing. This aligns with the series’ goal of prioritizing process stability over telemetry completeness.

The patch is well-motivated and technically sound, with clear commit message explanations and careful handling of edge cases (e.g., overflow checks, partial allocation cleanup). It builds directly on the earlier patches in the series, which introduced `banned-die.h` and replaced other `die()`-triggering helpers (`xsnprintf()`, `xstrdup()`, `ALLOC_ARRAY()`) with defensive fallbacks. No new objections or concerns are raised here, and the approach is consistent with the agreed hardening strategy.

Key technical details:
- **Files touched**: `banned-die.h` (to block `xstrfmt()`) and `trace2.c` (to replace `xstrfmt()` with manual string construction).
- **Behavior change**: `redact_arg()` now returns `NULL` on failure (allocation or overflow) instead of calling `die()`. Callers (`redact_argv()`) propagate this failure, degrading trace2 output rather than crashing.
- **Edge cases**: The patch handles overflow checks (`unsigned_add_overflows()`) and partial allocation cleanup (freeing memory if later steps fail).
- **Test coverage**: None, as the issue depends on transient allocation failures. This is consistent with the rest of the series.
- **Related work**: This is part of the broader trace2 hardening effort, which includes patches 1–4 (introducing `banned-die.h` and replacing other banned functions) and patches 6–7 (targeting `ALLOC_GROW()` and `xcalloc()`).
