This is the third patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The patch focuses on `builtin/clone.c` and prepares the ground for later changes that will consolidate alternates handling into the ODB backend.

The patch renames `setup_reference()` to `collect_alternates()` and refactors it to gather all alternate paths into a `strvec` instead of immediately writing them to the alternates file. This is a mechanical change that defers the actual writing of alternates until after the ODB is created, aligning with the series’ goal of moving alternates handling into the ODB backend. The new `add_one_alternate()` helper replaces `add_one_reference()` and uses a `struct add_one_alternate_data` to track whether an alternate is required or optional, along with the `strvec` for collected paths.

No user-visible behavior changes are introduced; the patch is purely preparatory. The motivation is to simplify the ODB interface by eventually removing the ability to write alternates after repository creation, making alternates an implementation detail of the ODB backend. Reviewers will likely focus on ensuring the refactoring doesn’t introduce edge-case regressions in `git clone --reference` or URI rewriting, though the mechanical nature of this patch may limit substantive feedback.

Key symbols introduced or modified include `collect_alternates()`, `add_one_alternate()`, and `struct add_one_alternate_data`. The patch touches only `builtin/clone.c` and is part of the broader ODB abstraction effort, building on `ps/odb-eagerly-load-alternates`. Later patches in the series will remove the now-unused `write_alternates()` callback and further consolidate alternates handling.
