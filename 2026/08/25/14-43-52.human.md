This is a follow-up in the ongoing RFC thread about making Git's stash stack configurable per-worktree. Phillip Wood responds to Junio C Hamano's refinement of the branch-aware stash design, clarifying how stash messages are already structured in a way that could support encoding branch information.

Phillip points out that Git already prepends branch information to stash messages in `create_stash()`. If the user supplies a custom message (via `-m`), Git prepends `"On $branch: "`; if no message is provided, it uses `"WIP on $branch ..."`. This existing structure means the branch name is already machine-readable at the start of the message, which could be leveraged for the branch-aware stash design without requiring changes to the `-m` option or breaking backward compatibility. The discussion is now focused on whether this existing format is sufficient for the proposed branch-aware filtering, or if further adjustments (like Junio's colon-separated suffix) are needed.

The thread remains constructive and technical, with no new objections raised. The original `stash.ref` config knob proposal is still sidelined in favor of the branch-aware approach, but Phillip's observation simplifies the implementation path. The key open question is whether the current message format is robust enough for branch-aware operations (e.g., handling branch names with colons or spaces) or if additional parsing rules are required. No decisions have been made yet, but the conversation is narrowing toward a practical design.
