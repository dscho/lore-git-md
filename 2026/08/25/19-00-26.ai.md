This is the first patch in Elijah Newren’s v2 four-patch bugfix series addressing a race condition in Git’s geometric repacking mechanism. It fixes a SIGSEGV in `git replay` when merge inputs are unreadable by explicitly handling the case where `result->clean < 0` (indicating a read failure) rather than only checking `!result->clean`. The fix is minimal: it adds an early return with an error message when `clean < 0`, preventing the code from dereferencing `result->tree` (which remains NULL in this case). The accompanying test simulates the scenario by removing the tree object for the `--onto` commit, verifying that `git replay` fails gracefully with an appropriate error message rather than crashing.

The patch touches `replay.c` and adds a new test case to `t/t3650-replay-basics.sh`. The test constructs a simple three-commit history, replays a commit onto a base, then removes the tree object for the `--onto` commit to trigger the read failure. The test checks for the expected error messages ("Could not read" and "collecting merge info failed") that the merge machinery already emits. Junio’s review of v1 requested removing a redundant `test_grep` check, which Elijah has addressed in this version.

This is a targeted bugfix with clear motivation and thorough test coverage. The fix is uncontroversial and aligns with the series’ overall goal of making server-side operations like `git replay` robust against missing objects caused by race conditions in geometric repacking. The patch is ready for merging and has no dependencies beyond the series itself.
