This is the seventh patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort, which aims to simplify the ODB interface and prepare for alternates to become an implementation detail of the ODB backend.

This patch wires up the new alternates-at-creation mechanism introduced in earlier patches. Previously, alternates were written in a separate step after the ODB was initialized, requiring a `write_alternates()` callback. Now, alternates are passed directly to `create_object_database()` via a `strvec` in the `odb_create_on_disk_options` struct, consolidating the process into a single step. The change removes the need for `odb_add_to_alternates_file()` in `builtin/clone.c` and updates `create_object_database()` to accept an optional `alternates` parameter.

The patch is small and mechanical, touching only `builtin/clone.c`, `setup.c`, and `setup.h`. It replaces the explicit alternates-writing loop in `cmd_clone()` with a single call to `create_object_database()`, passing the collected alternates. The change is straightforward and aligns with the series’ goal of simplifying the ODB interface. No user-visible behavior changes are expected, and the patch is unlikely to be controversial.

This is a well-crafted step in the refactoring, removing redundant code and preparing for future work where alternates become a backend-specific detail. The patch is clean and focused, with no obvious loose ends. Reviewers may check for edge cases around `NULL` alternates handling, but the implementation looks solid. The series as a whole remains on track for merging as part of the ODB abstraction effort.
