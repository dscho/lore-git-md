This is the fourth patch in the v5 series adding path-related keys to `git repo info`. It implements `path.index.absolute` and `path.index.relative`, exposing the repository’s index file location in a scriptable format.

The patch is straightforward: it adds two new keys that return the canonical absolute path and the relative path (from the current directory) to the index file, respecting the `GIT_INDEX_FILE` environment override. The implementation reuses `repo_get_index_file()` and the existing `format_path()` helper, following the established pattern from earlier patches in the series. Documentation and tests are included, covering standard cases, environment overrides, and bare-repository edge cases.

The behavior aligns with the series’ design principle: the keys return the configured index path unconditionally, even in bare repositories or when the file does not exist, matching `git rev-parse --git-path index` precedent. This was explicitly endorsed by Junio in earlier iterations and is now locked in by tests. The commit message is clear and the patch is mechanically clean, addressing all prior feedback.

This patch is uncontroversial and ready for final review. The only potential discussion points are minor naming tweaks (e.g., `path.index-file` instead of `path.index`), but the current name is consistent with the rest of the series and unlikely to change.
