This is the third patch in Derrick Stolee’s seven-part series hardening the trace2 subsystem against crashes caused by `die()`-triggering helpers. It removes the use of `xstrdup()` in `trace2/tr2_sysenv.c`, replacing it with `strdup()` and defensive fallbacks to prevent process termination under memory pressure.

The patch is small and focused: it updates `banned-die.h` to block `xstrdup()` in trace2 code and modifies two functions in `tr2_sysenv.c` to handle allocation failures gracefully. In `tr2_sysenv_cb()`, a failed `strdup()` now returns `-1` to halt config parsing, while in `tr2_sysenv_get()`, a failed `strdup()` returns `NULL`—indistinguishable from an unset environment variable. The commit message explains this trade-off: trace2 prioritizes process stability over telemetry completeness, and callers already handle `NULL` returns.

This aligns with the series’ broader goal of eliminating all `die()`-triggering helpers from trace2, ensuring the subsystem never crashes Git even under transient failures. The changes are minimal and self-contained, touching only the trace2 subsystem, and the defensive fallbacks are pragmatic given the difficulty of testing allocation failures. No objections or concerns were raised in the thread context, and the approach mirrors the earlier `xsnprintf()` patch (v2 2/7).
