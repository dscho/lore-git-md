This is the fifth patch in the v5 series adding path-related keys to `git repo info`. It implements `path.grafts.absolute` and `path.grafts.relative`, exposing the location of the repository’s graft file in a scriptable format. The graft file specifies alternate parent relationships for commits and is used by repository tooling; scripts currently retrieve its location via `git rev-parse --git-path info/grafts`.

The implementation uses `repo_get_graft_file()` to respect the `GIT_GRAFT_FILE` environment override and `format_path()` to return canonical absolute or relative paths. Both keys return the graft file path unconditionally, even if the file does not exist or the repository is bare, aligning with `git rev-parse --git-path` precedent and Junio C Hamano’s endorsement in earlier iterations. The documentation explicitly states this behavior, and the tests cover the standard case and a `GIT_GRAFT_FILE` override.

The patch touches `builtin/repo.c` (adding `get_path_grafts_absolute()` and `get_path_grafts_relative()`), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding tests). The commit message is clear, and the implementation follows the established pattern from earlier patches in the series. No substantive design questions remain for this patch; the only open discussion points are minor naming consistency (e.g., `path.graft-file` vs. `path.grafts`) and whether the unconditional path-return behavior is intuitive, but these are settled for the series as a whole. The patch is mechanically clean and ready for final review.
