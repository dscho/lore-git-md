This is a two-patch feature series that prevents `git branch -d` from deleting local branches that are upstream dependencies of other local branches. The motivation is to protect "stacked" branch workflows where one local branch builds on another, and deleting an intermediate branch could break the chain.

The first patch is a refactoring that moves helper functions related to stacked branches into a more logical location in `builtin/branch.c`. The second patch implements the core protection: when `git branch -d` is run, Git now checks whether any other local branch has the target branch set as its upstream, and refuses to delete it if so. The behavior change is documented in `git-branch.adoc`, and new tests in `t3200-branch.sh` verify the protection works as intended.

The series is narrowly scoped and well-structured, with clear separation between refactoring and new functionality. The commit messages explain the rationale and the implementation approach without overpromising. The test coverage looks adequate for the change, though the real-world impact on stacked branch workflows will likely be the main discussion point.

This is a user-facing change that could affect common workflows, so it may attract attention from contributors who rely on stacked branches or have strong opinions about safety checks in `git branch -d`.
