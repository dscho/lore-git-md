This is the fifth patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation, part of the broader ODB abstraction effort. The patch moves the setup of alternates for non-shared local clones into `collect_alternates()`, completing the consolidation of alternates collection logic begun in earlier patches.

The key change here is the extraction of alternates reading from `copy_alternates()` (now renamed to `read_alternates()`) into `collect_alternates()`. This fixes a latent bug: previously, Git failed to resolve the common directory of a referenced repository when cloning from a worktree, which meant alternates were not correctly set up. The patch leverages the already-resolved common directory path in `collect_alternates()` to address this. Two new tests verify the fix: one ensures alternates are correctly carried over when cloning from a linked worktree, and another confirms relative alternates paths are resolved properly.

The diff touches `builtin/clone.c` and adds tests to `t/t5604-clone-reference.sh`. The changes are mechanical but meaningful: they eliminate redundant code paths and ensure alternates are handled consistently regardless of whether the clone is shared or local. The patch is well-motivated, with clear commit message explanations and test coverage for the edge cases it addresses. No regressions are expected, and the consolidation aligns with the series’ goal of simplifying the ODB interface by moving alternates handling into a single, controlled code path.
