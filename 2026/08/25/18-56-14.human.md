This is a **bugfix and hardening series** targeting the trace2 subsystem. Derrick Stolee expands his earlier patch (which fixed a crash in timestamp formatting) into a comprehensive effort to eliminate all uses of `die()`-triggering helpers (`xsnprintf`, `xstrdup`, `ALLOC_ARRAY`, `xstrfmt`, `ALLOC_GROW`, `xcalloc`) from the trace2 API. The goal is to prevent process-ending failures in trace2, which can cause infinite recursion during error reporting (e.g., in `atexit` handlers).

The series introduces a new `banned-die.h` header that blocks these functions in trace2 files, then systematically replaces each one with defensive alternatives. For example, `xsnprintf` is replaced with `snprintf` (falling back to a hardcoded timestamp on failure), and `xstrdup` is replaced with `strdup` (dropping messages if allocation fails). The changes prioritize stability over completeness—trace2 may log incomplete or missing data during failures, but the process won’t crash.

This v2 addresses feedback from the earlier thread, where memory allocation failures (particularly in Git for Windows) were identified as the root cause of the original crash. The series is well-motivated and thorough, with clear commit messages explaining each change. It touches 15 files, primarily in the `trace2/` directory, and adds a new `banned-die.h` header to enforce the restrictions. No tests accompany the series, as the failures (allocation errors, system call issues) are hard to reproduce.

The approach is pragmatic and aligns with the project’s focus on robustness in low-level subsystems. While the series doesn’t solve the underlying allocation issues in Git for Windows, it ensures trace2 won’t be the vector for crashes. This looks like a solid, uncontroversial improvement that addresses a real problem.
