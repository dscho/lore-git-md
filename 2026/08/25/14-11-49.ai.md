This is the cover letter for an 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort, specifically preparing to move alternate handling into the "files" backend.

The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation. Currently, alternates can be added at any time via `odb_source_write_alternate()`, but in practice, Git only uses this during initial repository setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback. This change also paves the way for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration.

The patches touch `builtin/clone.c` (refactoring reference handling and deferring ODB setup), `odb/source-files.c` (adding support for writing alternates during creation), and several ODB source files (removing the now-unused `write_alternates()` callback). The series also updates tests to verify the new behavior. The motivation is clear: reducing complexity in the ODB interface while aligning with the broader ODB abstraction effort. The changes are mechanical but foundational, with no user-visible behavior changes expected.

This is a well-structured series with a focused technical goal. The cover letter explains the rationale and ties the work to the larger ODB refactoring effort. The patches themselves are likely to be uncontroversial, as they remove unused flexibility rather than introduce new behavior.
