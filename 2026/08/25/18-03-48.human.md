This is the second patch in René Scharfe’s four-part series fixing edge cases in `git worktree add`. It targets a specific bug: when the input path consists solely of slashes (e.g., `///`), the `worktree_basename()` helper returns an empty string, which later triggers a BUG message. René’s fix adds a check in `add_worktree()` to reject such paths early with a clear error message instead of letting the code fail obscurely.

The change is minimal and surgical: two lines added to `builtin/worktree.c` and a single test case in `t/t2400-worktree-add.sh` that verifies `git worktree add "" HEAD` fails as expected. The patch is well-motivated—it prevents a confusing BUG message and replaces it with a user-friendly error. No controversy is evident; this looks like a straightforward improvement that plugs a small but real gap in input validation. If the series lands as-is, this patch will be uncontroversial.
