This is the third patch in Derrick Stolee’s seven-part **bugfix and hardening series** for the trace2 subsystem, which aims to eliminate all `die()`-triggering helpers to prevent Git crashes during telemetry operations. This patch removes the use of `xstrdup()` from `trace2/tr2_sysenv.c`, replacing it with `strdup()` and defensive fallbacks to handle allocation failures gracefully.

The changes are straightforward but important. In `tr2_sysenv_cb()`, the patch ensures the config parsing loop halts if `strdup()` fails by returning a negative value. In `tr2_sysenv_get()`, the method now returns `NULL` when `strdup()` fails, which callers already handle as a valid response (indistinguishable from an unset environment variable). This trade-off prioritizes process stability over telemetry completeness—trace2 will drop or degrade data under memory pressure rather than crash.

The patch also updates `banned-die.h` to block `xstrdup()`, reinforcing the series’ architectural goal of systematically enforcing "no `die()` in trace2." The commit message clearly explains the rationale and the behavior change, though it acknowledges the limitation that callers won’t distinguish between a missing environment variable and an allocation failure. This is a pragmatic choice, as the latter case is likely to trigger other failures elsewhere in the system.

No test coverage is added, as the issue depends on transient allocation failures that are hard to reproduce. The patch is well-motivated and aligns with the series’ broader goal of hardening trace2 against crashes. Reviewers should focus on whether the fallback behavior is acceptable for trace consumers and whether the enforcement mechanism in `banned-die.h` is appropriately scoped. This looks like a solid, incremental step in the series.
