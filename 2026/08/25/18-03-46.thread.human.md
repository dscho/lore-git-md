This thread is a four-patch series from René Scharfe that fixes a data-corruption bug in `git worktree add`. The series targets the `worktree_basename()` helper, which had an out-of-bounds read when given an empty path—an issue reported in Git for Windows (issue #6346). The first patch, just posted, fixes the immediate bug with a minimal bounds check and is credited in part to Matthias Aßhauer.

The rest of the series cleans up related edge cases: rejecting paths made only of slashes, normalizing trailing-slash handling, and simplifying memory management by returning a string copy. All changes are confined to `builtin/worktree.c` and are tested in `t/t2400-worktree-add.sh`. No prior version of this series exists, and it’s under initial review. The only open question is whether reviewers will want more test coverage or reconciliation with an earlier stalled effort on the same code. So far, only René has weighed in.
