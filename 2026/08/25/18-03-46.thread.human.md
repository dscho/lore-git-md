This thread is a four-patch series from René Scharfe fixing bugs and edge cases in `git worktree add`'s basename handling. The series targets a real-world issue reported in Git for Windows (issue #6346) that can cause data corruption via an out-of-bounds read, along with other related problems like rejecting malformed paths and normalizing trailing-slash behavior.

So far, three of the four patches have been posted. The first two address the most critical issues: patch 1 fixes the out-of-bounds read that could corrupt memory, and patch 2 rejects paths consisting solely of separators (e.g., `"/"`), which previously triggered a BUG assertion. The third patch, just posted, trims trailing slashes from derived branch names—a subtle but important fix, since branch names cannot end with slashes. Each patch includes new tests in `t/t2400-worktree-add.sh` to cover the edge cases. The series is under review, with no feedback yet from other contributors. The remaining patch (not yet summarized) will simplify memory management by returning a string copy. No controversy has emerged so far; the changes appear to be straightforward bugfixes with solid test coverage.
