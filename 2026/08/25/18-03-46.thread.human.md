This thread is about René Scharfe’s four-patch series fixing bugs and edge cases in `git worktree add`, specifically in the `worktree_basename()` helper. The series addresses an out-of-bounds read that could cause data corruption, rejects malformed paths like `"/"` or `"//"`, trims trailing slashes from derived branch names, and simplifies memory management by returning a freshly allocated string copy. The patches target `builtin/worktree.c` and add tests in `t/t2400-worktree-add.sh`.

Junio C Hamano reviewed and approved all four patches, applying a minor commit-message tweak to Patch 4 to clarify that two callers already copy the returned string. With that resolved, the series has now been merged to the `next` branch for final integration testing. No further review or resend is expected unless new issues arise during cooking. The fixes address a real-world issue reported in Git for Windows (issue #6346) and supersede an earlier stalled effort.
