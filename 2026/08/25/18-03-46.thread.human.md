This thread is a four-patch series from René Scharfe that fixes and cleans up the `worktree_basename()` helper in `git worktree add`. The series addresses a real-world issue reported in Git for Windows (issue #6346), including an out-of-bounds read that could cause data corruption, a BUG assertion triggered by paths consisting solely of separators, and inconsistent handling of trailing slashes in branch names. The first three patches—fixing the bounds check, rejecting malformed paths, and trimming trailing slashes—have already been reviewed and confirmed by Junio C Hamano, who noted the user-visible symptom of invalid branch names like `bit/` when adding worktrees with trailing slashes.

The fourth and final patch, which Junio just reviewed, renames the helper to `worktree_basename_dup()` and makes it return a freshly allocated string copy, simplifying memory management for its callers. Junio’s only feedback was a minor clarification to the commit message to avoid ambiguity about whether callers were already freeing the result (they weren’t). The code change itself is uncontroversial and has Junio’s approval. With this, the series is effectively ready to move forward, pending a possible tweak to the commit message. No further technical objections or open questions remain.
