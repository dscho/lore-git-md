This thread is a four-patch series from René Scharfe that fixes and cleans up the `worktree_basename()` helper in `git worktree add`. The series addresses a real-world issue reported in Git for Windows (issue #6346), including an out-of-bounds read that could cause data corruption, improper handling of malformed paths (like those consisting solely of separators), and inconsistent behavior with trailing slashes in derived branch names. The patches also simplify the code by introducing a new helper, `worktree_basename_dup()`, which returns a freshly allocated string copy instead of a pointer into the input buffer.

The series has been under review and is effectively ready to advance. Junio C Hamano, the maintainer, has reviewed all four patches and signaled approval for the code changes. His only request was a minor clarification in the commit message of Patch 4 to avoid ambiguity about whether callers already free the returned string. René has accepted this tweak, and the series is now poised for integration once the commit message is updated. No further technical discussion or changes are expected.

The patches touch `builtin/worktree.c` and add tests in `t/t2400-worktree-add.sh`, covering edge cases like trailing slashes and separator-only paths. The series supersedes an earlier stalled effort and is motivated by a concrete bug report, making it a targeted and actionable fix.
