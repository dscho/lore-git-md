This thread is about a bugfix for `git am --3way` where a multi-patch series modifying the same file fails on the second patch because its preimage (the postimage of the first patch) wasn’t recorded. Nikita Leshenko proposed a fix that records postimages even for cleanly applied patches, but Junio C Hamano has raised a major performance concern: the solution would spawn an extra `git apply` process, write temporary index files, and generate loose objects for *every* cleanly applied patch in a series—meaning a 50-patch series would incur 49 unnecessary operations.

Junio instead suggests a lazy approach: when `fall_back_threeway()` fails to find a preimage, it should reconstruct the blob in-memory by applying only the relevant patches from `.git/rebase-apply/`, avoiding per-patch overhead. The discussion is now focused on whether Nikita can implement this alternative or justify why the original approach is necessary. No decisions or merges have been made yet, and the thread is waiting on the author’s response. The key technical trade-off is between correctness (fixing the edge case) and performance (avoiding unnecessary work).
