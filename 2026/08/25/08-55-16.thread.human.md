This thread is about a bugfix for `git am --3way` that addresses a specific edge case in patch application. The issue occurs when a multi-patch series modifies the same file, and while the first patch applies cleanly, the second fails because its preimage hash (the postimage of the first patch) wasn't recorded in the repository. Nikita Leshenko's patch fixes this by ensuring that even cleanly applied patches record their postimage when `--3way` is enabled, allowing subsequent patches to use 3-way merges.

The fix is isolated to `builtin/am.c` and introduces a new helper function `try_record_patch_postimage()` that applies the patch to a temporary index to record the postimage blob. The patch also updates `run_apply()` and `build_fake_ancestor()` to support quiet operation, suppressing error output when the recording is best-effort. A new test in `t/t4150-am.sh` verifies the fix by constructing a two-patch series where the first patch applies cleanly and the second requires a 3-way merge. The commit message is detailed and explains the problem, solution, and trade-offs clearly.

So far, the patch appears to be a well-motivated and straightforward fix for a real-world issue, with thorough test coverage and no obvious downsides beyond a minor performance cost (one extra `git apply` process per clean patch when `--3way` is used). No reviews or discussions have been posted yet, so the patch is still under initial consideration.
