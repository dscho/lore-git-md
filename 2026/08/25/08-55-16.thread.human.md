This thread is about a bugfix for `git am --3way` where a later patch in a series fails with "sha1 information is lacking or useless" because its preimage (the postimage of an earlier patch) wasn’t recorded. The original patch proposed recording postimages for every cleanly applied patch, but Junio C Hamano objected to the performance overhead—spawning extra processes and writing temporary files for every patch in a series.

Nikita Leshenko has now responded with a simpler alternative that avoids the per-patch cost. Instead of Junio’s suggested "lazy reconstruction" (which would surgically apply only the necessary prior patches), Nikita proposes a coarser approach: when the failure occurs, apply *all* prior patches (1 through N-1) on their fake ancestors to generate the missing preimage for patch N. To avoid repeating this expensive operation for every subsequent patch, the approach tracks how far the reconstruction has progressed in the `am_state` (`.git/rebase-apply/`), so only the necessary subset of patches is reapplied if another patch later fails. This trades some performance for simplicity and correctness, ensuring the fix works without the complexity of tracking individual blobs.

The patch is still under review, with the key question being whether Junio finds this trade-off acceptable. The fix remains internal to `git am --3way`, with no new user-facing changes or on-disk format modifications. Nikita’s proposal is pragmatic, but Junio may still prefer the more optimized lazy reconstruction if he believes the overhead is too high for large series. No other participants have weighed in yet.
