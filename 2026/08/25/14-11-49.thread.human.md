This thread is Patrick Steinhardt’s eight-patch series refactoring how Git handles ODB alternates during repository creation, part of the larger ODB abstraction effort. The goal is to remove the ability to write alternates after repository creation, simplifying the ODB interface by making alternates an implementation detail of the backend. Currently, alternates can be added at any time via `odb_source_write_alternate()`, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback.

The series is now technically complete with v2, addressing the primary blocker from v1: adopting Git’s standard lockfile API for writing the `info/alternates` file in patch 6, which resolved TOCTOU race and concurrent access concerns raised by Junio C Hamano and Toon Claes. Patches 1-5 refactored reference handling in `git clone`, deferring ODB setup and consolidating alternates logic into `collect_alternates()`. Patch 1 introduced the `INIT_DB_SKIP_ODB` flag to defer ODB initialization until after URI resolution, ensuring alternates are written with full context. Patch 3 renamed `setup_reference()` to `collect_alternates()` and introduced new structures to gather alternates paths into a `strvec`. Patch 4 extended this to handle shared local clones, and patch 5 (the latest update) completed the consolidation by moving non-shared local clones into `collect_alternates()`, fixing a latent bug in worktree alternates handling and adding test coverage for edge cases. Patches 6-8 implement the core design change, introducing `odb_create_on_disk_options` to write alternates during ODB creation and removing the now-unused `write_alternates()` infrastructure.

Junio C Hamano’s review of v1 raised a security concern about patch 6’s use of append mode for writing alternates, prompting Patrick to adopt the lockfile API in v2. Toon Claes provided reviews of several patches, with his earlier comments focusing on surface-level code structure without engaging deeply with technical substance. His review of patch 8 raised a substantive concern about locking, which is now resolved by the lockfile API adoption. Patrick has addressed all substantive feedback, and the series is expected to proceed to integration once ODB-focused contributors (e.g., Justin Tobler, Karthik Nayak) review patches 6-8. No user-visible changes are introduced, and the series is foundational for the broader ODB abstraction effort.
