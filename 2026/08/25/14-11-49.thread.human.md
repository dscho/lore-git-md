This thread is Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation, part of his ongoing ODB abstraction work. The goal is to remove the ability to write alternates after repository creation, simplifying the ODB interface by making alternates an implementation detail of the backend. The series is under review, with no prior versions or merge status reported.

The first three patches were mechanical refactorings in `builtin/clone.c` and `setup.c`, deferring ODB creation and gathering alternates into a `strvec` instead of writing them immediately. Patch 4 (the latest email) continues this work by moving the logic for shared local clones (`git clone --shared`) into the refactored `collect_alternates()` function. This unifies alternate handling and adds two new parameters to the function: the source repository path and a boolean indicating whether the clone is local. The changes are straightforward and don’t alter behavior, but reviewers may check for edge cases in URI rewriting or alternate requirements.

The series is built on Patrick’s earlier `ps/odb-eagerly-load-alternates` branch and is expected to attract review from ODB-focused contributors like Justin Tobler and Karthik Nayak. While the early patches are mechanical, later ones—particularly those removing the `write_alternates()` callback—will likely draw more scrutiny. No substantive feedback has been recorded yet, but the groundwork laid here is key to making alternates an ODB backend detail.
