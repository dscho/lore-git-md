Patrick Steinhardt’s eight-patch series to refactor how Git handles ODB alternates during repository creation is nearing readiness after addressing the main blocker—a lockfile API adoption in patch 6 that resolved TOCTOU race and concurrent access concerns raised by Junio C Hamano. The series, part of the larger ODB abstraction effort, removes the ability to write alternates after repository creation, simplifying the interface by consolidating alternates setup into a single step during ODB initialization.

The first five patches refactored `git clone` to defer ODB creation until after alternates paths are fully resolved, fixing a latent bug in worktree alternates handling and centralizing alternates logic into a new `collect_alternates()` function. Justin Tobler’s recent review of the first patch accepted the technical rationale but raised a forward-looking concern about the growing complexity of `init_db()`’s "skip" flags, suggesting it might be cleaner to require explicit setup of the refdb and ODB instead. This feedback, while not demanding immediate changes, highlights a potential maintainability issue as the interface evolves. The remaining patches (6-8) implement the core design change—writing alternates during ODB creation via a new `odb_create_on_disk_options` struct—and remove the now-unused `write_alternates()` infrastructure. These patches have not yet attracted substantive review beyond Toon Claes’s surface-level approval of the cover letter, leaving the door open for further scrutiny from ODB-focused contributors like Karthik Nayak. The series is technically complete and expected to proceed to integration once the remaining patches receive closer attention.
