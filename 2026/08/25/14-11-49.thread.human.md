This thread is about Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating the logic into a single step during ODB setup. This is part of the broader ODB abstraction effort, which aims to make alternates an implementation detail of the ODB backend.

The series is under active review, with all patches posted and feedback focused on two key areas. The first is a latent bug fix in worktree alternates handling (patches 1-5), which deferred ODB setup in `git clone` and consolidated alternates logic into a new `collect_alternates()` function. These changes were uncontroversial and addressed edge cases like unresolved common directory paths. The second, more contentious area is the core design change in patch 6, which introduces `odb_create_on_disk_options` to write alternates during ODB creation. Junio C Hamano raised a substantive concern about the patch’s use of append mode (`"a"`) instead of Git’s standard lockfile API for writing the `info/alternates` file, warning of potential TOCTOU races or partial writes. Toon Claes also questioned the removal of the lockfile mechanism in patch 8, suggesting the new implementation might not be safe under concurrent access.

Patrick has addressed minor code hygiene suggestions, such as reorganizing header includes in patch 6, but the locking issue remains unresolved. The series is built on `ps/odb-eagerly-load-alternates` and is a foundational step for the ODB abstraction effort, but further discussion is needed before it can progress. No other reviewers have weighed in on the locking concern, though contributors like Justin Tobler or Karthik Nayak may yet engage given their involvement in the ODB effort. For now, the series is stalled on the locking question, with no clear path forward until that’s settled.
