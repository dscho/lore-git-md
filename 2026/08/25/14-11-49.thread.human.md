This thread is Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation, part of his larger effort to abstract the object database. The goal is to remove the ability to write alternates after repository creation, simplifying the ODB interface and preparing for alternates to become an implementation detail of the backend. The series has now reached its final patch, which removes the unused `odb_source_write_alternates()` function and its supporting infrastructure across all ODB backends.

The key changes were introduced in earlier patches: deferring ODB creation in `git clone` until after URI resolution (patch 1), consolidating alternates logic into a single code path (patches 3-5), and adopting Git’s standard lockfile API for atomic writes (patch 6). These changes addressed a latent bug in worktree alternates handling and resolved security concerns about TOCTOU races and concurrent access, which Junio C Hamano raised during the v1 review. The final patch is a clean-up step, removing redundant code after all callers of the old alternates-writing mechanism were eliminated in patch 7.

The series has been uncontroversial since v2, with no substantive objections remaining. Toon Claes provided reviews of several patches, but his comments were mostly surface-level, and his earlier concern about locking was resolved by the lockfile API adoption. The series is now technically complete and expected to proceed to integration once ODB-focused contributors like Justin Tobler and Karthik Nayak have had a chance to review the final patch. This work is a foundational step toward simplifying the ODB interface and aligns with the broader goal of making alternates an implementation detail of the backend.
