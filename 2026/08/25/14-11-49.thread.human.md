Patrick Steinhardt’s eight-patch series refactoring ODB alternates handling during repository creation is now in its second iteration, addressing the last major blocker from v1—the adoption of Git’s standard lockfile API for writing the `info/alternates` file. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating all alternates setup into a single step during ODB initialization. This change is part of the broader ODB abstraction effort, preparing for alternates to become an implementation detail of the ODB backend.

The series has seen no substantive technical objections since v2 was posted. Junio C Hamano’s earlier concern about TOCTOU races and concurrent access was resolved by switching to the lockfile API in patch 6, and Toon Claes, who reviewed several patches in v1, has now given a brief but unqualified approval to the cover letter. His response, however, was purely surface-level—no engagement with the technical changes or edge cases—so the series is still awaiting deeper scrutiny from ODB-focused contributors like Justin Tobler or Karthik Nayak. The refactoring itself is now technically complete, with patches 1-5 consolidating alternates logic in `git clone` and patches 6-8 implementing the core design change and removing the old infrastructure. No user-visible behavior changes are expected, but the series fixes a latent bug in worktree alternates handling and ensures alternates are written with full context, including URI rewrites from template configurations. The next step is likely integration once the remaining reviewers have had a chance to weigh in on the final patches.
