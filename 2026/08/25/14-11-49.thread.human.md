This thread is Patrick Steinhardt’s eight-patch series refactoring how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating all alternates setup into a single step during ODB creation. The series is part of the ongoing ODB abstraction effort, which aims to make alternates an implementation detail of the ODB backend.

The first five patches refactored reference handling in `git clone` to defer ODB creation until after the clone source URI is resolved, fixing a latent bug in worktree alternates handling and consolidating alternates logic into a single code path. Patch 6 introduced the core design change: alternates are now written during ODB creation via a new `odb_create_on_disk_options` struct, eliminating the need for a separate `write_alternates()` callback. Patch 7 wired up this mechanism in `cmd_clone()`, removing the last manual alternates writing step. The final patch, just posted, removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure, completing the refactoring.

The series is under review, with no merge status reported. Key technical changes include exposing `create_object_database()` to accept a `strvec` of alternates paths, adding a new `INIT_DB_SKIP_ODB` flag, and introducing helper functions like `collect_alternates()` and `add_one_alternate()`. Test coverage in `t/t5604-clone-reference.sh` verifies the fix for worktree clones and relative path resolution. Reviewers are expected to focus on patches 6-8, particularly around error handling, deduplication logic, and the implications of making alternates an ODB backend implementation detail. No substantive feedback has been recorded yet, but the series is likely to attract review from ODB-focused contributors like Justin Tobler and Karthik Nayak. The removal of dead code in the final patch should be uncontroversial, provided no regressions are found.
