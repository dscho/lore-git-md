This thread is about Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating the logic into a single step during ODB setup. The series is part of the ongoing ODB abstraction effort and has been under review, with all patches posted and reviewed.

The core change introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback. Patches 1-5 refactored reference handling in `git clone`, deferring ODB setup and fixing a latent bug in worktree alternates handling. Patches 6-8 implement the core design change, with patch 6 introducing the new mechanism, patch 7 wiring it up in `cmd_clone()`, and patch 8 removing the now-unused `write_alternates()` infrastructure.

The series has attracted attention from Toon Claes, who raised a substantive concern in patch 8 about the removal of the lockfile mechanism, questioning whether the new design is safe under concurrent access. Junio C Hamano has now weighed in on patch 6, flagging a related issue: the patch opens the `info/alternates` file in append mode rather than using Git’s standard lockfile API, which could introduce race conditions or partial writes during repository creation. While Junio acknowledges that the operation happens only once during setup, he implies that the lockfile API would still be the safer choice. This comment directly challenges the patch’s technical design and may require revisions to the locking strategy, potentially delaying the series until resolved. No other reviewers have yet addressed these concerns, but the discussion is likely to attract scrutiny from ODB-focused contributors. The series remains under review, with the locking issue now its primary open question.
