This thread is about Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB (object database) alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, making alternates an implementation detail of the ODB backend. Currently, alternates can be added at any time, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback.

The series is now in its second version (`v2`), addressing the primary blocker from `v1`: the adoption of Git’s standard lockfile API for writing the `info/alternates` file, which resolves TOCTOU race and concurrent access concerns raised by Junio C Hamano and Toon Claes. Patches 1-5 refactor reference handling in `git clone`, deferring ODB setup and consolidating alternates logic into a single code path. Patch 1 introduced the `INIT_DB_SKIP_ODB` flag to defer ODB initialization until after URI resolution, ensuring alternates are written with full context. Patch 2 moved `setup_reference()` closer to `copy_alternates()` to prepare for later changes. Patch 3, the subject of this update, refactors `--reference` and `--reference-if-able` logic to gather alternates paths into a `strvec` instead of immediately writing them, centralizing the alternates logic. Patch 5 fixed a latent bug in worktree alternates handling and added test coverage. Patch 6 implements the core design change, introducing `odb_create_on_disk_options` to write alternates during ODB creation using the lockfile API. Patch 7 wires up the new mechanism in `cmd_clone()`, and patch 8 removes the now-unused `write_alternates()` infrastructure.

The series is technically complete, with all substantive feedback addressed. Junio’s security concern about patch 6’s initial approach was resolved by adopting the lockfile API, and Toon Claes’s review comments were either addressed or declined with justification. The series is now awaiting further review from ODB-focused contributors like Justin Tobler and Karthik Nayak, particularly for patches 6-8, which implement the core changes. No new open questions or blockers have emerged, and the series is expected to proceed to integration once reviews are complete. The broader ODB abstraction effort continues to progress incrementally, with this series representing a key step toward simplifying the ODB interface.
