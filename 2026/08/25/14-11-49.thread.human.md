This thread is about Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB (object database) alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, making alternates an implementation detail of the ODB backend. The series is part of the broader ODB abstraction effort, which aims to give backends more control over their configuration.

The series is now technically complete and under final review. The key change—adopting Git’s standard lockfile API for writing the `info/alternates` file—resolved the primary blocker raised by Junio C Hamano in the first version. Patches 1–5 refactored `git clone` to defer ODB setup and consolidate alternates logic into a single code path, fixing a latent bug in worktree alternates handling along the way. Patch 6 introduced the new `odb_create_on_disk_options` mechanism to write alternates during ODB creation, ensuring atomic writes and resolving TOCTOU race concerns. Patch 7, just reviewed by Justin Tobler, wires up this mechanism in `git clone`, removing the last direct use of the old alternates-writing function. The final patch (8) will remove the now-unused infrastructure.

Justin Tobler and Toon Claes have been the main reviewers. Justin’s earlier feedback raised thoughtful questions about the growing complexity of repository initialization flags and the ODB interface’s long-term flexibility, but these are maintainability concerns rather than blockers. Toon’s reviews were mostly surface-level, though his initial concern about locking was addressed by the lockfile API adoption. The series is expected to proceed to integration once the remaining ODB-focused contributors (e.g., Karthik Nayak) have reviewed the final patches. No user-visible changes are expected, and the refactoring lays groundwork for future ODB abstraction work.
