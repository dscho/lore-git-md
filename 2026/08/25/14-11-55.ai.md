This is the sixth patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation. It implements the core change announced in the cover letter: adding support for writing alternates at the time the object database is created, rather than via a separate callback.

The patch extends the `odb_source_files_create_on_disk()` function in `odb/source-files.c` to accept a new `odb_create_on_disk_options` struct, which carries a `strvec` of alternate paths. When the options include alternates, the function writes them to the `info/alternates` file, deduplicating against any existing entries (e.g., from template directories). It then calls `odb_reprepare()` to activate the new alternates. The public `odb_source_create_on_disk()` wrapper is updated to pass the options through, and `create_object_database()` in `setup.c` is adjusted to initialize an empty options struct.

This is a clean, well-scoped implementation of the design outlined in the cover letter. The code handles edge cases (existing alternates file, write errors, deduplication) and maintains backward compatibility by preserving any preexisting alternates. The change is mechanical and uncontroversial, but it is the linchpin of the series: once alternates can be written at creation time, the `write_alternates()` callback becomes redundant and can be removed in the next patch. Reviewers will likely focus on the error handling and the deduplication logic, but the patch looks solid and ready for integration.
