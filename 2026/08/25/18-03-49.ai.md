This is the third patch in René Scharfe’s four-patch series fixing `git worktree add` basename handling. It addresses a subtle but real bug: when deriving a branch name from a multi-component path (e.g., `/new/worktree/`), the current code copies everything from the basename start to the end of the string, including any trailing slashes. Since branch names cannot end with slashes, this produces invalid names. The patch trims trailing slashes by calculating the true basename length and using `xmemdupz()` to extract only that portion.

The change is small (two lines in `builtin/worktree.c`) and adds two new tests in `t/t2400-worktree-add.sh`: one for the default case (omitting `<branch>`) and one for `--orphan` mode. Both tests verify that the derived branch name omits the trailing slash. The fix is straightforward and aligns with the series’ overall goal of making `worktree_basename()` behavior consistent and safe. No controversy is evident; this looks like a clear bugfix with appropriate test coverage.
