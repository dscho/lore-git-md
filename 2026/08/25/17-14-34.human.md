This is Junio C Hamano's review of Nikita Leshenko's bugfix for `git am --3way`. Junio identifies a significant performance problem with the proposed solution: if a 50-patch series applies cleanly, the patch would spawn 49 extra `git apply --build-fake-ancestor` processes, write and unlink 49 temporary index files, and generate unneeded loose objects in the object database. He calls this overhead "simply unacceptable" and suggests a lazy approach instead.

Junio outlines an alternative design that would reconstruct the preimage blob only when needed (i.e., when `fall_back_threeway()` is called and the preimage is missing). The idea is to inspect previously applied patches in `.git/rebase-apply/`, apply them in-core to reconstruct the necessary preimage, and write only the final blob to the object database. This would avoid the per-patch overhead while still enabling 3-way merges for subsequent patches. The review is substantive, addressing both correctness and performance, and proposes a clear technical direction for the fix. No merge status is implied; this is still under discussion.
