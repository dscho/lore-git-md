This thread is about a patch series from Harald Nordgren that aims to prevent accidental deletion of local branches via `git branch -d` when those branches serve as upstreams for other local branches. The series is currently under review and consists of two patches: a preparatory refactoring and the core logic implementing the protection.

The key issue is a backward-compatibility concern raised by Junio C Hamano, the maintainer, who objects to changing the long-standing semantics of the `-d` flag. He argues that the change could break existing workflows and has not endorsed the current "block deletion" approach, suggesting instead that the patch should either implement retargeting of dependent branches or find another way to address the compatibility issue. Harald has acknowledged the concern but has not yet proposed a resolution or a new version of the series.

Elijah Newren has now identified a significant logical gap in the implementation: the protection is not transitive. If branch `C` depends on `B`, and `B` depends on `A`, deleting `A` and `B` in one command will delete `A` (which is not directly an upstream of any remaining branch) while protecting `B` (which is directly an upstream of `C`). This contradicts the commit message and documentation, which claim the protection applies to branches that are "directly or indirectly" upstream of another local branch. This discrepancy is a serious issue that would need to be fixed before the patch could move forward.

The thread remains unresolved, with the core design tension between protection and compatibility still open, and now an additional correctness issue to address. No new version of the series has been posted yet.
