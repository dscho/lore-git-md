This thread is about a proposed change to prevent `git branch -d` from accidentally deleting a local branch that serves as the upstream for another local branch, which would break the dependency chain. The series, submitted by Harald Nordgren, consists of two patches: a preparatory refactoring of helper functions in `builtin/branch.c` (no behavioral change), and the core logic that implements the protection (currently contested).

The key debate centers on backward compatibility. Junio C Hamano, the maintainer, has raised a substantive objection to the behavioral change in the second patch, arguing that it alters the long-established semantics of the `-d` flag and could disrupt existing workflows. Tuomas Ahola later clarified that Junio’s earlier feedback was a brainstorm of two possible approaches—either blocking deletion (as implemented) or retargeting dependent branches to a fallback upstream (e.g., `origin/master`)—rather than an endorsement of the current design. Harald has acknowledged this clarification but has not yet proposed a resolution or updated the series.

The current implementation blocks deletion of upstream branches unless `-D` (force) is used, but the alternative retargeting approach, while more user-friendly, would require significant additional logic. Junio has explicitly rejected introducing a configuration variable to toggle this behavior, emphasizing the need for predictability. The thread remains unresolved, with no clear path forward on whether the simpler "block deletion" approach is sufficient or if the patch must implement retargeting to be acceptable. No new version of the series has been posted.
