This thread introduces a small but user-visible change to `git branch -d`: it will now refuse to delete a local branch if that branch is the upstream of another local branch, unless the user explicitly uses `-D` (force). The series is from Harald Nordgren and consists of two patches. The first, a pure refactoring to move helper functions earlier in `builtin/branch.c`, has already been reviewed; the second, which implements the new protection logic, is now under review.

The change is motivated by a common footgun: deleting a branch that another branch depends on breaks the dependency chain, and users often don’t realize the branch they’re deleting is an upstream. The new behavior is order-independent, so even if the upstream branch is listed later in a multi-branch deletion command, it will still be protected. The implementation uses two new `strset` variables to track which branches are safe to delete and which are protected, and the error message includes advice to use `-D` if the user really wants to proceed.

The patch updates the documentation and adds test coverage for both single-branch and multi-branch deletion scenarios. It also updates existing tests to use `-D` where the new protection would otherwise cause them to fail. The change is scoped to local branches only; remote-tracking branches are unaffected. No new configuration options or CLI flags are introduced. The series is self-contained and under active review, with no open questions or objections raised so far.
