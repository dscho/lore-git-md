This is the second patch in Elijah Newren’s two-patch series fixing a race condition in Git’s geometric repacking mechanism that causes objects to be incorrectly reported as missing, leading to crashes in `git replay` and errors in other server-side operations. The series is under active review, with the core fix now widely accepted and the discussion focused on optimizing the recovery logic’s performance.

This email confirms that Elijah has adopted Jeff King’s (Peff) suggestion to tie the fallback recovery logic to the `SECOND_READ` phase, which occurs after a refresh when an object lookup fails. Peff argued that this change would optimize performance for `QUICK` callers (like `git replay`) by avoiding unnecessary scans of MIDX-covered packs during the initial lookup, while still preserving correctness for non-`QUICK` callers. The fallback now only triggers during `SECOND_READ`, when it is clear that the object exists in a duplicate pack not moved by repacking. Elijah’s implementation of this change is included in the upcoming `v2` of the patch.

The patch targets the packed-object backend (`odb/source-packed.c`) and introduces a tri-state return value from `fill_midx_entry()` to distinguish between misses, hits, and cases where the preferred pack is unavailable. This design, also proposed by Peff, shifts responsibility for handling missing packfiles to callers and aligns with the broader goal of making the recovery logic more precise. The fix is well-motivated, thoroughly tested, and addresses a real-world race condition that affects critical server-side operations. The remaining discussion is now focused on fine-tuning the implementation rather than questioning the fix’s necessity or correctness.

If you are following Git’s geometric repacking or MIDX subsystems, this patch is worth tracking, as it resolves a subtle but impactful race condition with minimal performance overhead. The upcoming `v2` will likely be the final version before integration, barring any further refinements suggested during review.
