This is a bugfix patch for `git am --3way`. It addresses a long-standing edge case where a multi-patch series fails to apply even when all the necessary information is available.

The problem occurs when two consecutive patches modify the same file, the first applies cleanly, and the second does not. Because `git am --3way` only records intermediate blob hashes when it performs a 3-way merge, the second patch’s preimage (the first patch’s postimage) is never stored, causing the second patch to fail with "sha1 information is lacking or useless". The patch teaches `git am` to proactively apply each clean patch to its fake ancestor and record the resulting postimage, so later patches can reference it.

The commit message is clear and thorough, walking through the scenario step-by-step. The code adds a new helper `try_record_patch_postimage()` that runs `git apply --build-fake-ancestor` quietly in the background whenever a patch applies cleanly and `--3way` is in effect. The change is guarded by an explicit check that there are more patches to come (`state->cur < state->last`), so it only runs when needed. A new test in `t/t4150-am.sh` exercises the exact edge case described.

The patch looks well-crafted: it preserves existing behavior for non-`--3way` invocations, fails gracefully if anything goes wrong, and comes with a regression test. The extra cost (one `git apply` per clean patch) is minimal and only incurred when the user explicitly requested `--3way`. No controversy is evident; this appears to be a straightforward fix for a real, if obscure, problem.
