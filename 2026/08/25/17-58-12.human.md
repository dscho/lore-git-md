This is the first patch in a seven-part feature series (v5) that adds new path-related keys to `git repo info`. This patch introduces `path.toplevel.absolute` and `path.toplevel.relative`, which expose the top-level working tree directory in both absolute and relative forms. The implementation is straightforward: it uses `repo_get_work_tree()` and the existing `format_path()` helper to return the path, or an empty string in bare repositories.

The patch is mechanically clean and well-tested. The commit message clearly explains the motivation—replacing ad-hoc `git rev-parse --show-toplevel` calls in scripts with a structured, scriptable alternative—and the tests cover both normal and bare-repository cases. The documentation update is minimal but sufficient, listing the new keys alongside existing ones.

This is a sensible, uncontroversial addition that fits neatly into the series’ goal of making repository paths available in a consistent format. No design questions remain for this patch; the only open discussion is about naming conventions for later keys (e.g., `path.hooks` vs. `path.hookdir`), which doesn’t affect this one. The patch is ready for final review and looks like a solid contribution.
