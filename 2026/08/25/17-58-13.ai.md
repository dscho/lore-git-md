This is the second patch in the v5 series adding path-related keys to `git repo info`. It implements `path.superproject-root.absolute` and `path.superproject-root.relative`, which expose the top-level working tree of a superproject when the current repository is a submodule. The keys return an empty string when not inside a submodule, matching the established pattern for inapplicable contexts.

The implementation reuses the existing `get_superproject_working_tree()` function and the `format_path()` helper introduced in earlier patches. The absolute variant uses `PATH_FORMAT_CANONICAL` to return a normalized path, while the relative variant uses `PATH_FORMAT_RELATIVE` with the repository’s `prefix` to compute the path from the current directory. The patch adds documentation to `git-repo.adoc` and includes thorough tests covering both submodule and non-submodule cases.

This patch is uncontroversial and mechanically clean. The naming (`superproject-root`) aligns with `git rev-parse --show-superproject-working-tree` and was suggested by Justin Tobler in earlier feedback. The behavior (empty string when not in a submodule) is consistent with the rest of the series and matches the precedent set by `path.toplevel`. The tests verify absolute path resolution using `test-tool path-utils real_path` and relative path formatting (e.g., `../` from a subdirectory).

- New symbols: `path.superproject-root.absolute` and `path.superproject-root.relative`.
