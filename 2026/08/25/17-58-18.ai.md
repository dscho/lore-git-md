This is the final patch in the **`[PATCH v5]` series** adding seven new path-related keys to `git repo info`, completing the feature set proposed in earlier iterations. This patch implements `path.cdup`, the inverse of `path.git-prefix`, as requested by Junio C Hamano to provide symmetry and resolve the last open design question from v4.

The patch introduces the `path.cdup` key, which returns the relative path from the current working directory to the root of the working tree (e.g., `../../` in a subdirectory, empty string at the root). The implementation reuses the repository’s `prefix` field, counting slashes to generate the correct number of `../` sequences. The key is documented in `git-repo.adoc` and tested for both the root and subdirectory cases, including edge cases like nested subdirectories.

Files touched are `builtin/repo.c` (new `get_path_cdup()` function), `Documentation/git-repo.adoc` (added `path.cdup` entry), and `t/t1900-repo-info.sh` (new tests). The implementation is straightforward and aligns with `git rev-parse --show-cdup` behavior, making it intuitive for users familiar with Git’s existing tools. The tests are thorough, covering both the root and subdirectory cases, and the commit message clearly explains the motivation and behavior.

This patch resolves the last design objection from v4, where Lucas Seiki Oshiro argued that `path.git-prefix` represented "current directory information" rather than "repository information." Junio rejected this objection, analogizing `path.git-prefix` to `git rev-parse --show-cdup` and `path.commondir.relative` as inherently repository-centric. The inclusion of `path.cdup` in this patch provides symmetry and completes the relative-path key set, solidifying the series’ design. With this addition, the series is now feature-complete and ready for final technical review.

Key technical details for follow-up discussion:
- New symbol: `path.cdup` (returns `../` sequences or empty string).
- Behavior: Inverse of `path.git-prefix`; returns empty string at the repository root.
- Files: `builtin/repo.c` (new `get_path_cdup()` function), `Documentation/git-repo.adoc` (documentation), `t/t1900-repo-info.sh` (tests).
- The implementation is self-contained and does not depend on other patches in the series. The tests are isolated and verify the key’s behavior in both root and subdirectory contexts. Reviewers may still suggest minor adjustments to the implementation (e.g., whether to include a trailing slash), but the core design is settled.
