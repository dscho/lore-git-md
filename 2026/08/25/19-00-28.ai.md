This is the third patch in Elijah Newren’s four-patch bugfix series (v2) addressing a race condition in Git’s geometric repacking mechanism. The patch targets a specific failure mode where an `OBJECT_INFO_QUICK` lookup—used by commands like `git mktree --batch`—incorrectly reports objects as missing when a concurrent repack removes a packfile mid-lookup. The fix introduces a lightweight recovery mechanism that forces a rescan of the object database only when a packfile vanishes beneath a running process, preserving the speed of `QUICK` lookups for genuine misses while ensuring correctness when the on-disk state changes unexpectedly.

The patch touches the packed-object backend (`odb/source-packed.c`, `packfile.c`), the object database core (`odb.c`, `odb.h`), and MIDX internals (`midx.c`), adding a new `stale_packs_detected` flag to `struct object_database`. This flag is set at three points where a reader can observe a packfile vanish: when `open_pack_index()` fails due to a missing `.idx` file, when `open_packed_git_1()` fails to open a `.pack` file after its `.idx` was already mapped, and when `prepare_midx_pack()` cannot open a pack referenced by a multi-pack-index. The flag triggers a second read in `odb_read_object_info_extended()` even for `OBJECT_INFO_QUICK` lookups, forcing a reprepare of the packfile set and a retry. The flag is cleared during the reprepare, ensuring the overhead is limited to the rare case where a packfile disappears mid-lookup.

The new test file `t/t5336-repack-reader-race.sh` reproduces the race deterministically by driving a resident `git mktree --batch` process across two removal windows: one where a pack’s `.idx` is deleted before its `.pack`, and another where the `.pack` is deleted after its `.idx` was already mapped. The tests confirm the reader recovers the relocated object instead of failing or producing incorrect output. The patch is well-motivated by production evidence, affecting server-side operations like `git upload-pack` (which uses `QUICK` lookups for negotiation) and `git mktree --batch` (used in scripting and tooling). The fix is narrowly scoped, avoiding on-disk format changes and minimizing runtime overhead by gating the recovery on the `stale_packs_detected` flag.

This patch is part of a converged series with no remaining technical objections. The core design—adopting Jeff King’s tri-state return values and `SECOND_READ`-gated fallback—has been settled in patch 4/4, and this patch complements it by addressing the `OBJECT_INFO_QUICK` edge case. The series is rebased on `ps/odb-generic-corrupt-objects` and is a high-priority candidate for merging. Key symbols introduced here include `stale_packs_detected` (a flag in `struct object_database`) and the test file `t/t5336-repack-reader-race.sh`. The patch is small, focused, and includes thorough test coverage, making it a clean and necessary addition to the broader race-condition fix.
