This is the core infrastructure patch of the RFC series introducing the **hunk provider interface** (`diff-provider.h`). It establishes the abstraction layer that lets Git consult alternate sources for diff hunks before falling back to the builtin xdiff computation. The patch defines the interface, its repository-owned provider chain, and the rules that govern how providers answer or refuse requests.

The interface is designed around a **provider chain** owned by each repository. The chain is built on first consultation and released when the repository is cleared, ensuring provider state (like a running process) never outlives its repository. Providers are consulted in order until one answers or refuses; the builtin xdiff is the terminal provider, so every request ends in an answer. A provider may refuse a request whose parameters its recording key cannot express, in which case no later provider answers from identity and the consumer must not record what it computes.

The consumer surface is minimal: `struct diff_provider_request` names what is diffed and under which parameters, and `enum diff_provider_outcome` flattens the response state (answered, unanswered, failed) and the recording rule into four values. The interface enforces that every answer passes `diff_provider_check_hunk()` before a consumer sees it: coordinates fit int32, hunks are ordered and non-overlapping, and unchanged runs between hunks match on both sides. The first consumer wired is `git blame`'s `pass_blame_to_parent()`, whose content loads move into a fill callback that runs only when the ranges are computed.

The patch adds two new files: `diff-provider.h` (the consumer interface) and `diff-provider-internal.h` (the implementor contract, modeled after `refs/refs-internal.h`). The walk in `diff-provider.c` maps provider dispositions (answer, pass, fail, refuse) onto the public outcome set and checks with `BUG()` that only the computing provider fails and that it passes on a consult-only walk. The chain composition is fixed; each provider gates itself per request, so chain order carries the authority resolution.

With only the terminal provider registered, every request still computes, so behavior is unchanged. The patch is the foundation for the two example providers (in-process cache and external process driver) that follow in the series, and for future extensions like content-carrying requests. The interface is technically complete for its scope, with robust error handling and no known regressions.
