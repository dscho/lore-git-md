This is the sixth patch in the v7 RFC series introducing Git’s new diff provider interface. It wires `git blame` to consult the in-process `diff-hunks` store before falling back to the built-in xdiff, completing the blame side of the identity-keyed provider chain.

The patch teaches `pass_blame_to_parent()` to offer the (old-blob, new-blob) identity to the provider interface whenever blame’s diff is the plain blob-pair diff the store key describes: no reverse blame, no ignored revisions, no textconv, and no working-tree or `--contents` pseudo-commit (whose blob is not a stored object). Requests carrying `-I` patterns or anchors are outside the key and always compute. Blame’s default xdl_opts now come from `DIFF_HUNKS_DEFAULT_XDL_OPTS`, ensuring a default blame run and a default `log --stat` warming run share keys by construction. `--show-stats` reports how many pairs the store served and how many it could not, read from the store’s own consultation counters.

Test coverage in `t4220-diff-hunks.sh` (355 new lines) verifies output parity for plain, `--porcelain`, and `--incremental` blame; hit and miss accounting across warming runs; the blame inputs that must bypass or miss the store (`-w`, indent heuristics, `--reverse`, textconv, `-M`/`-C`, `--ignore-rev`); rename and merge handling; `--contents`; and corruption recovery (truncated store, corrupt signature, over-claimed chunk count, zero-hunk record). The new `t/perf/p4218-diff-hunks.sh` measures the cost of a warming run and the read speedups: on `git.git` a warmed store speeds up blame by ~1.26×.
