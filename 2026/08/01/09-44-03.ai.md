This is the **v4 feature patch series** for `git bisect`, adding the `--reset-when-found[=<where>]` option. The series is now down to two patches: (1) a plumbing change to let `bisect_reset()` optionally check out quietly, and (2) the core feature implementation.

This version addresses the last of Johannes Sixt’s surface-level feedback from v3. The error messages for the `--reset-when-found`/`--no-checkout` conflict now use Git’s standard dual-option template (`"options '%s' and '%s' cannot be used together"`), reducing translation overhead. The test helpers (`test_bisect_state_file` and `test_bisect_state_missing`) no longer use unchecked `git rev-parse` calls in subshells, avoiding potential silent failures. The author also simplified translation calls in the code.

The series remains functionally unchanged from v3: once `git bisect` identifies the first bad commit, the working tree is automatically reset to either the pre-bisect commit (`original`, the default) or the first bad commit itself (`found`). The deferred reset behavior for `git bisect run` (to ensure captured output is printed before cleanup) is retained, as is the constraint that `--reset-when-found` cannot be used with `--no-checkout`. Test coverage is thorough, validating both reset targets, state cleanup, and edge cases.

All substantive feedback has been addressed, and the series is marked for integration into `next`. The only unaddressed item from Johannes Sixt’s review—joining `test_when_finished` commands with `&&`—is mechanical and does not affect the feature’s logic or readiness. The series is uncontroversial and ready for final review.
