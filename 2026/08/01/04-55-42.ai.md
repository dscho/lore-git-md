This is the third patch in Pablo Sabater’s GSoC v2 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the server-side object-info handler in `protocol-caps.c` to accept and return the "type" field when requested by the client. Junio C Hamano’s review confirms the implementation is straightforward and correct, though he notes the protocol’s input/output format for declaring requested fields ("size" and "type" on separate lines) feels odd compared to the actual response (object name, size, and type on a single line). The patch adds a `type` bit field to the `requested_info` struct, parses the "type" keyword in client requests, and appends the object type (e.g., `"blob"`, `"tree"`) to the server’s response using `type_name()`. It also includes a test in `t5701-git-serve.sh` verifying the server handles requests for both "size" and "type". Two minor cleanups are included: wrapping an over-long line in the error message and fixing the bit field style for `requested_info.size` to match the new `type` field. The changes are mechanical and align with the established pattern from Eric Sunshine’s recently merged v21 series. Junio’s feedback is advisory and does not block the patch; the series remains ready for maintainer consideration.
