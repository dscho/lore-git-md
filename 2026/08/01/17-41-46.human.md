This is the third patch in Michael Montalbo’s RFC v7 series introducing a diff provider interface. It implements the **`diff-hunks` store**, an in-process cache that memoizes diff hunk coordinates at `$GIT_DIR/objects/info/diff-hunks` so commands like `git blame` and `git log --stat` can skip recomputing them.

The store is a single chunk-format file (header, sorted index, hunk data, trailing checksum) keyed by the two blob OIDs and the `xdl_opts` they were diffed under. Only pairs whose zero-context trimmed diff and untrimmed diff are identical are recorded, so one entry serves both blame (zero context) and stat formats (any context). The rare divergent pair is always computed. The store is read by default (`core.diffHunks=true`) but written only when opted in (`GIT_DIFF_HUNKS_WRITE=1` or `diffHunks.write=true`), so ordinary commands never mutate it. A warming run (e.g., `GIT_DIFF_HUNKS_WRITE=1 git log --all --stat`) seeds the store, and later runs merge new pairs into it rather than replacing it.

The library provides a reader (loaded once and cached on the object database) and a writer that accumulates entries in memory and flushes them atomically. The reader bounds-checks every offset and count, so a corrupt store reads as all misses; `git diff-hunks verify` checks the checksum and structure separately. The writer deduplicates identical hunk blocks, so distinct keys that diff to the same hunks share one block. Performance measurements on `git.git` show a warmed store speeds up `log --stat -5000` by ~1.9x and blame by ~1.26x, with hit rates of 54-74% depending on the file.

The patch adds the store format, library (`diff-hunks.c`), and a new plumbing command (`git diff-hunks` with `verify` and `clear` subcommands). It touches 24 files, including new man pages (`git-diff-hunks(1)`, `gitformat-diff-hunks(5)`), configuration (`core.diffHunks`, `diffHunks.write`), and fsync support for the `diff-hunks` component. The implementation is careful about correctness: entries are validated before replay, the writer refuses values the on-disk 32-bit fields cannot hold, and corruption is handled gracefully (fallback to builtin diff). The store deliberately lacks fsck integration or expiry, relying on `git diff-hunks clear` and re-warming for recovery.
