This is a review comment from Junio C Hamano on the fourth patch in Pablo Sabater’s GSoC v2 series, which extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the client to parse the "type" field from the server’s response, preparing it for when the server advertises the capability.

Junio’s feedback is substantive but narrowly scoped: he questions whether the current implementation, which allocates memory for `object_info_data[j].typep` separately for each object ID, is necessary. His suggestion replaces the looped `xcalloc` calls with a single contiguous allocation, simplifying memory management and reducing the risk of leaks. The change is mechanical and does not alter the patch’s core functionality, but it improves code hygiene and maintainability.

The rest of the patch — tracking the `type_index`, updating the `BUG()` assertion, and parsing the type string — remains uncontroversial. Junio does not raise any concerns about the logic or safety of those parts. This review is a typical example of Junio’s attention to detail in memory management, a recurring theme in his feedback across the project.

The patch is not blocked; the feedback is advisory and can be addressed with a small follow-up change. The series as a whole remains on track for integration, with only minor adjustments needed.
