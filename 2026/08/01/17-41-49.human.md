This is the sixth patch in the v7 RFC series introducing a diff provider interface. It wires `git blame` to consult the new hunk provider chain, enabling it to read precomputed hunks from the `diff-hunks` store (or any other configured provider) before falling back to the builtin xdiff computation.

The patch teaches `blame.c` to offer the identity of each parent-target blob pair to the provider interface, filling in the object IDs and diff options in the `diff_request` struct. The store serves the pair if it holds a matching entry (keyed by the blob IDs and xdiff flags), replaying the recorded hunks through `blame_chunk_cb` without loading either blob. Blame diffs at zero context, which is not part of the key, so the store serves blame and stat formats interchangeably. Requests carrying `-I` patterns, `--anchored` anchors, or other exclusions bypass the store entirely, as do pairs where blame’s diff is not the plain blob-pair diff the key describes: reverse blame, ignored revisions, textconv paths, and the working-tree or `--contents` pseudo-commit (whose blob is not a stored object).

The patch also adds `DIFF_HUNKS_DEFAULT_XDL_OPTS` to ensure blame’s default xdl_opts match those of a diff_options-based consumer (like `git log --stat`), so a default blame run and a default warming run share keys by construction. The `--show-stats` option now reports how many pairs the store served and how many consultations it could not answer, read from the store’s own consultation counters.

Test coverage in `t4220-diff-hunks.sh` expands by 355 lines to verify blame output parity (plain, `--porcelain`, `--incremental`), hit and miss accounting, and the inputs that must bypass or miss the store: `-w`, indent heuristics, `--reverse`, textconv, `-M`/`-C`, `--ignore-rev`, and `--contents`. It also confirms that a single warming run serves both blame and diffstat, that a corrupt or truncated store is read as absent, and that a crafted zero-hunk record is treated as a miss that `verify` flags. The new `t/perf/p4218-diff-hunks.sh` measures the cost of a warming run and the read speedups, reporting ~1.26x faster blame on a warmed store.

The patch is cleanly structured and well-motivated, with thorough test coverage and no known regressions. It demonstrates the provider interface working as intended: blame consults the chain transparently, the store serves compatible pairs, and incompatible requests fall back to the builtin diff without disruption. The only open question is whether the overall framework direction is accepted; if it is, this patch will return as part of the interface-and-store series.
