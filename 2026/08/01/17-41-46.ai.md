This is the third patch in the v7 RFC series introducing Git’s new diff provider interface. It implements the **`diff-hunks` store**, an in-process cache of precomputed diff hunk coordinates that lets commands like `git blame` and `git log --stat` skip recomputing hunks for blob pairs they’ve already diffed. The store is a single chunk-format file at `$GIT_DIR/objects/info/diff-hunks`, keyed by the two blob OIDs and the `xdl_opts` they were diffed under, so an entry is valid in any context that key recurs in.

The patch adds the file format, library, and a new plumbing command (`git diff-hunks`) to inspect and manage the store. The format is a chunked binary file with a sorted index (DHIX) and a hunk data segment (DHDT), plus a trailing checksum. Entries are recorded only when a pair’s trimmed and untrimmed diffs are identical, so one entry serves both blame (zero context) and stat formats (any context). The library provides a reader (loaded once and cached on the object database) and a writer that accumulates entries in memory and flushes them atomically, merging with the existing store rather than replacing it. Writing is off by default and enabled per run via `GIT_DIFF_HUNKS_WRITE` or persistently via `diffHunks.write`, so ordinary commands read the store without modifying it.

Key technical details include bounds-checking every read (so corruption fails safe), deduplicating identical hunk blocks to save space, and fsyncing the file on flush (honoring `core.fsync`). The `git diff-hunks verify` command checks the checksum, chunk table, sort order, and every entry’s hunk sequence, while `git diff-hunks clear` removes the file. The store is designed to be transparent: absent, corrupt, or disabled stores read as misses, and the diff output is unaffected either way. Performance measurements in the series show a warmed store speeds up `log --stat -5000` by ~1.9x and `blame` by ~1.26x on `git.git`, with hit rates of 54-74% depending on the file.
