This is a refactoring patch in the diff provider interface RFC series. It extracts the process lifecycle management from the hashmap management in Git's sub-process API, introducing `subprocess_start_command()` and `subprocess_stop_command()` as lower-level primitives. The goal is to let callers like the upcoming diff process provider manage their own process pools without being forced into the global hashmap that `subprocess_start()` and `subprocess_stop()` maintain.

The change is mechanical: `subprocess_start()` and `subprocess_stop()` become thin wrappers around the new `_command` variants, which handle the actual process setup, handshake, and teardown. The diff process provider (introduced later in the series) needs this flexibility because its pool has custom membership rules—failed commands must remain in the pool to avoid retrying them, which the global hashmap does not support.

The patch touches only `sub-process.c` and `sub-process.h`, adding the new functions and updating the existing ones to call them. No behavior changes; this is purely about decoupling concerns. The commit message clearly explains the motivation and the specific use case (the diff process pool) that requires this refactoring. The change looks clean and well-motivated, with no obvious downsides.
