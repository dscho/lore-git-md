This is the core infrastructure patch of Michael Montalbo’s RFC series introducing a **hunk provider interface** (`diff-provider.h`). It establishes the abstraction layer that lets Git consult alternate sources for diff hunks before falling back to the builtin xdiff computation.

The patch adds the interface itself, the repository-owned provider chain, and the rules that govern how providers answer or refuse requests. A provider is either authoritative (its answer may differ from the builtin diff) or not (it must reproduce the builtin result exactly). Every answer served from identity passes a shared coordinate check before any consumer sees it, ensuring hunks are ordered, non-overlapping, and aligned on both sides. The chain is built on first consultation and released in `repo_clear()`, so no provider state outlives the repository it serves. Chain order resolves authority: the first answer wins, and the builtin xdiff is the terminal provider.

The consumer surface is deliberately minimal: a single struct (`diff_provider_request`) names what is diffed and under which parameters, and an enum (`diff_provider_outcome`) flattens the response state (answered, unanswered, failed) and the recording rule into four values. The recording rule rides in the outcome so that `-Wswitch` forces every consumer to place the no-record arm. The first consumer is `git blame`, whose `pass_blame_to_parent()` now consults the interface before loading either blob; its loads move into the fill callback that runs only when the ranges are computed.

With only the terminal provider registered, every request still computes, so behavior is unchanged. The patch is the foundation for the two example providers that follow in the series: an in-process cache (`diff-hunks` store) and an external process driver (`diff.<driver>.process`). The series is technically complete for its scope and ready for design feedback on the framework direction.
