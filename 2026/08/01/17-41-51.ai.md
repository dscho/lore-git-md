This is a plumbing patch in the RFC series introducing Git’s new diff provider interface. It adds a gentle variant of the existing `subprocess_read_status()` function to avoid dying on protocol errors when reading status packets from an external process.

The new `subprocess_read_status_gently()` uses `packet_read_with_status()` with gentle flags (`PACKET_READ_GENTLE_ON_EOF` and `PACKET_READ_GENTLE_ON_READ_ERROR`), so malformed length headers, truncated packets, or empty packets where a status line or flush is expected all return -1 instead of killing the process. This is essential for the upcoming diff process provider (patch 10), which treats its external process as optional: any protocol error must degrade to the builtin diff rather than abort the command. The existing `subprocess_read_status()` and its callers are unchanged, preserving the fatal behavior for required subprocesses like filters.

The patch is mechanical and self-contained, touching only `sub-process.c` and `sub-process.h`. It complements the gentle handshake added in 061a68e443, ensuring that both handshake and status phases of the protocol can fail gracefully for optional processes. No new symbols or behavior changes are introduced beyond the gentle status read; the diff process provider will use this in patch 10 to handle protocol errors without dying.
