This is the fourth patch in the v7 RFC series introducing Git’s new diff provider interface. It teaches the stat output (`--stat`, `--numstat`, `--shortstat`) to record precomputed hunks into the `diff-hunks` store when writing is enabled, turning a warming run into a side-effect that fills the cache.

The patch wires the stat path (`builtin_diffstat()`) to attach a writer when the output format is one of the stat variants and writing is enabled (via `GIT_DIFF_HUNKS_WRITE=1` or `diffHunks.write`). On a warming run, a modified pair’s stat is produced by collecting its hunk coordinates in a single xdiff pass, summing the counts from those hunks, and recording the pair into the store. The store records only “trim-stable” pairs—those whose zero-context trimmed diff (what blame reads) and untrimmed diff (whose counts a nonzero-context stat matches) are identical—so one entry serves both blame and stat formats. The warming run displays the trimmed counts (matching a store-less run), while the untrimmed counts serve only the stability comparison.

Key exclusions are enforced: `--ignore-blank-lines` is part of the store key but coalesces hunks differently between the text-emitting and coordinate-callback paths, so it is excluded; `-I` patterns, `--anchored`, and break detection (`-B`) shape the diff outside the key and are also excluded. Recording requires both sides to be valid regular files whose blobs the key can name, so working-tree sides, textconv output, and gitlinks are skipped. The patch adds the write half of `t/t4220-diff-hunks.sh`, testing that ordinary commands never create the store, that a warming run builds a store that verifies, that a second warming run refreshes it in place, and that the displayed counts stay correct on a trim-divergent pair (a real-world fixture whose counts change with context). It also tests that binary and mode-only pairs do not break the writer, that a corrupt store is discarded at seed, and that `verify` and `clear` work against the files a warming run builds.
