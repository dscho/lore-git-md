This is a bugfix for `git filter-branch`. The patch corrects a long-standing inversion in how the commit mapping directory is populated from the state branch. The state branch stores mappings in "from_commit:to_commit" format, but the code was reading them as "to_commit:from_commit", causing the mapping to be backwards. This becomes especially noticeable when `--prune-empty` is used, leading to errors like "Is a directory" when Git tries to create files with empty names.

The fix is a simple two-line change in `git-filter-branch.sh` that swaps the order of the fields when writing to the map directory. The test is also updated to verify the state branch functionality works correctly, though the new test case (`exit 1`) seems more like a placeholder than a thorough check of the mapping logic.

The commit message clearly explains the problem and the fix, and the patch itself is minimal and focused. This looks like a well-crafted fix for a real issue, though the test update could be more thorough. Worth attention from anyone who still uses `git filter-branch`.
