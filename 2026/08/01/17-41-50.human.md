This is a refactoring patch in the diff provider interface RFC series. It splits the `sub-process.c` API into two layers: the original `subprocess_start()` and `subprocess_stop()` functions that couple process lifecycle with hashmap management, and new `_command` variants that handle only the process setup, handshake, and teardown. The change is motivated by the upcoming diff process provider, which needs to manage its own pool of processes (with custom membership rules) rather than using the global hashmap.

The patch is small (28 lines added, 6 removed) and mechanical: it extracts the process-handling logic into standalone functions, then makes the original functions thin wrappers that add hashmap operations. No behavior changes; the existing callers (like `convert.c`) continue to work unchanged. The new `_command` variants will be used by the diff provider’s per-repository pool, which keeps failed processes in the map to avoid retries. This separation keeps the subprocess machinery reusable while allowing the diff provider to enforce its own policy.
