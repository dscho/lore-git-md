This is a refactoring patch that continues the `the_repository` removal effort by moving the global `fetch_if_missing` variable into `struct repository`. The patch is well-structured and addresses prior feedback, but Junio C Hamano recently identified a behavior change in repository-less invocations (like `git index-pack` outside a repository) where the patch inadvertently enables lazy fetches that were previously suppressed. This edge case must be fixed before the patch can proceed.

The patch touches 15 files, mostly converting call sites to use the repository-specific flag instead of the global variable. The default value remains `1` (enabled), preserving existing behavior. Special handling in `fsck.c` and `index-pack.c` avoids null pointer dereferences during early option parsing, and a `BUG()` check in `revision.c` enforces that `--exclude-promisor-objects` can only be used when `fetch_if_missing` is disabled. The patch retains `the_repository` in `index-pack.c` and `revision.c` to avoid regressions in multi-repository scenarios, a pragmatic compromise that Patrick Steinhardt’s earlier feedback endorsed.

The author has addressed all prior concerns, including a critical correctness issue in `setup.c` where the wrong repository was being used. The partial clone documentation is also updated to reflect the new per-repository nature of the flag. However, the lack of explicit testing for multi-repository or repository-less scenarios leaves some risk of undetected regressions. Junio’s observation about repository-less invocations is the remaining blocker; the author acknowledges the need for a v3 to resolve it.

This patch is a logical next step in the libification and `the_repository` removal efforts, but it isn’t yet ready for merging. If you’re following those initiatives, this is worth tracking for the v3 update. For others, it’s a niche refactoring with no user-visible changes—unless you’re working with promisor remotes or multi-repository setups, in which case the edge cases here might matter.
