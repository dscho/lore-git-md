This is the final patch in the v7 RFC series introducing Git's **diff provider interface**, specifically implementing the **external process provider** (`diff.<driver>.process`). The patch wires the provider into the repository's provider chain, enabling Git to consult a long-running external process for diff hunks before falling back to the builtin xdiff computation or the `diff-hunks` store.

The external process speaks a pkt-line protocol over stdin/stdout, answering requests by object names alone (no content is sent). This allows the process to serve a persistent cache keyed on the blob pair or fetch the blobs itself (e.g., via `git cat-file --batch`) to compute its own notion of changed lines. The process is authoritative: its answers may differ from the builtin diff and override the `diff-hunks` store. A pair the process answers is never recorded into the store, ensuring the store holds only builtin results.

Key technical details:
- **Protocol**: Versioned handshake (`git-diff-client`/`git-diff-server`, version=1), followed by per-pair requests (`command=hunks-by-oid`, `pathname=<path>`, `old-oid=<hex>`, `new-oid=<hex>`). The process responds with hunk lines (`hunk <old_start> <old_count> <new_start> <new_count>`) and a status packet (`success`, `need-content`, or `abort`). Git validates hunks for order, overlap, lockstep alignment, and bounds before replaying them.
- **Error handling**: Protocol errors (malformed packets, unrecognized status, or process crashes) disable the process for the remainder of the command, falling back to the builtin diff. Semantically invalid coordinates (e.g., overlapping hunks) skip only the affected pair while keeping the process alive.
- **Lifecycle**: The provider manages a repository-owned pool of running processes, keyed by the configured command string. Processes are launched on first use and stopped when the repository is cleared (`repo_clear()`). A failed process is retained in the pool to avoid retries.
- **Gating**: Consulting is opt-in per command (like `textconv`), with `--diff-process`/`--no-diff-process` controlling it independently of `--ext-diff`. Plumbing commands (e.g., `diff-tree`) forbid it by default; porcelain commands (`git diff`, `git log`, `git blame`) allow it. Options the process is never told about (e.g., whitespace-ignoring flags, `--ignore-matching-lines`, `--anchored`, or a forced diff algorithm) bypass the process entirely.
- **Integration**: `git blame` and the summary formats (`--stat`, `--numstat`, `--shortstat`) consult the process. A `status=success` response with zero hunks asserts the blobs equivalent, omitting the pair from the stat or passing the whole commit through in blame. Patch output and `git log -L` range tracking remain builtin, as the protocol currently lacks content-carrying requests.

The patch adds 669 lines to `diff-process.c`, implementing the protocol, process pool, request/response parsing, and validation. It introduces `subprocess_read_status_gently()` (patch 10) to handle protocol errors gracefully for optional processes and refactors `sub-process.c` (patch 11) to decouple process lifecycle management from the global hashmap. The test helper `test-diff-process-backend.c` (349 lines) exercises the protocol, including adversarial responses (e.g., malformed hunks, crashes, or unrecognized statuses), while `t/t4080-diff-process.sh` (593 lines) verifies integration, gating, and error paths.

The patch is technically complete for its scope (identity-only requests) and ready for design feedback. If the framework is accepted, this provider will return as a separate series alongside the `diff-hunks` store and future content-carrying extensions.
