This is a small but important patch in the RFC series introducing Git’s new diff provider interface. It adds a "gentle" variant of the existing `subprocess_read_status()` function, which reads status packets from a subprocess without dying on protocol errors.

The context is the external diff process provider (patch 10 in the series), which treats its subprocess as optional infrastructure. If the process misbehaves—sending a malformed packet, truncating the status section, or violating the protocol—Git must fall back to the builtin diff rather than aborting the entire command. The existing `subprocess_read_status()` dies on such errors, so it cannot be used for optional processes.

The patch introduces `subprocess_read_status_gently()`, which reads status packets through `packet_read_with_status()` with gentle options (`PACKET_READ_GENTLE_ON_EOF` and `PACKET_READ_GENTLE_ON_READ_ERROR`). It returns -1 on any protocol violation (truncated packet, malformed length header, empty packet where a status line or flush belongs), leaving the stream unusable but allowing the caller to handle the error gracefully. The handshake already has a gentle counterpart (added in 061a68e443), so a process that dies during startup or status exchange now feeds the same non-fatal fallback path.

The change is mechanical: the gentle variant is a copy of the original loop, with the gentle read options swapped in. The original `subprocess_read_status()` and its callers are untouched, preserving the die-on-error behavior for required subprocesses like filters. The patch touches only `sub-process.c` and `sub-process.h`, adding the new function and its documentation.

This is a well-motivated, narrowly scoped change that directly enables the optional diff process provider. The commit message clearly explains the problem (protocol errors in optional processes must not kill the command), the solution (a gentle status read), and the relationship to the existing gentle handshake. The patch is part of the series’ broader effort to make external diff processes degrade gracefully, and it looks ready for integration once the framework’s design is accepted.
