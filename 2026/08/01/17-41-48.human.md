This is patch 5/10 in the v7 RFC series introducing Git’s new diff provider interface. It teaches the stat output (`--stat`, `--numstat`, `--shortstat`) to consult the hunk provider chain before falling back to the built-in xdiff computation. The patch demonstrates the interface’s consult-only entry point, which answers without loading blob content or computing, and wires the `diff-hunks` store as the first provider in the chain.

The core change is in `builtin_diffstat()`: it now calls `diff_provider_consult()` with a summing callback that accumulates the provided hunk counts directly into the diffstat entry. On an unanswered outcome it computes as before and, if writing is enabled, records what it computed. The request struct gains the pair’s object IDs and diff options, and the walk enforces that a request’s diff options belong to the repository whose chain it walks. Object replacements are detected and handled as a no-record case, ensuring replaced content is never served from identity.

The patch also implements the store’s consult logic, which serves a recorded pair or passes, and excludes requests whose diff settings cannot be expressed in the store key (`-I`, `--anchored`, `-B`). The store’s consultation counters (`read_hits`, `read_misses`) are exposed through `diff_hunks_read_stats()` and emitted as a trace2 datum for tests and tuning. The stat consumer excludes `--ignore-blank-lines` before consulting, since that flag coalesces hunks differently between the text-emitting and coordinate-callback paths.

Test coverage is thorough: 280+ lines in `t/t4220-diff-hunks.sh` verify output parity with and without the store at several context lengths, both directions, and reversed pairs, and assert the consultation itself through the trace2 read-hits count. The tests also verify that settings which bypass the store (`-I`, `-B`, `--anchored`, `--ignore-blank-lines`) do so in both directions, and that a driver-forced algorithm keeps output correct and keys apart. A fixture with a real-world trim-divergent pair ensures the store never records a pair whose counts differ between contexts. The patch is well-motivated, with clear commit message and code comments explaining the design decisions and exclusions.
