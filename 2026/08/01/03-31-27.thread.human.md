This thread is about a bugfix for `git filter-branch` that corrects a long-standing inversion in the commit mapping logic when the `--state-branch` option is used. The issue causes the map directory to be populated backwards, leading to errors like "Is a directory" when `--prune-empty` is also used. The fix is minimal—just two lines in `git-filter-branch.sh`—and ensures that the state branch stores mappings in the correct "from_commit:to_commit" format.

Grant Moyer identified the problem and provided the patch, which also includes an updated test in `t/t7003-filter-branch.sh` to verify that the state branch is properly consulted. The test forces a failure in the tree filter and checks that the HEAD remains unchanged, confirming that the state branch was used and no new commits were created. The patch is straightforward and targets only the bug in question, with no broader changes to the script or its behavior. There are no open questions or objections in the thread so far.
