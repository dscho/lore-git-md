This is the eleventh iteration of Harald Nordgren’s `git history squash` feature, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now functionally complete and ready for integration, with v11 addressing the last design question from earlier versions: **message editing is now the default**, using the same autosquash-style template as `git rebase -i`.

The key changes in v11 are usability-focused. The command now opens an editor by default, pre-filled with every folded commit’s message in the same template used by `git rebase -i --autosquash`. Users who want to keep the default message (the oldest commit’s message, or the last `amend!` targeting it) can use `--no-edit`. This resolves the long-standing debate about whether to encourage commit hygiene by making users review the combined message. The implementation also tightens input validation: the range must now have exactly one boundary and one tip, and must not reach a root commit. Interior ref protection is now scoped to local branches only, leaving tags and remote-tracking refs unchanged.

The series is structured as four patches. Patch 1/4 refactors `first_parent_tree_oid()` to centralize logic for resolving a commit’s first-parent tree. Patch 2/4 adds a `message_template` parameter to `commit_tree_ext()`, enabling the message-editing feature. Patch 3/4 shares sequencer helpers for squash-message construction, ensuring the template matches `git rebase -i`. Patch 4/4 implements the core `squash` subcommand, including range validation, merge handling, ref protection, and the new default editor behavior. The test suite is comprehensive, covering edge cases like interior merges, ref handling, and `fixup!`/`squash!`/`amend!` message grouping.

This version is ready for merging. Junio’s "Will replace" sign-off on v7, the resolution of all technical feedback in v9 and v10, and the final design decision in v11 signal that the series is on track for the next release. The architectural vision of using `git history squash` as a faster backend for `git rebase --autosquash` remains a project-level aspiration, with this series as a foundational piece.
