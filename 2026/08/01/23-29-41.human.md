This is a follow-up in the GSoC patch series that extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. Jeff King (Peff) clarifies a fundamental architectural point: the current series is misusing `struct object_info`, which is designed for *single-object* queries, to handle *multi-object* remote queries.

Peff explains that `struct object_info` expects callers to provide pointers to where results should be stored for each queried field (e.g., `typep = &my_type`). This works for single-object queries but becomes awkward for batch operations, where you’d need an array of `object_info` structs—one per object—just to collect results. Instead, remote-object-info should define its own query structure using simple boolean flags (e.g., `want_type`) and store results in a flat array or directly in `expand_data`, the cat-file-specific struct.

The review is substantive and technical, not a blocker, but it identifies a conceptual mismatch that may require adjustments to the series. Pablo Sabater has not yet responded, and the thread remains under review. Key files: `fetch-object-info.c` and `odb.h`. The broader discussion about `struct object_info`’s design (pointer indirection vs. bitfields) is now secondary to this architectural concern.
