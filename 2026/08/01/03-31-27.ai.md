This is a bugfix for `git filter-branch`. The patch corrects a long-standing inversion in the commit mapping logic when `--state-branch` is used. The state branch stores mappings in "from_commit:to_commit" format, but the code was reading them as "to_commit:from_commit", causing the map directory to be populated backwards. The symptom is particularly visible with `--prune-empty`, which creates commits that map to nothing; on subsequent runs, the script tries to create files with empty names and emits errors like "Is a directory".

The fix is a two-line change in `git-filter-branch.sh`: split the line on the colon, then write the to-commit into the file named by the from-commit. The test is updated to verify that the state branch is actually used (by forcing a failure in the tree filter and checking that the HEAD is unchanged, meaning the state branch was consulted and no new commits were created).

The patch touches the shell script and the corresponding test file (`t/t7003-filter-branch.sh`). The test change is minimal and directly tied to the bug: it replaces a no-op tree filter with one that fails, ensuring that the state branch is the only reason the HEAD remains unchanged.
