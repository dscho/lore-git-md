This is the **second and final patch** in the v4 series adding the `--reset-when-found[=<where>]` option to `git bisect`. The series is now cooking in `next`.

The patch implements the core feature: once `git bisect` identifies the first bad commit, it automatically resets the working tree to either the pre-bisect commit (`original`, the default) or the first bad commit itself (`found`). The target is stored in a new `BISECT_RESET_WHEN_FOUND` state file and the reset is performed quietly. For `git bisect run`, the reset is deferred until after the captured output is printed and the `BISECT_RUN` file is closed, addressing platform-compatibility concerns about unlinking open files.

The implementation touches `bisect.c` and `builtin/bisect.c`, adding a new enum to track the reset mode, parsing logic for the `<where>` parameter, and wiring the option into both `git bisect start` and `git bisect run`. The option is rejected if used with `--no-checkout`, since that mode prevents checking out either target. Documentation updates and four new tests in `t/t6030-bisect-porcelain.sh` validate the behavior for both reset targets, state cleanup, and edge cases (invalid targets, `--no-checkout` conflicts, interrupted bisects).

All substantive and surface-level feedback from Johannes Sixt’s review has been addressed in this version. The series is uncontroversial, technically sound, and ready for integration. The only remaining loose end—joining `test_when_finished` commands with `&&`—is mechanical and does not affect the feature’s logic or readiness.
