Subject: [PATCH] filter-branch: fix commit mapping inversion with --state-branch
Series version: standalone patch (no series)
Originating author: Grant Moyer
Thread type: bugfix

Core problem or goal
`git filter-branch` with `--state-branch` has long stored commit mappings in "from_commit:to_commit" format but read them back as "to_commit:from_commit", causing the map directory to be populated backwards. When `--prune-empty` is used, this leads to commits that map to nothing; on subsequent runs the script attempts to create files with empty names and emits "Is a directory" errors.

- On-disk format change: none; the state branch file format is unchanged, only the read logic is corrected.
- Test coverage: minimal test change directly tied to the bug—replaces a no-op tree filter with one that fails, ensuring the state branch is the only reason HEAD remains unchanged.
