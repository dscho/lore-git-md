This is the seventh revision of the hunk provider interface RFC, now restructured as a unified series introducing a new abstraction layer (`diff-provider.h`) that lets Git consult alternate sources for diff hunks before falling back to the builtin xdiff computation. The series ships two example providers: an in-process cache (`diff-hunks` store) and an external process driver (`diff.<driver>.process`), both answering by object identity alone. The goal is to establish a framework where providers can supply hunks without consumers needing to know their implementation, enabling future extensions like content-carrying requests or additional backends.

The interface itself (patch 2) is the centerpiece: a repository-owned chain of providers, each asked in turn until one answers or fails, with the builtin xdiff as the terminal provider. The chain is built on first consultation and released in `repo_clear()`, ensuring provider state (like a running process) never outlives its repository. Consumers express requests in a single struct and read outcomes (answered, unanswered, or failed) without naming providers, so new providers integrate transparently. Performance measurements show the default path (no configured providers) runs within noise of the pre-series code, confirming the abstraction adds no measurable overhead.

The `diff-hunks` store (patches 3-6) demonstrates the non-authoritative side: an in-process cache at `$GIT_DIR/objects/info/diff-hunks` that may only reproduce the builtin diff. It is read by default and written only when opted in (`GIT_DIFF_HUNKS_WRITE=1`), warming as a side effect of existing diff work. The store is keyed by (old blob, new blob, xdl_opts) and recorded only when the pair's trimmed and untrimmed diffs agree, serving blame at zero context and stat formats at any `-U`. On git.git, a warmed store speeds up `log --stat -5000` by ~1.9x and blame by ~1.26x, with hit rates of 54-74% depending on the file. The store's format, keying, and handling of corruption/staleness are documented in new man pages (`git-diff-hunks(1)`, `gitformat-diff-hunks(5)`), and it deliberately lacks fsck integration or expiry, relying on `git diff-hunks clear` and re-warming for recovery.

The `diff.<driver>.process` provider (patches 7-10) demonstrates the authoritative side: an external process configured per driver, whose answers may differ from the builtin diff and outrank the store. Git asks it for a pair by object names alone, so it answers before any blob is read, suiting caches or processes that fetch blobs themselves. Consulting is opt-in per command (like `textconv`), and failures degrade to the builtin diff. The protocol is versioned and capability-negotiated, with forward-compatible design (processes ignore unknown request keys, Git ignores trailing hunk fields). The series stops at the identity-only request; content-carrying requests (for patch output) and other extensions are deferred to later series.

The series is a restructuring, not an incremental update, so it drops the content-carrying machinery from `mm/diff-process-hunks` and focuses on the identity-keyed framework. The external process protocol returns in patch 10, reduced to the oid-only request and consulting through the interface, with a per-command gate folded in. The blame and stat consults (patches 5-6, 10) are now identity-keyed, deferring their content legs to the content enrichment series. The documentation (patch 1) and subprocess plumbing (patches 7-9) return close to their v6 form, with patch 8 adding a gentle status read to avoid dying on protocol errors in optional processes.

Files touched span the diff core (`diff.c`, `diff.h`, `xdiff-interface.h`), blame (`blame.c`), and new components (`diff-provider.c`, `diff-hunks.c`, `diff-process.c`). New symbols include the provider interface (`diff_provider_emit_fn`, `diff_provider_consult_fn`), the store's on-disk format (`chunk-format.h`), and protocol constants (`PKT_REQUEST`, `PKT_HUNK`). The series applies on the `mm/line-log-limited-ops` topic (rebased onto master) and includes comprehensive test coverage (1412+ lines in `t/t4220-diff-hunks.sh` and `t/t4080-diff-process.sh`) and performance measurements (`t/perf/p4218-diff-hunks.sh`).

The RFC asks whether the direction is right, not for these ten patches to merge as one. If the approach is accepted, the work will return as separate series: the interface and store (patches 1-6), the process provider (patches 7-10), and the content enrichment (content-carrying requests and patch output integration). The series is technically complete for its scope, with all major diff and blame features wired to consult the interface, robust error handling, and no known regressions. The only remaining work is splitting into reviewable topics and addressing any design feedback on the framework.
