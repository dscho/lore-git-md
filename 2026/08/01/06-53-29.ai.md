This is the **final patch (4/4)** in Harald Nordgren’s `git history squash` series, now at **v11**. It implements the core functionality of the new `git history squash` subcommand, which folds a commit range into its oldest commit while preserving descendant history and opening an editor with an autosquash-style template by default.

The patch introduces the full implementation of the squash logic, including:
- **Range resolution and validation** via `resolve_squash_range()`, which ensures the selected history has exactly one boundary and one tip, rejects ranges reaching a root commit, and sanitizes `rev-list` options to enforce `--reverse --topo-order`.
- **Fixup/squash/amend handling** via `reject_dangling_fixups()`, which blocks markers whose targets lie outside the range (unless the range consists entirely of markers for one target).
- **Default message editing** via `build_squash_message()`, which constructs an autosquash-style template matching `git rebase -i --autosquash`, grouping markers under their targets and fully commenting out `fixup!` messages while retaining `squash!`/`amend!` bodies.
- **Ref-handling** via `find_interior_ref()`, which detects local branches pointing inside the range and rejects the operation by default, with advice guiding users to `--update-refs=head`.
- **Merge commit handling**, allowing fully contained merges (all parents within the range) while rejecting merges with external parents.

The implementation reuses sequencer helpers (extracted in patch 3/4) to ensure template consistency with `git rebase -i --autosquash`. The test suite (`t/t3455-history-squash.sh`) is comprehensive, covering edge cases like interior merges, ref handling, and marker grouping.

**Key names introduced**: `resolve_squash_range()`, `reject_dangling_fixups()`, `find_interior_ref()`, `build_squash_message()`, `--[no-]edit`, `ADVICE_HISTORY_UPDATE_REFS`, and the `interior`/`has_children` oidsets for range validation.
