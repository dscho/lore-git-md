This is a review comment on the second patch of Pablo Sabater’s GSoC v2 series, which extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. Junio C Hamano questions the motivation behind replacing `wc -c <two.t | xargs` with Git’s `test_file_size()` helper in `t/t5701-git-serve.sh`. The patch itself is mechanical and uncontroversial, but Junio’s feedback highlights that the commit message does not explain the benefit of the change. He notes that the exit status of `wc -c` is already lost due to the pipeline, and the current implementation does not improve error handling or reduce redundancy (e.g., running `git rev-parse` twice). While the helper is used elsewhere in the test suite, Junio suggests that the change would be more compelling if it also addressed these issues, such as by capturing the exit status of `git rev-parse` or avoiding redundant command invocations. The review is surface-level, focusing on the commit message’s clarity rather than the patch’s correctness or technical impact. No objections to the change itself are raised, but the feedback implies the patch could be more persuasive with a stronger rationale.
