This is the fifth patch in the v7 RFC series introducing Git’s new diff provider interface. It teaches the stat output (`--stat`, `--numstat`, `--shortstat`) to consult the hunk provider chain before falling back to the builtin xdiff computation. The patch wires the diff-hunks store (an in-process cache) into the stat path, so a warmed store can serve precomputed hunks directly, saving the xdiff run.

The core change is in `builtin_diffstat()`: it now calls `diff_provider_consult()` with a summing callback that accumulates the provided hunk counts into the diffstat entry. On an answer, the blobs were already loaded for the binary check, so the only cost saved is the diff computation itself (blame, taught in the next patch, skips its loads too). On an unanswered outcome, the code computes as before and, if writing is enabled, records what it computed. The request carries the pair’s object IDs and the diff options read by the exclusions; sides that are not stored blobs (working-tree files, gitlinks) have NULL IDs, so the store passes them by and the terminal provider computes them.

Exclusions live with the provider whose key cannot express them: `-I` patterns, `--anchored` anchors, and break detection (`-B`) shape the diff outside the store key, so the store’s consult maps all three to `DIFF_PROVIDER_DISP_STOP_NO_RECORD`, ensuring such a request is neither served nor recorded for any consumer. The stat consumer additionally excludes `--ignore-blank-lines` before consulting: that flag is part of the key but coalesces hunks differently between the text-emitting and coordinate-callback paths, so a served answer would not match a store-less run’s output. A “log -L” range-scoped stat neither reads nor records, since the line-range filter computes it as before.

The patch extends `t4220-diff-hunks.sh` with 280+ lines of tests covering the read half: output parity with and without the store at several context lengths, consultation visibility through the trace2 “read-hits” datum, trim-divergent pairs correct at every context, and every exclusion bypassing the store in both directions. The tests also verify that a driver-forced algorithm (e.g., `diff.foo.algorithm=histogram`) keys apart rather than bypassing, so a read under it misses the default entries and a warm records under its own. New symbols include `diff_provider_consult()`, the summing callback `diffstat_sum_hunk_cb()`, and the trace2 “read-hits” datum. Files touched are `diff.c`, `diff.h`, `diff-hunks.c`, `diff-hunks.h`, `diff-provider.c`, `diff-provider.h`, `diff-provider-internal.h`, `builtin/log.c`, and `t/t4220-diff-hunks.sh`.
