This is the fifth patch in Pablo Sabater’s GSoC v2 series, which extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote-object-info queries. The patch teaches the server to advertise the "type" capability, enabling the client to request object type metadata from the server. This is the last piece needed to complete the end-to-end chain: the server now advertises the capability, the client can request it (via earlier patches), and the test suite verifies the behavior.

The patch itself is small and mechanical. It updates `object_info_advertise()` in `serve.c` to include "type" in the advertised capabilities string, and adjusts the test suite in `t1017-cat-file-remote-object-info.sh` to reflect the new functionality. The test that previously verified `%(objecttype)` returned an empty string now expects the actual type ("blob"), and a new test confirms that truly unsupported placeholders (e.g., `%(objectmode)`) still return empty strings. The changes are straightforward and align with the established pattern from Eric Sunshine’s recently merged v21 series.

Chandra Pratap’s review comment is a surface-level nit: the line `echo $hello_type >expect` should use double quotes (`echo "$hello_type"`) to ensure proper handling of whitespace or special characters. Pablo has acknowledged the feedback and will incorporate the fix. The change has no functional impact in this context (since `$hello_type` is set to "blob"), but it is a best practice for robustness and aligns with Git’s shell scripting conventions.

The series as a whole is now complete and ready for maintainer consideration. All review feedback from v1 and v2 has been addressed, including Junio’s feedback on patches 2 and 4 (test portability and memory allocation strategy) and Chandra’s nit on this patch. The only remaining action is Pablo’s implementation of a preparatory patch to simplify the memory allocation pattern for `object_info_data[j].typep`, as suggested by Junio in patch 4. That change is not a blocker for this patch or the series, but it will further clean up the codebase.

This patch is uncontroversial and well-motivated. The series extends a recently merged feature (`--batch-command` remote-object-info) to include object type metadata, which is the last piece of metadata guaranteed to be identical on client and server after a fetch. The implementation is narrowly scoped, avoiding unreliable or context-dependent metadata like disk size or delta base, and the test coverage is thorough. The patch itself is a small, safe step that completes the advertised capability chain.
