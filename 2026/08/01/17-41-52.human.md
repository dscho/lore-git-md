This is a small but essential patch in the ongoing RFC series for Git’s new diff provider interface. It adds the `process` field to the `userdiff_driver` struct and teaches the config parser to read `diff.<driver>.process` from Git’s configuration. The field will hold the command string for a long-running external process that provides diff hunks, but nothing actually uses it yet — the plumbing for starting, pooling, and consulting these processes arrives in the next patch.

The change is mechanical: two lines in `userdiff.h` declare the field and its owned string, and seven lines in `userdiff.c` add the config parser. It follows the same pattern as the existing `textconv` and `algorithm` fields, so the code is clean and unsurprising. No tests or documentation are included here because the feature is inert until the next patch wires it up.

This patch is part of the external process provider effort in the larger diff-provider framework. The series as a whole is technically complete and ready for design feedback, but this particular patch is just the config scaffolding — the real action starts in patch 10.
