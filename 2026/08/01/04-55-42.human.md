This is the third patch in Pablo Sabater’s GSoC v2 series extending `` `git cat-file --batch-command` `` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the server-side object-info handler to add "type" support, completing the end-to-end chain that began in earlier patches.

The implementation is straightforward and follows the established pattern from Eric Sunshine’s recently merged v21 series. It adds a `type` bit field to the `requested_info` struct, parses the "type" keyword in client requests, and appends the object type (e.g., `"blob"`, `"tree"`) to the server’s response using `type_name()`. The patch also includes a test in `t5701-git-serve.sh` that verifies the server correctly handles a request for both "size" and "type" and returns the expected output format.

Junio’s review is substantive but narrowly focused on the patch’s mechanics rather than its design. He confirms the code change is correct and incremental, noting that the object type is already learned as part of the existence check, so adding it to the payload is a natural extension. His only observation is that the protocol’s input/output format (separate lines for "size" and "type" declarations but a single line for the response) feels inconsistent, though he acknowledges this is not something to change mid-series. The feedback is advisory and does not block the patch.

The patch is uncontroversial and ready for maintainer consideration. It is part of a well-scoped, review-converged series that addresses all prior feedback and is now complete. If the series lands, this patch will enable clients to request and display object type metadata from the server, matching the behavior of local queries.
