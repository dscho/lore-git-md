This is the second patch in Harald Nordgren’s **v11 `git history squash` series**, a **refactoring** that prepares the plumbing for the default message-editing feature introduced in patch 4/4. The patch adds an optional `message_template` parameter to the internal `commit_tree_ext()` helper in `builtin/history.c`. When the caller supplies a template, the function uses it instead of the commit message from the passed-in commit object; when NULL, the original behavior is preserved. This change is **purely preparatory**—no user-visible behavior changes—and enables the later patch to implement the autosquash-style message editor that resolves the usability debate from v10.

The patch modifies three existing callers (`commit_tree_with_edited_message`, `cmd_history_fixup`, and `split_commit`) to pass NULL, preserving their current behavior. The implementation is straightforward: if no template is provided, the function falls back to the original commit’s message body. The change is **well-scoped** and **ready to merge**, with no open technical concerns. Expect it to cook in `next` alongside the rest of the series.
