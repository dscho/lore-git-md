This is the fourth patch in Pablo Sabater’s GSoC v2 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the client to parse the "type" field from the server’s response, completing the end-to-end chain for object type metadata.

Junio’s review identified a memory allocation inefficiency: the current implementation calls `xcalloc` once per object ID to allocate `object_info_data[j].typep`, but these allocations are never freed independently. Pablo confirms this and proposes a simpler approach: allocate a single contiguous block for all `typep` pointers, then free them with a single `free(remote_object_info[0].typep)` call. This change will be implemented in a preparatory patch that also updates the `size` field to use the same pattern, and removes the now-unused `free_object_info_contents()` function.

The patch itself is otherwise uncontroversial and ready for integration once the memory management feedback is addressed. The thread context confirms this is the only outstanding feedback on the patch, and the series as a whole remains on track for maintainer consideration. The change is purely internal and does not affect the patch’s core functionality or user-visible behavior.
