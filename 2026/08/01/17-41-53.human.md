This is the final patch in the v7 RFC series introducing Git’s new diff provider interface. It wires up the external process provider (`diff.<driver>.process`) so that `git blame` and the stat formats (`--stat`, `--numstat`, `--shortstat`) can consult a long-running process for hunks before falling back to the built-in xdiff computation.

The patch implements the identity-only request leg of the protocol: Git sends only the blob object names (`old-oid`/`new-oid`) and the repository-relative path, and the process answers with hunk lines (`hunk <old_start> <old_count> <new_start> <new_count>`) or a `status=success` with zero hunks to assert the blobs equivalent. Because no content is exchanged, the answer is used as sent: hunks are validated for order, overlap, lockstep alignment, and magnitude (bounded by the blobs’ sizes), then replayed without xdiff’s compaction. A process that cannot answer from the object names responds `status=need-content`, and the pair falls through to the built-in diff.

The provider sits at the head of the repository’s chain, so its answers outrank the `diff-hunks` store and the built-in computation. A pair the process answers is never served from the store and never recorded into it; a pair it defers (with `need-content`, a missing capability, or a failed start) gets the built-in diff, so the store may serve it and a warming run may record it. The provider gates itself per request: it is looked up by the old-side path, so a renamed file resolves to the same driver, and options the process is never told about (whitespace-ignoring flags, `-I`, `--anchored`, a forced diff algorithm) bypass it. Consulting is opt-in per command, following the `allow_textconv` precedent: `git diff`, `git log`, `git show`, and `git blame` allow it by default; the plumbing diff commands and the interactive-patch machinery forbid it unless `--ext-diff` or `--diff-process` is given explicitly.

The process’s state is the repository’s pool of running processes, keyed by the configured command string, so drivers that share a command share a process, a submodule speaks to its own, and releasing the provider (from `repo_clear()`) stops them. A command that fails stays in the pool as an entry that is not retried, so its request and every later one pass to the built-in diff. Protocol errors (malformed frames, unrecognized status, a missing capability, or a process that dies mid-response) never kill the command: the response is read through a gentle packet reader, so an error warns once, stops the process, and falls back to the built-in diff for the rest of the command.

The patch adds the `process` field to `struct userdiff_driver` and teaches the config parser to populate it from `diff.<driver>.process`. It introduces `subprocess_read_status_gently()` to avoid dying on protocol errors in optional processes, and extracts `subprocess_start_command()`/`subprocess_stop_command()` as lower-level primitives to decouple the subprocess API from the global hashmap. The new test helper `test-diff-process-backend` implements the protocol and exercises every adversarial response shape the error paths handle, and `t/t4080-diff-process.sh` verifies the protocol, the per-command gate, and the error paths. The documentation updates `gitattributes(5)` to explain the protocol and when it is consulted, and the diff options to document `--diff-process` and `--no-diff-process`.
