This is the final patch in Harald Nordgren’s **v11 series** introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The patch implements the core logic, including **default message editing** (resolving the usability debate from v10), **range validation**, **merge commit handling**, and **ref safety checks**.

The command now **opens an editor by default** with an autosquash-style template matching `git rebase -i --autosquash`, grouping `fixup!`/`squash!`/`amend!` commits under their targets. The `--no-edit` flag skips the editor, keeping the oldest commit’s message (or the last `amend!` targeting it). This aligns with Phillip Wood’s argument for encouraging commit hygiene while preserving flexibility.

Key technical details:
- **Range validation**: Rejects ranges with multiple tips, roots, or ambiguous bases, ensuring the selected history has a single boundary and tip. Supports compound ranges (e.g., `HEAD~3..HEAD ^topic`) and sanitizes `rev-list` options.
- **Merge handling**: Allows interior merges (all parents within the range) but rejects merges with external parents. Uses `--ancestry-path` to ensure only commits descended from the base are included.
- **Ref safety**: By default, refuses operations where **local branches** point inside the range, with advice guiding users to `--update-refs=head` to rewrite only the current branch. Tags and remote-tracking refs are left unchanged.
- **Marker handling**: Rejects `fixup!`/`squash!`/`amend!` commits unless their target is in the range, except for ranges made entirely of markers for one target (e.g., a batch of fixups for the same commit).
- **Test coverage**: The 758-line test script (`t/t3455-history-squash.sh`) covers edge cases like interior merges, ref handling, and marker grouping, using helpers (`stage_file`, `commit_with_message`) to improve readability.
