This is the eleventh patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery to `size_t` for 64-bit Windows compatibility. The series is now fully type-consistent and queued in `next` for integration testing.

This patch widens the `maxsize` local variable in `t/helper/test-pack-deltas.c`’s `do_compress()` function from `unsigned long` to `size_t`. The change is purely preparatory: `maxsize` is only used to hold the return value of `git_deflate_bound()` (which will be widened to `size_t` in a later patch) and to size the output buffer for `xmalloc()` and `stream.avail_out`. The widening has no semantic effect today but ensures type consistency once `git_deflate_bound()`’s return type is updated.

The patch is mechanical and low-risk, touching only one line in a test helper. It is part of the broader effort to eliminate incorrect `unsigned long` usage in Git’s delta/pack subsystems, which is particularly important for 64-bit Windows where `unsigned long` is 32-bit. No behavior changes or new tests are introduced.

This is a minor but necessary step in the series, and the change aligns with the established pattern of widening size-related variables to `size_t`. The patch is uncontroversial and ready for integration.
