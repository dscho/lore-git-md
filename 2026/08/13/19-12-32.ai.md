This is the first patch in Junio C Hamano’s three-patch v3 series fixing Bash completion for `git checkout`. It is a **no-op refactoring** of the `_git_checkout()` function in `contrib/completion/git-completion.bash`, preparing the ground for the functional changes in patches 2/3 and 3/3.

The patch reorganizes the control flow to avoid the early return when `--` is detected on the command line. Previously, the function would exit immediately if `--` was present, delegating to Bash’s default file completion. Now, the logic is wrapped in an `if ! __git_has_doubledash` block, with explicit `return` statements added to each completion branch (option arguments, `--conflict=*`, and `--*` flags). The refactoring does not change behavior—it merely restructures the code to make room for the upcoming changes in patch 2/3, where the function will need to handle path completion even when `--` is present or revision completion yields no matches.

The diff shows a straightforward reorganization: the outer `case` statement is split into two nested `case` blocks (one for `$prev`, one for `$cur`), each now guarded by the `if ! __git_has_doubledash` condition. The core completion logic—handling `-b/-B/--orphan`, `--conflict=*`, and other options—remains identical, just moved into the new structure. The patch is uncontroversial and well-motivated by the series’ goal: ensuring `git checkout` path completion prioritizes tracked files over untracked ones, with a fallback only when necessary. Test coverage in `t/t9902-completion.sh` (added in patch 2/3) verifies that this refactoring preserves existing behavior.
