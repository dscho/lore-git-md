This is the fourth patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery to `size_t` for 64-bit Windows compatibility. The series as a whole is cooking in `next` and is uncontroversial.

This specific patch widens the return type of `free_unpacked()` from `unsigned long` to `size_t` to match the widened `SIZE(n->entry)` field (already `size_t` from prior work). The change prevents silent truncation on 64-bit Windows when packing repositories with many large objects. The patch is mechanical, touching only the function signature and its single local variable in `builtin/pack-objects.c`. The caller (`find_deltas()`) still uses `unsigned long` for its `mem_usage` counter, so truncation persists there, but this patch removes one truncation point in the chain.

The commit message clearly explains the truncation risk and the context (prior widening of `SIZE()`). No behavior change or new tests are introduced. This is a straightforward, low-risk correctness fix that aligns with the series’ goal of eliminating `unsigned long` usage in the delta/pack subsystems.
