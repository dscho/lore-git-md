This is the fifth patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t` to prevent integer truncation on 64-bit Windows. The series is now in its third iteration, fully type-consistent, and queued in `next` for integration testing.

This patch widens the `mem_usage` counter in `find_deltas()` and the corresponding output parameter in `try_delta()` from `unsigned long` to `size_t`. The change is necessary because `mem_usage` accumulates byte counts that are already computed as `size_t` (via `SIZE()` and `sizeof_delta_index()`), and leaving it as `unsigned long` would reintroduce truncation on platforms where `unsigned long` is 32-bit. The patch is mechanical and confined to a single file (`builtin/pack-objects.c`), changing only two lines to ensure type consistency.

The commit message clearly explains the rationale: `mem_usage` and `try_delta()`’s output parameter must move together to maintain type safety, as `find_deltas()` passes `&mem_usage` directly to `try_delta()`. The patch leaves `window_memory_limit` (a configuration-driven value) as `unsigned long` because it is only compared against `mem_usage` and promotes safely. This is a low-risk, correctness-focused change that aligns with the series’ broader goal of eliminating truncation risks in the delta/pack subsystems.

The patch is uncontroversial and well-motivated, addressing a specific truncation risk without altering behavior or on-disk formats. It is part of a larger, well-reviewed effort to modernize Git’s type usage, and the changes here are narrowly scoped to complete the type chain in the delta-window memory accounting logic. No new tests are needed, as the patch does not change observable behavior. This is a solid, incremental step toward platform compatibility on 64-bit Windows.
