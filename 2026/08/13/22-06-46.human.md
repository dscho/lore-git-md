This is a small but important **platform compatibility fix** for the external process provider in the diff-provider RFC series. Junio Hamano reports that the build breaks on platforms where `unsigned long` is narrower than `size_t` (e.g., 32-bit systems and 64-bit Windows) due to a recent change in Git's object database API (`c6a4629e32`, June 2026). The patch Michael Montalbo sent uses `unsigned long size` to store a blob size, but `odb_read_object_info_extended()` now expects a `size_t` for its `sizep` field.

Junio provides a one-line fix: replace `unsigned long size` with `size_t size` in `blob_line_cap()` (`diff-process.c`). This aligns the variable with the API's type and resolves the `-Wincompatible-pointer-types` warning. The change is purely mechanical and does not affect functionality, as the subsequent bounds check (`size > INT32_MAX`) remains valid. Junio has already applied the fix tentatively to his `seen` branch to unblock testing, but notes he hasn’t checked for further fallout in the series.

The fix is a minor but necessary step toward making the external process provider work across all supported platforms. It doesn’t address the larger design questions raised by Phillip Wood in the thread (motivation, terminology, or authority trade-offs), but it ensures the code compiles and runs where it’s supposed to. If you’re tracking the diff-provider RFC, this is a small but required update to keep the series viable.
