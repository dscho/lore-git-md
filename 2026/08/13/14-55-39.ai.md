This is the first patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t`. It prepares the ground for later patches by widening the internal `struct delta_index` fields (`memsize` and `src_size`) and the return type of `sizeof_delta_index()` to `size_t`. The struct is private to `diff-delta.c`, so this change is purely internal and has no runtime effect on its own—the public API around it still truncates values to `unsigned long`. The patch is mechanical and uncontroversial, touching only two files (`delta.h` and `diff-delta.c`) with no behavior or on-disk format changes.

The motivation is to eliminate integer truncation risks on 64-bit Windows (where `unsigned long` is 32-bit) and other platforms where `unsigned long` does not match the pointer width. This patch is a prerequisite for later commits that will widen the public delta-encoding API, allowing `pack-objects.c` to drop the `cast_size_t_to_ulong()` shims introduced in commit `606c192380`. The series is queued in `next` and remains type-consistent across all affected code paths after v3 addressed Junio C Hamano’s review feedback.

Key symbols modified in this patch include `struct delta_index.memsize`, `struct delta_index.src_size`, and `sizeof_delta_index()`. The changes are confined to type widening and do not alter the logic or behavior of the delta-encoding subsystem. This patch is part of the broader effort to replace incorrect `unsigned long` usage with `size_t` in Git’s delta and pack-objects code. No new tests are added, as the changes are internal and do not affect observable behavior. The series is expected to graduate to `master` without further changes unless integration testing reveals new issues.
