This is the v5 revision of the patch series introducing `git repack --drop-filtered` for partial clones, a feature that allows users to reclaim disk space by safely removing locally cached promisor blobs exceeding a specified size threshold. The series is now down to six patches after squashing the documentation into the relevant implementation patches, addressing all feedback from v4.

The core functionality remains unchanged: promisor objects are enumerated via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, filtered by size using the new `list_objects_filter__filter_oidset()` helper, and dropped by rebuilding the promisor pack while excluding them. The blocking type-mismatch bug in patch 2/7 (fixed by changing `unsigned long` to `size_t`) and Christian Couder’s mechanical feedback (making the `opts` parameter `const`, squashing documentation, and comment fixes) have all been incorporated. The series is now technically sound and ready for maintainer review, with no known blocking issues.

Key changes since v4 include the documentation reorganization (squashed into patches 5 and 6), improved error messages (now listing all blocked operations explicitly), and mechanical cleanups (comment formatting, indentation). The safety guards (merge/rebase/cherry-pick checks and index validation) are still framed as UX optimizations, and the deferred work (remote verification, recency-based culling, drop log) remains explicitly out of scope. The test script (`t/t7706-repack-drop-filtered.sh`) is comprehensive, covering option parsing, validation, enumeration, real drops, and the safety guards.

The series touches `builtin/repack.c`, `list-objects-filter.{c,h}`, `repack-promisor.c`, `repack.h`, and `Documentation/git-repack.adoc`, and introduces a new file (`repack-filtered.c`). The implementation is well-scoped, enforcing preconditions (`-a` required, promisor remote required, `--filter` limited to `blob:limit`), avoiding lazy fetches during enumeration, and silently disabling bitmaps to prevent pack closure issues. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety.
