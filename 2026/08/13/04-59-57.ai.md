This is a follow-up discussion in the resolved thread about unexpected pseudo-commits appearing in a custom `git lg` alias. Kristoffer Haugsbakk replies to Junio C Hamano’s reflection on the unintuitive behavior of `git log --all`, which includes all refs (such as Git notes and stash refs) rather than just branches, tags, and remote-tracking branches.

Kristoffer speculates that `--all` may have been designed before Git notes existed, with the intent to include custom refs users were expected to be aware of. He notes that while branches and tags are easily shared, Git notes require explicit refspecs to push or fetch, making them less likely to propagate unintentionally. However, he acknowledges that third-party tools (e.g., `rewrite-analytics` or IDE integrations) might use Git notes for metadata, exposing implementation details when `--all` is used. He also confirms Junio’s observation that `git log --all -p` includes commits from `refs/stash`, reinforcing the broader scope of `--all`.

The exchange remains observational, with no proposals for changes or further action. It clarifies the historical and technical context behind `--all`’s behavior but does not reopen the thread or suggest workarounds beyond those already identified. The discussion underscores the tension between plumbing-level flexibility (where `--all`’s inclusivity may be justified) and porcelain-level usability (where it can surprise end users).
