This is the third patch in the v5 series introducing `git repack --drop-filtered` for partial clones. It extends `repack_promisor_objects()` to accept an optional `to_drop` oidset, allowing the rebuilt promisor pack to exclude specific objects. The change is minimal and backward-compatible: all existing callers pass `NULL`, so behavior remains unchanged. The patch touches `repack-promisor.c`, `repack.h`, and updates the call site in `builtin/repack.c`.

The implementation adds a `to_drop` field to the `write_oid_context` struct and modifies `write_oid()` to skip objects present in the set. The logic is straightforward: during promisor object enumeration, any object in `to_drop` is omitted from the new pack. This is the mechanism `--drop-filtered` will use to remove large promisor blobs while ensuring they remain recoverable from the promisor remote.

The patch is well-scoped and uncontroversial. It doesn’t introduce new behavior on its own but enables the core functionality in later patches. The commit message clearly explains the purpose and backward compatibility. No test coverage is included here, as the functionality is exercised in subsequent patches (notably patch 5/6). This is a clean, mechanical change that fits neatly into the series’ overall design.
