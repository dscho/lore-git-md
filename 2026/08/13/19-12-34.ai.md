This is the third patch in Junio C Hamano’s v3 series fixing Bash completion for `git checkout`. It adds a fallback to untracked paths when no tracked paths match, ensuring completion never fails silently. The change is minimal—four lines in `contrib/completion/git-completion.bash`—and aligns with the earlier `git diff` completion series by using `__git_complete_index_file "--others --directory"` for consistency and performance.

The patch’s value is pragmatic rather than functional: while untracked paths are unlikely to be useful for `git checkout` (since they don’t exist in the index and are rarely present in other branches), the fallback prevents the completion from defaulting to arbitrary files in `$PWD`. The commit message acknowledges this limitation and marks the broader goal of completing paths from arbitrary trees as `#leftoverbits` for future work.

Test coverage is thorough, adding two new tests to `t/t9902-completion.sh`:
1. Verifies `git checkout u` (and `git checkout -- u`) completes untracked files (`ufile`) when no tracked paths or refs match.
2. Extends the existing `-C <path> checkout` test to include untracked files (`ufile`) alongside tracked and missing files, ensuring the fallback works consistently across directories.

The patch is uncontroversial and ready for integration. It follows Elijah Newren’s suggestion from v2 to include `--directory` in the `--others` call, resolving the only remaining technical question. The series as a whole is now complete, with patches 1/3 (refactoring) and 2/3 (tracked-path priority) already summarized.
