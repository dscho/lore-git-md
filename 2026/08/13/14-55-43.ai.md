This is a platform-compatibility patch widening two tightly coupled variables in the delta-compression memory accounting chain to `size_t`. It is the fifth patch in Johannes Schindelin’s 13-patch v3 series that completes the `unsigned long` → `size_t` conversion for Git’s delta and pack-objects machinery on 64-bit Windows.

The patch widens the `mem_usage` counter in `find_deltas()` and the corresponding output parameter in `try_delta()` from `unsigned long` to `size_t`. These two must move together because `find_deltas()` passes `&mem_usage` directly to `try_delta()`. The change is purely mechanical: the counter accumulates byte counts that are already computed as `size_t` (via `SIZE()` and `sizeof_delta_index()`), so widening it eliminates the last 32-bit truncation risk in the delta-window memory accounting chain on platforms where `unsigned long` is 32-bit. The `window_memory_limit` configuration variable remains `unsigned long` because it is only compared against `mem_usage` and promotes automatically.

The patch touches a single file (`builtin/pack-objects.c`), changes two lines, and carries no behavior or on-disk format change. It is uncontroversial and part of a well-reviewed series that is already queued in `next`. The commit message is clear and self-contained, explaining the coupling between the two variables and the rationale for leaving `window_memory_limit` unchanged. No new tests are needed because the change is internal and does not alter observable behavior. This patch is a small but necessary step toward full type consistency in the delta/pack subsystems.
