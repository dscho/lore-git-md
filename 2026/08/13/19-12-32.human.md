This is the first patch in Junio C Hamano’s three-part series fixing Bash completion for `git checkout`. It is a no-op refactoring of the `_git_checkout()` function in `contrib/completion/git-completion.bash`, reorganizing the control flow to prepare for the functional changes in the next two patches.

The patch eliminates an early return when `--` is detected on the command line, wrapping the existing logic in an `if ! __git_has_doubledash` block instead. Each completion branch (option arguments, `--conflict=*`, `--*`, and revision references) now ends with an explicit `return` statement. This refactoring makes room for the upcoming changes in patch 2/3, which will modify what happens when revision completion yields no matches or when `--` is present.

The commit message explains the motivation clearly: the early return currently allows Bash’s default file completion to kick in, but the next patch will need to override this behavior to prioritize tracked paths. The refactoring is mechanical and does not alter any behavior, as confirmed by the test coverage in `t/t9902-completion.sh` (which verifies that existing functionality remains unchanged).

This patch is uncontroversial and well-motivated. It is a necessary preparatory step for the series’ core fix, and the changes are straightforward and easy to review. The series as a whole is ready for integration, with no open questions or objections.
