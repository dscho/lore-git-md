This is the sixth patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t`. The series is a platform-compatibility fix targeting 64-bit Windows, where `unsigned long` is 32-bit and can truncate large object sizes.

This patch widens the `create_delta()` and `diff_delta()` functions in `delta.h` and their implementations in `diff-delta.c` to use `size_t` for all size parameters and output variables. The change is mechanical and confined to type signatures, with no behavior or on-disk format changes. The commit message explains the necessity of updating all callers in the same patch to maintain build consistency, as the `delta_size` output parameter must match the widened `size_t*` type.

Callers in `builtin/pack-objects.c`, `builtin/fast-import.c`, `diff.c`, and test helpers are updated with minimal changes. Some callers retain `unsigned long` locals (e.g., `deltalen` in `fast-import.c`) due to downstream dependencies on still-unsigned interfaces (like zlib’s `avail_in`), bridged via temporary `size_t` variables and `cast_size_t_to_ulong()` shims. The test helper `test-delta.c` widens its local outright, as it has no downstream consumers beyond its own `size_t` output. A GCC-specific workaround initializes `deltalen` to 0 to suppress a false-positive uninitialized-variable warning; this will be removed in a later series when the variable is widened to `size_t`.

The patch is part of a well-structured, uncontroversial series that has already addressed all prior review feedback. It is queued in `next` and ready for integration. The changes are low-risk and complete the type-widening work for the delta-encoding API, ensuring consistency across the delta and pack-objects subsystems on platforms where `unsigned long` is narrower than `size_t`. Key symbols modified include `create_delta()`, `diff_delta()`, and their `delta_size` output parameters.
