This is a **procedural follow-up** to the `http.sslVerifyStatus` security feature patch. Junio C Hamano provides two small but necessary corrections to the v3 submission. The first is a one-line addition to `t/meson.build` to ensure the new test script (`t5568-http-verify-status.sh`) is recognized by the Meson build system, preventing build failures. The second is a fix to the test script itself: the `SSL_VERIFYSTATUS` lazy prerequisite now properly checks the exit status of `git ls-remote`, ensuring the test fails loudly if the server does not support OCSP stapling rather than silently passing.

These changes are purely mechanical and do not alter the patch’s functionality or design. The patch remains a security feature that adds a boolean `http.sslVerifyStatus` config option (default `false`) to enable OCSP staple validation via libcurl, addressing a gap where OpenSSL-linked Git binaries ignore staples and accept revoked certificates. The procedural feedback here resolves the last integration hurdles, leaving the open question of whether the feature’s maintenance burden is justified by its use case (government and FIPS-compliant deployments) as the sole remaining discussion point. The patch is now technically complete and ready for final review.
