This is the fifth patch in the v5 series introducing `git repack --drop-filtered` for partial clones. It wires up the actual object removal logic, making the feature functional rather than just reporting candidates.

The patch connects the `to_drop` oidset—computed by `enumerate_promisor_blobs()` in patch 4—to `repack_promisor_objects()`, which rebuilds the promisor pack while excluding the dropped blobs. On a real run (`--drop-filtered` without `--dry-run`), it sets `delete_redundant = 1` to remove old promisor packs containing the dropped objects, reclaiming disk space. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. The test script verifies that a large promisor blob is absent after `--drop-filtered` runs, while a smaller one remains.

The documentation update in this patch is the bulk of the user-facing description for `--drop-filtered`, covering preconditions (`-a` required, promisor remote required, `--filter` limited to `blob:limit`), incompatibilities (`--filter-to`, bitmaps), implied `-d`, and silent bitmap disabling. The patch also removes the placeholder `die()` that previously blocked real runs, enabling the feature to work as intended.

This is a straightforward integration patch with no new technical debt. The only moving part is the conditional `to_drop` parameter passed to `repack_promisor_objects()`, which is backward-compatible (all existing callers pass `NULL`). The test coverage is minimal but sufficient: it confirms the large blob is gone and the small one remains, without re-testing the safety guards or validation logic already covered in earlier patches. The patch is ready for review, with no known issues.
