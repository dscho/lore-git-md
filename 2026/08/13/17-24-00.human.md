This is the final patch in Kristoffer Haugsbakk’s four-part series adding `--abbrev`, `--color`, and `--date` formatting options to the `git format-rev` command. The patch completes the feature work by implementing the three new options, reusing existing logic from `git log` to ensure consistent behavior.

The implementation is straightforward: it extends the `format_rev_data` struct (introduced in patch 2) to include a `rev_info` instance and a color setting, then wires up the new options via standard Git option callbacks (`OPT__ABBREV`, `OPT__COLOR`, and a custom `date_cb`). The pretty-printing context (`format_pp.ctx`) is now populated from the new struct fields rather than a local `rev_info` variable, and the command synopsis is simplified to highlight the two mandatory options (`--stdin-mode` and `--format`) while tucking the rest into `[<options>]`.

Test coverage is thorough: `t/t6120-describe.sh` adds three new test functions (`format_rev_cmp_log`, `format_rev_err_cmp_log`) that verify each option’s behavior by comparing `git format-rev` output against `git log --stdin --no-walk` output for the same input and options. Error cases (invalid `--color` or `--date` values) are also tested. The documentation updates are minimal but clear, adding concise descriptions of the new options and including the existing `--date` alternatives block (moved to a shared file in patch 3).

The patch looks well-crafted: it leverages existing infrastructure, avoids code duplication, and maintains parity with `git log`’s formatting behavior. The only open question is whether the UI simplification (collapsing all non-mandatory options into `[<options>]`) will draw objections, but the change is small and the rationale (improving readability) is reasonable.
