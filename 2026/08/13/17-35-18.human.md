This is a small bugfix patch series targeting Git's trailer parsing logic. The goal is to stop Git from mistakenly treating lines that begin with `<token>://` (like URLs) as trailers. For example, a line like `https://example.com` in a commit message should not be parsed as a trailer, but the current code sometimes does so.

The series consists of two commits. The first is a straightforward fix that updates the trailer parsing logic to exclude lines starting with `<token>://`. The second is a merge commit that incorporates an earlier documentation-only series (`kh/doc-trailers`), which is a dependency for this work. The commit message and cover letter are clear and well-motivated, explaining the problem and the fix without overcomplicating things.

The patch is currently on hold, waiting for its base topic (`kh/doc-trailers`) to graduate to `master`. Kristoffer Haugsbakk, the author, has stated he will resend the series once that happens.
