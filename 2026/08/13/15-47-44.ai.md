This is the first patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration to mark repositories as trusted for lazy fetching. The patch is a pure refactoring of the promisor-remote subsystem, extracting the lazy-fetch logic into a new `lazy_fetch_objects()` helper function.

The refactoring consolidates the `GIT_NO_LAZY_FETCH` environment variable check so it runs once up front instead of once per promisor remote, and skips the `promisor_remote_init()` call when lazy fetching is disabled. It also splits the `promisor_remote_get_direct()` function into two parts: one that decides which remotes to try (`lazy_fetch_objects()`), and another that validates the objects that could not be fetched. The `try_promisor_remotes()` helper is updated to return a `bool` instead of an `int` to clarify its meaning—whether all objects were fetched.

The patch is uncontroversial and introduces no behavior changes. It is a preparatory step for the later patches in the series, which will use the new `lazy_fetch_objects()` helper to integrate the `uploadpack.lazyFetchTrusted` configuration. The commit message is clear and the code changes are well-motivated, focusing on efficiency and clarity. No review feedback has been posted yet, but the patch is positioned as ready for integration once the broader series is reviewed.
