This is the first patch in Patrick Steinhardt’s four-part series refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternates. The patch decouples path comparisons for alternate ODB sources from `the_repository`, fixing a long-standing inconsistency in case-sensitivity handling when alternates are registered before repository configuration is parsed.

The change replaces the existing `khash`-based map (using `fspathhash()` and `fspatheq()`) with a `struct hashmap` that tracks case-sensitivity per ODB. This avoids relying on `repo_ignore_case()`, which may return a default value before configuration is loaded. The patch adds 41 lines of code and introduces new fields (`source_paths_icase`) and comparison functions (`odb_source_paths_cmp()`, `odb_source_by_path_cmp()`). The motivation is technical correctness: the current implementation can produce inconsistent deduplication results depending on when alternates are registered.

Karthik Nayak’s review is surface-level, suggesting a minor simplification to the `odb_source_paths_cmp()` function (removing a temporary variable) but otherwise approving the patch. The simplification is straightforward and doesn’t affect the patch’s core logic. No substantive concerns were raised, and the patch remains unchanged from v1 except for minor commit message clarifications in the series.

This patch is well-motivated and appears ready for integration. The added complexity is justified by the need to resolve case-sensitivity inconsistencies, though the trade-off between hashmap overhead and linear search performance for rare edge cases (e.g., repositories with thousands of alternates) was debated in earlier discussion. The patch is part of Patrick’s broader ODB abstraction effort and depends on his prior `ps/odb-make-creation-pluggable` series.
