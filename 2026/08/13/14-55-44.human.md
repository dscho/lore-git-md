This is the sixth patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t`. The series is a platform-compatibility fix targeting 64-bit Windows, where `unsigned long` is 32-bit and can truncate large object sizes.

This patch widens the `create_delta()` and `diff_delta()` functions in `delta.h` and their implementations in `diff-delta.c` to use `size_t` for all size parameters and output variables. The change is mechanical and confined to type widening, with no behavior or on-disk format changes. The patch updates all callers in `builtin/pack-objects.c`, `builtin/fast-import.c`, `diff.c`, and the test helpers (`test-delta.c` and `test-pack-deltas.c`), introducing temporary `cast_size_t_to_ulong()` shims where downstream consumers (e.g., zlib’s `avail_in`) still expect `unsigned long`. These shims are explicitly noted as temporary and will be removed in later patches that widen those consumers.

The commit message is clear and self-contained, explaining the scope of the changes and the rationale for the temporary shims. The patch is part of a well-structured series that has already addressed all prior review feedback, including Junio C Hamano’s concerns about truncation risks. The series is queued in `next` and is uncontroversial, with no open questions or loose ends. This patch is a straightforward, low-risk step in the broader effort to eliminate incorrect `unsigned long` usage in Git’s delta and pack-objects subsystems. It should be of particular interest to Windows users and anyone working with large objects.
