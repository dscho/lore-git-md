This is a bug report about `git pull`, `git merge`, and `git rebase` with `--autostash`. The author, Jos van den Oever, reports that when these commands use `--autostash` to stash and restore uncommitted changes, the mtime (modification time) of restored files is updated to the current time, even if the file content did not change. This breaks build systems that rely on mtime to determine whether to rebuild, and it disrupts workflows that use mtime as a proxy for file age (such as automated commit systems).

The report is clear and well-motivated, with two concrete use cases: avoiding unnecessary rebuilds and preserving accurate timestamps for automated commits. The author suggests that Git could restore the original mtime when applying the stash, which would align with Git’s general behavior of not altering mtime unless the file content actually changes. There is no patch attached—this is a problem statement rather than a fix—but the issue looks real and the impact is easy to understand. If you work on build systems or automated Git workflows, this is worth following.
