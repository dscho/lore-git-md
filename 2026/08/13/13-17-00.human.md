This is a minor follow-up in the ongoing ODB refactoring series from Patrick Steinhardt. The series as a whole aims to remove lazy-loading of alternate object databases, simplifying the codebase and enabling future work on the ODB abstraction. This specific email is a reply to Karthik Nayak’s surface-level review of the first patch in the v2 series, which decouples path comparisons for alternate ODB sources from `the_repository` to fix inconsistent case-sensitivity handling.

Karthik suggested a stylistic simplification to the code in `odb_source_paths_cmp()`—replacing a conditional block with a direct assignment—but Patrick explains why the original version is necessary. The configuration lookup (`repo_config_get_bool()`) can fail if the setting isn’t present, so the code must handle the case where `o->source_paths_icase` remains unset (retaining its initial value of `-1`). Patrick’s alternative rewrite avoids repeating the lookup but is less readable, so he opts to keep the original implementation. The exchange is purely about code clarity and correctness, with no impact on functionality or the series’ broader goals.

The series itself remains queued in Junio’s `seen` branch, with all patches unchanged except for minor commit message clarifications and a comment added in patch 4. The discussion here doesn’t reopen any of the substantive design decisions from v1 (e.g., the trade-offs of eager alternate loading or the hashmap-based deduplication), and no further changes are expected. This is a routine clarification in an otherwise uncontroversial cleanup effort.
