This is the final patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t`. Specifically, it widens the `unpack_object_header_buffer()` function in `packfile.c`—the last remaining `unsigned long` interface in the affected code paths—by converting its `len` parameter and return type to `size_t`. This change completes the series’ goal of eliminating integer truncation risks on 64-bit Windows, where `unsigned long` is 32-bit.

The patch touches four files: `builtin/pack-objects.c`, `oss-fuzz/fuzz-pack-headers.c`, `packfile.c`, and `packfile.h`. In `packfile.c`, the function’s signature and all internal variables (`used`, `size`, `c`) are updated to `size_t`, ensuring type consistency with the widened `sizep` output parameter introduced earlier in the series. Callers in `builtin/pack-objects.c` and the fuzzer are adjusted to pass `size_t` values, and the function’s return type in `packfile.h` is updated accordingly. The changes are mechanical and confined to type widening, with no behavior or on-disk format changes.

This patch directly addresses Junio C Hamano’s review feedback from v2, which flagged `unpack_object_header_buffer()` as a truncation risk. With this change, the series is now fully type-consistent across all delta and pack-objects code paths, including the zlib stream interfaces, delta-encoding API, and memory accounting variables.
