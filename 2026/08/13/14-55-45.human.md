This is the seventh patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t` to prevent integer truncation on 64-bit Windows. The series is now fully type-consistent and queued in `next` for integration testing.

This patch specifically widens the `use_pack()` function’s `left` output parameter and the `avail_in`/`avail_out` fields in the `git_zstream` struct to `size_t`. The change is mechanical and bundled together because four call sites pass `&stream.avail_in` directly to `use_pack()`, making it simpler to widen both types simultaneously. The patch also updates `zlib_buf_cap()` to accept `size_t` inputs, ensuring consistency with the widened zlib stream fields.

The affected code paths handle pack-window sizes and zlib buffer accounting, both of which are bounded by configuration limits (e.g., `core.packedGitWindowSize`) and the 1 GiB cap in `zlib_buf_cap()`. The change is purely about type consistency rather than enabling new >4GB capabilities. No behavior or on-disk format changes are introduced, and the patch is uncontroversial.

The commit message is clear and explains the rationale for bundling the changes, while the diff is straightforward and confined to type widening. This patch is a prerequisite for the next commit, which will widen `do_compress()` to eliminate the last `cast_size_t_to_ulong()` shim in `write_no_reuse_object()`. The series as a whole is a well-crafted, low-risk fix that completes the type-widening work for the delta and pack-objects subsystems.
