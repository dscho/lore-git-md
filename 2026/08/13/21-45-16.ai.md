This is the first patch in Justin Tobler’s v3 series extending ODB transactions to `git receive-pack`, and this email is his reply to Patrick Steinhardt’s substantive review of that patch. The patch fixes a critical lockfile lifecycle flaw introduced in an earlier ODB transaction commit (bdee7b3013), where stale ".keep" files were left behind because the lockfile path became invalid after the transaction committed.

The core of the discussion is whether the current design—writing the ".keep" file to the temporary transaction directory and migrating it alongside the packfile—actually preserves the race-avoidance properties the ".keep" file is meant to provide. Patrick proposes an alternative: write the packfile to the temporary directory without a ".keep" file, then at commit time write a ".keep" file to the main object directory before migrating the packfile, and finally remove it during finalization. Justin argues the current approach is functionally equivalent and prefers to keep the changes minimal, but agrees to clarify the commit message and add a test hook to verify the ".keep" file is in the correct location before commit.

The patch itself updates `index_pack_lockfile()` to accept an explicit `struct odb_source *` parameter and modifies call sites to pass the expected source (the main ODB for `receive-pack`, the repository’s primary source for `fetch-pack`). This ensures the lockfile path remains valid post-commit, fixing the cleanup issue. The new test in `t/t5547-push-quarantine.sh` verifies that ".keep" files are removed after a successful push, and Justin will enhance it in the next version to include the pre-commit verification Patrick suggested.

Key technical details: the patch touches `builtin/receive-pack.c`, `fetch-pack.c`, `pack-write.c`, `pack.h`, and the test suite. The new `index_pack_lockfile()` signature and explicit `struct odb_source *` tracking are central to the fix. The broader design question about ".keep" file placement remains open, but the immediate bug is resolved. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt.
