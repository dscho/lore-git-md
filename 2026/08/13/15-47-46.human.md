This is the third patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators mark repositories as trusted for lazy fetching. The series is a deliberate pivot from the earlier `GIT_NO_LAZY_FETCH=fromAccepted` proposal, replacing client-side negotiation with a server-controlled trust model.

This patch is a pure refactoring. It generalizes the `path_allowlist_apply()` helper—originally created for `safe.directory`—so it can be reused for the new `uploadpack.lazyFetchTrusted` configuration. The key change is adding a `bool allow_dot` argument: when true, the function accepts a single-dot path (`.`) as a shorthand for “the top level of the current repository,” matching the behavior of `safe.directory`; when false, it rejects non-absolute paths entirely. The function is also exported and documented in `setup.h`.

The patch is small (33 lines added, 4 removed), well-motivated, and uncontroversial. It touches only `setup.c` and `setup.h`, and the commit message clearly explains the purpose: preparing for the next patch, which will read the new configuration variable. No behavior changes are introduced; this is purely infrastructure for the feature. The patch is positioned as ready for integration once the broader series is reviewed.
