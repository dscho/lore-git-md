This is the v3 cover letter for a three-patch series that fixes race conditions in Git’s HTTP daemon test helpers. The series targets the test infrastructure (`t/` directory) and addresses a real, observed flake in `t5616.47` on macOS CI runners, where concurrent requests to the same CGI script caused HTTP 500 errors.

The core problem is that two CGI scripts (`apply-one-time-script.sh` and `http-429.sh`) use non-atomic shell operations (`test -f` followed by `rm` or `touch`) to manage shared state in `HTTPD_ROOT_PATH`. Because Apache serves requests concurrently, and a single Git operation can open multiple requests to the same endpoint (e.g., a partial fetch that lazily retrieves a promisor object while the first response is still being served), these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, causing an HTTP 500 error. The series replaces the non-atomic checks with atomic operations (`rm` without `-f` for the one-shot marker in `apply-one-time-script.sh`, `mkdir` for the first-request election in `http-429.sh`) to eliminate the race.

Key changes since v2 include simplifying the atomic operation in patch 1 (using `rm` without `-f` instead of `mv`), relocating the documentation from `t/README` to `t/lib-httpd.sh` to keep it specific to the HTTP daemon helpers, and rewording several helper comments and commit messages for clarity. The new test (`t5567-one-time-script.sh`) remains a strong addition, as it forces the race deterministically using FIFOs, confirming the fix works as intended. The series is now poised for integration, with all substantive and editorial feedback addressed. It looks well-crafted, thoroughly tested, and unlikely to be controversial.
