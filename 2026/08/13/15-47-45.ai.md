This is the second patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable for controlling lazy fetching. The patch extracts and generalizes the allowlist-checking logic from Git’s existing `safe.directory` machinery into a reusable `path_allowlist_apply()` helper, preparing the codebase for the new `uploadpack.lazyFetchTrusted` configuration.

The patch touches only `setup.c`, moving the core path-matching logic from `safe_directory_cb()` into the new `path_allowlist_apply()` function. The helper is designed to be generic: it takes a configuration key, value, target path, and an output pointer (`is_match`), and sets `*is_match` to 1 if the target path matches the allowlist entry. The logic handles wildcards (`*`), single-dot paths (`.`), and absolute paths, mirroring the behavior of `safe.directory` but without tying it to any specific configuration variable. The patch also simplifies the code by removing redundant checks and consolidating error handling.

This is a pure refactoring with no behavior changes. The `safe_directory_cb()` callback is updated to delegate to the new helper, and the patch is positioned as a preparatory step for the later introduction of `uploadpack.lazyFetchTrusted`. The commit message explicitly states that the helper will be reused in a subsequent commit to check whether a repository is part of an allowlist specified in a config variable.

The patch is uncontroversial and well-motivated. It improves code clarity and reusability, and the extracted helper will be directly reused in patch 4/5 to implement the `uploadpack.lazyFetchTrusted` configuration check. No review feedback has been posted yet, but the patch’s mechanical nature and clear separation of concerns make it a strong candidate for early integration, even if the broader series remains under discussion.
