This is a test fix series that is now ready to merge. The v2 iteration of Patrick Steinhardt’s two-patch series fixes a flaky test in `t/t7900-maintenance.sh` that has been causing intermittent CI failures (e.g., GitLab job #15762975482). The root cause is a race condition between the foreground test process and the auto-detaching background maintenance logic in `git maintenance`, which can leave a `maintenance.lock` file that prevents subsequent maintenance tasks from running.

Patch 1 refactors three tests to use throwaway repositories instead of the default trash directory, making them more self-contained and isolating environment changes. The commit message now clearly explains why `test_config` was replaced with `git config set`: `test_config` relies on `test_when_finished` cleanup, which doesn’t work in subshells, and the throwaway repository’s `rm -rf` cleanup makes per-config cleanup unnecessary. Patch 2 fixes the flake by restoring the default test suite behavior (auto-detach disabled) and only enabling auto-detach in the specific tests that require it, eliminating the race condition.

The series touches only `t/t7900-maintenance.sh` and makes no user-visible behavior changes. Both patches received substantive review from Karthik Nayak, who confirmed the approach and suggested minor wording improvements that were incorporated. The series is uncontroversial, narrowly scoped, and addresses a real CI reliability issue. Karthik’s final reply explicitly states the v2 iteration looks good, signaling the series is ready for integration.
