This thread is about a small but systematic test coverage patch for `git symbolic-ref`. Nikolaus Schuetz added tests to verify the exit codes and output of `git symbolic-ref` when querying a non-symbolic ref, both with and without the `--quiet` flag. The patch was initially straightforward, but Patrick Steinhardt’s review surfaced a design question: why does `git symbolic-ref` return exit code 128 in the non-quiet case but 1 with `--quiet`?

Nikolaus clarified that this behavior is intentional and consistent with other Git commands like `git rev-parse --verify --quiet`. The non-quiet path uses `die()`, which always exits 128, while `--quiet` cannot use `die()` (as it would print output) and thus returns 1. The patch now also verifies that stdout is empty in both cases, addressing Patrick’s suggestion. No objections to the patch itself have been raised, and it remains under review.

The discussion has settled the "why" behind the exit code behavior, but the thread is still open on whether the current design is a quirk worth revisiting. If the community decides the behavior should be aligned, a follow-up patch may be proposed. For now, the patch is a clean addition to test coverage, touching only `t/t1401-symbolic-ref.sh` and introducing no new functionality or on-disk changes.
