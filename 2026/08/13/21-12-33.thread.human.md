This thread is about adding test coverage for `git symbolic-ref`'s behavior when querying a non-symbolic ref, focusing on exit codes and output with and without the `--quiet` flag. The patch, now in its second version by Nikolaus Schuetz, documents the current behavior—exit code 128 without `--quiet`, exit code 1 with `--quiet`, and empty stdout in both cases—but the discussion has shifted toward treating this design as unintentional.

Key participants include Junio C Hamano, who agrees the differing exit codes likely reflect an oversight and prefers avoiding tests for the exact codes to prevent overspecifying behavior, and Patrick Steinhardt, who initially called the behavior "weird" and now leans toward aligning the exit codes. Nikolaus has clarified the motivation (filling a test coverage gap) and incorporated feedback, but the thread has converged on revisiting the design. Phillip Wood has now introduced a new perspective, suggesting the exit code discrepancy might be intentional to allow scripts to distinguish between invalid options (exit 128) and non-existent refs (exit 1), drawing parallels with `git rev-parse` and `git show-ref`. This challenges the emerging consensus and reframes the discussion around whether the current behavior serves a practical purpose.

The patch itself touches only `t/t1401-symbolic-ref.sh`, adding three tests to verify exit codes and stdout emptiness. No new functionality or on-disk changes are introduced. The remaining open question is whether to drop the exit code tests, align the exit codes (e.g., by changing the quiet path to use `die(NULL)`), or preserve the current behavior as intentional. No follow-up patch has been proposed yet, but the discussion is now more nuanced with Phillip’s input.
