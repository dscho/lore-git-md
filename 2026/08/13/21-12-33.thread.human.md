This thread is about a small but important test-coverage patch for `git symbolic-ref`. Nikolaus Schuetz has sent a second version of a standalone patch that adds tests for the command's exit codes and output when querying a non-symbolic ref, both with and without the `--quiet` (`-q`) flag. The patch now includes three new tests in `t/t1401-symbolic-ref.sh`, verifying that `git symbolic-ref` exits with code 128 and prints an error for non-symbolic refs, while `--quiet` suppresses the error and exits with code 1—both cases also confirm stdout is empty, addressing a review suggestion from Patrick Steinhardt.

The discussion has clarified the technical rationale behind the differing exit codes (128 vs. 1 with `--quiet`), which aligns with other Git commands like `git rev-parse --verify --quiet` and the behavior of `die()`. However, no consensus has emerged on whether this design is intentional or a quirk worth revisiting. Patrick initially called the behavior "weird" and questioned whether `--quiet` should affect exit status at all, but the patch itself has no objections and is likely to be merged as-is. The author has expanded the commit message to explain the motivation—existing tests already rely on this behavior, but none explicitly document it—and the patch is now ready for review. If the current behavior is later deemed unintentional, a follow-up patch may be proposed to align the exit codes.
