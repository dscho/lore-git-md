This thread is about a patch from Nikolaus Schuetz that adds test coverage for `git symbolic-ref`'s exit codes and output when querying non-symbolic refs. The patch, now in its second version, documents the current behavior: exit code 128 without `--quiet`, exit code 1 with `--quiet`, and empty stdout in both cases. The goal is to fill a gap in test coverage, though the patch leaves open whether this behavior is intentional or a quirk worth revisiting.

The discussion has centered on the design rationale behind the differing exit codes. Patrick Steinhardt, the primary reviewer, has consistently questioned whether the behavior is deliberate, calling it "weird" and suggesting that `--quiet` should only suppress output, not alter exit status. In the latest email, he doubles down on this skepticism, arguing that the current behavior likely reflects an oversight rather than a design choice. He proposes either avoiding tests for the exact exit codes or aligning them by changing the quiet path to use `die(NULL)` instead of `exit(1)`, which would standardize the exit code to 128 in both cases. Nikolaus, the author, has defended the current behavior as consistent with other Git commands but remains open to revisiting it if consensus emerges.

The patch itself is uncontroversial in terms of implementation—it touches only the test script `t/t1401-symbolic-ref.sh` and adds three new tests—but the underlying design question remains unresolved. No other participants have weighed in, and the patch is still under review. If the exit code behavior is deemed unintentional, a follow-up patch may be proposed to align the codes. For now, the thread is stuck on whether to codify the current behavior or change it.
