This thread is about adding test coverage for `git symbolic-ref`'s exit codes and output when querying a non-symbolic ref, with an initially proposed but now deferred documentation update. Nikolaus Schuetz sent a third version of the patch, which focuses on the test additions after Junio C Hamano objected to documenting what he considers "wrong behavior" in the man page.

The patch itself—adding tests to `t/t1401-symbolic-ref.sh`—is uncontroversial and ready for merging. It verifies that `git symbolic-ref` exits with 128 (without `--quiet`) or 1 (with `--quiet`) when given a non-symbolic ref, and that stdout is empty in both cases. The tests use `test_must_fail` instead of `test_expect_code` to avoid over-specifying exit codes, addressing earlier feedback from Junio.

The thread has explored whether the differing exit codes are intentional or an oversight. Junio and Patrick Steinhardt view them as likely unintentional, while Phillip Wood argues they may serve a useful purpose for script-level error differentiation. The documentation update, initially proposed as a compromise to avoid freezing behavior in tests, is now deferred. Junio objects to it on the grounds that it would "cast wrong behavior into stone," and no alternative wording has been proposed. Patrick’s latest email reinforces the discrepancy between the documented (exit code 1) and actual (128 without `--quiet`) behavior but accepts the patch as-is, leaving the design question unresolved.

The next steps are unclear. Nikolaus may need to revise the man page text to avoid normative language, propose a behavioral fix, or drop the documentation update entirely. The test additions are ready for integration, while the man page update may proceed as a separate follow-up.
