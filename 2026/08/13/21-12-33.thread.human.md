This thread began with Nikolaus Schuetz’s patch to add test coverage for `git symbolic-ref`’s exit codes and output when querying a non-symbolic ref. The patch documents the current behavior—exit code 128 without `--quiet`, exit code 1 with `--quiet`, and empty stdout in both cases—but the thread quickly focused on whether this design was intentional or an oversight. Junio C Hamano and Patrick Steinhardt both leaned toward treating it as an oversight, while Phillip Wood argued the discrepancy might be useful for scripts to distinguish between invalid options (exit 128) and non-existent refs (exit 1).

The discussion has now settled on a practical compromise: the tests will remain as-is to document the status quo, and the documentation (`git-symbolic-ref.adoc`) will be updated to accurately describe the current behavior. This avoids the need to align the exit codes or drop the tests, sidestepping the design debate while still addressing the original goal of filling a test coverage gap. Nikolaus has agreed to prepare a v3 with the updated man page, which should resolve the thread without altering any on-disk formats or user-visible behavior. The patch touches only tests and documentation, making it low-risk, and preserves the exit codes that existing scripts might rely on.
