This is the second patch in Junio C Hamano’s three-patch v3 series fixing Bash completion for `git checkout`. It implements the core behavior change: when no revision references match the input (or when `--` is present), the completion now offers only tracked paths—those already in the index—rather than falling back to untracked files in the current directory. This aligns `git checkout` completion with the command’s purpose of operating on repository files, not arbitrary filesystem paths.

The patch touches `contrib/completion/git-completion.bash`, adding a simple check in `_git_checkout()`: if `__git_complete_refs()` yields no candidates, it calls `__git_complete_index_file ""` to populate `COMPREPLY` with tracked paths. The empty string argument ensures untracked files are excluded. The change is minimal but effective, addressing the long-standing usability gap where completion previously suggested untracked files inconsistently, especially confusing when using `git -C <dir>`.

Test coverage is thorough. The patch adds two new tests in `t/t9902-completion.sh`. The first verifies that `git checkout f` (where no refs match "f") completes only tracked paths (`file1`, `file2`) and ignores untracked files. The second test confirms the fix works with `git -C <path> checkout`, completing tracked paths in the specified repository rather than the current directory. Both tests cover edge cases like missing files (`lostfile`) and ensure the behavior is consistent with or without `--`.

This patch is well-motivated and uncontroversial. The commit message clearly explains the problem (fallback to untracked files in `$PWD` is wrong when using `-C`) and the solution (prioritize tracked paths). The implementation is clean, and the test coverage leaves little room for regressions. The only remaining piece is the fallback to untracked paths when no tracked paths match, which is handled in patch 3/3—this patch focuses solely on the core fix.
