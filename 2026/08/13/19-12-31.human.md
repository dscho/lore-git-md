This is the third iteration of Junio C Hamano’s small but well-scoped series fixing Bash completion for `git checkout` (with or without `-C <dir>`). The series now consists of three patches: a no-op refactoring (1/3), the core fix that restricts completion to tracked paths (2/3), and a pragmatic fallback to untracked paths when no tracked paths match (3/3). The changes are confined to `contrib/completion/git-completion.bash` and the test suite (`t/t9902-completion.sh`), with thorough test coverage verifying edge cases.

The motivation is clear and uncontroversial: `git checkout` operates on files already in the repository (tracked paths), so completing untracked files is inconsistent and confusing. The previous behavior would fall back to untracked paths when no revision matched the input, which this series corrects. Patch 2/3 enforces tracked-path-only completion using `__git_complete_index_file ""` (equivalent to `--cached`), while patch 3/3 adds a fallback to untracked paths via `__git_complete_index_file "--others --directory"`—a last-resort measure that ensures completion never fails silently. Junio notes the fallback’s utility for `git checkout` is limited, but it serves as a pragmatic safeguard.

The series builds on the earlier `git diff` completion fix, reusing its machinery and rebasing onto the `complete-diff` topic for better test organization. Elijah Newren’s review of v2 prompted a minor but meaningful tweak to patch 3/3: adding `--directory` to the fallback call for consistency with the `git diff` series and performance benefits. Junio accepted the suggestion, and the series is now technically complete with no open questions. The refactoring in patch 1/3 (new in v2) reorganizes `_git_checkout()` to avoid an early return when `--` is detected, making the logic clearer without altering behavior.

Test coverage is a standout feature: eight new tests in `t/t9902-completion.sh` verify the refactoring, the tracked-path-only logic, the fallback behavior, and edge cases like missing files (`lostfile`). The tests cover both the happy path and scenarios with `--` and `-C <dir>`, ensuring the fix works consistently across contexts. The series is uncontroversial, well-explained, and ready for integration. It’s a textbook example of incremental improvement—small, focused, and thoroughly tested.
