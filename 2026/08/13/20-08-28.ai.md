This is the fourth patch in the v5 series introducing `git repack --drop-filtered` for partial clones. It implements the core enumeration logic that identifies which promisor blobs exceed the user-specified size threshold and should be dropped.

The patch adds `enumerate_promisor_blobs()` in `repack-filtered.c`, which walks all promisor objects (using `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`) and collects blobs into an oidset. It then applies the filter (currently only `blob:limit`) to that set using the new `list_objects_filter__filter_oidset()` helper from patch 2/6, producing the final `to_drop` set. In `--dry-run` mode, the function prints the OIDs of candidate blobs to stdout. The implementation avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query, ensuring enumeration never triggers network activity.

The patch updates `builtin/repack.c` to call `enumerate_promisor_blobs()` when `--drop-filtered` is specified, storing the results in a new `drop_oids` oidset. In `--dry-run` mode, it iterates over the set and prints each OID. The test script (`t/t7706-repack-drop-filtered.sh`) is expanded to cover enumeration, `--dry-run` output, and the exclusion of locally created blobs (which must never be dropped). The tests verify that only promisor blobs exceeding the threshold are listed and that locally created objects are untouched.

This patch is well-scoped and technically sound, addressing the core challenge of identifying drop candidates without relying on the filtered pack machinery (which cannot see promisor objects in partial clones). The use of `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` is correct and aligns with the series' safety guarantees. The test coverage is thorough, including edge cases like locally created blobs. No new blocking issues are introduced; the patch builds cleanly on the earlier ones and is ready for maintainer review.
