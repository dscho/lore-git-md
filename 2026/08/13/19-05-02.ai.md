This is the first patch in Vincent Mailhol’s four-part v3 series adding Bash completion for `git history`. It introduces the core completion logic for the command’s subcommands (`drop`, `fixup`, `reword`, `split`) and their options, along with revision completion for the first positional argument.

The patch adds a new `_git_history()` function in `contrib/completion/git-completion.bash` that uses Git’s parse-options helpers to complete subcommands and their options. The key technical improvement since v2 is the `__git_history_has_revision()` helper, which simplifies revision detection by ignoring `<option> <value>` pairs—eliminating hard-coded option names and making the logic more maintainable. Tests in `t/t9902-completion.sh` verify that options are not completed before a subcommand, that revision completion stops after the first required argument, and that `--` argument termination is respected.

This patch is well-structured and addresses prior feedback from Patrick Steinhardt and D. Ben Knoble. The implementation is clean, and the test coverage is thorough. The only remaining work is a trivial rebase to include the `squash` subcommand once it graduates from `seen`, but this does not affect the current patch’s readiness. The series looks solid and ready for integration.
