This is the second patch in a three-patch bugfix series targeting test infrastructure. It makes the `http-429.sh` CGI helper script concurrency-safe by replacing a non-atomic "check-and-set" (`test -f` followed by `touch`) with a single atomic `mkdir` operation. The change prevents a latent race condition where concurrent requests could both pass the `test -f` check, causing both to incorrectly return 429 (Too Many Requests) instead of forwarding one to `git-http-backend`.

The patch also fixes a correctness issue in the "permanent" mode (which returns 429 to every request) by skipping the `mkdir` entirely, ensuring no state marker is left behind. The original implementation used a racy "create-then-remove" pattern, which could leave a marker visible to a concurrent request, causing it to be wrongly forwarded. The commit message explains the problem, the atomic idiom (`mkdir`), and the reasoning behind the "permanent" mode fix in detail.

The diff touches only `t/lib-httpd/http-429.sh`, replacing the state file logic with a state directory and adding explanatory comments. The change is minimal and focused, with no regression test included because the race cannot be forced deterministically (the check and set are adjacent commands with no external synchronization point). The patch is part of a well-reviewed series that addresses a real, observed flake in `t5616.47` on macOS CI runners, and all substantive feedback from prior iterations has been incorporated. It is ready for integration into `next`.
