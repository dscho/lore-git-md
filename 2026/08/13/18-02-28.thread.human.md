This thread is a bug report from Jos van den Oever about how Git handles file modification times (mtime) during `--autostash` operations. When using `git pull`, `git merge`, or `git rebase` with `--autostash`, files restored from the stash have their mtime incorrectly set to the current time—even if their content didn’t change. This breaks build systems and automated tools that rely on mtime to track file changes, leading to unnecessary rebuilds or incorrect assumptions about when files were last modified.

The report frames this as a behavioral inconsistency: Git normally preserves mtime when writing files, but the `--autostash` workflow fails to do so. Jos suggests Git should track and restore the original mtime of dirty files during these operations. There’s no patch yet—this is a feature request or bug report raising a new issue. The thread is currently just the initial report, so no discussion or decisions have been made. If you’re working on build systems or tools that depend on mtime, this is worth watching.
