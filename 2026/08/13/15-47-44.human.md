This is the first patch in Christian Couder’s five-part series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration to control lazy fetching. The patch is a pure refactoring of the promisor-remote subsystem, extracting the lazy-fetch logic into a new `lazy_fetch_objects()` helper.

The change consolidates the `GIT_NO_LAZY_FETCH` environment variable check so it runs once up front instead of once per promisor remote, and skips `promisor_remote_init()` when lazy fetching is disabled (since nothing downstream needs it in that case). It also splits `promisor_remote_get_direct()` into two distinct phases: deciding which remotes to try (now in `lazy_fetch_objects()`) and validating that unfetched objects are promisor objects. The `try_promisor_remotes()` function is converted from returning an `int` to a `bool` for clarity, since it simply indicates whether all objects were fetched.

The commit message is clear and the diff is clean, with no intended behavior change. This refactoring is uncontroversial and lays the groundwork for the later patches that introduce the new configuration variable. It’s a small, focused improvement to the promisor-remote code’s efficiency and readability.
