This is a **bugfix proposal** for the long-standing discrepancy between `git config --global`'s documented and actual behavior. Delilah Ashley Wu resurfaces a year-old patch series that would make `--global` read *both* `~/.gitconfig` and the XDG config file (`~/.config/git/config`), aligning the code with the current documentation. The series has been dormant due to lack of community feedback, but Delilah now signals intent to reroll it soon.

The patch targets the configuration subsystem (`config.c`), specifically the `git_global_config()` function, which currently reads only one file (prioritizing `~/.gitconfig` if readable). The proposed change would make `--global` behave like `--get`, which already reads both files, resolving the inconsistency that has confused users and broken tools relying on the documented behavior. Delilah’s earlier work addressed review feedback, and the reroll is expected to be ready for broader discussion.

This contribution looks serious: the commit history shows engagement with prior feedback, and the author is affiliated with Microsoft (where "side project time" is explicitly allocated for upstream work). The patch’s backward compatibility is favorable—no existing configurations would break, and users would simply gain access to settings in the XDG file. However, the maintainer (Junio C Hamano) previously leaned toward fixing the *documentation* instead of the code, so the reroll may reignite debate over whether to align code with docs or vice versa.

The thread remains unresolved on the fix direction, but Delilah’s update adds momentum to the "fix the code" camp. If the series lands, it would likely be backported to maintenance releases given the issue’s age and user impact. Busy readers should watch for the reroll—this could be the turning point for a years-old inconsistency.
