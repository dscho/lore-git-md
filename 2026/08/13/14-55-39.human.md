This is the first patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t`. The series is a platform-compatibility fix targeting 64-bit Windows, where `unsigned long` is 32-bit and can truncate large object sizes.

This patch widens the `memsize` and `src_size` fields in the private `struct delta_index` (used internally by `diff-delta.c`) from `unsigned long` to `size_t`. It also updates the return type of `sizeof_delta_index()` to match. The change is purely internal and has no runtime effect yet—callers still truncate values to `unsigned long`—but it prepares the ground for later patches that will widen the public API. The commit message explains that this split keeps the API-change commit focused and avoids mixing mechanical widening with behavioral updates.

The patch is uncontroversial and mechanically correct. It touches only two files (`delta.h` and `diff-delta.c`) and makes no behavior changes. The series as a whole is queued in `next` and addresses all prior review feedback, including Junio C Hamano’s concerns about truncation risks in v2. This first patch is a straightforward refactoring that sets the stage for the rest of the series.
