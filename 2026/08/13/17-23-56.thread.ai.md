Thread identity: A four-patch series from Kristoffer Haugsbakk adding `--abbrev`, `--color`, and `--date` formatting options to the `git format-rev` command (introduced in Git 2.45). The series is preparing for v2 after v1 review feedback.

Core problem or goal: Extend `git format-rev` with three new formatting options (`--abbrev`, `--color`, `--date`) to bring it closer to parity with `git log`'s formatting flexibility. The preparatory patches (1–3) refactor option handling and documentation, while the final patch (4/4) implements the new options by reusing existing `git log` logic (`rev_info` struct and `pretty.c` date formatting).

Current status: Under review (v1 feedback addressed; v2 pending). Junio C Hamano reviewed patches 2/4 and 4/4, suggesting minor mechanical improvements (designated initializers in patch 2/4 and defensive code reordering in patch 4/4). Both suggestions have been accepted by the author. The series remains uncontroversial and is not queued in any integration branch.

Key technical details:
- Files touched: `builtin/name-rev.c` (main implementation), `Documentation/git-format-rev.adoc`, `Documentation/rev-list-option-date-alternatives.adoc`, test coverage in `t/t6120-describe.sh`.
- New CLI options: `--abbrev`, `--color`, `--date` (with same alternatives as `git log`).
- Subsystems reused: `rev_info` struct, `pretty.c` date formatting.
- On-disk format: No changes.
- Synopsis simplification: The command synopsis now highlights the two mandatory options (`--stdin-mode` and `--format`) while moving the rest into `[<options>]`.
- Test coverage: Added in `t/t6120-describe.sh`, verifying the new options behave identically to their `git log` counterparts, including error handling for invalid values (e.g., `--color=not-valid`).
- Patch 1/4: Cosmetic documentation cleanup in `builtin/name-rev.c`, converting option descriptions from mixed case ("Use NUL...") to lowercase ("use NUL...") for style consistency. Affects only help text; no functional changes.
- Patch 2/4: Refactoring introducing `struct format_rev_data` to group option variables, inlining the existing `format_nul_data` struct, and renaming `stdin_mode_arg` to `stdin_mode` to avoid shadowing. Junio C Hamano reviewed this patch, suggesting and approving a mechanical improvement: replacing the positional initializer with a designated initializer (C99) for clarity and maintainability. The author has accepted the suggestion.
- Patch 3/4: Pure documentation refactoring: extracts the 55-line block describing `--date` alternatives from `rev-list-options.adoc` into a new standalone file (`rev-list-option-date-alternatives.adoc`) so the same text can be included by both `git-rev-list` and `git-format-rev`. No user-visible behavior changes.
- Patch 4/4: Implements the three new options by reusing existing `git log` logic. Junio C Hamano identified a **defensive programming issue** in the `date_cb()` callback: the `BUG_ON_OPT_NEG(unset)` assertion was placed *after* dereferencing `option->value`, which could lead to a segfault if the callback were ever invoked with `unset==1` (e.g., via `--no-date`). While the current code is safe due to `PARSE_OPT_NONEG`, the assertion’s placement undermines its purpose. Junio suggested reordering the code to ensure the assertion triggers before any dereference. The author has accepted the suggestion; the fix is trivial (reordering two lines).
