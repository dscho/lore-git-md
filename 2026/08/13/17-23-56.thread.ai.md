Thread identity: A four-patch series from Kristoffer Haugsbakk adding `--abbrev`, `--color`, and `--date` formatting options to the `git format-rev` command (introduced in Git 2.45). The series is preparing for v2 after v1 review feedback.

Core problem or goal: Extend `git format-rev` with three new formatting options (`--abbrev`, `--color`, `--date`) to bring it closer to parity with `git log`'s formatting flexibility. The preparatory patches (1–3) refactor option handling and documentation, while the final patch (4/4) implements the new options by reusing existing `git log` logic (`rev_info` struct and `pretty.c` date formatting).

Current status: Under review (v1 feedback addressed; v2 pending). Junio C Hamano reviewed patches 2/4 and 4/4, suggesting minor mechanical improvements (designated initializers in patch 2/4 and defensive code reordering in patch 4/4). The author has accepted both suggestions, including a fix to reorder the `BUG_ON_OPT_NEG(unset)` assertion in the `date_cb()` and `format_nul_cb()` callbacks to ensure it triggers before any dereference of `option->value`. The series remains uncontroversial and is not queued in any integration branch.

Key technical details:
- Files touched: `builtin/name-rev.c` (main implementation), `Documentation/git-format-rev.adoc`, `Documentation/rev-list-option-date-alternatives.adoc`, test coverage in `t/t6120-describe.sh`.

- Patch 2/4: Refactoring introducing `struct format_rev_data` to group option variables, inlining the existing `format_nul_data` struct, and renaming `stdin_mode_arg` to `stdin_mode` to avoid shadowing. Junio C Hamano reviewed this patch, suggesting and approving a mechanical improvement: replacing the positional initializer with a designated initializer (C99) for clarity and maintainability. No user-visible behavior changes.
- Patch 4/4: Implements the three new options by reusing existing `git log` logic. Junio C Hamano identified and the author accepted a defensive programming fix: reordering the `BUG_ON_OPT_NEG(unset)` assertion in `date_cb()` to trigger before any dereference of `option->value`, preventing potential segfaults if the callback were invoked with `unset==1` (e.g., via `--no-date`).
