This is the third patch in Johannes Schindelin’s 13-part series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t`. The series is a platform-compatibility fix targeting 64-bit Windows, where `unsigned long` is 33-bit and can silently truncate large object sizes.

This patch widens the delta-cache accounting variables (`delta_cache_size` and `max_delta_cache_size`) and the `delta_cacheable()` helper function to `size_t`. The change is internally consistent: the accounting variables already interact with `size_t` sources (like `DELTA_SIZE()`), and the helper’s caller in `try_delta()` still passes an `unsigned long` value, which promotes safely. The patch also introduces `git_config_size_t()` and `git_parse_size_t()` helpers to handle the now-wider `max_delta_cache_size` configuration variable, ensuring type safety throughout the code path.

The motivation is clear: preventing integer truncation in delta-cache accounting, which could lead to silent misbehavior with large packs. The patch is narrowly scoped and mechanical, touching only the accounting logic in `builtin/pack-objects.c` and adding the necessary parsing helpers in `config.c` and `parse.c`. No behavior changes or new tests are introduced, as the fix is purely internal.

This patch is a prerequisite for later work in the series, which will remove `cast_size_t_to_ulong()` shims once the rest of the delta machinery is widened. The series as a whole is uncontroversial, well-reviewed, and now queued in `next` for integration testing. If you work with large repositories on Windows, this is worth tracking.
