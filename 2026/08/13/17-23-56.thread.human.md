This thread is about Kristoffer Haugsbakk’s four-patch series adding `--abbrev`, `--color`, and `--date` formatting options to `git format-rev`, bringing it closer to `git log`’s flexibility. The series is now preparing its second version after addressing feedback on the first.

The first three patches are mostly preparatory: a cosmetic documentation cleanup, a refactoring to group option variables, and a documentation move to share `--date` alternatives between `git-rev-list` and `git-format-rev`. Junio C Hamano reviewed the refactoring patch (2/4) and the final implementation (4/4), suggesting minor mechanical improvements—designated initializers and defensive code reordering—which the author accepted. The only remaining technical loose end is a memory leak in the `--date` callback, where `parse_date_format()` allocates a custom format string that isn’t released. The author spotted this while reviewing the documentation and will fix it in the next revision.

The series is uncontroversial and still under review, with no objections raised so far. The new options reuse existing `git log` logic (`rev_info` and `pretty.c`), and the tests verify they behave identically, including error handling. The synopsis was also tweaked to highlight mandatory options (`--stdin-mode` and `--format`). No merge status updates have been reported, and the series isn’t queued in any integration branch yet.
