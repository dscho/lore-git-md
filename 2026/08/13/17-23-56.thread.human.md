This thread is about Kristoffer Haugsbakk’s four-patch series adding `--abbrev`, `--color`, and `--date` formatting options to `git format-rev`, a command introduced in Git 2.45. The goal is to bring `format-rev` closer to `git log`’s formatting flexibility. The first three patches are preparatory: they clean up documentation, refactor option handling, and extract shared `--date` alternatives into a reusable file. The fourth patch, just posted, implements the new options by reusing existing `git log` logic, simplifying the command’s synopsis, and adding test coverage.

The series is under initial review, with no objections raised yet. The implementation is straightforward, reusing `rev_info` and `pretty.c` date formatting to avoid new logic, and the tests verify parity with `git log`. The only open question is whether `--date` should support the same alternatives as `git log`—this hasn’t been contested yet, but it might spark discussion. The series isn’t queued in any integration branch, and no prior context suggests these options were explicitly requested. So far, the preparatory patches (1–3) have drawn no feedback, but they’re uncontroversial refactorings and likely to be accepted as-is.
