This thread is about adding `--abbrev`, `--color`, and `--date` formatting options to `git format-rev` (introduced in Git 2.45) to bring it closer to `git log`'s flexibility. Kristoffer Haugsbakk sent a four-patch series, now preparing a v2 after addressing feedback on the first version.

The series refactors option handling and documentation in the first three patches, then implements the new options in the fourth by reusing `git log`'s existing logic. Junio C Hamano reviewed patches 2/4 and 4/4, suggesting minor mechanical improvements—using designated initializers in patch 2/4 and reordering a defensive assertion in patch 4/4 to ensure it triggers before dereferencing variables. The author has accepted both suggestions, including a parallel fix for the same issue in an existing callback. The changes are uncontroversial and the series remains under review, with no objections raised so far.

The new options (`--abbrev`, `--color`, `--date`) reuse `rev_info` and `pretty.c` date formatting, with test coverage added to verify they behave identically to their `git log` counterparts. The synopsis was also simplified to highlight mandatory options. No on-disk format changes are involved. The only remaining loose end is whether `--date` should support the same alternatives as `git log`, but no discussion has emerged yet. The series is not yet queued in any integration branch.
