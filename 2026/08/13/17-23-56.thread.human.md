This thread is about extending `git format-rev` (introduced in Git 2.45) with `--abbrev`, `--color`, and `--date` formatting options to match `git log`'s flexibility. Kristoffer Haugsbakk sent a four-patch series (v1) to implement these changes, with the first three patches refactoring option handling and documentation, and the fourth adding the new options by reusing existing `git log` logic.

The series is under initial review. Junio C Hamano reviewed patch 2/4, which groups option variables into a `struct format_rev_data`, and suggested a minor improvement: using a designated initializer (C99) for clarity. Kristoffer accepted the suggestion immediately, calling it "excellent," and the patch remains uncontroversial. No other reviews have been posted yet, and the series isn't queued in any integration branch. The UI design choice for `--date` alternatives hasn't attracted discussion yet, but this may change as more reviewers weigh in.

The implementation touches `builtin/name-rev.c`, documentation, and tests, reusing `rev_info` and `pretty.c` date formatting logic. No on-disk format changes are involved. The next step is a v2 of the series incorporating Junio's tweak, with the rest of the patches (1, 3, and 4) still awaiting feedback. The series is straightforward and appears technically sound, but broader review could surface additional considerations.
