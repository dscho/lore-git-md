This thread is about Kristoffer Haugsbakk’s five-patch series adding `--abbrev`, `--color`, and `--date` formatting options to `git format-rev` (introduced in Git 2.45). The goal is to bring `git format-rev` closer to `git log`’s formatting flexibility by reusing existing `rev_info` and `pretty.c` logic.

The series is now at v2, with all v1 feedback addressed. Junio C Hamano’s review suggestions—designated initializers, defensive assertion placement, and a memory leak fix in the `--date` callback—have been incorporated. A new refactoring patch (2/5) consolidates defensive assertions at the top of option callbacks for consistency. The series remains uncontroversial and is under review, with no objections raised so far.

The latest email covers patch 4/5, a mechanical documentation refactoring that extracts the `--date` alternatives block from `Documentation/rev-list-options.adoc` into a standalone file for reuse by both `git-rev-list` and `git format-rev`. This patch is a prerequisite for the final patch (5/5), which implements the `--date` option. No functional changes are introduced, and the patch is expected to be accepted as-is. The series is not yet queued in any integration branch.
