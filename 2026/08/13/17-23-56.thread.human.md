This thread is about Kristoffer Haugsbakk’s five-patch series adding `--abbrev`, `--color`, and `--date` formatting options to the experimental `git format-rev` command, bringing it closer to `git log`’s flexibility. The series is now at v2, with all v1 review feedback incorporated—including a memory leak fix, defensive code improvements, and a new refactoring patch for assertion placement.

The core work is in patch 5/5, which implements the new options by reusing `git log`’s existing `rev_info` struct and `pretty.c` date formatting logic. The patch also simplifies the command synopsis to highlight mandatory options (`--stdin-mode` and `--format`) and reuses a shared include file for `--date` documentation. Tests now verify the new options behave identically to `git log`, including error handling and custom date formats. Earlier patches in the series refactor option handling, documentation, and defensive code placement, with Junio C Hamano’s v1 review suggestions fully addressed.

The series remains uncontroversial and is under review, with no objections raised so far. It’s not yet queued in any integration branch, but the changes are straightforward and align with Git’s existing patterns. The only open question is whether the `--date` alternatives (shared with `git log`) are the right fit for `git format-rev`, though no concerns have been voiced yet.
