This thread is about a four-patch series from Kristoffer Haugsbakk that adds `--abbrev`, `--color`, and `--date` formatting options to the `git format-rev` command, bringing it closer to `git log`'s flexibility. The series is currently at version v1 and under initial review.

The first three patches are preparatory: they clean up documentation, refactor option handling, and extract shared documentation for `--date` alternatives. These changes are uncontroversial and likely to be accepted as-is. The fourth patch implements the new options by reusing existing `git log` logic, touching `builtin/name-rev.c` and adding test coverage in `t/t6120-describe.sh`.

Junio C Hamano recently reviewed the second patch, which refactors option variables into a new `struct format_rev_data`. His feedback was narrowly focused on improving maintainability by using C99 designated initializers, a minor and mechanical suggestion that the author is likely to adopt. The rest of the patch was approved, and no objections to the series' design or goals have been raised yet. The main open question is whether the `--date` option should support the same alternatives as `git log`, but this hasn't attracted discussion so far. The series is not yet queued in any integration branch.
