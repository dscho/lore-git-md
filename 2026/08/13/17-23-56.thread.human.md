This thread is about Kristoffer Haugsbakk’s four-patch series adding `--abbrev`, `--color`, and `--date` formatting options to the `git format-rev` command, bringing it closer to `git log`’s flexibility. The series is currently at version 1, with a second version expected soon.

The first three patches are preparatory: patch 1 cleans up documentation style, patch 2 refactors option handling (with Junio C Hamano suggesting and approving a minor improvement to use designated initializers), and patch 3 extracts shared `--date` documentation into a standalone file. The fourth patch implements the new options by reusing existing `git log` logic, but Junio recently identified a latent correctness issue in the `date_cb()` callback—an assertion meant to guard against future misuse is placed after a potentially unsafe dereference. This is not a bug in the current code (since `PARSE_OPT_NONEG` prevents the problematic case), but it’s a defensive programming concern that will be fixed in the next revision.

No other objections have been raised, and the series remains uncontroversial. The new options are tested in `t/t6120-describe.sh` and behave identically to their `git log` counterparts, including error handling. The series is still under initial review, with no integration branch queuing yet. The only open question is whether the `--date` option’s alternatives will attract further discussion, but so far there’s been no pushback.
