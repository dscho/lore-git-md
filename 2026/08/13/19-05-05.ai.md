This is the fourth and final patch in Vincent Mailhol’s v3 series adding Bash completion for `git history`. It implements pathspec completion for the `split` subcommand, allowing users to tab-complete tracked file paths after specifying the required revision argument.

The patch adds a small but crucial piece of functionality: when the user types `git history split <revision> <TAB>`, the completion script now offers tracked files as candidates, including after an explicit `--` argument. This matches the behavior of other Git commands that accept pathspecs (e.g., `git add`, `git checkout`). The implementation is minimal and idiomatic, using the existing `__git_complete_index_file` helper with the `--cached` option to avoid disk I/O during completion.

Test coverage in `t/t9902-completion.sh` verifies that pathspec completion works both before and after `--`, and that it correctly ignores options (e.g., `--update-refs`) when they appear after the revision. The tests also confirm that the pathspec candidates are drawn from the index, not the working tree.
