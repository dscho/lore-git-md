This is a **substantive follow-up in the packfile performance regression thread**, resolving the last open design question and clearing the path for Johannes Schindelin’s fast-path optimization patch to proceed.

Patrick Steinhardt accepts Johannes’s proposed rename of the `is_new` parameter to `skip_dup_check`, ending the naming debate. The new name better reflects the parameter’s behavior—skipping duplicate checks for packfiles the *caller* guarantees are new—without implying that the function itself enforces uniqueness. This is a minor but meaningful improvement that removes ambiguity and makes the caller’s responsibility explicit.

The thread’s central design tension—whether to land Johannes’s targeted fast-path fix or Patrick’s more comprehensive hashmap refactoring—is now resolved in favor of the fast-path. Patrick concedes that while his hashmap approach could speed up packfile reordering (a common operation in large repositories), it would not fully supersede the fast-path’s advantage: skipping the search entirely is faster than even an O(1) hashmap lookup. He signals intent to pursue the hashmap refactoring independently, framing it as a longer-term improvement that could complement or eventually replace the fast-path. For now, the project will proceed with Johannes’s patch as the immediate fix for the `git rev-parse --short HEAD` slowdown in Microsoft Git Scalar environments.

The patch’s scope and technical details remain unchanged: it targets the quadratic-time regression in `packfile_store_add_pack()` (introduced in commit `589127caa730`, October 2025) by adding a fast path that skips duplicate checks when the packfile is known to be new.
