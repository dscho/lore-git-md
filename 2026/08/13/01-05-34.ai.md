This is the first patch in a three-patch bugfix series targeting test infrastructure. It fixes a race condition in `t/lib-httpd/apply-one-time-script.sh`, a CGI helper used in HTTP daemon tests. The race occurs when Apache serves concurrent requests to the same endpoint (e.g., during a partial fetch that lazily retrieves a promisor object while the first response is still in flight). The original implementation used non-atomic shell operations (`test -f` followed by `rm`) to manage a one-shot marker file, which could lead to HTTP 500 errors when the second request tried to execute a script that the first request had already removed.

The fix replaces the non-atomic check-and-remove sequence with an atomic `rm` (without `-f`) operation. This ensures that exactly one request removes the marker and serves the modified response, while all other requests serve the unmodified response. The patch also adds a comment explaining why `stderr` is redirected to `/dev/null`: to suppress expected errors when the script is removed by a concurrent request. Per-request scratch files (using `$$` suffixes) prevent concurrent runs from overwriting each other, and the helper now runs the script only after confirming the response has changed, avoiding unnecessary executions.

The patch includes a new test, `t5567-one-time-script.sh`, which exercises the helper directly without a web server, using FIFOs to force the race deterministically. The test confirms that neither request emits an empty body (which would trigger HTTP 500) and that each behaves as expected: the modifying request rewrites its response, while the passthrough request remains unchanged. The commit message is thorough, explaining the problem, the atomic idiom, and the reasoning behind the changes.

This patch addresses a real, observed flake in `t5616.47` on macOS CI runners. The fix is well-motivated, the implementation is clean, and the test coverage is robust. The changes are confined to the test infrastructure (`t/` directory) and do not affect user-visible behavior.
