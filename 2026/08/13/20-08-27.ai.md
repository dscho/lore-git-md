This is the third patch in the v5 series introducing `git repack --drop-filtered` for partial clones. It extends `repack_promisor_objects()` to accept an optional `to_drop` oidset parameter, allowing the rebuilt promisor pack to exclude specific objects. The change is minimal and backward-compatible: all existing callers (currently only `builtin/repack.c`) pass `NULL`, so behavior remains unchanged. The patch touches three files: `builtin/repack.c` (updates the call site to pass `NULL`), `repack-promisor.c` (adds the `to_drop` field to `struct write_oid_context` and skips objects in the set during enumeration), and `repack.h` (updates the function signature).

The implementation is straightforward: during promisor object enumeration (via `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`), `write_oid()` checks if the current object is in `to_drop` and skips it if so. This ensures the rebuilt promisor pack omits the dropped objects while preserving all others. The patch does not introduce new behavior on its own—it merely provides the mechanism that later patches (5/6 and 6/6) will use to implement `--drop-filtered`.

The change is well-scoped and aligns with the series' goal of safely reclaiming disk space in partial clones. The `to_drop` set is populated by `enumerate_promisor_blobs()` (introduced in patch 4/6) and passed to `repack_promisor_objects()` in patch 5/6.
