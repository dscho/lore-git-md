This thread is about a small but useful test-only patch by Nikolaus Schuetz that adds coverage in `t/t1402-check-ref-format.sh` for characters already documented as forbidden in Git refnames but not explicitly tested in embedded form—things like spaces, `~`, `^`, `:`, `*`, `[`, and multi-byte sequences like `".."`. It also verifies that the single-character `@` refname is rejected even with `--allow-onelevel`.

The patch has been well received. Nikolaus has now posted an updated version that adopts this refactoring, making the test more concise and maintainable while preserving full coverage. The update also clarifies that an observed inconsistency in test fixtures (`heads/` vs `refs/heads/`) was inherited and doesn’t affect the validation logic, addressing Junio’s earlier note without requiring changes.
