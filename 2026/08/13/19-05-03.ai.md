This is the second patch in Vincent Mailhol’s four-patch v3 series adding Bash completion for `git history`. It implements value completion for the `--empty` option, which accepts `drop`, `keep`, or `abort` for the `drop` and `fixup` subcommands.

The patch updates `contrib/completion/git-completion.bash` to complete only the documented `--empty=<value>` form, omitting the undocumented `--empty <value>` split form for code simplicity. The implementation is subcommand-aware: it restricts completion to `drop` and `fixup` and ignores `reword` and `split`, which do not support the option. Tests in `t/t9902-completion.sh` verify that completion works for each valid value and that it is suppressed for unsupported subcommands.

The change is a targeted, well-scoped addition that follows the established pattern for option-value completion in the Git completion script. It is uncontroversial and ready for integration once the trivial rebase for the upcoming `squash` subcommand is applied. No substantive objections or loose ends remain.
