This is a brief update in the macOS fsmonitor bugfix thread. Tamir Duberstein withdraws the patch after further investigation failed to confirm that the proposed `FSEventStreamFlushAsync()` call actually resolves the performance regression described in the commit message. The thread is now closed unless Tamir revisits the issue later.

The patch targeted a macOS-specific timeout in Git’s fsmonitor daemon that triggered excessive `lstat()` calls and multi-second delays during `git status`. While the patch was narrowly scoped and received a tested review from Koji Nakamaru, the discussion stalled on two open questions: (1) the need for additional benchmark data in the commit message, and (2) a first-hand technical explanation of FSEvents queue behavior grounded in Apple’s documentation rather than empirical observation or third-party precedent. Patrick Steinhardt and Junio C Hamano both signaled that the patch could not proceed without these clarifications.

No code changes were merged, and the fsmonitor daemon’s macOS backend remains in its current state. The withdrawal leaves the original performance regression (introduced by 56cef9cb1a in April 2026) unresolved. If Tamir resends a revised patch, it will likely need to address the same technical and process concerns raised in this thread.
