Subject: [PATCH] t1401: add tests for `git symbolic-ref` exit codes and output with non-symbolic refs
Series version: standalone patch (v3 posted, documentation update deferred and now effectively abandoned)
Originating author: Nikolaus Schuetz
Thread type: patch (test coverage addition with documentation update)

Core problem or goal
Add systematic test coverage for `git symbolic-ref`'s exit codes and output behavior when querying a non-symbolic ref, both with and without the `--quiet` (`-q`) flag. The patch documents the current behavior—exit code 128 without `--quiet`, exit code 1 with `--quiet`, and empty stdout in both cases—while updating the command's documentation to reflect this reality. The thread has explored whether the exit code discrepancy is intentional or an oversight, with no consensus on a behavioral fix. The documentation update, initially proposed as a compromise to avoid freezing behavior in tests, is now effectively abandoned due to Junio's objection that documenting the current behavior would "cast wrong behavior into stone."

Current status
Under review; third iteration (v3) posted. The test additions are uncontroversial and ready for integration. The documentation update to `git-symbolic-ref.adoc` is abandoned; Patrick Steinhardt's latest review accepts the patch as "good enough" for merging without it. Changes since v2: replaced `test_expect_code` with `test_must_fail` to avoid over-specifying exit codes in tests, addressing Junio's earlier feedback. The patch itself (test additions) remains unchanged and is technically sound. Junio and Patrick continue to view the differing exit codes as likely unintentional, while Phillip Wood argues they may serve a useful purpose for script-level error differentiation. The path forward for the documentation update is now closed; a behavioral fix to unify exit codes may be proposed in a follow-up patch, but no such patch has been posted.
