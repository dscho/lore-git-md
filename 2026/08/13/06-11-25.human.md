This is a refactoring patch that moves the global `fetch_if_missing` variable into `struct repository`, continuing the `the_repository` removal effort. The patch is now in its fourth iteration (v4), addressing feedback from Junio C Hamano and Patrick Steinhardt on earlier versions.

The patch updates 15 files to replace the global `fetch_if_missing` with `repo->fetch_if_missing`, preserving the default value of `1` (enabled). Special handling is added in `builtin/fsck.c` and `builtin/index-pack.c` to avoid null pointer dereferences when these commands are invoked with `-h`. The partial clone documentation is updated to reflect the new per-repository nature of the flag.

Key improvements in v4 include using `revs->repo` in `revision.c` instead of `the_repository`, and coordinating with other in-flight topics to avoid conflicts with `seen` or `next`. The patch now uses `(repo ? repo : the_repository)->fetch_if_missing` in `builtin/index-pack.c` to handle both repository-bound and repository-less invocations safely. The author confirms the patch no longer conflicts with recent changes in `seen`, addressing a blocker from v3.

The patch is well-structured and addresses the immediate correctness issues raised in earlier reviews. The broader architectural question of whether `fetch_if_missing` belongs in `struct repository` remains open, but this iteration resolves the practical concerns about null pointer dereferences and repository-less invocations. The changes are minimal and focused, making it a logical step toward eliminating global state. While no new test coverage is introduced, the patch preserves existing behavior and appears ready for further review.
