This is a completion script patch series (four patches) that adds full Bash completion support for the `git history` command. The series covers subcommands (`drop`, `fixup`, `reword`, `split`), their options (including `--empty` and `--update-refs` value completion), and positional arguments (revisions and, for `split`, pathspecs).

Vincent Mailhol has split the work into four focused patches, each with thorough test coverage in `t/t9902-completion.sh`. The implementation uses Git’s existing completion helpers (`__gitcomp_builtin`, `__git_complete_refs`, `__git_complete_index_file`) and avoids hard-coding option names by ignoring the `<option> <value>` syntax during revision detection. Version 3 simplifies the logic and adds tests to ensure options are not completed before a subcommand is specified.

The series is a clear improvement over the previous standalone patch. It addresses the `split` subcommand’s pathspec edge case (switching from revisions to file paths after the first argument) and handles option value completion for `--empty` and `--update-refs`. The test coverage is comprehensive, and the code is well-structured. Junio C Hamano’s earlier suggestion about refactoring duplicated boilerplate is not addressed here, but Vincent’s follow-up in the thread defended the per-subcommand structure as more maintainable for future extensions.
