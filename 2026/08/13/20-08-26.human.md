This is the second patch in the v5 series introducing `git repack --drop-filtered` for partial clones. It adds a new helper function, `list_objects_filter__filter_oidset()`, to the list-objects-filter API, enabling callers to apply a filter to an existing set of OIDs without performing an object walk.

The helper is specifically designed for the `--drop-filtered` feature, which needs to identify which promisor blobs in an existing oidset exceed a size threshold (e.g., `--filter=blob:limit=10M`). Currently, it only supports `blob:limit` filters, reimplementing the size check logic directly rather than reusing the existing filter machinery, which is tied to the object-walk path. A `NEEDSWORK` comment marks this duplication for future refactoring. The helper avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info.

The patch is well-scoped and addresses the blocking type-mismatch bug identified in v4 by changing `unsigned long` to `size_t` to match `struct object_info.sizep`. It also incorporates Christian Couder’s mechanical feedback by making the `opts` parameter `const`. The implementation is straightforward: it iterates over the input oidset, reads object info (skipping unreadable objects), and inserts blobs exceeding the threshold into the `omitted` set. The function returns 0 on success or -1 if the filter is unsupported.

This patch is a clean, focused addition that enables the core functionality of `--drop-filtered` without introducing behavior changes. The technical debt (code duplication) is clearly marked and acknowledged as follow-up work. The helper’s design—avoiding lazy fetches and supporting only `blob:limit` for now—aligns with the series’ safety goals and incremental approach. No controversy or open questions remain for this patch; it is ready for maintainer review.
