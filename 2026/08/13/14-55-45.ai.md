This is the seventh patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t` to prevent integer truncation on 64-bit Windows. The series is now fully type-consistent and queued in `next` for integration testing.

This patch widens two tightly coupled interfaces: the `use_pack()` function’s `left` output parameter (used to report how many bytes remain in the current pack window) and the `avail_in`/`avail_out` fields in the `git_zstream` struct. These changes are bundled together because four call sites in `builtin/pack-objects.c` pass `&stream.avail_in` directly to `use_pack()`, making it simpler to widen both types at once rather than introduce bridge variables. The patch also updates the `zlib_buf_cap()` helper to accept `size_t` inputs, ensuring consistency with the widened zstream fields.

The changes are mechanical and confined to type widening, with no behavior or on-disk format changes. The `use_pack()` callers’ locals (e.g., `avail`, `remaining`, `left`) are updated to `size_t` for type consistency, though their values remain bounded by `core.packedGitWindowSize`, which is typically much smaller than 4 GiB. Similarly, the zstream fields are already capped by `zlib_buf_cap()`’s 1 GiB limit, so the widening does not introduce new >4 GiB capabilities but ensures the types match the existing constraints.

Files touched include `builtin/pack-objects.c`, `git-zlib.c`, `git-zlib.h`, `pack-check.c`, `packfile.c`, and `packfile.h`. The patch is a prerequisite for the next commit in the series, which widens `do_compress()` to eliminate the last `cast_size_t_to_ulong()` shim in `write_no_reuse_object()`. No new tests are added, as the changes are purely internal and do not alter observable behavior.

This is a well-scoped, low-risk change that aligns with the series’ goal of eliminating truncation risks on platforms where `unsigned long` is narrower than `size_t`. The patch is uncontroversial and ready for integration.
