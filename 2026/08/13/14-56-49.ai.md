This is a **bugfix** targeting the packfile subsystem, addressing a severe performance regression introduced in Git v2.53. The patch is the second iteration of a standalone fix by Johannes Schindelin, refining the approach after feedback from Junio C Hamano, Jeff King, and Patrick Steinhardt.

The regression causes quadratic-time (`O(N²)`) behavior when loading many packfiles, triggered by `packfile_store_add_pack()`’s linear scan of the packfile list before each insertion. In real-world Microsoft Git Scalar environments, this slows `git rev-parse --short HEAD` (used in shell prompts) from 0.4s to 4.5s with 37,815 packfiles. The fix adds a fast path to `packfile_list_append()` via a new `skip_dup_check` parameter, allowing callers to bypass the duplicate check when the packfile is known to be new. The parameter name was changed from `is_new` to better reflect its purpose, and the commit message now clarifies that the patch does *not* address an unrelated CI clone-time regression (previously claimed but later confirmed as a separate issue).

The patch touches `packfile-list.c`, `packfile-list.h`, and `packfile.c`, extending the API of `packfile_list_append()` while maintaining backward compatibility. A new perf test (`t/perf/p5303-many-packs.sh`) measures `git rev-parse --short HEAD` performance with 10,000 packs, complementing the existing `p5303.21` test. The change is minimal and targeted, focusing solely on the regression’s root cause without altering on-disk formats or other subsystems.

Junio’s latest review reopened the design discussion, raising **substantive maintainability concerns** about the fast-path’s reliance on caller discipline. The `skip_dup_check` parameter relaxes the uniqueness invariant of `packfile_list`, potentially introducing subtle performance or correctness issues if future changes violate the "known-new" assumption. While Patrick Steinhardt’s hashmap counterproposal remains deferred, Junio’s critique may prompt further iteration or accelerate its implementation. The patch is otherwise uncontroversial, with Peff confirming the regression’s severity and the fix’s reasonableness.

This is a production-critical fix for environments with many packfiles, such as Scalar’s shared cache repositories. The regression was introduced in commit `589127caa730` (October 2025) and undoes a prior fix (`ec48540fe8`, 2019). The patch is under active review, with the design question now the primary open issue.
