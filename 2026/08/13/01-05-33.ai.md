This is the v3 cover letter for a three-patch bugfix series targeting test infrastructure. The series makes two CGI helper scripts in `t/lib-httpd/` concurrency-safe by replacing non-atomic shell operations (`test -f` followed by `rm` or `touch`) with atomic alternatives (`rm` without `-f` for one-shot markers, `mkdir` for first-request election). The changes address a real, observed flake in `t5616.47` on macOS CI runners, where concurrent requests to the same endpoint caused HTTP 500 errors.

The v3 iteration incorporates feedback from Junio C Hamano and Patrick Steinhardt on v2. The most significant change is in patch 1, which now uses `rm` (without `-f`) instead of `mv` to consume the one-shot marker, simplifying the logic while maintaining atomicity. A new comment explains why the helper discards `stderr`: a losing request can find the marker already removed, and the error is expected. Patch 3, the documentation update, has been relocated from `t/README` to `t/lib-httpd.sh` and made specific to the HTTP daemon helpers, addressing Patrick Steinhardt’s preference for contextual placement. The documentation now also mentions `rm` (without `-f`) as an atomic alternative to `mv` for consuming one-shot markers, reflecting the change in patch 1.

The series is self-contained, touching only the test infrastructure (`t/` directory), and includes a new test (`t5567-one-time-script.sh`) that exercises the helper directly without a web server, making the race deterministic. The commit messages are detailed, explaining the problem, the atomic idioms, and the reasoning behind the changes. Junio has previously marked the series as ready for integration, and all substantive feedback has been addressed. The series looks well-crafted, addresses a real problem, and is unlikely to be controversial. It is poised for integration into `next`.
