This is the eighth patch in Johannes Schindelin’s 13-patch series widening size-related fields in Git’s delta and pack machinery to `size_t` for 64-bit Windows compatibility. The series is now fully type-consistent and queued in `next` for integration testing.

This patch widens the `maxsize` local variable in `archive-zip.c`’s `zlib_deflate_raw()` function from `unsigned long` to `size_t`. The change is a straightforward mechanical adjustment to prepare for the upcoming widening of `git_deflate_bound()`’s return type (Patch 12/13). Without this change, the widened `git_deflate_bound()` would silently truncate its return value on 64-bit Windows, where `unsigned long` is 32-bit but `size_t` is 64-bit. The patch has no semantic effect today because `size_t` and `unsigned long` are currently the same width on all platforms where this code runs, but it ensures type consistency once `git_deflate_bound()` is widened.

The patch touches only one line in `archive-zip.c` and is uncontroversial. It is part of the broader effort to eliminate incorrect `unsigned long` usage in Git’s delta and pack subsystems, aligning with the series’ goal of preventing integer truncation on platforms where `unsigned long` does not match the pointer width. No behavior or on-disk format changes are introduced.

This is a well-motivated, low-risk change that fits cleanly into the series. It should be of particular interest to Windows users and anyone working with large objects, though the impact is purely internal. The patch is ready for integration and requires no further review.
