This is the first patch in the v5 series introducing `git repack --drop-filtered` for partial clones. It adds the `--drop-filtered` and `--dry-run` command-line options to `git repack`, focusing solely on option parsing and validation without implementing the actual object enumeration or deletion logic (which will follow in later patches).

The patch enforces strict preconditions: `--drop-filtered` requires `--filter` (currently limited to `blob:limit`), `-a`, and a configured promisor remote, and it rejects `--filter-to` and explicit `-b`/`--write-bitmap-index`. The bitmap-handling logic is particularly careful, distinguishing between an explicit `-b` (which triggers an error) and a config-driven `repack.writeBitmaps` (which is silently disabled for the duration of the command). The `--dry-run` option is kept separate from `--drop-filtered` to maintain consistency with other Git commands and allow future expansion.

The implementation touches `builtin/repack.c` (adding option parsing, validation, and the `write_bitmaps_given` flag) and introduces a new test script (`t/t7706-repack-drop-filtered.sh`) covering all validation scenarios, including the bitmap-handling edge case. The patch is well-scoped, addressing only the CLI layer and deferring the core logic to later patches. The test coverage is thorough, and the validation logic is clear and specific.
