This is the v5 iteration of a feature patch series introducing `` `git repack --drop-filtered` ``, a new option for partial clones that safely reclaims disk space by removing locally cached promisor blobs exceeding a user-specified size threshold. The series is now six patches (down from seven in v4) after squashing the documentation into the patches that implement the corresponding functionality.

The core design remains unchanged: enumerate promisor blobs via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`, apply a size filter (currently only `blob:limit`), rebuild the promisor pack while excluding the selected blobs, and rely on lazy-fetch to restore them transparently if needed. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. The blocking type-mismatch bug identified in v4 (passing `unsigned long *` where `size_t *` was expected) has been fixed, and the `opts` parameter in the new `list_objects_filter__filter_oidset()` helper is now `const`. Christian Couder’s feedback on documentation organization (squashing the man page updates into the patches that implement the described behavior) and comment formatting has been incorporated.

The series is feature-complete for its stated scope: the three deferred items—remote verification (via the pending `remote-object-info` protocol command), recency-based culling, and the drop log—are explicitly follow-up work, not blocking requirements. The author has also improved the error message for ongoing operations to name the specific operations (merge, rebase, am, cherry-pick, revert, bisect) and standardized test script comments. The test coverage is thorough, including validation of option parsing, enumeration, real drops, and the safety guards.

This version looks production-ready: the blocking bug is fixed, the mechanical feedback has been addressed, and the series has been slimmed down by eliminating the standalone documentation patch. The next step is maintainer review and integration branch assignment; no new technical concerns have been raised since v4. The feature is a practical improvement for partial clone users, and the implementation is careful about safety and edge cases.
