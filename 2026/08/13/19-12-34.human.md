This is the final patch in Junio C Hamano’s three-part series fixing Bash completion for `git checkout`. It adds a fallback to untracked paths when no tracked paths match, ensuring completion never fails silently.

The change is minimal: four lines in `contrib/completion/git-completion.bash` that call `__git_complete_index_file "--others --directory"` when the tracked-path completion (`__git_complete_index_file ""`) yields no results. This aligns with the earlier `git diff` completion fix and addresses Elijah Newren’s feedback about consistency. The `--directory` flag improves performance by avoiding stat calls on non-directory files.

The patch also updates the test suite (`t/t9902-completion.sh`) with five new tests: two verify the fallback works for `git checkout u` (completing `ufile`), and three extend the existing `-C <path> checkout` test to include untracked files (`ufile`) alongside tracked and missing ones. All tests cover both the happy path and edge cases like missing files.

Junio acknowledges the fallback is of "dubious value" for typical `git checkout` workflows—untracked files are unlikely to exist in the index or another branch—but it’s a pragmatic last resort. The commit message flags a future enhancement (completing paths from arbitrary trees) as `#leftoverbits`, but this is explicitly out of scope.

The series is now technically complete, well-tested, and uncontroversial. It’s ready for integration and follows the earlier `git diff` completion work.
