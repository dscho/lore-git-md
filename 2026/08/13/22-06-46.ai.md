This is a **platform compatibility bugfix** for the external process provider in the diff provider RFC series. Junio Hamano reports that the `blob_line_cap()` function in `diff-process.c` breaks the build on platforms where `unsigned long` is narrower than `size_t` (e.g., 32-bit systems and 64-bit Windows). The issue stems from a type mismatch introduced by c6a4629e32 (June 2026), which changed `struct object_info.sizep` from `unsigned long *` to `size_t *`.

The fix is mechanical: replace `unsigned long size` with `size_t size` to align with the updated API. Junio has already applied this patch on top of the series in his `seen` branch, noting that further fallouts may exist but none are immediately apparent. The change is confined to `diff-process.c` and does not affect the provider interface, protocol, or integration logic. This resolves the `-Wincompatible-pointer-types` warning and ensures the external process provider works across all supported platforms.

The patch is uncontroversial and directly addresses a build regression. No design feedback is requested or implied; this is purely a correctness fix for the existing implementation. If the RFC is accepted, this change will be folded into the final version of the external process provider.
