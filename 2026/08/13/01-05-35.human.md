This is the second patch in a well-crafted three-patch bugfix series targeting test infrastructure. It makes the `http-429.sh` CGI helper concurrency-safe by replacing a non-atomic "check-and-set" (`test -f` followed by `touch`) with a single atomic `mkdir`. The change eliminates a latent race condition where concurrent requests could both pass the `test -f` check, causing both to return 429 instead of exactly one, which would break the retry flow.

The patch is narrowly focused on `t/lib-httpd/http-429.sh` and introduces no user-visible behavior changes. The commit message clearly explains the problem, the atomic idiom (`mkdir`), and the special handling for the "permanent" mode, which must return 429 to every request and therefore cannot leave any state marker. The reasoning is sound: the original "create-then-remove" pattern in "permanent" mode had the same race window as the main logic, and skipping the `mkdir` entirely is the correct fix.

This patch has already been reviewed by Junio C Hamano and Patrick Steinhardt in earlier iterations, and the current version addresses all feedback. The series as a whole is ready for integration and addresses a real, observed flake in the test suite. The fix is preventive rather than curative (the race cannot be forced deterministically), but the atomicity improvement is a clear correctness win. No controversy is expected.
