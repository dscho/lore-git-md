This is the fourth patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators mark repositories as trusted for lazy fetching. The patch implements the core logic for reading and validating the new configuration.

The patch adds a new function `upload_pack_lazy_fetch_trusted()` that checks whether the repository being served is listed in the `uploadpack.lazyFetchTrusted` allowlist. The allowlist is read only from protected configuration files (system or global scope), and relative paths (including single-dot paths) are explicitly rejected. The function returns a boolean indicating whether lazy fetching is permitted for the repository.

The implementation reuses the `path_allowlist_apply()` helper introduced in earlier patches, passing `allow_dot=false` to enforce absolute paths. The repository’s worktree or gitdir is resolved to an absolute path before checking the allowlist. The patch touches `upload-pack.c` (adding the new function and a protected config callback) and `upload-pack.h` (exporting the function).

This is a straightforward plumbing patch with no user-visible behavior change yet—it merely exposes the configuration check for use in the next patch. The motivation is clear: shift trust decisions to the server operator, addressing the security objection that untrusted repositories could abuse lazy fetching. The patch is uncontroversial in isolation, but its value depends on the broader series’ acceptance. No review feedback has been posted yet.
