This is a test patch. Nikolaus Schuetz adds missing test coverage in `t1402-check-ref-format.sh` for characters that are already documented as forbidden in refnames but were not fully exercised in the test suite.

The patch targets the `git check-ref-format` command, which validates whether a given string is a syntactically valid refname. The man page already lists the forbidden characters (space, tilde, caret, colon, question-mark, asterisk, open-bracket) and the special case that a refname cannot be the single character "@". The existing test suite only checked a subset of these: "?" was tested in embedded form, and "*" was tested only as a lone character or with `--refspec-pattern`. The new tests cover the remaining forbidden characters in embedded form and verify that "@" alone is rejected even when `--allow-onelevel` is given (since "@" is otherwise a valid component, as shown by the valid "refs/@" case).

The change is purely additive: eight new test cases in `t1402-check-ref-format.sh`, no code changes. The commit message is clear and references prior art (919eb8ace) for the same "document existing behaviour" pattern. This looks like a well-scoped, uncontroversial addition that fills a small gap in test coverage.
