Johannes Schindelin replies to Jeff King’s question about the necessity of the new performance test (`abbreviate with 10,000 packs`). Peff had argued the test was redundant because it showed the same slowdown as an existing test (`load 10,000 packs`). Johannes clarifies that the new test exercises a distinct code path: `git rev-parse --short HEAD` (used in shell prompts like GIT_PS1) must search for a unique abbreviation, while `--verify` stops at the first match. This distinction justifies the additional coverage, though the thread remains open on whether the test’s value outweighs its redundancy.

The patch’s core fix—a fast-path optimization in `packfile_store_add_pack()` to skip duplicate checks for new packfiles—is uncontroversial and endorsed by Junio C Hamano. However, Patrick Steinhardt’s earlier counterproposal (a hashmap-based redesign of `packfile_list`) and Ben Knoble’s question about `git maintenance` as a mitigation strategy remain unresolved.
