This is the first patch in Vincent Mailhol’s four-part series adding Bash completion for the `git history` command. It lays the foundation by implementing subcommand and option completion, along with revision argument handling.

The patch adds a new `_git_history()` function in `contrib/completion/git-completion.bash` that uses Git’s built-in parse-options helpers to complete the four existing subcommands (`drop`, `fixup`, `reword`, `split`) and their options. The key improvement since v2 is the elimination of hard-coded option names in revision detection logic: the completion script now ignores `<option> <value>` pairs when determining whether a revision has already been provided, making the code more maintainable.

Tests in `t/t9902-completion.sh` verify that options are not completed before a subcommand, that revision completion stops after the first required argument, and that `--` argument termination works as expected. The patch is well-structured and addresses all prior feedback from Patrick Steinhardt and D. Ben Knoble.

This is a quality-of-life improvement for users of `git history`, and the implementation looks solid. The only loose end is a trivial rebase to include the upcoming `squash` subcommand once it graduates from `seen`. No substantive objections remain, and the patch appears ready for integration.
