This is the third and final patch in a v3 bugfix series that makes HTTP daemon test helpers concurrency-safe. It adds a 13-line comment block in `t/lib-httpd.sh` documenting the atomic idioms used in the previous two patches: `mkdir` for first-request election and `rm` (without `-f`) for consuming one-shot markers. The comment explains why a non-atomic "test-then-act" sequence is unsafe (concurrent requests can both pass the check) and cross-references the two helpers (`http-429.sh` and `apply-one-time-script.sh`) that now use these idioms. It also notes the use of `$$` (process IDs) to prevent scratch-file clobbering.

The documentation is placed immediately before the `install_script` calls, so anyone adding a new helper will see it in context. This addresses Patrick Steinhardt’s feedback from v2, where he suggested moving the advice from `t/README` to a more specific location. The text is concise but complete, covering the problem, the anti-pattern, the safe alternatives, and the rationale for `$$` suffixes. No code changes are made; the patch is purely commentary. The series is now ready for integration into `next`.
