This is the second patch in Patrick Steinhardt’s six-part series making packfile generation pluggable as part of the ODB abstraction effort. It migrates `git upload-pack` from directly spawning `git pack-objects` to using the new ODB interface (`odb_generate_pack()`), eliminating backend-specific code in the transport layer.

The patch replaces manual `child_process` construction in `upload-pack.c` with a declarative `struct odb_generate_pack_options` that encapsulates wants, haves, shallows, filter specs, URI protocols, progress settings, and delta policies. The refactoring preserves all existing functionality—thin packs, progress meters, shallow clones, partial clones, and URI protocols—while delegating packfile generation to the ODB layer. A helper function (`append_one_shallow`) is renamed from `write_one_shallow` to reflect its new role in populating an `oid_array` instead of writing directly to a file.

The diff is clean and mechanical, with no behavior changes or on-disk format modifications. Test coverage in `t5516-fetch-push.sh` (adjusted in patch 3/6) accounts for benign argument-order changes and the replacement of `-q` with `--quiet`. This patch is a well-executed step toward decoupling Git’s transport layer from the "files" ODB backend, and it looks ready for deeper review of edge cases like error handling during pack generation. Contributors working on fetch plumbing or alternate ODB backends will want to pay attention.
