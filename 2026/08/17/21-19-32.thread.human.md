This thread is about a proposed bugfix to make `git config -e` propagate the exit code of the configured editor, rather than always returning 0 even if the editor fails. The patch, now in its second version, is a one-line change in `builtin/config.c` that makes `show_editor()` return the error code from `launch_editor()`, plus two new tests in `t/t1300-config.sh` to verify the behavior.

The v2 patch incorporates minor test-script cleanups suggested by Karthik Nayak—using `test_env` for `GIT_EDITOR` setup and simplifying test names—but leaves the core change and test coverage unchanged. The feature being modified was introduced mid-2024, so the risk of breaking existing scripts is limited but not zero. Junio has framed the decision as a trade-off between conceptual correctness (aligning with commands like `git commit`) and potential script breakage, but hasn’t taken a firm position. Karthik Nayak and brian m. carlson support the change, arguing that surfacing editor failures is more intuitive and safer for scripts using `set -e`. The patch itself is technically sound and ready for a maintainer decision, but the thread’s core tension remains unresolved.
