This thread is about a small but potentially impactful change to `git config -e`: making it exit with a non-zero status if the configured editor fails (crashes or returns an error). Currently, Git always exits with 0 even when the editor fails, which Kenneth Lorber argues may not have been intentional. The patch is minimal—just one line of code in `builtin/config.c` plus two new tests—and is marked as an RFC to gather feedback on whether this change is desirable.

Kenneth has framed this as a bugfix, but acknowledges that it could break scripts that rely on the current behavior (where `git config -e` always succeeds). The patch itself is clean and well-scoped, with appropriate test coverage for both success and failure cases. So far, there’s been no maintainer or reviewer feedback, so the key question is whether the community views this as a bug or an intentional quirk. If reviewers agree it’s a bug, the patch is likely to land; if not, it may be dropped or revised to minimize disruption.

The change is low-risk in terms of implementation, but its impact depends on how widely scripts depend on the current behavior. If you use `git config -e` in automation, this thread is worth following.
