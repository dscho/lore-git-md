This thread is about a small but meaningful consistency fix to `git config -e`. The command previously ignored failures from the configured editor, always exiting with status 0 even if the editor crashed or returned an error. Kenneth Lorber proposed a one-line patch to propagate the editor's exit code, aligning the behavior with commands like `git commit`. After brief discussion weighing the trade-off between correctness and potential script breakage, Junio merged the change to `next` as commit 633ac346ee in mid-August 2026.

The merged commit is functionally identical to Lorber's v2 patch, but it omitted the two new tests he had included to verify the new behavior. Lorber noted this in a follow-up, though no one pushed for the tests to be added afterward. The feature itself was introduced only in mid-2024, so the risk of breaking existing scripts was considered low. The thread is now closed, with the change in place and no reported issues since merging.
