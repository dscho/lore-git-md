This thread is about a proposed change to make `git config -e` return a non-zero exit code when the configured editor fails, rather than always succeeding. The patch, submitted by Kenneth Lorber as an RFC, modifies `show_editor()` in `builtin/config.c` to propagate the editor's exit code and adds two new tests to verify the behavior.

The discussion so far has centered on whether this change is worthwhile. Junio C Hamano, the maintainer, has expressed skepticism, noting that the config file is already modified by the time the editor exits, which could make the change less useful. Karthik Nayak, however, supports the patch, arguing that surfacing the error to the user is more intuitive and aligns with expectations, even if the config file has been modified. Kenneth Lorber acknowledges potential script breakage but frames the change as a potential bugfix, seeking broader input on the trade-off.

The patch itself is minimal and well-tested, with no technical objections raised. The latest feedback from Karthik Nayak is purely stylistic, suggesting minor test-script cleanups (using `test_env` for setting `GIT_EDITOR`) but leaving the core change untouched. The key open question remains whether the current behavior is intentional or a bug, and whether changing it now is worth the risk of breaking existing scripts. No other reviewers have weighed in yet, and Junio's position remains unresolved.
