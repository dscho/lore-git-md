This thread is about a proposed change to `git config -e` to make it exit with a non-zero status if the configured editor fails, rather than always returning success. The patch, submitted by Kenneth Lorber, fixes what the author argues may have been an unintentional behavior, adding two new tests to verify the exit codes when the editor succeeds or fails.

The discussion has centered on whether this change is worth making, given that the config file is already modified by the time the editor exits. Junio C Hamano, the maintainer, initially questioned the value of altering long-standing behavior, noting the potential for breaking existing scripts. Karthik Nayak has supported the change, arguing it aligns better with user expectations and is more intuitive, though his review was largely surface-level, focusing on minor test-script cleanups. Junio’s latest response acknowledges the trade-off but remains noncommittal, noting that `git config -e` is relatively new (introduced in mid-2024), which limits the risk of breakage. The thread is still open, with no clear consensus on whether the patch should proceed.
