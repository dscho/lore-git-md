This is the fourth patch in Patrick Steinhardt’s six-patch series making packfile generation pluggable in Git’s ODB layer. It refactors the progress-meter option handling in `git bundle` to simplify a confusing interface.

The current `git bundle create` command exposes four overlapping options (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`) that all control whether progress is shown. In practice, `--progress` and `--all-progress` do the same thing, and `--all-progress-implied` is always passed to `git pack-objects` regardless of user input. The patch replaces these with a single boolean `progress` flag, defaulting to true when stderr is a TTY. The change is purely internal: the default behavior (progress shown if stderr is a TTY) remains unchanged, and `--all-progress-implied` is still passed to `git pack-objects`.

The refactoring touches only `builtin/bundle.c`, replacing the `OPT_PASSTHRU_ARGV` options with `OPT_BIT` and `OPT_NEGBIT` macros and introducing a `progress` variable that controls whether `--progress` or `--quiet` is added to the `pack_opts` strvec. The patch is well-motivated and clearly explained, with a clean diff that makes the new logic easy to follow. It prepares the codebase for the next patch in the series, which migrates `git bundle` to the new ODB packfile-generation interface.

This is a small but meaningful cleanup that reduces cognitive overhead for future contributors. The change is uncontroversial and aligns with the series’ goal of reducing backend-specific code in transport commands. Contributors working on `git bundle` or the ODB abstraction effort may want to review the updated option handling, but most readers can safely treat this as a routine refactoring.
