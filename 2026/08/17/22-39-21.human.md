This is a bugfix patch under discussion, touching the exit code behavior of `git config -e`. Junio responds to Kenneth Lorber’s RFC with cautious skepticism.

The patch proposes to make `git config -e` exit non-zero when the editor fails, rather than always exiting 0 as it does now. Junio acknowledges the inconsistency—`git commit` already respects editor failure by aborting—but questions whether the change is worthwhile for `git config -e`. His reasoning: unlike `git commit`, where an editor failure can prevent an unwanted commit, `git config -e` has already modified the config file by the time the editor exits, so surfacing the failure doesn’t enable any meaningful recovery. The damage, if any, is already done, and there’s no way to undo it.

The discussion hinges on whether the current behavior is an oversight or an intentional quirk. Junio leans toward the latter, noting that Git has never cared about editor failure in this context. He doesn’t outright reject the idea but clearly sees little practical benefit. The thread is now waiting for broader community input—particularly from users who might rely on the current behavior or have strong opinions about consistency. If no compelling use case emerges, this patch is unlikely to move forward.
