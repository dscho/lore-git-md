This is Junio’s "What’s cooking in git.git" report for August 2026, #07 — the regular integration summary that gives a 30-second snapshot of every active topic in flight.

The 14th batch of topics graduated to `master` since the last report, bringing the total to 437 non-merge commits since Git 2.55.  The `next` branch holds 112 commits (some reverted), while `seen` contains 273, including everything still under review.

Notable graduations
• `jc/add-resolved` – `git add --resolved` stages only the conflict-resolved paths, aborting if any conflict markers remain.  Peff’s review flagged a NULL-deref edge case that was fixed before graduation.
• `tn/packfile-uri-concurrency` – concurrent packfile-URI downloads now avoid corrupting the staging file by opening it in read-write mode with separate offsets, making resumption safe.
• `js/sequencer-release-odb-before-commit` – the sequencer now releases the ODB before spawning `git commit`, preventing open file handles from blocking auto-maintenance on Windows.

Stalled topics
• `tb/repack-geometric-cruft` – the `--geometric` + `--cruft` combination still needs a reroll to address a bare `grep !` in the squash commit.
• `hn/checkout-track-fetch` – Junio marked this “Will discard” after the 15th iteration; the idea of auto-fetching the start-point branch remains controversial.

Cooking in `next` (ready for the next release unless last-minute issues surface)
• `ps/odb-pluggable-pack-generation` – the ODB layer now exposes callbacks to generate packfiles, removing hard-coded `pack-objects` calls from `upload-pack`, `send-pack`, and `bundle`.  Patrick’s review asked for a clearer separation between the public API and internal helpers.
• `ps/odb-eagerly-load-alternates` – alternates are now loaded at ODB initialization, eliminating scattered lazy-loading calls.  Taylor and Patrick are discussing whether this should be opt-in for submodules.
• `ss/repack-drop-filtered` – `git repack --drop-filtered` deletes local promisor blobs exceeding a `blob:limit=` filter, reclaiming space in partial clones.  Guards prevent running during other operations or if the index still references the blobs.
• `hn/bisect-reset-when-found` – `--reset-when-found[=<where>]` automatically runs `git bisect reset` after finding the culprit, optionally jumping to the found commit.
• `js/pack-objects-delta-size-t` – object sizes and offsets in `pack-objects` and delta encoding are now consistently `size_t`, fixing truncation on 64-bit Windows.

Waiting for review
• `mm/diff-process-hunks` – a new `diff.<driver>.process` config lets an external long-running process act as a hunk provider, so tools can decide which lines Git considers changed while leaving all output formatting to Git.  Elijah’s review raised concerns about the interaction with `-L` line-log ranges; the topic is currently stalled.
• `hn/history-squash` – the experimental `git history squash` folds a range of commits into one, replaying descendants on top.  Junio asked for a clearer distinction between `--no-edit` and `--edit` modes.
• `tc/replay-linearize` – `git replay --linearize` drops merge commits, mimicking `git rebase --no-rebase-merges`.  Phillip’s review identified a subtle ordering issue in the replay queue.

Small but useful
• `ss/repack-drop-filtered` – already mentioned above, but worth repeating: the `--dry-run` option lets users preview which blobs would be dropped.
• `ch/chdir-notify-drop-name` – the unused `name` parameter was removed from `chdir_notify_register()` and friends, simplifying the API.
• `cc/git-shallow-file-wo-value` – `git --shallow-file` without a value now fails gracefully instead of segfaulting.

The report also lists the usual housekeeping: typo fixes, test modernizations, and CI tweaks.  Nothing here looks sloppy or under-motivated; the topics that remain cooking are either waiting for a reroll or a final review pass.
