This is a **design discussion** in the ongoing ODB alternates refactoring series. Patrick Steinhardt responds to Jeff King’s critique of the first patch (`[PATCH v2 1/4]`), which decouples alternate path comparisons from `the_repository` to handle case-sensitivity inconsistently.

The core disagreement centers on whether the current patch’s complexity—using `core.ignoreCase` to deduplicate alternate paths—is justified. Jeff King (Peff) argues it’s an imperfect proxy for actual filesystem behavior, since alternates may reside on different filesystems with different case-sensitivity rules. He proposes two alternatives: (1) always use case-sensitive comparisons, accepting occasional duplicates as a minor performance trade-off, or (2) use `stat()` to compare `st_dev`/`st_ino` for potential duplicates, which would be more accurate but slightly more complex.

Patrick acknowledges the flaws in the current approach but raises concerns about `stat()`-based deduplication, noting that Windows filesystems (where case-insensitivity is common) often lack reliable `st_ino`/`st_dev` values. He leans toward Jeff’s first suggestion—simplifying to case-sensitive comparisons—while conceding that edge cases (e.g., multiple alternates differing only in case) would regress. His tone suggests he’s open to dropping the current complexity, though no revised patch has been posted yet.

The discussion remains unresolved, but consensus appears to be shifting toward a simpler design. Junio Hamano (the maintainer) has previously endorsed Peff’s preference for simplicity, and Patrick’s latest reply doesn’t push back strongly. The performance implications of eager alternate loading (e.g., for `git fsck`) and edge-case handling (e.g., corrupt alternates) are still unaddressed, but this thread focuses narrowly on the deduplication logic.

This is a **substantive design debate** with no clear resolution yet. If the series is to proceed, the next step will likely be a v3 patch simplifying the deduplication logic.
