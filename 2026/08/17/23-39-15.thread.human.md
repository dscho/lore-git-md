This thread is about a small but useful observability improvement to `git pack-objects`: adding a Trace2 event that records the total number of bytes written during pack generation, including headers and checksums. The patch, now in its second version, was submitted by friel@openai.com and has attracted review from Junio C Hamano, Patrick Steinhardt, and Jeff King.

The core idea is straightforward—Trace2 already tracks object counts, but byte counts are needed to measure how compression settings affect push performance. The v2 patch simplified the accumulation logic in response to Junio’s feedback, and a v3 is expected to incorporate consensus refinements around hash algorithm consistency (`f->algop->rawsz` instead of `the_repository->hash_algo->rawsz`) and minor stylistic cleanups suggested by Jeff King. The patch touches only `builtin/pack-objects.c` and the test suite (`t/t5300-pack-object.sh`), with no changes to on-disk formats.

The discussion also uncovered a tangential but notable performance curiosity: the current code recomputes the packfile’s hash three times when packs are split (triggered by `--max-pack-size`), which Jeff King and Patrick Steinhardt agree is "absurdly pessimal." They suggest dropping the redundant read-back verification, though this would be a separate optimization effort. For now, the Trace2 byte-counting patch itself is uncontroversial, and Jeff King’s recent endorsement ("good to me") signals it’s ready for Junio to pick up once the author posts v3 with the agreed refinements. No merge status has been reported yet.
