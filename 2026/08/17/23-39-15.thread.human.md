This thread is about a small but useful instrumentation patch for `git pack-objects`. The author, friel@openai.com, has submitted a second version of a patch that adds a Trace2 event to record the total number of bytes written during packfile creation, including headers and checksums. This fills a gap in observability, as Trace2 already tracks object counts but not byte counts, which are important for measuring how compression settings affect push performance.

The patch is uncontroversial and has received positive feedback from key reviewers. Junio C Hamano and Jeff King both gave it a thumbs-up in their latest replies, with Jeff calling it "good to me" and Junio adding "It looks good to me, too." The only remaining work is for the author to post a v3 incorporating two minor refinements: using `f->algop->rawsz` for hash size consistency (instead of `the_repository->hash_algo->rawsz`) and adopting Jeff's suggested refactoring for stylistic consistency. The patch touches only `builtin/pack-objects.c` and the test suite (`t/t5300-pack-object.sh`), with no on-disk format changes.

A side discussion about the triple-hash recomputation in `write_pack_file()`—where the code currently recomputes the packfile's hash three times during split-pack operations—has also reached consensus. Jeff King and Patrick Steinhardt agree that the read-back verification step is redundant and could be dropped without sacrificing safety, and Junio has endorsed this as a reasonable optimization. However, this is a separate issue and doesn't affect the current patch. The author is expected to post v3 shortly, after which the patch should be ready for merging.
