This thread is about a small but useful observability improvement to `git pack-objects`: adding a Trace2 event that records the total number of bytes written across all pack files in a single invocation, including headers and checksums. The patch, now in its second iteration, was posted by friel@openai.com in response to Junio C Hamano’s feedback on the initial version.

The current version (v2) simplifies the byte-accumulation logic and has been reviewed by both Junio and Patrick Steinhardt. Junio’s feedback focused on code clarity, while Patrick raised a correctness concern about whether the patch should use the hashfile’s algorithm (`f->algop->rawsz`) rather than the repository’s default hash algorithm (`the_repository->hash_algo->rawsz`) to ensure the byte count accurately reflects the trailing checksum. Jeff King (Peff) has since weighed in, confirming that the current approach is functionally correct but endorsing Patrick’s suggestion for consistency. Peff also proposed a small refactoring to align all three conditional blocks in `write_pack_file()` with `f->algop`.

The patch is still under review, with a v3 expected to address the hash size consistency point. No merge status has been reported, and the discussion remains focused on implementation details rather than the patch’s core goal. The only open questions are whether to adopt Patrick’s suggested change and, optionally, whether to rename the existing Trace2 event `"write_pack_file/wrote"` (which counts objects) to something clearer like `"wrote_objects"`. The author is expected to post a v3 incorporating the feedback, after which the patch should be ready for Junio to pick up.
