This thread is about a small but useful instrumentation patch that adds a Trace2 event to `git pack-objects` to record the total bytes written across all generated pack files. The goal is to improve observability of how compression settings affect push performance, since Trace2 already tracks object counts but not byte counts.

The patch is self-contained, touching only `builtin/pack-objects.c` and adding a test file (`t/t5326-pack-objects-trace2.sh`). It introduces a new `write_pack_file/wrote_bytes` event and an accumulator variable (`total_written`) to track cumulative bytes, including headers and checksums. Tests cover single packs, split packs (when `pack.packSizeLimit` is set), and edge cases like empty packs.

Junio C Hamano reviewed the patch and provided substantive feedback on the implementation. While he agrees with the patch’s motivation and design, he finds the two-variable approach (`pack_bytes` and `bytes_written`) unnecessary and potentially confusing. He suggests simplifying the code by directly accumulating the total in the common code path, eliminating the intermediate variable. This is a minor but typical maintainer preference for cleaner, more self-documenting code. No other concerns were raised, and the patch remains uncontroversial and well-scoped. The author will likely send a revised version addressing Junio’s feedback.
