This thread is about a small but useful instrumentation patch to `git pack-objects`: adding a Trace2 event that records the total number of bytes written across all pack files in a single invocation, including headers and checksums. The goal is to fill an observability gap—Trace2 already tracks object counts, but byte counts are needed to measure how compression settings affect push performance.

The patch is now at v2, posted in response to Junio’s substantive feedback on the initial version. The current version simplifies the accumulation logic and has been reviewed by Patrick Steinhardt and Jeff King, who reached consensus on two technical adjustments for v3: using `f->algop->rawsz` (the hashfile’s algorithm) instead of `the_repository->hash_algo->rawsz` for consistency, and refactoring the conditional blocks in `write_pack_file()` to align with `f->algop`. The patch remains focused on `builtin/pack-objects.c` and the test suite (`t/t5300-pack-object.sh`), with no changes to on-disk formats.

Two minor loose ends remain. First, Patrick suggested renaming the existing Trace2 event `"write_pack_file/wrote"` (which counts objects) to `"wrote_objects"` for clarity, but there’s no consensus on whether to do this. Second, Jeff and Patrick noted that the current code recomputes the packfile’s hash three times—during writing, during `fixup_pack_header_footer()`, and during verification on read-back—calling it "absurdly pessimal." They agreed this could be optimized by switching to the unsafe hash variant used by hashfiles, but this is deferred to a separate effort.

The patch is still under review, with no merge status reported. Junio’s latest reply was a brief, surface-level acknowledgment of Jeff’s hash recomputation observation, adding no new technical input. The author is expected to post v3 incorporating the agreed-upon changes soon.
