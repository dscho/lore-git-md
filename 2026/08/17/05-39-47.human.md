This is the final patch in Patrick Steinhardt’s six-part series making Git’s packfile generation pluggable. It migrates `git bundle` to the new ODB interface introduced earlier in the series, completing the goal of centralizing all outgoing packfile streams (fetch, push, bundle) under a single spawn point.

The patch replaces the manual `child_process` setup for `git pack-objects` in `bundle.c` with a declarative `struct odb_generate_pack_options`. The refactoring is straightforward: `write_pack_data()` now populates the ODB options (wants, haves, thin packs, delta policies, filter specs) and delegates to `odb_generate_pack()`, while `builtin/bundle.c` passes a simple boolean `progress` flag instead of a `strvec` of command-line arguments. The interface preserves all existing functionality—thin packs, delta base offsets, and filter specs—without changing on-disk formats or user-visible behavior.

This is a clean, well-motivated refactoring that aligns with the series’ goal of decoupling transport from the "files" ODB backend. The commit message clearly states the purpose, and the code changes are minimal and focused. The only loose end is the deferred plan to eventually replace `git-pack-objects` with a `git-objects` command, but that does not affect this patch’s correctness.

The series as a whole is now fully queued in `seen` and appears ready for wider testing. Contributors working on alternate ODB backends or transport-layer improvements may want to review this final piece, but for most readers, the earlier patches in the series are the ones that introduce the new ODB interface and migrate the core transport commands.
