## Notable threads

### Source tree reorganization: data-driven counterproposal
Junio C Hamano [2026/08/17/20-58-27] constructively engaged with Michael Montalbo’s data-driven counterproposal to Patrick Steinhardt’s `lib/` reorganization. Junio endorsed the mechanical grouping methodology—combining commit history patterns and call-graph relationships—as a valid thought experiment that produced intuitive results, such as the "transport" group (`connect.c`, `fetch-pack.c`, etc.). However, he cautioned that header-inclusion patterns may be fragile if a source file includes a header only for a single definition in an "out-of-place" header. Junio also proposed decoupling the `bisect` machinery from the `revision` machinery as a new reorganization target, framing it as a historical accident rather than a deliberate design choice. The discussion shifts the debate from *whether* to reorganize to *how* to do it effectively, with Montalbo’s methodology offering a potential path forward if the community addresses Junio’s caveats.

### Use-after-free in sparse index handling: merged
Junio C Hamano [2026/08/17/15-43-57] queued Shlok Kulshreshtha’s v3 bugfix for a use-after-free in `get_oid_with_context_1()` when resolving relative paths in the `:<stage>:<path>` syntax against a sparse index. The patch ensures the string allocated by `resolve_relative_path()` is freed only after its final use in `reject_tree_in_index()`. The regression test in `t1092-sparse-checkout-compatibility.sh` reliably reproduces the bug under `SANITIZE=address` and covers all three necessary conditions: a relative path, a sparse directory, and a leading colon followed by a digit. Junio called the fix "exactly what anybody would expect" and confirmed it matches the problem description. The patch is now cooking in `next` and will graduate to `master` in the next cycle.

### ODB alternates refactoring: v3 addresses `core.ignoreCase` timing
Patrick Steinhardt posted a v3 revision [2026/08/17/11-09-20] of the ODB alternates refactoring series, addressing the `core.ignoreCase` timing issue by reordering repository initialization (new patch 1/5) and retaining case-insensitive deduplication but documenting it as `NEEDSWORK`. The series now consists of five patches:
1. Reorders repository initialization to ensure the object database is created *after* the full repository configuration is written.
2. Migrates deduplication from `khash` to `hashmap` to support dynamic comparison functions, retaining case-insensitive deduplication but marking it as `NEEDSWORK`.
3. Eagerly initializes alternates during ODB creation and cache flushing, eliminating scattered calls to `odb_prepare_alternates()`.
4. Removes the `loaded_alternates` field from `struct object_database`.
5. Drops the `alternates_db` field from `struct object_database`.

Jeff King [2026/08/17/07-28-40] reached consensus with Patrick to drop case-insensitive deduplication entirely, calling it a "shoot yourself in the foot" scenario unlikely to affect real-world users. However, Jeff [2026/08/17/07-36-21] also identified a correctness concern: the patch caches `core.ignoreCase` during ODB initialization, but this value could be incorrect if the repository’s configuration isn’t fully loaded at that time. Patrick [2026/08/17/09-42-34] proposed cherry-picking a patch from a later series to ensure `core.sharedRepository` is set before `create_object_directory()` is called, but rejected using `repo_ignore_case()` because it relies on `repo_config_values()`, which is hardcoded to `the_repository` and would break submodule support. The series is queued in `seen` but may require a v4 to address the `core.ignoreCase` timing constraint.

### `git config -e`: RFC for editor failure propagation
Kenneth Lorber [2026/08/17/21-19-32] proposed an RFC patch to make `git config -e` exit non-zero if the editor fails, addressing an inconsistency with commands like `git commit`. The patch modifies `show_editor()` in `builtin/config.c` to return the error code from `launch_editor()` instead of unconditionally returning 0. Two new tests in `t/t1300-config.sh` verify the exit code when `GIT_EDITOR` is set to `true` (exit 0) and `false` (exit 1). Junio C Hamano [2026/08/17/22-39-21] questioned the value of changing the behavior now, given that the config file is already modified by the time the editor exits, and noted the bar for altering long-standing behavior is high. The RFC remains open pending further community input.

## In brief
- **Zsh completion**: Lutz Lengemann [2026/08/17/19-29-05] posted a v2 patch fixing completion for `git -C <path> <command>` by skipping *all* global options (not just `-C`) and their arguments to set `__git_cmd_idx`. The patch now handles constructs like `git -p checkout <TAB>` and `git --git-dir=<path> checkout <TAB>`.
- **Trace2 instrumentation**: A new patch [2026/08/17/23-39-15] adds a Trace2 event (`write_pack_file/wrote_bytes`) to record the total bytes written in each pack file, including tests for single and split packs. The motivation is to measure how compression settings affect push performance.
- **Submodule configuration**: Junio C Hamano [2026/08/17/17-43-34] questioned whether the warning-and-continue behavior for valueless `submodule.active` entries is an improvement over the existing hard error, arguing the hard error is sufficient for users to diagnose and fix their configuration.
- **Worktree repair**: Yoichi Nakayama [2026/08/17/21-27-01] clarified the real-world problem addressed by the worktree repair patch: symmetrical path conversion during `worktree.useRelativePaths` toggles. The author agreed to introduce a new function (`read_raw_gitfile()`) to return the path verbatim, leaving the existing API unchanged.
- **Packfile performance**: Jeff King [2026/08/17/07-21-13] clarified that the MRU optimization in `find_pack_entry()` mitigates `prepend()`’s quadratic-time behavior, making a hashmap-based solution unnecessary for this use case. The observed slowdown in `git rev-list --count` is due to pack lookup overhead, not list management.
