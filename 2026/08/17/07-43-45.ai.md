This is Junio’s "What’s cooking" report for August 2026, summarizing the current state of integration branches and in-flight topics. The report covers 437 commits graduated to `master` since Git 2.55, 112 commits cooking in `next`, and 273 commits in `seen`.

Key graduated topics include:
- **`jc/add-resolved`**: Introduces `git add --resolved` to stage conflict-resolved paths while preserving unrelated local changes. The feature aborts if conflict markers remain, ensuring safety.
- **`tn/packfile-uri-concurrency`**: Fixes concurrency issues in packfile URI downloads by avoiding concurrent appends to staging files, improving reliability for resumable downloads.
- **`js/sequencer-release-odb-before-commit`**: Releases the object database before spawning `git commit` in the sequencer, preventing file handle leaks that could block maintenance tasks on Windows.

Notable stalled topics:
- **`tb/repack-geometric-cruft`**: Aims to combine `--geometric` and `--cruft` repack modes but remains stalled due to unresolved feedback.
- **`hn/checkout-track-fetch`**: Proposes extending `git checkout --track` to fetch the branch from its remote, but Junio has marked it for discard due to design concerns.

Active topics cooking in `next` or `seen`:
- **`ps/odb-pluggable-pack-generation`**: Makes packfile generation pluggable via ODB callbacks, enabling alternative backends to serve packfiles directly. Expecting a reroll to address feedback.
- **`ps/odb-eagerly-load-alternates`**: Simplifies ODB initialization by eagerly loading alternates, reducing scattered lazy-loading calls. This is part of the ODB abstraction effort.
- **`js/packfile-fast-append`**: Fixes a performance regression in `packfile_list_append()` when adding many new packfiles, avoiding quadratic complexity.
- **`ss/repack-drop-filtered`**: Adds `--drop-filtered` to `git repack` to delete local promisor blobs exceeding a size limit, reclaiming space in partial clones.
- **`hn/bisect-reset-when-found`**: Introduces `--reset-when-found` to `git bisect`, automatically resetting to the original state or the found commit after completion.
- **`mm/diff-process-hunks`**: A major new feature allowing external processes to act as hunk providers via `diff.<driver>.process`, enabling tools to control which lines Git considers changed. This is stalled pending further discussion.

Controversial or complex topics:
- **`mm/diff-process-hunks`**: While powerful, this introduces significant complexity by delegating hunk detection to external processes. Feedback has focused on edge cases and integration with existing diff features.
- **`hn/history-squash`**: Adds a `git history squash` subcommand to fold a range of commits into one, with descendants replayed on top. Junio has requested clarification on the design.

The report also highlights several documentation updates (e.g., `kh/doc-trailers`), test modernizations (e.g., `ps/t7900-deflake-maintenance`), and platform-specific fixes (e.g., `js/mingw-build-updates`). The `the_repository` removal effort continues with `ty/repository-fetch-if-missing`, moving the `fetch_if_missing` global into `struct repository`.

For follow-up, the most critical topics are `ps/odb-pluggable-pack-generation` (ODB abstraction), `mm/diff-process-hunks` (external hunk providers), and `hn/history-squash` (new command). The stalled `tb/repack-geometric-cruft` and discarded `hn/checkout-track-fetch` are worth monitoring for potential resubmissions.
