This is the first patch in Patrick Steinhardt’s v3 series to remove lazy-loading of alternate object databases. It is a **bugfix and refactoring** that reorders repository initialization to ensure the object database is created *after* the full repository configuration — including `core.sharedRepository` and `core.ignoreCase` — has been written to disk.

The change is small (12 lines, 6 insertions, 6 deletions in `setup.c`) but critical: it fixes a latent correctness issue where the object database might read an incomplete or incorrect configuration during creation. This timing problem was highlighted by Jeff King during the v2 review, and this patch resolves it without requiring a cherry-pick from a later series. The fix moves the calls to `create_reference_database()` and `create_object_database()` to the end of `init_db()`, after all configuration values are set and written.

The patch is well-motivated and clearly explained. It touches only one file and makes no behavior changes visible to users. It is a prerequisite for the rest of the series, which will rely on `core.ignoreCase` being available during ODB setup. The change looks clean and uncontroversial, and it directly addresses a correctness concern raised in review.
