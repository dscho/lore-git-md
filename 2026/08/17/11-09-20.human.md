This is a refactoring patch series targeting the object database (ODB) subsystem, now in its third iteration. The goal is to simplify Git’s handling of alternate object databases by removing lazy-loading, which has become ineffective due to widespread eager parsing elsewhere in the codebase. The series now includes five patches, up from four in v2, with the new first patch addressing a long-standing timing issue by reordering database initialization to occur *after* repository configuration is fully written.

The core change is straightforward: alternates will now be initialized upfront during primary ODB setup, eliminating scattered calls to `odb_prepare_alternates()` and reducing code complexity. This also prepares the ground for future work to move alternates into the "files" backend. The series touches 13 files, primarily in the `odb/` subsystem, with a net reduction of one line of code (91 insertions, 92 deletions). No user-visible behavior changes are intended, though the removal of lazy-loading could affect performance in edge cases (e.g., repositories with thousands of alternates).

The most significant update in v3 is the new first patch, which reorders the creation of ref and object databases to happen *after* the repository configuration is written. This resolves a correctness concern raised by Jeff King about the timing of `core.ignoreCase` lookups, ensuring that configuration values are fully initialized before they are needed. The patch also documents the ongoing debate about whether case-insensitive deduplication of alternates is worth the complexity, leaving the door open for future simplification.

The remaining patches are largely unchanged from v2. Patch 2 decouples source path comparisons from `the_repository`, using a `struct hashmap` to handle case sensitivity without relying on global state. Patch 3 centralizes alternate initialization, patch 4 removes the now-unused `loaded_alternates` field, and patch 5 drops the `alternates_db` field. The series builds on Patrick Steinhardt’s prior ODB refactoring work (`ps/odb-make-creation-pluggable`) and is queued in Junio’s `seen` branch, though it has not yet appeared in a "What's cooking" report.

The series looks well-crafted and addresses the feedback from v2, particularly the timing issue. The new first patch is a pragmatic fix that avoids deeper architectural changes while ensuring correctness. The ongoing discussion about case-insensitive deduplication is noted but does not block this iteration. If you care about ODB internals or the broader effort to make Git’s object storage more modular, this series is worth following.
