This is the second patch in Patrick Steinhardt’s five-patch series refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternates. The patch decouples the comparison of alternate object database source paths from the global `the_repository` variable, addressing a long-standing dependency and correctness issue.

The core change migrates the deduplication of alternate sources from a `khash`-based map to a `hashmap`, allowing the comparison logic to be self-contained within the object database. Previously, the code relied on `fspathhash()` and `fspatheq()`, which implicitly depended on `the_repository` and could return inconsistent results if the repository’s configuration (specifically `core.ignoreCase`) wasn’t fully loaded. The new implementation resolves `core.ignoreCase` manually and uses dynamic comparison functions, eliminating the global dependency.

The patch retains case-insensitive deduplication of alternates but documents it as `NEEDSWORK`, reflecting the consensus from earlier review that this complexity may not be justified. The commit message acknowledges the dubious value of handling `core.ignoreCase` in this context, noting that duplicates are rare and the current implementation doesn’t fully resolve symlinks or mountpoints. The migration to `hashmap` is necessary to support the dynamic comparison logic, though it adds some boilerplate.

Code changes are confined to `odb.c`, `odb.h`, and `odb/source.h`, with the bulk of the work in `odb.c`. The patch removes the `khash` dependency and introduces new helper functions (`odb_source_paths_cmp()` and `odb_source_by_path_cmp()`) to handle path comparisons. The `struct object_database` gains a `source_paths_icase` field to cache the `core.ignoreCase` setting, and the `struct odb_source` gains a `hashmap_entry` to participate in the new map.

This is a well-motivated refactoring that aligns with the broader ODB abstraction effort. The changes are mechanical and don’t alter user-visible behavior, though the removal of the global dependency is a meaningful step toward making the ODB more modular. The `NEEDSWORK` note suggests this area may see further simplification in the future. The patch looks ready for integration, though it would benefit from a second look to confirm the `hashmap` migration is correct.
