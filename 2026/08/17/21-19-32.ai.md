This is a bugfix patch proposing to change the exit code behavior of `git config -e` when the editor fails. The patch surfaces an existing error condition that is currently swallowed: if the editor crashes or exits non-zero, Git currently ignores the failure and exits with status 0, which the author argues may not have been intentional.

The change is minimal: `show_editor()` in `builtin/config.c` now returns the error code from `launch_editor()` instead of unconditionally returning 0. The patch includes two new tests in `t/t1300-config.sh` that verify the exit code when `GIT_EDITOR` is set to `true` (exit 0) and `false` (exit 1).

The author flags this as an RFC because the behavior change could break scripts that rely on `git config -e` always succeeding, even when the editor fails. The commit message is clear about the trade-off, and the test coverage is appropriate for the change. The patch itself is small and focused, touching only the error propagation path. Whether this is accepted will likely hinge on whether the community considers the current behavior a bug or an intentional quirk.
