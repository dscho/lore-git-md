Subject: [PATCH v2] pack-objects: add Trace2 data point for total bytes written
Series version: v2 (single patch; v1 was initial submission)
Originating author: friel@openai.com
Thread type: patch submission

Core problem or goal
Add a Trace2 event to `git pack-objects` that records the cumulative size (in bytes) of all pack files generated during a single invocation, including headers and checksums. This fills an observability gap: Trace2 already records object counts but not byte counts, which are needed to measure how compression settings affect push performance.

Current status
Under review; v2 posted in response to Junio C Hamano’s **substantive review feedback** on v1. v3 is expected to incorporate the consensus reached between Patrick Steinhardt and Jeff King on hash algorithm consistency and stylistic refactoring. The update will switch from `the_repository->hash_algo->rawsz` to `f->algop->rawsz` for consistency with the hashfile’s algorithm and adopt Jeff King’s refactoring to align all three conditional blocks in `write_pack_file()` with `f->algop`. The patch remains focused on `builtin/pack-objects.c` and test suite (`t/t5300-pack-object.sh`). No merge status reported; still under review.

Key technical details
- New Trace2 event: `write_pack_file/wrote_bytes`
- Symbol: `bytes_written` (accumulator variable, simplified in v2)
- Files: `builtin/pack-objects.c`, `t/t5300-pack-object.sh`
- Behavior: reports cumulative bytes written across all packs in a single `git pack-objects` run, including headers and checksums
- On-disk format: no changes
- Test coverage: single pack, split packs (via `pack.packSizeLimit`), and edge cases (empty packs)
- Hash size handling: v3 will use `f->algop->rawsz` (the hashfile’s algorithm) instead of `the_repository->hash_algo->rawsz` for consistency, as confirmed functionally equivalent by Jeff King and endorsed by Patrick Steinhardt.

Open questions and loose ends
1. **Event naming clarity**: Patrick Steinhardt noted that the existing Trace2 event `"write_pack_file/wrote"` is ambiguously named (it counts objects, not bytes) and suggested `"wrote_objects"` would be clearer. This remains an optional improvement; no consensus has been reached on whether to rename it.
2. **Performance curiosity**: Jeff King and Patrick Steinhardt observed that the current code recomputes the packfile’s hash three times (once during writing, once during `fixup_pack_header_footer()`, and once during verification on read-back), calling it "absurdly pessimal." They agree that switching to the unsafe hash variant (used by hashfiles) could yield measurable speedups but explicitly deferred this discussion to a separate effort. Junio C Hamano acknowledged this observation in a **surface-level** reply but did not engage with the technical substance or express an opinion on the proposed refactoring.
