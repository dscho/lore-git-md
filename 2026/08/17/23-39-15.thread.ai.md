Subject: [PATCH] pack-objects: add Trace2 data point for total bytes written
Series version: single patch (no cover letter)
Originating author: friel@openai.com
Thread type: patch submission

Core problem or goal
Add a Trace2 event to `git pack-objects` that records the cumulative size (in bytes) of all pack files generated during a single invocation, including headers and checksums. This fills an observability gap: Trace2 already records object counts but not byte counts, which are needed to measure how compression settings affect push performance.

Current status
Under review; no prior versions. Patch touches only `builtin/pack-objects.c` and the test suite (`t/t5326-pack-objects-trace2.sh`). Tests verify the event fires for both single and split packs (when `pack.packSizeLimit` is set). Junio C Hamano provided **substantive review feedback** on the implementation’s clarity, specifically questioning the two-variable approach (`pack_bytes` and `bytes_written`) and suggesting a simpler accumulation strategy.

Key technical details
- New Trace2 event: `write_pack_file/wrote_bytes`
- Symbol: `total_written` (accumulator variable; implementation may change per review)
- Files: `builtin/pack-objects.c`, `t/t5326-pack-objects-trace2.sh`
- Behavior: reports cumulative bytes written across all packs in a single `git pack-objects` run
- On-disk format: no changes
- Test coverage: single pack, split packs, and edge cases (empty packs)

Open questions and loose ends
- **Implementation clarity**: Junio’s review requests simplification of the byte-accumulation logic, proposing to eliminate the intermediate `pack_bytes` variable by directly accumulating `bytes_written` in the common code path (hunk 1389) using `hashfile_total(f)` plus the hash algorithm’s raw size. This would remove the need for the separate accumulation step (hunk 1419) and improve readability.
