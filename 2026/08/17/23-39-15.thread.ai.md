Core problem or goal
Add a Trace2 event to `git pack-objects` that records the cumulative size (in bytes) of all pack files generated during a single invocation, including headers and checksums. This fills an observability gap: Trace2 already records object counts but not byte counts, which are needed to measure how compression settings affect push performance.

Current status
Under review; v2 posted in response to Junio C Hamano’s **substantive review feedback** on v1. v3 expected to address Patrick Steinhardt’s **substantive review** on hash size consistency and incorporate Jeff King’s suggested refactoring for stylistic alignment. The update simplified the byte-accumulation logic by removing the intermediate `pack_bytes` variable and directly accumulating `bytes_written` using `hashfile_total(f)` plus the hash algorithm’s raw size. The patch remains focused on `builtin/pack-objects.c` and test suite (`t/t5300-pack-object.sh`). No merge status reported; still under review.

Key technical details
- New Trace2 event: `write_pack_file/wrote_bytes`
- Symbol: `bytes_written` (accumulator variable, simplified in v2)
- Files: `builtin/pack-objects.c`, `t/t5300-pack-object.sh`
- Behavior: reports cumulative bytes written across all packs in a single `git pack-objects` run, including headers and checksums
- On-disk format: no changes
- Test coverage: single pack, split packs (via `pack.packSizeLimit`), and edge cases (empty packs)
- Hash size handling: v2 uses `the_repository->hash_algo->rawsz`; Patrick Steinhardt suggests `f->algop->rawsz` for consistency with the hashfile’s algorithm. Jeff King confirms functional equivalence but proposes a refactoring to make all three conditional blocks in `write_pack_file()` use `f->algop` for stylistic consistency.

Open questions and loose ends
1. **Hash size consistency**: Patrick Steinhardt’s review raises a correctness concern about whether the patch should use `f->algop->rawsz` (the hash algorithm used by the hashfile) instead of `the_repository->hash_algo->rawsz` to ensure the byte count accurately reflects the trailing checksum. Jeff King confirms the two are functionally equivalent in practice but suggests a refactoring to align all three conditional blocks in `write_pack_file()` with `f->algop`. This requires resolution in v3.
2. **Event naming clarity**: Patrick Steinhardt notes the existing Trace2 event `"write_pack_file/wrote"` is ambiguously named (it counts objects, not bytes) and suggests `"wrote_objects"` would be clearer. While he does not insist on a rename, this remains an optional improvement.
3. **Performance curiosity**: Jeff King observes that the current code recomputes the packfile’s hash three times (once during writing, once during `fixup_pack_header_footer()`, and once during verification on read-back), calling it "absurdly pessimal." He speculates that switching to the unsafe hash variant (used by hashfiles) might yield measurable speedups but notes this is a separate discussion from the Trace2 instrumentation.
