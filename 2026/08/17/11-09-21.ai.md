This is the first patch in Patrick Steinhardt’s v3 series refactoring the object database (ODB) subsystem to remove lazy-loading of alternates. It is a **correctness fix** for repository initialization timing, ensuring that the object database is created *after* the full repository configuration — including `core.sharedRepository` and `core.ignoreCase` — has been written to disk.

The patch moves the calls to `create_reference_database()` and `create_object_database()` to the end of `init_db()`, after the configuration for `core.sharedRepository` and `receive.denyNonFastforwards` is set. This change is motivated by a future patch in the series (patch 2/5) that will read `core.ignoreCase` during ODB creation; without this reordering, the value could be incorrect or uninitialized, leading to subtle bugs in case-insensitive path comparisons.

The diff is minimal (12 lines, 6 insertions, 6 deletions) and touches only `setup.c`. There are no user-visible behavior changes, and the patch is purely preparatory for the rest of the series. It directly addresses Jeff King’s concern from the v2 review about the timing of `core.ignoreCase` lookups and eliminates the need for Patrick’s earlier proposal to cherry-pick a patch from a later series.

This patch is a critical enabler for the rest of the series and is well-motivated. It looks ready for integration, with no open questions or loose ends. The change is mechanical and low-risk, as it only reorders initialization steps without altering logic.
