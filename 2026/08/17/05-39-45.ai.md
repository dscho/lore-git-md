This is the fourth patch in Patrick Steinhardt’s six-patch series making packfile generation pluggable in Git’s ODB layer. It refactors the progress-meter option handling in `git bundle create` to simplify its interface ahead of the ODB migration in the next patch.

The patch replaces four overlapping command-line options (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`) with a single boolean `progress` flag. The default behavior remains unchanged: progress is shown if stderr is a TTY, and `--all-progress-implied` is still passed unconditionally to `git pack-objects`. The refactoring is purely internal to `builtin/bundle.c` and does not affect the bundle format or on-disk behavior.

The change is well-motivated: the original interface was confusing, with redundant and historical options that did not map cleanly to user intent. The new boolean flag makes the code more readable and aligns it with the declarative style of the ODB interface introduced earlier in the series. The patch is small (16 insertions, 17 deletions) and focused, touching only the option-parsing logic in `cmd_bundle_create()`.

This is a preparatory refactoring with no functional impact, but it is a necessary step for the ODB migration in patch 5/6. Contributors working on `git bundle` or the ODB abstraction effort may want to review the new option-handling logic, though the change is straightforward and unlikely to introduce regressions. The patch is queued in `seen` as part of the series and is under active review.
