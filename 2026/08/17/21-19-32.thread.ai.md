Subject: [RFC PATCH] config: propagate editor failure exit code
Series version: none (standalone patch)
Originating author: Kenneth Lorber
Thread type: bug report / bugfix patch

Core problem or goal
`git config -e` currently exits with status 0 even when the configured editor fails (crashes or returns non-zero). The patch changes `show_editor()` in `builtin/config.c` to return the error code from `launch_editor()` instead of unconditionally returning 0, thereby surfacing the editor failure to the caller.

Current status
Under review (RFC). No prior versions. Patch is minimal: one-line code change plus two new tests in `t/t1300-config.sh` that verify exit codes when `GIT_EDITOR` is set to `true` (exit 0) and `false` (exit 1). The author has explicitly flagged the RFC status to solicit community input on whether the current behavior is intentional or a bug, and whether the potential for breaking existing scripts is an acceptable trade-off.

Key technical details
Files touched: `builtin/config.c` (function `show_editor()`), `t/t1300-config.sh` (new tests)
New symbols: none
Behavior change: `git config -e` now exits non-zero if the editor fails, rather than always exiting 0
On-disk format: unchanged
Test coverage: added two tests covering editor success (exit 0) and failure (exit 1)

Open questions and loose ends
- Is the current behavior (ignoring editor failure) intentional or a bug?
- Could this break existing scripts that rely on `git config -e` always succeeding?
- No maintainer or reviewer feedback yet; the RFC status remains in effect pending community input.

Participant positions
Kenneth Lorber (author): argues the current behavior may not have been intentional and proposes the change as a bugfix. Acknowledges potential script breakage and seeks community input on the trade-off. Implementation is clean and test coverage is appropriate.
