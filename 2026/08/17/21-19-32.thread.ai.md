Subject: [RFC PATCH v2] config: propagate editor failure exit code

Originating author: Kenneth Lorber
Thread type: bug report / bugfix patch

Core problem or goal
`git config -e` previously exited with status 0 even when the configured editor failed (crashes or returns non-zero). The patch proposed changing `show_editor()` in `builtin/config.c` to return the error code from `launch_editor()` instead of unconditionally returning 0, thereby surfacing the editor failure to the caller. This aligns the behavior with commands like `git commit`.

Current status
**Merged to `next` as commit 633ac346ee ("config: propagate launch_editor() failure in show_editor()", 2026-08-12)**. The implementation is functionally identical to the v2 patch, including the one-line code change and two new tests in `t/t1300-config.sh`. The feature's mid-2024 introduction limited the scope of potential breakage, and no issues have been reported since merging. The thread's core tension (consistency vs. script breakage) is now resolved in favor of propagating the editor exit code.

Key technical details
Files touched: `builtin/config.c` (function `show_editor()`), `t/t1300-config.sh` (updated tests)
New symbols: none
Behavior change: `git config -e` now exits non-zero if the editor fails, rather than always exiting 0
On-disk format: unchanged
Test coverage: two tests covering editor success (exit 0) and failure (exit 1), using `test_env` for `GIT_EDITOR` setup; no change to test logic or coverage
