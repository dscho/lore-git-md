This is a **bugfix** patch that closes a use-after-free in `get_oid_with_context_1()` when resolving relative paths in the `:<stage>:<path>` syntax against a sparse index. The patch is now in its third iteration (v3) and incorporates the only remaining feedback from Patrick Steinhardt: a minor stylistic tweak to use the return value of `reject_tree_in_index()` directly, eliminating redundant control flow.

The bug itself is subtle but well-documented. It requires three specific conditions to trigger: a relative path, a sparse directory in the index, and a leading colon followed by a digit (e.g., `:0:./dir/`). Without the fix, the code frees a heap-allocated string while still holding a pointer to it, leading to a use-after-free in `reject_tree_in_index()`. The patch consolidates the exit paths to ensure the string is freed only after its final use. The included test in `t1092-sparse-checkout-compatibility.sh` reliably reproduces the issue under `SANITIZE=address` and confirms the fix.

The commit message is thorough, explaining the bug’s origin (dating back to 2022), the conditions needed to trigger it, and the fix’s rationale. It also includes a clear reproduction recipe and demonstrates the bug’s symptoms both with and without the fix. The patch has received substantive reviews from René Scharfe and Patrick Steinhardt, both of whom confirmed the bug and the fix. Patrick’s tested review—where he observed the expected behavior (a fatal error for a non-existent path instead of a corrupted string) and verified the fix under `SANITIZE=address`—removes any lingering doubt about correctness.

This is a standalone bugfix with no dependencies or follow-up work. The patch is minimal, well-motivated, and ready for integration. The only changes since v2 are cosmetic, and the test remains unchanged. If you care about sparse index stability or memory safety, this is worth a quick look.
