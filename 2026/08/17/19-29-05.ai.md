This is a **bugfix for zsh completion**, specifically addressing the long-standing issue where `git -C <path> <command>` fails to complete commands or arguments. The author, Lutz Lengemann, has responded to stalled discussion with a **v2 patch** that significantly expands the scope of the fix.

The new version no longer just handles `-C` but now **walks the command line to skip all global options** (like `--git-dir`, `--work-tree`, `-p`, etc.) and their arguments, mirroring the logic in the bash completion script (`__git_main`). This means completions now work for constructs like `git -p checkout <TAB>` and `git --git-dir=<path> checkout <TAB>`, which previously failed. The patch also clarifies in the commit message that two related issues—`-c` not being listed in the `_arguments` spec and `--git-dir` only accepting `--git-dir=<path>` (not `--git-dir <path>`)—are left for separate follow-ups.

Lutz directly addresses D. Ben Knoble’s earlier concerns: the "local" variables (`__git_C_args` and `i`) propagate correctly due to zsh’s dynamic scoping, and the commit message now notes the limitation that directory completion for chained `-C` options (e.g., `git -C dir -C <tab>`) still doesn’t account for prior `-C` paths. Lutz experimented with a more ambitious fix (accumulating paths and using `_directories -W`) but opted to leave it out to avoid scope creep. The unrelated `git -<tab>` bug (producing redundant option descriptions and a giant file listing) is confirmed as a pre-existing issue, not introduced by this patch.
