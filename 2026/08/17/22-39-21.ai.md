This is a maintainer response to the RFC patch that proposes making `git config -e` exit non-zero when the editor fails. Junio C Hamano acknowledges the inconsistency in behavior compared to commands like `git commit` (which do propagate editor failure) but expresses skepticism about the value of changing it now. He notes that unlike `git commit`, where editor failure can prevent an unwanted commit, `git config -e` has already modified the config file by the time the editor exits, so surfacing the failure doesn’t enable meaningful recovery. The response leaves the RFC’s future open-ended, neither endorsing nor rejecting the change, but suggests the bar for altering long-standing behavior may be high. No technical objections to the patch itself are raised.
