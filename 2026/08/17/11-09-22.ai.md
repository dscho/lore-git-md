This is the second patch in Patrick Steinhardt’s five-patch v3 series refactoring the object database (ODB) subsystem to remove lazy-loading of alternates. It targets the deduplication logic for alternate object database sources, which currently depends on `the_repository` and `repo_ignore_case()` for case-insensitive path comparisons.

The patch migrates the deduplication mechanism from `khash` to `hashmap` to support dynamic comparison functions, eliminating the implicit dependency on `the_repository`. It introduces two new comparison functions (`odb_source_paths_cmp` and `odb_source_by_path_cmp`) that resolve `core.ignoreCase` manually at runtime, ensuring consistent behavior even if the repository’s configuration isn’t fully loaded. The change is motivated by correctness (avoiding flaky comparisons) and future-proofing (decoupling from global state), though the commit message acknowledges the complexity is of dubious value: case-insensitive deduplication may not be worth the overhead, and the patch explicitly marks it as `NEEDSWORK` for potential future removal.

Key technical details:
- **Files touched**: `odb.c`, `odb.h`, and `odb/source.h` (78 insertions, 22 deletions).
- **Symbols introduced**: `source_paths_icase` (field in `struct object_database`), `odb_source_paths_cmp()`, `odb_source_by_path_cmp()`, and `by_path_entry` (field in `struct odb_source`).
- **Behavioral change**: No user-visible impact, but the patch ensures consistent deduplication regardless of when alternates are registered. The `NEEDSWORK` note signals this mechanism may be simplified or removed later.
- **Dependencies**: Builds on the new first patch (1/5) in v3, which reorders repository initialization to ensure `core.ignoreCase` is set before ODB creation.

The patch is well-motivated and addresses the design concerns raised in v2 (notably Jeff King’s critique of the global dependency). The migration to `hashmap` is technically sound, though the `NEEDSWORK` note reflects the consensus that case-insensitive deduplication may not be worth retaining. No reviewer has yet engaged with this specific patch in v3, but the changes align with the broader ODB abstraction effort and look ready for integration. The only open question is whether the project will eventually remove the case-insensitive logic entirely, as suggested by the `NEEDSWORK` tag.
