This is the maintainer's **final acceptance** of the `http.sslVerifyStatus` security feature patch. Junio C Hamano has reviewed the v4 iteration and found it technically complete, with no remaining objections. The patch will be **merged to `next`** in the next integration cycle.

The feature adds a new boolean configuration option, `http.sslVerifyStatus` (default `false`), that enables OCSP staple validation during HTTPS certificate verification. When enabled, Git will fail the connection if the server does not provide a staple or if the staple indicates a revoked certificate. This closes a security gap where OpenSSL-linked Git binaries (common in FIPS-compliant deployments) currently ignore staples and accept revoked certificates. The design is fail-closed for security but defaults to `false` to avoid breaking remotes that do not support stapling.

The v4 iteration addressed all procedural feedback from earlier rounds: the four new tests were moved into `t5551-http-fetch-smart.sh` (eliminating the need for a new test script), the `SSL_VERIFYSTATUS` lazy prerequisite was made more robust with `test_might_fail`, and the commit message now includes the rationale that was previously in an in-code comment. The patch touches `http.c` (adding the config option and libcurl setup), `Documentation/config/http.adoc` (documenting the new key and backend differences), and the test script. No symbols are renamed, and the libcurl requirement (`CURLOPT_SSL_VERIFYSTATUS` since 7.41.0) is already below Git’s minimum version.

The author has provided concrete evidence for the feature’s value: government and FIPS-compliant deployments (e.g., US DoD PKI) mandate OCSP stapling, and OpenSSL-linked Git binaries (common in these environments) currently ignore staples, creating a security gap. The threat model (stolen private key impersonation enabling data exfiltration) is framed as a low-to-medium severity CVE risk. The patch is now ready for integration, with no outstanding technical or procedural issues. The open question about the feature’s long-term maintenance burden (given OCSP stapling’s declining relevance) remains, but the immediate need for government customers has been sufficiently justified.
