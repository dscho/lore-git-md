This is the third patch in Patrick Steinhardt’s five-patch v3 series refactoring the object database (ODB) subsystem to remove lazy-loading of alternate object databases. The series is part of the broader ODB abstraction effort and is currently queued in Junio’s `seen` branch.

This patch eagerly initializes alternates during ODB creation and cache flushing, eliminating the scattered calls to `odb_prepare_alternates()` across the codebase. The change is mechanical: it moves the alternates preparation from 11 call sites into two central locations (`odb_new()` and `odb_prepare()`), then makes `odb_prepare_alternates()` static since it is no longer needed externally. The patch removes 42 lines of code while adding only 2, a clear simplification.

The motivation is straightforward: lazy-loading alternates was an optimization that no longer pays off. Most Git commands access the ODB, so alternates would be loaded anyway, and the scattered preparation calls made the code harder to follow and risked bugs if a call site forgot to prepare alternates before iterating sources. The preceding patch in the series (1/5) fixed the timing issue with `core.ignoreCase` lookups, removing the last technical obstacle to eager initialization.

No user-visible behavior changes are intended, though the removal of lazy-loading could affect performance in edge cases (e.g., repositories with thousands of alternates). The patch is well-motivated and uncontroversial; the design discussion in the series has focused on the deduplication mechanism (patch 2/5) rather than this one. The changes are confined to the ODB subsystem, touching 11 files, and the patch looks ready for integration.
