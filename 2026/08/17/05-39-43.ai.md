This is the second patch in Patrick Steinhardt’s six-patch series making packfile generation pluggable via Git’s object database (ODB) layer. It migrates `git upload-pack` — the command that serves fetches — from directly spawning `git pack-objects` to using the new `odb_generate_pack()` interface introduced in the first patch.

The change is a mechanical but substantial refactoring of `upload-pack.c`. The old code manually constructed a `child_process` for `git pack-objects`, pushing dozens of command-line arguments (`--thin`, `--shallow`, `--filter`, `--uri-protocol`, etc.) into a `strvec`. The new code instead populates a declarative `struct odb_generate_pack_options` with the same settings (wants, haves, shallows, filter specs, URI protocols, progress flags, delta policies) and hands it to the ODB layer. The ODB layer’s files-backend implementation then translates these options into the equivalent `git pack-objects` command-line arguments under the hood.

Key symbols introduced or modified: `append_one_shallow()` (renamed from `write_one_shallow()`), `odb_generate_pack()`, `odb_pack_generator`, and `odb_generate_pack_options`. The patch preserves all existing functionality — thin packs, progress meters, shallow clones, partial clones, URI protocols, and bitmap usage — but moves the backend-specific logic out of `upload-pack.c` and into the ODB layer. Error handling and asynchronous operation (via file descriptors for pack and progress output) remain unchanged.

The diff is large (125 lines) but straightforward: the first half deletes the manual `child_process` setup, the second half adds the ODB interface calls and updates the polling loop to use the new `generator` handle. The only behavioral difference visible to callers is a benign change in argument order (e.g., `--shallow` now appears before `--stdout` in the internal `git pack-objects` invocation), which is already accounted for in the test adjustments in patch 3/6.

This patch is a clean, well-motivated step in the ODB abstraction effort. It reduces backend-specific code in the transport layer and sets the stage for alternative ODB backends that may not rely on `git pack-objects`. The next patch in the series (3/6) performs the same refactoring for `git send-pack`.
