This is a **bugfix** patch (v3) targeting a use-after-free in `get_oid_with_context_1()` when resolving relative paths in the `:<stage>:<path>` syntax against a sparse index. The patch is now ready for integration after addressing all substantive feedback, including a minor stylistic improvement suggested by Patrick Steinhardt.

The core issue remains unchanged from earlier versions: `resolve_relative_path()` allocates a new string for the resolved path, but the code frees this string (`new_path`) while still holding a pointer (`cp`) to it, leading to a use-after-free in `reject_tree_in_index()`. The fix consolidates the exit paths to ensure the string is freed only after its final use. The v3 update adopts Patrick’s suggestion to assign the return value of `reject_tree_in_index()` directly, eliminating redundancy while preserving correctness.

The regression test in `t1092-sparse-checkout-compatibility.sh` reliably reproduces the bug under `SANITIZE=address` and covers all three necessary conditions: a relative path, a sparse directory in the index, and a leading colon followed by a digit (e.g., `:0:./dir/`). The commit message provides a clear recipe for manual reproduction, demonstrating the bug’s manifestation (corrupted error messages or sanitizer failures) and confirming the fix resolves it.
