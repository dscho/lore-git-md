This is a small but useful instrumentation patch for the `git pack-objects` command. The author, Friel, works at OpenAI and wants to measure how different compression settings affect client-side push performance. Currently, Git’s Trace2 system records the number of objects written during pack generation, but not the actual byte count of the resulting packfile. This patch adds a new `write_pack_file/wrote_bytes` Trace2 datum that reports the total bytes written—including headers and checksums—whether the pack is streamed to stdout or written to disk. If the pack is split due to `pack.packSizeLimit`, the reported value is the sum of all partial pack sizes.

The change itself is straightforward: a new `bytes_written` counter is added to the `write_pack_file()` function, incremented for each pack segment, and emitted via `trace2_data_intmax()`. The patch also includes two new tests in `t/t5300-pack-object.sh` that verify the tracing works for both single and split packs.

The motivation is clear and practical: without this instrumentation, users experimenting with compression settings have no easy way to compare the resulting pack sizes. The implementation looks clean, the commit message is concise, and the tests cover the advertised behavior. There’s no obvious controversy or technical debt here—just a small, well-scoped addition that should be uncontroversial.
