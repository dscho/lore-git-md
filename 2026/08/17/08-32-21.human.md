This is a **bugfix** patch, now in its third iteration, that plugs a use-after-free in `get_oid_with_context_1()` when Git resolves relative paths in the `:<stage>:<path>` syntax against a sparse index. The issue was first reported in 2022 and has been dormant until now; the fix is minimal, well-tested, and uncontroversial.

The bug surfaces only when three conditions coincide: a relative path (e.g., `./dir/`), a sparse directory in the index, and a leading colon followed by a digit. Under these conditions, `resolve_relative_path()` allocates a new string for the resolved path, but the code later frees it while still holding a pointer to it, causing `reject_tree_in_index()` to read freed memory. The patch consolidates the exit paths so the string is freed only after its final use, eliminating the use-after-free.

Version 3 adopts Patrick Steinhardt’s stylistic suggestion to use the return value of `reject_tree_in_index()` directly, making the control flow slightly cleaner without changing the fix’s substance. The regression test in `t1092-sparse-checkout-compatibility.sh` reliably reproduces the bug under `SANITIZE=address` and remains unchanged. René Scharfe and Patrick Steinhardt have both explicitly approved the patch, and Patrick’s tested review confirms the fix works as intended.

This is a standalone patch with no dependencies or follow-up work. The commit message is clear, the test coverage is thorough, and all feedback has been addressed. It looks ready for integration.
