This is the first patch in Patrick Steinhardt’s six-patch series v2 introducing a pluggable interface for packfile generation in Git’s object database (ODB) layer. It establishes the core ODB interface (`odb_generate_pack()`) and implements it for the "files" backend, which delegates to the existing `git pack-objects` command.

The patch defines two new structures: `struct odb_generate_pack_options` (encapsulating wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies, and file descriptors for pack and progress output) and `struct odb_pack_generator` (an asynchronous operation handle with file descriptors for the generated pack and progress output, plus a finish callback). The interface is designed to support the transport layer’s needs (fetch, push, bundle) without exposing backend-specific options like cruft packs or keep packs, which are irrelevant for packfile generation during transport.

The files-backend implementation (`odb_source_files_generate_pack()`) constructs a `child_process` for `git pack-objects`, translating the ODB options into command-line arguments (e.g., `--thin`, `--shallow`, `--filter`, `--uri-protocol`). It handles shallow boundaries by neutralizing the repository’s shallow state when caller-provided shallows are present, and it supports asynchronous operation by returning file descriptors for the pack and progress output when the caller requests pipes. Error handling includes proper cleanup of descriptors and reporting of pack-objects failures (except SIGPIPE, which is treated as a normal occurrence).

The patch touches `odb.c`, `odb.h`, `odb/source-files.c`, and `odb/source.h`, adding 350 lines of new code. It does not change on-disk formats or user-visible behavior; the interface is internal and will be used by subsequent patches to refactor `upload-pack`, `send-pack`, and `bundle`. The commit message clearly explains the motivation (decoupling transport from the "files" backend to support pluggable ODBs) and the design trade-offs (excluding backend-specific options to keep the interface generic).

This is a well-structured foundational patch for the ODB abstraction effort. The interface is cleanly designed for asynchronous operation, and the files-backend implementation faithfully replicates the existing `git pack-objects` behavior. The next patches in the series will migrate transport commands to this interface, so contributors working on fetch/push plumbing or alternate ODB backends should pay attention. No substantive objections have been raised so far, but testing of edge cases (e.g., shallow clones, partial clones, error handling during pack generation) remains pending.
