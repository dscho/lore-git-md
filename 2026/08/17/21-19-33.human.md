This is a bugfix patch targeting the `git config -e` command. The patch addresses a long-standing quirk where Git ignores the exit code of the configured editor, always returning success (exit 0) even if the editor crashes or fails. Kenneth Lorber proposes surfacing the editor's failure to the caller by propagating the exit code from `launch_editor()` in `show_editor()`.

The change is minimal and focused: a one-line modification in `builtin/config.c` to return the editor's exit code, plus two new tests in `t/t1300-config.sh` that verify the behavior when the editor succeeds (exit 0) or fails (exit 1). The commit message is clear about the trade-off—this could break scripts that rely on `git config -e` always succeeding—but the author flags it as an RFC to gather community input on whether the current behavior is intentional or a bug.
