This is the first patch in Patrick Steinhardt’s six-part series making Git’s packfile generation pluggable as part of the ongoing ODB abstraction effort. It introduces the core interface that will be used by later patches to refactor `upload-pack`, `send-pack`, and `bundle`.

The patch defines two new structures: `struct odb_generate_pack_options` (which encapsulates all the parameters needed for transport-layer pack generation—wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies, etc.) and `struct odb_pack_generator` (an asynchronous handle for the ongoing pack generation). The main entry point is `odb_generate_pack()`, which delegates to the backend-specific implementation. For the "files" backend, this is implemented in `odb/source-files.c` by spawning `git pack-objects` as a child process, feeding it the same arguments that the transport layer currently constructs manually.

The commit message is clear: this interface is intentionally minimal, covering only the transport use case and not the repository-maintenance features of `git-pack-objects`. The long-term plan is to expose a more generic `git-objects` command, but that is deferred to a future series. The patch itself is mechanical and well-scoped, adding the scaffolding without changing any user-visible behavior. It is a prerequisite for the refactoring that follows in patches 2–6.
