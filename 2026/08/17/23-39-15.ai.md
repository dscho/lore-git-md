This patch adds a Trace2 data point to `git pack-objects` to record the total bytes written in each pack file. It introduces a new `write_pack_file/wrote_bytes` event that reports the cumulative size of all packs generated during a single invocation, including headers and checksums. The patch includes tests that verify the tracing works for both single and split packs (when `pack.packSizeLimit` is set).

The motivation is clear: the author wants to measure how different compression settings affect push performance by comparing the actual pack sizes produced. Currently, Trace2 records the object count but not the byte count, so this fills a gap in observability. The implementation is straightforward—it tracks the size of each pack file via `hashfile_total()` and accumulates the total in a new variable, which is then emitted as a Trace2 event.

The patch is well-scoped and includes thorough test coverage. It touches only the `pack-objects` command and its test suite, with no cross-subsystem changes. The commit message explains the "why" and the "what" concisely, and the code itself is minimal and focused. This looks like a clean, uncontroversial addition that addresses a real need for performance measurement.
