This is the final patch in Patrick Steinhardt’s six-part v2 series making Git’s packfile generation pluggable via the object database (ODB) layer. It migrates `git bundle` to the new `odb_generate_pack()` interface, completing the transport-layer refactoring that began in patches 2/6 (`upload-pack`) and 3/6 (`send-pack`).

The patch replaces the direct `git pack-objects` invocation in `bundle.c` with a declarative `struct odb_generate_pack_options` setup, mirroring the approach already taken for fetch and push. The ODB layer’s files-backend implementation translates these options into the equivalent `pack-objects` command-line arguments (`--thin`, `--delta-base-offset`, `--filter`, etc.), preserving all existing functionality (thin packs, filter specs, progress meters). The only user-visible change is the replacement of four overlapping progress-meter options (`--quiet`, `--progress`, `--all-progress`, `--all-progress-implied`) with a single boolean `progress` flag in `builtin/bundle.c`, though default behavior (progress shown if stderr is a TTY) remains unchanged.

The refactoring touches three files: `builtin/bundle.c` (simplifies option handling), `bundle.c` (replaces manual `child_process` construction with ODB calls), and `bundle.h` (updates the `create_bundle()` signature). The patch is clean and mechanical, with no changes to on-disk formats or transport protocols. Test coverage in `t5516-fetch-push.sh` (adjusted in patch 2/6) already accounts for the benign argument-order changes, and deeper edge-case verification (e.g., error handling during pack generation) remains pending for the series as a whole.

This patch is the culmination of the series’ goal: all pack streams leaving the repository (fetch, push, bundle) now delegate generation to the ODB layer, leaving only local maintenance tasks like `git repack` with direct knowledge of `git pack-objects`. The long-term plan to introduce a `git-objects` command for repository maintenance is deferred, so `git-pack-objects` and maintenance operations are not yet pluggable. The series is queued in `seen` and under active review, with no substantive objections raised so far. Contributors working on alternate ODB backends or transport-layer improvements may want to pay attention to the new `odb_generate_pack()` interface and its options structure.
