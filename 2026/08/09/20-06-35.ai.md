This is the final patch in Kristoffer Haugsbakk's 11-patch documentation series (`kh/doc-trailers`), now merged to `master`. The patch adds a new "OTHER RULES" section to the `git-interpret-trailers` man page to document how comment lines (as defined by `core.commentString`) are ignored during trailer parsing. This iteration (v5) is purely cosmetic, correcting a minor grammatical nit in the commit message ("to" → "to be") from v4; the patch content itself is unchanged.

The addition addresses a gap in the documentation: while `git interpret-trailers` has always ignored comment lines, this behavior was previously undocumented. The new section is positioned as supplementary material ("for completeness") rather than core usage guidance, reflecting the author's judgment that this detail is unlikely to affect most users. The commit message notes that comment characters are rarely alphanumeric (with Jujutsu VCS's `JJ:` as a notable exception), making accidental misparsing improbable. The patch also clarifies that this behavior is particularly relevant for `prepare-commit-msg` and `commit-msg` hooks.

This patch completes the series' goal of making the trailer format's parsing rules fully explicit. The "OTHER RULES" section joins earlier additions like strict key format definitions and failure-case examples, ensuring the documentation covers both common usage and edge cases. No further changes to the series are expected.
