This is the seventh patch in Kristoffer Haugsbakk’s now-merged 11-patch documentation series (`kh/doc-trailers`) that overhauls the `git-interpret-trailers` man page. The series as a whole was motivated by a bug report about silent failures when parsing trailer keys containing periods, and this patch specifically adds a concrete failure-case example to illustrate the strict key format (ASCII alphanumeric + hyphen only).

The patch inserts a 23-line example showing what happens when a trailer block contains invalid keys: `Skapad-på` (non-ASCII) and `Hash-in-v6.11` (contains periods). The example demonstrates that the entire block is rejected, even if some keys (like `Reviewed-by`) are valid. The accompanying explanation reinforces the two conditions for a valid trailer block and ties back to the key format rule introduced in the previous patch.

This is a well-crafted addition that directly addresses the original confusion by showing users exactly what to expect when their input doesn’t conform to the rules. The example is clear, self-contained, and pedagogically sound—exactly the kind of improvement that makes documentation more useful. No controversy or technical issues here; it’s a straightforward enhancement that completes the series’ goal of making trailer parsing behavior transparent.
