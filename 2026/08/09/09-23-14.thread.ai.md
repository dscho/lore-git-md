Subject: [PATCH] send-email: improve error message for missing subject
Series version: single patch, v2 under review; replaces v1
Originating author: Harald Nordgren
Thread type: bugfix patch

Core problem or goal
Fix a cryptic error message in `git send-email` when a patch file lacks a "Subject:" header. The current message "No subject line in <file>?" is terse, omits actionable guidance, and exposes Perl’s internal source location. The patch aims to make the error message clearer and suppress the Perl noise.

Current status
Under review; v2 posted. Junio C Hamano reviewed v1, identified a wording issue (the proposed message incorrectly implied the "Subject:" header must be on the first line), and confirmed the revised direction: the error message should simply state that no "Subject:" header was found anywhere in the file ("No 'Subject:' line in '%s'\n"). Harald Nordgren incorporated the feedback into v2, which is now posted. The patch is uncontroversial and addresses the core problem.

Key technical details
- File modified: `git-send-email.perl` (one line split and expanded)
- New test: `t/t9001-send-email.sh` (creates a patch file with no "Subject:" header, runs `--dry-run`, checks error output)
- Subsystem: send-email
- New behavior: error message is "No 'Subject:' line in '<file>'\n", actionable, omits Perl’s internal location, and accurately reflects the code’s logic (scans the entire header section for "Subject:")
- Old behavior: "No subject line in <file>?" plus Perl source location
- No on-disk format, CLI, or symbol changes

Open questions and loose ends
None. The final wording of the error message has been agreed and implemented in v2.
