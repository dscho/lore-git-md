Core problem or goal
Fix a cryptic error message in `git send-email` when a patch file lacks a "Subject:" header. The current message "No subject line in <file>?" is terse, omits actionable guidance, and exposes Perl’s internal source location. The patch aims to make the error message clearer and suppress the Perl noise.

Current status
Under review; v1 posted, v2 expected. Junio C Hamano reviewed v1 and identified a wording issue: the proposed message incorrectly implies that the first line of the file must start with "Subject: ", whereas valid patch files typically start with a "From " line followed by headers. The error condition is simply the absence of any "Subject:" header, not its position. Harald Nordgren has acknowledged the feedback and agreed to reword the message to focus on the absence of the header rather than its position. The patch is otherwise uncontroversial and addresses the core problem.

Key technical details
- File modified: `git-send-email.perl` (one line split and expanded)
- New test: `t/t9001-send-email.sh` (creates a patch file with no "Subject:" header, runs `--dry-run`, checks error output)
- Subsystem: send-email
- New behavior: error message is actionable and omits Perl’s internal location via trailing newline; wording to be adjusted in v2 to avoid implying the "Subject:" header must be on the first line
- Old behavior: "No subject line in <file>?" plus Perl source location
- No on-disk format, CLI, or symbol changes

Open questions and loose ends
