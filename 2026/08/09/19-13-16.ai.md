This is a maintainer review of a small bugfix patch for `git send-email`.

Junio reviews Harald Nordgren’s patch that improves the error message when a patch file lacks a subject line. The patch itself is straightforward: it replaces the cryptic "No subject line in <file>?" with a clearer "No 'Subject:' line in '%s'. The first line must start with 'Subject: '" and adds a trailing newline to suppress Perl’s internal source location. Junio’s feedback is largely positive, calling the newline fix "very nice" and acknowledging that the new error message is clearer.

However, Junio raises a subtle but important point about the wording: the patch’s new message implies that the first line of the file must start with "Subject: ", which is not actually the case for valid patch files (which typically start with a "From " line followed by headers). The subroutine’s error condition is simply the absence of a "Subject:" header anywhere in the file, not its position. Junio suggests rewording the message to avoid misleading users about the expected file structure. The review is substantive but not critical; it identifies a minor but real issue in the patch’s clarity without questioning the overall goal or implementation. No alternative wording is proposed, leaving that to the author. The patch remains under review, with this feedback likely to prompt a v2.
