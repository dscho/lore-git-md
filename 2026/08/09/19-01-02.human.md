This is the third patch in Justin Tobler’s seven-patch series (v2) that refactors `git receive-pack` to use the ODB transaction system for pluggable packfile writes. This patch specifically removes the global `unpack_limit` variable and replaces it with a lazy, per-repository configuration lookup inside the `unpack()` function.

The motivation is clear: the decision to explode a packfile into loose objects is a backend-specific detail, not something the generic ODB transaction interface should dictate. By moving the configuration lookup into `unpack()`, the patch prepares the codebase for the later introduction of `odb_transaction_write_pack()`, where the unpack limit will be handled internally by the backend. The change is mechanical and self-contained, touching only `builtin/receive-pack.c` and removing the now-unused global variables `receive_unpack_limit`, `transfer_unpack_limit`, and `unpack_limit`.

The implementation is straightforward: the new `get_unpack_limit()` function caches the unpack limit after the first lookup, ensuring the configuration is read only once per repository. The logic mirrors the original behavior, preferring `receive.unpackLimit` over `transfer.unpackLimit` and defaulting to 100 if neither is set. The patch is well-explained in the commit message and aligns with the series’ broader goal of eliminating global state to enable backend-agnostic packfile processing.

No test failures or edge cases are introduced, and the change is purely preparatory—observable behavior remains unchanged. This is a clean, focused refactoring that directly supports the series’ architectural goals. If you’re following the ODB abstraction effort, this patch is worth noting as a small but necessary step toward pluggable backends.
