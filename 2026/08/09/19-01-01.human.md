This is the second patch in Justin Tobler’s seven-patch v2 series making `git receive-pack` fully backend-agnostic for packfile writes. It tackles a key piece of global state: the temporary shallow file created during `unpack()`. The patch lifts the shallow-file setup out of `unpack()` and passes the file path explicitly through the call chain, preparing the ground for the later introduction of `odb_transaction_write_pack()` in patch 7/7.

The change is mechanical and focused: `unpack()` and `unpack_with_sideband()` gain a new `shallow_file` parameter, and the global `alt_shallow_file` is replaced with a local variable in `cmd_receive_pack()`. The temporary file is now created just before the transaction begins and passed down to `update_shallow_info()`, which propagates it to `prepare_shallow_update()`. No behavior changes are introduced; the patch is purely preparatory plumbing.

The diff is clean and the commit message clearly explains the motivation: removing reliance on global state so that the packfile ingestion logic can later be moved behind the ODB transaction interface. This is a well-crafted step in the larger ODB abstraction effort, and the patch looks ready for review attention on the interface ergonomics and the robustness of the transaction lifecycle.
