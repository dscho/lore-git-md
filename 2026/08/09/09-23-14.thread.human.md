This thread is about a small but user-facing improvement to `git send-email`. Harald Nordgren identified a confusing error message that appears when a patch file lacks a subject line: instead of the current terse "No subject line in <file>?", the new version explicitly tells users that the first line must start with "Subject: " and suppresses Perl's internal source location from the output.

The patch itself is minimal—just one line in `git-send-email.perl` is expanded—and includes a new test in `t/t9001-send-email.sh` to verify the error message is clean and matches expectations. The change is self-contained, touching only the send-email subsystem, and the motivation is straightforward: making the error more actionable for users unfamiliar with Git's patch format conventions. So far, the patch appears uncontroversial and ready for review.
