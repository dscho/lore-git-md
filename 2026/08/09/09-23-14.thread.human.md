This thread is about a small but user-visible improvement to `git send-email`. When a patch file lacks a "Subject:" header, the tool currently emits a cryptic error message that includes Perl's internal source location. Harald Nordgren posted a patch to make the message clearer and more actionable, replacing "No subject line in <file>?" with "No 'Subject:' line in '<file>'" and suppressing the Perl noise.

Junio C Hamano reviewed the first version, noted a minor wording issue (the message shouldn't imply the "Subject:" header must be on the first line), and confirmed the revised direction. Harald incorporated the feedback into a second version, which Junio has now approved and marked for the `next` integration branch. The patch is uncontroversial, includes a new test to verify the exact error message, and touches only the send-email Perl script and its test suite. It should graduate to `master` in the next integration cycle.
