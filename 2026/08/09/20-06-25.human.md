This is the first patch in Kristoffer Haugsbakk’s now-merged 11-patch documentation series (`kh/doc-trailers`) that overhauls the `git-interpret-trailers` man page. The series was motivated by a bug report about silent failures when parsing trailer keys containing periods (e.g., "My-6.11-Version"), which the maintainers confirmed was intentional but poorly documented.

This specific patch removes the RFC 822 email-header analogy from the command’s introduction. The commit message explains that most users don’t deal with email RFCs, so comparing trailers to them is unnecessarily technical. Instead, the patch simplifies the description to focus on trailers as key–value pairs, deferring the full format explanation to a later patch in the series. The change is purely textual: it removes the first mention of email headers, keeps a single innocuous comparison to email line folding, and drops a now-redundant disclaimer about RFC 822 differences.

The patch is well-motivated and uncontroversial. It’s part of a larger effort to make the documentation clearer and more self-contained, and the commit message provides historical context (the RFC 822 comparison dates back to 2013) and a clear rationale for the change. No technical behavior is altered—this is purely about improving the man page’s readability. The series as a whole has already been merged to `master`, so this patch is effectively a final, cosmetic refinement.
