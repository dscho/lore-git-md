This is the sixth patch in Justin Tobler’s seven-patch v2 series making `git receive-pack` fully backend-agnostic for packfile writes. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and is cooking in `seen`.

This patch updates the `unpack()` function signature to take an explicit file descriptor for the incoming packfile, replacing the hard-coded assumption that the packfile is always read from stdin. The change is a mechanical refactoring step that prepares for the introduction of `odb_transaction_write_pack()` in the next patch, which will move the packfile ingestion logic behind a generic ODB transaction interface. Call sites in `builtin/receive-pack.c` are updated to pass the correct file descriptor (0 for stdin when using sideband, or the packfile fd otherwise), and the `parse_pack_header()` helper is similarly updated to accept the fd as an argument.

The patch is small (9 insertions, 7 deletions) and touches only `builtin/receive-pack.c`. It does not change observable behavior and relies on existing test coverage. The motivation is clear: the current stdin assumption is incompatible with the goal of making packfile processing backend-agnostic, as alternative ODB backends (e.g., reftable, cloud storage) may not use the traditional files backend. The change is well-motivated and uncontroversial, fitting cleanly into the series’ overall goal of lifting global state and hardcoded assumptions out of `receive-pack`.
