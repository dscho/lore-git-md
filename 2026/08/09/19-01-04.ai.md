This is the fifth patch in Justin Tobler’s seven-patch v2 series making `git receive-pack` fully backend-agnostic for packfile writes. The patch converts the `unpack()` and `unpack_with_sideband()` functions from returning error strings to writing them into a caller-provided `strbuf` and returning a negative value on failure. The change is a prerequisite for moving the unpack logic behind the generic ODB transaction interface introduced later in the series.

The patch touches only `builtin/receive-pack.c`, updating the two unpack functions, their call sites, and the reporting functions (`report()` and `report_v2()`) to work with the new `strbuf`-based error reporting. The `execute_commands()` function is also updated to accept an integer error flag instead of a string. The diff is mechanical: every direct string return (`return "some error"`) becomes a `strbuf_addstr()` followed by `return -1`, and the callers now check the return value rather than the string pointer.

No behavior change is introduced; the patch is purely preparatory plumbing. The commit message explains that the motivation is to decouple error reporting from the function’s return value, which is necessary for the eventual ODB transaction interface. The `strbuf` is initialized once per `cmd_receive_pack()` invocation and released at the end, so buffer reuse is not a concern. The patch is uncontroversial and addresses feedback from v1 about error reporting ergonomics.
