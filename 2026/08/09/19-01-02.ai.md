This is the third patch in Justin Tobler’s seven-patch v2 series extending the ODB transaction system to make `git receive-pack` backend-agnostic for packfile writes. It is a refactoring patch that removes the global `unpack_limit` variable and its associated configuration globals (`receive_unpack_limit`, `transfer_unpack_limit`) from `builtin/receive-pack.c`, replacing them with a lazy, per-repository lookup via a new helper function `get_unpack_limit()`.

The patch is a direct response to feedback from v1: the decision to explode an incoming packfile into loose objects (rather than keeping it as a packfile) is a detail of the "files" backend and should not be exposed in the generic ODB transaction interface. By moving the unpack limit resolution into the `unpack()` function itself, the patch prepares the codebase for the subsequent introduction of `odb_transaction_write_pack()`, which will delegate packfile processing to the ODB backend. The change is purely internal; no user-visible behavior or on-disk format is altered.

The implementation is straightforward: the global variables are removed, the configuration parsing in `receive_pack_config()` is deleted, and `get_unpack_limit()` is introduced to lazily resolve the limit from the repository’s configuration. The helper caches the result statically to avoid repeated config lookups, and the logic mirrors the original fallback chain (`receive.unpackLimit` → `transfer.unpackLimit` → default of 100). The `unpack()` function now calls `get_unpack_limit(the_repository)` directly, preserving the existing behavior.

The patch touches only `builtin/receive-pack.c` and is mechanical in nature. It is a necessary plumbing step for the larger goal of making packfile writes backend-agnostic, and it aligns with the series’ overall direction of lifting global state out of the receive-pack logic. No test failures or edge cases are introduced, and the change is fully backward-compatible. The next patch in the series will continue the refactoring by introducing the `struct unpack_opts` bundle to further isolate unpack-related state.
