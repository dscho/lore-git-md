This is the sixth patch in Justin Tobler’s seven-patch v2 series making `git receive-pack` fully backend-agnostic for packfile writes. The patch explicitly passes the packfile file descriptor through the call chain instead of hard-coding stdin (`fd 0`). This is a mechanical refactoring step that prepares the `unpack()` logic to be moved behind the new `odb_transaction_write_pack()` interface in the next (and final) patch.

The change is confined to `builtin/receive-pack.c` and updates three functions: `parse_pack_header()` gains a `pack_fd` parameter, `unpack()` now takes the same parameter and wires it into the `child_process` struct for both `index-pack` and `unpack-objects` invocations, and `unpack_with_sideband()` passes `0` (stdin) to `unpack()` when the sideband is active. The diff is small (9 insertions, 7 deletions) and does not alter observable behavior.

This patch directly addresses feedback from v1 about the ergonomics of the transaction interface: by making the file descriptor explicit, the upcoming `odb_transaction_write_pack()` call will be able to accept an arbitrary fd rather than being tied to stdin. The change is uncontroversial and the series remains cooking in `seen`.
