This is a bugfix patch (v2) targeting a use-after-free in `get_oid_with_context_1()` when resolving relative paths in the `:<stage>:<path>` syntax against a sparse index. The patch is now ready for final review after incorporating a trivial trailer change to credit Johannes Schindelin as both reporter and original patch author, as suggested by René Scharfe.

The core issue remains unchanged from v1: `resolve_relative_path()` allocates a new string for the resolved path, but the code later frees this string while still holding a pointer (`cp`) to it, causing a use-after-free in `reject_tree_in_index()`. The fix consolidates the two exit paths into one, ensuring the string is freed only after its final use. The regression test in `t1092-sparse-checkout-compatibility.sh` reliably reproduces the bug under `SANITIZE=address` and confirms the fix.

Key technical details for follow-up discussion:
- **Files touched**: `object-name.c` (core function) and `t1092-sparse-checkout-compatibility.sh` (test).
- **Behavior change**: Eliminates the use-after-free by deferring `free(new_path)` until after `reject_tree_in_index()` completes.
- **Trigger conditions**: Requires a relative path, a sparse directory in the index, and a leading colon followed by a digit (e.g., `:0:./dir/`).
- **Test coverage**: The new test exercises these conditions and verifies the fix under address sanitization.
- **Related symbols**: No new symbols introduced; the change modifies control flow in `get_oid_with_context_1()`.
