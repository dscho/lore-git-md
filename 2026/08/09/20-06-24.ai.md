This is a documentation patch series (v5 of 11 patches) targeting `git-interpret-trailers`. The series has already been merged to `master` as `kh/doc-trailers`, but Kristoffer Haugsbakk is submitting a trivial v5 to address a minor grammatical nit in the commit message of patch 11/11. No technical or structural changes are proposed—this is purely a cosmetic update to the commit message wording ("to" → "to be").

The series itself is a comprehensive overhaul of the `git-interpret-trailers` man page, motivated by a prior bug report about silent failures when parsing trailer keys containing periods (e.g., "My-6.11-Version"). The maintainers confirmed the strict key format (ASCII alphanumeric + hyphen only) was intentional, but the documentation was unclear. This series addresses that gap by:
- Explicitly defining valid key formats and parsing rules.
- Standardizing terminology ("metadata" [singular], "trailer block", "key-value").
- Removing outdated RFC 822 references and replacing them with direct key-value framing.
- Adding concrete examples of valid/invalid usage, including a failure-case example showing rejection of keys with non-ASCII or non-hyphen characters.
- Clarifying comment handling via `core.commentString` and expanding the documented scope of the command (it operates on "any other kind of text," not just commit messages).
- Improving readability through structural reorganization (e.g., grouping related concepts about trailer addition before introducing `--trailer` aliases).

The v5 update is a response to surface-level feedback from D. Ben Knoble, who noted a missing word in the commit message of patch 11/11. Kristoffer declined to act on other optional suggestions (e.g., numbered inline list formatting), citing Git documentation conventions.
