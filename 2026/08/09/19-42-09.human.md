This is a bugfix patch that resolves a use-after-free in `get_oid_with_context_1()` when using sparse indexes with relative paths in the `:<stage>:<path>` syntax. The issue was originally reported by Johannes Schindelin and has been under discussion since 2022, but this is the first time it’s been properly fixed.

The bug occurs when three specific conditions coincide: a relative path (e.g., `./dir/`), a sparse directory in the index, and a leading colon followed by a digit (e.g., `:0:./dir/`). The function `resolve_relative_path()` allocates a new string for the resolved path, but the code later frees this string while still holding a pointer to it, leading to a use-after-free when `reject_tree_in_index()` tries to read it. The fix collapses the two exit paths into one, ensuring the string is freed only after its final use.

The patch includes a new test in `t1092-sparse-checkout-compatibility.sh` that reproduces the bug under `SANITIZE=address` and confirms the fix. Without the change, the test fails with heap-use-after-free errors; with it, the test passes cleanly. The commit message provides a clear explanation of the bug, the fix, and the test coverage, along with a step-by-step recipe to reproduce the issue manually.

This is the second iteration of the patch, but the only change from v1 is the addition of an `Original-patch-by: Johannes Schindelin` trailer to credit the original reporter. The fix itself and the test remain unchanged. René Scharfe reviewed the patch substantively and approved it, noting the bug’s origin and the importance of the test.
