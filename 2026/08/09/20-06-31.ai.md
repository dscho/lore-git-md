This is the seventh patch in Kristoffer Haugsbakk’s already-merged 11-patch documentation series (`kh/doc-trailers`) that overhauled the `git-interpret-trailers` man page. The series was motivated by a bug report about silent failures when parsing trailer keys containing periods and has since landed on `master`.

This specific patch adds a concrete failure-case example to the man page, demonstrating what happens when a trailer block contains keys that violate the strict format (ASCII alphanumeric + hyphen only). The example shows a three-line block where only the last line (`Reviewed-by`) is a valid trailer key; because the first two lines (`Skapad-på` and `Hash-in-v6.11`) contain non-ASCII or non-hyphen characters, the entire block is rejected. The patch also restates the two trailer-block detection rules and explains why the example fails to satisfy them.

The change is purely additive: 23 lines are inserted into the EXAMPLES section, immediately after the existing commit-msg hook example. No existing text is modified, and the new content is self-contained. The patch is part of the broader effort to make the command’s parsing rules explicit and pedagogically clear.
