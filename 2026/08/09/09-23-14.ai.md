This is a small bugfix and usability patch for `git send-email`.

The patch addresses a confusing error message that `git send-email` currently produces when a patch file lacks a subject line. Instead of the terse "No subject line in <file>?", the new message explicitly tells the user that the first line must start with "Subject: " and adds a trailing newline to prevent Perl from appending its internal source location to the error output.

The change is minimal: one line in `git-send-email.perl` is split and expanded, and a new test in `t/t9001-send-email.sh` verifies that the error message is clean and matches expectations. The test creates a patch file with no subject, runs `git send-email --dry-run`, and checks that the error output omits Perl's internal location.

The motivation is clear: the current error is cryptic to users unfamiliar with Git's patch format conventions. The new wording is more actionable and the newline suppression is a small but welcome polish. The patch is self-contained, includes a test, and touches only the send-email subsystem. It looks like a straightforward improvement that should be uncontroversial.
