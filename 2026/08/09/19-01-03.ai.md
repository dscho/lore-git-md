This is the fourth patch in Justin Tobler’s seven-patch v2 series making `git receive-pack` fully backend-agnostic for packfile writes. It is a refactoring patch that lifts eight previously global variables out of the `unpack()` function and bundles them into a new `struct unpack_opts` that is passed explicitly through the call chain.

The patch touches only `builtin/receive-pack.c` and is purely mechanical: no behavior change, no new API, and no test failures. The new `struct unpack_opts` contains the fields `fsck_msg_types`, `shallow_file`, `max_input_size`, `fsck_objects`, `reject_thin`, `err_fd`, and `quiet`, mirroring the globals they replace. The ternary initialization of `fsck_objects` and the late assignment of `err_fd` in `unpack_with_sideband()` are retained as-is; Patrick Steinhardt accepted these trade-offs in v1 as necessary for the larger goal of removing global state.

This change is a prerequisite for the seventh patch, which will move the packfile ingestion logic behind the new `odb_transaction_write_pack()` interface. By making the unpack options explicit, the patch enables the ODB backend to handle its own configuration (e.g., `unpack_limit` is irrelevant to backends that do not use loose/packed storage). The patch also clarifies the interface by passing the shallow file path and packfile file descriptor explicitly rather than relying on globals.
