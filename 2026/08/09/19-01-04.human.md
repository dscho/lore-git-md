This is the fifth patch in Justin Tobler’s seven-patch v2 series making `git receive-pack` fully backend-agnostic for packfile writes. The patch converts the `unpack()` and `unpack_with_sideband()` functions from returning error strings to writing errors into a caller-provided `strbuf` and returning a negative value on failure. This is a mechanical refactoring step that prepares the code for the later introduction of the generic ODB transaction interface, `odb_transaction_write_pack()`, which cannot return error strings directly.

The change is confined to `builtin/receive-pack.c` and touches the error-reporting paths in `unpack()`, `unpack_with_sideband()`, `execute_commands()`, and the two reporting functions (`report()` and `report_v2()`). The patch also initializes a single `strbuf` in `cmd_receive_pack()` that is reused throughout the unpacking and reporting phases, avoiding repeated allocations. The conversion is straightforward and preserves the existing error messages verbatim; the only observable difference is that the unpack status is now communicated via a buffer rather than a direct string pointer.

This patch is well-motivated and cleanly executed. The commit message clearly explains the purpose—preparing for a generic ODB transaction interface—and the diff is minimal, focused, and free of unrelated changes. The author has already addressed reviewer feedback from v1 regarding error-reporting ergonomics, so this version should be uncontroversial. No new test failures or edge cases are introduced, and the patch relies on existing test coverage. For anyone following the ODB abstraction effort, this is a small but necessary step toward backend-agnostic packfile processing.
