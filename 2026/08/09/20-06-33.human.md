This is a documentation patch, part of Kristoffer Haugsbakk’s already-merged 11-patch series (`kh/doc-trailers`) that overhauls the `git-interpret-trailers` man page. The series addresses long-standing confusion about the command’s strict parsing rules—particularly its rejection of trailer keys containing characters other than ASCII alphanumerics and hyphens—and standardizes terminology throughout the documentation.

Patch 9/11 (this email) commits to the term **"trailer block"** as the primary way to describe the group of trailers at the end of a commit message. The patch simplifies and clarifies several explanations by consistently using this term, which was introduced in earlier patches in the series. For example, it replaces a somewhat confusing discussion about blank lines ("A blank line will be added before the new trailer if there isn't one already") with a clearer rule: a new trailer block will be created if none exists, and a blank line will be inserted before it. This avoids edge-case ambiguity about whether the blank line is part of the trailer block or separates it from non-trailer content.

The patch also tightens the definition of where trailers are found in the input. Instead of describing two separate detection cases (a group of lines that is "all trailers" or "contains at least one Git-generated or user-configured trailer"), it now refers to the "trailer block" as a single concept, defined as being at the end of the commit message (either at the end of the input or before a `---` line). This makes the documentation more coherent and easier to follow.

The changes are purely textual and structural—no behavior is altered. The patch is well-motivated by the need to reduce ambiguity in the man page, and the commit message explains the reasoning behind each simplification. Since the series has already been merged to `master`, this v5 iteration is a trivial resend to address a minor grammatical nit in the commit message of another patch; this patch itself is unchanged from v4. No further review or discussion is expected.
