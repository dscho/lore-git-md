This is the final patch in Justin Tobler’s seven-patch v2 series extending the ODB transaction system to make `git receive-pack` fully backend-agnostic for packfile writes. It introduces `odb_transaction_write_pack()`, the generic interface that replaces `git receive-pack`'s hardcoded use of `git index-pack` and `git unpack-objects` with a transaction-based mechanism. The implementation in `object-file.c` becomes the "files" backend, while alternative ODB backends (e.g., reftable, cloud storage) can now provide their own implementations.

The patch moves the entire packfile ingestion logic—previously duplicated in `builtin/receive-pack.c`'s `unpack()`—into `object-file.c`, where it is refactored into `odb_transaction_files_write_pack()`. The "files" backend now owns the ".keep" lockfiles created by `git index-pack` and removes them post-commit via its new `finalize` callback, ensuring backend-agnostic cleanup. The transaction interface is extended with a `write_pack` callback and `struct odb_transaction_write_pack_opts`, which bundles previously global unpack options (shallow file, fsck settings, max input size, etc.) into a single, explicit parameter.

Mechanically, the patch deletes 165 lines from `builtin/receive-pack.c` (removing `unpack()`, `parse_pack_header()`, `push_header_arg()`, `get_unpack_limit()`, and the global `pack_lockfile`) and adds 180 lines to `object-file.c` (the new backend implementation and supporting helpers). The transaction API is updated to include the `write_pack` callback, and `odb_transaction_files_finalize()` is introduced to handle deferred cleanup of ".keep" lockfiles. The series’ preparatory refactoring (explicit shallow-file path passing, `strbuf`-based error reporting, and `struct unpack_opts`) ensures the new interface is ergonomic and robust.

No on-disk format changes are introduced, and the series relies on existing test coverage. The patch completes the ODB abstraction effort’s goal of making `git receive-pack` backend-agnostic, enabling alternative ODB backends to handle incoming packfiles without being tied to the traditional files backend. Reviewers are likely to focus on the ergonomics of the new interface, the robustness of the transaction lifecycle (particularly the deferred cleanup of ".keep" lockfiles), and the mechanical soundness of the global state removal.
