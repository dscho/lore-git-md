This is the final patch in Justin Tobler’s seven-part v2 series that completes the ODB transaction system’s support for pluggable packfile writes in `git receive-pack`. The patch introduces `odb_transaction_write_pack()`, a generic interface that replaces the hard-coded calls to `git index-pack` and `git unpack-objects` with a backend-agnostic transaction hook. The existing logic from `unpack()` is moved into `object-file.c` and becomes the "files" backend implementation.

The key change is that `receive-pack` no longer directly spawns `index-pack` or `unpack-objects`; instead, it delegates packfile ingestion to the ODB backend via the transaction system. The "files" backend retains the familiar `.keep` lockfile behavior, but now manages those lockfiles through the transaction’s `finalize` callback so they persist until references are updated. The patch also narrows `odb_reprepare()` to refresh only the transaction’s source ODB, avoiding unnecessary work for other backends.

Mechanically, the patch moves ~170 lines of code from `builtin/receive-pack.c` into `object-file.c`, updates the call sites to use the new interface, and adds the necessary transaction plumbing. No on-disk format changes are introduced, and the series relies on existing test coverage. The patch is well-motivated, clearly explained, and addresses all feedback from v1. It looks ready for serious review and is a natural next step in the ODB abstraction effort.
