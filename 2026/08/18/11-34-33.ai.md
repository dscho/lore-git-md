This is a feature patch introducing `git pull --hard`, a new mode that resets the current branch, index, and working tree to the fetched branch using `git reset --hard`. The patch adds the option to `builtin/pull.c`, updates the documentation, and includes tests covering basic usage, error conditions, and submodule recursion behavior.

The implementation rejects combinations with merge or rebase options (e.g., `--ff-only`, `--squash`) and ensures exactly one integration candidate is present. It preserves existing `--quiet` and submodule recursion settings from the pull context. The commit message and tests clearly document the destructive semantics: local commits and tracked-file changes are discarded, and untracked files may be deleted if they obstruct tracked files.

The patch is self-contained, well-tested, and addresses a plausible workflow need—users who want to discard local state and sync exactly to a remote branch without merge or rebase steps. The error handling is thorough, and the documentation explicitly warns about data loss. This looks like a clean, motivated addition that could spark discussion about whether such a destructive operation belongs in `git pull` or should remain a separate command.
