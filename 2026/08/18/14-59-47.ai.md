This is the third and final patch in D. Ben Knoble’s `dk/use-nsec-runtime` series (v3), which converts the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The patch is now technically complete, addressing all known correctness and performance concerns, and is ready for integration pending a final decision on the cache location for the new config value.

The patch removes the `USE_NSEC` macro from the build system (`Makefile`, `configure.ac`) and replaces it with a new `core.useNanosec` config key (defaulting to false). The `use_nanosec` field is added to `struct repo_config_values` and is `#ifdef`-ed out in `NO_NSEC` builds to prevent silent corruption on platforms lacking nanosecond support. This resolves the cross-platform correctness blocker raised by Junio C Hamano in earlier iterations. The performance regression identified in v1 (a ~41× slowdown in `git diff` benchmarks) is fixed by caching the value in `repo_config_values`, with benchmark results confirming performance is restored to baseline.

Key files touched include `read-cache.c` (the core `is_racy_stat()` logic), `environment.c`/`environment.h` (config handling), and documentation (`Documentation/config/core.adoc`, `Documentation/technical/racy-git.adoc`). The patch also updates the Racy Git documentation to list filesystems known to support nanosecond precision (ext2, ext4, XFS, CEPH, CIFS, NTFS, UFS, FUSE, FAT). The commit message retains the `Best-viewed-with: --ignore-space-change` hint as requested by SZEDER Gábor.

The only remaining open question is architectural: whether to cache `core.useNanosec` in `repo_config_values` (modern but limited to `the_repository`), `repo_settings` (supports per-repository variation), or a global variable. The author’s partial control-flow analysis shows that all 214 call paths to `repo_config_values()` currently terminate at `the_repository`, but Patrick Steinhardt has suggested a global variable as a fallback if the project prefers to avoid expanding the `the_repository`-only surface area. The patch is otherwise uncontroversial and aligns with the series’ goal of reducing "racy Git" problems without requiring recompilation. A textual conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics advance.
