This is a feature patch introducing a new `--hard` mode for `git pull`. The author, Artur Bieniek, proposes adding an explicit alternative to the existing merge and rebase modes. When invoked, `git pull --hard` fetches the remote branch and then performs a `git reset --hard` to it, discarding all local changes, untracked files, and local commits that aren’t present upstream.

The patch updates the `git-pull` documentation to list `--hard` as the fifth integration option, alongside `--ff-only`, `--rebase`, `--no-rebase`, and `--squash`. It adds a new `opt_hard` flag in `builtin/pull.c`, implements a `run_reset()` helper that delegates to `git reset --hard`, and wires up the option so that it rejects incompatible flags (e.g., `--rebase`, `--squash`, `--append`). The implementation preserves existing behaviors for quiet output (`-q`) and submodule recursion, and the tests verify that `--hard` fails when multiple branches are specified or when combined with disallowed options.

The motivation isn’t stated in the commit message, but the patch itself is clean: the code is straightforward, the documentation is clear about the destructive semantics, and the test coverage is thorough. There are no obvious red flags, though the feature itself may spark debate—`git pull --hard` is essentially a convenience wrapper around `git fetch && git reset --hard`, and some reviewers might question whether it’s worth adding a new top-level option for what is already a one-liner. Still, the patch is well-crafted and ready for discussion.
