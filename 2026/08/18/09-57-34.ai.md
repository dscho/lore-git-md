This is the final patch (5/5) in Kristoffer Haugsbakk’s v2 series adding `--abbrev`, `--color`, and `--date` formatting options to the experimental `git format-rev` command. The patch implements the new options by reusing `git log`’s existing `rev_info` struct and `pretty.c` date formatting logic, ensuring consistent behavior between the two commands.

The patch touches three files: `builtin/name-rev.c` (main implementation), `Documentation/git-format-rev.adoc` (updated synopsis and new option documentation), and `t/t6120-describe.sh` (expanded test coverage). The synopsis is simplified to highlight the two mandatory options (`--stdin-mode` and `--format`), with all others grouped under `[<options>]`. The `--date` documentation reuses the shared include file (`rev-list-option-date-alternatives.adoc`) introduced in patch 4/5.

Key technical details include the addition of a `date_cb()` callback to parse `--date` arguments, the use of `rev_info` to store formatting state, and the call to `date_mode_release()` to free any custom date format string allocated by `parse_date_format()`. The test suite is expanded to verify the new options behave identically to their `git log` counterparts, including error handling for invalid values (e.g., `--color=not-valid`) and custom date formats (`--date="format:%c"`). The helper functions `format_rev_cmp_log` and `format_rev_err_cmp_log` are updated to normalize option ordering, avoiding false negatives in comparisons.

The patch addresses all v1 feedback: the memory leak (missing `date_mode_release()`) is fixed, defensive `BUG_ON_OPT_NEG(unset)` assertions are consistently placed, and designated initializers are used for clarity. The series remains uncontroversial and is not yet queued in any integration branch. The new options fill a gap in `git format-rev`’s formatting flexibility, bringing it closer to parity with `git log`.
