This thread is a two-patch bugfix series from Elijah Newren addressing a race condition in Git's geometric repacking mechanism. The issue occurs when a multi-pack-index (MIDX) references a packfile that has been removed by a concurrent repack, causing processes using the stale MIDX to fail to locate objects. This manifests as crashes in `git replay` and missing-object errors in other commands like `git merge-tree`, `git diff`, and `git cat-file`.

The first patch ensures `git replay` fails gracefully when merge inputs are unreadable, preventing a SIGSEGV. The second patch, which is the focus of this latest email, tackles the root cause by modifying the packed-object backend to recover when a MIDX references a removed packfile. The fix is lightweight and confined to `find_pack_entry()` in `odb/source-packed.c`, ensuring all callers benefit without requiring broader changes. Both patches include thorough tests simulating the race condition and verifying the fixes.
