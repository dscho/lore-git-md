This thread is about a critical bugfix for a race condition in Git's geometric repacking mechanism, where a stale multi-pack-index (MIDX) can cause `git replay` and other server-side operations to crash or report missing objects. The two-patch series by Elijah Newren addresses this by making `git replay` fail gracefully when objects are unreadable (patch 1/2) and by adding recovery logic to the packed-object backend to handle MIDX-packfile mismatches (patch 2/2).

The fix is widely seen as necessary, but the implementation of patch 2/2 remains under active discussion. Junio C Hamano and Patrick Steinhardt have reviewed the series substantively, with no remaining technical objections to the core fix. Jeff King (Peff), however, has raised architectural and performance concerns, particularly about when the fallback logic should trigger. The latest exchange between Peff and Patrick clarifies that the bug affects *all* object lookups, not just those using `OBJECT_INFO_QUICK`, and that the fallback is only invoked when the MIDX should have found the object but didn’t. Peff now argues that the fallback should be tied to the `SECOND_READ` phase to optimize performance for `QUICK` callers, while Patrick’s refinement suggests scanning only the packs covered by the MIDX when the preferred pack is missing.

The series is at version 1, with no new version posted yet. The open question is whether Elijah will resubmit the patch with adjusted logic or leave the change to be handled during integration. The discussion has narrowed to optimizing the scan order and timing, with no fundamental objections to the fix itself. Key participants include Elijah (author), Junio (maintainer), Patrick (substantive reviewer), and Peff (architectural critic). The outcome may also influence Elijah’s planned follow-up patches to address additional race-condition scenarios.
