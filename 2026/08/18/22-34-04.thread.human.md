This thread is about a two-patch bugfix series by Elijah Newren that addresses a race condition in Git's geometric repacking mechanism, which was causing crashes in `git replay` and missing-object errors in server-side operations. The issue occurs when a multi-pack-index (MIDX) references a packfile removed by geometric repacking, leading to processes using the stale MIDX failing to locate objects. Patch 1 ensures `git replay` fails gracefully when merge inputs are unreadable, while patch 2 modifies the packed-object backend to recover from MIDX-packfile mismatches by scanning all packs covered by the MIDX when the normal lookup fails.

The series is now **ready for integration**. Junio C Hamano provided substantive reviews for both patches, endorsing the fixes and requesting only a minor test adjustment (removing a redundant `test_grep` check in patch 1/2). Elijah addressed this feedback, confirming the check was unnecessary, and Junio has since clarified that he can handle the adjustment during integration if Elijah prefers not to resubmit. Patrick Steinhardt also reviewed patch 2/2 substantively, praising the recovery logic and raising a nuanced question about its scope, which Elijah clarified—confirming the fix targets `OBJECT_INFO_QUICK` callers (e.g., `git replay`, `upload-pack`) while non-`QUICK` callers already recover naturally. No technical objections remain, and the series is a high-priority candidate for merging due to its impact on server-side stability.

The patches touch `replay.c` and `odb/source-packed.c`, adding graceful failure logic and MIDX recovery without changing on-disk formats. Tests simulate unreadable objects and MIDX-packfile mismatches, verifying error messages and recovery behavior. Elijah plans follow-up patches to address additional race-condition scenarios, but these are not blockers for the current series. The only remaining procedural question—whether Elijah should resubmit patch 1/2 with the test adjustment—has been resolved, with Junio confirming he can handle it during integration.
