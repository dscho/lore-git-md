This thread is about a two-patch bugfix series by Elijah Newren that addresses a race condition in Git's geometric repacking mechanism, where a multi-pack-index (MIDX) can reference a removed packfile, causing crashes in `git replay` and missing-object errors in other operations. The first patch ensures `git replay` fails gracefully when merge inputs are unreadable, while the second modifies the packed-object backend to recover from MIDX-packfile mismatches by scanning all packs covered by the MIDX when the normal lookup fails.

The series was initially considered ready for integration after substantive reviews from Junio C Hamano and Patrick Steinhardt, but Jeff King (Peff) raised an architectural critique of the second patch, proposing an alternative design where the packed-object backend returns a tri-state value to distinguish between different object lookup outcomes. Patrick Steinhardt has since clarified that the fix addresses a broader correctness issue: when an object exists in multiple packs covered by a MIDX and the preferred pack is removed, the current code fails to find the object in the remaining packs, affecting all object lookups, not just performance-sensitive ones. This narrows the disagreement, as Peff’s critique focused on whether `OBJECT_INFO_QUICK` callers should handle false negatives themselves, while the fix addresses a fundamental bug.

The discussion now centers on whether the recovery logic should remain in the packed-object backend (Elijah’s approach) or align with Peff’s tri-state proposal, where callers handle missing packfiles. Patrick’s latest email refines the tri-state design, suggesting that scanning only the packs covered by the MIDX when the preferred pack is missing would address the correctness issue without a performance penalty. The series remains a high-priority candidate for merging, but the outcome of this discussion may require revisions to the second patch. Key participants include Elijah Newren (author), Junio C Hamano (maintainer), Patrick Steinhardt (reviewer), and Jeff King (reviewer), with no response yet from Elijah to the latest design critique.
