This is the second patch in D. Ben Knoble’s three-patch series converting the `USE_NSEC` macro to a runtime configuration option (`core.useNanosec`). It is a no-op refactoring of `repo_config_values_init` in `environment.c` that reorders the assignments to match the struct declaration, grouping them by config section ("core", "sparse", "branch") for clarity and maintainability.

The patch is purely mechanical and uncontroversial. It changes no behavior, adds no new functionality, and is ready to advance independently of the rest of the series. The reordering makes it easier to validate future additions to the struct, which is particularly relevant since the third patch in the series will add a new field (`use_nanosec`) to `struct repo_config_values`. The commit message explains the motivation clearly: the current assignment order is chaotic and hard to follow when comparing with the struct definition.

This patch is part of a series that is already cooking in `next` under the topic `dk/use-nsec-runtime`. It does not address the series’ remaining open question (where to cache `core.useNanosec`), but it is not blocked by that discussion. The only potential conflict is with `ty/repo-config-cleanups` in `seen`, which removes comments in the same struct; this will require trivial resolution if both topics advance.
