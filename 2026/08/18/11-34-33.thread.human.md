This thread introduces a new `--hard` option for `git pull` that would reset the current branch, index, and working tree to the fetched branch, effectively discarding all local changes. The patch, submitted by Artur Bieniek, includes implementation, documentation, and tests, but has not yet received substantive review.

Junio C Hamano, the maintainer, has weighed in with a clear objection to the feature's design. He argues that `git pull` is meant for integrating history, not for destructive operations, and that adding `--hard` risks accidental data loss for users who make local changes. While he acknowledges that some users might find the convenience useful, he prefers keeping destructive operations explicit—such as the existing `git fetch && git reset --hard` sequence—rather than bundling them into `git pull`. His feedback is firm but measured, signaling that the patch is unlikely to be accepted without a significant shift in the discussion.

The thread is now at a decision point. Artur may choose to defend the feature's place in `git pull`, propose an alternative command (like a new `git sync` or `git reset-upstream`), or drop the effort entirely. No other reviews have been posted yet, so the conversation remains open.
