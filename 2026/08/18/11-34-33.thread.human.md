This thread introduces a new `git pull --hard` option, proposed by Artur Bieniek, that resets the current branch, index, and working tree to match a fetched remote branch using `git reset --hard`. The patch is self-contained, adding the option to `builtin/pull.c`, updating documentation, and including tests for basic usage, error conditions, and submodule recursion. It explicitly rejects combinations with merge or rebase options (like `--ff-only` or `--squash`) and preserves existing `--quiet` and submodule recursion settings.

The feature is framed as a convenience for users who want to discard local changes and sync exactly to a remote branch without merge or rebase steps. The implementation is thorough, with clear warnings about data loss—local commits and tracked-file changes are discarded, and untracked files may be deleted if they obstruct tracked files. While the patch is well-tested and motivated, it may spark debate about whether such a destructive operation belongs in `git pull` or should remain a separate command.
