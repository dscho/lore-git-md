The `git pull --hard` thread is about a proposed `--hard` option that would reset the current branch, index, and working tree to the fetched upstream branch, discarding all local changes. Artur Bieniek submitted the patch as a convenience shortcut, but Junio C Hamano objected on principle, arguing that `git pull` should focus on history integration and that destructive operations should remain explicit (e.g., `git fetch && git reset --hard`).

The discussion has now taken a constructive turn. Phillip Wood reviewed the patch and proposed an alternative design to address Junio’s safety concerns. Instead of silently discarding uncommitted changes, the feature would error out by default if such changes exist, making it safer than the current two-step workflow. He also suggested an `--autostash` option (similar to `git rebase`) to preserve uncommitted changes, with a possible interface like `git pull --reset [--discard-changes | --autostash]`. This shifts the debate from *whether* the feature belongs in `git pull` to *how* it could be made safe enough to include.
