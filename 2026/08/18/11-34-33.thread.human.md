This thread is about a proposed `--hard` (now `--reset`) option for `git pull` that would discard local changes and reset the working tree to match a fetched upstream branch, targeting the specific use case where the upstream branch has been force-pushed or rebased. The original patch by Artur Bieniek sparked a design debate, with Junio C Hamano, the maintainer, firmly opposing the feature on philosophical grounds: he argues that `git pull` should focus on history integration, not working-copy management, and that force-pushed or rebased upstream branches should require explicit user intervention rather than being automated.

The discussion has since shifted toward a safer redesign proposed by Phillip Wood: `git pull --reset [--discard-changes | --autostash]`, which would error out by default if uncommitted changes exist, with an `--autostash` option to preserve them. Artur now endorses this redesign, emphasizing its practical utility for syncing to force-pushed or rebased upstream branches—a gap that `git pull --ff-only` cannot address. However, Junio has not yet responded to the redesign or to Artur’s latest clarification of the use case. Kristoffer Haugsbakk suggested an alternative workflow (working directly with remote-tracking branches like `origin/main`), which Artur countered by noting that while `git fetch` updates the remote-tracking branch, it does not update the working tree, leaving the user at the old commit. Artur also floated a new idea: `git reset --pull --hard`, which would move the destructive operation to `git reset` while adding network I/O, but it remains unclear whether this would be more acceptable to Junio.

The thread is still under review, with no updated patch posted. The key open question is whether Junio will accept the `--reset` redesign or refine his objections further. Beyond Junio’s principled opposition, Phillip’s constructive counterproposal, and Artur’s evolving arguments, no other substantive feedback has emerged. The discussion remains conceptual, focusing on design philosophy and workflow gaps rather than technical implementation.
