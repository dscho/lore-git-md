The `git pull --hard` thread has evolved from a simple patch proposal into a design discussion about whether—and how—to add a convenient way to discard local state and sync to upstream in one command. Artur Bieniek initially proposed `git pull --hard`, which would reset the branch, index, and working tree to the fetched branch using `git reset --hard`. Junio C Hamano rejected the underlying motivation, arguing that `git pull` should focus on history integration, not working-copy management, and that users should discard local state explicitly with separate commands.

The discussion shifted toward a safer redesign proposed by Phillip Wood: `git pull --reset [--discard-changes | --autostash]`. This version would error out by default if uncommitted changes exist, with `--autostash` as an opt-in to preserve them. Artur has now endorsed this redesign, citing a concrete use case that Junio’s preferred `git pull --ff-only` cannot handle: syncing to an upstream branch that has been force-pushed or rebased. In this scenario, a user with a clean checkout of the upstream branch cannot use `--ff-only` to sync to the rewritten history, but `--reset` would allow it while still protecting uncommitted changes by default. This argument reframes the feature as addressing a genuine workflow gap rather than just a convenience.

The thread is now focused on whether this use case justifies the feature’s inclusion. No updated patch has been posted, and Junio has not yet responded to Artur’s latest argument. The feature’s fate remains uncertain, but the discussion is now grounded in a specific, motivated example.
