This is the fourth and final patch in Kristoffer Haugsbakk’s four-patch series adding `--abbrev`, `--color`, and `--date` formatting options to `git format-rev`. The patch implements the new options by reusing existing `git log` logic, but the author now acknowledges a missing cleanup step in the `--date` callback: the `parse_date_format()` function may allocate a custom format string that requires later release via `date_mode_release()`, which is currently not called.

The issue was raised in the thread by the author themselves, who noticed the omission while reviewing the documentation for `parse_date_format()`. This is a subtle but important correctness fix—without it, the code leaks memory when a custom date format is specified. The patch otherwise remains uncontroversial, with Junio C Hamano’s earlier feedback on defensive code ordering already addressed in the v2 preparation. The series is still under review, and this fix will likely be incorporated into the next revision.

The patch touches `builtin/name-rev.c`, updates the man page, and adds test coverage in `t/t6120-describe.sh`. The new options (`--abbrev`, `--color`, `--date`) are designed to match `git log`’s behavior, including error handling for invalid values. The synopsis simplification (highlighting mandatory options) and the reuse of `rev_info` and `pretty.c` logic remain unchanged. The missing cleanup is the only technical loose end, and its resolution should be straightforward. No other objections or merge status updates have been reported.
