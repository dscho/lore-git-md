This is a feature patch series adding `--abbrev`, `--color`, and `--date` options to `git format-rev`, bringing it closer to `git log`'s formatting flexibility. The series is now in its second iteration (v2), addressing review feedback from Junio C Hamano and fixing a memory leak in the `--date` callback.

The v2 series expands to five patches. Patches 1 and 3–4 remain largely unchanged from v1: patch 1 cleans up option descriptions, patch 3 refactors option variables into a struct, and patch 4 extracts `--date` alternatives documentation into a shared file. The new patch 2/5 ("place BUG calls first in callback") is a preparatory refactoring that moves `BUG_ON_OPT_NEG(unset)` assertions to the start of callback functions, ensuring they trigger before any dereference of `option->value`. This defensive programming fix was suggested by Junio in the v1 review and is now applied consistently across all callbacks. Patch 5/5 implements the three new options, reusing existing `git log` logic (`rev_info` struct and `pretty.c` date formatting), and includes the memory leak fix for `--date` by calling `date_mode_release()` after `parse_date_format()`.

The implementation touches `builtin/name-rev.c`, adds a new documentation file (`rev-list-option-date-alternatives.adoc`), and expands test coverage in `t/t6120-describe.sh`. The test suite now verifies that the new options behave identically to their `git log` counterparts, including edge cases like `--date="format:%c"` (which allocates a custom format string) and `--date` with no argument. The series is uncontroversial and appears well-scoped, leveraging existing Git infrastructure rather than introducing new logic. The v2 changes address all known issues from the v1 review, and the author has added thorough test coverage for the memory leak fix. This looks like a solid, incremental improvement to `git format-rev`'s usability.
