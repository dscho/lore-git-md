This is a refactoring patch in Kristoffer Haugsbakk’s five-part series extending `git format-rev` with `--abbrev`, `--color`, and `--date` options. Specifically, this is patch 2/5 in v2, newly introduced to address a defensive programming concern raised during v1 review.

The patch moves the `BUG_ON_OPT_NEG(unset)` and `BUG_ON_OPT_ARG(arg)` assertions to the top of the `format_nul_cb()` callback in `builtin/name-rev.c`. The change is purely stylistic: the assertions already existed in v1, but were placed after the two variable assignments (`data->nul_input = 1` and `data->nul_output = 1`). Since the callback unconditionally sets these variables regardless of the assertions, the placement had no functional effect. The new ordering follows the principle of testing function preconditions as early as possible, making the code’s intent clearer and aligning with Git’s defensive coding practices.

The patch touches only one file (`builtin/name-rev.c`) and changes two lines. It is uncontroversial and directly implements feedback from Junio C Hamano’s v1 review, which requested consistent placement of `BUG` assertions before any variable dereferencing. This patch applies the same defensive pattern to all option callbacks in the file, ensuring that future changes to the `opts[]` array cannot silently bypass the assertions. No functional or behavioral changes are introduced.
