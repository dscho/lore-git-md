This is the sixth patch in the v4 series adding path-related keys to `git repo info`. The author, K Jayatheerth, responds to Lucas Seiki Oshiro’s design objection that `path.git-prefix` represents "current directory information" rather than "repository information" and thus does not belong in `git repo info`. Jayatheerth acknowledges the conceptual distinction but argues that the key is useful for scripts and already exposed by `git rev-parse --show-prefix`, suggesting it fits the series’ purpose. He offers to drop the patch if reviewers prefer, leaving the decision to the broader community.

The exchange does not resolve the objection but clarifies the author’s position: the patch is included for scriptability and consistency with existing Git tooling, not because it is inherently repository metadata. The tone is collaborative, and the author’s willingness to defer to reviewer consensus keeps the discussion open. This reply does not advance the technical implementation but shifts the focus to whether the key’s inclusion aligns with the command’s intended scope. Future discussion will likely hinge on this design question rather than the patch’s code.
