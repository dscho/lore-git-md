This is a **security feature patch** that adds `http.sslVerifyStatus`, a new configuration option to enable OCSP staple validation for HTTPS connections. The patch is technically complete and ready for `next`; this email is the author’s response to Junio C Hamano’s final request for a clearer, more user-centric rephrasing of the documentation.

The author acknowledges Junio’s feedback and agrees to simplify the `Documentation/config/http.adoc` entry, replacing technical jargon ("fail-closed", "OCSP stapling") with plain-language phrasing that focuses on the user-facing outcome: refusing connections to servers with revoked certificates. The commit message will retain the edge-case details about older libcurl and GnuTLS versions for technical accuracy, while the documentation will prioritize clarity for end users. This is a minor, surface-level tweak and does not affect the patch’s implementation or security guarantees.

The feature itself addresses a real gap: Git’s HTTPS certificate verification currently ignores OCSP staples, which means revoked certificates can still be accepted. This is particularly relevant for government and FIPS-compliant deployments (e.g., US DoD PKI) that mandate stapling. The patch defaults to `false` for compatibility but provides a fail-closed mechanism when enabled, ensuring revoked certificates are rejected.
