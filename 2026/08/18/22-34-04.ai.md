This is a two-patch bugfix series addressing a race condition in Git's geometric repacking mechanism that can cause objects to be incorrectly reported as missing, even when they are present. The issue arises when a multi-pack-index (MIDX) references a packfile that is subsequently removed by a geometric repack, leaving processes that opened the old MIDX unable to locate objects. The problem is exacerbated in `git replay`, where missing objects trigger a SIGSEGV instead of a graceful error.

The series first fixes the `git replay` crash (patch 1/2) by making it fail gracefully when a merge input is unreadable. Patch 2/2 tackles the root cause: it modifies the packed-object backend to recover when a MIDX references a removed packfile, ensuring object lookups can still succeed. The fix touches `odb/source-packed.c` and adds tests for both scenarios.

The issue is rare but affects multiple server-side operations, including `git merge-tree`, `git diff`, `git rev-list`, and object resolution commands like `rev-parse` and `cat-file`. The commit message provides a clear table of affected commands and symptoms, and the series is well-motivated by production evidence. The patches are small, focused, and include thorough test coverage, suggesting a high-quality fix. This is likely to be uncontroversial and should be a priority for merging.
