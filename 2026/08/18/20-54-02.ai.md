This is a substantive review of Karthik Nayak’s `report` hook patch for `git-receive-pack`. Junio C Hamano raises several design questions about how the hook’s exit status interacts with the status report it produces, pointing out potential ambiguity in what the client sees when the hook rewrites the report but exits non-zero.

The review centers on three scenarios: (1) the hook rewrites some `ok` lines to `ng` but exits 0, (2) the hook rewrites all lines to `ng` and exits 0, and (3) the hook rewrites the report but exits non-zero. Junio observes that the current implementation discards the hook’s stdout entirely if the hook exits non-zero, so the client sees only a generic failure rather than the rewritten report. This behavior is not clearly documented in the patch and could surprise administrators who expect the rewritten report to be honored regardless of exit status.

The discussion touches the files `builtin/receive-pack.c` and `Documentation/githooks.adoc`, and the key names `run_report_hook`, `report`, and `report_v2`. The likely point of contention is whether the exit status should override the rewritten report or whether the two signals should be kept orthogonal. No alternative implementation is suggested, but the review implies that the current design may need to be tightened or at least documented more precisely.
