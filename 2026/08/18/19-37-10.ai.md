This is the **v5 iteration of a security feature patch** introducing `http.sslVerifyStatus`, a boolean config option (default `false`) that enables OCSP staple validation via libcurl’s `CURLOPT_SSL_VERIFYSTATUS`. The patch addresses a long-standing gap where Git ignores stapled OCSP responses, leaving OpenSSL-linked binaries (common in FIPS-compliant deployments) vulnerable to accepting revoked certificates. This version incorporates all prior feedback: it updates the commit message to clarify the default behavior, improves documentation to reflect recent libcurl backend parity (OpenSSL/GnuTLS), and enhances error messages with libcurl’s error strings for better diagnostics.

The core change remains unchanged: when `http.sslVerifyStatus` is enabled, Git fails connections if the server does not provide a valid OCSP staple, closing a security hole where stolen private keys could be used to impersonate servers. The default (`false`) preserves compatibility with remotes that do not support stapling, while per-URL overrides (e.g., `http.https://example.com/.sslVerifyStatus`) allow targeted enforcement. The patch touches `http.c`, `Documentation/config/http.adoc`, and `t/t5551-http-fetch-smart.sh`, where four new tests verify the fail-closed behavior, per-URL scoping, and edge cases. The `SSL_VERIFYSTATUS` lazy prerequisite now uses `test_might_fail` to handle expected failures gracefully.

Key improvements since v4:
- **Commit message**: Removed misleading phrasing ("Leaving the default to libcurl is not an option") and explicitly stated that the patch only enables `CURLOPT_SSL_VERIFYSTATUS` when the config is set to `true`.
- **Documentation**: Added a note about the fail-closed nature of the feature and clarified that recent libcurl versions (>= 8.10) unify OpenSSL/GnuTLS behavior, addressing Patrick Steinhardt’s request for backend-specific accuracy.
- **Error handling**: Now includes the libcurl error string (`curl_easy_strerror()`) in failure messages, distinguishing missing features (`CURLE_NOT_BUILT_IN`) from other errors.
- **Test robustness**: The `SSL_VERIFYSTATUS` prerequisite properly checks for stapling support without silently passing on unsupported servers.

The patch is **technically complete** and addresses all prior review feedback. Junio C Hamano previously accepted v4 as ready for integration, and this version resolves the remaining documentation and error-message concerns raised by Patrick Steinhardt. The only deferred item is the positive test case (valid OCSP staple validation), which the author prototyped but left out due to complexity; Junio and Patrick have not insisted on its inclusion. The long-term question of whether to flip the default to `true` or warn users about ignored staples remains open but does not block merging.

This is a **well-motivated security feature** with clear real-world impact: government and FIPS-compliant deployments (e.g., US DoD PKI) mandate OCSP stapling, and Git’s current behavior creates a security gap where revoked certificates are accepted. The design is conservative (default `false`, fail-closed) and the implementation is minimal, touching only the HTTP subsystem. The patch is now **ready for `next`** and eventual graduation to `master`.
