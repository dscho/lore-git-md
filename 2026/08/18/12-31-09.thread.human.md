This thread is an RFC from Kristofer Karlsson proposing a significant performance optimization for Git’s connectivity check, which currently scales with the entire repository size rather than just the incoming changes. The proposal targets large repositories with frequent pushes, where the existing `rev-list`-based implementation (`check_connected()`) introduces unnecessary overhead.

Kristofer outlines a two-part approach: first, an "opportunistic trusted-tree discovery" that lazily verifies only changed entries by comparing subtrees against trusted parents, and second, a bounded walk to find the boundary without traversing all refs (`--not --all`). Preliminary benchmarks on a 3 M-commit, 200 K-ref repository show 30–150× speed-ups for small pushes (e.g., 30 ms vs. 1 s for 5 commits). The proposal preserves correctness by falling back to the current implementation for edge cases like shallow clones or promisor remotes.

The RFC frames this as a logical extension of prior work, including Patrick Steinhardt’s 2021 quarantine-dir series and Justin Tobler’s 2025 `--skip-connectivity-check` option. It’s currently seeking feedback on whether the problem is worth solving and if the direction is sound—no patches have been posted yet. Key participants so far are Kristofer (author) and the broader list audience, with no substantive reviews or objections recorded yet. The thread remains open for discussion on design and feasibility.
