This is the third and final patch in D. Ben Knoble’s three-part series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The series is cooking in `next` under the topic `dk/use-nsec-runtime`.

The patch replaces the `#ifdef USE_NSEC` preprocessor checks with runtime logic that consults the new `core.useNanosec` configuration key, defaulting to false. On platforms where `NO_NSEC` is defined (meaning the system lacks nanosecond support), the `use_nanosec` field and all related code paths are `#ifdef`-ed out, ensuring backward compatibility and preventing silent corruption when `core.useNanosec=true` is set on an unsupported platform. This directly addresses Junio C Hamano’s concern about undefined behavior in cross-platform scenarios.

The change touches ten files, including `read-cache.c` (where the racy Git logic lives), `environment.c` (where the config key is parsed), and `Documentation/config/core.adoc` (where the new option is documented). The documentation now lists filesystems known to support nanosecond precision (ext2, ext4, XFS, CEPH, CIFS, NTFS, UFS, FUSE, FAT) and clarifies that the option is only effective when Git was compiled to store nanosecond timestamps.

Performance is preserved by caching the `core.useNanosec` value in the repository’s `repo_config_values` struct, avoiding the ~41× slowdown that appeared in the v1 implementation. The commit message retains the `Best-viewed-with: --ignore-space-change` hint to help reviewers navigate the preprocessor-to-runtime conversion.

This patch is technically complete and addresses all known correctness and performance concerns. The only remaining open question is architectural: whether to cache the value in `repo_config_values` (modern but limited to `the_repository`), `repo_settings` (supports per-repository variation), or a global variable. The author has framed this as a request for comments rather than a blocker, and the patch is otherwise ready for integration.
