This is the first patch in a seven-patch refactoring series targeting the object database (ODB) subsystem, authored by Patrick Steinhardt. The patch updates the documentation and function signature of `odb_source_read_object_info()` to formally distinguish between two error conditions: objects that are missing from a source (positive return value) and objects that are corrupt (negative return value). Currently, only the packed backend makes this distinction; the other backends (loose, in-memory, files) return a generic negative error code for both cases.

The change is preparatory: it does not alter any behavior yet, but it establishes the contract that subsequent patches will enforce across all ODB backends. The patch touches only `odb/source.h`, updating the callback documentation and the inline wrapper’s return-value comment. No code logic is modified, and no tests are added at this stage.

This is a clean, mechanical step in the ongoing ODB abstraction effort. The motivation is clear—consistent error handling is necessary for the ODB layer to decide whether to try another source when one fails—and the patch itself is narrowly scoped to the header file. The real work of propagating the new semantics through the backends will follow in later patches.
