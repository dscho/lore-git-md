This is a v2 of Kristoffer Haugsbakk’s five-patch series adding `--abbrev`, `--color`, and `--date` formatting options to `git format-rev`. The series is now split into two preparatory refactoring patches (1–2), a documentation extraction patch (3), and the main feature patch (5), with the memory-leak fix and defensive BUG placement incorporated.

Patch 1/5 is unchanged from v1: a cosmetic documentation tweak converting option descriptions in `builtin/name-rev.c` from mixed case (“Use NUL...”) to lowercase (“use NUL...”). Patch 2/5 is new in v2: it moves all `BUG_ON_OPT_NEG(unset)` assertions to the top of the option callbacks in `builtin/name-rev.c` to ensure they trigger before any dereference of `option->value`. This defensive pattern was agreed in v1 review and is now applied consistently to both existing and new callbacks.

Patch 3/5 (formerly 2/4 in v1) groups the command’s option variables into a `struct format_rev_data` and switches to designated initializers (C99) for clarity. Junio C Hamano’s v1 feedback on this patch has been incorporated: the positional initializer is replaced with a designated one, and the BUG placement fix is now handled by the new patch 2/5. Patch 4/5 (formerly 3/4) extracts the `--date` alternatives documentation from `rev-list-options.adoc` into a new standalone file (`rev-list-option-date-alternatives.adoc`) so it can be included by both `git-rev-list` and `git-format-rev`.

Patch 5/5 (formerly 4/4) implements the three new options by reusing `git log`’s existing logic (`rev_info` struct and `pretty.c` date formatting). The v2 interdiff shows two key fixes: (1) the missing `date_mode_release()` call is added to free any custom date format string allocated by `parse_date_format()`, plugging the memory leak identified after v1, and (2) the test suite is expanded to verify `--date` with a custom format (`--date="format:%c"`) and the no-argument case (`--date` alone). The tests now also normalize option ordering in the comparison functions to avoid false negatives.

The series touches `builtin/name-rev.c`, `Documentation/git-format-rev.adoc`, `Documentation/rev-list-option-date-alternatives.adoc`, and `t/t6120-describe.sh`. No on-disk format changes are introduced. The new options (`--abbrev`, `--color`, `--date`) behave identically to their `git log` counterparts, including error handling for invalid values (e.g., `--color=not-valid`). The synopsis in the man page is simplified to highlight the two mandatory options (`--stdin-mode` and `--format`), with the rest grouped under `[<options>]`.

The series is uncontroversial and addresses all v1 feedback. Junio’s suggestions (designated initializers, defensive BUG placement) have been accepted and incorporated. The memory leak fix and expanded test coverage further strengthen the patch. No objections have been raised to the UI design (e.g., supporting the same `--date` alternatives as `git log`), and the series is not yet queued in any integration branch.
