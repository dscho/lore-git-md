This is the final patch in Patrick Steinhardt’s seven-part refactoring series targeting the object database (ODB) subsystem. It completes the work begun in earlier patches by making the handling of `OBJECT_INFO_DIE_IF_CORRUPT` fully generic and backend-agnostic.

The patch removes the last vestiges of abstraction-breaking code: the `has_packed_and_bad()` function, which reached into packed-source internals to check for corrupt objects, is deleted, and the loose backend’s direct `die()` call is eliminated. Instead, `do_oid_object_info_extended()` now uses the infrastructure introduced in patches 1–6: it distinguishes missing objects (positive return) from corrupt ones (negative return) and propagates backend-generated error messages. When `OBJECT_INFO_DIE_IF_CORRUPT` is set, the process dies with the backend’s own message (e.g., “packed object X (stored in Y) is corrupt”) rather than reconstructing it later.

The change is mechanical but consequential: it ensures consistent behavior across all ODB backends (packed, loose, in-memory, files) and future-proofs the code against new backends. The test added in `t1060-object-corruption.sh` verifies that a corrupt loose object in one repository can still be read from an alternate, confirming that the loose backend no longer dies prematurely.

This patch is a clean, well-motivated refactoring that aligns with the series’ goal of making the ODB layer more modular. It should interest contributors working on low-level storage or refactoring, though it introduces no user-facing changes. The series as a whole looks technically sound and is part of Patrick’s ongoing ODB abstraction effort.
