This is the fourth patch in Patrick Steinhardt’s seven-patch series refactoring how the object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The series is part of the ongoing ODB abstraction effort.

This patch updates the loose-object backend (`odb/source-loose.c`) to distinguish between missing and corrupt objects, aligning it with the new calling convention established in patch 1. Previously, the loose backend returned a negative value for both missing and corrupt objects, making it impossible for callers to tell them apart. Now, it returns a positive value (1) for missing objects and a negative value for corrupt ones. The change also removes the separate `corrupt:` label, consolidating error handling into a single exit path.

The patch touches only `odb/source-loose.c` and is mechanical: it updates return values, adjusts error-handling logic, and removes redundant code paths. One `die()` call for invalid object types remains unchanged because converting it would break many tests, but the commit message notes this as a potential future improvement. The changes are confined to internal ODB logic and do not affect user-facing behavior.

This patch is a straightforward adaptation of the loose backend to the new ODB contract. It looks well-executed and necessary for the series’ goal of consistent, backend-agnostic error handling. The only loose end is the deferred cleanup of the `die()` call, but that does not block the current refactoring. No new tests are added here, but the series’ earlier patches updated `t1060-object-corruption.sh` and unit tests to cover the new behavior.
