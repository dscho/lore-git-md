This is a refactoring and correctness patch series targeting the object database (ODB) subsystem, specifically the handling of corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The series is authored by Patrick Steinhardt and consists of seven patches.

The goal is to make the handling of corrupt objects consistent and backend-agnostic. Currently, the flag is handled in two inconsistent ways: `do_oid_object_info_extended()` checks for corrupt objects in packfiles by reaching into the packed source's internals, breaking abstraction, while the loose source handles the flag directly, causing the process to die even if another source has a good copy. This series addresses these issues by extending the semantics of `odb_source_read_object_info()` to distinguish between missing and corrupt objects and to return error messages to the caller.

Key changes include modifying `odb_source_read_object_info()` to return a positive value for missing objects, updating backend-specific implementations (in-memory, packed, loose, and files) to signal corrupt objects appropriately, and handling `OBJECT_INFO_DIE_IF_CORRUPT` generically in the ODB layer. The series touches 14 files, including core ODB logic, backend implementations, and related utilities like `pack-objects.c` and `midx.c`.

The patches appear well-motivated and technically sound, with clear explanations in the cover letter. The changes are mechanical but non-trivial, as they involve refactoring how error conditions are propagated across the ODB layer. The series includes updates to tests (`t1060-object-corruption.sh` and `t/unit-tests/u-odb-inmemory.c`) to verify the new behavior, which is a positive sign of thoroughness.

This is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, which aims to make Git's object storage layer more modular and backend-agnostic. The series is likely to be of interest to contributors working on low-level storage, refactoring, or backend-specific optimizations. The changes are confined to the ODB subsystem, so they should not directly affect user-facing behavior, but they lay groundwork for future backend improvements.

Files modified include `odb.c`, `odb/source-*.c`, `packfile.c`, `midx.c`, and related headers, as well as test files. Key functions touched include `odb_source_read_object_info()`, `read_object_info_from_path()`, and `do_oid_object_info_extended()`. The series introduces no new user-facing options or commands.
