This thread is a seven-patch series from Patrick Steinhardt refactoring how Git’s object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The goal is to make error handling consistent and backend-agnostic: currently, the packed and loose backends treat corrupt objects differently, and the packed backend even reaches into internals to check corruption, breaking abstraction. The series introduces a clear contract where `odb_source_read_object_info()` returns a positive value for missing objects and a negative value for corrupt ones, letting callers decide how to handle errors.

The first three patches laid the groundwork: patch 1 formalized the new calling convention, patch 2 updated the in-memory backend, and patch 3 fixed the packed backend to correctly report corrupt objects (previously misreported as missing). This fourth patch updates the loose backend to align with the new contract, removing ambiguity in its return values. The changes are mechanical and confined to internal ODB logic, with no user-facing impact. The series is under review, with no replies or objections yet, and is part of Patrick’s larger ODB abstraction effort. The only loose end is a deferred cleanup of a `die()` call in the loose backend, but that doesn’t block the current work. Test coverage was updated in earlier patches.
