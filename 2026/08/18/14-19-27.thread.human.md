This thread is about Patrick Steinhardt’s seven-patch series refactoring how Git’s object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is set. The goal is to make error reporting consistent across backends and remove abstraction-breaking code that reconstructs error messages after the fact. The series is now at v2, which fully addresses Junio C Hamano’s earlier feedback on the return convention by introducing an `enum odb_read_status` with negative error codes.

The current version is under review and complete. Junio’s design concerns have been resolved, and the series now propagates backend-specific error messages to the ODB layer, removing the need for the `has_packed_and_bad()` function. However, Junio has since identified a latent correctness issue: if a corrupt pack contains duplicate objects, the error-reporting mechanism cannot distinguish which copy was corrupt. This edge case remains unresolved but is not considered blocking.

Karthik Nayak’s recent review adds a focused technical suggestion to the second patch, recommending that functions explicitly return the named enum values (`ODB_READ_OK`, `ODB_READ_ERROR`) rather than raw integers. This would improve code clarity and safety, especially as the series later introduces a third enum value (`ODB_READ_NOT_FOUND`). The feedback is constructive and narrowly scoped to code hygiene, without challenging the patch’s overall design or correctness. No other substantive reviews have been posted yet.
