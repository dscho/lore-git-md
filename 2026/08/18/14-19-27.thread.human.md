This thread is a patch series from Patrick Steinhardt refining how Git’s object database (ODB) handles corrupt and missing objects. The series, now at v2, focuses on making error reporting consistent and backend-agnostic when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The key change in this version is the formalization of a tri-state return convention using an `enum odb_read_status` with negative error codes (`ODB_READ_ERROR = -1` for corruption, `ODB_READ_NOT_FOUND = -2` for missing objects), addressing Junio C Hamano’s feedback from v1.

The latest email covers the third patch, which mechanically updates all ODB backends to return `ODB_READ_NOT_FOUND` for missing objects, separating this case from corruption errors. This is a preparatory step—no user-visible behavior changes yet—but it lays the groundwork for later patches that will make the ODB layer itself distinguish between the two conditions. Junio’s earlier concern about the granularity of the `bad_pack` logic in multi-pack scenarios remains unresolved, though Patrick clarified that the series does not mark entire packs as bad, only individual objects. The series is under active review, with no merge status reported, and is part of Patrick’s broader effort to refactor Git’s ODB subsystem for modularity.
