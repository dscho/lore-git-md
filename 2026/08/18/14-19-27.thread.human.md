This thread is about Patrick Steinhardt’s seven-patch series refactoring how Git’s object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The goal is to make error reporting consistent and backend-agnostic, ensuring that corrupt objects are reported the same way regardless of whether they come from loose files, packs, or the multi-pack index. The series is now in its second version, addressing Junio C Hamano’s earlier feedback on return conventions and error message propagation.

The key changes in v2 formalize the return status of `odb_source_read_object_info()` using an `enum odb_read_status` with negative error codes, introduce an `errmsg` parameter to carry backend-specific error messages, and remove the abstraction-breaking `has_packed_and_bad()` function. The series touches core ODB files (`odb.c`, `odb/source-*.c`), the packfile and MIDX subsystems, and test files, but doesn’t change the on-disk format or add new user-facing commands.

Junio’s latest review raises a new edge case: the current design assumes each object appears at most once per pack, but if a corrupt pack contains duplicate objects, the error message won’t distinguish which copy was corrupt. This is a latent correctness issue, though not one that blocks the current refactoring. The broader question about whether object-level granularity is sufficient for multi-pack scenarios remains open, but the series itself is otherwise complete and under review. No merge status has been reported.
