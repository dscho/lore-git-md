This thread is about Patrick Steinhardt’s seven-patch series refactoring how Git’s object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is set. The goal is to make error reporting consistent across backends and remove abstraction-breaking code. The series is now in its second version, addressing Junio C Hamano’s feedback on return conventions and error message propagation.

The key change is formalizing the return status of `odb_source_read_object_info()` with an `enum odb_read_status` (OK, error, not found) and introducing an `errmsg` parameter to propagate backend-specific error messages. The final patch removes the `has_packed_and_bad()` function, making `OBJECT_INFO_DIE_IF_CORRUPT` fully generic. Karthik Nayak and Junio have reviewed the series, with Karthik recently clarifying a documentation nit in patch 3/7: the commit message’s phrasing about error prioritization was misleading, as the design actually prefers *any* error (including corruption) over "not found" errors, and only prioritizes the packed backend’s error when both backends report non-"not found" failures. This has been acknowledged but not yet addressed in the commit message.

The series touches multiple ODB backends (packed, loose, files) and related subsystems like MIDX and pack-objects, with updated test coverage. Two open questions remain: a latent correctness issue Junio identified around duplicate objects in corrupt packs, and a stylistic disagreement between Karthik and Patrick over whether to return named enum constants or raw integers. The series is still under review, with no merge status reported.
