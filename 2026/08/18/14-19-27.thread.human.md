This thread is a seven-patch series from Patrick Steinhardt refactoring how Git’s object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The goal is to make error reporting consistent and backend-agnostic by ensuring corrupt objects are detected and reported by the backend that encountered the failure, rather than reconstructing error messages after the fact in the ODB layer.

The series is now complete with the final patch, which removes the last abstraction-breaking code—specifically, the `has_packed_and_bad()` function—and makes `OBJECT_INFO_DIE_IF_CORRUPT` fully generic. The ODB layer now relies on backend-provided error messages (e.g., "packed object X (stored in Y) is corrupt") and dies with the first available message when the flag is set. The loose backend no longer prematurely dies if another source has a good copy, improving robustness. The patch also adds a test case to verify this behavior.

The changes are internal to the ODB subsystem, touching `odb.c`, `odb/source-loose.c`, `packfile.c`, and related headers, with no user-facing impact or on-disk format changes. The series is part of Patrick’s broader ODB abstraction effort, which aims to make Git’s object storage more modular. No reviews have been posted yet, but the refactoring is well-motivated and unlikely to be controversial. The next step will be community review, with Junio’s eventual integration decision determining whether the series graduates to `next` or requires further iteration.
