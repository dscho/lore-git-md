This thread is a v2 patch series from Patrick Steinhardt that refactors Git’s object database (ODB) subsystem to handle corrupt objects consistently when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The series introduces a tri-state return convention (`ODB_READ_OK`, `ODB_READ_ERROR`, `ODB_READ_NOT_FOUND`) to distinguish between missing and corrupt objects, propagates backend-specific error messages to the ODB layer, and removes abstraction-breaking code that reconstructed error messages after the fact.

The v2 series is now complete and under review, with Junio C Hamano’s design concerns about the return convention fully addressed. The key unresolved technical discussion centers on the error-propagation logic in the files backend, where Karthik Nayak questioned whether the current prioritization of errors (corruption over "not found") was intentional. Patrick has now clarified the policy in detail: corruption errors are never masked by "not found" errors, and the packed backend’s corruption takes precedence when both backends fail. This explanation resolves the ambiguity, though the commit message could have been clearer upfront. A separate, unresolved stylistic debate remains over whether to return named enum constants (`ODB_READ_OK`) or raw integers (`0`), with Patrick preferring the latter for brevity.

Junio also identified a latent correctness issue—if a corrupt pack contains duplicate objects, the error-reporting mechanism cannot distinguish which copy was corrupt—but this remains unaddressed. The series touches multiple ODB backends (`odb/source-*.c`), removes the `has_packed_and_bad()` function, and adds test coverage for reading corrupted loose objects from alternates. No merge status has been reported, and the series is part of Patrick’s broader ODB abstraction effort.
