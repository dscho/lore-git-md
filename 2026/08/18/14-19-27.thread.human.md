This thread is a patch series from Patrick Steinhardt refactoring how Git’s object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The goal is to make error reporting consistent and backend-agnostic, ensuring corrupt objects are reported the same way regardless of which ODB backend (loose, packed, or files) encounters the failure.

The series is now in its second version (v2), addressing all of Junio C Hamano’s design concerns from the initial submission. The key changes include formalizing a tri-state return convention using an `enum odb_read_status` with negative error codes for all failure conditions, introducing an `errmsg` parameter to propagate backend-specific error messages, and removing abstraction-breaking code like `has_packed_and_bad()`. The final patch (5/5 in this version) completes the refactoring by making `OBJECT_INFO_DIE_IF_CORRUPT` fully generic: it now tracks corruption status and accumulates error messages from all backends, dying with the first available message when the flag is set. The loose backend’s direct `die()` call was also removed, allowing alternates to provide a good copy of a corrupted object.

The series touches core ODB internals (`odb.c`, `odb/source-*.c`, `packfile.c`, `midx.c`) and includes updated test coverage (`t1060-object-corruption.sh`, unit tests). No user-facing changes or on-disk format modifications are introduced. The only remaining open question is Junio’s broader concern about whether the current object-level granularity for tracking corrupt objects is sufficient for multi-pack scenarios, though this doesn’t block the series from moving forward. Patrick has addressed all prior feedback, and the refactoring is now ready for integration.
