This thread is a patch series from Patrick Steinhardt refactoring how Git’s object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is set. The goal is to make error reporting consistent across backends and remove abstraction-breaking code. The series is now at v2, addressing Junio C Hamano’s feedback on return conventions and error propagation.

The key changes introduce an `enum odb_read_status` to formalize return values, propagate backend-specific error messages, and eliminate the `has_packed_and_bad()` function. Junio’s earlier concerns about the tri-state return convention and the granularity of the `bad_pack` logic have been addressed, though he later identified a latent correctness issue: if a corrupt pack contains duplicate objects, the error-reporting mechanism can’t distinguish which copy was corrupt. Karthik Nayak has raised code hygiene concerns in patches 2/7 and 3/7, suggesting the use of named enum constants for clarity and questioning the error-propagation logic in the files backend. Patrick has not yet responded to these points.

The series touches multiple ODB backends and related files, with no changes to user-facing commands or on-disk formats. Testing has been updated to verify the new behavior. The only remaining open questions are the error-propagation logic in the files backend and the unresolved edge case around duplicate objects in corrupt packs. The series remains under review, with no merge status reported.
