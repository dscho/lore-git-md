This thread introduces a new `report` hook for `git-receive-pack`, allowing server administrators to filter or modify the status report sent to clients after ref updates. The patch, authored by Karthik Nayak, is motivated by GitLab’s need to implement MVCC (multi-version concurrency control), where the status report must reflect the repository state post-update but pre-client confirmation.

The core design—whether a non-zero hook exit should discard its stdout—has been resolved in favor of treating it as a "nuclear option" that kills `receive-pack` entirely, ensuring clients never receive malformed output. This aligns with Patrick Steinhardt’s arguments and Karthik’s acceptance. Junio C Hamano remains concerned about the surprising interaction between exit status and stdout, but no alternative implementation has been proposed. Documentation updates (to `githooks.adoc` and `git-receive-pack(1)`) and minor test adjustments (e.g., verifying "remote:" prefixes on stderr) are planned but not yet posted. The unresolved `pkt-line` format documentation remains a loose end.

Karthik has addressed most review feedback, including Kristoffer Haugsbakk’s suggestion to document the hook in both `git-receive-pack(1)` and `githooks(5)`. Patrick’s substantive reviews clarified the hook’s necessity and tightened its semantics, while Kristoffer’s feedback focused on documentation clarity. The patch is under review with no further changes expected to the core implementation.
