This thread introduces a new `receive-report` hook for `git-receive-pack`, allowing server administrators to intercept and modify the status report sent to clients after ref updates. The feature, authored by Karthik Nayak, is motivated by GitLab’s need to implement multi-version concurrency control (MVCC) on the server side, where the status report must reflect the repository state post-update but pre-client confirmation.

The series is now complete and queued in Junio C Hamano’s `seen` branch, ready for integration into `next`. All prior feedback has been addressed, including objections to the hook’s name (now `receive-report`) and exit status semantics (aligned with the `pre-receive` hook). The implementation is split into three patches: a documentation update, a refactoring to centralize status-report generation, and the core hook logic. The hook runs after ref updates are committed, receives the pkt-line encoded report on stdin, and replaces it with its stdout, while forwarding stderr to the client via sideband. Non-zero exit codes rewrite all ref status lines to indicate hook failure, ensuring consistency with existing hooks.

Key participants include Junio C Hamano, who endorsed the exit status proposal and resolved a conflict with Justin Tobler’s concurrent "pluggable writes" series, and Patrick Steinhardt, whose review shaped the hook’s design. The series is technically complete, with comprehensive test coverage and documentation, and awaits graduation to `next`. No open questions remain.
