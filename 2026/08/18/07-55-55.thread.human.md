This thread is about a new `report` hook for `git receive-pack`, allowing server administrators to filter or modify the status report sent to clients after ref updates. The patch, now at v2, was authored by Karthik Nayak to support GitLab’s MVCC system, where the status report must reflect the repository state after all ref updates are committed but before the client receives confirmation.

The key design decision—whether the hook should use Git’s config-based hook infrastructure or remain a single-script hook like `proc-receive`—has been resolved in favor of the single-script approach, with the rationale documented in the commit message. However, the exit status semantics remain contested. The current implementation treats a non-zero hook exit as a "nuclear option," discarding stdout and causing `receive-pack` to die, which Junio C Hamano and Patrick Steinhardt argue is surprising and unhelpful to clients. Both now endorse Patrick’s proposal to align the behavior with the `pre-receive` hook: rewriting all ref status lines to `"report hook failed"` and allowing `receive-pack` to exit cleanly. Karthik has acknowledged the proposal but noted that restructuring the output logic would be "awkward." Junio’s latest reply signals that the current behavior is unlikely to be accepted, leaving this the primary blocker for the patch.

Other feedback has been addressed: documentation is complete, tests cover passthrough and failure modes, and minor stylistic points have been resolved. The thread is now focused on finalizing the exit status semantics, with no further changes expected to the core implementation unless this issue is revisited.
