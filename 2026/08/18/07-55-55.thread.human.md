This thread introduces a new `report` hook for `git-receive-pack`, allowing server administrators to intercept and modify the status report sent to clients after ref updates. The hook is motivated by GitLab’s need to implement multi-version concurrency control (MVCC), where the status must reflect the repository state after all updates are committed but before the client receives confirmation. The patch, authored by Karthik Nayak, adds a bidirectional filter: the hook receives the pkt-line encoded status report on stdin, replaces it with its stdout, and forwards stderr to the client via sideband. A non-zero exit status causes `receive-pack` to die, treating the push as failed (ref changes are not rolled back).

The core design debate centers on whether the hook should use Git’s config-based hook infrastructure (which supports multiple scripts per event) or remain a single-script hook modeled after `proc-receive`. Junio C Hamano and Phillip Wood have challenged the single-script approach, arguing the server/client distinction doesn’t inherently justify avoiding the config-based system.
