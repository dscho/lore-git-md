The `report` hook patch series by Karthik Nayak has reached its final form in version 3. This feature allows server administrators to intercept and modify the status report sent by `git-receive-pack` after ref updates are committed, addressing GitLab’s need for server-side MVCC (multi-version concurrency control). The series is now split into three patches: a preparatory documentation update, a mechanical refactoring to extract status-report generation logic, and the core hook implementation.

The hook runs after all ref updates are committed but before the status report is sent. It receives the pkt-line encoded report on stdin and replaces it with its stdout, while forwarding stderr to the client via sideband. The exit status semantics—resolved after discussion with Junio C Hamano and Patrick Steinhardt—mirror the `pre-receive` hook: a non-zero exit rewrites all ref status lines to “report hook failed” and allows `receive-pack` to exit cleanly. The implementation is self-contained, avoiding the config-based hook infrastructure to prevent coordination complexity.

All prior feedback has been addressed, including documentation clarity and pkt-line format references. The series is now ready for integration, with no open questions or loose ends. Reviews from Junio, Patrick, and others have been substantive, while minor stylistic feedback from Kristoffer Haugsbakk and Phillip Wood was incorporated or addressed in earlier iterations. The test coverage verifies passthrough behavior, failure modes, and sideband relay.
