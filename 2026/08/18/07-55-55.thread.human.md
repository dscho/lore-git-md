This thread introduces a new `report` hook for `git receive-pack`, allowing server administrators to filter or modify the status report sent to clients after ref updates are committed. The hook is motivated by GitLab’s need to implement multi-version concurrency control (MVCC), where the status report must reflect the repository state post-update but before client confirmation.

The patch, authored by Karthik Nayak, has been under review with no prior versions posted. Key participants include Junio C Hamano, who raised concerns about the interaction between the hook’s exit status and stdout, and Patrick Steinhardt, who provided substantive feedback on design and documentation. The core ambiguity—whether a non-zero exit should discard the hook’s stdout—has now been resolved: the exit status will act as a "nuclear option" for exceptional cases, ensuring the client never receives a malformed response. This aligns with Patrick’s argument and Karthik’s acceptance of the approach.

The implementation remains unchanged, but documentation updates are planned to clarify the hook’s behavior, including its reliance on the client for stderr forwarding and the implications of a non-zero exit. Minor test adjustments, such as verifying the "remote:" prefix on stderr, are also in progress. The patch is still under review, with no indication of integration status yet.
