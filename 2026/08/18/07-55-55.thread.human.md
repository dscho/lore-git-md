This thread introduces a new `report` hook for `git-receive-pack`, allowing server administrators to filter or modify the status report sent to clients after ref updates. The patch, authored by Karthik Nayak, is currently under review and adds a bidirectional filter that reads the pkt-line encoded status report on stdin, replaces it with stdout, and forwards stderr to the client via sideband. A non-zero exit status causes the push to fail, though ref changes persist.

Junio C Hamano has raised substantive design questions about the interaction between the hook’s exit status and its rewritten report. The current implementation discards the hook’s stdout if it exits non-zero, meaning the client sees only a generic failure rather than the rewritten report. This behavior is undocumented and could lead to unexpected outcomes, particularly if administrators expect the rewritten report to be honored regardless of exit status. The discussion centers on whether the exit status should override the rewritten report or if the two should remain orthogonal, with no clear resolution yet. The patch itself is otherwise uncontroversial, with test coverage and documentation included.
