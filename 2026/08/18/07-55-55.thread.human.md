This thread introduces a new `report` hook for `git receive-pack`, allowing server administrators to filter or modify the status report sent to clients after ref updates. The patch, authored by Karthik Nayak, is under review and adds a hook that acts as a bidirectional filter: it receives the status report on stdin, replaces it with its stdout, and forwards stderr to the client via sideband. A non-zero exit status currently causes `receive-pack` to fail, discarding the hook’s stdout—a behavior Junio C Hamano has flagged as potentially surprising and in need of clarification or revision.

The patch is self-contained, with documentation in `githooks.adoc` and test coverage in `t/t5412-report-hook.sh`, though the interaction between exit status and stdout remains untested. Kristoffer Haugsbakk’s recent review focuses on documentation and style, suggesting a concrete use-case example (GitLab’s MVCC system) in the commit message, clarifying whether the hook should be documented in `git-receive-pack(1)`, and linking to `gitprotocol-v2(5)` for `pkt-line` format details. He also proposes refactoring test teardown logic but does not engage with the core design ambiguity. The thread’s key open question remains whether the hook’s exit status and stdout should be orthogonal or tied together, with no resolution yet.
