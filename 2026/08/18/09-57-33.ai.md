This is a documentation refactoring patch (4/5 in the v2 series) that extracts the `--date` alternatives block from `Documentation/rev-list-options.adoc` into a new standalone file, `Documentation/rev-list-option-date-alternatives.adoc`. The goal is to allow the same documentation to be reused by both `git-rev-list` and the upcoming `git format-rev --date` option (introduced in patch 5/5).

The patch is mechanical and uncontroversial: it moves 55 lines of verbatim text into a new file and replaces the block in `rev-list-options.adoc` with an `include::` directive. The commit message explains that the initial paragraph of the `--date` documentation (which references `git-log`) is intentionally left unchanged for `git-rev-list` and related commands, while `git format-rev` will use a dedicated paragraph in the next patch. This avoids the need for conditional AsciiDoc markup (`ifndef`) and keeps the documentation simple.

No functional changes are introduced, and the patch does not touch any code or tests. The new file is created with mode `100644` and follows the same formatting as the original block. The series’ earlier patches (1–3/5) have already addressed review feedback from Junio C Hamano, and this patch is likely to be accepted as-is. The refactoring is a prerequisite for patch 5/5, which implements the `--date` option in `git format-rev` by reusing the existing `pretty.c` date formatting logic.
