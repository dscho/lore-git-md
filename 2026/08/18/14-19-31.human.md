This is the fourth patch in Patrick Steinhardt’s seven-patch series refactoring how the object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. It focuses on the loose-object backend, bringing it into line with the new contract established in patch 1: `odb_source_read_object_info()` now returns a positive value (1) for missing objects and a negative value for corrupt ones.

The patch mechanically updates `odb/source-loose.c` to stop conflating missing and corrupt objects. Previously, the loose backend returned -1 for both cases, forcing callers to guess whether an object was absent or broken. The changes are straightforward: `read_object_info_from_path()` now checks `errno == ENOENT` and returns 1 instead of -1, and the `corrupt:` label is removed because the function can now distinguish the two conditions internally. One `die()` call for invalid object types remains untouched because fixing it would break many tests, but the commit message flags this as a future cleanup opportunity.

The patch is clearly part of the ODB abstraction effort and looks well-crafted. It touches only one file and 35 lines, with no new user-facing behavior or on-disk format changes. The test coverage in the series already verifies the new semantics, so this patch should integrate cleanly with the rest of the series. If you care about low-level storage or refactoring, this is a small but necessary step toward consistent error handling.
