This is a substantive review of the RFC patch that proposes making `git config -e` propagate editor failure exit codes. Karthik Nayak weighs in on the open question left by Junio C Hamano's earlier response, explicitly supporting the change. He argues that surfacing the error to the user (via a non-zero exit code) is more intuitive and aligns with user expectations, even if the config file has already been modified. His feedback directly addresses Junio's skepticism about the value of the change, framing it as a matter of user experience rather than technical recovery. The review is brief but substantive, engaging with the core trade-off (consistency vs. long-standing behavior) and siding with the patch's approach. No new technical concerns are raised.
