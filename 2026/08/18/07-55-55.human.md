This is a feature patch introducing a new `report` hook for `git-receive-pack`. The hook allows server administrators to intercept and modify the status report sent back to the client after reference updates but before the response is finalized. This is particularly useful for custom server-side logic—such as GitLab’s multi-version concurrency control (MVCC) system—where the final status depends on operations that run *after* the reference transaction completes.

The patch adds the hook to both the v1 and v2 report paths in `builtin/receive-pack.c`, documents it in `githooks.adoc`, and includes a thorough test suite (`t5412-report-hook.sh`) that exercises passthrough behavior, non-zero exit handling, stdin/stdout/stderr routing, and report rewriting. The implementation is careful to preserve the existing sideband channel for human-readable messages and to ensure that a non-zero exit from the hook causes the push to fail without rolling back already-committed ref changes.

Karthik’s motivation is clearly stated: GitLab needs to gate or transform the status report based on the outcome of post-transaction MVCC operations, and no existing mechanism provides this capability. The patch is well-scoped, well-tested, and directly addresses the stated use case. It looks like a serious, production-ready contribution that should interest anyone running custom Git server logic.
