This is the first patch in D. Ben Knoble’s three-patch series `dk/use-nsec-runtime` (v3), which is cooking in `next`. It addresses a build-system discrepancy between Meson and Makefile builds by exposing a configurable knob for `man.base.url.for.relative.links` in Meson, aligning its behavior with the long-standing Makefile equivalent.

The patch fixes a practical issue: Meson builds currently hard-code the base URL for relative links in manual pages to `$prefix/$mandir`, which is incorrect for most distribution builds and lacks a trailing slash, resulting in broken links (e.g., `/usr/share/manuser-manual.html`). The change defaults the Meson base URL to `file://$(htmldir)/` (matching the Makefile’s behavior) and adds a `man_base_url` option to `meson_options.txt`, allowing downstream packagers (like Gentoo) to override it if needed. The commit message includes a thorough audit of existing `link:<relative>` usage in the documentation, confirming that all current instances point to HTML files, making the new default safe.

This is a build-system patch with no functional impact on Git’s behavior. It is uncontroversial, self-contained, and ready to advance independently of the rest of the series. Patrick Steinhardt has already reviewed it and confirmed it aligns with the Makefile’s behavior. The change touches only `Documentation/meson.build` and `meson_options.txt`, making it low-risk and easy to verify. Downstream packagers may appreciate the added flexibility, though the default should work for most cases.
