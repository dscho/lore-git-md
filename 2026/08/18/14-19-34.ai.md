This is the final patch in Patrick Steinhardt's seven-patch series refactoring how the object database (ODB) subsystem handles corrupt objects when `OBJECT_INFO_DIE_IF_CORRUPT` is used. It completes the work begun in earlier patches by making the flag's behavior fully generic and backend-agnostic.

The patch removes the last vestiges of abstraction-breaking code in `do_oid_object_info_extended()` that previously relied on `has_packed_and_bad()` to check for corrupt objects. Instead, it now uses the new infrastructure introduced in the series: backends signal corruption via negative return values from `odb_source_read_object_info()`, and provide human-readable error messages via the `errmsg` parameter. When `OBJECT_INFO_DIE_IF_CORRUPT` is set, the ODB layer now dies with the backend-specific error message (e.g., "packed object X (stored in Y) is corrupt") or a generic one if no message was provided.

Key changes include:
- Removing the `has_packed_and_bad()` function and its declaration, as it is no longer needed.
- Deleting the direct handling of `OBJECT_INFO_DIE_IF_CORRUPT` in the loose backend (`read_object_info_from_path()`), which previously caused the process to die even if another source had a good copy.
- Updating `do_oid_object_info_extended()` to track whether any backend reported corruption (`corrupt` flag) and to accumulate error messages from backends. The function now dies with the first available error message when `OBJECT_INFO_DIE_IF_CORRUPT` is set.
- Adding a test case (`t1060-object-corruption.sh`) that verifies a corrupted loose commit can still be read from an alternate repository, demonstrating the new behavior where the process does not die if another source has a good copy.

The patch touches five files: `odb.c` (core logic), `odb/source-loose.c` (loose backend), `packfile.c` and `packfile.h` (removal of `has_packed_and_bad()`), and the test script. The changes are mechanical and align with the series' goal of making error handling consistent and backend-agnostic.

This is a well-motivated refactoring that addresses a long-standing abstraction violation in the ODB layer. The patch is likely to be uncontroversial, as it removes complexity and improves consistency without changing user-facing behavior. The test coverage is a positive sign of thoroughness. The series as a whole is part of Patrick Steinhardt's ongoing ODB abstraction effort, which aims to make Git's object storage layer more modular.
