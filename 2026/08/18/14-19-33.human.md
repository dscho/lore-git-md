This is the sixth patch in Patrick Steinhardt’s seven-patch series refactoring how the object database (ODB) handles corrupt objects. The series is part of the ongoing ODB abstraction effort, and this patch specifically enables ODB sources to propagate human-readable error messages up the call stack when reading objects fails.

The patch adds a new `errmsg` parameter to the `read_object_info()` callback in `odb/source.h`, allowing each ODB source (packed, loose, in-memory, files) to populate a `strbuf` with a descriptive message when an object is corrupt. The packed and loose backends are updated to provide specific messages (e.g., "packed object X (stored in Y) is corrupt"), while the in-memory and files backends pass the parameter through without modification. All existing callers are adapted to pass `NULL` for now; the next patch will introduce a user of this infrastructure.

The changes are mechanical but important for consistency: they ensure that error messages are generated at the source level, where the most context is available, rather than reconstructed later in the ODB layer. The patch touches nine files, including core ODB logic, backend implementations, and unit tests, and maintains the existing behavior while preparing for future improvements. The commit message clearly explains the motivation and the incremental nature of the change. This looks like a well-crafted step in the refactoring, with no obvious red flags.
