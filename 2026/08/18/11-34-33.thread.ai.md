Subject: [PATCH] pull: introduce `--hard` mode
Series version: v1 (initial submission, redesign proposed and now endorsed by author)
Originating author: Artur Bieniek
Thread type: patch series (single patch)

Core problem or goal
Add a convenient way to discard local state and sync to upstream in a single command, specifically targeting the use case where an upstream branch has been force-pushed or rebased and the user has no local development (only a clean checkout of the upstream branch). The original proposal (`git pull --hard`) would reset the current branch, index, and working tree to the fetched branch using `git reset --hard`, discarding all local changes. The discussion has evolved to a safer redesign (`git pull --reset [--discard-changes | --autostash]`) that would error out by default if uncommitted changes exist, with an `--autostash` option to preserve them. The core question is whether such a feature belongs in `git pull` at all, and whether the force-push/rebase use case justifies its inclusion.

Current status
Under review; no prior versions. The original patch implements `--hard`, but the thread has shifted to a conceptual debate about the feature’s inclusion and a proposed redesign. Artur Bieniek now endorses Phillip Wood’s `--reset` redesign, providing a concrete use case (syncing to a force-pushed or rebased upstream branch) that `git pull --ff-only` cannot address. Junio’s latest response rejects the underlying motivation, leaving the redesign’s viability uncertain. Kristoffer Haugsbakk suggests an alternative workflow (working directly with remote-tracking branches) that obviates the need for the feature, but this has not yet been addressed by other participants. No updated patch has been posted.

Key technical details
- Files touched: `builtin/pull.c`, `Documentation/git-pull.txt`, `t/t5520-pull.sh`
- Original CLI option: `--hard` (now deprecated in favor of redesign)
- Proposed redesign: `--reset` with sub-options `--discard-changes` (default, errors if uncommitted changes exist) and `--autostash` (stashes changes before reset, restores afterward)
- New behavior: `git pull --reset <remote> <branch>` → `git fetch <remote> <branch>` followed by `git reset --hard FETCH_HEAD` (with safety checks or autostash)
- Rejects combinations with `--ff-only`, `--squash`, `--rebase`, etc.
- Preserves `--quiet` and submodule recursion settings from the pull context
- On-disk format: no changes
- Test coverage: basic usage, error conditions, submodule recursion (original patch); proposed redesign would require additional tests for uncommitted changes and autostash behavior
