Subject: [PATCH] pull: introduce `--hard` mode
Series version: v1 (initial submission, now with proposed redesign)
Originating author: Artur Bieniek
Thread type: patch series (single patch)

Core problem or goal
Add a convenient way to discard local state and sync to upstream in a single command. The original proposal (`git pull --hard`) would reset the current branch, index, and working tree to the fetched branch using `git reset --hard`, discarding all local changes. The discussion has now shifted to a safer design that would error out by default if uncommitted changes exist, with an `--autostash` option to preserve them.

Current status
Under review; no prior versions. The patch implements the original `--hard` feature, but the thread has evolved to consider a redesign (`git pull --reset [--discard-changes | --autostash]`) that would address maintainer concerns about accidental data loss. No updated patch has been posted yet.

Key technical details
- Files touched: `builtin/pull.c`, `Documentation/git-pull.txt`, `t/t5520-pull.sh`
- Original CLI option: `--hard` (now in question)
- Proposed redesign: `--reset` with sub-options `--discard-changes` (default, errors if uncommitted changes exist) and `--autostash` (stashes changes before reset, restores afterward)
- New behavior: `git pull --reset <remote> <branch>` → `git fetch <remote> <branch>` followed by `git reset --hard FETCH_HEAD` (with safety checks or autostash)
- Rejects combinations with `--ff-only`, `--squash`, `--rebase`, etc.
- Preserves `--quiet` and submodule recursion settings from the pull context
- On-disk format: no changes
- Test coverage: basic usage, error conditions, submodule recursion (original patch); proposed redesign would require additional tests for uncommitted changes and autostash behavior

Open questions and loose ends
- Whether the feature belongs in `git pull` at all, or should remain a separate command sequence (`git fetch && git reset --hard`). Junio’s objection frames this as a design philosophy question.
- Whether the proposed `--reset` redesign (erroring by default on uncommitted changes, with `--autostash` as an opt-in) sufficiently addresses safety concerns to overcome Junio’s principled opposition.
- No response yet from the author (Artur Bieniek) to Phillip Wood’s redesign proposal; the thread is awaiting the author’s position on whether the original `--hard` behavior is non-negotiable or if the redesign is acceptable.
