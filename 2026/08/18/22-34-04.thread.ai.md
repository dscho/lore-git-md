Thread identity: Bugfix series addressing a race condition in Git's geometric repacking mechanism causing objects to be incorrectly reported as missing, leading to crashes in `git replay`. Two-patch series by Elijah Newren via GitGitGadget.

Core problem or goal: Fix a race condition where a multi-pack-index (MIDX) references a packfile removed by geometric repacking, causing processes using the stale MIDX to fail to locate objects. The issue manifests as a SIGSEGV in `git replay` and missing-object errors in other server-side operations (`git merge-tree`, `git diff`, `git rev-list`, `rev-parse`, `cat-file`). Patch 1/2 ensures `git replay` fails gracefully when merge inputs are unreadable, while patch 2/2 modifies the packed-object backend to recover from MIDX-packfile mismatches by scanning all packs covered by the MIDX when the normal lookup fails.

Current status: **Under review, effectively ready for integration.** Junio C Hamano provided a **substantive** review of patch 1/2, endorsing the fix for `pick_regular_commit()`'s incorrect handling of negative `result->clean` values (which signal unreadable objects) and requesting the removal of a redundant `test_grep ! "[Ss]egmentation"` check in the test (addressed in v2). Patch 2/2 received a **substantive** review from Patrick Steinhardt, who praised the targeted recovery logic but raised a nuanced question about whether the fix is strictly necessary for callers that do not use `OBJECT_INFO_QUICK` (e.g., `cat-file`, `rev-list`), as these paths already reload packfiles on failure and would recover naturally. Junio also acknowledged patch 2/2 **surface-level**, noting an upcoming merge conflict with an in-flight topic that changes the `packfile_fill_entry()` API. Junio will resolve the conflict with an "evil merge" when integrating the series into `seen`; no rebase is required from Elijah. No technical objections to either patch remain. The series is a high-priority candidate for merging due to its impact on server-side stability.

Key technical details:
- Files touched: `replay.c` (graceful failure logic), `odb/source-packed.c` (MIDX recovery), and test files (`t/t3650-replay-basics.sh` for patch 1/2, `t/t5319-multi-pack-index.sh` for patch 2/2).
- Subsystems: geometric repacking, MIDX, packed-object backend, `git replay`.

The recovery logic is gated by the presence of a stale MIDX and only triggers when the MIDX *should* have found the object but didn’t.
- New symbols: None (logic-only changes).

- Test coverage: Added for both the `git replay` crash scenario (patch 1/2) and MIDX recovery logic (patch 2/2). Tests simulate unreadable objects and MIDX-packfile mismatches, verifying error messages and recovery behavior. The redundant `test_grep` check in patch 1/2's test was removed in v2.
