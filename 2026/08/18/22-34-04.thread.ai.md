Thread identity: Bugfix series addressing a race condition in Git's geometric repacking mechanism causing objects to be incorrectly reported as missing, leading to crashes in `git replay`. Two-patch series by Elijah Newren via GitGitGadget.

Core problem or goal: Fix a race condition where a multi-pack-index (MIDX) references a packfile removed by geometric repacking, causing processes using the stale MIDX to fail to locate objects. The issue manifests as a SIGSEGV in `git replay` and missing-object errors in other server-side operations (`git merge-tree`, `git diff`, `git rev-list`, `rev-parse`, `cat-file`). The root cause is that when an object exists in multiple packs covered by a MIDX and the *preferred* pack (the one the MIDX would normally use) is removed, the current code fails to find the object in the remaining packs because the non-MIDX lookup skips all packs covered by the MIDX, and the MIDX lookup fails when the preferred pack is missing. This results in a false negative affecting *all* object lookups, not just those using `OBJECT_INFO_QUICK`. Patch 1/2 ensures `git replay` fails gracefully when merge inputs are unreadable, while patch 2/2 modifies the packed-object backend to recover from MIDX-packfile mismatches by scanning all packs covered by the MIDX when the normal lookup fails.

Current status: **Design discussion converging; core fix direction finalized.** The series remains a high-priority candidate for merging, with no remaining technical objections to the core fix. The latest update adopts Jeff King (Peff)'s tri-state design for `fill_midx_entry()`, which returns `MIDX_FILL_MISS`, `MIDX_FILL_HIT`, or `MIDX_FILL_OWNER_UNAVAILABLE` instead of a boolean, and further refines the recovery logic to **trigger only during `SECOND_READ`** (the retry phase after a refresh). This change addresses Peff’s performance concern by ensuring `QUICK` callers (e.g., `git replay`) do not incur the cost of scanning MIDX-covered packs unless the object lookup fails and a refresh is attempted. The tri-state approach remains compatible with Patrick Steinhardt’s refinement (scanning only MIDX-covered packs) and Derrick Stolee’s feedback about integrating with the `multi-pack-index expire` mechanism. The discussion now centers on follow-up work, including whether geometric repacking should adopt a grace period for redundant packfiles to reduce the race condition’s frequency, as suggested by Stolee. Elijah has acknowledged this as a worthwhile follow-up effort, signaling openness to future patches that would make the fallback logic a secondary defense rather than a frequent necessity.

Key technical details:
- Files touched: `replay.c` (graceful failure logic), `odb/source-packed.c` (MIDX recovery with tri-state return values and `SECOND_READ`-gated fallback), and test files (`t/t3650-replay-basics.sh` for patch 1/2, `t/t5319-multi-pack-index.sh` for patch 2/2).
- Subsystems: geometric repacking, MIDX, packed-object backend, `git replay`, `multi-pack-index expire`.
- New behavior: `git replay` fails gracefully with an error message when objects are unreadable; MIDX-packfile mismatches are recovered transparently by scanning packs in `find_pack_entry()` **only during `SECOND_READ`**. The recovery logic is gated by the tri-state return from `fill_midx_entry()` and triggers when the MIDX *should* have found the object but the preferred pack is missing (`MIDX_FILL_OWNER_UNAVAILABLE`). The fix targets `OBJECT_INFO_QUICK` callers but also addresses a broader correctness issue.
- New symbols: `MIDX_FILL_MISS`, `MIDX_FILL_HIT`, `MIDX_FILL_OWNER_UNAVAILABLE` (enum values in `odb/source-packed.c`).
- No on-disk format changes.
- Test coverage: Added for both the `git replay` crash scenario (patch 1/2) and MIDX recovery logic (patch 2/2). Tests simulate unreadable objects and MIDX-packfile mismatches, verifying error messages and recovery behavior. The redundant `test_grep` check in patch 1/2's test was removed as part of the review process.
- The central functions under discussion are `fill_midx_entry()` (now returning a tri-state value) and `find_pack_entry()` (updated to handle the tri-state return and defer recovery to `SECOND_READ`). The tri-state design shifts responsibility for handling missing packfiles to callers, aligning with Peff’s architectural preference. Peff’s refinement to gate the fallback on `SECOND_READ` optimizes performance for `QUICK` callers while preserving correctness.

Open questions and loose ends:
- **Follow-up work**: The primary focus is now on whether geometric repacking should adopt a grace period for redundant packfiles (per Stolee’s feedback) to reduce the race condition’s frequency and reliance on the fallback logic. This would involve modifying geometric repacking to leave redundant packfiles in place until all processes using them have finished, similar to the `multi-pack-index expire` mechanism. Elijah has acknowledged this as a worthwhile follow-up but has not proposed specific changes to the current patch. The two approaches are complementary: `expire` would minimize the race’s occurrence, while the fallback logic ensures correctness when the race does happen. Additional follow-up patches may address other race-condition scenarios, potentially leveraging the tri-state API and `SECOND_READ`-gated fallback.
- **Scan order optimization**: Patrick’s refinement to prioritize scanning MIDX-covered packs when the preferred pack is missing remains compatible with the current design but may be revisited if performance concerns arise during testing.
