This is a documentation refactoring patch, part of Kristoffer Haugsbakk’s five-patch series extending `git format-rev` with `--abbrev`, `--color`, and `--date` formatting options. This is patch 4/5 in the v2 series, which is under active review but not yet queued in any integration branch.

The patch extracts the `--date` alternatives documentation from `rev-list-options.adoc` into a new standalone file, `rev-list-option-date-alternatives.adoc`. This allows the same documentation block to be reused by both `git rev-list` (and related commands) and the upcoming `git format-rev` `--date` option, avoiding duplication. The change is purely mechanical: the 55-line block is moved verbatim, with no modifications to its content. The commit message notes that the initial paragraph of the `--date` option (which references `git log`) could have been conditionally adjusted for `git format-rev`, but the author opted for simplicity by writing a dedicated paragraph in the next patch instead.

This is a clean, uncontroversial refactoring that aligns with Git’s documentation practices. The patch touches only documentation files and has no functional impact on the codebase. It directly supports the feature addition in patch 5/5, which implements the `--date` option for `git format-rev` by reusing existing `git log` logic. No review feedback has been posted yet, but the change is straightforward and likely to be accepted as-is.
