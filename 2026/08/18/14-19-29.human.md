This is the second patch in Patrick Steinhardt’s seven-patch series refactoring how the object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The series is part of the ongoing ODB abstraction effort to make Git’s object storage layer more modular and backend-agnostic.

This patch updates the in-memory ODB source to follow the new calling convention established in patch 1/7: the `read_object_info()` callback now returns a positive value (1) to signal a missing object, rather than a negative value (-1). The change is mechanical—just flipping the return value—and includes a corresponding update to the unit test in `t/unit-tests/u-odb-inmemory.c` to verify the new behavior. No logic changes are introduced beyond aligning the in-memory source with the updated contract.

The patch is small, focused, and well-explained. It’s a necessary step toward making error handling consistent across all ODB backends, which will allow the ODB layer to handle `OBJECT_INFO_DIE_IF_CORRUPT` generically in later patches. Since this is part of a larger refactoring, the value of the patch will become clearer as the series progresses, but it looks like a clean, uncontroversial change. Reviewers familiar with the ODB subsystem or interested in backend abstraction will likely want to follow the full series.
