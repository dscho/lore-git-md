This is a bugfix series targeting the multi-pack-index (MIDX) and geometric repacking subsystems. Elijah Newren reports a race condition where objects become temporarily inaccessible during geometric repacking, even though they still exist on disk. The issue occurs when a process holds an open reference to an old MIDX file that lists a packfile later removed by repacking, causing object lookups to fail. The series also fixes a separate but related crash in `git replay` when it encounters missing objects.

The problem affects multiple server-side Git operations, including `git replay`, `git merge-tree`, `git diff`, and `git rev-parse`, though the window for the race is narrow. The first patch makes `git replay` handle missing merge inputs gracefully instead of crashing with a SIGSEGV. The second patch modifies the packed-object backend to recover when a MIDX references a removed packfile, ensuring object lookups succeed even after repacking.

The series includes new tests in `t3650-replay-basics.sh` and `t5319-multi-pack-index.sh` to verify the fixes. The commit messages are detailed and clearly explain the race condition and its impact. This looks like a well-motivated and thoroughly tested fix for a subtle but real issue in production environments.
