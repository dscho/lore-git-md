Thread identity
Subject: [PATCH 0/7] odb: refactor handling of corrupt objects with OBJECT_INFO_DIE_IF_CORRUPT
Series version: v2 (addresses Junio C Hamano’s feedback on return convention and error message propagation)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to make handling of corrupt objects consistent and backend-agnostic when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The series extends `odb_source_read_object_info()` to distinguish between missing and corrupt objects, propagates backend-specific error messages to the ODB layer, and removes abstraction-breaking code that reconstructs error messages after the fact. The goal is to ensure that corrupt objects are reported consistently regardless of backend, and that error messages are generated by the backend that encountered the failure.

Current status
Under review; v2 posted. Junio C Hamano’s design-level concerns have been fully addressed: the tri-state return convention is now formalized using an `enum odb_read_status` with negative error codes (e.g., `ODB_READ_ERROR = -1`, `ODB_READ_NOT_FOUND = -2`) for all error conditions, including missing objects. Patch 3/7 (this email) introduces the `ODB_READ_NOT_FOUND` error code and updates all ODB backends to return it for truly missing objects, while preserving `ODB_READ_ERROR` for corruption and other failures. The granularity of the `bad_pack` logic in patch 3/7 remains unresolved—while Patrick clarified that the patch does not mark entire packs as bad, Junio’s broader question about whether object-level granularity is sufficient for multi-pack scenarios is still open. No merge status reported. Patch 5/7’s commit message subject line was corrected from "signal mark objects" to "signal missing objects" in v1 and remains correct in v2.

Key technical details
- Files touched: `odb.c`, `odb/source-*.c` (in-memory, packed, loose, files), `odb.h`, `odb/source.h`, and related headers. Later patches in the series also touch `packfile.c`, `midx.c`, `midx.h`, `builtin/pack-objects.c`, `t/helper/test-read-midx.c`, and test files (`t1060-object-corruption.sh`, `t/unit-tests/u-odb-inmemory.c`).
- Key functions modified: `odb_source_read_object_info()`, `read_object_info_from_path()`, `do_oid_object_info_extended()`, `find_pack_entry()`, `fill_midx_entry()`, `packfile_fill_entry()`, `odb_source_packed_read_object_info()`, `odb_source_loose_read_object_info()`, `odb_source_files_read_object_info()`, and the `read_object_info()` callback in all ODB sources. The `has_packed_and_bad()` function was removed in patch 7/7.
- New behavior introduced in patch 1/7: the `enum odb_read_status` (`ODB_READ_OK = 0`, `ODB_READ_ERROR = -1`) is introduced to formalize the return convention for `odb_source_read_object_info()`. This is a type-system refactoring with no immediate behavior change; the packed backend’s existing positive return code for missing objects is preserved until patch 3/7 aligns it with the new convention.
- Patch 2/7 mechanically updates the `read_object_info()` callback and its callers across all ODB sources to return the new `enum odb_read_status` instead of a bare `int`. No behavior changes are introduced; this is purely a preparatory step to make the error semantics explicit.
- Patch 3/7 (this email) introduces the `ODB_READ_NOT_FOUND` error code (`-2`) and updates all ODB backends to return it for truly missing objects, while preserving `ODB_READ_ERROR` for corruption and other failures. The loose backend’s `read_object_info_from_path()` helper checks `errno` for `ENOENT` and returns `ODB_READ_NOT_FOUND` in that case; the packed backend’s positive return code for missing objects is changed to `ODB_READ_NOT_FOUND`; and the files backend now prefers the packed source’s error code when both sources fail, ensuring corruption errors take precedence over missing-object errors. The patch is preparatory: `odb_read_object_info()` still returns `-1` for both missing and corrupt objects until a later patch in the series.
- Patch 4/7 updates the loose-object backend to return negative values for all error conditions, removing redundant error handling.
- Patch 5/7 updates the files ODB source to propagate error codes from its child sources, preferring the packed source's error code when both fail.
- Patch 6/7 introduces the `errmsg` parameter to the `read_object_info()` callback, allowing backends to populate backend-specific error messages.
- Patch 7/7 (final) removes `has_packed_and_bad()` and makes `OBJECT_INFO_DIE_IF_CORRUPT` fully generic: `do_oid_object_info_extended()` now tracks corruption status and accumulates error messages from all backends, dying with the first available message when the flag is set. The loose backend’s direct `die()` call was removed, and a test case was added to verify that a corrupted loose commit can still be read from an alternate repository.
- No new user-facing options or commands; changes are internal to the ODB subsystem.
- On-disk format unchanged.
- Test coverage: updated `t1060-object-corruption.sh` and unit tests in `t/unit-tests/u-odb-inmemory.c` to expect `ODB_READ_NOT_FOUND` for missing objects.

Open questions and loose ends
- The granularity of the `bad_pack` logic remains a point of discussion: while Patrick clarified that patch 3/7 does not mark entire packs as bad, Junio’s broader question—whether the current object-level granularity is sufficient for multi-pack scenarios—remains unanswered.
- The `die()` call for invalid object types in the loose backend remains unchanged due to test dependencies; noted as a potential future cleanup but not blocking the current refactoring.
