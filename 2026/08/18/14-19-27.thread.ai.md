Subject: [PATCH 0/7] odb: refactor handling of corrupt objects with OBJECT_INFO_DIE_IF_CORRUPT
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to make handling of corrupt objects consistent and backend-agnostic when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. Currently, the flag is handled inconsistently: `do_oid_object_info_extended()` checks for corrupt objects in packfiles by reaching into packed source internals (breaking abstraction), while the loose source handles the flag directly, causing the process to die even if another source has a good copy. The series extends `odb_source_read_object_info()` to distinguish between missing and corrupt objects and to return error messages to the caller.

Current status
Under review; v1 posted. No prior versions. No merge status reported.

Key technical details
- Files touched: `odb.c`, `odb/source-*.c` (in-memory, packed, loose, files), `packfile.c`, `midx.c`, `midx.h`, `builtin/pack-objects.c`, `t/helper/test-read-midx.c`, related headers, and test files (`t1060-object-corruption.sh`, `t/unit-tests/u-odb-inmemory.c`).
- Key functions modified: `odb_source_read_object_info()`, `read_object_info_from_path()`, `do_oid_object_info_extended()`, `find_pack_entry()`, `fill_midx_entry()`, `packfile_fill_entry()`, `odb_source_packed_read_object_info()`, `odb_source_loose_read_object_info()`.
- New behavior: `odb_source_read_object_info()` now returns a positive value for missing objects and propagates corrupt-object errors (negative return values) to the caller; `OBJECT_INFO_DIE_IF_CORRUPT` is handled generically in the ODB layer. The packed and loose backends now correctly report known-bad objects as corrupt (negative return) rather than missing (positive return), fixing an inconsistency where `find_pack_entry()` and the loose backend previously misreported corrupt objects as missing.
- Patch 1/7 updated the documentation and function signature in `odb/source.h` to formalize the distinction between missing (positive return) and corrupt (negative return) objects, establishing the contract for subsequent patches.
- Patch 2/7 mechanically updated the in-memory ODB source (`odb/source-inmemory.c`) to return `1` (positive) for missing objects, aligning with the new contract.
- Patch 3/7 propagates corruption status through the packed backend by modifying `find_pack_entry()` and its callers to accept an optional `struct packed_git **bad_pack` parameter, which is populated when an object is found to be corrupt. This ensures that known-bad objects are correctly flagged as corrupt rather than missing.
- Patch 4/7 updates the loose-object backend (`odb/source-loose.c`) to return `1` for missing objects and negative values for corrupt ones, removing the redundant `corrupt:` label and consolidating error handling. One `die()` call for invalid object types remains unchanged due to test dependencies, but this is noted as a potential future cleanup.
- No new user-facing options or commands; changes are internal to the ODB subsystem.
- On-disk format unchanged.
- Test coverage: updated `t1060-object-corruption.sh` and added/updated unit tests in `t/unit-tests/u-odb-inmemory.c`.

Open questions and loose ends
- The `die()` call for invalid object types in the loose backend remains unchanged due to test dependencies; noted as a potential future cleanup but not blocking the current refactoring.
