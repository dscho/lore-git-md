This is the first patch in a seven-part refactoring series targeting the object database (ODB) subsystem. The series, led by Patrick Steinhardt, aims to standardize how corrupt objects are handled when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used.

This patch updates the documentation and function signature for `odb_source_read_object_info()` to formally distinguish between two failure modes: objects that are missing from a source (return a positive value) and objects that exist but are corrupt (return a negative value). Currently, only the packed backend makes this distinction; the other backends (loose, in-memory, files) treat both cases as a single negative return. The change is purely preparatory—no backend implementations are modified yet—but it sets the stage for the rest of the series.

The patch is small (14 lines added, 3 removed) and touches only the header file `odb/source.h`. It is a clean, well-explained refactoring step that aligns the API contract with the behavior already exhibited by the packed backend. There is no user-visible impact, and the commit message clearly states the motivation and next steps. This looks like a solid foundation for the rest of the series.
