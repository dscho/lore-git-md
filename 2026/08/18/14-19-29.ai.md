This is the second patch in Patrick Steinhardt’s seven-patch series refactoring how the object database (ODB) handles corrupt objects when `OBJECT_INFO_DIE_IF_CORRUPT` is set. It updates the in-memory ODB source to follow the new calling convention established in patch 1/7: the `read_object_info()` callback now returns a positive value (1) to signal a missing object, rather than a negative value (-1). The change is mechanical—flipping the return value—and includes a corresponding update to the unit test in `t/unit-tests/u-odb-inmemory.c` to assert that the return value is positive for missing objects. No logic beyond the return-value semantics is altered. The patch is small (two lines changed) and uncontroversial, serving as a straightforward adaptation of the in-memory backend to the new ODB-layer contract.
