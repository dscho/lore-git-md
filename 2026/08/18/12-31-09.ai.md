This is an RFC proposing a performance optimization for Git’s connectivity check (`check_connected()`), which is used by `fetch` and `receive-pack` (among other call sites). The current implementation relies on `rev-list --objects --stdin --not --all --quiet`, which scales with the size of the *entire* repository rather than just the incoming changes. Kristofer Karlsson argues this creates unnecessary overhead for large repositories with frequent pushes, and presents a two-part proposal to make the check proportional to the incoming set instead.

The first part (“opportunistic trusted-tree discovery”) replaces the eager traversal of the boundary commits’ tree closures with a lazy, parent-diff-based cache. Instead of marking every object reachable from the boundary as trusted up front, the walk verifies only the changed entries, pruning subtrees whose contents match a trusted parent. This reduces the object-verification phase from hundreds of thousands of objects to roughly the number of changed files.

The second part (“finding the boundary”) avoids the full `--not --all` traversal by seeding the walk with a small set of likely-useful refs (e.g., the old values of the updated refs) and imposing a bounded walk budget. If the boundary is closed within the budget, the check succeeds; otherwise, it falls back to the current `rev-list` path. Preliminary numbers on a 3 M-commit, 200 K-ref repository show a 30–150× speed-up for small pushes (5 commits, 45 changed files → 30 ms vs. 1 s; 1-commit trivial change → 7 ms vs. 1 s).

Kristofer explicitly ties the proposal to Patrick Steinhardt’s 2021 quarantine-dir series and Justin Tobler’s 2025 `--skip-connectivity-check` option, framing it as a natural next step for operators who still need the safety of the check but cannot tolerate its current cost. Edge cases (shallow clones, promisor remotes, replace objects, tree tips) are handled by falling back to the existing code path, so correctness is preserved. The RFC is seeking feedback on whether the problem is worth solving and whether the proposed direction is sound; no patches are included yet.
