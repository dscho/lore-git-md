This is a review reply in the ongoing ODB corruption-handling refactoring series. Junio C Hamano responds to Patrick Steinhardt’s second patch, which mechanically updates the in-memory ODB source to return a positive value (1) for missing objects instead of a negative one (-1). Junio’s feedback is substantive: he objects to the use of a hard-coded positive return value (1) to signal "missing object" and suggests formalizing the return convention with an enum. He reiterates his preference—first raised in the cover letter discussion—for using negative error codes (e.g., `-ENOENT`) for all error conditions, including missing objects, rather than reserving positive values for that purpose. The review does not engage with the patch’s correctness or test coverage, focusing instead on the design of the return-value convention that underpins the entire series. No resolution or counter-argument is offered; the thread remains open on this design question.
