This is the final patch in Kristoffer Haugsbakk’s five-part series adding `--abbrev`, `--color`, and `--date` formatting options to the experimental `git format-rev` command. The patch implements the new options by reusing existing `git log` logic (`rev_info` struct and `pretty.c` date formatting), completing the feature work after the preparatory refactoring in patches 1–4.

The patch touches three files: `builtin/name-rev.c` (main implementation), `Documentation/git-format-rev.adoc` (updated synopsis and new option documentation), and `t/t6120-describe.sh` (expanded test coverage). The synopsis is simplified to highlight the two mandatory options (`--stdin-mode` and `--format`), with the rest grouped under `[<options>]` for clarity. The documentation now includes the new options’ descriptions, mirroring `git log`’s behavior, and reuses the `--date` alternatives block extracted in patch 4/5.

Key technical details include the memory leak fix (adding `date_mode_release()` to free custom date format strings), defensive code improvements (consistent `BUG_ON_OPT_NEG` placement), and test coverage for edge cases like invalid values (`--color=not-valid`) and custom date formats (`--date="format:%c"`). The tests normalize option ordering to avoid false negatives when comparing `git format-rev` output with `git log`.

The series is uncontroversial and addresses all v1 feedback, including Junio C Hamano’s suggestions for designated initializers and defensive programming. The new options behave identically to their `git log` counterparts, and the patch is well-tested and documented. This looks like a solid, incremental improvement to `git format-rev`’s formatting flexibility.
