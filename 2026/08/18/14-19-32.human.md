This is the fifth patch in Patrick Steinhardt’s seven-patch series refactoring how the object database (ODB) handles corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. The series is part of the ongoing ODB abstraction effort to make error handling consistent and backend-agnostic.

This patch updates the "files" ODB source (`odb/source-files.c`), which aggregates the packed and loose backends. Previously, it treated all failures from its child sources as a generic negative return, preventing callers from distinguishing between missing and corrupt objects. Now that the packed and loose backends have been updated to return positive values for missing objects and negative values for corrupt ones (in earlier patches), this patch propagates those return values upward. If both backends fail, it returns the error from the packed source, preferring its error message when both report corruption.

The change is mechanical and aligns the files source with the tri-state return convention established in patch 1/7. It’s a small but necessary step in the refactor, touching only one file and 17 lines. The commit message is clear, and the logic is straightforward. No new tests are added here, but the existing test coverage in `t1060-object-corruption.sh` and unit tests should verify the behavior. This patch looks solid and uncontroversial, assuming the earlier patches in the series hold up.
