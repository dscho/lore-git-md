This is the fifth patch in Patrick Steinhardt's seven-patch series refactoring how the object database (ODB) handles corrupt objects when `OBJECT_INFO_DIE_IF_CORRUPT` is used. The series is part of the ongoing ODB abstraction effort to make Git's object storage layer more modular and backend-agnostic.

This patch updates the "files" ODB source (`odb/source-files.c`) to properly propagate the tri-state return values introduced in earlier patches. Previously, the files source conflated all failures (missing or corrupt objects) into a single negative return value, preventing callers from distinguishing between the two cases. Now, it correctly returns `0` for success, a positive value for missing objects, and a negative value for corrupt ones, mirroring the behavior already implemented in the packed and loose backends.

The change is mechanical but important for consistency: the files source now checks the return values of its child sources (packed and loose) and propagates the most relevant error. If both sources fail, it prefers the packed source's error code, which is a reasonable default given that packed objects are typically the primary storage mechanism. The patch includes a clear explanatory comment in the code, which is helpful for future maintainers.

This patch is a straightforward refactoring with no user-facing impact. It touches only one file (`odb/source-files.c`) and is well-aligned with the series' goal of making error handling consistent across all ODB backends. The change is unlikely to be controversial, as it simply extends the tri-state return convention already established in earlier patches. The series as a whole is shaping up to be a solid, incremental improvement to the ODB layer.
