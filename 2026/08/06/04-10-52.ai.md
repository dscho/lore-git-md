This is a **substantive review reply** in the ongoing NonStop textconv regression thread. Jeff King (Peff) responds to Randall S. Becker’s `%f` placeholder proposal with a technical feasibility assessment and a caution about caching.

Peff acknowledges that extending the textconv interface to support `%f` (expanding to the original file path) is *possible in principle*, but flags a critical implementation hurdle: Git’s textconv output is cached in git-notes using only the blob ID as the key. Introducing `%f` would break this cache consistency, as the same blob could produce different output depending on the working-tree path. He suggests the patch must either disable caching for filters using `%f` or risk returning incorrect cached results. This is a concrete technical constraint that any `%f` implementation would need to address.

Beyond feasibility, Peff questions the proposal’s premise. He frames `%f` as a workaround for the underlying bug—empty temp files on NonStop for binary content—rather than a fix. His preference is to resolve the root cause (the regression itself), noting that relying on the working-tree path could introduce new correctness issues (e.g., when diffing historical trees). This shifts the thread’s focus back to diagnosing the regression, though no new root-cause analysis is provided here.
