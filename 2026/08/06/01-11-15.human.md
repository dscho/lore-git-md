This is a **substantive review** from Junio C Hamano on the third patch in Johannes Schindelin’s 11-patch series addressing unchecked return values identified by Coverity. The patch adds an error check for `deflateInit()` in `reftable/block.c`, but Junio raises two technical concerns about memory safety and error propagation.

First, he questions whether the patch leaks memory when `deflateInit()` fails: the `zstream` buffer is allocated with `REFTABLE_CALLOC_ARRAY`, but if `deflateInit()` returns an error, the patch does not free it. He suggests adding `REFTABLE_FREE_AND_NULL(bw->zstream)` before returning `REFTABLE_ZLIB_ERROR` to prevent a leak.

Second, he notes that while the immediate caller (`writer_reinit_block_writer()`) checks the error code, not all upstream callers do — notably `reftable_writer_new()`, which ignores the return value and may leave the `block_writer` in a broken state with a non-NULL but uninitialized `zstream`. He speculates that this could lead to undefined behavior if `deflate()` is later called on an uninitialized stream, or if `deflateEnd()` is called on a stream where `deflateInit()` never succeeded.

The review is narrowly focused on correctness and does not question the patch’s goal or approach. It highlights a potential memory leak and a latent error-handling gap in the reftable writer machinery, both of which could undermine the hardening effort the series aims to achieve. The concerns are specific to the reftable backend and do not affect the rest of the series.
