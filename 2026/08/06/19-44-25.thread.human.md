This thread reports a regression in `git rebase` when commit-graph is enabled, specifically triggered by submodule pointer changes. Philippe Blain describes a fatal error (`error: Could not read 157b7492624...` followed by `fatal: invalid commit position. commit-graph is likely corrupt`) that occurs during rebase, where the problematic commit exists in a submodule (`rpmsrc/qemu-kvm`) but not in the main repository. Disabling commit-graph (`-c core.commitGraph=false`) works around the issue, though submodule conflicts still arise as expected.

The regression was bisected to commit `bb5da75d61` ("commit: use commit graph in `lookup_commit_reference_gently()`") by Patrick Steinhardt. The error message misleadingly suggests commit-graph corruption, but `git fsck` confirms the data is intact—this is a functional bug, not a storage issue. Philippe has CC’d Patrick and plans to write a minimal reproducer next. No responses or resolutions have been posted yet, so the thread is currently focused on diagnosing the problem.
