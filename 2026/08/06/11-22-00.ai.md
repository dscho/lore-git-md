This is the fifth patch in the v3 series introducing `git repack --drop-filtered` for partial clones. It implements the actual removal of filtered promisor blobs, transitioning the feature from a dry-run preview (as in earlier patches) to a functional disk-space reclamation tool.

The patch wires up the `to_drop` oidset—computed by `enumerate_promisor_blobs()` in patch 4/7—to `repack_promisor_objects()`, which now rebuilds the promisor pack while excluding the dropped blobs. On a real run (`--drop-filtered` without `--dry-run`), it also sets `delete_redundant = 1`, ensuring the old promisor packs (which still contain the dropped blobs) are removed. The repack machinery’s existing write-before-delete and fsync guarantees preserve crash safety. The test script is extended with a new case that verifies a large promisor blob is absent after `--drop-filtered` runs, while a smaller one remains.

The change is minimal and backward-compatible: all existing callers of `repack_promisor_objects()` pass `NULL` for the new `to_drop` parameter, so their behavior is unchanged. The patch completes the core functionality of the series, enabling users to reclaim space from cached promisor blobs exceeding a size threshold while ensuring the objects remain recoverable from the promisor remote.
