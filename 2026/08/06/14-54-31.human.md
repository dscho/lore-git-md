This is the fourth patch in Patrick Steinhardt’s six-patch series making Git’s on-disk object database (ODB) structures pluggable. The patch implements Toon Claes’s alternative design, abandoning the `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag introduced in an earlier version and instead making ODB creation an explicit step at every call site. This is a purely mechanical refactoring that moves `odb_new()` out of `apply_repository_format()` and into `repo_init()`, `enter_repo()`, `setup_git_directory_gently()`, and a new helper function `create_object_database()`. The change ensures ODB initialization and on-disk creation are handled together, simplifying the path for the next patch, which moves on-disk structure creation into the ODB backends themselves.

The patch is uncontroversial and ready for merging. Toon Claes’s review identified two minor issues: the docstring for `apply_repository_format()` in `setup.h` is now misleading because it no longer initializes the ODB, and there is a formatting inconsistency in `init_db()` where the `apply_repository_format()` call is split across lines while other call sites remain single-line. Patrick acknowledges both points but treats them as non-blocking; the docstring will likely be updated in a future patch. The series remains on track for the current development cycle, with the first patch already marked "will merge to 'next'" in Junio’s "What's cooking" report.

This patch is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, which aims to decouple Git’s core logic from the traditional loose/pack on-disk layout. The series is a prerequisite for future ODB backends that may use custom storage formats. The changes here are internal and do not affect user-visible behavior, but they lay the groundwork for more flexible object storage backends. The patch itself is a straightforward refactoring with no functional changes, and the review discussion confirms it is structurally sound.
