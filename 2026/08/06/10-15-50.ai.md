This is the first patch in the v4 series adding path-related keys to `git repo info`. It introduces `path.toplevel.absolute` and `path.toplevel.relative` to expose the repository's top-level working tree directory in a scriptable format, replacing the need for `git rev-parse --show-toplevel`.

The implementation is straightforward: it uses `repo_get_work_tree()` to fetch the working tree path and `format_path()` to produce absolute (canonical) or relative (to the current directory) output. In bare repositories, both keys return an empty string, matching the design principle of using empty strings for inapplicable contexts. The patch touches `builtin/repo.c` (adding the two new getter functions), `Documentation/git-repo.adoc` (documenting the keys), and `t/t1900-repo-info.sh` (adding tests for both normal and bare repositories).

The tests are thorough: they verify absolute and relative paths in a nested subdirectory and confirm the empty-string behavior in bare repositories. The commit message clearly states the motivation (scriptability and predictability) and the behavior (empty string in bare repos). No substantive design questions remain for this patch; the only potential discussion points would be minor naming or documentation tweaks (e.g., whether "toplevel" is the most intuitive term), but the current choice is defensible and consistent with Git's existing terminology.
