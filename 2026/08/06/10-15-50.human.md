This is the first patch in a seven-patch series adding new path-related keys to the `git repo info` command. The series is part of a Google Summer of Code project by K Jayatheerth, mentored by Justin Tobler and Lucas Seiki Oshiro, and is now in its fourth iteration.

This patch introduces `path.toplevel.absolute` and `path.toplevel.relative` keys, which expose the top-level working tree directory of a repository in a scriptable format. The absolute variant returns the canonical path, while the relative variant returns the path relative to the current working directory. In bare repositories, both keys return an empty string, as there is no working tree. The implementation is straightforward, using `repo_get_work_tree()` and the existing `format_path()` helper, and includes thorough test coverage for both normal and bare repositories.

The patch is mechanically clean and aligns with the series' design principle of exposing internal Git paths without requiring direct access to Git's internals. The behavior mirrors that of `git rev-parse --show-toplevel`, but with stricter formatting and a more predictable output structure. No substantive technical concerns have been raised about this patch in prior iterations, though reviewers may suggest minor adjustments to key naming or suffix semantics for consistency with existing Git terminology.

This patch is uncontroversial and ready for broader review. It touches `builtin/repo.c`, `Documentation/git-repo.adoc`, and `t/t1900-repo-info.sh`, and is part of a self-contained series that is not tied to any larger ongoing effort.
