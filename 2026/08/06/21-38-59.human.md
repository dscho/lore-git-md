This is the final patch in Justin Tobler’s six-part series making `git receive-pack` fully backend-agnostic for pluggable object databases. It introduces the new `odb_transaction_write_pack()` interface and switches `receive-pack` from directly invoking `git index-pack`/`git unpack-objects` to delegating packfile ingestion to the ODB backend via the transaction system.

The patch moves the existing packfile-parsing and child-process logic from `builtin/receive-pack.c` into `object-file.c`, where it becomes the “files” backend implementation of the new interface. The key behavioral change is that `.keep` lockfiles created by `index-pack` are now owned by the transaction and removed in the backend’s `release` callback, ensuring they persist until references are updated regardless of which ODB backend is in use. The rest of the series’ preparatory refactoring (explicit parameter passing, global-state removal, error reporting via `strbuf`) pays off here: the call sites in `receive-pack` shrink from ~150 lines to a single call to `odb_transaction_write_pack()`.

The interface itself (`odb_transaction_write_pack_opts` and the `write_pack` callback) is designed to be generic enough for alternative backends (reftable, cloud storage, etc.), and the commit message explicitly notes that some options (e.g., `unpack_limit`) may be ignored by backends that do not use loose/packed storage. Reviewers will likely focus on whether the abstraction is sufficiently flexible and whether the error handling remains robust across the split between `commit` and `release`. The patch is part of the ongoing ODB abstraction effort led by Patrick Steinhardt and is still under active review.
