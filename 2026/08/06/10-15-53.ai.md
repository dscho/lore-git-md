This is the **fourth patch in the v4 series** adding path-related keys to `` `git repo info` ``. Specifically, it introduces ``path.index.absolute`` and ``path.index.relative`` to expose the repository’s index file location in a scriptable, config-like format.

The patch implements the new keys by calling ``repo_get_index_file()`` and formatting the result with ``format_path()``, respecting the ``GIT_INDEX_FILE`` environment override. The behavior matches ``git rev-parse --git-path index``: the path is returned unconditionally, even if the repository is bare or the file does not exist. Documentation and tests are included, covering standard usage, environment overrides, and bare-repository edge cases.

This update is part of the broader GSoC effort to expose repository component paths (hooks, index, grafts, etc.) through ``git repo info``. The series is now mechanically clean and ready for substantive technical review; this patch itself has no unresolved feedback from prior rounds. Key details for follow-up discussion: the ``path.index`` keys, the use of ``repo_get_index_file()``, and the unconditional path-return behavior.
