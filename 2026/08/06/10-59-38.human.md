This is the seventh patch in the ready-to-merge v7 series optimizing Git’s `paint_down_to_common()` function, which calculates merge bases. The patch introduces a `paint_state` struct to track per-side commit counters (PARENT1-only, PARENT2-only, and pending merge-base candidates) during the traversal, replacing the older `nonstale_queue` logic.

The change refactors `paint_down_to_common()` to use the new counters for termination, eliminating the need for the `max_nonstale` pointer-based check. The new `paint_queue_get()` helper drains the queue until all counters reach zero, which is functionally equivalent but slightly more efficient—some step counts drop by one in edge cases because stale commits are now discarded immediately after dequeuing rather than being processed. The patch also removes unused functions (`nonstale_queue_put_dedup()`, `nonstale_queue_get_dedup()`) and updates the technical documentation to reflect the new termination logic.

This is a well-motivated refactoring that simplifies the code while preserving correctness. The step-count changes in the tests (`t6600-test-reach.sh`) are minimal and expected, and the exhaustive switch in `paint_count_update()` clearly documents all valid flag combinations. The series as a whole is queued in Junio’s tree and addresses a real performance bottleneck for repositories with asymmetric histories; this patch is a key enabler for the early-termination optimization in later patches. No controversy or open questions remain here—it looks like a clean, incremental improvement.
