This is the second patch in the v3 series introducing `git repack --drop-filtered` for partial clones. It adds a new helper function, `list_objects_filter__filter_oidset()`, to the object-filtering subsystem. This helper lets callers apply a filter (currently only `blob:limit`) to an existing set of object IDs without performing a full object walk, which is exactly what `--drop-filtered` needs: it collects promisor blobs into an oidset and wants to know which ones exceed the size threshold.

The implementation is straightforward but pragmatic. Instead of reusing the existing filter machinery (which is tightly coupled to object traversal), the patch reimplements the `blob:limit` size check directly. A `NEEDSWORK` comment marks this duplication for future refactoring. The helper avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info, ensuring it never triggers network requests. It silently skips unreadable objects and only supports `blob:limit` filters for now, returning an error for any other filter type.

This patch is a clean, focused addition that enables the core functionality of the series. The duplication is acknowledged and scoped, so it doesn’t block the feature, but future work could unify the filter logic. The helper is well-documented and tested in later patches, and it integrates smoothly with the rest of the series. No controversy here—just a necessary plumbing piece for the `--drop-filtered` feature.
