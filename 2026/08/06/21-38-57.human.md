This is the fourth patch in Justin Tobler’s six-patch series making `git receive-pack` fully backend-agnostic by moving its packfile processing behind the ODB transaction interface. The patch updates the `unpack()` function and its callers to report errors via a caller-provided `strbuf` instead of returning static strings. This is a mechanical but necessary step toward the later switch to the generic `odb_transaction_write_pack()` interface, which cannot return string literals.

The change touches only `builtin/receive-pack.c` and is confined to error-reporting plumbing: `unpack()` and `unpack_with_sideband()` now write any error messages to a `strbuf` and return a negative value on failure, while `execute_commands()`, `report()`, and `report_v2()` are updated to use the new convention. The patch is well-scoped and does not alter observable behavior; it simply prepares the code for the transaction abstraction that follows in later patches.

The motivation is clear: the existing string-return pattern is incompatible with the ODB transaction layer, which needs to propagate errors through a uniform interface. The conversion looks clean and the commit message explains the rationale concisely. No test failures or edge cases are introduced by this patch, and the series as a whole remains part of the ongoing ODB abstraction effort led by Patrick Steinhardt. Reviewers are likely to focus on whether the new error-handling pattern is ergonomic and whether the `strbuf` lifetime is managed correctly across the call chain.
