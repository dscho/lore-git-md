This is the third patch in the v4 series adding path-related keys to `git repo info`. It implements `path.hooks.absolute` and `path.hooks.relative`, exposing the repository’s hooks directory in a scriptable format while respecting the `core.hooksPath` configuration override.

The patch adds two new keys that return the hooks directory path, either as an absolute or relative path. The implementation uses `repo_git_path_replace()` to resolve the hooks path, which automatically honors `core.hooksPath` (including environment overrides like `GIT_HOOKS_PATH`). When `core.hooksPath` is set to `/dev/null`, the absolute key returns that value verbatim, matching the behavior of `git rev-parse --git-path hooks`. The relative key returns the path relative to the current working directory, or `/dev/null` if that is the configured value (tested only on non-Windows platforms due to `/dev/null` not being a canonicalizable path on Windows).

The documentation updates `git-repo.adoc` to describe both keys, explicitly noting the `/dev/null` handling. The test suite (`t/t1900-repo-info.sh`) adds coverage for standard hooks, custom hooks via `core.hooksPath`, and the `/dev/null` edge case (guarded for non-Windows platforms). The test helper `test_repo_info_path` was extended to handle absolute paths (like `/dev/null`) without prepending the repository root.

This patch is uncontroversial in design, aligning with the series’ established pattern of exposing internal paths via `git repo info` while respecting Git’s configuration and environment overrides. The `/dev/null` handling was previously debated but is now documented and tested, resolving the open question from v3. Reviewers may still suggest minor naming adjustments (e.g., `path.hookdir` instead of `path.hooks`), but the implementation itself is mechanically clean and ready for substantive review. The files touched are `builtin/repo.c`, `Documentation/git-repo.adoc`, and `t/t1900-repo-info.sh`.
