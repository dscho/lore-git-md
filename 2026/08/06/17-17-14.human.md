This is a refactoring patch proposed by Jeff King (Peff) that cleans up the transport layer’s handling of remote object-info requests. The patch is a follow-up to Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support `%(objecttype)` in remote-object-info queries.

Peff’s patch removes two fields (`object_info_oids` and `object_info_results`) from the `git_transport_options` struct and instead passes them directly as function parameters. The current design stores these fields in the transport struct, which is conceptually awkward because they are only valid for a single request. This creates potential for subtle bugs if the transport outlives the stack variables it points to, and it obscures ownership and cleanup responsibilities. The patch also marks the OID array as `const` where appropriate, clarifying that it is purely an input to the function.

The change is mechanical and does not alter behavior. It affects seven files, primarily updating function signatures and call sites in `transport.c`, `transport-helper.c`, and `builtin/cat-file.c`. The patch is narrowly scoped and does not touch the protocol or on-disk formats. Peff notes that the cleanup is worth doing now, even though the current caller (`builtin/cat-file.c`) disconnects the transport immediately after the request, because it paves the way for future optimizations like reusing the same transport for multiple object-info requests.

This patch is a natural extension of Pablo’s series, which already refactored the object-info storage layer in patches 3 and 4. Peff’s change complements that work by making the transport layer’s interface more explicit and safer. The patch is well-motivated and uncontroversial; reviewers familiar with the transport subsystem may want to verify the updated function signatures, but no substantive objections are expected.
