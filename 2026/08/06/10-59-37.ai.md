This is patch 6/10 in the v7 series optimizing `paint_down_to_common()` for one-sided histories. It adds test coverage for clock-skew edge cases that could break the side-exhaustion optimization, along with deterministic step counts for existing and new edge-case tests.

The patch introduces two new clock-skew topologies (`se-*` and `se2-*`) where commit-date ordering (used in v1 commit-graphs without corrected commit dates) violates the topological invariant that children are dequeued before parents. In these topologies, the correct merge base has a *higher* committer date than its child, which could cause side-exhaustion to fire too early or return a too-deep merge base if the algorithm relied on dates. The tests verify that generation ordering (now enforced by the series) prevents these failures by ensuring children are visited before parents regardless of dates.

Key additions:
- **`se-*` topology**: A simple diamond where the merge base (`se-D`) has a higher date than its child (`se-C`). Tests that side-exhaustion doesn’t fire prematurely.
- **`se2-*` topology**: A more complex case with a redundant ancestor (`se2-MB2`). The correct merge base (`se2-MB1`) is reached via a low-date path (`se2-C`), while a high-date path (`se2-E`) reaches its parent. Tests that the correct base is found and redundant ancestors are discarded.
- **Step counts**: Added to all edge-case tests (including the new `mixed-finite-infinity` test from patch 5/10) to validate the optimization’s performance impact deterministically across all commit-graph modes (none/full/half/no-gdat).

The patch also introduces a `mixed-finite-infinity` test (setup in a helper block) where one query tip lies outside the commit-graph (INFINITY generation) and the other is inside (finite generation). This exercises the transition between generation-number regions and ensures side-exhaustion works correctly when the walk crosses from INFINITY to finite regions.

The test infrastructure (`test_paint_down_steps`) and clock-skew helper (`skew_commit`) were introduced in earlier patches, so this is purely additive coverage. The step counts (e.g., `6 4 6 6` for `se-*`) reflect the 100-1000x speedups the optimization achieves in asymmetric queries. No new symbols are introduced; the focus is on hardening the existing logic.
