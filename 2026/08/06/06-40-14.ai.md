This is the first patch in a five-part series overhauling gitk’s color-preference dialog. It is a **refactoring** patch confined to the Tcl/Tk UI layer of gitk.

The patch consolidates the logic that sets the initial colors of the color-swatch labels into the existing helper procedure `prefspage_set_colorswatches`. Currently the swatch colors are set twice: once when the dialog is created (inline in `prefspage_colors`) and again whenever the user picks a new color (via `prefspage_set_colorswatches`). This change removes the duplication by calling the helper once at dialog construction, so the same code path is used for both initial and updated colors.

The diff is mechanical: thirteen lines of inline color assignments are removed, and a single call to `prefspage_set_colorswatches` is added at the end of the dialog setup. No behavior changes are introduced; the only effect is cleaner code. The patch is a prerequisite for the later patches in the series, which will make the swatches themselves clickable and standardize button widths.
