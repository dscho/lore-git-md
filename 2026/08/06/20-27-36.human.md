This is a Bash completion patch for the `git history` command. It is the first of four patches in Vincent Mailhol’s v2 series adding shell completion for `git history` and its subcommands.

The patch teaches Git’s completion script to handle the basic structure of `git history`: completing subcommands (`drop`, `fixup`, `reword`, `split`) and their options, and ensuring that exactly one revision is completed before delegating to subcommand-specific logic. The v2 update addresses feedback by testing options both before and after revisions, avoiding option completion after `--`, and adding thorough test coverage in `t/t9902-completion.sh`.

The helper function `__git_history_has_revision` checks whether a revision has already been provided, so the completion script knows when to stop offering revisions and start offering subcommand-specific arguments. The implementation is clean and follows Git’s existing parse-options completion patterns. The tests verify that subcommands, options, and revisions are completed correctly, including edge cases like `--` termination.

This patch is narrowly scoped to the basic completion framework; the next three patches in the series will add completion for `--empty`, `--update-refs`, and pathspecs for `git history split`. The series as a whole looks ready for integration and should be uncontroversial.
