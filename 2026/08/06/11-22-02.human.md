This is the final patch in a seven-part series introducing `git repack --drop-filtered`, a new feature for partial clones that safely reclaims disk space by removing locally cached promisor blobs exceeding a size threshold. This patch adds the documentation for the new `--drop-filtered` and `--dry-run` options to `git-repack.adoc`.

The documentation clearly explains what the options do: `--drop-filtered` deletes promisor objects matching the `--filter` specification (currently limited to `blob:limit`), while `--dry-run` lists the objects that would be dropped without making any changes. It specifies the requirements (a promisor remote must be configured, `-a` is mandatory, and `-d` is implied), the incompatibilities (`--filter-to` and bitmaps), and the safety guards that prevent the command from running during ongoing operations or dropping blobs referenced by the current index.

The text is thorough and precise, covering edge cases like bare repositories (where safety checks are skipped) and the silent disabling of config-driven bitmaps. It also explains the rationale behind the implied `-d` and the behavior when bitmaps are disabled. The documentation reflects the feedback from earlier versions, particularly the softened language around recoverability and the reframing of safety guards as UX optimizations rather than correctness measures.

This patch completes the series, which now looks production-ready. The documentation is well-written and aligns with the implementation in the earlier patches, making it easy for users to understand how to use the new feature safely. No further changes appear necessary for this patch.
