The gitk color-preference dialog overhaul is nearly complete, with the v2 patch series now under final review. Johannes Sixt, the gitk maintainer, has addressed all prior feedback on this six-patch series, which aims to make the dialog more intuitive by turning color swatches into primary clickable elements, standardizing button widths, and rewriting labels in natural language. The changes are confined to the Tcl/Tk UI and don’t affect core Git functionality.

The only remaining discussion is cosmetic: the wording of labels and the visual ordering of color options. In this latest exchange, Sixt clarified that the “Marked line background” label actually controls the background color of lines revealed by the “Show origin of this line” feature in the diff panel—not search-highlighted commit messages, as previously thought. This correction doesn’t require any code changes, and the series is otherwise ready for integration. Mark Levedahl, the only reviewer so far, has focused on visual presentation and has already endorsed the look of the new buttons. Junio C Hamano’s earlier comment on label phrasing has been addressed, and no substantive concerns remain.
