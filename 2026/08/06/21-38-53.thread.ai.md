Subject: [PATCH 0/6] receive-pack: use ODB transaction for pluggable packfile writes
Series version: v4 (nine-patch series; addresses all v3 feedback, including ".keep" file placement design, context-aware unpack limit resolution, and include hygiene)
Originating author: Justin Tobler
Thread type: patch series

Core problem or goal
Extend the ODB transaction system to make `git receive-pack` fully backend-agnostic by replacing its hardcoded use of `git index-pack` and `git unpack-objects` (which assume the "files" backend) with a new generic transaction interface, `odb_transaction_write_pack()`. The goal is to enable alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles without being tied to the traditional files backend.

Current status
Under active review; series updated to v4 (nine patches) with all critical design flaws and reviewer feedback addressed. Still cooking in `seen`; no merge status change. Key improvements since v3:
- **".keep" file design**: Fixed the regression introduced in bdee7b3013 (July 2026) where `.keep` files were orphaned after ODB transaction commit. The patch (1/9) updates `index_pack_lockfile()` to accept an explicit `struct odb_source *` parameter, ensuring the `.keep` file is written to the quarantine directory during the transaction but derived from the *final* location in the main ODB. A new test in `t/t5547-push-quarantine.sh` verifies the `.keep` file is generated in the quarantine directory and removed from the main ODB after the push completes. The design now preserves race-avoidance properties by writing the `.keep` file to the main object directory at commit time and removing it during finalization. **Patrick Steinhardt’s review of v4 (patch 1/9) identifies a gap in test coverage**: the test does not verify that the `.keep` file is correctly migrated to the target repository during the reference update phase, which is critical for ensuring the packfile is protected from pruning while refs are being updated. The proposed test addition uses a `reference-transaction` hook to check for the `.keep` file’s presence in the main ODB during the reference update, then verifies its removal afterward.
- **Context-aware unpack limit resolution**: Extended the `odb_transaction_write_pack()` interface to accept an `enum odb_transaction_flags` parameter (e.g., `ODB_TRANSACTION_RECEIVE`), enabling the backend to resolve the correct configuration (`transfer.unpackLimit`/`receive.unpackLimit` for `git receive-pack`, `fetch.unpackLimit` for future `git fetch-pack` users). The `get_unpack_limit()` helper now takes the flags parameter and defaults to 100. The "files" backend stores the flags in `struct odb_transaction_files` and passes them to `get_unpack_limit()`. **Patrick Steinhardt’s review of patch 9/9 in v4 approves the design**, noting that passing `enum odb_transaction_flags` to `get_unpack_limit()` is future-proof and simplifies the logic by removing static caching.
- **Transaction lifecycle management**: Split `odb_transaction_commit()` into `commit()` and `finalize()` phases (patch 2/9), enabling backends to perform deferred cleanup after objects are made visible. The "files" backend uses this to remove ".keep" files during finalization. Added `odb_transaction_commit_and_finalize_or_die()` helper for callers that cannot recover from failures. `git receive-pack` now explicitly calls `finalize()` after reference updates. **Patrick Steinhardt’s review of patch 2/9 in v4 suggests a surface-level improvement to the commit message**, rewording the paragraph explaining the motivation for `odb_transaction_commit_and_finalize_or_die()` to better distinguish between the *behavior* (immediate finalization with no intermediate work) and the *rationale* (avoiding repetitive error handling). The proposed rewrite is more precise but does not affect the patch’s technical content.
- **Global state removal**: Eliminated reliance on the global `alt_shallow_file` variable (patch 3/9), static unpack limit caching (patch 4/9), and unpack-related globals (`receive_fsck_objects`, `transfer_fsck_objects`, `fsck_msg_types`, `max_input_size`, `reject_thin`, `quiet`) (patch 5/9). The unpack limit is now resolved lazily via `get_unpack_limit()`, and unpack options are passed explicitly via `struct unpack_opts`. The `get_unpack_limit()` helper reads `transfer.unpackLimit` and `receive.unpackLimit` (with the latter taking precedence) from the repository, replacing the deleted globals and their configuration callbacks.
- **Explicit ODB source tracking**: Patch 8/9 (new in v4) addresses fragility in the ODB transaction system by returning the newly installed temporary ODB source directly from `odb_set_temporary_primary_source()` instead of relying on the caller to assume it is the first entry in the ODB source list. The function now returns the installed `struct odb_source *` and reports the previous primary source via an optional `prev_source` out parameter. The propagation continues through `tmp_objdir_replace_primary_odb()`, which now also returns the installed source, and the "files" ODB transaction struct (`struct odb_transaction_files`) gains a `quarantine` field to store it. This eliminates fragile source list ordering assumptions and enables the transaction commit logic to access the quarantine source directly during finalization.
- **Include hygiene**: Added a forward declaration for `struct odb_source` in `pack.h` to avoid including `odb/source.h`, addressing Patrick Steinhardt’s surface-level feedback from v3.
- **Error reporting and file descriptor passing**: Refactored error reporting in `unpack()` and `unpack_with_sideband()` to use a `strbuf` instead of returning static strings (patch 6/9), aligning with the established ODB transaction pattern. The explicit file descriptor parameter for the incoming packfile is now introduced in patch 7/9, enabling backend-agnostic use.
- **Generic `odb_transaction_write_pack()` interface**: Patch 9/9 (new in v4) introduces the backend-agnostic `odb_transaction_write_pack()` interface, replacing the hardcoded `unpack()` logic in `builtin/receive-pack.c` with a callback. The "files" backend implementation reuses the existing `unpack()` logic but now manages ".keep" lockfiles within the transaction lifecycle, ensuring they are removed during finalization. The `struct odb_transaction_files` gains fields to track multiple ".keep" lockfiles (`pack_lockfiles`, `pack_lockfiles_nr`, `pack_lockfiles_alloc`) and the transaction flags (`flags`). The `odb_transaction_write_pack_opts` struct bundles unpack options (fsck settings, shallow file, max input size, etc.) previously passed as separate globals or function parameters. Call sites in `receive-pack.c` are updated to use the new interface, and the explicit `delete_tempfile(&pack_lockfile)` call is removed since lockfile cleanup is now handled by the transaction’s `finalize()` callback.
