Subject: [PATCH 0/6] receive-pack: use ODB transaction for pluggable packfile writes
Series version: v1 (next version expected to address interface naming, error reporting ergonomics, const-correctness, backend-specific optimizations, and struct initialization refinements)
Originating author: Justin Tobler
Thread type: patch series

Core problem or goal
Extend the ODB transaction system to make `git receive-pack` fully backend-agnostic by replacing its hardcoded use of `git index-pack` and `git unpack-objects` (which assume the "files" backend) with a new generic transaction interface, `odb_transaction_write_pack()`. The goal is to enable alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles without being tied to the traditional files backend.

Current status
Under active review; not yet merged. Series remains at v1, posted by Justin Tobler as part of the ongoing ODB abstraction effort led by Patrick Steinhardt. No merge status change; still cooking in `seen` or under review. The next iteration is expected to rename `odb_transaction_release()` to `odb_transaction_finalize()`, clarify caller documentation, enable error reporting for post-commit cleanup failures, address ergonomic feedback on struct initialization and mutation patterns, mark `strbuf` parameters as `const` for const-correctness, reuse the `unpack_status` buffer to reduce memory allocations, narrow `odb_reprepare()` to reprepare only the transaction’s source ODB, and move `unpack_limit` to be handled internally by the backend.

Key technical details
- New symbols: `odb_transaction_finalize()` (renamed from `odb_transaction_release()`; decouples transaction cleanup from commit, enabling backend-specific deferred cleanup such as removing ".keep" lockfiles; will be capable of reporting errors), `odb_transaction_write_pack()` (generic interface for packfile writes, introduced in patch 6/6), `struct odb_transaction_write_pack_opts` (bundles previously global unpack options: shallow file, fsck settings, max input size, etc.), and `struct unpack_opts` (bundles eight previously global variables in `builtin/receive-pack.c`: `fsck_msg_types`, `shallow_file`, `max_input_size`, `fsck_objects`, `unpack_limit`, `reject_thin`, `err_fd`, `quiet`). The `write_pack` callback is added to `struct odb_transaction`.
- Files touched: `builtin/receive-pack.c` (main refactoring target: explicit shallow-file path passing through the call chain, introduction of `struct unpack_opts`, conversion of error reporting from direct string returns to `strbuf` output parameters in `unpack()` and `unpack_with_sideband()`, explicit file descriptor passing for the incoming packfile in `unpack()`, and replacement of `unpack()` with calls to `odb_transaction_write_pack()`), `odb/transaction.c` (new API and core transaction logic), `object-file.c` (implementation of the "files" backend for `odb_transaction_write_pack()`), related headers, plus mechanical updates in `builtin/add.c`, `builtin/unpack-objects.c`, `builtin/update-index.c`, `cache-tree.c`, and `object-file.c` to adopt the new `finalize` callback.
- Behavior change: `receive-pack` no longer directly invokes `git index-pack` or `git unpack-objects`; instead, it delegates packfile processing to the ODB backend via the transaction system. The first five patches are plumbing-only and do not change observable behavior. The sixth patch completes the switch to backend-agnostic packfile processing by introducing `odb_transaction_write_pack()` and moving the packfile ingestion logic into `object-file.c`, where it becomes the "files" backend implementation.
- On-disk format: no changes; the series remains plumbing-only.
- Test coverage: relies on existing `receive-pack` and transaction tests. No test failures or edge cases introduced by the series.

Open questions and loose ends
- Transaction lifecycle design: the author and Patrick Steinhardt have converged on renaming `odb_transaction_release()` to `odb_transaction_finalize()` and making it capable of reporting errors, as failures in cleaning up ".keep" lockfiles (which can occur in the "files" backend) should not be silently ignored. The commit message will clarify that `builtin/receive-pack.c` is the only caller where the transaction is not finalized immediately after commit, because it needs to retain ".keep" files until references are updated.
- Backend-specific optimizations: Patrick Steinhardt raised two questions in his review of patch 6/6: (1) whether `odb_reprepare()` (which refreshes the entire object database after packfile ingestion) is overly broad now that the logic is part of an ODB transaction, and (2) whether `unpack_limit` (a threshold for storing objects in loose vs. packed format) belongs in the generic `odb_transaction_write_pack_opts` struct, given that it is irrelevant to backends that do not use loose/packed storage. The author has accepted both suggestions: `odb_reprepare()` will be narrowed to reprepare only the transaction’s source ODB, and `unpack_limit` will be handled internally by the backend.
- Global state removal: Patrick Steinhardt’s review of patch 2/6 confirmed the mechanical soundness of the approach, and his review of patch 3/6 is similarly positive but flags three ergonomic concerns: (1) the diff is hard to audit for completeness due to scattered global references, (2) the ternary initialization of `fsck_objects` inside the struct initializer is visually awkward, and (3) the late assignment of `err_fd` in `unpack_with_sideband()` forces mutation of the passed-in struct, which feels unergonomic. Steinhardt accepts these trade-offs as necessary for the larger goal but invites future scrutiny when the function moves to a different file in a later patch.
- Error reporting ergonomics: the fourth patch shifts error reporting from direct string returns to `strbuf` output parameters. Patrick Steinhardt’s review finds the new calling convention clearer but suggests two refinements: (1) marking the `strbuf` parameters in `report()` and `report_v2()` as `const` for const-correctness, and (2) reusing the `unpack_status` buffer across multiple runs to reduce memory allocations. These refinements have been accepted by the author and will be incorporated in the next revision.
- File descriptor passing: the fifth patch introduces explicit file descriptor passing for the incoming packfile in `unpack()`; reviewers may evaluate whether this abstraction is ergonomic and whether it interacts cleanly with the new `odb_transaction_write_pack()` interface.
