Subject: [PATCH 0/6] receive-pack: use ODB transaction for pluggable packfile writes
Series version: v2 (addresses all feedback from v1: interface naming, error reporting ergonomics, const-correctness, backend-specific optimizations, struct initialization refinements, buffer reuse clarification, shallow-file path plumbing, and removal of `unpack_limit` global state)
Originating author: Justin Tobler
Thread type: patch series

Core problem or goal
Extend the ODB transaction system to make `git receive-pack` fully backend-agnostic by replacing its hardcoded use of `git index-pack` and `git unpack-objects` (which assume the "files" backend) with a new generic transaction interface, `odb_transaction_write_pack()`. The goal is to enable alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles without being tied to the traditional files backend.

Current status
Under active review; series updated to v2. Still cooking in `seen`; no merge status change. The next iteration, if any, will likely focus on reviewer feedback about the ergonomics of the new interface, the robustness of the transaction lifecycle, and the mechanical soundness of the global state removal.

Key technical details
- New symbols: `odb_transaction_finalize()` (renamed from `odb_transaction_release()`; decouples transaction cleanup from commit, enabling backend-specific deferred cleanup such as removing ".keep" lockfiles; capable of reporting errors), `odb_transaction_write_pack()` (generic interface for packfile writes, introduced in patch 7/7), `struct odb_transaction_write_pack_opts` (bundles previously global unpack options: shallow file, fsck settings, max input size, etc.), `struct unpack_opts` (bundles eight previously global variables in `builtin/receive-pack.c`: `fsck_msg_types`, `shallow_file`, `max_input_size`, `fsck_objects`, `unpack_limit`, `reject_thin`, `err_fd`, `quiet`), and `get_unpack_limit()` (lazy, per-repository helper that resolves `receive.unpackLimit` → `transfer.unpackLimit` → default of 100, introduced in patch 3/7). The `write_pack` callback is added to `struct odb_transaction`.
- Files touched: `builtin/receive-pack.c` (main refactoring target: explicit shallow-file path passing through the call chain, introduction of `struct unpack_opts`, conversion of error reporting from direct string returns to `strbuf` output parameters in `unpack()` and `unpack_with_sideband()`, explicit file descriptor passing for the incoming packfile in `unpack()`, replacement of `unpack()` with calls to `odb_transaction_write_pack()`, removal of global `unpack_limit` and related configuration globals, and mechanical updates to adopt the new `finalize` callback), `odb/transaction.c` (new API and core transaction logic), `object-file.c` (implementation of the "files" backend for `odb_transaction_write_pack()`), related headers, plus mechanical updates in `builtin/add.c`, `builtin/unpack-objects.c`, `builtin/update-index.c`, `cache-tree.c`, and `object-file.c` to adopt the new `finalize` callback.
- Behavior change: `receive-pack` no longer directly invokes `git index-pack` or `git unpack-objects`; instead, it delegates packfile processing to the ODB backend via the transaction system. The first six patches are plumbing-only and do not change observable behavior. The seventh patch completes the switch to backend-agnostic packfile processing by introducing `odb_transaction_write_pack()` and moving the packfile ingestion logic into `object-file.c`, where it becomes the "files" backend implementation.
- On-disk format: no changes; the series remains plumbing-only.
- Test coverage: relies on existing `receive-pack` and transaction tests. No test failures or edge cases introduced by the series.
- Backend-specific optimizations: `odb_reprepare()` is now narrowed to reprepare only the transaction’s source ODB (rather than the entire object database), and `unpack_limit` is handled internally by the backend, as it is irrelevant to backends that do not use loose/packed storage.

Open questions and loose ends
- Transaction lifecycle design: the interface now supports error reporting in `odb_transaction_finalize()`, which is critical for the "files" backend’s deferred cleanup of ".keep" lockfiles. The commit message clarifies that `builtin/receive-pack.c` is the only caller where the transaction is not finalized immediately after commit, because it needs to retain ".keep" files until references are updated. The first four patches in v2 (including this one) introduce mechanical refactoring steps to decouple transaction cleanup from commit and eliminate global state (shallow-file path, `unpack_limit`, and the eight variables now in `struct unpack_opts`), enabling backend-specific deferred operations.
- Error reporting ergonomics: the shift to `strbuf` output parameters is complete, with const-correctness refinements incorporated. The `unpack_status` buffer is initialized once per invocation of `cmd_receive_pack()`, so reuse is unnecessary. Patch 5/7 (new email) converts `unpack()` and `unpack_with_sideband()` from returning error strings to writing them into a caller-provided `strbuf` and returning a negative value on failure, addressing feedback from v1 about error reporting ergonomics.
- File descriptor passing: the explicit file descriptor passing for the incoming packfile in `unpack()` is now part of the interface; reviewers may evaluate whether this abstraction is ergonomic and whether it interacts cleanly with the new `odb_transaction_write_pack()` interface.
- Struct initialization and mutation patterns: the ternary initialization of `fsck_objects` and the late assignment of `err_fd` in `unpack_with_sideband()` remain as trade-offs for the larger goal of removing global state. Patrick Steinhardt accepted these as necessary but invited future scrutiny when the function moves to a different file.
