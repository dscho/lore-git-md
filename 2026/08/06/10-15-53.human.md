This is the fourth patch in K Jayatheerth’s seven-part GSoC series adding new path-related keys to the `git repo info` command. This specific patch implements `path.index.absolute` and `path.index.relative`, exposing the repository’s index file location in a scriptable format.

The patch is straightforward: it adds two new keys that return the absolute and relative paths to the index file, respecting the `GIT_INDEX_FILE` environment override. The behavior matches `git rev-parse --git-path index`—the path is returned unconditionally, even if the file doesn’t exist or the repository is bare. Documentation and tests are included, covering standard cases, environment overrides, and bare repositories.

The implementation is clean and aligns with the series’ established pattern: each key is implemented as a pair of functions (absolute/relative) in `builtin/repo.c`, documented in `git-repo.adoc`, and tested in `t/t1900-repo-info.sh`. The test coverage is thorough, including edge cases like bare repositories and environment overrides.

There’s little here to object to technically. The only potential discussion point is whether `path.index` is the best name—some reviewers might prefer `path.index-file` for consistency with `git rev-parse` terminology, but the current name is clear and matches the series’ existing naming scheme. The patch is ready for review, though substantive feedback is still welcome on naming or edge-case behavior.
