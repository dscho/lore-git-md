This is the fourth patch in Justin Tobler’s six-patch series converting `git receive-pack` to use the ODB transaction system for pluggable packfile writes. The patch updates the `unpack()` and `unpack_with_sideband()` functions to report errors via a caller-provided `strbuf` instead of returning error strings directly. This change is preparatory plumbing for the later introduction of the generic `odb_transaction_write_pack()` interface, which will move the unpack logic behind the ODB abstraction boundary.

The patch touches only `builtin/receive-pack.c`, converting the error-reporting paths in `unpack()` and `unpack_with_sideband()` to write messages into a `struct strbuf *err_msg` and return a negative value on failure. Call sites are updated to check the return value and pass the error buffer to the reporting functions (`report()` and `report_v2()`), which now expect a `strbuf` instead of a raw string. The change is mechanical and does not alter observable behavior; it simply shifts error reporting from return values to an output parameter.

This is a clean, well-scoped refactoring that fits neatly into the series’ goal of eliminating global state and making `receive-pack` backend-agnostic. The commit message clearly explains the motivation (preparing for the ODB transaction interface) and the mechanical nature of the change. No test failures or edge cases are introduced by this patch, and the error-handling logic remains robust. Reviewers are likely to focus on whether the `strbuf` approach is ergonomic for future callers and whether the error propagation is sufficiently clear.
