This is the fifth patch in the v3 series introducing `git repack --drop-filtered` for partial clones. It implements the actual removal of filtered promisor blobs, transitioning the feature from a dry-run preview (as in earlier patches) to a real disk-space reclamation operation.

The patch wires up the `drop_oids` set computed by `enumerate_promisor_blobs()` to `repack_promisor_objects()`, which now accepts an optional `to_drop` parameter. When `--drop-filtered` is specified without `--dry-run`, the rebuilt promisor pack excludes the blobs in `drop_oids`, and the old promisor packs (which still contain those blobs) are removed because `--drop-filtered` implies `-d`. The repack machinery’s existing write-before-delete and fsync guarantees ensure crash safety. The test confirms that a large promisor blob is no longer present locally after the command runs, while a smaller one remains.

This is a straightforward plumbing change that completes the core functionality. The commit message clearly explains the implied `-d` and the crash-safety guarantees, and the test is minimal but sufficient. No new edge cases or open questions are introduced; the patch simply turns the dry-run logic into a real operation. Reviewers familiar with the earlier patches in the series will recognize this as the expected next step.
