This is a substantive review of the eleventh patch in Johannes Schindelin’s v2 series addressing unchecked return values flagged by Coverity. Jeff King (Peff) identifies a resource leak introduced by the patch itself: if `dup2(temporary_stdout_fd, 1)` fails, the code breaks out of the bisect-run loop without closing the file descriptor stored in `saved_stdout`, which was successfully duplicated by the preceding `dup(1)` call. The leak is a direct consequence of the patch’s error-handling logic and was not present in the original code. Peff’s observation is precise, actionable, and grounded in static analysis (Coverity), confirming the issue is real and not theoretical. The fix will require an additional `close(saved_stdout)` call in the error path before breaking out of the loop. This patch, which was previously considered technically complete and uncontroversial, now has an open correctness issue that must be resolved before integration. The broader series remains under review, with only this patch and the third (reftable/block.c) currently blocked on unresolved feedback.
