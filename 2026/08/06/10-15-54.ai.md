This is the fifth patch in the v4 series adding path-related keys to `` `git repo info` ``. It introduces `path.grafts.absolute` and `path.grafts.relative` to expose the repository’s grafts file location in a scriptable format, mirroring the behavior of `` `git rev-parse --git-path info/grafts` ``.

The implementation is straightforward: two new getter functions (`get_path_grafts_absolute` and `get_path_grafts_relative`) call `repo_get_graft_file()` and format the result with `format_path()`, respecting the `GIT_GRAFT_FILE` environment override. The paths are returned unconditionally, even if the file does not exist, aligning with the series’ design principle and Junio’s prior endorsement for `path.index` and `path.grafts`. Documentation and tests are included, covering both the standard case and an environment-override scenario.

No open questions remain for this patch; it is mechanically clean and ready for substantive review. The only potential discussion point is whether the key name (`path.grafts`) or suffix semantics could be adjusted for consistency with existing Git terminology, but the current design is uncontroversial.
