This is a gentle ping on a sparse-checkout/sparse-index performance patch that has been under review since August 6.

The patch fixes an unnecessary index expansion in `repo_index_has_changes()` when HEAD is unborn (e.g., on a newly created orphan branch). The fix is straightforward: instead of falling back to a direct index walk that forces sparse directory expansion, the code now compares against the empty tree, which is logically equivalent to an unborn HEAD. This keeps the unborn-branch case on the same efficient diff code path as normal tree comparisons.

The original submission included a clear commit message, a net reduction of 28 lines in `read-cache.c`, and a new test case in `t1092-sparse-checkout-compatibility.sh` that verifies the unborn-branch scenario reports paths inside sparse directories without expanding the index. No feedback has been posted yet, so the patch remains in its initial state.
