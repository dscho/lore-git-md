This is the second patch in the v3 series introducing `git repack --drop-filtered` for partial clones. It adds a new helper function, `list_objects_filter__filter_oidset()`, to the object filtering subsystem. This helper lets callers apply a filter (currently only `blob:limit`) to an existing set of OIDs without performing an object walk, which is exactly what `--drop-filtered` needs to identify which promisor blobs exceed the size threshold.

The patch is straightforward: it implements the helper in `list-objects-filter.c` and declares it in `list-objects-filter.h`. The implementation reimplements the `blob:limit` size check directly rather than reusing the existing filter machinery, which is currently tied to the object-walk path. A `NEEDSWORK` comment marks this duplication for future refactoring. The helper avoids lazy fetches by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` when reading object info, ensuring it only operates on locally available data.

This is a refactoring patch that enables the core functionality of the series. The helper is cleanly scoped and well-documented, with clear error handling (unsupported filters return -1, unreadable objects are silently skipped). The duplication of the size check is a minor wart, but the patch is otherwise production-ready. Future work to unify the filter logic would be welcome but is not blocking. The patch is part of a well-structured series that has already addressed all feedback from earlier iterations, and this specific change looks solid.
