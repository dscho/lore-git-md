This is the first patch in Patrick Steinhardt’s v4 series making on-disk ODB structures pluggable, and it is now a standalone correctness fix slated for early graduation to `next`. The patch fixes a latent bug in loose-object map loading: when iterating through multiple ODB sources (e.g., the main repository and its alternates), Git always loaded the loose-object map from the common `objects/` directory instead of the path specific to each source. This caused alternates’ loose-object maps to be silently ignored, breaking repositories that rely on compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility).

The fix is surgical: `load_one_loose_object_map()` now takes only the loose source and constructs the map path from `loose->base.path` instead of using the repository’s common directory. The patch also adds a regression test in `t/t1016-compatObjectFormat.sh` that verifies `git rev-parse` correctly resolves an object borrowed from an alternate when using a compatibility hash algorithm. Toon Claes provided the test case, which Patrick incorporated in v2, elevating the patch’s status from a refactoring to a correctness fix with dedicated coverage.

The change is minimal and targeted, touching only `loose.c` and the test script. No new symbols are introduced; the patch simply corrects the path resolution logic.
