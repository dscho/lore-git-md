This thread is about adding Bash completion for the new `git history` command. Vincent Mailhol sent a second version of the patch series addressing earlier feedback, particularly around how the completion script handles the required revision argument before subcommands and options.

The main discussion now is a stylistic one between Vincent and reviewer D. Ben Knoble. They’re debating the best way to structure the `case` statement that completes values for `--empty` and similar options. Vincent’s current approach uses a single `case "$cur"` block, which he argues is cleaner and avoids duplication. Knoble suggests using the more idiomatic `case "$subcommand,$cur"` pattern seen elsewhere in Git’s completion scripts, which he believes would be more maintainable and consistent. Neither approach affects functionality, and the choice is still open.

The series is under review, with no major technical objections remaining. The maintainability of the helper function that checks for a revision argument is still a concern, but Vincent and Knoble now agree on a simplified approach that ignores the rare `--option <value>` syntax (as opposed to `--option=value`), aligning with Git’s documented conventions. A third version of the series is likely to incorporate this and other minor feedback before moving toward acceptance.
