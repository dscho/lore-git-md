This thread is about adding Bash completion for the new `git history` command. Vincent Mailhol sent a second version of the patch series addressing earlier feedback, and the discussion has now narrowed to a stylistic choice in the completion script: whether to check the subcommand or the option first.

The current implementation checks the option first, which Vincent argues avoids code duplication and keeps the logic cleaner. D. Ben Knoble prefers the opposite order—checking the subcommand first—for consistency with the rest of Git’s completion codebase. Both approaches work correctly, and the debate is purely about readability and maintainability. Vincent’s latest email lays out the trade-offs, showing how the alternative would either duplicate logic or introduce potential conflicts.

The series itself is technically sound and close to being ready. The only remaining open question is whether Vincent will adjust the code structure in a future version to match Knoble’s preference. No other objections or technical issues are holding it up.
