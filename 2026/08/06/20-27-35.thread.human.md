This thread is about adding Bash completion for the new `git history` command. Vincent Mailhol sent a second version of the patch series after addressing feedback on how revisions and subcommands are handled. The completion now covers all subcommands (`--empty`, `--update-refs`, and `split` pathspecs) and correctly handles `--` termination.

Patrick Steinhardt reviewed the patch and pointed out a maintainability issue: the helper function that checks whether a revision has been provided hardcodes the list of options that take arguments. He suggested simplifying the logic by always offering reference completions unless `--` has been seen, using Git’s existing `__git_hash_doubledash` helper. This would make the code easier to maintain but might occasionally suggest irrelevant completions. The series is otherwise uncontroversial and ready for integration, though this feedback may lead to a third version. No other reviews have been posted yet.
