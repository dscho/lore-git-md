This is the v4 cover letter for Patrick Steinhardt’s six-patch series that makes the creation of on-disk object database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort and is now ready for review after incorporating feedback from v3.

The goal remains the same: decouple the creation of backend-specific directories (like `objects/info` and `objects/pack`) from the generic repository setup code. The top-level `objects/` directory is still mandatory for repository recognition, but individual backends now handle their own subdirectory creation via a new `create_on_disk` callback. This enables future ODB backends to implement custom on-disk layouts without modifying core setup logic.

Key changes in v4 reflect a significant design concession. Patrick has dropped the `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag in favor of Toon Claes’s alternative: making ODB creation an explicit step at every call site by moving `odb_new()` out of `apply_repository_format()`. This change is mechanical and affects only the initialization sequence, but it simplifies the design and aligns with the longer-term goal of moving `apply_repository_format()` into `repo_init()`. The series also removes a redundant `xstrdup()` call and marks a new `die()` message as translatable.

The first patch in the series is already listed in Junio’s "What's cooking" report as "will merge to 'next'" due to its status as a correctness fix with dedicated test coverage. The remaining patches (2–6) are uncontroversial and ready for merging, pending the revised initialization sequence in patch 4. The series touches `odb.c`, `odb.h`, `setup.c`, `repository.c`, and related files, introducing new functions and structures while removing hardcoded assumptions about directory layouts.

This is infrastructure work with no immediate user-visible impact, but it’s a foundational step for future ODB backends that don’t follow the traditional loose/pack layout. The series is based on the recent "7th batch" integration (commit `9a0c4701dc`), indicating it’s targeting the current development cycle.
