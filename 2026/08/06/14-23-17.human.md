This is the fourth patch in Patrick Steinhardt’s six-patch series making Git’s on-disk object database (ODB) structures pluggable, now revised to adopt Toon Claes’s alternative design. The patch abandons the earlier `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag and instead makes ODB creation an explicit step at every call site by moving `odb_new()` out of `apply_repository_format()`. This change is purely mechanical, affecting only the initialization sequence in `repository.c` and `setup.c`, and directly reverts the refactoring introduced in the previous version of this patch.

The patch updates four call sites (`repo_init()`, `enter_repo()`, `setup_git_directory_gently()`, and a new helper function `create_object_database()`) to call `odb_new()` explicitly after `apply_repository_format()`. The only exception is `init_db()`, where ODB creation is deferred until `create_object_database()` is called, aligning with the series’ goal of decoupling repository configuration from ODB initialization. The new `create_object_database()` helper replaces the old `create_object_directory()` and encapsulates both ODB initialization and on-disk structure creation, simplifying the path for the subsequent patch that moves on-disk structure creation into the `struct odb_source` backends.

Toon Claes’s review raises two minor points: the docstring for `apply_repository_format()` in `setup.h` is now outdated since the function no longer initializes the ODB, and there is an inconsistent formatting change in `init_db()` where the `apply_repository_format()` call is split across multiple lines while other call sites remain single-line. Neither issue is a blocker, and the patch is otherwise uncontroversial. The series remains on track for merging, with the first patch already marked as "will merge to 'next'" in Junio’s "What's cooking" report. This patch is a prerequisite for the final patch in the series, which implements the `create_on_disk` callback in the "files" backend.
