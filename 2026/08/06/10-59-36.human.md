This is the fifth patch in the ready-to-merge v7 series optimizing Git’s `paint_down_to_common()` function for one-sided histories. The patch adds Trace2 instrumentation to count and report the number of commits visited during the paint walk, enabling observable measurement of optimization impact without relying solely on wall-clock benchmarks.

The change is straightforward: it increments a `steps` counter in the main loop of `paint_down_to_common()` and emits the total via `trace2_data_intmax()` at the end. The test suite (`t6600-test-reach.sh`) is updated to verify the step counts across all commit-graph modes (none, full, half, no-gdat) using the new `test_paint_down_steps()` helper, which checks Trace2 event files for the expected values. The test cases now also capture Trace2 output for each mode, replacing the previous `run_all_modes()` implementation with a more granular approach that ensures deterministic assertions.

This instrumentation is a key enabler for the series’ performance claims, as it allows future optimizations (like the side-exhaustion logic in later patches) to be quantitatively validated. The patch itself is uncontroversial and well-tested, with no behavioral changes—just observability. It’s part of a larger, thoroughly reviewed effort that’s already queued in Junio’s tree; the only remaining hurdle is additional review bandwidth. For developers tracking Git’s performance work, this is a small but essential piece of the puzzle.
