This is patch 7/10 in the v7 series optimizing `paint_down_to_common()` for one-sided histories. The patch introduces a `paint_state` struct to track per-side commit counters (PARENT1-only, PARENT2-only, and pending merge-base candidates) during the paint walk, replacing the old `max_nonstale` pointer-based termination logic with explicit counters.

The core change refactors `paint_down_to_common()` to use the new `paint_state` struct and helper functions (`paint_queue_put()`, `paint_queue_get()`, `paint_count_update()`). The counters are maintained via a signed delta system that adjusts the appropriate bucket when commits are enqueued or dequeued. The termination condition now checks whether all counters are zero, which is functionally equivalent to the old `max_nonstale` logic but more explicit and easier to reason about. The patch also removes unused functions (`nonstale_queue_put_dedup()`, `nonstale_queue_get_dedup()`) that became redundant with the new struct.

The change is a refactoring with no intended behavior change, but the new "pop first" logic in `paint_queue_get()` causes the loop to exit one iteration earlier in some topologies, reducing step counts by one in affected test cases (e.g., `pending-stale` and `se2-*` topologies). The documentation in `paint-down-to-common.adoc` is updated to reflect the new termination logic, replacing references to `max_nonstale` with the counter-based approach.
