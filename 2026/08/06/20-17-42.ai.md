This is a follow-up discussion in the ongoing trailer-parsing bugfix thread. His proposal would add a rule to ignore lines between `^[` and `]$`, preventing false trailers like `[peff: this is a comment: not a trailer]`. While acknowledging this is a Linux/Git-specific convention, he notes it would reduce accidental trailer misparsing without complicating the existing rules.

The discussion remains exploratory—no code changes are proposed yet—but it highlights a potential future direction for making trailer parsing more robust. The current patch (excluding `://`) is still the immediate focus, with the `starts_with()` tweak as a trivial follow-up.
