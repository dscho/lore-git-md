This is a test infrastructure patch, part of the larger `paint_down_to_common()` optimization series (v7, patch 2/10). It introduces `test_trace2_data_singular()`, a more robust diagnostic helper for Trace2 data assertions in Git's test suite.

The new helper replaces the existing `test_trace2_data` (a bare `grep` that fails silently) with a function that verifies a Trace2 event appears exactly once and reports detailed mismatches: missing keys, duplicate entries, or value mismatches. Output goes to FD 4, matching the style of `test_grep`. The implementation uses `sed` to extract values and checks for newlines (`$LF`) to detect duplicates.

This is a **surface-level improvement**—it doesn’t change Git’s behavior but makes test failures easier to debug. The patch is well-motivated (the original `grep`-only approach was brittle) and aligns with the test suite’s existing conventions. It’s already been reviewed and incorporated into the series, with René Scharfe’s suggestion to use `$LF` for consistency.

For the broader series, this patch enables deterministic step-count assertions in later commits (e.g., `paint_down_to_common steps 9`). The helper itself is generic and could be reused elsewhere in the test suite. No controversy or open questions here—just a small but useful cleanup.
