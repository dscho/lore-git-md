This is the fifth patch in K Jayatheerth’s GSoC v4 series adding six new path-related keys to the `git repo info` command. This patch implements `path.grafts.absolute` and `path.grafts.relative`, exposing the location of the repository’s graft file in a scriptable format.

The graft file (`info/grafts`) defines alternate parent relationships for commits, and scripts currently retrieve its path via `git rev-parse --git-path info/grafts`. The new keys provide the same information through the `git repo info` interface, respecting the `GIT_GRAFT_FILE` environment override. Like the existing `path.index` and `path.hooks` keys, these keys return the path unconditionally—even if the file does not exist or the repository is bare—aligning with `git rev-parse --git-path` precedent. The implementation uses `repo_get_graft_file()` and the shared `format_path()` helper to generate absolute and relative paths.

The patch touches three files: `Documentation/git-repo.adoc` (documenting the new keys), `builtin/repo.c` (adding the two new getter functions and registering them in the `repo_info_field` table), and `t/t1900-repo-info.sh` (adding test coverage for the standard path and the `GIT_GRAFT_FILE` override). The tests verify that the keys return the expected paths in both absolute and relative forms.

This patch is uncontroversial in design; the unconditional path-return behavior was explicitly endorsed by Junio in an earlier round, and the naming (`path.grafts`) follows the established pattern for other path keys. The only potential discussion point is whether the suffix semantics (`absolute`/`relative`) are sufficiently intuitive, but that would apply to the entire series rather than this patch specifically. The implementation is clean, well-tested, and ready for review.
