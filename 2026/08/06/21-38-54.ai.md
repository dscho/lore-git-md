This is the first patch in Justin Tobler’s six-patch series extending the ODB transaction system to support pluggable packfile writes in `git receive-pack`. It introduces `odb_transaction_release()`, a new interface that decouples transaction cleanup from commit, enabling backend-specific deferred cleanup (e.g., removing ".keep" lockfiles after references are updated).

The patch is mechanical and well-scoped: it stops freeing the transaction in `odb_transaction_commit()`, adds the new `release` callback to the `odb_transaction` struct, and updates all callers of `odb_transaction_commit()` to explicitly call `odb_transaction_release()` afterward. The changes touch a handful of builtins (`add`, `receive-pack`, `unpack-objects`, `update-index`), `cache-tree.c`, `object-file.c`, and the transaction core in `odb/transaction.c`. The commit message clearly explains the motivation—enabling post-commit cleanup for the "files" backend—and flags the design uncertainty around whether `release` is the right place for this logic, inviting reviewer feedback.

This is a foundational change for the series: the subsequent patches will build on this interface to refactor `receive-pack` and implement the generic `odb_transaction_write_pack()` interface. The patch looks clean and aligns with the ongoing ODB abstraction effort led by Patrick Steinhardt. Reviewers will likely focus on whether the `release` callback is sufficiently generic and whether the error handling remains robust after the split.
