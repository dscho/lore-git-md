This is a bug report about a regression in `git rebase` when commit graphs are enabled. The issue was bisected to commit `bb5da75d61` ("commit: use commit graph in `lookup_commit_reference_gently()`"), authored by Patrick Steinhardt, who has been CC’d.

The reporter, Florian Schmidt, encounters a fatal error during `git rebase`: `error: Could not read 157b7492624beac3ac667dd3a84de9969377866b` followed by `fatal: invalid commit position. commit-graph is likely corrupt`. The error disappears when disabling commit graphs (`-c core.commitGraph=false`), suggesting the commit graph is involved. The problematic commit OID (`157b7492624...`) does not exist in the main repository but *does* exist in one of the submodules (`rpmsrc/qemu-kvm`), hinting at confusion between the main repo and submodule object stores.

The regression appeared between Git v2.53 and v2.54. In v2.53, the same error appears but the rebase continues, while in v2.54 (and v2.55) it becomes fatal. The reporter notes that even in v2.53, the errors are absent when commit graphs are disabled, suggesting a deeper issue with how commit graphs interact with submodules. Philippe Blain, who forwarded the report, suggests creating a minimal reproducer as a next step. The report looks credible and well-documented, with clear steps and bisect results.
