This is the third patch in the v3 series introducing `git repack --drop-filtered` for partial clones. It extends the promisor pack rebuilding machinery to support excluding specific objects, which is the core mechanism the new feature will use to drop oversized promisor blobs.

The patch adds a `to_drop` oidset parameter to `repack_promisor_objects()`. When this set is non-NULL, the `write_oid()` callback skips any object whose OID is in the set, effectively rebuilding the promisor pack without those objects. All existing callers pass NULL, so there is no behavior change for current users. The implementation is minimal and focused: the oidset check is inserted early in `write_oid()`, ensuring dropped objects are never written to the new pack.

This is a refactoring patch that prepares the infrastructure for the actual `--drop-filtered` logic (which comes in later patches). The change is well-contained, touching only `repack-promisor.c`, its header, and the single caller in `builtin/repack.c`. The commit message clearly explains the purpose and the safety invariant: dropped objects remain recoverable from the promisor remote. No tests are included here, but the patch is covered by the broader test suite in the series.

The patch looks solid and uncontroversial. It does exactly what it claims without introducing new edge cases, and the oidset check is straightforward and efficient. This is a necessary plumbing change for the feature, and it integrates cleanly with the existing repack machinery.
