This thread is about Justin Tobler’s six-patch series that refactors `git receive-pack` to use the ODB transaction system for pluggable packfile writes, part of Patrick Steinhardt’s broader ODB abstraction effort. The goal is to replace hardcoded calls to `git index-pack` and `git unpack-objects` with a generic `odb_transaction_write_pack()` interface, enabling alternative ODB backends (like reftable or cloud storage) to handle incoming packfiles without relying on the traditional files backend.

The series is still under active review at version 1, with no merge status change. The latest exchange focuses on the fourth patch, which shifts error reporting from direct string returns to a caller-provided `strbuf`. Justin accepted Patrick’s suggestions to mark the `strbuf` parameters as `const` and reuse the buffer to reduce allocations—minor refinements that don’t alter the patch’s core design. Earlier feedback from Patrick also addressed interface naming (renaming `odb_transaction_release()` to `odb_transaction_finalize()`), error reporting for post-commit cleanup, and ergonomic concerns around struct initialization and mutation. The next version will incorporate these changes, with open questions remaining about transaction lifecycle robustness, backend-specific optimizations, and whether certain settings (like `unpack_limit`) belong in the generic interface.

Key participants include Justin (the author) and Patrick (the ODB abstraction lead), who has reviewed most of the series and engaged substantively on design and ergonomics. The series touches `builtin/receive-pack.c`, `odb/transaction.c`, and related files, introducing new symbols like `odb_transaction_finalize()` and `odb_transaction_write_pack()`. No on-disk format changes are proposed, and the series relies on existing tests. The discussion so far has been constructive, with no major objections, though the transaction lifecycle and error handling remain under scrutiny.
