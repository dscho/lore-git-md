This thread is about a nine-patch series from Justin Tobler that refactors `git receive-pack` to use the ODB transaction system, enabling pluggable backends like reftable or cloud storage to handle incoming packfiles without relying on the traditional files backend. The series is now at version 3, addressing all critical feedback from earlier iterations, including a lockfile lifecycle flaw, unpack limit resolution, transaction lifecycle management, and global state removal. Key improvements include explicit ODB source tracking, new `*_or_die()` helpers for stricter error handling, and a refactored `unpack()` function that eliminates reliance on global variables by introducing a `struct unpack_opts`.

The latest email covers patch 6/9, which updates error reporting in `unpack()` and `unpack_with_sideband()` to use a caller-provided `strbuf` instead of returning a static string. This change is internal and prepares the code for the upcoming `odb_transaction_write_pack()` interface, with no user-visible behavior changes. The series remains under active review, cooking in Junio’s `seen` branch, with no objections to its direction. Open questions include the transaction lifecycle design (whether `finalize()` and `commit()` should return `void`) and minor ergonomic trade-offs in struct initialization and file descriptor passing. The series is part of Patrick Steinhardt’s broader ODB abstraction effort and depends on prior ODB transaction infrastructure.
