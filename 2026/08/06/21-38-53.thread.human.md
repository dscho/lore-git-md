This thread is about Justin Tobler’s seven-patch series (v2) that completes the ODB abstraction effort by making `git receive-pack` fully backend-agnostic for packfile writes. The goal is to replace the hardcoded use of `git index-pack` and `git unpack-objects`—which assume the traditional "files" backend—with a new generic transaction interface, `odb_transaction_write_pack()`. This allows alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles without being tied to the files backend.

The series is now under active review, with v2 addressing all feedback from v1, including interface naming, error reporting ergonomics, const-correctness, backend-specific optimizations, and the removal of global state like `unpack_limit`. The final patch introduces `odb_transaction_write_pack()` and moves the packfile ingestion logic into `object-file.c`, where it becomes the "files" backend implementation. The transaction system now supports deferred cleanup of ".keep" lockfiles via a new `finalize` callback, ensuring backend-agnostic cleanup. The series touches `builtin/receive-pack.c`, `odb/transaction.c`, and `object-file.c`, with no on-disk format changes or new test failures.

Key participants include Justin Tobler (the author) and Patrick Steinhardt (ODB abstraction lead), who reviewed v1 substantively and flagged areas like transaction lifecycle design and interface ergonomics. All v1 feedback has been addressed in v2, but reviewers may still focus on the robustness of the deferred cleanup mechanism and the mechanical soundness of the global state removal. The series remains cooking in `seen` with no merge status change, and the next iteration, if any, will likely refine these aspects further.
