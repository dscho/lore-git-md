This thread is the first iteration of a six-patch series from Justin Tobler that refactors `git receive-pack` to use the ODB transaction system for packfile writes, replacing its hardcoded calls to `git index-pack` and `git unpack-objects` with a new generic interface, `odb_transaction_write_pack()`. The goal is to make the command fully backend-agnostic, enabling alternative ODB backends (like reftable or cloud storage) to handle incoming packfiles without relying on the traditional files backend. The series is part of Patrick Steinhardt’s broader ODB abstraction effort and is still under active review, with no merge status change—it remains cooking in `seen`.

The key technical change is the introduction of `odb_transaction_write_pack()`, which delegates packfile processing to the ODB backend via the transaction system. The first five patches are plumbing-only, refactoring global state into explicit structs and improving error reporting ergonomics, while the sixth patch completes the switch by moving the packfile ingestion logic into `object-file.c` as the "files" backend implementation. Reviewers have focused on the transaction lifecycle (particularly the split between `commit` and `finalize`), interface ergonomics, and backend-specific optimizations. Patrick Steinhardt’s recent review of the final patch prompted two design refinements: narrowing `odb_reprepare()` to refresh only the transaction’s source ODB (rather than the entire database) and moving `unpack_limit` (a loose/packed storage threshold) out of the generic options struct, since it’s irrelevant to non-files backends. Justin Tobler has accepted all feedback and plans to incorporate these changes in the next revision, along with earlier refinements like renaming `odb_transaction_release()` to `odb_transaction_finalize()` and improving const-correctness.

The series has no outstanding objections, but the transaction lifecycle and error-handling ergonomics remain open design questions. The next version is expected to address these, along with minor struct formatting tweaks. No test failures or edge cases have been introduced, and the changes are plumbing-only with no on-disk format impact. The thread is a good example of the ODB abstraction effort’s incremental progress, with reviewers and the author collaborating closely on interface design.
