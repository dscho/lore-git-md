This thread is about a nine-patch series (v3) from Justin Tobler that refactors `git receive-pack` to use the ODB transaction system, making it fully backend-agnostic. The goal is to replace hardcoded use of `git index-pack` and `git unpack-objects` with a new generic interface, `odb_transaction_write_pack()`, enabling alternative ODB backends like reftable or cloud storage to handle incoming packfiles. The series has undergone significant revisions since v2, addressing critical design flaws such as a lockfile lifecycle issue, improper transaction lifecycle management, and reliance on global state.

Key improvements in v3 include fixing the lockfile lifecycle flaw by tracking `struct odb_source *` explicitly, introducing `odb_transaction_finalize()` and `*_or_die()` helpers for stricter error handling, removing static caching of the unpack limit, and adding explicit ODB source tracking to avoid fragile assumptions about source list ordering. The series also refactored error reporting to use a `strbuf` for backend-agnostic use, replaced implicit stdin assumptions with explicit file descriptor passing, and introduced the new `odb_transaction_write_pack()` interface. Patrick Steinhardt, the ODB abstraction lead, has approved parts of the series, including the transaction lifecycle design, though he raised a substantive question about the placement of ".keep" files under the new system. Junio C Hamano, the maintainer, previously identified critical issues in v2, all of which have been addressed in v3.

The series is still under active review and cooking in `seen`. The latest patch (8/9) received a brief but clear approval from Patrick Steinhardt, signaling it is technically sound and aligns with the broader ODB abstraction goals. The only remaining open question is Patrick’s design suggestion for ".keep" files, which the author must address before the series can graduate. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt and depends on prior ODB transaction infrastructure. No user-visible behavior changes are introduced; the focus is entirely on enabling pluggable backends.
