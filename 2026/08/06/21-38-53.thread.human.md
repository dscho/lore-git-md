This thread is about a nine-patch series (v4) by Justin Tobler that refactors `git receive-pack` to use the ODB transaction system, enabling pluggable packfile writes for alternative object database backends. The series addresses all feedback from v3, including fixes for a regression in `.keep` file cleanup introduced in an earlier ODB transaction commit (bdee7b3013). The key changes involve ensuring `.keep` files are written to the quarantine directory during transactions but derived from the final location in the main ODB, resolving unpack limits contextually via transaction flags, splitting transaction commit into `commit()` and `finalize()` phases, and removing global state like `alt_shallow_file` and static unpack limit caching.

The series is under active review in Junio’s `seen` branch, with no merge status change yet. Patrick Steinhardt, the ODB abstraction lead, has approved most of the design and implementation, including the `.keep` file placement and transaction lifecycle changes. The only remaining open item is a test coverage gap in patch 1/9: Patrick’s review identified that the test does not verify the `.keep` file’s migration to the main ODB during reference updates, which is critical for protecting the packfile from pruning. Justin has agreed to add this test step, which will use a `reference-transaction` hook to check the file’s presence and removal. Once this is addressed, the patch—and likely the series—will be ready for merging. Junio previously reviewed v2 and identified critical issues, all of which have been resolved in v4. The series is part of Patrick Steinhardt’s broader ODB abstraction effort.
