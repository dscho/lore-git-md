This thread is about a nine-patch series (now at v5) from Justin Tobler that refactors `git receive-pack` to use the ODB transaction system, making it fully backend-agnostic. The goal is to replace hardcoded dependencies on `git index-pack` and `git unpack-objects` with a new generic interface, `odb_transaction_write_pack()`, enabling alternative ODB backends like reftable or cloud storage to handle incoming packfiles.

The series has been through several iterations, with v5 addressing all remaining feedback from v4. Key improvements include a fix for a lockfile lifecycle regression (where `.keep` files weren’t being cleaned up properly), enhanced test coverage for `.keep` file migration, and the removal of global state like `alt_shallow_file` and unpack limit variables. The latest version also splits the transaction lifecycle into `commit()` and `finalize()` phases, allowing for deferred cleanup after reference updates. All critical design issues raised by Patrick Steinhardt and Junio Hamano have been resolved, and the series is technically sound, currently cooking in Junio’s `seen` branch.

The patches touch several core files (`builtin/receive-pack.c`, `odb-interface.h`, `odb.c`, and others) and introduce new symbols like `odb_transaction_finalize()` and `get_unpack_limit()`. The changes are purely internal, with no user-visible behavior changes, but they lay the groundwork for pluggable ODB backends. The series is part of Patrick Steinhardt’s broader ODB abstraction effort and depends on prior ODB transaction infrastructure.

Justin has addressed all substantive feedback, and both Patrick and Junio have signaled agreement with the approach. The only remaining steps are Junio’s final review and potential merge to `next`. If you’ve been following the ODB abstraction work, this series is a significant milestone toward making Git’s storage layer more flexible.
