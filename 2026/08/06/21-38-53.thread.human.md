This thread is about Justin Tobler’s seven-patch series that makes `git receive-pack` fully backend-agnostic for packfile writes by extending Git’s ODB transaction system. The goal is to replace the hardcoded use of `git index-pack` and `git unpack-objects` (which assume the traditional "files" backend) with a new generic interface, `odb_transaction_write_pack()`, enabling alternative ODB backends like reftable or cloud storage to handle incoming packfiles. The series is now at v2, posted after addressing all feedback from v1, including interface naming (`odb_transaction_finalize()`), error reporting ergonomics, const-correctness, backend-specific optimizations, and struct initialization refinements.

The first six patches refactor `builtin/receive-pack.c` to lift global state, pass shallow files and packfile file descriptors explicitly, and improve error reporting via `strbuf`. The seventh patch introduces `odb_transaction_write_pack()` and moves the packfile ingestion logic into `object-file.c`, where it becomes the "files" backend implementation. Key technical details include the new `struct odb_transaction_write_pack_opts` (bundling previously global unpack options) and the `write_pack` callback added to `struct odb_transaction`. The series also narrows `odb_reprepare()` to refresh only the transaction’s source ODB and moves `unpack_limit` handling into the backend, as it’s irrelevant to backends that don’t use loose/packed storage. The transaction lifecycle is now more robust, with `odb_transaction_finalize()` capable of reporting errors—critical for the "files" backend’s deferred cleanup of ".keep" lockfiles.

Justin Tobler is the author, and Patrick Steinhardt (the ODB abstraction lead) has reviewed the series substantively, engaging with the transaction lifecycle design and ergonomic concerns. All feedback from v1 has been incorporated, and the series is now under active review for ergonomics and robustness.
