This thread is about a seven-patch series from Justin Tobler that makes `git receive-pack` work with pluggable object database (ODB) backends by replacing its hardcoded use of `git index-pack` and `git unpack-objects` with a new generic transaction interface, `odb_transaction_write_pack()`. The goal is to let alternative backends (like reftable or cloud storage) handle incoming packfiles without being tied to the traditional files backend. The series is now at version 2, addressing all feedback from the first round—interface naming, error reporting, const-correctness, backend optimizations, and global state removal.

The series is under active review and still cooking in Junio’s `seen` branch. The main open questions revolve around the transaction lifecycle, particularly how deferred cleanup of ".keep" lockfiles works (or doesn’t) on error paths, and a critical bug in the "files" backend where lockfiles are left stranded after migration. Junio Hamano also flagged that `odb_transaction_finalize()` is skipped on non-local exits, which could leave lockfiles behind, and questioned whether the function should return `void` since no callers check its return value. Patrick Steinhardt, who leads the ODB abstraction effort, has reviewed the series and accepted the trade-offs in struct initialization and global state removal, though he’s noted areas for continued attention.

In the latest email, Patrick reviewed the third patch, which removes the global `unpack_limit` variable in favor of a per-repository lookup. He suggested two mechanical improvements: changing the return type to `unsigned int` (since the limit is always non-negative) and dropping the static cache (since `unpack()` is only called once per invocation). These are minor tweaks and won’t affect the patch’s core value. The next iteration will likely adopt them. The series is part of the broader ODB abstraction effort and depends on already-merged transaction infrastructure.
