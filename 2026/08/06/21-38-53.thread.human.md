This thread is about a nine-patch series from Justin Tobler that refactors `git receive-pack` to use the ODB (object database) transaction system, making it fully backend-agnostic. The goal is to replace hardcoded dependencies on `git index-pack` and `git unpack-objects`—which assume the traditional "files" backend—with a new generic interface, `odb_transaction_write_pack()`. This is part of Patrick Steinhardt’s broader ODB abstraction effort, which aims to support alternative backends like reftable or cloud storage.

The series is now at **v3**, addressing all critical feedback from earlier versions. Key fixes include a lockfile lifecycle flaw (ensuring ".keep" files remain valid post-commit), proper transaction lifecycle management with `odb_transaction_finalize()`, and the removal of global state like `alt_shallow_file`. The unpack limit is now resolved lazily via `get_unpack_limit()`, and the interface is designed to be reusable for other commands (e.g., `git fetch-pack`). Patrick Steinhardt, the ODB abstraction lead, has approved several patches in v3, including the transaction lifecycle design and explicit ODB source tracking.

The main open question was how to handle context-specific configuration (e.g., `fetch.unpackLimit` vs. `receive.unpackLimit`). This was resolved by using transaction flags (`ODB_TRANSACTION_RECEIVE`/`ODB_TRANSACTION_FETCH`) to differentiate callers, with the fix slated for v4. The only remaining design discussion is about the ".keep" file placement strategy—Patrick proposed an alternative to preserve race-avoidance properties, but Justin argues the current approach is functionally equivalent. The series is otherwise technically sound and likely to stabilize soon.

The refactor touches core files like `builtin/receive-pack.c`, `object-file.c`, and the ODB transaction infrastructure, but introduces no user-visible changes. It’s currently cooking in Junio’s `seen` branch, with no merge status change yet.
