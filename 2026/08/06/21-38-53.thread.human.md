This thread is about Justin Tobler’s nine-patch series (now at v4) that refactors `git receive-pack` to use the ODB transaction system, making it fully backend-agnostic. The goal is to replace hardcoded calls to `git index-pack` and `git unpack-objects` with a new generic interface, `odb_transaction_write_pack()`, enabling alternative ODB backends (like reftable or cloud storage) to handle incoming packfiles without relying on the traditional files backend.

The series has addressed all critical feedback from earlier versions, including fixes for the ".keep" file placement regression, context-aware unpack limit resolution, and transaction lifecycle management. The latest version (v4) also removes global state, improves include hygiene, and introduces explicit ODB source tracking to eliminate fragile assumptions about source list ordering. Patrick Steinhardt, the ODB abstraction lead, has reviewed the series and provided mostly surface-level feedback, such as a proposed test addition to verify the ".keep" file’s migration during reference updates and a minor commit message rewording. Junio C Hamano, the maintainer, previously identified and helped resolve key issues in v2, and all of those fixes are retained in v4.

The series is now technically complete and cooking in `seen`. The only remaining open items are Patrick’s proposed test addition and a stylistic commit message tweak, neither of which block merging. The new `odb_transaction_write_pack()` interface introduced in the final patch is future-proof and simplifies the logic by removing static caching for unpack limits. Once the test gap is closed, the series appears ready to graduate.
