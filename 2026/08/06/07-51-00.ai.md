This is the second patch in Patrick Steinhardt’s v4 series making on-disk ODB structures pluggable, part of the ongoing ODB abstraction effort. It surgically detangles the loading of loose object maps from repository setup by moving the logic into the "loose" backend itself.

The patch fixes a latent correctness bug: the old code unconditionally downcast the primary ODB to the "files" backend when loading loose object maps, which would BUG if a different backend type were ever used with a compatibility hash algorithm. It also removes the awkward intermixing of repository configuration and ODB initialization by making the loose object map an internal detail of the loose backend. The `should_use_loose_object_map()` guard is now enforced at the source level during backend initialization, and the `loose_object_map_load()` function is exposed to the backend via a new header.

Files touched are `loose.c`, `loose.h`, `odb/source-loose.c`, `repository.c`, and `setup.c`. Key symbols introduced or modified include `loose_object_map_load()` (now public) and the downcast macro `odb_source_files_downcast()`. The patch is uncontroversial and ready for merging; it was explicitly called out in Junio’s "What's cooking" report as part of the series that is under review. The first patch in the series, which this patch depends on, is already slated for early graduation to `next` due to its status as a correctness fix.
