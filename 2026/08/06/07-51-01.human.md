This is the third patch in Patrick Steinhardt’s six-patch series (v4) making Git’s on-disk object database (ODB) structures pluggable. It refactors environment variable handling for ODB initialization, moving it from `apply_repository_format()` in `setup.c` into `odb_new()` itself. The change is part of the broader ODB abstraction effort and prepares the codebase for future backends that may not use traditional filesystem layouts.

The patch addresses a practical problem: if ODB creation is deferred to a later point (as planned in a subsequent patch), the logic for respecting `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` would need to be duplicated. By moving this logic into `odb_new()`, the code becomes self-contained and avoids awkward duplication. It also aligns with Patrick’s longer-term goal of moving environment variable handling into the ODB backends themselves, as noted in the commit message.

The implementation introduces a new `enum odb_new_flags` with a single flag, `ODB_NEW_HONOR_ENV`, which controls whether environment variables are respected. The `odb_new()` function now takes this flag instead of raw directory paths, and `apply_repository_format()` passes the appropriate flag based on its own `APPLY_REPOSITORY_FORMAT_HONOR_ENV` flag. The change is mechanical and touches only `odb.c`, `odb.h`, `setup.c`, and a unit test file (`t/unit-tests/u-odb-inmemory.c`).

This patch is uncontroversial and ready for merging. It was reviewed in earlier iterations, and the v4 changes are minor (e.g., using `CALLOC_ARRAY` instead of `xmalloc` + `memset`). The refactoring is a clean step toward the series’ goal of making ODB creation more flexible, and it doesn’t introduce behavioral changes. The only potential loose end is whether the `ODB_NEW_HONOR_ENV` flag will need to evolve if new environment variables are added, but that’s a future concern.
