Thread identity: Feature request for `git fetch` to decouple default fetch refspec from explicit branch mapping. Originating author: Douglas Puchalski (dpuchals). Thread type: RFC (no patch provided).

Core problem or goal: Address the workflow limitation where explicitly fetching a branch (e.g., `git fetch origin topic/example`) does not create or update the corresponding remote-tracking ref (`refs/remotes/origin/topic/example`) when the remote’s default fetch refspec is restricted (e.g., only `main` and `team/*`). The current behavior forces users to rely on `FETCH_HEAD` or manually specify a refspec, breaking the `git checkout -b <branch> origin/<branch>` workflow. The goal is to enable automatic mapping of explicitly named branches to their remote-tracking refs while preserving the restricted default fetch set, without requiring opt-out workarounds or fetching all remote branches.
