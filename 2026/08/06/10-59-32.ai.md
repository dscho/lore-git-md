This is the first patch in the v7 series optimizing `paint_down_to_common()` for one-sided histories. It adds a comprehensive technical document (`Documentation/technical/paint-down-to-common.adoc`) explaining the algorithm, generation-number regions, termination conditions, and edge cases like the commit-date fallback.

The document is well-structured and thorough, covering both the core paint-walk logic and subtleties such as INFINITY vs. finite generation regions, v1 commit-graph saturation, and why the date-ordering fallback exists. It also clarifies the distinction between merge-base discovery and ancestry checks, which share the same implementation. The only code change is a one-line pointer to the new document in `commit-reach.c`.

This patch is purely documentation and has no functional impact on the codebase. It serves as essential context for the subsequent performance optimizations and correctness fixes in the series. The document was previously reviewed by Elijah Newren, who raised precision concerns about v1 commit-graph handling and `min_generation` wording; those issues are now addressed in this version. No further technical feedback is expected to block this patch.
