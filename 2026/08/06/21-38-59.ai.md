This is the final patch in Justin Tobler’s six-part series introducing `odb_transaction_write_pack()`, the new ODB transaction interface for writing packfiles in `git receive-pack`. It completes the switch from hardcoded `git index-pack`/`git unpack-objects` calls to a backend-agnostic transaction system, enabling alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles.

The patch moves the packfile ingestion logic from `builtin/receive-pack.c` into `object-file.c`, where it becomes the "files" backend implementation of `odb_transaction_write_pack()`. The key change is that `.keep` lockfiles—previously managed by a global `pack_lockfile` tempfile—are now owned by the transaction itself and removed in the backend’s `release` callback, ensuring cleanup happens after references are updated. The `unpack()` function is deleted, and its call sites in `receive-pack` are replaced with calls to the new transaction interface.

The new `struct odb_transaction_write_pack_opts` bundles all previously global unpack options (shallow file, fsck settings, max input size, etc.) into a single struct, making the interface self-contained. The patch also introduces the `write_pack` callback in `struct odb_transaction` and the public `odb_transaction_write_pack()` function, completing the ODB transaction API surface.

This is the payoff patch of the series: it delivers the backend-agnostic packfile write mechanism that the earlier patches prepared for. The refactoring is mechanical and well-scoped, but the new interface’s design—particularly the transaction lifecycle and error handling—will likely be the focus of reviewer scrutiny. The series remains under active review and is not yet merged.
