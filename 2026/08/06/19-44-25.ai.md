This is a bug report about a regression in `git rebase` when commit-graph is enabled, triggered by submodule pointer changes.

The issue surfaces as a fatal error: `error: Could not read 157b7492624beac3ac667dd3a84de9969377866b` followed by `fatal: invalid commit position. commit-graph is likely corrupt`. The commit in question (`157b7492624beac3ac667dd3a84de9969377866b`) exists in a submodule (`rpmsrc/qemu-kvm`) but not in the main repository. Disabling commit-graph (`-c core.commitGraph=false`) allows the rebase to proceed, though it still encounters expected submodule conflicts.

Florian Schmidt bisected the regression to commit `bb5da75d61` ("commit: use commit graph in `lookup_commit_reference_gently()`"), authored by Patrick Steinhardt. The bisect result aligns with the observation that the error disappears when commit-graph is disabled. Philippe Blain, the email author, suggests writing a minimal reproducer as the next step and has CC’d Patrick for visibility.

The report includes key technical details: the commit OID, the affected submodule, the bisected commit, and the workaround. The error message’s reference to a "corrupt" commit-graph is misleading, as `git fsck` reports no corruption—this is a functional regression, not data corruption. The thread context (if any) would clarify whether this is a known issue or a new discovery.
