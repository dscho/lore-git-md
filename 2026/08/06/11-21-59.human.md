This is the fourth patch in Siddharth Shrimali’s seven-patch v3 series introducing `git repack --drop-filtered` for partial clones. It implements the core enumeration logic that identifies which promisor blobs exceed the user-specified size threshold and are therefore candidates for removal.

The patch adds a new function, `enumerate_promisor_blobs()`, in `repack-filtered.c`. This function walks all promisor objects (using `odb_for_each_object()` with `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`) and collects blobs into an oidset. It then applies the filter (currently only `blob:limit`) to that set using the new `list_objects_filter__filter_oidset()` helper introduced in patch 2/7, producing the final `to_drop` set. The enumeration never triggers lazy fetches because it passes `OBJECT_INFO_SKIP_FETCH_OBJECT` to every object info query.

In `--dry-run` mode, the patch prints the OIDs of the candidate blobs; actual removal is deferred to a later patch. The tests verify that only promisor blobs exceeding the threshold are listed, that locally created blobs are never considered, and that `--dry-run` does not remove anything.

The implementation is careful to avoid the pitfall described in the commit message: promisor objects are routed through a separate repack path (`repack_promisor_objects()`), so they never appear in the filtered pack. Direct enumeration via `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` is the correct approach.

This patch is well-motivated and technically sound. The enumeration logic is clean, the safety measures (skipping lazy fetches, excluding local objects) are in place, and the tests cover the key invariants. The only loose end is the deferred remote-object availability check, but that is explicitly scoped as follow-up work. The patch looks ready for review by repack and partial-clone experts (e.g., Patrick Steinhardt or Christian Couder).
