This is the second patch in the v4 series adding path-related keys to `git repo info`. It introduces `path.superproject-root.absolute` and `path.superproject-root.relative` to expose the superproject’s working tree root when the current repository is a submodule.

The implementation is straightforward: it uses `get_superproject_working_tree()` to retrieve the superproject path, then formats it as either an absolute or relative path using the existing `format_path()` helper. If the repository is not a submodule, both keys return an empty string. The patch touches `builtin/repo.c` (adding the two new keys and their formatting functions), `Documentation/git-repo.adoc` (documenting the keys), and `t/t1900-repo-info.sh` (adding test coverage for both submodule and non-submodule cases).

The behavior aligns with the series’ design principle: keys return empty strings only when the context is inapplicable (not in a submodule), and paths are returned unconditionally otherwise, matching `git rev-parse --show-superproject-working-tree` precedent. The naming (`superproject-root`) was settled in v4 after reviewer feedback, replacing the earlier `superproject-working-tree` for brevity and clarity.

For future summarization, note the key names (`path.superproject-root.absolute` and `path.superproject-root.relative`), the use of `get_superproject_working_tree()`, and the test cases covering both submodule and non-submodule scenarios. The patch is uncontroversial and mechanically clean, with no open design questions specific to this part of the series.
