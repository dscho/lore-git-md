This is a bugfix patch from Patrick Steinhardt’s six-part series making on-disk object database (ODB) structures pluggable. The patch corrects a latent bug in how Git loads loose-object maps: it now respects the ODB source path passed to `load_one_loose_object_map()` instead of always loading from the common `objects/` directory. This ensures that loose-object maps in configured alternates are properly loaded, fixing a failure mode in repositories with compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility).

The change is small but critical. The bug was surfaced by Toon Claes, who provided a test case that Patrick incorporated into the patch. The test verifies that `git rev-parse` correctly maps object IDs borrowed from an alternate repository when using a compatibility hash algorithm. The fix itself is straightforward: `load_one_loose_object_map()` now constructs the map path using the loose source’s path (`loose->base.path`) rather than the repository’s common directory.
