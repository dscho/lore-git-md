This is the third patch in the v4 series adding path-related keys to `` `git repo info` ``. It introduces `path.hooks.absolute` and `path.hooks.relative` to expose the hooks directory location in a scriptable format, respecting the `core.hooksPath` configuration override.

The implementation follows the established pattern: two new getter functions (`get_path_hooks_absolute` and `get_path_hooks_relative`) use `repo_git_path_replace()` to resolve the hooks path and `format_path()` to produce absolute or relative output. The patch updates `Documentation/git-repo.adoc` to document the new keys, including the special case where `core.hooksPath` is set to `/dev/null` (returning `/dev/null` verbatim, matching `` `git rev-parse --git-path hooks` `` behavior). Tests in `t/t1900-repo-info.sh` verify standard hooks paths, custom `core.hooksPath` overrides, and `/dev/null` handling (skipped on Windows).

The patch is mechanically clean and aligns with the series' design principles: paths are returned unconditionally, even if the directory does not exist, and empty strings are reserved for inapplicable contexts (e.g., bare repositories). The `/dev/null` behavior is now explicitly documented and tested, resolving the open question from v3. Reviewers may still suggest minor naming adjustments (e.g., `path.hookdir` instead of `path.hooks`), but the core functionality is uncontroversial.
