This is the first patch in a now-approved two-patch documentation series improving the `git-refs(1)` man page. The patch moves an important warning about ref migration limitations from the "KNOWN LIMITATIONS" section at the end of the page into a prominent `WARNING` admonition block directly under the `migrate` subcommand description. The warning text itself is unchanged; only its location and presentation are updated to make it more visible to users.

The motivation is clear: the warning was previously buried deep in the man page, requiring users to scroll three screens past the `migrate` subcommand description to find it. This is a usability issue, as the warning describes a serious risk (concurrent writes can lead to inconsistent migrated state) that users should be aware of before running the command. The patch addresses this by elevating the warning to a dedicated admonition block immediately following the subcommand synopsis, where it is impossible to miss.

The patch is technically straightforward, touching only the AsciiDoc source for `git-refs(1)` (`Documentation/git-refs.txt`). The change is purely presentational and uncontroversial, with no code, test, or on-disk format implications. The author has confirmed that the minor indentation in the rendered output (due to the `+` continuation line in the AsciiDoc) is intentional and consistent with existing patterns in other man pages like `git-clone(1)` and `git-blame(1)`.

This patch was previously reviewed in v1 and v2, with the only feedback being a stylistic preference to use `WARNING` instead of `CAUTION` for the admonition block. The author addressed this in v2, and the patch now carries Patrick Steinhardt’s `Acked-by`. Junio C Hamano has already approved the series ("Looks good. Thanks."), and it is queued in `seen`, expected to graduate to `next` in the next "What's cooking" cycle. No further discussion or revision is anticipated.
