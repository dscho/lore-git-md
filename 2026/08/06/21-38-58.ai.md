This is the fifth patch in Justin Tobler’s six-patch series extending the ODB transaction system to make `git receive-pack` backend-agnostic. The patch updates the `unpack()` function in `builtin/receive-pack.c` to accept an explicit file descriptor for the incoming packfile, replacing the current assumption that the packfile is always read from stdin. This is a preparatory step for moving the unpack logic behind the new `odb_transaction_write_pack()` interface in the next patch.

The change is mechanical: the `unpack()` function signature gains an `int pack_fd` parameter, and callers (`unpack()` itself and `unpack_with_sideband()`) are updated to pass the correct descriptor (0 for stdin when sideband is used, or the provided fd otherwise). The `parse_pack_header()` helper is also updated to take the fd explicitly. No behavior changes are introduced—this is purely plumbing to enable the ODB abstraction layer.

The patch is well-scoped and clearly motivated by the series’ goal of eliminating backend-specific assumptions in `receive-pack`. The commit message succinctly explains the "why" (preparing for a generic ODB transaction interface) and the "how" (explicit fd passing). The diff is small and focused, touching only the necessary lines in `builtin/receive-pack.c`. Reviewers will likely focus on whether the fd-passing abstraction is ergonomic and whether the error handling remains robust when the unpack logic is later moved behind the ODB transaction interface.

This patch is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, and Justin Tobler has been closely involved in that work. The series is under active review and not yet merged. The next patch (6/6) will introduce the `odb_transaction_write_pack()` interface and complete the switch to backend-agnostic packfile processing.
