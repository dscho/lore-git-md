This thread is a feature request from Douglas Puchalski proposing a change to `git fetch` behavior to better support workflows where users want to fetch specific branches not covered by the default refspec. Currently, when a remote is configured to fetch only certain branches by default (e.g., `main` and `team/*`), explicitly fetching an additional branch (e.g., `git fetch origin topic/example`) does not create or update the corresponding remote-tracking ref (`refs/remotes/origin/topic/example`). Instead, the branch is only available in `FETCH_HEAD`, which is ephemeral and shared, breaking common workflows like `git checkout -b topic/example origin/topic/example`.

The request is for an opt-in configuration or default behavior that would automatically map explicitly named branches to their remote-tracking refs while preserving the restricted default fetch set. The author emphasizes backward compatibility and suggests this could involve changes to `builtin/fetch.c` and new configuration options like `remote.<name>.explicitFetchRefmap`. No patch has been provided yet, so this is purely a request for comments (RFC) at this stage.
