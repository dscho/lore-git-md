This is the second patch in Justin Tobler’s six-patch series extending the ODB transaction system to make `git receive-pack` backend-agnostic. The patch lifts the temporary shallow-file setup out of the `unpack()` function and passes the shallow file path explicitly through the call chain, removing reliance on the global `alt_shallow_file` variable. This is a preparatory refactoring step for the later switch to the generic `odb_transaction_write_pack()` interface, which cannot depend on global state.

The change is mechanical and confined to `builtin/receive-pack.c`: the `unpack()` and `unpack_with_sideband()` functions now take a `shallow_file` parameter, and the shallow-file path is passed down from `cmd_receive_pack()` through `update_shallow_info()` and `prepare_shallow_update()`. The temporary file is still created in the same way, just earlier in the call stack. No behavior changes are introduced; the patch is plumbing-only.

This refactoring looks clean and well-scoped, addressing the author’s stated goal of removing global state ahead of the ODB transaction switch. The commit message clearly explains the motivation and the mechanical nature of the change. Reviewers are likely to focus on whether the explicit parameter passing is the right abstraction and whether the error handling remains robust, but the patch itself appears uncontroversial.
