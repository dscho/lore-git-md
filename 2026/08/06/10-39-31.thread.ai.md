Subject: Branch renaming edge case in Git for Windows (reflog path conflict)
Series version: N/A (bug report)
Originating author: Piotr Slowinski <Piotr.Slowinski@bentley.com>
Thread type: bug report

Core problem or goal
When a branch is renamed on the remote to introduce a directory hierarchy (e.g., `mybranch` → `mybranch/WIP`), Git for Windows 2.51.0.windows.2 fails to update the local reflog storage in a second repository (`Local2`). The stale reflog file `.git/logs/refs/remotes/origin/mybranch` remains as a file, causing fetch/pull to fail because Git expects it to be a directory to accommodate the new hierarchy. The issue is specific to the reflog filesystem storage and does not involve a patch or reproduction script.

Current status
Reported; no prior discussion, no patch, no maintainer response. The workaround is manual deletion of the stale reflog file.

Key technical details
- Subsystem: reflog storage (`.git/logs/refs/remotes/origin/`)
- Platform: Git for Windows 2.51.0.windows.2 (not upstream Git)
- Files touched: none in the report; the issue is about filesystem path handling
- Behavior: Git expects a directory but finds a file, causing fetch/pull to fail
- Workaround: manual deletion of the stale reflog file

Open questions and loose ends

- Whether the reflog storage format should automatically convert from file to directory when a branch is renamed into a directory-like path
- Whether a patch will be proposed to address the issue or if it will remain a known limitation
