Subject: [PATCH 0/5] gitk: overhaul color-preference dialog

Originating author: Johannes Sixt (Hannes)
Thread type: patch series (UI improvement)

Core problem or goal
Overhaul the gitk color-preference dialog to improve usability. The current dialog has non-clickable color swatches (users must click text labels instead), inconsistent button widths due to varying label lengths, technical/abbreviated labels, and untranslatable dialog titles constructed from dynamic fragments. The goal is to make the swatches the primary clickable elements, standardize button widths, rewrite labels in more natural language, and ensure all UI strings are fully translatable.

Current status
Under review (initial submission). No prior versions. The series consists of five patches confined to `gitk-git/gitk` (Tcl/Tk). The first two patches are pure refactorings with no behavior changes, serving as prerequisites for the subsequent UI improvements. The third patch implements the first major UI change: making color swatches the primary clickable elements by replacing `ttk::button` widgets with non-themed `button` widgets that can be directly recolored, and adjusting the grid layout to place labels before buttons. The fourth patch replaces the old, abbreviated labels with more natural, descriptive text (e.g., “Diff: old lines bg” → “Diff: old lines background”) now that the labels are static (non-clickable) following the UI changes in patch 3. The fifth patch addresses translatability by replacing dynamically constructed dialog titles (e.g., "Gitk: choose color for" + "background") with full, natural-language titles provided directly by the caller (e.g., "choose background color"). The series is now complete and ready for final review.

Key technical details
- Files touched: `gitk-git/gitk` only.
- Subsystem: gitk (Tcl/Tk UI).
- New/renamed symbols: none (UI-only changes). The first patch consolidates the `prefspage_set_colorswatches` helper procedure to eliminate duplicate color-setting logic. The second patch refactors repetitive Tcl/Tk code for color-selection buttons into a single `foreach` loop, reducing redundancy and making two minor naming cleanups ("sep" suffix dropped from "markbgsep" and "selbgsep", "but" suffix changed to "btn" for consistency). The third patch replaces `ttk::button` widgets with non-themed `button` widgets in the `prefspage_colors` and `prefspage_set_colorswatches` procedures, enabling direct background color setting and making swatches clickable. The fourth patch updates seven labels to more natural language: “Foreground” → “Main text”, “Diff: old lines bg” → “Diff: old lines background”, “Diff: hunk header” → “Diff: hunk headers”, “Marked line bg” → “Marked lines background”, “Select bg” → “Selected text background”, and “Link” → “Link text”. The fifth patch updates the `choosecolor` procedure to accept full dialog titles (e.g., "choose background color" or "choose text color of old lines") instead of dynamic suffixes, and modifies all 12 call sites in the `coloruielems` list to supply the new titles.
- On-disk format: unchanged.
- Test coverage: none (UI changes are not covered by the test suite).
