Originating author: Johannes Sixt (Hannes)

Core problem or goal
Overhaul the gitk color-preference dialog to improve usability. The current dialog has non-clickable color swatches (users must click text labels instead), inconsistent button widths due to varying label lengths, and technical, abbreviated labels. The goal is to make the swatches the primary clickable elements, standardize button widths, and rewrite labels in more natural language.

Current status
Under review (initial submission). No prior versions. The series consists of five patches confined to `gitk-git/gitk` (Tcl/Tk). The first two patches are pure refactorings with no behavior changes, serving as prerequisites for the subsequent UI improvements. The third patch (newly summarized) implements the first major UI change: making color swatches the primary clickable elements by replacing `ttk::button` widgets with non-themed `button` widgets that can be directly recolored, and adjusting the grid layout to place labels before buttons. The remaining two patches will standardize button widths and rewrite labels.

Key technical details
- Files touched: `gitk-git/gitk` only.
- Subsystem: gitk (Tcl/Tk UI).
- New/renamed symbols: none (UI-only changes). The first patch consolidates the `prefspage_set_colorswatches` helper procedure to eliminate duplicate color-setting logic. The second patch refactors repetitive Tcl/Tk code for color-selection buttons into a single `foreach` loop, reducing redundancy and making two minor naming cleanups ("sep" suffix dropped from "markbgsep" and "selbgsep", "but" suffix changed to "btn" for consistency). The third patch replaces `ttk::button` widgets with non-themed `button` widgets in the `prefspage_colors` and `prefspage_set_colorswatches` procedures, enabling direct background color setting and making swatches clickable.
- On-disk format: unchanged.
- Test coverage: none (UI changes are not covered by the test suite).

Open questions and loose ends
None yet. Potential minor discussion around widget styling, layout, or the specific wording of new labels in later patches, but these are expected to be easily adjusted based on feedback.
