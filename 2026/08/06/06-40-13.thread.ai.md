Thread identity
Subject: [PATCH 0/5] gitk: overhaul color-preference dialog
Series version: v2 (revision incorporating surface-level feedback)
Originating author: Johannes Sixt (Hannes)
Thread type: patch series (UI improvement)

Core problem or goal
Overhaul the gitk color-preference dialog to improve usability by making color swatches the primary clickable elements, standardizing button widths, rewriting labels in more natural language, and ensuring all UI strings are fully translatable. The current dialog has non-clickable color swatches (users must click text labels instead), inconsistent button widths due to varying label lengths, technical/abbreviated labels, and untranslatable dialog titles constructed from dynamic fragments.

Current status
Under review (v2 submitted). The six-patch series is now complete and ready for final review. All patches are confined to `gitk-git/gitk` (Tcl/Tk) and do not affect core Git functionality. The first patch consolidates the `prefspage_set_colorswatches` helper procedure to eliminate duplicate color-setting logic, adding the previously missing `linkfgcolor` global variable for completeness. The second patch refactors repetitive Tcl/Tk code for color-selection buttons into a single `foreach` loop, reducing redundancy and making two minor naming cleanups ("sep" suffix dropped from "markbgsep" and "selbgsep", "but" suffix changed to "btn" for consistency). The third patch replaces `ttk::button` widgets with non-themed `button` widgets in the `prefspage_colors` and `prefspage_set_colorswatches` procedures, enabling direct background color setting, making swatches clickable, swapping the grid layout so the label appears to the left of the button, and adding cosmetic adjustments (`-borderwidth 2`, `-pady 1`). Mark Levedahl has endorsed the visual presentation of this patch, noting that the new buttons "stand out much better" with the 2-pixel border and layout adjustments. The fourth patch updates seven labels to more natural language: “Foreground” → “Main text”, “Diff: old lines bg” → “Old line background”, “Diff: hunk header” → “Hunk header text”, “Diff: new lines bg” → “New line background”, “Marked line bg” → “Marked line background”, “Select bg” → “Selected text background”, and “Link” → “Link text”. The fifth patch ensures full translatability by replacing dynamically constructed dialog titles with full, natural-language titles provided directly by the caller, updating all 12 call sites in the `coloruielems` list and modifying the `choosecolor` procedure to accept the full title as an argument. The sixth patch reorders the color options list, placing generic colors (selection, marked lines, link text) above diff-specific colors for better visual hierarchy, without adding explicit section headers.

Open questions and loose ends
The remaining discussion is purely cosmetic and narrowed to two final adjustments: (1) the specific wording of the "Marked line background" label, and (2) the visual ordering of the color options list. Johannes Sixt clarified that the "Marked line background" label controls the background color of lines revealed by the "Show origin of this line" feature in the diff panel, not search-highlighted commit messages. Mark Levedahl proposes replacing "Marked line background" with "Origin line background" to better reflect the feature’s trigger, while noting that the unrelated `foundbgcolor` (which highlights search results in commit messages but not patch text) is intentionally omitted from the dialog and should remain so. These are presentational choices with no impact on functionality, translatability, or technical correctness. No substantive concerns, edge cases, or requests for changes remain; all feedback has been surface-level and addressed or proposed for resolution.
