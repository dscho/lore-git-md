Subject: [PATCH 0/5] gitk: overhaul color-preference dialog
Series version: v1 (initial submission)
Originating author: Johannes Sixt (Hannes)
Thread type: patch series (UI improvement)

Core problem or goal
Overhaul the gitk color-preference dialog to improve usability by making color swatches the primary clickable elements, standardizing button widths, rewriting labels in more natural language, and ensuring all UI strings are fully translatable. The current dialog has non-clickable color swatches (users must click text labels instead), inconsistent button widths due to varying label lengths, technical/abbreviated labels, and untranslatable dialog titles constructed from dynamic fragments.

Current status
Under review (initial submission). No prior versions. The five-patch series is now complete and ready for final review. All patches are confined to `gitk-git/gitk` (Tcl/Tk) and do not affect core Git functionality. The first two patches are pure refactorings with no behavior changes, serving as prerequisites for the subsequent UI improvements. The third patch implements clickable color swatches by replacing `ttk::button` widgets with non-themed `button` widgets, adjusting the grid layout, and incorporating **surface-level feedback** from Mark Levedahl: increasing the button border width (`-borderwidth 2`) and adding small vertical padding (`-pady 1`) to improve visual distinctness. The fourth patch replaces abbreviated labels with more natural, descriptive text (e.g., “Diff: old lines bg” → “Diff: old lines background”). The fifth patch ensures full translatability by replacing dynamically constructed dialog titles with full, natural-language titles provided directly by the caller. The author now proposes two final cosmetic adjustments to the "Diff: old lines background" label: dropping the "Diff:" prefix (as redundant) and using singular "line" ("old line background") instead of plural, along with a visual reordering of the color options list (selection, marked lines, and link text above diff-specific colors) without explicit section headers.

Key technical details
- Files touched: `gitk-git/gitk` only.
- Subsystem: gitk (Tcl/Tk UI).
- New/renamed symbols: none (UI-only changes). The first patch consolidates the `prefspage_set_colorswatches` helper procedure to eliminate duplicate color-setting logic. The second patch refactors repetitive Tcl/Tk code for color-selection buttons into a single `foreach` loop, reducing redundancy and making two minor naming cleanups ("sep" suffix dropped from "markbgsep" and "selbgsep", "but" suffix changed to "btn" for consistency). The third patch replaces `ttk::button` widgets with non-themed `button` widgets in the `prefspage_colors` and `prefspage_set_colorswatches` procedures, enabling direct background color setting, making swatches clickable, and now includes the cosmetic adjustments (`-borderwidth 2`, `-pady 1`). The fourth patch updates seven labels to more natural language: “Foreground” → “Main text”, “Diff: old lines bg” → “Diff: old lines background”, “Diff: hunk header” → “Diff: hunk headers”, “Marked line bg” → “Marked lines background”, “Select bg” → “Selected text background”, and “Link” → “Link text”. The fifth patch updates the `choosecolor` procedure to accept full dialog titles (e.g., "choose background color" or "choose text color of old lines") instead of dynamic suffixes, and modifies all 12 call sites in the `coloruielems` list to supply the new titles. The proposed final adjustments affect only the "Diff: old lines background" label (prefix removal and singular "line") and the visual ordering of the color options list.
- On-disk format: unchanged.
- Test coverage: none (UI changes are not covered by the test suite).

Open questions and loose ends
The cosmetic discussion about UI label phrasing and organization is now narrowed to two final adjustments: (1) whether to drop the "Diff:" prefix and use singular "line" in the "old line background" label, and (2) whether to adopt the proposed visual reordering of the color options list. These are purely presentational choices with no impact on functionality, translatability, or technical correctness. No substantive concerns, edge cases, or requests for changes remain; all feedback has been surface-level and addressed or proposed for resolution.
