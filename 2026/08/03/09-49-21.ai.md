This is a **refactoring patch** in Phillip Wood’s follow-up series addressing the `git history squash` implementation. It cleans up the `resolve_squash_range()` function in `builtin/history.c` by standardizing how `rev-list` options are handled, aligning it with the pattern used in `git replay`.

The patch replaces a mix of direct `rev_info` member manipulation and `strvec`-based argument passing with a consistent approach: all required options are set directly in the `rev_info` struct before calling `setup_revisions()`. This eliminates the need to duplicate `argv` into a temporary `strvec` and makes the code more maintainable. It also adds defensive checks for `--ancestry-path` and related options, ensuring future changes won’t silently alter the walk behavior. The change is purely internal—no user-visible behavior is altered.

This is the third of seven fixup patches Phillip posted in response to Harald Nordgren’s v10. While Harald’s v11 has since been posted (and adopts some of Phillip’s suggestions), this patch remains relevant for its structural improvements. The key change is the shift from `setup_revisions_from_strvec()` to `setup_revisions()`, which simplifies the code and reduces redundancy. The patch also moves the reflog message construction earlier in `cmd_history_squash()`, a minor cleanup that improves clarity.
