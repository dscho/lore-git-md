This is a **substantive fixup patch** in Phillip Wood’s review series for `git history squash`, targeting a correctness issue in the range-resolution logic. The patch replaces a check for `UNINTERESTING` commits with a check for `BOTTOM` commits, ensuring the code correctly identifies the base of the squash range.

The change is small but important: `UNINTERESTING` is a general flag used for many purposes in Git’s revision-walking machinery, while `BOTTOM` is specifically set for the boundary commit in a `<base>..<tip>` range. The current code risks misidentifying unrelated `UNINTERESTING` commits (e.g., from excluded side branches) as the range boundary, which could lead to incorrect range validation or even silent data loss if the wrong commit is treated as the base. This fix aligns the logic with the intended behavior of rejecting ranges that don’t have exactly one boundary commit.

The patch is part of Phillip’s broader effort to tighten input validation in `git history squash` (see his v10 review patches 3 and 4).
