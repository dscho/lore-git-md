This is the fifth patch in the eight-part GSoC v3 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch teaches the server-side object-info handler to accept "type" as a requested field and transmit the object type (e.g., `"blob"`, `"tree"`) alongside the existing size data.

The implementation adds a `type` bit field to the `requested_info` struct in `protocol-caps.c` and updates `send_info()` to parse the field from client requests. When the client includes "type" in its object-info request, the server calls `get_object_info()` to retrieve the object type and appends it to the response string using `type_name()`. The patch also includes a minor style fix for the `size` bit field and wraps an over-long line in the error message.

Test coverage is expanded in `t5701-git-serve.sh` with a new test that verifies the server correctly handles requests for both "size" and "type", including duplicate OIDs. The test configures `transfer.advertiseObjectInfo`, sends a stateless-rpc request with the "type" field, and checks that the response includes the expected type string (e.g., `"blob"`).

This patch is a straightforward extension of the existing object-info protocol and follows the hybrid design introduced in earlier patches. The changes are narrowly scoped to the server-side handler and do not affect client-side parsing or the new `fetch_object_info_results` struct. The implementation appears clean and aligns with the project’s defensive programming practices, though the test could arguably verify edge cases like unknown object types or malformed requests. No controversial design decisions are evident here, and the patch looks ready for review.
