This is the fourth patch in Pablo Sabater’s GSoC v3 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder. The patch refactors `fetch_object_info()` to use a dedicated `struct fetch_object_info_results` instead of `struct object_info`, a well-motivated cleanup that replaces inefficient parameter-passing with a cleaner, memory-efficient design. Junio’s review identified a forward-compatibility issue: the patch introduces the `ask_type` flag prematurely, before the client-side parsing logic (patch 6/8) and server-side capability advertisement (patch 7/8) are in place. If a user requests `%(objecttype)` at this stage and the server supports "type", the client will hit a `BUG()`. Pablo acknowledges the issue and plans to move the `ask_type` flag to a later patch where it aligns with the full implementation.

The patch itself is a solid refactoring that addresses earlier feedback from Junio and Peff, replacing the `object_info`-based approach with a dedicated struct that avoids unnecessary allocations. The premature flag is a minor protocol hygiene concern rather than a correctness bug, and Pablo’s fix (deferring `ask_type` to a later patch) resolves it without disrupting the series. The rest of the series remains feature-complete and merge-ready, with all prior review feedback addressed. This is a well-crafted contribution that fits cleanly into the ongoing remote-object-info effort.
