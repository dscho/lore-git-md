This is a **substantive review patch** from Phillip Wood, part of his series refining Harald Nordgren’s `git history squash` implementation. This specific patch (3.6/3.7 in v10) overhauls how the command handles `fixup!`, `squash!`, and `amend!` commit messages, replacing the existing logic with a stricter, more predictable approach that prioritizes preserving user intent.

The patch addresses a core design question: what should happen to the messages of `squash!` and `amend!` commits when they’re folded into a range? The current implementation (and v11) discards these messages unless they target the oldest commit in the range, which Phillip argues is too permissive. His solution is to **reject the operation by default** unless the user explicitly opts in via `--reedit-message`, ensuring no message is silently discarded. This aligns with the principle that `squash!` and `amend!` are strong signals of intent to reword, not just to fold.

Key changes:
- **Stricter message preservation**: The patch refuses to squash `squash!` or `amend!` commits unless their target is the first commit in the range *or* the user supplies `--reedit-message`. This prevents accidental loss of rewording intent.
- **Flexible fixup handling**: It allows `fixup!` commits to be squashed into other `fixup!` commits with the same target (e.g., `fixup! abc123` into `fixup! <subject of abc123>`), making it easier to group fixups.
- **Direct logic**: Replaces the existing rebase-todo-list-based approach with a single-pass algorithm that tracks commit subjects and targets using a `strintmap`. This is more efficient and easier to maintain.
- **Authorship rules**: Always uses the authorship of the first commit in the range, matching `git rebase` behavior. This avoids ambiguity about whether `amend!` commits should override authorship.
- **New helpers**: Introduces `squash_amend_message()`, `squash_squash_message()`, and `squash_check_autosquash_subject()` to handle the logic for each message type.

The patch also updates tests to verify the new behavior, including cases where `squash!` messages are rejected unless edited, and where `amend!` messages are preserved only when targeting the first commit. While v11 has already been posted with a different approach (defaulting to message editing), Phillip’s patch remains relevant as a stricter alternative that could inform future iterations or serve as a reference for `--reedit-message` behavior.

This is a **well-crafted, technically sound** contribution that addresses a real edge case in the `squash` command. The changes are motivated by clear principles (preserving user intent, avoiding silent data loss) and are thoroughly tested. Even though v11 has moved forward, the patch’s ideas are worth considering for future versions.
