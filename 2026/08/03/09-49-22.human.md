This is a **bugfix patch** from Phillip Wood, part of his substantive review series addressing edge cases in Harald Nordgren’s `git history squash` implementation (v10). The patch corrects a logic error in `resolve_squash_range()` where the code incorrectly checked for `UNINTERESTING` commits instead of `BOTTOM` commits when validating the revision range.

The issue is subtle but important: `UNINTERESTING` is a general flag used by Git’s revision-walking machinery to mark commits excluded from the walk, while `BOTTOM` is a specific flag used to denote the lower bound of a revision range (e.g., the `<base>` in `<base>..<tip>`). The current code could misidentify a commit as the range boundary if it was marked `UNINTERESTING` for unrelated reasons, leading to incorrect validation. Phillip’s fix ensures the code only considers commits explicitly marked as the range’s bottom boundary.

This is a **targeted, correctness-focused change** with no user-visible behavior impact—it prevents a potential false positive in range validation. The patch is part of a larger effort (Phillip’s v10 review series) to tighten input validation and edge-case handling in `git history squash`, though note that Harald’s v11 series has since addressed many of these concerns independently. Phillip’s patches remain a valuable reference for future improvements, particularly his structural refinements and stricter message preservation logic.
