This thread is about a small but long-overlooked quality-of-life fix for Git's bash completion. Junio himself posted a patch to make `git diff` completion behave consistently with other commands like `git status` and `git add`—specifically, when you type `git diff --` or `git -C some/repo diff`, it will now suggest only tracked files from the correct repository, rather than falling back to untracked files in the wrong directory.

The change is tiny: a tweak to `_git_diff()` in `contrib/completion/git-completion.bash` and four new tests in `t/t9902-completion.sh` to verify the fix works with both local and `git -C` invocations. Junio’s commit message is refreshingly direct—he calls it a "monkey see, monkey do" fix for a personal pet peeve he’s lived with for years. The patch follows existing patterns in the completion script and carries almost no risk of breaking anything else.

Given Junio’s role as maintainer and the patch’s narrow scope, this is likely to be merged soon after review. No objections or alternative approaches have been raised yet, and the tests cover the exact scenarios he describes as frustrating. If you use bash completion, this should make `git diff` feel more predictable.
