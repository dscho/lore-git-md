This thread is about a small but long-standing usability bug in Git's bash completion: when you type `git diff` (with or without `-C <path>`) and press Tab, the completion suggestions would sometimes include untracked files from the wrong directory, breaking the expected behavior that matches `git status` and `git add`. Junio C Hamano posted a one-patch fix that aligns the completion logic with these other commands, ensuring only tracked paths from the correct repository are suggested.

The patch itself is simple—it modifies `_git_diff()` in `contrib/completion/git-completion.bash` to call the existing `__git_complete_index_file()` helper when appropriate—and includes four new tests in `t/t9902-completion.sh` to verify the fix works for both local and `git -C` invocations. Junio has since clarified the commit message to emphasize that the improvement applies broadly, not just to the `-C` case, making the motivation clearer for future readers. The patch is already queued in Junio's `seen` branch, signaling his intent to merge it soon, and no objections or further review comments have appeared. Expect this to land in the next release without further drama.
