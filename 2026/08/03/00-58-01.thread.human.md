This thread is about a small but important fix to Git's bash completion for `git diff`. Junio Hamano posted a patch that makes completion behave consistently—suggesting only tracked files, just like `git status` and `git add`—when you use `git -C <path>` or type an empty revision. The patch was initially queued on Junio's `seen` branch, but SZEDER Gábor just spotted a regression: it breaks completion for `git diff --no-index`, which *should* show untracked files since it works outside Git's index.

SZEDER's review is sharp and actionable. He points out the exact problem (untracked files disappearing when they shouldn't) and suggests a clean fix: wrap the completion logic in a check for `--no-index` using Git's existing `__git_find_on_cmdline` helper. This keeps the original improvement while preserving the expected behavior for `--no-index`. The fix is minimal and aligns with the codebase's style, so it should be easy to fold into a v2 patch.

No other feedback has surfaced yet, and the issue is narrowly scoped. Junio will likely post a revised version soon, adding the `--no-index` guard and a test case to cover this edge case. Given the patch's low risk and maintainer backing, it should graduate to `next` in the next "What's cooking" report once the regression is addressed.
