This thread is about a now-merged bugfix series for Git's bash completion, specifically fixing inconsistent path completion behavior in `git diff` when used with `git -C` or empty revision input. The series, authored by Junio C Hamano, ensures completion aligns with `git status` and `git add` by suggesting tracked paths first, with untracked paths as a fallback, across all invocations.

The three-patch series (v4) was merged to `master` without further changes after addressing minor feedback. However, a substantive post-merge review by Elijah Newren has surfaced a latent API misuse in the second patch (v4 2/3). The helper function `__git_complete_index_file()` is documented to require one argument, but the patch invokes it with none, relying on accidental tolerance in the call chain. While this doesn’t affect current functionality, it could break if helper functions’ argument handling changes. Newren suggests passing an explicit empty string (`""`) to clarify intent and future-proof the code. This feedback is purely technical and doesn’t impact the series’ merged status, but it may prompt a follow-up patch for robustness.

Key participants included SZEDER Gábor, who identified the original `--no-index` regression, and D. Ben Knoble, who provided surface-level feedback on test layout. The series is complete, with no open questions or loose ends beyond Newren’s API observation.
