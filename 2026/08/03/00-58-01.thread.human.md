This thread is about a small but long-standing inconsistency in Git’s bash completion: when you type `git diff --<TAB>` or `git -C some/path diff --<TAB>`, the shell sometimes suggests untracked files instead of only the tracked ones that `git status` or `git add` would show. Junio sent a one-patch fix that makes completion behave consistently by always limiting suggestions to tracked files, matching the rest of Git’s UI.

The patch itself is simple—it tweaks the `_git_diff()` helper in `contrib/completion/git-completion.bash` and adds four new tests—but it initially broke completion for `git diff --no-index`, which *should* offer untracked files. Junio thought he’d need extra logic to handle that case, but in this latest message he realized the existing code already does the right thing: when Git’s own completion logic finds no candidates (which happens outside a repo or when no tracked files match), it silently falls back to listing everything in the current directory. That fallback covers `--no-index` automatically, so no further changes are needed.
