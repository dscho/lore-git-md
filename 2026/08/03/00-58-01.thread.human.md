This thread is about a three-patch series from Junio C Hamano that fixes inconsistent bash completion behavior for `git diff`. The goal is to make completion suggestions consistent with `git status` and `git add` by offering tracked paths first, then untracked paths as a fallback—regardless of whether the command uses `git -C <path>`, an empty revision, or `--no-index`.

The series is now complete and ready for merging. Version 4 addressed the last cosmetic issue (a redundant test) and is queued on `seen`. The first patch refactors the completion logic, the second adds tracked path completion, and the third adds untracked path fallback. Testing is thorough, with 119 new test cases covering tracked/untracked paths, `git -C`, `--no-index`, and explicit `--` scenarios.
