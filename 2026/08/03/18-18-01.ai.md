This is a substantive review comment on the second patch of Pablo Sabater’s GSoC v3 series, which extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. Junio C Hamano raises a forward-compatibility concern about the protocol’s robustness: the current patch detects if the server sends *fewer* objects than requested, but does not address the symmetric case where the server sends *more* objects than expected. The patch’s loop bounds prevent buffer overflow (it allocates for N objects and reads at most N), but Junio asks whether the client detects the protocol violation later—either when processing the next request or before shutting down the connection.

The question is narrowly scoped to protocol hygiene and does not challenge the patch’s immediate correctness. It suggests that the series could benefit from an additional defensive check to catch over-long responses, either in this patch or as a follow-up. The tone is constructive and technical, not prescriptive; Junio does not demand a change, but the observation is sharp enough that a future reviewer might raise it again. Pablo’s current implementation is safe against buffer overflow, but the thread now has an open question about whether the protocol layer should enforce stricter invariants. This is a minor loose end in an otherwise feature-complete, well-reviewed series.
