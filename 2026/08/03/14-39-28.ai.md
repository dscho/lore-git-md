This is the first patch in the GSoC v3 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch is a test cleanup in `t5701-git-serve.sh`, replacing two instances of `wc -c | xargs` with the `test_file_size()` helper and caching the output of `git rev-parse two:two.t` in variables.

The change is purely mechanical and motivated by test robustness: `wc -c` output can vary across platforms (some pad with blanks), and the pipe to `xargs` was only there to strip those blanks. The new helper outputs the size directly, and the cached variables avoid redundant subprocess calls. The commit message explicitly states that the pipe was only for whitespace stripping, clarifying a point that might otherwise puzzle future readers.

This patch is uncontroversial and aligns with established test practices. It was prompted by Chandra Pratap’s review feedback in v1 and is now part of the v3 series. No behavior change is introduced; the test’s expectations remain identical. The patch is a small but useful step toward the larger goal of the series.
