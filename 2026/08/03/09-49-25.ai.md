This is a **substantive review fixup patch** for the `git history squash` subcommand, part of Harald Nordgren’s v10 series. Phillip Wood refines the ref-handling logic to **protect all branches descended from the squashed range**, not just those pointing directly at a squashed commit. The patch replaces the existing `oidset`-based interior-ref detection with a more robust `ref-filter` approach, ensuring consistent behavior and clearer error messages.

Key changes:
- **Stricter branch protection**: The command now rejects operations if *any* local branch (not just direct pointers) descends from a commit in the squashed range. This fixes an inconsistency where branches pointing to descendants of squashed commits were ignored, while direct pointers were blocked.
- **Simplified ref filtering**: Uses `ref-filter` to walk commits with parents outside the range, reducing the set of commits that need to be checked. This improves efficiency and maintainability.
- **Error message clarity**: The patch updates tests to reflect the new behavior, though Phillip notes the error messages could be further polished to list problematic branches explicitly.
- **Detached HEAD handling**: Explicitly excludes detached HEADs from protection, treating them as experimental state not worth preserving.

The patch touches `builtin/history.c` (refactoring `resolve_squash_range` and removing the now-unused `find_interior_ref` helper) and updates test cases in `t/t3455-history-squash.sh` to match the stricter validation. While v11 of Harald’s series has since been posted, this fixup remains relevant for its structural improvements and edge-case handling. The change aligns with v11’s broader goal of tightening input validation but goes further in protecting descendant branches.
