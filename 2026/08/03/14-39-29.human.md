This is a bugfix patch in the ongoing GSoC series that extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote-object-info queries. It is the second of eight patches in v3 of the series.

The patch addresses a preexisting robustness issue in the `fetch_object_info()` function: if the server sends fewer object-info lines than the number of OIDs requested, the loop exits early, leaving the remaining entries in the result arrays uninitialized. The caller currently assumes all requested objects are accounted for, which could lead to reading garbage values or undefined behavior. The fix adds a simple check after the loop that calls `die()` if the number of objects processed does not match the number requested, providing a clear error message instead of silent corruption.

The change is minimal and targeted: it hoists the loop counter `i` to function scope, reuses it in the post-loop check, and adds the new `die()` call. The commit message is clear and concise, explaining both the problem and the solution. This is a sensible defensive programming measure that aligns with Git’s general approach to handling protocol errors. No controversy or design questions are raised; the patch looks like a straightforward improvement that should be uncontroversial.
