This is the sixth patch in Pablo Sabater’s eight-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now at v3, reflecting a major refactoring to replace `struct object_info` with a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests (size and type).

This patch teaches the client to parse object type from the server’s response. The server already knows how to handle type requests (added in patch 5), but does not yet advertise the capability. The patch updates `fetch-object-info.c` to recognize the "type" attribute in the server’s object-info response, validate the type string using `type_from_string_gently()`, and store the parsed enum in the `types` array of `struct fetch_object_info_results`. It also updates `builtin/cat-file.c` to include "objecttype" in the `remote_allowed_atoms` list when the results contain type data, and to set the `data->type` field for each object. The `free_fetch_object_info_results()` function is extended to free the new `types` array.

The implementation is straightforward and follows the established pattern for parsing the "size" attribute. The patch adds a defensive check for invalid type strings, ensuring the client fails fast if the server sends malformed data. No test coverage is added here; the existing tests in `t5701` and `t1017` will verify the end-to-end behavior once the server-side capability advertisement is added in patch 8.

The patch is well-motivated and aligns with the series’ goal of providing object type metadata via remote-object-info. The changes are localized to `fetch-object-info.c` and `builtin/cat-file.c`, and the new logic is consistent with the hybrid design proposed by Junio and Peff. Reviewers familiar with the object-info subsystem may want to verify the error handling and memory management, but the implementation appears solid and uncontroversial. The GSoC deadline is approaching, and this patch completes the client-side parsing logic, leaving only the capability advertisement and final test updates for the remaining two patches.
