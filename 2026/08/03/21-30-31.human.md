This is the second patch in Pablo Sabater’s eight-part GSoC series extending `git cat-file --batch-command` to support object type metadata in remote-object-info queries. The patch adds a defensive check in `fetch-object-info.c` to `die()` if the server sends fewer object-info lines than requested OIDs, preventing uninitialized data from being used by the caller. Junio’s review raised a symmetric concern: what happens if the server sends *more* objects than requested? Pablo confirms the current implementation is safe (the loop bounds prevent buffer overflow) but concedes it does not detect over-length responses. He proposes a follow-up fix: check for a flush packet after reading the expected number of objects and `die()` if extra data remains. The fix is straightforward and aligns with Git’s defensive programming practices, but it does not block merging the series. The patch itself is a small, well-motivated robustness improvement that addresses a latent bug in the object-info subsystem.
