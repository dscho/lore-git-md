This is a follow-up in Pablo Sabater’s GSoC v3 series (patch 2/8) that extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The email responds to Junio C Hamano’s substantive review comment about protocol robustness: whether the client should detect and reject over-length responses (server sending more objects than requested).

Pablo confirms that the current implementation silently discards excess objects, only detecting the protocol violation in the stateless case via `check_stateless_delimiter()`. He acknowledges this is not ideal, even though the connection is short-lived and each `remote-object-info` command starts fresh. He proposes a straightforward fix: after reading the expected number of objects, the client should check for an immediate flush packet; if anything else arrives, it should `die()` to fail fast. The tone is pragmatic and the solution aligns with Git’s defensive programming practices. This is a minor protocol hygiene improvement rather than a correctness bug, and it does not block merging the series. The thread now has a clear path forward for a follow-up patch or an incremental update to patch 2/8.
