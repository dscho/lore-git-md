This is a **bugfix patch** for the `git history squash` subcommand, part of Phillip Wood’s series of fixup commits addressing edge cases in Harald Nordgren’s v10 implementation. The patch prevents the command from attempting to squash down to a root commit (a commit with no parents), which the current implementation does not support and could lead to data loss or unexpected behavior.

The change is straightforward: in `resolve_squash_range()`, the code now checks if a commit has no parents (`!commit->parents`) and errors out with a clear message ("cannot squash down to root commit"). The accompanying test verifies this behavior by creating a disconnected root commit and confirming the command rejects the operation. The test also explains why the `--ancestry-path` option makes it difficult to accidentally trigger this edge case, as the revision walk will only include commits descended from the specified base.

This fix aligns with the stricter input validation introduced in v11 of Harald’s series, which also rejects ranges reaching a root commit. While v11 has since been posted, Phillip’s patch remains relevant as a targeted correction for the v10 codebase. The change is **well-motivated** and **tested**, addressing a clear correctness issue without introducing new complexity. It’s a small but important part of the broader effort to harden the `squash` subcommand against malformed input.
