This is a **substantive review fixup patch** for the `git history squash` command, part of Harald Nordgren’s v11 series to fold commit ranges into a single commit. Phillip Wood refines the ref-handling logic to make the command’s behavior more consistent and predictable.

The patch reworks how the command detects and rejects operations that would affect branches pointing to commits inside the squashed range. Previously, the code only protected branches that pointed *directly* at a squashed commit, ignoring branches descended from those commits. This led to inconsistent behavior: a branch pointing to a squashed commit was protected, but a branch pointing to its descendant was not, even though both would be affected by the squash. Phillip’s change tightens this by protecting *all* branches descended from the squashed range, not just those pointing directly to a squashed commit. This makes the behavior more intuitive and aligns with the principle of least surprise.

The implementation uses Git’s `ref-filter` API to walk the commit graph and identify branches that would be affected. It only adds commits with parents outside the squashed range to the filter, since all other commits are descended from those. The patch also updates the error message to be more generic ("a branch points to a commit that is being squashed") and removes the previous inconsistency where the command would complain about branches pointing to the *start* of the range but not those pointing to its interior.

Test coverage is updated to reflect the new behavior, though Phillip notes that the error message could be polished further to list the problematic branches by name. The patch also clarifies that detached HEADs are not protected, which is reasonable since they are typically used for experimentation.

This fixup is **ready to merge** and addresses a real usability issue in the v11 series. It is a targeted improvement that does not change the command’s core functionality but makes its ref-handling more robust and consistent. The change is well-motivated and aligns with the series’ overall goal of providing a safer, more predictable history-editing tool.
