This is a reply in the ongoing `git add --resolved` feature discussion. Michael Montalbo acknowledges Junio’s argument that false positives (incorrectly flagging a binary file as conflicted) are preferable to false negatives (missing actual conflict markers) in the `has_conflict_markers()` helper. He now agrees the current order of checks—conflict markers first, binary detection second—is correct for this workflow.

Montalbo then shifts the discussion to a new idea: instead of relying on the heuristic `buffer_is_binary()` check, the code could inspect the merge driver used for the file. Since only text-based merge drivers (like the default `text` driver) emit conflict markers, while `binary` and `union` drivers do not, this approach could provide a more deterministic early exit. He suggests this might be conceptually cleaner and eliminate the need for the binary-file heuristic entirely. However, he notes the potential brittleness if new merge drivers are introduced in the future.

The reply does not propose a concrete patch or challenge the current implementation; it is an exploratory suggestion about a possible architectural refinement.
