This is a **bugfix patch** for the `git history squash` subcommand, part of the ongoing effort to stabilize the feature before integration. The patch corrects a long-standing oversight in how the command handles merge commits: when the first commit in the squashed range is a merge (has multiple parents), the resulting squashed commit should preserve all parents, not just the first one. The current implementation silently drops all but the first parent, corrupting the commit topology.

The fix is straightforward: instead of hard-coding the first parent of the oldest commit as the sole parent of the squashed commit, the code now uses the full parent list from the oldest commit. This ensures that merges are preserved correctly. The patch also removes an unused `base` variable and simplifies the parent-handling logic in `cmd_history_squash()`, eliminating redundant list manipulation.

A new test case verifies the behavior: it creates a merge commit, amends it with an `amend!` message, and then squashes the amended merge with its immediate parent. The test checks that the squashed commit retains both parents, that the tree matches the original merge, and that the commit message is correctly preserved.

This is a **clear correctness fix** with no downsides. The change is minimal, well-tested, and directly addresses a bug that could silently corrupt history. It has already been incorporated into the v11 series, but this standalone version is useful for anyone testing v10. The patch is ready to merge and should be uncontroversial.
