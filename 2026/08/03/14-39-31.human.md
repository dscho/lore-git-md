This is the fourth patch in the v3 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch introduces `struct fetch_object_info_results`, a dedicated data structure for storing the results of `fetch_object_info()`, replacing the previous use of `struct object_info`.

The change is a clean architectural refactoring that addresses the inefficiency of the old design, where `fetch_object_info()` allocated one scalar per object per attribute just to provide pointers for `read_object_info()` to fill. The new struct holds only the fields the caller requests (currently size and type), with arrays allocated only for the attributes the server both advertised and answered. The caller controls which fields are populated via `wants_*` flags, and the results are released with `free_fetch_object_info_results()`. The patch also drops the now-unnecessary `object_info_options` string list, `remote_atom_map[]`, and `free_object_info_contents()`, simplifying the code and reducing memory overhead.

The implementation follows the hybrid design proposed by Junio and refined by Peff, avoiding sentinel values and boolean flags in favor of a single array of lightweight structs. The changes touch `fetch-object-info.c`, `fetch-object-info.h`, `builtin/cat-file.c`, and `transport.c`, with mechanical updates to function signatures and call sites. The patch is well-motivated and aligns with the established pattern from the predecessor series, though reviewers familiar with the object-info subsystem may want to verify the memory management and error handling. The refactoring is a necessary step for the `%(objecttype)` support added in later patches.
