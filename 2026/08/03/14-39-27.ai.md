This is the third iteration of a Google Summer of Code feature patch series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series now consists of eight patches, up from six in v2, reflecting a significant refactoring of the underlying data structures in response to feedback from Junio C Hamano and Jeff King (Peff).

The core goal remains unchanged: object type is the last piece of metadata guaranteed to match between client and server after a fetch, and this series adds end-to-end support for querying it via remote-object-info. The implementation now bypasses the `struct object_info` machinery entirely, replacing it with a dedicated `struct fetch_object_info_results` that holds only the fields the caller requests (currently size and type). This hybrid design—proposed by Junio and refined by Peff—avoids sentinel values and boolean flags, instead using a single array of lightweight structs where the caller controls which fields are populated. The refactoring is spread across four preparatory patches (1–4), with the actual type support added in patches 5–8.

Key changes in v3 include:
- A new safety check (patch 2) that dies if the server sends fewer object-info lines than requested OIDs, fixing a preexisting bug.
- The removal of `struct object_info_args` (patch 3), passing its members directly to `fetch_object_info()`.
- The introduction of `struct fetch_object_info_results` (patch 4), which replaces `struct object_info` and drops the `object_info_options` string list, `remote_atom_map[]`, and `free_object_info_contents()`.
- The removal of the v2 patch that looped over `object_info_options` in `send_object_info_request()`, as the list no longer reaches it.
- A test cleanup (patch 1) reworded to clarify why `wc -c | xargs` is unreliable for file size checks.
- Shell quoting fixes in tests (patch 7) to align with Git’s conventions.

The series touches `protocol-caps.c`, `fetch-object-info.c`, `serve.c`, `builtin/cat-file.c`, and documentation files, with test updates in `t5701` and `t1017`. New symbols include the `fetch_object_info_results` struct, the `type` array in the results, and the "type" capability in the protocol. The default format string in `cat-file` is unified to `%(objectname) %(objecttype) %(objectsize)` for all queries, removing a temporary workaround.

The refactoring addresses the memory inefficiency and awkwardness of the v2 design while retaining simplicity. Junio and Peff have confirmed that sentinel values like `OBJ_NONE` are unsuitable for fields like `size`, and the new approach avoids them entirely. Pablo has not yet responded to this design, but the GSoC deadline is approaching, and the refactoring is now part of the series. The implementation appears well-motivated and follows the established pattern from the predecessor series, though the architectural changes may warrant closer scrutiny from reviewers familiar with the object-info subsystem.
