This is the seventh patch in Pablo Sabater’s eight-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now at v3, with the architectural refactoring (replacing `struct object_info` with `struct fetch_object_info_results`) already implemented in earlier patches.

This patch is a small but essential step: it updates the server to advertise the "type" capability alongside "size" in the `object-info` protocol extension. Without this advertisement, the client will not request object type data, even if the server can provide it. The change is mechanical—adding the word "type" to the capability string in `serve.c`—but it enables the end-to-end functionality the series is building toward.

The test updates in `t1017` reflect the new behavior: the test that previously verified `%(objecttype)` returned an empty string now expects the actual type ("blob"), and a new test checks that truly unsupported placeholders (e.g., `%(objectmode)`, `%(deltabase)`) still return empty strings. The test cleanup is thorough and aligns with the series’ focus on robustness.

This patch is uncontroversial and appears ready to merge once the rest of the series is reviewed. It touches only two files and makes no behavioral changes beyond enabling the feature. The GSoC deadline is approaching, and this is one of the final pieces needed to complete the object type support.
