This is a **refactoring and robustness patch** for the `git history squash` subcommand, part of Phillip Wood’s seven-patch series offering substantive improvements to Harald Nordgren’s v10 implementation. The patch reworks how `rev-list` options are parsed and validated, making the code more consistent and future-proof.

The key change is replacing a hybrid approach—where some `rev-list` options were passed via `argv` and others set directly in `struct rev_info`—with a uniform method that sets all required options in the struct upfront. This matches the pattern used in `git replay` and eliminates the need to duplicate `argv` into a temporary `strvec`. The patch also adds defensive checks for `--ancestry-path` and related options, ensuring they cannot be overridden by user input (even though the current CLI does not expose them).

The diff touches only `builtin/history.c`, modifying `resolve_squash_range()` to accept `argc` alongside `argv` and using `setup_revisions()` instead of `setup_revisions_from_strvec()`. It also moves the reflog message construction earlier in `cmd_history_squash()`, avoiding a redundant `argc`/`argv` join later. The changes are mechanical but improve maintainability and reduce the risk of subtle bugs if the CLI evolves.

This patch is **ready to apply** and complements v11’s stricter range validation. While v11 has already addressed some of Phillip’s concerns, this refactoring remains valuable for its consistency and defensive programming. The patch is part of a larger effort to tighten the implementation, and its adoption would make the codebase more robust.
