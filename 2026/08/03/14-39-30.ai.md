This is a refactoring patch in the GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. Specifically, patch 3/8 removes the intermediate `struct object_info_args` and passes its three pointer members (`server_options`, `oids`, and `object_info_options`) directly to `fetch_object_info()` and `send_object_info_request()`.

The change is purely mechanical: every call site now lists the three parameters explicitly instead of bundling them in a struct. The commit message explains that the struct suggested a tighter coupling than actually exists—`fetch_object_info()` does not use all three fields in every code path. No behavior changes are intended, and the patch is presented as a cleanup that makes the API surface clearer.

The patch touches `fetch-object-info.c`, `fetch-object-info.h`, and `transport.c`, updating function signatures and call sites. The diff is straightforward, with the only complexity being the increased line length in some function declarations. The change is part of the larger architectural shift in v3 toward a dedicated `struct fetch_object_info_results` (introduced in patch 4), which will replace `struct object_info` entirely. This patch paves the way for that refactoring by eliminating the now-redundant grouping struct.
