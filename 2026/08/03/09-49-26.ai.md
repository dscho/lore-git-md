This is a **substantive review patch** from Phillip Wood, targeting the `git history squash` subcommand in Harald Nordgren’s v10 series. The patch overhauls the handling of `fixup!`, `squash!`, and `amend!` commits to ensure their messages are preserved according to stricter rules, addressing edge cases that v10 (and v11) do not fully resolve.

The patch replaces the existing `reject_dangling_fixups()` logic with a new `squash_check_subject()` mechanism that tracks commit subjects and their autosquash targets using a `strintmap`. This allows the command to:
- **Reject `squash!` or `amend!` commits** unless their target is the first commit in the range or the message is explicitly edited (`--reedit-message`), preventing accidental message loss.
- **Preserve `amend!` messages** when squashing into a `fixup!` commit by converting the subject prefix to `amend!` and appending the body.
- **Support nested fixups** (e.g., `fixup! fixup! target`) by recursively stripping autosquash prefixes.
- **Validate targets** more strictly, rejecting `fixup! HEAD^` or `fixup! main` in favor of fixed object IDs or subject-based targets.
- **Maintain authorship** from the first commit in the range, matching `git rebase --autosquash` behavior.

Key changes include:
- **New helpers**: `is_autosquash_subject()`, `skip_one_autosquash_prefix()`, `truncate_message_to_subject()`, and a `subject_data` struct to manage subject tracking.
- **Refactored `resolve_squash_range()`**: Now returns the constructed squash message and integrates subject validation.
- **Updated tests**: New cases verify nested fixups, `squash!`/`amend!` message preservation, and rejection of invalid targets.

The patch is **technically sound** but conflicts with v11’s approach, which adopts a more permissive default (editing the message by default) and simpler message handling. Phillip’s stricter rules could inform future iterations, particularly for users who rely on `amend!`/`squash!` messages for commit hygiene. The implementation is efficient (single-pass commit processing) and aligns with the project’s emphasis on correctness over convenience.
