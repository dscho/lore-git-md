This is a **substantive review fixup** for the `git history squash` feature, part of Harald Nordgren’s v10 series. Phillip Wood tightens the input validation to **reject ranges with more than one tip**, a correctness improvement that ensures the squash operation only proceeds when the commit range has a single, unambiguous endpoint.

The patch replaces the previous `--boundary`-based validation with a more precise approach: it marks each commit as a potential tip, then iterates over parents to unmark them if they are already seen. This lets the code count the number of tips and error out if more than one remains. The change also improves error messages by explicitly naming the offending parent commit when a commit’s parent lies outside the range. A new test case verifies the rejection of multiple tips, while existing tests are updated to reflect the stricter validation.

This fixup is **already incorporated into v11** of the series, which is functionally complete and marked "Will replace" by Junio. The patch itself is **ready to merge** as part of the larger effort, but its value now lies mainly in documenting the stricter validation logic for future reference.
