This is patch 7/8 of Pablo Sabater’s GSoC v3 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch is small and mechanical: it advertises the new "type" capability in the server’s object-info advertisement so the client knows it can request object type metadata.

The change touches only two files. In `serve.c`, the `object_info_advertise()` function now appends " type" to the advertised capabilities string, matching the existing "size" capability. In `t/t1017-cat-file-remote-object-info.sh`, the test that previously verified unsupported placeholders return empty strings is updated to expect the actual object type ("blob") for `%(objecttype)`, and a new test is added to confirm that truly unsupported placeholders (`%(objectmode)`, `%(objectsize:disk)`, etc.) still return empty strings.

The patch is uncontroversial and follows directly from the architectural refactoring in earlier patches (notably patch 5/8, which added server-side handling for type requests). It completes the server-side capability advertisement chain, enabling the client to request and receive object type data. No new symbols or behavior changes are introduced beyond the advertised capability string. The test updates are straightforward and maintain backward compatibility for unsupported placeholders. CI passed on GitHub.
