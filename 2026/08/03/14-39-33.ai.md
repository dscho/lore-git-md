This is the sixth patch in Pablo Sabater’s eight-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now at v3, with the architectural refactoring (introducing `struct fetch_object_info_results` and bypassing `struct object_info`) fully implemented in earlier patches.

This patch teaches the client to parse object type data from the server’s response. The server-side handler was updated in patch 5/8 to transmit type as a string (e.g., `"blob"`), and this patch completes the client-side logic by mapping that string to Git’s internal `enum object_type` using `type_from_string_gently()`. The parsed type is stored in the `types` array of `struct fetch_object_info_results` and later passed to `builtin/cat-file.c` for display. The patch also adds a safety check to `die()` if the server sends an invalid type string, aligning with Git’s defensive programming practices.

The implementation is straightforward and follows the established pattern for parsing size data. The new code is symmetric with the existing size-parsing logic, differing only in the use of `type_from_string_gently()` instead of `strtoumax()`. The patch touches `fetch-object-info.c`, `fetch-object-info.h`, and `builtin/cat-file.c`, adding minimal new logic while reusing the infrastructure introduced in earlier patches. No test coverage is added here, but the series expands test coverage in `t5701` and `t1017` elsewhere.

The patch is well-motivated and uncontroversial, assuming the server-side changes in patch 5/8 are correct. The only potential point of scrutiny is the error handling for invalid type strings, which currently `die()`s—this matches the existing behavior for malformed size data and is consistent with Git’s fail-fast philosophy. The patch is part of the end-to-end chain for object type metadata and brings the series one step closer to completion. The GSoC deadline is approaching, and this patch is a key piece of the remaining work.
