This is the **maintainer's final review** of the second patch in the `--reset-when-found` feature series for `git bisect`. The patch implements the core functionality: a `--reset-when-found[=<where>]` option that automatically resets the bisect state after identifying the first bad commit, targeting automated workflows and interactive debugging.

Junio’s review is **substantive and tested**, reflecting a thorough reading of the 500+ line patch. He raises no blocking concerns but notes several minor points for clarity and future-proofing. Key observations:

- The patch correctly centralizes auto-reset logic in `cmd_bisect()`, reads `refs/bisect/bad` directly before reset (eliminating the static `first_bad_oid`), and uses a sentinel value (`RESET_WHEN_FOUND_NONE`) for the `reset_when_found` variable. These changes address his earlier feedback and are now uncontroversial.
- He flags a **behavioral subtlety**: `bisect_reset()` no longer calls `bisect_clean_state()`, so callers (like `cmd_bisect__reset()` and `bisect_reset_when_found()`) must now explicitly invoke it. This is a deliberate refactoring, but the patch handles it correctly.
- The review highlights **style distractions**: two hunks (reflowing function signatures in `bisect_next()` and `bisect_auto_next()`) are pure style clean-ups that could have been split into a separate patch to avoid reviewer fatigue. Junio suggests omitting such changes in large patches to keep focus on the feature.
- A **minor logic question**: he wonders whether other "dead end" bisect states (e.g., contradictory good/bad labels) should also trigger auto-reset, but this is framed as an educational aside rather than a requirement.
- The only **debatable change** is an `else` clause added to `cmd_bisect()`’s term-validation logic. Junio finds it unnecessary (since `usage_msg_optf()` doesn’t return) but acknowledges it’s a matter of taste.

The patch is **technically sound** and ready for `next`. Junio’s feedback is entirely about polish, not correctness, and the author has already addressed all prior maintainer requests. The series is now a clean two-patch set (preparatory plumbing + feature) with no loose ends.
