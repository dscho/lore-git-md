This is a **test fix** for platform compatibility. Kenneth Lorber addresses a spurious failure in `t7528-signed-commit-ssh.sh` when the test suite runs under a `csh`-style shell (like `tcsh`). The issue occurs because `ssh-agent` emits shell initialization code in `csh` syntax if the user’s `$SHELL` variable points to a `csh`-like shell, even though the test harness explicitly uses Bourne shell (`sh`). This mismatch causes the test to fail with errors like `eval: setenv: not found`.

The fix is minimal and surgical: it adds the `-s` flag to `ssh-agent` to force Bourne shell syntax, ensuring consistent behavior regardless of the user’s login shell. The change touches only one line in `t/t7528-signed-commit-ssh.sh` and is uncontroversial. The commit message clearly explains the problem, the solution, and why an alternative approach (clearing `$SHELL` in `test-lib.sh`) was rejected—it could mask similar issues elsewhere.
