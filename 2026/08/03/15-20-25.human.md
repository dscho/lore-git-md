This is a review comment on Kristoffer Haugsbakk’s bugfix patch for Git’s trailer parsing. Jeff King (Peff) responds to the patch that implements the previously agreed-upon solution to stop Git from misinterpreting URLs as trailers in commit messages.

Peff’s feedback is substantive but narrowly focused. He suggests a minor readability improvement to the code: replacing the manual `://` check with `starts_with(c, "://")`, which would make the intent clearer without changing the behavior. He also muses briefly about future improvements—specifically, whether Git could be smarter about bracketed comments (like `[peff: some note]`) to avoid false trailer matches—but makes it clear this is not a critique of the current patch, just an idea for later.

The patch itself remains well-motivated and complete, addressing a real-world issue with 245 documented instances in the Linux kernel. Peff’s review does not raise any technical objections or request changes to the core logic; it is a surface-level suggestion aimed at code clarity. The patch is effectively ready for integration, pending any final tweaks to address this nit.
