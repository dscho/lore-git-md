This is a user-facing error message improvement for `git worktree add`. The patch addresses a usability pain point: when a user tries to create a worktree from a branch name that exists on multiple remotes (e.g., `foo` when both `origin/foo` and `upstream/foo` exist), Git currently fails with a terse "matched multiple remote tracking branches" warning and no guidance on how to proceed.

The change adds a detailed advice message that explains the ambiguity and offers two concrete workarounds: either specify the fully qualified remote branch name (`origin/foo`) or set `checkout.defaultRemote` in the Git config to prefer one remote by default. The advice is only shown when the new `advice.checkoutAmbiguousRemoteBranchName` setting is enabled (which it is by default). The patch also updates the existing tests to verify the new warning text and adds a new test case that checks the behavior when `--guess-remote` encounters an ambiguous branch name.

The implementation touches `builtin/worktree.c` and the corresponding test script `t/t2400-worktree-add.sh`. The code changes are localized to the DWIM (Do What I Mean) logic that guesses branch names, and the advice message is defined as a static string at the top of the file. The patch is well-motivated, includes test coverage, and follows the project's advice-message conventions. It looks like a straightforward usability win with no obvious downsides.
