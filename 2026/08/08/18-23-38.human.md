This is a bug report about inconsistent behavior between `git rebase` and `git merge` when given a nonexistent `-X` (or `--strategy-option`) argument.

The author demonstrates that `git rebase -X sillyoption` silently ignores the invalid option and proceeds with the rebase, while `git merge -X sillyoption` correctly reports an error. This inconsistency could mislead users into thinking their rebase operation succeeded with the intended strategy option when it actually did not. The report includes a detailed reproduction scenario using a test repository, showing the exact steps and output.

The issue is well-documented with clear examples, making it easy to verify. The author is running Git 2.55.0 on Fedora Linux 44. While the report does not include a proposed patch, the problem is straightforward and likely to be addressed quickly once confirmed. This looks like a genuine, user-facing bug worth fixing.
