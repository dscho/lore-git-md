This thread is a bug report about an inconsistency in how Git handles invalid `-X` (strategy-option) arguments between `git rebase` and `git merge`. The author, zrzut01@poczta.fm, demonstrates that while `git merge -X nonexistent-option` correctly reports an error, `git rebase -X nonexistent-option` silently ignores the invalid option and proceeds with the operation. This silent failure could mislead users into thinking their intended option was applied when it wasn't.

The report is thorough, including a clear reproduction scenario with exact commands and outputs, and identifies Git 2.55.0 as the tested version. The issue appears to be a genuine usability bug, likely stemming from differing error-checking logic in the merge strategy machinery between the two commands. No patch or prior discussion is mentioned, suggesting this is a newly identified problem. The thread is currently just the initial report, so no decisions or follow-ups have occurred yet.
