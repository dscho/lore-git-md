This is the fifth patch in Pablo Sabater’s ten-patch GSoC series, now at v6, which extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is feature-complete, addresses all prior review feedback, and Junio has explicitly endorsed all ten patches as ready to merge.

This patch aligns the last remaining error path in `fetch_object_info()` with Git’s defensive programming practices by converting it to `die()` instead of returning an error code. Previously, a short read while parsing attribute lines returned `-1`, which propagated through several layers before eventually triggering a generic `die()` in `cat-file`. The change makes `fetch_object_info()` void and updates its callers in `transport.c` to drop the now-unused return value check. The patch is purely mechanical, touching only `fetch-object-info.c`, `fetch-object-info.h`, and `transport.c`, and does not alter behavior or introduce new functionality.

The motivation is consistency: every other failure in `fetch_object_info()` already calls `die()`, so this patch eliminates the sole exception. The error message is specific, reporting the expected and actual number of attributes, which helps diagnose protocol mismatches or server misbehavior. The change is uncontroversial and has been explicitly endorsed by Junio as ready for integration.
