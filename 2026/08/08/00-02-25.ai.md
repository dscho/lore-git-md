This is the final patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch unifies the default output format for all `cat-file` batch commands, removing the temporary workaround that used `%(objectname) %(objectsize)` for remote queries and `%(objectname) %(objecttype) %(objectsize)` for local ones. With object type support now complete, the default format is `%(objectname) %(objecttype) %(objectsize)` for all queries, ensuring consistent output across all transport protocols (git://, file://, http://).

The patch touches four files: `Documentation/git-cat-file.adoc`, `Documentation/gitprotocol-v2.adoc`, `builtin/cat-file.c`, and `t/t1017-cat-file-remote-object-info.sh`. In the documentation, it removes the warning about the temporary format and updates the caveats to include `%(objecttype)` as a supported placeholder. In `gitprotocol-v2.adoc`, it clarifies the protocol’s response format, noting that values appear in the same order as the requested attributes. The code change in `builtin/cat-file.c` removes the conditional format logic in `parse_cmd_remote_object_info()`, dropping the temporary format override. The test suite is updated to expect the full default format (including object type) for all queries, confirming that mixing `info` and `remote-object-info` commands produces identical results.

The patch is mechanical and uncontroversial, addressing the last piece of technical debt from the temporary format workaround. All prior review feedback has been addressed, and Junio has explicitly endorsed this patch as ready to merge. The series is now feature-complete and ready for integration.
