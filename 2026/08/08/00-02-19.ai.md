This is patch 4/10 of Pablo Sabater’s GSoC v6 series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch replaces the `object_info`-based parsing logic with a dedicated `struct fetch_object_info_results` that avoids sentinel values and boolean flags, streamlining how object metadata is stored and handled.

The core change introduces `struct fetch_object_info_results`, where the caller sets `wants_*` flags to indicate which attributes it is interested in (currently only `wants_size`, but `wants_type` will follow in patch 8/10). The function then allocates one array per attribute, with a non-NULL array signaling availability. The caller releases these arrays with `free_fetch_object_info_results()`. This design eliminates the need for `object_info_options` (a string list of requested attributes) and `remote_atom_map[]` (which mapped protocol strings back to atom names), simplifying the code and removing about 30 lines of conditional logic.

The patch also drops `free_object_info_contents()`, which loses its only caller, and converts the final `else` in `fetch_object_info()` to `die()` instead of `BUG()`—an unknown attribute is now treated as a server error rather than an internal bug. The diff touches seven files, with the bulk of the changes in `fetch-object-info.c` and `builtin/cat-file.c`. In `fetch-object-info.c`, the patch replaces `object_info_data` with `results`, updates the function signature, and rewrites the parsing logic to populate the new struct. In `builtin/cat-file.c`, it removes the `remote_atom_map[]` array, updates the caller to use `results`, and replaces `free_object_info_contents()` with `free_fetch_object_info_results()`.

Key symbols introduced are `struct fetch_object_info_results`, the `wants_size` flag, the `sizes` and `unrecognized` arrays, and `free_fetch_object_info_results()`. The patch is purely refactoring—no behavior changes or protocol-level adjustments are involved. Junio has explicitly endorsed this patch as ready to merge, noting that it removes redundant code and aligns with the new design. The change prepares the codebase for the subsequent patches that implement object type support, though it does not introduce that functionality itself.
