This is a follow-up review in the thread improving the `git worktree add` error message for ambiguous remote branch names. Junio C Hamano expands on his earlier feedback, now focusing on what information the advice message should *actually* provide to users.

The core issue Junio raises is that the current advice ("use `git worktree add <path> origin/<name>`") assumes the user’s problem is *syntax*—that they don’t know how to specify a fully qualified branch name. But the real problem might be *discovery*: the user may not remember which remotes (`origin`, `upstream`, etc.) even *have* the branch they want. The patch’s advice doesn’t help with that. Junio suggests the message should instead list the conflicting remotes (e.g., "the branch exists on `origin`, `upstream`, and `home`") to let the user choose the right one.

This is a substantive refinement to the usability goal. The patch’s current approach is technically correct but misses an opportunity to be more helpful in the common case where the user simply forgot which remotes exist. Junio’s proposal would make the advice more actionable by surfacing the specific remotes involved, rather than leaving the user to guess or run `git branch -r` separately.

The review doesn’t reject the patch’s direction but pushes for a more user-centered design. No code changes are suggested yet—this is purely about the advice message’s content. The files involved remain `builtin/worktree.c` (where the advice is triggered) and the config key `advice.checkoutAmbiguousRemoteBranchName`. The thread is still under review, and a v2 will likely incorporate this feedback.
