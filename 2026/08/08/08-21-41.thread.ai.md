Thread identity: Patch series improving user-facing error message for `git worktree add` when an ambiguous remote branch name is provided (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). Single-patch series, originating author Yoichi NAKAYAMA, thread type: patch series.

Core problem or goal: Replace the terse "matched multiple remote tracking branches" warning with a detailed advice message to help users resolve ambiguity. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and focuses on *script-friendly discovery* (providing a command to list conflicting remotes) rather than a static list of remotes or syntactic workarounds. The patch also refines error handling by moving an existing `die()` call earlier in the code path, replacing a generic "invalid reference" message with a more specific diagnostic that explains the ambiguity. This is a usability improvement, not a regression, as the command was already failing — just with less clarity. The problematic flow (silent failure to resolve ambiguity -> `NULL` remote -> misleading "invalid reference" error) is now explicitly traced in the commit message to justify the early `die()` as intentional. The implementation avoids altering `dwim_branch()`'s return behavior, addressing concerns about workflow disruption.

Current status: Under review. Three iterations (v1, v2, v3).
