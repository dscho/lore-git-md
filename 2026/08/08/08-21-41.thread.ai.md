Thread identity: Patch series improving user-facing error message for `git worktree add` when an ambiguous remote branch name is provided (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). Single-patch series, originating author Yoichi NAKAYAMA, thread type: patch series.

Core problem or goal: Replace the terse "matched multiple remote tracking branches" warning with a detailed advice message to help users resolve ambiguity. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and is intended to focus on *script-friendly discovery* (providing a command to list conflicting remotes) rather than a static list of remotes or syntactic workarounds. The patch also introduces an unannounced behavior change: calling `die()` when ambiguity is detected, which may break existing workflows if users relied on Git proceeding despite the ambiguity.

Current status: Under review. No prior versions.
