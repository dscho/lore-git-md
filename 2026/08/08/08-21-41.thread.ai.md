Core problem or goal: Replace the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message to help users resolve ambiguity. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and provides a static list of conflicting remotes (e.g., "Branch name '%s' appears in multiple remotes:") for immediate usability. The series also refines error handling by moving an existing `die()` call earlier in the code path, replacing a generic "invalid reference" message with a more specific diagnostic that explains the ambiguity. This is a usability improvement, not a regression, as the command was already failing — just with less clarity. The problematic flow (silent failure to resolve ambiguity -> `NULL` remote -> misleading "invalid reference" error) is explicitly traced in the commit message to justify the early `die()` as intentional. The implementation avoids altering `dwim_branch()`'s return behavior, addressing concerns about workflow disruption. The series now also fixes a latent bug in the `--guess-remote` option of `git worktree add`: when multiple remote branches match the given name, the command previously succeeded silently, which could lead to unexpected behavior. The fix treats this scenario as an error, aligning it with the behavior of `git checkout` and `git switch`. The one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`) remains slated for a follow-up fix, as agreed in the thread.
