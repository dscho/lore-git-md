Thread identity: Patch series improving user-facing error messages for `git worktree add`, `git checkout`, and `git switch` when an ambiguous remote branch name is provided (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). Sixth iteration (v6) of a three-patch series originating from Yoichi NAKAYAMA. Thread type: patch series.

Core problem or goal: Replace the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message to help users resolve ambiguity. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and provides a static list of conflicting remotes (e.g., "the branch exists on `origin`, `upstream`") for immediate usability. The series also refines error handling by moving an existing `die()` call earlier in the code path, replacing a generic "invalid reference" message with a more specific diagnostic that explains the ambiguity. This is a usability improvement, not a regression, as the command was already failing — just with less clarity. The problematic flow (silent failure to resolve ambiguity -> `NULL` remote -> misleading "invalid reference" error) is explicitly traced in the commit message to justify the early `die()` as intentional. The implementation avoids altering `dwim_branch()`'s return behavior, addressing concerns about workflow disruption.

Current status: Functionally complete but requires two final adjustments before merging. The series is fully implemented across `git checkout`, `git switch`, and `git worktree add` via the shared `advise_disambiguating_remotes()` helper and `advise_ambiguous_remote()` logic. Junio C Hamano and D. Ben Knoble have reviewed the series and agreed on all structural adjustments: renaming the helper to `advise_disambiguating_remotes()` for clarity and splitting the first patch into three logical steps (mechanical refactoring in patch 1/3, functional change for `checkout`/`switch` in patch 2/3, and extension to `worktree add` in patch 3/3) to improve reviewability. The third and final patch (v6 3/3) extends the shared advice helper to `git worktree add`, but Junio has identified two issues: a grammatical error in the advice message ("Branches ... appears" should be "appear") and an unhandled edge case in the one-argument form of `git worktree add` (e.g., `git worktree add ../topic-branch`), where the branch name is guessed from the path but ambiguity is not detected. The edge case risks reintroducing the same silent failure and misleading "invalid reference" error that the series aims to fix. Junio suggests extending the disambiguation logic to this code path by calling `unique_tracking_name()` with the `string_list` parameter to detect and report ambiguity before proceeding. The series remains ready for merging once these nits are resolved.
