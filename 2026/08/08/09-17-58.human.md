This is the latest exchange in the long-running thread to add a `--linearize` option to `git replay`. Elijah Newren responds to Justin Tobler’s review of the final patch in the v8 series, agreeing with several of Justin’s points about documentation clarity and error-message wording.

The discussion centers on two user-facing issues. First, Elijah endorses Justin’s suggestion to simplify the documentation’s justification for restricting `--linearize` to single branches. Instead of explaining the technical rationale (emergent reachability issues), the text should simply state that multiple branches are not supported. Second, both agree that error messages should use “branches” rather than “revision ranges” for consistency with earlier discussion and to avoid confusing users.

Elijah also raises a new technical point: the current implementation may inadvertently allow `--revert` with multiple branches, which could concatenate unrelated histories in an unpredictable order. He suggests tightening the restriction to cover `--revert` as well, aligning with `git cherry-pick`’s behavior.

The series itself remains technically complete and ready for review. Junio has removed the previous version from `next` and will queue v8, but it has not yet been merged. The changes Elijah and Justin discuss are minor and non-blocking, likely to be addressed in a final documentation tweak before integration.
