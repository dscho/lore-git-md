This is a usability improvement for `git worktree add`. The patch addresses a confusing error message when a branch name matches multiple remote tracking branches (e.g., `foo` exists as `origin/foo` and `upstream/foo`). Instead of failing silently or with a cryptic message, it now warns the user about the ambiguity and offers concrete advice: either specify the fully qualified name (`origin/foo`) or set `checkout.defaultRemote` to prefer one remote.

The change touches `builtin/worktree.c` and adds new tests in `t/t2400-worktree-add.sh`. The implementation is straightforward: it counts how many remotes match the branch name, and if there’s more than one, it prints a warning and an advice message. The advice is controlled by a new advice setting (`ADVICE_CHECKOUT_AMBIGUOUS_REMOTE_BRANCH_NAME`), so users can suppress it if desired.

The patch is well-motivated and includes thorough test coverage. It’s a small but meaningful quality-of-life improvement for users who work with multiple remotes. No controversy is evident, and the change aligns with Git’s existing patterns for advice messages. Worth a quick review if you care about worktree usability.
