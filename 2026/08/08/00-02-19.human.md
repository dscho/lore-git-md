This is the fourth patch in Pablo Sabater’s ten-patch GSoC series, now at v6, which extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is feature-complete, addresses all prior review feedback, and Junio has explicitly endorsed all ten patches as ready to merge.

This patch replaces the `object_info` struct—originally designed for local object lookups via `read_object_info()`—with a dedicated `struct fetch_object_info_results` tailored for remote queries. The old struct required allocating one scalar per object per attribute just to hold pointers for `read_object_info()`; the new design lets the caller set `wants_*` flags to indicate interest, and the function allocates one array per attribute only if the server both advertises and answers with that data. The caller releases the arrays with `free_fetch_object_info_results()`, which also zeroes the struct to prevent use-after-free.

The patch drops the `object_info_options` string list and `remote_atom_map[]` entirely. Filtering against the server’s advertisement now sets local `ask_*` flags, and `send_object_info_request()` turns those into protocol option strings. The `remote_allowed_atoms` list is built directly from the result arrays, eliminating the need for string-based lookups. The final `else` in `fetch_object_info()`—now reachable from the wire—dies instead of BUG()ing, treating an unknown attribute as a server error rather than a client bug. The patch also removes `free_object_info_contents()`, which loses its only caller.

The diff is mechanical and touches seven files: `builtin/cat-file.c`, `fetch-object-info.c`, `fetch-object-info.h`, `object-file.c`, `odb.h`, `transport.c`, and `transport.h`. No behavior changes or protocol-level adjustments are involved; the patch simply restructures how object data is stored and handled, preparing the codebase for the subsequent patches that implement object type support. Junio and Jeff King have both helped refine the design, and the patch is explicitly marked as ready for integration.
