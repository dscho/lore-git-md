This thread is about a usability improvement for `git worktree add` that makes error messages more helpful when users provide an ambiguous remote branch name (like `foo` when both `origin/foo` and `upstream/foo` exist). The series, now at its fourth iteration, replaces a generic "invalid reference" error with a clear diagnostic and actionable advice, enabled by default via the new `advice.checkoutAmbiguousRemoteBranchName` config.

Yoichi NAKAYAMA is the author, and the patch has been refined through feedback from Junio C Hamano and D. Ben Knoble. The core change moves an existing `die()` call earlier in the code to provide a more specific error message, while keeping the rest of the workflow intact. The advice message suggests either using a fully qualified branch name or setting `checkout.defaultRemote`, and it uses a command (`git branch -r --list '*/<name>'`) to dynamically list conflicting remotes—a design choice that prioritizes flexibility over a static list of remotes, which Junio initially preferred.

The patch touches `builtin/worktree.c` and updates tests in `t/t2400-worktree-add.sh`. All substantive feedback has been addressed, and while minor code nits (like unnecessary braces) remain, they don’t affect functionality. The only unresolved discussion is whether the command-based advice is more effective than a static list, but this isn’t a blocker. The series is now ready for merging, offering a clear usability win without disrupting existing workflows.
