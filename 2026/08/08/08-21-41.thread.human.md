This thread is about a small but user-facing improvement to `git worktree add`: when you try to add a worktree for a branch name that exists on multiple remotes (e.g., `foo` when both `origin/foo` and `upstream/foo` exist), Git currently shows a terse warning. Yoichi NAKAYAMA’s patch replaces that with a more helpful advice message that lists the conflicting remotes, making it easier for users to resolve the ambiguity.

The patch is under review and hasn’t been revised yet. Junio C Hamano provided the main feedback, focusing on two things: first, that the advice should prioritize *discovery* (listing the conflicting remotes) over just suggesting syntactic workarounds, and second, a minor formatting nit about an unnecessary newline in the warning. The patch touches `builtin/worktree.c` and updates the test suite, and the only open questions are about how to format the list of remotes in the advice and whether the commit message adequately explains the shift in focus.

So far, only Junio’s feedback carries real weight—Harald Nordgren’s brief endorsement didn’t engage with the technical details, and Junio later gently corrected it for lacking context. The next version will likely address Junio’s points, but there’s no controversy or deeper design debate here; it’s just a matter of refining the wording and presentation.
