This thread is about a patch from Yoichi NAKAYAMA that improves the error message when `git worktree add` encounters an ambiguous remote branch name (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The patch replaces the terse warning with a detailed advice message, gated by the new `advice.checkoutAmbiguousRemoteBranchName` config (enabled by default). The goal is to help users resolve ambiguity by providing actionable guidance, but the discussion has shifted to how best to present that guidance—whether as a static list of conflicting remotes or a command (`git branch -r --list '*/<name>'`) for dynamic discovery.

The patch is under active review, with two key points of contention. First, Junio C Hamano initially suggested a static list of remotes for immediate usability, but Yoichi now proposes a command-based approach to avoid overwhelming users and align with script-friendly workflows. Junio’s earlier feedback on minor code style issues (unnecessary braces, newlines) remains unaddressed, but the `die()` issue is now the most pressing technical hurdle.

The patch touches `builtin/worktree.c` and updates tests in `t/t2400-worktree-add.sh`. While the advice message’s format is still debated, the immediate focus is on whether the new `die()` behavior is safe or needs to be reverted or documented.
