This thread is about a patch from Yoichi NAKAYAMA that improves the error message when `git worktree add` encounters an ambiguous remote branch name (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). Instead of a terse warning, the patch adds a detailed advice message listing the conflicting remotes to help users resolve the ambiguity. The advice is enabled by default via `advice.checkoutAmbiguousRemoteBranchName`.

The patch is under review, with Junio C Hamano providing feedback on both usability and code style. He suggested refining the advice to prioritize *discovery* (listing remotes) over generic workarounds and pointed out minor formatting issues (unnecessary newline, unnecessary braces). Yoichi is expected to address these in the next version. The discussion has also touched on whether the advice should vary based on context (e.g., `worktree.guessremote` setting) and how to format the remote list.

Harald Nordgren’s recent reply clarifies his earlier one-line endorsement but adds no new technical input. The thread remains focused on balancing usability with Git’s output conventions, with no decisions finalized yet.
