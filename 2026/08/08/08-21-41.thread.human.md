This thread is about a usability improvement to `git worktree add`. When a user tries to create a worktree from a branch name that exists on multiple remotes (like `foo` when both `origin/foo` and `upstream/foo` exist), Git currently fails with a cryptic error message. Yoichi NAKAYAMA's patch adds a detailed advice message that explains the ambiguity and suggests two workarounds: using the fully qualified branch name (e.g., `origin/foo`) or setting `checkout.defaultRemote` in Git config. The advice is enabled by default but can be turned off via `advice.checkoutAmbiguousRemoteBranchName`.

The patch touches `builtin/worktree.c` and updates the test script `t/t2400-worktree-add.sh` to verify the new behavior. The changes are localized to the DWIM (Do What I Mean) logic for branch name guessing, and the implementation follows Git's advice-message conventions. So far, the patch appears to be a straightforward usability win with no objections or requests for changes. It’s ready for review and, if approved, likely to be merged soon.
