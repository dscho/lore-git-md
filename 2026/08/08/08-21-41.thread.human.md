This thread is about a usability improvement to `git worktree add` that makes error messages more helpful when an ambiguous remote branch name is provided (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The series, now in its third version (v3), is authored by Yoichi NAKAYAMA and replaces a terse warning with a detailed advice message that guides users to resolve the ambiguity. The advice is enabled by default via `advice.checkoutAmbiguousRemoteBranchName` and focuses on script-friendly discovery by providing a command (`git branch -r --list '*/<name>'`) to list conflicting remotes dynamically.

The patch has evolved through feedback from Junio C Hamano, who initially suggested a static list of remotes but later focused on clarifying the commit message’s justification for an error-handling refinement. The latest version (v3) addresses Junio’s request by tracing the problematic code path: the DWIM logic silently fails to resolve ambiguity, leaving a `NULL` remote, which later triggers a misleading "invalid reference" error.
