This thread is about a patch series from Yoichi NAKAYAMA that improves user-facing error messages in `git worktree add`, `git checkout`, and `git switch` when an ambiguous remote branch name is provided (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The series is now in its eighth iteration (v8) and has been merged to Junio C Hamano’s `next` branch, meaning it’s under integration testing for the next Git release.

The goal is to replace the terse "matched multiple remote tracking branches" warning with detailed, actionable advice that lists the conflicting remotes and suggests fixes like using `--track` or setting `checkout.defaultRemote`. The series also fixes a latent bug in `git worktree add --guess-remote`, which previously succeeded silently when multiple matches existed—now it errors out, matching the behavior of `git checkout` and `git switch`. A shared advice helper (`advise_disambiguating_remotes`) was introduced to avoid code duplication across the three commands.

Key participants include Yoichi (the author), Junio (who reviewed, refactored parts of the series, and queued it for `next`), and D. Ben Knoble (who raised concerns about workflow disruption, later addressed by relocating the diagnostic logic). The series is functionally complete, with all prior feedback incorporated. The only remaining loose end is a follow-up fix for the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), which should error out when ambiguity exists but currently doesn’t. This was scoped as a separate commit, with Junio providing historical context and Yoichi agreeing to implement it later. The series is a clear usability win and appears ready for graduation.
