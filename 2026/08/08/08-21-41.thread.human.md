This thread is about a now-completed patch series from Yoichi NAKAYAMA that improves Git's error messages when users try to check out, switch to, or add a worktree for a branch name that exists in multiple remotes (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The series has been merged into Junio Hamano's `next` branch for integration testing and is functionally complete as of its twelfth iteration (v12).

The key change replaces Git's terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message that lists the conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes: origin, upstream"). This advice is enabled by default via the `advice.checkoutAmbiguousRemoteBranchName` config key. The series also fixes a latent bug in `git worktree add --guess-remote`, which previously succeeded silently when multiple matches existed—now it errors out, matching the behavior of `git checkout` and `git switch`. All prior review feedback has been addressed, including structural improvements like renaming a helper function, simplifying a data structure, and clarifying commit messages.

The only remaining loose end is a follow-up fix for the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), which currently succeeds even when ambiguity exists. This was scoped out of the current series by agreement, with Junio providing historical context for the incomplete refactoring. The series has broad support, with substantive reviews from Junio and D. Ben Knoble, and no outstanding objections. Test coverage verifies the new error and advice behavior across all three commands.
