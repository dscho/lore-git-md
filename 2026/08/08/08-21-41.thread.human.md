This thread is about a patch series (now in its fifth iteration) by Yoichi NAKAYAMA that improves Git's error messages when users run `git worktree add`, `git checkout`, or `git switch` with an ambiguous remote branch name (like `foo` when both `origin/foo` and `upstream/foo` exist). Instead of a terse warning, Git now shows a detailed advice message listing the conflicting remotes (e.g., "the branch exists on `origin`, `upstream`") and suggests using `--track` or setting `checkout.defaultRemote` to avoid future ambiguity. The feature is enabled by default but can be disabled via `advice.checkoutAmbiguousRemoteBranchName`.

The series is functionally complete and ready for merging. The latest version splits the work into two patches: the first introduces shared helper functions for the advice logic, and the second applies this to `git worktree add`. Junio C Hamano, the maintainer, has been heavily involved in refining the implementation, including a key refactoring to unify the advice logic across all three commands. D. Ben Knoble raised early concerns about a potential workflow disruption, but these were addressed by preserving the existing behavior of `dwim_branch()`. Knoble’s latest feedback—suggesting a clearer helper name and splitting the first patch for better reviewability—has been accepted by Junio but is not a blocker. Minor code nits remain, but the core usability improvement is now stable and uncontested. The series is under review but technically ready for integration.
