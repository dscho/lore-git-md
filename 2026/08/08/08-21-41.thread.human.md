This thread is about a patch series (v6) from Yoichi NAKAYAMA that improves user-facing error messages when `git worktree add`, `git checkout`, or `git switch` encounter an ambiguous remote branch name (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The series replaces the terse "matched multiple remote tracking branches" warning with detailed, actionable advice, listing the conflicting remotes and suggesting explicit disambiguation. The advice is enabled by default via `advice.checkoutAmbiguousRemoteBranchName` and is now uniform across all three commands.

The series is functionally complete and has received substantive review from Junio C Hamano and D. Ben Knoble. All structural adjustments—such as splitting the series into three patches (mechanical refactoring, functional changes for `checkout`/`switch`, and extension to `worktree add`) and renaming the advice helper—have been incorporated. The only remaining issues are minor: a grammatical error in the advice message ("appears" → "appear") and an unhandled edge case in `git worktree add`'s one-argument form (e.g., `git worktree add ../topic-branch`), where ambiguity isn’t detected if the branch name is inferred from the path. Junio has suggested extending the disambiguation logic to cover this case, which would involve a small, localized change in `builtin/worktree.c`. Neither issue blocks merging, and the series is otherwise ready to go.
