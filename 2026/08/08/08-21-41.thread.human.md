This thread is about a now-completed patch series that improves error messages when users run `git worktree add`, `git checkout`, or `git switch` with an ambiguous remote branch name (like `foo` when both `origin/foo` and `upstream/foo` exist). The series, originally authored by Yoichi NAKAYAMA, has been merged to Junio’s `next` branch after eleven iterations.

The core change replaces a terse warning with a detailed, actionable advice message that lists the conflicting remotes (e.g., “Branch name 'foo' appears in multiple remotes: origin, upstream”). The advice is controlled by the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and works across all three commands. The series also fixes a latent bug in `git worktree add --guess-remote`: when multiple remote branches match, the command now errors out instead of silently creating a branch from HEAD, matching the behavior of `checkout` and `switch`.

All prior feedback has been addressed, including Junio’s suggestions on code structure, function naming, and documentation. The final patch (4/4) adds test coverage for the `--guess-remote` error case and updates the documentation. The only remaining loose end is a follow-up fix for the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), which will be handled separately.
