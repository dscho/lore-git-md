This thread is about a usability improvement for `git worktree add` (and related commands like `git checkout` and `git switch`) that makes error messages more helpful when users provide an ambiguous remote branch name (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The series, originally authored by Yoichi Nakayama, is now in its fifth iteration and has converged on a design that replaces the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message listing the conflicting remotes (e.g., "the branch exists on `origin`, `upstream`").

The core debate—whether to use a static list of remotes (Junio’s preference) or require users to run a separate command to discover conflicts (Yoichi’s initial approach)—has been resolved in favor of the static list. Junio provided a refactoring that extends `unique_tracking_name()` to optionally return the list of conflicting remotes, enabling a consistent advice message across all affected commands. Yoichi has accepted this approach, and the patch is now functionally complete, with all substantive feedback addressed. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and avoids disrupting existing workflows by preserving the return behavior of `dwim_branch()`.

The only remaining open questions are minor: whether to emit a warning for non-`--guess-remote` cases (Ben Knoble supports signaling ambiguity but the final decision is pending) and a rare edge case involving typos in fully qualified branch names (e.g., `origin/bar-topik` matching multiple remotes due to partial matches). These are not considered blockers. The patch is under active review, with Junio’s refactoring providing a clear path forward. Ben Knoble (reviewer), with Junio’s feedback carrying the most weight.
