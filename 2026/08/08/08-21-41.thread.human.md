This thread improves the error message when `git worktree add` encounters an ambiguous remote branch name (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The series, now at version 3, replaces the terse "matched multiple remote tracking branches" warning with a detailed advice message that helps users resolve the ambiguity. The advice is enabled by default via `advice.checkoutAmbiguousRemoteBranchName` and focuses on script-friendly discovery by providing a command (`git branch -r --list '*/<name>'`) to list conflicting remotes dynamically.

The patch touches `builtin/worktree.c` and updates tests in `t/t2400-worktree-add.sh`. The only remaining loose ends are minor code nits (unnecessary newline and braces) and an unresolved design question: whether the command-based advice is more effective than a static list of remotes.
