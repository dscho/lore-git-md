This three-patch series from Yoichi NAKAYAMA improves Git's error messages when users try to check out or add a worktree for a branch name that exists on multiple remotes (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The final patch, just posted, extends the new detailed advice to `git worktree add`, completing the series. Now all three commands—`git checkout`, `git switch`, and `git worktree add`—will fail with a clear, actionable message listing the conflicting remotes and suggesting how to resolve the ambiguity, either by specifying the remote explicitly or by setting `checkout.defaultRemote` in the config.

The series has been reviewed by Junio C Hamano and D. Ben Knoble, who agreed on all structural adjustments, including splitting the series into three logical patches for better reviewability. The implementation is functionally complete, with only minor code nits remaining. The advice is enabled by default (via `advice.checkoutAmbiguousRemoteBranchName`) and avoids altering the underlying branch resolution behavior, ensuring no workflow regressions. The error messages are now uniform across commands and include the number of matching remotes for clarity. Testing covers the new advice format, error message consistency, and edge cases like `--guess-remote`, which remains unaffected. The series is ready for merging.
