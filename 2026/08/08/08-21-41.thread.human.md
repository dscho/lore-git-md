This thread is about a three-patch series (now at v7) by Yoichi NAKAYAMA that improves user-facing error messages when `git worktree add`, `git checkout`, or `git switch` encounter an ambiguous remote branch name—like trying to check out `foo` when both `origin/foo` and `upstream/foo` exist. The series replaces the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message (e.g., "Branch name 'foo' appears in multiple remotes: origin, upstream") that lists the conflicting remotes and suggests using `--track` or setting `checkout.defaultRemote` for future disambiguation. The advice is enabled by default via the new `advice.checkoutAmbiguousRemoteBranchName` config key.

The implementation is shared across all three commands via a new `advise_disambiguating_remotes()` helper, and the series also refines error handling by moving an existing `die()` call earlier in the code path to replace a generic "invalid reference" message with a more specific diagnostic. Junio C Hamano, the maintainer, has reviewed and approved the series, including two minor fixes in v7: a grammatical correction in the advice message and a narrowed scope for the `oid` variable in `builtin/worktree.c`. He praised the revised advice as "much more concise" and confirmed the series is ready for merging to `next`.

One edge case remains unresolved but non-blocking: the one-argument form of `git worktree add` (e.g., `git worktree add ../topic-branch`) silently succeeds when multiple remotes match the branch name, creating a local branch from HEAD. Junio identified this as a latent bug stemming from an incomplete 2018 refactoring but agreed it should be addressed in a follow-up effort. All other review feedback—including concerns about workflow disruption and structural improvements—has been addressed, and the series is now functionally complete with updated test coverage.
