This thread is about a three-patch series (now in its seventh iteration) by Yoichi NAKAYAMA that improves user-facing error messages when Git commands (`git worktree add`, `git checkout`, and `git switch`) encounter ambiguous remote branch names—for example, when you type `git checkout foo` but both `origin/foo` and `upstream/foo` exist. The series replaces the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message that lists the conflicting remotes and suggests how to resolve the ambiguity, either by specifying the remote explicitly or by setting `checkout.defaultRemote` in your Git config. The advice is enabled by default but can be turned off with `advice.checkoutAmbiguousRemoteBranchName`.

The final patch in the series, just posted, extends this improvement to `git worktree add`, completing the work. The implementation is consistent across all three commands, using a shared helper function (`advise_disambiguating_remotes()`) to avoid code duplication. The series also refines error handling by moving an existing `die()` call earlier in the code path, replacing a generic "invalid reference" message with a more specific diagnostic that explains the ambiguity and includes the number of matching remotes. This change was carefully designed to avoid disrupting existing workflows, and the commit messages trace the problematic flow to justify the early `die()` as intentional.
