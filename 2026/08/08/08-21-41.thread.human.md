This thread is about a patch series that improves user-facing error messages in `git worktree add`, `git checkout`, and `git switch` when an ambiguous remote branch name is provided (e.g., `foo` when both `origin/foo` and `upstream/foo` exist). The series, now in its ninth iteration (v8), originated from Yoichi NAKAYAMA and is functionally complete, with all prior feedback addressed. The key change replaces the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message that lists conflicting remotes and suggests resolution steps, gated behind the `advice.checkoutAmbiguousRemoteBranchName` config (enabled by default).

The series has been merged to Junio C Hamano’s `next` branch for integration testing. It covers all three commands and addresses a latent bug in `git worktree add --guess-remote`, which previously succeeded silently when multiple remote branches matched the given name—now it errors out, aligning with the behavior of `git checkout` and `git switch`. The advice logic is refactored into a shared helper, `advise_disambiguating_remotes()`, ensuring consistency across commands. All technical concerns, including workflow disruption and structural improvements, have been resolved, and the series has no remaining objections.

The only loose end is a follow-up fix for the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), which currently succeeds silently when ambiguity exists. Junio and Yoichi have agreed this should error out and will address it separately. The series itself is now stable, with thorough test coverage and clear, command-specific advice messages.
