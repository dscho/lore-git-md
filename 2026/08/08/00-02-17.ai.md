This is a bugfix patch in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote-object-info queries. The patch targets the `fetch-object-info.c` subsystem and addresses a latent protocol robustness issue in the client-side response parsing logic.

The current implementation reads object-info responses in a loop that stops either when the reader returns something other than `PACKET_READ_NORMAL` or when it has read as many lines as requested OIDs. Neither boundary is validated: a server sending too few objects leaves the end of the result arrays uninitialized, while a server sending too many leaves extra packets unread. The latter is caught on stateless transports by `check_stateless_delimiter()`, but on stateful transports (e.g., SSH) it passes silently.

The fix extracts `packet_reader_read()` from the loop condition so the loop no longer consumes the final packet. Inside the loop, if the read is not `PACKET_READ_NORMAL`, the client now `die()`s with a clear message indicating how many objects were expected versus received. After the loop, the client expects a flush packet; if anything else arrives, it `die()`s to fail fast. This change is purely mechanical (10 insertions, 4 deletions) and introduces no new symbols or behavior changes beyond the robustness checks.
