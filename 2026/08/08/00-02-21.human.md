This is the sixth patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote object queries. The patch is a mechanical refactoring by Jeff King (Peff) that removes the `object_info_oids` and `object_info_results` fields from `git_transport_options` and instead passes them as explicit parameters to `transport_fetch_object_info()` and its vtable implementations.

The current design stores pointers to the OID array and results struct in the transport struct, but these are only valid for a single request. This creates a subtle risk: if the transport were reused, the struct could retain dangling pointers to stack variables from the previous call. The fix clarifies ownership semantics—the caller retains responsibility for the OID array and results—and eliminates the latent bug. The change is purely mechanical (25 insertions, 19 deletions) and touches seven files, primarily `transport.c`, `transport-helper.c`, and `builtin/cat-file.c`. Peff also marks the OID array as `const` to emphasize its input-only role.

The patch does not alter behavior or introduce new functionality, but it reduces technical debt and prepares the codebase for future enhancements, such as reusing transport connections for multiple object-info requests. Peff’s patch is signed-off, tested, and uncontroversial; it has been integrated into Pablo’s series with only minor commit message typo fixes. Junio has explicitly endorsed this patch as ready to merge, and all tests are passing. The refactoring is part of the broader effort to add object type metadata to remote-object-info queries, which is now feature-complete and awaiting integration.
