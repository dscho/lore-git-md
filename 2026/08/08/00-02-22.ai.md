This is the seventh patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now at v6, feature-complete, and ready for integration.

This patch teaches the server-side object-info handler to accept "type" as a requested field. When the client includes "type" in its object-info request, the server returns the object type as a string (e.g., `"blob"`). The patch adds a `type` bit field to `struct requested_info` in `protocol-caps.c`, updates the server-side handler to parse the "type" keyword in client requests, and extends `send_info()` to transmit type data alongside the existing size field. Two minor cleanups are included: fixing a bit-field style nit (`size:1` → `size: 1`) and wrapping an over-long line in `send_info()`.

The test suite is expanded in `t/t5701-git-serve.sh` with a new test verifying the server handles requests for both "size" and "type", including duplicate OIDs. The test configures the server to advertise object-info support, sends a request for both fields, and confirms the server responds with the expected format (`<oid> <size> <type>`). The test uses the same helper functions and setup as the rest of the test file, ensuring consistency.

The patch is mechanical and follows the established pattern from the predecessor series. It completes the server-side implementation for object type metadata, enabling the server to parse, transmit, and (in later patches) advertise type data. Junio has explicitly endorsed this patch as ready to merge.
