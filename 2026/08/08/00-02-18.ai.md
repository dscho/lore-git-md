This is a refactoring patch in Pablo Sabater’s GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch is the third of ten in v6, which is now ready for integration after addressing all prior review feedback.

The change removes `struct object_info_args`, which grouped three unrelated pointers (`server_options`, `oids`, and `object_info_options`) that were passed to `fetch_object_info()` and `send_object_info_request()`. The struct was misleading because its members were accessed individually rather than as a unit, and it added no value beyond reducing the parameter count. The patch updates the function signatures to pass these parameters directly, eliminating the wrapper struct while preserving behavior. The commit message has been revised to clarify that `fetch_object_info()` *does* use all three fields, addressing Karthik Nayak’s feedback that the original phrasing was misleading.

The diff is mechanical, touching only `fetch-object-info.c`, `fetch-object-info.h`, and `transport.c`. In `fetch-object-info.c`, the patch replaces all `args->*` accesses with direct parameters and updates the function signatures. In `transport.c`, it constructs the arguments inline rather than initializing a struct. The change is uncontroversial and has been explicitly endorsed by Junio as ready to merge. It prepares the codebase for the subsequent patches that implement object type support, though it introduces no new functionality or protocol changes.
