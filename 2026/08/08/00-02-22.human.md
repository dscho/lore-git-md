This is the seventh patch in Pablo Sabater’s ten-patch GSoC series, now at v6, extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is feature-complete, addresses all prior review feedback, and is explicitly endorsed by Junio as ready to merge.

This patch teaches the server-side object-info handler to accept "type" as a requested field. When the client includes "type" in its object-info request, the server returns the object type as a string (e.g., `"blob"`). The patch adds a `type` bit field to `struct requested_info` in `protocol-caps.c` and updates the server-side handler to parse the "type" keyword in client requests. It also includes two minor cleanups: fixing the bit-field style of `requested_info.size` (`size:1` → `size: 1`) and wrapping an over-long line in `send_info()`.

The test coverage is expanded in `t5701-git-serve.sh` with a new test verifying the server handles requests for both "size" and "type", including duplicate OIDs. The test configures `transfer.advertiseObjectInfo`, sends a request with "size" and "type" keywords and two OIDs, and expects the server to respond with the object size and type for each OID. The patch is mechanical and follows the established pattern from the predecessor series, with no behavior changes beyond enabling the server to transmit type data. Junio has explicitly endorsed this patch as ready to merge.
