This is the ninth patch in Pablo Sabater’s ten-patch GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The series is now at v6, feature-complete, and ready for integration.

The patch appends "type" to the advertised capabilities string in `serve.c`, changing the comment from "Currently only size is supported" to "Currently only size and type are supported". This small but critical change enables the client to discover that the server can provide object type metadata, completing the end-to-end chain for object type support.

The test suite in `t/t1017-cat-file-remote-object-info.sh` is updated to replace the now-obsolete test for unsupported placeholders with two new tests. The first verifies that `%(objecttype)` returns the actual type ("blob") for a known object, confirming the server correctly transmits type data. The second confirms that truly unsupported placeholders (e.g., `%(objectmode)`, `%(objectsize:disk)`) still return empty strings, preserving backward compatibility. The patch also adds type variables (`hello_type`, `tree_type`, `commit_type`, `tag_type`) to the test preamble, mirroring the existing size and OID variables for consistency.

The change is mechanical and uncontroversial, touching only two files and aligning with the established pattern from the predecessor series. Junio has explicitly endorsed this patch as ready to merge, and all prior review feedback has been addressed. The series is now one patch away from unifying the default format for all queries, ensuring consistent output across all transport protocols.
