This is the ninth patch in Pablo Sabater’s ten-patch GSoC series (v6) extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch completes the end-to-end chain by enabling the server to advertise the "type" capability, allowing the client to request and display object type metadata.

The change is minimal and mechanical. In `serve.c`, the patch appends "type" to the advertised capabilities string in `object_info_advertise()`, changing the comment from "Currently only size is supported" to "Currently only size and type are supported". The test suite in `t/t1017-cat-file-remote-object-info.sh` is updated to replace the now-obsolete test for unsupported placeholders with two new tests: one verifying that `%(objecttype)` returns the actual type ("blob") for a known object, and another confirming that truly unsupported placeholders (e.g., `%(objectmode)`, `%(objectsize:disk)`) still return empty strings. The patch also adds type variables (`hello_type`, `tree_type`, `commit_type`, `tag_type`) to the test preamble, mirroring the existing size and OID variables.

This patch is uncontroversial and ready for integration. It touches only two files, follows the established pattern from the predecessor series, and all tests are passing. Junio has explicitly endorsed this patch as ready to merge. The series as a whole is now feature-complete, with all prior review feedback addressed and no open technical concerns.
