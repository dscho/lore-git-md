This is the final patch in Pablo Sabater’s ten-part GSoC series extending `git cat-file --batch-command` to support the `%(objecttype)` placeholder in remote-object-info queries. The patch unifies the default output format for all `cat-file` batch commands, removing the temporary workaround that used a different format for remote queries and ensuring consistent behavior across all transport protocols.

The change is straightforward: the default format is now `%(objectname) %(objecttype) %(objectsize)` for both local and remote queries, replacing the previous remote-specific `%(objectname) %(objectsize)`. The patch updates the documentation to reflect this change, removing the warning about the temporary format and listing `%(objecttype)` as a supported placeholder for `remote-object-info`. The test suite is updated to expect the new format, verifying that mixing `info` and `remote-object-info` commands produces identical output.

This patch touches only four files—`Documentation/git-cat-file.adoc`, `Documentation/gitprotocol-v2.adoc`, `builtin/cat-file.c`, and `t/t1017-cat-file-remote-object-info.sh`—and removes the conditional format logic in `parse_cmd_remote_object_info()`. The change is purely mechanical and uncontroversial, with no behavior changes beyond the format unification. All prior review feedback has been addressed, and Junio has explicitly endorsed this patch as ready to merge. The series is now complete and ready for integration.
