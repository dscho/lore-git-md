This is the latest exchange in the RFC series introducing `git repack --drop-filtered` for partial clones. The author, Siddharth Shrimali (a first-time contributor), responds to Junio C Hamano’s proposal to replace the current safety guards with a time-based heuristic.

Siddharth agrees that recency is a better signal than the existing merge/rebase/cherry-pick checks and index validation, which were framed as optional optimizations rather than correctness measures. He identifies a practical challenge: packed objects lack per-object timestamps, so the only cheap proxy for object age is the mtime of the promisor pack itself. This works well for objects fetched in their own packs (e.g., via lazy fetch), but loses granularity once packs are consolidated by `git repack`. He notes that Git already tracks per-object mtimes for cruft packs (via `.mtimes` files), suggesting this could be extended to promisor objects if the community wants age-based culling to survive repacking.

The response is constructive and pragmatic. Siddharth acknowledges the proposal’s merit, clarifies the technical constraints, and positions the time-based heuristic as a natural extension of the existing "enumerate-then-filter" framework. He does not commit to implementing it in the next revision, but flags it as a promising follow-up criterion. The tone remains collaborative, and the exchange advances the design discussion without derailing the core functionality. No code changes are proposed yet, but the idea is now on the table for the next iteration.
