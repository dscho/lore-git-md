This is a sparse-checkout performance patch. Sahitya Chandra fixes an unnecessary sparse-index expansion in `repo_index_has_changes()` when HEAD is unborn (i.e., on a new branch with no commits).

The bug: when no tree is passed to `repo_index_has_changes()`, the code tries to compare against HEAD. If HEAD doesn’t exist, it falls back to walking the index directly, which forces a full index expansion if the index is sparse. That expansion is wasteful because an unborn HEAD is logically equivalent to the empty tree—every index entry is new.

The fix: when HEAD can’t be resolved, the code now uses the empty tree instead of falling back to the index walk. This keeps the unborn-branch case on the same diff code path as normal tree comparisons, avoiding the expansion while still reporting paths inside sparse directories.

The patch adds a test helper (`test-tool read-cache --index-has-changes`) and a new test in `t1092-sparse-checkout-compatibility.sh` that verifies the unborn-branch case reports paths inside a sparse directory without expanding the index. The commit message is clear and the test coverage looks thorough.

This is a targeted, well-motivated micro-optimization that fits neatly into the ongoing sparse-checkout effort. It should be uncontroversial.
