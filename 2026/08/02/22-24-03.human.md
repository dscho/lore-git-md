This is a brief but substantive design discussion in the ongoing GSoC series that extends `git cat-file --batch-command` to support the `%(objecttype)` placeholder for remote-object-info queries. Junio C Hamano and Jeff King (Peff) are finalizing the storage design for batch results in `fetch-object-info.c`.

The exchange confirms the hybrid approach they converged on earlier: a single array of lightweight structs (`struct { struct oid *oid; enum object_type type; size_t size; }`) where the caller decides which fields to populate, avoiding sentinels entirely. Junio accepts Peff’s point that `OBJ_NONE` can serve as a sentinel for missing object types, but agrees that sentinels are awkward for numeric fields like `size`—there is no natural value that clearly means “not provided.” The discussion leaves open the possibility of using extreme values (e.g., `(size_t)-1`) as sentinels, but neither participant endorses it; the hybrid design remains the preferred path.

This email does not introduce new technical details or touch new files. It simply ratifies the design direction that Pablo Sabater will implement in the next revision of the series. The GSoC deadline is approaching, and this architectural decision clears the way for the final patches.
