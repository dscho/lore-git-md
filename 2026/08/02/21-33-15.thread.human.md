This thread is about a performance optimization for partial clones in Git, specifically targeting the `git index-pack` command. Arijit Banerjee has submitted a patch that addresses a serialization bottleneck in promisor pack handling, which occurs when worker threads parse reconstructed objects to record outgoing links.

The patch replaces the current mutex-protected approach with thread-local data structures, allowing worker threads to parse object buffers directly into local oidmaps. This change preserves all existing validation (malformed headers, conflicting link types, etc.) while significantly improving performance. Benchmarks show a 15% reduction in end-to-end wall-clock time for `--filter=blob:none` clones of `linux.git`, with the `index-pack` phase itself improving by 19%. The patch touches `builtin/index-pack.c` and adds test coverage in `t/t5302-pack-index.sh`.
