This is a follow-up in the GSoC series extending `git cat-file --batch-command` to support `%(objecttype)` in remote-object-info queries. Pablo Sabater responds to Junio C Hamano and Jeff King’s architectural feedback, confirming he now understands the design issue with `struct object_info` and proposing a concrete refactoring plan.

Pablo acknowledges the core problem: the remote-object-info path should not reuse `struct object_info` to store batch query results, since that struct was designed for single-object queries with pointer indirection, not for pre-allocated arrays. He proposes a new lightweight structure, `struct object_info_results`, to hold batch results with boolean flags (`wants_size`, `wants_type`) and arrays for each metadata field. The plan is to refactor `fetch_object_info()` in two patches: first, restructure the existing size-only logic to use the new struct, then add type support. Pablo is unsure whether to include this refactoring in the current series or defer it to a post-GSoC cleanup, noting the GSoC deadline is approaching in a few weeks.

The email does not resolve the timing question—Junio’s earlier comment suggested deferring the cleanup, but Pablo is open to either approach. The proposed `object_info_results` struct is a direct response to the architectural feedback and would replace the current `object_info`-based parsing logic in `fetch-object-info.c`. Key files affected: `fetch-object-info.c` and `builtin/cat-file.c`. No merge status is implied, and the series remains under review.
