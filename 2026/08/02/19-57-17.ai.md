This is a bugfix patch targeting Git's trailer parsing subsystem. Kristoffer Haugsbakk implements the solution previously discussed in the thread to stop Git from incorrectly interpreting URLs as trailers in commit messages. The patch modifies `find_separator()` in `trailer.c` to exclude lines containing `://` from trailer parsing, adds comprehensive test coverage (including unit tests and integration tests), and updates the documentation to explain the new behavior.

The implementation follows Jeff King's proposed approach exactly: it checks for `://` immediately after a colon separator and rejects the line as a trailer if found, unless whitespace has already been encountered (to preserve legitimate trailers that might coincidentally contain `://`). The test cases cover all three problematic scenarios identified in the original bug report: non-trailer URLs getting mangled, line-wrapped URLs creating false trailers, and patch processing introducing bad trailers.
