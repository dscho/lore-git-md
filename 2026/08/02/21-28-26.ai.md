This is a sparse-checkout/sparse-index performance patch. It fixes an unnecessary index expansion in `repo_index_has_changes()` when HEAD is unborn (e.g., on a newly created orphan branch).

The problem: when no tree is passed to `repo_index_has_changes()`, the function tries to compare the index against HEAD. If HEAD doesn’t exist (unborn branch), it falls back to walking the index directly, which forces a full expansion of any sparse directory entries. That expansion is wasteful because an unborn HEAD is logically equivalent to the empty tree—every index entry is new.

The fix: when HEAD resolution fails, the code now uses the empty tree (`repo->hash_algo->empty_tree`) instead of falling back to the index walk. This keeps the unborn-branch case on the same diff code path as normal tree comparisons, avoiding the expansion while still reporting paths inside sparse directories.

The patch adds a test helper (`test-tool read-cache --index-has-changes`) and a new test in `t1092-sparse-checkout-compatibility.sh` that verifies the unborn-branch case reports paths inside a sparse directory without expanding the index. The diff shows a net reduction of 28 lines in `read-cache.c` by consolidating the two code paths.
