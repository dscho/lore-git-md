This is the **v6 feature patch series** for `git bisect`, adding the `--reset-when-found[=<where>]` option. The series is now down to two patches and is essentially complete, addressing all prior feedback including Junio C Hamano’s latest internal clean-up suggestions.

The feature allows `git bisect` to automatically reset the working tree after identifying the first bad commit, either to the original pre-bisect state (`original`, the default) or to the first bad commit itself (`found`). This targets automated workflows (CI, scripts) and interactive debugging by eliminating the need for an explicit `git bisect reset`. The implementation is now simpler and more robust: the auto-reset logic is centralized in `cmd_bisect()`, and the first bad commit OID is read directly from `refs/bisect/bad` before reset, eliminating the need for a file-scope static variable. The redundant boolean flag `reset_when_found_arg_seen` has also been removed in favor of a sentinel value (`RESET_WHEN_FOUND_NONE`).

The series touches `bisect.c`, `builtin/bisect.c`, `Documentation/git-bisect.adoc`, and the test suite (`t/t6030-bisect-porcelain.sh`). The new option is wired into both `git bisect start` and `git bisect run`, and is incompatible with `--no-checkout` (since that mode prevents checking out either target). Test coverage is thorough, validating both reset targets, state cleanup, and edge cases like invalid targets or interrupted bisects. The preparatory patch (1/2) adds a `quiet` parameter to `bisect_reset()` to suppress checkout progress output, preserving existing behavior for other callers.

This version is uncontroversial and appears well-crafted, with clear commit messages, thorough test coverage, and no outstanding technical concerns. Junio’s post-acceptance suggestions have been fully implemented, and the series is ready for integration into `next`. The changes are internal and do not affect the user-facing behavior or CLI beyond the new option. If you use `git bisect` in scripts or CI, this feature is worth paying attention to.
