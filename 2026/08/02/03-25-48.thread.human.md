This thread introduces a new built-in `git interactive` command, proposed by shrimech as a simple terminal-based menu for common Git operations. The initial patch (v1) implements a numbered menu system that invokes existing Git commands like `git status` and `git add` as subprocesses, with basic terminal handling and test coverage. So far, the only feedback comes from Michael Montalbo, who raises two surface-level concerns: the feature’s redundancy with existing tools like `git-gui` and `gitk`, and a mechanical issue where the diffstat mistakenly includes a build artifact (`git-interactive`).

The patch is still in its early review phase, with no maintainer decisions or technical critiques yet. The current implementation lacks state persistence, tab completion, or integration with Git’s existing interactive modes (e.g., `git add -p`), and the commit message doesn’t address how this tool differs from or complements other interactive interfaces. The subprocess-based design—calling Git commands externally rather than reusing internal APIs—also hasn’t been discussed. For now, the thread’s direction hinges on whether the author can justify the feature’s necessity and address the build artifact issue.
