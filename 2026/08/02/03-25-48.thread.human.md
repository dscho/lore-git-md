This thread is about a proposed new built-in command, `git interactive`, which would provide a terminal-based menu for common Git operations like status, add, and log. The author, shrimech, posted the initial version (v1) of the patch, framing it as a simple interactive entry point for Git workflows. Michael Montalbo has been the primary respondent so far, questioning the necessity of the feature given existing tools like `git-gui`, `gitk`, and third-party frontends, and arguing that an interactive mode under `git add` would be a more natural fit. The discussion has so far focused on the feature’s conceptual justification rather than its implementation details.

The patch itself adds a new built-in command (`git interactive`) implemented in `builtin/interactive.c`, using ANSI colors and terminal detection to present a numbered menu. It invokes existing Git commands as subprocesses rather than reusing internal APIs, and includes a test script (`t/t0013-interactive.sh`) for basic menu navigation and file staging. However, the implementation lacks state persistence, tab completion, and integration with Git’s existing interactive modes (e.g., `git add -p`). The patch also mistakenly included a compiled binary (`git-interactive`) in the diffstat, a mechanical issue noted by Michael Montalbo and later confirmed by Kristoffer Haugsbakk in follow-ups to v2 and v3 (though only v1 was previously summarized).

The thread remains in the review phase, with no clear resolution on the feature’s necessity or design direction. The author has not yet addressed Michael’s broader skepticism about the command’s overlap with existing tools, and the discussion has not progressed beyond surface-level mechanical feedback. The next steps will likely depend on whether the author revises the patch to address the binary inclusion issue and provides a stronger rationale for the feature’s standalone design.
