This thread is an RFC proposal from Zhonghua Zhu exploring whether Git's remote helper mechanism can be adapted to better handle monorepos, inspired by Perforce's workflow. The author presents **blackgit**, a proof-of-concept external tool that wraps Git's remote helper interface to optimize operations in large repositories by fetching only relevant portions of the codebase. The proposal is conceptual—no patches or detailed technical design are included—and relies entirely on Git's existing plugin architecture, avoiding changes to the core codebase.

The idea leverages Git's sparse-checkout and partial-clone features but aims to provide a more Perforce-like experience (e.g., "sync only what you need"). The prototype (`git-remote-blackgit`) intercepts fetch/push operations, though the email doesn’t clarify how it differs from or improves upon Git’s built-in sparse-index or Microsoft’s GVFS/VFS for Git. The tone is exploratory, framing the discussion as "is this possible?" rather than advocating for a specific solution.

Key open questions include whether this functionality should live in Git core or remain an external tool, and whether it duplicates existing efforts like Scalar or sparse-index. The thread is early-stage, with no reviews or maintainer feedback yet, and no engagement with prior work in this space. If discussion progresses, expect debates about scope, performance trade-offs, and whether the remote helper interface is the right abstraction for this use case.
