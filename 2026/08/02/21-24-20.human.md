This is the **final patch (2/2) in the v6 series** adding the `--reset-when-found[=<where>]` option to `git bisect`. The feature is now complete, well-tested, and ready for integration.

The patch implements the core functionality: after `git bisect` identifies the first bad commit, it automatically resets the working tree to either the pre-bisect commit (`original`, the default) or the first bad commit (`found`). The option is available in both `git bisect start` and `git bisect run`, and the target is persisted in a new state file (`BISECT_RESET_WHEN_FOUND`). The reset is performed quietly, and the implementation handles edge cases like platform-specific file-locking constraints (e.g., deferring reset until after `BISECT_RUN` is closed).

The code is clean and follows Git’s conventions. The preparatory refactoring (patch 1/2) added a `quiet` parameter to `bisect_reset()` to suppress checkout progress output, and this patch centralizes the auto-reset logic in `cmd_bisect()`. The implementation avoids static variables by reading `refs/bisect/bad` directly before reset, and uses a sentinel value (`RESET_WHEN_FOUND_NONE`) to track the reset mode. The documentation and tests are thorough, covering both reset targets, state cleanup, and edge cases (invalid targets, `--no-checkout` conflicts, and interrupted bisects).
