This is the **v5 feature patch (2/2)** for `git bisect`, implementing the `--reset-when-found[=<where>]` option. The patch is the core of the series, adding the user-facing functionality and internal plumbing to automatically reset the working tree after the first bad commit is identified.

The patch wires the new option into both `git bisect start` and `git bisect run`, allowing users to specify `--reset-when-found[=<where>]` (with `<where>` being `original` or `found`). The default is `original`, which resets to the pre-bisect commit. The implementation persists the chosen target in a `BISECT_RESET_WHEN_FOUND` state file and centralizes the auto-reset logic in `cmd_bisect()`, which performs the reset after the subcommand returns. For `git bisect run`, this ensures the `BISECT_RUN` file is closed before cleanup, addressing platform-compatibility concerns about unlinking open files. The patch also enforces the constraint that `--reset-when-found` cannot be used with `--no-checkout`, as that mode prevents checking out either target.

Key technical details include the introduction of a file-scope static variable (`first_bad_oid`) to propagate the first bad commit OID from `bisect_next_all()` to `cmd_bisect()`, and the addition of a `quiet` parameter to `bisect_reset()` (introduced in patch 1/2) to suppress progress output during the auto-reset. The patch touches `bisect.c`, `builtin/bisect.c`, `bisect.h`, `Documentation/git-bisect.adoc`, and the test suite, adding four new tests in `t/t6030-bisect-porcelain.sh` to validate auto-reset behavior, state cleanup, and edge cases (invalid targets, `--no-checkout` conflicts, and interrupted bisects). The tests fix shell safety issues by assigning `git rev-parse` output to variables before passing them to `test_path_is_file`/`test_path_is_missing`.

The patch is well-crafted, with thorough test coverage and a clear commit message. It fully implements Junio’s refactoring proposal from earlier in the thread, eliminating the `defer_reset` parameter and decoupling `bisect_clean_state()` from `bisect_reset()`.
