Subject: [PATCH] index-pack: speed up promisor pack link recording
Series version: single patch (no cover letter)
Originating author: Arijit Banerjee (via GitGitGadget)
Thread type: performance patch for partial clones

Core problem or goal
Eliminate the serialization bottleneck in `git index-pack` when handling promisor packs by avoiding the per-object mutex that currently protects the shared object model during link recording. The goal is a 15–20 % wall-clock speed-up for `--filter=blob:none` clones without affecting full clones or relaxing any validation.

Current status
Under review; no prior versions posted. Patch touches `builtin/index-pack.c` and `t/t5320-pack-objects-hash.sh` (correcting the filename from the summary: t5302-pack-index.sh → t5320). New symbols: `struct outgoing_link`, thread-local oidmaps, `record_outgoing_links_from_data()`, and helper functions for parsing and merging link data.

Key technical details
- Files: `builtin/index-pack.c`, `t/t5320-pack-objects-hash.sh`
- Subsystem: promisor pack handling, object parsing
- Behavior change: normal promisor indexing now uses thread-local typed oidmaps instead of parsing objects into the shared object model under a mutex; strict and fsck code paths remain unchanged
- On-disk format: none
- Test coverage: new tests for malformed commit headers, conflicting link types, mismatched tag target types; passes existing SHA-1 and SHA-256 tests
- Performance: 15 % end-to-end reduction (156 s → 133 s) for `--filter=blob:none` linux.git clones, 19 % improvement in index-pack phase (121 s → 98 s), 46 % drop in system CPU time
