Subject: [PATCH] index-pack: speed up promisor pack link recording
Series version: single patch, RFC
Originating author: Arijit Banerjee (via GitGitGadget)
Thread type: performance patch for partial clones, now framed as RFC due to policy concern regarding AI-assisted contributions

Core problem or goal
Eliminate the serialization bottleneck in `git index-pack` when handling promisor packs by avoiding the per-object mutex that currently protects the shared object model during link recording. The goal is a 15–20% wall-clock speed-up for `--filter=blob:none` clones without affecting full clones or relaxing any validation. The patch is presented as an RFC to solicit maintainer guidance on whether the performance benefit justifies an exception to the project's cautious stance on AI-assisted contributions for non-trivial code.

Current status
RFC; no prior versions posted. Patch touches `builtin/index-pack.c` and `t/t5320-pack-objects-hash.sh`. New symbols: `struct outgoing_link`, thread-local oidmaps, `record_outgoing_links_from_data()`, and helper functions for parsing and merging link data. The technical implementation remains unchanged from the initial submission; only the framing has shifted to address the procedural objection. The project's stance on AI-assisted contributions is now clarified as cautious and case-by-case, with heightened scrutiny and no outright ban, but enforcement of human review expectations remains uncertain. Junio C Hamano has suggested looking to LLVM's policy on extractive contributions (rejecting those that merely extract or rephrase existing material without substantive original work) as a potential model for Git, tying this to the project's limited review bandwidth. No maintainer has yet weighed whether the performance benefit warrants an exception, and the thread remains stalled on the procedural question. The author has since floated speculative governance ideas (karma system, experimental release train) in response to Junio's policy exploration, but these are not formal proposals and have not advanced the discussion toward resolution.

Key technical details
- Files: `builtin/index-pack.c`, `t/t5320-pack-objects-hash.sh`
- Subsystem: promisor pack handling, object parsing
- Behavior change: normal promisor indexing now uses thread-local typed oidmaps instead of parsing objects into the shared object model under a mutex; strict and fsck code paths remain unchanged
- On-disk format: none
- Test coverage: new tests for malformed commit headers, conflicting link types, mismatched tag target types; passes existing SHA-1 and SHA-256 tests
- Performance: 15–26% end-to-end reduction (156 s → 133 s) for `--filter=blob:none` linux.git clones, 19% improvement in index-pack phase (121 s → 98 s), 46% drop in system CPU time
