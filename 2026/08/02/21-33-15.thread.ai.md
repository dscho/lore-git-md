Core problem or goal
Eliminate the serialization bottleneck in `git index-pack` when handling promisor packs by avoiding the per-object mutex that currently protects the shared object model during link recording. The goal is a 15–20% wall-clock speed-up for `--filter=blob:none` clones without affecting full clones or relaxing any validation. The patch was repositioned as an RFC to solicit maintainer guidance on whether the performance benefit justifies an exception to the project's cautious stance on AI-assisted contributions for non-trivial code.

Current status

The thread is now entirely stalled on policy: brian m. carlson’s latest reply explicitly rules out acceptance of nontrivial LLM-generated patches in the foreseeable future, citing legal, reputational, ethical, and environmental risks. Key technical details
- Files: `builtin/index-pack.c`, `t/t5320-pack-objects-hash.sh`
- Subsystem: promisor pack handling, object parsing
- Behavior change: promisor indexing now uses thread-local typed oidmaps instead of parsing objects into the shared object model under a mutex; strict and fsck code paths remain unchanged
- On-disk format: none
- Test coverage: new tests for malformed commit headers, conflicting link types, mismatched tag target types; passes existing SHA-1 and SHA-256 tests
- Performance: 15–26% end-to-end reduction (156 s → 133 s) for `--filter=blob:none` linux.git clones, 19% improvement in index-pack phase (121 s → 98 s), 46% drop in system CPU time
