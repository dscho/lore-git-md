This thread is about a performance fix for Git's sparse-checkout and sparse-index features. Sahitya Chandra identified an unnecessary index expansion in `repo_index_has_changes()` when working with an unborn branch (like a newly created orphan branch). The current code falls back to walking the index directly when HEAD doesn't exist, which forces a full expansion of sparse directory entries—even though an unborn HEAD is logically equivalent to an empty tree.

The patch replaces this fallback with a comparison against Git's empty tree object, keeping the unborn-branch case on the same efficient diff code path used for normal tree comparisons. This avoids the wasteful expansion while correctly reporting paths inside sparse directories. The change includes a new test helper (`test-tool read-cache --index-has-changes`) and a test in `t1092-sparse-checkout-compatibility.sh` to verify the fix works as intended. The implementation actually simplifies the code, reducing `read-cache.c` by 28 lines by consolidating the two code paths.

This is a targeted improvement for users working with sparse checkouts, particularly in scenarios involving new branches or orphaned worktrees. No objections or review feedback have been posted yet, so the patch is still in its initial review phase.
