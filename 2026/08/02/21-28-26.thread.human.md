This thread is about a small but targeted performance fix in Git’s sparse-index handling. Sahitya Chandra’s patch prevents an unnecessary index expansion when `repo_index_has_changes()` is called on an unborn HEAD (for example, on a newly created orphan branch). Instead of walking the index directly—which forces a full expansion of any sparse directory entries—the patch compares the index against the empty tree, keeping the unborn-branch case on the same diff code path as normal tree comparisons.

The patch itself is under review and hasn’t seen a prior version. Elijah Newren raised two main concerns: first, whether the change addresses a real-world use case or merely cleans up a TODO, and second, a bug in the test helper’s output format that would be ambiguous if multiple files are dirty. Sahitya has acknowledged both points. He concedes that he doesn’t have a concrete scenario where a user with an unborn HEAD would also have millions of uncommitted files in a sparse index, but argues that the patch still improves code clarity and removes a footgun for future readers. The test-helper issue will be fixed in a v2 iteration, but the core logic remains unchanged. The thread is still open, waiting for that revised patch.
