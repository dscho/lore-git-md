This thread is about a performance fix for Git's sparse-index feature. Sahitya Chandra's patch prevents unnecessary index expansion when checking for changes on an unborn HEAD (like a newly created orphan branch) by comparing against the empty tree instead of walking the index directly. The change is small—28 lines removed from `read-cache.c`—and includes a new test case in `t1092-sparse-checkout-compatibility.sh`.

Elijah Newren, the sparse-index expert, has raised two key concerns in his review. First, he questions whether this patch addresses a real-world problem: he can't think of a scenario where a user with an unborn HEAD would also have a sparse index with millions of uncommitted files. Second, he spotted a bug in the test helper (`test-tool read-cache --index-has-changes`), which assumes only one dirty file and could misreport output if multiple paths are dirty. The patch is still under review, and no updated version has been posted yet. If you're following sparse-index performance work, this is one to watch—Elijah's feedback suggests the fix might need either stronger justification or a rethink.
