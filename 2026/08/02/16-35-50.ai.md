This is a brief architectural review exchange in the ongoing GSoC series extending `git cat-file --batch-command` to support `%(objecttype)` in remote-object-info queries. Junio C Hamano responds to Jeff King’s (Peff) endorsement of Pablo Sabater’s plan to bypass `struct object_info` entirely and use a purpose-built `object_info_results` structure for batch queries.

Junio agrees with the decision to avoid `struct object_info` but suggests an alternative design: instead of Pablo’s proposed `struct object_info_results` (a struct of arrays with boolean flags like `wants_size` and `wants_type`), he prefers an **array of simple structs** (e.g., `struct { struct oid *oid; enum object_type type; size_t size; }`). This design would use `OBJ_NONE` or `NULL` values to signal missing data, avoiding the need for boolean flags and aligning more closely with the pointer indirection pattern used in `sha1_object_info_extended()`. Junio also requests a distinct name for the new structure to avoid confusion with the existing `object_info`.

The exchange introduces a clear architectural choice for the series: Pablo’s `object_info_results` with explicit flags and separate arrays, or Junio’s simpler array-of-structs approach. The decision will shape the refactoring in `fetch-object-info.c` and `builtin/cat-file.c`, where the current `object_info`-based parsing logic will be replaced. No objections to the series’ core functionality are raised, and the discussion remains focused on implementation details. The series is still under review, with no merge status implied.
