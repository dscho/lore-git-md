This is the **v6 feature patch series** for `git bisect`, adding the `--reset-when-found[=<where>]` option. The series is now down to two patches and implements Junio C Hamano’s final internal clean-up suggestions: (1) reading `refs/bisect/bad` directly before reset to eliminate the file-scope static variable `first_bad_oid`, and (2) using a sentinel value (`RESET_WHEN_FOUND_NONE`) for `reset_when_found` to remove the separate boolean flag `reset_when_found_arg_seen`.

The user-facing behavior is unchanged: after `git bisect` identifies the first bad commit, the working tree is automatically reset to either the pre-bisect commit (`original`, the default) or the first bad commit (`found`). The option is wired into both `git bisect start` and `git bisect run`, and remains incompatible with `--no-checkout`. The preparatory patch (1/2) adds a `quiet` parameter to `bisect_reset()` to suppress checkout progress output during auto-reset.

The series touches `bisect.c`, `builtin/bisect.c`, `Documentation/git-bisect.adoc`, and the test suite (`t/t6030-bisect-porcelain.sh`). Test coverage remains thorough, validating both reset targets, state cleanup, and edge cases. The changes are confined to the bisect subsystem and introduce no new dependencies or on-disk format changes.

This version addresses all prior feedback, including Junio’s post-acceptance suggestions, and is ready for integration into `next`. The implementation is clean, well-motivated, and uncontroversial, with no outstanding technical concerns. The commit history is clear, and the documentation and tests are complete.
