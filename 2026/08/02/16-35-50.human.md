This is a brief architectural discussion in the ongoing GSoC series to extend `git cat-file --batch-command` with `%(objecttype)` support for remote-object-info queries. Junio C Hamano responds to Jeff King’s endorsement of Pablo Sabater’s plan to bypass `struct object_info` entirely and use a new `object_info_results` structure for batch queries.

Junio agrees the refactoring should proceed and does not object to the core idea, but he suggests an alternative design: instead of Pablo’s proposed `struct object_info_results` (which uses boolean flags and separate arrays for each metadata field), he prefers an **array of simple structs**—for example, `struct { struct oid *oid; enum object_type type; size_t size; }`. In this design, missing data would be signaled by sentinel values like `OBJ_NONE` or `NULL`, avoiding the need for explicit `wants_*` flags. Junio believes this approach would be cleaner and more aligned with the pointer indirection pattern already used in `sha1_object_info_extended()`. He also requests the new structure be named differently from `object_info` to avoid confusion.

The exchange leaves the architectural decision open: Pablo’s `object_info_results` with boolean flags and separate arrays versus Junio’s array of simple structs. The choice will determine how the refactoring is implemented in `fetch-object-info.c` and `builtin/cat-file.c`. No objections to the series’ core functionality are raised, and the discussion remains focused on design clarity and maintainability. The series is still under review, with no merge status implied.
