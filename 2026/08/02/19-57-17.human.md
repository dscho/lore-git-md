This is a well-crafted bugfix patch targeting Git's trailer parsing logic. Kristoffer Haugsbakk implements the solution previously discussed in the thread: preventing URLs from being misinterpreted as trailers by modifying `find_separator()` in `trailer.c`. The patch addresses all three real-world cases identified in the Linux kernel history where URLs were incorrectly parsed as trailers, causing mangled output in commands like `git log --format='%(trailers:only)'`.

The implementation is clean and conservative. It adds a simple check in `find_separator()` to reject lines containing `://` as potential trailers, but only when no whitespace has been encountered yet (to avoid false positives with intentional trailers like `https: //example.com`). This matches Jeff King's earlier suggestion while adding sensible edge-case handling. The patch includes thorough test coverage in both the shell test suite (`t7513-interpret-trailers.sh`) and new unit tests (`t/unit-tests/u-trailer.c`), verifying that URLs are ignored while similar-looking but intentional trailers are still parsed correctly.

Documentation is updated in `git-interpret-trailers.adoc` to explicitly mention the URL exclusion behavior, which will help users understand why certain lines are no longer treated as trailers. The commit message provides excellent context, showing concrete examples from the Linux kernel where this bug manifested and explaining how the patch resolves them. This is clearly a real-world problem that affects users who include URLs in commit messages, and the solution appears to handle all the edge cases discussed in the thread.
