This is a substantive review exchange in the ongoing GSoC series to extend `git cat-file --batch-command` with `%(objecttype)` support for remote-object-info queries. Jeff King (Peff) responds to Pablo Sabater’s proposed refactoring plan, endorsing the direction and offering detailed guidance on implementation details.

Peff agrees that the remote-object-info path should bypass `struct object_info` entirely and use a new lightweight structure (`struct object_info_results`) to hold batch results. He clarifies the design intent: the new struct should use boolean flags (`wants_size`, `wants_type`) to declare what metadata the client requests, and the low-level code should allocate arrays for the results, leaving them NULL if the server does not support a requested field. This approach mirrors the pointer-indirection pattern of `object_info` but avoids its inefficiency for batch queries. Peff also suggests pushing the string-ification of requested fields (e.g., "size", "type") down into `send_object_info_request()`, so the rest of the code can consistently use the boolean flags to check what was requested.

The review identifies two pain points in the current code: (1) the protocol’s arbitrary ordering of returned fields (e.g., "type size" vs. "size type") forces the client to map responses onto pre-allocated arrays, and (2) the transport struct is overloaded with data that is only used for a single function call. Peff’s feedback is actionable and aligns with Junio’s earlier architectural recommendation. He explicitly endorses Pablo’s plan to split the refactoring into two patches—first restructuring the existing size-only logic, then adding type support—and encourages including it in the current series rather than deferring it to a post-GSoC cleanup.

The exchange does not resolve the timing question definitively, but Peff’s tone ("I think you should proceed") leans toward addressing the refactoring now. The series remains under review, with no merge status implied. Key files affected: `fetch-object-info.c` and `builtin/cat-file.c`. The proposed `object_info_results` struct and boolean flags are likely to become the new idiom for remote-object-info queries.
