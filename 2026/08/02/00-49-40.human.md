This is a surface-level review comment on the performance tweak in patch 3/4 of Junio’s `git add --resolved` series. Michael Montalbo points out a potential edge case in the newly added `buffer_is_binary()` check: if the first line of a binary file happens to match the pattern for a conflict marker (e.g., starts with `<<<<<<< `), the current placement of the check would incorrectly set `has_markers = 1` before realizing the file is binary. The fix is trivial—move the binary check *before* the conflict-marker check in the loop—but the observation is sharp and worth addressing before the series lands.

The rest of the series remains uncontroversial and technically solid. This is a minor nit in an otherwise clean patch; no deeper design questions or behavioral changes are raised. If Junio incorporates the suggestion, the series will be one step closer to readiness for `next`.
