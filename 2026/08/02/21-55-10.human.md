This is a brief follow-up in the ongoing RFC thread about restricting Git 3.0 to lowercase-only hex object IDs. Brian m. carlson acknowledges Jeff King’s observation that uppercase hex within commit and tag objects creates parallel histories, agreeing that this is problematic and worsens Git’s existing issue with multiple object representations. He adds a new technical point: such objects cannot be properly handled by Git’s interoperability layer, which only emits lowercase object IDs, effectively making them SHA-1-only and incompatible with SHA-256 repositories. This reinforces the argument for enforcing lowercase consistency, but the thread remains focused on design philosophy and the scope of the proposed breaking change, with no resolution yet.
