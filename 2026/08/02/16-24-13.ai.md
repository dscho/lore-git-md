This is a substantive review reply in the GSoC patch series extending `git cat-file --batch-command` to support `%(objecttype)` in remote-object-info queries. Junio C Hamano responds to Pablo Sabater’s proposed refactoring plan for `fetch_object_info()`, clarifying the intended design pattern for batch queries.

Junio endorses the core idea of bypassing `struct object_info` for batch results but suggests a different data structure: an array of simple structs (`struct { struct oid *oid; enum object_type type; size_t size; }`) instead of Pablo’s `object_info_results` with separate arrays and boolean flags. Junio’s design avoids the need for `wants_*` flags by using a single struct per object, with `OBJ_NONE` or `NULL` values signaling missing data. He outlines how the existing `sha1_object_info_extended()` interface can still be used to populate this array, preserving the pointer indirection pattern (`type_p = &result[it].type`) while avoiding the inefficiency of an array of `object_info` structs.

The reply is advisory and does not block the series, but it provides a concrete, actionable alternative to Pablo’s proposal. The suggested design would simplify the code by eliminating the need for separate arrays and flags, and it aligns with the historical use of `struct object_info` as a parameter container rather than a storage struct. Key files affected remain `fetch-object-info.c` and `builtin/cat-file.c`. No merge status is implied, and the series remains under review.
