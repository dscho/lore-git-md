This is the **final patch (2/2) of the v6 `--reset-when-found` feature series** for `git bisect`. The patch implements the core user-facing functionality: a `--reset-when-found[=<where>]` option that automatically resets the bisect state after identifying the first bad commit, eliminating the need for an explicit `git bisect reset`.

The patch wires the option into both `git bisect start` and `git bisect run`, with `<where>` accepting `original` (reset to the pre-bisect commit, the default) or `found` (leave the first bad commit checked out). The implementation centralizes the auto-reset logic in `cmd_bisect()`, which reads `refs/bisect/bad` directly before reset to avoid relying on the file-scope static variable `first_bad_oid`. The `reset_when_found` variable is initialized to `RESET_WHEN_FOUND_NONE` to remove the separate boolean flag `reset_when_found_arg_seen`, addressing Junio’s final internal clean-up suggestions.

Key changes include:
- New CLI option `--reset-when-found[=<where>]` (parameterized; incompatible with `--no-checkout`).
- Internal plumbing: `bisect_reset()` gains a `quiet` parameter (added in patch 1/2) to suppress checkout progress during auto-reset, and the new `BISECT_RESET_WHEN_FOUND` state file persists the reset target.
- Test coverage: four new tests in `t/t6030-bisect-porcelain.sh` validate both reset targets (`original`/`found`), state cleanup, and edge cases (invalid targets, `--no-checkout` conflicts, interrupted bisects). Shell safety issues in test helpers are fixed by assigning `git rev-parse` output to variables before passing them to `test_path_is_file`/`test_path_is_missing`.

The patch touches `bisect.c`, `builtin/bisect.c`, `Documentation/git-bisect.adoc`, and the test suite. The implementation is clean, well-tested, and uncontroversial, with no outstanding feedback or technical concerns. The series is ready for integration into `next`.
