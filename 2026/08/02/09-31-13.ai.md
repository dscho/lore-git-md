This is the **v5 feature patch series** for `git bisect`, implementing the `--reset-when-found[=<where>]` option. The series is now down to two patches and incorporates Junio C Hamano’s proposed refactoring to simplify the internal state machine.

The core change moves the auto-reset logic from the individual subcommands (`bisect_next`, `bisect_state`, etc.) into the top-level `cmd_bisect()` function. This eliminates the `defer_reset` plumbing parameter and decouples `bisect_clean_state()` from `bisect_reset()`. The first bad commit OID is now propagated from `bisect_next_all()` via a file-scope static variable (`first_bad_oid`), and the reset is performed after the subcommand returns. For `git bisect run`, this ensures `BISECT_RUN` is closed before cleanup, addressing platform-compatibility concerns about unlinking open files. The `bisect_reset()` function now returns early after checkout, leaving state cleanup to the caller.

The series retains all prior functionality: `--reset-when-found[=<where>]` (with values `original` or `found`) automatically resets the working tree after the first bad commit is identified, and the option remains incompatible with `--no-checkout`. Test coverage is unchanged, validating both reset targets, state cleanup, and edge cases. The refactoring is purely internal and does not affect the user-facing behavior or CLI.

This version addresses all prior feedback, including Junio’s refactoring proposal, and is ready for integration into `next`. The changes are confined to `bisect.c`, `builtin/bisect.c`, `bisect.h`, and the test suite. No new symbols or on-disk format changes are introduced. The series is uncontroversial and appears well-crafted, with thorough test coverage and a clear commit history.
