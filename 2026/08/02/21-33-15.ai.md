This is a performance patch targeting the promisor pack handling in `git index-pack`. It speeds up partial clones by avoiding the serialization bottleneck that occurs when worker threads parse reconstructed objects to record outgoing links.

The patch replaces the current approach—where every non-blob object is parsed into the shared object model under a mutex—with direct parsing of object buffers in worker-local data structures. The strict and fsck code paths remain unchanged, but normal promisor indexing now uses thread-local typed oidmaps to record links, merging them after workers exit. The implementation preserves all existing validation: malformed commit/tag headers, conflicting link types, and mismatched target types are still rejected, and commit-graft handling remains intact.

Benchmarking shows a 15% reduction in end-to-end wall-clock time for `--filter=blob:none` clones of linux.git (from 156s to 133s), with the index-pack phase itself improving by 19% (121s to 98s). System CPU time dropped by 46%. Full clones are unaffected, as expected. The patch adds new test coverage for malformed commit headers, conflicting link types, and mismatched tag target types, and passes existing tests under both SHA-1 and SHA-256.

The change touches `builtin/index-pack.c` and `t/t5302-pack-index.sh`, introducing a new `outgoing_link` struct, thread-local oidmaps, and helper functions to parse and merge link data. The core logic is in `record_outgoing_links_from_data()`, which extracts links directly from object buffers without materializing objects in the shared object store. The patch is well-motivated, thoroughly tested, and includes detailed performance measurements. It looks ready for serious review.
