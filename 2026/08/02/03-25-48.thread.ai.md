Subject: [PATCH] builtin: add `git interactive` command
Series version: v3 (v1 initially submitted; v2 and v3 posted subsequently)
Originating author: shrimech
Thread type: feature patch

Core problem or goal
Introduce a new built-in `git interactive` command that provides a terminal-based menu system for common Git operations (status, add, log, branch listing, help, quit). The goal is to offer a simple interactive entry point for working-tree and history operations, distinct from existing tools like `git add -i` or third-party Git assistants.

Current status
Under review; v3 posted. The series remains conceptually contested, with Michael Montalbo continuing to question the necessity of the feature given existing tools (`git-gui`, `gitk`, third-party frontends) and the lack of a clear rationale for a standalone command versus an interactive mode under `git add`. No evidence of maintainer interest or integration status (still under review).

Key technical details
- New built-in command: `git interactive` (registered as `ancillaryinterrogators` in `command-list.txt`).
- Implementation: `builtin/interactive.c`, using ANSI color codes, `isatty()` for terminal detection, and `strbuf_getline()` for input.
- Subprocess invocation: uses `run_command()` to call existing Git commands (`git status`, `git add`, etc.).
- Test coverage: `t/t0013-interactive.sh` (menu navigation, file staging).
- Files touched: `builtin/interactive.c`, `builtin.h`, `Makefile`, `command-list.txt`, `t/t0013-interactive.sh`.
- New symbols: `cmd_interactive()` (entry point), no new config keys or CLI options.
- Behavior: presents a numbered menu; no state persistence, tab completion, or integration with existing interactive modes (e.g., `git add -p`).
- On-disk format: no changes.
- Build artifact: `git-interactive` binary mistakenly included in diffstat (persists in v2 and v3; noted by Michael Montalbo and Kristoffer Haugsbakk).

Open questions and loose ends
- No comparison with existing tools (`git add -i`, `git citool`, third-party assistants) in commit message or implementation rationale.
- Limited scope: lacks state persistence, tab completion, and integration with Git’s existing interactive modes.
- Subprocess-based design: invokes Git commands externally rather than reusing internal APIs.
- Test script name (`t0013-interactive.sh`) suggests awareness of test suite conventions, but no discussion of test coverage gaps.
- No prior art or related efforts mentioned.
- Michael Montalbo’s repeated skepticism about the feature’s necessity remains unresolved; the author has not yet addressed the overlap with `git-gui`/`gitk` or third-party frontends.
- Persistent mechanical issue: inclusion of compiled binary `git-interactive` in diffstat (noted in v1, v2, and v3).
