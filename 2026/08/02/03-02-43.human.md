The patches make two CGI helper scripts in `t/lib-httpd/` concurrency-safe by replacing non-atomic shell operations (`test -f` followed by `rm` or `touch`) with atomic ones (`mv` for one-shot markers, `mkdir` for first-request election). The motivation is a real, observed flake in `t5616.47` on macOS CI runners, where concurrent HTTP requests to the same endpoint caused HTTP 500 errors due to the race condition. The v2 updates clarified the commit messages and code comments to explicitly state the rationale for the atomic operations, including the `"permanent"` case in `http-429.sh` and the distinction between shrinking the race window and preventing concurrent script execution in `apply-one-time-script.sh`.

The fixes are minimal, targeted, and unlikely to be controversial, as they address a concrete problem without changing user-visible behavior.
