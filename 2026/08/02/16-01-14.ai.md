This is Junio C Hamano’s **post-acceptance feedback** on the v5 `--reset-when-found` series for `git bisect`. The series is already marked for integration into `next`, but Junio now questions two internal implementation details that could further simplify the patch.

The first point targets the new file-scope static variable `first_bad_oid`. Junio suggests that instead of propagating the first bad commit OID from `bisect_next_all()` back to `cmd_bisect()`, the code could simply read `refs/bisect/bad` just before performing the reset. This would eliminate the need for the static variable and the plumbing that carries it, shrinking the patch series.

The second point concerns the dual variables `reset_when_found` and `reset_when_found_arg_seen`. Junio proposes initializing `reset_when_found` to a sentinel value (e.g., `NULL`) that no command-line argument or state file could ever set, thereby removing the need for the separate boolean flag. This would further reduce internal state complexity.

Neither suggestion affects the user-facing behavior or the series’ readiness for `next`; both are purely internal clean-ups. The author can choose to address them in a follow-up patch or leave them as-is, since the current implementation is already considered correct and complete.
