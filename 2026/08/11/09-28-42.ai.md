This is the v8 iteration of a performance optimization series for Git’s commit-reach subsystem, specifically targeting `paint_down_to_common()`. The series is now **technically complete, fully reviewed, and queued in Junio’s tree**, with only editorial refinements remaining before advancement beyond its current state.

The core optimization terminates the merge-base walk early when one side of the history is exhausted, eliminating unnecessary traversal of large one-sided histories (e.g., repositories with import grafts or shallow histories). This yields **100-1000x speedups** for asymmetric queries, such as `merge-base --all` across an import boundary in a 2.6M-commit monorepo (steps reduced from 2.1M to 3). The series also removes the long-standing commit-date ordering fallback, replacing it with a topological ceiling for v1 commit-graphs to ensure correctness.

Key changes since v7:
- **Terminology alignment**: Replaced "finite/INFINITY region" with "ordered/unordered region" throughout the documentation and code to better reflect the semantic boundary between regions where topological ordering holds and where it does not. The documentation now explicitly notes that v1 commit-graphs use `GENERATION_NUMBER_V1_MAX` as the topological ceiling, while v2 graphs use `GENERATION_NUMBER_INFINITY`.
- **Code clarity**: Added a comment to `paint_queue_get()` explaining why termination conditions must be checked before decrementing counters, addressing a critical ordering requirement raised in review.
- **Mechanical cleanup**: Moved the `topo_ceiling` field into patch 8 (where it is first needed) to ensure v1 commit-graph saturation is handled correctly at every commit in the series.
- **Test improvements**: Adopted Elijah Newren’s suggested fixed-width ASCII graph in `t6099-merge-base-side-exhaustion.sh` for clarity, and minor wording fixes in commit messages and test comments.

The series is structured as follows:
1. **Documentation**: A new technical document (`paint-down-to-common.adoc`) explains the algorithm, generation-number regions, termination conditions, and clock-skew invariants. The document is now aligned with the "ordered/unordered" terminology and clarifies how v1 commit-graphs fit into the region model.
2. **Test infrastructure**: A new `test_trace2_data_singular()` helper in `test-lib-functions.sh` improves diagnostic output for Trace2 data assertions, replacing brittle `grep`-based checks with detailed mismatch reporting.
3. **Edge-case tests**: New test cases in `t6600-test-reach.sh` cover self/duplicate/pending-stale/infinity-both-sides scenarios, while `t6099-merge-base-side-exhaustion.sh` adds regression tests for the side-exhaustion optimization (e.g., redundant merge-base candidates).
4. **Clock-skew hardening**: Tests for `se-*` and `se2-*` topologies validate generation-ordering invariants in clock-skew scenarios, ensuring the optimization does not fire prematurely.
5. **Trace2 instrumentation**: A `steps` counter in `paint_down_to_common()` reports the number of commits visited via `trace2_data_intmax()`, enabling deterministic performance measurement. Test expectations are updated to reflect reduced step counts across all commit-graph modes (none/full/half/no-gdat).
6. **Refactoring**: Introduces a `paint_state` struct with per-side counters (`parent1_count`, `parent2_count`, `mb_candidate_count`) to replace the old `max_nonstale` pointer-based logic. The change is non-behavioral but improves code clarity and maintainability.
7. **Core optimization**: Implements early termination in `paint_queue_get()` when one side’s exclusive count drops to zero and no pending merge-base candidates exist, gated by the ordered region check.
8. **Mechanical cleanup**: Moves the `min_generation` check into `paint_queue_get()` to consolidate termination conditions and reduce redundant work.
9. **Fallback removal**: Removes the commit-date ordering fallback entirely, replacing it with a topological ceiling for v1 commit-graphs. This ensures the queue is always generation-ordered, enabling consistent termination conditions.

The series touches `commit-reach.c`, `commit-graph.c`, `Documentation/technical/paint-down-to-common.adoc`, and test scripts (`t6600-test-reach.sh`, `t6099-merge-base-side-exhaustion.sh`). New symbols include the `paint_state` struct, `paint_queue_put()`/`paint_queue_get()` helpers, and test helpers like `test_paint_down_steps()`. The fallback removal deletes `corrected_commit_dates_enabled()` and the `gen_ordered` flag.

All substantive review feedback has been addressed, including Elijah Newren’s concerns about v1 commit-graph handling, `min_generation` wording, and the critical ordering requirement in `paint_queue_get()`. The series is **ready for advancement**, with no open technical concerns. The only remaining task is final documentation alignment to adopt the "ordered/unordered" terminology consistently.
