This thread is about a proposed new Git configuration option, `http.sslVerifyHost`, which would allow users to disable TLS hostname verification while keeping certificate verification enabled. The idea, suggested by Ron Nazarov, is aimed at decentralized setups using self-signed certificates where the Common Name (CN) may not match the hostname, but users still want to pin a specific CA certificate via `http.sslCAInfo`.

Patrick Steinhardt has raised significant concerns in his review. While he acknowledges the use case, he argues that the option’s security benefits are overstated. It may protect against passive eavesdropping but remains vulnerable to active man-in-the-middle (MITM) attacks. Patrick believes the commit message and documentation should clearly highlight these limitations rather than presenting the option as a secure middle ground. The discussion is likely to center on whether Git should expose such a configuration knob at all, given the risk of users misunderstanding its security implications. The patch affects the HTTP/HTTPS transport layer, and its interaction with `http.sslCAInfo` is a key technical detail. No decisions have been made yet, and the thread is just getting started.
