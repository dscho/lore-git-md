This is the eighth patch in Justin Tobler’s nine-patch v3 series that refactors `git receive-pack` to use ODB transactions for pluggable packfile writes. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, and this patch specifically addresses a fragility in how the temporary ODB source is tracked during quarantine operations.

The patch changes the interface of `odb_set_temporary_primary_source()` and `tmp_objdir_replace_primary_odb()` to return the newly installed ODB source directly, rather than relying on callers to assume it is the first entry in the ODB source list. This removes a subtle dependency on source list ordering, which was previously a source of bugs (e.g., the lockfile lifecycle flaw fixed in patch 1/9). The former primary source is now reported via an optional `prev_source` out parameter, and the "files" ODB transaction struct is updated to store the quarantine source explicitly.

The change is mechanical and targeted: it touches only the ODB source management functions in `odb.c`, `tmp-objdir.c`, and their headers, plus a single line in `object-file.c` to store the returned source in the transaction struct. No user-visible behavior changes, and the patch includes no new tests—existing tests in `t/t5547-push-quarantine.sh` (added in patch 1/9) already verify the quarantine logic.

This looks like a clean, well-motivated refactor that aligns with the series’ goal of making ODB source tracking explicit and robust. The interface change is backward-compatible (the `prev_source` parameter is optional), and the patch addresses a specific technical debt identified during review of earlier iterations. It’s a small but important step toward making the ODB abstraction more maintainable.
