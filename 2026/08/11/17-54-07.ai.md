This is the first patch in Justin Tobler’s v3 nine-patch series extending the ODB transaction system to `git receive-pack`. It fixes a critical lockfile lifecycle flaw that prevented ".keep" files from being properly removed after an ODB transaction commit.

The bug was introduced in bdee7b3013 when `git receive-pack` switched to using ODB transactions: the ODB source list reordering caused `index_pack_lockfile()` to derive the ".keep" path relative to the temporary transaction directory instead of the main object directory. After the transaction committed, the lockfile path became invalid, leaving stale ".keep" files behind.

The patch updates `index_pack_lockfile()` to accept an explicit `struct odb_source *` parameter and modifies call sites to pass the expected source (the main ODB for `receive-pack`, the repository’s primary source for `fetch-pack`). A new test in `t/t5547-push-quarantine.sh` verifies that ".keep" files are removed after a successful push.

The change is mechanical and narrowly scoped to the lockfile path derivation logic. It touches `builtin/receive-pack.c`, `fetch-pack.c`, `pack-write.c`, `pack.h`, and the test suite. The fix is a prerequisite for the rest of the series, which depends on proper lockfile cleanup to avoid repository corruption. All prior feedback on the lockfile lifecycle has been addressed.
