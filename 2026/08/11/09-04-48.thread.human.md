This thread is about a small but important fix to Git’s auto-maintenance: raising the default threshold for geometric repacking of loose objects from 100 to 6700, matching the long-standing `git gc` default. The change prevents excessive repacking in high-concurrency repositories, where the current aggressive threshold causes race conditions with loose object directory pruning. Patrick Steinhardt posted the fix as a standalone patch, providing historical context for the 6700 value and reaffirming its stability. Two substantive reviewers—Justin Tobler and Elijah Newren—have confirmed the patch is correct as-is, and it’s now ready for Junio to pick up.

The thread has also taken a deeper turn, with Patrick and Elijah exploring whether Git should stop pruning loose object sharding directories entirely. Patrick argues that the performance cost of pruning is negligible (since Git prioritizes packfiles), while the write churn it causes exacerbates the very race conditions his patch mitigates. Though this discussion hints at a potential future architectural change, it doesn’t affect the current fix, which remains uncontroversial and narrowly scoped. For now, the patch is a simple, conservative adjustment that aligns auto-maintenance with `git gc`’s behavior.
