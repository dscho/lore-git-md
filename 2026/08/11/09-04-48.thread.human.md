This thread is a targeted bugfix for Git's auto-maintenance feature, specifically addressing an issue with the geometric repacking strategy. Patrick Steinhardt reports that the current default threshold for loose objects (100) is far too low compared to `git gc`'s default (6700), causing excessive repacking that triggers race conditions in repositories with concurrent writers. The patch raises the threshold to 6700 to align with `git gc` and reduce instability.

The fix is minimal, touching only the default value in `maintenance.geometric-repack.auto` (both in documentation and implementation). It’s a standalone patch motivated by user reports of crashes in high-concurrency environments, where the aggressive repacking exacerbated existing race conditions in loose object directory handling. No objections or alternative proposals have been raised yet, and the change appears uncontroversial. The series is at version 1, and the patch is ready for review.
