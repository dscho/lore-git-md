This is the second patch in Justin Tobler’s nine-patch v3 series extending ODB transactions to `git receive-pack`. It introduces `odb_transaction_finalize()` and `odb_transaction_commit_and_finalize_or_die()` to decouple transaction cleanup from object visibility, enabling backend-specific post-commit operations like lockfile removal.

The patch splits the existing `odb_transaction_commit()` into two steps: `commit()` makes staged objects visible, while `finalize()` performs deferred cleanup (e.g., removing ".keep" lockfiles) and frees the transaction. The new `*_or_die()` helper enforces strict error handling for callers that cannot recover from failures. `builtin/receive-pack.c` is updated to call `finalize()` after reference updates, while other callers (e.g., `builtin/add.c`, `cache-tree.c`) switch to the `*_or_die()` helper for immediate cleanup.

Key technical details: the `finalize` callback is optional and backend-specific; the "files" backend will use it in a later patch to remove ".keep" files. The patch preserves the existing transaction lifecycle while adding flexibility for backends that need post-commit operations. All changes are mechanical updates to transaction call sites, with no behavior changes for existing users.

This patch directly addresses Junio’s v2 feedback about missing `finalize()` calls on non-local exits and the lack of caller-checked return values. The design aligns with Git’s broader pattern of explicit resource management and avoids static state. The `*_or_die()` helper is a pragmatic addition for callers that prefer strict error handling.
