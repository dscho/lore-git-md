This is a small **completion** patch series from Junio C Hamano, the Git maintainer. It fixes a specific edge case in Bash command-line completion: when you type `git -C <some-directory> checkout <path><TAB>`, Git should only suggest paths that are *tracked* in the index of the repository you switched to with `-C`, not untracked files.

The series consists of two patches. The first is a no-op refactoring that reorganizes the existing completion logic for `git checkout` without changing behavior. The second patch implements the actual fix: it ensures that path completion for `git checkout` (with or without `-C`) only offers paths that are already in the index, matching the command’s documented behavior ("checkout paths out of the index").

The change affects only the `contrib/completion/git-completion.bash` script and adds tests in `t/t9902-completion.sh`. The motivation is clear and narrowly scoped: the current completion logic is inconsistent with the command’s semantics. The series looks well-crafted, with a clean separation between refactoring and functional change, and includes test coverage for the new behavior. There’s no indication of controversy or open questions — this appears to be a straightforward bugfix for a long-standing papercut.
