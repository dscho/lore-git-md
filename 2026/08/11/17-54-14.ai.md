This is patch 8/9 in Justin Tobler’s v3 series extending ODB transactions to make `git receive-pack` fully backend-agnostic. The patch addresses a fragility in the current design by eliminating the assumption that the temporary ODB source is always the first entry in the source list.

The change is mechanical: `odb_set_temporary_primary_source()` now returns the newly installed source directly and reports the previous primary source via an optional out-parameter (`prev_source`). The return value is propagated through `tmp_objdir_replace_primary_odb()` and stored in the "files" ODB transaction struct (`quarantine` field). This ensures that subsequent commit operations can access the temporary source without relying on the ordering of the ODB source list, which could change as the ODB abstraction effort matures.

Files touched: `object-file.c`, `odb.c`, `odb.h`, `tmp-objdir.c`, and `tmp-objdir.h`. New or modified symbols: `odb_set_temporary_primary_source()` (signature change), `tmp_objdir_replace_primary_odb()` (now returns `struct odb_source *`), and the `quarantine` field in `struct odb_transaction_files`. No user-visible behavior changes; the patch is purely an internal refactor to improve robustness.

The patch directly addresses feedback from earlier iterations about the fragility of relying on source list ordering. By storing the temporary source explicitly in the transaction struct, the design becomes more resilient to future changes in how ODB sources are managed. This is a small but important step in the broader ODB abstraction effort, as it removes an implicit assumption that could complicate the integration of alternative backends.

No open questions or loose ends are introduced by this patch; it is a clean, targeted fix for a specific design flaw identified during review. The change aligns with the series’ overall goal of making the transaction interface more explicit and less reliant on global state.
