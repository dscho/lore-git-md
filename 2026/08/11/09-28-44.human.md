This is a test infrastructure patch, part of Tian Yuchen’s larger performance optimization series for `paint_down_to_common()`. The series is already fully reviewed and queued in Junio’s tree, with this patch addressing a specific improvement to test diagnostics.

The patch introduces `test_trace2_data_singular()`, a helper function that replaces the existing `test_trace2_data` grep-based check with a more robust assertion. Instead of silently failing when a Trace2 data event is missing or mismatched, the new function reports exactly what went wrong: whether the key was not found, appeared multiple times, or had an unexpected value. Diagnostics are written to file descriptor 4 (the same channel used by `test_grep`), making them visible in test output without cluttering the primary log.

The change is small but impactful for debugging. The old `test_trace2_data` would exit with status 1 and no output if the event was missing or mismatched, forcing developers to manually inspect Trace2 logs. The new function provides clear, actionable feedback, such as:
```
error: trace2 data 'status/count/changed'
  expected: 999
  actual:   0
```
This is especially useful for the series’ performance instrumentation, where step counts and other metrics are validated via Trace2 events.

The patch touches only `t/test-lib-functions.sh` and adds 35 lines. It is a pure test infrastructure improvement with no behavior changes to Git itself. Review feedback on earlier versions (notably from René Scharfe) has been incorporated, and the patch is now ready for integration. Since the series is already queued, this is a non-blocking refinement that improves testability for future work.
