This is the final patch in a now-complete performance optimization series for Git’s commit-reach subsystem. The patch removes the long-standing commit-date ordering fallback in `paint_down_to_common()`, a change made possible by the side-exhaustion optimization introduced earlier in the series.

The fallback was originally added in 2018 to avoid a performance regression on the Linux kernel repository when using v1 commit-graphs (topo levels only). Without it, `git merge-base v4.8 v4.9` would walk 636k commits instead of 167k. The side-exhaustion optimization—terminating the walk as soon as one side’s commits are exhausted—now achieves far better results: step counts drop from 167k to 5.7k (v1 graph) and 3.9k (v2 graph), with corresponding wall-clock time reductions from 0.25s to 0.02s.

Removing the fallback simplifies the code by eliminating the `gen_ordered` flag and ensuring the queue is always generation-ordered. This allows the existing `min_generation` check in `paint_queue_get()` to work reliably, as generation ordering guarantees children are visited before parents. The patch also updates the technical documentation (`paint-down-to-common.adoc`) to remove outdated sections about the fallback’s limitations (e.g., premature termination risks and disabled optimizations).

Test expectations in `t6600-test-reach.sh` are adjusted to reflect the reduced step counts enabled by the fallback’s removal. For example, the `merge-base --all` test now expects 37 steps (down from 81) in the "no-gdat" mode, and clock-skew tests see similar reductions.

The series as a whole is technically complete, fully reviewed, and queued in Junio’s tree. This patch is the last piece, and its inclusion is uncontroversial given the demonstrated performance gains and prior review approval. The optimization is particularly valuable for repositories with asymmetric histories (e.g., import grafts or shallow clones), where it delivers 100-1000x speedups.
