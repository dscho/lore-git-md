This thread began as a bug report about silent corruption in Git workflows on Windows, stemming from two related issues: misconfigured textconv filters that corrupt `git diff` output by stripping all 'r' characters instead of carriage returns, and overly broad global `.gitattributes` rules that force text filters onto binary files (like PNGs and JPEGs), corrupting them during checkout. The textconv issue was quickly dismissed as a shell misconfiguration problem (unquoted backslashes in filter commands) with no plans for Git-side fixes beyond potential documentation updates. The binary corruption issue, however, remains unresolved and has evolved into a broader critique of Git’s attribute system design.

Key participants include the author, Skybuck Flying, who initially reported both issues and provided reproduction steps, and Randall S. Becker, the NonStop port maintainer, who validated the binary corruption risk and highlighted Git’s unsafe defaults and unreliable binary file detection. Jeff King (Peff) and Theodore Tso (Ted) engaged only on the textconv issue, framing it as a "Windows problem" rather than a Git usability concern. The thread has since stalled on actionable solutions, with proposed mitigations ranging from documentation warnings and safer Windows defaults (`core.autocrlf=input`) to automatic binary detection or even removing global `.gitattributes` filters entirely. Maintainers have not yet weighed in on these proposals.

The latest email from Skybuck Flying shifts the discussion into a philosophical tangent, proposing a speculative text encoding format called Universal Text Coding (UTC) as an alternative to Git’s current text-handling assumptions. While technically detailed, this proposal is orthogonal to the thread’s original focus and does not engage with the practical solutions (warnings, safeguards) discussed earlier. The email reflects the author’s frustration with Git’s cross-platform quirks but does not advance the thread toward resolution. The core usability issues—global `.gitattributes` risks and binary corruption—remain open, with no consensus on whether Git should treat them as usability problems (requiring warnings or safeguards) or documentation gaps. The thread’s trajectory now hinges on whether maintainers will respond to Becker’s technical critiques or let the discussion fade.
