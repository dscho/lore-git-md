This thread is about two related but distinct usability issues in Git on Windows that can cause silent corruption in workflows, reported by Skybuck Flying. The first issue—a misconfigured textconv filter stripping all 'r' characters instead of just carriage returns—was quickly dismissed as a shell misconfiguration problem, not a Git bug, with maintainers like Jeff King and Theodore Ts'o suggesting it’s a documentation gap rather than something Git should fix.

The second issue, which this latest email focuses on, is more serious: overly broad global `.gitattributes` rules (like `* text diff=lfclean`) force text filters onto binary files (PNGs, JPEGs), corrupting them during checkout. Skybuck documents a real-world case where this happened, showing how the corruption occurs and providing clear reproduction steps. While the workaround is simple—delete the global `.gitattributes` file—the author now argues this is an **inherent design flaw** in Git’s attribute system, advocating for the complete removal of global filters rather than incremental fixes like warnings or automatic binary detection. No maintainers have yet weighed in on whether Git should add safeguards (e.g., warnings for global `*` rules) or treat this as a documentation issue. The thread remains open, with the core question unanswered: should Git do more to prevent silent corruption, or is this ultimately a user education problem?
