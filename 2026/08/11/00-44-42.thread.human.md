This thread is about a serious Windows-specific bug in Git’s textconv pipeline that silently corrupts `git diff` output. The issue was initially reported by Skybuck Flying, who discovered that a misconfigured textconv filter (`diff.lfclean.textconv=sed -e s/\r//`) was stripping all 'r' characters instead of just carriage returns due to MSYS argument parsing quirks on Windows. The problem has since been escalated: the author now confirms that the corruption is not limited to `sed` or shell behavior but is rooted in Git’s internal textconv execution path on Windows. This means *any* textconv filter can trigger silent corruption, making the issue far more severe than initially thought.

The corruption is silent—no errors or warnings are emitted—and only affects `git diff` output, leaving repository content intact. For example, identifiers like "compareCache" become "compaeCache" in diffs, which could mislead users into thinking their code has changed when it hasn’t. The author provides a clear test case and suggests practical fixes, such as a `--debug-textconv` flag to log executed commands, size-mismatch warnings, or platform-specific documentation to help users avoid pitfalls. The report is technically precise and actionable, but the tone is confrontational, reflecting the author’s frustration with Git’s handling of line endings and Windows compatibility.

No maintainer has responded yet, so the project’s stance on this issue remains unclear. The key questions are whether Git should provide built-in CR-stripping functionality (e.g., `git diff --strip-cr`), add diagnostic tools like `--debug-textconv`, or improve documentation with Windows-specific examples. The issue is high-priority for Windows users, as it risks undermining trust in `git diff` output, and the fact that the corruption cannot be reproduced outside Git makes it particularly difficult to diagnose. The next steps will likely depend on whether a maintainer or domain expert (e.g., Johannes Schindelin or a Git for Windows contributor) engages with the thread.
