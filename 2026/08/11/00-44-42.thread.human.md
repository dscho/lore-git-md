This thread began when a Windows user, Skybuck Flying, reported two related issues causing silent corruption in Git workflows. The first—a textconv filter misconfiguration due to unquoted backslashes in shell commands—was quickly dismissed as a shell parsing issue outside Git’s scope, though maintainers acknowledged it as a documentation gap. The second, more serious problem involves global `.gitattributes` rules like `* text diff=lfclean` forcing text filters onto binary files (PNGs, JPEGs), corrupting them during checkout. This has sparked a broader discussion about Git’s attribute system design and whether it should include safeguards against such misconfigurations.

Key participants have weighed in with varying perspectives. Jeff King (Peff) and Theodore Tso framed the textconv issue as a "Windows problem" solvable through better documentation, while Randall S. Becker (NonStop port maintainer) highlighted the risks of Git’s unsafe defaults and unreliable binary detection heuristics. D. Ben Knoble recently clarified the technical mechanism: the `text` attribute—not the `diff` filter—triggers line-ending normalization during checkout, corrupting binaries. Knoble endorsed safer configurations like `* text=auto` (which lets Git decide if a file is text) and `core.autocrlf=input`, reinforcing Becker’s earlier advice. The thread remains unresolved, with no maintainer consensus on whether Git should add warnings, automatic binary detection, or other safeguards.

The discussion has shifted from diagnosing the problem to debating Git’s responsibility for user misconfigurations. While the author has disengaged from technical discussion, the remaining participants agree on the risks of global `.gitattributes` rules but differ on solutions. The thread’s actionable takeaways include avoiding global `*` rules, using `text=auto` instead of `text`, and marking binaries explicitly (e.g., `*.png binary`). No code changes have been proposed yet, but the conversation may prompt documentation updates or future usability improvements.
