This is the final patch in Patrick Steinhardt’s four-part series refactoring Git’s object database (ODB) subsystem to remove lazy-loading of alternate object databases. The patch is a mechanical cleanup that removes the now-unused `alternates_db` field from `struct object_database`, completing the architectural shift introduced earlier in the series.

The change is straightforward: since the series’ second patch already centralized and eagerized alternate ODB initialization in `odb_new()`, the `alternates_db` field (which previously stored the `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variable) is no longer needed. The patch updates `odb_prepare_alternates()` to accept the alternate database path as a parameter (passed via `odb_new()`) instead of reading it from the ODB struct, and removes the redundant freeing of the field in `odb_free()`. The call to `odb_prepare_alternates()` in `odb_prepare()` is updated to pass `NULL` when flushing caches, since the field no longer exists.

Justin Tobler’s review raises a clarifying question about whether the `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variable is still needed during later calls to `odb_prepare_alternates()`. His observation—that alternates are already added as sources during initial setup, so subsequent calls only need to re-read the alternates file—is correct and aligns with the series’ goal of simplifying the code. The patch itself is uncontroversial and unlikely to draw further discussion, as it merely removes dead code following the earlier refactoring. The question is more about documenting the rationale than challenging the change.
