This is the third patch in Justin Tobler’s nine-patch v3 series making `git receive-pack` fully ODB-agnostic. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and has already addressed all critical feedback from v2, including a lockfile lifecycle flaw and transaction lifecycle management.

This patch removes a hidden dependency on global state in the `unpack()` function. Currently, if shallow information is provided, `unpack()` creates a temporary shallow file and stores its path in the global variable `alt_shallow_file`. The next patch in the series will move `unpack()` behind the new `odb_transaction_write_pack()` interface, which cannot rely on such globals. To prepare for that, this patch lifts the shallow-file setup out of `unpack()` and passes the file path explicitly through the call chain: `unpack_with_sideband()` → `unpack()` → `prepare_shallow_update()` → `update_shallow_info()`.

The change is mechanical and confined to `builtin/receive-pack.c`; it adds a `const char *shallow_file` parameter to each function in the chain and removes the global `alt_shallow_file`. The only caller (`cmd_receive_pack`) now creates the temporary file itself and passes the path down. The patch is a straightforward refactoring that clears the way for the ODB abstraction without altering behavior.
