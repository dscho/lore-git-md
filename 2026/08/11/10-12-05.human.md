This is the fifth patch in Patrick Steinhardt’s v2 series refactoring the Git object database (ODB) streaming API, and it’s the centerpiece of the effort. The patch merges the previously separate `odb_read_stream` and `odb_write_stream` structures into a single `odb_stream` that handles both directions, eliminating redundancy and paving the way for pluggable ODB backends. The change is mostly mechanical—replacing old type names with the new unified one—but two files (`builtin/unpack-objects.c` and `odb/streaming.c`) require special handling because they previously embedded the old `odb_write_stream` directly. Now they allocate a wrapper structure that embeds the new `odb_stream` base, using the container-of pattern to access the parent.

Karthik Nayak’s review is brief but substantive where it counts. He confirms the core idea—wrapping the stream with the data’s structure instead of embedding a pointer—is sound, and he notes the trade-off: the new `char *` buffer type loses some type safety (since both read and write streams now use the same pointer type) but gains flexibility. His only nit is the loss of type information, which is a minor concern given the broader goal of unification. The rest of the patch passes his inspection without further comment.

This patch is well-motivated and cleanly executed. The wrapper allocation logic is the only potential gotcha, but the container-of pattern is idiomatic in Git’s codebase, and the patch has already been through one round of review that surfaced no issues with it. The subsequent patches in the series (6/8 and 7/8) will clean up the slightly misleading names left behind here, so this is a safe, incremental step toward a more maintainable ODB layer. If you care about the ODB abstraction effort or plan to work with pluggable backends, this patch is worth a quick skim to see how the unified streaming API is taking shape. Otherwise, it’s safe to treat as a routine refactoring.
