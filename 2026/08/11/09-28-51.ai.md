This is the ninth patch in the v8 series optimizing `paint_down_to_common()` for one-sided histories. It consolidates the `min_generation` termination check into `paint_queue_get()`, alongside the existing stale-entry and side-exhaustion checks, and moves `last_gen` into `struct paint_state` to avoid redundant calls to `commit_graph_generation()`.

The change is a mechanical refactoring that centralizes termination conditions in `paint_queue_get()`, improving code clarity and maintainability. By storing `last_gen` in `paint_state`, the patch ensures `commit_graph_generation()` is called exactly once per dequeued commit, and the result is reused across all termination checks and the monotonicity BUG assertion. The `min_generation` check is now performed immediately after generation retrieval, before any counter decrements, aligning with the existing pattern for other termination conditions. The `topo_ceiling` check in the side-exhaustion optimization is updated to use `state->last_gen` instead of re-fetching the generation.

The patch touches only `commit-reach.c` and introduces no new symbols or behavior changes. It is part of the series' broader effort to make the queue's state and termination logic more explicit, enabling the side-exhaustion optimization in the final patch. The refactoring reduces redundancy and ensures consistent handling of generation-based termination across all code paths. All prior review feedback on this patch (e.g., Elijah Newren's concerns about ordering and clarity) has been addressed, and the patch is ready for advancement alongside the rest of the series.
