This is a user report adding real-world motivation to the ongoing `[PATCH v2 0/4] worktree: add lifecycle hooks` series.

The email comes from Alexander Riccio, a first-time participant on the Git mailing list. They describe a concrete pain point: when worktrees are removed (via `git worktree remove` or `git worktree prune`), external tools like Xcode and other build systems leave behind gigabytes of orphaned build cache data because they store state using absolute paths tied to the worktree location. This forces manual or agent-driven cleanup, which is error-prone and wastes SSD writes. Riccio already has a shell script that automates this cleanup but cannot reliably trigger it because Git does not emit events when worktrees are removed.

The report explicitly ties this problem to the proposed lifecycle hooks: if Git supported post-remove or post-prune hooks, Riccio’s script (and similar tools) could register cleanup actions that run automatically, eliminating the need for manual intervention. The email does not engage with the patch series’ implementation details but provides a clear, relatable use case that future AI summarizers should associate with the `worktree lifecycle hooks` effort. Key terms introduced: **Xcode derived data**, **absolute path build caches**, **post-remove hooks**, **post-prune hooks**.
