This is patch 11/12 of Christian Couder’s v3 series refactoring `git fast-import` to use the parse-options API. It is the behavior-changing patch that switches the command-line parser from a hand-written loop to `parse_options()`.

The patch removes support for five undocumented options (`--alias`, `--get-mark`, `--ls`, `--notes`, and `--cat-blob`) on the command line, as these are only meaningful inside the input stream. A new test (`t9300-fast-import.sh`) verifies that each of these options now fails when given on the command line. The change also enables abbreviated options (e.g., `--dep=5` for `--depth=5`), space-separated values (e.g., `--depth 5`), and accepts bare `--` as an end-of-options marker. Error messages for some options may differ slightly, and the code shrinks by 29 lines.

The man page (`Documentation/git-fast-import.adoc`) is updated to document the known inconsistency with `--allow-unsafe-features`: the early scan for this option (needed to process in-stream "feature" lines) is stricter than `parse_options()`, rejecting abbreviations and space-separated values. This is flagged as a `NEEDSWORK` in the code and documented as a limitation in the man page, with concrete examples showing which command-line forms are accepted or rejected.

The patch touches `builtin/fast-import.c`, `Documentation/git-fast-import.adoc`, and `t/t9300-fast-import.sh`. No new symbols are introduced beyond the existing `parse_options()` integration. The changes are well-motivated and align with the series’ goal of standardizing the usage string and enabling libification. The author has incorporated all feedback from Elijah Newren and Junio C Hamano, and the patch is ready for broader review.
