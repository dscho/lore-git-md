This is the third patch in Patrick Steinhardt’s four-patch series refactoring the Git object database (ODB) subsystem to remove lazy-loading of alternate object databases. The series is part of the broader ODB abstraction effort led by Patrick, which aims to simplify and modularize Git’s object storage layer.

This patch removes the `loaded_alternates` field from `struct object_database`, which previously tracked whether alternates had been loaded. Since the preceding patch (2/4) made alternate loading eager—happening during `odb_new()`—this field is now redundant. The change is purely mechanical: the field is deleted, and the single remaining check for it is replaced with unconditional execution of `odb_add_alternate_recursively()`. The patch also removes the now-unnecessary reset of `loaded_alternates` in `odb_prepare()` when `ODB_PREPARE_FLUSH_CACHES` is set.

Justin Tobler, who reviewed the earlier patches in the series, confirms the change is safe and logical. He notes that the field’s removal also eliminates an awkward pattern where `loaded_alternates` was unset just to force a re-preparation of alternates. The diff is small (9 lines removed, 1 added) and confined to `odb.c` and `odb.h`, with no intended behavioral changes. This is a straightforward cleanup that reduces state tracking in the ODB structure, making the codebase slightly simpler and more maintainable.

The patch is well-motivated and uncontroversial, following naturally from the architectural shift in patch 2. It’s a low-risk change that aligns with the series’ goal of simplifying the ODB code. If you’re following the ODB abstraction effort, this patch is worth noting as another incremental step toward a more modular and predictable object storage layer. For most readers, this is a minor cleanup that doesn’t require deep engagement unless you’re working directly with the ODB subsystem.
