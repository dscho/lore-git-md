This is the final patch (9/9) in Justin Tobler’s v3 series introducing `odb_transaction_write_pack()`, the generic interface that completes the ODB abstraction for `git receive-pack`. The patch moves the packfile ingestion logic from `builtin/receive-pack.c` into the "files" ODB backend (`object-file.c`), replacing the hardcoded `unpack()` function with the new `odb_transaction_write_pack()` callback. The "files" backend now manages ".keep" lockfiles explicitly, storing them in a dynamically grown array (`pack_lockfiles`) and removing them during transaction finalization. Call sites in `receive-pack` are updated to use the new interface, and the old `unpack()` implementation is removed.

Key technical details:
- Files touched: `builtin/receive-pack.c`, `object-file.c`, `odb/transaction.c`, `odb/transaction.h`.
- New or renamed symbols: `odb_transaction_write_pack()`, `struct odb_transaction_write_pack_opts`, `odb_transaction_files_write_pack()`, `pack_lockfiles` array in `struct odb_transaction_files`.
- The `odb_transaction_write_pack_opts` struct mirrors the old `unpack_opts` but is now part of the public ODB transaction interface, enabling backend-agnostic packfile ingestion.
- The "files" backend implementation (`odb_transaction_files_write_pack()`) is nearly identical to the old `unpack()` logic, with the addition of explicit lockfile tracking via `ALLOC_GROW` and `register_tempfile`.
- The transaction’s `finalize` callback now iterates over the `pack_lockfiles` array to clean up ".keep" files, ensuring they are removed even if the transaction is finalized after reference updates.
- The patch removes the global `pack_lockfile` variable and the last direct dependency on `lockfile.h` in `receive-pack.c`.

No user-visible behavior changes; the series remains a refactor to enable pluggable ODB backends. The patch is well-motivated, with clear commit message rationale and mechanical soundness. The lockfile lifecycle fix (addressing Junio’s v2 feedback) is preserved, and the explicit ODB source tracking introduced earlier in the series ensures the temporary source remains accessible post-commit. The patch appears ready for merging, completing the ODB abstraction for `git receive-pack`.
