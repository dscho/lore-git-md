Subject: [PATCH] copy: add reflink support for local clones and file copies
Series version: v1 (initial submission)
Originating author: Vlad Petric
Thread type: patch series (performance feature)

Core problem or goal
Teach Git to use copy-on-write reflinks (via Linux `FICLONE` ioctl) as a space-efficient alternative to hardlinks or byte-for-byte copying for object files, both in generic file copies (`copy_file()`) and local clones. Reflinks avoid inode aliasing while sharing storage, making them ideal for Git’s use case where independent modification is rare.

Current status
Under review; v1 posted. No prior versions.

Key technical details
- Files touched: `copy.c`, `clone.c`, test infrastructure (`t0094-reflink.sh`, `test-fake-reflink.c`), documentation.
- New functions: `copy_file_reflink()`, `copy_file_reflink_with_time()`, `finish_copy()`.
- Fallback order: reflink → hardlink (unless `--no-hardlinks`) → byte copy.
- Preserves source timestamps for `prune`/`gc` compatibility.
- Linux-specific; other platforms unaffected.
- Test coverage: generic file copy, local clone, `--no-hardlinks`, hardlink fallback, byte-copy fallback, object integrity, timestamp preservation.
- Test helper (`test-fake-reflink.c`) simulates reflink success/unsupported/errors via LD_PRELOAD.
