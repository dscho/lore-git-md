Core problem or goal
Teach Git to use copy-on-write reflinks (via Linux `FICLONE` ioctl) as a space-efficient alternative to hardlinks or byte-for-byte copying for object files, both in generic file copies (`copy_file()`) and local clones. Reflinks avoid inode aliasing while sharing storage, making them ideal for Git’s use case where independent modification is rare.

Current status
Under review; v2 posted. Junio’s **high-weight design question** about the fallback order (reflink → hardlink → byte copy) is resolved: the new version now attempts hardlink first, reflink second, and byte copy last, aligning with the principle that simpler mechanisms should be preferred for immutable files. No merge status.

Key technical details

- New functions: `copy_file_reflink()`, `copy_file_reflink_with_time()`, `finish_copy()`.
- Fallback order: hardlink → reflink → byte copy. With `--no-hardlinks`: reflink → byte copy.
