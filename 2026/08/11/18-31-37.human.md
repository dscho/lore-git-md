This is a **performance feature** for Linux that adds reflink support to Git’s file-copying logic, now revised to prefer hardlinks over reflinks for immutable object files. The author has responded to Junio C Hamano’s design question by flipping the fallback order: Git will now attempt a hardlink first, then a reflink, and finally a byte-for-byte copy. The `--no-hardlinks` option still skips the hardlink step, leaving reflink as the first choice in that case.

The patch remains Linux-specific, using the `FICLONE` ioctl, and retains all the original test coverage: generic file copying, local clones, `--no-hardlinks`, hardlink fallback, byte-copy fallback, object integrity, and timestamp preservation. The test helper (`test-fake-reflink.c`) continues to simulate reflink success, unsupported operation, and errors via LD_PRELOAD, ensuring the test suite can exercise every code path regardless of the underlying filesystem.

The change is a direct response to review feedback and should resolve the only substantive open question. The implementation is still clean, well-tested, and motivated by real-world use (the author reports that a reflink-capable ZFS filesystem produced byte-for-byte copies without this patch). No further design objections are apparent, and the patch now looks ready for integration.
