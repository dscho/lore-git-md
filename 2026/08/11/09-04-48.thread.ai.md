Thread identity: Patch series (1/1) fixing an overly aggressive geometric repacking threshold in Git's auto-maintenance. Originating author: Patrick Steinhardt.

Core problem or goal: The geometric repacking strategy in Git's auto-maintenance triggers repacks of loose objects too frequently (default threshold: 100 loose objects) compared to `git gc`'s default (6700). This causes instability in high-concurrency repositories due to race conditions between repacking and loose object directory pruning.

Current status: **Ready for integration.** Patch v1 posted as a standalone fix; no prior versions. The author has provided historical context for the threshold choice (6700), tracing its origin to a 2007 `git gc --auto` calibration that balanced pragmatism and stability. The rationale reaffirms alignment with `git gc`'s long-standing default as the simplest and most conservative fix. Justin Tobler, the sole substantive reviewer, has confirmed the patch is "fine as is" and withdrawn his prior suggestion to expand the commit message rationale. The author has now flagged the patch for Junio's attention, noting it has not yet appeared in "What's cooking" and may have been overlooked.

Key technical details:
- Files touched: `Documentation/config/maintenance.adoc`, `odb/source-files.c`.
- Symbols/config keys: `maintenance.geometric-repack.auto` (default value changed from 100 to 6700).
- Behavior change: Reduces frequency of geometric repacks for loose objects to match `git gc`'s threshold. The heuristic counts loose objects in only one fan-out directory and multiplies by 256, making it a rough estimate rather than a precise measurement. The author explicitly notes that the core issue is the overly aggressive default (100), not the estimation method. Historical context reveals the 6700 threshold was chosen to avoid triggering on a fully unpacked Git v0.99 repository while still activating for v1.0, and to prevent redundant repacks during incremental updates.
- No on-disk format changes; purely a configuration default adjustment.
- Test coverage: Not explicitly mentioned, but the patch is motivated by user-reported instability in real-world high-concurrency scenarios.
