This is the fifth patch in the v8 series optimizing `paint_down_to_common()` in Git’s commit-reach subsystem. The patch adds **Trace2 instrumentation** to measure the number of commits visited during the paint walk, enabling observable performance analysis of the optimization introduced in later patches.

The change is straightforward: a `steps` counter is incremented for each commit processed in `paint_down_to_common()`, and the final count is emitted via `trace2_data_intmax()`. This allows developers to measure the impact of future optimizations (or regressions) without relying solely on wall-clock benchmarks. The patch also updates the test suite to validate these step counts across all commit-graph modes (none, full, half, no-gdat), replacing the prior `run_all_modes` helper with a more granular approach that captures Trace2 output per mode. New helper `test_paint_down_steps` verifies the step counts match expected values, with test expectations already reflecting the reduced workload from the pre-existing `min_generation` optimization (e.g., 45 steps in "none" mode vs. 2 in "full" mode for `in_merge_bases_many:self`).

The patch touches only `commit-reach.c` and `t/t6600-test-reach.sh`, introducing no new symbols or behavior changes—just observability. The test updates are mechanical but necessary to ensure the instrumentation is robust. This is a **tested, non-controversial addition** that directly supports the series’ goal of making performance improvements measurable. All prior review feedback (e.g., Trace2 event validation) has been addressed in earlier patches (notably `test_trace2_data_singular()` added in patch 3/8). The patch is ready for advancement as part of the queued series.
