This is a maintainer review of the `http.sslVerifyStatus` security feature patch. Junio C Hamano responds to the author’s commit message and code with a single, focused critique: the in-code comment explaining why `http.sslVerifyStatus` defaults to `false` and how backends differ is unnecessary and distracting. He argues that design rationale belongs in the commit message (which the author already wrote well), not in the code itself, because developers debugging or extending the feature can find the reasoning via `git blame` and the commit log. The review is surface-level—it does not question the patch’s correctness, security model, or implementation, but rather its presentation. No objections to the feature itself are raised.
