Subject: Silent corruption in `git diff` on Windows due to misconfigured textconv filter

Originating author: Skybuck Flying
Thread type: bug report / usability discussion

Core problem or goal
A Windows user reported silent corruption in `git diff` output caused by a misconfigured textconv filter (`sed -e s/\r//`), which the shell interprets as `s/r//`, stripping all 'r' characters instead of carriage returns. The goal is to prevent such silent corruption by improving documentation, diagnostics, or built-in safeguards, while clarifying whether this is a Git bug, a shell misconfiguration, or a usability gap.

Current status
Under review. The root cause has been identified as shell argument parsing (unquoted backslashes in filter commands), not a flaw in Git’s textconv pipeline. Jeff King (Peff) confirmed the issue is reproducible on Linux and attributes it to user misconfiguration, narrowing the scope to documentation improvements (e.g., Windows-safe examples in `gitattributes(5)`). No maintainer decision yet on whether to add diagnostics (e.g., `--debug-textconv`) or built-in CR-stripping functionality.

Key technical details
- **Subsystem**: textconv filters, shell argument parsing (not Windows-specific).
- **Trigger**: Unquoted backslashes in textconv filter commands (e.g., `sed -e s/\r//` → `s/r//`).
- **Symptoms**: Silent corruption of identifiers (e.g., "compareCache" → "compaeCache") in `git diff` output; repository content remains uncorrupted. No warnings or errors are emitted.
- **Root cause**: Shell interprets unescaped backslashes in filter commands, not Git’s textconv execution path. The issue is reproducible on Linux with identical filter syntax.
- **Reproduction**: Provided by the author; corruption occurs when the filter is run via Git but not when executed manually outside Git.
- **Workaround**: Quote backslashes in filter commands (e.g., `sed -e "s/\\r//"`) or use `git diff --no-textconv`.
- **Suggested fixes**:
  - **Documentation**: Add Windows-safe examples to `gitattributes(5)` (e.g., `tr -d \r` or `dos2unix`).
  - **Diagnostics**: Consider a `--debug-textconv` flag to log executed commands and filter output for troubleshooting.
  - **Safeguards**: Size-mismatch warnings or built-in CR-stripping filters (e.g., `git diff --strip-cr`).
  - **Usability**: Improve error messages or warnings for potentially unsafe filter patterns.
