Subject: Silent corruption in `git diff` on Windows due to misconfigured textconv filter and binary file corruption from global `.gitattributes`

Originating author: Skybuck Flying
Thread type: bug report / usability discussion

Core problem or goal
A Windows user reported two related usability issues causing silent corruption in Git workflows:
1. **Textconv filter misconfiguration**: Unquoted backslashes in textconv filter commands (e.g., `sed -e s/\r//`) are misparsed by the shell, stripping all 'r' characters instead of carriage returns, corrupting `git diff` output without warnings. This was confirmed as a shell argument-parsing issue (not a Git flaw) and dismissed as a documentation gap or "Windows problem" by maintainers.
2. **Binary file corruption**: Overly broad global `.gitattributes` rules (e.g., `* text diff=lfclean`) force text filters onto binary files (PNGs, JPEGs), corrupting them during checkout. The issue is now framed as a **systemic design risk** in Git’s attribute system, with calls for safeguards (warnings, automatic binary detection) or even the removal of global filters. The goal is to prevent silent corruption through improved diagnostics, documentation, or built-in protections, while clarifying whether Git should mitigate user misconfigurations or defer to user education.

Current status
Under review. The root causes are identified, but maintainer consensus is lacking:
- **Textconv issue**: Closed as a shell misconfiguration; no further action planned beyond potential documentation updates (Windows-safe examples in `gitattributes(5)`).
- **Binary corruption issue**: Active and unresolved. The author and Randall S. Becker (NonStop port maintainer) have both highlighted the risks of global `.gitattributes` rules, demonstrating reproducible corruption of binaries (PNGs, JPEGs) during checkout. Proposed mitigations include:
  - **Configuration**: Safer defaults for Windows (`core.autocrlf=input`, `core.ignorecase=true`, `core.filemode=false`) and explicit binary declarations (e.g., `*.png binary`).
  - **Documentation**: Add warnings about global `*` rules in `gitattributes(5)` and emphasize local `.gitattributes` usage.
  - **Diagnostics**: Warnings for global `*` rules with `text` or textconv filters, or for files with binary extensions (e.g., `*.png`) subjected to text filters.
  - **Safeguards**: Automatic binary file detection (e.g., ignore `text` for known binary extensions), size-mismatch warnings during checkout, or built-in CR-stripping filters (e.g., `git diff --strip-cr`).
  - **Design changes**: The author advocates for removing global `.gitattributes` filters entirely, though this is unlikely to gain traction. Becker implies the attribute system’s design is inherently risky.

Key technical details
- **Subsystems**: textconv filters, shell argument parsing, `.gitattributes` handling (precedence rules, global vs. local files), checkout process, binary file detection, line-ending normalization (`core.autocrlf`).
- **Triggers**:
  - Textconv: Unquoted backslashes in filter commands (e.g., `sed -e s/\r//` → `s/r//`).
  - Binary corruption: Global `.gitattributes` rules like `* text diff=lfclean` applied to all files, including binaries.
- **Symptoms**:
  - Textconv: Silent corruption of identifiers (e.g., "compareCache" → "compaeCache") in `git diff` output; repository content uncorrupted.
  - Binary corruption: Corrupted binary files (PNGs, JPEGs) during checkout; repository blobs intact. DLL files were unaffected due to lack of CR bytes, masking the issue’s scope.
- **Root causes**:
  - Textconv: Shell interprets unescaped backslashes; reproducible on Linux with identical syntax.
  - Binary corruption: `.gitattributes` precedence rules apply text filters to all files, including binaries, without safeguards. Git’s binary detection heuristic (checking only the first "hunk") is unreliable, especially for files with CR bytes early in their content.
- **Workarounds**:
  - Textconv: Quote backslashes (e.g., `sed -e "s/\\r//"`) or use `git diff --no-textconv`.
  - Binary corruption: Delete global `.gitattributes` and use local rules (e.g., `*.txt text`) or mark binaries (e.g., `*.png binary`). Use `%f` in textconv commands on Windows to avoid text-mode file handling.
- **Suggested fixes**:
  - **Documentation**: Add Windows-safe examples (e.g., `tr -d \r`, `dos2unix`) and warnings about global `*` rules in `gitattributes(5)`.
  - **Diagnostics**: Warnings for global `*` rules with `text` or textconv filters, or for files with binary extensions subjected to text filters.
  - **Safeguards**: Size-mismatch warnings, built-in CR-stripping filters (e.g., `git diff --strip-cr`), or automatic binary file detection (e.g., ignore `text` for known binary extensions like `*.png`). Safer defaults for Windows (`core.autocrlf=input`).
  - **Design**: The author proposes removing global `.gitattributes` filters entirely; Becker implies the attribute system’s design is inherently risky.
