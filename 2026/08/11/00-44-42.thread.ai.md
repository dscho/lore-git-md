Subject: Silent corruption in `git diff` on Windows due to misconfigured textconv filter and binary file corruption from global `.gitattributes`

Originating author: Skybuck Flying
Thread type: bug report / usability discussion

Core problem or goal
A Windows user reported two related usability issues causing silent corruption in Git workflows:
1. **Textconv filter misconfiguration**: Unquoted backslashes in textconv filter commands (e.g., `sed -e s/\r//`) are misparsed by the shell, stripping all 'r' characters instead of carriage returns, corrupting `git diff` output without warnings. This was confirmed as a shell argument-parsing issue (not a Git flaw) and dismissed as a documentation gap or "Windows problem" by maintainers.
2. **Binary file corruption**: Overly broad global `.gitattributes` rules (e.g., `* text diff=lfclean`) force text filters onto binary files (PNGs, JPEGs), corrupting them during checkout. The author now frames this as an **inherent design flaw** in Git’s attribute system, advocating for the complete removal of global filters rather than incremental fixes. The goal is to prevent silent corruption through improved documentation, diagnostics, or built-in safeguards, while clarifying whether Git should mitigate user misconfigurations (e.g., warnings) or defer to user education.

Key technical details
- **Subsystems**: textconv filters, shell argument parsing, `.gitattributes` handling (precedence rules, global vs. local files), checkout process, binary file detection.
- **Triggers**:
  - Textconv: Unquoted backslashes in filter commands (e.g., `sed -e s/\r//` → `s/r//`).
  - Binary corruption: Global `.gitattributes` rules like `* text diff=lfclean` applied to all files, including binaries.
- **Symptoms**:
  - Textconv: Silent corruption of identifiers (e.g., "compareCache" → "compaeCache") in `git diff` output; repository content uncorrupted.
  - Binary corruption: Corrupted binary files (PNGs, JPEGs) during checkout; repository blobs intact. DLL files were unaffected due to lack of CR bytes, masking the issue’s scope.
- **Root causes**:
  - Textconv: Shell interprets unescaped backslashes; reproducible on Linux with identical syntax.
  - Binary corruption: `.gitattributes` precedence rules apply text filters to all files, including binaries, without safeguards.
- **Workarounds**:
  - Textconv: Quote backslashes (e.g., `sed -e "s/\\r//"`) or use `git diff --no-textconv`.
  - Binary corruption: Delete global `.gitattributes` and use local rules (e.g., `*.txt text`) or mark binaries (e.g., `*.png binary`).
- **Suggested fixes**:
  - **Documentation**: Add Windows-safe examples (e.g., `tr -d \r`, `dos2unix`) and warnings about global `*` rules in `gitattributes(5)`.
  - **Diagnostics**: Warnings for global `*` rules with `text` or textconv filters.
  - **Safeguards**: Size-mismatch warnings, built-in CR-stripping filters (e.g., `git diff --strip-cr`), or automatic binary file detection (e.g., ignore `text` for known binary extensions like `*.png`).
  - **Design**: The author proposes removing global `.gitattributes` filters entirely, though this is unlikely to be adopted.
