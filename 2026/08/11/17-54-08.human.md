This is the second patch in Justin Tobler’s nine-patch v3 series extending the ODB transaction system to make `git receive-pack` fully backend-agnostic. It introduces `odb_transaction_finalize()` and `odb_transaction_commit_and_finalize_or_die()` to decouple transaction cleanup from object visibility, enabling post-commit operations like lockfile removal.

The patch directly addresses a critical flaw in the transaction lifecycle: previously, `odb_transaction_commit()` both made objects visible and freed the transaction, leaving no room for backend-specific cleanup. The new `finalize()` interface allows backends to defer cleanup until after references are updated, which is essential for the "files" backend’s ".keep" lockfile management (handled in a later patch). The `*_or_die()` helper ensures proper cleanup on error paths for callers that cannot meaningfully recover.

Mechanically, the patch splits `odb_transaction_commit()` into two steps, adds a `finalize` callback to `struct odb_transaction`, and updates all callers to use the new helper. The changes are straightforward and well-motivated, with clear commit message rationale. This is a refactoring with no user-visible behavior change, but it’s a necessary foundation for the series’ broader goal of ODB backend abstraction.

The patch looks solid and uncontroversial. It’s part of a larger, actively reviewed effort (cooking in `seen`) and addresses all prior feedback about transaction lifecycle management. If the rest of the series holds up, this patch should merge cleanly.
