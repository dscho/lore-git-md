This is a usability-focused bugfix for `git worktree add`. The patch improves error messages when a user tries to create a worktree from a branch name that exists on multiple remotes (e.g., `git worktree add ../foo-dir bar-topic` when both `origin/bar-topic` and `upstream/bar-topic` exist). Previously, Git would fail with a generic "invalid reference" error, leaving users confused about why the command failed or how to resolve the ambiguity.

The change adds a detailed advice message that explains the problem and provides actionable guidance: users can either specify the fully qualified remote branch name (`origin/bar-topic`) or set `checkout.defaultRemote` in their Git config to prefer one remote by default. The advice is gated behind the new `advice.checkoutAmbiguousRemoteBranchName` setting, which is enabled by default. The patch also moves an existing `die()` call earlier in the code path to replace the generic error with a more specific diagnostic that clearly explains the ambiguity.
