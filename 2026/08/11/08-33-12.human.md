This is patch 10/12 in Christian Couder’s v3 series refactoring `git fast-import` to modernize its parse-options usage and prepare for libification. The patch converts a dozen command-line options from direct string/unsigned assignments to `OPT_CALLBACK` entries in the `fast_import_options` array, introducing dedicated callback functions (e.g., `option_parse_date_format`, `option_parse_max_pack_size`) that delegate to the existing helpers (e.g., `option_date_format`, `option_max_pack_size`). The callbacks are not yet invoked by `parse_options()`, so behavior remains unchanged; this is purely preparatory work for the parse-options integration in patch 11/12.

The patch touches only `builtin/fast-import.c`, adding 168 lines and removing 40. Each callback follows the same pattern: it checks for `unset` with `BUG_ON_OPT_NEG`, delegates to the existing helper, and returns 0. The `fast_import_options` array is updated to use `OPT_CALLBACK_F` for each converted option, passing the appropriate callback and adjusting the `value` field to either `NULL` or `&state` (the `struct fast_import_state` introduced in earlier patches). The changes are mechanical and well-scoped, with no new symbols beyond the callback functions themselves.

This is a solid, incremental step in the series. The commit message clearly states the purpose ("prepare for when we can use that API to also parse the options"), and the patch itself is clean and focused. No behavioral changes or edge cases are introduced here, making it a safe preparatory refactoring. The patch aligns with the series’ broader goal of standardizing `git fast-import`’s command-line parsing and eliminating global variables, and it should interest contributors working on parse-options modernization or `git fast-import` internals.
