This is the third patch in D. Ben Knoble’s three-part series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The series is under active review, with a second version expected soon.

The core change introduces a new `core.useNanosec` config key that lets users enable nanosecond precision on supported filesystems without recompiling Git, reducing "racy Git" problems. The first version of the patch introduced a severe performance regression—calling `repo_config_get_bool()` on every `is_racy_stat()` invocation slowed `git diff` by roughly 41× (854 ms vs 20 ms). The author has since benchmarked a fix that caches the value in the repository’s `repo_settings` struct, restoring performance to baseline (21 ms vs 20 ms).

The open question is architectural: where to cache the config value. Patrick Steinhardt suggests `repo_config_values()` is the modern target for config-driven settings, but it currently only works with `the_repository`. The author is now analyzing control flow to determine whether `core.useNanosec` might ever need to vary per-repository (e.g., for submodules), which would favor `repo_settings` instead. The analysis will inform the v2 implementation.

The rest of the series is uncontroversial: the first patch fixes a Meson build-system issue (`MAN_BASE_URL` configuration), and the second is a no-op refactor of `repo_config_values_init`. The series is based on `master` but conflicts textually and semantically with `ty/repo-config-cleanups` in `seen`. The author plans to move a `Best-viewed-with: --ignore-space-change` hint into the commit message body in the next version.
