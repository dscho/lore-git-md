This is a follow-up discussion from Junio C Hamano about the recently submitted patch series fixing Bash completion for `git checkout -C <dir>`. The series itself (patches 1/2 and 2/2) is already under review and addresses the core issue: restricting path completion to tracked files (those in the index) for `git checkout`, even when the `-C` option is used.

Junio now raises a nuanced edge case: when completing paths for `git checkout other-branch foo<TAB>`, the command could resurrect a file (e.g., `foolish`) that exists on `other-branch` but not in the current index. Currently, the series doesn’t handle this scenario, as it lacks machinery to complete paths from an arbitrary tree (e.g., `other-branch`). While he acknowledges this isn’t a high-priority issue—since untracked files matching such paths are unlikely to exist—he notes that the completion script doesn’t have the tools to implement this behavior cleanly.

The discussion is exploratory rather than actionable. Junio clarifies that this isn’t a request for changes to the current series but rather a note for future work, inviting others to build on the foundation once the series lands. His tone is pragmatic, emphasizing his limited expertise in the completion subsystem ("beyond my 'git-completion-fu'"). The thread doesn’t introduce new patches or objections but adds context for reviewers and potential future contributors. For now, the series remains focused and uncontroversial, with this follow-up serving as a low-priority roadmap item.
