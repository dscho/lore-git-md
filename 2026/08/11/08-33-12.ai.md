This is patch 10/12 in Christian Couder’s v3 series refactoring `git fast-import` for libification. The patch converts a dozen command-line options from direct string/unsigned assignments to `OPT_CALLBACK` entries in the `fast_import_options` array, introducing dedicated callback functions (e.g., `option_parse_date_format`, `option_parse_max_pack_size`) that delegate to the existing helpers (e.g., `option_date_format`, `option_max_pack_size`). The callbacks are not yet invoked by `parse_options()`, so behavior remains unchanged; this is purely preparatory work for the parse-options integration in patch 11/12.

The patch touches only `builtin/fast-import.c`, adding 168 lines and removing 40. Each callback follows the same pattern: it checks for the `unset` flag (using `BUG_ON_OPT_NEG`), delegates to the existing helper, and returns 0. The `fast_import_options` array is updated to use `OPT_CALLBACK_F` for each converted option, passing the appropriate callback and adjusting the `opt->value` field where needed (e.g., for options that store their result in `struct fast_import_state`). The changes are mechanical and preserve the existing behavior, but they lay the groundwork for the parse-options conversion in the next patch.

No new symbols are introduced beyond the callback functions themselves, and there are no behavior changes or on-disk format changes. The patch is a straightforward refactoring that aligns with the series’ goal of modernizing `git fast-import`’s parse-options usage and reducing global variables. It is well-motivated and uncontroversial, serving as a necessary step toward the parse-options integration in patch 11/12. Reviewers focused on parse-options modernization or `git fast-import` internals may want to pay attention to the callback implementations, though the changes are largely boilerplate.
