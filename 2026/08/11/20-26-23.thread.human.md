This thread is about a patch series (`[PATCH v2 0/4] worktree: add lifecycle hooks`) that proposes adding Git hooks triggered when worktrees are created, removed, or pruned. The series aims to let external tools like IDEs and build systems react automatically to worktree lifecycle events.

A new participant, Alexander Riccio, has shared a real-world use case: when worktrees are removed, tools like Xcode leave behind gigabytes of orphaned build cache data because they store state using absolute paths tied to the worktree location. Riccio currently uses a shell script to clean this up but can’t reliably trigger it because Git doesn’t emit events for worktree removal. They highlight how post-remove or post-prune hooks would solve this problem, making cleanup automatic and reducing manual effort.

The thread is still under review, with no maintainer decisions yet. The series is at version 2, and this report adds practical motivation but doesn’t engage with the technical implementation. Key terms like *Xcode derived data*, *absolute path build caches*, and *post-remove/post-prune hooks* are now associated with the effort.
