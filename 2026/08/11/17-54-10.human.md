This is the fourth patch in Justin Tobler’s nine-patch v3 series making `git receive-pack` fully ODB-backend-agnostic. The patch removes the static global variables `receive_unpack_limit`, `transfer_unpack_limit`, and `unpack_limit` and replaces them with a new helper, `get_unpack_limit()`, that reads the configuration lazily inside `unpack()` using `repo_config_get_uint()`.

The change is a straightforward refactoring that aligns with the series’ broader goal: since the decision to explode a packfile into loose objects is a backend-specific detail, the unpack limit should not be part of the generic ODB transaction interface. By resolving the limit lazily, the patch avoids wiring configuration values through the interface and keeps the logic where it belongs—in the backend implementation.

The patch is small (30 lines changed, 19 removed) and mechanical, touching only `builtin/receive-pack.c`. It preserves the existing behavior—defaulting to an unpack limit of 100 and respecting both `receive.unpackLimit` and `transfer.unpackLimit`—while removing the global state. This is a clean, uncontroversial step toward the series’ goal, and the change looks well-motivated and well-executed. No user-visible behavior changes or test failures are expected.
