This thread is a bug report from Tom Noonan II about `git-remote-https` failing to retry with BASIC authentication when a proxy responds with a 407 (Proxy Authentication Required) challenge, even when the proxy URL in `HTTP_PROXY` or `HTTPS_PROXY` includes embedded credentials (`http://user:pass@host`). The report demonstrates that Git’s HTTP transport layer does not automatically extract and use the username:password pair from the proxy URL, causing the connection to abort after the 407 response. The workaround—setting `GIT_HTTP_PROXY_AUTHMETHOD=basic`—forces Git to send credentials preemptively, which succeeds, suggesting the current behavior is unintended.

The email includes verbose logs showing the HTTP exchange: Git’s initial CONNECT request omits credentials, the proxy responds with a 407 and a `Proxy-Authenticate: Basic` header, and Git aborts instead of retrying with the credentials it already has. No prior discussion or patch series is referenced, so this is a standalone report. The issue affects users behind authenticated proxies who rely on the standard `user:pass@host` URL format, which other tools like `curl` handle transparently. No responses or reviews have been posted yet, so the thread is currently just the initial report.
