This is the fifth patch in the now-ready-to-merge v8 series optimizing `paint_down_to_common()` in Git’s commit-reach subsystem. The patch adds Trace2 instrumentation to expose the number of commits visited during merge-base calculations, enabling observable measurement of performance improvements.

The change is straightforward: a `steps` counter is incremented for each commit processed in `paint_down_to_common()`, and the final count is emitted via `trace2_data_intmax()`. This allows developers to quantify the impact of optimizations (like the side-exhaustion early termination in later patches) without relying on wall-clock benchmarks. The patch also updates the test suite to validate these step counts across all commit-graph modes (none, full, half, no-gdat), replacing brittle `grep`-based checks with the new `test_trace2_data_singular()` helper introduced earlier in the series.

The test expectations reflect existing variation in step counts due to the pre-existing `min_generation` optimization, which short-circuits walks when generation data is available. For example, the `in_merge_bases_many:self` test now expects 45 steps in "none" mode but only 2 in "full" mode. A new test case (`merge-base --all commit-walk steps`) explicitly validates step counts for a 10x10 commit grid, expecting 81 steps in most modes but 80 in "full" mode.

This is a well-motivated instrumentation patch with thorough test coverage. It directly supports the series’ goal of making performance improvements measurable and deterministic. The changes are minimal and focused, touching only `commit-reach.c` and `t/t6600-test-reach.sh`. No controversy or open questions remain; the patch is ready for integration.
