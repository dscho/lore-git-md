This thread is an announcement from Johannes Schindelin about a **Git for Windows security release (2.55.0(4))** addressing **CVE-2026-62960**. The vulnerability is specific to Git for Windows: when cloning from a malicious server, the server could trick Windows into disclosing the user’s NTLMv2 hash by advertising a bundle URI pointing to a network share. The fix blocks `file://` URIs by default, aligning bundle URI handling with Git’s existing protocol restrictions. This is a **high-risk issue** due to the potential for credential theft via brute-forcing the captured hash.

The release is **Windows-only**; upstream Git (the project on `git@vger.kernel.org`) is unaffected. Additionally, this release drops support for Windows 8.1, following MSYS2’s deprecation of the platform. The email provides download links for 32-bit, 64-bit, ARM64, and portable variants, along with SHA-256 checksums for verification. No further action is expected on the Git mailing list unless downstream packagers have questions. The fix is already shipped, and the CVE identifier and description make it easy for distributors to track.
