This is the second patch in a two-part series fixing Bash completion for `git checkout -C <dir>`. The series targets a usability issue where path completion for `git checkout` (with or without `-C`) would fall back to untracked files in the current directory, which is inconsistent with the command’s purpose of operating on tracked paths.

This patch implements the actual fix: when `git checkout` completion yields no matching references (or when `--` is present), it now delegates to `__git_complete_index_file()` to suggest only tracked paths. The change is minimal—just four lines added to `_git_checkout()`—but it ensures completion behaves correctly even when `git -C <path>` is used, where `$PWD` is not the target repository.

The patch also adds thorough test coverage in `t/t9902-completion.sh`, verifying that completion works for both `git checkout` and `git -C <path> checkout` when no references match, and that only tracked paths are suggested. The tests are clear and cover the edge cases mentioned in the commit message.
