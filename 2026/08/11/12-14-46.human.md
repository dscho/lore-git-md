This is a bugfix patch from Christian Couder that prevents a segfault when running `git --shallow-file` without providing a value. The issue occurs in `git.c`'s `handle_options()` function, where `--shallow-file` blindly dereferences the next argument in `argv` without checking if it exists. Other similar options (like `--git-dir`, `--namespace`, or `-C`) already include this safety check, and this patch aligns `--shallow-file` with that pattern.

The fix is small and localized: it adds a bounds check before accessing the argument, emits a clear error message if no value is provided, and reorders the code slightly to match the style of other options. The patch also includes a test in `t0041-usage.sh` to verify the new behavior. Christian notes that all existing in-tree callers of `--shallow-file` already pass a value (even if empty), so this change won’t break any existing usage.
