This is a refactoring patch (part 6 of 9) in Justin Tobler’s ODB abstraction series for `git receive-pack`. It changes how unpack errors are reported: instead of returning a static string, `unpack()` and `unpack_with_sideband()` now write error messages to a caller-provided `strbuf` and return a negative value on failure. The call sites in `cmd_receive_pack()` are updated to use the new error-reporting pattern, including the `report()` and `report_v2()` functions that format the client response.

The change is purely internal and prepares the code for the upcoming `odb_transaction_write_pack()` interface, which will move the unpack logic behind a generic ODB transaction boundary. No user-visible behavior changes; the patch is a mechanical refactor that lifts error reporting into a more flexible buffer-based design. The `strbuf` is initialized once in `cmd_receive_pack()` and released at the end of the function, avoiding any dynamic allocation overhead during the unpack phase.

Files touched: only `builtin/receive-pack.c`. Key symbols modified: `unpack()`, `unpack_with_sideband()`, `execute_commands()`, `report()`, and `report_v2()`. The patch is clean and well-contained, with no on-disk format changes or test coverage gaps. It directly addresses the feedback from earlier iterations that the error-reporting interface needed to be more flexible for backend-agnostic use.
