This is the behavior-changing patch in Christian Couder’s 12-patch series refactoring `git fast-import` to use the parse-options API. It replaces the hand-written command-line parser with `parse_options()`, completing the integration started in earlier patches.

The patch removes support for five undocumented options (`--alias`, `--get-mark`, `--ls`, `--notes`, and `--cat-blob`) on the command line, as these are only meaningful inside the input stream. A new test (`t9300-fast-import.sh`) verifies that each of these options now fails when given on the command line. The change also enables abbreviated options (e.g., `--dep=5` for `--depth=5`), space-separated values (e.g., `--depth 5`), and accepts bare `--` as an end-of-options marker, aligning with conventional `parse_options()` behavior.

The most subtle change is a known inconsistency with `--allow-unsafe-features`: the early scan for this option (needed to process in-stream "feature" lines) is stricter than `parse_options()`, rejecting abbreviations (e.g., `--allow-unsafe`) and space-separated values. This can cause the in-stream feature to be rejected even though the command-line option is accepted. The patch documents this limitation in the man page, cover letter, and code (with a `NEEDSWORK` comment), but does not fix it in this version. The author proposes deferring a general fix, leaving the inconsistency as a documented edge case.

The patch is well-motivated and clearly explained, with thorough test coverage for the new behavior. It shrinks the code by 29 lines while making the command-line interface more consistent with other Git commands. The only intentional behavior change is the rejection of undocumented options, which is a cleanup rather than a regression. The series as a whole is now ready for broader review, and this patch is the linchpin of the parse-options integration.
