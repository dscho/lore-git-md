This is a **performance feature** targeting Linux filesystems that support copy-on-write reflinks (e.g., Btrfs, XFS, ZFS). The patch teaches Git to attempt a reflink-based copy before falling back to hardlinks or byte-for-byte copying, both for generic file copies (`copy_file()`) and local clones. Reflinks share storage without the inode aliasing drawbacks of hardlinks, making them ideal for object files where independent modification is rare but space efficiency matters.

The implementation is Linux-specific, using the `FICLONE` ioctl. It treats reflinking as an optimization: if the ioctl fails (whether due to lack of support or transient errors), Git removes the partial destination and falls back to the existing copy path. The patch also preserves source timestamps when reflinking, matching the behavior of hardlinks and byte copies, which is important for `prune` and `gc` decisions.

Testing is thorough. The patch adds an LD_PRELOAD-based test helper (`test-fake-reflink.c`) that can simulate reflink success, unsupported operation, or other errors, allowing the test suite to exercise all code paths even on filesystems without reflink support. A new test script (`t0094-reflink.sh`) covers generic file copying, local clones, `--no-hardlinks`, hardlink fallback, byte-copy fallback, object integrity, and timestamp preservation. The author reports that the focused tests pass on ZFS, ext4, and tmpfs, and the full test suite passes on all three.

The patch touches 12 files, including the core `copy.c` and `clone.c` logic, test infrastructure, and documentation. It introduces three new functions: `copy_file_reflink()`, `copy_file_reflink_with_time()`, and a helper `finish_copy()`. The fallback order is now reflink → hardlink (unless `--no-hardlinks`) → byte copy. The patch is well-motivated, well-tested, and clearly written, with no obvious red flags. It should be uncontroversial for Linux users and invisible to other platforms.
