This is the seventh patch in Justin Tobler’s nine-patch v3 series extending ODB transactions to `git receive-pack`. It prepares the `unpack()` function for backend-agnostic use by replacing its implicit reliance on stdin with an explicit file descriptor parameter for the incoming packfile.

The change is mechanical: `unpack()` and its helper `parse_pack_header()` now take an `int pack_fd` argument, and callers (`unpack_with_sideband()` and the direct invocation in `cmd_receive-pack()`) pass `0` (stdin) to preserve the existing behavior. The patch updates the child-process setup in `unpack()` to wire the new `pack_fd` to the spawned `git index-pack` or `git unpack-objects` command. No user-visible behavior changes; the goal is purely to lift the hardcoded stdin assumption so the logic can later be moved behind the new `odb_transaction_write_pack()` interface.

The patch touches only `builtin/receive-pack.c` and is a straightforward refactor with no new symbols or on-disk format changes. It builds directly on the `unpack_opts` struct introduced in patch 5/9 and the `strbuf`-based error reporting from patch 6/9, completing the groundwork for the backend-agnostic transaction interface that lands in patch 8/9. The file-descriptor passing remains part of the interface; reviewers may still evaluate its ergonomics, but the change itself is uncontroversial and aligns with the series’ broader pattern of making implicit state explicit.
