This is the third patch in the v8 series optimizing `paint_down_to_common()` for one-sided histories. It adds test coverage for edge cases in the side-exhaustion optimization to `t6600-test-reach.sh`.

The patch introduces four new test cases that exercise specific scenarios in the merge-base walk:
- `in_merge_bases_many:self` – a commit is both the query and one of the inputs.
- `get_merge_bases_many:duplicate-twos` – duplicate entries in the input list.
- `get_merge_bases_many:pending-stale` – a STALE transition on an already-painted commit (tested via a diamond topology where a merge-base candidate is a descendant of another).
- `get_merge_bases_many:infinity-both-sides` – both tips outside the commit-graph with non-monotonic dates (tested via a topology with skewed timestamps to force commit-date fallback).

The setup section constructs two new test topologies:
- A diamond-shaped `ps-*` topology (`ps-X`, `ps-Z`, `ps-B`, `ps-W`, `ps-T1`, `ps-T2`) to trigger the (PARENT1|PARENT2) → (PARENT1|PARENT2|STALE) transition.
- A `pi-*` topology (`pi-X`, `pi-B`, `pi-C`, `pi-D`, `pi-P`) with non-monotonic dates to exercise the INFINITY-gate when both tips are outside the commit-graph.

The tests validate that the side-exhaustion optimization does not fire prematurely in these edge cases and that the correct merge-bases are returned. The patch is part of a fully reviewed, ready-to-merge series that has already addressed all substantive feedback. No new technical concerns are introduced here—this is purely test coverage for scenarios not exercised by the existing 10x10 grid topology. The test names and comments clearly document the intent and expected behavior.
