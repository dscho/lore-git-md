This is the first patch in Justin Tobler’s nine-patch v3 series making `git receive-pack` fully ODB-agnostic. It fixes a critical bug introduced in the ODB transaction transition (bdee7b3013): when `receive-pack` switched to using ODB transactions, the reordering of the ODB sources list caused `.keep` lockfiles to be written to the temporary quarantine directory instead of the main object store, so they were never cleaned up after the transaction committed.

The patch changes `index_pack_lockfile()` to take an explicit `odb_source` parameter instead of a `repository`, and updates the call site in `receive-pack` to pass the transaction’s source (the quarantine directory) while still deriving the lockfile path from the **main** ODB source. This ensures the `.keep` file is created in the quarantine directory but named for its eventual location in the main object store, so it can be found and removed after the transaction commits. A new test (`t5547-push-quarantine.sh`) verifies that `.keep` files are properly cleaned up after a push.

The fix is narrow, well-motivated, and directly addresses a real correctness issue. The commit message clearly explains the root cause and the solution, and the test coverage is appropriate. This patch is a prerequisite for the rest of the series and looks ready to merge.
