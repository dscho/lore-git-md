This is the final patch in Justin Tobler’s nine-patch v3 series that completes the ODB abstraction for `git receive-pack`. It introduces `odb_transaction_write_pack()`, a generic interface for writing incoming packfiles to an ODB transaction, and moves the existing `unpack()` logic from `builtin/receive-pack.c` into the "files" backend implementation in `object-file.c`.

The patch deletes 157 lines from `receive-pack.c`, replacing the hardcoded `unpack()` function with a call to `odb_transaction_write_pack()`. The new interface is backend-agnostic: the "files" backend spawns `git index-pack` or `git unpack-objects` as before, but alternative backends (e.g., reftable, cloud storage) can now implement their own logic. The "files" backend also manages ".keep" lockfiles, removing them post-commit via the finalize callback added in an earlier patch.

Key symbols introduced: `odb_transaction_write_pack()`, `struct odb_transaction_write_pack_opts`, and the `write_pack` callback in `struct odb_transaction`. The `odb_transaction_write_pack_opts` struct consolidates all previously implicit state (fsck settings, shallow file path, input size limits, error file descriptor, quiet flag, and thin-pack rejection) into an explicit options struct, aligning with the series’ goal of eliminating global state.

No user-visible behavior changes; the series remains a refactor to enable pluggable ODB backends. The patch is well-motivated, thoroughly tested (including a new test in `t/t5547-push-quarantine.sh` for lockfile lifecycle), and addresses all feedback from v2. With all critical design flaws resolved, this iteration looks ready for merging.
