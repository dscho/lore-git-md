**Core problem or goal**
Fix Bash completion for `git checkout` (with or without `-C <dir>`) to prioritize tracked paths (those in the index) over untracked ones, while adding a fallback to untracked paths as a last resort. The series builds on the earlier `git diff` completion fix and addresses a usability gap where completion previously suggested untracked files inconsistently. Junio clarified in v1 that `__git_complete_index_file` must be called with the `--cached` option (or its equivalent `""`) to strictly enforce tracked-path completion, ensuring untracked files are excluded by default. The v3 series retains the pragmatic fallback to untracked paths when no tracked paths match, now updated to include `--directory` in the `__git_complete_index_file "--others"` call for consistency with the `git diff` completion series and performance benefits. The discussion also clarified that Zsh completion support for `git show <tree>:<path>` is not reusable for `git checkout <treeish> <path>` due to differing semantics and completion requirements.

**Current status**
Technically complete and ready for integration. Junio's "What's cooking" report has not yet mentioned this series, so it remains under review in `seen` (not yet in `next` or `master`). The series consists of three patches:
1. Patch 1/3 is a no-op refactoring of `_git_checkout()` in `contrib/completion/git-completion.bash`, restructuring the control flow to avoid an early return when `--` is detected. The logic is now wrapped in an `if ! __git_has_doubledash` block with explicit `return` statements in each completion branch (option arguments, `--conflict=*`, and `--*` flags). This prepares the ground for patch 2/3’s functional changes without altering behavior.
2. Patch 2/3 modifies `_git_checkout()` to call `__git_complete_index_file ""` when revision reference completion yields no matches (or when `--` is present), ensuring tracked paths are prioritized. The change is minimal—four lines added—but fixes the core issue: previously, if no revision matched the input (e.g., `git checkout f`), Bash would fall back to completing untracked files in `$PWD`, which was especially problematic with `git -C <path>`. Test coverage adds two new tests to `t/t9902-completion.sh`:
   - Verifies `git checkout f` (and `git checkout -- f`) completes only tracked paths (`file1`, `file2`) when no refs match "f", ignoring untracked files.
   - Confirms `git -C <path> checkout o` completes tracked paths in the specified repository (e.g., `otherfile`), not the current directory, and handles edge cases like missing files (`lostfile`).
3. Patch 3/3 adds the fallback to untracked paths via `__git_complete_index_file "--others --directory"` when no tracked paths match, aligning with the `git diff` completion series and addressing Elijah Newren’s consistency concern. The fallback is pragmatic: while untracked paths are unlikely to be useful for `git checkout` (since they don’t exist in the index), it prevents completion from failing silently or defaulting to arbitrary files in `$PWD`. Test coverage adds two new tests:
   - Verifies `git checkout u` (and `git checkout -- u`) completes untracked files (`ufile`) when no tracked paths or refs match.
   - Extends the existing `-C <path> checkout` test to include untracked files (`ufile`) alongside tracked and missing files, ensuring the fallback works consistently across directories.
The series is rebased onto the `complete-diff` topic for better test organization and is uncontroversial. All patches are ready for integration.

**Key technical details**

- New behavior:
