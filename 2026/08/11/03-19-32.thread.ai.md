**Key technical details**
- Files touched: `contrib/completion/git-completion.bash`, `t/t9902-completion.sh`
- Subsystem: Bash completion
- New behavior: `git checkout -C <dir>` path completion now restricts suggestions to tracked paths only, even when no revision matches the input. This applies both to the current directory and to paths specified with `-C`. The fix explicitly uses `__git_complete_index_file --cached` to exclude untracked files.
- Old behavior: Previously fell back to untracked paths in `$PWD`, inconsistent with `git checkout`'s purpose of operating on repository files.
- Test coverage: Two new tests in `t/t9902-completion.sh` verify the fix:
  1. `git checkout f` (no refs matching "f") completes only tracked paths (`file1`, `file2`), ignoring untracked files.
  2. `git -C <path> checkout o` completes tracked paths in the specified repository, not the current directory.
- Refactoring details: Patch 1/2 reorganizes `_git_checkout()` to avoid an early return when `--` is detected, wrapping existing logic in an `if ! __git_has_doubledash` block and adding explicit `return` statements to each completion branch. Patch 2/2 modifies the function to call `__git_complete_index_file --cached` when revision reference completion yields no matches (or when `--` is present), ensuring tracked paths are offered as candidates.
- Completion semantics: Junio’s follow-up clarified that Zsh’s support for `git show <tree>:<path>` completion (e.g., `git show other-branch:foolish`) is not reusable for `git checkout <treeish> <path>` because the latter requires completing paths that exist in the target tree but may not be present in the working tree or index. This distinction underscores the need for new completion machinery (e.g., `git ls-tree`-based helpers) to support such cases, which is beyond the scope of the current series.
