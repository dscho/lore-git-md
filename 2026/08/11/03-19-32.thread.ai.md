Subject: [PATCH 0/2] bash completion: fix `git checkout -C <dir>` path completion
Series version: v1 (initial submission)
Originating author: Junio C Hamano
Thread type: patch series

Core problem or goal
Fix Bash completion for `git checkout -C <dir>` to only suggest tracked paths (those in the index) rather than falling back to untracked paths. The series also includes a preparatory refactoring to simplify the logic before applying the fix. Junio has since noted a potential future enhancement: completing paths that exist in a target branch but are untracked in the working tree (e.g., `git checkout other-branch <path>`), though this is not implemented due to lack of existing completion machinery for arbitrary trees.

Current status
Under review. Two patches: 1/2 refactors the completion logic (no functional change), 2/2 implements the fix and adds test coverage in `t/t9902-completion.sh`. The functional change in 2/2 is fully described, with test cases verifying the new behavior. No changes to the patches are proposed in the follow-up discussion.

Key technical details
- Files touched: `contrib/completion/git-completion.bash`, `t/t9902-completion.sh`
- Subsystem: Bash completion
- New behavior: `git checkout -C <dir>` path completion now restricts suggestions to tracked paths only, even when no revision matches the input. This applies both to the current directory and to paths specified with `-C`.
- Old behavior: Previously fell back to untracked paths in `$PWD`, inconsistent with `git checkout`'s purpose of operating on repository files.
- Test coverage: Two new tests in `t/t9902-completion.sh` verify the fix:
  1. `git checkout f` (no refs matching "f") completes only tracked paths (`file1`, `file2`), ignoring untracked files.
  2. `git -C <path> checkout o` completes tracked paths in the specified repository, not the current directory.
- Refactoring details: Patch 1/2 reorganizes `_git_checkout()` to avoid an early return when `--` is detected, wrapping existing logic in an `if ! __git_has_doubledash` block and adding explicit `return` statements to each completion branch. Patch 2/2 modifies the function to call `__git_complete_index_file()` when revision reference completion yields no matches (or when `--` is present), ensuring tracked paths are offered as candidates.
- Future enhancement context: Junio identified a theoretical edge case where completing paths from a target branch (e.g., `other-branch:foolish`) might be useful, but this would require new completion helpers (e.g., `git ls-tree`-based) and is not implemented in the current series.
