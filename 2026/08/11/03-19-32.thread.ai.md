**Core problem or goal**
Fix Bash completion for `git checkout` (with or without `-C <dir>`) to prioritize tracked paths (those in the index) over untracked ones, while adding a fallback to untracked paths as a last resort. The series builds on the earlier `git diff` completion fix and addresses a usability gap where completion previously suggested untracked files inconsistently. Junio clarified in v1 that `__git_complete_index_file` must be called with the `--cached` option (or its equivalent `""`) to strictly enforce tracked-path completion, ensuring untracked files are excluded by default. The v3 series retains the pragmatic fallback to untracked paths when no tracked paths match, now updated to include `--directory` in the `__git_complete_index_file "--others"` call for consistency with the `git diff` completion series and performance benefits. The discussion also clarified that Zsh completion support for `git show <tree>:<path>` is not reusable for `git checkout <treeish> <path>` due to differing semantics and completion requirements.

**Key technical details**
- Files touched: `contrib/completion/git-completion.bash`, `t/t9902-completion.sh`
- Subsystem: Bash completion
- New behavior:
  - `git checkout <path>` (with or without `-C <dir>`) now completes only tracked paths by default, using `__git_complete_index_file ""` to exclude untracked files.
  - If no tracked paths match, the completion falls back to untracked paths via `__git_complete_index_file "--others --directory"` (patch 3/3), ensuring completion never fails silently. This fallback is unlikely to be useful for typical `git checkout` workflows but serves as a pragmatic last resort.
  - The fix applies consistently whether the input includes a revision or not (e.g., `git checkout f` vs. `git checkout main f`).
- Old behavior: Previously fell back to untracked paths in `$PWD` when no revision matched the input, inconsistent with `git checkout`'s purpose of operating on repository files.
- Test coverage: Eight new tests in `t/t9902-completion.sh` verify:
  1. Patch 1/3’s refactoring preserves existing behavior (no functional change).
  2. Patch 2/3’s tracked-path-only logic works for `git checkout f` (no refs matching "f"), completing only tracked paths (`file1`, `file2`) and ignoring untracked files.
  3. Patch 2/3 works with `-C <path> checkout o`, completing tracked paths in the specified repository, not the current directory.
  4. Edge cases like missing files (`lostfile`) are handled correctly.
  5. Patch 3/3’s fallback to untracked paths works when no tracked paths match (e.g., `git checkout u` completes `ufile`).
  6. The fallback works consistently with `--` and `-C <dir>`.
  7. The existing test for `-C <path> checkout` is updated to include untracked files (`ufile`) and verify their completion alongside tracked and missing files.
  8. All tests cover both the happy path and edge cases (e.g., missing files).
- Refactoring details: Patch 1/3 reorganizes `_git_checkout()` to avoid an early return when `--` is detected, wrapping existing logic in an `if ! __git_has_doubledash` block and adding explicit `return` statements to each completion branch. Patch 2/3 modifies the function to call `__git_complete_index_file ""` when revision reference completion yields no matches (or when `--` is present), ensuring tracked paths are prioritized. Patch 3/3 adds the fallback to untracked paths as a last resort, now including `--directory` for consistency and performance.
- Completion semantics: Junio’s follow-up in v1 clarified that Zsh’s support for `git show <tree>:<path>` completion (e.g., `git show other-branch:foolish`) is not reusable for `git checkout <treeish> <path>` because the latter requires completing paths that exist in the target tree but may not be present in the working tree or index. This distinction underscores the need for new completion machinery (e.g., `git ls-tree`-based helpers) to support such cases, which remains out of scope for this series.
