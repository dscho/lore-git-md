This thread is a patch series from Junio C Hamano fixing Bash completion for `git checkout` when used with the `-C <dir>` option. The goal is to make path completion prioritize tracked files (those already in the repository) over untracked ones, while adding a fallback to untracked paths if no tracked files match. The series is now in its second version with three patches: the first refactors the completion logic without changing behavior, the second implements the core fix (tracked paths only), and the third adds the fallback to untracked paths.

The key change is that `git checkout <path>` (with or without `-C <dir>`) now completes only tracked paths by default, using `__git_complete_index_file ""` to exclude untracked files. If no tracked paths match, the completion falls back to untracked paths in the target directory. This makes the behavior more consistent with `git checkout`'s purpose of operating on repository files, rather than suggesting untracked files from the current directory. The series includes thorough test coverage, verifying edge cases like missing files and the new fallback behavior.

Junio refined the series in response to earlier feedback, clarifying the use of `--cached` (or its equivalent `""`) to enforce tracked-path completion and adding the pragmatic fallback in the final patch. D. Ben Knoble reviewed the first version but only offered surface-level feedback, so the series remains uncontroversial. No open questions or objections remain, and the patches appear ready for integration. The work builds on an earlier fix for `git diff` completion and is rebased onto the `complete-diff` topic for better test organization.
