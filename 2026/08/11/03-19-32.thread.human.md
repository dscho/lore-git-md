This thread fixes a long-standing usability gap in Git's Bash completion for `git checkout`. When you type `git checkout` followed by a partial path (like `git checkout f`), the completion now prioritizes tracked files—those already in Git's index—over untracked ones, making it consistent with how `git checkout` actually works. If no tracked files match, it falls back to untracked files as a last resort, matching the behavior already established for `git diff`.

Junio C Hamano sent the series, which went through three versions. The first two patches refactor the completion logic and implement the core fix, while the third adds the untracked-file fallback. Elijah Newren reviewed the changes, initially pointing out a minor inconsistency with the `git diff` completion code; Junio addressed this in the final version, and Elijah confirmed the series is now ready. The tests cover edge cases like missing files and the `-C <dir>` option, ensuring the fix works reliably.

The series is uncontroversial and technically complete. It’s a small but practical improvement that removes a common source of confusion—previously, completion would suggest untracked files in your current directory even when they weren’t relevant to the checkout. No further changes are expected, and the patches are ready to be merged.
