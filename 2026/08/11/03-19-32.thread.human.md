This thread is a small but practical fix to Git’s Bash completion for `git checkout -C <dir>`. Junio C Hamano sent a two-patch series that ensures path completion for this command only suggests tracked files (those in the index), rather than falling back to untracked files in the current directory. The first patch refactors the completion logic without changing behavior, and the second implements the fix with test coverage.

The series is under review and appears uncontroversial. Junio himself noted a potential future enhancement—completing paths from other branches (like `other-branch:foolish`)—but this isn’t part of the current patches, as the necessary completion machinery doesn’t yet exist. D. Ben Knoble briefly reviewed the second patch, calling it "reasonable" but without engaging deeply with the technical details or testing. A follow-up from Ben Knoble speculated that Zsh completion might already handle similar cases (like `git show <tree>:<path>`), but this was just a hint for future work, not a critique or request for changes. The series itself remains focused and ready for integration.
