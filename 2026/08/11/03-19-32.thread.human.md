This thread is a small but practical fix to Git's Bash completion. Junio C Hamano sent a two-patch series to correct how `git checkout -C <dir>` completes paths. The issue: when you type `git checkout -C some/dir f` and press Tab, Git was suggesting untracked files in your current directory instead of only tracked files in the target repository. The fix restricts suggestions to tracked paths, which matches the command's purpose.

The first patch refactored the completion logic to make the fix cleaner, and the second patch (just summarized) implements the actual change. Tests in `t/t9902-completion.sh` now verify that completion works correctly both with and without the `-C` option. The series is self-contained, follows a similar fix for `git diff`, and looks ready to merge—no objections or open questions have surfaced yet. If you use Bash completion with `git checkout`, this will make your life slightly easier.
