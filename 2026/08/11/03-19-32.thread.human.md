This thread is about a small but useful fix to Git’s Bash completion: when you type `git checkout -C <dir> <path>` and ask for tab completion, it now suggests only tracked files (those in the index) rather than falling back to untracked files in your working directory. The fix comes in two patches—one refactoring the completion logic, the other implementing the change and adding tests—and is currently under review.

Junio Hamano, the maintainer and author of the series, has since raised a subtle edge case: should completion for `git checkout other-branch <path>` also suggest files that exist in `other-branch` but aren’t currently in your index or working tree? He acknowledges this would be handy in rare cases (like resurrecting a deleted file from another branch) but notes the completion script lacks the machinery to implement it cleanly—it can’t easily list files from an arbitrary tree. While he invites others to explore this enhancement, he’s clear that the current fix is already a solid improvement and doesn’t block the series.

No objections or requests for changes have surfaced yet, and the patches remain as originally posted. The discussion is purely exploratory, leaving the door open for future work without complicating the immediate fix.
