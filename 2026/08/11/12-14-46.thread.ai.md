Thread identity: Bugfix patch series (single patch) addressing a segmentation fault in Git's command-line option parsing when `git --shallow-file` is invoked without a required argument. Originating author: Christian Couder.

Core problem or goal: Prevent a NULL dereference crash in `git.c`'s option parsing logic for the `--shallow-file` option, which currently lacks validation that a value was provided before dereferencing `argv`. The fix adds the missing validation and aligns the logic with other similar options (`--git-dir`, `--namespace`, `-C`).

Current status: Under review. The patch is a minimal, defensive fix with no known downsides and includes a new test in `t/t0041-usage.sh` to verify the error message and usage output when `--shallow-file` is called without a value. CI tests pass. Junio C Hamano's review raised procedural concerns about the patch's scope (mixing a defensive fix with a stylistic reordering) and the completeness of the test coverage (not all similar options are tested). Patrick Steinhardt now adds a **medium-weight** stylistic suggestion: condensing the two-line error message and `usage()` call into a single line, arguing the usage string adds little value and may distract users. The patch remains ready for merging, but the discussion now includes this additional stylistic point alongside the prior procedural questions.
