This is the fifth patch in Justin Tobler’s nine-patch v3 series extending ODB transactions to `git receive-pack`. It refactors the `unpack()` function to eliminate its reliance on global variables by introducing a `struct unpack_opts` that explicitly passes all previously implicit state (fsck settings, shallow file path, input size limits, error file descriptor, quiet flag, and thin-pack rejection).

The patch is a mechanical but necessary step toward the series’ goal of making `receive-pack` backend-agnostic. By lifting the global state into an explicit options struct, the `unpack()` logic becomes reusable behind the new `odb_transaction_write_pack()` interface introduced later in the series. The change touches only `builtin/receive-pack.c` and is straightforward: the new `unpack_opts` struct mirrors the globals it replaces, and the `unpack()` and `unpack_with_sideband()` call sites are updated to populate and pass the struct. The ternary initialization of `fsck_objects` and late assignment of `err_fd` in `unpack_with_sideband()` are preserved as trade-offs for removing global state.

This patch is well-motivated and uncontroversial. It addresses a specific reviewer concern from v2 (global state removal) and aligns with Git’s broader pattern of avoiding static variables in favor of explicit repository state. The refactoring is clean and does not change behavior, making it a safe precursor to the more invasive ODB transaction changes that follow. The only loose end is the struct initialization pattern, which remains a minor ergonomic trade-off for the sake of clarity and testability.
