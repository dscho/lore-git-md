This is the third iteration (v3) of Justin Tobler’s nine-patch series that completes the ODB abstraction for `git receive-pack` by introducing a generic `odb_transaction_write_pack()` interface. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt and builds on prior work (bdee7b3013) that staged incoming objects via ODB transactions.

The core goal remains unchanged: replace `git receive-pack`'s hardcoded use of `git index-pack` and `git unpack-objects` (which assume the "files" backend) with a backend-agnostic transaction interface, enabling alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles. This iteration addresses all feedback from v2, including a critical bug where ".keep" lockfiles were not being removed, and adds explicit error handling at transaction commit and finalize call sites. The series now also stops caching the unpack limit configuration, begins tracking the ODB source explicitly to avoid relying on source list ordering, and introduces `odb_transaction_commit_and_finalize_or_die()` to ensure proper cleanup.

Key changes since v2:
- Patch 1/9 fixes the ".keep" lockfile cleanup bug by ensuring the lockfile paths remain valid post-commit.
- Patch 2/9 introduces `odb_transaction_finalize()` and `odb_transaction_commit_and_finalize_or_die()` to enforce proper transaction lifecycle management.
- Patch 4/9 removes the static caching of the unpack limit, adopting a non-caching `unsigned int` version that reads the configuration directly.
- Patch 8/9 adds explicit ODB source tracking to avoid fragile reliance on source list ordering.
- The "files" backend now properly manages ".keep" lockfiles, removing them post-commit via the finalize callback.

The series touches `builtin/receive-pack.c`, `odb/transaction.c`, `object-file.c`, and related headers, with mechanical updates to other builtins for transaction API consistency. The new `odb_transaction_write_pack()` interface is designed to be backend-agnostic, with the "files" backend implementation handling the packfile ingestion logic previously embedded in `receive-pack`. The transaction lifecycle is now more robust, with explicit error handling and cleanup, and the unpack limit is resolved lazily in the backend rather than being wired through the interface.

This iteration appears well-prepared for merging, with all critical design flaws addressed and the interface refined based on reviewer feedback. The series is a significant step toward making `git receive-pack` fully ODB-agnostic, aligning with the broader ODB abstraction effort.
