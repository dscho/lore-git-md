This is patch 0/12 (the cover letter) of v3 of a refactoring and libification series for `git fast-import`. The series standardizes the command's usage string to match its SYNOPSIS documentation, modernizes its parse-options API usage, and begins removing global variables by introducing `struct fast_import_state`. The ultimate goal is full libification, though many globals remain for future work.

The v3 iteration addresses all feedback from Junio C Hamano and Elijah Newren. Key improvements include rewording the `PARSE_OPT_LASTARG_DEFAULT` documentation for clarity, reformatting overly long function signatures to comply with Git's 80-character line limit, and explicitly documenting three behavioral changes introduced by the switch to `parse_options()`: space-separated values for options (e.g., `--depth 5`), acceptance of bare `--` as an end-of-options marker, and a known inconsistency with `--allow-unsafe-features`. The inconsistency arises because the early scan for `--allow-unsafe-features` (needed to process in-stream "feature" lines) is stricter than `parse_options()` itself, rejecting abbreviations (e.g., `--allow-unsafe`) and space-separated values. This is now documented as a limitation in both the commit message and man page, with a `NEEDSWORK` comment in the code proposing a future fix.

The series is well-structured and incremental, with patches 1-10/12 serving as mechanical preparatory work (e.g., introducing `OPT_HIDDEN_GROUP`, factoring out option-parsing helpers, and encapsulating globals) and patches 11-12/12 completing the parse-options integration. The only intentional behavior change is the rejection of undocumented options (`--alias`, `--get-mark`, `--ls`, `--notes`, `--cat-blob`) on the command line, as these are meant for in-stream use only. CI tests pass except for a likely unrelated Windows+Meson failure. The series touches `parse-options.h`, `parse-options.c`, `builtin/fast-import.c`, and related documentation and tests, with no on-disk format changes.

The work is clearly motivated and aligns with broader Git-wide efforts to modernize parse-options usage and reduce global variables. The author has incorporated all feedback and documented the remaining edge case, making this version ready for broader review. The series is a solid step toward libification and should interest contributors working on parse-options modernization or `git fast-import` internals.
