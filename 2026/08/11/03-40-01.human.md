This is a review reply in an ongoing bug report thread about silent corruption in `git diff` output on Windows due to a misconfigured textconv filter. Jeff King (Peff) responds to Skybuck Flying’s detailed investigation, which isolated the issue to Git’s textconv pipeline on Windows.

Peff confirms the root cause: the unquoted `\r` in the `sed` command is interpreted by the shell as a literal `r`, causing `sed` to strip all `r` characters instead of carriage returns. He notes this would happen on Linux as well, not just Windows, and calls it a user misconfiguration rather than a Git bug. While he acknowledges the issue is already explained in Skybuck’s later text, he does not engage with the broader usability concerns—such as silent corruption, lack of diagnostics, or Windows-specific documentation gaps—that the original report raised.
