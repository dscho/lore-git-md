This is a review exchange on the first patch in Patrick Steinhardt’s four-part series to remove lazy-loading of alternate object databases. The patch decouples path comparisons for alternate ODB sources from `the_repository` to fix inconsistent case-sensitivity handling when alternates are registered before repository configuration is parsed.

Justin Tobler’s review is substantive but narrowly focused. He asks clarifying questions about whether alternates are currently registered before repository configuration is parsed (Patrick confirms this is an existing edge case, not a new bug) and confirms his understanding of the hash function choice (`strihash()` is safe even for case-sensitive comparisons because the equality function still distinguishes cases). He also notes the added complexity is debatable but reasonable given the performance concerns for repositories with thousands of alternates. The review walks through the code changes in detail, verifying the logic for path comparisons, hashmap initialization, and alternate registration, but does not identify any functional issues or suggest changes. His feedback is constructive and confirms the patch’s correctness without raising objections.

The patch itself is a refactoring with no intended user-visible changes, but it introduces new complexity to handle case-sensitivity correctly. It touches `odb.c`, `odb.h`, and `odb/source.h`, replacing khash with `struct hashmap` to allow dynamic comparison functions. The series as a whole aims to simplify the ODB codebase by centralizing alternate initialization, and this patch is a prerequisite for that goal. The review suggests the patch is well-motivated and mechanically sound, though the added complexity may warrant scrutiny during broader review. No performance regressions or edge-case issues are flagged.
