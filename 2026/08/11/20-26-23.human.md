This is a user report adding a concrete real-world motivation for the ongoing `worktree: add lifecycle hooks` series.

Alexander Riccio describes a pain point that arises when using many Git worktrees in an "agentic development" workflow (automated tooling creating and removing worktrees). On macOS, Xcode and other build tools store large amounts of derived data keyed by the worktree's absolute path. When a worktree is removed—either manually or by `git worktree remove`/`prune`—this data is left behind, consuming gigabytes of disk space and requiring manual or scripted cleanup. Because third-party tools do not emit events when Git removes a worktree, there is no reliable way to trigger cleanup automatically without native Git hooks.

The email does not propose code or review patches; it simply provides a vivid, quantified example of why worktree lifecycle hooks would be valuable. The scenario is plausible and likely to resonate with developers who use worktrees at scale, especially on macOS. It strengthens the case for the series by showing a clear, unmet need in the wild.
