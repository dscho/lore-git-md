Core problem or goal
Add Git worktree lifecycle hooks—specifically post-create, post-move, post-remove, and post-prune events—so that external tools (build systems, IDEs, CI agents) can register automated cleanup or state-synchronization actions when worktrees are created, moved, or removed.

Current status
Under review; v2 of the series is the latest posted version. No merge to any integration branch yet.

Key technical details
- New hook names: `post-create`, `post-move`, `post-remove`, `post-prune`
- Hooks are invoked by the existing `git worktree` command after the corresponding operation completes
- No on-disk format changes; hooks are configured via Git config keys (e.g., `hook.worktreePostRemove.command`)
- Test coverage added in `t/t2405-worktree-hooks.sh`

Open questions and loose ends
- Whether the hook set is complete (e.g., should there be a pre-remove hook?)
- Whether hook invocations should be synchronous or asynchronous
- Whether hook failures should block the worktree operation
- How to handle hook configuration inheritance (worktree vs. repository config)

Participant positions
- Adrian Ratiu (author): proposed the series; position is that the current hook set is sufficient for the stated use cases.
- Alexander G. Riccio (new participant): provided a real-world use case (Xcode-derived data and other build caches left behind after worktree removal) that directly motivates post-remove and post-prune hooks; no implementation feedback.
