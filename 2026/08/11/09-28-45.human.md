This is the third patch in the v8 series optimizing `paint_down_to_common()` for one-sided histories. It adds test cases to `t6600-test-reach.sh` that exercise edge cases in the side-exhaustion optimization, ensuring the algorithm handles unusual but valid commit topologies correctly.

The patch introduces four new test scenarios: a commit that is both the query and one of the inputs (`self`), duplicate entries in the input list (`duplicate-twos`), a STALE transition on an already-painted commit (`pending-stale`), and a case where both tips are outside the commit-graph with non-monotonic dates (`infinity-both-sides`). Each test builds a small, targeted commit topology (e.g., a diamond-shaped graph for `pending-stale` or a non-monotonic date chain for `infinity-both-sides`) and verifies the merge-base results match expectations across all commit-graph modes (none, full, half, no-gdat).

The test setup is thorough, with ASCII diagrams in the comments explaining the commit relationships and why each topology triggers the edge case. For example, the `pending-stale` test uses a diamond topology where a commit transitions to STALE after being painted, while the `infinity-both-sides` test forces a fallback to commit-date ordering due to missing generation numbers. These tests directly validate the invariants and termination conditions described in the series' new technical document (`paint-down-to-common.adoc`).
