This thread is about a security feature patch that adds `http.sslVerifyStatus`, a new Git configuration option to enable OCSP staple validation for HTTPS connections. The patch, now in its second version with a third pending, aims to close a security gap where Git accepts revoked certificates when linked against OpenSSL (which ignores OCSP staples by default), while GnuTLS-linked builds enforce them. The author, Grayson Gordon, has proposed the feature as opt-in (`http.sslVerifyStatus=false` by default) to avoid breaking existing setups, but this design has faced skepticism about its practical value.

The discussion took a decisive turn with Grayson’s latest response, which provides concrete motivation for the patch. The feature targets government and government-adjacent users—particularly those using US Department of Defense PKI certificates, where OCSP stapling is mandatory. These users frequently encounter Git servers with stapled responses, and the current behavior (OpenSSL-linked Git binaries silently ignoring staples) creates a security risk where revoked certificates could be accepted, enabling server impersonation and data exfiltration. The response also highlights a real-world deployment context: GitLab’s Helm charts default to OpenSSL on UBI-based images (a FIPS compliance requirement), leaving these users exposed unless they can opt into fail-closed validation. This shifts the debate from theoretical concerns to operational realities, addressing Patrick Steinhardt’s earlier challenge about the feature’s value.

The patch itself is technically straightforward: it adds a boolean config key (`http.sslVerifyStatus`) with per-URL overrides, leverages libcurl’s `CURLOPT_SSL_VERIFYSTATUS` (already supported by Git’s minimum libcurl version), and includes a test script (though a numbering conflict will be resolved in the next version). Junio C Hamano’s feedback has been procedural (e.g., test numbering), while Patrick’s critique focused on the feature’s limited scope (disabled by default, no backend unification) and declining relevance of OCSP stapling. Grayson’s response counters this by framing the patch as a targeted solution for a specific audience, though questions remain about whether this justifies long-term maintenance or if the default should eventually flip to `true`. The thread is now poised for follow-up on whether this use case is sufficient for merging.
