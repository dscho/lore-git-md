This thread is about a security feature patch that adds `http.sslVerifyStatus`, a boolean configuration option (defaulting to `false`) to enable OCSP staple validation in Git’s HTTPS certificate verification. The patch was introduced by graysongordon-gl to address a security gap where Git, when linked with OpenSSL, ignores OCSP staples, leaving it vulnerable to accepting revoked certificates—a concern for government and FIPS-compliant deployments (e.g., US Department of Defense PKI).

The patch has been accepted by Junio C Hamano and is queued for integration, with all procedural feedback resolved in the v4 iteration. However, Patrick Steinhardt’s latest review raises three unresolved technical and documentation concerns. First, the man page’s description of GnuTLS behavior is outdated, as recent versions now handle OCSP stapling identically to OpenSSL. Second, the error message when `CURLOPT_SSL_VERIFYSTATUS` fails should include the specific libcurl error string to aid debugging. Most critically, the test suite lacks coverage for the positive case—where a server provides a valid OCSP staple and Git successfully validates it—leaving the core functionality untested.

The author has previously addressed Patrick’s earlier concerns about the feature’s real-world relevance by providing concrete evidence of its necessity for government customers. While the patch is procedurally complete, these new review points will need to be resolved before it graduates to `master`. The long-term question of whether to flip the default to `true` or warn users about ignored staples remains open but does not block integration.
