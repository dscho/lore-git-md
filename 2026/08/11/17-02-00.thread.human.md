This thread is about a security feature patch that adds `http.sslVerifyStatus` to Git’s HTTPS certificate verification, enabling OCSP staple validation. The patch, now in its third version, addresses a procedural issue (test script numbering) while keeping the core functionality intact. The author, graysongordon-gl, introduced the feature to close a security gap where Git (when linked against OpenSSL) silently ignores stapled OCSP responses, potentially accepting revoked certificates. The patch defaults to `false` to avoid breaking remotes that don’t support stapling but can be enabled to enforce staple validation, failing connections if no staple is provided.

The patch has evolved from theoretical concerns to a well-supported proposal, with the author providing concrete use cases—particularly for government and government-adjacent customers (e.g., US Department of Defense PKI) who mandate OCSP stapling. The threat model is framed as a low-to-medium severity CVE risk, where stolen private keys could enable impersonation and data exfiltration. Junio C Hamano’s feedback has been procedural, while Patrick Steinhardt initially questioned the feature’s necessity but has since acknowledged its real-world value, though the long-term maintenance burden remains an open question.

The implementation is minimal, touching only `http.c` and the documentation, and includes thorough testing to verify the fail-closed behavior and per-URL configuration. The patch is now ready for substantive review, with the only remaining debate being whether the default should eventually change to `true` or if users should be warned when staples are ignored. The feature’s practical value is clear, but its relevance may diminish as OCSP stapling declines in broader use.
