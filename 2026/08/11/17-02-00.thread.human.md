This thread is about a security feature patch that adds `http.sslVerifyStatus`, a new Git configuration option to validate OCSP staples during HTTPS certificate verification. The patch, authored by Grayson Gordon, addresses a security gap where Git currently ignores OCSP staples, which is problematic for government and FIPS-compliant deployments (like US DoD PKI) that mandate stapling. The feature defaults to `false` for compatibility but fails closed when enabled, ensuring revoked certificates are rejected.

The patch has been technically complete since v4, with all substantive review feedback—including requests from Patrick Steinhardt for documentation updates, error message clarity, and test coverage—resolved in v5. Junio C Hamano accepted the v4 iteration as technically sound but requested a final documentation tweak in v5: rephrasing the `http.sslVerifyStatus` description to be more user-centric, avoiding jargon like "fail-closed" or "OCSP stapling" and focusing on the outcome (refusing connections to servers with revoked certificates). Grayson has agreed to this change and will submit a v6 iteration with the revised wording, which should clear the last procedural hurdle before the patch graduates to `next` and eventually `master`.

The only remaining open question is whether to include a positive test case for valid OCSP staple validation, which Grayson prototyped but deferred to maintainer discretion. The feature is well-motivated, thoroughly tested, and addresses a real-world security requirement, though its maintenance burden (given OCSP stapling’s declining relevance) remains a minor point of discussion. No substantive objections remain, and the patch is expected to merge soon.
