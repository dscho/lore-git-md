The `http.sslVerifyStatus` feature patch has reached its fifth iteration and is now ready for integration. The patch adds a boolean configuration option (defaulting to `false`) that enables OCSP staple validation via libcurl, addressing a security gap where Git ignores stapled OCSP responses in OpenSSL-linked binaries. This is particularly relevant for government and FIPS-compliant deployments, such as those using US Department of Defense PKI, where OCSP stapling is mandated.

The author, graysongordon-gl, has incorporated all prior feedback from Junio C Hamano and Patrick Steinhardt. The commit message has been clarified to accurately reflect that the feature only enables `CURLOPT_SSL_VERIFYSTATUS` when explicitly configured, documentation now notes the unified behavior of OpenSSL and GnuTLS in recent libcurl versions, and error messages include libcurl error strings for better diagnostics. The patch touches `http.c`, the HTTP configuration documentation, and the smart HTTP fetch test script, where four new tests verify the fail-closed behavior and edge cases.

Junio previously accepted the fourth iteration as technically complete, and this version resolves the remaining documentation and error-message concerns. The only deferred item is a test for the positive case (valid OCSP staple validation), which the author prototyped but left out due to complexity. Both Junio and Patrick have not insisted on its inclusion, so it does not block merging. The patch is now expected to graduate to `next` and eventually `master`. The long-term question of whether to flip the default to `true` or warn users about ignored staples remains open but is not a blocker for integration.
