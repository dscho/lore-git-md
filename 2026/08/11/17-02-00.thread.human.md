This thread is about a security feature patch adding `http.sslVerifyStatus` to Git, enabling OCSP staple validation for HTTPS connections. The patch, now at version 6, is technically complete and ready for Junio C Hamano to queue in `next`—all prior review feedback has been addressed, including documentation clarity and error message improvements.

The feature targets government and government-adjacent users (like US Department of Defense PKI environments) where OCSP stapling is mandatory, but Git’s OpenSSL-linked builds currently ignore staples, creating a security gap. The new config option defaults to `false` to avoid breaking existing setups but fails closed when enabled, rejecting connections to servers with revoked certificates. Patrick Steinhardt’s latest review provides a full test harness—Apache config, CA setup, OCSP responder, and test scripts—to verify both success and failure paths, addressing the last major test coverage gap. While Patrick leaves the decision to include this complex test infrastructure to Junio and the author, the patch itself is otherwise uncontroversial and expected to graduate to `master` soon. The remaining open questions are whether to add the positive test case, whether the default should eventually change to `true`, and whether the maintenance burden is justified.
