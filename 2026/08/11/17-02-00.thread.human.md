This thread is about a security feature patch adding `http.sslVerifyStatus` to Git, which enables OCSP staple validation for HTTPS connections. The patch, now in its fifth iteration, addresses a gap where Git ignores OCSP staples—critical for government and FIPS-compliant deployments (e.g., US Department of Defense PKI) that mandate stapling to detect revoked certificates.

The feature is technically complete and ready for integration. Junio C Hamano previously accepted the fourth version as sound, and the fifth resolves all remaining feedback: clearer documentation, improved error messages, and robust test coverage. Patrick Steinhardt’s substantive review questions (backend parity, error clarity, and test coverage) have been addressed, leaving only a minor documentation tweak requested by Junio in the latest email. This final change rephrases the `http.sslVerifyStatus` description to be more user-centric, replacing technical jargon ("fail-closed", "OCSP stapling") with plain language about refusing connections to servers with revoked certificates. The patch’s default (`false`) preserves compatibility, while enabling it ensures revoked certificates are rejected.

The only open question is whether to include a test for the positive case (valid OCSP staple validation), which the author prototyped but deferred to maintainer discretion. The feature’s maintenance burden and potential default change to `true` remain topics for future discussion, but neither blocks the current patch. With Junio’s latest request being a surface-level documentation improvement, the patch is expected to graduate to `next` and eventually `master` without further delay.
