This thread introduces a security feature to Git’s HTTPS certificate verification: the `http.sslVerifyStatus` option, which enables OCSP staple validation. The patch, now in its sixth iteration, is technically complete and ready for integration. Authored by graysongordon-gl, it addresses a gap where Git—particularly when linked with OpenSSL—ignores OCSP staples, leaving it vulnerable to accepting revoked certificates. This is a critical concern for government and enterprise users (e.g., US Department of Defense PKI) who mandate OCSP stapling for compliance.

The feature adds a boolean config key (defaulting to `false`) that, when enabled, causes Git to fail connections if the server does not provide a valid OCSP staple. This fail-closed design ensures security but avoids breaking existing setups by default. The patch includes thorough test coverage, error handling improvements, and documentation updates, all of which have been refined through feedback from Junio C Hamano and Patrick Steinhardt. The latest version (v6) focuses solely on clarifying the documentation to better explain the user-facing outcome—preventing connections to servers with revoked certificates—rather than relying on technical jargon.

No substantive objections remain, and the patch is expected to graduate to Junio’s `next` branch soon, with eventual inclusion in `master`. The only open question is whether to add a test for the positive case (valid staples), but this has been deferred. The feature is low-risk for integration but high-impact for its target audience, offering a practical solution to a niche but important security requirement.
