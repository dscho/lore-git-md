This thread is about a security feature patch that adds `http.sslVerifyStatus`, a boolean option (defaulting to `false`) to enable OCSP staple validation in Git’s HTTPS certificate verification. The patch was introduced by Grayson Gordon to address a security gap where Git—particularly in OpenSSL-linked builds common in government and FIPS-compliant environments—ignores OCSP staples, potentially accepting revoked certificates. The feature is fail-closed: if enabled, connections fail when the server doesn’t provide a staple.

After six iterations, the patch is now ready for merge. Junio C Hamano’s latest email confirms that all review feedback has been addressed, including Patrick Steinhardt’s concerns about test coverage (now resolved by existing tests in `t5551`) and documentation clarity. The v6 update rephrased the config documentation to focus on user-facing outcomes and added error messages with libcurl error strings for better debugging. The only remaining step is Junio’s merge to `next`, after which the patch is expected to graduate to `master`. Open questions remain about whether the default should eventually change to `true` or if users should be warned when staples are ignored, but these are deferred for future discussion.
