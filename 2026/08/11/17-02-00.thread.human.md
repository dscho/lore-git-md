This thread is about a security feature patch that adds `http.sslVerifyStatus`, a new Git configuration option to enable OCSP staple validation for HTTPS connections. The patch, authored by graysongordon-gl, addresses a security gap where Git currently accepts revoked certificates if they include OCSP staples, which is particularly problematic for government and government-adjacent customers (e.g., US Department of Defense PKI) that mandate OCSP stapling.

The patch is technically complete and ready for Junio C Hamano’s `next` branch. All review feedback has been addressed, including Junio’s final request to improve the documentation wording in the latest version (v6). The only remaining decision is whether to merge an additional test harness (`t5585-http-ssl-ocsp.sh`) provided by Patrick Steinhardt, which tests positive cases (valid staples) but adds complexity. Junio has now asked Patrick to clarify which parts of the test harness feel uncertain or overly complex, particularly whether it adequately covers the case where the server does not provide a staple. The thread is in a holding pattern awaiting Patrick’s response before the patch graduates to `next`.

Key participants include the author, who has driven the feature with clear rationale and thorough testing, Junio, who has confirmed the patch is technically complete, and Patrick Steinhardt, who raised initial concerns about the feature’s purpose and maintenance burden but has since provided a complete test harness. The patch introduces a boolean `http.sslVerifyStatus` option (default `false`) and integrates with libcurl’s `CURLOPT_SSL_VERIFYSTATUS` to fail connections if the server does not provide a staple. The feature is fail-closed for security but defaults to `false` to avoid breaking remotes that do not support stapling.
