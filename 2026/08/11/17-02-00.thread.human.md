This thread is about a patch that adds OCSP staple validation to Git’s HTTPS certificate checks. The author, graysongordon-gl, introduced `http.sslVerifyStatus`, a boolean option (defaulting to `false`) that enables libcurl’s `CURLOPT_SSL_VERIFYSTATUS`, causing Git to reject connections if the server doesn’t provide a staple. The patch is now in its second version, addressing Junio C Hamano’s earlier feedback by moving an explanatory comment into the commit message.

The discussion has shifted from implementation details to whether the feature is worth including at all. Patrick Steinhardt raised substantive concerns, arguing that the default-off setting, backend inconsistencies (OpenSSL vs. GnuTLS), and OCSP stapling’s declining relevance make the patch’s value questionable. The author will need to provide a concrete use case to address these doubts. Junio’s latest feedback is purely procedural—pointing out a test script numbering conflict—but doesn’t engage with the broader debate. The patch remains under review, with the next step being a v3 to resolve the test numbering issue.
