This thread is about a security feature patch that adds `http.sslVerifyStatus` to Git, enabling OCSP staple validation for HTTPS connections. The patch, now in its fourth version, was introduced by Grayson Gordon to address a security gap where Git accepts revoked certificates because it ignores OCSP staples. The feature is motivated by government and FIPS-compliant deployments (e.g., US Department of Defense PKI) that mandate OCSP stapling, and it defaults to `false` to avoid breaking remotes that don’t support stapling.

Junio C Hamano, the maintainer, has accepted the patch as technically complete and queued it for integration, meaning it will likely graduate to `next` and eventually `master`. However, Patrick Steinhardt’s latest review raises actionable improvements in documentation, error messages, and test coverage that must be addressed before the patch can be considered fully reviewed. Grayson has responded cooperatively, agreeing to update the documentation to reflect that recent versions of GnuTLS and OpenSSL now behave identically, and to improve error messages by including libcurl’s error strings. The most significant open question is whether to add comprehensive test coverage for the positive case (valid OCSP staple validation), which would require substantial new infrastructure. Grayson has the necessary setup working in a personal repo but is deferring to Junio and Patrick on whether to include it in the patch.

The discussion around the feature’s real-world impact has concluded, with Grayson providing concrete evidence of its necessity for government customers. The long-term question of whether to flip the default to `true` or warn users about ignored staples remains open but does not block integration. For now, the patch is on track for merging once the remaining review feedback is addressed.
