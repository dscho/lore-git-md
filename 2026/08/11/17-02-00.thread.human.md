This thread introduces a new security feature to Git: the `http.sslVerifyStatus` configuration option, which enables OCSP staple validation for HTTPS connections. The patch, now in its fourth version, was authored by graysongordon-gl and has just been accepted for merging by Junio C Hamano.

The feature addresses a security gap where Git binaries linked against OpenSSL (common in FIPS-compliant deployments like those used by government customers) silently ignore OCSP staples, potentially accepting revoked certificates. By default, the option is set to `false` to avoid breaking existing setups, but when enabled, it causes connections to fail if the server does not provide a staple. The design is intentionally fail-closed for security, and the patch includes thorough test coverage integrated into the existing `t5551-http-fetch-smart.sh` test script.

The discussion initially raised questions about the feature's practical value and long-term maintenance burden, given OCSP stapling's declining relevance. However, the author provided concrete evidence of its necessity for government and government-adjacent customers (e.g., US Department of Defense PKI), where stapling is mandated and the current behavior creates a real-world security risk. Junio's acceptance confirms the patch is now technically complete and ready for integration, with no remaining objections. The open question about whether the default should eventually change to `true` or if users should be warned about ignored staples remains unresolved but does not block the feature's inclusion.
