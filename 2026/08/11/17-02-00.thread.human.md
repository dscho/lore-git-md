This thread is about a security feature patch that adds `http.sslVerifyStatus`, a new Git config option to enable OCSP staple validation for HTTPS connections. The patch, now in its second version, was introduced by graysongordon-gl to address the risk of Git accepting revoked certificates by making connections fail if the server doesn’t provide a valid OCSP staple. The feature defaults to off (`false`) to avoid breaking existing setups, and can be overridden per-URL.

The patch itself is technically sound and addresses earlier feedback from Junio C Hamano, but Patrick Steinhardt’s recent review raises fundamental questions about its value. He argues that the feature doesn’t resolve the inconsistent behavior between OpenSSL (which ignores staples unless explicitly enabled) and GnuTLS (which checks them by default), and that its security benefit is limited because users must manually enable it per-host. He also notes that OCSP stapling is being phased out (e.g., by Let’s Encrypt), weakening the long-term case for the feature. The discussion now centers on whether the patch’s niche utility—fail-closed validation for users who opt in—justifies its maintenance cost and the potential confusion from backend differences. The author will need to address these concerns to move the patch forward. No other reviews have been posted yet.
