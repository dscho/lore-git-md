This thread is about a security feature patch that adds `http.sslVerifyStatus`, a new Git configuration option to validate OCSP staples during HTTPS certificate verification. The patch, authored by graysongordon-gl, addresses a gap where Git currently ignores OCSP staples, leaving government and FIPS-compliant users (such as those using US Department of Defense PKI) vulnerable to accepting revoked certificates. The feature defaults to `false` to avoid breaking existing setups but enables fail-closed behavior when enabled—connections fail if the server doesn’t provide a valid staple.

Key participants include the author, Junio C Hamano (the maintainer), and Patrick Steinhardt. Junio’s feedback focused on documentation clarity and procedural completeness, while Patrick initially raised concerns about the feature’s purpose and maintenance burden but later provided a thorough test harness and explicitly endorsed merging it. All review feedback has been addressed in the v6 iteration, including Junio’s final request for clearer documentation and Patrick’s confirmation that the existing tests already cover the fail-closed behavior. The patch is now ready for Junio to merge into `next`, with no further changes or open questions remaining. The feature is expected to graduate to `master` in the near future.
