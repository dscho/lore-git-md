This thread is about a security feature patch that adds `http.sslVerifyStatus`, a boolean option (defaulting to `false`) to enable OCSP staple validation in Git’s HTTPS certificate verification. The patch is motivated by government and government-adjacent customers (e.g., US Department of Defense PKI) who mandate OCSP stapling and encounter Git servers with stapled responses, but OpenSSL-linked Git binaries currently ignore staples, creating a security gap where revoked certificates could be accepted.

The patch is now in its third version, addressing procedural feedback from Junio C Hamano. The latest email resolves a minor integration issue: Junio provided a one-line diff to add the new test script (`t5568-http-verify-status.sh`) to `t/meson.build`, ensuring the Meson build system recognizes it. This is the last procedural hurdle before the patch can be merged. The substantive discussion—whether the feature’s maintenance burden (given OCSP stapling’s declining relevance) is justified—remains open, though the author has provided concrete evidence of its value for government customers. Patrick Steinhardt has questioned the long-term utility of the feature, but no one has objected to the implementation itself. The patch is otherwise ready for integration.
