This thread is about a security feature patch that adds `http.sslVerifyStatus`, a boolean configuration option (defaulting to `false`) to enable OCSP staple validation in Git’s HTTPS certificate verification. The patch aims to close a security gap where OpenSSL-linked Git binaries ignore OCSP staples, leaving them vulnerable to accepting revoked certificates—a concern for government and FIPS-compliant deployments like the US Department of Defense PKI.

The patch is now in its third version, with the author, graysongordon-gl, having addressed all procedural feedback. Junio C Hamano’s latest email provides minor corrections to ensure the new test script integrates properly with the Meson build system and fails loudly if OCSP stapling is unsupported. These changes are mechanical and do not affect the patch’s functionality. The substantive discussion has shifted from theoretical concerns to real-world impact, with the author providing a clear threat model (stolen private key impersonation enabling data exfiltration) and evidence of demand from government customers.

The patch is technically complete and under final review. The only remaining open question is whether the feature’s maintenance burden—given OCSP stapling’s declining relevance—is justified by its specific use case. Junio has not objected to the feature itself, while Patrick Steinhardt has raised concerns about its long-term value but has not opposed it outright. The patch is now ready for a maintainer decision on whether to merge it.
