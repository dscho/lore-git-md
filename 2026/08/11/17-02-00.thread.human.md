This thread is about a security feature patch that adds `http.sslVerifyStatus`, a new Git configuration option to enable OCSP staple validation for HTTPS connections. The patch, now in its fourth iteration, is authored by graysongordon-gl and aims to close a security gap where Git currently accepts revoked certificates when using OpenSSL-linked builds, even if the server provides an OCSP staple. This is particularly relevant for government and FIPS-compliant deployments, such as those using GitLab’s OpenSSL-based Helm charts, where OCSP stapling is mandated.

The patch has been accepted by Junio C Hamano as technically complete and is queued for integration, though it still needs some refinements. Patrick Steinhardt has provided substantive review feedback on documentation accuracy, error message clarity, and test coverage, all of which the author has agreed to address. The latest exchange between Junio and Patrick focused on improving the commit message’s readability and precision—specifically, clarifying that the patch only enables OCSP staple validation when the config option is explicitly set, rather than overriding libcurl’s default behavior unconditionally. This is a minor but important correction to avoid misleading future readers.

The feature itself is uncontroversial, with the author providing clear evidence of its necessity for government customers and addressing Patrick’s initial concerns about its real-world impact. The patch touches `http.c`, updates the documentation, and integrates tests into the existing `t5551` script. One open question is whether to add a test for the positive case (valid OCSP staple validation), which would require significant new infrastructure but could improve coverage. The author has deferred this to maintainer discretion. The long-term discussion about flipping the default to `true` or warning users when staples are ignored remains unresolved but does not block integration. A fifth version of the patch is likely to address the remaining feedback before the feature graduates to `master`.
