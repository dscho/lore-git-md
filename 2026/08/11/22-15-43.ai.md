This is a **bug report** about `git-remote-https` failing to retry with BASIC authentication when a proxy responds with a 407 (Proxy Authentication Required) challenge, even when the `HTTP_PROXY` or `HTTPS_PROXY` environment variables include credentials in the form `http://user:pass@host`.

The report demonstrates that Git’s HTTP transport layer does **not** automatically extract and use the username:password pair from the proxy URL when the proxy demands authentication. Instead, it aborts the connection after the 407 response. The workaround—setting `GIT_HTTP_PROXY_AUTHMETHOD=basic`—forces Git to send credentials preemptively, which succeeds. The author asks whether the current behavior is intentional or a bug, but the evidence strongly suggests the latter: the proxy URL format is standard, and other tools (e.g., `curl`) handle it transparently.

The email includes detailed `GIT_CURL_VERBOSE` logs showing the exact HTTP exchange: the initial CONNECT request omits credentials, the proxy responds with 407 and a `Proxy-Authenticate: Basic` header, and Git immediately aborts instead of retrying with the credentials it already has. No prior discussion or cover letter is referenced, so this appears to be a standalone report rather than part of a series.
