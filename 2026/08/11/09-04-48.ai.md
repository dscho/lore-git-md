This is a bugfix patch targeting the geometric repacking strategy in Git's auto-maintenance.

The patch addresses an issue where the geometric repacking strategy was too aggressive in triggering repacks of loose objects. Currently, the default threshold for loose objects is set to 100, which is much lower than `git gc`'s default of 6700. This low threshold causes frequent repacks, especially in repositories with concurrent writers, leading to race conditions where loose object directories are pruned while another process is trying to write to them.

Patrick Steinhardt changes the default threshold from 100 to 6700 to match `git gc`'s behavior, reducing the frequency of repacks. The change affects both the documentation (`Documentation/config/maintenance.adoc`) and the implementation (`odb/source-files.c`). The patch is motivated by user reports of instability in high-concurrency scenarios, where the aggressive repacking exacerbated existing race conditions in loose object directory handling.

This is a standalone patch (1/1 in the series) and appears to be a targeted fix rather than part of a larger effort. The commit message clearly explains the problem, the rationale for the chosen solution, and references a specific user report. The change itself is minimal and focused, touching only the default value for the `maintenance.geometric-repack.auto` configuration.
