This is part seven of Tian Yuchen’s **ready-to-merge** performance series optimizing `paint_down_to_common()` in Git’s commit-reach subsystem. The patch introduces a `paint_state` struct that replaces the old `max_nonstale` pointer-based termination logic with explicit per-side counters (`parent1_count`, `parent2_count`, `mb_candidate_count`). The change is a **refactoring with no behavior change**—both the old and new code detect when no non-stale commits remain—but it improves clarity and prepares the ground for the side-exhaustion optimization in later patches.

The patch touches `commit-reach.c` and updates the technical documentation (`paint-down-to-common.adoc`) to reflect the new counter-based termination condition. It also removes two unused helper functions (`nonstale_queue_put_dedup()` and `nonstale_queue_get_dedup()`) that were left behind by earlier refactoring. The test expectations in `t6600-test-reach.sh` are adjusted slightly because the new `paint_queue_get()` checks termination conditions *before* decrementing counters, causing the loop to exit one iteration earlier in some topologies (step counts drop by one in three test cases).

The commit message is clear and the code is well-documented, including an exhaustive switch in `paint_count_update()` that lists all valid flag combinations.
