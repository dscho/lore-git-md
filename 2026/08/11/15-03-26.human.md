This is a performance-focused patch that adds reflink support for file copies in Git, targeting Linux filesystems that support copy-on-write (CoW) cloning. The patch introduces a new optimization layer in the file-copying logic: before falling back to hardlinks or byte-for-byte copies, Git now attempts to use the `FICLONE` ioctl to create a reflink, which shares underlying storage without tying the files to the same inode. This is particularly beneficial for local clones and file copies, where it can significantly reduce I/O and storage overhead while preserving the ability to modify either file independently.

The implementation is Linux-specific and treats reflinking as an optimization rather than a requirement. If the ioctl fails (e.g., on unsupported filesystems), Git gracefully falls back to the existing hardlink or copy paths. The patch also preserves source timestamps when reflinking object files, maintaining consistency with Git’s existing behavior for prune and gc operations. A new test helper (`test-fake-reflink.c`) allows the test suite to simulate reflink success, unsupported operations, and errors, ensuring coverage even on filesystems that don’t support reflinks natively.

The patch touches core copying logic in `copy.c` and `builtin/clone.c`, adds a new test script (`t0094-reflink.sh`), and includes a small update to an existing test (`t5605-clone-local.sh`) to reflect the new behavior. The test suite passes on ZFS, ext4, and tmpfs, suggesting the change is robust across different filesystem types. The commit message and code are well-documented, and the patch includes thorough test coverage for edge cases like `--no-hardlinks` and reflink failures.

This looks like a well-crafted, low-risk optimization that addresses a real performance bottleneck for users on modern filesystems. The fallback logic ensures backward compatibility, and the test infrastructure makes it easy to verify correctness.
