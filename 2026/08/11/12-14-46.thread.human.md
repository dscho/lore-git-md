This thread is about a simple but important bugfix: Git would crash with a segmentation fault if you ran `git --shallow-file` without providing the required argument. Christian Couder submitted a one-patch series that adds the missing validation, preventing the NULL dereference and making `--shallow-file` behave like other similar options (`--git-dir`, `--namespace`, `-C`).

The fix itself was uncontroversial and has already been merged to `master`. Junio C Hamano, the maintainer, approved it as-is after initially raising procedural questions about test coverage and code reordering. Those concerns were resolved when Junio accepted the current test (a single new case in `t/t0041-usage.sh`) as sufficient for an undocumented, internal-only option. He did note that future contributors might want to expand the test to cover all similar options for completeness, but that’s a `#leftoverbits` item—nothing blocking the current patch.

The only minor back-and-forth was a stylistic suggestion from Patrick Steinhardt, who preferred a one-line `usage()` call over the existing two-line pattern (`fprintf` + `usage`). Christian explained that the two-line pattern is already the established convention for all similar options in `git.c`, and Patrick withdrew his suggestion, closing the discussion. The patch is now in `master` with no known issues.
