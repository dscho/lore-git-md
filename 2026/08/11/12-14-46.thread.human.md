This thread is about a small but important bugfix to Git's command-line option parsing. Christian Couder identified and fixed a segmentation fault that occurs when `git --shallow-file` is run without the required argument. The issue was that this option, unlike similar ones, didn't validate its argument before dereferencing it, leading to a crash. The fix adds the missing validation and aligns the logic with other options.

The patch is minimal and defensive, adding a new test in `t/t0041-usage.sh` to verify the error handling. Christian notes that all existing callers already provide a value (including empty strings), so this change only improves robustness for direct user input. The fix is uncontroversial, with no known downsides, and CI tests pass. While a broader refactoring of option handling is planned, this patch is the right short-term solution. There's no indication of any review feedback yet, but given the straightforward nature of the fix, it's likely to be merged soon.
