This thread is about a simple but important bugfix: Git crashes with a segmentation fault when `--shallow-file` is called without a required argument. Christian Couder sent a patch that adds the missing validation, preventing the NULL dereference, and includes a test to verify the error message and usage output. The fix is minimal and defensive, with no known downsides, and CI tests pass.

Junio C Hamano reviewed the patch and acknowledged it as correct and low-risk but raised two procedural concerns: whether the patch should be split to separate the defensive fix from a minor stylistic reordering, and whether the test coverage should be expanded to include all similar options (`-C`, `--git-dir`, `--namespace`, `--config-env`) or moved to a shared location. Patrick Steinhardt then suggested a stylistic tweak—condensing the two-line error message and `usage()` call into a single line—arguing that the usage string adds little value and may distract users.

Christian has now responded, defending the current two-line pattern as the established convention for similar options in `git.c`. He argues that consistency with the existing codebase is more important than the proposed tweak and suggests that any broader stylistic change should be handled separately. The core fix and test coverage remain uncontested, and the patch is still ready for merging, but the discussion now includes this additional stylistic point alongside Junio’s procedural questions. No one has objected to the technical substance of the patch.
