This is an **announcement of a Git for Windows security release** (2.55.0(4)), addressing CVE-2026-62960.

The patch fixes a security vulnerability specific to Git for Windows: when cloning from an attacker-controlled server, the server could advertise a bundle URI pointing to a network share, causing Windows to transparently perform NTLM authentication and disclose the user’s NTLMv2 hash. The fix aligns bundle URI handling with Git’s existing protocol restrictions, blocking `file://` URIs by default. The vulnerability is rated as high-risk due to the potential for credential theft via brute-forcing the captured hash.

This is a **Windows-only** issue; upstream Git (the project on `git@vger.kernel.org`) is unaffected. The release also drops support for Windows 8.1 following the MSYS2 project’s deprecation of that platform. Download links for 32-bit, 64-bit, ARM64, and portable variants are provided, along with SHA-256 checksums for verification.

The email is purely informational—no code or discussion is included. The fix is already shipped; no further action is expected on the Git mailing list unless downstream packagers have questions. The CVE identifier and clear description make this easy for distributors to track.
