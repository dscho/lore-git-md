This is the first patch in a two-part series fixing Bash completion for `git checkout -C <dir>`. The patch is a no-op refactoring of the `_git_checkout()` completion function in `contrib/completion/git-completion.bash`. It reorganizes the control flow to avoid an early return when `--` is detected on the command line, instead wrapping the existing logic in an `if ! __git_has_doubledash` block and adding explicit `return` statements to each completion branch.

The motivation is preparatory: the current early return prevents customizing what happens when option or revision completion yields no candidates (or when `--` is present), which the next patch will address. The refactoring is mechanical and does not change behavior, but it makes the logic more explicit and easier to modify. The patch touches only the completion script and is uncontroversial, serving as a clean foundation for the actual fix in 2/2.
