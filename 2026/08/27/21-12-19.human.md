This is a follow-up in the `the_repository` removal thread, specifically a reply from D. Ben Knoble to Junio C Hamano’s architectural objection. Ben raises a practical concern about libification: if built-in commands like `git switch` are not made reusable as library functions, external programs that want to replicate their behavior (without shelling out to Git) face a maintenance burden. He questions whether the project has explicitly decided not to support this use case, and suggests that it might be valuable to organize built-in code in a way that makes it easier to reuse—even if full libification isn’t the goal.

The email is thoughtful but speculative, lacking a concrete use case or proposal. It does not challenge Junio’s core objection (that built-in commands should not take a `struct repository *` parameter) but instead explores a tangential question: whether the project should support *any* form of direct reuse of built-in logic. This is a surface-level review of the broader architectural discussion—Ben acknowledges he may be missing prior consensus and asks for pointers rather than advocating for a specific change. The response is unlikely to shift the thread’s direction, but it surfaces a recurring tension in Git’s evolution: balancing architectural purity with practical reusability.
