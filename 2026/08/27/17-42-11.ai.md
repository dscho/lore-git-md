This is a **bugfix** patch in Wesley Schwengle’s two-patch series targeting `git-svn`. It addresses a long-standing annoyance: when `git svn info` is run in a plain Git repository (one that has never used `git-svn`), the code still prints a noisy “Migrating from a git-svn v1 layout…” message and creates an empty `.git/svn` directory. The fix delays the message and directory creation until the code actually finds a legacy `refs/remotes/*` candidate to migrate, mirroring the existing pattern in `migrate_from_v0()`.

The patch touches only `perl/Git/SVN/Migration.pm` and adds a single test in `t/t9107-git-svn-migrate.sh` that verifies the message is suppressed and the directory is not created when no SVN metadata exists. Junio’s review is **surface-level**: he notes a missing space in the error message (“git-svnexists” → “git-svn exists”) but does not engage with the behavioral change itself. No substantive objections or deeper technical concerns have surfaced yet.

This patch is the first half of the series; the second patch introduces a `NO_GIT_SVN` Makefile knob to allow users to opt out of building `git-svn` entirely. The series is still under review, with no indication of maintainer queue status. The change is narrow, well-motivated, and unlikely to be controversial.
