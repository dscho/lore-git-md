This is the second patch in the v10 iteration of a now functionally complete series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. The series is already in `next` and this patch makes a targeted but important refinement: it simplifies the data flow by removing unnecessary indirection in the `remote_names` field of `struct tracking_name_data`.

The patch extends `unique_tracking_name()` to optionally collect the names of matching remotes into a `string_list` provided by the caller. This allows the advice message in `parse_remote_branch()` to list the conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes: origin, upstream") rather than just reporting the count. The advice is still gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and is only shown when the ambiguity cannot be resolved deterministically.

The change is clean and well-motivated: the advice message is now more actionable, and the implementation avoids altering the return behavior of `dwim_branch()` or other core functions. The patch also updates the advice phrasing to be grammatically correct and command-specific, addressing feedback from earlier iterations. Test coverage in the series already verifies the new advice format and error handling.

This is a usability improvement, not a regression fix — the commands were already failing on ambiguity, just with less clarity. The patch is uncontroversial and aligns with the series' goal of making Git's error messages more helpful. The only remaining loose end is a follow-up fix for the one-argument `git worktree add` case, which is scoped separately.
