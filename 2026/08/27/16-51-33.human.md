This is the first patch in Wesley Schwengle’s two-part series targeting `git-svn`. It quiets the spurious "Migrating from a git-svn v1 layout..." message and prevents the creation of an empty `.git/svn` directory when `git svn info` is run in a plain Git repository (no SVN metadata present).

The change is straightforward: the `migrate_from_v1()` function in `perl/Git/SVN/Migration.pm` now defers printing the migration banner and creating the `.git/svn` directory until it actually finds a candidate ref to migrate, matching the existing pattern in `migrate_from_v0()`. A new test in `t/t9107-git-svn-migrate.sh` verifies that the message is suppressed and no empty directory is created when there is nothing to migrate.

The patch is well-motivated, touches only the Perl code and its test, and follows established Git conventions. No controversy is evident; this looks like a clean, uncontroversial bugfix.
