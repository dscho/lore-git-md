This is Junio C Hamano’s follow-up to his own review of the first patch in Elijah Newren’s v2 series, which rewords error messages to clarify that restrictions on `git commit --amend` and `git commit <paths>` apply specifically when resolving a commit that became empty during rebase. Junio acknowledges that his earlier concern about the reliability of the logic (`whence == FROM_REBASE_PICK`) was based on a misunderstanding of the code’s intent: `sequencer_determine_whence()` only sets `FROM_REBASE_PICK` when the rebase-head and cherry-pick-head are identical, which by definition indicates an empty commit. The confusion stemmed from the misleading name `FROM_REBASE_PICK`, which does not explicitly convey that it refers to an *empty* rebase step. Junio now proposes a targeted cleanup: rename `FROM_REBASE_PICK` and `is_from_rebase()` to include "empty" in their names (e.g., `FROM_REBASE_EMPTY_PICK` and `is_from_empty_rebase()`), and update all callers to use the renamed helper function. This would resolve his technical objection without requiring structural changes to the series’ logic. The error message phrasing ("while resolving a commit that became empty") remains awkward but is no longer a blocker; Junio still hasn’t proposed a better alternative. The series’ core goal—preventing unsafe commit operations during conflict resolution—remains uncontested, and this follow-up narrows the remaining work to a mechanical rename and minor textual tweaks.
