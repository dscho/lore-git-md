This is Junio C Hamano's **substantive review** of the first patch in Elijah Newren’s v2 series (1/3), which rewords error messages to clarify that restrictions on `git commit --amend` and `git commit <paths>` apply specifically when resolving a commit that became empty during rebase. Junio raises two key concerns: the phrasing of the new error messages is awkward and overly verbose ("while resolving a commit that became empty"), and he questions whether the code can reliably distinguish between a rebase stop caused by an empty commit and one caused by an ordinary conflict. He suggests that the current logic (`whence == FROM_REBASE_PICK`) may not be sufficient to guarantee the rebase stopped due to an empty commit, and warns that the new messages could mislead users if the rebase stopped for a different reason (e.g., a conflict that the user resolved manually). This feedback directly challenges the patch’s technical premise and could require structural changes to the series’ logic, not just textual tweaks. The review is substantive and may impact the series’ readiness for integration.
