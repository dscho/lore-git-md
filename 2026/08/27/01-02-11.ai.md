This is the **v2 cover letter** for a **bugfix patch series** (3 patches) by Elijah Newren, extending Git's protection against unsafe commit operations during conflict resolution. The series targets the merge machinery, preventing users from accidentally corrupting repository state by using `git commit --amend` or `git commit <paths>` during conflict stops in `git am`, `git revert`, and all forms of `git rebase`.

The series is a direct follow-up to the thread AI summary, which described the v2 patch as ready for integration after incorporating feedback from Junio C Hamano and Phillip Wood. This cover letter confirms that status: the three patches are now split into logical units, with the core logic consolidated into a new helper function, `sequencer_ongoing_operation()`, in `sequencer.c`. The series touches `builtin/commit.c`, `sequencer.c`, `sequencer.h`, and adds test coverage in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh`.

Patch 1 rewords two pre-existing rebase error messages to be more specific, avoiding generic phrasing that could mislead users. Patch 2 extends the existing protection against `git commit --amend` to cover `git am`, `git revert`, and rebase conflict stops, while carefully preserving the internal use of `--amend` by interactive rebase directives (`squash`, `reword`, `edit`, `break`). Patch 3 extends the same protection to `git commit <paths>`, blocking partial commits during conflict resolution across all affected operations.

The series is well-motivated and technically sound. The commit messages are thorough, explaining the hazard (recording conflict resolution requires capturing the entire tree state, not rewriting HEAD or committing a subset of paths) and the edge cases considered (distinguishing conflict stops from clean interactive rebase stops). The code is clean, with clear comments about the meaning of rebase-merge directory files, and the new helper function improves maintainability by consolidating logic while preserving separation of concerns between merge and sequencer subsystems. The series aligns with the `the_repository` removal effort by replacing `the_repository` with `s->repo` where possible, though the partial commit callsite retains `the_repository` due to lack of a readily available repository instance.
