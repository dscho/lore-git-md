The `git-svn` series by Wesley Schwengle has reached its second iteration, addressing the only feedback received so far—a minor typo in an error message. The series tackles two long-standing annoyances: silencing unnecessary migration noise when `git svn info` is run in a plain Git repository, and allowing users to skip building `git-svn` entirely via a new `NO_GIT_SVN` Makefile knob.

The first patch defers the "Migrating from a git-svn v1 layout..." message and `.git/svn` directory creation until a legacy `refs/remotes/*` candidate is actually found, mirroring the existing behavior for v0 migrations. The second patch adds the build-time opt-out, which disables compilation, installation, and tests for `git-svn`. Both changes are narrow and well-scoped, touching only `perl/Git/SVN/Migration.pm`, the `Makefile`, and adding a single test in `t/t9107-git-svn-migrate.sh`.

Junio’s initial review was surface-level, catching only the typo, and no substantive objections have emerged. The series remains under review, with no indication of maintainer queue status. Given the lack of deeper technical pushback, it’s likely to proceed once the typo fix is confirmed.
