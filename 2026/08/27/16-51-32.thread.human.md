This thread is about a small but practical improvement to `git-svn` by Wesley Schwengle. The goal is to reduce noise and unnecessary clutter when using `git svn info` in a plain Git repository—currently, it prints a misleading "Migrating from a git-svn v1 layout..." message and creates an empty `.git/svn` directory even when no Subversion metadata exists. The first patch in the series fixes this by deferring the migration message and directory creation until actual legacy refs are found, matching the behavior of the existing `migrate_from_v0()` logic.

The change is narrowly scoped to `perl/Git/SVN/Migration.pm` and includes a new test in `t/t9107-git-svn-migrate.sh` to verify the fix. There’s also a second patch (not yet summarized) that adds a `NO_GIT_SVN` Makefile knob to let users skip building `git-svn` entirely if they don’t need Subversion support. So far, the series is under review with no feedback yet, and no prior versions exist. The patch was posted on June 10, 2025.
