This thread is about a two-patch series from Wesley Schwengle that addresses two long-standing `git-svn` annoyances. The first patch silences spurious migration messages and prevents empty `.git/svn` directories from being created when running `git svn info` in a plain Git repository. The second patch, which is the focus of this latest email, adds a `NO_GIT_SVN=YesPlease` Makefile knob to let users skip building, installing, and testing `git-svn` entirely when SVN support isn’t needed. This also automatically disables the time-consuming SVN interoperability tests.

The series is now at version 2, posted on June 10, 2025, and remains under review. The only feedback so far was a minor typo fix in an error message, which Wesley addressed in this update. Junio C Hamano reviewed the first version but only noted the typo, not the behavioral changes themselves. The series has been uncontroversial, with no substantive technical objections raised. The changes are narrow and follow established patterns: the Makefile knob mirrors other `NO_*` options, and the behavioral fix aligns with existing migration logic. Unless new feedback emerges, the series appears ready to proceed.
