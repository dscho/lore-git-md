This thread is about a two-patch series from Wesley Schwengle that aims to clean up two long-standing annoyances in `git-svn`. The first patch, which is the focus of this update, fixes a bug where running `git svn info` in a plain Git repository (one that has never used `git-svn`) would print a spurious "Migrating from a git-svn v1 layout..." message and create an empty `.git/svn` directory. The fix delays the message and directory creation until the code actually finds a legacy `refs/remotes/*` candidate to migrate, making the behavior consistent with the existing `migrate_from_v0()` pattern.

Junio C Hamano has reviewed the patch and noted a minor formatting issue (a missing space in an error message), but he hasn’t raised any substantive concerns about the change itself. The patch touches only `perl/Git/SVN/Migration.pm` and adds a test to verify the fix. The second patch in the series, which hasn’t been discussed yet, introduces a `NO_GIT_SVN` Makefile knob to let users opt out of building `git-svn` entirely if they don’t need SVN support.

The series is still under review, with no indication yet of whether it will be queued for integration. The change is narrow, well-motivated, and unlikely to be controversial, so it may proceed smoothly once the minor formatting issue is addressed.
