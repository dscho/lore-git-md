This is the third patch in the v10 series improving error messages for ambiguous remote branch names in `git worktree add`. The series is now functionally complete and merged to `next`.

This patch extends the user-friendly advice and clearer error messages — already applied to `git checkout` and `git switch` in earlier patches — to `git worktree add`. When the user runs `git worktree add ../foo-dir bar-topic` and `bar-topic` exists in multiple remotes (e.g., `origin/bar-topic` and `upstream/bar-topic`), Git now dies immediately with a descriptive error: "'bar-topic' matched multiple (2) remote tracking branches". If advice is enabled (the default), it also lists the conflicting remotes and suggests how to resolve the ambiguity, such as using `git worktree add -b bar-topic ../foo-dir origin/bar-topic` or setting `checkout.defaultRemote`.

The implementation reuses the shared `advise_disambiguating_remotes()` helper introduced in patch 1/4 and extended in patch 2/4. The helper is called only when `advice.checkoutAmbiguousRemoteBranchName` is enabled and the command is not run in quiet mode (`--quiet`). The patch updates `builtin/worktree.c` to call `unique_tracking_name()` with a `string_list` to collect the names of matching remotes, then passes them to the advice helper. The advice message is tailored to `worktree add`, suggesting the correct syntax for creating a worktree from a specific remote branch.

Test coverage in `t/t2400-worktree-add.sh` verifies the new error message format and confirms the advice is suppressed in quiet mode. The patch is uncontroversial and aligns `git worktree add` with the behavior already established for `git checkout` and `git switch`. The only remaining loose end — the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`) — is scoped for a follow-up commit, as previously agreed.
