This thread began as a small refactoring to remove implicit use of Git’s global `the_repository` variable in a handful of built-in commands, but Junio C Hamano’s review transformed it into a sweeping architectural proposal. Junio rejected the original patch outright, arguing that the `struct repository *` parameter in built-in command implementations is a misguided design that should be eliminated entirely. Instead, he proposed replacing it with a simple `bool has_repo` flag in *all* built-in commands, a change that prevents segfaults (e.g., running `git foo -h` outside a repository), removes the false promise of libification for built-ins, and redirects the ongoing `the_repository` removal effort toward utility code outside `builtin/`. The patch itself is mechanical—touching 135 files and passing the test suite—but its implications are far-reaching, effectively halting further incremental conversions in built-in commands and reaffirming that these commands are not intended for direct reuse via libgit.

The discussion has now converged on Junio’s proposal as the active direction. Hardik Kumar, the original patch author, accepted the shift, and D. Ben Knoble’s follow-up explicitly endorsed Junio’s clarification on how to properly replicate built-in behavior: factor reusable logic out of built-in implementations (e.g., `cmd_checkout()`) into libified utility functions, which both the original command and new consumers (like `cmd_switch()`) can call. This resolves the libification question and provides a concrete technical path forward. The remaining open questions center on broader community consensus—whether contributors like René Scharfe or Patrick Steinhardt will accept this architectural shift—and coordination around the redirected `the_repository` effort. Hardik’s latest email also raises a speculative question about whether the `bool has_repo` approach is a stepping stone toward a more efficient future design, but this remains open-ended and does not contest the current patch. For now, the focus is on Junio’s proposal as the new baseline.
