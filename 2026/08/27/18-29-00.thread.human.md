This thread refactors the internals of `git checkout`, `git switch`, and `git restore` to eliminate a monolithic helper function and make reusable logic available to other parts of Git. Junio Hamano posted an 8-patch series demonstrating how to extract shared initialization, validation, and branch setup code into standalone utility functions that accept a `struct repository *` parameter, aligning with the project’s architectural direction to remove global state.

The series is now complete as an early draft for discussion. The first seven patches extracted and reorganized roughly 400 lines of logic, eliminating the `checkout_main()` choke point and rewriting the three command entry points to call the new helpers directly. The eighth patch moved the `post_checkout_hook()` function to a new top-level file so it can be used by other subsystems like `git worktree`, but Junio’s follow-up identified a shortcoming: the function still hardcodes `the_repository` and `the_hash_algo`, which limits its reusability. He noted that it should accept a repository parameter and derive the hash algorithm from that context instead. This feedback tightens the architectural direction without changing the overall goal.

No objections or alternatives have been raised, and the series remains uncontroversial. It is explicitly not intended for merging yet due to potential conflicts with other in-flight work, but the first seven patches could be merged independently if the eighth is deferred. The main open questions are whether the community will accept this refactoring approach and how it will be coordinated with other ongoing efforts like the `the_repository` removal. Junio’s feedback on the eighth patch sets a clear standard for what a fully libified helper should look like, making the series a stronger example of the intended architectural path.
