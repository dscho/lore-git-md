This thread is about refactoring Git’s `checkout`, `switch`, and `restore` commands to eliminate a monolithic helper function (`checkout_main()`) and extract reusable logic into standalone utilities. Junio C Hamano posted an 8-patch series as an early draft to illustrate the architectural direction agreed in a prior discussion: built-in commands should not be libified, but their internals should be factored into helpers that accept a `struct repository *` parameter, placing all callers on equal footing.

The series is not yet ready for merging, but the first four patches are self-contained and pass the test suite. The first three clean up global state and relocate validation logic to more appropriate functions; the fourth (just summarized) reorganizes option handling and pathspec parsing into four new static helpers within `builtin/checkout.c`. These changes are purely internal and do not alter CLI behavior or on-disk formats. No objections have been raised so far, and the patches are positioned as a discussion starter rather than a final proposal. The remaining patches will move the extracted logic into top-level files (`checkout.c`, `checkout.h`) to complete the libification. Open questions include how this refactoring will coordinate with other in-flight topics and whether the community will accept the proposed helpers.
