This thread began as a small refactoring to remove implicit use of the global `the_repository` variable in a handful of built-in commands, but Junio C Hamano’s review transformed it into a sweeping architectural proposal. The core issue is now the design of built-in command interfaces: Junio argues that the `struct repository *` parameter in `cmd_foo()` functions is a misguided design that should be replaced with a simple `bool has_repo` flag. This change eliminates segfault risks (e.g., running `git foo -h` outside a repository), removes the false promise of libification for built-ins, and redirects the `the_repository` removal effort toward utility code outside `builtin/`. Junio’s patch, which touches 135 files, is the active direction, with Hardik Kumar’s original patch definitively superseded.

The proposal is now framed as the **final state** for built-in command interfaces, motivated by safety and clarity rather than efficiency. Junio’s latest clarification sharpens the rationale: built-in commands are one-time orchestrators (like `main()` in ordinary programs) and should not be treated as reusable entry points. Instead, reusable logic should be factored out into standalone helper functions that accept a `struct repository *` parameter, allowing both built-ins and new consumers to call them. This approach resolves the libification question and provides a concrete path forward for the `the_repository` removal effort. The patch itself is mechanical, passes the test suite, and updates documentation examples to reflect the new interface, but its implications are far-reaching.

Three substantive concerns remain open: community consensus on the architectural shift, coordination with other contributors (e.g., René Scharfe, Patrick Steinhardt) to avoid duplicative work, and the need for follow-up patches to extract reusable logic from built-in commands. Junio’s proposal is explicitly a request for opinions, and while no new objections have been raised, the patch is not yet merged. D. Ben Knoble’s earlier question about libification has been resolved, and Hardik Kumar’s speculative follow-up about the `bool has_repo` design being a stepping stone was definitively answered—it is the final state. The focus now is on whether the community will accept this architectural direction and how the follow-up work will be coordinated.
