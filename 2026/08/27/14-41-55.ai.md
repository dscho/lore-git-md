This is the second patch in the v10 iteration of a four-patch series improving error messages for ambiguous remote branch names in `git checkout`, `git switch`, and `git worktree add`. The series is now functionally complete and has been merged to `next`.

This patch extends the `unique_tracking_name()` function to optionally collect the names of matching remotes, enabling a more detailed and actionable advice message when ambiguity arises. The advice now lists the conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes: origin, upstream") and suggests using `--track` or setting `checkout.defaultRemote` for future disambiguation. The advice is gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and is tailored to the command (`checkout` or `switch`).

The patch simplifies the `remote_names` field in `struct tracking_name_data` from `struct string_list **` to `struct string_list *`, removing unnecessary indirection. It also updates the `advise_disambiguating_remotes()` helper to accept the branch name and matched remote names as arguments, ensuring the advice message is consistent and informative. The `parse_remote_branch()` function is refactored to use the extended `unique_tracking_name()` and pass the matched remote names to the advice helper.

The changes touch `builtin/checkout.c`, `builtin/worktree.c`, `checkout.c`, and `checkout.h`, with the core logic residing in `checkout.c`. The patch maintains backward compatibility by preserving the existing behavior of `unique_tracking_name()` when the new `dwim_remote_names` parameter is `NULL`. Test coverage for the new advice format and error messages is provided in later patches in the series.

This patch addresses Junio’s feedback from v9, including simplifying the `remote_names` field and improving code clarity. The implementation is uncontroversial and aligns with the series’ goal of improving usability without disrupting existing workflows. The advice message is now grammatically correct and provides a static list of conflicting remotes, making it easier for users to resolve ambiguity.
