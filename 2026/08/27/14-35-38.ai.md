This is a refactoring patch discussion in the `die_for_incompatible_opts()` series, specifically a reply from Junio C Hamano to Jeff King’s substantive review of the second patch. The thread remains focused on internal API design for the new varargs helper that replaces the fixed-arity `die_for_incompatible_optN()` family.

Junio responds to Peff’s three main points with a proposed adjustment to the series. First, he agrees that the varargs function should retain compile-time safety for the common cases (2–4 options) by keeping the static inline wrappers, but now plans to drop the first patch (which reordered parameters) and instead have the varargs helper accept the same `<int, const char *>` pairs as the fixed-arity functions, using `EOF` (-1) as the sentinel. This preserves the old signatures while still allowing unbounded input. Second, he acknowledges the hard-coded error-message formatting but defers dynamic allocation to avoid breaking i18n message templates; the cap at four remains for now. Third, he confirms that no callers currently need more than four options, though the new helper is future-proof.

The discussion is technical and low-stakes: both participants accept the core design, and the remaining open items are mechanical (sentinel choice, message formatting). The series is still blocked by the previously identified `va_end()` omission, but Junio’s reply suggests a simpler implementation path that may reduce churn. No new edge cases or behavioral concerns are introduced.
