This is a **substantive review** of the first patch in Harald Nordgren’s two-patch series refining `git checkout -m` autostash conflict handling. Phillip Wood, a seasoned reviewer with deep expertise in the sequencer and checkout subsystems, raises a targeted but significant design concern: the patch adds a `conflicted` output parameter to the autostash plumbing functions (`apply_save_autostash_oid` and `apply_save_autostash_ref`) to report whether stash application resulted in conflicts, but Phillip argues it would be cleaner to use the return value for this purpose instead of introducing another parameter. His feedback is concise and technical, focusing on API design rather than implementation details.

The patch itself is mechanical and backward-compatible, threading the new `conflicted` parameter through the call chain while preserving existing behavior by having all current callers pass `NULL`. Phillip’s objection does not question the correctness of the change but rather its design elegance. The review is substantive because it engages with the patch’s architectural approach—how information should flow between functions—rather than surface-level issues like style or naming. No alternative implementation is suggested, but the implication is that the patch could be simplified by repurposing the return value to encode success/error/conflict states.

This feedback does not block the patch outright but signals that the author may need to revisit the design before the series can proceed.
