This is a **bugfix** patch for the sequencer subsystem, specifically addressing how `git rebase --autosquash` handles `fixup!` or `squash!` commits that cancel out their target, resulting in an empty commit. The patch is now at **v4**, incorporating substantive feedback from Phillip Wood, and is part of a thread that has been under active review.

The core issue is that Git currently fails to respect the `--empty` option (`drop`, `keep`, or `stop`) when a `fixup!` or `squash!` commit negates all changes in its target. Instead of dropping, keeping, or stopping at the empty commit as configured, the rebase halts with an error. This patch fixes that by teaching the sequencer to detect when applying a `fixup!` or `squash!` empties the target commit and to handle it according to the `--empty` setting.

Key improvements in **v4** include:
- **Correctness**: The patch now remembers whether the target commit was originally picked with changes (using a new `enum fixup_target` and on-disk state in `rebase-merge/fixup-target`), ensuring only commits that *become* empty are dropped. Commits picked empty are left alone, preserving existing workflows where empty commits serve as placeholders.
- **Mid-chain handling**: Only the final `fixup!` in a chain may drop the target commit; earlier ones keep it (empty) to avoid misapplying subsequent fixups.
- **Conflict resolution**: The patch also handles cases where a conflicted `fixup!` is resolved by undoing its target, ensuring `--empty=drop` applies correctly.
- **Post-rewrite machinery**: When a commit is dropped, the patch ensures nothing spurious is reported to hooks or `--update-refs`, avoiding broken mappings.

The patch touches `sequencer.c` (core logic), updates `Documentation/git-rebase.adoc` to document the new behavior, and adds comprehensive tests in `t/t3415-rebase-autosquash.sh` covering all `--empty` modes, edge cases (root commits, mid-chain fixups), and conflict scenarios. The tests are thorough and well-structured, reflecting the patch’s real-world motivation: simplifying workflows at Meta where internal LLVM patches are managed as single commits using `fixup!` autosquash.

This looks like a **well-crafted, uncontroversial fix** for a long-standing edge case. The commit message is detailed, the code changes are narrowly scoped, and the test coverage is complete.
