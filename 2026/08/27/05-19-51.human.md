The test case shows that the protection is not transitive: if branch `C`
depends on `B`, and `B` depends on `A`, then `git branch -d A B` will
delete `A` (because nothing depends on it directly) and refuse to delete

independent of argument order, and that is true, but it does not claim
transitivity.

I think the current behavior is correct, but the documentation should be
updated to clarify that only direct upstreams are protected.  The current
wording ("directly or indirectly") suggests transitivity, which is not
implemented.
