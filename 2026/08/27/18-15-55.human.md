This is a documentation patch refining the deprecation warning message shown when users invoke deprecated Git commands. It’s the third iteration of a small but well-motivated change that replaces the previous 8-line message with a shorter, clearer 6-line version. The new wording removes any language that could mislead users into thinking the Git project might reverse a deprecation decision, instead emphasizing that the command *will* be removed and guiding users toward finding a replacement workflow.

The patch modifies only the `you_still_use_that()` function in `usage.c`, updating the error message string and its formatting. The opening line now reads “'%s' will be removed soon” (previously “is nominated for removal”), reinforcing the finality of the deprecation. The rest of the message directs users to the breaking changes documentation, mailing list archives for prior discussion, and the mailing list itself for help—with the email-help line now explicitly tied to cases where suggested alternatives “do not work for you.” The patch also fixes two tests that checked for the old “nominated for removal” string.

This version (v3) addresses the last remaining nit from the thread: Elijah Newren’s grammatical suggestion to add the word “list” to “mailing” in the phrase “Check what others on the mailing suggest as a replacement.” The change is minor but makes the sentence grammatically correct. All other feedback from the thread—including Junio’s refinement of the opening line and the intentional double newlines for visual separation—has been incorporated in earlier versions.

The patch is now cooking in `next` and looks ready to graduate. It’s a clean, focused improvement that makes the deprecation warning more direct and user-friendly without changing any behavior.
