This is the second patch in Elijah Newren’s three-patch **bugfix series** that extends Git’s protection against unsafe commit operations during conflict resolution. Specifically, this patch blocks `git commit --amend` during conflict stops in `git am`, `git revert`, and all forms of `git rebase`, while carefully preserving the internal use of `--amend` by interactive rebase directives (`squash`, `reword`, `edit`, `break`).

The patch introduces a new helper function, `sequencer_ongoing_operation()`, in `sequencer.c`, which consolidates the logic for detecting active operations that record their result as a new commit on top of HEAD (rather than rewriting HEAD). This function distinguishes between genuine conflict stops (where amending would corrupt repository state) and clean interactive rebase stops (where amending is expected and safe). The logic relies on the presence or absence of specific files in the `rebase-merge/` directory: `stopped-sha` (written only when the rebase stops and hands control back to the user) and `amend` (written only when the rebase stops with HEAD already pointing at the commit to be amended).

The patch touches `builtin/commit.c` to extend the existing protection against `--amend` to cover the new cases, and adds test coverage in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh` to verify the behavior. The tests confirm that `--amend` is rejected during conflict resolution for all targeted operations, while remaining allowed for clean interactive rebase stops.

This patch is well-motivated and technically sound. The commit message clearly explains the hazard (amending during conflict resolution can corrupt repository state by recording only a subset of the intended tree state) and the edge cases considered (distinguishing conflict stops from clean interactive rebase stops). The code is clean, with clear comments about the meaning of the rebase-merge directory files, and the new helper function improves maintainability by consolidating logic while preserving separation of concerns between merge and sequencer subsystems.
