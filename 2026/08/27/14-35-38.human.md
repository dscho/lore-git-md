This is a refactoring patch discussion between Junio C Hamano and Jeff King (Peff) about the second patch in Junio’s series introducing `die_for_incompatible_opts()`. The series aims to replace the fixed-arity `die_for_incompatible_optN()` family with a single varargs helper that can handle an unbounded number of mutually exclusive command-line options, while preserving existing behavior.

Junio responds to Peff’s earlier review with a proposed simplification: he suggests dropping the first patch (which reordered parameters) and instead keeping the existing fixed-arity helpers as thin wrappers around the new varargs function. The wrappers would call `die_for_incompatible_opts()` with a sentinel value (`EOF == -1`) to mark the end of the argument list. This approach preserves compile-time safety for the common cases (2–4 options) while still allowing the flexibility of varargs for future callers. Junio acknowledges the trade-off Peff noted about hard-coded error-message formatting but prioritizes i18n/l10n concerns over dynamic allocation, noting that switching to dynamic allocation would require breaking existing message templates.

The discussion remains technical and uncontroversial. The only open issues are the previously identified `va_end()` omission (acknowledged by Junio and slated for the next iteration) and the mechanical improvements Peff suggested (NULL-sentinel annotation and hard-coded message formatting). Junio’s proposed simplification addresses the compile-time safety concern Peff raised while keeping the series scope unchanged. The patch is well-motivated, touches only internal plumbing, and has no user-visible impact. It looks like a clean, low-risk refactoring that should proceed once the `va_end()` fix is incorporated.
