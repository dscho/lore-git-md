This is the final patch in a now-complete four-patch series that improves error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The series is merged to `next` and addresses all prior feedback.

This patch specifically fixes a latent bug in `git worktree add --guess-remote`: when multiple remote branches match the given name, the command previously succeeded silently, creating a branch from HEAD. Now it errors out with a clear message ("'%s' matched multiple (%d) remote tracking branches") and suggests the user choose a start-point, aligning the behavior with `git checkout` and `git switch`. The patch updates the documentation to reflect this change and adds a test case in `t/t2400-worktree-add.sh` to verify the new error behavior.

The implementation extends the `dwim_branch()` helper to accept `add_opts` for `--quiet` support and detect multiple matches, then calls the shared `advise_disambiguating_remotes()` helper (introduced earlier in the series) to provide actionable advice. The advice is suppressed in quiet mode, and the error message includes the number of matching remotes for clarity. The patch touches `builtin/worktree.c`, documentation files, and the test suite, completing the command coverage for the series.

The one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`) remains scoped for a follow-up fix, as previously agreed. This patch is uncontroversial and functionally complete.
