This is the final patch in a now-complete four-patch series that improves error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The series is merged to `next` and addresses all prior feedback.

This patch specifically fixes a latent bug in `git worktree add --guess-remote`: when multiple remote branches match the given name (e.g., `foo` in both `origin/foo` and `upstream/foo`), the command previously succeeded silently, creating a branch from HEAD. That behavior was inconsistent with `git checkout` and `git switch`, which error out in the same scenario. The patch aligns `worktree add` with the other commands by treating multiple matches as an error, accompanied by a clear diagnostic ("matched multiple (2) remote tracking branches") and, when advice is enabled, a list of conflicting remotes.

The change is small but important for consistency. It updates the `dwim_branch()` helper to accept the `add_opts` struct (for `--quiet` support), extends `unique_tracking_name()` to detect multiple matches, and adds a new test case in `t/t2400-worktree-add.sh` that verifies the error behavior. Documentation in `git-worktree.adoc` and `config/worktree.adoc` is updated to reflect the new behavior. The implementation is careful not to disrupt existing workflows: the one-argument form of `git worktree add` (e.g., `git worktree add ../topic-branch`) remains slated for a follow-up fix, as previously agreed.

The patch is well-motivated and uncontroversial. It closes a long-standing inconsistency and improves usability without introducing new edge cases. The test coverage is thorough, and the commit message clearly explains the rationale and scope. This is a clean, focused fix that rounds out the series.
