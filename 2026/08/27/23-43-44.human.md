This is the first patch in Wesley Schwengle’s two-part series to reduce `git-svn` noise and make its build optional. It fixes a long-standing annoyance: when you run `git svn info` in a plain Git repository (one that never used `git-svn`), the command prints a misleading “Migrating from a git-svn v1 layout…” message and creates an empty `.git/svn` directory. The patch defers the message and directory creation until the code actually finds a legacy `refs/remotes/*` candidate, matching the existing behavior of `migrate_from_v0()`.

The change is confined to `perl/Git/SVN/Migration.pm` and adds a single test in `t/t9107-git-svn-migrate.sh` to verify that the noise is suppressed and the directory is not created. The diff is small (17 insertions, 6 deletions) and the logic is straightforward: the migration message and directory are now printed only when there is something to migrate. No new symbols or on-disk format changes are introduced.

The v2 iteration addressed the only feedback received on v1—a typo in an error message—and is otherwise identical. The series remains uncontroversial, with no substantive technical objections raised so far. If you use `git-svn` occasionally or build Git from source, this patch will make the experience quieter and less cluttered.
