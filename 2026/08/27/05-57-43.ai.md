This is a **substantive review** by Jeff King (Peff) of the third patch in Elijah Newren’s four-patch bugfix series (v2), which introduces a `stale_packs_detected` flag to handle `OBJECT_INFO_QUICK` lookups racing with concurrent repacks. Peff challenges the architectural premise of the patch, arguing that the `QUICK` flag’s contract is being misinterpreted and that the fix may be solving the wrong problem.

Peff’s core objection is that `OBJECT_INFO_QUICK` is *designed* to accept false negatives—its purpose is to optimize for the common case where an object is genuinely missing, not to recover from transient races. He suggests that `git mktree --batch` (the primary affected command in the tests) is misusing `QUICK` entirely: it should either avoid the flag or use `SKIP_FETCH_OBJECT` instead, as its original rewrite in 2022 (commit `817b0f6027`) may have been incorrect. The patch’s workaround—using `stale_packs_detected` to force a second read for `QUICK` lookups—violates the flag’s intended semantics and could introduce unnecessary overhead for legitimate misses.

Peff also raises a narrower concern about the patch’s error handling: the "error: packfile ... index unavailable" message is misleading when the object still exists in another pack, and suppressing it might be preferable to the current recovery mechanism. Additionally, he points out a race condition in the patch’s logic: if the `.idx` file is present but the `.pack` file vanishes, the code fails to set `stale_packs_detected`, leaving the reader in an inconsistent state.

The review does not engage with the broader correctness issue addressed by patch 4/4 (the MIDX recovery logic), which Peff has previously endorsed. Instead, it focuses on whether this patch’s approach to `QUICK` lookups is architecturally sound. The feedback implies that the series might need to revisit the use of `QUICK` in `git mktree --batch` rather than hacking around it in the object database layer. This could lead to a redesign of patch 3/4 or its removal in favor of a targeted fix for `mktree`. The thread’s convergence is now in question, as Peff’s critique targets a foundational assumption of the current approach.
