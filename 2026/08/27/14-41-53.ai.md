This is the tenth iteration (v10) of a four-patch series improving user-facing error messages for `git worktree add`, `git checkout`, and `git switch` when an ambiguous remote branch name is provided. The series is now functionally complete, with all prior feedback addressed, and was previously merged to `next`. This iteration makes final adjustments to function naming, commit message clarity, and code structure, including simplifying the `remote_names` field in `struct tracking_name_data` to avoid unnecessary indirection.

The core goal remains unchanged: replacing the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message that lists conflicting remotes (e.g., "Branch name '%s' appears in multiple remotes:") and suggests using `--track` or setting `checkout.defaultRemote`. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and applies consistently across all three commands. The series also fixes a latent bug in `git worktree add --guess-remote`, which now errors out when multiple matches exist, aligning it with the behavior of `git checkout` and `git switch`.

- **Patches 3/4 and 4/4**: Unchanged from v9, completing the command coverage and ensuring `--guess-remote` errors out on ambiguity.
