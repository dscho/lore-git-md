This is the **third and final patch** in Elijah Newren’s **bugfix series** (v2) extending Git’s protection against unsafe commit operations during conflict resolution. It blocks `git commit <paths>` (partial commits) during conflict stops in `git am`, `git revert`, and all forms of `git rebase`, completing the work begun in patch 2 (which handled `git commit --amend`).

The patch reuses the `sequencer_ongoing_operation()` helper introduced in patch 2 to detect active conflict-resolution states, then extends the existing partial-commit checks in `builtin/commit.c` to cover the newly protected operations. The error messages are specific to each operation (`am`, `revert`, `rebase`), avoiding the generic phrasing that patch 1 reworded for clarity. Test coverage is added to `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh`, verifying that partial commits are rejected in all relevant scenarios while preserving the ability to resolve conflicts normally.

The change is minimal and focused: the diff touches only `builtin/commit.c` (to extend the existing `switch` statement) and `sequencer.h` (to update a comment), with the bulk of the patch being new tests. The logic is uncontroversial—partial commits during conflict resolution have long been blocked for merges, cherry-picks, and some rebase variants, and this patch simply closes the gap for the remaining operations. The commit message clearly explains the hazard (recording conflict resolution requires capturing the entire tree state, not a subset of paths) and the edge cases considered (distinguishing conflict stops from clean interactive rebase stops).

This patch, like the rest of the series, is ready for integration. Junio and Phillip Wood have already endorsed the approach, and the series addresses all prior feedback. Key technical details for follow-up: the `sequencer_ongoing_operation()` helper in `sequencer.c`, the new test cases in `t3404`, `t3507`, and `t4151`, and the error messages that now cover all conflict-resolution scenarios. No on-disk format changes or new CLI options are introduced. The series aligns with the `the_repository` removal effort, though this patch retains `the_repository` in the partial-commit callsite due to lack of a readily available repository instance.
