Subject: [PATCH 0/8] builtin/checkout: libify reusable logic and eliminate checkout_main()
Series version: 8-patch series, early draft for illustration, not for merging to `seen`
Originating author: Junio C Hamano
Thread type: architectural refactoring of built-in command internals, direct follow-up to the `the_repository` removal architectural clarification

Core problem or goal
The thread implements the libification path clarified in the parent thread: reusable logic is factored out of the `git checkout`, `git switch`, and `git restore` built-in commands into standalone utility functions that accept a `struct repository *` parameter. The immediate goal is to eliminate the monolithic `checkout_main()` choke point, which was identified as a "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper. The broader goal is to place all callers (built-in commands and external programs) on equal footing by extracting reusable logic into top-level files (`checkout.c`, `checkout.h`) that can be called directly. This aligns with the architectural direction established in the parent thread: built-in commands are not libified, but their reusable internals are.

Current status
Junio’s 8-patch series is an early draft for illustration, explicitly not intended for merging to `seen` due to potential conflicts with in-flight topics. The series applies cleanly to `master` and passes the test suite. It directly addresses the "cheating" pattern and implements the libification path defined in the parent thread. No objections or alternatives have been raised, but the series is positioned as a discussion starter. The architectural shift is now concretely demonstrated: the three commands call extracted helpers directly, bypassing `checkout_main()`, and the final patch moves `post_checkout_hook()` to a top-level file as an example of libification.

The first three patches in the series are self-contained, uncontroversial, and pass the test suite. The first patch eliminates a file-scope static variable (`cb_option`) used for error reporting in branch name parsing, replacing it with an explicit parameter passed through the call chain. The second patch moves branch-name validation logic from `checkout_main()` into `checkout_branch()`, where it logically belongs. The third patch moves the validation of `--ours`, `--theirs`, `--force`, and `--merge` option compatibility from `checkout_main()` into `checkout_paths()`, where the logic is only relevant when pathspecs are present. The fourth patch extracts option validation and pathspec handling logic into four new static helper functions in `builtin/checkout.c`: `init_checkout_opts()`, `validate_path_options()`, `prepare_common_options()`, and `parse_pathspec_from_file_options()`. These helpers are called from `checkout_main()` to improve code organization and readability, reducing its size and complexity by roughly 150 lines. These patches are purely internal, do not alter CLI behavior, and could be merged independently if the rest of the series requires more time. The remaining patches continue the refactoring by extracting additional reusable logic into standalone helpers.
