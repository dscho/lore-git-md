Subject: [PATCH v2 0/8] builtin/checkout: libify reusable logic and eliminate checkout_main()
Series version: 8-patch series, second iteration, early draft for illustration, not for merging to `seen`
Originating author: Junio C Hamano
Thread type: architectural refactoring of built-in command internals, direct follow-up to the `the_repository` removal architectural clarification

Core problem or goal
The thread implements the libification path clarified in the parent thread: reusable logic is factored out of the `git checkout`, `git switch`, and `git restore` built-in commands into standalone utility functions that accept a `struct repository *` parameter. The immediate goal is to eliminate the monolithic `checkout_main()` choke point, which was identified as a "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper. The broader goal is to place all callers (built-in commands and external programs) on equal footing by extracting reusable logic into top-level files (`checkout.c`, `checkout.h`) that can be called directly. This aligns with the architectural direction established in the parent thread: built-in commands are not libified, but their reusable internals are.

Current status
Junio’s 8-patch series is now in its second iteration as an early draft for illustration, explicitly not intended for merging to `seen` due to potential conflicts with in-flight topics. The series applies cleanly to `master` and passes the test suite. It directly addresses the "cheating" pattern and implements the libification path defined in the parent thread. The first patch removes the file-scope static `cb_option` and passes it explicitly as a parameter to `parse_remote_branch()` and `parse_branchname_arg()`, eliminating a specific instance of global mutable state. The **second patch relocates branch name validation logic (`validate_branchname()` and `validate_new_branchname()`) from `checkout_main()` into `checkout_branch()`**, where it logically belongs, improving code locality without changing behavior. The **third patch moves the validation of `--ours`, `--theirs`, `--force`, and `--merge` option compatibility from `checkout_main()` into `checkout_paths()`**, where it logically belongs, since these options are only relevant when checking out pathspecs. The **fourth patch extracts initialization, validation, and pathspec handling logic into four new static helpers (`init_checkout_opts()`, `validate_path_options()`, `prepare_common_options()`, and `parse_pathspec_from_file_options()`)**, reducing `checkout_main()`'s complexity by roughly 100 lines while preserving all behavior. The **fifth patch extracts branch setup and tracking logic into three new static helpers (`validate_branch_options()`, `dwim_branch_track_option()`, and `setup_branch_name_and_info()`)** and updates `checkout_main()` to call them, further reducing its complexity by ~50 lines. The **sixth patch eliminates the monolithic `checkout_main()` choke point by rewriting the three command entry points (`cmd_switch()`, `cmd_restore()`, `cmd_checkout()`) to call the extracted utility helpers directly**, placing all callers on equal footing. This patch removes `enum checkout_command` and `checkout_main()`, replacing the shared entry point with direct calls to the extracted helpers (`init_checkout_opts()`, `setup_branch_name_and_info()`, `validate_path_options()`, `prepare_common_options()`, `parse_pathspec_from_file_options()`). The restructuring is mechanical, preserves all behavior, and passes the test suite. The **seventh patch wraps long lines and replaces manual option-compatibility checks with the `die_for_incompatible_optN()` helper macros**, addressing readability issues introduced by earlier patches. This version fixes a typo (`opts->new_new_branch_force` to `opts->new_branch_force`) and preserves the original option-compatibility error messages by reordering the arguments to `die_for_incompatible_optN()`, ensuring no functional impact. The **eighth patch moves `post_checkout_hook()` from `builtin/checkout.c` to the new top-level `checkout.c` and declares it in `checkout.h`**, making it available to other subsystems (e.g., `git worktree`) without depending on built-in command code. Junio’s follow-up to the eighth patch fixed the architectural shortcoming identified in the first iteration: the function now accepts a `struct repository *` parameter and uses `repo->hash_algo` instead of `the_hash_algo`, fully aligning with the series’ goal of making it reusable in non-global contexts. The series is self-contained, uncontroversial, and passes the test suite; the first seven patches could be merged independently if the eighth is deferred. D. Ben Knoble has expressed agreement with the architectural direction outlined in Junio’s follow-up, reinforcing the consensus on the libification path. No objections or alternatives have been raised, but the series remains a discussion starter.
