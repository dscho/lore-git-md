Subject: [PATCH 0/8] builtin/checkout: libify reusable logic and eliminate checkout_main()
Series version: 8-patch series, early draft for illustration, not for merging to `seen`
Originating author: Junio C Hamano
Thread type: architectural refactoring of built-in command internals, direct follow-up to the `the_repository` removal architectural clarification

Core problem or goal
The thread implements the libification path clarified in the parent thread: reusable logic is factored out of the `git checkout`, `git switch`, and `git restore` built-in commands into standalone utility functions that accept a `struct repository *` parameter. The immediate goal is to eliminate the monolithic `checkout_main()` choke point, which was identified as a "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper. The broader goal is to place all callers (built-in commands and external programs) on equal footing by extracting reusable logic into top-level files (`checkout.c`, `checkout.h`) that can be called directly. This aligns with the architectural direction established in the parent thread: built-in commands are not libified, but their reusable internals are.

Current status
Junio’s 8-patch series is now complete as an early draft for illustration, explicitly not intended for merging to `seen` due to potential conflicts with in-flight topics. The series applies cleanly to `master` and passes the test suite. It directly addresses the "cheating" pattern and implements the libification path defined in the parent thread. The first six patches extracted initialization, validation, pathspec handling, and branch setup logic, while the sixth patch eliminated the monolithic `checkout_main()` choke point by rewriting the three command entry points (`cmd_switch()`, `cmd_restore()`, `cmd_checkout()`) to call the extracted utility helpers directly. The seventh patch wrapped long lines and replaced manual option-compatibility checks with the `die_for_incompatible_optN()` helper macros, addressing readability issues introduced by earlier patches. The patch includes a minor typo (`opts->new_new_branch_force` should be `opts->new_branch_force`) that does not affect correctness but would need to be fixed before merging. The eighth and final patch moves `post_checkout_hook()` from `builtin/checkout.c` to the new top-level `checkout.c` and declares it in `checkout.h`, making it available to other subsystems (e.g., `git worktree`) without depending on built-in command code. However, Junio’s self-review of the eighth patch identified a shortcoming: the function still hardcodes `the_repository` and `the_hash_algo`, which undermines the goal of making it reusable in non-global contexts. The fix is straightforward (add a `struct repository *` parameter, use `repo->hash_algo` instead of `the_hash_algo`), and the updated version would fully align with the series’ architectural direction. The series is self-contained, uncontroversial, and passes the test suite; the first seven patches could be merged independently if the eighth is deferred. No objections or alternatives have been raised, but the series remains a discussion starter.
