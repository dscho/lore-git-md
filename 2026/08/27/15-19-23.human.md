This is the second patch in Elijah Newren’s three-patch bugfix series that extends Git’s protection against unsafe commit operations during conflict resolution. The patch blocks `git commit --amend` during conflict stops in `git am`, `git revert`, and all forms of `git rebase`, while carefully preserving the internal use of `--amend` by interactive rebase directives (`squash`, `reword`, `edit`, `break`).

Phillip Wood’s review is substantive but narrowly focused. He notes that the patch improves maintainability by moving detection logic into a separate function and using an `enum` for clarity, calling it “much nicer than the previous version.” His only technical suggestion is to use the existing `rebase_path_stopped_sha()` and `rebase_path_amend()` helpers instead of hardcoding paths in `sequencer.c`, avoiding duplication. This is a minor cleanup, not a correctness concern, and does not affect the patch’s readiness for integration.

The patch itself is well-crafted and uncontroversial. It consolidates logic into a new `sequencer_ongoing_operation()` helper, which distinguishes between genuine conflict stops (where amending would corrupt state) and clean interactive rebase stops (where amending is expected). The error messages are specific to each operation, improving clarity for users. Test coverage is thorough, verifying that `--amend` is blocked during conflict resolution but allowed during clean interactive rebase stops.

The series as a whole is ready for integration, with all prior feedback from Junio C Hamano and Phillip Wood already incorporated. The only remaining loose end is Phillip’s stylistic suggestion about path helpers, which is unlikely to block progress. If you care about conflict-resolution safety or the sequencer subsystem, this patch is worth a quick skim; otherwise, it’s safe to treat as a routine bugfix.
