This is the **third and final patch** in Elijah Newren’s **bugfix series** extending Git’s protection against unsafe commit operations during conflict resolution. It blocks `git commit <paths>` (partial commits) during conflict stops in `git am`, `git revert`, and all forms of `git rebase`, mirroring the protection already in place for `git commit --amend` (introduced in patch 2).

The patch reuses the `sequencer_ongoing_operation()` helper function (added in patch 2) to detect active conflict-resolution states and reject partial commits with clear, operation-specific error messages. The logic is straightforward: conflict resolution requires capturing the *entire* tree state on top of HEAD, so committing only a subset of paths risks corrupting repository state. The patch updates `builtin/commit.c` to check for these states and extends test coverage in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh` to verify the new behavior.

This is a **well-crafted, uncontroversial fix** that addresses a real hazard. The commit message clearly explains the motivation, the code is clean, and the tests cover all affected operations. The series as a whole (patches 1–3) has already incorporated feedback from Junio C Hamano and Phillip Wood, and this patch completes the logical extension of the protection to partial commits. No open questions remain, and the series is likely to be merged soon. If you care about merge/rebase safety or have ever accidentally committed only part of a conflict resolution, this is worth reviewing.
