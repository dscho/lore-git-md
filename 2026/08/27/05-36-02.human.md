This is a surface-level review of the second patch in Elijah Newren’s four-patch v2 series fixing a race condition in Git’s geometric repacking mechanism. The patch itself plugs a memory leak in `git mktree --batch` that was exposed by the new test cases in the series. Jeff King (Peff) notes that the leak slipped through because the test suite lacks coverage for `git mktree --batch` with multiple inputs, a gap dating back to the feature’s introduction in 2009. He suggests adding basic directed tests for the `--batch` mode in `t/t1010-mktree.sh` as a follow-up, calling it a `#leftoverbits` task.

The patch is uncontroversial and ready for merging. It is a small, targeted fix with no behavior change, freeing the entry buffer and its contents before reuse. Peff’s feedback does not challenge the fix itself but highlights a broader testing gap that could be addressed separately. The leak is real but minor (one allocation per tree entry), and fixing it is necessary for the test suite’s reliability. No further changes to this patch are expected.
