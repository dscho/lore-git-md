This is the first patch in the v10 iteration of a four-patch series improving error messages for ambiguous remote branch names in `git checkout`, `git switch`, and `git worktree add`. The series is now functionally complete and was previously merged to `next`; this iteration makes final refinements to function naming, commit message clarity, and code structure.

The patch extracts the advice logic for ambiguous remote branches into a new helper function, `advise_disambiguating_remotes()`, aligning with Git’s naming conventions (the function was previously named `advice_disambiguating_remotes()` in v9). The change also fixes incorrect indentation and reduces nesting in `parse_remote_branch()`, preparing the code for reuse in later patches. The advice message itself remains unchanged: it suggests using `--track` or setting `checkout.defaultRemote` to resolve ambiguity, and is gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default).

The patch touches only `builtin/checkout.c` and is purely refactoring at this stage—no behavior changes are introduced. The extracted function will be reused in subsequent patches to apply the same advice logic to `git worktree add`. Junio’s feedback on v9 (commit message clarity, function naming, and code structure) is fully addressed here, with the renaming and refactoring reflecting the series’ maturity. The change is uncontroversial and prepares the ground for the remaining patches in the series.
