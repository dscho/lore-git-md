This is the **second patch in a 3-patch bugfix series** that extends Git's protection against unsafe commit operations during conflict resolution. Specifically, this patch blocks `git commit --amend` during conflict stops in `git am`, `git revert`, and all forms of `git rebase`, while carefully preserving the internal use of `--amend` by interactive rebase directives (`squash`, `reword`, `edit`, `break`).

The patch introduces a new helper function, `sequencer_ongoing_operation()`, in `sequencer.c`, which consolidates logic for detecting active operations that record their result as a new commit on top of HEAD. This function distinguishes between genuine conflict stops (where amending would corrupt repository state) and clean interactive rebase stops (where amending is expected). The detection relies on the presence or absence of specific files in the `rebase-merge/` directory: `stopped-sha` marks a genuine stop, while `amend` indicates a clean `edit` or `reword` stop.

The patch touches `builtin/commit.c` to extend the existing protection logic, replacing a hardcoded check for merge and cherry-pick with a switch on the new `enum ongoing_operation` returned by `sequencer_ongoing_operation()`. The error messages are specific to each operation, improving clarity for users. Test coverage is added in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh`, verifying that `--amend` is blocked during conflict resolution but allowed during clean interactive rebase stops.

This patch is technically sound and well-motivated, addressing a real hazard (amending the wrong commit during conflict resolution) without disrupting legitimate workflows. The commit message is thorough, explaining the edge cases and the rationale for the on-disk state checks. The new helper function improves maintainability by consolidating logic while preserving separation of concerns between merge and sequencer subsystems. The series as a whole is uncontroversial and ready for integration, with prior feedback from Junio C Hamano and Phillip Wood already incorporated. Key technical details for follow-up discussion: the new `enum ongoing_operation` and `sequencer_ongoing_operation()` function, and the distinction between conflict stops and clean interactive rebase stops.
