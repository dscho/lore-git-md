This is the third patch in the v10 series improving error messages for ambiguous remote branch names in `git worktree add`. The patch extends the advice and error-handling logic introduced in earlier patches to `git worktree add`, ensuring consistent behavior with `git checkout` and `git switch`.

The patch modifies `builtin/worktree.c` to detect when multiple remote branches match the given branch name (e.g., `bar-topic` in both `origin` and `upstream`) and provides a detailed, actionable advice message. The advice lists the conflicting remotes (e.g., "Branch name 'bar-topic' appears in multiple remotes: origin, upstream") and suggests using `--track` or setting `checkout.defaultRemote` to resolve the ambiguity. The error message now includes the number of matching remotes (e.g., "matched multiple (2) remote tracking branches"), replacing the previous generic "invalid reference" error.

The implementation reuses the `advise_disambiguating_remotes()` helper introduced in patch 1/4 and extended in patch 2/4, avoiding code duplication. The `unique_tracking_name()` function is called with a `struct string_list` to collect the names of matching remotes, which are then passed to the advice helper. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and respects the `--quiet` flag, suppressing the message in quiet mode. The patch also narrows the scope of the `oid` variable to the block where it is used.

Test coverage in `t/t2400-worktree-add.sh` verifies the new error message format and advice behavior, including the suppression of advice in quiet mode. The test confirms that `git worktree add` now fails with a clear diagnostic when ambiguity exists, rather than silently proceeding or emitting a misleading error. The patch does not address the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), which remains scoped for a follow-up fix.

The changes are uncontroversial and align with the series' goal of improving usability by providing clearer, more actionable error messages. The patch is well-structured, with a clear commit message and minimal, focused modifications. No open questions or objections remain for this part of the series.
