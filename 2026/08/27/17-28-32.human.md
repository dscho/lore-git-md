This is a refactoring patch that replaces Git’s fixed-arity `die_for_incompatible_optN()` helpers (for N=2,3,4) with a single varargs function `die_for_incompatible_opts()` that can handle any number of mutually exclusive command-line options. The change is purely internal; no user-visible behavior is altered.

The patch is the second iteration of Junio C Hamano’s series, responding to feedback from Elijah Newren and Jeff King. The earlier parameter-reordering patch has been dropped, and the new helper now accepts `<int, const char *>` pairs terminated by `EOF` (-1) instead of a NULL sentinel. This preserves the existing fixed-arity signatures while allowing future callers to pass more than four options. The static inline wrappers for 2–4 options are retained for compile-time safety, and the previously missing `va_end()` call has been added.

Files touched are `parse-options.c` and `parse-options.h`; the helper is plumbing-only and does not affect on-disk formats or user-facing messages. The error-message formatting remains hard-coded to four options to avoid i18n breakage, but the new helper is future-proof for callers that need more. No test failures or edge cases are reported, and the change looks safe and well-scoped.
