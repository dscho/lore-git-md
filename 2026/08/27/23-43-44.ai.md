This is the first patch in Wesley Schwengle’s two-patch series targeting `git-svn`. It is a **bugfix** that eliminates spurious migration noise and empty `.git/svn` directory creation when `git svn info` (or other `git-svn` commands) are run in a plain Git repository with no SVN metadata.

The change defers the "Migrating from a git-svn v1 layout..." message and `.git/svn` directory creation until an actual legacy `refs/remotes/*` candidate is found, aligning the behavior with the existing `migrate_from_v0()` pattern. The fix is confined to `perl/Git/SVN/Migration.pm` and adds a single test in `t/t9107-git-svn-migrate.sh` to verify that the message and directory are suppressed when no migration is needed.

This v2 iteration is identical to v1 except for the typo fix in the error message (addressed in patch 2/2), which was the only feedback received. The patch is narrow, well-motivated, and unlikely to generate controversy. It touches only the Perl migration logic and test suite, with no new symbols or on-disk format changes. The series remains under review but has not attracted substantive technical objections.
