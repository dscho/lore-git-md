This is a **substantive review** of the memory-leak fix in `git mktree --batch` (patch 2/4 in Elijah Newren’s four-patch v2 series). Jeff King (Peff) identifies a gap in Git’s test coverage: the `--batch` mode of `git mktree` has apparently never been tested with multiple inputs, which explains why the leak went unnoticed for 17 years. The feature was introduced in 2009 (commit `f1cf2d8b14`) and has no dedicated test coverage in `t1010-mktree.sh`.

Peff’s feedback is constructive and forward-looking. He acknowledges that Elijah’s new test cases (added in patch 1/4) will incidentally cover the leak scenario, but suggests that a few basic, directed tests for `git mktree --batch` would be a worthwhile addition to the test suite. He labels this as `#leftoverbits` — a low-priority follow-up task rather than a blocker for the current patch. The fix itself (freeing the entry buffer and its contents) is uncontroversial and ready for merging; Peff does not raise any technical concerns about the implementation. The review shifts focus from the patch’s correctness to the broader health of the test suite, signaling an opportunity for future improvement.
