This is a **bugfix and build system enhancement** for `git-svn`, part of Wesley Schwengle’s two-patch series. This v2 iteration addresses the only feedback received on v1: a missing space in an error message (“git-svnexists” → “git-svn exists”).

The series still targets two long-standing `git-svn` pain points:
1. **Patch 1/2 (bugfix)**: Eliminates spurious “Migrating from a git-svn v1 layout…” messages and empty `.git/svn` directory creation when `git svn info` is run in a plain Git repository. The fix defers the message and directory creation until a legacy `refs/remotes/*` candidate is actually found, aligning the behavior with the existing `migrate_from_v0()` pattern. The change is confined to `perl/Git/SVN/Migration.pm` and adds a single test in `t/t9107-git-svn-migrate.sh` to verify the suppression.
2. **Patch 2/2 (build system)**: Introduces a `NO_GIT_SVN=YesPlease` Makefile knob that disables building, installing, and testing `git-svn` entirely. This is useful for users who do not need SVN interoperability and want to reduce build time or avoid Perl dependencies.
