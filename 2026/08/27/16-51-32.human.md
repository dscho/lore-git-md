This is a bugfix and build-system patch for `git-svn`. The author, Wesley Schwengle, reports that running `git svn info` in a plain Git repository (with no SVN metadata) prints a misleading "Migrating from a git-svn v1 layout..." message and creates an empty `.git/svn` directory. The noise appears even when there is nothing to migrate, and it recurs on every invocation until the directory is manually removed.

The first patch silences the bogus migration message by adopting the same pattern already used for v0-layout migration: it checks whether any migration work is actually needed before printing anything. The change is confined to `perl/Git/SVN/Migration.pm` and includes a new test in `t9107-git-svn-migrate.sh`.

The second patch adds a `NO_GIT_SVN=YesPlease` Makefile knob that skips building and installing `git-svn` entirely, along with its SVN-related tests. This is presented as a convenience for users who never interact with Subversion and want a smaller Git installation.

The series is small, self-contained, and addresses a real annoyance. The commit messages are clear, the test coverage is present, and the build-system change is unobtrusive. It looks like a straightforward improvement that should be uncontroversial.
