This is a sweeping refactoring patch from Junio C Hamano that directly addresses the architectural debate blocking the `the_repository` removal effort. The patch replaces the `struct repository *repo` parameter in all built-in command implementations (`cmd_foo()`) with a simple `bool has_repo` flag, eliminating the misguided design introduced in 2024 that attempted to pass `the_repository` as a parameter.

The patch touches 135 files, converting every built-in command in `builtin/` to use the new signature. The core idea is that built-in commands are inherently tied to `the_repository` and cannot meaningfully operate on arbitrary repositories, so passing a `struct repository *` is misleading and invites segfaults when commands are run outside a repository (e.g., `git foo -h` from `/`). The new `bool has_repo` flag lets commands detect whether they were invoked inside a repository without exposing the global variable or requiring NULL checks.

Junio’s commit message is clear: this is not just a cleanup but a strategic reversal. The earlier design was "wasteful makework" that did not advance libification, and the effort to incrementally convert built-in commands to use the `repo` parameter is now abandoned in favor of this architectural fix. The patch also updates documentation examples (`MyFirstContribution.adoc`, `MyFirstObjectWalk.adoc`) to reflect the new signature, ensuring new contributors follow the correct pattern.

The patch applies cleanly to `master` and passes the test suite, but Junio notes it may be tricky to merge due to its size and scope. This is the definitive direction for the `the_repository` removal effort in built-in commands: future work should focus on removing the `repo` parameter entirely rather than propagating it. The broader effort to eliminate `the_repository` will now proceed along two tracks: this architectural cleanup for built-in commands, and incremental conversions for utility functions outside `builtin/`.
