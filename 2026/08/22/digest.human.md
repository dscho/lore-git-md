# Git mailing list daily digest for 2026/08/22

## The day in brief

The Git mailing list saw active discussion on several fronts today. A long-standing discrepancy between `git config --global` documentation and behavior moved closer to resolution with a v2 patch series in progress. Meanwhile, a policy debate emerged over AI-generated contributions, blocking a technically complete `utimensat()` migration series. A usability improvement for ambiguous remote branch names was approved for `next`, and a new bug report highlighted a subtle interaction between `git subtree add --squash` and `git rebase`.

## Notable threads

### `git config --global` reads only one file despite docs claiming it reads both

Delilah Ashley Wu confirmed she is preparing a v2 patch series to align `git config --global` with its documentation by making it read both `~/.gitconfig` and the XDG config file (`~/.config/git/config`). The change targets the configuration subsystem (`config.c`) and modifies `git_global_config()` to delegate to `do_git_config_sequence()`, matching the behavior of `git config --get --global`. Delilah committed to testing both `git config --get --global` and `git config list --global` to ensure cross-command consistency.

This bugfix addresses a long-standing inconsistency that has caused user confusion and practical failures in tools relying on `--global`. The v2 series will include tests to verify the new behavior, specifically ensuring cross-command consistency between `--get --global` and `list --global`. The series is the most concrete step toward resolution to date, though maintainer approval remains uncertain.

### Policy debate blocks `utimensat()` migration series

A technically complete patch series to replace deprecated `utime()` with `utimensat()` for POSIX.1-2024 compatibility is now blocked by a policy debate over AI-generated contributions. brian m. carlson raised a process objection, citing the Git project's `SubmittingPatches` policy and the Developer Certificate of Origin's requirement for contributors to know the origin of their code. The series was generated by an AI tool (Gemini Flash) and manually verified, but the policy currently prohibits significant AI-generated content due to legal and ethical concerns.

Junio C Hamano acknowledged the legal risks, noting that accepting AI-generated work could expose the project to future legal costs if the code is later found to infringe. brian m. carlson reinforced the legal rationale, citing active global litigation around LLM outputs and the risk of copyright infringement from training data. The discussion now centers on balancing legal caution against the practical reality of contributor trust, with no resolution in sight. The series cannot proceed until the Project Leadership Committee or broader community clarifies or amends the AI-generated content policy.

### Usability improvement for ambiguous remote branch names merged to `next`

Junio C Hamano approved and queued a v7 series improving user-facing error messages for `git worktree add`, `git checkout`, and `git switch` when an ambiguous remote branch name is provided. The series replaces the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message listing conflicting remotes (e.g., "Branch name 'foo' appears in multiple remotes: origin, upstream"). The advice is controlled by the new `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and is consistent across all three commands.

The implementation introduces a new `advise_disambiguating_remotes()` helper and extends `unique_tracking_name()` to optionally collect remote names. Junio praised the revised advice message as "much more concise" and approved two minor fixes: correcting a grammatical error and narrowing the scope of the `oid` variable in `builtin/worktree.c`. The series is now cooking in `next`. Junio also identified a latent bug in `git worktree add`'s one-argument form, which should error out when ambiguity exists, but this remains a non-blocking follow-up item.

## In brief

- **`contrib/credential/libsecret` crash and silent data loss**: Daniel Martí reiterated his design preference for replacing the two-step (SearchItems + GetSecrets) process with a single SearchItems call plus one explicit GetSecret, ensuring all errors are surfaced in a single code path. The discussion remains focused on design trade-offs between optimization and reliability.
- **`git subtree add --squash` followed by `git rebase` produces spurious conflict**: Gabriel Ford reported a new bug where `git subtree add --squash` followed by `git rebase` produces a spurious conflict between identically named files in separate directories. The issue is reproducible with minimal steps and appears to stem from how the squash merge records history. No patches or workarounds have been proposed yet.
