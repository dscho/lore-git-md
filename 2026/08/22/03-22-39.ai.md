This is the seventh iteration (v7) of a three-patch series improving user-facing error messages for `git worktree add`, `git checkout`, and `git switch` when an ambiguous remote branch name is provided. The series is now functionally complete and ready for merging, with only minor grammatical fixes applied since v6.

The goal remains unchanged: replacing the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message that lists the conflicting remotes (e.g., "Branch name 'foo' appears in multiple remotes: origin, upstream"). The advice is controlled by the new `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and is consistent across all three commands. The series also moves an existing `die()` call earlier in the code path to replace a generic "invalid reference" error with a more specific diagnostic that explains the ambiguity, without altering `dwim_branch()`'s return behavior.

Key technical details include the new `advise_disambiguating_remotes()` helper (introduced in patch 1/3 and applied to `checkout`/`switch` in patch 2/3, then extended to `worktree add` in patch 3/3), the extension of `unique_tracking_name()` to optionally collect remote names via `struct string_list *dwim_remote_names`, and updated test coverage in `t/t2400-worktree-add.sh`. The grammatical error in the advice message ("Branches ... appears") has been fixed in both patch 2/3 and 3/3, and the scope of the `oid` variable in `builtin/worktree.c` has been narrowed.

The series touches `builtin/worktree.c`, `builtin/checkout.c`, `checkout.c`, `checkout.h`, and the test script. Junio C Hamano and D. Ben Knoble have reviewed the changes, and all structural adjustments (renaming helpers, splitting patches) are complete. The one-argument `git worktree add` edge case (e.g., `git worktree add ../topic-branch`) is intentionally excluded from disambiguation logic, as the command succeeds in this scenario due to `--guess-remote` or `worktree.guessremote=true`. Junio suggests adding a code comment near the `dwim_branch()` call in this path to flag it for future reconsideration, but this is non-blocking.

This is a usability improvement with no behavioral regressions, as the commands were already failing—just with less clarity. The implementation is localized, well-tested, and follows Git’s advice-message conventions. The series looks ready for `next`.
