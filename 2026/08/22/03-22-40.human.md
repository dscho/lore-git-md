This is the first patch in a three-part series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. It extracts the advice logic into a new helper function, `advice_disambiguating_remotes()`, to avoid code duplication and prepare for reuse in `git worktree add` (covered in patch 3/3).

The change is purely refactoring: it moves the existing advice message from `parse_remote_branch()` into a dedicated function, parameterized by the command type (`checkout` or `switch`). The advice itself remains unchanged, offering users guidance on resolving ambiguity with `--track` or `checkout.defaultRemote`. The patch touches only `builtin/checkout.c` and is mechanical in nature, with no behavioral changes.

This is a clean, well-motivated refactor that sets the stage for the series’ core improvements. The commit message is clear, and the code follows Git’s conventions.
