This is a bug report about `git subtree` and `git rebase` interacting poorly when a file in the main repository shares a path with a file in the vendored subtree.

The reporter, Gabriel Ford, describes a minimal reproduction: create a repository with a `.clang-format` file, vendor a library (which also contains a `.clang-format` file) using `git subtree add --squash`, then attempt to rebase the feature branch onto `master`. The rebase fails with a conflict between the two `.clang-format` files, even though they are in different directories and the main repository’s file was never modified.

The reporter speculates that the conflict arises because `git subtree` squash-merges the subtree’s history, causing Git to treat the two files as related despite their different paths. The expected behavior is that no conflict should occur, since the main repository’s file was unchanged.

The report is clear, includes a complete reproduction script, and provides system details (Git 2.55.0, Linux, Rust enabled). This looks like a real edge case worth investigating, though it may not affect many users. The issue is well-documented for a first-time bug report.
