This is the first patch in the v7 series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. It extracts the advice message logic into a new shared helper function, `advice_disambiguating_remotes()`, to avoid code duplication and prepare for reuse in `git worktree add` (covered in patch 3/3).

The patch moves the advice block from `parse_remote_branch()` into a standalone function that takes the `checkout_command` enum as an argument, allowing it to tailor the message for either `checkout` or `switch`. The advice itself remains unchanged: it suggests using `--track` or setting `checkout.defaultRemote` to resolve ambiguity. The `die()` call that follows the advice is left in place, preserving the existing error behavior (now with a slightly cleaner code structure).

This is a pure refactoring with no functional changes. The commit message is minimal, but the purpose is clear from the context of the series. The patch touches only `builtin/checkout.c` and is well-scoped. No new tests are needed here, as the behavior is unchanged. The extraction sets the stage for the more substantive changes in patches 2/3 and 3/3.
