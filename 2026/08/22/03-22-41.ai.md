This is the second patch in Yoichi NAKAYAMA’s v7 series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. It builds on the refactoring introduced in patch 1/3 by applying the new `advise_disambiguating_remotes()` helper to the checkout code path, replacing the terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message that lists the conflicting remotes (e.g., "Branch name 'foo' appears in multiple remotes: origin, upstream").

The patch extends `unique_tracking_name()` to optionally collect remote names via a new `struct string_list *dwim_remote_names` parameter, allowing the caller to access the list of matching remotes. This list is then passed to `advise_disambiguating_remotes()`, which emits the advice message tailored to the command (`checkout` or `switch`). The advice suggests using `--track <remote>/<branch>` or setting `checkout.defaultRemote` to resolve future ambiguity. The patch also moves the `die()` call earlier in the code path to replace the generic "invalid reference" error with a more specific diagnostic that includes the number of matching remotes (e.g., "matched multiple (2) remote tracking branches"), without altering `dwim_branch()`'s return behavior.

Files touched include `builtin/checkout.c` (where the advice logic is applied), `checkout.c` (where `unique_tracking_name()` is extended), and `checkout.h` (updated function signature). The grammatical error in the advice message ("Branch name '%s' appears in multiple remotes:") has been fixed here, matching the correction in patch 3/3. The patch is well-scoped, with no functional changes beyond the improved messaging, and the implementation follows Git’s advice-message conventions. Junio C Hamano and D. Ben Knoble have reviewed the changes, and all structural adjustments are complete. This patch is ready for `next` as part of the series.
