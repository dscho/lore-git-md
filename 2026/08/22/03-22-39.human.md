This is the seventh iteration of a three-patch series improving user-facing error messages for `git worktree add`, `git checkout`, and `git switch` when an ambiguous remote branch name is provided. The series is now ready for merging, with only minor grammatical fixes applied since v6.

The goal is to replace Git’s terse "matched multiple remote tracking branches" warning with clear, actionable advice. When a user runs a command like `git worktree add ../foo bar-topic` and both `origin/bar-topic` and `upstream/bar-topic` exist, Git now explains the ambiguity and suggests concrete fixes: either use a fully qualified branch name (`origin/bar-topic`) or set `checkout.defaultRemote` in their Git config. The advice is controlled by the new `advice.checkoutAmbiguousRemoteBranchName` setting, which defaults to true.

The implementation is shared across all three commands via a new helper function, `advise_disambiguating_remotes()`, introduced in patch 1. Patch 2 applies this to `git checkout` and `git switch`, while patch 3 extends it to `git worktree add`. The series also refines error handling by moving an existing `die()` call earlier in the code path, replacing a generic "invalid reference" message with a more specific diagnostic that explains the ambiguity. This change is well-justified in the commit message, which traces the problematic flow (silent failure to resolve ambiguity → `NULL` remote → misleading error).

Key technical details include the extension of `unique_tracking_name()` to optionally collect remote names via a `struct string_list`, and the addition of test coverage in `t/t2400-worktree-add.sh` to verify the new advice format and error-handling behavior. The series handles edge cases: it skips disambiguation logic for fully qualified branch names (e.g., `origin/bar-topic`) and for the one-argument `git worktree add` case (e.g., `git worktree add ../topic-branch`), where the command succeeds even with ambiguity due to `--guess-remote` or `worktree.guessremote=true`.

Junio C Hamano and D. Ben Knoble have reviewed the series and agreed on all adjustments. The only remaining action items are cosmetic: fixing a grammatical error in the advice message ("Branch name '%s' appears in multiple remotes:") and adding a suggested code comment near the `dwim_branch()` call in the one-argument `worktree add` path. The series is a straightforward usability improvement with no known downsides.
