This is the second patch in Yoichi NAKAYAMA’s three-patch series (v7) improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. It builds on the shared helper introduced in patch 1/3 and implements the core usability improvement: replacing the terse "matched multiple remote tracking branches" warning with a detailed advice message that lists the conflicting remotes (e.g., "Branch name 'foo' appears in multiple remotes: origin, upstream").

The patch extends `unique_tracking_name()` to optionally collect remote names via a new `struct string_list *dwim_remote_names` parameter, then uses this list in the updated `advise_disambiguating_remotes()` helper to print the remotes involved. The advice message is gated behind the new `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and includes actionable suggestions like using `--track` or setting `checkout.defaultRemote`. The commit message justifies moving an existing `die()` call earlier in the code path to provide a more specific diagnostic, replacing a generic "invalid reference" error with one that explains the ambiguity.
