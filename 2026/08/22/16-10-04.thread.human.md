This thread is a bug report from Gabriel Ford about a surprising interaction between `git subtree add --squash` and `git rebase`. When you vendor an external repository that contains a file with the same *relative* path as an existing file in your main repository (for example, both have a `.clang-format` at their root), and then rebase the branch that introduced the subtree onto `master`, Git reports a conflict between the two files—even though they live in completely different directories (the main repo root and the subtree prefix). The reporter provides a minimal reproduction case and confirms the issue exists on Git 2.55.0.

The root cause appears to be how `git subtree` performs the squash merge: it collapses the external repository’s history into a single commit, but the relative paths of the conflicting files end up looking identical to Git’s merge machinery during rebase. No prior discussion or related fixes are mentioned, so this is the first time the issue has been raised. The thread is currently just the initial report; no reviews, patches, or maintainer responses have appeared yet.
