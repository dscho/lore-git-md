This is a refactoring patch in the revision-walking subsystem, specifically touching Bloom filter logic. It is the first patch in Toon Claes’s six-patch series “speed up last modified” (v3).

The patch moves the `revs->bloom_keyvecs_nr != 0` precondition from the two external callsites into `check_maybe_different_in_bloom_filter()` itself. The change is purely mechanical: the guard is now inside the helper, so the callers no longer need to repeat it. The commit message notes that the new return value of -1 when no key vectors exist is unobservable to users, because Bloom statistics are only reported when key vectors were actually set up.

Code impact is confined to `revision.c`; the diff is seven lines (five insertions, two deletions). No behavior change is claimed or expected.
