This is the v9 iteration of the patch series introducing `--linearize` to `git replay`, a feature that flattens merge commits into a linear history. The series is now focused on **documentation and commit message polish** after addressing all prior technical feedback in v8. The core implementation remains unchanged from v8, which resolved the blocking "multi-branch ambiguity" by restricting `--linearize` (and now also `--revert` and `--advance`) to single-branch usage.

The key changes in v9 are **terminology tweaks**: replacing "multiple revision ranges" with "multiple branches" in error messages and documentation, and rewording the rationale for the single-branch restriction to be more user-friendly (e.g., "Due to current implementation limitations..." instead of a technical explanation). These adjustments address feedback from Justin Tobler and Elijah Newren in v8, who argued for clearer UX language. The commit message and `Documentation/git-replay.adoc` have been updated accordingly, and tests verify the new error messages.

The series remains a **three-patch refactoring + feature addition**:
1. **Patch 1/3**: Introduces `put_mapped_commit()` to encapsulate logic for tracking replayed commits (pure refactoring).
2. **Patch 2/3**: Moves replay base resolution out of `pick_regular_commit()` (pure refactoring).
3. **Patch 3/3**: Implements `--linearize` with the single-branch restriction and updated documentation.

**Technical details**:
- **Restrictions**: `--linearize` cannot be used with multiple branches or `--contained` (error messages updated in v9).
- **Behavior**: Merge commits are dropped, and subsequent commits are reparented onto the last non-merge commit, ensuring a single linear history. This differs from `git rebase --no-rebase-merges` (documented and tested).
- **Compatibility**: `--linearize` can be combined with `--revert` (mutual exclusivity removed in v7), but not with `--advance`.
- **Files touched**: `replay.c`, `replay.h`, `builtin/replay.c`, `Documentation/git-replay.adoc`, and `t/t3650-replay-basics.sh`.
- **Test coverage**: New tests verify the multi-branch and `--contained` restrictions, alongside existing coverage for edge cases (e.g., replaying to root, `--advance` compatibility).

**Status**: The series is **technically complete** and ready for integration. Junio removed the previous version from `next` and will queue v9 for review, but it has not yet been merged to `next`. The only remaining open question is whether `--linearize` should eventually support per-branch linearization (e.g., via `--ref` syntax), but this is deferred. Potential trivial conflicts with Kristoffer’s documentation changes and Patrick Steinhardt’s `git history drop` series are noted.
