This is a bug report about inconsistent validation of branch names. The author, Bence Csókás, points out that while `git check-ref-format` correctly rejects the single-character `@` as an invalid ref name, the porcelain commands (`git checkout -b`, `git switch -c`, and `git branch`) all allow creating a branch named `@`. This violates the documented rule that `@` is not a valid branch name.

The inconsistency is traced to `git check-ref-format --branch`, which incorrectly accepts `@` as valid, suggesting the bug lies in the branch-specific validation logic rather than the general ref validation. Once created, the `@` branch behaves strangely—`git checkout @` does nothing—but can still be deleted with `git branch -d @`.

The report is clear and includes reproduction steps, making it easy to verify. The issue appears well-scoped and uncontroversial: the code should either reject `@` consistently or update the documentation to reflect that it is allowed. No prior discussion or patch series is referenced, so this is likely a new finding. Worth attention from anyone maintaining the ref validation subsystem.
