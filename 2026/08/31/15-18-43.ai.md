This is the third patch in Toon Claes’s six-patch v3 series that speeds up the experimental `git last-modified` command by reusing Git’s Bloom filters. It adds a new helper function, `bloom_filter_contains_any_vec()`, to the Bloom filter API in `bloom.c` and `bloom.h`.

The helper answers a different question than the existing `bloom_filter_contains_vec()`: instead of reporting whether *all* keys in a vector are present (which proves the path *might* have changed), it reports whether *any* key is present (which proves the path *or any of its parent directories* might have changed). This is exactly what `git last-modified --show-trees` needs when it wants to know if a directory hierarchy was touched, even if the exact file wasn’t.

The implementation is a simple loop over the key vector that returns 1 as soon as any key is found in the filter. There are no callers in this patch; the next patch in the series will wire it up inside `revision.c`. The commit message explains the motivation clearly and gives an example of why the existing helper would give false negatives for directory queries. The patch is small (23 lines), well-scoped, and ready for review.
