This is a substantive review of a bug report about inconsistent branch name validation in Git's porcelain commands.

D. Ben Knoble engages directly with the technical issue reported by Bence Csókás. He confirms the core observation: porcelain commands like `` `git checkout -b @` `` create a branch named `@` despite `` `git check-ref-format` `` rejecting it, and traces the inconsistency to `` `git check-ref-format --branch` `` incorrectly accepting `@` as valid. Knoble reproduces the behavior and notes that while the resulting ref (`refs/heads/@`) is syntactically allowed, it is confusing because `@` is also the shorthand for `HEAD`. He observes that `` `git switch @` `` fails (interpreting it as `HEAD`), and that manual manipulation of `.git/HEAD` is required to check out the branch, which he describes as "yikes" — signaling that this is not just a cosmetic issue but a usability trap.

The review is substantive: Knoble identifies the exact validation logic (`--branch` mode in `check-ref-format`) that needs alignment, and suggests that stricter validation in that mode would be appropriate. He does not merely point out the inconsistency but frames it as a design question: whether `--branch` mode should be stricter than general ref validation. This moves the discussion from "is this a bug?" to "how should we fix it?" — a clear step forward in the thread. No prior context is missing; the review stands on its own.
