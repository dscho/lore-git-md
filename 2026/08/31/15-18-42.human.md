This is a refactoring patch that exposes Bloom filter path-checking logic for reuse by other Git built-ins. It is the second patch in Toon Claes’s six-patch series (v3) aimed at speeding up the experimental `git last-modified` command.

The patch splits the existing internal function `check_maybe_different_in_bloom_filter()` into two parts. The new public function `revs_maybe_changed_in_bloom()` takes a pre-loaded `struct bloom_filter` and returns a simple boolean: false if the commit definitely did not touch any of the paths in the revision’s pathspec, true if it might have. The old function remains as a thin wrapper that still handles the Bloom-filter lookup and statistics counting.

The motivation is efficiency: a future patch in the series will reuse this logic, and the caller already has the Bloom filter in hand, so a redundant lookup is avoided. The change is mechanical and does not alter behavior; it merely makes the filtering logic available outside `revision.c`.
