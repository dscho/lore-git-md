This is patch 6/10 in Patrick Steinhardt’s v2 series refactoring `git fsck` to make ODB consistency checks pluggable. The patch moves packfile verification from `builtin/fsck.c` into the packed ODB backend (`odb/source-packed.c`), eliminating 33 lines of code from the command-level logic and adding 46 lines to the backend. It threads the progress meter and object callback through the new `struct odb_fsck_options` so the caller’s preferences are respected without exposing backend details. The patch also simplifies error reporting by replacing the undocumented `ERROR_PACK` bit with the generic `ERROR_OBJECT` bit, which is already used elsewhere in the codebase.

The change is mechanical and well-contained: the packfile verification logic is lifted verbatim from `cmd_fsck()` and adapted to work within the packed ODB backend’s context. The progress meter logic is preserved, and the new `verify_packs()` helper mirrors the old loop over `repo_for_each_pack()`. The patch does not alter behavior—it merely relocates code and replaces one error bit with another. The commit message clearly explains the rationale for dropping `ERROR_PACK` (undocumented, untested, and backend-specific) and the choice to use `ERROR_OBJECT` instead.

This is a clean, incremental step in the larger ODB abstraction effort. The patch is part of a well-reviewed series that has already addressed all feedback from v1, and the relocation pattern here matches what later patches will do for reverse-index, bitmap, MIDX, and loose-object verification. No open questions or edge cases are raised by this patch; it looks like a straightforward refactoring that prepares the codebase for future pluggable ODB backends.
