Subject: Inconsistent branch name validation in porcelain commands
Series version: N/A (bug report)
Originating author: Bence Csókás
Thread type: bug report

Core problem or goal
Git’s porcelain commands (`checkout -b`, `switch -c`, `branch`) allow creating a branch named `@`, even though `@` is rejected by `git check-ref-format` as an invalid ref name. The inconsistency stems from `git check-ref-format --branch` incorrectly accepting `@` as valid. The branch cannot be checked out afterward (due to `@` being interpreted as `HEAD`) but can be deleted, creating a usability trap.

Current status
Under review. No prior versions or related patch series. The report is self-contained and includes reproduction steps.

Key technical details
- Commands affected: `git checkout -b @`, `git switch -c @`, `git branch @`
- Validation discrepancy: `git check-ref-format` (without `--branch`) rejects `@`; `git check-ref-format --branch` accepts it
- On-disk consequence: branch ref `refs/heads/@` is created but cannot be checked out via porcelain commands (e.g., `git switch @` fails, interpreting `@` as `HEAD`)
- Subsystem: ref name validation logic in `refs.c` and `check-ref-format.c`
- Usability impact: manual manipulation of `.git/HEAD` is required to check out the branch, described as a "yikes" moment by reviewer

Open questions and loose ends
- Design question: Should `--branch` mode in `check-ref-format` enforce stricter validation to align with general ref validation, or is there a deliberate reason for the current leniency?
