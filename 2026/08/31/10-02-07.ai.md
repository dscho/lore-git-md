This is the third patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch refactors the `--reference` and `--reference-if-able` logic in `git clone` to prepare for consolidating alternates setup into a single code path.

The patch renames `setup_reference()` to `collect_alternates()` and changes its behavior to gather alternates paths into a `strvec` instead of immediately writing them to the ODB. This is a pure refactoring with no user-visible behavior change, but it introduces new structures (`struct add_one_alternate_data`) and helper functions (`add_one_alternate()`) to track whether an alternate is required or optional. The collected alternates are later written to the ODB in `cmd_clone()` via `odb_add_to_alternates_file()`, preserving the existing behavior while centralizing the alternates logic.

The patch touches only `builtin/clone.c` and is mechanically straightforward, replacing direct ODB writes with deferred collection. The new `collect_alternates()` function is clearer about its purpose (collecting paths) than the old `setup_reference()` (which misleadingly suggested ref handling). The change is well-motivated by the series’ goal of simplifying the ODB interface, though the immediate benefit is limited to code organization. No test changes are needed, as the behavior remains identical.

This patch is a prerequisite for later changes in the series, particularly patch 6 (which introduces `odb_create_on_disk_options` for writing alternates during ODB creation) and patch 7 (which removes manual alternates writing in `cmd_clone()`). The refactoring is uncontroversial and aligns with the broader ODB abstraction effort, though its value will become clearer in the context of the full series. No review feedback has surfaced yet, but the patch is likely to be uncontested given its narrow scope and clear purpose.
