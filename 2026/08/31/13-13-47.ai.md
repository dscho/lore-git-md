This is the first patch in the v9 series introducing `--linearize` to `git replay`. It is a **refactoring** that extracts the logic for storing rewritten commits into a new helper function, `put_mapped_commit()`, and renames the existing `mapped_commit()` to `get_mapped_commit()` for symmetry. The changes are purely internal and preparatory for the `--linearize` feature in patch 3/3.

The patch touches only `replay.c`, moving 11 lines of code into a new helper and updating all callers to use the renamed function. The motivation is to reduce duplication and improve clarity in `replay_revisions()`, which is described as "rather lengthy." The new `put_mapped_commit()` helper encapsulates the logic for inserting a commit into the `replayed_commits` map, including the BUG check for duplicate commits. The rename from `mapped_commit()` to `get_mapped_commit()` makes the pairing with the new function more intuitive.

This refactoring was previously debated in v2–v5 of the series, with Patrick Steinhardt and Justin Tobler questioning an earlier enum-based approach. The current design (a simple boolean-based helper) was settled on in v5 and has not changed since. The patch is **non-controversial** and serves as a clean foundation for the `--linearize` implementation in patch 3/3. No behavior changes are introduced, and the commit message clearly states the goal: "Extract the logic to put a commit entry into a `struct mapped_commits` into a helper function."
