This is the **second patch in a seven-part bugfix/hardening series** targeting the trace2 subsystem. It directly addresses the root cause of the "recursion detected in die handler" crashes by replacing `xsnprintf()` with `snprintf()` in timestamp formatting functions, ensuring that trace2 operations degrade gracefully under system call failures (e.g., `gettimeofday()`, `gmtime_r()`, or `snprintf()` errors) instead of crashing Git.

The patch modifies `trace2/tr2_tbuf.c` to:
1. Initialize `timeval` and `tm` structs with zero values, allowing failed system calls to leave them in a predictable state.
2. Replace `xsnprintf()` with `snprintf()` and add explicit error handling. On failure, the code falls back to hardcoded timestamps (e.g., `"1900-00-00T00:00:00.000000Z"`), which are intentionally invalid to signal degraded operation to trace consumers.
3. Extend `banned-die.h` to block `xsnprintf()` in trace2, preventing future regressions.

**Key technical details:**
- **Behavior change:** Trace2 now tolerates system call failures in timestamp formatting by falling back to static strings, avoiding crashes. This is a breaking change for trace consumers, who may see malformed timestamps, but the trade-off is intentional.
- **Platform focus:** The issue was most acute on Git for Windows, where `libintl_vsnprintf()` allocates memory for positional arguments (like those in the datetime format string), but the fix applies to all platforms.
- **Test coverage:** No dynamic tests for system call failures (hard to reproduce), but the patch is motivated by real-world crash reports and aligns with the series' goal of eliminating `die()`-triggering helpers from trace2.

**Review context:**
- This patch is **well-motivated and technically sound**. It addresses a real stability problem (recursive `die()` calls during `atexit` events) with a minimal, defensive approach. The fallback timestamps are a pragmatic solution that prioritizes process stability over telemetry completeness.
- **No known issues:** The patch incorporates feedback from v2 (e.g., zero-initialization of structs) and avoids the pitfalls of earlier iterations (e.g., off-by-one errors in string handling).
- **Dependencies:** Relies on the first patch's `banned-die.h` mechanism to enforce the `xsnprintf()` ban. The series' later patches extend this pattern to other `die()`-prone helpers (e.g., `xstrdup()`, `ALLOC_ARRAY()`).
