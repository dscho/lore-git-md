This is the seventh patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch wires up the new `odb_create_on_disk_options` mechanism introduced in earlier patches, eliminating the last direct use of `odb_add_to_alternates_file()` in `cmd_clone()`.

The change is mechanical: `create_object_database()` now accepts a `strvec` of alternates paths (collected by `collect_alternates()` in the preceding patches) and passes them to the ODB backend via the `odb_create_on_disk_options` struct. This consolidates alternates setup into a single step during ODB creation, replacing the manual loop that previously wrote each alternate to the `info/alternates` file. The patch removes 6 lines from `builtin/clone.c` and updates `setup.c` to pass the alternates `strvec` to `create_object_database()`, while preserving the existing behavior of passing `NULL` when no alternates are specified (e.g., during `init_db()`).

No user-visible behavior changes are expected, and the patch is a straightforward integration of the refactoring work done in patches 1–6. The commit message clearly ties the change to the broader goal of making alternates an ODB backend implementation detail, which will simplify future ODB abstraction work. The patch is well-motivated and aligns with the series’ design, though its correctness depends on the earlier patches (particularly patch 6, which introduced the lockfile API for atomic alternates writes).

The diff is minimal and focused, touching only `builtin/clone.c`, `setup.c`, and `setup.h`. The updated `create_object_database()` signature is the only new symbol introduced here, and the change is backward-compatible with existing callers (e.g., `init_db()`) via the `NULL` alternates parameter.
