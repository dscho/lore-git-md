This is the latest installment in the long-running `git replay --linearize` feature series, now at v8. Toon Claes responds to Elijah Newren’s and Justin Tobler’s UX-focused review of patch 3/3, agreeing to simplify the documentation and error messages but pushing back on one technical suggestion.

The patch adds a `--linearize` option to `git replay` that flattens merge commits, producing a linear history. This v8 iteration restricts `--linearize` (and now also `--revert`) to single-branch usage to avoid concatenating unrelated histories, resolving the multi-branch ambiguity that had blocked earlier versions. The series is technically complete, addresses all prior feedback, and is ready for review, though Junio has not yet merged it to `next`.

Toon accepts the proposed documentation changes: replacing the technical explanation of emergent reachability issues with a simpler “multiple branches are not supported” statement, and using “branches” instead of “revision ranges” in error messages. These tweaks should improve clarity without altering functionality. However, Toon rejects Elijah’s suggestion to extend the single-branch restriction to `--revert` mode, pointing out that the restriction is already enforced for both `--revert` and `--advance` via the shared `set_up_branch_mode()` helper. This leaves the door open for future work on per-branch linearization (e.g., via `--ref` syntax) but keeps the current implementation simple and predictable.

The thread remains in active review, with no objections to the core logic. Minor documentation and error-message refinements are the only expected changes before the series graduates to `next`.
