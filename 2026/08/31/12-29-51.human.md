This is the first patch in Derrick Stolee’s seven-part series hardening the trace2 subsystem against crashes caused by `die()`-triggering functions. The patch introduces `banned-die.h`, a new header that blocks functions like `die()`, `xsnprintf()`, and `xstrdup()` at compile time to prevent Git from crashing during telemetry operations.

Elijah Newren’s review of this patch raised two technical concerns: a naming inconsistency (`banned(die)` instead of `BANNED(die)`) and an include-ordering risk (placing `banned-die.h` in the middle of the include list in `trace2.c`). Derrick acknowledges both issues in this reply. The naming fix is trivial, but the include-ordering risk is subtler—future includes added after `banned-die.h` could silently bypass enforcement. While the header’s documentation warns about this, Derrick agrees a comment in `trace2.c` would help.

The patch itself is well-motivated and addresses a real problem: trace2 operations (like timestamp formatting) can crash Git if memory allocations or system calls fail, particularly on Git for Windows. The hardening is part of a broader effort to make telemetry more resilient, though Jeff King’s later review questions whether the compile-time ban is sufficient, given that helpers like `strbuf` and `json-writer.c` can still trigger `die()` indirectly. For now, this patch is a pragmatic first step, and the fixes Derrick describes here will likely appear in a v3. The series remains under active review, with no fundamental objections to the goal.
