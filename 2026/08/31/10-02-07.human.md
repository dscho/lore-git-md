This is the third patch in Patrick Steinhardt’s eight-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort, which aims to simplify the ODB interface by making alternates an implementation detail of the backend.

This patch refactors the handling of `--reference` and `--reference-if-able` options in `git clone`. The existing `setup_reference()` function is renamed to `collect_alternates()` to better reflect its purpose—collecting alternate object store paths rather than setting up references (which could be misleading). The function now gathers all alternate paths into a `strvec` instead of immediately writing them to the ODB. This prepares the codebase for later patches where alternates will be written during ODB creation rather than piecemeal.

The changes are mechanical and well-motivated, with no user-visible behavior changes. The patch introduces a new `add_one_alternate_data` struct to track whether an alternate is required or optional and to hold the `strvec` of paths. The `add_one_reference()` function is renamed to `add_one_alternate()` and updated to push paths into the `strvec` instead of directly writing them to the alternates file. The `cmd_clone()` function is adjusted to call `collect_alternates()` and then iterate over the collected paths to write them to the ODB, maintaining the existing behavior for now.

The patch is clean and aligns with the series’ goal of consolidating alternates logic into a single code path. It sets the stage for patch 6, which will introduce the `odb_create_on_disk_options` struct to handle alternates during ODB creation, and patch 7, which will remove the manual alternates writing step entirely. The refactoring is a necessary step toward simplifying the ODB interface and improving safety by deferring ODB setup until after all alternates are resolved.
