This is a review of Harald Nordgren’s v2 patch that refines `git checkout -m` autostash conflict handling. Junio C Hamano’s feedback identifies a correctness issue in the patch’s logic for detecting conflicts during stash application.

The patch currently treats any non-zero return from `run_command()` as a conflict, but `git stash apply` can fail for many reasons (command not found, crash, permission error) that are not conflicts. The correct signal for a conflict is a specific positive exit code from `git stash apply`, which the patch does not currently distinguish. Junio outlines a three-step plan to fix this: audit all `git stash` subcommands’ return conventions, adjust the exit code handling in `cmd_stash()` to preserve the conflict signal, and document the exit status semantics. He suggests that for expediency the patch could initially assume all failures are conflicts, but notes that this is technically incorrect and should be documented as a known limitation.

The review is substantive: it identifies a real correctness gap, traces the code path through `builtin/stash.c`, and proposes a concrete fix. The patch will need a v3 to address this issue before it can be merged. No other objections are raised; the feedback is narrowly focused on the conflict detection logic.
