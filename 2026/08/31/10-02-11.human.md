This is the seventh patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort and aims to simplify the ODB interface by removing the ability to write alternates after repository creation.

This patch wires up the new mechanism introduced in earlier patches, replacing the manual alternates writing step in `cmd_clone()` with a single call to `create_object_database()`. The function now accepts a `strvec` of alternates paths via the `odb_create_on_disk_options` struct, consolidating alternates setup into the ODB creation process. The change removes the last direct use of `odb_add_to_alternates_file()` in `builtin/clone.c`, completing the shift to writing alternates at creation time.

The patch is small and mechanical, touching only `builtin/clone.c`, `setup.c`, and `setup.h`. It updates `create_object_database()` to accept an optional `strvec` of alternates paths and passes the collected alternates from `collect_alternates()` directly to the function. The `NULL` fallback in `init_db()` ensures backward compatibility for callers that do not specify alternates. No user-visible behavior changes are expected, and the patch aligns with the series’ goal of making alternates an implementation detail of the ODB backend.

The change looks clean and well-motivated, addressing the technical debt of having a separate `write_alternates()` callback. The lockfile API adoption in patch 6 resolves the primary review concern from v1, and this patch is a straightforward application of that mechanism. The series is now likely to proceed to integration once ODB-focused contributors (e.g., Justin Tobler, Karthik Nayak) have reviewed patches 6-8.
