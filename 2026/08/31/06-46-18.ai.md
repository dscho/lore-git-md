This is patch 4/10 in the v2 series refactoring Git’s object-database fsck checks to make them pluggable. The patch fixes a long-standing discrepancy between the documented and actual behavior of the `--full` flag in `git fsck`. The man page states that `--full` controls verification of both loose objects and alternates, but the code only honored it for packfiles, unconditionally checking loose objects in all sources (including alternates) regardless of the flag.

The change is minimal: three lines in `builtin/fsck.c` that add a conditional check (`if (check_full || source->local)`) to skip non-local sources when `--no-full` is passed. A new regression test in `t/t1450-fsck.sh` verifies that loose objects in alternates are not checked when `--no-full` is used. The patch does not introduce new flags or alter the on-disk format; it simply aligns the code with the existing documentation.

Karthik Nayak’s review of v1 confirmed the patch’s intent and logic, and Patrick Steinhardt incorporated a minor correction to Karthik’s restatement of the intended behavior (“latter” → “former”) in the commit message. No technical concerns or edge cases were raised. The patch is part of the ODB abstraction effort and depends on earlier topics (`ps/odb-eagerly-load-alternates` and `ps/odb-pluggable-pack-generation`), but it stands alone as a correctness fix for `git fsck`.

The fix is well-motivated, narrowly scoped, and thoroughly tested. It addresses a clear documentation/code mismatch without introducing new complexity or behavioral changes beyond what the man page already promises. The test addition ensures the new behavior is preserved in future refactorings. This patch is a straightforward improvement that should be uncontroversial.
