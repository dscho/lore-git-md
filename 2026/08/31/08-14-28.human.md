This is the final patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The patch removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure, including the lockfile mechanism that previously protected alternates file updates. The series as a whole aims to simplify the ODB interface by eliminating the ability to write alternates after repository creation, consolidating alternates setup into a single code path during ODB creation.

Toon Claes’s review raises a substantive concern: the new implementation (introduced in patch 6) writes alternates during ODB creation but does not use a lockfile, which could introduce race conditions if multiple processes create repositories concurrently. Patrick acknowledges this oversight and agrees to adopt Git’s standard lockfile API for writing the `info/alternates` file, addressing the same security and correctness concern previously raised by Junio C Hamano.

The patch itself is mechanical—removing dead code—but the locking issue it surfaces is not. The resolution will likely require a revision to patch 6 (which implements the new alternates-writing mechanism) rather than this patch, but the discussion here is the first time the broader implications of removing the lockfile have been explicitly addressed. This could attract further scrutiny from ODB-focused contributors, as the locking strategy may need to be reconsidered or justified before the series can progress.

The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort, and this patch represents the cleanup phase after the core design changes. While the earlier patches (1–7) were largely refactoring and consolidation, this one removes infrastructure that is no longer needed—assuming the locking question is resolved. The commit message does not explain why the lockfile is being removed, which may have contributed to the confusion. The fix will likely be straightforward, but the discussion highlights how even mechanical patches can reveal subtle design issues.
