This is a review of Harald Nordgren’s v2 patch that refines `git checkout -m` autostash conflict handling by printing a blank line after conflict advice. Junio C Hamano’s feedback is substantive: he identifies a flaw in how the patch detects conflicts from `git stash apply`.

The patch currently treats any non-zero return from `run_command()` as a conflict, but `git stash apply` can fail for reasons other than conflicts (e.g., missing stash, command not found, or internal errors). Junio points out that `builtin/stash.c`’s `do_apply_stash()` uses `merge_ort_nonrecursive()`’s return value to distinguish clean merges (0), conflicts (1), and errors (negative), but this detail is lost when `cmd_stash()` discards the exit code. He suggests a three-step fix: audit all `git stash` subcommands’ return conventions, propagate the detailed exit code, and document the new semantics.

The review is constructive and technical, focusing on correctness rather than style. Junio’s tone is matter-of-fact, and he acknowledges that a simplified approach (treating all failures as conflicts) might be acceptable for now, provided the code is clearly marked as incomplete. This is a targeted critique of the patch’s core logic, not a rejection of the feature itself. The next revision will need to address these exit-code semantics to avoid false positives in conflict detection.
