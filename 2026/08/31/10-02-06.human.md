This is the second patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort, which aims to simplify the ODB interface by making alternates an implementation detail of the backend.

This patch is a pure refactoring with no behavior change. It moves the `setup_reference()` function in `builtin/clone.c` further down in the file, closer to `copy_alternates()`, which it will soon call. The motivation is to avoid adding a forward declaration for `copy_alternates()` in a later patch. The change is mechanical: the function body is unchanged, and the diff shows only reordering.

The patch is well-motivated within the series. It prepares for patch 3, where `setup_reference()` will be updated to call `copy_alternates()`, consolidating alternates logic into a single code path. This refactoring is a small but necessary step toward deferring ODB setup until after the clone source URI is resolved, ensuring alternates are written with full context.

No review feedback has been posted on this patch yet, but it is unlikely to be controversial. The change is trivial and serves a clear purpose in the larger refactoring. The series as a whole is under active review, with the lockfile API adoption in patch 6 resolving the primary blocker from v1.

This patch is worth noting for readers following the ODB abstraction effort, but it is not a standalone change and has no user-visible impact. The real substance of the series begins in later patches.
