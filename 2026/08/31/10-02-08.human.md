This is the fourth patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort, aiming to simplify the ODB interface by removing the ability to write alternates after repository creation.

This patch moves the logic for setting up alternates in shared local clones from `clone_local()` into `collect_alternates()`. Previously, when cloning a local repository with `--shared`, the source repository’s objects directory was added to the new repository’s alternates in `clone_local()`. Now, this logic is consolidated into `collect_alternates()`, which already handles alternates from `--reference` and `--reference-if-able` options. The change unifies alternates setup under a single function, preparing for the eventual goal of writing alternates at ODB creation time rather than after the fact.

The patch updates `collect_alternates()` to accept two new parameters: `src_repo` (the source repository path) and `is_local` (a boolean indicating whether the clone is local). If the clone is local and `--shared` is specified, the source repository’s objects directory is added to the alternates list. The `clone_local()` function is simplified, retaining only the non-shared logic (which will be addressed in the next patch). The call to `collect_alternates()` in `cmd_clone()` is updated to pass the new parameters.

This is a refactoring patch with no user-visible behavior changes. The motivation is purely structural, aligning with the series’ goal of consolidating alternates handling. The change is well-motivated and mechanically straightforward, though it leaves the non-shared local clone logic for the next patch. The commit message clearly explains the purpose and scope of the change. This patch is unlikely to be controversial, as it is a preparatory step for the more substantive changes in later patches.
