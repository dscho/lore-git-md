This is a v2 patch that consolidates the two-patch series into a single commit, addressing the contested API design and performance concerns from v1. The patch now focuses solely on the uncontroversial part of the original series: visually separating the autostash conflict advice from the branch-switch confirmation message by printing a blank line when conflicts occur.

The key change is repurposing the return value of `apply_save_autostash_oid()` and `apply_save_autostash_ref()` to encode three states: success (0), error (-1), and conflict (1). This replaces the original output parameter approach, which Phillip Wood objected to. The checkout logic now checks the return value and prints a blank line to stderr when conflicts are detected (`autostash_res == 1`). The test in `t/t7201-co.sh` has been updated to verify the full output with `test_cmp`, addressing Phillip’s feedback about multi-grep validation.

The patch drops the fast-path optimization (skipping autostash retry when no tracked changes exist) entirely, as its performance trade-off was contested. This simplifies the change to a pure UX improvement, which Phillip Wood had already endorsed as "a good idea." The commit message now clearly frames the motivation: resolving the visual clutter between conflict advice and the branch-switch message. Files touched are `builtin/checkout.c`, `sequencer.c`, and the test suite. The base commit is `c73e85354c275c9d409b26445089bc16940fc527` on `master`.
