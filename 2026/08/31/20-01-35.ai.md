This is the first patch in the v6 series converting `USE_NSEC` to runtime configuration (`core.useNanosec`). It addresses a build-system discrepancy between Makefile and Meson builds by exposing a configurable knob for `MAN_BASE_URL` in Meson, matching the long-standing Makefile behavior.

The patch fixes a practical issue: Meson builds currently hard-code an incorrect base URL for relative links in manual pages, producing broken links like `/usr/share/manuser-manual.html` (missing a slash and pointing to the wrong directory). The fix aligns Meson’s default with Make’s (`file://$(htmldir)/`, with a trailing slash) and adds a `man_base_url` option to `meson_options.txt`, allowing distributions to override it if needed. The change is motivated by the author’s observation that a later patch in the series (adding a link to `racy-git.adoc`) rendered incorrectly without this fix.

The implementation is straightforward: `Documentation/meson.build` now constructs the base URL from `htmldir` (with a trailing slash) and falls back to a user-provided value if `man_base_url` is set. The patch touches only two files (`Documentation/meson.build` and `meson_options.txt`) and is uncontroversial. The author notes that while few distributions may currently use `MAN_BASE_URL`, the knob is necessary for consistency and future-proofing, particularly for Meson-based builds like Gentoo’s.

This patch is self-contained and ready to advance independently of the rest of the series. It resolves a minor but visible usability issue (broken links in man pages) and aligns Meson’s behavior with Make’s, eliminating a long-standing inconsistency. No performance or correctness concerns were raised in prior discussion, and the change is unlikely to require additional testing beyond verifying that links render correctly.
