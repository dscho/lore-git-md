This is the fourth patch in Patrick Steinhardt’s 10-patch series refactoring Git’s fsck checks to make them pluggable per ODB backend. The patch fixes a long-standing discrepancy between the documented and actual behavior of the `--full` flag: the man page claims `--full` controls verification of both loose objects and alternates, but the code only applied it to packfiles. This patch ensures loose objects in alternate object pools are skipped when `--no-full` is passed, aligning behavior with the documentation.

The change is minimal—just three lines in `builtin/fsck.c`—and adds a regression test in `t/t1450-fsck.sh` to verify that `git fsck --no-full` now correctly ignores alternates. The patch is part of a pure refactoring with no user-visible changes beyond fixing the latent bug. Karthik Nayak’s review confirmed the logic matches the documented intent, and Patrick corrected a minor wording nit in the commit message ("latter" → "former") in v2.
