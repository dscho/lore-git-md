This is the third patch in Derrick Stolee’s seven-part **bugfix/hardening series** for the trace2 subsystem. It removes the use of `xstrdup()` in `trace2/tr2_sysenv.c` to prevent Git crashes during telemetry operations under memory pressure.

The patch replaces `xstrdup()` with `strdup()` and adds defensive error handling. In `tr2_sysenv_cb()`, a failed `strdup()` now returns `0` (instead of `-1`) to halt the config parsing loop without signaling a fatal error, avoiding misleading error messages. In `tr2_sysenv_get()`, a failed `strdup()` returns `NULL`, which callers already handle as equivalent to an unset environment variable. This trade-off prioritizes process stability over telemetry completeness, as an allocation failure here would likely cascade to other subsystems anyway.

The patch also extends `banned-die.h` to block `xstrdup()` in trace2, preventing future regressions. This aligns with the series’ goal of eliminating all `die()`-triggering helpers from trace2, though Jeff King’s earlier critique notes that indirect dependencies (e.g., via `strbuf`) could still trigger crashes.

The change is minimal and self-contained, with clear rationale for the error-handling trade-offs. No new issues are introduced, and the patch integrates smoothly with the rest of the series. **Worth attention** for reviewers tracking the trace2 hardening effort.
