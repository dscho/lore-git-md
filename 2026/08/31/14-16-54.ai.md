This is a security feature patch targeting the HTTP transport layer, now in its final review stage before merging to `next`. Junio C Hamano’s latest reply clarifies a lingering test-coverage question about the "fail-closed" behavior of the new `http.sslVerifyStatus` option. The patch adds a boolean configuration key (default `false`) that enables OCSP staple validation via libcurl’s `CURLOPT_SSL_VERIFYSTATUS`, causing Git to reject HTTPS connections if the server does not provide a valid staple. This addresses a security gap for government and government-adjacent users (e.g., US DoD PKI) where OpenSSL-linked Git binaries currently ignore staples, accepting revoked certificates.

The email is a narrow technical exchange between Junio and Patrick Steinhardt about whether the test harness (`t5585-http-ssl-ocsp.sh`) adequately covers the case where a server provides *no* staple.
