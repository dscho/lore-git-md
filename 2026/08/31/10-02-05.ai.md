This is the first patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch defers initialization of the object database (ODB) in `git clone` until after the clone source URI is resolved, addressing two key problems: forward compatibility with alternate ODB backends (which may require object format information at creation time) and the need to resolve alternates paths before ODB setup.

The change introduces a new `INIT_DB_SKIP_ODB` flag to `init_db()`, which skips ODB creation when set. The `create_object_database()` function is made public and called later in `cmd_clone()`, after URI resolution and alternates collection. This ensures alternates are written with full context, including any URI rewrites from template `.git/config` files. The patch touches `builtin/clone.c`, `setup.c`, and `setup.h`, adding the new flag and exposing the ODB creation function.

No user-visible behavior changes are expected, but the refactoring is foundational for the series’ goal of writing alternates during ODB creation (rather than as a separate step). The commit message clearly ties the change to the broader ODB abstraction effort, noting that alternates backends may require object format information at creation time. The patch is well-motivated and mechanically straightforward, though its significance lies in enabling the subsequent patches that implement the core design changes. Review feedback on this patch was minimal and surface-level in v1, focusing on code structure rather than technical substance.
