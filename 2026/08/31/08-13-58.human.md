This is a brief follow-up in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation. The series is part of the ongoing ODB abstraction effort, aiming to simplify the interface by moving alternates setup into a single code path and eventually making alternates an ODB backend implementation detail.

The email is a direct reply to Toon Claes’s surface-level review of the fifth patch, which focused on a minor code hygiene detail: the placement of `fclose(in)` in the newly renamed `read_alternates()` function. Toon suggested moving the `fclose(in)` call before the `out` label to eliminate the need for an `if (in)` guard, simplifying the control flow. Patrick’s response pushes back gently, arguing that keeping the `fclose(in)` after the `out` label reduces fragility—if the function is later extended with additional `goto out` statements, it’s less likely that a developer would overlook the need to close the file handle.

This exchange is purely about code structure and does not affect the patch’s technical substance or correctness. The fifth patch itself remains well-motivated, addressing a latent bug in worktree alternates handling and consolidating alternates logic into `collect_alternates()`. The broader series is still under review, with substantive discussion now focused on the locking strategy for writing the `info/alternates` file in later patches. This minor disagreement is unlikely to delay the series, but it highlights the trade-off between simplicity and maintainability in code design.
