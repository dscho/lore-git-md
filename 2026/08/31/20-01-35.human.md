This is the first patch in D. Ben Knoble’s three-patch series converting Git’s nanosecond-precision support from a build-time macro (`USE_NSEC`) to a runtime configuration option (`core.useNanosec`). The series is now in `next` and technically complete, but this specific patch is a build-system fix for Meson that stands on its own.

The patch addresses a long-standing inconsistency between Makefile and Meson builds: Makefile-based builds have allowed customization of the `MAN_BASE_URL` (used for relative links in manuals) since 2009, but Meson hard-codes a value that is both incorrect and missing a trailing slash. The result is broken links in generated man pages, like `/usr/share/manuser-manual.html` instead of the intended `file:///usr/share/doc/git/user-manual.html`. The fix aligns Meson’s behavior with Make’s by defaulting to `file://$(htmldir)/` (with a trailing slash) and exposing a configurable knob (`man_base_url`) in `meson_options.txt` so distributions can override it if needed.

The change is small and self-contained, touching only `Documentation/meson.build` and `meson_options.txt`. The author’s rationale is clear: the default is safe because all current relative links point to HTML docs, and the knob matches the Makefile’s flexibility. The patch is uncontroversial and ready to advance independently of the rest of the series. If you care about Meson build correctness or distro packaging, this is worth noting; otherwise, it’s a minor infrastructure improvement.
