This is a maintainer resolution in the negative pathspec bugfix thread. Junio C Hamano now accepts Diogo Castro’s original patch as the correct fix: negative pathspecs should be ignored when computing the common prefix, and the prefix should be stripped only from positive pathspecs. The patch will reduce the traversal scope to the positive set and then filter out excluded paths by matching full paths against the negative patterns.

The discussion about potential future optimizations for cases with many negative patterns is acknowledged but explicitly deferred as a separate topic. No alternative implementation is needed for the current bug, and the thread is now effectively resolved in favor of the posted patch. The fix is minimal, well-tested, and addresses the root cause without introducing performance regressions.
