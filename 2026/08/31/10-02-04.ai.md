This is the v2 cover letter for an 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort, targeting the simplification of the ODB interface by removing the ability to write alternates after repository creation.

The key change in v2 is the adoption of Git’s standard lockfile API for writing the `info/alternates` file, addressing a security and correctness concern raised by Junio C Hamano in the v1 review. This resolves the TOCTOU race and concurrent access issues that were the primary blocker for the series. The lockfile integration is implemented in patch 6, which now uses `repo_hold_lock_file_for_update()` and `commit_lock_file()` to ensure atomic writes. The series also removes a redundant `strvec.h` include in `odb/source.h` by reordering declarations, a minor code hygiene improvement suggested in review.

The patches remain focused on refactoring `git clone` to defer ODB setup until after the clone source URI is resolved, consolidating alternates logic into a single code path. Patch 5 fixes a latent bug in worktree alternates handling (unresolved common directory paths) and adds test coverage for worktree clones and relative path resolution. Patch 8 removes the now-unused `write_alternates()` infrastructure, though the removal of the lockfile mechanism is now acknowledged as premature; the lockfile API will be retained in the new implementation.

The series touches `builtin/clone.c`, `odb/source-files.c`, and several ODB backend files, introducing new symbols like `odb_create_on_disk_options` (a struct carrying alternates paths for ODB creation) and removing the `write_alternates()` callback. No user-visible behavior changes are expected, but the refactoring is foundational for making alternates an implementation detail of the ODB backend. The updated tests in `t/t5604-clone-reference.sh` verify the new behavior, including edge cases for worktree clones.

The series is built on `ps/odb-eagerly-load-alternates` and is under active review. The lockfile integration resolves the last substantive concern, and the series is now likely to attract scrutiny from ODB-focused contributors (e.g., Justin Tobler, Karthik Nayak) for patches 6-8, which implement the core changes. The changes are mechanical but well-motivated, aligning with the broader ODB abstraction effort. The cover letter clearly ties the work to the larger goal of simplifying the ODB interface.
