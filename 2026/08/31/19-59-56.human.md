D. Ben Knoble replies to Bence Csókás's bug report about the inconsistent handling of the `@` branch name. The original report showed that porcelain commands like `` `git checkout -b @` `` allow creating a branch named `@`, even though `git check-ref-format` (without `--branch`) rejects it as invalid. Csókás traced the issue to `git check-ref-format --branch` incorrectly accepting `@` as a valid branch name.

Knoble acknowledges the inconsistency but notes that the current behavior isn't explicitly against documented rules. He observes that while `@` is shorthand for `HEAD`, creating a branch named `@` leads to confusing behavior—`` `git switch @` `` fails because it interprets `@` as `HEAD`, and `` `git switch refs/heads/@` `` also fails. He suggests that `--branch` mode *should* reject `@` to align with the general ref name rules, though he isn't sure where branch name validity is documented.
