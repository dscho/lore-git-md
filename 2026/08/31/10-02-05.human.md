This is the first patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. It defers ODB setup in `git clone` to address two key problems: forward compatibility with alternate ODB backends (which may need object hash information at creation time) and the need to resolve the clone source URI before writing alternates.

The patch introduces a new `INIT_DB_SKIP_ODB` flag to `init_db()`, skips ODB creation during initial repository setup, and exposes `create_object_database()` so it can be called later—after the clone source URI is resolved and alternates are determined. This is a preparatory refactoring with no user-visible behavior changes, but it lays the groundwork for the core design change in patch 6 (writing alternates during ODB creation).

The changes are mechanical and well-motivated, touching only `builtin/clone.c`, `setup.c`, and `setup.h`. The commit message clearly explains the rationale, and the patch is part of a larger, actively reviewed series that has already addressed the primary blocker (lockfile API adoption) in v2. This looks like a solid, uncontroversial step toward simplifying the ODB interface.
