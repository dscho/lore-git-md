This is a CI/build system patch, the third iteration of a standalone improvement to Git's GitHub Actions workflow configuration. The patch cancels stale CI workflow runs for pull requests, ensuring only the latest push consumes runner capacity.

The change modifies `.github/workflows/main.yml` to make the concurrency group pull-request-aware. For pull request events, runs are now grouped by pull request number (e.g., `main-workflow-42`) and `cancel-in-progress` is set to true, so a new push cancels any in-progress run for the same pull request. For regular pushes, the group remains commit-based (`workflow-name-commit-hash`) with no cancellation, preserving the existing `skip-if-redundant` optimization.

This version (v3) makes only a minor commit message tweak from v2, switching to present tense for the status quo description. The core implementation is unchanged: the concurrency group expression and cancellation logic remain identical to v2, which already addressed all prior feedback. Junio C Hamano previously accepted the trade-off that the same commit could trigger duplicate workflow runs if pushed directly and later submitted as a pull request, as this is inherent to GitHub Actions' concurrency model.

The patch is well-motivated and self-contained, targeting a real inefficiency in Git's CI infrastructure without touching core Git functionality. It looks ready for merge, with no open questions or loose ends. The updated commit message improves clarity while maintaining the same technical behavior.
