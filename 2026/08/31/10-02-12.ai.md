This is the final patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation. It removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure across all ODB backends, including the lockfile mechanism that was previously used to write the `info/alternates` file.

The patch deletes 117 lines across seven files: `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, `odb/source-packed.c`, and `odb/source.h`. The removals are mechanical and follow from the earlier patches in the series, which consolidated alternates logic into a single code path during ODB creation (via `odb_create_on_disk_options`) and adopted Git’s standard lockfile API for atomic writes. The lockfile mechanism in the "files" backend (`odb_source_files_write_alternate()`) is now redundant, as is the `write_alternate` callback in the other backends, which only returned errors (e.g., "in-memory source does not support alternates").

No user-visible behavior changes are introduced, and the patch is a clean-up step that aligns with the series’ goal of simplifying the ODB interface. The removal is safe because all callers of `odb_add_to_alternates_file()` (the public wrapper for `odb_source_write_alternates()`) were eliminated in earlier patches, particularly patch 7, which consolidated alternates setup into `create_object_database()`. The patch also removes the `write_alternate` field from the `odb_source` struct and its associated inline helper function, completing the transition to the new design.

The patch is uncontroversial and expected to proceed without further changes, though it may attract a final round of scrutiny from ODB-focused contributors (e.g., Justin Tobler, Karthik Nayak) to confirm the infrastructure is truly unused. The series as a whole is now technically complete, with the lockfile API adoption in patch 6 resolving the primary blocker raised during v1 review. This patch is the last step in making alternates an implementation detail of the ODB backend, a key milestone in the ongoing ODB abstraction effort.
