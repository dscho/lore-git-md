This is the final technical exchange in the `dk/use-nsec-runtime` series, which converts the build-time `USE_NSEC` macro into the runtime `core.useNanosec` configuration option. The patch itself is complete, well-reviewed, and ready for `master`; this reply clarifies the forward-looking architectural constraint introduced by the new dependency on `repo_config_values()`.

Patrick Steinhardt confirms that an upcoming patch series (motivated by removing submodule ODB registration) will rely more on sub-repositories, but notes that the `core.useNanosec` change does not break it. He reiterates the long-standing limitation of `repo_config_values()`: it is hard-coded to `the_repository`, making it unsuitable for any future in-process submodule operations. While this is not a regression—`repo_config_values` was already limited to `the_repository`—the new call site in `is_racy_stat()` makes the constraint more visible. Steinhardt expresses dissatisfaction with the current state of `repo_config_values()` but acknowledges that refactoring it away from `the_repository` is non-trivial due to its initialization via `repo_config(git_default_config)`. He suggests that if future edge cases reveal problems, the series could be refactored to move the `use_nanosec` value into `struct repo_settings` instead, which already supports multiple repositories.
