This is a brief follow-up in the ongoing ODB alternates refactoring series by Patrick Steinhardt. The thread focuses on patch 6/8, which introduces support for writing alternates during object database creation. Junio C Hamano previously raised a security concern about the patch’s use of append mode (`"a"`) for writing the `info/alternates` file instead of Git’s standard lockfile API, which would prevent TOCTOU races or partial writes. Patrick now acknowledges the issue, agreeing that while the risk is low (since the operation happens only during repository creation), there’s no strong reason not to use a lockfile. He implies the patch will be revised to address this, which may also affect the removal of the lockfile mechanism in patch 8/8.

The discussion remains narrowly scoped to the locking strategy, with no new technical objections or broader design questions raised. The change is uncontroversial in principle—both Junio and Toon Claes flagged the same issue—and Patrick’s response suggests a straightforward fix is forthcoming. This is a well-motivated refactoring that simplifies the ODB interface as part of the larger ODB abstraction effort, and the locking concern, while substantive, appears to be the last open question before the series can proceed.
