This is the fourth patch in Derrick Stolee’s seven-part series to harden the trace2 subsystem against crashes caused by `die()`-triggering helpers. It removes the use of `ALLOC_ARRAY()` in `trace2.c` and replaces it with `calloc()`, adding defensive error handling to prevent crashes when memory allocation fails.

The patch updates the `redact_argv()` function, which processes command-line arguments for telemetry redaction. Previously, it used `ALLOC_ARRAY()` to allocate an array for the redacted arguments, which would call `die()` on failure. Now, it uses `calloc()` and returns `NULL` if allocation fails. The callers (`trace2_cmd_start_fl()`, `trace2_child_start_fl()`, and `trace2_exec_fl()`) are updated to check for `NULL` and degrade gracefully by skipping telemetry logging for that event. The change also includes a cast to `char *` to free the `redacted` string when allocation fails, since `redact_arg()` returns a `const char *` (to handle both static and dynamically allocated strings).

The patch extends `banned-die.h` to block `ALLOC_ARRAY()`, preventing future regressions. This aligns with the series’ goal of eliminating all `die()`-prone functions from trace2, though Jeff King’s earlier critique notes that indirect dependencies (e.g., `strbuf`) could still trigger crashes. The change is minimal and self-contained, touching only `trace2.c` and the new header.

The error handling is pragmatic, prioritizing process stability over telemetry completeness, and the commit message clearly explains the motivation.
