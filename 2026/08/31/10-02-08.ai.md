This is the fourth patch in Patrick Steinhardt’s 8-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. It moves the logic for setting up alternates in shared local clones from `clone_local()` into `collect_alternates()`, consolidating alternates setup into a single code path.

The patch updates `collect_alternates()` to accept `src_repo` and `is_local` parameters, allowing it to handle local clones directly. When `is_local` is true and `--shared` is specified, it resolves the source repository’s common directory and adds its `objects` directory to the alternates list. This change removes the manual alternates file update in `clone_local()` for shared clones, deferring it to the unified alternates collection step. Non-shared local clones continue to use the existing `clone_local()` logic for now; the next patch will address those.

The diff is mechanical and focused, touching only `builtin/clone.c`. It introduces no new symbols but extends the `collect_alternates()` function signature and updates its call site in `cmd_clone()`. The change is a preparatory step for writing alternates at ODB creation time (patch 6) and aligns with the series’ goal of making alternates an ODB backend implementation detail. No user-visible behavior changes are expected, and the patch includes no tests—those are added in patch 5, which fixes a latent bug in worktree alternates handling. The refactoring is well-motivated and consistent with the broader ODB abstraction effort.
