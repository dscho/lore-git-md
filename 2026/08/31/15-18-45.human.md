This is the fifth patch in Toon Claes’s six-patch series that speeds up the experimental `git last-modified` command by reusing Git’s Bloom filters. The patch adds a 12-line pre-filter in `maybe_changed_path()` that calls the appropriate Bloom-filter helper (`revs_maybe_changed_in_bloom` or `revs_maybe_changed_in_bloom_with_parents`) before starting the per-path diff machinery. This discards commits that definitely did not touch any relevant path early, matching the optimization already used by `git log`.

The commit message explains the `--show-trees` wrinkle: because that option tracks parent directories as well as the pathspec itself, the patch uses `revs_maybe_changed_in_bloom_with_parents()` to check whether the commit might have changed any key in the path’s key vector (e.g., for `a/b/c/` it checks `a/`, `a/b/`, and `a/b/c/`). The new test in `t8020-last-modified.sh` verifies that Bloom-filter lookups work correctly with `--show-trees` by comparing the output with and without the commit-graph enabled.

The patch is clean, well-motivated, and directly addresses the performance regression that `--show-trees` would otherwise cause. All prior technical feedback has been resolved, and the instrumentation added in the v3 reroll confirms the Bloom-filter fast-path is correctly triggered. This looks ready to merge.
