This thread is about a refactoring in Git’s revision-walking code. Toon Claes is splitting out the core logic that checks whether a commit’s changed-path Bloom filter might contain any of the pathspecs the user cares about. The new function, `revs_maybe_changed_in_bloom()`, is a pure boolean helper that takes an already-loaded Bloom filter, so callers can reuse it without paying for a second filter lookup. The original function stays as a convenience wrapper. This is the first step in a six-patch series; the extracted helper will be used by another built-in command in a later patch. So far there are no reviews or objections—it’s just the initial posting.
