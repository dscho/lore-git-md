This is the second patch in Patrick Steinhardt’s 10-patch series refactoring Git’s fsck checks to make them pluggable for ODB backends. The patch merges `fsck_obj_buffer()` and `fsck_obj()` into a single function, simplifying the call chain and eliminating an early return check for the `SEEN` flag that was always cleared by the caller anyway.

The change is purely internal: no user-visible behavior is altered, and the patch touches only `builtin/fsck.c`, reducing its line count by 7. The merged function, still named `fsck_obj_buffer()`, now handles both object parsing and verification, setting the `SEEN` and `HAS_OBJ` flags unconditionally and clearing `REACHABLE` as part of its initialization. The commit message explains the motivation clearly—removing redundancy and making the code’s flow more obvious—and the diff is mechanical, moving the parsing logic from the old `fsck_obj_buffer()` into the body of the former `fsck_obj()`.

Karthik Nayak’s review of v1 was surface-level, suggesting only a minor wording tweak in the commit message (“early” → “early return”), which Patrick has incorporated in v2. There are no open technical questions or objections; the patch is a straightforward refactoring that aligns with the series’ goal of preparing the fsck code for pluggable ODB backends. If you’re following the ODB abstraction effort, this is a small but necessary step in that direction.
