This is a bugfix patch thread about negative pathspec handling in `` `git ls-files` `` and `` `git add` ``. Junio C Hamano, the maintainer, has just signaled agreement with the current patch's approach: negative pathspecs should be ignored when calculating the common prefix, and the prefix should be stripped only from positive pathspecs to optimize directory traversal. The patch itself—11 lines in `dir.c` with three new tests—now looks likely to be accepted as-is.

The discussion had previously stalled on a design question: whether negative pathspecs should influence the common prefix calculation. Junio initially suggested recalculating the prefix to include negatives when they share a meaningful prefix with positives, but after Diogo Castro's performance-focused reply (showing that such a change could degrade performance without improving correctness), Junio has dropped that idea. He now endorses the original patch's behavior, calling it "the right solution."

A minor open question remains: whether future work might optimize cases with many negative patterns, but Junio explicitly calls that "a separate topic," so it will not block this patch. The thread is now effectively resolved in favor of the current implementation.
