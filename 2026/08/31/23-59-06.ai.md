This is a feature patch introducing `git ident`, a renamed and substantially redesigned version of the previously proposed `git whoami` command. The patch is the second iteration (v2) of a new built-in command that consolidates Git’s identity and signing configuration into a single, user-friendly porcelain command.

The core change from v1 is the command’s renaming from `git whoami` to `git ident`, reflecting a shift toward Git’s existing naming conventions (`git var`, `git config`). The implementation now fully addresses the technical and usability critiques raised in the v1 review. Key improvements include: additive, composable flags (e.g., `-a -e -n` shows full author identity), machine-readable `--porcelain` output, NUL-terminated output (`-z`) for scripting, removal of `the_repository` usage, and support for X.509 signing keys. The flag interactions are now predictable and align with Git’s existing conventions, resolving Junio’s maintainer-level skepticism about the command’s usability.

The patch adds a new built-in command (`builtin/ident.c`), a man page (`Documentation/git-ident.adoc`), and a comprehensive test suite (`t/t0015-ident.sh`). It integrates with Git’s existing identity and GPG interfaces (`ident.h`, `gpg-interface.h`) and works outside of a repository. The implementation is self-contained, with no on-disk format changes or new configuration options. The commit message now explicitly justifies the command’s inclusion in Git core, contrasting it with `git var` and `git config` by emphasizing its unified, user-friendly design and scripting support.

Files touched: `builtin/ident.c`, `Documentation/git-ident.adoc`, `t/t0015-ident.sh`, build system files (Makefile, meson.build), `command-list.txt` (classified as `ancillaryinterrogators`), and `builtin.h`. The patch is technically sound, with thorough test coverage and attention to edge cases (environment variable overrides, incompatible flag combinations, signing key resolution). The redesign directly addresses all open questions from the v1 review, making the command’s value proposition clearer and its implementation more robust. The patch is now ready for substantive review and likely to advance to `next` if no new concerns arise.
