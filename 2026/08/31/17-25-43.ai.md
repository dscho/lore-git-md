This is the **seventh and final patch in Derrick Stolee’s v3 series** hardening the trace2 subsystem against crashes caused by `die()`-triggering helpers. It removes the last banned function (`xcalloc()`) from trace2’s thread-local storage (TLS) management and introduces a **statically allocated fallback context** to handle allocation failures gracefully.

### What the patch does
The patch replaces `xcalloc()` in `tr2tls_create_self()` with `calloc()` and adds defensive error handling. When allocation fails, it falls back to a statically allocated `tr2tls_thread_fallback` context (thread name: `"unknown"`) instead of crashing. The new `tr2tls_is_fallback()` helper lets callers detect and short-circuit operations on the fallback context, ensuring trace2 degrades gracefully under memory pressure.

### Key changes
- **`tr2tls_create_self()`**: Replaces `xcalloc()` with `calloc()` and checks for allocation failures. On failure, it sets the thread-specific key to the fallback context and returns it.
- **Fallback context**: A statically allocated `tr2tls_thread_fallback` (thread name `"unknown"`) is used when dynamic allocation fails. This ensures trace2 can still operate (albeit with degraded telemetry) instead of crashing.
- **Short-circuiting**: All trace2 counter/timer functions (`tr2_counter_increment()`, `tr2_start_timer()`, etc.) now check `tr2tls_is_fallback()` and return early if the context is the fallback. This prevents null-pointer dereferences and ensures stability.
- **Cleanup**: The `tr2tls_key_destructor()` and `tr2tls_unset_self()` functions skip cleanup for the fallback context to avoid freeing static memory.

### Assessment
This patch **completes the series’ goal** of eliminating all `die()`-triggering helpers from trace2. The fallback mechanism is a pragmatic solution that prioritizes process stability over telemetry completeness, aligning with the series’ broader hardening philosophy. The changes are self-contained to trace2 and introduce no new dependencies.

### Open questions
- **Testing**: Like the rest of the series, this patch lacks dynamic test coverage for allocation failures (hard to reproduce). The fallback context is exercised only in error paths, which may not be triggered in normal testing.
- **Impact on trace consumers**: The `"unknown"` thread name and degraded telemetry (e.g., dropped events) are breaking changes for tools relying on trace2 data. This is intentional but may require updates to monitoring pipelines.
