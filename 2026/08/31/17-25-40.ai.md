This is the **fourth patch in a seven-part bugfix/hardening series** targeting the trace2 subsystem. The series aims to eliminate all `die()`-triggering helpers (e.g., `ALLOC_ARRAY()`, `xstrdup()`, `xsnprintf()`) from trace2 to prevent Git crashes during telemetry operations, especially under memory pressure or system call failures. This patch specifically replaces `ALLOC_ARRAY()` with `calloc()` in the `redact_argv()` function, adding defensive error handling to avoid crashes when memory allocation fails.

The patch extends `banned-die.h` to block `ALLOC_ARRAY()` in trace2, preventing future regressions. In `trace2.c`, it replaces the banned helper with a direct `calloc()` call and adds explicit checks for allocation failures. When `calloc()` fails, the function now frees any previously allocated memory (e.g., the `redacted` string from `redact_arg()`) and returns `NULL` to signal degraded operation. Callers (`trace2_cmd_start_fl()`, `trace2_child_start_fl()`, and `trace2_exec_fl()`) are updated to short-circuit when `redact_argv()` returns `NULL`, ensuring the process continues without telemetry rather than crashing.

The change is **technically sound and well-motivated**, addressing a real stability issue in a low-level subsystem. The defensive fallbacks align with the series’ goal of prioritizing process stability over telemetry completeness. The patch is **self-contained** (touching only `banned-die.h` and `trace2.c`) and **backward-compatible** for trace consumers, who may see missing or truncated data under failure conditions but will not encounter crashes. The use of a `(char *)` cast to free the `redacted` string is a pragmatic solution to the `const` qualifier issue, though it underscores the complexity of retrofitting defensive error handling into existing code.

This patch is **part of a larger, high-quality series** that has already addressed prior feedback (e.g., Elijah Newren’s correctness concerns, Jeff King’s architectural critique). While the hardening is not complete (per Jeff King’s review, indirect `die()` calls via helpers like `strbuf` remain), this is a **necessary and incremental step** toward making trace2 more robust. The series is **under active review** and rebased onto `master`, with no unresolved technical objections. **Worth attention** for anyone interested in Git’s stability or telemetry subsystems.
