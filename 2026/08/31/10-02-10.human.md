This is the sixth patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. It implements the core design change: writing alternates at ODB creation time using Git’s standard lockfile API, replacing the previous append-mode approach that raised TOCTOU race and concurrent access concerns in v1.

The patch adds support for writing alternates to the "files" ODB backend via a new `odb_create_on_disk_options` struct, which carries a `strvec` of alternates paths. The implementation uses `repo_hold_lock_file_for_update()` and `commit_lock_file()` to ensure atomic writes, addressing the security issue Junio C Hamano flagged in v1. It also handles preexisting alternates (e.g., from template directories) by reading and deduplicating entries before writing, preventing duplicates.

The changes are confined to `odb/source-files.c` (the bulk of the logic), `odb/source.h` (adding the new options struct and updating the `create_on_disk` callback signature), and `setup.c` (trivial plumbing to pass an empty options struct). The patch is well-motivated and directly tied to the series’ goal of simplifying the ODB interface by removing the `write_alternates()` callback in patch 8. The lockfile adoption is a clear improvement over v1, and the code is careful about error handling and resource cleanup.

This is a foundational step for the ODB abstraction effort, though the patch itself is mechanical and unlikely to be controversial now that the locking issue is resolved. The next patches will wire up this mechanism in `git clone` and remove the old infrastructure. No user-visible behavior changes are expected.
