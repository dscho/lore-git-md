This is the fifth patch in Patrick Steinhardt’s eight-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort, which aims to simplify the ODB interface by making alternates an implementation detail of the backend.

This patch moves the setup of alternates for non-shared local clones into the `collect_alternates()` function, completing the consolidation of alternates logic into a single code path. Previously, alternates for non-shared local clones were handled separately in `clone_local()`, but this patch unifies the logic under `collect_alternates()`. The change also fixes a latent bug: when cloning from a worktree, the code now correctly resolves the referenced repository’s common directory, ensuring alternates are properly set up. The patch adds two new tests to `t/t5604-clone-reference.sh` to verify this behavior and prevent regressions. One test ensures alternates are correctly carried over when cloning from a linked worktree, while the other checks that relative alternates paths are resolved properly.

The patch touches `builtin/clone.c` and the test suite, renaming `copy_alternates()` to `read_alternates()` to reflect its new role in gathering alternates paths into a `strvec` rather than immediately writing them to the ODB. The changes are mechanical and well-motivated, aligning with the series’ goal of deferring ODB setup until after all alternates are collected. The commit message clearly explains the bug fix and the rationale for the refactoring, making it easy to follow the logic.

The patch looks solid and addresses a real issue in worktree alternates handling. The added test coverage is thorough and should catch future regressions. This is a sensible step toward simplifying the alternates logic, and the changes are unlikely to be controversial.
