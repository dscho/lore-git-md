This is a refactoring patch in the revision-walking subsystem, part of a six-patch series by Toon Claes. It extracts the core logic of `check_maybe_different_in_bloom_filter()`—the part that consults a commit’s changed-path Bloom filter to see whether any pathspec might have been modified—into a new public function `revs_maybe_changed_in_bloom()`. The new function takes an already-loaded `struct bloom_filter` instead of a commit, so callers that have already looked up the filter can avoid a redundant lookup. The old function becomes a thin wrapper that loads the filter and delegates to the new one. The new function is exposed in `revision.h` and returns a simple boolean (false iff the commit definitely did not touch any paths), whereas the original returned a tristate for statistics tracking. This change is preparation for a follow-up patch that will reuse the same filtering logic in another built-in command.
