This is the fifth patch in Derrick Stolee’s seven-part v3 series hardening the trace2 subsystem against crashes caused by `die()`-triggering helpers. The patch removes `xstrfmt()` from `redact_arg()` in `trace2.c` and replaces it with manual string concatenation using `memcpy()`, adding defensive error handling to prevent crashes during memory allocation or string formatting failures.

The core change is in `redact_arg()`, which now constructs the `:<REDACTED>` string by hand instead of relying on `xstrfmt()`. The new implementation checks for integer overflow when calculating the required buffer size, allocates memory with `malloc()`, and copies the prefix, redacted string, and suffix into place. If any step fails (overflow, allocation, or copying), the function returns `NULL` to signal degraded operation. The caller (`redact_argv()`) is updated to handle `NULL` returns by freeing any previously allocated memory and propagating the failure upward, ensuring the process continues without telemetry rather than crashing.

The patch also extends `banned-die.h` to block `xstrfmt()` in trace2, preventing future regressions.
