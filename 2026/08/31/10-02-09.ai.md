This is patch 5/8 of Patrick Steinhardt’s ODB alternates refactoring series, part of the ongoing ODB abstraction effort. The patch moves the setup of alternates for non-shared local clones into the unified `collect_alternates()` function, completing the consolidation of alternates logic begun in earlier patches. This is a refactoring patch with no user-visible behavior changes, but it fixes a latent bug in worktree alternates handling and adds test coverage for edge cases.

The key change is extending `collect_alternates()` to handle non-shared local clones by calling the newly renamed `read_alternates()` (formerly `copy_alternates()`) when `--shared` is not specified. This ensures alternates are resolved using the source repository’s common directory, fixing a bug where referencing a worktree failed to resolve alternates due to unresolved common directory paths. The patch also removes the manual alternates file update in `clone_local()`, deferring it to the unified alternates collection step.

The diff touches `builtin/clone.c` and adds two tests to `t/t5604-clone-reference.sh`. The first test verifies the bug fix by cloning from a linked worktree and checking that alternates are correctly carried over. The second test ensures relative alternates paths are properly resolved when cloning from a worktree. The changes are mechanical but well-motivated, aligning with the series’ goal of consolidating alternates logic before further ODB abstraction.

The patch addresses a review comment from Toon Claes in v1 about moving `fclose(in)` before the `out` label, but Patrick Steinhardt declined this suggestion, explaining that the current placement reduces fragility for future extensions. The fix for the worktree alternates bug is a clear improvement, and the added test coverage strengthens confidence in the refactoring. No substantive concerns remain for this patch.

This patch is a necessary step toward the series’ broader goal of simplifying the ODB interface by making alternates an implementation detail of the ODB backend. The consolidation of alternates logic into `collect_alternates()` prepares for the core changes in patches 6-8, which introduce the new `odb_create_on_disk_options` mechanism for writing alternates during ODB creation. The patch is well-explained in the commit message and should proceed smoothly to integration.
