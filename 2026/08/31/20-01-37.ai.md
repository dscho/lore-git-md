This is the final patch in D. Ben Knoble’s three-part series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The patch itself is the core implementation of the runtime switch, replacing preprocessor checks with a new `use_nanosec` field in `struct repo_config_values` and updating the racy Git logic in `is_racy_stat()` and `match_stat_data()` to respect the runtime setting. The series has already graduated to `next` and is technically complete; this patch carries forward all prior feedback, including the performance fix (caching the config value) and the cross-platform correctness guarantee (treating `use_nanosec` as false when `NO_NSEC` is defined).

The patch touches ten files, most notably `read-cache.c` (racy Git logic), `environment.c`/`environment.h` (config plumbing), and `Documentation/technical/racy-git.adoc` (updated to reflect the runtime switch). The new `core.useNanosec` config key defaults to false, preserving backward compatibility, and the documentation now explicitly warns users about platform/filesystem limitations. The architectural constraint introduced by the new call to `repo_config_values()` in `is_racy_stat()`—which limits future in-process submodule operations—is acknowledged but not blocking, as the limitation was already present in the codebase.

This patch is well-crafted and uncontroversial at this stage. The only remaining loose ends are routine conflict resolution with `ty/repo-config-cleanups` (a comment-only cleanup in `seen`) and platform-dependent test coverage, neither of which is blocking. The author, Junio, and Patrick Steinhardt have all signed off on the technical approach, and the performance regression from earlier iterations has been resolved. The patch is ready to advance to `master` alongside the rest of the series.
