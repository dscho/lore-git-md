This is a bug report about inconsistent validation of branch names in Git's porcelain commands.

The email reports that while `git check-ref-format` correctly rejects the single-character `@` as an invalid branch name, the porcelain commands `` `git checkout -b @` ``, `` `git switch -c @` ``, and `` `git branch @` `` all allow creating a branch named `@`. The author demonstrates that other invalid names (like `@{1}` or `@^`) are properly rejected by these commands, but `@` slips through. The inconsistency is traced to `git check-ref-format --branch`, which incorrectly accepts `@` as valid.

The branch cannot be checked out afterward (`` `git checkout @` `` does nothing), but it can be deleted with `` `git branch -d @` ``. The report is clear, includes reproduction steps, and points to the specific discrepancy in the `--branch` mode of `check-ref-format`. This looks like a genuine bug with a well-defined edge case, not a feature request or a matter of opinion. The fix will likely involve aligning the branch-name validation logic across all commands.
