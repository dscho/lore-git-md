This is the **third patch in the v3 series** hardening the trace2 subsystem against `die()`-triggering helpers. It removes `xstrdup()` from `trace2/tr2_sysenv.c` and replaces it with `strdup()`, adding defensive error handling to prevent crashes during memory allocation failures.

The patch updates two functions:
1. **`tr2_sysenv_cb()`** (the config callback): On `strdup()` failure, it now returns `0` instead of `-1` to terminate the config parsing loop early without signaling a fatal error. This avoids misleading error messages while still halting further processing.
2. **`tr2_sysenv_get()`**: Returns `NULL` on `strdup()` failure, which is indistinguishable from an unset environment variable. Callers already handle `NULL` gracefully, so this change preserves existing behavior while avoiding crashes.

The patch also extends `banned-die.h` to block `xstrdup()` in trace2, preventing future regressions. This aligns with the series’ goal of eliminating all `die()`-prone functions from trace2, though Jeff King’s critique (not addressed here) notes that indirect dependencies (e.g., `strbuf`) could still trigger crashes.

**Assessment**: A **clean, well-motivated fix** that addresses Elijah Newren’s prior concern about incomplete hardening in the config parsing path. The trade-off (degrading to `NULL` on failure) is pragmatic and documented. The patch is self-contained and ready for review, though the broader discussion about indirect `die()` calls remains unresolved. **Worth attention** for its role in the series’ stability improvements.
