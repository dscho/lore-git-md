This is the final patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort, and this patch removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure across all ODB backends.

The patch deletes 117 lines of code from seven files, including the `write_alternate` callback implementations in `odb/source-files.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, and `odb/source-packed.c`. It also removes the `odb_add_to_alternates_file()` helper from `odb.c` and `odb.h`, along with the `write_alternate` callback declaration from `odb/source.h`. The cleanup is mechanical and well-scoped: since earlier patches in the series consolidated alternates handling into ODB creation (via `odb_create_on_disk_options`), the old infrastructure is no longer needed.

This patch is uncontroversial and clearly motivated. The lockfile API adoption in patch 6 resolved the primary review concern from v1, and the series has already addressed all substantive feedback. The removal is a natural follow-up to the refactoring in patches 1-7, which deferred ODB setup in `git clone` and consolidated alternates logic into a single code path. No user-visible behavior changes are expected, and the patch includes no new tests—appropriate since the functionality being removed was already unused.

The patch is ready for integration, though it may attract a final round of scrutiny from ODB-focused contributors (e.g., Justin Tobler, Karthik Nayak) to confirm the removal is safe. The series as a whole is a clean, incremental step toward making alternates an implementation detail of the ODB backend, aligning with the broader goal of simplifying the ODB interface.
