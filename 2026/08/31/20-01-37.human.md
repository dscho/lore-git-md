This is the final patch in D. Ben Knoble’s three-part series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The series has already graduated to `next` and is considered technically complete, with all prior feedback addressed.

The patch replaces `#ifdef USE_NSEC` preprocessor checks with runtime logic that consults the new `core.useNanosec` config key (defaults to false). On platforms lacking nanosecond support (`NO_NSEC` defined), the field is still present in `struct repo_config_values` but treated as false, ensuring backward compatibility and preventing silent corruption. The change touches ten files, including `read-cache.c` (where `is_racy_stat()` now uses a ternary to check `use_nanosec`), `environment.c` (config parsing), and documentation (`core.adoc` and `racy-git.adoc`), which now warns users about platform/filesystem limitations.

Performance concerns raised in earlier iterations are resolved: the v1 regression (~41× slowdown in `git diff` benchmarks) is fixed by caching the config value in `repo_config_values`. The patch also updates comments and removes obsolete build-system knobs (`USE_NSEC` from `Makefile` and `configure.ac`). A minor architectural constraint remains—the new call to `repo_config_values()` in `is_racy_stat()` reinforces the existing limitation that this function only works with `the_repository`—but this is not blocking, and Patrick Steinhardt has suggested refactoring to `struct repo_settings` as a future mitigation if needed.

The patch is well-motivated and thoroughly tested, with benchmarks confirming restored performance and CI passing. The only loose end is a routine textual conflict with `ty/repo-config-cleanups` in `seen`, but resolution will be straightforward. This is a clean, uncontroversial change that delivers tangible user benefit (reducing "racy Git" problems) without breaking existing workflows.
