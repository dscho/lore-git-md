This is a **bugfix** targeting the sequencer subsystem, specifically the `--autosquash` behavior in `git rebase`. The patch (`v4`) is now in its final review phase after incorporating all feedback from Phillip Wood, the primary reviewer. The core issue is that `git rebase --autosquash` currently halts with an error when a `fixup!` or `squash!` commit cancels out its target, instead of respecting the user's `--empty` configuration (`drop`, `keep`, or `stop`). This patch fixes that edge case while carefully preserving existing behavior for workflows that rely on empty commits as placeholders.

The implementation introduces a new check (`is_amended_head_empty()`) to detect when applying a `fixup!` or `squash!` empties the target commit, and integrates it into the sequencer logic. It also tracks whether the target commit was originally picked with changes (via a new `enum fixup_target` and on-disk state in `$GIT_DIR/rebase-merge/fixup-target`), ensuring only commits that *become* empty are subject to `--empty` handling. The patch handles edge cases like mid-chain fixups (only the final fixup may drop the target), conflict resolution (honoring `--empty` if a user resolves a conflicted fixup by undoing its target), and proper cleanup of the `rewritten-pending` file when dropping commits.

Phillip Wood's review is **substantive and tested**, covering correctness, edge cases, and test coverage. He suggests a few minor tweaks (e.g., simplifying the `is_amended_head_empty()` call, consolidating cleanup code, and adding a test case for a fixup that becomes empty after its target is already empty), but these are refinements rather than blockers. The patch is well-motivated by a real-world workflow at Meta, where internal LLVM patches are managed as single commits using `fixup!` autosquash. The commit message is thorough, and the test coverage (in `t/t3415-rebase-autosquash.sh` and `t/t5407-post-rewrite-hook.sh`) is comprehensive.

This patch looks ready for merging. It addresses a long-standing edge case without introducing regressions, and the remaining feedback is minor and non-controversial. The follow-up discussion about a potential `revert!` autosquash directive remains unresolved but is orthogonal to this patch.
