This is a follow-up in the ODB alternates refactoring series, specifically addressing Junio C Hamano’s review comment on patch 6/8. The email confirms that Patrick Steinhardt will adopt the lockfile API for writing the `info/alternates` file during repository creation, replacing the current append-mode (`"a"`) approach. This change resolves the security and correctness concern raised by Junio and Toon Claes about potential TOCTOU races or partial writes, even though the operation occurs only once during repository setup.

The decision to use lockfiles is straightforward and aligns with Git’s established practices for atomic file updates. While the risk of concurrent access during repository creation is low, the lockfile API provides a robust, conventional solution that eliminates edge cases. This adjustment will likely require a revision to patch 6 and may also affect patch 8, which removes the old lockfile mechanism — the removal may now be premature or unnecessary if the new implementation retains locking. The series remains part of Patrick Steinhardt’s broader ODB abstraction effort, and this change reinforces the goal of simplifying the ODB interface while maintaining correctness.

No new technical details or edge cases are introduced in this reply; the focus is solely on agreeing to the review feedback. The next iteration of the series will need to incorporate the lockfile API, and the discussion may shift to whether the old lockfile infrastructure should still be removed or repurposed. The patch is otherwise uncontroversial, and this resolution clears the primary blocker for the series. Contributors involved in ODB work (e.g., Justin Tobler, Karthik Nayak) may weigh in on the revised implementation, but the core design remains unchanged.
