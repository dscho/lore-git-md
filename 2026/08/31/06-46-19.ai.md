This is patch 5/10 of Patrick Steinhardt’s v2 series making Git’s ODB fsck checks pluggable. It introduces the infrastructure for backend-specific integrity verification: a new `fsck` callback in the `struct odb_source` vtable, empty stubs for all existing source types (`files`, `inmemory`, `loose`, `packed`), and the `struct odb_fsck_options` structure with the `ODB_FSCK_FULL` flag. The patch replaces the old `check_full` boolean with the new options structure and adds the `odb_fsck()` helper, which iterates over all sources and invokes their respective `fsck` callbacks. No behavior changes yet—this is pure scaffolding for the refactoring that follows in patches 6–10.

The patch touches eight files, adding 100 lines and removing 5. Key symbols introduced: `fsck_obj_buffer()` (the sole entry point for object verification), backend-specific verification hooks (`odb_source_fsck_fn`), `struct odb_fsck_options`, and the `ODB_FSCK_FULL` flag. The `OPT_BIT` macro replaces `OPT_BOOL` for the `--full` flag, preserving `--no-full` functionality via bitwise negation. Karthik Nayak’s earlier review raised a technical question about this choice, which Patrick Steinhardt resolved by confirming that `OPT_BIT` provides equivalent semantics.

This patch is a clean, mechanical refactoring with no user-visible impact. It lays the groundwork for moving fsck logic into backend-specific implementations in subsequent patches, aligning with the series’ goal of preparing for pluggable ODB backends. The scaffolding is well-structured, and the commit message clearly explains the motivation and design. No open questions remain; all feedback from v1 has been addressed.
