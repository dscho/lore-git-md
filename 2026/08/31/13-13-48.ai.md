This is the second patch in the v9 series introducing `--linearize` to `git replay`. It refactors the replay machinery to resolve the replay base outside `pick_regular_commit()`, consolidating base-selection logic in `replay_revisions()` for clarity and maintainability.

The patch moves the logic that determines the commit onto which the next commit should be replayed from `pick_regular_commit()` into its caller, `replay_revisions()`. Previously, `pick_regular_commit()` would decide the base by checking if the parent commit had already been replayed (using the `replayed_commits` map) and falling back to `onto` or `last_commit` depending on the replay mode. Now, `replay_revisions()` resolves the base upfront and passes it directly to `pick_regular_commit()`, reducing the latter’s parameters from five to four and eliminating the need for it to know about `replayed_commits` or `onto`. The change is purely internal and introduces no behavior changes; it is preparatory for the `--linearize` feature in patch 3/3.

The refactoring improves code clarity by bundling all base-selection logic in one place, making it easier to follow how the replay base is determined for different replay modes (regular vs. revert). The commit message explains the motivation: the previous split logic was confusing, and consolidating it reduces cognitive load. The patch also adds a clarifying comment in `replay_revisions()` that distinguishes between regular replay (where the base is either the replayed parent or `onto`) and revert replay (where the base is always `last_commit`).

This patch is uncontroversial and has been stable since v5. Earlier iterations (v2–v4) experimented with an enum-based approach for the refactoring, but feedback from Justin Tobler and Patrick Steinhardt led to the current simpler design. The helper functions `put_mapped_commit()` and `get_mapped_commit()` (introduced in patch 1/3) are used here to maintain consistency in how replayed commits are tracked. The patch touches only `replay.c` and is a clean foundation for the `--linearize` implementation in patch 3/3.
