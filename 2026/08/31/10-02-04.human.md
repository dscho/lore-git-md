This is the cover letter for the second iteration of Patrick Steinhardt’s 8-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort and aims to simplify the ODB interface by moving alternates handling into the "files" backend.

The key change in this version is the adoption of Git’s standard lockfile API for writing the `info/alternates` file, addressing a security and correctness concern raised by Junio C Hamano in the first iteration. The lockfile ensures safe concurrent access and prevents partial writes or TOCTOU races. This revision also removes a redundant `strvec.h` include and reorders declarations in `odb/source.h` for better organization.

The series remains focused on removing the ability to write alternates after repository creation, consolidating alternates setup into `odb_source_create_on_disk()` via a new `odb_create_on_disk_options` struct. Patches 1-5 refactor `git clone` to defer ODB setup and consolidate alternates logic, fixing a latent bug in worktree alternates handling along the way. Patch 6 implements the core change, adding support for writing alternates during ODB creation, while patch 7 removes the last manual alternates writing step in `cmd_clone()`. Patch 8 deletes the now-unused `odb_source_write_alternates()` function and its infrastructure across all ODB backends.

The series is well-motivated and technically sound, with no expected user-visible behavior changes. The lockfile adoption resolves the primary blocker from the first iteration, and the remaining changes are mechanical refactorings that align with the broader ODB abstraction goals. Reviewers will likely focus on ensuring the lockfile integration is correct and that the refactoring doesn’t introduce regressions in clone behavior or alternates handling. The updated test coverage in `t/t5604-clone-reference.sh` verifies edge cases for worktree clones and relative path resolution.
