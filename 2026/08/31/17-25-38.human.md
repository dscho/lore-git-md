This is the second patch in Derrick Stolee’s seven-part bugfix/hardening series for the trace2 subsystem. It directly addresses the root cause of the "recursion detected in die handler" crashes by replacing `xsnprintf()` with `snprintf()` in timestamp formatting functions. The change ensures that trace2 degrades gracefully under system call failures (e.g., `gettimeofday()` or `gmtime_r()` errors) or formatting errors, rather than crashing Git.

The patch modifies three timestamp functions in `trace2/tr2_tbuf.c`:
- `tr2_tbuf_local_time()` (used for SID generation)
- `tr2_tbuf_utc_datetime_extended()` (used in event traces, the source of the original crash)
- `tr2_tbuf_utc_datetime()` (used for non-extended timestamps)

Each function now initializes its `timeval` and `tm` structs to zero, preventing undefined behavior if system calls fail. Instead of `xsnprintf()`, the code uses `snprintf()` and checks its return value. On failure, it falls back to hardcoded timestamps (`"00:00:00.000000"`, `"1900-00-00T00:00:00.000000Z"`, or `"19000000T000000.000000Z"`), which are intentionally invalid to signal degraded operation to trace consumers. The patch also updates `banned-die.h` to block `xsnprintf()` in trace2, preventing regressions.

This is a **well-crafted, targeted fix** that addresses a real stability issue. The commit message clearly explains the problem (including the Git for Windows-specific `vsprintf()` behavior), the solution, and the trade-offs (degraded telemetry instead of crashes). The changes are minimal and self-contained, with no test coverage (understandable given the difficulty of reproducing system call failures). The patch aligns with the series’ broader goal of eliminating `die()`-triggering helpers from trace2 and has already incorporated feedback from v2 (e.g., zero-initialization of structs).

**Worth attention** for anyone interested in Git’s stability or telemetry, though the most critical discussion is likely happening on the first patch (about the `banned-die.h` mechanism) and the broader architectural questions raised by Jeff King.
