This thread is a clear bug report from Bence Csókás about an inconsistency in how Git validates branch names. The core issue is that `git check-ref-format` correctly rejects the single-character `@` as an invalid branch name, but the porcelain commands (`git checkout -b`, `git switch -c`, and `git branch`) all allow creating a branch named `@`. While other invalid names like `@{1}` or `@^` are properly rejected, `@` slips through due to a flaw in `git check-ref-format --branch`.

The branch can't be checked out afterward, but it can be deleted, which suggests the validation logic is unevenly applied. The report is well-documented with reproduction steps and points to the specific discrepancy in the `--branch` mode of `check-ref-format`. No responses or reviews have appeared yet, so the thread is currently just the initial report—no decisions, patches, or discussions have taken place. The fix will likely involve harmonizing the branch-name validation across all commands.
