This thread is about an inconsistency in Git’s branch name validation: porcelain commands like `git checkout -b` and `git branch` allow creating a branch named `@`, but this branch cannot later be checked out because `@` is interpreted as `HEAD`. The root cause is that `git check-ref-format --branch` (used by porcelain commands) incorrectly accepts `@` as a valid branch name, while `git check-ref-format` without `--branch` rejects it.

The discussion has clarified that the current behavior is intentional for compatibility but is widely seen as a usability trap. The agreed direction is to tighten `--branch` validation to reject bare `@` while preserving compound names like `foo@bar`. Key participants—Bence Csókás (who reported the issue), D. Ben Knoble (who confirmed the inconsistency and usability problem), and Jeff King (who framed the fix around existing precedent)—have all converged on this approach. Kristoffer Haugsbakk recently added weight to the argument by citing a 2024 thread where Junio C Hamano advocated deprecating `@` as a synonym for `HEAD`, reinforcing that stricter validation aligns with broader project goals.

No patch has been proposed yet, but the technical path is clear: adjust `check-ref-format --branch` to treat bare `@` like `HEAD` (already rejected for porcelain safety). There are no known backwards compatibility concerns, as the change targets user-facing safety. The thread is now focused on implementation.
