This thread is about an inconsistency in Git’s branch name validation: porcelain commands like `git checkout -b` and `git switch -c` allow creating a branch named `@`, but this branch cannot later be checked out because `@` is interpreted as `HEAD`. The root cause is that `git check-ref-format --branch` incorrectly accepts `@` as valid, while the non-branch mode rejects it. The discussion hinges on whether to tighten validation to prevent accidental branch creation (prioritizing safety) or preserve `@` as a convenient shorthand for `HEAD` in complex expressions (prioritizing usability).

The thread remains unresolved, with no patch proposed yet. Ben Knoble (who confirmed the inconsistency and framed it as a design trade-off).
