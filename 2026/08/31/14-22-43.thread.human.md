This thread is about an inconsistency in Git’s branch name validation: porcelain commands like `git checkout -b` and `git switch -c` allow creating a branch named `@`, even though `@` is rejected by `git check-ref-format` as an invalid ref name. The root cause is that `git check-ref-format --branch` incorrectly accepts `@` as valid. While the branch can be created, it cannot be checked out normally, creating a usability trap.

Bence Csókás reported the bug with clear reproduction steps, and D. Ben Knoble confirmed the issue, adding that the inconsistency stems from `--branch` mode in `check-ref-format` being too permissive. Knoble framed this as a design question: whether `--branch` mode should enforce stricter validation to match the general ref name rules. The discussion is now focused on how to resolve the inconsistency rather than whether it exists.

The thread is still under review, with no patches proposed yet. The key technical detail is the validation logic in `refs.c` and `check-ref-format.c`, and the open question is how strictly `--branch` mode should validate names. No other related work or prior versions are involved.
