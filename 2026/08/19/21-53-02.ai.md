This is the fourth iteration (v4) of Justin Tobler’s nine-patch series completing the ODB abstraction for `git receive-pack` by introducing the generic `odb_transaction_write_pack()` interface. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and builds on prior work (bdee7b3013) that staged incoming objects via ODB transactions.

The core goal remains unchanged: replace `git receive-pack`'s hardcoded use of `git index-pack` and `git unpack-objects` (which assume the "files" backend) with a backend-agnostic transaction interface, enabling alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles. This iteration addresses all feedback from v3, including Patrick Steinhardt’s substantive design concerns about ".keep" file placement and the unpack limit resolution context. The series now enforces proper transaction lifecycle management, removes reliance on global state, and adds explicit ODB source tracking to avoid fragile source list ordering.

Key changes since v3 include a new test assertion in the first patch to verify the ".keep" file is generated and placed in the quarantine directory, context-aware unpack limit resolution via `odb_transaction_flags` (using `ODB_TRANSACTION_RECEIVE` to differentiate `git receive-pack` from future `git fetch-pack` users), and a forward declaration in `pack.h` to avoid including `odb/source.h`. The unpack limit helper `get_unpack_limit()` now takes an `enum odb_transaction_flags` parameter, enabling it to resolve `transfer.unpackLimit` and `receive.unpackLimit` for `git receive-pack` (with the latter taking precedence) and future `fetch.unpackLimit` for `git fetch-pack`. The "files" backend implementation in `object-file.c` now stores the transaction flags in the `struct odb_transaction_files` and passes them to `get_unpack_limit()`, ensuring the correct configuration is used.

The series touches `builtin/receive-pack.c`, `odb/transaction.c`, `object-file.c`, and related headers, with mechanical updates to other builtins for transaction API consistency. The new `odb_transaction_write_pack()` interface moves the packfile ingestion logic from `receive-pack` into the "files" ODB backend, replacing the hardcoded `unpack()` function with a backend-agnostic callback. The transaction lifecycle is now more robust, with explicit error handling via `odb_transaction_commit_and_finalize_or_die()` and proper cleanup of ".keep" lockfiles during finalization. The unpack limit is resolved lazily in the backend, and the interface is designed to be extensible for future users like `git fetch-pack`.

This iteration appears technically sound and ready for merging, with all critical design flaws addressed and the interface refined based on reviewer feedback. The series is a significant step toward making `git receive-pack` fully ODB-agnostic, aligning with the broader ODB abstraction effort. The new test assertion and context-aware unpack limit resolution address the last open design questions from v3, and the forward declaration in `pack.h` resolves a minor include hygiene issue. The series is now well-positioned for inclusion in `next`.
