This is a zsh completion bugfix that aligns the zsh wrapper with the bash implementation to handle global Git options like `-C`, `--git-dir`, and `-p`. The patch fixes a long-standing annoyance where typing `git -C <path> <command> <TAB>` would fail to offer completions for the command or its arguments. The issue affects any global option, not just `-C`—for example, `git -p checkout <TAB>` also fails to complete branch names.

The fix is straightforward and well-explained: it adds `-C` to the `_arguments` spec and scans past all global options (and their arguments) to correctly set `__git_cmd_idx`, mirroring the logic in `git-completion.bash`. It also collects `-C` paths into `__git_C_args` so the bash helpers run `git` in the intended directory. The patch is small (25 lines), touches only `contrib/completion/git-completion.zsh`, and includes clear documentation of its limitations—chained `-C` options still don’t complete directories relative to the previous `-C` path, and the unrelated `git -<tab>` bug remains unfixed, but both are explicitly noted in the commit message.
