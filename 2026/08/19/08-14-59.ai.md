This is a **tested, substantive review** of the `http.sslVerifyStatus` OCSP stapling feature. Patrick Steinhardt provides a complete, self-contained test harness that enables full OCSP stapling validation in Git’s HTTP test suite, addressing the last major gap in the patch’s test coverage.

The review includes a 150-line diff that adds OCSP stapling support to `t/lib-httpd.sh`, a new Apache configuration snippet (`<IfDefine OCSP>`), a CA configuration file (`ocsp-ca.cnf`), and a new test script (`t/t5585-http-ssl-ocsp.sh`). The harness creates a test CA, issues a server certificate, runs an OCSP responder, and configures Apache to staple responses. It also provides a helper (`revoke_httpd_cert`) to revoke the certificate and restart both the responder and HTTP server, allowing tests to verify both success and failure paths. The test script itself exercises the feature by confirming that a stapled "good" response allows the connection, a revoked certificate is rejected when `http.sslVerifyStatus` is enabled, and the same revoked certificate is accepted when the option is disabled.

Patrick’s feedback is **not a rejection** but a constructive offer to close the remaining test-coverage gap. He explicitly states that the complexity may not be worth it, leaving the decision to Junio and the author. The patch is otherwise ready for `next`; this review focuses solely on the unresolved question of whether to include comprehensive OCSP testing. The infrastructure provided is production-ready and could be merged as-is if the project decides to adopt it.
