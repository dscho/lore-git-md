This is the first patch in a two-part series improving error messages for ambiguous remote branch names in `git checkout`, `git switch`, and (in the next patch) `git worktree add`. The patch extends `unique_tracking_name()` to optionally collect the names of conflicting remotes, then uses that information to provide a static, actionable advice message listing the remotes (e.g., "the branch exists on `origin`, `upstream`"). The advice is gated behind the new `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and is tailored to the command context.

The implementation introduces a new shared helper, `be_explicit()`, which standardizes the advice message across `git checkout` and `git switch`. The patch also moves an existing `die()` call earlier in the code path to replace a generic "invalid reference" error with a more specific diagnostic that explains the ambiguity, while preserving `dwim_branch()`'s return behavior to avoid disrupting existing workflows. The changes touch `builtin/checkout.c`, `checkout.c`, `checkout.h`, and (in the next patch) `builtin/worktree.c`.

This patch is functionally complete, well-tested, and addresses all substantive review feedback from earlier iterations. The design debate over static vs. command-based advice is settled in favor of Junio’s refactoring, which prioritizes immediate usability. Minor code nits (unnecessary newline, braces) remain but are not blockers. The patch is a clear usability win, providing users with concrete, actionable guidance when they encounter ambiguous remote branch names. It looks ready for merging once the remaining nits are cleaned up.
