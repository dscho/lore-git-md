This is the final patch in Justin Tobler’s nine-patch v4 series completing the ODB abstraction for `git receive-pack`. It introduces the generic `odb_transaction_write_pack()` interface, replacing the hardcoded `unpack()` logic in `builtin/receive-pack.c` with a backend-agnostic callback. The "files" backend implementation in `object-file.c` reuses the existing `unpack()` logic but now manages ".keep" lockfiles within the transaction lifecycle, ensuring they are removed during finalization.

The patch moves 157 lines of packfile ingestion logic from `receive-pack.c` into `object-file.c`, adding the new `odb_transaction_write_pack()` callback to the ODB transaction vtable. The `struct odb_transaction_files` gains fields to track multiple ".keep" lockfiles (`pack_lockfiles`, `pack_lockfiles_nr`, `pack_lockfiles_alloc`) and the transaction flags (`flags`), enabling context-aware unpack limit resolution. The `odb_transaction_write_pack_opts` struct bundles unpack options (fsck settings, shallow file, max input size, etc.) previously passed as separate globals or function parameters. Call sites in `receive-pack.c` are updated to use the new interface, and the explicit `delete_tempfile(&pack_lockfile)` call is removed since lockfile cleanup is now handled by the transaction’s `finalize()` callback.

This patch is a clean refactoring with no user-visible behavior change. It addresses the last technical hurdle from v3 by ensuring ".keep" lockfiles are managed within the transaction lifecycle, eliminating the race condition introduced in bdee7b3013. The interface is designed to be extensible for future users like `git fetch-pack`, and the explicit file descriptor passing aligns with the ODB transaction system’s design. The series is now technically complete and ready for merging, pending any final surface-level feedback. Key symbols introduced: `odb_transaction_write_pack()`, `odb_transaction_write_pack_opts`, `write_pack` callback in `struct odb_transaction`, and the `pack_lockfiles` array in `struct odb_transaction_files`.
