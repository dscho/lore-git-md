This thread is a bugfix series from Patrick Steinhardt addressing a subtle but important issue in Git’s object database (ODB) subsystem. The problem is in how Git distinguishes between missing and corrupt objects when reading from packfiles: currently, if an object is marked as corrupt, the `find_pack_entry()` function incorrectly reports it as missing instead of corrupt. This happens because the function exits early when it encounters a known-bad object without passing the corruption status back up the call chain.

Patrick’s fix modifies the plumbing to propagate whether an object is corrupt and, if so, which packfile contains it. This change touches core ODB files (`odb/source-packed.c`, `packfile.c`, `midx.c`) and updates function signatures in headers and a few call sites. While this patch doesn’t yet change user-facing behavior—error messages will be improved in a later patch—it lays the groundwork by extending the API to pass a `struct packed_git **bad_pack` parameter through the call stack. The series is part of Patrick’s ongoing ODB abstraction effort, where consistent error reporting is a key prerequisite.

So far, this is the first version (`v2`) of the series, and only the first patch has been posted. There’s been no review yet, so the discussion is just getting started. If you’re following the ODB work, this is one to watch—it’s a foundational change that will support future improvements in error handling and object storage.
