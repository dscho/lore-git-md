This is a Trace2 instrumentation patch for `git pack-objects`. The author has sent a v2 that addresses Junio C Hamano’s **substantive review feedback** from v1 by simplifying the byte-accumulation logic. The patch adds a new Trace2 event (`write_pack_file/wrote_bytes`) that records the cumulative size of all pack files generated during a single `git pack-objects` invocation, including headers and checksums. This fills an observability gap for measuring how compression settings affect push performance, as Trace2 already records object counts but not byte counts.

The v2 patch drops the intermediate `pack_bytes` variable and directly accumulates the total bytes written in the common code path, as Junio suggested. The change is minimal and focused: only `builtin/pack-objects.c` and the test suite (`t/t5300-pack-object.sh`) are touched. The tests verify the event fires for both single and split packs (when `pack.packSizeLimit` is set), and the patch remains well-scoped and uncontroversial.

The motivation is clear and practical: users need pack size metrics to compare compression settings, and this patch provides that data without changing on-disk formats or behavior. The implementation is now cleaner and aligns with Junio’s preference for minimal, self-documenting code. The patch looks ready for integration, assuming no further feedback emerges.
