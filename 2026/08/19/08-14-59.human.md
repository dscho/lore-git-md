This is a **security feature patch follow-up** in the ongoing `http.sslVerifyStatus` thread. Patrick Steinhardt responds to Grayson Gordon’s v4 patch with a **substantive, tested review** that directly addresses the unresolved question of comprehensive OCSP testing.

Patrick provides a **fully functional test harness** for OCSP stapling, including:
- A new `LIB_HTTPD_OCSP` flag that enables OCSP stapling in the test Apache server (implying SSL).
- Certificate authority setup (`prepare_ocsp_stapling`) with a test CA, server certificate, and OCSP responder.
- Helper functions to start/stop the OCSP responder (`start_ocsp_responder`, `stop_ocsp_responder`) and revoke certificates (`revoke_httpd_cert`).
- A new test script (`t/t5585-http-ssl-ocsp.sh`) that verifies:
  - Basic certificate verification against the test CA.
  - Successful fetch with a stapled "good" OCSP response.
  - Rejection of a revoked certificate when `http.sslVerifyStatus` is enabled.
  - Acceptance of a revoked certificate when the option is disabled (demonstrating the feature’s opt-in nature).

The patch is **ready to use**—it includes all necessary configuration files (`ocsp-ca.cnf`, Apache `SSLStaplingCache` directives) and updates `t/meson.build` to include the new test. Patrick’s implementation is **fail-safe**: the OCSP responder is started with a 60-second nonce validity window, and the test suite will skip if the responder fails to start.

This contribution **resolves the last open technical question** from the v4 discussion: whether to include comprehensive OCSP testing. Patrick’s patch demonstrates that the infrastructure is feasible and provides a clear path forward.
