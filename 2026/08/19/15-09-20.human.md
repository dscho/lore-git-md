This is a v2 bugfix patch for the config subsystem. It makes `git config -e` return a non-zero exit code when the configured editor fails (crashes or exits with an error), rather than always returning 0. The change is a single line in `builtin/config.c`: `show_editor()` now returns the error code from `launch_editor()` instead of hardcoding a success return.

The patch includes two new tests in `t/t1300-config.sh` to verify the behavior for both successful and failed editor invocations, using `test_env` to set `GIT_EDITOR` to `true` or `false`. This version incorporates minor test-script cleanups suggested in the v1 review (simpler test names and proper environment handling), but the core change remains unchanged.

The feature being modified was introduced in mid-2024, so the risk of breaking existing scripts is lower than it would be for older functionality. However, the thread's central question—whether the current behavior (ignoring editor failures) was intentional—remains unresolved. Junio has framed this as a trade-off between conceptual correctness (aligning with commands like `git commit`) and potential script breakage, but hasn't taken a firm position. Karthik Nayak and brian m. carlson support the change, arguing that surfacing editor failures is more intuitive and safer for scripts using `set -e`.

The patch itself is clean and well-scoped, with appropriate test coverage. Its fate hinges on whether the community prioritizes consistency with other Git commands or backward compatibility.
