This is a bugfix patch from Patrick Steinhardt, part of a five-patch series targeting the object database (ODB) subsystem. It addresses a subtle but important correctness issue in how Git distinguishes between missing and corrupt objects when reading from packfiles.

The problem is that when an object is marked as corrupt in a packfile, the current code incorrectly reports it as missing rather than corrupt. This happens because `find_pack_entry()` returns a "not found" result for corrupt objects, and the higher-level code doesn't distinguish between "not found because missing" and "not found because corrupt." The patch fixes this by propagating information about whether an object is corrupt (and which packfile contains it) up through the call stack.

The change touches several key files in the ODB and packfile handling code: `odb/source-packed.c`, `midx.c`, `packfile.c`, and their headers. The patch is well-motivated with a clear explanation in the commit message, and the implementation looks careful - it even anticipates a future need (generating user-facing error messages that identify the corrupt packfile) by passing a `struct packed_git **` parameter rather than a simple boolean.

This is the first patch in the v2 of a series, so expect follow-up patches that build on this foundation. The fix appears to be a genuine bug rather than a feature or refactoring, and the affected code paths are central to Git's object storage, so this is likely to be of interest to anyone working with large repositories or custom ODB backends.
