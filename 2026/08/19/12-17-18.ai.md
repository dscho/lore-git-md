This is a refactoring patch series targeting the object database (ODB) subsystem, specifically the handling of corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. This is the second iteration (v2) of a five-patch series by Patrick Steinhardt, addressing feedback from Junio C Hamano on the initial submission.

The series now formalizes the return convention for `odb_source_read_object_info()` using an `enum odb_read_status` with negative error codes (e.g., `ODB_READ_ERROR = -1`, `ODB_READ_NOT_FOUND = -2`), resolving Junio’s concern about overloading positive values for missing objects. The changes ensure that corrupt objects are reported consistently regardless of backend, and that error messages are generated by the backend that encountered the failure rather than reconstructed after the fact.

Key technical details include:
- **Files touched**: `odb.c`, `odb/source-*.c`, `packfile.c`, `midx.c`, `builtin/pack-objects.c`, and related headers, plus test files (`t1060-object-corruption.sh`, `t/unit-tests/u-odb-inmemory.c`).
- **Behavior changes**: `odb_source_read_object_info()` now returns negative values for all error conditions, including missing objects (`ODB_READ_NOT_FOUND`). The `OBJECT_INFO_DIE_IF_CORRUPT` flag is handled generically in the ODB layer, which accumulates error messages from all backends and dies with the first available message when the flag is set. The loose backend no longer dies unconditionally on corruption, allowing other backends to provide a good copy.
- **New infrastructure**: The `read_object_info()` callback now accepts an `errmsg` parameter to bubble up backend-specific error messages, and the `bad_pack` logic in `fill_midx_entry()` enables richer error reporting (e.g., "packed object X (stored in Y) is corrupt").
- **Test coverage**: Updated tests verify that corrupted loose objects can still be read from alternate repositories, and that the new error conventions are respected.

The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, which aims to make Git’s object storage layer more modular and backend-agnostic. The changes are internal to the ODB subsystem and do not introduce new user-facing options or commands. The on-disk format remains unchanged.

This v2 addresses all design-level feedback from Junio, though the granularity of the `bad_pack` logic (object-level vs. pack-level) remains a potential point of discussion for future work. The patches are well-structured, with clear commit messages and thorough test updates, indicating a high-quality refactoring effort.
