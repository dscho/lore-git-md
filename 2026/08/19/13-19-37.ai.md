This is the first patch in Karthik Nayak's three-part series optimizing reftable stack reloads during transactions. The patch removes the `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag and makes stack reloading the default behavior in `reftable_stack_init_addition()`.

The change is a targeted cleanup that simplifies the reftable stack logic by eliminating a flag that all callers were already propagating. The commit message explains that since 16684b6fae (2025-08-12) all call sites already ensure stack reloading when needed, making the flag redundant. The patch removes the flag from the API, updates all callers (including unit tests), and removes redundant `REFTABLE_OUTDATED_ERROR` checks that are now handled by the default reload flow.

Files modified include `refs/reftable-backend.c`, `reftable/stack.h`, `reftable/stack.c`, and the corresponding unit tests in `t/unit-tests/u-reftable-stack.c`. The test modifications reflect the new default behavior, particularly in cases where outdated stacks are now automatically reloaded rather than requiring explicit flag propagation.

This patch sets the stage for the subsequent two patches in the series, which move the lock state into the `reftable_stack` structure and use it to skip unnecessary reloads during transactions. The change is mechanical and well-justified, with clear performance motivations established in the series cover letter.
