This is the second patch in Patrick Steinhardt’s five-patch v2 series refactoring how the object database (ODB) handles corrupt objects. It introduces a formal `enum odb_read_status` to distinguish between successful reads (`ODB_READ_OK`) and generic failures (`ODB_READ_ERROR`), laying the groundwork for a later patch that will add a third status (`ODB_READ_NOT_FOUND`) to explicitly signal missing objects.

The patch mechanically updates the function signatures and return types of `odb_read_object_info_extended()` and the `read_object_info()` callback in all ODB sources (in-memory, packed, loose, files) to use the new enum instead of a bare `int`. The packed backend’s existing positive-return convention for missing objects is preserved for now; the next patch will align it with the new enum. No behavior changes are introduced yet—this is purely a type-system cleanup that makes the error signaling more explicit and prepares for the tri-state logic that Junio C Hamano requested in the v1 feedback. The commit message is clear and the diff is straightforward, indicating a well-executed refactoring step.
