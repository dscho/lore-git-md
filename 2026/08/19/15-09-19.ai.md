This is a v2 bugfix patch for the config subsystem, updating the test script to address surface-level review feedback. The patch itself remains unchanged: it still modifies `show_editor()` in `builtin/config.c` to propagate the editor's exit code when `git config -e` is run, so that editor failures (crashes or non-zero returns) now cause Git to exit non-zero instead of always returning 0. The only differences in this version are cosmetic improvements to the test suite—replacing manual `GIT_EDITOR` export/unset with `test_env` and renaming tests from `--edit` to `-e` to match the actual command being tested.

The patch is part of an ongoing discussion about whether the current behavior (ignoring editor failures) was intentional and whether the benefit of consistency with commands like `git commit` outweighs the risk of breaking scripts. The feature being modified was introduced mid-2024, which limits but doesn’t eliminate the breakage risk. Junio has framed the decision as a trade-off but hasn’t taken a firm position, while Karthik Nayak and brian m. carlson support the change, arguing it improves user experience and script safety. The author has incorporated the test-script cleanups but left the core implementation and trade-off unresolved.

The files touched are `builtin/config.c` (one-line change in `show_editor()`) and `t/t1300-config.sh` (two updated tests). No new symbols or on-disk formats are introduced, and the behavior change is limited to error-propagation in the editor path. The tests now use `test_env` for cleaner environment setup and cover both editor success (exit 0) and failure (exit 1) cases. The patch is technically sound and well-scoped, but its fate depends on whether the community prioritizes consistency or backward compatibility.
