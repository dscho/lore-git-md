This is the final patch in Justin Tobler’s nine-patch v4 series making `git receive-pack` fully ODB-agnostic. It introduces the new `odb_transaction_write_pack()` interface and moves the packfile ingestion logic from `builtin/receive-pack.c` into the "files" ODB backend (`object-file.c`).

The patch deletes the old `unpack()` function (157 lines removed) and replaces it with a backend-agnostic callback. The "files" backend implementation (`odb_transaction_files_write_pack()`) is almost a verbatim copy of the deleted code, but now lives in `object-file.c` and uses the transaction’s stored flags to resolve the correct unpack limit (`transfer.unpackLimit`/`receive.unpackLimit`). The `.keep` lockfile management is also moved into the backend: lockfiles are registered in a new `pack_lockfiles` array on the transaction struct and cleaned up during `finalize()`.

Call sites in `receive-pack.c` are updated to use the new interface; the only visible change is the type of the `opts` struct (`odb_transaction_write_pack_opts` instead of `unpack_opts`). The series’ earlier patches already removed the global `pack_lockfile` variable and the explicit `delete_tempfile()` call, so this patch is purely mechanical.

The patch is well-motivated, thoroughly tested (the enhanced `t/t5547-push-quarantine.sh` test covers `.keep` file placement and cleanup), and addresses all feedback from v3. It completes the ODB abstraction for `git receive-pack` and is ready for `next`.
