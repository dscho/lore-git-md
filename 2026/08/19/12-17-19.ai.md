This is a bugfix patch in the object database (ODB) subsystem, specifically targeting the packed-object backend. It is the first patch in a five-part series (`[PATCH v2 1/5]`) by Patrick Steinhardt.

The patch addresses a logic error in how Git distinguishes between missing and corrupt objects when reading from packfiles. Currently, if an object is marked as corrupt in a packfile, `find_pack_entry()` incorrectly reports it as missing rather than corrupt. This happens because the function returns early when it encounters a known-bad object, without propagating the corruption status upward. The fix modifies the call chain to bubble up whether the object is corrupt and, if so, which packfile contains it, allowing the ODB layer to return the correct error code.

The change touches core ODB plumbing (`odb/source-packed.c`, `packfile.c`, `midx.c`) and updates function signatures in headers (`midx.h`, `packfile.h`). The patch also adjusts a few call sites in `builtin/pack-objects.c` and a test helper. While the patch does not yet use the packfile information for user-facing error messages (that is deferred to a later patch in the series), it lays the groundwork by extending the API to pass a `struct packed_git **bad_pack` parameter through the call stack.

The commit message is clear and technical, explaining both the bug and the chosen solution. The patch itself is mechanical and focused, with no behavior change visible to users in this iteration. The series context suggests this is part of Patrick’s ongoing ODB abstraction effort, where consistent error reporting is a prerequisite for higher-level features.
