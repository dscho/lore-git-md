This is a brief reply in the ongoing ODB refactoring series. Patrick Steinhardt acknowledges Junio C Hamano’s design feedback on patch 2/7, agreeing to change the return convention for `odb_source_read_object_info()` from a hard-coded positive value (`1`) for missing objects to a more formalized enum-based approach. The exact enum values are not yet settled—Junio prefers negative error codes (e.g., `-ENOENT`) for all error conditions, including missing objects, while the current series uses positive values for missing objects and negative for corruption. This concession addresses one of the two open design concerns raised by Junio (the tri-state return convention), but the second concern—the granularity of the `bad_pack` logic in patch 3/7—remains unresolved. The thread is now waiting for a revised version of the series that incorporates this change.
