This is a refactoring patch in Justin Tobler’s nine-patch series making `git receive-pack` fully ODB-agnostic. It prepares the ground for moving the packfile unpacking logic behind the new `odb_transaction_write_pack()` interface by changing how errors are reported: instead of returning a static string, the `unpack()` function now writes error messages to a caller-provided `strbuf` and returns a negative value on failure. The call sites in `receive-pack.c` are updated to match.

The change is mechanical and well-contained: the patch touches only `builtin/receive-pack.c`, converting the error-reporting path from a string return to a `strbuf` parameter. The motivation is clear—future ODB backends need a way to report errors without being tied to static strings—and the implementation is straightforward. No behavior change is visible to users, and the patch includes no new tests because the existing test suite already covers the error paths.

This is a sensible, uncontroversial step in the ODB abstraction effort. The patch is clean, the commit message is clear, and the change aligns with the series’ overall goal of making packfile ingestion backend-agnostic. It looks ready for merging.
