This is the third patch in Patrick Steinhardt’s v2 series refactoring how the object database (ODB) distinguishes between missing and corrupt objects. The patch introduces the `ODB_READ_NOT_FOUND` error code (`-2`) and updates all ODB backends (in-memory, loose, packed, and files) to return it when an object truly does not exist, rather than conflating that case with corruption (`ODB_READ_ERROR = -1`).

The change is mechanical and preparatory: the new error code is plumbed through the `read_object_info()` callbacks and their callers, but `odb_read_object_info()` itself still returns `-1` for both missing and corrupt objects until a later patch in the series. The loose backend’s `read_object_info_from_path()` helper is updated to check `errno` for `ENOENT` and return `ODB_READ_NOT_FOUND` in that case, while continuing to return `ODB_READ_ERROR` for other failures (e.g., permission denied, corrupt header). The packed backend’s positive return code for missing objects is changed to `ODB_READ_NOT_FOUND`, and the files backend now prefers the packed source’s error code when both sources fail, ensuring that corruption errors take precedence over missing-object errors.

Test coverage is light but sufficient: the in-memory backend’s unit test is updated to expect `ODB_READ_NOT_FOUND` for missing objects. No behavior changes are visible to users yet; this patch only lays the groundwork for the subsequent commit that will make `odb_read_object_info()` return the new error code. The patch is clean, well-motivated, and directly addresses the feedback from Junio C Hamano on the v1 series.
