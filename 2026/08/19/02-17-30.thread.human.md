This thread is a bug report from Yuri about `git stash push` failing non-atomically and producing unhelpful error messages when dealing with large untracked files. The report details two specific failure scenarios: first, when attempting to stash a 2GB untracked file, the command fails with "unable to generate diff" but leaves behind an invalid stash entry and the original file changes intact. After removing the large file, a second attempt fails with "patch too large" without indicating the actual size limit (reportedly 1GB). Yuri argues that error messages should be more explicit about limits and that stash operations should be atomic—either fully succeeding or fully rolling back on failure.

The report includes clear reproduction steps and emphasizes the problematic state left behind after failures, particularly the invalid stash entry missing files. While no patch is provided, the discussion is framed constructively, focusing on observable behavior and user experience rather than implementation specifics. So far, there are no replies or proposed fixes from other contributors.
