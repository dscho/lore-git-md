This is the eighth patch in Justin Tobler’s nine-patch v4 series making `git receive-pack` fully ODB-agnostic. The patch addresses a fragility in the ODB transaction system by returning the newly installed temporary ODB source directly, rather than forcing callers to assume it is the first entry in the source list.

The change is a targeted refactoring of the `odb_set_temporary_primary_source()` and `tmp_objdir_replace_primary_odb()` functions. Instead of returning the *previous* primary source (which was only useful for restoration), the functions now return the newly installed source and report the previous one via an optional out parameter. The "files" ODB transaction struct gains a `quarantine` field to store this source, eliminating the need to rely on source list ordering during transaction commit. This is a clean, mechanical change that touches only the ODB plumbing layer (`odb.c`, `odb.h`, `tmp-objdir.c`, `tmp-objdir.h`) and the "files" backend transaction struct in `object-file.c`.

The motivation is clear: the current design is awkward and fragile, requiring callers to assume the temporary source is always `repo->objects->sources[0]`. The new approach is more robust and self-documenting, storing the source explicitly in the transaction struct. The patch is well-explained in the commit message and aligns with the broader ODB abstraction effort’s goal of eliminating implicit state.

This patch was explicitly approved by Patrick Steinhardt in the v3 review, and the implementation matches the agreed-upon design. It is a straightforward improvement with no behavior change, and the interface change is backward-compatible (the out parameter is optional). The patch is ready for merging and fits cleanly into the series.
