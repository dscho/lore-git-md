This is the final version of a bugfix patch that restores the intended behavior of `git worktree add -b/-B`. The patch disables DWIM (Do What I Mean) branch resolution when the user explicitly provides a branch name with `-b` or `-B`, preventing unintended branch creation. This fixes a regression introduced in Git v2.42.0 by commit `128e5496b3` ("worktree add: extend DWIM to infer --orphan").

The patch is narrowly scoped to `builtin/worktree.c`, where it wraps the DWIM logic in a `!new_branch` guard, ensuring that explicit branch creation takes precedence. The accompanying test in `t/t2400-worktree-add.sh` validates that the error message `fatal: invalid reference: foo` appears when an invalid branch name is provided with `-b`. The test was refined in this version to avoid redundant setup and explicitly check the error message, addressing feedback from Junio C Hamano.

This version (v3) incorporates all prior feedback: it preserves warning behavior for edge cases (e.g., `-b HEAD`), uses `setup_remote_repo` for cleaner test setup, and tweaks the commit message to cite the regression commit with `log -1 --pretty=reference`. The fix is now merged to `master` and resolves the regression without side effects. No further discussion is expected.
