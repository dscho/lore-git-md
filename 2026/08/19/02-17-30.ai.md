This is a bug report about `git stash` behavior, specifically its non-atomic failure mode and unhelpful error messages.

The author describes a scenario where `git stash push` fails when attempting to stash a large (2GB) untracked file. The first failure ("unable to generate diff") leaves behind both an invalid stash entry and the original file changes, violating atomicity. After removing the large file, a second attempt fails with "patch too large" — again without specifying the actual size limit. The author argues that error messages should be more informative (e.g., stating the 1GB limit) and that `git stash` operations should be atomic: if the command fails, it should leave no partial state.

The report includes concrete reproduction steps and highlights two distinct failure modes: one related to diff generation for large files, and another related to patch size limits. The author also notes that the leftover stash entry is invalid because it is missing at least one file. No patch is provided; this is purely a problem statement aimed at prompting discussion or future fixes. The tone is constructive, focusing on observable behavior rather than implementation details.
