This is a zsh completion bugfix that aligns the zsh wrapper with the bash implementation to handle global Git options like `-C`, `--git-dir`, and `-p`. The v2 patch expands the scope beyond just `-C` to fix completion for *all* global options, addressing the core issue: the zsh wrapper hard-coded `__git_cmd_idx=1`, assuming the command was always the first argument. Now it scans past global options and their arguments (e.g., `-C <path>` or `--git-dir=<path>`) to correctly identify the command index, mirroring the logic in `__git_main` from `git-completion.bash`. The patch also collects `-C` paths into `__git_C_args` so the bash helpers run `git` in the intended directory, resolving aliases and refs properly.

The change is well-motivated and technically sound. It fixes a long-standing gap where `git -C <path> <command> <TAB>` or `git -p checkout <TAB>` would fail to complete commands or arguments, a common frustration for users. The implementation is clean: it reuses the existing loop counter (`i`) and avoids introducing new variables, while the commit message clearly documents the remaining limitations (e.g., chained `-C` directory completion and the pre-existing `git -<tab>` bug). The patch touches only `contrib/completion/git-completion.zsh` (25 lines added) and has no impact on on-disk formats, CLI behavior, or tests.
