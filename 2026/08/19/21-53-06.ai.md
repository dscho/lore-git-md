This is the fourth patch in Justin Tobler’s nine-patch v4 series making `git receive-pack` fully ODB-agnostic. It removes the global `unpack_limit`, `receive_unpack_limit`, and `transfer_unpack_limit` variables and replaces them with a new `get_unpack_limit()` helper that reads the configuration lazily inside `unpack()`. The change is a direct consequence of the series’ broader goal: moving packfile ingestion logic behind the pluggable `odb_transaction_write_pack()` interface, where the unpack limit must be resolved by the backend rather than hardcoded in `receive-pack`.

The patch deletes the now-unused globals and their configuration callbacks in `receive_pack_config()`, then introduces `get_unpack_limit()` to read `transfer.unpackLimit` and `receive.unpackLimit` (with the latter taking precedence) from the repository. The `unpack()` function now calls this helper instead of consulting the global `unpack_limit`. This is a mechanical but necessary step toward backend-agnostic packfile handling, as the decision to explode a packfile is a storage detail that should not leak into the generic transaction interface.

No user-visible behavior change is introduced; the patch is purely preparatory for the ODB abstraction. The new `get_unpack_limit()` helper will later be extended to accept an `enum odb_transaction_flags` parameter (added in a subsequent patch) to distinguish between `git receive-pack` and future `git fetch-pack` users, but this patch keeps the interface simple while removing the global state. The change is well-scoped and aligns with the series’ overall design direction.
