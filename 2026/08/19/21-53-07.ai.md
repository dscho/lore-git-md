This is the fifth patch in Justin Tobler’s nine-patch v4 series making `git receive-pack` fully ODB-agnostic by introducing the `odb_transaction_write_pack()` interface. The patch lifts global state out of the `unpack()` function in `builtin/receive-pack.c` and replaces it with an explicit `struct unpack_opts` parameter, preparing the code for the subsequent move to a backend-agnostic transaction interface.

The patch touches only `builtin/receive-pack.c`, replacing the global variables `receive_fsck_objects`, `transfer_fsck_objects`, `fsck_msg_types`, `max_input_size`, `reject_thin`, and `quiet` with a new `struct unpack_opts` that bundles these settings. The `unpack()` function signature changes from `(struct odb_transaction *, const char *shallow_file, int err_fd)` to `(struct odb_transaction *, const struct unpack_opts *)`, and the `unpack_with_sideband()` helper initializes the struct with the same ternary logic that previously set `fsck_objects`. The `err_fd` field is assigned late in `unpack_with_sideband()` to accommodate the sideband muxer’s file descriptor.

This is a refactoring patch with no user-visible behavior change; it is a prerequisite for patch 6/9, which moves the `unpack()` logic behind the new `odb_transaction_write_pack()` interface. The patch follows the series’ established pattern of removing global state and making configuration context explicit, aligning with the broader ODB abstraction effort. The `struct unpack_opts` initialization uses the same ternary logic as the original code, preserving the existing precedence rules for `receive_fsck_objects` and `transfer_fsck_objects`. The patch is mechanically straightforward and appears technically sound, addressing the global state removal goal without introducing new complexity.
