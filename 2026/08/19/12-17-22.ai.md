This is the fourth patch in Patrick Steinhardt’s v2 series refactoring how the object database (ODB) subsystem handles corrupt objects when `OBJECT_INFO_DIE_IF_CORRUPT` is used. The series is part of the ongoing ODB abstraction effort to make error reporting consistent and backend-agnostic.

This patch introduces an `errmsg` parameter to the `read_object_info()` callback, allowing ODB backends (packed, loose, etc.) to populate human-readable error messages when object reads fail. Previously, the ODB layer had to reconstruct error messages after the fact, which was fragile and backend-specific. The packed and loose backends are updated to use the new parameter, though all callers currently pass `NULL`—the actual consumer will be added in a later patch. The loose backend’s direct `die()` call is preserved for now but will be removed in patch 7/7, where the ODB layer takes over responsibility for dying with the first available error message.

Key changes:
- **Files touched**: `odb/source-loose.c`, `odb/source-packed.c`, `odb/source.h`, and callers in `odb.c`, `builtin/pack-objects.c`, `packfile.c`, and unit tests.
- **New infrastructure**: The `read_object_info()` callback now accepts a `struct strbuf *errmsg` parameter, which backends populate with backend-specific error messages (e.g., "packed object X (stored in Y) is corrupt").
- **Behavior**: No immediate behavior change; the patch is preparatory for patch 7/7, which will make `OBJECT_INFO_DIE_IF_CORRUPT` fully generic.

The patch is well-structured and addresses the core problem of lost context in error propagation. The commit message clearly explains the motivation and the incremental nature of the change.
