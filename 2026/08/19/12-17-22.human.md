This is the fourth patch in Patrick Steinhardt’s v2 series refactoring how the object database (ODB) handles corrupt objects. The series is part of the ongoing ODB abstraction effort and targets internal consistency in error reporting.

This patch introduces an `errmsg` parameter to the `read_object_info()` callback, allowing ODB backends to bubble up backend-specific error messages rather than forcing the ODB layer to reconstruct them after the fact. The packed and loose backends are updated to populate the buffer with human-readable messages (e.g., “packed object X (stored in Y) is corrupt” or “loose object X (stored in path) is corrupt”). All callers are mechanically adapted to pass `NULL` for now; the actual consumer will be added in the next patch.

The change is a straightforward plumbing improvement: no behavior changes yet, just infrastructure to enable richer error messages in later patches. The diff is clean, touching only the ODB source files and a few call sites in `builtin/pack-objects.c` and `packfile.c`. Test coverage remains unchanged in this patch. It looks well-crafted and uncontroversial.
