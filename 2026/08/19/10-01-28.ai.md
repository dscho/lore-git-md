This is a **reply in an ongoing ODB refactoring thread**, specifically addressing Junio C Hamano’s review of **patch 3/7** in Patrick Steinhardt’s series to refactor corrupt-object handling.

Patrick clarifies the intent behind the `bad_pack` logic in `fill_midx_entry()`: the patch does **not** mark an entire pack as bad, only the specific objects flagged in the `bad_objects` oidset. The pack pointer is passed upward solely to enable richer error messages in a later commit (patch 7/7), where the ODB layer can report which pack contained the corrupt object. This distinction resolves Junio’s concern about over-broad pack invalidation but leaves the broader question—whether the current granularity is sufficient for multi-pack scenarios—unanswered. The reply is concise and directly addresses the technical point raised, without revisiting the tri-state return convention or other open design questions.
