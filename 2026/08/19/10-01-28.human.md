This is a **brief follow-up in the ODB corruption-handling refactor series**, specifically addressing Junio C Hamano’s review of patch 3/7. The exchange clarifies a key design point about how corrupt objects are tracked in multi-pack-index (MIDX) scenarios.

Patrick responds to Junio’s concern that the patch might mark an entire pack as "bad" if even a single object is corrupt. He explains that the patch does *not* taint the whole pack—only the specific corrupt objects are flagged. The pack reference is only propagated upward to enable more informative error messages in later patches, allowing Git to tell users which pack contains the corrupt object. This distinction is already noted in the commit message, but Patrick reiterates it here for clarity.

The response is concise and directly addresses the review comment without introducing new technical details or reopening broader design questions (like the tri-state return convention).
