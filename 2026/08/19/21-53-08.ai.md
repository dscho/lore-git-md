This is the sixth patch in Justin Tobler’s nine-patch v4 series making `git receive-pack` fully ODB-agnostic. The patch refactors error reporting in the unpacking logic to use a `strbuf` instead of returning static strings, preparing the codebase for the upcoming `odb_transaction_write_pack()` interface.

The change is mechanical but necessary: `unpack()` and `unpack_with_sideband()` now write error messages to a caller-provided `strbuf` and return a negative value on failure, rather than returning a static string. The call sites in `cmd_receive_pack()` are updated to use the `strbuf` for reporting, preserving the existing behavior while enabling the ODB transaction system to handle errors generically. The patch touches only `builtin/receive-pack.c` and makes no user-visible changes.

This is a refactoring step with no design controversy; the approach was agreed upon in earlier iterations. The `strbuf`-based error reporting is already used elsewhere in the ODB transaction system, so this patch aligns the unpacking logic with the established pattern. The change is small (36 insertions, 27 deletions) and focused, making it a low-risk prerequisite for the backend-agnostic interface introduced later in the series.

Key symbols modified: `unpack()` (signature change: now takes `struct strbuf *err_msg`), `unpack_with_sideband()` (signature change: now takes `struct strbuf *err_msg`), `execute_commands()` (signature change: now takes `int unpacker_error` instead of `const char *unpack_status`), `report()` and `report_v2()` (signature change: now take `const struct strbuf *unpack_status`). The `unpack_opts` struct and related logic remain unchanged.

The patch is part of the broader ODB abstraction effort and depends on the transaction infrastructure already merged. It is uncontroversial and ready for inclusion.
