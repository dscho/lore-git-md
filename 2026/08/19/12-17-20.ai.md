This is the second patch in Patrick Steinhardt’s v2 series refactoring how the object database (ODB) handles corrupt objects. It introduces a formal `enum odb_read_status` to distinguish between successful reads (`ODB_READ_OK = 0`) and generic failures (`ODB_READ_ERROR = -1`), laying the groundwork for a future patch that will add a third state (`ODB_READ_NOT_FOUND`) to explicitly signal missing objects.

The patch mechanically updates the `read_object_info()` callback and its callers across all ODB sources (in-memory, packed, loose, files) to return the new `enum odb_read_status` instead of a bare `int`. The packed backend’s existing positive return code for missing objects is preserved for now; the next patch in the series will align it with the new convention. No behavior changes are introduced yet—this is purely a type-system refactoring to make the error semantics explicit.

Files touched include `odb.c`, `odb.h`, and the four `odb/source-*.c` backends. The changes are straightforward: function signatures and return types are updated, and the documentation in `odb/source.h` is revised to reference the new enum. The patch is a necessary precursor to the more substantive changes in later patches, and the commit message clearly explains the motivation and scope.
