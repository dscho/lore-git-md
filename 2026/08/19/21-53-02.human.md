This is the fourth iteration (v4) of Justin Tobler’s nine-patch series completing the ODB abstraction for `git receive-pack` by introducing a generic `odb_transaction_write_pack()` interface. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt and enables alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles without being tied to the traditional files backend.

The core goal remains unchanged: replace `git receive-pack`'s hardcoded use of `git index-pack` and `git unpack-objects` with a backend-agnostic transaction interface. This iteration addresses all feedback from v3, including Patrick Steinhardt’s substantive design concern about ".keep" file placement and the forward-compatibility gap in unpack limit resolution. The series now uses transaction flags (`ODB_TRANSACTION_RECEIVE`/`ODB_TRANSACTION_FETCH`) to enable context-specific configuration resolution, ensuring the unpack limit helper (`get_unpack_limit()`) can differentiate between `git receive-pack` and future users like `git fetch-pack`. A new test hook in `t/t5547-push-quarantine.sh` verifies the ".keep" file is generated and placed in the quarantine directory before commit, addressing the race-avoidance properties Patrick raised.

Key improvements since v3 include the transaction-flag-based unpack limit resolution (patch 9/9), the test hook for ".keep" file placement (patch 1/9), and minor ergonomic fixes (e.g., forward-declaring `struct odb_source` instead of including the full header). The series continues to enforce proper transaction lifecycle management via `odb_transaction_finalize()` and `odb_transaction_commit_and_finalize_or_die()`, and all global state in `unpack()` has been lifted into an explicit `struct unpack_opts`. The "files" backend now properly manages ".keep" lockfiles, removing them post-commit via the finalize callback, and the unpack limit is resolved lazily in the backend rather than being wired through the interface.

The series touches `builtin/receive-pack.c`, `odb/transaction.c`, `object-file.c`, and related headers, with mechanical updates to other builtins for transaction API consistency. The new `odb_transaction_write_pack()` interface is designed to be backend-agnostic, with the "files" backend implementation handling the packfile ingestion logic previously embedded in `receive-pack`. The transaction lifecycle is robust, with explicit error handling and cleanup, and the unpack limit resolution is now context-aware. This iteration appears well-prepared for merging, with all critical design flaws addressed and the interface refined based on reviewer feedback. The series is a significant step toward making `git receive-pack` fully ODB-agnostic.
