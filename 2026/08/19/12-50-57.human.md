This is the first patch in a two-part series improving Git's error messages when users try to check out or switch to a branch name that exists on multiple remotes (e.g., `git checkout foo` when both `origin/foo` and `upstream/foo` exist). The patch is a usability enhancement that replaces the current terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message listing the conflicting remotes (e.g., "the branch exists on `origin`, `upstream`") and suggesting how to resolve the ambiguity.

The implementation extends the `unique_tracking_name()` function to optionally collect the names of matching remotes, then introduces a new helper function `be_explicit()` to standardize the advice message across `git checkout` and `git switch`. The advice is gated behind the new `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and is tailored to the command being used. The patch also moves an existing `die()` call earlier in the code path to replace a generic "invalid reference" error with a more specific diagnostic, while preserving the return behavior of `dwim_branch()` to avoid disrupting existing workflows.
