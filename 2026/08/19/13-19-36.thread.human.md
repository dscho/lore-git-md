This thread is a three-patch series from Karthik Nayak aimed at optimizing reftable stack reloads during reference transactions. The goal is to eliminate redundant `fstat()` calls that scale poorly with the number of references, a bottleneck identified by Jeff King. The series is currently under review in its first version.

The first patch simplified the API by removing a redundant flag and making stack reloads the default behavior. The second patch, just posted, refactors the code to move the list lock from `struct reftable_addition` into `struct reftable_stack`. This is a mechanical change that doesn’t alter behavior but enables the real optimization in the third patch, which will skip unnecessary reloads when the stack is already locked. The work is motivated by performance benchmarks showing a 1-2% improvement in `git-update-ref` clock time and a dramatic reduction in `newfstatat()` syscalls.

No substantive reviews have landed yet, but the series is self-contained and appears ready for technical feedback. It’s part of the broader reftable backend effort led by Patrick Steinhardt and Karthik Nayak.
