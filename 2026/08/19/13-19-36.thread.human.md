This thread is about a three-patch series from Karthik Nayak that optimizes the reftable backend by eliminating redundant stack reloads during reference transactions. The goal is to address a performance bottleneck where excessive `fstat()` calls were slowing down bulk ref creation. The series is currently under review, with no prior versions posted.

The first patch removes a now-redundant flag (`REFTABLE_STACK_NEW_ADDITION_RELOAD`) and simplifies the API by making stack reloading the default behavior. This change has drawn surface-level feedback from Patrick Steinhardt, who noted that while libgit2 uses the flag, all its call sites already pass it, so the change is compatible with minimal adaptation. He suggested a cosmetic rename for naming consistency but did not object to the patch’s substance. Justin Tobler had previously reviewed this patch substantively, confirming its mechanical correctness and resolving his initial questions about edge cases.

The second patch relocates a lock from `reftable_addition` to `reftable_stack` to enable the optimization in the third patch. Junio C Hamano raised a safety concern here: if multiple `reftable_addition` instances operate on the same stack, the shared lock could be prematurely released, disrupting concurrent operations. This issue must be resolved before the patch can proceed. The third patch implements the core optimization, reducing `fstat()` calls from O(n) to a constant ~55, with benchmarks showing a 1-2% performance improvement. Justin Tobler proposed an alternative approach to avoid changing a function signature, which Karthik will need to address.

The series touches the reftable backend and related unit tests, with no changes to the on-disk format. Key participants include Karthik (author), Justin Tobler (substantive reviewer), Junio (safety concern), and Patrick Steinhardt (cosmetic feedback). The main open questions are Junio’s lock safety issue and Justin’s alternative proposal for the third patch. The first patch is effectively ready to proceed once the naming suggestion is incorporated.
