This thread is about a three-patch series from Karthik Nayak that optimizes the reftable backend by eliminating redundant stack reloads during reference transactions. The goal is to address a performance bottleneck where excessive `fstat()` calls were slowing down bulk ref creation, with independent benchmarks showing a consistent 25% speedup.

The first patch, which removes the now-redundant `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag, is effectively resolved. Karthik confirmed that libgit2 (a separate project) already passes the flag at all call sites, so the change is compatible with minimal adaptation. He also agreed to Patrick Steinhardt’s cosmetic suggestion to rename a function for naming consistency, though it’s unclear whether this will be done in this series or as a separate commit. The remaining patches—relocating a lock to enable the optimization and implementing the core performance improvement—are still under review. Junio C Hamano raised a safety concern about the lock relocation potentially causing premature lock release if multiple operations use the same stack, which remains the primary blocker. Justin Tobler has also suggested an alternative implementation for the third patch, though this is more a matter of design preference than correctness.

Key participants include Karthik (the author), Jeff King (who identified the bottleneck and provided benchmark data), Justin Tobler (who reviewed the patches substantively), Junio (who raised the safety concern), and Patrick Steinhardt (who noted external compatibility and suggested a cosmetic change). The series is still under review, with no merge status reported.
