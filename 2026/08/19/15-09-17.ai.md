This is a v2 bugfix patch targeting the config subsystem. The patch propagates the editor's exit code when `git config -e` is run, so that if the editor fails (crashes or returns non-zero), Git now exits non-zero instead of always returning 0. The change is minimal: one line in `builtin/config.c` (`show_editor()` now returns the error code from `launch_editor()`) and two updated tests in `t/t1300-config.sh`.

This version incorporates Karthik Nayak's surface-level review feedback from v1: the tests now use `test_env` for `GIT_EDITOR` setup instead of manual export/unset, and the test names have been simplified from `--edit` to `-e` to match the actual command being tested. The substance of the patch remains unchanged—no new behavior or edge cases are addressed, and the core trade-off (whether surfacing editor failures is worth the risk of breaking scripts) is still unresolved.

The patch touches only the error-propagation path in `show_editor()` and does not alter on-disk formats or introduce new symbols. The two new tests cover editor success (exit 0) and failure (exit 1) using `true` and `false` as stand-ins for the editor. The feature being modified was introduced mid-2024, limiting the scope of potential breakage, but the thread's open question—whether the current behavior (ignoring editor failures) was intentional—remains unanswered.
