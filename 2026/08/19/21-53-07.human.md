This is the fifth patch in Justin Tobler’s nine-patch v4 series making `git receive-pack` fully ODB-agnostic. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and is now technically sound after addressing all v3 feedback.

This patch lifts global state out of the `unpack()` function by introducing a `struct unpack_opts` that bundles all the configuration knobs (`fsck_objects`, `shallow_file`, `max_input_size`, `reject_thin`, `quiet`, and `err_fd`) that were previously scattered as globals. The new struct is passed explicitly to `unpack()`, making the function self-contained and ready for the subsequent move behind the generic `odb_transaction_write_pack()` interface. The change is mechanical and does not alter behavior; it simply reorganizes the existing logic into a more maintainable form.

The patch touches only `builtin/receive-pack.c` and is a straightforward refactor. The `unpack_opts` struct is initialized in `unpack_with_sideband()` with the same ternary logic that previously set `fsck_objects`, preserving the existing precedence rules (`receive_fsck_objects` overrides `transfer_fsck_objects`). The `err_fd` field is assigned late, after the sideband muxer is set up, which is a minor ergonomic trade-off for clarity and testability.

This is a well-executed preparatory step that aligns with the series’ broader goal of making `git receive-pack` backend-agnostic. The patch is uncontroversial and looks ready for merging.
