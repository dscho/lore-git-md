This is a refactoring patch series targeting the object database (ODB) subsystem, specifically the handling of corrupt objects when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used. This is the second iteration (v2) of a five-patch series by Patrick Steinhardt, addressing feedback from Junio C Hamano on the initial submission.

The series refactors how Git handles corrupt objects to make the behavior consistent and backend-agnostic. Previously, the `OBJECT_INFO_DIE_IF_CORRUPT` flag was handled inconsistently: `do_oid_object_info_extended()` used a backend-specific function (`has_packed_and_bad()`) that broke abstraction, while the loose backend handled the flag directly, causing the process to die even if another backend had a good copy. This series fixes these issues by extending `odb_source_read_object_info()` to distinguish between missing and corrupt objects and to propagate error messages from backends.

Key changes in v2 include adopting an `enum odb_read_status` with negative error codes exclusively, as suggested by Junio. This required a significant restructure of the series, consolidating patches and formalizing the return convention. The series now introduces `ODB_READ_NOT_FOUND` to distinguish missing objects from corrupt ones, updates all backends to use this convention, and allows `read_object_info()` to bubble up error messages via a `struct strbuf *errmsg` parameter. The final patch removes the abstraction-breaking `has_packed_and_bad()` function and makes `OBJECT_INFO_DIE_IF_CORRUPT` fully generic, with `do_oid_object_info_extended()` now tracking corruption status and accumulating error messages from all backends.

The series touches 15 files, including core ODB logic (`odb.c`, `odb/source-*.c`), backend implementations (`packfile.c`, `midx.c`), and related utilities (`builtin/pack-objects.c`). It also updates tests (`t1060-object-corruption.sh`, `t/unit-tests/u-odb-inmemory.c`) to verify the new behavior. The changes are internal to the ODB subsystem and do not introduce new user-facing options or commands. The on-disk format remains unchanged.

This is a well-motivated refactoring that addresses a long-standing inconsistency in how corrupt objects are handled. The changes are mechanical but non-trivial, and the inclusion of test updates suggests thoroughness. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, which aims to make Git's object storage layer more modular. The refactoring should be of interest to contributors working on low-level storage or backend-specific optimizations. The unresolved question from v1 about the granularity of the `bad_pack` logic (whether object-level granularity is sufficient for multi-pack scenarios) remains open but does not block this iteration.
