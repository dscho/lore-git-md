This is the v5 iteration of a two-patch series improving user-facing error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The series is functionally complete and addresses all substantive review feedback from earlier rounds. Junio C Hamano’s refactoring (now incorporated) extends `unique_tracking_name()` to optionally return the list of conflicting remotes, enabling a static, actionable advice message that lists the remotes (e.g., "the branch exists on `origin`, `upstream`") instead of the original command-based suggestion. The advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (default: true) and is tailored to each command’s context.

The implementation touches five files: `builtin/checkout.c`, `builtin/worktree.c`, `checkout.c`, `checkout.h`, and `t/t2400-worktree-add.sh`. The core logic is unified via a new shared helper, `be_explicit()`, which standardizes the advice message across all three commands. The patch also moves an existing `die()` call earlier in the code path to replace a generic "invalid reference" error with a more specific diagnostic that explains the ambiguity, while preserving `dwim_branch()`’s return behavior to avoid workflow disruption. Test coverage is updated to verify the new advice format and error handling, including a new test for `--guess-remote` with ambiguous branches (which explicitly suppresses the warning).

The series is backward-compatible and resolves the long-standing inconsistency in how Git handles ambiguous remote branch names. The design debate (static list vs. command-based advice) is settled in favor of Junio’s refactoring, which prioritizes immediate usability. Minor code nits (unnecessary newline, braces) remain unaddressed but are not blockers. The patch looks well-crafted, thoroughly tested, and ready for merging once the remaining nits are cleaned up. It is a clear usability win with no obvious downsides.
