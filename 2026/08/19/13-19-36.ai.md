This is a performance-focused refactoring of the reftable backend, specifically targeting redundant stack reloads during reference transactions. The series addresses a bottleneck identified by Jeff King where excessive `fstat()` calls during bulk ref creation were consuming significant time.

The patch set consists of three commits. The first removes the `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag, simplifying the stack reload logic since all code paths already reload the stack. The second moves the lock state into the `reftable_stack` structure, and the third uses this lock information to skip unnecessary stack reloads when the stack is already locked during a transaction.

Key technical details: the changes modify `refs/reftable-backend.c`, `reftable/stack.h`, and `reftable/stack.c`, with corresponding test updates in `t/unit-tests/u-reftable-stack.c`. The optimization shows consistent 1-2% clock time improvements in `git-update-ref` benchmarks, but more significantly reduces `newfstatat()` syscalls from linear growth to a constant ~55 calls regardless of ref count.

The series is well-motivated by Jeff King's profiling data and demonstrates clear performance benefits in the reftable backend's handling of reference transactions. The changes appear targeted and mechanical, focusing on eliminating redundant operations rather than introducing new behavior. The test modifications suggest thorough validation of the new locking logic.
