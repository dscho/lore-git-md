This is the third patch in Patrick Steinhardt’s five-patch v2 series refactoring how the object database (ODB) handles corrupt objects. The series is part of the ongoing ODB abstraction effort and aims to make error reporting consistent and backend-agnostic when the `OBJECT_INFO_DIE_IF_CORRUPT` flag is used.

This patch introduces the `ODB_READ_NOT_FOUND` error code (value `-2`) to distinguish between truly missing objects and corrupt ones. The change is mechanical: all ODB backends (in-memory, loose, packed, and files) are updated to return `ODB_READ_NOT_FOUND` when an object does not exist, rather than the generic `-1` (`ODB_READ_ERROR`). The files backend is also updated to prefer the packed backend’s error code when both fail, ensuring that corruption errors take precedence over "not found" errors.

The patch touches six files: `odb.h` (adding the new enum value), the four ODB source files, and a unit test. No behavior changes are introduced yet—this is purely a preparatory step to make the error semantics explicit. The actual propagation of `ODB_READ_NOT_FOUND` to callers will happen in a later patch.

The commit message is clear and the patch is well-structured, with each backend’s changes logically grouped. The test update verifies that the in-memory backend now returns the correct error code for missing objects. This is a solid refactoring step that lays the groundwork for the rest of the series.
