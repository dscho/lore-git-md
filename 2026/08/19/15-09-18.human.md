This is a v2 bugfix patch for the config subsystem. The patch makes `git config -e` (edit) propagate the editor's exit code to the Git process, so that if the editor fails (crashes or returns non-zero), Git now exits non-zero instead of always returning 0. The change is minimal: one line in `builtin/config.c` (`show_editor()` now returns the error code from `launch_editor()`) and two new tests in `t/t1300-config.sh` to verify the behavior.

The patch is clean and well-scoped, addressing a specific inconsistency: unlike commands such as `git commit`, `git config -e` currently ignores editor failures, which can mask errors in scripts using `set -e`. The feature being modified was introduced mid-2024, so the risk of breaking existing scripts is limited but not zero. The author has incorporated surface-level review feedback from Karthik Nayak (using `test_env` for `GIT_EDITOR` setup and simplifying test names), but the core trade-off—whether the benefit of consistency outweighs the risk of script breakage—remains unresolved.

Junio has framed the decision as a balance between conceptual correctness and backward compatibility but hasn't taken a firm position. Karthik Nayak and brian m. carlson support the change, arguing that surfacing the error is more intuitive and safer for scripts. The patch itself is uncontroversial technically, but its fate depends on whether the community prioritizes alignment with other Git commands or preserving the current behavior. If you care about error handling consistency or script safety, this patch is worth following.
