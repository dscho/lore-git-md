This is the second patch in the v5 series improving error messages for ambiguous remote branch names in `git worktree add`. It applies the shared advice logic (introduced in the first patch) to `git worktree add`, completing the series' goal of unifying and improving ambiguous branch name handling across `git checkout`, `git switch`, and `git worktree add`.

The patch modifies `builtin/worktree.c` to call the new `advise_ambiguous_remote()` helper when `unique_tracking_name()` reports multiple matching remotes. The advice message is tailored to `worktree add`, suggesting the user specify the remote explicitly (e.g., `git worktree add -b foo ../path origin/foo`) or set `checkout.defaultRemote` to avoid future ambiguity. The error message now clearly states how many remotes matched (`matched multiple (2) remote tracking branches`), replacing the previous generic "invalid reference" error. The test suite is updated to verify the new error message format.

This patch is a straightforward application of the infrastructure introduced in the first patch. The implementation is clean, the advice is actionable, and the error message is more informative. The series as a whole is now functionally complete, with only minor code nits (unnecessary newline, braces) remaining. It looks ready to merge once those are addressed. The usability improvement is clear and uncontroversial, and the patch maintains backward compatibility.
