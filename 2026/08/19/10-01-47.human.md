This is a design discussion in the ongoing ODB refactoring series from Patrick Steinhardt. The thread focuses on how the object database (ODB) layer should signal missing versus corrupt objects to callers.

Patrick acknowledges Junio’s concern about the current tri-state return convention (zero for success, positive for missing, negative for corrupt) and agrees to formalize it with an enum that uses negative values for all error conditions, including missing objects. This resolves the immediate design question: the next version will treat missing objects as a distinct error (e.g., `-ENOENT`) rather than a positive "half-error." The packed backend’s existing positive-return behavior, which was an undocumented quirk, will be brought into line with the new convention.

The discussion is narrow but important: it clarifies the contract between ODB backends and the rest of Git, ensuring that error signaling is consistent and future-proof. No other objections or edge cases were raised in this exchange. The change is internal to the ODB subsystem and does not affect user-facing behavior or on-disk formats.

This patch is part of Patrick’s larger ODB abstraction effort, which aims to make Git’s object storage more modular. The series is still under review, with a v2 expected to incorporate this design change. If the rest of the series holds up, this refactoring looks like a clean, well-motivated improvement to Git’s internals.
