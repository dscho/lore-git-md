This is the seventh patch in Justin Tobler’s nine-patch v4 series making `git receive-pack` fully ODB-agnostic. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and has already addressed all substantive feedback from earlier iterations, including the critical ".keep" file placement design and context-aware unpack limit resolution.

This patch updates the `unpack()` and `unpack_with_sideband()` functions in `builtin/receive-pack.c` to accept an explicit file descriptor for the incoming packfile, replacing the hardcoded assumption that the packfile is always read from stdin. The change is mechanical: the new `pack_fd` parameter is passed through to `parse_pack_header()` and set as the child process’s input (`child.in`) when invoking `git index-pack` or `git unpack-objects`. The `unpack_with_sideband()` function still passes `0` (stdin) to `unpack()` when sideband multiplexing is active, preserving the existing behavior for that code path.

The patch is a straightforward refactor that prepares the ground for the next patch in the series, which will move the `unpack()` logic behind the new `odb_transaction_write_pack()` interface. No user-visible behavior changes are introduced, and the patch is well-motivated by the series’ overall goal of enabling pluggable ODB backends. The commit message clearly explains the rationale, and the code changes are minimal and focused. This looks like a clean, uncontroversial step toward the larger ODB abstraction.
