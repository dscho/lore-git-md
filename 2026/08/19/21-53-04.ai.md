This is the second patch in Justin Tobler’s nine-patch v4 series extending the ODB transaction system to make `git receive-pack` fully backend-agnostic. The patch introduces a `finalize` callback to the ODB transaction interface, decoupling transaction cleanup from the commit step. This enables backends to perform deferred operations after objects are made visible but before the transaction is freed, which is necessary for the "files" backend to manage ".keep" lockfiles in `git receive-pack`.

The patch splits `odb_transaction_commit()` into two phases: `commit()` (which makes staged objects visible) and `finalize()` (which performs backend-specific cleanup). It adds a new `finalize` callback to `struct odb_transaction` and introduces `odb_transaction_finalize()` and `odb_transaction_commit_and_finalize_or_die()` helpers. The latter is used to update existing callers that previously committed and freed the transaction in one step, while `git receive-pack` now explicitly calls `finalize()` after reference updates to ensure ".keep" files are removed at the correct time.

Key changes include:
- **New `finalize` callback**: Added to `struct odb_transaction` to enable backend-specific deferred cleanup.
- **Split transaction lifecycle**: `odb_transaction_commit()` no longer frees the transaction, allowing post-commit operations.
- **Helper function**: `odb_transaction_commit_and_finalize_or_die()` updates callers that cannot recover from failures.
- **`git receive-pack` update**: The call site is moved to after reference updates, enabling the "files" backend to remove ".keep" files during finalization.

The patch touches `odb/transaction.c`, `odb/transaction.h`, and several builtins (`add.c`, `receive-pack.c`, `unpack-objects.c`, `update-index.c`, `cache-tree.c`, `object-file.c`, `read-cache.c`). It introduces no user-visible behavior changes but lays the groundwork for the ".keep" file cleanup in patch 3/9. The design addresses Patrick Steinhardt’s feedback from v3, ensuring the transaction lifecycle is robust and extensible for future backends. The patch is a critical refactoring step toward making `git receive-pack` ODB-agnostic.
