This is the second patch in Justin Tobler’s nine-patch v4 series, which refactors the ODB transaction system to support deferred cleanup operations. The patch splits the existing `odb_transaction_commit()` into two phases: `commit()` (which makes staged objects visible) and `finalize()` (which performs backend-specific cleanup). It also introduces a convenience helper, `odb_transaction_commit_and_finalize_or_die()`, for callers that need to perform both steps atomically.

The motivation is clear: the "files" ODB backend needs to hold lockfiles after commit until references are updated, particularly to manage ".keep" files for packfiles received via `git receive-pack`. The patch enables this by adding a `finalize` callback to `struct odb_transaction` and moving the transaction-freeing logic from `commit()` to `finalize()`. The `git receive-pack` call site is updated to invoke `finalize()` *after* reference updates, while other callers (which have no intermediate work) use the new `*_or_die()` helper.

The implementation is straightforward and well-motivated. The diff is clean, touching only the transaction interface and its callers, and the commit message clearly explains the design rationale. The new `finalize` callback is optional, preserving backward compatibility. The patch is a necessary step toward fixing the ".keep" file lifecycle regression introduced in bdee7b3013, which the series addresses in patch 1/9.

This patch looks technically sound and aligns with the broader ODB abstraction effort. It is uncontroversial and ready for merging, assuming the rest of the series holds up. The split between `commit()` and `finalize()` is a sensible design choice that enables future backend-specific cleanup without complicating the core transaction API.
