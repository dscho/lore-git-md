This would address the redundancy Peff identified while still pursuing a hashmap-based solution, albeit with a narrower scope than Patrick’s original counterproposal.

The comment is **technical and concise**, focusing on code organization rather than behavior. It does not resolve the immediate regression fix (Johannes Schindelin’s fast-path patch remains the leading candidate) but signals Patrick’s intent to **revive the hashmap approach as a longer-term refactoring**. The proposal is now framed as a cleanup of the existing hashmap rather than an alternative to Johannes’s patch, avoiding direct conflict with the fast-path optimization. Key implications:

- Moving the hashmap to `packfile_list` could enable O(log N) reordering (as Patrick previously claimed) and eliminate the O(N) scan in more code paths, but this would require careful coordination with Johannes’s patch to avoid breaking the fast-path’s assumptions.
