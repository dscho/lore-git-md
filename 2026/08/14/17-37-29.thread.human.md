This thread is about a GSoC 2027 microproject by first-time contributor Tilak Raaz, who proposed a patch to warn users when the `submodule.active` configuration key is set without a value. The patch addresses a documented `NEEDSWORK` comment in `submodule.c` by switching from `repo_config_get_string_multi()` to `repo_config_get_value_multi()` and emitting a warning for valueless entries. The patch has been through two iterations, with the latest version posted inline to address `b4` compatibility, but it remains blocked by a persistent formatting corruption issue—likely caused by GMail’s plain-text handling—that prevents it from being applied for review.

Junio C Hamano recently weighed in, suggesting the patch should use Git’s existing `config_error_nonbool()` helper instead of a custom warning message. This would align the behavior with Git’s standard error reporting for valueless non-boolean configuration keys. However, the patch is still unusable due to whitespace damage, so no substantive technical review has occurred beyond this feedback. The core questions—whether a warning is the right approach, how it might affect backward compatibility, and whether the message is clear—remain open. The thread is still in the review phase, with no maintainer decision or merge status recorded.
