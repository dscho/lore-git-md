This GSoC 2027 microproject patch from first-time contributor Tilak Raaz aims to fix a long-standing NEEDSWORK comment in Git's submodule handling. The patch changes how Git processes valueless `submodule.active` configuration entries - instead of silently ignoring them as before, it now emits a warning using Git's standard `config_error_nonbool()` helper. This aligns with the project's existing error-handling patterns and addresses maintainer feedback from the first version.

The patch has evolved through two iterations, with the current version incorporating Junio Hamano's suggestion to use the standard error helper rather than a custom warning. Tilak has also resolved the whitespace corruption issues that previously blocked review by resubmitting the patch inline. The change touches `submodule.c` and adds a test case to `t7400-submodule-basic.sh`, but introduces no new symbols or on-disk format changes.

While the implementation is now technically sound and ready for review, one open question remains: whether emitting a warning is the best approach, or if valueless keys should instead be treated as boolean values or continue being silently ignored. The patch is well-scoped for a microproject, with good test coverage and clear documentation of its motivation. No merge decision has been made yet, but the patch is now in good shape for substantive technical review after overcoming its initial formatting hurdles.
