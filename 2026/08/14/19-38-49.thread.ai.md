Subject: [PATCH] chdir_notify: remove unused `name` parameter
Series version: standalone patch
Originating author: Colin Hinton
Thread type: patch (refactoring)

Core problem or goal
Remove an unused `name` parameter from the `chdir_notify` API. The `name` field in `struct chdir_notify_entry` is always set to `NULL` and never read, so the patch simplifies the registration and unregistration functions by dropping the parameter entirely. The historical context is that the `name` field was only used by `chdir_notify_reparent()`, which was removed in commit `5bf546755c` (June 2026); earlier commits (`1f43ff2c7e`, `0de2467e6c`) had already stopped passing descriptive names in favor of `NULL`.

Current status
Under review; no prior versions. The patch is a pure refactoring with no behavioral changes. Jeff King (Peff) and Junio C Hamano have both reviewed the patch and confirmed its correctness. The only remaining action is to update the commit message to document the historical context of the unused parameter, as requested by Peff and reinforced by Junio.

Key technical details
- Files touched: ten files in the object database (ODB), refs, setup, and tmp-objdir subsystems.
- Symbols changed: `chdir_notify_register()`, `chdir_notify_unregister()`, and the callback type definition.
- No new symbols, no on-disk format changes, no CLI or config changes.
- Test coverage: existing test suite expected to verify the notification mechanism remains functional.
