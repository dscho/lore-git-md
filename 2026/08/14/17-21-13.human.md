This is Jeff King (Peff) following up on the first patch in Patrick Steinhardt’s four-part series to remove lazy-loading of alternate object databases. The series is part of the broader ODB abstraction effort and is currently queued in Junio’s `seen` branch.

Peff’s reply focuses narrowly on a technical detail in the patch’s implementation: the switch from `khash` to `struct hashmap`. The patch replaces the existing `khash`-based map (which used `fspathhash()` and `fspatheq()`) with a `struct hashmap` to support per-ODB case-sensitivity tracking. Peff questions whether the limitation that prompted this switch is real. He notes that `khash` does allow custom hash and equality functions, and wonders if the issue is simply that `khash`’s interface lacks a `void *` context parameter to pass the case-sensitivity flag. His question is purely about the implementation choice, not the patch’s overall goal or correctness.

This is a surface-level review comment—it does not engage with the patch’s motivation (resolving inconsistent case-sensitivity handling when alternates are registered before repository configuration is parsed) or its broader design trade-offs (e.g., the added complexity for deduplication). The comment is unlikely to block the patch, but it may prompt Patrick to clarify or justify the choice of `struct hashmap` over `khash`. No other reviewers have raised this point, and the discussion remains open.
