This is the fourth patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators mark repositories as trusted for lazy fetching. Junio C Hamano’s review is brief but positive: he accepts the implementation as reasonable, though he remains unsure whether the underlying idea of a configuration variable is sound. The patch itself is uncontroversial and mechanically clean, adding a new `upload_pack_lazy_fetch_trusted()` function that checks whether the served repository is listed in the allowlist, using the `path_allowlist_apply()` helper introduced earlier in the series. The configuration is read only from protected files, and relative paths are rejected. This patch is plumbing-only—it exposes the check for use in the next patch but does not yet change behavior. The series as a whole is still under review, pending a resend to fix email threading, and this patch has no outstanding technical objections.
