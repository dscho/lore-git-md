This is a documentation patch, part of a small but useful cleanup to align `git diff`'s short help text with its full documentation. The patch updates the one-line description of the `-l` option (which sets the `rename_limit`) to clarify that it only restricts the *exhaustive* (quadratic-time) portion of rename detection, not all rename detection. The new wording—"limit to cheap rename/copy detection if the number of rename/copy targets exceeds this value"—avoids technical jargon like "exhaustive" and instead uses "cheap," which the full documentation already defines to include both exact and basename-guided rename detection (both linear-time operations).

The change is a follow-up to a 2021 documentation update (commit 6623a528e00b) that clarified this distinction in the man pages but left the short help text misleading. The patch itself is minimal: a single-line edit in `diff.c` to the `OPT_INTEGER` help string for `-l`. No code behavior or tests are affected—this is purely about improving clarity for users who rely on the terse `-h` output.

Elijah Newren originally proposed wording that explicitly mentioned the "exhaustive portion," but Junio C Hamano suggested simplifying it further. The current version reflects that feedback and now matches terminology already used in the full documentation. The patch is uncontroversial and looks ready to merge; it’s a small but meaningful improvement that closes a long-standing inconsistency.
