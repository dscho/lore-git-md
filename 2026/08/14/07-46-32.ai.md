This is a **substantive design discussion** in the ongoing ODB transaction series, focusing on the first patch of Justin Tobler’s v3 series. The patch fixes a critical lockfile lifecycle flaw in `git receive-pack`’s use of ODB transactions, where stale ".keep" files were left behind because the lockfile path became invalid after the transaction committed. The core of the discussion is whether the current design—writing the ".keep" file to the temporary transaction directory and migrating it alongside the packfile—actually preserves the race-avoidance properties the ".keep" file is meant to provide.

Patrick Steinhardt proposes an alternative design: write the packfile to the temporary directory *without* a ".keep" file, then at commit time write a ".keep" file to the *main* object directory before migrating the packfile, and finally remove it during finalization. This would restore the original race-avoidance properties by ensuring the ".keep" file is always in the main ODB when the packfile is migrated. Justin Tobler argues the current approach is functionally equivalent and prefers to keep the changes minimal, but agrees to clarify the commit message and add a test hook to verify the ".keep" file’s location pre-commit. The design question remains open, though the immediate bug (stale ".keep" files) is resolved by the patch.

The patch itself updates `index_pack_lockfile()` to accept an explicit `struct odb_source *` parameter, ensuring the lockfile path remains valid post-commit. Call sites in `receive-pack` and `fetch-pack` are updated to pass the correct source (the main ODB for `receive-pack`, the repository’s primary source for `fetch-pack`). A new test in `t/t5547-push-quarantine.sh` verifies that ".keep" files are removed after a successful push. The series is part of the broader ODB abstraction effort led by Patrick Steinhardt, and this patch addresses a regression introduced in an earlier ODB transaction commit (bdee7b3013).

Key technical details: the patch touches `builtin/receive-pack.c`, `fetch-pack.c`, `pack-write.c`, `pack.h`, and the test suite. The new `index_pack_lockfile()` signature and explicit `struct odb_source *` tracking are central to the fix. The discussion highlights a tension between minimal changes and preserving the original system’s invariants, with Patrick’s proposal offering a more conservative approach. The outcome will likely influence how future ODB backends handle packfile ingestion.
