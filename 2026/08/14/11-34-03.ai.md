This is a minor follow-up in the ongoing RFC thread about filesystem-level copy-on-write (CoW) or block cloning optimizations for `git worktree add`. Kristoffer Haugsbakk, a documentation contributor, replies to Peter Morris to clarify a detail about the prior art he linked earlier.

The new email points out that Peter’s observation about `git clone --block-clone` (introduced in 2024) being limited to Linux and macOS overlooks Windows support: ReFS, a Windows filesystem, also supports block cloning, and the Windows `CopyFile` API can use it automatically when source and destination are on the same ReFS volume. This means the proposed `git worktree` optimization could potentially work "for free" on Windows Dev Drives if Git were to use `CopyFile` instead of manual copying. Haugsbakk also gently reminds Peter to use Reply-All on the mailing list, a procedural note rather than a technical one.

The follow-up does not advance the core discussion about whether Git’s architecture can support a platform-agnostic abstraction for filesystem-specific cloning in `git worktree add`, nor does it engage with the open questions about edge cases, portability, or alignment with Git’s roadmap. It is a narrow correction that may help refine the technical scope of the RFC but does not substantively change the thread’s direction. Readers tracking the RFC should note the Windows angle as a potential implementation detail, but the thread remains in the conceptual phase with no patches or deeper technical feedback yet.
