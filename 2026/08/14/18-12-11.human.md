This is a review comment on the third patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`. Junio C Hamano suggests a more flexible API design for `path_allowlist_apply()` instead of adding a boolean `allow_dot` parameter. He proposes replacing the hard-coded path validation logic with a callback function, allowing callers to define their own rules for what constitutes an acceptable path. This would make the function more reusable and avoid embedding policy decisions (like whether to accept `.` or absolute paths) directly in the API.

The review is substantive: it engages with the design of the helper function and suggests an alternative approach that could better serve future use cases. Junio’s proposal is well-motivated and includes a concrete code sketch, but it would require a more invasive refactoring than the current patch. The change is not blocking—Junio does not object to the current implementation—but it raises a design question that the author may want to address in a future iteration or follow-up patch.

This patch remains part of the broader effort to enable server-side control over lazy fetching, and the review does not affect the series’ overall goal or security model. The series is still under review, pending a resend with correct email threading.
