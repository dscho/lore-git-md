This is a follow-up in the ongoing RFC thread about adding filesystem-level copy-on-write (CoW) or block cloning optimizations to `git worktree add`. The author, Peter Morris, responds to Kristoffer Haugsbakk’s earlier pointer to the 2024 `git clone --block-clone` series with a small but concrete clarification: while that earlier feature officially supports only Linux and macOS, Windows’ ReFS filesystem also supports block cloning, and the Windows `CopyFile` API will automatically use it when copying files on the same ReFS volume. This means the proposed `git worktree` optimization could work "for free" on Windows Dev Drives (ReFS-formatted volumes) if Git were to use `CopyFile` instead of its current file-copying logic.

The observation is narrowly scoped but useful: it expands the potential reach of the optimization beyond the platforms explicitly mentioned in the prior art. No new technical questions or implementation details are introduced; the email simply flags a platform-specific opportunity that the eventual implementation might leverage. Readers following the thread now have a clearer picture of the cross-platform scope and can weigh whether the Windows case strengthens the case for pursuing the feature.
