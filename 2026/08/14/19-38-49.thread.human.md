This thread is about a small but clean refactoring patch by Colin Hinton that removes an unused `name` parameter from Git’s `chdir_notify` API. The patch itself is straightforward—it drops the parameter from the registration and unregistration functions since the field is always `NULL` and never read—but the discussion has focused on documenting why this change is safe.

Jeff King (Peff) reviewed the patch early on, confirming its correctness and requesting only that the commit message be expanded to explain the historical context. A follow-up exchange between Peff and Junio Hamano filled in that history: the `name` field was only ever used by `chdir_notify_reparent()`, which was removed in June 2026 (commit `5bf546755c`), and earlier commits had already stopped passing meaningful names in favor of `NULL`. Junio’s confirmation reinforces that the parameter is truly obsolete and can be removed without risk.

The patch is still under review, but there are no technical objections or requests for code changes. The only remaining task is to update the commit message to include the historical context Peff and Junio outlined. Once that’s done, the patch should be ready to merge.
