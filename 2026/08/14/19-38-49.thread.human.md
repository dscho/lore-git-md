This thread is about a small but clean refactoring patch by Colin Hinton that removes an unused `name` parameter from Git’s `chdir_notify` API. The parameter had been lingering since `chdir_notify_reparent()`—the only function that ever used it—was removed in June 2026, and earlier commits had already stopped passing meaningful names in favor of `NULL`.

The patch itself is straightforward: it mechanically drops the `name` argument from the registration and unregistration functions and updates all callers across ten files in the object database, refs, setup, and tmp-objdir subsystems. Both Jeff King and Junio C Hamano reviewed the change and confirmed it’s safe and correct. The only feedback was to improve the commit message to document the historical context, which Colin addressed in the v2 iteration by tracing the parameter’s deprecation through three prior commits.

There are no open technical questions or compatibility concerns. The patch is a pure code hygiene improvement with no behavioral changes, and the existing test suite should be sufficient to verify that the working-directory notification mechanism remains functional. It’s now ready for merging.
