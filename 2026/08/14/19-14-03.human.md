This is a maintainer feedback email on Tilak Raaz’s GSoC microproject patch to warn on valueless `submodule.active` configuration. Junio C Hamano points out two key issues: the patch is whitespace-damaged and cannot be applied, and the warning mechanism should use Git’s standard `config_error_nonbool()` helper instead of a custom warning. The feedback is technical and actionable, directly addressing the patch’s implementation rather than its design goals.

The whitespace damage likely stems from GMail’s plain-text handling, a recurring problem for first-time contributors. Junio’s suggestion to use `config_error_nonbool()` is a clear improvement—it aligns the warning with Git’s existing error-reporting conventions and ensures consistency with other non-boolean configuration keys. This change would also make the warning message more uniform and potentially more actionable for users.

The patch’s core goal—addressing the NEEDSWORK comment in `submodule.c`—remains valid, but the implementation now needs adjustment. The backward compatibility concern (whether scripts relying on silent behavior will now see warnings) is not directly addressed here, but using a standard helper might mitigate some of that impact. The patch is still under review and not yet ready for merging; the next iteration will need to fix the whitespace issues and adopt the suggested helper.
