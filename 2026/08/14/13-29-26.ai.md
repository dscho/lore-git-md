This is a follow-up in the ongoing RFC thread about adding filesystem-level copy-on-write (CoW) or block cloning optimizations to `git worktree add`. The author, Peter Morris, responds to Kristoffer Haugsbakk’s earlier pointer to the 2024 `git clone --block-clone` series by clarifying that Windows (ReFS) is already supported via the `CopyFile` API. Morris explains that if Git were to use `CopyFile` for `git worktree add` on Windows, block cloning would happen automatically when the source and destination are on the same ReFS volume, effectively providing the optimization "for free" on Windows Dev Drives. This narrows the technical gap for Windows support and strengthens the case for a platform-agnostic abstraction, as the underlying mechanism already exists in Git’s codebase for `git clone`. No new implementation or patch is provided; the email remains conceptual but advances the discussion by removing a potential portability obstacle. Readers should note that this does not address the broader open questions about architectural feasibility, edge cases, or alignment with Git’s roadmap, but it does confirm that Windows support is technically viable without additional work.
