This is a review comment on the first patch of Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration to mark repositories as trusted for lazy fetching. The patch refactors the promisor-remote subsystem to extract lazy-fetch logic into a new `lazy_fetch_objects()` helper, consolidating environment variable checks and improving clarity.

Junio C Hamano’s feedback is substantive but narrowly focused. He suggests a minor stylistic tweak to the new helper function—using a logical OR (`||`) to chain the two `try_promisor_remotes()` calls, which would make the control flow slightly clearer. More significantly, he raises a forward-looking concern about scalability: the current implementation keeps the list of missing object names in memory, which could become problematic if the number of missing objects grows very large in real-world use. He sketches an alternative streaming API (begin/this/done) but acknowledges that the multi-remote design likely rules it out, leaving file-based spooling as a possible mitigation.

The review is positive overall—Junio calls the patch "nice and cleanly done" and confirms it is a no-op refactoring—but the scalability question is worth noting. It does not block the patch or the series, but it may resurface if promisor-remote performance becomes a bottleneck in the future. No action is required from Christian yet; the feedback is more of a heads-up than a request for changes. The series remains under review, pending a resend with corrected email threading.
