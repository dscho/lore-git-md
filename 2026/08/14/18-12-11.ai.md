This is a substantive review of the third patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`. Junio C Hamano critiques the API design of `path_allowlist_apply()`, the helper function refactored in this patch to support an `allow_dot` argument. He argues that the current approach—hardcoding path validation logic—is too rigid for a public function and proposes a more flexible design using a callback mechanism. His alternative would let callers define their own validation rules (e.g., absolute paths, warnings, or other constraints) via a function pointer, making the helper reusable beyond the immediate use case. The review includes a code sketch showing how the callback-based design would work, with the original `safe.directory` logic preserved as one possible implementation.

The critique is narrowly scoped to the API itself and does not question the patch’s motivation or its role in the broader series. Junio’s suggestion is framed as a design improvement rather than a blocker, and he acknowledges that the current approach might suffice if the function is only intended for this specific reuse. However, the callback-based design would future-proof the helper for other potential callers, such as future protected configuration variables with different path-validation requirements.
