This is the second patch in Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration mechanism to control lazy fetching. The patch refactors Git’s existing `safe.directory` allowlist logic into a reusable `path_allowlist_apply()` helper, preparing the codebase for the new configuration variable.

The refactoring is clean and well-motivated. It moves the path-matching logic from `safe_directory_cb()` into a generic helper that can be reused for `uploadpack.lazyFetchTrusted` in a later patch. The helper simplifies error handling and inverts the control flow to reduce nesting, making the code easier to read. Junio’s review notes the improvement in clarity and suggests only a minor naming tweak (`matches` instead of `is_match`), which is purely stylistic and does not affect functionality.

This patch is uncontroversial and ready for integration. It touches only `setup.c` and introduces no behavior changes, so it could plausibly be merged early even if the broader series remains under discussion. The refactoring directly enables the next steps in the series, making it a foundational piece of the effort.
