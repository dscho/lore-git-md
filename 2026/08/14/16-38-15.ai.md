This is a substantive review comment on the third patch of D. Ben Knoble’s v2 series converting `USE_NSEC` from a build-time macro to a runtime `core.useNanosec` option. Junio C Hamano identifies a cross-platform correctness issue: if a user sets `core.useNanosec=true` in a shared configuration (e.g., a network-mounted `$HOME/.gitconfig`) and then uses Git on a platform where `NO_NSEC` is defined (meaning `ST_CTIME_NSEC()` and friends are no-ops or undefined), the code will still attempt to compare nanosecond fields that may contain garbage or zero. The patch currently does not enforce any runtime guard to prevent this mismatch, leaving the door open for silent data corruption or undefined behavior on platforms lacking nanosecond support. Junio suggests either forcing `use_nanosec` to false in `NO_NSEC` builds or adding a runtime check that disables the feature when the platform does not support it. The issue is not theoretical: it directly affects users who share configuration across heterogeneous environments (e.g., Linux and older Unix variants). The review does not propose a specific fix but flags the problem as a blocker for the patch’s correctness. No other aspects of the patch are addressed in this reply.
