This is a surface-level review comment from Jeff King (Peff) on the first patch of Patrick Steinhardt’s v2 series removing lazy-loading of alternates in the object database (ODB). Peff questions a detail in the commit message: the claim that `khash` cannot support custom comparison functions. He clarifies that `khash` *does* allow custom hash and equality functions, but the interface lacks a `void*` context parameter, which would be needed to pass the case-sensitivity flag (`source_paths_icase`) to the comparison function. This is a minor technical point about implementation mechanics, not a critique of the patch’s design or correctness. The comment does not engage with the broader discussion about whether the added complexity for case-sensitivity handling is justified (Peff’s earlier substantive critique remains unresolved). No action is required from Patrick unless he chooses to update the commit message for clarity. The patch itself is unaffected.
