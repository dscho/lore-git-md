Thread identity: RFC proposing filesystem-level copy-on-write (CoW) or block cloning optimizations for `git worktree add` to reduce storage overhead and improve performance when creating multiple worktrees for the same repository. Series version: RFC (no patch version). Originating author: Peter Morris. Thread type: RFC / design discussion.

Core problem or goal: Address the inefficiency of `git worktree add` physically copying all files from the source working tree to the new worktree, which is wasteful for scenarios like concurrent AI coding agents. The goal is to leverage filesystem-level CoW or block cloning (e.g., ReFS on Windows, Btrfs on Linux, APFS on macOS) to avoid duplicating data until a file is modified, reducing SSD wear, saving disk space, and speeding up worktree creation for large repositories. The optimization would be optional and default behavior would remain unchanged on unsupported filesystems or when files differ from the checked-out version.

Current status: Conceptual discussion; no implementation or patch provided. The RFC has advanced slightly by confirming that Windows (ReFS) support is technically viable via the `CopyFile` API, which already exists in Git’s codebase for `git clone --block-clone`. This removes a potential portability obstacle but does not resolve broader open questions about architectural feasibility, edge cases, or alignment with Git’s roadmap.

Key technical details:
- Subsystems touched: `git worktree`, platform compatibility layer, potentially repository scalability (intersection with sparse-checkout, ODB backends).
- New behavior: Filesystem-level CoW or block cloning during `git worktree add` to defer physical duplication until modification.
- Old behavior: Always physically copy all files to the new worktree.
- No new CLI options, config keys, or on-disk format changes proposed yet.
- Test coverage: Not discussed; likely to require platform-specific test cases for CoW/block cloning behavior.
- Edge cases noted: Hardlinks, symlinks, correctness on filesystems without CoW support, and Windows-specific behavior (ReFS, `CopyFile` API). Windows support is now confirmed as technically viable via `CopyFile`, which is already used in `git clone --block-clone`.
- Related prior work: `git clone --block-clone` (pull.2317, 2024) demonstrates Git’s existing ability to abstract filesystem-specific cloning, including Windows (ReFS) support via `CopyFile`. This serves as a technical precedent for the proposed `git worktree` optimization.
