This is the ongoing discussion about the first patch in Justin Tobler’s nine-patch v3 series that extends ODB transactions to `git receive-pack`. The series is part of Patrick Steinhardt’s broader ODB abstraction effort, aiming to make Git’s object storage pluggable.

The immediate issue is a lockfile lifecycle flaw: when `git receive-pack` switched to ODB transactions (commit bdee7b3013), the reordering of the ODB source list caused `.keep` files to be registered with paths relative to the temporary transaction directory rather than the main object directory. After the transaction commits and the packfile migrates, the `.keep` file’s path becomes stale, preventing cleanup. Justin’s patch fixes this by explicitly passing the main ODB source to `index_pack_lockfile()`, ensuring the `.keep` file’s path remains valid post-commit.

The deeper debate is whether the current design—writing the `.keep` file to the temporary directory and migrating it alongside the packfile—actually preserves the race-avoidance properties the `.keep` file is meant to provide. Patrick proposes an alternative: write the packfile to the temporary directory *without* a `.keep` file, then at commit time write a `.keep` file to the main object directory before migrating the packfile, and remove it during finalization. Justin argues the current approach is functionally equivalent and prefers minimal changes, but agrees to clarify the commit message and add a test hook to verify the `.keep` file’s location pre-commit.

The patch itself is technically sound and fixes the immediate bug. The unresolved design question is whether the current `.keep` file placement is sufficient or if Patrick’s alternative is necessary for correctness. Justin’s next revision will address the commit message and add the requested test hook, but the fundamental design may still evolve. The series remains under review in `seen`; no merge status change yet.
