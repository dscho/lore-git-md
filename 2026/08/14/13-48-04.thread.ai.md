Subject: [PATCH] rev-parse: compute object names in other algorithms
Series version: standalone patch (no prior versions in this thread)
Originating author: Dimitri John Ledkov <dimitri.ledkov@chainguard.dev>
Thread type: feature patch

Core problem or goal
Extend `git rev-parse` to compute the name of any Git object in a different hash algorithm on demand, enabling interoperability between repositories using different object formats (e.g., SHA-1 and SHA-256) without requiring full repository conversion. The feature is narrowly scoped: it does not convert commits or persist computed names, but recursively converts trees, tags, and blobs, rejecting submodules to avoid unbounded traversal.

Current status
Under review; no prior versions of this patch in the thread. No merge status reported.

Key technical details
- **New functionality**: `repo_oid_to_algop()` in `object-file-convert.c` computes object names in another algorithm by recursively converting object contents and hashing the result.
- **Cache**: In-memory `compat_oid_cache` in `struct repository` avoids redundant computation during a single process lifetime; not persisted.
- **CLI**: `git rev-parse` now accepts any known algorithm (not just the configured `extensions.compatObjectFormat`) and reports conversion errors.
- **Files touched**: `builtin/rev-parse.c`, `object-file-convert.c`, `repository.{c,h}`, `t/t1018-output-object-format.sh` (new test script).
- **Symbols**: `compute_oid_to_algop()`, `repo_oid_to_algop()`, `compat_oid_cache` field in `struct repository`.
- **Behavior**: Rejects commits and submodules; converts trees, tags, and blobs. Performance on Linux kernel tree (1.6 GiB): ~8 seconds for SHA-256 name computation.
- **Test coverage**: New test script `t/t1018-output-object-format.sh` verifies edge cases (empty trees, submodules, unknown algorithms) and correctness against `fast-export`/`fast-import`.
