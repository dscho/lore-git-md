This is the first patch in a two-patch series (v5) continuing the `the_repository` removal effort. It prepares `builtin/pack-objects.c` for the upcoming move of the global `fetch_if_missing` variable into `struct repository` by ensuring every call site has access to a `struct repository *`.

The patch drops the `UNUSED` annotation from `cmd_pack_objects()`'s `repo` parameter and propagates it into `read_stdin_packs()`, which previously hard-coded `the_repository`. The `option_parse_missing_action()` callback, constrained by its fixed signature, now only records the desired missing-action mode (`arg_missing_action`) and defers the actual `fetch_if_missing = 0` side effect to `cmd_pack_objects()` after `parse_options()` returns, where `repo` is available. This keeps the logic flow intact while making the repository parameter explicit throughout the call graph.

The diff is clean and mechanical: nine lines added, six removed, all in `builtin/pack-objects.c`. No behavior change is introduced; the patch is purely preparatory for the follow-up commit that will move `fetch_if_missing` into `struct repository`. The coordination with the callback signature constraint is handled pragmatically, and the solution aligns with Junio’s guidance from the v4 review.
