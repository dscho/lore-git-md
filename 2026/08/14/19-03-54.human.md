This is the third patch in D. Ben Knoble’s v2 series converting the `USE_NSEC` build-time macro into a runtime `core.useNanosec` configuration option. The series aims to let users enable nanosecond precision on supported filesystems without recompiling Git, reducing "racy Git" problems.

The email is a direct reply to Junio C Hamano’s review flagging a cross-platform correctness blocker: if `core.useNanosec=true` is set in a shared configuration (e.g., a network-mounted `$HOME/.gitconfig`) and Git is run on a platform where `NO_NSEC` is defined, the code will compare nanosecond fields that may contain garbage or zero, risking silent data corruption. Junio suggested either forcing `use_nanosec` to false in `NO_NSEC` builds or adding a runtime guard.

D. Ben Knoble acknowledges the issue and proposes a simple fix: in `NO_NSEC` builds, Git should force `use_nanosec` to false, preserving today’s behavior where nanosecond paths are ignored. This matches the existing `#undef USE_NSEC` pattern and avoids exposing users to undefined behavior. The author plans to include this change in the next revision unless objections arise.

The patch is otherwise uncontroversial; the Meson build-system fix and the no-op refactor in the series are already confirmed correct and ready to advance. The remaining open question is where to cache the `core.useNanosec` value (`repo_config_values`, `repo_settings`, or a global variable), but that discussion is orthogonal to the correctness fix. The series is still under review and not yet in `seen`.
