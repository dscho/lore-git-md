This is a **bugfix and feature enhancement** for `git rev-parse` that addresses a long-standing gap in Git's object-format interoperability. The patch allows `git rev-parse --output-object-format=<algo>` to compute object names in a different hash algorithm on demand, even for objects that predate the repository's `extensions.compatObjectFormat` setting.

The problem was clear: in a SHA-1 repository, asking for a SHA-256 name of an existing object either failed outright or silently returned the wrong answer (the SHA-1 name). The fix teaches `repo_oid_to_algop()` to read the object, convert its contents, and hash the result when the loose-object map has no entry. This is efficient: trees are walked once per process, and results are cached in memory. The implementation refuses to convert commits (to avoid unbounded history traversal) and trees containing submodules (which would require converting commits in another repository).

The patch is well-motivated and thorough. It includes a new test script (`t1018-output-object-format.sh`) with 12 test cases covering trees, blobs, submodules, error conditions, and cross-algorithm round-trips. The commit message explains the design choices and performance trade-offs, and the code is cleanly structured. This looks like a real improvement for users working across repositories with different hash algorithms.
