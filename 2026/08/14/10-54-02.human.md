This is a follow-up to Peter Morris’s RFC proposing filesystem-level copy-on-write (CoW) or block cloning for `git worktree add`. Kristoffer Haugsbakk, a frequent documentation contributor, replies with a link to a prior patch series that may be relevant.

Haugsbakk points to a 2025 patch series (GitGitGadget PR #2317) that introduced a `--clone` option for `git worktree add`. That series used `cp --reflink=auto` on Linux to achieve CoW-like behavior, but it was limited to Linux and did not abstract the optimization for other platforms. The series was ultimately dropped due to portability concerns and lack of cross-platform support, but it demonstrates that the idea has been explored before.

The link serves as a useful reference point for the current RFC, showing both the technical feasibility of CoW optimizations and the challenges of making them work across different filesystems and operating systems. Haugsbakk’s reply does not take a position on the proposal itself, but it provides context that could help shape the discussion: the earlier attempt suggests that platform-agnostic abstraction is the key hurdle, and that any new effort would need to address it to avoid the same fate.
