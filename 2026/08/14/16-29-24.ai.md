This is a substantive review from Junio C Hamano in the ongoing RFC thread about filesystem-level copy-on-write (CoW) or block cloning optimizations for `git worktree add`. The review engages deeply with the technical feasibility, architectural implications, and edge cases of the proposal, offering a concrete path forward while highlighting significant challenges.

Junio clarifies that the core obstacle is not the inability to CoW-copy files from an existing worktree (a point raised by Brian Carlson in the earlier `git clone --block-clone` thread), but rather the lack of visibility in the checkout machinery into what other worktrees have already checked out. The current `checkout_entry()` helper function, which materializes files from the object database, operates in isolation and has no awareness of sibling worktrees. To implement CoW, the system would need to build a mapping of blob objects to cleanly checked-out files across all worktrees, then intercept `checkout_entry()` to perform CoW instead of writing the blob contents directly. This would require careful handling of time-of-check-to-time-of-use (TOCTOU) races, where the source file might be modified between the mapping step and the CoW operation.

The review also notes that hooking into `checkout_entry()` would affect *all* Git operations that update working tree files, not just `git worktree add`. This broadens the scope of the change and introduces potential side effects for commands like `git checkout`, `git reset`, or `git restore`. Junio suggests verifying the CoW result by hashing the copied file against the index as a way to mitigate TOCTOU issues, but expresses personal disinterest in implementing such a change due to its complexity.

For readers tracking this RFC, Junio’s feedback provides a clear technical direction while underscoring the non-trivial nature of the work. The proposal is architecturally feasible but would require significant refactoring of the checkout machinery, with implications for performance, correctness, and cross-platform consistency. The TOCTOU issue in particular is flagged as a likely pain point. No fundamental objections are raised, but the review implies that the effort would need to be carefully justified given its scope and potential risks. Future discussion may focus on whether the benefits (reduced storage overhead and faster worktree creation) outweigh the complexity, especially for niche use cases like AI coding agents.
