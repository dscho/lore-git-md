This is a **substantive review** of the first patch in Patrick Steinhardt’s ODB alternates refactoring series. Jeff King (Peff) engages deeply with the technical rationale behind the patch’s case-sensitivity handling, questioning whether the added complexity is justified.

Peff argues that `core.ignoreCase` is a flawed proxy for determining whether alternate paths are duplicates, since it reflects the *repository’s* filesystem, not the filesystem where the alternate resides. He suggests two alternatives: (1) always use case-sensitive comparisons, accepting that duplicates might occasionally slip through (but noting this is rare and mostly a performance issue), or (2) use `stat()` to compare `st_dev`/`st_ino` for potential duplicates, which would be correct but slightly more complex. He frames the trade-off as one of correctness (avoiding false deduplication) versus simplicity, and leans toward the former.

The review highlights a subtle but important edge case: if a repository on a case-insensitive filesystem references alternates on a case-sensitive filesystem, the current code might incorrectly suppress a non-duplicate alternate, leading to missing objects. Peff downplays the likelihood of this scenario but notes it’s a correctness issue, not just a performance one. His proposed `stat()`-based approach would resolve this while keeping the deduplication logic cheap for typical cases.

This feedback doesn’t block the patch—Patrick’s implementation is technically sound—but it challenges the *motivation* for the added complexity. The discussion could lead to a simpler alternative (e.g., dropping case-insensitivity entirely) or a more robust one (e.g., Peff’s `stat()` suggestion). The thread’s prior reviews (Justin Tobler, Karthik Nayak) focused on implementation details; Peff’s critique is the first to question the fundamental design choice. Future replies may need to address whether the current approach is over-engineered for a rare edge case.
