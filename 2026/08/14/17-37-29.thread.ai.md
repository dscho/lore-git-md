Core problem or goal
Address a NEEDSWORK comment in `submodule.c` by changing how Git parses valueless `submodule.active` configuration entries. The patch switches from `repo_config_get_string_multi()` to `repo_config_get_value_multi()` and emits a warning via `config_error_nonbool()` when a valueless key is encountered, with a test case in `t7400-submodule-basic.sh`. The goal is to align with Git's existing error-handling patterns for non-boolean configuration keys while providing actionable feedback to users. The unresolved question is whether the command should **fail** (exit non-zero) or **continue** (emit warning only) after encountering a valueless key.
