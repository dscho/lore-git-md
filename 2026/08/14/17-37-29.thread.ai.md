Core problem or goal
Address a NEEDSWORK comment in `submodule.c` by changing how Git parses valueless `submodule.active` configuration entries. Currently, `repo_config_get_string_multi()` silently ignores such entries; the patch switches to `repo_config_get_value_multi()` and emits a warning via `config_error_nonbool()` when a valueless key is encountered, adding a test case in `t7400-submodule-basic.sh`. The goal is to align with Git's existing error-handling patterns for non-boolean configuration keys and provide actionable feedback to users.
