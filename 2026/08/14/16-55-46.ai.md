This is a **substantive technical follow-up** in the ongoing packfile performance regression thread, focused on the feasibility of Patrick Steinhardt’s proposed hashmap refactoring. Jeff King (Peff) clarifies a **critical implementation constraint**: the existing hashmap in `packfile_store` isn’t just for duplicate checks—it also avoids the expensive `add_packed_git()` path (which involves allocations and `stat()` calls). This means the hashmap can’t be trivially moved into `packfile_list` without redesigning how packfiles are loaded, and Peff suggests that the lack of multiple callers for `packfile_list_append()` makes it premature to generalize the pattern.

The exchange narrows the scope of Patrick’s refactoring proposal. While the existing hashmap *could* be repurposed, doing so would require a broader architectural change to decouple duplicate detection from the `add_packed_git()` logic. Peff’s tone implies skepticism about the effort’s immediate value, given the single-caller context, but leaves the door open for future work if more use cases emerge. This doesn’t block Johannes Schindelin’s fast-path patch (now in `next`), but it does **dampen enthusiasm for Patrick’s longer-term cleanup**, at least until additional callers materialize or the performance trade-offs become clearer.

Key technical details for follow-up discussion:
- **Files/subsystems**: The refactoring would touch `packfile.c` (hashmap logic), `packfile-list.c`/`packfile-list.h` (list management), and potentially `builtin/repack.c` or other packfile-loading code if the `add_packed_git()` path is redesigned.
- **Symbols**: `packfile_store_add_pack()`, `add_packed_git()`, `packfile_list_append()`, and the existing hashmap in `packfile_store`.
- **Behavioral implications**: Moving the hashmap would require separating duplicate detection from packfile initialization, which could introduce subtle correctness risks (e.g., race conditions during concurrent packfile loading).
- **Performance trade-offs**: Peff’s comment highlights that the current hashmap avoids `stat()` calls, a benefit that might be lost if the logic is split.
