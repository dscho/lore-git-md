This is a documentation patch that updates the short help text for the `-l` option in `git diff`. The patch is the second iteration of a standalone fix by Elijah Newren, addressing feedback from Junio C Hamano on the initial version. It corrects a misleading description of the `-l` option (which sets the `rename_limit`), clarifying that it only limits the *exhaustive* portion of rename/copy detection rather than disabling it entirely.

The new wording—"limit to cheap rename/copy detection if the number of rename/copy targets exceeds this value"—avoids technical jargon and aligns with terminology already used in the full documentation. The change is minimal (a single line in `diff.c`) and purely documentary, with no functional impact or test requirements. Junio has marked the patch for inclusion in `next`, signaling it is ready for integration testing. The patch is uncontroversial and follows up on a 2021 documentation update that clarified the same distinction in the manual pages. No further changes are expected.
