This is a refactoring patch that removes an unused `name` parameter from Git’s `chdir_notify` API. The patch is a follow-up to v1, incorporating feedback from Jeff King and Junio C Hamano to improve the commit message by documenting the historical context of the parameter’s deprecation.

The change is straightforward: the `name` field in `struct chdir_notify_entry` was only ever used by `chdir_notify_reparent()`, which was removed in June 2026 (commit `5bf546755c`). Even before that, most callers had already stopped passing meaningful names, defaulting to `NULL` in earlier commits (`1f43ff2c7e` and `0de2467e6c`). With no remaining consumers, the patch drops the parameter from the registration and unregistration functions, simplifying the API.

The diff touches ten files across the object database (ODB), refs, setup, and tmp-objdir subsystems, updating all callers to match the new function signatures. The changes are mechanical and uniform, with no behavioral impact—just a cleanup of dead code. The updated commit message now clearly traces the parameter’s history, addressing the feedback from the previous round.

This is a well-contained, low-risk refactoring. The patch is ready for merging, with no outstanding technical concerns or open questions. It’s a small but useful hygiene improvement, reducing complexity in a low-level notification mechanism.
