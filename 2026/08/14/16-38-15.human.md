This is the third patch in D. Ben Knoble’s v2 series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). Junio C Hamano raises a subtle but important edge case: if a user sets `core.useNanosec=true` in a shared Git configuration (e.g., a networked `$HOME/.gitconfig`) and then uses Git on a platform where nanosecond precision is not supported (i.e., `NO_NSEC` is defined), the code will still attempt to compare nanosecond fields, which may be uninitialized or zero. The patch currently lacks a safeguard to force-disable `core.useNanosec` on such platforms, risking undefined behavior or false positives in racy Git detection.

The concern is narrowly scoped to the interaction between runtime configuration and compile-time platform support. The rest of the patch—caching the config value in `repo_config_values`, removing the `USE_NSEC` build knobs, and updating documentation—remains uncontested. Junio’s feedback does not question the architectural choice of caching in `repo_config_values` or the performance fix, but it does highlight a missing safety check that could affect users on mixed-platform setups. The fix would likely involve a compile-time conditional in `environment.c` or `statinfo.c` to override `core.useNanosec` to `false` when `NO_NSEC` is defined, ensuring the runtime setting cannot enable unsupported behavior. This is a targeted, low-risk addition that would not disrupt the series’ overall design.
