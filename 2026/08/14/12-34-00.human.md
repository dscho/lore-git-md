This is the first patch in the v2 series converting Git’s `USE_NSEC` macro to runtime configuration. It fixes a long-standing inconsistency in the Meson build system: the `man.base.url.for.relative.links` setting, which Makefile-based builds have exposed as a configurable knob since 2009, was hard-coded in Meson to a broken default (`$prefix/$mandir` without a trailing slash). The result was malformed relative links in generated man pages—for example, `/usr/share/manuser-manual.html` instead of the intended `/usr/share/doc/git/user-manual.html`.

The patch aligns Meson’s behavior with the Makefile by changing the default to `file://$(htmldir)/` (with a trailing slash) and adding a new `man_base_url` option to `meson_options.txt`. This gives distributions like Gentoo, which use Meson, the same flexibility they have with Make. The change is uncontroversial: Patrick Steinhardt already confirmed the fix is correct, and the commit message documents the reasoning clearly. No test updates are needed, as the fix is self-contained and the build system is already covered by CI. This patch stands on its own and could land independently if the rest of the series stalls.
