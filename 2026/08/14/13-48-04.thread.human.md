This thread introduces a new feature for `git rev-parse` that allows computing object names in a different hash algorithm on demand, addressing a key gap in Git's object-format interoperability. The patch, authored by Dimitri John Ledkov, enables referencing objects across repositories using different hash algorithms (e.g., SHA-1 and SHA-256) without requiring a full repository conversion.

The implementation adds a `compute_oid_to_algop()` function that recursively converts object contents (trees, tags, blobs) to the target algorithm, caching results in-memory to avoid redundant work. Commits and trees containing submodules are explicitly rejected to avoid unbounded history traversal or external repository dependencies. The patch touches core files like `object-file-convert.c` and `repository.h`, and includes a new test script (`t/t1018-output-object-format.sh`) to verify edge cases and correctness.

Performance is practical, with the Linux kernel tree (1.6 GiB) taking about 8 seconds to compute its SHA-256 name. The patch avoids controversial design choices, such as persistent caching or commit conversion, and focuses on a narrow, well-motivated use case. So far, the thread consists of the initial patch submission, which appears technically sound, with clear documentation and thorough test coverage. No reviews or objections have been posted yet, so the discussion is still in its early stages.
