This is a documentation patch updating the short help message for the `-l` option in `git diff`. It is the second iteration of a standalone patch by Elijah Newren, addressing feedback from Junio C Hamano on the initial version.

The patch corrects a misleading one-line description of the `-l` option (which sets the `rename_limit` for diff operations). The previous text, "prevent rename/copy detection if the number of rename/copy targets exceeds given limit," incorrectly implied that the option disabled all rename detection. In reality, it only affects the *exhaustive* (quadratic-time) portion of rename detection, while *cheap* (linear-time) methods—exact and basename-guided rename detection—still run regardless of the limit. This distinction was already clarified in the full documentation in a 2021 commit (6623a528e00b), but the short help message was overlooked at the time.

The new wording, "limit to cheap rename/copy detection if the number of rename/copy targets exceeds this value," avoids technical jargon like "exhaustive" and aligns with terminology used elsewhere in the documentation. It directly references "cheap" rename detection, which encompasses both exact and basename-guided methods. The change is minimal—one line in `diff.c`—and does not alter any code behavior or require test updates.
