This thread is an RFC by Peter Morris proposing that `git worktree add` use filesystem-level copy-on-write (CoW) or block cloning to avoid physically duplicating files until they are modified. The goal is to reduce storage overhead and improve performance when creating multiple worktrees, particularly for use cases like concurrent AI coding agents. The proposal is conceptual, with no implementation yet, and seeks feedback on whether Git’s architecture can support a platform-agnostic abstraction for this optimization and whether it aligns with the project’s roadmap.

So far, the discussion has been light. The only substantive follow-up is from Kristoffer Haugsbakk, who points to a 2024 patch series (`git clone --block-clone`) that introduced similar filesystem-level cloning for `git clone`. This suggests the technical groundwork for such optimizations already exists in Git, though the RFC’s feasibility and design questions—such as how it would interact with existing worktree features, handle edge cases like hardlinks or symlinks, or ensure cross-platform consistency—remain unaddressed. No maintainers or domain experts have weighed in yet, so the thread is still in the early stages of gathering feedback.
