This is the first patch in the v2 series converting `USE_NSEC` to runtime configuration. It fixes a long-standing discrepancy in the Meson build system: the `man.base.url.for.relative.links` default now matches the Makefile’s behavior (`file://$(htmldir)/` with a trailing slash) instead of hard-coding `$prefix/$mandir`, which produces broken links in the generated man pages. The patch also adds a configurable `man_base_url` option to `meson_options.txt`, giving downstream packagers (e.g., Gentoo) the same flexibility they have with the Makefile.

The change is uncontroversial and confirmed correct by Patrick Steinhardt in the thread. It touches only `Documentation/meson.build` and `meson_options.txt`, making it a self-contained build-system improvement with no impact on runtime behavior. The commit message provides clear rationale and a grep-based audit showing that all current `link:<relative>` uses point to HTML documentation, justifying the new default. This patch is ready to advance independently of the rest of the series.
