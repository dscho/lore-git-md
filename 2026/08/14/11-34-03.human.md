This is a minor follow-up in the ongoing RFC thread about adding filesystem-level copy-on-write (CoW) or block cloning optimizations to `git worktree add`. The email is a brief correction from Kristoffer Haugsbakk, a documentation contributor, pointing out that the prior art cited in the thread—the 2024 `git clone --block-clone` feature—was incorrectly described as Linux- and macOS-only. In fact, the feature also supports ReFS on Windows, where the Windows `CopyFile` API automatically uses block cloning when the source and destination are on the same ReFS volume. This means the proposed `git worktree` optimization could potentially work "for free" on Windows Dev Drives if Git were to use `CopyFile` instead of manual file copying.

The observation is narrowly technical and does not engage with the broader feasibility or design questions raised in the RFC. It serves primarily as a factual correction to ensure the discussion accounts for Windows support in the existing block-cloning infrastructure. Readers following the thread may want to revisit the 2024 `git clone --block-clone` series to confirm how Git currently handles platform-specific cloning, as this could inform the proposed `git worktree` optimization. The thread remains conceptual, with no implementation or patch yet proposed.
