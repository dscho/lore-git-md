This is the third patch in Elijah Newren’s v3 four-patch series fixing a race condition in Git’s geometric repacking mechanism. It removes the `OBJECT_INFO_QUICK` flag from `git mktree --batch`’s object-type checks, ensuring that a resident `mktree` process can recover objects relocated by a concurrent repack.

The patch targets `builtin/mktree.c`, where `mktree_line()` uses `odb_read_object_info_extended()` to verify object types. The `QUICK` flag, added in 2022 to avoid lazily fetching promisor objects, inadvertently disabled the reprepare-and-retry logic that reloads the on-disk pack set. As a result, a long-running `git mktree --batch` process would fail to find objects moved into a new pack by a concurrent repack, rejecting valid tree entries. The fix replaces `QUICK` with `OBJECT_INFO_SKIP_FETCH_OBJECT`, preserving the promisor-object avoidance while allowing the reprepare-and-retry mechanism to recover relocated objects.

The regression test in `t/t1010-mktree.sh` simulates the race: it starts a resident `git mktree --batch` process, feeds it a tree referencing a blob in a pack, then mimics a concurrent repack by removing the pack’s `.idx` file and creating a replacement pack. Without the fix, the `mktree` process fails to resolve the blob; with the fix, it recovers the blob from the replacement pack. The test verifies both the recovery and the absence of error messages.

This patch is a targeted fix for a real-world issue, motivated by production crashes in server-side operations. It is uncontroversial, well-tested, and aligns with the series’ goal of making object lookups resilient to concurrent repacking. The removal of `QUICK` is minimal and does not affect other callers. The test coverage is thorough, simulating the exact race condition and verifying the recovery behavior. No follow-up work is needed beyond the minor error-message tweak suggested by Peff in the cover letter.
