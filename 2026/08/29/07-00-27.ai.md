This is the v3 cover letter for a four-patch bugfix series addressing a race condition in Git's geometric repacking mechanism that causes objects to be incorrectly reported as missing. The series is now merge-ready and has been refined based on substantive feedback from Jeff King (Peff) and Junio C Hamano.

The core issue is a race where a multi-pack-index (MIDX) references a packfile removed by geometric repacking, leaving processes using the stale MIDX unable to locate objects. This manifests as crashes in `git replay` and missing-object errors in other operations (`git merge-tree`, `git diff`, `git rev-list`, etc.). The series fixes the `git replay` crash (patch 1/4), plugs a leak in `git mktree --batch` (patch 2/4), removes the problematic `OBJECT_INFO_QUICK` flag from `git mktree --batch` (patch 3/4), and implements a recovery mechanism in the packed-object backend when a MIDX references a removed pack (patch 4/4).

Key changes since v2 include dropping the controversial patch 3/4 (which attempted to handle `QUICK` readers) and replacing it with a targeted fix for `git mktree --batch` that removes the `OBJECT_INFO_QUICK` flag. The MIDX recovery logic in patch 4/4 now uses a tri-state return value (`MIDX_FILL_MISS`, `MIDX_FILL_HIT`, `MIDX_FILL_OWNER_UNAVAILABLE`) and gates the fallback on `SECOND_READ` to optimize performance for `QUICK` callers. The function `fill_midx_entry()` has been renamed to `midx_fill_entry()` to reflect its new semantics, and the `stale_packs_detected` flag is no longer needed. The series is rebased on `ps/odb-generic-corrupt-objects` and includes thorough test coverage for all scenarios.

The series is well-motivated by production evidence and addresses a real problem affecting multiple server-side operations. The patches are small, focused, and include clear commit messages and tests. The recovery mechanism is targeted and avoids unnecessary rescans, making it a high-quality fix that should be uncontroversial. The only remaining loose ends are minor: the function name may be tweaked further, and Peff suggested improving the error message clarity, but neither is a blocker. Derrick Stolee's suggestion to defer pack deletion via `git multi-pack-index expire` remains a complementary follow-up.
