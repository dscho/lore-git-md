This is the v5 cover letter for the `dk/use-nsec-runtime` series, which is now marked as applied under its topic name. The series converts the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision on supported filesystems without recompiling Git.

The v5 update is minimal: it improves the commit message flow in the second patch (the no-op refactor of `repo_config_values_init`) to incorporate Junio C Hamano’s suggested wording tweak ("definition of 'struct repo_config_values'" instead of "struct definition"). This addresses the last polish request from the v4 review cycle. The core technical changes—introducing `core.useNanosec`, caching its value in `repo_config_values`, and unconditionally including the `use_nanosec` field while treating it as false on `NO_NSEC` platforms—remain unchanged from v4. The series is now effectively complete and ready for graduation to `master`.

The three patches are uncontroversial and self-contained: the first fixes a Meson build-system issue (`MAN_BASE_URL` configuration), the second reorders assignments in `repo_config_values_init` for clarity, and the third introduces `core.useNanosec` and removes `USE_NSEC`. The conflict with `ty/repo-config-cleanups` (which removes comments in `struct repo_config_values`) is still present but trivial to resolve. Performance benchmarks confirm the v2 fix for the v1 regression (~41× slowdown in `git diff`) is effective, with v5 restoring baseline performance (21 ms vs 20 ms).

The series touches 12 files, including `Documentation/config/core.adoc`, `environment.c`, `read-cache.c`, and `statinfo.c`. The documentation now includes a direct warning about platform/filesystem limitations, and the `core.useNanosec` config key defaults to false. The only remaining loose ends are platform-dependent test coverage (still unaddressed) and the potential naming issue (`core.useNanosec` might be too specific if future platforms offer extended precision beyond nanoseconds), but neither is blocking. Junio and Patrick Steinhardt have both endorsed the v4 changes, and the author has aligned with the project’s preference to omit runtime warnings for `NO_NSEC` builds.
