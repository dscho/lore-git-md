This is a substantive review reply in the `die_for_incompatible_opts()` refactoring thread, offering concrete technical proposals to address the compile-time safety concerns raised by Jeff King (Peff). René Scharfe engages directly with the trade-off between varargs flexibility and type safety, proposing two alternative approaches to enforce argument correctness at compile time while preserving the ability to handle more than four options.

The first proposal suggests combining `EOF` and `NULL` sentinels, using a macro to guarantee termination by construction. This approach retains the varargs interface but ensures the internal function is never called directly, mitigating the risk of unterminated argument lists. The second proposal introduces a type-safe variant using a compound literal (`struct used_option`) to enforce the correct argument pattern at compile time. This version is more verbose but eliminates the risk of mismatched argument types entirely, even for error-handling code that may be less frequently tested.

René’s suggestions are framed as technical explorations rather than objections to the current design. Neither proposal requires changes to existing call sites, and both preserve the series’ goal of replacing the fixed-arity `die_for_incompatible_optN()` family with a single varargs helper. The discussion remains focused on internal API safety, with no impact on user-visible behavior or i18n compatibility.
