This is the final patch in a well-reviewed, merge-ready bugfix series that fixes a race condition in Git's geometric repacking mechanism. The race occurs when a multi-pack-index (MIDX) references a packfile that has been removed by a concurrent repack, causing processes using the stale MIDX to fail to locate objects—leading to crashes in `git replay` and missing-object errors in other operations like `git merge-tree`, `git diff`, and `git rev-list`.

The patch implements a targeted recovery mechanism in the packed-object backend. The core change is in `find_pack_entry()`, which now handles a tri-state return from `midx_fill_entry()` (renamed from `fill_midx_entry()`): `MIDX_FILL_MISS` (object not in MIDX), `MIDX_FILL_HIT` (object found), and `MIDX_FILL_OWNER_UNAVAILABLE` (object is in the MIDX but its owning pack is missing). When the latter occurs and the caller is performing a second read (`OBJECT_INFO_SECOND_READ`), the code scans all packs covered by the MIDX to find a surviving copy of the object. This ensures that objects relocated by repacking are still accessible, even when the MIDX is stale. The recovery is gated on `SECOND_READ` to avoid unnecessary rescans for `QUICK` callers, which are designed to tolerate false negatives.

The patch touches `odb/source-packed.c` (the recovery logic), `midx.c`/`midx.h` (the tri-state return and function rename), `builtin/pack-objects.c` (updated caller), and adds a test in `t/t5319-multi-pack-index.sh` that simulates the race by removing a packfile while a MIDX still references it, verifying that `git cat-file` can still read the object. The test coverage is thorough and aligns with the series' goal of addressing production-reported issues.

This is a high-quality fix with clear motivation, minimal performance impact, and no on-disk format changes. All prior feedback has been addressed, including adopting Jeff King's tri-state design and gating the recovery on `SECOND_READ`. The only remaining loose end is a minor suggestion to improve error message clarity, but this is not a blocker. The patch is part of a four-patch series that also fixes a leak in `git mktree --batch` and removes the problematic `OBJECT_INFO_QUICK` flag from that command. The series is rebased on `ps/odb-generic-corrupt-objects` and is ready for integration.
