This is the first patch in a four-patch bugfix series addressing a race condition in Git's geometric repacking mechanism. The patch fixes a crash in `git replay` when merge inputs are unreadable, replacing a SIGSEGV with a graceful error message.

The issue occurs when the merge machinery fails to read an object (e.g., due to a race with geometric repacking), setting `result.clean` to a negative value while leaving `result.tree` as NULL. The existing code in `pick_regular_commit()` only checked `if (!result->clean)`, missing the negative case and causing a null-pointer dereference. The fix adds an explicit check for `result->clean < 0`, returning an error message without attempting to use the NULL tree.

The patch includes a new test in `t/t3650-replay-basics.sh` that simulates the scenario by removing the tree object for the `--onto` commit, verifying that `git replay` fails gracefully with appropriate error messages rather than crashing. The test covers both the success case (with all objects readable) and the failure case (with a missing object).

This is a targeted bugfix with clear motivation and thorough test coverage. The change is small and focused, touching only `replay.c` and the test file. The commit message explains the problem and solution clearly, and the test demonstrates the fix effectively. The patch addresses a real issue affecting server-side operations and is part of a well-reviewed series that is now merge-ready. No unresolved technical concerns remain for this patch.
