This is the v3 cover letter for a **bugfix series** addressing a race condition in Git's geometric repacking mechanism that causes objects to be incorrectly reported as missing, even when they exist in other packs. The issue primarily affects server-side operations like `git replay`, which previously crashed with a SIGSEGV when encountering missing objects. The series is now **merge-ready** after addressing all substantive feedback from prior rounds.

The core problem occurs when a multi-pack-index (MIDX) references a packfile that is later removed by geometric repacking. Processes using the stale MIDX fail to locate objects because the MIDX lookup routes to the missing pack, and the fallback code skips all MIDX-covered packs. The fix introduces a tri-state return value (`MIDX_FILL_HIT`, `MIDX_FILL_MISS`, `MIDX_FILL_OWNER_UNAVAILABLE`) in `midx_fill_entry()` (renamed from `fill_midx_entry()`) to distinguish between missing objects and those whose owning pack is unavailable. When the latter occurs, the code now rescans the MIDX's packs to find a surviving copy, but only during the second read (`OBJECT_INFO_SECOND_READ`) to avoid performance penalties for `QUICK` callers.

Key changes since v2 include:
- **Dropped the controversial patch 3/4** (which attempted to fix `QUICK` readers) and replaced it with a targeted fix for `git mktree --batch`, removing its erroneous use of `OBJECT_INFO_QUICK`.
- **Fixed a leak in `git mktree --batch`** (patch 2/4), which was exposed by new test cases.
- **Renamed `fill_midx_entry()` to `midx_fill_entry()`** to force callers to handle the new tri-state return value.
- **Removed an unnecessary comment rewrite** and the `stale_packs_detected` flag, simplifying the logic.

The series touches `replay.c`, `odb/source-packed.c`, `midx.c`, `builtin/mktree.c`, and test files, with thorough test coverage for the crash scenario, MIDX recovery logic, and the `mktree` leak. The fix is well-motivated by production evidence and addresses a rare but critical race condition affecting multiple commands. The patches are small, focused, and have addressed all substantive feedback, making this a high-priority candidate for merging. The only remaining loose ends are cosmetic (e.g., error message clarity) and follow-up work (e.g., adding test coverage for `git mktree --batch`).
