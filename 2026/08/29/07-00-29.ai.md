This is the second patch in Elijah Newren’s v3 four-patch series fixing a geometric-repacking race condition. It plugs a memory leak in `git mktree --batch` that was discovered while writing tests for the larger bugfix.

The leak occurs because `git mktree --batch` reuses a single `entries` buffer across multiple trees, resetting the `used` counter to zero after each tree but never freeing the `treeent` structures from the previous tree. The patch adds a loop to free each entry before resetting `used`, and frees the buffer itself before returning. The fix is minimal (three lines), well-scoped, and directly addresses the issue Jeff King (Peff) identified in his review of the original v2 series. No new tests are added here; the leak was exposed by the test infrastructure introduced in patch 1/4.
