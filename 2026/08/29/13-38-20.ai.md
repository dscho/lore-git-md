This is the third and final patch in the `dk/use-nsec-runtime` series (v5), which converts the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The patch is well-crafted, uncontroversial, and ready to advance to `master`.

The patch removes all remaining `USE_NSEC` preprocessor directives, replacing them with a runtime check of the `core.useNanosec` config key (cached in `repo_config_values`). The `is_racy_stat()` function is simplified from nested `#ifdef` guards to a single ternary expression, improving readability. The `use_nanosec` field is unconditionally included in `struct repo_config_values` but treated as false when `NO_NSEC` is defined, ensuring backward compatibility and eliminating uninitialized reads. Documentation in `Documentation/config/core.adoc` and `Documentation/technical/racy-git.adoc` is updated to reflect the change, including a direct warning about platform/filesystem limitations and a list of known-working filesystems (ext2, ext4, XFS, CEPH, CIFS, NTFS, UFS, FUSE, FAT).

The patch touches 10 files, including `Makefile`, `configure.ac`, `environment.c`, and `read-cache.c`. The `core.useNanosec` config key defaults to false, preserving existing behavior. The commit message notes that `--ignore-space-change` may be helpful when viewing the diff due to the conversion from `#ifdef` to runtime checks. Benchmark results from earlier in the series confirm the performance regression introduced in v1 (~41× slowdown in `git diff`) is fully resolved by caching the config value in `repo_config_values`. The only remaining loose end is platform-dependent test coverage, but this is not blocking. Junio C Hamano and Patrick Steinhardt have both endorsed the design and implementation, and the series is now applied under its topic name. A trivial textual conflict exists with `ty/repo-config-cleanups` in `seen` (removes comments in `struct repo_config_values`), but this is easily resolved.
