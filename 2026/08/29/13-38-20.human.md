This is the third and final patch in the `dk/use-nsec-runtime` series, which converts the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The patch is well-crafted, uncontroversial, and ready to graduate to `master`.

The change allows users to enable nanosecond precision for file timestamps at runtime, mitigating "racy Git" problems in commands like `git diff` without requiring a recompile. The patch removes all `USE_NSEC` preprocessor directives, replacing them with a runtime check of the new `core.useNanosec` config key (defaulting to false). The `use_nanosec` field is unconditionally included in `struct repo_config_values` but treated as false on platforms where `NO_NSEC` is defined, ensuring backward compatibility and eliminating uninitialized reads. The nested `#ifndef NO_NSEC` guards in `is_racy_stat()` are simplified to a single ternary expression for clarity.

Documentation updates include a new entry for `core.useNanosec` in `Documentation/config/core.adoc` and revisions to `Documentation/technical/racy-git.adoc` to reflect the runtime nature of the setting. The documentation now lists filesystems known to support nanosecond precision (ext2, ext4, XFS, CEPH, CIFS, NTFS, UFS, FUSE, FAT) and includes a direct warning about platform limitations. The commit message notes that `--ignore-space-change` may be helpful when viewing the diff due to the conversion from preprocessor directives to runtime logic.

Performance benchmarks confirm the fix for the v1 regression (~41× slowdown in `git diff`) is effective, with v5 restoring baseline performance. The patch touches 10 files, including `Makefile`, `configure.ac`, `environment.c`, and `read-cache.c`. The only remaining loose ends are platform-dependent test coverage (still unaddressed) and a potential naming issue (`core.useNanosec` might be too specific if future platforms offer extended precision), but neither is blocking. Junio C Hamano and Patrick Steinhardt have both endorsed the changes, and the series is now applied under its topic name.
