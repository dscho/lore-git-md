This is the eighth patch in Junio C Hamano’s 8-patch series refactoring the internals of `git checkout`, `git switch`, and `git restore`. The patch moves the `post_checkout_hook()` function from `builtin/checkout.c` to the new top-level `checkout.c` file, making it available to other subsystems like `git worktree` without requiring a dependency on built-in command code. However, the email is not the original patch submission—it is Junio’s self-review and follow-up fix.

The key change here is the removal of the function’s dependency on the global `the_repository` and `the_hash_algo`. The updated version now accepts a `struct repository *` parameter and uses the repository’s associated hash algorithm, aligning with the broader `the_repository` removal effort and ensuring the helper can be called from any repository context. This is a small but critical improvement: it transforms the patch from a simple code relocation into a proper libification step that fully supports multi-repository callers. The fix is mechanical and uncontroversial, addressing the architectural shortcoming Junio identified in his initial review of the patch.

The patch touches `builtin/checkout.c`, `checkout.c`, and `checkout.h`, updating function signatures and call sites to pass the repository parameter. The changes are minimal (about 30 lines) and do not alter CLI behavior or on-disk formats. The updated `post_checkout_hook()` now serves as a template for future libification efforts, demonstrating how to extract reusable logic while maintaining compatibility with non-global callers.
