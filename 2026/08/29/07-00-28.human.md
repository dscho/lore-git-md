This is the first patch in Elijah Newren’s v3 series fixing a race condition in Git’s geometric repacking that causes crashes in `git replay`. The patch itself is a targeted bugfix for a SIGSEGV that occurs when `git replay` encounters unreadable objects during a merge.

The issue is straightforward: when the merge machinery fails to read an object (e.g., due to a missing packfile), it sets `result.clean` to a negative value and leaves `result.tree` as `NULL`. The existing code in `pick_regular_commit()` only checked `if (!result->clean)`, missing the case where `clean < 0`. This causes a null-pointer dereference when the code later tries to use `result->tree`. The fix adds an explicit check for `clean < 0` and returns early with an error message, avoiding the crash.

The patch includes a new test in `t/t3650-replay-basics.sh` that simulates the scenario by removing the tree object for the `--onto` commit, verifying that `git replay` fails gracefully with an appropriate error message rather than segfaulting. The test is well-structured and covers the core issue without overcomplicating the setup.

This is a clear, well-motivated bugfix with minimal risk. The commit message explains the problem and solution concisely, and the test ensures the fix works as intended. The patch is part of a larger series addressing a race condition in geometric repacking, but it stands alone as a necessary fix for a crash that can occur independently of the repacking issue. If you care about server-side stability or use `git replay`, this patch is worth your attention.
