This is a bugfix patch targeting submodule configuration parsing. It addresses a case where Git currently crashes if the `submodule.active` configuration key is set without a value (e.g., `[submodule] active` with no pathspec). The patch replaces `repo_config_get_string_multi()` with `repo_config_get_value_multi()` to safely handle valueless entries and emits a warning via `config_error_nonbool()` instead of failing hard. The change preserves existing caller semantics—malformed entries are skipped after warning, while valid entries continue to be processed.

The patch resolves a documented `NEEDSWORK` comment in `submodule.c` and includes a new test in `t/t7400-submodule-basic.sh` that verifies the warning is emitted when `submodule.active` is valueless. The test sets up a minimal repository, adds a submodule, and injects a malformed config entry to check for the expected warning message.

The author explains in the cover note why returning an error code wasn’t feasible: `is_tree_submodule_active()` is used as a boolean predicate by callers, and returning `-1` would be treated as truthy in C, potentially causing broken submodules to be incorrectly considered active. The chosen approach avoids changing caller behavior or introducing process termination from the helper.

This is the fourth iteration of the patch. Changes from v3 include fixing the commit message tense (present instead of past) and terminology ("valueless true"), as well as correcting whitespace in the test script. The patch touches the submodule subsystem and config parsing logic, with no broader architectural implications. The fix is narrowly scoped and appears well-motivated.
