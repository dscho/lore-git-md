This thread is about a bugfix patch that prevents Git from crashing when the `submodule.active` configuration key is set without a value (e.g., `[submodule] active` with no pathspec). The issue was reported and fixed by Tilak Raaz, now in its fourth iteration (`v4`).

The fix replaces `repo_config_get_string_multi()` with `repo_config_get_value_multi()` in `submodule.c` to safely handle valueless entries, emitting a warning instead of crashing. The change preserves existing behavior for valid entries while skipping malformed ones after warning. A new test in `t/t7400-submodule-basic.sh` verifies the warning is emitted for valueless `submodule.active` entries. The author explains why returning an error code wasn’t feasible: `is_tree_submodule_active()` is used as a boolean predicate, and returning `-1` could incorrectly treat broken submodules as active.

The patch addresses a `NEEDSWORK` comment in the codebase and is narrowly scoped to submodule configuration parsing, with no broader architectural implications. Changes from `v3` were minor, focusing on commit message clarity and test script whitespace. The fix appears well-motivated and ready for review.
