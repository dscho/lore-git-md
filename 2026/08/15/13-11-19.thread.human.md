This thread is about a bugfix for `git worktree repair` that corrects how Git handles path resolution in `.git` files when the `worktree.useRelativePaths` configuration is toggled. The issue, introduced in Git v2.48.0, stems from `read_gitfile_gently()` always returning absolute paths, which obscures the original path style (relative or absolute) and prevents the repair logic from detecting mismatches when the configuration changes. Yoichi NAKAYAMA initially proposed a fix (v1) but revised it after Junio C Hamano raised concerns about API stability.

The v2 patch, now posted, takes a cleaner approach: it introduces a new function, `read_gitfile_raw()`, which returns the path verbatim from the `.git` file, while preserving the existing `read_gitfile_gently()` API. This allows the repair logic to detect and fix mismatches symmetrically when switching between relative and absolute paths. The patch touches `setup.c`, `setup.h`, and `worktree.c`, and includes expanded test coverage in `t/t2406-worktree-repair.sh` to verify the fix works in both directions. Junio’s earlier objections have been addressed, and the design is now settled. The patch is under review but appears uncontroversial, with no outstanding technical concerns. If accepted, it will resolve a subtle but real-world issue for users who toggle `worktree.useRelativePaths`.
