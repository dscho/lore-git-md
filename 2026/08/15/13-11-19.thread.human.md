This thread is about a bugfix patch (v3) from Yoichi NAKAYAMA that addresses a symmetry issue in Git’s worktree repair functionality. The bug occurs when `worktree.useRelativePaths` is toggled from `true` to `false`, causing Git to fail to detect mismatches in `.git` file paths because `read_gitfile_gently()` always returns absolute paths, obscuring the original path style. The patch introduces `read_gitfile_raw()` to return paths verbatim, enabling the repair logic to detect and correct these mismatches.

The patch has evolved through feedback, with Junio C Hamano initially raising concerns about the API design. Those concerns have now been partially resolved: Junio accepts the split between `read_gitfile_raw()` (which returns the verbatim path) and `read_gitfile_gently()` (which handles normalization and repository validation) in `setup.c`. However, the worktree repair logic in `worktree.c` still calls `read_gitfile_raw()` directly without explicitly re-adding path resolution or repository validation checks. Junio has not yet weighed in on whether this omission is acceptable, leaving one key technical detail unresolved. The patch is otherwise ready for integration, and the author will likely need to address this remaining point in a follow-up. Testing has been expanded to cover transitions between absolute and relative paths in both main and side worktrees.
