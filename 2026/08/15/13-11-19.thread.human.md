This thread is about a bugfix patch from Yoichi NAKAYAMA that aims to improve how Git handles path resolution in `.git` files during worktree repair. The patch modifies `read_gitfile_gently()` to optionally report whether the path in the `.git` file was originally absolute or relative, addressing what the author describes as dead code in the worktree repair logic.

Junio C Hamano has raised substantive concerns about the patch’s design and motivation. He argues that the commit message is too vague—it doesn’t clearly explain *why* the worktree repair logic needs to distinguish between absolute and relative paths, nor does it identify the specific dead code branches or broken conversion logic. Junio suggests the patch might be solving a non-problem or doing so in an overly invasive way by changing the API of `read_gitfile_gently()`. He proposes two alternative approaches: either using a different helper function to retrieve the path in its original form or introducing a new non-fatal error code to handle relative paths without modifying the existing API. The discussion is now awaiting the author’s response to justify the current approach or revise the patch. No other reviews have been posted yet.
