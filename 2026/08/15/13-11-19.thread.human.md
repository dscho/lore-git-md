This thread is about a bugfix for Git’s worktree repair functionality, specifically how it handles path resolution in `.git` files. The issue was first raised by Yoichi NAKAYAMA, who identified that the current code contains dead branches because `read_gitfile_gently()` always returns an absolute path, making it impossible to detect mismatches between the configured path style (absolute or relative) and the actual `.git` file contents. Junio C Hamano initially challenged the patch’s design, questioning whether the problem was real or well-motivated and suggesting alternative approaches.

The discussion has now clarified the real-world problem: when `worktree.useRelativePaths` is toggled, `git worktree repair` should symmetrically convert paths in `.git` files and `worktree/id/gitdir` entries, but the current implementation fails to detect mismatches when switching from relative to absolute paths. This asymmetry has existed since the feature’s introduction in October 2024 and is reproducible in Git v2.48.0. Yoichi has agreed to revise the patch to adopt Junio’s cleaner design—introducing a new function (`read_raw_gitfile()`) that returns the path verbatim—rather than modifying the existing `read_gitfile_gently()` API. The thread is now focused on finalizing this approach, with no other objections or reviews surfacing yet. The next step is a v2 patch implementing the new function.
