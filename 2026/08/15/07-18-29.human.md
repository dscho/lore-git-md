This is a bugfix patch for the submodule subsystem, specifically addressing how Git handles malformed `submodule.active` configuration entries.

The patch fixes a crash that occurs when `submodule.active` is set without a value (e.g., `[submodule] active` with no pathspec). Previously, Git would throw a hard error and abort commands, but now it emits a warning using the standard `config_error_nonbool()` helper and continues processing valid entries. The change replaces `repo_config_get_string_multi()` with `repo_config_get_value_multi()` to safely parse valueless configurations.

The commit message explains the reasoning behind not propagating an error code: `is_tree_submodule_active()` is used as a boolean predicate by callers, and returning `-1` would incorrectly treat malformed entries as "active." The solution skips invalid entries after warning the user, preserving existing caller semantics.

The patch includes a new test in `t/t7400-submodule-basic.sh` that verifies the warning is emitted when `submodule.active` lacks a value. This is the fourth iteration of the patch, with improvements to the commit message (present tense, terminology) and test script formatting based on Junio's feedback. The NEEDSWORK comment in the code is also resolved.
