Originating author: tilak-raaz

Core problem or goal
Git crashes when parsing a valueless `submodule.active` configuration entry (e.g., `[submodule] active` with no pathspec). The patch replaces `repo_config_get_string_multi()` with `repo_config_get_value_multi()` to safely handle such entries, emits a warning via `config_error_nonbool()`, and preserves existing caller semantics—malformed entries are skipped after warning, while valid entries continue to be processed.

Current status
Under review; v4 posted. Junio C Hamano has raised substantive objections to the warning-and-continue approach, arguing that the existing hard error is preferable for user visibility. The NEEDSWORK comment in `submodule.c` is now contested: it suggested a warning, but Junio questions whether that is the correct fix. No merge status change; still under review.

Key technical details

Test coverage: new test in `t/t7400-submodule-basic.sh` verifies the warning is emitted for valueless `submodule.active`.
