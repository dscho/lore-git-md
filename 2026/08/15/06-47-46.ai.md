This is a refactoring patch (v6) continuing the `the_repository` removal effort. It moves the global `fetch_if_missing` variable into `struct repository`, making it a per-repository flag that controls whether missing objects trigger lazy fetches from promisor remotes. The patch is now mechanically complete and addresses all feedback from v5, including Junio’s suggestion to use the `value` field in `OPT_CALLBACK_F()` to pass the repository address directly to `option_parse_missing_action()`, eliminating the intermediate variable and deferred side effect.

The patch touches 15 files, including `builtin/fetch-pack.c`, `builtin/fsck.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `builtin/rev-list.c`, `common-init.c`, `git.c`, and the partial clone documentation. It preserves existing behavior: the default value remains `1` (enabled), and initialization occurs in `initialize_repository()`. Special handling in `fsck.c` and `index-pack.c` (deferring operations until after parameter parsing) and the ternary fallback in `index-pack.c` (`(repo ? repo : the_repository)->fetch_if_missing`) remain unchanged. The preparatory patch from v5 (propagating the `repo` parameter in `pack-objects.c`) is now unnecessary due to the callback adjustment.

The series is now technically complete for its immediate goal—eliminating all direct uses of `the_repository` for `fetch_if_missing`—and is ready for maintainer decision. The broader architectural question of whether `fetch_if_missing` belongs in `struct repository` (or should instead use a global "basic settings" structure for repository-less invocations) remains unresolved, but the author has deferred that discussion until subsystems are fully prepared to handle `repo` instead of `the_repository`. No new test coverage is introduced, but the changes are expected to preserve existing behavior. The patch is well-scoped, addresses feedback directly, and coordinates with other topics to avoid conflicts.
