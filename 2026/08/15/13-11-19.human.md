This is a bugfix patch for `git worktree repair`, targeting a subtle but real issue in how Git handles relative versus absolute paths in `.git` files.

The patch corrects a long-standing flaw in `read_gitfile_gently()`: the function always returns an absolute path, so the code that tried to detect whether the original `.git` file contained a relative path was effectively dead. The fix adds a new `bool *absolute` output parameter to the function, allowing callers to learn whether the path in the `.git` file was absolute or relative. The patch then updates the worktree-repair logic to use this information, ensuring that the `--relative-paths` option and the `worktree.useRelativePaths` config setting are respected when repairing a worktree whose `.git` file path format does not match the expected convention.

The commit message is clear and the code changes are minimal and focused. The test suite is expanded significantly, covering both the new detection logic and the four possible repair scenarios (absolute→relative and relative→absolute, each in both the main and side worktrees). The patch looks well-crafted and addresses a real edge case that could confuse users who mix relative and absolute paths in their worktree setups.
