This is a bugfix patch targeting submodule configuration parsing. It addresses a case where Git previously crashed with a hard error if the `submodule.active` configuration key was set without a value (e.g., `[submodule] active` with no pathspec). The patch replaces the strict `repo_config_get_string_multi()` call with `repo_config_get_value_multi()`, which safely handles valueless keys, and emits a warning via `config_error_nonbool()` instead of failing.

The change is motivated by a `NEEDSWORK` comment in `submodule.c` and preserves existing caller semantics: `is_tree_submodule_active()` remains a boolean predicate, so malformed entries are skipped after warning rather than causing the command to abort. The patch includes a new test in `t/t7400-submodule-basic.sh` to verify the warning behavior.

Key technical details: the patch touches `submodule.c` (the core logic) and `t7400-submodule-basic.sh` (test coverage), modifies how `submodule.active` is parsed, and introduces no new configuration keys or user-facing options. The author explicitly considered error propagation but opted to maintain backward compatibility with callers expecting a boolean result. This is the third iteration of the patch, with improvements to commit message tense and terminology.
