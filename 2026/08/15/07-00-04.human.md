This is a bugfix patch for submodule configuration handling. The patch addresses a case where Git would previously crash with a hard error if the `submodule.active` configuration key was set without a value (e.g., `[submodule] active` with no pathspec). Instead of failing, the patch now emits a warning using the standard `config_error_nonbool()` helper and skips the malformed entry, allowing the command to continue processing valid entries.

The change is small but well-motivated: it resolves a `NEEDSWORK` comment in `submodule.c` and adds a test case in `t/t7400-submodule-basic.sh` to verify the new behavior. The author explains the reasoning for not returning an error code (to avoid breaking existing caller semantics) and incorporates feedback from Junio on commit message wording and tense. The patch looks clean, with no obvious red flags in the implementation or test coverage.

This is a sensible quality-of-life improvement for users who accidentally misconfigure `submodule.active`, and the fix aligns with Git’s general approach to non-fatal config errors. Worth a quick look if you work with submodules, but unlikely to be controversial.
