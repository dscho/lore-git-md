This is a **substantive review** in the ongoing discussion about the `git pack-objects` Trace2 instrumentation patch. Jeff King (Peff) responds to Patrick Steinhardt’s concern about hash size consistency in the byte-counting logic.

Peff clarifies that the current implementation is functionally correct because the hashfile is always created using `the_repository->hash_algo`, so `f->algop->rawsz` and `the_repository->hash_algo->rawsz` will always agree on the hash size. However, he acknowledges Patrick’s point about stylistic consistency and proposes a small refactor to make all three conditional blocks in `write_pack_file()` use the hashfile’s algorithm (`f->algop`) instead of mixing it with `the_hash_algo`. His suggested diff shows how to do this by passing `f->algop` to `fixup_pack_header_footer()`.

Peff also digresses into a broader observation about Git’s paranoid triple-hashing of packfiles (once during write, once during fixup, and once during verification), questioning whether the performance cost is justified. He treats this as a separate discussion, though, and concludes that either spelling (`f->algop->rawsz` or `the_repository->hash_algo->rawsz`) is acceptable for the current patch.

The thread remains focused on implementation details rather than the patch’s core goal. The author will likely incorporate Peff’s refactor into v3 to harmonize the code paths, but no fundamental objections or design changes are on the table. The patch is still on track for integration once the hash-size consistency point is resolved.
