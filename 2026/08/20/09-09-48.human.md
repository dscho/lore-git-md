This is the first patch in Patrick Steinhardt’s five-part series removing lazy-loading of alternate object databases. The patch reorders repository initialization so that the reference and object databases are created *after* the repository’s configuration — including `core.sharedRepository` and `core.ignoreCase` — has been written to disk. This is a correctness fix: without it, a later patch in the series would read an uninitialized or incorrect `core.ignoreCase` value during object database creation, potentially causing subtle bugs in case-insensitive path comparisons.

Karthik Nayak’s reply is a surface-level review. He confirms the patch’s motivation — ensuring `core.sharedRepository` is set before the object database is created — but does not engage with the technical details or edge cases. His feedback is limited to restating the patch’s purpose and does not identify any issues or suggest improvements. This aligns with his earlier reviews of the series, which have been similarly brief and focused on mechanical correctness rather than substantive design concerns.

The patch itself is small (12 lines changed) and touches only `setup.c`. It is purely preparatory, with no user-visible behavior changes, and is a critical enabler for the rest of the series. The change looks well-motivated and low-risk, as it only reorders initialization steps without altering logic. However, the broader series is now blocked by a separate issue: Jeff King (Peff) has pointed out that `repo_ignore_case()` cannot be used in submodule contexts because it relies on `repo_config_values()`, which is hardcoded to `the_repository`. This constraint was not addressed in this patch or Karthik’s review, and no alternative solutions have been proposed yet.

If you are following the ODB refactoring effort, this patch is worth noting as a necessary step, but the unresolved `repo_config_values()` limitation may delay the series’ integration. For most readers, this is a minor detail in a larger cleanup; the patch itself is uncontroversial and ready to proceed once the blocker is resolved.
