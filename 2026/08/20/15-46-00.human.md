This is a bugfix patch targeting the worktree repair functionality. It addresses a long-standing asymmetry in how Git handles relative versus absolute paths in `.git` files when the `worktree.useRelativePaths` configuration is toggled.

The core issue is that `read_gitfile_gently()` always returns an absolute path, which obscures whether the original `.git` file used a relative or absolute path. This prevents `git worktree repair` from detecting mismatches when switching from relative to absolute paths. The patch introduces a new function, `read_gitfile_raw()`, which returns the path verbatim from the `.git` file, enabling the repair logic to detect and correct these mismatches symmetrically.

The implementation is clean and focused: `read_gitfile_raw()` is a minimal wrapper around the existing file-reading logic, skipping the path normalization and repository existence checks performed by `read_gitfile_gently()`. The new function is then used in `worktree.c` to preserve the original path style, while the existing API remains unchanged. The test suite (`t/t2406-worktree-repair.sh`) is expanded with four new test cases that verify the repair logic works correctly in both directions (absolute-to-relative and relative-to-absolute) and from both the main and side worktrees.

This patch is part of a settled design direction agreed upon during the v1 review, where Junio C Hamano successfully argued for introducing a new function rather than modifying the existing API. The changes are well-motivated, with a clear real-world use case (symmetrical path conversion when toggling `worktree.useRelativePaths`), and the implementation appears robust. The patch is under review but looks ready for inclusion.
