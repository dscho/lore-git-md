This is the v6 iteration of a three-patch series improving user-facing error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The series is now functionally complete and ready for merging, with only minor structural adjustments since v5.

The core change replaces Git’s terse "matched multiple remote tracking branches" warning with a detailed, actionable advice message that lists the conflicting remotes (e.g., "the branch exists on `origin`, `upstream`") and suggests using `--track` or setting `checkout.defaultRemote`. The advice is controlled by the new `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and is implemented via a shared helper, `advise_disambiguating_remotes()`, which unifies the logic across all three commands. The series also refines error handling by moving an existing `die()` call earlier in the code path to replace a generic "invalid reference" message with a more specific diagnostic, without altering `dwim_branch()`’s return behavior.

Patch 1/3 is a mechanical refactoring that extracts the advice-display logic into a reusable helper, `advise_disambiguating_remotes()`. Patch 2/3 applies this helper to `git checkout` and `git switch`, while Patch 3/3 extends it to `git worktree add`. The changes touch `builtin/checkout.c`, `builtin/worktree.c`, `checkout.c`, `checkout.h`, and the test script `t/t2400-worktree-add.sh`. Key functions updated include `unique_tracking_name()` (extended to optionally collect remote names) and the new `advise_disambiguating_remotes()` helper. Test coverage verifies the new advice format, error message format, and edge cases like `--guess-remote` (which is explicitly excluded from emitting warnings).

The series addresses a long-standing usability pain point: users previously received no guidance on how to resolve ambiguity when a branch name exists on multiple remotes. The implementation avoids workflow disruption by preserving `dwim_branch()`’s behavior and gating the advice behind a config key. Junio C Hamano and D. Ben Knoble have reviewed the series and agreed on the structural adjustments (renaming the helper and splitting the first patch), which are now incorporated. The only remaining open items are minor code nits (unnecessary braces, newlines), which do not block merging.

This is a well-motivated, thoroughly tested usability improvement with no known downsides. The advice message is clear, actionable, and consistent across commands, and the code changes are localized to the DWIM logic. The series looks ready for `next`.
