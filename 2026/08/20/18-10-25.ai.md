This is the first patch in the v14 series introducing `git history squash`, a new subcommand that collapses a commit range into its oldest ancestor. The series is now technically complete and ready for integration, with all prior review feedback addressed.

This patch is a pure refactoring that extracts a helper function, `first_parent_tree_oid()`, to centralize the logic for resolving the tree of a commit's first parent (or the empty tree for root commits). The helper replaces three nearly identical code blocks in `builtin/history.c` that each performed the same parse-and-copy dance. The change is mechanical and behavior-preserving, touching only internal structure without altering functionality.

The patch is uncontroversial and serves as a preparatory step for the core implementation in later patches. It demonstrates the series' commitment to incremental, reviewable changes, addressing earlier feedback about structural decomposition. The helper itself is straightforward: it takes a repository, a commit, and an output OID buffer, returning 0 on success or -1 on error after printing an appropriate message.

No substantive discussion is expected on this patch, as it is a clean refactoring with no behavioral implications. It is part of a larger, well-reviewed effort that has already resolved all technical and procedural concerns in prior iterations.
