This is the second patch in Justin Tobler’s nine-patch v5 series making `git receive-pack` fully ODB-agnostic. The patch splits the ODB transaction interface into two distinct steps: `commit` (making staged objects visible) and `finalize` (performing deferred cleanup and freeing the transaction). This separation enables the "files" backend to hold lockfiles after commit until references are updated, a requirement for the `.keep` file migration logic introduced in patch 1/9.

The patch adds `odb_transaction_finalize()` to handle backend-specific deferred cleanup, such as removing `.keep` files after reference updates. It also introduces a convenience helper, `odb_transaction_commit_and_finalize_or_die()`, for callers that do not need to perform work between commit and finalize. The only functional change is in `builtin/receive-pack.c`, where `odb_transaction_finalize()` is now called after `execute_commands()` to ensure `.keep` files are removed only after references are updated. All other callers are mechanically updated to use the new helper, preserving existing behavior.

The commit message is clear and well-motivated, explaining the need for the split and the specific use case (`.keep` file cleanup) that drove the change. The patch is small, focused, and directly addresses the feedback from v4, where Patrick Steinhardt requested this separation to support the `.keep` file migration logic. The implementation is clean, with no user-visible behavior changes, and the new test in `t/t5547-push-quarantine.sh` (added in patch 1/9) verifies the `.keep` file lifecycle. This patch is a necessary step toward making `git receive-pack` backend-agnostic and looks ready for merging.
