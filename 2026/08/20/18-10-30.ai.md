This is the sixth patch in the `git history squash` series (v14, 8 patches total). It implements the ref-handling safety mechanism that protects local branches descended from the squashed range from being left dangling. The patch is a direct adoption of Phillip Wood’s review patch from earlier in the thread, now fully integrated into the series.

The patch adds a new `advice.historyUpdateRefs` message that appears when `git history squash` refuses to proceed because one or more local branches would become unreachable. The error message lists the blocking branches in sorted order (short names only) and suggests `--update-refs=head` as a way to rewrite only the current branch. The check is performed early, before any objects are created, using Git’s existing `ref-filter` infrastructure to enumerate local branches whose tips are reachable from the range but whose histories do not include the range’s tip. The implementation is careful to match the refs that the default rewrite mode would update, leaving tags and remote-tracking refs untouched.

The patch also updates the test suite with two new cases: one that verifies the error message and branch listing, and another that confirms the advice can be silenced with `advice.historyUpdateRefs=false`. The test setup creates a small commit graph with three branches (`feature`, `topic-1`, `topic-2`) and ensures the error message includes both topic branches in sorted order.
