This is the fourth patch in the v14 series implementing `git history squash`, a new subcommand that folds a range of commits into their oldest ancestor. This patch establishes the revision input contract: it adds the command-line entry point, parses options (`--dry-run`, `--update-refs=(branches|head)`, `--[no-]edit`), and hands the remaining arguments to `setup_revisions()` so the command accepts standard revision ranges (`HEAD~3..topic`) and `rev-list` options. The function `setup_squash_revisions()` then enforces the required walk settings (`--reverse --topo-order`, no history simplification, `ancestry_path=1`, `boundary=0`) and rejects any range that lacks a bottom commit (i.e., a commit outside the selected range to serve as the new base). The patch is intentionally minimal—it returns an “unimplemented” error so that graph validation and the actual rewrite logic can be added in later patches.
