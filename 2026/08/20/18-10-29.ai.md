This is the fifth patch in the v14 series implementing `git history squash`, a new subcommand that collapses a range of commits into their oldest ancestor. This patch focuses on **range validation**, enforcing the structural invariants the command requires: exactly one tip, no root commits, no external parents, and no single-commit ranges.

The patch introduces `resolve_squash_range()`, which walks the selected commits in topological order, marking each with `SQUASH_SEEN` and tracking remaining tips with `SQUASH_TIP`. It rejects ranges that reach a root commit, have more than one tip, or include parents outside the range (e.g., a merge arm that entered from elsewhere). The validation logic is strict: it accepts only fully contained merges, ensuring the oldest commit’s parents are preserved and the single tip’s tree is used for the rewrite. The patch also adds a new test script (`t/t3455-history-squash.sh`) with 65 lines covering error cases for empty ranges, single commits, root commits, multiple tips, and external parents.

This is a **well-crafted, substantive piece** of the series. The validation logic is thorough, the test coverage is comprehensive, and the commit message clearly explains the invariants being enforced. The patch directly addresses feedback from Phillip Wood’s earlier reviews, particularly around rejecting malformed histories and standardizing error messages. The use of object flags (`SQUASH_SEEN`, `SQUASH_TIP`) is idiomatic, and the topological walk ensures correctness. The only remaining work for the series is the actual rewrite logic (patches 6–8), but this patch’s validation layer is a critical foundation. If the rest of the series maintains this quality, it looks ready for integration.
