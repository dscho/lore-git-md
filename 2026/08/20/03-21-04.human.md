This is a bugfix patch for the HTTP transport layer, specifically addressing how Git handles authentication headers (`WWW-Authenticate`) during HTTP redirects. The issue arises when cURL follows a redirect: the original authentication headers from the server’s response are lost because `credential_from_url()` clears the entire credential state, including the `wwwauth_headers` list. This breaks credential helpers that rely on those headers to determine which authentication methods are allowed for the new URL.

Aaron Plattner’s patch introduces a new helper function, `credential_update_url()`, which updates the URL-derived fields of a credential while preserving the `wwwauth_headers`. The implementation uses `SWAP()` to avoid unnecessary copying of the `strvec`. The patch also includes a new test case in `t/t5563-simple-http-auth.sh` that verifies the fix works for bearer authentication after a redirect, ensuring the headers are passed correctly to the credential helper.

The commit message is clear and well-motivated, referencing both a prior discussion (Junio’s suggestion to move the logic into `credential.c`) and a real-world report of the same bug. The test coverage is thorough, adding a new scenario to the existing HTTP auth test suite. This looks like a clean, targeted fix for a real problem, and the approach—preserving only what needs to be preserved rather than overhauling the credential system—seems pragmatic. The patch is part of a v2 iteration, addressing feedback from the first version.
