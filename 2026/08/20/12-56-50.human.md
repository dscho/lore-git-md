This is a **substantive review** of patch 3/7 in Patrick Steinhardt’s ODB refactoring series. Karthik Nayak raises two technical points about the logic in `odb_source_files_read_object_info()`:

First, he suggests replacing the implicit boolean check `if (!ret_packed)` with an explicit comparison `if (ret_packed == ODB_READ_OK)` for clarity, mirroring his earlier feedback on patch 2/7 about using named enum constants instead of raw integers.

Second, he questions the error-propagation logic: the code currently returns `ret_packed` only if it is not `ODB_READ_NOT_FOUND`, otherwise it returns `ret_loose`. Karthik’s analysis shows this effectively prioritizes `ODB_READ_ERROR` from the packed backend over any error from the loose backend, even `ODB_READ_NOT_FOUND`. He asks whether this is intentional—whether the design is to prefer "object exists but is corrupt" (`ODB_READ_ERROR`) over "object does not exist" (`ODB_READ_NOT_FOUND`), and whether the packed backend’s error should take precedence over the loose backend’s.

The review is narrowly focused on code clarity and error-handling semantics, not on the overall design or correctness of the series. No response from Patrick Steinhardt yet.
