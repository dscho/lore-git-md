This is the final patch in Justin Tobler’s nine-patch v5 series completing the ODB abstraction for `git receive-pack`. It introduces the generic `odb_transaction_write_pack()` interface, replacing the hardcoded `unpack()` logic that previously spawned `git index-pack` or `git unpack-objects` directly. The patch moves the unpack logic into the "files" ODB backend (`odb_transaction_files_write_pack()`), making it reusable for alternative backends (e.g., reftable, cloud storage).

The patch deletes 157 lines from `builtin/receive-pack.c`, replacing them with a new implementation in `object-file.c` that mirrors the old logic but now operates within the ODB transaction system. Key changes include:
- The `unpack_opts` struct is renamed to `odb_transaction_write_pack_opts` and passed through the new interface.
- The ".keep" lockfile management is moved into the "files" backend, with lockfiles now tracked in `struct odb_transaction_files` and removed during transaction finalization (fixing the lockfile lifecycle regression from v4).
- The unpack limit resolution now uses the transaction’s `flags` field to determine whether to read `transfer.unpackLimit` or `receive.unpackLimit`.
- The `unpack_with_sideband()` function is updated to call `odb_transaction_write_pack()` instead of `unpack()`.

The patch is mechanical and preserves all existing behavior, including the ".keep" file migration during reference updates (verified by the enhanced test in `t/t5547-push-quarantine.sh`). It touches `odb/transaction.c` and `odb/transaction.h` to add the new interface, and updates `object-file.c` to implement the "files" backend logic. No new symbols are introduced beyond the interface itself and the renamed `odb_transaction_write_pack_opts` struct.

This patch is the culmination of the series and directly enables pluggable ODB backends to handle incoming packfiles. All prior feedback has been addressed, and the series is now technically complete and ready for merging. The interface is clean and aligns with the ODB abstraction effort’s goals.
