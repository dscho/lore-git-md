This is the second patch in Patrick Steinhardt’s six-patch v3 series making Git’s packfile generation pluggable. It refactors `git upload-pack` to use the new ODB interface (`odb_generate_pack()`) instead of directly spawning `git pack-objects`.

The patch replaces manual `child_process` construction with a declarative `struct odb_generate_pack_options` setup, preserving all existing functionality: thin packs, progress meters, shallow clones, partial clones, URI protocols, and bitmap usage. The refactoring eliminates 35 lines of backend-specific code while maintaining identical behavior. Key changes include renaming `write_one_shallow()` to `append_one_shallow()` (now appending to an `oid_array` instead of writing to a file), and replacing the direct `pack-objects` command-line construction with ODB option fields. The patch also adjusts file descriptor handling to work with the ODB’s asynchronous operation model, where the generator returns file descriptors for pack and progress output.

This is a clean refactoring with no user-visible changes. The commit message is minimal but the code changes are straightforward and well-contained. The patch is part of the larger ODB abstraction effort and looks ready for review. If the series lands, this will be one of the first transport commands to benefit from pluggable packfile generation.
