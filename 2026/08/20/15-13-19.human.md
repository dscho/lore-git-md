This is a test patch for the refs subsystem, specifically adding coverage for `git symbolic-ref`'s exit codes and output when querying a non-symbolic ref. The patch itself is small, well-scoped, and follows existing test conventions—it only touches `t/t1401-symbolic-ref.sh` and adds two new tests to verify behavior already documented in the man page.

The motivation is now clear: Nikolaus is systematically auditing Git commands to ensure their documented behavior is actually tested, preventing regressions in future refactors. This isn’t a random exercise but part of a broader effort to lock in the contract between Git and its users. The patch addresses a gap where `git symbolic-ref`’s exit codes (128 without `--quiet`, 1 with `--quiet`) and output suppression were undocumented in the test suite despite being specified in the man page.

Patrick Steinhardt’s review surfaced a design quirk—the differing exit codes—which Nikolaus explains is consistent with other Git commands like `git rev-parse --verify --quiet`. The behavior stems from how `check_symref()` handles errors: the non-quiet path uses `die()`, which exits with 128, while `--quiet` avoids `die()` to suppress output, returning 1 instead. This isn’t a bug but a deliberate (if unintuitive) pattern.

The patch has been updated to also verify that stdout is empty in both cases, addressing Patrick’s suggestion. No objections to the patch itself have been raised, and the discussion has shifted from "should this be tested?" to "is the current behavior the right one?" That’s a healthy sign—the patch is likely to land as-is, but it may prompt a follow-up to align exit codes if the community decides the current behavior is too surprising.
