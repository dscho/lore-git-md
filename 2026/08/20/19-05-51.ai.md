This is a review reply in the ongoing thread about a bugfix for the `contrib/credential/libsecret` credential helper. Junio C Hamano, the maintainer, has responded to Daniel Martí’s ping with a substantive review.

Junio acknowledges he is not a GNOME expert but still engages with the technical details. He questions whether the first part of the patch—dropping the `SECRET_SEARCH_LOAD_SECRETS` flag—is necessary. His rationale is that the race condition (items being locked or deleted after the search) is rare, so most calls would still benefit from the batch-fetch optimization. He also accepts the lack of test coverage, given the difficulty of reliably reproducing the race.

The review is substantive: it proposes an alternative implementation that preserves the existing optimization while still fixing the crash. This is a classic maintainer trade-off—balancing correctness with performance. The discussion is now open on whether the original patch’s more aggressive approach (dropping the flag entirely) is justified, or whether Junio’s incremental fix is preferable.
