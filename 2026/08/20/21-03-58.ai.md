This is the final patch in a three-part series improving error messages for ambiguous remote branch names in `git worktree add`. The series is now functionally complete and ready for `next`.

This patch extends the shared `advise_disambiguating_remotes()` helper (introduced in patch 1/3 and applied to `git checkout`/`git switch` in patch 2/3) to `git worktree add`. When the command encounters an ambiguous branch name (e.g., `foo` when both `origin/foo` and `upstream/foo` exist), it now dies immediately with a clear error message listing the conflicting remotes and suggests how to resolve the ambiguity: either by specifying the remote explicitly (`git worktree add -b foo ../path origin/foo`) or by setting `checkout.defaultRemote` in the config. The advice is gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default) and includes the number of matching remotes (e.g., "matched multiple (2) remote tracking branches").

The implementation modifies `builtin/worktree.c` to call `unique_tracking_name()` with a `string_list` parameter, which collects the names of conflicting remotes. The helper function `advise_disambiguating_remotes()` then formats the advice message specifically for `worktree add`, tailoring the suggested command syntax. The test in `t/t2400-worktree-add.sh` is updated to verify the new error message format and confirm that the command fails as expected when ambiguity is detected. The `--guess-remote` case remains unaffected, as it does not trigger the ambiguity check.

This patch completes the series by ensuring consistent behavior across `git checkout`, `git switch`, and `git worktree add`. The error message and advice are now uniform, actionable, and localized to the DWIM logic, with no changes to the underlying branch resolution behavior.
