This is the second patch in the v6 series improving error messages for ambiguous remote branch names in `git checkout` and `git switch`. It applies the shared advice helper introduced in patch 1/3 to the checkout/switch code paths, replacing the generic "matched multiple remote tracking branches" warning with a detailed, actionable message that lists the conflicting remotes (e.g., "the branch exists on `origin`, `upstream`").

The patch extends `unique_tracking_name()` to optionally collect the names of matching remotes via a new `struct string_list *dwim_remote_names` parameter, then passes this list to the renamed `advise_disambiguating_remotes()` helper. The advice message is tailored to the command (`checkout` or `switch`) and includes the branch name and a static list of remotes, along with suggestions to use `--track` or set `checkout.defaultRemote`. The error message is also improved to include the number of matching remotes (e.g., "matched multiple (2) remote tracking branches").

Key changes:
- `builtin/checkout.c`: Updates `parse_remote_branch()` to collect remote names and pass them to the advice helper. The advice message is now more specific, listing remotes and referencing the branch name.
- `checkout.c`: Extends `unique_tracking_name()` to optionally populate `dwim_remote_names` via a callback (`check_tracking_name()`).
- `checkout.h`: Updates the function signature to include the new `dwim_remote_names` parameter.

The patch preserves the existing `die()` behavior but moves it later in the flow to allow the advice message to be displayed first. It does not alter `dwim_branch()`'s return behavior, addressing earlier concerns about workflow disruption. The changes are localized to the DWIM logic and are gated behind the `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default).

This is a well-crafted usability improvement with clear test coverage (handled in patch 3/3). The advice message is actionable and consistent with the series' goal of helping users resolve ambiguity. The patch is ready for `next`.
