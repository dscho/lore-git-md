This is the seventh patch in the fourteenth iteration of Harald Nordgren’s `git history squash` series, which is now functionally complete and ready for integration. This patch implements the core commit-creation logic for the `--no-edit` mode, allowing users to fold a range of commits into their oldest ancestor without opening an editor.

The patch adds about 300 lines to `builtin/history.c`, introducing helpers to resolve `fixup!`, `squash!`, and `amend!` markers while walking the commit range. It enforces strict rules: markers whose targets are not in the range are rejected, and folding a `squash!` or `amend!` commit without `--edit` is refused unless the target is the first commit in the range. When multiple `amend!` commits target the same commit, the last one’s message is used. The implementation preserves the authorship and parent list of the oldest commit, uses the tip’s tree, and replays descendants through the existing history-rewrite machinery. The reflog records the full revision expression to preserve user intent.

The test suite expands significantly, covering edge cases like nested fixup markers, interior merges, octopus merges, and ranges whose base or tip is a merge commit. The tests verify that the command refuses operations that would leave local branches dangling, preserves merge topology, and correctly handles autosquash-style templates. The patch also updates the documentation to clarify that the command can fold merges inside the selected range but does not replay merge commits onto the rewritten history.

This patch is well-tested and addresses all prior review feedback, including Phillip Wood’s concerns about autosquash handling and merge-parent preservation. The series as a whole is marked "Will replace" by Junio Hamano, indicating intent to merge once the final procedural details (such as trailer ordering) are confirmed. The implementation is positioned as a foundational piece for future integration with `git rebase --autosquash` via `git replay`.
