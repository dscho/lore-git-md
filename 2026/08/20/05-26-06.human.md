This is the final exchange in the `dk/use-nsec-runtime` series, which replaces Git’s build-time `USE_NSEC` macro with the runtime configuration option `core.useNanosec`. The series is cooking in `next` and ready to graduate to `master` once the last polish items are addressed.

Junio and Patrick agree that **no runtime warning** should be emitted when `core.useNanosec=true` is set on a platform where `NO_NSEC` is defined. The concern was that users sharing a `.gitconfig` across machines with different Git builds (some with nanosecond support, some without) would find a warning obnoxious. Instead, the documentation will include a clear warning about platform and filesystem limitations, and users can use per-machine overrides (e.g., `includeIf`) to avoid setting the option on unsupported platforms. This decision prioritizes user experience for shared configurations over proactive warnings.

The exchange is brief and confirms what was already implied in earlier discussion: the cross-platform correctness blocker (silent corruption risk) is resolved by `#ifdef`-ing out the `use_nanosec` field and related code paths in `NO_NSEC` builds, and the remaining open questions—unconditional initialization of `use_nanosec`, simplifying preprocessor guards in `is_racy_stat()`, and updating a missed `USE_NSEC` reference in a comment—are unaffected. The series is otherwise technically complete and uncontroversial.
