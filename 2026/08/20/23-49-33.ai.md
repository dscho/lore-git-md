This is the second patch in Justin Tobler’s nine-patch v5 series completing the ODB abstraction for `git receive-pack`. It introduces the `odb_transaction_finalize()` interface, splitting the existing `odb_transaction_commit()` into two distinct steps: committing the staged objects (making them visible) and finalizing the transaction (performing deferred cleanup and freeing resources). The motivation is to enable post-commit operations, such as removing ".keep" files after reference updates, which is required for the "files" backend in `git receive-pack`.

The patch adds `odb_transaction_finalize()`, which invokes an optional backend-specific callback for deferred cleanup, and introduces the helper `odb_transaction_commit_and_finalize_or_die()` for callers that do not need to perform work between commit and finalization. The only functional change is in `builtin/receive-pack.c`, where `odb_transaction_finalize()` is now called *after* reference updates, ensuring ".keep" files are removed only once the packfile is no longer needed. All other callers (e.g., `builtin/add.c`, `builtin/unpack-objects.c`, `cache-tree.c`) are mechanically updated to use the new helper, preserving their existing behavior.

The commit message incorporates Patrick Steinhardt’s suggested rewording from v4, clarifying the motivation for the split without altering the technical content. The patch is a straightforward refactor with no user-visible behavior changes, and it directly addresses the lockfile lifecycle regression fix introduced in the prior ODB transaction work (bdee7b3013). The new interface is well-motivated and aligns with the broader ODB abstraction effort, enabling future backend-specific cleanup logic. The changes are minimal and focused, touching only the transaction API and its callers, and the patch is ready for merging as part of the series.
