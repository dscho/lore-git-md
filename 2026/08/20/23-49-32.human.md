This is the first patch in Justin Tobler’s nine-patch v5 series making `git receive-pack` fully ODB-agnostic. It fixes a regression introduced in bdee7b3013 (July 2026) where the ".keep" lockfile—used to protect incoming packfiles from pruning until refs are updated—was incorrectly placed in the quarantine directory instead of the main object directory. The bug surfaces when ODB transactions reorder the sources list, causing `index_pack_lockfile()` to derive the wrong path.

The patch updates `index_pack_lockfile()` to take an explicit `struct odb_source *` parameter instead of a `struct repository *`, ensuring the ".keep" file is written to the correct location. The call sites in `builtin/receive-pack.c` and `fetch-pack.c` are updated to pass the expected ODB source: the transaction source for the quarantine directory during unpacking, and the main ODB source for the final lockfile path. A new test in `t/t5547-push-quarantine.sh` verifies the ".keep" file is correctly migrated to the main ODB during the reference update phase and removed afterward.

The change is surgical and well-motivated, addressing a subtle but critical race condition. The test coverage—added in response to Patrick Steinhardt’s v4 feedback—directly validates the fix and ensures the packfile remains protected while refs are being updated. The patch is part of the broader ODB abstraction effort and is a prerequisite for the generic `odb_transaction_write_pack()` interface introduced later in the series. No user-visible behavior changes; this is purely a correctness fix for the transactional backend. The series is cooking in `seen` and appears ready for `next`.
