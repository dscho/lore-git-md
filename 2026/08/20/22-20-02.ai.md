This is a test patch targeting the `git symbolic-ref` command. It is the second iteration of a standalone patch that adds test coverage for exit codes and output behavior when querying a non-symbolic ref, both with and without the `--quiet` (`-q`) flag.

The patch now includes three new tests in `t/t1401-symbolic-ref.sh`. The first verifies that `git symbolic-ref` exits with code 128 and prints the expected error message ("is not a symbolic ref") when given a non-symbolic ref, while ensuring stdout is empty. The second checks that `--quiet` suppresses the error message, exits with code 1, and produces no output on either stdout or stderr. A third implicit test confirms stdout is empty in both cases, addressing a review suggestion from Patrick Steinhardt.

The commit message has been expanded to clarify the motivation: while existing tests (e.g., `t2020`, `t5621`) already rely on `--quiet` failing on a detached HEAD, none explicitly test the exit codes or confirm that `--quiet` suppresses diagnostics. The patch documents the current behavior, which is consistent with other Git commands (e.g., `git rev-parse --verify --quiet`), though the differing exit codes (128 vs. 1) remain a point of discussion. The technical rationale—consistency with `die()` and other plumbing commands—has been provided, but no consensus has emerged on whether this design is intentional or warrants a follow-up patch to align the exit codes.

The patch itself is minimal, touching only the test file and following existing test style. It introduces no new functionality or on-disk format changes. The tests are well-scoped and directly address the gap in coverage. The discussion remains open on the design question, but the patch is otherwise ready for review and likely to be merged as-is.
