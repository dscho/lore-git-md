This is the final patch in Patrick Steinhardt’s six-patch v3 series making packfile generation pluggable in Git’s object database (ODB) layer. It migrates `git bundle` to use the new ODB interface (`odb_generate_pack()`), completing the transport-layer refactoring for all pack-based transfer mechanisms (fetch, push, and now bundle).

The patch replaces the direct `git pack-objects` invocation in `bundle.c` with a declarative setup using `struct odb_generate_pack_options`. The new code preserves all existing functionality: thin packs, delta base offsets, and filter specs for partial clones. The `write_pack_data()` function is simplified from 45 lines to 37, eliminating manual `child_process` construction and replacing it with a single call to `odb_generate_pack()` followed by a loop to relay the generated pack data. The files-backend implementation (`odb_source_files_generate_pack()`) handles the translation of ODB options into `git pack-objects` command-line arguments, including `--thin`, `--delta-base-offset`, and `--filter`.

This patch also removes the last vestige of the `pack_opts` strvec from `builtin/bundle.c`, consolidating progress-meter handling into a single boolean `progress` flag (introduced in patch 4/6). The `create_bundle()` function signature is updated to accept `progress` directly, and the call in `cmd_bundle_create()` now passes the flag without intermediate string manipulation.

The series’ goal — making the ODB the single spawn point for all pack streams leaving the repository — is now fully realized. Only local maintenance tasks like `git repack` retain direct knowledge of `git pack-objects`. The patch touches three files (`builtin/bundle.c`, `bundle.c`, `bundle.h`) and introduces no new symbols or on-disk format changes. Test coverage remains unchanged, as the patch does not alter observable behavior. The unresolved `the_repository` dependency in `get_log_output_encoding()` (noted in patch 5/6) does not affect this patch.
