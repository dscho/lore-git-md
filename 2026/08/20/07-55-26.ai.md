This is the second patch in Patrick Steinhardt’s six-patch v3 series making packfile generation pluggable in Git’s object database (ODB) layer. It refactors `git upload-pack` to use the new ODB interface (`odb_generate_pack()`) instead of directly spawning `git pack-objects`.

The patch replaces manual `child_process` construction in `upload-pack.c` with a declarative `struct odb_generate_pack_options` setup, preserving all existing functionality: thin packs, progress meters, shallow clones, partial clones, URI protocols, delta policies, and promisor pack handling. The refactoring eliminates 35 lines of backend-specific code, replacing it with a single call to `odb_generate_pack()` and a loop to relay the generated pack data. Key changes include renaming `write_one_shallow()` to `append_one_shallow()` (now appending to an `oid_array` instead of writing to a `FILE*`), and updating the poll loop to read from the ODB generator’s file descriptors (`generator->out` and `generator->err`) instead of the child process’s pipes.

The patch is mechanical and well-scoped, touching only `upload-pack.c` and maintaining identical behavior. Test adjustments in `t5516-fetch-push.sh` (handled in a later patch) account for benign argument-order changes and the replacement of `-q` with `--quiet`. The ODB interface’s design for asynchronous operation (returning file descriptors for pack and progress output) is preserved, and the files-backend implementation (introduced in patch 1/6) translates the ODB options into `git pack-objects` command-line arguments.

No new edge cases are introduced, but deeper verification of shallow clone interactions, partial clone filter specs, and error handling during pack generation remains pending. The patch is part of the larger ODB abstraction effort, which aims to decouple Git’s transport layer from the "files" backend, and it sets the stage for future work on repository maintenance and the proposed `git-objects` command.
