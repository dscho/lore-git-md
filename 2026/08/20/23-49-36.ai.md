This is patch 5/9 in the v5 series making `git receive-pack` fully ODB-agnostic by introducing a generic `odb_transaction_write_pack()` interface. The patch lifts global state out of the `unpack()` function by bundling it into a new `struct unpack_opts` that is passed explicitly.

The patch touches only `builtin/receive-pack.c`, replacing the global variables `receive_fsck_objects`, `transfer_fsck_objects`, `fsck_msg_types`, `max_input_size`, `reject_thin`, and `quiet` with a structured `unpack_opts` that holds the same values. The ternary initialization of `fsck_objects` and the late assignment of `err_fd` in `unpack_with_sideband()` are preserved as trade-offs for removing global state. The `unpack()` function’s signature changes to take a `const struct unpack_opts *` instead of the old `shallow_file` and `err_fd` parameters, and all internal references to the globals are updated to use the struct fields.

No user-visible behavior change is introduced; this is a pure refactoring to enable the subsequent patch (6/9) that moves the unpack logic behind the ODB transaction interface. The patch is mechanically straightforward and aligns with the series’ goal of eliminating global state to support pluggable ODB backends. The `unpack_opts` struct is initialized in `unpack_with_sideband()` and passed through the call chain, making the state flow explicit and testable. This change directly addresses Junio’s v2 feedback about global state removal and is a prerequisite for the generic `odb_transaction_write_pack()` interface introduced in patch 6/9.
