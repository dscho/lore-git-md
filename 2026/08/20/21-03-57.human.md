This is the second patch in a three-part series improving Git’s error messages when an ambiguous remote branch name is provided to `git checkout` or `git switch`. The series is now functionally complete and ready for merging.

This patch updates the checkout code to show a detailed, actionable advice message when a branch name (e.g., `bar-topic`) exists on multiple remotes (e.g., `origin` and `upstream`). Instead of the terse “matched multiple remote tracking branches” warning, users now see a list of conflicting remotes and a suggestion to use `--track <remote>/<branch>` or set `checkout.defaultRemote`. The advice is controlled by the new `advice.checkoutAmbiguousRemoteBranchName` config key (enabled by default).

The implementation extends `unique_tracking_name()` to optionally collect the names of matching remotes, then passes them to the new `advise_disambiguating_remotes()` helper, which formats the advice message. The patch also moves an existing `die()` call earlier in the code path to replace a generic “invalid reference” error with a clearer diagnostic that explains the ambiguity. This change is intentional and justified in the commit message: the command was already failing, just with less clarity.

The patch touches `builtin/checkout.c`, `checkout.c`, and `checkout.h`, and updates the advice logic to include the branch name and remote list in the message. Test coverage is handled in the series’ third patch, which also extends the feature to `git worktree add`. Junio C Hamano and D. Ben Knoble have reviewed the series and agreed on the structural adjustments, which are now incorporated. Only minor code nits remain, and they do not block merging.

This is a well-crafted usability improvement that addresses a long-standing pain point without disrupting existing workflows. The advice is clear, actionable, and consistent across commands. The patch looks ready for `next`.
