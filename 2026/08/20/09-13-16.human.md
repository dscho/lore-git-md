This is a **substantive review follow-up** in the ongoing discussion about adding a Trace2 data point for total bytes written by `git pack-objects`. The email is a back-and-forth between Patrick Steinhardt and Jeff King (Peff) about a technical detail in the patch’s implementation: how to handle hash size consistency when calculating the cumulative byte count.

The core issue is whether the patch should use `f->algop->rawsz` (the hash algorithm used by the hashfile) or `the_repository->hash_algo->rawsz` to account for the trailing checksum in the byte count. Peff confirms that both are functionally equivalent in practice, since the hashfile is always created with `the_repository->hash_algo`, but suggests a refactoring to make the code more consistent by using `f->algop` in all three conditional blocks in `write_pack_file()`. Patrick agrees with this approach and also endorses Peff’s suggestion to switch to the unsafe hash algorithm variant for performance reasons, calling the current triple-hash recomputation "absurdly pessimal."

The discussion then broadens into a critique of the current code’s paranoid approach to packfile verification, which involves recomputing the hash three times (during writing, during `fixup_pack_header_footer()`, and during read-back verification). Both reviewers express skepticism about the necessity of this level of caution, noting that Git does not re-verify other on-disk data structures like loose objects or refs. However, they agree this performance curiosity is out of scope for the current patch and should be addressed separately.

For the patch itself, the takeaway is that the author will likely incorporate Patrick’s suggestion to use `f->algop->rawsz` in v3, possibly with Peff’s refactoring or a similar approach. The Trace2 event (`write_pack_file/wrote_bytes`) and the patch’s core goal—adding observability for cumulative packfile bytes—remain unchanged. The patch is still under review, with no merge status reported. This exchange is a good example of how the Git mailing list’s review process surfaces deeper technical considerations, even for small patches.
