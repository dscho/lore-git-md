This is the final patch in Justin Tobler’s nine-patch v5 series completing the ODB abstraction for `git receive-pack`. The patch introduces `odb_transaction_write_pack()`, a generic interface that replaces the hardcoded `unpack()` logic in `git receive-pack` with a backend-agnostic transaction mechanism. The "files" backend implementation reuses the existing `unpack()` logic but now manages ".keep" lockfiles within the transaction lifecycle, ensuring they are removed during finalization rather than relying on global state.

The patch moves the entire `unpack()` function from `builtin/receive-pack.c` into `object-file.c` as `odb_transaction_files_write_pack()`, updating it to store ".keep" lockfiles in the transaction’s `pack_lockfiles` array instead of a global `pack_lockfile` variable. The transaction’s `finalize()` callback now iterates over this array to clean up the lockfiles, fixing the regression introduced in bdee7b3013 where lockfiles were not being removed correctly. The call sites in `git receive-pack` are updated to use the new interface, and the global `pack_lockfile` variable is removed entirely.

The new `odb_transaction_write_pack_opts` struct bundles all unpack-related options (fsck settings, shallow file path, max input size, etc.) into a single parameter, replacing the previous ad-hoc parameter list. The patch also introduces the `write_pack` callback in `struct odb_transaction`, enabling alternative ODB backends to implement their own packfile ingestion logic. The "files" backend’s implementation is the only one provided here, but the interface is designed to be generic.

This patch is a clean, well-motivated refactoring that directly addresses the series’ goal of making `git receive-pack` fully ODB-agnostic. The commit message clearly explains the motivation, the changes, and the benefits, and the implementation is consistent with the rest of the ODB transaction system. The removal of global state and the explicit lockfile management are particularly strong improvements. The series as a whole is now technically sound and ready for merging, pending Junio’s final review.
