This is the fifth iteration (v5) of Justin Tobler’s nine-patch series completing the ODB abstraction for `git receive-pack` by introducing the generic `odb_transaction_write_pack()` interface. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and builds on prior work (bdee7b3013) that staged incoming objects via ODB transactions.

The core goal remains unchanged: replace `git receive-pack`'s hardcoded use of `git index-pack` and `git unpack-objects` (which assume the "files" backend) with a backend-agnostic transaction interface, enabling alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles. This iteration addresses the last remaining feedback from v4, including Patrick Steinhardt’s request for additional test coverage to verify the ".keep" file’s migration during the reference update phase. The series now includes a new test step in `t/t5547-push-quarantine.sh` that uses a `reference-transaction` hook to check for the ".keep" file’s presence in the main ODB during the reference update and its removal afterward. This enhancement ensures the packfile is protected from pruning while refs are being updated, addressing the race-avoidance properties Patrick highlighted.

The series also incorporates Patrick’s suggested commit message rewording for patch 2/9, improving clarity around the motivation for `odb_transaction_commit_and_finalize_or_die()`. The change is purely stylistic and does not affect the patch’s technical content. The rest of the series remains unchanged from v4, retaining all the substantive improvements: context-aware unpack limit resolution via `odb_transaction_flags`, explicit ODB source tracking, removal of global state, and the generic `odb_transaction_write_pack()` interface. The unpack limit helper `get_unpack_limit()` now takes an `enum odb_transaction_flags` parameter, enabling it to resolve `transfer.unpackLimit` and `receive.unpackLimit` (with the latter taking precedence) for `git receive-pack` and future `fetch.unpackLimit` for `git fetch-pack`.

The series touches `builtin/receive-pack.c`, `odb/transaction.c`, `object-file.c`, and related headers, with mechanical updates to other builtins for transaction API consistency. The new test assertion in `t/t5547-push-quarantine.sh` is the only functional change since v4, and it directly addresses the last open question from the v4 review. The series appears technically sound and ready for merging, with all critical design flaws addressed and the interface refined based on reviewer feedback. It is a significant step toward making `git receive-pack` fully ODB-agnostic, aligning with the broader ODB abstraction effort. The series is now well-positioned for inclusion in `next`, pending Junio’s final review.
