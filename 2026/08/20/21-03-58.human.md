This is the final patch in a three-part series improving error messages for ambiguous remote branch names in `git worktree add`. The series is now functionally complete and ready for merging.

This patch extends the shared advice helper (`advise_disambiguating_remotes()`) introduced in patch 1/3 and applied to `git checkout`/`git switch` in patch 2/3 to `git worktree add`. When the command encounters an ambiguous branch name (e.g., `foo` when both `origin/foo` and `upstream/foo` exist), it now dies immediately with a clear error message listing the conflicting remotes and actionable advice. The advice suggests creating a worktree from a specific remote branch (e.g., `git worktree add -b foo ../path origin/foo`) or setting `checkout.defaultRemote` to prefer a particular remote.

The implementation reuses the `unique_tracking_name()` function (extended in patch 1/3 to optionally collect remote names) and follows the same pattern as the earlier patches: the advice is gated behind `advice.checkoutAmbiguousRemoteBranchName` (enabled by default) and includes the number of matching remotes in the error message (e.g., "matched multiple (2) remote tracking branches"). The test suite is updated to verify the new error message format and behavior.

This patch ties the series together, ensuring consistent error handling and advice across `git checkout`, `git switch`, and `git worktree add`.
