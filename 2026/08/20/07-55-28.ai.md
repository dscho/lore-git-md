This is the fourth patch in Patrick Steinhardt’s six-patch v3 series making packfile generation pluggable in Git’s ODB layer. It is a refactoring patch targeting the `git bundle` command’s progress-meter option handling.

The patch simplifies the command-line interface for `git bundle create` by consolidating four related options (`--quiet`, `--progress`, `--all-progress`, and `--all-progress-implied`) into a single boolean `progress` flag. The `--all-progress-implied` option is retained as a no-op for backward compatibility, while `--all-progress` is kept as a hidden alias for `--progress`. The change reduces internal complexity by eliminating redundant option handling and prepares the codebase for the upcoming migration to the generic ODB packfile-generation interface (patch 6/6).

The diff touches only `builtin/bundle.c`, replacing the `OPT_PASSTHRU_ARGV` macros with `OPT_BIT`, `OPT_NEGBIT`, and `OPT_NOOP_NOARG` to manage the boolean state directly. The logic for determining whether to show progress (defaulting to `isatty(STDERR_FILENO)`) is preserved, and the resulting boolean is used to push either `--progress` or `--quiet` into the `pack_opts` strvec. The patch is mechanical and does not alter behavior; it merely streamlines the interface.

This patch is part of the larger ODB abstraction effort, which aims to decouple Git’s transport layer from the "files" backend. The series as a whole remains queued in `seen` and under active review, with this patch addressing a minor but necessary cleanup before the ODB migration in patch 6/6. The change is uncontroversial and appears well-motivated, aligning with the series’ goal of reducing backend-specific code.
