This thread is about a bugfix for Git’s HTTP authentication layer. When Git follows an HTTP redirect, it loses `WWW-Authenticate` headers from the response, breaking authentication for redirect targets that rely on credential helpers like OAuth2 Bearer tokens. Aaron Plattner identified the issue and proposed a fix in v1, which Junio C Hamano reviewed and suggested centralizing the preservation logic.

The v2 patch introduces `credential_update_url()`, a reusable helper in `credential.c` that preserves `wwwauth_headers` across URL updates. This helper is now used in `http.c` when recovering from redirects, ensuring the headers are retained. The change is minimal and focused, with a new test in `t/t5563-simple-http-auth.sh` verifying the fix using a custom Apache rewrite rule to simulate a redirect to a bearer-auth-protected endpoint.

The patch is uncontroversial and addresses the regression cleanly. Junio’s reply to v2 was procedural, linking to the v1 submission for context, but no substantive objections or open questions have been raised. The series is now under review, with no further changes expected unless new feedback emerges.
