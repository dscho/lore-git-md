This thread is about a bugfix patch that prevents Git from losing `WWW-Authenticate` headers during HTTP redirects, which breaks authentication when the redirect target requires credential helpers like OAuth2 Bearer tokens. The patch is now in its second version, posted by Aaron Plattner, and Junio C Hamano has explicitly called for reviewers to step in, noting that the HTTP transfer codepaths could use more attention.

The fix introduces a new helper function, `credential_update_url()`, in `credential.c` to preserve the `wwwauth_headers` field when updating the credential struct for a new URL. This replaces the previous behavior in `http.c`, where `credential_from_url()` would clear the field, and makes the logic reusable for future credential fields. The patch includes a test in `t/t5563-simple-http-auth.sh` that verifies the fix using a custom Apache rewrite rule to simulate a redirect to a bearer-auth-protected endpoint.

The patch is uncontroversial and addresses a clear regression without introducing new edge cases. Junio’s call for review is the main development since the last update, as the patch itself is ready for validation. No objections or open questions have been raised, and the series is complete at two iterations. If you’re familiar with Git’s HTTP or credential code, this is a straightforward and well-motivated change worth reviewing.
