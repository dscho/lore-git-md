This thread is about a bugfix for Git's HTTP authentication layer, authored by Aaron Plattner. The issue is a regression where `WWW-Authenticate` headers from an HTTP redirect response are lost when Git updates the credential struct for the new URL, breaking authentication when the redirect target requires a credential helper (like OAuth2 Bearer tokens).

The fix introduces a new helper function, `credential_update_url()`, in `credential.c` that preserves the `wwwauth_headers` field across URL updates. This change ensures the authentication challenge from the server persists through redirects, allowing credential helpers to work correctly. The patch is minimal, touching only the HTTP and credential subsystems, and includes a thorough test in `t/t5563-simple-http-auth.sh` to verify the fix.

The discussion so far shows no controversy, and the patch appears to address a real-world issue cleanly. The v2 iteration improves reusability by moving the preservation logic into `credential.c`, making it available for future credential fields that might need similar treatment. The fix is well-motivated, with references to prior reports and maintainer suggestions.
