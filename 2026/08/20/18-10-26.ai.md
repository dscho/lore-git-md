This is the second patch in the v14 series implementing `git history squash`, a new subcommand that folds a commit range into its oldest ancestor. The series is now technically complete and ready for integration, with all prior feedback addressed.

This patch adds an optional `message_template` parameter to `commit_tree_ext()` in `builtin/history.c`. When provided, the function uses the template as the commit message body instead of the original commit’s message. Existing callers (`cmd_history_fixup` and `split_commit`) pass `NULL` to preserve the current behavior. The change is a straightforward refactoring that enables later patches to seed the squashed commit’s message from multiple sources rather than a single commit.

The patch touches only `builtin/history.c`, modifying the function signature and adding a six-line conditional block to handle the template. No behavior changes are introduced; the patch is purely preparatory for the squash-message logic implemented in later patches. The commit message clearly states the motivation and the unchanged behavior for `NULL` templates. This is a well-scoped, uncontroversial refactoring that fits cleanly into the series’ decomposition.
