This is a bugfix patch for Git's trailer parsing subsystem, now ready for integration. The patch prevents Git from incorrectly interpreting URLs (e.g., `https://example.com`) as trailers in commit messages, a real-world issue affecting tools like `--only-trailers` and `%(trailers:only)` formatting. The problem was documented in 245 instances in the Linux kernel history, where URLs were mangled by Git's loose trailer matching.

The solution modifies `find_separator()` in `trailer.c` to exclude lines containing `://` from trailer parsing, a heuristic previously endorsed by Jeff King and Junio C Hamano as "much more robust" than alternative approaches. The patch includes comprehensive test coverage for all three problematic scenarios (non-trailer URLs, line-wrapped URLs, and patch-processing edge cases) and updates documentation. The only remaining change is a trivial readability improvement—replacing manual pointer arithmetic with `starts_with()`—which Kristoffer Haugsbakk has already prepared in a v2 patch.

Junio's query confirms the patch is now unblocked (its base topic has graduated to `master`) and asks only for confirmation of outstanding issues. Kristoffer's response indicates none exist beyond the minor `starts_with()` tweak, which is uncontroversial and does not affect functionality. The patch appears well-crafted, thoroughly tested, and addresses a clear pain point without introducing regressions. It should be a straightforward merge for the next release.
