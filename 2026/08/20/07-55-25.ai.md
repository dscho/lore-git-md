This is the first patch in Patrick Steinhardt’s six-part v3 series introducing a pluggable interface for packfile generation in Git’s object database (ODB) layer. It lays the foundation for the rest of the series by defining the new ODB interface (`odb_generate_pack()`) and implementing it for the "files" backend.

The patch adds two new structures: `struct odb_generate_pack_options` (encapsulating wants, haves, shallows, filter specs, URI protocols, progress settings, delta policies, and file descriptors for pack and progress output) and `struct odb_pack_generator` (an asynchronous operation handle with file descriptors for the generated pack and progress output, plus a finish callback). The files-backend implementation (`odb_source_files_generate_pack()`) delegates to the existing `git pack-objects` command, translating ODB options into command-line arguments (e.g., `--thin`, `--shallow`, `--filter`, `--uri-protocol`). It handles edge cases like shallow boundaries by neutralizing the repository’s shallow state when caller-provided shallows are present, and it supports asynchronous operation by returning file descriptors for the pack and progress output when the caller requests pipes. Error handling includes proper cleanup of descriptors and reporting of pack-objects failures (except SIGPIPE, which is treated as a normal occurrence).

The patch touches four files: `odb.c` (core ODB layer), `odb.h` (interface definitions), `odb/source-files.c` (files-backend implementation), and `odb/source.h` (ODB source interface). The changes are mechanical and focused on introducing the new interface without altering existing behavior. The commit message explains the motivation clearly: decoupling the transport layer from the "files" backend by making packfile generation pluggable, while deferring the more complex task of porting `git-pack-objects` itself to a future `git-objects` command.

This patch is well-crafted and addresses a real architectural need in the ODB abstraction effort. The interface is designed for asynchronous operation, which aligns with the transport layer’s requirements, and the files-backend implementation preserves all existing functionality (thin packs, shallow clones, partial clones, progress meters, delta policies). The use-after-scope bug identified by Elijah Newren in v2 has been fixed by moving the `child_process` struct from the stack to the heap, eliminating the risk of stale pointer dereferencing during abnormal exits. No test coverage is added in this patch, but the subsequent patches in the series adjust existing tests to account for benign argument-order changes and the replacement of `-q` with `--quiet`.
