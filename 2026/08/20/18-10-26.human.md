This is the second patch in the v14 series introducing `git history squash`, a new command that folds a range of commits into their oldest ancestor. The series is now technically complete and ready for integration, with all prior feedback addressed.

This patch adds an optional `message_template` parameter to `commit_tree_ext()`, allowing callers to seed the commit message from a source other than the single commit passed as `commit_with_message`. When the template is `NULL`, the function behaves exactly as before, preserving the existing fixup and split callers. The change is a straightforward refactoring that enables the later squash logic to build a composite message from multiple commits rather than reusing just one.

The patch touches only `builtin/history.c`, modifying the function signature and updating its three callers (`commit_tree_with_edited_message`, `cmd_history_fixup`, and `split_commit`) to pass `NULL` for the new parameter. The logic is behavior-preserving and uncontroversial; the real work of constructing a squash message happens in later patches.

This is a well-motivated refactoring that cleanly separates the plumbing from the policy. The commit message clearly explains why the change is needed and how it fits into the larger series. No test changes are required here because the patch does not alter observable behavior.
