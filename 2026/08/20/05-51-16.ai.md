This is a reply in the reftable stack-reload optimization thread, specifically addressing the first patch of Karthik Nayak’s three-patch series. The patch removes the `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag from the reftable stack API, making stack reloading the default behavior in `reftable_stack_init_addition()`.

Patrick Steinhardt’s reply is a surface-level review comment. He notes that libgit2 (a separate project) uses the flag being removed, but confirms that all libgit2 call sites already pass it, so the change is compatible with minimal adaptation. His only suggestion is a cosmetic one: renaming the function from `reftable_stack_new_addition()` to `reftable_stack_addition_new()` for naming consistency. There is no objection to the patch’s substance, and the feedback does not raise new technical concerns or block progress. The comment is narrowly scoped to API aesthetics and external compatibility, leaving the patch’s core logic and motivation intact.
