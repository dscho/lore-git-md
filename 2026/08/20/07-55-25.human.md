This is the first patch in Patrick Steinhardt’s six-part v3 series introducing a pluggable interface for packfile generation in Git’s object database (ODB) layer. It lays the foundation for the rest of the series by defining the new ODB interface and implementing it for the "files" backend.

The patch adds two key structures: `struct odb_generate_pack_options` (which encapsulates all the settings needed for packfile generation, such as wants, haves, shallows, filter specs, URI protocols, progress settings, and delta policies) and `struct odb_pack_generator` (a handle for asynchronous packfile generation, exposing file descriptors for the pack and progress output). The core function `odb_generate_pack()` delegates to the backend-specific implementation, while `odb_pack_generator_finish()` waits for completion and cleans up resources. The files-backend implementation (`odb_source_files_generate_pack()`) translates these options into a `git pack-objects` command, handling edge cases like shallow boundaries and promisor packs.

This is a well-structured refactoring that clearly separates the transport-layer use of packfiles from backend-specific details. The commit message explains the motivation (decoupling Git’s transport layer from the "files" ODB backend) and the long-term vision (a future `git-objects` command to expose generic ODB interfaces). The patch itself is clean, with thorough error handling and a fix for the use-after-scope bug identified in v2. The interface is designed for asynchronous operation, which aligns with the needs of transport commands like `git upload-pack` and `git send-pack`.

The series is part of Patrick’s larger ODB abstraction effort, and this patch is a critical step toward making Git’s transport layer backend-agnostic. It doesn’t change behavior yet—subsequent patches will migrate existing commands to use the new interface—but it establishes the plumbing needed for that transition.
