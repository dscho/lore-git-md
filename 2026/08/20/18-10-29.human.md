This is the fifth patch in the v14 series introducing `git history squash`, a new subcommand that collapses a range of commits into their oldest ancestor. This patch implements the core range validation logic, ensuring the input meets the command’s strict invariants: exactly one tip, no root commits, no external parents, and at least two commits.

The patch walks the selected commits in topological order, marking each with `SQUASH_SEEN` and tracking tips with `SQUASH_TIP`. It rejects ranges that reach a root commit, have more than one tip, or include a merge whose parent lies outside the range. The validation is shape-based, not content-based, so it accepts merges fully contained by the range while rejecting those with external arms. The test script (`t/t3455-history-squash.sh`) covers all error cases: empty ranges, single commits, root commits, multi-tip ranges, and external parents.
