This is a **substantive review** of the Trace2 instrumentation patch for `git pack-objects`. Patrick Steinhardt raises two technical points about the v2 implementation:

1. **Hash size consistency**: He questions whether the patch should use `f->algop->rawsz` (the hash algorithm used by the hashfile itself) instead of `the_repository->hash_algo->rawsz` to account for the trailing hash. This is a correctness concern about whether the byte count accurately reflects the actual data written, including the checksum.

2. **Event naming clarity**: He notes that the existing Trace2 event `"write_pack_file/wrote"` is ambiguously named (it counts objects, not bytes) and suggests `"wrote_objects"` would be clearer. While he acknowledges Trace2 events are not guaranteed stable, he implies the new `"wrote_bytes"` event could make the confusion worse. However, he does not insist on a rename, framing it as a minor preference rather than a blocker.

The review is narrowly scoped to implementation details and does not challenge the patch’s motivation or design. The author will need to address the hash size consistency point in a v3, while the event naming suggestion is optional. The patch remains uncontroversial and close to ready for integration. Key files: `builtin/pack-objects.c`; new event: `"write_pack_file/wrote_bytes"`.
