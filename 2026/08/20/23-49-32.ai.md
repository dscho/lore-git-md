This is the first patch in Justin Tobler’s v5 series completing the ODB abstraction for `git receive-pack`. It fixes a regression introduced in bdee7b3013 (July 2026) where `.keep` files—used to protect incoming packfiles from pruning until refs are updated—were not being properly cleaned up after the ODB transaction committed. The root cause is that `index_pack_lockfile()` was hardcoded to derive the `.keep` file path from the repository’s primary object directory, but the ODB transaction system reorders the sources list to make the quarantine directory the primary source during the transaction. This mismatch caused the `.keep` file to be written to the quarantine directory and then looked for in the wrong place during cleanup.

The patch updates `index_pack_lockfile()` to take an explicit `struct odb_source *` parameter instead of a `struct repository *`, allowing callers to specify which ODB source the `.keep` file should be associated with. In `builtin/receive-pack.c`, the call is updated to pass the transaction’s source (the quarantine directory) for lockfile creation, ensuring the `.keep` file is written to the correct location and can be found and removed after the transaction commits. The test added in `t/t5547-push-quarantine.sh` verifies the fix by checking that the `.keep` file is present in the quarantine directory during the pre-receive phase, migrated to the main ODB during the reference transaction, and removed afterward.

The change is minimal and targeted, touching only the lockfile path derivation logic and its call sites. The new test provides clear coverage for the regression and its fix, addressing the last open question from the v4 review. This patch is a prerequisite for the rest of the series, which builds on the corrected lockfile lifecycle to introduce the generic `odb_transaction_write_pack()` interface. The fix is technically sound and aligns with the ODB abstraction effort’s goal of making backend-agnostic packfile handling robust.
