This is the fourth patch in Justin Tobler’s nine-patch v5 series making `git receive-pack` fully ODB-agnostic. It removes the global `receive_unpack_limit`, `transfer_unpack_limit`, and `unpack_limit` variables and replaces them with a new helper, `get_unpack_limit()`, that reads the configuration lazily inside `unpack()`. The helper checks `transfer.unpackLimit` first, then `receive.unpackLimit` (which takes precedence), defaulting to 100 if neither is set.

The patch is a straightforward refactoring that eliminates global state in preparation for the generic `odb_transaction_write_pack()` interface introduced later in the series. By moving the configuration lookup into `unpack()`, the decision of whether to explode a packfile becomes a backend-specific detail, aligning with the ODB abstraction effort. The change is mechanical and does not alter user-visible behavior. The diff touches only `builtin/receive-pack.c` and removes 19 lines while adding 11, making the codebase slightly smaller and more maintainable.

This patch directly addresses feedback from earlier iterations, where reviewers noted that the unpack limit resolution should be context-aware and not rely on global variables. The new `get_unpack_limit()` helper is designed to be reusable for `git fetch-pack` in future work, as it already takes a `struct repository *` parameter (though it currently hardcodes `the_repository` in the call site). The patch is well-motivated and fits cleanly into the series’ overall goal of making `git receive-pack` backend-agnostic.

No test changes are included here, but the existing test suite (particularly `t/t5547-push-quarantine.sh`) already covers the unpack limit logic, and the enhanced test in patch 9/9 verifies the ".keep" file migration that depends on this refactoring. The patch is technically sound and ready for merging as part of the broader ODB abstraction effort.
