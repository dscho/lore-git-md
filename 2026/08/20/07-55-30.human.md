This is the final patch in Patrick Steinhardt’s six-part series making Git’s packfile generation pluggable via the object database (ODB) layer. It completes the transport-layer refactoring by converting `git bundle` to use the new ODB interface, eliminating the last direct call to `git pack-objects` outside of repository maintenance tasks.

The patch replaces the manual `child_process` setup in `bundle.c` with a declarative `odb_generate_pack()` call, mirroring the changes already applied to `upload-pack.c` and `send-pack.c` in earlier patches. The `write_pack_data()` function now constructs an `odb_generate_pack_options` struct (with `thin=1`, `ofs_delta=1`, and the caller’s progress preference) and delegates pack generation to the ODB layer. The patch preserves all existing functionality: thin packs, delta-base offsets, filter specs for partial clones, and progress meters. The files-backend implementation translates these options into the same `git pack-objects` command-line arguments as before, ensuring behavioral continuity.

This is a clean refactoring with no user-visible changes. The commit message explains the motivation clearly: centralizing packfile generation in the ODB layer so that only maintenance commands like `git repack` retain direct knowledge of `git pack-objects`. The patch is well-scoped, touching only `builtin/bundle.c`, `bundle.c`, and `bundle.h`, and the diff is straightforward. Test coverage remains unchanged, as the patch does not alter behavior.

The series as a whole is now technically complete, though the unresolved `the_repository` issue in patch 5/6 remains a loose end. This patch itself is uncontroversial and looks ready for `next`.
