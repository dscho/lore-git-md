This is the second patch in Patrick Steinhardt’s v2 series refactoring how Git’s object database (ODB) handles corrupt objects. The patch introduces a formal `enum odb_read_status` to replace the previous bare `int` return values from the `read_object_info()` callback, distinguishing between successful reads (`ODB_READ_OK = 0`) and generic failures (`ODB_READ_ERROR = -1`). This is a preparatory step for later patches that will add a third state (`ODB_READ_NOT_FOUND`) to explicitly signal missing objects, improving error handling clarity.

Karthik Nayak’s review raises a minor but valid point: the patch relies on implicit conversion from `int` to `enum odb_read_status` in some places, rather than explicitly returning the enum values. While this doesn’t affect functionality, it could make the code slightly less readable. The review is surface-level but constructive, focusing on code clarity rather than behavior. No substantive issues are identified, and the patch remains a straightforward type-system cleanup.

The series as a whole is part of Patrick’s ongoing ODB abstraction effort, aiming to make error handling more consistent and backend-agnostic. This patch doesn’t change behavior yet—it just sets the stage for the more meaningful changes in later patches. The files touched are limited to the ODB subsystem (`odb.c`, `odb.h`, and the four `odb/source-*.c` backends), and the changes are mechanical. The commit message clearly explains the motivation, making it easy to follow the refactoring’s progression.

If you’re tracking the ODB abstraction work, this patch is worth noting as a foundational step, but it’s unlikely to be controversial or require deep review. The real substance comes in later patches, where the new enum will be used to distinguish between missing and corrupt objects. For now, this is a clean, incremental improvement.
