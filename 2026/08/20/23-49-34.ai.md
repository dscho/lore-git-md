This is the third patch in Justin Tobler’s nine-patch v5 series making `git receive-pack` fully ODB-agnostic by introducing the generic `odb_transaction_write_pack()` interface. The patch removes the global `alt_shallow_file` variable and lifts the setup of the temporary shallow file out of `unpack()` and `unpack_with_sideband()`, passing it explicitly through the call chain instead. This change is a prerequisite for moving the unpack logic behind the ODB transaction interface in a later patch, as the transaction system cannot rely on global state.

The patch touches only `builtin/receive-pack.c`, updating function signatures and wiring the shallow file through `unpack()`, `unpack_with_sideband()`, `prepare_shallow_update()`, and `update_shallow_info()`. The temporary shallow file is now created in `cmd_receive_pack()` and passed down as a `const char *`, eliminating the need for the global variable. The change is mechanical and does not alter user-visible behavior, but it is a key step in removing global state to enable pluggable ODB backends.

This patch directly addresses feedback from Junio’s v2 review, which identified the global `alt_shallow_file` as a blocker for the ODB abstraction. The fix is straightforward and aligns with the series’ broader goal of making `git receive-pack` backend-agnostic. The test coverage added in patch 9/9 (verifying ".keep" file migration) does not interact with this change, but the explicit shallow file handling here ensures the transaction system can safely manage shallow information without relying on globals.
