This is the fourth patch in Justin Tobler’s nine-patch v5 series making `git receive-pack` fully ODB-backend-agnostic. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and is now technically complete, with all reviewer feedback addressed in this iteration.

This patch removes the global `receive_unpack_limit`, `transfer_unpack_limit`, and `unpack_limit` variables from `builtin/receive-pack.c` and replaces them with a new helper, `get_unpack_limit()`, that reads the configuration lazily inside `unpack()`. The change is a straightforward refactoring: the unpack limit logic is unchanged, but it is now resolved at the point of use rather than during configuration parsing. The helper reads `transfer.unpackLimit` first, then `receive.unpackLimit` (with the latter taking precedence), matching the existing behavior.

The motivation is clear: the decision to explode a packfile into loose objects is a detail of how a specific ODB backend stores objects, not part of the generic ODB transaction interface. By moving the configuration resolution into `unpack()`, the patch prepares for the subsequent introduction of `odb_transaction_write_pack()`, which will delegate the unpack decision to the backend. The patch is small (30 lines changed) and mechanical, touching only `builtin/receive-pack.c`.

This is a well-motivated refactoring that aligns with the series’ goal of eliminating global state and making the unpack logic backend-agnostic. The commit message is concise and explains the "why" clearly. The patch is uncontroversial and ready for merging as part of the larger series.
