This is a review reply to the first patch in Karthik Nayak’s three-part series optimizing reftable stack reloads during transactions. The patch removes the `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag and makes stack reloading the default behavior in `reftable_stack_init_addition()`.

Patrick Steinhardt’s review notes that libgit2 also uses this flag, but all its calls to `reftable_stack_add()` already pass it, so adapting libgit2 should be straightforward. He then suggests a minor API cleanup: renaming the function from `reftable_stack_new_addition()` to `reftable_stack_addition_new()` to better match Git’s naming conventions. The suggestion is purely stylistic and does not affect the patch’s core optimization goal, but it would tidy up the interface while the function signature is already being modified. No objections or deeper technical concerns are raised; the feedback is surface-level and constructive.
