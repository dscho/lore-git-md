This is the final patch in D. Ben Knoble’s three-part series converting Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The series is now cooking in `next` under the topic `dk/use-nsec-runtime` and is effectively ready to graduate to `master` after the polish incorporated in this version.

The patch replaces the `#ifdef USE_NSEC` preprocessor logic with a runtime check controlled by the new `core.useNanosec` config key. The field is unconditionally added to `struct repo_config_values` but treated as false when `NO_NSEC` is defined, ensuring backward compatibility and eliminating any risk of uninitialized reads. The documentation for `core.useNanosec` now includes a direct warning about platform and filesystem limitations, and the Racy Git technical note has been updated to list filesystems known to support nanosecond precision (ext2, ext4, XFS, CEPH, CIFS, NTFS, UFS, FUSE, FAT).

The change touches ten files, removing the `USE_NSEC` build flag from `Makefile` and `configure.ac`, updating `read-cache.c` and `statinfo.c` to use the runtime value, and cleaning up related comments. The performance regression identified in the first iteration (~41× slowdown in `git diff` benchmarks) is fixed by caching the value in `repo_config_values`, and the code is now simpler and more maintainable. Junio and Patrick Steinhardt have both confirmed that the patch addresses their final polish requests, and the author has declined to add a runtime warning for `NO_NSEC` builds, aligning with the project’s preference for shared-configuration compatibility.

The patch is uncontroversial and ready to advance, though it will require trivial conflict resolution with `ty/repo-config-cleanups` in `seen` if both topics graduate. The only remaining loose ends are platform-dependent test coverage and the potential naming issue (`core.useNanosec` might be too specific if future platforms offer extended precision), but neither is blocking.
