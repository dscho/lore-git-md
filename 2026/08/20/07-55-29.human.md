This is the fifth patch in Patrick Steinhardt’s six-patch series making packfile generation pluggable as part of the ODB abstraction effort. This patch refactors `bundle.c` to eliminate most uses of the `the_repository` global, bringing it in line with the series’ goal of removing implicit repository dependencies.

The conversion is straightforward for most of the file, since all callers already pass a `struct repository *` parameter. The only exception is `get_log_output_encoding()`, which still implicitly depends on `the_repository`. To avoid reintroducing the global, Patrick adds an `extern` declaration for the function, effectively bypassing the compile-time guard (`USE_THE_REPOSITORY_VARIABLE`) that would otherwise prevent its use. This workaround is a known point of contention: Junio C Hamano objected to it in prior reviews as undermining the guard’s purpose, but Patrick has kept it for now, signaling openness to revisiting the approach.

The patch touches 21 lines in `bundle.c`, replacing direct references to `the_repository` and `the_hash_algo` with the repository pointer passed via `revs->repo`. It also updates `is_tag_in_date_range()` to take an explicit `struct repository *` parameter, mirroring the pattern used elsewhere in the series. The changes preserve all existing functionality, including bundle version checks, object filtering, and ref listing.

This patch is a prerequisite for the final patch in the series (6/6), which migrates `git bundle` to the new ODB interface. The remaining `the_repository` dependency in `get_log_output_encoding()` is the only loose end, and its resolution will likely depend on broader progress in the `the_repository` removal effort. The patch is well-motivated and clearly written, but the `extern` workaround may draw further discussion.
