This is the second patch in Justin Tobler’s nine-patch v4 series making `git receive-pack` fully backend-agnostic by extending the ODB transaction system. The patch introduces a `finalize` callback to the ODB transaction interface, splitting the commit step into two phases: `commit()` (which makes staged objects visible) and `finalize()` (which performs backend-specific cleanup). This change is necessary to enable the "files" backend to manage ".keep" lockfiles correctly in `git receive-pack`, ensuring they are removed after references are updated.

The patch is a well-motivated refactoring that addresses a clear technical need: decoupling transaction cleanup from object visibility. The commit message explains the rationale clearly, and the implementation is straightforward, introducing a new `finalize` callback to `struct odb_transaction` and updating callers to use either the split interface or the new `odb_transaction_commit_and_finalize_or_die()` helper. The changes are confined to `odb/transaction.c`, `odb/transaction.h`, and a handful of builtins (`add.c`, `receive-pack.c`, `unpack-objects.c`, etc.), with no user-visible behavior changes.
