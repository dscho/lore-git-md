This is the seventh patch in the fourteenth iteration of a feature series implementing `git history squash`, a new subcommand that folds a range of commits into their oldest ancestor in a single operation. The series is now technically complete and ready for integration, with all prior review feedback addressed.

This patch implements the core commit-creation logic for `--no-edit` mode, enabling the command to produce a squashed commit without opening an editor. It handles autosquash markers (`fixup!`, `squash!`, `amend!`), enforces strict rules about their targets, and preserves merge topology by retaining the full parent list of the original merge commit. The implementation walks the selected range in topological order, resolves marker targets using a subject-to-flags map, and constructs the squashed commit’s message by either preserving the oldest commit’s message or incorporating the last applicable `amend!` body. The patch also ensures reflog messages accurately record the full revision expression and maintains dry-run and `--update-refs` behavior.

Key behaviors are now finalized: the command rejects any `--no-edit` fold that would discard a `squash!` or `amend!` message unless the target is also in the range, and it refuses markers whose targets lie outside the selected commits. A range made entirely of related markers can still be consolidated, with the last `amend!` message supplying the final commit message. The patch touches `builtin/history.c` (adding 260+ lines), `object.h` (updating flag definitions), and the test script `t/t3455-history-squash.sh` (expanding coverage to 633+ lines). New helpers include `is_autosquash_subject`, `skip_one_autosquash_prefix`, `truncate_message_to_subject`, `squash_amend_message`, `squash_squash_message`, `squash_check_can_autosquash`, `squash_check_autosquash_subject`, and `squash_check_subject`.

The test suite now covers autosquash handling (including nested fixups and `amend!`/`squash!` interactions), merge commit folding (single-base, interior, and octopus merges), ref-handling edge cases (tags, remote-tracking refs, and branches pointing into the range at merges), and error conditions (external parents, root commits, and multiple tips). The patch also validates that descendant replay above the range works correctly and that `--update-refs=head` restricts updates to the current branch. All test cases are self-contained and use helper functions like `check_commit_author`, `check_log_subjects`, and `check_log_messages` to verify authorship, subject lines, and full commit messages.
