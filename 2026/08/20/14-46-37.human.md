This is a **test patch update** targeting the refname validation subsystem. The author, Nikolaus Schuetz, has revised the patch to address reviewer feedback from Patrick Steinhardt and Junio C Hamano. The core goal remains unchanged: adding test coverage for characters already documented as forbidden in refnames (space, `~`, `^`, `:`, `*`, `[`, `@`, and multi-byte sequences like `".."`) but not explicitly tested in embedded form.

The update adopts the suggested refactoring, replacing repetitive test cases with a loop over forbidden characters, including multi-byte sequences like `".."`. This improves test readability and maintainability without altering the patch’s purely additive nature—it still touches only `t/t1402-check-ref-format.sh` and introduces no new production code or behavior changes. The `@` edge case (rejecting `@` even with `--allow-onelevel`) is preserved as a separate test, as it doesn’t fit the loop pattern.

A minor inconsistency in test fixtures (`heads/` vs `refs/heads/`) was noted but left unchanged to match existing test patterns. Both reviewers endorsed the patch’s goal and treated their suggestions as non-blocking improvements, so this version looks ready for merging unless further refinements are requested. The patch is well-motivated, clearly explained, and aligns with the project’s emphasis on thorough test coverage.
