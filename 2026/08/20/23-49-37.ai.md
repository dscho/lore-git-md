This patch (6/9 in the v5 series) is a refactoring step in Justin Tobler’s ODB transaction work for `git receive-pack`. It converts the `unpack()` and `unpack_with_sideband()` functions from returning static error strings to writing error messages into a caller-provided `strbuf` and returning a negative value on failure. The call sites in `builtin/receive-pack.c` are updated to match: `execute_commands()` now takes an `int unpacker_error` flag instead of a string, and the `report()` and `report_v2()` functions now accept a `struct strbuf *` for the unpack status.

The change is purely mechanical and preparatory. It removes the last use of static error strings in the unpack path, aligning it with the ODB transaction system’s `strbuf`-based error reporting introduced in earlier patches. No behavior changes are visible to users; the patch simply shifts where the error message is stored. The motivation is to allow the unpack logic to move behind the generic `odb_transaction_write_pack()` interface in a later patch, which will need to propagate errors through the transaction system rather than returning them directly.

The patch touches only `builtin/receive-pack.c` and is straightforward: every `return "..."` becomes `strbuf_addstr(err_msg, "..."); return -1`, and callers now check the return value instead of comparing against `NULL`. The new `unpack_status` strbuf is initialized in `cmd_receive_pack()` and released at the end of the function. The series’ overall goal—making `git receive-pack` ODB-agnostic—remains on track, and this patch is a necessary plumbing change for that abstraction.
