This is a minor cleanup patch in Karthik Nayak’s three-part series optimizing reftable stack reloads during transactions. The patch removes the `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag from the reftable stack API, making stack reloading the default behavior in `reftable_stack_init_addition()`. The change is safe because all callers already pass the flag, and the manual reload in `reftable_stack_clean_locked()` was confirmed to be redundant.

The discussion here is purely about housekeeping. Patrick Steinhardt notes that libgit2 (a separate project) uses the flag but confirms compatibility since all libgit2 call sites already pass it. He suggests a cosmetic rename of `reftable_stack_new_addition()` to `reftable_stack_addition_new()` for naming consistency, which Karthik agrees to address in a follow-up commit. There are no objections to the patch’s substance, and the feedback does not introduce new technical concerns. The patch itself is uncontroversial and looks ready to proceed once the naming tweak is handled.
