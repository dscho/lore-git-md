This is the fourth iteration of a well-cooked patch series that converts Git’s build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The series is now effectively complete and ready to graduate from `next` to `master`; v4 addresses the last round of review feedback from Junio and Patrick Steinhardt.

The core change lets users enable nanosecond precision on supported filesystems without recompiling Git, reducing "racy Git" problems. The implementation caches the config value in the repository’s `repo_config_values` struct, avoiding the 41× performance regression that appeared in v1. On platforms lacking nanosecond support (`NO_NSEC` builds), the `use_nanosec` field is now safely ignored rather than `#ifdef`-ed out, and the documentation explicitly warns about platform limitations. The commit message and config docs have been tightened to clarify that the option may be silently ignored on unsupported platforms, and the `#ifndef NO_NSEC` guards in `is_racy_stat()` are simplified to a single ternary expression for readability.

Two small preparatory patches accompany the main change: a Meson build-system fix for relative manual links and a no-op refactor of `repo_config_values_init`. Both are uncontroversial and ready to advance independently. The series touches a dozen files but leaves the on-disk format unchanged. A minor textual conflict with `ty/repo-config-cleanups` in `seen` will need resolution if both topics move forward, but that is not blocking.

The author has addressed all substantive review points—performance, cross-platform correctness, initialization safety, and documentation clarity—without introducing new design questions. The remaining open items (testing strategy and the config key’s name) are noted but not blocking. This looks like a clean, well-motivated improvement that should land soon.
