This is the fourth patch in Patrick Steinhardt’s six-patch v3 series making Git’s packfile generation pluggable. It is a refactoring patch targeting the `git bundle` command’s progress-meter option handling.

The patch simplifies `git bundle`’s command-line interface by consolidating four related options (`--quiet`, `--progress`, `--all-progress`, and `--all-progress-implied`) into a single boolean flag. The first three options all control whether progress is displayed, while `--all-progress-implied` is a no-op that is passed unconditionally to `git pack-objects`. The refactoring replaces the manual `strvec` construction with a cleaner `OPT_BIT`/`OPT_NEGBIT` pattern, making the code more maintainable and preparing it for the upcoming migration to the ODB interface in patch 6/6.

The change is straightforward and well-motivated: it reduces interface complexity without altering behavior. The commit message clearly explains the rationale and the mapping from old to new options. This patch is a small but necessary step in the larger ODB abstraction effort, and it looks like a clean, uncontroversial refactor.
