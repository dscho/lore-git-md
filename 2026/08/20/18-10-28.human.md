This is the fourth patch in the v14 series introducing `git history squash`, a new subcommand that folds a range of commits into their oldest ancestor. The series is now technically complete and ready for integration, with all prior feedback addressed.

This patch establishes the revision input contract for `git history squash`. It adds the subcommand’s entry point, option parsing, and argument handling, ensuring the command accepts revision ranges and `rev-list` options while enforcing the specific traversal settings required for the fold operation. The implementation requires at least one *excluded* revision (the "bottom" of the range) to ensure the squashed commit has a valid base to reparent onto. If users supply options that would alter the traversal (e.g., `--boundary`), the command issues a warning and resets the settings to their required values.

The patch is deliberately minimal: it defines only the input contract, leaving graph validation and the actual rewrite logic to later patches. This decomposition was explicitly requested in earlier reviews and keeps the series reviewable in focused steps. The new `setup_squash_revisions()` helper centralizes the revision setup logic, making it reusable and testable. The command’s usage string and help text are also added here, documenting the `--dry-run`, `--update-refs`, and `--[no-]edit` options upfront.

This is a well-structured, uncontroversial step in a series that has already resolved all substantive feedback. The patch itself is straightforward and aligns with the project’s preference for incremental, self-contained changes.
