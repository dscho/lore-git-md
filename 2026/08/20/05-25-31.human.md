This is a bug report about `git request-pull`.

A user reports that `git request-pull` incorrectly warns that a commit does not exist in the remote repository when the `<ref>` argument is given as a raw commit hash (e.g., `5a12652e`) rather than a ref name (e.g., `main`). The warning appears even when the commit is verifiably present in the remote. The behavior is reproducible with Git 2.43.0.

The report is clear and includes a concrete example, but it does not include a patch or a proposed fix. The issue seems minor but could confuse users who prefer to use commit hashes directly. No prior discussion or related patches are mentioned in the email.
