This is a follow-up in the `git history fixup` worktree corruption bug report. Patrick Steinhardt, the author of the original `git history` command, weighs in to endorse the safer approach: `git history fixup` should refuse to rewrite branches that are checked out in other worktrees, mirroring the behavior of `git rebase --update-refs`. He has opened a GitLab issue (#772) to track this for the next release cycle but welcomes a community patch in the meantime.

The thread has now converged on the conservative solution (option 1 from earlier discussion), which avoids the complexity and potential edge cases of attempting "best-effort" index updates in other worktrees. No patch has been posted yet, but the design decision is settled. The remaining work involves implementing the safety check (likely reusing logic from `git rebase`) and adding regression tests to both the `git history` and worktree test suites. The issue remains a clear bugfix targeting the worktree subsystem, with `builtin/history.c` and `worktree.c` as the primary files involved.
