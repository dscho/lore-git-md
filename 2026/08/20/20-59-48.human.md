Patrick pushes back, calling the change “mostly pointless” — the return convention is already established, and all callers already return the expected values. Karthik concedes the point but notes that mixing raw integers and named constants could eventually lead to inconsistency. The exchange leaves the code unchanged, but it surfaces a stylistic tension: Patrick values brevity and established convention, while Karthik (and likely others) would prefer explicit, self-documenting returns.

The thread is part of a larger, well-structured effort to make object corruption handling consistent and backend-agnostic. This particular patch is small and mechanical, but the unresolved hygiene question hints at a broader pattern: as the ODB abstraction grows, so does the risk of subtle misuse. The discussion is worth noting not because it blocks the series, but because it flags a recurring trade-off between conciseness and clarity in a subsystem that touches nearly every part of Git.
