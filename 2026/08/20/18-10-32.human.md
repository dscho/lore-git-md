This is the final patch in Harald Nordgren’s v14 series introducing `git history squash`, a new subcommand that folds a range of commits into their oldest ancestor in a single operation. The series is now complete and ready for integration, with all prior feedback addressed.

This patch implements the default message-editing workflow, opening an editor pre-filled with an autosquash-style template that matches `git rebase -i --autosquash`. The template groups `fixup!`, `squash!`, and `amend!` commits under their targets, comments out `fixup!` messages, retains `squash!` bodies, and lets `amend!` replace its target unless a preceding `squash!` requires both bodies. The `--no-edit` flag skips the editor, preserving the oldest commit’s message or using the last `amend!` targeting it. The implementation reuses the sequencer’s `todo_list_rearrange_squash` machinery to rearrange the selected commits and build the template, ensuring consistency with interactive rebase.

The patch touches `builtin/history.c` (adding the `build_squash_message` helper and wiring up the editor), updates `Documentation/git-history.adoc` to document the new behavior, and expands the test suite (`t/t3455-history-squash.sh`) with 203 lines of coverage for editor workflows, empty-message aborts, marker handling, and template formatting. The tests verify that the template matches rebase’s autosquash output and that the command aborts cleanly if the user clears the message.

This is a well-crafted, thoroughly reviewed feature that addresses a real workflow gap: collapsing a range of commits without the repeated conflict stops of a rebase-based approach. The series has been marked "Will replace" by Junio Hamano, signaling intent to merge, and all procedural and technical feedback has been resolved in v14. The command is positioned as a foundational piece for future integration with `git rebase --autosquash` via `git replay`.
