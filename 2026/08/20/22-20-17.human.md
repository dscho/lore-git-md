This is a test patch that fills a small but clear gap in Git’s refname validation coverage. The patch adds test cases for characters already documented as forbidden in refnames—space, tilde (`~`), caret (`^`), colon (`:`), asterisk (`*`), open-bracket (`[`), backslash, and the sequence `".."`—but which were not explicitly tested when embedded in an otherwise valid refname. It also verifies that the single-character `@` refname is rejected even when `--allow-onelevel` is passed, a subtle edge case that could otherwise slip through.

The changes are confined to `t/t1402-check-ref-format.sh` and are purely additive. The v2 update adopts the reviewers’ suggestion to replace repetitive `invalid_ref` checks with a loop, making the test more concise and maintainable. No production code is touched, and the patch does not alter behavior—it merely documents existing rules more thoroughly.

Review discussion has converged: both Patrick Steinhardt and Junio C Hamano endorsed the approach, and the fixture inconsistency (`heads/` vs `refs/heads/`) was explained as inherited and harmless. The patch looks ready for `next`.
