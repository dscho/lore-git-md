This is the fifth iteration (v5) of Justin Tobler’s nine-patch series making `git receive-pack` fully ODB-backend-agnostic by introducing the generic `odb_transaction_write_pack()` interface. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and is now technically complete, addressing all substantive feedback from v4.

The core goal remains unchanged: replace `git receive-pack`'s hardcoded use of `git index-pack` and `git unpack-objects` (which assume the "files" backend) with a backend-agnostic transaction interface, enabling alternative ODB backends (e.g., reftable, cloud storage) to handle incoming packfiles. This iteration adds the final test assertion Patrick Steinhardt requested in v4, verifying that the `.keep` lockfile is correctly migrated to the main ODB during the reference update phase and removed afterward. The test now uses a `reference-transaction` hook to check for the file’s presence and cleanup, closing the last open design question from the previous round.

Changes since v4 are minimal and focused on completeness. The first patch’s test now includes the missing assertion to validate `.keep` file migration, and the second patch’s commit message has been reworded for clarity (as suggested by Patrick Steinhardt) to better explain the motivation for `odb_transaction_commit_and_finalize_or_die()`. No technical changes were needed; the series was already functionally sound in v4.

The patches touch `builtin/receive-pack.c`, `odb/transaction.c`, `object-file.c`, and related headers, with mechanical updates to other builtins for transaction API consistency. The new `odb_transaction_write_pack()` interface moves packfile ingestion logic into the "files" ODB backend, replacing the hardcoded `unpack()` function with a backend-agnostic callback. The transaction lifecycle is now robust, with explicit error handling and proper cleanup of `.keep` lockfiles during finalization. The unpack limit is resolved lazily in the backend via `get_unpack_limit()`, which now takes an `enum odb_transaction_flags` parameter to differentiate between `git receive-pack` (`ODB_TRANSACTION_RECEIVE`) and future `git fetch-pack` users.

This iteration looks ready for `next`. All critical design flaws have been addressed, the interface is stable, and the test coverage is now complete. The series is a significant step toward making `git receive-pack` fully ODB-agnostic, aligning with the broader ODB abstraction effort.
