This is a **bugfix** for Git's HTTP authentication layer, addressing a regression where `WWW-Authenticate` headers are lost during HTTP redirects. The patch (v2) is a reply in an ongoing thread, with Junio C Hamano providing context for reviewers by linking to the v1 submission.

The core issue remains unchanged: when Git follows an HTTP redirect, the `credential_from_url()` call in `http_request_recoverable()` clears the `wwwauth_headers` field, breaking authentication for redirect targets that rely on credential helpers (e.g., OAuth2 Bearer tokens). The v2 iteration refines the solution by introducing `credential_update_url()`, a reusable helper in `credential.c` that preserves `wwwauth_headers` across URL updates using `SWAP()` for efficiency. This approach centralizes the preservation logic, making it available for future credential fields that may need similar treatment.

The patch touches two subsystems: `http.c` (updated to use `credential_update_url()`) and `credential.c` (where the new helper is defined). Test coverage is thorough, with a new test in `t/t5563-simple-http-auth.sh` verifying that `wwwauth_headers` survive redirects. The test uses a custom Apache rewrite rule (`/custom_auth_redir/`) to simulate a redirect to a bearer-auth-protected endpoint, checking both the credential query (with preserved headers) and subsequent credential storage.

The patch itself is uncontroversial, with no open questions or objections raised in the thread so far. The changes are minimal, focused, and well-motivated, addressing a real-world issue without introducing new edge cases. The use of `SWAP()` to avoid copying the `strvec` is a pragmatic optimization, and the commit message clearly explains the problem and solution.
