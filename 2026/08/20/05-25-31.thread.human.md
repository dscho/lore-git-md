This thread is a bug report from Gahtan Nahdi about a false warning in `git request-pull`. When the `<ref>` argument is provided as a commit hash (e.g., `5a12652e`) instead of a ref name like a branch or tag, Git incorrectly warns that the target commit (`1ccb9f6e` in the example) does not exist in the remote repository—even though it does. The issue is reproducible and specific to using commit hashes; ref names work as expected.

The report is clear and includes a reproduction case, but it doesn’t specify whether this is a regression or a long-standing issue, nor does it explore the root cause (e.g., whether the problem lies in how `git request-pull` resolves hashes or queries remotes). The false warning could mislead users into thinking their commits are missing, potentially causing unnecessary debugging. So far, there’s no discussion or patch attached, and the scope is limited to `git request-pull`’s behavior. It’s also unclear whether the issue affects all remote types (GitHub, GitLab, local repos) or only specific ones.
