This is the first patch in the v14 iteration of Harald Nordgren’s `git history squash` series, a refactoring that extracts a small helper function to reduce code duplication.

The patch introduces `first_parent_tree_oid()`, a helper that resolves the tree OID of a commit’s first parent (or the empty tree for a root commit). It consolidates three existing code paths in `builtin/history.c` that each performed the same parse-and-copy dance: one in `commit_tree_with_edited_message()`, one in `commit_became_empty()`, and one in `split_commit()`. The new helper is straightforward—it checks for a parent, parses it if present, and copies the tree OID into the caller-provided buffer—so the change is purely mechanical and does not alter behavior.

This is a classic cleanup patch: it touches only one file, removes 32 lines of duplicated logic, and leaves the rest of the series untouched. The commit message is clear and the diff is easy to verify. There is nothing controversial here; it is a routine refactoring that prepares the ground for the feature patches that follow.
