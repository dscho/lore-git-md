Subject: [PATCH v2] http: preserve WWW-Authenticate headers on redirect
Series version: v2 (root email is v1)
Originating author: Aaron Plattner <aplattner@nvidia.com>
Thread type: bugfix patch series

Core problem or goal
Git's HTTP layer loses `WWW-Authenticate` headers from an HTTP redirect response when updating the credential struct for the new URL. This breaks authentication when the redirect target requires a credential helper (e.g., OAuth2 Bearer tokens) rather than URL-embedded credentials.

Current status
Under review; v2 posted. Changes from v1: moved preservation logic into `credential.c` as a reusable `credential_update_url()` helper, making it available for future credential fields that may need similar treatment. Junio C Hamano linked to the v1 submission for context, confirming the patch remains uncontroversial.

Key technical details
- New symbol: `credential_update_url()` in `credential.c` (wraps `credential_from_url()` but preserves `wwwauth_headers` via `SWAP()`).
- Modified subsystem: `http.c` (now uses `credential_update_url()` when recovering from redirects).
- On-disk format: unchanged.
- Test coverage: new test in `t/t5563-simple-http-auth.sh` verifies `wwwauth_headers` preservation after redirect, using a custom Apache rewrite rule (`/custom_auth_redir/`) that redirects to a bearer-auth-protected endpoint.

Open questions and loose ends
None identified; the patch is uncontroversial and addresses the regression without introducing new edge cases.
