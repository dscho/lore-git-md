This is a **substantive follow-up** in the ongoing discussion about Elijah Newren’s bugfix for a race condition in Git’s geometric repacking mechanism. The email is from Patrick Steinhardt, responding to Jeff King’s (Peff) architectural critique of patch 2/2 in the series.

Patrick clarifies the core issue: when an object exists in multiple packs covered by a multi-pack-index (MIDX) and the *preferred* pack (the one the MIDX would normally use) is removed, the current code fails to find the object in the remaining packs. This happens because the non-MIDX lookup skips *all* packs covered by the MIDX, not just the missing one. The result is a false negative that affects *all* object lookups, not just those using `OBJECT_INFO_QUICK`. This narrows the scope of Peff’s critique, which had focused on whether `QUICK` callers should handle false negatives themselves.

Patrick also suggests an alternative fix: instead of rescanning *all* packs covered by the MIDX (as Elijah’s patch does), the code could skip only the missing pack and search the remaining MIDX-covered packs. This approach aligns with Peff’s proposal to use a tri-state return value from `fill_midx_entry()` to distinguish between (1) the object not being in the MIDX, (2) the object being in the MIDX but unavailable, and (3) the object being available. The key insight is that the bug only occurs in case (2), so the recovery logic could be more targeted.

The email does not resolve the architectural debate but reframes it. The discussion is now focused on whether the fix should be implemented in the packed-object backend (Elijah’s approach), as a tri-state return value (Peff’s suggestion), or as a hybrid (Patrick’s middle-ground proposal). The series remains a high-priority candidate for merging, but the outcome of this discussion may require revisions to patch 2/2. Elijah has not yet responded to this latest exchange.
