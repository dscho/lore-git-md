This is a substantive review reply in the ongoing thread about the `git symbolic-ref` test coverage patch. Patrick Steinhardt restates his skepticism about the intentionality of the differing exit codes (128 vs. 1) when `git symbolic-ref` encounters a non-symbolic ref with and without `--quiet`. He argues that the current behavior—where the non-quiet path uses `die()` (returning 128) and the quiet path uses `exit(1)`—likely reflects an oversight rather than a deliberate design choice, and suggests that codifying this behavior in tests "feels wrong."

Patrick proposes two alternatives: either avoid testing the exact exit codes (continuing to rely on the existing implicit coverage in other tests), or align the exit codes by changing the quiet path to use `die(NULL)` instead of `exit(1)`. His preference leans toward the latter, which would standardize the exit code to 128 in both cases while preserving the `--quiet` flag's effect on output suppression. The review is technical and focused on the design rationale, not the patch's implementation or test style. No new tests or code changes are suggested—just a reconsideration of the underlying behavior the patch aims to document.
