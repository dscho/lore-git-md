This is a design clarification in an ongoing discussion about Git’s `--ext-diff` option and its default behavior.

Junio C Hamano, the maintainer and original author of the `--ext-diff` feature, weighs in to endorse Jeff King’s explanation. He agrees that `textconv` (a more constrained mechanism for converting binary files to text for diffing) is generally a better fit for most use cases, as it integrates more smoothly with Git’s commands and avoids the disruptive side effects of external diff drivers. Junio’s only personal use case for `--ext-diff` is maintaining the "What's cooking" reports, and he suggests even that could likely be replaced with a combination of `textconv`, diff hunk header patterns, and the `-W` (function context) option.

The reply reinforces the idea that the current behavior—where external diffs are enabled by default in some commands (`git diff`, `git log -p`) but not others (`git show`, `git stash show -p`)—is not a deliberate security or performance trade-off, but rather an artifact of how the feature evolved. Neither Junio nor Peff proposes any code changes, but their comments imply that the distinction could be revisited if there is sufficient demand or a compelling use case. For now, the thread remains a user inquiry rather than a patch or RFC.
