This is the final exchange in the thread improving error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The main series (v7) has already been merged to `next`, but Yoichi Nakayama now signals intent to address a latent bug Junio C Hamano identified in the one-argument form of `git worktree add` (e.g., `git worktree add ../topic-branch`).

The bug stems from an incomplete 2018 refactoring: when multiple remotes contain the same branch name, the command silently creates a local branch from HEAD instead of erroring out. Junio’s analysis traces the issue to commits 3c87aa946a and 8d7b558bae, which improved `git checkout` but left `git worktree add` unable to distinguish between zero and multiple matches. Yoichi agrees the correct behavior is to treat ambiguity as an error and plans to send a follow-up patch.

This is a clean #leftoverbits item—small, well-scoped, and uncontroversial. The fix will touch `builtin/worktree.c` and likely reuse the `unique_tracking_name()` helper extended in the original series. No objections are expected; the discussion is purely about timing and completeness.
