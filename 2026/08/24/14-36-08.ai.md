This is a **substantive follow-up discussion** in the thread about the Windows-specific ODB deadlock fix in the sequencer. Junio C Hamano responds to Phillip Wood’s forward-looking questions, providing historical context and endorsing one of the proposed directions for future work.

Junio notes that the idea of disabling `gc.auto` during rebase is not new: an old discussion from 2007 (around the constant 6700, which governed auto-gc thresholds) already observed that since `git commit` triggers auto-gc, there is little point in running it again at the end of `git rebase`. While he agrees that for small projects and short rebases, a single gc at the end should suffice, he cautions that Git’s widespread use means this assumption may not hold universally. The tone is neutral, neither endorsing nor rejecting the idea outright, but acknowledging its plausibility.

On Phillip’s second suggestion — automatically closing the ODB whenever any Git command is spawned — Junio is more enthusiastic. He calls it a "great approach to study" and highlights the long-term benefit: avoiding the need to sprinkle one-off fixes like the current patch across many code paths. This endorsement positions the idea as a promising direction for future refactoring, though no immediate action is implied.
