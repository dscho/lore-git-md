This is the final patch in a three-patch feature series adding `--[no-]range-diff-notes` options to `git format-patch`. The patch implements the core functionality, allowing users to control whether Git notes appear in the range-diff section independently of their appearance in the patch output itself.

The implementation adds two new command-line options: `--range-diff-notes[=<ref>]` and `--no-range-diff-notes`. These options let users specify which notes (if any) should appear in the range-diff portion of `format-patch` output, while leaving the notes displayed in the patches themselves unchanged. The patch introduces a new `rdiff_override_notes` flag in `struct rev_info` to track whether the user has explicitly set range-diff notes behavior, and modifies `get_notes_args()` to respect this override.

The commit message explains the motivation clearly: users often add iteration notes (e.g., "v3: [description]") that document changes between patch series versions, but these notes are irrelevant or distracting when included in the range-diff. The implementation handles edge cases like toggling the override off after it has been set, and supports specifying particular notes refs for the range-diff (e.g., `--range-diff-notes=testing`).

The patch touches `revision.c` (option parsing), `revision.h` (new struct member), `builtin/log.c` (notes argument handling), and adds comprehensive test coverage in `t/t3206-range-diff.sh`. The tests verify scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and toggling the override on and off. The implementation is careful to maintain consistency with existing `--notes` behavior while adding the new functionality.
