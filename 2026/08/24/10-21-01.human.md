This is the final patch in Karthik Nayak’s three-part series introducing the new `report` hook for `git-receive-pack`. The hook is now fully implemented with all prior feedback incorporated, and this patch is ready for integration.

The `report` hook lets server administrators intercept and modify the status report sent to clients after all ref updates are committed but before the client receives confirmation. GitLab’s MVCC (multi-version concurrency control) system is the driving use case: the hook allows the server to report the repository state *after* external post-update operations succeed, rather than at the moment the ref transaction commits. The hook receives the complete pkt-line encoded status report on stdin, replaces it with its stdout, and forwards stderr to the client via the sideband channel. Exit semantics follow the agreed consensus: a non-zero exit rewrites all ref status lines to `"report hook failed"` and allows `receive-pack` to exit cleanly, matching the behavior of the existing `pre-receive` hook.

The implementation touches `builtin/receive-pack.c` (adding the hook runner and plumbing it into the status-report generation), `Documentation/githooks.adoc` and `git-receive-pack.adoc` (documenting the hook’s purpose, protocol, and exit semantics), and introduces a new test script `t/t5412-report-hook.sh` that covers passthrough, failure modes, stdin/stdout handling, sideband relay, and the interaction between exit status and stderr output. The hook deliberately avoids the config-based multi-script infrastructure to keep the bidirectional filter simple and consistent with the existing `proc-receive` hook.

All prior review feedback has been addressed: the exit status semantics are settled, the pkt-line format documentation links to `gitprotocol-pack[5]`, and the series is now split into three logical commits (documentation, refactoring, core implementation). The patch is well-motivated, thoroughly tested, and carries Reviewed-by/Acked-by from the key reviewers. Expect it to land in `next` shortly.
