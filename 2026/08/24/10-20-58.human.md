This is a feature patch introducing the new `report` hook for `git-receive-pack`, now split into a three-patch series for v3. The series addresses all prior feedback, most notably the exit status semantics: instead of treating a non-zero exit as a "nuclear option" that discards stdout and kills `receive-pack`, the hook now rewrites all ref status lines to `"report hook failed"` and allows the push to complete with a clean exit. This aligns with the `pre-receive` hook’s behavior and resolves the last substantive design question.

The series is well-structured: the first patch adds documentation for the existing `proc-receive` hook to `git-receive-pack.adoc` (a previously missing piece), the second refactors the status report generation into a reusable function, and the third introduces the `report` hook itself. The implementation is clean, the commit messages are thorough, and the test coverage exercises all key behaviors (passthrough, failure modes, stdin/stdout handling, and sideband relay). The documentation now links to `gitprotocol-pack[5]` for protocol details, resolving the earlier ambiguity about where to document the pkt-line format.

This is a mature, well-motivated feature that fills a real gap in Git’s server-side extensibility. The use case (GitLab’s MVCC system) is concrete and documented, and the design avoids config-based hooks for sound technical reasons. The series is ready for final review and likely to be merged once Junio confirms the exit status change is acceptable.
