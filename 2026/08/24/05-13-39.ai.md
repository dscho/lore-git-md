This is a **substantive reply** in the ongoing design discussion about Elijah Newren’s patch 2/2, which fixes a race condition in Git’s packed-object backend when a multi-pack-index (MIDX) references a removed packfile. Patrick Steinhardt clarifies a key technical point in response to Jeff King’s (Peff) critique, reinforcing the necessity of the fix while acknowledging Peff’s broader concerns about `OBJECT_INFO_QUICK`.

Patrick agrees with Peff that `OBJECT_INFO_QUICK` is working as designed and that callers using it must tolerate false negatives. However, he identifies a separate, more fundamental bug: when an object exists in *multiple* packs covered by a MIDX and the *preferred* pack (the one the MIDX would normally use) is removed, the current code fails to find the object even in the remaining packs. This happens because the non-MIDX lookup skips all packs covered by the MIDX, and the MIDX lookup fails when the preferred pack is missing. The result is a false negative *regardless* of whether `QUICK` is used, breaking even callers that do not rely on performance trade-offs.

The email narrows the scope of the disagreement: Peff’s critique focused on whether `QUICK` callers should handle false negatives themselves, but Patrick’s response shows the fix addresses a broader correctness issue that affects *all* object lookups, not just those using `QUICK`. This distinction may help resolve the design tension by separating the architectural question (how to handle `QUICK`) from the immediate bug (objects disappearing from the MIDX). The fix’s recovery logic—scanning all packs covered by the MIDX when the preferred pack is missing—remains necessary for correctness, though the discussion about `QUICK` and caller responsibility may still influence future work. No code changes are proposed here, but the clarification strengthens the case for merging the patch as-is.
