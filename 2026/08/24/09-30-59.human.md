This is a refactoring patch targeting the reftable backend, part of the ongoing work to optimize and simplify the reftable stack implementation. It is the first patch in a four-part series (`[PATCH v2 1/4]`).

The patch removes the `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag, which was introduced in 2024 to allow callers of `reftable_stack_init_addition()` to reload the stack if a concurrent update occurred before locking. A subsequent commit in 2025 made this flag mandatory for all call sites, meaning the reload behavior is now the default. The patch eliminates the flag and its associated conditional logic, simplifying the code by making stack reloading automatic whenever the stack is outdated. The commit message explains that this change makes the control flow easier to follow and removes redundant checks for `REFTABLE_OUTDATED_ERROR`.

The patch touches the core reftable stack logic (`reftable/stack.c`), the backend interface (`refs/reftable-backend.c`), the public API header (`reftable/reftable-stack.h`), and unit tests (`t/unit-tests/u-reftable-stack.c`). The unit tests are updated to reflect the new default behavior, and the manual reload in `reftable_stack_clean()` is removed since it is now handled automatically.

The change appears well-motivated and mechanically sound: the flag was introduced as an opt-in, then made mandatory, so removing it now is a natural cleanup. The commit message clearly explains the history and the exceptions (unit tests and `reftable_stack_clean()`), and the diff is focused and easy to review. This looks like a straightforward improvement that reduces complexity without changing behavior.
