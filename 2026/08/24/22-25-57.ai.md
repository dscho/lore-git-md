This is a follow-up discussion to the recently merged series improving error messages for ambiguous remote branch names in `git worktree add`, `git checkout`, and `git switch`. The thread picks up a latent bug identified by Junio C Hamano in the one-argument form of `git worktree add` (e.g., `git worktree add ../topic-branch`).

The current behavior creates a local branch from HEAD when the branch name matches multiple remote tracking branches, treating it the same as if no match existed. Junio argues this is a bug, tracing it to an incomplete refactoring in 2018 (commits 3c87aa946a and 8d7b558bae) that improved `git checkout` but left `git worktree add` unable to distinguish between zero and multiple matches. The original series intentionally left this edge case untouched, as the command succeeds in this scenario, but Junio now suggests it should error out when ambiguity exists.

Yoichi Nakayama agrees with the analysis and proposes to implement the fix in a follow-up commit. The discussion is framed as a #leftoverbits item—documenting a known issue for future resolution rather than blocking the current work. Key technical details for follow-up include the `unique_tracking_name()` function in `builtin/worktree.c` and the historical commits that introduced the incomplete refactoring. The tone is collaborative and forward-looking, with no controversy or open questions remaining. This is a clear, well-motivated plan for a targeted bugfix.
