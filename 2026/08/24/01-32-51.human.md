This is a clarification from Junio C Hamano in the thread about Delilah Ashley Wu’s three-patch series fixing the `--global` config listing inconsistency. The series, now technically complete and reviewed, addresses the discrepancy where `git config list --global` only showed `$HOME/.gitconfig` while Git actually reads both that and `$XDG_CONFIG_HOME/git/config`.

Junio confirms that Git’s original design for reading per-user configuration from both files was intentional, aimed at easing migration from `~/.gitconfig` to the XDG layout without disrupting users who chose not to migrate. For writing, however, the behavior was deliberately different: `git config --global --edit` (and `set`) writes only to `~/.gitconfig` to avoid duplication and because most users at the time had their config there. He emphasizes that the read-side inconsistency the series fixes was not a deliberate choice but a bug—an oversight in how `--global` was implemented compared to the general config-reading sequence.

The reply does not alter the series’ direction but provides historical context and reinforces that the fix aligns with the project’s original intent. It also implicitly answers Chris Torek’s question: `git config --global --edit` currently edits `~/.gitconfig` and should continue to do so, as the write path was designed to avoid writing to multiple files. No further changes are suggested, and the series remains ready for integration.
