This is the third and final patch in Karthik Nayak’s v3 series introducing the `report` hook for `git-receive-pack`. It implements the core hook logic whose design and exit semantics were settled in earlier rounds.

The patch adds the new `report` hook, which runs after all ref updates are committed but before the status report is sent to the client. The hook receives the pkt-line encoded report on stdin and replaces it with its stdout; stderr is forwarded to the client via the sideband channel. A zero exit code means the hook’s stdout is used as the report; a non-zero exit rewrites all ref status lines to “report hook failed” and discards the hook’s stdout, matching the behavior of the `pre-receive` hook. The implementation is self-contained: it does not use the config-based hook infrastructure (to avoid piping multiple scripts), and it does not roll back already-committed ref updates. The patch touches `builtin/receive-pack.c`, adds documentation in `githooks.adoc` and `git-receive-pack.adoc`, and includes a new test script (`t/t5412-report-hook.sh`) that verifies passthrough, failure modes, stdin/stdout handling, and sideband relay.

All prior feedback has been addressed: the exit semantics align with Junio and Patrick’s proposal, the pkt-line format documentation links to `gitprotocol-pack[5]`, and the preparatory documentation and refactoring patches are already in place. The series is now effectively complete and ready for integration.
