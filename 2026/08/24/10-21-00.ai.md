This is the refactoring patch (2/3) in Karthik Nayak’s `report` hook series. It extracts the message-generation logic from `report()` and `report_v2()` into a shared helper, `generate_response()`, so that the upcoming hook implementation can reuse it when rewriting the status report on hook failure.

The patch is mechanical: it moves the pkt-line formatting loops into the new function, adds a boolean parameter to control whether v2-specific reports are included, and updates the callers to pass a pre-allocated `strbuf`. No behavior changes; the diff is purely structural. The commit message explains the motivation clearly—preparing for the next patch, which will need to regenerate the message during hook failure—and the code is cleanly split along protocol-version lines. This is a textbook refactoring that should be uncontroversial and ready for `next`.
