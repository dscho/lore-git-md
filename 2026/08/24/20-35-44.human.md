This is the final patch in Kristoffer Haugsbakk’s three-part series adding `--[no-]range-diff-notes` options to `git format-patch`. It implements the core functionality that motivated the series: independent control over whether notes appear in the range-diff section versus the patches themselves.

The patch introduces two new options, `--range-diff-notes[=<ref>]` and `--no-range-diff-notes`, that let users specify which notes (if any) should appear in the range-diff output. The default behavior remains unchanged: range-diffs inherit the same notes settings as the patches. The implementation is careful to handle edge cases, such as toggling the override on and off (`--no-range-diff-notes --range-diff-notes` restores the default behavior) and supporting multiple notes refs (e.g., `--notes=patch --range-diff-notes=rdiff`).

The code touches `revision.c` (option parsing), `revision.h` (new `rdiff_override_notes` flag), `builtin/log.c` (notes argument construction), and adds comprehensive tests in `t/t3206-range-diff.sh`. The documentation update in `git-format-patch.adoc` clearly explains the new options and their interaction with existing `--notes` behavior.
