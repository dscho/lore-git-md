This is a **substantive follow-up** in the design discussion about Elijah Newren’s patch 2/2, which fixes a race condition in Git’s packed-object backend when a multi-pack-index (MIDX) references a removed packfile. Jeff King (Peff) acknowledges Patrick Steinhardt’s clarification that the patch addresses a broader correctness issue affecting *all* object lookups, not just those using `OBJECT_INFO_QUICK`. Peff now accepts the necessity of the fix but raises a **performance concern** about the current implementation: when an object is missing from the MIDX’s preferred pack, the fallback logic scans *all* packs covered by the MIDX, which could be prohibitively expensive if the MIDX spans many packs (e.g., a million).

Peff suggests that the fallback should only trigger when `SECOND_READ` (the flag indicating a retry after a refresh) is *not* set, arguing that `QUICK` callers are already prepared to tolerate false negatives and should not incur the cost of a full MIDX pack scan. However, he concedes this is mostly an academic concern, as the fallback is only invoked when the MIDX *should* have found the object (due to the `bsearch()` check), meaning the scan is likely to succeed. The discussion remains focused on refining the fix’s implementation rather than questioning its correctness, and no code changes are proposed here. The key takeaway is that the fix’s recovery logic is now widely accepted as necessary, but its performance implications may still influence the final design.
