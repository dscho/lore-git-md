This is a brief follow-up in the ongoing discussion about the Windows-specific deadlock fix in the sequencer. Junio C Hamano responds to Phillip Wood’s forward-looking questions with a mix of historical context and cautious encouragement.

Junio notes that the idea of disabling `gc.auto` during rebase is not new: an old discussion from 2007 already observed that since `git commit` triggers auto-gc, there is little point in running it again at the end of `git rebase`. He acknowledges that for small projects and short rebases, Phillip’s suggestion makes sense, but cautions that Git’s widespread use means the trade-off may not hold universally.

On Phillip’s second idea — automatically closing the object database whenever any Git command is spawned — Junio is more positive. He calls it a "great approach to study" and suggests it could eliminate the need to sprinkle one-off fixes like the current patch across many code paths. The tone is exploratory, not prescriptive: Junio is signaling openness to the idea, not committing to it. No new technical details or objections are raised; this is a conceptual nod to future work.
