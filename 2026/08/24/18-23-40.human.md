This is a review discussion about a test coverage patch for `git symbolic-ref`. Junio C Hamano weighs in on the ongoing debate about whether the differing exit codes (128 without `--quiet`, 1 with `--quiet`) when querying a non-symbolic ref are intentional or an oversight. He agrees with Patrick Steinhardt that the current behavior likely reflects an accident rather than a deliberate design choice, noting that the use of `exit(1)` in the quiet path was probably just a quick way to return a non-zero status without considering consistency with `die()`'s exit code of 128.

The discussion now centers on two options: either avoid testing the exact exit codes (to prevent "overspecifying" behavior that may not matter) or align the exit codes by changing the quiet path to use `die(NULL)` instead of `exit(1)`. Junio endorses both approaches but seems to lean slightly toward the former, emphasizing that the exact exit code may not be critical as long as it’s non-zero. No code changes are proposed here—just agreement on the direction. The patch’s future now hinges on whether the author (Nikolaus Schuetz) revisits the design or proceeds with the current behavior.
