This is the refactoring patch in Karthik Nayak’s three-part series introducing the new `report` hook for `git-receive-pack`. The patch extracts the status-report generation logic from `report()` and `report_v2()` into a shared helper, `generate_response()`, which takes a boolean flag to control whether it adds per-reference reports (v2 protocol only). The motivation is purely preparatory: the next patch will reuse this function to regenerate the status message if the new `report` hook fails.

The change is mechanical and well-scoped: it moves 40 lines of near-identical code into a single function, reducing duplication without altering behavior. The commit message is clear and the diff is clean, showing only the extracted function and the two callers. No new tests are needed because this is a pure refactoring. The patch is uncontroversial and ready to land; it simply sets the stage for the hook implementation that follows.
