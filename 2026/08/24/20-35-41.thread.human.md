This thread began as a patch series proposing `--[no-]range-diff-notes` options for `git format-patch`, allowing users to control whether Git notes appear in the range-diff section separately from the patches themselves. The series, authored by Kristoffer Haugsbakk, was abandoned after Junio C Hamano raised fundamental usability concerns about the option semantics and the unintuitive toggle mechanism (`--no-range-diff-notes --range-diff-notes`).

The core issue was that the interaction between `--notes` and `--range-diff-notes` couldn’t be cleanly defined, leading to confusing edge cases—such as `--no-notes` suppressing notes in both contexts or `--range-diff-notes` having no effect when used without `--range-diff`. While Kristoffer later clarified that the implementation already followed the intended design (separate control for patch notes and range-diff notes), the documentation’s phrasing and the toggle mechanism’s complexity made the behavior hard to predict. Junio proposed simplifying the design by making `--no-range-diff-notes` mean "no notes for range-diff" without fallback, but no redesign emerged before the feature was abandoned.

In this follow-up discussion, Kristoffer and D. Ben Knoble explored the toggle mechanism’s intended purpose: to undo prior overrides (e.g., `--range-diff-notes=changelog`) and restore the default state where both patches and range-diffs use the same notes. Kristoffer argued the flexibility justified the complexity, while Ben noted a tangential inconsistency in `format-patch`’s handling of default notes (`format.notes` vs. `notes.displayRef`). The exchange remains theoretical, as the feature is unlikely to be revived without addressing Junio’s concerns. If it is, the redesign would need to enforce explicit separation of the two notes lists, clarify CLI semantics, and eliminate the toggle mechanism’s unintuitive edge cases.
