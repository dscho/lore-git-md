This thread introduced a proposed feature for `git format-patch`—the `--[no-]range-diff-notes` options—to allow users to control whether Git notes appear in the range-diff section independently of the patches themselves. The series, authored by Kristoffer Haugsbakk, aimed to address workflows where iteration notes (like "v3: [description]") are useful in patches but clutter the range-diff output. However, the effort was abandoned after Junio C Hamano identified a fundamental flaw in the option semantics: the interaction between `--range-diff-notes` and the existing `--notes` flag couldn’t be defined in simple or intuitive terms. Specifically, the fallback behavior meant that `--no-notes --range-diff-notes` would suppress notes in *both* contexts, defeating the purpose of the feature.

Kristoffer acknowledged the issue and chose not to pursue a redesign, closing the thread without further versions. The series touched several core files (`builtin/log.c`, `revision.c`, etc.) and introduced new struct members, but these changes are now moot. While the goal of independent notes control remains unmet, any future attempt would need to address Junio’s usability concern—likely by maintaining separate notes lists for patches and range-diffs. For now, the thread is concluded with no action taken.
