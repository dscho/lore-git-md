This thread introduces a small but useful quality-of-life improvement to `git format-patch`: the `--[no-]range-diff-notes` options, allowing users to control whether Git notes appear in the range-diff section of the output. Kristoffer Haugsbakk posted the three-patch series (v1) to address a common workflow friction—iteration notes (like "v3: fixed typo") cluttering range-diffs while remaining useful in the patch output itself.

The series is under review, with all tests passing in CI. The first two patches are preparatory: one refactors `get_notes_args` to simplify its interface, and the other renames a struct member in `revision.h` (`rdiff_log_arg` → `rdiff_notes_arg`) to better reflect its narrowed role after the feature lands. The third patch implements the core functionality, adding the new options and a `rdiff_override_notes` flag to track user intent. The implementation is clean, follows Git’s option-handling patterns, and includes thorough test coverage for edge cases like toggling the override or using different notes refs for patches and range-diffs.

No reviews or objections have surfaced yet, but the feature seems uncontroversial. The only loose end is the author’s uncertainty about the CI setup, though no failures are reported. The series is self-contained and doesn’t conflict with other in-flight work. If feedback arrives, it will likely focus on edge-case handling (e.g., whether `--range-diff-notes` should error without `--range-diff`). For now, the ball is in the reviewers’ court.
