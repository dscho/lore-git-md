This thread began with Kristoffer Haugsbakk’s patch series proposing `--[no-]range-diff-notes` options for `git format-patch`, aiming to let users control whether Git notes appear in the range-diff section separately from the patches themselves. The series was abandoned after Junio C Hamano identified a fundamental usability flaw: the interaction between the new options and the existing `--notes` flag couldn’t be clearly defined, leading to unintuitive behavior—like `--no-notes --range-diff-notes` suppressing notes in both contexts. Kristoffer later clarified that the implementation already followed the design Junio sketched (separate control for patch notes and range-diff notes), but the documentation’s phrasing obscured this.

The thread is now closed, with no further action expected. D. Ben Knoble’s recent reply offered a minor editorial suggestion on Kristoffer’s rewritten documentation snippet, proposing a tweak to clarify that toggling off the override refers to suppressing notes (via `--no-range-diff-notes`) rather than the override mechanism itself. The feedback was purely stylistic, with no technical objections, and the thread remains inactive. If this feature is ever revived, it will need to address Junio’s usability concerns—likely by enforcing explicit separation of the two notes lists and ensuring `--range-diff-notes` errors when used without `--range-diff`.
