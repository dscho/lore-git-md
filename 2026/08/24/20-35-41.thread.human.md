This thread began as a patch series proposing `--[no-]range-diff-notes` options for `git format-patch`, allowing users to control whether Git notes appear in the range-diff section independently of the patches themselves. The feature aimed to address workflows where iteration notes (e.g., "v3: [description]") are useful in patches but clutter range-diffs. Kristoffer Haugsbakk implemented the series in three patches, touching core files like `builtin/log.c` and adding tests.

The effort was abandoned after Junio C Hamano raised a fundamental usability concern: the interaction between the new `--range-diff-notes` and existing `--notes` options was unintuitive and couldn’t be cleanly defined. Kristoffer confirmed the issue—`--no-notes --range-diff-notes` suppressed notes in both contexts—and later clarified that the implementation already followed Junio’s suggested design (separate control for patch and range-diff notes), though the documentation obscured this. D. Ben Knoble reviewed a rewritten documentation snippet, suggesting minor wording tweaks but no technical changes.

This follow-up email revisits the documentation’s clarity, focusing on how to revert the override behavior. Kristoffer explains that `--no-range-diff-notes --range-diff-notes` (without arguments) was intended to toggle back to the default state, where both patches and range-diffs use the same notes. While the interaction is complex, he argues the flexibility justifies it. The thread is now closed, with no further action expected. If revived, the feature would need to address Junio’s usability concerns, likely by enforcing clearer CLI semantics and erroring when `--range-diff-notes` is used without `--range-diff`.
