This thread began as a patch series adding `--[no-]range-diff-notes` options to `git format-patch`, allowing users to control whether Git notes appear in the range-diff section separately from the patches themselves. The feature aimed to address workflows where iteration notes (like "v3: [description]") should be visible in the patch output but suppressed in the range-diff. Kristoffer Haugsbakk implemented the series, but Junio C Hamano raised a fundamental usability concern: the interaction between the new options and the existing `--notes` flag was unintuitive and couldn’t be cleanly defined. Specifically, `--no-notes --range-diff-notes` suppressed notes in both contexts, and the fallback behavior of `--range-diff-notes` (inheriting from `--notes` when no range-diff was present) created ambiguity.

Kristoffer acknowledged the issue and chose to abandon the feature, though he later clarified that the implementation already followed the design Junio had sketched—separate control for patch notes and range-diff notes—despite the documentation’s misleading phrasing. The thread is now closed, with no further action expected. The latest email provides a rewritten documentation snippet to correct the record, explicitly describing how the feature maintained two independent notes lists and handled overrides. While this confirms the implementation was closer to the intended design than initially apparent, it doesn’t resolve the underlying usability flaw Junio identified. If the feature is ever revived, it will need a redesign to address those concerns.
