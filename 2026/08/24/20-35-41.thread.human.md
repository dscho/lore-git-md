This thread began with Kristoffer Haugsbakk’s patch series proposing `--[no-]range-diff-notes` options for `git format-patch`, aiming to let users control whether Git notes appear in the range-diff section separately from the patches themselves. The series was abandoned after Junio C Hamano identified a fundamental usability issue: the interaction between the new options and the existing `--notes` flag couldn’t be defined in simple, intuitive terms. Specifically, `--no-notes --range-diff-notes` would suppress notes in both contexts because the implementation fell back to the patch notes setting when the range-diff notes list was empty.

Kristoffer has now clarified that the implementation already followed the alternative design Junio sketched in his closure email—where `--notes` controls only the final patch output and `--range-diff-notes` controls only the range-diff material. The documentation’s phrasing was misleading, describing the behavior only for the edge case where the range-diff notes list was empty, which obscured the independent control the code actually provided. The usability issue Junio raised arose because `--no-notes` cleared the notes list that the range-diff fallback path still referenced, not because the design lacked separate control. No further action is planned; the thread remains closed.
