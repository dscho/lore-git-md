This is a feature patch series introducing `--[no-]range-diff-notes` options to `git format-patch`. The series consists of three patches: the first two are preparatory refactorings (simplifying parameter handling and renaming a struct member for clarity), while the third patch implements the new functionality.

The goal is to allow users to control whether notes are included in the range-diff section of `format-patch` output independently of whether notes are included in the patches themselves. The author notes this was motivated by personal workflow needs and has been used privately for months, though the current implementation is entirely new and untested at scale.

Key changes:
- Patch 1/3 simplifies `get_notes_arg` parameter handling in `builtin/log.c`
- Patch 2/3 renames the `notes_opt` struct member to `patch_notes_opt` in `revision.h` to better reflect its role
- Patch 3/3 adds the new `--range-diff-notes` and `--no-range-diff-notes` options, with corresponding documentation and tests

The implementation touches `format-patch` internals (`builtin/log.c`, `log-tree.c`, `revision.c/h`) and adds comprehensive tests in `t/t3206-range-diff.sh`. The CI run shows all tests passing, though the author expresses some uncertainty about the CI setup.

This appears to be a well-structured feature addition with clear separation between refactoring and new functionality. The test coverage looks thorough, and the commit messages explain the motivation and changes clearly. The feature itself addresses what seems like a reasonable workflow need for users who want fine-grained control over notes display in range-diffs.
