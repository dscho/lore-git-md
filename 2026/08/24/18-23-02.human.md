This is a design clarification reply in an ongoing user inquiry about Git’s `--ext-diff` option.

Jeff King (Peff) explains that external diff drivers can do more than generate text output—such as opening GUI windows—which could be disruptive if triggered automatically during commands like `git log` that process many commits. This justifies why some commands suppress external diffs by default. He notes that `git show` likely inherited its behavior from `git log --no-walk` without deliberate consideration, and suggests that it *could* reasonably default to the same behavior as `git diff`.

Peff also mentions `textconv` as a more predictable alternative for converting binary files to diffable text, though he acknowledges his bias as its author. The response is concise and practical, offering both a rationale for the current design and a workaround for users who want consistent diff behavior. No patches or technical changes are proposed—this is purely an explanation of Git’s existing behavior.
