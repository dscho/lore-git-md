This is a **substantive reply** in the ongoing discussion about Elijah Newren’s patch series fixing a race condition in Git’s geometric repacking mechanism. Patrick Steinhardt clarifies a key technical point in response to Jeff King’s (Peff) review of patch 2/2, which proposed recovering from multi-pack-index (MIDX) references to removed packfiles.

Patrick agrees with Peff that the `OBJECT_INFO_QUICK` flag is working as designed—callers using it must tolerate false negatives—but argues that Elijah’s patch still addresses a real bug. The issue arises when an object exists in *multiple* packs covered by the MIDX, but the "preferred" pack (the one the MIDX would normally use) is removed by a concurrent repack. In this case, the lookup fails entirely because the MIDX-based search returns an error (due to the missing pack), and the fallback non-MIDX search skips all packs covered by the MIDX, even though the object might still be available in another pack. This failure occurs regardless of whether `QUICK` is used, making it a distinct problem from the one Peff described.

The reply narrows the scope of the bug: it’s not about `QUICK`’s behavior but about the MIDX’s inability to recover when its preferred pack disappears. This reinforces Elijah’s original fix (scanning all MIDX-covered packs when the preferred one is missing) as a targeted solution to a real edge case. The discussion now hinges on whether this recovery logic belongs in the packed-object backend (Elijah’s approach) or should be handled at the caller level (Peff’s preference). Patrick’s clarification suggests the fix is necessary, but the architectural debate remains unresolved.
