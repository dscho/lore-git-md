Thread identity: `[PATCH 0/3] format-patch: add --[no-]range-diff-notes` series introducing options to control notes inclusion in range-diff output. Originating author: Kristoffer Haugsbakk. Thread type: patch series (feature addition).

Core problem or goal: Add `--[no-]range-diff-notes` options to `git format-patch` to allow independent control over whether Git notes are included in the range-diff section versus the patches themselves. The feature aimed to address workflow needs where users want to suppress iteration notes (e.g., "v3: [description]") in range-diffs while retaining them in the patch output, but the proposed implementation failed to support this intuitive use case.

Current status: **Abandoned**. The series was posted as v1 and remains at that version. Junio C Hamano raised a substantive usability concern about the option semantics, specifically that the interaction between `--range-diff-notes` and the existing `--notes` could not be defined in simple terms and was conceptually flawed. Kristoffer Haugsbakk acknowledged the issue and chose to abandon the feature rather than propose a redesign. No further versions or alternative designs have been proposed, and the thread is now closed.

Key technical details:
- Files touched: `builtin/log.c`, `log-tree.c`, `revision.c`, `revision.h`, `Documentation/git-format-patch.txt`, and tests in `t/t3206-range-diff.sh`.
- Proposed CLI options: `--range-diff-notes[=<ref>]` and `--no-range-diff-notes`.
- New struct members: `rdiff_override_notes` flag in `struct rev_info` (patch 3); `rdiff_notes_arg` (renamed from `rdiff_log_arg` in patch 2).
- Refactoring: `get_notes_args` was modified to use `rev->rdiff_notes_arg` directly instead of an explicit `struct strvec *arg` parameter (patch 1).
- Behavior: The implementation fell back to the patch notes setting when the override was not explicitly set, which created the usability issue where `--no-notes --range-diff-notes` suppressed notes in both contexts because the notes list was cleared by `--no-notes`.
- Edge cases handled: Toggling the override off after it was set, supporting specific notes refs for range-diffs (e.g., `--range-diff-notes=testing`).
- Test coverage: Comprehensive tests were added to `t/t3206-range-diff.sh`, verifying scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and toggling the override. The tests did not cover the problematic interaction between `--no-notes` and `--range-diff-notes` that Junio highlighted.
- Prior commit dependency: 85bd88a7 (2025-09-25) introduced `rdiff_log_arg` to `struct rev_info`.

Open questions and loose ends:
- The usability issue with option semantics remains unresolved: the current implementation did not support the intuitive use case where `--no-notes --range-diff-notes` suppresses notes in patches but includes them in the range-diff. Junio explicitly stated that the interaction between the new option and the existing `--notes` could not be defined in simple terms, making the feature’s semantics conceptually flawed.
- Kristoffer previously sketched a potential solution (maintaining a separate "shadow list" of notes for range-diffs) but did not propose a concrete design change before abandoning the effort.
- The implementation did not error when `--range-diff-notes` was used without `--range-diff`, which may warrant further discussion if the feature is revived.
- All tests passed in CI, though the author previously expressed uncertainty about the CI setup.
