Thread identity: `[PATCH 0/3] format-patch: add --[no-]range-diff-notes` series introducing options to control notes inclusion in range-diff output. Originating author: Kristoffer Haugsbakk. Thread type: patch series (feature addition).

Core problem or goal: Add `--[no-]range-diff-notes` options to `git format-patch` to allow independent control over whether Git notes are included in the range-diff section versus the patches themselves. The feature addresses workflow needs where users want to suppress iteration notes (e.g., "v3: [description]") in range-diffs while retaining them in the patch output.

Current status: Under review (v1 posted). The series consists of three patches: (1) a preparatory refactoring simplifying `get_notes_args`, (2) a rename of `rdiff_log_arg` to `rdiff_notes_arg` in `revision.h`, and (3) the core implementation of `--range-diff-notes` and `--no-range-diff-notes`. Junio C Hamano has raised a substantive usability concern about the option semantics in patch 3, specifically the fallback behavior where `--range-diff-notes` inherits the patch notes setting. Kristoffer Haugsbakk has acknowledged the issue, confirming that `--no-notes --range-diff-notes` suppresses notes in both contexts because the notes list is cleared by `--no-notes`. The thread is now at a decision point: whether to redesign the option semantics (e.g., by maintaining a separate "shadow list" of notes for range-diffs) or document the current behavior as intentional. No concrete design change has been proposed yet, and the series remains in review with no new version posted.

Key technical details:
- Files touched: `builtin/log.c`, `log-tree.c`, `revision.c`, `revision.h`, `Documentation/git-format-patch.txt`, and tests in `t/t3206-range-diff.sh`.
- New CLI options: `--range-diff-notes[=<ref>]` and `--no-range-diff-notes`.
- New struct members: `rdiff_override_notes` flag in `struct rev_info` (patch 3); renamed `rdiff_log_arg` -> `rdiff_notes_arg` (patch 2).
- Refactoring: `get_notes_args` now uses `rev->rdiff_notes_arg` directly instead of an explicit `struct strvec *arg` parameter (patch 1).
- Behavior: The options control notes inclusion in the range-diff section independently of the main patch notes, but the current implementation falls back to the patch notes setting when the override is not explicitly set. Edge cases handled include toggling the override off after it has been set and supporting specific notes refs for range-diffs (e.g., `--range-diff-notes=testing`).
- Test coverage: Comprehensive tests added to `t/t3206-range-diff.sh`, verifying scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and toggling the override. The tests do not currently cover the interaction between `--no-notes` and `--range-diff-notes` that Junio highlighted.
- Prior commit dependency: 85bd88a7 (2025-09-25) introduced `rdiff_log_arg` to `struct rev_info`.

Open questions and loose ends:

Kristoffer has noted a conceptual problem: since `format-patch` does not show notes by default, it is unclear what `--range-diff-notes` should display when no explicit notes ref is provided.
- The implementation does not error when `--range-diff-notes` is used without `--range-diff`, which may warrant further review discussion.

- All tests pass in CI, though the author previously expressed uncertainty about the CI setup.
