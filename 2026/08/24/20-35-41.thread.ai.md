Thread identity: `[PATCH 0/3] format-patch: add --[no-]range-diff-notes` series introducing options to control notes inclusion in range-diff output. Originating author: Kristoffer Haugsbakk. Thread type: patch series (feature addition).

Core problem or goal: Add `--[no-]range-diff-notes` options to `git format-patch` to allow independent control over whether Git notes are included in the range-diff section versus the patches themselves. The feature addresses workflow needs where users want to suppress iteration notes (e.g., "v3: [description]") in range-diffs while retaining them in the patch output.

Current status: Under review (v1 posted). The series remains at v1 with no new version proposed. Junio C Hamano has now explicitly stated that the current option semantics are conceptually flawed and may not be acceptable in their present form, elevating the usability concern to a potential blocker. The thread is at a design impasse: the intuitive use case (`--no-notes --range-diff-notes` suppressing notes in patches but including them in the range-diff) is not supported by the current implementation, and no concrete redesign has been proposed. The series is still under review, but the unresolved design tension may prevent progression until a clearer semantics is defined.

Key technical details:
- Files touched: `builtin/log.c`, `log-tree.c`, `revision.c`, `revision.h`, `Documentation/git-format-patch.txt`, and tests in `t/t3206-range-diff.sh`.
- New CLI options: `--range-diff-notes[=<ref>]` and `--no-range-diff-notes`.
- New struct members: `rdiff_override_notes` flag in `struct rev_info` (patch 3); renamed `rdiff_log_arg` -> `rdiff_notes_arg` (patch 2).
- Refactoring: `get_notes_args` now uses `rev->rdiff_notes_arg` directly instead of an explicit `struct strvec *arg` parameter (patch 1).
- Behavior: The options control notes inclusion in the range-diff section independently of the main patch notes, but the current implementation falls back to the patch notes setting when the override is not explicitly set. This creates the usability issue where `--no-notes --range-diff-notes` suppresses notes in both contexts because the notes list is cleared by `--no-notes`.
- Edge cases handled: Toggling the override off after it has been set, supporting specific notes refs for range-diffs (e.g., `--range-diff-notes=testing`).
- Test coverage: Comprehensive tests added to `t/t3206-range-diff.sh`, verifying scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and toggling the override. The tests do not cover the problematic interaction between `--no-notes` and `--range-diff-notes` that Junio highlighted.
- Prior commit dependency: 85bd88a7 (2025-09-25) introduced `rdiff_log_arg` to `struct rev_info`.

Open questions and loose ends:
- The usability issue with option semantics remains unresolved and is now a potential blocker: whether `--range-diff-notes` should override the patch notes setting only for the range-diff or inherit it by default. The current implementation does not support the intuitive use case where `--no-notes --range-diff-notes` suppresses notes in patches but includes them in the range-diff.
- Kristoffer previously sketched a potential solution (maintaining a separate "shadow list" of notes for range-diffs) but has not proposed a concrete design change.
- The implementation does not error when `--range-diff-notes` is used without `--range-diff`, which may warrant further review discussion.
- No other review feedback or objections have been recorded yet.
- All tests pass in CI, though the author previously expressed uncertainty about the CI setup.
