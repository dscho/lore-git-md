Thread identity: `[PATCH 0/3] format-patch: add --[no-]range-diff-notes` series introducing options to control notes inclusion in range-diff output. Originating author: Kristoffer Haugsbakk. Thread type: patch series (feature addition).

Core problem or goal: Add `--[no-]range-diff-notes` options to `git format-patch` to allow independent control over whether Git notes are included in the range-diff section versus the patches themselves. The feature aimed to address workflow needs where users want to suppress iteration notes (e.g., "v3: [description]") in range-diffs while retaining them in the patch output, but the proposed implementation was deemed conceptually flawed due to ambiguous option semantics and unintuitive fallback behavior.

Current status: **Abandoned**. The series was posted as v1 and remains at that version. Junio C Hamano raised a substantive usability concern about the option semantics, specifically that the interaction between `--range-diff-notes` and the existing `--notes` could not be defined in simple terms and was unintuitive. Kristoffer Haugsbakk acknowledged the issue, confirmed the problematic behavior of `--no-notes --range-diff-notes` suppressing notes in both contexts, and chose to abandon the feature. In the closure email, Junio restated the usability issue and noted that no alternative design was proposed before abandonment. Kristoffer later clarified that the implementation *did* already follow the alternative design Junio sketched (where `--notes` controls only the final patch output and `--range-diff-notes` controls only the range-diff material), but the documentation’s phrasing obscured this. The thread is now closed with no further action expected.

Key technical details:
- Files touched: `builtin/log.c`, `log-tree.c`, `revision.c`, `revision.h`, `Documentation/git-format-patch.txt`, and tests in `t/t3206-range-diff.sh`.
- Proposed CLI options: `--range-diff-notes[=<ref>]` and `--no-range-diff-notes`.
- New struct members: `rdiff_override_notes` flag in `struct rev_info` (patch 3); `rdiff_notes_arg` (renamed from `rdiff_log_arg` in patch 2).

- Behavior: The implementation maintained two separate notes lists (one for patches, one for range-diffs) and used the `rdiff_override_notes` flag to toggle between them. The usability issue arose because `--no-notes` cleared the notes list that the range-diff fallback path still referenced, and because `--range-diff-notes` without `--range-diff` had no effect but did not error. The documentation’s phrasing was misleading, describing the behavior only for the edge case where the range-diff notes list was empty.
- Edge cases handled: Toggling the override off after it was set, supporting specific notes refs for range-diffs (e.g., `--range-diff-notes=testing`).
- Test coverage: Comprehensive tests were added to `t/t3206-range-diff.sh`, verifying scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and toggling the override. The tests did not cover the problematic interaction between `--no-notes` and `--range-diff-notes` that Junio highlighted.
- Prior commit dependency: 85bd88a7 (2025-09-25) introduced `rdiff_log_arg` to `struct rev_info`.
- Documentation clarification: Kristoffer Haugsbakk provided a rewritten documentation snippet explicitly describing the two separate notes lists (patch notes vs. range-diff notes) and their independent control. The rewrite confirms the implementation already followed the design Junio sketched, though the original phrasing obscured this.

Junio explicitly stated that the interaction between the new option and the existing `--notes` could not be defined in simple terms, making the feature’s semantics conceptually flawed.

No redesign was proposed to address the remaining usability concerns (e.g., `--range-diff-notes` without `--range-diff`).
