This is a **substantive follow-up** in the ongoing design discussion for Elijah Newren’s patch 2/2, which fixes a race condition in Git’s packed-object backend when a multi-pack-index (MIDX) references a removed packfile. Jeff King (Peff) refines his earlier performance concern about the fallback logic’s scan order, now arguing that the recovery mechanism should **only trigger during `SECOND_READ`** (the retry phase after a refresh) rather than on the initial lookup. His reasoning is twofold: first, `QUICK` callers (like `git replay`) are already prepared to tolerate false negatives and should not incur the cost of scanning potentially many MIDX-covered packs; second, the fallback is only useful when an object exists in a duplicate pack *not* moved by repacking, a scenario that cannot be distinguished from a true negative until the `SECOND_READ` phase. Peff acknowledges that this is mostly an academic concern, as the fallback is gated by a `bsearch()` check that ensures it only runs when the MIDX *should* have found the object, but he suggests the change would optimize the common case where the object is in a newer, non-MIDX pack.

The email does not propose new code or challenge the fix’s correctness, but it narrows the debate to a specific implementation detail: whether the recovery logic should be tied to `SECOND_READ`. This aligns with Peff’s earlier tri-state design preference (shifting responsibility to callers) but reframes it as a performance optimization rather than an architectural overhaul. The discussion remains focused on refining the patch’s behavior for edge cases, with no objections to the core fix. Key technical details include the role of `SECOND_READ` in distinguishing between true negatives and race-condition-induced false negatives, and the observation that newer packs (sorted by reverse mtime) are likely to contain the object if it was recently repacked. The outcome of this debate may influence whether Elijah resubmits the patch with adjusted logic or leaves the change to be handled during integration.
