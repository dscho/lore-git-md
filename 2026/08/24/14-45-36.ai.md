This is a **substantive review** of the second patch in Elijah Newren’s two-patch bugfix series addressing a race condition in Git’s geometric repacking mechanism. Derrick Stolee’s email engages directly with the architectural trade-offs of the fix, offering context about the existing `multi-pack-index expire` mechanism and its role in mitigating similar races. His feedback is constructive and grounded in real-world deployment concerns, particularly around Windows platform constraints.

Stolee’s core observation is that the race condition Elijah’s patch addresses—where a stale multi-pack-index (MIDX) references a packfile removed by geometric repacking—is already partially mitigated by `git multi-pack-index expire`. This command deletes packfiles whose objects are fully covered by other packs, but it does so in a way that avoids breaking existing processes: the MIDX continues to reference the "stale" packs until all processes using them have finished. This design is especially important on Windows, where open file handles prevent deletion, making the "dance" of leaving redundant data temporarily critical for stability. Stolee suggests that geometric repacking could adopt a similar approach, reducing the frequency with which the fallback logic in Elijah’s patch would need to trigger.

While Stolee endorses the goal of making Git more robust to missing packs, his comment underscores the complexity of the problem and the value of avoiding the fallback logic when possible. He frames the fix as a useful safeguard but implies that the project might prefer to minimize its reliance on it, favoring instead a strategy that leaves redundant data in place for a grace period. This perspective aligns with the broader discussion in the thread, where Jeff King (Peff) and Patrick Steinhardt have debated the performance implications of the fallback logic, particularly its scan order and timing. Stolee’s input adds a deployment-level dimension to that debate, highlighting how platform-specific constraints (like Windows’ file-handle behavior) shape the trade-offs between correctness, performance, and operational simplicity.

The email does not propose a specific alternative or request changes to the patch, but it does introduce a new angle for the ongoing design discussion. Future iterations of the series—or follow-up work—may need to reconcile the fallback logic with the existing `expire` mechanism, possibly by adjusting how geometric repacking interacts with the MIDX to reduce the likelihood of triggering the race. For now, Stolee’s feedback reinforces the fix’s necessity while nudging the conversation toward minimizing its runtime cost.
