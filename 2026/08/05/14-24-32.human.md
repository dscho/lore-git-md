This is part two of Harald Nordgren’s seven-patch series introducing `git branch --delete-merged`, now merged to **'next'**. The series is feature-complete, well-tested, and ready for integration.

This patch converts `delete_branches()` and `check_branch_commit()` from separate boolean arguments (`force`, `quiet`) to a single `unsigned int flags` parameter and an enum (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is purely mechanical: every use site now tests the flags directly, eliminating the risk of stale cached values when flags are mutated or forwarded. The commit message explicitly states there is no behavior change, and the diff confirms this is a straightforward refactoring.

The flags-based API is a prerequisite for the later patches that add `DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`, and `DELETE_BRANCH_DRY_RUN`. Phillip Wood’s earlier review identified a maintenance risk in patches 2–4/7 (two sources of truth for flags), which this patch resolves by ensuring flags remain the single source of truth. The refactoring is low-risk and well-tested, with no functional impact on existing callers.

This patch touches only `builtin/branch.c` and is part of the series’ broader effort to establish a consistent, extensible API for branch deletion. The series as a whole is a well-motivated feature that addresses a common workflow pain point with careful attention to safety and edge cases.
