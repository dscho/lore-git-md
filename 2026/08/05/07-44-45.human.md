This is the first patch in Patrick Steinhardt’s v2 series unifying Git’s ODB streaming API. It moves the expected object size from a separate parameter into `struct odb_write_stream` itself, making the structure self-describing. The change touches 14 files, primarily in the object database (`odb/`) and object-file subsystems, and is purely mechanical: every function that previously took a `size_t len` alongside the stream now reads `stream->size` instead.

The patch is well-motivated: the size is always known when the stream is created, and embedding it in the structure brings `odb_write_stream` closer to `odb_read_stream`, paving the way for the eventual unification in later patches. The commit message is clear, and the diff is clean—no behavior changes are intended, and the series’ goal (enabling pluggable ODB backends) is reiterated.

Justin Tobler’s review of v1 was positive, calling the approach “complete sense,” and no correctness issues were raised. This patch is uncontroversial and looks ready to advance.
