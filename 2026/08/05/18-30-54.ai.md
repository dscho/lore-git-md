This is the fifth patch in the v2 Coverity unchecked-return-values series, targeting the `git last-modified` built-in. It adds missing error checks for `repo_parse_commit()` at three call sites in `builtin/last-modified.c`, preventing silent incorrect results when commits are corrupt or unavailable.

The patch is small (six lines added, three removed) and self-contained. It follows the established defensive pattern used in other revision walkers like `limit_list()` and `get_revision_internal()`. When `repo_parse_commit()` fails, the code now skips the unparsable commit by either continuing to the next iteration or returning early, ensuring no undefined behavior or silent corruption. The commit message clearly explains the consequences at each call site: incorrect "last modified" attribution, premature exclusion-walk termination, and wrong diff results.

This patch directly addresses Junio C Hamano's correctness concern from the v1 review, which identified the risk of proceeding with uninitialized commit data. The fix is minimal and uncontroversial, matching the error-handling approach already used elsewhere in the codebase. No new behavior or on-disk formats are introduced, and the existing test suite implicitly exercises the new error paths. The patch is ready for integration.
