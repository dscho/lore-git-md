Ben Knoble’s report about `git rebase -x` losing notes when combined with `git commit --amend`. He identifies the root cause: the rebase machinery records the new commit object ID *before* the external command runs, so when `--amend` creates a new commit, the notes-rewriting step still uses the pre-amend ID, effectively copying notes to the now-discarded commit. Phillip notes he has an old, unfinished patch series that attempts to fix this by making `git commit --amend` update the rebase’s internal rewrite map, but the effort stalled due to complexities around commit editing.
