This is the third patch in Harald Nordgren’s seven-patch series introducing `git branch --delete-merged`, now merged to **'next'**. The patch adds a new flag, `DELETE_BRANCH_SKIP_UNMERGED`, to the branch-deletion API, allowing bulk callers (like the upcoming `--delete-merged` subcommand) to silently skip unmerged branches instead of failing with the usual "use `git branch -D`" advice. The change is purely internal: existing callers of `delete_branches()` and `check_branch_commit()` continue to behave exactly as before, so there is no user-visible impact until the later patches in the series wire up the new flag.

The implementation is straightforward. In `check_branch_commit()`, the function now checks the new flag before emitting the error and advice messages; if the flag is set, it simply returns `-1` without printing anything. In `delete_branches()`, the caller suppresses the non-zero return code when the flag is active, allowing the loop to continue to the next branch. The patch is mechanical and risk-free: it introduces no new logic, only a conditional guard around existing error-handling code.

This is part of the series’ broader flags-based API refactoring (patches 2–4/7), which replaces boolean parameters with an `unsigned int flags` field to eliminate local boolean caching and ensure flags remain the single source of truth. The new flag will be used in patch 5/7, where `delete_merged_branches()` needs to skip unmerged branches without aborting the entire operation. The patch is well-tested as part of the series’ comprehensive test suite, which verifies that the skip-unmerged behavior works as intended in the context of `--delete-merged`.
