This is the first patch in Patrick Steinhardt’s v3 six-patch series making on-disk ODB structures pluggable. It fixes a latent correctness bug in loose-object map loading: the function `load_one_loose_object_map()` was always reading from the common `objects/` directory instead of the path belonging to the specific ODB source passed to it. This meant loose-object maps in alternates were silently ignored, which could break object resolution in repositories using compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility).

The patch changes `load_one_loose_object_map()` to use the loose source’s path (`loose->base.path`) instead of the repository’s common path. The function signature is simplified to take only the `odb_source_loose` pointer, and the repository is retrieved from the source’s ODB. The test added in `t/t1016-compatObjectFormat.sh` creates two SHA-256 repositories (one acting as an alternate), configures both with SHA-1 compatibility, and verifies that `git rev-parse` correctly resolves an object borrowed from the alternate when using the compatibility hash format.

This patch is now a strong candidate for early graduation: it is a correctness fix with a dedicated regression test, and the change is minimal and well-justified. The fix is uncontroversial and ready for merging. Files touched: `loose.c` and `t/t1016-compatObjectFormat.sh`. Key names: `load_one_loose_object_map()`, `odb_source_loose`, `repo_read_loose_object_map()`, `compat_hash()`. The patch is part of the ongoing ODB abstraction effort and is a prerequisite for future non-filesystem backends.
