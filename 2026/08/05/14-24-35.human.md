This is the core implementation patch of Harald Nordgren’s long-running `--delete-merged` series, now merged to **'next'**. Patch 5/7 adds the actual `git branch --delete-merged <pattern>` subcommand that safely deletes local branches whose work has already landed on their upstream.

The command takes one or more upstream patterns (exact refnames, remote shorthand, or shell-style globs) and optional branch patterns to limit the scope. It deletes only branches whose tip is reachable from the specified upstream, skipping checked-out branches, branches whose upstream no longer exists, branches that would update their upstream if pushed, and branches used as upstreams for unmerged work. The stacked-branch protection is order-independent: it collects all protected upstreams in a single pass, then removes them from the deletable set, ensuring the result is the same regardless of ref iteration order. When a protected branch’s own upstream is deleted, its upstream configuration is cleared.

The patch is well-motivated and thoroughly tested. The commit message clearly explains the safety checks and the order-independent design, and the test suite covers all advertised behavior, including edge cases like self-referential upstreams and missing upstreams. The implementation is complete and ready for integration; the only changes since v24 were mechanical test readability improvements in patch 1/7.
