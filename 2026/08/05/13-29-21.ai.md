This is the third patch in Patrick Steinhardt’s six-patch series making Git’s on-disk object database (ODB) structures pluggable, part of the broader ODB abstraction effort. The patch moves handling of the `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables from `apply_repository_format()` into `odb_new()` itself, making the function self-contained and eliminating the need to duplicate environment variable logic in future call sites.

The change is mechanical and uncontroversial: `odb_new()` gains an `enum odb_new_flags` parameter (`ODB_NEW_HONOR_ENV`) to control whether environment variables are respected, and `apply_repository_format()` now passes the flag through instead of managing the strings itself. The patch also updates the in-memory ODB unit test to pass `0` instead of empty strings. Toon Claes’s review notes that the `xstrdup_or_null()` call for `o->alternate_db` is now redundant (since `secondary_sources` is already duplicated or NULL) and could be removed, along with the corresponding `free()` call. This is a minor cleanup opportunity but does not affect functionality.

The patch prepares the ground for future work, including deferring ODB construction and moving alternate handling into the "files" backend, without altering current behavior. It touches only ODB initialization plumbing (`odb.c`, `odb.h`, `setup.c`, and a unit test) and is ready for merging. The broader series remains under review, with the first patch (a correctness fix) already marked for early graduation to `next`.
