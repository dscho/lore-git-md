This is a **platform compatibility** patch (part 9 of 12) in Johannes Schindelin’s series to upstream Git for Windows build adjustments. It stops creating hard-linked `git-<command>` executables (e.g., `git-commit`) for built-in commands on Windows.

The motivation is practical: these hard-links are a legacy holdover from Git’s early days when commands were shell scripts. They were officially deprecated in 2008, but the links are still created for backward compatibility. On Windows, they add noticeable build time (about 30 seconds per build), confuse users about disk usage, and generate recurring bug reports. The patch sets `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname` for both Windows and MINGW builds, which will suppress the hard-link creation.

The change is Windows-only and does not affect other platforms. It’s a straightforward cleanup with no behavioral impact—scripts using the dashed form will still work because the `git` executable itself handles those invocations. The patch is narrowly scoped and well-motivated, making it a routine maintenance step rather than a controversial change. If you’re interested in Windows build quirks or reducing unnecessary build artifacts, this is worth noting; otherwise, it’s safe to skip.
