This is the first patch in Harald Nordgren’s **v25 `--delete-merged` series**, which is now merged to **'next'**. The patch introduces the `--forked` filter for `git branch --list`, serving as the foundation for the `--delete-merged` subcommand added later in the series.

The `--forked <branch>` option filters the branch list to show only local branches whose upstream matches the given argument. The argument can be:
- A full refname (e.g., `origin/main`),
- A remote shorthand (e.g., `origin` for `origin/HEAD`),
- A shell-style glob (e.g., `origin/*`),
- Or repeated to widen the filter (e.g., `--forked origin/main --forked origin/next`).

The filter is composable with existing list-mode filters like `--merged` and `--no-merged`. For example:
```
git branch --merged origin/main --forked 'origin/*'
```
lists branches forked from `origin` that are already merged into `origin/main`.

The implementation adds:
- A new `strvec forked` field to `struct ref_filter` to store patterns,
- A `ref_filter_forked_add()` helper to resolve ref arguments or accept globs,
- A `filter_forked_match()` function to check each branch’s upstream against the registered patterns,
- And a `short_upstream_name()` utility to abbreviate refnames for glob matching.

The test suite verifies:
- Exact ref matching (e.g., `origin/one`),
- Glob matching (e.g., `origin/*`),
- Remote shorthand resolution (e.g., `origin` for `origin/HEAD`),
- Composition with other filters (`--merged`, `--no-merged`),
- Repeated arguments to widen the filter,
- And error handling for invalid patterns.

This patch is **purely additive** and has no functional impact on existing `git branch` behavior. The only change since v24 is mechanical: long test command lines have been wrapped for readability. The `--forked` filter is the technical underpinning for `--delete-merged`, which uses it to identify deletable branches in later patches.
