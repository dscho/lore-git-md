This is a refactoring patch series targeting the object database (ODB) subsystem, part of Patrick Steinhardt’s ongoing ODB abstraction effort. The v2 series now consists of eight patches (up from seven in v1) and completes the unification of `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure. The changes are purely structural, with no behavior changes intended, and aim to simplify the API while enabling pluggable ODB backends.

The series addresses all feedback from v1, including a critical bug fix in Patch 3/8 where the in-memory ODB backend was incorrectly hard-coding `OBJ_BLOB` when computing object hashes, risking silent corruption for non-blob objects. The fix now propagates the correct `stream->type` to `hash_object_file()`. Other improvements include removing a stale comment in `odb/transaction.h`, adapting a commit message to clarify future renames, and adding a new cosmetic Patch 7/8 to rename `struct input_zstream_data` (in `builtin/unpack-objects.c`) to better reflect its role as a stream wrapper.

The refactoring is incremental and well-scoped: Patch 1/8 tracks the write stream size in the structure, Patch 2/8 removes the redundant `is_finished` field, Patch 3/8 extends streaming to arbitrary object types, Patch 4/8 renames `struct odb_read_stream` to prepare for unification, Patch 5/8 merges the two structures into `odb_stream`, Patch 6/8 renames `struct read_object_fd_data` to `struct fd_stream`, Patch 7/8 renames `struct input_zstream_data`, and Patch 8/8 standardizes function names (e.g., `odb_stream_from_object()` and `odb_stream_from_fd()`). The series touches 23 files, including core ODB code (`odb/streaming.c`, `odb/source-*.c`), archive formats (`archive-tar.c`, `archive-zip.c`), and packfile operations (`builtin/pack-objects.c`).

Review feedback from v1 has been fully incorporated, and the series now looks ready for integration. Justin Tobler’s substantive reviews confirmed the structural changes align with the read stream’s design, while Junio C Hamano’s critical bug report was promptly addressed. The only remaining loose ends are minor: potential performance regressions in stream-heavy code paths (e.g., `pack-objects`) due to added indirection, and edge cases in error handling for mixed read/write operations. Neither appears likely to block progress, given the thoroughness of the refactoring and the lack of behavioral changes.

This is a solid, uncontroversial refactor that advances the ODB abstraction goals. The series is based on Junio’s "10th batch" (`5b2471720c`) and is likely targeting `next` or `master` soon. Reviewers familiar with the ODB (e.g., Justin Tobler, Taylor Blau) may focus on the remaining edge cases, but the core unification work is now complete and well-tested.
