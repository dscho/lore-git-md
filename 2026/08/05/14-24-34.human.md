This is the fourth patch in Harald Nordgren’s seven-part series introducing `git branch --delete-merged`, now merged to **'next'**. The patch prepares the existing `delete_branches()` function for the upcoming `--delete-merged` subcommand by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that prevents falling back to `HEAD` when a branch has no upstream.

The change is small and surgical: it modifies the function to skip the `HEAD` fallback when the new flag is set, ensuring `--delete-merged` only deletes branches that are merged into their upstream. Existing callers (like `git branch -d`) retain their current behavior. The commit message explains the reasoning clearly: callers that opt out of the `HEAD` fallback have already confirmed the branch has an upstream, so `HEAD` is irrelevant to the decision.

This patch is part of the flags-based API refactoring that began in patches 2 and 3, which replaced boolean arguments with an `unsigned int flags` parameter to avoid local boolean caching and ensure flags remain the single source of truth. The new flag is purely internal and has no user-visible impact until the `--delete-merged` subcommand is wired up in patch 5. The implementation is straightforward and well-tested, with no behavioral changes for existing callers. The series as a whole is ready for merging, and this patch is a necessary step toward the final command.
