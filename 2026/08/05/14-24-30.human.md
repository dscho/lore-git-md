This is the final version of Harald Nordgren’s `git branch --delete-merged` series, now merged to **`next`** and ready for the next release. The v25 update is purely cosmetic: it wraps overly long test command lines for readability, addressing the last surface-level nit from earlier reviews. No functional changes were made since v24, which already resolved the two blocking correctness issues (push-detection logic and stacked-branch protection).

The series adds a safe, automated way to clean up local branches that have been merged upstream. Key features include:

- **Repeatable `--delete-merged` arguments** (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the upstream match, with optional positional patterns (e.g., `topic-*`) to limit deletion scope.
- **Order-independent stacked-branch protection**: the command refuses to delete a branch if it is used as an upstream for an unmerged branch, and clears stale upstream configs for kept (merged) branches whose own upstream is being deleted.
- **Per-branch opt-out** via `branch.<name>.deleteMerged=false`, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.
- **`--dry-run` preview mode**, which prints "Would delete" or "Would skip" messages without modifying refs or config.
- **Push-divergence safety**: branches are preserved if pushing them by name would update their upstream (e.g., `main` tracking `origin/main`), with the v24 update fixing the logic to correctly handle `remote.pushDefault` configurations.

The implementation is thorough, with a flags-based API refactoring (patches 2–4/7) that replaces boolean arguments with `unsigned int flags` for consistency and maintainability. The test suite covers all edge cases, including the corrected push-detection logic, stacked-branch protection, and `--dry-run` functionality. This is a well-crafted addition that addresses a real workflow pain point while maintaining Git’s safety-first ethos. The only remaining follow-up is extending the stacked-branch protection to `git branch -d` for consistency, which Harald has agreed to implement after the series lands.
