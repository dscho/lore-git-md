This is the sixth and final patch in Patrick Steinhardt’s v3 series making the creation of on-disk object database (ODB) structures pluggable. It implements the core mechanism introduced in earlier patches by adding a `create_on_disk` callback to the ODB source interface and using it in the "files" backend to create its required subdirectories (`pack/` and `info/`).

The patch touches three files: `odb/source-files.c` (where the callback is implemented), `odb/source.h` (where the interface is defined), and `setup.c` (where the generic directory creation logic is replaced with the new callback). The change is mechanical and aligns with the series’ goal of decoupling backend-specific on-disk layout from core repository setup. The top-level `objects/` directory remains hardcoded as a requirement for repository discovery, but all backend-specific directories are now handled by the backend itself.

This patch is uncontroversial and ready for merging. It builds directly on the refactoring done in earlier patches (particularly the third and fourth in this series) and completes the series’ stated goal. The callback naming (`create_on_disk`) was previously discussed but deferred to maintain consistency with the ref subsystem’s `ref_store_create_on_disk()`; no further debate appears necessary. The implementation is straightforward, and the commit message clearly explains the exception for the `objects/` directory.

Key technical details for follow-up discussion: the callback is invoked in `create_object_database()` after the ODB is initialized, and the "files" backend’s implementation uses `safe_create_dir()` to create `pack/` and `info/` subdirectories. The patch also removes the now-redundant environment variable check from `create_object_database()`, as that logic was moved into `odb_new()` in the third patch. No new configuration options or user-visible behavior changes are introduced.
