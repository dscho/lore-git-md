This thread is about a patch from a new contributor, shrimech, that removes the `--interactive` (`-i`) mode from `git add`, leaving only `--patch` (`-p`) for interactive staging. The patch itself is straightforward—it deletes the option from the command-line parser, updates error messages, and removes all interactive-mode documentation—but it lacks any explanation for why the removal is justified. There’s no discussion of user demand, redundancy, or prior community feedback, making this feel like a drive-by change rather than a deliberate project decision.

So far, the thread consists only of the initial patch. No reviews or replies have appeared yet, so there’s no indication of whether the community sees this as a worthwhile simplification or an unnecessary removal of functionality. The absence of a sign-off from an established contributor and the lack of context in the commit message suggest this patch may struggle to gain traction unless someone steps in to advocate for it—or to push back. If this were part of a broader effort to streamline Git’s UI, you’d expect to see that mentioned in a cover letter, but as a standalone change, it feels under-motivated and likely to spark debate.
