This is a fixup patch for the fifth patch in Johannes Schindelin’s 11-patch series addressing unchecked return values identified by Coverity. The series aims to harden Git by adding missing error checks in various code paths, and this specific patch corrects a resource leak in `builtin/last-modified.c`.

The issue is straightforward: when a commit in the `--not` queue fails to parse, the original patch skipped it with `continue`, bypassing cleanup of the `active_paths` slab associated with that commit. Junio C Hamano pointed out that this could lead to a leak, and the fix replaces `continue` with `goto cleanup` to ensure the slab is properly released even for unparsable commits. The change is minimal—just one line—but it aligns the error path with the function’s existing resource-management pattern.

This fix is technically necessary and uncontroversial. It doesn’t introduce new behavior or change the on-disk format, and it doesn’t require new tests or documentation since it only affects an internal error-handling path that existing tests already exercise indirectly. The patch is presented as a `fixup!` commit, meaning it should be squashed into the original fifth patch before integration.

The series as a whole is under review, and this fix resolves one of the two substantive correctness concerns Junio raised. The other concern (a resource leak in `bisect.c`) was addressed in a separate fixup patch.
