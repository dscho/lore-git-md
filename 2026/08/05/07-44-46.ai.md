This is the second patch in Patrick Steinhardt’s eight-patch v2 series refactoring the object database (ODB) streaming API. It removes the `is_finished` field from `struct odb_write_stream` and adjusts the loop logic in `builtin/unpack-objects.c` to infer stream completion from zero-byte returns, aligning the write stream’s behavior with the read stream’s design.

The patch touches seven files, primarily updating loops that previously checked `stream->is_finished` to instead break when `odb_write_stream_read()` returns zero. The most involved change is in `builtin/unpack-objects.c`, where the `feed_input_zstream()` function is restructured to ensure at least one byte is produced before yielding, addressing the edge case where zlib decompression might not immediately yield output. Other callers (`object-file.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, and the unit test) are updated with straightforward loop adjustments, replacing the `is_finished` check with a zero-byte return condition.

The change is mechanical and preparatory, with no intended behavior changes. It eliminates redundancy by making the write stream’s completion semantics consistent with the read stream’s existing design, a key step toward the unified `odb_stream` structure introduced later in the series. The patch has already received substantive review from Justin Tobler, who confirmed the loop restructuring aligns the write stream’s behavior with the read stream’s design. No open questions or correctness issues remain for this patch.
