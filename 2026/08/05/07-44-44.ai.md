This is a refactoring patch series targeting the object database (ODB) subsystem, part of the ongoing ODB abstraction effort. The v2 series now consists of eight patches (up from seven in v1) and completes the unification of `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure. The changes are mechanical and touch 23 files, including core object handling (`object-file.c`, `odb/streaming.c`), archive formats (`archive-tar.c`, `archive-zip.c`), and packfile operations (`builtin/pack-objects.c`, `packfile.c`).

The key updates in v2 address feedback from the v1 review: Patch 3/8 now correctly propagates the object type (`stream->type`) to `hash_object_file()` in the in-memory ODB backend, fixing a critical bug that previously hard-coded `OBJ_BLOB` and could cause silent corruption or hash collisions. The series also removes a stale comment in `odb/transaction.h` that assumed blob-only streaming, and adds a new cosmetic Patch 7/8 to rename `struct input_zstream_data` (in `builtin/unpack-objects.c`) to better reflect its role as a stream wrapper. The commit messages have been updated to clarify that renames are deferred to subsequent patches, and the series now explicitly documents file descriptor ownership semantics in Patch 8/8.

The unified `odb_stream` structure supports bidirectional streaming via a direction-agnostic interface, enabling use cases like reading an object and writing it elsewhere without intermediate buffering. The refactor is purely structural, with no intended behavior changes, and aligns with the broader goal of enabling pluggable ODB backends. The series is based on Junio’s "10th batch" (`5b2471720c`) for the upcoming release, targeting `next` or `master` soon.

Key technical details for follow-up discussion include the removal of the `is_finished` field (Patch 2/8) and the loop restructuring in `builtin/unpack-objects.c` to infer completion from zero-byte returns, the introduction of wrapper structures (`struct odb_stream_write` and `struct odb_stream_read`) around the new `odb_stream` base (Patch 5/8), and the standardized function names in Patch 8/8 (e.g., `odb_stream_from_object()` replacing `odb_read_stream_open()`). The series also updates the unit test `t/unit-tests/u-odb-inmemory.c` to match the new API.

The v2 series addresses all known correctness issues and incorporates reviewer feedback, making it a strong candidate for merging. The only remaining open questions are edge cases in the unified API (e.g., error handling for mixed read/write operations) and potential performance regressions in stream-heavy code paths due to the additional indirection introduced by wrapper structures. The planned cosmetic rename in Patch 7/8 may prompt minor follow-up discussion about naming conventions, but this is unlikely to block progress. Reviewers familiar with the ODB (e.g., Justin Tobler, Taylor Blau) may focus on these aspects in subsequent rounds.
