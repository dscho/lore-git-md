This is a brief follow-up in Johannes Schindelin’s 11-patch series fixing unchecked return values flagged by Coverity. The series as a whole adds missing error checks to prevent silent failures in critical code paths.

The eleventh patch originally checked only the return value of `dup(1)` in `bisect_run()`, ensuring that if duplicating stdout fails, the function emits an error and cleans up the temporary file descriptor. Patrick Steinhardt suggested extending the patch to also check the return value of the subsequent `dup2(temporary_stdout_fd, 1)` call, which redirects stdout to a temporary file. If `dup2()` fails, the bisect run would proceed with stdout still pointing to the original destination, potentially masking errors or corrupting output.

Johannes has now updated the patch to include this additional check, following the same pattern already established: verify the return value, emit an `error_errno()` message, close the temporary file descriptor, and break out of the loop. The change is mechanical and aligns with the series’ goal of hardening error handling without altering behavior. No new technical questions or design concerns are introduced; this is purely a completeness fix. The series is now one step closer to being ready for integration.
