This is the fifth patch in Johannes Schindelin’s 12-patch series widening size-related fields in Git’s delta and pack-objects code from `unsigned long` to `size_t` to prevent integer truncation on 64-bit Windows. The series is part of the broader effort to eliminate incorrect `unsigned long` usage in favor of `size_t`.

This patch widens the `mem_usage` counter in `find_deltas()` and the corresponding output parameter in `try_delta()` from `unsigned long` to `size_t`. The change is necessary because `mem_usage` accumulates per-object byte counts (via `SIZE()` and `sizeof_delta_index()`) that are already computed as `size_t`, and leaving it as `unsigned long` would reintroduce truncation on 64-bit Windows. The patch is mechanical and maintains type consistency across the delta-window memory accounting chain, though it notes that `window_memory_limit` (a config-driven value) remains `unsigned long` since it is only compared against `mem_usage` and promotes automatically.

The change is low-risk and uncontroversial, touching only two lines in `builtin/pack-objects.c`. It directly addresses a real truncation risk on 64-bit Windows while keeping the rest of the logic intact. The patch is well-motivated and aligns with the series’ goal of eliminating latent bugs in size-related calculations. No behavior or on-disk format changes are introduced.
