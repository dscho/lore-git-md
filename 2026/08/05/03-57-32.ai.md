This is a two-patch bugfix series targeting the `git maintenance` command, specifically its geometric repack task when promisor packs are present. The series addresses a regression in behavior introduced after promisor packs gained their own geometric progression support (dcc9c7ef47, 2026-01-05).

The first patch modifies how the maintenance task decides between `--geometric` and the all-into-one fallback. Previously, it only considered the ordinary pack progression, which could lead to unnecessary rewrites when promisor packs would have been left intact. Now it evaluates both progressions and only falls back to all-into-one when neither progression would keep a pack above its split threshold.

The second patch adjusts the `--auto` trigger condition to also consider `geometry.promisor_split`. This ensures the task runs when promisor packs are ready for rollup, even if the ordinary pack progression or loose object count wouldn't normally trigger it. The tests demonstrate this by creating three promisor packs where the two smaller ones should roll up while the large one remains untouched.

The changes touch `builtin/gc.c` (the core logic), `t/t5331-pack-objects-stdin.sh` (a minor test adjustment), and `t/t7900-maintenance.sh` (new test coverage). The series is well-motivated with clear before/after behavior descriptions and includes thorough test cases that verify the new promisor-specific logic. This looks like a clean, targeted fix for a real-world issue in partial clone repositories.
