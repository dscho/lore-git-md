This is the final patch in Johannes Schindelin’s 12-patch v2 series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t`. It widens `git_deflate_bound()`—both its parameter and return type—from `unsigned long` to `size_t`, completing the type-consistency chain across all callers (archive-zip, diff, http-push, test helpers, remote-curl, and fast-import).

The patch handles the edge case where the input exceeds zlib’s `uLong` range (>4 GiB on 64-bit Windows) by falling back to zlib’s stored-block formula plus worst-case wrapper overhead, mirroring zlib’s own fallback logic. This ensures correctness without changing behavior for inputs that fit within `uLong`. The commit message cites zlib’s source and an upstream issue for context, and the code itself is guarded by `#if SIZE_MAX > ULONG_MAX` to avoid unnecessary overhead on platforms where `unsigned long` is already 64-bit.

This is a mechanical, low-risk change that directly addresses the truncation risk on 64-bit Windows. All prior patches in the series have already widened the callers, so this patch is uncontroversial and ready for integration. The series as a whole is part of the broader `unsigned long` → `size_t` conversion effort and is motivated by real-world platform-compatibility issues.
