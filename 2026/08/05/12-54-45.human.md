This is a bugfix for `git worktree add` that restores the intended behavior when `-b` or `-B` is used. The patch prevents Git from performing DWIM (Do What I Mean) branch resolution when the user explicitly specifies a new branch name with `-b` or `-B`, fixing a regression introduced in Git v2.42.0.

The issue occurs when running `git worktree add -b <new-branch> <path> <branch>`. Previously, Git would ignore `<new-branch>` and instead DWIM `<branch>` to a remote-tracking branch, creating a worktree with the wrong branch. The fix is straightforward: the DWIM logic in `builtin/worktree.c` now checks whether `new_branch` is set before attempting to resolve `<branch>` to a remote-tracking branch.

The patch includes a new test case in `t/t2400-worktree-add.sh` that verifies the corrected behavior. The test ensures that `git worktree add -b branch ../wt foo` fails with the expected error message (`fatal: invalid reference: foo`) rather than silently DWIMming `foo` to a remote-tracking branch. This aligns with the principle that explicit options (`-b`/`-B`) should take precedence over implicit behavior.
