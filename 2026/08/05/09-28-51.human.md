This is the first patch in Patrick Steinhardt’s six-part series making Git’s on-disk object database (ODB) structures pluggable. It fixes a latent correctness bug in how loose object maps are loaded: the code was always reading from the common `objects/` directory instead of the specific ODB source’s path, which meant it ignored loose object maps in alternates. The bug surfaces in repositories using compatibility hash algorithms (e.g., SHA-256 with SHA-1 compatibility) and is now covered by a new test case that creates two SHA-256 repositories (one acting as an alternate), configures both with SHA-1 compatibility, and verifies `git rev-parse` resolves an object borrowed from the alternate.

The fix itself is small and surgical: `load_one_loose_object_map()` now uses the loose source’s path (`loose->base.path`) instead of the repository’s common path. The patch also drops the redundant `struct repository *` parameter and simplifies the path-handling logic. The test, contributed by Toon Claes, elevates this from a theoretical issue to a confirmed regression fix with clear reproduction steps.

This patch is a strong candidate for early graduation: it’s a correctness fix, has thorough test coverage, and the change is minimal and well-justified. The rest of the series builds on this foundation, but this piece stands alone. Reviewers have already signaled approval, and the fix aligns with the broader ODB abstraction effort without introducing new abstractions of its own. If you care about multi-backend correctness or the ongoing ODB work, this patch is worth a quick look.
