Thread identity
Subject: `git rebase -x` with `git commit --amend` loses notes
Series version: standalone bug report (no patch series)
Originating author: D. Ben Knoble
Thread type: bug report

Core problem or goal
`git rebase -x` (with an external command) combined with `git commit --amend` fails to rewrite notes attached to the tip commit, even when `notes.rewriteref` is configured to include the relevant notes ref (`refs/notes/benknoble/commits`). The bug is specific to the interaction between `-x` and `--amend`: plain `--amend` or plain rebase works correctly.

Current status
Root cause confirmed; two proposed fix strategies now exist. Phillip Wood diagnosed the issue: the rebase machinery records the new commit OID *before* the external command runs, so `git commit --amend` creates a new OID that the notes-rewriting step (post-rebase) does not map correctly. The notes are copied from the old OID to the pre-amend OID, not the post-amend one, making them appear lost. Two approaches are now under discussion:
1. **Post-amend update** (prior work): Update the rebase’s internal `rewritten` file after `git commit --amend` (Phillip’s stalled `wip/rebase-update-rewritten` branch). This worked for simple `exec` amend cases but stalled on interactive editing robustness.
2. **Pre-exec copy** (new proposal): Copy notes *before* stopping for an `exec` or `edit` command, allowing `git commit --amend` to handle note copying directly to the amended commit. This avoids OID-mapping issues but may complicate conflict handling during interactive editing.

Key technical details
- Subsystems: rebase, notes
- Commands: `git rebase -x`, `git commit --amend`
- Config keys: `notes.rewriteref`, `core.notesref`
- Notes ref: `refs/notes/benknoble/commits`
- Files touched: rebase state directory (`rewritten` file)
- Behavior: notes are lost only when `-x` and `--amend` are combined; plain `--amend` or plain rebase works as expected
- On-disk: notes ref is not updated during rebase because the `rewritten` file maps the old OID to the pre-amend OID, not the post-amend one
- New detail: Preemptive note copying could sidestep the OID-mapping issue entirely, but may require conflict handling for interactive edits

Open questions and loose ends
- Test coverage: no minimized test case yet; reproduction sketch provided but not formalized
- Regression: unclear whether this is a long-standing edge case or a recent regression
- Fix completeness: Neither approach has been fully implemented or tested for edge cases (e.g., interactive editing conflicts, performance impact of pre-exec note copying)
- Implementation trade-offs: Pre-exec copying may simplify the fix but could introduce new complexity for conflict resolution during interactive rebase
