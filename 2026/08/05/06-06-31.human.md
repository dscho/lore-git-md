This is a reply in the ongoing ODB streaming API refactoring series, specifically addressing Junio C Hamano’s review of Patch 3/7. The patch supports streaming arbitrary object types (not just blobs) into the object database, a key step toward unifying the read and write streaming APIs.

Patrick acknowledges a critical bug Junio identified: the in-memory ODB backend was computing the object name (`oid`) using `OBJ_BLOB` even when streaming non-blob objects, which could lead to hash collisions or silent corruption. The fix is straightforward—passing `stream->type` to `hash_object_file()`—and Patrick has already implemented it. This resolves the blocker Junio raised, clearing the way for the series to proceed once the fix is incorporated into the next revision.

The exchange also clarifies the motivation for unifying the read and write streams: despite their names, both stream types fundamentally do the same thing (streaming data), differing only in whether the object type is encoded in the stream itself. This refactoring is part of the broader ODB abstraction effort to enable pluggable backends, though the current series is purely structural with no behavior changes.

No other technical issues are raised in this reply, and the discussion remains focused on the correctness fix. The series is still under review, with the critical bug now addressed and the unification goal unchanged.
