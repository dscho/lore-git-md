This is the third patch in Patrick Steinhardt’s six-patch series making on-disk ODB structures pluggable, new in v3. It refactors environment variable handling for object database creation, moving the logic from `apply_repository_format()` into `odb_new()` itself.

The patch addresses a practical problem: the current code handles `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` in `apply_repository_format()`, but a future change will defer ODB construction to a later point, requiring a second call to `odb_new()`. Rather than duplicate the environment variable logic, Patrick moves it into `odb_new()`, making the function self-contained. This also aligns with a longer-term goal of moving alternate handling into the "files" backend itself, as noted in the commit message.

The change is mechanical: `odb_new()` gains an `enum odb_new_flags` parameter, with `ODB_NEW_HONOR_ENV` controlling whether environment variables are respected. The function now allocates and frees its own copies of the environment variable values, and `apply_repository_format()` passes the flag through instead of managing the strings itself. The unit test for the in-memory ODB backend is updated to pass `0` instead of empty strings.

This patch is uncontroversial and ready for merging. It simplifies the control flow in `apply_repository_format()` and prepares the ground for future work without altering behavior. The files touched are `odb.c`, `odb.h`, `setup.c`, and a unit test; the changes are confined to ODB initialization plumbing.
