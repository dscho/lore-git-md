This is the second patch in Johannes Schindelin’s v2 series addressing unchecked return values flagged by Coverity. It fixes a silent failure in `builtin/config.c` where `show_editor()` ignores the return value of `launch_editor()`, causing `git config edit` and `git config --edit` to report success even when the editor fails to launch.

The patch is a straightforward bugfix: `show_editor()` now checks `launch_editor()`’s return value and propagates failure by returning `-1`. The two callers (`cmd_config_edit` and `cmd_config`) already handle negative returns by exiting with an error, so no additional changes are needed. Patrick Steinhardt reviewed this patch and confirmed the approach is correct, noting that `launch_editor()` already emits its own error messages, so the caller only needs to propagate the failure.

The change is minimal (four lines added, one removed) and uncontroversial. It aligns `git config`’s editor-launching behavior with other Git commands like `git commit` and `git rebase --edit-todo`, which already propagate editor failures. No new behavior, config keys, or on-disk formats are introduced. The patch is ready for integration.
