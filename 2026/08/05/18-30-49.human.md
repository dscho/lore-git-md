This is the v2 revision of an 11-patch series that fixes unchecked return values identified by Coverity. The patches add missing error checks to various Git subsystems—HTTP, config editing, reftable, `git last-modified`, platform compatibility, transport helpers, and bisect—without changing behavior or on-disk formats.

The series is now complete after addressing all substantive review feedback. Junio C Hamano raised four correctness concerns (in the fifth and ninth patches), which Johannes Schindelin resolved with fixup patches. Patrick Steinhardt reviewed the second and seventh patches, confirming their correctness, and suggested two design improvements (centralizing error handling in `get_terms()` and checking `dup2()` in the eleventh patch), both of which are now implemented. The only remaining surface-level note was Steinhardt’s observation about inconsistent indentation in `compat/pread.c`, which does not affect functionality.

Each patch is small and focused, adding error checks to functions like `curl_easy_duphandle`, `deflateInit`, `repo_parse_commit`, `lseek`, `dup`, and `strbuf_getline_lf`. The fixes either `die()` on unrecoverable errors or propagate failures upward, ensuring silent failures are caught. For example, `git config --edit` now exits with an error if `launch_editor()` fails, and `bisect_run()` handles `dup()`/`dup2()` failures gracefully. The bisect subsystem received particular attention: the ninth and tenth patches ensure `get_terms()` properly cleans up resources and centralizes error handling, while the eleventh patch prevents silent failures when redirecting stdout.

The series is well-motivated and uncontroversial. The commit messages clearly explain the Coverity-reported issues and the fixes, and the patches are mechanical enough to be low-risk. No new symbols or on-disk formats are introduced, and existing tests implicitly cover the new error paths. This looks like a solid, incremental hardening effort that’s ready for final review.
