This is the eleventh patch in Johannes Schindelin’s 12-patch **platform compatibility** series, upstreaming Git for Windows build and runtime adjustments into mainline Git.

The patch addresses a regression in the MSYS2 runtime (introduced between versions 2.4.1 and 2.6.0) that changed how locales are initialized. Without intervention, Git for Windows starts with a locale derived from the current code page, which breaks handling of non-ASCII characters in command-line arguments. The symptom is that `git clone` or `git fetch` fails when shelling out to `git-upload-pack` with paths containing non-ASCII characters, because the shell misinterprets the command line.

The fix is minimal: in `compat/mingw.c`, the `setup_windows_environment()` function now sets `LC_CTYPE=C.UTF-8` if none of `LC_ALL`, `LC_CTYPE`, or `LANG` are already set. This ensures consistent UTF-8 handling for command-line arguments without affecting other platforms. The change is Windows-specific and has no impact on non-Windows builds.

The commit message is clear and links to a GitHub issue documenting the symptom. This looks like a targeted, well-motivated bugfix for a real-world Windows compatibility problem. If you care about non-ASCII path handling on Windows, this patch is worth noting; otherwise, it’s a safe, self-contained fix that can be ignored.
