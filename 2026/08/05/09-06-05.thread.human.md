This thread is a bug report from Adien Akhmad about a regression in Git’s credential helper behavior during HTTP redirects. When `git push` follows a 301 redirect, the `wwwauth[]` attribute—containing the `WWW-Authenticate` header from the server—is stripped from the credential helper’s input. This breaks helpers like `git-credential-oauth`, which rely on the header to detect the required authentication scheme. The issue is reproducible by pushing to a remote that 301-redirects before responding with a 401 and `WWW-Authenticate` header, and it does not occur in direct (non-redirect) requests.

The report highlights a specific interaction between Git’s HTTP redirect handling (via libcurl 8.15.0) and the credential helper protocol, but no patch or proposed fix is included. The affected helper, `git-credential-oauth`, is used with a self-hosted Forgejo instance. Key details include the `wwwauth[]` attribute, the HTTP 301/401 flow, and the regression’s impact on authentication workflows. So far, this is the first email in the thread, so no responses or resolutions have been shared.
