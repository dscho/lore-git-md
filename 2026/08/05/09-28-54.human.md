This is the fourth patch in Patrick Steinhardt’s six-patch series making Git’s on-disk object database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort, and this patch prepares the ground for the upcoming pluggable directory creation mechanism by deferring ODB creation until after repository format configuration.

The patch splits the current `apply_repository_format()` function into two phases: first, it configures the repository format and skips ODB creation (using the new `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag), then it creates the ODB in a separate `create_object_database()` function. This separation ensures that both steps happen in the same place (`init_db()`), avoiding an awkward intermediate state where the ODB is configured but not yet usable. The change is mechanical and touches only `setup.c` and `setup.h`, introducing the new flag and renaming `create_object_directory()` to `create_object_database()` to reflect its broader responsibility.

This patch is uncontroversial and ready for merging. It doesn’t change behavior but lays the groundwork for the next patch, which introduces the pluggable `create_on_disk` callback. The split is clean and aligns with the series’ goal of making ODB backend initialization more flexible. The first patch in the series (a correctness fix for loose-object map loading) is already slated for early graduation to `next`, and this patch is a logical follow-up that should proceed smoothly.
