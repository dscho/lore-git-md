This is a user support response from Jeff King (Peff) addressing Randall S. Becker’s report of a regression in Git’s textconv feature. Peff explains why textconv filters sometimes receive the actual working-tree file and other times a temporary file, clarifying that this behavior is intentional and tied to diff operations involving the index. However, he does not address the core issue Randall raised—why the temporary file is *empty* for binary files on NonStop since Git 2.50.

Peff’s explanation focuses on the optimization where Git reuses the working-tree file instead of creating a tempfile when the file is clean and one diff endpoint is the index. He demonstrates this with a text-based example, showing that `git diff HEAD^` or `git diff --cached HEAD^` will pass the working-tree file to the filter, while `git show HEAD` will always use tempfiles. This distinction is unrelated to the regression Randall reported, which specifically involves empty tempfiles for binary files, not the choice between tempfiles and working-tree files.

The response does not reproduce the empty tempfile issue, even for files with null bytes, leaving the root cause of the regression unresolved. Peff’s analysis suggests the problem may be platform-specific (NonStop’s handling of null bytes or I/O behavior) or tied to a subtle interaction in Git’s tempfile creation logic for binary files. The thread remains open, with no patch or workaround proposed, and the key question—whether the empty tempfile behavior is a bug or intentional—still unanswered. Randall’s follow-up will likely need to focus on isolating the binary-file-specific aspect of the issue.
