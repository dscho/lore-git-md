This thread is about a 12-patch series from Johannes Schindelin (Dscho) that upstream Git for Windows-specific build and runtime adjustments into the main Git codebase. The series addresses hard-coded assumptions in the build system, MSYS2 integration, linking behavior, deprecated artifacts, a locale-handling regression, and direct `git.exe` invocation—all without affecting non-Windows platforms.

The series is now at v2, with the only change from v1 being a fix to align Meson’s `MINGW_PREFIX` handling with the Makefile’s. Most patches are uncontroversial and ready for integration, but one issue remains open: whether to guard against an empty `MSYSTEM` export in Patch 12. Johannes declined to add build-system guards, arguing the scenario is too unlikely, but Junio C Hamano has now restated his position, pointing to existing patterns in `config.mak.uname` where similar variables are guarded to avoid exporting empty strings. This is a matter of consistency rather than new complexity, and the ball is back with Johannes to either implement the guard or justify an exception.

The rest of the series is in good shape, with no objections from Junio or other reviewers. Patches 10 (simplifying path logic for `ETC_GITCONFIG`/`ETC_GITATTRIBUTES`) and 11 (fixing the locale-handling regression) are particularly straightforward and could likely be merged independently if the `MSYSTEM` discussion drags on. Junio has also floated the idea of removing dashed-form executables (e.g., `git-commit`) entirely in Git 3.0, but this is a forward-looking proposal and not a blocker for the current series. The series remains under review, with no merge intent signaled yet.
