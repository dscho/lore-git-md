This thread is about a 12-patch series from Johannes Schindelin (Dscho) that upstream Git for Windows build and runtime adjustments into the main Git codebase. The series addresses hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, a locale-handling regression in the MSYS2 runtime, and direct `git.exe` invocation—all without affecting non-Windows platforms. The initial version (v1) is under review, with no merge status reported yet.

Dscho positions the series as routine build-system adjustments, including enabling Python support, allowing alternative compilers (e.g., Clang), removing deprecated compiler flags, refining linker behavior, and phasing out dashed-form executables (e.g., `git-commit`). One patch fixes a real-world locale-handling regression in MSYS2, and another allows `git.exe` to be called directly, reducing runtime overhead. Junio C Hamano, the maintainer, has reviewed the series and flagged a cross-build-system inconsistency in one patch: the Meson build retains a leading slash in `MINGW_PREFIX`, while the Makefile strips it, which could cause path-handling issues on Windows.

In this latest reply, Dscho acknowledges Junio’s feedback and commits to fixing the inconsistency in the next iteration by aligning Meson’s behavior with the Makefile’s. No other objections or changes are raised. The series remains in a proposed state, with the only open question being this minor build-system alignment. The broader discussion about removing dashed-form executables entirely in Git 3.0 is noted but not a blocker for this series.
