This thread is a 12-patch series from Johannes Schindelin (Dscho) aimed at upstreaming Git for Windows build and runtime adjustments into the main Git codebase. The series addresses hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, and a locale-handling regression in the MSYS2 runtime, all while ensuring no impact on non-Windows platforms.

The first 11 patches, already summarized, cover a range of improvements: enabling Python support, allowing alternative compilers like Clang, removing deprecated compiler flags, refining linker behavior, dynamically setting build paths, disabling dashed-form executables, and fixing a locale-handling regression. The series is under review, with no objections or substantive feedback recorded yet.

The newly arrived 12th patch completes the series by allowing `git.exe` to be called directly instead of through the Git wrapper, eliminating an extra process hop. It initializes the `MSYSTEM` environment variable and constructs a `PATH` that ensures scripts and tools are found in the expected locations. This change is Windows-specific, addresses a long-standing Git for Windows quirk (GitHub issue #2283), and includes a new test to verify the environment setup. The patch is designed to avoid breaking existing workflows, as the Git wrapper remains functional. With this final patch, the series is now complete and ready for further review.
