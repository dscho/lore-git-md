This thread is about a 12-patch series from Johannes Schindelin (Dscho) that upstream Windows-specific build and runtime adjustments into Git’s main codebase. The series is now at v2, with most patches uncontroversial and ready for integration.

The key focus is improving Windows compatibility without affecting other platforms. Recent attention has centered on Patch 11, a targeted bugfix for a locale-handling regression in the MSYS2 runtime (versions 2.4.1–2.6.0). This regression broke Git’s ability to handle non-ASCII characters in command-line arguments when shelling out to subprocesses, causing failures in operations like `git clone` or `git fetch` when repository paths contained such characters. The fix is minimal—setting `LC_CTYPE=C.UTF-8` as a fallback in `compat/mingw.c`—and has no impact on non-Windows platforms. It directly addresses a real-world issue (GitHub issue #1036) and is uncontroversial.

Other notable patches include enabling Python support for MinGW builds (Patch 1), removing deprecated compiler flags (Patches 3 and 4), and simplifying environment-variable logic (Patches 6, 8, and 10). Patch 9 disables generation of dashed-form executables (e.g., `git-commit`) for Windows, aligning with their long-standing deprecation. The only unresolved discussion involves Patch 12, where Junio C Hamano raised a potential correctness issue with environment-variable initialization, but Dscho declined to address it, arguing the scenario is too unlikely to warrant changes.

The series is under review, with no merge status reported. Most patches are ready for integration, and the locale fix in Patch 11 is a clear win for Windows users. The remaining open question is minor and unlikely to block progress.
