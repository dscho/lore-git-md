This thread is about a 12-patch series from Johannes Schindelin (Dscho) that upstreamed Git for Windows-specific build and runtime adjustments into the main Git codebase. The goal is to improve Windows compatibility—enabling Python support, compiler flexibility, UCRT64 compatibility, MSYS2 integration, and direct invocation of `git.exe`—without affecting other platforms.

The series is now at v2, with only minor changes from v1 to address a cross-build-system inconsistency in how Meson and the Makefile handle `MINGW_PREFIX`. Patches 10 (simplifying `ETC_GITCONFIG`/`ETC_GITATTRIBUTES` path logic) and 11 (fixing a locale-handling regression in MSYS2) are uncontroversial and ready for integration. The only remaining open question is whether to guard against an empty `MSYSTEM` export in Patch 12, which Johannes declined to address, arguing the scenario is too unlikely to warrant additional complexity. Junio C Hamano raised the concern but did not block the patch.

Key changes include enabling Python in MinGW builds, removing deprecated compiler flags, refining linker behavior for 32-bit vs. 64-bit builds, making MSYS2-specific code conditional on the `MSYSTEM` environment variable, and allowing `git.exe` to be called directly (eliminating a process hop). The series touches build files, `compat/mingw.c`, and one test (`t0060-path-utils.sh`), with no changes to on-disk format or non-Windows behavior.

The patches are incremental and well-motivated, with clear commit messages. The unresolved `MSYSTEM` discussion is minor and unlikely to block integration. The series is effectively complete and ready for Junio to pick up.
