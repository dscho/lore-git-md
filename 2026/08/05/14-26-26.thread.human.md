This thread is about a 12-patch series from Johannes Schindelin (Dscho) that upstreamed Git for Windows-specific build and runtime adjustments into the main Git codebase. The goal is to improve Windows compatibility—enabling Python support, compiler flexibility, UCRT64 compatibility, MSYS2 integration, and fixing a locale-handling regression—without affecting non-Windows platforms. The series is now at version 1, with review feedback incorporated.

Junio C Hamano, the maintainer, has reviewed the series and identified two issues. The first, in Patch 8, was a cross-build-system inconsistency in how `MINGW_PREFIX` is handled between Make and Meson; Dscho has committed to fixing this in the next iteration. The second, raised in the latest email, is a potential edge case in Patch 12 where an empty `MSYSTEM` environment variable could be exported if undefined at build time. Junio suggested a simple guard in `config.mak.uname` to prevent this, which Dscho is likely to address in the next version.

The series touches build files, `compat/mingw.c`, and one test (`t0060-path-utils.sh`), with no changes to on-disk formats or non-Windows behavior. Key adjustments include removing deprecated build artifacts, refining linker flags, and enabling direct `git.exe` invocation (eliminating an extra process hop). Junio also noted that the deprecation of dashed-form executables (e.g., `git-commit`) could be completed in Git 3.0, though this is a forward-looking suggestion, not a blocker. The series remains under review, with no merge status reported.
