This is a fixup patch for the fifth patch in Johannes Schindelin’s 11-patch series addressing Coverity-identified unchecked return values. The series as a whole adds missing error checks to prevent silent failures in Git’s codebase, and this specific patch corrects a resource leak in `builtin/last-modified.c`.

The issue is in the `--not` queue handling within `last_modified_run()`: when a commit fails to parse, the original patch skipped it with `continue`, bypassing cleanup of the `active_paths` slab associated with that commit. Junio C Hamano identified this as a correctness concern, and the fix replaces `continue` with `goto cleanup` to ensure the slab is properly released even for unparsable commits. The change is minimal (one line) and aligns the error path with the function’s existing resource-management pattern.

No new tests or documentation are needed, as the fix only affects an internal error-handling path that existing tests already exercise indirectly. The patch is presented as a `fixup!` commit, signaling it should be squashed into the original fifth patch before integration. This is a narrowly scoped but technically necessary correction; the series remains under review, with two design questions from Patrick Steinhardt still open on the tenth and eleventh patches.
