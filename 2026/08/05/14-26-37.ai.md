This is the eleventh patch in Johannes Schindelin’s 12-patch **platform compatibility** series for MinGW/Windows. It addresses a locale-handling regression introduced in the MSYS2 runtime between versions 2.4.1 and 2.6.0, which caused Git for Windows to mishandle command-line arguments containing non-ASCII characters when shelling out to subprocesses like `git-upload-pack`.

The fix is minimal: in `compat/mingw.c`, the `setup_windows_environment()` function now sets `LC_CTYPE=C.UTF-8` as a fallback if no locale-related environment variables (`LC_ALL`, `LC_CTYPE`, or `LANG`) are already defined. This ensures that the POSIX emulation layer starts with a UTF-8 locale, preventing the runtime from misinterpreting command-line arguments based on the system’s current code page. The change is Windows-specific and has no effect on other platforms.

The commit message provides clear context: the issue was triggered by an upstream MSYS2 change (d16a56306d) and manifests as failures when Git shells out to subprocesses with non-ASCII paths. The fix is narrowly scoped to the environment setup and does not alter Git’s core logic. Test coverage is implied by the linked GitHub issue (#1036), which documents the symptom and likely includes reproduction steps.

This patch is a targeted bugfix for a real-world Windows compatibility issue. It is unlikely to be controversial, as it only affects the MSYS2 runtime’s locale initialization and aligns with Git’s general preference for UTF-8. If you maintain or use Git on Windows, this is worth noting; otherwise, it can be safely ignored. The series as a whole remains under review, with no merge status reported.
