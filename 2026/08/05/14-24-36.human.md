This is the sixth patch in Harald Nordgren’s **`--delete-merged`** series, now merged to **'next'**. It adds a per-branch opt-out mechanism via the `branch.<name>.deleteMerged` config key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The implementation is straightforward: during candidate filtering in `delete_merged_branches()`, the code checks for `branch.<name>.deleteMerged=false` using `repo_config_get_bool()`. If set, the branch is skipped with a non-quiet message explaining the opt-out. The config is ignored by traditional `git branch -d`, which continues to use the normal merge check. Documentation updates to `branch.adoc` and `git-branch.adoc` clarify the behavior, and the test suite verifies both the opt-out skip and explicit deletion.

Phillip Wood’s earlier review suggested a mechanical test improvement—verifying branch state via `for-each-ref` using the `check_branches` helper—which this version incorporates. The patch is well-tested, clearly motivated, and aligns with the series’ safety-focused design. No substantive issues remain; this is a polished, ready-to-merge feature.
