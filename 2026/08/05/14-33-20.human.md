This is a **fixup patch** for the ninth patch in Johannes Schindelin’s 11-patch series addressing Coverity-reported unchecked return values. The series systematically adds missing error checks to harden Git against silent failures, and this fixup resolves a **resource leak** in the bisect subsystem’s `get_terms()` function.

The leak occurs when the first line of the `BISECT_TERMS` file is read successfully but the second fails (returning `EOF`). The original patch correctly detects the failure and jumps to `finish`, but it does not free `terms->term_bad`, which was allocated by `strbuf_detach()`. The fix adds a single line—`FREE_AND_NULL(terms->term_bad)`—before the `goto finish`, ensuring the struct is left in a clean state. This aligns with Git’s established practice of thorough resource cleanup in error paths.

Junio C Hamano identified the issue and provided the fixup, which Johannes Schindelin promptly accepted. The change is narrowly scoped and mechanical, addressing only the leak without altering the patch’s overall goal or behavior. It does not interact with the two open design questions Patrick Steinhardt raised about the ninth patch (whether `get_terms()` should centralize error handling for `NULL` terms), so those discussions remain unaffected.

The fixup is uncontroversial and a prerequisite for the ninth patch’s readiness. The rest of the series—including the other 10 patches—is unaffected by this change. If the series progresses, this fixup will be squashed into the ninth patch before integration.
