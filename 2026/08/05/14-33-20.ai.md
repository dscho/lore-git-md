This is a **fixup patch** for the ninth patch in Johannes Schindelin’s 11-patch series addressing Coverity-reported unchecked return values. The series systematically adds missing error checks to harden Git against silent failures, and this fixup resolves a **resource leak** in the bisect subsystem’s `get_terms()` function that Junio C Hamano identified during review.

The leak occurs in the error path where the first line of the `BISECT_TERMS` file is read successfully (populating `terms->term_bad`), but the second line fails (returning `EOF`). The original patch correctly sets `res = -1` and jumps to `finish`, but it does not free `terms->term_bad`, which was allocated by `strbuf_detach()`. This leaves the struct in a partially initialized state with a dangling pointer, risking a leak if the caller does not handle the `-1` return value by calling `free_terms()`. The fix adds a single line—`FREE_AND_NULL(terms->term_bad)`—before the `goto finish`, ensuring proper cleanup.

The fix is narrowly scoped and mechanical, addressing only the leak without altering the patch’s overall goal or behavior. Junio’s review explicitly frames this as a targeted correction, and Johannes’s reply confirms the fix without further discussion. This fixup is a prerequisite for the ninth patch’s readiness and does not interact with the two open design questions Patrick Steinhardt raised about the series (centralizing error handling in `get_terms()` and checking `dup2()` in the eleventh patch). The rest of the series remains unaffected.

This patch is unlikely to be controversial, as it aligns with Git’s established practice of ensuring resource cleanup in error paths. The series as a whole continues to address a real and well-motivated problem—Coverity-identified unchecked return values—with clear, incremental improvements. The fixup itself is minimal and correct, and the broader effort to harden error handling in Git is uncontested.
