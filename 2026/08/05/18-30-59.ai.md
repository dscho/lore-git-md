This is the tenth patch in a v2 series addressing unchecked return values identified by Coverity. It centralizes error handling in the bisect subsystem by extending `get_terms()` to accept a `file_missing_is_ok` flag, ensuring all callers properly handle failures when reading the `BISECT_TERMS` file.

The patch modifies `builtin/bisect.c` to check the return value of `get_terms()` at all six call sites. Previously, most callers ignored the return value, allowing empty or `NULL` term strings to propagate downstream, which produced nonsensical ref names (e.g., `refs/bisect/` with no suffix) and confusing error messages. The new `file_missing_is_ok` flag distinguishes between callers that treat a missing `BISECT_TERMS` file as an error (e.g., `bisect_terms()`) and those that tolerate its absence (e.g., `cmd_bisect__next()`). This deduplicates error messages and simplifies caller logic.

The change is minimal and mechanical: each call site now checks `get_terms()`'s return value and propagates errors upward with a consistent error message (`"no terms defined"`). The patch resolves Patrick Steinhardt’s design suggestion from the v1 review, which proposed centralizing error handling to avoid redundant checks at call sites. No new behavior is introduced; the patch only ensures existing error conditions are surfaced clearly.

This patch is uncontroversial and ready for integration. It complements the ninth patch (which added error checks for `strbuf_getline_lf()` in `bisect.c`) and the eleventh patch (which checks `dup()`/`dup2()` return values). The series as a whole is now complete, with all substantive review feedback addressed. The bisect subsystem’s error handling is now more robust, preventing silent failures when the `BISECT_TERMS` file is missing or truncated.
