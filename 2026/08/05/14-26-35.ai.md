This is the ninth patch in Johannes Schindelin’s 12-patch **platform compatibility** series for MinGW/Windows. It stops Git for Windows from creating hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/`.

The patch adds a single line to `config.mak.uname` under both the generic Windows and MINGW sections: `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo`. This variable tells the build system to skip generating the dashed-form hard-links, which have been deprecated since Git 1.5.4 (February 2008). The change affects only Windows builds; non-Windows platforms continue to generate the links as before.

The motivation is practical: the hard-links add about 30 seconds to every Windows build, confuse some Windows Explorer versions into reporting inflated disk usage, and have generated numerous user bug reports over the years. The patch is a small, targeted step toward phasing out the dashed form entirely on Windows, aligning with the long-standing deprecation. No behavior change is expected for end users, since scripts that still rely on the dashed form will continue to work via the `git` executable’s built-in command dispatch.
