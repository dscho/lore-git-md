This is the eighth patch in Johannes Schindelin’s 12-patch **platform compatibility** series for MinGW/Windows, continuing the theme of replacing hard-coded build assumptions with values derived from MSYS2’s environment.

The patch removes hard-coded defaults for the `MSYSTEM` environment variable and the installation prefix (`/mingw32`, `/mingw64`, `/clangarm64`) in `config.mak.uname`, CMake, and Meson. Instead, it uses the `MINGW_PREFIX` and `MSYSTEM` variables that MSYS2 already sets at build time. When `MINGW_PREFIX` is missing (as in Git for Windows’ minimal SDK), it falls back to `/$(MSYSTEM in lowercase)`. The change is guarded by the same `ifneq (,$(MSYSTEM))` check that already controls other MinGW-specific code, so it affects only Windows builds.

CMake keeps its hard-coded platform assignments (`MINGW64`, `CLANGARM64`, `MINGW32`) because there is no clear way to make them dynamic, but Meson gains two new build options (`msystem` and `mingw_prefix`) that serve as fall-backs when the environment variables are unset.

The patch is a clean, mechanical refactoring that aligns the build system with MSYS2’s conventions. It does not change behavior for non-Windows platforms and is unlikely to be controversial. If you are tracking the series for Windows build hygiene, this is a routine step; otherwise, it can be safely ignored.
