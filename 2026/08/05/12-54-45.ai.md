This is the third iteration of a bugfix for `git worktree add`. The patch prevents DWIM (Do What I Mean) behavior from overriding the explicit `-b` or `-B` options when creating a new worktree. The regression was introduced in Git v2.42.0 and causes the command to ignore the user-specified branch name in favor of a remote-tracking branch, which is unintuitive and contrary to the documented behavior of `-b`/`-B`.

The change is minimal and surgical: in `builtin/worktree.c`, the DWIM logic is now guarded by a check for `!new_branch`, ensuring it only triggers when no explicit branch name is provided. The test in `t/t2400-worktree-add.sh` verifies that `git worktree add -b branch ../wt foo` fails with the expected error message (`fatal: invalid reference: foo`) rather than silently creating a worktree for a remote-tracking branch. The test setup uses `setup_remote_repo` to create a controlled environment with a remote repository, avoiding redundant initialization steps.

This version (v3) incorporates Junio C Hamano’s feedback from v2, which focused on preserving warning behavior for edge cases (e.g., using `-b` with `HEAD`) and refining the test to be more precise. The commit message has also been updated to use consistent single-quoted command invocations, addressing a minor stylistic nit. The patch is now narrowly scoped to the regression, with no unintended side effects on related functionality.
