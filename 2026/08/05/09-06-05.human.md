This is a bug report about a regression in Git’s credential helper protocol. When a `git push` follows an HTTP 301 redirect, the `wwwauth[]` attribute (which carries the WWW-Authenticate header from the server) is silently dropped before the credential helper is invoked. The reporter expects the attribute to be preserved, just as it is when the same server is accessed directly without a redirect. The context is a self-hosted Forgejo instance and the `git-credential-oauth` helper, which relies on `wwwauth[]` to detect the authentication scheme. The report includes reproduction steps, system details, and a clear description of the discrepancy. It looks like a real, narrowly scoped issue that should be straightforward to verify and fix.
