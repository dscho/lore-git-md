This is a maintainer follow-up in the revived `writev(3p)` wrapper series. Junio C Hamano confirms Johannes Sixt’s assessment that Git’s current use cases for `writev()`—pktline transmission in `sideband.c` and cat-blob responses in `fast-import.c`—do not require atomicity. Both scenarios involve single-writer pipes, so the lack of atomicity in an emulated `writev()` implementation (which would loop over `write(2)` calls) poses no correctness risk. Junio proposes documenting this limitation explicitly and treating any future attempt to use `writev()` in a multi-writer context as a bug. This removes the last technical obstacle to the series: the API can now be implemented safely without atomicity guarantees, and the naming (`git_write_gather()`) and platform-compatibility design are settled. The only remaining open questions are maintainer appetite (whether the performance gains justify the complexity) and the absence of a range-diff to the reverted version, neither of which Junio addresses here. Patrick Steinhardt is still at an offsite, so no immediate reroll is expected.
