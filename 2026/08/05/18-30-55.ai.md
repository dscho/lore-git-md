This is the sixth patch in the v2 Coverity unchecked-return-values series, targeting the `compat/pread.c` file. The patch adds a missing error check for the initial `lseek(fd, 0, SEEK_CUR)` call in `git_pread()`. Without this check, a failed `lseek()` (e.g., on a non-seekable descriptor like a pipe) leaves `current_offset` as `-1`, which is later passed to `lseek(fd, -1, SEEK_SET)`. This can either silently corrupt the file position or fail with `EINVAL` on some platforms. The fix is minimal: two lines added to return `-1` immediately if the initial `lseek()` fails, matching the existing error-handling pattern for the other `lseek()` calls in the function.

The patch is uncontroversial and technically complete. It directly addresses the Coverity-identified issue and aligns with the series' goal of hardening error paths. Patrick Steinhardt noted in a surface-level review that the new code uses tabs for indentation while the rest of the file uses spaces, but this does not affect correctness. The fix is self-contained and does not introduce new behavior or dependencies. The existing test suite implicitly exercises this code path, so no additional test coverage is needed. This patch is ready for integration alongside the rest of the series.
