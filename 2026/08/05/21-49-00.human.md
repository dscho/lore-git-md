This is a refactoring patch in Tian Yuchen’s three-part series to clean up repository configuration handling in `environment.c`. The patch simplifies three getter functions—`repo_protect_ntfs`, `repo_protect_hfs`, and `repo_ignore_case`—by removing redundant parentheses and NULL checks for the `repo` parameter. The commit message justifies the change by noting these getters are only called with non-NULL repositories, making the checks unnecessary.

Junio C Hamano, the maintainer, has reviewed this specific patch and explicitly approves it, calling the removal of the NULL checks "definitely an improvement" given the assumption that `repo` is always non-NULL. The diff is small and mechanical, touching only the three functions without altering their behavior or signatures. No new tests or documentation changes are introduced here.

This patch is the first in the series and sets the stage for the subsequent changes: patch 2 unifies documentation for these getters, and patch 3 reorders fields in the `repo_config_values` structure. While Junio has raised concerns about those later patches—particularly around documentation scope and the maintainability of field reordering—this first patch appears uncontroversial and ready to proceed.

The patch is well-motivated and clearly scoped, making it easy to verify. Reviewers may still want to confirm that all callers indeed pass non-NULL repositories, but the current usage patterns and Junio’s approval suggest the change is safe.
