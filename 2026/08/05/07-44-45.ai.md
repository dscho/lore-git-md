This is the first patch in Patrick Steinhardt’s v2 series refactoring the object database (ODB) streaming API. It moves the expected object size from function parameters into the `struct odb_write_stream` itself, making the stream self-describing. The change touches 14 files, primarily in the ODB layer (`odb/`, `object-file.c`) and a unit test (`t/unit-tests/u-odb-inmemory.c`).

The patch is mechanical and preparatory: it embeds the `size` field in the write stream structure and updates all callers to use `stream->size` instead of passing the size as a separate argument. This brings `odb_write_stream` closer to the existing `odb_read_stream` design, setting the stage for the later unification in Patch 5/8. The commit message is clear and the diff is straightforward, with no behavior changes intended.

No new edge cases or open questions are introduced here; the patch is purely structural. Reviewers familiar with the ODB (e.g., Justin Tobler) have already endorsed the approach in v1, calling it sensible. The only follow-up discussion likely to arise is whether the field name (`size`) is sufficiently descriptive, but this is a minor cosmetic point and not a blocker. The patch is ready for integration and should land as-is.
