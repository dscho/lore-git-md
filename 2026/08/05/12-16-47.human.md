This is a bugfix for `git worktree add` addressing a regression introduced in Git v2.42.0. The patch ensures that when `-b` or `-B` is explicitly provided, the command does not DWIM (Do What I Mean) the branch name to a remote-tracking branch, which could otherwise override the user’s intended branch name.

The v2 update incorporates feedback from Junio C Hamano, refining the fix to avoid unintended side effects. The key change moves the DWIM suppression logic inside the `ac == 2` branch, wrapping it in a `!new_branch` condition. This preserves warning behavior (e.g., for invalid references) while still preventing DWIM when `-b` or `-B` is used. The test case has also been improved: it now validates the error message (`fatal: invalid reference: foo`) and removes redundant setup steps.

The patch is narrowly scoped, touching only `builtin/worktree.c` and adding a single test in `t/t2400-worktree-add.sh`. The regression it fixes is user-facing and frustrating—explicit branch creation flags being ignored—so the fix is well-motivated. The adjustments in v2 address Junio’s concerns about preserving warning paths, making this version more robust. No controversy remains; the patch looks ready for merging once the final details are settled.
