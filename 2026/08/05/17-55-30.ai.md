This is a substantive review follow-up in the `writev(3p)` wrapper revival series. Johannes Sixt responds to Junio C Hamano’s request to enumerate the POSIX guarantees that Git’s intended use cases can safely omit. He identifies the atomicity guarantee as the critical "Y" — the one feature that a `writev(2)` emulation cannot realistically provide when implemented as multiple `write(2)` calls. This directly addresses the architectural question Junio raised: because Git’s pktline and cat-blob use cases do not require atomicity, the proposed `git_write_gather()` API can indeed be implemented as a simple loop of `write(2)` calls without violating any necessary semantics. The response is concise, technically precise, and resolves the last major open question about the API’s design constraints.
