This is a refactoring patch in Tian Yuchen’s three-patch series on repository configuration handling. Junio C Hamano’s reply to patch 3/3 questions the claimed maintainability benefit of reordering the `repo_config_values` structure fields to match Git’s configuration sections. He points out that without an authoritative source of truth (e.g., an automated tool or designated list) to enforce the ordering, the change may not actually make the code easier to maintain. Additionally, he notes that the reordering spreads pointer-valued members more widely, increasing the structure’s size due to padding between members with different alignment requirements. The patch itself is purely cosmetic, with no functional changes, but Junio’s concerns suggest the reordering may introduce more complexity than it resolves. The thread remains in review, awaiting Tian’s response to these points.
