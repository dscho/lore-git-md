This is a final maintainer sign-off for a bugfix targeting `git worktree add`. Junio C Hamano approves the third iteration of Yoichi Nakayama’s patch, which fixes a regression introduced in Git 2.42.0 where the `-b` or `-B` options were ignored when a branch name could be DWIMmed to a remote-tracking branch. The patch ensures that explicit branch creation options take precedence over DWIM behavior, restoring the intended pre-regression behavior.

The change is minimal and surgical: in `builtin/worktree.c`, the DWIM logic is now guarded by a check for `!new_branch`, preventing it from overriding user-specified branch names. The test in `t/t2400-worktree-add.sh` verifies that `git worktree add -b branch ../wt foo` fails with the expected error message (`fatal: invalid reference: foo`) rather than silently creating a worktree for a remote-tracking branch. Junio’s only requested adjustment is a minor commit message tweak to use the standard `log -1 --pretty=reference` format for citing the regression commit (`128e5496b3 (worktree add: extend DWIM to infer --orphan, 2023-05-17)`).
