This is the fourth patch in Patrick Steinhardt’s six-patch v3 series making on-disk object database (ODB) structures pluggable, part of the ongoing ODB abstraction effort. The patch defers the creation of the object database until after the reference database has been initialized, preparing for the next patch in the series which will make on-disk ODB structure creation pluggable.

The change is mechanical: it splits the current `create_object_directory()` function into two steps. First, `apply_repository_format()` is called with the new `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag, which configures the repository but leaves the ODB uninitialized. Then, after the reference database is created, the new `create_object_database()` function is called, which both initializes the ODB (via `odb_new()`) and creates its on-disk structures. This ensures that both the ODB and its on-disk directories are set up in the same function, avoiding an intermediate state where the ODB exists but its directories do not.

The patch touches only `setup.c` and `setup.h`, adding the new flag and refactoring the initialization sequence. The new `create_object_database()` function is a straightforward replacement for the old `create_object_directory()`, with the addition of the `odb_new()` call. The change is uncontroversial and aligns with the series’ goal of making ODB directory creation pluggable in the next patch.

This patch is ready for merging and has no known open questions. It is a prerequisite for the pluggable ODB directory creation mechanism introduced in the sixth patch. The thread context confirms that the first patch in the series is already slated for `next`, while the rest (including this one) are under review and uncontroversial. The only functional difference from v2 is the adjustment to account for the new third patch, which moved environment variable handling into `odb_new()`.
