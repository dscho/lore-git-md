This is a substantive review follow-up in the revived `writev(3p)` wrapper series. Johannes Sixt ("Hannes") responds to Junio C Hamano’s request for clarification on which POSIX guarantees Git’s intended use cases *do not* need. He identifies the atomicity guarantee — the promise that `writev()` outputs data as a single uninterrupted block — as the key POSIX feature (`Y`) that Git’s pktline and cat-blob use cases can safely omit. This atomicity is inherently unimplementable when emulating `writev()` with multiple `write()` calls, so the wrapper’s design can proceed without it.

The response directly addresses the architectural question that has been blocking the series: the proposed `git_write_gather()` API (or whatever name is settled on) does not need to provide atomicity, meaning platforms can implement it either via native `writev()` or as a simple loop of `write()` calls. This removes a major technical obstacle and brings the series closer to resolution. The thread remains in technical review, but this clarification should allow Patrick Steinhardt to finalize the API design and respin the patches once he returns from his offsite.
