This is the third patch in Harald Nordgren’s seven-part series introducing `git branch --delete-merged`, now merged to **'next'**. The patch adds a `DELETE_BRANCH_SKIP_UNMERGED` flag to the branch-deletion API, allowing bulk callers (like the upcoming `--delete-merged` subcommand) to silently skip unmerged branches instead of failing with the usual "use `git branch -D`" advice. Existing callers—such as `git branch -d`—are unaffected, preserving their current behavior.

The change is a straightforward refactoring of `check_branch_commit()` and `delete_branches()`: when the new flag is set, the functions return early without emitting an error or advice, letting the caller proceed with the next branch. The patch is purely mechanical, introducing no behavioral changes for current users, and serves as a prerequisite for the `--delete-merged` implementation in patch 5/7, which needs to handle unmerged branches gracefully during bulk operations.

This is a well-motivated, low-risk addition that aligns with the series’ goal of providing safe, automated branch cleanup. The flag is part of a broader effort (patches 2–4/7) to modernize the deletion API by replacing boolean parameters with a flags-based interface, eliminating local boolean caching and ensuring consistent state.
