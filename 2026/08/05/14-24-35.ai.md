This is the core implementation patch (5/7) of Harald Nordgren’s `--delete-merged` series, now merged to **'next'**. It adds the `git branch --delete-merged <pattern>` subcommand, which safely deletes local branches whose tips are reachable from any of the supplied upstream patterns while preserving branches that are still needed (checked out, used as upstreams, or diverged from their upstream).

Key technical details:
- The command accepts **repeatable `--delete-merged` arguments** (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the upstream match, and **optional positional branch patterns** (e.g., `topic-*`) to limit deletion scope.
- **Order-independent stacked-branch protection** ensures branches used as upstreams for unmerged work are spared, and their stale upstream configs are cleared if their own upstream is deleted. The logic is implemented via two passes: first collecting all deletable candidates, then removing protected branches (those used as upstreams for surviving branches) from the set.
- **Safety checks** include:
  - Skipping checked-out branches (any worktree).
  - Preserving branches with missing upstreams or where pushing would update their upstream (e.g., `main` tracking `origin/main`).
  - Silently skipping unmerged branches (one unmerged topic doesn’t abort the sweep).
- The implementation uses the `--forked` filter machinery (introduced in patch 1/7) to resolve upstream patterns and relies on the flags-based API (patches 2–4/7) for deletion behavior (`DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`).
