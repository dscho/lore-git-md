This is a bug report about `git rebase` losing notes when used with `-x` and `git commit --amend`.

D. Ben Knoble describes a scenario where they used `git rebase -x` with a command that amends commits (`git commit --amend --author=...`). After the rebase, they noticed that notes attached to the rewritten commits were lost, even though their Git configuration (`notes.rewriteref`) explicitly lists the notes ref (`refs/notes/benknoble/commits`) as one that should be rewritten during operations like rebase or amend. Manual testing confirmed that `git commit --amend` alone *does* rewrite notes, and a plain `git rebase` (without `-x`) also preserves them, but the combination of `git rebase -x` with an amend command does not.

The report is well-structured and includes relevant configuration details, but it lacks a minimal reproduction case. The author acknowledges this and is seeking feedback on whether this is a known issue or user error before investing time in debugging. The behavior appears unintuitive and inconsistent with how notes rewriting is expected to work, so this may be a genuine bug in the rebase machinery. If confirmed, it would likely affect users who rely on notes for metadata tracking during history rewriting.
