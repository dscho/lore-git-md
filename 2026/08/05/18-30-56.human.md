This is the seventh patch in Johannes Schindelin’s v2 series fixing unchecked return values flagged by Coverity. It targets `transport-helper.c` and plugs a silent failure in the `get_exporter()` function.

When `dup(helper->in)` fails—typically due to file descriptor exhaustion—it returns -1. The child-process machinery treats `out = -1` as a request to create a new pipe, so the fast-export process would write its output to an unread pipe instead of back through the helper’s input fd. The patch adds a simple check: if `dup()` returns a negative value, the function now propagates the error upward with `error_errno()`, preventing the silent mis-wiring.

The change is minimal (two lines added) and uncontroversial. Patrick Steinhardt already reviewed the patch and confirmed that the only caller (`push_refs_with_export()`) already handles non-zero return values by dying, so the new error check integrates cleanly with the existing control flow. No new behavior or on-disk formats are introduced.
