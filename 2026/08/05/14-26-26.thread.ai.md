Thread identity: patch series (12 patches), "[PATCH 0/12] MinGW/Windows build and runtime adjustments", originating author Johannes Schindelin (Dscho).
Core problem or goal: upstream a batch of Git for Windows-specific build and runtime adjustments into the main Git codebase, addressing hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, a locale-handling regression in the MSYS2 runtime, and direct `git.exe` invocation. The series aims to make the mainline Git codebase more compatible with Windows without affecting non-Windows platforms.
Current status: initial version (v1) posted; under review. Junio C Hamano’s review of Patch 8 identified a cross-build-system inconsistency (leading slash in `MINGW_PREFIX` between Make and Meson) that Johannes Schindelin has committed to fixing in the next iteration. No merge status reported; series remains in proposed state.
Key technical details:
- Files touched: `compat/mingw.c`, `config.mak.uname`, CMake/Meson build files, test `t0060-path-utils.sh`.
- New/renamed symbols: none.
- Behavior changes: none for non-Windows platforms. Windows-specific adjustments include:
  - Enabling Python buildability by removing `NO_PYTHON` for MINGW in `config.mak.uname` (Patch 1).
  - Removing hard-coded `CC = gcc` assignment in MINGW section of `config.mak.uname` to allow alternative compilers (e.g., Clang) (Patch 2).
  - Removing the `-D_USE_32BIT_TIME_T` compiler flag from the MinGW section of `config.mak.uname` (Patch 3), as it is incompatible with the UCRT64 runtime and was only needed for the original MinGW runtime (deprecated since 2015).
  - Refining the linker flag `-Wl,--large-address-aware` to apply only to 32-bit builds (`MINGW32`), omitting it for 64-bit builds (`MINGW64` and `CLANGARM64`) where it is irrelevant or unsupported (Patch 4).
  - Removing redundant `-e` entry-point specifications from the `-Wl,--pic-executable` linker flag in `config.mak.uname` (Patch 5).
  - Replacing hard-coded `prefix` and `HOST_CPU` values in `config.mak.uname` with dynamic settings derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MINGW_CHOST`) (Patch 6).
  - Making MSYS2-specific code conditional on the presence of the `MSYSTEM` environment variable (Patch 7).
  - Replacing hard-coded defaults for `MSYSTEM` and installation prefix in `config.mak.uname`, CMake, and Meson with values derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MSYSTEM`), guarded by `ifneq (,$(MSYSTEM))` to affect only Windows builds (Patch 8). Junio C Hamano identified a cross-build-system inconsistency: the Makefile strips the leading slash from `MINGW_PREFIX` before passing it to the compiler, but the Meson build retains the leading slash. This mismatch will be corrected in the next iteration by aligning Meson’s behavior with the Makefile’s, ensuring consistent path handling.
  - Disabling generation of hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/` for Windows builds by setting `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname` (Patch 9). This eliminates a 30-second build-time overhead, avoids Windows Explorer disk-usage confusion, and aligns with the long-standing deprecation of the dashed form (since Git 1.5.4, February 2008). No end-user behavior change is expected, as the `git` executable’s built-in command dispatch remains functional.
  - Simplifying the logic for setting `ETC_GITCONFIG` and `ETC_GITATTRIBUTES` paths by unconditionally defining them for all MSYS2 environments, removing a hard-coded `/mingw64` prefix check in `config.mak.uname` (Patch 10).
  - Fixing a locale-handling regression in the MSYS2 runtime (introduced between versions 2.4.1 and 2.6.0) that caused Git to mishandle command-line arguments containing non-ASCII characters when shelling out to subprocesses (e.g., `git-upload-pack`). The fix sets `LC_CTYPE=C.UTF-8` as a fallback in `compat/mingw.c:setup_windows_environment()` if no locale-related environment variables (`LC_ALL`, `LC_CTYPE`, or `LANG`) are defined, ensuring UTF-8 locale initialization for the POSIX emulation layer. This is a targeted bugfix for a real-world Windows compatibility issue, with no effect on other platforms (Patch 11).
  - Allows `git.exe` to be called directly instead of through the "Git wrapper" (`C:\Program Files\Git\cmd\git.exe`), eliminating an extra process hop. The patch adds logic in `compat/mingw.c` to detect when `MSYSTEM` is unset (indicating the Git wrapper has not run) and initializes it, along with `PLINK_PROTOCOL` and a carefully constructed `PATH` that prepends `$HOME/bin`, the MSYS2 system directories (`/mingw64/bin` and `/usr/bin`), and the original `PATH`. The build system (`config.mak.uname`) is updated to pass `MSYSTEM` and `MINGW_PREFIX` as compiler definitions. A new test in `t0060-path-utils.sh` verifies the environment setup. This change addresses GitHub issue #2283 and aligns with the series’ goal of reducing Windows-specific runtime overhead (Patch 12).
- On-disk format: unchanged.
- Test coverage: one existing test (`t0060-path-utils.sh`) updated for Windows compatibility; the locale regression fix (Patch 11) is implied to be covered by GitHub issue #1036; Patch 12 adds further test coverage for the environment setup.
Open questions and loose ends: Junio C Hamano has suggested that the deprecation of dashed-form `git-<command>` executables (e.g., `git-commit`) could be completed by removing them entirely at the Git 3.0 boundary. This is a forward-looking proposal and not a request for changes to the current series. The cross-build-system inconsistency in Patch 8 (leading slash in `MINGW_PREFIX`) has been acknowledged by Johannes Schindelin and will be addressed in the next iteration.
