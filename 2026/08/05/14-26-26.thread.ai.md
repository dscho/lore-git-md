Thread identity: patch series (12 patches), "[PATCH 0/12] MinGW/Windows build and runtime adjustments", originating author Johannes Schindelin (Dscho).
Core problem or goal: upstream a batch of Git for Windows-specific build and runtime adjustments into the main Git codebase, addressing hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, and a locale-handling regression in the MSYS2 runtime. The series aims to make the mainline Git codebase more compatible with Windows without affecting non-Windows platforms.
Current status: initial version (v1) posted; under review. No merge status reported; series remains in proposed state.
Key technical details:
- Files touched: `compat/mingw.c`, `config.mak.uname`, CMake/Meson build files, test `t0060-path-utils.sh`.
- New/renamed symbols: none.
- Behavior changes: none for non-Windows platforms. Windows-specific adjustments include:
  - Enabling Python buildability by removing `NO_PYTHON` for MINGW in `config.mak.uname` (Patch 1).
  - Removing hard-coded `CC = gcc` assignment in MINGW section of `config.mak.uname` to allow alternative compilers (e.g., Clang) (Patch 2).
  - Removing the `-D_USE_32BIT_TIME_T` compiler flag from the MinGW section of `config.mak.uname` (Patch 3), as it is incompatible with the UCRT64 runtime and was only needed for the original MinGW runtime (deprecated since 2015).
  - Refining the linker flag `-Wl,--large-address-aware` to apply only to 32-bit builds (`MINGW32`), omitting it for 64-bit builds (`MINGW64` and `CLANGARM64`) where it is irrelevant or unsupported (Patch 4).
  - Removing redundant `-e` entry-point specifications from the `-Wl,--pic-executable` linker flag in `config.mak.uname` (Patch 5).
  - Replacing hard-coded `prefix` and `HOST_CPU` values in `config.mak.uname` with dynamic settings derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MINGW_CHOST`) (Patch 6).
  - Making MSYS2-specific code conditional on the presence of the `MSYSTEM` environment variable (Patch 7).
  - Removing hard-coded defaults for `MSYSTEM` and installation prefix in `config.mak.uname`, CMake, and Meson, using `MINGW_PREFIX` and `MSYSTEM` variables set by MSYS2 at build time (Patch 8).
  - Disabling generation of hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/` for Windows builds by setting `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname` (Patch 9). This eliminates a 30-second build-time overhead, avoids Windows Explorer disk-usage confusion, and aligns with the long-standing deprecation of the dashed form (since Git 1.5.4, February 2008). No end-user behavior change is expected, as the `git` executable’s built-in command dispatch remains functional.
  - Simplifying the logic for setting `ETC_GITCONFIG` and `ETC_GITATTRIBUTES` paths by unconditionally defining them for all MSYS2 environments, removing a hard-coded `/mingw64` prefix check in `config.mak.uname` (Patch 10).
  - **New in Patch 11**: Fixes a locale-handling regression in the MSYS2 runtime (introduced between versions 2.4.1 and 2.6.0) that caused Git to mishandle command-line arguments containing non-ASCII characters when shelling out to subprocesses (e.g., `git-upload-pack`). The fix sets `LC_CTYPE=C.UTF-8` as a fallback in `compat/mingw.c:setup_windows_environment()` if no locale-related environment variables (`LC_ALL`, `LC_CTYPE`, or `LANG`) are defined, ensuring UTF-8 locale initialization for the POSIX emulation layer. This is a targeted bugfix for a real-world Windows compatibility issue, with no effect on other platforms.
- Additional adjustments (per series cover letter): direct `git.exe` usage.
- On-disk format: unchanged.
- Test coverage: one existing test (`t0060-path-utils.sh`) updated for Windows compatibility; the locale regression fix (Patch 11) is implied to be covered by GitHub issue #1036, which documents the symptom and likely includes reproduction steps.
