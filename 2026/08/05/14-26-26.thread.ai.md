Thread identity: patch series (12 patches), "[PATCH 0/12] MinGW/Windows build and runtime adjustments", originating author Johannes Schindelin (Dscho).
Core problem or goal: upstream a batch of Git for Windows-specific build and runtime adjustments into the main Git codebase, addressing hard-coded assumptions, MSYS2 integration, and linking behavior for the MinGW/Windows build system. The series aims to make the mainline Git codebase more compatible with Windows without affecting non-Windows platforms.
Current status: initial version (v1) posted; under review. No merge status reported; series remains in proposed state.
Key technical details:
- Files touched: `compat/mingw.c`, `config.mak.uname`, CMake/Meson build files, test `t0060-path-utils.sh`.
- New/renamed symbols: none.
- Behavior changes: none for non-Windows platforms. Windows-specific adjustments include:
  - Enabling Python buildability by removing `NO_PYTHON` for MINGW in `config.mak.uname` (Patch 1).
  - Removing hard-coded `CC = gcc` assignment in MINGW section of `config.mak.uname` to allow alternative compilers (e.g., Clang) (Patch 2).
  - Removing the `-D_USE_32BIT_TIME_T` compiler flag from the MinGW section of `config.mak.uname` (Patch 3), as it is incompatible with the UCRT64 runtime (mingw-w64-git package in MSYS2) and was only needed for the original MinGW runtime (version 4.0, deprecated since 2015).
  - Refining the linker flag `-Wl,--large-address-aware` to apply only to 32-bit builds (`MINGW32`), omitting it for 64-bit builds (`MINGW64` and `CLANGARM64`) where it is irrelevant or unsupported (Patch 4).
  - Removing redundant `-e` entry-point specifications (`_mainCRTStartup` for 32-bit, `mainCRTStartup` for 64-bit) from the `-Wl,--pic-executable` linker flag in `config.mak.uname` (Patch 5). These symbols are the default and were added in 2016 to avoid stripping relocations, but are no longer necessary.
  - Replacing hard-coded `prefix` and `HOST_CPU` values in `config.mak.uname` with dynamic settings derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MINGW_CHOST`). The change affects only the MinGW section and removes explicit `/mingw32`, `/mingw64`, and `/clangarm64` paths and corresponding `i686`, `x86_64`, and `aarch64` CPU assignments, letting MSYS2 supply them instead (Patch 6).
- Additional adjustments (per series cover letter): conditional MSYS2 code, direct `git.exe` usage.
- On-disk format: unchanged.
- Test coverage: one existing test (`t0060-path-utils.sh`) updated for Windows compatibility.
Open questions and loose ends: none identified yet; series is self-contained and routine.
