Thread identity: patch series (12 patches), "[PATCH v2 0/12] MinGW/Windows build and runtime adjustments", originating author Johannes Schindelin (Dscho).
Core problem or goal: upstream Git for Windows-specific build and runtime adjustments into the main Git codebase, addressing hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, a locale-handling regression in the MSYS2 runtime, and direct `git.exe` invocation. The series aims to improve Windows compatibility without affecting non-Windows platforms.
Current status: v2 posted; under review. The only changes from v1 were the alignment of Meson’s `MINGW_PREFIX` handling with the Makefile’s (removing the leading slash) in Patch 8, addressing Junio C Hamano’s cross-build-system inconsistency concern. The unresolved discussion about guarding against an empty `MSYSTEM` export in Patch 12 remains open, with Johannes Schindelin declining to add build-system guards. No merge status reported; series remains in proposed state.
Key technical details:
- Files touched: `compat/mingw.c`, `config.mak.uname`, CMake/Meson build files, test `t0060-path-utils.sh`.
- New/renamed symbols: none.
- Behavior changes: none for non-Windows platforms. Windows-specific adjustments include:
  - Enabling Python buildability by removing `NO_PYTHON` for MINGW in `config.mak.uname` (Patch 1), allowing users to leverage MSYS2-provided Python interpreters in Git for Windows’ SDK environment. This reverses a long-standing exclusion of Python from MinGW builds.
  - Removing the hard-coded `CC = gcc` assignment in the MINGW section of `config.mak.uname` to allow alternative compilers (e.g., Clang) (Patch 2). This is a minimal, uncontroversial change that aligns with the series’ goal of modernizing the Windows build process.
  - Removing the `-D_USE_32BIT_TIME_T` compiler flag from the MinGW section of `config.mak.uname` (Patch 3), as it is incompatible with the UCRT64 runtime and was only needed for the original MinGW runtime (deprecated since 2015). The flag was introduced in 2013 to work around a limitation in MinGW 4.0; its removal is a routine cleanup that addresses UCRT64 incompatibility without affecting other platforms.
  - Refining the linker flag `-Wl,--large-address-aware` to apply only to 32-bit builds (`MINGW32`), omitting it for 64-bit builds (`MINGW64` and `CLANGARM64`) where it is irrelevant or unsupported (Patch 4). The flag was originally introduced to allow 32-bit Git executables to access more than 2 GB of address space, but it has no effect on 64-bit builds (which already have a 64-bit address space) and can cause issues with some toolchains (e.g., UCRT64 versions of GCC). The patch moves the flag into the `MINGW32`-specific branch of `config.mak.uname` and removes it from the fallback `else` clause.
  - Removing redundant `-e` entry-point specifications from the `-Wl,--pic-executable` linker flag in `config.mak.uname` (Patch 5). The commit message confirms that the entry-point symbols (`_mainCRTStartup` for 32-bit, `mainCRTStartup` for 64-bit) are already the MinGW linker’s defaults, as documented in a Sourceware Bugzilla report. This is a surface-level cleanup with no functional impact.
  - Replacing hard-coded `prefix` and `HOST_CPU` values in `config.mak.uname` with dynamic settings derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MINGW_CHOST`) (Patch 6). The patch removes explicit assignments for `MINGW32`, `MINGW64`, and `CLANGARM64` environments, replacing them with a single conditional block that sets `prefix = $(MINGW_PREFIX)` and `HOST_CPU = $(patsubst %-w64-mingw32,%,$(MINGW_CHOST))` whenever `MSYSTEM` is defined. The `patsubst` strips the `-w64-mingw32` suffix from `MINGW_CHOST` to extract the CPU architecture (e.g., `x86_64`). The `-Wl,--pic-executable` linker flag is retained for all MSYS2 environments, while the `-Wl,--large-address-aware` flag remains specific to 32-bit builds (`MINGW32`).
  - Making MSYS2-specific code conditional on the presence of the `MSYSTEM` environment variable (Patch 7).
  - Replacing hard-coded defaults for `MSYSTEM` and installation prefix in `config.mak.uname`, CMake, and Meson with values derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MSYSTEM`), guarded by `ifneq (,$(MSYSTEM))` to affect only Windows builds (Patch 8). The v2 iteration aligns Meson’s behavior with the Makefile’s by removing the leading slash from `MINGW_PREFIX`, ensuring consistent path handling across build systems.
  - Disabling generation of hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/` for Windows builds by setting `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname` (Patch 9). This eliminates a 30-second build-time overhead, avoids Windows Explorer disk-usage confusion, and aligns with the long-standing deprecation of the dashed form (since Git 1.5.4, February 2008). No end-user behavior change is expected, as the `git` executable’s built-in command dispatch remains functional.
  - Simplifying the logic for setting `ETC_GITCONFIG` and `ETC_GITATTRIBUTES` paths by unconditionally defining them for all MSYS2 environments, removing a hard-coded `/mingw64` prefix check in `config.mak.uname` (Patch 10).
  - Fixing a locale-handling regression in the MSYS2 runtime (introduced between versions 2.4.1 and 2.6.0) that caused Git to mishandle command-line arguments containing non-ASCII characters when shelling out to subprocesses (e.g., `git-upload-pack`). The fix sets `LC_CTYPE=C.UTF-8` as a fallback in `compat/mingw.c:setup_windows_environment()` if no locale-related environment variables (`LC_ALL`, `LC_CTYPE`, or `LANG`) are defined, ensuring UTF-8 locale initialization for the POSIX emulation layer. This is a targeted bugfix for a real-world Windows compatibility issue, with no effect on other platforms (Patch 11).
  - Allows `git.exe` to be called directly instead of through the "Git wrapper" (`C:\Program Files\Git\cmd\git.exe`), eliminating an extra process hop. The patch adds logic in `compat/mingw.c` to detect when `MSYSTEM` is unset (indicating the Git wrapper has not run) and initializes it, along with `PLINK_PROTOCOL` and a carefully constructed `PATH` that prepends `$HOME/bin`, the MSYS2 system directories (`/mingw64/bin` and `/usr/bin`), and the original `PATH`. The build system (`config.mak.uname`) is updated to pass `MSYSTEM` and `MINGW_PREFIX` as compiler definitions. Junio C Hamano’s review identified a potential correctness issue: the Makefile’s `COMPAT_CFLAGS` definition for `ENSURE_MSYSTEM_IS_SET` does not guard against an empty or undefined `$(MSYSTEM)`, which could result in exporting an empty `MSYSTEM` value. Johannes Schindelin has declined to address this, arguing the scenario is too unlikely to warrant additional build-system guards. The impact is minimal—Git will still function, but scripts relying on `MSYSTEM` as a non-empty indicator may behave unexpectedly. A new test in `t0060-path-utils.sh` verifies the environment setup (Patch 12).
- On-disk format: unchanged.
- Test coverage: one existing test (`t0060-path-utils.sh`) updated for Windows compatibility; the locale regression fix (Patch 11) is implied to be covered by GitHub issue #1036; Patch 12 adds further test coverage for the environment setup.
