This thread is about a bug in `git push --delete --porcelain` where the command outputs human-readable error messages instead of the documented machine-readable format when attempting to delete a ref that no longer exists on the remote. Xavier Morel reported the issue, and Junio C Hamano, the maintainer, acknowledged it as an unintended oversight and invited a patch to fix it.

Xavier has now proposed a concrete implementation plan to address the problem. The plan involves modifying `match_explicit` to create a dummy destination ref with a failure status when the remote ref does not exist, ensuring `set_ref_status_for_push` skips refs that already have a status set, and adapting the reporting logic to use the `!` prefix for errors in the `--porcelain` output. The proposal is technically detailed, referencing specific functions and edge cases, and aims to maintain backward compatibility for valid pushes unless `--atomic` is used. The maintainer’s earlier invitation suggests this approach would likely be accepted once implemented.

The next step is for Xavier or another contributor to write the patch and add test coverage for this edge case. No objections or alternative approaches have been raised, and the fix is expected to be low-risk and well-scoped, benefiting script authors who rely on the `--porcelain` output for automation.
