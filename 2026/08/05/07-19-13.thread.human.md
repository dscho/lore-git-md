This thread is about a bug in `git push --porcelain` where deleting a non-existent remote ref produces unstructured error output instead of the documented machine-readable format. Xavier Morel reported the issue: while successful deletions use the expected `:` prefix, failures (like "remote ref does not exist") fall back to human-readable text, breaking script parsing. The inconsistency affects tools relying on `--porcelain`'s stable output format, particularly in edge cases like concurrent deletions.

The problem is well-defined and uncontroversial—it’s a clear gap in porcelain output coverage for error paths. Morel suggests using `!` as an error prefix (matching the documented format) but hasn’t provided a patch, so this will need implementation by someone familiar with the push/transport code (likely `push.c` or related files). No prior discussion or related commits are mentioned, so this appears to be a newly identified issue. If fixed, it would make `--porcelain` more reliable for automation without changing existing successful-case behavior. The thread is currently in the RFC stage, awaiting a contributor to implement the proposed fix.
