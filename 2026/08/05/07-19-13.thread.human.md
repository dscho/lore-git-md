This thread is about a bug in `git push --delete --porcelain` where the command outputs human-readable error messages instead of the documented machine-readable format when attempting to delete a ref that no longer exists on the remote. Xavier Morel reported the issue, noting that scripts relying on `--porcelain` for automation cannot reliably detect deletion failures in this edge case.

Junio C Hamano, the maintainer, acknowledged the oversight—this case hadn’t been considered when the porcelain output was designed—and confirmed the behavior is unintended. The proposed fix (using `!` as an error prefix for machine-readable output) aligns with existing porcelain conventions and is uncontested. The thread is now in a holding pattern, awaiting a contributor to implement the fix in `push.c` or related transport code and add test coverage for the edge case. No prior discussion or related commits exist, so this is a straightforward, well-scoped bugfix with clear value for script authors. A patch would likely be accepted if it follows the established porcelain output format.
