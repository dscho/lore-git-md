This is the tenth patch in Johannes Schindelin’s 12-patch **platform compatibility** series for MinGW/Windows. It simplifies the logic that sets the `ETC_GITCONFIG` and `ETC_GITATTRIBUTES` paths by making them unconditionally defined for all MSYS2 environments, rather than special-casing only the `/mingw64` prefix.

The change removes the redundant `ifeq (/mingw64,...)` check in the MINGW section of `config.mak.uname` and moves the `ETC_*` definitions into the broader MSYS2 conditional block (triggered by the presence of the `MINGW_PREFIX` environment variable, introduced in an earlier patch). This ensures that system-wide Git config and attributes files are always placed in the top-level `/etc/` directory on MSYS2, regardless of whether the build uses `/mingw64`, `/mingw32`, or `/clangarm64` as its prefix.

The patch is a straightforward cleanup: it eliminates a hard-coded assumption about the prefix path and aligns the behavior with the MSYS2 environment variables already in use. No functional change is expected for end users or non-Windows platforms. The commit message is minimal but sufficient for the scope of the change. If you are following the series for Windows build system improvements, this patch is a minor but logical step in reducing configuration complexity.
