This is the fourth patch in Patrick Steinhardt’s six-patch v3 series making on-disk ODB structures pluggable, part of the ongoing ODB abstraction effort. The email is a review reply from Toon Claes proposing an alternative design for the initialization sequence.

Toon’s reply centers on Justin Tobler’s earlier suggestion to simplify the API by requiring an explicit `odb_new()` call after `apply_repository_format()` instead of embedding ODB creation inside it. Toon implements this idea in a proof-of-concept diff that removes the `APPLY_REPOSITORY_FORMAT_SKIP_ODB_CREATION` flag entirely, moves all `odb_new()` calls to the call sites, and eliminates the intermediate state where the repository is configured but the ODB is not yet created. The diff touches `repository.c`, `setup.c`, and `setup.h`, showing that the change is mechanical and affects only the initialization sequence.

The proposal directly challenges the design introduced in this patch, which defers ODB creation to `create_object_database()` to keep the ODB and its on-disk structures in sync. Toon’s alternative would revert that refactoring, making ODB creation an explicit step at every call site. This is a substantive architectural question: whether the initialization sequence should be split into two steps (configure, then create ODB) or remain unified. The thread context confirms that the current patch is uncontroversial and ready for merging, but Toon’s reply reopens the design discussion and may require a v4 if Patrick chooses to adopt the simpler API.
