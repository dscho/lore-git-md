This is the sixth patch in Johannes Schindelin’s 12-patch series widening size-related fields in Git’s delta and pack-objects code from `unsigned long` to `size_t`. The series is a platform-compatibility fix for 64-bit Windows (where `unsigned long` is 32-bit) and part of the broader effort to eliminate incorrect `unsigned long` usage.

This patch widens the `create_delta()` and `diff_delta()` functions in `delta.h` to use `size_t` for all size parameters and output fields. The change is mechanical and does not alter behavior or on-disk formats. The patch updates all callers in the same commit to maintain build consistency, using temporary `cast_size_t_to_ulong()` shims where downstream consumers (like zlib’s `avail_in` or test helpers) still expect `unsigned long`. These shims will be removed in later patches when those consumers are also widened.

Files touched include `builtin/fast-import.c`, `builtin/pack-objects.c`, `delta.h`, `diff-delta.c`, `diff.c`, and two test helpers (`t/helper/test-delta.c` and `t/helper/test-pack-deltas.c`). The patch is uncontroversial and directly addresses the truncation risk for large blobs on 64-bit Windows. The commit message clearly explains the scope and rationale, and the changes are minimal and focused. This is a well-crafted, low-risk patch that advances the series’ goal.
