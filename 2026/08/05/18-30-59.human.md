This is the tenth patch in Johannes Schindelin’s v2 series fixing unchecked return values flagged by Coverity. The patch centralizes error handling in the bisect subsystem by extending `get_terms()` to accept a `file_missing_is_ok` flag, ensuring all call sites properly handle failures when reading the `BISECT_TERMS` file.

Previously, six callers of `get_terms()` silently ignored its return value. When the `BISECT_TERMS` file was missing or truncated, the term strings remained `NULL` or empty, leading to confusing downstream behavior—commands like `git bisect next` or `git bisect run` would proceed with nonsensical ref names (e.g., `refs/bisect/` with no suffix) and misleading error messages. The patch addresses this by making `get_terms()` return an error if either term is `NULL`, unless the caller explicitly sets `file_missing_is_ok`. This deduplicates error messages and simplifies the callers, which now uniformly check the return value and propagate failures.

The change is minimal and targeted: the function signature is extended, and each caller is updated to pass the appropriate flag and handle errors. The patch resolves Patrick Steinhardt’s earlier design suggestion to centralize error handling, which was incorporated via a fixup patch in v2. No new behavior or on-disk formats are introduced, and the existing test suite implicitly covers the new error paths. The patch is uncontroversial and ready for integration, as all substantive review feedback has been addressed.
