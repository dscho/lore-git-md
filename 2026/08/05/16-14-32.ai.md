This is the fifth patch in Johannes Schindelin’s 12-patch v2 series widening size-related fields in Git’s delta and pack-objects machinery from `unsigned long` to `size_t`. The patch targets `builtin/pack-objects.c`, widening the `mem_usage` counter in `find_deltas()` and the corresponding output parameter in `try_delta()` to `size_t`. This change ensures type consistency with upstream callers (notably `free_unpacked()`, whose return type was widened to `size_t` in Patch 4) and eliminates the last 32-bit truncation risk in the delta-window memory accounting chain on 64-bit Windows.

The commit message clarifies that `window_memory_limit` (a configuration-driven `unsigned long`) remains unchanged because it is only compared against `mem_usage` and promotes implicitly. The patch is mechanical and uncontroversial, addressing a latent type mismatch without altering behavior or on-disk format. The series as a whole remains ready for integration, with all prior review feedback from Patrick Steinhardt already incorporated in earlier patches. Key symbols introduced here: `mem_usage` (now `size_t`), `try_delta()`’s `mem_usage` parameter (widened to `size_t`).
