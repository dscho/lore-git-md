This is the v3 cover letter for Patrick Steinhardt’s six-patch series that makes the creation of on-disk object database (ODB) structures pluggable. The series is part of the ongoing ODB abstraction effort and is now in its third iteration.

The core goal remains unchanged: decouple the creation of backend-specific directories (like `objects/info` and `objects/pack`) from the generic repository setup code. The top-level `objects/` directory is still mandatory for repository discovery, but individual backends now handle their own subdirectory creation via a new `create_on_disk` callback. This enables future ODB backends to implement custom on-disk layouts without modifying core setup logic.

Key changes in v3 center on the third patch, which is new: it moves the handling of `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables into `odb_new()` itself. This deduplicates logic and prepares for a future where alternates are managed by the "files" backend. The fourth patch (previously the third) has been adjusted to reflect this change, simplifying the control flow in `apply_repository_format()` by removing the need to pass environment variables through intermediate variables.

The series still starts with the same correctness fix for loose-object map loading (patch 1), followed by the detangling of loose object map loading from repository setup (patch 2). The fifth patch introduces a helper function to map ODB source types to their names, and the sixth implements the pluggable directory creation mechanism. The first patch remains a strong candidate for early graduation due to its status as a correctness fix with regression coverage, while the fourth and sixth patches are now uncontroversial and ready for merging.

Files touched span loose-object handling (`loose.c`, `loose.h`), ODB source management (`odb/source*.c`, `odb/source*.h`), and repository setup (`setup.c`, `repository.c`). The changes are mechanical but foundational, introducing new functions and structures while removing hardcoded assumptions about directory layouts. The series is based on the recent "7th batch" integration (commit `9a0c4701dc`), indicating it’s targeting the current development cycle.
