This is a refactoring patch in Patrick Steinhardt’s six-part series making Git’s object database (ODB) structures pluggable. It introduces a small helper function, `odb_source_type_to_name()`, that maps an ODB source type (e.g., `ODB_SOURCE_LOOSE`, `ODB_SOURCE_PACKED`) to a human-readable string. The patch then updates all downcast macros in the ODB source headers to use this function in their BUG messages, replacing numeric type codes with descriptive names like “loose” or “packed.”

The change is purely internal and has no user-visible effect; it only improves the clarity of error messages when a downcast fails. The implementation is straightforward: a static array of names indexed by the enum, with bounds checking and a fallback to “unknown.” All four existing source types (files, loose, packed, in-memory) are covered, and the helper is exposed in `odb/source.h` for future backends.

This is the fifth patch in the v3 series and is uncontroversial. It touches only the ODB source headers and the central `odb/source.c` file, making no behavioral changes beyond the error-message wording. The patch is ready for merging and is part of the broader ODB abstraction effort that will eventually allow non-filesystem backends.
