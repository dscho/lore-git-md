This is a maintainer reply in the ongoing `writev(3p)` wrapper revival series. Junio C Hamano acknowledges Johannes Sixt’s forward-compatibility concern about the API name (`git_writev()` or `git_write_gather()`) potentially misleading future contributors into assuming atomicity. He reaffirms his earlier position: the API can and should explicitly document that emulation may be non-atomic, and that competing writes to the same destination are a bug. This stance resolves the last remaining design question by treating the naming issue as a documentation and declaration problem rather than a technical obstacle. The series is now technically complete, with all correctness, platform compatibility, and architectural issues resolved; the only open questions are maintainer appetite (whether the performance gains justify the complexity) and the absence of a range-diff to the reverted version, neither of which Junio addresses here. No immediate reroll is expected while Patrick Steinhardt remains at an offsite.
