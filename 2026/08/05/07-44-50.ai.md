This is a refactoring patch (part 6/8 of the ODB streaming API unification series). It renames `struct read_object_fd_data` to `struct fd_stream` in `odb/streaming.c` to better reflect its expanded role after earlier patches merged the read and write stream structures into a single `odb_stream` base. The change also renames the associated callback functions (`read_object_fd` → `fd_stream_read`, `close_object_fd` → `fd_stream_close`) for consistency.

The patch is purely mechanical: it updates the structure definition, all references to it (17 lines changed), and the function names, but does not alter behavior or logic. The new name (`fd_stream`) aligns with the unified API introduced in Patch 5/8, where the structure now holds both stream state and file descriptor data. This rename was previewed in Justin Tobler’s review of v1 and is uncontroversial, though reviewers may check for completeness (e.g., no lingering references to the old name).

The change is part of the broader ODB abstraction effort led by Patrick Steinhardt, which aims to enable pluggable backends. This patch specifically addresses feedback to improve naming clarity after the structural unification of read/write streams. No new edge cases or performance concerns are introduced here, as the patch only affects symbol names and not data flow or memory management. The series is targeting `next` or `master` for the upcoming release.
