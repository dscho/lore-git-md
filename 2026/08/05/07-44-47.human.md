This is the third patch in Patrick Steinhardt’s eight-patch series refactoring the object database (ODB) streaming API to support arbitrary object types. The patch extends the write-stream infrastructure beyond blobs, allowing streams to carry commits, trees, or tags as well. It fixes the critical bug identified in v1: the in-memory ODB backend now correctly propagates `stream->type` to `hash_object_file()`, preventing silent corruption when hashing non-blob objects. The stale comment in `odb/transaction.h` that assumed blob-only streaming has also been updated.

The changes are mechanical: adding an `enum object_type type` field to `struct odb_write_stream`, updating callers to pass the type (e.g., `OBJ_BLOB` in `builtin/unpack-objects.c`), and renaming helper functions (`hash_blob_stream` → `hash_stream`, `stream_blob_to_pack` → `stream_to_pack`) to reflect the new generic infrastructure. The patch touches eight files, including core object handling (`object-file.c`, `odb/source-inmemory.c`) and unit tests (`t/unit-tests/u-odb-inmemory.c`).

This is a well-crafted refactoring with clear motivation and thorough test coverage. The fix for the hash-collision bug in the in-memory backend removes the last known blocker for the series, and the updated commit message now explicitly notes the bug’s resolution. Reviewers (notably Junio and Justin Tobler) have already validated the core logic, leaving only minor naming consistency questions for later patches. The patch is part of the broader ODB abstraction effort and is a strong candidate for merging.
