This is the second patch in Patrick Steinhardt’s eight-patch v2 series refactoring Git’s object database (ODB) streaming API. The patch removes the `is_finished` field from `struct odb_write_stream` and adjusts the code to infer stream completion from zero-byte returns instead, bringing the write stream’s behavior in line with the read stream’s design.

The change is mechanical and touches seven files, primarily updating loops in `builtin/unpack-objects.c`, `object-file.c`, `odb/source-inmemory.c`, and `odb/source-loose.c` to check for zero-byte returns rather than relying on the `is_finished` flag. The most notable adjustment is in `builtin/unpack-objects.c`, where the `feed_input_zstream()` function is restructured to ensure at least one byte is produced before yielding, preventing premature termination when zlib decompression yields no output. The patch also updates the unit test in `t/unit-tests/u-odb-inmemory.c` to match the new logic.

The motivation is clear: eliminating redundancy between the read and write stream APIs simplifies the code and prepares for the later unification into a single `odb_stream` structure. The commit message explains the rationale well, and the changes are narrowly scoped to the stated goal. No behavior changes are intended, and the patch appears to achieve that—though reviewers may focus on edge cases in the loop logic (e.g., ensuring the zlib status is correctly propagated in `builtin/unpack-objects.c`).

This patch is part of the broader ODB abstraction effort and depends on the preparatory work in Patch 1/8 (which embedded the `size` field in `struct odb_write_stream`). It sets the stage for Patch 3/8, which adds an `object_type` field to the stream. The series is under active review, and this patch has already received substantive feedback in v1, which has been addressed here. The changes look solid and are likely to proceed without major controversy.
