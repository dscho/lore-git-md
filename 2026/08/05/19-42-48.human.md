This is the first patch in Junio C Hamano’s three-part series fixing bash completion for `git diff`. It is a no-op refactoring that reorganizes the control flow in `_git_diff()` inside `contrib/completion/git-completion.bash`.

The patch removes the early return that currently happens when no `--` is seen on the command line. Instead, the logic now falls through to the same end point, making room for the next two patches to add new behavior without disrupting the existing option-completion paths. The diff shows the same case statements moved inside a new `if ! __git_has_doubledash` block, but the actual completion suggestions remain unchanged.

Because this is purely structural, there is no new test coverage or user-visible change. The commit message explains that the goal is to prepare for the follow-up patches, which will make `git diff` path completion behave consistently with `git status` and `git add`. The series as a whole is already under review and queued in `seen`; this patch is the low-risk first step.
