This is the fourth patch in Harald Nordgren’s seven-patch `--delete-merged` series, now merged to **'next'**. It adds a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, to the `delete_branches()` API in `builtin/branch.c`. The flag prevents the function from falling back to `HEAD` when checking whether a branch is merged, ensuring that `--delete-merged` only deletes branches that are merged into their upstream.

The change is a preparatory refactoring for the `--delete-merged` subcommand (introduced in patch 5/7). Without this flag, `delete_branches()` would fall back to `HEAD` if a branch had no upstream, which is not the intended behavior for `--delete-merged`. The patch modifies the `branch_merged()` helper to skip the `HEAD` fallback check when `head_rev` is `NULL`, and updates `delete_branches()` to conditionally set `head_rev` based on the new flag. Existing callers (e.g., `git branch -d`) retain their current behavior.

The implementation is mechanical and low-risk, with no behavioral changes for current users. The flag is purely internal and will be wired up in later patches. The patch touches only `builtin/branch.c` and is part of the broader flags-based API refactoring (patches 2–4/7) that replaces boolean arguments with an `unsigned int flags` parameter. This refactoring resolves the maintenance risk of local boolean caching by ensuring flags remain the single source of truth. The test suite (expanded in later patches) verifies that the flag works as intended when combined with `--delete-merged`.
