This is the final patch in Patrick Steinhardt’s eight-patch v2 series unifying the ODB streaming API. It standardizes the function names that create new streams—`odb_stream_from_object()` (replacing `odb_read_stream_open()`) and `odb_stream_from_fd()` (replacing `odb_write_stream_from_fd()`)—and documents that the caller retains ownership of the file descriptor passed to `odb_stream_from_fd()`.

The patch is purely mechanical, touching eight files (`archive-tar.c`, `archive-zip.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `object-file.c`, `object.c`, `odb/streaming.c`, and `odb/streaming.h`). All changes are straightforward renames and signature updates, with no behavior changes. The commit message explicitly clarifies the file descriptor ownership semantics, addressing a potential edge case that could have led to leaks or double-closes.

This patch completes the series’ goal of consolidating `odb_write_stream` and `odb_read_stream` into a single `odb_stream` structure. The v2 series has already resolved the critical correctness issue in Patch 3/8 (propagating `stream->type` to `hash_object_file()`) and incorporated reviewer feedback on naming and documentation. The only remaining open questions are edge cases in the unified API and potential performance regressions from the additional indirection introduced by wrapper structures, but this patch itself is uncontroversial and ready for merging. It is a clean, well-motivated refactoring that aligns with the broader ODB abstraction effort.
