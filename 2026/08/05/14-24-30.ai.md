This is the v25 iteration of Harald Nordgren’s `--delete-merged` series, now merged to **'next'**. The only change since v24 is purely mechanical: long test command lines in patch 1/7 (`--forked` filter) have been wrapped for readability. No functional or correctness changes were made.

The series adds a safe, automated way to clean up local branches that have already been merged upstream. Key features:

- **`--delete-merged <pattern>`** – deletes local branches whose tips are reachable from any of the supplied upstream patterns (exact refnames, remote shorthand, or shell-style globs). The option can be repeated to widen the match (e.g., `--delete-merged origin/main --delete-merged origin/next`).
- **Order-independent stacked-branch protection** – if a branch is used as an upstream for an unmerged branch, it is spared and its stale upstream config is cleared. The v24 update simplified this logic to protect only the *direct* upstream of a surviving branch, resolving the last correctness issue.
- **Per-branch opt-out** – `branch.<name>.deleteMerged=false` exempts specific branches from automated cleanup while still allowing explicit deletion via `git branch -d`.
- **`--dry-run`** – prints "Would delete" or "Would skip" messages without modifying refs or config.
- **`--forked` filter** – a composable `--list` mode filter that underpins `--delete-merged` and can be combined with existing filters (`--merged`, `--no-merged`).

The flags-based API refactoring (patches 2–4/7) is complete, eliminating local boolean caching to ensure flags remain the single source of truth. The test suite covers all edge cases, including the corrected push-detection logic and simplified stacked-branch protection.
