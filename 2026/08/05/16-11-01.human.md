This is Junio C Hamano, the Git maintainer, replying to the thread that proposes removing `--interactive` (`-i`) mode from `git add`. His response is decisive and sets a high bar for any breaking change: the patch, as currently justified, is unacceptable.

Junio dismisses the rationale ("the patch mode remains available") as logically equivalent to removing `git add` entirely while claiming `git diff` still works. He makes it clear that a feature removal must be justified by more than personal preference or anecdotal disuse. The implicit standard he sets is that the author must demonstrate either (a) that the feature is actively harmful, (b) that it is universally unused, or (c) that a superior replacement exists and has been widely adopted. None of these conditions are met by the current patch.

The procedural critique from Michael Montalbo remains valid, but Junio’s reply shifts the focus from "how to document the removal" to "whether the removal is justified at all". This effectively closes the door on the patch in its current form; any future revision would need to address both the documentation standards and the substantive question of user impact. The thread is now waiting for either a compelling justification from the author or a withdrawal.
