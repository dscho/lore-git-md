This is the second patch in Harald Nordgren’s seven-patch series introducing `git branch --delete-merged`. The series is now merged to **'next'**, with no remaining technical blockers.

This patch refactors `delete_branches()` and `check_branch_commit()` to replace the existing `force` and `quiet` boolean parameters with a single `unsigned int flags` argument and an enum (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`). The change is purely mechanical: flags are tested directly at each use site to prevent stale cached values, and no behavior changes are introduced. The patch is well-tested and low-risk, serving as the foundation for the flags-based API additions in subsequent patches (e.g., `DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`, `DELETE_BRANCH_DRY_RUN`).

The refactoring resolves a maintenance issue identified in earlier versions, where local boolean caching (e.g., `int force = 1`) risked inconsistency if flags were mutated or forwarded. By eliminating caching and testing flags directly, the patch ensures the flags argument remains the single source of truth. This design choice was explicitly endorsed by Phillip Wood, who noted the risk of stale values in his review of the earlier API structure.

The patch touches only `builtin/branch.c` and is part of the broader effort to unify the deletion API for both traditional `git branch -d` and the new `--delete-merged` subcommand. The enum and flags introduced here will be extended in patches 3/7, 4/7, and 7/7 to support the additional functionality required by `--delete-merged`. The test suite confirms the refactoring introduces no regressions for existing callers.
