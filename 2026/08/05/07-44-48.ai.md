This is the fourth patch in Patrick Steinhardt’s v2 series unifying the ODB streaming API. It performs a straightforward rename: `struct odb_read_stream` becomes `struct odb_stream` across 18 files, preparing for the later merge of read and write streams into a single structure. The patch is purely mechanical—no logic changes, only type and function signature updates to reflect the new name.

The rename touches core object handling (`object-file.c`, `odb/streaming.c`), archive formats (`archive-tar.c`, `archive-zip.c`), packfile operations (`builtin/pack-objects.c`, `packfile.c`), and the in-memory ODB unit test. All callers of `odb_read_stream_open()`, `odb_read_stream_read()`, and `odb_read_stream_close()` are updated to use the new type name, and the typedefs for the stream’s function pointers (`odb_read_stream_close_fn`, `odb_read_stream_read_fn`) are similarly renamed to `odb_stream_close_fn` and `odb_stream_read_fn`.

This patch is a prerequisite for Patch 5/8, which merges `odb_read_stream` and `odb_write_stream` into the unified `odb_stream`. The rename itself is uncontroversial and aligns with the series’ goal of eliminating redundancy. No behavior changes or edge cases are introduced; the patch is purely preparatory. Reviewers familiar with the ODB may focus on ensuring the rename is complete (no lingering references to the old type name) and that the updated function signatures match the intended unified API.
