This is the sixth patch in Patrick Steinhardt’s v3 series making on-disk object database (ODB) structures pluggable, and Toon Claes’s review of it. The patch implements the `create_on_disk` callback in the "files" ODB backend, replacing generic directory creation logic in `setup.c` with backend-specific handling. This completes the series’ goal of decoupling backend-specific on-disk layout from core repository setup.

Toon’s review is substantive but narrow. He notes two minor issues: the reintroduction of `DB_ENVIRONMENT` in `setup.c` (after it was moved to `odb_new()` in patch 3/6) feels awkward, though he acknowledges no better alternative exists; and the new `die()` message in `create_object_database()` is not translatable. Neither is a blocker, but both could be addressed in a future iteration if the series is otherwise ready.

The patch itself is uncontroversial and technically sound. It builds directly on the refactoring done in earlier patches (particularly the third and fourth) and aligns with the series’ architectural direction. The callback naming (`create_on_disk`) was previously discussed but deferred to maintain consistency with the ref subsystem’s `ref_store_create_on_disk()`; Toon does not revisit this. The implementation is straightforward, and the commit message clearly explains the exception for the top-level `objects/` directory.

Key technical details for follow-up: the callback is invoked in `create_object_database()` after ODB initialization, and the "files" backend’s implementation uses `safe_create_dir()` to create `pack/` and `info/` subdirectories. The patch also removes redundant environment variable checks from `create_object_database()`, as that logic was moved to `odb_new()` in patch 3/6. No new configuration options or user-visible behavior changes are introduced.

The series as a whole remains under review, with the first patch marked as "will merge to 'next'" in Junio’s "What's cooking" report due to its status as a correctness fix. The remaining patches (including this one) are uncontroversial and ready for merging, pending resolution of Toon’s alternative design proposal for patch 4/6. This patch does not interact with that discussion.
