This is the third patch in Patrick Steinhardt’s six-patch series refactoring Git’s object database (ODB) initialization to make on-disk structures pluggable. The patch moves handling of the `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables from `apply_repository_format()` into `odb_new()`, making the function self-contained and eliminating the need to duplicate environment variable logic in future call sites. This is a preparatory step for later patches that defer ODB construction and for a planned move of alternate handling into the "files" backend itself.

Toon Claes’s review is surface-level but constructive: he endorses the change ("I like this!") and points out a minor cleanup opportunity. The `xstrdup_or_null()` call for `secondary_sources` is now redundant because the variable is either set from an environment variable (already duplicated) or remains `NULL`, so the explicit duplication can be removed. Similarly, the `free()` call for `secondary_sources` is safe but unnecessary if the variable is never duplicated. These are small, mechanical improvements that do not affect behavior but tidy up the code.

The patch itself is uncontroversial and ready for merging. It touches only ODB initialization plumbing (`odb.c`, `odb.h`, `setup.c`, and a unit test) and does not alter user-visible behavior. The change is well-motivated in the commit message and aligns with the series’ broader goal of making ODB backends more modular. Toon’s feedback is the only response so far, and it is minor enough that Patrick may choose to incorporate it without a full v4.
