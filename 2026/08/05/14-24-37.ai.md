This is the final patch in Harald Nordgren’s `git branch --delete-merged` series, now merged to **'next'**. It adds `--dry-run` support to the new `--delete-merged` subcommand, allowing users to preview which branches would be deleted without modifying refs or configuration.

The implementation is straightforward: the `DELETE_BRANCH_DRY_RUN` flag is added to the existing deletion API, and `delete_branches()` skips ref/config deletion when the flag is set, printing "Would delete" messages instead. The dry-run mode is rejected unless `--delete-merged` is also specified, and the nonsensical `--dry-run --quiet` combination is explicitly blocked. Documentation is updated to describe the new option, and tests verify the output matches the real deletion/protection output exactly, including stacked-branch protection during dry runs.

This patch completes the series’ safety architecture by enabling users to sanity-check wide patterns (e.g., `origin/*`) before committing to deletions. The implementation is minimal and well-tested, with no functional changes since v24.
