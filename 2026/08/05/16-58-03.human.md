This is a bugfix for `git worktree add` that restores the intended behavior when `-b` or `-B` is used. The patch prevents Git from overriding an explicitly specified branch name with DWIM (Do What I Mean) logic, which was a regression introduced in Git v2.42.0. Junio C Hamano has reviewed the third iteration and is ready to merge it, with only a minor tweak to the commit message to use the standard reference format for the regression commit.

The fix is minimal and surgical: it adds a guard (`if (!new_branch)`) around the DWIM logic in `builtin/worktree.c`, ensuring it only triggers when no branch name is explicitly provided via `-b` or `-B`. The test case in `t/t2400-worktree-add.sh` verifies that `git worktree add -b branch ../wt foo` fails with the expected error message (`fatal: invalid reference: foo`) rather than silently creating a worktree for a remote-tracking branch. The test uses `setup_remote_repo` to create a controlled environment, avoiding redundant setup steps.

This version (v3) addresses all feedback from prior iterations, including preserving warning behavior for edge cases (e.g., using `-b` with `HEAD`) and refining the test for precision. The commit message has also been updated to use consistent single-quoted command invocations. The patch is narrowly scoped to the regression and has no unintended side effects.
