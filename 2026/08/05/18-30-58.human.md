This is the ninth patch in Johannes Schindelin’s v2 series fixing unchecked return values identified by Coverity. It targets the bisect subsystem, where two functions—`get_terms()` in `builtin/bisect.c` and `read_bisect_terms()` in `bisect.c`—read the `BISECT_TERMS` file without checking whether `strbuf_getline_lf()` succeeds. If the file is truncated (e.g., due to a crash or disk-full condition), the functions silently proceed with empty term names, leading to confusing downstream behavior like nonsensical ref names (`refs/bisect/` with no suffix).

The patch adds minimal error checks: in `read_bisect_terms()`, a failed `strbuf_getline_lf()` now calls `die()` with a descriptive message, matching the existing error-handling pattern for file-open failures. In `get_terms()`, a failed read returns `-1` and ensures proper cleanup with `FREE_AND_NULL(terms->term_bad)`, preventing resource leaks. The changes are uncontroversial and align with the defensive patterns used elsewhere in the codebase. Junio’s earlier review concern about proceeding with uninitialized data is fully addressed by the added checks. The patch is ready for integration.
