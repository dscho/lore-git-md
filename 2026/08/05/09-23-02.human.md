This is a **platform-compatibility bugfix** and part of Johannes Schindelin’s 12-patch series converting size fields in Git’s delta and pack machinery from `unsigned long` to `size_t` for 64-bit Windows correctness.

Patrick Steinhardt’s review of the third patch surfaces a latent configuration-parsing issue: `max_delta_cache_size` is currently set via `git_config_int()`, which accepts negative values. On 32-bit platforms this has always been broken (negative values wrap to huge positive numbers), but the patch’s widening to `size_t` makes the problem more visible. The documentation only mentions positive values, so the fix is uncontroversial in principle, but it would change behavior for anyone who mistakenly configured a negative value and relied on the current (accidental) “infinite cache” semantics.

The review is **substantive**: it identifies a real edge case, engages with the configuration system, and suggests a small but meaningful improvement (`git_config_uint()` or a new `git_config_size_t()` helper) that could be folded into the next iteration. The feedback is constructive and does not block the patch’s core goal.
