This is the second patch in Junio C Hamano’s three-patch v3 series fixing bash completion for `git diff`. It teaches the completion script to suggest **tracked paths** when no revision matches the user’s input or when `--` is present, aligning `git diff`’s behavior with `git status` and `git add`. The change ensures that `git -C <path> diff fil<TAB>` now correctly completes tracked files in the target repository rather than falling back to Bash’s default filename completion in `$PWD`. The patch adds 39 new test cases in `t/t9902-completion.sh` to verify the new behavior across local and `git -C` invocations, with and without `--`. No new CLI options, config keys, or on-disk formats are introduced; the change is purely behavioral and confined to `contrib/completion/git-completion.bash`. The implementation is straightforward: after `__git_complete_revlist_file()` yields no candidates, `_git_diff()` now calls `__git_complete_index_file()` to populate `COMPREPLY` with tracked paths. This patch is the core of the series’ goal—consistent, predictable path completion for `git diff`—and is uncontroversial given the thorough test coverage and alignment with existing completion patterns. The next patch (v3 3/3) will add untracked path fallback to handle edge cases like `--no-index`.
