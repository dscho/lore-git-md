This is a brief follow-up in the ongoing discussion about whether `git replay` and `git history` should preserve Git notes during history rewriting.

D. Ben Knoble acknowledges Phillip Wood’s suggestion that `git replay` (a plumbing command) should offer a command-line option to enable note copying, rather than relying on configuration. He suggests that the existing `notes.rewrite.<command>` configuration pattern might be worth considering, but concedes that Phillip’s point about keeping plumbing commands config-free makes sense. No new design direction is proposed; the exchange simply refines the earlier consensus that `git replay` should get an opt-in flag while `git history` handles notes automatically. The thread remains in the design-discussion phase with no patches yet.
