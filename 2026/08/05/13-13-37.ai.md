This is a bug report about `git rebase` losing notes when used with `-x` and `git commit --amend`.

The author, D. Ben Knoble, describes a scenario where they used `git rebase -x` with a `git commit --amend` command to adjust the author email of commits during a rebase. After completing the rebase, they discovered that the notes attached to the tip commit (stored in `refs/notes/benknoble/commits`) were lost, despite having configured `notes.rewriteref` to include that ref. The author notes that running `git commit --amend` directly *does* rewrite the notes, and a plain `git rebase` (without `-x`) also preserves them, suggesting the issue is specific to the combination of `rebase -x` and `commit --amend`.

The report includes relevant configuration details (e.g., `notes.rewriteref` and `core.notesref`) and a clear reproduction sketch, though the author acknowledges they haven’t minimized a test case yet. The issue appears to be a regression or edge case in how `git rebase -x` interacts with note rewriting during amend operations. The report is well-structured and provides enough context for someone familiar with the rebase and notes subsystems to investigate further. No prior discussion or thread context is provided, so this appears to be the first report of the issue.
