This thread is a refactoring series by Tian Yuchen that cleans up Git’s repository configuration handling in `environment.c` and `environment.h`. The v3 patches are technically complete, addressing all prior feedback from Junio C Hamano: commit messages and documentation are now clearer about the intended use of the `repo_config_values` structure and its getter functions, and misleading comments have been removed without altering behavior.

The series itself is ready for final review, but it has sparked a forward-looking discussion about Git’s configuration architecture. Patrick Steinhardt and Junio have explored whether the current design—where configuration is tied to `the_repository`—can be evolved into a hierarchical system with truly global (system- and user-wide) settings. Patrick’s latest email proposes merging `repo_settings` and `repo_config_values` into a single structure, then splitting it into repository-bound and global levels, with `repo_config_values()` returning an immutable pointer. While this would require significant caller-side changes, it’s seen as a principled direction for subsystems that don’t depend on repositories. Junio remains skeptical about whether `repo_init()` alone can make embedded settings usable, noting the current design still relies on global variables. Neither position blocks the current series, but the discussion may shape future work on configuration flexibility.
