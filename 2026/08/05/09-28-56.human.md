This is the final patch in Patrick Steinhardt’s six-part series making the creation of on-disk object database (ODB) structures pluggable. It implements the core infrastructure promised by the series: a new `create_on_disk` callback in the ODB source interface that lets each backend handle its own directory layout.

The patch wires up the callback for the "files" backend, which now creates its traditional `objects/pack` and `objects/info` subdirectories via the new mechanism. The top-level `objects/` directory remains a special case—it is still created unconditionally (unless overridden by environment variables) because Git needs it to recognize a repository at all. Everything else moves into the backend’s control.

Code changes are straightforward: the "files" backend (`odb/source-files.c`) gains a 20-line callback that creates the required subdirectories, the ODB source header (`odb/source.h`) adds the new vtable entry and a helper function, and `setup.c` replaces 16 lines of hard-coded directory creation with a single call to `odb_source_create_on_disk()`. The patch is mechanical and uncontroversial; it simply shifts responsibility from the generic setup code to the backend where it belongs.

This is a refactoring patch that enables future ODB backends to use custom on-disk layouts without touching core setup logic. It is part of the ongoing ODB abstraction effort and is ready for merging alongside the rest of the series.
