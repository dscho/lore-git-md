This is a **bugfix follow-up** to Patch 3/7 in Patrick Steinhardt’s ODB streaming API refactoring series. The patch corrects a **critical correctness issue** identified by Junio C Hamano: the in-memory ODB backend was computing the object name (`oid`) using `OBJ_BLOB` even when streaming non-blob objects, which could lead to silent corruption or hash collisions. Patrick acknowledges the bug, confirms its impact (wrong object header → wrong hash → wrong storage location), and states it is now fixed. The fix ensures `hash_object_file()` uses the intended `stream->type` instead of hard-coding `OBJ_BLOB`.
