This thread is about a bug in `git rebase -x` where notes attached to commits are lost when the external command amends the commit. D. Ben Knoble reported the issue, and Phillip Wood diagnosed the root cause: the rebase machinery records the new commit’s OID *before* the external command runs, so if `git commit --amend` changes it again, the notes-rewriting step misses the final OID.

Phillip has now proposed a new approach to fixing this. Instead of updating the rebase’s internal tracking file after the amend (as in his earlier, stalled branch), he suggests copying notes *before* the external command runs. This would let `git commit --amend` handle note copying directly, avoiding the need to track OIDs after the fact. The idea is still conceptual—no patch or test results yet—but it shifts the focus to preemptive note copying, which could simplify the fix. The main open question is how to handle conflicts during interactive editing, where this approach might be trickier. The thread remains in the design phase, with no concrete implementation posted.
