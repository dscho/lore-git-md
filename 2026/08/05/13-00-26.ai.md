This is a substantive review in the ongoing `git-replay` and `git-history` notes-preservation bugfix thread.

Phillip Wood joins the discussion to confirm the recent `git rebase` notes bug that both Patrick Steinhardt and D. Ben Knoble had vaguely recalled. He then weighs in on the design: for the plumbing-level `git replay`, he suggests a command-line option (not config) to enable note copying, while agreeing with Patrick that `git history` (user-facing) should handle notes automatically. The implication is that the shared implementation would live in the history-rewriting codebase, so both commands could reuse it once the plumbing flag is exposed. No timeline or assignee is proposed, but the design direction is now clearer—plumbing gets an opt-in switch, user-facing gets automatic behavior.
