This is patch 4/7 in Taylor Blau's RFC series addressing `--path-walk` filter integration, specifically adding support for the `combine` filter type. The series aims to make path-walk work with GitHub's infrastructure requirements by improving compatibility with various Git features.

The patch implements intersection logic for combining multiple filters, handling cases like:
- `blob:none` + `tree:0` (collapsing to `tree:0`)
- `object:type=blob` + `blob:limit=3` (yielding only small blobs)
- Incompatible combinations (like `object:type=blob` + `object:type=tree`)

Key technical aspects:
- Refactors filter preparation to support recursive handling of combined filters
- Maintains monotonic restriction properties for all supported child filters
- Preserves existing behavior for `sparse:oid` filters (only one allowed per combine)
- Adds comprehensive test coverage in t6601 for various combinations

The implementation appears clean and follows the pattern established in earlier patches of the series. The documentation is updated to include `combine` in the list of supported filter forms. As an RFC patch, it's likely to generate discussion about the recursive filter handling approach and edge cases in large repositories.
