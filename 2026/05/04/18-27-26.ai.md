Feature: Improved error handling for bulk branch deletion in the `fetch.pruneBranches` series.

This second patch in Harald Nordgren's v2 series enhances the branch deletion machinery to support bulk operations more cleanly. The changes modify `delete_branches()` and its helper `check_branch_commit()` to:

1. Add a `warn_only` mode that converts hard errors about unmerged branches into one-line warnings, while still skipping those branches from deletion. This prevents overwhelming users with verbose advice when pruning many branches at once.

2. Introduce a counter parameter `n_not_merged` that tracks how many branches were skipped due to unmerged changes, allowing bulk callers to provide a summary rather than per-branch details.

The existing single-branch deletion behavior (used by `git branch -d`) remains unchanged, as those callers pass the default values (0 and NULL). The new parameters are designed for the upcoming `--prune-merged` functionality where the focus is on cleaning up many branches at once.

The implementation shows careful attention to backward compatibility and maintains all existing safety checks - branches with unmerged work are still protected from deletion unless forced. The patch includes thorough updates to the error/warning messages and preserves the advisory messages for interactive use cases.

This change supports the series' goal of making branch cleanup more automated while respecting Git's safety mechanisms. The warning-only mode is particularly valuable for the planned `fetch --prune-merged` integration where users will want to see problems at a glance rather than wade through repeated advice blocks.
