This is the final iteration of the `--max-count-oldest` feature patch, which provides a cleaner way to show the oldest N commits in a revision walk without requiring awkward workarounds. The patch has evolved through five versions from Mirko Faina's original `--reverse=before` proposal, with maintainer Junio C Hamano now indicating the interface is preferable to previous approaches.

The implementation adds `--max-count-oldest` as a new commit-limiting option that avoids the current cumbersome alternatives - either needing to know the total commit count first (for `--skip`) or using shell pipelines with `tail`. The core algorithm preserves Jeff King's optimized sliding window approach (`retrieve_oldest_commits()`) that maintains O(K) space and O(N) time characteristics.

Junio's feedback focuses on final polish, noting the current version causes "measurably smaller damage to the codebase" than earlier iterations. He suggests rewording the commit message to better highlight the user experience improvement over the current workarounds, which Mirko acknowledges will be addressed in v6. With the technical implementation settled and maintainer approval indicated, this feature appears ready for inclusion in the next release cycle.
