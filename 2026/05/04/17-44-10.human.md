This is patch 6/9 in Karthik Nayak's v4 series refactoring Git's refs backend to consolidate object validation and peeling logic. The series is part of the ongoing effort to standardize behavior across Git's reference backends (files, packed, reftable).

This particular patch modifies `builtin/update-ref.c` to handle reference update rejections more robustly. The key changes:

1. Introduces a new `handle_ref_transaction_error()` helper that centralizes error handling for ref updates, distinguishing between generic failures (which abort the operation) and specific rejections (which can be allowed to fail when using `--batch-updates`).

2. Adds a `command_options` struct to track whether individual update failures should be tolerated, set when using `--batch-updates`.

3. Updates all the parse_cmd_* functions to use the new error handling infrastructure, ensuring consistent behavior across different update types (create, delete, symref operations etc).

The changes are mechanical but important - they prepare for upcoming patches that will move object validation earlier in the ref update process. The patch maintains existing functionality while making the error handling more systematic. With comprehensive test coverage added in previous iterations, this version appears ready for merging as part of the larger backend consolidation effort.
