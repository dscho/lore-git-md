This is patch 8/9 in a refactoring series that centralizes object validation and peeling logic in Git's reference backend system. The patch adds a `peeled` field to the `ref_update` struct to enable standardized tag object peeling across all ref backends (files, packed, reftable).

Key changes in this patch:
1. Introduces `REF_HAVE_PEELED` flag and `peeled` field in `ref_update` to store peeled OIDs
2. Modifies `ref_transaction_add_update()` to accept and store peeled OIDs
3. Updates `ref_transaction_update()` to perform tag peeling and pass results downstream
4. Adjusts all backend implementations (files, reftable) to handle the new parameter
5. Maintains special cases for reflog updates and deletions which don't need peeling

The change moves peeling responsibility from individual backends to the shared refs layer, continuing the series' goal of backend consolidation. The implementation appears thorough, with all call sites updated and the reftable backend's object.h include now properly redundant (to be removed in the next patch).

This is a mechanical but important step in the larger backend refactoring effort, ensuring consistent tag handling while simplifying backend implementations. The patch follows the established pattern of the series and appears ready for merging.
