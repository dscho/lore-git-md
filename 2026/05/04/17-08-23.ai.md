This is a test patch (6/11) in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The patch adds a regression test verifying that cloning repositories with objects exceeding 4GB works correctly after the fixes in earlier patches.

The test uses the new `test-tool synthesize pack` infrastructure (introduced in patch 5/11) to create a test repository containing a 4GB+1 byte blob. It then verifies the clone operation works through both unpack-objects and index-pack paths by comparing object IDs rather than sizes (since size reporting still uses 32-bit types on Windows).

Key technical details:
- Tests are marked SIZE_T_IS_64BIT to only run on platforms where size_t is 64-bit
- Uses fetch.unpackLimit to force testing both unpack-objects (limit=100) and index-pack (limit=1) code paths
- Verifies integrity by comparing OIDs rather than sizes due to remaining Windows limitations in object_info.sizep

The test demonstrates the core functionality fixed by the series - proper handling of large objects during clone operations. It builds on the test infrastructure improvements from earlier patches while avoiding known limitations (like size reporting) that will require future work. The patch fits cleanly into the series' progression from core fixes to validation.
