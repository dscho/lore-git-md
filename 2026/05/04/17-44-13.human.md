This is the final patch in a 9-part series refactoring Git's reference backend code to consolidate object validation and peeling logic. The series is part of the ongoing refs backend consolidation effort led by Karthik Nayak and Patrick Steinhardt.

The patch removes redundant `peel_object()` calls from the packed and reftable backends, since the peeled values are now provided by the generic refs layer (as established in previous patches). This completes the standardization of tag handling across all backends, ensuring consistent behavior while eliminating duplicate work.

Key changes:
- Packed and reftable backends now use the pre-peeled values from the `ref_update` struct rather than peeling tags themselves
- The reftable backend removes its now-unneeded `object.h` include
- Both backends check the `REF_HAVE_PEELED` flag to determine whether to write the peeled value

This is a mechanical cleanup that builds on the architectural changes from earlier in the series. With this patch, all backends handle tag peeling consistently through the shared layer rather than implementing their own logic. The changes are straightforward and well-contained, following the pattern established in the series.

The patch has already been reviewed in previous iterations (v4 addressing Toon Claes' feedback about error handling) and appears ready for merging. This completes the series' goal of moving object validation and peeling out of the individual backends and into the generic refs layer.
