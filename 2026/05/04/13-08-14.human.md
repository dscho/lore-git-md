This is the final iteration of a feature patch implementing `--max-count-oldest` for revision walks, now approved by maintainer Junio C Hamano. The patch provides a cleaner interface for showing the oldest N commits without requiring users to first determine the total commit count (as would be needed with `--skip`).

The implementation preserves the optimized sliding window algorithm (O(K) space, O(N) time) from earlier iterations while adopting Junio's preferred interface name. Key changes in this version include rewording the commit message to better highlight the awkwardness of current workarounds, as Junio noted the existing description understated the usability problem.

The patch extends `struct rev_info` with new flags to track the limiting behavior and includes comprehensive error checking for invalid option combinations. Test coverage in t4202-log.sh verifies both direct and reversed output cases. Junio's approval signals this is ready for inclusion, marking the successful conclusion of a multi-iteration effort that balanced technical excellence with interface clarity.
