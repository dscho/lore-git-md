This is a performance optimization patch in Derrick Stolee's series (v2 05/10) that adds blob size limit filter support to Git's path-walk API. The patch enables `--filter=blob:limit=<size>` functionality when using `--path-walk`, allowing exclusion of blobs above a specified size threshold.

The implementation:
- Adds blob size filtering during path traversal by checking object sizes via `odb_read_object_info()`
- Handles edge cases like missing objects (conservatively included) and zero limits (equivalent to `blob:none`)
- Updates `git backfill` to explicitly reject blob size limits since they would trigger inefficient single-object downloads
- Includes test cases validating both blob:limit=0 (all blobs excluded) and blob:limit=3 (partial filtering) behavior

The patch builds on previous work in the series to expand filter compatibility while maintaining performance. It demonstrates careful attention to edge cases and includes comprehensive test coverage. The implementation appears technically sound, though the interaction with partial clone behavior (where missing objects must be downloaded to check sizes) may warrant review from experts in that area.

This continues the series' focus on optimizing sparse-checkout scenarios while expanding the range of supported filters. The next steps likely involve further performance measurement and potentially optimizing the path-walk for sparse filters.
