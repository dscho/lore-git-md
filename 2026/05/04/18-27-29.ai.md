Feature: Per-branch opt-out for automatic pruning via `branch.<name>.pruneMerged` config.

This patch adds a configuration option to exempt specific branches from being automatically deleted by `git branch --prune-merged` and `git fetch --prune-merged`. When `branch.<name>.pruneMerged` is set to false, the branch will be preserved even if its upstream tracking ref has been deleted and the branch would otherwise qualify for pruning.

Key aspects:
- The opt-out is respected even when using `--force`, maintaining protection for designated branches
- Explicit deletion via `git branch -d` remains unaffected by this setting
- The implementation includes clear warning messages when skipping protected branches
- Comprehensive test coverage verifies:
  - Basic opt-out behavior
  --force interaction
  - Explicit deletion independence
  - Warning message output

This completes the safety mechanisms for the automatic branch pruning feature, allowing users to mark long-lived topic branches that should persist between development cycles while still benefiting from automated cleanup of temporary branches. The implementation integrates cleanly with the existing `--prune-merged` plumbing from earlier patches in the series.

The documentation updates clearly explain the new configuration option and its relationship to both the plumbing commands and the porcelain `fetch --prune-merged` interface. The tests demonstrate all specified behaviors while maintaining the series' pattern of focused, scenario-based verification.
