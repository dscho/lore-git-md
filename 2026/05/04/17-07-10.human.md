This is a continuation of the discussion about test suite management in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The thread has evolved from technical fixes to broader questions about test infrastructure.

Schindelin responds to concerns raised by Derrick Stolee and Jeff King about the execution time and resource usage of the new regression tests. He explains his efforts to optimize the test cases by using unsafe SHA-1 hashing and adding shortcuts for the 4GB+1 test cases, though notes the fundamental limitations that make the `git clone` test unavoidably slow. As a result, he's marked the tests as `EXPENSIVE`.

The email reveals an interesting technical constraint - the incompatibility between OpenSSL's license and Git's GPLv2 that prevents using OpenSSL's more efficient SHA-1 implementation, despite Linus Torvalds' original intention to allow it. Schindelin also proposes running all `EXPENSIVE` tests in CI for integration branches (except `seen`), though acknowledges this might warrant being a separate patch.

The discussion highlights the practical challenges of maintaining comprehensive test coverage while balancing resource constraints, particularly for platform-specific issues. Schindelin's pragmatic solution of keeping the CI change in the current series while being open to splitting it out reflects the real-world tradeoffs contributors face when trying to land complex changes.
