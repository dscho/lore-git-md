This is a platform compatibility patch from Johannes Schindelin (Git for Windows maintainer), part of a series addressing Windows-specific issues with large objects (>4GB) during cloning. This particular patch focuses on the object database (ODB) and packfile streaming interfaces.

The core change replaces `unsigned long` with `size_t` in the `odb_read_stream` structure and related functions to prevent truncation of large object sizes on Windows (where `unsigned long` is 32-bit even in 64-bit builds). The patch carefully maintains API compatibility where needed, using temporary variables and adding comments to document remaining truncation limitations in some paths.

Key technical aspects:
- Updates `odb_read_stream.size` to use `size_t` instead of `unsigned long`
- Introduces `unpack_object_header_sz()` variant that returns sizes via `size_t*`
- Maintains backward-compatible `object_info.sizep` (which remains `unsigned long*`) with clear comments about truncation risks
- Updates callers across packfile handling code to use the new size types

The changes appear well-contained and focused on the specific Windows limitation. The patch includes authorship clarification (originally by "LordKiRon" but now attributed to Schindelin) and follows the pattern of similar conversions in the codebase. This is part of a larger effort to properly handle large objects on Windows, with more work still to come on other code paths like `cat-file` and delta machinery.
