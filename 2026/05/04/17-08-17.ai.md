This is a platform compatibility patch series from Johannes Schindelin (Git for Windows maintainer) addressing Windows-specific issues with large objects (>4GB) during cloning. The v2 iteration builds on the initial fixes with significant test infrastructure improvements and CI integration changes.

The core technical problem remains the same: Windows' 32-bit `unsigned long` causes object size truncation in critical paths. The series systematically replaces these with 64-bit `size_t` across:
- index-pack/unpack-objects
- zlib wrapper
- ODB/packfile streaming
- delta header handling

New in v2 are optimizations to the test infrastructure:
1. Added unsafe SHA-1 hashing mode to accelerate test pack generation
2. Precomputed "Lego block" packs for common test cases (4GB+1)
3. Marked the large-object tests as EXPENSIVE due to their 160s runtime and 4-8GB disk requirements
4. Proposed CI policy change: run EXPENSIVE tests on integration branches (except `seen`)

The test optimizations help mitigate the fundamental slowness of cloning large objects, though OpenSSL licensing prevents more efficient implementations. The series still represents just the first step - many other code paths (cat-file, delta machinery) remain to be converted.

Schindelin shows responsiveness to review feedback by proposing the EXPENSIVE test classification as a compromise between thorough validation and CI resource constraints. The changes appear well-motivated given Windows' platform limitations and the clear regression test coverage. The series builds on work by "LordKiRon" and remains focused on the most severe truncation issues that prevent large objects from surviving clones at all.
