# Platform compatibility patch for Windows large object handling

This is the fourth patch in Johannes Schindelin's series addressing Windows platform limitations with objects larger than 4GB during cloning. The patch focuses on delta header size handling, introducing 64-bit variants of key functions to prevent truncation issues.

The core change introduces `size_t` variants of delta header parsing functions (`get_delta_hdr_size_sz()` and `get_size_from_delta_sz()`) while maintaining the existing `unsigned long` versions for compatibility. The new functions are used in `packed_object_info()` where accurate size tracking is critical for streaming decisions, though the patch notes that truncation may still occur when storing results in the `object_info.sizep` field (which remains `unsigned long*`).

The patch was originally authored by an anonymous contributor (LordKiRon) who transferred authorship to Schindelin. It builds on the previous patches in the series that addressed similar truncation issues in index-pack, zlib, and packfile streaming. The changes appear well-contained and focused on the specific Windows limitation, with clear comments explaining the purpose of each new function.

This continues the series' pattern of methodically converting size handling to 64-bit types while maintaining backward compatibility, though as noted in the thread summary, some paths (like loose object handling) remain to be addressed in future work.
