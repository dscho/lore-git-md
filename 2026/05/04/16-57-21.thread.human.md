This thread examines edge cases in Git's clean/smudge filter behavior, particularly concerning binary files that match filter patterns. Randall Becker (NonStop platform maintainer) initially raised concerns about how filters handle directories containing both text files meant for filtering and binary files that also match the pattern. Junio Hamano clarified Git's design: filters process all matching files regardless of binary/text designation, with the expectation that binary data can pass through stdin/stdout (as seen in JPEG exif textconv), and that precise .gitattributes patterns should control filtering rather than runtime detection.

Randall has now acknowledged this design and plans to implement an extension-based solution to manage .gitattributes patterns automatically. This approach aligns with Git's philosophy of precise upfront configuration over runtime adaptation. The thread appears to be reaching a resolution, with Randall working within Git's existing framework rather than proposing core changes. This outcome demonstrates Git's strong preference for explicit configuration patterns, even when they require more initial setup, over more forgiving but potentially ambiguous runtime behaviors.
