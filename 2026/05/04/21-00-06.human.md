This is a follow-up discussion in the thread about adding diff-stat placeholders to Git's pretty formats. The author, Andrey Zarubin, responds to Junio C Hamano's concern that the feature might open the door to more extensive diff content in log formats.

Zarubin makes a key distinction between the proposed numeric counters (files changed, insertions, deletions) and more complex diff output. He argues that the current proposal only exposes bounded scalar values already available via `--shortstat`, while path summaries and patch text would be qualitatively different as they involve multi-line, formatted output. The author suggests this boundary could be reinforced by dropping the short aliases (%aF, %aA, %aR) and keeping only the explicit `%(diff-stat:<field>)` forms.

The response is thoughtful and directly addresses the maintainer's design concerns, attempting to draw a clear line between what should and shouldn't be included in pretty formats. This moves the discussion forward by offering a principled limitation on the feature's scope, though it remains to be seen whether Junio will find this distinction sufficient.
