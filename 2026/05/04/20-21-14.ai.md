This is a performance optimization patch from Derrick Stolee (with Taylor Blau) that adds blob size limit filter support to the path-walk API, part of their ongoing series to improve `git pack-objects` and related commands. The patch builds on previous work integrating path-walk with object filters.

The key technical change enables the path-walk API to handle `blob:limit=<size>` filters natively. When this filter is active, the walk will skip blobs equal to or larger than the specified size. The implementation:
- Stores the size limit in the walk context during filter preparation
- Checks each blob's size via `odb_read_object_info()` during traversal
- Skips blobs that meet/exceed the limit while preserving those that don't
- Includes special handling for blob:limit=0 (equivalent to blob:none)
- Updates `git backfill` to explicitly reject size-limited filters since they would trigger undesirable on-demand downloads

The patch adds test coverage for both blob:limit=0 and blob:limit=3 cases, verifying the filtering behavior works as expected. The implementation appears thorough, with careful attention to edge cases like missing objects (which are conservatively included) and proper batch processing.

This continues the series' pattern of comprehensive test coverage and thoughtful integration with existing systems. The change maintains backward compatibility while expanding filter support, though the performance implications of size checks (which may trigger object downloads) are noted as a consideration for future optimization.
