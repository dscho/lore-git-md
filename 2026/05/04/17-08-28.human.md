This is the final patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The patch focuses on CI integration for the expensive tests introduced earlier in the series.

The change modifies the CI configuration to run expensive tests (marked with the EXPENSIVE prereq) only on push builds to integration branches (next, master, main, maint) rather than on every PR iteration. This responds to feedback from Derrick Stolee about balancing thorough testing with CI resource constraints. The tests in question involve cloning objects >4GB and can take several minutes to run while consuming multiple GB of disk space.

The implementation adds a case statement to ci/lib.sh that sets GIT_TEST_LONG=YesPlease when the GITHUB_EVENT_NAME is "push" and the branch is one of the integration branches. This follows Git's existing pattern for similar test gating while specifically addressing the resource concerns raised during review.

This patch completes the series by ensuring the new large-object tests will run in CI at an appropriate cadence without slowing down every PR build. The change appears well-considered and maintains the series' focus on practical Windows compatibility improvements.
