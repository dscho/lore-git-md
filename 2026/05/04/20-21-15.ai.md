This is a performance optimization patch from Derrick Stolee that enhances the path-walk API's handling of sparse-checkout patterns. It's part of a larger series (v2 06/10) integrating path-walk with various filter options in `git pack-objects`.

The key change introduces a `pl_sparse_trees` flag to control whether sparse patterns should prune both trees and blobs (current behavior) or just blobs (new mode needed for sparse filters). The patch:

1. Adds the flag to `path_walk_info` and sets it in `git backfill --sparse`
2. Modifies tree entry processing to check this flag before applying sparse patterns to trees
3. Fixes a subtle SEEN flag timing issue where identical objects at multiple paths could be incorrectly skipped
4. Extends the test helper to toggle tree pruning behavior
5. Adds new test cases verifying the no-tree-pruning mode

The implementation carefully preserves existing backfill behavior while enabling future sparse filter integration. The SEEN flag fix addresses a real edge case where objects could be missed when appearing at both sparse and non-sparse paths. Test coverage is thorough, including a new scenario that walks all trees while still filtering blobs by sparse patterns.

This change demonstrates the series' attention to both performance optimization and correctness, with clear documentation of the new flag's purpose in the header comments. The patch builds logically on previous work while cleanly separating concerns between backfill's needs and upcoming filter support.
