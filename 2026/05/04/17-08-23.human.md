This is a test patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The patch adds regression tests for cloning repositories containing objects larger than 4GB, specifically verifying the fixes for size truncation issues in index-pack and unpack-objects.

The test creates a synthetic packfile with a 4GB+1 byte blob using the new `test-tool synthesize pack` helper introduced earlier in the series. It then verifies the object survives cloning intact by comparing OIDs between source and clone repositories, since direct size comparison would still be unreliable on Windows due to remaining unsigned long limitations in some paths.

The test exercises both unpack-objects and index-pack code paths by controlling fetch.unpackLimit, providing comprehensive validation of the core fixes. This is part of the broader effort to make Git properly handle large objects on Windows where 32-bit types would previously cause truncation. The test is marked as SIZE_T_IS_64BIT to only run on platforms where size_t is 64-bit.

The patch appears well-crafted, with clear test cases that directly validate the specific fixes from earlier in the series. The use of OID comparison rather than size checks shows thoughtful consideration of remaining Windows limitations while still providing strong verification. This continues the series' pattern of thorough, platform-aware testing.
