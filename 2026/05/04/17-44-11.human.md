This is patch 7/9 in Karthik Nayak's v4 series refactoring Git's reference backend system. The patch moves object validation logic from individual backends (files, packed, reftable) into the generic refs layer, eliminating duplicate code.

The key change is that object existence and type checking (via `parse_object()`) now happens when updates are queued in `ref_transaction_update()`, rather than during transaction preparation. This provides earlier validation and makes the backends simpler by removing their responsibility for object validity. The patch:

1. Adds validation to `ref_transaction_update()` that checks new object IDs exist and are commits when updating branches
2. Removes now-redundant validation from both the files and reftable backends
3. Updates `receive-pack` to handle the new error reporting structure
4. Adds new tests verifying the error cases

This is a mechanical but important step in the larger backend consolidation effort, making the backends more focused on storage while centralizing common logic. The changes are well-contained and maintain backward compatibility, with thorough test coverage added for the new error paths.

As part of a mature series that has already addressed reviewer feedback in previous iterations, this patch appears ready for merging as part of the complete refactoring.
