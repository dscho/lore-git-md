This is a test infrastructure patch (8/11) in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The patch introduces a significant optimization for test pack generation by adding a precomputed "fast path" for 4GB+1 byte test objects.

The key technical contribution is replacing the expensive SHA-1 hashing of 8GB of NUL bytes (previously taking 80-140 seconds) with direct writing of precomputed packfile data. The new approach uses deterministic constants for:
- Pack header and object headers
- Zlib stream structure (with periodic deflate block headers)
- Tree and commit objects in the suffix
- Pack checksum

The optimization reduces pack generation time from minutes to seconds (14-15s in benchmarks), making the large-object tests practical to run in CI. The implementation is structured to support adding SHA-256 later through a hash-algorithm-specific suffix table.

The patch demonstrates responsiveness to prior review feedback about test runtime concerns from Derrick Stolee and Jeff King. By eliminating the SHA-1 bottleneck, it enables thorough testing of the 32-bit truncation fixes while remaining resource-efficient. The precomputed approach is safe because every byte in the generated pack is deterministic for a given blob size and hash algorithm.

This builds on the test infrastructure foundation laid in earlier patches (particularly 5/11's `test-tool synthesize pack` command) and prepares for the CI integration work in subsequent patches. The change is Windows-specific in motivation but improves testing infrastructure for all platforms.
