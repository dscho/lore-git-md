This is patch 5/7 in Taylor Blau's RFC series addressing `--path-walk` compatibility with reachability bitmaps and delta-islands. The patch focuses specifically on enabling bitmap support during path-walk operations, removing a previous restriction that prevented bitmap usage entirely.

The key changes are:
1. Removing the forced `use_bitmap_index = 0` when `--path-walk` is active
2. Adding `index_commit_for_bitmap()` calls during path-walk's commit processing
3. Updating documentation to reflect the new fallback behavior (bitmap first, then path-walk)
4. Adding comprehensive tests in t5310 that verify both writing and reading bitmaps with path-walk

The implementation handles both bitmap generation (during repacking) and usage (during fetches/clones) by ensuring:
- Bitmap writing sees all commits via the path-walk callback
- Bitmap reading works because `--objects` flag provides the necessary object type flags
- Fallback to path-walk occurs naturally when bitmaps can't satisfy the request

The test coverage is thorough, checking both with and without pack reuse to ensure the bitmap logic works independently of pack-reuse optimizations. The changes are relatively focused, touching just a few key locations in the pack-objects code.

This appears to be a well-constructed patch that removes an artificial limitation while maintaining the existing fallback behavior. The RFC flag suggests the author wants review on the approach, particularly around the interaction between path-walk ordering and bitmap selection heuristics.
