This is a test infrastructure patch (5/11) in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The patch introduces a new test helper tool to efficiently generate synthetic packfiles containing very large objects for testing purposes.

The new `test-tool synthesize pack` command creates packfiles with:
- A single large blob (filled with NUL bytes) of specified size
- Supporting tree and commit objects to make it reachable
- An empty tree and child commit to complete the history

The implementation bypasses normal Git object creation to optimize speed, using direct zlib stream writing techniques. This reduces test setup time from over 10 hours (using regular Git commands) to about 2.5 minutes for a 4.5GB packfile. The tool handles the packfile checksum calculations properly while avoiding expensive SHA-1 computations where possible.

Key technical details:
- Uses uncompressed zlib blocks with proper headers/checksums
- Maintains packfile integrity through proper hash calculations
- Outputs the final commit OID for test script reference
- Designed specifically to test the >4GB object handling that triggers Windows truncation bugs

This test helper enables the subsequent patches in the series to validate the Windows fixes with realistic large-object scenarios. The approach represents a careful balance between test validity (requiring reachable objects) and practical CI runtime constraints. The patch follows Git's test infrastructure patterns while adding specialized functionality needed for this platform-specific testing.
