Feature: Revised implementation of automatic local branch pruning via new `git branch` plumbing commands.

Harald Nordgren's v2 series completely reworks the approach to pruning local branches when their upstream remote-tracking refs are deleted, following Junio Hamano's architectural feedback. Instead of implementing the logic directly in `git fetch`, the functionality is now decomposed into new `git branch` plumbing commands that `fetch` can compose:

1. `git branch --forked <remote>` lists local branches tracking the given remote (read-only building block)
2. `git branch --prune-merged <remote>` deletes local branches whose tips are reachable from their upstream tracking ref
3. `--force` skips the reachability check (unpushed work only recoverable via reflog)
4. `--all-remotes` operates across all configured remotes at once

The currently checked-out branch is always preserved, and individual branches can opt out via `branch.<name>.pruneMerged=false`. The `fetch --prune-merged` command now simply calls this plumbing after fetching.

Key improvements from v1:
- More composable design with standalone plumbing commands
- Simpler configuration (per-branch opt-out rather than global modes)
- Better error handling with one-line warnings for skipped branches
- More focused tests (most logic now in t3200-branch.sh)

The series appears well-structured with thorough documentation and test coverage. The architectural shift addresses Junio's concerns while maintaining the original feature's value - automating cleanup of merged topic branches while protecting unpushed work. The per-branch opt-out via config is a better fit for Git's typical workflow patterns than the previous global safe/force modes.
