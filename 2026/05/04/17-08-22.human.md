This is part 5/11 of Johannes Schindelin's platform compatibility series addressing Windows' 32-bit size limitations when handling large objects (>4GB). The patch introduces a test helper tool to efficiently generate synthetic packfiles containing very large objects for testing purposes.

The new `test-synthesize` tool can create packfiles with a single large (>4GB) reachable blob in about 2.5 minutes - a significant improvement over naive approaches that would take hours. The tool works by:
1. Writing uncompressed zlib streams directly (bypassing Git's normal compression)
2. Creating a minimal commit history containing one large blob
3. Generating proper packfile checksums and object headers

This enables testing Git's ability to handle large objects on Windows where 32-bit `unsigned long` would normally cause truncation. The synthetic packs include:
- A large NUL-filled blob
- A tree referencing the blob
- A commit pointing to that tree
- An empty tree
- A final commit with the empty tree

The implementation carefully maintains packfile validity while optimizing for speed, making it practical to include these tests in CI. This is part of Schindelin's broader effort to make Git properly handle large objects on Windows platforms.
