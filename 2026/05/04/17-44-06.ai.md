This is patch 2/9 in Karthik Nayak's v4 series refactoring Git's reference backend infrastructure. The patch introduces a new `ref_store_init_options` structure to standardize how initialization options are passed to ref backends.

The key change replaces direct passing of `access_flags` with a structured approach that can be extended in future commits (notably to include reflog configuration). The patch:

1. Defines `struct ref_store_init_options` in `refs-internal.h` to hold backend initialization parameters
2. Updates all three backend implementations (files, packed, reftable) to use the new structure
3. Modifies the core `ref_store_init()` function to construct and pass the options

The changes are mechanical but important for the series' goal of consolidating backend behavior. The patch maintains all existing functionality while providing a cleaner foundation for upcoming changes to reflog handling in later patches. As part of the broader backend consolidation effort, this helps standardize how backends receive their configuration.
