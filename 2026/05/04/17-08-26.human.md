This is part 9/11 of Johannes Schindelin's platform compatibility series addressing Windows' handling of large objects (>4GB) during cloning. The patch adds SHA-256 support to the test infrastructure's precomputed packfiles, which were introduced in earlier patches to speed up testing of large object handling.

The change adds a new SHA-256 variant of the test packfile suffix data (609 bytes vs SHA-1's 513 bytes) with matching structure but different OID sizes and checksums. The constants were generated from a SHA-256 repository to ensure correctness. This maintains the series' test optimizations while extending coverage to SHA-256 repositories, important for future-proofing the large object handling.

The patch is a mechanical addition following the same pattern as the SHA-1 implementation from earlier in the series. It demonstrates responsiveness to the broader context of Git's hash algorithm transition work, though the immediate focus remains on the Windows-specific 32-bit truncation issues. The precomputed packs continue to provide the same test speed benefits (5-10x faster than runtime generation) for SHA-256 as they did for SHA-1.
