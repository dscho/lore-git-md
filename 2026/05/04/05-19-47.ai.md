This is a feature patch implementing the `--max-count-oldest` option for revision walks, representing the final iteration of a feature that evolved from the `--reverse=before` proposal. Maintainer Junio C Hamano provides feedback on the v5 submission from Mirko Faina, noting the new interface is cleaner than the previous approach.

The patch introduces `--max-count-oldest` as a user-friendly way to show the oldest N commits without requiring awkward workarounds like combining `--max-count` with `--skip`. Junio points out the current alternatives are particularly cumbersome, requiring users to first determine the total number of interest before using `--skip`.

Key technical aspects:
- Adds new `max_count_type` and `max_count_stage` flags to `struct rev_info` to track the limiting behavior
- Implements `retrieve_oldest_commits()` which maintains the optimized sliding window approach from previous versions (O(K) space, O(N) time)
- Includes comprehensive error checking for invalid option combinations with `--max-count` and `--skip`
- Adds test cases verifying both direct and reversed output behavior

Junio's response indicates approval of the direction, noting the implementation causes "measurably smaller damage to the codebase" compared to the earlier `--reverse=before` approach. The thread appears to be reaching consensus, with the maintainer's feedback focused on the interface design rather than the underlying algorithm.

This represents the culmination of several iterations that preserved Jeff King's state machine design and Tian Yuchen's performance analysis while addressing Junio's concerns about the original interface approach. The feature is now ready for potential inclusion in the next release cycle.
