This is patch 8/9 in a refactoring series that standardizes object validation and peeling logic across Git's reference backends (files, packed, reftable). The series is part of the ongoing backend consolidation effort led by Karthik Nayak and Patrick Steinhardt.

The current patch adds infrastructure to handle peeled object IDs at the generic refs layer rather than having each backend implement it separately. Specifically:

- Adds a `peeled` field to the `ref_update` struct to store peeled OIDs when available
- Modifies `ref_transaction_add_update()` to accept and store peeled OIDs
- Updates `ref_transaction_update()` to peel tag objects and pass the result downstream
- Adjusts all callers to pass NULL for peeled OIDs where appropriate (reflog updates, deletions)

The change is mechanical but wide-ranging, touching multiple backend implementations and call sites. The goal is to enable future patches to remove backend-specific peeling logic, making the backends more consistent and simpler. 

This version appears well-tested and addresses all feedback from the v3 review. The series as a whole has strong architectural approval and seems ready for merging. The final patch (9/9) will complete the transition by removing the now-redundant backend peeling code.
