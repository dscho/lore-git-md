This is the first patch in Johannes Schindelin's v2 series addressing Windows platform limitations with large objects (>4GB). The patch focuses on index-pack and unpack-objects, changing size variables from `unsigned long` to `size_t` to prevent truncation when handling large objects.

The technical change is straightforward but important: Windows' 32-bit `unsigned long` causes object size truncation during packfile operations, corrupting or rejecting objects over 4GB. The patch modifies the size handling in both commands to use 64-bit `size_t` where appropriate, particularly in the shift arithmetic that decodes variable-length size encodings.

Notable details:
- Originally authored by an anonymous contributor ("LordKiRon") who transferred authorship to Schindelin
- Changes are mechanical but critical for correct large object handling
- Part of a broader effort to make Git handle large objects properly on Windows
- Follows similar size_t conversions elsewhere in the codebase (like f9ba6acaa934)

The patch appears well-contained and focused on the immediate issue without introducing broader architectural changes. As the first in a series, it sets up the foundation for subsequent patches that will address related issues in other subsystems.
