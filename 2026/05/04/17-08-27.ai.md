This is a test infrastructure patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). As part 10/11 of the v2 series, it marks the >4GB clone tests as EXPENSIVE to avoid running them in normal test suites due to their significant runtime (200-850 seconds) and disk space requirements (4+ GiB). The change responds to feedback from Jeff King about the tests' resource impact, particularly for developers using RAM disks.

The patch modifies t/t5608-clone-2gb.sh to gate the large-object tests behind both SIZE_T_IS_64BIT and EXPENSIVE prerequisites. This ensures the tests will only run when explicitly requested via GIT_TEST_LONG, while still maintaining the platform-specific guard for 64-bit systems. The tests remain important for validating the Windows fixes but are now opt-in rather than part of default test runs.

This change reflects the series' ongoing effort to validate the core Windows compatibility fixes while being considerate of developer workflows and CI resources. The EXPENSIVE classification follows established Git test suite conventions for resource-intensive tests.
