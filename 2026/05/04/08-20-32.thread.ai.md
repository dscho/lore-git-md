Thread identity: Bug report about `git clone --dissociate` failing during checkout when using a reference repository, with "unable to parse commit" errors despite successful clone.

Core problem: When cloning with `--dissociate` and a reference repository, the checkout phase fails to resolve commits that should be available, suggesting premature dissociation from the reference repo's object store. The issue is reproducible locally and occurs intermittently in CI.

Current status: Unresolved bug affecting Git 2.47.3 through 2.53.0, reported with complete reproduction recipe. The failure occurs during post-clone checkout when `--dissociate` is active, regardless of `--depth` usage.

Key technical details:
- Failure occurs in the checkout phase after successful object transfer
- Reference repository maintained via standard mirroring workflow (`clone --mirror` + `remote update`)
- Error suggests reference repo objects become inaccessible during critical window
- `--dissociate` appears to sever object links before checkout completes

Open questions:
- Exact timing of dissociation relative to checkout operations
- Whether this violates documented `--dissociate` behavior
