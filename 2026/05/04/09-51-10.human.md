This is a bugfix for `git clone --dissociate` that addresses a race condition with commit-graph handling. Jeff King (Peff) explains the root cause: when cloning with a reference repository, Git may load commit objects from the reference repo's commit-graph file but defer loading their tree contents. If `--dissociate` closes the reference repo's object database before checkout needs those trees, Git fails to find them, producing "unable to parse commit" errors.

The fix modifies `repo_get_commit_tree()` to fall back to reading the commit object directly when graph-derived data is missing, which occurs after dissociation. This matches behavior discussed in an earlier thread but not previously implemented. The patch includes a workaround (`-c core.commitGraph=false`) for affected users until the fix lands.

This is a subtle interaction between three features: reference repositories, commit-graph acceleration, and the `--dissociate` optimization. The bug manifests during checkout after successful cloning, making it particularly confusing for users. The analysis confirms the reporter's suspicion that dissociation was happening too early in the process, though the mechanism (commit-graph invalidation) was more nuanced than expected.
