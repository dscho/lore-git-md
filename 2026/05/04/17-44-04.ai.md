This is the v4 cover letter for a refactoring series that moves object validation and peeling logic from individual ref backends to the generic refs layer, part of the ongoing backend consolidation effort led by Karthik Nayak and Patrick Steinhardt.

The series has evolved through four iterations, with v4 specifically addressing an error handling issue identified by Toon Claes in patch 6/9 of v3. The key changes in this version:

1. Introduces a new `handle_ref_transaction_error()` helper function to centralize error handling for ref updates
2. Adds missing test coverage for error cases when updating refs with non-commit objects
3. Maintains all the architectural improvements from previous versions while fixing the specific edge case

The core work remains:
- Moving object parsing/validation earlier in the ref update process
- Standardizing peeled tag handling across backends via a new `peeled` field in `ref_update`
- Extracting reflog configuration to the generic layer

The series touches multiple components including `update-ref`, `receive-pack`, and all three ref backends (files, packed, reftable). Karthik notes this emerged from working on other ref-related code, indicating these are practical pain points rather than theoretical cleanups.

With the error handling fix in place and new test coverage added, this version appears ready for final review. The changes are mechanical but wide-ranging, affecting how ref updates are validated throughout the system. The consolidation work should make the backends more consistent while simplifying their individual responsibilities.
