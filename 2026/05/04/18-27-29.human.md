Feature: Per-branch opt-out for automatic pruning of merged branches.

This patch adds a `branch.<name>.pruneMerged` configuration option that allows individual branches to be excluded from automatic pruning via `git branch --prune-merged` and `fetch --prune-merged`. When set to `false`, the branch will be preserved even if its upstream tracking ref has been deleted and the branch would otherwise qualify for pruning.

The implementation maintains all existing safety checks - the currently checked-out branch is still preserved across all worktrees, and the configuration only affects the automatic pruning behavior. Explicit deletion with `git branch -d` remains unaffected, providing a clear escape hatch when users want to manually remove protected branches.

The patch includes thorough test coverage demonstrating:
- Basic opt-out functionality
- That the opt-out persists even with `--force`
- That manual deletion still works
- Clear warning messages when skipping protected branches

This completes the safety mechanisms for the new branch pruning functionality, following the architectural direction established in earlier patches of the series. The per-branch granularity provides a natural way to handle long-lived topic branches that go through multiple rounds of development while still allowing cleanup of short-lived feature branches.
