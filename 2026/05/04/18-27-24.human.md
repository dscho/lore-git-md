Feature: Revised approach for automatic local branch pruning after fetch, now using `git branch` plumbing commands.

Harald Nordgren has revised his proposal for automatically pruning local branches when their upstream remote-tracking refs are deleted. Following Junio Hamano's architectural feedback, the functionality has been moved out of `git fetch` and into new `git branch` plumbing commands, making the feature more composable.

The v2 series introduces:
- `git branch --forked <remote>` to list local branches with upstreams on a given remote
- `git branch --prune-merged <remote>` to delete those branches if their tips are reachable from upstream
- A `--force` option to skip the reachability safety check
- `--all-remotes` to operate across all configured remotes
- A per-branch `branch.<name>.pruneMerged=false` opt-out for long-running branches
- Simplified `git fetch --prune-merged` that calls the new plumbing

The implementation preserves the key safety features from v1: the checked-out branch is always protected, and unpushed work is preserved (unless `--force` is used). The new approach gives users more direct control through standalone commands while maintaining the convenience of automatic cleanup during fetch.

This appears to be a thoughtful response to the maintainer's feedback, restructuring the feature into more fundamental building blocks while preserving the original goal of automated branch cleanup. The test coverage remains thorough, now split between `t3200-branch.sh` for the new plumbing and a smaller set in `t5510-fetch.sh`.
