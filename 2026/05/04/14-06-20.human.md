This is the third patch in Phillip Wood's four-part performance optimization series for xdiff diff algorithm memory usage. The series has already received thorough technical review from Junio C Hamano in its v1 iteration, and this v2 version maintains the same changes with only a rebase.

The current patch simplifies error handling in `xdl_cleanup_records()` by combining two separate allocation failure checks into a single conditional with a logical OR. This is a straightforward cleanup that makes the code more concise while maintaining identical behavior - if either allocation fails, the same cleanup path is taken. The change also sets up the code to more easily accommodate additional allocations in future changes (as hinted at in the commit message).

As with the rest of the series, this is a mechanical improvement that doesn't affect the actual diff results, only the memory usage patterns. The patch has already been reviewed and approved in principle by Junio, and the v2 changes appear to be just a rebase with no substantive modifications.
