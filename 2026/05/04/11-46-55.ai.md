This is a review of a preparatory refactoring patch in Christian Couder's URL-based promisor remote auto-configuration series. The patch adds infrastructure for handling locally configured remote names that differ from server-advertised names, without yet implementing the actual auto-configuration behavior.

Toon Claes confirms the patch is purely mechanical at this stage, noting that since `local_name` isn't yet populated, the new helper function `promisor_info_internal_name()` simply falls back to the existing `name` field. This maintains the current behavior while setting up the structure for subsequent patches that will implement the name differentiation. The review is surface-level, verifying the refactoring doesn't introduce functional changes yet.

The patch is part of a larger effort to improve promisor remote configuration by allowing URL pattern-based auto-configuration, with this particular change enabling clean separation between server-advertised and locally configured remote names. The series has already received positive reviews from key contributors like Patrick Steinhardt and Junio Hamano.
