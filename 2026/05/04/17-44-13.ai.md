This is the final patch (9/9) in Karthik Nayak's v4 series refactoring Git's reference backend architecture. The patch completes the consolidation of tag peeling logic by having the packed and reftable backends use the pre-peeled values now provided by the generic refs layer, rather than performing their own peeling operations.

The change is mechanical but important - it removes duplicate peeling work that was previously done independently by each backend. The patch modifies both backends to check the new `REF_HAVE_PEELED` flag and use the `peeled` field from the `ref_update` struct that was introduced in earlier patches. This ensures consistent tag handling while eliminating redundant object database lookups.

Notable technical details:
- The packed backend now checks `update->flags & REF_HAVE_PEELED` rather than calling `peel_object()`
- The reftable backend similarly uses the pre-peeled value from `u->peeled` when available
- The reftable change also removes an unnecessary `#include "../object.h"` that's no longer needed
- Both backends maintain the same behavior but with simpler, more efficient implementations

This patch represents the culmination of the series' goal to move object validation and peeling logic out of the individual backends and into the shared refs layer. With all feedback addressed in previous iterations and comprehensive test coverage added, this version appears ready for merging as part of the ongoing backend consolidation effort.
