This is a platform compatibility patch series addressing Windows-specific issues with handling large objects (>4GB) during cloning operations. Johannes Schindelin (Git for Windows maintainer) presents version 2 of his series that fixes truncation problems caused by 32-bit `unsigned long` types on Windows systems.

The series now includes 11 patches (up from 6 in v1) with significant test infrastructure improvements. The core technical changes remain focused on converting size handling to 64-bit `size_t` in critical paths:
- zlib wrapper updates to handle >4GB streams
- Object size fixes for pack streaming and delta headers
- Corrections for index-pack/unpack-objects and pack-objects reuse

New in v2 are optimizations to the test infrastructure that dramatically speed up the large packfile generation:
- Using "unsafe" SHA-1 hashing for test blobs
- Precomputing "Lego block" pack components for known sizes
- Marking the >4GB tests as EXPENSIVE
- Proposing CI integration to run these tests on integration branches (excluding `seen`)

The test optimizations reduce runtime from impractical durations to ~160 seconds while still requiring 4-8GB disk space. Schindelin notes OpenSSL licensing prevents more efficient implementations, and the fundamental clone operation remains unavoidably slow for such large objects.

This appears to be a well-considered update addressing previous feedback about test feasibility while maintaining the core Windows fixes. The EXPENSIVE test classification and selective CI integration represent a pragmatic compromise between thorough validation and resource constraints. Given Schindelin's Windows expertise and the clear platform limitation being addressed, this series continues to look like an important improvement for Windows users working with large repositories.
