This is a bugfix discussion for git-gui's handling of bare repositories and worktree detection. Mark Levedahl responds to Johannes Sixt's proposal for a backward-compatible solution, arguing that it doesn't fully address the underlying issues.

Mark identifies a deeper problem with how git-gui handles GIT_WORK_TREE and GIT_DIR environment variables, noting inconsistent behavior between using these versus the `-C` flag. He demonstrates that the current implementation only works correctly when starting from a valid worktree directory, while other cases produce unexpected results. The core issue appears to be that environment variable handling happens too late in the process.

The email suggests two potential solutions: either properly handle the environment variables by checking them first (and changing directory context early), or simply abort when these variables are set to avoid undefined behavior. Mark leans toward the latter as potentially more robust, as he questions whether there are valid use cases for setting these variables when launching git-gui.

This moves the discussion beyond just the bare repository case to consider broader architectural questions about git-gui's startup sequence. The thread remains focused on finding a solution that maintains backward compatibility while properly handling edge cases, with Mark now raising additional concerns about environment variable handling that weren't addressed in previous iterations.
