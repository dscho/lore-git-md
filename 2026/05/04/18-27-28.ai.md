Feature: Implementation of `fetch --prune-merged` to automate local branch cleanup.

This patch adds the `--prune-merged` option to `git fetch`, completing the integration of Harald Nordgren's decomposed branch pruning design. When enabled, `fetch` will automatically run `git branch --prune-merged` after a successful fetch operation, deleting local branches that track pruned remote branches while preserving unpushed work.

The implementation builds on the plumbing commands introduced in earlier patches of this series:
- Uses the new `git branch --prune-merged` command (from patch 3/6)
- Preserves the safety mechanisms (reachability checks, checked-out branch protection)
- Adds comprehensive tests verifying both successful pruning and proper skipping of branches with unpushed work

Key characteristics:
- Only activates when fetching from a configured remote (not direct URL)
- Returns error if pruning fails but fetch succeeded
- Maintains all safety checks from the underlying branch command
- Includes clear warning messages when branches are skipped due to unpushed work

The tests demonstrate the expected behavior:
1. Successfully prunes local branches when their upstream tracking ref is deleted
2. Preserves branches with unpushed commits (with appropriate warning)
3. Verifies the integration with existing `--prune` functionality

This represents the user-facing culmination of the architectural approach suggested by Junio Hamano - keeping the core logic in `git branch` while providing convenient automation via `fetch`. The implementation appears clean and well-tested, with clear documentation of the new option in fetch-options.adoc.
