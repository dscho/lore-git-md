This is a bug report about Git's resource usage exceeding configured limits. The reporter describes Git consuming all available CPU threads (28/32) and excessive disk space during operations like `git add` and `git commit`, despite having configuration settings that should limit these resources (`gc.auto=0`, `pack.threads=1`).

Key observations:
- The issue occurs during what should be routine operations (add/commit)
- Git appears to ignore the pack.threads=1 setting, spawning many pack-objects processes
- The gc.auto=0 setting doesn't prevent packing operations
- System resources (CPU, RAM, storage) are heavily impacted

The report includes detailed system info (Git 2.51.0, Linux 6.17, glibc 2.42) and configuration settings that show the expected behavior (limited threading, disabled auto-gc). The mismatch between configuration and actual behavior suggests either a configuration parsing bug or pack-objects not properly respecting these settings.

This appears to be a legitimate resource management issue that could affect server environments where predictable resource usage is critical. The report provides clear reproduction steps and configuration details that would help diagnose the problem.
