Refactoring patch in the refs backend consolidation series, moving reflog configuration handling to the generic layer. This is patch 3/9 in v4 of Karthik Nayak's series to standardize object validation and peeling logic across Git's reference backends.

The change extracts the `core.logallrefupdates` configuration check from individual backends (files and reftable) into the shared refs layer, passing it down through the new `ref_store_init_options` structure introduced in patch 2/9. This continues the architectural goal of having backends focus on storage while the generic layer handles policy decisions.

The patch:
1. Adds `log_all_ref_updates` to `ref_store_init_options` in refs-internal.h
2. Sets this value during ref store initialization in refs.c
3. Updates both files-backend.c and reftable-backend.c to use the passed value rather than querying config themselves

This is a mechanical change that maintains all existing behavior while reducing backend-specific knowledge of configuration details. The series as a whole has been through multiple rounds of review, with v4 specifically addressing error handling concerns raised in earlier versions. With this change, reflog creation policy becomes a concern of the generic refs layer rather than individual backends, furthering the goal of backend consolidation.
