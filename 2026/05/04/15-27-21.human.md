This is a bug report about Git's resource usage exceeding configured limits. The reporter describes Git consuming all available CPU threads (28/32) and excessive disk space during operations like `git add` and `git commit`, despite having configuration settings that should limit packing threads (`pack.threads = 1`) and disable automatic garbage collection (`gc.auto = 0`).

The key issue appears to be that Git is ignoring the configured thread limit and performing packing operations aggressively. The reporter provides system info showing Git 2.51.0 running on Linux with 32 CPU cores, and includes their relevant Git config showing the attempted resource constraints.

This looks like a legitimate configuration enforcement bug where Git's pack-objects operation is disregarding the thread count setting. The report is well-structured with clear reproduction steps, expected vs actual behavior, and system details - all hallmarks of a serious bug report worth investigating. The impact is significant as it can starve other processes on the system when Git operations run.
