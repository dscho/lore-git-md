This is part 8/11 of Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB) during cloning. The patch introduces a significant optimization to the test infrastructure for generating precomputed packfiles for 4GB+1 byte objects, dramatically speeding up test execution.

The key improvement is a "fast path" that writes packfiles from precomputed constants rather than computing SHA-1 hashes and adler32 checksums on the fly. For a 4GB+1 byte blob (the test case that exposed Windows' 32-bit truncation issues), this reduces pack generation time from 1-2 minutes down to about 15 seconds by making the process purely I/O-bound. The precomputed packs are deterministic since they contain all-NUL bytes, allowing the same pack to be generated without expensive hashing.

The implementation stores constant pack components (header, periodic deflate blocks, and hash-specific suffixes) in static arrays. The patch includes the SHA-1 variant and is structured to easily add SHA-256 support later. Benchmarks show the fast path is 3-5x faster than the generic path, which is particularly valuable for CI where these tests previously took 200-850 seconds.

This builds on earlier patches in the series that added the test infrastructure and addresses concerns raised in review about test execution time. The optimization is cleanly implemented with a clear fallback to the generic path for unsupported cases. The precomputed constants were generated from actual packfiles to ensure correctness.

As part of a larger effort to fix Windows-specific large object handling, this patch makes the regression tests more practical to run while maintaining their effectiveness at catching size truncation issues. The series as a whole appears well-considered, with each patch building toward the goal of robust 64-bit object handling on Windows.
