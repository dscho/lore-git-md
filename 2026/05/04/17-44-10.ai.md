This is patch 6/9 in Karthik Nayak's v4 series refactoring Git's reference backend validation logic. The patch focuses on improving error handling in `git update-ref` when using batch mode (`--batch-updates`).

The key change introduces a new `handle_ref_transaction_error()` helper that centralizes error reporting logic. This allows `update-ref` to properly distinguish between fatal errors (which should abort the command) and non-fatal rejections (which should be reported but allow other updates to proceed when using `--batch-updates`). The patch modifies all command parsing functions to use this new helper.

The changes are mechanical but important for maintaining consistent behavior as more validation moves into the ref transaction layer. The patch builds on previous work in the series that introduced the `ref_transaction_error` enum (patch 4/9) and relocates `print_rejected_refs()` (patch 5/9). 

With this change, errors will be detected and reported earlier in the update process (during `ref_transaction_update()` rather than at commit time), though the actual behavior remains the same. The patch includes comprehensive updates to all command handlers in `builtin/update-ref.c` to ensure consistent error handling across all operations.

This is part of the larger effort to standardize object validation and peeling logic across Git's reference backends (files, packed, reftable). The series has already addressed all prior review feedback and appears ready for final approval.
