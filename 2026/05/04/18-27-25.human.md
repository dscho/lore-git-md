Feature: New `git branch --forked` plumbing command for branch management.

This is the first patch in Harald Nordgren's v2 series implementing automatic local branch pruning functionality. The series follows Junio Hamano's architectural feedback to decompose the feature into standalone plumbing commands that `git fetch` can compose, rather than implementing the logic directly in fetch.

The new `--forked` option lists local branches that track any of the specified remote refs. It accepts either remote names (like "origin") or specific remote-tracking refs (like "origin/master"), with multiple arguments being unioned. This provides the building block for the subsequent `--prune-merged` functionality that will delete these branches when their upstreams are gone.

The implementation is clean and well-tested, with thorough documentation and test coverage in t3200-branch.sh. The command handles edge cases like invalid remote names and ensures the output is properly sorted. This appears to be a solid foundation for the rest of the series, which will build on it to implement the actual pruning behavior.

Key technical details:
- New `git branch --forked <remote>...` command
- Accepts both remote names and specific tracking refs
- Outputs sorted list of matching local branches
- Includes comprehensive tests for various usage patterns
- Part of a larger effort to improve branch management automation

The patch follows Git's coding style and includes all the expected components (documentation, implementation, tests). The design appears well-considered and ready for review.
