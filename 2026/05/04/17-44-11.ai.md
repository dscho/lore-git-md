This is patch 7/9 in a refactoring series that moves object validation logic from individual ref backends to the generic refs layer, part of the ongoing backend consolidation effort led by Karthik Nayak and Patrick Steinhardt.

The patch centralizes object validation (checking that referenced objects exist and are of the correct type) in the generic `ref_transaction_update()` function rather than having each backend implement it separately. Key changes include:

1. Moving the `parse_object()` check from files and reftable backends to the shared refs.c layer
2. Removing the now-unused `REF_TRANSACTION_ERROR_INVALID_NEW_VALUE` error type
3. Updating `receive-pack.c` to handle the new error reporting structure
4. Adding new test cases to verify error handling for invalid object updates

The validation now happens when updates are queued rather than during transaction preparation, which the commit message argues is more logical since validation doesn't depend on the transaction state. This does change behavior slightly by making invalid-object errors unavoidable even in batched updates, but callers can still choose how to handle them.

The patch continues the series' goal of making backends focus purely on storage while moving shared logic to the generic layer. It builds on previous patches that standardized initialization, reflog configuration, and error reporting. With comprehensive test coverage and all prior feedback addressed, this appears to be a well-considered mechanical change that improves code organization without introducing new risks.
