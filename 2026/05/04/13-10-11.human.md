This is a review acknowledgment for a bugfix in `git grep`'s column number reporting. Phillip Wood confirms René Scharfe's fix for the `--only-matching --column` behavior, which was incorrectly calculating positions relative to previous match ends rather than line starts.

The fix makes Git's output match GNU grep's behavior for multiple matches on the same line, showing absolute column numbers (e.g., columns 1, 11, 21 for digits in "1234567890" rather than the previous 1, 2, 12). Phillip notes the solution looks correct, with the key change being:
1. Storing the line start position (`start = bol`)
2. Calculating column numbers relative to that (`cno = bol - start + match.rm_so + 1`)
3. Removing the incorrect relative adjustment (`cno += match.rm_eo`)

The thread shows clear consensus that this was an unintentional bug in the original implementation, with multiple reviewers agreeing the fix properly aligns Git's behavior with user expectations and GNU grep's output. The change is low-risk as it only affects column number calculation without modifying core matching logic.
