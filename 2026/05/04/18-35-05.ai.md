This is a review comment on the final patch in Johannes Schindelen's series addressing Windows platform limitations with large objects (>4GB). Derrick Stolee acknowledges the CI gating approach for expensive tests (which require 4+ GiB disk space and take 200-850 seconds) but raises an important operational question about how CI failures will be noticed.

The review is substantive, focusing on the practical impact of the change rather than surface-level concerns. Stolee notes that while running expensive tests on integration branches is good in principle, it only helps if someone actually monitors the results. He specifically asks Junio (the maintainer) whether he pays attention to CI breaks when pushing to master, suggesting that automated issue creation for CI failures might improve visibility.

This touches on a broader project workflow question - the series has carefully balanced thorough testing with CI resource constraints, but the effectiveness depends on human processes that aren't formally defined. The comment doesn't require any code changes to the current patch but highlights an important consideration for the project's CI strategy going forward.
