This is a bug report about `git clone` failing when using `--dissociate` with a reference repository. The issue manifests when trying to check out a specific commit after cloning, with the error "unable to parse commit" despite the clone itself succeeding.

The reporter provides a reproducible test case using a local mirror repository, showing the failure occurs consistently when `--dissociate` is used, but works fine without it. The problem appears intermittently in their CI environment, having last occurred in January for a different repository with identical symptoms.

Key technical details:
- The failure occurs during checkout after successful clone
- Affects both Git 2.47.3 and 2.53.0
- Reproducible with both `--depth` and without
- Reference repository is maintained via `git clone --mirror` with periodic `git remote update`
- Error suggests the reference repository's objects become inaccessible too early in the clone process when `--dissociate` is active

The reporter suspects `--dissociate` may be severing ties to the reference repository before the checkout phase completes, though this is not the expected behavior. This appears to be a genuine bug in Git's handling of the `--dissociate` option during the clone-and-checkout sequence.
