This thread, which began as a bug report about repository corruption from concurrent `git maintenance run --detach` operations, has now reached an architectural consensus around how to fix it. The key decision: Jeff King (Peff) has firmly endorsed Taylor Blau's comprehensive approach -- transferring *all* tempfile ownership from parent to child during daemonization -- over Patrick Steinhardt's narrower proposal of handling only lockfiles. Peff argued the fix belongs in `daemonize()` itself, not as a per-caller responsibility, and has now supplied a concrete refinement for the implementation: have the parent reassign ownership to "0" (no owner) before `fork()`, reclaiming ownership only if `fork()` fails. This eliminates the risk of double-delete while making the worst case -- a stale temporary file left behind if the child dies before claiming ownership -- no worse than what is already possible with `kill -9`.

Jacob Keller has offered lightweight concurrence with Peff's refinement, noting it is simpler than pipe-based signal coordination and that the worst case is already an existing risk. The remaining open question is Derrick Stolee's position on the fix-forward direction; his earlier technical objections have been addressed by Peff's architectural arguments, but he has not announced a decision. Junio Hamano has also not yet weighed in on the overall direction or on the v2.54.1 release strategy. Keller's latest reply did not advance the technical debate -- the thread is now awaiting decisions from Stolee and Junio.
