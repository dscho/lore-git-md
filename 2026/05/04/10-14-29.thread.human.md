This thread addresses a test fix for spurious failures in `t7703-repack-geometric.sh` on ZFS and similar copy-on-write filesystems. The issue stemmed from comparing full `ls -l` output—including the 'total N' block count line—when verifying MIDX (multi-pack-index) retention behavior during geometric repacks. The fix, which modifies two test cases, strips this variable header using `sed 1d` before comparisons while preserving the core test logic that validates MIDX isn't unnecessarily rewritten when already up-to-date. The change is small and targeted, resolving a filesystem-specific instability without altering the underlying geometric repack or MIDX behavior being tested.
