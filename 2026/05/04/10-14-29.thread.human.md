This thread addresses test instability in t7703-repack-geometric.sh, which verifies that `git repack --geometric` with `--write-midx` doesn't unnecessarily rewrite MIDX files. The original tests compared full `ls -l` output, but this failed on ZFS and similar filesystems where the 'total N' line varies. Joerg Thalheim proposed stripping this line with `sed 1d` as a fix.

Now Patrick Steinhardt suggests a more robust approach: using `test-tool chmtime --get` to directly compare file modification times rather than parsing `ls -l` output. This would precisely test what matters (whether files were rewritten) while avoiding filesystem-specific parsing quirks entirely. The change would affect the same two test cases covering both bitmap and non-bitmap MIDX scenarios, maintaining the same verification of geometric repack behavior while making the tests more portable. The proposal represents a refinement of the earlier solution by testing the underlying property of interest directly rather than working around output format differences.
