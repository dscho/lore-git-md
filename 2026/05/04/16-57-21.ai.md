This is a question about Git's clean/smudge filter infrastructure, specifically how it handles binary files that match filter patterns in .gitattributes.

Randall Becker asks about the behavior when a directory contains both text files (which should be processed by clean/smudge filters) and binary files (marked as binary in .gitattributes) that also match the filter pattern. He's concerned about:
1. Whether binary files get processed by filters despite their binary designation
2. The portability of passing binary data through stdin/stdout in filters
3. Wants a reliable way for filters to detect and skip binary files

The underlying motivation is preventing errors when contributors forget to update .gitattributes or misname files in a directory that undergoes frequent changes. Randall is looking for robust handling that makes the system more resistant to such mistakes.

As a NonStop platform maintainer, he raises valid concerns about binary data handling portability. The question doesn't propose a solution but seeks clarification on current behavior to inform potential approaches. This touches on edge cases in Git's filtering pipeline that may not be well-documented.
