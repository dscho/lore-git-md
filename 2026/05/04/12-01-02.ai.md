This is a technical follow-up in Derrick Stolee's series optimizing `git pack-objects` with path-walk and sparse filters, now merged into 'seen'. The email clarifies two points from Junio's review of the first patch.

Derrick confirms Junio's suggested correction in the commit message ("once" -> "one") and provides deeper technical context about why bitmaps must remain disabled despite adding `--objects`. The key insight is that the path-walk API internally disables tree/blob walking in the revision machinery (`revs->blob_objects = revs->tree_objects = 0`), using it only for commit walking while handling trees/blobs separately. The `--objects` flag is added solely to satisfy filter option parsing requirements, not because the full object walk is needed.

The email references Taylor Blau's prior work on bitmap handling (linked via lore.kernel.org) suggesting bitmap support might become possible in the future, but the current implementation still requires disabling them. This maintains the series' focus on optimizing sparse-checkout scenarios while ensuring filter compatibility.
