This is a test infrastructure optimization patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The patch focuses on speeding up test execution by using an accelerated but cryptographically unsafe SHA-1 implementation for test data generation.

The key change replaces the standard collision-detecting SHA-1 implementation with `unsafe_hash_algo()` when generating large test packs, providing a 3-5x speedup in test runtime. This addresses performance concerns raised by Jeff King about the test suite's runtime being dominated by these large-object tests (160+ seconds vs 90 seconds for the rest of the suite).

The optimization is safe for testing since the synthesized data is deterministic and doesn't require cryptographic security. The patch maintains backward compatibility by falling back to the standard implementation when no accelerated backend is available (like on default Windows builds). Benchmarks show the unsafe version completing in 20 seconds versus 75-80 seconds for the safe version when generating a 4GB+1 test pack.

This change helps make the large-object testing more practical while maintaining test coverage for the core Windows fixes in the series. The patch demonstrates responsiveness to prior review feedback about test performance concerns.
