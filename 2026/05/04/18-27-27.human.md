Feature: Implementation of `git branch --prune-merged` for automatic local branch cleanup.

This is the third patch in Harald Nordgren's v2 series to automate local branch cleanup when upstream branches are deleted. Following Junio Hamano's architectural feedback, the series decomposes the functionality into standalone `git branch` plumbing commands rather than implementing it directly in `git fetch`.

The new `--prune-merged` option deletes local branches that were previously pushed to a remote but whose remote-tracking refs no longer exist (indicating they were pruned upstream). By default, it only deletes branches whose tips are reachable from their upstream (protecting unpushed work), with `--force` overriding this safety check. The currently checked-out branch is always preserved.

Key aspects of this implementation:
- Reuses the `--forked` logic from patch 1/6 to identify candidate branches
- Adds careful handling of push refs (respecting `push.default` configuration)
- Includes thorough test coverage of edge cases (unpushed work, checked-out branches, push vs upstream ref differences)
- Produces clear warning messages when skipping unmerged branches

The patch appears well-structured with clean separation between the core logic and UI/error handling. The tests demonstrate thoughtful consideration of real-world usage scenarios while maintaining safety. This builds on the series' foundation to provide the key deletion primitive that `fetch --prune-merged` will compose in later patches.
