This is part 3 of a 9-patch series refactoring Git's reference backend code, specifically moving reflog configuration handling from individual backends to the generic refs layer. The patch standardizes how backends determine when to create reflog entries by having the generic layer pass down the `core.logallrefupdates` setting rather than each backend checking it separately.

The change is mechanical but meaningful - it removes duplicate configuration lookups and ensures consistent behavior across all backends (files, packed, and reftable). The patch adds the new `log_all_ref_updates` field to `struct ref_store_init_options` and updates the initialization code to populate it from repository settings before passing to backends.

This continues the broader effort to consolidate backend logic, following naturally from the previous patches in the series that standardized initialization options. The change is well-contained, touching only the refs subsystem with straightforward updates to each backend's initialization code. With the series already receiving positive reviews in prior iterations, this patch appears ready for inclusion as part of the larger refactoring.
