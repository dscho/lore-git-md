Feature: Implementation of `git branch --prune-merged` for automatic local branch cleanup.

This patch (3/6 in the v2 series) implements the core `--prune-merged` functionality for `git branch`, building on the `--forked` plumbing from patch 1/6. The command deletes local branches that were tracking now-deleted remote branches, with careful handling of unpushed work and checked-out branches.

Key behaviors:
- Only prunes branches whose push destination ref no longer exists (using `branch_get_push` semantics)
- By default, refuses to delete branches with unpushed commits (reachability check)
- `--force` overrides the reachability check (unpushed work only recoverable via reflog)
- Always preserves currently checked-out branches across all worktrees
- Provides clear warnings about skipped branches with unpushed work
- The implementation reuses the `collect_forked_set` helper from patch 1/6 to identify candidate branches
- Uses `delete_branches()` for the actual deletion with appropriate flags
- Includes comprehensive tests covering:
  - Basic pruning of merged branches
  - Protection of unpushed work
  - `--force` behavior
  - Checked-out branch preservation
  - Push ref vs upstream ref handling

The patch appears well-structured with thorough documentation and test coverage. It cleanly implements the decomposed design approach requested by Junio Hamano, where `fetch --prune-merged` will later compose these primitives. The safety mechanisms (reachability checks, checked-out branch protection) address the key concerns around data loss while still providing automation for the common case of cleaning up merged topic branches.
