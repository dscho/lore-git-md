This is a platform compatibility patch (part 3/11 in the series) from Johannes Schindelin that continues the effort to enable Git on Windows to handle objects larger than 4GB. The patch focuses on the object database (ODB) and packfile streaming interfaces, converting size fields from `unsigned long` (32-bit on Windows) to `size_t` (64-bit).

The key changes:
1. Updates the `odb_read_stream` struct to use `size_t` for object sizes
2. Introduces `unpack_object_header_sz()` variant that returns sizes via `size_t*`
3. Adds temporary variables and comments to handle API compatibility where `object_info.sizep` remains `unsigned long*`
4. Modifies packfile-related functions to use 64-bit sizes throughout the delta handling and object streaming paths

The patch maintains backward compatibility while addressing the core issue - Windows' 32-bit `unsigned long` causing truncation of large object sizes. The changes are systematic, touching multiple subsystems (pack-objects, object-file, odb streaming) with clear comments explaining the type conversion requirements.

This builds on the previous patches in the series (zlib wrapper updates) and sets up for subsequent test infrastructure changes. The patch appears well-structured with thorough coverage of the affected code paths, though as noted in the commit message, some paths still truncate for loose objects >4GB (which are rare in practice).

The authorship situation is notable - originally written by "LordKiRon" who preferred anonymity, with Schindelin taking over as the public author. This continues the pattern seen in earlier patches of the series where Windows-specific limitations are being methodically addressed.
