This is the second patch in a 9-part series refactoring Git's reference backend system, part of the ongoing effort to standardize object validation and peeling logic across all ref backends (files, packed, reftable).

The patch introduces a new `ref_store_init_options` structure to centralize initialization parameters for ref backends, starting with the existing access flags. This prepares for future extensions (like reflog configuration) to be added to this structure rather than passed as separate parameters. The change is mechanical but touches all three backend implementations to adopt the new initialization pattern.

The series has already gone through three iterations with substantive review, and this version addresses all feedback. The changes are straightforward - replacing direct flag passing with a structure that will make future additions cleaner. The patch maintains the existing functionality while improving the code organization.

This is a foundational change in a well-reviewed series that's part of a larger backend consolidation effort led by Karthik Nayak and Patrick Steinhardt. The work is clearly motivated by practical needs encountered while working on other ref-related code.
