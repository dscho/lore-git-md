This is the final patch in Johannes Schindelin's 11-part series addressing Windows platform limitations with large objects (>4GB). The patch focuses on CI infrastructure changes to handle the new EXPENSIVE tests introduced earlier in the series.

The change modifies `ci/lib.sh` to enable expensive tests (via GIT_TEST_LONG) only for push builds to integration branches (next, master, main, maint), not for every PR iteration. This implements Derrick Stolee's suggestion to run these resource-intensive tests at a regular cadence rather than on every CI run, as the tests require 4+ GiB of disk space and take 200-850 seconds to complete.

The patch follows the series' pattern of balancing thorough testing with practical constraints - here by gating the expensive tests behind branch conditions rather than removing them entirely. It maintains the Windows-specific fixes from earlier patches while addressing CI resource concerns raised during review. The change is straightforward and well-motivated, completing the series' test infrastructure improvements while keeping CI runtimes reasonable for routine PR validation.
