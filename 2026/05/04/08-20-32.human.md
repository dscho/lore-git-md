This is a bug report about `git clone` failing when using `--dissociate` with a reference repository. The issue occurs intermittently in CI environments when cloning from local mirror repositories, resulting in the error "fatal: unable to parse commit" during checkout, despite the clone itself succeeding.

Rasmus Villemoes provides a reproducible test case showing the failure occurs when combining `--dissociate` with either `--depth` or `--branch` options. The problem appears related to when the dissociation from the reference repository happens during the clone process - it seems to cut ties with the reference repo too early, before the checkout is complete.

The report includes detailed reproduction steps using a 200MB test repository (shared via external link) and notes this has been seen across multiple Git versions (2.47.3 and 2.53.0) and with different repositories. The workaround is to omit `--dissociate`, which allows the clone to complete successfully.

This appears to be a genuine edge case in Git's reference repository handling that could affect users who maintain local mirrors for faster cloning. The reporter is unsure whether this indicates incorrect usage of `--dissociate` or an issue with how their mirror repositories are maintained (they use standard `git clone --mirror` with periodic updates).
