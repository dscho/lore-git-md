This is the final design discussion in Pablo Sabater's series improving `git log --graph` visualization for commits with excluded parents. The thread has narrowed to two competing approaches for root commit separation:

1. **Indentation approach** (current v3 implementation) Indents child commits after root commits, maintaining column consistency for roots but requiring complex collapse lines. Example:
```
* A root
  * B child
 /
* B root
```

2. **Blank line approach** (Phillip Wood's proposal) Uses vertical spacing before root commits for cleaner visual separation but may be less noticeable without `--oneline` and requires lookahead logic for diagonal connection lines. Example:
```
* A child
* B child

* C root
* D child
```

Pablo demonstrates both approaches with concrete examples, noting that the blank-line method particularly improves merge commit readability by avoiding "commit showers." However, as Chandra Pratap points out, implementing the blank-line approach would require significant changes to the graphing logic to handle the lookahead needed for diagonal connection lines.

The technical tradeoffs are now fully laid out:
- Blank lines offer superior visual distinction but complicate the code
- Indentation is more conservative but produces less obvious separation
- Both satisfy the core requirement of distinguishing root commits

With all implementation considerations surfaced and no outstanding technical questions, this thread is now ready for Junio Hamano to make the final design decision between these two approaches. The choice is purely about output formatting preferences, as both solutions are technically sound.
