This is a review comment on the final patch in Harald Nordgren's `git branch --prune-merged` series, which adds a new `--all-remotes` flag. Phillip Wood raises a substantive interface design issue about whether the flag should accept additional remote arguments when it already covers all configured remotes.

The series implements safe local branch cleanup by introducing commands to list (`--forked`) and delete (`--prune-merged`) branches that track remote branches. The `--all-remotes` flag is a convenience feature that applies these operations to all configured remotes rather than requiring explicit remote names.

Phillip's question focuses on the interaction between `--all-remotes` and explicit remote arguments - he wonders why the command accepts additional remote names when `--all-remotes` already covers everything. This suggests the interface might be more intuitive if it were strictly either/or rather than allowing both together.

The patch itself is otherwise complete and well-tested, with Junio C Hamano having approved the safety model in earlier versions. This review raises a last-minute design consideration about the command's ergonomics rather than any technical deficiency. The series appears ready for merging once this interface question is resolved.
