This is a feature patch proposing to enhance `git commit --fixup` functionality. The author wants to allow using `-m` and `-F` options with `--fixup=amend:` and `--fixup=reword:` flags, which currently only work with an interactive editor.

The patch addresses a limitation where users currently must use `$EDITOR` when rewording commits with these fixup options. The change would enable non-interactive workflows, such as batch-applying rewritten messages from files. The author cites potential benefits for AI-assisted workflows that can't use interactive editors.

The patch follows up on a 2021 discussion where Junio Hamano questioned why `-m` was treated specially compared to other message options. The current implementation checks `-m` separately from other message flags due to how early the fixup type is determined. The patch maintains the existing behavior for `-c/-C` options but could be extended to support them in a future version.

The change touches documentation, the commit command implementation, and adds new test cases. The author notes this is their first patch and has intentionally kept the scope narrow. The implementation appears well-motivated and addresses a real workflow limitation while maintaining backward compatibility.
