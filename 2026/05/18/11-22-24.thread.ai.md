Git thread summary:

This thread introduces Erik Cervin Edin's patch to enhance `git commit --fixup` by allowing non-interactive message specification via `-m` and `-F` options when using `--fixup=amend:` or `--fixup=reword:`. The change addresses a 2021 inconsistency noted by Junio Hamano regarding `-m` handling and enables automation workflows like batch-applying rewritten messages from files or AI-generated content.

The implementation modifies `builtin/commit.c` to:
- Support `-m` for direct message specification with amend/reword fixups
- Add `-F` support for reading messages from files
- Maintain backward compatibility (editor still required when no message provided)
- Includes comprehensive new test cases in `t/t7501-commit.sh`

Junio Hamano's substantive review identified several areas needing improvement:
- Author identity consistency between From: and Signed-off-by:
- Terminology should describe current behavior as "awkward" rather than "unusable"
- Implementation could reuse existing `-F` handling code paths
- Test style should standardize on "expected" rather than "expect"
- Potential debugging impact from lost message source information

Phillip Wood's follow-up review adds:
- Confirms "awkward" is better terminology than "unusable"
- Argues `-m` with plain `--fixup` has legitimate use cases for annotation
- Recommends refactoring to reuse `prepare_to_commit()` rather than duplicating `-F` logic
- Suggests using `test_commit_message` helper for cleaner tests
- Notes test file predominantly uses "expect" convention
