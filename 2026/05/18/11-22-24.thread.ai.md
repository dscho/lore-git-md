Git thread summary:

This thread introduces Erik Cervin-Edin's patch to enhance `git commit --fixup` by allowing non-interactive message specification via `-m` and `-F` options when using `--fixup=amend:` or `--fixup=reword:`. The change addresses a 2021 inconsistency noted by Junio Hamano regarding `-m` handling and enables automation workflows like batch-applying rewritten messages from files or AI-generated content.

The implementation:
- Supports `-m` for direct message specification with amend/reword fixups
- Adds `-F` support for reading messages from files
- Maintains backward compatibility (editor still required when no message provided)
- Modifies `builtin/commit.c` for proper message flag handling
- Includes comprehensive new test cases in `t/t7501-commit.sh`

Junio Hamano's substantive review identified several areas for improvement:
- Author identity consistency between From: and Signed-off-by: needs fixing
- Terminology should describe current behavior as "awkward" rather than "unusable"
- Implementation could reuse existing `-F` handling code paths
- Test style should standardize on "expected" rather than "expect"
- Potential debugging impact from lost message source information
- Suggests reconsidering whether plain `--fixup` with `-m` should remain a no-op

Open questions:
- Whether to extend functionality to plain `--fixup` cases
- Potential future support for `-c/-C` options
- Implementation refinements around code reuse and debugging information

The patch remains well-scoped with thorough test coverage. Junio's review indicates the approach is fundamentally sound but requires minor adjustments before proceeding. The author will need to address the identity consistency issue and consider the implementation feedback in a revised version.
