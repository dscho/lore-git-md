This is a documentation patch review from Junio C Hamano, commenting on Jean-Noël Avila's conversion of the git-bisect man page to the new synopsis style. Junio notes that while most of the changes follow the expected pattern for standardizing documentation format, the introduction of [synopsis] tags in example usage blocks is unexpected and potentially confusing.

Junio makes a technical observation that the [synopsis] attribute was intended specifically for command syntax definitions in the SYNOPSIS section, not for general usage examples elsewhere in the documentation. He points out that including shell prompts ($) in these blocks is particularly problematic since prompts aren't part of the actual command syntax.

The feedback suggests that while the overall documentation standardization effort is progressing well (Junio calls it "quite exciting"), this particular application of the [synopsis] tag may need reconsideration for non-synopsis examples. As the maintainer, Junio's comment carries weight, though he doesn't explicitly request changes - this appears to be constructive feedback rather than a blocking concern.
