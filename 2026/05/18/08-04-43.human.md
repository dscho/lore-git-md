This is a feature patch, the tenth iteration of Harald Nordgren's `--track=fetch` series for `git checkout` and `git switch`. The patch extends the `--track` option to automatically fetch from the remote when creating a tracking branch, eliminating the need for a separate `git fetch` step.

**What's new in v10.** This version rebases on master to resolve a merge conflict, with no functional changes from v9. The core functionality remains: when `--track=fetch` is specified, Git will fetch the remote branch before creating the local tracking branch. The implementation handles edge cases like hierarchical remote names (e.g., `nested/remote/branch`) and maintains the existing tracking branch configuration options (`direct` and `inherit` modes).

**Current status.** The patch has addressed all technical feedback from previous rounds, including Junio C Hamano's concerns about remote name parsing. The test coverage is comprehensive (16 test cases) and the documentation is updated. While Junio's earlier philosophical objection to the feature remains unaddressed, his silence on v9 suggests possible acceptance. The code appears ready for integration from a technical standpoint.

**Key details.** The feature allows combining fetch with other modes (e.g., `--track=fetch,inherit`) and handles various edge cases: failing gracefully when the remote is unavailable, respecting configured refspecs, and not disturbing unrelated remote-tracking branches. The implementation is careful to only fetch the specific branch being tracked when possible.
