This is Junio C Hamano's review of Jörg Thalheim's v2 patch adding configurable timeout behavior for config file locking. The review focuses on the implementation details of the timeout configuration mechanism rather than the core concept, which was already thoroughly discussed in previous rounds.

Junio points out that the current implementation's caching behavior makes the timeout effectively a per-process setting despite taking a repository parameter, since the first call to `config_lock_timeout_ms()` permanently sets the value. He suggests two alternative approaches: either make it explicitly process-wide by using `the_repository` and removing the misleading parameter, or make it truly per-repository by removing the caching and doing a config lookup each time.

The review leans toward the first option (process-wide timeout) as the simpler and more practical choice, noting there's likely no real need for per-repository timeout values. This is a substantive technical observation about the patch's internal design rather than a surface-level nit, though it doesn't challenge the overall approach.

The tone is constructive and the feedback appears aimed at helping refine the implementation details before potential inclusion. This continues the thread's pattern of the maintainer engaging with technical tradeoffs after the core concept was previously rejected but later reconsidered in v2.
