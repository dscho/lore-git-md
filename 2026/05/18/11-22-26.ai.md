This is a feature patch that enhances `git commit --fixup` to support non-interactive message specification via `-m` and `-F` options when using `--fixup=amend:` or `--fixup=reword:`. The patch builds on previous discussion from 2021 where Junio Hamano noted the inconsistency in how `-m` was handled compared to other message options.

The key changes allow:
- Using `-m` to directly specify the replacement message for amend/reword fixups
- Using `-F` to read the replacement message from a file for amend/reword fixups
- Maintaining backward compatibility by still requiring an editor when no message is provided
- Keeping the existing restriction that plain `--fixup` (without amend/reword) cannot use `-F`

The implementation:
- Updates documentation to clarify the new behavior
- Modifies `builtin/commit.c` to handle message flags with fixup types
- Adds comprehensive test coverage in `t/t7501-commit.sh`
- Preserves the existing behavior for `-c/-C` options (still incompatible)

The patch appears well-scoped and addresses a genuine workflow limitation, particularly for non-interactive use cases like AI-assisted workflows.
