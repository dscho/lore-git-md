This is the final patch in a feature series adding remote group support to `git push`, mirroring the existing `git fetch` functionality. The implementation allows pushing to all remotes in a configured group (via `remotes.<name>`) with commands like `git push all-remotes`.

The patch adds the core implementation with several key characteristics:
- Each remote is pushed independently via child processes for failure isolation
- Refreshes per-remote refspec lists to handle `remote.<name>.push` configs
- Isolates mirror flags per-remote (a mirror remote won't affect others in the group)
- Explicitly rejects `--atomic` for group pushes
- Accumulates exit codes via bitwise OR to continue after failures

The patch includes comprehensive documentation updates explaining the group push semantics and thorough test coverage in t5566-push-group.sh verifying:
- Basic group push functionality
- Error handling and continuation after failures
- Config interactions
- Mirror flag isolation
- Rejection of atomic pushes
- Various edge cases

This appears to be the final iteration of a well-reviewed series that has progressed through multiple rounds of feedback. The implementation follows Junio Hamano's guidance on process isolation and type safety, with all architectural decisions settled. The only changes from v5 were minor documentation formatting fixes.
