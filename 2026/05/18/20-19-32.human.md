This is patch 6/8 in Derrick Stolee's series introducing new negotiation controls for fetch/push. The series is now in its final form after thorough review, with all technical concerns addressed.

The patch adds a new `--negotiation-include` option to `git fetch` that ensures specified ref tips are always sent as "have" lines during negotiation, regardless of what the negotiation algorithm selects. This complements the existing `--negotiation-restrict` option (formerly `--negotiation-tip`) by allowing certain critical refs (like release branches) to always be considered while still allowing opportunistic inclusion of other refs.

Key aspects of this implementation:
- Accepts exact ref names or glob patterns (matching `--negotiation-restrict` behavior)
- Silently ignores non-existent refs
- Properly handles duplicates when the same ref would be included by both the negotiator and this option
- Includes comprehensive tests covering glob patterns, duplicate handling, and protocol version compatibility
- Adds the option to `git pull` passthrough

The patch builds on the `have_sent()` negotiator interface introduced in patch 5/8 to properly track which commits have been sent. This is a well-tested, production-ready addition that solves real-world problems with large monorepos where critical refs were being dropped from negotiation, causing massive unnecessary downloads.
