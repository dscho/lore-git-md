This is a review response from Git maintainer Junio C Hamano on a patch that adds configurable timeout behavior for config file locking. The patch had previously been rejected but was resubmitted with improvements.

Junio focuses on a specific implementation detail - whether the timeout value should be cached per-process or looked up fresh for each repository. He notes the current design misleadingly takes a repository parameter but caches the value globally, suggesting two alternative approaches: either make it clearly global by using `the_repository` and dropping the parameter, or make it truly per-repository by removing the caching.

His preference leans toward the simpler global approach, reasoning that per-repository timeout values likely don't provide meaningful benefit. This is a substantive review that gets into the semantics of the implementation while acknowledging the tradeoffs between correctness and simplicity.

The exchange shows the patch is being seriously reconsidered despite prior rejection, with Junio engaging constructively on the technical details. His feedback suggests the core concept may now be acceptable if this last design question is resolved appropriately.
