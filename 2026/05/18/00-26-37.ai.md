This is a documentation patch review from Junio C Hamano, commenting on Jean-Noël Avila's conversion of the git-bisect man page to the new synopsis style. Junio notes that while the core SYNOPSIS section conversion follows the expected pattern, the patch unexpectedly applies [synopsis] formatting to in-body command examples as well.

Junio raises two specific concerns about this extension of the [synopsis] attribute: First, that these in-body examples are usage demonstrations rather than formal syntax definitions, and second, that the '$' prompt in command-line examples is particularly confusing when marked as [synopsis] since prompts aren't part of the actual command syntax. He suggests the team had only envisioned [synopsis] being used for the dedicated SYNOPSIS section at the top of man pages.

The feedback indicates this may require clarification or adjustment in the documentation standardization effort's guidelines. While Junio calls the overall effort "exciting," his comments suggest the application of [synopsis] formatting needs to be more precisely scoped to avoid confusing cases like command-line prompts being treated as part of the syntax definition. This is a substantive review that touches on documentation conventions rather than just surface-level presentation.
