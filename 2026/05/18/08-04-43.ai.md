This is a feature patch, version 10 of Harald Nordgren's `--track=fetch` series for `git checkout` and `git switch`. The patch extends the `--track` option with a "fetch" mode that automatically fetches from the remote when creating a tracking branch.

**What's new in v10.** This version rebases on master to resolve a merge conflict, with no functional changes from v9. The core functionality remains: when `--track=fetch` is specified, Git will fetch the remote branch before creating the local tracking branch, ensuring the new branch starts from the latest remote state. The implementation handles hierarchical remote names (like `nested/remote`) correctly by walking backwards from the end of the start-point string to find the remote name.

**Current status.** The patch has addressed all technical feedback from previous rounds, including Junio C Hamano's v8 review comments about remote name parsing and control flow. The test coverage is comprehensive (16 test cases) and includes specific tests for hierarchical remote names and various fetch scenarios. While Junio's earlier philosophical objection to the feature's workflow implications remains unaddressed, his silence on v9 suggests he may have accepted the technical merits.

**Implementation details.** The key changes are in `builtin/checkout.c` with new functions `resolve_fetch_target()` and `fetch_remote_for_start_point()`. The documentation for both `git-checkout` and `git-switch` is updated to explain the new `fetch` mode and its comma-separated combination with existing `direct` and `inherit` modes. The patch maintains backward compatibility while adding the new functionality.

**Assessment.** This is a polished, well-tested feature that has been through ten iterations. The code quality is high and all known technical issues have been addressed. The feature's acceptance now depends on maintainer approval rather than any remaining technical concerns.
