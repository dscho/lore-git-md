This is patch 6/8 in Derrick Stolee's v5 series implementing new negotiation controls for fetch/push. The series introduces `--negotiation-include` to complement the existing `--negotiation-restrict` option, addressing inefficient object transfer in monorepos.

The patch adds the `--negotiation-include` option to `git fetch`, which ensures specified ref tips are always sent as 'have' lines during negotiation, regardless of what the algorithm selects. This is particularly useful when critical refs (like release branches) might otherwise be dropped from negotiation, triggering full-history transfers. The implementation:
- Takes ref names or glob patterns as arguments
- Silently ignores non-existent refs
- Outputs the requested objects as haves before the negotiator runs
- Uses the new have_sent() interface to track sent commits
- Adds passthrough support in `git pull`

The patch includes comprehensive tests verifying:
- Basic functionality with exact refs and glob patterns
- Additive behavior with normal negotiation
- Silent handling of missing refs
- Duplicate avoidance with both v0 and v2 protocols

This builds on the `have_sent()` interface introduced in patch 5/8 and completes the core negotiation control functionality before the final push integration in patch 8/8. The implementation is thorough, with Matthew Cheetham's Reviewed-by confirming technical soundness. The series is now in final form after multiple review iterations.
