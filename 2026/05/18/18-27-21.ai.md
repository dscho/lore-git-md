This is the final patch in a feature series adding remote group support to `git push`, mirroring the existing `git fetch` functionality. The implementation allows pushing to all remotes in a configured group (via `remotes.<name>`) with commands like `git push all-remotes`.

The patch introduces the core group push functionality, with each remote being pushed independently via child processes for failure isolation. Key technical aspects include:
- Rebuilding refspec lists per-remote to handle `remote.<name>.push` configs
- Isolating mirror flags per-remote
- Explicitly rejecting `--atomic` for group pushes
- Accumulating exit codes via bitwise OR to continue after failures

The v6 changes are purely documentation fixes (correcting backtick formatting in git-push.adoc) from Kristoffer Haugsbakk's review. The implementation appears production-ready with comprehensive test coverage in t5566-push-group.sh verifying:
- Basic group push functionality
- Error handling and continuation after failures
- Config interactions
- Mirror flag isolation
- Atomic push rejection
- Various edge cases

The series has progressed through six review rounds with all feedback addressed, including Junio Hamano's guidance on process isolation and type safety. The shared group resolution logic between fetch and push was refactored into remote.c in earlier patches. Parallel push support remains noted as a potential future enhancement.
