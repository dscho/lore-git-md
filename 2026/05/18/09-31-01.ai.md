This is patch 10/18 in Patrick Steinhardt's series to remove `the_repository` usage from the setup subsystem, continuing the `the_repository` removal effort. The patch converts `set_git_work_tree()` to take an explicit `struct repository *` parameter instead of implicitly using the global variable.

The key changes are:
- Moves the `worktree_initialized` flag from a static variable into `struct repository`
- Updates all callers (in clone.c, init-db.c, and setup.c) to pass `the_repository` explicitly
- Maintains the same safety check that prevents reinitializing with a different worktree path
- Follows the series' approach of removing static state rather than just relocating it

The patch is mechanically straightforward, touching 5 files with 17 lines added and 18 removed. It builds on the thread-safety improvements from earlier patches (particularly the removal of static buffers in patches 2-3) and continues the consistent pattern of this series. The changes are focused on the setup machinery, with no behavioral impact expected.

This represents another incremental step in the larger effort to eliminate global state from Git's core. The patch appears well-contained and follows the established approach of the series, making it likely to be accepted as-is.
