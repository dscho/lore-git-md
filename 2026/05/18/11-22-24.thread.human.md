This thread centers on Erik Cervin-Edin's proposal to enhance `git commit --fixup` by allowing non-interactive message specification via `-m` and `-F` options when using `--fixup=amend:` or `--fixup=reword:`. The change would address a long-standing inconsistency in message handling and enable automation workflows like batch-applying rewritten messages.

The current patch implementation adds support for `-m` and `-F` while maintaining backward compatibility (the editor still launches when no message is provided). Junio Hamano's initial review found the approach fundamentally sound but identified several areas needing refinement, including author identity consistency, terminology adjustments ("awkward" vs. "unusable"), and opportunities for code reuse in the `-F` handling logic.

Phillip Wood's follow-up review builds on Junio's feedback, adding that the `-m` option with plain `--fixup` could actually be useful for annotating fixup purposes, contrary to the patch's current "no-op" treatment. He also raises implementation concerns about duplicated code paths and lost debugging context, recommending refactoring through `prepare_to_commit()` and using the `test_commit_message` helper for cleaner tests.

The discussion remains focused on practical improvements rather than fundamental objections. Both reviewers agree the core functionality is valuable but suggest refinements around code organization, test hygiene, and edge case handling before the patch can proceed. The author will need to address these points in a revised version, particularly the implementation structure and test consistency issues highlighted by both Junio and Phillip.
