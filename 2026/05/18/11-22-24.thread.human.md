This thread introduces a useful enhancement to `git commit --fixup`, allowing non-interactive message specification via `-m` and `-F` options when using `--fixup=amend:` or `--fixup=reword:`. Currently these fixup types require interactive editor use, which limits automation potential. The change enables workflows like batch-applying rewritten messages from files or AI-generated content.

The patch builds on a 2021 discussion where Junio Hamano noted the inconsistency in how `-m` was handled compared to other message options. The implementation carefully preserves backward compatibility while adding the new functionality - it still requires an editor when no message is provided and maintains existing restrictions on plain `--fixup`. The changes are well-scoped, touching documentation, `builtin/commit.c`, and adding comprehensive test coverage in `t/t7501-commit.sh`.

As a first-time contributor, the author has focused the patch on the core `-m` and `-F` use cases while leaving room for potential future extension to `-c/-C` options. The implementation appears clean and addresses a genuine workflow limitation without disrupting existing use cases. The patch stands alone without dependencies on other series, making it a straightforward candidate for inclusion.
