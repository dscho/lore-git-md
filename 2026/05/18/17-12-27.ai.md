This is a review of patch 6/8 in Derrick Stolee's negotiation-control series, focusing on the `--negotiation-include` feature for `git fetch`. The review comes from Matthew Cheetham, who has been closely following this series.

The review is substantive, engaging with the technical implementation details. Cheetham notes the patch has improved from v3, particularly in its use of the new `have_sent()` negotiator callback introduced in patch 5/8. He highlights several positive aspects: the unified implementation for both restrict and include lists, thorough test coverage, and correct handling of edge cases like missing refs and duplicate avoidance.

One minor issue is identified: the warning message for unmatched refs incorrectly hardcodes `--negotiation-restrict` when it should use the actual option name being processed. Cheetham suggests passing the option name as a parameter to the helper function.

The review confirms the core functionality works as intended - `--negotiation-include` forces specific refs into the negotiation have stream while still allowing the negotiator to select additional haves. This addresses the monorepo use case where certain long-lived branches (like release branches) must always be advertised to avoid massive downloads.

Cheetham having already reviewed and approved patches 1-5/8, this leaves only patches 7-8/8 (config options and push integration) awaiting review to complete the series. The structural completeness of the implementation is noted, with the remaining work being straightforward plumbing.
