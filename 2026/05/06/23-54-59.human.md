Feature patch adding a word-diff view option to `git add -p`.

Javier Bassi proposes a new 'w' command for `git add -p` that shows the current hunk using word-diff formatting. This helps review inline changes in files with long lines (like JSON, CSV, or Markdown) where small edits might be hard to spot in the standard line-based diff. The implementation builds word-diff versions of the old/new content and uses Git's existing diff machinery to display them.

The patch looks well-constructed with:
- Clear documentation update
- Comprehensive implementation in add-patch.c
- New test cases verifying the word-diff behavior
- Careful handling of edge cases (empty hunks, colored output)

This appears to be a focused, self-contained improvement to the interactive add workflow. The change is backward compatible and doesn't affect how patches are actually staged - it's purely a viewing aid. The test coverage is thorough, including verification that the word-diff output matches expectations and that the command doesn't accidentally stage changes.
