This is the final polish phase of the `--max-count-oldest` feature, which adds an option to show the oldest N commits in a revision walk. Mirko Faina responds to Johannes Sixt's review of the sixth iteration, addressing documentation and implementation feedback.

The author agrees to:
1. Reword the man page description to more clearly contrast `--max-count-oldest` with `--max-count`
2. Use standard Git error message formatting for conflicting options
3. Investigate moving the counting logic into `get_revision_internal()` to better handle edge cases and maintain consistency with other revision walk features

Notably, the review identified that the current implementation doesn't properly handle the `--boundary` option, which will be fixed in the next version. The discussion also touched on whether negative values for `--max-count` could serve the same purpose, but this was rejected due to backward compatibility concerns with existing scripts.

The patch appears technically sound with thorough test coverage, now just needing these final refinements before maintainer approval. The core sliding window algorithm (which maintains O(K) space and O(N) time characteristics) remains unchanged from Jeff King's original design.
