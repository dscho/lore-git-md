This is a bugfix patch addressing a regression in `git fetch --deepen` behavior that was introduced in Git 2.54.0. The issue caused history truncation in shallow clones when using relative deepen operations on non-shallow repositories.

Samo Pogačnik's patch fixes the problem by modifying `shallow.c` to properly handle non-shallow repositories when a relative deepen is requested. The key change makes `get_shallow_commits()` return NULL when the current shallow depth is zero, effectively making `--deepen` a no-op in full clones as originally intended. This prevents the incorrect conversion of a full clone to a shallow one.

The patch includes a test case that verifies the fix by cloning a full repository, recording its state, performing a deepen fetch, and confirming the repository remains unchanged. This builds on previous discussion in the thread where René Scharfe had approved the technical approach.

The fix appears well-contained and addresses the regression cleanly, with the test providing clear verification. This should resolve the issue where repeated `fetch --deepen` commands were incorrectly reverting repositories to shallow state.
