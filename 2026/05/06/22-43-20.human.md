This is the first patch in Johannes Schindelin's RFC series to add merge commit support to `git history`. The patch implements core functionality for replaying 2-parent merges, building on Elijah Newren's earlier design notes.

The implementation handles merges by:
1. Performing an auto-remerge of the original parents (R)
2. Auto-merging the rewritten parents (N) 
3. Applying the user's manual changes (from the original merge O) onto N via a 3-way merge with R as base

Key technical details:
- Uses identical branch labels ("ours"/"theirs") for inner merges to ensure consistent conflict markers
- Handles non-clean inner merges by treating conflict-markered results as valid inputs
- Properly maps boundary commits when both parents need replaying
- Explicitly rejects octopus merges (>2 parents) and merge reverts

The patch includes:
- Core merge handling in `replay.c` (209 lines)
- Updates to `builtin/history.c` to relax merge restrictions
- Test updates showing successful merge replay scenarios
- New test cases for octopus/revert rejection

This appears to be a well-considered implementation that addresses the practical limitations of the original `git history` command while deferring more complex merge cases. The RFC status suggests the author is seeking feedback on the approach before finalizing.
