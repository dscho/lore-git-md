Bugfix targeting the rebase machinery's `--update-refs` feature. This patch addresses an edge case where using a custom `rebase.instructionFormat` with `%d` (which shows all ref decorations) could cause the rebase to generate invalid `update-ref` instructions for non-branch refs like HEAD.

The issue occurs because the decoration table gets populated with all refs when using `%d`, but `--update-refs` only meant to handle local branch updates. The patch filters decorations to only process `DECORATION_REF_LOCAL` types, preventing invalid instructions like `update-ref HEAD` from being generated. A new test case verifies the fix by explicitly checking that non-branch refs are ignored while legitimate branch updates still work.

The change is small and focused, with a clear commit message explaining both the problem and solution. The test case provides good coverage of the edge condition while maintaining the expected behavior for normal branch updates. This appears to be a straightforward correctness fix for a relatively new feature (--update-refs was introduced in Git 2.38).
