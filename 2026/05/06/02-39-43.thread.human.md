This thread addresses a bug in Git's `rebase --update-refs` feature where using `rebase.instructionFormat` with `%d` (show all ref decorations) could incorrectly generate update instructions for non-branch refs like HEAD. The original patch correctly filtered decorations to only process local branches, but the test case needed refinement.

Phillip Wood, a recognized expert on Git's rebase machinery, provided substantive review suggesting test improvements. The v2 patch incorporates his feedback by simplifying the test to remove redundant checks and verify the complete update-ref list rather than individual patterns. The fix remains focused - preventing invalid instructions while maintaining correct branch updates - and the improved test now provides cleaner verification that non-branch refs are properly ignored.

With these test refinements addressed, this appears to be a straightforward correctness fix for the relatively new `--update-refs` feature (introduced in Git 2.38). The patch is small, well-contained, and ready for inclusion. No outstanding technical concerns remain.
