This thread addresses a bug in the `rebase --update-refs` feature where non-branch refs like HEAD could incorrectly appear in the rebase todo list when `rebase.instructionFormat` includes `%d` decorations. The original author submitted a fix that ensures the decoration table only processes local branch refs (`DECORATION_REF_LOCAL` types) when generating update-ref instructions.

Phillip Wood, a recognized expert on rebase/sequencer code, reviewed the patch and suggested improvements to the test case - simplifying redundant checks and making the verification more robust by examining the complete update-ref list. The v2 patch incorporates these changes while maintaining the core fix. Phillip has now approved the changes ("this looks great"), indicating the patch is ready for inclusion.

The fix is well-contained and maintains the documented behavior of `--update-refs`, which is designed to only move branch refs under `refs/heads/` while leaving display-only decorations (like HEAD and tags) untouched. This addresses a real edge case in the relatively new `--update-refs` feature (introduced in Git 2.38) without introducing new complexity. With Phillip's approval and no outstanding concerns, this fix appears ready to be picked up for the next release.
