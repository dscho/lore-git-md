This thread addresses a bug in Git's `--update-refs` rebase feature where non-branch refs like HEAD could incorrectly appear in update-ref instructions when `rebase.instructionFormat` includes the `%d` decoration specifier. The fix, now in its third version, properly restricts decorations to `DECORATION_REF_LOCAL` types through existing branch filtering in the sequencer code.

Phillip Wood, the sequencer expert, has reviewed and approved the approach (adding his Reviewed-by) after confirming it correctly handles branch refs. During review, he identified a related issue in the parallel `make_script_with_merges()` code path that needs the same decoration restriction - though this will be handled separately. The current patch is ready for merging with its clean logic merging two conditionals into one and including regression tests.

The discussion shows how a focused bugfix uncovered a broader consistency need in the rebase machinery's ref handling. While the immediate issue is resolved, there's now awareness that similar filtering should be applied to another code path in a future patch.
