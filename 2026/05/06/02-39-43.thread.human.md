This thread addresses a bug in `rebase --update-refs` where using `%d` in the rebase instruction format would incorrectly generate update-ref instructions for non-branch refs like HEAD. The issue affects both interactive and non-interactive rebase modes.

The solution, now in v3 of the patch, correctly filters to only process branch refs (DECORATION_REF_LOCAL) while maintaining the validity of using `%d` in the format string. The patch has received Phillip Wood's Reviewed-by and Junio C Hamano's confirmation that this is the correct approach. Abhinav Gupta, who originally reported the issue, has confirmed the fix works for their use case in non-interactive mode.

While there remains a parallel issue in make_script_with_merges() that needs the same ref filtering, the core fix is complete and ready for integration. The thread has reached clear consensus that the update-refs feature should only process branch refs regardless of instruction format configuration, with no outstanding objections to the maintainer-approved solution.
