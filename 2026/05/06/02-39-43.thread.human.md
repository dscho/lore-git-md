This thread addresses a bug in Git's rebase machinery where using `--update-refs` with a custom `rebase.instructionFormat` containing `%d` (which shows all ref decorations) could generate invalid update instructions for non-branch refs like HEAD. The issue stems from the decoration table including all refs while `--update-refs` was only designed to handle local branch updates.

The proposed fix filters decorations to only process `DECORATION_REF_LOCAL` types, preventing invalid instructions such as `update-ref HEAD` from being generated. A new test case verifies that non-branch refs are properly ignored while legitimate branch updates continue to work as expected. The patch is small and focused, with a clear commit message explaining both the problem and solution. This appears to be a straightforward correctness fix for the relatively new `--update-refs` feature introduced in Git 2.38.
