This thread addresses a bug in `rebase --update-refs` where using `%d` in `rebase.instructionFormat` could incorrectly generate update instructions for non-branch refs like HEAD. The v3 patch fixes this by properly filtering to branch refs, with Phillip Wood providing a Reviewed-by and Junio confirming the approach is correct. 

A new email from Abhinav Gupta confirms the issue also affects non-interactive rebases, showing the same failure when attempting to update HEAD. This reinforces that the current solution - limiting updates to branch refs - is the right approach, as the problem would have surfaced in prior versions anyway when trying to update non-branch refs. The behavior is consistent across both interactive and non-interactive modes since they share the same underlying todo list mechanism.

With maintainer approval and additional validation of the fix's scope, this patch appears ready for inclusion. A related issue in `make_script_with_merges()` still needs the same ref filtering but can be handled separately. The thread demonstrates how careful review from domain experts like Phillip Wood helps ensure robust fixes even for edge cases that span different rebase modes.
