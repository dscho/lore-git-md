This thread addresses a bug in `git rebase --update-refs` where the rebase machinery could incorrectly generate update instructions for non-branch refs like HEAD when `rebase.instructionFormat` includes `%d` (ref decorations). The fix, now in its third version, properly filters to branch refs using `DECORATION_REF_LOCAL` types and has been reviewed by sequencer expert Phillip Wood, who confirmed the approach and identified a related issue in `make_script_with_merges()` that needs the same filtering.

Junio Hamano, the maintainer, has now weighed in to confirm that ignoring non-branch refs is the correct behavior, noting that even prior versions would have failed when attempting to update HEAD or tags. This hardening of the behavior aligns with the rebase feature's intended scope of updating branch refs. The core fix is ready for inclusion with Phillip's Reviewed-by, while the parallel issue in `make_script_with_merges()` remains to be addressed separately. The thread shows clear consensus on the current patch's approach, with both technical review and maintainer approval confirming it properly handles the edge case while maintaining the expected behavior for branch ref updates.
