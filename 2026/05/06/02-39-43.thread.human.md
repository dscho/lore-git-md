This is a short bugfix thread for `rebase --update-refs` when `rebase.instructionFormat` uses `%d` (ref decorations). The fix correctly filters to only branch refs, and is complete.

Phillip Wood spotted that when `rebase.instructionFormat` includes `%d`, the rebase machinery incorrectly generates `update-ref` instructions for non-branch refs like HEAD in both interactive and non-interactive rebase. He wrote a v3 patch that filters to `DECORATION_REF_LOCAL` types in `sequencer.c`'s `todo_list_add_update_ref_commands()`, and reviewed the fix. Junio C Hamano confirmed the approach is correct and defended the validity of using `%d`. Abhinav Gupta validated that the same issue occurs in non-interactive rebase, which Phillip Wood then explained is expected because non-interactive rebase shares the same code path.

Phillip also identified a parallel code path in `make_script_with_merges()` needing the same fix, and sent a follow-up snippet for that, but is leaving it to the author to submit as a separate patch. The core fix has Phillip's Reviewed-by, Junio's approval, and regression tests in `t/t3404-rebase-interactive.sh`. Nothing remains open on the main fix.
