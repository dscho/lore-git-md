This thread addresses a bug in `git rebase --update-refs` where using `rebase.instructionFormat` with `%d` (ref decorations) would generate incorrect update-ref instructions for non-branch refs like HEAD or tags. The fix, now at v3, filters decorations to only local branches via `load_branch_decorations()` in `sequencer.c`. 

Phillip Wood provided a Reviewed-by and confirmed the behavior is correct for both interactive and non-interactive rebase (which share this code path). Junio C Hamano also approved the approach, defending the validity of `%d` usage. The patch includes regression tests and was considered complete, though there was an open question about whether a parallel code path in `make_script_with_merges()` needed similar changes.

Phillip has now clarified that `make_script_with_merges()` doesn't require the same fix, as it loads decorations before commit formatting occurs. This means the current patch series fully addresses the issue without needing further modifications. With this final technical point resolved and the patch already reviewed, the fix appears ready for merging.
