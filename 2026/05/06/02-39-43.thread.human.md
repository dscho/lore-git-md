This thread addresses a subtle bug in Git's `--update-refs` rebase feature where using `rebase.instructionFormat` with `%d` (ref decorations) could incorrectly generate update instructions for non-branch refs like HEAD. The fix in v2 filters decorations to only process local branch refs (`DECORATION_REF_LOCAL`), which maintainer Junio Hamano initially thought might be too much by excluding local tags.

Phillip Wood, the sequencer expert, has since clarified that the current implementation is correct because the affected code path in `sequencer.c` already filters to branches via `load_branch_decorations()`. He also identified a related issue in `make_script_with_merges()` that needs the same treatment and provided a suggested fix. The v3 patch remains unchanged from v2 as it correctly handles its specific context, with Phillip's Reviewed-by confirming the approach.

The author now needs to decide whether to incorporate Phillip's additional fix for `make_script_with_merges()` into this patch or handle it separately. This is a focused correction for an edge case in the relatively new `--update-refs` feature (introduced in Git 2.38), with the core issue now resolved and only the question of handling the parallel code path remaining open.
