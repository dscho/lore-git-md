This is the final patch in Johannes Schindelin's RFC series adding merge commit support to `git history`. It introduces comprehensive test coverage for the new merge-replay functionality using a dedicated test helper (`test-tool historian`) that was added in the previous patch.

The test script exercises several key scenarios for merge commit handling:
- Clean merges where each side touches unrelated files
- Textual conflict resolutions that must be preserved during replay
- Semantic edits outside conflict regions that must also be preserved
- Rejection of octopus merges (explicitly deferred in this series)
- Complex cases involving function renames and new callers

The test infrastructure is notable for its declarative approach - each test scenario is described concisely using the historian helper rather than sprawling shell commands. This makes the test cases more readable and maintainable as the feature evolves.

The patch demonstrates thoughtful attention to edge cases, particularly around boundary conditions where merges have parents outside the rewrite range. The test for function renames explicitly documents the intentional limitation that symbol-level intent is not propagated (only textual diffs are preserved).

This appears to be a well-constructed test suite that provides solid coverage for the merge replay functionality introduced earlier in the series. The RFC status suggests the author is seeking feedback on whether the test strategy adequately covers the merge scenarios users might encounter in practice.
