Bug report about `git diff --word-diff` showing incorrect output for whitespace-only changes. Vincent Lefevre demonstrates that when comparing files where the only differences are leading/trailing spaces, `git diff --word-diff` incorrectly highlights entire lines as changed rather than showing just the whitespace differences. The report includes minimal test cases showing the behavior and notes it was originally discovered when viewing a commit in the Mutt repository.

The issue appears consistent across multiple Git versions (2.39.5 through 2.54.0) and shows different behavior from GNU wdiff, which correctly handles the whitespace-only case. The report is well-structured with clear reproduction steps and test cases, making it doesn't appear to have been previously reported. This looks like a legitimate bug in Git's word-diff implementation's whitespace handling.
