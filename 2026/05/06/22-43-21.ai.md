This is a performance optimization patch (part 2/5) in Johannes Schindelin's RFC series adding merge commit support to `git history`. The patch focuses on optimizing the common case where only commit messages are being rewritten (`git history reword`), leaving the trees unchanged.

The key optimization detects when both rewritten parents and their merge bases have identical trees to the originals, allowing it to skip the expensive merge operations entirely. In such cases, it can directly reuse the original merge tree while updating the parent pointers - a significant win for histories with many merges. The patch carefully maintains correctness by verifying both parent trees and all merge base trees match before taking the fast path.

Implementation details show thoughtful engineering:
- Merge bases are computed upfront and reused in both fast and slow paths
- Tree comparisons are done in order to catch subtle cases where different base trees could produce different merge results
- The optimization is transparently integrated into the existing merge replay logic

This appears to be a well-considered optimization that should provide measurable speedups for the targeted use case without compromising correctness.
