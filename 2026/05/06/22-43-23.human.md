This is a test infrastructure patch (part 4/5) in Johannes Schindelin's RFC series adding merge commit support to `git history`. It introduces a new `test-tool historian` subcommand that provides a declarative way to create complex merge test scenarios.

The tool reads a simple domain-specific language (DSL) that lets test authors specify blobs and commits with precise control over content, parent relationships, and merge topologies. Each object can be given a logical identifier that gets translated into fast-import marks and tags for easy reference in tests. The DSL supports:
- Creating blobs with exact content
- Building commits with explicit parent relationships (including merges`)
- Defining complete trees without inheriting from parents

The implementation is intentionally minimal - it trusts test authors to provide valid input and delegates most work to `git fast-import`. This keeps the helper focused on its core purpose: making it easier to write and maintain the complex merge scenarios needed to test the `git history` command's merge handling.

This patch is part of the larger effort to add robust merge support to `git history`, building on Elijah Newren's design. The test helper will be used extensively in the follow-up test file (t3454-history-merges.sh) to verify the merge replay functionality works correctly across various edge cases and conflict scenarios.
