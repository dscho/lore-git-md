RFC series adding merge commit support to `git history` (introduced in Git 2.54), building on Elijah Newren's design. Current implementation focuses on 2-parent merges while explicitly deferring octopus merges and merge reverts. Core approach uses three-way merge composition: R=auto-remerge of original parents, N=auto-remerge of rewritten parents, O=original merge tree, layering user's manual resolutions onto new auto-merge using R as base.

Key technical details:
- `replay.c` merge handling updated with consistent conflict marker labels between R and N
- `create_commit()` refactored to support multiple parents while maintaining boundary commit mapping
- Performance optimization detects when only commit messages change (`reword` case), skipping expensive merge operations by reusing original trees when parent and merge base trees match exactly
- Merge bases computed upfront for reuse in both fast and slow paths
- Explicit rejection of octopus merges and merge reverts in current scope
- New test infrastructure (`test-historian` helper) and extensive test coverage (300+ line `t3454-history-merges.sh`)
- Documentation updated to reflect supported merge scenarios (two-parent merges using R/O/N algorithm) and limitations (octopus merges, symbol-level intent propagation)

Substantive review from Phillip Wood identifies edge cases:
1. When merge commit O has parents B and D, and rewriting B onto E creates E', if E' and D conflict in ways not overlapping O's original conflicts, current implementation silently accepts new conflicts
2. Proposes alternative approach when only one parent is rebased: use original parent as merge base and rebased parent as merge head, avoiding R/O/N complexity for this case
3. Suggests either requiring both parents be rebased onto new base (E) or extending xdiff merge detection per Elijah's notes

Test infrastructure includes `test-tool historian` subcommand with DSL for creating complex merge test scenarios. Final test coverage (patch 5/5) exercises:

3. Semantic edit preservation outside conflict regions
4. Octopus merge rejection
5. Boundary commit handling

Implementation shows thoughtful incremental improvements to `git history` with both core merge composition logic and comprehensive test infrastructure.
