**Thread identity**: `[RFC PATCH 0/5]` series adding merge commit support to "git history", by Johannes Schindelin (Dscho), building on Elijah Newren's design.

**Core problem or goal**: Extend "git history" (introduced in Git 2.54) to handle merge commits, which were previously unsupported. The approach uses three-way merge composition: given a merge commit O with parents B and D, where rewriting B onto a base E produces E', the algorithm computes R = auto-remerge of original parents (B,D), N = auto-remerge of rewritten parents (E',D), then layers O's manual resolutions onto N using R as the merge base.

**Current status**: RFC -- not yet queued. The series has patches for the core merge logic in `replay.c`, conflict marker labeling, `create_commit()` multi-parent refactoring, a "reword" optimization (skipping remerge when only commit message changes), explicit octopus merge rejection, new `test-tool historian` helper with DSL, 300+ line test coverage in `t3454-history-merges.sh`, and documentation updates. DSL syntax questions are now resolved; Phillip Wood's merge algorithm edge case remains open.

**Key technical details**:
- Files touched: `replay.c`, `builtin/historian.c`, `t/helper/test-tool-historian.c` (new helper), `t/t3454-history-merges.sh` (new test file), `Documentation/` updates.
- Algorithm: R=remerge(B,D) -- original parents auto-merged. N=remerge(E',D) -- rewritten parents auto-merged. O=original merge tree. Final tree = three-way merge of O (ours) vs N (theirs) with R as base. This preserves O's manual conflict resolutions while applying the rebase's tree changes.
- New symbols/concepts: `test-tool historian` subcommand with revised DSL syntax using `parent=`, `branch=`, and `PATH:BLOB` format (adopting Toon Claes' suggestions).
- Optimization: reword case detection -- when parent trees match exactly, reuse original merge tree directly.
- Merge bases computed upfront for reuse in both fast and slow paths.
- Explicit rejection of octopus merges (3+ parents) and merge reverts in current scope.
- Error handling refined to clarify limitations when reporting unrewritten descendants (information not available at error detection point).
- Test coverage includes clean merges, conflict resolution preservation, semantic edits outside conflict regions, octopus rejection, boundary commits, function rename handling.

**Open questions and loose ends**:

(Unresolved) Phillip Wood identified that when one parent is rebased (E') and the other parent (D) is not, if E' and D have new conflicts not overlapping O's original conflicts, the current algorithm silently accepts the new conflicts instead of flagging them. The alternative: use original parent as merge base and rebased parent as merge head, avoiding R/O/N complexity for the single-parent-rebase case.
2. (Resolved) DSL syntax questions - now addressed by adopting Toon Claes' suggestions: `PATH:BLOB` format and flexible `parent=`/`branch=` keywords.
