This is a bug report about unexpected behavior in `git diff --word-diff`. The reporter demonstrates that when comparing files where the only differences are in whitespace (specifically leading spaces), the word-diff output incorrectly highlights entire lines as changed rather than just the whitespace differences.

The issue is reproducible across multiple Git versions (2.39.5 through 2.54.0) and platforms (Debian and Termux/Android). The reporter provides a minimal test case showing the problem and notes they originally encountered it when examining a commit in the Mutt email client's repository.

The expected behavior would be to show no differences (like GNU wdiff does) since only whitespace changed, but Git's word-diff incorrectly marks the non-whitespace content as changed too. This appears to be a long-standing issue in Git's word-diff implementation that affects real-world use cases like examining commit history.
