This is a documentation patch in Johannes Schindelin's RFC series adding merge commit support to `git history`. It updates the command's man page to reflect the new capabilities and limitations of merge handling.

The patch replaces the previous blanket statement about merge incompatibility with detailed documentation of what is now supported (two-parent merges using the R/O/N algorithm) and what remains out of scope (octopus merges, symbol-level intent propagation). It also clarifies when users should fall back to interactive rebase (when conflicts would occur during replay).

Key technical details documented:
- The three-way merge composition approach (R=original parents' auto-merge, O=original merge, N=rewritten parents' auto-merge)
- Explicit rejection of octopus merges
- Limitations around symbol-level refactoring
- Design rationale for not handling replay-time conflicts

The documentation maintains the command's philosophy of being non-interactive while setting clear expectations about edge cases. This appears to be a thorough update that matches the implementation in the earlier patches of the series.
