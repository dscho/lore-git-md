This thread proposes a word-diff view option for `git add -p`, letting users inspect hunks with word-level diffing (helpful for JSON, CSV, LaTeX, Markdown). Javier Bassi authored the original patch, with reviews from Pablo Sabater, Phillip Wood, D. Ben Knoble, and now Junio C Hamano.

The core debate has shifted from the patch itself to how to expose the feature. The original proposal adds a single-letter `w` command, but Junio warned against burning single-letter mnemonics for each future diff option. In the latest exchange, D. Ben Knoble fleshed out his earlier `:show <opts>` idea into two concrete designs: either let the existing `p/P` command accept options when not in single-key mode, or introduce a new `:` prefix that is explicitly exempt from single-key restrictions, allowing commands like `:print --word-diff`. Since `:` is not currently bound, exempting it from single-key mode would not break existing muscle memory.

The interface question remains open. Neither the maintainer nor the reviewers have settled on a direction, though all three proposals (single-letter `w`, option-bearing `p`, or `:command` syntax) are now on the table. No new patch version has been sent, and the original technical work on marker parsing and line-end handling has been addressed in review. The thread is currently waiting on a design decision.
