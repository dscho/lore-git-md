Junio C Hamano has narrowed the interface design discussion to a practical question: is introducing a general `:` command prefix infrastructure justified for the word-diff feature alone, or for the foreseeable set of future commands that might need it? He agrees the `:` prefix idea makes sense conceptually and that it provides a clean way to exempt commands from single-key mode, but he is not convinced the machinery earns its keep for this single use case. The burden of proof is now on the proponents to make that case.

The three proposals remain on the table (single-letter `w`, reusing `p`/`P` with options, or `:` prefix), but the thread is approaching a decision point. All technical review items from earlier substantive reviews (marker parsing, line ending handling) remain unresolved pending a new patch version.
