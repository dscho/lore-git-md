This is a documentation patch from Johannes Schindelin, part of an RFC series (3/5) adding merge commit support to `git history`. The patch updates the command's man page to replace the previous blanket warning about merge support with a detailed description of what merge scenarios are now handled and which remain out of scope.

The documentation now explains that two-parent merges are supported via the R/O/N algorithm (auto-remerge of original parents, original merge tree, and auto-remerge of rewritten parents), preserving user conflict resolutions. It explicitly calls out unsupported cases: octopus merges, symbol-level intent extrapolation when parent rewrites introduce new content, and merges that would require interactive conflict resolution during replay.

The patch maintains the command's design philosophy of avoiding stateful operations while providing clearer guidance on when to fall back to `git rebase --rebase-merges`. The changes reflect the implementation work in the series while setting appropriate expectations about edge cases. As an RFC patch, it invites feedback on whether the documented behavior matches reviewer expectations for merge handling in this relatively new command.
