This is a feature patch finalizing the `--max-count-oldest` option for revision walks, now in its sixth iteration. Johannes Sixt provides a review focusing on documentation clarity and implementation details.

The review suggests improving the man page wording to better contrast `--max-count-oldest` with `--max-count`, proposing "Unlike --max-count, limits the output to _<number>_ last commits" as clearer phrasing. He also raises the interesting question of whether negative values for `--max-count` could serve the same purpose.

On the implementation side, Sixt notes the error messages could follow Git's standard pattern for option conflicts, and questions whether the commit counting logic should be handled in `get_revision_internal()` rather than the current approach, to maintain consistency with other revision walker features like sorting and graph output.

The patch appears technically sound but may need minor adjustments to documentation and potentially the implementation location. This represents the final polishing stage before maintainer approval, with all major technical concerns from previous rounds already addressed.
