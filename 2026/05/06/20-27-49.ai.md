This is the first patch in the v6 series fixing git-gui's handling of bare repositories and missing worktrees. The patch restructures the repository startup sequence to properly handle edge cases while maintaining backward compatibility.

The key changes in this iteration:

1. Early bare repository detection - now checked right after config loading, with clear error messages when bare repos are used with unsupported subcommands.

2. Preserved historical behavior - maintains the ability to launch git-gui from a .git directory of non-bare repos (a feature since 2010) by checking `--is-inside-git-dir`.

3. Removed unsafe fallback paths - eliminates the problematic `_prefix`-based worktree guessing that could cause issues in multi-worktree setups.

4. Added robust error handling - wraps `--show-object-format` calls and provides descriptive errors for broken configurations.

The implementation carefully balances correctness with backward compatibility, addressing the 2019 regression in `--show-toplevel` behavior while maintaining the expected workflow for non-bare .git directories. The patch shows thorough consideration of edge cases and multi-worktree safety.

Technical details of note:
- New early bare repo check before Tcl initialization
- Special handling of non-bare .git directories via explicit check
- Removal of relative path fallback logic
- Added error wrapping for hash algorithm detection
- Clear error messages for all failure cases

The changes focus on git-gui.sh's startup sequence, particularly around worktree path resolution and repository state detection. This foundational patch enables the subsequent patches in the series to build on this more robust startup handling.
