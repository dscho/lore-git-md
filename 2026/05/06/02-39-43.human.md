This is a bugfix for `git rebase --update-refs` that addresses an edge case when using custom rebase instruction formats. The patch comes from Abhinav Gupta and targets the sequencer subsystem.

The issue occurs when `rebase.instructionFormat` includes `%d` (which shows all ref decorations), causing the rebase machinery to incorrectly try to generate `update-ref` instructions for non-branch decorations like HEAD. The current behavior results in an invalid rebase todo instruction that gets rejected.

The fix modifies the decoration scanning logic in `sequencer.c` to explicitly skip non-branch decorations (DECORATION_REF_LOCAL). This matches the documented purpose of `--update-refs`, which is specifically about updating branch references. The patch includes a new test case that verifies the corrected behavior when using a format string with `%d`.

The change is small and focused, with clear justification in the commit message and test coverage for the specific edge case. This appears to be a straightforward improvement that makes the feature more robust when used with custom formatting.
