The thread discusses unexpected behavior in `git diff --word-diff` when handling files where only whitespace changes. Vincent Lefevre initially reported that Git highlights entire lines in such cases, unlike GNU wdiff which only shows the changed whitespace. Johannes Sixt explained this is intentional - Git's word-diff inherits the same whitespace sensitivity rules as regular diffs, and users should use `-w` for whitespace-agnostic comparison.

Vincent has now followed up, arguing the documentation doesn't make this distinction clear. He demonstrates that piping Git's regular diff output to wdiff produces different (and in his view more accurate) results for whitespace changes. The core question remains whether Git should align with external tools' behavior by default, or if better documentation of the current design would suffice. While Johannes' technical explanation stands, the thread reveals a gap between Git's behavior and some users' expectations shaped by other diff tools. The discussion remains open regarding whether this warrants a behavior change or just clearer documentation.
