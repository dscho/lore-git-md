This thread reports a bug in `git diff --word-diff` where whitespace-only changes (leading/trailing spaces) incorrectly trigger highlighting of entire lines rather than just the affected whitespace. Vincent Lefevre provided clear test cases demonstrating the issue across multiple Git versions (2.39.5 through 2.54.0), showing that GNU wdiff handles the same cases correctly. The bug appears to have gone unnoticed until now, despite affecting a commonly used diff mode. The report is well-documented with minimal reproduction steps, making it easy for maintainers to investigate the word-diff implementation's whitespace handling logic.
