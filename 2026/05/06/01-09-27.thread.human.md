This thread clarifies the behavior of `git diff --word-diff` when handling whitespace changes. Vincent Lefevre initially reported what appeared to be a bug where the command highlighted entire lines when only leading/trailing whitespace differed, contrasting with GNU wdiff's behavior. 

Johannes Sixt explained this is actually intentional - the word-diff output inherits Git's standard whitespace sensitivity by default, matching the underlying line-diff behavior. The key takeaway is that users who want to ignore whitespace changes should use the `-w` flag with `--word-diff`, just as they would with a regular diff. This isn't a bug but rather the expected interaction between word-diff and Git's whitespace handling rules. The discussion effectively resolves the original concern by clarifying the design behavior and proper usage.
