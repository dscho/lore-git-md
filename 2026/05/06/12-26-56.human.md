This is a bug report about a minor output inconsistency in `git reflog expire`. The author, Sven Weiland, notes that when running the command with `--dry-run`, the output message "prune checkout: <something>" omits the expected "would " prefix that typically indicates a dry-run operation. 

The behavior is otherwise correct - the dry-run doesn't actually prune anything - but the output message doesn't follow the usual dry-run convention of using "would" to indicate hypothetical actions. This appears to be a simple logging oversight rather than a functional issue.

The report includes clear reproduction steps and expected/actual behavior, making it easy to verify. This seems like a straightforward fix that would improve consistency in the command's output. The bug affects Git 2.54.0 but likely exists in other versions as well.
