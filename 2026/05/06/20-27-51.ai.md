This is the final patch in a bugfix series for git-gui's handling of bare repositories and missing worktrees. The patch specifically addresses environment variable handling to make `GIT_DIR` and `GIT_WORK_TREE` behave consistently with `git -C` invocations.

The key changes introduce early environment resolution that:
1. Validates and processes `GIT_DIR`/`GIT_WORK_TREE` pairs before repository detection
2. Unsets `GIT_WORK_TREE` after validation to prevent inheritance issues
3. Preserves backward compatibility for `GIT_DIR`-only cases
4. Fixes `git gui blame` in bare repositories by not exporting empty worktree paths

The implementation adds a new `resolve_initial_environment` proc that handles the validation logic, with careful attention to error cases. The patch completes the series' goal of making git-gui robust across all repository states while maintaining historical behavior where needed.

Technical details include:
- Absolute path validation via `git rev-parse --absolute-git-dir`
- Worktree verification before changing directories
- Clean separation between environment-driven and automatic detection paths
- Removal of problematic worktree exports that broke bare repo operations

The patch has consensus from both Mark Levedahl (correctness) and Johannes Sixt (backward compatibility), suggesting it successfully reconciles the thread's competing requirements. With this change, the series appears ready for merging.
