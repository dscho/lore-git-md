Thread summary:

Bug report from Vincent Lefevre about incorrect whitespace handling in `git diff --word-diff`. When comparing files where only leading/trailing whitespace differs, the command incorrectly highlights entire lines as changed rather than showing just the whitespace differences. The issue is reproducible across Git versions 2.39.5 through 2.54.0 and differs from GNU wdiff's correct handling of such cases. The report includes minimal test cases demonstrating the behavior, originally discovered when viewing a commit in the Mutt repository. This appears to be a previously unreported bug in Git's word-diff implementation's whitespace handling logic. No responses or analysis from other contributors yet.
