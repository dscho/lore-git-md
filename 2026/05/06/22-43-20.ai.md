This is the first patch in Johannes Schindelin's RFC series to add merge commit support to `git history`. The patch implements core functionality for replaying 2-parent merges while explicitly deferring octopus merges and merge reverts.

The key technical approach builds on Elijah Newren's design notes, using a three-way merge composition:
1. R = auto-remerge of original parents
2. N = auto-remerge of rewritten parents 
3. O = original merge tree
The outer merge layers the user's manual resolutions (O) onto the new auto-merge (N) using R as base.

Notable implementation details:
- Consistent conflict marker labels between R and N ensure clean resolution application
- Unclean inner merges are handled (not fatal)
- Boundary commit mapping properly handles merge parents
- `create_commit()` refactored to support multiple parents
- Octopus merges and merge reverts explicitly rejected

The patch includes test updates showing successful merge replay scenarios and maintains existing protections against unsupported cases. Given the complexity of merge handling and the command's recent introduction, this appears to be a well-considered incremental improvement with thorough test coverage.

The RFC status suggests the author is seeking feedback on the approach before finalizing, particularly around the merge conflict handling strategy and boundary case behaviors. Reviewers will likely focus on the merge composition logic and whether the test coverage adequately exercises edge cases.
