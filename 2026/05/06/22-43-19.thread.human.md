This is a patch series adding merge commit support to `git history` (introduced in Git 2.54), building on Elijah Newren's design. The current implementation focuses on two-parent merges, using a three-way merge composition: auto-remerge original parents (R), auto-remerge rewritten parents (N), and the original merge tree (O), then layering original conflict resolutions onto the new merge. Octopus merges and merge reverts are explicitly deferred.

Substantive review by Phillip Wood identified a key edge case: when only one parent of a merge is rewritten and the new parent conflicts with the unchanged parent in ways that didn't exist in the original merge, the current implementation silently accepts the new conflicts. Phillip proposes using the original (unchanged) parent as merge base and the rebased parent as merge head as an alternative, avoiding the full R/O/N complexity for common single-parent-rebase scenarios. This remains the main open technical question.

A design discussion from Toon Claes raised clarity concerns with the `test-tool historian` DSL, which uses keyword arguments (`from=`, `merge=`) mixed with file-tree specifications in the same token stream. Toon proposed a `parent=` keyword syntax or a `--` separator to visually distinguish path arguments from structural keywords. This is a collegial, low-impact suggestion -- the reviewer acknowledges the tool's value and would accept Dscho's current design.

The series remains in RFC status. Key participants are Christian Couder (author), Phillip Wood (substantive review), Toon Claes (test infrastructure design), Johannes Schindelin, and D. Ben Knoble. No version updates have been posted since the RFC. Open questions include the conflict-detection edge case for single-parent rebases and the test helper DSL syntax.
