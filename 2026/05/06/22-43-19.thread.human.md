Johannes Schindelin (Dscho) is working on extending "git history" to properly handle merge commits, building on Elijah Newren's design. The current RFC series proposes a three-way merge composition approach to preserve manual conflict resolutions when rebasing merge commits. 

A key discussion point has been an edge case identified by Phillip Wood, where silently introducing new conflicts when only one parent is rebased could cause problems. In the latest exchange, Dscho acknowledges Wood's alternative approach - using the original parent as merge base when only one parent is rebased - as "a really good idea" that would particularly help with conflict marker clarity. This represents productive technical collaboration to refine the merge handling.

The series already includes substantial test coverage (300+ lines) and addresses other review feedback, such as adopting Toon Claes' suggested syntax for the test DSL. While the core merge algorithm is taking shape, the discussion around Wood's edge case shows there's still work to be done on conflict detection before this functionality would be ready for merging. No formal Reviewed-by tags have been given yet, indicating the technical details are still being worked through between the contributors.
