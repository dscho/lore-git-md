This RFC series proposes adding merge commit support to `git history`, focusing on two-parent merges while explicitly deferring octopus merges and merge reverts. The core approach uses a three-way merge composition strategy (R=auto-remerge of original parents, N=auto-remerge of rewritten parents, O=original merge tree) to layer manual resolutions onto new auto-merges.

The discussion has centered around edge cases in merge conflict resolution, particularly one identified by Phillip Wood where rewritten parents might introduce new conflicts not present in the original merge. Phillip has now proposed an alternative approach when only one merge parent is rebased - using the original parent as merge base and rebased parent as merge head, which could avoid silent conflict introduction in some cases. This builds on earlier substantive reviews from Johannes Schindelin and D. Ben Knoble about edge cases in `git history reword` operations and error messaging.

The implementation includes comprehensive test infrastructure (300+ line test file) and handles various scenarios like clean merges, conflict resolution preservation, and boundary cases, while explicitly rejecting octopus merges. Open questions remain about the adequacy of the conflict handling strategy, test coverage completeness, and whether to implement workarounds or document limitations for certain edge cases. The technical discussion continues to focus on faithfully preserving manual resolutions while addressing the complex scenarios that arise during history rewriting of merge commits.
