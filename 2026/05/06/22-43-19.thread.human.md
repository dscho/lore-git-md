Johannes Schindelin (Dscho) has been working on extending `git history` to handle merge commits, building on Elijah Newren's design. The RFC series uses a three-way merge composition approach to preserve manual conflict resolutions while applying rebase changes. The current version includes core merge logic, test infrastructure, and documentation updates.

In the latest exchange, Dscho has accepted Toon Claes' suggestions to improve the test DSL syntax, adopting clearer `PATH:BLOB` notation and a more flexible `parent=`/`branch=` design that better handles edge cases like root commits. This resolves the test infrastructure questions that were under discussion.

The main remaining issue is a substantive edge case identified by Phillip Wood: when only one parent of a merge is rebased, the current algorithm may silently accept new conflicts between the rebased and unchanged parents. This is the key technical question still needing resolution before the series can progress beyond RFC status. The thread remains collegial, with participants focused on refining both the implementation and testing approach.
