This is the final patch (5/5) in Johannes Schindelin's RFC series adding merge commit support to `git history`. It introduces comprehensive test coverage for the new merge-replay functionality using a dedicated test helper (`test-tool historian`) that was introduced in patch 4/5.

The test script (`t3454-history-merges.sh`) exercises several key scenarios for merge handling:

1. Clean merges where each side touches unrelated files
2. Textual conflict resolutions that must be preserved through replay
3. Semantic edits (changes outside conflict regions) that must also be preserved
4. Rejection of octopus merges (explicitly out of scope for this initial implementation)
5. Complex cases involving boundary commits and function renames

The test helper allows each scenario to be described declaratively in about a dozen lines, making the test file readable while covering edge cases. Notable test cases include:

- Verifying that manual conflict resolutions are preserved exactly
- Ensuring semantic edits outside conflict regions survive replay
- Confirming octopus merges are properly rejected
- Testing correct handling of merges where one parent sits outside the rewrite range
- Demonstrating the intentional limitation around symbol-level intent (function renames don't propagate to new callers introduced in rewritten parents)

The implementation shows careful attention to edge cases and includes clear documentation of known limitations. The test coverage appears thorough, with each scenario carefully constructed to verify specific aspects of the merge-replay behavior. This final patch completes the RFC series by providing the testing infrastructure needed to validate the merge support introduced in earlier patches.
