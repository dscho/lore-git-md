This is the second patch in a three-part bugfix series for git-gui, addressing visualization menu behavior in bare repositories. The patch follows foundational changes in v6 that improved repository state detection.

The core issue is that git-gui's "Visualize History" menu items remain enabled in bare repositories, leading to Tcl errors when clicked since they require a worktree. The fix:

1. Disables the visualization menu items when in a bare repository with the 'bare' option active
2. Adds a defensive check in do_gitk() to prevent errors if the menu state gets out of sync
3. Updates the branch tracking logic to maintain consistent menu state when branches change

The changes are straightforward and well-contained, touching only the UI state management while preserving existing functionality for non-bare repos. The patch includes helpful error messages and maintains the series' focus on graceful degradation when worktree-dependent features aren't available.

This continues the thread's careful balance between correctness and backward compatibility, with both Mark Levedahl and Johannes Sixt having provided input that shaped the solution. The implementation appears technically sound and completes one of the key user-facing aspects of the bare repository support improvements.
