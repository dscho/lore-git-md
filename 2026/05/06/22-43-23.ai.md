This is a test infrastructure patch (part 4/5) in Johannes Schindelin's RFC series adding merge commit support to `git history`. The patch introduces a new `test-tool historian` subcommand that provides a declarative way to create complex merge test scenarios for the `git history` command.

The new test helper` allows creating test repositories with precise control over blob contents, commit parentage, and merge topologies through a simple DSL (Domain Specific Language). This replaces fragile shell scripts and sequences of plumbing commands that would otherwise be needed to set up merge test cases. The DSL supports:

- Creating blobs with exact content (`blob NAME LINE...`)
- Creating commits with specified parents and file trees (`commit NAME BRANCH SUBJECT [from=PARENT] [merge=PARENT]... [PATH=BLOB]...`)
- Automatic mark allocation and lightweight tag creation for easy reference

The implementation is a C program that feeds the DSL commands to `git fast-import`, handling all the low-level details of mark management and tree construction. The helper is intentionally minimal - it trusts its caller (test scripts) to provide valid input and doesn't include extensive validation.

This test tool will be used in the follow-up patch (5/5) to create the merge test cases for `git history`. The implementation shows careful attention to testability needs, providing a clean way to express complex merge scenarios that would be cumbersome to create with raw Git commands. The DSL design balances expressiveness with simplicity, focusing specifically on the needs of testing merge commit replay.

The patch follows Git's standard patterns for adding new test helpers, including Makefile and meson build system integration. The implementation is clean and straightforward, leveraging existing Git infrastructure like `split_cmdline()` for argument handling and `strintmap` for name resolution.
