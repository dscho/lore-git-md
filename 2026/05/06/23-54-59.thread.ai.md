Subject: [PATCH v?] git add -p: word-diff visualization interface design

Thread identity: Feature proposal (initial RFC, no version number) for adding word-diff visualization to `git add -p` interactive patch review, authored by Javier Bassi.

Core problem or goal: Allow users reviewing files with long lines (JSON, CSV, LaTeX, Markdown) to toggle word-diff display so changed tokens are visible without leaving the interactive workflow. Must integrate with existing single-key interactive mode.

Current status: Interface design discussion at a decision point. Junio C Hamano responded to D. Ben Knoble's detailed `:` prefix proposal. Junio acknowledged the conceptual soundness of the `:` prefix for exempting commands from single-key mode, but then asked the pivotal question: is the machinery worth building for the word-diff use case alone? He identified word-diff as "a good candidate" but said it is "not immediately obvious" that a general `:` command infrastructure is justified. This shifts the burden of proof -- proponents must show that word-diff, or the foreseeable set of future commands, warrants the new mechanism.

Key technical details: Feature would touch `builtin/add.c`, `add-interactive.c`, `add-patch.c`. No config keys, new symbols, or on-disk format changes. The three interface proposals remain:
1. Single-letter `w` command (original proposal).
2. Reuse existing `p`/`P` with options (Junio's historical consideration, also Knoble's two implementation strategies).
3. `:command` syntax with exemption from single-key mode (Knoble's refined proposal).

Open questions and loose ends:
1. **Interface design**: junio's framing demands a justification that the `:` machinery's complexity pays for itself. If proponents cannot make that case, the thread must fall back to one of the simpler alternatives (single-letter `w` or reused `p`/`P` with options).
2. **Tension between single-key usability and extensibility** remains unresolved; Junio has not dictated a solution.
3. **All technical review items** from earlier substantive reviews (marker parsing, line ending handling) remain open pending a new patch version.
