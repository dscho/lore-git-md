Subject: [PATCH v?] git add -p: word-diff visualization interface design

Thread identity: Feature proposal for `git add -p` to add a word-diff view option for displaying hunks with word-level formatting, authored by Javier Bassi. Series has no version number -- only initial RFC/proposal.

Core problem or goal: Allow users of `git add -p` reviewing files with long lines (e.g., JSON, CSV, LaTeX, Markdown) to toggle word-diff visualization, making changed tokens visible without switching to a separate diff tool. Must integrate with existing interactive single-key workflow.

Current status: Interface design discussion ongoing. Maintainer Junio C Hamano has joined the thread. No new patch version has been submitted by the author. Technical details of the underlying word-diff implementation (marker parsing, line ending handling) have been addressed in earlier review but remain pending in code.

Key technical details: Feature lives in `builtin/add.c` and the interactive patch mode code path (`add-interactive.c`, `add-patch.c`). Toggles word-diff display for individual hunks in the interactive reviewer. No new symbols, config keys, or on-disk format changes; purely a presentation-mode toggle in interactive patch review.

Participant positions:
- Javier Bassi (author): proposed `w` as a single-letter command in interactive mode.
- D. Ben Knoble (reviewer): proposed `:show <opts>` syntax for future extensibility, citing exhaustion of single-letter namespace.
- Phillip Wood (reviewer): gave substantive technical review of marker parsing and line ending edge cases.
- Junio C Hamano (maintainer): engaged in interface design. Raised tension between single-key usability and extensibility. Noted he had previously considered reusing the existing `p` command with options. Expressed personal preference for verbose interfaces but recognized the need to accommodate single-key-mode users. Did not dictate a solution.
- D. Ben Knoble (follow-up): responded to Junio with two concrete implementation strategies for either `p/P` taking options in non-single-key mode, or a new `:` prefix exempted from single-key behavior (since it is a new keybinding with no existing muscle memory). This moves the earlier `:show <opts>` spitballing toward testable design options.

Open questions and loose ends:

   - Single-letter `w` command (original proposal).

   - `:command` syntax (`:print --word-diff`, `:show <opts>`) with explicit exemption from single-key mode (Knoble's refined proposal).
2. Tension between single-key-mode users and extensibility for future diff-viewing options remains unresolved (Junio's skepticism about single-key users is still open).
3. All technical review items from earlier substantive reviews (marker parsing, line ending handling) remain open pending a new patch version.

Related work: Part of the broader interactive-patch review workflow discussion. Also related to ongoing interface design conversations around `:` prefix syntax that recur across Git's interactive subsystems.
