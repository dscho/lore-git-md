This is a bugfix patch addressing a regression in `git fetch --deepen` behavior that was introduced in Git 2.54.0. The patch follows up on earlier discussion where the technical approach was reviewed and approved by René Scharfe.

The fix prevents `--deepen` from incorrectly converting a full clone into a shallow one when used on a non-shallow repository. The key change is in `shallow.c` where `get_shallow_commits()` now returns NULL (effectively making the operation a no-op) when the current repository isn't shallow, rather than treating the depth as absolute. This matches the expected behavior where `--deepen` should only affect already-shallow repositories.

The patch includes a test case that verifies the fix by cloning a full repository, recording its state, then ensuring that state remains unchanged after a `fetch --deepen` operation. The test checks both the shallow status and commit history to confirm no truncation occurs.

This appears to be the final version of the fix for this regression, incorporating the architectural improvements suggested in earlier review. With the sign-off and test coverage in place, it seems ready for potential inclusion in the next release cycle.
