This is a feature proposal to add support for replaying 2-parent merges in `git history`, Git's new history-rewriting command. The patch series comes from Johannes Schindelin (Git for Windows maintainer) and builds on prior design work by Elijah Newren (merge machinery expert).

The core problem is that `git history` currently fails when encountering merge commits, making it impractical for workflows that rely on feature branch merges. The proposed solution implements merge replay for the common 2-parent case using an algorithm Elijah previously prototyped, with additional tweaks to handle edge cases like conflict resolution. Octopus merges and merge reverts remain unsupported.

The series includes:
1. Core merge replay implementation
2. Optimization for unchanged parent/base trees
3. Documentation updates explaining the new capability
4. A new `test-historian` helper for building merge test cases
5. Extensive new test coverage

The implementation appears thorough, with careful attention to edge cases and 300+ lines of new tests. This would significantly expand `git history`'s usefulness for real-world workflows. The RFC status suggests the author is seeking feedback on the approach before finalizing.
