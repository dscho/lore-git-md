Feature proposal: automatic local branch pruning during fetch

Harald Nordgren proposes a new config option `fetch.pruneBranches` that, when combined with `--prune`, will automatically delete local branches whose upstream remote-tracking refs have been pruned. This aims to clean up topic branches after their upstream counterparts have been merged and removed.

The config offers three modes:
- `false` (default): no change to current behavior
- `safe`: delete local branches only if their tip is reachable from the upstream (preserving unpushed work)
- `force`: delete unconditionally (recoverable only via reflog)

The patch includes thorough documentation and test coverage, with special handling to never delete the currently checked-out branch. The implementation adds a new `--prune-branches` CLI option and corresponding remote-specific config (`remote.<name>.pruneBranches`).

This appears to be a well-considered addition to Git's branch management capabilities, addressing a common workflow pain point while providing safety mechanisms to prevent accidental data loss. The implementation is clean and follows existing patterns for similar features like `fetch.pruneTags`.
