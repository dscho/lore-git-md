Thread identity: Bug report about Git's rename detection behavior with Ruby files when moving classes between namespaces, reported by Sébastien Stettler.

Core problem: When Ruby classes are moved between namespaces (e.g. `Foo::Bar` to `Baz::Bar`), Git treats this as a file deletion+addition rather than a rename, while simple class renames (within same namespace) are correctly detected. The reporter questions whether this is intentional design or an area for potential improvement in Git's rename heuristics.

Current status: Open question about expected behavior, with test repository (https://github.com/billybonks/git-rename) demonstrating the issue. No responses or analysis from Git contributors yet.

Key technical details:
- Affects Ruby source files with namespace/class restructuring
- Demonstrates difference in detection between:
  - Simple class rename (detected as rename)
  - Class moved between namespaces (detected as delete+add)
- System context: Git 2.47.1 on macOS ARM64

Open questions:
- Is this behavior intentional?
- If intentional, what design considerations lead to this?
- If unintentional, would this be worth improving in rename detection heuristics?
