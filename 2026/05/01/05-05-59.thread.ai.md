Thread identity: Bug report about Git's rename detection behavior with Ruby files when moving classes between namespaces, reported by Sébastien Stettler.

Core problem: When Ruby classes are moved between namespaces (e.g. `Foo::Bar` to `Baz::Bar`), Git treats this as a file deletion+addition rather than a rename due to indentation changes affecting all lines, while simple class renames (within same namespace) are correctly detected. The discussion explores whether this is intentional design or an area for potential improvement.

Current status: Technical analysis complete from multiple contributors. A workaround exists (split into move-then-modify commits) but has limitations. No decision about core behavior changes yet.

- Demonstrates difference in detection between:
  - Simple class rename (detected as rename)
  - Class moved between namespaces (detected as delete+add due to indentation changes)
- Git's similarity-based rename detection: indentation changes reduce similarity below threshold
- Workaround limitation: split commits help `git log` but not cross-change comparisons
- System context: Git 2.47.1 on macOS ARM64
