This is the fourth iteration of a bugfix for git-gui's handling of bare repositories and missing worktrees. The patch addresses a long-standing issue where git-gui would crash with cryptic Tcl errors when launched from bare repos or directories with inaccessible worktrees.

The key change in v4 is a shift in approach from the previous versions. Instead of trying to recover valid worktrees when launched from .git subdirectories, the patch now explicitly blocks operation when started from inside any Git directory (including .git subdirs). This matches Git's own behavior where commands like `git status` refuse to run in such contexts.

The implementation uses `rev-parse --is-inside-git-dir` to detect Git directory launches, showing a clear error message in those cases while maintaining the existing behavior for bare repositories. The 12-line diff is focused and well-contained within git-gui.sh.

This version appears to be a direct response to Mark Levedahl's substantive review of v3, which pointed out the complexity and potential pitfalls of trying to handle .git subdirectory cases. The commit message makes a strong case for the new approach, noting that the old behavior was unreliable anyway and incompatible with multi-worktree setups.

The patch seems technically sound and addresses the core issue while simplifying the logic. It may be ready for merging unless there are objections to the stricter behavior regarding .git subdirectories.
