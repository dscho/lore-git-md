This thread explores Git's rename detection challenges with Ruby files when classes move between namespaces, where indentation changes cause Git to see deletions and additions rather than renames. The discussion has evolved from initial workarounds to deeper technical analysis of potential solutions.

Sébastien Stettler originally reported the issue, demonstrating how moving a Ruby class between namespaces (like `Foo::Bar` to `Baz::Bar`) breaks Git's rename tracking due to changed indentation. Early suggestions from Phillip Wood proposed splitting changes into separate commits (move first, then modify), but Junio Hamano clarified this only helps certain commands like `log -M` and fails for `diff` or `merge`. Jeff King identified technical feasibility for whitespace-ignoring rename detection while noting edge cases.

The latest contribution from Chris Torek builds on Junio's suggestion about whitespace handling, proposing specific normalization approach that would compress leading/trailing whitespace while preserving semantic meaning. He notes implementation challenges around line length heuristics and humorously points out this would fail for the Whitespace programming language. The discussion now centers on whether Git should implement whitespace-ignoring rename detection (perhaps as `-M -w`) or leverage the attributes system for language-specific handling, with consensus that Git's snapshot model allows for such improvements without breaking history.

Key participants include the original reporter (Stettler), technical reviewers (Wood, King, Torek), and maintainer perspective from Hamano. While no solution is finalized, the thread has progressed from problem identification to concrete technical exploration of implementation paths, with whitespace normalization emerging as a promising direction despite some edge cases to resolve.
