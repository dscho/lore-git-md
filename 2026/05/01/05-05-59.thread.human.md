The thread examines Git's rename detection behavior when Ruby classes are moved between namespaces (e.g., `Foo::Bar` to `Baz::Bar`), which currently gets treated as a file deletion and addition due to indentation changes affecting most lines. Sébastien Stettler originally reported the issue, demonstrating how this breaks history tracking across such changes.

Technical analysis from Phillip Wood and Johannes Sixt confirmed this is expected behavior given Git's snapshot-based model - rename detection happens after the fact by comparing file similarity, and indentation changes often push files below the similarity threshold. A suggested workaround of splitting the change into two commits (move first, then modify) was shown to have limited value: while it improves `git log` output, it fails for `git diff`, `git merge`, and non-adjacent commit comparisons.

Junio Hamano has now weighed in, emphasizing that the split-commit approach doesn't address the core limitation - Git fundamentally lacks context about semantic changes like namespace moves. His intervention clarifies that while the current behavior is working as designed, there may be room for improvement in handling language-specific cases where most lines change but the semantic content remains similar. The discussion remains open for proposals that could enhance rename detection without compromising Git's general-purpose design or performance characteristics.
