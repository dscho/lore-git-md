Here's a human-readable summary of the thread so far:

The thread discusses Git's rename detection behavior when moving Ruby classes between namespaces (e.g., changing `Foo::Bar` to `Baz::Bar`). Sébastien Stettler reported that while simple class renames are detected, namespace moves often show as file deletions/additions due to indentation changes affecting all lines. 

Phillip Wood explained this is expected behavior - Git's similarity-based rename detection sees the indentation changes as making the files too different. He suggested splitting changes into two commits (move first, then modify) as a workaround. Johannes Sixt (Hannes) followed up, agreeing with the technical analysis but noting the workaround only helps when comparing adjacent commits, not when looking at the before/after state across the entire change.

The discussion highlights a fundamental limitation in Git's current approach for this Ruby-specific case. While the workaround helps in some scenarios, there's no clear solution yet for cases where structural refactoring affects every line. The core question remains open: whether Git should be enhanced to better handle such language-specific refactorings, though any such change would need to carefully weigh the benefits against added complexity.
