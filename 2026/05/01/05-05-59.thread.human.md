The thread discusses Git's rename detection behavior when moving Ruby classes between namespaces. Sébastien Stettler reported that while simple class renames (within the same namespace) are correctly detected as renames, moving a class between namespaces (e.g., `Foo::Bar` to `Baz::Bar`) is treated as a deletion and addition. He provided a test repository demonstrating this difference in behavior.

Phillip Wood provided a technical explanation for this behavior: when moving between namespaces, the indentation changes on every line make the files appear too dissimilar for Git's rename detection heuristics. In contrast, simple renames within the same namespace preserve indentation, allowing the similarity threshold to be met. He suggested a practical workaround of splitting the change into two commits - first moving the file without changes, then modifying the namespace - to help Git recognize the rename.

The discussion has clarified why Git behaves this way but hasn't yet addressed whether this is the desired long-term behavior or if the rename detection could be improved to handle such cases automatically. The original reporter remains available to help with implementation if the community decides this is worth changing.
