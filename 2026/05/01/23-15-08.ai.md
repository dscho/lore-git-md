This is patch 6/8 in a feature series introducing a new `git url-parse` plumbing command. The command exposes Git's internal URL parsing logic to allow scripts to reliably extract components from Git's various URL formats (including non-standard ones like SCP-style URLs).

The patch implements the core `url-parse` command itself, which:
- Takes URLs as arguments and optionally a `-c` flag to specify which component to extract (scheme, user, password, host, port, or path)
- Uses the url_parse() function from earlier patches to validate and normalize URLs
- Provides clear error messages when invalid URLs or components are specified
- Returns the requested component (or nothing if no component is specified)
- Includes the necessary build system changes to add the new command

Key technical details:
- The command is classified as a "purehelper" in command-list.txt
- Uses the url_info struct from previous patches to store parsed URL components
- Implements strict validation that rejects local paths unless properly formatted as file:// URLs
- Handles memory management carefully with xstrndup/free for extracted components
- Follows Git's standard command-line parsing conventions

This builds on the preparatory work in patches 1-5 which refactored Git's URL parsing internals. The implementation looks clean and well-integrated with the existing codebase. The command fills a clear need for tools that need to parse Git URLs programmatically without reimplementing Git's parsing logic.

The series appears to be in good shape overall, with thorough test coverage added in earlier patches. This plumbing command could be particularly useful for scripts that need to work with Git repository URLs in a robust way.
