This is a continuation of the git-gui bugfix thread about handling bare repositories and missing worktrees. Mark Levedahl responds to Johannes Sixt's (Hannes) proposed middle-ground approach with a strong technical argument for stricter solution.

Mark identifies a particularly problematic edge case where git-gui could silently commit files into the gitdir itself if launched from a non-bare repository with core.bare=false but no accessible worktree. He demonstrates this by showing how the current code could commit the refs/heads/master *file* rather than its contents.

The email makes a clear technical case that git-gui's read/write mode should only run when `--is-inside-work-tree` is true, and should either abort or explicitly prompt the user when launched from a gitdir. Mark strongly advocates for failing fast ("abort and let me learn") rather than automatically switching directories, arguing that silent behavior changes would encourage user errors.

This positions Mark firmly on the "correctness over compatibility" side of the debate, in contrast to Hannes' more compatibility-focused proposal. The email doesn't directly reference Shroom Moo's v4 patch but aligns with its stricter approach. The thread now has three distinct technical perspectives that will need resolution from the maintainers.
