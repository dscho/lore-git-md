This is part 3 of a refactoring series preparing for the new `git url-parse` builtin command. The patch moves URL scheme detection logic (enum url_scheme and url_get_scheme()) from connect.c to new url.[ch] files, continuing the architectural separation of URL parsing from connection-specific code.

Key changes:
- Extracts enum url_scheme and url_get_scheme() from connect.c to url.h/url.c
- Keeps scheme_name() in connect.c as it's only used there
- Maintains identical behavior including error messages
- Follows RFC-compliant naming established in earlier patches (URL_SCHEME_*)

The move enables other code to identify URL schemes without depending on connect.c, which is important for the upcoming url-parse command. The patch is mechanical with no functional changes - it's purely moving code to better reflect the logical separation between URL parsing and connection handling.

This continues the clean separation started in earlier patches, with url.c becoming the canonical home for URL parsing logic while connect.c retains connection-specific functionality. The change is well-contained and maintains all existing behavior, including the die() message for unsupported schemes.
