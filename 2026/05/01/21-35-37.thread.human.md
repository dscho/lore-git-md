This thread presents the final version (v17) of Harald Nordgren's `git branch --delete-merged` series, which introduces safe automated local branch cleanup with comprehensive filtering and safety controls. The series is now fully implemented, including all previously discussed features: the core `--delete-merged` command, the `--forked` filter for branch selection, a refactored flags-based deletion API, per-branch opt-out via `branch.<name>.deleteMerged=false`, stacked-branch protection, and `--dry-run` preview capability.

The command safely deletes local branches merged into their upstream while preserving branches that are checked out, missing their upstream, pushing back to their upstream, opted out via configuration, or used as upstreams for other branches (stacked-branch protection). The `--dry-run` flag, added in this final patch, allows users to preview deletions without modifying refs, completing the safety architecture. All high-weight feedback—including Phillip Wood's concerns about stacked-branch safety and API consistency, and Junio C Hamano's initial skepticism about stacked-branch protection—has been addressed. Junio now fully endorses the preserve-and-notify default as the safer approach.

The series is mature and ready for final review, with comprehensive test coverage verifying all safety mechanisms, opt-out behavior, and `--dry-run` functionality. Key participants—Harald Nordgren (author), Phillip Wood (reviewer), and Junio C Hamano (maintainer)—have converged on the design, and no blocking issues remain. The implementation establishes a composable foundation for future branch management features while addressing iterative topic branch workflows.
