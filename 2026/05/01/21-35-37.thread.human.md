Harald Nordgren's v8 series adds `git branch --prune-merged` for safe automated local branch cleanup when upstream branches are deleted. The core idea is a safety model that checks whether a local branch's tip is reachable from its configured upstream remote-tracking branch -- a much more intuitive and defensible criterion than earlier approaches.

The series consists of five patches. Patch 1 (unchanged from v7) adds a `--forked <remote>` infrastructure option for listing local branches with a given upstream. Patch 2 (unchanged) introduces `warn_only` and `n_not_merged` parameters to `delete_branches()` so that bulk pruning can suppress per-branch error messages and instead report a summarized count -- a clean mechanical refactoring. Patch 3 (completely redesigned from v7 in direct response to Junio C Hamano's concerns) contains the core `prune_merged_branches()` logic: roughly 140 lines of new C code with three safeguards -- not checked out, resolvable upstream, and upstream isn't the remote's default branch with the same local name. Patch 4 adds a `branch.<name>.pruneMerged` config option (defaulting to true) for per-branch opt-out; notably `--force` does not override it, by deliberate design. Patch 5 adds a `--all-remotes` convenience flag that enumerates all configured remotes, building on patches 1-3's infrastructure.

Junio C Hamano raised fundamental concerns about the safety model on v7, and Harald responded with this complete v8 redesign the next day -- a strong signal of engagement with maintainer feedback. Junio has not yet responded to v8. No other substantive review has appeared this round; the only remaining question is whether the community finds the new upstream-reachability safety model acceptable. The separate `fetch.pruneLocalBranches` concept remains unrelated to this series.
