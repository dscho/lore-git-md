This thread concerns Harald Nordgren's v7 patch series adding `git branch --prune-merged`, a feature for safely cleaning up local branches whose upstream counterparts have been deleted on the remote. The series now has all five patches submitted.

Patches 1-4 have been reviewed with no objections. Patch 1 introduced `--forked` for listing branches whose push destination refs are gone, Patch 2 added the warning infrastructure for bulk deletion, Patch 3 implemented the core `--prune-merged` logic with an upstream-fallback system that handles branches pushed under different names, and Patch 4 added a `branch.<name>.pruneMerged` configuration option for per-branch opt-out. Patch 5, the final piece just submitted, adds `--all-remotes` so that both `--forked` and `--prune-merged` can operate across all configured remotes at once.

The design decisions appear settled. Junio's v6 concern about merged-ness checking was addressed, and no issues have been raised against any of the five v7 patches. Junio has not yet reviewed v7 as a whole, but with all reviews so far showing no objections, the series appears well-advanced. Johannes Sixt's earlier position, that branch modification should remain exclusive to `git branch`, has been upheld and has not required further engagement.
