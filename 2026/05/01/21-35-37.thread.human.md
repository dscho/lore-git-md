This thread proposes a new `fetch.pruneBranches` feature to automatically clean up local branches when their upstream branches are deleted, while protecting unpushed work. Harald Nordgren's v2 series implements this through new composable `git branch` plumbing commands following Junio Hamano's architectural feedback. The current implementation includes core functionality (`git branch --prune-merged`), fetch integration (`fetch --prune-merged`), per-branch opt-out configuration, and a new `--all-remotes` convenience flag.

Johannes Sixt has raised an important terminology concern about the `--prune-merged` flag name, noting it could confuse users since the command checks upstream status rather than merge status (unlike Git's existing `--merged` behavior). He suggests either changing the implementation to match the name's implied behavior or renaming the flag to better reflect its actual function. This naming issue remains open for discussion.

The series otherwise appears complete, with comprehensive test coverage for all components including push ref handling, unpushed work protection, checked-out branch preservation, and multi-remote scenarios. Junio has endorsed the decomposed architectural approach, and Kristoffer Haugsbakk previously provided documentation feedback that was incorporated regarding "remote-tracking branches" terminology.
