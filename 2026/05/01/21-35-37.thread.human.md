This thread is about the final version (v15) of Harald Nordgren’s patch series adding `git branch --delete-merged`, a safe, automated way to clean up local branches that have been merged. The series is feature-complete, with all safety mechanisms—including `--forked` filtering, per-branch opt-out via config, and `--dry-run` preview—now implemented and passing tests. Harald has also begun overhauling the test suite to use shared fixtures and more realistic scenarios.

The only remaining technical blocker is a small API consistency issue: the `delete_merged_branches()` function still uses a boolean `dry_run` parameter instead of the new flags-based API, preventing full test integration. Phillip Wood, the primary reviewer, has also raised a new design question: whether the command should protect branches that serve as upstreams for other branches not slated for deletion, to avoid breaking stacked-branch workflows. This could require a behavioral change, though Phillip has not yet insisted on it. His other feedback—clearer repository naming, better test consolidation, and exact output matching—is uncontroversial and will likely be adopted in the next iteration.

Harald has committed to waiting for Phillip’s full review before sending another version, so no new patches will appear until the API issue and the stacked-branch question are resolved. Junio and Johannes Sixt have previously weighed in on platform and CLI design, but the thread is now focused on these final details.
