Harald Nordgren's series to automate local branch cleanup when upstream branches are deleted is now complete with the addition of a final convenience flag. The thread started with a proposal for `fetch.pruneBranches` functionality, which evolved into a more composable design at Junio Hamano's suggestion - implementing the core logic as new `git branch` plumbing commands that could then be integrated with fetch.

The v2 series provides both low-level control and user-friendly automation. The new `git branch --forked` lists local branches tracking a remote, while `--prune-merged` safely deletes branches whose upstreams are gone (with protections for unpushed work and checked-out branches). These now work with a new `--all-remotes` flag for convenience across multiple remotes. The high-level `fetch --prune-merged` integration ties it all together for automated cleanup after fetches.

Throughout the series, careful attention was paid to safety: reachability checks prevent data loss, per-branch opt-outs via `branch.<name>.pruneMerged=false` allow exceptions, and the implementation properly handles multiple worktrees. The final patch maintains this rigor while adding the `--all-remotes` convenience, completing the vision of providing both precise control and automation through well-designed plumbing.
