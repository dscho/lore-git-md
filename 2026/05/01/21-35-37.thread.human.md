The thread is Harald Nordgren's v7 patch series (5 patches) adding standalone local branch pruning via `git branch` commands (`--forked`, `--prune-merged`, `--all-remotes`), with per-branch opt-out through `branch.<name>.pruneMerged` config. The core challenge has been safely detecting when an upstream branch has been deleted and the local copy can be cleaned up.

Patches 1 through 3 have now arrived. Patch 1 (`--forked <remote>`) lists branches whose upstream lives on a given remote. Patch 2 is a mechanical refactoring of `delete_branches()` to support bulk-deletion with a single summary warning. Patch 3 -- the heart of the series -- implements `git branch --prune-merged <remote>`, which finds local branches whose push destination has been pruned, verifies their contents are safe to delete, and removes them. The safety logic directly addresses Junio C Hamano's v6 objection: it first checks whether the branch is merged into its own upstream tracking ref, and only falls back to the remote's default branch if that upstream is gone (e.g., because the remote branch was deleted). If neither is available, the branch is refused rather than silently deleted.

Patch 3's implementation reuses the `collect_forked_set()` machinery from patch 1 to enumerate candidates, then filters through two gates: it skips branches whose push destination still exists, and branches whose push destination is the remote's default branch. It uses `branch_get_push()` rather than the upstream tracking ref for the right semantic -- a branch pushed under a different name should be pruned by its push ref. Worktree-checked-out branches are excluded. The test suite is unusually thorough at 14 test cases, covering the mainline case, in-flight branches, unpushed commits, the upstream-gone fallback, the both-gone rejection, checked-out protection, push-ref-different-from-upstream, default-branch protection, and a tricky case with custom `remote.origin.push` config.

Key participants are Harald Nordgren (author) and Junio C Hamano (who raised the v6 design concern that drove the v7 refactoring). No review of the v7 patches has arrived yet, but the design has been iterated seven times and Junio's single technical objection has been addressed. Patches 4-5 (the config opt-out and `--all-remotes` flag) have not yet arrived. The series appears on track for integration once those land and pass review.
