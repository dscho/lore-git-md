This is the final version of Harald Nordgren's `git branch --delete-merged` series, now fully polished and ready for integration. The command provides safe automated cleanup of local branches whose work has already been merged into their upstream, while protecting branches that are still needed—whether because they're checked out, missing their upstream, pushing back to their upstream (like `main` tracking `origin/main`), or explicitly opted out via `branch.<name>.deleteMerged=false` configuration.

The most significant improvement in this version is the refined stacked-branch protection mechanism. Instead of the all-or-nothing approach in earlier iterations, the command now intelligently cleans up while preserving safety: if you try to delete a branch that another unmerged branch depends on, the command will fail with a clear error. However, if a merged branch in the chain is no longer needed (because its own upstream is being deleted), its upstream configuration is automatically cleared, avoiding stale references without breaking the dependency chain. For example, in a stack like `lower→mid→tip` where only `tip` remains unmerged, deleting `lower` will clear `mid`'s upstream (since `lower` is gone) but keep `mid` itself (because `tip` still needs it). This strikes a balance between thorough cleanup and protecting active work.

The series is now complete, with all safety mechanisms in place: per-branch opt-out via configuration, `--dry-run` preview functionality, and comprehensive filtering through the new `--forked` option. The implementation has been thoroughly tested, including edge cases like self-referential upstreams and complex dependency chains. Phillip Wood and Junio C Hamano have both weighed in on the design, with Phillip providing the key refinement to the stacked-branch protection logic that made this version possible. The code maintains Git's API consistency standards and integrates cleanly with existing branch management workflows.
