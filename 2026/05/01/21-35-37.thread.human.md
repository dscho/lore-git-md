This thread is about the final version (v19) of Harald Nordgren's `git branch --delete-merged` series, which is now complete and ready to be merged. The series introduces a new `--delete-merged` command for safe automated local branch cleanup, with multiple safety mechanisms and filtering options.

Key features include a refined stacked-branch protection system that aborts deletion if a branch is used as an upstream for an unmerged branch (while clearing stale upstream configs for kept branches), per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview functionality, and the foundational `--forked` filter. The latest patch adds the `--dry-run` support, which was the last remaining implementation detail - it prints what would happen without making any changes, including properly handling stacked-branch protection scenarios.

The series has received thorough review from Phillip Wood, who provided high-weight feedback on the API design and safety mechanisms, and Junio C Hamano has endorsed the approach. All technical concerns have been addressed, including edge cases around the `--forked` filter and dry-run behavior. The only remaining work is a follow-up to extend the stacked-branch protection to `git branch -d` for consistency, which Harald has agreed to implement after this series lands.

The implementation is now complete with comprehensive test coverage, and the series is ready for merging. The new command will provide Git users with a safer way to clean up merged branches while preserving important branch relationships.
