Harald Nordgren’s `git branch --delete-merged` series is now complete and ready for merging, with all design questions resolved and only a minor mechanical fix remaining. The series introduces a safe, automated way to clean up local branches that have been merged into their upstream, with multiple safety mechanisms and precise control over which branches are deleted.

The core command, `--delete-merged`, deletes local branches merged into their upstream while preserving branches used as upstreams for unmerged branches. It includes stacked-branch protection that aborts deletion if a branch is needed by an unmerged branch but clears stale upstream configurations for kept branches. Other key features include per-branch opt-out via `branch.<name>.deleteMerged=false`, a `--dry-run` preview mode, and the `--forked` filter for selecting branches by their upstream. The command now also supports `<branch>` arguments to limit deletion candidates, reusing the `--forked` filter machinery for consistency.

Phillip Wood’s reviews have been instrumental in shaping the final design, particularly the stacked-branch protection and the flags-based API refactoring. His latest feedback on the per-branch opt-out patch (6/7) was purely stylistic, suggesting a test improvement to use `git for-each-ref` instead of `rev-parse` for verifying branch state. This change would align the test with the series’ broader testing style but doesn’t affect functionality. The only remaining pre-merge action is a mechanical fix to patches 2–4 to resolve a maintenance issue with the flags-based API.
