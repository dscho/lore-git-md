This is the final v24 of Harald Nordgren’s `git branch --delete-merged` series, now fully ready for merging after resolving the last two blocking correctness issues. The series introduces safe, automated local branch cleanup with precise filtering and robust safety controls.

The core feature is the new `--delete-merged` subcommand, which deletes local branches already merged into their upstream while preserving branches that are checked out, missing upstreams, or used as upstreams for unmerged work. Key safety mechanisms include per-branch opt-out via `branch.<name>.deleteMerged=false`, order-independent stacked-branch protection (which now clears stale upstream configs for kept branches), and `--dry-run` preview mode. The command supports repeatable `--delete-merged` arguments (e.g., `--delete-merged origin/main --delete-merged origin/next`) and optional positional patterns (e.g., `topic-*`) to control deletion scope.

Version 24 fixes the two remaining issues from v23: the push-detection logic now correctly determines whether pushing a branch would update its upstream, and the stacked-branch protection has been simplified to align with the design goal of clearing upstream configs for kept branches. Junio C Hamano has confirmed the series is ready for merging pending final review of these fixes, and Phillip Wood’s technical concerns have been addressed. The implementation is complete, thoroughly tested, and introduces no regressions to existing functionality.

Harald has agreed to extend the stacked-branch protection to `git branch -d` as a follow-up, and Phillip Wood’s proposed refinement to the `--forked` filter (to better distinguish true forks) is noted as a future improvement. The series touches `builtin/branch.c`, `ref-filter.c`, and documentation, and is well-aligned with Git’s API consistency expectations.
