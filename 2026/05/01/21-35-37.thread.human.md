Harald Nordgren’s `git branch --delete-merged` series, now at v17, aims to automate local branch cleanup with precise controls and robust safety mechanisms. The command deletes merged branches while preserving those used as upstreams for unmerged work, avoiding stale references. Key features include the `--forked` filter for branch selection, per-branch opt-out via `branch.<name>.deleteMerged=false`, and a `--dry-run` preview to show what would be deleted or modified without making changes.

The series is functionally complete, with all planned features implemented, but a critical bug in the stacked-branch protection logic remains unresolved. The current implementation incorrectly preserves *all* upstream configurations instead of selectively clearing the upstream settings of unmerged branches that depend on merged ones, undermining the safety mechanism. Harald has acknowledged this issue and will revise the patch. Junio C Hamano and Phillip Wood have weighed in on the design, agreeing that `--delete-merged` should behave like a loop over `git branch -d`, inheriting its safety checks—including preserving branches used as upstreams. This simplifies the implementation and avoids surprises for users.

The series is close to final review, but the stacked-branch protection bug must be fixed first. Once resolved, the command will provide a safe, automated way to clean up local branches while respecting dependencies and user preferences.
