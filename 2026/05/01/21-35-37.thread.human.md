This thread is about the final version (v18) of Harald Nordgren's `git branch --delete-merged` series, which is now implementation-complete and ready for merging. The series introduces a new `--delete-merged` command for safe automated local branch cleanup, with comprehensive filtering and safety controls. Key features include stacked-branch protection (abort-and-clear), per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview, and the `--forked` filter for branch selection.

The latest discussion between Phillip Wood and Harald Nordgren clarified a subtle edge case: when `remote.pushDefault` is set, branches without an explicit `branch.<name>.pushRemote` (like `main`, `next`, or `seen`) may be incorrectly classified as "forked" and thus eligible for deletion unless manually exempted. This was exposed by a test improvement—replacing an artificial `mainline` branch with `main` and explicitly configuring `branch.main.pushRemote`—which made the test more realistic. While this is a known limitation, it doesn’t affect the core logic or safety checks, and the series remains on track for merging once a mechanical flags cleanup (agreed earlier) is applied. A documentation note may be added to warn users about this behavior.

Phillip Wood’s feedback has been instrumental in shaping the final design, including the refined stacked-branch protection and flags-based API. Junio C Hamano has endorsed the design, and all substantive design questions are now resolved. The only remaining pre-merge action is the agreed-upon cleanup in patches 2-4/7. The test suite is comprehensive, covering all safety mechanisms, edge cases, and the new `--dry-run` functionality.
