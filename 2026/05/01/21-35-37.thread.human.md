Harald Nordgren’s `git branch --delete-merged` series is now complete and merged into Junio C Hamano’s `next` branch for integration testing. The series introduces a new `--delete-merged` subcommand that safely automates local branch cleanup with fine-grained control and robust safety mechanisms.

The feature allows users to delete local branches that are merged into specified upstreams (e.g., `origin/main`) while preserving branches that are checked out, used as upstreams for unmerged work, or explicitly opted out via `branch.<name>.deleteMerged=false`. The command supports repeatable `--delete-merged` arguments to widen the upstream match (e.g., `--delete-merged origin/main --delete-merged origin/next`) and optional positional patterns (e.g., `topic-*`) to limit deletion scope. A `--dry-run` mode, added in the final patch, lets users preview deletions without modifying refs or configuration, completing the safety architecture.

Key safety features include order-independent stacked-branch protection (which aborts deletion if a branch is used as an upstream for an unmerged branch and clears stale upstream configs for kept branches), push-divergence checks, and per-branch opt-out. The implementation also includes a composable `--forked` filter for `git branch --list`, which serves as the foundation for the deletion logic. Junio and Phillip Wood have both confirmed the series is ready for merging after Harald addressed the last technical blockers in v24: a corrected push-detection algorithm and a simplified stacked-branch protection design. The v25 update made only mechanical changes (wrapping long test command lines) with no functional impact.

The series is now in `next` and expected to graduate to `master` in the current cycle. The only planned follow-up is extending the stacked-branch protection to `git branch -d` for consistency, but this is not a blocker for the current work. The code touches `builtin/branch.c`, `ref-filter.c`, and the test suite, with documentation updates for the new options and config keys.
