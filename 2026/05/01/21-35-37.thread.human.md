Harald Nordgren’s `git branch --delete-merged` series has reached its final form in v18 and is now ready for merging, with all design questions resolved and every planned feature implemented. The series introduces a new `--delete-merged` command that safely automates local branch cleanup while providing fine-grained control through filters, safety mechanisms, and preview capabilities.

The core command, added in patch 5/7, deletes local branches that are merged into their upstream, but only after passing a battery of safety checks: it preserves checked-out branches, branches with missing upstreams, branches where the push ref diverges from the upstream, and branches opted out via the new `branch.<name>.deleteMerged=false` config key. Most importantly, it implements **refined stacked-branch protection**, which prevents deletion of any branch that is used as an upstream for an unmerged branch—while still cleaning up stale upstream configurations for branches that are kept. This ensures that dependency chains (like `feature1→feature2→feature3`) remain intact, and the command provides clear feedback when it skips a branch for this reason.

The foundation for branch selection is laid in patch 1/7 with the `--forked` filter, which lets users target branches forked from specific refs (e.g., `origin/main` or `origin/*`). Patches 2-4/7 refactor the deletion API to use flags instead of boolean arguments, making it easier to extend with new behaviors like `DELETE_BRANCH_SKIP_UNMERGED` (added in this latest patch) and `DELETE_BRANCH_DRY_RUN`. The `--dry-run` preview, implemented in patch 7/7, gives users a zero-risk way to see exactly which branches would be deleted or skipped, including all safety checks and protection logic.

Phillip Wood’s feedback was instrumental in shaping the final design, particularly the refined stacked-branch protection, and Junio C Hamano has endorsed the approach. The series is now implementation-complete, with a comprehensive test suite covering edge cases like self-referential upstreams and chains of dependencies.
