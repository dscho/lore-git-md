Harald Nordgren's `git branch --delete-merged` series is now in its 17th iteration, offering a safe and automated way to clean up local branches that have been merged into their upstreams. The core command, introduced in this patch, deletes merged branches while preserving those used as upstreams for other branches—a feature called stacked-branch protection. The series also includes per-branch opt-out via `branch.<name>.deleteMerged=false`, a `--dry-run` preview mode, and a composable `--forked` filter for precise branch selection.

The implementation is largely complete, with all planned safety mechanisms in place, but a critical issue remains: the stacked-branch protection logic is currently broken. The design was finalized as "abort-and-notify" (failing with an error if a branch is used as an upstream), but the current code incorrectly attempts to clear upstream configurations instead. Phillip Wood identified this flaw and proposed an alternative approach that would preserve only the upstreams of unmerged branches while clearing configs for merged ones, offering a more nuanced solution. Harald has agreed to revise the implementation to align with the agreed-upon design.

Junio C Hamano has confirmed the abort-and-notify approach as the correct direction, meaning the series is not yet ready for final review. Once the stacked-branch protection logic is fixed, the command should be fully functional, providing a robust tool for branch cleanup with clear safety guarantees. The `--dry-run` mode and per-branch opt-out further enhance its usability, making it suitable for both casual and advanced workflows.
