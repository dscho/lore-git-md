This is the eighteenth and likely final version of Harald Nordgren's `git branch --delete-merged` series, which adds safe automated cleanup of local branches with fine-grained control. The series is now implementation-complete, with all design questions resolved and only minor mechanical fixes remaining before it can be merged.

The core feature is a new `--delete-merged` command that deletes local branches already merged into their upstream, while preserving branches that are checked out, used as upstreams for unmerged work, or explicitly opted out via `branch.<name>.deleteMerged=false`. The command includes stacked-branch protection that aborts if a branch is needed by an unmerged branch, but clears stale upstream configurations for kept branches whose own upstream is being deleted. A `--dry-run` mode lets users preview what would happen without making changes.

Phillip Wood has been the primary reviewer, shaping key aspects of the design—particularly the stacked-branch protection and the flags-based deletion API. His latest feedback proposed a refinement to the `--forked` filter to better distinguish true forks from long-lived branches like `main` or `next` when `remote.pushDefault` is set. While Harald agrees the idea is sound and plans to implement it, this improvement is not a blocker for merging the current series. Junio Hamano has already endorsed the design, and the only remaining tasks are mechanical cleanups to the flags API and rejecting the nonsensical `--dry-run --quiet` combination. The series is ready for Junio’s queue.
