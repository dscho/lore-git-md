This thread is about the final version (v23) of Harald Nordgren's `git branch --delete-merged` series, which adds safe automated local branch cleanup with comprehensive filtering and safety controls. The series is **implementation-complete but blocked on two unresolved correctness issues** identified by Phillip Wood.

Harald has addressed all prior feedback, including Junio C Hamano's mechanical fixes to patch 1/7 (style and type mismatch) and Phillip's test improvements. The core command supports repeatable `--delete-merged` arguments (e.g., `--delete-merged origin/main --delete-merged origin/next`), per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview, and **order-independent stacked-branch protection** (failing to delete a branch if it's used as an upstream for an unmerged branch). Junio has confirmed the series is ready for merging pending resolution of Phillip's technical concerns.

The two remaining blockers are:
1. **`branch_pushes_to_upstream()` correctness**: The current implementation risks false negatives/positives. Harald is rewriting it to correctly apply push/fetch refspecs.
2. **Stacked-branch protection test discrepancy**: The test expects upstream configs of kept merged branches to remain intact, but the design goal is to clear them. Harald will update the logic to match the design.

Harald's latest email confirms he's actively fixing both issues. Once resolved, the series will be ready for merging, with follow-up work planned to extend stacked-branch protection to `git branch -d`. The rest of the series—including the flags-based API, per-branch opt-out, and `--dry-run`—is finalized and unchanged.
