This thread is about the final version (v20) of Harald Nordgren's `git branch --delete-merged` series, which is now complete and ready for merging. The series introduces a safe, automated way to clean up local branches with fine-grained control and multiple safety mechanisms.

The core feature is the `--delete-merged` subcommand, which deletes local branches merged into their upstream while preserving branches used as upstreams for unmerged work. Key capabilities include per-branch opt-out via `branch.<name>.deleteMerged=false`, order-independent protection for stacked branches (e.g., `b1→b2→b3`), and a `--dry-run` preview mode. The latest patch adds this `--dry-run` support, allowing users to preview deletions without modifying refs or config. The implementation respects all safety checks and integrates cleanly with the flags-based API introduced earlier in the series.

Harald Nordgren has addressed all feedback from Phillip Wood and Junio C Hamano, including a structural fix for order dependency in stacked-branch protection and test improvements. Junio's earlier blocking concern about correctness is now resolved, and the series is unblocked. The only agreed follow-up is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands. Phillip Wood's reviews have been thorough but now only raise minor stylistic points, all of which have been addressed.

The series is now feature-complete, with comprehensive test coverage for edge cases like self-referential upstreams, missing upstreams, and push divergence. The `--dry-run` implementation is particularly well-scoped, matching Git's existing conventions and providing a practical way to sanity-check wide deletion patterns before execution. No open questions remain, and the series is ready for merging.
