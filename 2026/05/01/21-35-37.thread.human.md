Harald Nordgren’s `git branch --delete-merged` series has reached its final form in v19 and is now ready for merging. The series introduces a safe, automated way to clean up local branches that have been merged into their upstream, with multiple layers of protection to prevent accidental data loss. Key features include a refined stacked-branch protection system that aborts deletion if a branch is used as an upstream for an unmerged branch (while clearing stale upstream configs for kept branches), a per-branch opt-out mechanism via `branch.<name>.deleteMerged=false`, and a `--dry-run` preview mode that shows exactly which branches would be deleted or skipped.

The latest patch in the series adds the per-branch opt-out, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`. This addresses a common workflow need for iterative topic branches without complicating the core deletion logic. Phillip Wood and Junio C Hamano have reviewed the series thoroughly, with only minor test improvements and documentation tweaks requested and addressed. Junio has endorsed the stacked-branch protection design and requested that it be extended to `git branch -d` for consistency; Harald has agreed to implement this as a follow-up after the series lands.

All design questions are resolved, the test suite is comprehensive, and the implementation is complete. The series is now waiting for Junio to pick it up for merging.
