Here’s the human-mode summary for a developer catching up on the thread:

Harald Nordgren’s `git branch --delete-merged` series, now at v23, is a long-running effort to add safe automated branch cleanup to Git. The command deletes local branches merged into their upstream while preserving branches used as upstreams for unmerged work, with safety controls like per-branch opt-out, `--dry-run` preview, and protection against breaking dependency chains. Junio C Hamano has already signaled the series is ready for merging, but two unresolved correctness issues identified by Phillip Wood are blocking progress.

The first issue is a flaw in the push-detection logic. The current implementation risks deleting branches like `main` that track `origin/main` (false negatives) or keeping branches that should be deleted (false positives). Phillip Wood clarified the correct approach: apply the *push* refspec to the local branch, then apply the *fetch* refspec in reverse, and compare the result to the upstream branch. Harald acknowledges this will require re-adding some of the push logic removed earlier for simplicity.

The second issue is a test discrepancy in the stacked-branch protection logic. The test expects the upstream config of a kept merged branch (`lower`) to remain intact, but the design goal is to clear stale configs for kept branches whose own upstream is being deleted. Harald confirmed the intent is to preserve the upstream chain of surviving *tips*, but the test expectation contradicts this. Resolution will require either adjusting the logic to match the test or updating the test to match the design.

Beyond these blockers, the series is complete. It includes a flags-based API for deletion behavior, per-branch opt-out via `branch.<name>.deleteMerged=false`, and order-independent stacked-branch protection via a single-pass graph traversal. The `--dry-run` preview is fully implemented and avoids modifying config during dry runs. Junio has requested extending the stacked-branch protection to `git branch -d` for consistency, which Harald has agreed to implement as a follow-up after the series lands.

Phillip Wood’s feedback has been instrumental in shaping the series, from the stacked-branch protection design to the flags-based API. His latest review drills into the core logic, identifying the two blocking issues. The rest of the feedback—minor documentation and test style improvements—has already been addressed in principle. Once the push-detection logic and stacked-branch test discrepancy are resolved, the series should be ready to merge.
