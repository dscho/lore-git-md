This thread is about the final version (v22) of Harald Nordgren’s `git branch --delete-merged` series, which is now **implementation-complete, unblocked, and ready for merging**. The series introduces a safe, automated way to clean up local branches that have been merged into their upstream, with robust filtering and safety controls.

The only change in v22 is a mechanical loop variable adjustment (`int i` instead of `size_t i`) to avoid CI timeouts, with no functional impact. This version is identical to v21, which resolved the last major correctness issue—order dependency in stacked-branch protection—via a single-pass graph traversal that ensures consistent results regardless of ref iteration order. Junio C Hamano has confirmed there are no outstanding issues, and the series is now ready for merging.

The core command, `git branch --delete-merged`, deletes local branches merged into their upstream (specified via one or more `--delete-merged` arguments, e.g., `--delete-merged origin/main --delete-merged origin/next`) while preserving branches used as upstreams for unmerged branches. It supports optional positional patterns (e.g., `topic-*`) to limit deletion scope and includes multiple safety mechanisms: skipping checked-out branches, branches with missing upstreams, branches that push to their upstream (e.g., `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`. The `--dry-run` flag provides a preview without modifying refs or config, and the nonsensical `--dry-run --quiet` combination is rejected.

The series has been thoroughly reviewed and tested, with contributions from Phillip Wood and Junio C Hamano shaping its final design. The only agreed follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands. The implementation touches `builtin/branch.c`, `ref-filter.c`, documentation, and the test suite, and is well-aligned with Git’s API consistency expectations.
