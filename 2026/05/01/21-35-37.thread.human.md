Harald Nordgren’s `git branch --delete-merged` series has reached its final stages, with all design questions resolved and only mechanical pre-merge fixes remaining. The series introduces a safe, automated way to clean up local branches with fine-grained control, including a `--forked` filter, per-branch opt-out, `--dry-run` preview, and robust stacked-branch protection.

The core command, `--delete-merged`, now safely deletes local branches merged into their upstream while preserving those used as upstreams for unmerged branches. This protection—refined to "abort-and-clear" (fail to delete a branch if it’s an upstream for an unmerged branch, but clear stale upstream configs for kept branches)—has been endorsed by Junio and will now also apply to `git branch -d` for consistency. Other key features include per-branch opt-out via `branch.<name>.deleteMerged=false`, a `--dry-run` mode for risk-free previews, and `<branch>` argument support to limit deletion candidates.

Phillip Wood’s review is now complete, and the only remaining work before merging is mechanical: cleaning up the flags-based API in patches 2-4/7, rejecting the nonsensical `--dry-run --quiet` combination, and extending stacked-branch protection to `git branch -d`. A proposed refinement to the `--forked` filter’s logic (to better distinguish true forks from long-lived branches) is acknowledged as a sound improvement but will be implemented as a follow-up. The series is ready for merging once these final touches are applied.
