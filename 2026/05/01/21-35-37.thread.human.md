This thread explores automating local branch cleanup when upstream branches are deleted, with Harald Nordgren's v4 series proposing both low-level `git branch` plumbing commands and high-level `fetch.pruneLocalBranches` integration. The implementation includes robust safety mechanisms like default branch protection and per-branch opt-outs.

A significant development has emerged: Johannes Sixt, maintainer of gitk/Git GUI, raised a fundamental objection to having `fetch` modify local branches, arguing this violates command boundary principles. Harald's latest response suggests he may be reconsidering the design in light of this feedback, acknowledging "maybe that's a good point."

The discussion now stands at a crossroads. The technical implementation is complete and functional, but faces an architectural dilemma. The core branch-pruning commands (`git branch --forked` and `--prune-merged`) remain uncontroversial and useful regardless of the outcome. However, the convenience of automatic pruning via fetch may need to be rethought to maintain clean command separation. Next steps will likely involve either justifying the current integration approach despite the boundary concerns, or proposing alternative automation mechanisms that respect the command boundaries while still providing similar functionality.
