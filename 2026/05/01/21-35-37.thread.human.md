Harald Nordgren’s `git branch --delete-merged` series has reached its final version (v18) and is now implementation-complete, with all design questions resolved and only minor mechanical fixes remaining before it can be merged. The series introduces a new `--delete-merged` command that automates safe local branch cleanup, offering precise control through filtering, safety checks, and user-configurable opt-outs. Key features include the `--forked` filter (which supports exact refnames, remote shorthand, and shell-style globs), per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview, and refined stacked-branch protection that aborts deletion if a branch is used as an upstream for an unmerged branch while clearing stale upstream configs for kept branches.

Phillip Wood’s reviews have been instrumental in shaping the series, particularly the stacked-branch protection design and the flags-based API refactoring. His latest feedback focuses on a subtle edge case in the `--forked` filter: branches without an explicit `branch.<name>.pushRemote` may be misclassified as forked when `remote.pushDefault` is set, potentially affecting long-lived branches like `main`. Phillip proposes a refined heuristic (simulating push/fetch refspecs) to improve precision, but this is a forward-looking improvement rather than a blocker. The series remains ready for merging once the agreed mechanical fixes—replacing local boolean uses with direct flag checks in patches 2-4/7 and rejecting the nonsensical `--dry-run --quiet` combination—are applied.
