Harald Nordgren’s `git branch --delete-merged` series has reached its final form in v24 and is now ready for merging. The series introduces a safe, automated way to clean up local branches with precise control over which branches are deleted, including robust safety mechanisms and a preview mode.

The core command, `git branch --delete-merged`, deletes local branches that are merged into their upstream (as specified by one or more `--delete-merged` arguments) while preserving branches that are still needed—such as those used as upstreams for unmerged branches, checked-out branches, or branches explicitly opted out via `branch.<name>.deleteMerged=false`. The v24 update resolves the last two technical blockers: a push-detection logic flaw that could incorrectly preserve or delete branches based on `remote.pushDefault` configuration, and a stacked-branch protection issue where the implementation didn’t fully align with the design goal of clearing upstream configs for kept branches. Phillip Wood’s final review confirms these fixes work as intended, and Junio C Hamano’s prior approval stands contingent on these corrections.

The series also includes a `--dry-run` mode to preview deletions without making changes, per-branch opt-out via config, and a composable `--forked` filter for future branch management features. The implementation is thoroughly tested, with coverage for edge cases like self-referential upstreams, missing upstreams, and chains of branch dependencies. The only remaining feedback is a minor test formatting nit, which could be addressed in a final version if requested. The series is now poised to land in `next`, with a follow-up planned to extend the stacked-branch protection to `git branch -d` for consistency.
