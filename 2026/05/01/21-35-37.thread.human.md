This thread is about the final version (v21) of Harald Nordgren's `git branch --delete-merged` series, which is now complete and ready for merging. The series introduces a safe, automated way to clean up local branches that have been merged into their upstream, with robust filtering and safety controls.

The core feature is the `--delete-merged` subcommand, which deletes local branches merged into one or more specified upstreams (e.g., `git branch --delete-merged origin/main --delete-merged origin/next`). It includes multiple safety mechanisms: it skips checked-out branches, preserves branches used as upstreams for unmerged work, respects per-branch opt-out via `branch.<name>.deleteMerged=false`, and provides a `--dry-run` preview. The implementation is order-independent, ensuring consistent results regardless of how branches are iterated, and handles edge cases like self-referential upstreams and missing configurations.

All planned features are implemented, including the `--dry-run` flag added in this final patch, which prints what would be deleted without making changes. The series has been thoroughly reviewed by Phillip Wood and Junio C Hamano, with all blocking issues resolved. The only remaining work is a follow-up to extend the stacked-branch protection to `git branch -d` for consistency, which Harald has agreed to implement after this series lands. The code touches `builtin/branch.c`, documentation, and the test suite, and is now unblocked for merging.
