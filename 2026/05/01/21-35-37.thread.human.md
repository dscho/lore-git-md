Harald Nordgren's `git branch --delete-merged` series is now complete and ready for merging, with the final piece—per-branch opt-out via `branch.<name>.deleteMerged`—now implemented in v24. This series introduces safe, automated local branch cleanup with precise control over which branches are deleted, addressing long-standing workflow pain points for Git users.

The core command, `git branch --delete-merged`, deletes local branches that are fully merged into their upstream (as specified by one or more `--delete-merged` arguments) while preserving branches that are checked out, used as upstreams for unmerged work, or explicitly opted out. The v24 update resolves the last two technical blockers: a flaw in the push-detection logic that could misidentify branches as safe to delete, and a test discrepancy in the stacked-branch protection mechanism. Junio C Hamano has confirmed the series is ready for merging pending final review of these fixes, and Phillip Wood, whose feedback shaped much of the design, has signed off on the corrections.

Key features include order-independent stacked-branch protection (which now clears stale upstream configs for kept branches), a `--dry-run` preview mode, and the ability to exempt specific branches from automated cleanup via config. The series also refactors the deletion API to use flags instead of boolean arguments, improving maintainability. All planned functionality is implemented, thoroughly tested, and documented. The only remaining work is a follow-up to extend stacked-branch protection to `git branch -d` for consistency, which Harald has agreed to tackle after the series lands. The patches touch `builtin/branch.c`, `ref-filter.c`, and documentation, and the changes are backward-compatible with existing workflows.
