This thread is about the final version (v21) of Harald Nordgren’s patch series adding `git branch --delete-merged`, a new command for safe automated cleanup of merged local branches. The series is now complete, unblocked, and ready for merging with no known issues.

The feature provides precise control over branch deletion through repeatable upstream selectors (e.g., `--delete-merged origin/main --delete-merged origin/next`), per-branch opt-out via `branch.<name>.deleteMerged=false`, and a `--dry-run` preview mode. The most significant technical achievement is order-independent stacked-branch protection, which ensures branches used as upstreams for unmerged work are preserved regardless of iteration order. This was implemented via a single-pass graph traversal that collects all protected branches before any deletions occur, resolving a correctness issue that previously blocked the series.

All planned functionality is implemented, including the flags-based API refactoring (patches 2-4/7), per-branch opt-out (patch 6/7), and `--dry-run` support (patch 7/7). The only change in v21 was a mechanical loop variable adjustment to prevent a CI timeout, with no functional impact. Junio C Hamano and Phillip Wood have reviewed the series and confirmed the design is sound. The sole agreed follow-up is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented after the series lands. The test suite is comprehensive, covering all edge cases including the fixed `--forked` filter behavior and order-independent protection logic.
