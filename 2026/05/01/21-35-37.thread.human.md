This is the final version of Harald Nordgren's `git branch --delete-merged` series, now fully implemented and ready for merging. The feature allows safe, automated cleanup of local branches that have been merged into their upstream, with robust safety controls to prevent accidental data loss.

The core command, introduced in this patch, deletes local branches merged into one or more specified upstreams (e.g., `git branch --delete-merged origin/main --delete-merged origin/next`) while preserving branches that are still needed. Key safety mechanisms include protection for checked-out branches, branches with missing upstreams, branches that push to their upstream (like `main` tracking `origin/main`), and branches opted out via `branch.<name>.deleteMerged=false`. The implementation is order-independent, ensuring consistent results regardless of how branches are iterated, and includes a new stacked-branch protection system that prevents deletion of branches used as upstreams for unmerged work while cleaning up stale upstream configurations for kept branches.

The series has been thoroughly reviewed and tested, with all prior concerns addressed. Junio C Hamano has confirmed there are no outstanding issues, and the only remaining work is a follow-up to extend the stacked-branch protection to `git branch -d` for consistency. The feature is now unblocked and will appear in an upcoming "What's cooking" report.
