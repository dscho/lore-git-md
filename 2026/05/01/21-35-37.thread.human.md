Harald Nordgren's `git branch --delete-forked` series has reached its 13th and likely final iteration, now in the polishing phase before merging. The feature provides safe automated cleanup of local branches by deleting those whose upstream branches match specified patterns (like "origin/*"), with comprehensive safety checks to prevent accidental data loss. After extensive review, the implementation is technically complete with all core functionality in place: configurable branch exemptions, dry-run previews, warnings for unmerged branches, and flexible branch specification patterns.

The latest version confirms the command name as `--delete-forked` (originally proposed as `--prune-merged`) and makes several final refinements. The filtering logic is now fully moved into `apply_ref_filter()` for better integration with Git's existing ref machinery, uses positional arguments for branch patterns, and requires full refname matching for exact patterns while supporting glob matching for upstream names. All safety mechanisms from previous versions remain intact, including protection for checked-out branches and configurable opt-outs.

Phillip Wood has been driving the final syntax refinements, with Junio C Hamano having confirmed technical completeness in v11. Only minor documentation adjustments remain before the series can be merged.
