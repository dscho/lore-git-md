This thread is about the final version (v23) of Harald Nordgren’s `git branch --delete-merged` series, which adds safe automated local branch cleanup with comprehensive filtering and safety controls. The series is now implementation-complete, unblocked, and ready for merging after addressing all prior review feedback, including mechanical fixes in the latest iteration.

The core feature is a new `--delete-merged` subcommand that deletes local branches merged into their upstream while preserving branches used as upstreams for unmerged work. Key capabilities include per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview, order-independent stacked-branch protection, and repeatable upstream selectors (e.g., `--delete-merged origin/main --delete-merged origin/next`). The series also introduces a composable `--forked` filter for `git branch --list` and refactors the deletion API to use flags instead of boolean arguments.

Junio C Hamano has confirmed the series is ready for merging, and it will appear in an upcoming "What’s cooking" report. However, Phillip Wood’s latest review raises two critical technical concerns that must be addressed first. The first is a potential logic error in the stacked-branch protection traversal, where the test for "keeps the upstream chain of a surviving branch" may have mismatched expectations. The second is a flaw in the `branch_pushes_to_upstream()` function, which incorrectly checks fetch refspecs instead of push refspecs, risking false negatives (deleting branches that should be preserved) or false positives (keeping branches that should be deleted). These issues are blockers but should be straightforward to fix, as the core design and safety mechanisms are already sound and well-tested.

Harald has agreed to implement a follow-up to extend stacked-branch protection to `git branch -d` for consistency, but this is not a blocker for the current series. The series touches `builtin/branch.c`, `ref-filter.c`, documentation, and tests, with patches 2–4/7 focusing on the flags-based API and patch 1/7 providing the `--forked` filter foundation. Once the push-detection logic and test expectations are corrected, the series is ready to land.
