Harald Nordgren's `git branch --prune-merged` series is nearing completion, providing safe automated cleanup of local branches whose changes have been merged upstream. The v9 implementation has addressed all technical concerns, with Junio Hamano approving the safety model after removal of the `--force` option. The series currently offers remote-focused operations through `--forked <remote>`, `--prune-merged`, and `--all-remotes` flags, along with per-branch `branch.<name>.pruneMerged` configuration.

A key remaining discussion centers on interface design. Phillip Wood has advocated for making the command work with local upstream branches (like `master`) in addition to remote-tracking branches. Junio has now strongly endorsed this position, demonstrating how the feature could be generalized while maintaining safety. This reveals an inconsistency in Git's existing behavior regarding how `origin` is interpreted differently between `checkout -b` and the current `--prune-merged` design. 

With the maintainer's clear preference for a more flexible interface, the series will likely see a v10 revision adjusting the argument handling semantics before final acceptance. The core implementation remains sound, but the scope is expanding to better accommodate both remote-tracking and local-only workflows.
