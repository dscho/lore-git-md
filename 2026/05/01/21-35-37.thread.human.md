This is the final version (v19) of Harald Nordgren’s `git branch --delete-merged` series, now complete and ready for merging. The series introduces a new `--delete-merged` command that safely automates local branch cleanup with multiple safety mechanisms, including per-branch opt-out, stacked-branch protection, and a `--dry-run` preview mode.

The core feature is the `--delete-merged` subcommand (patch 5/7), which deletes local branches merged into their upstream while preserving branches used as upstreams for unmerged work. The command now supports repeatable `--delete-merged` arguments (e.g., `--delete-merged origin/main --delete-merged origin/next`) to widen the upstream match and optional positional patterns (e.g., `topic-*`) to limit deletion scope. Safety checks include protection for checked-out branches, missing upstreams, and branches where pushing by name would update their upstream (e.g., `main` tracking `origin/main`). Per-branch opt-out via `branch.<name>.deleteMerged=false` (patch 6/7) allows users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The series also introduces the `--forked` filter (patch 1/7) as a foundational building block, which lists branches whose upstream matches a given ref, remote name, or shell glob. This filter is composable with existing filters like `--merged` and is used internally by `--delete-merged`. The v19 implementation fixes an edge case where branches without explicit `branch.<name>.pushRemote` could be misclassified as forked, ensuring they are protected if pushing them by name would update their upstream.

All design questions have been resolved, including the stacked-branch protection mechanism, which now uses an "abort-and-clear" approach: the command fails to delete a branch if it is used as an upstream for an unmerged branch but clears the upstream config for kept (merged) branches whose own upstream is being deleted. Junio C Hamano has requested that this protection be extended to `git branch -d` for consistency, and Harald has agreed to implement this as a follow-up after the series lands.

Phillip Wood’s reviews have been instrumental in shaping the final design, particularly the flags-based API refactoring (patches 2-4/7) and the stacked-branch protection logic. His feedback on test improvements and edge cases has been fully addressed, and he has confirmed his review of the series is complete. The series is now ready for merging, with no remaining open questions. The only follow-up work is the extension of stacked-branch protection to `git branch -d` and a future refinement to the `--forked` filter heuristic.
