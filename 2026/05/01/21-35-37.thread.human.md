Harald Nordgren’s `git branch --delete-merged` series is now in its 17th iteration, offering a safe way to automate local branch cleanup with fine-grained controls. The command deletes branches merged into their upstream while preserving those still in use—either as upstreams for unmerged work, checked-out branches, or branches explicitly opted out via `branch.<name>.deleteMerged=false`. It also includes a `--dry-run` mode to preview changes and a `--forked` filter to refine branch selection.

The core functionality is complete, but a critical bug in the stacked-branch protection mechanism remains unresolved. The current implementation incorrectly preserves *all* upstream configurations, including those of merged branches, instead of clearing only the upstreams of unmerged branches that depend on them. Phillip Wood identified this flaw, along with an inefficiency in how upstream branches are tracked, and Harald has acknowledged both issues. The next version will need to fix these problems before the series can move forward.

Junio has not objected to the upstream-clearing approach, but the series isn’t ready for final review until the stacked-branch protection is corrected. The rest of the features—per-branch opt-out, `--dry-run`, and the `--forked` filter—are working as intended and have solid test coverage.
