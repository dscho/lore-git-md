Harald Nordgren's `git branch --delete-merged` series has reached its 15th iteration, introducing a safe and configurable way to automatically clean up merged local branches. The command now includes multiple safety mechanisms: it never touches checked-out branches, preserves branches that push to their upstream, skips unmerged branches by default, and provides dry-run capability. The v15 series adds new filtering options like `--forked` for branch selection and a flag-based API for controlling deletion behavior.

The latest patch (6/7) introduces a per-branch opt-out mechanism via `branch.<name>.deleteMerged` configuration. When set to false, this prevents automatic deletion of specific branches even if they meet all other criteria, with the command showing an explanatory message unless `--quiet` is used. The implementation includes thorough documentation and tests, maintaining the series' strong focus on safety while giving users more control. 

The series has benefited from extensive review, with Phillip Wood providing key implementation feedback and Junio C Hamano confirming resolution of platform issues. With all test failures now resolved and core functionality complete, the remaining work appears to be final documentation polish and verification of edge cases in remote shorthand resolution. This represents a mature solution after fifteen iterations, building on Git's existing branch management capabilities while introducing new safety-focused automation.
