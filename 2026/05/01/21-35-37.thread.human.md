Harald Nordgren’s `git branch --delete-merged` series has reached its seventeenth and likely final iteration, offering a safe, automated way to clean up local branches that have been merged. The series is now technically complete, with all requested safety mechanisms—including stacked-branch protection—implemented and tested. The command filters candidates by reachability from a specified upstream, checks for push divergence, respects per-branch opt-outs via `branch.<name>.deleteMerged`, and never touches checked-out branches or those used as upstreams for other branches. A `--dry-run` mode lets users preview deletions before committing to them.

The foundation for the feature was laid in the first two patches: patch 1/7 introduced the `--forked` filter, which lists branches whose upstreams match a given ref, remote, or glob, while patch 2/7 refactored the internal deletion API to use flags instead of booleans, making it easier to extend. The third patch, just summarized, added a `DELETE_BRANCH_SKIP_UNMERGED` flag so that bulk operations like `--delete-merged` can silently skip unmerged branches rather than failing on the first refusal. Later patches built out the core logic, safety checks, and stacked-branch protection, which aborts deletion if a branch is used as an upstream for any other branch, preventing broken `@{u}` references in stacked workflows.

Phillip Wood and Junio C Hamano were the key reviewers, with Phillip advocating for stacked-branch safety and Junio initially skeptical but now fully endorsing the abort-and-notify default. The series has addressed all high-weight feedback and is ready for final review. The only remaining step is a thorough look from the maintainer before it can be queued for merging.
