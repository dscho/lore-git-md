Harald Nordgren's series to automate local branch cleanup when upstream branches are deleted has reached its third and final iteration. The core idea is to provide both low-level plumbing commands (`git branch --forked` and `--prune-merged`) and high-level automation (`git fetch --prune-merged`) for safely removing local branches that track deleted upstream branches while preserving unpushed work. 

The v3 series now includes all planned functionality, with the latest patch adding a convenient `--all-remotes` flag that works with both the `--forked` and `--prune-merged` options to operate across all configured remotes at once. The implementation maintains robust safety checks: it protects checked-out branches across all worktrees, performs reachability check by default to prevent data loss (with `--force` override available), and introduces a new per-branch opt-out via `branch.<name>.pruneMerged` configuration. 

While the technical implementation appears complete with thorough test coverage, Johannes Sixt's concern about the potentially misleading `--prune-merged` naming remains unresolved - the flag actually checks upstream status rather than commit reachability. The series awaits final review with this semantic question as the last open issue before potential merging.
