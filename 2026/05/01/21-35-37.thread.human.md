Harald Nordgren's `git branch --delete-merged` series has reached its final form after 15 iterations, introducing a safe and flexible way to clean up merged local branches. The feature now includes comprehensive safety mechanisms: it never touches checked-out branches, preserves branches that can still push to their upstream, and offers both a per-branch config opt-out (`branch.<name>.deleteMerged`) and a new `--dry-run` preview mode in the final patch.

The command provides precise control through its `--forked` filter (added in v15) and flag-based API, with strict checks for merged status and push divergence. The implementation has been thoroughly tested across edge cases, with Phillip Wood contributing key feedback that shaped the final design. Junio Hamano and Johannes Sixt also participated in reviewing platform-specific aspects and CLI decisions.

With the series now complete—passing all tests and fully documented—it offers a robust branch cleanup tool that builds on Git's existing pruning patterns while adding new safeguards against accidental data loss. The `--dry-run` option in particular lets users verify the operation's behavior before executing deletions, rounding out the safety-focused approach that has characterized this multi-version effort. The feature appears ready for maintainer consideration.
