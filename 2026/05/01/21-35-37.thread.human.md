Harald Nordgren's `git branch --delete-merged` series is now in its 23rd and final version, fully implemented and ready for merging. The series introduces a new subcommand that safely automates local branch cleanup with comprehensive filtering and safety controls, including per-branch opt-out, `--dry-run` preview, and order-independent protection for branches used as upstreams.

The latest update (v23) contains only mechanical fixes to the first patch, addressing Junio C Hamano's final review comments. The rest of the series remains unchanged from v22, which Junio confirmed has no outstanding issues. The fourth patch in this series (now under discussion) prepares the existing branch deletion API for the new subcommand by adding a `DELETE_BRANCH_NO_HEAD_FALLBACK` flag. This ensures `--delete-merged` only deletes branches merged into their specified upstream, without falling back to `HEAD`. The change is minimal, touches only `builtin/branch.c`, and introduces no behavioral changes for existing callers.

Key features of the series include repeatable `--delete-merged` arguments to widen the upstream match, optional positional patterns to limit deletion scope, and stacked-branch protection that prevents deletion of branches used as upstreams for unmerged work. The implementation also includes a `--forked` filter foundation and per-branch opt-out via `branch.<name>.deleteMerged=false`. All planned features are complete, and the test suite covers edge cases like self-referential upstreams and missing upstreams. Junio has signaled the series is ready for merging, and it should appear in an upcoming "What's cooking" report. The only remaining work is a follow-up to extend stacked-branch protection to `git branch -d` for consistency.
