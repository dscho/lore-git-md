This is the final version of Harald Nordgren's `git branch --delete-merged` series, now fully polished and ready for Junio to merge. The series introduces a safe, automated way to clean up local branches that have been merged, with fine-grained controls to prevent accidental data loss.

The core command, `git branch --delete-merged`, deletes local branches that are fully merged into their upstream while preserving branches that are still needed—either because they're checked out, used as upstreams for unmerged work, or explicitly opted out via `branch.<name>.deleteMerged=false`. The safety net is robust: it handles chains of dependent branches (e.g., `b1→b2→b3`) by keeping only what's necessary and clearing stale upstream configs, and it refuses to touch branches that would break unmerged work. A `--dry-run` mode lets users preview what would happen without making changes.

Phillip Wood's feedback was instrumental in shaping the final design, particularly the "abort-and-clear" protection for stacked branches, which Junio endorsed as the right approach. The series also includes a `--forked` filter (composable with `--merged`/`--no-merged`) and support for limiting deletions to specific branches via arguments like `origin/next` or `topic/*`. All planned features are implemented, and the only remaining work is mechanical cleanup: replacing a few local boolean variables with flag checks in the deletion API and rejecting the nonsensical `--dry-run --quiet` combination. The test suite is thorough, covering edge cases like self-referential upstreams and missing push remotes, and now uses consistent helpers like `git for-each-ref` for verification.

Harald has addressed every review suggestion, and the series is now implementation-complete. It’s a well-scoped addition that complements existing Git workflows while adding much-needed safety for iterative topic branch management.
