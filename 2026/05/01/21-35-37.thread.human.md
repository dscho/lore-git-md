This thread is about the final version (v21) of Harald Nordgren's `git branch --delete-merged` series, which is now ready to be merged. The series adds a safe, automated way to clean up local branches that have been merged into their upstream, with multiple safety mechanisms and filtering options.

The implementation is complete, with all planned features—including per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview, and order-independent stacked-branch protection—now working correctly. The only change since v20 is a mechanical adjustment to prevent a CI timeout, with no functional impact. Junio C Hamano, the maintainer, has confirmed there are no remaining issues and asked if the series is "pretty much done," signaling it’s ready for inclusion. The only follow-up work is extending stacked-branch protection to `git branch -d` for consistency, which Harald has agreed to implement after the series lands.

Phillip Wood provided key feedback on the design, particularly the stacked-branch protection logic, which was refined to ensure consistent behavior regardless of branch iteration order. His review also helped shape the flags-based API and test improvements. The series has been thoroughly tested, covering edge cases like self-referential upstreams, missing upstreams, and push divergence. It touches `builtin/branch.c`, `ref-filter.c`, documentation, and the test suite, and is well-aligned with Git’s API consistency expectations. Expect this to appear in Junio’s "What’s cooking" report soon.
