Harald Nordgren’s `git branch --delete-merged` series is now complete and ready for merging, with all planned features implemented and no outstanding issues. The series introduces a safe, automated way to clean up local branches that have been merged into their upstream, with robust filtering and multiple safety mechanisms.

The core command, `git branch --delete-merged`, supports repeatable upstream selectors (e.g., `--delete-merged origin/main --delete-merged origin/next`) and optional positional patterns (e.g., `topic-*`) to precisely control which branches are deleted. Safety checks include protection for checked-out branches, branches with missing upstreams, and branches where pushing by name would update their upstream. A key innovation is **order-independent stacked-branch protection**, which ensures branches used as upstreams for unmerged branches are preserved, while stale upstream configurations are cleaned up for kept branches. This logic is now implemented via a single-pass graph traversal that guarantees consistent results regardless of ref iteration order.

Additional safeguards include a **per-branch opt-out** via `branch.<name>.deleteMerged=false` and a `--dry-run` preview mode that shows exactly which branches would be deleted or skipped without making any changes. The `--dry-run` implementation was finalized in the latest patch, which adds the `DELETE_BRANCH_DRY_RUN` flag and ensures config modifications are avoided during dry runs. Phillip Wood and Junio C Hamano have reviewed the series, with Junio explicitly confirming there are no remaining blockers and asking whether the topic is "pretty much done." The series will appear in an upcoming "What’s cooking" report, and a follow-up is planned to extend the stacked-branch protection to `git branch -d` for consistency.
