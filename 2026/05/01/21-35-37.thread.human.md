Harald Nordgren’s `git branch --delete-merged` series is now in its final v18 iteration, fully implemented and ready for merging once a minor technical fix is applied. The series introduces a new `--delete-merged` command for safe automated local branch cleanup, with comprehensive filtering and safety controls. Key features include the `--forked` filter for branch selection, per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview, and refined stacked-branch protection that aborts deletion if a branch is used as an upstream for an unmerged branch while clearing stale upstream configs for kept branches.

The core command and all safety mechanisms—checked-out branches, missing upstreams, push divergence, per-branch opt-out, and stacked-branch protection—are implemented and tested. The series also refactors the branch deletion API to use flags instead of boolean arguments, improving extensibility. Phillip Wood’s review has been instrumental in shaping the design, particularly the stacked-branch protection and flags-based API. His latest feedback identifies a maintenance risk in the flags handling: the patches split the `flags` variable into local booleans, creating two sources of truth. He recommends replacing all local boolean uses with direct flag checks (e.g., `flags & DELETE_BRANCH_SKIP_UNMERGED`) to avoid future regressions. This is a straightforward fix that does not affect functionality or the series’ readiness for merging.

Harald has addressed all prior feedback, including Phillip’s style suggestions, and the only remaining task is this flags maintenance fix.
