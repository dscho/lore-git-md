This thread is about the final version (v24) of Harald Nordgren's `git branch --delete-merged` series, which is now ready for merging. The series introduces a safe, automated way to clean up local branches that have been merged into their upstream, with robust filtering and safety controls.

Key features include order-independent stacked-branch protection (which now simplifies to protect only direct upstreams of surviving branches while clearing stale configs), per-branch opt-out via `branch.<name>.deleteMerged=false`, a `--dry-run` preview mode that avoids modifying config, and repeatable `--delete-merged` arguments to widen upstream matches. The v24 update fixed two critical issues: the push-detection logic to correctly handle `remote.pushDefault` configurations, and the stacked-branch protection to align with the design goal.

Both Junio C Hamano and Phillip Wood have confirmed the series is ready for merging after reviewing the v24 fixes. The only remaining feedback is a minor test formatting nit, which is unlikely to block progress. The series is expected to land in Junio's `next` branch soon. Harald has also agreed to extend the stacked-branch protection to `git branch -d` as a follow-up after this series is merged. The implementation is well-tested, with comprehensive coverage of edge cases, and aligns with Git's API consistency expectations.
