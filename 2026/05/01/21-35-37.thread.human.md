Harald Nordgren's `git branch --delete-merged` series is now complete and ready for merging. This feature enables safe automated cleanup of local branches that have been merged into their upstream, with multiple layers of safety and control. The series has evolved through 23 versions, incorporating feedback from Junio C Hamano and Phillip Wood to address correctness, consistency, and usability concerns.

The core command, `git branch --delete-merged`, deletes local branches that are fully merged into one of the specified upstreams (e.g., `--delete-merged origin/main --delete-merged origin/next`). It includes several safety mechanisms: it skips checked-out branches, preserves branches used as upstreams for unmerged work, respects per-branch opt-out via `branch.<name>.deleteMerged=false`, and provides a `--dry-run` mode to preview changes. The stacked-branch protection logic ensures consistent results regardless of the order in which branches are processed, addressing a key correctness issue raised during review.

The latest update, version 23, contains only mechanical fixes to the first patch in the series, resolving a type mismatch and a style nit identified by Junio. The rest of the series is unchanged from version 22, which Junio confirmed has no outstanding issues. Phillip Wood's feedback has been instrumental in shaping the final design, particularly the flags-based API and the order-independent stacked-branch protection. The series is now unblocked, with all planned features implemented and thoroughly tested. Junio has signaled it is ready for merging, and it should appear in an upcoming "What's cooking" report. A follow-up to extend the stacked-branch protection to `git branch -d` is planned but not a blocker for this series.
