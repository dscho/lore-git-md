This thread delivers the final version (v20) of Harald Nordgren’s `git branch --delete-merged` series, which is now **implementation-complete and unblocked for merging**. The series adds a safe, automated local-branch cleanup command with fine-grained filtering and multiple safety mechanisms: per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview, and **order-independent stacked-branch protection**—the last of which was the sole remaining correctness concern.

The key development in this update is the resolution of the order-dependency issue in stacked-branch protection. The previous two-phase approach (marking spared branches during iteration, then clearing their upstreams) could produce inconsistent results depending on ref iteration order. Harald Nordgren’s v20 refactor replaces this with a **single-pass graph traversal** (`collect_stacked_branch_bases()`) that collects all protected branches before any deletions occur, ensuring deterministic behavior. This addresses Junio C Hamano’s blocking concern, and the series is now ready for merging. The only agreed follow-up is extending stacked-branch protection to `git branch -d` for consistency, which will be implemented post-merge.
