Harald Nordgren’s `git branch --delete-merged` series, now in its sixteenth iteration, is nearing completion. The feature introduces safe automated cleanup of local branches with fine-grained control: `--forked` filtering to select branches, multiple safety mechanisms (checked-out branches, missing upstreams, push divergence, and per-branch opt-out via `branch.<name>.deleteMerged`), and a `--dry-run` preview mode. The series has resolved its last major design question—how to handle branches used as upstreams for other unmerged branches (e.g., `feature1` if `feature2` stacks on it). Junio C Hamano and Phillip Wood now agree these must be preserved to avoid breaking `@{u}` references and implicit `git rebase` workflows.

The implementation is feature-complete, with core deletion logic, safety checks, and test coverage in place. The stacked-branch protection is the final piece; Junio’s latest email proposes two user-facing approaches: abort the deletion with a clear error message, or automatically retarget the dependent branch’s upstream to the branch that merged the deleted one (e.g., `origin/master`). Junio leans toward the former as the default, with retargeting as an optional flag. Harald will implement this in the next iteration (v17), after which the series should be ready for final review. The feature builds on familiar patterns like `fetch.prune` but adds new safety-focused capabilities tailored for iterative topic branch workflows.
