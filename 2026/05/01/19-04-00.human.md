This is a bugfix patch for Git's HTTP proxy handling. The patch addresses a case where Git would silently accept proxy URLs with unsupported schemes (like "htpp://" instead of "http://") by only extracting the host portion and passing that to libcurl. The fix explicitly rejects such malformed URLs while maintaining backward compatibility with the existing host:port format.

The patch comes with test coverage in t5564-http-proxy.sh to verify the new rejection behavior. The change is focused and well-motivated, clearly identifying both the current incorrect behavior and the proposed solution. The implementation touches the http.c file to add the scheme validation logic while preserving the existing host:port parsing path.

This appears to be a straightforward improvement that closes a potential source of confusion when configuring HTTP proxies. The patch maintains the existing behavior for valid inputs while adding proper validation for invalid ones. The test addition suggests the author has considered how to prevent regression of this behavior in the future.
