Feature: New config option for pruning local branches when their upstream remote-tracking refs are deleted.

Harald Nordgren proposes a new `fetch.pruneBranches` configuration option (with corresponding command-line `--prune-branches` and per-remote `remote.<name>.pruneBranches` variants) that automatically deletes local branches when their upstream remote-tracking refs are pruned. This helps clean up topic branches after their upstream counterparts have been merged and deleted.

The option offers three modes:
- `false` (default): No change to current behavior
- `safe`: Delete local branches whose tips are reachable from the upstream tip (preserving unpushed work)
- `force`: Delete unconditionally (unpushed work only recoverable via reflog)

The currently checked-out branch is always preserved regardless of mode. The patch includes thorough documentation and test coverage demonstrating the different behaviors and configuration precedence rules. The implementation handles the common case where a branch was pushed and then merged upstream (via squash or rebase), while protecting against accidental data loss for branches with local work.

This appears to be a well-considered addition that could help automate branch cleanup workflows. The careful distinction between "safe" and "force" modes provides flexibility while maintaining safety defaults. The implementation builds on existing pruning infrastructure and follows Git's configuration patterns.
