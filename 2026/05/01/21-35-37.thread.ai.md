Thread identity: Proposal for new `fetch.pruneBranches` functionality via composable `git branch` plumbing commands in v3 series, authored by Harald Nordgren with maintainer feedback from Junio C Hamano.

Core problem/goal: Automating local branch cleanup when upstream branches are deleted while preserving unpushed work. The v3 series implements decomposed design with standalone branch plumbing now complete with bulk deletion improvements, `--all-remotes` convenience flag, `fetch --prune-merged` integration, and per-branch opt-out configuration while leaving the `--prune-merged` naming concern unresolved.

Key technical details:
- Core plumbing commands:
  - `git branch --forked <remote>`:
    - Lists local branches tracking specified remote(s)
    - Uses efficient `refs_for_each_branch_ref()` scan
    - `git branch --prune-merged <remote>`:
    - Push ref existence checking via `branch_get_push`
    - Reachability checks for unpushed work (default)
    - Checked-out branch protection across all worktrees
    - Per-branch opt-out via `branch.<name>.pruneMerged=false`
- New in v3:
  - Bulk deletion improvements with `warn_only` parameter
  - `--all-remotes` flag for both commands (new in final patch)
  - `fetch --prune-merged` integration:
    - Only operates on configured remotes
    - Runs after successful fetch
    - Preserves checked-out branches
  - Per-branch opt-out configuration
  - Documentation using "remote-tracking branches" consistently
- Safety mechanisms:
  - Default reachability check prevents data loss
  - Checked-out branch protection
  - Per-branch opt-out configuration
  - Explicit deletion via `git branch -d` bypasses opt-out

Current status: v3 series now complete with all planned functionality including final `--all-remotes` convenience flag while deferring resolution of Johannes Sixt's naming concern about `--prune-merged` potentially misleading users about upstream-based behavior rather than commit reachability.
