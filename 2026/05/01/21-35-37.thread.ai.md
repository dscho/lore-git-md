Thread identity: Proposal for new `fetch.pruneBranches` functionality, now implemented via composable `git branch` plumbing commands in v2 series, authored by Harald Nordgren with maintainer feedback from Junio C Hamano.

Core problem/goal: Automating local branch cleanup when upstream branches are deleted while preserving unpushed work. The v2 series shifts from direct fetch integration to a decomposed design with standalone branch plumbing commands following Junio's architectural feedback.

Key technical details:
- New plumbing commands:
  - `git branch --forked <remote>`: lists local branches tracking given remote (now with detailed implementation in first patch)
    - Accepts remote names or specific remote-tracking refs
    - Multiple arguments unioned
    - Uses efficient `refs_for_each_branch_ref()` scan
  - `git branch --prune-merged <remote>`: deletes local branches whose tips are reachable from upstream
  - `--force` skips reachability check (unpushed work only recoverable via reflog)
  - `--all-remotes` operates across all configured remotes
- Safety mechanisms:
  - Always preserves checked-out branch
  - Per-branch opt-out via `branch.<name>.pruneMerged=false`
- Integration:
  - `fetch --prune-merged` will call the new plumbing commands
  - Simplified configuration via per-branch opt-out rather than global modes
