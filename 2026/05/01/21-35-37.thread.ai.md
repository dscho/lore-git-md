Thread identity: Proposal for new `fetch.pruneBranches` functionality, implemented via composable `git branch` plumbing commands in v2 series, authored by Harald Nordgren with maintainer feedback from Junio C Hamano.

Core problem/goal: Automating local branch cleanup when upstream branches are deleted while preserving unpushed work. The v2 series implements a decomposed design with standalone branch plumbing commands following Junio's architectural feedback, now completed with `fetch --prune-merged` integration, per-branch opt-out configuration, and new `--all-remotes` convenience flag, with new discussion about flag naming semantics.

Key technical details:
- New plumbing commands:
  - `git branch --forked <remote>`: lists local branches tracking given remote (patch 1/6)
    - Accepts remote names or specific remote-tracking branches (updated terminology per Kristoffer Haugsbakk's review)
    - Multiple arguments unioned
    - Uses efficient `refs_for_each_branch_ref()` scan
    - New `--all-remotes` flag processes all configured remotes
  - `git branch --prune-merged <remote>`: core functionality (patch 3/6)
    - Push ref existence checking via `branch_get_push`
    - Reachability checks for unpushed work (default)
    - `--force` override for reachability checks
    - Checked-out branch protection across all worktrees
    - Uses `collect_forked_set` from patch 1/6 and `delete_branches()` infrastructure
    - New `--all-remotes` flag processes all configured remotes
    - New naming concern raised by Johannes Sixt: "merged" may imply commit reachability when actual behavior checks upstream status
- New `fetch --prune-merged` integration:
  - Automates `git branch --prune-merged` post-fetch
  - Only activates for configured remotes (not direct URLs)
  - Fails if pruning fails after successful fetch
  - Maintains all safety checks from underlying branch command
- Safety mechanisms:
  - Always preserves checked-out branch (multi-worktree aware)
  - New per-branch opt-out via `branch.<name>.pruneMerged=false`
    - Overrides even `--force` pruning
    - Preserves explicit `git branch -d` behavior
    - Generates clear warning output when skipping
  - Default reachability check prevents data loss
- `--all-remotes` implementation:
  - Processes all configured remotes via `for_each_remote()`
  - Combines with explicit remote arguments
  - Rejects standalone use without primary operation
  - Full test coverage for multi-remote scenarios

Current status: v2 series now complete with all planned functionality but facing new naming concern from Johannes Sixt regarding potential confusion between "merged" terminology and actual upstream-based pruning behavior. Options under consideration:
1. Modify implementation to actually check merge status (like `git branch -d`)
2. Change flag name to better reflect upstream-based behavior
