Thread identity: Proposal for new `fetch.pruneBranches` config option to automatically delete local branches when their upstream remote-tracking refs are pruned, authored by Harald Nordgren.

Core problem/goal: Currently, `git fetch --prune` removes remote-tracking branches but leaves corresponding local branches, requiring manual cleanup. This feature would automate local branch cleanup when upstream branches are deleted, with configurable safety levels.

Key technical details:
- New configuration options:
  - `fetch.pruneBranches` (main config)
  - `remote.<name>.pruneBranches` (per-remote override)
  - `--prune-branches` CLI flag
- Three modes:
  - `false`: Default, no change
  - `safe`: Delete local branches only if their tips are reachable from upstream tip (preserves unpushed work)
  - `force`: Unconditionally delete (unpushed work recoverable only via reflog)
- Always preserves currently checked-out branch
- Thorough test coverage in t/t5510-fetch.sh demonstrating behavior
- Documentation in Documentation/config/fetch.txt

Implementation notes:
- Builds on existing fetch/prune infrastructure
- Handles common case of branches pushed then merged upstream (squash/rebased)
- Follows Git's configuration precedence patterns
- Includes protection against accidental data loss
