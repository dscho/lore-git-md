This is version 2 of a feature series introducing a new `git url-parse` builtin command that exposes Git's internal URL parsing logic as a plumbing command. The series has been refined based on feedback from the initial submission.

The command allows scripts and tools to reliably parse Git's various URL formats (including non-standard ones like SCP-style URLs) by using Git's own parsing logic rather than reimplementing it. Key improvements in v2:

- Renamed `protocol` to `scheme` throughout for RFC compliance
- Added better error messages for local paths (suggesting `file://` format)
- Fixed handling of `~user` paths with query strings/fragments
- Expanded test coverage with IPv6 and SCP-style URL cases
- Improved documentation with clearer examples and output behavior
- Collapsed some preparatory commits into more cohesive units
- Added unit tests for the URL parsing logic

The series now consists of 8 patches:
1. Renames internal enum for consistency
2. Moves URL helper functions to shared location
3-4. Refactors scheme detection to be more cases
5. Implements core URL parsing function
6. Adds the `url-parse` builtin command
7. Documents the new command
8. Adds comprehensive tests

The implementation looks solid, with thorough test coverage (319 lines of tests) and clear documentation. The use case - enabling reliable URL parsing by external tools - is well-motivated. This appears ready for review, particularly from contributors familiar with Git's URL handling code.
