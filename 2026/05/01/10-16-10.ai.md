This is a substantive technical review by Phillip Wood of Kristoffer Haugsbakk's proposed `git format-rev` command (patch 5/5 in the v3 series). The review focuses on edge cases and potential pitfalls in the command's design, particularly around input/output handling.

Phillip identifies two key concerns with the current implementation:

1. **Stream processing limitations**: The command currently lacks clear delimiters between input messages and their corresponding output, which could cause problems for single-process use cases where a program both writes to and reads from the command. Phillip notes this is particularly problematic for formats that produce variable-length output (e.g., trailers) and for multi-line revision names.

2. **Deduplication behavior**: While the patch correctly handles duplicate input commits (unlike `git log`/`git show`), Phillip suggests the documentation should more clearly explain the streaming behavior difference from those commands.

The review also catches a minor typo ("massagge" -> "message") and provides context about why this functionality is better implemented as a new command rather than extending `git name-rev`.

His review will likely require revisions to both the implementation (to add proper message delimiters) and documentation (to clarify streaming behavior).
