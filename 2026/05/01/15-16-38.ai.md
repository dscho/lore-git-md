This is a refactoring patch that factors out sequencer todo command parsing logic into a reusable function. Phillip Wood extracts the command parsing code from `parse_insn_line()` into a new `sequencer_parse_todo_command()` function in sequencer.c, making it available via sequencer.h for use by other code (specifically the status display fixes in patch 2 of this series).

The refactoring introduces two subtle behavior changes that were identified and discussed in review: it reverses the order in which commands vs comments are checked (now trying commands first), and it handles bare carriage returns more strictly (treating them as invalid rather than comments). Elijah Newren confirmed these changes are intentional and sound, suggesting they be documented in the commit message. The implementation demonstrates careful attention to edge cases while maintaining the overall parsing behavior.

The patch is part of a larger effort to improve `git status` display during interactive rebase by sharing parsing logic between the sequencer and status code. It touches sequencer.c (moving the parsing logic) and sequencer.h (exporting the new function), with no user-visible behavior changes yet - those come in the follow-up patch that builds on this refactoring. The changes have been reviewed by domain experts and all technical questions resolved.
