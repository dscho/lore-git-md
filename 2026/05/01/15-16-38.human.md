This is the first patch in a two-part bugfix series improving `git status` display during interactive rebase. Phillip Wood factors out the sequencer's todo command parsing logic into a new `sequencer_parse_todo_command()` function, making it reusable by other code (specifically the status display logic in the next patch).

The refactoring intentionally changes two subtle parsing behaviors: it now handles bare carriage returns differently (treating them as invalid rather than comments) and reverses the order in which commands vs comments are checked. Elijah Newren reviewed these changes and confirmed they're sound, suggesting only minor documentation improvements which Phillip has incorporated.

The patch is a clean refactoring with no behavior changes beyond those explicitly noted. It moves parsing logic from `parse_insn_line()` to the new function while maintaining the same interface. The changes enable sharing this parsing with the display code in `wt-status.c` in the following patch. As Phillip is a recognized expert on Git's sequencer and rebase machinery, this refactoring comes with high confidence in its correctness.
