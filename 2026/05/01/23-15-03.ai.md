This is the first patch in an 8-part series introducing a new `git url-parse` builtin command, focused on refactoring Git's URL parsing internals. The series aims to expose Git's URL handling logic as a reusable plumbing command.

This specific patch performs a mechanical rename of the `enum protocol` to `enum url_scheme` and related functions/variables to align with RFC 1738 terminology. The change was suggested by Torsten Bögershausen in the v1 review. The patch maintains all existing behavior while making the code more semantically accurate - "scheme" is the correct term for the part of a URL before the colon (like "https" or "git").

Key technical changes:
- Renames `protocol` to `url_scheme` throughout connect.c
- Updates all related function names (`prot_name` -> `url_scheme_name`, `get_protocol` -> `url_get_scheme`)
- Preserves existing diagnostics and error messages for compatibility
- No functional changes - this is purely a naming improvement

The patch is well-contained and clearly motivated by the RFC standard. It serves as groundwork for later patches that will move these URL parsing helpers to shared files where they can be used by both the connect code and the new url-parse command. The change demonstrates good attention to review feedback from v1 of the series.
