This is version 2 of a feature series introducing a new `git url-parse` builtin command. The command provides plumbing to expose Git's internal URL parsing logic, allowing scripts to reliably parse Git's various URL formats (including non-standard ones like SCP-style URLs).

Key changes in v2:
- Renamed enum protocol to url_scheme for RFC alignment
- Moved URL parsing helpers from connect.c to new url.[ch] files
- Added url_parse() function in urlmatch.[ch] with same interface as url_normalize()
- Improved error messages for local paths
- Renamed -c protocol to -c scheme for consistency
- Added comprehensive documentation and tests (now 53 tests covering all URL types)
- Fixed handling of ~user paths with query strings/fragments
- Added IPv6 support in both URL and SCP formats
- Improved handling of bracketed hostnames in SCP syntax

The series appears well-structured with logical progression from internal refactoring to the new command implementation. The test coverage is thorough, validating parsing behavior across all URL types. This could be useful plumbing for tooling that needs to interact with Git repositories programmatically.

Notable technical details:
- Uses url_info struct consistently across parsing functions
- Returns components as offset/length pairs into normalized URL buffer
- Deliberately diverges from parse_connect_url in handling local paths
- Includes unit tests for SCP-style URL parsing
- Handles IPv6 addresses in both bracketed and unbracketed forms

The implementation looks clean and the use case is clearly motivated. The series seems ready for review, particularly from contributors familiar with Git's URL handling code.
