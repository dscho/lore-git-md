Thread identity: Discussion on improving `git log --follow`'s handling of merge commits, particularly subtree merges, focusing on rename detection when files are added in one parent but renamed in another.

Core problem: Current `--follow` behavior struggles with merge commits where a path is added in one parent and renamed in another, often failing to track renames across such merges. The goal is to better handle these cases without regressing other scenarios.

Key technical details: The patch focuses on `builtin/log.c`'s `--follow` implementation, specifically the logic for choosing which merge parent to follow. The distinction between "added vs parent" (considered uninteresting) versus actual content changes is central to the proposed solution.

Open questions: Whether Miklos's adjusted approach sufficiently addresses Jeff's concerns about being too strict with TREESAME while handling subtree merge cases. Jeff's feedback is pending on whether this seems like a reasonable direction.
