This is a feature request regarding the `git history` command's handling of commit signatures. 

Alix Brunet points out that while `git rebase` has a `-S` option to preserve or re-sign commits during rewriting, the newer `git history` command currently drops signatures entirely. The email asks whether signature preservation will be implemented for `git history` in the future.

The question appears to be a straightforward inquiry about planned functionality rather than a bug report. The tone is polite and the observation seems valid - signature preservation is indeed a feature users might reasonably expect to be consistent across similar Git commands that rewrite history. 

Since this is the first message in the thread, we don't yet know how maintainers or other contributors will respond regarding whether this is a deliberate design choice or an oversight in the command's implementation. The `git history` command is relatively new (added in 2025 by Patrick Steinhardt), so it's plausible that signature handling simply hasn't been prioritized yet.
