This thread is about a four-patch series (now at v6) that refactors two core configuration flags—`trust_executable_bit` and `has_symlinks`—to eliminate their reliance on the global `the_repository` variable, completing a key phase of Git’s ongoing `the_repository` removal effort. The series is authored by Tian Yuchen and targets Git’s index-handling and configuration plumbing.

The earlier v4 iteration, which migrated only `trust_executable_bit`, was merged into `master` after a smooth review. The current v6 iteration reintroduces the previously deferred `has_symlinks` migration and resolves a design-level objection from Junio C Hamano about the mingw compatibility layer’s use of a global fallback variable. The solution adopts Junio’s proposed pattern: replacing the global with a compile-time macro (`platform_has_symlinks()`) and a platform-specific function (`mingw_platform_has_symlinks()`), modeled after existing Git conventions like `is_dir_sep()`. The series remains under active review, with no indication of movement to `next` or `master`.

The second patch in the v6 series, summarized here, is a preparatory cleanup that moves the `ce_mode_from_stat()` helper from `read-cache.h` to `read-cache.c`. This relocation is necessary to allow future repository-scoped configuration access without exposing internal dependencies in the header. The change is mechanical, uncontroversial, and received no objections in prior iterations. It also removes redundant `extern` declarations and adds a clarifying comment, but introduces no behavioral changes. The patch is well-scoped and unlikely to attract further discussion, serving as a prerequisite for the core migrations in later patches.

Key participants include Tian Yuchen (author), Junio C Hamano (maintainer, provided design feedback), Christian Couder (reviewed commit messages), and Patrick Steinhardt (reviewed documentation placement). The series demonstrates incremental progress in the `the_repository` removal effort while establishing patterns for future configuration migrations. The mingw compatibility adjustments may still draw attention from platform-specific contributors, but the current design aligns with Git’s existing conventions.
