Tian Yuchen's series to migrate the `trust_executable_bit` configuration from global to repository-scoped storage is now complete and ready for merging. This 3-patch series is part of the ongoing effort to eliminate Git's reliance on the `the_repository` global variable. 

The final patch moves `trust_executable_bit` into `struct repo_config_values` and introduces a new `repo_trust_executable_bit()` getter function that maintains backward compatibility by falling back to `the_repository` when needed. All call sites have been updated to use the repository-scoped accessor, while preserving the eager parsing behavior important for performance. The changes are mechanical and behavior-preserving, touching core index handling code in `read-cache.c` and configuration plumbing.

Christian Couder provided final documentation polish, catching minor wording issues in the getter's description. The series has been mentored by Christian Couder along with Ayush Chandekar and Olamide Caleb Bello, with all technical feedback incorporated. Junio C Hamano has confirmed the series is ready for merging after the final reroll. 

While this series successfully handles `trust_executable_bit`, the more complex `has_symlinks` migration has been deferred for future work. The completed changes demonstrate a practical pattern for incrementally migrating configuration variables while maintaining compatibility, representing another step forward in removing global state from Git's codebase.
