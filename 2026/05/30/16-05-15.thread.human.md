This thread is about a 4-patch series (v5) by Tian Yuchen that refactors Git’s `trust_executable_bit` and `has_symlinks` configuration flags to be repository-scoped rather than global, completing a key step in the ongoing effort to remove the `the_repository` global variable. The earlier v4 iteration, which handled only `trust_executable_bit`, was merged to `master` after a smooth review, but v5 reintroduces the previously deferred `has_symlinks` migration and is now under active review.

The series is mechanical—no behavioral changes—but Junio C Hamano’s latest review of the final patch (4/4) raises a design concern about the mingw compatibility layer. The current implementation uses a global fallback variable (`default_has_symlinks`), which Junio warns could encourage misuse elsewhere in the codebase. Instead, he proposes a cleaner pattern using a compile-time macro (`platform_has_symlinks()`) that platforms like mingw can override, aligning with Git’s existing conventions for platform-specific logic. This feedback doesn’t block the series but suggests a revision to avoid technical debt.

Otherwise, the series has strong support: Christian Couder explicitly approved the approach (with a minor commit message nit), and v4’s review included substantive feedback from Patrick Steinhardt and others. The new getter functions (`repo_has_symlinks()` and `repo_trust_executable_bit()`) establish a pattern that may guide future configuration migrations. The author has also flagged potential follow-ups, like reducing `istate` passing, but these are deferred. For now, the focus is on addressing Junio’s mingw feedback before the series can move forward.
