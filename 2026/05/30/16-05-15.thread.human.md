This thread is about a 4-patch series (v7) from Tian Yuchen that refactors two core configuration flags—`trust_executable_bit` and `has_symlinks`—to be repository-scoped as part of the ongoing effort to remove the `the_repository` global variable. The series is nearly ready for inclusion, with all prior design and editorial feedback addressed, but a new issue has surfaced.

The latest email is a substantive review from SZEDER Gábor, who caught a build-breaking problem in the second patch: the newly added `struct repository *repo` parameter to `ce_mode_from_stat()` is unused in this patch, triggering `-Werror=unused-parameter` under `DEVELOPER=1` and causing compilation failures across multiple files. This is a blocking issue for integration, though the fix is straightforward—mark the parameter as `UNUSED` in this patch and remove the annotation in the next one, where the parameter is actually used. The problem doesn’t challenge the series’ design or correctness but is a process-level oversight that could derail progress if left unaddressed.

The series itself has evolved through seven iterations, with the fourth version (migrating only `trust_executable_bit`) already merged to `master`. The current v7 reintroduces the `has_symlinks` migration, resolves Junio’s prior objections (including a design change to eliminate a global fallback variable in the mingw compatibility layer), and keeps `ce_mode_from_stat()` as a `static inline` function in `read-cache.h` with a repository parameter. Junio’s latest feedback on v7 was low-weight—stylistic and defensive-programming questions about formatting and NULL checks—but SZEDER’s review now takes precedence as it identifies a concrete integration blocker. The series remains uncontroversial and is likely to proceed once this issue is fixed.
