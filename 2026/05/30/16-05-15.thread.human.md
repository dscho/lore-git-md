This thread is about the seventh iteration of a four-patch series by Tian Yuchen that refactors two core configuration flags—`trust_executable_bit` and `has_symlinks`—to be repository-scoped rather than global. The work is part of the long-running effort to remove Git’s `the_repository` global variable. The earlier v4 of this series (which handled only `trust_executable_bit`) was merged to `master` without controversy, but v5 reintroduced `has_symlinks` and ran into design feedback from Junio Hamano about mingw compatibility. That feedback was resolved in v6, only for Junio to raise a new concern about the relocation of a helper function, `ce_mode_from_stat()`. The v7 iteration addressed all prior feedback but introduced a build-breaking issue: the newly added `struct repository *` parameter to `ce_mode_from_stat()` is unused in patch 2/4, triggering a compilation error under `DEVELOPER=1`.

SZEDER Gábor caught this in review and suggested marking the parameter as `UNUSED` in patch 2/4, then removing the annotation in patch 3/4 where the parameter is actually used. Tian has now replied with a minimal fix—casting the unused parameter to `void` with a `TODO` comment—since the `UNUSED` macro isn’t available in the header context. This is a straightforward process-level oversight, not a design flaw, and once fixed the series should be ready to proceed. Junio’s only remaining feedback on v7 was stylistic (formatting and a question about defensive NULL checks), neither of which blocks integration. The series is uncontroversial and likely to land in `next` once the build issue is resolved.
