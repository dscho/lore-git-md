This thread is about a 4-patch series (now at v6) that refactors Git's `trust_executable_bit` and `has_symlinks` configuration flags to be repository-scoped rather than global, completing the last phase of the `the_repository` removal effort for these index-related settings. The series is authored by Tian Yuchen and has been under active review for several iterations.

The v4 iteration (which migrated only `trust_executable_bit`) was merged to `master` after a smooth review period. The v5 iteration reintroduced the `has_symlinks` migration but ran into a design-level objection from Junio C Hamano regarding the mingw compatibility layer's use of a global fallback variable. The v6 iteration resolves this by adopting Junio's proposed design: replacing the global variable with a compile-time macro (`platform_has_symlinks()`) and a platform-specific function (`mingw_platform_has_symlinks()`), modeled after existing Git platform-compatibility patterns like `is_dir_sep()`. This change eliminates mutable global state while preserving the ability to detect native symlink support via environment variables.

The series is now uncontested, with all substantive review feedback addressed. Patches 1 and 2 are preparatory cleanups (removing redundant declarations and relocating a function), while patches 3 and 4 implement the core migrations. The migration pattern established here—moving global configuration flags into `struct repo_config_values` with repository-scoped getters—may serve as a template for future configuration refactoring efforts. The mingw adjustments could attract attention from platform maintainers like Johannes Schindelin, but the design is now settled. The series appears ready for final review and likely inclusion in Junio's `next` branch.
