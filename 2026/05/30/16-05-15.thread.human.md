This thread is about a 4-patch series (now at v8) from Tian Yuchen that refactors two core configuration flags—`trust_executable_bit` and `has_symlinks`—to be repository-scoped rather than global. This is part of the broader effort to eliminate Git’s `the_repository` global variable, a long-running cleanup project led by René Scharfe.

The series has been through several iterations, with the v4 version (which handled only `trust_executable_bit`) already merged to `master`. The current v8 iteration reintroduces the previously deferred `has_symlinks` migration and addresses all prior feedback, including design concerns from Junio C Hamano and a build-breaking issue spotted by SZEDER Gábor. The latest changes are minor: removing redundant `extern` declarations, reformatting a ternary expression for clarity, and dropping defensive NULL checks to match Junio’s preference for crashing on bugs rather than masking them.

The technical work is now complete, with all call sites updated to pass a repository pointer and the mingw compatibility layer settled. The series is uncontroversial and likely to proceed to Junio’s `next` branch soon. No open questions remain, though Tian has suggested a follow-up to further reduce `istate` passing and possibly update another helper (`repo_protect_ntfs`) to match the stricter NULL-crashing pattern. Reviewers have been thorough, with Junio and SZEDER Gábor providing substantive feedback that’s since been addressed. The migration pattern established here may serve as a template for future configuration refactoring.
