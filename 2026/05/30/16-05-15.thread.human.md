This thread is about a 4-patch series from Tian Yuchen that refactors two core configuration flags—`trust_executable_bit` and `has_symlinks`—to be repository-scoped rather than global, completing a key step in the ongoing effort to eliminate Git’s `the_repository` global variable. The series has evolved through seven versions, with the fourth iteration (which handled only `trust_executable_bit`) already merged to `master`. The current v7 iteration reintroduces the `has_symlinks` migration, addresses all prior feedback, and is now uncontested and ready for inclusion.

The core work is mechanical but foundational: both flags are moved into `struct repo_config_values`, new getter functions (`repo_has_symlinks()` and `repo_trust_executable_bit()`) are introduced, and call sites across the codebase are updated to use repository-scoped access. The mingw compatibility layer for `has_symlinks` was refactored to eliminate mutable global state, adopting a compile-time macro pattern that Junio C Hamano proposed and later approved. The only remaining discussion is stylistic—Junio’s latest feedback on v7’s third patch suggests minor formatting tweaks and a preference for crashing on NULL repository pointers rather than defensive checks—but this does not block progress.

Key participants include Tian (the author), Junio (who merged v4 and provided design feedback on v5–v6), and mentors Christian Couder, Ayush Chandekar, and Olamide Caleb Bello. The series is part of René Scharfe’s broader `the_repository` removal effort and establishes a pattern for future configuration migrations. With all substantive feedback resolved, the series is poised to move forward.
