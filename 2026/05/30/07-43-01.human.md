This is a documentation patch addressing Git's handling of small Unix timestamps, following up on a bug report about inconsistent parsing behavior. The patch documents the previously-undocumented `@` prefix syntax that forces Git to interpret a value as a raw timestamp, which is necessary for timestamps below 100,000,000 (pre-1973 dates) to avoid confusion with YYYYMMDD formats.

Junio C Hamano provides a suggested patch format that:
1. Adds clear documentation of the `@` prefix behavior in `date-formats.adoc`
2. Includes test cases demonstrating the difference between prefixed and unprefixed timestamps
3. References the original 2012 commits that introduced this feature

The patch cleanly addresses the documentation gap while leaving the underlying parsing inconsistency as a known issue. The test cases help prevent future regressions and serve as practical examples for users needing to work with very old timestamps. This is a common pattern in Git development - documenting existing behavior before considering whether to change it.
