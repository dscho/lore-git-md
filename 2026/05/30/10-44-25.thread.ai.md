Thread identity: Feature request regarding signature handling in `git history` command, initiated by Alix Brunet. Follow-up to ongoing `git history` development work led by Patrick Steinhardt.

Core problem: `git history` currently drops commit signatures during operation, unlike `git rebase` which preserves/re-signs commits via its `-S` flag. Request seeks consistency between these related commands' behavior regarding cryptographic signatures.

Current status: Patrick Steinhardt acknowledges the feature gap but indicates it's not currently a priority for his development focus. The `git history` command remains in development without signature preservation, though the maintainer explicitly invites community contributions to implement this.

Key details: 
- `git history` performs history rewriting operations similar to `git rebase`
- Current behavior strips GPG/SSH signatures during these operations
- `git rebase -S` provides precedent for signature preservation in similar contexts
- Implementation would likely follow similar patterns to `git rebase -S`'s signature handling

Open questions:
- Whether a community contributor will step forward to implement signature preservation
- Exact technical approach (new flag vs default behavior)
- Integration with existing `git history` code paths

Participant positions:
- Alix Brunet raised the feature request, citing consistency with `git rebase` as motivation
- Patrick Steinhardt acknowledges the validity but lacks bandwidth to prioritize it himself
- Patrick explicitly invites community contributions to address this gap

Related work:
- Original `git history` implementation series by Patrick Steinhardt
- GPG signature infrastructure used by `git rebase -S`
- Ongoing discussions around commit signing best practices in Git
