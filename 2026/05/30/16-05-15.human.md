This is a refactoring patch series that's part of the ongoing `the_repository` removal effort. Tian Yuchen proposes moving the `trust_executable_bit` configuration (which controls whether Git respects filesystem executable bits) from a global variable into the per-repository `repo_config_values` struct.

The series makes several mechanical changes to support this:
1. Cleans up redundant extern declarations in read-cache
2. Moves `ce_mode_from_stat()` to read-cache.c where it's primarily used
3. Actually migrates `trust_executable_bit` to be repository-specific
4. Updates helper functions to accept `struct index_state*` rather than implicitly using the global state

The motivation is to eliminate another use of global state in preparation for removing `the_repository`. The author notes this is groundwork - while the change makes the code repository-aware, the implementation still only works with `the_repository` for now. The series references previous attempts to move this configuration that chose different structs, with this version selecting `repo_config_values` as the better home.

The changes appear focused and well-scoped, touching only the necessary files to maintain the same behavior while making the state repository-specific. The commit messages reference prior discussion and justify the design choices. This looks like solid incremental progress on the larger `the_repository` removal effort.
