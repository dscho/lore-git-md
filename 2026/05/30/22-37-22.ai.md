This is a documentation follow-up in Kristoffer Haugsbakk's series standardizing `git replay` configuration. Junio C Hamano provides a substantive review of the patch that removed redundant ref-action mode details from the config documentation, replacing them with a cross-reference to the command documentation.

Junio notes that while the change is technically correct and follows standard documentation practices (using `ifdef::git-replay[]` for conditional linking), it makes it slightly harder for readers looking up `replay.refAction` in `git-config(1)` to quickly see the valid values. The modes ("update" and "print") are now only listed in the `git-replay(1)` man page under `--ref-action`. He acknowledges this isn't a blocking issue since the cross-reference makes the information discoverable, but flags it as a minor usability tradeoff.

The review confirms the technical approach is sound - the conditional linking infrastructure works as intended and the patch maintains documentation completeness while reducing duplication. This continues the pattern of Kristoffer's documentation work: precise, convention-following improvements that sometimes prioritize structural cleanliness over immediate convenience. Junio's feedback suggests the change is likely to be accepted as-is, with the usability observation noted for future consideration rather than requiring a rework.
