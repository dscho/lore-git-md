This is a refactoring patch series that's part of the ongoing `the_repository` removal effort. The goal is to migrate the `trust_executable_bit` configuration (which controls whether Git respects filesystem executable bits) from a global variable to being repository-scoped in `repo_config_values`.

The series makes several mechanical changes to support this:
1. Cleans up redundant extern declarations in read-cache
2. Moves `ce_mode_from_stat()` to read-cache.c where it's primarily used
3. Actually moves the `trust_executable_bit` variable into `repo_config_values`
4. Updates helper functions to take an `index_state` parameter rather than relying on globals

The work builds on previous attempts to scope this configuration properly, with the author noting that earlier approaches targeting `struct repo_settings` were deemed optimal. The changes touch core index and filesystem interaction code, modifying functions like `ce_mode_from_stat()` and `fake_lstat()` to explicitly pass state rather than using implicit globals.

This appears to be a well-structured preparatory series for the larger `the_repository` elimination effort, with each patch making incremental progress toward the goal. The author has clearly researched prior attempts at this refactoring and is working under mentorship from established contributors. The changes are focused and mechanical, with no behavior changes intended - just moving state management to be more explicitly scoped.
