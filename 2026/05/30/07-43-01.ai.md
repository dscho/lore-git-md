This is a documentation patch addressing Git's handling of small Unix timestamps, following up on a bug report about inconsistent parsing behavior. Junio C Hamano provides a suggested patch to document the `@` prefix workaround for specifying very old timestamps (like Unix epoch 0) that was introduced in 2012 but never documented.

The patch adds clear documentation in `date-formats.adoc` explaining that the `@` prefix forces Git to interpret the value as a raw timestamp, which is necessary for timestamps below 100,000,000 (9 digits) to avoid confusion with YYYYMMDD date formats. It also includes test cases in `t0006-date.sh` demonstrating the difference between prefixed and unprefixed small timestamps.

The patch cleanly addresses the documentation gap while leaving the underlying parsing inconsistency as a known issue. The test cases serve both to verify the current behavior and provide examples for users. This is a straightforward, well-contained improvement that follows the earlier discussion where Junio confirmed the `@` prefix was the intended solution for ancient timestamps.
