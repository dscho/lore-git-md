This is the fifth patch in Derrick Stolee's 7-part series integrating `--walk-path` with `--filter` options in `git pack-objects`. The series focuses on performance optimizations for sparse-checkout scenarios.

The current patch adds support for the `blob:limit=<size>` filter in the path-walk API, which excludes blobs larger than a specified size. Key technical aspects:

1. The filter implementation checks blob sizes via `odb_read_object_info()`, skipping blobs that meet or exceed the limit. Blobs with undetermined sizes (e.g. in partial clones) are conservatively included.

2. A special case (`blob:limit=0`) is optimized to behave identically to `blob:none` (excluding all blobs).

3. The patch adds validation in `git backfill` to reject blob size limits since they would trigger undesirable on-demand blob downloads.

4. New test cases verify both the zero-size limit case and partial filtering (keeping some blobs under the size threshold while excluding others).

The implementation maintains consistency with existing filter behavior while adding the new capability. The changes touch core path-walk logic, backfill validation, and test infrastructure. This continues the series' pattern of thorough test coverage and careful attention to edge cases.

As with previous patches, this builds on the path-walk infrastructure while maintaining backward compatibility. The performance implications for sparse-checkout scenarios remain a key consideration, though this particular filter's benefits may be more modest compared to the sparse filter optimizations shown earlier in the series.
