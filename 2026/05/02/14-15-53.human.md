This is the sixth patch in Derrick Stolee's series optimizing `git pack-objects` with path-walk and filter integration, focusing on sparse-checkout scenarios. The patch introduces finer control over tree pruning behavior when using sparse patterns.

The key change adds a `pl_sparse_trees` flag to the path-walk API that determines whether sparse patterns should prune both trees and blobs (when set) or just blobs (when unset). This enables different use cases:
- `git backfill --sparse` needs full tree pruning to only fill in-cone objects
- Future sparse filters will want to keep all trees while filtering blobs

The patch also fixes a subtle SEEN flag issue where identical objects at multiple paths could be incorrectly skipped if first seen outside the sparse cone. By moving the flag assignment after path checks, objects remain discoverable at in-cone paths.

Test coverage is expanded to verify both pruning modes, with new cases showing the difference in tree inclusion when `pl_sparse_trees` is disabled. The implementation maintains backward compatibility while providing the flexibility needed for upcoming filter types.

This continues the series' pattern of careful, well-tested changes to core path-walk behavior, with clear documentation of the tradeoffs. The changes are focused and maintainable, though the interaction between tree pruning and sparse filters may warrant review from sparse-checkout experts given the performance implications.
