This is the sixth patch in Derrick Stolee's series optimizing `git pack-objects` with path-walk and filter integration, focusing on sparse-checkout scenarios. The patch introduces finer control over tree pruning behavior in the path-walk API by adding a `pl_sparse_trees` flag. When enabled (as in `git backfill --sparse`), sparse patterns prune both trees and blobs. When disabled (for `sparse:<oid>` filter use), only blobs are filtered while all trees are walked.

Key technical aspects:
1. Moves SEEN` flag assignment after sparse/path checks to properly handle objects appearing at multiple paths (fixing a case where identical content in sibling directories could be incorrectly skipped)
2. Adds test coverage demonstrating the difference in behavior between tree-pruning and non-pruning modes
3. Maintains backward compatibility while enabling the upcoming sparse filter integration

The change is well-motivated by the series' goal of optimizing pack-objects for sparse-checkout cases, though it touches subtle path-walk behavior that may warrant review from sparse-checkout experts. The patch includes thorough test coverage of both the new flag and the SEEN flag timing change.
