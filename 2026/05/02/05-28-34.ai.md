This is version 3 of a feature series introducing a new `git url-parse` builtin command, providing plumbing to expose Git's internal URL parsing logic. The command allows scripts to reliably parse Git's various URL formats including non-standard ones like SCP-style URLs and IPv6 addresses.

Key changes in v3:
- Fixed Windows CI failure by handling DOS drive prefixes in the local-path error message
- Relaxed test assertion for absolute paths to be cross-platform compatible (checking for "file:///" structure rather than exact path)
- Maintained all other improvements from v2 including RFC-compliant naming, comprehensive documentation, and thorough test coverage

The series now includes:
1. Internal refactoring moving URL parsing helpers to dedicated files
2. New `url_parse()` function with same interface as `url_normalize()`
3. User-facing `git url-parse` command with helpful error messages
4. Complete documentation in man page format
5. 53 tests covering all URL types and edge cases

Notable technical decisions:
- Uses "scheme" terminology consistently per RFC standards
- Deliberately diverges from `parse_connect_url` in handling local paths
- Returns URL components as offset/length pairs into normalized buffer
- Includes comprehensive IPv6 and SCP-style URL support
- Provides clear error messages when input isn't a valid URL

The implementation appears robust with thorough test coverage across all supported URL formats. The Windows-specific fixes in v3 demonstrate attention to cross-platform concerns. This plumbing command could be valuable for tools needing to interact with Git repositories programmatically while correctly handling all Git URL variants.

With all prior feedback addressed and now including Windows compatibility fixes, this series appears ready for final review. The comprehensive test suite (319 lines across 53 tests) provides high confidence in the implementation's correctness.
