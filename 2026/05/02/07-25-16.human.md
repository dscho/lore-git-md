This is a technical follow-up in the thread about Git's rename detection behavior with Ruby files moved between namespaces. Johannes Sixt (Hannes) responds to Phillip Wood's earlier explanation and suggested workaround.

Hannes agrees with Phillip's technical analysis that indentation changes make the files appear too dissimilar for Git's rename detection, but points out a limitation in the proposed workaround. While splitting the change into two commits (move then modify) helps when comparing adjacent commits (like in `git log`), it doesn't solve the case when comparing commits across the entire change (before-move vs after-modify).

The exchange highlights a subtle aspect of Git's rename detection - it's fundamentally based on content similarity between specific versions being compared, not on tracking file identity across the entire history. This means workarounds that rely on commit ordering may not address all use cases.

The thread continues to explore whether this is an inherent limitation of Git's design or something that could be improved, particularly for language-specific cases like Ruby namespace restructuring. Hannes' contribution adds important nuance to the discussion by identifying scenarios where the proposed solution wouldn't help.
