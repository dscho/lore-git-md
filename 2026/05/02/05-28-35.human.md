This is the first patch in a series introducing a new `git url-parse` builtin, focusing on preparatory refactoring to rename URL-related terminology for RFC compliance. The patch renames `enum protocol` to `enum url_scheme` and related functions/variables to use "scheme" terminology consistently, as suggested by Torsten Bögershausen. This aligns with RFC 1738's URL specification while avoiding confusion with the unrelated `enum protocol_version`.

The changes are mechanical renames with no behavior change - user-visible diagnostics and error messages remain identical. This refactoring enables sharing the URL parsing logic between the connect path and the new plumbing command in later patches. The patch demonstrates careful attention to maintaining backward compatibility while improving internal naming.

As the first step in a well-structured series, this patch cleanly separates the terminology change from functional additions, making the subsequent patches easier to review. The author has incorporated prior feedback (notably from Torsten Bögershausen) and the changes appear straightforward with no obvious technical concerns.
