This is part 3 of a feature series introducing a new `git url-parse` command, which exposes Git's internal URL parsing logic. The patch moves URL scheme detection code from connect.c to dedicated url.[ch] files as part of the architectural refactoring needed for the new command.

The changes are mechanical - enum url_scheme and url_get_scheme() are relocated from connect.c to url.[ch] with no behavior changes. The die() message for unsupported protocols remains identical. The scheme_name() helper stays in connect.c since it has no other callers.

This is part of the broader effort to make Git's URL parsing logic available to other parts of Git and external tools, rather than having it buried in connect.c. The patch follows the pattern established in earlier parts of the series, continuing the clean separation of concerns. With this change, code that needs to identify URL schemes can do so without pulling in all of connect.c's dependencies.

The patch appears straightforward and well-contained, with no obvious issues. It's one of several preparatory refactoring steps needed before introducing the actual url-parse command in later patches. The series as a whole has already gone through multiple rounds of review, with this particular change being a relatively uncontroversial code movement.
