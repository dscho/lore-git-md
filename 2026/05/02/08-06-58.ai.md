This is a technical explanation of Git's rename detection behavior in response to the Ruby namespace move issue. Chris Torek provides a detailed breakdown of how Git's snapshot-based model affects rename detection, explaining why moving Ruby classes between namespaces (with indentation changes) often fails to register as a rename.

Key points:
- Git fundamentally stores snapshots, not changes - rename detection happens when comparing commits
- Exact content matches are always detected as renames
- Similar-but-not-identical content requires fuzzy matching (controlled by --find-renames)
- The current workaround (split into move-then-modify commits) works because the first step preserves exact content
- Future improvements could make detection smarter, but would need to be general (not Ruby-specific)
- Whitespace-ignoring comparison might help multiple language cases

The response confirms the current behavior is expected given Git's design, while leaving the door open for potential future improvements in rename detection heuristics. It provides useful context about Git's internals that helps explain why the Ruby namespace case behaves differently from simple renames.
