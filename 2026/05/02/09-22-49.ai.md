Bugfix for `git fetch --deepen` regression causing history truncation in shallow clones.

René Scharfe confirms Owen Stephens' bug report about `git fetch --deepen` unexpectedly reverting repositories to shallow state in Git 2.54.0. The issue, introduced in commit 3ef68ff40e ("shallow: handling fetch relative-deepen"), causes data loss by truncating history when `--deepen` is run on a fully-fetched shallow clone. René verifies the regression by reproducing it with Owen's test script and confirms reverting 3ef68ff40e fixes the problem.

The patch adds a regression test to t5537-fetch-shallow.sh that verifies `fetch --deepen` doesn't modify a non-shallow repository's history or shallow status. The test compares the repository state before and after the fetch operation, ensuring both the shallow status (via `rev-parse --is-shallow-repository`) and commit history (via `log --oneline`) remain unchanged.

This is a straightforward fix for a clear regression that was already well-documented in the thread. The test case will prevent future regressions of this behavior. The patch doesn't address the documentation ambiguity raised earlier in the thread (whether `--deepen` should be explicitly documented as a no-op in non-shallow repos), focusing instead on the immediate bugfix.
