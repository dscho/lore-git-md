This is the fifth patch in Derrick Stolee's 7-part series integrating `--walk-path` with `--filter` options in `git pack-objects`. The series focuses on performance optimizations for sparse-checkout scenarios.

This patch specifically adds support for the `blob:limit=<size>` filter in the path-walk API, which excludes blobs larger than a specified size. The implementation:

1. Checks blob sizes via `odb_read_object_info()` during traversal
2. Skips blobs that meet or exceed the size limit
3. Handles edge cases like missing objects (conservatively including them)
4. Adds validation in `git backfill` to prevent inefficient single-blob downloads
5. Includes tests for both zero and non-zero size limits

The patch maintains consistency with existing filter behavior and adds thorough test coverage. It builds on the infrastructure established in earlier patches while being careful about performance implications - the size checks require object content to be present, which could impact partial clone scenarios.

This continues the series' focus on large-repository optimizations, with particular attention to sparse-checkout use cases. The implementation looks solid, though reviewers may want to scrutinize the performance characteristics of the size checks during traversal.
