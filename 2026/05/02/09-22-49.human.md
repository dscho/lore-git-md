Bugfix for `git fetch --deepen` regression causing history truncation in shallow clones. René Scharfe confirms Owen Stephens' bug report with a test case showing that Git 2.54.0 incorrectly reverts fully-fetched shallow repositories back to shallow state when `fetch --deepen` is run again. The regression was introduced in commit 3ef68ff40e ("shallow: handling fetch relative-deepen", 2026-02-15).

Scharfe provides a test script that demonstrates the correct behavior (where `fetch --deepen` should be a no-op in non-shallow repositories) and adds it to the test suite in t5537-fetch-shallow.sh. The test verifies both the repository remains non-shallow and preserves commit history after the operation.

This follows the thread's technical consensus that the 2.54.0 behavior is a clear regression that must be fixed, regardless of documentation wording. The patch appears straightforward and well-targeted, adding test coverage to prevent future regressions. No maintainer has yet responded to the thread, but Scharfe's test case suggests a likely path forward.
