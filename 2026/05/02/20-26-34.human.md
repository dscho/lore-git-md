This is a follow-up bugfix for the `git fetch --deepen` regression that causes history truncation in shallow clones. René Scharfe proposes a simple fix that prevents `--deepen` from modifying non-shallow repositories by only applying the depth calculation when the repository is actually shallow. The change is minimal - just a conditional check around the depth assignment in `builtin/fetch.c`.

René notes this feels like "cheating" compared to a more thorough fix in `shallow.c`, but it directly addresses the regression while being straightforward to verify. The patch maintains the pre-2.54.0 behavior where `--deepen` is a no-op in non-shallow repos, which the thread has already established as the correct behavior.

This appears to be a clean, focused fix for a clear regression that was well-analyzed earlier in the thread. The change is small and low-risk, though as René hints, there may be room for a more architectural solution in the shallow handling code. Given the consensus around the bug's severity, this seems likely to be accepted as-is while leaving deeper refactoring for later.
