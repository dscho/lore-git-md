This is the final patch (7/7) in Derrick Stolee's series optimizing `git pack-objects` with `--path-walk` and sparse filters. The series focuses on performance improvements for sparse-checkout scenarios.

The patch adds support for the `sparse:oid` filter in path-walk mode, which dramatically speeds up pack creation by checking sparse patterns against path groups rather than individual objects. The key technical aspects are:

1. Loading sparse-checkout patterns from the provided OID and verifying they use cone-mode (the only supported pattern type for this optimization)
2. Handling shared tree OIDs that appear at both in-cone and out-of-cone paths by deferring SEEN flag assignment until after pattern checks
3. Comprehensive test coverage showing identical object sets between standard and path-walk modes, including edge cases with shared tree OIDs

Performance tests show a 60% speed improvement and 14% smaller packs when using path-walk with sparse filters. The implementation maintains backward compatibility and falls back gracefully when patterns aren't cone-mode compatible.

This completes the series' goal of integrating path-walk with all three filter types (`blob:none`, `blob:limit`, and `sparse:oid`). The work builds on Stolee's expertise in large-repository optimizations and sparse-checkout interactions, with careful attention to edge cases and test coverage.
