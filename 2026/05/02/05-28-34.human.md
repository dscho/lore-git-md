This is version 3 of a feature series introducing a new `git url-parse` builtin command, providing plumbing to expose Git's internal URL parsing logic. The command helps scripts reliably parse Git's various URL formats (including non-standard ones like SCP-style URLs) without reimplementing the logic.

Key changes in v3:
- Fixed Windows CI failure by handling DOS drive prefixes in the local-path error message
- Relaxed test assertion for absolute paths to work cross-platform (checking for "file:///" structure rather than exact path)
- Maintains all other improvements from v2 including RFC-compliant naming, comprehensive tests, and documentation

The series remains well-structured with:
1. Internal refactoring (renames and code movement)
2. Core URL parsing implementation
3. User-facing command with helpful error messages
4. Thorough documentation
5. 53 tests covering all URL types and edge cases

The implementation looks solid and the use case is clearly motivated - this would be useful plumbing for tools that need to interact with Git repositories programmatically. The test coverage is particularly thorough, validating parsing behavior across all URL types including SCP-style and IPv6 formats.

With the Windows-specific fix in place and all prior feedback addressed, this version appears ready for final review. The changes since v2 are minimal and focused on cross-platform compatibility, suggesting the series is stabilizing.
