Derrick Stolee replied to Taylor Blau's question on patch 07/12 about whether `odb_read_object_info()` should skip on-demand fetches in partial clones when checking blob sizes for the `blob:limit` filter. Stolee argued against it: a user running `git pack-objects --filter=blob:<size>` from a blobless partial clone is knowingly requesting an inefficient operation, and downloading blobs to check their size is correct behavior. For `git backfill`, he noted the size-limit filter is irrelevant because backfill makes batch-download decisions based on local tree structure, not server-side size filtering. This closes Blau's question.

The series remains on track for v4 with no blocking issues. The only remaining conversation Stolee has not addressed is Blau's question about whether `/tagged-trees` should apply to directly-listed trees under `--filter=tree:0` in patch 10/12.
