The thread covers Derrick Stolee's v3 patch series integrating `--path-walk` with `--filter` in `git pack-objects`. Derrick Stolee and Taylor Blau are the key participants; Taylor contributed three of the twelve patches (commits 10-12 covering `tree:0`, `object:type`, and `combine` filters). The series is well along -- patches 02/12 through 04/12 have now been posted with no objections raised.

The most recent patch (04/12) fixes a correctness bug where the path-walk API silently dropped directly-requested objects (blobs needed for partial-clone fetches) when a filter was active. The fix exempts pending objects from type filters, forcing their inclusion through the revision walk before restoring the correct filter values. It is a self-contained prerequisite that was uncovered by running the test suite with `GIT_TEST_PACK_PATH_WALK=1`.

The core design decision in v3 moves filter logic into `path-walk.c` rather than `builtin/pack-objects.c`. Each filter type gets specific handling: `blob:limit` checks blob sizes before emission, `sparse:oid` validates entire path groups against sparse-checkout patterns (producing the biggest speedups -- up to 2x-3x faster on some repos), `tree:0` gives tagged trees their own pseudo-path so they are not suppressed, and `combine` filters use a recursive helper. A `GIT_TEST_PACK_PATH_WALK=1` test gate has been added, forcing one test file (`t5620-backfill.sh`) to disable it locally. Performance results are documented across several large repositories.

Open items include potential edge cases with `combine` filters (multiple `blob:limit` values taking the smaller), the `strict_types` behavior for `object:type`, and documentation for bitmap integration expected in a follow-up. Stolee has noted that `sparse:oid` and the hypothetical `treesparse:oid` should not be supported by Git servers -- they are for local bundle construction only. Junio is tracking the topic without pressure.
