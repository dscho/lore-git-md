This thread is about making `git pack-objects --path-walk` work correctly with all `--filter` options (`blob:none`, `blob:limit`, `sparse:oid`, `tree:0`, `object:type`, and `combine` filters). The series is at v3 with 12 patches, co-authored by Derrick Stolee and Taylor Blau, and is tracked by Junio without pressure as it nears completion.

The key architectural change moves filter logic from `builtin/pack-objects.c` into the `path-walk.c` API, enabling filters to check path groupings before emitting objects. This produces significant performance wins: a sparse repack drops from 77.91s to 31.41s under the `sparse:oid` filter. V3 changes included passing all tests with `GIT_TEST_PACK_PATH_WALK=1`, uncovering failures in `t5620-backfill.sh`, requiring earlier emission of directly-requested objects, and extensive test updates.

Co-author Taylor Blau has now reviewed all twelve patches, but the depth is uneven. Patch 04/12 received substantive engagement on a heuristic for identifying directly-requested objects, which Blau flagged as brittle but offered no alternative for. Patch 06/12 prompted a brief discussion about error messages for incompatible combined filters that Blau resolved himself. Patches 02/12, 03/12, and 05/12 got surface-level feedback (typos, word-choice suggestions, test optimizations). The remaining seven patches (01/12, 07/12, 08/12, 09/12, 10/12, 11/12, 12/12) received no review comment at all. Because the only reviewer is a co-author, the series has received zero independent code review from anyone outside the two authors.

The latest email is a new surface-level review from Blau on patch 07/12 (`blob:limit`). He raises a legitimate design question: the patch uses `odb_read_object_info()` which fetches missing objects on-demand in partial clones, and asks whether it should use `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` to avoid downloading blobs just to check their size. Blau admits he does not know enough about `git backfill` to judge which behavior is better, and the existing backfill code already has its own guard for this. This is an open-but-not-blocking question for Stolee to answer.

Open items remain: the `strict_types` behavior for `object:type` is not fully resolved; `GIT_TEST_PACK_PATH_WALK=1` CI flag placement is undecided; the `path_is_for_direct_objects()` heuristic brittleness is acknowledged with no alternative; three additional bitmap-related patches have been posted on top by Stolee as follow-up work; and a documentation typo ("Whe" → "When") will be fixed in v4.
