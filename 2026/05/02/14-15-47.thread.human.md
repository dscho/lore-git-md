# pack-objects: add --path-walk and --filter interaction

Derrick Stolee and Taylor Blau have a 12-patch series at v3 adding `--path-walk` support for `blob:none`, `blob:limit=<size>`, `sparse:<oid>`, `tree:0`, `object:type=<type>`, and `combine` filters. The core architectural decision in v3 moved filter logic into `path-walk.c` rather than `builtin/pack-objects.c`. Stolee's patches (01-09) cover the base infrastructure and the simpler filters; Blau's (10-12) add `tree:0`, `object:type`, and `combine`.

The series has received exactly one piece of review -- a single-character surface-level typo fix from Taylor Blau on patch 05/12 ("Whe" -> "The" in the documentation, with the same typo appearing in nearby context lines). Stolee acknowledged this and will fix it in a v4 re-roll. No reviewer has engaged with the technical content, correctness, or performance of any patch in the series, meaning the code's behavior remains independently unverified by anyone outside the authors. The series is in Junio's tracking as "in final refinement" with no pressure.

Key implementation details across the three new filters: `tree:0` suppresses trees and blobs while preserving tagged trees via a `/tagged-trees` pseudo-path; `object:type` maps the filter onto per-type flags and adds a `strict_types` flag preventing direct-object requests from bypassing type restrictions; `combine` uses a recursive `prepare_filters_one()` helper with monotonic intersection. Non-zero tree-depths are explicitly rejected, triggering fallback to standard revision walking. The `sparse:oid` filter produces the biggest speedups (77.91s to 31.41s on git/git sparse repack).

Open items: the documentation typo fix for v4; Stolee's explicit warning that sparse filters should not be used on Git servers (only for local bundle construction); multiple `blob:limit` values in a `combine` filter take the minimum; and the `GIT_TEST_PACK_PATH_WALK=1` CI flag placement remains undecided. Stolee has three bitmap-related follow-up patches posted on top.
