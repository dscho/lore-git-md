This email is patch 09/12 in the v3 `--path-walk --filter` series, adding support for the `sparse:<oid>` filter to the path-walk API. This is a key payoff patch: grouping objects by path allows entire groups to be checked against sparse-checkout patterns at once, producing a dramatic speedup (repack time from 77.91s to 31.41s, packfile from 187.5M to 161.1M on git/git).

The design includes a graceful fallback: because `sparse:<oid>` requires parsing a blob that might be missing or not in cone mode, `get_object_list_path_walk()` returns an error code instead of dying, and `builtin/pack-objects.c` falls back to the standard revision walk with a warning. This means users get correct behavior even when path-walk cannot be used.

The SEEN-flag ordering fix from patch 08/12 is exercised here: the shared-tree-OID test creates two sibling directories with identical content, one in-cone and one out-of-cone, and confirms the in-cone blob is included even though its out-of-cone sibling was visited first. Test coverage also includes an end-to-end comparison of packfiles between standard and path-walk traversal in `t5317-pack-objects-filter-objects.sh`, and direct path-walk tests in `t6601-path-walk.sh`.

The `sparse:<oid>` filter is noted as intended for local bundle construction only, not for Git servers. The `git-pack-objects.adoc` typo ("Whe") remains uncorrected. No review comments have been raised on this patch.
