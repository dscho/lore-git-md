Bugfix follow-up for `git fetch --deepen` regression.

René Scharfe proposes a simple fix for the `fetch --deepen` regression that was causing history truncation in shallow clones. The patch modifies `builtin/fetch.c` to only apply the `--deepen` operation when the repository is actually shallow, preventing the problematic behavior in non-shallow repositories. This builds on the earlier confirmation that commit 3ef68ff40e introduced the regression and that reverting it fixes the issue.

The proposed change is minimal - it adds a condition to check `is_repository_shallow(the_repository)` before applying the deepen operation. René notes this feels "like cheating" and suggests a more thorough fix might belong in `shallow.c`, but this immediate solution would prevent the data loss while leaving room for a more architectural fix later.

The patch maintains the thread's established understanding that `--deepen` should be a no-op in non-shallow repositories, aligning with the behavior prior to Git 2.54.0. This follows the technical consensus reached earlier in the thread that the 2.54.0 behavior was clearly a regression. The change is narrowly focused on fixing the immediate issue while the discussion about potential documentation updates remains open.
