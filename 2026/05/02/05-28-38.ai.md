Feature: Refactoring URL scheme handling for new `git url-parse` command (patch 4/8 in series)

This patch modifies the URL scheme detection logic to be more flexible by introducing a `URL_SCHEME_UNKNOWN` return value instead of dying when encountering an unrecognized scheme. The change moves the error handling up to `parse_connect_url()` while keeping the same user-facing behavior for existing callers.

Key technical changes:
- Adds `URL_SCHEME_UNKNOWN` with value 0 to the `enum url_scheme`
- Removes the `die()` call from `url_get_scheme()` and makes it return the new enum value
- Moves the error handling to `parse_connect_url()` where the function is used
- Removes now-unneeded `gettext.h` include from url.c
- Updates the function's documentation to reflect the new behavior

The change is part of the larger effort to expose Git's URL parsing logic through a new plumbing command. By making `url_get_scheme()` non-fatal, it becomes usable in contexts where the caller wants to validate or analyze URLs without necessarily treating unknown schemes as fatal errors. This is particularly useful for the upcoming `git url-parse` command which needs to handle invalid input gracefully.

The patch maintains backward compatibility for existing callers while enabling new use cases. The test coverage from later patches in the series will verify this behavior, though this particular patch doesn't add new tests since it's purely a refactoring with no observable behavior change for current Git commands.
