This is a technical explanation of Git's rename detection behavior in response to a Ruby namespace move issue. Chris Torek provides a detailed breakdown of how Git's snapshot-based model affects rename detection, explaining why moving Ruby classes between namespaces (which changes indentation) often fails to detect renames while simple class renames work.

The key points are:
1. Git fundamentally stores snapshots, not changes, and rename detection happens when comparing these snapshots
2. Rename detection looks for exact or "sufficiently similar" content matches between deleted and added files
3. The current behavior with Ruby namespace moves occurs because indentation changes reduce content similarity below Git's threshold
4. While the workaround (split commits) helps, it has limitations for cross-commit comparisons
5. Future improvements could make rename detection more sophisticated (like whitespace-insensitive comparison), but would need to work generally across file types
