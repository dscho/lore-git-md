Performance optimization enabling path-walk with blobless filters in `git pack-objects`. This is patch 3/7 in Derrick Stolee's series integrating `--path-walk` with various `--filter` options.

The patch teaches the path-walk API to handle `blob:none` filters natively, removing a previous limitation that forced disabling path-walk when any filter was used. When encountering a blobless filter, the path-walk now skips all blob objects while still processing commits and trees. This is particularly useful for large repositories using partial clones.

Key changes:
- Adds `prepare_filters()` to validate filter compatibility and modify path-walk behavior
- Updates `path_walk_filter_compatible()` to check filter support
- Enhances the test helper to accept filter specifications
- Adds tests verifying blobless filter behavior with both `--all` and single-branch walks

Performance tests show a tradeoff - while blobless packs with path-walk are 16% smaller, they take 73% longer to generate due to extra compression passes. The space savings make this worthwhile for large repositories where storage is a concern than CPU time.

This continues Stolee's focus on optimizing pack-objects performance, particularly for sparse-checkout and partial clone scenarios. The implementation looks thorough with good test coverage, though the performance impact suggests this may be most beneficial for specific use cases rather than general adoption.
