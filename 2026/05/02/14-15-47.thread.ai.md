Subject: `[PATCH v4 00/13] pack-objects: add --path-walk and --filter interaction`. Series at v4, 13 patches, originating author and primary driver Derrick Stolee, co-author Taylor Blau. Thread type: patch series (iterative, fourth version). Based on `en/backfill-fixes-and-edges`.

**Core problem or goal:** Make `--path-walk` fully interoperable with all `--filter` options by moving filter logic from `builtin/pack-objects.c` into the `path-walk.c` API. The `tree:0` bug from v3 (tagged tree objects that were not also reachable from any commit were silently dropped) is fixed by a substantial rewrite at patch 11/13, with a new test at patch 10/13 establishing coverage for this edge case.

**Current status:** All 13 patches posted. Nine of thirteen v4 patches (01/13 through 09/13) were posted in a prior batch. Patch 10/13 (`t6601: tag otherwise-unreachable trees`) and patch 11/13 (the `tree:0` fix) have now been posted. Patches 12/13 and 13/13 remain to be posted and their content has not been summarized in this session. Patches 01/13 through 09/13 integrate filters `objects`, `object:type`, `blob:limit`, `blob:none`, `sparse:oid`, and related infrastructure into `path-walk.c`. Performance data in commit messages for earlier patches shows a 60% time reduction (77.91s to 31.41s) and 14% pack size reduction (187.5MB to 161.1MB) on the Git repository.

**Key technical details:** Files touched across all posted patches: `path-walk.c`, `path-walk.h`, `builtin/pack-objects.c`, `builtin/backfill.c`, `t/t5317-pack-objects-filter-objects.sh`, `t/t6601-path-walk.sh`, `Documentation/git-pack-objects.adoc`, `Documentation/git-backfill.adoc`. Patch 10/13 (newly summarized) rewrites the tagged-tree test setup in `t6601-path-walk.sh` to create tree objects reachable only through tags, using `git mktree` from objects written with `git hash-object -w`, rather than extracting trees from commits. This fixes a latent test bug where the tagged trees were also reachable from included commits, meaning the `tree:0` filter scenario was not actually being tested. On the `pack-objects` side, `get_object_list_path_walk()` becomes `int`-returning, and failure triggers fallback to standard revision-walk with a warning. Patch 09/13 integrated the `sparse:oid` filter into `path-walk.c` by loading cone-mode sparse-checkout patterns from a blob and populating the pattern list; non-cone-mode patterns trigger graceful fallback.
