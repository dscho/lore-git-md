The series makes `--path-walk` work with `blob:none`, `blob:limit=<size>`, `sparse:<oid>`, `tree:0`, `object:type=<type>`, and `combine` filters. The core architectural decision in v3 moves filter logic into the path-walk API (`path-walk.c`) rather than `builtin/pack-objects.c`. Key implementation patterns: `blob:limit` checks each blob's size via `odb_read_object_info()` before emission; `sparse:oid` validates entire path groups against sparse-checkout patterns at once (producing the biggest speedups, e.g. git/git sparse repack from 77.91s to 31.41s); `object:type` adds a `strict_types` flag to prevent direct object requests from bypassing type restrictions; `combine` filters use a recursive `prepare_filters_one()` helper.

**Patch 10/12 (Taylor Blau, `tree:0` filter):** Suppresses all trees and blobs from output, keeping only commits and tags. `prepare_filters()` sets `info->trees = 0` and `info->blobs = 0` when the filter is `LOFC_TREE_DEPTH` with depth zero. Tagged trees are collected into a `/tagged-trees` pseudo-path to bypass the type filter so they are still emitted -- matching the existing `/tagged-blobs` pattern. Non-zero tree-depths are rejected with a specific error, causing fallback to the standard revision walk. Tests in `t6601-path-walk.sh` cover `--all` output, single-branch walk with no tags, and rejection of `tree:1`.

**Patch 11/12 (Taylor Blau, `object:type=<type>` filter):** Maps `LOFC_OBJECT_TYPE` onto the existing per-type flags (`info->{commits,tags,trees,blobs}`) using bitwise AND so that `object:type=blob` leaves only `info->blobs=1` and zeroes everything else. The substantive fix handles the "trees off, blobs on" case (`object:type=blob`): `setup_pending_objects()` was skipping pending trees when `info->trees` was zero, but tags pointing to trees can reach blobs otherwise unreachable from any commit's root tree; and `handle_commit()` drops pending trees when `revs->tree_objects` is zero before path-walk sees them. The fix sets `revs->tree_objects` to `info->trees || info->blobs` during setup, then resets it to zero after `prepare_revision_walk()`. A new `strict_types` flag on `path_walk_info` gates the direct-object-request bypass -- when set, direct requests no longer override type restrictions. Test coverage in `t6601-path-walk.sh` covers each of the four `object:type` values, with the `blob` test specifically verifying that blobs reachable only through tag-pointed trees are correctly emitted.

**Patch 12/12 (Taylor Blau, `combine` filter):** Adds `combine` filter support. Every supported child filter is a monotonic restriction, so intersecting them via `path_walk_info` is natural: `blob:none` and `tree:0` clear flags that may already be clear; `object:type=blob+object:type=tree` ANDs the type flags down to zero; `blob:limit` takes the minimum of its child values; `sparse:oid` is allowed at most once and refuses overwriting. The main structural change splits `prepare_filters()` into a recursive `prepare_filters_one()` helper plus a thin wrapper that releases the top-level filter once after all children have been processed. This avoids the problem of releasing child filters prematurely when recursing into `LOFC_COMBINE` -- the parent's `list_objects_filter_release` already handles the recursive release. Unsupported sub-filters bubble a failure up, triggering the existing fallback to standard revision walking. Four new tests in `t6601-path-walk.sh` cover the `blob:none+tree:0` intersection (collapsing to `tree:0`), `object:type=blob+blob:limit=3` (emitting only small blobs), a disjoint `object:type=blob+object:type=tree` (resulting in empty output), and rejection of `tree:1` as an unsupported sub-filter. Documentation in `git-pack-objects.adoc` is updated to mention the `combine:<spec>+<spec>` form.
