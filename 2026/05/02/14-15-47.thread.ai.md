Subject: `[PATCH v4 00/13] pack-objects: add --path-walk and --filter interaction`. Series at v4, 13 patches, originating author and primary driver Derrick Stolee, co-author Taylor Blau. Thread type: patch series (iterative, fourth version). Based on `en/backfill-fixes-and-edges`.

**Core problem or goal:** Make `--path-walk` fully interoperable with all `--filter` options by moving filter logic from `builtin/pack-objects.c` into the `path-walk.c` API. The `tree:0` bug from v3 (tagged tree objects that were not also reachable from any commit were silently dropped) is fixed by patch 11/13 with a substantial rewrite of the tagged-trees path in `setup_pending_objects()`. The fix was pre-empted by a new test at patch 10/13 that establishes coverage for this edge case using trees created via `git mktree` rather than extracted from commits.

Patch 12/13 adds `object:type=<type>` filter support to the path-walk machinery, completing the "object-info-only" filter family alongside `blob:none` and `tree:0`. The mapping in `prepare_filters()` ANDs each of the four `info->{commits,tags,trees,blobs}` flags against whether the requested type matches, so a single filter like `object:type=blob` leaves only `info->blobs = 1` and everything else zero. This AND-based approach is explicitly designed to be composable with future combined-filter support.

The key technical contribution of patch 12/13 is handling the "trees off, blobs on" case. Previously, `setup_pending_objects()` skipped pending trees as soon as `info->trees` was zero, but `object:type=blob` needs those trees because a lightweight or annotated tag pointing to a tree can reach blobs that are otherwise unreachable from any commit's root tree. The fix loosens the gate to "skip only when both `info->trees` and `info->blobs` are zero". A second subtlety involves the revision machinery: by default, `handle_commit()` drops pending tree objects when `revs->tree_objects` is zero, so the patch sets `revs->tree_objects = info->trees || info->blobs` before `prepare_revision_walk()` to ensure those pending trees survive, then immediately resets it to zero afterwards so the revision walk does not redundantly enumerate trees alongside path-walk's own descent.

A new `strict_types` field is introduced in `struct path_walk_info` and set to 1 for `object:type` filters. This flag is checked in `walk_path()` to override the normal behavior where directly-requested objects bypass type-based filtering -- without it, a pending tree would always be emitted under its path regardless of the filter. The flag is designed for this filter, though the commit message hints it may serve combined-filter cases later.

Patch 13/13 adds support for the `combine` filter type, allowing users to take the intersection of multiple supported filter specifications in a single `--filter` expression. The approach splits `prepare_filters()` into a recursive `prepare_filters_one()` helper that walks `sub_nr` children, plus a thin wrapper that does the top-level filter release once. The composition semantics: `blob:none` and `tree:0` simply clear flags already zero (no-op on duplicate), `object:type=X` ANDs its type flag (two type filters truly intersect), and `blob:limit=N` takes the running minimum of the limit values (`combine:blob:limit=10+blob:limit=5` yields limit 5). The `sparse:oid` filter is left unchanged, and the existing handler already refuses to overwrite an already-set `info->pl`, so a `combine` with two `sparse:oid` children is rejected with a warning -- consistent with standalone behavior. The recursive split of `prepare_filters()` into an inner helper and an outer wrapper introduces a subtle ordering dependency around `list_objects_filter_release()` that warrants a second look: the inner helper must not release sub-filters (the parent's release iterates the sub array), and the outer wrapper must not release twice or leave dangling sub-pointers. No bugs are visible in the diff.

Patch 12/13 extends `prepare_filters()` in `path-walk.c` and adds the `strict_types` field to `struct path_walk_info` in `path-walk.h`. Four new tests in `t6601-path-walk.sh` cover `object:type=commit`, `object:type=tag`, `object:type=tree`, and `object:type=blob`; the blob test explicitly asserts `file2` and `child/file` appear in the output (exercising the pending-tree fix in `setup_pending_objects()`). Patch 13/13 splits `prepare_filters()` into `prepare_filters_one()` plus a wrapper in `path-walk.c`, with four new tests in `t6601-path-walk.sh` covering `combine:blob:none+tree:0`, `combine:object:type=blob+blob:limit=3`, a disjoint `combine:object:type=blob+object:type=tree` (produces empty result), and rejection of `combine` containing an unsupported subfilter; plus a documentation single-line addition.

Performance data from earlier patches in the series shows a 60% time reduction (77.91s to 31.41s) and 14% pack size reduction (187.5MB to 161.1MB) on the Git repository.
