**Thread identity:** Subject: `[PATCH v4 00/13] pack-objects: add --path-walk and --filter interaction`. Authors: Derrick Stolee and Taylor Blau. Series at v4, 13 patches (was 12 patches at v3), based on `en/backfill-fixes-and-edges`.

**Core problem or goal:** Make `--path-walk` fully interoperable with all `--filter` options (`blob:none`, `blob:limit=<size>`, `sparse:<oid>`, `tree:0`, `object:type=<type>`, and combined filters) by moving filter logic from `builtin/pack-objects.c` into the `path-walk.c` API.

**Current status:** Series at v4. The major open item from v3 -- the buggy `tree:0` handling (previously patch 10/12) -- is addressed. Stolee confirms Blau "correctly smelled a problem" with the v3 approach of using `/tagged-trees` for tagged trees. The bug (tagged trees silently dropped under `tree:0` when they had no alternative reference path) is fixed by a substantial rewrite now at patch 11/13. A new preparatory patch (patch 10/13) adds a tagged-tree test to `t6601` that tags trees with no other reachability path, making future regressions detectable. The `tree:0` implementation now expands directly-requested trees in `/tagged-trees` from the root path rather than from the pseudo-path itself. A new `ASSERT(path)` is added to `path_is_for_direct_objects()`.

Other changes from v3: typo fixed (`Whe` -> `The --path-walk` in docs), performance test script (`p5315`) made submodule-resilient via more careful `git ls-tree -d` usage, minor commit-message wording improvements.

Performance data is identical to v3 and remains compelling: dramatic speedups for `sparse:oid` (git/git: 72.53s to 29.00s, nodejs/node: 518.84s to 27.99s), more modest wins for `blob:none` and `blob:limit`. Path-walk generally produces smaller packfiles. Azure-devops-docs remains an outlier (path-walk sometimes takes longer when space savings don't materialize).

**Key technical details:** Core architecture unchanged from v3. Patch 11/13 is the substantive rewrite: tagged trees in `/tagged-trees` are now expanded from the root path, ensuring they aren't silently dropped. Patch 10/13 (`t6601: tag otherwise-unreachable trees`) is new -- tags trees that have no commit root reference, closing the test gap that let the v3 bug escape detection. The `ASSERT(path)` in `path_is_for_direct_objects()` (patch 11/13) is new. Range-diff shows extensive renumbering of object indices in `t6601-path-walk.sh` because `/tagged-trees` path now separates tagged trees out of the default sort order. Patch 04/13 (`'/'`-prefix namespace convention, NULL-pointer `ASSERT()`) and patch 07/13 (`odb_read_object_info()` blob size checks, `OBJECT_INFO_SKIP_FETCH_OBJECT` not needed) are unchanged from v3.
