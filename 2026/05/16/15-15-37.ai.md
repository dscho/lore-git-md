This is the first patch in Tuomas Ahola's v4 series fixing edge cases in Git's date approximation logic. The patch implements a semantic change for the "today" special date format, making it resolve to midnight rather than the current time.

The change addresses a long-standing quirk where "today" was not actually a documented special date format but happened to resolve to "now" as a side effect. The new behavior makes more intuitive sense for common use cases like `git log --since=today`, which will now show commits from the current day rather than (usually) nothing (since it was previously comparing against future timestamps).

The patch adds a new `date_today()` function to the approxidate machinery that sets the time to midnight while preserving any explicitly specified time components (like "noon today"). It also documents the new behavior in the rev-list-options man page and adds test coverage.

This change represents a deliberate resolution of the "today" semantics discussion from previous iterations of the series, implementing Junio's preferred approach of having "today" mean midnight. The patch is cleanly implemented with clear test coverage, though it does represent a user-visible behavior change that may need to be noted in release notes.
