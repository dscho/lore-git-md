This is a bugfix patch from Jeff King addressing a memory leak in Git's apply functionality. The issue occurs when processing patches that are too large (over ~1GiB), where the strbuf contents would be leaked when returning an error.

The fix modifies `apply.c` to properly clean up the strbuf when hitting the "patch too large" error case by using the existing cleanup path (via `goto end`).

Key technical details:
- The leak was introduced in commit f1c0e3946e (2022-10-25) which added size checking
- The fix adds just 4 lines while removing 2, cleanly plugging the leak
- The change future-proofs against potential new error modes in read_patch_file()
- The issue can be reproduced by running test t4141 with LSan and EXPENSIVE prereq

This is a typical Jeff King patch - small, precise, and addressing a real issue found through expanded CI testing. The fix demonstrates his characteristic attention to edge cases and memory safety. The patch is part of a series addressing UBSan failures that were found when EXPENSIVE tests were enabled in CI.
