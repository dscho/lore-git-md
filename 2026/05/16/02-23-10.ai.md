This is a bugfix patch from Jeff King addressing a signed integer overflow in Git's UTF-8 verification code for commit messages. The issue was discovered when running expensive tests under UBSan in CI, which revealed that creating a message over 2GB would trigger an overflow when calculating buffer positions.

The fix makes several careful changes to the UTF-8 verification logic in `commit.c`:
1. Changes buffer size/offset handling from `int` to `size_t` to properly handle large buffers
2. Splits the return value into a boolean "found invalid UTF-8" flag and an out-parameter for the offset
3. Updates the caller in `verify_utf8()` to use `size_t` consistently
4. Makes internal byte counting unsigned to avoid sign comparison warnings

While 2GB commit messages are clearly impractical, the patch makes the code robust against such edge cases. The changes are relatively small (15 lines added, 16 removed) but demonstrate Jeff King's characteristic attention to edge cases and memory safety. This follows his earlier fix for a memory leak in `apply.c` that was also found through expanded CI testing.

The patch appears well-considered, with Jeff noting he carefully checked for cases where values could be negative and calling out a potentially concerning `offset-1` operation that is safe due to context.
