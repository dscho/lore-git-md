This is a bugfix patch from Jeff King addressing a signed integer overflow in Git's UTF-8 verification code for commit messages. The issue was discovered when running expensive tests under UBSan (Undefined Behavior Sanitizer) in CI, which revealed that creating a message over 2GB would trigger an overflow when checking for invalid UTF-8 sequences.

The fix makes several careful changes to the verification logic in `commit.c`:
1. Changes the size/offset handling from `int` to `size_t` to properly handle large buffers
2. Splits the return value into a boolean "found invalid" flag and an out-parameter for the offset
3. Updates the caller to use `size_t` consistently
4. Makes internal byte counting unsigned to avoid sign comparison warnings

While 2GB commit messages are clearly impractical, the patch makes the code robust against such edge cases. The changes are well-explained and demonstrate Jeff King's characteristic attention to detail in handling memory safety and integer overflow cases. This follows his earlier fix for a memory leak in `apply.c`, both addressing issues found through expanded CI testing.

The patch is relatively small (15 lines added, 16 removed) but effectively eliminates a real undefined behavior case that could affect users in extreme scenarios. It's part of ongoing efforts to harden Git's code paths against edge cases through improved CI testing.
