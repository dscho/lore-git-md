This is a bugfix patch that changes Git's date parsing to make "today" resolve to midnight rather than the current time. The change addresses an inconsistency where "today" wasn't officially supported as a date format, causing `git log --since=today` to incorrectly include future commits (since it fell back to current time) and `@{today}` to be rejected outright.

The patch adds a new `date_today()` function that returns midnight of the current day when no specific time is given, while preserving existing behavior for expressions like "noon today". The implementation is clean and focused (10 lines of code plus tests), touching only the date parsing subsystem.

The commit message thoughtfully discusses the tradeoffs - while making "today" mean midnight works well for `--since` (showing today's commits), it creates some ambiguity for `--until` where users might expect "until now" rather than "until midnight". The author argues this is still preferable to the current behavior, and notes it actually better matches the documented meaning of `--until` as showing commits "older than" the given date.

This appears to be a well-considered quality-of-life improvement that makes date handling more intuitive for common cases. The patch follows Git conventions, includes thorough test coverage, and documents the new behavior in the man pages. It's now in its second iteration with an improved commit message addressing feedback from the initial RFC.
