This is a follow-up discussion in a bugfix thread about UBSan (Undefined Behavior Sanitizer) failures in Git's CI pipeline. The original issues, found when EXPENSIVE tests were enabled, involved a memory leak in `apply.c` and an integer overflow in `commit.c` during UTF-8 verification of extremely large commit messages (over 2GB).

Derrick Stolee acknowledges Jeff King's quick fixes for both issues. While noting that 2GB commit messages are impractical in real-world usage, Stolee agrees the type improvements are valuable since the affected code paths might be reused elsewhere. He suggests considering explicit size limits for commits could be a separate feature discussion.

The exchange shows consensus on the technical solutions while leaving the door open for future policy decisions about handling extremely large inputs. The thread demonstrates how CI testing with UBSan and EXPENSIVE tests helps catch edge cases that might otherwise go unnoticed until they cause problems.
