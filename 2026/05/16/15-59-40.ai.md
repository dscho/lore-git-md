Performance optimization patch for commit-reach.c's `tips_reachable_from_bases()` function, part of a v3 series addressing ref-filter operations like `for-each-ref --merged`. This patch implements the core algorithmic improvement by using object flags to mark tip commits, replacing an O(C*T) linear scan with O(1) flag checks.

The change marks tip commits with the RESULT flag upfront, allowing the reachability check to become a simple flag test rather than scanning the tips array. This handles duplicate refs naturally via shared commit objects and maintains the 4x-6x speedups shown in benchmarks (2.3M commit monorepo: 2.3s->0.31s). The patch also cleans up by removing an unused index field from commit_and_index struct.

The implementation follows Jeff King's v2 suggestion to use object flags rather than the original decoration hash approach, addressing the collision issues that surfaced in v1. The change is concise (+11/-12 lines) while fixing the early termination bug from earlier versions. Performance impact is most significant for operations checking many refs (like for-each-ref), with smaller gains for commands examining fewer tips (branch/tag).

This optimization provides a key primitive for ref-filter operations in large repositories, connecting to broader performance efforts around ref handling. The patch stands ready for integration with all review feedback addressed, including the regression tests added in the companion patch.
