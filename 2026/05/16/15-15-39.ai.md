This is the third patch in Tuomas Ahola's four-part series fixing edge cases in Git's date approximation logic (approxidate). The patch focuses on making special time-of-day formats like "noon" and "tea" respect explicitly specified days.

The core issue is that these special formats were incorrectly rolling back to the previous day even when a specific date was given (e.g., "May 13 at noon" would incorrectly evaluate to May 12). The fix is straightforward - only apply the day rollback logic when no specific day has been set (tm_mday < 0). The patch includes test cases demonstrating the corrected behavior for combinations like "today at noon" and "last Friday at noon".

This patch was already accepted in previous iterations of the series, with the current version incorporating Jeff King's feedback via Junio's earlier review. The changes from v3 to v4 are focused on the first patch's "today" semantics rather than this core fix.

The patch touches date.c's date_time() function and adds test coverage in t/t0006-date.sh. It references a 2006 bug report from Linus Torvalds about similar date parsing quirks, showing this has been a long-standing issue. The implementation is clean and focused, with just a 3-line logic change plus test updates.
