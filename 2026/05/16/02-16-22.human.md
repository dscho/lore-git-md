This is a bugfix patch from Jeff King addressing a memory leak in Git's apply functionality. The issue occurs when processing patches that are too large (over ~1GB), where the code would fail to free the buffer containing the patch contents before returning an error.

The fix is straightforward - it ensures proper cleanup by using an existing error-handling path in `apply_patch()` when `read_patch_file()` fails. This matches the error handling pattern used elsewhere in the function. The change is small (just 4 lines modified) but important, as it prevents memory leaks in an error case that could affect users applying very large patches.

The bug was discovered through Git's CI pipeline when EXPENSIVE tests were enabled, demonstrating the value of thorough testing. Jeff King's fix is characteristically precise - he identifies the root cause clearly and provides a clean solution that also future-proofs against similar issues.
