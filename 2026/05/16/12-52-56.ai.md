This is a bugfix/UX improvement patch for the config subsystem, addressing user confusion when mistakenly using `=` syntax in `git config` commands. The v2 patch from Harald Nordgren builds on Junio's feedback by:

1. Moving the hint logic from `git_config_parse_key()` to `builtin/config.c`, restricting it to only "set" contexts where the `=` mistake is likely
2. Adding more precise detection - only triggering when `=` appears after the last dot (avoiding false positives with valid subsection syntax like `[foo "bar=baz"]`)
3. Handling 2-arg forms by using the user's provided value in the suggestion
4. Adding comprehensive test coverage in t1300-config.sh

Key technical changes:
- New `advise_setting_with_equals()` helper in builtin/config.c
- Wired into `cmd_config_set()` and bare `git config` paths
- Explicitly excluded from `--get`/`unset` operations
- 47 lines of new tests covering all edge cases

The patch addresses Junio's concerns from v1 by:
- No longer touching the low-level `git_config_parse_key()`
- Properly handling legitimate uses of `=` in subsections
- Adding missing tests
- Making the hint context-aware (only showing for set operations)

This appears ready for merging - it's a focused UX improvement with thorough test coverage and clear boundaries crossed with the config parsing internals. The implementation cleanly separates the hinting logic from core config parsing.
