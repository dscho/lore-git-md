Performance optimization for ref-filter operations. This is the first patch in a v3 series that improves the efficiency of `tips_reachable_from_bases()` in commit-reach.c, a function used by commands like `for-each-ref --merged` and `branch/tag --contains`.

The patch replaces an O(C*T) linear scan with O(1) flag checks using the RESULT object flag, following Jeff King's suggestion from earlier reviews. Benchmarks show 4x-6x speedups in large repositories, particularly for operations checking many refs. The change also naturally handles cases where multiple refs point to the same commit through shared object flags.

Key technical changes include removing an unused struct field and simplifying the commit marking logic. The implementation remains clean (+11/-12 lines) while fixing issues from earlier versions. Performance improvements are most noticeable in monorepos with many refs, where the original linear scan was particularly costly.

This optimization is now production-ready with comprehensive test coverage added in the second patch of the series, addressing all outstanding review feedback. The change provides a significant performance boost for ref-filter operations in large repositories.
