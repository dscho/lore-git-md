Test patch adding coverage for duplicate ref handling in commit-reach optimization.

This is the second patch in v3 of a series optimizing `tips_reachable_from_bases()` in commit-reach.c, which improves performance for ref-filter operations like `for-each-ref --merged`. The optimization (introduced in v1 and refined in v2) uses object flags for O(1) reachability checks rather than linear scans.

The patch adds three test cases specifically covering scenarios where multiple refs point to the same commit, addressing a review request from Derrick Stolee. The tests verify correct behavior when:
1. All duplicate tips are reachable from the base commit
2. No duplicate tips are reachable
3. Duplicate tips exist at the minimum generation number (testing early termination logic)

The test implementation follows the existing pattern in t6600-test-reach.sh, using the `run_all_modes` helper to exercise both the original and optimized code paths. The test cases are well-constructed, creating temporary branches to simulate the duplicate ref scenarios and verifying expected output.

This completes the test coverage for the optimization series, which has already demonstrated significant performance improvements (4x-6x speedups in large repositories). With these regression tests added, the series appears ready for final review and potential merging.
