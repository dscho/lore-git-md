This is a bugfix/UX improvement patch for the config subsystem, addressing a common user error when setting config values. The patch follows up on Junio's feedback from v1 by making the "did you mean" hint more precise and adding test coverage.

The patch improves error messages when users accidentally use `=` syntax (e.g. `git config pull.rebase=false`) instead of the correct space-separated form. Key changes in v2:

1. The hint is now restricted to "set" contexts (both explicit `git config set` and implicit forms) and won't appear for `get`/`unset` operations
2. It only triggers when `=` appears after the last `.` in the key, avoiding false positives for valid uses of `=` in subsection headers
3. When a separate value is provided (e.g. `git config pull.rebase=false true`), the hint uses that value rather than the text after the `=`
4. Comprehensive tests verify the behavior in various scenarios

The implementation moves the hint logic from `config.c` to `builtin/config.c` where it can better understand the command-line context. The 47-line test addition thoroughly covers edge cases, including valid uses of `=` in subsection names.

This is a real pain point for users (the commit message cites `pull.rebase=false` as a common mistake) and the v2 iteration addresses the maintainer's concerns from the initial review. The patch is well-scoped and clearly explained, making it a strong candidate for inclusion.
