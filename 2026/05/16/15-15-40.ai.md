This is the final patch in Tuomas Ahola's four-part series fixing edge cases in Git's approxidate parser, specifically addressing how special time formats like "noon" and "tea" interact with explicit day specifications.

The patch introduces a deferred adjustment mechanism using negative `tm_mday` values to handle cases where time-based special formats ("noon", "tea") combine with relative day references ("today", "yesterday"). The key change is making these combinations work more intuitively - for example, "tea yesterday" will now correctly mean "5pm yesterday" rather than going back to the last 5pm and then subtracting a day.

The implementation:
- Uses negative `tm_mday` values (-1 for yesterday, -2 for day before, etc.) as markers for deferred adjustments
- Modifies `update_tm()` to handle these negative values appropriately
- Updates time-specific handlers (`date_noon`, `date_tea`, etc.) to use the new deferred approach
- Adds test cases verifying the new behavior works as expected

This builds on the previous patches in the series which established the "today=midnight" semantic and fixed core issues with special time formats respecting explicit days. The changes show careful attention to Junio's earlier feedback about making the behavior more intuitive while maintaining backward compatibility where needed.
