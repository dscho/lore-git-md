Performance optimization follow-up with benchmark analysis and implementation refinement for commit-reach.c's tips_reachable_from_bases().

Kristofer Karlsson responds to Jeff King's benchmark results showing a regression in the linux.git case, identifying the root cause as a flaw in the early termination logic when multiple refs point to the same commit. The original decoration-based approach failed to properly track the minimum generation index due to hash collisions, causing unnecessary graph traversal. 

With a fix for this issue, Kristofer now reports consistent 4.3x speedups in both the monorepo and linux.git cases (1.33s -> 0.31s for --merged/--no-merged operations). However, he acknowledges Jeff's architectural concerns about using the decoration API, agreeing that an object-flags bit or commit-slab would be cleaner solutions than the current (void*)(i+1) hack.

The email moves the discussion forward by:
1. Validating the optimization's core premise with corrected benchmarks
2. Confirming the performance benefits extend beyond the initial test case
3. Accepting the need for implementation refinement while maintaining the algorithmic improvement

Key technical points:
- The early termination bug stemmed from decoration hash collisions when multiple refs shared commits
- Fixed version shows consistent speedups across repository types
- Implementation still needs migration from decoration API to a more appropriate data structure

This positions the thread for the next round focusing on selecting the optimal low-level implementation (object-flags vs commit-slab vs other alternatives) while preserving the proven O(C+T) algorithmic improvement. The performance claims now have broader validation, but the implementation needs cleanup before final acceptance.
