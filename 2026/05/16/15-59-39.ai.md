Performance optimization patch series (v3) for commit-reach.c's `tips_reachable_from_bases()`, addressing a bottleneck in ref-filter operations like `for-each-ref --merged` and `branch/tag --contains`. This version adds regression tests requested in v2 review while maintaining the object-flag optimization approach.

The core change replaces an O(C*T) linear scan with O(1) flag checks using the RESULT object flag, building on Jeff King's v2 feedback to simplify from the original decoration hash approach. Benchmarks show consistent 4x-6x speedups across different repository sizes (2.3M commit monorepo and linux.git with synthetic branches). The new second patch adds test coverage for the duplicate-tips case that exposed a bug in v1's decoration implementation, addressing Derrick Stolee's review request. The tests verify correct handling when multiple refs point to the same commit, a scenario the object-flag approach naturally handles via shared commit object flags.

The implementation remains clean (+11/-12 lines in commit-reach.c) while fixing v1's early termination bug and removing an unused struct field. The optimization is production-ready with comprehensive test coverage, marking a significant improvement for ref-filter operations in large repositories. This connects to broader performance efforts around ref handling efficiency (reftable, geometric repacking) by optimizing a key commit-reach primitive.
