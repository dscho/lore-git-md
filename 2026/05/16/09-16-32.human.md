Performance optimization patch for commit-reach.c, improving the efficiency of `tips_reachable_from_bases()` by using object flags instead of linear scans. This is version 2 of the patch, incorporating feedback from Jeff King.

The key change replaces the O(C*T) complexity linear scan with an O(1) flag check using the RESULT object flag, where C is commits walked and T is number of tips. The patch demonstrates significant speedups (4-6x) for `for-each-ref` operations in both a large monorepo and linux.git with synthetic branches, while having minimal impact on commands that check fewer tips like `branch --merged`.

Notable improvements in v2:
- Switched from decoration hash to RESULT object flag (simpler implementation)
- Fixed early-termination bug for duplicate tips
- Removed now-unused index field from struct commit_and_index
- Added linux.git benchmark results showing worst-case improvements

The patch appears well-validated with clear performance benefits and addresses the architectural concerns raised in previous reviews. The implementation is now cleaner while maintaining the same algorithmic improvements.
