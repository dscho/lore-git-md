Performance optimization patch for commit-reach.c's `tips_reachable_from_bases()` function, now using object flags rather than decoration API. This is v2 of a series addressing performance bottleneck in ref-filter operations like `for-each-ref --merged` and `branch/tag --contains`.

The patch simplifies the previous approach by using the RESULT object flag to mark tip commits, eliminating the need for a separate decoration hash. This maintains the O(C+T) complexity improvement over the original O(C*T) while being more straightforward. The change naturally handles duplicate tips (multiple refs pointing to same commit) since the flag is set on the shared commit object.

Benchmarks show consistent 4x speedups for `for-each-ref` operations on both a large monorepo (2.3M commits, 10k refs) and linux.git with synthetic branches. The implementation removes the now-unused index field from commit_and_index struct and fixes the early termination logic that was broken in v1 when multiple refs pointed to the same commit.

This version incorporates Jeff King's feedback to use object flags instead of decorations, resulting in a cleaner solution that still delivers the same performance benefits. The diff is +11/-12 lines, showing the simplification while maintaining the core optimization.
