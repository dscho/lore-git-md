Performance optimization patch series for commit-reach.c, now with regression tests. This is v3 of a series that speeds up ref-filter operations like `for-each-ref --merged` by optimizing the `tips_reachable_from_bases()` function.

The core optimization replaces an O(C*T) linear scan with O(1) flag checks using Git's object flag system, maintaining the 4x speedup seen in v2 (2.3M commit monorepo benchmarks show 6.6s->1.6s). The key technical change from v2 is the addition of regression tests covering the case where multiple refs point to the same commit - a scenario that revealed a bug in the v1 implementation.

The patch series now addresses all outstanding feedback:
- Jeff King's v1 suggestion to use object flags instead of decorations was implemented in v2
- Derrick Stolee's request for regression tests is now fulfilled in v3 with new t6600 test cases
- The implementation remains clean (+11/-12 lines) while delivering measurable performance wins
- Benchmarks now include both merged and no-merged cases across two repository sizes

This appears production-ready, with the test coverage addressing the last remaining review point. The optimization will benefit users of ref-filter operations in large repositories, particularly those with many refs.
