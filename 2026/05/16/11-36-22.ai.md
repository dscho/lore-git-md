This is a v2 patch in the "today as midnight" series, addressing date parsing behavior in Git. The patch makes "today" resolve to midnight rather than the current time when used in date specifications like `git log --since=today`.

The key changes from v1 include:
- Expanded commit message explaining the tradeoffs between `--since=today` and `--until=today` behaviors
- Added documentation of the new behavior in rev-list-options.adoc
- Maintains existing behavior for time-qualified expressions like "noon today"

The implementation adds a new `date_today()` function to the approxidate machinery that returns midnight when no specific time is given, while preserving current behavior for expressions with explicit times. Test cases verify both the basic "today" case and interactions with other date components.

The patch addresses the original issue where `--since=today` would incorrectly show future commits (since it fell back to current time), while acknowledging that this change also affects `--until=today` behavior in a potentially less intuitive way. The author argues the practical utility of `--since=today` outweighs the `--until` edge case, especially since the new behavior better matches the documented meaning of `--until` as "older than date".

This appears to be a well-considered quality-of-life improvement to Git's date handling, with thorough consideration of edge cases and appropriate test coverage. The v2 iteration incorporates maintainer feedback by more explicitly documenting the behavior tradeoffs.
