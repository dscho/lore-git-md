This is a follow-up discussion in the git-gui bugfix series addressing repository and worktree detection issues. Mark Levedahl responds to Johannes Sixt's review of patch 3/11, which introduced centralized functions for managing GIT_DIR and GIT_WORK_TREE environment variables.

The key development here is Mark's agreement to simplify the approach further by only setting GIT_DIR (not GIT_WORK_TREE) while still maintaining the cleanup of both variables when unsetting. This aligns with Johannes' earlier suggestion that GIT_WORK_TREE shouldn't be set at all in modes requiring a worktree.

The exchange shows the series continuing to refine based on maintainer feedback, with the author demonstrating responsiveness to technical guidance. The change represents a small but meaningful simplification of the environment variable handling logic in git-gui. This patch remains part of the larger effort to make git-gui more robust when dealing with bare repositories and edge cases around worktree detection.
