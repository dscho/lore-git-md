This is a maintainer follow-up in the "today as midnight" thread, where Junio C Hamano is considering how to integrate Tuomas Ahola's patch with another related effort. The patch itself (v2) proposes making "today" resolve to midnight in Git's date parsing, which fixes the unintuitive behavior where `--since=today` could include future commits by default.

Junio expresses approval for the patch's approach ("I like this construction of argument") and raises a practical integration question - whether this change should replace or coexist with Ahola's earlier work on making time expressions like "noon" and "tea" more sensible. This suggests the patch is likely to be accepted, pending resolution of how it fits with the broader date-handling improvements.

The technical merits remain as described in previous summaries: the change provides more intuitive behavior for common `--since=today` use cases while explicitly documenting the tradeoff for `--until=today`. The implementation is clean (a 10-line function plus tests) and well-justified. Junio's question indicates this is now in the final consideration stage before potential merging.
