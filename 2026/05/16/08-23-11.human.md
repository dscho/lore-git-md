Performance optimization follow-up with benchmark improvements and implementation insights for commit-reach.c.

Kristofer Karlsson responds to Jeff King's benchmark results showing a regression in the linux.git test case. He identifies the root cause: the original patch's use of decoration hash was failing to properly handle multiple refs pointing to the same commit, breaking the early termination optimization. This explains why Jeff saw slower performance (650ms to 830ms) while Kristofer saw speedups in his monorepo tests.

The author has a local fix that restores the early termination behavior, now showing a 4.3x speedup in linux.git (1.33s to 0.31s). However, he acknowledges Jeff's architectural concerns about using the decoration API and agrees it's not the right long-term solution. The email suggests he's working on a revised version using either object-flags or commit-slab as Jeff recommended, which would avoid the current hack of storing array indices as pointers.

This moves the discussion forward by both validating the optimization's potential (when correctly implemented) and confirming the need for a cleaner implementation approach. The thread now awaits Kristofer's revised patch using one of the suggested data structures.
