This is patch 4/6 in Johannes Schindelin's series removing the unmaintained nedmalloc allocator from Git's Windows builds. The series addresses GCC 16 compatibility issues and completes the deprecation path started when Git for Windows switched to mimalloc.

This patch removes the first 2235 lines of `compat/nedmalloc/malloc.c.h`, stopping just before the "Overlaid data structures" section. The removal is split across multiple commits due to the file's size exceeding mailing list limits. The commit message notes this mechanical deletion is part of systematically removing all nedmalloc code after first disabling its usage and build system integration in earlier patches.

The change is straightforward - it simply deletes the initial portion of the malloc implementation file, including:
- Version and licensing information
- Configuration options and tuning parameters
- Core malloc/free/realloc function declarations
- Platform-specific code for Windows and Unix systems
- Locking implementations
- Chunk representation and memory management internals

This continues the series' logical progression of first making the code unused (patch 1), then removing build system support (patch 2), auxiliary files (patch 3), and now the core implementation in chunks. The remaining patches will complete the removal of the malloc.c.h file.

Since Git for Windows has used mimalloc for years and benchmarks show no advantage over system allocators, this removal has no functional impact while resolving the GCC 16 build issue. The structured approach minimizes disruption by ensuring all dependencies are removed in the correct order.
