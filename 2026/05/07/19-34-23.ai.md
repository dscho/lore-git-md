This is a test patch (4/5) in Kristoffer Haugsbakk's `git format-rev` series, adding a dedicated regression test for the `--annotate-stdin --name-only` option combination in `git name-rev`. The test ensures proper handling of name-only output when processing stdin, which was recently refactored to use a new `struct command` infrastructure.

The test:
- Generates expected output by collecting name-only revs for all commits
- Verifies the new code path produces identical results
- Maintains the series' pattern of thorough test coverage
- Prevents future regressions in the stdin processing path

This follows the series' careful approach of adding tests alongside functionality changes, with this particular test addressing a gap where the name-only behavior wasn't explicitly verified for the stdin case. The implementation appears straightforward and well-integrated with the existing test suite.
