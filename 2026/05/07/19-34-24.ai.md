This is the final patch (5/5) in Kristoffer Haugsbakk's v4 series introducing the new `git format-rev` command, a feature that provides on-demand pretty formatting of revisions from stdin. The command addresses use cases where users need to format commits encountered in arbitrary contexts (like in text or from other commands' output, without the deduplication behavior of `git log`/`git show`).

Key technical additions in this patch:
- Implements the core `format-rev` command with two input modes:
  - `--stdin-mode=revs`: Processes one revision per line/record
  - `--stdin-mode=text`: Finds and formats commit object names in freeform text
- Adds NUL-termination support via `-z`, `--null-input`, and `--null-output` options
- Uses `maybe_flush_or_die()` for safe interactive stream processing
- Handles annotated tags by peeling to commits
- Includes comprehensive tests covering both modes, edge cases, and NUL handling

The implementation builds on the preparatory refactoring from earlier patches in the series, reusing the command dispatch infrastructure added to `builtin/name-rev.c`. The documentation thoroughly explains the command's purpose, options, and use cases with practical examples.

Review feedback from Phillip Wood, Ramsay Jones, and Junio C Hamano has been incorporated, particularly around stream safety and NUL-handling. The patch maintains excellent separation of concerns from the preparatory work and demonstrates robust test coverage.

This represents a well-considered addition to Git's revision formatting capabilities, marked as EXPERIMENTAL to allow for future interface refinement based on user feedback. The command fills a clear gap in Git's tooling for on-demand commit formatting scenarios that existing commands don't handle well.
