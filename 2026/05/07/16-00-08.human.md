Platform compatibility patch from Johannes Schindelin, part of a series removing the unmaintained nedmalloc allocator from Windows (MINGW) builds. This first patch stops using nedmalloc by removing the build system configurations that enable it, while subsequent patches in the series will fully remove the code.

The change is motivated by GCC 16 compatibility issues - the old nedmalloc code triggers new warnings that break builds with `-Werror`. Since Git for Windows has already been using mimalloc successfully for years, and benchmarks show no significant advantage over platform allocators, this series takes the opportunity to fully remove the obsolete code rather than just patching it.

This patch specifically:
- Removes `USE_NED_ALLOCATOR` from `config.mak.uname`
- Drops nedmalloc references from CMake and Meson build configurations
- Leaves the actual code removal for later patches in the series

The change is well-justified and mechanically straightforward. As noted in the thread context, this represents the logical next step after Git for Windows' earlier switch to mimalloc, completing the deprecation of the unmaintained nedmalloc code.
