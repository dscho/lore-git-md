This is the first patch in a platform compatibility series from Johannes Schindelin, completing the removal of the unmaintained nedmalloc allocator from Git's Windows (MINGW) builds. The patch disables nedmalloc usage across all build systems (Makefile, CMake, Meson) in preparation for its complete removal in subsequent patches.

The change is motivated by GCC 16 compatibility issues - the vendored nedmalloc code fails to build with GCC 16's new -Wunused-but-set-variable warning. Since Git for Windows already switched to mimalloc years ago (with no significant performance advantage over platform allocators), this patch takes the first step toward fully excising the obsolete code.

The patch removes nedmalloc-related configuration from:
- config.mak.uname (Makefile build)
- contrib/buildsystems/CMakeLists.txt
- meson.build

This is a mechanical change with no expected runtime impact, as Git for Windows has been using mimalloc instead of nedmalloc since 2019. The commit message provides thorough background including bisection results showing the GCC 16 regression and links to relevant CI failures.

The patch in the series will follow a logical progression - first disabling usage (this patch), then removing build system references, auxiliary files, and finally the large malloc.c.h implementation in chunks. This structured approach demonstrates careful handling of the technical constraints while working toward complete removal.
