This is patch 4/6 in Johannes Schindelin's series removing the unmaintained nedmalloc allocator from Git's Windows builds. The series addresses GCC 16 compatibility issues and completes the deprecation path started when Git for Windows switched to mimalloc.

This particular patch removes the first 2235 lines of the large `malloc.c.h` file from the `compat/nedmalloc` directory. The removal is split across three commits due to the file's size (196KB) exceeding mailing list size limits. This chunk covers everything up to the "Overlaid data structures" section marker.

The change is purely a deletion of obsolete code - there's no functional impact since Git for Windows has been using mimalloc instead of nedmalloc for years. The commit message notes the mechanical nature of the change and the splitting strategy.

This continues the systematic removal approach established in earlier patches: first disabling usage (patch 1), then build system references (patch 2), auxiliary files (patch 3), and now the core implementation in chunks. The series demonstrates careful attention to dependency order and technical constraints of the mailing list workflow.

No new review feedback appears in this iteration - the approach seems uncontroversial and the patch appears mechanically sound. The remaining patches in the series will complete the removal of `malloc.c.h`.
