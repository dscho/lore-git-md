Feature enhancement for `git add -p` adding word-diff view option.

D. Ben Knoble builds on Phillip Wood's substantive technical review of Javier Bassi's patch to add a 'w' command for word-diff viewing in `git add -p`. While agreeing with the usefulness of the feature, Knoble suggests a more extensible approach than single-letter commands - proposing a `:show <opts>` syntax that could support arbitrary diff options and even shell commands (modeled after Vim's command mode). This idea would avoid the need to invent new single-letter mnemonics for future diff viewing variations.

The suggestion comes from someone familiar with Git's interactive commands and build system, though it's presented as a speculative extension rather than a direct critique of the current patch. The core word-diff functionality remains valuable, but this opens a design question about how best to expose diff customization in the interactive interface going forward. The thread continues to explore ways to improve change review for structured text formats while maintaining the patch mode's usability.
