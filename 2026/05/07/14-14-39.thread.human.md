This documentation thread addresses a long-standing gap in Git's man pages - the `--no-follow` option for `git log` has existed since 2012 but was never properly documented. Tamir Duberstein's initial patch added basic documentation, and now in the second version, he's refined the wording to be more precise about how these options interact with pathspecs (not just single files) and configuration.

The key point is that `--no-follow` serves as an explicit override for the `log.follow` configuration, allowing users to disable the follow behavior even when it's configured globally. The documentation now clearly explains this relationship while maintaining references to the original implementation work by Junio Hamano and Jeff King. 

The changes are focused and non-controversial - they simply document existing behavior more accurately. The v2 improvements make the documentation technically precise while keeping it concise, particularly around pathspec handling where the original wording could have been misinterpreted. This appears ready for merging as a straightforward documentation improvement.
