This is the second patch in a two-part bugfix series addressing a Windows-specific deadlock in geometric repacking during `git maintenance`. The issue occurs when mmap'd pack index files prevent deletion of old packfiles on certain Windows 10 versions.

The patch fixes the root cause by properly setting `child.odb_to_close` in `maintenance_task_geometric_repack()`, ensuring the object database is released before spawning `git repack`. This matches the behavior of other maintenance tasks and prevents the Windows deadlock where mmap'd files cannot be deleted.

The commit adds a robust test verification that checks for orphaned .idx files after repacking, which would indicate the bug is present. It also includes a Windows-specific test using the new `GIT_TEST_LEGACY_DELETE` infrastructure (added in patch 1/2) to simulate the problematic pre-POSIX-delete behavior on modern Windows systems.

The fix is well-validated with:
- Direct code fix in `builtin/gc.c`
- Cross-platform test coverage
- Windows-specific regression testing
- Documentation of the Windows version behavior changes
- Reference to prior related work (df76ee7b77f0)

The patch has already received positive reviews from domain experts (Derrick Stolee and Patrick Steinhardt) and appears ready for inclusion. This completes the series addressing Git for Windows issue #6210.
