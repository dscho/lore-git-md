This is a feature patch series (v4) from Kristoffer Haugsbakk introducing the experimental `git format-rev` command for on-demand pretty formatting of revisions. The series has evolved through substantive technical review, with v4 focusing on stream processing safety and NUL-termination options.

Key changes in v4:
- Adds `-z/--null` options for NUL-terminated I/O
- Implements `maybe_flush_or_die()` pattern from `merge-tree` to prevent buffered I/O deadlocks
- Documents input/output format handling in the man page
- Fixes a `-Werror=maybe-uninitialized` warning
- Improves error messages for object lookup failures

The command provides two input modes:
1. `--stdin-mode=revs`: Each line/record is a commit to format
2. `--stdin-mode=text`: Finds and formats commit object names in freeform text

Notable technical details:
- Uses Git's existing pretty formatting machinery
- Handles annotated tags by peeling to commits
- Includes comprehensive tests covering both modes and edge cases
- Marks the command as EXPERIMENTAL to allow future interface changes

The implementation appears robust, with thorough test coverage and careful attention to stream processing safety. The documentation is detailed, explaining the use cases where this command provides advantages over alternatives like `git show` or `git log`.
