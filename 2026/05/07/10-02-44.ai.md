This is a technical follow-up in the RHEL 6 build failure thread. Phillip Wood provides more specific guidance about the OpenSSL version mismatch issue that's causing the build to break.

He confirms the root cause is that Git 2.54 requires OpenSSL 3.0+ APIs but the build system is linking against an older OpenSSL version (likely the system's OpenSSL 1.0.x). While not contradicting brian m. carlson's earlier position that RHEL 6 is unsupported, Phillip offers practical advice: the user needs to explicitly point the build system to a newer OpenSSL installation if one exists on their system, either through configure flags or direct Makefile modifications.

The response shifts from policy discussion to technical troubleshooting, suggesting the user may be able to work around the issue by ensuring the build finds the correct OpenSSL version. However, it doesn't identify the specific commit that introduced the OpenSSL 3.0 dependency, which was the original question. The advice implies the issue is more about build configuration than a regression that needs reverting.
