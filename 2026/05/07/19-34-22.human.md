This is a refactoring patch (3/5) in Kristoffer Haugsbakk's v4 series introducing the new `git format-rev` command. The patch factors out common code from `name-rev.c` to be shared with the upcoming command.

The key changes:
- Introduces a `command` struct with a tagged union to handle command-specific payloads (currently only `name-rev` is supported)
- Moves the core line-processing logic into a more generic `name_rev_line` function that takes the command type as input
- Maintains all existing functionality while preparing for code reuse

The refactoring appears clean and well-motivated, with no functional changes to `git name-rev` itself. The patch follows good practice by separating mechanical preparation (this patch) from the actual feature introduction (later in the series).

Review feedback from Phillip Wood has been incorporated, reverting to `continue` instead of `goto` and improving pointer arithmetic handling. The changes are focused and clearly explained in the commit message, making this a straightforward preparatory step in the larger series.
