This is the final patch in Kristoffer Haugsbakk's v4 series introducing the new `git format-rev` command, a feature that provides on-demand pretty formatting of revisions. The command fills a gap in Git's tooling by allowing users to format individual commits from stdin in a streaming fashion, unlike `git log` or `git show` which require all input before producing output.

The key capabilities added in this patch:
- Two input modes: `--stdin-mode=revs` (one revision per line) and `--stdin-mode=text` (extract commits from freeform text)
- Support for NUL-terminated I/O via `-z/--null` options to handle binary data
- Integration with Git's existing pretty formatting machinery
- Thorough test coverage including edge cases and NUL-handling scenarios

The implementation appears robust, with careful attention to stream processing safety (using `maybe_flush_or_die()` pattern from `merge-tree`) and comprehensive error handling. The documentation is detailed, explaining use cases where this command provides advantages over alternatives.

Reviewers (Phillip Wood, Ramsay Jones, and Junio C Hamano) have provided substantive feedback that shaped the implementation, particularly around control flow and stream handling. The series demonstrates good responsiveness to technical review while maintaining its core functionality.

This represents a well-considered addition to Git's revision formatting capabilities, with the experimental flag providing flexibility for future refinement based on user feedback.
