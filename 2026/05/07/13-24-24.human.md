Feature enhancement for `git add -p` adding word-diff view option.

Phillip Wood provides a substantive review of Javier Bassi's patch to add a 'w' command to `git add -p` that shows hunks with word-diff highlighting. While praising the general approach of using the current hunk text rather than running a fresh diff, Phillip identifies several areas for improvement:

1. The implementation should propagate the filename to use the correct word-diff regex for the file type
2. It should respect the context and inter-hunk context settings from interactive_options
3. The hunk header from the unified diff should be reused to ensure correct line numbers

Phillip notes this feature would be particularly useful compared to existing diff-highlight tools since it works with edited hunks and handles reflowed text better. The review demonstrates deep familiarity with both the interactive patch machinery and diff generation internals, suggesting specific ways to better integrate the new functionality with existing systems.

This continues the discussion from Javier's initial patch, which proposed the word-diff view as a way to better review changes in structured text formats like JSON and Markdown where small inline edits can be hard to spot in line-based diffs. Phillip's feedback indicates the feature has merit but needs tighter integration with Git's existing diff infrastructure.
