This is the second patch in a two-part bugfix series addressing a Windows-specific deadlock in geometric repacking during `git maintenance`. The issue occurs when mmap'd pack index files prevent deletion of old packfiles on certain Windows 10 versions.

The patch fixes the root cause by properly setting `child.odb_to_close` in `maintenance_task_geometric_repack()`, ensuring the object database is released before spawning `git repack`. This matches the pattern used by other maintenance tasks and prevents mmap'd files from being held open during deletion attempts.

The commit adds comprehensive test coverage:
- A general check for orphaned .idx files after repacking
- A Windows-specific test using the new `GIT_TEST_LEGACY_DELETE` infrastructure (added in patch 1) to verify the fix works even with legacy Windows delete semantics
- Preservation of the test environment to allow both modern and legacy behavior verification

The fix builds on prior work (df76ee7b77f0) and addresses GitHub issue #6210 from the Git for Windows tracker. The implementation is clean and focused, with the test additions demonstrating thoughtful consideration of platform-specific edge cases. The patch has already received positive reviews from Derrick Stolee and Patrick Steinhardt, with all feedback addressed in this version.

This completes the series, which appears ready for inclusion with no outstanding technical concerns. The changes are well-contained to the geometric repack task and test infrastructure, with clear commit messages documenting both the Windows-specific behavior and the solution.
