This is the first patch in a two-part series addressing a Windows-specific deadlock in geometric repacking during `git maintenance`. The patch introduces test infrastructure to simulate legacy (non-POSIX) delete semantics on Windows, which is needed to properly test the fix in the second patch.

The change adds a new `GIT_TEST_LEGACY_DELETE` environment variable that forces Windows to use pre-POSIX delete behavior, where files cannot be deleted if another process holds an active file mapping. This allows testing the deadlock scenario that occurs on older Windows versions, even when running on modern systems that default to POSIX semantics.

The implementation provides a new `legacy_delete_file()` helper that uses `SetFileInformationByHandle()` with `FileDispositionInfo` to force the legacy behavior, and modifies `mingw_unlink()` to use this when the test flag is set. The patch follows Patrick Steinhardt's suggestion from the previous version to use `git_env_bool()` for environment variable parsing.

This test infrastructure will be used in the second patch to verify the geometric repack deadlock fix works correctly across all Windows versions. The change is well-contained to the Windows compatibility layer and maintains backward compatibility while providing the needed testing capability.
