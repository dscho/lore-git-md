This is a feature patch series (v4) from Kristoffer Haugsbakk introducing the experimental `git format-rev` command for on-demand pretty formatting of revisions. The series has evolved through substantive technical review, with v4 focusing on stream processing safety and NUL-termination options.

Key changes in v4:
- Adds `-z`/`--null` options for NUL-terminated I/O
- Implements `maybe_flush_or_die()` to prevent buffered I/O deadlocks
- Fixes a `-Werror=maybe-uninitialized` compiler warning
- Expands documentation with detailed input/output format specifications
- Adds comprehensive tests for NUL-handling behavior

The command provides two input modes:
1. `--stdin-mode=revs`: Processes each line/record as a commit
2. `--stdin-mode=text`: Finds and formats commit object names in freeform text

The implementation shares infrastructure with `name-rev.c` through refactored common code. The series appears well-structured, with preparatory commits cleaning up and factoring code before introducing the new command. Review feedback from Phillip Wood, Ramsay Jones, and Junio C Hamano has been incorporated, addressing control flow, compiler warnings, and stream processing safety.

The experimental flag remains, allowing for potential future interface changes. The implementation looks solid with thorough test coverage, though some documentation gaps around streaming behavior remain. This represents a more architecturally sound approach than the v2 attempt to extend `git name-rev`.
