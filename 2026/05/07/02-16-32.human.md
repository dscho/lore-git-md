This is a build system patch addressing a Clang compiler warning issue on Linux. The problem occurs when building with DEVELOPER=1, where Clang treats C11 features in glibc headers (like _Generic in string.h macros) as extensions due to the combination of -std=gnu99, -pedantic, and -Werror flags. 

The patch adds -Wno-c11-extensions to DEVELOPER_CFLAGS specifically for Clang on Linux, while maintaining strict warnings on other platforms like macOS. This matches GCC's behavior of suppressing pedantic warnings for system headers. The change is narrowly scoped to only affect Linux builds with Clang, preserving the ability to catch accidental C11 usage in Git's own code elsewhere.

The patch appears well-motivated and technically sound - it solves a real build issue while being careful not to relax warnings more broadly than necessary. The commit message clearly explains both the problem and the solution's rationale.
