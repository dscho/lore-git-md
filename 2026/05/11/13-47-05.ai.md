Feature patch extending `--track` with a "fetch" mode to automatically fetch remote refs before branch creation.

This is the eighth iteration of Harald Nordgren's proposal to streamline the workflow of fetching before creating a tracking branch. The v8 patch addresses a final technical refinement from Phillip Wood's review of v7, fixing how the fallback ref is checked when a fetch fails but a remote-tracking ref already exists.

Key changes in v8:
1. Simplifies the ref resolution logic by checking the input argument directly rather than reconstructing the ref path
2. Maintains all other v7 improvements including:
   - Rejection of invalid mode combinations (`inherit,direct`)
   - "Last one wins" behavior for multiple `--track` flags
   - Conversion of fetch failures to warnings when an existing ref exists
   - Respect for configured remote fetch refspecs
   - Narrow fetch scoping for bare remote names
   - Comprehensive test coverage

The implementation remains robust with:
- The `resolve_fetch_target()` helper for proper refspec resolution
- Enhanced error handling in `fetch_remote_for_start_point()`
- Updated documentation
- 12 test cases covering edge cases

While the technical execution is now thoroughly refined, the patch still doesn't address the maintainer's core workflow concerns from earlier rounds. The parallel `--autostash` work mentioned in the thread context remains unsubmitted. This remains a well-crafted feature addition that would provide concrete workflow improvements, but its acceptance likely depends on whether the maintainer can be convinced to reconsider the earlier objections based on the improved implementation.
