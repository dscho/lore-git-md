This is the final iteration of a documentation patch series clarifying the behavior of `git log --follow` and `--no-follow`. The patch addresses long-standing gaps in documenting these options, particularly around their limitations with non-linear history and directory pathspecs.

The key clarification is that `--follow` is explicitly designed to work only with single filenames on linear history - any other usage (multiple pathspecs, directories, or non-linear history) results in undefined behavior. The documentation now clearly marks these boundaries rather than implying partial functionality. 

The patch also documents the precedence rules between the command-line `--no-follow` option and the `log.follow` configuration setting. This completes the documentation of a feature that has existed since 2012 but lacked proper specification of its constraints.
