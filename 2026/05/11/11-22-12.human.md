Performance optimization for single merge-base calculation in large repositories. This is the third version of a patch that speeds up `git merge-base` by exiting early when only one merge-base is needed (the common case without `--all`) and generation numbers are available.

The key optimization remains skipping the expensive STALE commit frontier drain when generation numbers guarantee the first valid merge-base found is the best one. The patch now introduces an enum `merge_base_flags` to replace the boolean parameters in `paint_down_to_common()`, addressing Patrick Steinhardt's suggestion from v2. The flags are threaded through the call chain including the public `repo_get_merge_bases_many_dirty()` API.

Performance improvements are substantial - the commit message shows examples going from 5 seconds to 24ms (100x speedup) in a 2.2M-commit monorepo. The patch includes extensive test coverage verifying behavior with/without commit-graphs, agreement between `--all` and non-`--all` cases, and correctness in both shallow and deep commit histories.

Changes from v2:
- Replaced boolean flags with enum `merge_base_flags` (MERGE_BASE_FIND_ALL and MERGE_BASE_IGNORE_MISSING_COMMITS)
- Threaded flags through the API chain while avoiding parameter shadowing
