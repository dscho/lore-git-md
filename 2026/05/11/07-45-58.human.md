This is a final review discussion on a bugfix for `git fetch --deepen` that prevents it from incorrectly converting full clones to shallow ones. The core technical fix (already approved) moves the shallow boundary handling to `shallow.c`. 

René Scharfe responds to Junio Hamano's suggestion about whether `--deepen` should warn when used on non-shallow repositories. He notes that the command has silently no-op'd in this case since its introduction in 2016 (commit cccf74e2da), and suggests that if a warning is added, it should be done in the `fetch` command itself as a separate change.

The exchange indicates the fix is technically sound and likely ready for merging, with only minor UX questions remaining about warning messages. This appears to be the final polish before the regression fix can be queued for inclusion in a future release.
