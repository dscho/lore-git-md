This is a feature request, not a patch -- Thorsten Glaser is asking whether `git alias` execution can be made configurable to use a shell other than the hardcoded `/bin/sh`.

The author describes a concrete pain point: if a user's shell aliases rely on features not available in `/bin/sh` (for example, they are written for `mksh`, `bash`, or `zsh`), there is currently no way to tell Git to invoke that shell instead. A configuration option like `core.shell` would let users work around this without rewriting portable aliases to be POSIX-shell-compatible.

The email is brief and does not include a proposed implementation, patch, or analysis of where in Git's codebase shell invocations for aliases are hardcoded. This is essentially a request for discussion or guidance rather than a ready-to-merge contribution. It will likely attract discussion about whether this is a good idea (portability versus user convenience), whether it has been rejected before, and whether there is prior art or existing workarounds.

Worth a skim if you use shell-based aliases with non-POSIX features; otherwise, not a high-priority thread to follow.
