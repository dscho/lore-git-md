Performance optimization for merge-base calculation in large repositories. This is the third version of a patch that speeds up single merge-base queries by exiting early when generation numbers are available, avoiding the expensive STALE commit frontier drain.

The key change in v3 is replacing two boolean parameters in `paint_down_to_common()` with an explicit `enum merge_base_flags` containing `MERGE_BASE_FIND_ALL` and `MERGE_BASE_IGNORE_MISSING_COMMITS`. This addresses Patrick Steinhardt's suggestion from v2 for better API clarity. The optimization itself remains: when only one merge-base is needed (without `--all`), the algorithm can stop after finding the first valid merge-base when generation numbers guarantee no better candidate exists.

Performance improvements remain dramatic - the commit message shows examples going from 5 seconds to 24ms (100x improvement) in a 2.2M-commit monorepo. The patch includes extensive test coverage verifying behavior with/without commit-graphs and in both shallow and deep commit histories.

Changes from v2:
1. Introduced `enum merge_base_flags` to replace boolean parameters
2. Renamed parameters to avoid shadowing
3. Maintained the same optimization logic while improving API clarity

The patch appears ready for merging, having addressed all review feedback from previous versions while maintaining its significant performance benefits. The enum change makes the API more maintainable without affecting the core optimization.
