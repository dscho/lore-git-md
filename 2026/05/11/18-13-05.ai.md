This is patch 08/12 of the `--path-walk --filter` integration series from Derrick Stolee and Taylor Blau. It adds a `pl_sparse_trees` flag to the path-walk API that separates two related but distinct behaviors for how sparse-checkout patterns interact with trees.

The motivation is straightforward: the `git backfill --sparse` command wants sparse patterns to prune *both* trees and blobs -- it only needs objects within the sparse cone. But the `sparse:<oid>` filter (being added later in this series) wants the opposite: prune *only* blobs while walking all reachable trees. Before this patch, `backfill`'s behavior was hardcoded into the path-walk API. Now, a new `pl_sparse_trees` field on `path_walk_info` controls which mode is active. When set (as `backfill` does), behavior is unchanged. When unset, all trees are walked and only blobs are filtered by the sparse patterns.

The patch also fixes a subtle SEEN-flag ordering bug that this change exposed. Previously, the SEEN flag was set on an object immediately when it was discovered in a tree entry, before checking whether the path matched sparse patterns. When the same object ID appeared at multiple paths -- for example, sibling directories with identical contents -- the first path visited would mark the object as SEEN. If that first path was outside the sparse cone, the object would be skipped there but also never re-discovered at its in-cone path. The fix moves the SEEN flag assignment to *after* the sparse-pattern and pathspec checks, so objects remain discoverable at other paths when they are filtered out at the first one.

This is a clean, focused, and clearly motivated patch. The new test in `t6601-path-walk.sh` exercises `--no-pl-sparse-trees` on a four-commit branch structure with sparse patterns that exclude most paths except `/left/`, and confirms that all 10 trees are emitted (one for each commit's tree and each commit's subtrees) along with the blobs at allowed paths, while the equivalent test with the default behavior (from earlier in the file) shows fewer trees because out-of-cone subtrees like `right/` are pruned. The test infrastructure change in the test helper adds a `--pl-sparse-trees` option defaulting to the previous behavior (on), so existing tests are unaffected.

This patch is a piece of infrastructure preparation for the `sparse:<oid>` filter patch that will arrive later in the series. It does not add user-visible functionality on its own. The SEEN-flag fix is a genuine correctness win that would matter even without the new flag, and the flag itself is a minimal, well-documented addition to the API. No review comments have been raised.
