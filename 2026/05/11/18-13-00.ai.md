This is a performance benchmark patch, part of Derrick Stolee and Taylor Blau's ongoing series (v3, 12 patches) to integrate `--path-walk` traversal with `--filter` in `git pack-objects`.

Patch 03/12 adds a new performance test script `p5315-pack-objects-filter.sh` that measures `git pack-objects --revs --all` under three filter scenarios -- no filter, `blob:none`, and `sparse:oid` -- each tested both with and against the standard revision walk. The setup is thoughtful: it automatically builds a cone-mode sparse-checkout definition by sampling depth-2 directories from the test repository, with a fallback to a single top-level directory when deeper ones are absent and an explicit prerequisite skip for flat repos that have nothing to sample. This means the test can be run against any large repo passed via `GIT_PERF_LARGE_REPO` without per-repo manual configuration.

The test results included in the commit message are telling -- they confirm that with the current code (v3 before the filter integration patches are all in place) the `--path-walk` option makes essentially no difference for `blob:none` and `sparse:oid` filters, and is actually slower for the unfiltered repack (34.92s vs. 27.91s). This is expected and explicitly noted: the path-walk integration with filters has not been wired up yet in this patch, so these measurements serve as a no-op baseline. The point is that the benchmarks are now ready to show meaningful speedups once commits 04/12 through 12/12 land.

This is a well-structured, professional piece of test infrastructure. The commit message clearly explains what is being measured, why the current numbers are unremarkable (path-walk not yet wired for filters), and how the sparse-pattern sampling works. No issues, no controversy -- a straightforward prep patch that sets up the measurement yardsticks for the work that follows.
