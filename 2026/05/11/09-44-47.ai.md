Feature: New `--forked` option for `git branch` to identify branches with deleted upstreams.

This patch introduces the foundational `--forked` option to `git branch`, which lists local branches whose upstreams match given remote references. This is the first of five patches in Harald Nordgren's v6 series implementing safe branch pruning functionality.

The new `--forked` option accepts either remote names (like `origin") or specific remote-tracking branches (like `origin/main`), and unions multiple arguments. It uses new helper functions `parse_forked_args()` for argument processing and `branch_is_forked()` for matching logic. The implementation handles both configured remotes and direct remote-tracking references, with proper error handling for invalid inputs.

Key technical details:
- Adds `--forked` documentation to `git-branch.adoc`
- Implements core matching logic in `builtin/branch.c`
- Includes comprehensive tests in `t3200-branch.sh` covering:
  - Basic remote name matching
  - Specific remote-tracking branch matching
  - Multiple argument unioning
  - Error cases (unknown remotes, missing arguments)

This patch provides the plumbing needed by the subsequent `--prune-merged` functionality while being useful on its own for identifying branches that may need cleanup. The implementation follows Git's existing branch handling patterns and includes thorough test coverage. As the first patch in a technically complete series that has addressed all maintainer feedback, this appears ready for inclusion.
