This is a process discussion about Git's contribution workflow, specifically around who should be responsible for adding Reviewed-by/Acked-by trailers to patches. The thread originated from a documentation patch about commit-graph behavior but has shifted to broader project management questions.

Oswald Buddenhagen pushes back against Junio Hamano's suggestion that contributors should take more responsibility for adding trailers, arguing that additional bureaucracy will discourage contributions from non-core contributors. He suggests that if the current process doesn't scale, the project should consider switching to a tool like Gerrit rather than making the workflow more burdensome for contributors.

The exchange highlights the ongoing tension in open source between maintaining quality control and keeping the contribution process accessible. While the original documentation patch is technically complete and ready to merge, this follow-up discussion provides insight into Git's evolving workflow challenges.
