This is a bugfix thread addressing edge cases in `rebase --update-refs` when `rebase.instructionFormat` includes `%d` decorations. The latest email from Junio C Hamano responds to Abhinav Gupta's confirmation that the issue affects non-interactive rebase as well, showing the same error when attempting to update HEAD.

Junio pushes back against the unstated implication that using `%d` in the instruction format might itself be considered a bug. His response suggests maintaining the current approach of filtering to branch refs (DECORATION_REF_LOCAL) rather than treating the format string usage as invalid. This aligns with Phillip Wood's earlier Reviewed-by and Junio's own confirmation that the v3 patch's approach is correct.

The thread has established that:
1. The bug manifests identically in both interactive and non-interactive rebase
2. The current fix's branch-ref limitation matches historical behavior
3. A parallel issue in make_script_with_merges() needs the same filtering but doesn't block this fix

With maintainer approval and reviewer consensus, this appears ready for integration while leaving the make_script_with_merges() case for follow-up work. The discussion has validated that the core issue stems from the rebase machinery's ref handling rather than being specific to the instruction format configuration.
