This is patch 6 of 12 in the v3 series from Derrick Stolee and Taylor
Blau that adds `--filter` support to `git pack-objects --path-walk`.
This particular patch is a small correctness fix for the `git backfill`
command, which is a separate tool that uses the path-walk API to fetch
missing objects from a server in batches.

The change is straightforward: `git backfill` currently rejects any
`--filter` option outright, but since the preceding patch introduced a
new `path_walk_filter_compatible()` function that knows which filters
the path-walk API can actually handle, this patch replaces the blanket
rejection with a call to that function. If a user passes a filter that
path-walk can handle (like `blob:none`), `git backfill` will now let it
through; if they pass one it cannot (like `tree:1` or `blob:limit`), the
error message is slightly more general but still serves the same purpose.
Two new tests in `t5620-backfill.sh` confirm the rejection for
`tree:1` and `blob:limit`.

This is a tidy, mechanical cleanup -- it is clearly correct and follows
naturally from the API addition in patch 5. Not much to argue with here;
it is the sort of patch that exists to keep the codebase consistent as
capabilities grow. No review comments or discussion so far, and none
seems necessary unless someone takes issue with the error message wording.
