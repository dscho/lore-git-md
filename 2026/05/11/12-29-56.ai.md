This is the second patch in Patrick Steinhardt's two-patch series fixing maintenance mode issues. It addresses a regression where the `gc.auto` configuration was no longer being respected after Git switched from using `git gc` to `git maintenance` for auto-maintenance tasks.

The patch restores the expected behavior where setting `gc.auto=0` will prevent auto-maintenance from running, while maintaining backward compatibility with the newer `maintenance.auto` configuration (which takes precedence when both are set). The changes are:

1. Modifies `prepare_auto_maintenance()` in `run-command.c` to check both `maintenance.auto` and `gc.auto` configs, defaulting to enabled if neither is set
2. Adds comprehensive tests in `t/t7900-maintenance.sh` that:
   - Verify both config options work independently
   - Confirm `maintenance.auto` overrides `gc.auto` when both are set
   - Maintain existing test coverage for the auto-detach behavior

The fix addresses a user-reported regression (Jean-Christophe Manciot) where the behavior change was surprising to users who had relied on `gc.auto=0` to disable maintenance. The patch maintains the principle of least surprise while cleanly handling the transition between the old and new maintenance systems.

This is a well-constructed fix with thorough test coverage that should be uncontroversial. It completes the series' goal of addressing maintenance mode bugs, following the first patch's lockfile fix for detached mode.
