This is a two-patch series from Patrick Steinhardt addressing issues in Git's maintenance mode. The changes focus on fixing locking behavior and making auto-maintenance respect the "gc.auto" configuration.

The first patch fixes a bug where `git maintenance run --detach` could fail to properly release the lock file when running in the background. The change ensures proper lock cleanup even when the process detaches.

The second patch makes auto-maintenance (triggered via `git run-command`) properly respect the "gc.auto" configuration setting. Previously, auto-maintenance would run regardless of this setting, which could be problematic for users who explicitly disabled automatic garbage collection.

The series includes substantial test coverage in t/t7900-maintenance.sh, adding new test cases to verify both the locking behavior and gc.auto integration. The changes touch core components like the lockfile API and run-command infrastructure, but appear focused and well-contained.

Given Patrick's track record with maintenance-related changes and the clear problem statements, this looks like a solid improvement to Git's background maintenance behavior. The patches should be of interest to anyone using or maintaining Git's background maintenance features.
