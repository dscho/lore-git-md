This is a bugfix review from Jeff King (Peff) addressing a file descriptor leak in Justin Tobler's ODB write stream interface patch (part 3/7 of the ODB abstraction series). Peff identifies that when an error occurs during stream reading in `odb_source_loose_write_stream()`, the function jumps to cleanup without closing the file descriptor opened earlier. The issue was caught by Coverity static analysis.

The fix would require either closing the descriptor at the error site or ensuring consistent cleanup handling. This is a focused, substantive review that identifies a real resource leak in code that has already been approved by Patrick Steinhardt (the primary driver of the ODB abstraction effort). The review demonstrates Peff's characteristic attention to low-level resource management details, even in code that has already passed other reviewers.

For future reference: The issue occurs in `odb_source_loose_write_stream()` when handling errors from `odb_write_stream_read()`. The file descriptor leak affects loose object writing paths. While the patch was already approved, this review catches a subtle resource management issue that would need addressing before final merging.
