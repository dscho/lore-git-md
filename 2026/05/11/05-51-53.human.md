This is a status update from Junio Hamano about the sideband control character sanitization feature, which has been cooking in the 'next' branch. The feature, originally from Johannes Schindelin, restricts which terminal control sequences Git passes through from remote sideband communications by default, allowing only ANSI color sequences while masking other potentially risky control characters.

Junio notes the topic has been in 'next' long enough without complaints and is ready to graduate to 'master'. However, he plans to hold off merging the final step that would loosen these restrictions until Git 3.0. This gives users on 'master' time to experience the stricter default behavior before deciding whether the final relaxation is needed. If significant issues arise from the strict filtering, the project may need to reconsider the approach (possibly switching to blacklisting known-bad sequences rather than whitelisting known-good ones), but Junio expresses optimism this won't be necessary given the lack of complaints during the 'next' testing period.

The update reflects Junio's careful approach to rolling out security-sensitive changes - moving forward while maintaining an escape hatch in case real-world usage reveals unanticipated problems with the new defaults. The sideband sanitization represents a security hardening measure that could potentially break some legitimate uses, hence the phased rollout strategy.
