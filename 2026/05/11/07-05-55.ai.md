This is a CI configuration discussion between Patrick Steinhardt and Junio C Hamano about when to run expensive tests in the Git project's continuous integration system. The exchange follows Junio's patch to enable expensive tests (including the >4GB object tests from Johannes Schindelin's series) on both pull request builds and integration branch pushes.

Patrick raises a follow-up question: since the new configuration covers all "official" branches and pull requests, he wonders if there are any regular CI events that would still be excluded. He suggests that if not, it might make sense to enable expensive tests unconditionally, which would also ensure they run on GitLab CI (where the current GitHub-specific condition wouldn't apply).

The question reflects a practical consideration about CI resource usage versus test coverage. Patrick's suggestion to potentially simplify the configuration by making expensive tests always-on would provide more consistent testing across all CI events and platforms, though it would increase resource consumption. This is a natural next-level discussion after Junio's change to expand test coverage from just integration branches to also include PR builds.
