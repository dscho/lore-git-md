This is the third patch in Kristoffer Haugsbakk's v5 series introducing the new `git format-rev` command. It's a refactoring patch that prepares the existing `name-rev` code to be shared with the upcoming command.

The patch factors out common functionality from `git name-rev` into reusable components, using a tagged union pattern to handle command-specific behavior. Key changes include:

1. Introduces a `command` struct with a tagged union to distinguish between different command types (currently just `NAME_REV`)
2. Extracts the core `name_rev_line` processing logic to make it command-agnostic
3. Adds initialization helpers for the command structure
4. Maintains all existing functionality while making the infrastructure more flexible

The changes are mechanical and well-contained, with no functional changes to `git name-rev` itself. The patch follows good hygiene by:
- Keeping the refactoring separate from the actual feature implementation (which comes in patch 5)
- Including notes about review feedback addressed from v4
- Preserving all existing behavior while enabling future extension

This is a solid infrastructure patch that cleanly separates concerns in preparation for the new command. The use of a tagged union provides a clear pattern for adding future command variants while keeping the core logic shared.
