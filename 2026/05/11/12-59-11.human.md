Refactoring patch for merge-base performance optimization. This is the first of two patches in v4 of a series that speeds up single merge-base calculations in large repositories. 

The patch converts a boolean parameter (`ignore_missing_commits`) in the merge-base calculation code to use an enum (`merge_base_flags`) instead, making the API more readable and extensible. The change is purely mechanical - all existing callers are updated to pass either 0 or the new `MERGE_BASE_IGNORE_MISSING_COMMITS` flag, with no behavior change.

This refactoring prepares for the second patch in the series, which will add an optimization flag to enable early exit when only one merge-base is needed. The performance benefits (100x speedup in large repos) will come in the follow-up patch. 

The change follows Git conventions by separating refactoring from behavior changes, as suggested in previous review feedback. The patch appears straightforward and well-tested, with all call sites updated. This is part of ongoing performance work in the commit-reach area.
