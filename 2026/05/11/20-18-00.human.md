This is a **review reply** from Jeff King (Peff) on Patrick Steinhardt's second patch, which restores `gc.auto` support in the auto-maintenance path. The review is **substantive** — Peff has spotted a type mismatch in Patrick's config handling.

Peff's observation is sharp and to the point: `gc.auto` is not a boolean, but a count of loose objects (an integer). Patrick's patch reads it with `repo_config_get_bool()`, which works for the value `0` (since `0` is false in both contexts) but would silently misinterpret an integer like `100`. The original `git gc` code correctly used `repo_config_get_int()`. The fix that Peff is implicitly suggesting is to read `gc.auto` as an integer and then compare it against zero, while keeping the logic for `maintenance.auto` (which *is* a boolean) unchanged.

This is the kind of subtle correctness issue that Peff is known for catching — it would not cause a crash or an obvious failure, but it means that anyone who set `gc.auto = 100` to get auto-gc at a specific threshold would see their setting ignored and maintenance would run unconditionally. For the reader: this review is important and should be addressed before the patch graduates to `next`.
