This is the first patch in a 12-patch v3 series (on `en/backfill-fixes-and-edges`) from Derrick Stolee, integrating `--path-walk` with `--filter` in `git pack-objects`. A cover letter was already posted for the series.

This specific patch is a small preliminary fix: it disables the `GIT_TEST_PACK_PATH_WALK` test variable for three tests in `t5620-backfill.sh` that currently fail when path-walk is globally enabled. The failure is straightforward -- these tests run `git backfill`, which internally calls `pack-objects`, and when `--path-walk` is implicitly on the `--filter` flag used by `backfill` triggers a warning-and-skip because the two options were incompatible. The fix is simply to set `GIT_TEST_PACK_PATH_WALK=0` locally for each of the three affected tests, adding inline comments explaining why.

This is the kind of small preparatory patch that usually lands without controversy. It does not change any production code, only test infrastructure, and it is clearly motivated by the rest of the series (which makes `--path-walk` and `--filter` work together). The only notable detail is that the commit message describes the variable as enabling `--path-walk` "by default", which is slightly inaccurate -- `GIT_TEST_PACK_PATH_WALK` is a CI-only test knob, not user-facing, but that is standard usage in Git's test infrastructure.

If the rest of the series delivers on its promise (making path-walk work with all the major filter types, as the cover letter describes), this patch is a necessary stepping stone. Nothing here should be contentious.
