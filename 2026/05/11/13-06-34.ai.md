This is a review of Christian Couder's URL-based promisor remote auto-configuration series (v2 7/8). Toon Claes provides a substantive review focusing on two key implementation details:

1. **Host-only URL naming**: Notes that URLs without paths could generate names like "example-com-8443" and questions whether the MAX_REMOTES_WITH_SIMILAR_NAMES limit of 20 would be problematic. Confirms the current collision handling (appending numeric suffixes) properly handles this case without needing to parse existing remote numbers.

2. **Configuration precedence**: Asks whether promisor.acceptFromServerUrl should work when promisor.acceptFromServer is set to "all" (currently it works only when set to "none"), suggesting this behavior should be documented or reconsidered. This touches on the interaction between the two configuration options.

The review validates the security-conscious implementation while identifying areas where the behavior could be clarified. It builds on previous positive feedback from Patrick Steinhardt and Junio, with Toon's review providing additional verification of edge cases in the auto-creation logic. The patch appears ready for merging with these considerations noted.
