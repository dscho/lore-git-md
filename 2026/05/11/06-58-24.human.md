Feature: New `git branch --forked` command for identifying branches with deleted upstreams.

This is the first patch in Harald Nordgren's v5 series implementing standalone branch-pruning functionality. The series has evolved through previous iterations to settle on a clean architectural approach where branch management is handled exclusively through `git branch` commands rather than integrating with `git fetch`.

The `--forked` option introduced here provides the plumbing to identify local branches that "fork" from specified remotes - meaning their configured upstream branches have been deleted. It accepts either remote names (like `origin`) or specific remote-tracking branches (like `origin/main`), and can handle multiple arguments by unioning the results. The implementation includes thorough error checking and validation of input remotes.

Key aspects:
- Core functionality is in `builtin/branch.c` with new `parse_forked_args()` and `branch_is_forked()` helper functions
- Comprehensive test coverage in t3200-branch.sh verifies:
  - Basic remote name matching
  - Specific remote-tracking branch matching
  - Multi-remote union behavior
  - Error cases (unknown remotes, missing arguments)
- Documentation updates explain the new option clearly

This patch lays the groundwork for the subsequent `--prune-merged` functionality in the series while being useful on its own for scripting and inspection. The implementation appears clean and well-tested, with careful attention to edge cases. The separation from fetch operations (a point of earlier discussion) is now clearly established.
