This is **patch 02/12** in Derrick Stolee's v3 series integrating `--path-walk` with `--filter` options in `git pack-objects`.

The patch is a tiny mechanical fix -- five lines changed in `builtin/pack-objects.c`. When `--path-walk` is active, the code now explicitly passes `--objects` to the revision machinery. Previously the path-walk API assumed `--objects` was implied and did not add it; this meant that any attempt to combine `--path-walk` with a `--filter` would hit a fatal error from the revision machinery ("object filtering requires --objects"). The patch also cleans up an outdated comment about "removing" options and keeps the existing line that disables bitmaps when path-walk is active.

This is a straightforward prerequisite for the rest of the series. Nothing controversial: it simply makes the path-walk path satisfy the same `--objects` requirement that the normal pack-objects path already meets, unblocking the filter integration that the remaining patches build on. The motivation is clearly stated, the change is self-contained, and it passes the `GIT_TEST_PACK_PATH_WALK=1` test gate described in the cover letter.
