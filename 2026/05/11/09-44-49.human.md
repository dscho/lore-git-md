Feature: Finalized branch pruning functionality in v6 series with `--prune-merged` command.

This patch introduces the `git branch --prune-merged` command, which safely deletes local branches that were forked from specified remotes but whose upstream branches have been deleted. The key safety mechanisms are:

1. It only prunes branches whose push destination (what `git push` would update) no longer exists on the remote
2. By default, it refuses to delete branches with unpushed commits (unless `--force` is used)
3. It never deletes the currently checked-out branch in any worktree
4. It measures merged-ness against the remote's default branch rather than local HEAD, making the behavior more consistent

The implementation includes comprehensive test coverage in t3200-branch.sh, verifying edge cases like:
- Detached HEAD states
- Missing remote HEAD references
- Multi-remote configurations
- Various merged/unmerged states
- Default branch protection
- Push ref vs upstream ref differences

This is part of a larger v6 series that provides standalone branch cleanup functionality without integrating with `git fetch`. The design appears technically sound with all safety mechanisms preserved and all maintainer feedback addressed. The patch is well-structured with clear documentation updates and thorough test coverage.
