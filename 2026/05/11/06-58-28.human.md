Feature: Finalized branch pruning functionality with multi-remote support in `git branch`.

This is the final patch in Harald Nordgren's v5 series implementing safe branch pruning functionality through standalone `git branch` commands. The series has evolved through architectural discussions to completely decouple branch pruning from fetch operations, settling on explicit `git branch` commands as the interface.

The current patch adds a `--all-remotes` flag that works with both `--forked` (which identifies branches with deleted upstreams) and `--prune-merged` (which safely deletes them). When used, the flag makes the commands operate on all configured remotes rather than requiring explicit remote arguments. The implementation includes:

- New plumbing to collect all remote names when the flag is set
- Updated documentation explaining the flag's behavior
- Comprehensive test coverage verifying:
  - Basic functionality with multiple remotes
  - Error cases (using the flag without `--forked`/`--prune-merged`)
  - Interaction with explicit remote arguments
  - Preservation of existing safety checks

The patch maintains all the safety mechanisms established earlier in the series: protection for checked-out branches, default branch preservation, and the per-branch `branch.<name>.pruneMerged` opt-out. The implementation appears clean and well-tested, with the new functionality fitting naturally alongside the existing commands.

This completes the technical implementation of the feature as agreed in the architectural discussions, providing users with flexible way to manage stale branches while maintaining clear boundaries between different Git commands. The series is now ready for final maintainer consideration.
