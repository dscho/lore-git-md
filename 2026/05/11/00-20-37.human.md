This is a bugfix thread addressing edge cases in `rebase --update-refs` when `rebase.instructionFormat` includes `%d` decorations. The latest email from Junio C Hamano responds to Abhinav Gupta's confirmation that the issue affects non-interactive rebase as well.

The core problem is already well-understood: the rebase machinery incorrectly generates update-ref instructions for non-branch refs like HEAD when decorations are shown. The v3 patch (already reviewed by Phillip Wood and approved by Junio) fixes this by filtering to branch refs only. Abhinav's new example shows the same failure occurs in non-interactive mode, reinforcing that the fix's approach is correct.

Junio pushes back slightly against what he interprets as a potential suggestion to prohibit `%d` in the format entirely, indicating the current branch-ref filtering solution is the preferred path. The thread appears ready for the v3 patch to be picked up, with the parallel issue in `make_script_with_merges()` (which needs the same filtering) remaining as follow-up work.

This is a focused technical discussion where the solution has reached consensus, with the new data point serving to validate rather than change the approach. The patch appears to be queued for inclusion once the author decides how to handle the remaining related fix.
