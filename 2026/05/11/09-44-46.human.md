Feature: Finalized branch pruning functionality in v6 series with refined merged-ness checks.

Harald Nordgren's v6 patch series completes the branch pruning functionality with a key refinement: `--prune-merged` now measures merged-ness against the remote's default branch rather than the candidate's upstream. This makes the behavior more consistent and independent of local checkout state. The series also introduces a `--all-remotes` flag for multi-remote operations and maintains all safety mechanisms from previous versions.

Key technical changes in v6:
1. Merged-ness is now determined by comparing against the remote's default branch (via `refs/remotes/<remote>/HEAD`) rather than the candidate's specific upstream
2. New `--all-remotes` flag works with both `--forked` and `--prune-merged` to operate across all configured remotes
3. Per-branch opt-out via `branch.<name>.pruneMerged` configuration is preserved
4. Checked-out branch protection remains in place for any worktree

The implementation adds infrastructure to resolve each remote's HEAD reference and thread it through the deletion checks. Test coverage has been expanded to verify the new behavior, including cases where the remote HEAD is unset or the local HEAD is detached. The documentation clearly explains that pruning decisions are now based on integration with the remote's default branch rather than local state.

This version represents the culmination of the architectural discussion, with all components now technically complete and all maintainer feedback addressed. The series is ready for final consideration with no remaining open questions.
