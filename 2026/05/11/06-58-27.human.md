Feature: Per-branch opt-out for branch pruning functionality in v5 series.

This patch adds a `branch.<name>.pruneMerged` configuration option that allows specific branches to be exempted from automatic pruning, even when using `git branch --prune-merged`. The option defaults to true but can be set to false for branches that should persist even after their upstream counterparts are deleted - particularly useful for topic branches that go through multiple development cycles.

Key aspects:
- The opt-out is respected even with `--force`, maintaining protection for branches marked this way
- Explicit deletion via `git branch -d` remains unaffected, allowing manual cleanup when desired
- Documentation clearly explain the new config option and its interaction with other commands
- Tests verify the behavior in various scenarios including with --force and alongside manual deletion

This completes the safety mechanisms for the branch pruning feature, giving users fine-grained control over which branches are candidates for automatic cleanup. The implementation appears clean and well-tested, with clear documentation updates. As the final piece of the v5 series, it maintains the architectural separation from fetch operations while providing all the originally promised functionality through standalone branch commands.
