This is a performance optimization patch for the merge-base calculation in large repositories, building on previous feedback from Junio Hamano. The key change allows early termination when only a single merge-base is needed (the common case without `--all`) and generation numbers are available, avoiding the expensive STALE commit frontier processing.

The patch modifies `paint_down_to_common()` to exit immediately after finding the first valid merge-base when generation numbers guarantee no better candidate exists. This provides dramatic speedups - the commit message shows examples going from 5 seconds to 24ms (100x improvement) in a 2.2M-commit monorepo.

Kristofer Karlsson has addressed Junio's review feedback from v1 by:
1. Simplifying the generation number logic (removing the `has_gens` variable)
2. Improving comment wording and formatting
3. Keeping the early-exit logic inline rather than extracting a helper function
4. Adding extensive test coverage across different commit-graph scenarios

The implementation appears careful to maintain correctness while enabling the optimization, with tests verifying behavior with/without commit-graphs, shallow/deep histories, and agreement between `--all` and non-`--all` cases. This looks like a well-justified optimization that could significantly benefit users of large repositories making frequent merge-base queries.
