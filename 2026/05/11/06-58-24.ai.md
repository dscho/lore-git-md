Feature: First patch in the finalized branch pruning series introducing `git branch --forked`.

This patch introduces the foundational `--forked` option for `git branch`, which identifies local branches whose upstreams match specified remote references. The command accepts either remote names (like `origin`) or specific remote-tracking branches (like `origin/main`), unioning multiple arguments. This plumbing command will be used by the `--prune-merged` functionality in subsequent patches.

Key technical details:
- New `parse_forked_args()` handles both remote names and tracking refs
- `branch_is_forked()` checks if a branch's upstream matches the criteria
- Comprehensive test coverage in t3200-branch.sh verifies:
  - Basic remote name matching
  - Specific tracking branch matching
  - Multi-argument union behavior
  - Error cases (unknown remotes, missing arguments)

The implementation appears clean and focused, with clear documentation explaining the new option's behavior. As the first building block in the series, this establishes the branch identification mechanism that the pruning functionality will use while maintaining the architectural separation from fetch operations that was agreed upon in earlier discussion.
