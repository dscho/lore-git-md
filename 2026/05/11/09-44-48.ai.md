Feature: Bulk branch deletion improvements in branch pruning series.

This patch from Harald Nordgren enhances the bulk deletion behavior in the branch pruning functionality by making refusal messages more appropriate for batch operations. The changes allow callers to suppress verbose per-branch advice when doing bulk deletions while still preserving all safety checks.

Key technical changes:
1. Adds `warn_only` parameter to convert hard errors about unmerged branches into one-line warnings during bulk operations
2. Introduces `n_not_merged` counter to track skipped branches without printing individual advice
3. Maintains all safety checks (unmerged branch protection) while making the output more suitable for scripts
4. Preserves existing behavior for single-branch deletions (still shows full advice)

The implementation carefully separates the safety mechanisms from the messaging, ensuring branches with unmerged changes are still protected from accidental deletion. The patch fits into the larger branch pruning series by providing better tooling for the new `--forked` and `--prune-merged` operations while maintaining compatibility with existing `git branch -d` behavior.

This appears to be a well-considered refinement that addresses a real usability issue in bulk operations without compromising safety. The changes are focused and maintainable, with clear parameterization that keeps the single-branch case unchanged while improving the bulk case.
