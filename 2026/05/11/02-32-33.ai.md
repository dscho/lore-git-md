This is a maintainer follow-up on the config file locking timeout patch. Junio C Hamano is considering dropping the patch from his queue due to lack of response to Patrick Steinhardt's earlier concerns, despite having previously accepted the change.

The core issue remains concurrent config file writes failing due to lock contention, particularly affecting `git worktree add -b` operations. The proposed 100ms timeout solution was modeled after reference lock behavior, but Patrick raised two important caveats: (1) config writes lack the conflict detection that reference updates have, meaning concurrent changes could still silently overwrite each other, and (2) the timeout value might need to be configurable like reference timeouts are.

Junio notes that these points went unaddressed in the thread, and after some time without further discussion, he's inclined to discard the patch rather than let it linger indefinitely. This doesn't reflect a technical rejection of the approach, but rather the practical reality of patch maintenance - unanswered questions can stall even reasonable changes.

The email suggests this may be the final word on the topic unless other participants re-engage. The underlying reliability issue with concurrent config writes remains unresolved, but the specific timeout solution appears unlikely to proceed without renewed discussion.
