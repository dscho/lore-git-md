Performance optimization for single merge-base calculation. This is the second patch in a v4 series that speeds up `git merge-base` operations in large repositories by leveraging generation numbers to exit early when only one merge-base is needed (the default case without `--all`).

The patch modifies `paint_down_to_common()` to skip the expensive STALE commit frontier processing once it finds the first valid merge-base with a finite generation number. This provides dramatic speedups (5,229ms -> 24ms in a 2.2M-commit monorepo) while maintaining correctness. The optimization builds on the enum refactoring from the first patch in the series.

Key technical details:
- Only activates when generation numbers are available and finite
- Preserves existing behavior for `--all` cases via the `MERGE_BASE_FIND_ALL` flag
- Includes comprehensive tests covering all commit-graph configurations
- Updates all relevant callers to pass the appropriate flags

The patch appears technically sound and well-tested, having addressed all feedback from previous iterations. It represents a significant performance win for a common case in large repositories while maintaining the project's careful approach to correctness. The optimization is particularly valuable for monorepos with deep commit histories where merge-base calculations are frequent operations.
