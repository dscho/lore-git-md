This is a test-infrastructure patch, the third in a 12-part series integrating `--path-walk` traversal with `--filter` options. It adds a new performance benchmark script, `p5315-pack-objects-filter.sh`, to the `t/perf/` directory.

The benchmark measures `git pack-objects --revs --all` under three filter scenarios (no filter, `blob:none`, and `sparse:oid`) and tests each both with and without `--path-walk`, producing eight paired measurements per repo run. The sparse filter definition is generated automatically from the test repository's directory structure, which is a thoughtful touch -- it samples depth-2 directories at evenly-spaced positions, with sensible fallbacks for flat repos where the sparse tests are skipped entirely. This means the benchmark works on any repo passed via `GIT_PERF_LARGE_REPO` without manual setup.

The current results included in the commit message show that before the rest of the series is applied, `--path-walk` makes no meaningful difference for `blob:none` or `sparse:oid` (the times are essentially identical), and is actually a bit slower for the no-filter case (34.92s vs 27.91s). This is expected -- the point of the benchmark is to have a baseline *before* the filter integration lands, so that the dramatic speedups claimed in the cover letter (e.g., sparse repack going from 72s to 29s) can be measured against a known starting point.

The patch is clean and well-structured. The commit message is clear about what the test does, why it exists, and what the current numbers mean. No issues here.
