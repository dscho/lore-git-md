Maintainer feedback on finalized branch pruning series.

Junio C Hamano provides review comments on patch 2/5 of Harald Nordgren's v5 series implementing standalone branch pruning functionality. The patch modifies the branch deletion machinery to support bulk operations with less verbose output when pruning branches with deleted upstreams.

Junio notes that while existing call sites (like `git branch -d`) will remain unchanged, he raises a design question about whether the new `--prune-merged` functionality should respect the same branch protection rules as single-branch deletion - specifically whether it should consider whether branches are part of HEAD or their tracking branch. He clarifies this is an open question rather than a criticism, stating he has no strong opinion either way.

The patch itself adds two key parameters to the branch handling functions:
1. `warn_only` to suppress verbose error messages during bulk operations
2. `n_not_merged` counter to track skipped branches without per-branch output

All safety checks remain intact - branches with unmerged work are still protected from deletion - but the interface becomes more suitable for bulk operations when used with the new `--forked` and `--prune-merged` commands. The changes are cleanly implemented while maintaining backward compatibility with existing single-branch deletion behavior.

This appears to be a final round of maintainer review before potential merging, with Junio focusing on clarifying the design boundaries rather than requesting changes. The series has reached technical completeness with all components implemented and tested.
