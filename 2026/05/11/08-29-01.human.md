This is a follow-up discussion on CI configuration for expensive tests in the Git project, continuing the thread about Johannes Schindelin's Windows large-object handling series. The exchange between Junio Hamano and Patrick Steinhardt considers whether to make expensive tests (including the >4GB object tests) run unconditionally in CI rather than just on official branches and pull requests.

Junio acknowledges the appeal of Patrick's suggestion to simplify the configuration by always running expensive tests, noting it would provide more comprehensive coverage across all CI events and platforms (including GitLab CI). He contrasts this with the opposite extreme of only running them on specific configurations like "linux-test-vars", which would only make sense if expensive-test failures were platform-independent - something he doubts is true. 

The maintainer concludes that the additional machine resources required for unconditional expensive testing would be a worthwhile tradeoff compared to the human time spent diagnosing issues that broader test coverage might catch. This suggests the project is likely to adopt Patrick's proposed simplification, though no final decision is recorded in this email. The discussion reflects Git's pragmatic approach to balancing CI resource usage against test thoroughness.
