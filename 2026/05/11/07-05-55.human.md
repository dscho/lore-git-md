This is a CI configuration discussion between Patrick Steinhardt and Junio C Hamano about when to run expensive tests in the Git project's continuous integration system. The exchange is part of the larger thread about Johannes Schindelin's series for handling large objects (>4GB) on Windows.

Junio's patch modified `ci/lib.sh` to run expensive tests (including the >4GB object tests) on both pull request builds and integration branch pushes, rather than just the latter. This was meant to catch issues earlier in the development cycle.

Patrick Steinhardt now suggests that if these are the only two cases where tests run, it might make sense to enable expensive tests unconditionally. He notes this would also cover GitLab CI jobs, which currently don't run expensive tests under this configuration. The implication is that there's no real downside to broader test coverage if we're already running these tests in the main scenarios.

This is a substantive but focused technical discussion about CI strategy - whether to make the expensive test coverage universal rather than conditional. It shows the project carefully considering how to balance test thoroughness with resource usage. The change would affect all future test runs, not just the Windows large objects series.
