Feature: Finalized branch pruning with multi-remote support via `--all-remotes` flag.

This patch completes the v6 series by adding the `--all-remotes` flag to both `--forked` and `--prune-merged` operations in `git branch`. The flag enables acting on all configured remotes rather than requiring explicit remote arguments, while maintaining all the safety mechanisms established in previous patches.

Key technical aspects:
1. New `--all-remotes` flag works with both `--forked` (listing branches) and `--prune-merged` (deleting branches)
2. When used, it collects all configured remotes via `for_each_remote()` in addition to any explicitly specified remotes
3. Maintains all existing safety checks:
   - Still requires `--force` for branches with unpushed work
   - Respects `branch.<name>.pruneMerged` configuration
   - Protects checked-out branches in any worktree
4. Includes comprehensive test coverage for:
   - Basic functionality with multiple remotes
   - Error cases (invalid remote names, standalone usage)
   - Interaction with existing safety mechanisms

The implementation builds on the series' established architecture while expanding its scope to handle multi-remote repositories more conveniently. The test suite verifies both the happy path and edge cases, including proper error messaging when the flag is used incorrectly.

This appears to be the final piece of the branch pruning functionality, completing the design that was discussed and refined through multiple iterations of the series. The implementation is clean and maintains the separation of concerns established in earlier patches.
