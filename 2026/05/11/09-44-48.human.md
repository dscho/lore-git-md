Feature: Bulk branch deletion improvements in the branch pruning series.

This patch modifies the branch deletion machinery to better support bulk operations by making merge-check failures non-fatal when requested. It's part of Harald Nordgren's v6 series implementing standalone branch pruning commands (`git branch --forked` and `git branch --prune-merged`).

The key change introduces two new parameters to the deletion functions:
- `warn_only` converts merge-check failures from errors to warnings while still skipping deletion
- `n_not_merged` counts skipped branches for bulk operation summaries

Existing callers (like `git branch -d`) remain unchanged, continuing to treat unmerged branches as errors. The new parameters will be used by the upcoming `--prune-merged` command to provide a summary of skipped branches rather than verbose per-branch advice.

The implementation maintains all safety checks - branches with unpushed work are still protected unless forced - but makes the output more suitable for automated cleanup scenarios. This is a focused plumbing change that enables the higher-level pruning functionality while keeping the existing branch deletion behavior intact.

The patch follows the series' established pattern of careful, incremental changes to the branch machinery. It demonstrates good attention to backward compatibility and provides clean hooks for the bulk operations coming in the series.
