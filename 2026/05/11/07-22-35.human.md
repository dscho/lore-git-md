This is a review comment on a performance optimization patch for merge-base calculations in large repositories. Patrick Steinhardt suggests improving the readability of the boolean flags in the `paint_down_to_common()` function by converting them to an enum with named flags.

The patch (v2) had already addressed Junio's earlier review feedback about the core optimization, which speeds up single merge-base queries by exiting early when generation numbers are available. The optimization provides 100x speedups in large monorepos while maintaining correctness.

Patrick's comment focuses on code style rather than the optimization itself. He notes that the current implementation with multiple boolean parameters makes the calling code harder to read, and proposes using an enum with bit flags instead. This would make the callsites more self-documenting, though he acknowledges it would be more verbose. He also points out a potential complication - these flags are passed through multiple function layers.

This is a substantive review suggestion that would affect the API design, though it doesn't challenge the core optimization logic. The author will need to decide whether to implement this change in a v3 or keep the current approach. The tradeoff is between readability and verbosity in the calling code.
