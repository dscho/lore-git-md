Feature: Finalized branch pruning functionality in v6 series with `--prune-merged` implementation.

This patch introduces the `--prune-merged` option to `git branch`, completing the branch pruning functionality alongside the previously added `--forked` flag. The new command safely deletes local branches that were forked from now-deleted remote branches, with several key safety mechanisms:

1. **Merged-ness checking**: Branches are only deleted if their commits are fully merged into the remote's default branch (via `refs/remotes/<remote>/HEAD`), making the behavior independent of local checkout state. This is a refinement from earlier versions that now uses the remote's default branch rather than the candidate's specific upstream.

2. **Safety protections**: The command preserves:
   - Currently checked-out branches in any worktree
   - The local default branch by name
   - Branches with unpushed work (unless `--force` is used)
   - Branches whose push ref is the remote's default branch

3. **Implementation details**:
   - New infrastructure resolves remote HEAD references for merged-ness comparison
   - Uses `branch_get_push()` to verify push destinations
   - Handles edge cases like missing remote HEAD references
   - Includes comprehensive test coverage in t3200-branch.sh for various scenarios

The patch maintains all the architectural decisions from previous iterations, keeping the functionality as standalone `git branch` commands rather than integrating with fetch. The test suite verifies behavior across:
- Basic deletion cases
- Unpushed work protection
- Detached HEAD states
- Default branch preservation
- Push ref vs upstream ref differences
- Multi-remote scenarios (though the `--all-remotes` flag comes in a separate patch)

This represents the core implementation of the pruning functionality, with subsequent patches in the series adding the `--all-remotes` flag and per-branch configuration options. The design appears technically sound with all maintainer feedback addressed from previous rounds.
