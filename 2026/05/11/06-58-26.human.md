Feature: Finalized branch pruning functionality via standalone `git branch` commands in v5 series.

This patch (3/5 in the series) introduces the `--prune-merged` option to `git branch`, completing the decoupled branch pruning functionality that was previously debated. The command safely deletes local branches whose upstream counterparts have been deleted, with several key protections:

1. It only prunes branches where the push destination ref no longer exists (matching the `--forked` criteria from earlier patches)
2. By default, it refuses to delete branches with unpushed commits (reachability check)
3. The currently checked-out branch is always preserved
4. Default branches (those matching remote HEAD) are protected by name

The implementation includes comprehensive tests covering edge cases like:
- Push refs differing from upstream tracking
- Default branch protection by name vs upstream
- Force deletion of unmerged branches
- Protection of checked-out branches

The patch builds on the architectural consensus to keep branch management separate from fetch operations, providing a clean way to automate branch cleanup through explicit commands rather than implicit fetch behavior. The safety mechanisms appear well-considered, and the test coverage is thorough.

This represents the core functionality of the series, with the remaining patches focusing on bulk operation improvements and documentation. The implementation looks solid and ready for final review.
