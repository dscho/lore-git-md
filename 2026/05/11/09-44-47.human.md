Feature: New `--forked` option for `git branch` to identify branches with deleted upstreams.

This is the first patch in Harald Nordgren's v6 series implementing standalone branch pruning functionality. It introduces a new `git branch --forked` command that lists local branches whose upstream branches have been deleted on the remote. The command accepts either remote names (like `origin`) or specific remote-tracking branches (like `origin/main`) as arguments, and unions the results when multiple arguments are given.

The implementation includes:
- New `parse_forked_args()` to handle remote name vs remote-tracking branch arguments
- `branch_is_forked()` helper to check if a branch's upstream matches any of the given remotes
- Comprehensive test coverage in t3200-branch.sh for various scenarios including multiple remotes and error cases

This provides the plumbing needed by the subsequent `--prune-merged` patch (which will actually delete these branches) while maintaining all the safety mechanisms discussed in the thread. The patch appears well-structured with clear documentation and thorough tests covering the expected use cases.
