Feature: Final version of standalone branch pruning commands, dropping fetch integration.

Harald Nordgren's v5 series completes the evolution of the branch pruning functionality by fully removing the `fetch --prune-merged` integration that was present in earlier versions. This follows the architectural decision to keep branch management separate from fetch operations, as advocated by Johannes Sixt and accepted by Junio Hamano.

The series now provides a clean set of `git branch` commands for local branch cleanup:
- `--forked` identifies branches whose upstreams no longer exist
- `--prune-merged` safely deletes branches merged into their upstreams
- `--all-remotes` applies operations across all remotes
- `branch.<name>.pruneMerged` allows per-branch opt-out

The implementation appears thorough, with:
- Careful handling of default branch protection (carried over from v4)
- Bulk deletion optimizations
- Comprehensive test coverage in t3200-branch.sh
- The only change from v4 is the removal of `fetch --prune-merged` (patch 4/5 dropped)
- All safety mechanisms remain intact, including reachability checks and default branch protection
- The documentation has been updated to remove references to fetch integration

This version represents the settled design direction for this feature, with clear boundaries between branch management and fetch operations. The functionality remains useful for automation through standalone `git branch` commands or periodic execution, just without direct fetch integration. The series appears ready for final consideration.
