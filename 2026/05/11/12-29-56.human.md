This is the second patch in Patrick Steinhardt's two-part bugfix series for Git's maintenance mode. It addresses a regression where the `gc.auto` configuration was no longer respected after Git switched from using `git gc` to `git maintenance` for automatic maintenance tasks.

The patch fixes the behavior so that when `gc.auto=0` is set, auto-maintenance will be skipped, matching the historical behavior users expect. The change modifies `run-command.c` to properly check both `maintenance.auto` and `gc.auto` configurations, with `maintenance.auto` taking precedence when both are set.

The commit includes thorough test coverage in `t/t7900-maintenance.sh`, adding new test cases that verify:
- Both `maintenance.auto` and `gc.auto` configurations work independently
- `maintenance.auto` correctly overrides `gc.auto` when both are set
- The expected subcommands are (or aren't) run based on the configuration

This is a straightforward fix for a clear regression, with comprehensive tests that should prevent future breakage. The patch builds on Patrick's expertise with the maintenance subsystem and follows the pattern of his previous maintenance improvements. Given the clear motivation and test coverage, this change is likely to be uncontroversial.
