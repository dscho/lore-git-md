This is a follow-up email in the interface design discussion for the `git add -p` word-diff feature.

D. Ben Knoble responds to Junio C Hamano's earlier email about the tension between single-letter shortcuts and extensible command syntax. Knoble agrees with Junio's observation about not wanting to consume a new letter ('w') for every future diff view option, and elaborates on his previous `:show <opts>` idea by directly addressing the single-key user concern Junio raised.

Knoble suggests two possible compromises to accommodate both audiences. One is to let `p`/`P` (the existing "print" command) accept optional arguments in non-single-key mode, so users who mash a single key still get the current behavior, while those who want to customize can type `p --word-diff`. The other is to introduce `:` as a new "escape" that is explicitly exempt from single-key mode -- hitting `:` would always accept a longer command, the first of which could be `print` with options.

This is a thoughtful design contribution from a contributor who clearly cares about the interaction model (he even notes he uses Vim, which uses a similar `:` prefix for commands). He is not trying to push a specific solution but rather sketching concrete ways to have both extensibility and single-key convenience. It is the kind of email a maintainer would find useful when weighing the next iteration.
