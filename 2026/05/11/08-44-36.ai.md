This is a follow-up discussion in Harald Nordgren's branch pruning series, responding to Junio Hamano's question about how `--prune-merged` should handle checked-out branches. Harald agrees with the suggestion that pruning behavior should be consistent regardless of which local branch is currently checked out, rather than comparing against HEAD.

The author reports observing unexpected behavior when running from non-main branch, confirming Junio's architectural point. Harald commits to modifying the implementation to make pruning behavior consistent by always comparing against the remote's default branch rather than the current HEAD.

This exchange represents the final design refinement in the technically complete v5 series, addressing the last remaining architectural question about branch state handling. The change will make the behavior more predictable and align with the principle of remote-tracking branch comparison that underlies the feature.
