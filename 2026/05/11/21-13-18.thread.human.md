This thread is a feature proposal from Thorsten Glaser to allow Git users to configure which shell is used to run alias commands, rather than always hard-coding `/bin/sh`. The author asks for a config key — suggesting `core.shell` with an example of `core.sh = /bin/mksh` — to give users the option of using a non-POSIX shell with specific features they rely on in aliases. No patch, reproduction steps, or implementation analysis are provided; this is a request only, not a substantive development submission.

The email raises a reasonable quality-of-life concern: there are real cases where alias syntax depends on shell-specific features not found in `/bin/sh`. However, the proposal does not address any of the significant trade-offs involved — changing the shell affects Git's entire shell-command spawning path across platforms, and would introduce portability concerns on systems where `/bin/sh` is the only reliable option. No other participants have yet chimed in with use cases, constraints, or implementation ideas, so the thread is effectively in a "waiting for discussion" state. Anyone interested in pursuing this should weigh in with concrete scenarios before any patches are written.
