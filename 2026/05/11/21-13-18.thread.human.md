Thorsten Glaser's original request for a `core.shell` config option got a firm rebuttal from Brian M. Carlson, who explained that `/bin/sh` is hard-coded by design: it ensures consistent alias behavior system-wide, avoids quoting and security problems with arbitrary shells, and is already overridable at build time via `SHELL_PATH`. No other participants weighed in.

Now Thorsten has replied and effectively withdrawn the ask. He acknowledges he initially misunderstood the "with-shell" vs "without-shell" command modes (aliases use the former), and reports that the alias that prompted the request was not actually using a mksh-specific feature -- it was a recent POSIX construct that his customer's `/bin/sh` happened not to support. Rewording the alias solved the problem. The only forward-looking remark -- pointing to a portable mksh on macOS -- was offered as a casual thought, not a proposal.

The thread is closed. Neither Thorsten nor anyone else has offered a redesign that addresses Brian's objections, so `core.shell` is not going anywhere unless a new proponent takes up the idea.
