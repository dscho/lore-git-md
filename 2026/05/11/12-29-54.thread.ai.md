Thread identity: Two-patch series from Patrick Steinhardt fixing maintenance mode issues in Git, targeting bugs in `--detach` lockfile handling and `gc.auto` threshold checking. Series at v1; a v2 will be needed for the patch 2 correctness issue.

Core problem/goal: Correct two maintenance subsystem issues -- (1) lockfile release in `--detach` mode causing subsequent runs to fail, and (2) restore expected `gc.auto` threshold behavior after transition from `git gc` to `git maintenance` while maintaining backward compatibility.

Current status: Complete v1 series posted, targeting Git 2.54.0 base. Patch 1 has been reviewed by the maintainer with no blockers (see below). Patch 2 has a substantive correctness issue raised by Jeff King and will need revision. Changes span:
- `builtin/gc.c` (maintenance logic)
- `run-command.c` (detached process handling and config evaluation)
- Lockfile API (`lockfile.c/h`)
- 95 lines of new tests in `t/t7900-maintenance.sh`

Key technical details:
- Patch 1: Adds proper lockfile cleanup in `run_processes_parallel_tr2()` for detached mode. No correctness concerns raised.
- Patch 1 code: A new `daemonize_without_exit()` wrapper exists; Junio noted the `#ifdef NO_POSIX_GOODIES` duplication between this wrapper and the inner function is less-than-ideal but unavoidable because the `die_errno()` call for fork failure means the conditional must remain in the caller, and changing that is out of scope. Junio also observed that a comment in `maintenance_run_tasks()` saying "we assign ownership of the lockfile to the child" is misleading since any non-own-PID would do; he suggested phrasing like "we relinquish ... to prevent us removing upon exiting" would be clearer. Both are conversational observations, not demands for revision.
- Patch 2: Restores `gc.auto` behavior while respecting newer `maintenance.auto` precedence. Modifies `prepare_auto_maintenance()` to check both configs. Maintains backward compatibility for existing `gc.auto=0` users. Adds tests verifying config precedence and edge cases. Fixes user-reported regression (Jean-Christophe Manciot).
- **Substantive review issue (Jeff King)**: Patch 2 uses `repo_config_get_bool()` to read `gc.auto`, but `gc.auto` is not a boolean -- it is an integer specifying the loose-object count threshold. The value "0" is falsy in both bool and int contexts, but a value like `gc.auto=100` would produce fragile/incorrect behavior. The existing `git gc` code uses `repo_config_get_int()` for this config key. This is a real correctness issue that the author must address.

Open questions and loose ends:
- Patch 2 will need revision to read `gc.auto` as an integer rather than a boolean. This is the blocker before the series can advance.
- Patch 1 is ready to proceed; both of Junio's observations are conversational and do not block it.
- No reviews from maintenance subsystem experts (Derrick Stolee, Taylor Blau) yet.
