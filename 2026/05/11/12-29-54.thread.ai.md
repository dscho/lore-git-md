**Key technical details**:

Junio's observations: (a) the `#ifdef NO_POSIX_GOODIES` duplication in the `daemonize_without_exit()` wrapper is unavoidable because the `die_errno()` call for fork failure means the conditional must remain in the caller -- deferred to a future cleanup series, and (b) a comment saying "we assign ownership of the lockfile to the child" should instead say "we drop ownership ... to prevent us removing it upon exit" since any non-own-PID would suffice -- Patrick has confirmed this wording change for v2.
- Patch 2: Restores `gc.auto` behavior while respecting newer `maintenance.auto` precedence. Modifies `prepare_auto_maintenance()` to check both configs. Maintains backward compatibility for existing `gc.auto=0` users. Fixes user-reported regression (Jean-Christophe Manciot). Critical issue: uses `repo_config_get_bool()` for `gc.auto`, which is an integer config key (the loose-object count threshold). Both Jeff King and Junio C Hamano raised this; Patrick Steinhardt has accepted the finding and will fix it in v2. The correct fix is `repo_config_get_int()`, per the existing `git gc` code.
