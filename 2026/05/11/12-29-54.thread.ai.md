**Thread identity**: Two-patch v3 bugfix series from Patrick Steinhardt fixing maintenance mode issues in Git, targeting Git 2.54.0.

**Core problem/goal**: Correct two maintenance subsystem issues: (1) lockfile release in `git maintenance run --detach` mode causing stale locks that block subsequent runs, and (2) restore expected `gc.auto` integer-threshold behavior after the transition from `git gc` to `git maintenance` while maintaining backward compatibility. The `gc.auto` regression root cause: when the default maintenance strategy stopped shelling out to `git gc`, the code path that previously hit `git gc`'s own config check was broken; the newer `maintenance.auto` was the only key checked, so `gc.auto=0` no longer suppressed automatic maintenance. The fix reads `maintenance.auto` first (takes precedence), falling back to `gc.auto` as an integer when unset. If `gc.auto` is 0 or negative, maintenance is disabled.

**Current status**: Both patches ready for merge. No outstanding concerns. Patch 1 (lockfile) now at v3 with Taylor Blau's alternative design incorporated. Patch 2 (`gc.auto`) unchanged from v2 and fully settled. The v3 cover letter signals readiness for merge.

**Key technical details**:
- Patch 1: When `git maintenance run --detach` runs, the parent creates a lockfile but exits immediately after forking, releasing the lock before the child completes. The fix: `daemonize()` in `setup.c` now automatically reassigns all open tempfiles and lockfiles from the parent PID to the child PID after forking. A new helper `reassign_tempfile_ownership()` in `tempfile.c`/`tempfile.h` walks the linked list of active tempfiles and updates the owner PID for any that match the parent. The parent drops ownership (so its atexit handler does not unlink them on exit), and the child claims ownership (so it cleans them up when it eventually exits). Only other caller is `daemon.c`, which creates no tempfiles before calling `daemonize()`, so it's a no-op there. The `#ifdef NO_POSIX_GOODIES` duplication in `setup.c` is acknowledged as messy but deferred to a follow-up. Files: `builtin/gc.c`, `setup.c`, `setup.h`, `tempfile.c`, `tempfile.h`. Test in `t/t7900-maintenance.sh` is an elaborate FIFO-based integration test verifying the lock is held until the child exits.
- Patch 2: Restores `gc.auto` behavior while respecting newer `maintenance.auto` precedence. Modifies `prepare_auto_maintenance()` in `run-command.c` to check both configs. The fallback pattern matches the existing approach for `autoDetach` keys (`maintenance.autoDetach` and `gc.autoDetach`). Maintains backward compatibility for existing `gc.auto=0` users. Fixes user-reported regression by Jean-Christophe Manciot. Files: `builtin/gc.c`. New tests in `t/t7900-maintenance.sh` covering five cases: default behavior (maintenance runs), `gc.auto=1` (maintenance still runs), `gc.auto=0` (maintenance suppressed), `maintenance.auto` overriding `gc.auto` in both directions (false overrides 1, true overrides 0).
- The v2->v3 change for patch 2 is purely a resubmission to stay coherent with v3 of patch 1; no code or commit message changes.
