**Thread identity**: Two-patch v2 bugfix series from Patrick Steinhardt fixing maintenance mode issues in Git. Series at v2; the only substantive change from v1 is the type correction in patch 2. Targeting Git 2.54.0.

**Core problem/goal**: Correct two maintenance subsystem issues: (1) lockfile release in `git maintenance run --detach` mode causing stale locks that block subsequent runs, and (2) restore expected `gc.auto` integer-threshold behavior after the transition from `git gc` to `git maintenance` while maintaining backward compatibility. The `gc.auto` regression has a detailed root cause: when the default maintenance strategy stopped shelling out to `git gc`, the code path that previously hit `git gc`'s own config check was broken; the newer `maintenance.auto` was the only key checked, so `gc.auto=0` no longer suppressed automatic maintenance. The fix reads `maintenance.auto` first (takes precedence), falling back to `gc.auto` as an integer when unset. If `gc.auto` is 0 or negative, maintenance is disabled.

**Current status**: V2 series posted, but now has a new open design question on patch 1. Taylor Blau's substantive review advocates for a different implementation strategy for the lockfile ownership transfer -- performing it automatically inside `daemonize()` rather than via a new `daemonize_without_exit()` introduced at the single call site in `builtin/gc.c`. Taylor feels "fairly strongly" about this and offers Co-authored-by and Signed-off-by lines if Patrick adopts the alternative. Patrick has not yet replied. Patch 2 is fully settled with no outstanding concerns.

**Key technical details**:
- Patch 1: Adds proper lockfile cleanup in `run_processes_parallel_tr2()` for detached mode. Files: `builtin/gc.c`, `lockfile.c`, `lockfile.h`, `run-command.c`, `setup.h`. The contested design point: Taylor wants the ownership transfer folded into `daemonize()` automatically (documented, with `daemonize_without_transfer()` introduced only if a future caller needs it), instead of Patrick's v2 approach of adding `daemonize_without_exit()` at the single call site. Taylor already posted an off-list sketch of this alternative approach. Taylor praised the FIFO-based test as "much more robust" and said the rest of the test "looks good to me."
- Patch 2: Restores `gc.auto` behavior while respecting newer `maintenance.auto` precedence. Modifies `prepare_auto_maintenance()` in `run-command.c` to check both configs. The fallback pattern matches the existing approach for `autoDetach` keys (`maintenance.autoDetach` and `gc.autoDetach`). Maintains backward compatibility for existing `gc.auto=0` users. Fixes user-reported regression by Jean-Christophe Manciot. Files: `builtin/gc.c`. New tests in `t/t7900-maintenance.sh` covering three cases: `gc.auto=1` allows maintenance, `gc.auto=0` suppresses it, `maintenance.auto` overrides `gc.auto` in both directions.
- The `#ifdef NO_POSIX_GOODIES` duplication is acknowledged as cleanable but deferred to a follow-up series, unchanged from v1. Not raised in this email.
