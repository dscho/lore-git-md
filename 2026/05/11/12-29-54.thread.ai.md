**Thread identity**: Two-patch series from Patrick Steinhardt fixing maintenance mode issues in Git, targeting bugs in `--detach` lockfile handling and `gc.auto` threshold checking. Series at v1; a v2 will be needed for patch 2.

**Core problem/goal**: Correct two maintenance subsystem issues -- (1) lockfile release in `--detach` mode causing subsequent runs to fail, and (2) restore expected `gc.auto` threshold behavior after transition from `git gc` to `git maintenance` while maintaining backward compatibility.

**Current status**: Complete v1 series posted, targeting Git 2.54.0 base. Patch 1 reviewed by Junio C Hamano with only conversational observations (no blockers). Patch 2 has a confirmed correctness issue: Junio explicitly endorsed Jeff King's criticism of using `repo_config_get_bool()` for the integer-valued `gc.auto` config key. This closes off debate -- the fix (switch to `repo_config_get_int()`) is straightforward but mandatory before the series can advance. No reviews yet from maintenance subsystem experts Derrick Stolee or Taylor Blau. Files touched: `builtin/gc.c`, `run-command.c`, `lockfile.c`, `lockfile.h`, plus 95 lines of new tests in `t/t7900-maintenance.sh`.

**Key technical details**:
- Patch 1: Adds proper lockfile cleanup in `run_processes_parallel_tr2()` for detached mode. No correctness concerns raised. Junio noted (a) the `#ifdef NO_POSIX_GOODIES` duplication in the `daemonize_without_exit()` wrapper is unavoidable because the `die_errno()` call for fork failure means the conditional must remain in the caller, and (b) a comment in `maintenance_run_tasks()` saying "we assign ownership of the lockfile to the child" is misleading since any non-own-PID would do; he suggested phrasing like "we relinquish ... to prevent us removing upon exiting." Both are conversational observations, not revision demands.
- Patch 2: Restores `gc.auto` behavior while respecting newer `maintenance.auto` precedence. Modifies `prepare_auto_maintenance()` to check both configs. Maintains backward compatibility for existing `gc.auto=0` users. Fixes user-reported regression (Jean-Christophe Manciot). **Critical issue**: Uses `repo_config_get_bool()` for `gc.auto`, which is an integer config key (the loose-object count threshold). A value like `gc.auto=100` would produce incorrect behavior. The existing `git gc` code uses `repo_config_get_int()`. Jeff King raised this; Junio C Hamano explicitly concurred with "Very good point. I was about to send the same message ;-)," confirming the issue is undisputed and must be fixed.

**Open questions and loose ends**:
