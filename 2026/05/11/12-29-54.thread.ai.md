**Thread identity**: Two-patch v2 bugfix series from Patrick Steinhardt fixing maintenance mode issues in Git. Series at v2, heading to v3 for patch 1 only. Targeting Git 2.54.0.

**Core problem/goal**: Correct two maintenance subsystem issues: (1) lockfile release in `git maintenance run --detach` mode causing stale locks that block subsequent runs, and (2) restore expected `gc.auto` integer-threshold behavior after the transition from `git gc` to `git maintenance` while maintaining backward compatibility. The `gc.auto` regression root cause: when the default maintenance strategy stopped shelling out to `git gc`, the code path that previously hit `git gc`'s own config check was broken; the newer `maintenance.auto` was the only key checked, so `gc.auto=0` no longer suppressed automatic maintenance. The fix reads `maintenance.auto` first (takes precedence), falling back to `gc.auto` as an integer when unset. If `gc.auto` is 0 or negative, maintenance is disabled.

**Current status**: Design disagreement on patch 1 has been resolved. Patrick accepted Taylor Blau's alternative implementation strategy. Next iteration (v3) will fold the lockfile and tempfile ownership transfer into `daemonize()` automatically, matching the approach Taylor already shared off-list; Taylor's Co-authored-by and Signed-off-by will likely appear on the commit. Patch 2 is fully settled with no outstanding concerns.
