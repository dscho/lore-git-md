**Thread identity**: Two-patch v3 bugfix series from Patrick Steinhardt fixing maintenance mode issues in Git, targeting Git 2.54.0.

**Core problem/goal**: Correct two maintenance subsystem issues: (1) lockfile release in `git maintenance run --detach` mode causing stale locks that block subsequent runs, and (2) restore expected `gc.auto` integer-threshold behavior after the transition from `git gc` to `git maintenance` while maintaining backward compatibility. The `gc.auto` regression root cause: when the default maintenance strategy stopped shelling out to `git gc`, the code path that previously hit `git gc`'s own config check was broken; the newer `maintenance.auto` was the only key checked, so `gc.auto=0` no longer suppressed automatic maintenance. The fix reads `maintenance.auto` first (takes precedence), falling back to `gc.auto` as an integer when unset. If `gc.auto` is 0 or negative, maintenance is disabled.

**Current status**: Both patches ready for merge with unanimous reviewer agreement. Patch 1 (lockfile) at v3 with Taylor Blau's alternative design incorporated and Junio C Hamano's endorsement. Patch 2 (`gc.auto`) unchanged from v2 where Jeff King (Peff) previously approved. Taylor Blau suggests waiting for Peff's reconfirmation on patch 2 as a formality, though the code is identical to his approved v2 version. Taylor also proposes backporting to v2.54.1 due to the severity of the lockfile issue.

**Key technical details**:
- Patch 1: `daemonize()` in `setup.c` now automatically reassigns all open tempfiles and lockfiles from parent to child PID after forking via new `reassign_tempfile_ownership()` helper in `tempfile.c`. The parent drops ownership (preventing atexit cleanup) while the child claims it. Only other caller (`daemon.c`) creates no tempfiles before `daemonize()`, making this a no-op there. Files: `builtin/gc.c`, `setup.c`, `setup.h`, `tempfile.c`, `tempfile.h`. Test in `t/t7900-maintenance.sh` uses FIFO to verify lock held until child exits.
- Patch 2: Modifies `prepare_auto_maintenance()` in `run-command.c` to check both `maintenance.auto` (precedence) and fall back to `gc.auto` as integer. Maintains backward compatibility for `gc.auto=0` users. Files: `builtin/gc.c`. Tests cover five cases in `t/t7900-maintenance.sh`.
