This is the final patch in Kristoffer Haugsbakk's feature series introducing `git format-rev`, a new command for on-demand pretty formatting of revisions from stdin. The series has undergone five iterations with thorough review from Phillip Wood (substantive feedback on stream safety and NUL-handling) and René Scharfe (style consistency).

The command provides two main modes:
1. `--stdin-mode=revs`: Processes one revision per line/record
2. `--stdin-mode=text`: Finds and formats commit object names in freeform text

Key features include:
- NUL-termination support via `-z`, `--null-input`, and `--null-output` options
- Safe interactive operation using `maybe_flush_or_die()`
- Support for notes display via `%N` format specifier
- Comprehensive test coverage including edge cases and failure modes

The implementation builds on infrastructure refactored in earlier patches, sharing code with `git name-rev` while adding new formatting capabilities. The documentation has been refined through multiple iterations, with v5 focusing on:
- Fixing AsciiDoc formatting for nested definition lists
- Clarifying NUL-handling behavior in text mode
- Simplifying example object names
- Improving wording about the command's advantages

The command fills a gap in Git's tooling by providing flexible commit formatting for stdin input scenarios that existing commands like `git log` and `git show` don't handle well, particularly when processing mixed input or needing to preserve input order with duplicates. It's marked as EXPERIMENTAL to allow for interface refinement based on real-world usage.

The patch series demonstrates excellent patch hygiene with clear separation of concerns, incremental progression from refactoring to implementation, and responsiveness to reviewer feedback. The final version appears ready for inclusion, pending any final maintainer feedback.
