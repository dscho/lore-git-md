This is a review of Christian Couder's URL-based promisor remote auto-configuration series (v2 7/8), which implements automatic creation of remote configurations when a server advertises a promisor remote URL that matches an allowlist pattern.

Toon Claes provides a substantive review, focusing on two key technical points:

1. He questions whether the name generation logic could cause issues when URLs lack paths (resulting in names like "example-com-8443"), but confirms the collision handling with numeric suffixes would prevent problems.

2. He raises an important documentation question about the interaction between `promisor.acceptFromServer` and `promisor.acceptFromServerUrl` - specifically whether URL-based auto-configuration should work when `acceptFromServer` is set to "all" rather than "none". This appears to be an intentional design choice that should be documented more clearly.

The review confirms the security mechanisms and test coverage are thorough, while identifying areas where the behavior could be more explicitly documented. This comes after Patrick Steinhardt and Junio have already given positive feedback on the series, suggesting the core functionality is sound but final polish is needed on edge case documentation.

The patch appears ready for merging pending clarification of the configuration precedence rules between the two related settings.
