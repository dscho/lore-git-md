This is the fourth patch in Kristoffer Haugsbakk's v5 series introducing the `git format-rev` command. The patch adds a dedicated test case for the `--annotate-stdin --name-only` option combination in `git name-rev`.

The test ensures proper handling of name-only output when processing stdin input, which was recently refactored to use a new `struct command` infrastructure in patch 3. The author notes this catches potential regressions where the name-only flag might be incorrectly handled in the stdin processing path, even though existing tests would still fail - just not for the right reasons.

The test follows the pattern of:
1. Generating expected output by calling `git name-rev --name-only` on each commit
2. Sorting the results for comparison
3. Verifying the same output comes from the stdin-processing variant

This represents careful attention to test coverage for the refactored code paths. The patch maintains the series' high standard of thorough testing and clear commit messages explaining the motivation. As part of a well-reviewed series that's now in its fifth iteration, this test addition shows the author's continued diligence in ensuring all edge cases are covered before final submission.
