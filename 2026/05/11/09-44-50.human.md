This is the 4th patch in Harald Nordgren's v6 series implementing safe branch pruning functionality. The series introduces new `git branch --forked` and `--prune-merged` commands to identify and clean up local branches whose upstream counterparts have been deleted.

This particular patch adds a per-branch opt-out mechanism via `branch.<name>.pruneMerged=false`. When set, this configuration exempts the branch from being pruned by `--prune-merged`, even when using `--force`. This is useful for keeping topic branches around between development rounds while still allowing explicit deletion via `git branch -d`.

The implementation:
- Adds documentation for the new config option
- Modifies the pruning logic to check the config before deletion
- Includes comprehensive tests verifying:
  - Basic opt-out functionality
  - Interaction with `--force`
  - That explicit `branch -d` still works
  - Proper warning messages

The patch maintains all the safety mechanisms from previous iterations while adding this new flexibility. It's a straightforward addition that completes the feature set for the branch pruning functionality. The series appears technically sound and ready for final consideration.
