Feature patch extending `--track` with a "fetch" mode to automatically fetch remote refs before branch creation.

This is the eighth iteration of Harald Nordgren's proposal to streamline the workflow of fetching before creating a tracking branch. The v8 patch makes a small but important fix to the ref resolution logic, addressing a technical issue identified in v7's review.

Key changes in v8:
1. Fixes the ref resolution logic to properly handle the fallback case when checking for existing remote-tracking refs, using the input argument directly rather than reconstructing it
2. Maintains all the robust error handling and edge case coverage from v7

The implementation remains thorough, with:
- Careful handling of remote refspec configurations
- Proper error recovery when fetches fail but refs exist
- Comprehensive test coverage (12 test cases)
- Clear documentation of the new behavior

While the technical refinement continues, the philosophical disagreement with the maintainer about the feature's appropriateness remains unresolved. The parallel `--autostash` work mentioned in earlier threads still hasn't been submitted for review.

This remains a well-crafted feature that would provide concrete workflow improvements, though its path to acceptance remains uncertain due to the maintainer's workflow objections. The v8 iteration shows the author's continued commitment to technical excellence in the implementation.
