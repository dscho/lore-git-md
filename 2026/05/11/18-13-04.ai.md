This is patch 07/12 of the v3 series integrating `--filter` support into the `--path-walk` API, specifically adding `blob:limit=<size>` support.

The patch extends the path-walk API to handle `blob:limit` natively. In `prepare_filters()`, the limit value is stored in a new `info->blob_limit` field and the filter is cleared from `revs` so that `prepare_revision_walk()` does not reject the configuration. A limit of zero degenerates to `blob:none`, so `info->blobs` is set to 0 in that case.

During `walk_path()`, blob batches are filtered per-object: each blob's size is checked via `odb_read_object_info()`, and only blobs strictly smaller than the limit are included in the batch delivered to the callback. Blobs whose size cannot be determined (e.g. missing in a partial clone) are conservatively included, matching the existing list-objects-filter behavior. Empty batches after filtering are skipped.

The implementation notes a specific interaction with `git backfill`: `odb_read_object_info()` will download a missing blob on-demand, which defeats the purpose of backfill's batch-download strategy. So `builtin/backfill.c` adds its own extra check to reject `blob:limit` explicitly with a new error message. The existing rejection test is updated to expect this new message.

The test additions are thorough: a `blob:limit=0` test confirming equivalence to `blob:none` (emitting no blobs at all), and a `blob:limit=3` test that exercises partial filtering within a batch where some blobs are kept (`left/b`, `right/c`, `right/d`) and others are excluded -- notably blobs in the `a/` subtree are kept, but the `a` blob at the root-level tree is not, confirming the filter works correctly. The documentation in `git-pack-objects.adoc` is updated to list `blob:limit=<n>` alongside `blob:none` as a supported filter form (though the pre-existing typo "Whe" remains).

This is a straightforward, well-structured patch that handles the main case cleanly. The design choice to check blob sizes per-object in the batch (rather than batch-level filtering) is the only plausible alternative; there is no obvious way to do it more efficiently without knowing blob sizes ahead of time. The `backfill` guard is a sensible precaution. The tests are comprehensive and include both the degenerate and the partial-filter case. A reader can expect this patch to land as-is.
