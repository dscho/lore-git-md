This is a patch in the v5 series implementing standalone branch pruning functionality via `git branch` commands. The series has already settled the architectural debate about keeping this functionality separate from fetch operations.

This particular change modifies the branch deletion logic to be more flexible for bulk operations. It adds two new parameters to `delete_branches()` and its helper `check_branch_commit()`:

1. `warn_only` - When set, converts hard errors about unmerged branches into one-line warnings while still skipping those branches from deletion. This prevents noisy output during bulk operations while maintaining safety.

2. `n_not_merged` - An optional counter that tracks how many branches were skipped due to being unmerged, allowing bulk callers to provide a summary rather than per-branch advice.

The patch maintains all existing safety checks (verifying branch reachability, protecting unpushed work) while making the output more suitable for automated use cases. The core behavior remains unchanged for single-branch deletions (`git branch -d`), which will still show the full error message and advice.

This appears to be a well-considered refinement of the branch deletion interface, keeping the safety mechanisms while making the plumbing more flexible for scripting scenarios. The implementation is clean and maintains backward compatibility with existing callers.
