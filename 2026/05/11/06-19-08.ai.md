Performance optimization for merge-base calculation in large repositories. This is the second version of a patch that speeds up single merge-base queries by exiting early when generation numbers are available, avoiding the expensive STALE commit frontier drain.

The key change is that when only one merge-base is needed (the common case without `--all`), the algorithm can stop after finding the first valid merge-base when generation numbers guarantee no better candidate exists. This provides dramatic speedups - the commit message shows examples going from 5 seconds to 24ms (100x improvement) in a 2.2M-commit monorepo.

The patch addresses Junio's review feedback from v1 by:
1. Simplifying the generation number logic by dropping the `has_gens` variable
2. Making the early exit condition clearer (just `!find_all && generation < INFINITY`)
3. Fixing comment formatting to match Git style
4. Keeping the logic inline rather than extracting a helper function

The implementation is well-tested with new cases that verify:
- Behavior matches with/without commit-graphs
- Results agree between `--all` and non-`--all` cases
- Correctness in both shallow and deep commit histories

This appears to be a solid optimization that maintains correctness while providing significant performance benefits for large repositories. The changes are focused and the test coverage is thorough. The patch should be ready for merging after incorporating Junio's stylistic suggestions.
