This is the first patch in Kristoffer Haugsbakk's v5 series introducing the new `git format-rev` command. It's a preparatory style cleanup patch that brings the code in `builtin/name-rev.c` into compliance with Git's coding guidelines regarding brace usage in conditionals.

The change is mechanical and straightforward - it adds braces around both branches of two if-else statements where previously only one branch had braces. This matches the project's style guideline that when any arm of a conditional requires braces, all arms should use braces for consistency. The patch follows the series' pattern of separating mechanical changes from functional work, with patches 1-2 handling style cleanup before the later patches introduce new functionality.

The changes affect:
1. The `get_rev_name` function's output formatting logic
2. The `name_rev_line` function's hex character detection

This is a clear example of the project's emphasis on code hygiene - even in a feature series, taking the time to clean up surrounding code before adding new functionality. The patch has already been through one revision (v2) to fix a stray formatting issue with `(p+1)`.
