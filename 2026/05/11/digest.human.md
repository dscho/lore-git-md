# Git Mailing List Daily Digest — 2026/05/11 (Monday)

**The day in brief.** A heavy-traffic Monday with 114 emails across 31 active threads. The day's dominant story is the v3 submission of Derrick Stolee and Taylor Blau's 12-patch series integrating `--path-walk` with `--filter` in `git pack-objects` — a substantial architectural change that has received no substantive review discussion despite its size. Also notable: the daemonized maintenance locking bug reaches a resolution point as Jeff King endorses Taylor Blau's comprehensive tempfile-ownership fix over a narrower alternative, and Junio's "What's cooking" report tracks several features nearing graduation.

## Notable threads

**`pack-objects --path-walk --filter` reaches v3.** Derrick Stolee and Taylor Blau posted the third iteration of their 12-patch series making `--path-walk` work with `blob:none`, `blob:limit`, `sparse:oid`, `tree:0`, `object:type`, and `combine` filters. The core architectural decision in v3 moves filter logic into the path-walk API itself rather than keeping it in `builtin/pack-objects.c`. Performance data is striking: `sparse:oid` repacks on the Git repository drop from 77.91s to 31.41s. The series also fixes a correctness bug where directly-requested objects could be silently dropped when a filter was active, uncovered by running the test suite with `GIT_TEST_PACK_PATH_WALK=1`. Taylor Blau caught a one-character typo ("Whe" -> "The") in the documentation; Stolee confirmed it will be fixed in v4. The series has received no substantive review of any patch's technical content — the only review to date is that single surface-level typo correction.

**Daemonized maintenance locking fix reaches a decision point.** The thread about repository corruption from `git maintenance run --detach` — where the parent process's atexit handlers release locks the child still needs — saw Jeff King endorse Taylor Blau's comprehensive approach of transferring all tempfile ownership during daemonization, over Patrick Steinhardt's narrower lockfile-only proposal. Peff argued the fix belongs in `daemonize()` itself, not as a per-caller responsibility, and offered a refinement: have the parent reassign ownership to "0" before `fork()`, then reclaim ownership if the fork fails. This eliminates the double-delete risk while keeping the worst case as a stale lock if the child dies before claiming ownership — an already-possible outcome. Peff also confirmed Windows is not a blocker (daemonize is a no-op there) and proposed a concrete test strategy using SIGTERM on a long-running maintenance task. The remaining open question is Derrick Stolee's acceptance of the fix-forward direction.

**Branch pruning series reaches v6 with maintainer pushback.** Harald Nordgren's v6 series implementing `git branch --forked` and `--prune-merged` is technically complete with all agreed functionality — standalone branch commands, per-branch opt-out via `branch.<name>.pruneMerged`, and `--all-remotes` support. But Junio pushed back on a v6 refinement: `--prune-merged` now checks merged-ness against the remote's default branch (`refs/remotes/<remote>/HEAD`) rather than the branch's specific upstream. Junio argues this is wrong — a local branch tracking `origin/todo` may have nothing in common with `origin/HEAD` — and notes the existing `branch_merged()` function already does the right thing by checking the specific upstream. The core feature direction remains viable, but this detail needs to be reverted before the series can proceed.

**Merge-base optimization split into two clean patches.** Kristofer Karlsson's performance optimization for single merge-base calculations — providing a 100x speedup (5s to 24ms) in a 2.2M-commit monorepo — reached v4, now split into two commits per Patrick Steinhardt's suggestion: a pure refactoring introducing `enum merge_base_flags`, followed by the generation-aware early-exit logic. Junio's v2 review feedback (simplifying the generation check, fixing comment formatting) has been incorporated. The series appears merge-ready with all substantive feedback addressed.

**What's cooking: sideband sanitization held for Git 3.0.** Junio's biweekly status report notes several graduates to `master`: parallel hook execution (Adrian Ratiu), Rust-by-default (brian m. carlson), promisor remote refactoring (Christian Couder), and test suite hardening (Patrick Steinhardt). The sideband control character sanitization series is ready to graduate from `next` to `master`, but Junio plans to hold the final patch (which would loosen restrictions) until Git 3.0 to gather real-world feedback on the stricter defaults. The `kh/name-rev-custom-format` topic introducing `git format-rev` was marked ready for `next` but is temporarily delayed at Kristoffer Haugsbakk's request to fix an AsciiDoc formatting issue.

## In brief

**`git format-rev` v5 posted** -- Kristoffer Haugsbakk submitted the fifth iteration of his series introducing a new command for on-demand pretty formatting of revisions from stdin. The series has undergone thorough review from Phillip Wood (stream safety, NUL-handling) and René Scharfe (style consistency). v5 focuses on documentation refinements: fixing AsciiDoc nested list formatting, clarifying NUL-handling in text mode, and simplifying example object names. The command is marked EXPERIMENTAL to allow interface refinement based on real-world usage.

**`git interpret-trailers` documentation merged** -- Junio confirmed that Kristoffer Haugsbakk's 9-patch documentation series for `git-interpret-trailers` has been merged. The series thoroughly documents the strict parsing rules for trailer keys (ASCII alphanumeric + hyphen only), standardizes terminology, and provides clear examples of both valid usage and failure cases. D. Ben Knoble noted a minor prose clarity issue in pre-existing documentation ("the new trailer" has no clear antecedent) but framed it as low priority.

**`git fetch --deepen` regression fix at v2** -- Samo Pogačnik submitted v2 of the fix for a regression introduced in Git 2.54.0 where `git fetch --deepen=<n>` on a non-shallow repository incorrectly converted it to a shallow one. The fix guards the depth addition by checking whether the repository actually has a shallow depth. Junio and René Scharfe agreed that adding warnings for `--deepen` on non-shallow repos is a separate concern, deferred to a future patch.

**Clang/glibc 2.43 compatibility fix finalized** -- Junio synthesized contributions from Patrick Steinhardt and Shardul Natu into a unified fix adding `-Wno-c11-extensions` for Clang builds in both Makefile and Meson build systems, while maintaining C99 enforcement. The issue stems from glibc 2.43 headers using C11's `_Generic` feature. The fix will be fast-tracked to stabilize CI and backported to v2.54.0.

**ODB write stream interface gets bugfix review** -- Jeff King identified a file descriptor leak in Justin Tobler's ODB write stream interface patch (part 3/7 of the ODB abstraction series). When an error occurs during stream reading in `odb_source_loose_write_stream()`, the function jumps to cleanup without closing the file descriptor opened earlier. The issue was caught by Coverity static analysis.

**Config file locking timeout patch abandoned** -- Junio and Patrick Steinhardt agreed to drop Jörg Thalheim's proposal for a 100ms timeout on config file locking, after Patrick's analysis confirmed the timeout couldn't resolve deeper semantic conflicts in concurrent config writes. The original author has implemented a workaround in their own project (workmux). The underlying reliability issue with concurrent config writes remains unaddressed in core Git.

**`git log --follow` documentation finalized** -- Tamir Duberstein's documentation patch for `git log --follow` and `--no-follow` reached consensus with Junio's definitive guidance: the existing wording ("works only for a single file") sufficiently communicates the core constraint, and directory pathspecs and non-linear history are intentionally left as undefined behavior. Junio rejected enumerating unsupported cases as inconsistent with Git's documentation style.

**`git add -p` word-diff interface design continues** -- D. Ben Knoble proposed two concrete implementation strategies for adding word-diff visualization to interactive patch review: either let the existing `p` command accept options in non-single-key mode, or introduce a new `:` prefix exempted from single-key behavior. Junio acknowledged the tension between single-key usability and extensibility but did not dictate a solution. Three proposals are now on the table: single-letter `w`, reused `p` with options, or `:command` syntax.

**`git maintenance` locking and `gc.auto` fixes posted** -- Patrick Steinhardt submitted a two-patch series fixing two maintenance subsystem issues: proper lockfile cleanup in detached mode, and restoring `gc.auto` threshold behavior after the transition from `git gc` to `git maintenance`. Jeff King identified a correctness issue in patch 2: it reads `gc.auto` as a boolean when it is actually an integer threshold. The series will need a v2.

**Pseudo-merge bitmap bugfixes near merge** -- Junio noted Taylor Blau's nine-patch v2 series is "so close to the finish line," kept as "Expecting (hopefully minor and final) reroll" in his draft "What's cooking." The only remaining item is addressing Elijah Newren's feedback about a duplicate `git init` in the test script.

**`git cherry`/`git grep` prefetch optimization** -- Elijah Newren responded to Junio's status inquiry about the merged patches for partial clone prefetching in `git cherry` and `git grep`, citing work emergencies for the delayed response.
