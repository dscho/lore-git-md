This is patch 09/12 in the v3 `--path-walk --filter` integration series from Derrick Stolee (with a co-authored-by from Taylor Blau), adding `sparse:<oid>` filter support to the path-walk API.

The patch addresses a real performance problem: constructing packs with `--filter=sparse:<oid>` has historically been computationally expensive because the revision walk checks every object individually against sparse-checkout patterns. With path-walk, objects are grouped by path and entire groups can be checked at once, producing dramatic speedups. The benchmarks quoted in the commit message show repack time dropping from 77.91s to 31.41s (60% faster) and packfile size shrinking from 187.5M to 161.1M (14% smaller) on the Git repository itself.

There is a notable design detail here around error handling: because `sparse:<oid>` requires parsing a blob from the repository to load cone-mode patterns, it can fail in ways that are not the path-walk's fault (the blob might be missing or the patterns might not be cone-mode). The patch makes `get_object_list_path_walk()` return an error code instead of dying, and the caller in `builtin/pack-objects.c` falls back to the standard revision-walk path with a warning. This means users get correct behavior even when the path-walk approach cannot be used.

The SEEN-flag ordering fix from patch 08/12 is exercised here in a concrete edge case. The patch adds tests in both `t5317-pack-objects-filter-objects.sh` (end-to-end pack-objects comparison between standard traversal and path-walk) and `t6601-path-walk.sh` (the test-tool path-walk directly). The shared-tree-OID tests are well-designed: they create a repository with two sibling directories that share identical content (and thus the same tree OID), where one directory is inside the sparse cone and the other is not. The test confirms that the blob inside the in-cone directory is included even though its out-of-cone sibling was visited first -- the deferred SEEN flag from patch 08 makes this work.

Test coverage is thorough: a `sparse:oid` test that verifies blobs and commits match exactly between standard and path-walk packfiles, another test confirming all trees are preserved (since `sparse:<oid>` only restricts blobs), and the shared-tree-OID regression test. The documentation updates list `sparse:<oid>` as a supported filter form in both `git-pack-objects.adoc` and `git-backfill.adoc`. The pre-existing typo "Whe" in `git-pack-objects.adoc` remains.

This is a well-motivated, well-tested patch that delivers on the performance promise the series has been building toward. The fallback mechanism is a pragmatic touch. No review comments have been raised so far.
