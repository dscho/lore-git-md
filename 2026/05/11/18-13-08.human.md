This is patch 11/12 in the `--path-walk` and `--filter` integration series from Derrick Stolee and Taylor Blau. It adds support for the `object:type=<type>` filter, authored by Taylor Blau.

The implementation is tidy and well-explained. The filter maps `LOFC_OBJECT_TYPE` to the existing per-type flags (`info->{commits,tags,trees,blobs}`) using an AND operation rather than assignment -- this is explicitly future-proofed for the combined-filter support that comes in the next patch. A new `strict_types` flag prevents direct object requests (pending objects that would normally bypass type restrictions) from leaking through.

Two subtle correctness fixes are worth noting. First, the existing gate for pending trees was too aggressive: it skipped them as soon as `info->trees` was zero, but `object:type=blob` still needs those trees walking to reach blobs reachable only through tag-pointed trees. The fix widens the gate to check both flags. Second, the revision machinery drops pending trees when `revs->tree_objects` is zero, so path-walk must temporarily set that flag whenever either trees or blobs are wanted, then reset it after `prepare_revision_walk()` returns so the rev-walk doesn't redundantly enumerate trees.

The tests are thorough -- four new tests covering all object types, plus a `blob` test that specifically exercises the tag-to-tree-to-blob path (objects reachable only through `refs/tags/tree-tag`). Documentation is updated to list the new filter form.

This looks like a well-crafted, properly motivated patch from someone who understands the revision-walk machinery's pitfalls. No obvious controversy or quality concerns.
