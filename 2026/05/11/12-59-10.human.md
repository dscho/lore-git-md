Performance optimization for merge-base calculation in large repositories. This is the fourth version of a patch series that speeds up single merge-base queries by exiting early when generation numbers are available, avoiding the expensive STALE commit frontier drain.

The series has been split into two commits based on Patrick Steinhardt's suggestion from v3:
1. A pure refactoring that introduces an `enum merge_base_flags` to replace boolean parameters
2. The actual optimization that adds early exit logic when only one merge-base is needed

The optimization provides dramatic speedups - from 5 seconds to 24ms (100x improvement) in a 2.2M-commit monorepo. The key insight is that when generation numbers exist and `--all` isn't specified, we can stop after finding the first valid merge-base since generation numbers guarantee no better candidate exists.

The patch includes extensive test coverage verifying behavior with/without commit-graphs and in both shallow and deep commit histories. All previous review feedback from Junio and Patrick has been addressed, and the current version appears merge-ready.

This builds on Git's existing generation number infrastructure and complements other performance work in commit-reach.c. The optimization is particularly valuable for large monorepos where merge-base calculations can otherwise be prohibitively expensive.
