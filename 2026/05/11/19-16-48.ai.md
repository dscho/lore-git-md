**Part of the `git add -p` word-diff interface design thread; D. Ben Knoble responding to Junio C Hamano's maintainer feedback.**

Knoble agrees with Junio's concern about not wasting single-letter mnemonics for each new diff-viewing option, reiterating his earlier `:show <opts>` proposal as a more extensible alternative to the `'w'` command. He builds on Junio's suggestion of reusing the existing `'p'` command with options, proposing two concrete implementation strategies to accommodate both power users and single-key-mode users: either let `p/P` accept options only in non-single-key mode, or introduce a new `:` prefix that is explicitly exempted from single-key behavior, allowing long-form commands like `:print --word-diff`. His thinking is that since `:` would be a brand-new keybinding, exempting it from single-key mode would not disrupt existing muscle memory.

This is a continuation of the interface design discussion -- the email advances from the earlier "spitballing" phase to offering specific, testable design options. It does not introduce new code or technical concerns about the patch itself; the focus remains on how to structure the UI so the project can support future diff options without exhausting its single-letter namespace. The thread's open question (whether to use `'w'`, reuse `'p'`, or adopt `:command` syntax) now has three concrete proposals on the table, with Junio's earlier skepticism about single-key users still unresolved.
