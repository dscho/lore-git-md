This is a review reply in the ongoing thread about the `git maintenance run --detach` locking bug. Jeff King (Peff) is responding to Patrick Steinhardt's alternative proposal for fixing the repository corruption risk when geometric repacks run in daemonized auto-maintenance mode.

Peff pushes back against Patrick's narrower approach. Patrick had proposed adding a targeted `lock_file_reassign_owner()` function so that only lockfiles get explicitly transferred to the child process during daemonization, rather than Taylor Blau's broader `reassign_tempfile_ownership()` that transfers all tempfiles. Peff argues that the transfer should be an automatic part of `daemonize()` itself, not something each caller has to remember to invoke.

His reasoning is twofold. First, the problem is general: any cleanup handler that runs in the parent after fork() while the child still holds references is a lurking risk -- lockfiles just happen to be the one that bit us here. Second, he notes that `git gc --detach` without `--skip-foreground-tasks` narrowly avoids the same bug by explicitly dropping and reacquiring locks on either side of the daemonize call, which is essentially a manual workaround for the same missing infrastructure.

Peff also points out that baking this into `daemonize()` is more abstract and future-proof, especially since on Windows `daemonize()` is already a no-op. An implementation that does weird platform-specific things and doesn't switch PIDs at all would still be safe if the tempfile handling is built into the abstraction rather than left to callers.

This is a substantive review from a domain expert. Peff does not propose new code or testing here; he is making an architectural argument about where the fix should live. He endorses the broader scope of Taylor's approach over Patrick's narrower one, and his position carries weight in this thread given his earlier root-cause analysis of the bug. The decision point remains: Taylor's comprehensive solution, Patrick's lockfile-only solution, or a revert. Peff is now clearly aligned with Taylor's direction.
