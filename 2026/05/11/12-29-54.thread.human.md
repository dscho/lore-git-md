This thread is a v2 bugfix series from Patrick Steinhardt targeting Git 2.54.0, fixing two issues in the maintenance subsystem. The series addresses a regression where setting `gc.auto=0` no longer prevented automatic maintenance from running, and improves lockfile cleanup in detached `git maintenance` mode. The `gc.auto` regression had a complex root cause: originally `git maintenance` shelled out to `git gc`, which respected the config key directly; when the default strategy stopped calling `git gc`, the indirect dependency broke, and only the newer `maintenance.auto` key was consulted.

Patch 1 corrects lockfile release in `git maintenance run --detach`. Patch 2 restores `gc.auto` behavior by having `prepare_auto_maintenance()` check `gc.auto` as an integer fallback when `maintenance.auto` is unset, matching the existing pattern used elsewhere for `autoDetach` keys. The only substantive change from v1 was fixing a type error in patch 2, switching from `repo_config_get_bool()` to `repo_config_get_int()` for the integer-valued key -- a finding independently confirmed by Jeff King and Junio C Hamano in their v1 reviews, which Patrick accepted.

The series is technically settled with no open objections. An acknowledged `#ifdef` duplication in patch 1 is deferred to a follow-up series. Awaiting final review before moving to `next`; no reviews have appeared from the maintenance subsystem's usual reviewers.
