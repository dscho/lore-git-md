Patrick Steinhardt posted a two-patch series fixing two bugs in Git's
maintenance subsystem: a lockfile-handling issue in `--detach` mode and a
`gc.auto` config-reading regression since the move to `git maintenance`.
The series is at v1 but will need revision.

The maintainer, Junio C Hamano, reviewed patch 1 and gave it a light,
approving review. He flagged two small observations -- a slightly
misleading comment and a duplicated `#ifdef` -- but neither is a blocker,
and he explicitly acknowledged why both are acceptable as-is. Patch 1 is
ready to proceed.

Patch 2 has a more serious problem. Jeff King identified that it reads
`gc.auto` as a boolean via `repo_config_get_bool()`, but this config key
is an integer threshold (the loose-object count before gc triggers). This
happens to work for the regression case (`gc.auto=0`) because zero is
falsy, but would produce incorrect behavior for any non-zero value like
`gc.auto=100`. The fix is to use `repo_config_get_int()` like the existing
`git gc` code does. This must be addressed before the series can advance,
and the author will likely need to post a v2. No reviews have come in from
the maintenance subsystem experts (Derrick Stolee, Taylor Blau) yet.
