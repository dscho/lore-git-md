This is a two-patch v3 bugfix series from Patrick Steinhardt fixing two
maintenance subsystem issues that are both ready to merge for Git 2.54.0.

Patch 1 fixes a lockfile release bug in `git maintenance run --detach`
where the parent process exits after forking, releasing the lock before
the child completes. The fix moves the lockfile ownership transfer
into `daemonize()` in `setup.c`, which now automatically reassigns
all open tempfiles and lockfiles from the parent PID to the child PID
after forking. This was Taylor Blau's alternative design, which Patrick
accepted after Taylor felt "fairly strongly" about it. Taylor appears
as Co-authored-by and Signed-off-by on the commit. The fix adds a
`reassign_tempfile_ownership()` helper to `tempfile.c`/`tempfile.h` and
includes an elaborate FIFO-based integration test in `t/t7900-maintenance.sh`.

Patch 2 restores the expected behavior where `gc.auto=0` disables automatic
maintenance. The regression was user-reported (by Jean-Christophe Manciot)
and caused when the internal shell-out to `git gc` was removed from the
maintenance path, breaking the indirect dependency on `git gc`'s own config
checking. The fix in `run-command.c` checks `maintenance.auto` first (via
`repo_config_get_bool`), falling back to `gc.auto` as an integer, matching
the existing pattern for `autoDetach` keys. Both Jeff King and Junio C
Hamano confirmed the correctness of the approach in earlier versions, and
the patch is substantively unchanged from v2. New tests cover `gc.auto=1`,
`gc.auto=0`, and `maintenance.auto` overriding `gc.auto` in both directions.

No open questions or loose ends remain on either patch. The v3 cover letter
signals readiness for merge.
