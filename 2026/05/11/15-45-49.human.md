This is the final patch in Kristoffer Haugsbakk's feature series introducing the new `git format-rev` command, which provides on-demand pretty formatting of revisions from stdin. The command fills a gap in Git's tooling by allowing flexible commit formatting for stdin input scenarios that existing commands like `git log` and `git show` don't handle well.

The command offers two main modes:
- `--stdin-mode=revs`: Processes one revision per line/record
- `--stdin-mode=text`: Finds and formats commit object names in freeform text

Key features include:
- NUL-termination support via `-z`, `--null-input`, and `--null-output` options
- Safe interactive operation using `maybe_flush_or_die()`
- Support for notes display via `--notes` option
- Comprehensive test coverage including edge cases

The implementation builds on infrastructure refactored in earlier patches of the series, sharing code with `git name-rev`. The command is marked EXPERIMENTAL to allow for future interface refinements based on real-world usage.

The patch includes thorough documentation and tests, demonstrating use cases like formatting commit hashes in commit messages or processing output from `git last-modified`. The series has benefited from substantive reviews by Phillip Wood (stream safety, NUL-handling) and surface-level feedback from René Scharfe (code style).

This represents a well-considered addition to Git's tooling, providing capabilities that existing commands don't offer while maintaining robust stream handling and safety characteristics. The experimental flag provides room for future adjustments based on user feedback.
