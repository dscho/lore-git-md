Feature: Finalized branch pruning functionality via standalone `git branch` commands in v5 series.

Harald Nordgren's v5 patch series represents the conclusion of the branch pruning functionality discussion, now fully decoupled from fetch operations per the architectural consensus. The series provides composable plumbing commands for safely identifying and removing local branches whose upstream counterparts have been deleted.

Key changes from v4:
1. Complete removal of `fetch --prune-merged` integration, settling the architectural debate in favor of keeping branch management separate from fetch operations
2. Retention of all core functionality through standalone `git branch` commands:
   - `--forked` to list branches with deleted upstreams
   - `--prune-merged` to safely delete them
   - `--all-remotes` flag for multi-remote scenarios
3. Preservation of safety mechanisms:
   - Default branch protection
   - Per-branch opt-out via `branch.<name>.pruneMerged`
   - Bulk deletion improvements

The implementation appears clean with comprehensive test coverage in t3200-branch.sh. The documentation updates clearly explain the new functionality while the config option wording has been updated to reflect the removal of fetch integration.

This version addresses all outstanding architectural concerns while maintaining the practical utility of the feature. The series is now focused purely on branch operations, making it a natural extension of existing `git branch` functionality rather than crossing command boundaries. The removal of fetch integration represents a significant simplification that should ease maintenance while still allowing automation through separate tooling or periodic execution of the branch commands.
