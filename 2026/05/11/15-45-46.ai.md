This is a preparatory style cleanup patch (part 2/5) in Kristoffer Haugsbakk's series introducing the new `git format-rev` command. The patch applies clang-format to `builtin/name-rev.c` to standardize formatting before the subsequent refactoring and feature work.

The changes are purely mechanical style adjustments:
- Normalizes pointer arithmetic spacing (e.g., `*(p+1)` becomes `*(p + 1)`)
- Aligns continuation lines in option definitions
- Standardizes spacing around operators and parentheses
- Maintains all functionality while making the code more consistent

This follows patch 1/5 which added braces to conditional branches in the same file. Together these style changes create a clean baseline for the substantive refactoring in patch 3/5 that will share code between `git name-rev` and the new `git format-rev` command.

The patch demonstrates good patch hygiene by separating mechanical changes from functional work, making the actual refactoring patches easier to review. The changes are straightforward and unlikely to be controversial, having already passed review in previous iterations of the series.
