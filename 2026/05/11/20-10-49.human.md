This is a reply from Jeff King (Peff) to Derrick Stolee in the ongoing thread about fixing the locking bug in daemonized `git maintenance` that can corrupt repositories. The thread has been discussing Taylor Blau's proposed `reassign_tempfile_ownership()` fix and Stolee's preference for an alternative approach.

Peff's email is short and narrowly focused. He addresses two of Stolee's concerns:

First, on cross-platform support: Peff points out that Windows is not an issue here because `daemonize()` is already a no-op on Windows (controlled by the `NO_POSIX_GOODIES` knob). So any fix involving fork() and file-descriptor inheritance simply doesn't apply to that platform. This clears a worry Stolee had raised.

Second, on Stolee's request for a test that proves lock cleanup works on both normal exit and early exit in the detached child: Peff agrees that testing an early exit (like hitting a `die()` while holding the lock) is hard to arrange, because the maintenance tasks mostly just spawn subprocesses via `run-command` rather than calling `die()` themselves. But he notes that testing SIGTERM cleanup is doable. Taylor already has a test that uses a slow prefetch task to keep maintenance running; Peff suggests modifying that test to kill the detached process at the right moment and verify the lock file was cleaned up, instead of only testing the normal-exit path that the test already covers.

The key takeaway: Peff is endorsing Taylor's fix direction and telling Stolee that his two remaining objections -- Windows portability and testability of early-exit cleanup -- are either non-issues or solvable with a straightforward extension to the existing test. This moves the discussion closer to consensus around Taylor's comprehensive solution, though Peff is not weighing in on the revert-versus-fix-forward release strategy choice.
