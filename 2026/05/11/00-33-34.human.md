This is a bugfix thread addressing edge cases in `rebase --update-refs` when the rebase instruction format includes ref decorations. The latest email from Abhinav Gupta confirms agreement with the current approach, clarifying that their earlier example was meant to show the issue also affects non-interactive rebases, not to suggest banning `%d` decorations.

The thread has established consensus that:
1. The fix should maintain support for `%d` in instruction formats
2. The bug manifests in both interactive and non-interactive modes
3. The current patch's approach of filtering to branch refs (DECORATION_REF_LOCAL) is correct

With Phillip Wood's Reviewed-by and Junio's approval, this appears ready for integration. The remaining open question is whether the parallel issue in make_script_with_merges() will be addressed in a follow-up patch or combined with this fix. The core solution is well-vetted and solves the immediate problem while preserving the desired functionality of showing ref decorations.
