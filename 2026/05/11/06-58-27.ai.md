Feature: Per-branch opt-out for branch pruning functionality in v5 series.

This patch adds a `branch.<name>.pruneMerged` configuration option that allows specific branches to be exempted from automatic pruning via `git branch --prune-merged`, even when using `--force`. The option defaults to true, maintaining the default behavior for most branches while giving users explicit control to preserve topic branches they intend to continue developing.

Key technical aspects:
- The implementation checks the config value before pruning, skipping branches where `pruneMerged` is false
- The protection works even with `--force`, ensuring branches marked for preservation won't be accidentally deleted
- Explicit deletion via `git branch -d` remains unaffected, providing an escape hatch when needed
- Comprehensive test coverage verifies:
  - Basic opt-out functionality
  - Interaction with `--force`
  - Preservation of explicit deletion capability
  - Proper warning messages when skipping protected branches

The patch fits cleanly into the v5 series' architectural approach of keeping branch management separate from fetch operations while maintaining all safety mechanisms. The documentation updates clearly explain the new configuration option and its relationship to the existing pruning behavior.

This represents the final piece of the branch pruning functionality, completing the series with all agreed-upon features while maintaining the project's principle of giving users control over their local branches. The implementation appears robust with thorough test coverage of edge cases.
