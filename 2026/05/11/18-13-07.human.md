This is patch 10/12 of the `pack-objects --path-walk --filter` series (v3), contributed by Taylor Blau. It adds support for the `tree:0` filter to the path-walk API. This is a relatively mechanical patch compared to some of its neighbors -- the logic is straightforward because `tree:0` is type-based filtering, not path-sensitive, so it maps cleanly onto the existing flags in `path_walk_info`.

The patch does two things. First, in `prepare_filters()`, it handles the `LOFC_TREE_DEPTH` filter: if the depth is non-zero (e.g., `tree:1`), it rejects the filter with an error, because the path-walk API does not have a concept of tree depth. If the depth is zero, it sets `info->trees = 0` and `info->blobs = 0`, which causes the path-walk to skip every tree and blob object entirely. Non-zero rejections cause pack-objects to fall back to the standard revision walk, same as for other unsupported filters.

Second, it handles an edge case in `setup_pending_objects()`: trees that are reachable only through tags (a tagged tree, like `refs/tags/tree-tag^{tree}`) would normally be placed into the regular tree-paths data structure. But when `tree:0` is active, those paths would be skipped. So the patch collects tagged trees into a new `/tagged-trees` pseudo-path using the same mechanism already used for tagged blobs, ensuring they are still emitted even though normal trees are suppressed.

The test coverage is solid: two positive tests (one for `--all`, one for a single branch) confirm only commits and tags (and their tagged-objects) appear, and a negative test confirms `tree:1` produces the expected error message. The tests are placed early in the file, before the sparse-filter setup, so they run on the original set of refs.

Worth noting: the ongoing documentation typo (`"Whe"` instead of `"When"`) persists in the updated man page, but that is a pre-existing issue across the whole series, not something introduced here. This is a straightforward, well-explained patch from a knowledgeable contributor, and the approach is clearly the right one.
