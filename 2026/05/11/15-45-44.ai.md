This is the fifth iteration of Kristoffer Haugsbakk's feature series introducing the new `git format-rev` command for on-demand pretty formatting of revisions. The series has undergone thorough review and refinement, with v5 focusing on documentation improvements.

The patch series follows a clear progression:
1. Patches 1-2: Style cleanup and formatting of existing code
2. Patch 3: Core infrastructure refactoring to share code with the new command
3. Patch 4: Test improvements
4. Patch 5: Implementation of the new `git format-rev` command

Key changes in v5 are all documentation-related:
- Fixed AsciiDoc formatting for nested definition lists (replacing `::` with `;;`)
- Rewrote the explanation of NUL-handling in text mode to be clearer about use cases
- Simplified example object names in documentation
- Improved wording about the command's advantages over alternatives

The command provides two main modes:
1. `--stdin-mode=revs`: Processes one revision per line/record
2. `--stdin-mode=text`: Finds and formats commit object names in freeform text

Notable features include:
- NUL-termination support via `-z`, `--null-input`, and `--null-output`
- Safe interactive operation using `maybe_flush_or_die()`
- Comprehensive test coverage
- Marked as EXPERIMENTAL to allow for future refinement

The series has benefited from substantive reviews by Phillip Wood (stream safety, NUL-handling design) and surface-level feedback from René Scharfe (code style). The documentation refinements in v5 show the author's continued attention to detail and responsiveness to feedback.

This represents a well-considered addition to Git's tooling, providing flexible commit formatting capabilities that fill a gap in the existing command set. The experimental flag provides room for future interface adjustments based on real-world usage.
