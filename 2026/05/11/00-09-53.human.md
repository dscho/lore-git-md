Maintainer follow-up on the `git fetch --deepen` regression fix. Junio C Hamano responds to Samo Pogačnik's patch that prevents `--deepen` from incorrectly converting full clones to shallow ones.

Junio confirms the core issue - that treating `--deepen` as an absolute depth on non-shallow repositories was wrong - but raises an important question about user experience. While making the operation a no-op (as the patch does) fixes the data loss issue, Junio suggests we might want to warn users when they attempt to use `--deepen` on a non-shallow repository, since the operation will have no effect.

This is a subtle but important design consideration. The patch currently silently ignores the `--deepen` request in non-shallow cases, which prevents harm but might leave users confused about why their command didn't produce the expected result. Junio's comment suggests the behavior might be more user-friendly if it included a warning message explaining why the operation was skipped.

The thread appears to be in its final stages, with the technical solution already reviewed and approved by René Scharfe. Junio's feedback focuses on polishing the user-facing behavior rather than challenging the core fix. This suggests the patch is likely to be merged soon, possibly with an added warning message if Samo agrees with Junio's suggestion.
