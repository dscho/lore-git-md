Performance optimization for merge-base calculation in large repositories. This is the fourth version of a patch series that speeds up single merge-base queries by exiting early when generation numbers are available, avoiding the expensive STALE commit frontier drain.

The series has been split into two commits per Patrick Steinhardt's suggestion from v3:
1. A pure refactoring that replaces boolean parameters with an `enum merge_base_flags`
2. The actual optimization that enables early exit when only one merge-base is needed

The optimization provides dramatic speedups (100x in a 2.2M-commit monorepo) by leveraging generation numbers to determine when the first valid merge-base found is guaranteed to be the best possible candidate. The patch maintains thorough test coverage across different commit-graph configurations.

Changes in v4:
- Split the original patch into two separate commits
- First commit introduces the enum refactoring with no behavior change
- Second commit adds the optimization logic
- Maintains all performance benefits while improving code organization
