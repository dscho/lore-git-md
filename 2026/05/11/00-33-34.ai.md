This is a bugfix thread addressing edge cases in `rebase --update-refs` when the instruction format includes ref decorations. Abhinav Gupta confirms agreement with Junio C Hamano's position that using `%d` in the rebase instruction format is valid and desirable, despite it currently causing incorrect behavior with non-branch refs like HEAD.

The email reinforces that the issue affects both interactive and non-interactive rebase modes, with the latter breaking entirely when the todo list is non-empty. This aligns with the v3 patch's approach of filtering to branch refs (DECORATION_REF_LOCAL) rather than treating the format string usage as invalid. The discussion has reached consensus on the solution's correctness, with Phillip Wood's Reviewed-by and Junio's approval already in place.

With this confirmation from the original reporter that the patch addresses their needs and no objections to the maintainer's stance, the thread appears ready for integration.
