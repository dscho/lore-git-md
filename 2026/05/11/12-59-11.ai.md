Refactoring patch in a performance optimization series for merge-base calculations. This is the first of two patches in v4, splitting the original patch as suggested by Patrick Steinhardt in v3 review.

The patch introduces an `enum merge_base_flags` to replace a boolean `ignore_missing_commits` parameter in `paint_down_to_common()` and related functions. This is a mechanical refactoring with no behavior change - the single caller that used the boolean flag now sets `MERGE_BASE_IGNORE_MISSING_COMMITS` in the flags enum instead. The change makes the API more readable and prepares for additional flags in the subsequent optimization patch.

The refactoring touches the commit-reach subsystem, modifying the function signatures and call sites while maintaining identical behavior. The patch follows Git convention by separating pure refactoring from behavior changes, making the actual optimization (coming in patch 2/2) easier to review.

This continues the series that aims to dramatically speed up single merge-base queries in large repositories by leveraging generation numbers for early termination. The split into two commits addresses Patrick's v3 feedback about keeping refactoring and optimization separate.
