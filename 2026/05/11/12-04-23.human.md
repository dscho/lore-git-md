Performance optimization for merge-base calculation, now with suggested split into refactoring and optimization commits. Patrick Steinhardt reviews v3 of Kristofer Karlsson's patch that speeds up single merge-base queries by early-exiting when generation numbers are available. While the current version addresses his earlier API suggestion (replacing boolean parameters with an enum), Patrick now recommends splitting the changes into two commits: one purely refactoring the API to use the new enum, and another adding the actual optimization. This would make review easier by cleanly separating the mechanical change from the behavior change.

The core optimization remains unchanged - it provides a 100x speedup (5s->24ms in a 2.2M-commit monorepo) by avoiding unnecessary work when only one merge-base is needed. The patch has already incorporated feedback from Junio and Patrick in previous iterations, and appears technically sound. Patrick's latest suggestion is about commit organization rather than the optimization itself, indicating the series is nearing readiness for merging.
