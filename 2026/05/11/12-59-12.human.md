Performance optimization for single merge-base calculation. This is the second patch in a v4 series that speeds up `git merge-base` queries by exiting early when only one merge-base is needed (the default case without `--all`). The optimization leverages generation numbers to determine when the first valid merge-base found is guaranteed to be the best possible candidate, avoiding the expensive STALE commit frontier drain.

Key technical points:
- When generation numbers are available and finite, the first doubly-painted commit is guaranteed to be the best merge-base
- The patch adds a new `MERGE_BASE_FIND_ALL` flag to control the behavior
- Callers that need all merge-bases (like `repo_get_merge_bases_many`) pass the flag to preserve existing behavior
- Regular `git merge-base` (without `--all`) gets the optimization by default

Performance impact is dramatic - in a 2.2M-commit monorepo with commit-graph:
- HEAD vs ~500 commits: 5,229ms → 24ms (100x speedup)
- HEAD vs ~1000 commits: 4,214ms → 39ms
- The patch includes thorough test coverage across different commit-graph configurations

This builds on the first patch in the series (v4 1/2) which did the mechanical refactoring to introduce the `merge_base_flags` enum. The series has addressed all substantive feedback from previous rounds and appears ready for merging.
