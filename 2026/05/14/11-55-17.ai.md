This is a test infrastructure patch, part 1 of Tuomas Ahola's four-patch v3 series fixing edge cases in Git's approxidate date parser. The patch is a revised version of what was previously patch 1/3 in v2, now updated in response to review feedback from both Junio C Hamano and Jeff King.

The patch adds an optional time-offset parameter to the `check_approxidate` test helper in `t/t0006-date.sh`. This allows individual test cases to run with a different "now" time, which is necessary for the substantive behavioral patches later in the series (patches 3/4 and 4/4) to test date approximations that only manifest at particular clock times. The offset is expressed as a human-readable value like `+2 days`, with a helper function `add_time_offset` that converts it to seconds; this addresses Jeff King's v2 complaint that the previous opaque `+48`-style integer was hard to understand.

The v3 revision addresses all three of Junio's v2 coding-style requests: the shell logic has been restructured from a single arithmetic expression into an explicit `if/else` block, `test` is used instead of `[ ... ]`, and the `export` statement has been moved to a single declaration. It also handles the `failure` expectation case properly when no offset is given, which Jeff King noted was awkward in v2. Two new test cases demonstrate the feature, checking that `"January 5th yesterday"` produces different results depending on whether it's evaluated two days later.

This is a well-crafted test infrastructure patch. The interface changes from v2 are responsive to the review feedback without over-engineering the helper. The `add_time_offset` function with `case` dispatch over `hours`/`days` is clean and extensible. There are no open issues on this patch from the v2 review cycle.
