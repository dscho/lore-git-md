This is a bugfix patch in the git-gui series addressing repository and worktree detection. The patch specifically handles the case where git-gui is launched from inside a .git directory and should use the parent directory as the worktree if valid.

The change adds a new `is_parent_worktree` procedure that:
1. Checks if we're in a .git directory
2. Verifies the parent directory is a valid worktree using `rev-parse --show-toplevel`
3. If valid, sets the worktree variables and changes directory

This restores functionality that was unintentionally broken in 2019 when Git's rev-parse behavior changed. The implementation carefully mirrors Git's own worktree validation logic through rev-parse calls rather than reimplementing checks.

The patch is part of a larger series that has undergone extensive review (now at v8) and represents the final architectural approach to repository handling in git-gui. It maintains backward compatibility while fixing edge cases, and follows the series' pattern of using Git's own commands (rev-parse) for repository state detection rather than custom logic.
