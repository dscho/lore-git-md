Performance optimization follow-up on revision walking improvements.

Derrick Stolee provides a positive review of Kristofer Karlsson's patch that replaces a linked list with a priority queue in `limit_list()`. He confirms the optimization makes sense, noting the change from O(n) to O(log n) insertion cost is particularly beneficial for large commit sets in merge-heavy repositories.

Stolee highlights several key points from the patch:
- The implementation is clean (21+17-) since `process_parents()` already supported both data structures
- The optimization affects commands like `--left-right`, `--cherry-mark`, bisect, rebase fork-point, and `git status --ahead-behind`
- Performance improvements show 2.5-3x speedups for large commit sets while maintaining parity for small traversals

He asks two follow-up questions:
1. Whether the benchmarks could be demonstrated on the Git repository itself, particularly around point releases with lopsided symmetric differences
2. Whether any tests in t/perf/ demonstrate this improvement

The review is substantive, engaging with both the technical implementation and practical implications of the change. Stolee's questions suggest areas where the patch's impact could be further validated, though he clearly approves of the core approach.
