This is the final patch in a completed bugfix series for git-gui, adding explicit subcommands to control repository picker behavior. The series has already gone through extensive review and achieved consensus.

The patch introduces two new subcommands:
- `gui`: Runs the GUI only if repository/worktree discovery succeeds, never showing the picker
- `pick`: Always shows the repository picker first before launching the GUI

This gives users direct control over when the picker appears, rather than having it trigger automatically on discovery failures. The change maintains backward compatibility while addressing a usability pain point where the picker would sometimes appear unexpectedly.

The implementation is straightforward, adding new subcommand handling while preserving all existing functionality. The patch follows the architectural direction established earlier in the series, using the same error handling patterns and repository discovery mechanisms.

As the last patch in a well-reviewed series that has already been signed off by the maintainer (Mark Levedahl), this appears ready for integration. It completes the series' goal of making git-gui's repository handling more robust and predictable.
