This is the fourth and final patch of Tuomas Ahola's v3 series fixing edge cases in Git's `approxidate` parser. It introduces a deferred-adjustment scheme for how "now" and "yesterday" interact with time-of-day specials like "noon" and "tea."

The patch handles a subtle inconsistency: when you write "tea yesterday," Git's current logic processes "tea" first (wrapping to the *most recent* tea-time, which is earlier today or yesterday) and then applies "yesterday" on top, often producing a date two days ago rather than yesterday's tea-time. The fix repurposes negative `tm->tm_mday` values as deferred markers -- "now" and "yesterday" set `tm_mday` to -1, and `date_time()` uses `tm_mday = -2` (meaning "yesterday, pending confirmation") instead of calling `update_tm()` directly. Later, `update_tm()` resolves these negative markers to the actual day if no explicit day has been provided. The change to `date_time()` is about six lines of logic; the rest is mechanical cleanup of function signatures that no longer need the `now` parameter (marked with `UNUSED`).

Four new test cases are added, verifying that "tea last saturday" and "noon yesterday" produce the expected results, including when evaluated at different "now" offsets using the test infrastructure from patch 1/4. The test for "noon today" also gets a +36-hours variant confirming correct rollover behavior.

This is a clean, well-structured patch that addresses a real and long-standing consistency problem in the date parser. The deferred-mday scheme is clever without being overengineered -- it extends an existing convention (negative `tm_mday` means "not yet set") with a small integer offset to convey "yesterday, if no explicit day follows." The negative-value encoding ( -2 = yesterday, -3 = two days ago, etc.) is a natural extension that adds no real complexity. The commit message is clear about what problem this solves and why the deferred approach is needed. This patch is the only one in the series that has not yet received Junio's review, but it is mechanically sound and logically continuous with patches 1/4 and 3/4. No open review items exist.
