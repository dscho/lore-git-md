This is the final patch in Elijah Newren's performance optimization series for partial clone behavior, specifically targeting `git grep`. The patch implements blob prefetching to address the severe latency issues in partial clones where blobs are fetched one at a time.

The key technical aspects of this patch include:

1. A new `collect_blob_oids_for_tree()` function that recursively walks trees to identify missing blobs matching the given pathspec, avoiding submodules (which have their own promisor configuration).

2. A `prefetch_grep_blobs()` function that:
   - Checks if we're in a partial clone
   - Collects all missing blob OIDs from the trees being searched
   - Batches them into a single fetch request using `promisor_remote_get_direct()`

3. Comprehensive test coverage in t7810-grep.sh that verifies:
   - Pathspec filtering works (only fetches matching blobs)
   - Batched fetching occurs (reduces network roundtrips)
   - No redundant fetches of already-local blobs
   - Correct behavior across multiple invocations

The implementation is careful to:
- Use the existing ODB API (`odb_has_object()`, `odb_read_object()`) to check local availability
- Handle both commit and tree objects as starting points
- Maintain pathspec filtering throughout the prefetch process
- Clean up all allocated resources

This builds on the series' earlier work (documenting promisor-remote contracts, fixing efficiency bugs) and represents the final piece of the optimization effort for `git grep`. With all requested test coverage and fixes incorporated, this appears ready for integration. The patch shows thoughtful attention to edge cases and maintains good separation of concerns while delivering measurable performance improvements for partial clone users.
