This is patch 6/8 of Derrick Stolee's negotiation-control series, implementing the `--negotiation-include` option for `git fetch` (and the corresponding passthrough for `git pull`). This is the feature patch that the `have_sent()` abstraction in patch 5/8 was designed to enable.

The core idea: `--negotiation-include` takes ref patterns, commit hashes, or globs, and guarantees those tips are always sent as "have" lines during negotiation, regardless of what the negotiator algorithm selects on its own. This complements the `--negotiation-restrict` option from earlier in the series: restrict narrows the set of refs the negotiator considers, while include forces specific refs into the have stream even if they would otherwise be pruned. The motivating use case is monorepos with a long-lived release branch -- if the negotiator skips that branch, the server may assume no shared history exists and send the entire parallel commit tree (60+ GB in a real case Stolee cites).

The implementation is clean and matches the design from the cover letter. In `builtin/fetch.c`, the existing `add_negotiation_restrict_tips()` function is generalized to `add_negotiation_tips()` which handles both restrict and include lists, then stores the resolved OID arrays separately in `transport->smart_options`. In `fetch-pack.c`, the include OIDs are sent as haves *before* the negotiator's `next()` iterator runs, and the `have_sent()` callback tracks them so the negotiator does not re-emit duplicates. Both the v0/v1 codepath (`find_common`) and the v2 codepath (`send_fetch_request`) are wired up. The `negotiate_using_fetch()` function (used for `--negotiate-only` / push negotiation) also gets the include-tips parameter, threaded through from `transport.c`.

One notable behavioral change: the restrict-tip matching logic in `add_negotiation_tips()` now silently ignores non-existent refs (previously it would die), matching the include behavior. This is called out directly in the commit message.

The test coverage is thorough: basic include with restrict, glob patterns, additive behavior without restrict, silent handling of missing refs, duplicate avoidance (v0 and v2), and the existing tests for ignoring missing refs/invalid hashes on the restrict side are updated to match the new silent-ignore behavior.

The two remaining patches in the series (7/8: `remote.<name>.negotiationInclude` config, 8/8: push negotiation wiring) will complete the feature. At this point the core machinery is in place and working -- the config plumbing should be straightforward.
