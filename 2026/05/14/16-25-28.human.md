This is the final patch in Elijah Newren's performance optimization series for partial clone behavior, specifically targeting `git grep`. The patch implements blob prefetching to avoid the severe latency of fetching blobs one at a time in partial clones.

The key technical aspects are:
1. A new `prefetch_grep_blobs()` function that walks trees to collect missing blob OIDs before the actual search begins
2. Pathspec-aware filtering to only prefetch relevant blobs
3. Batched fetching via `promisor_remote_get_direct()`
4. Careful handling of local objects to avoid redundant fetches
5. Comprehensive tests verifying the prefetch behavior and pathspec filtering

The implementation shows thoughtful attention to edge cases like submodules (explicitly skipped) and binary files (handled naturally via the pathspec system). The test suite demonstrates both the batching efficiency (measuring fetch counts) and correctness (verifying search results).

This patch completes the series' goal of optimizing `git grep` in partial clones while maintaining all existing functionality. With the prior patches having addressed API documentation and test coverage, this appears ready for integration. The performance benefits for partial clone users should be significant, reducing what could be minutes of latency down to a single batch fetch.
