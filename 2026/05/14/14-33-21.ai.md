This is the 10th patch in an 11-part bugfix series for git-gui, focusing on worktree discovery improvements. The patch refactors how git-gui determines the working tree location, building on earlier changes in the series that unified repository state detection.

The changes centralize worktree discovery immediately after repository validation, using `git rev-parse --show-toplevel` as the primary source of truth. The new logic handles three cases:
1. Normal case: Valid worktree found via rev-parse
2. Error case: Fails if GIT_DIR/GIT_WORK_TREE are set but invalid
3. Fallback: Allows bare repo operation for browser/blame commands or tries parent-as-worktree

The patch removes 33 lines of legacy worktree handling code, replacing it with a more robust 23-line implementation that better matches Git's own behavior. Key improvements include:
- Earlier error detection for misconfigured environments
- More graceful handling of bare repositories
- Proper support for parent-as-worktree cases
- Simplified path normalization using rev-parse

This appears to be a well-considered refinement of git-gui's startup sequence, completing the architectural shift to rev-parse-based state detection that was introduced earlier in the series. The changes maintain backward compatibility while making the behavior more predictable.
