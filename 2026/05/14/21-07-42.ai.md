This is a follow-up in the ongoing discussion about the "today" alias patch in the approxidate series. The author, Tuomas Ahola, responds to Junio's clarification about the semantic concerns with making "today" an alias for "now". 

Tuomas proposes a middle-ground solution that would handle "today" by setting only the day component (tm_mday) to match the current day, without committing to any particular time-of-day behavior. This approach would support compound expressions like "today at noon" while avoiding the controversial "today=now" equivalence that Junio objected to.

The key points:
- The proposal avoids codifying the current accidental behavior where unrecognized strings (including "today") default to "now"
- It provides basic "today" functionality by aligning just the day component with the current date
- This leaves the time component unspecified, allowing for future discussion/implementation of what "today" should mean time-wise
- The change would still enable time-qualified variants like "today at noon" to work correctly

This moves the discussion forward by offering a concrete technical alternative that addresses Junio's design concerns while maintaining functionality. The ball is now in Junio's court to evaluate whether this partial implementation is acceptable or if a more comprehensive solution for "today" semantics is needed before proceeding.
