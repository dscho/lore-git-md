Performance optimization for partial clones in `git cherry`. This is the third patch in Elijah Newren's series to improve performance of commands in partial clone environments by prefetching necessary blobs upfront rather than fetching them one at a time.

The patch implements blob prefetching for `git cherry` by:
1. Adding a new `prefetch_cherry_blobs()` function that uses a temporary hashmap comparison function to identify which blobs would be needed without actually fetching them
2. Collecting blob OIDs from commit diffs while skipping files marked as binary (since patch-ID doesn't need their contents)
3. Performing a bulk fetch of all needed blobs at once via `promisor_remote_get_direct()`
4. Restoring the original hashmap comparison function before proceeding with normal operation

The implementation includes test verification that:
- Only one fetch operation occurs for all needed blobs
- Subsequent invocations don't refetch blobs already present locally
- The command produces correct results in partial clone scenarios

This builds on the series' earlier work to document the promisor-remote API contracts and adds specific handling for `git cherry`'s two-phase patch-ID computation (header-only first, then full content when needed). The patch demonstrates careful attention to edge cases like binary files and merge commits while maintaining the command's exact semantics.
