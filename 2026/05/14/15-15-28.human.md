This is a review comment on Pablo Sabater's `git log --graph` rendering improvement patch series. Phillip Wood suggests an alternative approach to visually separating root commits from unrelated child commits in the graph output.

Phillip proposes using blank lines rather than indentation to distinguish root commits, arguing this would keep related commit groups together while maintaining clear visual separation. His example shows:

```
* root-B

* child-A2
* child-A1
* root-A
```

This contrasts with Pablo's current approach which indents child commits after a root (using placeholder columns) to show they belong to different lineages. Phillip's suggestion would require less horizontal space and might be more intuitive for some readers, though it would consume the same vertical space as the current solution.

The review is substantive - it engages with the core design choice of how to best represent commit relationships visually, rather than just surface-level issues. Phillip doesn't reject Pablo's approach outright but offers a concrete alternative for consideration. This continues the thread's technical discussion about graph rendering aesthetics and readability.

No new technical concerns are raised about the implementation itself - the feedback is purely about the user-facing output format. The ball is now in Pablo's court to consider whether to adapt the approach, justify the current design, or perhaps offer both options configurable via a flag.
