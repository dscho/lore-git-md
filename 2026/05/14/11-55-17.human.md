This is patch 1/4 of a v3 series from Tuomas Ahola, fixing edge cases in Git's approxidate date parser. This particular patch is **test infrastructure only** -- it extends the `check_approxidate` test helper to allow temporarily shifting the "now" time so that future behavioral patches in the series can test date-relative strings from a specific point in time.

The core change: `check_approxidate` now accepts an optional human-readable time offset (e.g. `+2 days` or `-12 hours`) as a parameter. The offset is parsed by a new `add_time_offset` helper and applied via `GIT_TEST_DATE_NOW`. The test helper also gets cleaner handling of the `failure` expectation flag, no longer requiring it to sit between the input string and an eventual offset parameter. Two new demonstration tests using this capability are added, showing that `"January 5th yesterday"` produces a different result depending on when "now" is.

This is a clean, well-responded-to patch. It addresses all the feedback from Junio's v2 review (preferring `test` over `[ ... ]`, moving the arithmetic into an explicit `if` block, and cleaning up the export) as well as Jeff King's observation that opaque numeric offsets like `+48` were confusing. The resulting interface is clearer. The patch is straightforward and should be uncontroversial -- it is a pure improvement to test infrastructure with no behavioral change to Git itself. Worth a quick scan from anyone who reviewed v2, but not something that needs deep study.
