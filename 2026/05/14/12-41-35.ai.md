This is the eighth and final patch of Derrick Stolee's v4 series adding `--negotiation-include` and `--negotiation-restrict` controls to Git's fetch/push negotiation. Picks up the push-negotiation wiring that was deferred from the rest of the series.

When `push.negotiate` is enabled, `git push` spawns a `git fetch --negotiate-only` child process to discover common commits. This patch passes the new `remote.<name>.negotiationInclude` and `remote.<name>.negotiationRestrict` config values into that child process, so that users who have configured these options for fetch also get the same behavior during push. The implementation in `send-pack.c` is straightforward: if a restrict list is configured, the child process receives `--negotiation-restrict` arguments from that list instead of the default behavior (passing every remote-ref's new OID); if an include list is configured, `--negotiation-include` arguments are added on top. The `send_pack_args` struct gains two new `string_list` pointer fields, and `transport.c` wires them from the remote config at push time. Two new tests in `t5516-fetch-push.sh` exercise the include and restrict paths using the trace2 `total_rounds` event and a `grep_wrote` helper to confirm the expected number of have lines. Documentation for both config keys in `remote.adoc` gets a one-sentence note that the values also influence push negotiation.

This is a clean, mechanical patch that completes the feature. The design follows directly from the pattern established by patches 4 and 7 (the config options), and the implementation is exactly what you would expect from reading those earlier patches. The commit message is well-structured and explains both the what and the why. The test coverage is appropriate: two tests that mirror each other for include and restrict, using the same trace2-based verification pattern. No surprises, no loose ends -- this is clearly the capstone patch that ties the config options into the push codepath.
