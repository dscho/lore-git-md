This is patch 3/8 of Derrick Stolee's v4 series adding `--negotiation-include` and `--negotiation-restrict` to fetch/push. It is purely a mechanical rename.

The patch renames the internal data structures from `negotiation_tips` to `negotiation_restrict_tips` across six files: `builtin/fetch.c`, `fetch-pack.c`, `fetch-pack.h`, `transport-helper.c`, `transport.c`, and `transport.h`. The static string list that stores the command-line input, the function that resolves ref patterns into an `oid_array`, the field on `struct fetch_pack_args`, and the field on `struct git_transport_options` are all renamed. Every change is a straightforward identifier substitution with no behavioral alteration.

The commit message frames this as preparation for the upcoming `--negotiation-include` option (patch 6/8): the two mechanisms share a similar plumbing path but need distinct internal names so the transport layer can distinguish them. The rename makes that distinction explicit before the new option is introduced.

This is one of those patches that is trivially correct but individually uninteresting -- it exists only to keep the rename separate from the behavioral patches for reviewability. No tests are changed, no behavior is affected, and the patch is uncontroversial. The real logic in this series lives in the patches around it.
