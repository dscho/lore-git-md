This is patch 5/7 in Justin Tobler's series to finalize the object database (ODB) transaction write interface, part of the ongoing ODB abstraction effort. The patch optimizes packfile handling for large blobs by avoiding unnecessary file descriptor seek operations.

The key change replaces the previous approach of rewinding and retrying when a packfile size limit is exceeded with a more efficient upfront size check. Instead of:
1. Writing the blob
2. Checking if it exceeded the limit
3. Seeking back and retrying in a new packfile if needed

The new approach:
1. Estimates if writing would exceed the limit using the uncompressed blob size
2. Starts a new packfile preemptively if needed
3. Writes the blob once without seeking

This works because blobs written this way aren't delta-compressed, so the uncompressed size is a reasonable approximation of the final packfile growth. The change simplifies the seek/retry logic while maintaining the same pack size limiting behavior.

The patch affects `git add`, `git update-index`, and other commands that write large objects when core.bigFileThreshold is configured. It's a performance optimization that builds on the transaction interface changes in earlier patches, removing one of the last fd-specific operations as the series moves toward the more general `odb_write_stream` interface.

With Patrick Steinhardt's approval and Jeff King's earlier concerns addressed in v4, this appears ready for merging as part of the larger ODB abstraction effort. The change is well-contained and doesn't introduce new interfaces - it simply makes better use of information already available.
