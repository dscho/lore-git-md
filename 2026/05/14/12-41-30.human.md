This is a **refactoring patch** -- patch 3 of 8 in Derrick Stolee's v4 series adding `--negotiation-include` and `--negotiation-restrict` to `git fetch` and `git push`.

This patch does nothing visible to the user. It mechanically renames every occurrence of `negotiation_tips` to `negotiation_restrict_tips` across six files: `builtin/fetch.c`, `fetch-pack.c`, `fetch-pack.h`, `transport-helper.c`, `transport.c`, and `transport.h`. The companion variable `negotiation_tip` (the `string_list` in `builtin/fetch.c` that collects CLI arguments) becomes `negotiation_restrict`. The commit message is clear about why: the previous patch added `--negotiation-restrict` as the new primary name (keeping `--negotiation-tip` as an alias). Now Stolee wants the internal identifier to match the user-facing name before the next patch introduces a *different* negotiation option (`--negotiation-include`) that would make the ambiguous name actively confusing.

The patch is mechanically correct -- every line is a straightforward `s/old_name/new_name/` substitution across data structures, function names, parameter lists, and comments, with no behavioral change. The only design observation worth noting is that Stolee kept the `_tips` suffix in the new name because the transport layer uses `oid_array` objects (a collection of tip commit OIDs). This signals that the upcoming `--negotiation-include` option, while similar, will need its own distinct internal representation.

This is the kind of cleanup patch that makes a series easier to review and maintain. Combined with the test-order fix in patch 1 and the CLI renaming in patch 2, patches 1-3 of this series are all preparation for the substantive changes that start with patch 4 (the config option) and patch 5 (the new `have_sent()` negotiator interface).
