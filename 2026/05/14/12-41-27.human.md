This is a v4 cover letter for Derrick Stolee's 8-patch series adding fetch negotiation control options. The core idea is to give users two knobs instead of one: `--negotiation-restrict` (replacing `--negotiation-tip`) to limit which refs are advertised as haves, and `--negotiation-include` to guarantee certain important refs (like `main` or `release`) are always advertised even when other heuristics would skip them. Both options get parallel config keys (`remote.<name>.negotiationRestrict` and `remote.<name>.negotiationInclude`).

The motivating scenario is a monorepo with many short-lived feature branches and a long-lived `release` branch containing nontrivial content. Without these controls, the client can run out of have slots before advertising its version of `release`, causing the server to send the entire changelog history on every update.

What changed from v3 to v4 is significant and responds to Matthew Cheetham's thorough review. The biggest technical change is patch 5/8, which adds a new `have_sent()` callback to the negotiator struct. This replaces a hack in v3 where included commits were marked with the COMMON flag to prevent the negotiator from re-advertising them. The new callback is cleaner and avoids the flag-abstraction breakage Cheetham identified. The ref-resolution logic for both options has also been unified into `add_negotiation_tips()` in `builtin/fetch.c`, so the transport layer receives pre-resolved `oid_array`s instead of `string_list`s. This is a meaningful structural improvement.

Other fixes include: replacing the custom empty-value reset logic in config parsing with `parse_transport_option()` (which handles list reset uniformly), removing the claim that these options work with `git push` (they don't yet), adding a test for missing-ref ignoring, adding a v0 duplicate-avoidance test, and fixing a handful of documentation cross-references and typos.

The series looks solid. Stolee has engaged seriously with every piece of feedback, and the structural changes (new negotiator callback, unified ref-resolution) are clearly motivated by real design issues rather than polishing. The commit messages are detailed and explain both the what and the why. The test coverage is good, including both the nominal paths and edge cases like mixed `--negotiation-restrict` and `--negotiation-include` usage.

One thing to note: the series is 8 patches now (was 7 in v3), with the new patch 5 being the `have_sent()` interface patch. This is a non-trivial change that touches the negotiator abstraction, so reviewers who already reviewed v3 may want to re-read that patch in particular. The other patches are mostly mechanical renames, documentation fixes, and test additions.

Overall this looks ready for careful review and likely graduation to `next` after that. The problem statement is well-motivated, the design is cleaner than v3, and the implementation looks careful.
