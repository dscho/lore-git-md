Jonas Rebmann's four-patch series to make `git bisect` respect user-configured alternate terms is now complete with the arrival of v4, patch 3/3. This final patch fixes `git rev-parse --bisect`, which was hardcoding `refs/bisect/good` and `refs/bisect/bad` instead of reading the actual terms from `BISECT_TERMS`. When a user ran with `--term-old=known --term-new=curious`, the plumbing command would silently find nothing. The fix reads the terms dynamically and builds the ref prefixes with `xstrfmt()`, with proper memory management throughout. The test is well-constructed, verifying that only the custom-termed refs are listed even when the standard refs happen to exist too.

The series as a whole covers three changes: replacing hardcoded strings in `bisect_print_status()` and `bisect_run()` with `terms->term_good`/`terms->term_bad` (patch 1), adding single-quoting around bisect terms in all status and error messages for consistency (patch 2, new in v4), and the rev-parse fix (patch 3). All review feedback from Junio C Hamano and Phillip Wood across earlier versions has been addressed -- memory leaks fixed, quoting conventions settled, and commit messages improved. No design objections remain and no further review is needed; the series is ready for merge. The only feedback received was iterative polish, not substantive correctness concerns, which is appropriate given the mechanical nature of the fixes.
