This is the first patch of a three-patch series (now at v4) from Jonas Rebmann that fixes `git bisect` to use user-configured alternate bisect terms in places where it still hardcodes "good" and "bad".

Specifically, this patch targets three pieces of status output that have been silently displaying the wrong terms when someone uses e.g. `--term-old`/`--term-new`: the "waiting for both good and bad commits" message, the "waiting for bad commit, N good commit known" variant, the "waiting for good commit(s), bad commit known" message, plus two error messages in `bisect run` that were hardcoding "good" and "bad" in their text.

The commit message is well-written and includes a concrete example of the problem: running `git bisect old` on an alternate-terms bisect would print the confusing "is the first new commit", leaving the user unsure what "new" refers to, and running `git bisect bad` (the default term) on a session configured with `new`/`old` would produce an error. The fix itself is straightforward -- replace hardcoded strings with `terms->term_good` and `terms->term_bad` -- and comes with test additions that verify the correct terms appear in status output and in `bisect run`.

This is a clean, well-scoped fix in a well-understood area, already through four iterations of review from Junio Hamano and Phillip Wood with no outstanding design objections. Worth a quick read for anyone who maintains or frequently uses the bisect subsystem, especially if they use alternate terms.
