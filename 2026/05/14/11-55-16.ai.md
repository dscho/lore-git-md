This is the cover letter for a v3 iteration of the three-patch series (now split into four patches) by Tuomas Ahola fixing edge cases in Git's approxidate date parser. The series addresses the same long-standing quirks flagged by Linus Torvalds in 2006, centered on special time-of-day strings like "noon" and "tea" producing the wrong day when combined with explicit date references.

The big change from v2 is structural: the previous patch 2 (the "today" alias patch) has been pulled out into its own standalone patch (now patch 2/4), placed *before* the substantive behavioral fix (now patch 3/4). This addresses the open discussion point from Junio's v2 review -- by making the "today" alias a separate, independently negotiable patch, it can be applied or dropped without affecting the core bugfix. The inter-diff confirms no other changes to the date.c logic from v2; the only differences are the new patch ordering, the test infrastructure (patch 1/4) now accepts human-readable offsets like `-12 hours` instead of the opaque `-12` from v2 (addressing Jeff King's interface-design suggestion), and the test data has been expanded slightly.

Patch 1/4 adds time-of-day offset support to the `check_approxidate` test helper, now using human-readable offset strings. This is a pure test infrastructure patch. Patch 2/4 adds "today" as an alias for "now" in the specials table -- the same one-liner from v2, now isolated so it can be debated independently. Patch 3/4 is the core fix: when `date_time()` sets the hour for a special like "noon" or "tea", it checks whether `tm_mday` has already been set to a non-negative value (indicating a specific day was provided) and if so, skips the "most recent in the past" rollback that would otherwise move the date to yesterday. Patch 4/4 uses negative `tm_mday` values as deferred markers for "now" and "yesterday", resolved later by `update_tm()`.

For context: Junio's v2 review requested coding-style changes on patch 1 and raised a substantive concern about the "today" alias on patch 2, with patch 3 unreviewed. This v3 addresses the style changes and the interface-design observations from both Junio and Jeff King, and isolates the contentious alias into its own patch. The series is ready for re-review. For a reader tracking this thread: the interesting outcome will be whether the "today" alias patch (2/4) can land, or whether it gets dropped, and what Junio thinks of the deferred-mday approach in patch 4/4 now that he has a chance to see it.
