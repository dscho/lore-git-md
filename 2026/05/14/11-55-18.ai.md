This is RFC patch 2/4 in a series from Tuomas Ahola fixing edge cases in Git's approxidate parser. It is a one-line change that registers "today" as an alias for "now" in the specials table in `date.c`.

The patch is trivial in content, but the open question that already appears in the thread -- noted from Junio's review -- is whether this actually produces the behavior users expect. For `--since=today`, the alias means "since right now, i.e. the exact timestamp", which would exclude any commits made earlier today. That is almost certainly not what a user typing `git log --since=today` intends; they likely mean "since midnight". Junio flagged this as a functional concern in v2, and the author's reply -- included as a note in the patch -- suggests he may not fully grasp the concern: he describes `--since=today` as effectively a no-op (which is wrong if it excludes all of today's history), and then proposes a fix that would make it behave like `--since=midnight` only when the current time exactly matches the time that was parsed (midnight), which would rarely trigger. That proposed fix would not solve the actual problem.

The patch itself is well-formed: one insertion, a clear commit message, and proper Signed-off-by. But it is the most controversial piece of the series, and the author's response to the maintainer's concern suggests the design discussion is not yet resolved. This patch will not land until the semantics of `--since=today` are clarified. If it is dropped, the rest of the series (patches 3/4 and 4/4, which contain the actual edge-case fixes for "noon"/"tea"/"now"/"yesterday") is unaffected and can proceed independently.
