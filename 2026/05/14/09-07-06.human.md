This is patch 3/3 of Jonas Rebmann's series to fix `git bisect` respecting user-configured alternate bisect terms. It addresses a real gap: `git rev-parse --bisect` hardcodes lookups for `refs/bisect/bad` and `refs/bisect/good`, so when a bisect uses e.g. `old`/`new`, the command produces no output at all. The fix reads the current bisect terms via `read_bisect_terms()` and constructs the correct ref prefixes dynamically.

The patch is mechanically straightforward -- about 15 lines changed in `builtin/rev-parse.c`, with memory cleanup for the allocated term strings. A new test creates a repository with custom bisect terms (`known`/`curious`), sets up several refs including the old-style `refs/bisect/bad` and `refs/bisect/good`, and verifies that only the correctly-named refs are included (and that the hardcoded ones are correctly ignored). The test is well-constructed: it explicitly creates the old-style refs to demonstrate they are no longer matched.

The only small note is that `--bisect` is not being passed any filtering for `bisect/curious-*` vs `bisect/known-*` beyond what was originally intended. The test comment acknowledges that `refs/bisect/bad` and `refs/bisect/good` should be ignored during an alternate-term bisect, which the code does correctly. This looks clean, well-tested, and clearly motivated. No reason to hold it up.
