Subject: trailer subsystem refactoring (unfold_value optimization)
Author: René Scharfe
Thread type: performance optimization patch
Status: initial version (v1)

Core change: Eliminates temporary buffer allocation in `unfold_value()` by performing newline-whitespace normalization in-place on the input strbuf. The transformation (equivalent to `s/\n\s*/ /g`) now uses read/write pointers within the same buffer rather than allocating a second strbuf.

Technical details: Modifies `trailer.c::unfold_value()` to track separate read/write positions while collapsing newlines and adjacent whitespace. The change reduces the function from 16 to 6 lines while maintaining identical behavior. Touches only internal trailer processing code with no interface changes. Ramsay Jones reviewed the pointer arithmetic, confirming the post-increment of `i` doesn't affect correctness despite his initial question about relative positions.

Motivation: Performance optimization suggested by Jeff King (Peff) to avoid unnecessary allocations. The in-place approach is safe since the transformation never increases string length.

Participant positions:
- Jeff King (Peff): Suggested the optimization approach
- René Scharfe: Implemented and tested the change
- Ramsay Jones: Reviewed pointer arithmetic (surface-level, confirmed no functional impact)

Related work: Part of ongoing trailer subsystem optimizations. Follows René's pattern of memory efficiency improvements to core data structures.
