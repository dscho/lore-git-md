This is the third version of Elijah Newren's performance optimization series for partial clone behavior in `git cherry` and `git grep`. The series addresses severe performance penalties in partial clones where commands would fetch blobs one at a time, with each fetch taking 3+ seconds.

Key changes in v3:
1. Added documentation about promisor-remote filtering contracts (new patch 1)
2. Modified the test case for `git grep` to include pathspec usage as suggested by Derrick Stolee
3. Fixed a bug where blobs already present locally were being unnecessarily re-downloaded
4. Added verification in tests that subsequent invocations don't refetch local blobs

The implementation remains focused on:
- `builtin/log.c` for cherry prefetch logic
- `builtin/grep.c` for grep prefetching
- Test files with expanded test coverage

Notably, Newren declined to centralize the prefetch logic as suggested by Stolee, providing a detailed technical rationale for keeping it command-specific until a third use case emerges. The series shows thoughtful responsiveness to feedback while maintaining architectural coherence. With the additional fixes and test improvements, this appears ready for integration, offering measurable performance benefits for partial clone users of these commands.
