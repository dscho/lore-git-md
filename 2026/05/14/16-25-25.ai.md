This is a documentation patch clarifying the contract for `promisor_remote_get_direct()`, part of Elijah Newren's performance optimization series for partial clone behavior. The patch explicitly states that callers must filter out locally-present OIDs before invoking the function, as the API does not perform this filtering itself (except as a fallback after fetch failures). The documentation also points callers to the appropriate helper functions (`odb_has_object()` and `odb_read_object_info_extended()`) for checking local object presence without triggering unwanted fetches.

The patch serves as important groundwork for the series by preventing future callers from making the same mistake Newren initially did - sending unnecessary fetch requests for objects already present locally. This documentation will help maintain the efficiency gains the series aims to achieve in `git cherry` and `git grep` operations under partial clone conditions. The change is straightforward and uncontroversial, simply codifying existing (but previously implicit) expectations about caller responsibilities.
