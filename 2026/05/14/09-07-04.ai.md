This is patch 1 of 3 in the fourth iteration of a well-scoped series by Jonas Rebmann fixing places in `git bisect` that hardcode the terms "good" and "bad" even when the user has configured alternate terms (e.g. "old"/"new"). The series has been through four rounds of review from Junio and Phillip Wood and appears near final form.

The patch addresses status output messages that still say "good" and "bad" regardless of the user's chosen terms. This is a real usability bug: if you start a bisect with `--term-old term2 --term-new term1`, the output would tell you `status: waiting for bad commit, 1 good commit known` while simultaneously telling you `git bisect bad` is an invalid command because you are in a term1/term2 bisect. The fix replaces hardcoded strings with `terms->term_good` and `terms->term_bad` in three status messages in `bisect_print_status()` and two error messages in `bisect_run()`. Tests are added to `t6030-bisect-porcelain.sh` that grep the output for the dynamic terms.

The patch is mechanically straightforward and the problem it fixes is clearly real -- the inconsistency it describes is exactly the kind of thing that would confuse a user trying alternate terms for the first time. The diff is compact (27 insertions, 12 deletions across two files) and the implementation looks correct at a glance. The changelog note about memory leaks in `read_bisect_terms()` and `xstrfmt()` having been fixed (from the series-level context, not visible in this patch itself) suggests the author has been responsive to review feedback. No outstanding objections remain from previous rounds.

Worth a read if you use or maintain the bisect subsystem; otherwise this is a clean, uncontroversial fix that will likely land soon.
