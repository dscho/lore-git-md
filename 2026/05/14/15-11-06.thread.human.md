René Scharfe continues his series of cleanups to Git's overflow checking infrastructure with a performance optimization targeting Clang builds. The thread began with a refactoring of strbuf_grow()'s overflow checks to use the st_add3() helper. This new patch focuses on the underlying st_add() primitive, introducing a Clang-specific optimization that uses __builtin_add_overflow() to improve performance on ARM64 (particularly Apple M1) hardware, where Clang's code generation for the current implementation is suboptimal. Benchmarking shows a 5% speedup for strbuf-heavy operations.

The change maintains all safety guarantees while being narrowly scoped - it only affects Clang builds and leaves the higher-level st_add3()/st_add4() macros unchanged. Jeff King (Peff) provided input on the approach, as noted in the Suggested-by credit. This continues René's pattern of small, focused improvements that incrementally modernize core infrastructure without changing behavior. The patch builds logically on the previous strbuf_grow refactoring while addressing a distinct performance consideration.
