René Scharfe's thread on improving Git's overflow checking has evolved from a targeted strbuf_grow optimization to a broader discussion of arithmetic safety. The original proposal to optimize strbuf_grow() using Clang's builtins led Junio Hamano to identify a deeper issue with ALLOC_GROW's argument evaluation. René has now responded with a comprehensive solution: a new uint_add_overflow() helper that would replace the current unsigned_add_overflows() macro, providing both overflow checking and result computation in one operation.

The latest proposal addresses the performance concerns while eliminating the argument evaluation pitfalls of macros. It would affect all arithmetic overflow checking in Git, making the code both safer and potentially faster. The discussion remains active as the project weighs these architectural changes against their widespread impact - the changes would modify core infrastructure used throughout the codebase. Junio's initial concerns about ALLOC_GROW have sparked what may become a significant hardening of Git's memory allocation patterns.
