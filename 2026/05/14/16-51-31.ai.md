This is a performance optimization patch targeting the revision walking code. It replaces a linked list with a priority queue in `limit_list()` to improve performance in merge-heavy repositories.

The key change switches from using a date-sorted linked list (with O(n) insertion cost) to a priority queue (binary heap) with O(log n) insertion. The patch shows significant speedups (2.5-3x) when processing large numbers of commits (thousands) in the symmetric difference, as commonly seen in merge-heavy histories. Small traversals show no measurable difference.

The optimization affects several Git commands that use `limit_list()` including `--left-right`, `--cherry-mark`, bisect, rebase's fork-point computation, and `git status --ahead-behind`. The implementation is relatively clean (21 lines added, 17 removed) since `process_parents()` already supported both data structures.

The patch includes clear benchmark results from a 2.3M-commit monorepo showing the performance impact scales with the size of the commit set being processed. The commit message thoroughly explains the algorithmic improvement and practical implications.
