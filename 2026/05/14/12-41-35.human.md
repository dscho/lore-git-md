This is the final patch (8/8) of Derrick Stolee's v4 series adding
negotiation controls for monorepo fetch and push.  It wires the
`remote.<name>.negotiationRestrict` and `remote.<name>.negotiationInclude`
config keys into the push path when `push.negotiate` is enabled.

When the user has a push-negotiating remote configured, `git push` spawns
a child `git fetch --negotiate-only` process to find common commits.
Previously that child was fed every local ref as a negotiation tip.
This patch changes the logic: if `remote.<name>.negotiationRestrict` has
been configured, those patterns *replace* the default list of all refs,
so the user can narrow what the push negotiator considers.  If
`remote.<name>.negotiationInclude` is configured, those patterns
become `--negotiation-include` arguments on the child command,
guaranteeing those tips are always advertised even if they would not
otherwise be part of negotiation.

The patch also adds plumbing in `send-pack.h` -- two new fields on the
`send_pack_args` struct -- and passes them from `transport.c` during
`git_transport_push()`.  Documentation in `remote.adoc` is updated to
note that both config keys also apply during push.  Two new tests in
`t5516-fetch-push.sh` verify each config key's push behavior, using
trace2 to confirm the negotiator actually ran and the correct number of
objects were sent.

This completes the feature -- the series started with CLI options and
their config counterparts in the fetch path, and now push is fully
wired.  The implementation follows the same logic patterns as patches 4
and 6, making it predictable and easy to review.  That is also the main
observation: this is a straightforward plumbing patch that does exactly
what the cover letter promised, with no surprises.  The test coverage
is adequate (one happy-path test per config key) and the code touches
only a small number of files.

If anyone has reservations about the overall direction of the series,
this patch is where they would want to look at the push-specific
details, but there is nothing here that looks controversial on its own.
The series as a whole has been through four rounds and the design
discussion is well settled.
