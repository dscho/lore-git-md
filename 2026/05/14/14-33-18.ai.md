This is a bugfix patch in the git-gui repository handling series. It simplifies and strengthens the repository discovery logic by exclusively using `git rev-parse --absolute-git-dir` rather than mixing direct environment variable checks with Git's built-in repository validation.

The key change is replacing the previous two-step approach (first checking GIT_DIR directly, then falling back to rev-parse) with a single rev-parse call that performs all necessary validation. This ensures errors are caught early and consistently. The patch also removes redundant directory existence checking since rev-parse's validation already guarantees this.

When repository discovery fails, the behavior now depends on whether environment variables were set: if GIT_DIR/GIT_WORK_TREE were explicitly provided, git-gui exits with an error (via the new `is_gitvars_error` helper); otherwise it falls back to the repository picker UI. This maintains the expected workflow while preventing silent failures.

The changes align git-gui's behavior more closely with command-line Git's repository handling, particularly in error cases. This is part of a larger effort to make git-gui more robust in edge cases like bare repositories and separate git-dir configurations. The patch appears well-contained and focused changes that follow the series' architectural direction.
