This is patch 2/8 of the v4 negotiation-controls series by Derrick Stolee. This is a **feature** patch that renames the existing `--negotiation-tip` option to `--negotiation-restrict`, keeping the old name as an alias.

The core change is straightforward: the patch adds `--negotiation-restrict` as the primary option name in the CLI parser (using `OPT_STRING_LIST`), and marks the old `--negotiation-tip` as an alias via `OPT_ALIAS`. This is done in both `builtin/fetch.c` and `builtin/pull.c`. The distinction matters because the `--negotiation-tip` name made it sound like the user was adding *more* tips to negotiate with, when in fact the option *restricts* the set of refs considered during negotiation -- it sets an upper bound, not a lower bound. The documentation is updated to explain that `--negotiation-restrict` is the preferred name and `--negotiation-tip` is a retained synonym.

Beyond the renaming, the patch also makes several warning messages translatable (wrapping strings in `_()`), updates references in the die message for `--negotiate-only`, and changes the option name used in warning strings throughout `builtin/fetch.c`, `transport-helper.c`, and `send-pack.c`. The test suite gets three new tests in `t5510-fetch.sh` that verify the new option works: one exercising the basic restrict behavior, one confirming glob patterns work (`*_1`), and one confirming the two option names can be mixed in the same invocation. Two test names in `t5702-protocol-v2.sh` are updated to reflect the new option name.

The commit message explains the motivation clearly: the `--negotiation-tip` name gave users the wrong mental model of what the option did. By renaming it to `--negotiation-restrict`, the semantics become obvious -- and this clearer name also sets the stage for a future `--negotiation-include` option that will provide the complementary "minimum set" behavior. No behavioral change, just a naming improvement and documentation cleanup.

This is well-motivated and well-executed, exactly the kind of careful naming fix that prevents confusion for years to come. No controversy.
