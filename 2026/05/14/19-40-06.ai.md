This is a performance optimization thread regarding the revision walking code. The original patch from Kristofer Karlsson replaced a linked list with a priority queue in `limit_list()` to improve performance in merge-heavy repositories, showing 2.5-3x speedups for large commit sets while maintaining parity for small traversals.

Junio C Hamano's review notes that the commit message's list of affected commands curiously omits the standard `A..B` range syntax. He hypothesizes this may be because modern Git (with commit-graph enabled and using --topo-order) sometimes avoids `limit_list()` entirely for such cases, referencing commit 1b4d8827 from 2019. Junio suggests extending the benchmarks to test with/without --topo-order in a commit-graph-less repository to better understand the optimization's scope.

The exchange highlights how Git's revision walking optimizations have evolved over time, with newer features like commit-graph sometimes bypassing older code paths entirely. The review maintains the project's characteristic attention to historical context and edge cases, even while evaluating a straightforward performance improvement.
