This is patch 2 of a 3-patch series (v4) by Jonas Rebmann that makes `git bisect` respect user-configured alternate bisect terms. The series is a well-scoped maintenance fix that has been through multiple rounds of review from Junio C Hamano and Phillip Wood, with all feedback addressed. No outstanding design objections remain, and the series looks close to final form.

This specific patch is a formatting cleanup, split out as a separate patch in response to a review comment from Junio. It single-quotes all occurrences of bisect terms (e.g. `good`, `bad`, or whatever the user configured) in status and error messages. The goal is consistency: some messages already quoted the terms, others didn't, and translators were inconsistent as well. The patch wraps every `term_good`/`term_bad` printf argument in single quotes across the bisect subsystem's output -- things like "the first bad commit" become "the first 'bad' commit", and "mistook good and bad" becomes "mistook 'good' and 'bad'".

The commit message is clear about the motivation and the change is mechanically straightforward. The diff is large (114 lines of test changes) but purely mechanical: every test that greps for a bisect output string just updates its expected pattern to include the single quotes. No logic changes, no new tests. The code changes in `bisect.c` and `builtin/bisect.c` follow the same pattern.

This is a minor but sensible papercut fix. The patch is correct and unlikely to be controversial. Worth noting that this series' other two patches do the real work (dynamic terms in status output and rev-parse ref lookup), while this one is purely cosmetic consistency. Anyone reviewing for merge should just verify the quoting is applied everywhere consistently -- the automated test updates mean the test suite will catch any missed spot.
