Cover letter for a patch series that has already been picked up by `next` and is waiting to graduate to `master`. The series adds a `log.diffMerges` configuration option that lets users flip the current default behavior of `git log --diff-merges` -- the default is `on`, and this option makes it `off` permanently, so that merge commits are no longer shown in the default diff output but `--diff-merges` (or sub-options like `--cc`) still works when explicitly requested. Three patches: a preparatory refactoring that moves merge-related diff-flags logic into its own helper, the new config option itself, and a documentation patch covering the option and clarifying the current `diff-merges` default behavior. The refactoring is clean and well-motivated, the config option is straightforward, and the documentation patch addresses a genuine gap (the current state where the default is "show a diff for merges" was previously undocumented). The series is already in `next` and ready to proceed to `master` -- nothing for a reviewer to do unless someone objects to the new config key.
