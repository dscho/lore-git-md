This is patch 5/7 in Justin Tobler's series to finalize the object database (ODB) transaction write interface, part of the ongoing ODB abstraction effort. The patch optimizes packfile handling for large blobs by avoiding unnecessary file descriptor seek operations.

The key change replaces a seek-based approach for handling packfile size limits with a simpler size check upfront. Previously, if writing a blob would exceed the configured pack size limit, Git would:
1. Start writing the blob
2. Detect the limit was hit mid-stream
3. Seek back in the input file descriptor
4. Start a new packfile and retry

The new approach checks the inflated blob size before writing begins. If adding this size would exceed the limit, it starts a new packfile immediately. While this may leave some unused space in packfiles (since compressed sizes vary), it eliminates the need for seeking and simplifies the code.

The patch removes the seekback logic entirely, including the `stream_blob_to_pack()` return value that previously signaled when a retry was needed. It also simplifies the hash computation by removing the need to track how much of the input has already been hashed during retries.

This change prepares for future work where the input source may not be seekable (like when using the new `odb_write_stream` interface). Patrick Steinhardt has approved the technical direction, and Jeff King's earlier review identified a resource leak that was fixed in v4. The series appears ready for merging as a significant step in the ODB abstraction effort.
