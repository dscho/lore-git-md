This is a bugfix patch in the git-gui series addressing bare repository handling. The patch simplifies the `is_bare` procedure to just check if a worktree is known (`$_gitworktree` is empty) rather than maintaining complex cached state and fallback logic.

The change removes 24 lines of legacy code that tried to determine bare status through multiple methods (rev-parse, core.bare config, and path inspection), replacing it with a single straightforward check. This aligns with the series' broader goal of making repository state detection more reliable by centralizing it around `git rev-parse` results.

The patch is part of an 11-patch v8 series that has already undergone extensive review and appears ready for merging. It represents a cleanup of technical debt in git-gui's repository detection code, removing now-redundant logic after the series' earlier patches established more robust ways to determine repository state.
