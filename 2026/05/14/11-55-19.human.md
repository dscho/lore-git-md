This is patch 3/4 in Tuomas Ahola's v3 series fixing long-standing edge cases in Git's `approxidate` date parser — and it's the core behavioral fix that the whole series has been building toward.

The problem is a quirk that has been biting Git users for two decades (Linus Torvalds reported it in 2006). When you combine a "special" time-of-day string like `noon` or `tea` with an explicit date reference — e.g. "13 May at tea" or "last Friday at noon" — the parser ignores the day you gave and rolls back to yesterday. That happens because the "specials" have a built-in feature: if the current time is before noon, `noon` wraps to the previous day. The bug is that this wrap logic fires even when you already supplied a specific day.

The fix is a three-line change to `date_time()` in `date.c`: it now checks whether `tm_mday` has already been set to a non-negative value, and only applies the "most recent" rollback when no specific day was given. The commit message walks through the examples clearly, including the old "one year ago yesterday at tea-time" example from Linus's 2006 report.

This patch is clean, well-motivated, and addresses all the feedback from Junio's v2 review — the comment wording has been improved (the author credits Jeff King's version from the earlier iteration), and the test coverage now exercises the fixed behavior from multiple "now" time positions to confirm correctness across day boundaries. Of the entire series, this is the least controversial patch and the one most likely to land without further discussion.
