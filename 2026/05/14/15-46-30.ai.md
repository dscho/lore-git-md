This is the first patch in a bugfix series addressing network address handling issues in Git's daemon mode. The patch specifically fixes IPv6 address corruption that occurs when `getaddrinfo()` returns IPv6 results but the code incorrectly assumes IPv4 format.

The fix properly handles both AF_INET and AF_INET6 address families by:
1. Checking the `ai_family` field to determine the address type
2. Extracting the correct address pointer from either sockaddr_in or sockaddr_in6
3. Passing the proper family to `inet_ntop()`
4. Adding a safety check to die on unexpected address families

The change is focused and well-contained to the `lookup_hostname()` function in `daemon.c`. It addresses a clear correctness issue that would manifest on IPv6-only hosts, where the current code would read from the wrong struct offset and produce garbage IP addresses. The patch maintains the existing behavior for IPv4 while properly supporting IPv6.

This appears to be a straightforward and necessary fix - the change is mechanical but important for correct operation. The addition of the die() for unexpected families also improves robustness by failing explicitly rather than potentially corrupting memory.
