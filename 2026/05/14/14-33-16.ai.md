This is a bugfix patch in the git-gui series addressing repository path handling. The change simplifies git-gui's startup code by using `git rev-parse --absolute-git-dir` instead of manually converting relative paths to absolute ones. 

The patch removes special-case handling for when `--git-dir` returns "." (indicating the current directory is the .git directory), since `--absolute-git-dir` always provides an absolute path. This makes the code more robust by relying on Git's built-in path resolution rather than custom logic. The change is safe since git-gui already requires Git 2.36+, and `--absolute-git-dir` has been available since 2.31.

This is patch 5/11 in a series that has already gone through extensive review (v8 was the final version). The change aligns with the series' goal of making git-gui's repository detection more reliable, particularly for edge cases like bare repositories and separate git dir configurations. The patch demonstrates good attention to detail by removing now-redundant code while maintaining all existing functionality.
