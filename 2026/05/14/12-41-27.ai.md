This is the v4 cover letter for Derrick Stolee's 8-patch series adding `--negotiation-include` and `--negotiation-restrict` options (along with their config counterparts) to Git fetch and push. This thread has been active since mid-2025 and is now in its fourth iteration.

## What this is

A feature patch series (8 patches) that overhauls Git's fetch/push negotiation tip mechanism. The core problem: in monorepos with many branches, Git's negotiation algorithm can drop critical refs (like 'release') from the have list, causing massive unnecessary downloads when those refs update. The series solves this by providing two complementary controls: `--negotiation-restrict` to limit which refs are considered, and `--negotiation-include` to guarantee specific refs are always advertised while still allowing opportunistic inclusion of others.

## Key design change in v4

The biggest structural change from v3 is patch 5/8 (new): a `have_sent()` callback interface on the negotiator struct. This replaces the earlier approach of marking included commits as `COMMON` (which was a hack that conflated two different meanings of that flag). The negotiators (`default`, `noop`, `skipping`) each implement `have_sent()` to track which commits have already been advertised, cleanly avoiding duplicates in the have stream. This is the abstraction fix that Matthew Cheetham identified as needed in his v3 review.

## What's in the 8 patches

1. **Test order flakiness fix** (t5516): a `sort -k 4` that should be `sort -k 3`, introduced in 3f763ddf28 (2024-11-22).

2. **`--negotiation-restrict` CLI option**: a synonym for the existing `--negotiation-tip`, keeping that name as an alias. Updated in pull.c, send-pack.c, transport-helper.c, and all documentation.

3. **Rename internal field `negotiation_tips` to `negotiation_restrict_tips`**: across transport, fetch-pack, and their header files.

4. **`remote.<name>.negotiationRestrict` config**: multi-valued config option, uses `parse_transport_option()` for consistency. Empty value resets the list.

5. **`have_sent()` negotiator interface** (new patch): three strategy implementations. The fetch-pack code calls `have_sent()` for each unconditional include-have before starting the negotiator's `next()` iterator.

6. **`--negotiation-include` CLI option**: ref patterns or commit hashes that are always sent as haves. Moves ref-pattern resolution into `builtin/fetch.c` so `fetch-pack` receives pre-resolved `oid_array` objects rather than doing its own ref lookup.

7. **`remote.<name>.negotiationInclude` config**: same pattern as patch 4, but for the include list. Empty value resets.

8. **Push negotiation wiring**: `send-pack.c` passes the `remote.*.negotiationRestrict` and `remote.*.negotiationInclude` config values when spawning the `git fetch --negotiate-only` child process, and documents that these configs apply during push with `push.negotiate`.

## What the cover letter doesn't say

The test flakiness fix in patch 1 identifies 3f763ddf28 as the regression source but does not explain *why* `sort -k 4` was wrong there -- the commit message just notes the column mismatch. It would be helpful to understand whether the original author used `-k 4` intentionally with a different sort implementation in mind, or if it was simply a bug from the start. This is a small observation on an otherwise clean patch.
