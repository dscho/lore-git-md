## Patch 4/4 of a 4-patch series fixing approxidate edge cases

This is the final patch in Tuomas Ahola's v3 series, and it's the one Junio hasn't reviewed yet -- the core logic in this patch is unchanged from v2's patch 3/3. It introduces a deferred-adjustment scheme for the "now" and "yesterday" specials, using negative `tm_mday` values as markers that get resolved later by `update_tm()`.

The problem it tackles: "tea yesterday" and "yesterday tea" currently produce different results because the "most recent in the past" rollback in `date_time()` fires independently of any explicit day specification that came earlier. The patch makes "now" and "yesterday" set `tm_mday` to -1 (instead of calling `update_tm()` directly), and changes `update_tm()` to interpret negative values as relative offsets from "now" -- -2 means yesterday, -3 means two days ago, and so on. The `date_time()` function now uses a -2 marker instead of calling `update_tm()` directly, so the day offset can be overridden by an explicit date specification that arrives later in parsing.

It's a clever mechanical trick -- reusing negative mday as a deferred marker -- and the code change is modest (about 25 lines in date.c, 4 lines of tests). The commit message is clear about the motivation, and the tests cover "noon yesterday", "tea last saturday", and the "noon today" edge case at a time-shifted offset.

The caveat is that this patch has never been reviewed by Junio, and the approach is somewhat subtle. The negative-mday-as-deferred-marker scheme is a neat hack but it touches the core of date parsing and might have edge cases the author hasn't thought of. That said, it's isolated from the other patches: it can be applied or dropped independently of patches 1/4 and 3/4 (which are the core bugfix and the test infrastructure), and it has no dependency on the still-controversial patch 2/4 (the "today" alias). If Junio has concerns, they're likely to be about whether the deferred-marker approach is too clever for what it achieves, or whether there are untested interaction paths.

Overall, this is the piece of the series that needs fresh eyes. The other three patches are either clean (1/4 and 3/4) or still in design discussion (2/4). This one represents genuine new logic that hasn't had maintainer scrutiny.
