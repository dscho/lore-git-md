This is a follow-up in the ongoing discussion about Git's date parsing behavior, specifically regarding the "today" alias in the approxidate series. The author, Tuomas Ahola, responds to Junio C Hamano's clarification that the current behavior (treating "today" as equivalent to "now") was never an intentional design choice but rather a side effect of how approxidate handles unrecognized strings.

Tuomas proposes a minimal implementation that would make "today" set only the day-of-month field to match the current day, without committing to any particular time-of-day semantics. This approach would allow expressions like "today at noon" to work while leaving the broader "today" meaning open for future discussion. The change is presented as a compromise that doesn't lock in behavior that might need revisiting later.

The exchange shows the author engaging with Junio's core concern about semantic design rather than just implementation details. This patch remains the key open question in the otherwise largely resolved series, with patches 1/4 and 3/4 already accepted and 4/4 awaiting Junio's review. The discussion has moved from technical correctness to intentional API behavior - a sign the series is nearing completion once this design question is settled.
