This is a cover letter for a bugfix series targeting git-gui's handling of bare repositories and missing worktrees. The series represents the culmination of a multi-iteration effort (previously at v7) to address longstanding issues where git-gui would fail with cryptic errors in these scenarios.

The 11-patch series rewrites git-gui's repository and worktree discovery logic, with key improvements:
- Proper support for blame/browser subcommands in bare repositories
- Correct handling of .git directory parent-as-worktree cases
- More reliable repository picker behavior that doesn't mask configuration problems
- Unified use of `git rev-parse` for repository discovery to maintain consistency with command-line Git
- Explicit subcommand support for `gui` and `pick` modes

The changes maintain backward compatibility while fixing several pain points, particularly around environment variable handling (GIT_DIR/GIT_WORK_TREE) and worktree detection. The cover letter notes an interesting design question about whether git-gui should export GIT_WORK_TREE at all, given that the current directory already communicates this information to subprocesses.

This appears to be the final form of the solution after extensive review and iteration, with the cover letter serving as documentation of the architectural approach. The patches touch core git-gui startup logic but focus on making existing behavior more robust rather than introducing new features.
