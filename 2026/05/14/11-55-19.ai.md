This is patch 3/4 in a series by Tuomas Ahola fixing long-standing edge cases in Git's approxidate date parser, and it represents the core behavioral fix of the series.

The patch addresses a specific bug: when a user writes something like "today at noon" or "13 May at tea", the special time-of-day keywords "noon" and "tea" have logic that rolls back to the most recent occurrence of that time -- meaning they go to yesterday if the current time is before noon or tea time. This rollback fires even when the user has explicitly specified a day, producing wrong results like "today at noon" yielding yesterday's noon rather than today's. The commit message traces this quirk back to a 2006 complaint by Linus Torvalds about "one year ago yesterday at tea-time" being "just silly and not even correct."

The fix is a tidy three-line change in the `date_time()` function. It adds a guard that checks whether `tm_mday` is non-negative (meaning the caller already set a specific day-of-month). If it has, the "most recent" rollback logic is skipped entirely. The test file gets four new test cases, including time-shifted variants using the new offset infrastructure from patch 1/4.

The quality of the patch is strong: the commit message explains the problem clearly with concrete examples, the code change is minimal and well-commented (the author incorporated a comment suggested by Jeff King in earlier review), and the tests cover both the basic fix and the time-shifted variant to confirm the rollback is properly suppressed regardless of when "now" is. The commit message also helpfully references the original 2006 bug report by Linus Torvalds, providing historical context without editorializing.

This is a low-risk, well-understood patch. It addresses all feedback from Junio C Hamano and Jeff King on the v2 version (clearer commit message, better comment wording). No open issues remain on this patch from previous review rounds. If the "today" alias patch (2/4) ends up being dropped, this patch is unaffected and stands on its own as a valuable fix.
