This is the final patch in a completed bugfix series for git-gui, adding explicit subcommands to control repository picker behavior. The patch introduces two new subcommands:

1. `gui` - Runs the GUI only if repository/worktree succeeds, failing with an error message rather than falling back to the picker
2. `pick` - Forces the repository picker to run first before starting the GUI

The change maintains backward compatibility while giving users more control over when the picker appears. The implementation adds a `run_picker_on_error` flag to control the fallback behavior and updates the usage message to include the new subcommands. This completes the architectural unification of git-gui's repository handling that was described in earlier patches, with all state detection now going through `git rev-parse`.

The patch follows the series' pattern of making existing behavior more robust rather than introducing new features. It has been signed off by Mark Levedahl, indicating consensus was reached on the technical approach. This appears to be the final form of the solution after extensive review and iteration.
