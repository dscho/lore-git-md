This is patch 2/4 of Tuomas Ahola's series fixing edge cases in Git's date approximation parser, specifically the "today" alias patch -- the one that was split out from the core behavioral fix to be independently negotiable. The change itself is trivial, a one-line addition to the specials table in `date.c` that makes `"today"` an alias for `date_now()`, meaning approxidate treats it exactly like `"now"`.

The commit message is candid about the thinness of this change: as far as approxidate is concerned, `"today"` is already a no-op, so this just makes the existing behavior explicit in the code. The justification is forward-looking: once this alias exists, later patches can give `"today"` distinct behavior in combos like `"today at noon"`. A maintainer's note attached to the patch flags a potential problem with `git log --since=today`, where the `--since` semantics (strictly after the given time) might produce surprising results -- the reader would get no commits rather than commits from today. The author acknowledges the concern but does not resolve it in this patch, noting that if the desired behavior is `--since=midnight`, a different implementation would be needed.

This is the contentious patch in the series. Junio raised the same `--since` concern during v2 review, and it remains unresolved here. The patch is small, well-scoped, and technically correct for its stated purpose, but the practical consequence for command-line usage is not fully settled. A reader tracking this thread will want to watch whether the `--since` objection is addressed in a follow-up or whether this patch gets dropped from the series as a result.
