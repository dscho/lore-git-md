This is the third patch in Elijah Newren's performance optimization series for partial clone behavior, specifically targeting `git cherry`. The patch implements blob prefetching to avoid the latency of fetching blobs one at a time in partial clones.

The key technical contribution is a new `prefetch_cherry_blobs()` function that:
1. Temporarily replaces the hashmap comparison function to identify which blobs would be needed for patch-ID calculations
2. Collects these blob OIDs without triggering fetches
3. Fetches them all in a single batch
4. Restores the original comparison function

The implementation carefully handles edge cases like binary files (which don't need blob content for patch-IDs) and verifies that subsequent invocations don't refetch already-present blobs. The accompanying test demonstrates the prefetch behavior in a partial clone scenario and verifies the no-refetch optimization.

This builds on the series' goal of extending batch prefetching to more commands after its success in checkout/diff/merge operations. The patch shows thoughtful attention to the command's specific needs while maintaining the partial clone performance benefits. With the test coverage and fixes from earlier versions now incorporated, this appears ready for integration.
