This is v3 of a three-patch series (now reorganized as four patches) by Tuomas Ahola, fixing long-standing quirks in Git’s fuzzy date parser ("approxidate"). The problem is that special time words like "noon" and "tea" (5 PM) produce wrong dates when combined with a specific day — for example, "last Friday at noon" might give you the previous day's noon instead. This series makes those combinations work predictably, regardless of the current time of day. The v2 review by Junio and Jeff King left open items that this version addresses: the "today" alias from v2 has been split into its own preparatory patch (now patch 2/4), and the test infrastructure from patch 1/3 now accepts human-readable time offsets like "-12 hours" or "+36 hours" instead of the opaque "+48" that Jeff King flagged as awkward. Junio’s three coding-style nits on the test helper have been applied.

Patch 1/4 adds that test infrastructure: a new optional last argument to the `check_approxidate` helper that shifts the test’s "now" time, letting tests exercise time-of-day-dependent behavior (e.g., whether "noon" means today or yesterday depending on whether it’s morning or afternoon). Patch 2/4, new in this series, adds "today" as an alias for "now". This was part of the v2 bugfix but raised a substantive concern from Junio: `--since=today` would be exclusive (meaning "strictly after today"), which naive users would not expect. In v3, the alias is standalone rather than bundled with the fix, and Junio seemed to have relaxed his concern — his review of this patch was basically "OK, that was the only thing, and now it is addressed" after the author clarified that `--since=today` already treats "today" like the current timestamp, so the alias doesn’t introduce new confusion. Patch 3/4 is the core fix: when a time-based special like "noon" fires, the "roll back to most recent" logic now checks whether the day-of-month was explicitly provided and skips the roll if it was. Patch 4/4 uses a different approach for "now" and "yesterday": it defers the day-of-month adjustment using a negative sentinel value, so that those specials don’t need the same rollback logic. The total delta is 66 insertions, 11 deletions across date.c and t/t0006-date.sh.

For a human reader: this is a well-scoped, well-tested bugfix series that addresses behaviors known to be broken since at least 2006. The author has been responsive to review feedback — the v2 open items are closed, the "today" alias concern has been resolved, and the test infrastructure now uses human-readable offsets as Peff suggested. Junio reviewed v3 and gave a green light on patch 2/4 (the alias). Patch 3/4 and 4/4 are the remaining substantive changes. If you have ever been confused by `git log --after="last week noon"` landing on the wrong day, this series directly fixes that. It is ready for merge.
