This is the second patch in a bugfix series addressing network address handling issues in Git's daemon mode. The patch fixes IPv6 address truncation in logs by correcting the buffer size passed to `inet_ntop()`.

The key change replaces the use of `ai_addrlen` (the sockaddr struct size) with `sizeof(ip)` (the actual buffer size) when calling `inet_ntop()`. This ensures IPv6 addresses aren't silently truncated - the previous code would pass only 28 bytes when INET6_ADDRSTRLEN requires 46 bytes. The patch also simplifies the `ip2str()` function signature by removing the now-unused length parameter and updates all callers.

The fix is straightforward and maintains the existing functionality while properly handling IPv6 addresses. This continues the series' focus on correctness in the daemon's network plumbing, following the first patch's fix for IPv6 address corruption. The changes are limited to `daemon.c` and don't affect the protocol or on-disk formats.

This appears to be a well-motivated fix for a real issue that could affect IPv6-only hosts. The patch follows the same careful approach as the first in the series, with clean changes and no obvious side effects.
