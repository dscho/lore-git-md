Performance optimization patch targeting the overflow checking infrastructure. This is the second patch in a series (following the strbuf_grow refactoring) that improves how Git handles size_t overflow detection.

René Scharfe introduces a Clang-specific optimization for the st_add() helper function, which is used throughout the codebase for safe size_t arithmetic. The patch provides a variant of st_add() that uses __builtin_add_overflow() when compiling with Clang, as the compiler currently doesn't optimize the existing unsigned_add_overflows() check as well as GCC does on ARM64 (specifically Apple M1). Benchmark results show a 5% speedup for a strbuf-heavy operation (git cat-file --batch-all-objects) on M1 hardware.

The change maintains identical overflow safety guarantees while improving performance on Clang builds. The implementation is conditional on __clang__ to avoid changing behavior for GCC, which already generates optimal code. This continues René's pattern of small, focused improvements to core infrastructure - in this case building on the previous st_add3() refactoring in strbuf_grow().

The patch includes a Suggested-by credit to Jeff King (Peff), indicating the optimization approach was discussed with another experienced contributor. The change is narrowly scoped to the performance-sensitive st_add() primitive while leaving the higher-level st_add3() and st_add4() macros unchanged.
