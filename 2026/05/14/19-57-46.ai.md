Performance optimization follow-up discussing the priority queue change for `limit_list()`. Derrick Stolee reviews Kristofer Karlsson's patch that replaces a linked list with a priority queue to improve merge-heavy repository performance.

Stolee confirms the technical merits of switching from O(n) to O(log n) insertion cost, noting the patch's clean implementation that leverages existing `process_parents()` support for both data structures. He highlights the practical impact on commands like `git log --graph` when commit-graph files are absent, and suggests additional benchmarking scenarios - specifically testing with/without `--topo-order` in commit-graph-less repositories to better understand the optimization's scope.

The review identifies an opportunity to include the benchmark data from the cover letter in the commit message itself, and asks whether the Git repository's own history (particularly around point releases) could demonstrate the improvement. Stolee also inquires about potential perf test coverage, though acknowledges this is a performance-only change that wouldn't require new functional tests.

This is a substantive review that both validates the technical approach and suggests ways to strengthen the patch's presentation and evaluation, while noting the clean implementation that minimizes churn by building on existing infrastructure.
