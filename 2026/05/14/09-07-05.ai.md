This is patch 2/3 in Jonas Rebmann's v4 series to make `git bisect` respect user-configured alternate bisect terms. This patch adds single-quoting around bisect terms in all status and error messages, addressing a formatting consistency concern raised by Junio C Hamano in earlier review rounds.

The change is mechanically straightforward but touches a large surface area: every place in `bisect.c` and `builtin/bisect.c` where a bisect term appears in a user-facing message gets single quotes wrapped around the `%s` format specifier. This affects the "first bad commit" output, "waiting for both good and bad commits" status lines, "mistook good and bad" error messages, log-file comments, and run-command output. The test suite in `t6030-bisect-porcelain.sh` is updated in lockstep -- every `grep` pattern that matched the old unquoted output now matches the quoted version, and several tests that used bare `grep` have been converted to `test_grep` as well. The test changes account for 114 lines of the diff, but every one is a mechanical string update.

This is a formatting-only change. It does not alter any behavior -- the terms still come from the user's configuration (or default to "good"/"bad"), they are just now printed with quotes around them everywhere rather than inconsistently. The commit message explains the motivation well: since terms can be arbitrary strings, quoting makes it clearer which words are the term values versus prose, and it brings consistency to places where translators had already added quotes on their own. The patch is exactly what you would expect for a cleanup of this kind -- zero behavioral surprises, complete test coverage, and a clear before/after that is easy to verify by inspection.
