This is the 10th patch in an 11-part bugfix series for git-gui, focusing on worktree discovery improvements. The patch refactors how git-gui determines the working tree location, making it more robust in edge cases while maintaining backward compatibility.

The key changes in this specific patch:
- Moves worktree discovery immediately after repository discovery, centralizing error handling
- Uses `git rev-parse --show-toplevel` as the primary method for finding the worktree root
- Handles three fallback cases when worktree discovery fails: invalid environment variables, bare repository mode, and parent-as-worktree detection
- Simplifies the path normalization logic by removing redundant checks
- Maintains the same end-state behavior while making the code more maintainable

This is part of a larger effort to fix git-gui's handling of bare repositories and missing worktrees, addressing regressions dating back to 2014/2019. The series has gone through extensive review (now at v8) and appears ready for merging, with Mark Levedahl signing off on the architectural consistency. The changes focus on making existing behavior more robust rather than introducing new features.
