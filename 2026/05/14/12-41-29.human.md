This is patch 2/8 of Derrick Stolee's v4 series adding negotiation controls to `git fetch`. This particular patch is a straightforward rename-and-alias operation: it introduces `--negotiation-restrict` as the preferred name for what was previously `--negotiation-tip`, preserves the old name as an alias via `OPT_ALIAS`, and updates documentation, warning messages, and error strings to prefer the new name.

The reasoning given in the commit message is that `--negotiation-tip` is confusing. A user reading "tip" might think this is a *minimum set* -- tips you want to negotiate from -- when in fact it is a *maximum set*: a restriction on which refs are considered. The new name `--negotiation-restrict` is intended to make this limiting semantics obvious, and it also frees up the "tip" namespace for the complementary `--negotiation-include` option that comes later in this series.

The patch touches eight files. In `builtin/fetch.c` and `builtin/pull.c`, a `--negotiation-tip` option defined with `OPT_STRING_LIST` is replaced by a `--negotiation-restrict` option pointing to the same variable, and `OPT_ALIAS` is used to make the old name an alias. The same pattern is applied in `send-pack.c` for the child process invocation. Warning and error messages are updated to say `--negotiation-restrict` instead of `--negotiation-tip`, and crucially they are also made translatable (the `_()` wrapper is added). Two existing test strings in `t5702` are updated to match the new fatal-error message, and three new tests in `t5510` validate that the new option works, handles globs, and coexists with the old alias on the same command line.

This is a mechanical renaming patch. It does not change any behavior. The only substantive work is the careful use of `OPT_ALIAS` to ensure both old and new names work without confusing the help text or option parsing, plus the i18n wrapping of messages. The test coverage is decent: the glob test and the mixing test are worthwhile additions. There is nothing controversial here -- the reasoning is sound, the implementation is clean, and the change is backwards compatible by design.

Bottom line: a sensible rename that clarifies the semantics, done carefully with alias support and updated tests. Part of the larger negotiation-overhaul series that is gearing up for `next`.
