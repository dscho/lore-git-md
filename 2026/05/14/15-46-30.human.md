This is the first patch in a bugfix series addressing network address handling issues in Git's daemon mode. The patch specifically fixes IPv6 address corruption that occurs when `getaddrinfo()` returns IPv6 results but the code incorrectly assumes IPv4 addresses.

The issue stems from unconditionally casting the address to `sockaddr_in` and using `AF_INET` with `inet_ntop()`, which causes incorrect memory access on IPv6-only hosts. The fix properly handles both IPv4 and IPv6 address families by checking `ai_family` and extracting the correct address pointer before calling `inet_ntop()`. It also adds a safety check to die on unexpected address families.

The change is focused and well-contained to `daemon.c`, touching only the `lookup_hostname()` function. The fix appears technically sound and addresses a clear correctness issue that could affect IPv6 deployments. The patch maintains the existing behavior for IPv4 while properly supporting IPv6, and the defensive programming against unexpected address families is a welcome addition.

This is a straightforward bugfix that should be uncontroversial, though reviewers will likely want to verify the behavior on IPv6-only test environments. The patch is part of a series that also addresses IPv6 address truncation and NULL pointer safety in the same area of code.
