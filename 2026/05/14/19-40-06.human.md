This is a follow-up discussion on a performance optimization patch that replaces a linked list with a priority queue in `limit_list()` to speed up revision walking in merge-heavy repositories. The original patch showed 2.5-3x speedups for large commit sets while maintaining parity for small traversals.

Junio C Hamano notes that the patch's description curiously omits the standard `A..B` range syntax from the list of affected commands. He suggests this might be because modern Git (with commit-graph enabled) sometimes avoids using `limit_list()` for such ranges when in topo-order mode. He proposes extending the benchmark to test with and without `--topo-order` in a repository without commit-graph to better understand the optimization's scope.

The exchange indicates the patch is technically sound (Junio calls the results "impressive") but could benefit from more comprehensive benchmarking to fully characterize its impact across different revision walking scenarios. This would help users understand when they can expect to see the performance improvements.
