Documentation patch clarifying promisor-remote behavior for partial clones.

This is the first patch in Elijah Newren's v3 series optimizing `git cherry` and `git grep` for partial clones. It adds API documentation to `promisor_remote_get_direct()` explaining that callers must filter out locally-present objects before requesting fetches from promisor remotes. The current behavior silently includes already-present objects in fetch requests, making them unnecessarily large.

The patch spells out this previously implicit contract and points callers to the correct helper functions (`odb_has_object()` and `odb_read_object_info_extended()`) for checking local presence without triggering unwanted fetches. This documentation gap was discovered when Newren initially wrote two callers that missed this filtering step, leading to inefficient fetches.

The change is straightforward and uncontroversial - it documents existing behavior rather than changing it. As the first patch in a performance-focused series, it provides important context for the optimizations that follow. The thorough documentation will help prevent similar oversights by future contributors working with the promisor-remote API.
