Performance optimization follow-up discussing benchmark results and implementation alternatives for the commit-reach.c improvement.

Jeff King (Peff) responds to Kristofer Karlsson's patch that optimized `tips_reachable_from_bases()` by replacing a linear scan with decoration hash lookups. While the original patch showed 4x speedups in a monorepo with 10,000 refs, Peff reports seeing a slowdown (650ms to 830ms) when testing on linux.git with synthetic branches. This suggests the optimization's benefits may be repository-dependent.

Peff questions the choice of using Git's decoration API for the optimization, noting several alternatives that might be cleaner:
- oidmap (though with boilerplate)
- khash with custom value type
- commit-slab (using commit IDs to index an array)
- oidset for simple membership testing
- object-flags bit

The response indicates the core optimization idea is sound but needs more investigation into both the performance characteristics across different repository shapes and the most appropriate data structure implementation. Peff's benchmarking suggests the current approach may not be universally faster, while his technical alternatives offer potentially cleaner solutions to the same problem.

This moves the discussion from initial proposal to deeper technical evaluation, focusing on both empirical results and implementation choices. The thread now has two clear directions to explore: understanding the performance discrepancy and selecting the best underlying data structure for the optimization.
