Performance optimization for reachability checks in ref-filter operations.

This patch from Kristofer Karlsson improves the performance of `tips_reachable_from_bases()` in commit-reach.c, which is used by commands like `git for-each-ref --merged` and `git branch --contains`. The original implementation did a linear scan through all tip commits for each visited commit during the graph traversal, resulting in O(C*T) complexity. The new version uses Git's decoration hash to store tip commit indices, reducing the per-commit lookup to constant time.

The benchmark shows significant speedups (4x faster) for `for-each-ref --merged` on a large monorepo with 2.3M commits and 10,000 refs, as this command checks all refs as tips. The improvement is smaller for commands like `branch --merged` that check fewer tips.

The author notes some rough edges in the implementation (hacky pointer casting, unsigned wraparound check) that could be cleaned up in follow-up patches, but presents this minimal version first for discussion. The core optimization idea appears sound and well-motivated by the performance data.
