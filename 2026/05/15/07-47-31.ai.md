This is a performance optimization patch for revision walking, now in its second iteration with benchmark data incorporated in response to reviews. The patch replaces a linked list with a priority queue in `limit_list()` to improve performance in merge-heavy repositories, particularly for commands like `--left-right`, `--ancestry-path`, and `git status --ahead-behind`.

The author provides detailed benchmark results showing 1.6-4.3x speedups depending on the scenario, with the largest gains seen when commit-graph is enabled (2.5x faster) and for ancestry-path queries (4.3x faster). The optimization is most effective for repositories with many merge commits where the active frontier grows large, while showing negligible impact on mostly-linear histories like git.git itself.

Technical discussion in this round confirms that the edge case Jeff King identified regarding `revs->unsorted_input` is not a practical concern, as the code paths where it would matter don't reach `limit_list()`. The author also notes this change would integrate cleanly with Peff's parallel work to convert `revs.commits` to a priority queue.

The patch appears technically sound with positive reviews from multiple domain experts (Junio, Stolee, and Peff). Remaining considerations include whether to add a perf test for this optimization path and how to best present the benchmark data in the commit message. The author is preparing a revised version that will incorporate these points.
