This is the final implementation of the `--max-count-oldest` feature for revision walks, addressing all substantive feedback from previous iterations. The patch from Mirko Faina introduces a new option that complements `--max-count` by showing the oldest N commits in a history rather than the newest.

The implementation preserves the optimized sliding window algorithm (O(K) space, O(N) time) from earlier versions while incorporating several key improvements:
- Proper integration with `--boundary` and `--graph` output modes
- Clear error messages for invalid combinations with `--skip` or `--max-count`
- Comprehensive test coverage including edge cases
- Documentation that stands independently rather than referencing `--max-count`

The patch represents the culmination of multiple rounds of review, with all technical concerns addressed. The only remaining change is a final whitespace fix (tab-to-space conversion) that will be included in v7. This feature provides a clean solution for users who need to view the earliest commits in a history without resorting to complex shell pipelines.
