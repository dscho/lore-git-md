This is a technical review in the ongoing `the_repository` removal effort, specifically addressing the migration of `core.precomposeunicode` configuration. Tian Yuchen raises an architectural concern about how the precompose_unicode handling is implemented in the filesystem wrapper functions.

The key observation is that the current patch adds repository awareness to `precompose_utf8_readdir()` (a `readdir()` wrapper), while Yuchen suggests it would be more appropriate to handle this in the corresponding `opendir()` wrapper instead. The argument is that directory handle initialization (`opendir`) is the natural place to determine whether precompose behavior should be applied, rather than checking on every `readdir` call.

This is a substantive review that engages with the underlying design rather than just the mechanical changes. Yuchen doesn't object to the overall goal of removing the global variable, but suggests a potentially cleaner way to structure the filesystem wrapper functions. The feedback is constructive and specific, pointing to a concrete alternative implementation approach.

The review doesn't block progress - the current approach works and matches the series' pattern - but offers food for thought about future refactoring opportunities in the filesystem compatibility layer. This kind of design-level feedback is valuable for the long-term maintainability of the code, even if it may not require immediate changes to this particular patch.
