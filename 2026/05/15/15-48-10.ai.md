This is the second patch in Philippe Blain's documentation series clarifying Git's raw diff output format. The patch specifically addresses how `git diff-files` displays unmerged files, noting that unlike other diff commands which show one line per changed file, `git diff-files` shows two lines for unmerged files: an "unmerged" line ('U') and an "in-place edit" line ('M').

The change is small and focused, updating the `diff-format.adoc` file to document this existing behavior that has been present since 2005. The commit message clearly explains the change and provides the commit hash where the behavior was introduced. This continues the series' theme of making the documentation more accurate and complete regarding diff output formats.

The patch appears uncontroversial and maintains consistency with the series' goal of catching documentation inconsistencies. It follows naturally from the first patch's cleanup of diff output documentation and keeps the scope limited to factual corrections without changing any behavior.
