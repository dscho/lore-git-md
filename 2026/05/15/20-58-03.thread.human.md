This RFC thread discusses a small but thoughtful change to Git's date parsing: making "today" resolve to midnight rather than the current time. The original patch noted that while "today" isn't currently a valid date format, when it falls through to the current time it can incorrectly include future commits in `git log --since=today` queries. The proposed solution adds a "today" handler that returns midnight, making such queries more intuitive.

Junio Hamano, the Git maintainer, has weighed in with characteristically nuanced feedback. He agrees the midnight definition works well for `--since`, but points out it creates ambiguity for `--until=today` in the afternoon—where "until today" would more naturally mean "until now" rather than "until midnight tonight." While acknowledging this can't be perfectly resolved without deeper changes to date parsing, Junio suggests the midnight definition provides more practical utility overall, especially for viewing "today's work." He requests the commit message explicitly document this tradeoff before proceeding.

The discussion has clarified both the value and limitations of the change, with Junio's input steering it toward a well-justified improvement. The patch appears headed for acceptance with minor documentation updates to explain the `--until` edge case.
