The thread discusses a proposed change to Git's date parsing that would make "today" resolve to midnight when no specific time is given, rather than the current behavior of using the current time. This primarily affects commands like `git log --since=today`, where the current behavior can incorrectly include future commits. The patch author, Tuomas Ahola, has submitted a second version that maintains the midnight definition for `--since` while explicitly documenting the tradeoff for `--until` (where "until today" would naturally mean "now" rather than midnight).

Junio C Hamano, the Git maintainer, has now responded positively to the v2 patch, expressing approval of its approach and asking how it relates to Tuomas's previous work on improving time specifications like "noon" and "tea". Junio suggests potentially coordinating this change with those other date-related improvements, indicating the solution is technically sound and likely to be merged once integrated with related pending work. The thread appears headed toward resolution, with this well-considered quality-of-life improvement to Git's date handling on track for inclusion.
