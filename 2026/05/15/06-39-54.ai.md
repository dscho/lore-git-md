This is a bugfix targeting the promisor pack fast-path in `connected.c`. The patch addresses a file descriptor leak that can cause deadlocks in `receive-pack` when used with partial clones.

The issue stems from the promisor fast-path added in 50033772d not properly cleaning up the `err_fd` file descriptor before returning, despite documentation in `connected.h` promising this would happen. This same oversight has caused deadlocks twice before in `receive-pack` (fixed in 49ecfa13f and 6cdad1f13), where the async sideband muxer waits indefinitely for EOF on this descriptor.

The fix is straightforward - adding the missing `close(opt->err_fd)` call in the promisor fast-path exit. The patch is small (2 lines) and well-motivated, with clear references to prior related fixes. It follows the established pattern seen in the other exit paths of `check_connected()`.

This appears to be a solid fix for a real issue that has manifested multiple times in the past. The commit message provides good context about the problem's history and impact, making it easy to verify the correctness of the solution. The change is low-risk as it only affects error handling paths in partial clone scenarios.
