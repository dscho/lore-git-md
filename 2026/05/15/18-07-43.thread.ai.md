Thread identity: Performance optimization patch for commit-reach.c's `tips_reachable_from_bases()` function, used by ref-filter operations like `for-each-ref --merged` and `branch/tag --contains`.

Core problem: Current implementation has O(C*T) complexity from linear tip scans. The optimization aims for O(C+T) by using faster lookup structures, but initial benchmarks show inconsistent speedups across repository types.

Key technical details: The commit-reach.c change would replace linear scans with a lookup structure for tip references. Jeff King's response identifies multiple implementation alternatives beyond the original decoration-based approach: oidmap, khash with custom values, commit-slab, oidset, or object-flags bit. Each has tradeoffs in boilerplate, memory use, and lookup speed.

Current status: Initial version showed 4x speedup in monorepo with 10,000 refs, but Jeff King observed a 28% slowdown (650ms->830ms) in linux.git with synthetic branches. The core optimization concept remains valid but requires more investigation of performance characteristics across repository shapes.

Open questions: 
1. Why the performance impact varies between repository types
2. Which data structure is most appropriate (decoration vs. oidmap vs. khash vs. commit-slab vs. oidset vs. object-flags)
3. Whether to proceed with the current approach or switch implementation strategy

Participant positions:
