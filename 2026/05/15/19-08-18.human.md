This is a technical review of a refactoring patch that modified the ALLOC_GROW macro to evaluate its arguments only once. Jeff King (Peff) identifies a potential regression in the patch - it could introduce array overflows when callers pass non-size_t arguments (like 'int') due to type conversion issues.

The review is substantive, pointing to a concrete example (alloc_node()) where this could occur and explaining how the current overflow protection would break with the proposed change. Peff notes that while Git generally uses size_t for allocations, there are likely holdouts that could be affected.

This feedback suggests the patch needs adjustment to handle mixed integer types safely, either by adding explicit type checking or preserving the original overflow protection logic. The issue wasn't caught in initial review, showing how subtle macro behavior can be.
