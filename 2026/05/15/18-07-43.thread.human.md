This thread explores a performance optimization for `commit-reach.c`'s `tips_reachable_from_bases()` function, which underpins operations like `for-each-ref --merged` and `branch --contains`. The original patch by Kristofer Karlsson showed promising 4x speedups in a monorepo with 10,000 refs by replacing linear scans with a decoration-based lookup structure, but Jeff King (Peff) found it regressed performance by 28% in linux.git with synthetic branches.

Kristofer has now diagnosed the linux.git regression: the decoration approach had flawed early termination logic when multiple refs pointed to the same commit, causing unnecessary graph traversal due to hash collisions. With this fixed, benchmarks show consistent 4.3x speedups in both repository types (1.33s → 0.31s for --merged operations). While the algorithmic improvement is now validated, Kristofer agrees with Jeff that the implementation needs refinement—the current hack of casting integers to void pointers is unclean. The discussion now turns to selecting a more appropriate low-level structure, with object-flags bits and commit-slabs as leading candidates. The optimization's core premise stands, but the final implementation choice will determine its readiness for merging.
