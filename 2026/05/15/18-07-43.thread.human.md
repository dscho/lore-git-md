This thread explores a performance optimization for `tips_reachable_from_bases()` in commit-reach.c, which affects commands like `for-each-ref --merged`. The original patch by Kristofer Karlsson showed promising 4x speedups in monorepos by replacing linear scans with decoration hash lookups. However, Jeff King (Peff) has raised important caveats from testing on linux.git, where the change actually slowed operations from 650ms to 830ms. 

Peff suggests the optimization's benefits may vary by repository structure and proposes alternative implementations using oidmap, khash, commit-slab, oidset, or object-flags that might offer cleaner solutions. The discussion has now moved beyond the initial proposal to focus on two key questions: understanding why performance gains aren't universal across repository types, and evaluating which data structure would be most appropriate for this optimization. While the core idea remains sound, these findings indicate the implementation needs more careful benchmarking and design consideration before proceeding.
