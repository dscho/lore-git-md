This is a refactoring patch that modifies the ALLOC_GROW macro to evaluate its second argument (the new element count) only once. The change addresses a potential issue where the count expression might have side effects by moving the evaluation into a new helper function st_alloc_nr().

The patch comes from René Scharfe, a frequent contributor known for clean, focused refactorings. It was suggested by Junio Hamano (the Git maintainer), indicating the change aligns with project direction. The implementation introduces a new static inline function while maintaining the same growth behavior - arrays still grow by at least 50% (via alloc_nr) unless the requested size exceeds that.

The change is mechanical and touches only git-compat-util.h, modifying a core utility macro used throughout the codebase for dynamic array growth. The patch follows Git's coding style and includes the standard documentation block explaining ALLOC_GROW's purpose.
