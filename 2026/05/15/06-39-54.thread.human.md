This thread addresses a file descriptor leak in the promisor pack fast-path within `connected.c`, which can lead to deadlocks in `receive-pack` when used with partial clones. The issue occurs when the fast-path fails to close the `err_fd` descriptor before returning, despite documentation promising this cleanup. This same oversight has caused deadlocks twice before in `receive-pack`, where the async sideband muxer would hang waiting for EOF on the leaked descriptor.

The proposed fix is minimal and targeted - adding a single `close(opt->err_fd)` call in the promisor fast-path exit. The patch follows the established pattern seen in other exit paths of `check_connected()` and comes with a clear commit message documenting the problem's history and impact. Given this is a repeat issue with prior fixes following the same pattern, and considering the change only affects error handling in partial clone scenarios, the fix appears both correct and low-risk.
