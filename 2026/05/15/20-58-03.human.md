This is a feature proposal to make "today" a valid approxidate format that resolves to midnight rather than the current time.

The patch introduces a new `date_today()` function that returns the timestamp for midnight of the current day when "today" is used without a specific time (e.g. in `git log --since=today`). The current behavior treats invalid date formats as "now", which can lead to counterintuitive results like showing future timestamps. The change maintains backward compatibility by still allowing time qualifiers like "noon today".

The implementation adds the new special date handler alongside existing ones like "now" and "never", with corresponding test cases to verify the midnight behavior and interaction with other date components. The test case for "Jan 5 today" is adapted from an existing test for similar date parsing edge cases.

This appears to be a well-motivated quality-of-life improvement for date handling, particularly for commands like `git log` that commonly use relative dates. The patch is small and focused, with clear test coverage of the new behavior.
