This is a bugfix addressing a file descriptor leak in the promisor pack fast-path of `check_connected()`. The patch closes an error file descriptor that was being left open when the function takes the promisor-pack optimization path, which could lead to deadlocks in `receive-pack` operations.

The commit message clearly explains the issue: while `connected.h` documents that `err_fd` should be closed before `check_connected()` returns, this wasn't happening in one of four exit paths. The author notes this same oversight has caused deadlocks twice before in `receive-pack`, where the file descriptor is used for async sideband communication.

The fix is straightforward - adding the missing `err_fd` close in the promisor pack fast-path. The patch is small (just 2 lines added) and well-motivated, with references to prior similar fixes. This appears to be a clear-cut case where the missing close was an oversight in the original implementation rather than an intentional design choice.
