This is a substantive review from gitk maintainer Johannes Sixt, pushing back on the final patch in Shroom Moo's git-gui bugfix series. The review identifies a fundamental disagreement about how GIT_WORK_TREE should be handled in git-gui's environment management.

Sixt argues the current approach is architecturally wrong for gitk's bare repository mode and proposes an alternative solution that:
1. Relies on Git's documented behavior where GIT_DIR alone implies the working tree location
2. Avoids exporting GIT_WORK_TREE entirely in non-bare repositories
3. Preserves bare repository functionality by keeping GIT_WORK_TREE only in those cases
4. Simplifies the code by removing redundant environment variable management

The review is technically detailed, showing exactly which environment variables should be set/unset and when, with specific attention to submodule handling. Sixt's proposed patch demonstrates the alternative approach with concrete changes to git-gui.sh.

This represents a significant challenge to the series' current direction, as it suggests the environment variable handling needs a different architectural foundation rather than just incremental fixes. The review reopens discussion on core design decisions that were previously considered settled.
