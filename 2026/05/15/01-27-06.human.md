This is a bugfix patch in the ongoing series addressing edge cases in Git's date parsing (approxidate) logic. Junio C Hamano responds to Tuomas Ahola's proposal for handling the "today" alias, clarifying the project's stance on fixing unintended behavior versus preserving backward compatibility.

Junio makes a key distinction: while Git generally avoids breaking existing behavior, it's acceptable to fix clearly unintended functionality - like the current "today" handling which simply falls through to the "now" behavior as a side effect of the implementation. He emphasizes that the current behavior shouldn't be codified just because it exists, especially when it doesn't make logical sense.

The exchange shows Junio's maintainer perspective - balancing compatibility concerns against the opportunity to improve confusing edge cases. This moves the discussion forward by establishing that the "today" behavior can be reconsidered rather than being locked in, though any changes still need to be technically sound and well-justified.

The thread remains active with Patch 2/4 (the "today" alias) still under discussion, while Patches 1/4 and 3/4 have been resolved in previous iterations of the series.
