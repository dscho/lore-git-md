This is a refactoring patch that improves the ALLOC_GROW macro, a core utility for dynamic array growth in Git's codebase. The change makes the macro evaluate its second argument (the new element count) only once, which is important when that argument is a complex expression with side effects.

The patch introduces a new helper function `st_alloc_nr()` that handles the growth calculation logic, moving it out of the macro expansion. This makes the macro safer to use while maintaining the same behavior. The change was suggested by Junio C Hamano, indicating it addresses a known concern.

René Scharfe is a frequent contributor known for clean, focused refactorings like this one. The patch is small (14 lines added, 6 removed) and touches only git-compat-util.h, which contains fundamental utilities used throughout the codebase. The change is mechanical and unlikely to be controversial, though it could potentially affect many call sites that use ALLOC_GROW with complex arguments.
