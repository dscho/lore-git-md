Performance optimization patch targeting the commit-reach.c machinery. The patch replaces a linear scan in `tips_reachable_from_bases()` with a decoration hash lookup, changing the complexity from O(C*T) to O(C+T) where C is commits walked and T is number of tips.

The function is used by several ref-filter operations (`for-each-ref --merged`, `branch/tag --contains`). Benchmark shows significant speedups (4x) for `for-each-ref` on a monorepo with 10,000 refs, as it benefits most from avoiding the O(T) scan per commit. Other commands see smaller gains since they check fewer tips.

The author notes several rough edges in the implementation (hacky pointer casting, scope indentation) that could be cleaned up in follow-up patches if the approach is accepted. The core optimization itself is straightforward - using Git's existing decoration mechanism to store tip indices for O(1) lookup.

This appears to be a well-motivated optimization targeting a clear performance bottleneck in ref filtering operations. The benchmark demonstrates meaningful real-world improvements, particularly for repositories with many refs. The implementation is minimal (9 lines added, 6 removed) and leverages existing infrastructure (decoration API).
