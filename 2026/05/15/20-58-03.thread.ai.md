RFC patch series proposing to make "today" resolve to midnight in Git's date parsing, now at v2. Original proposal adds `date_today()` function to handle "today" as midnight when no time is specified, fixing current behavior where "today" falls back to current time (causing `git log --since=today` to incorrectly include future commits). Junio C Hamano noted the tradeoff with `--until=today` - while midnight works well for `--since`, it creates ambiguity for `--until` where "until today" would naturally mean "now". Maintainer suggested keeping the midnight definition for `--since` as more practically useful (allowing easy specification of "today's work"), while explicitly documenting the `--until` tradeoff.

Key changes in v2:
- Expanded commit message explaining the `--since`/`--until` tradeoffs
- Added documentation of new behavior in rev-list-options.adoc
- Maintains existing behavior for time-qualified expressions like "noon today"

Implementation remains focused on the `date_today()` function in approxidate.c (10 lines of code plus tests). Technical details unchanged: returns midnight for standalone "today" while preserving current behavior for expressions with explicit times. Test cases verify both basic "today" case and interactions with other date components. The patch argues the practical utility of `--since=today` outweighs the `--until` edge case, especially since the new behavior better matches the documented meaning of `--until` as "older than date". No outstanding open questions remain from initial discussion.
