RFC patch proposing to make "today" a valid special date format in Git, resolving to midnight rather than current time. Currently "today" is not recognized as an approxidate format, causing `git log --since=today` to incorrectly include future commits (falling back to current time) and `@{today}` to be rejected. Patch adds new `date_today()` function that returns midnight of current day when no specific time is given, while maintaining existing behavior for expressions like "noon today". Implementation adds the special date handler alongside existing ones like "now" and "never", with test cases covering basic "today" case and interactions with other date components (e.g. "Jan 5 today"). Small change (10 lines of code plus tests) focused on date parsing subsystem. Well-motivated quality-of-life improvement making date handling more intuitive for common cases like viewing today's commits. Follows Git conventions with appropriate test coverage. Open question: whether change could impact existing scripts/workflows relying on current fallback-to-now behavior.
