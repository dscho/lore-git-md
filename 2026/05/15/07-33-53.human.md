This is a performance optimization patch for Git's trailer subsystem (commit message footers), part of René Scharfe's ongoing work to improve memory efficiency in core subsystems. The patch eliminates an unnecessary buffer allocation in `unfold_value()` by performing newline-whitespace normalization in-place on the input strbuf rather than using a temporary buffer. The function processes trailer values by replacing newlines and subsequent whitespace with single spaces (like `s/\n\s*/ /g`).

This v2 iteration removes a redundant comparison that was identified in v1's review (the `pos != i` check that turned out to always be true). The change demonstrates René's characteristic precision - the function is now down to just 6 lines while maintaining identical behavior. Jeff King previously confirmed the correctness of the non-trivial in-place approach.

The optimization is low-risk with no user-visible effects, touching only internal trailer processing. With all feedback addressed and no outstanding concerns, this appears ready for integration in the next merge window.
