This is a substantive review from Johannes Sixt (gitk maintainer) pushing back on the final patch in Shroom Moo's git-gui bugfix series. The review identifies a fundamental architectural issue with the current approach to GIT_WORK_TREE handling.

Johannes argues that git-gui should not export GIT_WORK_TREE at all, leveraging instead Git's documented behavior where setting GIT_DIR alone implies the working tree is the current directory. His proposed alternative patch:
1. Removes all GIT_WORK_TREE exports when in a non-bare repo
2. Only keeps GIT_WORK_TREE in bare repos where no worktree exists
3. Simplifies the submodule handling by removing redundant environment variable management
4. Fixes the root cause of empty GIT_WORK_TREE exports that break commands like `git branch --show-current`

The review is technically deep, citing Git's documentation about GIT_DIR behavior and showing how the current patch's approach conflicts with gitk's needs. Johannes provides a complete replacement patch that implements his suggested solution, demonstrating the concrete changes needed in git-gui.sh.

This feedback requires the original author to reconsider the series' approach to environment variable management, particularly around the interaction between git-gui and gitk. The review effectively reopens what was thought to be a settled design decision in the series.
