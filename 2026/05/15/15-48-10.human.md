This is the second patch in Philippe Blain's documentation series clarifying Git's raw diff output format. It focuses on `git diff-files` behavior for unmerged files, which has printed two lines (an "unmerged" line and an "in-place edit" line) since 2005 but wasn't documented as such.

The change is straightforward - it adds a clarifying note to `diff-format.adoc` that `git diff-files` is an exception to the "one output line per changed file" rule when dealing with unmerged files. The commit message clearly cites the 2005 commit that introduced this behavior, showing this is a long-standing behavior that just needed documentation.

Like the rest of the series, this is a small but useful documentation improvement that makes the manual pages more accurate without changing any actual Git behavior. The patch appears well-researched and uncontroversial, continuing the series' focus on catching and fixing documentation inconsistencies.
