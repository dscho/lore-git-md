This is the final version (v7) of Mirko Faina's patch implementing the `--max-count-oldest` option for revision walks, which shows the oldest N commits in a history. The feature has evolved through multiple iterations from the original `--reverse=before` proposal and is now implementation-complete with all substantive review feedback addressed.

The patch adds a new `--max-count-oldest=<number>` option that complements the existing `--max-count` by showing the oldest commits rather than the newest. The implementation preserves the optimized sliding window algorithm (O(K) space, O(N) time) while properly integrating with Git's revision walker architecture. Key technical aspects include:

- New `max_count_type` and `max_count_stage` flags in `struct rev_info`
- Core logic in `retrieve_oldest_commits()` using a two-queue approach
- Comprehensive error handling for invalid option combinations
- Full compatibility with `--reverse` and proper handling of `--boundary` cases

The documentation has been refined to clearly explain the new option's behavior compared to `--max-count`. All identified issues from previous rounds have been addressed, including test portability fixes (replacing GNU `tac`), documentation improvements, and proper error message formatting. The only remaining change is a final whitespace fix noted by Junio C Hamano.

This represents a clean solution to the original problem of efficiently showing the oldest commits without requiring complex shell pipelines. With all substantive feedback incorporated, the feature is ready for inclusion in Git.
