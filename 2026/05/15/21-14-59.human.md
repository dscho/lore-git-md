Performance optimization review for commit-reach.c's tips lookup. Jeff King (Peff) responds to Kristofer Karlsson's patch that replaced a linear scan with a decoration hash for O(1) tip lookups in `tips_reachable_from_bases()`.

Peff reports he couldn't reproduce the 4x speedup shown in the original benchmarks when testing on linux.git with synthetic branches - instead seeing a slight slowdown (650ms to 830ms). This suggests the optimization's impact may be repository-dependent, working best on monorepos with many active refs.

The review raises several technical considerations about the implementation approach:
- Questions whether the decoration API is the right choice versus alternatives like oidmap, khash, or commit-slabs
- Suggests simpler set operations (oidset or object flags) might suffice since the main operation is membership testing
- Notes the current pointer-casting approach feels hacky

This is a substantive review that digs into both the performance claims and implementation choices. Peff's inability to reproduce the speedup on a different repository raises important questions about when this optimization provides value. The discussion is now poised to explore alternative data structures that might be cleaner or more generally performant.
