This is an RFC patch proposing a change to Git's date parsing behavior, specifically making "today" a valid special date format that resolves to midnight rather than the current time.

The patch addresses an inconsistency where "today" isn't currently a valid approxidate format, causing commands like `git log --since=today` to incorrectly return future commits (since it falls back to current time) and `@{today}` to be rejected outright. The proposed solution adds a new `date_today()` function that returns midnight of the current day when no specific time is given, while preserving existing behavior for expressions like "noon today".

The implementation adds the new special date handler alongside existing ones like "now" and "never", and includes test cases verifying the basic "today" case as well as interaction with other date components (like "Jan 5 today"). The change is relatively small (10 lines of code plus tests) and focused on the date parsing subsystem.

As an RFC, this appears to be a well-motivated quality-of-life improvement that would make date handling more intuitive, particularly for common cases like viewing today's commits. The patch follows Git's conventions and includes appropriate test coverage. The main question for discussion would likely be whether this change in behavior could impact any existing scripts or workflows that might rely on the current fallback-to-now behavior.
