This is a documentation and naming clarification patch in Christian Couder's URL-based promisor remote configuration series. Junio Hamano provides a light review of the naming choices in patch 4/8, which adds infrastructure for handling auto-generated remote names.

Junio notes that while the const handling in the struct is slightly awkward (inherited from existing code), it's probably the right tradeoff for safety. His main observation is that the helper function `promisor_info_internal_name()` returns what is essentially a "local name" (either auto-generated or the advertised one), yet this same function's return value gets stored in variables with inconsistent names - sometimes called "remote_name" and other times "local". He suggests `promisor_info_local_name()` might be a clearer function name since it's always representing the local view.

The feedback is constructive but not blocking - Junio explicitly says "let's not worry too much" about the const casting issue and frames the naming observation as a mild inconsistency rather than a problem requiring changes. This suggests the series remains on track for integration, with this being more of a polish point than a substantive concern.
