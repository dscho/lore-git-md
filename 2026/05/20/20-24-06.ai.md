This is patch 7/11 in a bugfix series for git-gui, focusing on worktree discovery from gitdir locations. The patch addresses cases where git-gui fails to properly identify the worktree when launched from certain repository configurations.

The change specifically handles two previously unsupported scenarios:
1. When the gitdir is embedded in a worktree as a .git subdirectory (the parent directory case)
2. When the gitdir is a worktree-specific directory (the worktrees/worktree_name case)

The implementation introduces a new `find_worktree_from_gitdir` procedure that:
- Validates the parent directory is actually a worktree pointing to the discovered gitdir
- Handles worktree-specific gitdirs by reading the gitdir file and verifying the link
- Uses `git rev-parse --show-toplevel` and `--absolute-git-dir` for reliable path resolution
- Includes robust error handling to fall back gracefully when assumptions don't hold

This completes the series' goal of making git-gui's repository detection match core Git's behavior, particularly for edge cases that regressed in 2019. The patch maintains backward compatibility while fixing long-standing issues with worktree discovery.

The changes are well-contained and focused, building on the earlier patches in the series that standardized gitdir handling. The maintainer has already approved the overall approach, and this patch implements one of the key missing pieces identified in earlier review rounds.
