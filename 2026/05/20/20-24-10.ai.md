This is the final patch in a bugfix series for git-gui, adding explicit subcommands to control repository/worktree discovery behavior. The patch introduces two new subcommands:

1. `gui` - Runs the GUI only if repository/worktree succeeds, failing with an error message rather than falling back to the repository picker
2. `pick` - Forces the repository picker to run first before starting the GUI

The changes maintain backward compatibility while giving users more control over when the repository picker appears. The implementation:
- Adds new subcommand handling in git-gui.sh
- Disables the picker when `gui` is specified
- Disables automatic discovery when `pick` is specified
- Updates the usage message to include the new subcommands

This completes the series' goal of making git-gui's startup behavior more predictable and aligned with user expectations. The patch has already received maintainer approval from Johannes Sixt and is ready for merging.
