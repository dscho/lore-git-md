This is patch 10/11 in a completed bugfix series for git-gui, focusing on improving blame and browser subcommand parsing in bare repositories. The patch addresses long-standing inconsistencies where git-gui's argument handling for these commands didn't properly match core Git's behavior, particularly in bare repo scenarios.

The key changes in this patch:
- Rewrites the argument parser to properly respect `--` delimiters like `git blame` does
- Uses `git ls-tree` to check path existence in the given revision rather than relying on worktree presence
- Adds proper type checking (blob vs tree) for paths based on the subcommand's needs
- Fixes edge cases where argument swapping behavior differed from core Git
- Provides clearer error messages when paths don't exist in the target revision

The patch completes the series' goal of making git-gui's repository and worktree handling robust and consistent with core Git behavior. It specifically resolves issues where git-gui would:
- Incorrectly handle `--` in argument positions
- Fail to properly validate paths in bare repositories
- Produce confusing behavior when paths and revisions were swapped

With maintainer-approved technical changes and comprehensive test coverage, this series represents a significant improvement to git-gui's core functionality. The changes are focused on correctness rather than new features, bringing git-gui's behavior in line with user expectations from the command-line interface.
