This is patch 7/11 in a bugfix series for git-gui that has already received maintainer approval. The patch focuses on improving worktree detection when git-gui is launched from a git directory rather than a worktree.

The key improvement here is handling two previously unsupported cases:
1. When the git directory is embedded in a worktree (parent/.git)
2. When the git directory is a worktree-specific directory (under mainrepo/worktrees/worktree_name)

The patch adds a new `find_worktree_from_gitdir` procedure that carefully validates the discovered worktree by cross-checking with `git rev-parse` to ensure consistency. This prevents issues that could arise from filesystem quirks or misconfigurations. The implementation maintains robustness by properly handling error cases and verifying that the discovered worktree actually points back to the original git directory.

This change helps restore functionality that was unintentionally broken in 2019 when Git's `--show-toplevel` behavior changed, and brings git-gui's worktree detection in line with core Git's behavior. The patch fits into the series' broader goal of making git-gui's repository handling more robust and consistent with command-line Git.
