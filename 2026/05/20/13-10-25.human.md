This is a bugfix and UX improvement for `git status`'s push-branch tracking feature (`status.compareBranches`). It's the third iteration of a patch from Harald Nordgren that makes `git status` give better advice when a local branch is behind its push target.

The key improvement is that `git status` now suggests the correct `git pull <remote> <branch>` command when the push branch differs from the upstream branch. Previously, it would suggest a bare `git pull` which would follow the upstream remote - potentially misleading in triangular workflows where push and pull remotes differ. The patch now only shows the verbose pull advice when the remotes actually differ, falling back to the simple `git pull` when they match.

The implementation adds logic to `remote.c` to compare push and pull remotes, only showing the qualified pull advice when they differ. The patch includes several new test cases covering:
- When both upstream and push branches are behind
- When only the push branch is behind
- When push and upstream point to the same ref
- With remapped push refspecs

This version incorporates Junio C Hamano's feedback from v2 about making the verbose advice conditional. The patch is well-tested and addresses a real usability pain point for triangular workflows while maintaining backward compatibility for simpler setups.
