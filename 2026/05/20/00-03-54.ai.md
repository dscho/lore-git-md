This is a review of the core feature patch in a series introducing external command execution for Git notes. Junio C Hamano raises two substantive concerns about the patch's motivation and structure.

First, he questions whether the proposed solution (external notes commands) properly addresses the stated problem (TOCTOU races in distributed repos). He notes that similar race conditions exist in the main history and are typically handled through merge resolution rather than external processes, suggesting the approach may not be well-motivated for this specific case.

Second, he challenges the decision to split documentation and tests into separate commits, arguing that undocumented code is harder to review rather than easier. This implies the patch series structure may not be optimally organized for reviewability.

The review does not engage with the technical implementation details of the external notes protocol or timeout handling infrastructure, focusing instead on higher-level design and presentation concerns. Junio's feedback suggests the series needs stronger justification for why this approach is preferable to existing merge-based solutions for consistency, and may benefit from restructuring to keep documentation and tests with the code they describe.

This is a substantive review that identifies potential architectural questions rather than surface-level issues, though it stops short of outright rejecting the approach. The author will need to address these concerns in a revision, particularly the rationale for choosing external processes over improved merge handling for notes consistency.
