This is patch 10/11 in a bugfix series for git-gui, focusing on improving the blame and browser subcommands' behavior in bare repositories. The patch addresses long-standing parsing issues where git-gui's argument handling for these commands didn't properly match core Git's behavior, particularly in bare repo scenarios.

The key changes in this patch:

1. Rewrites the argument parser to properly handle `--` delimiters, matching core Git's blame behavior where `--` forces path interpretation
2. Uses `git ls-tree` to check path existence in the given revision rather than relying on worktree presence
3. Adds proper type checking (blob vs tree) for paths based on the subcommand's needs
4. Fixes edge cases where argument swapping would incorrectly succeed or fail
5. Improves error handling when paths don't exist in the given revision

The patch makes git-gui's behavior consistent with core Git's blame command in all cases, including bare repositories. It specifically fixes cases where git-gui would:
- Incorrectly accept invalid argument orders with `--`
- Fail to handle valid argument orders with `--`
- Mismatch path types (treating files as directories or vice versa)
- Silently fail when paths didn't exist in the worktree

The implementation now properly queries the repository state rather than making assumptions based on worktree presence, which was the root cause of many of these issues. This completes the series' goal of making git-gui work reliably in bare repository contexts while maintaining compatibility with existing worktree-based workflows.
