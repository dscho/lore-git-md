This is the third iteration of a bugfix and UI improvement for `git status`'s push-branch tracking feature (`status.compareBranches`). The patch from Harald Nordgren addresses a usability issue where `git status` would suggest an incorrect `git pull` command when comparing against a push branch.

The key change in v3 implements Junio Hamano's suggestion from the v2 review: the verbose `git pull <remote> <branch>` advice is now only shown when the push and pull remotes differ. When they're the same (the common case), it falls back to the simpler `git pull`. This makes the advice more precise while avoiding unnecessary verbosity in standard workflows.

The implementation adds logic to compare push and upstream remotes in `format_tracking_info()`, only showing the qualified pull advice when they differ. The patch includes four new test cases covering:
1. When both upstream and push branches are behind (showing different advice for each)
2. Remapped push refspecs
3. Push branch tracking with no upstream set
4. The common case where upstream and push are the same (verifying the simple `git pull` advice)

The changes from v2 are focused and well-tested, addressing the review feedback while maintaining the original goal of fixing the misleading advice in triangular workflows. The patch remains small and targeted, with clear test coverage of both the edge cases and the common path. This looks ready for inclusion pending any final review comments.
