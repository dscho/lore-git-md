This is a bugfix patch in the git-gui series addressing path handling in the browser subcommand. The change ensures that "git-gui browser rev ." works when run from the root directory of the worktree, where the normalized path would otherwise become empty. The fix makes the browser accept "./" as the path in this case, maintaining consistency with command-line behavior.

The patch is part of the v2 series that has already received maintainer approval from Johannes Sixt. It specifically addresses an edge case in path normalization where the current directory ('.') at the root would fail. The solution preserves cross-platform compatibility, noting that "./" works on Windows via Git for Windows' POSIX path handling.

This is a small but important fix that completes the browser subcommand's path handling, ensuring it behaves consistently with core Git's expectations. The change is minimal (6 lines modified) and focused, touching only the path normalization logic while maintaining all other behavior.
