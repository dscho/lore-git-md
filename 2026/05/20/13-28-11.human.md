This is a follow-up to Miklos Vajna's bugfix patch addressing `git log --follow` behavior with subtree merges. The patch aims to make `log --follow` track file renames across subtree merges consistently with how `blame --follow` already works.

Miklos is now actively seeking review from domain experts Elijah Newren (merge machinery) and Jeff King (diff/performance) after Junio Hamano suggested finding additional reviewers. The author acknowledges Junio's earlier point about the fundamental limitations of `--follow` with merges, but argues this incremental improvement is still valuable since it matches `blame`'s existing behavior.

The technical change modifies `log-tree.c` to properly check all merge parents for renames, similar to how `blame.c` already handles this case. The patch appears well-motivated by a concrete inconsistency between related commands, though as Junio pointed out, it doesn't solve `--follow`'s broader merge-related limitations. The next step depends on whether the requested reviewers see value in this narrow fix versus holding out for a more comprehensive solution.
