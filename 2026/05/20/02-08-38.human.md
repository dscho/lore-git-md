This is a performance optimization patch for `git stash -p` that builds on Adam Johnson's initial proposal. Junio C Hamano (the Git maintainer) provides a review that both acknowledges the cleverness of the approach and raises some thoughtful questions.

Junio notes that preserving the fsmonitor_valid bit requires in-process index updates, making this approach sensible. However, he wonders whether simply using `git read-tree -m HEAD` (oneway merge) as an external command might achieve similar speed improvements without the need for new in-process logic. This suggests the optimization might be achievable through simpler means.

The review also questions the need for a new test in the functional test suite (t/t3904) since the change is purely performance-related. Junio indicates he would have anticipated a performance test (t/perf/) instead, which would directly measure the speed improvement claimed in the patch.

The exchange shows Junio engaging with the technical merits while maintaining his characteristic focus on simplicity and appropriate testing. His questions don't reject the approach but probe whether the same benefits could be achieved with less complexity.
