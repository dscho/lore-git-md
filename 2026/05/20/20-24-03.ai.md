This is the fourth patch in an 11-part bugfix series for git-gui, focusing on repository discovery. The patch standardizes git-gui's repository finding logic to exclusively use `git rev-parse --absolute-git-dir` rather than checking GIT_DIR directly, ensuring consistent validation with Git's core behavior.

Key changes in this patch:
1. Replaces direct GIT_DIR checking with `git rev-parse` for all discovery, centralizing repository validation
2. Adds new error handling that respects user-set GIT_DIR/GIT_WORK_TREE by failing fast when these are invalid
3. Restructures the repository picker flow to be more modular and independent of discovery
4. Removes redundant directory validation (now handled by rev-parse)
5. Fixes timing of `_prefix` initialization to match worktree discovery

The patch improves robustness by:
- Preventing deferred errors from invalid repositories
- Maintaining compatibility with Git CLI behavior
- Preserving existing picker functionality while making it more maintainable
- Centralizing environment variable management

This change is part of a larger effort to make git-gui's startup behavior more predictable, particularly in edge cases involving bare repositories and worktrees. The implementation aligns with the thread's overall goal of eliminating subtle failures in repository detection.
