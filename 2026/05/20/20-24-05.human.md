This is patch 6/11 in a bugfix series for git-gui that standardizes repository and worktree discovery using `git rev-parse`. The patch focuses on improving reliability when determining the worktree location and handling edge cases.

The key change replaces custom Tcl path resolution with direct use of `git rev-parse --show-toplevel` and `--show-prefix` to get the worktree root and relative path. This ensures consistent behavior with Git's CLI by letting Git handle all error checking and configuration validation. The patch also reorganizes the startup sequence to:
- Perform worktree discovery immediately after repository discovery
- Move configuration loading after worktree setup
- Centralize error handling for invalid worktrees

Notable improvements include:
- Better detection of configuration errors when GIT_DIR/GIT_WORK_TREE are set
- Clearer separation between bare repository and worktree cases
- More robust handling of filesystem errors when changing directories
- Removal of manual path manipulation in favor of Git's built-in resolution

The changes maintain all existing functionality while making the code more maintainable and consistent with core Git behavior. This is part of a larger effort to fix long-standing edge cases in git-gui's startup logic that could previously lead to cryptic failures.
