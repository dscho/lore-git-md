This is the second patch in an 11-part bugfix for git-gui's repository and worktree detection logic, which has received maintainer approval and is ready for merging. The patch focuses on cleaning up the repository picker interface.

The change refactors `choose_repository::pick` to return a simple success/failure status (1/0) rather than directly setting global variables `_gitdir` and `_prefix`. This makes the control flow clearer by moving the repository validation and variable setting to the caller in `git-gui.sh`. The picker now properly indicates whether a valid worktree+repo was selected, while leaving the actual gitdir discovery to happen through `git rev-parse` in the caller.

Key technical changes include:
- Replacing the `clone_ok` field with a more general `pick_ok` field
- Removing direct manipulation of `::_gitdir` and `::_prefix` from the picker
- Adding proper return value handling in the main script
- Maintaining the same behavior for error cases (git-gui still exits on failure)

This is part of a larger effort to make git-gui's startup behavior more robust and consistent with command-line Git, particularly around edge cases involving bare repos and worktrees. The patch series as a whole has been thoroughly reviewed and addresses long-standing issues dating back to 2014/2019 regressions.
