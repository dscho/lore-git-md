This is the first patch in an approved bugfix series for git-gui, focusing on environment variable handling during repository setup. The patch introduces centralized control over GIT_DIR and GIT_WORK_TREE environment variables to prevent edge case failures.

The key change replaces scattered direct environment manipulation with two new Tcl procs:
- `set_gitdir_vars`: Safely exports the discovered repository (_gitdir) and worktree (_gitworktree) paths
- `unset_gitdir_vars`: Cleans up these variables when needed

The motivation stems from problematic behavior when:
1. Empty GIT_WORK_TREE exports would break Git commands like `git branch --show-current`
2. Inconsistent variable handling across different code paths could lead to discovery failures

The patch maintains backward compatibility while fixing several subtle issues:
- Preserves the ability to override discovery via pre-set environment variables
- Handles bare repository cases correctly
- Ensures worktree-dependent operations only export valid paths
- Centralizes the logic to prevent future inconsistencies

This foundational change enables subsequent patches in the series to build on reliable environment handling. The implementation has been reviewed and approved by git-gui maintainer Johannes Sixt as part of the complete series addressing long-standing repository discovery issues.
