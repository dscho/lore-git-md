This is the final version (v2) of a bugfix series for git-gui, addressing long-standing issues with repository and worktree detection. The series has received maintainer approval from Johannes Sixt and is ready for merging.

The 11 patches comprehensively rewrite git-gui's startup logic to properly handle edge cases that previously caused cryptic failures, particularly around bare repositories and missing worktrees. Key improvements include:

1. Unified use of `git rev-parse` for repository discovery, ensuring consistency with command-line behavior
2. Proper support for blame/browser subcommands in bare repositories
3. Correct handling of .git directory parent-as-worktree cases
4. More reliable repository picker behavior that doesn't mask configuration problems
5. Explicit subcommand support for `gui` and `pick` modes

The implementation now properly handles complex scenarios like:
- Launching from a .git directory with the parent as worktree
- Bare repository operations
- Worktree discovery via gitdir files
- Blame/browser argument parsing that matches core Git behavior

Notable technical changes in v2 include:
- Restructured patch ordering to enable testing of blame/browser fixes
- Improved worktree discovery logic that verifies gitdir consistency
- Better handling of detached HEAD states
- More robust path normalization and type checking
- Cleaner subcommand interface with explicit `gui` and `pick` modes

The series resolves issues dating back to 2014/2019 regressions while maintaining backward compatibility. It represents the culmination of extensive review and iteration, with all maintainer feedback addressed. The changes touch core git-gui startup logic but focus on making existing behavior more robust rather than introducing new features.
