This is the final patch in an approved bugfix series for git-gui, adding explicit subcommands to control repository/worktree discovery behavior. The patch introduces two new subcommands:

1. `gui` - Runs the GUI only if repository/worktree discovery succeeds, failing with an error message rather than falling back to the repository picker
2. `pick` - Forces the repository picker to run first before starting the GUI

The change maintains backward compatibility while giving users more control over when the picker appears. The implementation builds on the series' earlier work to make repository detection more robust, now exposing that reliability through explicit subcommand choices. The patch completes the architectural shift to consistent behavior across all git-gui modes.

This represents the culmination of a thorough review process addressing long-standing edge cases in git-gui's startup logic. With maintainer Johannes Sixt's approval, the full series is now ready for merging.
