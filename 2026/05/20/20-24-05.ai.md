This is patch 6/11 in a bugfix series for git-gui, focusing on improving worktree discovery by leveraging `git rev-parse` instead of custom Tcl logic. The patch centralizes worktree path resolution to match core Git's behavior more closely.

The key changes in this patch:
1. Replaces manual path resolution with direct `git rev-parse --show-toplevel` and `--show-prefix` calls for worktree discovery
2. Moves worktree detection immediately after repository discovery (before config loading) to fail fast on configuration errors
3. Simplifies error handling by distinguishing between Git configuration errors (fatal) and filesystem issues (recoverable)
4. Maintains bare repository support while properly validating worktree states
5. Preserves the existing behavior of exporting environment variables only after full discovery is complete

The implementation ensures git-gui handles edge cases consistently with the Git CLI, particularly around:
- User-specified GIT_DIR/GIT_WORK_TREE overrides
- Bare repository operations
- Filesystem permission issues
- Subdirectory launches within worktrees

This change builds on the series' earlier standardization of repository discovery (patch 4/11) and bare repository handling (patch 5/11). The maintainer-approved approach demonstrates careful consideration of the interaction between worktree discovery, config loading, and environment variable management.
