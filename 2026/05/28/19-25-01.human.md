This is the final version of a documentation patch clarifying how `git diff --word-diff` handles whitespace changes. The patch stems from a user report about confusing output when files differ only in whitespace.

The commit explains that word diffs are currently computed from line diffs first, which can produce suboptimal results for whitespace-only changes. It notes this implementation may change in the future, similar to how `--diff-algorithm` affects diff output. The wording has been refined through review feedback to focus on the technical reality while avoiding philosophical digressions about diff limitations.

The patch appears ready for merging, having incorporated maintainer feedback and cleanly addressing the original user confusion. It maintains Git's documentation standards by explaining current behavior without over-specifying implementation details. While Phillip Wood had suggested potential algorithmic improvements, those remain a separate consideration from this documentation update.
