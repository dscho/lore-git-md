Bugfix for `git rebase --update-refs` when dealing with branch symrefs. This is a two-patch series addressing an edge case where rebase fails when updating symbolic references to the current branch (like when migrating from 'master' to 'main').

The issue occurs when:
1. A branch (e.g. 'main') is a symref to another branch ('master')
2. `git rebase --update-refs` runs (e.g. via `pull.rebase`)
3. The rebase updates 'master' successfully but fails to update 'main' due to the symref resolution

The first patch adds a test demonstrating the failure case, while the second implements the fix by having the sequencer resolve symrefs before queuing update-ref commands and skip aliases of the current branch. The solution maintains the existing safety checks while handling this symref case gracefully.

The patch series is well-structured with clear motivation (the practical case of branch renaming during migration) and follows Git's standard approach of first demonstrating the bug before fixing it. The changes are focused on the sequencer.c internals and come with corresponding test coverage.
