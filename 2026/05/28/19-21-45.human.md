This is a v2 of a documentation patch clarifying how `--word-diff` works. The patch improves the man page to explain that `--word-diff` operates in two stages: first computing a line-level diff, then applying word-level comparison within those hunks. This can produce counterintuitive results where word changes appear even when the actual words are identical, due to the line-level alignment.

The v2 revision expands the explanation to note that this implementation may produce larger diffs than a dedicated word-diff tool would, and that the behavior could change if Git adopts a different implementation in the future. It also draws a parallel to how `--diff-algorithm` can affect output.

The commit message is clear and well-motivated, citing two contributors (Vincent Lefevre and Johannes Sixt) who presumably encountered the confusion. The change is small and focused, touching only the documentation for this one option. This should be an uncontroversial improvement that helps users better understand Git's behavior.
