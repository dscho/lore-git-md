This is the first patch in a two-part bugfix series addressing `git rebase --update-refs` behavior with branch symrefs. The patch adds a failing test case that demonstrates the issue when a branch is a symbolic reference to another branch (like `main` pointing to `master` during a branch rename migration).

The test shows that currently, when rebasing with `--update-refs`, the operation fails during ref updates because it tries to update the symref with an old value after the primary branch has already been rebased. The test is marked as `test_expect_failure` to document the current broken behavior, which the subsequent patch will fix.

The test setup creates a symref alias pointing to a branch, then performs a rebase that should update both the branch and its alias. The expected behavior (which will be verified once fixed) is that the symref should continue pointing to the rebased branch. The test includes careful cleanup steps to ensure the test environment is reset properly.

This is a well-constructed test that clearly isolates the edge case, following Git's standard test patterns. The commit message explains both the current broken behavior and what the fixed behavior should be. The test will serve as validation for the actual fix in the next patch of the series.
