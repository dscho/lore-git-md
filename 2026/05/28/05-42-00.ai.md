This is the first patch in a bugfix series addressing `git rebase --update-refs` behavior with branch symrefs. The patch adds a failing test case that demonstrates the problem: when a branch is a symbolic reference to another branch (like `main` pointing to `master` during a branch rename migration), the rebase operation fails during the ref update step even after successfully rebasing the primary branch.

The test creates a scenario where:
1. A base commit and topic branch commits are set up
2. A symbolic reference (`update-refs-symref-alias`) points to the topic branch
3. The rebase operation should update both the topic branch and its symref alias

Currently marked as `test_expect_failure`, this test will be flipped to success in the subsequent patch that fixes the underlying issue. The test verifies that after rebase:
- The topic branch is properly rebased onto the new base
- The symref alias still correctly points to the rebased topic branch
- No duplicate or incorrect ref updates occur

This is a well-constructed test that clearly isolates the edge case while maintaining the existing test suite's style and cleanup patterns. The test case is particularly relevant for workflows involving branch renames where symbolic references are used during the transition period.
