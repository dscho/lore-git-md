This is the second patch in a 3-part series that refactors how `git log -L` (line-log) integrates with Git's diff output pipeline. The patch has already been through two rounds of review and is now in its final form.

The key change in this patch is routing line-log output through Git's standard `log_tree_diff()` pipeline rather than having it bypass the normal diff processing flow. This fixes several long-standing inconsistencies where `-L` would skip features like pickaxe filtering (`-S`, `-G`), `--diff-filter`, and standard diff formats (`--raw`, `--name-only`). The patch also properly handles cleanup and header formatting that was previously skipped.

The technical changes include:
- Renaming `line_log_print()` to `line_log_queue_pairs()` and simplifying it to just queue pre-computed filepairs
- Removing the early return in `log_tree_commit()` that previously bypassed the standard diff pipeline
- Adding explicit handling of `--full-diff` as an unsupported option with `-L`
- Updating tests to verify the new behavior, including proper filtering with pickaxe and diff-filter options

The patch demonstrates careful attention to both technical correctness and review feedback from previous iterations. It represents a significant improvement to the line-log machinery by bringing it into alignment with Git's standard diff processing while maintaining all existing functionality. With all feedback addressed in v3, this appears ready for merging.
