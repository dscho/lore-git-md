Bugfix for `git describe`'s interaction between `--contains`, `--all`, and pattern matching options.

Jacob Keller fixes an issue where `git describe --contains --all` would silently ignore `--match` and `--exclude` patterns instead of forwarding them to the underlying `git name-rev` call. The patch ensures these patterns are properly passed through with the correct ref prefixes (refs/tags, refs/heads, refs/remotes) depending on whether `--all` is used.

The fix matches the documented behavior where these options should work together. The patch includes new tests verifying the corrected behavior with various combinations of `--match` and `--exclude` patterns against tags and branches. The change is relatively straightforward - it restructures the argument building logic to handle the `--all` case properly while maintaining the existing behavior when `--all` isn't used.

This addresses a real inconsistency where the command's behavior didn't match its documentation. The fix appears clean and well-tested, with no obvious gotchas in the implementation.
