This is the second patch in a two-part refactoring series that completes the removal of deprecated commit list functions from commit.h. The patch follows through on deprecations planned since Git 2.53.0, removing the inline compatibility wrappers after ensuring all callers have been updated to use the modern equivalents.

The changes are straightforward and mechanical deletions of three deprecated functions (`copy_commit_list`, `reverse_commit_list`, and `free_commit_list`) that were marked for removal. These functions have direct modern replacements (`commit_list_copy`, `commit_list_reverse`, and `commit_list_free` respectively) that were already being used throughout the codebase. The first patch in the series updated the remaining callers to use the modern names.

The patch carries an Acked-by from Patrick Steinhardt, who originally authored both the deprecated functions and their replacements. This provides strong social validation that the removal is appropriate and complete. The author has also verified there are no remaining uses of these functions in the integration branches, following Git's standard deprecation workflow where functions are first marked obsolete, callers migrated, and then removed after verification.

This is a clean, uncontroversial cleanup that demonstrates Git's approach to maintaining API hygiene while ensuring backwards compatibility during transitions. The changes are limited to commit.h and don't affect behavior - they simply remove deprecated code that is no longer needed.
