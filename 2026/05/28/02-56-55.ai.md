This is the second patch in a completed bugfix series addressing network address handling issues in Git's daemon mode (`daemon.c`). The patch specifically fixes IPv6 address truncation in logging by correcting the buffer size passed to `inet_ntop()`.

The key technical change replaces the use of `ai_addrlen` (the sockaddr struct size) with `sizeof(ip)` (the actual buffer size) when calling `inet_ntop()`. This ensures IPv6 addresses aren't silently truncated - the buffer is now properly sized to hold the full 46 characters of an IPv6 address in text form (INET6_ADDRSTRLEN) rather than being limited to the 28-byte sockaddr_in6 struct size. The patch also simplifies the `ip2str()` function signature by removing the now-unused `len` parameter, updating all callers accordingly.

This is a straightforward correctness fix that has already been reviewed positively in previous iterations (v1 and v2) by both Junio C Hamano and Patrick Steinhardt. The changes are confined to `daemon.c` with no protocol or on-disk format implications. As part of the completed v3 series, this patch is ready for merging alongside the other two fixes in the series (IPv6 address family correction and NULL pointer safety).
