This is the final version (v3) of a bugfix series addressing network address handling issues in Git's daemon mode. The patches fix three related problems in `daemon.c`:

1. IPv6 address corruption when `getaddrinfo()` returns IPv6 results but the code incorrectly assumes IPv4, reading from wrong struct offsets. The fix properly handles both AF_INET and AF_INET6 address families.

2. IPv6 address truncation where the sockaddr struct size was incorrectly used as the output buffer size for `inet_ntop()`, causing silent truncation of long IPv6 addresses. The fix uses the proper buffer size constant.

3. A NULL pointer safety issue when logging connection details if the REMOTE_PORT environment variable is unset, adding a NULL check and fallback string (though technically redundant since REMOTE_ADDR and REMOTE_PORT are set together, it's added as defensive programming).

The series has been through multiple rounds of review with positive feedback from both Junio C Hamano and Patrick Steinhardt. Changes since v2 are minor commit message clarifications for patch 3/3, confirming the NULL check is defensive rather than fixing an immediate issue. The technical content remains unchanged from the v2 version that was already approved.

This appears ready for merging, addressing clear correctness issues in the daemon's network handling that could affect IPv6-only hosts or cause crashes from NULL pointer dereferences. The changes are well-contained to `daemon.c` with straightforward fixes.
