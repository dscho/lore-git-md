This thread addresses a bug in `git describe` where `--match` and `--exclude` patterns weren't being properly handled with `--contains --all`, particularly for remote refs. Jacob Keller initially fixed the pattern forwarding, but Junio C Hamano spotted an edge case where exclude patterns failed to match full remote branch names. 

The discussion initially considered making the output stable (via `STABLE_QSORT`), but consensus has shifted to instead modify the test to expect unambiguous results through stricter pattern matching. Junio has now acknowledged Jacob's plan for a v2 patch that takes this approach, calling it "workable." The test will be restructured to either use additional `--exclude` patterns to force unambiguous outputs or accept any valid matches when multiple refs qualify equally.

One open question remains about whether exclude patterns should match full remote ref names (like "remotes/origin/branch") or just the branch component, but this is being deferred until after the immediate test stability fix. The thread shows alignment between Jacob and Junio on preserving the command's flexible matching behavior while making the tests properly validate it.
