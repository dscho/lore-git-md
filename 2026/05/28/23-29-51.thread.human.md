This thread addresses a bug in `git describe` where `--match` and `--exclude` patterns weren't being properly handled with `--contains --all` flags. Jacob Keller initially fixed the pattern forwarding, but Junio Hamano spotted an edge case where exclude patterns failed to match full remote branch names (like "remotes/origin/branch" vs just "branch").

A secondary issue emerged when Tuomas Ahola noticed test output instability due to non-deterministic ref sorting. While Tuomas proposed enforcing stable sorting, Junio correctly pointed out this would mask the real problem - the test was written to expect one "correct" answer when multiple refs could validly match. 

Jacob has now agreed with Junio's assessment, recognizing that stable sorting would artificially prioritize certain refs. Instead, he's working on revising the test to either:
1) Add more `--exclude` patterns to ensure unambiguous expected output, or
2) Restructure the test to properly handle cases where multiple answers are valid

The discussion has shifted focus to test design principles, with consensus forming around maintaining `git describe`'s flexible matching behavior while making tests more robust. The remaining question about how `--exclude` should match remote ref names will be addressed after these test improvements land. Junio's guidance has steered the thread toward solutions that preserve the command's intended behavior rather than adding artificial constraints.
