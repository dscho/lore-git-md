This is the final patch in a 3/3 series that integrates `git log -L` (line-log) with Git's standard diff output pipeline. The patch enables several non-patch diff formats (`--raw`, `--name-only`, `--name-status`, and `--summary`) to work with `-L`, while still blocking stat-based formats like `--stat` that would show whole-file statistics rather than line-specific ones.

The changes include:
- Updating documentation to clarify which formats are now supported
- Modifying the format allowlist in `revision.c`
- Adding comprehensive tests for the newly supported formats
- Explicitly testing that stat formats remain unsupported

The patch builds on the previous refactoring in the series to ensure line-log output properly flows through Git's standard processing pipeline. It demonstrates careful attention to edge cases, including testing the behavior with root commits and verifying the output formats contain only the expected information (no diff headers or hunks for metadata-only formats).

With this change, `git log -L` now works consistently with more of Git's diff formatting options while maintaining clear boundaries around what makes sense for line-oriented history. The series has already been merged into the `next` branch after addressing all review feedback, marking a successful conclusion to this line-log integration effort.
