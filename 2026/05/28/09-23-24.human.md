This is a reply to a feature proposal about adding real-time collaboration features to Git. Christian Couder provides a thoughtful response that acknowledges the problem while steering the discussion toward more practical solutions.

Christian agrees that real-time collaboration is useful but suggests it's not Git's role to implement this directly. Instead, he points to several existing approaches that could help:

1. Jujutsu's working-copy-as-commit model for continuous syncing
2. Pijul's CRDT-based merging system
3. git-imerge for simplifying complex merges
4. Various CRDT libraries (Automerge, Yjs) that could potentially be integrated

The response is constructive but makes clear that implementing such features in core Git would be complex. Christian suggests that AI-based conflict resolution might be a promising direction, while emphasizing the need for human oversight. This reply effectively redirects the conversation from "should Git do this" to "here are tools that already address parts of this problem."
