This is a Windows platform compatibility patch discussion regarding signal handling in Git's Windows compatibility layer. Johannes Schindelin (Git for Windows maintainer) responds to Junio's earlier query about distinguishing between SIGTERM and SIGKILL on Windows.

Schindelin reveals that Git for Windows has a more sophisticated implementation than what's being proposed - it actually differentiates SIGTERM by allowing processes to run their `atexit()` handlers, while the current patch would treat all signals identically via `TerminateProcess()`. He indicates this would conflict with Git for Windows' existing behavior, which hasn't been upstreamed yet due to time constraints.

The key takeaway is that Windows signal handling is more nuanced than the initial patch assumed - there is already a working implementation in Git for Windows that provides some Unix-like signal semantics (specifically for SIGTERM). Schindelin plans to upstream these changes properly rather than adopting the simplified approach in the current patch.

This moves the discussion from theoretical (whether Windows can support signal distinctions) to practical (Git for Windows already does, and we should align with that implementation). The ball is now in Schindelin's court to prepare and submit the more complete solution.
