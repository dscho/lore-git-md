This is the second patch in a bugfix series addressing `git rebase --update-refs` behavior with branch symrefs. The issue occurs when a local branch is a symbolic reference to another branch (like `main` pointing to `master` during a branch rename migration), causing the rebase to fail during ref updates.

The patch modifies the sequencer to properly handle branch symrefs by:
1. Resolving symref decorations before queuing update-ref commands
2. Skipping aliases of the current branch
3. Avoiding duplicate updates for the same underlying branch

The changes are focused in sequencer.c and include additional safety checks while preventing false failures with symref aliases. The test case from the first patch is now updated to expect success rather than failure.

This is a well-contained fix that maintains existing behavior while addressing a real edge case that affects workflows involving branch renames. The changes are surgical and come with test coverage, making this a low-risk improvement to the rebase machinery.
