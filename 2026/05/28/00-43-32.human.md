This is a bugfix for `git describe` that prevents invalid combinations of options from silently failing. The patch addresses an issue where `git describe --contains --all` would ignore `--match` and `--exclude` pattern options rather than erroring out. This could lead to unexpected behavior when users specify patterns that have no effect.

Jacob Keller originally submitted the fix in May 2026, but it wasn't merged. Now Tuomas Ahola has independently confirmed the bug still exists in current Git, showing that both `--match=bogus` and `--exclude="*"` have no effect when combined with `--contains --all`. The patch would make this invalid combination fail with an error message instead.

Eric Sunshine previously reviewed the patch with minor suggestions about commit message wording and code style, but the core technical approach was sound. The main outstanding issue is test coverage, which Jacob indicates he'll address when reviving the patch. This appears to be a straightforward fix for a real usability issue that multiple users have encountered.
