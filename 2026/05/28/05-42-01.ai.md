This is the second patch in a bugfix series addressing `git rebase --update-refs` behavior with branch symrefs. The patch implements the fix for the issue demonstrated in the first patch's test case.

The core fix modifies the sequencer's decoration handling to properly resolve symbolic references before queuing update-ref commands. Key changes include:

1. Resolving symref decorations to their target branches before processing
2. Skipping updates for symrefs that point to the current branch being rebased
3. Avoiding duplicate updates when multiple symrefs point to the same branch
4. Maintaining all existing safety checks (like preventing updates of checked-out branches)

The implementation:
- Uses `refs_resolve_ref_unsafe()` with `RESOLVE_REF_NO_RECURSE` to detect symrefs
- Only processes symrefs that point to local branches (under refs/heads/)
- Updates the test from `test_expect_failure` to `test_expect_success` now that the behavior is fixed

The changes are focused on `sequencer.c`'s decoration handling logic, with careful attention to:
- Memory management of resolved ref strings
- Maintaining the ref-to-oid tracking for update safety
- Preserving the existing behavior for non-symref cases

This completes the fix for the symref edge case while keeping all the safety properties of the original `--update-refs` feature. The solution is particularly relevant for branch rename migrations where old/new branch names coexist via symrefs during the transition period.
