Thread identity: Bugfix series for `git rebase --update-refs` behavior with branch symrefs, addressing an edge case where symbolic references to branches cause rebase failures during ref updates.

Core problem: When a local branch is a symbolic reference to another branch (e.g. `main` pointing to `master` during a branch rename migration), `git rebase --update-refs` fails during the ref update step even after successfully rebasing the primary branch, due to incorrect handling of symref decorations.

Current status: Initial version of the fix series, consisting of:
1. A new failing test case demonstrating the symref issue in t3404
2. Core changes to sequencer.c that:
   - Resolve symref decorations before queuing update-ref commands
   - Skip aliases of the current branch
   - Prevent duplicate updates for the same underlying branch

Key technical details:
- Modifies sequencer.c's update-ref handling logic
- Adds test coverage in t3404-rebase-update-refs.sh
- Maintains existing safety checks while accommodating symref workflows
- Specifically helps branch rename migration scenarios where old/new names coexist

Open questions: None raised yet in this initial version.

Related work: Builds on the existing `--update-refs` feature in git-rebase, which was introduced to handle dependent branch updates during rebase operations.
