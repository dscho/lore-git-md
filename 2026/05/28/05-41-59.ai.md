This is a bugfix series addressing an edge case in `git rebase --update-refs` when dealing with branch symrefs. The issue occurs when a local branch is a symbolic reference to another branch (like `main` pointing to `master` during a branch rename migration), causing the rebase to fail during the ref update step even after successfully rebasing the primary branch.

The series starts by adding a failing test case that demonstrates the problem, then provides a fix that makes the sequencer properly handle branch symrefs by:
1. Resolving symref decorations before queuing update-ref commands
2. Skipping aliases of the current branch
3. Avoiding duplicate updates for the same underlying branch

The changes touch the sequencer.c core logic and add test coverage in t3404. The fix maintains the existing safety checks while preventing false failures when dealing with symref aliases. This is particularly relevant for workflows involving branch renames where both old and new branch names need to coexist temporarily.
