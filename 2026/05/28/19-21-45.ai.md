This is a v2 documentation patch clarifying how `--word-diff` works internally. The patch improves the man page to explain that word-diff operates in two stages: first computing a line-level diff, then applying word-level comparison within those hunks. This can produce counterintuitive results where word changes appear even when the actual words match, due to the line-level alignment.

The v2 iteration expands the explanation to note that this implementation may produce larger diffs than a dedicated word-diff tool would, and that the output could change if Git adopts a different implementation in the future. It also draws a parallel to `--diff-algorithm` which similarly documents potential output changes.

The commit message is clear and well-motivated, citing two contributors (Vincent Lefevre and Johannes Sixt) who presumably encountered the confusion.
