This is the second patch in a 3-patch series that refactors how `git log -L` (line-log) integrates with Git's diff output pipeline. The series has already been through two rounds of review and is now in its final form, addressing all substantive feedback.

The key change in this patch is routing line-log output through Git's standard `log_tree_diff()` pipeline rather than having it bypass the normal diff processing. This fixes several long-standing inconsistencies where `-L` would skip features like pickaxe filtering (`-S`, `-G`), `--diff-filter`, and standard diff formats (`--raw`, `--name-only`). The patch also properly handles cleanup and header formatting that was previously skipped.

The technical changes include:
- Renaming `line_log_print()` to `line_log_queue_pairs()` and simplifying it to just queue the pre-computed file pairs
- Removing the early return in `log_tree_commit()` that previously bypassed the standard pipeline
- Adding proper rejection of `--full-diff` which isn't yet compatible with `-L`

The patch includes extensive test updates to verify the new behavior, particularly around filtering and diff formatting. The changes demonstrate careful attention to both technical correctness and review feedback, making this a well-structured improvement to the line-log machinery. With all feedback addressed in previous iterations, this series appears ready for merging.
