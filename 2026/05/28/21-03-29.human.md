This is a bug report describing unexpected behavior when running `cd` in a Git hook within a secondary worktree. The issue manifests when changing directories in a hook script - after the `cd` command, `git status` incorrectly reports all tracked files as deleted in secondary worktrees, while working correctly in the main worktree.

The reporter provides a detailed reproduction script showing the problem occurs specifically in secondary worktrees across multiple Git versions (2.51.1, 2.47.3, 2.25.1) and platforms (Windows, Linux). The core issue appears to be related to how Git's environment variables (GIT_PREFIX, GIT_DIR, GIT_WORK_TREE) interact with directory changes in hook contexts.

The bug affects real-world use cases where hooks need to change directories (like updating generated files in subfolders). The report is well-documented with clear reproduction steps and expected vs actual behavior, making it easy to verify. This looks like a legitimate bug in Git's worktree/hook interaction that warrants investigation.
