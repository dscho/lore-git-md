Bugfix for `git describe`'s handling of `--exclude` and `--match` with `--contains` and `--all`.

Jacob Keller fixes an inconsistency where `git describe --contains --all` wasn't properly forwarding `--match` and `--exclude` patterns to the underlying `git name-rev` command. The documentation claims these options should work together, but the implementation was silently ignoring the patterns in `--all` mode.

The patch makes `describe` properly pass the patterns to `name-rev` with the appropriate ref prefixes (refs/tags, refs/heads, refs/remotes) depending on whether `--all` is used. This matches the documented behavior. The change is straightforward - it restructures the pattern passing logic to handle both modes correctly.

Four new tests verify the fixed behavior, checking combinations of `--match` and `--exclude` with branches and tags. The implementation looks clean and the tests provide good coverage of the affected scenarios. This appears to be a well-contained fix for a clear documentation/implementation mismatch.
