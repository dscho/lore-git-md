This thread is about a bugfix series for `git rebase --update-refs` that handles edge cases involving symbolic references (symrefs) to branches. The issue occurs when local branches are symrefs (e.g., `main` pointing to `master`), causing rebase failures during ref updates even when the primary branch rebases successfully. This is particularly relevant for branch rename migrations where old and new names coexist via symrefs.

The series is now in its third version (v3), consisting of two focused patches. The first patch, just summarized, prevents duplicate updates by skipping symrefs that point to other branches under `refs/heads/`, while preserving the symref itself. It also ensures the current branch is unconditionally skipped to avoid duplicate updates. The implementation is in `sequencer.c` and includes comprehensive test coverage in `t3404-rebase-interactive.sh` for HEAD aliases, secondary branch aliases, and symref chain verification.

All prior review feedback from Phillip Wood and others has been addressed, including symref resolution logic, checked-out branch detection, and cross-worktree conflict prevention. The series is technically complete and ready for maintainer consideration, with no remaining open questions. Junio Hamano’s earlier architectural concern about ref filtering consistency has been resolved by the current focused implementation. The patches are minimal, backend-agnostic, and maintain compatibility with both files and reftable backends.
