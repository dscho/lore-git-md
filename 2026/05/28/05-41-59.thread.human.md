This thread is fixing edge cases in `git rebase --update-refs` when dealing with symbolic references—situations where a branch or HEAD points not to a commit directly but to another ref, like `main` pointing to `master` or a symref pointing to a tag. Son Luong Ngoc’s two-patch series (now at v3) ensures that rebases don’t fail when symrefs are involved, which is particularly important for branch-rename migrations and tools like TopGit that rely on HEAD pointing outside the usual `refs/heads/` namespace.

The design debate between Junio Hamano and Phillip Wood has been resolved: Junio initially argued that high-level commands like `rebase` shouldn’t handle such edge cases, but Phillip demonstrated that real-world tools (specifically TopGit, which uses `refs/top-bases/...` symrefs) actively depend on this behavior. The current approach—using the resolved ref for HEAD comparisons—will be retained in the upcoming v4, which is expected to address minor refinements like explanatory comments and test organization. The series also fixes a latent bug in `master` where the `head_ref` buffer gets clobbered during resolution, causing incorrect entries in the rebase todo list when multiple worktrees are involved, though that issue will likely be handled in a follow-up.

Reviewers Erik Cervin-Edin and Phillip Wood have provided substantive feedback, including catching a regression in an earlier version and confirming its resolution. The series is functionally complete and under active review, with no merge status reported yet. The next step is v4, which will incorporate the latest refinements before the patches are ready for Junio’s integration branches.
