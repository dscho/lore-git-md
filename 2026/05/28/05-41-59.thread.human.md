This thread addresses a bug in `git rebase --update-refs` where symbolic references to branches (like when `main` points to `master` during a branch rename) caused rebase failures. The author first sent a test case demonstrating the issue, showing how rebase would successfully update the primary branch but fail on symref updates.

The second patch implements the fix by modifying the sequencer's decoration handling. It now properly resolves symrefs before processing updates, skips symrefs pointing to the current branch, and avoids duplicate updates when multiple symrefs point to the same branch. The changes maintain all existing safety checks while adding support for this symref case. The test was updated from `expect_failure` to `expect_success` to confirm the fix works.

This solution is particularly useful for branch rename migrations where old and new branch names temporarily coexist via symrefs. The changes are focused in `sequencer.c` with careful attention to memory management and preserving the existing behavior for non-symref cases. So far only the author has participated in the thread, and no open questions remain about the implementation.
