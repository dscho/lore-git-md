This thread is about a bugfix series for `git rebase --update-refs` that handles edge cases involving symbolic references (symrefs) to branches or other refs. The series, now in its third version (v3) and authored by Son Luong Ngoc, addresses failures that occur when symrefs—like a `main` branch pointing to `master` or a symref pointing to a tag—are present during rebase operations. These issues particularly affect branch rename migrations and cross-worktree workflows.

The core problem is that `git rebase --update-refs` fails to properly handle symref decorations, causing rebase failures even when the primary branch rebases successfully. Additionally, a latent bug in `master` causes branches matching HEAD to incorrectly appear in the rebase todo list when multiple worktrees are involved, due to a clobbered `head_ref` buffer during resolution. The series spans two patches, touching `sequencer.c` and `branch.c`, and includes extensive test coverage in `t3404-rebase-interactive.sh` to verify symref handling, cross-worktree conflicts, and backend compatibility.

The design debate between Junio C Hamano and Phillip Wood has been resolved in favor of the current patch’s robustness approach. Junio initially argued that high-level commands like `rebase` should not handle edge cases that Git discourages, such as HEAD pointing outside `refs/heads/`. However, Phillip provided concrete evidence that tools like TopGit actively rely on this flexibility, using symrefs to `refs/top-bases/...` and depending on `git rebase` for their workflows. Junio conceded the point, acknowledging the real-world constraint and closing the design discussion. The series is now expected to proceed to a fourth version (v4) with minor refinements, while the latent `head_ref` bug remains a candidate for a follow-up patch. Key reviewers include Phillip Wood, who identified design and implementation issues, and Erik Cervin-Edin, who surfaced the latent bug in `master`.
