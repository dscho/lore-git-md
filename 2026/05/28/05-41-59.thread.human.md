This thread is fixing edge cases in `git rebase --update-refs` when dealing with symbolic references (symrefs) to branches or other refs. Son Luong Ngoc’s two-patch series (now at v3) addresses failures that occur when symrefs—like a `main` branch pointing to `master`—cause rebase to mishandle ref updates, even if the primary branch rebases successfully. The series is functionally complete and under review, with Phillip Wood providing detailed feedback that’s been largely addressed.

The key technical work spans `sequencer.c` and `branch.c`, focusing on safe symref resolution, deduplication of updates, and preventing cross-worktree conflicts. Tests in `t3404-rebase-interactive.sh` cover scenarios like HEAD aliases, non-branch symrefs (tags, notes), and backend compatibility (files and reftable). While earlier versions had regressions—like incorrectly including the current branch in the rebase todo list—v3 fixed these by reworking the logic to skip the checked-out branch reliably.

A latent bug in the current `master` branch surfaced during review: the `head_ref` buffer used to compare against decoration names can be clobbered by `branch_checked_out()`, causing branches that should be skipped to appear in the todo list. This isn’t a regression from the series but a pre-existing issue that may explain unexpected behavior for users with multiple worktrees. The discussion suggests this will likely become a follow-up topic after the current series lands. No merge status has been reported yet, and the author is expected to post a v4 addressing Phillip Wood’s latest refinements (e.g., an explanatory comment and test tweaks).
