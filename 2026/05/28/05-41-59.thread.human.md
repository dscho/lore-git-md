This thread is about a bugfix series for `git rebase --update-refs` when dealing with symbolic references (symrefs) to branches or other refs. The series, now at its third version (v3) and authored by Son Luong Ngoc, addresses edge cases where symrefs (like a `main` branch pointing to `master` or a symref pointing to a tag) cause rebase failures, even when the primary branch rebases successfully. The issue affects branch rename migrations and cross-worktree workflows.

The current v3 series is functionally complete and under review, with no merge status reported. Junio C Hamano initially raised a design question about whether `git rebase` should assume HEAD always points to a branch or robustly handle edge cases like symrefs to tags. Phillip Wood clarified that Git has always allowed HEAD to point to any ref under `refs/`, and the current patch’s approach aligns with this behavior. However, Junio’s latest email pushes back, arguing that while low-level plumbing commands may need to handle such edge cases, user-facing commands like `git rebase` should not be burdened with them. This design tension remains unresolved but doesn’t block the series; it may influence how the author frames the upcoming v4 revision.

Key technical details include fixes in `sequencer.c` and `branch.c` to safely resolve symrefs, skip duplicates, and handle cross-worktree conflicts. The series also uncovered a latent bug in `master` where the `head_ref` buffer is clobbered during HEAD resolution, causing incorrect todo list entries in multi-worktree setups. This bug is not addressed in the current series but may become a follow-up topic. Phillip Wood and Erik Cervin-Edin provided substantive reviews, with Phillip confirming the core logic and Erik identifying a regression in an earlier version. Son Luong Ngoc is expected to address the latest refinements in v4, including an explanatory comment and test organization tweaks.
