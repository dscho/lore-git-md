This thread addresses a bug in `git rebase --update-refs` when working with branch symrefs - a common scenario during branch rename migrations where the old name points to the new one (e.g., `main` symref to `master`). The issue caused rebase to fail during ref updates even after successfully rebasing the primary branch.

The proposed fix comes as a series that first adds a failing test case to demonstrate the problem, then modifies the sequencer to properly handle symrefs. The solution involves resolving symref decorations before queuing updates, skipping aliases of the current branch, and avoiding duplicate updates for the same underlying branch. The changes touch core sequencer logic while maintaining all existing safety checks, making the feature work correctly in symref scenarios without compromising safety. This is particularly valuable for workflows that need to maintain both old and new branch names temporarily during migrations.
