This thread is about a bugfix series for `git rebase --update-refs` that handles edge cases involving symbolic references (symrefs) to branches or other refs. The series, now in its third version (v3) by Son Luong Ngoc, consists of two focused patches that address failures during rebase when symrefs are present—common in branch rename migrations or cross-worktree workflows.

The core issue is that `git rebase --update-refs` fails to properly handle symrefs, such as when `main` points to `master` or when a symref targets a tag. The v3 series resolves this by skipping branch-to-branch symrefs to prevent duplicate updates and safeguarding non-branch symref targets. All prior technical feedback from Phillip Wood, including edge cases around symref resolution, checked-out branch detection, and cross-worktree conflicts, has been addressed. The implementation spans `sequencer.c` and `branch.c`, with comprehensive test coverage in `t3404-rebase-interactive.sh`.

Phillip Wood’s latest review of the first patch raises minor points about implementation clarity and test organization—such as adding a missing comment, using a more efficient ref resolution function, and tidying up test assertions—but confirms the core logic is sound. The series is now functionally complete and ready for maintainer consideration, with no remaining open questions. Key participants include Son Luong Ngoc (author), Phillip Wood (reviewer), Kristoffer Haugsbakk (earlier review), and Junio C Hamano (who raised a broader ref filtering question, now resolved). The work builds on Git’s existing `--update-refs` feature and complements ongoing efforts around ref filtering and reftable backend consistency.
