This is a platform compatibility follow-up discussing a proposed fix for macOS linker warnings. Junio C Hamano responds to Harald Nordgren's patch that initialized a large global buffer in pkt-line.c to avoid alignment warnings on macOS.

Junio expresses skepticism about the linker behavior, calling it "nuts" that a char array would have alignment constraints. He's concerned the initialization workaround might bloat object files on some compilers, though testing shows modern GCC/Clang optimize it away. The discussion reveals this is a known issue with Xcode 16.3+.

Rather than accepting the initialization fix, Junio suggests trying `-fno-common` in CFLAGS as an alternative solution. He proposes this could be conditionally added in config.mak.uname for affected macOS versions. The thread shows Junio's characteristic attention to cross-platform build implications and preference for solutions that don't pessimize other compilers.

Key technical details for future reference:
- The issue affects pkt-line.c's 64KB packet_buffer used for network operations
- Problem manifests as alignment warnings during linking on macOS with Xcode ≥16.3
- Two potential solutions under discussion: zero-initialization vs. -fno-common flag
- Junio favors the compiler flag approach to avoid potential object file bloat
