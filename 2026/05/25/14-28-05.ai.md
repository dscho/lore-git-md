Performance optimization patch completing the O(1) solution for commit-reach.c algorithms. This is the final patch in Kristofer Karlsson's v2 series that eliminates O(n) queue scans in merge-base and ahead-behind calculations.

The patch introduces a `nonstale_queue` wrapper structure that maintains a pointer to the lowest-priority non-stale commit, allowing termination checks to run in constant time. The design leverages the one-way transition property of commits (they only go from non-stale to stale) and uses priority queue ordering guarantees to ensure correctness. Benchmark results show 2-3x speedups in merge-base calculations on large monorepos, with paint_down_to_common() runtime dropping from 50% to 4% of total execution time.

Key technical aspects:
- The wrapper bundles a priority queue with a `max_nonstale` pointer tracking the oldest non-stale commit
- Deduplication (added in patch 2/3) ensures unambiguous pointer comparisons
- Priority comparison uses `<= 0` to handle equal-priority commits correctly
- Changes are contained to commit-reach.c with no behavioral regressions

The implementation addresses all prior technical concerns about queue scanning and cache invalidation while maintaining the performance gains from earlier versions. This completes the optimization path suggested by Jeff King, moving from the initial O(n) scans to a mathematically cleaner O(1) solution.
