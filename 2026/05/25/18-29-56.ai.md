This is a technical patch in the `diff.<driver>.process` series, adding the configuration plumbing for the new external diff processor feature. It's the second of four patches in the v2 iteration.

The change introduces a new `process` field in the `userdiff_driver` struct to store the command for a long-running diff processor, following the same pattern as the existing `textconv` configuration. The implementation mirrors Git's established filter process protocol, with the subprocess staying alive across multiple file operations within a single Git invocation.

The patch details:
- Adds `process` and `process_owned` string fields to `struct userdiff_driver`
- Implements config parsing for `diff.<driver>.process` keys
- Follows the same memory management pattern as `textconv` (with owned/non-owned pointer pairs)
- Maintains consistency with existing userdiff configuration infrastructure

This is a straightforward infrastructure patch that enables the subsequent implementation of the diff processor protocol. The change is mechanical and well-contained, with no behavioral changes yet - that comes in later patches of the series. The implementation appears technically sound and follows established Git patterns for similar process-based extensions.
