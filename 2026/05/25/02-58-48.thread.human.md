Junio Hamano has proposed a small but useful update to the SubmittingPatches documentation. The patch adds guidance encouraging contributors to monitor CI test results for their patches after integration into Git's development branches, even if they didn't use GitHub CI for initial testing. It specifically suggests watching the maintainer's GitHub Actions workflow page to catch any integration issues that might surface when the patch lands in the 'seen' branch. This proactive approach could help identify problems earlier in the development cycle. The change is straightforward - adding a new section with clear instructions and a direct link to the relevant CI view - and comes from the maintainer himself, so it's likely to be merged as-is.
