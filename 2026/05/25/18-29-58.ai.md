This is the final patch in a series introducing the `diff.<driver>.process` feature, which enables external tools to inject diff hunks into Git's diff and blame pipelines. The specific focus here is integrating this with `git blame` to skip commits where the external diff tool reports no meaningful changes (zero hunks).

The patch modifies `blame.c` to consult the configured diff process during blame traversal. When the tool returns zero hunks for a commit's changes, blame will treat it as a no-op and continue attributing lines to earlier commits. This is particularly useful for skipping reformat-only commits in history analysis.

Key technical aspects:
- Adds a new `diff_hunks()` wrapper that checks for configured diff processes
- Passes the index state and path to enable driver lookup
- Handles zero-hunk responses by returning early (skipping the commit)
- Includes test cases showing blame correctly skipping reformat commits when using a zero-hunk mode

The implementation maintains the long-running process model from earlier patches, amortizing startup costs across the blame traversal. Performance remains a consideration - each commit still requires a round-trip to the external tool, though this could be optimized in future work (as noted in the thread).

The patch builds on the core protocol and xdiff integration established in earlier parts of the series, with thorough test coverage (32 new lines of test script) verifying the blame-specific behavior. Documentation is updated to explain how zero-hunk responses affect blame attribution.

This completes the technical implementation of the RFC, though the thread indicates performance optimization and stronger documentation of benefits remain as open items before potential inclusion.
