This is an RFC proposal for a new `diff.<driver>.process` feature that would allow external tools to inject diff hunks into Git's diff and blame pipelines. The v2 series (4 patches) refines the approach based on feedback from the initial proposal.

The core idea remains enabling structural/AST-based diffs while preserving Git's standard diff output features (word-diff, color-moved, etc.). The protocol follows Git's existing filter process model, with a long-running subprocess that provides hunk information while Git handles the final display.

Key changes in v2:
- Dropped the built-in whitespace normalizer demo tool to focus attention on the core infrastructure
- Improved xdiff integration with better encapsulation of memory management
- Restructured fallback logic to share more code with the standard diff path
- Changed error reporting from trace to warning messages
- Added test coverage for blame integration and various error cases

The implementation appears solid, with 370 lines of test coverage across success/error paths. Performance remains a concern (17% blame slowdown in current measurements), though the design allows for future optimizations like OID-based object access.

Junio Hamano has been engaged in the technical details but remains neutral-to-skeptical about merging until performance improves and use cases are better documented. The thread shows productive iteration, with the xdiff changes now looking sound but needing clearer justification of the feature's value before inclusion.

This could be particularly useful for tools that understand code structure better than line-based diffs, though the maintenance burden of the new protocol warrants careful consideration. The opt-in nature and graceful fallback suggest good forward compatibility.
