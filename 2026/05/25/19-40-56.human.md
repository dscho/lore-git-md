This is the first patch in a 3-part series refactoring how `git log -L` (line-log) integrates with Git's diff output pipeline. The series aims to make line-log processing flow through the standard `log_tree_diff()` pipeline rather than taking a separate shortcut.

This particular patch is a preparatory change that moves the line-log setup code earlier in `setup_revisions()` so that the default `DIFF_FORMAT_PATCH` setting for line-log will be visible when `revs->diff` is computed. This doesn't change any behavior yet, but enables the subsequent patches to properly route line-log output through the standard diff pipeline.

The change is straightforward and mechanical - it just reorders code blocks in `revision.c` to ensure the line-log defaults are set before the diff output derivation happens. The patch has been updated from v1 based on D. Ben Knoble's review, with improved commit message clarity about why this ordering matters for the series' goals.

This is a well-structured incremental change that lays groundwork for the more substantial pipeline integration in the following patches. The author demonstrates good attention to detail in ensuring the change is properly isolated and explained.
