This is a bugfix for `receive-pack` that addresses environment variable leakage between `push_to_checkout()` and `push_to_deploy()` operations. The issue was introduced by commit a8cc594333 ("hooks: fix an obscure TOCTOU 'did we just run a hook?' race") which changed the hook execution flow but didn't account for environment variable side effects.

The v2 patch from Alyssa Ross moves the `GIT_WORK_TREE` environment variable setting to only affect the hook execution environment rather than the shared environment, preventing leakage that broke `push_to_deploy()` when `core.worktree` was configured. The change is minimal (2 lines modified) but well-targeted, with a new test case verifying the fix works with `core.worktree` configurations.

Junio C Hamano's earlier review confirmed the technical correctness of isolating the environment and suggested improving the commit message, which Alyssa has addressed in v2. The test case provides effective regression protection, and there are no remaining technical objections to the solution. This appears to be a solid fix for a specific but important edge case in the receive-pack workflow.
