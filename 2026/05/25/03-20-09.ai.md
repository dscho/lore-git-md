This is the second patch in a v5 series introducing new `includeIf` conditions for matching worktree paths in Git configs. The patch adds the core implementation of `worktree:<pattern>` (case-sensitive) and `worktree/i:<pattern>` (case-insensitive) matching against worktree paths.

The implementation reuses the `include_by_path()` helper from the previous patch, passing the worktree path (from `repo_get_worktree()`) instead of the gitdir path. The conditions explicitly don't match in bare repos (no worktree) or during early config reading (no repo object available).

The patch includes comprehensive test coverage for:
- Bare repository handling
- Multiple worktree scenarios
- Symlink resolution
- Case sensitivity (with platform-specific tests)
- Early config reading edge cases
- Non-repository contexts

Documentation explains the new conditions and contrasts them with `extensions.worktreeConfig`, noting this approach allows global configuration of worktree-specific settings without requiring per-worktree config files. Example use cases show how this could help users maintain separate personal/work identities based on checkout location.

The implementation appears solid, with careful attention to edge cases and platform differences. The thorough test suite and clear documentation suggest this is production-ready functionality that cleanly solves the articulated problem of worktree-specific config inclusion.
