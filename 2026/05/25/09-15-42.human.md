This is a UX improvement for the `git config` command, specifically addressing user confusion when mistakenly using `=` syntax. Junio C Hamano provides a thorough review of Harald Nordgren's v3 patch, suggesting refinements to the error messaging approach.

Junio argues that the special handling of `=` in config keys may be unnecessary - the core issue is invalid variable names, not specifically the `=` character. He proposes simpler, more general error messages that would apply to any invalid character (not just `=`), like "error: setting to a variable with invalid name: 'pull.rebase*false'".

The review identifies several nuanced cases where the current hint logic could be misleading or unhelpful, particularly when:
- The key before `=` isn't a valid config name
- There are multiple arguments with explicit "set" operation
- The key contains legitimate `=` in subsections

Junio suggests the implementation could be simplified by focusing on clear error messages about invalid names rather than special-casing `=` for hints. This would maintain consistency with how other invalid characters are handled while still helping users understand what went wrong.

The review also notes an unusual double Signed-off-by line in the patch, which isn't standard practice. This appears ready to move forward after addressing these final points about error messaging philosophy.
