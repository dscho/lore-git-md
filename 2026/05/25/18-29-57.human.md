This is the third patch in a 4-part series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The feature enables structural/AST-based diffs while preserving Git's standard diff output formatting.

The patch adds the core implementation of the long-running diff process protocol, which follows Git's established pattern for subprocess communication. Key aspects:

- Tools are configured per userdiff driver via `diff.<name>.process` and communicate via pkt-line protocol
- The protocol allows tools to specify exactly which lines changed (with 1-based line numbers)
- Zero hunks with success status means the tool considers files equivalent (no diff output)
- Falls back gracefully to builtin diff on errors or invalid hunk data
- Includes thorough test coverage (338 lines) of success/error paths

The implementation builds on xdiff internals with careful memory management and follows Git's existing patterns for subprocess communication. The tests demonstrate integration with various Git features (word-diff, log -p) and proper fallback behavior.

This is part of an ongoing effort to enable more sophisticated diff tools while maintaining compatibility with Git's existing diff pipeline. The series has been refined through review iterations, with this version showing improved encapsulation and test hygiene compared to earlier submissions. Performance optimization (notably for blame) remains a future work item.
