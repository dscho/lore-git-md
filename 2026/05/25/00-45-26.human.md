Process management bug in containerized Git operations.

brian m. carlson responds to SURA's report about zombie processes accumulating when `git fetch` runs as PID 1 in Docker containers. They confirm this is a known limitation rather than a Git-specific bug, noting that any program spawning background processes in this environment would face the same issue. The response positions this as a general container design consideration rather than something Git should handle internally.

The reply suggests using an init process like `tini` (which SURA has already implemented) is the correct solution, as PID 1 in Linux has special responsibilities for process reaping that application processes aren't expected to handle. This aligns with standard container best practices but doesn't propose any changes to Git's behavior.

The response is technically accurate but doesn't engage with the regression aspect (the reporter noted this started in Git 2.53.0) or suggest whether Git could better handle this case. It's a useful confirmation of the workaround's validity but doesn't advance the technical discussion about potential fixes within Git itself. For container users, the takeaway is clear: always use a proper init process when running Git operations as PID 1.
