This is a revised RFC proposal for a new `diff.<driver>.process` feature that enables external tools to inject diff hunks into Git's diff and blame pipelines. The series has been refined based on feedback from the initial submission, with the main changes being:

1. Removal of the built-in whitespace normalizer demo tool to focus attention on the core protocol
2. Improved xdiff integration with better encapsulation of memory management via a new `xdl_clear_changed()` helper
3. Restructured fallback logic in the diff algorithm to avoid code duplication
4. Changed error reporting from trace to warning messages
5. Test suite improvements including replacing `grep` with `test_grep`

The core concept remains allowing specialized tools (like AST-based diff tools) to participate in Git's diff processing while preserving downstream features like word-diff and color-moved. The protocol follows Git's established long-running process pattern from the filter subsystem.

Key technical points:
- Uses pkt-line protocol for communication with external tools
- Tools can mark files as unchanged (zero hunks) which affects both diff output and blame attribution
- Falls back gracefully to builtin diff on errors
- Includes thorough test coverage (370 lines) of success/error paths

The blame integration shows how this could be used to skip reformat-only commits in history analysis. Performance remains a consideration - the current implementation adds ~17% overhead to blame operations due to per-commit roundtrips, though an OID-based optimization is noted as future work.

The changes since v1 address several of Junio Hamano's technical concerns, particularly around the xdiff integration. The series appears to be converging toward a technically sound implementation, though documentation of the performance/benefit tradeoffs may need strengthening before final acceptance.
