This is the final patch in a series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The specific focus here is integrating this with `git blame` to skip commits where the external diff tool reports no meaningful changes (zero hunks).

The patch modifies `blame.c` to consult the configured diff process during blame operations. When the tool returns zero hunks for a commit's changes, blame will treat the commit as having no changes and continue attributing lines to earlier commits. This is particularly useful for skipping reformat-only commits in history analysis.

Key technical aspects:
- Adds a new `diff_hunks()` wrapper that checks for a configured diff process
- Maintains the existing blame behavior when no process is configured
- Includes test cases showing how blame skips reformat-only commits when using a zero-hunk mode
- Documents the blame integration in gitattributes.adoc

The implementation follows the established pattern from earlier patches in the series, using the same pkt-line protocol for communication with external tools. Performance remains a consideration - each commit in the file's history incurs a round-trip to the tool, though the subprocess is long-running to amortize startup costs.

This completes the technical implementation of the RFC series, which has evolved through review feedback to improve encapsulation, test coverage, and error handling. The remaining open questions from earlier in the thread (performance optimization and documentation) still apply to this final piece.
