This is the second version of a performance optimization series from Kristofer Karlsson, targeting the commit-reach.c algorithms used by `git merge-base` and ahead-behind calculations. The series has evolved from an initial caching approach to a cleaner O(1) solution based on tracking the lowest-priority non-stale commit in the queue.

The key improvement in v2 replaces the previous nonstale counter with a `max_nonstale` pointer approach suggested by Jeff King. This tracks the oldest non-stale commit in the queue - when it's popped, all remaining entries must be stale. The implementation introduces a `nonstale_queue` wrapper structure that maintains this invariant while keeping the same performance gains (2x speedup in large monorepos) as the original approach.

The series is now structured as three patches:
1. Fixes stale entries in object flag allocation
2. Deduplicates queue entries in paint_down_to_common()
3. Replaces the O(n) queue scan with the new O(1) tracking

Benchmarks on a 3.7M commit monorepo show dramatic improvements - paint_down_to_common() runtime drops from 50% to just 4% of total execution time (~27x faster). The changes maintain all performance benefits while being mathematically cleaner and addressing Jeff King's concerns about worst-case behavior in the original caching approach.
