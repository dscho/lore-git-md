This is the first patch in a 4-part series introducing `diff.<driver>.process` support, enabling external tools to inject diff hunks into Git's diff and blame pipelines. The series builds on previous RFC discussions and incorporates feedback from Junio Hamano and others.

The patch adds core infrastructure in xdiff to accept pre-computed hunks via new `xpparam_t` fields (`external_hunks` and `external_hunks_nr`). When these are set, `xdl_diff()` populates the changed[] arrays directly from the provided hunks rather than running the diff algorithm. Key aspects:

1. **Validation**: Strict validation ensures hunks are in-order, non-overlapping, within bounds, and maintain the synchronization invariant (unchanged line counts must match between files). Invalid hunks trigger fallback to builtin diff.

2. **Memory management**: Introduces `xdl_clear_changed()` helper to properly reset the changed[] arrays, including sentinel slots used by xdiff internals.

3. **Line number handling**: Skips `trim_common_tail()` when using external hunks since they reference original line numbers that trimming would invalidate.

The implementation shows careful attention to xdiff's internal requirements while maintaining the existing diff pipeline's behavior. The validation logic is thorough, checking edge cases like zero-count hunks and bounds conditions. The patch lays groundwork for the series' goal of enabling structural/AST-based diffs while preserving downstream features like word-diff and color-moved.

Technical notes for future summarization:
- New `xdl_hunk` struct defines the unified diff hunk format (1-based line numbers)
- `xdl_populate_hunks_from_external()` handles the validation and array population
- Fallback to builtin diff occurs on any validation failure
- Changes touch xdiff internals but maintain compatibility with existing callers
