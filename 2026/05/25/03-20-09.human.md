This is the second patch in a v5 series introducing new `includeIf` conditions for matching worktree paths in Git configs. The patch adds two new condition keywords: `worktree:<pattern>` for case-sensitive matching and `worktree/i:<pattern>` for case-insensitive matching against the worktree path.

The implementation builds on the previous patch's `include_by_path()` helper, using `repo_get_work_tree()` to get the worktree path. The conditions won't match in bare repos or during early config reading when no repository is available. The patch includes comprehensive tests covering:
- Bare repositories
- Multiple worktree scenarios
- Symlinked paths
- Case sensitivity
- Early config reading
- Non-repository cases

The documentation explains the difference between this approach and `extensions.worktreeConfig`, noting that this solution allows global configuration based on worktree location rather than requiring per-worktree config files. Example use cases show how this could help users who work on the same project in different contexts (e.g. personal vs work).

This appears to be a well-considered solution to the problem of configuring worktrees based on their filesystem location rather than their `.git` directory path. The thorough test coverage and clear documentation suggest this is production-ready. The series has already incorporated feedback from several core contributors (Patrick Steinhardt, Phillip Wood, Junio Hamano) through multiple iterations.
