This is the first patch in a 4-part series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The series aims to enable structural/AST-based diffs while preserving Git's existing diff features like word-diff and color-moved.

This particular patch adds core xdiff infrastructure to support externally computed hunks. It introduces:

1. A new `xdl_hunk` struct to represent diff hunks (with 1-based line numbers matching unified diff convention)
2. New fields in `xpparam_t` to pass external hunks to the diff engine
3. Validation logic that checks hunk boundaries, ordering, and synchronization invariants
4. A new `xdl_clear_changed()` helper for proper memory management
5. Fallback to built-in diff algorithm when validation fails

The implementation carefully handles edge cases like zero-count hunks and maintains xdiff's internal invariants. The patch shows good attention to detail with thorough bounds checking and proper cleanup of the changed[] arrays. This foundational work will be used by subsequent patches to implement the actual process protocol and integration with Git's diff and blame commands.

The changes since v1 include improved memory management encapsulation and better error handling, addressing feedback from Junio Hamano. The patch appears technically sound and well-tested, though the overall series still needs performance optimization work (particularly for blame) before it can be merged.
