This is the third and final patch in Michael Montalbo's series to integrate `git log -L` (line-log) with Git's standard diff output pipeline. The patch enables metadata-only diff formats (`--raw`, `--name-only`, `--name-status`, and `--summary`) to work with `-L` while continuing to block stat formats (`--stat`, `--numstat`, etc.) which would show whole-file statistics rather than range-scoped ones.

The changes include:
- Updating documentation to clarify which diff formats are now supported
- Expanding the allowlist in `revision.c` to permit the new formats
- Adding comprehensive tests verifying the behavior of each supported format
- Explicitly testing that stat formats remain blocked (with clear error messages)

The implementation leverages the fact that metadata formats only need filepair fields (status, mode, path, oid) which are already set during line-log processing. The patch maintains the architectural separation established in earlier patches while completing the core functionality goal of unifying line-log output with Git's standard diff pipeline.

This final patch builds on the v1 feedback and v2 refinements, demonstrating careful attention to both technical correctness and user experience. The test coverage is thorough, verifying not just the happy path but also edge cases like root commits. With this change, line-log users gain access to more output format options while the implementation remains cleanly integrated with Git's existing diff machinery.
