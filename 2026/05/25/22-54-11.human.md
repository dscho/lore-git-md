This is a bugfix for `receive-pack` that has now been approved by Junio C Hamano for merging. The patch addresses an environment variable leakage issue between `push_to_checkout()` and `push_to_deploy()` operations, a regression introduced by commit a8cc594333 ("hooks: fix an obscure TOCTOU 'did we just run a hook?' race").

Alyssa Ross's v2 patch moves the `GIT_WORK_TREE` environment variable setting to only affect the hook execution environment rather than the shared environment, preventing leakage that broke `push_to_deploy()` when `core.worktree` was configured. The change is minimal (2 lines modified) but well-targeted, with a new test case verifying the fix works with `core.worktree` configurations.

Junio notes that Alyssa also fixed an indentation issue in the test case and has improved the commit message based on earlier feedback. With no remaining technical objections, this appears to be a solid fix for a specific but important edge case in the receive-pack workflow, and will be queued for inclusion in the next release.
