This is the second version of a performance optimization series targeting commit-reach.c algorithms (merge-base and ahead-behind calculations). The series comes from Kristofer Karlsson and builds on previous discussion to implement an O(1) solution for tracking non-stale commits in the priority queue.

The v2 series introduces a new `nonstale_queue` wrapper structure that maintains a pointer to the lowest-priority non-stale commit, eliminating the need for O(n) scans of the queue. This approach was suggested by Jeff King and provides the same performance benefits as the previous caching approach while being mathematically cleaner. Benchmark results show significant speedups (2-3x) for merge-base calculations in large repositories, with paint_down_to_common() dropping from 50% to 4% of total runtime.

The series is now restructured into 3 patches:
1. Fixes stale entries in object flag allocation table (prerequisite)
2. Deduplicates queue entries in paint_down_to_common()
3. Implements the O(1) nonstale tracking with the new queue wrapper

Key technical points:
- The `nonstale_queue` leverages the one-way transition property of commits (they only go from non-stale to stale)
- Maintains all performance gains from v1 while eliminating worst-case quadratic scenarios
- Benchmarked on a 3.7M commit monorepo showing consistent improvements
- Simple/linear cases show no regression

The thread has progressed from initial problem identification through technical refinement to this final implementation. The collaboration between Kristofer and Jeff King has produced a solution that addresses both performance goals and code quality concerns. Architectural discussions about Git's flag management system remain as separate future work.
