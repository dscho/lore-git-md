This is the third patch in a v2 series introducing a new `diff.<driver>.process` feature that enables external tools to inject diff hunks into Git's diff and blame pipelines. The patch implements the core process communication protocol and integration with Git's diff machinery.

The feature allows specialized tools (like AST-based diff tools) to participate in Git's diff processing while preserving downstream features like word-diff and color-moved. The protocol follows Git's established long-running process pattern from the filter subsystem, using pkt-line communication over stdin/stdout.

Key technical aspects of this patch:
- Adds new `diff-process.c` and `diff-process.h` implementing the protocol
- Integrates with existing diff infrastructure via new `xpp.external_hunks` field
- Handles error cases gracefully with fallback to builtin diff
- Includes comprehensive test coverage (338 lines) for various scenarios:
  - Correct hunk boundary handling
  - Error recovery (tool errors, crashes, invalid hunks)
  - Session state management (capability disable on abort)
  - Interaction with other features (word-diff, log -p)
  - Zero-hunk case (suppressing diff output)

The implementation shows careful attention to memory management and error handling, with clear separation between the protocol layer and diff integration. The test suite exercises both happy paths and edge cases, including verifying the process is properly contacted for each diff operation.

This builds on the xdiff modifications from earlier patches in the series, now encapsulating the hunk handling cleanly via the new `xdl_clear_changed()` helper. The patch appears technically sound and well-tested, though as noted in the thread summary, performance optimization and stronger use case justification remain open questions before final acceptance.
