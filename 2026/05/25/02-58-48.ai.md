Documentation patch updating the SubmittingPatches guide to encourage contributors to monitor CI results, even for patches not originally tested via GitHub CI.

The patch adds a new section explaining that contributors should watch for CI failures that may appear after their patches are integrated into the project's 'seen' branch. It provides a direct link to the GitHub Actions workflow page filtered to show only pushes by the maintainer (gitster). The intent is to help catch integration issues early, even from contributors who don't use GitHub CI for initial testing.

This is a straightforward documentation improvement from the maintainer himself, suggesting a proactive approach to CI monitoring that could help reduce integration issues. The change is small and focused, adding clear instructions without modifying any existing content. The link provided gives contributors a direct way to monitor the CI status of their changes after integration.
