This is a design discussion about the interface for `git branch --prune-merged` in Harald Nordgren's v9 series. Junio C Hamano weighs in on Phillip Wood's suggestion to make the command more flexible by allowing local branches as upstream targets, not just remote-tracking branches.

Junio strongly agrees with Phillip's point that the pruning functionality shouldn't be limited to remote-tracking branches. He demonstrates how the feature could be composed from existing commands if `--forked` (from patch 1) were generalized to work with local branches. His example shows how users could already achieve similar results by combining `--forked`, `--merged`, and `branch -d`, though the built-in command would be more convenient.

The discussion reveals an inconsistency in how "origin" is interpreted differently between `git checkout -b` (where it means the remote's default branch) and the proposed `--prune-merged` (where it would apply to all branches tracking any remote branch from that remote). Junio acknowledges this as a design flaw in the current proposal.

This email moves the thread forward by solidifying support for Phillip's interface suggestion, with Junio's authoritative voice now backing the more flexible approach. The technical implementation remains sound, but the command's semantics may need adjustment before final inclusion. The series appears headed toward consensus, with this being one of the last interface details to resolve.
