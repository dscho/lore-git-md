This is patch 13/18 in Patrick Steinhardt's series refactoring Git's loose object handling as part of the ODB (object database) abstraction effort. The patch focuses on cleaning up the loose object map implementation to work directly with `struct odb_source_loose` rather than going through the files backend as an intermediary.

The key change removes an implicit assumption that loose object map functions were making - they accepted a generic `struct odb_source*` but always expected it to be the files backend, which was just used to access the loose source. The patch makes this relationship explicit by having the functions operate directly on `struct odb_source_loose`.

The changes are mechanical:
1. Updates function signatures to take `struct odb_source_loose*` instead of `struct odb_source*`
2. Removes the intermediate `files->loose` dereferences
3. Updates callers to pass the loose source directly where needed
4. Maintains all existing functionality including hash algorithm compatibility handling

This continues the pattern seen in earlier patches of making the object storage interfaces more precise and removing unnecessary indirection. The changes are limited to loose.c, loose.h, and object-file.c, with no behavioral modifications - just cleaner internal organization.

The patch fits cleanly into the series' progression toward a fully abstracted object storage layer, though as with previous patches in the series, it hasn't yet received review feedback. The changes appear straightforward and focused, following the established pattern of mechanical interface updates.
