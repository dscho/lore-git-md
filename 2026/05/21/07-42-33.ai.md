This is the 6th patch in Patrick Steinhardt's 8-part series refactoring repository initialization and object database setup. The patch fixes an inconsistency where Git would initialize an object database even when no repository exists (specifically when GIT_DIR_EXPLICIT points to a non-existent directory).

The key changes are:
1. Modifies `commit-graph.c` to check for the presence of an object database rather than a gitdir when deciding whether to use commit graphs
2. Moves object database initialization in `setup.c` to only happen when we actually have a repository (inside the `have_repository` conditional)

The patch fixes a specific edge case where `git-index-pack` could fail when run outside a repository due to commit graph parsing assumptions. The change is part of the larger effort to make object database initialization more intentional and consistent across all code paths.

This continues the series' pattern of careful, incremental refactoring with clear motivation - here eliminating an unnecessary object database initialization that was a historical artifact. The changes are focused and well-explained, with the commit message detailing both the current behavior and why the change is safe.
