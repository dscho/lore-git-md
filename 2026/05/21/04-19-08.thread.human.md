This thread concerns a straightforward documentation fix for the `git-range-diff` man page. Siddh Raman Pant submitted a patch to add the missing `--no-notes` and `--notes[=<ref>]` options to the command's synopsis section, correcting an oversight from when these options were originally implemented in commit bd3619188682. The options were already properly documented in the body of the man page, just omitted from the synopsis.

Kristoffer Haugsbakk reviewed the patch, confirming the technical correctness of the change while pointing out two minor style issues: a typo in the commit message ("synopis" instead of "synopsis") and noting that Git doesn't use `Fixes` trailers like the Linux kernel does. He also observed that `git-range-diff` is exempt from the documentation test that would normally catch such mismatches, making this manual update necessary. The review was surface-level, focusing on style rather than substance, as the change itself was uncontroversial. With these minor corrections addressed, the patch appears ready to be picked up.
