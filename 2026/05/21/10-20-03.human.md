This is version 12 of Harald Nordgren's feature patch series adding a `--track=fetch` mode to `git checkout` and `git switch`. The feature automatically fetches from the remote when creating a tracking branch, eliminating the need for a separate `git fetch` step.

**Key changes in v12.** This version addresses the two edge cases Junio identified in v11: handling overlapping remote-tracking refs when multiple remotes map to the same namespace, and properly dealing with missing HEAD cases for bare namespace names. The implementation now follows Phillip Wood's suggestion to reuse existing `--track` behavior for overlapping refs rather than inventing new logic.

**Implementation details.** The patch adds robust error handling for ambiguous remote mappings, requiring exactly one remote to match the fetch refspec. It also properly validates `<remote>/HEAD` symrefs when using bare remote names, rejecting those that point outside the namespace. The test coverage has been expanded to 20 cases, including new tests for error conditions like invalid refnames and ambiguous remote mappings.

**Assessment.** The patch appears technically complete, with thorough test coverage of edge cases. The documentation clearly explains the behavior, including failure modes. The implementation aligns with Git's existing conventions for remote tracking. This looks ready for final review and potential inclusion, pending maintainer approval of the remaining edge case handling.
