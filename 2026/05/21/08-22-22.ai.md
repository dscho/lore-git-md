This is the second patch in Patrick Steinhardt's 18-part series refactoring Git's loose object handling as part of the ODB (object database) abstraction effort. The patch focuses on clarifying the relationship between the "loose" and "files" object sources.

The change makes the `struct odb_source_loose` store a direct pointer to its parent `struct odb_source_files` rather than a generic `struct odb_source`. This is an intermediate step toward completely removing the parent pointer relationship, which the cover letter identified as an awkward architectural detail that needs cleaning up.

The patch updates all the relevant call sites to use the new direct pointer, including the constructor function signature. While this is a mechanical change, it serves an important purpose in making the code's intent clearer before the more substantial refactoring in later patches. The changes touch core object-file handling code but don't modify any behavior - this is purely about improving type safety and making the relationships between components more explicit.

This continues the pattern seen in the first patch of carefully structured, incremental changes that move the larger ODB abstraction effort forward while minimizing risk. The patch appears well-contained and focused on its stated goal of clarifying the source relationships.
