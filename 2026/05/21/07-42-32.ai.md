This is the fifth patch in Patrick Steinhardt's series refactoring Git's repository initialization and object database setup. The patch continues the work of centralizing object database creation by removing conditional ODB initialization from `setup_git_env_internal()` and making it explicit in all call path.

The key change is eliminating the `skip_initializing_odb` parameter that was previously used to conditionally create the object database. Now ODB creation happens unconditionally in all paths that discover and configure a repository, including `enter_repo()`, `setup_git_directory_gently()`, and `init_db()`. This creates temporary duplication (acknowledged in the commit message) that will be cleaned up in subsequent patches.

The patch touches several core setup functions in `setup.c` but doesn't change user-visible behavior - it's purely an internal refactoring to make the code more consistent and prepare for further unification. The changes follow Patrick's typical careful approach, where each commit makes one logical step toward the larger goal while keeping the code functional at each stage.

This work is part of the broader effort to clean up repository setup and prepare for pluggable object storage backends. The next patch in the series will address the remaining inconsistency in `setup_git_directory_gently()` where ODB creation happens without applying repository formats.
