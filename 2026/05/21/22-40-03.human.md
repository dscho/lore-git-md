This is patch 3/4 in Harald Nordgren's series adding `git branch --prune-merged`, introducing a config option to exempt specific branches from automatic pruning. The patch adds `branch.<name>.pruneMerged=false` to protect topic branches that may see further development after initial upstream merging.

The implementation:
- Adds documentation for the new config option in both the config and command man pages
- Modifies the pruning logic to check the config before deletion
- Includes tests verifying both the opt-out behavior and that explicit `branch -d` still works
- Maintains all existing protections (checked-out branches, default branches, etc.)

The patch fits cleanly into the series' safety-focused approach, providing granular control while preserving the ability to manually remove branches when needed. The tests cover the key scenarios and the documentation is clear. This looks like a straightforward addition to the core functionality established in earlier patches.
