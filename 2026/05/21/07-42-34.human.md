This is patch 7/8 in Patrick Steinhardt's series refactoring repository initialization and object database setup. The patch eliminates a redundant read of the loose object map during repository initialization.

The change is straightforward: when initializing a repository, Git was reading the loose object map twice - once through `repo_set_compat_hash_algo()` (called via `apply_repository_format()`) and then again directly in `repo_init()`. The patch removes the second, unnecessary read.

This is a clean, mechanical improvement that follows the series' theme of making repository setup more efficient and intentional. The change touches only internal plumbing in `repository.c` with no user-visible impact. As with the rest of the series, it's part of the groundwork for future work on pluggable object storage backends.
