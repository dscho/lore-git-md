This is the second patch in Harald Nordgren's v10 series introducing `git branch --prune-merged`, a feature for safely cleaning up local branches that have been merged into their upstream. The patch implements the core pruning functionality that builds on the `--forked` infrastructure from patch 1.

The new `--prune-merged` option deletes local branches whose tips are reachable from their configured upstream (either a remote-tracking branch or local branch), while carefully preserving:
- Currently checked-out branches in any worktree
- Branches matching any remote's default branch name (e.g. 'main' or 'master')
- Branches whose upstream no longer exists locally

The implementation handles both remote-tracking and local upstreams, with comprehensive test coverage of edge cases like unmerged commits, missing upstreams, and default branch protection. The command is designed to be used after `git fetch` when pruning remote-tracking branches, ensuring reachability is checked against current upstream state.

Key technical details:
- Uses the same <branch> argument syntax as `--forked` (remote-tracking refs, local branches, or glob patterns)
- Combines multiple branch arguments via union
- Preserves branches by name (not just by upstream reference)
- Includes detailed tests covering:
  - Literal vs glob patterns
  - Local vs remote tracking branches
  - Default branch protection
  - Error cases and unmerged branches

The patch follows the safety model previously approved by Junio C Hamano in v9 while implementing the more flexible interface he requested. It incorporates Phillip Wood's suggestion for local branch support and maintains all the original safety guarantees. The implementation looks solid with thorough test coverage of the specified behavior.
