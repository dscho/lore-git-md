This is the final patch in Patrick Steinhardt's 8-part series refactoring repository initialization and object database setup. The patch completes the centralization of object database creation by moving it into `apply_repository_format()`, eliminating duplicate initialization code across multiple call sites.

The key technical changes are:
1. Object database construction is now handled within `apply_repository_format()` rather than at individual call sites
2. A new `APPLY_REPOSITORY_FORMAT_HONOR_ENV` flag controls whether environment variables (GIT_OBJECT_DIRECTORY and GIT_ALTERNATE_OBJECT_DIRECTORIES) should be respected
3. The object database is created after setting the main hash algorithm but before the compatibility hash algorithm
4. Removes redundant object database setup code from `repository.c`, `setup.c`, and `init_db()`

The patch maintains careful ordering of operations - the database is created after the main hash algorithm is set (since it may need that information) but before the compatibility hash (which requires the database to be initialized). Patrick notes this isn't ideal architecturally but defers further cleanup.

This change completes the series' goal of unifying scattered format application logic and eliminating redundant object database initializations. The series as a whole represents another step in Patrick's ongoing effort to clean up repository setup and prepare for pluggable object storage backends. The changes are internal plumbing improvements with no user-visible behavior differences.
