This is a feature patch for the `git-jump` contrib script, now in its third version, implementing automatic mode selection when run without arguments. The patch simplifies the auto-detection logic from v2 by removing the whitespace error detection that was found to be problematic.

The patch maintains the core functionality where `git jump` without arguments will now:
1. Default to "auto" mode (same as explicitly specifying `git jump auto`)
2. First check for unmerged paths (using `git ls-files -u`) and use merge mode if found
3. Otherwise check for unstaged changes (using `git diff --quiet`) and use diff mode if found
4. Fall back to showing usage if neither condition is met

Key changes from v2:
- Removed whitespace error detection from auto mode (since it was always subsumed by diff mode)
- Fixed a stray `#` character in the README
- Clarified the usage string to better explain the behavior with and without arguments
- Maintained the ordered priority (merge > diff) when multiple conditions could apply

The patch has already received positive feedback from Jeff King (Peff) in earlier versions, and the current iteration addresses Junio Hamano's concerns about the whitespace detection logic by removing that aspect entirely. The implementation remains clean and focused on the two most common use cases for `git-jump`.

This appears ready for merging as it has addressed all substantive feedback through multiple iterations and maintains a simple, predictable behavior for users. The documentation clearly explains both the explicit and automatic modes of operation.
