This is the third patch in Harald Nordgren's v10 series adding `git branch --prune-merged`, introducing a config-based opt-out mechanism for the new pruning functionality. The patch adds `branch.<name>.pruneMerged` configuration to exempt specific branches from automatic pruning while still allowing explicit deletion with `git branch -d`. This provides finer control over which branches get automatically cleaned up, particularly useful for topic branches that may see further development after initial upstream merging.

Key technical details:
- Adds documentation for the new config option in both `branch.adoc` and `git-branch.adoc`
- Implements the opt-out check in the pruning logic, skipping branches where `pruneMerged` is false
- Includes tests verifying both the opt-out behavior and that explicit deletion still works
- Maintains all existing safety checks from previous patches

The implementation is straightforward and well-tested, with clear documentation of the new feature. This patch completes the core functionality of the series, with only documentation polish remaining in the final patch. The opt-out mechanism addresses a real use case (preserving branches for further development) while keeping the default behavior safe and predictable.
