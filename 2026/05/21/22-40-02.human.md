This is the second patch in Harald Nordgren's v10 series adding `git branch --prune-merged`, a feature for safely automating local branch cleanup. The patch implements the core pruning functionality that builds on the `--forked` infrastructure introduced in patch 1.

The new `--prune-merged` option deletes local branches whose commits have been fully integrated into their upstream branches, with several safety mechanisms:
- Never deletes the currently checked-out branch in any worktree
- Preserves branches matching any remote's default branch name (typically 'main' or 'master')
- Skips branches whose upstream ref no longer exists locally
- Includes comprehensive tests covering edge cases like unmerged commits and default branch protection

The implementation handles both remote-tracking and local upstream branches through the flexible branch/glob syntax established in patch 1. The command is designed to be used after `git fetch` to ensure reachability checks use current upstream state.

This version incorporates Junio C Hamano's requested interface changes from earlier feedback, moving from remote-specific flags to a more general branch specification approach.
