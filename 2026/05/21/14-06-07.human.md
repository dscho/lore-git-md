This is the fourth iteration of a bugfix and UX improvement for `git status`'s push-branch tracking feature (`status.compareBranches`). The patch from Harald Nordgren addresses the final edge case identified in v3's review, where unconventional push tracking refs could still generate misleading pull advice.

The key change in v4 suppresses the pull advice entirely when the push tracking ref cannot be cleanly parsed into a remote/branch pair. This happens with unconventional refspec mappings like `refs/heads/*:refs/imported/imported/*`. The patch adds a test case specifically for this scenario, verifying that the status output shows the branch comparison but omits the pull advice when the ref format is non-standard.

The implementation remains focused and well-tested, with five test cases covering:
1. When both upstream and push branches are behind (different advice for each)
2. Remapped push refspecs
3. Push branch tracking with no upstream set
4. The common case where upstream and push are the same
5. The new edge case with unconventional refspecs

This version appears to fully address Junio Hamano's feedback from v3 and looks ready for inclusion. The changes are minimal and targeted, maintaining the original goal of providing accurate pull advice in triangular workflows while gracefully handling edge cases.
