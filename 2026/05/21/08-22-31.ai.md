This is patch 11/18 in Patrick Steinhardt's series refactoring Git's loose object handling as part of the ODB (object database) abstraction effort. The patch removes the redundant `odb_source_loose_has_object()` function, which checked for loose object existence via lstat(3p), in favor of using the more general `odb_source_read_object_info()` interface.

The key change is recognizing that `read_object_info_from_path()` already performs the same lstat(3p) check when called without the `OBJECT_INFO_QUICK` flag. The patch updates three call sites in `builtin/pack-objects.c` and `object-file.c` to use the unified interface instead, removing the now-unnecessary specialized function and its declaration.

This continues the mechanical conversion pattern seen in earlier patches, moving from direct function calls to callback-based operations through the odb_source interface. The changes are straightforward and maintain existing behavior while reducing code duplication. The patch touches core object handling code but appears low-risk since it's replacing equivalent functionality rather than introducing new behavior.
