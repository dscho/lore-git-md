This is the final patch in Harald Nordgren's series adding `git branch --prune-merged`, introducing a `--dry-run` mode for the new functionality. The patch completes the v10 series that has evolved through multiple iterations based on maintainer feedback.

The `--dry-run` option allows users to preview which branches would be deleted by `--prune-merged` without actually removing any refs. This is particularly useful for verifying glob patterns (like `origin/*`) before execution. The implementation:
- Prints "Would delete branch 'X'" for each branch that meets the pruning criteria
- Maintains all existing protections (checked-out branches, default branches, unmerged commits)
- Includes comprehensive tests verifying dry-run behavior with both deletable and protected branches
- Enforces that `--dry-run` can only be used with `--prune-merged`

The patch follows the same careful approach as previous versions, with thorough test coverage and clear documentation updates. It addresses Phillip Wood's earlier suggestion for dry-run capability while preserving the safety mechanisms that Junio C Hamano approved in v9. With this addition, the series appears complete and ready for final consideration.
