This is the first patch in Tuomas Ahola's five-part series fixing edge cases in Git's date approximation logic ("approxidate"). The patch specifically addresses the handling of the "today" keyword, changing its behavior from meaning "now" (the current time) to meaning "midnight" (the start of the current day).

The key changes are:
1. Introduces a new `date_today()` function that sets the time to midnight when no specific time is given (e.g. plain "today"), while preserving time components when combined with other specifiers (e.g. "noon today")
2. Updates the documentation to clarify that "--since=today" now means "since midnight"
3. Adds test cases to verify the new behavior, including combinations with explicit dates ("January 5th today pm")

The change resolves an inconsistency where "today" was previously treated as "now" by accident rather than design, which made "--since=today" effectively useless (as it would only show future commits). The new behavior aligns better with user expectations and matches the documented meaning of "--until" as showing commits "older than" the given date.

This is part of a larger effort to clean up approxidate's handling of special time formats when combined with explicit date references. The patch has gone through multiple iterations (now at v5) with all feedback addressed, including adding proper clearing of the `num` parameter in this version. The series appears ready for merging.
