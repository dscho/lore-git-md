This is the final patch in Patrick Steinhardt's series refactoring Git's repository initialization and object database setup. The series is part of the ongoing effort to clean up repository setup logic and prepare for pluggable object storage backends.

The patch centralizes object database creation within `apply_repository_format()`, eliminating duplicate initialization code across multiple setup paths. Key changes include:

1. Moving ODB construction into `apply_repository_format()` after hash algorithm setup but before compatibility hash setup
2. Introducing a new flag `APPLY_REPOSITORY_FORMAT_HONOR_ENV` to control whether environment variables (like `GIT_OBJECT_DIRECTORY`) should be respected
3. Removing redundant ODB initialization calls from `repository.c`, `setup.c`, and `init_db()`

The patch maintains existing behavior while making the initialization sequence more logical and consistent. Patrick notes this is a stepping stone - ideally the ODB would handle compatibility hash initialization itself, but that's left for future work.

This completes the series' goal of unifying repository format application and ODB initialization. The changes touch core setup code but don't affect user-visible behavior, continuing Patrick's careful, incremental refactoring approach. The series appears ready for merging as groundwork for future ODB abstraction work.
