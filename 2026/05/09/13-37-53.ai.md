This is the first patch in the final v7 series fixing git-gui's handling of bare repositories and missing worktrees. The patch restructures the repository startup sequence to properly handle these cases while maintaining backward compatibility.

Key changes in this patch:
1. Adds early bare repository detection right after config loading, rejecting bare repos for subcommands that require a worktree (like commit mode)
2. Preserves the historical behavior of treating a parent directory as worktree when inside a non-bare repo's .git directory
3. Removes unsafe relative path fallbacks that could break in multi-worktree setups
4. Adds proper error handling for broken repository configurations
5. Only exports GIT_WORK_TREE when actually needed (not for bare repos)

The patch carefully balances fixing the Tcl errors that occur in bare repos while maintaining the intentional behavior from 2010 that allows starting git-gui from within a .git directory. The changes reflect consensus from previous discussion rounds with Johannes Sixt and Mark Levedahl, particularly around the timing of bare repo checks and worktree detection.

Technical improvements include:
- More robust error messages for all failure cases
- Safer directory handling by using absolute paths from git rev-parse
- Clear separation between bare and non-bare repository logic
- Removal of problematic fallback paths that could cause issues in multi-worktree setups

This foundational change enables the subsequent patches to build on a more reliable startup sequence while fixing the core issues that caused git-gui to crash in bare repository scenarios.
