This is the first patch in the final v7 series fixing git-gui's handling of bare repositories and missing worktrees. The patch restructures the startup sequence to properly detect repository states and handle edge cases that previously caused Tcl errors.

The key changes:
- Adds early bare repository detection right after config loading, with clear error messages for unsupported modes
- Preserves the historical behavior of treating a parent directory as the worktree when launched from a `.git` subdirectory
- Removes unsafe relative path fallbacks that could break in multi-worktree setups
- Adds proper error handling around `rev-parse` calls that might fail
- Only sets GIT_WORK_TREE when actually needed (not for bare repo operations)

The patch shows careful attention to backward compatibility while fixing multiple regressions. It builds on feedback from Johannes Sixt and Mark Levedahl to create a robust solution that maintains expected behaviors while properly handling error cases. The changes are well-contained to the startup sequence and don't introduce new technical debt.

This appears to be the culmination of several rounds of review, with all edge cases addressed and consensus reached on the approach. The patch is focused and ready for merging.
