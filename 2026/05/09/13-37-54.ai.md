This is the second patch in a three-part bugfix series for git-gui, addressing visualization menu behavior in bare repositories. The patch specifically disables the "Visualize History" menu items when git-gui is running in a bare repository mode (such as when used for blame/browser functionality).

The key changes are:
1. Adding a check in `do_gitk` to prevent Tcl errors when attempting to visualize history without a worktree
2. Disabling the visualization menu items during initial UI setup when in bare mode
3. Updating `current_branch_write` to maintain consistent menu state when branches change

The patch builds on the repository detection improvements from the first patch in the series, ensuring the UI properly reflects when visualization features are unavailable. The changes appear well-contained and maintain backward compatibility while fixing a clear usability issue. The defensive programming approach (checking state in both initialization and runtime paths) suggests careful consideration of edge cases.

This is part of a mature series that has gone through multiple iterations with input from git-gui maintainers, and appears ready for merging. The patch follows the established pattern of graceful degradation when features aren't available in certain repository states.
