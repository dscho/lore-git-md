This is the final patch in a bugfix series for git-gui, addressing environment variable handling in bare repositories and worktree-less scenarios. The patch specifically focuses on making `GIT_DIR` and `GIT_WORK_TREE` environment variables behave consistently with `git -C` invocations.

The key changes introduce:
- Early environment resolution before repository detection
- Safe helpers for managing `GIT_WORK_TREE` that prevent empty exports
- Proper validation of environment-specified paths
- Cleaner separation between environment-driven and automatic detection paths

The patch appears well-considered, building on feedback from Johannes Sixt and Mark Levedahl in previous iterations. It resolves the long-standing inconsistency where environment variables were processed too late in git-gui's startup sequence, which could lead to the repository picker appearing unexpectedly or worktrees being ignored.

This completes the series' goal of making git-gui robust in all repository states (bare, non-bare, separate gitdir) while maintaining backward compatibility. The changes are focused and the diff shows careful attention to edge cases. With all technical points addressed and consensus reached, this series looks ready for merging.
