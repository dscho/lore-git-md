# Documentation polish for `--max-count-oldest` feature

Jean-Noël Avila provides final documentation feedback on the `--max-count-oldest` patch series, which is now implementation-complete after seven iterations. The feature adds a new option to show the oldest N commits in a history, complementing the existing `--max-count` for newest commits.

The review focuses on documentation clarity and error message consistency. Avila suggests:
1. Making the `--max-count-oldest` documentation more self-contained rather than defining it relative to `--max-count`
2. Fixing a typo in an error message ("con't" → "can't")
3. Using Git's standard `die_for_incompatible_opt2()` for option conflict messages to maintain consistency
4. Adding tests for the new option incompatibilities

These are minor polish items for what appears to be a well-vetted feature. The core technical implementation (including the optimized sliding window algorithm and integration with the revision walker) remains unchanged from previous versions that received thorough review. The patch series has addressed all substantive feedback from Junio C Hamano, Johannes Sixt, Jeff King, and Tian Yuchen.

This email represents the final documentation-focused review before the feature is ready for merging. The changes requested are straightforward and unlikely to require another revision cycle.
