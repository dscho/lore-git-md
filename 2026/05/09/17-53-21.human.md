This is a technical clarification in the ongoing thread about Git maintenance's resource usage and repository corruption risks. Jeff King (Peff) responds to concerns raised by Mikael Magnusson about background maintenance being enabled by default.

Key points:
- Peff clarifies that the immediate issue affects the "auto" maintenance mode (not the scheduled background jobs), which triggers during operations like `git commit` when the repo needs maintenance
- He notes this behavior isn't new - it previously ran as `git gc --auto` before being moved to the maintenance subsystem
- The dangerous locking issue appears specific to `--detach` mode in auto maintenance
- Peff confirms the situation worsened in Git 2.54 due to recent changes

The response helps distinguish between different maintenance modes while acknowledging the severity of the regression. Peff maintains a measured tone, providing technical context without downplaying the issue. This moves the discussion forward by narrowing the scope of immediate concern while leaving open the broader questions about maintenance defaults and safety guarantees.
