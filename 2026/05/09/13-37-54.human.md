This is the second patch in a three-part bugfix series for git-gui, addressing visualization menu behavior in bare repositories. The patch specifically disables the "Visualize History" menu items when git-gui is running in a bare repository mode (like for blame/browser operations) where no worktree exists.

The changes:
1. Add a defensive check in `do_gitk` to prevent Tcl errors when attempting to visualize history without a worktree
2. Disable the visualization menu items during initial UI setup when in bare mode
3. Update the branch tracking logic to keep menu states consistent when branches change

The patch builds on the previous commit's improvements to bare repository detection and maintains backward compatibility while preventing error conditions. It's a focused change that cleanly handles the visualization edge case while keeping the UI responsive to repository state changes.

The implementation shows careful attention to detail with both initial state setup and dynamic updates, and includes helpful error messages. The changes have been reviewed by both Mark Levedahl and Johannes Sixt, suggesting the technical approach has consensus.
