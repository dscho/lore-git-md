Prerequisite memory leak fix for revision walking optimization series.

This first patch in Kristofer Karlsson's series addresses a memory leak in `pack-objects.c` that becomes visible when the revision walking machinery starts using dynamically allocated structures (as will happen in patch 3). The leak occurs in `enumerate_and_traverse_cruft_objects()` which initializes a `rev_info` struct on the stack but fails to call `release_revisions()` to clean it up.

The fix is straightforward - adding the missing cleanup call. While this isn't strictly necessary on current master (where the structures are stack-allocated), it's a necessary prerequisite for the upcoming priority queue changes. The patch demonstrates good hygiene by fixing the issue separately rather than bundling it with the performance optimization.

This appears to be a well-scoped preparatory change that follows the pattern of fixing infrastructure issues before building on them. The commit message clearly explains both the current harmless-but-wrong state and why the change is needed for the series. No functional changes are expected beyond the memory leak fix.
