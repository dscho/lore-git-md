Feature patch series (v4) that completes the URL-based auto-configuration for promisor remotes, now ready for merging with only minor documentation refinements remaining.

This is the final version of Christian Couder's series that adds `promisor.acceptFromServerUrl` configuration, allowing clients to automatically configure promisor remotes based on URL patterns rather than requiring manual pre-configuration. The implementation builds on the previously approved LOP (Large Object Promisors) series and represents significant progress in promisor remote functionality.

Key technical aspects:
- URL patterns support globs (`*`) with strict security constraints (exact scheme/port matching, host boundary rules)
- Auto-generated remote names use `promisor-auto-` prefix with URL sanitization
- Collision handling prevents remote name hijacking
- Comprehensive security documentation in promisor.adoc
- Core changes in `promisor-remote.[ch]` and `urlmatch.[ch]`
- Extensive test coverage in t5710-promisor-remote-capability.sh

Changes since v3 are minimal:
- Renamed `promisor_info_internal_name()` to `promisor_info_local_name()` for clarity
- Fixed minor documentation formatting issues in promisor.adoc
- Removed spurious comma in commit message
- Added proper AsciiDoc block delimiters in security guidelines list

The series has received thorough review from Toon Claes, Patrick Steinhardt, and Junio C Hamano, with all technical feedback addressed. Kristoffer Haugsbakk identified two remaining documentation formatting issues that have now been fixed. CI tests pass cleanly.

This work enables simpler configuration for organizations using promisor remotes while maintaining strong security defaults. The implementation is now technically complete and ready for merging alongside the previously approved LOP series.
