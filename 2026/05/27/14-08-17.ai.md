This is patch 5/8 in Christian Couder's v4 series implementing URL-based auto-configuration for promisor remotes. The patch introduces the core functionality for `promisor.acceptFromServerUrl` configuration, which allows clients to automatically configure promisor remotes based on URL patterns.

The key technical additions are:
1. A new `struct allowed_url` to store parsed URL patterns and optional remote name prefixes
2. Validation functions (`valid_accept_url`) that check for:
   - Valid remote names when a prefix is specified
   - Absence of control characters in URLs
   - Proper URL pattern normalization using the new `url_normalize_pattern()` helper
3. Configuration loading via `load_accept_from_server_url()` that populates a string list of allowed patterns
4. Initial test coverage verifying rejection of invalid remote names in patterns

The implementation builds on the previously approved LOP series and represents a significant step toward simplifying promisor remote configuration while maintaining security. The patch includes thorough error handling and warning messages for invalid configurations.

This is part of the larger promisor remote enhancement effort that has undergone extensive review, with all technical feedback addressed in previous iterations. The changes are now focused on final documentation and code hygiene refinements.
