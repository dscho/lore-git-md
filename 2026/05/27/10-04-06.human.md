This is a review of Taylor Blau's bitmap optimization patch in his performance series, focusing on the sorting approach for XOR compression. Jeff King (Peff) provides his analysis after testing the changes.

Peff confirms the technical correctness of the sorting implementation, noting it properly maintains the hash pointers after reordering commits by date. While he expected the bitmap generation might already produce reasonably ordered commits, his tests on linux.git show no regression between versions (the bitmap size remained ~67MB both before and after the change). He speculates the dramatic 72% reduction Taylor saw might be visible in repositories with different commit patterns.

The review raises two follow-up questions: (1) how the bitmap size compares when generated with older Git versions (v2.30.0 vs v2.31.1) to understand when the ordering behavior changed, and (2) whether the smaller XOR-compressed bitmaps actually improve read performance, since fewer bytes to process could help but hidden assumptions might hurt. These aren't blockers - Peff's "looks correct" indicates approval - but represent the kind of thorough validation expected from senior reviewers on performance-sensitive changes.

This continues the pattern of substantive technical review from Peff throughout the series, where he verifies both the correctness and the real-world impact of optimizations. The exchange demonstrates how even straightforward-seeming changes receive careful scrutiny when touching core functionality like bitmap generation.
