This is the third patch in an RFC series proposing a new `--word-diff-align` feature for Git's diff output. The patch adds a focused test case demonstrating the feature's ability to highlight edits within moved blocks of code.

The test shows a common scenario where a block of permission definitions is moved (from before to after some internal debug flags) while one value is modified (`0x0008` -> `0x0001`). The test verifies that:
1. The moved block is correctly detected and aligned
2. The changed value is highlighted with word-diff markers (`[-old-]`/`{+new+}` syntax)
3. The output preserves the moved-line coloring from `--color-moved`

This test complements the earlier patches in the series by providing a concrete example of the feature's value - making small edits within moved blocks more visible during code review. The test case is well-chosen, showing a realistic example where this capability would help (permission bit changes in moved code).

The patch follows Git's testing conventions and integrates cleanly with the existing word-diff test file. It demonstrates the feature works as intended while keeping the test focused and minimal. This continues the series' pattern of careful, incremental development with each patch building on the last.
