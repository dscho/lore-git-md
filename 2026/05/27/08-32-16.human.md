Performance optimization discussion for `git fetch` connectivity checks.

Jeff King (Peff) raises a technical question about Kristofer Karlsson's patch that optimizes `git fetch` connectivity checks by passing the transport parameter through `store_updated_refs()`. While the optimization makes conceptual sense, Peff notes that the `self_contained_and_connected` flag is currently only set during clone operations (in `builtin/clone.c`), not during regular fetches. This suggests the optimization may not actually activate for the fetch case as intended.

The question probes whether there's an overlooked code path that enables this optimization for fetches, or if additional changes would be needed to make the flag available outside clone operations. This is a level deeper than the initial review, focusing on the actual mechanism rather than just the interface change.

The exchange represents a substantive technical review from a domain expert (Peff has deep knowledge of Git's transport and connectivity checking code). The answer to this question will determine whether the patch works as advertised or needs further refinement to achieve its performance goals for fetch operations.
