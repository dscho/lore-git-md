This is a performance optimization series targeting Git's revision walking code, specifically improving the streaming (non-limited) walk path. It follows up on a previous optimization that addressed the limited walk case (kk/limit-list-optim).

The key change replaces the O(N) linked list insertion in the streaming walk with a priority queue, similar to what was done for limited walks. The author provides compelling benchmarks showing a 5.3x speedup on a large monorepo (2.4M commits) for `git rev-list --count HEAD`, with the queue maintenance itself becoming 27x faster. The improvement is most noticeable in merge-heavy repositories where the walk frontier stays wide.

The series consists of three patches:
1. A leak fix in pack-objects that becomes visible with the new queue implementation
2. A refactoring to introduce an enum for walk modes, making the code more maintainable
3. The main optimization switching to a priority queue

The approach is carefully considered - it keeps the linked list for external interfaces while using the queue internally, avoiding disruption to bisect/line-log code. The benchmarks show no regression on non-merge-heavy repos like linux.git, where the optimization wasn't expected to help.

This appears to be a well-motivated, carefully measured optimization that builds on prior work in this area. The performance gains on large, merge-heavy repositories are substantial while maintaining compatibility elsewhere. The patch series looks production-ready and addresses a clear bottleneck in Git's revision walking performance.
