This is a technical patch in Christian Couder's URL-based promisor remote configuration series (v4 3/8). It introduces a new helper function `url_normalize_pattern()` to the URL matching subsystem, specifically designed to handle glob patterns (`*`) in hostnames when normalizing URLs.

The new function builds on the existing `url_normalize()` infrastructure but adds support for wildcards by passing `allow_globs=true` to the internal `url_normalize_1()`. This enables the caller to properly normalize URL patterns that will later be used for matching against actual URLs, which is a key requirement for the promisor remote auto-configuration feature.

The implementation is straightforward - just a thin wrapper around the existing normalization logic with the glob flag enabled. The header file includes clear documentation about the function's purpose and behavior, noting that while `*` is always allowed in the host portion, it's also technically valid in paths per RFC 3986.

This change is part of the larger effort to make promisor remotes more configurable through URL patterns rather than requiring manual setup. The patch has already gone through multiple review iterations and appears ready for merging, with all prior feedback addressed.
