This is the third patch in an RFC series proposing a new `--word-diff-align` feature for Git's diff output. The patch adds a test case demonstrating the feature's ability to highlight edits within moved blocks, specifically showing how a changed value in a permission-style block gets properly aligned and marked.

The test creates two versions of a C-style header file where a block of `#define` statements is moved, with one value changed (0x0008 -> 0x0001). The test verifies that the moved block is detected and that the changed line shows both the old and new values with word-diff-style markers ([-old-] and {+new+}).

This completes the initial prototype demonstration by:
1. The core matching from patch 1 identifies the moved block
2. The debug renderer from patch 2 shows the aligned changes
3. This test confirms the end-to-end behavior works on a realistic code example

The test is well-constructed to exercise the key scenario the feature aims to address - making small edits within moved blocks more visible during code review. The choice of a permission bitmask change is particularly appropriate as these are exactly the kind of subtle edits that can be missed in larger code movements.

The patch maintains the series' careful approach, adding just enough test coverage to validate the functionality without attempting to be exhaustive at this early stage. The test will serve as a foundation for further refinement of the scoring and rendering as the feature develops.
